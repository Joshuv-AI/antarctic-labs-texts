MiST: rapid, accurate and flexible (core-genome) multi-locus sequence typing (MLST) allele calling from draft genomes
Authors: Bert Bogaerts, Nancy H. C. Roosens, Kevin Vanneste
Published: 2025

ABSTRACT
BackgroundMulti-locus sequence typing (MLST) is a typing method to differentiate bacteria based on the sequence of several housekeeping genes. Identifiers are assigned to unique allele sequences for each locus in the scheme, and the combination of these identifiers defines a genetic profile. Its reproducibility and portability across laboratories have made it a staple typing method, widely used for epidemiological and evolutionary analyses. Although MLST was traditionally based on Sanger sequencing, the method is still widely used in the era of whole-genome sequencing (WGS). Moreover, WGS has made core-genome MLST (cgMLST) possible, which scale up MLST to hundreds or thousands of loci across the genome. Conventional and cgMLST schemes are publicly available on various platforms such as PubMLST.org, BIGSdb Institut Pasteur, cgMLST.org, and EnteroBase. However, the available software for (offline) cgMLST allele calling is often not flexible to accommodate schemes from diverse sources and/or lacks the computational scalability required to efficiently process larger schemes.ResultsIn this study, we present Minimap2-inferred Sequence Typing (MiST), a rapid and flexible cgMLST allele caller that is low-resource intensive and can easily accommodate schemes from different sources. We benchmarked the tool against other available MLST and cgMLST calling software using WGS data from five different species and schemes collected from various sources. We demonstrate that MiST can accurately identify alleles while requiring substantially fewer computational resources than existing allele callers.ConclusionMiST can help to make cgMLST analysis more accessible for integration into local bioinformatics workflows. MiST is available as an open-source Python package under the GPLv3 license at https://github.com/BioinformaticsPlatformWIV-ISP/MiST, and can be installed via Pip or Conda.Supplementary InformationThe online version contains supplementary material available at 10.1186/s12864-025-12324-z.

Background

Multi-locus sequence typing (MLST) is a well-established typing method for bacteria [1]. In MLST, a small set of housekeeping genes is sequenced with Sanger sequencing to type bacterial isolates based on their allelic profiles, by comparing against a harmonized reference database where each different sequence receives a different identifier (i.e., a number), providing a standardized way to study genetic diversity and epidemiology [2]. A sequence type (ST) is then assigned to each unique combination of these allele identifiers. Allele sequences and MLST profiles are maintained in public repositories such as PubMLST, which hosts databases for over 140 species and genera [1]. Although MLST was initially designed for typing bacterial strains, it is also used for typing fungi [3] and plasmids [4]. Historically, the lower throughput of Sanger sequencing has limited MLST to a few loci. The onset of whole-genome sequencing (WGS) has rendered it possible to scale MLST to hundreds or thousands of loci across the genome, greatly increasing the resolution. In core-genome MLST (cgMLST), the scheme is restricted to core loci shared by the majority of strains within a species or genus (typically found in ≥ 95% of strains). In contrast, whole genome MLST (wgMLST) includes all annotated loci in the genome, including both core and accessory genes. Compared to cgMLST, the number of available wgMLST schemes is limited. The greatly increased resolution of cgMLST and wgMLST compared to classic MLST enables the differentiation of closely related strains in outbreak and relatedness investigations [5]. Consequently, cgMLST and wgMLST schemes have been developed for many species [6, 7], with cgMLST in particular becoming a staple method for infectious disease surveillance and outbreak investigation [8]. Analogous to conventional MLST, most cgMLST schemes also define core-genome sequence types (cgSTs).

Numerous software packages are available for (cg)MLST analysis, which can be divided into two categories: (1) genome-based tools and (2) read-based tools. Genome-based tools start with draft or complete genomes in FASTA format and typically employ alignment methods to compare them with the allele sequences in the database. In this category, Seemann-MLST (available at https://github.com/tseemann/mlst) and CGE-MLST [9] are two commonly used tools, intended for conventional MLST. Tools developed specifically for cgMLST, such as ChewBBACA [10] and pyMLST [11], generally cluster allele sequences to reduce the number of sequences that need to be aligned, thereby reducing running times. These two tools also offer the possibility to create schemes de novo based on a set of input genomes. Recently, CoreProfiler also became available, which was developed specifically for rapid, offline cgMLST calling (https://gitlab.com/ifb-elixirfr/abromics/coreprofiler). CoreProfiler currently supports a set of cgMLST schemes hosted on BIGSdb, but no MLST schemes. It uses a two-step BLAST-based approach whereby it performs a rapid screening for perfect matches followed by a slower screening for potential novel alleles. Read-based tools start with read data, typically in FASTQ format, and use read mapping or k-mer matching to compare the reads directly with the sequences in the database. In theory, these methods can be faster, as the de novo assembly step is not required. StringMLST [12], MentaliST [13], and ARIBA [14] are some of the available read-based tools. These tools start with an initial mapping step, but ARIBA performs an additional local re-assembly using the reads mapped to the target sequence.

Although several tools are available for accurate MLST calling, scaling these tools up to handle cgMLST schemes is often not feasible due to performance and design limitations. Furthermore, most cgMLST-specific software tends to be inflexible due to assumptions or limitations regarding the alleles and loci that can be typed. Finally, while online platforms such as PubMLST and EnteroBase offer extensive functionality including cgMLST typing, they cannot easily be integrated into automated or high-throughput workflows, which limits their usefulness in scalable, reproducible bioinformatics pipelines.

To address these challenges, we developed Minimap2-inferred Sequence Typing (MiST), an open-source Python package for rapid, flexible, and low-resource (cg/wg)MLST allele calling that can accommodate schemes from multiple sources. We benchmarked MiST against several widely used MLST and cgMLST callers using WGS data from seven different bacterial species. By combining high accuracy, resource efficiency, and broad scheme compatibility, MiST makes (cg)MLST analysis more accessible and easier to integrate into scalable bioinformatics workflows.

Implementation

Software implementation

Overview

MiST is written in Python 3 and uses Minimap2 [15] to screen for alleles against a subset of representative alleles (Fig. 1). During database creation, identity-based clustering is performed on each locus using CD-HIT v4.6.8 to identify a subset of representative alleles. Alleles of different lengths are always assigned to separate clusters, regardless of sequence identity. An additional correction step is included to extract alleles with an alternative start position (i.e., shifted relative to other members of the cluster), by global alignment of all cluster members using nucmer from the MUMmer v4.0.0 package [16]. The SHA-1 hash for each allele sequence is then computed and stored in a JSON file, alongside locus metadata. Allele calling begins with Minimap2 v2.28 [15] alignment against a database containing all the representative alleles, combined across all loci. The ‘--all-chain’ option is enabled to ensure that all alignments, including suboptimal ones, are retained. The location of the locus in the input draft genome is then determined based on the alignment output. The corresponding sequence is then extracted, and its SHA-1 hash is then compared to a database containing pre-computed hashes of known alleles. If an exact match is found, the corresponding allele is reported, otherwise a search for the best-matching allele is performed.

For imperfect hits, alleles are reported as potential novel alleles if they have ≥ 99% sequence identity (this parameter can be adapted) and the length matches exactly to an existing allele in the database. In this case, the best-matching allele(s) from the database are reported and the novel allele sequence is exported. If no such match is found, the locus is reported as missing. If there are multiple hits, there are several options for handling them. The ‘longest’ strategy is applied by default, whereby the longest perfect matching allele(s) are reported. If there are multiple longest alleles, they are reported separated by ‘__’ (i.e., 1__4). Alternatively the ‘all’ strategy can be used where all perfect matches are reported, regardless of length. Finally, the ‘first’ strategy is available, which reports the allele with the lowest allele identifier (i.e., the first allele introduced into the database) in the event of multiple hits.

If the detected allele combination matches a (cg)ST in the database, the corresponding profile is reported along with the corresponding metadata. Otherwise, the best matching (cg)ST is reported along with the percentage of matching loci.

Databases

The tool supports arbitrary scheme definitions which can be provided as a list of FASTA files containing the allele sequences for each locus, along with an optional profiles file in tab-separate values (TSV) format. The allele calling method does not rely on translation or identifying coding sequences (CDSs), so allele sequences do not have to start and end with valid start and/or stop codons. Helper scripts are provided to list and download schemes from BIGSdb (e.g., PubMLST, Institut Pasteur Paris), EnteroBase, and cgMLST.org. Note that, from this year onwards, registration is required to access the latest allele sequences and profiles in certain BIGSdb instances (including PubMLST.org and BIGSdb Institut Pasteur Paris). Once the user has registered and provided valid credentials, the BIGSdb helper script can retrieve the most recent alleles and profiles.

Phylogenetic tree estimation

We have included a companion script, ‘mist dists’, that can be used to create allele matrices and distance matrices based on the MiST output. The script combines the (cg)MLST output files and generates an allele matrix that can be optionally filtered to remove low quality datasets and/or loci. The `--min-perc-loci` parameter specifies the minimum percentage of loci that must be present in a sample for it to be included in the allele matrix. The `--min-perc-samples` parameter defines the minimum percentage of samples in which a locus must be detected for it to be retained in the allele matrix. A pairwise allele distance matrix is then generated, which can be used as for input for phylogeny software. If GrapeTree [17] is installed, a minimum spanning tree can be generated in Newick format, otherwise the command to generate the tree using the ‘MSTreeV2’ method is logged. Potential novel alleles are incorporated into the allele matrix using allele identifiers based on sequence hashes to ensure maximum resolution, even when the novel alleles have not yet been added to the underlying scheme.

Performance evaluation

Strategy

Tool performance was evaluated by comparing the allele calls with an approach where all loci are aligned separately to the input contigs using BLASTN v2.16.0 [18], an approach that was previously validated for various species [19, 20]. For loci with alleles ≤ 100 bp, the BLASTN ‘task’ parameter was set to ‘blastn-short’. This approach is computationally inefficient, but is expected to yield accurate results as each allele sequence in the database is considered for alignment. In rare cases where multiple alleles were identified, the locus was considered a match if at least one of them matched. Only exact matches were considered. Potential novel alleles were treated as missing alleles because the tools use different strategies to identify and report this type of hit.

The resource usage of the various cgMLST calling tools was evaluated using the benchmark functionality of Snakemake v7.32.4 [21]. The following metrics were used: CPU time (‘cpu_time’), execution time (‘execution_time’), maximum memory usage (‘max_rss’), and total I/O (i.e. the sum of ‘io_in’ and ‘io_out’, which are the cumulative numbers of megabytes read and written, respectively). All tools were executed with four threads (if multiple threads were supported by the tool) on the same virtualized Ubuntu 22.04 server with no other analyses running. The server was equipped with two AMD EPYC 7H12 64-core processors and 1 TB of system memory. Resource usage was not assessed for the MLST analysis due to its minimal computational requirements.

Dataset

The tool was evaluated using datasets from seven species for which both MLST and cgMLST schemes were publicly available (Table 1). The MLST schemes contained seven or eight loci, while the number of loci in the cgMLST scheme ranged from 501 to 3,002. These schemes were selected to include schemes from various origins, including PubMLST.org, cgMLST.org, EnteroBase, and BIGSdb Institut Pasteur Paris. For each species, ten samples were randomly selected from the AllTheBacteria [22] collection, based on the provided species classifications. The assemblies were download from AllTheBacteria, while the corresponding Illumina reads were downloaded from the European Nucleotide Archive (ENA). Accession numbers are provided in Supplementary Table S1.

Results

Accuracy of MiST for conventional MLST allele calling

Figure 2 shows the accuracy of the allele calling using the evaluated MLST schemes (Table 2). Overall, performance was high for all tools. The most mismatches were identified in the ARIBA output, which failed to detect the S7 and S8 loci in all M. tuberculosis datasets. An additional mismatch was identified in the xpt locus in one of the Enterococcus faecalis datasets. CGE-MLST did not detect the S12 locus for any of the ten M. tuberculosis datasets, while it was correctly picked up by all other methods. The remaining mismatches were: (1) the gdh locus in the SAMN35364752 E. faecalis dataset, for which the correct allele was identified by CGE-MLST and Seemann-MLST but flagged as imperfect identity; and (2) the cat locus in the L. monocytogenes SAMN19571709 dataset which was also incorrectly flagged as imperfect identity by Seemann-MLST. This resulted in overall accuracy of 100% for BIGSdb, CoreProfiler, MiST, and StringMLST, 99.60% for Seemann-MLST, 97.80% for CGE-MLST, and 95.80% for ARIBA. The datasets for which there were mismatches with the CGE-MLST tool were re-analyzed using the online tool, which produced the same results as the offline installation.

Accuracy of cgMLST allele calling

Figure 2 shows the accuracy of the allele calling using the evaluated cgMLST schemes (Table 2). Overall, BIGSdb and CoreProfiler achieved the highest level of accuracy, matching with the reference method for all loci. However, not all schemes were available in BIGSdb and it could only be evaluated on 43,210 of the 118,080 alleles (36.59%). MiST achieved an accuracy of 99.97% on 118,080 allele calls. There were a total of 31 mismatches, 26 of which were caused by small alleles (ranging from 45 to 63 bp) in the E. coli cgMLST scheme. These alleles were not detected up in the initial seed alignment with Minimap2. Note that for the BLAST-based approach, the ‘task’ parameter also had to be adapted to detect these short alleles (see Sect. Strategy). The remaining five mismatches were also caused by loci where the cluster representative was not detected in the seed alignment step (four for the Neisseria scheme, one for the E. coli scheme), but these alleles were longer. Although the global identity between the reference allele and the cluster representative was higher than the sequence identity threshold, the alignment failed due to localized variation.

For ChewBBACA, the overall accuracy was 87.06%, though this varied substantially between schemes for different species, with the best performance for the Listeria and Yersinia schemes and the worst performance for the Mycobacterium and Enterococcus schemes. The primary cause of mismatched alleles was CDS identification, which often resulted in a different allele being called. This occurred with uncommon start codons (e.g., GTG in the Yersinia scheme) or when multiple start or stop codons were located close to each other in the input assembly. ChewBBACA also struggled to identify short alleles, such as the NEIS1020 Neisseria locus. As ChewBBACA was originally designed for creating schemes, it is reasonable to expect that it performs best with schemes that closely follow its design guidelines.

Execution time and resource usage

Resource usage for different cgMLST allele calling methods is provided in Fig. 3. Overall, MiST had the shortest execution time, followed by CoreProfiler and ChewBBACA. On average, allele calling for a complete cgMLST scheme using MiST took 15 s per dataset, compared to 36 s using CoreProfiler, and 83 s using ChewBBACA. For all tools, the execution times were correlated with the size of the input scheme (see Table 2). Execution times tended to be shortest for the Y. enterocolitica and M. tuberculosis schemes (501 loci and 744 loci, respectively) and longest for Salmonella and Shigella spp. (3,002 and 2,513 loci, respectively). For example, querying the Yersinia enterocolitica cgMLST scheme using MiST took an average of four seconds, whereas querying the Salmonella cgMLST scheme took 28 s. The memory usage pattern was similar to the execution times, with MiST having the smallest memory footprint followed by ChewBBACA and CoreProfiler. There was a similar scheme-specific effect, with larger schemes requiring more memory. The maximum memory usage across all datasets was 1,555 MB for MiST, 3,683 MB for ChewBBACA, and 4,081 MB for CoreProfiler. ChewBBACA had the highest I/O usage (310 MB), followed by CoreProfiler (84 MB), and MiST, which had the lowest average read/write I/O usage at 37 MB. In summary, MiST had the lowest execution time, whilst using substantially less memory and less I/O than the other tested tools.

Discussion

In this study, we present MiST, an open-source Python package for MLST, cgMLST, and wgMLST allele calling. Using schemes from various species and origins, we demonstrated that MiST is faster and requires less memory than the other tested tools with similar or higher accuracies. MiST performed well across all tested schemes and datasets, consistently achieving highly accurate MLST and cgMLST typing results. Since MiST operates entirely within the nucleotide space, it does not consider the effect on the amino acid sequences. This was a deliberate design choice, since many (cg)MLST schemes contain loci that do not correspond to intact CDSs, i.e. the contain additional flanking sequences or contain irregular start or stop codons. While allele size is theoretically irrelevant for MiST, our performance evaluation showed that performance was lower for very small loci (< 80 bp). Nevertheless, the tool remains very flexible, enabling typing of loci and schemes which are problematic for other tools. For example: (1) ChewBBACA could not identify loci with unconventional CDSs, such as the CTG start codons in the Yersinia cgMLST scheme; (2) pyMLST restricts scheme creation to a single sequence per locus, preventing the import of complete external schemes; and (3) BIGSdb and EnteroBase are online platforms that only allow queries on the schemes hosted on their sites. They are also complex to setup locally or to query from the command line.

Two of the most commonly used cgMLST allele callers are ChewBBACA and pyMLST, which also have functionality to create novel schemes. These tools are highly performant and enable relatively rapid typing. However, both tools are limited in their ability to use external schemes. For pyMLST, schemes are created using only a single allele per locus, making it incompatible with existing schemes, which usually have numerous allele sequences for each locus. Consequently, this tool was omitted from the performance evaluation. ChewBBACA has similar limitations regarding the use of external schemes. ChewBBACA relies on CDS identification and uses BLASTP (i.e., translated nucleotide sequences) for allele calling. However, some existing MLST and cgMLST schemes contain alleles that do not correspond to (conventional) CDSs. For instance, for six out of seven tested MLST schemes, all loci were incompatible with ChewBBACA. This issue was less apparent for the cgMLST schemes for which all loci were compatible, except for the Neisseria NEIS1452 locus. Nevertheless, several alleles were still flagged as ‘invalid’ alleles and were therefore not detectable (e.g., ~ 5% of alleles in the E. coli cgMLST scheme). Furthermore, many of the cgMLST mismatches reported by ChewBBACA were also caused by the CDS calling step. MiST did not have this limitation and was able to handle all tested MLST and cgMLST schemes from various sources without any issues.

Overall, the recently released CoreProfiler tool and the online BIGSdb portal performed very well in our benchmark, matching the reference method for all allele calls and achieving perfect accuracy. BIGSdb also offers extensive functionality, such as novel allele detection and phylogenomic investigation across strains. However, as the portal is hosted online, integrating it into automated workflows is challenging. Furthermore, BIGSdb is restricted to the schemes that are hosted on the platform. MiST does not have these limitations and can be used offline with arbitrary schemes. Compared to MiST, CoreProfiler also achieved slightly higher accuracy, primarily because it had no mismatches in the very short loci of the E. coli cgMLST scheme. However, since these loci are rare and limited to a very small number of schemes, this difference does not typically impact standard analyses. MiST could still provide an added value over CoreProfiler. First, CoreProfiler currently supports only a limited set of schemes hosted on BIGSdb instances, and its helper scripts currently do not handle authorization. Consequently, recently added alleles and profiles cannot be retrieved due to changes in PubMLST.org’s data access policy. Second, MiST was less resource-intensive in terms of CPU, RAM and I/O usage. Third, CoreProfiler does not report all matching alleles in cases of multi-hits, i.e. when multiple perfectly matching alleles are present [23]. Although these cases typically arise from sub-optimal scheme curation, they are quite common for the EnteroBase E. coli and Salmonella cgMLST schemes. For our evaluation we considered a locus a correct match if at least one of the reported alleles matched the reference method (e.g., reporting allele 3 when both alleles 3 and 15 were both present was accepted). However, this behavior can affect downstream phylogenetic analyses, as discrepancies in reported alleles between strains can artificially inflate distances. MiST addresses this issue by reporting multi-hits explicitly using a double-underscore notation (e.g., 3__15).

We also tested several tools that were originally developed for classic MLST, including stringMLST, Seemann-MLST and CGE-MLST. However, these tools either did not support cgMLST schemes (Seeman-MLST and CGE-MLST) or did not scale well to larger schemes (StringMLST). For StringMLST, constructing the database indices caused memory issues, even on high-memory systems. This illustrates the need for optimized, scalable methods for cgMLST analysis.

MiST does not contain functionality to construct novel schemes and is therefore entirely reliant upon externally hosted schemes or other software, such as ChewBBACA. Users are strongly encouraged to deposit novel alleles and profiles into external schemes to ensure they become available to others. MiST applies relatively strict thresholds for reporting potential novel alleles, requiring > 99% sequence identity (adjustable by the user) and an exact match in length to an existing allele, which help prevent allele identifiers being assigned to sequencing artefacts or invalid variants while still capturing genuine novel alleles. The user can change the identity thresholds for reporting novel alleles. Stricter values reduce the risk of false positives, but increase the likelihood of genuine novel alleles being missed. Conversely, more relaxed thresholds detect more putative novel alleles, but increase the risk of false positives. When conducting a phylogenomic investigation, it is essential to use the same threshold for all datasets. Potential novel allele sequences can be exported in FASTA format and easily submitted to the database hosting the underlying scheme. The final integration of novel alleles into the underlying scheme is handled by scheme curators, who apply domain-specific knowledge and criteria to accept or reject new allele sequences. MiST displays a reminder to cite the scheme used, which could help to secure funding and continued hosting from the providers of the scheme. Another limitation is the lack of support for raw read input. The de novo assembly step can be time-consuming and may affect typing accuracy. However, by starting from FASTA input, the tool can accommodate data from various sources without requiring specialized preprocessing.

Conclusion

In conclusion, we have developed an efficient and accurate tool that can enhance the existing (cg/wg)MLST analysis in bioinformatics workflows by providing accurate and resource-efficient (cg/wg)MLST profiling. Furthermore, by providing the ability to download, query and construct phylogenies from (cg)MLST schemes, MiST renders offline cgMLST and wgMLST analysis more accessible.

Availability and requirements

Project name: MiST.

Project home page: https://github.com/BioinformaticsPlatformWIV-ISP/MiST.

Operating system(s): UNIX.

Programming Language: Python 3.

Other requirements: Minimap2, CD-HIT, MUMmer4.

License: e.g. GNU GPLv3.

MiST is available as a Python package that can be installed via ‘pip’. It requires Minimap2 [15], CD-HIT [24] and MUMmer4 [16] as external dependencies. Alternatively, MiST and all its dependencies can be installed via Bioconda. The tool can also be used via the Galaxy instance of our institute (registration required) at https://galaxy.sciensano.be [25]. Further documentation, including step-by-step examples such as performing an outbreak investigation, is available on the Wiki (https://github.com/BioinformaticsPlatformWIV-ISP/MiST/wiki).
