Computing Range Consistent Answers to Aggregation Queries via Rewriting
Aziz Amezian El Khalfioui, Jef Wijsen

Abstract
. We consider the problem of answering conjunctive queries with aggregation on database instances that may violate primary key constraints. In SQL, these queries follow the SELECT-FROM-WHERE-GROUP BY format, where the WHERE-clause involves a conjunction of equalities, and the SELECT-clause can incorporate aggregate operators like MAX, MIN, SUM, AVG, or COUNT. Repairs of a database instance are defined as inclusion-maximal subsets that satisfy all primary keys. For a given query, our primary objective is to identify repairs that yield the lowest aggregated value among all possible repairs. We particularly investigate queries for which this lowest aggregated value can be determined through a rewriting in first-order logic with aggregate operators.



1.
Introduction

Consistent query answering
(CQA) was introduced at PODS’99
(
Arenas et al., 1999
)
as a principled approach to answering queries on database instances that are inconsistent with respect to a given set of integrity constraints.
The only integrity constraints we consider in the current work are primary keys.
A
block
in a database instance is a
\subseteq
-maximal set of tuples of a same relation
R
that agree on the primary key of
R
.
A
repair
of a database instance picks exactly one tuple from each block.
Given a Boolean query
q
,
{\mathsf{CERTAINTY}}(q)
is then defined as the decision problem that takes a database instance
\mathbf{db}
as input, and asks whether
q
holds true in every repair of
\mathbf{db}
.
This problem, while commonly studied for Boolean queries, can be readily extended to queries with free variables
\vec{x}
: a
consistent answer
to a query
q(\vec{x})
is any sequence
\vec{c}
of constants, of length
|\vec{x}|
, such that
q(\vec{c})
holds true in every repair.
The computational complexity of
{\mathsf{CERTAINTY}}(q)
is well understood for all queries
q
in
\mathsf{sjfBCQ}
, the class of self-join-free Boolean conjunctive queries
(
Koutris and Wijsen, 2017
;
Koutris and Wijsen, 2021
)
. This understanding readily extends to queries with free variables.

The current paper focuses on the complexity of CQA for
numerical queries

g()
, which throughout this paper are mappings that take a database instance as input and return a single number; numerical queries are commonly called
numerical terms
in logic. We will assume that some database columns are constrained to be numerical; in particular, values in numeric columns will be non-negative rational numbers throughout this paper, except for Section
7.3
. We employ the range semantics as presented by Arenas et al.
(
Arenas et al., 2001
)
, which provides the greatest lower bound (glb) and the least upper bound (lub) of query answers across all repairs.
Specifically, the function problems
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
and
{\mathsf{LUB\mathchar 45\relax CQA}}(g())
take a database instance
\mathbf{db}
as input, and return, respectively, the glb and the lub of the set that contains each number returned by
g()
on some repair.

As motivated by Arenas et al.
(
Arenas et al., 2001
)
, range consistent query answers are of particular interest for aggregation queries, which are likely to return different numbers on different repairs, and therefore will lack a single consistent answer that holds true across all repairs.
Our attention will therefore be directed towards aggregation queries. In particular, we consider numerical queries
g()
that take the following form in the extended Datalog syntax of
(
Cohen et al., 1999
;
Cohen et al., 2006
)
:

(1)

\displaystyle\mathtt{AGG}(r)\leftarrow q(\vec{u}),

where the
body

q(\vec{u})
is a conjunction of atoms (a.k.a. subgoals),
r
is either a numeric variable occurring in
\vec{u}
or a constant rational number, and
\mathtt{AGG}
is an aggregate symbol (like
\mathtt{MAX}
,
\mathtt{MIN}
,
\mathtt{SUM}
,
\mathtt{AVG}
,
\mathtt{COUNT}
).
Such a query will be called called an
\mathtt{AGG}
-query, and is interpreted as follows.
Every aggregate symbol
\mathtt{AGG}
in our query language is associated with an aggregate operator, denoted
\mathcal{F}_{\mathtt{AGG}}
, which is a function that takes a multiset of non-negative rational numbers, and returns a rational number.
The semantics on a given database instance
\mathbf{db}
is standard:
let
\theta_{1},\theta_{2},\ldots,\theta_{n}
enumerate all embeddings of the body into
\mathbf{db}
, then the query returns
\mathcal{F}_{\mathtt{AGG}}(\left\{\!\left\{{\theta_{1}(r),\theta_{2}(r),\ldots,\theta_{n}(r)}\right\}\!\right\})
.
Note that the argument of
\mathcal{F}_{\mathtt{AGG}}
is a multiset, because it is possible that
\theta_{i}(r)=\theta_{j}(r)
for
i\neq j
.

Note that numerical queries
g()
of the form (
1
) may return
\mathcal{F}_{\mathtt{AGG}}(\emptyset)
.
The value of an aggregate operator on the empty multiset is often fixed by convention, such as setting
\mathcal{F}_{\mathtt{SUM}}(\emptyset)\vcentcolon=0
.
To be independent of any such convention, we will define
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
and
{\mathsf{LUB\mathchar 45\relax CQA}}(g())
to return a distinguished constant
\bot
if
g()
returns
\mathcal{F}_{\mathtt{AGG}}(\emptyset)
on some repair. So we have the following function problem for any
\mathtt{AGG}
-query
g()
of the form (
1
):

Problem
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
.:

Input::

A database instance
\mathbf{db}
that may violate its primary key constraints.

Output::

Return
\bot
if some repair of
\mathbf{db}
falsifies
\exists\vec{u}(q(\vec{u}))
;

otherwise return
\min\left\{\llbracket{g()}\rrbracket^{\mathbf{r}}\mid\textnormal{$\mathbf{r}$ is a repair of $\mathbf{db}$}\right\}
.

Here,
\llbracket{g()}\rrbracket^{\mathbf{r}}
denotes the result of
g()
on
\mathbf{r}
.
The function problem
{\mathsf{LUB\mathchar 45\relax CQA}}(q)
is obtained by replacing
\min
with
\max
in the above problem.
Note that since every repair has a finite number of repairs, glb and lub are the same as min and max, respectively.

We write
\mathsf{AGGR}[\mathsf{sjfBCQ}]
for the class of all queries of the form (
1
) whose body
q(\vec{u})
is self-join-free (i.e., does not contain two distinct atoms with the same relation name).
In this paper, we are interested in the following complexity classification problem: Given a query
g()
in
\mathsf{AGGR}[\mathsf{sjfBCQ}]
,
determine the computational complexity of the function problem
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
.

(

)

From a theoretical perspective, our focus on the glb over the lub is without loss of generality, by exploiting that
\max(\left\{\!\left\{{r_{1},r_{2},\ldots,r_{k}}\right\}\!\right\})=-1*\min(\left\{\!\left\{{-1*r_{1},-1*r_{2},\ldots,-1*r_{k}}\right\}\!\right\})
.
For every aggregate operator
\mathcal{F}_{\mathtt{AGG}}
, we define its dual, denoted
\mathcal{F}_{\mathtt{AGG}}^{\mathsf{dual}}
, by
\mathcal{F}_{\mathtt{AGG}}^{\mathsf{dual}}(X)\vcentcolon=-1*\mathcal{F}_{\mathtt{AGG}}(X)
, for every multiset
X
.
Then, solving
{\mathsf{LUB\mathchar 45\relax CQA}}(g())
for an
\mathtt{AGG}
-query
g()\vcentcolon=\mathtt{AGG}(r)\leftarrow q(\vec{u})
is the same (up to a sign) as solving
{\mathsf{GLB\mathchar 45\relax CQA}}(h())
for
h()\vcentcolon=\mathtt{AGG}^{\mathsf{dual}}(r)\leftarrow q(\vec{u})
, where
\mathtt{AGG}^{\mathsf{dual}}
is the aggregate symbol associated with
\mathcal{F}_{\mathtt{AGG}}^{\mathsf{dual}}
.

We now discuss why we restrict ourselves to self-join-free queries.
Note that for a numerical query
g()\vcentcolon=\mathtt{AGG}(r)\leftarrow q(\vec{u})
, the decision problem
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
returns
\bot
on (and only on) “no”-instances of
{\mathsf{CERTAINTY}}(\exists\vec{u}(q(\vec{u})))
. Thus, a solution to
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
also solves
{\mathsf{CERTAINTY}}(\exists\vec{u}(q(\vec{u})))
. The computational complexity of the latter problem is well understood whenever
q(\vec{u})
is self-join-free
(
Koutris and Wijsen, 2017
)
—an understanding we build upon in the current paper—but it remains largely unexplored for queries with self-joins. Only recently has it been established for self-joins of size two
(
Padmanabha et al., 2024
)
. In particular, the concept of an attack graph, which is a key tool used in
(
Koutris and Wijsen, 2017
)
and in the current paper, loses its meaning and usefulness when self-joins are present.
Given the limited understanding of CQA for self-joins, we exclude self-joins in the current paper.

In our complexity study, we specifically aim to understand the conditions on
g()
under which
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
is solvable through rewriting in an aggregate logic, denoted
\mathsf{AGGR}[\mathsf{FOL}]
, which extends first-order logic with aggregate operators along the lines of
(
Hella et al., 2001
)
.
So our central problem takes as input a numerical query
g()
in
\mathsf{AGGR}[\mathsf{sjfBCQ}]
, and asks whether or not there is a numerical query
\varphi()
in
\mathsf{AGGR}[\mathsf{FOL}]
that solves
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
; moreover, when such
\varphi()
exists, we are interested in constructing it, a task loosely referred to as “glb rewriting of
g()
in
\mathsf{AGGR}[\mathsf{FOL}]
.”
A practical motivation for focusing on
\mathsf{AGGR}[\mathsf{FOL}]
is that formulas in this logic are well-suited for implementation in SQL, allowing them to benefit from existing DBMS technology.

Our primary general result can now be stated as follows, with the definitions of
monotone
and
associative
deferred to Section
5.1
:

Theorem 1.1 (Separation Theorem).

The following decision problem is decidable in quadratic time (in the size of the input):
Given as input a numerical query
g()
in
\mathsf{AGGR}[\mathsf{sjfBCQ}]
whose aggregate operator is both monotone and associative,
is
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
expressible in
\mathsf{AGGR}[\mathsf{FOL}]
?
Moreover, if the answer is “yes,” then it is possible to effectively construct, also in quadratic time, a formula in
\mathsf{AGGR}[\mathsf{FOL}]
that solves
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
.

That is, within the class
\mathsf{AGGR}[\mathsf{sjfBCQ}]
, we can effectively separate
\mathtt{AGG}
-queries that allow glb rewriting in
\mathsf{AGGR}[\mathsf{FOL}]
from those that do not, provided that
\mathtt{AGG}
satisfies monotonicity and associativity.
Such a separation result will also be obtained for
\mathtt{MIN}
- and
\mathtt{MAX}
-queries, for both glb and lub (see Theorem
7.11
).
Since the glb rewriting of Theorem
1.1
, if it exists, can be constructed in quadratic time, its length is at most quadratic.

As will be argued in Section
6.2
, all our results naturally extend to queries with a GROUP BY feature.

2.
Related Work

Consistent query answering (CQA) started by a seminal paper in 1999 co-authored by Arenas, Bertossi, and Chomicki
(
Arenas et al., 1999
)
, who introduced the notions of repair and consistent answer.
Two years later, the same authors introduced the
range semantics
(with lower and upper bounds) for queries with aggregation
(
Arenas et al., 2001
;
Arenas et al., 2003
)
(
Bertossi, 2011
, Chapter 5)
, which has been commonly adopted ever since.
Immediately related to our work is
(
Arenas et al., 2003
, Theorem 9)
, which establishes that

{\mathsf{GLB\mathchar 45\relax CQA}}(g())
is
\mathsf{NP}
-hard (and hence not expressible in
\mathsf{AGGR}[\mathsf{FOL}]
) for
g()\vcentcolon=\mathtt{COUNT\mathchar 45\relax DISTINCT}(r)\leftarrow R(\underline{x},r)
, where
R
is a binary relation whose first attribute is the primary key.
This
\mathsf{NP}
-hardness result is not implied by our Theorem
1.1
, as
\mathtt{COUNT\mathchar 45\relax DISTINCT}
lacks monotonicity and associativity (see Section
5.1
for details).

Ariel Fuxman defined in his PhD thesis
(
Fuxman, 2007
)
a syntactic class of self-join-free conjunctive queries, called
\mathsf{Cforest}
, whose extension with aggregate operators (
\mathtt{MAX}
,
\mathtt{MIN}
,
\mathtt{SUM}
,
\mathtt{COUNT}
) yields
\mathsf{Caggforest}
. Range semantics for queries in
\mathsf{Caggforest}
can be obtained by executing two first-order queries (one for lower bounds, and one for upper bounds) followed by simple aggregation steps; this technique was subsequently implemented in the ConQuer system
(
Fuxman et al., 2005a
)
through rewriting in SQL.
Although
(
Fuxman, 2007
)
permits aggregation over numerical columns containing both positive and negative numbers, as well as zero, we discovered that the SQL rewriting for
\mathtt{SUM}
-queries in
(
Fuxman, 2007
)
is flawed when negative numbers are present, as detailed in Section
7.3
.

The class
\mathsf{Cparsimony}

(
Khalfioui and Wijsen, 2023
)
is an extension of
\mathsf{Cforest}
that contains all (and only) self-join-free conjunctive queries for which Fuxman’s technique applies for
\mathtt{COUNT}
.
The ease with which
\mathsf{Cforest}
and
\mathsf{Cparsimony}
facilitate range semantics through Fuxman’s technique can be attributed to their requirement that joins between non-key and key attributes must involve the entire key of a relation, commonly referred to as “full” joins; they do not allow “partial” joins where two relations can join on some (but not all) attributes of a primary key.
In the current paper, we allow partial joins.

Fuxman’s technique is different from AggCAvSAT
(
Dixit and Kolaitis, 2022
)
, a recent system by Dixit and Kolaitis, which uses powerful SAT solvers for computing range semantics, and thus can solve queries that are beyond the computational power of ConQuer.
Aggregation queries were also studied in the context of CQA in
(
Bertossi et al., 2008
)
.

CQA for self-join-free conjunctive queries
q
, without aggregation, and primary keys has been intensively studied.
Its decision variant, which was coined
{\mathsf{CERTAINTY}}(q)
in 2010
(
Wijsen, 2010
)
, asks whether a Boolean query
q
is true in every repair of a given database instance.
A systematic study of its complexity for self-join-free conjunctive queries had started already in 2005
(
Fuxman and Miller, 2005
)
, and was eventually solved in two journal articles by Koutris and Wijsen
(
Koutris and Wijsen, 2017
;
Koutris and Wijsen, 2021
)
, as follows: for every self-join-free Boolean conjunctive query
q
,
{\mathsf{CERTAINTY}}(q)
is either in
\mathsf{FO}
,
\mathsf{L}
-complete, or
\mathsf{coNP}
-complete, and it is decidable, given
q
, which case applies.
This complexity classification extends to non-Boolean queries by treating free variables as constants.
Other extensions beyond this trichotomy deal with foreign keys
(
Hannula and Wijsen, 2022
)
, more than one key per relation
(
Koutris and Wijsen, 2020
)
, negated atoms
(
Koutris and Wijsen, 2018
)
, or restricted self-joins
(
Koutris et al., 2021
;
Koutris et al., 2024
;
Padmanabha et al., 2024
)
.
For unions of conjunctive queries
q
, Fontaine
(
Fontaine, 2015
)
established interesting relationships between
{\mathsf{CERTAINTY}}(q)
and Bulatov’s dichotomy theorem
for conservative CSP
(
Bulatov, 2011
)
.
Recently, Figueira et al.
(
Figueira et al., 2023
)
proposed a polynomial-time algorithm for solving
{\mathsf{CERTAINTY}}(q)
for conjunctive queries
q
, including those with self-joins, and showed that it can replace all polynomial-time algorithms found in
(
Koutris and Wijsen, 2017
;
Koutris et al., 2021
)
.

The counting variant
\sharp{\mathsf{CERTAINTY}}(q)
asks to count the number of repairs that satisfy some Boolean query
q
.
This counting problem is fundamentally different from the range semantics in the current paper.
For self-join-free conjunctive queries,
\sharp{\mathsf{CERTAINTY}}(q)
exhibits a dichotomy between
\mathsf{FP}
and
\sharp\mathsf{P}
-complete under polynomial-time Turing reductions
(
Maslowski and Wijsen, 2013
)
. This dichotomy has been shown to extend to queries with self-joins if primary keys are singletons
(
Maslowski and Wijsen, 2014
)
, and to functional dependencies
(
Calautti et al., 2022a
)
.
Calautti, Console, and Pieris present in
(
Calautti et al., 2019
)
a complexity analysis of these counting problems under weaker reductions, in particular, under many-one logspace reductions.
The same authors have conducted an experimental evaluation of randomized approximation schemes for approximating the percentage of repairs that satisfy a given query
(
Calautti et al., 2021
)
.
Other approaches to making CQA more meaningful and/or tractable include operational repairs
(
Calautti et al., 2018
;
Calautti et al., 2022b
)
and preferred repairs
(
Kimelfeld et al., 2020
;
Staworko et al., 2012
)
.

Recent overviews of two decades of theoretical research in CQA can be found in
(
Bertossi, 2019
;
Wijsen, 2019
;
Kimelfeld and Kolaitis, 2024
)
.
It is worthwhile to note that theoretical research in
{\mathsf{CERTAINTY}}(q)
has stimulated implementations and experiments in prototype systems
(
Dixit and Kolaitis, 2019
;
Fan et al., 2023
;
Fuxman et al., 2005a
;
Fuxman et al., 2005b
;
Khalfioui et al., 2020
;
Kolaitis et al., 2013
)
.

3.
Preliminaries

We assume denumerable sets
\mathbf{var}
and
\mathbf{dom}
of variables and constants respectively.
The set
\mathbf{dom}
includes
\mathbb{Q}_{\geq 0}
, the set of non-negative rational numbers.
The set of
numerical variables
is a subset of
\mathbf{var}
.

We assume denumerably many relation names. Every relation name is associated with a
signature
, which is a triple
(n,k,J)
where
n
is the
arity
,
\{1,\ldots,k\}
is called the
primary key
, and
J\subseteq\{1,\ldots,n\}
are
numerical positions
(also called
numerical columns
).
This relation name is
full-key
if
n=k
.
Note that each relation name
R
is associated with exactly one key constraint, which is determined by the signature of
R
. For an
n
-tuple
\vec{x}=(x_{1},\ldots,x_{n})
, we write
|\vec{x}|
to denote its
arity

n
.
We often blur the distinction between a sequence
(x_{1},\ldots,x_{n})
of distinct variables and the set
\{x_{1},\ldots,x_{n}\}
, which is also denoted
{\mathsf{vars}}(\vec{x})
.

Atoms, facts, and database instances

Let
R
be a relation name of signature
(n,k,J)
.
An
atom
is an expression
R(u_{1},\ldots,u_{n})
where each
u_{i}
is either a constant or a variable, and for every
j\in J
,
u_{j}
is a numerical variable or a number in
\mathbb{Q}_{\geq 0}
.
It is common to underline positions of the primary key.
If
F
is an atom, then
{\mathsf{vars}}(F)
is the set of variables that occur in
F
, and
{\mathsf{Key}}(F)
is the set of variables that occur in
F
at a position of the primary key. Further, we define
{\mathsf{notKey}}(F)\vcentcolon={\mathsf{vars}}(F)\setminus{\mathsf{Key}}(F)
.
A
fact
is an atom without variables.
A fact with relation name
R
is also called an
R
-fact.
Two facts
R_{1}(\underline{\vec{a}_{1}},\vec{c}_{1})
and
R_{2}(\underline{\vec{a}_{2}},\vec{c}_{2})
are said to be
key-equal
if
R_{1}=R_{2}
and
\vec{a}_{1}=\vec{a}_{2}
.

A
database instance
is a finite set of facts.
If
R
is a relation name, then the
R
-relation of
\mathbf{db}
is the set of all
R
-facts in
\mathbf{db}
.
A
database instance
is
consistent
if it does not contain two distinct facts that are key-equal.
Please be aware that there is no requirement to explicitly specify the primary keys, as they are derived from the predetermined signatures associated with the relation names of the facts present in the database instance.

Valuation.

A
valuation
over a finite set
U
of variables is a total mapping
\theta
from
U
to
\mathbf{dom}
such that
\theta(r)\in\mathbb{Q}_{\geq 0}
for every numeric variable
r
.
For a valuation
\theta
over
U
, we write
\mathsf{dom}(\theta)
to denoted its
domain

U
.
A valuation
\theta
over
U
is extended to every element
u
in
\mathbf{var}\cup\mathbf{dom}
by letting
\theta(u)=u
for every
u\notin U
.
If
\theta
is a valuation and
V\subseteq\mathsf{dom}(\theta)
, then
{\theta}\restriction_{V}
denotes the restriction of
\theta
to
V
, i.e.,
\mathsf{dom}({\theta}\restriction_{V})=V
and for every
x\in V
, we have
{\theta}\restriction_{V}(x)=\theta(x)
.

Let
\theta
be a valuation.
If
F
is the atom
R(u_{1},\ldots,u_{n})
, then
\theta(F)\vcentcolon=R(\theta(u_{1}),\ldots,\theta(u_{n}))
.
If
q
is a set of atoms, then
\theta(q)\vcentcolon=\{\theta(F)\mid F\in q\}
.
The set
\theta(q)
is also denoted
{q}_{[{\vec{y}}\mapsto{\vec{c}}]}
where
\vec{y}
is a shortest sequence containing every variable in
\mathsf{dom}(\theta)
, and
\vec{c}\vcentcolon=\theta(\vec{y})
.
Significantly, every variable in
{\mathsf{vars}}(q)\setminus\mathsf{dom}(\theta)
remains a variable in
\theta(q)

Partial valuation.

Boolean Conjunctive Queries

A

For example, if

from its body.

Attack graph

Attack graphs of queries in

were first introduced in
(

and subsequently generalized in
(
Koutris and Wijsen, 2017
)

Their definition is technical and not immediately intuitive.
However, as will become clear in the technical treatment, the partial order induced by acyclic attack graphs will play an essential role in query rewriting.

Let
q\in\mathsf{sjfBCQ}
.
We write
{\mathcal{K}}(q)
for the set of functional dependencies that contains
{{\mathsf{Key}}(F)}\rightarrow{{\mathsf{vars}}(F)}
whenever
F\in q
.
For
F\in q

{F}^{+,q}\vcentcolon=\{x\in{\mathsf{vars}}(q)\mid{\mathcal{K}}(q\setminus\{F\})\models{{\mathsf{Key}}(F)}\rightarrow{x}\}
, where
\models
is the standard notion of logical implication.
An atom
F
of

is said to

, if there is a sequence of variables
(x_{1},x_{2},\ldots,x_{m})
such that no

is in
{F}^{+,q}
,

,

, and every two adjacent variables occur together in some atom of

.
A variable

is said to be
unattacked (in
q
)
if no atom attacks
x
.
The
attack graph
of

is a directed simple graph whose vertices are the atoms of
q
. There is a directed edge from

to
G
, denoted
F\stackrel{{\scriptstyle q}}{{\rightsquigarrow}}G
, if
F
attacks some variable of
{\mathsf{vars}}(G)
.

Whenever a query in
\mathsf{sjfBCQ}
is clear from the context, we can use a relation name as a shorthand for the unique atom with that relation name in the query. For example, in the following example,
R
is a shorthand for the atom

.

\forall

In

)
, a construct called “frugal repair” was introduced. In the current section, we introduce a related but more stringent construct, called

Embeddings and
\forall
embeddings

Whenever
q(\vec{u})
is a conjunction of atoms, we write
q
to denote the closed formula
\exists\vec{u}(q(\vec{u}))
.
Let
q(\vec{u})
now be a self-join-free conjunction of
n
atoms such that the attack graph of
q
is acyclic.
The following definitions are relative to a fixed topological sort
(F_{1},\ldots,F_{n})
of
q
’s attack graph and a fixed database instance
\mathbf{db}
.
We define the following sequences of variables for
\ell\in\{1,\ldots,n\}
:

•

\vec{u}_{\ell}
contains all (and only) variables of
\bigcup_{i=1}^{\ell}{\mathsf{vars}}(F_{i})
. Thus,
\vec{u}_{n}=\vec{u}
;

•

\vec{x}_{\ell}
contains the variables of
{\mathsf{Key}}(F_{\ell})
that do not already occur in
\bigcup_{i=1}^{\ell-1}{\mathsf{vars}}(F_{i})
; and

•

\vec{y}_{\ell}
contains the variables of
{\mathsf{notKey}}(F_{\ell})
that do not already occur in
\bigcup_{i=1}^{\ell-1}{\mathsf{vars}}(F_{i})
.

Moreover, we define
\vec{u}_{0}=()
, the empty sequence.
With this notation, we have that for every
\ell\in\{1,\ldots,n\}
,

(2)

\vec{u}_{\ell}=(\vec{u}_{\ell-1},\vec{x}_{\ell},\vec{y}_{\ell}).

Let
\ell\in\{1,\ldots,n\}
in what follows.
An
\ell
-embedding (of
q
in
\mathbf{db}
)
is a valuation
\theta
over
\vec{u}_{\ell}
such that
(\mathbf{db},\theta)\models q(\vec{u})
. Further, a
0
-embedding is defined to be the empty set.
An
\ell
-embedding with
\ell=n
is also called an
embedding
for short.
A set
M
of embeddings is said to be
consistent
if
M\models{\mathcal{K}}(q)
.

The following definition is by induction.
An
\ell
-embedding
\theta
is called an
\ell
-
\forall
embedding (of
q
in
\mathbf{db}
)
if one of the following holds true:

Basis::

\ell=0
and every repair of
\mathbf{db}
satisfies
q
; or

Step::

\ell\geq 1
and both the following hold true:

•:

(\mathbf{db},{\theta}\restriction_{\vec{u}_{\ell-1}\vec{x}_{\ell}})\models_{\mathsf{cqa}}F_{\ell}\land F_{\ell+1}\land\dotsm\land F_{n}
; and

•:

the
(\ell-1)
-embedding contained in
\theta
is an
(\ell-1)
-
\forall
embedding.

In simple terms, the first bullet states that every repair must satisfy the query whose atoms are obtained from
F_{\ell},F_{\ell+1},\ldots,F_{n}
by replacing
x
with
\theta(x)
whenever
x
is a variable that occurs in the primary key of
F_{\ell}
or in an atom that precedes
F_{\ell}
.
The second bullet implies that the same condition must hold for
\ell-1,\ell-2,\ldots,2,1
, and eventually
0
.
An
\ell
-
\forall
embedding with
\ell=n
is also called a
\forall
embedding
for short.

Example 4.1.

The query
q_{0}=\exists t\exists p(\mathit{Dealers}(\underline{\textnormal{``James''}},t)\land\mathit{Stock}(\underline{p,t},\textnormal{35}))

in the town where James is a dealer.
It holds true in every repair of the database instance

of Fig.

.
The embedding
\{t\mapsto\textnormal{``Boston''},p\mapsto\textnormal{``Tesla~Y''}\}
is a
\forall
embedding.
On the other hand, the embedding

is not a

embedding, because
{\theta}\restriction_{\{t,p\}}=\theta
and
(\mathbf{db}_{\mathsf{Stock}},\theta)\not\models_{\mathsf{cqa}}\mathit{Stock}(\underline{p,t},\textnormal{35})
.
Indeed, if
\mathbf{r}
is a repair that contains
\mathit{Stock}(\underline{\textnormal{``Tesla~X''},\textnormal{``Boston''}},\textnormal{40})
,
then
(\mathbf{r},\theta)\not\models\mathit{Stock}(\underline{p,t},\textnormal{35})
.

\triangleleft

We now state two important helping lemmas. The first one states that all topological sorts of an acyclic attack graph yield the same
\forall
embeddings. The second lemma establishes that
\forall
embeddings can be computed in
\mathsf{FOL}
.

Lemma 4.2.

Let
q
a query in
\mathsf{sjfBCQ}
with an acyclic attack graph, and
\mathbf{db}
be a database instance.
Let

be the number of atoms in
q
.
Let

and
\prec_{2}
be two topological sorts of

Every
n
-
\forall
embedding relative to

is an

-
\forall
embedding relative to
\prec_{2}
.

Lemma 4.3.

Let

be a query in
\mathsf{sjfBCQ}
with an acyclic attack graph.
It is possible to construct, in quadratic time in the size of

, a
\mathsf{FOL}
formula

such that for every database instance
\mathbf{db}
, for every valuation
\theta
over
\vec{u}

\mathbf{db}
.

Note that since the formula

in Lemma

Let
\mathbf{db}
be a database instance, and

In the current paper, we opted to define superfrugal repairs in terms of

5.
Aggregate Logic and CQA

In this section, we first define the notion of
aggregate operator
and then introduce the logic
\mathsf{AGGR}[\mathsf{FOL}]
which will serve as the target language for our rewritings.
We formally define consistent lower and upper bounds, denoted
{\mathsf{LUB\mathchar 45\relax CQA}}(g(\vec{x}))
and
{\mathsf{GLB\mathchar 45\relax CQA}}(g(\vec{x}))
, for arbitrary numerical terms
g(\vec{x})
in
\mathsf{AGGR}[\mathsf{FOL}]
with free variables
\vec{x}
.
Our study will subsequently focus on closed numerical terms
g()
in
\mathsf{AGGR}[\mathsf{sjfBCQ}]
, a subclass of
\mathsf{AGGR}[\mathsf{FOL}]
introduced in Section
5.4
.

5.1.
Aggregating Non-Negative Numbers

A
(positive) aggregate operator
is a function
\mathcal{F}
that takes as argument a finite multiset
X
of non-negative rational numbers such that
\mathcal{F}(X)\in\mathbb{Q}_{\geq 0}
if
X\neq\emptyset
, and
\mathcal{F}(\emptyset)=f_{0}
.
Here,
f_{0}
is a constant (not necessarily in
\mathbb{Q}_{\geq 0}
), which is the value returned by
\mathcal{F}
on the empty multiset.
In the following definitions, all multisets are understood to be multisets of non-negative rational numbers.

An aggregate operator is
associative
if for all non-empty multisets
X
and
Y
such that
X\neq\emptyset
, we have
\mathcal{F}(X\uplus Y)=\mathcal{F}(\left\{\!\left\{{\mathcal{F}(X)}\right\}\!\right\}\uplus Y)
, where
\uplus
denotes union of multisets.

Example 5.1.

Examples of associative aggregate operators are
\mathcal{F}_{\mathtt{MAX}}
,
\mathcal{F}_{\mathtt{MIN}}
, and
\mathcal{F}_{\mathtt{SUM}}
.
Examples of aggregate operators that are not associative are
\mathcal{F}_{\mathtt{AVG}}
,
\mathcal{F}_{\mathtt{COUNT}}
, and
\mathcal{F}_{\mathtt{SUM\mathchar 45\relax DISTINCT}}
.
Note, for instance,
\mathcal{F}_{\mathtt{COUNT}}(\left\{\!\left\{{5,6,7,8}\right\}\!\right\})=4
and
\mathcal{F}_{\mathtt{COUNT}}(\left\{\!\left\{{\mathcal{F}_{\mathtt{COUNT}}(\left\{\!\left\{{5,6,7}\right\}\!\right\}),8}\right\}\!\right\})=\mathcal{F}_{\mathtt{COUNT}}(\left\{\!\left\{{3,8}\right\}\!\right\})=2
.

\triangleleft

An aggregate operator
\mathcal{F}
is
monotone
if for all
m>0
and every (possibly empty) multiset
Y
, we have
\mathcal{F}(\left\{\!\left\{{x_{1},\ldots,x_{m}}\right\}\!\right\})\leq\mathcal{F}(\left\{\!\left\{{x_{1}^{\prime},\ldots,x_{m}^{\prime}}\right\}\!\right\}\uplus Y)
whenever
x_{i}\leq x_{i}^{\prime}
for every
i
.

Example 5.2.

Examples of monotone aggregate operators are
\mathcal{F}_{\mathtt{MAX}}
,
\mathcal{F}_{\mathtt{SUM}}
, and
\mathcal{F}_{\mathtt{COUNT}}
.
Note that
\mathcal{F}_{\mathtt{MIN}}
is not monotone since
\mathcal{F}_{\mathtt{MIN}}(\left\{\!\left\{{3}\right\}\!\right\})>\mathcal{F}_{\mathtt{MIN}}(\left\{\!\left\{{2,3}\right\}\!\right\})
.

\mathtt{COUNT\mathchar 45\relax DISTINCT}
also lacks monotonicity: if we increase
3
to
4
in the multiset
\left\{\!\left\{{3,4}\right\}\!\right\}
, the number returned by
\mathtt{COUNT\mathchar 45\relax DISTINCT}
drops from
2
to
1
.

\triangleleft

Significantly, an aggregate operator
\mathcal{F}
that is not monotone in general may become monotone under a restriction of its underlying domain. For example,
\mathcal{F}_{\mathtt{PRODUCT}}
, defined by
\mathcal{F}_{\mathtt{PRODUCT}}(\left\{\!\left\{{x_{1},\ldots,x_{m}}\right\}\!\right\})\vcentcolon=\Pi_{i=1}^{m}x_{i}
, is not monotone over
\mathbb{Q}_{\geq 0}
(because
\mathcal{F}_{\mathtt{PRODUCT}}(\left\{\!\left\{{1}\right\}\!\right\})>\mathcal{F}_{\mathtt{PRODUCT}}(\left\{\!\left\{{1,\frac{1}{2}}\right\}\!\right\})
), but is monotone over
\mathbb{Q}_{\geq 1}
.

5.2.
The Logic
\mathsf{AGGR}[\mathsf{FOL}]

Our treatment of aggregate logic follows the approach in
(
Hella et al., 2001
;
Libkin, 2004
)
.
We write
\mathsf{AGGR}[\mathsf{FOL}]
for the extension of predicate calculus introduced next.

Let
q(\vec{x},\vec{y})
be a formula, where
\vec{x}
,
\vec{y}
are disjoint sequences that together contain each free variable of
q
exactly once.
A
primitive numerical term
is either a non-negative rational number or a numerical variable in
\vec{x}\vec{y}
.
For example, the query of Example
4.1
uses the constant numerical term
35
.
For every possible aggregate operator
\mathcal{F}
, a primitive numerical term
r
, and a formula
q(\vec{x},\vec{y})
, we have a new
numerical term

g(\vec{x})=\mathsf{Aggr}_{\mathcal{F}}\vec{y}\left[{r,q(\vec{x},\vec{y})}\right].

Variables
\vec{y}
that are free in
q(\vec{x},\vec{y})
become bound in
\mathsf{Aggr}_{\mathcal{F}}\vec{y}\left[{r,q(\vec{x},\vec{y})}\right]
;
in this respect
\mathsf{Aggr}_{\mathcal{F}}\vec{y}
behaves like a sort of quantification over
\vec{y}
.
Next, we define the semantics.

Let
\vec{a}
be a sequence of constants of length
|\vec{x}|
.
The value
g(\vec{a})
on a database instance
\mathbf{db}
, denoted
\llbracket{g(\vec{a})}\rrbracket^{\mathbf{db}}
, is calculated as follows.
If there is no
\vec{b}
such that
\mathbf{db}\models q(\vec{a},\vec{b})
, then
\llbracket{g(\vec{a})}\rrbracket^{\mathbf{db}}=f_{0}
, with
f_{0}
as defined in Section
5.1
.
Otherwise, let
\theta_{1},\ldots,\theta_{m}
enumerate (without duplicates) all valuations over
{\mathsf{vars}}(\vec{x}\vec{y})
such that
\theta_{i}(\vec{x})=\vec{a}
and
(\mathbf{db},\theta_{i})\models q(\vec{x},\vec{y})
for
1\leq i\leq m
.
Then,
\llbracket{g(\vec{a})}\rrbracket^{\mathbf{db}}=\mathcal{F}(\left\{\!\left\{\theta_{1}(r),\ldots,\theta_{m}(r)\right\}\!\right\})
.
Note that the argument of
\mathcal{F}
is in general a multiset, since
\theta_{i}(r)
may be equal to
\theta_{j}(r)
for
i\neq j
.
A numerical term without free variables is also called a
numerical query
, denoted
g()
.

Example 5.3.

Retrieve the town(s) with the largest total quantity of stored products.
First, we provide a formula
q_{0}(t,y)
which holds true if
y
is the total quantity of products stored in town
t
:

q_{0}(t,y)\vcentcolon=\exists p\exists z\left(\mathit{Stock}(\underline{p,t},z)\right)\land y=\mathsf{Aggr}_{\mathcal{F}_{\mathtt{SUM}}}(p,z)\left[{z,\mathit{Stock}(\underline{p,t},z)}\right].

The final query is

\exists y\left(q_{0}(t,y)\land y=\mathsf{Aggr}_{\mathcal{F}_{\mathtt{MAX}}}(t,z)\left[{z,q_{0}(t,z)}\right]\right)
,
with
q_{0}
as previously defined.
The variable
z
is used for clarity, but can be renamed in
y
without creating a naming conflict.

\triangleleft

5.3.
Lower and Upper Bounds Across All Repairs

For each numerical term
g(\vec{x})\vcentcolon=\mathsf{Aggr}_{\mathcal{F}}\vec{y}\left[{r,q(\vec{x},\vec{y})}\right]
, we define
{\mathsf{GLB\mathchar 45\relax CQA}}(g(\vec{x}))
and
{\mathsf{LUB\mathchar 45\relax CQA}}(g(\vec{x}))
relative to a database instance
\mathbf{db}
.
Let
\vec{a}
be a sequence of constants of length
|\vec{x}|
.
If there is a repair
\mathbf{r}
of
\mathbf{db}
such that
\llbracket{g(\vec{a})}\rrbracket^{\mathbf{r}}=f_{0}
, then
\llbracket{{\mathsf{GLB\mathchar 45\relax CQA}}(g(\vec{a}))}\rrbracket^{\mathbf{db}}=\bot
; otherwise

\llbracket{{\mathsf{GLB\mathchar 45\relax CQA}}(g(\vec{a}))}\rrbracket^{\mathbf{db}}\vcentcolon=\min\left\{\llbracket{g(\vec{a})}\rrbracket^{\mathbf{r}}\mid\mathbf{r}\in\mathsf{rset}({\mathbf{db}})\right\}.

The value

is defined symmetrically by replacing

with

Note that

is not a consistent answer to the query

5.4.
Range CQA for
\mathsf{AGGR}[\mathsf{sjfBCQ}]

Our focus will be on glb and lub rewriting of numerical terms

g(\vec{x})\vcentcolon=\mathsf{Aggr}_{\mathcal{F}}\vec{y}\left[{r,q(\vec{x},\vec{y})}\right]

where
q(\vec{x},\vec{y})
is a self-join-free conjunction of atoms.
For readability, we often express such a numerical term

using the following Datalog-like syntax:

where the aggregate symbol

is interpreted by the aggregate operator

, which is often made explicit by writing

.
For instance,
\mathtt{SUM}
is interpreted by
\mathcal{F}_{\mathtt{SUM}}
, and
\mathtt{MAX}
by
\mathcal{F}_{\mathtt{MAX}}
.

Our research question is: Under which conditions can

and
{\mathsf{LUB\mathchar 45\relax CQA}}(g(\vec{x}))
be expressed in
\mathsf{AGGR}[\mathsf{FOL}]
?
In the initial technical treatment, we assume that
\vec{x}
is empty, i.e., we are dealing with numerical terms

without free variables, which are conveniently expressed as

.
In Section

, we treat the extension to free variables.
The following definition pinpoints the class of queries we are interested in; it is followed by a first inexpressibility result, which captures the “no”-side of Theorem

.

Definition 5.4.

\mathsf{AGGR}[\mathsf{sjfBCQ}]
is defined as the class of numerical queries
\mathsf{Aggr}_{\mathcal{F}}\vec{y}\left[{r,q(\vec{y})}\right]
where

is a self-join-free conjunction of atoms.
An alternative syntax is
\mathtt{AGG}(r)\leftarrow q(\vec{y})

\mathtt{AGG}
is interpreted by

(which is often made explicit by writing

\triangleleft

Theorem 5.5.

Let
g()\vcentcolon=\mathtt{AGG}(r)\leftarrow q(\vec{y})
be a numerical query in

.

(

(

It follows from
(

that

Moreover, from the proof of Theorem

6.
Aggregate Operators that are Both Associative and Monotone

In this section, we show that the inverse of Theorem

Later, in Section

Theorem 6.1.

It follows from Theorems

5.5

6.2.
Aggregation Queries with Free Variables

So far, we have focused on numerical terms
g()
without free variables.
We now explain how our results extend to numerical terms
g(\vec{x})=\mathsf{Aggr}_{\mathcal{F}}\vec{y}\left[{r,q(\vec{x},\vec{y})}\right]
with free variables
\vec{x}\vcentcolon=(x_{1},\ldots,x_{k})
, where
q(\vec{x},\vec{y})
is self-join-free.
Let
\vec{c}=(c_{1},\ldots,c_{k})
be a sequence of distinct constants.
Let
q_{\vec{c}}(\vec{y})
be the conjunction obtained from
q(\vec{x},\vec{y})
by replacing, for
i\in\{1,\ldots,k\}
, each occurrence of each
x_{i}
by
c_{i}
.
Then,

•

if the attack graph of
\exists\vec{y}(q_{\vec{c}}(\vec{y}))
is cyclic, then by Theorem
5.5
,
{\mathsf{GLB\mathchar 45\relax CQA}}(g(\vec{c}))
is not in
\mathsf{AGGR}[\mathsf{FOL}]
; and

•

if the attack graph of
\exists\vec{y}(q_{\vec{c}}(\vec{y}))
is acyclic, then by Theorem
6.1
, there is a formula
\varphi_{\vec{c}}
in
\mathsf{AGGR}[\mathsf{FOL}]
that solves
{\mathsf{GLB\mathchar 45\relax CQA}}(g(\vec{c}))
.

It is now not hard to show that since
q(\vec{x},\vec{y})
is self-join-free, different sequences of constants involve the same calculations up to a renaming of constants.
This implies that we can perform the calculation once by treating the free variables in
\vec{x}
as distinct constants. This treatment of free variables is often used in consistent query answering (and in logic in general
(
Libkin, 2004
, Lemma 2.3)
); however, it fails for CQA in the presence of self-joins.
This is one of the reasons why assuming self-join-freeness serves as a simplifying assumption in much work on CQA.

7.
Aggregate Operators Lacking Monotonicity or Associativity

Let
g()\vcentcolon=\mathtt{AGG}(r)\leftarrow q(\vec{y})
be a numerical query in
\mathsf{AGGR}[\mathsf{sjfBCQ}]
.
In this section, we explore the scenario left open by Theorems
5.5
and
6.1
: we assume that the attack graph of
\exists\vec{y}(q(\vec{y}))
is acyclic, but that
\mathcal{F}_{\mathtt{AGG}}
lacks either monotonicity, associativity, or both.
We introduce in Section
7.1
a manifestation of non-monotonicity, called
descending chains
, which is used to identify cases where
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
is not expressible in
\mathsf{AGGR}[\mathsf{FOL}]
under the above assumptions.
Descending chains are also used in Section
7.2
in the study of
{\mathsf{LUB\mathchar 45\relax CQA}}(g())
via the use of dual aggregate operators, and in Section
7.3
to demonstrate that unconstrained numeric columns (i.e., columns not constrained to
\mathbb{Q}_{\geq 0}
) suffice for moving from expressibility in
\mathsf{AGGR}[\mathsf{FOL}]
to non-expressibility.
We conclude with a positive result: when
g()
is a
\mathtt{MIN}
- or a
\mathtt{MAX}
-query, it is decidable whether or not
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
and
{\mathsf{LUB\mathchar 45\relax CQA}}(g())
are expressible in
\mathsf{AGGR}[\mathsf{FOL}]
.

7.1.
Aggregate Operators with Descending Chains

We show that the inverse of Theorem
5.5
does not hold: Lemmas
7.2
and
7.3
introduce numerical queries with acyclic attack graphs that however do not allow glb rewriting in
\mathsf{AGGR}[\mathsf{FOL}]
.
Their proofs rely on the existence of a (possibly bounded) descending chain for an aggregate operator
\mathcal{F}_{\mathtt{AGG}}
, which implies that
\mathcal{F}_{\mathtt{AGG}}
lacks monotonicity.
Concrete examples of such aggregate operators are
\mathcal{F}_{\mathtt{AVG}}
and
\mathcal{F}_{\mathtt{PRODUCT}}
, as expressed by Corollary
7.5
(assuming that the numeric domain is
\mathbb{Q}_{\geq 0}
).

Definition 7.1 (Descending chain).

,

\mathcal{F}_{\mathtt{AGG}}(\left\{\!\left\{{s,{i}\#{t}}\right\}\!\right\})>\mathcal{F}_{\mathtt{AGG}}(\left\{\!\left\{{s,{(i+1)}\#{t}}\right\}\!\right\})

\mathcal{F}_{\mathtt{AGG}}(\left\{\!\left\{{s,{k^{\prime}}\#{t}}\right\}\!\right\})<\mathcal{F}_{\mathtt{AGG}}(\left\{\!\left\{{{j}\#{m_{i}},s,{k}\#{t}}\right\}\!\right\})
.
Informally, this expression means that

will strictly increase if at least one copy of
m_{i}
is added, regardless of any addition of copies of

.
Notice that

depends on

.
See the proof of Lemma

for examples.

\triangleleft

Lemma 7.2.

Let

\mathcal{F}_{\mathtt{AVG}}

Proof.

For

\mathcal{F}_{\mathtt{AVG}}(\left\{\!\left\{{1}\right\}\!\right\})>\mathcal{F}_{\mathtt{AVG}}(\left\{\!\left\{{1,0}\right\}\!\right\})>\mathcal{F}_{\mathtt{AVG}}(\left\{\!\left\{{1,0,0}\right\}\!\right\}>\mathcal{F}_{\mathtt{AVG}}(\left\{\!\left\{{1,0,0,0}\right\}\!\right\}>\dotsm

7.2.
Dual Aggregate Operators

Definition 7.6 (Dual aggregate operator).

The
dual
of a positive aggregate operator
\mathcal{F}
, denoted
\mathcal{F}^{\mathsf{dual}}
, is defined as the function that takes as argument a finite multiset
X
of non-negative rational numbers such that
\mathcal{F}^{\mathsf{dual}}(X)=-1*\mathcal{F}(X)
if
X\neq\emptyset
, and
\mathcal{F}^{\mathsf{dual}}(\emptyset)=\mathcal{F}(\emptyset)
.
The dual of a positive aggregate operator is also called a
dual aggregate operator
.

\triangleleft

Note that a dual aggregate operator is not a positive aggregate operator itself, as it can return negative rational numbers. Despite this, Definition
7.1
of (bounded) descending chain applies also to dual aggregate operators. Additionally, it can be verified that Lemmas
7.2
and
7.3
remain valid for dual aggregate operators, since their proofs do not rely on the signs of the aggregated values.

As argued in Section
1
and formalized by Proposition
7.7
, the function problem
{\mathsf{LUB\mathchar 45\relax CQA}}(g())
for
g()\vcentcolon=\mathtt{AGG}(r)\leftarrow q(\vec{u})
is the same up to a sign as
{\mathsf{GLB\mathchar 45\relax CQA}}(h())
where
h()
has the same body as
g()
, but uses the dual of
\mathtt{AGG}
in its head:

h()\vcentcolon=\mathtt{AGG}^{\mathsf{dual}}(r)\leftarrow q(\vec{u}),

where the aggregate symbol
\mathtt{AGG}^{\mathsf{dual}}
is interpreted by
\mathcal{F}_{\mathtt{AGG}}^{\mathsf{dual}}
, i.e., the dual of
\mathcal{F}_{\mathtt{AGG}}
.
The semantics of
h()
on a database instance
\mathbf{db}
is naturally defined: if
g()
returns a rational number
r
distinct from
f_{0}
, then
h()
returns
-1*r
; and if
g()
returns
f_{0}
, then so does
h()
.
The problems
{\mathsf{GLB\mathchar 45\relax CQA}}(h())
and
{\mathsf{LUB\mathchar 45\relax CQA}}(h())
are defined as before.
The proof of the following propostion is straightforward.

Proposition 7.7.

Let
g()\vcentcolon=\mathtt{AGG}(r)\leftarrow q(\vec{u})
be a numerical query in
\mathsf{AGGR}[\mathsf{sjfBCQ}]
.
Let

Then, for every database instance
\mathbf{db}
such that

\llbracket{{\mathsf{LUB\mathchar 45\relax CQA}}(g())}\rrbracket^{\mathbf{db}}=-1*\llbracket{{\mathsf{GLB\mathchar 45\relax CQA}}(h())}\rrbracket^{\mathbf{db}}
.

If we let
\mathtt{AGG}=\mathtt{SUM}
in the numerical term

of Lemma

{\mathsf{GLB\mathchar 45\relax CQA}}(g())
is in

(by Theorem

{\mathsf{LUB\mathchar 45\relax CQA}}(g())

From

8.
Summary and Open Questions

We studied the complexity of computing range consistent answers to numerical queries
g()
of the form
\mathtt{AGG}(r)\leftarrow q(\vec{u})
where
q(\vec{u})
is a self-join-free conjunction of atoms.
Given a database instance that may violate its primary key constraints, the question is to determine the minimal (glb) and maximal (lub) values of
g()
returned across all repairs.
Since the lub coincides (up to a sign) with the glb relative to the dual aggregate operator
\mathtt{AGG}^{\mathsf{dual}}
, it suffices to focus on the glb, i.e., on
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
.
Our main result is that for aggregate operators
\mathtt{AGG}
that are monotone and associative (e.g.,
\mathtt{SUM}
over
\mathbb{Q}_{\geq 0}
), it is decidable, given
g()
, whether or not
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
can be expressed in the aggregate logic
\mathsf{AGGR}[\mathsf{FOL}]
.
Decidability also holds for
\mathtt{AGG}\in\{\mathtt{MIN},\mathtt{MAX}\}
, for both glb and lub.
On top of these complete dichotomies, we obtained some results of inexpressibility in
\mathsf{AGGR}[\mathsf{FOL}]
for aggregate operators that lack monotonicity or associativity (e.g.,
\mathtt{AVG}
).
We also refuted a longstanding claim made in
(
Fuxman, 2007
)
.

An open question remains as follows. Let
\mathcal{C}
denote the class of
\mathtt{AGG}
-queries
g()\vcentcolon=\mathtt{AGG}(r)\leftarrow q(\vec{y})
, without self-joins, that satisfy all of the following:
(i)
the attack graph of
\exists y(q(\vec{y}))
is acyclic,
(ii)

\mathtt{AGG}
lacks monotonicity, associativity, or both, and
(iii)

\mathtt{AGG}
is neither
\mathtt{MIN}
nor
\mathtt{MAX}
. That is,
\mathcal{C}
contains those numerical queries not covered by our results. It remains open to determine, for
each
query
g()
in
\mathcal{C}
, whether or not
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
is expressible in
\mathsf{AGGR}[\mathsf{FOL}]
.
We only showed inexpressibility for specific queries in
\mathcal{C}
(cf. Corollary
7.5
).

Another open question concerns shifting our focus from expressibility in
\mathsf{AGGR}[\mathsf{FOL}]
to computability in
\mathsf{P}
.
By changing the focus of Theorem
1.1
, we can formulate the following conjecture:

Conjecture 8.1.

Given a numerical query
g()
in
\mathsf{AGGR}[\mathsf{sjfBCQ}]
whose aggregate operator is both monotone and associative,
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
is either in
\mathsf{P}
or
\mathsf{coNP}
-hard, and it can be decided which of the two cases holds.

We now outline a possible route to proving Conjecture
8.1
.
In
(
Koutris and Wijsen, 2017
)
, each cycle in the attack graph of a query
q\in\mathsf{sjfBCQ}
is classified as either
weak
or
strong
, which is a decidable property.
It is then shown that the decision problem
{\mathsf{CERTAINTY}}(q)
is in
\mathsf{P}
if
q
’s attack graph contains no strong cycles, and
{\mathsf{CERTAINTY}}(q)
is
\mathsf{coNP}
-complete otherwise.
Let
g()\vcentcolon=\mathtt{AGG}(r)\leftarrow q(\vec{u})
be a numerical query in
\mathsf{AGGR}[\mathsf{sjfBCQ}]
.
Since a solution to
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
also solves
{\mathsf{CERTAINTY}}(\exists\vec{u}(q(\vec{u})))
, it follows that
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
is
\mathsf{coNP}
-hard if the attack graph of
\exists\vec{u}(q(\vec{u}))
contains a strong cycle.
To show Conjecture
8.1
, it suffices therefore to establish that if all cycles in the attack graph of
\exists\vec{u}(q(\vec{u}))
are weak, and
\mathcal{F}_{\mathtt{AGG}}
is both monotone and associative, then
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
is in
\mathsf{P}
. For attack graphs without cycles, the latter follows from Theorem
1.1
under the assumption that
\mathsf{AGGR}[\mathsf{FOL}]
is in
\mathsf{P}
(which requires that aggregate operators are computable in polynomial time).
So the remaining problem concerns handling weak cycles in attack graphs, which we anticipate might be solvable by employing the constructs developed in
(
Koutris and Wijsen, 2021
, Section 8)
or
(
Figueira et al., 2023
, Section 4)
. Specificallly, it should be investigated whether
\forall
embeddings can be generalized to address weak cycles, enabling
{\mathsf{GLB\mathchar 45\relax CQA}}(g())
to be solved along the lines presented in Section
6
of the current paper—i.e., by computing the smallest aggregated value over all
\subseteq
-maximal consistent sets of
\forall
embeddings.

Lemma A.3.

Let
q
be query in
\mathsf{sjfBCQ}
.
For some
w\in{\mathsf{vars}}(q)
, let
(F_{1},F_{2},\ldots,F_{n})
be a sequential proof of

If
G\stackrel{{\scriptstyle q}}{{\rightsquigarrow}}x
for some variable
x
in
Z\cup\left(\bigcup_{i=1}^{n}{\mathsf{vars}}(F_{i})\right)
,
then there is

such that
G\stackrel{{\scriptstyle q}}{{\rightsquigarrow}}z
.

Proof.

Assume that
G\stackrel{{\scriptstyle q}}{{\rightsquigarrow}}x
for some variable
x
in
Z\cup\left(\bigcup_{i=1}^{n}{\mathsf{vars}}(F_{i})\right)
.
The proof runs by induction on increasing
n
.
For the basis of the induction,
n=0
, we obtain
x\in Z
with
G\stackrel{{\scriptstyle q}}{{\rightsquigarrow}}x
, as desired.

For the induction step,
n-1\rightarrow n
, assume that the lemma holds for sequential proofs of length
<n
.
Notice that for every
m\in\{0,1,\ldots,n-1\}
, there is some
w^{\prime}
such that

is a sequential proof of
{\mathcal{K}}(q\setminus\{G\})\models{Z}\rightarrow{w^{\prime}}
.
Therefore, if

occurs in

, then the desired result holds by the induction hypothesis.
Assume from here on that
x\notin Z\cup\left(\bigcup_{i=1}^{n-1}{\mathsf{vars}}(F_{i})\right)
.
Then,
x\in{\mathsf{notKey}}(F_{n})
.
From
G\stackrel{{\scriptstyle q}}{{\rightsquigarrow}}x
, it follows that there is
x^{\prime}\in{\mathsf{Key}}(F_{n})
such that
G\stackrel{{\scriptstyle q}}{{\rightsquigarrow}}x^{\prime}
.
By the definition of sequential proof, it must be the case that
x^{\prime}\in Z\cup\left(\bigcup_{i=1}^{n-1}{\mathsf{vars}}(F_{i})\right)
.
Again, the desired result holds by the induction hypothesis.
∎

Proof of Lemma
4.3
.

We define a formula
\varphi_{q}(\vec{u})
such that for every database instance
\mathbf{db}
,

\mathbf{db}\models\varphi_{q}(\vec{c})
if and only if the valuation
\theta
over
{\mathsf{vars}}(\vec{u})
such that
\theta(\vec{u})=\vec{c}
is an
n
-
\forall
embedding in
\mathbf{db}
.

Let
p(\vec{x})
be a conjunctive query with free variables
\vec{x}
.
A
consistent first-order rewriting of
p(\vec{x})
is a first-order formula
\omega(\vec{x})
such that for every database instance
\mathbf{db}
, for every sequence
\vec{c}
of constants, of length
|\vec{x}|
, we have
\mathbf{db}\models_{\mathsf{cqa}}p(\vec{c})
if and only if
\mathbf{db}\models\omega(\vec{c})
.
The following problem has been solved in
(
Koutris and Wijsen, 2017
)
:
given a self-join-free conjunctive query
p(\vec{x})
, decide whether
p(\vec{x})
has a first-order rewriting, and if affirmative, construct such a a first-order rewriting.

Let
q
be a query in
\mathsf{sjfBCQ}
with an acyclic attack graph.
Assume that
q
’s body is
F_{1}\land F_{2}\land\dotsm\land F_{n}
, where the atoms are listed in a topological sort of the attack graph.
For
j\in\{0,1,2,\ldots,n\}
, we inductively define a formula
\psi_{j}(\vec{u}_{j})
expressing that
\vec{u}_{j}
is a
j
-
\forall
embedding.
The basis of the induction is
\psi_{0}()=\mathsf{true}
.
For the induction step,
j\rightarrow j+1
, the formula
\psi_{j+1}(\vec{u}_{j+1})
reads as follows:

\psi_{j+1}(\overbrace{\vec{u}_{j},\vec{x}_{j+1},\vec{y}_{j+1}}^{\vec{u}_{j+1}})\vcentcolon=\psi_{j}(\vec{u}_{j})\land\omega_{j+1}(\vec{u}_{j},\vec{x}_{j+1})\land F_{j+1},

where
\omega_{j+1}(\vec{u}_{j},\vec{x}_{j+1})
is a consistent first-order rewriting of

\ \exists\vec{y}_{j+1}\exists\vec{x}_{j+2}\exists\vec{y}_{j+2}\dotsm\exists\vec{x}_{n}\exists\vec{y}_{n}\left(F_{j+1}\land F_{j+2}\land\dotsm\land F_{n}\right).

It follows from
(
Koutris and Wijsen, 2017
)
that
\omega_{j+1}(\vec{u}_{j},\vec{x}_{j+1})
exists, and can be constructed in linear time in the length
|q|
of
q
.
Then, our desired formula
\varphi_{q}(\vec{u}_{n})
is equal to
\psi_{n}(\vec{u}_{n})
:

\varphi_{q}(\vec{u}_{n})\vcentcolon=\psi_{n}(\vec{u}_{n}).

It remains to show the quadratic upper bound on the construction of
\psi_{n}(\vec{u}_{n})
. If
T_{j+1}
denotes the time for constructing
\psi_{j+1}
, then
T_{0}=1
and for some constant
c
, we have
T_{j+1}\leq T_{j}+c\cdot|q|
.
It follows that
T_{n}\leq n\cdot c\cdot|q|
.
Since
n\leq|q|
,
T_{n}
is quadratic in the length of
q
.

∎

We illustrated the construction with an example.

Example C.1.

Let

.

\displaystyle\psi_{1}(x,y)

\displaystyle=\mathsf{true}\land\omega_{1}(x)\land R(\underline{x},y),

\displaystyle\psi_{2}(x,y,z)

\displaystyle=\psi_{1}(x,y)\land\omega_{2}(x,z)\land S(\underline{y,z},c),

where

\displaystyle\omega_{1}(x)

\displaystyle=\begin{array}[t]{ll}\exists yR(\underline{x},y)\land\\
\forall y\left(R(\underline{x},y)\rightarrow\exists z\left(S(\underline{y,z},c)\land\forall u\left(S(\underline{y,z},u)\rightarrow u=c\right)\right)\right),\end{array}

\displaystyle\omega_{2}(x,z)

\displaystyle=S(\underline{y,z},c)\land\forall u\left(S(\underline{y,z},u)\rightarrow u=c\right).

Putting all together, with some simplifications:

\psi_{2}(x,y,z)=\begin{array}[t]{ll}&R(\underline{x},y)\land S(\underline{y,z},c)\\
\land&\forall y\left(R(\underline{x},y)\rightarrow\exists z\left(S(\underline{y,z},c)\land\forall u\left(S(\underline{y,z},u)\rightarrow u=c\right)\right)\right)\\
\land&\forall u\left(S(\underline{y,z},u)\rightarrow u=c\right).\end{array}

\triangleleft

Proof of Theorem
