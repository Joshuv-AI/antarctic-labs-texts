Federated Learning in Open- and Closed-Loop EMG Decoding: A Privacy and Performance Perspective Thanks: This work was partially supported by an unrestricted gift from Meta Reality Labs.
Kai Malcolm, César A. Uribe, Momona Yamagami

Abstract
Invasive and non-invasive neural interfaces hold promise as high-bandwidth input devices for next-generation technologies. However, neural signals inherently encode sensitive information about an individual’s identity and health, making data sharing for decoder training a critical privacy challenge. Federated learning (FL), a distributed, privacy-preserving learning framework, presents a promising solution, but it remains unexplored in closed-loop adaptive neural interfaces. Here, we introduce FL-based neural decoding and systematically evaluate its performance and privacy using high-dimensional electromyography signals in both open- and closed-loop scenarios. In open-loop simulations, FL significantly outperformed local learning baselines, demonstrating its potential for high-performance, privacy-conscious neural decoding. In contrast, closed-loop user studies required adapting FL methods to accommodate single-user, real-time interactions, a scenario not supported by standard FL. This modification resulted in local learning decoders surpassing the adapted FL approach in closed-loop performance, yet local learning still carried higher privacy risks. Our findings highlight a critical performance-privacy tradeoff in real-time adaptive applications and indicate the need for FL methods specifically designed for co-adaptive, single-user applications.



Keywords:
Electromyography, federated learning, open- and closed-loop decoding, neural interfaces, privacy.

Federated Learning Background

2.1
What is Federated Learning?

Federated learning (FL) is a type of
distributed learning
, where users collaborate through a central coordinating server to optimize a shared global model while keeping their raw data local (i.e., on device).
In comparison to
centralized learning
, where all users upload their data to a central server to train a single model, or
local learning
, where each user trains their own model, FL strikes a balance between privacy and performance by enabling local training (keeping raw data private) with coordinated model updates (model weights are aggregated across many users)
[
54
]
.
Centralized and local learning can be considered opposite ends of this performance-privacy trade-off (Fig.
1
).
In centralized learning, data is not private since it must be uploaded to the server, where the user no longer has control or knowledge of how it is used (for example, if the server is breached or untrustworthy). The centralized model can often achieve high performance due to the scale of the dataset, but it is inherently a one-size-fits-all model and may be limited in neural interface applications where models can struggle to generalize across users.
On the other hand, in local learning raw data is not shared, but model performance may be limited because of the much smaller dataset.
Furthermore, every user is burdened with training their own model from scratch.
FL offers an option between these extremes, where users do not have to give up custody of their data but still benefit from data in the network of users, enabling more generalizable models.

In FL, each
user
(also called client, agent, or node) communicates with the server via
edge devices
of limited computational capacity
[
55
]
.
The server does not access user data, but instead aggregates the users’ model parameters into the
global model
that solves the server’s global cost function.
The global cost function represents an aggregated optimization objective that combines individual user cost functions, often incorporating weighting, regularization, or fairness constraints to improve generalization across distributed data sources.
In FL, in addition to the server’s global model, each user maintains their own set of model weights referred to as their
local model
.

2.2
A Basic FL Algorithm

The canonical FL formulation, introduced in the FedAvg algorithm by
[
56
]
, is a distributed setting in which
K
users collaborate to find a set of global model weights
w
that minimizes the global cost function.
In this work, we refer to such FL algorithms that aim to train a single shared global model for all users as
traditional federated learning (TFL)
.
For FedAvg, the global cost function
F(w)
is the sum of all user cost functions
f_{i}(w)
:

\min_{w\in\mathbb{R}^{d}}F(w)=\frac{1}{K}\sum^{K}_{i=1}f_{i}(w)

(1)

which optimizes for a model that performs well on average for all users
i
.
In each round, the server sends the current global model
w
to a random subset of users. Each selected user performs several steps of gradient descent using their local data:

w_{i}^{(t)}=w_{i}^{(t-1)}-\alpha\nabla f_{i}(w_{i}^{(t-1)};\xi_{i}^{t}),

(2)

where
\xi_{i}^{t}
is a mini-batch of user
i
’s data at time
t
,
\alpha
is the learning rate, and
\nabla
indicates the gradient of cost function
f_{i}
.
The server waits for all users to upload their updated local models before aggregating the uploaded models via a weighted averaging scheme.
Variants such as FedProx
[
57
]
and SCAFFOLD
[
58
]
add regularization terms to reduce client drift, ensuring that local models stay close to the global one. These extensions aim to improve convergence under non-IID conditions, which are common in biosignal data
[
59
,
60
,
61
,
62
,
63
,
64
]
.

In neural interface applications, it is often desirable to personalize decoders to individual users.
Personalization can be incorporated into FL by shifting the optimization focus from a single shared model to user-specific models, optimizing for each user’s individual performance while still allowing for some form of shared learning or initialization via the global model.
One popular approach is Per-FedAvg
[
65
]
, which draws from Model-Agnostic Meta-Learning (MAML). Rather than optimizing the global model
w
directly (as in Equation
1
), Per-FedAvg optimizes for a model that performs well after one or a few gradient updates on each user’s data:

\min_{w\in\mathbb{R}^{d}}F(w)=\frac{1}{K}\sum^{K}_{i=1}f_{i}(w-\alpha\nabla f_{i}(w)),

(3)

Thus, MAML optimizes for a global model that is a good starting point for its users, such that users can quickly personalize, regardless of whether the global starting point model achieves strong performance.
This allows users to quickly personalize the shared model without needing to train from scratch, balancing the benefits of shared learning with user-specific adaptation.

3
FL for Privacy-Preserving Neural Interfaces

Applying federated learning (FL) to neural interfaces presents unique challenges, particularly due to the breadth of available FL algorithms and the complex demands of real-time neural systems.
In this section, we introduce a conceptual framework to help researchers reason about FL in open- and closed-loop neural decoding and other biosignal-based scenarios.
Whereas existing frameworks (such as Flower
[
25
]
) look to provide the code for simulating FL algorithms, our framework focuses on how researchers should choose an FL algorithm for their application.
Rather than recommending specific algorithms, our goal is to highlight two key attributes that influence the applicability and performance of FL, especially as they relate to neural interface studies: (1) personalized cost and (2) user availability.
Understanding these attributes can help practitioners identify potential pitfalls and necessary algorithmic adjustments when implementing FL in privacy-sensitive neural interface applications (see Table
1
).

3.1
Attribute 1: Personalized Cost

FL algorithms can broadly be categorized as either traditional (i.e., TFL) or personalized (i.e., PFL). TFL optimizes for a global model that works well on average for all users, whereas PFL optimizes for user-specific models tailored to each user’s data distribution
[
66
]
.
Data heterogeneity refers to variations in user data distributions and is a critical factor in determining which class of algorithm is appropriate.
When user data is relatively homogeneous, TFL can perform well by leveraging a shared global model trained on updates pooled across similar data distributions.
However, with high heterogeneity, TFL often suffers from slow or unstable convergence and degraded performance
[
67
]
.
PFL mitigates this by enabling local adaptation, though it often introduces more hyperparameters and higher training complexity
[
68
]
.
In practice, heterogeneity is rarely explicitly measured, so researchers often rely on domain knowledge to judge dataset heterogeneity and whether personalization is necessary.

3.1.1
Traditional Federated Learning (TFL)

TFL algorithms such as FedAvg
[
56
]
focus on training a single shared global model that performs well, on average, for all users.
When all users sample from the same distribution, the global model benefits from a larger multi-user dataset, leading to improved performance.
In contrast, local learning (i.e., training a local model for each user) is often limited to a smaller single-user dataset and less generalizable models.
Furthermore, each new user must train their local model from scratch.
In the presence of substantial data heterogeneity, the performance of TFL methods often degrades.
FedAvg, in particular, may converge slowly, diverge, or yield suboptimal results
[
67
]
.
While some TFL variants attempt to accommodate heterogeneity
[
69
,
70
]
, the FL research community has increasingly shifted toward PFL approaches.

3.1.2
Personalized Federated Learning (PFL)

PFL algorithms can be grouped into two categories: those addressing device heterogeneity (e.g., network reliability, hardware capabilities) and those focused on data heterogeneity. In this work, we concentrate on the latter.
PFL optimizes a set of user-specific models, often using the global model as a prior or initialization point to improve generalization and stability. These approaches tend to be more flexible and robust to distributional variation but are often more complex to tune and slower to converge
[
68
]
.
If dataset heterogeneity is unknown, personalized models may offer a more robust solution, trading better convergence speeds (i.e., if the dataset is homogeneous) for better performance (i.e., if the dataset is heterogeneous).
A growing number of PFL algorithms exist to address diverse personalization scenarios, including Per-FedAvg
[
65
]
, pFedMe
[
71
]
, APFL
[
67
]
, FedALA
[
72
]
, Fedcp
[
73
]
, FedDBE
[
74
]
, and GPFL
[
75
]
, with most work being done in the context of standardized image datasets such as CIFAR-100
[
76
]
.

3.2
Attribute 2: User Availability

User availability refers to how frequently and reliably user information can be integrated back into the network.
This includes real-world issues like users dropping out of the network, differences in computational resources, and differences in network connections (e.g., delays). Our framework considers three modes of user availability: synchronous, asynchronous, and sequential.

3.2.1
Synchronous

Synchronous FL assumes that all selected users are available and active at the same time. This is the default setup for most FL algorithms
[
56
,
72
,
74
,
77
,
57
,
71
,
65
]
.
While simple and easy to simulate, synchronous FL has limited applicability in real-world settings, especially in closed-loop neural interface experiments with subjects, where running multiple users simultaneously is often infeasible due to hardware availability.
Looking towards deployment, synchronous FL also struggles with straggling users that require substantially more time to complete each training round: slow users can delay global model updates, and users unexpectedly dropping out of the network can halt training indefinitely
[
82
]
.
That said, synchronous algorithms are often sufficient for open-loop simulations, where real-time constraints and hardware limitations do not apply.

3.2.2
Asynchronous

Asynchronous FL relaxes the requirement for simultaneous user availability.
Typically, users can upload their updates and download the latest global model at their own pace, thus reducing sensitivity to stragglers and dropouts
[
68
]
.
However, this flexibility introduces two new challenges. First, updates from slower users may be based on outdated global models, resulting in “stale” updates with respect to the current global model. Second, faster users can dominate the training process, introducing bias (i.e., over-representation) into the global model.
Newer algorithms attempt to address these issues with fairness and weighting mechanisms
[
27
,
30
]
.
Asynchronous methods offer a more practical and robust alternative to synchronous FL, particularly for real-world deployment. However, they still assume that at least a small group of users is active concurrently and typically rely on multiple users intermittently querying and updating the global model. This ongoing stream of diverse updates serves as an implicit form of regularization, helping prevent overfitting to any single user.

3.2.3
Sequential

We introduce a novel learning scenario we term
sequential federated learning
, defined by two constraints: (1) only one user is active at a time, and (2) each user appears exactly once, completing all of their local training during their limited availability.
This regime is highly relevant for closed-loop decoding experiments, such as EMG or BCI studies
[
83
,
84
,
85
,
86
,
87
]
, where participants contribute data in isolation, and repeated access to the same user is infeasible outside of larger-scale longitudinal studies.
Despite its practical importance, no existing FL algorithms are designed for this scenario.

Sequential FL breaks a core assumption of FL that updates from multiple users can be aggregated via averaging each training round.
In sequential FL, since only one client is active per round, averaging-based model aggregation becomes model replacement: the global model is simply overwritten with the active user’s uploaded model.
This prevents the stabilizing effect of averaging over users and may make optimization highly sensitive to the order in which users appear.
Moreover, if a user’s model drifts far from the current global model (e.g., due to strong local training), this can exacerbate client drift and hinder convergence. When users are seen only once, mitigating overfitting to individual users becomes critical.

While no prior work addresses this exact setting, a few related paradigms exist.
For instance,
cyclical FL

[
88
,
89
]
also assumes one user trains at a time but relaxes the single-pass constraint by returning to users in subsequent cycles.
This approach is often applied in with a small number of persistent institutions, where institutions will pass the model weights around in a continuous cycle, thus violating constraint (2) of our sequential FL definition.
Finally, we note that “sequential FL” has appeared in prior literature
[
90
,
91
,
92
]
, but with different meanings.
Depending on the paper, it can refer to 1) the stepwise application of algorithmic components
[
90
]
, 2) the sequential nature of the data (i.e., time series and adjacent data types), or 3) how clients are processed (i.e., sequential versus parallel) within synchronous FL training rounds
[
91
,
92
]
.
Our definition of sequential FL refers instead to a unique client availability regime, motivated by the realities of neural interface studies and other closed-loop neural experiments.
In summary, our formulation of sequential FL introduces unique challenges not addressed by prior work, motivating the development of new methods for real-world closed-loop neural applications.

Methods

The goal of our empirical evaluation is to analyze how decoder performance and privacy risk vary not only across learning strategies (i.e., traditional local approaches versus FL) but also across two key settings for high-dimensional neural interface control: open-loop and closed-loop. By running matched experiments under both conditions, we assess how learning paradigms generalize and adapt in offline (open-loop) versus real-time (closed-loop) decoding scenarios.
Most FL algorithms are exclusively applied in open-loop settings
[
26
,
28
,
38
,
37
,
31

, but decoders trained in this manner do not work well for individuals with motor brain-computer interface inefficiency
[

,

95
]
;
for such individuals, closed-loop decoding (e.g., closed-loop decoder adaptation; CLDA
[
40
]
) could enhance and optimize decoder adaptation for these individuals.
Thus, we expect closed-loop convergence to be influenced by this human-interface co-adaptation process
[
41
]
.

4.1
Task and Adaptive Decoder Description

The open-loop study is a secondary data analysis of the data collected in
[
96
]
, and the closed-loop study experiment adapts the same task of
[
96
]
to facilitate direct comparison.
Briefly, subjects were asked to control a cursor
y
in the horizontal and vertical directions on the screen to track a reference
r
using an EMG interface placed on their forearm (Fig.
3
).
The reference trajectory was the sum of two sinusoids with frequencies 0.10 and 0.25 Hz in the horizontal direction and 0.15 and 0.35 Hz in the vertical direction, both of which started each trial with a random phase to prevent trajectory memorization.

4.1.1
EMG Data Collection and Filtering

EMG data was collected using the Quattrocento system (Bioelettronica, Italy), measuring subjects’ dominant hand’s forearm muscle activity using a 64-channel electrode array (5x13 electrode layout). All subjects were right-handed.
EMG data was collected at 2048 Hz and filtered via built-in analog high- and low-pass filters at 10 Hz and 130 Hz, respectively.
We then computed the EMG linear envelope following
[
97
]
, and applied a rolling average with a window size of 250 ms and 93% overlap to downsample the EMG data from 2048 Hz to 60 Hz.

4.1.2
EMG-to-Cursor Decoder and Adaptation

Detailed methods and decoder parameter analysis can be found in
[
96
]
.
Briefly, linear regression was used to convert the streamed EMG data
(
s\in\mathbb{R}^{64\times 1}
) into the x and y cursor velocity (
v=ws
, where
w\in\mathbb{R}^{2\times 64}
are the decoder parameters and
v\in\mathbb{R}^{2\times 1}
).
The cursor velocity
v
was numerically integrated to obtain the horizontal and vertical cursor positions.
The decoder parameters
w
were updated in roughly 20-second batches by minimizing the sum of the error between the velocity error and the decoder parameters’ magnitudes. The velocity error is defined as the difference between the decoder’s predicted velocity and the optimal gap-closing velocity between the reference
r
and the user’s cursor
y
velocities:

\min\limits_{w}f(w)=\lambda_{e}||ws-\frac{\partial}{\partial t}(r-y)||_{2}^{2}+\lambda_{w}||w||_{2}^{2},

(4)

where
\lambda_{w}
is the penalty parameter associated with the L2 norm on the decoder parameters
w
.
All decoder updates implemented SmoothBatch
[
40
]
, where the optimal decoder parameters are linearly combined with the old decoder parameters
w_{new}=(1-\alpha)w_{old}+\alpha w_{optimal}
, with learning rate
\alpha
.
In line with prior work
[
96
]
, our pilot closed-loop studies found that penalty parameters of
\lambda_{w}=10^{-4}
and
\lambda_{e}=10^{-6}
performed best.
Thus, both the open- and closed-loop studies used these penalty parameters.
The dataset collected by
[
96
]
was a closed-loop experiment, but was not federated: rather, each subject trained their own subject-specific local decoder (i.e., local learning) using what we denote as the
Local
algorithm.
Each subject started with random initial decoder parameters and adapted simultaneously with the decoder during each 5-minute trial.
The best-performing hyperparameters (i.e., slow SmoothBatch learning rate
\alpha=0.75
) from
[
96
]
were used in our open- and closed-loop studies.

For the second attribute,

4.2.2
Closed-Loop Study

For the first attribute,
personalized cost
, we assume the dataset is heterogeneous and therefore best suited to a PFL algorithm.

For the second attribute,
user availability
, when running closed-loop studies in the lab environment, we are constrained by the fact that we only have one data acquisition device and thus only one participant can participate in the experiment at a time.
This necessitates a sequential FL setup, where users train one at a time and do not return for subsequent rounds.
Since we are not subject to real-world deployment challenges such as stragglers or intermittent connectivity, we do not require the robustness offered by asynchronous FL methods.
Thus, we choose to adapt an existing synchronous FL algorithm to operate in the sequential setting.
This allows us to preserve algorithmic simplicity while accommodating the constraints of our closed-loop, real-time experimental design.
We point out that applying our modification required in the sequential scenario to FedAvg removes the model averaging step, effectively reducing it to a local learning approach where each sequential user simply solves their own local objective function.

Taking the results of both attributes into consideration, the algorithms of row 2 in Table

4.3.1
Local

We implemented the same
Local

[

We ran SmoothBatch

This algorithm is subject-specific and local to that subject’s (simulated) device, using only the data from the subject’s most recently streamed update.
In both the open- and closed-loop studies, Local fully minimized each streamed update, with each update being comprised of 20 seconds of data.

4.3.2
Per-FedAvg and Sequential Modification

Per-FedAvg
optimizes the MAML cost function (eq.
3
). For both the open- and closed-loop implementations, we followed the first-order version of Per-FedAvg as described in
[
65
]
, where the Hessian is approximated via a first-order term.

In the open-loop study, Per-FedAvg was run for 500 global rounds, selecting 35% of clients per round and performing 25 gradient steps per client each round.
Each client advanced to their next streamed update after completing 25 local training rounds, meaning clients progressed at different rates due to the random sampling of clients each round.
Once a client advanced to the final streamed update, they used that final update for the rest of the simulation.

In the closed-loop study, we ran 40 training rounds on each streamed update, with 20 seconds of data per update. We divided each update into 6 batches to achieve real-time speed.
We additionally made modifications to the original Per-FedAvg algorithm
[
65
]
to accommodate the sequential nature of the human-subject study.
When only one subject is active, taking the average of just one set of uploaded decoder weights simply returns that set of decoder weights.
Thus, we replaced the server’s model-averaging scheme with a weighted average between the uploaded subject’s local decoder and the server’s global decoder.
With our linear models, this modification equates to applying SmoothBatch
[
40
]
between global and local decoders after each update.
This applies a similar form of regularization, keeping the local decoder close to the global decoder.

FedAvg

The FedAvg algorithm is the baseline algorithm for FL, coming from the paper that first introduced FL
[
56
]
.
FedAvg is only implemented for the open-loop study, and it shared all of Per-FedAvg’s described hyperparameters.
The only difference is the cost function that FedAvg optimizes (eq.

).

4.4
Outcome Measures

Our primary outcomes for both the open- and closed-loop studies were 1)
Velocity Error
and 2)
Empirical Privacy Risk
.
These outcomes help compare each trained decoder’s performance and privacy risk across the tested FL algorithms.

4.4.1
Velocity Error

We quantified decoder performance using velocity error, the first term of the cost function:

\lambda_{e}||ws-\frac{\partial}{\partial t}(r-y)||_{2}^{2}

(5)

The last full decoder update was used to compute performance for each user.

4.4.2
Empirical Privacy Risk

Inspired by recent works taking advantage of gradient leakage
[
102
,
103
]
, we quantified empirical privacy risk as the ability of an adversary (specifically, a support vector classifier (SVC)) to infer subject identity from trained decoder weights.
We note that our FL implementation communicates decoder weights instead of gradients, and furthermore that our Local implementation does not give us direct access to its gradients, hence our decision to implement our own decoder weight attack instead of a traditional gradient leakage attack.
High identification accuracy suggests that these weights encode subject-specific information, potentially increasing vulnerability to other privacy attacks such as membership inference
[
104
]
or model inversion
[
105
]
(i.e., more advanced attacks typically conducted on deep learning models).

To evaluate this privacy risk, we extracted a representative set of decoder snapshots from each user and condition.
Specifically, we selected the final six decoder updates per user (i.e., corresponding to the final six streamed updates, by which point the model should have been sufficiently trained and retained subject-specific information), ensuring consistency across different conditions. We flattened these decoder snapshots into vectors and assembled them into comprehensive datasets covering all subjects.
We then performed leave-one-out cross-validation (LOOCV) to quantify the adversary’s ability to correctly identify subjects from their decoder weights.
For each sample, we trained an SVC classifier using all other samples as the training set and assessed whether the held-out sample’s subject identity was correctly predicted. By aggregating these predictions over all iterations, we obtained a per-subject accuracy measure, reflecting each subject’s empirical privacy risk.

4.5
Open-Loop Evaluation and Analysis

4.5.1
Dataset

The open-loop evaluation presented here used only the data from the best-performing condition from
[
41
]
: a slow (SmoothBatch) learning rate (
\alpha=0.75
), a low decoder parameter penalty (
10^{-4}
), and a positive decoder parameter initialization.
In total, we used five minutes’ worth of data (one full trial) for each of the 14 subjects.
Because we did not simulate the subjects’ changing EMG responses to adaptive (i.e., updating) decoders, we excluded the initial two updates (of 18 total) to allow initial learning and adaptation effects to stabilize. Thus, our analysis used data from update three onward (approximately 4 minutes of the 5-minute trial duration), resulting in roughly 17,000 time points per subject.

4.5.2
Data Streaming and Train/Test Split

In the data collecting experiment, each subject’s data was streamed in 18 consecutive updates containing 20 seconds of data.
To replicate this streaming effect in our open-loop study, we segmented the dataset so that the decoder trains on one update at a time. After training for a predefined number of rounds, the simulated subject advances to the next update in the sequence.

Closed-Loop Evaluation and Analysis

4.6.1
Real-Time Implementation

In our closed-loop study, we used batches of 20 seconds, as pilot studies found that this increased FL’s stability. Thus, over the roughly five-minute trial, we had 15 updates.
The reference tracking task, real-time EMG streaming, and decoder parameter adaptation were implemented in

4.6.2
Subject Demographics

16 people (8 women, 8 men) participated in the study.
Subjects were all right-handed (61% all dominant, 39% somewhat ambidextrous in handedness), with an average weight and standard deviation of 151.1 ± 36.8 lbs, a height of 65.9 ± 3.6 in, a forearm circumference of 10.1 ± 1.1 in, and an age of 23 ± 2 years. All subjects were daily computer users.

4.6.3
Evaluation Design

The closed-loop evaluation was performed with the following factors and levels:

•

Algorithm
(within-subject): Local, Per-FedAvg, Static;

•

We evaluated two

6
Discussion

6.1
Open-Loop Results are Consistent with Prior Work

Our work found that FL approaches offered strong performance compared to traditional local learning approaches in open-loop settings, in line with previous applications of FL to off-line neural interfaces
[
109
,
110
,
111
,
112
]
.
For example, Liu et al.
[
110
]
show that their FL BCI (EEG) application increased performance up to 8.4% by learning over multiple datasets, when compared to non-federated baseline models.
Similarly, in the context of emotion recognition from EEG data, Xu et al.
[
109
]
found that when using local approaches, model accuracy decreased 29.31% compared to FL.
Finally, Zafar et al.
[
111
]
showed success with FedAvg for EMG gesture recognition, finding that FedAvg outperformed FedSGD, FedProx, and non-federated deep learning baseline models.
This finding highlights FL’s ability to aggregate data across multiple users, thus improving generalization.
As noted by Nesterov
[
113
]
, stochastic gradient estimates derived from larger sample sizes have reduced variance, thereby providing more reliable approximations of the true gradient.
In the context of FL versus local learning, aggregating updates from multiple users similarly yields a lower-variance estimate of the underlying global gradient, helping the model better approximate the global data distribution and enhancing generalization.
We hypothesize this reduction in variance is why the FL decoders converge smoothly, whereas Local, which fully optimizes for the given streamed update, failed to converge to a single point (Fig.
7
, bottom left), resulting instead in high variability across individual trajectories.

While many papers assume that FL alone is sufficient to fully protect privacy, recent works have shown that neither FL nor fully decentralized learning is immune to adversarial attacks, in particular to gradient leakage or inversion attacks
[
114
]
.
However, direct empirical comparisons between FL and non-FL methods in terms of performance and privacy remain scarce.
Existing studies either compare centralized (i.e., server-based) FL against decentralized FL
[
115
]
, or evaluate the relative privacy of specific FL implementations against their predecessors
[
103
]
.
Our analysis helps fill this gap by explicitly comparing FL to local learning in both open- and closed-loop settings.
Across both settings, we found that Local decoders exhibited high variance in their final decoder weights, making the decoders more unique and more vulnerable to linkage attacks.
In contrast, FL models stayed tightly clustered to their respective global models, reducing uniqueness and effectively curbing the linkage attacks.

In our open-loop simulations, we compared TFL (FedAvg), PFL (Per-FedAvg), and local learning (Local), obtaining results consistent with our proposed framework.
The similar performance between FedAvg and Per-FedAvg underscores the challenge of selecting an optimal FL algorithm, which is often an empirical decision.
Although Per-FedAvg outperformed FedAvg in both scenarios, as predicted by our framework, the performance advantage was modest.
Both FL approaches significantly outperformed local learning (Local), which we attribute to FL’s model aggregation mechanism, which leverages larger multi-user training datasets and thus better approximates the global user distribution.
In particular, we note that Local struggled in the Cross-subject scenario (i.e., decoder is trained on one user and tested on another), which is well-established as a difficult task
[
116
]
, but both FL algorithms experienced only minor degradations in performance when translating to the Cross-subject scenario.
Finally, we highlight how local learning only maximizes user privacy when there is no data sharing: even simple remote training (e.g., cloud-based or app-based) introduces vulnerabilities for adversaries to intercept trained model weights and compromise user privacy.

6.2
Federated Learning: Open-Loop Benefits, Closed-Loop Challenges

Our results demonstrate that FL provides substantial benefits in neural decoding, significantly outperforming local learning (Local) in open-loop simulations.
However, these advantages did not extend directly to the closed-loop setting, where the Local algorithm outperformed a modified version of personalized FL (Per-FedAvg).
Nevertheless, Per-FedAvg still effectively mitigated privacy risks from adversarial attacks, highlighting FL’s potential for privacy preservation even under modified conditions.

We attribute this performance discrepancy to differences in how FL was applied across settings.
Standard FL relies on averaging updates across multiple users simultaneously, but in our sequential, single-user closed-loop experiments, this was not feasible. Thus, we adapted Per-FedAvg by averaging model weights across time (i.e., averaging between the initial and updated weights) rather than across users.
Although necessary for real-time feasibility, this modification substantially reduces the implicit regularization provided by traditional FL’s inter-user aggregation, and results in an algorithm that more closely resembles Local than FL.

An additional factor limiting the closed-loop Per-FedAvg performance may be hyperparameters that failed to generalize from the pilot studies and lead to unstable learning dynamics. In closed-loop, our Per-FedAvg decoders did not significantly change over the course of the experiment (Fig
7
, top right), contrasting sharply with the smooth convergence seen in open-loop simulations (Fig
7
, top left).
Real-time, closed-loop scenarios impose strict constraints on hyperparameter selection.
We found that four hyperparameters were critical for convergence and real-time feasibility: the number of gradient steps per update, the size of each streamed update, the penalty parameters, and the learning rate. When these were not carefully tuned, the decoder often failed to converge and produced erratic behavior, resulting in uncontrollable cursors that frustrated users and destabilized the delicate co-adaptive interaction.
For example, in this work, open-loop training tolerated a larger range of values for the aforementioned hyperparameters, but these values failed to converge in the closed-loop experiments and had to be re-tuned.
In other works, decoders adapted for much longer periods of time (e.g., over 30 minutes in Orsborn et al.
[
59
]
, six times longer than our study) and still did not see substantial improvements in performance until subsequent practice with a fixed decoder.
This emphasizes the challenge of designing and training decoders in closed-loop with subjects
[
117
]
.

This underscores the challenge in finding methods for better translating hyperparameters optimized in open-loop to closed-loop. Closed-loop hyperparameter tuning is inherently time-consuming and costly due to subject variability and experimental constraints.
As neural decoder complexity grows, adaptive hyperparameter strategies that dynamically respond to real-time user interactions will become increasingly critical.

6.3
Limitations and Future Directions

Our framework provides valuable guidance in choosing appropriate FL algorithms based on data heterogeneity and user availability. However, the framework is inherently limited in prescriptiveness; it identifies suitable algorithmic classes without specifying implementation details or hyperparameter settings.
This is because there is no single best FL algorithm that dominates all tasks across all domains.
Outside of task-specific benchmarks (such as CIFAR-100
[
76
]
for image classification), there are no standards showing researchers how a given FL algorithm will extend to their specific domain and task, particularly for neural applications.
Invariably, researchers must complement this framework with domain-specific tuning.
Furthermore, this framework is not a guide for implementation: other frameworks, such as Flower
[
25
]
, provide the infrastructure and code for setting up a distributed learning scenario once an appropriate FL algorithm is chosen with our framework.
Future research should explore specialized FL algorithms explicitly designed for sequential, real-time training scenarios. Longitudinal studies could further elucidate the dynamics of repeated user interaction, client drift mitigation, and improved personalization without privacy compromise. Additionally, adaptive hyperparameter tuning mechanisms tailored for closed-loop, co-adaptive environments warrant investigation.

7
Conclusion

This study provides empirical insights into applying federated learning to offline open-loop and real-time closed-loop neural decoding. By illuminating key practical challenges, including the complexity of balancing privacy and personalization, we lay critical groundwork for future methodological innovations and adaptive algorithm development in privacy-sensitive, interactive neural interfaces.
