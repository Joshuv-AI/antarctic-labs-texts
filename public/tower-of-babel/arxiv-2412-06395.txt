Query Complexity with Unknowns
Nikhil S. Mande, Karteek Sreenivasaiah

Abstract
We initiate the study of a new model of query complexity of Boolean functions where, in addition to 0 0 and 1 1 , the oracle can answer queries with “unknown”. The query algorithm is expected to output the function value if it can be conclusively determined by the partial information gathered, and it must output “unknown” if not. We formalize this model by using Kleene’s strong logic of indeterminacy on three variables to capture unknowns. We call this model the ‘ 𝗎 \mathsf{u} -query model’. We relate the query complexity of functions in the new 𝗎 \mathsf{u} -query model with their analogs in the standard query model. We show an explicit function that is exponentially harder in the 𝗎 \mathsf{u} -query model than in the usual query model. We give sufficient conditions for a function to have 𝗎 \mathsf{u} -query complexity asymptotically the same as its query complexity. Using 𝗎 \mathsf{u} -query analogs of the combinatorial measures of sensitivity, block sensitivity, and certificate complexity, we show that deterministic, randomized, and quantum 𝗎 \mathsf{u} -query complexities of all total Boolean functions are polynomially related to each other, just as in the usual query models.

The logic K3 is typically used in models where there is a need to represent, and work with,
unknowns
and hence has found several important wide-ranging applications in computer science. For instance, in relational database theory, SQL implements K3 and uses
\mathsf{u}
to represent a NULL value
[
Mey98
]
. Perhaps the oldest use of K3 is in modeling
hazards
that occur in real-world combinational circuits. Recently there have been a series of results studying constructions and complexity of hazard-free circuits
[
IKL+19
,
Juk21
,
IKS23
]
. Here
\mathsf{u}
was used to represent an
unstable
voltage that can resolve to
0
or
1
at a later time.

One way to interpret the basic binary operations
\vee
,
\wedge
, and
\neg
in K3 is as follows: for a bit
b\in\{0,1\}
, if the value of the function is guaranteed to be
b
regardless of all
\{0,1\}
-settings to the
\mathsf{u}
-variables, then the output is
b
. Otherwise, the output is
\mathsf{u}
. This interpretation generalizes in a nice way to
n
-variate Boolean functions: given
f:\{0,1\}^{n}\to\{0,1\}
, an input to
f
in K3 would be a string in
\{0,1,\mathsf{u}\}^{n}
, and the output is
b\in\{0,1\}
if and only if
f
evaluates to
b
for all settings of the
\mathsf{u}
-variables in
\{0,1\}
. Otherwise, the output is
\mathsf{u}
. We denote this extension
f_{\mathsf{u}}
and formally define it below. In literature, this extension is typically called the
hazard-free
extension of
f
(see, for instance,
[
IKS23
, Equation 1]
), and is an important concept studied in circuits and switching network theory since the 1950s. The interested reader can refer to
[
IKL+19
]
, and the references therein, for history and applications of this particular way of extending
f
to K3.

Formally, for an input
x\in\{0,1,\mathsf{u}\}^{n}
, define the
resolutions
of
x
as follows:

\mathsf{Res}(x):=\left\{y\in\{0,1\}^{n}:y_{i}=x_{i}~\forall i\in[n]~\textnormal{with}~x_{i}\in\{0,1\}\right\}.

That is,
\mathsf{Res}(x)
denotes the set of all strings in
\{0,1\}^{n}
that are consistent with the
\{0,1\}
-valued bits of
x
.
For a Boolean function
f:\{0,1\}^{n}\to\{0,1\}
, define its extension to K3, denoted
f_{\mathsf{u}}:\{0,1,\mathsf{u}\}^{n}\to\{0,1,\mathsf{u}\}
, by

f_{\mathsf{u}}(y)=\begin{cases}b\in\{0,1\}&f(x)=b~\forall x\in\mathsf{Res}(y)\\
\mathsf{u}&\textnormal{otherwise}.\end{cases}

We initiate a study of the
query complexity
of these extensions of Boolean functions. Here, in addition to
0
and
1
, the oracle can answer a query with “unknown”, which is denoted
\mathsf{u}
. This can model scenarios where the oracle itself holds incomplete information, or would like to withhold some information from the querying agent.

The deterministic
\mathsf{u}
-query complexity of
f
, denoted
\mathsf{D}_{\mathsf{u}}(f)
, is defined as maximum over all inputs of length
n
, the number of queries by a best query algorithm for
f_{\mathsf{u}}
.

While the query complexity of
n
-variate Boolean functions that depend on all input variables is well known to be between
\log n
and
n
, the analogous bounds are no longer clear in the
\mathsf{u}
-query setting. In particular, the Indexing function which admits a simple
O(\log n)
query algorithm, can be seen to have linear
\mathsf{u}
-query complexity. In light of this exponential gap, it is natural to ask — do all functions require
n^{\Omega(1)}

\mathsf{u}
-query complexity? We show that this is not true, and exhibit an explicit example of a non-degenerate Boolean function that has
\mathsf{u}
-query complexity
O(\log n)
.

Towards the more general goal of understanding what properties of Boolean functions play a role in determining their
\mathsf{u}
-query complexity, we give sufficient conditions under which
\mathsf{u}
-query complexity is asymptotically the same as standard query complexity. Further, analogous to existing measures, we redefine notions of sensitivity, block sensitivity, and certificate complexity for functions over the logic K3. We show that
\mathsf{D}_{\mathsf{u}}(f)
is related to these measures in a similar fashion as is known in query complexity.

1.1
Our Results

We relate deterministic
\mathsf{u}
-query complexity of Boolean functions to their query complexity in Section
3
. It is well known that the Indexing function on
n+2^{n}
input variables (see Definition
2.3
) has
O(n)
query complexity. In contrast, we show that its
\mathsf{u}
-query complexity is polynomially large in the number of variables.

Lemma 1.1
.

Let
n
be a positive integer. Then,

\mathsf{D}_{\mathsf{u}}(\mathsf{IND}_{n})=\Theta(2^{n}),\qquad\mathsf{R}_{\mathsf{u}}(\mathsf{IND}_{n})=\Theta(2^{n}),\qquad\mathsf{Q}_{\mathsf{u}}(\mathsf{IND}_{n})=\Theta(2^{n/2}).

We prove this lemma by showing a reduction from the OR function on
2^{n}
variables, which is well known to have
\Theta(2^{n})
deterministic and randomized query complexities, and
\Theta(2^{n/2})
quantum query complexity.
Given that the Indexing function is considered to be one of the textbook “easy” functions for query complexity, this raises the question of whether the
\mathsf{u}
-query complexity of all Boolean functions is polynomially large. We show that this is not true, witnessed by a monotone variant of the Indexing function (see Definition
2.4
). We show that this function admits a
\mathsf{u}
-query protocol of logarithmic cost in its input size (see Lemma
3.3
). More generally, we show that for monotone functions, their query complexity and
\mathsf{u}
-query complexity are asymptotically the same.

Lemma 1.2
.

Let
f:\{0,1\}^{n}\to\{0,1\}
be a monotone Boolean function. Then we have

\mathsf{D}_{\mathsf{u}}(f)=\Theta(\mathsf{D}(f)),\qquad\mathsf{R}_{\mathsf{u}}(f)=\Theta(\mathsf{R}(f)),\qquad\mathsf{Q}_{\mathsf{u}}(f)=\Theta(\mathsf{Q}(f)).

In Section
4
, we show that the deterministic, randomized, and quantum
\mathsf{u}
-query complexities of a function are all polynomially related to each other.

Theorem 1.3
.

For
f:\{0,1\}^{n}\to\{0,1\}
, we have

\mathsf{D}_{\mathsf{u}}(f)=O(\mathsf{R}_{\mathsf{u}}(f)^{3}),\qquad\mathsf{D}_{\mathsf{u}}(f)=O(\mathsf{Q}_{\mathsf{u}}(f)^{6}).

An analogous statement has been long known to hold true in the usual query models
[
Nis91
,
NS94
,
BBC+01
]
. All of these proofs proceed by showing polynomial relationships of these query measures with the intermediate combinatorial measure of
block sensitivity
. While we are able to adapt these known proofs to yield a proof of Theorem
1.3
, we do have to redefine the relevant combinatorial measures appropriately and suitably modify certain steps to ensure that the analogous results in the
\mathsf{u}
-query model still hold.

2.1
The
\mathsf{u}
-query model

Recall from Section
1
that for a string
x\in\{0,1,\mathsf{u}\}^{n}
,

\mathsf{Res}(x):=\left\{y\in\{0,1\}^{n}:y_{i}=x_{i}~\forall i\in[n]~\textnormal{with}~x_{i}\in\{0,1\}\right\}.

\mathsf{Res}(x)
denotes the set of all strings in
\{0,1\}^{n}
that are consistent with the
\{0,1\}
-valued bits of
x
.
Also recall that for a Boolean function
f:\{0,1\}^{n}\to\{0,1\}
, its K3 extension, denoted
f_{\mathsf{u}}:\{0,1,\mathsf{u}\}^{n}\to\{0,1,\mathsf{u}\}
, is defined by

f_{\mathsf{u}}(y)=\begin{cases}b\in\{0,1\}&f(x)=b~\forall x\in\mathsf{Res}(y)\\
\mathsf{u}&\textnormal{otherwise}.\end{cases}

That is,
f_{\mathsf{u}}(y)=b\in\{0,1\}
if
f_{\mathsf{u}}
evaluates to the constant
b
in the subcube of
\{0,1\}^{n}
defined by all inputs consistent with the
\{0,1\}
-valued bits of
y
, and
f_{\mathsf{u}}(y)=\mathsf{u}
otherwise.

For the discussion below, fix a positive integer
n
and a Boolean function
f:\{0,1\}^{n}\to\{0,1\}
.

A
deterministic decision tree
, also called a
deterministic query algorithm
, computing
f_{\mathsf{u}}
, is a ternary tree
T
whose leaf nodes are labeled by elements of
\{0,1,\mathsf{u}\}
, each internal node is labeled by an index
i\in[n]
and has three outgoing edges, labeled
0,1
, and
u
.
On an input
x\in\{0,1,\mathsf{u}\}^{n}
, the tree’s computation proceeds from the root down to a leaf as follows: compute
x_{i}
as indicated by the node’s label and follow the edge indicated by the value of
x_{i}
. Continue this way until reaching a leaf, at which point the value of the leaf is output.
The correctness requirement of the algorithm is that the output of
T
on input
x\in\{0,1,\mathsf{u}\}^{n}
equals
f_{\mathsf{u}}(x)
for all
x\in\{0,1,\mathsf{u}\}^{n}
. In this case,
T
is said to compute
f_{\mathsf{u}}
.
The cost of a query algorithm is the number of queries made on a worst-case input, which is exactly the depth of the corresponding tree.
Formally, the deterministic
\mathsf{u}
-query complexity complexity of
f
, denoted
\mathsf{D}_{\mathsf{u}}(f)
, is defined as

\mathsf{D}_{\mathsf{u}}(f):=\min_{T}\textnormal{depth}(T),

where the minimization is over all deterministic decision trees
T
that compute
f_{\mathsf{u}}
.
A randomized decision tree is a distribution over deterministic decision trees. We say a randomized decision tree computes
f_{\mathsf{u}}
with error
1/3
if for all
x\in\{0,1,\mathsf{u}\}^{n}
, the probability that it outputs
f_{\mathsf{u}}(x)
is at least
2/3
. The depth of a randomized decision tree is the maximum depth of a deterministic decision tree in its support.
Define the randomized
\mathsf{u}
-query complexity of
f
as follows.

\mathsf{R}_{\mathsf{u}}(f):=\min_{T}\textnormal{depth}(T),

where the minimization is over all randomized decision trees
T
that compute
f_{\mathsf{u}}
to error at most
1/3
.
A quantum query algorithm
\mathcal{A}
for
f_{\mathsf{u}}
begins in a fixed initial state
|\psi_{0}\rangle
in a finite-dimensional Hilbert space, applies a sequence of unitaries
U_{0},O_{x},U_{1},O_{x},\dots,U_{T}
, and performs a measurement. Here, the initial state
|\psi_{0}\rangle
and the unitaries
U_{0},U_{1},\dots,U_{T}
are independent of the input. The unitary
O_{x}
represents the “query” operation, and does the following for each basis state:
it maps
|i\rangle|b\rangle|w\rangle
to
|i\rangle|b+x_{i}\mod 3\rangle|w\rangle
for all
i\in[n]
(here
x_{i}=\mathsf{u}
is interpreted as
x_{i}=2
, and the last register represents workspace that is not affected by the application of a query oracle).
The algorithm then performs a 3-outcome measurement on a designated output qutrit and outputs the observed value.
We say that
\mathcal{A}
is a bounded-error quantum query algorithm computing
f_{\mathsf{u}}
if for all
x\in\{0,1,\mathsf{u}\}^{n}
the probability that
f_{\mathsf{u}}(x)
is output is at least
2/3
. The (bounded-error)
quantum query complexity of
f_{\mathsf{u}}
, denoted by
\mathsf{Q}_{\mathsf{u}}(f)
, is the least number of queries required for a quantum query algorithm to compute
f_{\mathsf{u}}
with error probability at most
1/3
.

(Sensitive block, block sensitivity)
.

Let

.
A set

A sensitive block of

at

f_{\mathsf{u}}
at
x
.
The block sensitivity of

at

at

. The

-block sensitivity of

\mathsf{bs}_{\mathsf{u}}(f)=\max_{x\in\{0,1,\mathsf{u}\}^{n}}\mathsf{bs}(f_{\mathsf{u}},x).

For a string

at

By a

Definition 2.8

(Certificate)
.

Let

. A partial assignment

The

For

We require the following observations.

Let

3
Relating query complexity and
\mathsf{u}
-query complexity

In this section, we examine the relationship between the well-studied notion of query complexity and
\mathsf{u}
-query complexity. We begin by showing that the Indexing function exhibits an exponential separation between usual query complexity and
\mathsf{u}
-query complexity.

The following is well known.

Fact 3.1
.

Let
n
be a positive integer. Then,

\mathsf{D}(\mathsf{IND}_{n})=n+1,\qquad\mathsf{R}(\mathsf{IND}_{n})=\Omega(n),\qquad\mathsf{Q}(\mathsf{IND}_{n})=\Omega(n).

Define the OR function as

\mathsf{OR}_{n}(x)=\begin{cases}0&x=0^{n}\\
1&\textnormal{otherwise}.\end{cases}

Lemma 3.2
.

Let
n
be a positive integer. Then,

\mathsf{D}(\mathsf{OR}_{n})=n,\qquad\mathsf{R}(\mathsf{OR}_{n})=\Theta(n),\qquad\mathsf{Q}(\mathsf{OR}_{n})=\Theta(\sqrt{n}).

The deterministic and randomized bounds are folklore, the quantum upper bound follows by Grover’s search algorithm
[
Gro96
]
, and the quantum lower bound was first shown in
[
BBBV97
]
.

We now prove Lemma
1.1
using a reduction from the OR function.

Proof of Lemma
1.1
.

Let
f=\mathsf{IND}_{n}
. We first show the upper bounds. The deterministic and randomized upper bounds are trivial since the number of input bits is
\Theta(2^{n})
. For the quantum upper bound, we first query the
n
addressing variables, let the output be
x\in\{0,1,\mathsf{u}\}^{n}
. Further, let
z\in\{0,1,\mathsf{u}\}^{2^{n}}
denote the input’s target variables. Consider the set of indices
I=\left\{\mathsf{bin}(y)\in[2^{n}]:y\in\mathsf{Res}(x)\right\}
. By the definition of
\mathsf{IND}_{n}
, we have
f_{\mathsf{u}}(x,z)=b\in\{0,1\}
iff
z_{i}=b
for all
i\in I
. By a standard use of Grover’s search algorithm a constant number of times, we can determine with high probability whether
z
is the constant 0 on
I
, or whether it is the constant 1 on
I
, or whether neither of these is the case. This immediately gives us the output: 0 in the first case, 1 in the second case, and
\mathsf{u}
in the last case. The cost of querying the addressing variables is
n
, and constantly many applications of Grover’s search algorithm costs
O(2^{n/2})
.

We now show the lower bounds. Given a (deterministic/randomized/quantum) algorithm
\mathcal{A}
solving
f_{\mathsf{u}}
, we construct a (deterministic/randomized/quantum) algorithm
\mathcal{A}^{\prime}
with query complexity at most that of
\mathcal{A}
, and that solves
\mathsf{OR}_{2^{n}}
. Let the input to
\mathsf{OR}_{2^{n}}
be denoted by
x
.

We define
\mathcal{A}^{\prime}
to be the algorithm that simulates a run of
\mathcal{A}
in the following way:

1.

If
\mathcal{A}
queries the
j
’th bit of its input where
j\in[n]
, return
\mathsf{u}
.

2.

If
\mathcal{A}
queries the
j
’th bit of its input, where
j=n+k
for some
k>0
, then query
x_{k}
and return that value.

If
\mathcal{A}
outputs
0
,
\mathcal{A}^{\prime}
outputs
0
. Else
\mathcal{A}^{\prime}
outputs
1
. This can be simulated in the deterministic, randomized, and quantum models.
Note that the query complexity of
\mathcal{A}^{\prime}
is at most that of
\mathcal{A}
. We now argue correctness.

•

Let
x=0^{2^{n}}
. The input
z\in\{0,1,\mathsf{u}\}^{n+2^{n}}
to
f_{\mathsf{u}}
with all addressing bits set to
\mathsf{u}
, and the target bits all equal to
0
is consistent with the run of
\mathcal{A}
above. Note that for all
y\in\mathsf{Res}(z)
we have
f(y)=0
since the relevant target bit is always 0 regardless of the choice of addressing bits.
Since (with high probability)
\mathcal{A}
must be correct on
z
, this means that the output of
\mathcal{A}
, and hence
\mathcal{A}^{\prime}
, is 0 (with high probability) and correct in this case.

•

Let
x\neq 0^{2^{n}}
. The input
z\in\{0,1,\mathsf{u}\}^{n+2^{n}}
to
f_{\mathsf{u}}
with all addressing bits set to
\mathsf{u}
, and the target bits equal to the string
x
is consistent with the run of
\mathcal{A}
above. Now there exists a
y\in\mathsf{Res}(z)
that sets all indexing variables to point to a non-0 bit of the target variables (since there exists such a target variable). By the correctness of
\mathcal{A}
(with high probability), this means the output of
\mathcal{A}
must either be
\mathsf{u}
or 1. Thus
\mathcal{A}^{\prime}
outputs 1 in this case (with high probability), which is the correct answer.

∎

Now that we have exhibited an explicit function in Lemma
1.1
that witnesses an exponential gap between each of deterministic, randomized, and quantum query complexity and their
\mathsf{u}
counterparts, we turn to the question of what functions are as hard in the standard query model as they are in the
\mathsf{u}
-query model. We now prove Lemma
1.2
, which says that that the class of monotone functions is one such class of functions.

Proof of Lemma
1.2
.

Any query algorithm for
f_{\mathsf{u}}
also computes
f
with at most the same cost, and hence
\mathsf{D}(f)\leq\mathsf{D}_{\mathsf{u}}(f)
. Similarly we have
\mathsf{R}(f)\leq\mathsf{R}_{\mathsf{u}}(f)
and
\mathsf{Q}(f)\leq\mathsf{Q}_{\mathsf{u}}(f)
.

We start with a best (deterministic/randomized/quantum) query algorithm
\mathcal{A}
for
f
, and an oracle holding an input
x\in\{0,1,\mathsf{u}\}^{n}
for
f_{\mathsf{u}}
.
Now, for
b\in\{0,1\}
, we define
\mathcal{A}_{b}
to be the same algorithm as
\mathcal{A}
, but whenever
\mathcal{A}
queries the
j
’th bit of its input, it performs the following operation instead:

1.

Query the
j
’th bit of
x
, denote the outcome by
x_{j}
.

2.

If
x_{j}\in\{0,1\}
, return
x_{j}
.

3.

If
x_{j}=\mathsf{u}
, return
b
.

Note that this operation can indeed be implemented quantumly making
2
queries to
O_{x}
. The initial query performs the instructions described above, and the second query uncomputes the values from the tuple we don’t need for the remaining part of the computation. Note here that
O_{x}^{3}=I
by definition, and thus
O_{x}^{2}=O_{x}^{-1}
, which is what we need to implement for the uncomputation operations.

Let
S_{\mathsf{u}}=\{i\mid x_{i}=\mathsf{u}\}
be the positions that have
\mathsf{u}
in
x
. Recall that
y^{0}:=x|_{S_{u}\leftarrow\vec{0}}
(and
y^{1}:=x|_{S_{u}\leftarrow\vec{1}}
) is the input that has all the
\mathsf{u}
in
x
replaced by
0
s (by
1
s respectively). Run
\mathcal{A}_{0}
and
\mathcal{A}_{1}
(possibly repeated constantly many times each) to determine the values of
f(y^{0})
and
f(y^{1})
with high probability. If
f(y^{0})=1
, then we output
1
. Else if
f(y^{1})=0
, we output
0
. Else we have
f(y^{0})=0
and
f(y^{1})=1
, and we output
\mathsf{u}
.

Correctness:
First observe that for
b\in\{0,1\}
, all answers to queries in the algorithm
\mathcal{A}_{b}
are consistent with the input
y^{b}
. Next observe that in the poset (equivalently ‘subcube’) formed by the resolutions of
x
, the inputs
y^{0}
and
y^{1}
form the bottom and top elements respectively. Since
f
is monotone, if
f(y^{0})=1
, we can conclude that
f
is
1
on all resolutions of
x
. Similarly when
f(y^{1})=0
, it must be the case that
f
is
0
on all inputs in the poset. The remaining case is when
f(y^{0})=0
and
f(y^{1})=1
. In this case, the inputs
y^{0}
and
y^{1}
are themselves resolutions of
x
with different evaluations of
f
, and hence the algorithm correctly outputs
\mathsf{u}
.

By standard boosting of success probability using a Chernoff bound by repeating
\mathcal{A}_{0}
(
\mathcal{A}_{1}
) constantly many times and taking a majority vote of the answers, we can ensure that the correctness probability of
\mathcal{A}_{0}
(
\mathcal{A}_{1}
) is at least 0.9. Thus, the algorithm described above has correctness probability at least
0.9^{2}=0.81
, and its cost is at most a constant times the cost of
\mathcal{A}
.
∎

Specifically, Lemma
1.2
allows us to exhibit an explicit
n
-variate Boolean function
f
with even
\mathsf{u}
-query complexity
O(\log n)
. The function of interest here is the monotone variant of the Indexing function due to Wegener
[
Weg85
]
, defined in Definition
2.4
.

Lemma 3.3
.

Let
n
be a positive integer and let
m=n+\binom{n}{n/2}
. Let
f=\mathsf{mIND}:\{0,1\}^{m}\to\{0,1\}
. Then,

\mathsf{D}_{\mathsf{u}}(f),\mathsf{R}_{\mathsf{u}}(f),\mathsf{Q}_{\mathsf{u}}(f)=O(\log m).

Proof.

A deterministic (and hence randomized and quantum) query upper bound for
f
is as follows: first query the
n
indexing variables. If the number of 1’s seen so far is smaller than
n/2
, output 0, else if the number of 1’s seen so far is larger than
n/2
, output 1, else query the relevant target variable and output the value seen. This gives a deterministic query upper bound of
n=O(\log m)
. Since
f
is monotone, using Lemma
1.2
completes the proof.
∎

This shows a stark contrast between the (deterministic/randomized/quantum)
\mathsf{u}
-query complexity of the monotone and non-monotone variants of the Indexing function, with the former having logarithmic (deterministic/randomized/quantum)
\mathsf{u}
-query complexity and the latter having linear (square root in the case of quantum) query complexity (Lemma
1.1
).

Observation 3.4
.

goes through for unate functions (Definition

) too. Let

\mathcal{A}

\mathcal{A}_{\mathsf{u}}

It was shown in a line of work

The polynomial equivalences can be shown using the following three inequalities:

(i)

\mathsf{D}(f)\leq\mathsf{C}(f)\cdot\mathsf{bs}(f)

(ii)

\mathsf{C}(f)\leq\mathsf{bs}(f)\cdot\mathsf{s}(f)\leq\mathsf{bs}(f)^{2}

\mathsf{bs}(f)=O(\mathsf{R}(f))

. Algorithm
1
is a deterministic query algorithm that achieves this bound, as shown in Theorem

. Following this, we show
\mathsf{u}
-query versions of (ii) and (iii) in Lemma

and Lemma

(in particular, the unknown input
x
) must satisfy
f_{\mathsf{u}}(x)=\mathsf{u}
, which concludes the proof of correctness.

The
for
loop on Line
4
runs for
\mathsf{bs}_{\mathsf{u},1}(f)=O(\mathsf{bs}_{\mathsf{u}}(f))
many iterations, and at most
\mathsf{C}_{\mathsf{u},0}(f)\leq\mathsf{C}_{\mathsf{u}}(f)
many bits are queried in each iteration. So the first
for
loop makes a total of
O(\mathsf{C}_{\mathsf{u}}(f)\mathsf{bs}_{\mathsf{u}}(f))
many queries.
Similarly, the number of queries by the second
for

is
O(\mathsf{C}_{\mathsf{u}}(f)\mathsf{bs}_{\mathsf{u}}(f))
, making the total number of bits queried by the algorithm as
O(\mathsf{C}_{\mathsf{u}}(f)\mathsf{bs}_{\mathsf{u}}(f))

∎

Lemma 4.4
.

Let
f:\{0,1\}^{n}\to\{0,1\}
. Then
\mathsf{C}_{\mathsf{u}}(f)=O(\mathsf{bs}_{\mathsf{u}}(f)\cdot\mathsf{s}_{\mathsf{u}}(f))
.

Proof.

Fix
x\in\{0,1,\mathsf{u}\}^{n}
. Let
B_{1},\dots,B_{k}
be a maximal set of minimal disjoint sensitive blocks of
f_{\mathsf{u}}
at
x
. By the definition of
\mathsf{bs}_{\mathsf{u}}(f)
, we have
k\leq\mathsf{bs}_{\mathsf{u}}(f)
. We first show that for all
i\in[k]
,
|B_{i}|\leq\mathsf{s}_{\mathsf{u}}(f)
. Towards this, fix
i\in[k]
. We have
b=f_{\mathsf{u}}(x)\neq f_{\mathsf{u}}(x^{B_{i}})=b^{\prime}
. Furthermore, for any
j\in B_{i}
, if we denote by
y
the input obtained by flipping the value of the
j
’th coordinate of
x^{B_{i}}
back to the value
x_{j}
, then we must have
f_{\mathsf{u}}(y)=b
. This is because
B_{i}
was assumed to be a
minimal
sensitive block; if
f_{\mathsf{u}}(y)\neq b
, then the set
B_{i}\setminus\left\{j\right\}
would have been a smaller sensitive block for
f_{\mathsf{u}}
at
x
than
B_{i}
. In particular, this means each
j\in B_{i}
is sensitive for
x^{B_{i}}
.

Next denote
S=\bigcup_{i=1}^{k}B_{i}
. We claim that
x_{S}
is a certificate for
f_{\mathsf{u}}
at
x
. Towards a contradiction, suppose
x_{S}
is not a certificate for
f_{\mathsf{u}}
at
x
. This implies existence of a
y\in\{0,1,\mathsf{u}\}^{n}
such that
y_{S}=x_{S}
and
f_{\mathsf{u}}(y)\neq f_{\mathsf{u}}(x)
. Let
B^{\prime}=\left\{i\in[n]:x_{i}\neq y_{i}\right\}
. Thus
B^{\prime}
is a sensitive block for
f_{\mathsf{u}}
at
x
. Furthermore,
B^{\prime}\cap S=\emptyset
, which means
B^{\prime}\cap B_{i}=\emptyset
for all
i\in[k]
. This contradicts our assumption that
B_{1},\dots,B_{k}
was a
maximal
set of minimal disjoint sensitive blocks for
f_{\mathsf{u}}
at
x
.

Combining the above, we conclude that
S=\bigcup_{i=1}^{k}B_{i}
is a certificate for
f_{\mathsf{u}}
at
x
, and its size is at most
k\cdot\mathsf{s}_{\mathsf{u}}(f)\leq\mathsf{bs}_{\mathsf{u}}(f)\cdot\mathsf{s}_{\mathsf{u}}(f)
, concluding the proof of the lemma.
∎

Lemma 4.5
.

Let
f:\{0,1\}^{n}\to\{0,1\}
. Then,

\mathsf{R}_{\mathsf{u}}(f)=\Omega(\mathsf{bs}_{\mathsf{u}}(f)),\qquad\mathsf{Q}_{\mathsf{u}}(f)=\Omega(\sqrt{\mathsf{bs}_{\mathsf{u}}(f)}).

Proof.

We use Lemma
2.5
for the randomized lower bound. Let
x\in\{0,1,\mathsf{u}\}^{n}
be such that
\mathsf{bs}_{\mathsf{u}}(f)=\mathsf{bs}(f_{\mathsf{u}},x)=k
, say. Define a distribution
\mu
on
\{0,1,\mathsf{u}\}^{n}
as follows:

\displaystyle\mu(x)

\displaystyle=1/2,

\displaystyle\mu(x^{B_{i}})

\displaystyle=1/2k~\textnormal{for all}~i\in[k].

Towards a contradiction, let
T
be a deterministic decision tree of cost less than
k/10
that computes
f_{\mathsf{u}}
to error at most
1/3
under the input distribution
\mu
. Let
L_{x}
denote the leaf of
T
reached by the input
x
. There are now two cases:

•

If the output at
L_{x}
is not equal to
f_{\mathsf{u}}(x)
, then
T
errs on
x
, which contributes to an error of 1/2 under
\mu
, which is a contradiction.

•

If the output at
L_{x}
equals
f_{\mathsf{u}}(x)
, since the number of queries on this path is less than
k/10
, there must exist at least
9k/10
blocks
B_{i}
from the set
B_{1},\dots,B_{k}
such that no variable of
x^{B_{i}}
is read on input
x^{B_{i}}
(observe that in this case,
x^{B_{i}}
also reaches the leaf
L_{x}
). Since
f(x^{B_{i}})\neq f(x)
, this means
T
makes an error on each of these
B_{i}
’s, contributing to a total error of at least
9k/10\cdot 1/2k=0.45
under
\mu
, which is a contradiction.

This concludes the randomized lower bound.

For the quantum lower bound we use Theorem
2.6
. Define
X=\left\{x\right\},Y=\left\{x^{B_{i}}:i\in[k]\right\}
, and
R=X\times Y
. From Theorem
2.6
we have
m=k,m^{\prime}=1,\ell=1
(since each index appears in at most 1 block, as each block is disjoint) and
\ell^{\prime}=1
. Theorem
2.6
then implies
\mathsf{Q}_{\mathsf{u}}(f)=\Omega(\sqrt{k})=\Omega(\sqrt{\mathsf{bs}_{\mathsf{u}}(f)})
.
∎

We conclude this section by proving Theorem
1.3
.

Proof of Theorem
1.3
.

Theorem
4.3
and Lemma
4.4
imply

\mathsf{D}_{\mathsf{u}}(f)=O(\mathsf{C}_{\mathsf{u}}(f)\cdot\mathsf{bs}_{\mathsf{u}}(f))=O(\mathsf{bs}_{\mathsf{u}}(f)^{2}\cdot\mathsf{s}_{\mathsf{u}}(f))=O(\mathsf{bs}_{\mathsf{u}}(f)^{3})=O(\mathsf{R}_{\mathsf{u}}(f)^{3}),

where the final bound is from Lemma
4.5
. Substituting the second bound from Lemma
4.5
in the last equality above also yields
\mathsf{D}_{\mathsf{u}}(f)=O(\mathsf{Q}_{\mathsf{u}}(f)^{6})
.
∎

5
Conclusions and future work

In this paper we initiated a study of
\mathsf{u}
-query complexity of Boolean functions, by considering a natural generalization of Kleene’s strong logic of indeterminacy on three variables. On the one hand, we showed that the Indexing function which admits a logarithmic-cost query protocol in the usual query model, has linear query complexity in the
\mathsf{u}
-query model.
On the other hand, we showed that a monotone variant of it admits an efficient
\mathsf{u}
-query protocol. More generally, we showed that for monotone Boolean functions, the
\mathsf{u}
-query complexity and usual query complexity are within a factor of two of each other.

We showed using
\mathsf{u}
-analogs of block sensitivity, sensitivity, and certificate complexity that for all Boolean functions
f
, its deterministic, randomized, and quantum
\mathsf{u}
-query complexities are polynomially related to each other. An interesting research direction would be to determine the tightest possible separations between all of these measures. It is interesting to note that our cubic relationship between deterministic and randomized
\mathsf{u}
-query complexity matches the best-known cubic relationship in the usual query models. However, it is known that
\mathsf{D}(f)=O(\mathsf{Q}(f)^{4})

[
ABDK+21
]
, which is essentially the best separation possible in the usual query model
[
ABB+17
]
. This proof goes via giving a lower bound on quantum query complexity of a Boolean function by the intermediate measure of its
degree
.
It is interesting to see if the techniques of
[
ABB+17
]
can be adapted to show a fourth-power relationship between deterministic and quantum
\mathsf{u}
-query complexities in our setting as well.
It would also be interesting to see if
\mathsf{u}
-query complexity of Boolean functions can be characterized by more standard measures of complexity of Boolean functions. More generally, it would be interesting to see best known relationships between combinatorial measures of Boolean functions in this model, and see how they compare to the usual query model (see, for instance,
[
ABDK+21
, Table 1]
).

While we studied an important extension of Boolean functions to a specific three-valued logic that has been extensively studied in various contexts, an interesting future direction is to consider query complexities of Boolean functions on other interesting logics. Our definition of
f_{\mathsf{u}}
dictates that
f_{\mathsf{u}}(x)=b\in\{0,1\}
iff
f(y)=b
for all
y\in\mathsf{Res}(x)
, and
f_{\mathsf{u}}(x)=\mathsf{u}
otherwise. A natural variant is to define a 0-1 valued function that outputs
b\in\{0,1\}
iff majority of
f(y)
equal
b
over all
y\in\mathsf{Res}(x)
. The same proof technique we used in Lemma
1.1
can easily be extended to show that the complexity of this variant of
\mathsf{IND}_{n}
is bounded from below by the usual query complexity of Majority on
2^{n}
variables, which is
\Omega(2^{n})
in the deterministic, randomized, and quantum query models.
