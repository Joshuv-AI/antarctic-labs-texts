From Reasoning to Code: GRPO Optimization for Underrepresented Languages
Federico Pennino, Bianca Raimondi, Massimo Rondelli, Andrea Gurioli, Maurizio Gabbrielli

Abstract
Generating accurate and executable code using large language models (LLMs) is challenging for languages with limited public training data compared to popular languages such as Python. This paper introduces a generalizable approach that uses small-scale code versions of the Qwen 2.5 model combined with Group Relative Policy Optimization (GRPO) to enable effective code generation through explicit reasoning steps, which is particularly beneficial for languages with smaller source code databases. Using Prolog as a representative use case — given its limited online presence — the initial model faced challenges in generating executable code. After some training steps, the model successfully produces logically consistent and syntactically accurate code by directly integrating reasoning-driven feedback into the reinforcement learning loop. Experimental evaluations using mathematical logic problem benchmarks illustrate significant improvements in reasoning quality, code accuracy, and logical correctness, underscoring the potential of this approach to benefit a wide range of programming languages lacking extensive training resources.

1
Introduction

Code generation using large language models (LLMs)
[
Jiang et al.(2024)Jiang, Wang, Shen, Kim, and Kim
]
has rapidly gained importance, providing significant potential for automating and improving software development processes. By generating executable code to solve common mathematical and logical problems, LLMs facilitate increased productivity, accessibility, and innovation in various programming tasks. However, the ability of LLMs to generate accurate and executable code often depends on their familiarity with the target programming languages and the availability of extensive training data. For underrepresented languages, that is, languages with limited public training data, the task of code generation using LLMs can be very challenging. This is particularly true for Prolog, since this language adds the challenge of Prolog’s declarative paradigm to the already limited training data
[
Yang et al.(2024)Yang, Chen, and Tam
]
.

Prolog is a logic programming language in which programs consist of facts and rules, and the computation proceeds by performing deduction steps. Given a Prolog program, the user poses a query (or
goal
) that the language interpreter attempts to solve using SLD resolution. Queries range from requests for simple fact retrieval to complex recursive reasoning involving numerical and non-numerical data (e.g., graphs, lists, difference lists, etc.). Modern Prolog systems include constraint programming capabilities, dramatically improving computation efficiency by introducing the “constraint and generate” paradigm and using sophisticated constraint solvers (including numerical ones).

Figure 1:
Schematic representation of the GRPO training pipeline utilizing a Prolog interpreter for evaluation. The framework consists of
Qwen2.5-Coder
generating Prolog solutions, which are then evaluated through
PySwip
to determine correctness and reward signals.

Prolog’s strengths in symbolic reasoning, logic inference, and constraint solving made it one of the most important languages for AI in the previous century (see, for example, the Fifth Generation Computer Systems project, a 10-year initiative launched in 1982 by Japan). Nevertheless, Prolog has a very limited online presence in public repositories today, hence its particular appropriateness for our study.

To overcome limitations related to training data scarcity, recent research has explored integrating external tools and interpreters into the LLM workflow, enabling models to leverage external computational resources rather than relying solely on internal reasoning. This integration, often called the program-of-thought approach
[
Chen et al.(2023)Chen, Ma, Wang, and Cohen
]
, allows models to offload complex calculations or logical reasoning to specialized external tools, improving efficiency and accuracy.

In this context, reinforcement learning (RL) has emerged as a valuable strategy to refine LLM-based code generation further. RL enables models to iteratively improve their outputs by learning from explicit execution-based feedback. Group Relative Policy Optimization (GRPO)
[
Shao et al.(2024)Shao, Wang, Zhu, Xu, Song, Bi, Zhang, Zhang, Li, Wu, and Guo
]
, a RL technique that extends Proximal Policy Optimization (PPO), simplifies the complexity of training by normalizing rewards across groups of sampled trajectories.

In this paper, we apply GRPO to QwenCoder 2.5 models
[
Hui et al.(2024)Hui, Yang, Cui, Yang, Liu, Zhang, Liu, Zhang, Yu, Dang, et al.
]
of varying sizes (0.5B, 1.5B, 3B, and 7B parameters) to investigate their ability to generalize effectively to languages with limited representation in training datasets, using Prolog as a representative case.

GRPO is especially suitable for tasks where multiple syntactic solutions may correspond to the same logical outcome. In our context, we use GRPO to optimize the generation of Prolog programs by using execution-based rewards to guide training. GRPO’s flexibility allows us to integrate domain-specific constraints into the reward; incorporating it into our pipeline is expected to improve the consistency and correctness of synthesized Prolog programs across several different tasks.

In our approach, at each step, the model must generate both the Prolog program (facts and rules) and a corresponding set of queries; we then execute these in a standard Prolog interpreter and assign a reward based on whether the returned solutions match the expected answers. By incorporating this explicit execution-based evaluation step, we can directly measure a model’s generalization ability.

To evaluate the effectiveness of our approach, we utilize the GSM8K dataset
[
Cobbe et al.(2021)Cobbe, Kosaraju, Bavarian, Chen, Jun, Kaiser, Plappert, Tworek, Hilton, Nakano, Hesse, and Schulman
]
. This is composed of grade-school mathematical word problems designed to test multi-step reasoning and has become a standard benchmark for evaluating the code generation capabilities of LLMs. Models are typically assessed on their ability to generate executable code (often Python) that correctly solves these mathematical problems. The GSM8K benchmark was also employed in the technical paper for the base Qwen2.5 models
[
Hui et al.(2024)Hui, Yang, Cui, Yang, Liu, Zhang, Liu, Zhang, Yu, Dang, et al.
]
. Instead of generating Python, we evaluate whether the Qwen models fine-tuned with GRPO can leverage their mathematical reasoning abilities to produce coherent and executable Prolog programs that solve the GSM8K problems. Furthermore, to assess generalization beyond mathematical word problems, we tested the GRPO-adapted models on a curated subset of 20 distinct programming tasks sourced from Rosetta Code. We evaluated their ability to generate correct Prolog solutions for more general programming tasks.

Summarizing, the main contributions of this article are:

•

applying GRPO to the task of generating code for underrepresented languages. In particular, we apply this to Prolog code, allowing
Qwen2.5 Coder
to learn the reasoning process to generate effective Prolog code;

•

directly integrating explicit Prolog execution-based evaluation into the reinforcement learning loop;

•

evaluating the models’ generalization capabilities in zero-shot and one-shot learning environments;

Our results, discussed in Section
4
, show that GRPO presents a compelling approach for advancing Prolog-based synthesis models, particularly by efficiently leveraging execution feedback to enhance neural-symbolic reasoning capabilities.
More generally, our findings demonstrate the robustness and adaptability of the proposed methodology for languages traditionally challenging for code generation due to limited training data availability.

2
Related work

Early efforts to solve GSM8K math problems predominantly employed purely neural approaches, notably Chain-of-Thought (CoT) prompting, which guides models to generate intermediate reasoning steps. Although CoT significantly improved model accuracy by decomposing complex problems, its effectiveness was limited by recurrent calculation errors in multi-step reasoning. The researchers integrated external computational tools and verifiers to address this limitation, enhancing the model’s reliability. For example,
[
Cobbe et al.(2021)Cobbe, Kosaraju, Bavarian, Chen, Jun, Kaiser, Plappert, Tworek, Hilton, Nakano, Hesse, and Schulman
]
trained neural models with external calculator modules or separate verification steps, achieving better computational accuracy.

More recently, neural-symbolic approaches have emerged, merging neural language comprehension with formal symbolic reasoning.
[
Yang et al.(2024)Yang, Chen, and Tam
]
introduced GSM8K-Prolog, a dataset that pairs GSM8K problems with the corresponding Prolog programs, demonstrating superior accuracy compared to CoT by explicitly delegating symbolic reasoning to logic engines. Their Prolog generation model substantially outperformed equivalent models relying solely on textual reasoning, further enhanced by predicate permutation (ProPro) as a data augmentation technique. This method increased the model’s accuracy from approximately 41–48% to approximately 50–51%, significantly surpassing traditional CoT prompting (36%), thus emphasizing the benefits of combining symbolic logic with neural training.

Advances in specialized large language models for code generation, such as OpenAI Codex, Code-Llama
[
Rozière et al.(2023)Rozière, Gehring, Gloeckle, Sootla, Gat, Tan, Adi, Liu, Sauvestre, Remez, Rapin, Kozhevnikov, Evtimov, Bitton, Bhatt, Canton Ferrer, Grattafiori, Xiong, Défossez, Copet, Azhar, Touvron, Martin, Usunier, Scialom, and Synnaeve
]
, StarCoder
[
Li et al.(2023)Li, Allal, Zi, Muennighoff, Kocetkov, Mou, Marone, Akiki, Li, Chim, Liu, Zheltonozhskii, Zhuo, Wang, Dehaene, Davaadorj, Lamy-Poirier, Monteiro, Shliazhko, Gontier, Meade, Zebaze, Yee, Umapathi, Zhu, Lipkin, Oblokulov, Wang, V, Stillerman, Patel, Abulkhanov, Zocca, Dey, Zhang, Fahmy, Bhattacharyya, Yu, Singh, Luccioni, Villegas, Kunakov, Zhdanov, Romero, Lee, Timor, Ding, Schlesinger, Schoelkopf, Ebert, Dao, Mishra, Gu, Robinson, Anderson, Dolan-Gavitt, Contractor, Reddy, Fried, Bahdanau, Jernite, Ferrandis, Hughes, Wolf, Guha, von Werra, and de Vries
]
, and Qwen2.5-Coder
[
Hui et al.(2024)Hui, Yang, Cui, Yang, Liu, Zhang, Liu, Zhang, Yu, Dang, et al.
]
, have further enhanced the capability for program synthesis. These models leverage vast code-pretraining datasets, enabling zero-shot or few-shot solutions to math problems by internally synthesizing and mentally ”executing” code snippets.

Program synthesis in logic programming traditionally relied on Inductive Logic Programming (ILP) systems, which, while effective, often required explicit formal specifications rather than natural language inputs. Recent neuro-symbolic methods bridge this gap, using neural networks to propose candidate programs verified through symbolic execution. Various learning paradigms, supervised learning, heuristic search, and reinforcement learning (RL), have been explored for program synthesis. Notably, RL approaches leverage feedback from intermediate program states or execution outcomes to iteratively refine the synthesis policy. Previous works like
[
Simmons-Edler et al.(2018)Simmons-Edler, Miltner, and Seung
]
and
[
Chen et al.(2020)Chen, Wang, Bastani, Dillig, and Feng
]
demonstrated the efficacy of reinforcement learning combined with logical deduction. Similarly,
[
Le et al.(2022)Le, Wang, Gotmare, Savarese, and Hoi
]
proposed CodeRL, a framework leveraging pretrained language models and deep reinforcement learning for general-purpose program synthesis. CodeRL employs an actor-critic setup where the language model (actor) generates code, and a critic model predicts functional correctness based on unit tests, providing dense reward signals to optimize the actor beyond standard supervised learning. Their method, enhanced by a ”Critic Sampling” inference technique that refines and repairs code using unit test feedback, achieved state-of-the-art results on benchmarks like APPS and MBPP, highlighting the effectiveness of RL in improving functional correctness.

Within RL, Group Relative Policy Optimization (GRPO)
[
Shao et al.(2024)Shao, Wang, Zhu, Xu, Song, Bi, Zhang, Zhang, Li, Wu, and Guo
]
has recently emerged as an efficient alternative to traditional policy-gradient methods like PPO. GRPO eliminates the need for a separate critic network by computing relative advantages based on peer performance within sampled batches, simplifying training and enhancing stability. This approach achieved notable success in math reasoning tasks, increasing accuracy on GSM8K and other math benchmarks. Furthermore, initial studies applying GRPO to code synthesis tasks, such as Rust code generation, highlight its potential effectiveness in structured domains such as program synthesis
[
Guan et al.(2025)Guan, Lyna Zhang, Liu, Shang, Sun, Zhu, Yang, and Yang
]
.

3
Methodology

3.1
Models and datasets

This study investigates applying smaller-scale language models for Prolog code generation, employing the 0.5B, 1.5B, 3B, and 7B versions of QwenCoder 2.5 Instruct
[
Hui et al.(2024)Hui, Yang, Cui, Yang, Liu, Zhang, Liu, Zhang, Yu, Dang, et al.
]
. We selected these models for their efficacy and lower computational requirements. A key challenge was the limited availability of publicly accessible Prolog code for supervised training, significantly restricting the models’ initial exposure to Prolog’s syntax. To address this, we adopted a reinforcement learning (RL) strategy using the GSM8K dataset
[
Cobbe et al.(2021)Cobbe, Kosaraju, Bavarian, Chen, Jun, Kaiser, Plappert, Tworek, Hilton, Nakano, Hesse, and Schulman
]
. While GSM8K comprises grade-school math word problems primarily designed for arithmetic reasoning, its emphasis on structured, logical problem-solving makes it a valuable proxy for evaluating and improving the reasoning skills necessary for Prolog code generation. An example of the execution pipeline is shown in Figure
1
.
In our setup, the language model learns to map natural language prompts to executable Prolog programs via feedback from execution results.

To evaluate the generalization capabilities of our models, we built a 20-task Prolog dataset sourced from Rosetta Code, including common algorithmic tasks: Fibonacci sequence, Sieve of Eratosthenes, Quicksort, Binary search, Greatest common divisor, Factorial, Towers of Hanoi, Palindrome detection, Prime decomposition, Dijkstra’s Algorithm, Levenshtein distance, N-queens problem, Ackermann function, Balanced brackets, Knight’s tour, Merge sort, Roman numerals decode, Longest common subsequence, Huffman coding, 24 game.
These tasks were selected to cover various programming constructs, recursion patterns, and symbolic reasoning challenges.
By evaluating on this diverse benchmark, we aimed to assess not only syntactic fluency in Prolog but also structural generalization and algorithmic alignment.
This evaluation setting enables an analysis of model performance beyond GSM8K, testing transferability to real-world logic programming tasks.

3.2
Group Relative Policy Optimization (GRPO)

Group Relative Policy Optimization (GRPO)
[
Shao et al.(2024)Shao, Wang, Zhu, Xu, Song, Bi, Zhang, Zhang, Li, Wu, and Guo
]
is a variant of Proximal Policy Optimization (PPO) specifically designed for the fine-tuning of large language models in reasoning. By removing the value (critic) network and instead computing a baseline from a small group of sample outputs, GRPO reduces memory and compute overhead without sacrificing stability.
We sample for each prompt
q
a
group
of
G
complete outputs
\{o^{(i)}\}_{i=1}^{G}
from the old policy. We then compute relative advantages within the group:

\hat{A}^{(i)}_{t}\;=\;r^{(i)}-\frac{1}{G}\sum_{j=1}^{G}r^{(j)}

r^{(i)}=r_{\phi}\bigl(q,o^{(i)}\bigr)-\beta\,D_{\!\mathrm{KL}}\bigl(\pi_{\theta}(\cdot\mid q)\,\|\,\pi_{\rm ref}(\cdot\mid q)\bigr)

where
r_{\phi}
is the reward model score (e.g. correctness on MATH) and
\beta
weights the global KL penalty. Compared to the original implementation, we applied the GRPO objective at token-level instead of the sentence-level as proposed in
[
Yu et al.(2025)Yu, Zhang, Zhu, Yuan, Zuo, Yue, Fan, Liu, Liu, Liu, Lin, Lin, Ma, Sheng, Tong, Zhang, Zhang, Zhang, Zhu, Zhu, Chen, Chen, Wang, Yu, Dai, Song, Wei, Zhou, Liu, Ma, Zhang, Yan, Qiao, Wu, and Wang
]
.

GRPO offers several key advantages. Primarily, it eliminates the need for a critic network by estimating the baseline using the group mean, which saves significant memory and computational resources. Furthermore, its use of relative advantages aligns well with reward models typically trained on pairwise or groupwise comparisons.

3.3
Experimental Setup

To evaluate the effectiveness of our approach, we conducted experiments on different model configurations, varying the model size. We utilized Low-Rank Adaptation (LoRA)
[
Hu et al.(2021)Hu, Shen, Wallis, Allen-Zhu, Li, Wang, Wang, and Chen
]
— with a LoRA rank of
32
— for efficient adaptation and fine-tuning across these configurations.
The evaluation process consisted of multiple runs with varying hyperparameters:

•

Model size: Different configurations of the model size were tested, corresponding to 7B, 3B, 1.5B, and 0.5B.

•

Checkpoints: The model was evaluated at three different training checkpoints 1500, 1000, 500.

•

Zero-shot vs. One-shot: The model was trained in both one-shot and zero-shot learning to measure its ability to generalize based on the context provided.

The resulting models were appropriately prompted based on the learning hyperparameter to be consistent with the prompt setting. The testing script executed inference using the vLLM
[
Kwon et al.(2023)Kwon, Li, Zhuang, Sheng, Zheng, Yu, Gonzalez, Zhang, and Stoica
]
framework on a GPU-enabled system, ensuring efficient execution of large-scale language models.

All experiments were conducted on the same hardware environment to fairly compare runtime and resource usage.
Evaluation metrics and experiment scripts were standardized to facilitate reproducibility and future benchmarking.

3.4
Reward system

The training pipeline adopts a reinforcement learning framework utilizing Group Relative Policy Optimization (GRPO). This enables iterative refinement of code generation capabilities based on interpreter feedback, ensuring syntactic correctness and logical soundness in the generated Prolog code and throughout the entire text generation process.
The model’s adherence to the required template outlined by the system prompt (Fig.
1
) is enforced through the reward function.

We considered two main aspects of assigning a reward to model generation: the format used by the model to provide its reasoning and the correctness of the generated code based on ground truth.
The format-based rewards encourage structured generation that aligns with the system template, ensuring the Prolog code remains extractable and consistently interpretable.
These reward signals are combined at each step to form the total reward, which GRPO uses to rank and guide policy updates.

3.4.1
Format Reward

We implement a format-based reward mechanism to ensure the generated Prolog code adheres to a structured and readily usable format. This mechanism incentivizes the model to organize its output using predefined XML-like tags:
<reasoning>
,
<code>
, and
<query>
. The reward function operates based on a multi-step evaluation, combining both strict and flexible criteria:

•

xmlcount_reward_func
- Tag Presence (Incremental Scoring): The model receives incremental rewards for the presence of each required tag (+0.125 each). This includes all necessary components (reasoning, code, and query). After some initial experimentation, an important adjustment (-0.5) was made to ensure that the Prolog query is placed only inside the
<query>
tag and not inside the
<code>
tag, to avoid execution during rule assertion. Minor deductions are applied for extraneous text outside the defined template structure.

•

soft_format_reward_func
- Soft Format Evaluation: this provides a partial reward (+0.5) even if minor formatting errors are present, provided a regular expression can still successfully extract the Prolog code from the output. This offers greater flexibility while ensuring the core functionality (extractable code) remains intact.

•

strict_format_reward_func
- Strict Format Evaluation (Primary): Our primary approach, strict format evaluation, assigns a fixed reward (+0.5) only if the entire response strictly adheres to the predefined format.

This multi-level format-based reward system promotes consistently structured model outputs, enhancing their readability and usability.
Empirically, this has led to greater sample efficiency in enforcing structural conformity, reducing the number of epochs required for the model to consistently produce extractable and executable Prolog segments.
Additionally, the format reward is an early signal to guide learning, especially before the model has learned to solve problems correctly, thus playing a key role in early-stage stabilization.
Moreover, the combination of strict and flexible evaluation strategies allows us to balance rigorous format enforcement with a degree of tolerance for minor deviations.

3.4.2
Correctness Reward

We incorporate a correctness-based reward mechanism (
correctness_reward_func
) to ensure the generated Prolog code is syntactically valid and semantically correct. This reward incentivizes the model to produce code that, when executed, yields the expected answer. The evaluation uses
PySwip

[
Tekol and contributors(2024)
]
, a Python library that interfaces with
SWI-Prolog
.

The process begins with extracting the generated Prolog knowledge base and the corresponding query from the model’s output. This raw output is then preprocessed to remove any extraneous formatting elements, comments, or whitespace, and the query is refined to ensure it is correctly formatted for execution.

The extracted knowledge base is dynamically asserted into the SWI-Prolog environment using PySwip, and the refined query is executed within this environment. The result obtained from the Prolog interpreter (via
PySwip
) is then compared against the expected answer. A full reward (+1.0) is awarded if the Prolog interpreter’s output exactly matches the expected answer; otherwise, penalties are applied for incorrect results (-1.0), malformed responses (-0.5) that prevent execution (e.g., for syntax errors), or cases where the interpreter fails to produce an output (-0.1).
This reward structure reflects functional and structural correctness, penalizing failure modes with granularity proportional to their severity.
In particular, differentiating between syntax errors and incorrect logical outcomes helps the model learn first to prioritize code that runs before optimizing for correctness.

To ensure robustness and prevent resource exhaustion, the entire execution process is conducted within a sandboxed environment with a predefined timeout mechanism to avoid infinite loops or excessively long computation times.

This
PySwip
-based correctness evaluation provides a reliable and automated way to assess the functional correctness of the generated Prolog code. It drives the model towards producing solutions that adhere to the correct syntax and deliver the expected results.

3.5
Evaluation metrics

We assess the model’s capability to generate functionally correct Prolog code through evaluation. For each problem instance in our dataset, the model generates
k=4
candidate solutions. This generation process utilizes nucleus sampling (
p=0.95
) and a temperature of
0.8
to encourage diversity among the generated code snippets. The correctness of each generated solution
c_{i}^{j}
(the
j
-th solution for the
i
-th problem) is determined by executing it using a standard Prolog interpreter
P
and comparing its output
P(c_{i}^{j})
against the predefined ground truth result
r_{i}
.

We employ two primary metrics based on this execution framework to quantify performance: Pass
@k
and Pass
{}^{\wedge}k
.

Pass
@k
This metric measures the success rate considering the
k
generated candidates per problem. A problem is deemed successfully solved if
at least one
of the
k
generated solutions produces the correct output when executed. It is calculated over the entire dataset of
N
problems as shown in Eq.
1
. In this formula,
N
is the total number of problems,
c_{i}^{j}
is the
j
-th code for the
i
-th problem,
P(c_{i}^{j})
is its execution result via interpreter
P
,
r_{i}
is the ground truth, and the disjunction (
\bigvee
) captures the ”at least one” success condition.

\displaystyle pass@k=\frac{1}{N}\sum_{i=1}^{N}\bigg(\bigvee_{j=1}^{k}P(c_{i}^{j})=r_{i}\bigg)

(1)

Pass
{}^{\wedge}k
Providing a stricter assessment of performance, this metric requires
all

k
generated solutions for a given problem to execute correctly. It measures the model’s consistency and reliability in generating valid code. The formal definition is shown in Eq
2
.

\displaystyle pass^{\wedge}k=\frac{1}{N}\sum_{i=1}^{N}\bigg(\bigwedge_{j=1}^{k}P(c_{i}^{j})=r_{i}\bigg)

(2)

The notation follows Equation
1
, but the conjunction (
\bigwedge
) enforces the requirement that all
k
generated candidates must match the ground truth
r_{i}
for the problem to be counted as correct. This stricter metric evaluates the model’s reliability across multiple generations of attempts.

Using these metrics provides a more granular understanding of the model’s performance, offering insights into its ability to generalize across different problems while maintaining high accuracy and consistency in Prolog code generation. This is a key contribution of our work, bridging the gap between single-solution accuracy and multi-solution reliability.

4.2
Rosetta Code

We evaluated the generalization capabilities of our models by having them generate Prolog code for common algorithms at various training checkpoints under zero-shot and one-shot settings. We measured performance using the pass@4 and pass
∧
4 metrics detailed in Table
3
. In the zero-shot setting, baseline performance was negligible (pass@4=0.00) for the 0.5B and 1.5B models, while the 3B and 7B models achieved pass@4 scores of 0.20 and 0.26. GRPO adaptation yielded improvements within the first 500 steps, particularly for the 1.5B model, which improved from pass@4=0.00 to 0.20. Further steps showed diminishing or fluctuating returns, with the 7B model peaking at pass@4=0.33 after 1000 steps. One-shot prompting significantly improved performance: the 7B model reached its peak pass@4 of 0.46 after just 500 steps, nearly doubling its baseline zero-shot score, while the 3B model peaked at pass@4=0.20, also at 500 steps. Instead, pass
∧
4 remained low for the smaller models. The 7B model achieved its highest zero-shot pass
∧
4 of 0.26 (from base 0.13) and its highest one-shot pass
∧
4 of 0.33 (from base 0.20), both after 500 steps. These results underscore GRPO’s efficiency, with most gains realised by 500 steps, especially under one-shot prompting. These results confirm that mathematical reasoning fine-tuning enhances logic programming capabilities, though absolute performance indicates room for further specialized adaptation.

This evaluation highlights the importance of adapting general-purpose reasoning models for logic-based tasks, where accuracy metrics like pass
∧
4 are crucial for revealing real-world usability.
Our results suggest that targeted fine-tuning combined with minimal prompting can unlock substantial gains in code generation for traditionally underrepresented programming paradigms like Prolog.

Furthermore, the persistent gap between zero-shot and one-shot performance reinforces the importance of example-based prompting for reasoning tasks, suggesting the utility of supervised regimes that explicitly integrate symbolic logic demonstrations.
Finally, incorporating structured intermediate representations (such as predicate trees or derivation traces) into the training loop may further reduce hallucinations.

6
Conclusion

This work validates using GRPO to improve Prolog code generation in Qwen2.5-Coder models. Our results showed clear improvements across sizes: the 0.5B model improved in one-shot scenarios (pass@4 from 0.006 to 0.124), while the 1.5B model showed steady gains (e.g., zero-shot pass@4 up to 0.312). The 3B model demonstrated the most significant zero-shot learning, improving its pass@4 accuracy from 0.341 to 0.777. Optimizing the reward function for the 7B model by removing the KL penalty yielded the highest performance, achieving pass@4 scores of 0.882 (zero shot) and 0.893 (one shot), representing a new state of the art on Prolog GSM8k. Also, the generalization to broader tasks like those taken from Rosetta Code showed improvements (e.g., 7B reaching 0.467 pass@4 one-shot), thus indicating room for further improvement.

Our results demonstrate the robustness and adaptability of the proposed methodology for optimizing code generation via GRPO.
This suggests that it may be a valuable approach for enhancing the code generation capabilities of underrepresented programming languages. These languages often lack extensive training datasets and could significantly benefit from such targeted optimization methods.

Future work could investigate hybrid neural-symbolic architectures where LLMs delegate complex logical inference or constraint satisfaction to a Prolog engine, moving beyond simple code generation. Extending program-of-thought approaches, LLMs could learn to generate intermediate Prolog queries to structure their reasoning on complex tasks. Furthermore, Prolog’s capabilities can be leveraged for more sophisticated verification, checking the logical consistency of LLM reasoning steps or formal properties of generated code, potentially using execution traces for enhanced explainability. Finally, given the success demonstrated with Prolog, we plan to extend our study to other underrepresented languages.
