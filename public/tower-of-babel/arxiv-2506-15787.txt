SLR : An Automated Synthesis Framework for Scalable Logical Reasoning
Lukas Helff, Ahmad Omar, Felix Friedrich, Wolfgang Stammer, Antonia Wüst, Tim Woydt, Rupert Mitchell, Patrick Schramowski, Kristian Kersting

Abstract
We introduce SLR , an end-to-end framework for systematic evaluation and training of Large Language Models (LLMs) via S calable L ogical R easoning. Given a user’s task specification, SLR enables scalable, automated synthesis of inductive reasoning tasks with precisely controlled difficulty. For each task, SLR synthesizes (i) a latent ground-truth rule, (ii) an executable validation program used by a symbolic judge to deterministically verify model outputs, and (iii) an instruction prompt for the reasoning task. Using SLR , we create SLR-Bench , a benchmark comprising over 19k prompts spanning 20 curriculum levels that progressively increase in relational, arithmetic, and recursive complexity. Large-scale evaluation reveals that contemporary LLMs readily produce syntactically valid rules, yet often fail at correct logical inference. Recent reasoning LLMs do somewhat better, but incur substantial increases in test-time compute, sometimes exceeding 15k completion tokens. Finally, logic-tuning via SLR doubles Llama-3-8B accuracy on SLR-Bench , achieving parity with Gemini-Flash-Thinking at a fraction of computational cost. SLR is fully automated, requires no human annotation, ensures dataset novelty, and offers a scalable environment for probing and advancing LLMs’ reasoning capabilities.

3
SLR
: Automatic Logic Benchmark Synthesis

This section introduces
SLR
, a methodology for systematically generating, evaluating, and training on Inductive Logic Programming (ILP) tasks at scale. The core motivation for
SLR
is to provide a principled, automated, and scalable means of constructing diverse and challenging logical reasoning tasks embedded within natural language prompts. The
SLR
pipeline follows the three-stage process of Task Specification, Task Synthesis, and Evaluation & Training, as illustrated in Fig.
1
and detailed in the following sections.

Task Notation.

Our methodology adopts a structured design for ILP tasks, following the Learning-from-Entailment (LFE) paradigm
(
Raedt1997LogicalSF
)
and using the Prolog language for task representation. Each ILP task
\mathcal{I}
is defined as follows:

\mathcal{I}=\left(B,E^{+},E^{-}\right)

where
B
is the set of background ground atoms (i.e., context or facts for the task),

E^{+}
(
E^{-}
) is the set of positive and negative labeled examples (i.e., ground atoms for which the target predicate should or should not hold. A candidate hypothesis
H

solves
the task if and only if:

B\cup H\models E^{+}\quad\text{and}\quad B\cup H\not\models E^{-}.

Here,
\models
denotes logical entailment, as verified through symbolic execution in Prolog under the closed-world assumption.

3.1
Task Specification (Input)

The
SLR
synthesizer is controlled by a set of user-defined inputs that specify the structure and content of the generated tasks.
Specifically, these inputs consist of the Task Language
\mathcal{L}
, which defines the logical vocabulary and grammar, and the Task Configuration
\Theta
, which encodes parameters to control the generation process (see Fig.
1
, left).

Language Specification (
\mathcal{L}
):

We define a language
\mathcal{L}=(\mathcal{V},\mathcal{G})
that specifies the building blocks for task generation. This involves formulating a vocabulary
\mathcal{V}
of allowed syntactic elements and a grammar
\mathcal{G}
that imposes semantic constraints.

⟦(i)⟧

1.

Vocabulary
\mathcal{V}
: A set of constant, function, and predicate symbols that
form the syntax for generating rules, examples, and background knowledge. The vocabulary induces the Herbrand base
\mathrm{HB}(\mathcal{V})
, which is the set of all syntactically valid ground atoms (facts).

2.

Grammar
\mathcal{G}
: A set of semantic rules that filter the Herbrand base to include only meaningful atoms,
\mathrm{HB}_{\mathcal{G}}(\mathcal{V})
. In this way, the grammar introduces a bias so that only semantically coherent facts are produced. For instance, the grammar ensures that a color is assigned to a car (
car_color(car, red)
) but not to semantically incompatible objects.

Task Configuration (
\Theta
):

The configuration parameters give fine-grained control over the generation process via the tuple:

\Theta=\langle R_{\text{sample}},R_{\text{len}},B_{\pi},\kappa\rangle

⟦(i)⟧

1.

Rule Sampling Policy (
R_{\text{sample}})
: The policy for synthesizing the ground truth rule
R^{\star}
. Rules can either be sampled randomly (Uniform Sampling) or generated via an LLM (LLM-Guided Generation). For LLM-Guided Generation, a model is tasked to generate rules that contain arithmetic, recursions, variables, cuts, or comparison operators.

2.

Rule Length (
R_{\text{len}}
): An integer specifying the number of literals in the body of the ground-truth rule
R^{\star}
.

3.

Background Sampling Policy (
B_{\pi}
): A probability mass function that assigns a selection probability to each ground atom in the grammar-filtered Herbrand base
\mathrm{HB}_{\mathcal{G}}(\mathcal{V})
, enabling designers to encode priors on the data distribution (e.g.,
uniform
). We also include
mirror
sampling, where backgrounds for
(E^{+},E^{-})
are identical except for ground atoms relevant to
R^{\star}
.

4.

Problem Size (
\kappa=(\kappa_{\text{pos}},\kappa_{\text{neg}})
): A tuple specifying the target number of positive (
\kappa_{\text{pos}}=|E^{+}|
) and negative (
\kappa_{\text{neg}}=|E^{-}|
) examples. This directly controls the size and class balance of each generated ILP task.

3.2
ILP Task Synthesiser (Generation)

The core of
SLR
is the ILP Task Synthesizer (Fig.
1
, center), an automated process detailed in Algorithm
1
. Given a high-level task specification, the synthesizer generates complete and solvable ILP problems. The process consists of two main phases: rule synthesis and background synthesis.

1. Rule Synthesis (Alg.
1
, line 2).

The process begins with the
RuleGenerator
creating a latent, ground-truth rule
R^{\star}
. This rule represents the underlying logical pattern that a model is expected to induce. The generation is guided by pre-defined parameters (
R_{\text{len}}
,
R_{\text{sample}}
) that control the length and generation policy for the rule. The resulting rule is a syntactically valid definite clause of the form
h\texttt{:-}b_{1},~\dots,~b_{R_{\text{len}}}
.

2. Background Synthesis (Alg.
1
, lines 3-13).

Once
R^{\star}
is fixed, the synthesizer enters a loop to construct the background knowledge
B
and the label sets
E^{+}
and
E^{-}
. This loop executes three steps until the desired number of positive and negative examples is reached:

⟦(i)⟧

1.

Sample Background:
The
BackgroundGenerator
samples a set of ground atoms specifying the properties and relationships of the background instance. The background sampling is directed by a probability distribution (
B_{\pi}
) over
\mathrm{HB}_{\mathcal{G}}(\mathcal{V})
.

2.

Assign Label:
The
AssignLabel
function determines whether a query atom
q
(that is the ground atom of the target predicate
h
) is logically entailed by the sampled background
b
and the ground-truth rule
R^{\star}
(i.e., whether
b\cup R^{\star}\models q
holds). This produces a label (positive or negative) for the query. We denote the labeling function as:

\textsc{AssignLabel}(R^{\star},b)\\
=\begin{cases}(1,q),&\text{if}~b\cup R^{\star}\models q\\
(0,q),&\text{otherwise}\end{cases}

3.

Accept/Reject Sample:
To ensure the desired class balance, a stratified rejection sampling strategy is used to populate the example sets. The generated background
b
and query
q
are accepted only if the corresponding example set (
E^{+}
or
E^{-}
) is not yet full, as specified by the task size parameter (
\kappa
). If accepted,
b
is added to the task’s main background knowledge
B
, and
q
is added to the appropriate example set. Otherwise, the sample is discarded.

Synthesizer Outputs (Alg.
1
, lines 14-17).

The synthesizer then finalizes three key outputs for each task:
1. The
latent ground-truth rule
(
R^{\star}
) of the task.
2. A
validation program
, i.e., an executable logic program encoding the task instance (
B,E^{+},E^{-}
) for automated evaluation.
3. An
instruction prompt
that presents the task in a user-friendly format, either as natural language or Prolog code, ready for an LLM. App. Fig.
5
illustrates an example run to using the Synthesizer.

3.3
Training and Evaluation

The final stage, shown in Fig.
1
(right), uses the synthesized task to evaluate and train models.

SymbolicJudge
.

The core element for training and evaluation is the SymbolicJudge. It provides a deterministic interface for evaluating a candidate hypothesis
H
for a task. It runs
H
against the validation program, checking for correct entailment over all examples in
E^{+}
and
E^{-}
. Two evaluation metrics are used: an overall binary score indicating whether the task is perfectly solved, and a partial score corresponding to the fraction of correctly classified examples.

\textsc{OverallScore}_{B,E^{+},E^{-}}(H)=\llbracket\\
\forall q\in E^{+}:(B\cup H)\models q\quad\land\\
\forall q\in E^{-}:(B\cup H)\not\models q\rrbracket\in{0,1}

\textsc{PartialScore}_{B,E^{+},E^{-}}(H)=\\
\frac{\sum_{q\in E^{+}}\llbracket(B\cup H)\models q\rrbracket+\sum_{q\in E^{-}}\llbracket(B\cup H)\not\models q\rrbracket}{|E^{+}\cup E^{-}|}

Model Evaluation.

SLR
also streamlines the creation of logical reasoning benchmark datasets for systematic model evaluation. By specifying various combinations of task language and configuration, users can generate diverse ILP tasks that span a broad range of domains, prompt styles, and reasoning complexities. Each synthesized task comprises a natural language prompt, the corresponding ground-truth rule, and an executable validation program for assessment by the Symbolic Judge.

Model Training.

SLR
enables automated training loops, with model feedback available in two flavors. For SFT, the ground-truth rule
R^{\star}
serves as the training target, allowing for cross-entropy loss updates based on predicted rules. For RLVR, the symbolic judge provides reward signals, using partial or overall scores, to guide the model’s policy updates. This cohesive, automated pipeline efficiently supports the scalable generation, evaluation, and training of LLMs, facilitating systematic advances in logical reasoning capabilities.

Novelty and Systematic Generalization.

SLR
is fully synthetic, so overlap with existing data is statistically negligible, making it robust against data leakage and memorization. By default, we exclude ground-truth rules
R^{\star}
in the test set that are found in the training set, guaranteeing that inputs and outputs at test time are completely novel to the model. This setup enables us to assess whether the model is capable of systematic generalization to entirely new rules.

Design rationale.

The task specification is inspired by the train domain
helff2025vlol
;
michalski1980
;
Mitchell1997MachineLI
, which is attractive for three reasons. First, its hierarchical object structure (trains → cars → attributes) naturally gives rise to first-order rules that are far richer than simple lookups, yet more tractable than general theorem proving. Second, every attribute has a small, discrete grounding domain, which allows us to measure and control the complexity of the problem precisely. Third, we ensure expandability and novelty, as
SLR-Bench
is fully synthetic and programmatically generated from a user-constructed language and not curated from existing corpora.

Curriculum.

SLR-Bench
presents a 20-level curriculum that progresses systematically in difficulty and is organized into four overarching complexity tiers:
basic
,
easy
,
medium
, and
hard
. For a detailed overview of the level-wise task specifications, see App. Sec.
A
and Tab.
3

Each level increases in difficulty through systematic modifications to both the task language and configuration, including:
(i) increasing the overall size of the task (
\kappa
),
(ii) expanding the vocabulary by adding new car constants per train, and
(iii) broadening the set of predicates and grounding domains.
Next, (iv) we adapt the policy used for synthesizing background knowledge,
(v) alter the length
R_{len}
of the ground truth rule, and
(vi) Adjust the rule sampling policy.
Finally, (vii) the combinatorial space of tasks, quantified as the approximate number of distinct tasks that can be generated per level, also increases across the curriculum.

Language.

The vocabulary in
SLR-Bench
centers on two mutually exclusive class predicates,
eastbound/1
and
westbound/1
, which serve as the targets for classification tasks. Additionally, the vocabulary includes five predicates
(
has_car/2
,

car_num/2
,

car_color/2
,

car_len/2
, and

has_wall/2
) that define the basic properties of trains, with their respective grounding domains fully specified in App.
A.1
. As curriculum levels increase in complexity, the vocabulary expands monotonically to accommodate new predicates and grounding domains at higher levels.
These include additional categorical predicates (
has_roof/2
,
has_payload/2
,
has_window/2
,
car_type/2
), and numerical predicates (
load_num/2
,
has_wheel/2
,
passenger_num/2
). Semantic coherence is maintained by constraining predicate groundings to valid combinations (e.g., only colors as arguments for
car_color
), and by enforcing mutually exclusive constraints across predicates (e.g., passenger cars cannot simultaneously carry payloads). Comprehensive details on the vocabulary and grammar can be found in App.
A.1
.

Task config.

Next to the language
\mathcal{L}
, each curriculum level is parameterized using level-specific settings of
\theta
that are summarized in App. Tab.
3
and fed directly to the
SLR
synthesizer (Alg.
1
).
Problem size (
\kappa
) increases steadily across levels, with an equal balance of positive and negative samples.
For background knowledge, levels 1–5 use a
mirror
sampling policy to provide simple, nearly identical east- and westbound trains (differing only in ground atoms relevant to
R^{\star}
). From level 6 upward, background is sampled uniformly over the filtered Herbrand base, increasing train diversity.
The first five (basic) levels employ uniform rule generation; from level 6 onwards, 30% of rules are LLM-guided, introducing greater diversity in variables, arithmetic, and recursion.

The compounding effect of larger problems, expanded vocabulary (constants and predicates), and more complex rules not only yields exponential growth in the combinatorial space, but also effectively increases the complexity of the tasks, while guaranteeing that heuristics that merely memorise surface patterns in early levels do not scale to later ones.
For each generated task, we retain (i) the generated latent ground-truth rule, (ii) the corresponding validation program, and
associated instruction prompt for the task. A representative example is shown in Fig.
3
.

Intended use.

SLR-Bench
serves two complementary purposes. (1) As a
static
benchmark, it allows fine-grained evaluation of an LLM’s reasoning skills along an axis of increasing logical depth, and is easily extensible as models improve. (2) As a
dynamic
curriculum, it acts as the training backbone, providing reasoning tasks and model feedback for learning logical reasoning with LLMs and reasoning LLMs.

5
LLMs Can’t Do Induction at Scale

We benchmark 17 LLMs on
SLR-Bench
for their logical reasoning, syntactic capabilities, and computational efficiency across a systematic curriculum (
basic
,
easy
,
medium
,
hard
). In this section, we highlight the principal trends, identify the challenges revealed by our benchmark, and discuss the impact of training on logical reasoning data.

5.1
Evaluation Setup

All models are evaluated in a zero-shot fashion on
SLR-Bench
using prompts generated in the previous section. Each model receives a single attempt per task. Due to the high computational costs for some of the models, we report results on a representative 600-task subset (which reduces our cost to just under $1,000). We report the following metrics:
(i)
Logical–Reasoning Level (LRL):
The aggregated level of logical reasoning attained by a model on the 20-level
SLR-Bench
:

\text{LRL}=\sum_{\ell=1}^{L}\frac{\#\text{solved}_{\ell}}{\#\text{tasks}_{\ell}}

where
L
is the number of curriculum levels.
(ii)
Syntax Score:
The proportion of syntactically valid logic rules generated by the model.
(iii)
Logic-Reasoning Accuracy:
Fraction of correct solutions per complexity tier and overall.
(iv)
Compute:
Aggregate completion tokens and cost in USD (see App. Tab.
4
for pricing details).

5.2
Training Setup

We fine-tune models on 16,000 training tasks sampled from all levels of the
SLR-Bench
curriculum. For each task, the input consists of the complete prompt, while the output target is the ground-truth rule
R^{\star}
. All training instances are strictly disjoint from the test set to prevent data leakage and ensure fair evaluation. Thus, neither the evaluation prompts nor the ground-truth rules have been seen during training.
We explore two training regimes for Llama-3-8B-Instruct: (1) full-parameter fine-tuning (FFT) and (2) parameter-efficient adaptation via LoRA tuned on a shuffled version of the dataset. Both approaches optimize a cross-entropy loss between the model’s predicted rule tokens and the ground truth.

5.3
Analysis and Key Findings

Tab.
2
reports the overall model performance across all 20 curriculum levels, with the compute-performance trade-off for OpenAI models in Fig.
4
.

Curriculum Stages Effectively Modulate Challenge.

SLR-Bench
’s staged curriculum successfully delivers a controlled gradient in task complexity.
At the
basic
tier, most models achieve accuracies close to 100% (see Tab.
2
), confirming that basic logical inference is a solved problem for contemporary LLMs. As the curriculum progresses, each new tier introduces greater logical depth, leading to a monotonic decrease in model performance on the subsequent complexity tiers.

At the
easy
tier, a clear gap emerges between the conventional LLMs as well as the reasoning LLMs. While conventional LLMs plateau (all models solve less than 50%), reasoning models sustain performance, solving most of the easy tasks (with all models above 60% solved). This indicates that the conventional LLMs have much stronger difficulties when it comes to solving logical reasoning tasks, and are insufficient for more advanced logical induction.

At the
medium
tier, difficulty increases further, causing significant performance drops even among reasoning models. Only 2 models (o3 and 04-mini) are still able to clear more than 50% of the tasks. Among OpenAI’s mini series, Tab.
2
depicts a clear trend: steady improvement across model generations. While o1-mini solves only 20% of medium tasks, o3-mini 37%, and o4-mini reaches 52%. This illustrates both progress across model generations and the fine granularity and challenge provided by the benchmark’s curriculum.

The
hard
tier proves formidable for all current models. Even the strongest model (OpenAI’s
o3
) solves fewer than half of these tasks (45%), and all others fall below 21%, demonstrating that the upper curriculum levels set a bar that remains out of reach for today’s LLMs.

Reasoning is Challenging; Syntax is Nearly Solved.

Syntactic validity is nearly perfect for most LLMs. Especially base LLMs typically produce syntactically valid logic rules (see Tab.
2
). In contrast, the logical reasoning accuracy of all base LLMs lags by 50+ percentage points. Most errors, therefore, are of a semantic nature. Interestingly, advanced reasoning models (DeepSeek-R1, o3) exhibit lower syntax scores (57%, 80%) than base models (e.g., Llama-3-70B, GPT-4.5-prev at 99% and 100%). This degradation often stems from models producing ill-formed rules when navigating complex reasoning traces. Nevertheless, across all models, semantic errors are the predominant obstacles to higher accuracy.

Scaling Test-time Compute Improves Reasoning, but Returns Diminish and Costs Escalate.

Increasing test-time compute (via reasoning models) yields substantial gains in logical reasoning performance. For example, the lowest-performing reasoning LLM (DeepSeek-R1, LRL=8.1) surpasses the best conventional LLM (GPT-4.5, LRL=7.2). However, improvements come at a significant computational expense. For instance, moving from GPT-4o to
o3
doubles accuracy, but inflates cost by 20 times and increases the number of generated completion tokens by 27 times.
Analyzing the number of generated reasoning tokens (Fig.
4
), we find that higher test-time compute generally correlates with better reasoning outcomes, but this relationship does not always hold. On the easy and medium tiers, models that generate the most completion tokens do not achieve the highest reasoning accuracy. This trend persists even within the same architecture (
cf.
Tab.
2
). For instance, o4-mini-high typically outperforms o4-mini overall (LRL: 12.3 vs. 12.8), yet on the medium tier, o4-mini-high lags behind (40% vs. 52% accuracy).
This plateau effect demonstrates that, beyond a certain threshold, additional compute may yield diminishing, or even negative, returns in reasoning accuracy.

Scaling Model Parameters Translates to only Marginal Gains in Logical Reasoning.

Scaling model parameters across both open and closed checkpoints consistently results in diminishing returns when it comes to logical reasoning. For instance, Llama-3-70B surpasses its 8B counterpart by just 1%, while GPT-4.5-prev shows only a 2% advantage over GPT-4o. These marginal gains demonstrate that simply scaling model size does not guarantee corresponding advances in logical proficiency.

Computational Burden Increases with Task Complexity.

As we move towards more complex reasoning problems, we observe that reasoning models increase their spend tokens (Fig.
4
). The increased token usage translates into higher test-time computational and financial costs. Consequently, scaling LLM-based reasoning to harder tasks (via test-time compute) is fundamentally limited by these growing resource demands.

Logic-tuning with
SLR
Improves Reasoning.

Crucially, to test for systematic generalization to entirely novel tasks (and avoid memorization), we test our models on held-out data, ensuring that both input prompts and ground-truth rules are never seen during training. Via logic-tuning, our models not only outperform all base LLMs but also surpass some advanced reasoning models such as Gemini-2.0-flash-thinking, demonstrating that base language models can indeed acquire logical reasoning skills. Substantial performance gains are especially evident at lower difficulty tiers, as the accuracy on the “easy” tier increases from just 17% to 77%. However, improvements at the hardest tier are limited (e.g., accuracy rises only from 1% to 2%), suggesting that these challenges may exceed the learning capacity of the current model architecture. Overcoming this limitation may require architectural changes or the adoption of more sophisticated, search-based reasoning strategies.
Overall, our approach yields significant performance improvements while using only a fraction of the inference tokens, e.g.,
o1-mini
achieves only a marginally higher LRL (10.1 vs. 9.4,), but does so at the cost of 91 times more tokens (
cf.
Tab.
2
).

6
Conclusion and Future Direction

In this work, we introduced
SLR
, a principled and fully automated framework for synthesizing, training on, and evaluating logical reasoning benchmarks for LLMs. By leveraging symbolic synthesis and evaluation, our approach enables precise control over problem complexity and guarantees dataset novelty, circumvents issues of data leakage, and ambiguous grading. Using
SLR
, we developed
SLR-Bench
: a 20-level curriculum spanning over 19k tasks with progressively increasing logical complexity.

Our evaluation reveals that while current LLMs readily produce syntactically valid logic rules, robust logical reasoning remains elusive for conventional models, particularly as task complexity scales. Recent reasoning LLMs close some of the gap, but do so at large computational costs.
In contrast, we find that logic-tuning on
SLR-Bench
yields substantial improvements, achieving strong performance at a fraction of the inference costs. Furthermore, we hypothesize that combining the
SLR-Bench
curriculum with reinforcement learning using verifiable rewards (RLVR) could further enhance reasoning performance. We are actively investigating the integration of
SLR-Bench
into established training pipelines for both standard and reasoning LLMs, with a comprehensive evaluation of their impact reserved for future work.

Looking forward,
SLR
paves the way for several promising research directions: expanding into richer logical domains beyond the train scenario, supporting open-ended program synthesis and multi-rule induction, benchmarking neuro-symbolic and interactive reasoning systems, and moving toward higher-order tasks such as causal inference and theory of mind. Ultimately,
SLR
provides a flexible and extensible resource for probing and advancing the frontiers of logical reasoning in the next generation of language models.

7
Limitations

While
SLR
and
SLR-Bench
provide a scalable testbed for logical reasoning, there remain many opportunities for further enrichment. Although
SLR-Bench
currently applies
SLR
to the train domain with a single rule, the framework is readily extensible to multiple more complex, multi-rule reasoning scenarios and to entirely different domains. Our current focus on first-order, function-free Horn clauses enables systematic benchmark creation and evaluation; future instantiations could expand towards higher-order logic or probabilistic reasoning. While synthetic task generation comes with many benefits, such as ensuring novelty and precise control, it makes it difficult to incorporate real-world diversity and ambiguity. Our symbolic judge provides deterministic, discrete scoring and could potentially be enhanced to also recognize partial solutions, syntactically invalid rules, or natural language formulations. Overall, these points highlight the flexibility of our framework and outline promising directions for broadening its reach and impact.

Broader Impact

SLR
and
SLR-Bench
provide a scalable, reproducible foundation for evaluating and advancing logical reasoning in AI without relying on human annotation. By enabling robust measurement and targeted training, our framework supports progress in areas such as scientific discovery, program synthesis, and trustworthy AI. However, as LLMs acquire deeper logical competence, the risk of dual-use knowledge increases, enabling beneficial applications but also the potential for misuse, such as generating deceptive arguments or bypassing safety mechanisms. We urge responsible use and active consideration of ethical risks as these capabilities advance.
