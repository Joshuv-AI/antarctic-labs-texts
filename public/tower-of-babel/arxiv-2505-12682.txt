RoFL: Robust Fingerprinting of Language Models
Yun-Yun Tsai, Chuan Guo, Junfeng Yang, Laurens van der Maaten

Abstract
AI developers are releasing large language models (LLMs) under a variety of different licenses. Many of these licenses restrict the ways in which the models or their outputs may be used. This raises the question how license violations may be recognized. In particular, how can we identify that an API or product uses (an adapted version of) a particular LLM? We present a new method that enable model developers to perform such identification via fingerprints : statistical patterns that are unique to the developer’s model and robust to common alterations of that model. Our method permits model identification in a black-box setting using a limited number of queries, enabling identification of models that can only be accessed via an API or product. The fingerprints are non-invasive: our method does not require any changes to the model during training, hence by design, it does not impact model quality. Empirically, we find our method provides a high degree of robustness to common changes in the model or inference settings. In our experiments, it substantially outperforms prior art, including invasive methods that explicitly train watermarks into the model. Code is available at https://github.com/yunyuntsai/robust_llm_fingerprint



1
Introduction

The widespread commercial application of large language models (LLMs) has led to concerns about safeguarding the intellectual property (IP) of model developers.
A particular concern is
model theft
in which an adversary obtains access to a model and uses it in ways that violate the model’s license
(
OWASP 2025
)
.
It can be relatively easy for an adversary to steal a model, for example, when proprietary models are deployed on the premises of a customer or when model weights are released publicly under a bespoke license.
The substantial development costs of modern LLMs imply that adversaries may be incentivized to commit model theft.

Model theft can be difficult to detect.
Similarity detection approaches
(
Pei et al. 2021
;
Gabel et al. 2010
)
used to detect theft in traditional software do not work well for LLMs
(
Yao et al. 2024
)
, as these models consist of floating-point weights that can easily be adapted via finetuning, pruning, or quantization.
Moreover, an adversary can deploy a stolen model via an API or product, preventing the original model developer from accessing those weights.
Combatting model theft thus requires the development of model identification methods that are
robust
against common model changes and require solely
black-box
access to the model under investigation.

This paper introduces Robust Fingerprinting of Language models (
RoFL
), a new method that enables robust black-box identification of LLMs via fingerprints.

RoFL
fingerprints are statistical patterns in the output of an LLM that are
unique
to that model and robust against other common model changes (such as finetuning, pruning, or quantization).
They consist of a particular user prompt
x
and the corresponding model response
y
.
Fingerprints are unique (with high probability): given prompt
x
, all models of the same lineage consistently generate response
y
, whereas other models yield different responses.
As a result, the presence of these fingerprints in a model can be verified via black-box access to the model under a small number of queries.

RoFL
enables model developers to verify model ownership via standard cryptographic commitments: before deploying a model, the developer uses
RoFL
to generate a set of fingerprints, stores them securely, and publishes cryptographic hashes of the fingerprints.
In cases of suspected model theft, the model developer can first investigate the suspicious model by generating new fingerprints on-the-fly to query the API without exposing the secret fingerprints.
If this produces evidence of model theft, the developer can prove model ownership by revealing a previously committed fingerprint and demonstrating that the model under investigation contains this fingerprint.

While
RoFL
does not permit formal security proofs because it lacks a formal definition of robustness, our empirical security analyses on modern LLMs demonstrate that
RoFL
is effective under common changes to the model, including model finetuning, changes in the model’s system prompt, and quantization.

RoFL
also protects against
fingerprint race
attacks in which adversaries publish valid alternative fingerprints after model release in an attempt to claim the model ownership.

2
Model Identification with
RoFL

We first introduce the threat model we consider in this study, present an overview of the general
RoFL
scheme for model identification, and perform a security analysis of that scheme.

2.1
Threat Model

We assume a scenario in which an adversary aims to steal an LLM for economic gain, for example, by selling products based on the stolen model that violate the original model developer’s license terms.
To secure its economic gain, the adversary seeks to hide the model theft from the model developer.
In order for an attack to bring economic value to the adversary, the attack must: (1) require limited resources to be executed and (2) not alter the original model so much that its value is destroyed.
Based on this scenario, we identify four main limitations of the adversary:

1.

Limited resources.
The adversary cannot use compute resources that match or exceed those used to train the original model.
Such attacks do not have economic value for the adversary, as they could have simply trained their own model.

2.

Model training integrity.
The adversary cannot tamper with the (pre)-training process of the original model.
They cannot alter the training data, the training algorithm, or the training infrastructure.

3.

Common model changes.
The adversary is restricted to common model changes that are designed to maintain or increase the economic value of the model.
These changes include supervised fine-tuning, low-rank adaptation (LoRA), system prompt engineering, quantization, and tuning of inference hyperparameters (e.g., for specific productions) by an adversary.
It is trivial to remove fingerprints from a model – for example, by randomly re-initializing all the model weights – but such model changes would destroy the economic value of the stolen model.

4.

Unfiltered black-box access.
The adversary provides black-box access to the actual LLM, without applying additional pre-processing filters to the input or post-processing filters to the output.

Admittedly, this threat model lacks a formal definition of what model changes are permitted.
As a result,
RoFL
does not permit formal theoretical proofs of security.

2.2
Overview of the Scheme

We denote the original LLM by
\mathcal{M}_{\theta}
, where
\theta
represents the model weights.
We denote adapted versions of this LLM by
\mathcal{M}_{\theta_{u}}
.
The goal of model identification is to verify that
\mathcal{M}_{\theta_{u}}
is, indeed, an adapted version of
\mathcal{M}_{\theta}
.
Our model identification scheme involves two functions: (1) a function,
\gen(\mathcal{M}_{\theta})=F
, that generates a fingerprint for model
\mathcal{M}_{\theta}
; and (2) a function,
\verify(F,\mathcal{M})
, that decides whether or not
F
is a fingerprint of model
\mathcal{M}
.
The first function is used to generate and (cryptographically) commit to fingerprints prior to the release of the original model, whereas the second function is used to investigate suspected model theft after model release.
In order to create an effective model identification scheme, these two functions must have the following properties:

1.

Effective.
Model identification using
\verify(F,\mathcal{M}_{\theta})
should succeed with high probability. (See Table
2
)

2.

Robust.

Model identification should be robust under common model changes and work for all models in a lineage with high probability, that is,
\forall{\mathcal{M}_{\theta_{u}}}:\verify(F,\mathcal{M}_{\theta})\implies\verify(F,\mathcal{M}_{\theta_{u}})
. (See Table
3
)

3.

Unique
: Fingerprints from different model lineages should be distinguishable with high probability, that is,

\verify(F,\mathcal{M}_{\theta})\implies\neg\verify(F,\mathcal{M}_{\omega})
when
\theta\neq\omega
. (See Table
4
)

4.

Unforgeable.
Without access to
\mathcal{M}_{\theta}
or its adaptions, it should be difficult for an attacker to generate
F^{\prime}
such that
\verify(F^{\prime},\mathcal{M}_{\theta})
accepts. See Appendix
A.6
.

5.

Black-box.
To facilitate investigation of models deployed in products,
\verify(F,\mathcal{M}_{\theta_{u}})
can query
\mathcal{M}_{\theta_{u}}
but not access
\mathcal{M}_{\theta_{u}}
in any other way.

6.

Dense.
To facilitate commitment to multiple fingerprints (as some may need to be revealed later), repeated invocation of
\gen(\mathcal{M}_{\theta})
should produce sufficiently many different fingerprints. See Appendix
A.7
.

7.

Harmless.
Invoking
\gen(\mathcal{M}_{\theta})
should not degrade the quality of the model.

The overall
RoFL
scheme works as follows.
Prior to the release of LLM
\mathcal{M}_{\theta}
, the model developer generates a set of fingerprints by repeatedly invoking
\gen(\mathcal{M}_{\theta})
, and stores the resulting fingerprints securely.
She then computes hiding and binding commitments to these fingerprints by invoking a collision-resistant and preimage-resistant hash function, such as SHA-256, and publishes the commitments on an immutable public ledger (e.g., a permissionless blockchain).

After the model release, the model developer can investigate whether model
\mathcal{M}_{\theta_{u}}
is derived from
\mathcal{M}_{\theta}
by generating a new fingerprint
F^{\prime}
using
\gen(\mathcal{M}_{\theta})
and checking whether or not
\verify(F^{\prime},\mathcal{M}_{\theta_{u}})
accepts.
If this investigation provides evidence for model theft, she can reveal one of the previously committed fingerprints
F
and prove model ownership by demonstrating that
\verify(F,\mathcal{M}_{\theta_{u}})
accepts.
It is important that the initial investigation is performed with a new fingerprint
F^{\prime}
, as querying the suspicious model with a committed fingerprint risks leaking that fingerprint to the model thief (who could then adapt the stolen model to reject that fingerprint).

2.3
Security Analysis

RoFL
provides security against four main types of attacks:

1.

White-box theft.
An adversary provides access to the model weights of a stolen model or its adaptation, claiming the model as her own. As explained above, the developer of the original model can use
\verify(\cdot)
to prove the model theft.

2.

Black-box theft.
An adversary provides query access to a stolen model via an API or other product service. As described above, the model developer can use
\verify(\cdot)
to gather evidence of the theft and prove model ownership.

3.

Fingerprint race.
An adversary publishes commitments to valid fingerprints of a stolen model. The original model developer can demonstrate that her previously committed fingerprints have earlier timestamps in the public ledger than the adversary’s, thereby proving ownership.

4.

Fingerprint spray.
An adversary commits random fingerprints or fingerprints from other model lineages to the public ledger, attempting to falsely claim ownership of future models. This attack has a low probability of success, as fingerprints are unforgeable and unique to a model’s lineage.

RoFL
does
not
provide security against the following five attacks:

1.

Front-running.
As in data poisoning, an adversary plants malicious data in the public domain, hoping it will be absorbed into the training data of a model, thereby creating predictable fingerprints. The adversary can commit to these fingerprints first and falsely claim model ownership. While a full defense is out of scope, we show preliminary results in Appendix
A.2
.

2.

Insider theft.
An adversary gains unauthorized access to the original model developer’s infrastructure (for example, through compromised networks or employee access control) and uses it to commit fingerprints first.

3.

Model distillation.
An adversary reconstructs the model by training on query-response pairs from the original model. We note that such distillation likely requires similar amounts of computation as the training of the original model.

4.

Adversarial model changes.
An adversary drastically modifies a stolen model, trying to erase most or all existing fingerprints. This attack is out-of-scope because it requires substantial resources and/or leads to a significant degradation in model quality.

5.

Pre- and post-filtering.
Filtering risks rejecting legitimate queries and responses, potentially degrading the economic value of the model significantly. See preliminary analysis in Appendix
A.3
. We note that no existing work on model watermarking or fingerprinting has been designed to be secure against filtering attacks.

3
Robust Fingerprinting in
RoFL

Our model identification scheme works with any fingerprinting method that meets the requirements described above.
We will now describe a practical fingerprinting method that satisfies these properties.

. Prompts are selected by discrete optimization of unlikely token sequences. Corresponding responses are found via greedy decoding. As there are many unlikely token sequences, prompts are difficult to find even for an adversary that knows

Our fingerprints consist of a special prompt
x
and a corresponding response
y
.
Given prompt
x
, all models of the same lineage consistently generate response
y
, whereas other models produce different responses.
Verification of such fingerprints
(x,y)
is straightforward, as we can confirm whether or not
\mathcal{M}_{\theta_{u}}(x)=y
.
Fingerprint generation is more complex. It requires producing prompts
x
that consistently lead to the same response
y
, even when the model is finetuned, the system prompt is changed, or inference hyperparameters are altered.

3.1
Fingerprints Generation

Fingerprint generation is performed without changing the model itself by identifying statistical patterns in model
\mathcal{M}_{\theta}
itself.
Recall that we want these patterns to be unique, robust, and unforgeable.
We obtain these properties by selecting a fingerprint prompt
x
that: (1) is an
unlikely
token sequence and (2) very
reliably
leads to the same response
y
.
We do so using the following three-step procedure:

1.

Prompt initialization.
We sample an initial prompt
x\textquoteright
by (i) sampling the first
l
tokens uniformly at random and (ii) performing bottom-k sampling from model
\mathcal{M}
for the remaining tokens.

2.

Response generation.
We produce the corresponding response
y
by greedy decoding (that is, top-1 sampling) given the system prompt and the fingerprint prompt
x\textquoteright
.

3.

Prompt optimization.
We perform discrete optimization over fingerprint prompts
x
to maximize the (log)likelihood of model
\mathcal{M}_{\theta}
with system prompt
h
producing the response
y
. We initialize the optimization with
x\textquoteright
, and perform the optimization using greedy coordinate gradient (GCG;
Zou et al. 2023
) optimization. The optimization maximizes the following objective:

\max_{x}\quad\log p_{\mathcal{M}_{\theta}}\left(y|h,x\right),

(1)

where
p_{\mathcal{M}_{\theta}}
is the model distribution,
y
is the (fixed) fingerprint response,
h
is the (fixed) system prompt, and
x
is the fingerprint prompt we aim to find.

Because we initialize part of the fingerprint prompt randomly from a combinatorially large number of options, we obtain a different fingerprint pair
(x,y)
every time we perform this procedure.
Hence, we can repeat the procedure multiple times to generate multiple independent fingerprints, so the fingerprints are
dense
.
Responses to unlikely token sequences do not appear in training data, which makes them an artifact of the specific model training that is likely to be
unique
.
Moreover, their absence in natural training data also makes them unlikely to change under common model changes, so the resulting fingerprints are likely to be
robust
.

Multi-task prompt optimization.
We can further increase the robustness of
RoFL
by summing the log-likelihood over multiple derivative models and multiple system prompts, and performing discrete optimization over fingerprint prompts
x
to maximize the resulting sum.
That is, we optimize:

\max_{x}\quad\sum_{\mathcal{M}^{\prime}\in\{\mathcal{M}^{\prime}_{1},\dots,\mathcal{M}^{\prime}_{M}\}}\sum_{h\in\mathcal{H}}\log p_{\mathcal{M}^{\prime}}\left(y|h,x\right),

(2)

where
\mathcal{M}^{\prime}_{m}
is a model that was obtained by adapting
\mathcal{M}_{\theta}
and
\mathcal{H}
is a set of system prompts.
This type of multi-task prompt optimization leads us to identify fingerprint pairs that are resilient under natural model and system prompt changes.
We perform experiments with both single-task and multi-task versions of
RoFL
.

Fingerprint Example.
The resulting
RoFL
fingerprints are resilient to changes in the system prompt.
Figure
2
shows an example where the
fingerprint prompt
leads to the same
fingerprint response
irrespective of whether a
system prompt
is provided.

3.2
Practical Considerations

Multi-trial strategy.

In the original GCG algorithm, the optimization process stops either when the fingerprint proves successful
on the model that we use to learn the fingerprint or when reaching the maximum learning epoch.
We find that the fingerprint learned by a single model may lack transferability to downstream models if we stop the optimization at the first-trial success. We hypothesize that the token replacement strategy of GCG, which leverages gradients on tokens to find a set of promising
candidate tokens, is suboptimal.
In particular, the replacement randomly selects
B
tokens from the candidate set and chooses the one with the lowest loss from this subset.
Thus, the first-trial success sample is composed of some optimal tokens from a subset of candidate sets.
To explore more possible sets of tokens for replacement, we adopt a multi-trial strategy, where the fingerprint optimization does not stop until an
n
-trial success. We set
n
to 20 in our experiments.

Uniqueness checking in fingerprint verification.
An adversary may attempt to find universal fingerprints that match multiple model lineages, e.g. using the aforementioned multi-task optimization on many unrelated models.
Thus, our fingerprinting verification also checks that the fingerprint is unique by matching it against irrelevant models and confirming rejections.

RoFL

We also perform a set of ablation experiments to study which components of
RoFL

Baselines.
We consider the following baseline methods in our experiments.

Variants of
RoFL
:
Although our fingerprinting method focuses on learning suffix strings, we first compare it with several GCG-based fingerprint learning variants. The
GCG

Base-only

Base + 1 task

Base + 2 tasks
, we learn the fingerprint with one base model + two fine-tuned models.

Watermarking:
Besides the GCG-based fingerprint baselines, we compare our method with two fingerprint training variants, including full parameter fine-tuning
(IF-SFT)

(
Xu et al. 2024

and fine-tuning with embedding layer
(IF-Emb)

However, full-finetuning all model parameters with SFT overfits with the fingerprint pairs and makes parameters shift hugely, which can hurt the original performance on standard benchmark. As SFT leads to a huge parameter shift, which might lead to performance degradation, we can further limit the learnable parameters
(
Kurita et al. 2020
)
to the embedding layers.
Yang et al. 2021
shows the embedding layers are relatively less affected by fine-tuning than other parameters at higher network layers.

Results

\bullet
Evaluation on Effectiveness of Fingerprinting
We assess four variants of GCG-based fingerprinting and two variants of IF in terms of Effectiveness and Persistence.

Related Work

LLM watermarking

The predominant strategy for IP protection is model watermarking in the LLM field. Recently,
Kirchenbauer et al. 2024
presented the first watermarking scheme for white-box models. By randomly selecting a set of greenlist tokens from the model vocabulary and encouraging the use of these tokens at each generation step, the distribution of the generated output text changes. The watermark can be further detected by these distribution changes.

Aaronson 2022
have described a watermarking technique using a pseudo-random cryptographic function. However, their methods can introduce bias to the output, leading to performance degradation. Several concurrent works

(
Kuditipudi et al. 2024
;
Christ et al. 2023
;
Yang et al. 2023
;
Hu et al. 2023
)
proposed to reduce the bias in watermarking.
Zhao et al. 2023
proposed a watermarking method that can avoid model stealing by distillation.

Gu et al. 2023a
inserts backdoor triggers to model using some rare words. They adopt a
multi-task learning loss function to share a common feature representation of backdoor triggers with multiple downstream tasks. By doing so, the backdoor triggers can be difficult to remove by downstream fine-tuning. Double-I
(
Wang et al. 2024
)
proposes backdoor watermarking with triggers in the instruction and input.
Another branch of watermarking aims to detect whether LLM output is used as training data.
Sander et al. 2024
shows the radioactivity of the watermarked text, where the fine-tuned models training with a small proportion (5%) of watermarked texts can still be detected and trace the source.

Gu et al. 2023b
distills the watermark with the model weights by training a student model to behave like the teacher model.

LLM fingerprinting

In contrast to watermarking, which changes the distribution of output generation, fingerprinting extracts special properties from models.
Several works have studied how to fingerprint pre-trained language model by learning pairs of fingerprint triggers and targets.

Xu et al. 2024
propose to use instructional fine-tuning to learn fingerprint pairs into the models. While training the fingerprint, they integrate
an additional adapter with the model, and
requires to have white-box access to load the adapter with parameters of the suspect model and verify the presence of the fingerprint.
The fingerprint pairs are manually designed using multiple languages (e.g., Russian, Chinese, Japanese, etc).

Zeng et al. 2024
proposed to learn a human-readable fingerprint for LLMs. They observe some of the weights in LLMs remain stable during fine-tuning and those invariant terms can be leveraged to identify the base models. Thus, they convert invariant terms in the model to the image through convolutional image encoder and evaluate the similarity between the images.
Closer to our work,
one study on learning an Adversarial Example (AE) sets to fingerprint the model
(
Jin et al. 2024
)
. The fingerprinting operates by appending and optimizing a suffix with questions such that the answer can be triggered by the suffix. For example, the question is "Where does the sun rise?", and the answer is "North". The random suffix string is appended with the question during the optimization. The ownership verification is based on testing fingerprint response rate on suspect models that are derived from the base model. The average fingerprint response rate of suspect models will be higher than those irrelevant models. However, the AE set is predefined, which is possible the attacker can easily guess the fingerprint.

We discover several main challenges in existing prior works
(
Xu et al. 2024
)
1)
Fingerprint learning with SFT: Memorized fingerprints do not persist after user fine-tuning. 2) The generation quality drops on the based model. 3) Design of the fingerprint pattern: Fingerprints are constructed manually. 4) The fingerprint can be leaked due to the model over-memorizing them.

7
Conclusion

In our work, we present a novel fingerprint method for large language model’s IP protection. Our method learns to extract statistical patterns from base model and seeks to find an unique mapping between fingerprint prompt and target under a rare token distribution, such that the fingerprint is stealthy on any derived models. Different from prior SOTA watermarking method, our method does not interfere with model training, hence by design, it is harmless, stealthy, and robust on any downstream finetuning. Our experiments evaluate the fingerprint on multiple training variants and prompt templates for derived models, validating the effectiveness and robustness of our method.
In our research, we highlight the necessity of fingerprint and show challenges of current SOTA, that is, the model developer needs to in control the data and training environment for LLMs.
Future discussion can focus on how to fingerprint LLMs with web-scale model training.

Impact Statements

This paper presents work whose goal is to advance the field of fingerprinting LLM. Technically, RoFL serves as a robust method to identify and track the origin of specific models involved in generating particular texts. This capability enhances models’ transparency, aids in attributing content to its source, and can deter the misuse of LLMs.

Ethically, fingerprinting LLM might raise concerns about surveillance and privacy. It requires carefully weighing the need for security and accountability against the risk of violating users’ privacy rights.
By allowing the identification of downstream models’ origins, there is a risk that this capability could be exploited for surveillance and monitoring, potentially resulting in limiting the right of users on using public models or the suppression of free speech.

Future societal consequences of deploying fingerprints with LLMs hinge on regulatory and governance frameworks. People need to have clear policies that define acceptable uses of LLMs and further recognize which form of fingerprinting can be used for model verification. We believe this technology can foster a more trustworthy digital communication environment, reducing the prevalence of fake news and enhancing the credibility of LLM-generated content.

A.2
Front-running Attack Analysis

In our threat model, we assumed the adversary does not have any influence over the model development process. In this section, we relax this assumption and consider a
front-running attack
based on data poisoning. Since LLMs are typically trained on web-crawled data, the attacker may inject fingerprints into the model in the following manner: 1) The attacker constructs a trigger-fingerprint pair and posts it on a public web domain. 2) The attacker commits this trigger-fingerprint pair according to the procedure described in Sec.
3
. 3) The LLM trainer crawls the web and constructs a training dataset that contains the trigger-fingerprint pair, and trains the model on this dataset. 4) When the LLM is released, the attacker claims ownership over the model by verifying the committed fingerprint according to Sec.
3
. This fingerprint has precedence over any fingerprint constructed by our method post-training, and thus the attacker is established as the model owner.

The front-running attack exploits the known data poisoning vulnerability of web-scale model training
(
Carlini et al. 2024
)
, and can be plausibly executed against our fingerprinting protocol.
To understand the threat of this front-running attack, we ask how much training data does attacker need to control to successfully execute the attack?
We simulate such an attack by fine-tuning the LLM on a fixed trigger-fingerprint pair until the LLM achieves 100% TPR on the injected fingerprint. Since frontier LLMs often make only a single pass over its training data, the number of steps required to achieve 100% TPR can be thought of as a lower bound for the number of training samples the attacker needs to control. Figure
7
shows the number of steps required as a function of the length of the fingerprint. As the length of fingerprint increases, the attacker needs to control a larger number of training samples, although this number is relatively low even for length 54 fingerprints. Our experiment suggests that to prevent this front-running attack, the model trainer should select longer fingerprints and apply strong data de-duplication to reduce the attacker’s control over training data.

:
Analysis of the front-running attack. As the length of fingerprint increases, the attacker needs to inject more poisoned training samples in order to achieve 100% TPR.

A.6
Unforgeable Property

We consider two strategies that an adversary uses to forge fingerprints. First, she can learn fingerprints from other model lineages and hope that they transfer to a target model. For instance, she can extract a likely query-response pair from the Common Crawl dataset that may match many model lineages. As §
4
demonstrates,
RoFL
learns unique fingerprints for a model lineage. In fingerprint verification,
RoFL
checks for uniqueness by querying irrelevant models and rejects the fingerprint if it matches them.

Second, the adversary can generate random query-response pairs and hope that they coincide with a target model. We show that analytically this is is extremely unlikely. Suppose the randomly generated query-response pair is
x,y^{\prime}
and the model’s true response is
y
. Since there is only one valid
y
for any given
x
, the probability for
y^{\prime}
to be the same as
y
is
\frac{1}{\mathcal{\mathcal{D}}^{|y|}}
if the mapping from
x
to
y
is sufficiently random, where the length of
y
is
|y|
and the domain size of each token in
y
is
\mathcal{D}
. In our implementation of
RoFL
,
\mathcal{D}
is 2,000 and
|y|
is 9, yielding a probability of
1.95e-30
.
