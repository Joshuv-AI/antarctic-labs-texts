ScrapeGraphAI-100k: A Large-Scale Dataset for LLM-Based Web Information Extraction
William Brach, Francesco Zuppichini, Marco Vinciguerra, Lorenzo Padoan

Abstract
. The use of large language models for web information extraction is becoming increasingly fundamental to modern web information retrieval pipelines. However, existing datasets tend to be small, synthetic or text-only, failing to capture the structural context of the web. We introduce ScrapeGraphAI-100k, a large-scale dataset comprising real-world LLM extraction events, collected via opt-in ScrapeGraphAI telemetry during Q2 and Q3 of 2025. Starting from 9M events, we deduplicate and balance by schema to produce 93,695 examples spanning diverse domains and languages. Each instance includes Markdown content, a prompt, a JSON schema, the LLM response, and complexity/validation metadata. We characterize the dataset’s structural diversity and its failure modes as schema complexity increases. We also provide a fine-tuning experiment showing that a small language model (1.7B) trained on a subset narrows the gap to larger baselines (30B), underscoring the dataset’s utility for efficient extraction. ScrapeGraphAI-100k enables fine-tuning small models, benchmarking structured extraction, and studying schema induction for web IR indexing, and is publicly available on HuggingFace .



1.
Introduction

Large language models are increasingly used to extract structured data from the web, feeding downstream information retrieval (IR) tasks such as vertical search, structured indexing, and knowledge base construction. Yet the community still lacks a realistic dataset that captures the full extraction life cycle: web content, natural language prompts, target schemas, and model outputs at the scale and diversity required for robust analysis.
This work sits at the intersection of two sub-fields that will remain central to IR in the next 3–5 years: (i) web content extraction, which seeks to isolate meaningful text from noisy HTML, and (ii) schema-constrained information extraction, which converts content into structured records for retrieval and analytics. Existing resources typically cover only one side of this pipeline, making it difficult to study end-to-end extraction quality, failure modes, or downstream impact.
Current datasets are either small, synthetic, or text-only; many are English-only and lack explicit schema complexity metadata. Most importantly, they do not include real prompts, real schemas, and real model outputs from production usage. This limits our ability to analyze how extraction reliability changes with schema complexity, how small models can be fine-tuned effectively, or what failure patterns emerge in practice.
To address this gap, we introduce ScrapeGraphAI-100k, a dataset derived from 9M opt-in PostHog telemetry events collected during Q2–Q3 2025. This is not synthetic data: it contains real prompts, real schemas, real web content, and real LLM responses from real usage. After cleaning, deduplication, and balancing, we release 93,695 examples across domains and languages with validated outputs and fine-grained complexity metadata. The dataset enables future research on questions such as how schema complexity affects reliability, how small models can be adapted for structured extraction, and how extraction errors propagate to retrieval pipelines.

We make the following contributions:

•

We release ScrapeGraphAI-100k, a large-scale, real-world dataset for LLM-based web extraction, containing paired content, prompts, schemas, and model outputs.

•

We provide schema-centric diagnostics (validation labels and structural complexity metadata) to support failure analysis under increasing task complexity.

•

We report baseline fine-tuning results showing that a 1.7B model can approach much larger models on structural extraction metrics.

2.
Related work

Research on web data processing spans three interconnected areas: large-scale corpora for pre-training, content extraction, and structured information extraction. We review each in turn to motivate the gap that ScrapeGraphAI-100k fills.

Web-Scale Corpora.

Massive datasets derived from Common Crawl
(
2
)
, such as C4
(
20
)
and FineWeb
(
18
)
, provide the token volume that powers modern LLMs. While the Information Retrieval community has moved toward hybrid resources like Istella22
(
3
)
—combining raw text with query-document feature vectors—the web extraction domain lacks a similar unified benchmark. Pre-training corpora systematically strip HTML tags, visual layouts, and hierarchical metadata, discarding the very signals needed for structured schema extraction. The result is a data ecosystem rich in volume but poor in structural ground truth.

Content Extraction.

To recover some of this lost context, the community has developed benchmarks for Web Content Extraction—isolating the main content of a page from boilerplate (navigation menus, advertisements). Evaluation was historically fragmented until Bevendorff et al.
(
1
)
consolidated eight human-labeled resources and evaluated 14 extraction systems, finding that heuristic methods often remain competitive with pre-transformer baselines. More recently, Liu et al.
(
11
)
introduced WebMainBench, a benchmark of over 7,800 human-annotated pages for token-efficient main-content identification. However, WebMainBench targets the HTML-to-text task exclusively, leaving the downstream problem of mapping content to structured schemas unaddressed.

Structured Data Extraction.

Unlike content extraction, structured extraction maps web segments to specific schema fields (e.g., price, author, date). The SWDE dataset
(
5
)
and OpenCeres
(
13
)
have served as standard benchmarks, but both are small-scale and do not reflect modern dynamic DOM structures. CrossNER
(
12
)
addresses domain adaptation with a fully-labeled benchmark spanning five domains, yet, like its predecessors, operates on clean text rather than raw HTML. Tan et al. validated the cost of this simplification with HtmlRAG
(
23
)
, showing that plain-text conversion strips essential semantic markers, tables, headings, hierarchies,that are vital for deep document understanding. Existing structured extraction benchmarks therefore remain either too small, too narrow, or disconnected from the HTML source that real-world systems must process.

Multimodal and Generative Approaches.

The rise of vision-language models has expanded the extraction landscape: LangChain’s agentic workflows
(
10
)
and Image2Struct
(
22
)
offer new pathways via tool-use orchestration and visual reconstruction, respectively. However, by relying on flat text or screenshots, these methods bypass the underlying DOM tree, missing the structural signals critical for complex live web pages.

In summary, existing resources address isolated slices of the web extraction pipeline: pre-training corpora provide scale but lack structural ground truth; content extraction benchmarks evaluate HTML-to-text but not schema extraction; structured extraction datasets are small-scale and outdated; and generative benchmarks operate on clean text rather than raw HTML. To the best of our knowledge, ScrapeGraphAI-100k is the large-scale dataset that unifies the evaluation of LLM-based web information extraction by providing: (1) Markdown content from real-world web pages, (2) natural-language extraction prompts, (3) target JSON schemas of varying complexity, and (4) ground-truth extraction results validated against these schemas.

3.1.
Data Source and Collection

Data collection was facilitated through PostHog
1
1

1

https://posthog.com/
, an analytics platform integrated into the ScrapeGraphAI library
(
19
)
. The raw dataset contains
\sim
9 million opt-in telemetry events collected in Q2-Q3 2025; users explicitly consented to share anonymized execution data to support the maintenance and development of the open-source project. PostHog is configured to avoid PII collection, and telemetry excludes user identifiers or other personal data. This approach allowed us to aggregate real-world usage patterns ranging from simple testing scripts (e.g., price monitoring, real estate scraping, and market research,
\sim
50 bytes) to complex production pipelines (e.g., full articles with metadata,
\sim
50 KB) without relying on synthetic data generation. Each event encapsulates the full extraction lifecycle: the input prompt, the target JSON schema, the source content, the specific LLM utilized, and the generated response.

3.2.
Data Processing

The raw telemetry of
\sim
9 million events contained redundancy, noise, and extreme class imbalance. We implemented a multi-stage cleaning pipeline to produce a high-quality dataset suitable for training and benchmarking.

Flattening and Validation.

Each event was flattened into a structure containing the source URL, user-provided JSON schema, website content in Markdown, and the LLM-generated response. We validated every response against its corresponding schema using the jsonschema-rs library.
2
2

2

https://github.com/Stranger6667/jsonschema
The average validity rate across the raw corpus was 93%, invalid responses are retained in the final dataset with
response_is_valid=false
, enabling research on extraction failure modes.

Complexity Metrics.

For each schema, we computed structural complexity metrics following the SLOT framework
(
26
)
: schema depth, key count, element count, cyclomatic complexity, and a composite complexity score. These metrics quantify extraction task difficulty and are detailed in Section
3.3
.

Balancing and Deduplication.

The raw dataset exhibited extreme class imbalance: two schemas targeting high-traffic Chinese e-commerce sites accounted for nearly 5 million of the 9 million events. To address this, we grouped events by a SHA256 hash of their JSON schema and applied a sampling strategy retaining a maximum of 5 examples per unique schema. This threshold was empirically tuned to balance final dataset size against schema coverage. To ensure diversity, we required that selected examples originate from distinct root domains preventing over-representation of any single website. Following these steps, the dataset was reduced from 9 million to 93,695 balanced examples.

Schema Complexity

Schema complexity in ScrapeGraphAI-100k reflects real-world usage patterns (Table
2
,
Figure
1
). Schema depth clusters tightly around 5 levels (median=5,
\sigma
=0.74), ranging from flat structures (depth 2) to deeply nested hierarchies (depth 9). Key counts show greater variance: the median schema contains 37 keys, but the distribution is heavily right-skewed (max 3,060 keys,
\sigma
=42.10), reflecting the gap between routine extractions (product details, article metadata) and complex multi-entity tasks. The composite complexity score (median=131.3,
\sigma
=123.78) reveals two distinct populations. Approximately 90% of schemas cluster around common extraction templates, while the remaining 10% reach complexity scores up to 7,935 representing the challenging edge cases where LLM extraction systems are most likely to fail. This bimodal distribution enables both robust baseline training on routine schemas and stress-testing on structurally demanding tasks.

Response Characteristics

Response sizes follow a heavy-tailed distribution, ranging from under 1 KB to nearly 1 MB (Figure
3
). The majority of responses are smaller than 100 KB, with a median of around 15 KB. Smaller responses tend to represent straightforward extractions, such as prices or contact details, while larger responses correspond to more complex tasks, such as full articles with metadata or detailed product listings. The wide range of responses, from 50-byte price lookups to 50 KB article extracts, reflects the dataset’s diverse use cases.

Model Distribution and Validation

GPT-4o-mini dominates the dataset (87.4% of requests), followed by GPT-4o (3.6%) and GPT-4.1-mini (1.0%), with the remainder distributed across Gemini, DeepSeek, Llama, and others. This skewed distribution reflects real-world adoption patterns but represents a dataset limitation: extraction patterns and failure modes may be biased toward GPT-4o-mini’s behavior. We observe consistent complexity-driven failure patterns (Figure
2
). Validation rates remain high (
\sim
95%) for moderate schemas but exhibit sharp, non-linear declines at specific thresholds: depth
\geq
7 drops validation from 98% to 20%; key count
\geq
200 falls to
\sim
65%; complexity score >1,000 drops to
\sim
55%. These thresholds suggest that LLMs handle incremental complexity gracefully until hitting structural limits where failures accelerate rapidly.

5.
Preliminary Experiments

To demonstrate the utility of ScrapeGraphAI-100k, we evaluate its effectiveness in a knowledge distillation framework. We show that a small language model (Qwen3-1.7B
(
25
)
), can achieve extraction accuracy competitive with significantly larger models when fine-tuned on high-quality synthetic labels derived from our dataset. This enables cost-effective, privacy-preserving, on-premises extraction by mimicking complex real-world extraction patterns.

Experimental Setup

We curate a training-efficient subset from ScrapeGraphAI-100k, filtering for schema length (
\leq
10k chars), source content (
\leq
50k chars), and response size (
\leq
10k chars). To ensure 100% label consistency and correctness, we performed a re-generation pass using GPT-5-nano to produce the target extraction outputs for all filtered samples. This "teacher" model provides a gold-standard reference for the SLM to emulate. Large content fields were processed using a 4,096-token sliding window to maintain context without exceeding the model’s primary attention window. This version of dataset is published via Huggingface
3
3

3

https://huggingface.co/datasets/scrapegraphai/scrapegraph-100k-finetuning
for further research.

Training Methodology

Fine-tuning was conducted using QLoRA
(
4
)
with 4-bit quantization. We applied LoRA
(
6
)
adapters (rank
r=16
) to all linear projections within the attention and MLP blocks. We utilized a learning rate of
10^{-4}
with a cosine decay scheduler over 2 epochs on a single NVIDIA A100 (80GB). We specifically contrast standard fine-tuning against completion-only loss (response-only training), where the gradient is computed exclusively on the assistant’s output tokens to prioritize structural accuracy in the JSON response.

Evaluation

We evaluate extraction quality across complementary dimensions using vLLM
(
9
)
with greedy decoding. Structural validity metrics assess whether outputs are well-formed: is_valid_json checks JSON parseability, while is_schema_compliant verifies conformance to the target schema. Key extraction metrics (precision, recall, F1) measure structural accuracy by comparing flattened JSON keys using dot-notation paths with [*] wildcards for arrays. Value extraction is captured by value_score, a type-aware metric averaging exact match for booleans/numbers, set equality for arrays, and sentence-level BLEU
(
17
)
for strings. Finally, overall_bleu on serialized JSON provides a holistic quality measure. Samples exceeding the 8192-token context limit were excluded. Code for evaluation and fine-tuning is available at
https://github.com/ScrapeGraphAI/scrapegraph-100k-paper
.

Results

Table
4
reports per-metric results, while Figure
4
visualizes the overall BLEU scaling trend. The 30B model delivers the strongest overall validity and content scores (e.g., 0.9913 valid JSON, 0.8915 key F1), serving as a high-capacity reference point. Our fine-tuned 1.7B remains close on structural accuracy (key F1 0.8866, within 0.005 of 30B) and surpasses the 4B baseline on all key-based metrics, showing that ScrapeGraphAI-100k can narrow the gap between small and large models.

Response-only training consistently improves over the base 1.7B across all metrics. The most considerable improvement is seen in schema compliance, rising from 0.7954 to 0.9167 (an absolute increase of 15%), suggesting that optimising for output generation helps models internalise schema constraints. Extra key generation drops from 2.64 to 0.33 per sample, and even undercuts the 30B baseline (0.5679), indicating that dataset-specific fine-tuning reduces hallucinated fields beyond what scale alone provides. Despite this, a notable gap remains in value extraction. While the fine-tuned model achieves strong structural accuracy (89% key F1), the value score of 0.4624 shows that correctly identifying which fields to extract is easier than accurately extracting what those fields contain. This structural-semantic gap—models producing correct JSON skeletons with imprecise values—represents an open challenge for extraction systems.

6.
Utility and Research Opportunities

ScrapeGraphAI-100k facilitates research across four interconnected areas of LLM-based web information extraction. These opportunities leverage the dataset’s unique combination of scale, structural metadata, and real-world provenance.

Efficient Extraction with Small Language Models

The dataset enables cost-effective extraction by supporting fine-tuning of Small Language Models to match proprietary baselines. With 93,695 diverse examples, researchers can apply Parameter-Efficient Fine-Tuning (PEFT) techniques
(
27
)
to train compact models like Llama-3.1-8B or Qwen3-1.7B that achieve competitive accuracy at a fraction of inference cost. The distribution—90% routine schemas suitable for robust training, 10% complex edge cases for stress-testing supports development of privacy-preserving, on-premises extraction systems that address the cost-accuracy trade-off central to production pipelines.

Benchmarking Extraction Systems

ScrapeGraphAI-100k provides a standardized testbed for evaluating extraction robustness across varying task complexity. The rich structural metadata (depth, key count, cyclomatic complexity) enables stratified evaluation that moves beyond aggregate accuracy to identify specific thresholds where systems fail. For example, researchers can measure how extraction quality degrades as schema depth exceeds 7 levels or key count surpasses 200—the empirical breakpoints observed in Section
3.3
. This granular analysis supports development of adaptive systems that route tasks based on predicted difficulty
(
16
)
.

Failure Mode Analysis

The dataset’s retention of invalid responses (
response_is_valid=false
) creates opportunities for systematic failure analysis. Researchers can distinguish between syntactic errors (malformed JSON), structural errors (missing required keys), and semantic errors (valid JSON with incorrect values). The correlation between complexity metrics and validation rates (Figure
2
) provides a foundation for predicting extraction failures before execution and developing targeted interventions
(
8
;
14
)
.

Schema Induction

By pairing raw web content with successful extraction schemas, ScrapeGraphAI-100k enables research on automatic schema suggestion. Given unstructured text, can models predict the most suitable JSON schema for extraction? This “schema-from-content” task
(
24
)
has practical applications in bootstrapping extraction pipelines for new domains without manual schema design. The dataset’s coverage of 18,000+ unique schemas across diverse domains provides training signal for learning domain-independent schema patterns.

8.
Ethical Considerations

Data Collection and Consent.

The ScrapeGraphAI-100k dataset was constructed exclusively from telemetry data contributed by users who explicitly opted into data collection by setting a configuration flag in the ScrapeGraphAI library. This privacy-by-design approach ensures that no data was collected without user awareness. Users voluntarily contributed anonymized execution data to support the development of the open-source library, and the scope of telemetry collection was documented in the library’s documentation.

Bias and Representativeness.

The dataset exhibits couple of biases that researchers should consider. First, GPT-4o-mini accounts for 87.4% of requests, meaning extraction patterns may disproportionately reflect this model’s behavior rather than LLM capabilities in general. Second, the raw telemetry data showed extreme geographic and domain imbalance two e-commerce schemas alone accounted for approximately 5 million of the 9 million total events. Our balancing strategy (limiting to a maximum of 5 examples per unique schema hash) substantially mitigates but does not entirely eliminate this skew; e-commerce domains may still be over-represented.

Terms of Service and Responsible Use.

ScrapeGraphAI is a general-purpose tool for LLM-based web extraction; compliance with website Terms of Service, robots.txt directives, and applicable laws is the responsibility of individual users. Our dataset reflects real-world user behavior, and we cannot independently verify that all scraped content was obtained in accordance with source websites’ policies. We do not endorse or encourage scraping that violates website Terms of Service. Researchers using this dataset should apply standard ethical guidelines and ensure their downstream applications respect legal and ethical boundaries.

Data Quality Limitations.

As a real-world dataset derived from production telemetry, ScrapeGraphAI-100k includes imperfect data that reflects authentic operational conditions. Some LLM responses are truncated or malformed due to API timeouts, rate limiting, or model errors. The 93% schema validation rate measures syntactic compliance (whether outputs parse as valid JSON matching the requested schema) but does not assess semantic correctness- a response may be structurally valid yet factually incorrect. Dataset represents a temporal snapshot from Q2-Q3 2025; web content evolves continuously, and some source pages may have changed or become unavailable.

Environmental Impact.

Dataset creation involved processing 9 million telemetry events, requiring modest computational resources compared to typical machine learning workloads. Our preliminary fine-tuning experiments used approximately 3 days of training on a single NVIDIA A100-80GB GPU. This computational footprint is orders of magnitude smaller than LLM pretraining, and the dataset enables training efficient small language models that can reduce inference costs and energy consumption in production deployments.

9.
Conclusion

ScrapeGraphAI-100k provides the large-scale, real-world dataset for LLM-based structured web extraction. Built from 9M opt-in production telemetry events, it yields 93,695 balanced examples spanning a wide spectrum of schema complexity, and pairs Markdown content with natural-language prompts, JSON schemas, validated responses, and fine-grained complexity metadata. Our analysis shows sharp, non-linear failure thresholds as schema depth and key count increase, and preliminary experiments demonstrate that fine-tuning a 1.7B model on this data narrows the gap to 30B baselines on structural accuracy. These findings position ScrapeGraphAI-100k as a practical dataset for researchers evaluating extraction robustness and its impact on structured indexing and retrieval pipelines, while acknowledging that model usage in the telemetry skewed toward GPT-4o-mini.

Looking forward, we plan to extend the dataset with richer modalities (raw HTML, DOM structure, and visual cues), deeper semantic evaluation of value correctness, and new tasks such as schema induction and error correction. We also aim to broaden multilingual and domain coverage through continued telemetry releases, and to ship reproducible baselines and leaderboards that track evolving LLM capabilities. The dataset is publicly available on HuggingFace to enable immediate research and facilitate reproducible comparisons.

Appendix B
Metric Correlations

The correlation structure of dataset metrics (Figure
5
) reveals three findings with practical implications for extraction system design. First, schema complexity metrics exhibit near-perfect multicollinearity: keys, elements, cyclomatic complexity, and composite score correlate at
r\geq 0.98
, indicating that key count alone suffices as a complexity proxy for most applications. Second, validation success shows consistent negative correlations with all complexity measures (
r=-0.15
to
-0.20
), confirming that schema complexity directly predicts extraction failure risk—a pattern exploitable for adaptive prompting or model selection. Third, execution time correlates negligibly with schema complexity (
r\approx 0.02
) and only weakly with response size (
r=0.06
), suggesting that latency in LLM-based extraction is dominated by factors outside schema structure (e.g., API overhead, content length, model inference). These patterns enable practitioners to use lightweight complexity estimates for task routing while focusing optimization efforts on non-schema bottlenecks.
