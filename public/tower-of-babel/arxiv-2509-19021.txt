Optimization of Base- n n Radix Sort for Skewed Datasets
Atharv Pandey, Lakshmanan Kuppusamy

Abstract
The importance and applications of sorting is apparent and needs no explanation. In this paper, we analyse a non-comparison sorting algorithm, Base- n n Radix Sort (BNRS) and introduce an optimized variant of BNRS, namely, Stable Logical Partition Radix Sort (SLPR). The complexity of these algorithms is measured by the input size n n and the maximum value k k . We show that with respect to time complexity, these algorithms are more succinct than traditional comparison-based sorting algorithms for representing the sorted order of certain integer distributions, specifically, when k < n log 2 ⁡ n k<n^{\log_{2}n} is met. We also show that the SLPR optimization, which uses in-place stable partitioning to reduce the active problem size in each pass, resulting in highly effective sorting for skewed datasets that contain a majority of small numbers and mix of very large numbers.

Now, we shall explore a novel optimisation strategy utilising mathematical approach to effectively reduce the input size for sorting in the consecutive rounds which is achieved by partitioning the input into ‘sorted’ and ‘active’ regions.

Logical Partitioning Approach

•

Mechanism:
This approach utilizes a stable partitioning algorithm in each round. It separates elements into two groups— sorted and active based on a mathematical predicate. The predicate evaluates whether an element has been fully sorted relative to the current and future rounds.

•

Advantage:
Only the active portion of the array is processed by the sorting subroutine in subsequent passes which results to reducing the active portion, though need not be at every round. This drastically reduces the number of elements handled in later rounds, leading to significant performance gain on skewed datasets.

•

Stability:
The use of a stable partition function and a stable sorting subroutine ensures the entire algorithm maintains the relative order of equal elements (i.e., the elements having the same values).

Compared to BNRS, the logical partitioning approach reduces redundant work by limiting the process required for the unsorted portion in each round, improving the efficiency and performance of the algorithm. However, these improvements come at the cost of increased overhead, which is a drawback, hence we need to find break-even condition which would determine the utility of the optimization in comparison to the cost of implementation by the provision of the early termination strategies.

3.

Comparing the Complexities:
For BNRS to outperform comparison-based sorting algorithms, it’s complexity must be asymptotically smaller, satisfying the condition:
O(n\log_{n}k)<O(n\log n)
.

Removing the common factor
n

\log_{n}k<\log_{2}n
.

Converting to natural logarithm (ln)
\frac{\ln k}{\ln n}<\frac{\ln n}{\ln 2}

This gives:
\ln k<\frac{(\ln n)^{2}}{\ln 2}

\frac{(\ln n)}{\ln 2}=log_{2}n

\ln k<\ln n\cdot log_{2}n

Exponentiating by

k<e^{(\ln n)\cdot\log_{2}n}
.
Since
e^{\ln n}=n

k<n^{\log_{2}n}
.

This inequality,
k<n^{\log_{2}n}

n
and
k

n

4.

Practical analysis of the relation
k<n^{\log_{2}n}
:

We are required to store elements of the dataset in common datatypes. Since we are utilising these datatypes for storing elements into memory, the maximum possible value that can be stored in the datatype becomes our
k_{max}
.

•

Datatype - Int (32-bit): Max value is
2^{31}-1\approx 2.147\times 10^{9}

•

Datatype - Long Long (64-bit): Max value is
2^{63}-1\approx 9.223\times 10^{18}

Assuming
k_{max}
to be the maximum possible value for the largest common datatype (64-bit unsigned integer), we can find the crossover point for
n
as given below:

k_{max}\leq n^{\log_{2}n}
. That is,

n^{\log_{2}n}\geq 2^{63}-1
.

Taking
\log_{10}

\log_{10}(n^{\log_{2}n})\geq\log_{10}(2^{63}-1)

This implies,

(\log_{2}n)\cdot(\log_{10}n)\geq 18.9648
.

Since
\log_{2}n=\frac{\log_{10}n}{\log_{10}2}
, we get

\left(\frac{\log_{10}n}{\log_{10}2}\right)\cdot(\log_{10}n)\geq 18.9648
.

From this we get,
\frac{(\log_{10}n)^{2}}{0.30103}\geq 18.9648
. That is,
(\log_{10}n)^{2}\geq 5.7081

\log_{10}n\geq\sqrt{5.7081}\approx 2.3891

n\geq 10^{2.3891}

Therefore, we get,
n>245

This is the theoretical crossover point which implies that when sorting an array containing the maximum possible 64-bit integer value, BNRS algorithm is guaranteed to be theoretically faster than any comparison-based sorting algorithm for average case once the input size surpasses 245 elements.

Analysis of the Optimization

We can break down the cost of operations of the algorithm in stages on the basis of rounds, which run from 1 to R, number of rounds are further determined from the formula
\lfloor\log_{n}k\rfloor+1
, where
k
is the maximum element.

•

Stage 1 (Round 1): Perform sorting on the mod values of the entire array, no partitioning required.

•

Stage 2 (Rounds 2 to R-1): Perform partitioning and iteratively sort the active region.

•

Stage 3 (Round R): Perform sorting on the final active region, no partitioning required.

5.1
Deriving the Final Break-Even Condition

To determine the condition under which the optimized algorithm is faster compared to the BNRS, we analyze its cost in three distinct stages, assuming the total number of rounds
R>2
. We define p as the proportion of elements partitioned out in the first effective partitioning step (Round 2).

Stage 1: The Initial Sort (Round 1)

The first round consists of a single sort operation on the entire array.

\text{Cost}_{\text{Stage 1}}=n

Stage 2: The Core Optimization Loop (Rounds 2 to R-1)

This stage is the most crucial portion and the optimization takes place in this stage, we model it’s cost with an assumption:
We assume a proportion ‘
p
’ of the initial n elements are removed post the first round (Round 2) for the elements that satisfy the predicate. For the remainder of the Core Loop (Rounds 3 to R-1), we conservatively assume the active region does not shrink further.

The cost of this entire stage is the sum of its first iteration (Round 2) and the subsequent
R-3
iterations:

\displaystyle\text{Cost}_{\text{Stage 2}}

\displaystyle=\underbrace{[n+(1-p)n]}_{\text{Cost of Round 2}}+\underbrace{[(R-3)\times 2(1-p)n]}_{\text{Cost of Rounds 3 to R-1}}

Cost of Round 2 is calculated by the cost of partitioning
O(n)
added to the cost of sorting the active region i.e. elements not satisfying the predicate, hence requiring sorting.

Cost of subsequent rounds
3
to
R-1
is calculated from
R-3
as the number of iterations multiplied with
2\cdot(1-p)\cdot n
cost per iteration where
(1-p)\cdot n
is the cost of partitioning as well as sorting

Stage 3: The Final Sort (Round R)

The last round requires only a sort on the final active set from the previous stage.

\text{Cost}_{\text{Stage 3}}=(1-p)n

Total Cost and The Final Inequality

The total cost,
T_{SLPR}
, is the sum of these three stages:

\displaystyle T_{SLPR}

\displaystyle=\text{Cost}_{\text{Stage 1}}+\text{Cost}_{\text{Stage 2}}+\text{Cost}_{\text{Stage 3}}

\displaystyle T_{SLPR}

\displaystyle=n+\left([n+(1-p)n]+(R-3)2(1-p)n\right)+(1-p)n

Simplifying this expression gives us the following cost function:

T_{SLPR}=2n+2(R-2)(1-p)n

Now, we set the cost of SLPR to be less than the cost of BNRS, where
T_{BNRS}=R\times n

\displaystyle 2n+2(R-2)(1-p)n

\displaystyle<R\times n

\displaystyle<R

5.2
Analysis of Result:
p>0.5

We derived a conservative break-even condition showing that for any sort requiring more than 2 rounds, our algorithm is faster if more than 50% of the data is partitioned in the first effective round (
p>0.5
). This condition is based on a simplified model that assumes no further partitioning benefits in subsequent rounds. In practice, for realistically skewed data like a Zipfian distribution, the partitioning continues to be effective in a cascading manner, further reducing the active region. Hence, the true performance of the algorithm is even better than what
p>0.5
threshold suggests, making it overwhelmingly efficient for the targeted skewed datasets.

6.4
Analysis of Results

The benchmark results from the skewed dataset validate the core argument of the paper, findings are as follows:

1.

A primary finding is the clear advantage of a well-parameterized Radix Sort over comparison based sorting algorithm, At an input size of
1,000,000
, the baseline BNRS (103 ms) is approximately 1.6x faster than the highly optimized
std::sort
(165 ms). This confirms that for large integer datasets, a non-comparison, large-radix approach is fundamentally more efficient than a comparison-based one.

2.

The naive Base-10 Radix Sort is by far the slowest algorithm, taking nearly twice as long as
std::sort
. This demonstrates that the choice of the radix is a critical factor; a small base like 10 leads to an excessive number of rounds for large integer types, making it practically inefficient.

3.

As predicted by our theoretical analysis, the adaptive partitioning provides a clear performance benefit on skewed data. For smaller inputs (
n=1,000
), SLPR is approximately
1.4
times faster than BNRS (
178,500/125,137\approx 1.43
).

Nonetheless, the consistent performance advantage across all scales validates SLPR as the better performing algorithm for this dataset.

While the performance gains on the largest dataset are more modest than the theoretical model predicts, the empirical results unequivocally establish SLPR as the best performant algorithm in the test suite for sorting skewed integer data.

7
Conclusion

In this paper, we introduced an optimized version of BNRS which performs very well for skewed datasets provided that
p>0.5
where
p
is the proportion of elements partitioned in the second round and
R>2
. As a future work, one can consider to minimize the space complexity and also reducing the practical implementation cost of modulo and division operators. Further, one can consider making optimizations to sorting algorithms possibly utilising data transformations.
