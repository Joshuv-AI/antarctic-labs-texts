Fixing non-blocking data structures for better compatibility with memory reclamation schemes
Md Amit Hasan Arovi, Ruslan Nikolaev

Abstract
We present a new technique, Safe Concurrent Optimistic Traversals (SCOT), to address a well-known problem related to optimistic traversals with both classical and more recent memory reclamation schemes, such as Hazard Pointers (HP), Hazard Eras (HE), Interval-Based Reclamation (IBR), and Hyaline. Unlike Epoch-Based Reclamation (EBR), these schemes guarantee protection against stalled threads (robustness) but lack support for well-known data structures with optimistic traversals such as Harris’ original list, Natarajan-Mittal tree, among others. For these reclamation schemes, existing data structure implementations are either buggy (e.g., Natarajan-Mittal tree) or come with performance trade-offs (e.g., Harris-Michael modified list). A recent work, HP++, supports optimistic traversals but uses a different API and is generally slower than even HP, not to mention more recent schemes such as IBR or Hyaline. Moreover, it has undesirable applicability trade-offs, and more complex implementation, among other issues. We propose a different method which keeps existing reclamation schemes intact but instead relies on data structure adaptations. Unlike existing Harris-Michael approach or HP++, our method retains performance benefits of the original data structure and also does not compromise performance of the underlying reclamation scheme. In fact, for IBR and Hyaline, our results almost match those of EBR, which often serves as a practical upper bound due to its great performance. We implement and evaluate two fundamentally different data structures: Harris’ list and Natarajan-Mittal tree. SCOT enables their first correct implementations with optimistic traversals for HP, HE, IBR, and Hyaline. Our method is also directly applicable to other data structures, e.g., Fraser’s skip list or hash map that uses Harris’ list internally. We observe similar performance speedups (e.g., Harris vs. Harris-Michael list) that were previously available only to EBR users. As we discuss in the paper, our version of Natarajan-Mittal tree is the first bug-free implementation for HP, HE, IBR, and Hyaline; it achieves very high throughput, comparable to that of EBR.

Introduction

With the growing prevalence of multicore and manycore systems, parallelization is becoming crucial for enhancing performance across the entire software stack – applications, middleware, core system services, and low-level components inside an operating system (OS). Non-blocking data structures, which are not dependent on mutual exclusion, are becoming increasingly popular due to their scalability, throughput, and latency characteristics. Unfortunately, many data structures that utilize non-blocking techniques conflict with fundamental assumptions of classical memory management. This is because memory cannot be promptly reclaimed after an object is removed from a data structure, as there may still exist stale pointers to the object due to ongoing operations.

When using manual memory management, memory has to be safely reclaimed by freeing memory only when
all
ongoing operations with stale pointers complete. A number of past researchers proposed various
safe memory reclamation
(SMR) techniques in C, C++, or Rust.
Non-blocking SMR progress is often crucial for the overall progress guarantees, as we do not want to compromise data structure progress properties. Unfortunately, many SMR schemes are trying to attain several

[

(A) robustness

(B) easy integration
(no dependency on any special APIs, such as roll-back mechanisms or OS-based primitives), and
(C) wide applicability

2
Background

2.1
Lock- and Wait-Freedom

The most widely used
non-blocking
progress is
lock-freedom
, which allows threads to interfere with each other while still guaranteeing that
at least
one thread makes progress in a finite number of steps. (It should be noted that good lock-free algorithms allow multiple threads to make concurrent progress in practice.)
This should not be confused with “lockless” approaches that simply avoid
explicit
locks, where one preempted thread can block all other threads.

Wait-freedom
is a much stronger property which requires that
all
threads make progress in a finite number of steps.

2.2
Memory Reclamation API

For both EBR and HP, the API is called directly. Each thread maintains a
reservation
, which is a globally accessible per-thread state. Memory objects, containing the required SMR header, are allocated using standard OS methods. Once a memory object is part of a data structure, it can only be reclaimed through two steps. First, after removing a pointer from the data structure, a memory object is
retired
. When the object becomes unreachable by any other concurrent thread, it is then returned to the OS.

EBR requires specifying both the start and end points of an operation to define the scope of protected memory accesses. In contrast, HP offers finer granularity in terms of reserved objects, requiring to
explicitly
wrap accesses to shared-memory objects. Additionally, in HP, the number of local pointers that can be held simultaneously by each thread is limited, and local pointers must be differentiated by unique indices.

These data structures employ “logical” deletion, i.e., a node inside a data structure is first simply marked (by stealing one bit from a node pointer), and then unlinked from the data structures (i.e., “physically” deleted). The original Harris’ List and Fraser’s Skip List use optimistic traversals, i.e., a chain of
consecutive

search

However, as we discuss below, this approach is
incompatible
with HP. Harris-Michael List and Herlihy-Shavit Skip Lists use a different approach: they still use “logical” deletion. However, they mandate that logically deleted nodes are removed
immediately

There is a similar difference between them with respect to optimistic traversals. 2.4
Harris’ and Harris-Michael Linked Lists

The main challenge in lock-free linked lists is allowing a deleting thread to mark a node as deleted and update the preceding node’s next pointer.
Timothy L. Harris solved this
[
10
]
by using helper threads during deletion. A deleting thread first marks a node as “logically” deleted by updating its next pointer, and then the node is “physically” removed by the deleting thread or a helper (conflicting concurrent operation).
Harris’ list supports
optimistic traversals
, meaning that logically deleted nodes can still be traversed and bypassed by a search operation without immediate physical removal. This allows threads to defer unlinking logically deleted nodes until reaching the intended destination node.

However, this approach presents fundamental challenges for HP. Figure
1
shows an example with several concurrent operations. Suppose Thread 3 (not shown in the figure) has previously marked N2 for deletion but has not yet unlinked it. Then, Thread 2 marks N3 for deletion and unlinks the entire chain of nodes between N1 and N4 (assuming all
consecutive
nodes in the chain are logically deleted). Meanwhile, Thread 1 is traversing the list; it reaches N2 before Thread 2 physically removes the chain. Although N2 is now
retired
by Thread 2, it still remains in the HP limbo list. The reason for that is that Thread 1 has made a reservation
prior to its physical deletion
. N3 is also retired by Thread 2, but because Thread 1 never reserves N3, it is not guaranteed to stay in the HP limbo list, i.e., N3 is returned to the OS. Consequently, Thread 1 fails when accessing N3.

Maged M. Michael modified
[
13
]
Harris’ approach to resolve compatibility issues with HP: when a thread encounters a node marked as logically deleted during traversal, it
immediately
attempts to physically remove the node from the list.

Why does Michael’s approach work?
Recall that accessing N2 is still safe, because its HP reservation is made prior to N2’s physical deletion. (To
successfully
make a reservation, HP verifies that the pointer from N1 to N2 remains intact.) Once N2 is physically deleted, it is retired and ends up in the HP limbo list. If we now attempt to reserve N3, HP falsely succeeds as
the pointer from N2 to N3 remains intact unlike the pointer from N1 to N2
. Thus, Michael’s approach is to ensure that pointers always change during physical removal, which happens automatically when we remove one node at a time.

Another way to think about Michael’s approach is that if we remove nodes one by one, N3 takes place of N2, i.e., right after N1. N3 will be the first logically deleted node in the chain when making the HP reservation, which is still safe to access.

While it fully solves the HP problem, Michael’s approach increases the number of CAS operations and may lead to a higher contention among threads. It also makes read-only traversals impossible.

Design

3.1
Bird’s-Eye View

The crux of the problem with the HP implementation is its inability to properly track physically deleted nodes in the original Harris’ list (or tagged edges in Natarajan-Mittal tree) while traversing through logically deleted nodes. However, if there was some way to confirm that the following logically deleted node is not yet physically deleted, optimistic traversals are still feasible.

In Figure
1
, N2 is still
safe
to access because it is not physically deleted, i.e., N1 still points to N2. Moreover, according to Figure
2
, we always make sure that the node to the left is not logically deleted and thus
never unlink nodes in the middle of the chain
, i.e., we can delete just N2, or both N2-N3, but we never delete N3 while keeping N2 in the list. In other words, we either remove the entire chain of logically deleted nodes or a subchain with the truncated tail.

Combining these observations together, we make one crucial insight that helps solve the issue with HP: It is still safe to access N3 and the following nodes as long as at every step, i.e., after making an HP reservation for the next logically deleted node, we verify that N1 still points to N2. In other words, once we reach N2, we declare it to be a “dangerous zone”. Until we reach the end of the chain of consecutive logically deleted nodes, we are going to stay in the dangerous zone and perform additional checks. More specifically, after retrieving N3’s pointer and creating its HP reservation, we check that N1 still points to N2. We will continue to perform these checks at every iteration until we reach the end of the chain. If the check fails, we cannot proceed further and need to restart the search operation from the very beginning.

3.2.1
Recovery Optimization

For simplicity, we have stated that when validation fails, we need to go back to the beginning of the list. While this is acceptable, this validation check is not always critical: the last safe node may simply point to another node now (e.g., when a new node was inserted or the chain of logically deleted nodes was already eliminated by a concurrent thread). In such cases, we can simply escape from the dangerous zone and continue to new node. We must, however, ensure that the last safe node is still not logically deleted. When it is deleted, the last safe node (
prev
) is in a dangerous zone itself (though still safe to access due to prior reservation). Depending on the SMR algorithm, we have different choices.

For HP and HE,
protect
uses indices and cancels previous reservations. As keeping a predecessor of
prev
would induce extra hazard pointers and duplication (hence memory barriers), it makes sense to simply go back to the beginning of the list when
prev
gets logically deleted.

For IBR and Hyaline-1S,
protect
has a cumulative effect and does not cancel previous reservations. For these schemes, we implement a small on-stack ring buffer of
prev
pointers, which allows us to fall further back in the list when
prev
gets logically deleted. Empirically, we found that a ring buffer of size 8 is more or less optimal. Only when exhausting all 8 predecessors, do we go back to the beginning of the list. (See Figure
6
.)

. The
current
node points to the lowest node that is currently considered.

To properly support optimistic traversals, after each HP reservation of the
current
node, if the corresponding node is flagged or tagged, we need verify that ancestor still points to successor. If ancestor points to some other node or successor becomes tagged, we need to restart from the very beginning.

This idea is largely similar to the above-mentioned Harris’ list approach, except that no additional hazard pointer is required, as we already need to protect both ancestor and successor nodes. Additionally, we need to check both
tagged
and
flagged
conditions for the current node, as (flagged) leaf nodes’s hazard pointer reservations need to be also verified.

Unlike Harris’ list, empirically, we found that
recovery
does not help improve performance for various key ranges, primarily because of the hierarchical structure of the tree (e.g., when there is a mismatch, likely, the tree has diverged substantially anyway). If ancestor no longer points to the original successor, we simply restart the search from the very beginning.

Due to complexity of the algorithm and very similar checks for optimistic traversals, we omit pseudocode in this paper. In Section
5
, we evaluate Natarajan-Mitttal Tree with SCOT.

3.4
SCOT for Hash Map and Skip Lists

SCOT for these data structures is largely similar to Section
3.2
. Hash Maps are based on linked lists directly. Fraser’s skip list uses the same idea of logically deleted nodes as Harris’ list.

4
Correctness

We analyze the SCOT technique when applied to Harris’ linked list and the Natarajan-Mittal (NM) tree. Our goal is to establish two core properties under concurrent execution with SMR: (1)
Safety:
No thread accesses reclaimed or unlinked memory, and (2)
Lock-Freedom:
The system guarantees global lock-free progress - some thread completes its operation in a finite number of steps.
We present invariant-based correctness arguments below.

4.1
Model and Setup

Our reasoning is based on a standard concurrent execution environment, assuming the following commonly accepted properties:

•

Sequential consistency
for all loads and stores.

•

Atomic
compare-and-swap (CAS) operations.

•

Safe memory reclamation (SMR)
with hazard pointers (HP):

–

A node protected by a hazard pointer
HP(T, i)
is not reclaimed until all hazard reservations are cleared.

–

Reclamation is conservative: memory is retired before reuse.

Node Semantics:

•

A node
n
is
logically deleted
if
isMarked(n.next) = true
.

•

A node is
physically deleted
if its predecessor no longer points to it.

4.2
Definitions

Let
H
denote the Harris linked list under consideration, consisting of nodes
N_{1},N_{2},\dots
, each with a
next
pointer that may be marked to indicate logical deletion.

•

\mathcal{D}
: A maximal subsequence
\langle N_{k},\dots,N_{\ell}\rangle
such that:

–

\forall i\in[k,\ell]
:

=

,

–

\forall i\in[k,\ell-1]

\text{Valid}(a,b)\triangleq a.\texttt{next}=b

Invariants

Invariant 1

(Safe Traversal)
.

A thread traversing a dangerous zone

\text{Valid}(N_{i-1},N_{i})\wedge\texttt{HP(T, 3)}=N_{i}

Invariant 2

(ABA Prevention)

A node protected by hazard pointers cannot be reclaimed or reused until all hazard reservations are cleared.

(Path Validation)

•

4.4
Structural Guarantees

Lemma 1

(Ordered Node Removal)
.

In Harris’ list and NM tree, nodes are always unlinked starting from the head of logically deleted chains. This prevents:

•

Mid-chain removals that could violate traversal safety

•

Reattachment of logically deleted nodes to other deleted nodes

4.5
Traversal Strategy in Harris’ List

SCOT maintains a bounded buffer of previously validated "safe" nodes during traversal. If validation fails, the thread:

1.

Attempts to resume from the most recent valid node in buffer

2.

Only restarts from head if all buffer entries are invalidated

4.6
Memory Bounds

Lemma 2

(Bounded Memory Overhead)
.

The total memory overhead for hazard pointers is bounded and grows linearly with the number of threads.

Proof.

Let
N
be the number of threads,
K
the number of hazard pointers per thread, and
S
the size of a node. Then the total hazard pointer memory usage is:

\text{Memory}=N\times K\times S
.
In our SCOT-based implementation:

•

The Harris list requires one more hazard pointer per thread than the Harris-Michael list, due to the need to traverse chains of logically deleted nodes safely.

•

The Natarajan-Mittal tree operates within standard hazard pointer usage for tree traversal, requiring no additional hazard pointers beyond typical SMR-compatible designs.

Since
K
and
S
are constants, the total memory overhead scales as
O(N)
, ensuring bounded and predictable memory usage.
∎

4.7
Harris’ List Correctness

Theorem 1

(HP Compatibility & Traversal Safety)
.

Let thread
T
traverse a dangerous zone
\mathcal{D}=\langle N_{k},\dots,N_{\ell}\rangle
with:

•

\texttt{HP(T, 2)}=N_{k-1}
,

•

\texttt{HP(T, 3)}=N_{i}
for current
N_{i}\in\mathcal{D}
,

•

Validation:
\text{Valid}(N_{k-1},N_{k})
.

Then
T
never accesses a reclaimed node.

Proof.

•

Base case:

N_{k}
is protected and validated via
N_{k-1}.\texttt{next}=N_{k}
.

•

Inductive step:
Before accessing
N_{i+1}
,
T
validates
N_{i}.\texttt{next}=N_{i+1}
and protects it.

•

Fallback mechanism:
If validation fails, the thread does not immediately restart from the head. Instead, it backtracks through a bounded buffer of previously validated safe nodes. It resumes traversal from the most recent entry in the buffer whose next pointer is still valid. Only if all buffered entries (buffer size is bounded) are invalidated (e.g., due to concurrent modifications),
T
performs a full restart from the head.

•

Termination:
This buffered fallback approach preserves Invariant
1
and ensures that all accessed nodes remain protected and reachable, while reducing unnecessary restarts.

∎

Theorem 2

(ABA Prevention)
.

During traversal, no node in
\mathcal{D}
is reclaimed or reused.

Proof.

N_{i}
is protected via
HP(T, 3)
. SMR guarantees prevent reclamation while protected. Invariant
2
holds.
∎

Theorem 3

(Lock-Freedom of Harris’ List)
.

SCOT-based Harris’ List is lock-free.

Proof.

Restarts occur only when validation fails, implying a successful CAS by another thread (e.g., physical unlink). Each such CAS represents system-wide progress, bounding the number of retries for any thread. Thus, at least one thread always makes progress in finite steps, satisfying lock-freedom.
∎

Clarification of Roles:

•

•

successor

•

Theorem 4

(NM Tree Traversal Safety)
.

Let thread
T
traverse with:

•

\texttt{HP(T, 0)}=\texttt{current}

•

\texttt{HP(T, 1)}=\texttt{successor}

•

\texttt{HP(T, 2)}=\texttt{ancestor}

\texttt{ancestor.link}=\texttt{successor}
.

current
is reachable from
successor
(ensured by hazard pointer protection of the path during traversal).
Then

Proof.

current
is hazard-protected. Invariant

∎

Theorem 5

(Lock-Freedom of NM Tree)
.

SCOT preserves NM Tree’s lock-freedom.

Proof.

Restarts occur only when:

•

successor
is tagged, or

•

ancestor
\rightarrow
successor
becomes invalid (implying a concurrent structural modification).

Each restart corresponds to a
forward progress
event (e.g., physical unlink via CAS). Contention is thus bounded, and lock-freedom is preserved.
∎

We measure both throughput and memory overhead. Memory overhead is represented by the number of not-yet reclaimed objects, which are nodes that remain in an unreclaimed state due to the use of SMR. Related Work

6.1
Non-Blocking SMR

The ERA theorem
[
22
]
demonstrates that at most two out of three properties – (A)
robustness
, (B)
easy integration
, and (C)
wide applicability
– can be achieved simultaneously. Moreover,
strong applicability
, as defined by that work, currently seems to be available only with SMR schemes that implement some kind of quiescence, similar to EBR. However, quiescence periods inevitably lead to potentially unbounded memory usage (i.e., lack of non-blocking progress).

A number of schemes, e.g., DEBRA+
[
5
]
, QSense
[
4
]
, ThreadScan
[
2
]
, ForkScan
[
1
]
, NBR
[
23
]
, propose a solution to EBR’s robustness (A) problem. However, they all need special OS-based support such as interaction with the OS scheduler or signal delivery. These OS mechanisms inevitably use locks in most typical OSs. They satisfy (A) and (C) properties but not (B), which is essential to the strict non-blocking progress.
Other schemes that satisfy (A) and (C), e.g., VBR
[
21
]
, need non-trivial roll-back mechanisms, which are too complicated to generalize in terms of the uniform library API.

There were also recent attempts to build non-blocking data structures using automatic garbage collection techniques. Generally speaking, garbage collection is subject to the same trade-offs and limitations, discussed above.
FreeAccess
[
6
]
addresses the problem with (C) and optimistic traversals but forgoes (B) by requiring to divide code into
separate read and write phases. OrcGC
[
7
]
is another lock-free garbage collector. OrcGC only works with data structures without loops and requires mechanisms similar to smart pointers, either in the compiler or the language itself; it can also be slower than HP in certain tests.

Other SMR schemes such as interval-based reclamation (IBR)
[
26
]
, hazard eras (HE)
[
20
]
, wait-free eras (WFE)
[
17
]
, Hyaline
[
18
]
, and Crystalline
[
19
]
provide HP-like interface; they still lack the wide-applicability property (C) but are often faster than HP. The method proposed in this paper to mitigate the problem with (C) is suitable to all of them.

6.2
Non-Blocking Data Structures

Timothy L. Harris
[
10
]
was the first to present a
practical
lock-free linked list. Maurice Herlihy and Nir Shavit pointed out
[
11
]
that read-only optimistic search operations are feasible with Harris’ list. Unfortunately, Harris’ list is incompatible with HP
[
7
,
6
,
12
,
3
,
19
,
18
]
. Maged M. Michael proposed
[
13
]
disabling optimistic traversals by unlinking logically deleted nodes one by one, making it feasible to use HP. SCOT enables support for Harris’ original list with HP, HE, IBR, and Hyaline, while using optimistic traversals.

A skip list is a data structure with an efficient search, insertion, and deletion operations, achieving (probabilistically) logarithmic time complexity. Lock-free skip lists
[
11
,
9
]
are very similar to Harris’ list and Harris-Michael list, except that they consist of several sublists. Consequently, challenges related to logical deletion and optimistic traversals are identical.

Hash maps store and retrieve key-value pairs in constant time.
A lock-free hash map
[
13
]
is an array of linked lists, which can be based on either Harris’ or Harris-Michael approach.

Binary search trees are also commonly used for efficient search, insertion, and deletion operations. Ellen at al. Tree
[
8
]
implements one such approach which is compatible with HP. However, Natarajan-Mittal Tree
[
16
]
is significantly faster (around 43% according to
[
12
]
) due to its ability to remove multiple concurrently tagged edges in one pass. Natarajan-Mittal Tree is a very popular data structure and evaluated in several recent works
[
26
,
3
,
18
,
12
]
. Prior to our work, as pointed out in
[
3
,
12
]
, Natarajan-Mittal Tree was incompatible with HP, IBR, and other similar schemes.

6.3
Wait-Free Optimistic Traversals

With our approach, optimistic traversals might have to occasionally restart the search operation from the beginning if, due to overlapping modifications, the state of the data structure diverges significantly and cannot be recovered locally. This guarantees lock-free but not wait-free progress. This limitation is very similar to that of HP++’s existing solution which also does not support wait-free optimistic traversals due to potential restarts.

However, this restart is inherently unavoidable with data structures that use optimistic traversals: it is still needed for insertion and deletion operations, regardless of the search operation or the reclamation scheme used. We note that we can still implement wait-free search traversals by using Timnat-Petrank’s method
[
24
,
25
]
which allows restarts and works with HP. This method can be applied to various data structures, including linked lists. Timnat-Petrank’s original wait-free linked list, implemented in HP, is similar to Harris-Michael list. With SCOT, it can now use Harris’ optimistic traversals for faster performance.

7
Conclusion

We introduced safe concurrent optimistic traversals (SCOT), a new method which enables support for data structures that are incompatible with HP, IBR, HE, Hyaline-1S, and similar SMRs that lack the wide applicability support. Despite prior beliefs
[
12
]
of incompatibility of Natarajan-Mittal Tree and Harris’ List with HP, we have demonstrated that not only they are feasible with HP, IBR, HE, and Hyaline-1S, but they also can largely retain performance benefits when comparing to equivalent data structures without optimistic traversals.

We hope that our work will help to spur further research and reevaluate the existing challenges related to safe memory reclamation because lack of the wide applicability property may be addressed by other means.
