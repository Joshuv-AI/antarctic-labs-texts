Relational GNNs Cannot Learn 𝒞 2 \mathcal{C}_{2} Features for Planning
Dillon Z. Chen

Abstract
Relational Graph Neural Networks (R-GNNs) are a GNN-based approach for learning value functions that can generalise to unseen problems from a given planning domain. R-GNNs were theoretically motivated by the well known connection between the expressive power of GNNs and 𝒞 2 \mathcal{C}_{2} , first-order logic with two variables and counting. In the context of planning, 𝒞 2 \mathcal{C}_{2} features refer to the set of formulae in 𝒞 2 \mathcal{C}_{2} with relations defined by the unary and binary predicates of a planning domain. Some planning domains exhibit optimal value functions that can be decomposed as arithmetic expressions of 𝒞 2 \mathcal{C}_{2} features. We show that, contrary to empirical results, R-GNNs cannot learn value functions defined by 𝒞 2 \mathcal{C}_{2} features. We also identify prior GNN architectures for planning that may better learn value functions defined by 𝒞 2 \mathcal{C}_{2} features.

Introduction

Graph neural networks (GNNs) are a popular deep learning architecture that can learn embeddings for graph data.
It is well known that the expressive power of standard GNNs is upper-bounded by the Weisfeiler-Leman (WL) algorithm
(
Xu et al. 2019
;
Morris et al. 2019
)
.
The expressive power of the WL algorithm and, hence GNNs, is in turn characterised by
\mathcal{C}_{2}
logic
(
Cai, Fürer, and Immerman 1989
;
Barceló et al. 2020
;
Grohe 2021
)
, first-order logic with two variables and counting.
Inspired by this result,
Ståhlberg, Bonet, and Geffner 2022
introduce Relational Graph Neural Networks (R-GNNs) for learning domain-dependent value functions for planning: value functions that are trained from a finite set of problems from a given classical planning domain that can be used in unseen problems from the same domain.
The key contributions of the paper include the characterisation of optimal value functions for multiple planning domains via
\mathcal{C}_{2}
features, and corresponding experiments showing that R-GNNs can return optimal solutions with learned value functions on such domains.

However, it was never theoretically shown that R-GNNs can represent such value functions encoded via
\mathcal{C}_{2}
features.
Indeed, we show in this paper that R-GNNs cannot learn such value functions using the counterexamples in
(
Chen, Thiébaux, and Trevizan 2024
, Theorem 4.3)
and
(
Chen, Trevizan, and Thiébaux 2024
, Theorem 4.2)
.
The main reason for why this is the case is that the relations defined in R-GNNs do not correspond to the relations defined in
\mathcal{C}_{2}
features, and thus the theory characterising the expressiveness of GNNs and
\mathcal{C}_{2}
logic do not apply.
We instead show that the GNN architectures proposed by
Rivlin, Hazan, and Karpas 2020
and
(
Silver et al. 2021
)
, where objects are encoded as graph nodes and binary predicates as graph edges, exactly capture the
\mathcal{C}_{2}
features described by
Ståhlberg, Bonet, and Geffner 2022
.

3

\mathcal{C}_{2}
features.

Section

4

\mathcal{C}_{2}

Background and Notation

We begin by describing the classical planning instances represnted in lifted STRIPS.
We then introduce the concept of a relational language and relational structure in order to define
\mathcal{C}_{2}
logic and
\mathcal{C}_{2}
features for planning.

Planning Representation

Following
Ståhlberg, Bonet, and Geffner 2022
, a planning instance is a pair
P=\left<D,I\right>
where
D
is a first-order planning domain and
I
is the instance information.
A domain
D
consists of a set of first-order predicates
P
and action schemata
A
.
A predicate
p\in P
has parameters
x_{1},\ldots,x_{n_{p}}
for
n_{p}\in\mathbb{N}\cup\left\{0\right\}
, and
n_{p}
denotes the arity of the predicate; e.g. a binary predicate
P
has
n_{p}=2
.
An action schema has preconditions and effects defined as formulae over atoms
p(x_{1},\ldots,x_{n_{p}})
where the
x_{i}
are arguments of the schema.
The instance information
I
consists of a finite set of object names
O=\left\{o_{1},\ldots,o_{c}\right\}
, and an initial state
s_{0}
and a goal condition
g
which are sets of ground atoms: predicates in
P
whose parameters have been instantiated with object names in
O
; e.g.
p(o_{3},o_{2},o_{4})
.
A state
s
is a goal state if it contains all the goal condition atoms; i.e.
s\supseteq g
.

Relational Languages and Structures

A relational language
\mathcal{L}
is a set of first-order predicates and their corresponding parameters and (nonnegative) arities.
A relational structure is a tuple
\mathcal{A}=(\mathcal{C},\mathcal{L},\mathcal{S})
where
\mathcal{C}
is a set of constants,
\mathcal{L}
is a relational language, and
\mathcal{S}
a set of ground atoms: predicates in
\mathcal{L}
whose parameters have been instantiated with constants from
\mathcal{C}
.

A graph is an example of a relational structure with relational language induced from the edge relations of graphs.
Specifically, a graph
\mathbf{G}
defined as a tuple of nodes
\mathbf{V}
and edges
\mathbf{E}\subseteq{{\mathbf{V}}\choose{2}}
induces the relational structure
\mathcal{A}_{\mathbf{G}}=(\mathbf{V},\left\{E\right\},\left\{E(u,v)\mid(u,v)\in\mathbf{E}\right\})
, where
E
is a binary predicate corresponding to graph edges.

\mathcal{C}_{2}
Logic

\mathcal{C}_{2}
logic refers to first-order logic with 2 variables and counting over a given relational language.
We recite two example formulae by
Cai, Fürer, and Immerman 1989
for the relational language for graphs and refer to the same article for a formal presentation of
\mathcal{C}_{2}
logic.

The first such example does not use counting:

\varphi\equiv\forall x\exists y(E(x,y)\wedge\exists x[\neg E(x,y)]).

The formula
\varphi
states that every vertex is adjacent to some other vertex that itself is not adjacent to every vertex in the graph.
Note that variables may be requantified, as in the case of
x
here.
The second such example involves counting:

\psi\equiv(\exists^{\geq 17}x)(\exists^{\geq 5}y)E(x,y).

The formula
\psi
states that there are at least 17 vertices of degree at least 5.
In general, one can also specify exact values with the expression

(\exists^{=i}x)\varphi(x)\equiv(\exists^{\geq i}x)\varphi(x)\wedge\neg(\exists^{\geq i+1}x)\varphi(x)

which states that there are exactly
i
constants satisfying the formula
x
(at least
i
constants but not more than
i+1
constants).

\mathcal{C}_{2}
Features for Planning

Given a planning domain
D
,
Ståhlberg, Bonet, and Geffner 2022
refer to
\mathcal{C}_{2}
features as formulae in
\mathcal{C}_{2}
logic with the language
P\cup P_{G}
where
P
are the predicates of
D
and
P_{G}:=\left\{p_{G}\mid p\in P\right\}
are duplicate predicates for encoding goal information.
A states in a given planning instance also induces a relational structure.
This is done by extending the state with a copy of the goal condition from their corresponding instance
s_{G}:=\left\{p_{G}(o_{1},\ldots,o_{n_{p}})\mid p(o_{1},\ldots,o_{n})\in g\right\}
.
Then the explicit relational structure for a given state is given by

\displaystyle\mathcal{A}_{s}=(O,P\cup P_{G},s\cup s_{G})

(1)

where
O
is the set of objects in the corresponding instance.
An example
\mathcal{C}_{2}
feature for planning consists of checking if the goal has not been achieved for planning domains with predicates whose predicates have at most arity 2:

\displaystyle\varphi_{\mathrm{goalNotAchieved2}}\equiv

\displaystyle\qquad\biggl(\bigvee_{p(x_{1},x_{2})\in P}\exists x\exists y(p_{G}(x,y)\wedge\neg p(x,y))\biggr)\vee

\displaystyle\qquad\qquad\biggl(\bigvee_{p(x_{1})\in P}\exists x(p_{G}(x)\wedge\neg p(x))\biggr)\vee

\displaystyle\qquad\qquad\qquad\biggl(\bigvee_{p()\in P}(p_{G}()\wedge\neg p())\biggr)

The formula
\varphi_{\mathrm{goalNotAchieved2}}
states that the goal is not achieved when there is at least one goal atom with predicate at most 2 that is not achieved in the state.
Note that
\varphi_{\mathrm{goalNotAchieved2}}
does not make use of counting.
Indeed, a special case of
\varphi_{\mathrm{goalNotAchieved2}}
is presented in
(
Ståhlberg, Bonet, and Geffner 2022
, page 3)
.
More specifically, one can define the formula
\alpha\equiv\exists x\exists y\left(On_{G}(x,y)\wedge\neg(x,y)\right)
for detecting whether a single Blocksworld goal atom has been achieved, and similarly for other planning domains.

3
R-GNNs
\not=

\mathcal{C}_{2}

The proof for why R-GNNs do not encapsulate
\mathcal{C}_{2}
features for planning is straightforward and involves showing that it cannot distinguish pairs of planning problems with different
\varphi_{\mathrm{goalNotAchieved2}}
evaluations.
The counterexample is inspired by
(
Chen, Thiébaux, and Trevizan 2024
, Theorem 4.3)
and explicitly presented in
(
Chen, Trevizan, and Thiébaux 2024
, Theorem 4.2)
which we describe as follows.

Counterexample

Consider the planning domain
D
with a single binary predicate
P=\left\{q(x,y)\right\}
and single action schema
A=\left\{s(x,y)\right\}
.
The action schema
s(x,y)
has no preconditions and its effect adds the atom
q(x,y)
.
Then consider two different planning instances with information in the following table.

Instance

Objects

Initial State

Goal Condition

I_{1}

\left\{a,b\right\}

\left\{q(a,a),q(b,b)\right\}

\left\{q(a,b),q(b,a)\right\}

I_{2}

\left\{a,b\right\}

\left\{q(a,b),q(b,a)\right\}

\left\{q(a,b),q(b,a)\right\}

Both planning instances
I_{1}
and
I_{2}
have the same objects and goal condition but only differ in their state.
Note that the optimal solution for
I_{1}
has 2 actions (
s(a,b)
and
s(b,a)
) while
I_{2}
’s state is already in the goal condition.
Thus the evaluation of
\varphi_{\mathrm{goalNotAchieved2}}
is true on
I_{1}
and is false on
I_{2}
.
In other words, if R-GNNs indeed capture
\mathcal{C}_{2}
features, they should
distinguish

I_{1}
and
I_{2}
; i.e. R-GNNs should return different outputs for
I_{1}
and
I_{2}
for some set of hyperparameters and weights.

However,
(
Chen, Trevizan, and Thiébaux 2024
, Theorem 4.2)
shows that R-GNNs cannot distinguish
I_{1}
and
I_{2}
, which implies that R-GNNs cannot learn nor capture
\mathcal{C}_{2}
features.

Empirical Tests

We also empirically show that the counterexample holds true.
We perform two different setups commonly performed in the GNN research community for empirically testing the distinguishing power of GNN architectures
(
Kriege, Johansson, and Morris 2020
;
Abboud et al. 2021
;
Balcilar et al. 2021
;
Feng et al. 2022
;
Zhao et al. 2022
;
Wang et al. 2023
;
Bouritsas et al. 2023
)
.
Both setups are not entirely conclusive due to numerical precision errors, but are very likely to be representative of the expressive power of a GNN on specific inputs.
Given a GNN architecture
\mathrm{GNN}^{\theta}
with hyperparameters and weights
\theta
, and a pair of inputs
I_{1}
and
I_{2}
, denote
O^{\theta}_{1}=\mathrm{GNN}_{\theta}(I_{1})
and
O^{\theta}_{2}=\mathrm{GNN}_{\theta}(I_{2})
to be the GNN’s outputs.

Distinguishibility Test by Random Initialisation

The first experiment we perform involves randomly initialising
n
different hyperparameter and weight configurations for the GNN to get
\theta_{1},\ldots,\theta_{n}
.
Then if it holds that

\displaystyle{|O^{\theta_{i}}_{1}-O^{\theta_{i}}_{2}|}/{\max(|O^{\theta_{i}}_{1}|,|O^{\theta_{i}}_{2}|)}>\varepsilon

for some small
\varepsilon>0
and some
\theta_{i}
, it is likely that
\mathrm{GNN}
can distinguish the pair of inputs.
The
\varepsilon
is nonzero to account for numerical precision errors from neural network predictions, and represents the percentage of the difference
|O^{\theta_{i}}_{1}-O^{\theta_{i}}_{2}|
relative to the maximum
\max(|O^{\theta_{i}}_{1}|,|O^{\theta_{i}}_{2}|)
.
Otherwise, it is likely that
\mathrm{GNN}
cannot distinguish the pair and the likelihood increases with larger
n
and smaller
\varepsilon
.

We perform this setup using publicly available code
1

Accessed from
https://github.com/simon-stahlberg/relational-neural-network-python
under the commit
dd70a46
for R-GNN.
We fix the hyperparameters to be
64
for the embedding size;
sum
to be the aggregation function, as the sum function is maximally expressive for GNNs
(
Xu et al. 2019
)
; and
30
to be the number of layers.

Then we randomly initialise weights for R-GNN
n=100,000
times and set
\varepsilon=0.01
(1%) to account for numerical instability.

Over all

trials, there is a less than 1% difference between the predictions made on the input tasks relative to the maximum of the predictions.

Distinguishibility Test by Training

Recall that the counterexample has two instances
I_{1}
and
I_{2}
with optimal plan lengths given by 2 and 0 respectively.
If R-GNN is able to distinguish between the two instances, then it should be able to learn their optimal plan lengths if trained on them directly.
We train the R-GNN on the dataset consisting of only
I_{1}
and
I_{2}
and their corresponding ground truth values 2 and 0.
The same hyperparamter configuration of R-GNN in the previous experiment is used, alongside the default optimiser provided in the code (Adam with a learning rate of
0.0002
).

The loss never drops below 1, the average of the ground truth values, across all 10000 training steps.
This is the loss that R-GNN can best achieve if it cannot distinguish the inputs.
This observation holds true for different tested hyperparameters for R-GNN, such as the default R-GNN hyperparameters provided in the code.

These two experiments imply that it is highly likely that R-GNN is not able to distinguish the two instances, supporting the result in
(
Chen, Trevizan, and Thiébaux 2024
, Theorem 4.2)
.
More precisely, R-GNNs cannot learn value functions defined with
\mathcal{C}_{2}
features for planning.

4
PLOI Graphs + GNN
\simeq

\mathcal{C}_{2}

We conclude this paper by identifying graph encodings of planning instances on which GNNs are better able to learn
\mathcal{C}_{2}
features.
We identify them as PLOI graphs, named
2
2

2

Although the graph was first introduced by
Rivlin, Hazan, and Karpas 2020
in the context of learning, they do not introduce a descriptive name of their approach.
after the work by
Silver et al. 2021
.
We begin by introducing a more expressive notion of a graph under the relational structure framework, which includes node features and edge labels.
A graph with node features and edge labels is a relational structure
(\mathbf{V},\left\{E_{1},\ldots,E_{l},F_{1},\ldots,F_{n}\right\},\mathcal{S})
where the
E_{i}
are binary relations representing edge labels and the
F_{j}
are unary relations representing node features.
Note that it is possible for a pair of nodes to be instantiated in two different relations
E_{i}
and
E_{j}
, and similarly for singleton nodes in different unary relations
F_{i}
and
F_{j}
.
Furthermore, a graph presented in this way can be transformed into a standard GNN input with node and edge features represented as one-hot encodings that encode whether the relations
F_{j}
and
E_{i}
hold respectively, and vice versa for GNN inputs with binary node and edge features as is the case for PLOI.

PLOI Graphs

Let
s
be a planning state, and
G
be the goal condition and
O
the objects from the corresponding planning instance, and
P
the set of predicates from the corresponding planning domain.
We assume that all predicates are at most binary
3
3

3

Higher arity predicates can be compiled down to binary predicates but the compilation loses information
(
Chen, Trevizan, and Thiébaux 2024
, Theorem 4.4)
due to the two variable limitation of
\mathcal{C}_{2}
.

Then one defines the PLOI graph with node features and edge labels as the relational structure

\displaystyle\mathcal{A}_{\mathrm{PLOI}}=(O,P\cup P_{G}\cup\overleftarrow{P}\cup\overleftarrow{P_{G}},s\cup s_{G}\cup\overleftarrow{s}\cup\overleftarrow{s_{G}})

(2)

where

•

P_{G}
and
s_{G}
are the same as in
Equation

1
,

•

\overleftarrow{P}:=\left\{\overleftarrow{p}\mid p\in P,\text{$p$ is binary}\right\}
and similarly for
\overleftarrow{P_{G}}
, and

•

\overleftarrow{s}:=\left\{\overleftarrow{p}(o_{2},o_{1})\mid p(o_{1},o_{2})\in P\right\}
and similarly for
\overleftarrow{s_{G}}
.

Notably, the PLOI relational structure defined in
Equation

2
subsumes the relational structure for planning defined in
Equation

1
.
Now recall that
\mathcal{C}_{2}
features are defined from the planning structure.
Furthermore, GNNs can encapsulate
\mathcal{C}_{2}
logic with unary and binary relations defined from the graphs they operate on
(
Barceló et al. 2020
;
Grohe 2021
)
.
Thus, it is more sensible to view GNNs operating on the PLOI graph as better able to capture
\mathcal{C}_{2}
features for planning than R-GNNs.

5
Conclusion

We highlighted theoretically and empirically that Relational GNNs for planning (R-GNNs)
(
Ståhlberg, Bonet, and Geffner 2022
)
do not correspond with
\mathcal{C}_{2}
features for planning,
\mathcal{C}_{2}
logic where relations are defined by unary and binary planning domain predicates.
In light of this, we identify that a different GNN architecture, PLOI
(
Rivlin, Hazan, and Karpas 2020
;
Silver et al. 2021
)
, that better approximates
\mathcal{C}_{2}
features for planning.
