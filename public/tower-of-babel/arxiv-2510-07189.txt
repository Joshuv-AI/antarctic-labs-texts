Prompt, Synthesize, Fine-Tune: A Secure Code Generation Recipe
Junjie Li, Fazle Rabbi, Bo Yang, Song Wang, Jinqiu Yang

Abstract
Although Large Language Models (LLMs) show promising solutions to automated code generation, they often produce insecure code that threatens software security. Current approaches (e.g., SafeCoder) to improve secure code generation suffer from limited and imbalanced datasets, reducing their effectiveness and generalizability. In this work, we present Secure-Instruct, a novel framework that automatically synthesizes high‑quality vulnerable and secure code examples, generates fine‑tuning instructions, and instruction‑tunes LLMs to align task description and secure code generation abilities. We evaluate Secure-Instruct on four representative LLMs using two benchmarks: our own CWEBench and the existing CWEval. CWEBench comprises 93 scenarios on 44 CWEs, all without overlap with Secure-Instruct’s synthetic instruction‑tuning dataset, while CWEval covers 31 CWEs with 119 manually verified security‑critical tasks. We find that Secure-Instruct improves not only the security but also the functional correctness of the generated code. On CWEBench, Secure-Instruct substantially improves secure code generation, giving a 14.3% average increase in secure ratio over the pretrained models and outperforms SafeCoder by 7.6%. On CWEval, Secure-Instruct achieves a 14% increase for CodeLlama-7B and 5.8% for Mistral-7B in Func-Sec@1 over pretrained models, and surpasses SafeCoder by 15.8% and 6.8% respectively.

Improving LLMs for Better Code Generation.

Acquiring an effective and high-quality fine-tuning dataset from real-world sources is often expensive and labor-intensive. To address this challenge, researchers have explored methods for synthesizing datasets using large language models (LLMs). Recent advancements have introduced synthetic data generation techniques during fine-tuning to address data acquisition challenges and enhance LLM performance on specific tasks

.

Self-Instruct

Subsequent works extend this strategy to a broader range of models and tasks

;

Chaudhary 2023
;
Luo et al. 2023
;

)
uses ChatGPT to generate diverse instruction-following examples using carefully crafted prompts.
Wei et al.
Wei et al. 2024
proposed OSS-Instruct, a method that uses ChatGPT to generate diverse coding problems and solutions from seed code snippets from open-source code, to create a high-quality fine-tuning dataset to improve code generation accuracy.

Improving the Security of LLM Generated Code.

To address security problems in LLM-generated code, Li et al.
Li et al. 2024b
proposed an approach to fine-tune one LLM by using the vulnerability-fixing commits. Hajipour et al.
(
Hajipour et al. 2024
)
introduced a technique to synthesize secure code examples guided by CodeQL
(
CodeQL 2024
)
oracle. Another work
(
Li et al. 2024a
)
explored the effect of parameter-efficient fine-tuning techniques in secure code generation. He et al.
(
He and Vechev 2023
)
introduced SVEN, an advanced prompting method, i.e., prefix-tuning, that uses property-specific continuous vectors (prefixes) to guide LLMs to generate secure code and reduce the likelihood of generating vulnerable code. The training of SVEN optimizes these continuous vectors using a carefully curated, high-quality dataset.

The most recent work, SafeCoder
(
He et al. 2024
)
, proposes a security-focused instruction tuning approach that learns from vulnerable–fix code pairs mined from 145 million commits. Through semi-automated filtering, the authors curate a dataset of 465 high-quality code examples. Their findings show that the LLM fine-tuned on this data achieves state-of-the-art performance in secure code generation.

Despite improved results, SafeCoder has several limitations. First, the quality of code from open-source repositories is inconsistent, often involving complex dependencies with external libraries. As a result, many code snippets are unsuitable for fine-tuning, requiring significant manual effort to filter and curate appropriate samples. Second, it is challenging to obtain a sufficiently large fine-tuning dataset for each category of security issues (e.g., CWE). For example, the work
(
He et al. 2024
)
identified 71 code snippets for CWE-079 but only one for CWE-732, resulting in an imbalance that hinders the model’s ability to achieve robust security performance. Besides, this approach is expensive. They only collected 456 code snippets covering 23 CWEs from 145 million commits, making it difficult to expand to other CWEs.
To address these limitations, we propose Secure-Instruct to automatically construct a more extensive and diverse dataset to further enhance the security of LLM-generated code.

The Methodology of Secure-Instruct

We introduce Secure-Instruct, a framework that leverages LLMs (e.g., ChatGPT and Claude) to synthesize fine-tuning data for instruction-tuning code language models (CLMs) to enhance secure code generation.
Figure
2
shows an overview of Secure-Instruct.
It adopts two data-generation schemes, secure-code driven (Secure-Instruct
secure
) and vulnerable-code driven (Secure-Instruct
(vul, secure)
), to generate high-quality secure training data with no human intervention (Section
3.2
).
It then uses LLMs to generate natural-language instructions that describe the functionality of each code example in the dataset. Finally, Secure-Instruct applies two instruction tuning strategies to produce security-enhanced LLMs (Section
3.3

)

3.1
CWE Seeds Collection

First, we collect CWE documents from the MITRE. The MITRE is an official website that serves as an authoritative resource for understanding and analyzing Common Weakness Enumerations (CWEs). Each CWE entry on the website includes a comprehensive description, highlighting the nature of the vulnerability, its potential impact, and common scenarios in which it arises. Additionally, the entries feature illustrative code examples that contrast vulnerable and secure implementations, offering both context and practical insights.

Figure
3
presents an example of CWE-78 (OS Command Injection) from the MITRE website. This example includes a detailed overview of the weakness, an explanation of its root causes, and multiple code snippets demonstrating how this vulnerability can manifest in real-world software. These examples not only facilitate a deeper understanding of the security flaws but also serve as valuable references for LLMs to generate secure code examples. In particular, Secure-Instruct leverages the information from the MITRE website for each CWE, namely 1) the category of CWE, 2) the overall description, and 3) code snippet examples with their explanations.
In total, we collected 44 CWEs from MITRE.

Synthetic Data Generation By Prompting LLMs

Given seed CWE documents, Secure-Instruct employs two data generation strategies to prompt LLM for generating fine-tuning datasets, namely vulnerable-code driven (Secure-Instruct
(vul, secure)

Secure-Instruct
(vul, secure)

We employ two powerful LLMs for code generation, i.e., ChatGPT (gpt-4o-2024-08-06) and Claude (claude-3-5-sonnet-20241022), to generate intentionally vulnerable code snippets. Below, we show the prompt templates for generating and fixing vulnerable code.

For each pair of “CWE-ID” and “programming language”, Secure-Instruct
(vul, secure)

In total, Secure-Instruct
(vul, secure)

Then, Secure-Instruct
(vul, secure)
utilizes static security analyzers to verify the vulnerabilities present in the generated code.
Finally, we instruct the LLMs to fix the vulnerable code and verify that the vulnerabilities are gone using static security analyzers.

Since static analysis tools can produce both false positives and false negatives, we use two static security analyzers, CodeQL
(
CodeQL 2024
)
and SonarQube
(
SonarQube 2025
)

A code snippet is considered vulnerable only if both tools produce identical detection results.
However, while CodeQL supports all 78 CWE-language pairs, SonarQube only supports a subset of 41 pairs (i.e., 6 CWEs for C, 9 for Java, 12 for Python, 9 for JavaScript, 0 for Ruby, and 5 for Go).
For the cases not supported by SonarQube, Secure-Instruct solely relies on CodeQL.

After verification of the 1,560 snippets by static analyzers, 475 code snippets were confirmed to be truly vulnerable. These verified snippets then served as input seeds for the LLMs to generate five fixes for each snippet. Finally, static analyzers are used again to verify whether the generated fixes were valid.
In the end, Secure-Instruct
(vul, secure)
collected 856 pairs of vulnerable code and their corresponding fixed code, which cover 25 CWEs in 6 programming languages, i.e., 39 CWE-language pairs.

To source an even larger set of secure code snippets, we propose an alternative approach, Secure-Instruct

For each CWE-language pair, we generate 100 secure code snippets that pass verification by both CodeQL and SonarQube, ensuring they do not contain vulnerabilities.

4
Evaluation Setup

In this section, we describe our experimental setup.

Subject Large Language Models.

We evaluate Secure-Instruct to improve four representative small and medium-sized LLMs with 1 to 7 billion parameters: CodeGen2-7B
(
Nijkamp et al. 2023
)
, CodeLlama-7B
(
Roziere et al. 2023
)
, Mistral-7B
(
Jiang et al. 2023
)
, and StarCoder-1B
(
Li et al. 2023
)
. These models are specifically designed for code generation, offering a balance between computational efficiency and performance. These models are widely used in prior works on secure code generation, such as
(
He and Vechev 2023
;
He et al. 2024
;
Wei et al. 2024
)
for a fair comparison.

- CodeGen2-7B
is a language model specifically designed for program synthesis. Trained on the “The Stack” dataset
(
Kocetkov et al. 2022
)
, a comprehensive collection of diverse code repositories, CodeGen2 excels at generating and completing code snippets across multiple programming languages.

- CodeLlama-7B
is developed by Meta, builds upon the Llama 2
(
Touvron et al. 2023
)
architecture and is further fine-tuned specifically for code generation.

- StarCoder-1B
is trained on “The Stack 1.2” dataset, a collection of code data and natural language text from GitHub, including over 80 programming languages, and the text extracted from GitHub issues and commits.

- Mistral-7B
is developed by Mistral AI. It adopted Group-query attention (GQA) and sliding window attention (SWA) to increase the speed and lower the costs. It outperforms other models of the same size on a variety of benchmarks.

Details on Fine-Tuning LLMs.

We use the parameter-efficient fine-tuning technique, LoRA
Hu et al. 2021
, to fine-tune the 7B LLMs. LoRA fine-tuning reduces the GPU memory usage during fine-tuning and maintains a promising performance. For the 1B model, we apply full-weight fine-tuning. All fine-tuning experiments are conducted on five Nvidia RTX A6000 GPUs with 48GB of memory. For full-weight fine-tuning, we set the learning rate to 2e-5, while for LoRA fine-tuning, the learning rate is 3e-4. Each model is fine-tuned in 2 epochs. In LoRA fine-tuning, we configure the LoRA alpha to 16 to control the scaling of LoRA layers and set the dropout rate to 0.05.

De-duplication between fine-tuning datasets and evaluation benchmarks
.

To prevent data leakage between the fine-tuning dataset and the two benchmark datasets, we performed de-duplication between training and evaluation following
Zhou et al. 2025
.
Specifically, we used MinHash with Locality-Sensitive Hashing (LSH) to detect potential duplicates. Code snippets were grouped based on similarity, and pairs with a Jaccard similarity above 0.7 were flagged as potential duplicates. After that we removed these flagged snippets from the fine-tuning dataset.

RQ2: How is Secure-Instruct compared with the state-of-the-art (SOTA) approach in securing LLM-based code generation?

Motivation.

SafeCoder
(
He et al. 2024
)
represents the state-of-the-art in secure LLM-based code generation. It employs an automated pipeline to mine vulnerable code and corresponding fixes from a large corpus of open-source commits (145 million), followed by human intervention for post-processing and validation. The final dataset consists of (instruction, vulnerable code, secure code) triples used to fine-tune LLMs. In contrast, our proposed approach, Secure-Instruct , is a fully automated technique with zero human intervention. Given these fundamental differences, it is important to compare the performance of Secure-Instruct against SafeCoder to assess the effectiveness and scalability of our method.

Approach.

We further conducted a comparative analysis between Secure-Instruct
secure
and SafeCoder on CWEBench and CWEval.
In particular, we used the two released models, i.e., CodeLlma-7B and Mistral-7B, which were already fine-tuned by SafeCoder.
In CWEBench, there are 44 CWE types. However, the training dataset of SafeCoder does not include all of them.
SafeCoder was fine-tuned on a dataset containing 23 CWEs, whereas Secure-Instruct was fine-tuned on a dataset covering 44 CWEs.
There are 20 CWEs covered by both Secure-Instruct and SafeCoder.
We used the same configuration as described in the SafeCoder paper, namely a temperature of 0.8 and 100 samples for each security-specific scenario.

Results.

Table

shows that Secure-Instruct achieves higher Func-Sec@1 on CWEval than SafeCoder for both CodeLlama‑7B and Mistral‑7B.
Notably, SafeCoder exhibits a performance drop on CWEval.
For example, SafeCoder’s CodeLlama-7B achieves only 7.1% Func-Sec@1, which is lower than the pre-trained model.
A similar decline is observed in SafeCoder’s Mistral-7B.
These findings are consistent with the observations reported in the study
Peng et al. 2025

RQ3: Can the LLM fine-tuned by Secure-Instruct preserve the functional correctness in code generation?

Motivation.

A critical concern in fine-tuning LLMs in secure code generation is understanding how fine-tuning impacts the functionality of the generated code. While fine-tuning with secure code examples aims to improve the security aspects of the output, it may compromise the model’s ability to produce functionally correct code.

Approach.

The benchmark, CWEval, evaluates the functionality of generated code by test cases with the metric Func@1. Besides, we evaluate the fine-tuned models on HumanEval and MBPP, two widely used benchmarks for assessing code generation in Python.
For each task of HumanEval and MBPP, we generate 40 samples using both pre-trained and fine-tuned models and assess their functionality using the Pass@k metric, including Pass@1 and Pass@10.
Pass@k is a standard metric for evaluating code generation, which represents the probability that at least one of the
k
generated candidates for a given problem is correct.

6
Discussions

The accuracy of CodeQL.
In CWEBench, the ground-truth of security is based on CodeQL, which is a static tool and may produce false positives. To address this concern, we randomly sampled 291 code snippets labeled as secure by CodeQL from four models and manually verified their security. All sampled snippets were confirmed to be truly secure. Additionally, we used another benchmark, CWEval, which evaluates security through test cases, to further validate our results.

The similarity between Secure-Instruct’s fine-tuning datasets and our evaluation benchmark.
To clarify data leaks (i.e., overlap between fine-tuning dataset and benchmark), we performed a similarity analysis. Specifically, we first extracted all the secure code examples
from the CodeQL repository for the 44 CWEs of our benchmark.
Since most scenarios of the 44 CWEs are created based on the CodeQL repository, such secure code can be considered as ground-truth code for conducting such a similarity analysis.
We compare each LLM-generated secure code with the secure code examples from the CodeQL repository under the same CWE.
We then calculated the cosine similarity of each pair using TF-IDF embeddings
(
Sparck Jones 1972
)
.
As there exist multiple secure examples for one CWE in the CodeQL repository, we selected the highest score, as the similarity score for an LLM-synthesized secure code snippet.

Low cost of Secure-Instruct in generating fine-tuned datasets.
We show that Secure-Instruct is able to generate high-quality fine-tuning data with low monetary cost and no human intervention.
For example, when using ChatGPT (GPT-4o-2024-08-06), Secure-Instruct costs $114.09 USD for generating all secure code snippets.
Similarly, for Claude, the cost is $109.74 USD for generating all secure code snippets. Compared to manually curated datasets, this synthesis method is highly cost-efficient.
The cost per CWE-language is $2.87 USD.
Compared to our Secure-Instruct, prior work SafeCoder
(
He et al. 2024
)
imposes challenges on a high-efficient data curation process, i.e., a sharp reduction from hundreds of millions of code commits on open source repositories on GitHub to a total of 25,000 repositories that can be compiled and scanned by CodeQL for automatically detecting vulnerability-fixing commits, finally to merely 1,200 pairs of vulnerable and secure code examples.
In addition, SafeCoder relies on manual effort to identify 465 high-quality code samples from the 1,211 samples produced by the automated pipeline.
In contrast, Secure-Instruct demonstrates significant advancements in efficiency by reducing the time and cost required to construct high-quality datasets while maintaining a strong focus on generating reliable and secure code samples.

7
Threats to Validity

Internal Threats.

LLMs can produce different outputs for the same prompt. To prevent the huge variations, we set a large sample size to ensure the stabilization results. CWEBench relies on CodeQL to detect vulnerability. Such a static analyzer may produce false positives. Although we manually reviewed samples, misclassifications could still influence the conclusions. We performed de-duplication across both our fine-tuning dataset and evaluation benchmarks (CWEBench and CWEval). However, this process may fail to detect duplicates, leading to false negatives.

External Threats.

We follow prior work and choose LLMs with smaller parameter sizes to make fine-tuning feasible under limited computational resources.
Fine-tuning larger models, such as ChatGPT-4o, would incur significantly higher costs. As a result, we acknowledge that our findings may not fully generalize to larger LLMs, and we consider this a direction for future investigation. We include 44 distinct CWEs in this study, reflecting a broad range of vulnerabilities. However, numerous additional CWEs remain unaddressed in this study. Moreover, individual CWE can manifest in various real-world scenarios, further highlighting the complexity of comprehensive evaluation. To improve coverage, we expanded our security-sensitive prompts to incorporate additional CWEs beyond those included in earlier studies. Compared to prior work
(
Pearce et al. 2022
;
He and Vechev 2023
;
He et al. 2024
;
Li et al. 2024a
)
, our study evaluates a significantly greater number of CWEs, providing a more thorough assessment of generated code vulnerabilities. Future efforts should include broader CWEs.
Additionally, we include six programming languages in our evaluation benchmark. While these languages are highly popular and widely adopted in software development, our findings may not generalize to all programming languages. Future work should expand the language set to strengthen the robustness of the results.

8
Conclusion

In this paper, we proposed Secure-Instruct, a novel framework to improve LLM for secure code generation by harnessing LLMs for generating instruction tuning datasets.
Secure-Instruct overcomes the limitations of the state-of-the-art technique, particularly addressing dataset imbalance, inefficient data curation, and the significant manual effort required. Unlike existing approaches, Secure-Instruct can be easily adapted to support new CWEs. Additionally, we contribute CWEBench, the largest evaluation benchmark to date for secure code generation. Our evaluation shows that Secure-Instruct significantly improves the performance of four representative LLMs, achieving 14.3% more secure code on average on CWEBench and +5.3% Func-Sec@1 on average on CWEval. Compared to the state-of-the-art, Secure-Instruct demonstrates strong performance even with a smaller fine-tuning dataset, highlighting its scalability and efficiency. Finally, we show that LLMs fine-tuned with Secure-Instruct maintain comparable or improved functional correctness in generated code.
