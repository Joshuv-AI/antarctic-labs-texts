Light Tree Covers, Routing, and Path-Reporting Oracles via Spanning Tree Covers in Doubling Graphs
Hsien-Chih Chang, Jonathan Conroy, Hung Le, Shay Solomon, Cuong Than

Abstract
A ( 1 + " ) (1+\varepsilon) -stretch tree cover of an edge-weighted n n -vertex graph G G is a collection of trees, where every pair of vertices has a ( 1 + " ) (1+\varepsilon) -stretch path in one of the trees. The celebrated Dumbbell Theorem by Arya et al. [STOC’95] states that any set of n n points in d d -dimensional Euclidean space admits a ( 1 + " ) (1+\varepsilon) -stretch tree cover with a constant number of trees, where the constant depends on " \varepsilon and the dimension d d . This result was generalized for arbitrary doubling metrics by Bartal et al. [ICALP’19]. While the total number of edges in the tree covers of Arya et al. and Bartal et al. is O ⁡ ( n ) O(n) , all known tree cover constructions incur a total lightness of ⁡ ( log ⁡ n ) \Omega(\log n) ; whether one can get a tree cover of constant lightness has remained a longstanding open question, even for 2-dimensional point sets. In this work we resolve this fundamental question in the affirmative, as a direct corollary of a new construction of ( 1 + " ) (1+\varepsilon) -stretch spanning tree cover for doubling graphs; in a spanning tree cover, every tree may only use edges of the input graph rather than the corresponding metric. To the best of our knowledge, this is the first constant-stretch spanning tree cover construction (let alone for ( 1 + " ) (1+\varepsilon) -stretch) with a constant number of trees, for any nontrivial family of graphs. Concrete applications of our spanning tree cover include: 1. A ( 1 + " ) (1+\varepsilon) -stretch tree cover construction, where both the number of trees and lightness are bounded by O ⁡ ( 1 ) O(1) , for doubling graphs. In doubling metrics, we can also bound the maximum degree of each vertex by O ⁡ ( 1 ) O(1) (which is impossible to achieve in doubling graphs). 2. A compact ( 1 + " ) (1+\varepsilon) -stretch routing scheme in the labeled model for doubling graphs, which uses the asymptotically optimal (up to the dependencies on " \varepsilon and d d ) bound of O ⁡ ( log ⁡ n ) O(\log n) bits on all the involved measures (label, header, and routing tables sizes). This is a significant improvement over the works of Chan et al. [SODA’05], Abraham et al. [ICDCS’06], Konjevod et al. [SODA’07], where the local memory usage either depends on the aspect ratio of the graph or is ⁡ ( log 3 ⁡ n ) \Omega(\log^{3}n) . 3. The first path-reporting distance oracle for doubling graphs achieving optimal bounds for all important parameters: O ⁡ ( n ) O(n) space, ( 1 + " ) (1+\varepsilon) -stretch, and O ⁡ ( 1 ) O(1) query time for constant d d and " \varepsilon .

Tree covers.

While a spanner is a sparsifier that guarantees compactness (via sparsity and lightness), a
tree cover

Formally, a tree cover of a graph

d_{T}(u,v)\leq t\cdot d_{G}(u,v)

The number of trees in the cover measures the

The structural simplicity of tree covers makes them a powerful tool for a wide range of applications where spanners fall short

In contrast, routing schemes for tree covers are significantly simpler, as they reduce to the problem of routing on trees, where optimal routing schemes are known. Distance oracle construction is another application of tree cover: one could get a compact distance oracle for the input graph or metric space by constructing a distance oracle for every tree in the cover, which reduces to constructing a lowest common ancestor (LCA) data structure. Spanning tree cover.

We say that a tree cover
\mathcal{T}
is a
spanning tree cover
of a graph
G
if every tree in
\mathcal{T}
is a spanning subgraph of
G

(Clearly, the notion of spanning tree cover only applies to graphs.)
The
doubling dimension of a graph

is the doubling dimension of its shortest path metric.
Our goal is to construct a spanning
(1+\varepsilon)
-tree cover with small sparsity (small number of trees) for a graph
G
with a constant doubling dimension
d

[

]

All existing techniques
[

,
CCL+24b
,
CCL+23

BFN22

are effective for constructing
(1+\varepsilon)
-tree cover for
metric spaces
.
These techniques, when tailored to the graph setting, will produce trees that contain edges and vertices that do not belong to the input graph (called
Steiner edges
and
Steiner vertices
), which are forbidden in a spanning tree cover.
A natural idea is to replace a Steiner edge with a corresponding shortest path between the two endpoints.
The issue is that there could be multiple Steiner edges in a single tree, and doing multiple replacements may create cycles.
The fact that replacing Steiner edges with shortest paths does not work is hardly surprising: this is the key issue whenever one tries to construct a spanning version of a non-spanning object.
A prime example is designing metric embedding into non-spanning trees vs spanning trees: the well-known FRT embedding
[
FRT04
]
gives a stochastic embedding of arbitrary graphs and metric spaces into a non-spanning tree with (optimal) expected distortion
O(\log n)
, while if one insists on an embedding into a
spanning
tree, the best known expected distortion is
O(\log n\log\log n)

[
AN19
]
despite significant research efforts and innovative technical ideas aimed at closing the gap
[
EEST08
,
ABN08
,
KMP11
,
AN19
]

Here, we construct a spanning tree cover for doubling graphs based on two ideas: (i) a family of hierarchical partitions with
strong diameter
guarantee and (ii) a collection of shortest paths that serve as a distance sketch called a
preservable set
.
Idea (i) partly imitates the construction of non-spanning tree cover
[
BFN22
]
; the difference here is that our clusters in the hierarchies of partitions have strong diameter guarantee so that the tree cover we build has the option to take the edges of the input graph, even though naively doing so will blow up the stretch to
\Omega(\log n)
.
Idea (ii) is the most innovative one: roughly speaking, when we recursively construct a subtree of a given cluster, the preservable set technique seeks to preserve
two shortest paths
(one of which is outside the cluster) in the recursion.
One path plays the role of the “spine” or “highway” in the subtree, and the other path preserves the distance between a dedicated pair of vertices whose distance scale is the same as the scale of the cluster. The former path guarantees that the recursion does not blow up the diameter of a cluster when we replace the cluster with a recursively constructed spanning subtree, while the latter path guarantees the stretch
1+\varepsilon
for the dedicated pair.
(See
Section

2
for a more in-depth technical overview.)
A surprising fact, perhaps, is that preserving a single shortest path is not sufficient to get a stretch of
1+\varepsilon
while preserving three or more paths seems impossible because they could form cycles.
That is, our technique hits a sweet spot where preserving two paths is doable and, at the same time, sufficient for our purpose.
Our end result is the first spanning tree cover for doubling graphs with a small number of trees.

Consider a distributed network of vertices in which each vertex has an arbitrary

A

The most basic trade-off is between the

stretch

Other important quality measures are the sizes of

Another important advantage of our routing scheme over previous ones is that, loosely speaking,

We achieve this using an appropriate labeling scheme, described in

In the second stage we route on top of that tree.

Path-reporting distance oracle.

An
approximate distance oracle with stretch
t
for an edge-weighted graph
G
is a compact data structure for answering distance queries: given any two vertices
u
and
v
in
V_{G}
, return a distance estimate
\tilde{d}(u,v)
such that
d_{G}(u,v)\leq\tilde{d}(u,v)\leq t\cdot d_{G}(u,v)
. A distance oracle is
path-reporting
if, in addition to the distance estimate
\tilde{d}(u,v)
, the oracle returns a path
\tilde{P}(u,v)
in
G
of length
\tilde{d}(u,v)
.
The
query time
of a path-reporting distance is
q
if for every pair
(u,v)
, it outputs
\tilde{P}(u,v)
in time
q+O(|\tilde{P}(u,v)|)
, where
|\tilde{P}(u,v)|
is the number of edges in
\tilde{P}(u,v)
.
(It is often the case that reporting
\tilde{P}(u,v)
takes more time than computing the distance estimate
\tilde{d}(u,v)
, and hence the query time definition focuses only on the time it takes to find
\tilde{P}(u,v)
.)

A distance oracle construction often exhibits a trade-off between the space, stretch, and query time. The
space
of a distance oracle is the number of machine words needed to store the oracle. In general graphs, the seminal result by Thorup and Zwick
[
TZ05
]
gives the first path-reporting distance oracle (PRDO) with space
O(k\cdot n^{1+1/k})
, stretch
2k-1
, and query time
O(k)
for any given positive integer parameter
k
. The query time then was improved to
O(\log k)
by Wulff-Nilsen
[
WN13
]
, but the space remained
O(k\cdot n^{1+1/k})
.
One important question from a practical point of view is to construct a PRDO with
linear space
and
O(\log n)
stretch and query time
.
Regardless of the choice of stretch parameter
k
, the oracle by Thorup and Zwick
[
TZ05
]
(and Wulff-Nilsen
[
WN13
]
) has space
\Omega(kn^{1+1/k})=\Omega(n\log n)
. Various attempts have been made to answer this question
[
WN13
,
EP16
,
ENW16
,
ES23
,
NS24
,
CZ24
]
, leading to the recent result by Chechik and Zhang
[
CZ24
]
who constructed an oracle with
O(n)
space,
O(\log n)
stretch and
O(\log\log\log n)
query time.

In the linear space regime, it is not possible to obtain stretch below
O(\log n)
for general graphs, even for non-path-reporting oracle
[
TZ05
]
. On the other hand, a practical distance oracle should ideally have stretch
1+\varepsilon
for any given fixed

[
AGGM06
,
FM20

KSGKSS24
]

In this setting, Filtser

and query time

While the space of Filtser’s oracle is super-linear, the distortion is better than
O(\log n)
for constant doubling dimension. On the other hand, a

distance oracle with

and
1+\varepsilon
stretch for a constant

[

]
(it should be noted that Filtser’s construction has a polynomial dependence on the dimension, which is better than the exponential dependence in
[

BKG11
]

We will construct an

To motivate the following definition, we draw analogy to the quadtree construction

3.2
Preservable sets

Let
\widehat{G}
be a subgraph with diameter

of a graph

Let
\mathcal{C}
be a clustering of
\widehat{G}
into clusters of strong diameter

. Let
\pi
be a path in
G

not necessarily contained in
\widehat{G}
, such that
\pi
is a shortest path in the graph
\widehat{G}\cup\pi
.
We emphasize again that

may not be in the subgraph

\widehat{G}\cup\pi
in the definitions below.

Definition 3.7
(Preservable set)

Fix a graph
\widehat{G}
, clustering
\mathcal{C}
, and path
\pi
. Let
\mathcal{P}
be a set of paths in the graph
\widehat{G}\cup\pi
.
We say that
\mathcal{P}
is a
preservable set
with respect to
(\widehat{G},\mathcal{C},\pi)
if:

1.

Every cluster is
touched
by
exactly one
path in
\mathcal{P}
.
That is, for every cluster
C\in\mathcal{C}
, there exists a unique path
\pi_{C}
in
\mathcal{P}
such that
C\cap V(\pi_{C})\not=\varnothing
.
In particular, this means that the collections of subsets of clusters touched by every path in
\mathcal{P}
are pairwise disjoint, and paths in
\mathcal{P}
are vertex-disjoint paths.

2.

\pi
itself is in the preservable set
\mathcal{P}
.

3.

For every
C\in\mathcal{C}
,
\pi_{C}
is a shortest path in
\widehat{G}[C]\cup\pi_{C}
.

We call
\mathcal{P}
a preservable set because, when we construct a tree
T
for our tree cover (in Section
3.3
) via a recursive procedure, we will be able to guarantee that every path in
\mathcal{P}
is in the tree
T
— that is, the tree
T

preserves
these paths. We now give a definition and lemma which let us choose a “good” set of paths to preserve — that is, a preservable set which helps to satisfy the distortion guarantee of tree cover.

Definition 3.8
(Sketch graph)

Let
\mathcal{P}
be a preservable set with respect to
(\widehat{G},\mathcal{C},\pi)
,
and let
I
be a set of
inter-cluster edges
from
\widehat{G}
with respect to
\mathcal{C}
(that is, no edge has both endpoints in the same cluster of
\mathcal{C}
).
The sketch graph
\operatorname{sketch}(\mathcal{P},I)
is a graph with vertex set
V(\widehat{G}\cup\pi)
and edge set that is comprised of the following:

1.

Take all edges in all paths of
\mathcal{P}
.

2.

For every cluster
C
in
\mathcal{C}
,
for every vertex
v
in
C
, add a
fake edge
between
v
and the closest vertex in
\pi_{C}\cap C
with weight
10\cdot\varepsilon D
.
(Recall
\pi_{C}
is the unique path in
\mathcal{P}
touching
C
, if exists.)

3.

Add the inter-cluster edges
I
to form the final sketch graph
\operatorname{sketch}(\mathcal{P},I)
.

If there are no cycles in
\operatorname{sketch}(\mathcal{P},I)
, we say the sketch graph and the inter-cluster edges

are

.

We observe that a cycle-free sketch graph

is always a forest, but not a spanning forest because of the fake edges.
Intuitively, we will later replace the fake edges within each cluster

with a spanning tree

constructed recursively on

and
\pi_{C}
; this will ensure that together with some inter-cluster edges, we have a spanning tree
for
\widehat{G}
and
\pi
. For each cluster in a HP, we consider it as an induced subgraph of
G
and use the same notation for the induced subgraph and the cluster.

3.3

To construct a

-stretch spanning tree cover, we use the procedure SpanTreeCover
(G)
