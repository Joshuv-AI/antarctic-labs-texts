tanggle: An R package for the visualization of phylogenetic networks
Authors: Klaus Schliep, Marta Vidal‐García, Leann Biancani, L. Francisco Henao‐Díaz, Eren Ada, Joshua Justison, Claudia Solís‐Lemus
Published: 2026

ABSTRACT
AbstractPremisePhylogenetic trees depict evolutionary relationships among taxa. However, they are strictly bifurcating structures that do not take into account several types of evolutionary events such as horizontal gene transfer, hybridization, or introgression. Although the development of new methods in phylogenetic networks has recently increased, limited visualization software is available to plot the phylogenetic networks.Methods and resultsHere, we present the R package tanggle, a visualization package for phylogenetic networks. Our package extends the widely used visualization package ggtree and allows a variety of input data from DNA sequences to extended Newick format; it also builds on the flexibility of ggplot2 to manipulate colors and other plot characteristics. In addition, our package allows for the inclusion of images and mapped morphological and geographical characteristics on the network.ConclusionsIn response to growing demands for reproducible, open‐source research, tanggle facilitates the production of script‐based, publication‐quality figures rather than graphics manually created with design software. By embedding figure code and metadata directly within analysis pipelines, tanggle improves transparency, traceability, and version control; enables automated regeneration of figures as data or methods change; and simplifies sharing and reuse of visualizations.

Recent years have seen an explosion of phylogenetic network inference methods (for a recent review, see Kong et al., 2025), which fall broadly into two complementary classes: implicit (split) networks and explicit networks. Split networks provide fast, visually intuitive summaries that scale readily to large datasets and are well suited to exploratory analysis. For example, in Figure 1B, there are two possible ways to resolve the uncertain split: (1) by considering the longer edges of the rectangle to be the correct split and collapsing the shorter edges (making C, D and A, B sister species) or (2) by considering the shorter edges of the rectangle to be the correct split and collapsing the longer edges (making A, D and B, C sister species). Explicit networks are directed models of reticulation that aim to recover hybridization or introgression events and estimate parameters such as inheritance proportions and branch lengths under an explicit evolutionary model (e.g., approaches based on the multispecies network coalescent). For example, in Figure 1A, the hybrid node (where the green arrow is pointing) corresponds to some reticulation event and the tree nodes correspond to speciation events. Hybrid edges are parametrized by an inheritance probability (γ) that can provide information on the proportion of genes that were transferred through the hybrid edge (green arrow). For example, an estimated γˆ≈0.5 could indicate hybrid speciation, whereas a smaller estimated γˆ≈0.01 could refer to horizontal gene transfer (but see Kong et al., 2025 for pitfalls interpreting the γ parameter). The split vs. explicit network paradigms differ in their biological interpretability and computational demands. Explicit networks offer an interpretable representation of processes such as hybrid speciation, introgression, allopolyploidy, or horizontal gene transfer, phenomena that are well documented in groups ranging from hybridizing plants to introgressing animal radiations and recombining microbes. Conversely, split networks provide an efficient, model‐free depiction of conflicting signals that is often preferred for large or exploratory datasets.

Explicit and implicit representations of phylogenetic networks. (A) An explicit network where internal nodes represent biological processes (e.g., tree nodes correspond to speciation events and hybrid nodes correspond to reticulation events). In addition, hybrid edges (green arrow) have a numerical parameter (inheritance probability) that represents the proportion of genes transferred through the arrow (here 17%). (B) A split network where split configurations are represented as parallel lines representing discordance in the input data (sequences or gene trees). It is not possible to know the specific source of the discordance (e.g., estimation error, incomplete lineage sorting, or gene flow).

Alongside the development of methods to reconstruct phylogenetic networks, multiple plotting options are now available (Table 1). Here, we introduce tanggle, a novel R package that extends ggtree (Yu et al., 2017) to plot split and explicit networks. The main advantage of tanggle over other existing plotting software is that it allows seamless, flexible, and fully reproducible incorporation of metadata directly into network visualizations using the same code that generates the phylogeny, building on ggtree's metadata‐driven approach for trees and extending it to networks. The package ggtree itself builds on the R package ggplot2, which implemented ideas from the influential book the Grammar of Graphics (Wilkinson, 1999), and as such, it provides a whole philosophy for composing sophisticated graphics. While this manuscript was under review a similar plotting tool was published (ggret; Specht et al., 2025). We provide a benchmark comparison with this other package in the project repository, and note that while both methods perform well for explicit networks, ggret does not support plotting split networks, whereas tanggle does.

Our package tanggle builds on other existing popular R packages such as ape (Paradis and Schliep, 2019) and phangorn (Schliep, 2010), using the functions and the data structures defined therein. The class “phylo” is the main data structure to store phylogenetic trees in R and is extended in two ways: (1) with the class “evonet” for explicit networks defined in ape along with functions to import and export these data as extended Newick format and (2) with the class “networx” for split networks defined in phangorn along with functions to import or export networks in NeXus format and different algorithms to infer split networks (e.g., consensus networks [Holland et al., 2004], NeighborNet [Bryant and Moulton, 2004]). Methods to plot implicit and explicit networks have already been available using base R graphics in ape and in the rgl package (Murdoch and Adler, 2021) within phangorn to plot interactive three‐dimensional split networks. These functions, however, do not allow the flexibility of ggplot2 for metadata and visual formatting, which is what tanggle provides.

METHODS AND RESULTS

The tanggle package extends the already widely used visualization package ggtree (Yu et al., 2017) to implicit and explicit phylogenetic networks.

Functions in tanggle

Currently, the following five functions are available in the tanggle package. There are two main functions: ggsplitnet, which plots split networks, and ggevonet, which plots explicit networks. There are also three secondary functions, which are mainly called internally by the two primary functions: 1. geom_splitnet provides a geom object for plotting split networks. It is called by ggsplitnet(net), which is a shortcut for ggplot(net) + geom splitnet.2. node_depth_evonet can be used to assign edge length to an explicit network. The function is called by ggevonet if no edge lengths are provided.3. minimize_overlap reduces reticulation lines crossing over in explicit networks. This function is by default called in the function ggevonet by the argument min_crossing.

Reconstructing and plotting a split network

In addition to plotting, the tanggle package can reconstruct split networks. There are three types of input data that our package takes to reconstruct a split network: 1.A NeXus file created with SplitsTree (Huson, 1998), which is read with the read.nexus.networx function in the phangorn package (Schliep, 2010).2.A collection of gene trees in a NeXus file, or in a text file with one row per gene tree in Newick format. These trees are read with the functions read.tree or read.nexus. A consensus split network is then computed using the consensusNet function in the phangorn package, which implements the algorithm in Holland et al. (2004).3.Sequences in NeXus, FASTA, or PHYLIP format read with the read.phyDat function in the phangorn package or the read.dna function in the ape package (Paradis and Schliep, 2019). Distance matrices are computed for specific models of evolution using the function dist.ml from the phangorn package or the function dist.dna from the ape package. From the distance matrix, a split network is reconstructed using the neighborNet function in the phangorn package, which implements the algorithm in Bryant and Moulton (2004). In this case, there is the additional option to estimate branch lengths (which is not usually the case for split networks) with the function splitsNetworks in the phangorn package.

After any of these three steps, a “networx” object represents a split network by two matrices: (1) a standard edge matrix with two columns for the two nodes connecting every edge (row) and (2) a split vector with an integer identifier for every edge. Each entry in the split vector represents the split for that edge. In split networks, there are more edges than splits as two (or more) edges could represent the same split (see Figure 1, where parallel edges represent the same split).

The ggsplitnet function takes a “networx” object as input and produces a plot. In Figure 2, we show the split network corresponding to the yeast dataset produced in the phangorn package using the code to the left of the plot.

Plotting explicit networks

Algorithms to reconstruct explicit networks are more computationally intensive than those to reconstruct split networks. Thus, to the best of our knowledge, there are no R functions that would estimate an explicit network from sequences or from gene trees. To obtain an explicit network, users need to use existing tools like PhyloNet (Yu et al., 2014; Wen et al., 2016; Wen et al., 2018), BEAST (Zhang et al., 2017), or SNaQ (Solís‐Lemus and Ané, 2016). These methods take sequences or gene trees as input and estimate an explicit network, which is represented in extended Newick format (Appendix S1). The explicit network is then read with the function read.evonet in the ape package and an “evonet” object is created.

The original “phylo” class is the internal graph presentation for a phylogenetic tree in ape. It contains a matrix, where each row is a pair of vertices representing an edge and a vector of tip labels. Additionally, “phylo” objects can contain a vector of weights for the edges and a vector of labels for internal nodes. The “evonet” object has two matrices: (1) a standard edge matrix with two columns for the two nodes connecting every edge (row) and (2) a hybrid edges matrix with two columns for the nodes connected by the hybrid edge (row). In Figure 3, we show an explicit network for a toy example in extended Newick format produced using the code to the left of the figure. Hybrid edges are drawn as dotted lines by default to distinguish them from the tree edges.

Applications to real data: Helianthus (Asteraceae)

We illustrate the use of tanggle with the sunflower genus Helianthus (Asteraceae) dataset in Stephens et al. (2015). Helianthus is highly diverse both phenotypically and genetically. To address this variation, Stephens et al. (2015) assembled the most comprehensive Helianthus dataset to date using a target enrichment approach across 37 diploid species/subspecies (103 accessions), capturing 170 nuclear loci. Phylogenetic inference with both coalescent‐ and concatenation‐based methods produced largely congruent results, recovering a strongly supported large annual clade and two principal perennial clades (a southeastern perennial clade and a clade of primarily large‐statured perennials). However, several deeper relationships, notably the placements of H. agrestis Pollard, H. cusickii A. Gray, H. gracilentus A. Gray, H. mollis Lam., and H. occidentalis Riddell, exhibited low support and were inconsistent among analyses. This discordance motivates the application of phylogenetic network approaches: the observed conflict and reduced support at the bases of the perennial clades can be consistent with ancient introgression and emphasizes the difficulty of reconstructing relationships in a highly reticulate group. While explicit phylogenetic networks are the preferred representation for reticulate evolutionary histories (Kong et al., 2025), explicit network inference for all 37 species is computationally intensive and beyond the scope of the present study. Thus, we generated a split network derived from the estimated gene trees using the tanggle toolkit; this is displayed, along with other examples of explicit networks, in Appendix S1.

Here, we used the set of 54 gene trees that contained all species to estimate and plot the consensus split network for the Helianthus group with tanggle (Figure 4). The collection of gene trees is stored in the Helianthus.trees file, and the Figures folder contains the sunflower images as JPG files using the same filenames as the taxon names in the network. For example, the image for H. salicifolius should be in the file H_salicifolius.jpg inside the Figures folder. A consensus network (Holland et al., 2004) is a generalization of a (majority) consensus tree. Instead of only representing splits (taxon bipartitions) occurring in at least 50% of the trees in a bootstrap or Markov chain Monte Carlo sample, one can use a lower threshold (e.g., 10% in the example in Figure 4) and explore competing splits.

CONCLUSIONS

Evidence of reticulate evolution across multiple domains in the tree of life has brought considerable attention to the area of phylogenetic networks, including new methods to reconstruct networks as well as extensive research on the evolution of traits in phylogenetic networks via comparative methods (Jhwueng and O'Meara, 2015; Bastide et al., 2018). Our R package tanggle is not the first software for the visualization of networks. Dendroscope (Huson et al., 2007) and SplitsTree (Huson, 1998) are the pioneers of network visualization, with multiple functionalities being added constantly. In R, the widely used ape package (Paradis and Schliep, 2019) has extended the base plot function to visualize explicit networks, but it does not yet provide functionalities to plot implicit networks. In Julia, PhyloPlots is the accompanying package of PhyloNetworks (Solís‐Lemus et al., 2017) and is able to plot rooted explicit networks, but is not able to plot implicit or unrooted networks.

The tanggle package complements the ape plotting function in two main ways: (1) by making it possible to plot implicit networks and (2) by building on ggtree (Yu et al., 2017) (which in turn builds on ggplot2 [Wickham, 2016]) to manipulate the structure, nodes, and edges in the network. With the increased (and timely) pressure for reproducible research, limiting the use of design software like Adobe Illustrator to produce publication figures is paramount. The R package ggtree and now tanggle work towards script‐based publication figures that can incorporate colors, images, and mapped morphological and geographical characteristics. Furthermore, ggtree and thus tanggle are based on underlying data frames to represent the phylogenies, which allows considerable flexibility on mapped traits, colors, and linetypes.
