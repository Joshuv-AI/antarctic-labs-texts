Adversary Resilient Learned Bloom Filters
Ghada Almashaqbeh, Allison Bishop, Hayder Tirmazi

Abstract
A learned Bloom filter (LBF) combines a classical Bloom filter (CBF) with a learning model to reduce the amount of memory needed to represent a given set while achieving a target false positive rate (FPR). Provable security against adaptive adversaries that advertently attempt to increase FPR has been studied for CBFs, but not for LBFs. In this paper, we close this gap and show how to achieve adaptive security for LBFs. In particular, we define several adaptive security notions capturing varying degrees of adversarial control, including full and partial adaptivity, in addition to LBF extensions of existing adversarial models for CBFs, including the Always-Bet and Bet-or-Pass notions. We propose two secure LBF constructions, PRP-LBF and Cuckoo-LBF, and formally prove their security under these models assuming the existence of one-way functions. Based on our analysis and use case evaluations, our constructions achieve strong security guarantees while maintaining competitive FPR and memory overhead.



1
Introduction

Bloom filters are probabilistic data structures that allow building a succinct representation of a data set while offering approximate membership queries, i.e., whether an element
x
is in a set
S
. Bloom filters have one-sided error guarantees: if
x\in S
the filter always returns yes (i.e., no false negatives), but if
x\notin S
, the filter may return yes, instead of no, with some probability resulting in a false positive. Bloom filters greatly improve space efficiency; instead of storing the full set, this set is encoded in a much shorter bit string using a family of hash functions to map each item into a few bits (set to 1) in this string
[
3
]
.

Learned Bloom filters (LBFs) have been introduced to improve upon conventional, or classical Bloom filters (CBFs)
[
14
]
. In particular, and as shown in Figure
1
, an LBF combines a learning model with a CBF to obtain a lower false positive rate (FPR) than CBFs under the same memory budget. The learning model acts as an initial filter, providing a probabilistic estimate on whether
x\in S
, while a smaller CBF serves as a backup to prevent any false negatives.

Bloom filters are used in various practical applications, including Linux network drivers, network protocols, deep packet scanners, peer-to-peer networking, and caching
[
28
,
3
]
. Many well-known systems, such as Apache Hadoop, Apache HBase, Google BigTable, Google LevelDB, and Meta RocksDB, use Bloom filters as part of their implementations. As LBFs provide the same one-sided error guarantees as CBFs, the applications of LBFs and CBFs are identical. Recently, Roblox used LBFs to achieve 25% cost savings in their production workloads for Spark join queries
[
16
]
.

In such critical infrastructures, adversaries may attempt to craft false positives, causing the Bloom filter to deviate from its expected behavior
[
10
]
, thereby disrupting system operation. For example, as discussed in
[
20
]
, in a Bloom filter-based spam email whitelist (that stores addresses of known senders), crafting false positives allows spam emails to pass as benign emails. Similarly, in web caches, a Bloom filter can be used to represent the web pages in the cache; a false positive causes an unsuccessful cache access, which degrades performance and may eventually cause a denial of service attack. Another case is related to databases
[
29
]
, including Meta’s RocksDB and Google’s LevelDB; crafting false positives in the Bloom filters of RocksDB (respectively LevelDB) can degrade the performance of query lookups by up to 8x (respectively 2x).

These cases attest to the importance of studying provable security for Bloom filters against adaptive adversaries. This has been done for CBFs, including studying practical attacks
[
10
]
, and formalizing notions for adaptive security alongside showing new CBF constructions that realize these notions
[
20
,
21
]
. However, to the best of our knowledge, no such notions/provably-secure constructions exist for LBFs. Indeed, as an LBF contains a backup CBF, it inherits all the adversarial vulnerabilities of CBFs. However, securing the backup CBF does not imply that the LBF employing this CBF is secure, as LBFs have different designs. That is, having a learning model allows adversaries to craft false positives in new ways
[
23
]
. Examples include mutating an existing false positive or modifying certain features (relevant to the learning model) of a true negative input to convert it into a false positive. Nonetheless, the work
[
23
]
only demonstrated such attacks while leaving provable adaptive security of LBFs as an open problem.

1.1
Contributions

In this paper, we close this gap and initiate a formal study on the security of LBFs against adaptive adversaries. In particular, we make the following contributions.

New notions for adaptive security.
We define several new security notions for LBFs that capture a spectrum of adversarial capabilities. These include
fully-adaptive
adversaries who choose all queries,
partially-adaptive
adversaries who choose a fraction of queries,
bet-or-pass
adversaries who can selectively choose to output a guess in the security game, and
always-bet
adversaries who always output a guess (the latter two are inspired by similar models defined for CBFs
[
21
]
). These models provide fine-grained understanding of the attack surface against LBFs and several security-efficiency tradeoffs. Moreover, we explore the relationships between these various notions, proving which security notions imply which. We believe that our notions contribute to establishing a foundation for analyzing learning-augmented data structures in adversarial settings.

Constructions.
We propose two constructions for LBFs: PRP-LBF and Cuckoo-LBF. Our constructions extend a prior LBF variant called Partitioned LBFs
[
30
]
by introducing cryptographic hardness through pseudorandom permutations (PRPs) and pseudorandom functions (PRFs). Assuming one-way functions exist, we show that PRP-LBF achieves security under the fully-adaptive and partially-adaptive adversarial models. We also show (assuming one-way functions) that Cuckoo-LBF satisfies the bet-or-pass security notion (the extended notion for LBFs). Bet-or-pass is one of the strongest adversaries considered by prior work
[
21
,
15
]
for CBFs. Our constructions require only
\mathcal{O}\left(n\log{\frac{1}{\varepsilon}}+\lambda\right)
additional bits of memory, where
n
is the cardinality of the set represented by the filter,
\varepsilon
is the desired FPR, and
\lambda
is the security parameter.

Performance evaluation
. We analyze FPR of our constructions in both adversarial and non-adversarial settings. Our results show that LBFs can provide lower FPR than CBFs in realistic workloads using the same memory budget. They also show that our LBF constructions achieve better FPR-memory tradeoffs than prior CBF constructions while maintaining strong security guarantees. These results demonstrate that adversarial resilience can be supported for LBFs with minimal performance overhead.

1.2
Related Work

Security of Classical Bloom Filters.
Gerbet et al.
[
10
]
demonstrate practical attacks on CBFs in the context of web crawlers and spam email filtering, and propose combining universal hash functions with message authentication codes to mitigate a subset of these attacks. Naor et al.
[
20
]
define an adversarial model for CBFs and show that for computationally bounded adversaries, non-trivial adversary
resilient CBFs exist if and only if one-way functions exist, and that for computationally unbounded adversaries there exists a CBF
that is secure when the adversary makes
t
queries while using only
\mathcal{O}(n\log\frac{1}{\varepsilon}+t)
bits of memory.

Clayton et al.
[
4
]
and Filic et al.
[
8
]
present stronger adversarial models than
[
20
]
, giving the adversary the capability of performing insertions and accessing the internal CBF state, and they show secure CBF constructions realizing these models. Naor and Oved
[
21
]
introduce a comprehensive study of CBF security and define several robustness notions in a generalized adversarial model. Concretely,
[
21
]
calls the notion of
[
20
]
as
Always-Bet (AB)
test since the adversary must output a guess. Then, it introduces a new, strictly stronger, security notion called the
Bet-Or-Pass (BP)
test, giving the adversary the option to pass without outputting a guess. Lotan and Naor
[
15
]
provide further results related to relationships between the security notions of
[
21
]
.

Security of Learned Bloom Filters.
LBFs were first introduced by Kraska et al.
[
14
]
who showed that LBFs can offer better FPR vs. memory tradeoffs than CBFs. Mitzenmacher
[
18
]
provides the first rigorous mathematical model for LBFs, focusing on analyzing performance in terms of memory size and FPR, and introduces an LBF variant called Sandwiched LBF. Vaidia et al.
[
30
]
introduce another LBF variant, called partitioned LBFs (PLBFs). PLBFs use a learning model to partition the set
S
into
p\in\mathbb{N}
partitions and use a separate backup CBF for each of the
p
partitions. PLBFs reduce the FPR for specific partitions compared to original LBFs that employ only one backup CBF.

All these works only examine performance, but not security. We are only aware of one prior work that studied LBFs in adversarial settings: Reviriego et al.
[
23
]
demonstrate practical attacks on LBFs, which, as mentioned earlier, rely on exploiting the learning model to craft false positives in new ways. In response, they propose two potential mitigations: the first relies on switching back to a CBF once an attack is detected, while the second adds a second backup CBF. However, Reviriego et al.
[
23
]
do not provide provable security guarantees for the suggested mitigations, or even empirical evaluations of their effectiveness, and leave provable security of LBFs as an open problem.

1.3
Future Directions

Our work offers important foundational steps towards understanding provable security of LBFs. Here, we list some natural directions for future work.

Unsteady setting.
We provide secure constructions for LBFs in which the query algorithm
does not
modify the internal representation of the LBF. Naor and Yogev
[
20
]
call this the
steady
setting, and show secure CBF constructions for the
unsteady
setting where the query algorithm changes the internal filter representation after each query. An interesting direction is to build LBF constructions and prove their adaptive security in the unsteady setting.

Dynamic Bloom filters.
As opposed to static Bloom filters, which do not modify the input set
S
after construction, dynamic Bloom filters allow insertions of new elements
S^{\prime}=\{x\}\cup S
after construction. Note that to maintain their one-sided error guarantees, even dynamic Bloom filters do not allow deletions. Similar to prior work
[
20
,
21
,
15
]
that consider static CBFs, our work focuses on static LBFs. Clayton et al.
[
4
]
and Filic et al.
[
8
]
show provably-secure security constructions for dynamic CBFs. As such, another interesting direction to explore is formulating adaptive security and building secure constructions for dynamic LBFs under an adversarial model that admits insertions.

Computationally unbounded adversaries.
Our constructions are secure against polynomial-time adversaries. Another interesting avenue for future research is showing LBF constructions that realize our security notions while assuming computationally unbounded adversaries.

Preliminaries

In this section, we review CBFs and their adversarial models from
[
20
,
21
]
, which form the basis for the adversarial models we define for LBFs.

Notation.
For a set

,

denotes the size of

, and

denotes that

. For

,

CBF Modeling.
We adopt the CBF model from
[
20
]
while considering the
steady
setting in which the query algorithm does not change the filter representation.

Definition 1

A Bloom filter
\mathbf{B}=(\mathbf{B}_{1},\mathbf{B}_{2})
is a pair of polynomial time algorithms.
\mathbf{B}_{1}
is a randomized construction algorithm that takes as input a set
S\subseteq\mathfrak{D}
of size

, and outputs a representation

.
\mathbf{B}_{2}
is a deterministic query algorithm that takes as input an element

and a representation

, and outputs 1 indicating that

, and 0 otherwise. We say that
\mathbf{B}
is an
(n,\varepsilon)
-Bloom filter if for all sets
S\subseteq\mathfrak{D}
of cardinality
n
, the following hold:

1.

Completeness:
\forall{x}\in S:\Pr[\mathbf{B}_{2}(\mathbf{B}_{1}(S),x)=1]=1

2.

Soundness:
\forall x\notin S:\Pr[\mathbf{B}_{2}(\mathbf{B}_{1}(S),x)=1]\leq\varepsilon

where the probabilities are taken over the random coins of
\mathbf{B}_{1}
.

A standard CBF is implemented as a string
str
of length
n_{b}\in\mathbb{N}
bits indexed over
[n_{b}]
, along with
n_{h}\in\mathbb{N}
hash functions

, for

, from a universal hash family
\mathcal{H}
used for element mapping. That is, each
h_{i}
maps an element from
\mathfrak{D}
to an index value within
[n_{b}]
, so
h_{i}:\mathfrak{D}\mapsto[n_{b}]
. Then, for each element
x\in S
, for
i\in[n_{h}]
, the bit at index
h_{i}(x)
of
str
is set to
1
(if it is already set to 1, it stays 1). For a queried element
x
, a CBF returns 1 if all bits within
str
at indices corresponding to
h_{i}(x)
are set to
1
, otherwise, the CBF returns 0.

Always-Bet Security.

Naor et al.
[
20
,
21
]
introduced the Always-Bet security game for CBFs, denoted as
ABGame
, in which an adversary who has oracle access to the CBF aims to find a false positive. It is denoted as always-bet since the adversary is required to output a guess

at the end of the game that will be tested whether it is a false positive (i.e., always bets that
x^{*}
is a false positive). In detail, for an adversary
\mathcal{A}=(\mathcal{A}_{1},\mathcal{A}_{2})
,
{\mathcal{A}}_{1}
chooses a set
S\subseteq\mathfrak{D}
for which
\mathbf{B}_{1}
will compute a representation
M
, and
{\mathcal{A}}_{2}
gets
S
as input and attempts to find a false positive

that was not queried before, given only oracle access

.

ABGame(
\mathcal{A},t,\lambda
)
:

1.

S\leftarrow\mathcal{A}_{{1}}(1^{\lambda})
such that
S\subseteq\mathfrak{D}
and
|S|=n
.

2.

M\leftarrow\mathbf{B}_{1}(S)
.

3.

x^{*}\leftarrow\mathcal{A}_{2}^{\mathbf{B}_{2}(M,\cdot)}(1^{\lambda},S)
where
\mathcal{A}_{2}
can make at most
t
queries to
\mathbf{B}_{2}(M,\cdot)
—in this and other games, we denote the adversarial queries as
\{x_{1},\dots,x_{t}
}.

4.

If
x^{*}\notin S\cup\{x_{1},\cdots,x_{t}\}
and
\mathbf{B}_{2}(M,x^{*})=1
, return
1
. Otherwise, return
0
.

We use the following security notion for all security games discussed in this paper (except for

, which we discuss next).

Definition 2

A Bloom filter
\mathbf{B}
is
(n,t,\varepsilon)
-secure under a security game

\lambda\in\mathbb{N}
, all
\mathsf{PPT}

, and all sets

\text{Pr}[\texttt{Game}(\mathcal{A},t,\lambda)=1]\leq\varepsilon
, where the probability is taken over the random coins of
\mathbf{B}
and
\mathcal{A}
.

Bet-or-Pass Security.

Naor and Oved
[
21
]
introduce a security game stronger than

called Bet-or-Pass, or
BPGame
. Here,
\mathcal{A}
can either output
x^{*}
or
pass
, so it is not always betting on the output of the game to be a false positive.
BPGame
also defines
\mathcal{A}
’s
profit

C_{\mathcal{A}}
, rewarding
\mathcal{A}
if

is a false positive, penalizing
\mathcal{A}
if
x^{*}
is not a false positive, and leaving
C_{A}
unchanged if
\mathcal{A}
chooses to pass.

BPGame(
\mathcal{A},t,\lambda
)
:

1.

S\leftarrow\mathcal{A}_{{1}}(1^{\lambda})
such that
S\subseteq\mathfrak{D}
and
|S|=n
.

2.

M\leftarrow\mathbf{B}_{1}(S)
.

3.

(b,x^{*})\leftarrow\mathcal{A}_{2}^{\mathbf{B}_{2}(M,\cdot)}(1^{\lambda},S)
where
\mathcal{A}_{2}
can make at most
t
queries,
\{x_{1},\dots,x_{t}\}
, to
\mathbf{B}_{2}(M,\cdot)
.

4.

Return
\mathcal{A}
’s profit,
C_{\mathcal{A}}
, which is defined as

C_{\mathcal{A}}=\begin{cases}0,&\text{if }b=0\\
\varepsilon^{-1},&\begin{aligned} &\text{if }b=1\text{ and }x^{*}\notin S\cup\{x_{1},\ldots,x_{t}\}\\
&\text{ and }\mathbf{B}_{2}(M,x^{*})=1\end{aligned}\\
-(1-\varepsilon)^{-1},&\text{otherwise}\end{cases}

The profit formulation is set in this way to ensure that an adversary that makes a random guess (which will be a false positive with probability

) has an expected profit of zero

21
]
.
\mathcal{A}
breaks the security of the CBF if its profit is noticeably larger than zero. Thus, the security guarantee for

is defined as an upper bound on the expectation of the adversary’s profit.

Definition 3

A Bloom filter
\mathbf{B}
is

-secure under

if for all large enough

, all
\mathsf{PPT}

\mathcal{A}
, and all sets
S\subseteq\mathfrak{D}
of cardinality

, there exists a negligible function
\mathsf{negl}\left(\cdot\right)
such that
\operatorname{\mathbb{E}}\left[C_{\mathcal{A}}\right]\leq\mathsf{negl}\left(\lambda\right)
, where the expectation is taken over the random coins of
\mathbf{B}
and
\mathcal{A}
.

3
Definitions and Adversarial Models for LBFs

In this section, we first define a model for LBFs, followed by three LBF adaptive security notions: full adaptivity (which when slightly modified captures always-bet security), partial adaptivity, and learned bet-or-pass.

3.1
LBF Definition

We present our definitions for LBFs, which are based on the model of
[
18
]
with additional formalism and adaptations to make it convenient to compare with the models of CBFs introduced earlier. An LBF uses a learning model trained over the dataset the LBF represents, such that the model determines a function
\mathscr{L}
that models this set. In particular, on input
x
,
\mathscr{L}
outputs the probability that
x\in S
. In what follows, we define the notion of a training dataset and a learning model in the context of LBFs (where
y_{i}
is a label stating whether
x_{i}\in S
).

Definition 4

Let
S\subseteq\mathfrak{D}
be any set represented by a Bloom filter. For any two sets
P\subseteq S
and
N\subseteq\mathfrak{D}\setminus S
, the training dataset is the set
\mathscr{T}=\{(x_{i},y_{i}=1)\mid x_{i}\in P\}\cup\{(x_{i},y_{i}=0)\mid x_{i}\in N\}
.

Definition 5

For an
\mathscr{L}:\mathfrak{D}\mapsto[0,1]
and threshold
\tau
, we say
\mathscr{L}
is an
(S,\tau,\varepsilon_{p},\varepsilon_{n})
-learning model if for any set
S\subseteq\mathfrak{D}
the following hold:

1.

P-Soundness:
\forall x\notin S:\Pr[\mathscr{L}(x)\geq\tau]\leq\varepsilon_{p}

2.

N-Soundness:
\forall x\in S:\Pr[\mathscr{L}(x)<\tau]\leq\varepsilon_{n}

where the probability is taken over the random coins of
\mathscr{L}
.

Now, we define an LBF capturing both the classic and learning components. We consider the
steady
setting in which the query algorithm
\mathbf{B}_{2}
does not change the learned representation of the set
S
(including both the set representation held by the backup CBF, i.e.,
M
, and
(\mathscr{L},\tau)
).

Definition 6

An LBF
\mathbf{B}=(\mathbf{B}_{1},\mathbf{B}_{2},\mathbf{B}_{3},\mathbf{B}_{4})
is a tuple of four polynomial-time algorithms:
\mathbf{B}_{1}
is as before,
\mathbf{B}_{2}
is a query algorithm,
\mathbf{B}_{3}
is a randomized algorithm that takes a set
S\subseteq\mathfrak{D}
as input and outputs a training dataset
\mathscr{T}
, and
\mathbf{B}_{4}
is a randomized algorithm that takes the training dataset
\mathscr{T}
as input and returns a learning model
\mathscr{L}
and a threshold
\tau\in[0,1]
. The internal representation of an LBF contains two components: the classical component
M
and the learned component (
\mathscr{L},\tau)
.
\mathbf{B}_{2}
takes as inputs an element
x\in\mathfrak{D}
,
M
, and (
\mathscr{L},\tau
), and outputs 1, indicating that
x\in S
, and 0 otherwise. We say that
\mathbf{B}
is an
(n,\tau,\varepsilon,\varepsilon_{p},\varepsilon_{n})
-LBF if for all sets
S\subseteq\mathfrak{D}
of cardinality
n
, it holds that:

1.

Completeness:
\forall{x}\in S:\Pr[\mathbf{B}_{2}(\mathbf{B}_{1}(S),\mathbf{B}_{4}(\mathbf{B}_{3}(S)),x)=1]=1
.

2.

Filter soundness:
\forall x\notin S:\Pr[\mathbf{B}_{2}(\mathbf{B}_{1}(S),\mathbf{B}_{4}(\mathbf{B}_{3}(S)),x)=1]\leq\varepsilon
.

3.

Learning model soundness:
\mathbf{B}_{4}(\mathbf{B}_{3}(S))
is an
(S,\tau,\varepsilon_{p},\varepsilon_{n})
-learning model.

where the probabilities are over the random coins of
\mathbf{B}_{1}
,
\mathbf{B}_{3}
, and
\mathbf{B}_{4}
.

Standard LBFs (Figure
1
) use a learning model as a pre-filter before a CBF. The CBF is called a backup CBF as it is only queried on inputs
x
for which the learning model decides that
x
is not an element of the stored set
S
, i.e.,
\mathscr{L}(x)<\tau
.

3.2
Full Adaptive Security

Full adaptivity means that
\mathcal{A}
chooses all the queries submitted to the query algorithm
\mathbf{B}_{2}
, i.e., the adversary controls the entire workload. For CBFs, the full adaptivity game, besides the oracle access to
\mathbf{B}_{2}(M,\cdot)
, gives oracle access to
\mathbf{B_{1}}
enabling
\mathcal{A}
to obtain
M
for any set
S
of its choosing. Based on that, we define the following game capturing full adaptive security for CBFs.

FAGame(
\mathcal{A},t,\lambda
)
:

1.

S\leftarrow\mathcal{A}_{{1}}(1^{\lambda})
such that
S\subseteq\mathfrak{D}
and
|S|=n
.

2.

M\leftarrow\mathbf{B}_{1}(S)
.

3.

x^{*}\leftarrow\mathcal{A}_{2}^{{\mathsf{O}}}(1^{\lambda},S)
, where
{\mathsf{O}}=\{\mathbf{B}_{1}(\cdot),\mathbf{B}_{2}(M,\cdot)\}
.
\mathcal{A}_{2}
can make at most
t
queries to
\mathbf{B}_{2}
, and any polynomial number of queries to
\mathbf{B}_{1}
.

4.

If
x^{*}\notin S\cup\{x_{1},\cdots,x_{t}\}
and
\mathbf{B}_{2}(M,x^{*})=1
, return
1
, else, return
0
.

For LBFs, we define a similar security game, denoted
LFAGame
. The difference is that
\mathcal{A}
now has oracle access to the additional algorithms in the LBF structure. We note that our results hold even if we let
\mathcal{A}
choose
\mathscr{T}
directly (rather than having the challenger invoke
\mathbf{B}_{3}
over the set
S
chosen by
\mathcal{A}
), as long as the challenger validates that this

satisfies Definition
4
.

LFAGame
(
\mathcal{A},t,\lambda
):

1.

S\leftarrow\mathcal{A}_{{1}}(1^{\lambda})
such that
S\subseteq\mathfrak{D}
and
|S|=n
.

2.

M\leftarrow\mathbf{B}_{1}(S)
,
\mathscr{T}\leftarrow\mathbf{B}_{3}(S)
, and
(\mathscr{L},\tau)\leftarrow\mathbf{B}_{4}(\mathscr{T})
.

3.

x^{*}\leftarrow\mathcal{A}_{2}^{{\mathsf{O}}}(1^{\lambda},S)
, where
{\mathsf{O}}=\{\mathbf{B}_{1}(\cdot),\mathbf{B}_{2}(M,\mathscr{L},\tau,\cdot),\mathbf{B}_{3}(\cdot),\mathbf{B}_{4}(\cdot)\}
.
\mathcal{A}_{2}
can make at most
t
queries to
\mathbf{B}_{2}
, and any polynomial number of queries to each of
\mathbf{B}_{1}
,
\mathbf{B}_{3}
, and
\mathbf{B}_{4}
.

4.

If
x^{*}\notin S\cup\{x_{1},\cdots,x_{t}\}
and
\mathbf{B}_{2}(M,\mathscr{L},\tau,x^{*})=1
, return 1, else, return 0.

If we remove
\mathcal{A}_{2}
’s oracle access to
\mathbf{B}_{1}(\cdot)
,
\mathbf{B}_{3}(\cdot)
, and
\mathbf{B}_{4}(\cdot)
, we obtain a notion for the
always-bet
security game, which we refer to as
LABGame(
\mathcal{A},t,\lambda
)
.

3.3
Partial Adaptive Security

For partial adaptivity, among the
t
queries to
\mathbf{B}_{2}
,
\mathcal{A}
can choose
\alpha t
of them, where
\alpha\in[0,1]
. These
t
queries may be part of a batch workload or a streaming workload under any streaming models described by
[
19
]
. Systems incorporating Bloom filters can operate under such a partial-adaptivity model in many real-world scenarios, including content caching (e.g., as in content delivery networks) and database systems. For example, LSM (log-structured merge) Tree stores, including Google’s LevelDB
[
11
]
and Facebook’s RocksDB
[
17
]
, use Bloom filters to reduce read times
[
6
]
. These stores can receive queries from both malicious and non-malicious users, which captures the fact that
\mathcal{A}
can observe the output of queries made by others while it can choose the rest.

In the partial adaptivity game
PAGame
, as in
FAGame
,
\mathcal{A}
’s goal is to produce a previously unseen false positive. However, this time,
\mathcal{A}
cannot choose all the queries; it can only choose a fraction
\alpha

(1-\alpha)t

\mathfrak{D}
.
\mathcal{A}
, however, still observes the output of all queries.
\mathcal{A}
also has the freedom to choose the order in which adversarial queries are interleaved between non-adversarial queries. We show this notion first for CBFs, where
c

\mathcal{A}
’s choice of whether to evaluate the adversarial query if
c=1
, or a non-adversarial one if
c=0
.

PAGame(
\mathcal{A},\alpha,t,\lambda
)
:

1.

S\leftarrow\mathcal{A}_{{1}}(1^{\lambda})
such that
S\subseteq\mathfrak{D}
and
|S|=n
.

2.

M\leftarrow\mathbf{B}_{1}(S)
, and set
i=\beta=0
.

3.

(c,x_{i})\leftarrow\mathcal{A}_{2}^{\mathbf{B}_{1}(\cdot)}(1^{\lambda},S,i,\beta)
—
\mathcal{A}_{2}
can make any polynomial number of queries to
\mathbf{B}_{1}
.

4.

If
c=1
and
\beta<\alpha t
, give
\mathcal{A}_{2}
the output of
\mathbf{B}_{2}(M,x_{i})
, and set
\beta=\beta+1
.

5.

Otherwise,
{x_{i}}\leftarrow\mathrel{\mkern-2.0mu}\mathrel{\mathchoice{\vbox{\hbox{$\displaystyle\textnormal{\$\hskip-0.52502pt}$}}}{\vbox{\hbox{$\textstyle\textnormal{\$\hskip-0.52502pt}$}}}{\vbox{\hbox{$\scriptstyle\textnormal{\$\hskip-0.36751pt}$}}}{\vbox{\hbox{$\scriptscriptstyle\textnormal{\$\hskip-0.26251pt}$}}}}\mathfrak{D}
and give
\mathcal{A}_{2}
the output of
\mathbf{B}_{2}(M,x_{i})
.

6.

Set
i=i+1
. If
i<t
, go back to Step 3.

7.

\mathcal{A}_{2}
outputs
x^{*}
. If
x^{*}\notin S\cup\{x_{1},\dots,x_{t}\}
and
\mathbf{B}_{2}(M,x^{*})=1
, return 1. Otherwise, return 0.

This security game can be modified to work for LBFs as follows.

.

4.

If

and

, give
\mathcal{A}_{2}

\mathbf{B}_{2}(M,\mathscr{L},\tau,x_{i})
, and set

.

5.

Otherwise,
{x_{i}}\leftarrow\mathrel{\mkern-2.0mu}\mathrel{\mathchoice{\vbox{\hbox{$\displaystyle\textnormal{\$\hskip-0.52502pt}$}}}{\vbox{\hbox{$\textstyle\textnormal{\$\hskip-0.52502pt}$}}}{\vbox{\hbox{$\scriptstyle\textnormal{\$\hskip-0.36751pt}$}}}{\vbox{\hbox{$\scriptscriptstyle\textnormal{\$\hskip-0.26251pt}$}}}}\mathfrak{D}

\mathcal{A}_{2}

Definition

still applies to these games with one change; now we say a Bloom filter is

.

3.4
Learned Bet-or-Pass Security

This section extends the CBF
BPGame
from Naor and Oved
[

]
to LBFs, denoted as
LBPGame
(the same expectation notion from Definition
3
applies here as well).

LBPGame(
\mathcal{A},t,\lambda
)
:

1.

S\leftarrow\mathcal{A}_{{1}}(1^{\lambda})
such that
S\subseteq\mathfrak{D}
and
|S|=n
.

2.

M\leftarrow\mathbf{B}_{1}(S)
,
\mathscr{T}\leftarrow\mathbf{B}_{3}(S)
,

.

3.

(b,x^{*})\leftarrow\mathcal{A}_{2}^{{\mathsf{O}}}(1^{\lambda},S)

.

Return

’s profit,

, which is defined as

C_{\mathcal{A}}=\begin{cases}0,&\text{if }b=0\\
\varepsilon^{-1},&\begin{aligned} &\text{if }b=1\text{ and }x^{*}\notin S\cup\{x_{1},\ldots,x_{t}\}\\

3.5
Relationships between Security Notions

We investigate relationships between the security games we defined so far. For clarity, we focus on LBF versions of all security games. Naor et al.
[
21
,
15
]
investigate similar relationships for the CBF security notions they defined, including
ABGame
and
BPGame
.

We first explore connections between
LFAGame
and
LPAGame
. Notice that when
\alpha=1
,
LPAGame
is equivalent to
LFAGame
.
LFAGame
, therefore, is the special case of
LPAGame
where all queries are adversarial. The converse relationship is false, meaning that
LFAGame
is stronger than
LPAGame
.

Theorem 1

For
\varepsilon\in(0,1),\alpha\in[0,1]
and
n,t\in\mathbb{N}
, we have:

(n,t,\varepsilon)\text{-security in {LFAGame}}\implies(n,\alpha,t,\varepsilon)\text{-security in {LPAGame}}

(n,\alpha,t,\varepsilon)\text{-security in }\texttt{LPAGame}\mathchoice{\mathrel{\hbox to0.0pt{\kern 3.75pt\kern-5.27776pt$\displaystyle\not$\hss}{\implies}}}{\mathrel{\hbox to0.0pt{\kern 3.75pt\kern-5.27776pt$\textstyle\not$\hss}{\implies}}}{\mathrel{\hbox to0.0pt{\kern 2.625pt\kern-4.45831pt$\scriptstyle\not$\hss}{\implies}}}{\mathrel{\hbox to0.0pt{\kern 1.875pt\kern-3.95834pt$\scriptscriptstyle\not$\hss}{\implies}}}(n,t,\varepsilon)\text{-security in }\texttt{LFAGame}

Proof

For the first relationship, fix a
\mathsf{PPT}
adversary
\mathcal{A}=(\mathcal{A}_{1},\mathcal{A}_{2})
and
t,\lambda\in\mathbb{N}
. Pick any
\alpha,\alpha^{\prime}\in[0,1]
such that
\alpha^{\prime}\geq\alpha
. Construct another adversary
\mathcal{A}^{\prime}=(\mathcal{A}^{\prime}_{1},\mathcal{A}^{\prime}_{2})
as follows. Let
\mathcal{A}^{\prime}_{1}(1^{\lambda},\alpha^{\prime},t)=\mathcal{A}_{1}(1^{\lambda},\alpha,t)
and
\mathcal{A}^{\prime}_{2}(1^{\lambda},S,\alpha^{\prime},t,\beta,i)=\mathcal{A}_{2}(1^{\lambda},S,\alpha,t,\beta,i)
. This does not break the rules of
\mathtt{LPAGame}
as still
\alpha^{\prime}\in[0,1]
. Since
\alpha^{\prime}\geq\alpha
, the winning probability of
\mathcal{A}^{\prime}
is at least as high as
\mathcal{A}
’s winning probability. When
\alpha^{\prime}=1
, we have
\mathtt{LPAGame}(\mathcal{A}^{\prime},1,t,\lambda)=\mathtt{LFAGame}(\mathcal{A}^{\prime},t,\lambda)
, thus the result follows.

For the second relationship, let
\mathbf{B}
be an
(n,\alpha,t,\varepsilon)
-secure LBF construction in
\mathtt{LPAGame}
. Consider
\mathtt{LFAGame}
with the same parameters (excluding
\alpha
) as
\mathtt{LPAGame}
. Also, let
\mathbf{B}^{\prime}
be an alternative LBF construction such that the construction algorithm
\mathbf{B}^{\prime}
is identical to
\mathbf{B}
, while the query algorithm
\mathbf{B}^{\prime}_{2}
differs from
\mathbf{B}_{2}
as follows. Initially,
\mathbf{B}^{\prime}_{2}(M,\mathscr{L},\tau,\cdot)=\mathbf{B}_{2}(M,\mathscr{L},\tau,\cdot)
. However,
\mathbf{B}^{\prime}_{2}
tracks the number of identical queries it receives. On receiving
t
identical queries,
\mathbf{B}^{\prime}_{2}
switches to always output
1
for all future queries. An adversary can win
LFAGame
with non-negligible probability by having all its
t
queries over the same value
x
. At this point,
\mathbf{B}^{\prime}_{2}
will output 1 for any guess
x^{*}\neq x
that the adversary outputs and wins the game. Therefore,
\mathbf{B}^{\prime}
is not
(n,\alpha,t,\varepsilon)
-secure in
LFAGame
. Now, consider an adversary
\mathcal{A}
in
LPAGame
. To win with non-negligible probability,
\mathcal{A}
must trigger
\mathbf{B}^{\prime}_{2}
to always output
1
.
\mathcal{A}
can have at most
t-1
adversarial queries, and can choose all of them to be over the same value
x
. However, to trigger
\mathbf{B}^{\prime}_{2}
to always output 1, the final query, which is chosen uniformly randomly by the challenger, must also be
x
. Assuming the domain
\mathfrak{D}
is large, the probability of this happens is negligible. Therefore,
\mathbf{B}^{\prime}
remains
(n,\alpha,t,\varepsilon)
-secure in
LPAGame
.∎

We now compare
LFAGame
and
LPAGame
to
LABGame
and
LBPGame
.

Theorem 2

For
\varepsilon\in(0,1),\alpha\in[0,1]
and
n,t\in\mathbb{N}
, we have:

(n,t,\varepsilon)\text{-security in }\texttt{LFAGame}\implies(n,t,\varepsilon)\text{-security in }\texttt{LABGame}

(n,\alpha,t,\varepsilon)\text{-security in }\texttt{LPAGame}\implies(n,\alpha t,\varepsilon)\text{-security in }\texttt{LABGame}

Proof

Fix a
\mathsf{PPT}
adversary
\mathcal{A}
, and
t,\lambda\in\mathbb{N}
.
\mathtt{LABGame}(\mathcal{A},t,\lambda)
is identical to
\mathtt{LFAGame}(\mathcal{A},t,\lambda)
aside from the fact that
\mathcal{A}
does not have oracle access to
\mathbf{B}_{1}(\cdot)
in
\mathtt{LABGame}
. Hence,
\mathcal{A}
’s winning probability in
\mathtt{LABGame}(\mathcal{A},t,\lambda)
cannot be greater than
\mathcal{A}
’s winning probability in
\mathtt{LFAGame}(\mathcal{A},t,\lambda)
. Following a similar argument, we get an implication between
LPAGame
and
LABGame
.∎

To disprove the converse, we introduce an
(n,t,\varepsilon)
-secure construction under
LABGame
and then modify it such that it remains secure under
LABGame
but not under
LFAGame
. We first recall the following theorem for CBFs by Naor and Yogev
[
20
]
.

Theorem 3
(Naor-Yogev Theorem)

Let
B
be an
(n,\varepsilon)
-Bloom filter using
m
memory bits. If pseudorandom permutations (PRPs) exist, then for security parameter
\lambda
there exists a negligible function
\mathsf{negl}\left(\cdot\right)
and an
(n,\varepsilon+\mathsf{negl}\left(\lambda\right))
-strongly resilient Bloom filter in
ABGame
that uses
m^{\prime}=m+\lambda
bits of memory.
1
1

1

Strongly resilient means being
(n,t,\varepsilon)
-secure under
BPGame
for any
t\in\mathcal{O}\left(\mathsf{poly}\left(n,\lambda\right)\right)
. For more details, see Definition 2.4 in
[
21
]
.

This theorem is proved for the following construction, which we denote as Naor-Yogev CBF, or NY-CBF. Run the initialization algorithm of a CBF with the set
S^{\prime}={\{\mathsf{PRP}_{\mathsf{\vphantom{p}sk}}(x):x\in S\}}
instead of
S
, where
\mathsf{PRP}_{\mathsf{\vphantom{p}sk}}
is a keyed PRP. Similarly, for an element
x\in\mathfrak{D}
, query the filter over
\mathsf{PRP}_{\mathsf{\vphantom{p}sk}}(x)
instead of
x
. This new CBF construction uses
m+\lambda
bits of memory and is
(n,\varepsilon+\mathsf{negl}\left(\lambda\right))
-secure for any
t\in\mathcal{O}\left(\mathsf{poly}\left(n,\lambda\right)\right)
under
ABGame
. We modify this construction in the proof for the theorem below.

Theorem 4

For
\varepsilon\in(0,1),\alpha\in[0,1]
,
n,t\in\mathbb{N}
, and
\delta\in(0,1)
, we have:

(n,t,\varepsilon)\text{-security in {LABGame}}\mathchoice{\mathrel{\hbox to0.0pt{\kern 3.75pt\kern-5.27776pt$\displaystyle\not$\hss}{\implies}}}{\mathrel{\hbox to0.0pt{\kern 3.75pt\kern-5.27776pt$\textstyle\not$\hss}{\implies}}}{\mathrel{\hbox to0.0pt{\kern 2.625pt\kern-4.45831pt$\scriptstyle\not$\hss}{\implies}}}{\mathrel{\hbox to0.0pt{\kern 1.875pt\kern-3.95834pt$\scriptscriptstyle\not$\hss}{\implies}}}(n,t,\delta)\text{-security in {LFAGame}}

(n,\alpha t,\varepsilon)\text{-security in {LABGame}}\mathchoice{\mathrel{\hbox to0.0pt{\kern 3.75pt\kern-5.27776pt$\displaystyle\not$\hss}{\implies}}}{\mathrel{\hbox to0.0pt{\kern 3.75pt\kern-5.27776pt$\textstyle\not$\hss}{\implies}}}{\mathrel{\hbox to0.0pt{\kern 2.625pt\kern-4.45831pt$\scriptstyle\not$\hss}{\implies}}}{\mathrel{\hbox to0.0pt{\kern 1.875pt\kern-3.95834pt$\scriptscriptstyle\not$\hss}{\implies}}}(n,\alpha,t,\delta)\text{-security in {LPAGame}}

Proof

Let
\mathbf{B}
be an NY-CBF that is
(n,t,\varepsilon)
-secure under
ABGame
. Consider a construction
\mathbf{B}^{\prime}
that is
(n,t,\varepsilon)
-secure under
LABGame
.
\mathbf{B}^{\prime}
replaces
\mathbf{B}
with standard (or conventional) LBF that uses
\mathbf{B}
as its backup CBF and has a trivial learning model that responds negative (i.e.,
x\notin S
) to all queries
x\in\mathfrak{D}
. Although contrived,
\mathbf{B}^{\prime}
is a correct LBF by Definition
6
. Consider a
\mathsf{PPT}
adversary
\mathcal{A}
. Since the learned representation of
\mathbf{B}^{\prime}
contains no information on the input set
S
and routes all queries to its backup CBF, which is a NY-CBF,
\mathcal{A}
in
LABGame
has no advantage over
\mathcal{A}
in
ABGame
. Hence,
\mathbf{B}^{\prime}
is also
(n,t,\varepsilon)
-secure in
LABGame
.

Now consider a second construction
\mathbf{B}^{\prime\prime}
that is identical to
\mathbf{B}^{\prime}
but with one modification: instead of storing the internal representation
M
like
\mathbf{B}^{\prime}
,
\mathbf{B}^{\prime\prime}
stores the internal representation
M^{\prime}=(M,\mathsf{\vphantom{p}sk})
where
\mathsf{\vphantom{p}sk}
is the secret key of
\mathsf{PRP}
.
\mathbf{B}^{\prime\prime}
is still
(n,t,\delta=\varepsilon+\mathsf{negl}\left(\lambda\right))
-secure under
LABGame
as
\mathcal{A}
does not have access to the internal representation of the Bloom filter. However,
\mathbf{B}^{\prime\prime}
is not
(n,t,\delta=\varepsilon+\mathsf{negl}\left(\lambda\right))
-secure under
LFAGame
or
LPAGame
where
\mathcal{A}
has oracle access to
M^{\prime}
and can obtain the secret key
\mathsf{\vphantom{p}sk}
.∎

Before we show our next result, we recall a theorem by Naor and Oved
[
21
]
, in which they proved that security in
ABGame
does not imply security in
BPGame
. Their proof uses a counterexample construction that usually behaves like an
(n,t,\varepsilon)
-secure CBF in
ABGame
but has a small probability of reaching an always-one state, i.e., the query algorithm always outputs 1 for any query.

Theorem 5
(Naor-Oved Theorem)

Let
0<\varepsilon<1
and
n\in\mathbb{N}
, then for any
0<\delta<1
, assuming the existence of one-way functions, there exists a non-trivial Bloom filter
\mathbf{B}
that is
(n,\varepsilon)
-strongly resilient under
ABGame
and is not
(n,\delta)
-strongly resilient under
BPGame
.

Theorem 6

For
\varepsilon\in(0,1)
,
n,t\in\mathbb{N}
, and
\delta\in(0,1)
, we have:

(n,t,\varepsilon)\text{-security in {LABGame}}\mathchoice{\mathrel{\hbox to0.0pt{\kern 3.75pt\kern-5.27776pt$\displaystyle\not$\hss}{\implies}}}{\mathrel{\hbox to0.0pt{\kern 3.75pt\kern-5.27776pt$\textstyle\not$\hss}{\implies}}}{\mathrel{\hbox to0.0pt{\kern 2.625pt\kern-4.45831pt$\scriptstyle\not$\hss}{\implies}}}{\mathrel{\hbox to0.0pt{\kern 1.875pt\kern-3.95834pt$\scriptscriptstyle\not$\hss}{\implies}}}(n,t,\delta)\text{-security in {LBPGame}}

(n,t,\varepsilon)\text{-security in {LBPGame}}\implies(n,t,\varepsilon)\text{-security in {LFAGame} and {LABGame}}

Proof

For the first relationship, let
\mathbf{B}
be the Naor-Oved CBF construction that is
(n,t,\varepsilon)
-secure under
ABGame
but not under
BPGame
. We demonstrated in Theorem
4
how to create a construction
\mathbf{B}^{\prime}
that is
(n,t,\varepsilon)
-secure under
LABGame
by having a trivial learning model that routes all queries to the backup CBF. This backup CBF is
\mathbf{B}
, which is secure under the
ABGame
, making the overall construction secure under the
LABGame
. By Theorem
5
, we know that
B
is not
(n,t,\delta)
-secure under
BPGame
for any
\delta\in(0,1)
. Since the learning model in
\mathbf{B}^{\prime}
is trivial and adds no adversarial resilience, it follows that
\mathbf{B}^{\prime}
is not
(n,t,\delta)
-secure under
LBPGame
for any
\delta\in(0,1)
.

For the second relationship, Naor and Oved
[
21
]
also prove that for CBFs
(n,t,\varepsilon)
-security under
BPGame
implies
(n,t,\varepsilon)
-security under
ABGame
. We use a proof technique similar to theirs. Let
\mathbf{B}
be a construction that is
(n,t,\varepsilon)
-secure under
LBPGame
. Fix an
LBPGame
adversary
\mathcal{A}
that outputs a guess
x^{*}
. Let
FP
denote the event that
x^{*}
is a false positive. For construction
\mathbf{B}
, the expected profit of
\mathcal{A}
is:

\displaystyle\operatorname{\mathbb{E}}\left[C_{A}\right]

\displaystyle=\frac{1}{\varepsilon}\Pr[\text{FP}]-\frac{1}{1-\varepsilon}\Pr[\lnot\text{FP}]=\frac{1}{\varepsilon}\Pr[\text{FP}]-\frac{1}{1-\varepsilon}(1-\Pr[\text{FP}])

\displaystyle=\left(\frac{1}{\varepsilon}+\frac{1}{1-\varepsilon}\right)\Pr[\text{FP}]-\frac{1}{1-\varepsilon}=\frac{1}{\varepsilon(1-\varepsilon)}\Pr[\text{FP}]-\frac{1}{1-\varepsilon}

Using
\operatorname{\mathbb{E}}\left[C_{A}\right]\leq\mathsf{negl}\left(\lambda\right)
, we obtain

\frac{1}{\varepsilon(1-\varepsilon)}\Pr[\text{FP}]-\frac{1}{1-\varepsilon}\leq\mathsf{negl}\left(\lambda\right)

Since
\varepsilon\in(0,1)
, we have
\varepsilon(1-\varepsilon)\in(0,1)
, and thus

\Pr[\text{FP}]\leq\varepsilon+\varepsilon(1-\varepsilon)\mathsf{negl}\left(\lambda\right)\leq\varepsilon+\mathsf{negl}\left(\lambda\right)

.

We have shown that the probability of
x^{*}
being a false positive is at most negligibly greater than
\varepsilon
. This is the condition needed for
\mathbf{B}
to be
(n,t,\varepsilon)
-secure under
LFAGame
and
LABGame
.∎

Finally, we show that security in
LFAGame
does not imply security in
LBPGame
. As mentioned before, Naor and Oved proved Theorem
5
using a CBF counterexample that has a small probability of reaching an always-one state. We extend this idea to LBFs and prove that security in
LFAGame
does not imply security in
LBPGame
. Our proof is simpler than Naor and Oved’s proof for CBFs because we give the adversary an oracle access to the Bloom filter’s internal representation.

Theorem 7

For
\varepsilon\in(0,1)
,
n,t\in\mathbb{N}
, and
\delta\in(0,1)
, we have:

(n,t,\varepsilon)\text{-security in {LFAGame}}\mathchoice{\mathrel{\hbox to0.0pt{\kern 3.75pt\kern-5.27776pt$\displaystyle\not$\hss}{\implies}}}{\mathrel{\hbox to0.0pt{\kern 3.75pt\kern-5.27776pt$\textstyle\not$\hss}{\implies}}}{\mathrel{\hbox to0.0pt{\kern 2.625pt\kern-4.45831pt$\scriptstyle\not$\hss}{\implies}}}{\mathrel{\hbox to0.0pt{\kern 1.875pt\kern-3.95834pt$\scriptscriptstyle\not$\hss}{\implies}}}(n,t,\delta)\text{-security in {LBPGame}}

Proof

Fix an
\varepsilon^{\prime}\in(0,\varepsilon)
and let
\mathbf{B}
be an LBF construction that is
(n,t,\varepsilon^{\prime})
-secure in
LFAGame
(we show the existence of such a construction in Theorem
2
). Let
\mathbf{B}^{\prime}
be a modified construction that behaves as follows. The construction algorithm
\mathbf{B}^{\prime}_{1}
flips a bit
b
with probability
p
of being
1
. If
b=1
,
\mathbf{B}^{\prime}
always answers
1
to any query. Otherwise,
\mathbf{B}^{\prime}
behaves identically to
\mathbf{B}
. Let
M
be the internal classical representation of
\mathbf{B}
.
\mathbf{B}^{\prime}
stores
M^{\prime}=(M,b)
as its internal classical representation. We first show that
\mathbf{B}^{\prime}
is
(n,t,\varepsilon)
-secure in
LFAGame
. An adversary
\mathcal{A}
in
LFAGame
is always required to output a guess
x^{*}
. Let
FP
denote the event that
x^{*}
is a false positive. Note that
\Pr[\text{FP}\mid b=1]=1
while
\Pr[\text{FP}\mid b=0]
is same as the probability of
\mathcal{A}
winning
LFAGame
with construction
\mathbf{B}
, i.e.,
\Pr[\text{FP}\mid b=0]\leq\varepsilon^{\prime}+\mathsf{negl}\left(\lambda\right)
. Based on that, and by choosing
p=\frac{\varepsilon-\varepsilon^{\prime}}{1-\varepsilon^{\prime}}
, we have:

\displaystyle\Pr[\text{FP}]

\displaystyle=\Pr[\text{FP}\mid b=1]\Pr[b=1]+\Pr[\text{FP}\mid b=0]\Pr[b=0]

\displaystyle\leq p+(\varepsilon^{\prime}+\mathsf{negl}\left(\lambda\right))(1-p)

\displaystyle\leq\varepsilon^{\prime}+p(1-\varepsilon^{\prime})+\mathsf{negl}\left(\lambda\right)

\displaystyle\leq\varepsilon^{\prime}+\frac{\varepsilon-\varepsilon^{\prime}}{1-\varepsilon^{\prime}}(1-\varepsilon^{\prime})+\mathsf{negl}\left(\lambda\right)

\displaystyle\leq\varepsilon+\mathsf{negl}\left(\lambda\right)

Thus,
\mathbf{B}^{\prime}
is
(n,t,\varepsilon)
-secure in
LFAGame
. All that is left to show is that
\mathbf{B}^{\prime}
is not
(n,t,\varepsilon)
-secure in
LBPGame
. Consider an adversary
\mathcal{A}^{\prime}
in
LBPGame
. Recall that
\mathcal{A}^{\prime}
has oracle access to
\mathbf{B}^{\prime}
’s internal classical representation
M^{\prime}
. Once
\mathbf{B}^{\prime}
is constructed,
\mathcal{A}^{\prime}
can read
b
in
M^{\prime}
to check whether
\mathbf{B}^{\prime}
is in the always-one state.
\mathcal{A}^{\prime}
chooses to bet only if
b=1
. Thus, we have:

\displaystyle\operatorname{\mathbb{E}}\left[C_{\mathcal{A}^{\prime}}\right]

\displaystyle=\operatorname{\mathbb{E}}\left[C_{\mathcal{A}^{\prime}}\mid b=1\right]\Pr[b=1]+\underbrace{\operatorname{\mathbb{E}}\left[C_{\mathcal{A}^{\prime}}\mid b=0\right]\Pr[b=0]}_{0\text{ since }\mathcal{A}^{\prime}\text{ won't bet}}

5
Security and Performance Analysis

In this section, we formally prove security of our LBF constructions. We show that PRP-LBF is secure under
LABGame
,
LFAGame
, and
LPAGame
, and that Cuckoo-LBF is secure under the
LBPGame
and
LABGame
. We leave studying whether Cuckoo-LBF is secure under
\mathtt{LFAGame}
and
\mathtt{LPAGame}
or introducing a construction that is secure against all LBF games as a future work direction.

We also analyze FPR (achieved for a given memory budget) of our constructions under these adversarial settings. Our results show that our LBF constructions achieve strong security guarantees while maintaining competitive performance (in terms of FPR achieved for a given memory budget).

5.1
Fully Adaptive Adversary

This section establishes the security of PRP-LBF against fully adaptive adversaries. We first prove that NY-CBF maintains its security guarantees even when facing a fully adaptive adversary who can access the filter’s internal representation. Building on this result, we then prove that PRP-LBF preserves these security properties in the LBF context.

Theorem 1

Let
\mathbf{B}

(n,\varepsilon)

Proof

We now discuss how PRP-LBF mitigate concrete attacks discussed in the literature, namely, the two attacks on LBFs by Reviriego et al.
[

]
(which we refer to as opaque-box and clear-box attacks), as well as a general poisoning attack on learned index structures introduced by Kornaropoulos et al.
[
13

Opaque-box attack.
The opaque-box adversarial model is similar to
LABGame
as both allow
\mathcal{A}
to query the LBF. However, in
LABGame

\mathcal{A}
chooses the LBF’s input set
S
, whereas in Reviriego et al.’s model,
\mathcal{A}
does not choose that. The opaque-box attack first tests elements until a false positive or a true positive is found. They it mutates the positive by changing a small fraction of the bits in the input to generate more false positives. The attack targets the learning model in standard LBFs by making it generate false positives without having the input reach the backup CBF. Unlike a standard LBF, PRP-LBF ensures both positive and negative queries are routed to a backup CBF that is
(n,t,\varepsilon)
-secure under
ABGame
. This ensures that the opaque-box attack will not induce a false positive in PRP-LBF with probability non-negligibly greater than
\varepsilon
.

Clear-box attack.
The clear-box adversarial model is similar to
LFAGame

NY-CBF has only been shown to be secure under

Theorem 5
(NOY Theorem)

Assuming one-way functions exist, for any

(n,\varepsilon)

BPGame

We now show that our Cuckoo-LBF construction is secure under

in

to the security of NOY-Cuckoo Filter under

6.2
Use-case Evaluation

We evaluate the performance of our constructions within the context of a use case to get a sense of how they would perform in practice. Historically, web browsers, including Google Chrome, used a Bloom filter
[
9
]
to store a set of Malicious URLs. In this design, whenever a user attempts to access a URL on the web browser, the browser queries the Bloom filter for the URL. If the Bloom filter says that the URL is in the Malicious URLs set, the web browser warns the user that they are accessing a potentially unsafe website. The malicious URLs use case has been studied by prior works on LBFs
[
24
,
30
]
. Thus, we evaluate this use case using the same public Malicious URLs dataset
[
25
]
as prior work. This dataset contains around 223K malicious and around 428K benign URLs.

Implementation and experimental setup.
We implemented PRP-LBF, Cuckoo-LBF, NY-CBF, and NOY-Cuckoo Filter in
903
lines of Python 3 code, which can be found in our open-source repository
[
12
]
. The implementation allows any PRP/PRF implementation to be plugged in for internal use. Similar to
[
20
]
, we use AES to instantiate PRPs and PRFs in our implementation. In particular, we use AES in the ECB mode where the input size of the PRP/PRF is 128 bits (so one block for AES encryption). Our implementation uses the
PyCryptoDome

[
26
]
library for these cryptographic primitives. Our implementation is also modular in a way that allows any machine learning model to be easily plugged in. We tested the correctness of our implementation on a broad range of common classification models, including the Random Forest model, Gaussian Naive Bayes, the Gradient Boosting Classifier, Support Vector Machine-based Classifiers, and Adaptive Boosting, using implementations provided by
scikit-learn
.

For our experiments, we use a set of
20
features to train the learning models, including URL length, whether the URL contains an IP address, whether the URL uses a shortening service, whether the URL is “abnormal”, digit count and letter count of the URL, and whether the URL contains special symbols. This set of features for the Malicious URLs Dataset is common in open-source learning models, and similar features have been used by prior work
[
30
]
. In the case of Cuckoo filter-based constructions, we use fingerprints of size
4
bits,
2
as the table size constant factor, and
5000
maximum eviction attempts in the Cuckoo hashing tables. For Cuckoo filter-based constructions, we also skip elements that cannot be inserted after the maximum eviction attempts have been reached.
