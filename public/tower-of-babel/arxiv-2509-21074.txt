RePro: Leveraging Large Language Models for Semi-Automated Reproduction of Networking Research Results
Yining Jiang, Wenyun Xu , Qingyu Song, Yuling Lin, Xuanhao Liu, Xiaoqiang Zheng, Qiang Su, Lizhao You, Lu Tang, Wanjin Feng, Linghe Kong, Qiao Xiang , Jiwu Shu

Abstract
Reproducing networking research is a critical but challenging task due to the scarcity of open-source code. While Large Language Models (LLMs) can automate code generation, current approaches lack the generalizability required for the diverse networking field. To address this, we propose RePro, a semi-automated reproduction framework that leverages advanced prompt engineering to reproduce network systems from their research papers. RePro combines few-shot in-context learning with Structured and Semantic Chain of Thought (SCoT/SeCoT) techniques to systematically translate a paper’s description into an optimized, executable implementation. The framework operates through a three-stage pipeline: system description extraction, structural code generation, and code optimization. Our evaluation with five state-of-the-art LLMs across diverse network sub-domains demonstrates that RePro significantly reduces reproduction time compared to manual efforts while achieving comparable system performance, validating its effectiveness and efficiency.

Introduction

The study of network systems spans protocols, distributed systems, and large-scale network architectures, among other areas, and its high complexity makes reproduction highly challenging. Reproducing results of networking research is of substantial value to both academia and industry. Reproduction is essential for ensuring the reliability and reproducibility of results, which strengthens academic credibility and provides industry with evidence-based guidance for technology selection and system optimization
handigol2012reproducible
. Moreover, it allows researchers to acquire a deep understanding of system design and implementation, while honing engineering and analytical skills
yan2017learning
.

Despite its significance, reproduction remains challenging due to the limited availability of source code and the effort required to faithfully re-implement complex systems, underscoring the need for tools and methods that facilitate efficient and accurate replication.
Current reproduction methods include: (1) running publicly available prototypes provided by authors
yang2015real
or recreated by others
zhang2020apkeep
; (2) manually re-implementing systems from paper descriptions. The availability of public code for networking research is limited. For instance, even in top-tier conferences such as SIGCOMM and NSDI, only 40.15% of papers published in the last decade have been accompanied by open-source implementations. Unofficial, third-party reproductions are even scarcer
snlabflash
, and private code sharing is often precluded by factors such as patents or commercial interests.

Manual re-implementation, while insightful, is a laborious process requiring significant expertise—a challenge that grows with the proliferation of complex networking research. This difficulty is in stark contrast to fields like machine learning, where a novice can often replicate a paper in about a week
yan2017learning
. The substantially higher time investment required for networking systems creates a significant barrier to entry and slows the overall pace of innovation.

To reduce reproduction costs and accelerate research, recent studies have investigated the use of large language models (LLMs) for automated code generation, including code completion, debugging, and synthesis
github_copilot_2025
;
openai-chatgpt
;
zhang2024pydex
;
rahmani2021multi
;
yen2021semi
. In particular, recent advances in paper-to-code generation
seo2025paper2code
;
lin2025autop2c
;
luo2025intention
have shown promising results in machine learning and biomedical domains, where standardized frameworks (e.g., PyTorch
pytorch
, TensorFlow
tensorflow
) and widely adopted benchmarks facilitate reproducibility.

Networking research presents the following challenges: heterogeneous architectures, complex paper parsing, and diverse programming languages. Existing work
xiang2023toward
relies on prompt-heavy methods requiring hundreds of manual interactions, imposing substantial reproduction costs;
wang2025llm
targets only satellite networks, limiting its applicability; and
chen2022software
;
yen2021semi
focus solely on well-formatted inputs within narrow domains, making them unsuitable for broader networking contexts. These limitations underscore the need for a systematic method to parse, reasoning, and generate code from complex, unstructured networking research with LLMs.

To address this critical issue, we propose RePro, a semi-automated framework that leverages advanced LLMs and structured prompt engineering to streamline the paper reproduction process, thereby reducing the manual labor and time cost associated with reproduction while maintaining high fidelity to the original paper’s design and implementation details. We design a four-step systematic workflow to reproduce the system in a network research.

Step ①:
System Description Extraction
. RePro automatically decomposes the system’s architecture. First, we preprocess the paper to perform structured text analysis and process multimodal information from the source document. This process extracts foundational system information, such as its sub-field, core problem, and high-level components. Next, drawing upon principles of software engineering modularity, we define clear evaluation metrics for the system architecture. We design a series of specialized prompt templates to guide an LLM in generating a well-defined system architecture composed of multiple functional modules.

Step ②:
Framework-Level Code Generation
. RePro translates the extracted system architecture into a modular code framework. This process integrates principles from program analysis with advanced prompt engineering techniques, notably Structured Chain-of-Thought (SCoT) and In-Context Learning (ICL). This methodology guides the Large Language Model (LLM) to first comprehend the context of each functional module and then reason progressively, culminating in the generation of specific structural, functional, and procedural requirements. To enhance correctness, a strong correlation and an explicit mapping are established between the content of the source paper and the generated code framework. This mapping provides precise guidance for the subsequent code population phase.

Step ③:
Function-Level Code Generation
.
To automate code population, RePro transforms the previously generated framework into executable code. For each function, we employ a few-shot learning approach, providing the LLM with examples that map requirement descriptions to their corresponding code implementations. We apply the Semantic Chain-of-Thought (SeCoT) method, which incorporates control and data flow, to structure the model’s output. This approach ensures logical rigor and verifies correctness by compelling the LLM to explicitly trace data manipulation and program execution.

Step ④:
Code Optimization
. RePro is designed for the automated correction and refinement of the generated code. To resolve syntactic or runtime errors, we employ a feedback loop where the erroneous code and its corresponding compiler or runtime error report are provided as input to an LLM. The LLM is then instructed to perform a detailed analysis of the error report—including stack traces, exception types, and specific messages—to identify the root cause and generate a corrected version of the code. This iterative debugging mechanism resolves immediate errors and serves to optimize the framework’s overall generation strategy by learning from failure cases, thereby enhancing its robustness and accuracy.

The main contributions of this paper are as follows.

•

Systematic Prompt Engineering.
We propose a systematic prompt engineering strategy that integrates few-shot learning, structured chain-of-thought reasoning, and semantic chain-of-thought reasoning. This unified design enables comprehensive paper analysis, automated module framework generation, and iterative code completion and optimization, ultimately supporting the construction of complete, executable systems.

•

First Semi-Automated Framework for Network Research Reproduction.
We address the novel and critical challenge of efficient paper reproduction in computer networking by proposing RePro, the first semi-automated reproduction framework based on LLM prompt engineering. Through its two key components—automated system architecture generation and semi-automated module code generation—RePro systematically transforms complex network research papers into complete, executable systems, significantly enhancing reproduction efficiency.

•

Reliable and Fast Reproduction.
We validate the effectiveness and generality of the RePro framework through a comprehensive evaluation. Using five different LLMs, we conduct reproduction experiments on nine distinct network systems. Our results show that the framework completes a reproduction task in an average of just 38.6 hours and requires an average of only 32.2 manual prompts, providing strong evidence of its efficiency and universality.

Background

This section reviews the two areas that form the foundation for our approach: workflows for reproducing research results and prompt engineering techniques of LLMs to accomplish complex tasks.

2.1
Research Results Reproduction

We formalize the steps to reproduce the results of a research work as follows. Each step necessitates both in-depth domain knowledge and a thorough understanding of research.

1.

Paper Comprehension.
A foundational understanding is established through an in-depth review of the primary paper and relevant supplementary materials (e.g., technical reports, project documents), focusing on its main ideas, architecture, and implementation details.

2.

Planning.
Building on the initial understanding, a reproduction strategy is developed by decomposing the system into its functional modules and defining their logical interdependencies, yielding a clear implementation plan for each core component.

3.

Implementation.
Finally, the system is assembled through two stages: the detailed implementation of each module, and their systematic integration.

Manually reproducing network systems papers is time-consuming and labor-intensive, requiring both a deep understanding of the research content and overcoming technical challenges during coding and implementation.

2.2
Prompt Engineering for LLM

As a key technique for enhancing the performance of LLMs, Prompt Engineering (PE)
gu2023systematic
involves designing effective prompts to guide an LLM toward accurate task comprehension and high-quality output generation.

Prompt Engineering Modeling

A systematic framework for PE is composed of two fundamental elements:
core components
and
design principles
. The core components include task description, input data, contextual information, and prompt style.

•

Task Description:
A natural language directive outlining the task objectives, including any explicit output formatting requirements.

•

Input Data:
The primary data for the task. Structured data (e.g., trees, tables) is often transformed via linearization
jiang2023structgpt
or code-based representations
beurer2023prompting
to facilitate model ingestion.

•

Supplemental Information:
Such as few-shot exemplars, retrieved documents, or external knowledge, used to ground the model and enhance output accuracy.

•

Prompt Style:
The structure and phrasing of the prompt. Techniques like direct instruction, question-based framing, or role-playing
chen2023chatcot
can influence output coherence, especially for complex, multi-step tasks.

Effective prompt design adheres to three core principles: 1) Clarity and Conciseness, to eliminate ambiguity and extraneous information; 2) Structured Formatting, using elements like numbering to guide the model’s sequential reasoning; and 3) Style Tailoring, adapting the prompt to the specific task and model to optimize performance. The rigorous application of these principles is essential for achieving accurate and reliable code reproduction.

Prompt Templates

Prompt templates define the function
g(\cdot)
used to structure inputs for downstream tasks. Initial approaches relied on manual design or algorithmic generation to create task-specific templates that improved model performance. Common types are tailored to the model architecture:
Cloze prompts

cui2021template
;
petroni2019language
use a fill-in-the-blank format for masked LMs like BERT
devlin2019bert
, while
prefix prompts

lester2021power
prepend instructions for autoregressive models like GPT. For complex or multi-input scenarios, templates must explicitly organize inputs to ensure correct interpretation. Their consistent formatting and reusability make them essential for structured tasks requiring high output stability and quality control.

In-Context Learning.

In-context learning enables LLMs to adapt to new tasks without parameter updates, relying solely on task descriptions and a few examples within the input prompt. This approach leverages the model’s pre-trained knowledge to infer task patterns.
The process includes three steps: 1) describing the task, 2) providing few-shot examples formatted using
g(\cdot)
and ordered logically, and 3) appending the test query for prediction. Proper selection and organization of examples are critical to performance
dong2022survey
. In-context learning is especially effective for rapid adaptation to new or cross-domain tasks, often used alongside prompt templates.

Chain-of-Thought Prompting.

Chain-of-Thought (CoT) prompting
wei2022chain
is an in-context learning technique that enhances the problem-solving capabilities of LLMs by decomposing complex tasks into intermediate reasoning steps. CoT exemplars provided in the prompt include not only input-output pairs but also explicit reasoning chains, guiding the model through a step-by-step deductive process.
Formally, denote the instructional prompts as
T
, given an input
x
, output
y
, and a reasoning chain
\mathrm{CoT}
, the prompt function
g(x,\mathrm{CoT})
converts them into natural language, and the LLM predicts
\hat{y}
:

\mathrm{LLM}(T,g(x,\mathrm{CoT}))\rightarrow\hat{y}.

(1)

While textual CoT is common, code-based reasoning
chen2022program
can improve precision for complex tasks. Zhao et al.
zhao2023automatic
further propose dynamic switching between text and code CoT to combine their strengths. CoT prompting is well-suited for complex reasoning tasks, such as guiding LLMs through multi-step logic when generating network systems code, and is often combined with in-context learning for enhanced performance.

Structured Chain of Thought

SCoT
li2025structured
utilizes natural language reasoning steps in a pseudo-code format to describe the program’s control flow, guiding the model to generate a logically coherent framework. It enhances the reasoning process by incorporating two key features. First, it constrains the LLM’s solution space by requiring that all solutions be constructed exclusively from the three fundamental control structures: sequential, conditional, and iterative. Second, SCoT mandates a more rigorous definition of module interfaces by requiring the explicit declaration of input and output parameter types.

Semantic Chain of Thought

SeCoT
ma2023bridging
guides LLMs to incorporate source code semantics—including data flow and control flow—into function-level code generation. It structures reasoning into coherent steps by explicitly tracking how data is processed and operations are executed, dividing tasks into data flow and control flow components. Practically, SeCoT can be applied by first analyzing the program’s data dependencies and operation order, then generating code step by step while maintaining logical consistency, ensuring accurate translation of requirements into executable functions, and supporting adaptive solutions for complex tasks.

Motivation

This section identifies a research gap in applying LLMs to the reproduction of network research results. While the demand for reproducibility is high and LLMs are capable of code generation, current frameworks are too narrow in scope, limiting their applicability to the unique challenges of networking and motivating our work.

3.1
Necessity of Results Reproduction in Network Research

The limited availability of open-source implementations requires independent result reproduction. A statistical analysis of papers published in SIGCOMM and NSDI from 2016 to 2025, shown in Figure
1
, confirms this trend: only 41.63% of SIGCOMM and 38.78% of NSDI papers, respectively, released their code during this period.

Figure 1
:
Statistics of SIGCOMM and NSDI papers with an
open-source prototype from the authors (2016-2025).

As noted in
xiang2023toward
, conducting a comprehensive network systems study often requires substantial effort from authors to reproduce others’ systems. Specifically, 59.68% of the papers compared their work against at least two systems, with authors manually reproducing an average of 2.29 systems per paper. Furthermore, 49.20% of the papers reproduced at least one comparison system, and 26.65% required reproducing two or more systems. Researchers are compelled to invest considerable effort in fundamental reproductions, thereby impeding the overall pace of innovation.

Manual reproduction of network research presents three critical challenges. First, it is exceptionally labor-intensive, demanding significant effort for re-implementation that detracts from research productivity. Second, the process is error-prone, as missing source code or experimental details can lead to deviations from the original findings and compromise the work’s credibility. Moreover, with the escalating complexity of network systems, this reliance on manual effort is unsustainable, slowing the verification of new research and diverting focus from innovation.

3.2
Code Reproduction with LLMs

LLMs have demonstrated significant capabilities in code generation, achieving remarkable performance on tasks such as code completion
github_copilot_2025
, debugging
openai-chatgpt
;
zhang2024pydex
;
zhang2022automated
, and code synthesis
rahmani2021multi
;
yen2021semi
. However, existing approaches face significant limitations in automatically extracting information from the structured and cross-referenced contexts found in multimodal research papers, thereby hindering LLMs’ end-to-end code generation for network systems.

Recent work on using LLMs to automatically implement findings from academic literature has shown promise, but these efforts have been largely confined to highly structured domains. For instance, existing studies have successfully transformed machine learning papers into executable code
seo2025paper2code
;
lin2025autop2c
, a task facilitated by the standardized ML ecosystem of frameworks like PyTorch
pytorch
and benchmark datasets. This standardization simplifies environment configuration and data preparation, making the code generation task more tractable for LLMs. In contrast, the heterogeneity of the networking research landscape—with its diverse experimental setups and lack of uniform frameworks—presents significant challenges to straightforward, end-to-end code reproduction.

3.3
Complexity of Network Research Paper Reproduction

Prior work has begun to explore the use of LLMs in networking research, albeit with certain limitations. Some early efforts focused on using natural language processing techniques to translate structured inputs, such as network configurations and RFC documents, into system code
chen2022software
;
yen2021semi
. More recent work has adopted direct, prompt-based interaction with LLMs for code generation; however, this approach can demand substantial manual effort, with one study reporting an average of 294.5 handcrafted prompts to reproduce a single system
xiang2023toward
. To mitigate this burden, LASER was introduced as a semi-automated, LLM-assisted framework for experiment reproduction, but its application is currently limited to the specific domain of Low Earth Orbit (LEO) satellite networks
wang2025llm
.

Moreover, although LLMs have demonstrated the capability to generate system-level code, these methods are restricted to well-structured inputs within narrow domains and remain inadequate for generating system code or evaluating novel contributions across the broader networking research landscape.
The heterogeneity of the computer networking field presents three primary obstacles to automated research reproduction:

•

Diverse Research Topics:
The field encompasses a wide array of distinct sub-domains (e.g., congestion control, traffic engineering, verification), which has precluded the development of a single, standardized framework for reproducing results.

•

Unstructured Content Formats:
Research papers lack a standardized format, with authors employing diverse writing styles and embedding critical information in multimodal content like diagrams, thereby challenging comprehensive interpretation by LLMs.

•

Heterogeneous Architecture:
A direct consequence of the broad scope of networking research is the significant variation among proposed systems, including differences in their architectural design, programming languages, and overall complexity.

The deficiency of existing methods for reproduction of network research motivates the development of a framework for automated code generation in this domain. To address the above challenges, we design a fine-grained workflow for applying LLMs to the automated code generation of network systems.

4.1
Paper Content Decomposition

Content decomposition module first partitions a paper by its sectional structure, uniformly processing multimodal content such as figures, tables, formulas, pseudo-code, and text. This approach is designed to simplify the information volume provided to LLM, addressing the established trade-off where performance suffers from insufficient or excessive input

•

•

•

•

This retrieval-augmented approach grounds the LLM, allowing it to discern relationships between document sections and efficiently pinpoint necessary information.

4.2
System Description Extraction

A key vulnerability of LLMs is their tendency to accept user prompts without verifying their factual or logical integrity, which can lead to unreliable outputs from ambiguous or misleading inputs. RePro addresses this by systematically augmenting the prompts with relevant background knowledge. This proactive contextualization minimizes the impact of potentially flawed user input, thereby reducing ambiguities and biases in the generated results.

Progressive Prompt Template

We employ a progressive prompt template to enhance the LLM’s ability to parse and reason about research papers. First, RePro primes the LLM with the paper’s foundational domain knowledge. Then, it specifies decomposition metrics to guide the model towards a high-quality architectural structure. Further, RePro integrates specific content from the paper to generate the complete system architecture. Moreover, we employ an iterative querying process in each task (e.g., system’s architecture generation) to enable the model to construct a deep contextual understanding.

To establish a foundational context for the LLM, RePro first extracts key metadata from the paper, including the research domain, system name, deployment type, and specific problems. 5
Code Generation and Optimization

This section introduces RePro, a semi-automated system based on LLMs for implementing the systems designed in network research. RePro is a highly structured prompt engineering framework that is composed of three core modules–framework-level and function-level code generation, and code optimization, that work collaboratively to achieve accurate and efficient reproductions of network research.

5.1
Automated Framework-Level Code Generation

Based on requirements for software architectures in software engineering, we consider the following principles to design the prompts for framework-level code generation:

•

Design-Oriented Guidance:
The prompt must direct the model to prioritize the module’s high-level design logic and structure, deferring function-level details.

•

Structured Function Signatures:
The prompt must require the model to define each sub-function with an explicit signature (i.e., name, input parameters, and output), ensuring these definitions align with the paper.

•

Facilitation of Iterative Refinement:
To facilitate a subsequent process of iterative refinement, the prompt should instruct the model to generate minimal, yet executable, placeholder implementations for sub-functions.

Motivated by the structured program theorem
bohm1966flow
, which establishes that any computable function can be implemented using only sequential, conditional, and iterative control structures, we employ the SCoT
li2025structured
to generate framework-level code, which intentionally abstracts away from low-level semantic details.

We continue the progressive code generation scheme to construct prompt templates. First, we generate SCoTs to illustrate a coarse-grained solution produced by the LLM. Second, building on the SCoTs, we enable the LLMs to generate code frameworks by learning from given examples. Further, we map functions to the paper’s content to ensure consistency.

As shown in Figure

5.2
Automated Function-Level Code Generation

After producing the framework-level code, RePro then implements the placeholder functions within the framework and integrates them to construct a fully functional module.

The SCoT approach does not model fine-grained semantic details of source code, such as data and control flow
schach1990software
, which limits its ability to accurately represent complex function logic. To address this limitation, we employ Semantic Chain of Thought (SeCoT)
ma2023bridging
for function-level code generation. By explicitly incorporating this low-level semantic information, SeCoT facilitates a more detailed code representation, significantly improving the accuracy and consistency of the generated functions.

We design prompts based on the following principles to ensure the comprehensiveness and completeness:

1.

Structured Design:
Each function represents an independent sub-function, adhering to the single responsibility principle, with clear inputs and outputs.

2.

Detail Completeness:
Function code should be comprehensive, fully realizing the functional requirements without missing edge cases or error-handling logic.

To generate high-quality function code, we utilize a few-shot prompting approach with SeCoT, as shown in Figure
7
. The prompt conditions the LLM on example triplets of
\langle\text{Requirement, SeCoT, Code}\rangle
. When presented with a new requirement, the LLM first generates a SeCoT that explicitly details the necessary
Data Flow
and
Control Flow
. This intermediate reasoning step then guides the generation of the final code, ensuring a precise mapping from the high-level requirement to the low-level implementation. Moreover, the prompt explicitly enforces strict adherence to new requirement descriptions.

Prompt engineering for generating function code.

RePro also instructs the LLM to verify input/output format compliance and to generate test cases for correctness validation.

5.3
Code Optimization

We use manually constructed test cases along with generated test cases to optimize code. When module code fails validation, it reveals errors that undermine the reliability of reproduction. We categorize such errors into syntactic and semantic types, as they differ fundamentally in nature and repair strategies. Syntax errors are usually straightforward to fix through structural corrections, whereas semantic errors demand deeper reasoning and contextual understanding. This distinction enables more efficient debugging and enhances the robustness of reproduction outcomes.

Syntax Error Correction

When a syntax error prevents code compilation, we leverage the compiler-generated error message as direct input to the LLM, prompting the model to automatically correct the underlying syntactic flaw in the code.

First, we prevent
variable access errors
by pre-specifying all necessary variables and their data types in the prompt (e.g., “variable
x
should be a floating-point number”) before the main code generation task.
Second, we mitigate potential
type errors
in loops by explicitly defining variables intended for iteration as iterable objects in the prompt (e.g., instructing the model that “the items variable must be a list or string”).
Moreover, we enforce a consistent
data format
and prevent errors by providing the model with a template that defines the required attributes and structural schema for the output.

Semantic Error Correction

Semantic errors occur when code is syntactically valid but its logic or behavior does not match the intended design, which are typically uncovered only during execution or testing. We categorize them into two main types:
invocation errors
and
logical errors
.

To address invocation errors, which often result from contextual issues such as improper resource initialization, we iteratively prompt the LLM to correct the code. In each iteration, we provide the model with detailed specifications of the relevant functions, including their inputs, outputs, and intended behavior.

We address logical errors, where generated code is inconsistent with textual descriptions or expected logic, through two main approaches.

•

Test-Driven
: To facilitate self-correction, the LLM is prompted with the expected input-output pairs and functional requirements, effectively providing it with a test case to validate its generation.

•

Human-in-the-Loop
: We first manually identify the precise error location and perform a root cause analysis. We then decompose the complex error and design a targeted prompt to guide the LLM through an incremental correction of the specific issue.

Once the corrected code modules are integrated to assemble the complete system, a final phase of integration testing is performed. This step validates the function calls and data exchange between the different module interfaces.

This section outlines our end-to-end methodology for automated code reproduction, detailing a systematic process that begins with high-level document analysis and culminates in low-level code generation.

RepLLM Architecture.

6.1
Workflow of RePro

As depicted in Figure
8
, RePro is divided into two parts: automated system architecture generation and semi-automated module code generation. We propose a multi-stage pipeline. Starting from a network systems paper, the
Paper Preprocessing
stage extracts key contextual information through structured analysis. This information, combined with a prompt template, guides the

6.2
System Description Extraction

Preprocessing module contextualizes the LLM for the paper’s specific domain while extracting essential information, which enhances the performance of all downstream tasks.
First, RePro employs prompts to guide the LLM in extracting key elements from the paper. The LLM is first tasked with identifying the paper’s core characteristics, such as the network sub-field, the system’s name and purpose, and its architectural details. The output is a structured JSON object that encapsulates this initial understanding.

Further, the LLM decomposes the reproduction task into a series of independent functional steps, leveraging information from the introduction, design, and outline. For each step, the model produces a concise description, a detailed explanation, and the corresponding inputs and outputs, again in structured JSON format. This representation provides a clear and actionable blueprint for subsequent code generation.

6.3
Framework-Level Code Generation

RePro first generates the system’s framework.
The generation of executable code for each decomposed module is an iterative, three-phase process guided by CoT-based prompt engineering. The process is initiated by contextualizing the LLM, which involves mapping the module to its relevant descriptive sections in the source paper. With this context, a few-shot prompt is then used to generate a logical scaffold, consisting of both a SCoT and a modular code framework. The final output is a comment-rich code framework, produced by synthesizing the generated SCoT with verbatim text from the paper, ensuring each component is annotated with its original description.

6.4
Function-Level Code Generation

RePro then implements each function using a two-step generation process. First, it prompts the LLM to generate a SeCoT for the target function, which serves as a structured representation abstracting the required data flow and control flow. Subsequently, this newly generated SeCoT, combined with a set of few-shot exemplars, is used to prompt the LLM to produce the final, executable code for the function.

6.5
Code Optimization

In the final stage, RePro applies automatically generated test cases to fix errors. Moreover, we apply manual optimization to enhance its robustness and verifiability. The ultimate output of this entire workflow is a set of complete, documented, and semantically-grounded code modules. These modules are then ready for integration to construct the full, reproducible system implementation.

7
Evaluation

This section evaluates RePro in terms of reproduction accuracy and time efficiency. We reproduce six distinct systems addressing heterogeneous tasks.
The accuracy of our reproduced implementations closely matches the original open-source versions, confirming RePro’s high fidelity. Moreover, RePro significantly reduces the time for this process compared to unstructured LLM interactions, which validates the efficiency of our prompt engineering framework.

7.1
Setup

We select our participants for using our RePro to be students in computer science or related disciplines, each having received systematic training in programming and computer networks. As designed in RepLLM, participants were tasked with leveraging a suite of our framework’s techniques, including structured preprocessing, SCoT, and SeCoT.

For consistency, each participant was tasked with reproducing a computer networking paper with which they were already familiar. Participants were explicitly prohibited from manual coding and were required to use our framework exclusively for all generation and debugging tasks. The debugging process involved iterative interaction with the LLM. To resolve persistent errors, participants were permitted to refine their prompting strategies or adjust generation parameters within the system.

To comprehensively evaluate the adaptability and performance of LLMs in the context of research paper reproduction, our experiment considers multiple critical dimensions, including code generation capability, context window size, and output token constraints.

8
Conclusion

This work presents RePro, a semi-automated LLM-based framework for reproducing computer networking research. RePro transforms complex academic descriptions into executable code through a structured, multi-stage pipeline, incorporating techniques such as structured preprocessing, SCoT, and SeCoT to maintain fidelity and logical rigor. Experimental results show that RePro substantially reduces reproduction time while achieving performance closely aligned with original systems, demonstrating the effectiveness of our prompt engineering approach.

Appendix A
Comparison of Different CoT

Unlike natural language generation, code generation targets highly structured output. Thus, intermediate reasoning steps must also be structured to ensure clarity, correctness, and problem-solving efficiency. The standard Chain of Thought (CoT) method provides only natural-language descriptions of task logic without explicitly embedding program structures. For instance, in Figure
16
, the CoT method outlines the process of finding odd numbers in an array but fails to specify program structure or I/O requirements, leading to less accurate code.

SCoT explicitly incorporates the three basic structures (sequential, conditional, iterative) into reasoning, constraining the LLM to flexibly leverage them to build solutions. In addition, SCoT extends the definition of input-output structures, including parameter types. This allows the model to analyze requirements more precisely, clarifying inputs and outputs for downstream code generation. As shown in Figure
16
, SCoT defines input-output requirements first, then details pseudo-code steps that map directly to structured logic. This structured design not only enhances logical reasoning but also reduces potential errors caused by missing program structures, improving usability and accuracy.

SeCoT guides LLMs to integrate data and control flow semantics into function-level code generation. It structures reasoning into coherent steps, analyzing dependencies and execution order to produce accurate, consistent, and adaptable code.As shown in Figure
16
, SeCoT systematically summarizes semantic information into a series of coherent reasoning steps, dividing the task into
Data flow
and
Control flow
, and guiding LLMs to integrate key elements from both. Furthermore, SeCoT introduces semantic summaries within the reasoning process, reminding the model to leverage semantic information to better understand program logic and behavior. This design not only improves the quality of generated code but also enables LLMs to construct more innovative and adaptive solutions when handling complex requirements.

These studies all demonstrate the potential of large language models for reproducing research papers, but none have focused on the field of networking research.
