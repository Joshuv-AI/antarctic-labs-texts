Compressing Hypergraphs using Suffix Sorting
Enno Adler, Stefan Böttcher, Rita Hartel

Abstract
Hypergraphs model complex, non-binary relationships like co-authorships, social group memberships, and recommendations. Like traditional graphs, hypergraphs can grow large, posing challenges for storage, transmission, and query performance. We propose HyperCSA, a novel compression method for hypergraphs that maintains support for standard queries over the succinct representation. HyperCSA achieves compression ratios of 26 % 26\% to 79 % 79\% of the original file size on real-world hypergraphs—outperforming existing methods on all large hypergraphs in our experiments. Additionally, HyperCSA scales to larger datasets than existing approaches. Furthermore, for common real-world hypergraphs, HyperCSA evaluates neighbor queries 6 6 to 40 40 times faster than both standard data structures and other hypergraph compression approaches.

Related Work

Like graphs, hypergraphs can be very large. For large hypergraph databases, there is the research branch of partitioning a hypergraph
[
20
]
and of parallel graph processing with tools like Hygra
[
21
]
and CHGL
[
13
]
.

Each hypergraph can be translated into a graph with edges connecting only two nodes, that describes essentially the same data as a hypergraph. Most common methods are the clique expansion, where the rank-k hyperedge is represented by a k-clique, and the star expansion, where a new node is introduced and all nodes of the hyperedge are connected by a new edge with that node. Both methods have multiple downsides regarding compression and querying: They increase the number of objects in the graph by a large factor in comparison to using hyperedges. These expanded graphs are less effective to compress and need many edge lookups to check for an existing hyperedge between multiple nodes. Huang et al.
[
11
]
conclude in the context of distributed hypergraph processing, that expanding hypergraphs to graphs cause major efficiency drawbacks.

Liu et al.
[
16
]
argue likewise for graph processing acceleration. They propose a hypergraph compression method based on the incidence list: They use two one-dimensional arrays, one for the incident hyperedges and one for the nodes and two indexes for each one that contain the start and end of ranges in the arrays. They achieve compression by overlapping the equal nodes (or equal incident hyperedges) of successive hyperedges (or successive nodes). As neither nodes nor hyperedges have an order, they propose a reordering strategy for better compression and less cache misses on access.

4.2
Decompression

Every SA-position

4.3
Theoretical Analysis of HyperCSA

We start with analyzing the size of HyperCSA.
D
has
M_{G}+1
bits and we store this as a plain bitvector together with rank and select data structures that support
\mathcal{O}(1)
rank
[
26
]
and select
[
3
]
queries. For the rank data structure, we need additional
0.25(M_{G}+1)
bits and for the select data structure, we need up to
0.2(M_{G}+1)
bits, so in total,
D
requires at most
1.45(M_{G}+1)
bits.

Storing
\Psi
as plain numbers is inefficient, because
\Psi
has size
M_{G}
and would take the same space as
T
. However,
\Psi
can be encoded significantly smaller than
T
, because
\Psi
consists of at most
|V_{G}|
strictly increasing subsequences. In
Theorem 0.A.2
in Appendix
0.A
is the proof of this statement. This property makes
\Psi
compressible using the differences
\Psi[i]-\Psi[i-1]
.

Overall,
\Psi
can be stored in space proportional to the zero-order empirical entropy of
T

[
6
]
. The
zero-order empirical entropy
for
T
is

H_{0}(T)=\sum_{i=0}^{|V_{G}|-1}\frac{degree(i)}{M_{G}}\log\left(\frac{M_{G}}{degree(i)}\right)\text{ with }M_{G}=\sum_{i=0}^{|V_{G}|-1}degree(i)

with
degree(i)
being the degree of node
i
, which is equal to the frequency of
i
in
T
,
|T|=M_{G}
, and
|\Sigma|=|V_{G}|
.
\Psi
can be represented in
M_{G}H_{0}(T)+\mathcal{O}(M_{G}\log(H_{0}(T)))\leq M_{G}\log(|V_{G}|)+o(M_{G}\log(\log(|V_{G}|)))
bits.
Using
\delta
-codes and run-length encoding for runs of
1
in the
\Psi[i+1]-\Psi[i]
, we can reduce the size to
M_{G}H_{k}(T)
with
H_{k}(T)=\frac{1}{M_{G}}\sum_{w\in\sigma^{k}}|w_{T}|H_{0}(w_{T})
with
w_{T}
being the concatenation of all symbols following the sequence
w
in
T

[
1
]
.

We encode
\Psi
using the relative values
\Psi[i+1]-\Psi[i]
. For fast practical access, every
t=128
position stores the absolute value of
\Psi
. This ensures a constant access time of
\mathcal{O}(t)
. In
Figure 2
, we show
\Psi_{\Delta}
for the example with

.

Next, we investigate the construction time of HyperCSA. First, constructing
T
uses two rounds of sorting integers. First, we do
|E_{G}|
sorting steps of edges, which takes
\mathcal{O}(|E_{G}|\cdot R\log(R))
time. Second, the sorting of the edges takes
\mathcal{O}(|E_{G}|\cdot R\log(|E_{G}|))
, because a single comparison of two edges can take up to
R
steps. Constructing
D
takes
\mathcal{O}(M_{G})
for the frequency scan of
T
and
\mathcal{O}(M_{G})
for assigning the unary code to
D
. Constructing
\Psi
takes
\mathcal{O}(M_{G})
, as the construction consists mostly of computing the suffix array.
Algorithm 2
traverses the cycle of
\Psi_{CSA}
once, which takes
\mathcal{O}(M_{G})
. Thus, the construction time of HyperCSA is
\mathcal{O}(|E_{G}|\cdot R(\log(R)+\log(|E_{G}|))+M_{G})=\mathcal{O}(|E_{G}|\cdot R(\log(R)+\log(|E_{G}|)))
.

Hypergraph input files are often sorted, so the nodes in edges appear in ascending order and the edges are also in ascending order. In this case, we can omit the sorting steps and get
\mathcal{O}(M_{G})
as construction time.

4.4
Queries

The
degree(v)
query answers for a node
v\in V_{G}
, how many edges are incident to
v
. The question can be solved in
\mathcal{O}(1)
by using
D
only:
degree(v)=select_{D}(v+2,1)-select_{D}(v+1,1)
, and
select

\mathcal{O}(1)

[
3
]
.

The
contains(v_{0},\dots,v_{k-1})
query returns all edges that contain all the nodes
v_{0}
to
v_{k-1}
, so
contains(v_{0},\dots,v_{k-1})=\{e\in E_{G}:\{v_{0},\dots,v_{k-1}\}\subset e\}
.

Answering
contains
queries is straightforward. As first step, we sort the nodes of the query in ascending order, if they are not already sorted. Second, let
v_{m}
be the node of the query with the smallest
S(v_{i})
for all
i=0,\dots,k-1
. Every position
i\in S(v_{m})
belongs to one (different) edge that contains the node
v_{m}
.

We test each edge at a position
i\in S(v_{m})
individually by traversing
\Psi^{k}[i]
if the set
\{\Psi^{k}[i]:k=0,1,\dots\}
contains the other nodes of the query. We sorted the query because the nodes will appear in the same order in the edge as in the sorted query. However, the edge is allowed to contain more nodes than the query. When the last node of the query
v_{m-1\mod k}
is found in an edge, we can output the edge as valid result. Note that we partially decompressed the edge for checking the nodes, so we only need to decompress the rest of the edge.

Due to the construction of
T
, we have multiple conditions to abort and discard an edge:

1.

When
\Psi^{l}[i]=i
for
l\in\mathbb{N}
before we found all nodes of the query.

2.

If the current node
rank_{D}(\Psi^{l}[i],1)
is higher than the next node of the query, except if the next node of the query is the lowest node of the query.

3.

If we are at the index
j
with
\Psi[j]<j
for the edge and the next node of the query is not the lowest node.

4.

If we look for the lowest node of the query, we are at position
j=\Psi^{l}[i]
with
\Psi[j]<j
and the node
rank_{D}(\Psi^{l+1}[i],1)
is greater than the node of the query.

All these discard conditions origin in the sorting of the nodes of an edge and the cyclic structure of
\Psi
.

The
exists(v_{0},\dots,v_{n})
query answers how many edges
\{v_{0},\dots,v_{n}\}
exist in
E_{G}
, so
exists(v_{0},\dots,v_{n})=|\{\{v_{0},\dots,v_{n}\}\in E_{G}\}|
. In the case of
E_{G}
being a multiset, the answer might be larger than one.

First, we sort
v_{0},\dots,v_{n}
in ascending order, if they are not already sorted. Second, we set
\mathcal{I}_{0}=S(v_{0})
. Third, we iterate over the nodes
v_{2}
to
v_{n}
. At the iteration of node
v_{i}
, we determine
\mathcal{I}_{i}
using
\mathcal{I}_{i-1}
, where each
\mathcal{I}_{i}
is a subinterval of
S(v_{i})
as follows: We binary search the subinterval
\mathcal{S}
of
\mathcal{I}_{i-1}\subset S(v_{i-1})
with the property that for
i\in\mathcal{S}
,
\Psi[i]\in S(v_{i})
. Then, we set
\mathcal{I}_{i}=\Psi[\mathcal{S}]=[\Psi[\min(\mathcal{S})],\Psi[\max(\mathcal{S})]]
. Fourth, we have
\mathcal{I}_{n}
for the highest node
v_{n}
now. We check for closed cycles like the previous steps: We search the interval
\mathcal{S}
of
\mathcal{I}_{n}
with
\Psi[i]\in S(v_{0})
. Then, we output the length of the interval
[\Psi[\min(\mathcal{S})],\Psi[\max(\mathcal{S})]]
as the result to the
exists
query. We prove the correctness of the results of the exists queries in
Theorem 0.A.3
in Appendix
0.A
.

4.5
Runtime Analysis of Queries

Because we answer
select
queries on
D
in
\mathcal{O}(1)
, we can get
S(v)
for
v\in V
in
\mathcal{O}(1)
. The length of
S(v)
is
degree(v)
. The binary search on
\Psi
on the interval
S(v)
thereby needs only
\mathcal{O}(\log(degree(v)))
.

For the
contains
query, we search the minimum over
k
values. Then, for every edge of that interval, we perform at most
R
decompression steps. Each test for the next query node costs only
\mathcal{O}(1)
. Thus, we have an average runtime of
\mathcal{O}(k+\text{avg}(degree,V_{G})\cdot R)
.

For the
exists
query with
v_{0},\dots,v_{n}
, we have
2(n+1)
binary searches. Thus, the average runtime of an exists query is
\mathcal{O}(n*\log(\text{avg}(degree,V_{G})))
. Here,
avg
is the average of the degrees of
V_{G}
.

6
Conclusion

We presented HyperCSA, a succinct data structure for compressing and querying hypergraphs. HyperCSA employs multiple sorting steps and compressed suffix arrays for compression and uses this sorting beneficially together with select and rank for querying the hypergraph. Our experiments show that HyperCSA has smaller compression size and faster query time on all large datasets than comparable approaches.

Theorem 0.A.1

Let
T
be constructed as described above. If
T[j+1]\leq T[j]
, then
T[j+1..]<T[j..]

Proof

If

is obvious.

If
T[j+1]=T[j]
:
T[j]
is the highest node of an edge
(T[i],\dots,T[j])
with

and
(T[j])
is an edge of rank

(T[j+1])
must be a loop at the same node
T[j]

(T[j+1],\dots,T[m])
is lexicographic smaller than
(T[j])

We now have three cases:

First, if

Second, if

Third,

Note that the second case proves the following statement: If we do not have multiple loops at a single node,

Theorem 0.A.3

Proof

.
