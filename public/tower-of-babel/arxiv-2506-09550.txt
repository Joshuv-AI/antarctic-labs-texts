Automated Synthesis of Formally Verified Multi-Abstraction Function Summaries
1 st Fanpeng Yang, 2 nd Xu Ma, 3 rd Shuling Wang *, 4 th Xiong Xu, 5 th Qinxiang Cao, 6 th Naijun Zhan, 7 th Xiaofeng Li, 8 th Bin Gu

Abstract
Function summaries, which characterize the behavior of code segments (typically functions) through preconditions and postconditions, are essential for understanding, reusing, and verifying software, particularly in safety-critical domains like aerospace embedded systems. However, these mission-critical legacy code serving as a valuable reused asset often lacks formal specifications. It is challenging to automatically generate function summaries for C programs, due to the existence of complex features such as loops, nested function calls, pointer aliasing, and so on. Moreover, function summaries should support multiple abstraction levels to meet diverse requirements, e.g. precise summaries capturing full functionality for formal verification and intuitive summaries for human understanding. To address these challenges, we first propose a novel framework that combines symbolic execution, large language models (LLMs), and formal verification to generate Relatively Strongest Postconditions (RSPs) and build function summaries that fully capture program behavior. Our approach leverages VST-A’s symbolic execution to precisely track program execution paths and state transitions, employs LLMs to infer loop invariants based on predefined templates, and uses Frama-C to guarantee soundness of generated summaries in an iterative refinement loop. Furthermore, from generated RSPs, we automatically synthesize strongest non-redundant postconditions expressed within given domain specific language. We compare our approach with existing work through extensive experiments.



I
Introduction

In many safety-critical domains, such as aerospace, automotive, and medical systems, software often relies on legacy code that implements critical functionality but lacks formal specifications. This raises challenges for correct reuse of these codebases, particularly when such code is integrated into new safety-critical systems. A key requirement in these domains is the ability to automatically determine what a piece of code actually does, which we formalize as generating function summaries. These summaries are crucial for selecting correct implementations and ensuring their safe usage in safety-critical system design.

However, representing function summaries introduces additional challenges. For formal verification purpose, summaries must be precise enough to capture fine-grained functional behavior, with details necessary for rigorous proof construction. Yet, for human-centered tasks, e.g., selecting reusable components during design, overly detailed summaries make them difficult to understand for domain experts. Existing approaches fail to reconcile these needs: traditional verification tools require predefined specifications and thus produce property-specific postconditions to prove the given specifications, while design documentation suffers from ambiguity due to natural language description; and recent work on formal specification synthesis lacks multi-level abstractions to meet diverse requirements

This paper addresses these challenges by proposing a multi-granularity summary synthesis framework for C programs. We represent function summaries through pre-/postconditions, with an automatic precondition generation to derive the weakest sufficient initial conditions for correct execution (e.g. pointer validity). The key challenge lies in postcondition generation for C programs, which must account for complex features including loops, nested function calls, and complex pointer manipulations. They introduce fundamental difficulties: loops demand precise invariants to capture the behavior of unbounded iterations without predefined verification targets, complicating invariant synthesis; nested function calls introduce interprocedural control flow complexity; and pointer aliasing leads to state space complexity.

To address these challenges, we develop a combined approach which seamlessly integrate symbolic execution, formal verification and large language models (LLM) to generate relatively strongest postconditions (RSPs) of functions. Through symbolic execution, our tool can precisely track program execution paths and state changes, constructing strongest postconditions for straight-line code segments. For loops, we propose a template-guided LLM synthesis to generate invariants fitting constraint templates derived from symbolic execution data. Generated invariants are then iteratively refined via formal verification, with counterexamples fed back to the LLM until soundness is achieved.
In the implementation, we leverage VST-A’s symbolic execution engine
[
5
]
for its ability to precisely track program states and path conditions at arbitrary execution points, combined with Frama-C
[
6
]
as our formal verifier to ensure summary correctness due to its automated verification and also ACSL-style assertions that are particularly amenable to LLM processing. Our framework tightly integrates VST-A, Frama-C, and LLMs, where each component’s strengths compensate for the others’ limitations.

Starting from the generated RSPs, we further develop an automated synthesis framework to generate more absract function summaries expressed in given domain specific languages (DSLs). Targeting aerospace software requirements as a case study, we design specialized DSLs focusing on different aspects such as side effects and numerical computation properties. Our framework is able to derive the strongest non-redundant postcondition expressible within each given DSL’s vocabulary, effectively distilling verification-grade RSPs into DSL summaries without losing essential information.

Our goal is to automatically generate function summaries at multiple abstraction levels, satisfying both rigorous verification and human-centric system design requirements. This task is particularly challenging for real-world code programs due to the existence of loops, nested function calls, and complex pointer manipulations. Traditional formal verification faces the same problem but it focuses exclusively on verifying whether a program satisfies a given specification rather than inferring complete summaries that fully characterize the program’s behavior.

II-A

Our Approach

Our approach to generating program summaries is structured into a two-phase process:
summary generation
and
summary generalization
, as shown in Fig.
2
.

The
summary generation
phase employs mainly symbolic execution to automatically derive precise, first-order logic summaries from input functions by exploring all execution paths. Two program constructs require specialized handling:

•

Loop invariant generation: When a loop is encountered during symbolic execution, a loop invariant is required to summarize its behavior without unfolding the loop many times for the symbolic execution to proceed. We develop a key module that combines symbolic execution, LLMs and formal verification to generate precise and sound loop invariants. Especially, using symbolic execution results and constraint templates, it produces precise invariants
able to characterize loop behavior without relying on predefined verification targets.

•

Callee summary generation: During symbolic execution, function calls are handled by generating reusable callee summaries. These are instantiated with current symbolic states to derive the function call postconditions. For nested calls, a call stack is introduced to track the execution contexts, constructing summaries bottom-up for composition.

Ideally, once symbolic execution is completed for a function, the disjunction of assertions specifying all reachable paths and final symbolic states constitutes the
relative strongest postcondition (RSP)
of the function, which serves as its most precise summary.

The
specification generalization
phase takes the precise function summary derived from the first phase and transforms it into a more generalized and abstract representation within a given domain-specific language (DSL).
As illustrated in Fig.
2
, we implement an algorithm to find the best conjunction in DSL from the initial function summary, which is analogous to computing a strongest non-redundant clause set. It involves simplifying the complex disjunctive precise summary into a conjunction of clauses expressible in the chosen DSL.

III-A

Symbolic Representation

We use a
flattened memory model
to represent symbolic states, explicitly tracking pointer aliasing and memory dependencies. Before giving the definition, we introduce some notations. A
program point

p
is a distinct location in a program’s control flow, with an associated scope determining accessible variables. Within a given scope, the memory is modeled as a collection of atomic memory locations
\mathcal{L}_{p}
, representing flattened program variables and addressable memory units. Each
v\in\mathcal{L}_{p}
is a unique, indivisible unit storing a value of a base type, e.g.,
int
, pointer address
etc
.

A
symbolic state

\sigma_{p}
at program point
p
maps
\mathcal{L}_{p}
to their respect symbolic values in
\mathcal{V}
. Our memory model assumes that at any program point
p
, every atomic memory location in
\mathcal{L}_{p}
is accessible and initialized. The symbolic execution of a program is then a sequence of state transitions, staring from the initial state
\sigma_{p_{0}}
at initial program point
p_{0}
.

Limitations
:
Building upon the flattened memory model, we restrict our analysis to C programs with non-recursive data structures and non-recursive function calls.
This ensures all memory locations can be statically determined and finitely represented in
\mathcal{L}_{p}
.

III-B

Symbolic Execution

Symbolic execution
is a program analysis technique that explores program execution paths using symbolic values instead of concrete inputs.
Given a function
\mathcal{F}
, its symbolic execution starts with a precondition
Pre
, defined as
PC_{0}\land\mathrm{StateForm}(\sigma_{p0})
, where
\sigma_{p0}
is the initial state mapping inputs to initial symbolic values,
\mathrm{StateForm}(\sigma_{p0})
is the logical formula, i.e. the conjunction of equalities
describing the values of all memory locations in
\sigma_{p0}
in terms of initial symbolic values, and
PC_{0}
the constraints on these symbolic values. By default,
Pre
ensures that all memory locations of
\sigma_{p0}
are accessible and initialized. An execution path
\pi
tracks symbolic values of all atomic memory locations, accumulating branch constraints. Upon completion, it yields
(PC_{\pi},\sigma_{p,\pi})
, where
\sigma_{p,\pi}
is the final symbolic state and
PC_{\pi}
is the path condition for path
\pi
to be executable.

We define two procedures:
\mathrm{SEStart}(\mathcal{F},\textit{Pre},p)
performs symbolic execution from any program point
p
for function
\mathcal{F}
with precondition
Pre
, till a loop or a function call is reached, and
\mathrm{SECollect}(\mathcal{F},\textit{Pre},p)
collects the symbolic results composed of sets of (path, state) for program point
p
, i.e.

\displaystyle\left\{(PC_{\pi},\sigma_{p,\pi})\left|\begin{array}[]{l}\pi\text{ is an execution path}\\
\text{reachable from }p_{0}\text{ to }p\end{array}\right.\right\}

Denote the function’s exit point by
p_{-1}
, then
\mathrm{SECollect}(\mathcal{F},\textit{Pre},p_{-1})
provides all accumulated path conditions and states at termination of
\mathcal{F}
.

Loops and function calls pose challenges for complete path exploration. To address these constructs, our approach integrates symbolic execution with LLMs and formal verification to generate loop invariants to over-approximate iterative behavior and callee function summaries to handle (nested) function calls. We detail these techniques in Sections
III-D
and
IV
respectively.”

III-C

Relative Strongest Postconditions

Performing symbolic execution on a program segment from its entry
p_{0}
to any program point
p
yields a set of pairs
(PC_{\pi},\sigma_{p,\pi})
for all reachable paths
\pi
targeting at
p
.
The relative strongest postcondition (RSP) of
\mathcal{F}
at
p
with respect to
Pre
, denoted by
\textit{RSP}(\mathcal{F},\textit{Pre},p)
, is a logical formula describing the disjunction of these (path, state) pairs of
p
reachable from
p_{0}
satisfying
Pre
, defined as blow:

\displaystyle PC_{0}\land\Bigl(\bigvee_{i=1}^{m}\bigl(PC_{\pi_{i}}\land\mathrm{StateForm}(\sigma_{p,\pi_{i}})\bigr)\Bigr)

(1)

where
\mathrm{StateForm}(\sigma_{p,\pi_{i}})
is the logical formula specifying the symbolic state
\sigma_{p,\pi_{i}}
in terms of initial symbolic values recorded by
PC_{0}
.
Specially,
\textit{RSP}(\mathcal{F},\textit{Pre},p_{-1})
for the exit point
p_{-1}
is the final RSP of
\mathcal{F}
with respect to
Pre
at termination.

The ”relative” in RSP reflects its dependence on loop invariant accuracy during symbolic execution. Perfect invariants yield the true strongest postcondition, but in practice, we usually obtain over-approximation of the actual reachable state space of loops.

Definition 1

(Loop invariant generation problem)

Given a loop

P

•

Base:

IV-B

Template Generation

The above
\mathrm{LoopAnalysis}
phase extracts symbolic execution data from loop unfoldings to provide inputs for
\mathrm{LoopInvTemGen}
, which then generates a set of invariant templates. These templates have parameters partially determined by symbolic execution results, while the remaining undetermined parameters are completed using the subsequent LLM synthesis method (as presented in Algorithm
3
).
Below we introduce four forms of invariant templates.

•

Unchanged variables:
For any variable
v\in uV
and any execution path
\pi_{j}
to the loop entry
p
, the invariant component
\mathcal{I}_{v,\pi_{j}}
is:

\mathcal{I}_{v,\pi_{j}}\equiv PC_{\pi_{j}}\Rightarrow v=\sigma_{p,\pi_{j}}(v)

asserting that, if execution follows path
\pi_{j}
,
v
consistently retains its symbolic value
\sigma_{p,\pi_{j}}(v)
at the loop entry.

•

Loop skip conditional property:
For a path
\pi_{j}
to
p
, and a loop condition
B
where
v\in\mathcal{L}_{p}
, if the condition
B
for path
\pi_{j}
is false, the loop is skipped without altering variables. The invariant component
\mathcal{I}_{v,\pi_{j}}
is:

\displaystyle B^{\prime}\leftarrow B\land(PC_{\pi_{j}}\land\mathrm{StateForm}(\sigma_{p,\pi_{j}}))

\displaystyle\mathcal{I}_{v,\pi_{j}}\equiv\neg B^{\prime}\Rightarrow v=\sigma_{p,\pi_{j}}(v)

This ensures
v
retains its initial value. Both the above two types of invariants satisfy the base and preservation conditions.

•

Non-inductive variables:
For a non-inductive variable
v
(typically overwritten in the first iteration) and any path
\pi_{j}
to
p
:

\displaystyle B^{\prime}\leftarrow B\land(PC_{\pi_{j}}\land\mathrm{StateForm}(\sigma_{p,\pi_{j}}))

\displaystyle\mathcal{I}_{v,\pi_{j}}\equiv(B^{\prime}\Rightarrow((v=\sigma_{p,\pi_{j}}(v))\lor\Phi(v,\mathcal{L}_{p}\cup\mathcal{V})))

where
\Phi(v,\mathcal{L}_{p}\cup\mathcal{V})
is the synthesized inductive invariant.

•

Inductive variables:
For an inductive variable
v
(which is neither unchanged nor non-inductive and whose value relates to its previous value after the iteration) and any path
\pi_{j}
to
p
:

\displaystyle B^{\prime}\leftarrow B\land(PC_{\pi_{j}}\land\mathrm{StateForm}(\sigma_{p,\pi_{j}}))

\displaystyle\mathcal{I}_{v,\pi_{j}}\equiv(B^{\prime}\Rightarrow\Phi(v,\mathcal{L}_{p}\cup\mathcal{V}))

This template-driven approach is a cornerstone of our loop invariant geneartion algorithm. By using precise symbolic execution, it simplifies the LLM’s task, shifting from full invariant generation to completing template invariant components. It also provides inherent syntactic guidance, easing the LLM’s adherence to formal logical syntax. This approach guarantees
strong invariants
that capture all relevant variable behaviors across every execution path, thereby closely over-approximating the set of all possible variable assignments within the loop.

IV-C

Loop Invariant Refinement

Loop invariants generated by the LLM may not always be sound or sufficiently strong. To ensure their correctness, we implement a fine-grained, iterative refinement framework. This system leverages verifier errors and the LLM’s self-correction to continuously refine invariants. Verification failures fall into four categories, each prompting a specific action:

•

Syntax error: Verifier reports a parse error and the LLM repairs the syntax error directly.

•

Invariant failure (postcondition passed): Invariants fails Base or Preservation condition, yet surprisingly implies the post-condition (if given). The LLM adjusts the invariant to correct the failed property.

•

Invariants correct (postcondition failed): Invariant satisfies Base and Preservation, but is too weak, failing Termination postcondition (if given). The LLM strengthens the invariant.

•

Fundamental failure: Invariant fails Base, Preservation, and Termination. A complete re-generation by the LLM is triggered.

If errors persist after multiple repair rounds, we apply a final filtering step to iteratively prune any invariant components consistently failing.

V
Summary Generalization

The RSPs generated in the previous stage are crucial for verification of safety-critical systems, however, they can be overly detailed for human understanding. To address this, starting from the RSPs, we propose a summary generalization procedure to generate summaries expressed within given Domain-Specific Languages (DSL). This process distills implementation details while guarantees to derive the strongest postconditions with respect to the DSL.

In our approach, the DSL is constructed by manually providing parameterized clauses, called

VI
Implementation

VI-A

Toolchain Integration of VST-A, Frama-C, and LLM

In our implementation, we combine the strengths of symbolic execution, large language models (LLMs), and formal verification to achieve precise, efficient and sound function summary generation.
We use VST-A
[
5
]
as our foundational symbolic execution engine, which generates precise path conditions and symbolic states for straightline code through Coq-verified strongest postcondition derivation. However, VST-A requires manual annotation for loop invariants and callee function summaries, and its output may include unproven lemmas requiring manual Coq proofs. To address these limitations, we leverage LLMs to automatically synthesize candidate invariants, and meanwhile employ Frama-C
[
6
]
as our formal verifier to ensure soundness and automate verification. The integration of Frama-C with SMT solvers enables automatic verification, while its ACSL (ANSI/ISO C Specification Language) assertion language offers LLM-friendly syntax to facilitate iterative collaboration. Through collaboration, Frama-C refines incorrect invariants learned from LLM through counterexamples and guides LLMs to finally obtain sound invariants.

VI-B

Implementation Details

We detail the realization of some key functions here.
Function
\mathrm{DefaultAnnotation}
establishes the initial precondition of a given function for its symbolic execution to start. While manual setup is possible, our tool automatically provides VST-A a default precondition for each function, which specifies the validity assumptions over atomic memory locations within the initial program point’s scope.

For LLM-based invariant synthesis, Both functions
\mathrm{OuterLoopLLMCall}
and
\mathrm{NestedLoopLLMCall}
synthesize loop invariants by integrating LLMs with a zero-shot, Chain-of-Thought (CoT) prompting approach. CoT improves LLM understanding via contextual questions before invariant generation.

A key feature of our toolchain is the interoperability between VST-A and Frama-C, despite their different assertion languages. During the
\mathrm{LoopInvGen}
phase, LLM-generated loop invariants in ACSL are translated into VST user assertion format. This enables VST-A to correctly interpret and leverage them for symbolic execution across loop and function boundaries. After symbolic execution, VST-A’s generated RSPs are converted from its assertion format to ACSL for subsequent Frama-C automated verification. To achieve these, we establish an automatic translation that enables the conversion of assertions in both directions (see Appendix
-B
).

IX
Conclusion

In this paper, we have presented a novel, end-to-end framework for automatically synthesizing multi-granularity function summaries for C programs by tightly integrating path-sensitive symbolic execution, large language models, and formal verification. Our approach generates formally-verified relatively strongest postconditions (RSPs), infers precise loop invariants via template-guided LLM synthesis and iterative refinement, and automatically abstracts these RSPs into domain-specific summaries. Experimental results on standard benchmarks and real-world aerospace code show that our tool outperforms existing methods in both precision and efficiency, achieving strong results on invariant generation, particularly on SyGuS numeric single-program benchmarks, and summarizing complex legacy functions.

For future work, we will extend our approach to handle recursive functions and recursive data structures, and devlelop richer domain-specific languages that incorporate user-defined abstract predicates. We also plan to improve our invariant generation methods to deal with these complex cases through LLM fine-tuning and specialized training procedures.
