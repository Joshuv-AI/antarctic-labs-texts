Filtered Approximate Nearest Neighbor Search Cost Estimation
Wenxuan Xia, Mingyu Yang, Wentao Li, Wei Wang

Abstract
. Hybrid queries combining high-dimensional vector similarity with structured attribute filtering have garnered significant attention across both academia and industry. A critical instance of this paradigm is filtered Approximate k k Nearest Neighbor (AKNN) search, where embeddings (e.g., image or text) are queried alongside constraints such as labels or numerical range. While essential for rich retrieval, optimizing these queries remains challenging due to the highly variable search cost induced by combined filters. In this paper, we propose a novel cost estimation framework 𝖤𝟤𝖤 {\mathsf{E2E}} for filtered AKNN search and demonstrate its utility in downstream optimization tasks, specifically early termination. Unlike existing approaches, our model explicitly captures the correlation between the query vector distribution and attribute-value selectivity, yielding significantly higher estimation accuracy. By leveraging these estimates to refine search termination conditions, we achieve substantial performance gains. Experimental results on real-world datasets demonstrate that our approach improves retrieval efficiency by 2 × \times –3 × \times over state-of-the-art baselines while maintaining high search accuracy.

Each node is connected to its proximity neighbor, forming a graph with navigational properties. During the search, starting from the entry point of the graph, each step moves to the node closer to the query. To adapt these indexes for filtered search, existing strategies typically employ either a

k

Both

As a result, the difficulty of filtered AKNN queries becomes highly skewed: some queries are highly selective and trigger the exploration of many candidates, while others are comparatively simple. To guarantee high recall across such unstable workloads, existing systems typically rely on conservative, worst-case, static configurations

Based on these predictions, they adaptively terminate the search, mitigating the computational overhead and latency variability inherent in fixed, globally configured search parameters.

Motivation
. Existing cost estimate methods that directly adapt to filtered AKNN search have several limitations. Relying solely on features such as distance and distribution within the queue makes it difficult to capture the correlation between the filter and the query, and this is also a key factor affecting the performance of filtered search. As illustrated in Fig.
2
, the image embedding of a
luxury watch
strongly correlates with a high price range. When a user queries for such an item with a contradictory filter (e.g., finding a luxury watch for under $20), the valid candidate set becomes extremely sparse despite a high density of query vector neighbors. State-of-the-art estimators that treat vector similarity and attribute selectivity as independent variables fail to predict the high computational cost required to traverse this sparse intersection, necessitating a correlation-aware approach for accurate query planning.

We propose a novel cost estimation framework,

2.
Preliminary

In this section, we first define the specific filtered AKNN search problem and introduce the basic AKNN index and existing solution for AKNN search cost estimate.

2.1.
Problem Statement

We first define the filtered approximate
k
nearest neighbor search problem, which unifies various filtering scenarios. In this paper, we focus on specific range and label-filtered search, since they are widely used in practice.

Definition 2.1 (Attributed Vector Dataset).

A data item in an attributed vector dataset
S
is defined as
o_{i}=(x_{i},A_{i})
, where
x_{i}\in\mathbb{R}^{d}
is a high-dimensional vector and
A_{i}
denotes its filter attribute. We consider two primary types of attributes:

•

Discrete Label Set:
A_{i}\subseteq\mathcal{L}
, where
\mathcal{L}
is the global alphabet of labels.

•

Numeric Attribute:
A_{i}\in\mathbb{R}
, a continuous scalar value.

For simplicity, we assume all data items in a dataset
S
share the same attribute type.

Definition 2.2 (Filtered Query).

A filtered query is denoted as
q=(x_{q},f_{q})
, where
x_{q}
is the query vector and
f_{q}
represents the
filtering constraint
. Similar to the definition of data items in
S
.
f_{q}
can be a set of labels
f_{q}=L_{q}
or a numeric range
f_{q}=[l,r]
.

To determine whether a data item satisfies a query, we formally define the concept of a
Filter Predicate
.

Definition 2.3 (Filter Predicate).

Let
\mathcal{P}(A_{i},f_{q})\to\{\text{True},\text{False}\}
be a boolean predicate function that evaluates the validity of object
o_{i}
against query constraint
f_{q}
. We support the following predicate types:

•

Label Containment: Requires the item label set contain the query label set.

\mathcal{P}_{\text{contain}}(A_{i},f_{q})\iff L_{q}\subseteq A_{i}

•

Label Equality: Requires an exact match between label sets.

\mathcal{P}_{\text{equal}}(A_{i},f_{q})\iff L_{q}=A_{i}

•

Numerical Range: Requires the object’s attribute to fall within the closed interval.

\mathcal{P}_{\text{range}}(A_{i},f_{q})\iff A_{i}\in[l,r]

Definition 2.4 (Filtered Subset).

Given a dataset
S
, a query
q
, and a specific predicate logic
\mathcal{P}
, the filtered subset
S(q)
is defined as:

S(q)=\{o_{i}\in S\mid\mathcal{P}(A_{i},f_{q})=\text{True}\}

Definition 2.5 (Filtered
k
Nearest Neighbor Search).

Given a dataset
S
and a query
q
, the problem is to return a result set
S^{\prime}\subseteq S(q)
with
|S^{\prime}|=k
, such that for any
o_{i}\in S^{\prime}
and
o_{j}\in S(q)\setminus S^{\prime}
,
\delta(x_{i},x_{q})\leq\delta(x_{j},x_{q})
, where
\delta
denotes the distance function.

To characterize the distribution of valid data items, we define the concept of
selectivity
over a specific data scope.

Definition 2.6 (Selectivity).

Given a query
q=(x_{q},f_{q})
and a target subset of data items
S^{\prime}\subseteq S
, the selectivity
\sigma(S^{\prime},f_{q})
measures the proportion of items in
S^{\prime}
that satisfy the filter condition:

\sigma(S^{\prime},f_{q})=\frac{|S^{\prime}(f_{q})|}{|S^{\prime}|}

Based on the scope of
S^{\prime}
, we distinguish between two critical metrics:

•

Global Selectivity (
\sigma_{global}
): When
S^{\prime}=S
(the entire dataset),
\sigma(S,f_{q})
represents the overall probability that a random object satisfies the filter. This is often available from database statistics.

•

Local Correlation (
\rho_{local}
): When
S^{\prime}
corresponds to a proximity neighborhood of
x_{q}
(e.g., the top-
m
nearest neighbors based on vector distance),
\rho_{local}=\sigma(S^{\prime},f_{q})
represents the
local query-filter correlation
.

Remark.
For simplicity, the definition only considered two common filters: label and range filter. In practice, any type of filter, such as combinations of multiple attributes, can be supported, as our method only depends on the output of the predicate
\mathcal{P}
and is not affected by the input attributes.

2.2.
The AKNN Search Index

Exact
k
Nearest Neighbor search often suffers from the
curse of dimensionality
, making traditional methods
(
5
;
3
)
that perform well in low-dimensional spaces degrade greatly in high-dimensional settings. As a result, much of the recent work focuses on approximate
k
Nearest Neighbor (AKNN) search, which achieves higher efficiency at the mere cost of accuracy. This challenge also arises in the filtered KNN search. Therefore, we focus on the filtered approximate
k
nearest neighbor search (filtered AKNN) problem.
To address the filtered AKNN search problem, existing approaches typically adapt filter processing strategies on top of different types of AKNN indexes. Among these AKNN methods, graph-based indexes
(
34
;
14
;
23
;
38
;
45
)
are widely adopted due to their superior search efficiency, which is the main focus of this paper.

Graph Indexes
. In a graph index, base vectors in the dataset
S
are defined as nodes in a graph, where each node is connected to its proximity neighboring nodes via index construction algorithms
(
13
;
31
;
34
;
38
;
27
;
37
)
. Most graph-based indexes adopt a greedy search algorithm for searching the top-
1
nearest neighbor
(
14
;
23
;
34
;
22
;
51
)
. It starts from a designated entry node and iteratively explores neighbors that are closer to the query until the top-
1
result is found. For AKNN search, beam search is used to acquire more than one result. It maintains a queue containing the top-
m
closest candidates during traversal, where
m
is the beam width.

Filtered Search
. On top of the graph index, there are two basic filter-based search strategies to support filtered AKNN search
(
37
;
48
;
24
;
6
;
24
;
55
;
42
)
:
{\mathsf{PreFiltering}}
and
{\mathsf{PostFiltering}}
. Both strategies keep the index structure unchanged and apply attribute-based filtering during search. (1)
{\mathsf{PreFiltering}}
: given a query
q=(x_{q},f_{q})
,
{\mathsf{PreFiltering}}
does not expand the filter unmatched nodes and their neighbors. (2)
{\mathsf{PostFiltering}}
disregards the filters during the traversal but excludes the unmatched nodes from the result set. For top-
k
queries,
{\mathsf{PostFiltering}}
accumulates successive nearest neighbors until
k
matching results are found. Since the
{\mathsf{PreFiltering}}
strategy can cause graph disconnection and may return insufficient results, existing systems mainly use the
{\mathsf{PostFiltering}}
strategy
(
33
;
23
)
, at a cost of computed distances of a large number of filtered-out points.

2.3.
The Cost Estimation of AKNN Search

Existing AKNN search cost can be simply obtained by the search parameter(budget) of vector index (i.e., efsearch of HNSW, nprobes of IVF). In the context of filtered search, the naive method sets a relatively large search budget for the filtered AKNN query to guarantee both accuracy and sufficient results. Systems like VBase
(
56
)
, Chase
(
32
)
, VSAG
(
59
)
, and AnalyticDB
(
43
)
use static features such as selectivity to estimate the search cost of different vector indexes for better query optimization. Light learning-based method LAET
(
28
)
and DARTH
(
7
)
adopt vector index runtime features to estimate the cost at target search accuracy. The estimate of LAET and DARTH also serves as a search budget allocator, achieving early termination of search. Thus, improve search efficiency. Despite the success of the above methods, the correlation between the query filter and vector still lacks explicit modeling. We propose a simple yet effective method with existing indexes for both accurate cost estimation and search early termination in the following sections.

3.
Problem Analysis

In this section, we begin by modeling the search cost of the graph index, followed by the challenge and motivation of the filtered AKNN search cost estimation.

3.1.
Filtered Index Search Cost

We begin with the search complexity of a graph-based index (e.g., HNSW) employing a post-filtering strategy. Let a query be denoted as
q=(x_{q},f_{q})
, where
x_{q}
represents the query vector and
f_{q}
represents the associated filtering constraint. The search process for AKNN on existing graph-based indexes typically proceeds in two distinct phases.

Greedy Routing.
The initial phase aims to locate the approximate nearest neighbor of
x_{q}
within the global graph structure, disregarding the filter
f_{q}
. The search employs a greedy strategy, iteratively moving to the neighbor that most reduces the distance to the query. The complexity of this greedy routing phase is generally logarithmic with respect to the dataset size,
O(\log N)
, where
N
is the total cardinality of the dataset. Advanced structures like HNSW
(
34
)
and HVS
(
31
)
further optimize this phase by introducing hierarchical layers or sparse navigational graphs, effectively reducing the computational overhead of this initial descent to a negligible fraction of the total cost.

Local Expansion.
Upon identifying the approximate top-1 result, the algorithm transitions to a local exploration phase using a beam search strategy. The index iteratively expands the search frontier by exploring the neighbors of visited nodes, maintaining a candidate pool of size
m
(the beam width). For a standard top-
k
search without filtering, the overall complexity is traditionally derived as
O(\log N+m\cdot\bar{d})
, where
\bar{d}
represents the average node degree. Since the maximum degree of nodes in the graph index is typically bounded by a constant (e.g.,
M_{max}
in
{\mathsf{HNSW}}
), the cost of a single node expansion is effectively constant
O(1)
. Consequently, the complexity is dominated by the number of expansions required to fill the beam, often simplified to
O(\log N+m)

(
37
;
51
)
.

filtered search Complexity.
The
{\mathsf{PostFiltering}}
strategy adheres to the established two-stage search mechanism of graph indexes. The distinction lies in the second phase: upon locating the top-1 neighbor of
q
(regardless of being filtered out with respect to
f_{q}
), the algorithm performs an incremental neighbor expansion to accumulate
m
candidates that explicitly satisfy the filter constraint. A critical inefficiency of
{\mathsf{PostFiltering}}
is that it incurs distance computation costs for filtered-out candidates encountered during traversal—nodes that are evaluated but subsequently discarded due to the filter. Consequently, the computational overhead of this second stage is often substantial. Under the assumption that the data distribution and filtering predicates are independent, the expected cost to retrieve
m
valid neighbors is derived as
O(m/\sigma_{global})

(
37
;
51
)
. Here,
\sigma_{global}
represents the global selectivity; specifically, this bound assumes that the probability of the top candidates generated during neighbor expansion satisfying the filter is at least
\sigma_{global}
. Therefore, the overall complexity of
{\mathsf{PostFiltering}}
is

(1)

O(\log N+m/\sigma_{global})

.

) versus global selectivity (
\sigma_{global}
) in log-scale. The chaotic distribution in Tripclick-label (left) and the high variance in Arxiv-range (right) highlight the inability of static estimators to capture runtime search difficulty.

3.2.
Challenge and Motivation

With the analysis above, the search cost can theoretically be derived using an accurate estimate of global selectivity,
\sigma_{global}
, under the assumption that the data distribution and attribute filters are independent. However, real-world attributed vector data frequently exhibit significant positive or negative correlations between vector proximity and attribute filters. As illustrated in Fig.
3
, there is a substantial misalignment between local and global selectivity across real-world datasets. Consequently, the neighbor expansion cost in the
{\mathsf{PostFiltering}}
stage depends not on
\sigma_{global}
, but on
\rho_{local}
—the local correlation—defined as the ratio of valid candidates among the top-
m
nearest neighbors for a specific query.

Challenge.
While selectivity estimation
(
16
;
10
)
has been studied for decades, directly adapting traditional techniques to filtered AKNN search presents fundamental challenges:

Prohibitive Latency.
Filtered AKNN necessitates sub-millisecond response times. State-of-the-art learned estimators, which often rely on complex deep learning architectures, incur inference overheads that paradoxically exceed the execution time of the search itself, rendering them impractical for real-time applications.

Local Correlation.
Traditional methods focus on estimating global attribute density. They fail to capture
local correlation
—the conditional probability of attribute satisfaction within a specific proximity neighborhood of the query. Accurately modeling this local density is further complicated by the
curse of dimensionality
.

Motivation.

To address these challenges, we efficiently repurpose the graph index to estimate local correlations for cost estimation. Adhering to the established two-stage search framework, we introduce a key innovation: collecting features via low-cost early probes immediately following the first search stage. Subsequently, a lightweight GBDT model predicts the cost of the next stage to enable early termination. Since the first stage is indispensable and incurs minimal overhead on a graph index, our method achieves lightweight and extremely fast cost estimation for filtered AKNN search depend only on the graph index traverse features without being coupled by the data item attributes.

4.
The
{\mathsf{E2E}}
Framework

In this section, we begin with an overview of the
{\mathsf{E2E}}
framework. Next, we introduce the input features and model training strategy. Last, we integrate the prediction model for filtered search early termination.

4.1.
Framework Overview

To bridge the gap between our cost model and practical query execution, we introduce the
{\mathsf{E2E}}
framework, as illustrated in Fig.
4
. The workflow is decomposed into three stages.

Early Probe.
The search starts from the entry node, exploring neighboring nodes within a restricted probe radius (indicated by the blue dashed circle) to capture the local valid density
\rho_{local}
and distance-based features used in previous research
(
28
;
7
)
. We emphasize that this stage is seamlessly integrated into the query execution pipeline of graph index, incurring negligible overhead. Our early probe is simply the first
f
steps of the actual query execution. If the estimator predicts that the query is already satisfied, the results collected during this phase are directly returned or used.

Cost Estimation.
The framework aggregates these filter-aware runtime features, such as local correlation and queue distance distributions, and feeds them into a GBDT-based Cost Estimator (LightGBM) to predict the total search budget
W_{q}
.

Adaptive Termination.
As the second search stage, our algorithm dynamically monitors the accumulated distance computations. The
{\mathsf{E2E}}
framework utilizes the predicted budget
\hat{W}_{q}
as an adaptive search boundary, effectively pruning unnecessary node expansions (the avoided cost in Fig.
4
) while maintaining high search quality.

Remark.
We quantify the total computational cost, denoted as
W_{q}
, by the Number of Distance Computation (NDC) performed during the filtered search for
q
. We utilize NDCs as our primary metric because it provides a hardware-agnostic measure of algorithmic efficiency, linearly mapping to search latency while abstracting away variations in machine architecture and implementation details.

4.2.
Input Features

To effectively drive our learned cost estimator, we categorize the runtime features into three groups. While we adopt established feature definitions (e.g., relative distance ratios) from prior art such as LAET
(
28
)
and DARTH
(
7
)
, we fundamentally redefine their computation scope to address the unique challenges of filtered search in the appendix. Specifically, accurately predicting the cost in this setting requires capturing the
Feature-Filter Misalignment
—the discrepancy between vector proximity and attribute validity. To achieve this, we explicitly distinguish between the statistics of the
filtered
result set (representing valid progress) and the
distance
search queue (representing the cost of future exploration). The notations are summarized in Table
1
and the appendix.

Filter Features.

To quantify the
Feature-Filter Misalignment
, we introduce two runtime metrics derived from the early probe phase. Unlike global selectivity
\sigma_{global}
or static entry-point statistics, which often fail to reflect the local neighborhood of a specific query, we rely exclusively on dynamic trajectory statistics collected during the early probe phase.

•

\rho_{pilot}
: This metric quantifies the validity ratio within the search range of the early probe stage:

(2)

\rho_{pilot}=\frac{N_{valid\_visited}}{N_{total\_visited}}

where
N_{valid\_visited}
is the number of valid nodes popped from the candidate queue during the early probe stage, and
N_{total\_visited}
denotes the number of all nodes visited in this stage.
\rho_{pilot}
serves as a direct sampler of the local correlation
\rho_{local}
around the query. Unlike global selectivity, it captures whether the query vector is located in a region locally dense with valid nodes or in a sparse region where valid matches are scarce.

•

\rho_{queue}
: This metric measures the validity ratio within the current search:

(3)

\rho_{queue}=\frac{N_{valid\_in\_queue}}{N_{queue}}

where
N_{valid\_in\_queue}
is the number of valid nodes in the priority candidate queue, and
N_{queue}
is the queue size. While
\rho_{pilot}
reflects search history,
\rho_{queue}
predicts the search difficulty of immediate future expansions. A low
\rho_{queue}
implies that although the candidates in the queue are close to
x_{q}
, they are mostly invalid (high misalignment), which signals the model that a larger search budget is required to traverse these invalid candidates and expand the search scope sufficiently to retrieve the target
k
valid neighbors.

Model.
For our cost estimator model, we choose a Gradient Boosting Decision Tree (GBDT)
(
25
)
. GBDT trains decision trees sequentially. In each iteration, a new tree is added to train on the errors of the combined results of previous trees. We specifically implement our estimator using LightGBM
(
25
)
, a highly optimized GBDT framework. LightGBM was selected over alternatives like XGBoost
(
8
)
due to its superior inference speed for single-output predictions. (0.025 ms on average for our model estimator on a single-thread query). This low-latency characteristic is critical for our adaptive framework, ensuring that the overhead of frequently evaluating the termination condition remains negligible relative to the overall query execution time.

4.3.
Training

Training Strategy.

We adopt a supervised learning paradigm to train the cost estimator. To construct the training dataset, we execute query logs on a hold-out training set. For each query
q

z_{q}
(as detailed in Table
1
) with a sufficiently large search queue.
Subsequently, we continue the search until the
ground truth
top-
k
neighbors are fully retrieved (i.e., reaching 100% recall). We record the total number of distance computations consumed at this convergence point as the regression target, denoted as
W_{q}
. This process generates a labeled dataset
\mathcal{D}=\{(features,W_{q})\}_{q\in S_{train}}
, mapping the intermediate search state (features) to the ultimate search cost required for target recall. Distinct from step-wise predictors (e.g., DARTH
(
7
)
) that harvest multiple samples from a single trajectory, our end-to-end model derives a single scalar signal per query, necessitating a larger query pool (up to
10^{6}
in our experiments) to match the training data volume of prior art. However, we observe that the model converges with much fewer samples (e.g.,
50k
) in practice. Crucially, this ground truth generation is a one-time offline process that is highly parallelizable, ensuring practical feasibility even for massive datasets.

Log Optimization.

Directly regressing the raw cost
W_{q}
is difficult due to the
heavy-tailed
nature of the search cost distribution in filtered AKNN. The required distance computations can span orders of magnitude (e.g., from
10^{2}
to
10^{6}
) depending on the filter selectivity. Training on such skewed targets causes the loss function to be dominated by hard queries with large
W_{q}
, leading to poor generalization on easy queries.
To mitigate this, we also employ a logarithmic transformation on the target variable
(
28
)
. The model
\mathcal{M}
is trained to predict
\log(W_{q})
by minimizing the Mean Squared Error (MSE) in the log-space:

(4)

\mathcal{L}=\sum_{q\in S_{train}}||\mathcal{M}(z_{q})-\log(W_{q})||^{2}

Crucially, minimizing MSE in the log-space is mathematically equivalent to minimizing the
Mean Squared Logarithmic Error (MSLE)
in the original space. Since
\log(y)-\log(\hat{y})=\log(y/\hat{y})
, this loss function penalizes the ratio between the predicted and actual cost, thereby implicitly optimizing for the relative error rather than the absolute error. This ensures that the model remains sensitive to deviations for both short and long queries, providing robust predictions across the entire query difficulty spectrum.

Algorithm

1

Upon initialization (Line 1-4), we initiate the early probe phase. In this stage, we execute a beam search where each visited node is evaluated against the query filter
f_{q}
(Line 5-12). This phase operates under a fixed and low budget (i.e., a pre-defined NDCs). Once this budget is exhausted, we pause the traversal to extract runtime features (Line 13), which capture both the observed query correlation of
f_{q}
within the local neighborhood and the search progression.
These features are input into our prediction model (Line 14), which estimates the total search budget required to reach groundtruth. The algorithm then transitions to the adaptive termination phase (Line 15-22), resuming the
{\mathsf{PostFiltering}}

\mathcal{V}
and result queue
\mathcal{R}

f_{q}

Learned Approach for AKNN search.
Learning-based approaches have demonstrated significant success in AKNN search, spanning applications such as vector quantization

7.
Conclusion

In this paper, we addressed the critical challenge of cost estimation and early termination for filtered approximate nearest neighbor search, where the misalignment between vector proximity and query filters often degrades cost estimation. To overcome this, we proposed
{\mathsf{E2E}}
, a novel framework that leverages a low-cost early probing phase to extract runtime features and accurately predict the necessary search budget. By integrating these filter-aware signals into a learned cost model, our approach enables dynamic, per-query early termination that adapts to varying workload difficulties. Future work will explore cost estimation under different hardware environments.

A.3 Adaptation to State-of-the-Art Indices

Our proposed method,
{\mathsf{E2E}}
, is designed to be index-agnostic. While our primary evaluation focuses on standard indices with
{\mathsf{PostFiltering}}
(e.g., HNSW),
{\mathsf{E2E}}
can be generalized to other state-of-the-art filter-aware indices, such as ACORN
(
37
)
. However, applying
{\mathsf{E2E}}
to these indices requires adaptation to their unique traversal mechanisms. We use ACORN as a representative example to illustrate this adaptation.

Features with
{\mathsf{PreFiltering}}
.

ACORN employs a
{\mathsf{PreFiltering}}
strategy. It navigates the predicate subgraph and ensures connectivity by expanding the 2-hop neighbor list (via the parameter
\gamma
) at runtime. A key characteristic of this
{\mathsf{PreFiltering}}
traversal is that the candidate queue
\mathcal{Q}
contains
only
valid nodes satisfying the filter. Consequently, the observed queue validity ratio
\rho_{queue}
remains consistently at 1. Directly adapt previous feature (as used in
{\mathsf{PostFiltering}}
) would incorrectly predict a low search cost for all queries.

Feature adaptation.

To address this, we find that in
{\mathsf{PreFiltering}}
traversal indices like ACORN, the search cost shifts from
queue expansion
to
neighbor inspection
. The
hard
query in ACORN does not necessarily exhibit a sparse queue, but rather a high rejection rate during the neighbor expansion process.

Therefore, when integrating with ACORN, our feature extraction (
z_{q}
in Algorithm
1
) emphasizes the
Visited Correlation
rather than just Queue Correlation. We introduce the
Visited Filter Ratio

\rho_{visited}
:

(5)

\rho_{visited}=\frac{N_{valid\_visited}}{N_{total\_visited}}

where
N_{total\_visited}
includes all 1-hop and 2-hop neighbors inspected during the expansion. A low
\rho_{visited}
indicates that the index is performing extensive underlying graph traversals to maintain a valid queue, signaling a high remaining search budget. As demonstrated in our evaluation,
{\mathsf{E2E}}
effectively captures this implicit cost, enabling accurate early termination even when the explicit queue validity is high.
