Abstract
. Multi-agent social interaction has clearly benefited from Large Language Models. However, current simulation systems still face challenges such as difficulties in scaling to diverse scenarios and poor reusability due to a lack of modular design. To address these issues, we designed and developed a modular, object-oriented framework that organically integrates various base classes through a hierarchical structure, harvesting scalability and reusability. We inherited the framework to realize common derived classes. Additionally, a memory summarization mechanism is proposed to filter and distill relevant information from raw memory data, prioritizing contextually salient events and interactions. By selecting and combining some necessary derived classes, we customized a specific simulated environment. Utilizing this simulated environment, we successfully simulated human interactions on social media, replicating real-world online social behaviors. The source code for the project will be released and evolve.

Despite these new advances in virtual worlds and social simulations, challenges remain.
Current frameworks suffer from low scalability and reusability and a lack of components similar to those of human society.
In addition, memory systems are burdened with redundant information, leading to a low utilization efficiency in leveraging stored content.

The hierarchical structure of base classes.

To this end, we propose an innovative solution.
As illustrated in Figure
1
, we design a modular, object-oriented framework where the components are organically integrated through a hierarchical structure.
Each component is a generic base class corresponding to the various components of human society, and specific simulated environments are created by inheriting these base classes.
We realize common derived classes which others can simply reuse.
Moreover, we propose a memory summarization mechanism that filters and distills relevant information from raw memory data, reducing redundancy.

We selected some off-the-shelf derived classes to customize a specific simulated environment.
The simulation scenario was designed to represent online activities in the real world, where agents engage in discussions on social issues and interact within the virtual community.
We conducted a series of experiments to validate the effectiveness of our customized environment.

In summary, the main contributions of this paper are as follows:

Modular, Object-Oriented System Design.

The framework has a modular and object-oriented design, where each component serves as a general base class.
By inheriting these base classes, the framework can be adapted to different simulated environments, offering a high degree of scalability and reusability.

Memory Summarization Mechanism.

This mechanism reduces information overload, prioritizes contextually salient events and interactions, and enables agents to exhibit more adaptive and cognitively plausible behaviors by focusing on meaningful historical data.

3.
Method

3.1.
Basic Framework Explanation

Figure 2.
The hierarchical structure of the proposed framework.

To enhance scalability and reusability, we introduced a novel architecture with a modular, object-oriented design.
As shown in Figure
2
, this architecture is composed of various core components and each component is defined as a generic base class, and specific derived classes are created by inheriting these base classes to meet distinct requirements, as detailed below.

Social Simulation.
It is responsible for managing the components and controlling the entire simulation process.

World.
The module can be customized to various worlds depending on specific needs, for example offline physical world and online virtual world.

Tool.
Through inheritance, this module enables the creation of various tools, such as search engines.
It is designed with the Singleton Pattern
(
Gamma et al. 1994
)
to ensure efficient use and management, avoiding resource waste and complexity from multiple tools while maintaining consistent tool behavior.

Persona.
The persona is the agent which is autonomous and capable of mimicking human behavior, interacting with other agents and the environment.

Stuff.
This refers to all available resources in the world, including both abstract entities, such as events and policies, and concrete entities, for example non-player characters (NPCs).

Organization.
We introduced this module to simulate organization, for example companies, government bodies, and civic groups, providing realistic social dynamics to enhance the realism.

Memory.
The memory module stores an agent’s initial state, environmental perceptions, and internal reflections, guiding its functions.
Different memory modules can be created as needed to store various types of information, such as short-term memory, long-term memory, and spatial memory.

Workflow.
This module guides agents through a structured sequence of behaviors to accomplish tasks efficiently and coherently.
Using the Strategy Pattern
(
Gamma et al. 1994
)
, different behaviors can be combined to form different workflows.

Behavior.
Each one represents a specific human behavior, such as perception and decision-making, simulating the specific operations a person would perform when completing tasks.

Furthermore, Workflow and Memory adopt the Visitor Pattern
(
Gamma et al. 1994
)
, allowing the workflow module to flexibly access, operate, or combine multiple types of memory without altering their data structure.

3.2.
Memory Summarization Mechanism

In the process of agents calling memory for decision-making or dialogue, the large language model first generates multiple retrieval keywords and performs query operations in the memory in sequence. For each keyword, we select the top-k most relevant results as the final retrieval results
R
.

On this basis, to improve agents’ understanding of memory content and enable them to generate decisions and dialogues more suitable for the scenario, we propose a summarization mechanism for further generalization and in-depth analysis of the final retrieval results
R
. Specifically, this mechanism first calls the large language model to determine
P
key information points according to current task requirements, and then allows the large language model to extract corresponding relevant information
C_{i}
from the final retrieval results
R
for each key information point. Finally, the refined information
[C_{1},C_{2},...,C_{P}]
is provided to agents to assist their decision-making and dialogue generation. The prompt template for summarization is shown in Figure
3
.

For controlled evaluation, experiments are conducted on the RoleAgentBench
(
Liu et al. 2024
)
dataset. RoleAgentBench is a systematic and comprehensive evaluation benchmark designed to assess the generation ability and interaction performance of agents. The dataset covers 20 original English scripts and 5 original Chinese scripts, containing a total of 128 characters (100 English characters and 28 Chinese characters), spanning various scenarios such as movies and TV dramas. The evaluation system of RoleAgentBench consists of two parts: agent simulation and memory system. The agent simulation part includes three core evaluation tasks: Self-Knowledge, Reaction, and General Response. Among them, Self-Knowledge and Reaction are evaluated using Accuracy (ACC), and General Response is evaluated using Win Rate (WR). The memory system part mainly uses WR as an indicator to measure the quality of the memory system. All evaluation questions are based on the original scripts, generated by GPT-4 and manually calibrated to ensure their high consistency with the character settings, thereby providing a multi-dimensional and multi-lingual standardized testing benchmark for agents. The evaluation metrics for this test mainly include two categories: ACC and WR. The calculation of ACC is shown in Equation
1
.

(1)

\displaystyle ACC=\frac{\sum_{i}^{N}I(y_{i}==\hat{y_{i}})}{N_{all}}

where
N
is the total number of samples in the test set,
y_{i}
is the predicted result of the
i
-th test sample,
\hat{y_{i}}
is the true label of the
i
-th test sample, and
I(\cdot)
is an indicator function, which takes a value of 1 when
y_{i}=\hat{y_{i}}
, and 0 otherwise. For WR, its calculation is shown in Equation
2
.

(2)

\displaystyle WR=\frac{\sum_{i}^{N}I(Rank(y_{i})==1)}{N_{all}}

where
N
is the total number of samples in the test set,
Rank(\cdot)
is a ranking function used to rank the model’s predicted answers against the reference answers, and
I(\cdot)
is an indicator function, which takes a value of 1 if the rank is first, and 0 otherwise. The ranking process employs prompt engineering to enable GPT-4 for ranking, and its prompt template is shown in Figure
4
.

4.2.
End-to-end Evaluation

For end-to-end evaluation, we design multiple experiments covering various scenarios, from basic single-event discussions to interwoven multi-event discussions, committee policy releases, and applications of search engine results. Each experiment involves three agents, and their behaviors are observed through three rounds of discussions. The basic details of the agents are presented in Table
3
. Their personalized characteristics and backgrounds ensure the richness and diversity of the discussions, thereby more truthfully reflecting the collision of diverse perspectives caused by individual differences in social contexts. By simulating a series of real internet communications, we obtain relevant discussion contexts that conform to the characteristics of actual online interactions, verifying the effectiveness of the proposed framework.

Appendix A
Off-the-shelf Derived Classes

As illustrated in Figure
6
, we have realized common derived classes by inheriting the base classes on leaf nodes.
The details of these derived classes are as follows.

Memory.
We implemented
SpatialMemory
,
Scratch
, and
AssociativeMemory
to store different types of memory information.
Spatial Memory records and manages the agent’s memory of the environment, supporting navigation and path planning in complex environments, helping the agent move and make decisions effectively.
Scratch, similar to short-term memory, supports short-term plan management, decision-making, and task progress tracking, ensuring that the agent quickly responds to environmental changes and adjusts actions.
Associative Memory stores the persona’s reflections, building long-term memory to help the agent reason and make decisions effectively.

Behavior.
We implemented several types of behaviors:
Perceive
,
Retrieve
,
Reflect
,
Plan
, and
Execute
, which can be combined to form different workflows.
Each agent has its own independent workflow that drives its behavior in both physical and social environments.

Organization.
We implemented the
Committee
class using a prompting technique called Solo Performance Prompting (SPP)
(
Wang et al. 2024a
)
.
Upon receiving a case, the committee identifies relevant roles and facilitates discussions among them to develop policy measures.

Stuff.
We implemented the
PhysicalEnvironment
class to describe the physical environment, including facilities and physical objects.
In the environment, agents use coordinates to navigate and gather information about their surroundings.
We also implemented abstract entities, namely
Event
and
Policy
.

Tool.
To enhance the capabilities of agents, we implemented the
SearchEngine
class that provides agents with internet access.
This greatly enhances our social simulations by providing more realistic and dynamic interactions.
Agents can retrieve real-time information from the web, for example related events, demographic data, and economic indicators.
They can also expand their knowledge base by incorporating insights from academic papers, technical documentation, and other educational materials.
