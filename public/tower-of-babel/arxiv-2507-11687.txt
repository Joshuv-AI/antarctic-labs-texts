MetaLint : Generalizable Idiomatic Code Quality Analysis Through Instruction-Following and Easy-to-Hard Generalization
Atharva Naik, Lawanya Baghel, Dhakshin Govindarajan, Darsh Agrawal, Daniel Fried, Carolyn Rose

Abstract
Large Language Models, though successful in code generation, struggle with code quality analysis because they are limited by static training data and can’t easily adapt to evolving best practices. We introduce MetaLint , a new instruction-following framework that formulates code quality analysis as the task of detecting and fixing problematic semantic code fragments or code idioms based on high-level specifications. Unlike conventional approaches that train models on static, rule-based data, MetaLint employs instruction tuning on synthetic linter-generated data to support easy-to-hard generalization, enabling models to adapt to novel or complex code patterns without retraining. To evaluate this, we construct a benchmark of challenging idioms inspired by real-world coding standards such as Python Enhancement Proposals (PEPs) and assess whether MetaLint -trained models reason adaptively or simply memorize. Our results show that MetaLint improves generalization to unseen PEP idioms, achieving a 70.37% F-score on idiom detection with the highest recall (70.43%) among all evaluated models. It also achieves 26.73% on localization, competitive for its 4B parameter size and comparable to larger state-of-the-art models like o3-mini, highlighting its potential for future-proof code quality analysis.



1
Introduction

With the rise of Large Language Model (LLM) agents, concerns around the quality of generated code, such as readability, maintainability, efficiency, and security, have become increasingly prominent.
Researchers have been investigating the potential of LLMs to evaluate and improve code quality through benchmarks
(
Chambon et al. 2025
;
Zheng et al. 2024
;
Waghjale et al. 2024
)
, code review agents
(
Vijayvergiya et al. 2024
;
Rasheed et al. 2024
)
, and static analysis with LLMs
(
Fang et al. 2025
;
Holden & Kahani 2024
;
Khare et al. 2023
)
.
However, many of these efforts are hindered by reliance on task-specific training data, often based on narrow or outdated coding best practices
(
Vijayvergiya et al. 2024
;
Khare et al. 2023
;
Holden & Kahani 2024
)
.
As a result, these systems often perform poorly when detecting rare issue types or when applied to code distributions that differ from their training data
(
Holden & Kahani 2024
)
. They may also over-flag outdated best practices, leading to a negative user experience and wasted time
(
Vijayvergiya et al. 2024
)
.
Ideally, we would develop LLM systems capable of identifying code quality issues without explicit supervision for the target idioms, especially for hard or rare patterns, and that can adapt to evolving best practices over time.

One approach to this problem is to train the LLM on a more general task: understanding and detecting semantic blocks of code, also known as
code idioms
.
For example, a commonly used idiom for generating secrets or passwords in Python is to use the
random.choice
standard library function.
However, as noted in PEP 506
(
D’Aprano 2017
)
, it is cryptographically insecure and Python documentation explicitly warns against the usage of this module for security reasons, which is often missed by developers as highlighted by accepted answers on forums like StackOverflow.
PEP 506 also introduces a more secure semantic block or idiom in the form of the
secrets
module and the
secrets.choice
function, which acts as a safer alternative to the
random.choice
idiom.
As illustrated by this example, detecting and locating idioms associated with bad practices can be leveraged for identifying code quality issues like
code smells

(
Wikipedia contributors 2024
)
or
Common Weakness Enumerations
(CWE)
(
MITRE Corporation 2024
)
.
Additionally, the issues can be fixed by replacing instances of “bad” idioms with corresponding “good” idioms that align with best practices.

In this work we extended this observation by training the LLM on a higher-level instruction-following task: given a specification of a best-practice code idiom
I
, the model learns to identify and localize code fragments that violate the idiom and could be rewritten to adhere to or incorporate idiom
I
.
We refer to this instruction-following task as
meta-linting
.
The core idea is to teach the LLM the underlying structure of the task, namely identifying and locating idioms based on high-level specifications, rather than training it to memorize or learn a static set of best practices.
Since the focus is on improving the model’s instruction-following ability rather than tailoring it to a particular data distribution of best practices, this approach can keep up with evolving best practices.

Our approach, MetaLint, is motivated by the observation that instruction tuning enables cross-task generalization and improves performance on unseen tasks
(
Mishra et al. 2021a
;
Sanh et al. 2021
;
Wang et al. 2022
)
. Since meta linting frames each idiom as a separate task, instruction style training is naturally suited to generalize to novel and unseen idioms. Existing linters for programming languages (e.g., Ruff for Python) implement numerous simple rules, or “easy” idioms, that reflect aspects of code quality such as modern syntax, readability, and security. These linters can be used to generate large-scale synthetic data for supervised instruction fine-tuning and serve as verifiers during preference optimization or reinforcement learning. This setup also supports easy-to-hard generalization: training on automatically generated linter data for easy idioms helps build a strong model that can handle harder, more abstract idioms at test time, which go beyond the reach of static analyzers. Similar strategies have shown success in math reasoning tasks
(
Sun et al. 2024b
)
.
To systematically study this generalization, we construct a challenging benchmark of hard idioms based on popular PEPs that introduce high-level constructs. We evaluate state-of-the-art reasoning and code models on this benchmark and compare them to models trained with
MetaLint
, focusing on whether LLMs can move beyond memorization, generalize from easy to hard idioms, and adapt to novel patterns across code quality domains.

Our key contributions are as follows:

1.

We introduce
MetaLint
, an instruction-following framework that leverages synthetic data for easy-to-hard generalization and addresses the limitations of static training used in prior LLM-based code quality approaches.

2.

We construct a benchmark of challenging, widely relevant idioms inspired by various PEPs, and evaluate state-of-the-art code and reasoning models on it.

3.

We analyze whether
MetaLint
promotes adaptive reasoning over memorization and enables generalization from easy to hard idioms.

2
Related Work

2.1
Code Quality Analysis with Large Language Models

A large body of prior work has explored the use of LLMs for code quality analysis through code review and static analysis. Tools like GPTLint
(
Travis Fischer 2024
)
and lintrule
(
lin 2023
)
treat LLMs as linters guided by rule descriptions, relying on prompting or fine-tuning to improve rule enforcement.
LiteLLM
(
Fang et al. 2025
)
leverages LLMs to reduce both the cost and false positive rate of linting for Verilog.
Khare et al. 2023
show that LLMs can outperform traditional static analysis tools for detecting certain security-related CWEs, especially when step-by-step reasoning is used.
Vijayvergiya et al. 2024
train LLMs to detect and localize violations of best practices, while Rasheed et al.
Rasheed et al. 2024
design a multi-agent review pipeline targeting issues like maintainability, efficiency, and bugs.
Other works
(
Jiang et al. 2025b
;
Yao et al. 2025
)
use comparative prefix-tuning and reinforcement learning with static analysis–based rewards to promote the generation of higher-quality functionally correct code.

Naik et al. 2024
and
Jaoua et al. 2025
integrate LLMs with linters to produce more informative code reviews.
Finally, CoUpJava
(
Jiang et al. 2025a
)
presents a benchmark of Java version–related code upgrade histories, conceptually similar to the hard PEP idiom benchmark we developed for Python.
While such efforts highlight the potential of LLMs in code quality tasks, they often target specific rule sets or best practices, necessitating retraining as those evolve.
In contrast, our instruction-following meta-linting framework trains models to interpret high-level code quality specifications and perform static analysis to enforce them, enabling broader generalization beyond fixed rules.

2.2
Instruction Following for Generalization

Instruction tuning has emerged as a powerful form of meta-learning that enables cross-task generalization by training models to interpret and follow natural language instructions rather than learning a single fixed task. Prior work shows that exposing models to diverse task instructions allows them to extract underlying task abstractions and apply them to unseen settings
(
Mishra et al. 2021b
;
Wang et al. 2022
)
.
Large-scale instruction tuning further improves zero- and few-shot generalization across tasks and modalities
(
Wei et al. 2021
;
Chung et al. 2022
;
Gao et al. 2021
;
Iyer et al. 2022
;
Brown et al. 2020
)
.
Instructions serve as high-density task representations, acting as a substitute for supervision
(
Puri et al. 2022
)
and enabling models to generalize even with minimal labeled data or via pseudo-labeled examples
(
Gu et al. 2022
)
.
Studies also show that instruction diversity is a key driver of generalization, with varied instructions improving performance more than repeated exposure to the same task format
(
Charton et al. 2024
)
.
This phenomenon holds across domains, including program synthesis, where task-level prompting facilitates generalization in code generation models
(
Niu et al. 2023
)
.
SELF-GUIDE
(
Zhao et al. 2024
)
also performs task-specific instruction following using synthetic data, demonstrating its effectiveness; however, it relies entirely on LLM-generated data and does not incorporate verifiers.
Collectively, these results suggest that instruction tuning functions as task-level meta-learning, equipping models with the ability to rapidly adapt to new tasks via natural language. Inspired by this work we treat modeling of specific code quality idioms as individual tasks and propose the MetaLint training framework that generates synthetic data at scale for each meta-task to facilitate cross-idiom generalization. This way the trained model can keep up with new idioms and evolving best practices.

2.3
Easy-to-Hard Generalization

Recent research demonstrates that easy-to-hard generalization improves model performance across mathematical, algorithmic, and coding tasks, motivating its application to code quality analysis.
In math reasoning, models trained on easier problems (e.g., level 1–3) consistently generalize better to harder benchmarks (e.g., level 4–5)
(
Bai et al. 2024
;
Shafayat et al. 2025
;
Parashar et al. 2025
)
.
Several works implement curriculum strategies to structure this progression
(
Parashar et al. 2025
;
Zhao et al. 2025
)
, while others emphasize the importance of selecting high-quality supervision for harder problems
(
He et al. 2024
)
.
These principles extend beyond math:
Sun et al. 2024a
shows that reward models trained on simple code and math problems improve performance on complex ones, and
Zhao et al. 2025
further explores generalization in code tasks through curriculum fine-tuning.
Multi-task and length generalization studies
(
Hu et al. 2025
)
and differentiable programming setups
(
Gaunt et al. 2016
)
reveal how structural simplicity during training can lead to robustness on longer or more complex reasoning instances, including code.

Zhang et al. 2024
reinforces this by evaluating reward models on algorithmic tasks like string manipulation and demonstrating transfer from simpler to harder formats.
While our approach does not explicitly follow curriculum learning, we draw inspiration from this line of work by training
MetaLint
on large-scale synthetic data that captures easily detectable code idioms, many of which are directly covered by rule-based linters.
We hypothesize that these simple patterns act as a stepping stone, enabling generalization to more complex and abstract unseen PEP idioms.

Method

MetaLint
training framework (1/2):
Core components of our framework include using linter tools (like Ruff) for 1) Synthetic Data Generation, 2) Supervised Instruction Fine-Tuning (SFT) with synthetic data and a 3) Verifiable Reward Model (also derived from the Ruff linter).

Figure 2:
MetaLint
training framework (2/2):
We use the linter-based verifiable reward model for the final two preference optimization components: 4) Rejection Sampling Direct Preference Optimization (RS-DPO), and, 5) Rejection Sampling Supervised Fine-Tuning (RS-SFT).

We propose the
MetaLint
framework to support the learning of skills essential for code idiom analysis, such as interpreting idiom descriptions in terms of underlying code constructs and performing line-by-line static analysis to detect idiom violations. We formulate idiom detection as an instruction-following
meta-task

M_{I}
for a given idiom
I
, where the prompt includes a natural language description
D_{I}
and illustrative examples
E_{I}
, denoted as
M_{I}={D_{I},E_{I}}
. The LLM must identify all and only those code fragments that match idiom
I
while performing
M_{I}
. This setup discourages rote memorization and encourages adaptive reasoning over the prompt’s specification, since flagging violations of any other idiom
I^{\prime}\neq I
is penalized during
M_{I}
. By framing best practices as meta-tasks, this approach enables the LLM to remain flexible and better aligned with evolving best practices. We describe the components of our training framework in Figure
1
and Figure
2
below.

3.1
Synthetic Data Generation

A key advantage of our meta-task formulation is its support for easy-to-hard generalization. We train LLMs on a set of idioms
I_{\mathcal{L}}
that are detectable by existing linters
\mathcal{L}
to improve their ability to flag idiom violations, and evaluate them on a harder set
I_{\mathcal{L^{\prime}}}
consisting of idioms that linters cannot detect (where
\mathcal{L^{\prime}}
denotes the complement of
\mathcal{L}
, i.e., all idioms not detectable by
\mathcal{L}
). Our hypothesis is that training on
I_{\mathcal{L}}
helps the LLM acquire the ability to understand, and detect code idioms from high level descriptions, enabling it to generalize more effectively to the harder idioms in
I_{\mathcal{L^{\prime}}}
compared to an untrained checkpoint.

Since idioms in
I_{\mathcal{L}}
are already covered by linters, we can leverage these tools to generate large-scale synthetic training data and provide supervision. For this purpose, we use the popular Ruff linter, which implements over 800 rules spanning syntax modernization, security, readability, semantics, and more.
We run Ruff on Python source code files
f\in\mathcal{F}
from the STACK-V2
(
Lozhkov et al. 2024
)
dataset, which contains code from a diverse range of GitHub repositories.
This allows us to collect files with either no violations or one or more violations for each idiom in
I_{\mathcal{L}}
.
Ruff also incorporates rules from other linters such as PyFlakes, Bandit, and autoPEP8, making it well-suited for producing diverse and representative synthetic data. Additionally, the Ruff website hosts rule-specific documentation, including descriptions and examples, which we scrape to construct meta-task prompts
M_{I_{\mathcal{L}}}
for each idiom. An example prompt, along with a code file containing lines that violate the idiom, is shown in Appendix
A.1.1
.

3.2
Instruction Supervised Fine-Tuning

As discussed in Section
3.1
, we train the target LLM
\Phi
on a set of 50 linter-detectable, easy idioms
I_{\mathcal{L}}
, using the corresponding meta-task specifications
M_{I_{\mathcal{L}}}
and a set of source code files
\mathcal{F}
.
The input to the model consists of a prompt
p
, which combines a meta-task specification
M_{I}
for some
I\in I_{\mathcal{L}}
with a source code file
f\in\mathcal{F}
.
The model’s output is a list of idiom violations in the file, denoted as
V_{f,I}
, formatted as a JSON list with one violation per line (see example output in Appendix
A.1.1
).
In cases where there are no violations (
|V_{f,I}|=0
), the model is expected to output the phrase
NO VIOLATIONS FOUND
.
We attempt to balance the data between positive (violations) and negative (no violations) examples as much as possible; however, due to the rarity of some idioms, the final distribution is approximately 70:30 in favor of files with no violations.
This results in a total of 53k training instances spanning 50 idioms.

3.3
Verifiable Reward Model and Preference Optimization

For preference optimization, we adopt the RS-DPO approach
(
Khaki et al. 2024
)
, which combines rejection sampling (RS)
(
Touvron et al. 2023
)
with Direct Preference Optimization (DPO)
(
Rafailov et al. 2023
)
to generate on-policy data from a supervised fine-tuned (SFT) policy model.
It samples
k
outputs per input, computes rewards for them, and constructs contrastive win–loss pairs based on the reward distribution and a threshold
\eta
(Figure
2
).
We detail the verifiable linter-based reward model and contrastive pair sampling procedure below.

Reward Model Design:

The reward model evaluates model outputs by comparing predicted violations against those flagged by the linter, treating the linter’s line numbers (yellow circle in “Verifiable Reward Model”, Figure
1
) as ground truth and the model’s predicted lines (blue circle) as predictions.
Reward is computed using set-based precision, recall, and F1-score (visualized via the Venn diagram in the same figure), based on line-level overlap.
Since each meta-task
M_{I}
corresponds to a single idiom
I
, we compute one F1-score (reward) per instance.

Sampling Contrastive Pairs:

We begin with an SFT policy model
\Phi^{SFT}
and sample
k=5
outputs
y_{i}
,
i\in\{1,\dots,k\}
for each input
x
, using a range of temperature values
\tau=\{0,0.3,0.5,0.7,1.0\}
to promote output diversity.
Each response
y_{i}
receives a reward
r_{y_{i}}
, and for each pair
(y_{i},y_{j})
, we compute the reward gap
|r_{y_{i}}-r_{y_{j}}|
.
Pairs with a gap greater than the threshold
\eta=0.2
are added to the preference dataset
\mathcal{D}_{p}
.
For any such pair where
r_{y_{i}}\geq r_{y_{j}}+\eta
, we assign
y_{win}=y_{i}
,
y_{lose}=y_{j}
, and store the instance
(x,y_{win},y_{lose})\in\mathcal{D}_{p}
.

Following
Khaki et al. 2024
, we train the preference-tuned model
\Phi^{RL}
using the DPO objective:

\Phi^{RL}=\arg\max\sum_{(x,y_{win},y_{lose})\in\mathcal{D}_{p}}\log\sigma\left(\beta\log\frac{\Phi^{RL}(y_{win}|x)}{\Phi^{SFT}(y_{win}|x)}-\beta\log\frac{\Phi^{RL}(y_{lose}|x)}{\Phi^{SFT}(y_{lose}|x)}\right)

Here,
\sigma
denotes the sigmoid function, and
\beta=0.1
is the KL penalty coefficient, corresponding to low-to-moderate regularization.

3.4
Training with Reasoning Traces

Finally, inspired by the success of reasoning-augmented models in code and math tasks, and their demonstrated effectiveness in improving CWE detection performance in LLMs
(
Khare et al. 2023
)
, we propose SFT and DPO methods that incorporate chain-of-thought (CoT) reasoning. To obtain CoT traces that help the LLM arrive at the correct answer, we adopt a rejection sampling approach (“Rejection Sampling SFT” in Figure
2
) for collecting SFT data. For each input
x
, we sample
k=5
responses
y_{i}
,
i\in\{1,\dots,k\}
, from a base untrained LLM capable of CoT reasoning (e.g., Qwen3-4B), and compute the reward
r_{y_{i}}
for each response, following a similar procedure as in RS-DPO. However, instead of forming contrastive pairs, we discard any
y_{i}
with reward
r_{y_{i}}<\gamma
, where
\gamma=1
. In other words, we discard CoT–response pairs that are incorrect or improperly formatted and retain only those that are fully correct. The reward is applied only to the final response, obtained after extracting or parsing the CoT trace. We also remove any cases where the CoT fails to terminate or produce a final answer.

For some inputs
x
, no valid
y_{i}
may be found. In such cases, we skip the input entirely. To promote meta-task diversity, we retain at most two valid responses
y_{i}
per input. We sample multiple
y_{i}
only for inputs with at least one violation, and only a single
y_{i}
for inputs with no violations, this helps maintain a similar no-violation-to-violation ratio of 71:29 as in the regular SFT data. The latter case is also more likely to yield a valid CoT–response pair within the token limit. When more valid responses are available than needed, we keep the shortest
y_{i}
completions, as they typically reflect more concise reasoning (the final answer usually consumes a similar number of tokens across samples). Following this policy, we collect 52.7k instances, which we use to train the base model using SFT.

After training the LLM on this dataset, we obtain a CoT-capable SFT model
\Phi_{CoT}^{SFT}
. We then apply the same RS-DPO procedure described in Section
3.3
, with the only modification being that each
y_{i}
now contains both the CoT trace and the final response.

4
Experiments

4.1
PEP Hard Idiom Benchmark

To evaluate whether
MetaLint
training helps the base LLM learn to interpret high-level idiom specifications, and apply this skill to harder, more abstract idioms that linters struggle to detect, we construct a benchmark of “hard idioms” sourced from PEPs.
We begin by identifying fifteen PEPs that define semantic or abstract behaviors beyond what syntax or token patterns capture, then design specific heuristics for each to detect code that violates their guidelines.
Using these heuristics, we search the STACK‑V2 corpus for violations, prioritizing high recall over strict precision to retrieve a broad set of candidates for manual selection.
These “hard idioms” cannot be reliably detected by simple pattern matching, making them ideal for testing whether models truly understand idiom specifications or memorize frequent patterns seen in the Ruff idioms.
From the retrieved examples, we handpick 15–20 representative files per PEP that clearly illustrate each violation.
For each file, we identify the exact lines showing the violation (“before” snippet) and author a corrected version (“after” snippet) that complies with the PEP, forming the ground truth.
To balance the benchmark, we include negative examples (code without violations) by selecting files retrieved for one PEP and confirming they don’t violate others.
This results in 536 challenging examples, with 52% containing at least one violation and 48% being violation-free, allowing us to evaluate
MetaLint
’s ability to generalize from easy to hard idioms.

4.2
Evaluation Metrics

We evaluate the LLM’s ability to detect idiom violations through two tasks:
detection
, which assesses whether a given idiom is violated in a code file, and
localization
, which evaluates whether the model accurately identifies the specific line numbers where the violation occurs.
For both tasks, we compute precision, recall, and F-score metrics. Detection metrics are calculated at the corpus level for each idiom, treating each idiom as a distinct class.
Since the distribution of idiom occurrences may be imbalanced, we use macro averaging across idioms to weigh each class equally.

Let
I
denote an idiom,
M_{I}
its corresponding meta task specification,
f\in\mathcal{F}
a code file,
V_{f,I}
the ground truth set of violating line numbers, and
\hat{y}=V^{\Phi}_{f,I}
the model predicted violations. For each instance
(x,y)=(\{f,M_{I}\},V_{f,I})\in\mathcal{D}
, we define the indicator variable:

\mathds{1}[x]=\begin{cases}1&\text{if }x\text{ is true}\\
0&\text{otherwise}\end{cases}

The idiom detection metrics per idiom
I
are defined as:

P_{I}=\frac{\sum_{(x,y)\in\mathcal{D}}\mathds{1}[|y|>0]\cdot\mathds{1}[|\hat{y}|>0]}{\sum_{(x,y)\in\mathcal{D}}\left(\mathds{1}[|y|>0]\cdot\mathds{1}[|\hat{y}|>0]+\mathds{1}[|y|=0]\cdot\mathds{1}[|\hat{y}|>0]\right)}

R_{I}=\frac{\sum_{(x,y)\in\mathcal{D}}\mathds{1}[|y|>0]\cdot\mathds{1}[|\hat{y}|>0]}{\sum_{(x,y)\in\mathcal{D}}\left(\mathds{1}[|y|>0]\cdot\mathds{1}[|\hat{y}|>0]+\mathds{1}[|y|>0]\cdot\mathds{1}[|\hat{y}|=0]\right)}

We compute the final detection metrics by macro averaging across all idioms:

P_{\text{Det}}=\frac{1}{|I|}\sum_{I}P_{I},\quad R_{\text{Det}}=\frac{1}{|I|}\sum_{I}R_{I},\quad F_{\text{Det}}=\frac{2P_{\text{Det}}R_{\text{Det}}}{P_{\text{Det}}+R_{\text{Det}}}

For idiom localization, we compute set level precision, recall, and F1-score for each instance
(x,y)\in\mathcal{D}
, comparing the predicted and ground truth violation lines:

P_{\text{Loc}}=\frac{1}{|\mathcal{D}|}\sum_{(x,y)\in\mathcal{D}}\frac{|y\cap\hat{y}|}{|\hat{y}|},\quad R_{\text{Loc}}=\frac{1}{|\mathcal{D}|}\sum_{(x,y)\in\mathcal{D}}\frac{|y\cap\hat{y}|}{|y|},\quad F_{\text{Loc}}=\frac{2P_{\text{Loc}}R_{\text{Loc}}}{P_{\text{Loc}}+R_{\text{Loc}}}

4.4
Evaluating Transfer Performance

To evaluate the extent to which the
MetaLint
training framework encourages adaptive reasoning over idiom specifications, as opposed to memorization, we construct a synthetic test set of 5.3k instances spanning 50 Ruff idioms, using the same data generation procedure described in Section
3.1
.
The data has a similar distribution of no-violation to violation examples as the SFT training set, with a 74:26 split in favor of no violations.
We carefully select idioms to vary in their degree of overlap with those used for training, as shown in Figure
3
. The selected idioms fall into three categories:

In-Domain:
We select 5 idioms that are identical to those seen during SFT training, to assess whether
MetaLint
improves performance on idioms it was explicitly trained on.

Near Transfer:
We include 10 idioms with specifications that closely resemble those in the training set but differ slightly. This category is crucial for probing memorization: if
MetaLint
relies too heavily on memorized training idioms, it may misclassify or underperform on these similar-looking test idioms due to interference.

Far Transfer:
We choose 35 idioms that are substantially different from the training idioms to assess whether the LLM can rely solely on the provided specification. Success in this category would indicate that
MetaLint
fosters generalizable reasoning skills rather than dependence on specific training instances.

4.5
Evaluating Easy-to-Hard Generalization

To evaluate easy-to-hard generalization, we use the PEP hard idiom benchmark and compare the
MetaLint
-trained model against the baselines described in Section
4.3
. The PEP idioms are held out for all models, including
MetaLint
, which is trained only on synthetic data generated from Ruff idioms.
If training on the easier Ruff idioms leads to improved performance of
MetaLint
over the base models on the harder PEP idioms, it provides evidence that
MetaLint
encourages adaptive reasoning rather than memorization, thereby supporting easy-to-hard generalization.

5
Results

To test whether
MetaLint
enables the base LLM to interpret idiom specifications rather than simply memorize training examples, we evaluate its ability to generalize beyond the 50 Ruff idioms seen during training (Section
4.4
) to both similarnear-transfer and significantly different far-transfer idioms. We also hypothesize that the RS-DPO (preference optimization) stage improves generalization over SFT alone, and that chain-of-thought (CoT) variants outperform their standard counterparts. Additionally, we assess easy-to-hard generalization by training on synthetic data for simpler Ruff idioms and evaluating on harder PEP idioms; if the model has truly learned to interpret high-level specifications, it should improve on these harder cases as well. Once again, we expect RS-DPO and CoT variants to yield stronger generalization. We present and analyze the results of these experiments in the following sections.

training, comparing CoT and non-CoT variants across both SFT and DPO stages. The untrained Qwen3-4B without CoT achieves decent detection precision but performs poorly on detection recall and localization. After SFT training, it shows substantial improvements in precision and all localization metrics, with modest recall gains. RS-DPO training further boosts detection recall and localization significantly (over 3× and nearly 5×, respectively), although with a slight drop in detection precision.

This precision drop stems from contrastive training examples where input
x
has no violations, reducing the model’s accuracy in identifying such cases. We observe a strong correlation between the fraction of no-violation samples in training and detection precision. Including more such samples can improve precision but at the cost of recall and localization, leading to an unfavorable tradeoff. We find that including just 0.05% of no-violation data yields the best balance, minimizing precision loss while maximizing recall and improving detection F-score. Detailed ablation results are reported in Appendix
A.2.2
.

For the CoT variant, the untrained model already achieves strong detection precision and recall, along with high localization metrics—outperforming the SFT-only non-CoT model and trailing only slightly behind the SFT+RS-DPO non-CoT model (except in precision). To train the CoT model, we first apply RS-SFT to promote correct CoT reasoning and response formatting. This step is critical, as direct RS-DPO training alone causes metric collapse due to lack of absolute correctness supervision (since RS-DPO optimizes relative preference). RS-SFT leads to similar gains as non-CoT SFT, improving precision, recall, and localization. Final RS-SFT+RS-DPO training with 5% no-violation data mirrors the trends seen in the non-CoT case: increased recall, slight drop in precision, and overall gains in detection F-score and localization. Overall, the CoT model (RS-SFT+RS-DPO) is the strongest, achieving the highest precision and localization performance. However, the non-CoT SFT+RS-DPO model closely matches it in recall and approaches it on localization. Given that CoT inference is nearly 6× slower
1

the non-CoT model may be preferable in settings where detection recall and localization are the primary concerns.

6
Conclusion

Our results demonstrate that
MetaLint
may encourage more adaptive reasoning over idiom specifications instead of rote memorization of code patterns through instruction-following and easy-to-hard generalization from synthetic data.
By training on synthetic examples of easy-to-detect idioms derived from linter signals,
MetaLint
enables both Qwen3-4B CoT and non-CoT variants to generalize well across Ruff idioms in in-domain, near-transfer, and far-transfer settings, as well as to real-world, hard-to-detect PEP idioms.
The models show substantial improvements in both detection and localization, particularly after RS-DPO training, with the non-CoT variant achieving the highest detection recall among all evaluated models, despite its smaller size and training solely on synthetic data.
Additionally, it achieves this with just 4B parameters and no test-time compute in the non-CoT setting, making it one of the most efficient models.
These findings underscore the effectiveness of synthetic instruction-tuned training for fostering generalization and reasoning, even in low-resource scenarios where annotated examples of harder idiom categories are limited or unavailable.
Finally, we note that for easy idioms that are more “mechanical” to detect, linters remain the most cost-effective option.
However, LLMs—when trained with the
MetaLint
approach—enable detection of more abstract idioms, potentially unlocking support for personalized linting, and offering a no-code solution for code quality enforcement.

7
Limitations and Future Work

Despite the promising results achieved by
MetaLint
, our work has several limitations that we plan to address in future research.
First, our experiments are restricted to a single model family (Qwen3) and model size (4B).
We intend to extend our evaluations to other model families, including LLaMA and Phi, as well as larger Qwen models (8B and 14B).
In the CoT setting, it remains an open question whether non-CoT models can be trained to effectively produce CoT-style reasoning with supervision from a teacher model.
We also explored self-improvement strategies for RS-SFT data generation in cases where the base model failed, such as STaR
(
Zelikman et al. 2022
)
, but found it challenging to generate CoTs that do not directly reference provided hints, which risks contaminating the training data.
As a result, we adopted a simpler rejection sampling strategy.
Furthermore, our approach does not yet incorporate more advanced reinforcement learning techniques such as direct GRPO
(
Shao et al. 2024
)
using our verifiable linter-based reward model, or curriculum learning methods to control the progression of idiom difficulty within synthetic training data.
Our current experiments also focus exclusively on the Python programming language. Future work will explore extensions to other languages such as Java using Java-specific linters, as well as cross-language generalization by training on Python idioms and evaluating on Java idioms, and vice versa. Finally, while we prompt and train the models to generate refactoring fixes for code with idiom violations to improve code quality, we do not evaluate this capability in the present work and leave it for future exploration.

For RS-DPO sampling (in both CoT and non-CoT settings), we used the standard

A.1.3
Training Hyperparameters and Computational Environment

We use the following hyperparameters for the SFT and DPO training experiments.

SFT/RS-SFT hyperparameters:

For both SFT and RS-SFT we fine-tune the
Qwen3-4B
model using
flash_attention_2
and
bfloat16
precision. The model is trained for 2 epochs with a learning rate of 2e-5, cosine learning rate schedule, and a warmup ratio of 0.1. We use a maximum sequence length of 3000 tokens, a per-device batch size of 2, and gradient accumulation steps of 4. Gradient checkpointing is enabled to reduce memory usage, with non-reentrant mode. Evaluation is performed every 2000 steps, and checkpoints are saved at the same interval. Special tokens are manually handled in the chat template without automatic insertion. The training uses 12 preprocessing workers and is seeded with 42 for reproducibility.

RS-DPO parameters:

We fine-tune the model using RS-DPO with
bfloat16
precision and a reward shaping parameter
\beta=0.1
. Training is performed for 1 epoch with a learning rate of 5e-7, cosine learning rate scheduling, and a warmup ratio of 0.1. We use a maximum input length of 3500 tokens, a per-device batch size of 2, and gradient accumulation steps of 4. Gradient checkpointing is enabled with non-reentrant mode to optimize memory usage. The optimizer is
AdamW
, and evaluation is conducted every 200 steps with checkpoints saved at the same interval. The training is seeded with 42 for reproducibility.

Computational Environment:

All SFT, RS-SFT and RS-DPO experiments were conducted on a Linux server equipped with two NVIDIA A100 80GB PCIe GPUs (Ampere architecture), CUDA 12.9, and driver version 575.51.03.
Each job had access to 100 GB of CPU memory and 2 CPU cores.
Training was performed using mixed-precision (
bfloat16
) with gradient checkpointing to optimize memory usage.
For inference we used a similar environment but varied number of GPUs based on model sizes and needs.

A.2.2
DPO No Violation Fraction Ablations

We analyze the impact of varying the amount of samples with zero violations used for RS-DPO training. These experiments were motivated by initial findings comparing models trained only on data with at least one violation to those trained on the full dataset. By design, RS-DPO generates significantly more training data for cases with at least one violation, due to greater variance in reward signals. This is further amplified by the fact that the initial SFT policy/checkpoint is already quite accurate in handling cases with
NO VIOLATIONS FOUND
leading to low variance in reward across responses.

Our early experiments showed that excluding all
NO VIOLATIONS FOUND
cases led to notable gains in recall and line-level localization. However, this came at the cost of a significant drop in precision compared to the SFT policy/base model. Further analysis revealed a sharp decline in the accuracy of predicting
NO VIOLATIONS FOUND
, from nearly 99% down to 70-80%, with performance worsening monotonically over training steps. Conversely, training on the full dataset (i.e., including 100% of the
NO VIOLATIONS FOUND
cases) improved precision but offered only modest gains in recall and localization, which also degraded with continued training. These findings suggest that while some
NO VIOLATIONS FOUND
data is necessary to maintain high precision, too much of it may hinder recall and localization.

To investigate this trade-off, we experimented with keeping only a fraction of the
NO VIOLATIONS FOUND
data during training. Specifically, we randomly sampled
k
% of such data, varying
k
across {0%, 2%, 5%, 10%, 20%, 40%, 100%}. These percentages were selected based on observed trends: 20%, 40%, and 100% yielded similar results, which discouraged further tests at 60% or 80%, while 2% and 5% were chosen due to a noticeable performance jump between 0% and 10%. We found that 5% offered a favorable middle ground, largely retaining or slightly reducing precision, while preserving most of the recall (resulting in the highest detection F-score), and only modestly impacting line-level localization. Based on these insights, we conducted a limited ablation on the CoT model, evaluating 2% and 5% inclusion to determine the optimal setting for both detection and localization (as shown in Table
6
).

A.3.2
Statistical Significance of Results on the PEP Hard Idiom Benchmark

To analyze the statistical significance of performance differences over the PEP benchmark, we conduct Wilcoxon signed-rank tests comparing various
MetaLint
variants against each other and against baseline models.
We evaluate instance-level detection accuracy (binary labels indicating whether the LLM correctly predicted the presence of a violation) as well as instance-level precision and recall for line-level localization.
To control for multiple comparisons, we apply a Bonferroni correction to adjust the significance threshold
\alpha
as
\alpha=\frac{0.05}{m}
where
m
is the number of comparisons (or rows in any given statistical significance table in this case).

Table
9
reports the Wilcoxon signed-rank test statistic and corresponding
p
-value (in parentheses) for detection accuracy, localization precision, and localization recall when comparing various
MetaLint
variants to assess the effects of RS-DPO and CoT. We find that applying RS-DPO to the base SFT policy leads to statistically significant improvements in both detection and localization performance, with RS-DPO consistently outperforming the original SFT checkpoint across all three metrics with it being always better for localization. For the CoT variant, RS-DPO also yields consistent but less significant gains, likely because the RS-SFT CoT checkpoint is already relatively strong. Finally, we observe no statistically significant difference between the CoT (RS-SFT+RS-DPO) and the standard (SFT+RS-DPO) variant, suggesting that CoT does not provide a meaningful additional benefit in this setting.

Table

shows the statistical significance of comparing the base untrained model Qwen3-4B with its
MetaLint
variants (SFT and SFT+RS-DPO), and the Qwen3-4B CoT model with
MetaLint
w/ CoT (RS-SFT and RS-SFT+RS-DPO). The SFT variant yields significant gains in detection and localization recall, but not in localization precision. The SFT+RS-DPO model improves significantly across all three metrics. In contrast, training RS-SFT from the Qwen3-4B w/ CoT base does not yield significant improvements. However, the RS-SFT+RS-DPO variant produces significant gains in localization precision and recall, but not detection. These results suggest that while SFT alone offers limited generalization, combining it with DPO reliably improves localization and can significantly boost detection when starting from a weaker base model.

A.3.3
Failure Analysis of MetaLint CoT Model VS Non CoT Model

We observe that a significant portion of the lower detection recall of the CoT
MetaLint
Qwen3-4B model, relative to its non CoT counterpart, can be attributed to its higher tendency to predict
NO VIOLATIONS FOUND
in cases that do, in fact, contain violations. Specifically, the CoT model fails to flag violations in 89 additional instances compared to the non CoT model, amounting to nearly 17% of the evaluation set (89 out of 536 examples).

The idiom wise distribution of these missed violations is shown in Figure
4
. While the failure distribution follows a somewhat long tail pattern, the most significant drops occur for PEP 614, PEP 616, and PEP 593. Notably, if the CoT model matched the non CoT model’s performance on just these three PEPs, its detection recall would rise to 0.605, surpassing that of all open source baselines evaluated.

Upon inspecting CoT traces for these and other idioms (see examples in Table
15
), we identify several recurring failure modes:
1) Ambiguity in interpreting the idiom specification. For example, in PEP 614, which targets decorators with complex expressions, the CoT model often labels expressions that humans consider complex as simple.
2) Overthinking and repetitive reasoning traces, particularly for PEP 616.
3) Skipping or entirely missing lines that contain violations, again observed in PEP 616.
4) Underspecified idioms. For instance, in PEP 593, which recommends using the
Annotated
type from the
typing
module to attach metadata to type hints, the spec lacks clarity and concrete examples, making it hard to learn what constitutes a violation.

We also find similar issues in idioms like PEP 487, which discourages the use of metaclasses for simple customization tasks that could be handled via

Overall, these patterns suggest that the CoT model applies the idiom specifications more conservatively, resulting in higher precision but at the cost of reduced recall.
