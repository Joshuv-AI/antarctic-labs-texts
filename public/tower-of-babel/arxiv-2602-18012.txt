DeCEAT: Decoding Carbon Emissions for AI-driven Software Testing
Pragati Kumari, Novarun Deb

Abstract
The increasing use of language models in automated software testing raises concerns about their environmental impact, yet existing sustainability analyses focus almost exclusively on large language models. As a result, the energy and carbon characteristics of small language models (SLMs) during test generation remain largely unexplored. To address this gap, this work introduces the DeCEAT framework, which systematically evaluates the environmental and performance trade-offs of SLMs using the HumanEval benchmark and adaptive prompt variants (based on the Anthropic template). The framework quantifies emission and time-aware behavior under controlled conditions, with CodeCarbon measuring energy consumption and carbon emissions, and unit test coverage assessing the quality of generated tests. Our results show that different SLMs exhibit distinct sustainability strengths: some prioritize lower energy use and faster execution, while others maintain higher stability or accuracy under carbon constraints. These findings demonstrate that sustainability in the generation of SLM-driven tests is multidimensional and strongly shaped by prompt design. This work provides a focused sustainability evaluation framework specifically tailored to automated SLM-based test generation, clarifying how prompt structure and model choice jointly influence environmental and performance outcomes.

This gap underscores the need for an evaluation approach tailored to SLM inference patterns. The DeCEAT framework addresses this need by offering a multidimensional sustainability assessment designed specifically for SLM-based automated test generation.

III-A

Data Preprocessing

The foundation of our experimental evaluation is the widely adopted HumanEval benchmark
4
4

4

https://huggingface.co/datasets/openai/openai_humaneval
, a standardized dataset comprising 164 Python programming tasks used to measure the coding capabilities of Language Models. Each entry in the HumanEval dataset is structured as a record containing five key components:

(i)

task_id
: a unique identifier for each problem;

(ii)

prompt
: the natural language problem statement and the required Python function signature;

(iii)

canonical_solution
: a reference implementation of the correct function logic;

(iv)

test
: an assertion-based validation script containing the pre-defined, human-written unit tests; and

(v)

entry_point
: the callable name of the function to be tested.

For this work, a crucial preprocessing step was necessary to prepare the data for the test script generation and evaluation process. We merged the
prompt
(defining the task and signature) and the
canonical_solution
(the target code under test) to create a single runnable Python code file for each of the 164 tasks. This unified file represents the
Software Module Under Test

5
5

5

https://anonymous.4open.science/r/DeCEAT-1B25
.

This module, combined with its corresponding set of baseline unit tests (the
test
scripts provided by the
HumanEval
dataset), served as the foundation for the subsequent inference tasks. The Language Models were utilized strictly in a zero-shot inference mode, with no training or fine-tuning performed on this data set. By using this setup, we effectively simulate a realistic automated test synthesis scenario where the Language Models are challenged to infer a comprehensive suite of edge, normal, and invalid test cases from only the minimal contextual information contained within the runnable function code and its original prompt. This step ensures that the generated test scripts are evaluated against the actual function implementation, aligning with practical unit testing workflows.

III-C

Test Script Generation

The Test Script Generation phase focuses on the systematic creation of unit tests by the selected language models based on the structured prompts and prepared data modules. For this study, the generation process utilized a specific set of Small Language Models (SLMs), all instantiated under various quantization schemes to maximize efficiency and achieve a low computational footprint during inference. The core evaluation focused on five models divided by their primary quantization level:

-

8-bit Quantization:
This scheme was applied to the
Phi-3.5-mini
and
Qwen2.5-1.5B
models.

-

4-bit Quantization:
This more aggressive compression was applied to the
deepseek-coder-7b
,
Mistral-7B
, and
Llama-3-8B
models.

In addition to the core five, several models were explored for completeness:

-

TinyLlama/TinyLlama-1.1B-Chat-v1.0
was tested without any quantization, although it yielded weak and unstable output.

-

google/codegemma-7b
was tested using 4-bit quantization; however, while it performed reliably with minimal prompts (AP
{}_{V_{0}}
and AP
{}_{V_{1}}

{}_{V_{2}}
and AP
{}_{V_{3}}

-

Similarly,

faced similar AP
{}_{V_{2}}

{}_{V_{3}}

Each of the prepared code modules is passed to the quantized SLMs using the engineered prompt variants (AP
{}_{V_{0}}
to AP
{}_{V_{3}}
). To maintain the scientific rigor of the experiment, all key generation hyperparameters are fixed across all trials to isolate the effects of prompt structure and model quantization. For example, parameters such as the generation

The entire generation process is executed within a controlled environment and is designed to produce a sufficient number of test scripts to allow statistical stability in the subsequent analysis of quality and environmental metrics. The output is a set of generated unit test scripts for each module, prompt, and model configuration, ready for the next phases of quality assessment.

III-D

Primary Analysis

To assess the environmental impact of Small Language Models (
SLMs
) in automated test script generation, the proposed framework evaluates a set of
primary metrics
that are derived directly from the fundamental evaluation parameters:
Energy Consumption
(
E
),
Carbon Emission
(
C
), and
Test Quality/Code Coverage
(
Q
). These parameters form the basis for quantifying both the functional utility and the environmental cost of the generated test scripts. This section details these primary metrics and their calculation.

III-D
1
Software Carbon Intensity (SCI)

The
Software Carbon Intensity (SCI)
metric, adapted from the Green Software Foundation’s standard
[
21
]
, represents the environmental cost of a model’s computational activity as the amount of
grams of
\text{CO}_{2}
equivalent (
\text{gCO}_{2}\text{e}
)
emitted per functional run. It is directly proportional to the total energy consumed (by CPU, GPU, and RAM) and can be expressed as:

\text{SCI}\propto E\;\implies\;\text{SCI}=kE,\ \text{where }k=\frac{I}{R}.

(1)

Here, the proportionality constant
k
is defined by the fixed environmental and operational parameters of the experiment.

•

E
(in
\mathrm{kWh}
) denotes the
total energy consumption
recorded during the entire batch of test generation.

•

I
(in
\mathrm{gCO}_{2}/\mathrm{kWh}
) is the
carbon intensity
of the power grid where the experiments were carried out.

•

R
is the
number of functional runs
(i.e., the number of individual Python code modules from the
HumanEval
dataset processed within that batch).

Interpretation:

SCI
quantifies the carbon cost associated with generating one complete execution cycle (i.e., generating the test script for one code module). A
lower
SCI
signifies reduced energy-to-output emissions, providing a direct measure of energy efficiency in the model’s operation.

Relevance to Sustainability:

SCI
forms the foundation of the sustainability framework, establishing a baseline for emission-aware performance comparison. It quantifies the immediate
carbon footprint of productivity
and aligns with the principles of environmental efficiency under ISO 14067 and the Green Software Foundation guidelines
[
21
]
.

III-D
2
Sustainable Efficiency Index (SEI)

The
Sustainable Efficiency Index (SEI)
provides an inverse measure of
SCI
, indicating the
number of functional executions achievable per gram of
\text{CO}_{2}
emitted
.

\text{SEI}=\frac{1}{\text{SCI}}.

(2)

While
SCI
captures the environmental cost per output,
SEI
emphasizes the return—how effectively computational effort converts into productive inference.

Interpretation:

A
higher
SEI
indicates greater computational productivity under fixed carbon constraints, linking efficiency directly with the emission economy. It complements
SCI
by reflecting the sustainability gain per unit of emission rather than just its cost.

Relevance to Sustainability:

SEI
captures the principle of
doing more with less
by translating energy optimization into meaningful output efficiency. It bridges traditional performance evaluation with ecological responsibility, quantifying the
positive sustainability return
from energy-efficient model behavior.

III-D
3
Carbon Efficiency Ratio (CER)

The
Carbon Efficiency Ratio (CER)
integrates model output quality with environmental cost, expressing the
percentage of code coverage achieved per gram of emitted
\text{CO}_{2}
.

\text{CER}=\frac{Q}{C}

(3)

In this formula:

•

Q
denotes the code coverage achieved by the generated test scripts (expressed as a percentage, %).

•

C
represents the total carbon emission per prompt execution or functional run (in
\text{gCO}_{2}\text{e}
).

Interpretation:

A
higher
CER
represents greater output quality per unit of emission, effectively balancing test accuracy with ecological expenditure. This metric extends sustainability assessment beyond simple energy conservation to include reliable performance outcomes.

Relevance to Sustainability:

CER
emphasizes
quality-oriented sustainability
, ensuring that emission-efficient models also deliver a consistent and complete test coverage. By correlating coverage (
Q
) with emission data (
C
), it reinforces the idea that carbon efficiency must reflect both energy responsibility and result integrity within software testing workflows.

III-E

Trade Off Analysis

This section introduces a collection of derived metrics designed to facilitate a nuanced trade-off analysis between model performance (test quality) and environmental sustainability (carbon and energy expenditure). While the primary metrics established the foundational costs and efficiencies, these derived metrics explicitly capture the interplay and complexity of optimizing both factors simultaneously. By combining core parameters, they provide a powerful quantitative basis for users and researchers to select optimal, high-quality, and environmentally responsible models and prompt configurations for automated test script generation.

III-E
1
Stability Index (SI)

The
Stability Index (SI)
measures the
run-to-run consistency
in a model’s sustainability performance.

\text{SI}=1-\frac{\sigma}{\mu}

(4)

In this formula:

•

\mu
denotes the
mean value
of any previously defined primary metric (
SCI
,
SEI
or
CER
) in multiple inference runs.

•

\sigma
represents the
standard deviation
of the same metric in multiple runs.

Interpretation:

SI
captures the steadiness of model behavior under repeated execution. A
high
SI
indicates a model that maintains uniform emission and energy profiles, while a lower or negative
SI
reflects irregular or unstable sustainability patterns.

Relevance to Sustainability:

Stability ensures that sustainability gains are not random or context-dependent. Models exhibiting high
SI
values deliver predictable and reliable performance—key to scalable and reliable sustainable
AI
deployment. It links directly to environmental reproducibility, confirming that energy efficiency persists in dynamic testing scenarios.

III-E
2
Green Quality Index (GQI)

\text{GQI}=2\times\frac{Q\times E}{Q+E}

(5)

The
Green Quality Index (GQI)
combines normalized quality (
Q
) and efficiency (
E
) through a harmonic mean, providing a unified view of sustainability progress.

Interpretation:

GQI measures the holistic improvement in environmental efficiency and functional quality.
A higher GQI indicates that a model achieves better energy–quality synergy, effectively balancing emission reduction with reliable output generation.

Relevance to Sustainability:

GQI emphasizes
co-optimization
, where improvements in sustainability are achieved without compromising output performance.
By integrating emission reduction, energy efficiency, and quality metrics, it represents the comprehensive sustainability maturity of a model—crucial for long-term green AI development.

III-E
3
Sustainable Coverage Velocity (
SCV
)

The
Sustainable Coverage Velocity (SCV)
includes two variants: SCV
C
, which uses Carbon Emissions (C), and its energy variant SCV
E
, which uses Energy Consumption (E), both of which integrate time into the sustainability assessment by measuring the
coverage achieved per unit of time and resource consumption
.

\text{SCV}_{C}=\frac{Q}{T\times C},\qquad\text{SCV}_{E}=\frac{Q}{T\times E}

(6)

In these formulas:

•

Q,C,E
have been defined in section
III-D
, and

•

T
is the execution time (duration of the inference task) in seconds (
s
).

Interpretation:

A higher value of
\text{SCV}_{C}
or
\text{SCV}_{E}
implies a faster coverage progression with a lower time and resource cost, revealing which models deliver faster and cleaner execution cycles.

Relevance to Sustainability:

SCV
transforms sustainability into a dynamic perspective, emphasizing how efficiently models utilize time and resources to generate validated outputs. It reflects the practical notion of "
green velocity
"—achieving maximum computational productivity within minimal carbon and energy budgets.

III-E
4
Sustainable Velocity Index (SVI)

The
Sustainable Velocity Index (SVI)
combines four critical sustainability aspects—coverage, software carbon intensity, execution time, and stability—into a single normalized metric.

\text{SVI}=\frac{Q}{100}\cdot\frac{1}{1+\hat{\text{SCI}}}\cdot\frac{1}{1+\hat{T}}\cdot(1-\hat{\sigma}),\qquad\hat{x}=\frac{x-x_{\min}}{x_{\max}-x_{\min}}

(7)

In this formula:

•

Q
is the code coverage achieved (%).

•

\hat{\text{SCI}}
is the normalized Software Carbon Intensity.

•

\hat{T}
is the normalized execution time.

•

\hat{\sigma}
is the normalized average standard deviation of
SCI, SEI,
and
CER
(used as a proxy for instability).

•

\hat{x}
is the normalization function that ensures fair and consistent cross-model comparisons by scaling all metrics to a common range.

Interpretation:

SVI
quantifies the comprehensive sustainability performance under temporal and variability constraints. A
high
SVI
indicates a model that achieves broad coverage (
Q
) with minimal time (
\hat{T}
), consistent stability (
\hat{\sigma}
), and low emissions (
\hat{\text{SCI}}
).

Relevance to Sustainability:

The multiplicative formulation of
SVI
ensures that deficiencies in one dimension (e.g., long runtime) cannot fully offset strengths in another, promoting
balanced eco-performance
. It rewards models that maintain consistent speed, stability, and emission efficiency simultaneously, reflecting a holistic view of sustainable
AI
deployment.

III-E
5
Green
\text{F}_{\beta}
Score (
\text{GF}_{\beta}
)

The
Green
\text{F}_{\beta}
Score (
\text{GF}_{\beta}
)
synthesizes eco-efficiency (
ECO
) and code coverage accuracy (
Q
), balancing environmental impact with performance quality.

\text{GF}_{\beta}=\frac{(1+\beta^{2})Q\cdot\text{ECO}}{\beta^{2}Q+\text{ECO}},\qquad\text{ECO}=\frac{1}{(1+\hat{\text{SCI}})(1+\hat{T})}

(8)

In this formula:

•

Q
is the code coverage achieved (%).

•

ECO
represents the eco-efficiency index, combining normalized
SCI
(
\hat{\text{SCI}}
) and normalized execution time (
\hat{T}
), where
T
is the duration in seconds.

•

\beta
is the
weighting parameter
that modulates the emphasis placed on quality versus eco-efficiency.

The resulting mean values of
\text{GF}_{\beta}
were grouped into two comparative regimes:
\beta<1
representing the
eco-efficiency domain
and
\beta>1
representing the
quality-oriented domain
.

Interpretation:

\text{GF}_{\beta}
provides a tunable trade-off between environmental and performance priorities. The values of
\beta<1
prioritize eco-efficiency, while
\beta>1
prioritize output quality. Higher values in the
\beta<1
regime indicate stronger eco-efficiency under time and emission constraints, whereas higher values in the
\beta>1
regime signify improved quality retention despite ecological limitations.

Relevance to Sustainability:

\text{GF}_{\beta}
integrates the dynamics of time, emission and quality into a single composite index, allowing a holistic evaluation of how models optimize resource usage while maintaining accuracy of coverage. It is particularly suited for sustainable systems in the real-world
AI
, where both energy optimization and quality assurance are essential for the implementation of environmentally responsible models.

The setup integrates structured prompt variants (AP

VI
Threats to Validity

This study presents several potential threats to validity.

Internal Validity:
Although the experimental pipeline was kept constant, uncontrolled factors such as system background processes, variability in model loading, or cache effects may have influenced the energy measurements and execution time, potentially introducing bias in reported outcomes.

External Validity:
The generalizability of the results is limited due to the reliance on a single benchmark (HumanEval), fixed hardware configuration, and specific assumptions of the carbon intensity of electricity. Performance and emission outcomes may vary across other datasets, programming tasks, geographic regions (owing to electricity grid differences), or hardware architectures such as TPU, AMD GPU, or edge devices.

Construct Validity:
Emission values were derived using estimated carbon intensity from CodeCarbon rather than real-time smart-meter measurements. Therefore, the reported results serve as approximations rather than absolute emission values. Similarly, test coverage and accuracy may not fully capture the broader notions of quality, usability, or robustness of AI-generated test scripts.

Statistical Conclusion Validity:
Experiments were carried out with a limited number of trials per model–prompt pair, which may affect the reliability of observed trends in emission variations and time–efficiency relationships. Minor fluctuations might not reach statistical significance, and potential correlations should be interpreted with caution.

VII
Conclusion

This study presented a comprehensive sustainability evaluation framework for small language models (SLMs) using the HumanEval dataset and progressive prompt variants (AP
{}_{V_{0}}
–AP
{}_{V_{3}}
). By integrating primary and derived sustainability metrics—SCI, SEI, CER, SI, GQI, SCV, SVI, and GF
β
—the framework quantified not only the energy and emission footprints of model inference but also their stability, temporal efficiency, and quality trade-offs.

Experimental analysis revealed model-specific strengths:
deepseek-coder-7b
excelled in emission and energy efficiency,
Phi-3.5-mini
provided the best eco–quality and temporal balance, and
Qwen2.5-1.5B
showed the highest run-to-run stability. These results highlight the multidimensional nature of sustainability—no single model performs best across all axes, and the optimal choice depends on desired priorities such as emission control, stability, or output quality.

Future work will refine prompt design for greener configurations, extend the framework to additional model families, and evaluate unquantized executions and diverse hardware settings to uncover deeper sustainability patterns.
