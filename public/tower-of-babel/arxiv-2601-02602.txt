SWaRL: Safeguard Code Watermarking via Reinforcement Learning * Corresponding author: njavidnia@ucsd.edu
Neusha Javidnia *, Ruisi Zhang, Ashish Kundu, Farinaz Koushanfar

Abstract
We present SWaRL, a robust and fidelity-preserving watermarking framework designed to protect the intellectual property of code LLM owners by embedding unique and verifiable signatures in the generated output. Existing approaches rely on manually crafted transformation rules to preserve watermarked code functionality or manipulate token-generation probabilities at inference time, which are prone to compilation errors. To address these challenges, SWaRL employs a reinforcement learning-based co-training framework that uses compiler feedback for functional correctness and a jointly trained confidential verifier as a reward signal to maintain watermark detectability. Furthermore, SWaRL employs low-rank adaptation (LoRA) during fine-tuning, allowing the learned watermark information to be transferable across model updates. Extensive experiments show that SWaRL achieves higher watermark detection accuracy compared to prior methods while fully maintaining watermarked code functionality. The LoRA-based signature embedding steers the base model to generate and solve code in a watermark-specific manner without significant computational overhead. Moreover, SWaRL exhibits strong resilience against refactoring and adversarial transformation attacks.



I
Introduction

Large language models are capable of generating high-quality source code, which has tremendously accelerated productivity in software development. Building these powerful tools requires substantial investments in data curation, post-training alignment, and architecture design, all of which constitute valuable intellectual property (IP). Such high-quality code, however, can be easily redistributed, modified, or reused without attribution, obscuring the provenance of the model and undermining the ownership rights of model developers. At the same time, the ease of producing functional code at scale also raises serious concerns regarding code accountability. Malicious adversaries can exploit code LLMs to create obfuscated or vulnerable code snippets, making it difficult to trace their origins during forensic analysis. As a result, watermarking, the process of embedding imperceptible yet verifiable signatures into generated code, emerges as a crucial mechanism for tracing authorship, ensuring IP protection, and enabling accountability in the era of AI-assisted programming.

Prior code watermarking work can be generally categorized into two approaches: (i) inference-based watermarking, and (ii) neural-based watermarking. Inference-based watermarking encodes watermarks at the token generation step by constraining the decoding process. The vocabulary is split into “green” and “red” token sets, and biasing the model to sample primarily from the green set
[
12
]

[
10
]
. While such methods require no additional model updates, they often degrade code fidelity as small probability bias can collapse the code syntax, thereby compromising its functionality. Neural-based watermarking, in contrast, embeds the watermark globally by training an additional watermarking network that learns to transform the code to watermarked variants with hidden signatures embedded
[
28
]

[
26
]
. Such transformations are done with manually defined syntactic structure rules and learned variable renaming patterns. This approach can better preserve the code’s functionality, but relies on manually defined transformation rules and is therefore vulnerable to refactoring attacks that systematically edit and restructure the artifact.

This paper presents SWaRL, a robust watermarking framework that aligns code LLMs to automatically generate fidelity-preserving code with the owner’s signature embedded. SWaRL fine-tunes the model so that its outputs satisfy two objectives: (i) produce functional code that successfully passes unit tests after compilation, and (ii) embed signatures that can be reliably detected by a watermark detector. Both criteria can be verified automatically without human-in-the-loop inspection or manually-crafted transformation rules, which ensures SWaRL’s generalizability toward new syntactic structures and robustness toward refactoring attacks.

To accomplish this, SWaRL fine-tunes the model using Group Relative Policy Optimization (GRPO)
[
21
]
, a lightweight and human-preference-free alignment algorithm. Given an input prompt, the model samples multiple candidate code outputs, each of which is evaluated using functional unit tests for correctness and a trainable watermark detector for signature detectability. To ensure stable optimization across these objectives, SWaRL employs a co-training mechanism in which, after every few optimization steps, the watermark detector—serving as the reward model—is updated jointly with the actor. This coordinated update schedule prevents any single reward component from dominating and enables the model to simultaneously improve code quality and watermark strength without collapsing toward a single objective.

To keep the process lightweight and maintainable across model versions, SWaRL uses Low-Rank Adaptation (LoRA)
[
8
]
to inject watermark-specific behavior as a small adapter on top of the base LLM, rather than fine-tuning all model parameters, which ensures computation efficiency. As a result, SWaRL produces semantically correct code that carries a verifiable watermark, with modest training overhead.

In brief, our contributions are summarized as follows:

•

We introduce SWaRL, a reinforcement-learning-based watermarking framework that automatically aligns code LLMs to generate functionality-preserving code without requiring manually crafted transformation rules.

•

SWaRL leverages (i) Group Relative Policy Optimization to align the model to generate code with functional correctness, reliable watermark detectability, and robustness against refactoring-based attacks, and (ii) Low-Rank Adapters to provide a modular, lightweight mechanism for integrating watermarking behavior into base LLMs.

•

SWaRL delivers state-of-the-art watermark detectability while achieving the highest code-generation accuracy among all watermarking baselines.
Across all four benchmarks, SWaRL consistently surpasses the non-watermarked SFT baseline in pass rate and outperforms prior watermarking methods. Furthurmore, It demonstrates the strongest robustness to refactoring attacks, exhibiting 6.4% average AUROC degradation across evaluated datasets.

Adding watermarks in LLM-generated code can be categorized into

[
14

uses a syntax-replacement table to insert watermarks by systematically replacing certain code tokens or constructs with the watermarked variants. It relies on handcrafted rules and language-specific heuristics to ensure successful watermark insertion.
(ii) inference-based watermarking

II-B

Reinforcement Learning

Reinforcement learning (RL) has become a central component in post-training large language models beyond supervised instruction tuning
[
16
]
. RL-based post-training enables models to align with human preferences, improve reasoning, and optimize for task-specific objectives that are difficult to capture through static datasets. A typical RL pipeline for LLMs builds upon a reward signal, which is derived from human feedback, learned reward models, or rule-based evaluators, and a policy model using variants of policy-gradient methods. Previous work uses reinforcement learning from human feedback (RLHF), where the reward function is trained from pairwise preference data and optimized via trust-region policy optimization. Despite its effectiveness, these RLHF pipelines can be computationally expensive, tightly coupled to reward-model quality, and prone to reward hacking or distributional drift.

Group Relative Policy Optimization (GRPO)
[
20
]
has emerged as a lightweight and robust alternative to standard RLHF-style optimization for LLM alignment. It is particularly effective in tasks requiring structured reasoning, such as code generation and mathematical reasoning. Unlike traditional methods that rely on a separately trained reward model, GRPO directly compares a group of sampled responses for each prompt to derive a relative advantage signal from evaluators like code compilers. Formally, given a prompt
x
and a set of
K
candidate responses
\{y_{1},\dots,y_{K}\}
sampled from the current policy
\pi_{\theta}
, each response receives a quality score
s_{k}
from a rule-based evaluator (e.g., functional compiler for coding tasks). GRPO computes the relative advantage

A_{k}=s_{k}-\frac{1}{K}\sum_{j=1}^{K}s_{j},

which normalizes each sample’s quality relative to the group mean. The policy update then maximizes the objective

\mathcal{L}_{\text{GRPO}}(\theta)=\frac{1}{K}\sum_{k=1}^{K}A_{k}\log\pi_{\theta}(y_{k}\mid x),

a simplified policy-gradient formulation that removes the need for KL penalties or PPO-style clipping while reducing variance through group-relative normalization. This design is especially advantageous for code-generation tasks, where automatic evaluators (unit tests, execution traces, syntax checks) provide precise and high-quality signals.

II-C

Low-Rank Adaptation

Low-Rank Adaptation (LoRA)
[
7
]
is a parameter-efficient fine-tuning (PEFT) technique that reduces the computational and memory cost of training large language models. Instead of updating the full parameter of a pretrained model, LoRA introduces a pair of trainable low-rank matrices that capture task-specific updates while keeping the original weights frozen. For a weight matrix
W_{0}\in\mathbb{R}^{d\times k}
, LoRA replaces the standard update

W=W_{0}+\Delta W

with a low-rank parameterization

\Delta W=BA,

where
A\in\mathbb{R}^{r\times k}
and
B\in\mathbb{R}^{d\times r}
, with
r\ll\min(d,k)
. During fine-tuning, only
A
and
B
are trained while
W_{0}
remains fixed. A scaling factor
\alpha
is typically applied to stabilize training:

\Delta W=\frac{\alpha}{r}\,BA.

By restricting updates to a low-rank subspace, LoRA substantially reduces the number of trainable parameters and enables efficient multi-task and modular adaptation through merging or removing adapters as needed.

III
Threat Model

Scenario

As in Figure
1
, we consider the code LLM owner hosts the model as a cloud API service. End users receive only the final watermarked code, but do not have access to the code generation and watermarking process. An adversarial user may attempt to tamper with or transform the watermarked code through post-processing and refactoring to remove the embedded watermarking message. However, any manipulated code must remain functional and semantically valid, as the adversary relies on it for normal use or distribution.

Watermarking Requirement

An ideal code LLM watermarking framework should meet the following requirements: (i) Fidelity: the watermarking framework must embed the watermark without degrading the quality, correctness, or functional behavior of the generated code; (ii) Robustness: the embedded watermark must resist removal and forgery attempts from adversaries and remain recoverable even after these attacks; (iii) Efficiency: the watermark
insertion should be efficient both in terms of time and computation overheads. By taking these criteria into the design, SWaRL
delivers reliable IP protection for LLM-generated code.

Attacker’s Capability and Goal

The attacker is assumed to have full access to the watermarked code produced by the provider, including the ability to read, edit, refactor, and execute it. However, the attacker does not have access to (i) the provider’s watermarking key and hyperparameters, and (ii) the watermarking insertion and verification process.
The attacker’s primary objective is to deactivate the watermark verification process by preventing correct message recovery, while preserving the functional behavior of the code. The attacker therefore aims to strike a balance between aggressive code manipulation and maintaining correctness, efficiency, and compatibility requirements.

The attacker can perform several categories of watermark-removal attacks:

(i)
Refactoring attacks.
The adversary leverages an external LLM to automatically refactor the code through variable renaming, syntactic transformations, loop restructuring, function inlining or decomposition, and other semantics-preserving edits. This includes the LLM-based refactoring attack used in our evaluation, where a third-party model is prompted to generate an alternative implementation with identical functionality but altered surface form.

(ii)
Compiler-based transformations.
The adversary may apply standard compiler optimizations or source-to-source transformations, such as constant folding, dead-code elimination, and control-flow simplification.

(iii)
Syntactic rewriting tools.
Automated code-formatting or rewriting frameworks (e.g., tree-based code transformers, linting/formatting tools, or AST-level mutation libraries) can introduce deterministic structural changes that may reduce or remove watermark patterns without affecting functionality.

Together, these attack vectors represent realistic adversarial capabilities aimed at removing, changing, or weakening the embedded watermark while maintaining correct program behavior.

IV
Methodology

The combined reward drives a Group Relative Policy Optimization (GRPO) update, adjusting the model via lightweight LoRA. Periodically, the detector is retrained on new outputs so it stays aligned with the evolving actor policy.

SWaRL consists of two primary components: an actor model for generating candidate code, and a reward function that validates if the generated code is functional and have watermark embedded.
These two components are aligned end-to-end as in shown Figure
2
.

During fine-tuning, SWaRL leverages Group Relative Policy Optimization (GRPO), a light-weight and human-preference-free alignment algorithm, to update the model. It is driven by three complementary feedback signals: (i) watermark detector feedback, encouraging the actor to embed model-specific watermarking features; (ii) execution feedback from a test runner, ensuring that watermarking does not compromise functional correctness; and (iii) reference-model divergence control, which stabilizes RL training by preventing the policy from drifting too far from the original model.

At deployment time, the fine-tuned LLM can be deployed through standard cloud APIs and behaves identically to conventional code-generation services, producing natural and executable code. Authorized parties may then apply the watermark detector to verify whether any given code snippet originated from the watermarked actor, enabling reliable provenance tracking without altering user workflow or output quality.

IV-A

GRPO-based Optimization

To train the actor code LLM to produce code that is both watermarked and functionally correct, we extend Group Relative Policy Optimization (GRPO) to optimize a hybrid reward combining three objectives: (1) a watermark detection score that encourages embedding model
-
specific watermark signals, (2) an execution
-
based correctness score that ensures the generated code passes unit tests, and (3) a divergence penalty that constrains the policy to stay close to the original reference model. Concretely, for each sampled trajectory (code output)
\tau

R_{\text{wm}}
is the watermark reward,
R_{\text{exec}}
is the test

\pi_{\text{ref}}

\begin{split}R(\tau)=\lambda_{\text{wm}}\,R_{\text{wm}}(\tau)\;+\;\lambda_{\text{exec}}\,R_{\text{exec}}(\tau)\\
\;-\;\beta\,D_{\mathrm{KL}}\bigl(\pi_{\theta}(\cdot\mid x)\,\big\|\,\pi_{\text{ref}}(\cdot\mid x)\bigr),\end{split}

(2)

Given a group of
G
trajectories
\{\tau_{1},\dots,\tau_{G}\}
drawn under the current policy
\pi_{\theta}
, each trajectory receives a scalar reward
R_{i}=R(\tau_{i})
. GRPO computes a group baseline

b=\frac{1}{G}\sum_{i=1}^{G}R_{i},

and defines the relative advantage for each trajectory as

A_{i}=R_{i}-b.

The actor is then updated via a clipped policy
-
gradient objective as:

\mathcal{L}_{\text{clip}}(\theta)=-\frac{1}{G}\sum_{i=1}^{G}\sum_{t=1}^{T}\min\!\Bigl(r_{i,t}A_{i},\;\mathrm{clip}(r_{i,t},1-\epsilon,1+\epsilon)\,A_{i}\Bigr),

where
r_{i,t}=\dfrac{\pi_{\theta}(a_{t}\mid a_{<t},x)}{\pi_{\theta_{\text{old}}}(a_{t}\mid a_{<t},x)}
is the importance ratio, and
\epsilon
is the trust
-
region (clipping) parameter.

As such, the actor learns to prefer outputs that balance watermark embedding with functional correctness, while the KL regularization term prevents the policy from drifting too far from the original model, which lead to stable and controlled learning of watermarked code generation.

To make the GRPO fine
-
tuning procedure computationally efficient and the watermarked behavior modular, we apply LoRA on top of the frozen base model. Rather than updating all parameters of the large pretrained code LLM, we inject small trainable low
-
rank matrices into its linear layers (e.g., the attention and MLP layers). Concretely, for any weight matrix

W_{0}\in\mathbb{R}^{d_{\text{out}}\times d_{\text{in}}},

we reparameterize the updated weight as

W=W_{0}+\Delta W,\qquad\Delta W=BA,

where
A\in\mathbb{R}^{r\times d_{\text{in}}}
and
B\in\mathbb{R}^{d_{\text{out}}\times r}
, with rank
r\ll\min(d_{\text{in}},d_{\text{out}})
. Only the adapter matrices
A,B
are trainable; the original base weights
W_{0}
remain frozen throughout training.

End-to-end SWaRL Fine-tuning

We now show the full training loop of SWaRL in Algorithm
1
, which alternates between policy optimization of the code LLM (actor) and periodic updates to the watermark detector. In each iteration, a mini
-

watermark score
(from the current detector) and an
execution correctness score

-

K

-

IV-D

SWaRL Deployment

During inference, the fine-tuned LLM is deployed as a standard code-generation API or service. The SFT-trained base model and the GRPO-tuned LoRA adapter are merged so that the model produces watermark-embedded code. Each time the API receives a prompt, the fine-tuned LLM generates code that (i) is functional to pass unit tests, and (ii) carries the signature that SWaRL has learned. The trained watermark detector can be later used to verify if a code is watermarked. Given any arbitrary code sample, the watermark detector outputs a likelihood indicating whether the code was generated by code LLM trained with SWaRL. This enables external auditing or provenance checking without needing access to the original LLM or retraining.

SWaRL Balances Both Watermark Detectability and Code Quality:

A key finding is that SWaRL attains strong watermark detectability while simultaneously preserving and even improving—code-generation quality.

In contrast to WLLM and SWEET, which sacrifice correctness in exchange for stronger statistical watermarking signals, SWaRL embeds watermark information in a semantically aligned manner that does not distort the model’s decoding distribution. Instead of perturbing token-level probabilities, SWaRL leverages reinforcement learning to guide the actor toward watermark-consistent solution strategies.

GRPO-Based SWaRL Improves Code Accuracy Over the SFT Baseline

A distinguishing result of our experiments is that our GRPO-based method SWaRL not only preserves utility under watermarking but, in all settings, exceeds the Base+SFT model in code correctness. This improvement is especially visible in HumanEval and HumanEval+, where SWaRL shows higher Pass@1 and Pass@10 scores than the non-watermarked baseline.

This performance gain arises from the execution reward incorporated into the GRPO optimization. During training, the actor model is positively reinforced for generating code that successfully passes unit tests and is penalized for producing functionally incorrect solutions. As a result, GRPO effectively acts as an additional functionality fine-tuning stage, guiding the model toward syntactically valid and semantically correct program outputs. This behavior is consistent with prior observations that GRPO often provides a more targeted and effective fine-tuning signal than supervised learning alone, particularly for tasks where correctness can be explicitly validated.

VI
Conclusion

This paper presents SWaRL, a reinforcement-learning-based watermarking framework that automatically aligns code LLMs to generate functional code with detectable watermarking signatures for attribution. In addition, a LoRA-based fine-tuning method is applied to provide a modular, lightweight mechanism
for integrating watermarking behavior into base LLMs. Extensive evaluations demonstrate that code LLMs fine-tuned with SWaRL are capable of generating quality code with highly detectable signatures and strong resilience against attacks.
