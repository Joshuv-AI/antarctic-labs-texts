Universally Optimal Decremental Tree Minima
Benjamin Aram Berendsohn

Abstract
An algorithm on weighted graphs is called universally optimal if it is optimal for every input graph, in the worst case taken over all weight assignments. Informally, this means the algorithm is competitive even with algorithms that are optimized for only one specific input graph. Universal optimality was recently introduced [Haeupler et al. 2024] as an alternative to the stronger, but often unachievable instance optimality . In this paper, we extend the concept of universal optimality to data structures. In particular, we investigate the following dynamic graph problem: Given a vertex-weighted forest, maintain the minimum-weight vertex of every tree under edge deletions. The problem requires Θ ⁡ ( log ⁡ n ) \Theta(\log n) amortized time per operation in general, but only 𝒪 ⁡ ( 1 ) \mathcal{O}(1) time if the initial forest is a path. We present a data structure that has optimal total running time for every fixed initial forest and every fixed number of operations/queries m m , when taking the worst case over all weight assignments and operation sequences of length m m . This definition of universal optimality is easily adapted to other data structure problems. Our result combines two techniques: (1) A decomposition of the input into paths, to take advantage of the 𝒪 ⁡ ( 1 ) \mathcal{O}(1) -time path-specific data structure; and (2) splay trees [Sleator and Tarjan 1985], which, informally speaking, are used to optimally handle a certain sorting-related subproblem. We apply our data structure to solve problems related to Cartesian trees , path minimum queries , and bottleneck vertex/edge queries , each with a certain universal optimality guarantee. Our data structure also can be modified to support edge weights instead of vertex weights. Further, it generalizes to support semigroup sum queries instead of minimum queries, in universally optimal time.

In this paper, we study the following dynamic graph problem, which we call

For the

Universal optimality for algorithms.

In classical worst-case complexity, the running time of an algorithm is usually measured in terms of input size only; i.e., for a fixed input size, take the worst case over all inputs of that size. For graph algorithms, sometimes both the number
n
of vertices and the number
m
of edges is fixed, and parametrized graph algorithms additionally fix the value of some parameter.
In universal optimality, the parameter is the
graph itself
, and the worst case is only taken over additional data like vertex weights.

More precisely, consider a problem where the input is a graph
G
with an (edge- or vertex-)weight function
w
, and let
A
be an algorithm for this problem. Let
\mathbb{T}(A,G,w)
denote the running time of
A
on input
(G,w)
, and let
\mathbb{T}(A,G)=\max_{w}\mathbb{T}(A,G,w)
, where the maximum is taken over all possible weight functions for
G
.

1

Then

\mathbb{T}(A,G)\leq c\cdot\mathbb{T}(A^{\prime},G)
for some globally fixed constant

In particular, universal optimality means that

In contrast,

\mathbb{T}(A,G,w)\leq c\cdot\mathbb{T}(A^{\prime},G,w)

First, in the

A related problem is

We need to sort the elements using comparisons, under the promise that the sorted order is a linear extension of the given partial order. For universal optimality, the Hasse diagram corresponds to the graph

Two different universally optimal algorithms for this problem have been found recently

Finally, there is an algorithm for

(replacing the weight assignment). For convex hull, the primary input part is taken as the
set

A universally optimal algorithm by this definition is

[

Note that all three problems have worst-case lower bounds of
\Omega(n\log n)
(where

denotes the number of vertices in the graph, the number of elements to sort, or the number of points). These lower bounds are achieved if the input is a star, a partial order consisting of a single antichain, or a set of points in convex position, respectively. In all three cases, worst-case optimal algorithms have been known for a long time.

On the other hand, the following easy cases can be identified: For the distance-ordering problem, if

is a directed path starting at

Finally, it is known that a convex hull can be computed in linear time if it only contains a constant number of points, regardless of the input order
[
KS86
,
Cha96
]

Thus, worst-case running times range between
\Theta(n\log n)
and
\Theta(n)
depending on the primary input part (i.e., the graph, partial order, or point set). It is reasonable to ask for some
interpolation
between these extremes.
A well-known result in that direction are the output-sensitive convex hull algorithms of Kirkpatrick–Seidel
[
KS86
]
and Chan
[
Cha96
]
, which take
\mathcal{O}(n\log h)

Universally optimal algorithms can be seen as a
best possible
such interpolation.

Universal optimality for data structures.

Recall the
Decremental Tree Minima
(DTM) problem defined above. We start with a vertex-weighted forest, we can delete an edge with
\textup{{delete-edge}}(u,v)
, and we can find the minimum-weight vertex in the tree containing a given vertex
v
with
\textup{{tree-min}}(v)
.
In the following, we call vertex weights
priorities
, to distinguish them from numerical weights. We assume priorities in the input forest are pairwise distinct and can only be accessed via comparisons.

When the input forest
G
has
n
vertices, then
\Theta(n)
DTM operations can be performed in
\mathcal{O}(n\log n)
time
[
GGT91
]
.
This is tight if
G
is a star where the central vertex has priority
\infty
. Indeed, in this case a DTM data structure can
sort
the leaf priorities with alternating
tree-min
queries and edge deletions, which requires
\Omega(n\log n)
. On the other hand, if
G
is path, then DTM can be solved with
\mathcal{O}(n)
time preprocessing and
\mathcal{O}(1)
time per operation (details are given in
section

2.3
).

We are thus in a similar situation as for the aforementioned algorithmic problems: The worst-case running time for
\Theta(n)
operations a fixed graph can be
\Theta(n\log n)
or
\Theta(n)
, depending on the graph (in fact, it can be anything in between).
However, it is not immediately obvious how to define universal optimality for data structures.
In particular, the restriction to
\Theta(n)
operations may not adequately capture the complexity of the problem.
On the other hand, if the number of operation is arbitrary, the worst-case total running time for any fixed graph is unbounded.

We hence use the following definition, which can be easily adapted to a wide range of dynamic graph problems (see below). We model a problem instance as a tuple
(G,p,\sigma)
, where
G
is the initial tree,
p
is the priority assignment and
\sigma
is the sequence of operations.
The primary input part for universal optimality is
(G,|\sigma|)
, i.e., the graph and the
number
of operations.
Note that
\sigma
is revealed one-by-one, and not even
|\sigma|
is known at the start.

More precisely, if
D
is a data structure for the DTM problem,
G
is a graph, and
m\in\mathbb{N}
, then
\mathbb{T}(D,G,m)
denotes the total time
D
requires for an input
(G,p,\sigma)
, in the worst case over all possible priority assignments
p
and all valid operation sequences
\sigma
with
|\sigma|=m
. We call
D
universally optimal when, for each
G
, each
m
, and each other data structure
D^{\prime}
, we have
\mathbb{T}(D,G,m)\leq c\cdot\mathbb{T}(D^{\prime},G,m)
for some globally fixed constant
c
.
Our main result is:

Theorem 1.1
.

There is a universally optimal data structure for the
Decremental Tree Minima
problem.

Alternative definitions.

Our definition is not the only reasonable interpretation of universal optimality. For the DTM problem specifically, one could require
tree-min
to run in constant time, and measure the total time for preprocessing plus the at most
n
edge deletions. This is in line with the idea of “maintaining” tree minima. However, our definition is stronger and more directly generalizes to other decremental graph problems.

Another definition may count each operation separately. For example, for DTM, we may consider pairs
m_{1},m_{2}\in\mathbb{N}
instead of a single value
m
, and take the worst case over all sequences of
m_{1}
edge deletions and
m_{2}

tree-min
queries.
Our data structure does not achieve this definition of universal optimality, but perhaps it could be adapted with some mechanism that postpones edge deletions until required.

For an even stronger definition, we could fix the whole sequence of operations, taking the worst case over only the input weights. An algorithm satisfying this definition would have to match the running time of an optimal
offline
algorithm, which is impossible for DTM, as is explained at the end of this section.
However, for a different problem where operations have weight parameters, the following definition could be interesting: Fix the operations and their vertex parameters, but not the weight parameters.

Cartesian trees on graphs.

Our second result is a universally optimal algorithm for computing a certain graph decomposition, using our
Decremental Tree Minima
data structure. We start with some definitions.
An

A priority assignment

In this paper, we give an algorithm for

Path minimum and bottleneck queries.

Suppose we are given a tree

Edge-weighted graphs.

All of our results generalize to a setting where priorities are given for
edges
instead of vertices. The
Decremental Tree Minima

Elimination trees also can be adapted as follows: An

An edge-priority assignment

again uniquely determines an EPT on the given graph

,

,

,

All these edge-weighted variants reduce to the corresponding vertex-weighted problem with the following reduction: Place a vertex “on” each edge, i.e., replace each edge with a path of length two. That vertex receives the priority of the original edge, and all original vertices are assigned priority

Since the number of newly introduced vertices is linear, worst-case optimality is maintained. We can also prove our universal optimality guarantees with some additional work.
In particular, our universally optimal algorithm for computing Cartesian EPTs strictly improves upon early

Semigroups.

Consider the following variation of the DTM problem, which we call
Decremental Semigroup Tree Sums
.
Instead of priorities, each vertex
v
is assigned a weight
w(v)
from some
commutative semigroup

(S,+,0)
.
Instead of
tree-min
queries, we need to answer queries
\textup{{tree-sum}}(v)
, which return the sum of the weights of all vertices in the same component as
v
.
Since the set of priorities under taking minima forms
a commutative semigroup, this is a strict generalization of the DTM problem.
It turns out that our data structure can be generalized to solve the this problem as well.

Theorem 1.5
.

There is a universally optimal data structure for the
Decremental Semigroup Tree Sums
problem.

It should be noted that the semigroup itself is neither given as part of the input nor is it fixed; rather, data structures for
Decremental Semigroup Tree Sums
are expected to work with arbitrary semigroups. That is, data structures may use the

operation and the neutral element

, and may assume that associativity, etc., hold. This is sometimes called the
semigroup model

[
Yao82
]
.

In the

, where subtraction is possible, our data structure still works, but is no longer universally optimal. Indeed, computing group
tree-sum
s on a star is possible in linear total time: Simply subtract
w(v)
from the total weight whenever deleting an edge to a leaf
v
.

1.1
Techniques

In this section, we briefly present the main ingredients of our universally optimal data structure for
Decremental Tree Minima
and the associated lower bound. For simplicity, we only assume the initial forest is a tree, the number of operations is linear in the number of vertices, and every edge is deleted eventually.

Figure 2:
A tree partitioned into chains and the corresponding compressed tree (top left), and the effect an edge deletion between or within super-nodes (right). Chains are light blue rectangles, and super-nodes are blue.

Dynamic trees with chain compression.

As mentioned above, classical dynamic tree data structures achieve a running time of
\mathcal{O}(\log n)
per operation, but for
paths
, we can achieve
\mathcal{O}(1)
time via range minimum queries. The first idea is to combine these two data structures. To do this, we partition the initial tree into induced paths (called
chains
), as shown in
fig.

2
. For each of the chains, we maintain the constant-time DTM data structure. We also maintain the tree obtained by contracting each chain into a single node (called a
super-node
), using a logarithmic-time DTM data structure
D
based on dynamic forests.

The priority of each super-node is always the minimum of the associated chain; thus, a tree minimum can always be found with
D.\textup{{tree-min}}
. An edge deletion may affect up to one of the constant-time DTM data structures, and either deletes an edge in
D
(see
fig.

2
, top right) or “splits” a super-node in
D
(see
fig.

2
, bottom right). The latter operation is not standard in dynamic forests, but easy to implement.

Observe that when the initial tree has
\ell
leaves, then it can be partitioned into
\mathcal{O}(\ell)
chains. Thus, the compressed tree stored in
D
initially has
\mathcal{O}(\ell)
super-nodes. While “splitting” can create new super-nodes, it can be shown that the number of super-nodes in a single tree in
D
cannot ever be more than
\mathcal{O}(\ell)
. This implies that every dynamic tree operation takes
\mathcal{O}(\log\ell)
time. Since the operations on the chain data structures only take constant time, the overall running time for
\mathcal{O}(n)
operations is
\mathcal{O}(n\log\ell)
. This is strictly better than
\Theta(n\log n)
for some initial trees, but not universally optimal.

Lower bound.

Before refining the data structure above, we describe our lower bound.
Recall that if the initial tree is a star, then we can sort the leaf priorities by repeatedly deleting the (edge to the) minimum-priority leaf. Actually, for any initial tree, we can sort its leaves this way, which implies a general
\Omega(\ell\log\ell)
lower bound.
Thus, for trees with
\Theta(n)
leaves, our previous algorithm is optimal. However, for some trees, neither the
\mathcal{O}(n\log\ell)
upper bound nor the
\Omega(\ell\log\ell)
lower bound is tight.

A tight lower bound can be obtained as follows. Make the initial tree
T
rooted by choosing an arbitrary root.
Suppose that for each node
v
in
T
, each ancestor of
v
has larger priority. This means that
tree-min
will always return a leaf. Thus, we can again sort the nodes in
T
by priority by repeatedly deleting the minimum-priority leaf. This is not
general
sorting, since the set of possible priority assignments is restricted by the condition above. Instead, we get a special case of the aforementioned
partial order sorting
problem. Taking
T
as the Hasse diagram of a partial order
P
, then the possible orderings respecting the above condition is the set
\mathcal{L}(P)
of linear extensions of
P
. By the information-theoretic lower bound, we need
\log|\mathcal{L}(P)|
comparisons to sort, so we have an
\Omega(\log|\mathcal{L}(P)|)
lower bound for
2n
DTM operations on
T
.

Matching the lower bound with splay trees.

Now, if we continue assuming that the minimum is always a leaf, then we can match the
\Omega(\log|\mathcal{L}(P)|)
bound using known results on partial order sorting. In particular the optimal algorithm of Haeupler et al.
[
HHI+24
]
, in our language, maintains the set of leaves in a special fast priority queue. It repeatedly extracts the minimum leaf from the priority queue, removes it from the tree, and then, if this makes another vertex a leaf, inserts that vertex into the priority queue.

For our data structure, we follow the same basic framework. However, we cannot use the same priority queue implementation: In the final data structure, general edge deletions will be allowed, which sometimes require
splitting
the set of leaves in a certain way. To support this, we instead use a
splay tree

[
ST85
]
that maintains the leaf set in left-to-right order, and supports finding the minimum as well as arbitrary splits.
7
7

7

A negative result for a related problem
[
HHR+24a
]
may seem to imply that splay trees are unsuitable for such a task; however, note that they only consider splay trees which keep nodes sorted by priority, which we avoid.
The analysis is very different.

Putting things together.

We now go back to the original algorithm using dynamic forests and chain compressions. We modify it as follows. The dynamic tree
D
is now no longer responsible for maintaining the priorities of the root and leaf super-nodes of the compressed forest; their priorities are permanently set to
\infty
in
D
. The leaf super-nodes of each tree are stored in a splay tree, and the root super-node priority is maintained explicitly for each tree. We can now find the minimum of a tree by checking (1) the root super-node, (2) the corresponding tree in
D
, and (3) the leaf splay tree.

The running time analysis very roughly goes as follows. We always explicitly update tree minima when deleting edges, so
tree-min
takes constant time. For edge deletions, we distinguish between three cases:
When we delete an edge within a root super-node, only that super-node needs to be updated, in constant time.
When we delete an edge within a leaf super-node, only the corresponding splay tree needs to be updated, in optimal amortized time by the above discussion.

The only remaining case are edge deletions within other super-nodes, or between super-nodes, which take (essentially)
\mathcal{O}(\log\ell)
amortized time to update
D
and to split a splay tree. However, it can be shown that such edge deletions only happen
\mathcal{O}(\ell)
times overall. Thus, the total time for these edge deletions is
\mathcal{O}(\ell\log\ell)
, which is accounted for by the basic
\Omega(\ell\log\ell)
leaf sorting lower bound.

Semigroups.

Most parts of our data structure generalize to the semigroup model without change. The only exception is the path-specific DTM implementation that uses range minimum queries. In fact, for the corresponding
semigroup range query
problem, a super-linear lower bound is known
[
Yao82
]
.

However, with a different data structure based on previous work by Gajewska and Tarjan
[
GT86
]
and Weiss
[
Wei94
]
, we can still solve the
Decremental Semigroup Tree Sums
problem in linear time on paths. With this, we can generalize our main data structure to semigroup sums.

Cartesian trees and path-minimum queries.

We discussed above how to compute Cartesian trees using a DTM data structure. To prove this algorithm is universally optimal, we give an estimate of the information-theoretic lower bound, which again is based on partial order sorting.

For path-minimum queries, recall that we claimed that using a Cartesian tree together with an LCA data structure has universally optimal preprocessing time if no comparisons are allowed in
path-min
queries. To prove this, we show that a Cartesian tree can be constructed using only
path-min
queries. Although the number of queries needed is quite large, this shows that any
Path Minima
data structure can be used to compute an elimination tree. If that data structure performs no comparisons in
path-min
queries, all comparisons necessary to compute the elimination tree must occur in preprocessing, and thus our information-theoretic lower bound applies.

1.2
Conclusions

We defined universal optimality for data structures, and gave a universally optimal data structure for
Decremental Tree Minima
.
Our definition could be applied to other data structure problems, not necessarily restricted to dynamic weighted graphs. In particular, any problem where both “easy” special cases and tight worst-case bounds are known could be a good candidate for universal optimality.
Our techniques for
Decremental Tree Minima
are robust enough to allow replacing vertex weights with edge weights, and generalize tree minima queries to arbitrary semigroup tree sum queries.

We applied our data structures to obtain a universally optimal algorithm to compute Cartesian trees. An interesting generalization is
weighted centroid trees
. Here, a vertex-weighted tree
(G,w)
is given, and we need to construct the elimination tree on
G
where the root of every subtree is the
centroid
of the respective subgraph
H
of
G
. A vertex
v
is a centroid of
H
if removing
v
splits
H
into components whose weight is at most half the total weight of
H

[
KH79
,
BGKK23
]
.

The special case where all weights are distinct powers of two is equivalent to Cartesian trees; thus, our lower bounds hold. However, our approach does not work for centroid trees; essentially, the problem of computing centroids does not decompose as nicely as the problem of computing minima. We leave open the question whether there exists a universally optimal algorithm for computing weighted centroid trees.

We used Cartesian trees to give a
static
data structure for
Path Minima
, with a restricted universal optimality guarantee, which holds only if all
path-min
queries perform zero comparisons. If comparisons in
path-min
queries are allowed, an inverse-Ackermann tradeoff between preprocessing and query time is possible and optimal
[
Cha87
,
Pet06
]
. Since
Path Minima
on
paths
(i.e., the
range minimum queries
problem) can be solved with linear preprocessing and constant query time, this is another candidate for universal optimality.

As a final note, observe this paper and several recent results
[
HHR+24a
,
HHI+25
,
Ber25
]
use
adaptive data structures
(splay trees here and working-set heaps in the other references). In this context, adaptivity means that these data structures are able to exploit certain
sequential patterns
in access sequences. These results suggest that they are also useful to exploit the input graph structure, i.e., the
topology
of an input.

Dynamic and semi-dynamic graph data structures.

A
dynamic graph data structure
maintains a changing graph, e.g., under edge insertions and deletions, while maintaining certain properties of the graph or allowing certain queries.

The special case of
forests

In another related paper, Brodal, Davoodi, and Rao

In the introduction, we defined generalizations of Cartesian trees to vertex-weighted and edge-weighted graphs. In particular the edge-weighted version (

The (vertex-weighted)

ZM94

Further results related to universal optimality.

There are several more results that predate the term

Definition 2.1

Let

The operation

Observe that

Lemma 2.2
.

Let

For the second bound, observe that the number of non-root-non-leaf nodes is at most

∎

Priorities.

In this paper,
\mathfrak{P}
denotes some totally ordered universe of
priorities
. We assume priorities can be compared in constant time, but not accessed otherwise (see below). Our algorithms may internally use a special priority
\infty
that is larger than all other priorities given in the input. A

maps a set of elements (usually the vertices of a graph) to
distinct
priorities.

Machine model.

We assume the standard Word RAM model with logarithmic word size and the usual modification for comparison-based algorithms, specified in the following. Priorities are not given explicitly. Instead, our algorithms have access to an oracle that answers queries of the form
p(v)<p(u)
, where
u
and
v
are vertices in the input graph (represented as integers), and
p
denotes the input priority function.
Whenever an algorithm “stores” a priority somewhere, it really stores the
node
with that priority. The special priority
\infty
is stored as a special integer, and comparisons with it are resolved without calling the oracle.

Lemma 2.5

There is a data structure for

Proof.

A basic lower bound via tree sorting

The main idea, reducing from partial order sorting, was already presented in the introduction. We start here by defining our special case of the partial order sorting problem.
Given a rooted tree

Definition 3.1

In the

Let

Observe that
\mathcal{L}(T)
is the set of linear extensions of the partial order with Hasse diagram
T
.
Also,
\mathcal{L}(T)
is precisely the set of possible outputs of the
Tree Sorting
problem on the tree
T
. Since we can only distinguish between different outputs with comparisons, the information-theoretic lower bound yields:

Observation 3.2
.

Fix a rooted tree
T
. Then, for every
Tree Sorting
algorithm
A
, there exists a priority function
p
such that
A
requires at least
\log|\mathcal{L}(T)|
comparisons on input
(T,p)
.

It turns out that
\mathcal{L}(T)
is characterized a simple formula. For a rooted tree
T
on
n
nodes, define the
tree entropy
of
T
as

H(T)=\sum_{v\in V(T)}\log\tfrac{n}{|T_{v}|}.

Lemma 3.3

(Knuth
[
Knu98
, Exercise 5.4.1.20]
)
.

Let
T
be a rooted tree on
n
nodes. Then

|\mathcal{L}(T)|=|T|!\cdot\prod_{v\in V(T)}\frac{1}{|T_{v}|},

implying that
\log|\mathcal{L}(T)|\geq H(T)-n\log e
.

The formula in
lemma

3.3
is known in the literature as
Knuth’s hook-length formula
.
We prove a generalization of
lemma

3.3
in
section

5
(
lemma

5.12
).

We now turn back to the DTM problem.
Suppose we have a DTM data structure
X
and are given an input
(T,p)
for
Tree Sorting
. Find the root
r
of
T
, initialize
X
with
(T,p)
, then repeatedly call
v\leftarrow X.\textup{{tree-min}}(r)
and
X.\textup{{cut}}(v)
, until all edges are deleted. Since
p
is
T
-monotone, each node returned by
tree-min
is a leaf, and the sequence of outputs of
tree-min
is precisely
V(T)
in sorted order.

Thus, a DTM data structure can solve
Tree Sorting
with a sequence of
2n-2
operations, so the
\log|\mathcal{L}(T)|\geq H(T)-n\log e
lower bound applies. We also have a trivial
\Omega(n)
bound, if the first operation is
tree-min
. Therefore, we obtain:

Corollary 3.4
.

For each DTM data structure
X
and each rooted tree
T
with
n\geq 2
nodes, there exists a priority function
p
on
T
and a sequence
\sigma
of
2n-2
operations such that
\mathbb{T}(X,T,p,\sigma)\geq\Omega(H(T))
.

In the next section, our goal will be to give a data structure that matches
corollary

3.4
(which, as mentioned, is not quite enough for our definition of universal optimality). The following simple lower bounds will be useful:

Lemma 3.5
.

Let
T
be a rooted tree with
n
nodes and
\ell
leaves. Then
H(T)\geq\ell\log n
and
H(T)\geq n-1
.

Proof.

Observe that for each leaf
v
, we have
|S_{v}|=1
, so
\log\tfrac{n}{|S_{v}|}=\log n
. Summing up only the contribution of the leaves to
H(T)
, we get
\ell\log n
, as required.

We prove the second inequality by induction. if
n=1
, then
H(T)=0=n-1
. Now suppose
n\geq 2
, and let
T^{1},T^{2},\dots,T^{k}
be the trees obtained by removing the root from
T
. Observe that
T^{i}_{v}=T_{v}
for each
v\in V(T_{i})
, and let
n_{i}=|T^{i}|
.
With this, we have

\displaystyle H(T)=\sum_{v\in V(T)}\log\tfrac{n}{|T_{v}|}=\sum_{i=1}^{k}\sum_{v\in V(T^{i})}\log\left(\tfrac{n}{n_{i}}\cdot\tfrac{n_{i}}{|T^{i}_{v}|}\right)=\sum_{i=1}^{k}n_{i}\log\tfrac{n}{n_{i}}+H(T^{i}).

Since
n_{i}\leq n-1
, we have
n^{n_{i}}\geq(n_{i}+1)^{n_{i}}
. It is easy to check that
(n_{i}+1)^{n_{i}}\geq 2n_{i}^{n_{i}}
by the binomial theorem, so
n_{i}\log\tfrac{n}{n_{i}}\geq 1
. The statement follows by induction.
∎

4
Step-by-step towards universal optimality

In this section, we present our data structure for
Decremental Tree Minima
.
For now, we will prove optimal running time for every initial tree
T
, for a worst-case sequence of operations of length at least
2|V(T)|-2
(matching
corollary

3.4
).
We start with a relatively naive attempt, and then gradually improve our algorithm.
The full proof of universal optimality (for an arbitrary number of operations) is given in
section

.

4.1
An
\mathcal{O}(n\log n)
algorithm with dynamic forests

A
dynamic forest
data structure
[
ST83
,
ST85
,
AHDLT05
]
maintains a rooted forest and some associated data along with edge insertion and deletion.
We use the following specification.
Note that for our
\mathcal{O}(n\log n)

Decremental Tree Minima
data structure, we only need the operations

and

, and only need
\mathcal{O}(\log n)
amortized upper bounds for their running time. The operations

and

will be useful later.

Definition 4.1
.

A
dynamic forest data structure
represents a rooted forest
F
with vertex priorities
p\colon V(F)\rightarrow\mathfrak{P}
. It supports the operations listed below.

•

D.\textup{{find-min}}()\rightarrow v
returns the node
v
with minimum priority.

•

D.\textup{{cut}}(v)
removes the edge between
v
and its parent (see
definition

2.1
).

•

D.\textup{{set-priority}}(v,q)
sets
p(v)\leftarrow q
.

•

D.\textup{{split}}(v)\rightarrow(u_{1},u_{2})
splits

into two new nodes (see
definition

2.1
). The priorities of the two new nodes

and
u_{2}
are initialized as

.

Lemma 4.2
.

There is a dynamic forest data structure such that:

•

Initialization takes
\mathcal{O}(n)
time, where
n
is the number of nodes in the given initial forest;

•

find-min
takes
\mathcal{O}(1)
time;

•

\textup{{split}}(v)
takes
\mathcal{O}(1)
time when
v
is a root or a leaf;

•

split
in every other case, as well as
cut
and
set-priority
, all take
\mathcal{O}(1+\log n)
time, where
n
is the number of nodes in the tree containing the affected nodes.

All running times are amortized.

Proof.

All operations besides
split
can be implemented in
\mathcal{O}(\log n)
amortized time by standard solutions
[
ST83
,
ST85
,
GGT91
]
. Suppose we have such a data structure
X
, which also supports the operation
X.\textup{{link}}(u,v)
that makes
u
a child of
v
.

We can implement
\textup{{split}}(v)
by first calling
X.\textup{{cut}}(v)
, then adding a new child
u_{1}
to the former parent of
v
using
X.\textup{{link}}(u_{1},v)
. Then, we set the priority of
u_{1}
to
p(v)
and finally return
(u_{1},v)
. This yields the required running time of
\mathcal{O}(\log n)
in the general case.

To implement

in
\mathcal{O}(1)
time, we store the minimum value of each component
S
of
F
explicitly in the root
r
of
S
, as a value
q_{r}
. We maintain a
Decremental Tree Roots
data structure on
F
to access

. Whenever we need to update

, we compute it with the standard
\mathcal{O}(\log n)
-time
find-min
operation of
X
. This happens at most twice after each
cut
or
split
, so we stay within the
\mathcal{O}(\log n)
budget.

Finally, we describe how to perform
split
in
\mathcal{O}(1)
time for roots and leaves. Suppose
v
is a leaf. For
\textup{{split}}(v)
we create a new, disconnected vertex

with priority
p(v)
, and return
(v,u_{2})
. This requires only calling
\textup{{set-priority}}(u_{2},p(v))
, which takes
\mathcal{O}(1)
time since

is an isolated vertex.
Moreover, the only newly created root is
u_{2}
, we clearly have
q_{u_{2}}=p(v)
, and

does not need updating for any other root

.

If
v
is a root, we proceed similarly.
∎

Lemma

4.2
implies that, starting with a tree with
n
nodes, we can perform
m
DTM operations in
\mathcal{O}(m\log n+n)
time.

4.2
Chain compression

In this section, we give an improved data structure with
\mathcal{O}(\log\ell)
running time per operation, where
\ell
is the number of leaves in the input forest
F
. The main idea is that since we can solve the DTM problem efficiently on

, and solve the problem separately on them.

Let

be a rooted forest. A

in

is a sequence

such that for each

is
v_{i+1}
. Note that
v_{k}
may have an arbitrary number of children. The
top node
of the chain is
v_{1}
, and the
bottom node
is
v_{k}
.
Contracting

yields a new rooted forest
F^{\prime}
, where
C
is replaced by a single node
x
, such that the parent of
x
in
F^{\prime}
is the parent of
v_{1}
in
F
(if it exists), and the children of
x
in
F^{\prime}
are the children of
v_{k}
in
F
.

Original forest
F

Compressed forest
F^{\prime}

Chain forest
F_{C}

Let

be a rooted forest obtained from

by contracting a pairwise disjoint set of chains that covers the whole forest (see
fig.

4
). For each

, let

be the chain in

that produced

(observe that

may consist of only one node). If

is a vertex priority function for

, then we define

as

. Together, the tuple
(F^{\prime},p^{\prime},C)
is called a

of

. In the following, we call the nodes of a compression

. We will sometimes use chains and super-nodes interchangably when there is no danger of confusion, e.g., we may say for

” or “

and roots in

.

It will also be useful to consider the collection of chains as a rooted forest, where each tree is a chain

. We denote this

by

(see

The key idea for our improved data structure is that if we contract all

\mathcal{O}(\log\ell)

Maintaining a compression.

We´ now show how to maintain the structure of a compression under edge deletions, disregarding priorities. Define an
unweighted compression

(F^{\prime},C)

We refer to this operation on

or

in

.
We now give a data structure maintaining an unweighted compression and some useful additional data.

Lemma 4.3
.

There is a data structure that maintains an unweighted compression

\mathcal{O}(n)

in

. Moreover, the data structure maintains the following auxiliary structures:

•

An explicit representation of

•

A constant-time mapping from each node

•

A constant-time mapping from each node

•

A constant-time mapping from each super-node

Proof.

In addition to the explicit representations of

One, denoted

, on

, and one, denoted

is the forest of all chains

Moreover, we explicitly maintain a pointer

Now we can find the super-node containing a given node

and

Suppose we call
\textup{{cut}}(v)
, and say

To update

Suppose now

is the parent of

Tree minima with chain compression.

We now describe our improved data structure for the DTM problem. An instance maintains a compression
(F^{\prime},p^{\prime},C)
on
(F,p)
. At the start, the compression is obtained by contracting all maximal chains in the initial tree
T^{0}
.

We maintain
F
and
(F^{\prime},C)
in an instance

of the auxiliary structure of

4.3
, and additionally:

•

A dynamic forest
D
for
(F^{\prime},p^{\prime})
.

•

A Path-DTM data structure

for

, using
corollary

.

Observe that, given an input
(F,p)
, we can initialize the data structure in linear time.
We now show how to implement the two DTM operations. Let
X
denote an instance of our data structure.
For
X.\textup{{tree-min}}(v)
, we simply defer to
D.\textup{{tree-min}}(x)
, where
x
is the super-node that contains
v
. This returns the correct answer because, for every component of
F
and its associated component of

, we have
\min_{x\in V(F^{\prime})}p^{\prime}(x)=\min_{v\in V(F)}p(v)
.

Consider now a call
X.\textup{{cut}}(v)
, when
u
is the parent of
v
in
F
.
Perform
\textup{{cut}}(v)
in

, thereby identifying the corresponding canonical

or

in
F^{\prime}
. We perform the respective operation in

. Also, if
v
and its parent

are in the same chain (i.e., if the canonical operation is a

), we call

. Otherwise,

does not change, so

does not need to be updated.

It remains to update the priorities of super-nodes in
D
. This is only necessary if the canonical operation is a

, since otherwise no super-nodes are changed.
Let
y_{1}
be the super-node containing
u
, and let
y_{2}
be the super-node containing
v
, after the operation (see
fig.

5
, right). We update their priorities with
D.\textup{{set-priority}}(y_{1},R.\textup{{tree-min}}(u))
and

. Since now

and

are the two parts of the previous chain

that contain

and

, respectively, this correctly assigns the new priorities

and

.
Observe that every other super-node

Running time analysis.

Initializing each data structure needs
\mathcal{O}(n)
time, and the running time of
tree-min
is clearly constant.
In
\textup{{cut}}(v)
, the only non-constant operations are the dynamic tree operations, so the running time is
\mathcal{O}(\log n^{\prime})
, where
n^{\prime}
is the number of super-nodes in the component
S^{\prime}
of
F
containing
x
. We now show that
n^{\prime}\leq 2\ell-1
, where
\ell
is the number of leaves in the
initial
forest.

As we have argued before, since we contract all maximal chains, every inner node in the initial super-forest

has two children, implying that
|F^{\prime}|\leq 2\ell-1
. This implies in particular that
|E(F^{\prime})|\leq 2\ell-2
. Observe that
cut
s and
split
s cannot
increase
the number of edges. Thus, the compression never has more than
2\ell-2
edges, implying that each of its components has no more than
2\ell-1
vertices.
With this, we have:

Proposition 4.4
.

The
Decremental Tree Minima
problem can be solved with linear-time preprocessing, constant worst-case time per
tree-min
, and
\mathcal{O}(\log\ell)
amortized time per
cut
, where
\ell
is the number of leaves of the initial forest
F
.

Unfortunately,
proposition

4.4
does not imply universal optimality, even in the restricted case of
\Theta(n)
operations. Indeed, consider the input tree
T
where the root
r
has
k+1
child subtrees, one being a chain of

nodes, and each other consisting of a single node (see
fig.

6
). It is easy to check that the lower bound given by
corollary

3.4
is
\Theta(n+k\log k)
. Thus, if

, the lower bound is linear, but the upper bound from
proposition

4.4
is
\Theta(n\log\ell)=\Theta(n\log k)=\Theta(n\log n)
.

4.4
is not optimal.

A more thorough analysis reveals that the problem lies with modifications of the
super-roots
and
super-leaves
. Consider an operation
\textup{{cut}}(v)
, and call it
type 1
if both
v
and its parent
u
are both contained in a single super-leaf or super-root. Otherwise, call it
type 2
. For each type-2 operation, the corresponding canonical super-forest operation is either a
cut
, or a
split
of a non-root-non-leaf super-node. By
lemma

2.2
, there can be at most linearly many such operations. Since the super-forest has
\mathcal{O}(\ell)
nodes, and each operation takes at most
\mathcal{O}(\log\ell)
time by the analysis above, the total time of type-2 operations is
\mathcal{O}(\ell\log\ell)
, which is within our budget (see
lemma

3.5
).

For type-1 operations, we need a different approach.
It turns out that we can handle
split
s of
super-roots
without much effort, with constant time per operation. We now sketch the solution as a warm-up. More details and the solution for super-leaves are presented in
section

.

The idea is to simply
not
store the priority for super-roots in
D
. This means setting the priority of every super-root in
D
to
\infty
.
Observe that we can still compute
X.\textup{{tree-min}}(v)
: First, if
x
is the super-node containing
v
, then
D.\textup{{tree-min}}(x)
will return the minimum node in the component
S
containing
x
, among all nodes that are
not
in the “root chain”.
Using the auxiliary data structure, we can compute the root node
r
of the component containing
v
. Then
R.\textup{{tree-min}}(r)
is the minimum node within the root chain. Thus,
X.\textup{{tree-min}}(v)=\min(D.\textup{{tree-min}}(x),R.\textup{{tree-min}}(r))
.

We can ensure that each root super-node has priority
\infty
in
D
by simply calling
D.\textup{{set-priority}}
whenever a
cut
or a type-2
split
occurs. This requires
\mathcal{O}(\log\ell)
time, which is subsumed by the other dynamic tree operations.

Finally, we argue that
X.\textup{{cut}}(u)
only needs constant time if
u
is in a root chain

. First, observe that
D.\textup{{split}}(x)
only takes constant time by
lemma

4.2
. Second, the two returned super-nodes

and
y_{2}
are both super-roots, and

initializes them with priority
p(x)=\infty
. Thus, no priority updates are necessary.

4.3
Leaf handling with splay trees

To deal with leaves, we need to finally consider the details of our lower bound in
corollary

3.4
. We first describe the solution informally. As we did with root nodes, we now relieve the dynamic tree
D
of the duty of maintaining super-leaf priorities and set all of them to
\infty
. Like we argued for super-roots, this means that, for
D
,
split
ting super-leafs costs only constant time, while
cut
s and
split
s of non-leaf non-root nodes still costs
\mathcal{O}(\log\ell)
time. By
lemma

2.2
, the latter can happen at most
\mathcal{O}(\ell)
times. For our
\Theta(n)
operations, the total running time for
cut
s and
split
s is thus
\mathcal{O}(n+\ell\log\ell)
, which is within the required bound (
lemma

3.5
).

The problem are now the
tree-min
operations. The reason root nodes are easy to handle is that there is only one root per component in
F
; obviously, this is not the case for leaves. To handle super-leaves, we use a data structure based on
splay trees

[
ST85
]
that maintains an ordered sequence of super-leaves for each component in
F
. The running time analysis uses a potential argument based on the
access lemma

[
ST85
]
to match
corollary

3.4
.

We now proceed with describing the data structure. We begin with some technical details on how to maintain an
ordered
forest. Then, we describe two new sub-structures, and finally put everything together and analyze the running time.

Ordered forests and compressions.

From now on, we assume that for each node of
F
, its children are ordered in a fixed, but arbitrary way. We call
F
an
ordered
forest. This induces an ordering on the leaves of each component
T
of
F
, which will be useful later. A sub-forest
S
inherits the ordering in the obvious way, and so does a compression of
F
or
S
.

When maintaining an explicit representation of an ordered forest

4.3.1
Maintaining leaf sequences

We now describe our data structure responsible for maintaining leaf priorities. Essentially, the sequence of super-leaves of

is maintained in a

[

Note that

We proceed with the specification of our data structure. For technical reasons, we describe it differently than the other data structures in this paper. Instead of maintaining each leaf sequence of each component of

Lemma 4.6
.

Let

be a universe equipped with a priority function
p\colon U\rightarrow\mathfrak{P}
and a weight function

. Assume the

over

•

\mathcal{O}(n+W)
for preprocessing, when initialized with

•

\mathcal{O}(1)

•

\mathcal{O}(\log\tfrac{W}{w(x)})
for

We now review splay trees, which are the base for our implementation of SSM.
Originally
[
ST85
]
, splay trees were presented as an implementation of
ordered dictionaries
. They maintain an ordered list of
n
keys, or key-value pairs, in a binary search tree (BST).
As usual, the keys are stored in the tree in
symmetric order
, that is, an in-order traversal of the BST visits the keys in the same order as they appear in the maintained list.

Other standard BST data structures, such as AVL trees
[
AVL62
]
,
keep the height of the BST at
\mathcal{O}(\log n)
, to ensure
\mathcal{O}(\log n)
worst-case search time.
In contrast, splay trees do not provide such a guarantee. Instead, after every search, they
rebalance
themselves in order to speed up future searches. While only an
amortized

\mathcal{O}(\log n)
running time per search is ensured by splay trees, they have the upside of a simple implementation without additional bookkeeping, and also can be shown to perform
better
then
\mathcal{O}(\log n)
per operation when the search sequence has a certain structure.

The central operation for splay trees is the eponymous
\texttt{splay}(x)
, which moves a node
x
to the root of the splay tree through a sequence of
rotations
. It is performed after every search, where
x
is the found node.
splay
is also useful to implement insertion and deletion of keys. For definitions of rotations and the
splay
operation, we refer to Sleator and Tarjan
[
ST85
]
. For us, the only important detail is the rotations (and thus
splay
) do not change the symmetric order of the nodes.

Here, we use splay trees in a different way; we never need to search for keys, but instead use it as a dynamic decomposition of a sequence as in
definition

4.5
. The nodes will maintain minima of contiguous subsequences, and
splay
will be useful to implement the operations
replace
and
split-interval
. There are other examples of a similar “structural” use of splay trees, most prominently the dynamic forest data structure of Sleator and Tarjan
[
ST83
,
ST85
]
.

Here, we consider a splay tree to be a binary tree
T
with three allowed operations:

•

\textup{{splay}}(x)
, which brings
x
to the root of
T
with a series of rotations. The exact way this is done is not relevant here, see
[
ST85
]
for details.

•

Attach the root
r^{\prime}
of another splay tree
T^{\prime}
as a left or right child to the root
r
of
T
.

•

Detach a child from the root
r
of
T
, producing a new splay tree.

Analysis of splay trees.

For the analysis of our data structure, we will consider a
set
of splay trees, called a
splay forest
. Each node
x
comes from a universe
U
as in
lemma

4.6
, and thus has an associated weight
w(x)\in\mathbb{N}_{+}
. The weight of a subtree
T_{x}
, denoted
w(T_{x})
, is the sum of weights of its nodes, i.e.,
w(T_{x})=\sum_{y\in V(T_{x})}w(y)
. The
rank
of a node is
r(x)=\log w(T_{x})
, and the
potential
of a splay tree
T
is
\Phi(T)=\sum_{x\in V(T)}r(x)
. The potential of a splay forest is the sum of the splay tree potentials.

Consider a call to
\textup{{splay}}(x)
that changes the splay tree containing
x
from
T
to
T^{\prime}
. The
amortized running time
of
\textup{{splay}}(x)
is the actual running time plus the potential change
\Phi(T^{\prime})-\Phi(T)
.
Sleator and Tarjan’s well-known
access lemma

[
ST85
, lemma 1]
states that the amortized running time is
\mathcal{O}(1+\log\frac{W}{w(x)})
, where
W
is the sum of weights of all tree nodes.
11
11

11

The potential needs to be scaled by a constant factor depending on the actual running time of a single
rotation
; we omit this detail for simplicity.

The overall running time of a sequence of
splay
operations is then at most the total amortized running time plus the potential
\Phi(F_{0})
of the initial splay forest
F_{0}
.

As mentioned above, we can also attach a root node as a child to another node, and detach a child from its parent. Both these operations change the potential. We will take this into account when analyzing the amortized running time of the SSM operations.

Implementing SSM.

An instance of our SSM implementation consists of a single splay tree
T
, containing the elements (keys)
x_{1},x_{2},\dots,x_{n}\in U
in symmetric order. We assume that we can find the predecessor
x_{i-1}
and the successor
x_{i+1}
of an element
x_{i}
in constant time (should either exist). This can be accomplished by explicitly maintaining pointers within
T
.

For each node
x\in V(T)
, we additionally maintain the minimum priority
q_{x}
of all nodes in
T_{x}
, i.e.:

q_{x}=\min_{y\in V(T_{x})}p(y).

Whenever we perform a rotation, attach a child to the root, or detach a child from the root, we only need to recompute
q_{x}
for at most two nodes. Clearly,
q_{x}
can be recomputed from the values
q_{y}
of its children in constant time. Thus, the time to update
q_{x}
is dominated by other operations, and will be ignored from now on.

We now proceed with the implementation and running time analysis of each SSM operation. In the following,
W
denotes the sum of all node weights before the operation, and

denotes the sum of all node weights after the operation, in all produced trees.

•

, the total potential of any tree can be upper bounded by

.
However, when starting with a

\mathcal{O}(W^{\prime})
.
12
12

12

Recall that we assume that all weights are at least one. Sleator and Tarjan

We defer the proof to

Computing each

•

of the root

•

•

4.3.2
Maintaining leftmost and rightmost leaves

When performing a

Definition 4.7
.

An
Extremal Leaves

under the operations

and

•

\textup{{extremal-leaves}}(v)\rightarrow(u_{1},u_{2})

u_{1}

.

Lemma 4.8

An

\mathcal{O}(n)

\mathcal{O}(1)
amortized running time for

\mathcal{O}(\log n)

Proof.

We show how to maintain

via a left-to-right post-order traversal, in linear time (see

9

More precisely, for two nodes

if and only if either

is a descendant of
v

is the lowest common ancestor of

and

T_{c}
of

containing

is to the left of the child subtree

of

We maintain nodes and their labels in a dynamic forest data structure

5
Universal optimality for short sequences

In this section, we extend

and

to prove full universal optimality of our data structure, including for operation sequences of length

. Note that no changes to the data structure are necessary; only the analysis needs to be refined.

We first quantify the optimal running time, then prove our data structure matches it (
section

5.1
), and finally prove that it is a lower bound for all data structures (
section

5.2
). We need the following generalizations of the

defined in

.

Let
T
be a rooted tree and
S\subseteq V(T)
. Then we define

H_{S}(T)=\sum_{v\in S}\log\frac{|S|}{|V(T_{v})\cap S|}.

Further, for
k\in\mathbb{N}_{+}
, we define

H_{k}(T)=\max_{\begin{subarray}{c}S\subseteq V(T)\\
|S|\leq k\end{subarray}}H_{S}(T).

Observe that for

, we have
H_{k}(T)=H_{V(T)}(T)=H(T)
.
We now prove a few useful properties of

.

Lemma 5.1
.

Let
T
be a rooted tree with
n\geq 2
nodes and
\ell
leaves, and let
k\in\mathbb{N}_{+}
.
Then
H_{k}(T)+n\geq\tfrac{1}{3}\min\{k,\ell\}\log n
.

Proof.

Let
m=\min\{k,\ell\}
, let
S^{\prime}
be a set of
m
leaves of
T
, and let
S
be an arbitrary vertex set of size
k
with
S^{\prime}\subseteq S\subseteq V(T)
. Observe that

H_{k}(T)\geq H_{S}(T)\geq H_{S^{\prime}}(T)=m\log m.

Our claim holds trivially when
m\leq n/\log n
. If
m\geq n/\log n
, then
H_{k}(T)\geq m\log m\geq m(\log n-\log\log n)\geq\tfrac{1}{3}m\log n
, as desired.
∎

Lemma 5.2
.

Let
T
be a rooted tree, and let
S\subseteq V(T)
be closed under taking descendants. Then
H_{S}(T)=\sum_{v\in S}\log\tfrac{|S|}{|T_{v}|}
.

Proof.

For each
v\in S
, we have
V(T_{v})\subseteq S
by assumption; the statement then follows by definition of
H_{S}(T)
.
∎

Lemma 5.3
.

Let
T
be a rooted tree and
k\in\mathbb{N}_{+}
. Then there exists a set
S\subseteq V(T)
of size at most
k
that is closed under taking descendants and satisfies
H_{k}(T)=H_{S}(T)
.

Proof.

Let
S\subseteq V(T)
with
|S|\leq k
and
H_{k}(T)=H_{S}(T)
. We claim that, if some
u\in S
has a child
v\notin S
, we have
H_{S}(T)\leq H_{S^{\prime}}(T)
for
S^{\prime}=S\setminus\{u\}\cup\{v\}
. Thus, repeatedly replacing
u
with
v
will eventually yield a set that satisfies the lemma.

Towards our claim, observe that we have
|V(T_{w})\cap S|=|V(T_{w})\cap S^{\prime}|
for all

. Thus,

H_{S^{\prime}}(T)-H_{S}(T)=\log\frac{k}{|V(T_{v})\cap S^{\prime}|}-\log\frac{k}{|V(T_{u})\cap S|}.

It is easy to see that
|V(T_{v})\cap S^{\prime}|\leq|V(T_{u})\cap S|
, which implies
H_{S^{\prime}}(T)-H_{S}(T)\geq 0
, proving our claim.
∎

Corollary 5.4
.

For
k\leq|T|
,

holds even when requiring that

has size exactly
k
.

Proof.

Suppose that

5.3
yields a set

of size

with

. Since
S
is closed under taking descendants and
|S|<k\leq n
, the root

of

is not contained in
S
. Consider now the set
S^{\prime}=S\cup\{r\}
. We have

\displaystyle H_{S^{\prime}}(T)=\sum_{v\in S^{\prime}}\log\frac{|S^{\prime}|}{V(T_{v})\cap S^{\prime}}

\displaystyle=\log\frac{|S^{\prime}|}{V(T_{r})\cap S^{\prime}}+\sum_{v\in S}\log\frac{|S^{\prime}|}{V(T_{v})\cap S^{\prime}}

\displaystyle=\log\frac{\ell+1}{\ell+1}+\sum_{v\in S}\log\frac{\ell+1}{V(T_{v})\cap S}>H_{S}(T).

This implies
H_{S}(T)<H_{k}(T)
, a contradiction.
∎

Lemma 5.5
.

Let
T
be a rooted tree and
k\leq k^{\prime}
be positive integers. Then

\tfrac{k}{k^{\prime}}H_{k^{\prime}}(T)-k\log\tfrac{k^{\prime}}{k}\leq H_{k}(T)\leq H_{k^{\prime}}(T).

Proof.

The second inequality holds by definition. For the first inequality, let
S^{\prime}\subseteq V(T)
be a node set with
H_{S^{\prime}}(T)=H_{k^{\prime}}(T)
. By

, we can assume that

and

is closed under taking descendants.
Now construct

by removing from

the

such that

\sum_{u\in S^{\prime}}\log\tfrac{k}{|T_{u}|}\leq\tfrac{k^{\prime}}{k}\sum_{u\in S}\log\tfrac{k}{|T_{u}|}=\tfrac{k^{\prime}}{k}H_{S}(T).

Clearly,

is also closed under taking descendants. Again using

, we have:

\displaystyle H_{k^{\prime}}(T)=H_{S^{\prime}}(T)=\sum_{u\in S^{\prime}}\log\tfrac{k^{\prime}}{|T_{u}|}\leq\sum_{u\in S^{\prime}}\log\left(\tfrac{k^{\prime}}{k}\cdot\tfrac{k}{|T_{u}|}\right)

\displaystyle=k^{\prime}\log\tfrac{k^{\prime}}{k}+\sum_{u\in S^{\prime}}\log\tfrac{k}{|T_{u}|}

\displaystyle\leq k^{\prime}\log\tfrac{k^{\prime}}{k}+\tfrac{k^{\prime}}{k}H_{S}(T).

The first inequality of the lemma follows immediately.

In this section, we show how to compute Cartesian trees and use them to implement a

Recall DTM-based algorithm described in the introduction. Take an arbitrary rooting

Semigroup sums

In this section, we show:

Recall that the input is now a a vertex-weighted tree
(T,w)

, and we need to answer the query

Most of our data structure can be used as-is, with the only change being changing

to

•

The dynamic tree

maintains the minimum super-node.
We can easily maintain the sum of all super-node weights instead.

•

In our splay-tree-based
Splittable Sequence Minima
data structure, each node

in the splay tree

maintains the minimum priority
q_{x}
of
T_{x}
. We can instead maintain the sum of weights in
T_{x}
, and easily update it for each relevant binary tree operation (rotation, attaching to the root, detaching from the root).
The crucial observation here is that a sum
q_{x}
can be recomputed from the weight of
x
and the sums of its (up to two) children.

•

In contrast, the path-DTM data structures for each chain depend on certain properties of the minimum function and need to be entirely replaced; see below.

•

Finally, to answer
tree-min
queries, we compute the minimum of three values; instead, we can simply take their sum.

It remains to show how to solve
Decremental Semigroup Tree Sums
on a path. As mentioned in the introduction, a sufficiently fast
semigroup range query
data structure does not exist. However, we can instead directly solve the problem, with linear preprocessing time and constant query time.

Our data structure is based on an algorithm of Weiss
[
Wei94
]
for constructing
Cartesian trees
on paths in linear time. While a much simpler algorithm for this task exists
[
GBT84
]
, Weiss’s approach is still useful to us.

Lemma 7.1
.

There is a data structure for the
Decremental Semigroup Tree Sums
problem on paths with linear preprocessing time and constant query time.

Proof sketch.

Weiss’s algorithm for Cartesian trees works as follows: Identify the minimum vertex of the path, make it the root of the Cartesian tree, remove it, and then recurse on the (up to) two remaining paths.
It is easy to check that, actually, the algorithm supports removing an
arbitrary edge
instead of specifically the (up to) two edges incident to the minimum vertex. The minimum of each path is always maintained explicitly. This gives us a data structure for DTM.

Generalizing this data structure to semigroup turns out to be quite easy. Suppose the input path has
n=2^{k}
nodes.
There are two places where minima are computed:

•

At the start, for each interval of the form
I_{p,q}=[q\cdot 2^{p}+1,(q+1)\cdot 2^{p}]
with
0\leq p\leq k
and
0\leq q<n/2^{p}
, the algorithm computes the minimum of the subpath corresponding to
I
, in
\mathcal{O}(n)
total time. This can easily be done for the respective semigroup sums.

•

For each current subpath, the data structure stores precisely the minimum set of intervals
I_{p,q}
whose union corresponds to the subpath. These intervals are stored in a double-ended queue (deque) that supports finding the minimum in addition to the usual deque operations, all in constant time.

This deque is due to Gajewska and Tarjan
[
GT86
]
, and is called, somewhat deceptively, a
deque with heap order
. This data structure implements a deque with the familiar technique of using two stacks for the left and right part of the deque. An amortization argument shows that
m
deque operations can be performed using
\mathcal{O}(m)
stack operations.

Each stack maintains the minimum of each of its suffixes. This requires
\mathcal{O}(1)
time to maintain per stack operation, and allows computing the minimum of the deque by taking the minimum of the two whole stacks.
Observe that the same can be done with semigroup sums.∎

for

be a rooted tree, and let

be the number of operations. By

Theorem 8.4
.

8.2
Cartesian edge-partition trees

Recall the definition of
Cartesian edge-partition trees
(Cartesian EPTs) from the introduction. A Cartesian EPT on a connected graph
G
with edge priority function
p
is a rooted binary tree
T
with
V(T)=E(G)\cup V(G)
, where the edges of
G
correspond to inner nodes of
T
, and vertices of
G
correspond to leaves of
T
. If
G
consists of a single vertex, then
T
also consists of that vertex. Otherwise, the root of the EPT is the minimum-priority edge of
(G,p)
, and the the up to two child subtrees are recursively constructed on the up to two components of
G-e
.
We also write
\mathcal{C}^{\mathrm{E}}(G,p)=T
.
Let
\mathcal{E}^{\mathrm{E}}(G)
denote the set of possible Cartesian EPTs on
G
.

It is known that Cartesian EPTs on
trees
can be constructed in
\mathcal{O}(n\log n)
time
[
Cha87
]
, or in
\mathcal{O}(n\log\ell)
time if
G
has
\ell
leaves
[
DM13
]
. In this section, we give a universally optimal algorithm for arbitrary graphs.

Fix some connected graph
G
and edge priority function
p
on
G
. Recall that
\widetilde{p}
assigns multiple vertices the same priority
\infty
. Since this does not play well with our definition of Cartesian trees, we introduce the following tie-breaking.
Fix an arbitrary ordering
\pi
on
V(G)
, and redefine
\widetilde{p}(v)=\infty_{v}
; where
\infty_{v}
is a priority that is larger than all edge priorities, and
\infty_{v}<\infty_{u}
if
v
precedes
u
in
\pi
. We can now prove the following.

Lemma 8.5
.

Let
G
be a graph with edge priority function
p
. Then
\mathcal{C}^{\mathrm{E}}(G,p)
is isomorphic to
\mathcal{C}(\widetilde{G},\widetilde{p})
under the mapping
v\rightarrow v
for
v\in V(G)
and
e\rightarrow v_{e}
for
e\in E(G)
.

Proof.

If
G
contains only one vertex, then both
\mathcal{C}^{\mathrm{E}}(G,p)
and
\mathcal{C}(\widetilde{G},\widetilde{p})
consist of that vertex only.

Otherwise, let
e
be the minimum-priority edge of
G
, and recall that
v_{e}
must be the minimum-priority vertex of
\widetilde{G}
.

Suppose first that
G-e
is disconnected, so it has two components
H_{1}
,
H_{2}
.
Then
\widetilde{G}-v_{e}
also has two components
H^{\prime}_{1}
,
H^{\prime}_{2}
. It is easy to see that
H^{\prime}_{1}=\widetilde{H}_{1}
and
H^{\prime}_{2}=\widetilde{H}_{2}
(for some assignment of the names
H_{1},H_{2}
).
By induction,
\mathcal{C}(H_{i},p)=\mathcal{C}(\widetilde{H}_{i},\widetilde{p})
for
i\in\{1,2\}
. Since
\mathcal{C}^{\mathrm{E}}(G,p)
consists of the root
e
with children
\mathcal{C}(H_{1},p)
,
\mathcal{C}(H_{2},p)
, and
\mathcal{C}(\widetilde{G},\widetilde{p})
consists of the root
v_{e}
with children
\mathcal{C}(\widetilde{H}_{1},\widetilde{p})
,
\mathcal{C}(\widetilde{H}_{2},\widetilde{p})
, our claim follows.

Suppose now
H\coloneq G-e
is connected. Clearly,
\widetilde{G}-v_{e}=\widetilde{H}
. Our claim follows similarly.
∎

Observe that
lemma

8.5
in particular implies that the choice of
\pi
for tie-breaking does not affect the Cartesian tree
\mathcal{C}(\widetilde{G},\widetilde{p})
.

We now give the universally optimal algorithm. Given is a graph
G
with
n
vertices and
m
edges, and an edge priority function
p
. Start by computing
(\widetilde{G},\widetilde{p})
in
\mathcal{O}(m+n)
time. Then, compute
\mathcal{C}(\widetilde{G},\widetilde{p})
with
theorem

1.2
. Using
lemma

8.5
, we can map the result to the correct EPT
\mathcal{C}^{\mathrm{E}}(G,p)
.

The total running time is
\mathcal{O}(m+n+\log|\mathcal{E}(\widetilde{G})|)
. Since
lemma

8.5
defines a bijection between
\mathcal{E}^{\mathrm{E}}(G)
and
\mathcal{E}(\widetilde{G})
, we have
|\mathcal{E}^{\mathrm{E}}(G)|=|\mathcal{E}(\widetilde{G})|
.

Theorem 8.6
.

Given a connected graph
G
with edge priority function
p
, we can compute
\mathcal{C}^{\mathrm{E}}(G,p)
in time
\mathcal{O}(|E(G)|+\log|\mathcal{E}^{\mathrm{E}}(G)|
.

By the information-theoretic lower bound and the trivial
\Omega(|E(G)|)
lower bound,
theorem

8.6
is universally optimal.

Appendix A
The potential of complete binary trees

Let
T
be a binary tree and
w\colon V(T)\rightarrow\mathbb{N}_{+}
be a node weight function. Recall that the
rank
of a node
v\in V(T)
is
\log w(T_{v})
and the
potential

\Phi(T)
of
T
is defined as the sum of all node ranks. In the following, we explicitly write
\Phi(T,w)
to denote the potential of
T
w.r.t. the weight function
w
.

The
complete binary tree

C_{n}
on
n=2^{k}-1
nodes is the tree where all leaves are at depth
k
. If
n+1
is not a power of two, then
C_{n}
is constructed from
C_{n^{\prime}}
with
n^{\prime}=2^{\lceil\log(n+1)\rceil}-1
by progressively removing leaves from right to left until the number of nodes is
n
.
In this section, we show:

Theorem A.1
.

Let
T=B_{n}
and let
w\colon V(T)\rightarrow\mathbb{N}_{+}
. Let
W=w(T)
be the sum of weights in
T
. Then
\Phi(T,w)\in\mathcal{O}(W)
.

The following lemma is central:

Lemma A.2
.

Let
T=B_{n}
, let
v\in V(T)
, and let
w,w^{\prime}\colon V(T)\rightarrow\mathbb{N}_{+}
be weight functions such that
w^{\prime}(u)=w(u)
for all
u\neq v
and
w^{\prime}(v)>w(v)
. Then
\Phi(T,w^{\prime})\leq\Phi(T,w)+3(w^{\prime}(v)-w(v))
.

Proof.

Let
x=w^{\prime}(v)-w(v)
. Let
a_{0}=v
and let
a_{1},a_{2},\dots,a_{k}
be the proper ancestors of
v
in
T
, ordered from
v
to the root. The weight increase of
v
only affects itself and its ancestors, so we have:

\Phi(T,w^{\prime})-\Phi(T,w)=\sum_{i=0}^{k}\log w^{\prime}(T_{a_{i}})-\log w(T_{a_{i}})=\sum_{i=0}^{k}\log\frac{w(T_{a_{i}})+x}{w(T_{a_{i}})}.

Observe that
w(T_{a_{i}})\geq 2^{i+1}-1\geq 2^{i}
. Using the fact that
\tfrac{a+x}{a}\leq\tfrac{b+x}{b}
for all
a\geq b
, we get

\displaystyle\Phi(T,w^{\prime})-\Phi(T,w)

\displaystyle\leq\sum_{i=0}^{k}\log\frac{2^{i}+x}{2^{i}}\leq\sum_{i=0}^{k}\log\left(1+\frac{x}{2^{i}}\right)\leq\sum_{i=0}^{k}\log e^{x/2^{i}}

\displaystyle\leq 2x\log e\leq 3x.

∎

Proof of
theorem

A.1
.

Suppose that
n=2^{k}-1
; the other cases follow by padding with weight-one leaves.

We start with the case that
w(v)=1
for all
v\in V(T)
.
Then

\Phi(T,w)=\sum_{i=0}^{k-1}2^{i}\log\tfrac{n}{2^{i}}\in\mathcal{O}(n),

as desired.

We can now transform
w
into an arbitrary weight function
w^{\prime}
by repeatedly increasing the weight of some node by some amount
x
. Every time we do this, the potential increases by at most
3x
by
lemma

A.2
. Thus, the total potential increase is at most
3(w^{\prime}(T)-w(T))=3(w^{\prime}(T)-n)
, for a total potential of
\mathcal{O}(w^{\prime}(T)+n)=\mathcal{O}(w^{\prime}(T))
.
∎
