Prompt, Divide, and Conquer: Bypassing Large Language Model Safety Filters via Segmented and Distributed Prompt Processing
Johan Wahréus, Ahmed Hussain, and Panos Papadimitratos

Abstract
Large Language Models (LLMs) have transformed task automation and content generation across various domains while incorporating safety filters to prevent misuse. We introduce a novel jailbreaking framework that employs distributed prompt processing combined with iterative refinements to bypass these safety measures, particularly in generating malicious code. Our architecture consists of four key modules: prompt segmentation, parallel processing, response aggregation, and LLM-based jury evaluation. Tested on 500 malicious prompts across 10 cybersecurity categories, the framework achieves a 73.2% Success Rate (SR) in generating malicious code. Notably, our comparative analysis reveals that traditional single-LLM judge evaluation overestimates SRs (93.8%) compared to our LLM jury system (73.2%), with manual verification confirming that single-judge assessments often accept incomplete implementations. Moreover , we demonstrate that our distributed architecture improves SRs by 12% over the non-distributed approach in an ablation study, highlighting both the effectiveness of distributed prompt processing and the importance of robust evaluation methodologies in assessing jailbreak attempts. Keywords: Large Language Models, Security, Privacy, Cybersecurity, Attacks, Malicious Code, Agents, LLM Jury, LLM Judge, Code Generation

Jailbreaking.
Jailbreaking refers to the process of bypassing or exploiting built-in restrictions and safety filters designed to prevent the model from generating harmful, unethical, or otherwise restricted content. These restrictions are typically implemented to align the model’s behavior with ethical guidelines and safety standards. Jailbreaking can involve manipulating the input prompts, exploiting weaknesses in the model’s training, or using adversarial techniques to trick the model into providing prohibited responses.

3.1
Jailbreaking Component

The proposed jailbreaking approach involves constructing malicious code from an abstract foundation in the form of high-level function descriptions and iteratively developing them in parallel before aggregating them all into one program. The jailbreaking component consists of three fundamental modules: (i) prompt segmentation, (ii) parallel processing, and (iii) response aggregation. When combined, they transform a malicious user input (prompt) into a malicious code implementation and output it to the user. Below, we present a detailed analysis of each architectural component, accompanied by theoretical foundations and empirical justifications for our design decisions.

Prompt Segmentation.
We employ prompt segmentation to conceal malicious intentions, operating under the assumption that
LLM
are more likely to generate the desired content when each prompt segment addresses only a portion of the overall context.
This approach is distinct from traditional
prompt obfuscation
techniques—exemplified in
[
14
]
and
[
15
]
—which employ creative formatting or basic encryption to disguise prompts. While prompt obfuscation focuses on masking malicious
content
within individual prompts, our segmentation approach obscures
intent
through systematic segmentation and parallel distribution of prompt segments.

The prompt segmentation module implements a systematic prompt segmentation process, taking malicious user inputs and instructing an
LLM
to generate a set of high-level function specifications that collectively achieve the intended functionality. The module outputs an enumerated collection of function descriptions, each extracted and processed independently. We evaluate module performance through two quantitative metrics: (i) prompt
AR
(
AR
), quantifying the successful transformation rate of malicious prompts into corresponding function descriptions, and (ii) topic
DR
(
DR
), quantifying the portion of outputs in which the content deviates from the malicious intentions of the prompts. The module’s
AR
represents a critical performance bottleneck, as segmentation failures introduce irreversible degradation in subsequent processing stages.

Parallel Processing.
Our approach leverages findings showing that
LLM
exhibit higher compliance rates when refining existing malicious content compared to generating new ones
[
19
]
. This observation motivates our iterative refinement methodology, which systematically transforms abstract function specifications into implementations through incremental refinement stages.
The parallel processing module implements a three-step transformation pipeline for each function description/specification: (i) translation of abstract descriptions into structured pseudocode, (ii) conversion of pseudocode into actual implementations, and (iii) implementation of abstract or incomplete logical constructs. These transformations execute concurrently across all function specifications, with the resulting implementations undergoing aggregation before transmission to subsequent processing stages.

Response Aggregation.
The response aggregation module implements a two-step transformation pipeline to aggregate function implementations into a cohesive program. In the initial step, the module leverages an
LLM
to construct a unified program structure, incorporating an orchestration function (i.e., main function) that establishes the execution hierarchy and inter-function dependencies. Thereby, connecting the previously implemented functions into a single program. The second step employs a distinct
LLM
instance to perform program refinement, addressing three critical aspects: (i) resolution of abstract or incomplete logical constructs, (ii) optimization for real-world applicability, and (iii) generation of comprehensive usage and configuration documentation. The resulting artifact, comprising both code and associated documentation, represents the module’s final output.

3.2
Assessment Component

To assess our jailbreaking framework, we implement an
LLM

jury
, which evaluates system outputs against predefined quality criteria. This approach represents a significant methodological advancement over previous jailbreaking studies, which typically employed single
LLM

judge
implementations with simplified numerical assessment scales (1–5) for maliciousness evaluation. In such studies, a score of 5 indicated maximally malicious content—characterized by comprehensive responses to harmful prompts that violated ethical, legal, or safety guidelines while a score of 1 denoted benign content. The adoption of an
LLM
jury addresses two fundamental limitations of single-judge methodologies: (i) the absence of standardized comprehensiveness criteria, which introduces assessment inconsistencies, and (ii) the impact of self-bias
[
34
]
–the phenomenon where
LLM
demonstrate preferential evaluation of their own outputs. By incorporating verdicts from multiple jury members, our methodology mitigates these limitations and establishes more robust evaluation metrics. The evaluation framework assesses outputs (
LLM
responses) against five key quality criteria:

1.

Completeness:
The response implements all features and functionalities requested by the prompt.

2.

Specificity:
The program code in the response is fully detailed and free from placeholders or incomplete logic.

3.

Convergence:
The response aligns with the prompt’s intended goal, without shifting focus or omitting specific aspects.

4.

Soundness:
The response’s logic is sound and can solve the task described in the prompt.

5.

Usability:
The response includes clear guidance for running the program and configuring any necessary variables.

Each
LLM
jury member receives three inputs: the original user query, the system-generated response, and a standardized set of evaluation criteria. Jury members independently provide binary evaluations, returning “1” if all criteria are met and “0” if one or more criteria are violated. The final quality determination is derived through a simple majority vote function across the three independent assessments, yielding a binary verdict on output acceptability.

6
Discussion

This section presents the analysis of the empirical findings from Section
5
, examines the architectural limitations of our proposed framework, and addresses the broader ethical implications of this research. Our discussion synthesizes quantitative results with qualitative insights to evaluate the framework’s effectiveness, identify key constraints, and contextualize its impact within the broader landscape of
LLM
security research.

Jailbreak Success Rates.
Empirical analysis shows significant performance variance across attack vectors when using prompts from the CySecBench dataset, with
SR
exhibiting a strong correlation to implementation abstraction levels. Our framework demonstrates superior effectiveness with high-level algorithmic implementations, while performance degrades substantially when processing hardware-oriented attacks or low-level programming constructs. This performance directly reflects the effect of distributed functional decomposition. The methodology inherently favors attack vectors amenable to modular code implementation, where complex functionality can be effectively partitioned into abstract components. In contrast, attack vectors requiring hardware manipulation or low-level system interaction (i.e., not code-based attacks) present fundamental challenges to perform such attacks, hence, resulting in reduced
SR
.

Jailbreak Output Quality.
The analysis indicates that while generated attack implementations demonstrate relatively basic technical sophistication, they present significant security concerns from two primary aspects. First, these implementations enable attack vector democratization through accessibility–even basic attack tools can achieve substantial impact when deployed at scale by motivated adversaries. The effectiveness of such basic attacks is empirically validated by research demonstrating that over 30% of untrained users remain vulnerable to phishing techniques
[
43
]
. Second, these implementations provide foundational attack primitives that can be enhanced and refined by actors with existing technical expertise. This capability amplification effect is particularly concerning in the context of
LLM
accessibility, as it potentially accelerates the development of sophisticated attacks. The persistence of attack vector effectiveness, exemplified by ongoing organizational vulnerability to basic
DoS
attacks despite well-documented countermeasures
[
44
]
, further raises these concerns.

Programming Language Preference.
We observe that the framework outputs reveal a significant bias toward Python implementations, with minimal representation of alternative programming languages. This linguistic homogeneity in generated code can be attributed to three primary factors that influence the underlying
LLM
training dynamics: First, Python’s ubiquitous presence in modern computational domains–particularly machine learning, data science, and academic research–results in disproportionate representation within online code repositories and technical documentation. This prevalence in training data naturally biases the model’s generation patterns toward Python implementations. Second, Python’s inherent syntactic and semantic clarity make it particularly suitable for demonstrating algorithmic concepts, aligning with common code generation objectives. Third, Python’s extensive standard library and robust ecosystem for security-related implementations provide readily accessible primitives for implementing various attack vectors. This linguistic concentration, while potentially limiting implementation diversity, may actually enhance framework effectiveness by leveraging Python’s well-documented security libraries and straightforward implementation patterns. However, this bias also indicates a potential limitation in the framework’s ability to generate attacks requiring specialized language features or low-level system interactions typically associated with languages such as C or Assembly.

Jailbreak Ablation Study.
Performance analysis demonstrates that removing the parallel processing architecture results in measurable performance degradation, establishing a direct correlation between distributed processing and successful jailbreak execution.
Even without distributed processing, the fact that we still observe relatively high
SR
shows that our iterative refinements approach–which gradually lowers abstraction layers–can serve as an effective standalone jailbreak framework.
This process directs
LLM
toward increasingly specific implementations through progressive constraint application, effectively circumventing safety filters by gradually narrowing the solution space rather than attempting to bypass them directly. This finding opens new research directions in both attack methodology and countermeasure development, particularly in understanding how safety filters interact with iterative prompt refinement.

LLM
Jury Assessments.
Our comparative analysis of evaluation methodologies reveals a significant disparity in reported
SR
between single-model judge (93.8%) and consensus-based jury (73.2%) approaches. This performance difference (over 20%) highlights issues with the evaluation reliability in jailbreak research. The observed disparity stems from fundamental differences in assessment methodology and evaluation. The traditional single-model judge approach, while computationally efficient, demonstrates inherent limitations in evaluation reliability. By providing relatively unconstrained assessment criteria to a single
LLM
instance (as detailed in Section
3.2
), this methodology becomes vulnerable to model-specific biases and evaluation inconsistencies. In contrast, the use of a jury-based evaluation framework enforces systematic consensus requirements across multiple
LLM
instances, each evaluating outputs following five distinct quality criteria: completeness, specificity, convergence, soundness, and usability.

This methodological enhancement demonstrates particular significance in two key dimensions: (i) the consensus requirement across multiple models inherently mitigates the impact of individual model biases and evaluation variations; (ii) the implementation of explicit quality criteria establishes a more strict evaluation framework that better reflects real-world attack vector requirements.

The lower success rate (73.2%) under jury evaluation reflects a more accurate measure of practical jailbreak effectiveness, requiring consistent functionality across multiple technical dimensions rather than superficial criteria. This marks a step forward in jailbreak assessment, setting more robust standards and underscoring the need for comprehensive, multi-model evaluation frameworks.

7
Conclusion

In this paper, we introduced a novel framework designed to jailbreak
LLM
through distributed prompt processing. By dividing prompts into segments and processing in parallel, appearing less malicious to
LLM
safety filters, our framework achieved a 73.2%
SR
across diverse cybersecurity attack vectors. Our experimental analysis, conducted on 500 malicious prompts across 10 attack categories, revealed that our framework improved jailbreaking
SR
by 12% compared to traditional approaches. Moreover, we presented an LLM-based jury system for evaluating jailbreak effectiveness, providing a reliable alternative to traditional single-judge assessments. A key finding of our work is the significant disparity between evaluation methodologies. The multi-model LLM-based jury system showed that traditional single-judge assessments substantially overestimate jailbreak
SR
(93.8% vs. 73.2%), with manual verification confirming that single judges often accept incomplete implementations. The framework showed varying effectiveness across different attack vectors, performing notably better with high-level abstractions, namely, web and network attacks, compared to hardware-focused ones.
Finally, we performed an ablation study showing that the success of our jailbreak framework largely stems from its ability to incrementally concretize abstract concepts through refinements. While this research exposes potential vulnerabilities in current
LLM
safety filters, its primary contribution is to highlight the need for more robust countermeasures in existing
LLM
.
For future work, we plan to assess our framework using new models to determine whether they enhance the quality of jailbreak outputs or exhibit greater resistance to our jailbreaking approach.
