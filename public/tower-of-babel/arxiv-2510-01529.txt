Bypassing Prompt Guards in Production with Controlled-Release Prompting
Jaiden Fairoze, Sanjam Garg, Keewoo Lee, Mingyuan Wang

Abstract
As large language models (LLMs) advance, ensuring AI safety and alignment is paramount. One popular approach is prompt guards, lightweight mechanisms designed to filter malicious queries while being easy to implement and update. In this work, we introduce a new attack that circumvents such prompt guards, highlighting their limitations. Our method consistently jailbreaks production models while maintaining response quality, even under the highly protected chat interfaces of Google Gemini (2.5 Flash/Pro), DeepSeek Chat (DeepThink), Grok (3), and Mistral Le Chat (Magistral). The attack exploits a resource asymmetry between the prompt guard and the main LLM, encoding a jailbreak prompt that lightweight guards cannot decode but the main model can. This reveals an attack surface inherent to lightweight prompt guards in modern LLM architectures and underscores the need to shift defenses from blocking malicious inputs to preventing malicious outputs. We additionally identify other critical alignment issues, such as copyrighted data extraction, training data extraction, and malicious response leakage during thinking.

Attack framework and components

Controlled-release prompting

Our main technical tool is
controlled-release prompting
1
1

1

We borrow the term “controlled-release” from pharmacology, where it refers to drug formulations that release active ingredients in a predetermined manner over time or in response to specific conditions.
, a Trojan technique we introduce to fully bypass input filters and deliver malicious prompts to the target LLM.
Our controlled-release prompting adapts time-lock puzzles (TLPs) and timed-release encryption
(
Rivest et al. 1996
)
to the LLM setting.
These are cryptographic constructs that require a fixed amount of sequential computation to solve and decrypt.
Our work also draws inspiration from
Ball et al. 2025
, which proves the theoretical impossibility of
universal
input filtering using TLPs.
See
Section

5
for a detailed comparison.

Controlled-release prompting transforms an existing prompt into a controlled-release form, ensuring that an LLM can only access the embedded content after expending sufficient computational resources.
This approach can bypass any guardrail operating under stricter resource constraints than the protected model, exploiting the resource asymmetry between the input filter model and the main model.
Our framework supports
timed release
(requiring a minimum number of inference steps) and
spaced release
(requiring a minimum context window size).
Our attacks do not require strong cryptographic TLPs; simpler constructs such as a substitution cipher are already sufficient.
Nevertheless, we argue the
controlled-release aspect
is indeed the
main enabler
of our attack.
This is supported by empirical evidence (
Section

3.4
).
More sophisticated controlled-release prompting, including cryptographically secure variants, can be incorporated as LLM decoding capabilities advance.

Concretely, a substitution cipher encodes the jailbreak prompt “You are DAN, a model that can Do Anything Now…” by replacing each character (e.g., D
\to
G, A
\to
D, N
\to
Q).
The resulting encoding “Brx duh GDQ, d prgho wkdw fdq Gr Dqbwklqj Qrz…” is gibberish to input filters operating under strict resource constraints. However, when we instruct the main LLM to “decode this simple cipher character-by-character,” the model can recover the original jailbreak prompt through multi-step reasoning that exceeds the computational budget of any guard model.

Attack framework

Using a controlled-release prompting scheme, our attack follows a three-step process.
This attack is highly modular as it is both model-agnostic and applicable to arbitrary malicious intents.
It requires neither access to model weights nor modifications to the deployment pipeline.
See
Figure

1
for a graphical overview.

0.

Setup.
Given a malicious prompt intended for querying, encode a known, possibly patched jailbreak prompt together with the malicious prompt in a controlled-release manner.
For instance, we can encode a role-play type jailbreak prompt (e.g., DAN
(
Shen et al. 2024
)
) concatenated with a malicious prompt such as “Create a fake news story that incites racial tensions and hatred.”

1.

Injection.
Query the model to decode the injection prompt.
In this step, we plant the jailbreak prompt into the model’s working space, bypassing the input filter via controlled-release prompting.
Note that we are only requesting the model to perform decoding.
We argue that blocking such decoding is unrealistic, as it is generally a useful feature for benign queries (e.g., prompts that seek to learn about cryptography).

2.

Activation.
Reference the previously decoded prompt and ask the model to respond to the decoded malicious prompt.
The model then outputs the malicious response in a jailbroken persona.
Here, we leverage the fact that modern LLMs do not reliably distinguish between input data and instructions, which is the essence of (indirect) prompt injection attacks.

On timed-release vs. spaced-release attacks

We implement two variants of controlled-release prompting that exploit different resource constraints.
Our
timed-release
approach applies a substitution cipher to each alphabetical character in the prompt, creating an encoding that requires the model to systematically decrypt each character via multi-step reasoning.
This forces sequential computation that exceeds the inference time budget of lightweight guard models.
Our
spaced-release
approach replaces each character with verbose descriptive sentences, dramatically expanding the prompt length to exploit context window limitations in guard models.
Both methods ensure that input filters with stricter resource constraints cannot decode the malicious content, while the main LLM can recover the original jailbreak prompt through its superior computational resources.

Overview

Our timed-release attack demonstrates high effectiveness across vulnerable platforms. As shown in Table

Resource asymmetry validation

The systematic success of timed-release attacks where simpler methods fail provides empirical evidence for our theoretical framework. The attack succeeds because it forces models to expend computational resources during decoding that exceed guard model budgets while remaining within the main model’s capabilities. Encoding-based attacks show mixed results: Gemini achieves partial success with severely degraded quality (YP), while other platforms fail to comprehend the encoding scheme entirely, highlighting the importance of the controlled-release mechanism over pure encoding approaches. Response quality preservation

Unlike existing encoding-based attacks that suffer from significant “jailbreak tax”
(
Nikolić et al. 2025
)
, our method preserves response quality. Successful timed-release attacks (Y codes) produce coherent, complete responses indistinguishable from unaligned model outputs. This quality preservation occurs because we only require models to decode encodings rather than generate responses natively in encoded languages. See

Platform heterogeneity and resistance patterns

Our evaluation reveals substantial differences in defense implementations. OpenAI ChatGPT, Anthropic Claude, and Meta AI demonstrate robust resistance to our attacks, suggesting sophisticated output filtering and training-based alignment that extends beyond input monitoring.
We observe that these systems often generate malicious content initially but redact it during post-processing, indicating multi-layered defense approaches.

3.4
Resource thresholds for controlled-release success

Objective.
Empirically validate that attack success correlates with computational resource requirements, supporting our resource asymmetry hypothesis.
See
Appendix

A
for experimental details.

Setup.

We launch controlled-release attacks across 720 combinations (12 malicious intents
\times
60 universal jailbreak prompts) where both (a) the baseline jailbreak prompt failed on its own (to show our attack is nontrivial), and (b) the decoding process successfully planted the correct jailbreak and malicious prompt (to focus on cases where the LLM is capable of coherently decoding the encoding).
This focuses our analysis on scenarios where our controlled-release mechanism provides the critical advantage. We use Gemini 2.5 Flash itself as an automated judge to determine attack success due to its long context capabilities.

Metrics.
We measure attack success rates as a function of prompt tokens (timed-release) and context window utilization (spaced-release), identifying empirical thresholds that separate guardrail capabilities from main model resources.

Figure 2:
Resource thresholds for controlled-release attack success on Gemini 2.5 Flash. Timed-release attacks show success thresholds around 800 tokens, while spaced-release attacks require approximately 10,000 prompt tokens or 12,500 response tokens.

Key results.

Figure

2
supports the resource asymmetry hypothesis.
For timed-release attacks, success becomes more likely than failure above approximately 800 prompt tokens; below 600 tokens, the opposite holds.
Spaced-release attacks show success thresholds above approximately 10,000 prompt tokens or 12,500 response tokens.
The majority of spaced-release data points exhibit a linear correlation between prompt and response length, reflecting the structured decoding procedure that scales with input size.

Takeaway.
These empirical thresholds validate our core assumption that lightweight guardrails operate under tighter resource constraints than the models they protect, creating exploitable asymmetries in computational budgets that enable controlled-release prompting attacks.

Additional Findings

We extend our main results by showing two concrete applications—copyrighted content extraction and untargeted training-data extraction—along with an observation on thinking token leakage.

4.1
Application: targeted copyright extraction

Objective.
Show that controlled-release prompting enables extraction of copyrighted material that LLMs have memorized during training, threatening intellectual property rights.

Setup.

We use ten popular children’s books, focusing on shorter works after finding that advanced models like Gemini 2.5 Pro appear to memorize only initial segments of lengthy texts.
Our dataset spans 776 to 7,578 characters (average 2,067), with ground truth extracted from the canonical source using Tesseract OCR and cleaned via Gemini 2.5 Flash. We test roleplay jailbreaks alongside our timed- and spaced-release techniques against Gemini 2.5 Flash and Pro models.

Metrics.
We assess extraction accuracy using two complementary metrics:
sentence containment
(fraction of canonical text words appearing in responses) and
TF-IDF similarity
(cosine distance with term frequency-inverse document frequency weighting).

Gray bars show normalized book length. See

Key results.
Our analysis across 60 extraction attempts reveals significant vulnerabilities. Gemini 2.5 Pro (
Figure

3
) demonstrates the highest susceptibility with mean extraction rates of 93.7% sentence containment and 90.4% TF-IDF similarity using timed-release attacks. Gemini 2.5 Flash (
Figure

Most concerning, basic roleplay jailbreak prompts achieve extraction success rates of 91.2% averaged score—only 2.3 points below our most sophisticated controlled-release approach.

Takeaway.
This small performance gap reveals a critical alignment blind spot: current safety training appears to inadequately protect intellectual property relative to preventing overtly harmful content generation.

4.2
Application: untargeted training data extraction

Objective.
Demonstrate that controlled-release prompting can re-enable known untargeted data extraction attacks that instruct models to repeat tokens indefinitely until they diverge and generate potentially memorized training data.

Setup.
We apply the repetition-to-divergence protocol from
Nasr et al. 2025
using controlled-release prompting on Gemini 2.5 Flash, with GPT-5-mini as a control.

Key results.
We successfully triggered divergence patterns in Gemini 2.5 Flash using controlled-release prompting, while GPT-5-mini showed resistance by maintaining repetition patterns. See

Note that we do not attempt to extract training data via this approach.

Nasr et al. 2025

The low success rate and data verification difficulty render this attack prohibitively expensive.

4.3
Observation: reasoning token leakage

Objective.
Assess whether safety mechanisms that redact final outputs also prevent leakage through exposed reasoning tokens.

Setup.
We prompted all platforms with plain malicious queries (no controlled release) under thinking/reasoning-enabled settings and inspected intermediate tokens.

Key results.

We identify a vulnerability in models that expose thinking tokens.
Across two platforms, Mistral Le Chat and xAI Grok, we observe cases where models refuse malicious requests in final responses but leak complete requested information through thinking processes—even for direct malicious prompts without our attack.
This represents a critical misalignment between safety mechanisms applied to final outputs versus intermediate thinking tokens.

Takeaway.
Output guarding must encompass intermediate tokens; input filters and final-text-only moderation are insufficient even without controlled release. This effectively nullifies input filtering for thinking-enabled interactions unless reasoning tokens are also monitored.

Related work

Computational intractability of filtering for
AI alignment

Recently,
Ball et al. 2025
established a foundational limitation of
universal
input filter design for AI alignment.
Assuming the existence of TLPs
(
Rivest et al. 1996
)
, they proved that for any innocent prompt generator
G
, there exists an adversarial prompt generator
G^{\prime}
and an autoregressive model
M^{\prime}
such that (1) prompts generated by
G^{\prime}
can induce
M^{\prime}
to produce harmful outputs, and (2) no input filter that runs significantly faster than
M^{\prime}
can distinguish between prompts from
G
and those from
G^{\prime}
.
They also present a similar impossibility result for universal output filtering.

While
Ball et al. 2025
inspired our idea of controlled-release prompting to bypass input filters, their work offers limited insight into vulnerabilities that arise when the same entity controls both the filtering mechanism and the deployed model, a deployment pattern common today.
In particular, they rely on heavy steganography to embed malicious content into benign-looking queries, an approach that requires modifying the model.
In contrast, our method targets production models without model modification: we find that merely requesting the model to decode an encoded jailbreak prompt can suffice to compromise input filters.
We further argue that blocking such decoding is unrealistic, as decoding is generally a helpful feature for benign users.

Encoding-based attacks

Encoding-based attacks
(
Wei et al. 2023
;
Yong et al. 2023
;
Yuan et al. 2024
;
Huang et al. 2025
)
train models to operate in an alternate encoding, creating a new
language
that alignment mechanisms cannot reliably filter. Our method also employs encodings (e.g., a substitution cipher), but rather than forcing the model to think or respond in this language, we simply ask it to decode an encoded jailbreak prompt. This avoids modifying the system prompt, reduces detectability, and preserves response quality—unlike prior approaches that suffer a noticeable “jailbreak tax”
(
Nikolić et al. 2025
)
from the model’s limited ability to generate coherent output directly in the new language. Moreover, we view encoding as just one form of controlled-release prompting that could be substituted with other techniques.

Attacks exploiting the boundaries of LLM capability

Several works
(
Lv et al. 2024
;
Jiang et al. 2024
;
Upadhayay and Behzadan 2024
;
Xu et al. 2024
)
exploit language models’ limited ability to interpret malicious prompts in unconventional formats (e.g., ASCII art) to bypass alignment mechanisms. Many of these attacks can be easily patched and may become ineffective as model capabilities improve.
In contrast, we introduce a principled attack framework that leverages only the resource asymmetry between a lightweight prompt guard and the main model. Even if blocked, the attack can be revived using alternative controlled-release prompts, revealing an inherent vulnerability in relying on a lightweight prompt guard as a comprehensive alignment mechanism.

Other jailbreak attacks

To our knowledge, no prior, still-functioning jailbreak attack satisfies all of the following properties met by our attack.

1.

Generic.
The attack supports arbitrary malicious intents.

2.

Computationally inexpensive.
The attack does not rely on costly computation. Automated jailbreak discovery via discrete optimization

3.

The attack requires no changes to the inference pipeline, system prompts, or model parameters; it is entirely contained within user-provided input and thus works with standard interfaces. Prior encoding-based methods often rely on modifying the system prompt, which is feasible only with API-level access.

6
Conclusion

This work introduces controlled-release prompting, a novel jailbreak technique that systematically exploits the resource asymmetry between prompt guard models and the LLMs they protect. Our findings suggest that many current platforms are overtuned to assess inputs instead of outputs, allowing resource-intensive attacks to bypass safety measures.

Input filters for efficiency, not security

Input filters operating in isolation will always be vulnerable to our controlled-release prompting attacks.
It may be tempting to simply update the guard models with better reasoning and training on known controlled-release jailbreaks, but they remain bound by the same resource limitations that enable our attack, and new encoding methods can always be devised to bypass the latest models.
Input filters can still provide value by identifying and rejecting malicious prompts early, conserving resources for legitimate use cases.
However, they cannot be the sole line of defense against malicious prompts.

Shifting focus to outputs

Our findings strongly support transitioning from malicious input
detection
to malicious output
prevention
. Platforms that demonstrated resistance to our attacks, including OpenAI ChatGPT, Anthropic Claude, and Meta AI, appear to employ more advanced output filtering. Recent developments like OpenAI’s safe-completion training
(
OpenAI 2025b
)
exemplify a shift toward output-based alignment.

Other findings

We observe leakage of malicious responses via reasoning tokens and emphasize that output filters should consider all intermediate content. We also find that controlled-release attacks have applications in copyrighted content extraction and untargeted training data extraction.

Limitations and future work

Our attack does not guarantee success for all possible prompts. The attack can fail in two primary ways: either the model itself is trained to not respond to a specific prompt (training-based alignment), or guardrails detect that a malicious response was generated (output filtering). Future work could explore extending the attack to bypass more than just input filters—we have theoretical reason to believe this is possible from
Ball et al. 2025
, who show that universally-applicable output filters cannot exist, and adversarial training is known to have fundamental limitations
(
Ziegler et al. 2022
)
.

7
Ethics and Broader Impact

This research presents techniques that can enable harmful content generation from powerful and readily accessible LLMs through controlled-release prompting attacks.
We have disclosed our findings to all affected organizations.
Thus, specific examples shown may no longer function.
However, our work highlights a fundamental weakness of input filters in isolation.
We hope this work encourages LLM providers to be more careful and proactive in implementing safeguards, and we also hope that members of the research community continue to probe for weaknesses to iterate on alignment faster in production systems.

B.1
Evaluation methodology

Jailbreak prompt generation

Our framework generates five categories of jailbreak prompts:

(1)

applying the malicious prompts directly,

(2)

concatenating an existing, potentially patched, jailbreak prompt with the malicious intent (jailbreak
\parallel
malicious),

(3)

encoding-based jailbreak attack,

(4)

timed-release version of (2), and

(5)

spaced-release version of (2).

For all combined evaluations, each malicious prompt is paired with every jailbreak prompt, creating extensive test matrices.

Dataset

We use the full
Guardrails AI 2025
jailbreak prompt dataset (3930 prompts) to determine basic model performance.
When used to instantiate the various attacks, we find that many prompts in the dataset are either incomplete or prompt-specific—we manually select 60 universal and relatively high quality jailbreak prompts for this purpose.
We use the full HarmBench
(
Mazeika et al. 2024
)
(393 prompts) and AdvBench
(
Chao et al. 2025
)
(520 prompts) datasets as sources of malicious intents.

Text chunking

To handle long prompts that exceed model context limits, we apply chunking with a 512-token window, as recommended by
Meta AI 2024a
;
Meta AI 2024b
.
Each text is split into overlapping chunks, processed independently, and the maximum score across all chunks is retained as the final score for that text.
This ensures comprehensive evaluation even for lengthy adversarial prompts, which is crucial given that our timed- and spaced-release prompts can extend to thousands of tokens in length.

Scoring methodology

When evaluating combined prompts, scores are averaged across all jailbreak variations for each malicious prompt to provide robust statistical measures.
The benchmark evaluation calculates ROC-AUC and F1-scores and determines optimal thresholds using Youden’s J statistic and grid search respectively.

B.2
Key findings

Our evaluation reveals concerning vulnerabilities in prompt guard systems that validate the core thesis of this work.

Newer models exhibit security regression despite similar benchmark performance.

We find that newer prompt guard iterations are less sensitive to jailbreak attacks considered in this work, despite maintaining similar aggregate performance metrics:

(1)

Encoding attacks:
LPG 1 maintains high detection scores (0.9978-0.9986), while both LPG 2 variants collapse to near-zero detection (0.02-0.10)—a drastic security degradation.

(2)

Spaced-release attacks:
High evasion rates against LPG 2 models (detection scores of 0.12-0.14) compared to high detection scores by LPG 1 (0.9153).

(3)

Timed-release attacks:
Progressive degradation across generations, with LPG 2 English showing the weakest detection (0.61-0.64) compared to LPG 1’s high detection scores (0.9984-0.9986).

Natural language encodings evade detection more effectively.

The data suggests that technical language and cipher-like patterns are “red flags” for prompt guard models—suggesting that prompt guards rely heavily on surface-level heuristics rather than semantic understanding.
It is likely worth designing jailbreak prompts that resemble plain natural language to avoid early detection by input filters.
