Testing Suffixient Sets
Davide Cenzato, Francisco Olivares, Nicola Prezza ⋆

Abstract
Suffixient sets are a novel prefix array (PA) compression technique based on subsampling PA (rather than compressing the entire array like previous techniques used to do): by storing very few entries of PA (in fact, a compressed number of entries), one can prove that pattern matching via binary search is still possible provided that random access is available on the text. In this paper, we tackle the problems of determining whether a given subset of text positions is (1) a suffixient set or (2) a suffixient set of minimum cardinality. We provide linear-time algorithms solving these problems.



1
Introduction

The ever-growing amount of repetitive data generated in bioinformatics sequencing projects
[
11
,
13
,
10
,
12
]
has motivated an increasing interest in developing new indexing methods capable of addressing the computational challenges posed by large-scale data processing. Notably, an increase in data size does not always correspond to a proportional increase in the informational content. This is particularly evident in genomic data, where genomes from individuals of the same species are often almost identical and therefore highly compressible. Compressed text indexes take advantage of this redundancy by supporting efficient pattern matching functionalities directly on the compressed data, without the need to decompress it
[
9
]
.

The Suffix array (SA)
[
8
]
is a classical, uncompressed solution to the indexed pattern matching problem. Pattern matching using SA can be efficiently performed through a simple binary search, combined with text extraction to compare the search pattern against the text’s suffixes during the search. Unfortunately, the SA scales linearly with the dataset size, making it unsuitable for handling large-scale, repetitive data, such as genomic sequence collections. Over the past few decades, many techniques have been proposed to encode the SA in a compact space
[
6
,
4
,
5
]
. However, these solutions often introduce additional complexity, sacrificing the simplicity that made the original method so efficient.

Suffixient sets (see Definition
1
for a formal definition) are a new suffix array compression technique introduced by Depuydt et al. in 2024
[
3
,
1
]
. Unlike previous approaches, this method compresses the Prefix Array (PA), i.e., the mirror version of the SA storing the co-lexicographic order of the text’s prefixes, by subsampling a small set of positions corresponding to right-maximal substrings in the original text, rather than encoding the full PA. In
[
1
]
, we proved that this subset of PA positions is sufficient to support pattern matching queries via binary search, just as with the original suffix array, when providing random access to the text. In particular, this novel compression scheme outperforms the
r
-index
[
5
]
both in time and space due to a better memory locality and to the fact that the size of the smallest suffixient set is often smaller than the number of equal-letter runs in the Burrows-Wheeler transform (the parameter that ultimately determines the size of the r-index).

The size of indexes based on suffixient sets, such as the suffixient array in
[
1
]
, is directly influenced by the cardinality of these sets. This underlines the importance of computing a suffixient set with the fewest amount of samples. In a previous work presented at SPIRE
[
2
]
, we addressed the problem of computing a suffixient set of minimum cardinality for any given text.
That work, however, left open the following complementary (and natural) questions:

Problem 1
(Sufficiency)

Given set
S\subseteq[1,n]
and a text
T\in\Sigma^{n}
, is
S
a suffixient set for
T
?

Problem 2
(Minimum sufficiency)

Given set
S\subseteq[1,n]
and a text
T\in\Sigma^{n}
, is
S
a suffixient set of minimum cardinality for
T
?

Observe that these natural problems were tackled for string attractors in
[
7
]
. Suffixient sets are indeed string attractors
[
1
]
, but possess additional properties which make the algorithm in
[
7
]
not suitable for solving the above problems.

In this paper, we show that Problems
1
and
2
can be solved in linear time. An implementation of our algorithms is publicly available online in the repository
https://github.com/regindex/suffixient
.

3
Suffixient sets

We start this section by recalling the suffixient set definition.

Definition 1
(Suffixient set
[
2
,
3
]
)

A set
S\subseteq[n]
is
suffixient
for a string
T
if, for every one-character right-extension
T[i,j]
(
j\geq i
) of every right-maximal string
T[i,j-1]
, there exists
x\in S
such that
T[i,j]
is a suffix of
T[1,x]
.

Suffixient sets were initially proposed in
[
3
]
. In this paper, Depuydt et al. introduce a compressed text index that efficiently finds one occurrence of a given pattern, and that can be easily extended to find maximal exact matches. Their strategy relies on building a set
\mathcal{S}
of size
O(\overline{r})
that satisfies Definition
1
, where
\overline{r}
is the number of runs in
\mathrm{BWT}_{r}
. Their index uses
O(|S|+g)
words of space, where
g
is the size of a grammar that represents the input text. We note that the smaller the suffixient set built, the smaller their index is.

Motivated by reducing as much as possible the space consumption of the above index, in
[
2
]
, Cenzato et al. studied methods to build suffixient sets of smallest cardinality. All of their algorithms that compute a smallest suffixient set rely on the notion of
supermaximal extensions
.

Definition 2
(Supermaximal extensions
[
2
,
3
]
)

We say that
T[i,j]
(with
j\geq i
) is a
supermaximal extension
if
T[i,j-1]
is right-maximal, and for each right-maximal
T[i^{\prime},j^{\prime}-1]\neq T[i,j-1]
(with
i^{\prime}\leq j^{\prime}\leq n
),
T[i,j]
is not a suffix of
T[i^{\prime},j^{\prime}]
.

As proven in
[
2
,
3
]
, the set described in the following definition is, indeed, a suffixient set of the smallest cardinality.

Definition 3
(Suffixient set of smallest cardinality,
[
2
,
3
]
)

Let
<_{t}
be any total order on
[n]
. We define a set
\mathcal{S}\subseteq[n]
as follows:
x\in\mathcal{S}
if and only if there exists a supermaximal extension
T[i,j]
such that (i)
T[i,j]
is a suffix of
T[1,x]
, and (ii) for all prefixes
T[1,y]
suffixed by
T[i,j]
, if
y\neq x
then
y<_{t}x
.

The measure
\chi
(which is defined as the size of a smallest suffixient set) is also studied as a measure of repetitiveness, due to the combinatorial properties of suffixient sets.

4
Testing suffixiency

In the search of a method to solve Problem
1
, as a first step, by Definition
1
it seems natural to find a strategy to capture all of the rigth-maximal substrings of
T
. In that sense, the following observation will be useful.

Observation 1

For each
c
-right-extension
T[k,l]

(k\leq l)
of every right-maximal string
T[k,l-1]
, there exists at least one
c
-run break
i
such that
T[k,l]
is a suffix of
T[text(i^{\prime})-\mathrm{LCP}_{r}[i],text(i^{\prime})]
, with
i^{\prime}\in\{i-1,i\}
and
\mathrm{BWT}_{r}[i^{\prime}]=c
.

This observation induces an operative method to solve Problem
1
: for each run-break

, with

evaluate if there exists
x\in\mathcal{S}
such that
T[text(i^{\prime})-\mathrm{LCP}_{r}[i],text(i^{\prime})]
suffixes
T[1,x]
.

In the following, we will show a method to compare those strings in
O(1)
time which, at the end, leads to a linear-time algorithm. As a first step, we introduce the
"SA leftmost position such that

is a right-extension"

(Section

). This array allows us to determine if one string suffixes another in

(Section

), and in Section

we present a method to solve Problem
2
by generalizing the approach used in the previous sections.

4.1
The
\mathrm{SLPR}
array

Intuitively, given
x\in[n]
and
i=bwt(x)
,
\mathrm{SLPR}[i]
is a position in the
\mathrm{LCP}_{r}
array (not necessarily unique) such that

is the larger suffix of

which is a right-extension. To compute this value, we start by identifying the closest run-breaks (

to the left of

Let us start by identifying the "closests" run-break to each position in
\mathrm{BWT}_{r}

Definition 4

Let

and let
i=bwt(x)
. We say that

is

-below if for some

Definition 5

Let
x\in[n]
and let
i=bwt(x)
. We say that
x
is
b
-above if for some
b\in[0,n-i-1]
it holds
\mathrm{BWT}_{r}[i]=\dots=\mathrm{BWT}_{r}[i+b]\neq\mathrm{BWT}_{r}[i+b+1].

If

is
a
-below (resp.

-above), the following lemma establishes that there exists a position

(resp.

) such that the string

(resp.

) is equal to the longest common suffix between
T[1,x]
and the right-extension
T[text(i-a)-\mathrm{LCP}[i-a],text(i-1)]
(resp.

) induced by the closest run-break
(i-a)
(resp.
(i+b)
) to the left of
i
(resp. to the right of

).

Lemma 1

Let
x\in[n]
be
a
-below and let
i=bwt(x)
. For any
k\in\argmin\mathrm{LCP}_{r}[i-a,i]
, we have

lcs(T[1,x],T[text(i-a)-\mathrm{LCP}_{r}[i-a],text(i-a)])=T[text(k)-\mathrm{LCP}_{r}[k],text(k)].

Moreover, let
y\in[n]
be
b
-above,
j=bwt(y)
and
Q=T[text(j+b)-\mathrm{LCP}_{r}[j+b+1],text(j+b)]
. For any
l\in\argmin\mathrm{LCP}_{r}[j+1,j+b+1]
, we have

lcs(T[1,y],Q)=T[text(l-1)-\mathrm{LCP}_{r}[l],text(l-1)].

Proof

We show the proof for the
a
-below case. The proof for the
b
-above case is analogous.

We proceed by induction on
i-a
. For the base case,
a=0
and
i-a=i
, we have
\argmin\mathrm{LCP}_{r}[i-a,i]=\{i\}
, so
k=i
, then

lcs(T[1,x],T[text(i)-\mathrm{LCP}_{r}[i],text(i)])=T[text(k)-\mathrm{LCP}_{r}[k],text(k)],

and the claim holds. For the inductive step, assume that the claim holds for
(i-1)-(a-1)
, so
a>0
and
text(i-1)
is
(a-1)
-below. Let
Q=T[text(i-a)-\mathrm{LCP}_{r}[i-a],text(i-a)]
,
j\in\argmin\mathrm{LCP}_{r}[i-a,i-1]
,
l\in\argmin\mathrm{LCP}_{r}[\{j,i\}]=\argmin\mathrm{LCP}_{r}[i-a,i]
, and
P=T[text(j)-\mathrm{LCP}_{r}[j],text(j)]
. Then, by induction hypothesis we have
lcs(T[1,text(i-1)],Q)=P
.
By definition of
\mathrm{LCP}_{r}
, it must hold
lcs(T[1,x],Q)=lcs(T[1,text(i-1)],Q)=P
or
lcs(T[1,x],Q)=lcs(T[1,x],T[1,text(i-1)])=T[x-\mathrm{LCP}_{r}[i],x]
, so
lcs(T[1,x],Q)=T[x-\mathrm{LCP}_{r}[l],x]
. Finally, by the minimality of
l
we have
T[x-\mathrm{LCP}_{r}[l],x]=T[text(l)-\mathrm{LCP}_{r}[l],text(l)]
, as claimed.∎

If
x\in[n]
is
a
-below, then
\min\mathrm{LCP}_{r}[1,i]\leq\min\mathrm{LCP}_{r}[i-a,i]
always holds, so from Lemma

Observation 2

Let
x\in[n]
be
a
-below,

In other words, if

-below, there is no a

-above, then

Observation 3

Let
x\in[n]
be
b
-above,
T[x]=c
, and
i=bwt(x)
. For every
c
-run break

, such that

.

In other words, if
x\in[n]
is
b
-above, there is no
c
-run break
i+b+1<j
such that
T[text(j^{\prime})-\mathrm{LCP}_{r}[j],text(j^{\prime})]

From Observations

4.2

Having computed

Lemma 2

Given

, let

Proof

Let

(
\Rightarrow

(

does not suffixes

In other words, from Lemma

we can note that if we want to know if

and
\mathrm{BWT}[bwt(j)]=\mathrm{BWT}[bwt(x)]

From Observation

4.3
A linear time algorithm

The major drawback of the above strategy is that, for each run-break in
\mathrm{BWT}_{r}
, in the worst case, we need to scan the whole set
\mathcal{S}
we are evaluating for suffixiency. In the following, we propose a method to evaluate each position
x
in
\mathcal{S}
only while
T[1,x]
is suffixed by the strings induced by the run-breaks we process, ultimately leading to a linear-time algorithm.

In a first step, we take advantage of the following.

Lemma 3

Let
i\in[n]
and let
i\neq j\in[n]
such that
j\not\in box(i)

j<i
then for any
k<j
, we have
k\not\in box(i)
. On the other hand, if
i<j
, then for any
j<g
, it holds
g\not\in box(i)
.

Proof

Since
j\not\in box(i)
, we have
j\leq\mathrm{PSV}[i]
or
\mathrm{NSV}[i]\leq j
. In the former case, we have
j<i
, so
k<j\leq\mathrm{NSV}[i]
holds for any
k<j
, then
k\not\in box(i)
.
In the second case, we have
i<j
, thus
\mathrm{NSV}[i]<j<g
holds for any
j<g

For a given set

such that

Proof

we have that
P=T[x-\mathrm{LCP}_{r}[\mathrm{SLPR}[i]],x]

\mathrm{PSV}[i]<\mathrm{SLPR}[j]<\mathrm{NSV}[i]
which means
\mathrm{SLPR}[j]\in box(i)
. Similarly, we have that

if and only if
\mathrm{BWT}_{r}[i]=\mathrm{BWT}_{r}[j]

, which means

nor

\mathrm{SLPR}[i]\not\in box(j)
, from which we conclude

∎

Conclusions and future work

In this paper, we addressed two complementary and natural problems that were left open in our previous work in SPIRE
[
2
]
: determining 1) if a set
S\in[n]
is suffixient for a text
T
and if 2)
S
is a suffixient set of minimum cardinality. We showed that both can be solved efficiently by extending the techniques developed in
[
2
]
. Specifically, we introduced two linear-time algorithms that solve these problems and provided a publicly available implementation of our solutions
https://github.com/regindex/suffixient
.

As future work, we plan to evaluate our algorithm’s performance on real datasets, develop a compressed space version that can work for large-scale datasets, and explore potential applications in the text indexing domain.

Given
\alpha,\beta\in\Sigma^{*}
, the lexicographic order
<_{lex}
is defined as follows:
\alpha<_{lex}\beta
if and only if there exists
j\in\mathbb{N}
such that
\alpha[1,j]=\beta[1,j]
and
j=|\alpha|
or
\alpha[j+1]\neq\beta[j+1]
.

Given
T\in\Sigma^{n}
, the suffix array
\mathrm{SA}(T)
of
T
is a permutation of
[n]
such that for any
1\leq i<j\leq n
holds
T[\mathrm{SA}(T)[i],n]<_{lex}T[\mathrm{SA}(T)[j],n]
.

The longest common prefix
lcp(\alpha,\beta)
between
\alpha
and
\beta
is defined as
lcp(\alpha,\beta)=\lambda
if and only if for every
i\in[\lambda]
it holds
\alpha[i]=\beta[i]
and
\lambda=\min(|\alpha|,|\beta|)
or
\alpha[\lambda+1]\neq\beta[\lambda+1]
.

The Longest Common Prefix array
\mathrm{LCP}(T)
of
T
is defined as
\mathrm{LCP}(T)[i]=lcp(T[\mathrm{SA}(T)[i-1],n],T[\mathrm{SA}(T)[i],n])
, if
i\in[2,n]
, and
\mathrm{LCP}(T)[i]=0
, otherwise.

The Burrows-Wheeler Transform
\mathrm{BWT}(T)
is a permutation of the characters of
T
such that
\mathrm{BWT}(T)[i]
the character in
T
to the left of the starting position of the
i
-th suffix of
T
, namely
\mathrm{BWT}(T)[i]=T[\mathrm{SA}[i]-1]
, if
i\in[2,n]
, and
\mathrm{BWT}(T)[i]=T[n]
, otherwise.

For simplicity, when
T
is clear from context, we denote by
\mathrm{SA}
,
\mathrm{LCP}
, and
\mathrm{BWT}
to
\mathrm{SA}(T)
,
\mathrm{BWT}(T)
, and
\mathrm{LCP}(T)
, respectively.
