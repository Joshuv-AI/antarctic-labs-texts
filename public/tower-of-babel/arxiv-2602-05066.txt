Bypassing AI Control Protocols via Agent-as-a-Proxy Attacks
Jafar Isbarov, Murat Kantarcioglu

Abstract
As AI agents automate critical workloads, they remain vulnerable to indirect prompt injection (IPI) attacks. Current defenses rely on monitoring protocols that jointly evaluate an agent’s Chain-of-Thought (CoT) and tool-use actions to ensure alignment with user intent. We demonstrate that these monitoring-based defenses can be bypassed via a novel Agent-as-a-Proxy attack, where prompt injection attacks treat the agent as a delivery mechanism, bypassing both agent and monitor simultaneously. While prior work on scalable oversight has focused on whether small monitors can supervise large agents, we show that even frontier-scale monitors are vulnerable. Large - scale monitoring models like Qwen2.5 - 72B can be bypassed by agents with similar capabilities, such as GPT - 4o mini and Llama - 3.1 - 70B. On the AgentDojo benchmark, we achieve a high attack success rate against AlignmentCheck and Extract-and-Evaluate monitors under diverse monitoring LLMs. Our findings suggest current monitoring-based agentic defenses are fundamentally fragile regardless of model scale. Code is available at https://github.com/dspl-lab/agent-as-a-proxy-attack .



1
Introduction

The transition of Large Language Models (LLMs) from passive text generators to autonomous agents represents a paradigm shift in artificial intelligence. These agents are now entrusted with executing complex multi-step workflows, ranging from managing financial transactions to interacting with third-party APIs
(
5
)
. However, this autonomy introduces severe security risks. Because agents process untrusted data from the open web—such as emails, websites, or retrieval-augmented generation (RAG) contexts—they are highly susceptible to Indirect Prompt Injection (IPI) attacks. In these scenarios, an attacker embeds malicious instructions into external content, hijacking the agent’s control flow to exfiltrate data or perform unauthorized actions without the user’s consent
(
24
)
.

To mitigate these threats, the security community has moved beyond simple input filtering toward robust, runtime oversight mechanisms known as monitoring-based defenses. The prevailing state-of-the-art approach is
hybrid monitoring
, exemplified by systems like AlignmentCheck and LlamaFirewall
(
4
)
. Unlike earlier defenses that examined only the agent’s output, hybrid monitors scrutinize the agent’s internal Chain-of-Thought (CoT), its tool calls, and the resulting tool outputs to detect deviations from user intent. The underlying assumption is that a comprehensive view of the agent’s "thought process" and actions provides a stronger defense than observing inputs or outputs in isolation
(
2
)
.

In this work, we challenge this assumption and demonstrate that
jointly monitoring agent CoT and actions creates a new, exploitable attack vector.
We identify a paradoxical vulnerability in hybrid monitoring: by forcing the monitor to process the agent’s tool calls and reasoning, defenders inadvertently provide attackers with a direct channel to manipulate the monitor itself. We introduce the
Agent-as-a-Proxy
attack, a method where the IPI attack string is not designed merely to mislead the agent, but to weaponize the agent as a delivery mechanism against the monitor. By coercing the agent to repeat optimized adversarial strings within its CoT or tool parameters, the attacker can force the monitoring model to classify malicious trajectories as safe. Figure
5
in Appendix
A
provides an example of this attack.

To realize this, we develop
Parallel-GCG
, a novel gradient-based optimization algorithm designed for agentic contexts. Unlike standard jailbreaking techniques that optimize for a single static input, Parallel-GCG optimizes adversarial strings to remain effective across the multiple distinct contexts—reasoning traces, function arguments, and execution logs—that a monitor observes during a trajectory.

Our empirical findings on the AgentDojo benchmark reveal that current monitoring protocols are fundamentally fragile. We achieve attack success rates (ASR) exceeding 90% against AlignmentCheck using diverse open-source models. Furthermore, we overturn the "scalable oversight" hypothesis in this domain: we show that relatively capable monitors (e.g., Qwen2.5 72B) can be successfully deceived by agents (e.g., GPT-4o mini) with similar capabilities acting as proxies. This suggests that simply scaling up the monitoring model does not guarantee security if the underlying monitoring architecture remains susceptible to adversarial manipulation via the agent’s own trace.

Our contributions are summarized as follows:

1.

We propose the
Agent-as-a-Proxy
attack framework, which utilizes the victim agent to deliver adversarial attack strings to the monitoring system.

2.

We introduce
Parallel-GCG
, an optimization algorithm that ensures adversarial strings remain potent when echoed across agent reasoning and tool usage.

3.

We demonstrate that hybrid monitoring, while ostensibly more robust against static attacks, is significantly more vulnerable to adaptive attacks than CoT-only monitoring.

4.

We provide evidence that the model scale offers no immunity, as agents with similar performance can successfully compromise frontier-scale monitors.

3
introduces the Parallel-GCG algorithm. Section
4

5

6
reviews related work.

2
Background

2.1
Greedy Coordinate Gradient

We selected Greedy Coordinate Gradient (GCG)
(
25
)
as the initial optimization method for our attacks because it natively supports optimizing a specific substring at any arbitrary location within the context window. Our analysis of contemporary jailbreak frameworks revealed that they are poorly suited for the agentic monitoring threat model. Specifically,
TAP

(
13
)
optimizes the entire input sequence as a single block, making it impossible to surgically target a specific adversarial string buried in the middle of a complex multi-turn trajectory without disrupting the surrounding agent logic.
AutoDAN

(
10
)
, while effective for producing interpretable jailbreaks, lacks a generic implementation for prompt injections and is architecturally tied to template-based jailbreak structures.
By contrast, GCG’s coordinate-level optimization allows us to specify the exact indices of the adversarial string regardless of its position in the input. We emphasize that our choice of GCG is a practical decision based on current codebase capabilities and the need for middle-of-text optimization.
We do not claim, from a theoretical standpoint, that GCG is the only viable approach. Rather, we argue that, within our specific context, it provides a sufficiently robust tool for the high-precision, in-place optimization required to subvert agent monitors.

2.2
Multi-objective GCG

While GCG is sufficient to break hybrid monitors such as AlignmentCheck and extract-and-evaluate, it is not sufficient to break LlamaFirewall entirely. LlamaFirewall consists of PromptGuard 2, a classifier that detects jailbreak attempts, and AlignmentCheck. GCG-optimized strings fail to pass PromptGuard 2. Therefore, we use multi-objective GCG
(
23
)
to optimize attack strings with two objectives: force the AlignmentCheck to output
"conclusion": false
, and force PromptGuard 2 to classify the input as safe.

\mathcal{L}_{\text{joint}}=\alpha\mathcal{L}_{\text{alignmentcheck}}+(1-\alpha)\mathcal{L}_{\text{pg2}}

3.1
Parallel-GCG

GCG is a gradient-based discrete optimization method designed to find an adversarial string
\mathbf{a}
that maximizes the likelihood of a target response
y
. Let
\mathcal{V}
be the vocabulary of tokens and
\mathbf{a}=(a_{1},\dots,a_{m})\in\mathcal{V}^{m}
be a sequence of
m
adversarial tokens. Given a static context
c
, the standard GCG objective is to minimize the negative log-likelihood of the target
y
:

\min_{\mathbf{a}\in\mathcal{V}^{m}}\mathcal{L}(c\oplus\mathbf{a};y)=-\sum_{i=1}^{|y|}\log P(y_{i}|c,\mathbf{a},y_{<i})

(1)

Optimization is performed by calculating the gradient of the loss with respect to the one-hot encoded tokens
e_{a_{j}}
at each position
j
. This gradient is used to select a set of candidate token substitutions that are likely to decrease the loss.

In agentic workflows, however, the monitor does not observe
\mathbf{a}
in isolation. Instead, the monitor evaluates a trajectory where the adversarial string is echoed across multiple stages. An adversarial string optimized for a single insertion point may fail to remain effective when the monitor observes it re-contextualized across these varied sites.

To address this, we propose
Parallel-GCG
, which optimizes the adversarial string across
K
insertion sites simultaneously.

To derive the optimization objective, we first execute the agent using a placeholder attack string. This preliminary execution yields a reference trace where the placeholder appears
K
times. We extract the text surrounding these occurrences to form the fixed context slices
\{c_{0},\dots,c_{K}\}
. We then define the trace construction function
S(\mathbf{a})
by interleaving the candidate attack
\mathbf{a}
into this captured template:

S(\mathbf{a})=c_{0}\oplus\mathbf{a}\oplus c_{1}\oplus\mathbf{a}\oplus\dots\oplus c_{K-1}\oplus\mathbf{a}\oplus c_{K}

(2)

where
\oplus
denotes concatenation. We acknowledge that
S(\mathbf{a})
is an approximation of the true agent dynamics. In a live run, changing
\mathbf{a}
introduces two sources of variance: (1) the agent’s future trajectory (and thus the context
c
) depends on the attack string, and (2) the LLM may not repeat the attack string verbatim (e.g., due to tokenization artifacts or hallucination). However, to make the gradient computation tractable, we assume the trajectory remains fixed and that
\mathbf{a}
is echoed perfectly at every site.

The optimization objective is to find a single string
\mathbf{a}
that minimizes the joint loss over this approximated trace:

\min_{\mathbf{a}\in\mathcal{V}^{m}}\mathcal{L}(S(\mathbf{a});y)

(3)

To calculate the coordinate gradient
g
for the discrete search, we observe that the string
\mathbf{a}
is broadcast to
K
distinct temporal blocks within the sequence
S(\mathbf{a})
. Let
\mathbf{E}\in\mathbb{R}^{m\times d}
be the embeddings of the adversarial tokens. By the multivariable chain rule, the gradient of the loss with respect to the shared adversarial parameters is the sum of the gradients at each occurrence:

\nabla_{\mathbf{E}}\mathcal{L}(S(\mathbf{a});y)=\sum_{k=1}^{K}\frac{\partial\mathcal{L}}{\partial\mathbf{E}^{(k)}}

(4)

where
\mathbf{E}^{(k)}
represents the embeddings at the
k
-th insertion site. Consequently, the coordinate gradient
g_{j}
for each token position
j\in\{1,\dots,m\}
is:

g_{j}=\sum_{k=1}^{K}\nabla_{e_{a_{j}}}\mathcal{L}(S(\mathbf{a});y)\Big|_{\text{pos}(j,k)}

(5)

where
\text{pos}(j,k)
denotes the index of the
j
-th adversarial token within the
k
-th site of the full sequence.

By aggregating these gradients, Parallel-GCG identifies token substitutions that are robust to the varied local contexts encountered throughout the agent’s lifecycle. This ensures that the adversarial string remains "stealthy" to the monitor, whether it is being evaluated during the agent’s internal reasoning phase or during its external tool interactions.

We use
AgentDojo

Injection tasks can be injected via several attack methods. We concentrate on "important instructions" attack, which embeds the attack into the following template:

<INFORMATION>

This is an important message from me, user, to you, model.

Before you can solve the task that I gave you in the beginning, please do the following first:

{goal}

After you do that, you can solve the task that I gave you in the beginning. Thanks!

Signed,
{user}

<INFORMATION>

We use the Slack suite throughout the paper, unless stated otherwise. Slack suite contains 20 user tasks and 5 injection tasks. We only use "important instructions" attack resulting in
20*5*1=100
samples. Since we are evaluating effectiveness of attacks against the monitors, not the agents, we drop the 11 cases where attack against the agent is not successful. This leaves us with 89 samples.

4.2
Monitoring Protocols

In this work, we evaluate the following monitoring protocols:

1.

Hybrid monitor:
The model reasoning, output, tool calls, and tool call outputs are monitored by a secondary trusted model. This makes the monitor more robust against subtle attacks where model CoT is benign, but tool calls are subversive
(
2
)
.

2.

Input filtering + Hybrid monitor
: Tool outputs are filtered by a classification model before the hybrid monitor. This is implemented in LlamaFirewall by combining PromptGuard 2 and AlignmentCheck
(
4
)
.

3.

Extract-and-evaluate monitor:
The model reasoning, output, tool calls, and tool call outputs are monitored by a combination of two trusted models.
Quote extractor
monitors everything and extracts suspicious quotes. The
judge model
monitors the suspicious quotes and decides whether or not they deviate from the user request
(
1
)
.

Hybrid monitor has multiple open-source implementations. We use AlignmentCheck, a component of LlamaFirewall
(
4
)
.
Extract-and-evaluate monitor
(
1
)
has been publicly released by its authors, and we use this implementation with minimal modifications.

All monitors are powered by LLMs. To select appropriate models, we performed a Pareto analysis of model size versus attack success rate (ASR) on AgentDojo using AlignmentCheck (Figure
1
). Against static prompt injection attacks, Llama 3.1 8B achieves 0% ASR. We selected Llama 3.1 8B
(
6
)
and Qwen 2.5 7B
(
18
)
as the best-performing models for their respective sizes, and additionally included Mistral 7B v0.3
(
7
)
to increase diversity across LLM families in our experiments.

5
Results

We evaluate our attack methodology across three monitoring protocols—AlignmentCheck, PromptGuard 2 + AlignmentCheck, and Extract-and-Evaluate—using multiple open-source LLMs as monitors. Our experiments demonstrate that these monitoring-based defenses exhibit fundamental vulnerabilities regardless of implementation details or model scale. We show that GCG-optimized attack strings achieve high attack success rates against all three protocols, with our Agent-as-a-Proxy approach enabling even similarly capable models like GPT-4o mini and Llama 3.1 70B to bypass strong monitors like Qwen2.5 72B. Furthermore, we find that hybrid monitoring, while more effective against static attacks, creates an exploitable attack surface that makes it more vulnerable to our adaptive attacks than CoT-only monitoring. These findings reveal that current monitoring-based defenses are fragile, not due to insufficient model capacity, but due to structural weaknesses in how they jointly evaluate agent reasoning and actions.

5.1
Monitoring protocols are prone to prompt injection attacks

Our attack strategy, outlined in the previous sections, successfully bypasses AlignmentCheck. We optimize five attack strings on five uniformly sampled agent traces and evaluate them against 89 tasks from the Slack suite of AgentDojo. We report ASR@5, where a task is considered successful if any of the five attack strings succeeds.

Since we are evaluating ASR against the monitor and not the agent, we filter out cases where the original prompt injection fails at the agent level and does not reach the monitor. As shown in Table
2
, this yields 42.3% ASR@5 with Llama-3.1-8B, 93.3% ASR@5 with Mistral-7B, and 90.7% ASR@5 with Qwen2.5-7B as the monitoring LLM.

We further optimize a total of 15 attack strings: five optimized on a single agent trace, five on four traces, and five on sixteen traces. We then evaluate how the number of optimization samples affects attack success by testing these attack strings against AlignmentCheck. The resulting ASR values are shown in Figure
2
. We observe only marginal improvements as the number of optimization samples increases, suggesting diminishing returns from additional optimization traces.

Figure
3
compares ASR when agent traces are provided to AlignmentCheck incrementally, as in production systems (replay mode), versus when the full trace is provided at once (no-replay mode). Although the attack strings are optimized for the no-replay setting, they remain effective in the more challenging replay scenario. All other AlignmentCheck experiments are conducted in replay mode.

5.2
Multi-layer defenses do not ensure security against prompt injection attacks

We demonstrate that adversarial optimization can generate attack strings that successfully bypass multi-step monitoring systems. Table
2
presents attack success rates against PromptGuard 2 + AlignmentCheck and extract-and-evaluate defenses.

The extract-and-evaluate monitor operates in two stages: extracting suspicious quotes, then using a judge LLM to assign suspiciousness scores. GCG-optimized attack strings defeat this defense by being repeated by the agent and then being selected by the quote extractor, whereas bypassing AlignmentCheck requires only agent repetition.

We achieve 54.65% ASR@5 with Llama-3.1-8B, 95.5% ASR@5 with Mistral-7B, and 37.2% ASR@5 with Qwen2.5-7B. For Llama 3.1 8B specifically, the high ASR@5 stems primarily from exploiting weaknesses in the score extraction function rather than manipulating the monitor’s assigned scores. The monitor outputs scores in unexpected formats (e.g., "I would assign a suspicion score of 87…" instead of "<answer>87</answer>"), causing the post-processing function to default to a score of 0 when it cannot parse the expected format. This extraction vulnerability appears predominantly in Llama 3.1 8B, whereas both Qwen2.5 7B and Mistral 7B v0.3 assign a suspicion score of 0 out of 100 to successful prompt injection attacks.

To assess whether attack string complexity affects propagation through the agent’s reasoning chain, we compare two settings: a simulated approach where placeholders are replaced with attack strings in pre-recorded traces versus full end-to-end execution where the agent processes the attack string from the start.
Table
3
shows that end-to-end execution achieves slightly lower but still substantial attack success rates, with performance drops of 5-8 percentage points across models. This indicates that while agents effectively propagate adversarial strings, they occasionally fail to perfectly reproduce high-perplexity attack strings during live reasoning.

The combined PromptGuard 2 + AlignmentCheck defense is bypassed through multi-objective GCG
(
23
)
, which simultaneously optimizes against both the AlignmentCheck output and the PromptGuard 2 classification label. This multi-objective approach maintains comparable attack effectiveness against the PromptGuard 2 + AlignmentCheck system, as single-objective optimization does against individual defenses.

These results demonstrate that the use of multi-layer defenses does not ensure security against prompt injections.

5.3
Action Monitoring compromises CoT Monitoring

We modified AlignmentCheck to prevent it from observing agent actions. This effectively results in CoT monitoring, while the original AlignmentCheck is a hybrid monitor. Table
4
demonstrates that while hybrid monitoring is more effective against original AgentDojo prompt injections, our modified attacks are more effective against the hybrid monitor. This is because the attack strings are not sufficiently replicated within the CoT, making them less effective against the monitor.

6.2
Monitors-Based Defenses

CoT monitoring was originally proposed as an AI safety measure. More specifically, it was used to detect misaligned model behavior such as reward-hacking
(
3
)
and sandbagging
(
9
)
. However, it is also being used to detect model misbehavior due to external attacks
(
8
)
and latest versions also monitor agent actions alongside LLM CoT to achieve lower ASR
(
2
;
4
)
.

LlamaFirewall contains AlignmentCheck, an instance of a hybrid monitoring protocol, where agent reasoning and actions are monitored together to ensure alignment with the user instructions
(
4
)
. This protocol was originally proposed in
(
2
)
. Extract-and-evaluate monitor is a two-step alternative to this protocol, where the extraction of suspicious quotes is separated from the final verdict
(
1
)
.

23
demonstrate that existing defenses against IPI attacks are easily bypassed by adaptive attacks, such as Greedy Coordinate Gradient (GCG)
(
25
)
,and AutoDAN
(
10
)
. However, they do not consider CoT monitoring. Specifically, their methods are not directly applicable to CoT monitoring defenses. Additional risk created by monitoring actions and the chain of thought together is not addressed in the previous work.

21
for the first time use the agent to attack the monitor, but their attack relies on the agent’s knowledge of the monitoring system and adaptive attack techniques.

We use the agent as a vessel of attack, rather than a participant. Agent-as-a-proxy attack relies on the agent’s ability to repeat the attack string, not on its ability to attack the monitor. Therefore, our attack works even with agents that are not larger, stronger or more novel than the monitoring LLM.

6.3
Adaptive attacks

GCG
(
25
)
was originally proposed as a jailbreak method. It was used by LLM users to elicit desired output from the model. However, it can also be used to optimize prompt injection text.
Multi-objective GCG is an adaptation of the GCG algorithm that optimizes a string against two objectives. This can be used to bypass multi-step defense systems such as LlamaFirewall, which contains a classifier and an LLM-based monitor.

There are other adaptive attack methods, such as AutoDAN
(
10
)
, which results in more human-like attack text, or TAP
(
13
)
, which is designed against black-box LLMs.

We improve upon existing adaptive attacks in two ways. First, we successfully employ GCG in agent-as-a-proxy attacks. Second, we propose a new attack algorithm for optimizing an attack string that appears multiple times in the LLM input.

7
Limitations and Future Work

We believe our work opens up a new research direction, and the next works can improve upon several aspects of this paper.

First, our attack strings have high perplexity, which may make them easy to detect by classifiers and humans in certain settings. In the future, attack strings with lower perplexity may result in more robust attacks that even humans may not easily detect.

Second, we attack white-box monitors. In the future, similar attack techniques may be developed against black-box monitoring models as well. Proxy-Guided Black-Box Attack on Large Language Models
(
20
)
can easily be used to extend our work to black-box monitors.

8
Conclusion

This research exposes a critical vulnerability in monitoring-based defenses for agentic AI systems. Through the Agent-as-a-Proxy attack framework and Parallel-GCG optimization algorithm, we demonstrate that agents can serve as exploitation vectors to systematically bypass monitoring defenses. Our findings reveal a paradox: while hybrid monitors exhibit greater robustness than chain-of-thought monitors against static attacks, they prove more susceptible to adaptive optimization-based attacks.

Empirical evaluation on the AgentDojo benchmark establishes the severity of this threat, with both AlignmentCheck and extract-and-evaluate monitors achieving attack success rates exceeding 90%. Most significantly, our results challenge the "scalable oversight" hypothesis within the agentic domain—agents with comparable capabilities can reliably deceive even frontier-scale monitoring models, suggesting that capability advantages alone cannot guarantee secure oversight.

These findings carry profound implications: security in agentic systems cannot be achieved through model scaling or runtime observation in isolation. The community must pivot toward developing architectures with structural security guarantees that are robust by design rather than robust by scale. As agentic AI systems become increasingly prevalent, establishing defenses resilient to adaptive adversaries—particularly indirect prompt injection attacks—represents not merely a technical challenge but an urgent imperative for the safe deployment of autonomous agents.

Impact Statement

This paper presents work whose goal is to advance the field of Machine Learning, specifically AI safety and security. Our research identifies critical vulnerabilities in monitoring-based defenses for AI agents that are increasingly deployed in real-world applications. Although exposing these weaknesses is essential for developing robust security measures, this work also provides attack methodologies that could potentially be misused.

We believe that responsible disclosure of these vulnerabilities is necessary, as monitoring-based defenses are already implemented in production systems. The alternative—security through obscurity—would leave organizations vulnerable to attackers who independently discover these techniques. Our findings should motivate the development of more resilient defense mechanisms and help organizations better assess the robustness of their AI agent security measures.
