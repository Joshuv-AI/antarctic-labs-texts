From LLMs to LRMs: Rethinking Pruning for Reasoning-Centric Models
Longwei Ding, Anhao Zhao Fanghua Ye, Ziyang Chen, Xiaoyu Shen

Abstract
Large language models (LLMs) are increasingly costly to deploy, motivating extensive research on model pruning. However, most existing studies focus on instruction-following LLMs, leaving it unclear whether established pruning strategies transfer to reasoning-augmented models that explicitly generate long intermediate reasoning traces. In this work, we conduct a controlled study of pruning for both instruction-following ( LLM-instruct ) and reasoning-augmented ( LLM-think ) models. To isolate the effects of pruning, we align pruning calibration and post-pruning recovery data with each model’s original training distribution, which we show yield more stable and reliable pruning behavior. We evaluate static depth pruning, static width pruning, and dynamic pruning across 17 tasks spanning classification, generation, and reasoning. Our results reveal clear paradigm-dependent differences: depth pruning outperforms width pruning on classification tasks, while width pruning is more robust for generation and reasoning. Moreover, static pruning better preserves reasoning performance, whereas dynamic pruning excels on classification and generation but remains challenging for long-chain reasoning. These findings underscore the need for pruning strategies that explicitly account for the distinct characteristics of reasoning-augmented LLMs. Our code is publicly available at https://github.com/EIT-NLP/LRM-Pruning .

Model pruning has emerged as one of the most widely adopted approaches for improving LLM efficiency
43
;
28
;
30
. Early work has primarily focused on
static pruning
, where a fixed subset of parameters is removed prior to deployment. Within this paradigm,
static depth pruning
reduces inference cost by removing entire layers, shortening the model and decreasing sequential computation
(
30
;
21
)
. In contrast,
static width pruning
reduces per-layer computation by shrinking hidden dimensions or pruning channels while preserving the original network depth
(
28
;
4
)
. More recently,
dynamic pruning
has been explored, which adaptively skips parts of the computation during inference based on input-dependent signals, rather than permanently removing parameters
(
34
;
20
;
58
)
. Together, these techniques form a mature toolkit for accelerating LLMs.

Meanwhile, the LLM landscape is undergoing a paradigm shift from instruction-following models, which we refer to as
LLM-instruct
, to reasoning-augmented models, denoted as
LLM-think

51
;
11
. Unlike LLM-instruct
(
54
)
, which generate a direct response with reasoning implicitly embedded, LLM-think explicitly externalize their reasoning process by producing step-by-step intermediate traces prior to the final answer
(
49
)
. While this shift substantially improves performance on complex tasks, it also results in markedly longer generations, often spanning thousands of tokens
(
7
;
53
)
. Despite these fundamental changes in model behavior and output characteristics, existing pruning research has almost exclusively focused on LLM-instruct. This gap motivates a central question:
does pruning for LLM-think require new strategies, or can existing approaches generalize across paradigms?

Addressing this question necessitates a carefully controlled pruning pipeline. We therefore begin by revisiting a critical yet often overlooked design choice in prior work:
the selection of datasets used for pruning calibration and post-pruning recovery
. However, prior studies adopt highly heterogeneous datasets for these stages, ranging from general-domain corpora to instruction-tuning data, often without systematic justification
(
33
;
44
)
. Such inconsistency introduces confounding factors, making it difficult to disentangle the effects of pruning from those of distribution mismatch.

To enable a principled comparison, we adopt a controlled setting in which calibration and recovery data are strictly aligned with the original training distribution of the target model. Under this setting, we construct matched model–dataset pairs for both paradigms. For
LLM-instruct
, we use the open-sourced Tulu model
(
22
)
together with its full instruction-following fine-tuning corpus. For
LLM-think
, we derive a reasoning-augmented counterpart by further fine-tuning the same base model on OpenThoughts
(
17
)
, a dataset designed to elicit explicit multi-step reasoning across diverse difficulty levels. This alignment ensures that each model is pruned, calibrated, and recovered using data drawn from its own training distribution, thereby isolating the impact of pruning itself.
As we show empirically, such alignment best preserves pre-pruning performance and leads to substantially more stable and effective pruning behavior compared to using mismatched datasets.

Under this controlled setting, we conduct a comprehensive evaluation of three categories of pruning strategies on both LLM-instruct and LLM-think across
17
diverse classification, generation, and reasoning tasks. Our experiments yield several key empirical findings. First, static depth pruning is more effective than static width pruning on classification tasks, whereas the opposite trend holds for generation and reasoning tasks, where width pruning degrades performance more gracefully. Second, dynamic pruning with unconstrained token-level routing benefits classification and generation but proves substantially harder to optimize for long-chain reasoning, suggesting that aggressive computation skipping is particularly risky for reasoning-intensive workloads. Finally, while dynamic pruning generally outperforms static methods on classification and generation, static pruning retains higher performance on reasoning tasks, highlighting an important gap in current dynamic pruning approaches.

Background

LLM-instruct and LLM-thinking

The rapid progress of LLMs has not only improved their instruction-following ability but also expanded their scope toward explicit reasoning. This shift has given rise to two major families: instruction-following models (
LLM-instruct
), which are optimized to produce outputs that closely align with user-specified instructions, and reasoning-augmented models (
LLM-think
), which are trained to generate long chains of thought (CoT) reasoning before arriving at final answers.
Although the two are built upon the same underlying architecture, recent studies show that they diverge significantly in both internal representations and emergent behaviors.
Mechanistically, LLM-think retain richer contextual information across layers and exhibit higher token-level entropy
(
40
;
47
)
. In terms of attention, LLM-instruct generally display diverse specialization across heads, with each attending to different token subsets
(
15
)
, whereas LLM-think show considerable overlap in tokens attended by different heads
(
55
)
.

Formalizing Structure Pruning Strategies

Model pruning in LLMs can be broadly categorized into two approaches:
unstructured pruning
, which removes individual weights based on their magnitudes or importance
(
23
)
, and
structured pruning
, which discards entire coupled structures
(
9
)
. Although unstructured pruning is conceptually simple, it rarely yields practical acceleration on modern GPUs (e.g., Nvidia GPUs typically require over 90% sparsity for speedup
(
39
;
48
)
), while LLMs usually collapse once sparsity exceeds 50%
(
42
)
. Therefore, we focus on structured pruning, which is both hardware-friendly and effective. Structured pruning can be further categorized into
width pruning
, which reduces hidden dimensions, and
depth pruning
, which removes redundant layers either statically (the same set of layers is pruned for all inputs) or dynamically (the pruned layers vary depending on the input). The architectures of each method are illustrated in
Figure 1
. To the best of our knowledge, a unified and systematic formulation of these strategies has not been explicitly articulated in the existing literature. We therefore introduce the following formal definitions, which serve as the foundation for our subsequent analysis.

Formally, let
\mathbf{H}_{l}\in\mathbf{R}^{N\times d}
denote the hidden representations at layer
l
, where
N
is the sequence length and
d
is the hidden dimension.

•

Static width
pruning reduces the hidden dimension
d
to
d^{\prime}<d
by removing less important neurons:

\mathbf{H}_{l}^{\prime}=\mathbf{H}_{l}[:,\mathcal{I}_{l}],\quad|\mathcal{I}_{l}|=d^{\prime},

(1)

where
\mathcal{I}_{l}
indexes the retained neurons in layer
l
.

•

Static depth
pruning removes entire layers, keeping only a subset
\mathcal{L}^{\prime}\subseteq\{1,\dots,L\}
of layers:

\mathbf{H}_{\mathcal{L}^{\prime}}=\{\mathbf{H}_{l}\mid l\in\mathcal{L}^{\prime}\},\quad|\mathcal{L}^{\prime}|=L^{\prime}<L.

(2)

Static depth pruning computes a fixed importance score for each layer and permanently removes those identified as redundant. Typical criteria for scoring include:

–

Block Influence (BI)
(
30
)
measures the cosine similarity between the input and output representations of a layer. Layers with high similarity are considered to contribute little new information and are thus pruned.

–

Perplexity (PPL)
(
21
)
quantifies the impact of individually removing a layer on validation perplexity. Layers that cause minimal degradation are considered less critical.

–

Taylor
(
21
)
estimates the sensitivity of the loss to parameter removal through the first-order gradient–weight product, and the layer with low aggregated sensitivity are pruned.

•

Dynamic depth
pruning introduces a router module, denoted as
R(\cdot)
, which determines whether a block is executed or skipped for each input token
(
35
;
20
;
58
)
.
Let
x
denote the input to a block, which may correspond to a Transformer layer, an attention module, or a MLP.
A binary gate
g
governs the execution, and is defined as

g=R(x)\in\{0,1\}.

(3)

where
g=1
indicates execution and
g=0
indicates skipping.
Let
f(\cdot)
denote the computation performed by the block; the output is then updated as:

x^{\prime}=g\cdot f(x)+x.

(4)

Problem Setting

Let
M
and
M^{\prime}
denote the original and compressed LLM respectively.
Following common practice, we quantify the degree of pruning using the
compression ratio
, defined as the reduction in the average number of parameters active per token:
58
:

R(M,M^{\prime})=1-\frac{|M^{\prime}|}{|M|}

(5)

where
|M|
and
|M^{\prime}|
denote the average per-token parameters in the original and pruned models, respectively.
To evaluate utility, we define
performance retention
as the ratio
\text{Perf}(M^{\prime})/\text{Perf}(M)
, which measures how effectively the pruned model maintains the functional capabilities of the dense baseline. Consequently, our objective is to identify a pruning strategy that maximizes the compression ratio
R(M,M^{\prime})
while minimizing degradation in performance retention.

Evaluated Pruning Methods

To systematically evaluate pruning in both LLM-instruct and LLM-think models, we consider representative methods from three main categories of structured pruning.

•

Static depth pruning
reduces model depth by removing entire transformer layers. We consider SLEB, an iterative method that recomputes layer-importance scores after each pruning step;
ShortGPT

(
30
)
, which prunes layers based on input–output representation cosine similarity; and
Shortened-PPL
/
Shortened-Taylor

(
21
)
, which identify and remove layers using perplexity (PPL) and Taylor-based criteria, respectively.

•

Static width pruning
reduces model width by pruning attention heads or shrinking the hidden-state dimension. We adopt
LLM-Pruner

(
28
)
, a gradient-based method that prunes coupled structures, and
SliceGPT

(
4
)
, which removes low-variance components from weight matrices via principal component analysis.

•

Dynamic depth pruning
reduces per-input computation by adaptively skipping layers or submodules.
MOD

(
35
)
selects a subset of tokens to process in each layer via Top-
k
routing.
D-LLM

(
20
)
uses a router to decide whether to execute each transformer layer.
SkipGPT

(
58
)
combines global token-aware routing with decoupled pruning of MLP and self-attention modules, and defines the pruning ratio as the mean token-level skipping rate across the two modules.

Effects of Calibration/Recovery Data

Before analyzing the effects of different pruning strategies, we first examine a fundamental yet often overlooked design choice in the pruning pipeline:
the datasets used for calibration and post-pruning recovery
. In modern LLM pruning methods, these two stages constitute the most critical components of the pipeline. Calibration estimates the importance of model structures (e.g., layers or channels) to guide pruning decisions, while post-pruning recovery aims to restore performance by adapting the remaining parameters after pruning. While prior work adopts heterogeneous datasets, their choice for calibration and recovery data is rather arbitrary.

To establish a well-founded experimental setting for subsequent analysis, we first investigate whether aligning both pruning calibration and post-pruning recovery with the model’s original training distribution is beneficial for preserving pre-pruning performance. To this end, we examine two representative pruning methods: ShortGPT for static depth pruning and SliceGPT for static width pruning. We compare general-domain corpora (e.g., C4, PTB, and WikiText2) and standard instruction-tuning datasets (e.g., Alpaca) against the model’s original training corpora, namely
tulu-3-sft-mixture
for LLM-instruct and
openthoughts
for LLM-think, under a fixed pruning ratio of 20%. Additional results that separately disentangle the effects of the calibration dataset and the post-pruning recovery dataset are reported in
Appendix D
.

We hypothesize that this behavior may arise from SkipGPT’s highly flexible compute allocation: frequent token-wise routing changes can destabilize depth-wise computation trajectories, reducing path continuity across layers. In contrast, MOD enforces a Top-
k

Overall, these results suggest that SkipGPT’s highly flexible token-wise routing works well for LLM-instruct but is less reliable for LLM-think, whereas MOD’s Top-
k
constraint trades adaptivity for more stable reasoning retention.

Static depth vs. width pruning.

For LLM-instruct, as shown in

and

, static depth pruning slightly outperforms width pruning on classification tasks, whereas width pruning demonstrates greater robustness on generation tasks. While both approaches perform similarly at a 20% pruning ratio, increasing the ratio to 40% leads to a markedly larger performance drop for depth pruning (55.57%) than for width pruning (41.83%).
This pattern extends to LLM-think: despite marginally stronger performance from depth pruning at 20%, both methods deteriorate rapidly at higher pruning levels. At a 40% pruning ratio, depth pruning drops by 85.38%, compared to 77.69% for width pruning.
This gap reflects a fundamental structural difference between depth and width pruning. While depth pruning reduces the model’s depth, width pruning primarily limits representational capacity. As a result, width pruning exhibits more stable performance on generation and reasoning tasks at higher sparsity levels.
Overall, these results suggest that preserving model depth is more critical than preserving width, implying that depth should be pruned conservatively while width admits more aggressive compression.

Conclusion

Static vs. Dynamic Pruning.

As shown in
Figure 4
, on LLM-instruct, dynamic pruning methods consistently outperform static ones. In particular, both SkipGPT and MOD achieve superior performance across pruning ratios, with the advantage becoming more pronounced at higher pruning ratios.
In contrast, this trend reverses on LLM-think: dynamic pruning methods consistently underperform static pruning methods. As shown in
Figure 5
, under a 20% pruning ratio, static pruning methods reliably converge to low-loss regions, whereas many dynamic methods display unstable or even pathological optimization dynamics and settle at substantially higher training loss. This optimization gap provides a mechanistic explanation for the weaker downstream performance of dynamic pruning on LLM-think. Notably, MOD is a clear exception among dynamic approaches, exhibiting strong and stable convergence that is comparable to static pruning methods.
These results indicate that reasoning performance hinges less on whether pruning is static or dynamic than on whether the pruning strategy preserves continuous computation paths along the depth dimension. Accordingly, static width pruning methods (e.g., LLM-Pruner, SliceGPT) and dynamic pruning(MOD) perform better on LLM-think.

For LLM-instruct, dynamic pruning yields the best performance, whereas for LLM-think, static pruning retains higher performance.

Conclusion

6
Conclusion

We study whether pruning methods developed for LLM-instruct generalize to LLM-think, where models explicitly generate long intermediate reasoning traces. Using a controlled pipeline that aligns calibration and post-pruning recovery with each model’s original training distribution, we construct matched model–dataset pairs for both paradigms and evaluate static depth pruning, static width pruning, and dynamic pruning across 17 classification, generation, and reasoning tasks. The results show clear paradigm and task-dependent trade-offs: static depth pruning is more effective for classification, whereas static width pruning degrades more gracefully for generation and reasoning. Dynamic pruning benefits classification and generation but is substantially harder to optimize for long-chain reasoning, making aggressive compute skipping risky for reasoning-intensive workloads. Overall, dynamic methods lead on classification and generation, while static pruning better preserves reasoning performance, highlighting an important gap in current dynamic pruning for LLM-think.

Limitations

Our experiments are conducted on Llama-8B–scale language models, and we do not explicitly evaluate how the observed pruning behaviors generalize across model scales. While our findings reveal clear and consistent trends within this setting, extending the analysis to smaller and larger models remains an important direction for future work.

Appendix B
Related Work

The multi-layer Transformer architecture of LLMs inherently contains substantial parameter redundancy. Model pruning is a key technique to mitigate this redundancy by removing non-essential components. In practice, hardware-friendly structured pruning, which eliminates entire components such as layers, channels, or attention heads, has become the dominant approach and can be broadly categorized into static depth, static width, and dynamic depth methods.

B.1
Static Depth Pruning

Static depth pruning reduces model depth by removing fixed Transformer layers or their internal submodules (Attention or MLP). The main challenge is to reliably estimate layer importance. Most existing approaches rely on one-shot scoring. Shortened Llama
(
21
)
introduces three types of importance estimators: Magnitude, which approximates a layer’s contribution using weight norms; Taylor, which estimates the change in loss when the layer’s weights are removed; and PPL, which directly measures the increase in PPL after removing a layer. These methods often underestimate the importance of early and late layers, so practical pruning pipelines typically keep the first four and the last two layers intact. ShortGPT
(
30
)
further proposes Block Influence (BI), which measures redundancy by comparing the cosine similarity between a layer’s input and output. In contrast, SLEB
(
41
)
adopts an iterative strategy, recomputing importance scores after each pruning step for the remaining layers.

While these approaches focus primarily on layer-level redundancy, they overlook finer-grained intra-layer structure. To address this, Joint Layer Drop
(
18
)
removes Attention and MLP modules jointly based on their similarity, and BlockPruner
(
60
)
decomposes each layer into Attention and MLP blocks for iterative pruning. Beyond direct deletion, Laco
(
56
)
introduces layer collapse, replacing the parameters of multiple layers with a single layer while preserving the internal structure of the LLM.

B.2
Static Width Pruning

Static width pruning aims to reduce the computational cost of Transformer models by removing redundant components within submodules, such as attention heads or MLP neurons, while typically preserving the residual stream dimensionality. A central challenge lies in defining reliable importance criteria for identifying removable components.

Based on how pruning decisions vary across layers, existing approaches can be broadly categorized as uniform or non-uniform in the pruning process. Non-uniform methods, such as Sheared-LLaMA
(
50
)
, LLM-Pruner
(
28
)
, and FLAP
(
2
)
, leverage importance metrics, such as weight norms, Taylor-based sensitivity, or activation statistics, to adaptively determine pruning decisions for each layer or submodule.
Although these methods typically retain a consistent post-pruning layer structure, they primarily reduce submodule-internal widths rather than the residual stream, which limits their ability to achieve substantial hardware-level acceleration with standard inference kernels.

In contrast, approaches such as SliceGPT
(
4
)
directly compress the residual stream by projecting hidden representations onto a lower-dimensional subspace shared across all layers. This uniform reduction of the residual stream dimension yields consistent tensor shapes throughout the network, enabling efficient utilization of optimized GPU kernels and resulting in more stable inference and tangible speedups.

B.3
Dynamic Depth Pruning

Unlike static methods, dynamic pruning customizes the computational path for each input at inference time, reducing computation by executing only the essential components.

A widely studied approach is early exit
(
38
;
46
;
12
;
13
;
8
;
14
)
. By inserting intermediate classifiers at multiple depths, early exit allows “simple” inputs to terminate inference early, bypassing the remaining layers. While this can substantially accelerate inference, it may compromise the model’s ability for deep semantic reasoning.

Another paradigm is layer skipping, where router modules dynamically determine whether a layer should be executed or bypassed. Layer skipping can be divided into vertical dynamics (D-LLM, SkipGPT) and horizontal dynamics (MOD). Vertical dynamics control the allocation of computation along the model depth based on token importance, whereas horizontal dynamics distribute computation unevenly across the sequence dimension using a Top-
k
constraint.
For
vertical dynamics
, D-LLM
(
20
)
introduces a dynamic decision module at each layer to adaptively execute network units and implements an efficient eviction strategy for the KV cache. Similarly, SkipGPT
(
58
)
combines global token-aware routing with decoupled pruning of MLP and self-attention layers, enabling fine-grained resource allocation. For
horizontal dynamics
, MOD
(
35
)
applies Top-
k
routing to select which tokens are processed by each layer’s self-attention and MLP modules. Together, these methods provide a flexible framework for balancing inference efficiency and per-input model performance.
