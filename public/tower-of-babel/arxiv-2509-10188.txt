Abstract




Abstract:

Although the notion of computation with preprocessing is commonly used in computer science, its computational complexity has been little studied.
In this paper, we study the class
\cpp
of operations
\mathtt{op}:\mathbb{N}^{k}\to\mathbb{N}
, of any fixed arity
k\geq 1
, satisfying the following property:
for each fixed integer
d\geq 1
, there exists an algorithm for a RAM machine which, for any input integer

N\geq 2
,

•pre-computes some tables in
O(N)
time,

•then reads
k
operands
x_{1},\ldots,x_{k}<N^{d}
and computes
\mathtt{op}(x_{1},\dots,x_{k})
in
constant time
.

We show that the
\cpp
class is robust and extensive and satisfies several closure properties.
It is invariant depending on whether the set of primitive operations of the RAM is
\{+\}
, or
\{+,-,\times,\mathtt{div},\mathtt{mod}\}
, or any set of operations in
\cpp
provided it includes
+
.
We prove that the
\cpp
class is closed under composition
and, for fast growing functions, is closed under inverse.
We also show that in the definition of
\cpp
the constant-time procedure can be reduced to a single return instruction.
Finally, we establish that linear preprocessing time is not essential in the definition of
the
\cpp
class: this class is not modified if the preprocessing time is increased to
O(N^{c})
, for any fixed
c>1
, or conversely, is reduced to
N^{\varepsilon}
, for any positive
\varepsilon<1
(provided the set of primitive operation includes
+
,
\mathtt{div}
and
\mathtt{mod}
).
To complete the picture, we demonstrate that the
\cpp
class degenerates if the preprocessing time reduces to
N^{o(1)}
.

It is significant that the robustness of
\cpp
entails the robustness of more classical complexity classes on RAMs such as
LinTime
, and more generally
\textsc{Time}(T(N))
for usual time functions
T
, or even the enumeration complexity class
\cdlin
.

Introduction

The notion of computation with preprocessing is in common use in
computer science. The goal is to answer questions asked by users as
quickly as possible. The price to pay is a computation of auxiliary
data, an off-line phase which may be quite long because it is carried
out once beforehand. This has long been the case in database systems
where a set of indexes are preprocessed in order to instantly answer the most
frequently asked queries
[
18
,
41
]
. In
artificial intelligence, what we call knowledge compilation serves a
comparable purpose as Darwiche and Marquis
[
17
,
31
]
write: “The key motivation behind knowledge compilation
is to push as much of the computational overhead into the off-line
phase, which is amortized over all on-line queries.”

Since reading an input of size
N
requires time
N
, it is well accepted that the minimum time complexity class of
\mathtt{Input}\mapsto\mathtt{Output}
problems is linear time

O(N)
which turns out to be a robust complexity class
[
24
,
26
,
35
]
.
For problems computable with preprocessing, it seems clear that the minimum preprocessing time is also
O(N)
to read the input and the minimum computation time is
O(1)
if the question asked by the user and its response are of constant size
[
7
]
.

In the most basic version, the preprocessing consists of constructing
an array
T
of
O(N)
integers in linear time and the on-line phase
consists of directly accessing an element
T[a]
for an index
a

given by a user. As an example, using addition as the only primitive
operation (“primitive” here means “of unit time cost”) one can
construct, for each input integer
N>0
, an array

\mathtt{SquareRoot}[0..N]
such that
\mathtt{SquareRoot}[x]\coloneqq\left\lfloor\sqrt{x}\right\rfloor
, in
O(N)
time. This allows a user to obtain
\left\lfloor\sqrt{a}\right\rfloor
by direct access, for any integer
a\leq N
that she
needs.

It seems natural and useful to ask whether the following generalization is possible.
For any fixed integer
d\geq 1
, is there an algorithm, using addition as the only primitive operation, such that, for any input integer
N
, the algorithm computes some tables in time
O(N)
and then, by using these tables and after reading any integer
x<N^{d}
, the algorithm computes
\left\lfloor\sqrt{x}\right\rfloor
in
constant time
?
In
[
25
]
we answered this question positively.
The solution is not trivial because only tables of size
O(N)
, and not of size
O(N^{d})
, are authorized.

In this paper which complements paper
[
25
]
but can be read independently, we study the class of operations
\mathtt{op}:\mathbb{N}^{k}\to\mathbb{N}
, of any arity
k\geq 1
, satisfying the following property:
for each fixed integer

, there exists an algorithm
\mathcal{A}

such that, for all input integer

,

•

Preprocessing (off-line phase):

\mathcal{A}

•

.

For a set (or list) of operations

In

Comparison with literature:

Since we study classical arithmetic operations, addition, multiplication, division, square root, etc., the reader may wonder how our algorithms compare to those of other communities, particularly in computer algebra, see for example
[
44
]
.
The
setting
and the
goal
of our results are
completely different
.

While the algorithms in the literature deal with “long integers” whose reference is the binary length of the operands,
our algorithms deal with “short integers”, i.e. integers
polynomial in the reference integer

N
, which is often the size of the input.
Equivalently, our operands have binary length
O(\log N)
and are represented in base
N
with O(1) digits.
This is a necessary condition for obtaining
constant-time
algorithms.

The main difference is the following:
while the goal of arithmetic algorithms in the classical setting
[
1
,
16
,
30
,
34
]
is to
minimize the computation time
with respect to the length (or value) of the operands, our sole goal is to obtain
constant-time algorithms modulo some preprocessing
1
1

1

However, the constant-time algorithm (with preprocessing) that we present in this paper for division is exactly a copy of the tricky algorithm presented in Knuth’s book
[
30
]
, Section 4.3.1, and attributed to Pope and Stein
[
33
]
.
(Additionally, to achieve constant time, we first convert the operands to a suitable base and complete the algorithm by pre-computing some tables.)
.

Our central object in this paper is the class of operations computable in constant time with linear-time preprocessing.

Our input and output instructions can be executed

Our algorithmic conventions.

From now on, we will place ourselves in an even broader framework corresponding to the usual presentation of algorithms, which we also call RAMs or programs interchangeably.
We freely use “if…then…else…” statements, “while” and “for” loops, and procedures with “return” instructions, also called functions.
Additionally, we allow elaborate test conditions in conditional and while instructions.

This allows us to replace the reference integer

by its root

Thus, any operand or result

Therefore, starting from any reference integer

Using the same idea, we will show that we can also reduce a preprocessing time

, see Theorem

below.

The following general definition which extends

by mentioning the preprocessing time will allow us to formalize precisely the results of this section.

Definition 6
.

For a set (or a list)

of operations and a function

In the notation introduced in Definition

6
Minimality of the
\cpp

In this section, we prove two minimality properties of the class
\cpp(+)
of operations computable, using only addition, in constant time with linear-time preprocessing:

1.

the class becomes

, and degenerates, if the preprocessing time is reduced to

as the only primitive RAM operation, addition

6.1
Minimality for preprocessing time

Can preprocessing time be reduced to

The following result answers “no”:
multiplication can no longer be computed in constant time if the preprocessing time – or even more weakly, the size of the pre-computed tables – is reduced to

Theorem 8

There is

1.

Conclusion and other open problems

In this paper, we have proven that the
\cpp
class is very robust:

•

it is not sensitive to the set of primitive operations of the RAM, provided it includes addition
(Theorems
2
,
4
and
12
, also proved in
[
25
]
);

•

it is not sensitive to the preprocessing time, which can be
reduced
from
O(N)
to
N^{\varepsilon}
, for all
\varepsilon>0
, if
+
,
\mathtt{div}
,
\mathtt{mod}
are among the primitive operations (Theorem
5
and Corollary
2
) or
increased
to
N^{c}
, for all
c>1
(Theorem
6
);

•

any constant-time procedure can be reduced to an expression (a return instruction) involving only additions and direct memory accesses (Theorem
10
).

Note the transitive effect of Theorem
1
:
e.g., the division operation is in
\cpp
because
+,-,\times\in\cpp
, which makes it possible to show that the function
x\mapsto\left\lfloor\log_{2}(x)\right\rfloor
(or more generally the function
(x,y)\mapsto\left\lfloor\log_{x}y\right\rfloor
, see
[
25
]
) also belongs to
\cpp
, which we in turn used crucially to prove Theorem
11
whose Corollary
4
states that the inverses of the Fibonacci function and the factorial function belong to
\cpp
.

As a side effect, recall that Lemma
2
also establishes the invariance of the “minimal” complexity classes
LinTime
and
\cdlin
– and a fortiori, all classes of higher complexity – as a function of the set of primitive RAM operations, provided it includes addition (Theorems
2
,
4
and
12
).

We believe the main outstanding question concerns the boundaries of the
\cpp
class:
we think that if an operation is piecewise monotonic or is local (or is composed of such operations), then we can reasonably conjecture and try to prove that it is in
\cpp
, as the following examples suggest.

•

All operations inspired by arithmetic and proven to be in
\cpp
in
[
25
]
and/or in this paper are monotonic:
+,-,\times,\mathtt{div},\log
.
Note that the
\mathtt{mod}
operation is defined by an expression on
\mathtt{div},\times
and
-
.
The function
x\mapsto\left\lfloor x^{p/q}\right\rfloor
, for a fixed rational exponent
p/q
, is also in
\cpp
because it is composed of the
\cpp
functions
x\mapsto x^{p}
and
y\mapsto\left\lfloor y^{1/q}\right\rfloor
.

•

The division algorithm of Pope and Stein
[
33
]
presented in Knuth’s book
[
30
]
and recalled here is local.
Similarly, the proof given in
[
25
]
that the operations computable in linear time on Turing machines or cellular automata belong to
\cpp
is essentially based on the locality of these computation models.

It would be interesting to generalize and classify the methods used to prove that problems belong to
\cpp
, mainly Newton’s approximation method (used for square root or more generally
c
th root, for fixed
c
, see
[
25
]
) and local methods, used e.g. for the class of operations computable in linear time on cellular automata
[
25
]
.
We believe this could significantly expand – and provide a better understanding of – the class of operations known to be in
\cpp
.

As we hope to have convinced the reader in this paper, the
\cpp
class is flexible and broad.
Therefore, we believe that, as with other robust and broad complexity classes such as

PTime
and
LinTime
, there are
countless
algorithmic strategies for computing operations in
\cpp
.
In other words, it is impossible to group them into a single model or a fixed number of models.
For the same reason, we believe that with our current knowledge it is impossible to
prove
that a given “natural” operation is
not
in
\cpp
,
as it is currently still impossible for
PTime
and even
LinTime
.

Let us list some operations whose memberships in the
\cpp
class are open problems.

Generalized root.

We strongly conjecture but cannot prove that the function
(x,y)\mapsto\left\lfloor x^{1/y}\right\rfloor
belongs to
\cpp
.
Indeed, we proved in
[
25
]
that its restriction for

in the union of intervals

Exponential, logarithm and beyond.

In
[
25
]
, we proved that the function

We strongly conjecture that the iterated exponential

On the other hand, we think that the belonging to

Modular exponential and GCD.

Even though it is well-known that the ternary operation

.

Operations computable by local models.

As we proved in
[

the general result that each operation computable by (one-dimensional) cellular automata in linear time (such as

, bitwise operations, etc.) is in

multi-dimensional
cellular automata?
More importantly, can such a local computation model be general enough to incorporate the local division algorithm?

Operations computable by circuits.

What about the complexity classes of operations defined by circuits such as
\textsc{AC}^{0}

This is an important question because several authors

Even though it is well-known that the

Any way,
\cpp
contains all the operations mentioned by Thorup
[

The paper

“…

In this model, it is therefore the class of functions for which we can reasonably assume unit cost evaluation.”

Beyond
\cpp
: computations interspersed with inputs/outputs.

If the notion of
computation with preprocessing
and, more generally, the notion of
computation interspersed with inputs/outputs
are very common in computer science and specially in database management systems, the study of the associated complexity is still in its infancy, with the exception of that of enumeration problems
[

,

,

,

,

]
, complexity of the

As we did for the

This is thanks to the “fundamental lemma” (Lemma

In the end, let us recall that the lemma combines this notion with that of linear-time preprocessing to make the complexity classes concerned robust.

10.6
How to define time complexity classes beyond linear time on RAMs?

This cannot be achieved by maintaining the constraint that allowed integers are
O(N)
because this implies that RAM uses linear space.
The upper limit of allowed integers and allowed addresses should be increased according to the chosen time limit.

Definition 11

(General RAM time complexity classes)
.

For a function
T:\mathbb{N}\to\mathbb{N}
,
T(N)\geq N
,
we denote by
\textsc{Time}(T(N))
the class of problems
\Pi:X\mapsto\Pi(X)
, with input

X=(x_{1},\dots,x_{N})
of size
N
, and
\;0\leq x_{i}<cN
(where
c
is a constant integer), which are computed in time
O(T(N))
by RAMs whose registers can contain integers
O(T(N))
, instead of
O(N)
, and which can also use addresses
O(T(N))
.

Remark 9
.

In addition to
N
, a RAM of time complexity

has a second reference integer,

. Note that for usual time functions

, for example

or

,

can be easily computed from

The general complexity class

is robust like its linear version

as expressed for example by the following theorem which generalizes the part of Theorem
4
concerning

.

Theorem 12
.

The complexity class
\textsc{Time}(T(N))
is invariant depending on whether the set of primitive operations is
\{+\}
or
\{+,-,\times,\mathtt{div},\mathtt{mod}\}
or is a set of
\cpp
operations including

.

The result follows from Lemma
2
(Fundamental Lemma) and the first item of Theorem
4
by replacing the first reference integer

.
