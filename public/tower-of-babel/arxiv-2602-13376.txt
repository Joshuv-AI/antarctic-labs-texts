An Online Reference-Free Evaluation Framework for Flowchart Image-to-Code Generation
Giang Son Nguyen, Zi Pong Lim, Sarthak Ketanbhai Modi, Yon Shin Teo, Wenya Wang

Abstract
Vision-Language Models (VLMs) are increasingly used in document processing pipelines to convert flowchart images into structured code (e.g., Mermaid). In production, these systems process arbitrary inputs for which no ground-truth code exists, making output quality difficult to assess. We propose a reference-free evaluation framework that monitors flowchart image-to-code generation quality at inference time, using only the input image and the generated output. The framework introduces two automated metrics: Recall OCR \text{Recall}_{\text{OCR}} , which estimates content coverage by extracting text from the input image via OCR as a proxy reference, and Precision VE \text{Precision}_{\text{VE}} , which detects hallucinated elements through Visual Entailment against the original image. Their harmonic mean, F1 OCR-VE \text{F1}_{\text{OCR-VE}} , provides a unified quality score. Validation on the FlowVQA dataset shows strong agreement with ground-truth metrics (average Pearson’s r = 0.97 r=0.97 , 0.91 0.91 , and 0.94 0.94 for Recall, Precision, and F1, respectively), confirming the framework’s reliability as a practical, reference-free alternative for continuous quality monitoring in production settings.

Introduction

Vision-Language Models (VLMs) are increasingly deployed in production systems to convert flowchart images into structured code representations such as Mermaid
1
1

1

https://mermaid.js.org/
or GraphViz
2
2

2

https://graphviz.org/
.
In document processing pipelines, process automation, and software engineering workflows, these models ingest diverse visual inputs (scanned documents, screenshots, photographs of whiteboards) and produce graph-structured code encoding nodes and edges
13
;
14
;
20
.

The central challenge in these deployments is
quality monitoring at inference time
.
When the system receives a new flowchart image, no ground-truth code exists to compare against; the code is precisely what the system must generate.
Errors such as missing nodes, fabricated edges, or hallucinated labels then propagate silently into downstream systems unless caught.
Traditional evaluation relies on offline benchmarks with paired images and ground-truth code
15
;
11
, but these static test sets cannot represent the diversity of inputs encountered in production, where diagram styles, image quality, and domain conventions vary continuously.

We propose a reference-free evaluation framework that assesses flowchart image-to-code generation quality using only the input image and the generated output, without requiring ground-truth code, human annotation, or access to the generating model’s internals.
The framework introduces two complementary metrics:

•

\text{Recall}_{\text{OCR}}
estimates content coverage by using optical character recognition (OCR) to extract textual elements from the input image as a proxy reference. This answers:
did the model capture everything visible in the image?

•

\text{Precision}_{\text{VE}}
estimates correctness by verifying each generated element against the original image through Visual Entailment (VE). An independent VLM checks whether each claimed node or edge is visually supported. This answers:
is everything the model generated actually present in the image?

Together, these metrics form the composite score
\text{F1}_{\text{OCR-VE}}
, providing a unified quality measure.

Because the evaluation uses the same input the VLM receives at inference time, it can be integrated as a quality gate within existing pipelines.
The framework is model-agnostic: both the OCR and VE components can be independently upgraded as better models become available.
The outputs are also interpretable, producing lists of potentially missed elements (via OCR) and potentially hallucinated elements (via VE) for error triage.

We validate the proposed metrics against ground-truth evaluations on a randomly sampled subset of the FlowVQA dataset
15
.
Results demonstrate strong agreement with ground-truth metrics across four VLM configurations:

•

\text{Recall}_{\text{OCR}}
: average Pearson’s
r=0.967
(using Gemini 1.5 Pro as OCR model)

•

\text{Precision}_{\text{VE}}
: average
r=0.910
(using Gemini 2.5 Pro as VE model)

•

\text{F1}_{\text{OCR-VE}}
: average
r=0.939

An error analysis of VE model behavior further reveals that the worst-performing VE model (Gemini 1.5 Pro) suffers from both high false positive and false negative rates, leading to unstable precision estimates. The best-performing model (Gemini 2.5 Pro) maintains low error rates across both dimensions.

Related Works

Evaluation of image-to-code generation and Visual Question Answering (VQA) for flowcharts has predominantly relied on ground-truth datasets.
FlowVQA
15
and FlowLearn
11
provide paired flowchart images and Mermaid code for direct code-to-code comparison;
14
similarly pairs images with TikZ source code.
Broader benchmarks for chart and diagram understanding follow the same paradigm
20
;
13
;
6
.
While effective for offline model development, these approaches assume access to high-quality annotations for every evaluation input, an assumption that breaks down in production where inputs are diverse, unpredictable, and arrive without paired references.

The natural language generation community has explored reference-free evaluation through learned similarity metrics (e.g.,
BERTScore

(
22
)
,
BARTScore

(
21
)
) and QA-based factuality checks
(
18
)
.
These methods demonstrate that model judgments can approximate human evaluation, but they operate purely in the text domain and cannot be directly applied to image-to-code tasks where visual fidelity is central.

For visual reasoning, Visual Entailment (VE), the task of determining whether an image supports a textual hypothesis, has been explored as a verification mechanism.

19
introduced VE for natural images, and
6
adapted it to chart captioning, producing entailment scores from decoder logits.
However, their scores show weak correlation with human judgment (Kendall’s
\tau=0.09
–
0.21
) and provide limited interpretability for diagnosing specific errors.

AI-as-judge
approaches
(
8
)
, where VLMs evaluate generated outputs against visual inputs, similarly report limited performance on diagrammatic or text-heavy images.

In deployed ML systems, the gap between offline benchmarks and online performance is well recognized.
Production pipelines require continuous quality monitoring on live inputs without ground-truth supervision, including the ability to detect degradation from distribution shifts and flag individual errors for triage.
Our work addresses this gap for the flowchart image-to-code domain by proposing metrics that run alongside inference, require no annotations, and produce interpretable error diagnostics.

3
Methodology

3.1
Background: Traditional Evaluation

In conventional flowchart-to-code evaluation, a generated Mermaid program is decomposed into elements (nodes and edges) and compared against a ground-truth reference.
Let
Actual Elements
and
Generated Elements
denote the multisets of elements from the reference and generated code, respectively.
Traditional recall, precision, and F1 are:

\displaystyle\text{Recall}_{\text{Actual}}

\displaystyle=\frac{|\text{Actual}\cap\text{Generated}|}{|\text{Actual}|}

\displaystyle\text{Precision}_{\text{Actual}}

\displaystyle=\frac{|\text{Actual}\cap\text{Generated}|}{|\text{Generated}|}

\displaystyle\text{F1}_{\text{Actual}}

\displaystyle=2\times\frac{\text{Precision}_{\text{Actual}}\times\text{Recall}_{\text{Actual}}}{\text{Precision}_{\text{Actual}}+\text{Recall}_{\text{Actual}}}

These metrics require ground-truth code.
In production, the system processes arbitrary, unseen flowchart images for which no reference code has ever been written.
This motivates proxy metrics that estimate recall and precision directly from the input image and generated code.

3.2
\text{Recall}_{\text{OCR}}
: Estimating Completeness via Text Extraction

We observe that flowchart elements predominantly carry textual labels, and approximate the actual element set by extracting text from the input image using OCR:

\text{Actual Elements}\approx\text{OCR Texts}

This metric targets node-level completeness; edge recall remains an open problem in vision-language research
5
and is discussed in §
6
.
Matching extracted strings against labels in the generated code estimates how completely the model recovered the flowchart’s textual content:

\text{Recall}_{\text{OCR}}=\frac{|\text{OCR Texts}\cap\text{Generated Elements}|}{|\text{OCR Texts}|}

(1)

3.3
\text{Precision}_{\text{VE}}
: Estimating Correctness via Visual Entailment

Without ground-truth annotations, it is unclear whether a generated element is a true positive (present in the original diagram) or a false positive (hallucinated).
We address this through Visual Entailment (VE): each generated element is treated as a hypothesis and verified against the input image by an independent VLM, queried with prompts such as:

“Is the edge ‘Node A –> Node B’ visually present in the image?”

The model outputs a binary judgment (
Yes
/
No
), and the set of entailed elements approximates the true positives:

\text{Precision}_{\text{VE}}=\frac{|\text{Entailed Elements}|}{|\text{Generated Elements}|}

(2)

The VE model is
independent
of the code-generating VLM.
Using the same model for both generation and verification creates circular validation; our framework avoids this by decoupling the two roles.

3.4
\text{F1}_{\text{OCR-VE}}
: Composite Metric

The two reference-free metrics combine into a unified quality score:

\text{F1}_{\text{OCR-VE}}=2\times\frac{\text{Precision}_{\text{VE}}\times\text{Recall}_{\text{OCR}}}{\text{Precision}_{\text{VE}}+\text{Recall}_{\text{OCR}}}

(3)

3.5
Design Properties

The framework is designed for practical deployment with three properties in mind.

Model-agnostic.

Any OCR and VE model can be swapped in without changing the evaluation pipeline.
The framework is also language-agnostic, applicable to any diagramming language (Mermaid, GraphViz, UML, etc.) whose output can be parsed into nodes and edges.

Interpretable.

Unlike prior reference-free approaches that produce opaque scores
6
;
8
, our metrics have direct operational meaning:
\text{Recall}_{\text{OCR}}=0.85
means approximately 85% of visible textual elements were captured;
\text{Precision}_{\text{VE}}=0.9
means 90% of generated elements are visually supported.
The framework also produces explicit lists of missed elements (OCR texts absent from generated code) and potentially hallucinated elements (non-entailed outputs), enabling targeted error triage.

Online-capable.

Both metrics are computed from the input image and generated output alone, the same artifacts available at inference time.
This enables integration as a post-generation quality check within existing pipelines, supporting continuous monitoring without manual annotation.

4.1
Setup

Dataset and code generation.

Due to the high cost of validating the framework using API calls, we only validate our approach on 197 flowchart images randomly sampled from the FlowVQA dataset
15
(the same subset sampled by
20
), each paired with ground-truth Mermaid code. This sample size is sufficient for our validation objective: establishing that the reference-free metrics reliably approximate ground-truth metrics, not benchmarking VLMs themselves.
We follow the prompt design and Mermaid parser of
20
for code generation and element decomposition.

Four VLMs generate Mermaid code: Qwen2.5-VL-32B
2
(open-source), Gemini 1.5 Pro
16
, GPT-4o Mini
10
, and Claude Sonnet 4.0
1
(commercial).
This diversity tests whether our metrics generalize across generators with different architectures and performance levels.
Ground-truth benchmarks yield
\text{Recall}_{\text{Actual}}
and
\text{Precision}_{\text{Actual}}
.

OCR models for
\text{Recall}_{\text{OCR}}
.

We evaluate three OCR models spanning open-source and commercial options: PaddleOCR
4
, Google Document AI
3
, and Gemini 1.5 Pro (prompted for text extraction).

VE models for
\text{Precision}_{\text{VE}}
.

Three commercial VLMs serve as VE models: Claude Sonnet 4.0, Gemini 1.5 Pro, and Gemini 2.5 Pro
17
.
To manage API costs at scale, we dynamically batch elements into single API calls, allocating fewer elements per batch for complex images (higher element counts) with a minimum of three elements per call.

Matching and compositing.

To tolerate minor surface-level errors (e.g., tilde/single-quote confusion), we use Levenshtein-based similarity matching with a threshold of 0.9 rather than exact string matching.
For
\text{F1}_{\text{OCR-VE}}
, we select the best-performing OCR model (Gemini 1.5 Pro) and VE model (Gemini 2.5 Pro) from the individual metric experiments.

Validation measures.

We assess agreement between our reference-free metrics and ground-truth using Pearson’s
r

12
and Kendall’s
\tau

7
for correlation, and RMSE and MAE for error magnitude.
We report micro-averaged F1 scores for OCR and VE model quality, as micro-averaging ensures each element contributes proportionally regardless of per-image element counts.

Terminology.

We refer to the models generating Mermaid code as VLMs, and the models performing text extraction or visual verification as OCR and VE models, respectively.

4.2.5
VE Error Analysis

The large correlation differences between VE models, despite similar F1 scores, are explained by their error profiles (
Table 2
).
Gemini 2.5 Pro maintains the lowest FPR (0.020), while Claude Sonnet 4.0 (0.051) and Gemini 1.5 Pro (0.052) produce over twice as many false positives.
These false positives are elements incorrectly classified as entailed, causing
\text{Precision}_{\text{VE}}
to overestimate
\text{Precision}_{\text{Actual}}
.
Conversely, Claude Sonnet 4.0 achieves the lowest FNR (0.008), while Gemini 1.5 Pro’s high FNR (0.034) leads to frequent underestimation.

For production deployment, this analysis suggests that selecting a VE model with low FPR is particularly important, as false positives directly mask hallucinated elements, the primary failure mode operators need to detect.

5
Conclusion

We present a reference-free evaluation framework for flowchart image-to-code generation, designed for production settings where ground-truth code is unavailable.
The framework introduces
\text{Recall}_{\text{OCR}}
and
\text{Precision}_{\text{VE}}
, two automated metrics that estimate content coverage and hallucination rates using only the input image and generated output, along with their composite
\text{F1}_{\text{OCR-VE}}
.

Validation on FlowVQA demonstrates strong agreement with ground-truth metrics (average Pearson’s
r
of 0.97, 0.91, and 0.94 for Recall, Precision, and F1), confirming the framework’s reliability as a proxy for traditional evaluation.
Error analysis further reveals that VE model selection matters: models with low false positive rates produce the most stable precision estimates, directly impacting hallucination detection.

For practitioners deploying VLMs on document understanding tasks, this framework enables continuous quality monitoring without annotation overhead, produces interpretable diagnostics for error triage, and supports modular upgrades as better OCR and VE models become available.

6
Limitations

\text{Recall}_{\text{OCR}}
effectively captures text-labeled nodes but cannot handle unlabeled edges, leaving edge recall unaddressed. However, reasoning over edges, arrows, and connections remains an open problem in computer vision and vision-language model research
5
. Recently,
9
proposed methods leveraging object detection and OCR to obtain a list of edges. Their method relies on certain heuristics (detecting edges based on the Intersection-over-Union ratio between arrows and nodes) and has not been tested on large-scale datasets despite promising preliminary results. When reliable edge detection methods become available, an edge recall component can be integrated into our framework without changing the overall architecture.

Moreover, the framework can be further validated against ground-truth in other flowchart datasets, such as FlowLearn
11
.
