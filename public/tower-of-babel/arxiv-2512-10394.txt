RoboNeuron: A Modular Framework Linking Foundation Models and ROS for Embodied AI
Weifan Guan, Huasen Xi Chenxiao Zhang Aosheng Li, Qinghao Hu, Jian Cheng, [0.6em] Institute of Automation, Chinese Academy of Sciences, [-0.1em] University of Chinese Academy of Sciences AiRiA MICRO[0.6em] guanweifan2024@ia.ac.cn , xihuasen2025@ia.ac.cn , zhang_cx@buaa.edu.cn , liaosheng24@mails.ucas.ac.cn , huqinghao2014@ia.ac.cn , jcheng@nlpr.ia.ac.cn

Abstract
Current embodied AI systems face severe engineering impediments, primarily characterized by poor cross-scenario adaptability, rigid inter-module coupling, and fragmented inference acceleration. To overcome these limitations, we propose RoboNeuron, a universal deployment framework for embodied intelligence. RoboNeuron is the first framework to deeply integrate the cognitive capabilities of Large Language Models (LLMs) and Vision-Language-Action (VLA) models with the real-time execution backbone of the Robot Operating System (ROS). We utilize the Model Context Protocol (MCP) as a semantic bridge, enabling the LLM to dynamically orchestrate underlying robotic tools. The framework establishes a highly modular architecture that strictly decouples sensing, reasoning, and control by leveraging ROS’s unified communication interfaces. Crucially, we introduce an automated tool to translate ROS messages into callable MCP functions, significantly streamlining development. RoboNeuron significantly enhances cross-scenario adaptability and component flexibility, while establishing a systematic platform for horizontal performance benchmarking, laying a robust foundation for scalable real-world embodied applications. The full code implementation of this work is available at github repo : RoboNeuron .

1
Introduction

Despite significant progress in developing advanced Vision-Language-Action (VLA) models, the field of embodied AI is hampered by critical engineering challenges in real-world deployment. This disparity creates systemic friction that stalls the migration of laboratory prototypes into practical applications. Specifically, we identify three core impediments that limit the scalability and robustness of current embodied systems.

The first major difficulty is the high engineering barrier for
cross-scenario adaptation
. Most existing algorithms are tightly dependent on specific hardware configurations, sensor drivers, or simulation environments. This lack of unified interface specifications across diverse hardware platforms means that adapting a VLA model to a new robotic arm or upgrading a sensor suite demands extensive manual refactoring of low-level engineering code. This scenario-specific dependency restricts system generalization and wastes research effort on hardware integration.

A second challenge arises from the
rigid coupling of system modules
. Many current embodied AI projects utilize monolithic structures where functional components, such as perception devices, VLA models, and execution mechanisms, are fused together at the project level. This blurred separation creates a brittle architecture, making the replacement of individual hardware components or the upgrading of specific algorithms exceptionally difficult. Such rigid coupling severely hinders system iteration and long-term maintenance.

The third impediment is the
fragmented nature of inference acceleration
. Real-time performance is a non-negotiable requirement for physical robot deployment. While many acceleration techniques exist for VLA models
[
1
]
, they remain scattered across various frameworks and lack a unified integration layer. This fragmentation complicates the deployment process for developers and prevents the establishment of a standardized platform for horizontal benchmarking and performance comparison across different acceleration strategies.

To overcome these interwoven obstacles, we present
RoboNeuron
, a universal deployment framework for embodied intelligence. The core of RoboNeuron is a novel architecture that utilizes the Model Context Protocol (MCP) as a cognitive bridge to integrate the decision-making power of LLM models with the robust execution environment of the Robot Operating System (ROS).

RoboNeuron implements a
layered, decoupled system
built upon the mature ROS ecosystem, which serves as the unified communication backbone across heterogeneous hardware. In this architecture, the LLM acts as the cognitive core, leveraging the type-safe nature of MCP to orchestrate tasks. Complex semantic tasks are routed to VLA models, while basic automation directives are executed directly through ROS functional modules. A critical innovation is the
ROS Message Translator
, which automatically parses native ROS message types and registers them as callable MCP tools. This mechanism completely eliminates the structural and semantic gap between the free-form intent of the LLM and the rigid protocol requirements of ROS.

Furthermore, RoboNeuron is designed for high engineering efficiency. It establishes unified interfaces for VLA models, ensuring that various algorithms and specialized acceleration techniques can be integrated seamlessly. We systematically consolidate mainstream VLA acceleration algorithms and adapt efficient inference engines (such as llama.cpp) to run within the framework. By abstracting the complexities of both the cognitive layer and the execution layer, RoboNeuron provides a generalized, highly adaptable, and efficient platform for deploying embodied algorithms.

The main contributions of this paper are summarized as follows:

1.

The First Integrated Framework for LLM-Driven ROS Control
: We propose RoboNeuron, the first architecture to successfully bridge the LLM/VLA cognitive ecosystem with the ROS execution ecosystem. This integration is realized through the novel application of the MCP protocol and the automated ROS message translator, enabling seamless, type-safe control.

2.

Modular Decoupling for High Adaptability
: Leveraging the unified communication mechanisms of ROS, we establish strictly decoupled modules (Perception, Plan, Control). This design directly resolves the rigid coupling problem, significantly enhancing the flexibility for hardware, sensor, and algorithm replacement across different deployment scenarios.

3.

Systematic Integration and Benchmarking Platform
: We systematically integrate VLA inference engines and acceleration algorithms. This approach not only addresses the need for high real-time performance but also provides a unified, readily available platform for researchers to conduct horizontal performance comparisons.

Related Work

This section reviews prior advances across three major areas relevant to RoboNeuron: LLM-driven embodied intelligence, the Robot Operating System ecosystem, and the deployment of modern VLA models. By outlining the structural limitations in existing methodologies, we motivate the need for a unified runtime framework that connects high-level reasoning, system middleware, and model inference.

Despite these advances, most existing approaches present robot capabilities as fixed APIs, static skill libraries, or prompt-engineered action spaces. These designs often rely on hand-crafted interfaces that restrict extensibility and do not support dynamic capability discovery at runtime. Moreover, the lack of a standardized, type-safe semantic protocol limits the ability of LLMs to interact with heterogeneous robot functionalities in a scalable manner. This gap motivates the search for a more general interface layer that can declaratively expose system-level capabilities to LLMs.

2.2
Robot Operating System

ROS remains the dominant middleware in robotics. As detailed in the ROS 2 architectural design
[
7
]
, it provides structured communication (topics, services, and actions), hardware abstraction, and integration with mature motion-planning libraries such as MoveIt. ROS 2’s utilization of the Data Distribution Service and strongly typed Interface Definition Language ensures interoperability and real-time reliability within traditional robotics pipelines .

However, ROS’s message-centric communication model is not naturally aligned with the JSON-based, semantically flexible formats expected by modern LLM tool-use systems. Bridging the two often requires custom wrappers or task-specific API layers that introduce type inconsistencies and demand continuous manual maintenance. These ad-hoc integrations make it difficult to expose ROS resources to LLMs in a systematic, scalable manner. A more automated and semantics-preserving mechanism for translating ROS message structures into LLM-callable tool interfaces would alleviate this mismatch.

Yet, there remains a noticeable lack of attention to system-level deployment challenges. Current VLA policies typically operate as standalone inference modules and do not inherently support runtime interchangeability, dynamic resource management, or integration within larger robotic software stacks. As a result, switching between different models, or even different accelerated variants of the same model, often entails redesigning the surrounding execution pipeline. This absence of a unified abstraction layer complicates the use of VLA models within heterogeneous real-world systems.

In summary, current embodied AI efforts face three key architectural gaps: LLM-driven planning relies on rigid, hardcoded interfaces; the ROS middleware remains semantically mismatched with LLM abstraction; and the VLA ecosystem lacks system-level runtime management and inter-compatibility. RoboNeuron is positioned as the systemic solution, leveraging the MCP semantic protocol, the ROS2MCP translator, and the Wrapper mechanism to connect LLM reasoning, ROS execution, and VLA policies in a dynamically flexible and type-safe runtime framework.

3
Method

This section details the architectural design and operational mechanisms of the RoboNeuron framework. To address engineering challenges such as cross-platform adaptability, high module coupling, and complex resource scheduling, RoboNeuron prioritizes generality, modularity, and scalability. We propose a layered hybrid architecture that establishes the ROS as the fundamental interface and utilizes the MCP as a cognitive bridge, achieving a deep integration between the AI ecosystem (LLM/VLA) and traditional robotic engineering.

3.1
Overview

The design of RoboNeuron addresses the fundamental friction between high-level cognitive models and low-level robotic execution by proposing a Layered Cognitive-Execution Architecture. This architecture strictly separates concerns across the embodied pipeline, establishing clear boundaries for orchestration, communication, and hardware control.As illustrated in Fig.
1
, the system is defined by three interconnected operational domains, unified by the MCP:

Figure 1:
The Layered Cognitive-Execution Architecture of RoboNeuron. The framework strictly decouples the high-level Cognitive Core (LLM Orchestration) from the Execution Environment. The MCP Tool Library acts as the Semantic Bridge, utilizing the MSG Translator to automatically register type-safe ROS functionalities as callable tools. Execution is managed via a Bifurcated Path (Simple Path for low-latency commands, Complex Path for VLA-driven perception-action loops). The standardized output is finally adapted by the Adapter layer for seamless deployment across heterogeneous physical or simulated platforms.

Cognitive Core and Semantic Bridge

The Large Reasoning Model acts as the cognitive orchestrator, responsible for interpreting complex natural language instructions and generating abstract action plans. Crucially, the LLM is not directly involved in low-level decision-making; instead, it utilizes the MCP as a type-safe semantic bridge to discover and invoke underlying capabilities. All functional components, ranging from VLA models to hardware drivers, are encapsulated as callable MCP Tools. A critical innovation here is the ROS Message Translator, which automatically parses the rigid structures of ROS messages and transforms them into Pydantic-validated MCP tool definitions, thereby seamlessly closing the protocol gap between the LLM and the ROS environment.

Decoupled Execution Middleware

The Robot Operating System serves as the real-time execution middleware, which manages standardized communication and asynchronous data flow across the entire system. Building upon this middleware, the framework implements a bifurcated execution path whose routing decision is based on the complexity of the Large Reasoning Model’s command. For immediate, low-overhead tasks, the system utilizes the Simple Path to ensure low latency; here, the LLM bypasses the computationally intensive VLA process and invokes basic MCP tools that publish commands directly onto the ROS topics (e.g., querying robot status or issuing direct velocity commands). Conversely, for tasks requiring visual comprehension and sequential decision-making, the LLM orchestrates a series of dedicated ROS nodes via the Complex Path: this sequence involves activating the ROS Perception node to stream sensor data, invoking the VLA Inference node for multi-modal reasoning, and finally directing the ROS Control node to execute the resulting actions. This fundamental separation ensures that high-level planning is completely decoupled from real-time motion control, significantly enhancing overall system stability and responsiveness.

Abstraction and Deployment Layer

To ensure high cross-scenario adaptability, the Execution Middleware is further abstracted through a Wrapper-Based Strategy. Core functionalities like sensor access (CameraWrapper) and VLA models (ModelWrapper) adhere to standardized interfaces, enforcing consistency regardless of the underlying vendor or algorithm. The final layer is the Adapter, which translates the standardized ROS messages into platform-specific protocols required by the physical or simulated execution environments (e.g., translating ROS trajectory commands to a proprietary robot arm API). This comprehensive decoupling strategy is fundamental to achieving RoboNeuron’s goal of flexible deployment and component interchangeability.

3.2
Core Modules

The RoboNeuron framework achieves its architectural flexibility and robust capability by implementing a series of strictly decoupled modules. These components abstract the complexities of hardware interfaces and advanced algorithms, exposing only standardized functions to the cognitive core. The subsequent detailed analysis of these key modules will focus on how the design choices guarantee hardware interchangeability, enforce protocol safety, and provide a unified platform for performance optimization.

a. ROS Perception: Abstraction and Dynamic Stream Scheduling

The first challenge in integrating embodied intelligence is the heterogeneity of perception hardware and the resulting difficulties in managing sensor data streams. Traditional systems often tightly bind the algorithm layer to specific sensor drivers, crippling the system’s ability to adapt to new environments or sensor suites. To overcome this, RoboNeuron establishes a robust Unified Sensor Abstraction Layer. This is implemented via a standardized abstraction base class for sensing devices. By mandating a uniform set of fundamental operational methods, such as starting the stream, reading the latest frame, and closing the connection (
open()
,
read()
,
close()
), this base class ensures that all sensor data, whether originating from a physical camera or a simulated environment, is presented to the upstream VLA inference engine in a consistent, standardized format. This crucial decoupling means that replacing a high-fidelity RealSense camera with a simpler virtual camera requires no modification to the cognitive planning or inference logic, thus guaranteeing hardware-agnostic perception.

Beyond merely standardizing data format, the Perception module implements dynamic resource management. In typical robotic systems, sensor streams are often initialized and run continuously, leading to unnecessary computation and high power consumption when the sensor data is not actively required for the current task. RoboNeuron resolves this inefficiency by treating sensor activation as a dynamically scheduled MCP Tool. The LLM, acting as the orchestrator, invokes the
start_camera()
tool only when visual input is explicitly needed for a VLA task. This approach triggers the launching of the dedicated sensor node in an isolated process. This strategy offers two major benefits: first, it conserves computational resources by running sensor streams on-demand. Second, utilizing a process-level isolation mechanism ensures that any failure or exception in a specific sensor’s driver or communication stream does not propagate and crash the central LLM orchestration loop, thereby significantly enhancing the system’s operational robustness during long-duration, complex tasks.

b. ROS Control: Dynamic IK and Cross-Platform Adaptation

The Control layer’s primary hurdle in multi-robot deployment lies in the rigid coupling of kinematic models and the challenge of integrating proprietary, non-ROS execution platforms. Traditional robotic control systems often hardcode the Inverse Kinematics (IK) logic specific to a single manipulator’s geometry, which necessitates extensive code modification for any change in robot type or configuration. RoboNeuron resolves this by implementing a Dynamic Kinematic Solver mechanism. This solver operates by dynamically parsing the robot’s Universal Robot Description Format (URDF) file at runtime. By constructing the specific kinematic chain based on the loaded description, the system can calculate accurate IK solutions without relying on pre-compiled, robot-specific libraries. This separation ensures that the core control algorithm remains entirely decoupled from the robot’s morphology, allowing the framework to offer a unified action control interface across diverse manipulators.

The Dynamic Kinematic Solver typically runs in an isolated control node, receiving high-level Cartesian commands from the VLA inference pipeline. It performs closed-loop control by utilizing real-time joint state feedback to correct its calculations before publishing precise, low-level joint commands to the hardware. Furthermore, to enable deployment across proprietary or simulation platforms, such as the LIBERO benchmark environment
[
13
]
, RoboNeuron employs a Platform Adapter Abstraction Base Class. While ROS provides standardized communication, external platforms may only expose their functionality through proprietary APIs. The adapter enforces a contract that translates the framework’s standardized ROS messages (e.g., trajectory commands) into the platform-specific API calls required by the non-ROS environment. This mechanism guarantees that the system enhances the project’s overall extensibility and utility for comparative research.

c. Message Translator: Automated Semantic Bridging via ROS2MCP

A fundamental challenge in integrating the Large Reasoning Model ecosystem with the Robot Operating System is the semantic and structural mismatch between the two protocols. The LLM, operating with structured textual output (JSON schema/Pydantic models), requires strict parameter validation, whereas ROS utilizes its own dedicated, potentially complex, binary message definitions in .msg files. Manually creating and maintaining wrappers for hundreds of ROS message types, many of which have deeply nested structures, is highly prone to error and unsustainable for large-scale systems.

To eliminate this engineering bottleneck and guarantee protocol safety, RoboNeuron introduces the ROS2MCP Automated Translator, a pivotal mechanism for semantic mapping. The translation process is driven by a two-stage engine. First, a Recursive Protocol Parsing Engine is employed to systematically analyze all declared ROS message definitions. This engine is specifically designed to handle the complexity of nested types, building a comprehensive, flattened index of message fields and their types. Second, this standardized structural information is fed into a Code Generation Template Engine (built on a framework like Jinja2). This engine automatically synthesizes the Python wrapper code required for the MCP tool, including the necessary server logic and callback functions.

The most critical feature of this automated synthesis is the integration of a type validation layer. Every parameter defined in the generated MCP tool is automatically linked to a corresponding Pydantic schema. This enforcement ensures that when the LLM orchestrator proposes a tool call, the arguments are rigorously checked for correct data types and constraints before they are published to a live ROS topic. This automated, type-safe validation mechanism drastically enhances the system’s robustness against LLM hallucination or improper parameter formatting, guaranteeing that only structurally sound commands reach the low-level execution layer. This automated approach is instrumental in scaling the framework, allowing new ROS capabilities to be exposed to the LLM with minimal developer overhead.

d. VLA Inference: Decoupled Integration and Benchmarking

The final, and most strategically flexible, module is the VLA Inference Engine, which is designed to handle the complexity of multi-modal reasoning algorithms and their associated deployment optimizations. The architecture is built around a unified Model Wrapper Base Class. This base class enforces a standardized contract for model management, including consistent methods for loading the model weights (
load()
) and executing the core multi-modal prediction (
predict_action()
). By abstracting these operations, RoboNeuron ensures that the LLM orchestration layer can seamlessly integrate and invoke diverse VLA models.

To balance the latency requirements of real-time robotics with the substantial computational cost of modern VLA architectures, the module incorporates a configurable backend registry rather than fixed, hardcoded optimization logic. Each supported VLA model and its corresponding acceleration variant
[
14
]
, as well as optional lightweight LLM inference engines, are registered as selectable backends. When the VLA Inference Node receives a command from the LLM, it resolves the designated model, the chosen acceleration method, and the desired execution backend according to a user-specified configuration. This design enables the LLM to dynamically select the most suitable combination of model and backend, providing fine-grained control over the trade-off between computational efficiency and predictive accuracy.

The primary academic value of this design lies in establishing a Unified Benchmarking Platform. Because all models and all acceleration schemes are managed, deployed, and executed within the single, standardized environment of the VLA Inference Node, researchers gain a reliable framework. This framework facilitates rigorous horizontal performance comparison of different VLA models and their corresponding optimization strategies against critical real-time metrics, a capability that is often fragmented or impossible in bespoke robotic deployments. This integration simplifies research iteration and accelerates the deployment of performance-optimized cognitive agents.

3.3
Workflow

The operational workflow of RoboNeuron is designed around two distinct, yet interconnected, phases:
Capability Registration
and
Task Execution
. This division ensures maximal resource efficiency, strict protocol compliance, and dynamic orchestration capability.

Capability Registration

This phase prepares all system-level capabilities that the LLM may invoke during execution. Rather than performing any computation or launching runtime processes, the system focuses on generating a complete and task-specific capability map that binds ROS interfaces, hardware modules, and VLA models into a unified MCP-accessible form.

The first step is ROS Message Conversion. Using the ROS2MCP Translator, the system statically converts only the ROS messages and services required for the current task into structured, type-safe MCP Tool Calls. This produces a dedicated tool library through which the LLM can publish commands, receive sensor updates, or interact with the robot’s internal state. In effect, the translator exposes the operational subset of the robot’s ROS interface as a coherent MCP API that the cognitive layer can reliably access.

The second step is Wrapper Initialization for the three fundamental capability groups-Perception, Control, and VLA. Each group instantiates its corresponding Wrapper Base Class, which defines how the system will interact with a specific camera setup, robot platform, or VLA model. Default wrappers are provided for common hardware and model configurations, while users operating different sensors, manipulators, or VLA models need only implement the matching wrapper. Importantly, this stage does not start ROS nodes or load large models; it merely standardizes the interfaces that will later be bound to runtime components.

Together, these two procedures complete the system’s capability declaration. By ensuring that all ROS interfaces are translated into MCP tools and all hardware/model dependencies are abstracted behind consistent wrappers, the registration phase guarantees that downstream execution can operate on a stable, hardware-agnostic API surface.

Task Execution

This phase describes how the system dynamically responds to a human instruction and orchestrates the full perception–reasoning–control loop. Execution begins with LLM-driven capability selection. Upon receiving a task instruction, the LLM infers the minimal set of capabilities required and activates them by invoking the corresponding MCP tools. Each invocation serves as the sole trigger for launching its associated ROS node, ensuring that resources are brought online strictly on demand.

Once the required resources are active, the system enters an Asynchronous Perception–Inference Loop. The Perception Node publishes its sensor stream, and the VLA Inference Node subscribes to this feed while simultaneously grounding the data against the LLM-provided task intent. By decoupling sensing from inference scheduling, the system maintains consistent throughput and avoids unnecessary blocking across components.

The resulting VLA’s low-level action outputs are passed to the Control Node, which is similarly activated through its Core MCP Tool. This node performs closed-loop motion generation using the dynamically loaded URDF for kinematic reasoning and then issues the corresponding robot-specific commands. The Adapter Layer finalizes protocol conversion, ensuring that all low-level signals conform to the target platform’s native interface and thus completing the text-to-action execution cycle.

Throughout the mission, the LLM maintains explicit authority over the task lifecycle. It starts, coordinates, and terminates resources entirely through MCP tool calls; upon task completion or environmental changes, the LLM invokes the appropriate
stop_…
tools to shut down active nodes and release their resources. This event-driven structure ensures that robotic execution remains tightly aligned with the LLM’s evolving task plan.

Case I: Unified Control of Heterogeneous Vehicles

This case evaluates whether RoboNeuron can transform standard ROS messages into actionable MCP tools and use them to control heterogeneous platforms through a single, unified interface.

Four mobile robots with different kinematic structures were deployed simultaneously in Isaac Sim. When the system received the instruction "Move forward at 0.5m/s", the LLM identified the task as a velocity-control request and selected the
pub_twist
interface, automatically generated from the standard
geometry_msgs/Twist
specification. As illustrated in Fig.

The consistent response across vehicles with different base configurations demonstrates that RoboNeuron effectively abstracts platform-specific control details. By exposing standard ROS messages as uniform MCP tools, the framework allows high-level reasoning to operate over a stable, device-independent action space, validating its capability for protocol unification and heterogeneous system control.

Case II: Kinematic-Aware Manipulation in Simulation

This case examines whether RoboNeuron can operate over dynamically loaded robot kinematics and utilize custom ROS messages to command precise manipulation behaviors.

In this scenario, a simulated Franka Panda arm was instructed to perform linear end-effector motion (0.01m/s forward). Executing such a command requires the system to construct an IK-capable control stack on the fly. Upon receiving the instruction, the LLM activated the control module by supplying the path to the
panda.urdf, enabling the framework to parse the robot’s kinematic structure and initialize the corresponding IK solver. It subsequently issued a custom end-effector command through the
pub_eecommand

The resulting motion trajectory shows that the Control Node correctly resolved the custom message into a valid IK solution using the dynamically imported model. This demonstrates two key capabilities: RoboNeuron can (i) incorporate arbitrary robot descriptions at runtime to instantiate full kinematic reasoning, and (ii) expose complex, user-defined control protocols to the LLM through the same unified MCP abstraction. Together, these results confirm that the framework extends beyond basic velocity control to support structured, kinematics-aware manipulation tasks.

The three case studies collectively validate the core design principles of the RoboNeuron framework, highlighting three key advantages:

Unified Protocol Access:

Cases I and II demonstrate how the ROS2MCP Translator enables type-safe access to both standard (
Twist
) and custom (
EECommand
) ROS interfaces. By unifying protocol-level interactions, the framework allows LLMs to operate directly on semantic intent without being constrained by heterogeneous message specifications, significantly reducing integration complexity.

Modular Interchangeability:

Across Cases II and III, the system transitions from the simulated Panda arm to the real FR3 arm, and from simulated perception to the RealSense-based pipeline, without affecting the high-level reasoning process or the sequence of MCP calls. This confirms that hardware, sensors, and models can be swapped simply by changing Wrapper instances and URDF paths, enabling rapid prototyping.

LLM-Orchestrated Closed-Loop Execution:

Case III validates that RoboNeuron maintains a coherent perception–inference–control loop under LLM supervision. The LLM manages module activation, drives the asynchronous data flow, and oversees the full task lifecycle, demonstrating reliable end-to-end orchestration for real-world embodied tasks.

5
Conclusion

We introduced RoboNeuron, a universal deployment framework that addresses the core engineering barriers of embodied AI by unifying LLM/VLA reasoning with ROS’s real-time execution layer through the Model Context Protocol. By automatically translating ROS interfaces into type-safe MCP tools and enforcing a Wrapper-based abstraction between sensing, reasoning, and control, the framework enables seamless substitution of hardware, sensors, and VLA models with minimal reconfiguration. Experiments across simulated and real-world settings demonstrate reliable orchestration, consistent cross-scenario transfer, and robust closed-loop control. RoboNeuron therefore provides a scalable foundation for embodied intelligence research, and future work will expand model coverage and integrate inference acceleration to further strengthen its universality.
