DAYPSCI: Event-based dataset for anomaly detection through fault injection in PLC-controlled industrial cyber-physical systems
Authors: Juan Vicente Martín-Fraile, Nuño Basurto Hornillos, Jesús Enrique Sierra-García, Álvaro Herrero
Published: 2026

ABSTRACT
AbstractThis article presents DAYPSCI, an event-based dataset generated using an industrial cyber-physical system (CPS) testbed based on a PLC-controlled part marking station with Siemens S7-1200 and S7-1500 devices. The system integrates real industrial hardware with digital twin technologies, enabling controlled and repeatable experiments. Data acquisition follows an event-based logging approach, where only changes in system variables are recorded rather than using fixed sampling rates, and each event is associated with its corresponding inter-event time (Δt), enabling precise temporal characterization of system dynamics. The dataset also includes scan-level identifiers (scan_id) and event ordering (event_order), preserving the logical execution order within PLC scan cycles. It contains time-stamped records of digital sensors, solenoid valve control signals, and process states under both normal operation and controlled fault injection scenarios affecting sensors, actuators, or both. Ground truth is generated through a hybrid approach combining externally defined labels from the experimental configuration and labels derived at runtime from control system signals (e.g., GEMMA states), ensuring a clear separation between CPS execution and the labeling layer while enabling traceability between injected faults (cause) and observable system behavior (effect), and allowing differentiation between fault activation and observable anomaly manifestation, which may be temporally decoupled. The dataset is organized into independent experimental batches, each including processed data (CSV), network traffic captures (PCAPNG) from a Profinet-based industrial communication network, and detailed documentation, facilitating sequence-based analysis and reproducibility. The dataset supports the development and evaluation of machine learning methods for anomaly detection and fault classification in industrial CPS.Keywords: Event-based logging, Digital twin, Ground truth labeling, Discrete-event systems, PLC scan cycles, Industrial cybersecurity, Fault injection, Sensor and actuator faults

Background

The increasing adoption of cyber-physical systems (CPS) in industrial environments has created a growing demand for datasets that accurately represent the behavior of discrete-event processes under both normal and faulty conditions.

In this context, recent studies have highlighted the importance of data representation in anomaly detection for industrial CPS, particularly distinguishing between time-sampled and event-based approaches [1]. In many industrial applications, data are commonly collected using fixed sampling rates, which may fail to capture the precise timing and ordering of events occurring within PLC-based control systems.

Furthermore, existing research has pointed out limitations in currently available datasets, including restricted diversity, limited representation of industrial processes, and challenges in capturing realistic cyber–physical interactions. These limitations hinder the evaluation and generalization of anomaly detection methods across different industrial scenarios.

To address these challenges, this dataset was created to provide realistic, event-based data acquired directly from industrial control systems. The dataset focuses on an event-based data acquisition strategy that captures both the temporal dynamics and logical execution order of industrial processes, enabling a more accurate representation of discrete-event behavior in PLC-controlled systems.

The data were generated using a PLC-controlled part marking station integrating Siemens S7-1200 and S7-1500 devices, combined with digital twin technologies to enable controlled and repeatable experimentation. The data acquisition process follows an event-based logging paradigm, where only changes in system variables are recorded, and each event is associated with a duration (Δt).

The dataset design is aligned with discrete-event system modeling approaches commonly used in industrial automation. In addition, system operation is described using process states based on the GEMMA reference model, enabling the representation of normal operation, fault conditions, and recovery phases. Controlled fault injection was applied to sensors and solenoid valves to generate labeled anomaly scenarios under consistent experimental conditions.

This data article provides a detailed description of the dataset structure, acquisition methodology, and labeling strategy, complementing related research focused on anomaly detection and machine learning applications in industrial CPS.

Data Description

The DAYPSCI dataset described in this article is organized as a collection of independent experimental batches and is publicly available at [2], each corresponding to a specific operating condition of the industrial cyber-physical system.

The dataset repository is structured into batches, where each batch represents a complete and self-contained experiment, as illustrated in Fig. 1. These experiments include baseline operation (normal behavior) and controlled fault injection scenarios affecting sensors, solenoid valves, or both.

The naming convention follows a structured format that encodes the type of scenario and the batch identifier. For example: pn_baseline_batch01.csv, pn_sensor_T1_batch02.csv, pn_valve_T1_batch08.csv, pn_combined_T1_batch11.csv (combined sensor–solenoid valve faults).

Within each CSV file, the dataset is organized as a sequence of events. Each row corresponds to a system event, defined as a change in one or more variables. Events are grouped into sequences associated with individual processed parts, identified by the field part_id.

Experimental Design, Materials and Methods

The dataset was generated using an industrial cyber-physical system (CPS) testbed based on a PLC-controlled part marking station, previously described and validated in [3]. The testbed integrates Siemens S7-1200 and S7-1500 programmable logic controllers, digital sensors, and electromechanical actuators. A digital twin environment was incorporated to enable controlled, repeatable, and extensible experimentation.

All data included in the DAYPSCI dataset were generated by the authors through controlled experimental campaigns conducted on the proposed CPS testbed. No external datasets or third-party sources were used for dataset generation.

To improve clarity and reproducibility, Fig. 2 illustrates the architecture of the CPS-based testbed and the data acquisition pipeline used for dataset generation.

CPS-based testbed architecture for event-based dataset generation.

Control logic and process modeling

The control program was implemented following standard PLC programming practices [4], based on cyclic scan execution. The system behavior was modeled using a discrete-event approach, representing the industrial process as a sequence of state transitions.

The operational workflow was defined according to the GEMMA guideline [5], explicitly modelling modes such as automatic operation, fault occurrence, and recovery sequences. This approach ensures a structured and reproducible representation of system dynamics under both nominal and faulty conditions.

Data acquisition strategy

Data acquisition was performed at the PLC level using an event-based approach. Events were generated upon changes in relevant system variables, including sensor signals, actuator states, and internal control variables.

Each event includes a timestamp obtained from the PLC system time (RD_SYS_T, UTC), a unique sequential identifier, and the corresponding variable change. Events were temporarily stored in an internal ring buffer within the PLC memory and periodically transmitted to an external storage system.

Fig. 3 illustrates the event-based data acquisition and transformation process, improving the clarity and interpretability of the dataset. Raw binary signals from sensors and actuators, together with process-state information based on the GEMMA methodology, are monitored at the PLC level, where events are generated through rising and falling edge detection.

Event-based data acquisition pipeline with SQL-based Δt computation.

Events are temporarily stored in a circular buffer and subsequently transferred to a SQL Server database, where the time between consecutive events (Δt) is computed to obtain a compact and temporally meaningful representation of system behavior. The buffer is implemented within the PLC memory and consumed by a dedicated acquisition application, decoupling event acquisition from data storage operations and preventing event loss caused by communication or database access delays.

The dataset generation workflow follows a structured process. First, experimental conditions and fault-injection scenarios are defined through the supervisory layer. The CPS testbed then executes the corresponding production cycles using Siemens PLCs and the digital twin environment.

In addition to process data acquisition, the CPS architecture illustrated in Fig. 2 enables the collection of industrial network traffic through a managed switch configured for traffic mirroring. Using a Wireshark-based acquisition system connected to the PROFINET network, the network traffic is captured and stored in PCAPNG format. The resulting traffic traces are linked to the corresponding experimental batch, enabling joint analysis of process events, system behavior, and network traffic.

Finally, processed datasets (CSV files), network traffic captures (PCAPNG files), and metadata describing the experimental configuration are organized into independent experimental batches and made publicly available through the institutional repository.

Data storage and feature engineering

All data were stored in an SQL Server database. The original event records were preserved without modification to ensure data integrity. Additional temporal features, such as inter-event time (Δt), were computed through SQL-based post-processing.

To capture execution semantics at scan level, each event was annotated with: scan_id (identifier of the PLC scan cycle) and event_order (relative execution order within the scan).

This allows the representation of multiple events occurring within the same scan cycle while preserving the logical execution order of the control program.

Fault injection and experimental conditions

Controlled fault injection was applied to generate anomalous operating conditions by introducing faults in digital sensors and solenoid valves. The dataset includes multiple fault types, comprising six sensor fault scenarios, three solenoid valve fault configurations, and one combined fault conditions affecting both components, providing representative coverage of common fault conditions encountered in PLC-controlled automated systems.

To ensure reproducible experimental campaigns, a dedicated fault-planning tool was developed. The tool allows researchers to configure batch size, random seed, class distribution, candidate sensors and actuators, and fault-injection parameters before data acquisition. Based on this configuration, a fault-injection plan is automatically generated, specifying the affected parts, target components, fault types, and associated parameters for each experimental batch.

Fig. 4 illustrates the configuration and planning stage of the fault-injection campaigns. The tool distinguishes between eligible components that may be affected by faults and the actual components selected for a given experimental batch, ensuring controlled and reproducible fault distributions. Faults were configured externally to the control logic, ensuring that the PLC program remained unchanged during all experiments. This separation ensures that anomalies are externally defined and not derived from the control logic, providing a clear distinction between process execution and labeling.

Experiments were conducted under consistent conditions, including identical hardware configuration, communication settings, and control logic.

Ground truth labeling

Ground truth labeling is generated through a hybrid approach, combining externally defined labels from the experimental configuration and labels derived at runtime from control system signals, as illustrated in Fig. 5.

The experimental configuration, defined by a higher-level supervisory layer, specifies the intended fault scenarios, while runtime signals from the PLC (e.g., GEMMA states and system responses) capture the observable effects of these faults.

During data acquisition, configuration parameters are associated with each event, enabling the integration of planned fault information with runtime behavior. This allows each event to be labeled according to anomaly type, fault occurrence, affected component, and fault characteristics.

This approach ensures a clear separation between the industrial process (CPS) and the labeling layer, while enabling traceability between injected faults (cause) and observable system behavior (effect). Furthermore, it enables differentiation between fault activation and observable anomaly manifestation, which may be temporally decoupled.

Network data acquisition

Network traffic was captured simultaneously during each experiment using Wireshark (version 4.4.5) from a mirrored network interface in a Profinet-based industrial communication environment and stored in PCAPNG format for subsequent analysis.

The captured traffic includes cyclic communication and industrial network interactions between PLCs and field devices operating over Profinet.

Dataset organization

The dataset is structured into independent experimental batches, as illustrated in Fig. 1. Each batch corresponds to a specific operating condition, including nominal operation and fault injection scenarios, and contains the corresponding processed event-based dataset (CSV), synchronized industrial network traffic captures (PCAPNG), and a README.md file describing the associated experimental configuration.

This organization facilitates reproducibility and supports benchmarking of anomaly detection, fault diagnosis, machine-learning, and cybersecurity methods.

Limitations

The dataset was generated using an industrial CPS testbed based on a PLC-controlled part marking station, and therefore reflects its specific characteristics, architecture, and operational behavior, potentially limiting generalization to other industrial systems. Experiments were conducted under controlled conditions with deterministic fault injection, ensuring reproducibility and precise ground truth labeling, but potentially not capturing the full variability of real production environments.

Furthermore, the range of fault types and experimental scenarios is limited to a predefined set of sensor and actuator faults. Other types of anomalies, such as complex multi-component failures or network-based attacks, are not included in the current version of the dataset.

Despite these limitations, the dataset provides a consistent and well-controlled representation of industrial process behavior under both nominal and faulty conditions, enabling systematic experimentation and benchmarking.
