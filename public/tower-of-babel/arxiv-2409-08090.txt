nifty-ls : Fast and Accurate Lomb-Scargle Periodograms Using a Non-Uniform FFT
Lehman H. Garrison, Dan Foreman-Mackey, Yu-hsuan Shih, Alex Barnett

Abstract
We present nifty-ls , a software package for fast and accurate evaluation of the Lomb-Scargle periodogram. nifty-ls leverages the fact that Lomb-Scargle can be computed using a non-uniform FFT (NUFFT), which we evaluate with the Flatiron Institute NUFFT package ( finufft ). This approach achieves a many-fold speedup over the Press & Rybicki (1989) method as implemented in Astropy and is simultaneously many orders of magnitude more accurate. nifty-ls also supports fast evaluation on GPUs via CUDA and integrates with the Astropy Lomb-Scargle interface. nifty-ls is publicly available as open-source software.



I
Introduction

The Lomb-Scargle periodogram is a widely-used analysis tool for astronomical time-series data

1

For recent improvements in time-series analysis with unevenly sampled data, see
Wilber et al. 2024

, which also use
finufft
.
(
Lomb 1976
;
Scargle 1982
; c.f.
VanderPlas 2018
). However, its direct computation is prohibitively slow: for a number of observations
N_{d}
and number of periodogram frequencies
N_{f}
, the work has time complexity
\mathcal{O}(N_{d}N_{f})
. The popular
Press & Rybicki 1989
method (hereafter
9
) addresses this by posing the computation as four weighted trigonometric sums solved with a pair of fast Fourier transforms (FFTs) on an equi-spaced grid. The unevenly sampled data points are interpolated to this grid by a process that
9
call “extirpolation.” The trigonometric sums take the form:

\displaystyle S_{k}=\sum_{j=1}^{N_{d}}h_{j}\sin(2\pi f_{k}t_{j}),

\displaystyle C_{k}=\sum_{j=1}^{N_{d}}h_{j}\cos(2\pi f_{k}t_{j}),\quad k=0,1,\dots,N_{f},

(1)

where

f_{k}
is the cyclic frequency of bin
k
,
t_{j}
are the observation times (of which there are
N_{d}
), and
h_{j}
are the weights. The
9
method
approximates these sums via extirpolation, which, with the FFT, reduces the work to
\mathcal{O}(N_{d}+N_{f}\log N_{f})
. This is the default algorithm in popular packages like
Astropy

(
Astropy Collaboration et al. 2018
)
and
LombScargle.jl
2
2

2

https://github.com/JuliaAstro/LombScargle.jl
. Indeed, the algorithm is simply called
fast
by
Astropy
3
3

3

https://docs.astropy.org/en/v6.1.x/timeseries/lombscargle.html
.

We observe
(
Leroy 2012
, following, e.g.,)
that Eqs.
1
are exactly the equations of a non-uniform fast Fourier transform (NUFFT). A NUFFT is an extension of the FFT to unevenly sampled data
(
Dutt & Rokhlin 1993
)
. Specifically, a type 1 (non-uniform to uniform, also known as “adjoint”) complex NUFFT evaluates

g_{k}=\sum_{j=1}^{N_{d}}h_{j}e^{ikt_{j}},\qquad k=-N_{f}/2,-N_{f}/2+1,\dots,N_{f}/2.

(2)

In modern NUFFT algorithms, the accuracy of evaluation
\varepsilon
is a user-controlled parameter that may be chosen as small as desired, down to nearly machine precision. Higher accuracy increases the cost per nonuniform data point:
specifically, the NUFFT time cost is
\mathcal{O}(N_{d}\log\varepsilon^{-1}+N_{f}\log N_{f})
.
We see that the real and imaginary parts of
g_{k}
are
9
’s
C_{k}
and
S_{k}
respectively, for frequencies
f_{k}=k/2\pi
.

We evaluate the NUFFT with
finufft
, the Flatiron Institute NUFFT
(
Barnett et al. 2019
;
Barnett 2021
)
. The
finufft
approach is similar in spirit to
9
—upsample the data to a fine grid, perform an FFT, then correct with a diagonal rescaling—but
finufft
has a near-optimal spreading kernel (an “exponential of semicircle”) that it uses instead of extirpolation. Its width and fine grid size are carefully chosen to match the user tolerance
\varepsilon
, and manual SIMD-vectorized piecewise polynomials makes kernel evaluation extremely fast.
finufft
also supports multi-threaded CPU evaluation and GPU evaluation via CUDA
(
Shih et al. 2021
)
, with best-in-class performance and accuracy.

We implement this
finufft
-based Lomb-Scargle periodogram in the
nifty-ls
software package.
nifty-ls
is written in Python, with some modules implemented using C
++
and OpenMP for performance. It provides a backend to the
Astropy
Lomb-Scargle interface, so code that uses
Astropy
can benefit with minimal changes (setting
method="fastnifty"
in
Astropy
calls).
nifty-ls
is developed as open-source software on GitHub
4
4

4

https://github.com/flatironinstitute/nifty-ls/
, with binary distributions available on PyPI.

II.1
Performance

nifty-ls
is several times faster than
Astropy

fast
on using a single CPU thread, with speedups of
2\times
on small transforms to
5\times
on large. This is seen in the left panel of Fig.
1
. CPU multi-threading helps large transforms, yielding a
11\times
speedup over
Astropy
, although the improvement is sub-linear in the number of threads (a well-known result for FFTs, since the time is dominated by memory accesses).
The performance can be summarized by around
10^{7}
output frequencies per second on the CPU, or
10^{8}
on the GPU. Additionally,
nifty-ls
exposes a batched processing mode for sets of time series with the same observation times, which can more efficiently use CPU and GPU parallelism.

Using the GPU via
cufinufft

nifty-ls
is
200\times
faster than
Astropy
for large
N_{d}
. For small
N_{d}
, the problem is not large enough to overcome GPU overheads or saturate the GPU. Still, for
N_{d}
as small as 4000 there is a benefit over
finufft

N_{d}

Our tests also suggest that the NUFFT approach is more efficient than a brute-force (i.e. quadratic complexity) CUDA evaluation of Eqs.
1

Townsend 2010

Gowanlock et al. 2021

2\times 10^{7}

2.4\times
performance advantage of the A100.

II.2
Accuracy

nifty-ls

In summary,
