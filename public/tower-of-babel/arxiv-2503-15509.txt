Representing data in words
Amandine M. Caut, Amy Rouillard ∗, Beimnet Zenebe ∗, Matthias Green, Ágúst Pálmason Morthens, David J. T. Sumpter

Abstract
An important part of data science is the use of visualisations to display data in a way that is easy to digest. Visualisations often rely on underlying statistical or machine learning models — ranging from basic calculations like category means to advanced methods such as principal component analysis of multidimensional datasets — to convey insights. We introduce an analogous concept for word descriptions of data, which we call wordalisations. Wordalisations describe data in easy to digest words, without necessarily reporting numerical values from the data. We show how to create wordalisations using large language models, through prompt templates engineered according to a task-agnostic structure which can be used to automatically generate prompts from data. We show how to produce reliable and engaging texts on three application areas: scouting football players, personality tests, and international survey data. Using the model cards framework, we emphasise the importance of clearly stating the model we are imposing on the data when creating the wordalisation, detailing how numerical values are translated into words, incorporating background information into prompts for the large language model, and documenting the limitations of the wordalisations. We argue that our model cards approach is a more appropriate framework for setting best practices in wordalisation of data than performance tests on benchmark datasets. Keywords: NLP, visualisation, wordalisation, LLM

As a form of documentation, model cards lie somewhere between a README file, which explains how to run the code, and detailed analyses of a method that are typically presented in academic publications. By following a model card, users have a clear, step-by-step guide to reproduce the model and understand how it functions. This approach not only ensures reproducibility but also helps demystify the model’s behaviour, making it easier for others to replicate, test, and build upon the work. Additionally, it provides crucial information about the model’s limitations, enabling users to understand its boundaries and potential risks. By clearly outlining both the model’s strengths and weaknesses, the model card fosters more informed and responsible use, helping users avoid misuse or misinterpretation.

With the increased capabilities of large language models, benchmarks have been proposed to measure labelling, paraphrasing and inference performance of these models
[

[
19

[

These issues can be understood in the context of visualisations, of which thousands are produced daily across industries, science, and journalism. Given that the range of subject matter for which visualisations are created is so diverse, it would be both impractical and meaningless to expect every design to adhere strictly to a benchmark or pass standardised design test. In the context of this critique of benchmarking, we will view the model card approach as providing a much needed alternative to model benchmarking, by instead offering best practices for thinking about how to describe the principles used in constructing wordalisations. Indeed, rather than just being about documentation, model cards offer a flexible framework for innovative thinking around best practices in modelling. For example, Tang et al. (2024) used a participatory approach where members of communities impacted by AI decision-making systems created their own cards to illustrate how AI can fail

3
Constructing prompts

The aim of this section is to explain step-by-step how to construct a prompt underlying a wordalisation. We propose four steps for the prompt as follows:

Tell it who it is.

The first step is to set the system prompt, which defines the role of the language model (e.g. Gemini or ChatGPT) which will be used to generate text.

Tell it what it knows.

Here we give user-assistant prompts in the form of question-answer pairs which provide both information on how the language model should answer questions and provide background knowledge.

Tell it what data to use.

This step converts the content of the dataset and a selected data point into words.

Tell it how to answer.

We provide examples of how the language model should write the final description from the text generated at the "tell it what data to use" stage.

We now outline these steps in more detail using the three applications as examples.

3.3
Tell it what data to use

Wordalisations are not machine learning models, but they do assume an underlying statistical model in how we interpret data. In the case of the three applications presented here we assume we can assess an individual
i

z_{i,j}=\frac{x_{i,j}-\mu_{j}}{\sigma_{j}},

where
\mu_{j}
is the mean and
\sigma_{j}
the standard deviation of the metric
j

The z-scores are useful because they standardise the metrics and allow us to, for example, compare a player in terms of receiving and passing the ball on the same scale, defined by how far their z-score is from that of the average player in terms of standard deviations. Following statistical convention, one standard deviation can be considered to be larger than usual, two standard deviations can be considered to be significantly larger and so on.

Model cards

We advocate for design transparency through the use of detailed model cards, with evaluation used to support specific claims about model performance. A model card is a structured document that provides key information about a machine learning model, with a particular focus on providing relevant information about how the model was designed, how it can and cannot be used and its potential weaknesses
[
14
]
. A model card differs from a README file in that it helps the reader to understand and reproduce the results, possibly modified for their own use case, as opposed to simply instructing a new user how to run the code. It should also enhance transparency and accountability, point out weaknesses and outline ethical considerations. Building on concepts from Mitchell et al
[
14
]
, Gebru et al
[
16
]
. and Bender and Friedman
[
29
]
, we align our work to follow standardised documentation practices that emphasise transparency, reproducibility and context based interpretability.

We adopted Mitchell et al.’s framework to create a comprehensive model card for our applications, covering essential aspects such as model details, intended use, key factors affecting performance, evaluation metrics, and ethical considerations
[
14
]
. Since we used a pre-trained large language model rather than training our own model, certain elements were adapted or omitted. Specifically, we did not include details on training algorithms, parameters, or fairness constraints in the Model Details section, nor did we apply "variation approaches" for metrics or specify decision thresholds.

In each model card, we fully document the data source, detail how the data was interpreted, explain how z-scores were used to describe individuals, explain the quantitative mode in term of z-score, outline the normative models implied, and discuss the ethical considerations.
For example, for the personality test data we reference the Kaggle
4
4

4

www.kaggle.com/datasets/tunguz/big-five-personality-test
dataset which we used, gave a description of how questions were weighted to give the personality traits and then explained how the scores were calculated, and the corresponding source of informations. For ethical considerations, we examine the ethical concerns associated with the application of personality tests and provide relevant references.

The international survey data, which focuses on social differences between people living in different countries, was possibly the most challenging ethically. To address these concerns, we provide a detailed explanation of the dataset utilised, including it is nature and composition. In the model card, we provide a map showing the distribution of participants across the global.
This information is presented to caution against overgeneralising insights derived from analysing this dataset to broader populations. Additionally, we acknowledge criticisms of the analytical framework applied
[

,

]
and strongly encourage domain experts to consider these critiques when interpreting or leveraging this data.
We state that we used this dataset solely to demonstrate our methodology for converting complex data into wordalisations, without any intention to generalise findings beyond this scope.

5
Evaluation

Assessing the performance of a large language model on a specialised task, such as creating wordalisations for a specific application, is challenging. There exists no standardised benchmark test that can evaluate the model’s performance on such a task in a consistent way, nor do we believe it is realistic or necessary to construct one. Each wordalisation application has it’s own unique and subjective set of goals and assessment criteria. Furthermore, it is difficult to verify whether a particular benchmark presents a valid measure of a models behaviour in a real world setting
[
32
,
19
,
33
]
. Instead of benchmarks we propose a method for estimating the accuracy of the statements made in a wordalisation with respect to the original data. In other words, our goal is to establish whether the model was able to faithfully report on the data that was provided.

For each data point in our datasets — that is a player, person or country — we generated a wordalisation based on the prompt template used in the corresponding application. As a control comparison, we also generated wordalisations using a modified prompt that omitted the synthetic text generated using the normative model, see boxes in Section
3.3
for examples. To discourage the LLM from declining to respond, we added the sentence "If no data is provided answer anyway, using your prior statistical knowledge.". We also modify one of the few-shot learning examples by removing the synthetic text from the user prompt while leaving the wordalisation unchanged. This corresponds to removing the statistical description from the ‘User’ column of Table
3
. For consistency, the same prompt template was used in both test and control settings, that is with and without statistic descriptions. To take into account random variations in the wordalisations due to the stochastic nature of the language model, we passed each prompt to the LLM multiple times generating several wordalisations for each data point. In this way, we generated a sample of test and control wordalisations for players, people and countries.

We then investigate whether it is possible to accurately reconstruct the statistical description of a data point from the wordalisation. The accuracy of the reconstructed statistical description serves as a measure of how faithfully the wordalisation represents the data point. Given a wordalisation, we instruct the LLM to classify each factor according to the classes determined by the normative model. For example, given the wordalisation of Peru for the international survey application shown the ‘Assistant’ column of Table
3
, it is possible to (correctly) predict the class ‘below average’ for the ‘Survival vs Self-expression’ factor. We prompt the LLM to predict a classification for each relevant factor in the form of a json file. We then compare the ‘true’ class determined by data and the normative model with the predicted class. In cases where the generated json file could not be parsed, the data was discarded.

For this reasons it was more difficult for the LLM to reconstruct the statistical descriptions of a football player from a wordalisation, compared to a person or a country. Depending on the use case and intended audience of the application this is of more or less concern. For example, a football expert might favour an engaging, descriptive text, while a human resources manager or social scientist might prefer an unadorned, to-the-point summary.

7
Discussion

The "stochastic parrots" view of large language models sees them as a method for predicting the next phrase in a sequence of words, without understanding or reasoning
[
34
]
. Accepting this view, and rejecting more speculative ideas about the general intelligence of these models, we can still ask to what degree LLMs can produce texts that are simultaneously engaging to a reader and accurate about a given subject. It is answering this question that has led us to our four steps of telling an LLM ‘who it is’, ‘what it knows’, ‘what data to use’ and ‘how to answer’ as a way to produce convincing texts. Instead of fine-tuning a model, we force the parrot (i.e. a pre-trained LLM) to produce the texts which reflect our own model of that data. Previous work has shown that extensive fine-tuning of LLMs often does not significantly outperform (and in some cases underperforms) methods based on prefixed prompts on benchmark tasks
[
35
,
36
]
. Indeed, “prompt-based learning”
[
37
,
12
,
13
]
, of which our wordalisations are examples, are a powerful way of utilising the power of LLMs in a way which respects their limitations. Our four-step automated method underlines just how well prompting can perform on application areas.

Novel to the wordalisation approach is an extensive and explicit representation of an underlying mathematical model of the data. A standard prompt-based method typically uses the pre-prompt to clarify the task. For example, in order to determine the emotion in a sentence like “I missed the bus today", we might add a prompt “I felt so …” to model the fact we would like to extract emotion
[
12
]
. Similarly, we might prompt "1+4=5; 7+12=19; 3+13=…" to model that we would like the result of an addition of two numbers. In our case, the ‘what data to use’ step defines a mathematical model of how we interpret the numbers in terms of z-scores and the other three steps give a text-based model of how we should interpret those scores. While z-scores are a relatively simple mathematical model, we envisage (and are currently implementing) more advanced statistical models — such as regression, principal component analysis and moving averages — as the basis for wordalisations.

As language models become integrated into an increasing number of tools, it is essential to provide transparent documentation of the thought process behind the prompt engineering
[
12
]
. Our four-step construction method provides a structured way to perform such documentation and aligns well with the model card framework. We believe that such documentation makes it easier to identify the source of a problem, should it arise, and facilitates adapting the prompting technique to new use cases.

We investigated one automated evaluation process, whereby the texts that were generated by the LLMs from the data were used to reconstruct the raw data. This evaluated whether the generated text captured the true information presented in the data.
The main advantages of leveraging the capabilities of a language model to automate the evaluation process are speed and ease of implementation. We were able to evaluate more than five thousand texts, a task that we did not have the resources to perform manually. However, while this type of automated evaluation provides an indication of how literally the wordalisations represents the data, this assesses just one narrow aspect of the model’s performance and does not replace the qualitative evaluation that comes from using the application and judging its usefulness. To draw a comparison with visualisations, while it is important that a graph reflects data accurately this cannot be used as the yardstick to differentiate between all ‘good’ and ‘bad’ visualisations. For example, according to the LLM evaluation, the wordalisations for the football scout application were on average poor. But upon inspection it was clear that they did not contain inaccuracies, rather they contained more varied language and were less formulaic, and therefore were difficult to parse by the LLM. In summary, we see our evaluations primarily as highlighting the limitation of the automated approach.

The wordalisation task involves generating text from structured data, making it a fundamentally different objective than captured by established benchmarks for Natural Language Processing (NLP) tasks. To see why this is the case, consider how
Wang et al.
[
18
]
categorise NLP benchmarks into three types: single-sentence tasks, similarity and paraphrase tasks, and inference tasks.
In the case of single-sentence tasks, the benchmarks CoLA
[
38
]
and SST-2
[
39
]
are designed for labelling, such as sentence acceptability and sentiment prediction, and differ significantly from the aim of wordalising data. Moreover, similarity and paraphrase tasks, where the goal is to assess whether sentence pairs or question-answer pairs are similar or semantically equivalent
[
40
,
41
,
42
]
, also do not align with the needs. That said, in the "tell it how to answer" step, where we rephrase and refine the generated text using models like ChatGPT
6
6

6

https://github.com/openai/simple-evals?tab=readme-ov-file#benchmark-results
and Gemini
7
7

7

https://deepmind.google/technologies/gemini/
, we could consider relevant benchmark tests from those models themselves. For inference tasks, the benchmarks focus on evaluating prediction performance from a given text. For example, the Multi-Genre Natural Language Inference Corpus (MNLI)
[
43
]
and the Recognizing Textual Entailment (RTE)
[
44
,
45
,
46
,
47
]
datasets evaluate whether a given hypothesis is confirmed, contradicted, or neutral based on the provided context. Similarly, the Stanford Question Answering Dataset (QNLI)
[
48
]
focuses on classifying sentence pairs by determining whether a question is supported by its corresponding sentence. Finally, The Winograd Schema Challenge (WNLI)
[
49
]
, on the other hand, assesses a model’s ability to correctly resolve pronouns in ambiguous contexts. While these benchmarks are valuable for a variety of NLP tasks, they do not align with the objectives of our approach.

We rather see the wide variety of potential wordalisations as an illustration of Bowman and Dahl’s assertion that "benchmarking for NLU (Natural Language Understanding) is broken". In our work, we do not aim to build AI agents that improve on benchmark tasks, but rather we aim to propose methods for generating reliable texts about specific areas. We prime the stochastic parrot with information in a way that better reflects the domain. Since no standardised benchmark exists to evaluate the domain — how people discuss football, personality tests, or international value surveys — the assessment primarily relies on human feedback to gauge its effectiveness. We thus recommend adopting best practices, such as using a model card, as outlined here and working iteratively to improve this approach.

Wordalisations, similar to visualisations, are powerful tools for data communication. They have the potential to make all types of data more accessible and comprehensible to a wider audience. However, evaluating them is inherently subjective, as absolute accuracy is often unattainable
[
50
,
51
]
. In our work, we have embraced this reality by prioritising transparency and honesty, akin to practices in visualisation. Rather than solely emphasising numerical evaluations, we advocate for providing thoughtful documentation through model cards as a more holistic approach to communicating model capabilities. Benchmarking and evaluation, while having some value, should support this process rather than be the sole target. We can compare this process with journalism: journalists rarely focus on benchmarking their work, but attempt to maintain high standards. Those exploring prompting should focus on documenting and standardising their methodologies to build a robust framework for future use. Looking ahead, prompting will play an increasingly significant role and having a clear structure for documentation will be essential. We hope that this article is a contribution in that direction.
