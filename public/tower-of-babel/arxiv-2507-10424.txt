A mapping of the Min-Sum decoder to reduction operations, and its implementation using CUDA kernels
Omer S. Sella, Thomas Heinis

Abstract
Decoders for Low Density Parity Check (LDPC) codes are usually tailored to an application and optimized once the specific content and structure of the parity matrix are known. In this work we consider the parity matrix as an argument of the Min-Sum decoder, and provide a GPU implementation that is independent of the content of the parity matrix, and relies only on its dimensions.



I
Introduction

LDPC codes made their way into several standards and technologies, spanning telecommunications and storage
[
1
]
. Prior to adoption, it is sometimes the case that several codes are considered, stemming from different constructions or parameter tuning of a single construction
[
15
]
. In this early, short-lived stage, decoder optimizations that are a function of the specific parity matrix are not readily available. In this stage, a high throughput decoder helps eliminate or choose from a selection of codes, often having a parity matrix of similar dimensions.
This work is concerned with the optimization of the Min-Sum decoder when only the dimensions of the parity matrix
H
are known.

II
Preliminaries

The material presented here is entirely covered or can be deduced from prior literature. Nevertheless, we believe that the practical significance of it makes it worthwhile to present here.

II-A

A collection of linear equations over a binary field

The reader may be familiar with the term Single Parity Checksum (SPC).
Given a vector

(2)

.
The corresponding vector
\mathds{1}_{I}=(1,1,0,1,1,0)

II-B

The Min-Sum algorithm

We continue by examining the Min-Sum decoding algorithm as summarised here in Algorithm
1
.
A complete mathematical derivation, as well as other algorithms, can be found in
[
12
]
.
In our context, it is more important to understand how the algorithm works and how it could be rephrased so it can be implemented in various ways.
As mentioned, an assignment of a binary sequence:

c\in\{0,1\}^{||B||}

(3)

is a codeword if and only if it satisfies all check nodes in
C
.
The Min-Sum algorithm, summarised in Algorithm
1
and used in this work, uses this structure to pass messages between bit nodes and check nodes. Every bit node is assigned a real number representing Log-Likelihood-Ratio (LLR).
Its sign represents its logical value. In this work, strictly positive means logical "1", and non-positive means logical "0".
A bit node’s magnitude represents the confidence of the bit node in its logical value, i.e., larger magnitude means more certainty.
We follow the notation from
[
12
]
with minor changes so that we can build on it in the following chapters. For a check node
c_{i}\in C
denote by
N_{i}
the subset of bit nodes that are connected to
c_{i}
, i.e.:

N_{i}\;=\;\left\{b_{j}\,:\,H(i,j)=1\right\}

(4)

the reader may note that these are determined by the locations of the non-zero entries in the
i^{\prime}th
row of the parity matrix
H
,
and indeed this is demonstrated in Figure

An observed vector
\boldsymbol{r}
of real values serves as initial values for the bit nodes.
The task of the decoder is to find a value
\lambda_{j}
for each bit node
b_{j}
that maximises:

P(\lambda_{j}\;|\;\boldsymbol{r},\,all\,checks\,involving\,b_{j}\,are\,satisfied)

(6)

It should be noted that this is a computationally feasible approximation of the optimum decoder, i.e., a decoder that would seek a codeword
\boldsymbol{c}
that maximises:

P(\boldsymbol{c}\;|\;\boldsymbol{r},\,H\cdot\boldsymbol{c}\,=\,0)

(7)

The min-sum decoder starts by taking the received values
\boldsymbol{r}
as a first estimation for the bit values, i.e.:

\lambda_{j}\;=\;\boldsymbol{r}(j)

(8)

The decoder continues by generating update values at the check nodes, followed by updating the values of the bit nodes.
Check node
c_{i}
generates individual updates to each bit node
b_{j}
which is a member of the set
N_{i}
, using the values
\lambda_{j}
of the other bit nodes in the same set:

\eta_{i,j}=\min_{b_{k}\in N_{i},\,k\neq j}\left\{|\lambda_{k}-\eta^{previous}_{i,k}|\right\}\cdot\prod_{\left\{k\neq j\;:b_{k}\in N_{i}\right\}}{sign(\lambda_{k}-\eta^{previous}_{i,k})}

(9)

where
\eta^{previous}_{i,k}
is the value calculated in the previous iteration by
c_{i}
and sent to
b_{k}
.
Where in the special case of the first iteration we define
\eta^{previous}_{k}=0
.

The bit nodes update their values by summing all values calculated by the check nodes connected to them, as well as the initially observed information i.e.:

\lambda_{j}=\boldsymbol{r}(j)+\sum_{c_{i}\in M_{j}}\eta_{i,j}

(10)

At this point, we can check if the algorithm converged to a binary code-word
b
by "slicing" the inferred values vector
\lambda(j)
, i.e. setting:

\begin{split}b(i)&=1\;if\;s(i)>0\\
b(i)&=0\;if\;s(i)\leq 0\\
\end{split}

(11)

III
A map reduce architecture of the Min-Sum algorithm

We begin this section with two observations regarding the Min-Sum algorithm
1
.
The first observation regards the term:

\min_{b_{k}\in N_{i},\,k\neq j}\left\{|\lambda_{k}-\eta^{previous}_{i,k}|\right\}

(12)

in equation
9
:

Observation III.1

The minimum taken in equation
9
does not need to be calculated for every
j
in the set
N_{i}=\left\{b_{j}\;:\;H(i,j)=1\right\}
.

Let:

min^{i}_{0}=\min_{b_{k}\in N_{i}}\left\{|\lambda_{k}-\eta^{previous}_{i,k}|\right\}

(13)

and:

min_{0}^{i}Location=arg\min_{\left\{b_{k}\in N_{i}\right\}}\left\{|\lambda_{k}-\eta^{previous}_{i,k}|\right\}

(14)

and finally:

min^{i}_{1}=\min_{\left\{b_{k}\in N_{i},\;k\neq min0Location\right\}}\left\{|\lambda_{k}-\eta^{previous}_{i,k}|\right\}

(15)

then there are two cases:

Case 1:

j\neq min^{i}_{0}Location
and hence

\min_{\left\{b_{k}\in N_{i},\,k\neq j\right\}}\left\{|\lambda_{k}-\eta^{previous}_{i,k}|\right\}\;=\;min0

(16)

Case 2:

j=min0Location
and hence

\min_{\left\{b_{k}\in N_{i},\,k\neq j\right\}}\left\{|\lambda_{k}-\eta^{previous}_{i,k}|\right\}\;=\;min1

(17)

Observation
III.1
can be found in
[
17
]
.

The second observation is similar in nature to observation
III.1
,
in that, we seek to reduce the number of numerical operations.
The second term of equation
9
, i.e.:

\prod_{\left\{k\neq j\;:b_{k}\in N_{i}\right\}}{sign(\lambda_{k}-\eta^{previous}_{i,k})}

(18)

requires a product of signs.

Observation III.2

Assuming the function
sign(\cdot)
returns either
1
or
-1
(but not
0
), we have:

\begin{split}\prod_{\left\{k\neq j\;:b_{k}\in N_{i}\right\}}{sign(\lambda_{k}-\eta^{previous}_{i,k})}=\\
=\prod_{\left\{b_{k}\in N_{i}\right\}}{sign(\lambda_{k}-\eta^{previous}_{i,k})}\times\frac{1}{sign(\lambda_{j}-\eta^{previous}_{i,j})}\\
=\prod_{\left\{b_{k}\in N_{i}\right\}}{sign(\lambda_{k}-\eta^{previous}_{i,k})}\times sign(\lambda_{j}-\eta^{previous}_{i,j})\end{split}

(19)

where the last equality stems from the fact that
\frac{1}{1}=1
and
\frac{1}{-1}=-1
.

The importance of observation
III.1
and observation
III.2
, other than the apparent reduction of mathematical operations,
is that they allow us to reformulate the Min-Sum algorithm using reduction operation on matrices.
Reduction operations lend themselves to Single Instruction Multiple Threads (SIMT) architectures, which are common to Graphics Processing Unit (GPU). Examples of reductions are the functions
min(\cdot),sum(\cdot),product(\cdot)
, and implementation of reduction operations on GPUs are explained in
[
7
]
and
[
5
]
.

In this section we will restate the components
\eta
and
\lambda
of the Min-Sum algorithm
1

so that a single iteration could be easily seen as a sequence of fan-out (map) and reduction operations.

If we define
\eta
as a matrix, i.e.:

\eta(i,j)\triangleq\eta_{i,j}

(20)

Then equation
10
takes the form:

\begin{split}\lambda_{j}&=\boldsymbol{r}(j)+\sum_{c_{i}\in M_{j}}\eta_{i,j}\\
&=\boldsymbol{r}(j)+\sum_{c_{i}\in M_{j}}\eta(i,j)\end{split}

(21)

If we were to make sure that in the above equation we have
\eta(i,j)=0
whenever
c_{i}\notin M_{j}
, then we would obtain:

\begin{split}\lambda_{j}&=\boldsymbol{r}(j)+\sum_{c_{i}\in M_{j}}\eta(i,j)\\
&=\boldsymbol{r}(j)+\sum_{c_{i}\in M_{j}}\eta(i,j)+0\\
&=\boldsymbol{r}(j)+\sum_{c_{i}\in M_{j}}\eta(i,j)+\sum_{c_{i}\notin M_{j}}\eta(i,j)\\
&=\boldsymbol{r}(j)+\sum_{i}\eta(i,j)\end{split}

(22)

We make sure of that by setting
\eta(i,j)=0
whenever
H(i,j)=0
, i.e.:

H(i,j)=0\implies\eta(i,j)=0

(23)

This allows for the implementation of the summation part of equation
10
as a reduction operation, rather than needing control logic.
Next we turn our attention to equation
9
.
Plugging in observations
III.1
and
III.2
as well as our definition of
\eta
as a matrix we obtain:

\eta_{i,j}=\\
\min_{b_{k}\in N_{i},\,k\neq j}\left\{|\lambda_{k}-\eta^{previous}_{i,k}|\right\}\cdot\prod_{\left\{k\neq j\;:b_{k}\in N_{i}\right\}}{sign(\lambda_{k}-\eta^{previous}_{i,k})}=\\
\min_{b_{k}\in N_{i},\,k\neq j}\left\{|\lambda_{k}-\eta^{previous}_{i,k}|\right\}\cdot\\
\cdot\prod_{k\;:\left\{b_{k}\in N_{i}\right\}}{sign(\lambda_{k}-\eta^{previous}_{i,k})}\cdot sign(\lambda_{j}-\eta^{previous}_{i,j})=\\
(\delta_{j,min^{i}_{0}Location}\cdot min^{i}_{1})+((1-\delta_{j,min^{i}_{0}Location})\cdot min^{i}_{0})\cdot\\
\cdot\;\prod_{\left\{b_{k}\in N_{i}\right\}}{sign(\lambda_{k}-\eta^{previous}_{i,k})}\cdot sign(\lambda_{j}-\eta^{previous}_{i,j})

(24)

We have already set
\eta(i,j)=0
whenever
H(i,j)=1
. Assume that:

sign(0)=1

then we have the following:

\displaystyle\prod_{\left\{b_{k}\in N_{i}\right\}}{sign(\lambda_{k}-\eta^{previous}_{i,k})}\cdot sign(\lambda_{j}-\eta^{previous}_{i,j})=

(25)

\displaystyle 1\;\cdot\;\prod_{\left\{b_{k}\in N_{i}\right\}}{sign(\lambda_{k}-\eta^{previous}_{i,k})}\cdot sign(\lambda_{j}-\eta^{previous}_{i,j})

(26)

\displaystyle=\prod_{\left\{b_{k}\notin N_{i}\right\}}{sign(\lambda_{k}-\eta^{previous}_{i,k})}

(27)

\displaystyle\cdot\prod_{\left\{b_{k}\in N_{i}\right\}}{sign(\lambda_{k}-\eta^{previous}_{i,k})}

(28)

\displaystyle\cdot sign(\lambda_{j}-\eta^{previous}_{i,j})

(29)

\displaystyle=\prod_{i}{sign(\lambda_{k}-\eta^{previous}_{i,k})}\cdot sign(\lambda_{j}-\eta^{previous}_{i,j})

(30)

and the term

\prod_{i}{sign(\lambda_{k}-\eta^{previous}_{i,k})}

(31)

is a reduction operation.
We are now ready to restate the Min-Sum algorithm in map and reduce form.

We begin with the inputs:

1.

The parity matrix
H
with dimensions
m\times n

2.

A set of values
\boldsymbol{r}
is observed at the receiver

3.

The maximal number of iterations is
L

The first iteration of the Min-Sum algorithm starts as follows:
We first map the vector of observation
\boldsymbol{r}
to a matrix by taking as many copies as there are check nodes,
m
, followed by masking with
H
and subtracting
\eta
:

\lambda(i,j)\triangleq\boldsymbol{r}(j)\cdot H(i,j)

(32)

We proceed by a reduction of
\lambda
to four vectors of size
m
;
min_{0}
,
min_{1}
and
min_{0}Location
defined as follows:

min_{0}(i)=\min_{0\leq j<m}\left\{|lambda(i,j)|:H(i,j)=1\right\}

(33)

and

min_{0}Location(i)=arg\min_{0\leq j<m}\{|lambda(i,j)|:H(i,j)=1\}

(34)

as well as:

min_{1}(i)=\min_{0\leq j<m,\;i\neq min_{0}Location(i)}\left\{|\lambda(i,j)|:H(i,j)=1\right\}

(35)

and finally:

sgn(i)=\displaystyle\prod_{\left\{0\leq j<m\right\}}sign(\lambda(i,j))\\

(36)

It should be noted that the first three vectors could be calculated at once using a sort function truncated to the two smallest elements.
Furthermore, the sign function here satisfies
sign(0)=1
.
We now have all the information we need to update the matrix
\eta
as follows:

\begin{split}\eta(i,j)=&H(i,j)\cdot\\
&sign(\lambda(i,j))\cdot sgn(i)\cdot\\
&(\delta_{j,min_{0}Location(i)}\cdot min_{0}(i)+\\
&(1-\delta_{j,min_{0}Location(i)})\cdot min_{1}(i))\end{split}

(37)

The next part is the "sum" part of the Min-Sum algorithm,
which we perform as a column-wise sum reduction of the matrix
\eta
, and add to it the initial observations vector
\boldsymbol{r}
:

\begin{split}s(j)=\displaystyle\sum_{\left\{0\leq j<n\right\}}\eta(i,j)+r(j)\\
\end{split}

(38)

At this point, we check if the algorithm converged to a binary code-word
\boldsymbol{b}
by slicing the vector
\boldsymbol{s}
as in equation
11
.
i.e. setting:

\begin{split}b(i)&=1\;if\;s(i)>0\\
b(i)&=0\;if\;s(i)\leq 0\end{split}

(39)

And then checking whether
\boldsymbol{b}
is in the kernel of
H
, i.e.:

\begin{split}H\cdot\boldsymbol{b}\;\;\;?=\;\;\;\boldsymbol{0}\end{split}

(40)

where the last equation is over the binary field, and
\boldsymbol{0}
is the all
0s
vector.

If
\boldsymbol{b}
is indeed in the kernel of
H
, then
\boldsymbol{b}
is a code-word and we can stop the algorithm.
Otherwise, we increase the iteration counter
k
by
1
:

k:=k+1

(41)

The algorithm proceeds iteratively, with a single difference in subsequent iterations.
We replace equation
32
with the following update of the matrix
\lambda
,
based on the vector
\boldsymbol{s}
instead of
\boldsymbol{r}
, and reducing the formerly calculated
\eta
:

\lambda(i,j)\triangleq\boldsymbol{s}(j)\cdot H(i,j)-\eta(i,j)

(42)

We note that this could be incorporated into the first iteration (setting
\eta
initially to an
m\times n\;\;0s
matrix as well as
\boldsymbol{s}
to be
\boldsymbol{r}
).

.

, the iteration number at which the decoder stopped

, a status indication

.

for all

.

Set

.

V
Related work

The implementation of a message-passing decoder developed in this work uses the min-sum decoding algorithm described in (for example)
[
12
]
and
[
10
]
.
A decoder architecture for 60GHz WiFi (802.11ad) and Bluetooth (802.153c) can be found in
[
16
]
.
The work there provides micro architecture hardware schematics as well as an estimate of power consumption.
Some insights on Graphical Processing Unit (GPU) implementation could be found in
[
17
]
,
where a 4.7 Gbps decoder is implemented on a GeForce 1080Ti.
The LDPC used in
[
17
]
was the same as the one used in WiFi standard 802.11n.
A similar work but specific to the codes used in the Digital Video Broadcasting (DVB-S2)
[
4
]
is presented in
[
8
]
.
For the codes used in 5G, a comparison between an FPGA and a GPU implementation is given in
[
2
]
,
and a 150Mbps software decoder is reported in
[
6
]
.
In this work we use CUDA kernels to implement reduction functions. The reader would find such reduction functions explained in
[
5
]
, and
[
7
]
.
