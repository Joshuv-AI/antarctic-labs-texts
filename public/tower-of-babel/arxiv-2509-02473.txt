FDABench: A Benchmark for Data Agents on Analytical Queries over Heterogeneous Data
Ziting Wang 1 Shize Zhang 2 Haitao Yuan 1 Jinwei Zhu 3 , Shifu Li 3 , Wei Dong 1 , Gao Cong 1

Abstract
. The growing demand for data-driven decision-making has created an urgent need for data agents that can integrate structured and unstructured data for analysis. While data agents show promise for enabling users to perform complex analytics tasks, this field still suffers from three critical limitations: first, comprehensive data agent benchmarks remain absent due to the difficulty of designing test cases that evaluate agents’ abilities across multi-source analytical tasks; second, constructing reliable test cases that combine structured and unstructured data remains costly and prohibitively complex; third, existing benchmarks exhibit limited adaptability and generalizability, resulting in narrow evaluation scope. To address these challenges, we present FDABench, the first data agent benchmark specifically designed for evaluating agents in multi-source data analytical scenarios. Our contributions include: (i) we construct a standardized benchmark with 2,007 diverse tasks across different data sources, domains, difficulty levels, and task types to comprehensively evaluate data agent performance; (ii) we design an agent-expert collaboration framework ensuring reliable and efficient benchmark construction over heterogeneous data; (iii) we equip FDABench with robust generalization capabilities across diverse target systems and frameworks. We use FDABench to evaluate various data agent systems, revealing that each system exhibits distinct advantages and limitations regarding response quality, accuracy, latency, and token cost. The source code, data artifacts have been made available at https://github.com/fdabench/FDAbench .

Challenges.
For benchmarking data agents with heterogeneous data, there are three key challenges (referred to as C1, C2, C3).

Challenge 1 (C1):
How to design test cases to comprehensively evaluate the abilities of data agents with various analytical query tasks?

Traditional benchmarks focus on well-defined, single-purpose tasks such as text-to-SQL
(
Yu et al. 2018
;
Lei et al. 2025
;
Li et al. 2023
)
or retrieval-augmented generation (RAG)
(
Yang et al. 2024
;
Nguyen et al. 2016
;
Cohen et al. 2018
;
Yang et al. 2018
)
. These tasks use fixed pipelines and produce standardized outputs such as SQL queries, which makes test case design relatively straightforward.
However, data agent systems are inherently open-ended, producing outputs that range from precise numerical values to comprehensive analytical reports that blend quantitative findings with qualitative insights. This output diversity creates significant evaluation complexity, as conventional metrics cannot adequately assess correctness, completeness, and reasoning quality across such heterogeneous results.
Moreover, data agents must orchestrate multiple analytical tools while integrating diverse data sources, including both structured databases and unstructured content. This multiple tools, multi-source orchestration capability makes comprehensive evaluation across varied analytical scenarios particularly challenging.

Challenge 2 (C2):
How to efficiently construct reliable test cases integrating structured and unstructured data?

Real-world data agents must handle diverse problems spanning multiple data sources, modalities, and domains. This necessitates benchmarks that combine structured data (e.g., relational databases) and unstructured data (e.g., text, documents, images), making data agent scenarios more complex than traditional tasks.
The fundamental challenge lies in effectively constructing real-world data agent tasks that meaningfully integrate these heterogeneous data types while establishing reasonable and reliable relationships.
Traditional manual dataset construction
(
Yu et al. 2018
;
Lei et al. 2025
;
Li et al. 2023
)
by human experts is prohibitively expensive, requiring careful problem design and ground truth verification for each task. While recent efforts
(
Hu et al. 2025
;
Wu et al. 2024
;
Zhao et al. 2024a
)
have explored automated task generation using LLMs, these approaches suffer from reliability issues
(
Snyder et al. 2024
)
. Therefore, the key challenge is designing methods to efficiently construct reliable test cases that meaningfully integrate structured and unstructured data.

Challenge 3 (C3): How to construct a generalizable and adaptable evaluation pipeline for various data agent systems?
Existing benchmarks are designed for specific tasks like text-to-SQL
(
Yu et al. 2018
)
or RAG
(
Yang et al. 2024
)
, making them unsuitable for evaluating diverse data agent systems. Current data agent research spans multiple technical approaches, including semantic operators
(
Liu et al. 2025a
;
Patel et al. 2025
)
, document processing pipelines
(
Shankar et al. 2025
)
, and multi-modal integration systems
(
Liu et al. 2025b
)
. Each approach employs different input formats, processing workflows, and output structures. Therefore, a rigid evaluation pipeline designed for one agent type may fail to capture the capabilities of another, while overly generic evaluation metrics may miss critical functionality differences. The challenge lies in developing an evaluation framework that can accommodate this technical heterogeneity while maintaining meaningful performance comparisons across different data agent paradigms.

Our contributions.

To address these challenges, we present three key contributions:

•

Comprehensive Data Agent Task Design:

To tackle C1, we develop FDABench with three distinct task categories (single-choice, multiple-choice, and report) that systematically evaluate different data agents’ analytical capabilities. Our benchmark encompasses 2,007 tasks across 50+ domains with varying difficulty levels, incorporating diverse input-output formats that range from precise numerical answers to comprehensive analytical reports. This design captures the inherent open-endedness of data agents while enabling systematic evaluation across heterogeneous data sources, including relational databases, PDF documents, video, audio, and web content.

•

Heterogeneous Data Construction Framework:

To address C2, we design an expert-agent collaboration framework for effectively constructing reliable and reasonable test cases that integrate structured and unstructured data. This approach helps establish meaningful connections between heterogeneous data (e.g., linking databases with relevant documents to produce reasonable data agent tasks). The framework incorporates expert validation at critical integration points to ensure data coherence and task validity while also providing a foundation for scalability.

•

Unified Evaluation Pipeline for Diverse Architectures:

To solve C3, we identify and categorize four distinct data agent workflow patterns: planning agent, tool use agent, reflection agent, and multi agent pattern. Based on this taxonomy, we design a unified evaluation pipeline that adapts to each pattern’s specific input formats, processing workflows, and output structures. This enables FDABench to evaluate both complete data agent systems and individual components within larger frameworks, providing meaningful comparisons across diverse technical approaches while maintaining evaluation consistency.

Finally, we conduct extensive experiments evaluating state-of-the-art data agent systems on FDABench. Our analysis examines how data agent architectural patterns impact performance, what factors affect cost-efficiency, and identifies research opportunities for improving data agent accuracy, latency, and token cost.

PRELIMINARIES

In this section, we first introduce the definitions of key concepts in Section
3.1
, including the data agent and heterogeneous analytical data workload. Subsequently, we define the problem formulation for our benchmark task.

3.1.
Key Concepts

Foundation Data Agent.
As mentioned in the introduction, data agents are designed to utilize LLMs’ reasoning and tool invocation capabilities by repositioning LLMs as reasoning and orchestrating tools rather than processing entire data content directly. A typical data agent generally possesses: first, multi-data source reasoning capabilities that enable data agents to analyze both structured data and unstructured content; second, capabilities of tool selection guided by contextual understanding and reasoning; third, adaptive decision-making frameworks that refine strategies through observation and external environment feedback. These features enable data agents to be used in multi-data reasoning and multi-step inference for complex scenarios.

Heterogeneous Analytical Data Workloads.
Heterogeneous analytical data workloads encompass analytical data agent tasks that integrate structured data content with unstructured data including documents, videos, or web content to generate comprehensive reports or inferences for decision-making, requiring data agent systems with robust understanding and processing capabilities for diverse heterogeneous data.

3.2.
Problem Definition

We formally define the key components of our benchmark for evaluating data agents on heterogeneous data analytics tasks.

Definition 3.1 (Analytical Data Agent Workload over Heterogeneous Data).

A heterogeneous data analytics workload
W
is characterized by the tuple
(q,\mathcal{D},\mathcal{K})
where:

•

q
denotes a user natural language analytical query that requires a data agent to solve

•

\mathcal{D}=\{D_{1},D_{2},\ldots,D_{n}\}
represents structured data sources such as relational databases

•

\mathcal{K}=\{K_{1},K_{2},\ldots,K_{p}\}
represents unstructured data sources such as documents or images

The complexity of such workloads arises from the need to combine and relate structured data and unstructured data. Unlike traditional analytics workloads that operate solely on structured databases or pure natural language processing tasks on text corpora, analytical heterogeneous data workloads for data agents require target systems to possess understanding and reasoning capabilities spanning both structured and unstructured data.

Definition 3.2 (Data Agent for Heterogeneous Data Analytics).

A data agent
\mathcal{A}
is defined as an agent system that processes analytical queries through heterogeneous data workloads with:

•

Foundation large language model
\mathcal{L}
: The underlying LLM providing reasoning and understanding capabilities for the data agent

•

Available tools
\mathcal{T}=\{T_{1},T_{2},\ldots,T_{m}\}

•

Agent policy
\pi
: The agent interaction orchestration strategy that determines tool selection and invocation based on query and observation information

The agent processes a query through:

(1)

\mathcal{A}(q,\mathcal{D},\mathcal{K},\mathcal{T})=\mathcal{L}\left(\pi(q,\mathcal{D},\mathcal{K},\mathcal{T},\mathcal{O})\right)

where
\mathcal{O}
represents the observation information gathered during agent-tool interactions.

The key characteristic of data agents for multi-source data analytics tasks lies in the data agent’s ability to autonomously decide and select appropriate tools to effectively answer a given query. This requires not only understanding the semantic intent of the user’s natural language query but also necessitates capabilities for selection and orchestration of different tools across multiple data.

TARGET SYSTEMS

Due to unclear boundaries of data agent capabilities and scope, users lack systematic understanding of what data agents can accomplish. Data agents are inherently open-ended: their role extends beyond solving fixed problems to coordinating multiple tools and sub-agents across heterogeneous data sources for comprehensive analytical results. In this section, we provide details about FDABench’s target systems. First, we introduce data agent architecture and components. Subsequently, we present four typical data agent architectural patterns.

4.1.
Data Agent Architecture Overview

As illustrated in Figure
2
, we systematically analyze FDABench’s target data agent system architecture. A typical data agent system should possess three fundamental capabilities:

Self-Decision.
Data agents should autonomously address complex data analytical tasks by integrating reasoning, understanding, and execution capabilities through large language models. Data agent systems should dynamically understand and reason over user natural language queries for goal completion. We follow Andrew Ng’s
(
dee 2025
)
agent architecture pattern classification to categorize different data agent architecture patterns, detailed in Section
4.2
.

Agent Tools.
Another distinguishing feature of data agents is their tool selection and orchestration capability for task completion. Data agents should effectively leverage diverse related tools (e.g., file systems, web search, and vector search) to address user natural language queries. For example, Agenticdata
(
Sun et al. 2025
)
designs a tool orchestration mechanism by selecting relevant tools based on semantic requirements, planning solutions with step-by-step tool invocation, and executing detailed operations such as generating SQL, specifying parameters for file operations, and configuring aggregation functions with appropriate keys and operators.

Heterogeneous Data Sources.
Data agents should differ from conventional agents through their capability to understand and process both structured and unstructured data simultaneously. When confronted with complex heterogeneous data environments, data agents must demonstrate proficiency in handling diverse data formats including relational databases, text, and multimedia content.

In FDABench, we provide over 2,007 different data agent tasks across over 110 databases and over 50 domains, encompassing diverse data sources, difficulty levels, and task types. These data agent tasks include both structured data and unstructured data, such as video, documents, and audio, specifically designed to comprehensively evaluate data agent performance in heterogeneous data analytical scenarios.

Data Agent Workflow Patterns

Current research presents diverse data agent workflows
(
Zhang et al. 2025
;
Xu et al. 2025
;

;

;

.

Planning Agent.

As shown in Figure
3(a)
, the Planning Agent enables LLM-based agents to autonomously decompose complex user queries into action sequences. This systematic decomposition reduces computational complexity and improves reasoning reliability. Agents dynamically generate multi-step plans and coordinate parallel subtask execution, incorporating resource allocation strategies to optimize workflow efficiency.

Tool-use Agent.

As depicted in Figure
3(c)
, the tool use pattern extends agent capabilities beyond static parametric knowledge through dynamic integration with external systems. Data agents invoke search engines, databases, APIs, and computational tools to overcome pre-trained knowledge limitations.

Reflection Agent.

As presented in Figure
3(b)
, the reflection pattern incorporates self-evaluation mechanisms for intermediate result assessment. Unlike forward-only execution, this workflow enables agents to assess output quality and relevance through dual-module architectures where evaluative components provide feedback to generative components. Through iterative evaluation and generation cycles, agents progressively refine outputs, transforming static execution into adaptive, self-correcting workflows.

Multi-Agent.

As demonstrated in Figure
3(d)
, the multi-agent pattern enables collaborative problem-solving by distributing specialized roles across multiple agents. Each agent maintains localized memory and task-specific workflows, exchanging intermediate results through inter-agent communication upon subtask completion. This enables complex problem decomposition and scalable modularity while leveraging distributed processing and specialized expertise for tasks exceeding single-agent capabilities.

BENCHMARK OVERVIEW

5.1.
Design Goals

Following typical system benchmark design goal classifications
(
Zhou et al. 2023
)
, we construct FDABench based on the four core benchmark design guidelines outlined by Jim Gray
(
Gray 1991
)
.

Relevance.
We design FDABench, which encompasses 2,007 diverse tasks across different data sources, domains, difficulty levels, and task types, collected from four data agent-related benchmarks: Spider, Spider2.0, BIRD, and DABStep. For unstructured data, we also collect over 1,600 unstructured multi-modal files including PDF, audio, and video for vector database search across different data domains. During benchmark construction, we incorporate extensive web information utilizing Perplexity search
(
Per 2025
)
to enhance unstructured data diversity. Ultimately, FDABench provides 2,007 distinct data agent tasks covering three task types across multiple data formats, domains and difficulty levels to comprehensively evaluate data agent performance in multi-data source analytical scenarios.

Simplicity.
To ensure benchmark simplicity, FDABench standardizes diverse data agent outputs into three concise task types: report, single-choice, and multiple-choice modes. This design transforms dynamic data agent responses into a fixed evaluation output format, thereby simplifying benchmark processing for users and enabling straightforward assessment of data agent systems’ complex reasoning and inference capabilities across different task types and data sources.

Portability.
We design FDABench with strong generalization and portability to accommodate diverse target data agent systems. FDABench features custom interfaces that enable straightforward evaluation of incoming target systems, regardless of variations in foundation models, tools, or agent patterns. Given the current fragmentation and lack of standardization in existing agent patterns, we provide fair open-sourced implementations and comparisons of four typical agent architectures. With minimal modifications, target agent systems can be seamlessly integrated into our benchmark for evaluation.

Scalability.
We design an agent-expert collaboration dataset generation framework to efficiently build FDABench with 2,007 diverse data agent tasks spanning multiple data formats, domains, difficulty levels, and task types, ensuring comprehensive benchmark scalability.

5.2.
Benchmarking Workflow

As illustrated in Figure
4
and Figure
5
, our benchmarking workflow consists of two primary phases: the Construction Phase and the Evaluation Phase, each designed to systematically generate and assess data agent capabilities.

Construction Phase.
This phase generates comprehensive datasets containing query workloads and associated structured and unstructured data sources. The process begins with
Data Collection
, where we gather diverse unstructured data from multiple sources, including academic papers, web content, and multimedia files, alongside existing data agent datasets from established benchmarks like BIRD, Spider, and DAbench.

Following the data collection phase, we implement
Dataset Construction Agent Generation
to first generate drafts of test case workloads. During this stage, we design three distinct task categories, including single-choice, multiple-choice, and report modes, that systematically evaluate data agents across heterogeneous data environments. These task types assess core capabilities, including data analysis, cross-modal reasoning, and inference capacity, while providing standardized metrics for both traditional database operations and emerging unstructured data requirements. For example, we use report mode to evaluate data agent performance in insight generation and use choice-based queries to assess data agents’ performance in precise numerical result retrieval and reasoning scenarios.
This automated generation leverages original gold SQL queries from validated datasets and ensures meaningful correspondence between natural language queries and database operations.
The construction phase concludes with
Human Expert Verification
, where generated test case drafts undergo expert review and incorporation of human feedback. This process continues until experts approve both the generated queries and corresponding gold results, or until maximum iteration limits are reached. Approved tasks are stored in FDABench, while substandard drafts are discarded to maintain benchmark quality and reliability. We follow this framework to generate over 3,000 data agent tasks and retain 2,007 distinct data agent tasks after expert filtering.

Evaluation Phase.
This phase systematically assesses
Target Data Agent Systems
using the constructed benchmark through comprehensive multi-stage evaluation. It begins by integrating various target data agent systems into our benchmark framework. These systems can invoke both structured data tools (e.g., traditional SQL-based tools, query optimization tools) and unstructured data tools (e.g., document processing tools, vector-based retrieval tools). Each target data agent system is configured to interface while maintaining its native processing capabilities. Subsequently, target systems process the FDAbench data agent tasks across three distinct task categories (i.e., single-choice, multiple-choice, and report). During execution, target data agent systems generate responses in standardized formats that capture both final answers and intermediate reasoning steps, enabling detailed analysis of decision-making processes. Finally, the
Evaluation Suite
employs multiple complementary metrics to evaluate data agent performance across each task category.

6.
DATASET CONSTRUCTION

As discussed previously, FDABench is designed to benchmark data agent performance over heterogeneous data sources in analytical workloads. To construct comprehensive analytical workloads across heterogeneous data, we first introduce our data collection methodology, then discuss the rationale behind the workload design, and finally present how we ensure the reliability of FDABench.

6.1.
Data Collection

The first step in our data collection involves systematic integration and preprocessing of heterogeneous data sources. We collect four open-source large-scale datasets: Spider
(
Yu et al. 2018
)
, Spider2.0
(
Lei et al. 2025
)
, BIRD
(
Li et al. 2023
)
, and DABstep
(
Egg et al. 2025
)
. These datasets comprehensively cover database text-to-SQL generation and multi-step reasoning tasks, providing a foundation for our data collection process. Following data cleaning and reorganization, we gather additional data for generating heterogeneous data analytic tasks. We collected and integrated unstructured data from over 50 domains across the internet, comprising more than 1,600 unstructured data files including PDF documents, audio recordings, and videos, embedding them into high-dimensional vector representations in vector databases.

To construct a benchmark for data agents in complex heterogeneous data analytics workloads, we acquire additional unstructured data beyond the initial text-to-SQL datasets and construct new complex query workloads. We employ unstructured data gathering tools like Perplexity search and vector database retrieval to gather supplementary unstructured information related to the original query for the next stage’s dataset generation. This approach captures external unstructured content and query-specific context that enhances the quality of workloads generated for data agents. Upon acquiring sufficient unstructured data, we implement an agent-expert collaboration dataset generation framework for validation to ensure data quality and consistency. This comprehensive data collection process serves as the foundation for constructing our data agent workload in heterogeneous data analytic scenarios.

To better evaluate data agents’ capabilities in multi-data source analytical scenarios, we design our workload with three distinct evaluation task categories targeting a comprehensive assessment of data agents’ analytical capabilities.

Our data schema comprises three primary task categories: single-choice (SC) Mode, multiple-choice (MC) Mode, and Report Mode. This design addresses Challenge 1: data agents’ outputs may exhibit dynamic answer formats that are non-standard and complicate the evaluation phase. Therefore, we design multiple task categories to standardize and comprehensively assess data agent performance. We design FDABench report mode which combines structured and unstructured data with real-world user queries, each paired with corresponding gold results, while we also construct single-choice and multiple-choice modes which include more numerical data or precise inference results in such heterogeneous data scenarios for evaluating data agents’ complex inference and reasoning capabilities.

Choices-based Task.
We design single-choice and multiple-choice modes to address data agents’ dynamic response nature, whose response format is difficult to determine, by providing standardized answer formats for objective correctness assessment. We construct choice-based questions requiring agents to perform aggregation and reasoning across heterogeneous data sources. The single-choice mode focuses on precise analytical queries with numerical results. Multiple-choice mode extends to more complex analytical tasks that involve reasonable structured and unstructured data combined inference results, requiring the identification of multiple correct answers.

Report-based Task.
Another urgent need for evaluating data agents is assessing report generation and inference capabilities. We provide Report Mode to address the need for evaluating data agents’ advanced report generation capabilities. Following traditional retrieval and RAG benchmark construction, we developed a Report Mode subset in FDABench containing gold results. This subset incorporates relational database analytical queries and unstructured data inference tasks to comprehensively assess inference skills in heterogeneous data scenarios. This mode requires agents to generate comprehensive reports demonstrating sophisticated database query processing, pattern identification, and synthesis of database insights with external knowledge sources.

6.3.
Dataset Generation

Next, we introduce how we guarantee FDABench’s test cases’ reliability. As mentioned in Challenge 2, due to LLMs’ hallucination and human annotation’s expensive cost, constructing a reliable benchmark efficiently is vital for dataset construction. To address these limitations, we design an agent-expert collaboration framework to maximize the efficiency and reliability of large-scale test cases. This design ensures the quality and reliability of FDABench while also providing a reusable framework for generating high-quality workloads across different tasks and domains.

Phase 1 (Initialization):
As shown in Algorithm
1
, we first extract original gold SQL queries from validated text-to-SQL datasets and execute them to obtain gold results, ensuring correctness between natural language queries and specific relational database operations. Then we design a data collection module that gathers comprehensive unstructured contextual information through web search, vector database retrieval, and file systems for the user’s natural language query based on database information and query intent. These designs enable FDABench to collect more relevant and complete content including both structured and unstructured data that serve as potential ground truth for subsequent dataset generation phases and ensure the correctness of appropriate gold subtasks for each query.

Phase 2 (Expert Verification and Refinement):
As shown in Figure
4
and Algorithm
1
Phase 2, given the original query and relevant multi-data source content, the dataset construction agent first generates FDABench dataset instances for human expert review. This draft instance includes new queries considering structured data and unstructured data relationships. Human experts review the generated draft instances and carefully examine the reliability and reasonableness of relationships between the new queries and corresponding gold results. The expert has three choices: accept, dispose, or revise. Human experts review based on the quality of the generated results, ensuring that only reasonable and high-quality instances are included in FDABench.

When human experts provide revision comments, dataset construction agents will incorporate comments and reanalyze context history to generate a revised dataset instance. This iterative refinement process continues until experts approve both the generated new queries and their corresponding gold results or the maximum iteration count is reached.

Phase 3 (Finalization):
As illustrated in Algorithm
1
, after human expert decisions, accepted dataset instances with gold results are stored in FDABench. We then classify each dataset test case into three difficulty levels based on reasoning token and tool call counts to ensure hierarchical dataset difficulty. Generated task drafts that fail to meet quality standards and reach maximum iterations are discarded to maintain FDABench reliability and quality.

Performance Analysis.

As demonstrated in Table
3
, architectural distinctions between planning-based workflow (e.g., DAgent) and Multi Agent workflow approaches reveal fundamental trade-offs in data agent design. First, for examining performance and effectiveness, we observe a clear difference between these two agent workflow types. For example, with the help of reflection and planning combined, AOP significantly outperforms DAgent’s purely planning-based method. This performance gap is also manifested in choice-based questions, where AOP’s EX scores exceed DAgent’s, demonstrating that complex agent architectures with reflection perform better in handling complex reasoning and precise numerical analytical scenarios.

Next, for efficiency, we find DAgent’s offline planning strategy achieves superior computational resource utilization, maintaining the lowest latency across all difficulty levels. In contrast, other complex workflow methods incur significant computational overhead: AOP shows moderate latency increase (165→225), while Multi Agent workflow approaches (e.g., AgenticData) suffer more latency penalties. Cost analysis reveals DAgent’s acceptable token increase, whereas other methods exhibit steeper cost increase.

Furthermore, external model call counts also serve as another key metric for evaluating data agent tool utilization, distinctly characterizing each data agent architectural design. DAgent’s lower average external model calls (4.1→5.1) reflect its pre-generated plans that eliminate runtime decision overhead. Other complex agent workflow methods require substantially more external model calls: AOP maintains moderate external model call counts (15.2→19.8), while Multi Agent workflow Taiji exhibits the highest external model call counts (26.4→31.1), indicating that complex data agents risk excessive tool invocation. Notably, Taiji’s excessive external model calls coupled with moderate performance expose the inefficiency of complex agent workflow design, suggesting that selecting suitable data agent workflows is essential for effective runtime adaptation.

In summary, the performance analysis reveals that architectural choice fundamentally determines data agent system performance rather than task-specific optimizations. DAgent’s offline planning excels in efficiency but suffers from adaptation limitations when task complexity increases. Complex agent workflow methods (AOP, AgenticData, Taiji) achieve superior effectiveness but incur computational cost penalties in latency and token, which represents an important consideration factor for future data agent design.

Performance Analysis.

Graph-based indexing methods such as GraphRAG and HippoRAG demonstrate the highest number of external model calls (23-25 times) for index construction and exhibit higher latency, while NaiveRAG achieves the lowest external model calls. CORAG’s optimization strategies effectively balance retrieval accuracy with computational overhead, representing successful cost-aware RAG design practices. These results demonstrate that in data agent applications with RAG frameworks, increased computational cost and complexity may not directly yield corresponding performance gains in analytical scenarios. Given the necessity for data agents to process diverse unstructured data, future data agents with RAG selection should prioritize efficiency and cost considerations due to the substantial performance disparities observed across different RAG approaches.

Observation 1.
Regarding data agent architectural trade-offs, complex data agent architectures like Multi Agent workflow methods demonstrate superior heterogeneous data analytical capabilities but incur higher costs, whereas simple data agent workflows and RAG systems offer cost-effective solutions with moderately reduced quality. Future data agent design may require cost-aware strategies, selecting semantic processing and Multi Agent workflows for complex analytical tasks while utilizing lightweight frameworks for simple queries, balancing inference quality against computational efficiency.

Summary.

Whether the target system is a complete data agent or a component within a data agent architecture, FDABench maintains its evaluation capabilities through standardized interfaces and metrics. We conduct extensive experiments across different data agent workflow methods and components to demonstrate the trade-offs in the selection and design of data agent architectures.

To evaluate data agent systems’ efficiency, we compare the end-to-end latency of each data agent method. DAgent and data agents with RAG exhibit lower latency growth, while complex multi-agent systems such as AgenticData show steeper efficiency degradation.

Similarly, we compare the end-to-end latency of different workflow patterns across various difficulty levels. Regarding efficiency across workflow patterns, Planning Agents maintain the lowest end-to-end latency across all difficulty levels, demonstrating the efficiency advantages of the Planning Agent workflow. Conversely, Reflection Agents exhibit 2-3 times higher latency than Planning Agents, with the steepest growth as difficulty increases, indicating that iterative reflection mechanisms improve quality at significant computational costs, thereby limiting their feasibility in real-time applications.

Reasoning Token Scaling Analysis.

As mentioned previously, reasoning cost is vital to inference quality. To understand how different workflow patterns utilize reasoning tokens and their impact on data agent performance, we analyze scaling laws across patterns. As shown in Figure

However, additional reasoning tokens do not necessarily guarantee inference quality gains, as Planning Agent and Multi Agent workflows exhibit erratic performance, suggesting reasoning token effectiveness is limited to reasoning-intensive workflows such as reflection. For planning workflows that generate plans in single iterations, improvements are minimal. This indicates opportunities for workflow-specific reasoning token allocation to improve data agent performance rather than uniform resource distribution, representing an optimization strategy for data agent systems.

For data agent design, identifying the most efficient LLM is crucial. We conduct a comprehensive cost-quality trade-off analysis as shown in Figure

Observation 3.

We identify a "reasoning efficiency paradox" in data agent architectures: we discover cognitive load redistribution patterns where complex agent workflows like Reflection Agent exhibit high retry costs (26-29%) but low generation time (10-14%), while Planning Agent show the inverse (retry <3%, generation 32-35%). This reveals that data agent workflows can reorganize computation by moving reasoning phases to earlier decision phases, providing trade-off insights for future data agent designs that can adapt based on task scenarios and difficulty levels, balancing upfront reasoning against iterative refinement.

CONCLUSION

In this work, we propose FDABench, a comprehensive benchmark for evaluating data agent performance across heterogeneous analytical scenarios encompassing analysis, calculation, and reasoning tasks. We introduce an agent-expert collaboration framework for reliable and efficient dataset construction, ensuring benchmark quality and scalability. Experimental evaluation across multiple methodologies yields key insights into data agent capabilities and validates FDABench’s effectiveness as an evaluation framework for advancing data agent research.
