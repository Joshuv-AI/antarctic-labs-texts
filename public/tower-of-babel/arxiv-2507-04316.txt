Retargeting an Abstract Interpreter for a New Language by Partial Evaluation
Jay Lee

Abstract




1.
Problem and Motivation

It is well-known that abstract interpreters
(
Cousot and Cousot 1977
)
can be systematically derived from their concrete counterparts using a “recipe,”
(
Rival and Yi 2020
)
but developing sound static analyzers remains a time-consuming task.
Reducing the effort required and mechanizing the process of developing analyzers continues to be a significant challenge.
Is it possible to automatically retarget an existing abstract interpreter for a new language?

We propose a novel technique to automatically derive abstract interpreters for various languages from an existing abstract interpreter.
By leveraging partial evaluation
(
Futamura 1971
;
Futamura 1999
)
, we specialize an abstract interpreter for a source language.
The specialization is performed using the semantics of target languages written in the source language
(
Reynolds 1972
)
.
Our approach eliminates the need to develop analyzers for new targets from scratch.
We show that our method can effectively retarget an abstract interpreter for one language into a correct analyzer for another language.

2.
Background and Related Work

Partial Evaluation

Partial evaluation specializes an interpreter with respect to a program, effectively compiling it—an observation known as the first
Futamura 1971
;
Futamura 1999
projection.
The result is a specialized interpreter that only accepts the input for the program it was specialized for.
Interpreting a program with different inputs repeatedly incurs the overhead of traversing the program’s AST; Specializing the interpreter eliminates this overhead
(
Jones 1996
)
.

Staged abstract interpreters
(
Wei et al. 2019
)
extend the first Futamura projection to monadic abstract interpreters in the style of Abstracting Definitional Interpreters
(
Darais et al. 2017
)
.
This approach demonstrates performance improvements when analyzing programs by specializing the abstract interpreter for each target.

Our approach differs fundamentally, as we specialize an abstract interpreter not for an analysis target, but for a
definitional interpreter
for a new language.

Meta-level Analysis

JSAVER

(
Park et al. 2022
)
is a meta-level static analyzer that analyzes JavaScript (JS) programs according to the rapidly evolving ECMA-262
(
Guo et al. 2025
)
specification.
It analyzes JS programs by performing meta-level analysis on a definitional interpreter for JS written in a lower-level language called
\text{IR}_{\text{ES}}
.
In this specialized setting, JS and
\text{IR}_{\text{ES}}
share the same base values, and the analysis operates on the AST of the JS interpreter.

Our approach offers a promising extension of this in two ways:

(1)

Our method is language-agnostic, allowing source and target languages to have distinct value domains.

(2)

We address the performance limitations identified in their work through partial evaluation.

Reusing Abstractions

Our motivation aligns with the broader concept of reusing abstractions in static analysis.
Mechanized frameworks such as skeletal semantics
(
Bodin et al. 2019
)
have been proposed to derive abstract interpreters by integrating meta-language abstractions with language-specific ones
(
Jensen et al. 2023
)
.
Another approach by
Keidel and Erdweg 2019
employs arrows meta-language
(
Hughes 2000
)
to compose modular, reusable analysis components.

Mopsa

(
Journault et al. 2020
)
, an open-source static analysis framework, leverages OCaml’s extensible variants to easily define new targets and reuse abstractions compositionally.

Unlike these bottom-up approaches that compose analysis components, our method reuses an existing abstract interpreter in its entirety to derive a new one.

3.1.
An Interpreter for the New Language

The first ingredient is the semantics of the new language
T
: a definitional interpreter
\text{{\color[rgb]{0,0.5,1}{I}}}_{\text{{\color[rgb]{0,0.5,1}{S}}}}^{\text{{\color[rgb]{1,0.23,0.13}{T}}}}
.
This is written in the source language
S
for which we have an abstract interpreter
\smash{\text{{\color[rgb]{0,0,0}{I}}}_{\text{{\color[rgb]{0,0,0}{M}}}}^{\sharp\mskip 1.0mu\text{{\color[rgb]{0,0.5,1}{S}}}}}

For an interpreter to accept a program of another target language, we need to embed programs and values of the target language into the source language.

An encoder

This induces a decoder

{\color[rgb]{0,0.5,1}\big\lfloor\mathbf{{\color[rgb]{1,0.23,0.13}\lceil\mathtt{e}\rceil_{\text{{\color[rgb]{1,0.23,0.13}{\text{{\color[rgb]{1,0.23,0.13}{T}}}}}}}^{\text{{\color[rgb]{0,0.5,1}{\text{{\color[rgb]{0,0.5,1}{S}}}}}}}}}\big\rfloor_{\text{{\color[rgb]{0,0.5,1}{\text{{\color[rgb]{0,0.5,1}{S}}}}}}}^{\text{{\color[rgb]{1,0.23,0.13}{\text{{\color[rgb]{1,0.23,0.13}{T}}}}}}}}={\color[rgb]{1,0.23,0.13}\mathtt{e}}\quad\text{and}\quad{\color[rgb]{0,0.5,1}\big\lfloor\mathbf{{\color[rgb]{1,0.23,0.13}\lceil\mathtt{v}\rceil_{\text{{\color[rgb]{1,0.23,0.13}{\text{{\color[rgb]{1,0.23,0.13}{T}}}}}}}^{\text{{\color[rgb]{0,0.5,1}{\text{{\color[rgb]{0,0.5,1}{S}}}}}}}}}\big\rfloor_{\text{{\color[rgb]{0,0.5,1}{\text{{\color[rgb]{0,0.5,1}{S}}}}}}}^{\text{{\color[rgb]{1,0.23,0.13}{\text{{\color[rgb]{1,0.23,0.13}{T}}}}}}}}={\color[rgb]{1,0.23,0.13}\mathtt{v}}

{\color[rgb]{1,0.23,0.13}\mathtt{e}}\in{\color[rgb]{1,0.23,0.13}\mathtt{\mathbb{E}_{\text{{\color[rgb]{1,0.23,0.13}{T}}}}}}

3.3.
Retargeting using a Partial Evaluator

The final ingredient for automatically deriving a retargeted abstract interpreter is a partial evaluator for

\mathcal{P\mskip-1.3muE}\in{\color[rgb]{0,0,0}\mathsf{\mathbb{E}_{\text{{\color[rgb]{0,0,0}{M}}}}}}\times{\color[rgb]{0,0,0}\mathsf{\mathbb{V}_{\text{{\color[rgb]{0,0,0}{M}}}}}}\mathbin{\to}{\color[rgb]{0,0,0}\mathsf{\mathbb{E}_{\text{{\color[rgb]{0,0,0}{M}}}}}}
.

Definition 6 (Partial Evaluator).

A partial evaluator
\mathcal{P\mskip-1.3muE}\in{\color[rgb]{0,0,0}\mathsf{\mathbb{E}_{\text{{\color[rgb]{0,0,0}{M}}}}}}\times{\color[rgb]{0,0,0}\mathsf{\mathbb{V}_{\text{{\color[rgb]{0,0,0}{M}}}}}}\mathbin{\to}{\color[rgb]{0,0,0}\mathsf{\mathbb{E}_{\text{{\color[rgb]{0,0,0}{M}}}}}}
accepts two inputs,

(1)

an

5.
Future Work

Our recipe for retargeting abstract interpreters for new languages opens several promising research directions.

To evaluate our approach, we are working on an expanded example from
section

4.2
where
S
and
T
include loops.

We plan to investigate the following research questions:

RQ1:

How does a retargeted abstract interpreter compare to manually crafted ones and meta-level analyzers in terms of precision and performance (in terms of time complexity)?

RQ2:

How do semantic gaps between source and target languages (e.g., value domains, higher- vs. first-order) affect the retargeted abstract interpreter?

RQ3:

How does the partial evaluation strategy impact the quality of the retargeted abstract interpreter?

RQ4:

How can this technique be extended to analyze real-world programs with more complex abstractions?
