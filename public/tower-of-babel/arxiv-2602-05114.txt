Abstract
Traditional synchronous STEM assessments face growing challenges including accessibility barriers, security concerns from resource-sharing platforms, and limited comparability across institutions. We present a framework for generating and evaluating large-scale isomorphic physics problem banks using Generative AI to enable asynchronous, multi-attempt assessments. Isomorphic problems test identical concepts through varied surface features and contexts, providing richer variation than conventional parameterized questions while maintaining consistent difficulty. Our generation framework employs prompt chaining and tool use to achieve precise control over structural variations (numeric values, spatial relations) alongside diverse contextual variations. For pre-deployment validation, we evaluate generated items using 17 open-source language models (LMs) (0.6B–32B) and compare against actual student performance (N>200) across three midterm exams. Results show that 73% of deployed banks achieve statistically homogeneous difficulty, and LMs pattern correlate strongly with student performance (Pearson ρ \rho up to 0.594). Additionally, LMs successfully identify problematic variants, such as ambiguous problem texts. Model scale also proves critical for effective validation, where extremely small (<4B) and large (>14B) models exhibit floor and ceiling effects respectively, making mid-sized models optimal for detecting difficulty outliers.

Assessments are fundamental to STEM education, yet conventional single-attempt synchronous exams present growing challenges

Moreover, exam security is increasingly compromised by online resource-sharing platforms and Generative AI (GenAI)

In this paper, we propose that large-scale isomorphic problem banks, created and evaluated using GenAI, can enable asynchronous, multi-attempt assessments. Isomorphic problems test identical concepts and solution structures while varying surface features and contexts
[
14

. Compared to conventional parameterized questions that only vary numerical values, isomorphic problems provide richer variation through diverse contexts while maintaining consistent difficulty
[

. Sufficiently large banks can be made openly available for practice, as the volume and diversity make rote memorization cognitively inefficient, thereby incentivizing transferable knowledge development.

However, creating large isomorphic problem banks presents two significant bottlenecks: (1) manually generating massive numbers of high-quality variations is prohibitively resource-intensive, and (2) validating difficulty homogeneity is challenging when each variant is assigned to only a small fraction of students, providing insufficient response data for traditional statistical methods.

We present a framework leveraging Large Language Models (LLMs) for both scalable generation and pre-deployment validation of isomorphic problem banks in introductory physics. Our generation approach employs prompt chaining and tool use to enable precise control over structural variations while supporting diverse contextual variations. For validation, we evaluate 17 open-source Language Models (LMs) (0.6B–32B parameters) on all generated problems, then compare LM performance patterns against actual student data (N>200) across three midterm exams.

Our analysis confirms that LMs provide reliable difficulty signals for moderate-difficulty banks, achieving LM-student correlations up to
\rho=0.594
. LMs successfully identify problematic variants pre-deployment, including ambiguous problem text and missing contextual information. Model scale critically determines validation utility: small models (
<4B
) exhibit floor effects with insufficient reasoning capacity while large models (
>14B
) show ceiling effects that obscure difficulty gradations.

3
Isomorphic Problem Generation

3.1
AI-assisted Isomorphic Problem Generation

Our approach leverages prompt chaining and tool-use to achieve precise control over structural variations while enabling contextual creativity.
Prompt chaining
decomposes complex tasks into sequential sub-tasks, where outputs from earlier prompts inform subsequent ones, enabling multi-step reasoning beyond single-prompt capabilities. For isomorphic problem generation, it separates construct-relevant variations (e.g., numerical values, spatial arrangements) from construct-irrelevant variations (e.g., context, wording), allowing independent constraints on each.
Tool-use
enables LLMs to invoke external functions beyond text generation. The Python code interpreter
[
2
]
executes scripts in real-time to systematically generate constrained variations, validate solution correctness, and produce diagrams aligned with problem specifications.

3.2
Problem Generation Framework

Our framework distinguishes between two types of variations.
Structural variations
are construct-relevant changes (e.g., numerical values, spatial arrangements, number of objects) that must remain within precise ranges to ensure correctness and appropriate difficulty. They are typically generated through LLM output combined with Python code execution.
Contextual variations
modify surface features (e.g., problem context, scenarios, objects) with fewer restrictions but greater creative flexibility, such as reading level or cultural background. These variations often interact: object weight (structural) must align with object type (contextual). We developed the following seven-step framework for prompt chain design:

1.

Identify a template problem or problem type.

2.

Identify the problem components.

3.

Define structural and contextual variations with their constraints.

4.

Design a prompt chain to generate variations for individual components.

5.

Execute and iteratively refine each prompt based on outcomes.

6.

Combine components into complete problems in the desired format.

7.

Verify correctness of generated problems using LLMs.

3.3
Example Problem Bank Creation: Angled Force with Friction

Below we detail the problem components, variations, and prompt-chain design for example bank
3-3
.

Problem Template:
An object is pushed or pulled by a single angled force across a rough surface at constant velocity. Students calculate the mass, force, or coefficient of kinetic friction.

Problem Components:
Problem body, known/unknown variable, solution.

Variations and Constraints:

•

Contextual:
Realistic scenarios of pushing/pulling objects on rough surfaces with angled forces (e.g., horse pulling sledge on snow, person pushing couch on carpet).

•

Structural:
(1) Force direction and nature (upward/downward, pushing/pulling); (2) Known variable values (friction coefficient, force angle, mass, force magnitude); (3) Unknown variable selection.

•

Constraints:
Force angle 10°–60° from horizontal; mass and force appropriate to context; horizontal force component balances kinetic friction; force magnitude positive; unknown from mass, force, or friction coefficient (excluding angle for consistent complexity).

Prompt Chain Design:
Five sequential prompts generate contextual then structural variations:

Prompt 1:
Generate 10 problem contexts with brief descriptions (e.g., "horse pulling sledge on snow, upward").

Prompt 2:
Generate context-appropriate random variable values satisfying structural constraints. Use Python to calculate required force via
F=\mu mg/(\cos\theta+\mu\sin\theta)
and verify it falls within realistic bounds and is positive.

Prompt 3:
Select different unknown variables for each problem and compose problem bodies. Iteratively refined to specify units and significant figures.

Prompt 4:
Generate step-by-step solutions following specified format guidelines. Developed through multiple iterations.

Prompt 5:
Export problems and solutions in pre-defined data format.

5
Validation of Isomorphic Problem Banks

To evaluate the homogeneity of generated isomorphic problems, we conducted a two-phase validation study: (1) assessing whether LMs detect difficulty variations within isomorphic banks, and (2) examining whether LM performance patterns correlate with actual student data.

5.1
LM-based Isomorphic Problem Validation

We evaluate homogeneity by deploying a suite of open-source language models to solve all isomorphic variants, determining whether specific items exhibit unintended difficulty fluctuations that compromise assessment fairness. This LM-based approach enables pre-deployment quality assurance, where instructors can identify and revise problematic items before deployment to students. This validation is particularly valuable for large-scale banks where piloting every variant with real students would be impractical. We restrict analysis to numerical response and multiple-choice questions, as smaller models showed insufficient capability on multiple-answer and categorization formats.

Evidence of Homogeneity from Student Performance

Variance as a Homogeneity Indicator.

The standard deviation of problem accuracy within an isomorphic bank directly measures difficulty homogeneity. Among the 15 banks with student data, the majority demonstrate low variance, with exemplary cases including Banks
10-1
(std = 0.075),
0-2
(std = 0.076), and
3-5
(std = 0.076). These low variance values demonstrate that the our generation framework successfully maintains construct equivalence while varying surface features.

Assessment Format Differences.
Multiple-choice questions show higher mean student accuracy (0.796 across 6 banks) than numerical questions (0.661 across 14 banks), consistent with research showing selected-response formats facilitate recognition over calculation
[
18
]
. However, MCQ banks exhibit proportionally more heterogeneity (2 of 6 vs. 2 of 10 numerical), suggesting the framework requires refinement in distractor design to maintain consistency across MCQ variations.

Summary.
Student performance validates that our framework generates homogeneous isomorphic banks at scale, with 11 of 15 deployed banks (73%) passing Fisher’s exact test for homogeneity.

A small boat is coasting toward a dock. To stop it gently, an elastic bungee net is stretched across the path. The boat travels a short distance through the water, experiencing drag, before contacting the net and stretching it to a stop. Given: The boat’s mass is 250 kg and its initial velocity is 3.0 m/s. It coasts for 5.0 m before hitting the net. The constant drag force from the water is 150 N. The net stretches by 2.0 m to bring the boat to rest. What is the effective spring constant (
k
) of the bungee net in N/m?

The LLM failed to incorporate the fact that the boat is still traveling in the water when it touches the net, so the stretching distance of the net needs to be added for correct calculation of the work of the boat.

Category 2: Overlooked Verbal Condition (
q20
)

In this item, the LM disregarded a key verbal cue embedded in the problem statement.

A ball is rolling with some initial speed. It enters a 2.0 m long patch of mud, which provides a constant resistive force. Nearing the middle of the mud patch, it hits an elastic band that stretches until the ball stops.

The LLM failed to notice the verbal condition that "Nearing the middle of the mud patch" means that the ball only traveled 1.0 meters before hitting the elastic band, and mistakenly used 2.0 meters. It also failed to understand that the elastic band is also on the mud patch, due to lack of world knowledge. Problems in those two categories seem to be difficult for both LLM and real student.

Category 3: Ambiguous Problem Text (
q2, q5
)

In these items, the problem statement omitted or under-specified a key condition. For example,
q5
states:

For a movie scene, a stunt performer executes a high fall from a platform onto a large, soft crash mat below. As the performer lands, the mat compresses, exerting a constant upward force to safely slow them down. Given: The performer falls from a height of 15 m. The mat compresses by a distance of 1.5 m while providing an upward force of 5000 N.

The problem body failed to specify whether the height was calculated from the ground or from the surface of the mat, leading the LLM to interpret the problem in an unintended way. Notably, the course instructor reported that students raised the same question during the exam, leading to a class-wide clarification.

Summary.
Categories 1 and 2 flag genuine difficulty outliers confirmed by student data, while Category 3 exposes flaws in the problem text itself, which are flaws that may not show in student data if clarified during exam. These findings support the use of LM-simulation as a diagnostic tool for identifying both difficulty heterogeneity and text-level deficiencies in isomorphic problem banks prior to deployment.

7
Conclusion

This study demonstrates the feasibility of using GenAI for scalable creation and rapid evaluation of large isomorphic problem banks. Our prompt-chaining and tool-use framework successfully generates isomorphic problems that maintain precisely controlled structural variations while incorporating diverse contextual elements, achieving quality consistency that single-prompt approaches cannot replicate. While initial prompt-chain development requires effort, its scalability and adaptability to new domains make it exceptionally efficient.

For validation, mid-sized LMs serve as effective pre-deployment screening tools. While their performance shows moderate correlation with student difficulty patterns, they successfully identify outlier items and ambiguous problem text. Model scale proves critical: small models lack sufficient reasoning capacity, while very large models exhibit ceiling effects that obscure difficulty gradations.

Future work includes enhancing diagram generation beyond Python-based visuals, exploring multi-agent frameworks for improved automation, and investigating ability-stratified LM simulations that better mirror diverse student populations. As generation quality improves, real-time problem creation may enable truly personalized assessment at scale.
