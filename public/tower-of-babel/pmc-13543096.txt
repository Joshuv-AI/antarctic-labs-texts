TSD-DDoS: A time-series dataset for TCP flooding attack detection and severity assessment for server health monitoring
Authors: Sajja Ratan Kumar, Valli Kumari Vatsavayi
Published: 2026

ABSTRACT
Distributed Denial-of-Service (DDoS) attacks continue to threaten the availability of networked services by overwhelming server resources with malicious traffic. Among the different attack vectors, TCP flooding attacks remain particularly critical because TCP forms the backbone of reliable Internet services, such as web applications, cloud back-end systems, enterprise platforms, and many blockchain-based applications. Although several benchmark datasets exist for DDoS attack detection, most of them are flow-based and primarily support attack classification, offering a limited scope for analyzing how an ongoing attack impacts server health over time.This data article introduces TSD-DDoS, a time-series dataset specifically developed to fill a crucial gap in the detection of TCP flooding attacks and assessment of their severity in relation to server health. Unlike conventional flow-level datasets, TSD-DDoS organizes network traffic into fixed 5-second intervals. This temporal aggregation enables continuous monitoring of traffic patterns and provides direct insights into the progression and impact of TCP flooding on server performance and availability. By capturing the evolving nature of attacks over time, TSD-DDoS opens new avenues for research into time-aware detection mechanisms and server health monitoring, areas that are underrepresented in existing benchmark datasets.The dataset was constructed using packet capture (PCAP) files from the CICDDoS2019 benchmark dataset. The selected PCAP files were replayed at network speeds of up to 20 Gbps using the tcpreplay tool, whereas traffic capture was performed using Wireshark, a widely recognized packet analysis tool. The collected traffic was divided into successive 5-second intervals, and for each window, aggregated TCP statistics were extracted, specifically the counts of TCP-SYN, TCP-SYN-ACK, TCP-ACK, TCP-RST, and total TCP packets.Each interval was labeled as either normal or attack traffic, with an additional annotation indicating the server health status: Good, Fair, Serious, or Critical. These labels allowed for a clear temporal analysis of both the presence of attacks and the progression of severity.By offering structured, labelled, and time-indexed TCP traffic data, TSD-DDoS enables the development and evaluation of ML-based intrusion detection systems, time-sensitive server health monitoring tools, and adaptive resource management strategies. This is especially valuable in cloud and virtualized environments, where effective mitigation and scaling decisions rely on understanding how attacks evolve over time rather than on isolated flow-level metrics.

Background

Distributed Denial-of-Service (DDoS) attacks aim to disrupt networked services by overwhelming servers and network resources with malicious traffic. Among the different attack vectors, TCP-based flooding attacks remain a persistent threat because of the widespread use of the Transmission Control Protocol in supporting reliable Internet services, such as web applications, cloud back-end systems, databases, and enterprise platforms. As a result, TCP flooding attacks directly impact server availability and service continuity [1,2].

Most publicly available benchmark datasets for DDoS research, including CICDDoS2019 [3,4], describe network behavior using flow-level features extracted from packet capture data. Although flow-based representations are effective for attack detection, they do not directly capture the evolution of traffic intensity and server load over time. This limits their applicability for server health monitoring and time-dependent attack severity assessment, which are important in cloud and virtualized environments, where resources can be dynamically scaled based on demand. The original CICDDoS2019 PCAP files used to generate the proposed dataset are publicly available from the Canadian Institute for Cybersecurity (CIC), University of New Brunswick, and can be obtained from the official dataset repository [4].

The motivation for compiling this dataset was to create a time-series representation of TCP-flooding traffic that reflects server-side load variations over fixed time intervals. The dataset was generated by processing packet capture files from CICDDoS2019 and aggregating TCP packet statistics over consecutive 5-second windows. In addition to the attack detection labels, time-window–level severity annotations were introduced to reflect changes in server health during attack progression.

The TSD-DDoS dataset released in this study was generated as part of the authors’ earlier research efforts on time-series–based DDoS detection and server health assessment. The dataset preparation pipeline was initially introduced in [1], and the labeling framework and server health severity modeling were further developed and validated in [2]. While those studies focused on the methodological development and performance evaluation of machine learning models, the present article provides a structured, publicly accessible release of the curated time-series dataset with comprehensive documentation, schema description, and reusable CSV files to support independent research and benchmarking.

Traffic replay from CICDDoS2019

The TSD-DDoS dataset was generated by replaying the CICDDoS2019 benchmark dataset using Tcpreplay v4.3.3 [5]. The traffic generation system was equipped with an Intel Core i7-9700 K processor (8 cores), 32 GB DDR4 RAM, and an Intel XXV710-DA2 25 GbE network interface card. The replayed traffic was transmitted through the network infrastructure, while a mirror port passively duplicated all packets to an independent monitoring system for traffic capture. This architecture ensured that monitoring activities did not interfere with traffic generation or target server operations, thereby preserving the fidelity of the replayed traffic.

Before traffic replay, the PCAP files were pre-processed using Tcprewrite. Oversized packets were truncated to the configured MTU (1500 bytes), and IP/TCP/UDP checksums were recalculated to produce replay-compatible PCAP files while preserving the original packet sequence and traffic characteristics.

Traffic capture using a dedicated monitoring system

The mirrored network traffic was captured using a dedicated multi-core monitoring system that was physically isolated from the replay source and target server. This separation ensured that packet capture and monitoring activities did not interfere with network operations, thereby preserving the integrity of the collected traffic. Wireshark [6] was employed for packet capture due to its reliability under high-throughput network conditions. All incoming packets were captured and stored in raw PCAP format for subsequent processing and analysis. The monitoring system was equipped with an Intel Core i5-9400 processor (6 cores / 6 threads), 32 GB DDR4 RAM, and an Intel XXV710-DA2 25 GbE network interface card. Packet capture and traffic analysis were performed using Wireshark v3.4.4 and Tcpdump v4.99.0, with PCAP files rotated automatically every five seconds to facilitate efficient storage management and subsequent time-window-based analysis. The traffic generation and monitoring systems were configured using Ubuntu Server 20.04 LTS (64-bit) with the Linux 5.4.0 generic kernel.

Time-window segmentation

The captured traffic stream was segmented into fixed-length, non-overlapping 5-second time windows. Each time window (denoted as T₀, T₁, ..., Tᵢ) represents a discrete observation period during which the TCP activity is aggregated. This segmentation enables a temporal analysis of traffic patterns, facilitating time-series-based detection and monitoring approaches. Each time window represents a snapshot of TCP activity and is stored in memory buffers categorized by TCP control flag types: SYN, SYN-ACK, ACK, and RST as shown in Fig. 2. This segregation facilitates precise feature extraction relevant to the different stages of TCP communication.

Feature extraction using parallel processing

Within each time window, TCP packets are classified into four categories based on their control flags: SYN, SYN-ACK, ACK, and RST. Each category is assigned a dedicated processing thread, with the computation distributed across multiple CPU cores. These threads operate in parallel, extracting the following features for each window:•Number of TCP SYN packets.•Number of TCP SYN-ACK packets.•Number of TCP ACK packets.•Number of TCP RST packets.

No feature normalization or scaling was applied during dataset preparation. The released data retain their original extracted values, with only minor preprocessing performed to remove 28 traffic intervals that contained no TCP traffic and, therefore, did not satisfy the predefined criteria for either normal traffic or any TCP attack severity level.

This parallelized approach ensures the efficient processing of high-volume data and minimizes the latency in feature generation. The extracted features were compiled into a Comma-Separated Values (CSV) format, where each row corresponded to a 5-second time window. Labeling procedure

Each 5-second time window was assigned a label using a rule-based deterministic procedure based on TCP control packet behavior. For every window, feature scores were computed from the aggregated TCP traffic statistics and used to assign the class labels. The labeling process distinguishes between normal and attack traffic and further classifies the attack windows according to their severity level.

The labeling criteria followed the definitions provided in Eqs. (1), (2), (3). Eq. (1) computes the server health indicator from the TCP SYN and TCP ACK packet counts. Based on this indicator, Eq. (2) assigns each window as normal traffic or indicative of a DDoS attack. Windows identified as attack traffic were further categorized into low, moderate, or high severity levels using the threshold-based rules defined in Eq. (3).

This procedure ensured consistent and reproducible labeling of server health conditions for each time window, supporting both attack detection and severity assessment in the derived CSV files [2].

Limitations

The TSD-DDoS dataset was derived from the CICDDoS2019 benchmark, which was designed to represent realistic network traffic patterns and attack behaviors of DDoS. However, the dataset reflects specific traffic generation scenarios and attack configurations defined within that benchmark environment and may not encompass the full variability of all real-world network deployments.

The scope of this dataset is limited to TCP-based flooding attacks, with a primary focus on TCP SYN flooding. Other attack types, such as UDP floods, application-layer attacks, or multi-vector DDoS campaigns, were not included. As a result, the dataset is specifically suited for research on TCP handshake–level attack detection and time-series-based analysis.

The notion of server health in this dataset is inferred from traffic-based indicators computed from both client- and server-side TCP packet statistics, including SYN, SYN-ACK, and ACK behaviors within each time window. These labels reflect operational conditions observable at the network traffic level rather than direct system-level measurements, such as CPU utilization, memory consumption, or application-layer performance metrics.

In addition, traffic statistics were aggregated over fixed 5-second time windows. Different aggregation intervals may influence temporal resolution and detection sensitivity, and researchers should consider this design choice when adapting datasets to alternative experimental settings.
