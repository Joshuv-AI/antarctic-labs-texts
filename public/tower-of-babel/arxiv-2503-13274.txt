Parallel Minimum Cost Flow in Near-Linear Work and Square Root Depth for Dense Instances
Jan van den Brand, Hossein Gholizadeh, Yonggang Jiang, Tijn de Vos

Abstract
For n n -vertex m m -edge graphs with integer polynomially-bounded costs and capacities, we provide a randomized parallel algorithm for the minimum cost flow problem with O ~ ​ ( m + n 1.5 ) \widetilde{O}(m+n^{1.5}) work and O ~ ​ ( n ) \widetilde{O}(\sqrt{n}) depth 1 1 1 We use O ~ ​ ( ⋅ ) \widetilde{O}\left(\cdot\right) to hide polylogarithmic factors. . On moderately dense graphs ( m > n 1.5 m>n^{1.5} ), our algorithm is the first one to achieve both near-linear work and sub-linear depth. Previous algorithms are either achieving almost optimal work but are highly sequential [ 18 ] , or achieving sub-linear depth but use super-linear work [ 49 , 62 ] . Our result also leads to improvements for the special cases of max flow, bipartite maximum matching, shortest paths, and reachability. Notably, the previous algorithms achieving near-linear work for shortest paths and reachability all have depth n o ⁡ ( 1 ) ⋅ n n^{o(1)}\cdot\sqrt{n} [ 33 , 26 ] . Our algorithm consists of a parallel implementation of [ 10 ] . One important building block is a parallel batch-dynamic expander decomposition, which we show how to obtain from the recent parallel expander decomposition of [ 17 ] .

Techniques.

To obtain this result, we use an interior point method based on the sequential algorithm by v.d.Brand et al.
[
10
]
. Their interior point method contains
\widetilde{O}\left(\sqrt{n}\right)
iterations, and they show how to perform each iteration in amortized
\widetilde{O}\left(m/\sqrt{n}+n\right)
time by using sequential data structures maintaining the information needed for each iteration. For an overview, see
Section

3.1

Our contribution is to parallelize the data structures so that they cost
\widetilde{O}\left(m/\sqrt{n}+n\right)
work and
\widetilde{O}\left(1\right)
depth per iteration, which then implies a
\widetilde{O}\left(m+n^{1.5}\right)
work and
\widetilde{O}\left(\sqrt{n}\right)
depth flow algorithm.
In particular, most of the operations used by the data structures involve multiplying matrices and are thus easily parallelizable. The bottleneck is the following data structure involving parallel batch-dynamic expander decomposition: given edge deletions (or insertions) in batches, maintaining an expander decomposition of the graph in work proportional to the batch size and depth
\widetilde{O}\left(1\right)

Previous work shows dynamic expander decomposition can be done in sequential time proportional to the batch size
[
71

[
17
]
shows how to use parallel push-relabel to get a parallel static expander decomposition. Our main contribution is adapting their algorithms to get a parallel batch-dynamic expander decomposition that supports low-depth updates. We provide a detailed overview in
Section

Min-Cost Flow and Max Flow.

In the
minimum cost flow problem

G=(V,E,u,c)

\sum_{(u,v)\in E}e_{(u,v)}=\sum_{(v,u)\in E}e_{(v,u)}

The min-cost flow problem generalizes many important graph problems, among which the max flow problem, maximum bipartite matching, the negative-weight shortest path problem, and reachability.

The Laplacian Paradigm.

For

The algorithm of Madry
[
58

Distributed Min-Cost Flow.

Exact min-cost flow has also been studied in the related CONGEST model
[
29
,
23
]
and the (broadcast) congested clique
[
27
,
28
]
. The CONGEST model and (broadcast) congested clique are message passing models, where a network of processors is modeled as a graph. Problems are solved in synchronous rounds, in which the processors can perform (unlimited) local computation and exchange bounded-size messages with their neighbors. The complexity of a problem is measured by the number of rounds it requires. The difference between the CONGEST model and the congested clique lies in which communication network is used.
[
23
]
achieves
n^{1.5+o(1)}
rounds for the min-cost flow problem in the CONGEST model, and
[
27
]
achieves
\widetilde{O}(\sqrt{n})
rounds in the broadcast congested clique.

Since in both these models each node has infinite computing capacities, the total work is not taken into account and hence the results there are orthogonal to the contributions of this paper.

Open Questions

Our min-cost flow algorithm,
Theorem

1.2
, consists of an interior point method with
\widetilde{O}\left(\sqrt{n}\right)
iterations. Since each iteration takes
\widetilde{O}\left(m/\sqrt{n}+n\right)
work, this leads to
\widetilde{O}\left(m+n\sqrt{n}\right)
work in total. Obtaining an algorithm with a lower iteration count is an obvious open question, but also hard – even in the sequential setting. An interesting open question is whether we can reduce the per-iteration cost to
\widetilde{O}\left(m/\sqrt{n}\right)
. Currently, our algorithm involves updating an
n
-dimensional vector in each iteration. This would have to be circumvented to obtain an algorithm with lower work.

Our batch-dynamic parallel
\phi
-expander decomposition,
Lemma

1.6
, takes
\widetilde{O}\left(1/\phi^{4}\right)
depth and
\widetilde{O}\left(|E^{\prime}|/\phi^{5}\right)
work. This depth matches the static state of the art
[
17
]
, so we expect any improvement for the dynamic depth to also require improving the static depth. The work for our dynamic algorithm is a factor
1/\phi^{3}
worse than its static counterpart (
Lemma

4.4
). It is an interesting open question if this overhead can be reduced.

2
Preliminaries

Parallel Computing.

The parallel model we consider is the widely used
\mathsf{PRAM}
(Parallel RAM) model
. In this model, we consider multiple synchronous processors with shared memory. The access to this memory can differ: exclusive-read-exclusive-write, concurrent-read-exclusive-write, and concurrent-read-concurrent-write. However, up to polylogarithmic factors, these have shown to be equivalent. We measure the efficiency of an algorithm by its
work
, the total number of operation performed, and its
depth
, the longest sequence of dependent operations.

Notation.

We let
[n]\stackrel{{\scriptstyle\mathrm{{\scriptscriptstyle def}}}}{{=}}\{1,\dots,n\}
denote the set of the first
n
natural numbers.
We use the
\widetilde{O}\left(\cdot\right)
notation to hide
\operatorname{\text{{\rm poly}}}(\log\varepsilon^{-1},\log n)
factors, where
n
denotes the number of vertices.
We write
with high probability
or
w.h.p.
to describe a probability of
1-n^{c}
for some constant
c>0
.
Further, we write
\mathbf{1}_{\text{condition}}
for the indicator variable,
which is
1
if the condition is true and
0
otherwise.

2.1
Linear Algebra

Norms

We write
\|\cdot\|_{p}
for the
\ell_{p}
-norm, i.e., for any vector
v\in\mathbb{R}^{d}
,

\|v\|_{p}:=\left(\sum_{i}|v_{i}|^{p}\right)^{1/p}
,
\|v\|_{\infty}=\max_{i}|v_{i}|
,
and
\|v\|_{0}
denotes the number of non-zero entries of
v
.
Further, for a vector
\tau\in\mathbb{R}^{d}

\|v\|_{\tau}:=\left(\sum_{i}\tau_{i}v_{i}^{2}\right)^{1/2}
and the mixed norm

\|v\|_{\tau+\infty}:=\|v\|_{\infty}+C\log(4m/n)\|v\|_{\tau}

for a large constant
C
.
With regards to this norm, for given vectors
h,\tau\in\mathbb{R}^{n}
, we define

\displaystyle h^{\flat(\tau)}:=\argmax_{\|x\|_{\tau+\infty}\leq 1}\langle h,x\rangle.

Matrix and Vector Operations.

Given vectors
u,v\in\mathbb{R}^{d}
for some
d
,
we perform arithmetic operations
\cdot,+,-,/,\sqrt{\cdot}
element-wise.
For example,
(u\cdot v)_{i}=u_{i}\cdot v_{i}
or
(\sqrt{v})_{i}=\sqrt{v_{i}}
.
For the inner product, we write
\langle u,v\rangle
and
u^{\top}v
instead.
For a vector
v\in\mathbb{R}^{d}
and a scalar
\alpha\in\mathbb{R}
, we let
(\alpha v)_{i}=\alpha v_{i}
and
(v+\alpha)_{i}=v_{i}+\alpha
. Additionally, given a vector
v\in\mathbb{R}^{d}
, we define
\mV\in\mathbb{R}^{d\times d}
as the diagonal matrix whose diagonal entries are the elements of

\mV_{i,i}=v_{i}
for all

For a function

\mathbf{\Phi}(x)
is defined analogously.

For a positive definite matrix
\mM\in\mathbb{R}^{n\times n}
, we denote the weighted Euclidean
\mM

\|x\|_{\mM}=\sqrt{x^{\top}\mM x}
. Furthermore, for symmetric matrices
\mA,\mB\in\mathbb{R}^{n\times n}
, we use
\preceq
to denote the Loewner ordering, i.e.,
\mB\preceq\mA
if and only if
\|x\|_{\mA-\mB}\geq 0
for all

.

In this context, we write
\mA\approx_{\varepsilon}\mB
if and only if
\exp(-\varepsilon)\mB\preceq\mA\preceq\exp(\varepsilon)\mB
. Observe that
\exp(\pm\varepsilon)
is close to
(1\pm\varepsilon)
for small
\varepsilon>0
. Similarly, we extend this notation for vectors, letting
u\approx_{\varepsilon}v
if and only if
\exp(-\varepsilon)v\leq u\leq\exp(\varepsilon)v
entrywise. This implies that
u\approx_{\varepsilon}v\approx_{\delta}w
yields
u\approx_{\varepsilon+\delta}w
, and
u\approx_{\varepsilon}v

for any
\alpha\in\mathbb{R}
.

For any matrix
\mA\in\mathbb{R}^{m\times n}
, we denote
a_{i}\in\mathbb{R}^{n}
as the

row of
\mA
, represented as a column vector. Further, let
\operatorname{nnz}(\mA)
denote the number of non-zero entries in
\mA
, and similarly,
\operatorname{nnz}(a_{i})
the number of non-zero entries in
a_{i}
.

Leverage Scores and Lewis-Weights.

For a full-rank matrix
\mA\in\mathbb{R}^{m\times n}
, let
\sigma(\mA)\in\mathbb{R}^{m}
denote its

, defined as
\sigma(\mA)_{i}\stackrel{{\scriptstyle\mathrm{{\scriptscriptstyle def}}}}{{=}}a_{i}^{\top}(\mA^{\top}\mA)^{-1}a_{i}
for each

.

For

\mA\in\mathbb{R}^{m\times n}

to the equation

\mW=\mathbf{Diag}(w)
. As we follow the approach of
[

]

and consider the solution

to

\displaystyle\sigma(\mW^{\frac{1}{2}-\frac{1}{p}}\mA)+\frac{m}{n}\mathbf{1}.

Graph Matrices.

For a directed graph
G=(V,E)
, we define the edge-vertex incidence matrix
\mA\in\{-1,0,1\}^{E\times V}
via
\mA_{e,u}=-1
and
\mA_{e,v}=1

. We typically refer to the number of edges by

\mA_{i,j}

For technical reasons,
[

.

2.2
Graphs

Expander Graphs.

For an
undirected graph

G=(V,E)
, we use
E(A,B)
for two disjoint vertex sets
A,B
to denote the edge set between
A
and
B
. We use
\deg_{G}(A)
to denote
\sum_{v\in A}\deg_{G}(v)
where
\deg_{G}(v)
is the degree of
v
in
G
. We say
G
is a
\phi
-expander
if for every
S\subseteq V
with
S\not=\emptyset,S\not=V
, we have

\frac{|E(S,V\backslash S)|}{\min(\deg_{G}(S),\deg_{G}(V\backslash S))}\geq\phi

In this overview, to simplify notation, when we say a graph is an
expander
, we mean a
\phi
-expander for some
\phi=\frac{1}{\operatorname{polylog}(n)}
.

(Edge-partitioned) expander decomposition.

For an undirected graph
G=(V,E)
,
(edge-partitioned)
\phi
-expander decomposition
is a partition
E=E_{1}\cup E_{2}\cup\ldots\cup E_{z}
such that
E_{i}
is a
\phi
-expander for every
i
(as a subgraph), and every vertex is contained in at most
\widetilde{O}\left(1/\phi\right)
many different
E_{i}
’s (as subgraphs). We mostly care about the case when
\phi=1/\operatorname{polylog}(n)
, so to simplify notation, in this overview, when we say expander decomposition, we mean an edge-partitioned
\phi
-expander decomposition for some
\phi=1/\operatorname{polylog}(n)
.

Note that the expander decomposition operates by ignoring edge directions and is therefore defined on undirected graphs. This simplification is appropriate because the decomposition is primarily used to construct the HeavyHitter data structure, which maintains edge weights and supports weight-based queries, rather than relying on edge directions.

Parallel batch-dynamic expander decomposition.

The problem of parallel batch-dynamic expander decomposition asks for maintaining the expander decomposition of an undirected graph
G=(V,E)
where
G
undergoes edge updates (both insertions and deletions). Moreover, the edge updates are given as batches: in each batch, a set of edges is given to the algorithm to be deleted (or inserted), and the algorithm needs to perform this update and give the expander decomposition after this batch update in small work (ideally proportional to the number of updated edges) and small depth (ideally
\operatorname{polylog}(n)
).

Flows.

A
flow

f
on an undirected graph
G=(V,E)
assigns non-negative real values to simple paths in
G
, meaning the total value of flow over this path. The size of the flow is the total value among all paths. A source (sink) demand vector
{\Delta}
assigns a real value to each vertex. We say a flow routes a source demand
{\Delta}
to a sink demand
{\nabla}
if at least
{\Delta}(v)
flows are starting from
v
for every
v
and at most
{\nabla}(v)
flows are ending at
v
for every
v
.

Note that the notion of flow is defined for undirected graphs in the context of the expander decomposition algorithm, where it is exclusively used.

3.1
A (Parallel) Interior Point Method

In this section we recap interior point methods for solving minimum cost flows. The interior point method presented here stems from previous work on sequential algorithms. We outline the framework and the computational tasks that must be solved in the parallel setting. Readers familiar with this framework may skip ahead to
Section

3.2
, where we outline our contributions, i.e., solving the necessary subroutines in a parallel setting.

Consider the linear programming definition of minimum cost flow: for an
m\times n
incidence matrix
\mA\in\{-1,0,1\}^{m\times n}
, edge-cost vector
c\in\mathbb{R}^{m}
, demand vector
b\in\mathbb{R}^{n}
, and edge capacities
u\in\mathbb{R}^{m}_{\geq 0}
, the following linear program models minimum-cost flows.

\displaystyle\min_{x\in\mathbb{R}^{E}}c^{\top}x~\text{ subject to }~\mA^{\top}x=b,~~0\leq x\leq u

A common approach for solving linear programs is central path methods.
These reduce solving linear programs to solving a sequence of linear systems. The idea is to define a potential function
f_{\mu}
for
\mu\in\mathbb{R}_{>0}
such as

\displaystyle f_{\mu}:

\displaystyle~\{x\mid\mA^{\top}x=b\}\rightarrow\mathbb{R}~~\text{ where }

\displaystyle f_{\mu}(x)=

\displaystyle~c^{\top}x-\mu\cdot\sum_{i=1}^{m}\log x_{i}+\log(u_{i}-x_{i}).

(1)

Observe that the log-terms go to
-\infty
as
x_{i}
approaches 0 or capacity
u_{i}
. Hence to minimize
f_{\mu}(x)
, we need that
x
stays far from the boundaries
0\leq x_{i}\leq u
.
However, as
\mu\rightarrow 0
, the first term
c^{\top}x
starts to dominate, so minimizing
c^{\top}x
becomes more important.
In particular, for
\mu\rightarrow 0
, the minimizer
x
converges towards the optimal solution of the linear program.
The curve of minimizers
c(\mu)=\argmin_{\mA^{\top}x=b}f_{\mu}(x)
, is referred to as “the central path” as it traces a path from the center of the feasible space towards the optimal solution of the linear program.

The idea of central path methods is to start with an initial point
x
that is the minimizer of
f_{\mu}
for large
\mu
, and then follow the central path by repeatedly decreasing
\mu
and moving
x
closer to the new minimizer of
f_{\mu}
via Newton steps.

Once
\mu
is small enough (i.e., some
1/\operatorname{\text{{\rm poly}}}(m,\|u\|_{\infty},\|c\|_{\infty})
) then
x
is close to the optimal solution of the linear program. In particular for min-cost flow, where the optimal solution is guaranteed to be integral, we can simply round all coordinates of
x_{i}
to the nearest integer to obtain the optimal min-cost flow.

Solving min-cost flow in
\sqrt{n}
depth.

In
[
50
]
, it was shown that for a slightly different choice of
f_{\mu}
, the number of iterations is
\widetilde{O}(\sqrt{n})
.
They use a variation of (
1
) where the log-terms are weighted by Lewis-weights
\tau\in\mathbb{R}^{m}_{\geq 0}
.

\displaystyle f_{\mu}(x)=

\displaystyle~c^{\top}x+\mu\cdot\sum_{i=1}^{m}\tau_{i}\cdot\phi(x)_{i}

\displaystyle\phi(x)_{i}=

\displaystyle~-\log(x_{i})-\log(u_{i}-x_{i}),

\displaystyle\phi^{\prime}(x)_{i}=

\displaystyle~-\frac{1}{x_{i}}+\frac{1}{u_{i}-x_{i}},

\displaystyle\phi^{\prime\prime}(x)_{i}=

\displaystyle~\frac{1}{x_{i}^{2}}+\frac{1}{(u_{i}-x_{i})^{2}}

\displaystyle\tau=

\displaystyle~\sigma(\mT^{1/2-1/p}\Phi^{\prime\prime}(x)^{-1/2}\mA)+\frac{n}{m}

(2)

Here the
\tau
that satisfy the recursive equation (
2
) for
p=1-1/(4\log(4m/n))
are referred to as
\ell_{p}
Lewis-weights
[
22
,
50
]
.

To measure the distance of
x
towards the central path, it is useful to introduce a variable
s\in\mathbb{R}^{m}
of form
s=c-\mA y
for
y\in\mathbb{R}^{n}
. The optimality condition for
f_{\mu}(x)
is the existence of
y\in\mathbb{R}^{n}
with
0=\nabla f_{\mu}(x)-\mA y
(using that the gradient
\nabla f_{\mu}
must be orthogonal to the feasible space
\{x\mid\mA^{\top}x=b\}
), and thus
0=c+\mu\tau\phi^{\prime}(x)-\mA y=s+\mu\tau\phi^{\prime}(x)
.
So the distance to the central path can also be measured via the length of the vector
s+\mu\tau\phi^{\prime}(x)
rather than the value of
f_{\mu}(x)
.
In
[
50
]
, it was shown that for certain potential function
\Psi
, measuring the length of
s+\mu\tau\phi^{\prime}(x)
, the following iterative steps allow convergence towards the optimal solution of the linear program in only
\widetilde{O}(\sqrt{n})
iterations.

\displaystyle x\leftarrow

\displaystyle~x+\delta_{x},~~s\leftarrow s+\delta_{s}

(3)

\displaystyle\delta_{x}=

\displaystyle~\Phi^{\prime\prime}(x)^{-1/2}g

\displaystyle~-\mT^{-1}\Phi^{\prime\prime}(x)^{-1}\mA~(\mA^{\top}\mT^{-1}\Phi^{\prime\prime}(x)^{-1}\mA)^{-1}~\mA^{\top}\Phi^{\prime\prime}(x)^{-1/2}g

\displaystyle\delta_{s}=

\displaystyle~\mu\mA~(\mA^{\top}\mT^{-1}\Phi(x)^{-1}\mA)^{-1}~\mA^{\top}\Phi^{\prime\prime}(x)^{-1/2}g

\displaystyle g=

\displaystyle~\nabla\Psi\left(\frac{s+\mu\tau\phi^{\prime}(x)}{\mu\tau\sqrt{\phi^{\prime\prime}(x)}}\right)^{\flat(\tau)}

where we define for vectors
v,\tau\in\mathbb{R}^{m}

\displaystyle v^{\flat(\tau)}:=\argmax_{\|w\|_{\tau+\infty}\leq 1}\langle w,v\rangle.

Essentially,
g
is the largest step we can take in direction of the gradient
\nabla\Psi
while the step is still bounded in the
\|\cdot\|_{\tau+\infty}
norm.

Performing steps as in (
3
), then decreasing
\mu
by some
1-O(1/\sqrt{n}))
factor, and repeating, takes
\widetilde{O}(\sqrt{n})
iterations to solve the linear program. In particular, it implies a
\widetilde{O}(\sqrt{n})
depth algorithm for min-cost flow, but with large work to calculate the steps in each iteration.
Thus the next task is to reduce the total amount of work without substantially increasing the depth.

Robust Interior Point Method.

Observe that even when ignoring the time for calculation, just writing down the vectors
\delta_{x},\delta_{s}
of (
3
) takes
\Theta(m)
work per iteration.
To reduce time per iteration, sequential work
[
20
,
12
,
51
,
34
,
10
,
11
]
has shown that computing the Newton steps approximately suffices. These methods use only approximations of
x
,
s
,
\tau
and the matrix inverse
(\mA\mT^{-1}\Phi^{\prime\prime}(x)^{-1}\mA)^{-1}
. Concretely,
[
10
]
showed the following method converges within
\widetilde{O}(\sqrt{n})
iterations despite crude approximations (here
\varepsilon=O(1/\log m)
):

\displaystyle\text{Pick }{\overline{x}}\approx_{\varepsilon}x,~~{\overline{s}}\approx_{\varepsilon}s,~~{\overline{\tau}}\approx_{\varepsilon}\tau(\Phi^{\prime\prime}(x)^{-1/2}\mA),~~~{\overline{\mu}}\approx_{\varepsilon}\mu

(4)

\displaystyle g=-\gamma\nabla\Psi\left(\frac{{\overline{s}}+{\overline{\mu}}{\overline{\tau}}\phi^{\prime}({\overline{x}})}{{\overline{\mu}}{\overline{\tau}}\sqrt{\phi^{\prime\prime}({\overline{x}})}}\right)^{\flat({\overline{\tau}})}

\displaystyle\mH\approx_{\varepsilon}\mA^{\top}\omT^{-1}\Phi^{\prime\prime}(x)^{-1}\mA~~~~\text{(spectral sparsifier)}

\displaystyle\delta_{c}=\mH^{-1}(\mA^{\top}x-b),~~\delta_{y}=\mH^{-1}\mA^{\top}\mathbf{\Phi}^{\prime\prime}(x)^{-1/2}g

\displaystyle\mR=\text{random $m\times m$ diagonal matrix, }

\displaystyle\mR_{i,i}=\begin{cases}1/p_{i}&\text{with probability }p_{i}\\
0&\text{else}\end{cases}

(5)

\displaystyle~~~\text{where }p_{i}\geq\min\left(1,~\frac{m}{\sqrt{n}}\cdot\frac{((\omT\Phi^{\prime\prime}({\overline{x}}))^{-1}\mA(\delta_{y}+\delta_{c}))_{i}^{2}}{\|(\omT\Phi^{\prime\prime}({\overline{x}}))^{-1}\mA(\delta_{y}+\delta_{c})\|_{2}^{2}}+\frac{1}{\sqrt{n}}+{\overline{\tau}}_{i}\right)

\displaystyle\delta_{x}=\Phi^{\prime\prime}(x)^{-1/2}g-\mR\omT^{-1}\Phi^{\prime\prime}(x)^{-1}\mA(\delta_{y}+\delta_{c}),~~\delta_{s}=\mu\mA\delta_{y}

\displaystyle x\leftarrow x+\delta_{x},~~~s\leftarrow s+\delta_{s},~~~\mu\leftarrow\mu(1-\widetilde{O}(1/\sqrt{n}))

Repeat from (
4
)

Unlike (
3
), here the additional term
\delta_{c}
is needed, because by using the spectral approximation
\mH
, we no longer have
\mA^{\top}\delta_{x}=0
. Thus
\mA^{\top}(x+\delta_{x})\neq b
which is corrected with the
\delta_{c}
step.
To support fast calculation of
\mA^{\top}x-b=\mA x^{(\rm{old})}+\mA^{\top}\delta_{x}
, part of the vector
\delta_{x}
is sparsified via the random matrix
\mR
in (
5
).

It is important for (
4
) that
x,s,\tau
are not actually computed and only
defined
as reference points for the approximation
{\overline{x}},{\overline{s}},{\overline{\tau}}
. Only these approximate values are computed by the algorithm.
This allows for (amortized) sublinear-work per iteration, because one can prove that the vectors
{\overline{x}},{\overline{s}},{\overline{\tau}}
require only a few changed entries per iteration to stay valid approximations. So there is no need to recompute
m
entries of
{\overline{x}},{\overline{s}},{\overline{\tau}}
from scratch in each iteration.
By developing data structures tailored to this task of updating entries of
{\overline{x}},{\overline{s}},{\overline{\tau}}
,
[
10
]
obtained a sequential algorithm that solves min-cost flow in
\widetilde{O}(m+n^{1.5})
time.
However, their result does
not
imply an
\widetilde{O}(\sqrt{n})
-depth algorithm, because their data structures need up to
\Theta(m)
depth in some iterations.
Our main contribution is the development of low-depth equivalents of their data structures.
The major bottlenecks we need to solve are as follows.

Sampling
\mR
.

Computing the sampling probabilities for
\mR
as in (
5
) would require a matrix vector product of form
\mW\mA h
for some vector
h\in\mathbb{R}^{n}
and
m\times m
diagonal matrix
\mW
.
This calculation would require
O(m)
time per iteration.
However, let us assume for simplicity that
\mA
is incidence matrix of an expander graph and
\mW_{i,i}=\mW_{j,j}
for all
i,j
. We will argue that for this case, the sampling task is simple.

Assume without loss of generality that
h\bot\mD\mathbf{1}
where
\mD\in\mathbb{R}^{V\times V}
is a diagonal matrix with
\mD_{v,v}=\deg(v)
(we can add a multiple of the all-1-vector to
h
to satisfy this. This does not change the task as
\mA\mathbf{1}=0
).
Iterate over the vertices, and for each
v\in V
sample each incident edge
\{u,v\}
independently with probability proportional to
h_{v}^{2}>|h_{u}-h_{v}|^{2}/2=(\mA h)_{uv}
.
This sampling can be implemented to take time proportional to the number of returned edges, i.e.,
\sum_{v\in V}1+\deg(v)\cdot h_{v}^{2}\leq\widetilde{O}(n+\|\mA h\|_{2}^{2})
in expectation by Cheeger-inequality (which states

\phi^{2}_{G}/2\leq\lambda_{2}(\mD^{-1/2}\mL\mD^{-1/2})
, and thus bounds

\sum_{v\in V}\deg(v)\cdot h_{v}^{2}=\|\mD^{1/2}h\|_{2}\leq\widetilde{O}((\mD^{1/2}h^{\top})(\mD^{-1/2}\mL\mD^{-1/2})(\mD^{1/2}h))=\widetilde{O}(h^{\top}\mL h)

=\widetilde{O}(\|\mA h\|_{2}^{2})
for
1/\operatorname{polylog}(n)
expander graph and
h\bot\mD\mathbf{1}
, i.e.,
\mD^{-1/2}h
is orthogonal to the
(\lambda_{1}
=
0)
-eigenspace of
\mD^{-1/2}\mL\mD^{-1/2}
).

Thus, if we can decompose the weighted graph represented by
\mW\mA
into a collection of expanders such that each expander has (almost) uniform edge weights, then sampling can be done efficiently without computing
\mW\mA h
in
O(m)
time.
Hence the main problem is to maintain an expander decomposition for the graph where edge weights are
w:=({\overline{\tau}}\phi^{\prime\prime}({\overline{x}}))^{-1}
, and thus change from one iteration to the next.
In previous work, this expander decomposition could not be done in low depth.
We solve this issue by developing a parallel batch-dynamic expander decomposition that is efficient in the parallel setting, see
Section

3.2
.

Maintaining
{\overline{s}},{\overline{\tau}}
.

We also need to compute
{\overline{s}}
and
{\overline{\tau}}
in each iteration. Since they are
m
-dimensional vectors, we cannot afford to recompute them in each iteration.
Instead, we aim to only update a few of their entries per iteration. We outline the idea here for
{\overline{s}}
but it extends to
{\overline{\tau}}
as well.

If we already have some approximation
{\overline{s}}\approx s
, and perform one more iteration
s\leftarrow s+\delta_{s}
, then
{\overline{s}}_{i}
is still a good approximation of
s_{i}
if
(\delta_{s})_{i}\ll s_{i}
was sufficiently small.
In particular, instead of computing the entire
m
-dimensional vector
\delta_{s}
in each iteration, it suffices to only calculate information about entries
(\delta_{s})_{i}
where
(\delta_{s})_{i}\gg\varepsilon\cdot s_{i}
for some threshold
\varepsilon
.

We thus reduce the problem to a data structure task where, given a vector
\delta_{y}\in\mathbb{R}^{n}
, we must detect all indices
i
where
(\omS^{-1}\delta_{s})_{i}=(\omS^{-1}\mA\delta_{y})_{i}>\varepsilon
.
This too can be solved easily when incidence matrix
\omS^{-1}\mA
represents an expander graph. E.g., it could be solved by repeatedly sampling indices proportional to
\omS^{-1}\mA\delta_{y}
, which reduces the task to the previously outlined sampling problem. In summary, for an efficient parallel algorithm for min-cost flow, all that is left is to develop a dynamic expander decomposition of low-depth and work.

3.2
Expander Decomposition

In this section, we provide an overview of our algorithm for parallel batch-dynamic expander decomposition (
Section

4
), i.e., we want to maintain an expander decomposition
4
4

4

As defined in
Section

2
, in this overview, for simplicity, we use
expander decomposition
to refer to decomposing the edge set of a graph into subgraphs where each subgraph is an
expander
, and
expander
refers to a
\phi
-expander for some
\phi=1/\operatorname{polylog}(n)
. It is guaranteed that each vertex appears in at most
\widetilde{O}\left(1\right)
subgraphs.
of an
undirected
graph while this graph undergoes edge insertions and deletions in batches, and for each batch update of edge set
E^{\prime}
, we wish to maintain the expander decomposition in
\widetilde{O}\left(1\right)
depth and amortized
\widetilde{O}\left(|E^{\prime}|\right)
work. See
Lemma

4.1
for a detailed definition.

Reduction to decremental setting.

It is known that in the sequential setting, fully dynamic expander decomposition (edges can be both inserted and deleted) can be reduced to two subroutines, (i) the static setting (compute an expander decomposition of an undirected graph once) and (ii) the decremental setting (edges can only be deleted). The reduction can be found in
[
6
]
. This reduction can be naturally implemented in the
\mathsf{PRAM}
model under batch updates (see
Section

4
, Proof of
Lemma

4.1
for more details). In a nutshell, we partition the edge set
E
into
O(\log n)
edge sets
E_{1},...,E_{O(\log n)}
where
|E_{i}|<2^{i}
, and the algorithm will maintain expander decomposition for every
E_{i}
. When a batch of edges
E^{\prime}
is inserted into the graph, the algorithm will find the smallest
i
such that
2^{i}>|E^{\prime}|+\sum_{j\leq i}|E_{i}|
and use the static algorithm to recompute an expander decomposition of
\cup_{j\leq i}E_{i}\cup E^{\prime}
and make it the new
E_{i}
. Notice that the static algorithm takes work proportional to the number of edges inserted. Thus, we only need to handle the static case and the decremental case.

For the static computation of expander decomposition, a recent paper
[
17
]
gives a near-linear time and polylogarithmic depth algorithm, so it is done. For the rest of this section, we focus on giving the decremental algorithm.

Reduction to expander pruning.

It is known from
[
71
]
that decremental expander decomposition can be reduced to the following expander pruning task.

Input.
An expander graph
H
.

Updates.
An online sequence of batch deletions
E_{1},...,E_{k}
. Denote
H_{i}=H-\cup_{j\leq i}E_{i}
the graph after the
i
-th deletion.

Outputs.
After each update, a set of
pruned
vertices
V_{i}
such that after deleting
\cup_{j\leq i}V_{i}
from
H_{i}
(and all their adjacent edges), the graph becomes an expander again. It is required that the number of adjacent edges in
V_{i}
in
H_{i}
is at most
\widetilde{O}\left(|E_{i}|\right)
, i.e., at most
\widetilde{O}\left(|E_{i}|\right)
edges can be pruned out after the
i
-th update.

We also wish to perform the
i
-th update in
\widetilde{O}\left(|E_{i}|\right)
amortized work and
\widetilde{O}\left(1\right)
depth.

In a nutshell, the reduction works as follows. In the decremental setting, i.e., deleting an edge set
E^{\prime}
from an expander decomposition, we ‘prune out’ sets of vertices (and adjacent edges) from each decomposed expander of total size
\widetilde{O}\left(|E^{\prime}|\right)
so that the remaining subgraphs are still expanders, where the ‘pruned out’ edges are inserted into the graph again which is handled by edge insertion in the previous paragraph (remember that edge insertion can be handled by static computation of expander decomposition).

For the rest of this section, we only need to consider parallel expander pruning, the formal definition is in
Lemma

.

Trimming.

In
[
71
]
, expander pruning is based on modifying a procedure called
trimming
, which can be viewed as a static version of expander pruning: a set of edges
E^{\prime}
is deleted from an expander
H
, and we want to delete another set of edges of size
\widetilde{O}\left(|E^{\prime}|\right)
5
5

5

In the previous paragraph, we mentioned deleting a set of vertices, but that is equivalent to deleting all the adjacent edges and for convenience here we write deleting a set of edges.
so that the remaining subgraph is still an expander. Notice the difference: expander pruning requires many batches of deletions where expander trimming only requires one batch of deletions.

However, the trimming algorithm in
[
71
]
is highly sequential. In a more recent paper
[
17
]
, a parallel trimming algorithm is provided, with
\widetilde{O}\left(m\right)
work and
\widetilde{O}\left(1\right)
depth. The challenge is to use it to get expander pruning, i.e., instead of just deleting one batch of edges from
H
, it needs to support deleting an online sequence of edge sets
E_{1},E_{2},...,E_{k}
, where each deletion only uses
\widetilde{O}\left(|E_{i}|\right)
work and
\widetilde{O}\left(1\right)
depth. This is not so obvious to do as the algorithmic ideas from
[
17
]
are quite different from
[
71
]
.

Algorithm overview of
[
17
]
.

We first give a brief overview of the trimming algorithm in
[
17
]
. Given an expander
H
and an edge set
E^{\prime}
to be deleted from
H
, it outputs an edge set of size
\widetilde{O}\left(|E^{\prime}|\right)
deletions such that after these deletions
H
is an expander again. The algorithm uses
\widetilde{O}\left(m\right)
work and
\widetilde{O}\left(1\right)
depth.

The intuition of the algorithm comes from a structural lemma (see
Lemma

4.9
), for which we first define a
certificate
. We call a flow
f
supported by
H-E^{\prime}
a
certificate
if: (i)
f
routes the source demand
{\Delta}(u)=\widetilde{O}\left(\deg_{E^{\prime}}(u)\right)
6
6

6

Here we use
\deg_{E^{\prime}}(u)
for the edges in
E^{\prime}
that are adjacent to
u
.
, i.e., each edge
(u,v)\in E^{\prime}
contributes roughly
\widetilde{O}\left(1\right)
source demands on both
(u,v)
, (ii)
f
routes the sink demand
{\nabla}(u)=\deg_{H}(u)/\operatorname{polylog}(n)
.
Lemma

4.9
shows that if a certificate exists, then
H-E^{\prime}
is an expander.

A natural idea is to solve a max flow problem to try to find a certificate in case
H-E^{\prime}
is already an expander and we do not need to delete any further. One worry is that we might not be able to solve the max flow problem in
\widetilde{O}\left(m\right)
work and
\widetilde{O}\left(1\right)
depth. However,
[
17
]
shows that we do not need to solve the flow problem perfectly but just need to use the push relabel algorithm up to
\widetilde{O}\left(1\right)
layers. After which, either we route all the demand, which certifies that
H-E^{\prime}
is an expander, so we are done, or we can find a set of edges to be deleted from
H-E^{\prime}
, denoted by
E^{\prime\prime}
, of size
\widetilde{O}\left(|E^{\prime}|\right)
. It is guaranteed that if we substitute
E^{\prime}
by
E^{\prime}\cup E^{\prime\prime}
, we can set up the flow problem again and the source demand size reduces by a constant factor. Thus,
\widetilde{O}\left(1\right)
iterations suffice to finally find a certificate, and the remaining graph is an expander. The flow algorithm is described in detail in
Section

4.2
.

A better analysis of the algorithm.

Although in
[
17
]
, the stated work is
\widetilde{O}\left(m\right)
, we can actually give a better analysis to make the work
\widetilde{O}\left(|E^{\prime}|\right)
. The intuition is that the sink demand for every vertex
u
is
\deg_{H}(u)/\operatorname{polylog}(u)
, so the flow cannot go out of
u
unless roughly
\deg_{H}(u)
amount of flow is absorbed by
u
. In other words, if an edge
(u,v)
is in the support of the flow, then either
u
or
v
is saturated so that we can charge the size of the support by the total source demand size, which is
\widetilde{O}\left(|E^{\prime}|\right)
. The algorithm has work proportional to the support of the flow as it is using push-relabel.

Supporting decremental updates.

Now, we explain how we convert the trimming algorithm into an pruning algorithm supporting many batches of edge deletions. Suppose that after the first batch of edge deletions
E_{1}
arrives, we call the trimming algorithm on
H,E_{1}
and get a set
E^{\prime}_{1}=\widetilde{O}\left(|E_{1}|\right)
such that
H-E_{1}-E^{\prime}_{1}
is an expander. A natural idea is to substitute
H
by
H_{2}:=H-E_{1}-E^{\prime}_{1}
and run the algorithm again on
H_{2}
with the next batch of deletion
E_{2}
. However, there is a technical issue that makes this simple idea wrong: the trimming algorithm has an inherent property that the expansion of
H_{2}
decreases by a constant factor compared to
H
, which means after
k
updates, the expansion becomes exponentially smaller in terms of
k
. To avoid this, instead of replacing
H
by
H_{2}
and feeding it into the trimming algorithm, we will try to run the trimming algorithm again on
H,E_{1}\cup E_{2}
. This results in high work since the work for the second update is
\widetilde{O}\left(|E_{1}\cup E_{2}|\right)
instead of
\widetilde{O}\left(|E_{2}|\right)
. We resolve this in a similar way to
[
71
]
, i.e., by reusing the flow information from the first trimming algorithm on
H,E_{1}
so that we only need to route the flow contributed by
E_{2}
. Let us call the flow instance routing the contribution of
E_{i}
by
f_{i}
. The certificate after deleting
E_{1},...,E_{i}
from
H
will be
f_{1}+...+f_{i}
.

However, this idea has an additional issue in the parallel setting. The parallel trimming algorithm by
[
17
]
has good parallel work and depth mainly because each time the sink demand for flow
f_{i}
is relatively large, i.e., at least
\deg(u)/\operatorname{polylog}(n)
. That means that the flow cannot go out from
u
unless it gets absorbed by an amount proportional to the degree of
u
. Also, remember that we compute each
f_{i}
using the idea from
[
17
]
, which means
f_{i}
must have sink demand at least
\deg(u)/\operatorname{polylog}(n)
for every
i
.
Thus, the total flow summing over all
f_{i}
is polynomially larger than
\deg(u)
if the number of updates are polynomial. This
violates
the definition of a certificate flow.
In other words: we can only support the batch updates up to
\operatorname{polylog}(n)
times.

In order to support an arbitrary number of batch updates, we prove a lemma of batch number boosting (see
Lemma

4.5
for more details). Similar ideas appear in
[
61
,
35
]
. The boosting is simple: every time the algorithm undergoes
2^{i}
batch updates, it rolls back to the beginning and combines all the
2^{i}
updates into a single batch update, and does the
2^{i}
to
2^{i+1}
updates using similar rolling back techniques. Finally, we can support polynomially many decremental batch updates.

Vertex Decomposition.

Although we presented our algorithm for maintaining an (edge-partitioned) expander decomposition, the same algorithm should work for the more prevalent vertex-partitioned expander decomposition, where the vertex set is partitioned into
V_{1},...,V_{z}
such that each induced subgraph is an expander, and there are at most
\widetilde{O}\left(1/\phi\right)\cdot m
inter-cluster edges. This is because expander pruning will give a pruned
vertex
set instead of and
edge
set, and all the arguments above should work. Note that since our result specifically concerns edge-partitioned decompositions, the vertex-partitioned variant is not directly relevant to our main result.

4.1

Lemma

)

Later we will show that we can only get expander pruning for
\widetilde{O}\left(1\right)
batch updates at most, instead of supporting an arbitrary number of updates. Luckily, this is not a problem according to the following batch number boosting lemma. Similar ideas were used in
[
61
,
35
]
.

First we define some notation. A data structure (decremental, incremental, or fully dynamic) requires preprocessing, then can undergo a bunch of
batch updates
where each update is guaranteed to have some complexity, in our case work and depth. The data structure has
batch number

b
if it can only support
b
batch updates, after which the data structure cannot support any updates.

Lemma 4.5

(Batch number boosting)
.

Let
G
be a graph undergoing batch updates (decremental, incremental, or fully dynamic).
Assume there is a data structure
\mathfrak{D}
maintaining some graph properties of
G
with batch number
b
, preprocessing time
t_{\mathrm{pre}}
, amortized update work
w_{\mathrm{amor}}
, update depth
d
.
Here
b,t_{\mathrm{pre}},w_{\mathrm{amor}}
and
d
are functions that map the upper bounds of some graph measures throughout the update, e.g. maximum number of edges, to non-negative numbers.

Then, for an arbitrary function
\overline{b}
, there is a data structure (decremental, incremental, or fully dynamic, correspondingly) undergoing batch updates with batch number
\overline{b}
, preprocessing time
t_{\mathrm{pre}}
, amortized update work
O(b\cdot(\overline{b})^{1/b}\cdot w_{\mathrm{amor}})
and update depth
O(d\cdot b+\log_{b}\overline{b})
, maintaining the same graph properties of
G
as
\mathfrak{D}
.

Proof.

The case for
\overline{b}\leq b
is trivial. Let us consider the instance where
\overline{b}>b
. The data structure first initializes the data structure
\mathfrak{D}
. When we update the data structure
\mathfrak{D}
we will memorize our updates so that in the future we can make an operation called
rollback
, which will restore the data structure to a previous state where the updates have not been made.

Define
D_{k}=(\overline{b})^{k/b}
. When the
i
-th batch update arrives, the data structure checks for every integer
k>0
if there exist integers
a
and
b
such that
i=a\cdot D_{k}+b\cdot D_{k-1}
with
b<D_{1}=D_{k}/D_{k-1}
or not. It finds the largest such
k>0
(it must exist since when
k=1
,
D_{k-1}=1
and
a,b
are simply the module of
D_{1}
) and rollback the data structure to the point where the
a\cdot D_{k}
-th update has just been made. Then it updates the batch combining all the updates from
a\cdot D_{k}+1
to
i
.

Correctness.

Notice that after the arriving of the
i
-th update, the data structure maintains the correct
\mathfrak{D}
which undergoes the updates combined by all the
1
to
i
-th updates, by induction on the correctness. Moreover,
\mathfrak{D}
has always been updated by at most
b
batches: according to the definition of the data structure, if a batch update is generated by rolling back to the
a\cdot D_{k}
-th update, then the previous batch update must be rolling back to the
a^{\prime}\cdot D_{k+1}
for some
a^{\prime}
, which means the batch size goes up by
D_{1}
at each time, so that the maximum batch number is at most
\log_{D_{1}}(\overline{b})=b
.

Complexity.

Finding the
k
and finding
a,b
costs
O(\log_{b}\overline{b})
work and
O(\log_{b}\overline{b})
depth. Then for the largest
k
, rolling back the data structure costs depth
O(d\cdot b)
since as we previously proved, the batch number for the data structure is at most
b
and rolling back one batch costs
d
depth as it requires to reverse all the operations made by
\mathfrak{D}
. Now we show the amortized work. Notice that the rolling back procedure can be charged to the update procedure, so we only need to analyze the updates. We only need to prove that for every
i
, the
i
-th update batch gets involved in at most
O(b\cdot(\overline{b})^{1/b})
many batch updates for
\mathfrak{D}
. For that, we only need to prove that for every
k
(at most
b
different
k
’s), it is involved in at most
O(\overline{b})^{1/b})
updates. Now fix
k
and let
a
be the largest integer such that
a\cdot D_{k}<i
. The
i
-th update can only be involved in the batch update from
a\cdot D_{k}+1
to
a\cdot D_{k}+b\cdot D_{k-1}
for
b<D_{1}=(\overline{b})^{1/b}
, so we are done.
∎

Lemma 4.8
.

For every

\boldsymbol{\mathit{f}}_{i}
supported by the graph

\frac{2}{\phi}(\mathbf{deg}_{G}(v)-\mathbf{deg}_{G_{i}[V_{i}]}(v))

We prove it by induction on

\boldsymbol{\mathit{f}}_{i}

, which is the same as
G_{i}[V_{i}]
. After this restriction, for every edge
(u,v)
in

that goes from

to

,

will receive at most

many redundant flows since flow of
\boldsymbol{\mathit{f}}_{i-1}
is cut out here. Moreover, for every edge
(u,v)
in

that

,

gets an extra source capacity from

of

compared to
\boldsymbol{\mathit{f}}_{i-1}
if either
(u,v)\in E_{i}
(newly deleted edge) or

and
(u,v)\in E(G_{i-1})

\boldsymbol{\mathit{f}}
returned by

The following lemma shows that the flow in

-nearly expander
if for all

Lemma 4.9
.

Given a graph
G=(V,E)
and a subgraph
G^{\prime}\subseteq G
such that
G^{\prime}
is a
\phi
-nearly expander and there exists a flow
f
supported on the graph
G^{\prime}
that routes source
\Delta(v)\stackrel{{\scriptstyle\mathrm{{\scriptscriptstyle def}}}}{{=}}2/\phi\cdot(\mathbf{deg}_{G}(v)-\mathbf{deg}_{G^{\prime}}(v))
to sinks
\nabla(v)\stackrel{{\scriptstyle\mathrm{{\scriptscriptstyle def}}}}{{=}}\mathbf{deg}_{G}(v)
for

with uniform edge capacity

. Then

is a
\frac{\phi}{6\log n}
-expander.

Proof.

If

is not a
\frac{\phi}{6\log n}
-expander, then there exists

, such that more than

fraction of the edges in

are not in

is a

is at most
\mathbf{deg}_{G}(A^{\prime})
, so at least

∎

By combining

-expander.

Since we only give implicit output, the initialization of

Claim 1

The total number of edges adjacent to a vertex without remaining sink capacity is at most
\widetilde{O}\left(\|{\Delta}\|_{0}/\gamma\right)

A vertex can have excess only if it has no remaining sink capacity, which means it absorbs at least
\widetilde{\Omega}\left(\gamma\cdot\mathbf{deg}(v)\right)

\|{\Delta}\|_{0}
flows in total. Thus, if we sum up
\gamma\cdot\mathbf{deg}(v)
for all

with excess, it is at most
\|{\Delta}\|_{0}

\widetilde{O}\left(\|{\Delta}\|_{0}/\gamma\right)
.

According to
PushThenRelabel
, a vertex has a non-zero level only if it has no sink capacity. So the claim follows.
∎

According to

\widetilde{O}\left(1\right)

\widetilde{O}\left(\|{\Delta}\|_{0}/\gamma\right)

We can skip initializing

Now we look at the while-loop: the condition is checked in
\widetilde{O}\left(\|{\Delta}\|_{0}/\gamma\right)

\widetilde{O}\left(1\right)
depth according to
Claim

1
. Inside

, the push operations can be performed in

work and
\widetilde{O}\left(1\right)

\widetilde{O}\left(\|{\Delta}\|_{0}/\gamma\right)
work and

1

Now we argue the number of times that the while-loop can be ran as the following claim. It is implicitly implied by the proof of Claim 4.1 in
[
17

Claim 2
.

In

Proof.

Loot at

, after the push operation, we claim that all the nodes with excess must have their level increase unless it is at level
h+1
. This is because such a node cannot have remaining sink capacity as otherwise it cannot have excess; also it cannot have non-saturated edges going to level
l(v)-1
, as otherwise the excess would be pushed through that edge in the push operations (during the push operations, if a node has all edges going to level

Now we count the total number of flows that can be raised. A vertex

\eta
and
\mathbf{deg}_{G}(v)
edges going into this node, and it can increase its level at most

Proof of
Theorem

A.3
.

The main idea behind the implementation of this data structure is similar to the

. Specifically, we distribute the weights

into

Initialize
.

Begin by storing
\tau
internally within the data structure. Then, for each
i\in[1,m]
in parallel, compute the index

such that

. Next, initialize

, where

\displaystyle B_{j}=\{i\mid\tau_{i}\in[2^{j},2^{j+1})\}.

Additionally, compute and store

internally within the data structure.

For managing the buckets, we use the data structure from
Lemma

A.2
. Thus, the initialization procedure requires
\widetilde{O}\left(m\right)
work and
\widetilde{O}\left(1\right)
depth.

Scale
.

For each
i\in I
in parallel, determine its new bucket by computing

such that
a_{i}\in[2^{j_{i}},2^{j_{i}+1})
. Then, update the bucket assignments by removing all

from its previous bucket

in parallel and adding it to its new bucket, also in parallel, while updating

Since we use the list data structure from

\widetilde{O}\left(1\right)

Additionally, we update the value of

\displaystyle\|\tau\|_{1}\leftarrow\|\tau\|_{1}+\sum_{i\in I}(a_{i}-\tau_{i}).

This update requires
\widetilde{O}\left(|I|\right)

\widetilde{O}\left(1\right)

Sample
.

For each

, we sample

\displaystyle p_{i}=K\cdot\frac{n2^{j+1}}{\|\tau\|_{1}}>K\cdot\frac{n\tau_{i}}{\|\tau\|_{1}},

assuming

To implement this (similar to

\displaystyle\mathbb{E}[X]

\displaystyle=\sum_{B_{j}}\sum_{i\in B_{j}}K\cdot\frac{n2^{j+1}}{\|\tau\|_{1}}

\displaystyle\leq\sum_{B_{j}}\sum_{i\in B_{j}}K\cdot\frac{n2\tau_{i}}{\|\tau\|_{1}}

\displaystyle=\sum_{i\in[1,m]}2K\cdot\frac{n\tau_{i}}{\|\tau\|_{1}}

Thus, the work complexity of

Probability
.

For this operation, we essentially need to compute

for each

Since this computation is independent for each

Appendix D
Parallel Primal and Gradient Maintenance

In their IPM for solving LPs with two-sided constraints, as well as some special cases, such as the Minimum-Cost Flow Problem,

In order to compute and maintain (an approximation of) this gradient, as well as maintaining an approximation of the primal solution

In this section, we discuss how this data structure can be implemented in the parallel setting. The main result of this section is

D.1

Before discussing the implementation of this data structure in the parallel setting, we first state a tool used for gradient reduction.

\widetilde{O}\left(1\right)

(Line

\widetilde{O}\left(|I|\right)

.

Sample
.

First, we bound the number of entries of
I
: In Line
14
, we set
I=I_{u}\cup I_{v}\cup I_{w}
, thus

\displaystyle|I|\leq|I_{u}|+|I_{v}|+|I_{w}|.

As
I_{u}
and
I_{v}
are the results of the

operation of
\tau
-Sampler
and

A.3
and

\displaystyle|I_{u}|\leq\widetilde{O}\left(C_{3}n\right)\quad\text{and}\quad|I_{v}|\leq\widetilde{O}\left(C_{1}m/\sqrt{n}\right).

Furthermore, in Line
14

, thus, w.h.p.,
|I_{w}|\leq\widetilde{O}\left(C_{2}m/\sqrt{n}\right)

So, we have that, w.h.p.,

\displaystyle\widetilde{O}\left(C_{3}n\right)+\widetilde{O}\left(C_{1}m/\sqrt{n}\right)+\widetilde{O}\left(C_{2}m/\sqrt{n}\right)=\widetilde{O}\left((C_{1}+C_{2})m/\sqrt{n}+C_{3}n\right).

Note that, since in Line
14
, we set the values of
\mR_{i,i}
for

, w.h.p., the number of non-zero entries of

\widetilde{O}\left((C_{1}+C_{2})m/\sqrt{n}+C_{3}n\right)

For the implementation of sets

, as well as

A.2

A.3

14

\widetilde{O}\left(C_{3}n+\log W\right)

\widetilde{O}\left(1\right)

In Line
14

A.3
-

\widetilde{O}\left(C_{2}m/\sqrt{n}\right)

Consequently, w.h.p., we have in total

Overall, w.h.p., the work complexity of
