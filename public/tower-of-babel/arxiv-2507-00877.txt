Verifiable Natural Language to Linear Temporal Logic Translation: A Benchmark Dataset and Evaluation Suite
William English will.english@ufl.edu, Chase Walker chasewalker@ufl.edu, Dominic Simon dominic.simon@ufl.edu, Sumit Jha sjha@fiu.edu, Rickard Ewetz rewetz@ufl.edu

Abstract
Empirical evaluation of state-of-the-art natural-language (NL) to temporal-logic (TL) translation systems reveals near-perfect performance on existing benchmarks. However, current studies measure only the accuracy of the translation of NL logic into formal TL, ignoring a system’s capacity to ground atomic propositions into new scenarios or environments. This is a critical feature, necessary for the verification of resulting formulas in a concrete state space. Consequently, most NL-to-TL translation frameworks propose their own bespoke dataset in which the correct grounding is known a-priori, inflating performance metrics and neglecting the need for extensible, domain - general systems. In this paper, we introduce Verifiable Linear Temporal Logic Benchmark (VLTL-Bench) , a unifying benchmark that measures verification and verifiability of automated NL-to-LTL translation. The dataset consists of three unique state spaces and thousands of diverse natural language specifications and corresponding formal specifications in temporal logic. Moreover, the benchmark contains sample traces to validate the temporal logic expressions. While the benchmark directly supports end-to-end evaluation, we observe that many frameworks decompose the process into i) lifting, ii) grounding, iii) translation, and iv) verification. The benchmark provides ground truths after each of these steps to enable researches to improve and evaluate different substeps of the overall problem. Using the benchmark, we evaluate several state - of - the - art NL-to-TL translation models and frameworks, including nl2spec, NL2TL, NL2LTL, sequence-to-sequence translation, and various prompting techniques. Our evaluation reveals that existing work is capable of reliably performing lifting and translation with high accuracy but struggle with grounding the translation in a state space, which stems from the lack of datasets to drive the research. Moreover, we provide traces that can be used for integrating verification into translation process, unlocking further directions for future research. To encourage methodologically sound advances in verifiable NL-to-LTL translation approaches, we release VLTL-Bench here: https://www.kaggle.com/datasets/dubascudes/vltl-bench .

Current approaches for automated NL-to-TL translation are characterized by the use of multiple components, each with a distinct purpose in the end-to-end translation process. As noted earlier, we categorize these components into either lifting, grounding, or translation. Many frameworks employ different combinations of these components, such as nl2spec
[
7
]
, which presupposes a
pre-lifted and pre-grounded
natural language specification as input. For example, an input "Globally, grant 0 and grant 1 do not hold at the same time until it is allowed," is assumed to be accompanied by a dictionary that maps the natural language sub-string "grant 1" to a known atomic proposition
g_{1}
. Therefore, this framework lacks the components for lifting and grounding, but includes a human auditing feature, which we omit from our analysis of automated translation frameworks. Meanwhile, another SOTA approach NL2TL
[
6
]
is divided into two processes. First, an LLM - in this case GPT3.5
[
1
]
- is prompted to extract the atomic propositions (APs) from the NL input, creating “lifted NL" (NL without complex propositions). This new, less complex representation is then translated by a trained sequence-to-sequence model, such as T5
[
22
]
. For example, an NL specification for a system: “You have an apple until you eat it.", will be converted into the lifted NL: “
prop1
until
prop2
.". Here,
prop1
is “You have an apple" and
prop2
is “you eat it". This lifted NL is then translated to the lifted TL: “
prop1

\cup

prop2
." and the lifted propositions would be replaced.

These two frameworks are representative of the general research effort to produce better NL-to-TL translation frameworks, and yet no current frameworks have a holistic and faithful approach to translation. Therefore, we note the need for a benchmark that includes the data required to evaluate all components of the end-to-end translation pipeline - lifting, grounding, translation, and verification - in order to provide a complete picture of a framework’s true performance. We compare existing datasets and benchmarks on the basis of the linguistic and logical complexity of the end-to-end input and output, as well as the inclusion of features required to measure the performance of each individual component in Table
1
.

We address these gaps with the
Verifiable Linear Temporal Logic Benchmark (VLTL-Bench)
, a benchmark that grounds linear temporal logic (LTL) in a concrete world state space while broadening linguistic and logical coverage. VLTL-Bench introduces three new datasets which contain both raw and lifted versions of NL specifications, an AP-to-Condition dictionary, lifted and grounded LTL, and examples of satisfying and unsatisfying traces. The provision of each of these elements enables us to evaluate the four abstract components present in emerging NL-to-TL translation frameworks. Furthermore, the inclusion of example traces allows us to further evaluate the semantic consistency of translation and grounding attempts, resulting in a new
verification accuracy
performance metric, which measures whether an output translation holds on an a given trace. This feature permits consistency checking against real formal traces- a heretofore omitted feature of NL-to-TL translation corpora which will improve future explorations of NL-to-TL translation. In plausible real-world applications, a system may be given some example traces with which to grade its own translation attempts. This provides the opportunity to improve translation attempts
without
human auditing. We believe that the ability to measure the performance of individual components of a given framework will clarify the weaknesses of existing frameworks and guide future work. We outline our dataset synthesis and translation evaluation pipelines in Figure
1
.

In summary, our contributions are: (i) a single, extensible benchmark and data synthesis pipeline for the evaluation of all current NL-to-TL translation components; (ii) a first-of-its-kind evaluation of the verification potential of existing frameworks, using our example satisfying and unsatisfying traces; and (iii) an empirical study that exposes both new failure modes in current translation methods and the severe accuracy decline when grounding is required. By providing a rigorous and extensible yardstick, VLTL-Bench can catalyze methodologically sound advances in NL-to-TL translation and, more broadly, in grounding large language models for formal reasoning tasks.

Background and Related Work

2.1
Preliminaries

In this section, we formally define a number of key terms necessary to describe and evaluate natural language-temporal logic translation systems. In particular, we have found that several terms are often conflated or co-defined in prior work, often leading to confusion regarding framework abilities. In order to provide a cogent description of these systems, as well as a robust evaluation, we define these terms as follows:

Scenario:
Referred to in existing work as the “World", “Environment", or “Space". A set
S
of conditions appearing on a trace.

Condition:
In model checking, a condition is a uniquely-named Boolean variable
c_{i}
.

Atomic Proposition:

\pi\in\Phi
, where
\Phi
is the set of propositional variables in an LTL expression. During LTL verification,
\pi_{i}
is assigned a value by matching with a condition
c\in S
.

Lifting:

\lambda
: NL
\rightarrow\Phi
, extracting substrings corresponding to APs from natural language.

Grounding:

g(\pi)=c
, replacing an abstract AP in an LTL expression with a condition
c\in S
.

Translation:

\tau
: NL
\rightarrow
LTL, converting a natural language string into a formal LTL expression.

Verification:
Given a trace
\sigma
or Kripke structure
K
, check whether a grounded LTL expression
g(\varphi)
holds. For trace-based verification, construct a minimally satisfactory
K
from
\sigma
.

2.2
Linear Temporal Logic

The syntax of LTL is given by the following grammar:

\displaystyle\varphi::={}

\displaystyle\pi\;\mid\;\neg\varphi\;\mid\;\varphi_{1}\wedge\varphi_{2}\;\mid\;\varphi_{1}\vee\varphi_{2}\;\mid\;\varphi_{1}\Rightarrow\varphi_{2}

\displaystyle\;\mid\;\bigcirc\varphi\;\mid\;\diamondsuit\varphi\;\mid\;\Box\varphi\;\mid\;\varphi_{1}\,\cup\,\varphi_{2}

We further discuss model checking with linear temporal logic in Appendix
A.1
and Appendix
A.2
.

2.3
Benchmark Datasets

The
Cleanup World (CW)
dataset
MacGlashan et al. 2015
pairs NL commands with reward functions in an OO
-
MDP. While this work introduces a supervised grounding approach, the dataset used for training and evaluation is limited in terms of logical and linguistic complexity. This is due to the minimal set of APs used to construct the examples, and lack of diversity in both AP representation and sentence structure. Similarly,
GLTL

Gopalan et al. 2018
gathers English sentences mapped to
Geometric LTL
formulas in robot
-
navigation scenarios, emphasizing stochastic
-
window operators but remaining modest in scale. The contents are remarkably similar to Cleanup World in both quality and metrics, with both datasets having the same number of unique temporal logic phrases and unique APs. The use of LLMs to enhance sentence diversity had not yet been adopted in the field at this time, and no alternate AP representations are introduced in the natural language. Therefore, the evaluation abilities of the GLTL dataset are limited in largely the same manner as Cleanup World. The
Navi.
corpus, introduced by
Wang et al. 2021
couples NL commands with LTL formulas and execution traces in a grid world. Its 226 unique APs make it a strong test of translation and lexical robustness, though this improvement comes at the cost of grounding- the Navi corpus does not specify formal APs, providing instead POS-tagged natural language representations, as shown below. Most recently, the
ConformalNL2LTL
dataset, introduced by
Wang et al. 2025
, frames translation as open
-
vocabulary QA wrapped in conformal prediction (CP) to provide statistical guarantees. If the cumulative CP
p
-
value falls below a user
-
specified threshold, the system escalates to a human; otherwise, it commits the subformula. The authors release a 1000
-
example corpus of grounded robot tasks partitioned by difficulty. We provide examples and a quantitative evaluation of existing datasets in Appendix
A.3
.

3
Verifiable Linear Temporal Logic Benchmark

Our framework is built around two core stages:
Grounded Scenario Configuration
, which defines the domain in which every proposition lives, and
Data Synthesis
, which instantiates our library of expert templates with scenario-specific atoms and then prunes any invalid NL. In the first stage, we provide the canonical formalization of the agent and the world it operates in. In the second stage, we apply the canonical APs obtained from the first to our expert-defined NL, TL, and trace templates.

3.1
Grounded Scenario Configuration

Each dataset is parameterized by a
scenario
—a small, declarative world model that provides:

•

Targets

\mathcal{L}
: e.g. {
location
,
item
} or {
street
,
light
}.

•

Actions

\mathcal{A}_{\mathrm{args}}
: verbs the agent may perform (e.g.
idle
,
deliver(item, location)
,
search(item)
).

•

Target types

t\in\mathcal{T}
: each with its own action set
\mathcal{A}_{t}
and argument signatures (e.g.
deliver(item,location)
,
avoid(threat)
).

By swapping the scenario description of
\mathcal{L}
,
\mathcal{A}_{\mathrm{args}}
, and
\{\mathcal{A}_{t}\}
, the same logical and linguistic templates can be deployed in multiple domains without changing the core synthesis code.

3.2
Data Synthesis

To produce our datasets, we started with the 36 expert-crafted lifted NL-LTL pairs introduced by
Cosler et al. 2023
in the nl2spec benchmark and we crafted 7 of our own. We then crafted 43 pairs of corresponding example traces to each NL-LTL pair. Following this, we transform these lifted examples into a set of templates that can be used for diverse NL-LTL synthesis, introducing three substantial increases in complexity.

1.

We generate more diverse words for objects, actions, and items as a potential scenario to enhance each example.

2.

Each LTL skeleton (e.g.
globally(prop_1 implies prop_2)
) is coupled to action and target references from these scenarios.

3.

Each example is given a corresponding pair of
trace templates
that yield a minimal satisfying (
\sigma_{good}\models\varphi_{G}
) and violating (
\,\sigma_{bad}\not\models\varphi_{G}
) trace.

To generate one example:

1.

Atom sampling.
Draw
k
unique atomic propositions by randomly selecting actions and arguments from the scenario’s
\mathcal{A}_{\mathrm{ego}}\cup\mathcal{A}_{t}
and
\mathcal{L}
.

2.

Template instantiation.
Uniformly choose a lifted template whose arity
\leq k
. Fill its LTL skeleton with the
k
canonical atoms to obtain the
grounded
formula
\varphi_{g}
, and replace each atom by
\mathsf{prop}_{i}
to obtain the
lifted
formula
\varphi_{L}
.

3.

NL realization.
Fill the semantic pattern with each atom’s surface-form (including articles/prepositions), apply morphological fixes (gerunds, capitalization), and record token-level spans. Emit both the free-form sentence and its
grounded_sentence
with explicit
\mathsf{prop}_{i}
placeholders.

4.

Trace filling.
Apply the template’s trace builder to the list
[\mathsf{prop}_{1},\dots,\mathsf{prop}_{k}]
, yielding one
good
trace (satisfies
\varphi_{G}
) and one
bad
trace (violates
\varphi_{G}
).

5.

Pruning.
Submit each candidate NL sentence to GPT-4o for a lightweight check of the natural language components, removing any entries that the model flags as nonsensical or incorrect from the benchmark set.

3.3
Metrics

Each dataset entry includes three paired artifacts:

\bigl\{\,\underbrace{\mathrm{sentence},\,\mathrm{lifted\ sentence\}}}_{\text{NL (grounded \& lifted)}},\;\underbrace{\varphi_{G},\,\varphi_{L}}_{\text{LTL (grounded \& lifted)}},\;\underbrace{\sigma_{good}\models\varphi_{G},\,\sigma_{bad}\not\models\varphi_{G}}_{\text{Traces (holds \& $\neg$ holds)}}\bigr\}.

This rich annotation supports four independent evaluation axes, displayed in Figure
2
:

1.

Lifting accuracy:
The ability to correctly extract substrings from a natural language specification that map to a corresponding atomic proposition in the linear temporal logic.

2.

Translation accuracy:
The fidelity of mapping grounded
or
lifted NL to the correct temporal-logic formula.

3.

Grounding accuracy:
The ability to align logical atomic proposition labels with their corresponding world state condition.

4.

Verification accuracy:
The capacity to decide satisfaction or violation of a grounded LTL formula on a given trace or traces.

Datasets

Warehouse.

Our

Search and Rescue.

The
Search-and-Rescue
(S&R) scenario presents a detailed context of emergency response and robotic aid. It emphasizes multi-step TL relationships, requiring precise event sequencing and robust conditional propositions. Like the Warehouse scenario, it provides complete grounding information and includes scenario-specific LTL templates with both positive and negative execution traces for rigorous verification. The S&R scenario deliberately includes an "avoid" action for the purpose of stress-testing the a framework’s ability to distinguish between APs and LTL operators, because avoid is commonly used to indicate a "globally (negation
\varphi

Example:

•

Sentence:
“If deliver aid to the safe rescuer holds and request assistance holds next, then stay away from the active gas leak holds in the step after that.”

“If prop_1 holds and prop_2 holds next, then prop_3 holds in the step after that.”

•

APs:
prop_1 = deliver aid to safe rescuer, prop_2 = request assistance, prop_3 = avoid active gas leak

Traffic Light Control.

The
Traffic Light Control
scenario introduces LTL propositions relevant to urban navigation and infrastructure management. This scenario tests an NL-to-LTL system’s ability to accurately ground complex real-world relationships, such as spatial landmarks and persistent behaviors like "infinitely often." Each dataset entry is provided with explicit good and bad traces, detailed proposition grounding, and is constructed via a flexible scenario template, allowing straightforward extension to additional real-world tasks.

•

Grounded LTL Formula:

•

4.3
Grounding Evaluation

In this section, we present the results obtained from our evaluation of our baseline grounding framework, applied to the ground truth lifted TL from our three VLTL-Bench datasets. We use two prompting strategies (described in Appendix
A.4
) applied to three GPT models to provide a broad evaluation of current grounding capabilities. Our first prompting baseline -
few-shot
- is composed of a brief description of the task at hand, accompanied by nine few-shot examples of correct (sentence, lifted sentence, AP-dictionary) tuples from
all three scenarios
(as opposed to individual scenarios). The next strategy is the
scenario
baseline prompt which includes the full scenario configuration file, as well as three few-shot examples from the dataset. To measure grounding accuracy, we parse the resulting AP-dictionary predictions and compare them with our ground-truth knowledge of the AP-dictionary in each entry. Our metrics are per-AP and per-AP-dictionary accuracy. Per-AP accuracy is calculated by recording the total number of correctly grounded APs divided by the total number of APs in the test set, and per-AP-dictionary accuracy is calculated by recording the total number of correct complete AP-dictionaries, divided by the size of the test set. These results are presented in Table
4
.

Our evaluation of the two grounding baselines reveals that even advanced LLMs struggle to accurately ground lifted APs into a concrete world state space - even when the parameters of this state space are provided, as is done in the
scenario
baseline. We observe that even though the
scenario
baseline achieves lower performance on most benchmarks and settings, it beats the
few-shot
baseline on our Warehouse scenario when comparing the more powerful reasoning models. As noted in Section
3
, the Warehouse scenario is specifically designed to stress-test
grounding and lifting
. We conclude that the provision of the world state space in the
scenario
baseline includes information that aids reasoning models in determining which world state conditions are referred to in the lifted APs, but the overall performance of these baselines on the grounding task remains notably lower than other tasks involved in verifiable NL-to-LTL translation.

Conclusion

We present the Verifiable Linear Temporal Logic Benchmark. VLTL-Bench is a suite of three new NL-to-LTL translation datasets that include the standard natural language and LTL pairs, supplemented with lifted natural language, lifted LTL, and trace examples. These additional features provide a method for the isolated training and evaluation of individual NL-to-LTL translation framework components. The provision of trace examples in VLTL-Bench introduces the possibility of a new type of input that is plausible in real-world translation frameworks, but unrepresented in current corpora. We acknowledge that the datasets included in the VLTL-Bench suite are generated using a finite number of linguistic and logical templates, populated by diverse synthetic natural language APs. Therefore, our logical diversity is limited to 43 lifted NL-LTL templates. The linguistic complexity of our benchmark is also partially limited in the same manner. However, our randomly selected action and target references combined with LLM-based pruning allows this work to surpass existing datasets in terms of diversity and realism, and we believe future effort should be partially devoted to further improvements in this area. VLTL-Bench reveals significant weaknesses in what were previously ironclad NL-to-LTL translation frameworks. Among these our the reliance on accurately lifted NL inputs for translation, lack of accurate grounding components, and lack of example trace inputs in current approaches. We hope that contribution will encourage exploration of diverse methods for NL-to-LTL translation, beyond the use of LLMs.

A.1
Linear Temporal Logic

Linear temporal logic (LTL) is a modal extension of classical propositional logic that enables reasoning about how truths evolve over a discrete, linear timeline
[
32
]
. Formulas in LTL are interpreted over infinite sequences (or “traces”) of states

\sigma=s_{0},s_{1},s_{2},\ldots,

where each state
s_{i}
(which has a set of conditions) specifies which atomic propositions
\pi^{\mu}
hold true at time
i
. This framework makes it possible to specify and verify both safety properties (e.g., “nothing bad ever happens”) and liveness properties (e.g., “something good eventually happens”), and it underpins many model-checking techniques for reactive systems.

The syntax of LTL is given by the following grammar:

\displaystyle\varphi::={}

\displaystyle\pi\;\mid\;\neg\varphi\;\mid\;\varphi_{1}\wedge\varphi_{2}\;\mid\;\varphi_{1}\vee\varphi_{2}\;\mid\;\varphi_{1}\Rightarrow\varphi_{2}

\displaystyle\;\mid\;\bigcirc\varphi\;\mid\;\diamondsuit\varphi\;\mid\;\Box\varphi\;\mid\;\varphi_{1}\,\cup\,\varphi_{2}

where

\pi
ranges over a finite set of atomic propositions;
\neg
,
\wedge
,
\vee
, and
\Rightarrow
are the standard Boolean connectives;
\bigcirc
(
next
) asserts that its operand holds in the immediately following state;
\diamondsuit
(
eventually
) asserts that its operand holds at some point in the future;
\Box
(
always
) asserts that its operand holds at every future state;
\varphi_{1}\cup\varphi_{2}
(
until
) asserts that
\varphi_{1}
continuously holds until
\varphi_{2}
becomes true. Formally, we write

\sigma,i\models\varphi

to mean “formula
\varphi
holds at position
i
in trace
\sigma
.” For example:

\displaystyle\sigma,i\models\varphi_{1}\cup\varphi_{2}

\displaystyle\quad\text{iff}\quad\exists k\geq i:\;\sigma,k\models\varphi_{2}\;\wedge\;\forall j\in[i,k):\;\sigma,j\models\varphi_{1}.

Although our focus is on discrete-time LTL, many of these ideas carry over to related formalisms such as signal temporal logic (STL) for continuous-time, real-valued signals
[
19
]
.

A.2
Verification via Kripke Structures and Fluents

Verification of LTL specifications is typically conducted using a Kripke structure, which is a formal transition system comprising states, transitions, and labels indicating which atomic propositions hold true in each state. Formally, a Kripke structure is defined as a tuple
M=(S,S\_0,R,L)
, where:

•

S
is a finite set of states,

•

S_{0}\subseteq S
is the set of initial states,

•

R\subseteq S\times S
is the transition relation, specifying allowed state transitions,

•

L:S\rightarrow 2^{\mathit{AP}}
is a labeling function mapping states to the sets of atomic propositions that are true in each state.

Verification involves checking whether every possible path through the Kripke structure satisfies the given LTL formula. For instance, safety properties such as
“a collision never occurs”
require that no path through the structure contains a state labeled with the proposition
collision
. Conversely, liveness properties such as
“a goal is eventually reached”
demand the existence of a future state in every valid path labeled with the proposition
goal
. Additionally, verification explicitly involves fluents—timestamped state variables that indicate when certain conditions or states become true. Each fluent captures both the state variable (atomic proposition) and the time step at which the transition into the corresponding state occurs. Formally, a fluent can be represented as a tuple
(\pi^{\mu},t)
, indicating that proposition
\pi^{\mu}
becomes true at time step
t
due to a state transition within the Kripke structure. Fluents bridge the gap between high-level temporal specifications and lower-level state transitions, facilitating practical model checking and control synthesis in robot control systems.
