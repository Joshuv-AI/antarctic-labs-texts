Structural Enforcement of Statistical Rigor in AI-Driven Discovery: A Functional Architecture
Karen Sargsyan

Abstract
Sequential statistical protocols require meticulous state management and robust error handling—challenges naturally suited to functional programming. We present a functional architecture for structural enforcement of statistical rigor in automated research systems ("AI-Scientists"). These LLM-driven systems risk generating spurious discoveries through dynamic hypothesis testing. We introduce the Research monad, a Haskell eDSL that enforces sequential statistical protocols (e.g., Online FDR (false discovery rate) control) using a monad transformer stack. To address risks in hybrid architectures where LLMs generate imperative code, we employ Declarative Scaffolding— generating rigid harnesses that structurally constrain execution and prevent methodological errors like data leakage. We validate this approach through large-scale simulation (N=2000 hypotheses) and an end-to-end case study, demonstrating essential defense-in-depth for automated science integrity.

Introduction

Managing the complex, evolving state required by sequential statistical protocols is a significant challenge in software engineering. Protocols designed to control the False Discovery Rate (FDR) during dynamic hypothesis testing require strict sequential accounting of an "error budget." Imperative implementations of these protocols are brittle; subtle errors in state management can invalidate statistical guarantees. Functional programming paradigms offer powerful mechanisms for managing state and effects rigorously. We propose a functional architecture that leverages these mechanisms for the structural enforcement of statistical rigor.

2.1
The Hybrid Workflow

The process begins with the Haskell Orchestrator, which manages the sequence of research ideas. For each idea, the orchestrator must ensure methodological correctness before execution. The execution itself occurs in the Python environment, where an LLM Coder Agent generates the specific implementation logic. Upon completion, the Python environment returns a P-value to the Haskell orchestrator, which then updates the global statistical state.

2.2
The Two Levels of Risk

This architecture introduces risks at two distinct levels:

Macro-level Risk (Orchestration):
This concerns the global management of the False Discovery Rate (FDR) across the sequence of ideas. Online FDR protocols, such as LORD++
[
19
]
, require strict sequential accounting of an "
\alpha
-wealth" (error budget). Errors in state management (e.g., timing errors, state corruption) at this level can invalidate the overall statistical guarantees.

Micro-level Risk (Execution):
This concerns the integrity of individual experiments within the Python environment. The LLM-generated code might introduce bias, such as data leakage between exploration and validation datasets, or use inappropriate statistical tests. If the input P-values are biased ("garbage in"), the macro-level FDR control is meaningless ("garbage out").

Furthermore, the dynamic nature of LLM execution means the total number of tests is uncertain. The LLM might fail to generate valid code, terminating a test prematurely. This uncertainty necessitates Online FDR control methods, as traditional methods (e.g., Bonferroni) require knowing the total number of tests in advance.

We combine two essential capabilities:

Inevitable Accounting (StateT):
The foundation is the State Monad (‘StateT s m‘). This guarantees that the protocol state ‘s‘ is threaded purely and sequentially through every operation. It ensures that every hypothesis test accesses and updates the same unified statistical state, preventing state corruption or stale reads.

Robust Error Handling (ExceptT):
We layer the Exception Monad Transformer (‘ExceptT ResearchError‘) over ‘StateT‘. This allows us to halt the computation gracefully if a protocol violation is detected, rather than relying on partial functions like ‘error‘. The ordering (‘ExceptT‘ over ‘StateT‘) is crucial: if an error occurs, the entire computation, including any pending state changes, is short-circuited, ensuring the integrity of the statistical state.

4.1
The Strategy: Standardized Methodology Enforcement

Relying on LLMs to generate methodologically sound code via prompts alone ("soft enforcement") is brittle. We employ
Declarative Scaffolding
as a defense-in-depth strategy. We enforce a standardized scientific methodology structurally, while allowing the LLM flexibility in the domain implementation.

The functional orchestrator generates a rigid execution environment—a Scaffold—that implements the methodology. The LLM’s role is to adapt the domain logic (including refactoring user-provided baseline code) into the structure required by the scaffold.

Evaluation

We evaluate our architecture through a simulation study and an end-to-end case study. The objectives are to: (1) demonstrate the necessity of FDR control at scale, (2) validate the correctness of the monadic implementation, and (3) illustrate the integrated architecture (Monad + Scaffolding) in a realistic scenario. The full code is available for replication at
https://github.com/karsar/ai-scientist-guards
. Note that realistic case study results may vary due to differences in LLM responses.

5.1
Simulation Study: Necessity of FDR Control at Scale

We validate two claims: the behavioral correctness of the monadic implementation of LORD++, and the necessity of FDR (false discovery rate) control in large-scale automated discovery. We used a Monte Carlo simulation (repeating a randomized process to understand the distribution of outcomes). The objective was to determine the empirical False Discovery Rate (FDR) when testing
N=2000
hypotheses sequentially. We modeled a scenario where the ground truth is known: 10% of hypotheses were true effects (
H_{1}
), and 90% were null effects (
H_{0}
).

We simulated P-values based on ground truth to create realistic scenarios.
A P-value quantifies evidence: lower values indicate stronger evidence of an
effect. When no effect exists (
H_{0}
), any P-value is equally likely, following
a Uniform distribution
U(0,1)
. When a true effect exists (
H_{1}
), we expect
smaller P-values. We model this using the Beta distribution
\text{Beta}(a,1)

with
a=0.15
, which concentrates probability mass near zero. The parameter

a=0.15
represents moderate statistical power—the probability that our test
correctly identifies a true effect. This realistic mixture (90% nulls, 10%
true effects) mimics automated discovery where most hypotheses fail but some
succeed.

The simulation setup used a target FDR/
\alpha
of 0.05 and was repeated 100 times. We compared the Monadic (LORD++) implementation against a Naive approach using a fixed significance threshold
\alpha=0.05
without multiple comparison correction.

5.2
Case Study: End-to-End Architecture Demonstration

We utilized the AI-Scientist prototype to illustrate the integrated architecture in practice, optimizing a Support Vector Machine (SVM) classifier on the Wine dataset. The objective was to demonstrate the end-to-end workflow, including the structural enforcement of the methodology and the dynamic nature of the LLM interaction.

The system was initialized with a baseline Python script defining a suboptimal SVM configuration, and a set of five optimization hypotheses. The LLM (GPT-4o) was instructed to refactor the baseline code into the scaffold structure. The setup enforced a standardized methodology via the ‘DataContract‘ (separate data splits) and ‘StatisticalTestSpec‘ (3-repeated 10-fold Paired T-Test). The target FDR was 0.05.

Preventing Methodological Errors:
This setup demonstrates how scaffolding prevents critical errors. Without scaffolding, the LLM might optimize the model using the entire dataset (including validation data). This data leakage would inflate the accuracy and deflate the resulting P-value, leading to spurious discoveries. Our architecture prevents this structurally: the harness ensures the LLM’s ‘optimize‘ function only receives the exploration data path.

Related Work and Future Directions

eDSLs for Correctness:
Functional programming has a rich history of using eDSLs to ensure correctness. Examples include DSLs for financial contracts
[
20
]
, and ensuring dimensional correctness in scientific computing
[
21

. Our work applies this paradigm to the enforcement of statistical methodology.

Managing Effects and State:
The use of the State Monad is standard. The use of Monad Transformers (like
ExceptT

[

. Alternative approaches, such as Algebraic Effects
[

Advanced Type Systems (Future Work):
We can explore advanced type system features to strengthen the guarantees further. Indexed Monads
[
24
]
could potentially encode the constraints currently checked by
isValidTransition
directly in the type system, turning runtime checks into compile-time guarantees.

Similarly, Generalized Algebraic Data Types (GADTs) could be used to model the staged experimental workflow (Exploration vs. Validation). By parameterizing the experiment type by the stage, the type system could statically enforce the correct sequence of operations, verifying the structure of the experiment before the scaffold is generated.

Safe Code Generation and Scaffolding:
The Declarative Scaffolding approach relates to work on safe code generation and type-safe metaprogramming
[
26
]
. It ensures the generated code adheres to a specific structure (the harness), applied here specifically to enforce scientific methodology across the IO boundary.

Parallelization and Asynchronous Testing:
Our current architecture
enforces strictly sequential hypothesis testing, where each test must complete
before the next begins. This design choice simplifies the statistical
accounting and ensures correctness of the LORD++ protocol, which was designed
for sequential settings. However, modern AI-Scientist systems often execute
multiple experiments in parallel for efficiency, particularly when computational
resources allow concurrent model training.

Extending our architecture to parallel settings requires adopting asynchronous
FDR control methods
[
27
]
. These protocols maintain
statistical validity when tests complete in arbitrary order, but introduce
additional complexity: the
Research
monad would need to handle
concurrent state updates and resolve race conditions in
\alpha
-wealth
allocation. One approach is to use Software Transactional Memory (STM) in
Haskell to manage concurrent access to the statistical state, preserving the
structural guarantees while enabling parallelism. We defer this extension to
future work, as the sequential case already demonstrates the core architectural
principles and provides a foundation for parallel variants.

Probabilistic Programming:
Probabilistic Programming Languages (PPLs)
[
28
]
focus on inference within a single model. Our work addresses the complementary challenge of controlling error rates across a sequence of multiple, dynamically generated experiments.

7
Conclusion

We have presented a functional architecture designed for the structural enforcement of statistical controls in hybrid AI-Scientist systems. The
Research
monad guarantees the integrity of sequential statistical protocols at the macro level through inevitable accounting and robust error handling. Declarative Scaffolding provides defense-in-depth at the micro level by structurally constraining LLM-generated code to adhere to a standardized methodology. This architecture provides essential guardrails for the integrity and reliability of automated scientific discovery.
