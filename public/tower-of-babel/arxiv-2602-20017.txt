QuIeTT : Query-Independent Table Transformation for Robust Reasoning
Gaurav Najpande, Tampu Ravi Kumar, Manan Roy Choudhury, Neha ValetiYanjie FuVivek Gupta Arizona State University {gnajpand,traviku2,mroycho1,nvaleti1,yanjie.fu,vgupt140}@asu.edu

Abstract
Real-world tables often exhibit irregular schemas, heterogeneous value formats, and implicit relational structure, which degrade the reliability of downstream table reasoning and question answering. Most existing approaches address these issues in a query-dependent manner, entangling table cleanup with reasoning thus limiting generalization. We introduce QuIeTT , a query-independent table transformation framework that preprocesses raw tables into a single SQL-ready canonical representation before any test-time queries are observed. QuIeTT performs lossless schema and value normalization, exposes implicit relations, and preserves full provenance via raw table snapshots. By decoupling table transformation from reasoning, QuIeTT enables cleaner, more reliable, and very efficient querying without modifying downstream models. Experiments on four benchmarks: WikiTQ, HiTab, NQ-Table, and SequentialQA shows consistent gains across models and reasoning paradigms, with particularly strong improvements on a challenge set of structurally diverse, unseen questions.

Introduction

Table-based reasoning is a central component of many natural language
understanding tasks, including question answering, information
retrieval, and decision support. However, real-world tables are often

not
directly suitable for either natural-language or symbolic
querying. In practice, tables frequently exhibit schema inconsistencies,
heterogeneous value formats, implicit relational structure, and
irregular cell contents. Common failure patterns include mixed units
within a single column (
e.g.
,
‘‘5 km’’
vs.
‘‘300 m’’
),
dates expressed as free text (11th October 2020), multiple entities packed into a single (John Smith (USA), Maria Lopez (ESP), Li Wei (CHN))
cell, symbols used in place of text, missing or non-unique keys, and
hierarchical layouts that are not readily queryable by SQL or
language-based models. Such issues are pervasive in both curated
benchmarks and real-world data, and they significantly complicate
downstream reasoning.

This design stands in contrast to standard data engineering practices,
where raw tabular data is typically transformed into a clean,

Can raw, semi-structured tables be transformed into a single reusable representation that generalizes across unseen, structurally diverse queries?

In this work, we propose a

enables natural-language and programmatic querying to operate over
cleaner and more regular table representations, without modifying
downstream reasoning models. Our main contributions are as follows:

1.

We introduce

, a query-independent framework that transforms raw tables into a single canonical, SQL-ready representation by disentangling table preparation from query-specific reasoning.

2.

Through experiments on four table QA benchmarks, we show that
QuIeTT
consistently improves performance across models and reasoning strategies, with particularly strong gains on unseen and structurally diverse queries.

3.

We conduct ablation studies analyzing the effects of model size, table context availability, and table-level variation, clarifying when and why query-independent transformation improves robustness.

4.

We construct a manually annotated challenge set with greater query diversity and structural complexity to evaluate generalization beyond the original query distribution.

2
Problem Definition and Task Setup

We study query-independent table transformation for table reasoning. Let
T_{\text{raw}}\in\mathcal{T}

denote a raw, semi-structured table drawn from the space of real-world tables
\mathcal{T}
, and let
\mathcal{Q}
denote the space of possible downstream queries.

2.1
Query-Independent Table Transformation

The first task is to construct a transformation function,
f:\mathcal{T}\rightarrow\mathcal{T}
, that maps a raw table
T_{\text{raw}}
to a single canonical table,
T_{\text{C}}=f(T_{\text{raw}})
,
without access to any downstream query
q\in\mathcal{Q}
. The input table
T_{\text{raw}}
may contain schema inconsistencies, heterogeneous value formats, implicit relational structure, and irregular cell contents. The output table
T_{\text{C}}
is a canonical, SQL-ready representation that resolves these issues through normalization, restructuring, and the addition of derived columns, while preserving all original information. We impose three constraints on the transformation:
(a) Query Independence.

The transformation is performed before any downstream query is observed and does not condition on anticipated questions. Formally, the transformation function
f
is independent of any
q\in\mathcal{Q}
,
(b) Lossless Execution.

All information in the original table must remain preserved after transformation. For any value or relation derivable from
T_{\text{raw}}
, there exists a deterministic procedure to recover it from
T_{\text{C}}
, and
(c) Single-Table Reuse.

Each table is transformed once into a single representation that can be reused across an arbitrary number of queries, tasks, and reasoning models.

2.2
Downstream Table Question Answering

The second task is table question answering performed after transformation. Given a fixed reasoning model
M
and a fixed prompting or execution strategy
S
, a query
q\in\mathcal{Q}
is answered by operating on the transformed table:
\hat{a}=M(S(q,T_{\text{C}})).
The reasoning model and prompting strategy are held fixed throughout; only the table representation is changed.

Evaluation Protocol.

Query-independent table transformation is evaluated indirectly through its impact on downstream table question answering. For a fixed reasoning model and reasoning strategy, we compare performance when operating on the raw table
T_{\text{raw}}
versus the transformed table
T_{\text{C}}
. Improvements in accuracy and execution robustness are attributed solely to changes in table representation. To assess generalization, we further evaluate on a manually constructed challenge set of unseen queries with increased structural diversity.

QuIeTT
consists of three stages: (a.) issue generation, (b.) transformation plan generation, and (c.) deterministic plan execution.

Issue Generation.

Probes
T_{\mathrm{raw}}
to expose latent structural deficiencies that hinder general-purpose querying. Formally, issue generation is a mapping
g:\mathcal{T}\rightarrow\mathcal{Q}_{\mathrm{probe}}
, where
\mathcal{Q}_{\mathrm{probe}}(T_{\mathrm{raw}})=\{q^{(1)}_{\mathrm{syn}},\dots,q^{(M)}_{\mathrm{syn}}\}
is a finite set of synthetically generated queries designed to be difficult to answer under the current table representation. In addition to the probe queries themselves, each
q^{(i)}_{\mathrm{syn}}
is associated with an explicit set of detected representational issues, producing a structured artifact (
e.g.
,
issues.json
) that maps probe identifiers to issue types and their corresponding locations in
T_{\mathrm{raw}}
.

These issue annotations are used exclusively to guide transformation planning and are not consumed by downstream reasoning. Both the synthetic probe set
\mathcal{Q}_{\mathrm{probe}}(T_{\mathrm{raw}})
and the associated issue annotations are discarded after plan generation, ensuring that the transformation pipeline remains independent of the downstream test-time query distribution.

Handling Hierarchical Complexity.

Hierarchical tables pose a structural challenge for downstream normalization and issue detection, as relevant information may be distributed across implicit parent–child levels rather than explicit columns. To address this, we first apply a deterministic flattening step that materializes all hierarchy levels as explicit columns or repeated parent labels. This pre-processing is lossless and preserves the original hierarchical semantics, while enabling subsequent transformation stages to operate over a uniform, columnar representation.

Transformation Plan Generation.

A transformation plan is defined as an ordered sequence
\pi=\langle o_{1},\dots,o_{K}\rangle
, where the plan length
K
and the specific operations are determined dynamically based on the input table and detected issues. Each operation
o_{i}
explicitly specifies its input columns, output columns, and dependencies, yielding an auditable transformation graph. Collectively, the plan
\pi
induces an explicit target schema
\mathcal{S}_{\pi}
that determines the column set, names, types, and derived fields of the transformed table prior to execution. The plan is generated by a function
\mathcal{P}:\mathcal{T}\times\mathcal{Q}_{\mathrm{probe}}\times\mathcal{I}\rightarrow\Pi
, yielding
\pi=\mathcal{P}(T_{\mathrm{raw}},\mathcal{Q}_{\mathrm{probe}}(T_{\mathrm{raw}}),\mathcal{I}(T_{\mathrm{raw}}))
. By constraining operation semantics while allowing variable plan length and composition,
QuIeTT
produces executable and reproducible plans while limiting hallucinated behavior.

Transformation Plan Execution

The transformation plan
\pi
is realized through an explicit code generation and execution stage. This explicit plan-to-code execution model is inspired by design principle of
separating symbolic planning from deterministic execution, as advocated in Weaver
Khoja et al. 2025
.
Given
\pi
and the raw table
T_{\mathrm{raw}}
,
QuIeTT
deterministically generates executable code in Python where each code block corresponds to a specific operation
o_{i}\in\pi
and faithfully implements its declared inputs, outputs, and dependencies. Let
E
denote the executor; executing the generated code yields the canonical table
T_{C}=E(\pi,T_{\mathrm{raw}})
. Determinism requires that for fixed
(\pi,T_{\mathrm{raw}})
, both code generation and execution produce the same
T_{C}
.

The executor enforces plan faithfulness by disallowing implicit control flow, undeclared side effects, or data-dependent behavior not specified in
\pi
. The resulting canonical table contains normalized and derived columns while preserving all original values via auxiliary snapshot columns whenever operations would otherwise be lossy. The induced representation conforms to the target schema
\mathcal{S}_{\pi}
and is SQL-ready, enabling direct consumption by downstream reasoning systems without modifying the reasoning model or prompting strategy.

Query Independence, Losslessness, and Reuse

QuIeTT
enforces a strict separation between transformation and reasoning. The transformation plan
\pi
and its execution
\mathcal{E}
are constructed without access to any downstream query
q\in\mathcal{Q}
and are reused unchanged across all subsequent queries. Although
QuIeTT
employs synthetic probe queries during issue generation, these probes do not approximate or encode any downstream query distribution. Instead, they induce a table-intrinsic closure over representational deficiencies, identifying the structural conditions that must be satisfied for the table to support general-purpose querying. The probing process depends only on the input table and a fixed transformation vocabulary, and all probe queries and intermediate artifacts are discarded before downstream evaluation. Consequently, the resulting transformation is fully query-independent.

Losslessness further requires that all information in
T_{\mathrm{raw}}
remain recoverable from the canonical table
T_{\mathrm{C}}
, ensuring that transformation does not constrain the space of answerable queries. Each table is therefore transformed exactly once into a single canonical representation that can be reused by an arbitrary number of downstream queries, tasks, and reasoning models.

QuIeTT
Challenge Set

To evaluate robustness and generalization under increased structural complexity, we construct a challenge set using a controlled, LLM-driven data generation pipeline.

Dataset Creation.

Challenge set is constructed from tables drawn from the WikiTQ and NQ-Tables datasets. For each table, we first apply the
QuIeTT
transformation framework to obtain a canonical, SQL-ready representation with normalized schemas, explicit relations, and derived attributes. Conditioned on this representation, we generate structurally challenging question–answer pairs following recent LLM-based table QA benchmarks
Choudhury et al. 2025
;
Tian et al. 2025
.

To ensure answerability and faithfulness, the generation process enforces that answers be derived exclusively from the table content. This biases the challenge set toward queries that are difficult to answer reliably on raw or weakly structured tables but are well-supported by a canonical representation. As the challenge data is automatically generated, we additionally perform human verification of the generated questions and answers to assess correctness and clarity. Details of the verification protocol and agreement analysis are presented in the following section.

Dataset Verification.

To assess the quality and correctness of the automatically generated challenge set, we conduct a human verification study with three NLP experts. Each annotator independently verified the generated questions and their corresponding ground-truth answers against the associated tables. We compute inter-annotator agreement using both pairwise Cohen’s Kappa and multi-rater agreement metrics (Fleiss’ Kappa and Jaccard coefficient).

Results and Analysis

Table

Performance across model sizes and families.

Across all datasets,
QuIeTT
consistently improves performance across language models of different sizes and families under the same prompting strategy (Table
4
). These improvements hold for both proprietary models (Gemini 2.0, Gemini 2.5) and open-weight models (DeepSeek-V3.1, Qwen3-80B, GPT-OSS-120B).
QuIeTT
achieves average F1 scores of 77.82 (Gemini 2.0), 84.41 (Gemini 2.5), 81.30 (DeepSeek-V3.1), 81.22 (Qwen3-80B), and 79.50 (GPT-OSS-120B). Relative to the strongest prior baseline for each model, these gains correspond to improvements of approximately 4–8 F1 points depending on the model and dataset. Notably, comparable gains are observed for both larger and smaller models, suggesting that
QuIeTT
reduces reliance on model scale for effective table question answering.

Effect of table structure on performance.

QuIeTT
demonstrates consistent improvements across diverse table structures and reasoning settings, including web tables, hierarchical tables, and multi-turn reasoning scenarios (Table
4
). Across WikiTQ and NQ-Table,
QuIeTT
attains strong performance across models, reaching F1 scores as high as 79.80 on WikiTQ and 80.10 on NQ-Table. On SequentialQA, which requires interdependent multi-turn reasoning,
QuIeTT
maintains robust performance, achieving F1 scores up to 72.32, indicating that transformation benefits extend beyond single-turn question answering. Similarly, on HiTab, which emphasizes hierarchical structure and numerical reasoning,
QuIeTT
achieves the highest performance across models, with peak F1 reaching 84.41. Together, these results show that the benefits of query-independent table transformation generalize across a wide range of table structures and reasoning requirements.

When such structure is already sufficient, applying

typically leaves performance unchanged.

6
Related Work

Recent work in table question answering (QA) shows that table representation and pre-processing strongly impact downstream reasoning, especially for noisy and semi-structured tables.

Lightweight normalization for table QA.

Some methods apply one-time normalization to reduce surface-form variability while preserving the original structure. NormTab
Nahid and Rafiei 2025
standardizes values (e.g., dates and numbers) and applies limited fixes such as transposition but leaves hierarchical structure, implicit relations, and heterogeneous layouts to downstream reasoning. Related approaches similarly assume mostly fixed schemas and rely on query-time reasoning to resolve remaining ambiguity
Pasupat and Liang 2015
;
Nahid and Rafiei 2024
.

Programmatic table restructuring.

A second line of work performs broader extensive restructuring via explicit transformation programs. Auto-Tables
Li et al. 2023
synthesizes multi-step pipelines from a fixed operator vocabulary but is limited to predefined transformations. DataMorpher
Sharma et al. 2025
and RelationalCoder
Dong et al. 2025b
generate Python or SQL programs for ETL or schema matching, remaining tightly coupled to program execution and not enforcing a single, lossless, reusable representation.

Transformation coupled with reasoning.

Other approaches integrate transformation directly into reasoning. TabFormer
Dong et al. 2025a
jointly applies restructuring and SQL answering, making transformations dependent on the query set. Chain of Tables
Wang et al. 2024
and TableReasoner
Xiong et al. 2025
similarly adopt query-driven schema selection or iterative reasoning, improving efficiency but coupling structure to query-time reasoning. In contrast,
QuIeTT
treats table transformation as a query-independent preprocessing step that produces a single canonical and lossless representation reused across queries, tasks, and models, cleanly separating representation quality from downstream reasoning.

7
Conclusion

We introduced
QuIeTT
, a query-independent table transformation framework that converts raw, semi-structured tables into a single, lossless, SQL-ready representation prior to question answering. By decoupling table preprocessing from downstream reasoning,
QuIeTT
enables a transformed table to be reused across queries, models, and reasoning strategies. Experiments across multiple benchmarks and language model families show that
QuIeTT
consistently improves table QA performance under identical prompting conditions, including with smaller models and constrained inputs, indicating that gains arise from improved table representation rather than changes in reasoning strategy. These results highlight query-independent table transformation as a foundational component of robust table question answering and motivate future work on scaling to large tables, hybrid or multimodal formats, and multi-table reasoning.

8
Limitations

Despite its effectiveness across diverse table QA benchmarks,
QuIeTT
has several limitations. The framework is primarily designed for small to medium-sized tables that can be reasonably processed by current language models; very large tables, such as long spreadsheets with hundreds or thousands of rows, remain challenging due to input length constraints and the difficulty of producing compact yet faithful transformed representations. In addition,
QuIeTT
focuses on structured tabular data and does not explicitly handle hybrid or multi-modal tables that interleave free-form text, images, or other non-tabular content, which are common in real-world documents and require joint multi-modal reasoning. While the transformed tables produced by
QuIeTT
enable effective question answering even with smaller or constrained QA models, the transformation stage itself relies on sufficiently capable language models; very small models may struggle with complex or ambiguous table structures. Finally,
QuIeTT
operates on individual tables and does not address retrieval or reasoning across multiple tables or documents, leaving extensions to multi-table or retrieval-augmented settings as an important direction for future work.

9
Ethics Statement

This work studies table transformation and reasoning over publicly available benchmark datasets, including WikiTQ, HiTab, NQ-Table, and SequentialQA. All datasets consist of tabular data derived from publicly accessible sources (e.g., Wikipedia) and do not contain personally identifiable information beyond what is already publicly disclosed.
The proposed framework,
QuIeTT
, operates purely on tabular structure and content and does not introduce new data or modify the semantic content of the original tables beyond lossless normalization and restructuring. The challenge set introduced in this work is automatically generated from existing tables and manually verified by expert annotators to ensure correctness and faithfulness; no human subjects are involved beyond standard dataset verification, and no personal or sensitive attributes are inferred or labeled.
We do not anticipate any harmful or unethical use of the proposed method. However, as with all large language model-based systems, care should be taken when applying
QuIeTT
to proprietary, sensitive, or private data, and appropriate data governance and privacy safeguards should be followed. AI tools were used for manuscript and code editing. We will release code and data under a permissive license to support transparency and reproducibility.

B.2
Token Usage Accounting

For reproducibility, we log token usage at the granularity of individual tables
and preprocessing stages (issue generation, plan generation, and code
generation). For each language model invocation, we record the number of input
tokens, output tokens, and total tokens consumed.

Total preprocessing token usage over a corpus of tables is computed as:

\text{Tokens}=\sum_{i=1}^{T}\sum_{s\in\{\mathrm{issue},\,\mathrm{plan},\,\mathrm{code}\}}\left(\mathrm{in}_{i,s}+\mathrm{out}_{i,s}\right),

where
T
denotes the total number of tables.

B.3
Amortization Across Queries

Because preprocessing is performed once per table and cached, the marginal
preprocessing token cost per downstream query is zero. All downstream question
answering is performed on the canonical transformed table using an unchanged QA
model, without incurring any additional preprocessing-related language model
cost.

Appendix D
Human Verification Guidelines and Annotation Rubric

To assess the correctness, faithfulness, and clarity of the automatically
generated QUIETT challenge set, we conduct a structured human verification
study. This section documents the annotation setup, verification objectives,
and rubric provided to annotators.

D.1
Annotation Setup

Each annotator is presented with the following materials:
(i) the
original raw table
drawn from the source dataset,
(ii) a generated natural-language question, and
(iii) the corresponding proposed ground-truth answer.
Annotators perform verification independently and without access to
model predictions or outputs. All judgments are based solely on the
provided table content.

D.2
Verification Objectives

Annotators are instructed to evaluate each question–answer pair according
to the following criteria:

1.

Well-formedness
: The question is clearly phrased and free of ambiguity.

2.

Answerability
: The question can be answered using only the table content.

3.

Answer correctness
: The provided answer is fully supported by the table.

4.

Structural reasoning
: The question requires non-trivial reasoning,
such as aggregation, comparison, filtering, or reasoning over normalized
or derived fields, rather than simple cell lookup.

Annotators are explicitly instructed not to assess model difficulty,
linguistic style beyond clarity, or subjective preferences.

D.3
Annotation Guidelines

The following guidelines are provided to annotators to ensure consistent
judgments:

•

Table faithfulness
: All answers must be derivable exclusively
from the table content, including normalized or derived columns introduced
by QUIETT. External knowledge may not be used.

•

Table representation awareness
: Annotators should treat
the raw table as authoritative. Questions relying on derived or
normalized fields (e.g., parsed dates or normalized units) are considered
valid.

•

Ambiguity handling
: If a question admits multiple reasonable
interpretations or more than one valid answer, it must be marked incorrect.

•

Incomplete answers
: Answers that partially satisfy the question
(e.g., missing entities in list-valued outputs or incorrect aggregation
results) are marked incorrect.

•

Assumption prohibition
: Questions requiring assumptions not
grounded in the table (e.g., inferred semantics, unstated ordering, or
missing values) are marked incorrect.

D.4
Annotation Rubric

Each question–answer pair is evaluated using the rubric shown in
Table
11
. A pair is marked
valid
if and only
if all criteria are satisfied.

Criterion

Description

Answer Correctness

The provided answer exactly matches the value(s) supported by the table.

The question can be answered using only the table content.

D.5
Disagreement Analysis

All annotations are performed independently without discussion or
adjudication during the annotation phase. Inter-annotator agreement is
reported using pairwise Cohen’s Kappa and multi-rater agreement metrics
(Fleiss’ Kappa and Jaccard coefficient), as described in Section 4.

D.6
Annotator Qualifications

All annotators are NLP researchers with prior experience in table-based
question answering, semantic parsing, or structured data reasoning.
Annotators were briefed using written instructions and example annotations
prior to the study.

D.7
Rationale

This verification protocol ensures that the QUIETT challenge set evaluates
faithful, well-defined, and structurally grounded reasoning over tables,
rather than exploiting annotation artifacts or superficial patterns. The
high inter-annotator agreement reported in Section 4 indicates strong
consistency in judgments and supports the reliability of the challenge set.
