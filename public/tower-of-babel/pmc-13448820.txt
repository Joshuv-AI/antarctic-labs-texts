Intelligent malware detection on Android smartphones via a hybrid approach using gradient boosting and convolutional neural network
Authors: Collins Chimeleze, Norziana Jamil, Zuhaira Muhammad Zain, Nasir Faruk
Published: 2026

ABSTRACT
Malware is malicious software that infiltrates systems without user consent. Effective detection involves identifying such software and distinguishing it from benign programs. While machine learning has shown promise in malware detection, many existing techniques demand extensive feature engineering and representation, leading to higher computation times and error rates. To address these limitations, we propose CNN-GBM, a hybrid model combining Convolutional neural networks (CNN) with Gradient Boosted Machines (GBM), aimed at improving Android malware detection. The approach begins by constructing a dataset comprising malware and benign files, represented as numerical feature vectors through n-grams, opcode sequences, or byte-level features. CNN processes the raw data to learn hierarchical patterns, while an entropy-based feature selection technique identifies the most informative attributes. These selected features are then fed into the GBM, trained to classify files as malware or benign. Evaluation using metrics such as accuracy, precision, F1 score, and false positive rate indicates that CNN-GBM outperforms existing deep learning models. Notable improvements include accuracy (+ 3%), precision (+ 1%), recall (+ 5%), AUC (+ 3.5%), and significant reductions in false positive rate (− 52%), false negative rate (− 15%), and error rate (− 35%). These enhancements stem from the effective integration of CNN feature extraction with GBM’s boosting capabilities.Supplementary InformationThe online version contains supplementary material available at 10.1038/s41598-026-47985-7.

Introduction

The Internet quickly becomes integral to everyday life, and our reliance on it rises1,2. However, its growing popularity makes it vulnerable to misuse and exploitation1. Malware attacks have increased dramatically in recent years, paralleling the Internet’s expansion2. Computer malware, also known as malicious software, aims to steal information, disable operations, or gain control of a victim’s computer1,2. While computer viruses are the earliest forms of malware, other types, such as logic bombs, worms, rootkits, ransomware, backdoors, and trojans, have emerged over the years1. Despite advancements in anti-malware technology, the number of new malware samples continues to rise daily (McAfee).

The malware detection technique is divided into static analysis-based detection3,4 and dynamic analysis-based detection5–8. Dynamic analysis is running the malware, monitoring its actions, and reporting changes in the executed environment7–9. The complexity of the environment setup is significant in this case, and the runtime required to view the results of executing all malware is increased due to the CPU limitation in Android smartphones10. Static analysis is inspecting malware by evaluating the metadata of malware executables, assembly code instructions, and binary data in their content3,4. This strategy incurs a low cost for setting up the environment and produces results considerably more quickly than dynamic analysis11.

Deep learning models achieve high accuracy in tasks like image classification, face recognition, sentiment analysis, text classification, and speech interpretation12–14. Previous studies indicate that these models require significant computational resources for feature extraction15–32, resulting in performance delays25 and increased time consumption. Despite their accuracy in malware detection, applying these approaches to Android smartphones is challenging due to resource limitations15–37,70–77. Addressing these issues motivates the development of a deep learning-based detection technique to effectively mitigate these challenges. Based on these gaps, the following research questions arise:I.How can existing deep-learning malware detection techniques be enhanced to reduce the false-positive rate in malware detection?II.How can the runtime rate in malware detection be improved to reduce the computational overhead on resource-constrained devices like Android mobile devices?III.How can improvements in error rates and other performance evaluation metrics be employed to reduce the misclassification of malware and benign samples in malware detection systems?

Related works

In this section, we review existing malware detection techniques, highlighting thematic trends, limitations, and gaps that motivate our CNN–GBM approach.

Static analysis-based detection

Several studies have leveraged static features of Android applications for malware detection. Rani et al.38 developed a proof-of-concept ransomware detection system using machine learning models. Acharya et al.39 proposed a framework combining transfer learning and topic modeling to detect and cluster Android malware. Chimeleze et al.33,36,40–44 explored static scanning methods and ML-based approaches such as BFEDroid, aiming to detect malware variants on resource-constrained devices. While these methods achieve reasonable accuracy, they often suffer from high false-positive rates due to reliance on manually engineered or static-only features. Molina-Coronado, et al. and Rathore et al.45,46 studied the robustness of static-analysis features under code obfuscation and proposed a detector that remains effective even when many static features are changed by obfuscation. Singh et al.47 proposed a feed-forward deep neural network (FFDNN) that extracts deep features from portable executable header information to improve static malware classification, showing high generalization capabilities on a large malware dataset.

Dynamic and hybrid analysis

Dynamic analysis, which monitors runtime behaviors, has been explored to improve detection accuracy. Faruk et al.48 highlighted AI-based techniques for detecting malware activities dynamically. Wu et al.49 proposed XMal, which interprets dangerous behaviors in Android apps during execution. Hybrid approaches combining static and dynamic features were introduced by Gibert et al.50 and Chimeleze et al.33, improving robustness but often incurring high computational overhead, making them less suitable for resource-limited devices. López-de-Ipiña et al.51 propose a hybrid multilevel detection method under concept drift, combining local static and remote dynamic analysis. They trigger more computationally expensive dynamic analysis only when the initial static analysis is uncertain, thereby reducing computation while addressing evolving malware threats. Singh et al.52 examined ensemble and hybrid classifiers for malware detection within static and dynamic contexts, demonstrating that combining different analysis perspectives can enhance detection robustness beyond static features alone.

Deep learning-based detection

Deep learning (DL) techniques have recently dominated malware detection research. Qiu et al.53, Zhao et al.54, and Xiao et al.26 applied CNNs to learn features directly from bytecode or opcode sequences. McLaughlin et al.27 and Karbab et al.55 used raw opcode sequences with CNNs to eliminate manual feature engineering. Vinayakumar et al.56 and Su et al.32 employed LSTM and CNN architectures on permission sequences and static features. While these methods achieve high accuracy, many still struggle with false positives, feature redundancy, and runtime inefficiency, particularly on Android devices. Alhussen57 optimized LSTM and neural network (NN) models for Android malware detection, achieving very high accuracy (99%+). This work demonstrates that well-tuned deep models remain highly competitive in the field. Singh et al.58 used an FFDNN to learn deep discriminative representations from static malware data, enabling robust classification when combined with classical ML classifiers.

Resource-constrained and IoT applications

Recent works have addressed malware detection in IoT and resource-limited environments. Naeem et al.59,60 developed platform-independent models combining CNNs and meta-learners for hardware-level malware detection. Alzaylaee et al.61 and Chimeleze et al.40 evaluated models on large real-device datasets. Although these approaches reduce some overhead, they remain computationally expensive and not fully optimized for low-latency detection, highlighting a persistent need for efficient hybrid solutions. Taşcı62 designed a lightweight 1D-CNN model for IoT malware and attack detection, evaluated on the CIC-IoT-2023 and other datasets. The model achieves high performance (~98.36% accuracy) and is particularly suitable for resource-constrained devices. Mehrban et al.63 explored malware detection in IoT systems using machine learning techniques. Their approach, available on arXiv, demonstrates effective classification and detection of threats in resource-constrained environments. Singh et al.64 minimized feature overhead model provides useful insights for resource-limited environments, as reducing feature dimensionality can ease deployment constraints on IoT and mobile systems. Chimeleze et al.65 proposed a lightweight Android malware detection model using hybrid fuzzy simulated annealing clustering. The results showed improved detection accuracy and reduced computational cost compared to traditional methods, making it suitable for resource-constrained mobile

Optimized and boosting-based approaches

Gradient boosting models have shown promise in improving classification performance by iteratively refining predictions. However, their integration with deep learning models for Android malware detection remains limited. Our review shows that existing hybrid or optimized models—while addressing feature selection and accuracy—still face challenges in false-positive mitigation, runtime efficiency, and overall error reduction. Abbas, Daud, et al.66 enhanced Android malware detection by combining XGBoost with convolutional neural networks (CNNs). Their approach achieves high accuracy, demonstrating the effectiveness of hybrid models in improving detection performance. Singh et al.67 explored machine learning models with preprocessing steps that directly limit overhead and refine feature selection, achieving improved performance. Chimeleze, et al.68 reviewed Android malware research and found that evolving, obfuscated, and hybrid threats continue to outpace traditional detection methods. The study categorizes malware types and detection approaches, highlighting gaps in static analysis and the limited generalizability of current machine learning models

The 1D-CNN extracts hierarchical embeddings, guided by similarity-aware regularization, which preserves critical behavioral relationships. These embeddings are then passed to the GBM classifier, whose gradient boosting procedure further mitigates any partial information loss from the CNN. We designed a hybrid CNN-GBM malware detection model employing a 1D-CNN to extract hierarchical features from byte, opcode, or n-gram sequences (length 512–2048). The 1D-CNN consists of two convolutional layers (64 and 128 filters, kernel size 5), each followed by ReLU activation and max-pooling (pool size 2). The output is flattened and passed through two fully connected layers (512 and 256 neurons) with ReLU activation and dropout (0.5) for regularization. A final dense layer with sigmoid activation performs binary classification. Hyperparameter selection

Learning rate, batch size, and epochs were determined using preliminary experiments and grid search with cross-validation. Specifically, learning rates of 1e-2, 1e-3, and 1e-4, batch sizes of 32, 64, and 128, and epochs of 20, 30, and 40 were tested. The final values (learning rate = 1e-3, batch size = 64, epochs = 20–40) provided stable convergence and optimal validation performance while balancing computational efficiency.

Model deployment considerations for android devices

Although we conducted the experiments on a high-performance Windows 10 Pro system equipped with an Intel® Core™ i7-7500U CPU, 32 GB of RAM, and implemented using Java, we designed the CNN-GBM model with mobile efficiency in mind. We adopted a 1D-CNN architecture with relatively small kernel sizes and structured convolution–pooling layers, as shown in Table 1, to limit computational complexity. In addition, we applied entropy-based feature selection to reduce input dimensionality, thereby lowering both memory usage and processing overhead. We employed a lightweight GBM classifier that was further pruned or quantized to support deployment on resource-constrained mobile devices. For practical implementation on Android platforms, we utilized mobile-oriented framework and we applied batch-wise feature processing to further reduce memory consumption. Evaluation of the proposed CNN-GBM model on real Android smartphones was planned as future work.

Feature selection sensitivity analysis

In this subsection, we examine feature selection sensitivity and justify the use of entropy-based selection, highlighting its robustness across n-gram, byte-sequence, and opcode features.

To analyze the sensitivity of the proposed CNN–GBM model to different feature representations, we examined the impact of byte sequences, opcode sequences, n-gram features, and entropy-selected feature subsets on detection performance. These feature types capture complementary aspects of malware behavior, ranging from low-level binary patterns to higher-level instruction semantics.

The 1D-CNN feature extractor is inherently feature-agnostic and operates on fixed-length numerical sequences, enabling it to learn local and contextual patterns regardless of the underlying feature modality. As a result, the model demonstrates stable performance across different feature types, with variations primarily affecting convergence speed and recall rather than overall classification accuracy.

Entropy-based feature selection further reduces sensitivity by filtering out low-information and redundant features across all representations. This step ensures that only the most discriminative byte, opcode, or n-gram features are retained, preventing overfitting and improving robustness. The subsequent GBM classifier refines decision boundaries on the CNN-extracted representations, mitigating residual variability introduced by different feature choices.

Empirically, byte and opcode sequences provide strong baseline performance, while n-gram features improve contextual awareness and robustness against obfuscation. The best and most stable results are achieved when entropy-based feature selection is applied, confirming that model performance depends more on feature informativeness than on a specific representation. Feature representation and CNN-based extraction

To effectively capture discriminative patterns from the input data, a convolutional neural network (CNN) is employed as the primary feature extractor. The CNN architecture is designed to learn hierarchical feature representations, transforming raw inputs into a high-dimensional feature vector that encodes both local and global structural characteristics. Let \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$${\mathbf{x}}_{i}$$\end{document} denote the i-th input sample; the CNN maps \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$${\mathbf{x}}_{i}$$\end{document} to a feature embedding \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$${\mathbf{f}}_{i}\in {\mathbb{R}}^{d}$$\end{document}, where d represents the dimensionality of the learned feature space.

Given the potential redundancy and noise introduced by high-dimensional representations, an entropy-based feature selection strategy is applied to identify the most informative feature dimensions. Specifically, features with higher information entropy are retained, as they contribute more significantly to class discrimination. This process results in a reduced feature vector \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\hat{f}_{i} \in {\mathbb{R}}^{{d^{\prime}}}$$\end{document}, where \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$d^{\prime} \ll d$$\end{document}.

To ensure fair contribution of each selected feature dimension in subsequent similarity computations, Min–Max normalization is applied:10\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\hat{f}_{i,j} = \frac{{\tilde{f}_{i,j} - \min \left( {\tilde{f}_{j} } \right)}}{{\max \left( {\tilde{f}_{j} } \right) - \min \left( {\tilde{f}_{j} } \right)}},j = 1, \ldots ,d^{\prime}$$\end{document}where \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$${\widehat{\mathbf{f}}}_{i}$$\end{document} denotes the normalized feature vector. This normalization step prevents scale dominance by any single feature and stabilizes distance-based similarity measurements in the reduced feature space.

Similarity-based regularization within the gradient boosting framework

While gradient boosting machines (GBMs) are effective in modeling complex decision boundaries, their performance can degrade in the presence of noisy or ambiguous samples. To address this issue, a similarity-based regularization term is introduced to guide the boosting process using neighborhood-level structural information derived from the CNN feature space.

Given the normalized feature representation \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$${\widehat{\mathbf{f}}}_{i}$$\end{document}, the similarity between two samples i and j is computed using a distance-based metric in the reduced feature space. To mitigate the curse of dimensionality and reduce sensitivity to noise, the similarity score for a given sample is not based on a single nearest neighbor. Instead, the average similarity over the top-K nearest neighbors is computed as:11\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$${\mathrm{Sim}}_{Avg}(i)=\frac{1}{K}\sum_{j\in {\mathcal{N}}_{K}(i)}\mathrm{Sim}({\widehat{\mathbf{f}}}_{i},{\widehat{\mathbf{f}}}_{j})$$\end{document}where \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$${\mathcal{N}}_{K}(i)$$\end{document} denotes the set of the K nearest neighbors of sample i in the reduced and normalized feature space, and \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\mathrm{Sim}(\cdot )$$\end{document} represents the chosen similarity function.

This top-K aggregation strategy alleviates the influence of outliers and unreliable distance estimates, providing a more stable and robust similarity measure in high-dimensional settings. The resulting similarity term serves as a regularization signal that is integrated into the gradient boosting objective, influencing the adaptive weight updates during training. Samples with low neighborhood consistency receive higher corrective emphasis, while samples embedded in coherent regions of the feature space are reinforced.

By embedding similarity-based regularization directly into the gradient boosting framework, the model effectively compensates for residual noise in similarity estimation and enhances generalization performance. This integration enables the CNN-GBM model to jointly leverage deep feature representations and neighborhood-aware regularization, leading to improved detection accuracy and robustness under high-dimensional conditions.

Discussion on CNN-GBM performance under low-data regimes and comparison with lightweight and transfer learning approaches

Under low-data regimes, model generalization and robustness become critical challenges, particularly for malware detection systems that often operate with limited labeled samples. Although lightweight models and transfer learning–based approaches are commonly adopted to reduce computational overhead and mitigate data scarcity, the experimental results in Categories A, B, and C demonstrate that the proposed CNN-GBM model consistently achieves superior performance even without reliance on pretrained models or aggressive architectural simplifications.

Across both static and dynamic feature analyses, CNN-GBM outperformed CNN-embedded lightweight classifiers such as KNN, SVM, and Naïve Bayes. These models, while computationally efficient, exhibited limited representation capacity and weaker generalization, particularly in static feature analysis where average accuracies ranged between 66.5% and 68.6%, compared to 71.9% achieved by CNN-GBM (Table 4). This performance gap highlights the advantage of hierarchical feature learning through CNN layers, followed by Gradient Boosting Machine refinement, which effectively captures complex malware patterns even when training data is limited.

Similarly, in dynamic feature analysis, CNN-GBM achieved an average accuracy of 96.6% and an AUC of 0.987 (Table 9), outperforming both lightweight CNN-based models and the Random Forest–MLP approach25. Lightweight classifiers embedded with CNN showed improved results over static analysis but still lagged behind CNN-GBM, indicating that reduced model complexity alone does not guarantee optimal performance under constrained data conditions.

While transfer learning–based models typically leverage pretrained knowledge to compensate for data scarcity, the comparative analysis in Category C demonstrates that CNN-GBM achieves competitive or superior performance relative to existing deep learning–based approaches that implicitly rely on large-scale training or feature reuse. The proposed method attained higher accuracy, lower false positive and false negative rates, and improved generalization without dependence on external pretrained datasets. This suggests that entropy-driven feature selection combined with CNN-based hierarchical abstraction and GBM optimization provides an effective alternative to transfer learning in low-data malware detection scenarios.

Overall, the results indicate that proposed CNN-GBM strikes a favorable balance between model complexity and data efficiency. By reducing feature dimensionality through entropy-based selection and enhancing decision boundaries via gradient boosting, CNN-GBM maintains strong generalization capabilities and robustness under limited training data, outperforming both lightweight and transfer learning–based approaches across multiple evaluation metrics.

Conclusion

This research work has made significant contributions to addressing key challenges faced by current deep learning-based techniques in malware detection. The improvements in the false-positive rate have effectively narrowed the persistent gap among existing techniques as shown in Fig. 4. Additionally, the enhancement of the runtime rate has alleviated the computational burden on resource-constrained devices, particularly Android mobile devices. These contributions collectively enhance the effectiveness and efficiency of malware detection, ultimately advancing the field of cybersecurity. This stems from modified system call via similarity calculation, which optimizes the convolutional network with gradient boosting machine at the malware detection phase, on Android application sets when compared with other recent deep-based learning detection techniques. Its performance was compared with that of commonly used machine learning methods, and the result verified its superiority on all performance metrics considered. Though the outcome is promising, future research should focus more on improving the data engineering phase by improving the feature ranking and feature selection techniques, which can ease the work of the classifiers. This can be done by integrating feature selection or feature ranking techniques.

The proposed CNN-GBM technique proffered a robust defense mechanism, however, its performance is suboptimal when confronted with small datasets. This is primarily due to the sophisticated nature of the CNNs utilized in GBM, which require ample data for effective training. In the case of small datasets, the model may exhibit either overfitting or underfitting, leading to inadequate generalization when presented with new data.
