Efficiently Constructing Sparse Navigable Graphs
Alex Conway, Laxman Dhulipala, Martin Farach-Colton, Rob Johnson, Ben Landrum, Christopher Musco, Yarin Shechter, Torsten Suel, Richard Wen

Abstract
Graph-based nearest neighbor search methods have seen a surge of popularity in recent years, offering state-of-the-art performance across a wide variety of applications. Central to these methods is the task of constructing a sparse navigable search graph for a given dataset endowed with a distance function. Unfortunately, doing so is computationally expensive, so heuristics are universally used in practice. In this work, we initiate the study of fast algorithms with provable guarantees for search graph construction. For a dataset with n n data points, the problem of constructing an optimally sparse navigable graph can be framed as n n separate but highly correlated minimum set cover instances. This yields a naive O ⁡ ( n 3 ) O(n^{3}) time greedy algorithm that returns a navigable graph whose sparsity is at most O ⁡ ( log ⁡ n ) O(\log n) higher than optimal. We improve significantly on this baseline, taking advantage of correlation between the set cover instances to leverage techniques from streaming and sublinear-time set cover algorithms. Combined with problem-specific pre-processing techniques, we present an O ~ ​ ( n 2 ) \tilde{O}(n^{2}) time algorithm for constructing an O ⁡ ( log ⁡ n ) O(\log n) -approximate sparsest navigable graph under any distance function. The runtime of our method is optimal up to logarithmic factors under the Strong Exponential Time Hypothesis via a reduction from the Monochromatic Closest Pair problem. Moreover, we prove that, as with general set cover, obtaining better than an O ⁡ ( log ⁡ n ) O(\log n) -approximation is NP-hard, despite the significant additional structure present in the navigable graph problem. Finally, we show that our techniques can also beat cubic time for the closely related and practically important problems of constructing α \alpha -shortcut reachable and τ \tau -monotonic graphs, which are also used for nearest neighbor search. For such graphs, we obtain O ~ ​ ( n 2.5 ) \tilde{O}(n^{2.5}) time or better algorithms.

1.2
Efficient Graph Construction

Despite the interest in navigability and its practical importance, surprisingly no prior work has addressed one of the most basic algorithmic questions to ask about the property:

How efficiently can one compute the
sparsest navigable graph
for a point set
P

Note that “sparsest” can be defined in multiple ways: we could ask to minimize maximum degree or average degree. As will become clear in

Current graph-based nearest neighbor search methods universally employ heuristics that tend to construct “almost” navigable graphs
[
18

[

[

21

47

Recent work by Diwan et al. shows that

n

[

[

]

2.1
Sparsest Navigable Graph as Minimum Set Cover.

As a starting point towards understanding better algorithms, we first observe that constructing a navigable graph amounts to solving
n
separate
minimum set cover instances
, one for each node. For the instance corresponding to node
p_{i}
, the elements that need to be covered are all other points
p_{j}

.
We also have one set,

S_{i\rightarrow k}
contains any point

such that

, we need to have an edge from
p_{i}
either directly to
p_{j}
, or to some node that gets us closer. Choosing the smallest number of sets that covers all elements amounts to choosing the smallest number of out-edges for
p_{i}
that satisfy the navigability requirements of
Definition

1
. See
Figure

1
for an illustration of the set cover instances.

The set cover formulation reinforces that, while navigability is usually thought of as a “global property” about routing in
G
, it can be viewed as a collection of purely “local” conditions: the out-edges of node
p_{i}
can be chosen optimally without considering out-edges for any other nodes in the graph. Moreover, while we are not aware of any prior work that leverages the connection to set cover,
it leads to an immediate approach to constructing a navigable graph with near minimal sparsity: run any black-box approximation algorithm for set cover instance. The best known approximation ratio of
O(\log n)
can be achieved by the standard greedy algorithm, which can be implemented in time linear in the total size of the sets
[
13
]
.
Implementing this idea naively amounts to
O(n^{2})
time per instance in our setting, for a total complexity of
{O}(n^{3})
time to construct a navigable graph where the degree of every node is at most
O(\log n)
higher than optimal. By simultaneously obtaining near-minimum degree for every node, it follows that the greedy algorithm produces a graph
G
whose maximum and average degree are also no more than
O(\log n)
time more than optimal.

2.2
Algorithmic Techniques

Our algorithm that establishes
Theorem

1
relies on three key ingredients to push beyond the
O(n^{3})
baseline obtained via greedy set cover. These ingredients are summarized below.

Efficient Query Access.
We first observe that, instead of treating navigable graph construction as
n
disjoint set cover instances, we can obtain a faster runtime by taking advantage of the fact that these instances are highly correlated.
Concretely, we can
jointly preprocess
the instances in
O(n^{2}\log n)
time to support natural “query access” to the set cover problem, which obviates the need to explicitly construct each set cover instance (write down each set and its elements), as doing so would already require
O(n^{3})
time.

Specifically, for each point,
p_{i}
, we construct a list of all other points, sorted in increasing order of distance from
p_{i}
. Doing so takes
O(n\log n)
time per data point, so
O(n^{2}\log n)
time total.
From this list, we can immediate answer what is called an “SetOf” query in the literature on sublinear-time set cover algorithms
[
46
,
54
,
27
]
: concretely, for any element
p_{j}
, we can return in
O(1)
time the number of sets
q
that cover the element, and the identity of the
\ell^{\text{th}}
set covering
p_{j}
for any
\ell\leq q
.
To do so, we simply look at the sorted list corresponding to the point
p_{j}
.
The number of points before
p_{i}
in
p_{j}
’s list is
q
, as this is the number of points
k
for which
d(p_{k},p_{j})<d(p_{i},p_{j})
.
Moreover, the
\ell^{\text{th}}
set that covers
p_{j}
in the set cover instance corresponding to node
p_{i}
is simply the set corresponding to the
\ell^{\text{th}}
element of the list.
In addition to SetOf queries, presorting our data also allows us to easily answer “Membership” queries in
O(1)
time: to check if
p_{j}\in S_{i\rightarrow k}
, simply check if
p_{k}
precedes
p_{i}
in the sorted list corresponding to
p_{j}
.

With the ability to answer SetOf and Membership queries in
O(1)
time, we can immediately obtain faster algorithms by turning to existing work on sublinear-time set cover algorithms, which assumes similar query access
[
24
,
27
]
. Ultimately, however, we take an approach that differs somewhat from this prior work, yielding a simpler algorithm with sharper bounds. We describe our approach next.

Greedy Simulation.

We take advantage of efficient query access by showing that it is possible to
directly simulate
the natural greedy algorithm for set cover, which repeatedly selects the set that covers the largest number of uncovered elements. In particular, we uniformly sample uncovered points and run SetOf queries to record what sets those points are contained in. Doing so allows us to estimate the number of uncovered elements in any set. These estimates can then be used to choose a near-optimal set at each iteration, yielding the same
O(\log n)
approximation as would be obtained if the truly optimal greedy set was chosen.

This greedy simulation is reminiscent of an approach from Nguyen and Onak
[
46
]
, although the runtime of their method scales exponentially with both the maximum size of any set and the maximum number of sets any element is contained in: in our setting, both of these numbers could be as large as
n
.
Our approach also bears high-level similarity to the sub-linear set cover algorithm of Indyk et al.
[
27
]
, which samples random elements and selects multiple sets at once by finding a near-optimal set cover for those elements.
Their algorithm, however, requires different techniques based on whether
\mathsf{OPT}
is small or large, and uses sampling to obtain smaller sub-problems that are then solved to obtain good coverage for the original problem.

As with the result of
[
27
]
, a key step in making our approach efficient is to start by sampling roughly
\mathsf{OPT}
sets uniformly at random to add to our cover, where
\mathsf{OPT}
is the size of the minimum set cover.
Doing so does not significantly impact our final approximation factor, and ensures that all elements contained in
\gtrsim m/\mathsf{OPT}
sets are covered after this first sampling step (here
m
is the total number of sets, which is
n-1
for the navigability problem).
As a consequence, the cost of recording what sets a randomly sampled element is contained in can be bounded by
\lesssim m/\mathsf{OPT}
instead of the naive
m
.

Altogether, we obtain the following result for general set cover instances, which is proven in
Section

5

Theorem 3

Suppose that we have an unweighted minimum set cover instance with

\tilde{O}\left(\min\left(m+n\cdot\mathsf{OPT},\frac{mn}{\mathsf{OPT}}\right)\right)

for constructing sparse navigable graphs, we take even more advantage of correlations between the
n
set cover instances underlying the problem. As mentioned above, a key step in our efficient set cover routine is adding initial sets uniformly at random. This ensures that all elements that are contained in many sets are covered with high probability. However, for the sparsest navigable graph problem, can exploit even more structure in the underlying problem.
In particular, suppose we add roughly
\mathsf{OPT}^{*}/n
out-edges at random to every vertex in
G
, where
\mathsf{OPT}^{*}
is the total degree of the minimum navigable graph (which can be guessed efficiently using exponential search). Doing so does not impact our
O(\log n)
approximation guarantee for the average degree or maximum degree. However, building on an idea from
[
18
]
, we can show that these random edges cover, with high probability,
all but

O(n^{3}/\mathsf{OPT}^{*})
elements across
all
n
set cover instances
. Recall that each instance originally has
n-1
elements to cover, for a total of
O(n^{2})
elements. Since
OPT^{*}\geq n-1
, random edge sampling thus always reduces the overall number of elements left to cover, and significantly so when
\mathsf{OPT}^{*}
is large (which is exactly the case where where
Corollary

2.1
fails to yield a nearly quadratic time algorithm). We emphasize that this argument does not imply that the cost of solving
every
set cover instance will be reduced, since it is possible that some instances will have very few elements covered during the preprocessing step where random edges are added. The runtime improvement comes from amortizing over all instances.

The above approach nearly yields
Theorem

1
. Indeed, if the optimum degree of every node is roughly the same – i.e.
O(\mathsf{OPT}^{*}/n)
– we obtain a
\tilde{O}(n^{2})
time algorithm. However, when the optimal degrees vary (in the worst case, they could vary by a large amount), we obtain a sub-optimal result.
We deal with this final challenge by introducing an additional preprocessing step – essentially, we group nodes with similar optimum degree together and connect them by a clique.
The effect of doing so is that any
p_{j}
not in the clique is covered in
all but one of the set cover instances corresponding to nodes in the clique
. In particular,
p_{j}
is covered in all instances besides the one corresponding to its nearest neighbor in the clique. We defer details to
Section

4
, but roughly speaking this clique forming techique allows for finer-grained control over the number of uncovered elements in each instance after preprocessing, yielding our final
\tilde{O}(n^{2})
time result.

A side consequence of this final technique is that it actually allows us to prove a slightly tighter existence result for navigable graphs: we show that, for any distance function, any point set in general position admits a navigable graph with
O(n^{3/2})
edges, whereas prior work achieved a bound of
O(n^{3/2}\sqrt{\log n})

[
18
]
. We comment on this finding further in
Section

3
.

3
Preliminaries

Set Cover Notation.

Central to our approach is a set cover formulation of the sparsest navigable graph problem. We begin by reiterating notation introduced in the introduction. Formally, for each point
p_{i}\in P=\{p_{1},\ldots,p_{n}\}
, we have a set cover instance
\mathcal{I}_{i}=(P\setminus\{p_{i}\},\mathcal{F}_{i})
with elements
P\setminus\{p_{i}\}
and sets
\mathcal{F}_{i}=\{S_{i\rightarrow k}:k\neq i\}
, where the set
S_{i\rightarrow k}
contains all
p_{j}\in P\setminus\{p_{i}\}
such that
d(p_{j},p_{k})<d(p_{j},p_{i})
.

Our solution to the set cover instances will be a set of out-neighborhoods
N_{1},\ldots,N_{n}
, one for each point. If
p_{k}\in N_{i}
this indicates that set
S_{i\rightarrow k}
was selected in our solution to
\mathcal{I}_{i}
. These neighborhoods comprise our final navigable graph,
G
. We let
\mathsf{OPT}_{i}
denote the minimum size solution to set cover instance
\mathcal{I}_{i}
and
\mathsf{OPT}^{*}=\sum_{i=1}^{n}OPT_{i}
denote the minimum number of edges in a navigable graph for point set
P
.

Distance Functions.
As discussed, our algorithms work with any distance function
d
, where we define:

Definition 2

(Distance Function)
.

A
distance function

d:P\times P\rightarrow\mathbb{R}^{\geq 0}
for a point set
P=\{p_{1},\ldots,p_{n}\}
is any function such that
d(p_{i},p_{i})=0
for all
i
and
d(p_{j},p_{i})=d(p_{i},p_{j})>0
for all
j\neq i
.

Importantly, we do not require triangle inequality.
Throughout, we make the mild assumption that the point set
P
is in “general position” meaning that 1) it contains no repeated data points and 2) for all
i,j,k
,
d(p_{i},p_{j})\neq d(p_{i},p_{k})
. These conditions are essentially always true in practice, or can be ensured by adding arbitrarily small random perturbations to our data. While the assumption of general position is not strictly necessary, it has been made in prior work (see, e.g.,
[
1
]
) as it greatly simplifies the definition of navigability. In particular, our
Definition

1
only captures the more usual definition of navigability (that greedy search always converges for a query
q\in P
) if there is a strict ordering on the distances
d(p_{i},p_{1}),\ldots,d(p_{i},p_{n})
. Otherwise “greedy search” is not well-defined unless we introduced a tie-breaking rule that determines where to move if two neighbors are equally close to a given query. Avoiding the notation and corner-casing required to handle tie-breaking simplifies the presentation of our results.

Other Notation.
Throughout, we use “with high probability” to mean with probability
1-1/n^{c}
for an arbitrarily large constant
c
(the specific choice of which will impact other constant terms in the statement).

3.1
The Distance-Based Permutation Matrix and Fast Query Access

As in recent work on existential results for navigability
[
18
]
, it will be helpful to think about our navigability problem as represented in a “distance-based permutation matrix”,
\Pi
. In particular,
\Pi
has
n
rows and
n

sorted in increasing order of their distance from

. See
Figure

2

\Pi

[p_{1},p_{5},p_{4},p_{6},p_{3}]

The

sorted in increasing order of their distance from

. Importantly, this matrix can be used to quickly identify what sets a node

. In particular, if

Given a set of

Proof.

3.2
Pre-processing via Random Edges and Arbitrary Cliques

As discussed in
Section

2.2
, a key component of our algorithm is to reduce the cost of running a greedy set cover method by “pre-processing” the navigability problem by adding a small number of less carefully chosen edges that nevertheless aid in covering many elements. We do so in two ways: by adding random edges and adding random cliques. We discuss basic properties of these strategies below.

3.2.1
The Power of Random Edges

A first observation, which is standard in prior work on sublinear time set cover
[
27
]
, is that, by adding random sets to the instances
\mathcal{I}_{1},\ldots,\mathcal{I}_{n}
, we can cover all elements that are contained in many sets, with high probability. In our setting, this corresponds to adding random out-neighbors to each node
i
. In particular, we will utilize the following basic claim:

Claim 3.2
.

Suppose we add
\beta
sets,
R_{1},\ldots,R_{\beta}
, uniformly at random to our solution,
N_{i}
, for set cover instance
\mathcal{I}_{i}
. I.e., we choose
\beta
out-neighbors for
i
, without replacement. Then for any
p_{j}
contained in
\geq c\log(n)\cdot\frac{n}{\beta}
sets
S_{i\rightarrow k}
for
k\neq i
, we have that
p_{j}\in R_{1}\cup\ldots\cup R_{\beta}
with probability
>1-1/n^{c}
.

Proof.

We can assume
R_{1},\ldots,R_{\beta}
are drawn with replacement, as the probability that
p_{j}
is covered is only higher if they are drawn without replacement.
Since
p_{j}
is contained in
z\geq cn/\beta
sets, for any
\ell
,
\Pr[j\in R_{\ell}]=\frac{z}{n-1}
. Accordingly, we can bound:

\displaystyle\Pr[p_{j}\notin R_{1}\cup\ldots,R_{\beta}]\leq\left(1-\frac{z}{n-1}\right)^{\beta}<\left(1-\frac{c\log n}{\beta}\right)^{\beta}\leq\left(\frac{1}{e}\right)^{c\log n}=\frac{1}{n^{c}}.

An implication of
3.2
is that, if we add
\beta={O}(\mathsf{OPT}^{*}\log(n)/n)
random edges to every node in our navigable graph, where we recall that
\mathsf{OPT}^{*}
is the fewest number of edges in a navigable graph for
P
, then, with high probability, for all instances
\mathcal{I}_{i}
, the only elements remaining to be covered are contained in
\leq n^{2}/OPT^{*}
sets. This property will be critical in our efficient simulation of the greedy set cover algorithm, which requires sampling a random uncovered element and recording all sets it is contained in.

Moreover, due the additional structure of the navigable graph problem, adding random sets actually guarantees an another property that does not hold for arbitrary collections of set cover instances:

Corollary 3.3
.

Suppose that, as in
3.2
, we add
\beta
sets,
R_{1},\ldots,R_{\beta}
, uniformly at random to our solution,
N_{i}
, for set cover instance
\mathcal{I}_{i}
. For all
i
, let
U_{i}
contain all
p_{j}
such that
p_{j}\notin R_{1}\cup\ldots,\cup R_{\beta}
. I.e,
U_{i}
is the set of uncovered elements after adding
\beta
random edges to
p_{i}
. Then with probability
>1-1/n^{c-2}
,

\displaystyle\sum_{i=1}^{n}|U_{i}|<c\log n\cdot\frac{n^{2}}{\beta}.

In particular, if we choose
\beta={O}(\mathsf{OPT}^{*}\log(n)/n)
, then we have at most
\leq n^{3}/OPT^{*}
elements remaining to be covered across all set cover instances after adding the random edges.

Proof.

By
3.2
and a union bound, we have that, simultaneously for all
i
, all
p_{j}
contained in
\geq c\log(n)\cdot\frac{n}{\beta}
sets in
\mathcal{I}_{i}
are in
R_{1}\cup\ldots,\cup R_{\beta}
. So
|U_{i}|
only contains elements
p_{j}
contained in
<c\log(n)\cdot\frac{n}{\beta}
sets. Referring to the distance-based permutation matrix, we notice that there are exactly
n\times\left(c\log(n)\cdot\frac{n}{\beta}-2\right)
such elements across all instances: in particular, these elements are exactly those contained in columns proceeding column
c\log(n)\cdot\frac{n}{\beta}
in the matrix (and excluding column one). It follows that
\sum_{i=1}^{n}|U_{i}|<c\log n\cdot\frac{n^{2}}{\beta}.

∎

3.2.2
The Power of Cliques

Interestingly, a result similar to
Corollary

3.3
can be obtained without randomness, but rather by adding arbitrary cliques to our search graph. In particular, we can argue that, if we add a clique over a subset of nodes,
Q
, then the total number of uncovered elements across all
\mathcal{I}_{i},p_{i}\in Q
is bounded. Formally, we have:

Claim 3.4
.

Suppose we select a subset of points
Q\subset P
and add a clique over those points to
G
. I.e., for each
i\in{Q}
, we add
Q\setminus p_{i}
to
p_{i}
’s out-neighborhood,
N_{i}
. Then for any
p_{j}\notin Q
, for all but possibly a single
p_{i}\in Q
,
p_{j}\in{S}_{i\rightarrow k}
for some
p_{k}\in N_{i}
. I.e.,
p_{j}
is covered in all set cover instances corresponding to nodes in the clique, except one. It follows that, if
U_{i}
contains all
p_{j}
not covered in instance
\mathcal{I}_{i}
by edges in
G
, then:

\displaystyle\sum_{i\in Q}|U_{i}|\leq n-|Q|.

Proof.

The proof is immediate: let
p_{\ell}=\argmin_{p_{i}\in Q}d(p_{i},p_{j})
. For all other
p_{i}\in Q
, we have that
p_{j}
is contained in
S_{i\rightarrow\ell}
, which we added when forming the clique. So
p_{j}
can only be uncovered in instance
\mathcal{I}_{\ell}
. There are
n-|Q|
points not in the clique, hence at most
n-|Q|
uncovered elements across all instances.
∎

An immediate consequence of
3.4
is that, if we partition our points into
n^{2}/\mathsf{OPT}^{*}
sets of size
\mathsf{OPT}^{*}/n
, and add a clique for each of those sets, then we only add
O(\mathsf{OPT}^{*})
edges to the graph (specifically,
\mathsf{OPT}^{*}/n-1
for each node), but cover all but
(n-|Q|)\cdot n^{2}/\mathsf{OPT}^{*}<n^{3}/\mathsf{OPT}^{*}
elements across all
n
set cover instances. This matches what was obtained above for random edge deletions. We will use a slightly finer-grained version of the statement in our proof of
Theorem

1
in
Section

4
.

Figure 3:
A partial illustration of the graph construction used to prove
Theorem

4
. We begin by partitional our points into
O(\sqrt{n})
arbitrary groups of size
O(\sqrt{n})
. An example group,

, is illustrated in green. We connect all points in
Q
via a clique and for every point
p_{j}\notin Q
, we draw and edge from
p_{j}

p_{j}
. By
3.4
, this yields a navigable graph. The total number of edges is
O(n^{3/2})
.

While a very simple observation, the argument above can actually be used to tighten the best previous upper bound of
2n^{3/2}\sqrt{\ln n}
on the number of edges in the minimum navigable graph for an arbitrary distance function and point set (in general position)
[
18
]
. In particular, simply partition our points into
\lceil\sqrt{n}\rceil
arbitrary sets of size
\leq\sqrt{n}
. For each set
Q
, add a clique between the nodes in that set. For any
p_{j}\notin Q
, add an edge from
p_{\ell}=\argmin_{p_{i}\in Q}d(p_{i},p_{j})
.
This yields a navigable graph, and we add at most
|Q|(|Q|-1)+n-|Q|=|Q|^{2}+n-2|Q|
edges per set, for a total of
\left(2n-2\sqrt{n}\right)\cdot\sqrt{n}
edges when

is a perfect square. It can be verified that essentially the same bound holds when
n
is not a perfect square, yielding:

Theorem 4
.

There is a deterministic algorithm that, given any point set
P
of size
n
and distance function
d
, constructs a navigable graph on
P
with at most
2n^{3/2}-n
edges in
O(n^{2})
time.

4
Quadratic Time Minimum Navigable Graphs

In this section, we prove
Theorem

1
by presenting an algorithm that returns an

-approximation to the minimum navigable graph for any set of

4.1
Minimum Neighborhood Cover Subroutine

We begin by presenting our core routine for simulating the greedy set cover algorithm on any set cover instance

Theorem 5
.

There is an algorithm (

NGCover
works by initializing an empty set cover

and incrementally adding certain choices of
S_{i\to j}
. In order to obtain as small a cover as possible,
NGCover
tries to greedily add the choices of
S_{i\to j}
that cover the most uncovered points. Formally, given the current state of
C
,
NGCover
tries to add to
C
the set
S_{i\to j}
that maximizes
|S_{i\to j}\cap(U\setminus\bigcup_{p_{c}\in C}S_{i\to c})|
. This is a well-known strategy for approximating minimum set covers, but maintaining the structures that allow for this selection can be expensive. Moreover, we do not have explicit access to the sets themselves, nor even their sizes. Our approach is to randomly sample “voters” from among all uncovered points. Each voter votes for all sets containing it. Through this voting process, we hope to find sets that contain close to the maximum number of uncovered points. It is easy to show, as we do in Claim
4.4
, that doing so suffices to obtain the desired
O(\log n)

We start by briefly explaining the structures we use to maintain the votes. As explained above,
C
holds all sets added to the cover thusfar.

represents the set of
nominees
, i.e., all uncovered points that are not yet voters. We randomly sample new voters from this set.

represents the pool of active

is an array of sets, each corresponding to all active voters in

that voted for a given set. That is,
votes[j]=V\cap S_{i\to j}
.

To select a set with high coverage, we sample a point from
N
, move it to
V
, and have it vote once for every set which contains it: these sets can be efficiently obtained via
\mathrm{SetOf}

The number of voters we need to sample in order for this to be a likely event depends on the amount of coverage these sets offer, so rather than choose a fixed number of samples, we instead sample points until some set reaches a certain threshold of votes, specifically on the order of
O(\log n)
. Once a set obtains sufficient votes, we are confident that it has high coverage and subsequently add it to
C
. We also update our set of uncovered nominees, scanning through

and removing any covered by the chosen set.

We repeatedly use the voting strategy to add large sets to

. However, rather than restart the voting from scratch each time we choose a set
S_{i\to j}
, which would be costly, we instead continue from the current state, keeping all votes that were previously cast, except those case by voters that are now covered. These are easy to obtain, since all of them would have voted for

. Thus, by maintaining for each set a list of all voters who voted for it, we can efficiently find such voters and remove any votes cast for other sets.

We continue this process until only a small number of uncovered points remain. Specifically, we sample voters
without replacement
during the voting process, and we stop once there are no more voters to be sampled. At this point, there may still be active voters in

whose sets never received enough votes to be chosen. We finish by explicitly covering each of these voters with one set each. That is, for each
p_{k}
yet to be covered, we add
S_{i\to k}
to
C
, which trivially covers
p_{k}
.

4.3
Sparsest Navigable Graph Construction in
\tilde{O}(n^{2})

We now present our approach to proving the main positive result of this paper,
Theorem

1

To make the jump from
\tilde{O}(n^{2.5})
to
\tilde{O}(n^{2})
, we make two major additions to the algorithm. Both assume rough knowledge of the number of edges
\mathsf{OPT}{}^{*}
of the minimum navigable graph. In order to get access to this information, we execute an exponential search strategy in which we run the entire algorithm in a loop. We begin with a guess
\ell^{*}=n
and run the remainder of the algorithm with that guess. We realize that our guess is wrong if the number of edges we add to the graph ends up exceeding
\ell^{*}
by a large amount. In response, we terminate the algorithm, double
\ell^{*}
, and restart.

Given an estimate
\ell^{*}
of
\mathsf{OPT}{}^{*}
, we make the two following additions to our algorithm:

•

We prepend the algorithm by adding
(\ell^{*}/n)\log(n)
random edges to each point, then filtering out any points that those edges cover. This covers many points across all set cover instances, in particular those contained in many sets, which would otherwise cast many votes in
NGCover
.

•

We estimate the local
\mathsf{OPT}{}_{i}
’s of each set cover instance, then combine instances with similar
\mathsf{OPT}{}_{i}
’s in cliques. This limits the number of set cover instances that have both high
\mathsf{OPT}{}_{i}
and a large number of points to cover, which are the most expensive instances for our algorithm.

4.3.1
Random edges and cliques

Suppose we have a guess
\ell^{*}
of
\mathsf{OPT}{}^{*}
satisfying
\ell^{*}\leq c\mathsf{OPT}{}^{*}
for some constant
c
. Then we can add
(\ell^{*}/n)\log n
random out-neighbors to each point without violating the guarantee of an
O(\log n)
-approximation on the total number of edges in the graph (and the maximum degree, since the average degree cannot exceed the maximum degree). In return, across all set cover instances
\mathcal{I}_{i}
, we cover any points
p_{k}
contained in a large number of sets
S_{i\to j}
with high probability.

We showed in
3.2
that when adding
(\ell^{*}/n)\ln n
random sets to a set cover instance
\mathcal{I}_{i}
, any point still uncovered is contained in
\leq n^{2}/\ell^{*}
sets with high probability. We now show that after adding these random edges to each instance, we can efficiently find the set of points
U_{i}
that remain uncovered.

Claim 4.9
.

If

Proof.

Recall from

We now iterate over all
n^{2}
pairs
i,p_{k}
, checking for each pair the number of sets
S_{i\to j}
containing
p_{k}
.
If this frequency is at least
n^{2}/\ell^{*}
, then
p_{k}
is covered in
\mathcal{I}_{i}
with high probability by
3.2
.
Otherwise, we simply iterate over each
p_{r}\in R_{i}
, of which there are at most
(\ell^{*}/n)\ln n
, and check if any of them contain
p_{k}
in
O((\ell^{*}/n)\ln n)
time. If so, then
p_{k}
is covered in
\mathcal{I}_{i}
; otherwise, it is not.
By
Corollary

3.3
,
p_{k}
is less than
n^{2}/\ell^{*}
in instance
i
for at most
n^{3}/\ell^{*}
pairs
i,p_{k}
.
Thus, the total time taken by this procedure is
O(n^{2}\log n)
to preprocess
P
,
O(n^{2})
to filter out points with high frequency, and
O((n^{3}/\ell^{*})(\ell^{*}/n)\log n)=O(n^{2}\log n)
to filter out covered points with low frequency, for a total of
O(n^{2}\log n)
.
∎

Claim 4.10
.

If
R\subseteq P
is a random sample of size
\beta
, and
p_{i}\in P
, then running
NGCover
on point
p_{i}
with size limit
\ell
to cover
U_{i}=P\setminus\{p_{i}\}\setminus\bigcup_{p_{r}\in R}S_{i\to r}
takes
\tilde{O}((n/\beta+|U|)\min(\ell,\mathsf{OPT}{}_{i}))
time.

Proof.

By
3.2
, any point in set cover instance

with frequency
\geq\frac{cn}{\beta}\log n
is contained in
S_{i\to r}
for some
p_{r}\in R
, and thereby not in
U
, with probability
>1-1/n^{c}
. By union bound, the maximum frequency

of any point in
U
is at most
\frac{cn}{\beta}\log n
with probability
>1-1/n^{c-1}
.
By
Lemma

,
NGCover
runs in

\displaystyle O(f\min(\mathsf{OPT}{}_{i},\ell)\log^{2}n+|U|\min(\ell,\mathsf{OPT}{}_{i}))

\displaystyle\leq O((n/\beta)\min(\mathsf{OPT}{}_{i},\ell)\log^{3}n+|U|\min(\ell,\mathsf{OPT}{}_{i}))

\displaystyle=\tilde{O}((n/\beta+|U|)\min(\ell,\mathsf{OPT}{}_{i}))

time with probability
>1-1/n^{c-1}
.
∎

In fact, it can be shown that modifying Algorithm
2
by estimating
\mathsf{OPT}{}^{*}
through exponential search and adding roughly
(\mathsf{OPT}{}^{*}/n)\log n
random neighbors to each point is already enough to bound the time to construct an approximate minimum navigable graph to
\tilde{O}(n^{2.25})
. However, we omit that proof here in favor of the full
\tilde{O}(n^{2})
bound.

Of the two terms in the running time of
4.10
, the first term
(n/\beta)\min(\ell,\mathsf{OPT}{}_{i})
is actually sufficient to achieve an
\tilde{O}(n^{2})
time navigable graph construction, as we will show later. That is, the only bottleneck remaining is the
|U|\min(\ell,\mathsf{OPT}{}_{i})
term, coming from the cost of eliminating covered points from
N
upon adding a set to the cover. Let us illustrate the issue with this term and why it prevents our algorithm as described so far from running in
\tilde{O}(n^{2})
time.

Note that if
\ell
is set high enough such that
NGCover
returns a cover of
U
, then this term amounts to
O(|U|\mathsf{OPT}{}_{i})
, contributing
O(\sum_{p_{i}\in P}|P\setminus\{p_{i}\}\setminus\bigcup_{p_{r}\in R_{i}}S_{i\to r}|\cdot\mathsf{OPT}{}_{i})
total time to the full graph construction algorithm for randomly-chosen sets
R_{1},\dots,R_{n}
. If the random sets are able to eliminate a similar number of points per instance, or if
\mathsf{OPT}{}_{i}
is similar across all instances, then
Corollary

3.3
implies an
\tilde{O}(n^{2})
running time. However, this may not always be the case, depending on the point set. For a particular
i
, if
R_{i}
is unable to cover a large number of points in instance
i
(because they might all be highly selective, that is, each one is contained in a small number of sets), and
\mathsf{OPT}{}_{i}
is large, then the product
|P\setminus\{p_{i}\}\setminus\bigcup_{p_{r}\in R_{i}}S_{i\to r}|\cdot\mathsf{OPT}{}_{i}
will be large. For example, suppose almost all (i.e.
\Omega(n)
) points remain uncovered in instance
i
after adding random edges. Suppose also that it requires a large number of sets (e.g.
\Omega(\sqrt{n})
) to cover those uncovered points. Then it would take
\Omega(n^{3/2})
time to solve such a set cover instance. It can in fact be shown that there exist simple point sets that with high probability induce
\Omega(n^{5/8})
such set cover instances, resulting in
\Omega(n^{17/8})
time navigable graph construction.

Thus, for our algorithm to run in
\tilde{O}(n^{2})
time, we need to bound the number of instances that simultaneously have large solutions and many points to cover after the addition of random edges. We now explain how we accomplish this.

As the final addition to the algorithm, we use the tool we introduced in Section
3.2.2
of forming cliques in the graph. Cliques, like random edges, allow us to cover many points across set cover instances prior to running
NGCover
. However, unlike random edges, cliques allow us to coordinate how this coverage jointly affects several targeted instances together.

Like with random edges, suppose we have a guess
\ell^{*}\leq c\mathsf{OPT}{}^{*}
for some constant
c
. Then if we randomly partition points into groups of size
(\ell^{*}/n)\log n
and build cliques over each partition, we do not violate an
O(\log n)
approximation on the minimum number of edges. In short, the intuition behind our approach with cliques is to estimate the
\mathsf{OPT}{}_{i}
for each instance, group together instances with similar
\mathsf{OPT}{}_{i}
’s, and form cliques from the groups. This addresses the issue discussed in the previous section by covering many points across the instances with highest
\mathsf{OPT}{}_{i}
.

5
Sublinear Set Cover Algorithms

In this section we extend the results from Section
4
to the setting of sublinear set cover algorithms.
In particular, we provide proofs for Theorem
3
and Corollary
2.1
.
We note here as in Section
2.2
that there are similar results existing in the literature, some of which can be modified to achieve the same bounds as Theorem
3
, but our results use completely different techniques.
The problem of finding a minimum set cover is a classic
NP-Complete
problem that has been studied in a variety of settings.
The input to a set cover problem includes a
set system
, which is a pair
(U=\{e_{1},...,e_{n}\},\mathcal{F}=\{S_{1},...,S_{m}\})
where each
S_{i}\subseteq U
.
The output to the minimum set cover problem is a minimum subset of
\mathcal{F}
which includes a set covering each
e_{i}\in U
.
While set cover is
NP-Complete
, the greedy algorithm which chooses the set covering the maximum number of remaining elements, is a
O(\log n)
approximation which runs in
O\left(\sum_{i=1}^{m}\left|S_{i}\right|\right)
time.
Unless
\textsc{P}=\textsc{NP}
, this is essentially the best possible approximation ratio for a polynomial-time algorithm
[
17
]
.
Our results are in a sublinear model of the problem, where we do not explicitly interact with
U
and
\mathcal{F}
, but rather through specific queries which we assume can be performed in constant time.
Specifically, our results will use the
\mathrm{SetOf}
query described in Section
3
, which returns for a given element
e\in U
all sets in
\mathcal{F}
containing
e
. In addition, we use the related
\mathrm{EltOf}
query, which returns for a given set
S\in\mathcal{F}
all elements contained in
S
.
As in the data structure in
3.1
, we can also support the
\mathrm{FreqOf}
query with
O(n\log n)
preprocessing.
The primary goal of this section is to describe sublinear set-cover algorithms for
Theorem

3
.
We start with an emulation of the greedy algorithm in the sublinear model, then progressively modify it to achieve two algorithms which will together satisfy the theorem.

We first present an implementation of the classical greedy algorithm in the sublinear model,

The algorithm emulates the greedy algorithm in the standard model and therefore obtains the same approximation ratio.
We use a standard binary heap with

The running time is determined by the time spent performing heap operations, as all other costs are linear in

The algorithm performs at most

For each set

Thus, the total number of decrease key operations is bounded by

The total running time is therefore bounded by

∎

5.2
The voting algorithm

As in
Algorithm

1
, the first approach to improving the run time of the greedy algorithm is to approximate the greedy choice made at each step by using voting.
To do this, the algorithm samples a random element from the pool of unsampled uncovered elements (prospective voters),
N
, which then votes for all sets it is an element of.
The element is added to the set of active voters,
V
.
Whenever a set reaches a logarithmic number of votes, the algorithm chooses it as the next set, which involves enumerating all of its elements using membership queries, removing them from
P
and
V
, as well as removing any votes they may have cast.
This process continues until
N
is empty, at which point the set of uncovered elements is

, so the residual instance is relatively small, and we can just use the greedy algorithm.

5.2.1
Bounding the approximation ratio.

The key difference between the voting algorithm and the greedy algorithm is that the voting algorithm approximates the largest sets at each step.
Therefore, the key thing to prove in order to bound the approximation ratio is that these approximations are sufficient. We begin by observing that
Algorithm

5
maintains the following invariants:

Claim 5.3
.

The main while loop in ConstructVoteCover maintains the following invariants:

1.

N\sqcup V=U_{\overline{C}}
,

2.

V
is a set of random, uniformly distributed elements in
U_{\overline{C}}
,

3.

For every set
S
:
v(S)=\lvert V\cap S_{\overline{C}}\rvert
, and

4.

For every set
S
:
v(S)\leq 100(\log(m)+\log(n))
.

Next we show that the set chosen at each step is the largest set up to constant factors with high probability.

Lemma 5.4
.

With probability at least
1-\frac{1}{m^{28}\cdot n^{28}}
, in every call to
\mathrm{AddSet}(S)
,
S_{\overline{C}}
is approximately the largest set in
\mathcal{F}_{\overline{C}}
, more specifically:

\forall S^{\prime}\in F\setminus C:\lvert S_{\overline{C}}|\geq\frac{1}{8}\cdot\lvert S^{\prime}_{\overline{C}}\rvert

Proof.

It suffices to bound the probability that at some point in the execution there exists a pair
S,S^{\prime}\in\mathcal{F}\setminus C
such that
v(S)=100(\log(m)+\log(n))
and
\lvert S_{\overline{C}}|<\frac{1}{8}\cdot\lvert S^{\prime}_{\overline{C}}\rvert
.
Assume that during the execution of the algorithm, such a pair exists.
By
5.3
,
v(S^{\prime})\leq 100(\log(m)+\log(n))
which in turn implies,
\lvert V\cap S_{\overline{C}}\rvert\geq 100\cdot(\log(m)+\log(n))
while
\lvert V\cap S_{\overline{C}}^{\prime}\rvert\leq 100(\log(m)+\log(n))
.
Because
V
is uniformly random over
U_{\overline{C}}
, we can apply a standard Chernoff bound to conclude the probability of
\lvert V\cap S_{\overline{C}}\rvert
exceeding
100\cdot(\log(m)+\log(n))
is at most
\frac{1}{m^{30}\cdot n^{30}}
.
∎

We now can use this to bound the number of sets added in the main loop.

Lemma 5.5
.

With probability at least
1-\frac{1}{m^{28}\cdot{n^{28}}}
, the algorithm calls
\mathrm{AddSet}(S)
at most
O(\mathsf{OPT}\cdot\log(n))
times.

Proof.

Consider some optimal solution
\mathcal{F}^{\prime}\subseteq\mathcal{F}
to the input set cover instance, and denote its size by
\mathsf{OPT}
.
Note that for every subset
U^{\prime}\subseteq U
, since
\mathcal{F}^{\prime}

S^{\prime}\in\mathcal{F^{\prime}}
that covers a
\frac{1}{\mathsf{OPT}}
-fraction of all elements in
U^{\prime}
.
Consider a call to
\mathrm{AddSet}(S)
: We know that there exists some set in
S^{\prime}\in\mathcal{F^{\prime}}
that covers a
\frac{1}{\mathsf{OPT}}
fraction of all elements in

, meaning
\lvert S^{\prime}_{\overline{C}}\rvert\geq\frac{1}{\mathsf{OPT}}\cdot\lvert U_{\overline{C}}\rvert

Note that

since for every set in
A\in C
we have
A\cap U_{\overline{C}}=\emptyset
.
By
Lemma

5.4
, with probability of at least
\frac{1}{m^{28}\cdot n^{28}}

.
So each call to

Therefore, at most
8\ln{n}\cdot\mathsf{OPT}

∎

Finally, we observe that the call to the greedy algorithm cannot add more then
\ln(n)\cdot\mathsf{OPT}
sets, so we have:

Claim 5.6
.

With probability at least
1-\frac{1}{m^{28}\cdot{n^{28}}}
,
Algorithm

returns a
9\ln(n)
-approximate minimum set cover.

Running time analysis.

To analyze the running time, we first observe that there are three non-linear costs to the algorithm: managing votes, enumerating added sets, and executing the greedy algorithm on any remaining elements. We start by analyzing the cost of managing votes.

Claim 5.7
.

There are at most
\mathsf{OPT}\cdot 100(\log(m)+\log(n))

after the main while loop terminates.

Proof.

We know from

.
As in the proof of

∎

Claim 5.8
.

With probability at least
1-\frac{1}{m^{28}\cdot{n^{28}}}
, the cost of managing votes is at most

O\left(f\cdot(\log(m)+\log(n))\cdot\mathsf{OPT}\cdot\log(n)\right).

Proof.

An element is added to

at most once, and either is present at the end of the loop or removed during a call to

By

Each call to

So, the total number of elements added to

Each element added/removed from

∎

We now bound the total cost of the algorithm.

Lemma 5.9
.

With probability at least
1-\frac{1}{m^{28}\cdot n^{28}}

O(m+n+\mathsf{OPT}\cdot\log(n)\cdot(f\cdot(\log(m)+\log(n))+\Delta)),

and

Proof.

Observe that aside from costs linear in

By

∎

5.3
Reducing cost by limiting the maximum frequency

The cost of the voting algorithm depends both on
f
, the maximum frequency of an element in
\mathcal{S}_{C}
, and
\Delta
, the maximum size of a set in
\mathcal{S}_{C}
.
In this section, we’ll give an algorithm that limits the effective value of
f
, which in turns reduces the cost.
The key idea is to add
O(\mathsf{OPT}\cdot\log(n))
random sets to the cover.
Then, any element that is a member of at least
\frac{m}{\mathsf{OPT}}
sets will be covered with high probability, which in turn bounds
f
by
\frac{m}{\mathsf{OPT}}
.
The issue is we don’t know what
\mathsf{OPT}
is equal to in advance, so we don’t have a predetermined frequency threshold to enforce.
To overcome this we use exponential search.
We first make a guess
L
for
\mathsf{OPT}
, allowing us to remove all sets that have at least
\frac{m}{L}
elements.
We then run ConstructVoteCover, which is cheaper, because
f
is now small.
If our guess is sufficiently larger than
\mathsf{OPT}
, we show this will return a small set cover.
To deal with the case of our guess being smaller than
\mathsf{OPT}
, we modify ConstructVoteCover to stop early, so that we don’t incur its full running time.
In particular, we stop execution as soon as we add the
(L+1)
th set to the cover; we will refer to this as
\textrm{CVCStopEarly}(U,\mathcal{F},L)
.
The algorithm is given as

First, if we assume the algorithm does not return

Lemma 5.11

With probability at least

By

We know from

Thus the running time is dominated by the calls for

We can union bound over all of these calls, to conclude that with probability at least

We can therefore conclude a total bound of:

O\left(\sum_{k=\log(\mathsf{OPT})}^{\log(16n\cdot\ln(n))}m+n+\mathsf{OPT}\cdot\log(n)\cdot(f_{k}\cdot(\log(m)+\log(n))+\Delta)\right),

By the criterion the algorithm imposes we have:

\displaystyle O\left(\sum_{k=\log(\mathsf{OPT})}^{\log(16n\ln n)}m\log n(\log m+\log n)^{2}+\mathsf{OPT}\cdot n\log n\right)=O\left(m\log^{2}n(\log m+\log n)^{2}+\mathsf{OPT}\cdot n\log^{2}n\right)

.

5.4
Using lazy enumeration to save cost

We now turn to another way to reduce the cost of the voting algorithm, namely avoiding the expensive enumeration during the
\mathrm{AddSet}
step.
The idea is that rather than marking elements as covered in the CVCStopEarly algorithm, we can instead check whether an element has already been covered during the sampling step (when drawing it from
N
) and remove it then.
This can be achieved using
\mathrm{SetOf}
queries, and testing whether each set the element is a member of is in
C
or not.
We refer to this algorithm as LazyCVCSE and the version of ConstructLimitedVoteCover which uses it as LazyCLVC.
LazyCVCSE is logically equivalent to CVCStopEarly: the only difference is when elements are identified as covered.
Therefore the correctness and approximation ratio properties of
Lemma

5.10
are still satisfied.
Similarly, LazyCLVC satisfies
Lemma

5.11
.

Lemma 5.13
.

The total running time for LazyCVCSE is
O(m+n\cdot f)
where
f
is the maximum frequency of an element in
\mathcal{S}_{C}
.

Proof.

In contrast to the proof of
Lemma

5.9
, the non-linear cost is dominated by the cost of sampling voters (now requiring checking whether they are covered), vote management, and the greedy algorithm at the end.
Note that the cost of
\mathrm{AddSet}
is now constant, since we are no longer enumerating the set.
The cost of checking whether a potential voter has already been covered is at most
f
, since we check whether any of the at most
f
sets it belongs to have been chosen. The cost of vote management is also at most
f
.
So we can bound both of these costs in total by
O(n\cdot f)
.
The cost of executing the greedy algorithm is
\sum_{S\in\mathcal{F\setminus C}}|S_{\overline{C}}|\leq\sum_{e\in U}|\{S\in\mathcal{F}:e\in S\}|\leq O(n\cdot f)
, which completes the proof.
∎

We now prove the following bound on the running time of LazyCLVC:

Lemma 5.14
.

The running time of LazyCLVC is bounded by
O\left(\frac{mn\cdot\log(n)\cdot(\log(m)+\log(n))}{\mathsf{OPT}}\right)=\tilde{O}(mn/\mathsf{OPT})
.

Proof.

As in the analysis of ConstructLimitedVoteCover, the running time is dominated by calls to LazyCVCSE in which
L\geq\mathsf{OPT}
.
We can therefore conclude according to
lemma

5.13
that the running time is bounded by

O\left(\sum_{k=\log(\mathsf{OPT})}^{\log(16n\cdot\ln(n))}m+n\cdot f_{k}\right),

where
f_{k}
is the maximum frequency when
L=2^{k}
.
As before,

f_{k}\leq\frac{100\cdot(\log(m)+\log(n))\cdot m}{L}\leq\frac{100\cdot(\log(m)+\log(n))\cdot m}{\mathsf{OPT}},

so the running time is upper bounded by:

\displaystyle O\left(\sum_{k=\log(\mathsf{OPT})}^{\log(16n\cdot\ln(n))}m+n\cdot{f_{k}}\right)

\displaystyle\leq O\left(\sum_{k=\log(\mathsf{OPT})}^{\log(16n\cdot\ln(n))}m+\frac{mn\cdot(\log(m)+\log(n))}{\mathsf{OPT}}\right)

\displaystyle\leq O\left(\frac{mn\cdot\log(n)\cdot(\log(m)+\log(n))}{\mathsf{OPT}}\right).\qed

Theorem

3
now follows as an immediate consequence of
Lemmas

5.12
and
5.14
, by taking the minimum runtime. A simple theoretical approach to doing this it to run ConstructLimitedVoteCover and LazyCLVC in parallel, then take the result of the first to finish. This gives us an algorithm that constructs an
O(\log n)
-approximate minimum set cover in time proportional to the minimum running time of the two algorithms. This gives us an
\tilde{O}(\min(m+n\mathsf{OPT}{},mn/\mathsf{OPT}{}))

To leverage

6
Hardness

In this section we establish hardness results to show that the approximation ratios achieved by our algorithm are essentially tight for any polynomial-time algorithm, not only in general metrics, but in Euclidean spaces. We further demonstrate that the problem maintains hardness of approximation even in low-dimensional Euclidean space, i.e
O(\log(n))
dimensions.
We start with some preliminary terminology, definitions and lemmas we will use in proving the results.

6.1
Preliminaries

We first define navigability on a local scale, in terms of the neighborhood of a single point.

Definition 4
.

Given point set
P
and distance metric
d:P\times P\rightarrow\mathbb{R}^{+}
, and given a point
p_{i}\in P
and a set
P^{\prime}\subseteq P
,
P^{\prime}\subseteq P
is a
navigable neighborhood
for
p_{i}
if and only if for every
p_{k}\in P
where
p_{i}\neq p_{k}
, there exists some
p_{j}\in P^{\prime}
such that
d(p_{j},p_{k})<d(p_{i},p_{k})
.

Definition 5
.

Given point set
P
and distance metric
d:P\times P\rightarrow\mathbb{R}^{+}
, and given a point
p\in P
and a set
P^{\prime}\subseteq P
, we say that
P^{\prime}\subseteq P
is a
minimum navigable neighborhood
for
p
if and only if for every navigable neighborhood
P^{\prime\prime}\subseteq P
we have
\left|P^{\prime}\right|\leq\left|P^{\prime\prime}\right|
.
we say that
P^{\prime}\subseteq P
is a
c
-
approximate minimum navigable neighborhood
for
p
if and only if for every navigable neighborhood
P^{\prime\prime}\subseteq P
we have
\left|P^{\prime}\right|\leq c\cdot\left|P^{\prime\prime}\right|
.

As mentioned before, navigability can be viewed as a local property, and this can also be illustrated through the above definitions - a graph is navigable if and only if every neighborhood is a navigable neighborhood. Further, a graph is a minimum navigable graph if and only if the neighborhood of every point is the minimum navigable neighborhood. Note however, that if we have a
c
-approximate minimum navigable graph, it does not mean that any particular neighborhood is
c
-approximate minimum. This provides perspective as to why obtaining any hardness of approximation results for the average degree of a navigable graph is much more involved then arguing that the construction of a minimum navigable graph is
NP
-hard.

6.1.1
Defining covering point sets

Now we turn to define a prototypical transformation from a set cover instance to a point set. Then we turn to prove some properties of this prototypical transformation. To achieve our hardness we will instantiate this transformation in different settings.
We start with the concept of covering point sets - these are point sets we construct from set cover instances, which main feature is that navigable neighborhoods for some of the points can be translated into set covers for the original instance. We later prove some properties of these point sets. Our hardness results come from constructing covering point sets in the different settings.

Definition 6
.

Given a set cover instance
(U=[n],\mathcal{F}=\{S_{1},...,S_{m}\})
, a point set
P
is called a representative point set for
(U,\mathcal{F})
if
P_{(U,\mathcal{F})}=\{p_{i}:i\in[n]\}\cup\{p_{S_{j}}:S_{j}\in\mathcal{F}\}\subseteq P
, meaning
P
contains a point for every element, which we term element points, and every set, which we term set points.
Further,
P
contains a distinguished point,
c\in P\setminus P_{(U,\mathcal{F})}
which we term the centroid.
Points in
(P\setminus P_{(U,\mathcal{F})})\setminus\{c\}
, i.e the remaining points, are called solution points. We denote the set of solution points by
P_{SC}
.

Definition 7
.

Given a set cover instance
(U=[n],\mathcal{F}=\{S_{1},...,S_{m}\})
, a point set
P
is called a covering point set for
(U,\mathcal{F})
with respect to distance metric
d
on
P
, if it is a representative point set, and the following properties hold:

1.

c
is the unique nearest neighbor for any solution point, i.e:
\forall p\in P_{SC},p^{\prime}\in P\setminus\{p,c\}:d(p,c)<d(p,p^{\prime})
.

2.

A set point is closer to another set point than to a solution point:
\forall j,j^{\prime}\in[m],p\in P_{SC}:d(p_{S_{j}},p_{S_{j^{\prime}}})<d(p_{S_{j}},p)
.

3.

\forall p\in P_{SC},p^{\prime}\in P,i\in[n]:d(p^{\prime},p_{i})<d(p,p_{i})
if and only if
p^{\prime}=p_{i}
or
p^{\prime}=p_{S_{j}}
where
e\in S_{j}
. In other words: Moving from a solution point to another point gets us closer to an element point
p_{i}
if and only if the other point is equal to
p_{i}
or is the point corresponding to a set that contains
i
.

4.

A solution point is closer to another solution point than it is to any element or set point:

\forall p,p^{\prime}\in P_{SC},p^{\prime\prime}\in(P\setminus P_{SC})\setminus\{c\}:d(p,p^{\prime})<d(p,p^{\prime\prime})
.

6.1.2
Properties of covering point sets

Observation 6.1
.

In a covering point set, an element point or a set point has a minimum navigable neighborhood which size is at most
m+n+1
.

Proof.

Let
p
be an element or a set point, and observe

as a candidate neighborhood for
p
. All set and element points are in
N
and so is
c
. Further, according to property (4) of covering set points,
c
is closer than

to all cover points, thus
N
is a navigable neighborhood which size is at most
n+m+1
.
∎

Observation 6.2
.

Given a covering point set for a set covering instance
(U,\mathcal{F})
, a solution point

, and

Proof.

Observe the set

|N|-1
(because no point in this set is closer to another solution point than

is a navigable neighborhood for

or

∎

Lemma 6.3
.

In a covering point set, the size of a minimum navigable neighborhood for a solution point is exactly
\mathsf{OPT}{}+1
where
\mathsf{OPT}{}
is the size of the minimum set cover for
(U,\mathcal{F})

Proof.

Let

, if

.

As this lemma shows, the main strength of covering point sets, is that the problem of finding a navigable neighborhood for a solution point corresponds to computing a set cover for the original instance. A crucial part, is that the size of minimum navigable neighborhoods for set and element points does not scale with the number of solution points (due to the centroid), so by including moderately many solution points in the construction we can claim that in a navigable graph with approximate-minimum average degree, some solution point has a navigable neighborhood that reasonably approximates the minimum. This will be central to the way we use these constructions.

Corollary 6.4
.

The total number of edges in a minimum navigable graph for a covering point set is at most
(n+m)(n+m+1)+m+n+|P_{SC}|+(\mathsf{OPT}{}+1)\cdot|P_{SC}|
.

(\frac{1}{3}\cdot ln(n)-\varepsilon)\cdot\mathsf{OPT}{}
, where
\mathsf{OPT}{}
is the minimum average degree of any navigable graph on
P
with respect to the Euclidean metric.

6.4
Hardness in low-dimensional Euclidean metric

Our next goal is to establish hardness of approximation results for constructing navigable graphs in low-dimensional Euclidean space, specifically when
d=\Theta\left(\log(n)\right)
. The main idea is to construct a point set similar to the one we saw in the previous section project it down to
\Theta(\log(n))
dimensions using a JL
[
15
]
transform, while maintaining it being a covering point set. In order to achieve all of this, we need a covering point set which properties are maintained under some constant distortion factor
\varepsilon
.
Note that the point set presented in
section

6.3
does not satisfy this requirement - for example if we want to maintain property (3) we have to make sure whatever distortion factor
\varepsilon
we use will maintain:
(1-\varepsilon)\cdot(n^{2}+f_{i}+1)>(1+\varepsilon)\cdot(n^{2}+f_{i})
but this certainly requires
\varepsilon
to be sub-constant.
Our way of solving this issue is looking at set cover instances with bounded-frequency, and using known hardness of approximation results for those instances. Specifically, for set cover instances in which frequency is bounded by a constant, we can define covering point sets which maintain their properties under JL transform with constant distortion factor
\varepsilon
.
We now define such a point set, and prove that it maintains its properties under JL transform with constant distortion factor.
Given a set cover instance
(U,\mathcal{F})
we define a parameterized mapping
\varphi(U,\mathcal{F},f)
which maps the set cover instance to a representative point set
P\subseteq\mathbb{E}^{(m+n+2+(m+n)^{3})}
with
(m+n)^{3}
solution points, which we denote by
P_{SC}=\{\ell_{1},...,\ell_{(m+n)^{3}}\}
, as follows:

•

\forall S_{j}\in\mathcal{F}:p_{S_{j}}=\mathbf{e}_{j}+\mathbf{e}_{n+m+1}
.

•

\forall i\in\left[n\right]:p_{i}=f\cdot\mathbf{e}_{m+i}+\sum_{j:i\in S_{j}}\mathbf{e}_{j}

•

\forall k\in\left[\left(m+n\right)^{3}\right]:\ell_{k}=\frac{1}{2}\cdot\mathbf{e}_{n+m+2}+\sqrt{0.65}\cdot\mathbf{e}_{n+m+2+k}

•

c=\mathbf{e}_{n+m+2}
.

Lemma 6.6
.

If
(U,\mathcal{F})
is a set cover instance in which the frequency of every element is exactly
k\geq 2
, and let
d
be a distance metric on
P=\varphi(U,\mathcal{F},k)
that satisfies:

\forall p\neq p^{\prime}\in P:d(p,p^{\prime})\in\left[(1-\delta)\cdot\lVert p-p^{\prime}\rVert,(1+\delta)\cdot\lVert p-p^{\prime}\rVert\right]

where
\lVert\cdot\rVert
denotes the euclidean norm, then: If
\delta\leq\frac{1}{40k^{2}}
,
P
is a covering point set for
(U,\mathcal{F})
w.r.t
d
.

Proof.

First note, that if the frequency of every element in the set cover instance is
k
, the only changes in distances in
\varphi(U,\mathcal{F},k)
are in the category of element points.
Specifically, the distance between
c
and an element point is now
\sqrt{k^{2}+k+1}
, the distance between a solution point and an element point is
\sqrt{k^{2}+k+0.9}
.
The distance between an element point and a set point is
\sqrt{k^{2}+k}
or
\sqrt{k^{2}+k+2}
, depending on whether the element is a member of the set.
Now, to verify
\varphi(U,\mathcal{F},f)
is a covering point set w.r.t
d
:
Note that:

0.9\cdot(1+\delta)\leq 0.9+\frac{0.9}{40}<\sqrt{1.3}-\frac{\sqrt{1.3}}{40}\leq\sqrt{1.3}\cdot(1-\delta)

This implies that
c
is still strictly closer to a solution point than a different a solution point is. The Euclidean distance between solution points to other classes of points is only greater, which implies
c
is still the unique nearest neighbor of all solution points, so property (1) is maintained.
Now, observe:

\frac{\left(\sqrt{k^{2}+k+0.9}+\sqrt{k^{2}+k+1}\right)^{2}}{0.1}\leq\frac{4k^{2}}{0.1}=40k^{2}.

Thus:

\frac{\sqrt{k^{2}+k+0.9}+\sqrt{k^{2}+k+1}}{\sqrt{k^{2}+k+1}-\sqrt{k^{2}+k+0.9}}=\frac{\left(\sqrt{k^{2}+k+0.9}+\sqrt{k^{2}+k+1}\right)^{2}}{\left(\sqrt{k^{2}+k+1}-\sqrt{k^{2}+k+0.9}\right)\left(\sqrt{k^{2}+k+0.9}+\sqrt{k^{2}+k+1}\right)}

\frac{\left(\sqrt{k^{2}+k+0.9}+\sqrt{k^{2}+k+1}\right)^{2}}{0.1}\leq 40k^{2}.

So:

\frac{\sqrt{k^{2}+k+0.9}+\sqrt{k^{2}+k+1}}{40k^{2}}\leq\sqrt{k^{2}+k+1}-\sqrt{k^{2}+k+0.9},

which implies

\sqrt{k^{2}+k+0.9}\cdot\left(1+\frac{1}{40k^{2}}\right)\leq\sqrt{k^{2}+k+1}\cdot\left(1-\frac{1}{40k^{2}}\right)

\to\sqrt{k^{2}+k+0.9}\cdot\left(1+\delta\right)\leq\sqrt{k^{2}+k+1}\cdot\left(1-\frac{1}{\delta}\right).\qed

This implies that given an element point
p_{i}
and a solution point
\ell_{r}
,
c
is still further from
p_{i}
than
\ell_{r}
is. Further, any other point
p\in\varphi(U,\mathcal{F},k)
that does not correspond to a set containing
i
is further from
p_{i}
than
c
is in the Euclidean metric, so they also remain further from
p_{i}
than
\ell_{r}
is under
d
. For a point corresponding to a set containing
i
, i.e of the form
p_{S_{j}}
where
i\in S_{j}
, it can similarly be verified that:

\sqrt{k^{2}+k}\cdot\left(1+\delta\right)\leq\sqrt{k^{2}+k+0.9}\cdot\left(1-\frac{1}{\delta}\right).

This means moving from a solution point to
p_{S_{j}}
where
i\in S_{j}
gets us closer to
p_{i}
under
d
. Overall property (3) is maintained.
The other properties can be similarly verified.

Theorem 9
.

For every
k\geq 2,\varepsilon>0
, there exists
C(k)
(
C(k)
is only a function of
k
) such that unless
P=NP
, there does not exist a polynomial time algorithm which receives as input a set
P
, of
N
points in
E^{C(k)\cdot\log(N)}
, i.e
((C(k)\cdot\log(N))
-dimensional Euclidean space, and returns a navigable graph on
P
which average degree is
(k-1.5-\varepsilon)
-approximate.

Proof.

We assume such an algorithm exists, and then use it to construct a polynomial time algorithm that produces a
(k-1-\varepsilon)
-approximate solution for the
E_{k}
-vertex-cover problem, which according to
[
16
]
would imply
P=NP
.
Let
k\geq 2
,
\varepsilon>0
, and set
\varepsilon^{\prime}=1.5\varepsilon>\varepsilon
.
Let
G=\left(V,E\right)
be an
E_{k^{\prime}}
-vertex-cover instance that is hard to
(k^{\prime}-1-\varepsilon^{\prime})
-approximate for
k^{\prime}=2k
as constructed in the reductions proving hardness of approximation for hypergraph vertex cover by
[
16
]
. Let
n
denote the number of vertices in
G
, and
m
denote the number of edges.
Now, consider the set cover instance induced by
G
:
\left(U_{G}=E,\mathcal{F}_{G}=V\right)
in which for every
e\in E
and
v\in V
we say that
e\in v
if and only if
v
is adjacent to
v
, it has
m
elements and
n
sets. Further, the frequency of every element is exactly
k^{\prime}
. Note that
V^{\prime}\subseteq V
is a vertex cover for
G
if and only if it is a set cover for
\left(U_{G},\mathcal{F}_{G}\right)
.
The next step is to construct Now, we construct
P=\varphi\left(U_{G},\mathcal{F}_{G},k^{\prime}\right)
and apply a deterministic polynomial-time JL transform
[
14
]
to the result with distortion parameter
\delta=\frac{1}{40k^{2}}
, and obtain a projected point set
P^{\prime}\in\mathbb{E}^{\Theta\left(\log\left(N\right)\right)\cdot 40k^{4}}
where
N
is the number of points in
P^{\prime}
. Note that
N=m+n+\left(m+n\right)^{3}+1
, so it is polynomial in
\left(m,n\right)
. According to
lemma

6.6
, since the frequency of every element in
U_{G}
is exactly
k^{\prime}
,
P^{\prime}
is a covering point set for
\left(U_{G},\mathcal{F}_{G}\right)
with respect to the Euclidean distance metric.
We can now apply the hypothesized algorithm to
P^{\prime}
to obtain a navigable graph (in time polynomial in
N
, and thus in
m,n
)
H_{P^{\prime}}
which degree is
r
-approximate minimum where
r=k-1.5-\varepsilon
. Note that according to
lemma

6.5
we can then use
H_{P^{\prime}}
to construct a set cover for
\left(U_{G},\mathcal{F}_{G}\right)
which average degree is
\left(r+o\left(1\right)+\Theta\left(\frac{r}{\mathsf{OPT}{}}\right)\right)
-approximate minimum. Observing the proof of
6.2
and specifically
eq.

1
, we can actually conclude that
H_{P^{\prime}}
can be used to efficiently compute a
\left(2r+2+o\left(1\right)\right)
-approximate minimum set cover, because:

\left(r+o\left(1\right)+\frac{1}{\mathsf{OPT}{}}\right)\cdot\left(\mathsf{OPT}{}+1\right)=\left(r+o\left(1\right)+\frac{1}{\mathsf{OPT}{}}+\frac{r}{\mathsf{OPT}{}}+\frac{1}{\mathsf{OPT}{}^{2}}\right)\cdot\mathsf{OPT}{}\leq\left(2r+o\left(1\right)+2\right)\cdot\mathsf{OPT}{}

Overall we have a
\left(2r+o\left(1\right)+2\right)
-approximate minimum set cover for
(U_{G},\mathcal{F}_{G})
.
Note that:

2r+o\left(1\right)+2=2k-3-2\varepsilon+o\left(1\right)+2=k^{\prime}-1-2\varepsilon+o\left(1\right)\leq k^{\prime}-1-\varepsilon^{\prime}

Thus we have a
(k^{\prime}-1-\varepsilon^{\prime})
-approximate minimum solution in polynomial time for the hard
E_{k^{\prime}}
-vertex cover instance we started with, which according to
[
16
]
implies
P=NP
.
