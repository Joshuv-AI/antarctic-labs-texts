SilentWood: Efficient Private Inference Over Gradient Boosting Decision Forests
Ronny Ko, Abdelkarim Kati, Robin Geelen, Rasoul Mahdavi, Byoungwoo Yoon, Jongho Shin, Zhiqiang Lin, Makoto Onizuka, Florian Kerschbaum CTO Division, LG Electronics, Seoul, South Korea David R. Cheriton School of Computer Science, University of Waterloo, Waterloo, Canada Department of Electrical Engineering, KU Leuven, Leuven, Belgium Computer Science and Engineering, Ohio State University, Columbus, USA Graduate School of Information Science and Technology, The University of Osaka, Osaka, Japan

Abstract
Gradient boosting decision forests, used by XGBoost or AdaBoost, offer higher accuracy and lower training times than decision trees on large datasets. Private inference protocols for decision trees can preserve both input and tree privacy. However, naively extending them to decision forests by replication leads to impractical running times. In this paper, we propose an efficient private decision inference protocol using homomorphic encryption. We present several optimizations that identify and remove (approximate) duplication between trees, significantly reducing communication and computation costs over the naive approach. We present the private inference protocol for highly scalable gradient boosting decision forests. Our protocol ( SilentWood ) is faster than parallel RCC-PDTE by up to 42.5x, Zama’s Concrete ML XGBoost by up to 27.8x, and SoK-GGG’s two-party garbled circuit protocol by 2.94x.



1
Introduction

Machine Learning as a Service (MLaaS) allows large user groups to use machine learning models.
A service provider trains a model and offers users inference using this model.
Some of such examples include recommendation systems, spam filtering, and object detection used in e-commerce services, social networking services, and smart home.
An advantage of such MLaaS is that the provider can control access to the model and easily update it when new training data is available.
In contrast, its disadvantage is the privacy concern of the users revealing their test data to the provider which may be sensitive or legally restricted.
Cryptography offers a compelling solution to this problem. For example, the provider can use fully homomorphic encryption
Gentry (2009b)
;
Fan and Vercauteren (2012b)
to
blindly
process the user’s input features in an encrypted form through the trained model and yield an encrypted prediction result, which only the user can decrypt.
However, this solution usually has high computational costs.
Alternatively, the user and the provider can engage in a two-party computation
Yao (1982)
;
Yao (1986)
;
Oded (2009)

where the user’s input is computed through the model in a
blinded
manner, during which the server’s trained model parameters and the user’s private data are not leaked to each other. However, a two-party computation usually incurs high communication costs.

In this paper, we develop a new protocol for private inference over gradient boosting decision forests
, which
are collections of decision trees whose results are combined into the final model prediction.
Gradient boosting forests offer a better trade-off between higher accuracy and lower training time than training a single decision tree for large datasets.
Moreover, they retain a critical advantage of decision trees over many other machine learning techniques; their predictions are explainable, helping to fulfill legal, social, and ethical requirements.

Many private inference protocols over decision trees exist
(
§5
).
However, extending these to gradient boosting decision forests comes with two challenges.
First, the results of the decision trees need to be combined into a single prediction result, requiring further computation.
This can particularly pose a problem for protocols using homomorphic encryption,
since these computations increase
the multiplication overhead
, significantly increasing the
runtime
of the protocols.
Second, even naively running several independent decision tree protocols without combining their results can exhaust the server’s computing resources.
Therefore, optimizations are necessary to reduce the cost of executing multiple decision tree evaluations on the same input.

To solve these problems, we propose
SilentWood
, a private inference protocol for gradient boosting that uses three novel techniques. First, to reduce the high computation overhead caused by frequent homomorphic computations in FHE-based PDTE (private decision tree evaluation),
SilentWood
applies node clustering (i.e., grouping and weighted-averaging tree nodes having similar thresholds) to eliminate redundant computations (
§3.1
). Second,
SilentWood
proposes the Blind Code Conversion (BCC) protocol to combine SumPath’s depth-independent multiplicative cost with MultiplyPath’s arithmetic compatibility for score aggregation (
§3.2
). BCC is a lightweight two-party protocol without garbled circuits or secret sharing: the server pads and shuffles its intermediate ciphertext so its plaintext looks uniformly random to the client. The client’s role is to decrypt it and convert the underlying plaintext values
blindly
to help the server’s subsequent computation of score aggregation. This process ensures the information in the intermediate ciphertext to be inaccessible from both the client and server, while realizing arithmetic compatibility of the server’s score aggregation. Lastly, to reduce communication overhead caused by repetitive data encoding in FHE-based PDTE,
SilentWood
’s ciphertext compression carefully removes repetitive encodings before encryption and then homomorphically restores the original data format on the server side (i.e., homomorphic decompression), thus minimizing ciphertext size while preserving necessary SIMD comparisons (
§3.3
).

While RCC-PDTE
Akhavan Mahdavi et al. (2023)
(
§B.3
), the state-of-the-art PDTE protocol, is effective for computing a single decision tree, naively repeating this protocol for all decision trees (100 in our default setup) can take more than 5 minutes for a single inference, which is prohibitively long.
The inference time of
SilentWood
is, on average, faster than this baseline by 42.5x, faster than Zama’s Concrete ML
Zama (2024)
XGBoost by 34.0x, and faster than SoK-GGG (i.e., a state-of-the-art MPC protocol based on GC) by 2.94x (
§4
).
Our paper’s contributions are as follows:

•

We propose three optimization techniques for efficient private inference of random forest models: node clustering, blind code conversion, and ciphertext compression.

•

We implemented
SilentWood
, a prototype of our proposed techniques.

•

We provide evaluation results of
SilentWood
and compare it to other state-of-the-art protocols.

Preliminaries

2.1
Gradient Boosting Models

Ensemble decision trees
Bishop (2006)
combine many shallow trees (weak learners) to improve prediction, typically via either random forests
Breiman (2001)
or gradient boosting
Friedman (2001)
. Random forests train trees independently and aggregate their outputs (e.g., voting/averaging), whereas gradient boosting trains trees sequentially to correct prior residual errors, yielding a strong additive model. We focus on private inference for AdaBoost
Freund and Schapire (1995)
and XGBoost
Chen and Guestrin (2016)
. In AdaBoost, each tree has a weight and each leaf outputs a signed value ((+)/(-)); inference traverses every tree by threshold comparisons, retrieves the reached leaf value, multiplies it by the tree weight, sums across trees, and predicts by the sign of the final sum. XGBoost similarly sums leaf values of traversed trees: for binary classification it applies a sigmoid to the sum and thresholds at 0.5; for multi-class it computes a per-class sum, applies softmax, and outputs the argmax.

2.2
Fully Homomorphic Encryption (FHE)

Fully Homomorphic Encryption (FHE)
Gentry (2009a)
enables addition and multiplication directly on ciphertexts, allowing computation on encrypted data without decryption.
SilentWood
adopts an RLWE-family scheme, BFV
Fan and Vercauteren (2012a)
, primarily for efficient SIMD batching: an
n
-dimensional plaintext vector is encoded (
Encode
) into a
(n-1)
-degree (or lesser degree) polynomial
M(X)
, then encrypted (
Encrypt
) under a secret polynomial
S(X)
to an RLWE ciphertext (with a large scaling factor
\Delta
as part of the scheme). The scheme supports cipher-plaintext and cipher-cipher addition/multiplication (
PAdd/CAdd/PMult/CMult
) as well as slot rotations (
Rotate
) that cyclically permute packed plaintext elements without decryption. SIMD means these operations act element-wise over all packed slots at once; typical slot counts are
2^{13}\sim 2^{15}
, providing substantial parallelism. We will treat these FHE primitives as black boxes to implement private gradient-boosting inference. The supported operations of the BFV scheme are detailed in
§A
.

2.3
Private Decision Tree Evaluation

Private Decision Tree Evaluation (PDTE) is a protocol between a server holding a decision tree and a client holding a feature vector for one sample. At the end of PDTE, the server learns nothing about the client’s inputs, while the client learns nothing about the server’s model beyond the prediction result and model hyper-parameters (e.g., feature/class types)
1
1

1

More precisely, PDTE’s server-side privacy goal is to reveal no more model information than plaintext inference.
. The server typically returns class scores (probabilities), from which the client selects the top class (or applies a tie-breaking rule). PDTE generally consists of two steps: (i) value comparison at each node; and (ii) tree path evaluation.

Value Comparison at Each Node:
Tree traversal requires
greater-than
comparisons between an input feature
X
and a node’s threshold
Y
. Under FHE, only two arithmetic operations
(+,\cdot)
are natively supported, so comparisons must be implemented as an arithmetic circuit over
(+,\cdot)
. A direct approach is to bitwise-decompose
X,Y
into encrypted bits and
homomorphically
evaluate a standard comparator circuit, where all logic gates are implemented as bit-wise
(+,\cdot)
operations of encrypted bits. This approach computationally requires a cipher-cipher multiplication (
CMult
) chain as long as the bit length of
X,Y
. In FHE, cipher-cipher multiplication is computationally heavy, so shortening the multiplication chain is crucial. To this end, a more efficient method of value comparison is based on constant-weight (CW) encoding
Akhavan Mahdavi et al. (2023)
, where numbers are encoded using a fixed Hamming weight, and the
CMult
chain’s length for value comparison is equivalent to the Hamming weight. While
SilentWood
is compatible with both methods, our prototype adopts the CW-based one. We explain the details of these two comparison methods in
§B.3
.

Tree Path Evaluation:
Given encrypted comparison results at all nodes (1 if
>
is satisfied; 0 otherwise), PDTE’s next step is to determine the reached leaf by evaluating path conditions. Two common methods are MultiplyPath (path conjugation)
Kiss et al. (2019)
and SumPath
Tueno et al. (2019)
. As illustrated in
Figure 2
(
§B.2
), MultiplyPath assigns each edge a 0/1 indicator and multiplies indicators along a root-to-leaf path, so only the true path yields 1 (others 0). However, this requires a cipher-cipher multiplication (
CMult
) chain length proportional to tree depth. On the other hand, SumPath assigns 0 to satisfied edges and 1 to unsatisfied edges and sums along each path, so the true path yields 0 and every other path yields its number of unsatisfied edges (
1\!\sim\!d
); each sum is then multiplied by a fresh random non-zero value to hide the count. This needs only ciphertext additions and one plaintext multiplication, which is substantially cheaper under FHE. After homomorphically computing the values for all tree paths, the server returns them to the client, who decrypts and selects the unique leaf whose SumPath equals 0 (or MultiplyPath equals 1) to obtain the prediction. We provide an example of tree path evaluation based on MultiplyPath and SumPath in
Figure 5
(
§B.4
).

3
Methodology

This section explains the problems of applying existing PDTE methods to evaluate private gradient boosting models, and how
SilentWood
solves them through three novel techniques: node clustering, blind code conversion, and ciphertext compression.

Threat Model:
Our threat model for privacy assumes a semi-honest client (i.e., follows the protocol) and a malicious server (i.e., may deviate from the protocol)
2
2

2

For assuming a malicious client and a malicious server, see
§D
. They try to learn about each other’s secrets from exchanged messages. The server’s secret is its trained gradient boosting model; the client’s secret is its input feature values. Their common knowledge is the feature names and feature bit-length. At the end of the protocol, the server learns nothing about the client’s features; the client learns only the inference scores/probabilities for each class and the fact that the number of tree paths is capped at some multiple of the cyclotomic polynomial’s degree (e.g.,
2^{14}
) as a hyperparameter. Besides that, the client learns nothing about the server’s model (e.g., node/tree count, depth, or node thresholds).

Existing PDTE protocols homomorphically compare each internal node’s threshold

Leaf Value Re-optimization:

After updating thresholds for a cluster

, we re-optimize the leaf values (scores) while keeping the tree topology fixed.
Concretely, we re-route the training samples under the updated thresholds and, for each leaf

G_{\ell}=\sum_{x\in\ell}\frac{\partial}{\partial\hat{y}(x)}\mathcal{L}\!\big(y(x),\hat{y}(x)\big)

This update recalibrates the existing leaf outputs under the modified decision boundaries induced by threshold averaging.

Once the candidate cluster

Ciphertext Compression

Problem of Huge Communication Cost.
In FHE-based PDTE, ciphertext size grows quickly with the number of nodes because inputs are encoded/encrypted bit-wise. For example, RCC-PDTE
Akhavan Mahdavi et al. (2023)
requires an 85.7 MB query ciphertext for 32-bit feature precision, where network transmission dominates inference time. The major bottleneck is
repetitive data encoding
for SIMD comparisons, which intentionally duplicates the same feature value across multiple slots for the server’s computational efficiency, but instead sacrifices slot utility.
For example, suppose that the server’s tree model has three nodes on
age
(thresholds 21, 23, 45) and two on
sleep
(6, 8). To homomorphically compare against the encrypted client inputs
age
=28
and
sleep
=7
in SIMD, the client repeatedly encodes
age
and
sleep
three times each (capped by the maximum repetition of all features), wasting slots for redundancy.

To reduce such communication inefficiency,
SilentWood
introduces
ciphertext compression
: (1) the client removes such repetitions
before
encryption to form compact ciphertexts; (2) upon receiving them, the server
homomorphically
decompresses to restore the intended repetition pattern. Algorithm
4
generalizes the client’s packing based on: (1) the
M
plaintext data arrays
A_{0},\ldots,A_{M-1}
, one per CW-encoded bit position; (2) each feature
j
’s start slot
\mathit{start}_{j}
; (3) the offsets
\mathit{gap}_{0},\ldots,\mathit{gap}_{R-1}
at which the
R
repetitions of a feature would have been encoded; and (4) the number
R
of arrays packed into one ciphertext, so that the slot a repetition would have occupied now holds the bit of another array. The key requirement is that the offsets
\mathit{gap}_{r}
are the same for every feature, so the server can restore all repetitions
homogeneously
in SIMD (e.g.,
age
and
sleep
are expanded simultaneously).

The server’s homomorphic decompression is essentially a homomorphic reverse operation of Algorithm
4
. Ciphertext (de-)compression does not leak the client’s input data to the server. We provide an example of ciphertext compression and the ciphertext decompression algorithm in
§E

Related Work

FHE vs 2PC for PDTE:

RCC-PDTE
Akhavan Mahdavi et al. (2023)
uses CW-encoding-based comparison to improve this limitation, yet its SumPath aggregation is incompatible with standard forest inference and becomes costly with many trees.
Brickell et al. (2007)
and
Kiss et al. (2019)
design constant-round 2PC protocols for PDTE from oblivious transfer and garbled circuits (GC), but their communication grows exponentially with tree depth for evaluating all paths; oblivious RAM (
Tueno et al. (2019)
) or pseudo-random functions (
Bai et al. (2022)
) help only modestly. Gazelle-style FHE+GC hybrids
Juvekar et al. (2018)
inherit this cost for tree traversal (as SoK-GGG does), whereas BCC’s only interactive step exchanges packed FHE ciphertexts.

Scaling PDTE to Random Forests:
HBDT (
Shin et al. (2024)
) uses FHE with one-hot encoded features, but one-hot inflates ciphertext count (e.g., a 32-bit feature needs 655 ciphertexts). BPDTE-CW (
Cong et al. (2024)
) uses one non-zero digit per node to batch comparisons, yet communication still grows (e.g., +17.7% when precision increases from 11 to 16 bits). Moreover, since summing path scores (SumPath) dominates cost, faster comparisons alone yield limited speedup. Both HBDT and BPDTE-CW aggregate results via MultiplyPath, multiplying along decision paths and incurring heavy ciphertext multiplications. In contrast,
SilentWood
uses summation with BCC to avoid multiplications. Kangaroo (
Xu et al. (2026)
) combines packed HE and secret sharing for amortized private inference over large tree ensembles in WANs. Compared with
SilentWood
, it assumes a weaker threat model (semi-honest server and client), reveals an obfuscated tree topology that constrains the original tree structure, and requires 4 RTTs.
SilentWood
supports malicious-server privacy, hides tree topology from the client, and uses 2 RTTs.

Other Efficiency Protocols:

SortingHat (
Cong et al. (2022)
) and Onion-ORAM (
Chen et al. (2019)
) are based on TFHE, much slower than
SilentWood
because they lack SIMD.
SortingHat’s transciphering accounts for 35% of inference time and grows with tree depth; Onion-ORAM’s ciphertext expansion adds 33–66% overhead (see Table 2 in their paper).
SilentWood
’s decompression overhead is only 4.5% (
Table 11
), independent of depth, making it a more efficient compression method for BFV/BGV.

Tree Compression:
Various pruning techniques reduce inference cost by trimming nodes or trees, e.g.,
Liu and Mazumder (2023)
,
Devos et al. (2025)
, (
(2025)
. In contrast, our node clustering preserves the full model structure and merges similar thresholds per feature to reduce distinct comparisons while preserving logic structure. This approach is beneficial when preserving the tree structure is important for interpretability or certification workflows.
SilentWood
’s node clustering complements pruning methods by unifying similar threshold values even after pruning a model.

6
Conclusion

SilentWood
’s private inference over gradient-boosting forests significantly enhances performance compared to existing methods.
SilentWood
’s novel techniques include node clustering to eliminate duplicate homomorphic computations, blind code conversion to preserve arithmetic compatibility for efficient tree score aggregation, and ciphertext compression to reduce the encrypted data size.
SilentWood
achieves an average private XGBoost inference time of 1.8x
\sim
41.9x faster than state-of-the-art FHE or MPC-based protocols (i.e., Zama’s concrete ML, RCC-PDTE, and SoK-GGG).

Security Against Corrupted Server:

SilentWood
can be modeled as a client-aided outsourcing protocol. Akavia et al.
Akavia et al. (2025)
show that such a protocol achieves privacy if at least one of the following conditions is satisfied:

•

It is cleartext computable (all plaintexts/cleartexts are functions of the client’s input) and it is instantiated with a CPA-secure FHE scheme.

•

It is instantiated with a funcCPA-secure FHE scheme.

The first condition is not satisfied in
SilentWood

However, Akavia et al.
Akavia et al. (2025)
show that sanitized CPA-secure schemes are funcCPA-secure.
Therefore, security can be proven in one of these situations: (i) BFV is funcCPA-secure; or (ii) BFV is CPA-secure and all ciphertexts are sanitized before sending them to the server.

An example of ciphertext compression

Figure 7
is an example showing how PDTE generally uses repetitive data encoding: the server’s tree has 3 nodes conditioned on the
age

sleep
feature (each threshold is 6 and 8). The server homomorphically compares these threshold values against the client’s encrypted

and
sleep=7
input feature values in a SIMD manner. Since the server has 3 distinct threshold values for
age
and 2 distinct threshold values for
sleep

age=28
and
sleep=7
values repetitively 3 times (capping to the server’s maximum number of comparisons for any same feature name). While such repetitive data encoding enables efficient SIMD comparisons, this repetition wastes ciphertext slot utility.

Figure 8
shows the resulting example of
SilentWood
’s ciphertext compression. In FHE-based private protocols, when a client CW-encodes feature data, s/he has to create as many ciphertexts as the number of feature data bits (
M
in
Figure 8

SilentWood

M
to
\frac{M}{3}
. Once the server receives these compressed ciphertexts, it homomorphically performs a reverse operation of what the client did, effectively decompressing and restoring the originally intended data encoding (i.e., 3 repetitions of feature bits).
