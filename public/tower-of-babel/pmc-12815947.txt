Efficient multi-finger vein recognition using layer-wise progressive MobileNet fine-tuning and a Dense-Head Probabilistic Siamese Network
Authors: Alaa S. Alaerjan, Ayman Mohamed Mostafa, Alshimaa Abdelraof Mahmoud, Mohamed Ezz
Published: 2025

ABSTRACT
Finger-vein recognition offers a highly secure and non-intrusive biometric modality ideal for modern authentication systems, yet its deployment on resource-limited devices remains challenging due to the high computational cost of deep models and the rigidity of single-finger enrollment. We present a new two-stage deep learning framework that solves these problems by combining a lightweight MobileNet feature extractor that gets better over time with a new Dense-Head Probabilistic Siamese (DHPS) matcher. Our method is the only one that allows for multi-finger recognition, so users can authenticate with any finger without losing accuracy or speed. Layer-wise unfreezing carefully adjusts the feature extractor to find the right balance between model compactness and discriminative power. The DHPS matcher replaces traditional margin-based losses with a calibrated probabilistic output that is optimized through binary cross-entropy. Our system gets the best results on three different public finger-vein datasets, with Equal Error Rates (EER) of 0.002, 0.067, and 0.075 on the FV-USM, UTFVP, and VERA datasets, respectively. It also has F1-scores of 99.8%, 95.6%, and 91.3% on their test sets. These results are possible because the model is small and can be used on embedded platforms with fast inference. In addition, the pre-trained extractor will be made available to the public to encourage more research in the future. This work improves practical finger-vein biometrics by making them more accurate, flexible, and efficient, which gets around major obstacles to their use in the real world.Supplementary InformationThe online version contains supplementary material available at 10.1038/s41598-025-32132-5.

Introduction

Biometric authentication is becoming more crucial for keeping devices, buildings, and services safe. It has advantages over traditional password and token-based methods. Finger-vein recognition is a type of biometric recognition that has received significant attention because of its natural benefits. For example, internal vein patterns are hard to fake, stay the same over time, and can be captured without having to touch the person using near-infrared imaging. These traits make finger-vein biometrics perfect for a wide range of uses, from smart cards and smart rings to secure building access. Finger-vein recognition has gained importance recently, but there are still a number of problems that make it hard to use in places with limited resources, like wearables and embedded controllers. First, deep learning models that are often used for recognition are usually big and need a lot of processing power. Second, many existing systems require fixed-finger enrollment, which limits users’ options. Third, many current matchers use margin-based contrastive or triplet losses, which are hard to optimize and sensitive to hyperparameter tuning.

As presented in1, the authors developed a user authentication by using a DL-based system that takes advantage of the unique patterns of finger veins. This system combines CNN-based feature extraction with real-time data collection using a scanner, preprocessing with Gaussian median filters, and classification using MATLAB. It also stores results in an IoT system and sends alerts to users via GSM. The goal of the method is to achieve high accuracy (96%) for secure tasks like access control and financial transactions. The authors of2 applied a biometric authentication system based on finger veins that makes sure transactions are safe by using Near-Infrared (NIR) imaging to find the unique vein patterns under the skin. The goal is to get around the problems with other biometric methods (like fingerprints and irises) by using stable internal vascular features that are very hard to copy. The authors of3 developed a secure and efficient finger-vein authentication device using OpenCV and Python. The device will have three stages: image capture, feature extraction, and authentication. The system is meant to make consumer electronics safer by using internal biometric traits that are harder to see and fake from the outside. As presented in4, the authors concentrated on creating a strong authentication system with vein patterns in the fingers, which are more secure than surface-level biometrics like fingerprints. The system helps to prevent identity fraud and ensure safe, secure transactions by utilizing near-infrared imaging and sophisticated filtering techniques to extract meaningful patterns from beneath the skin. The authors of5 developed a two-step finger vein recognition system, which first analyzes the vein patterns’ structure and then assesses image quality to enhance classification in cases where the data is ambiguous. Additionally, the system is optimized for GPU acceleration, which makes it quick and effective—perfect for protecting private information on contemporary consumer electronics. This paper was inspired from our previous research papers in which we used transfer learning to create a feature extractor6 and then created a Siamese network architecture for cross-palmprint recognition7. We expand and modify the approach to finger vein recognition, addressing modality-specific issues and bringing novelties like multi-finger flexibility and calibrated probabilistic matching.

This paper suggests a novel finger-vein recognition framework that balances accuracy, efficiency, and operational flexibility in order to fill the gaps mentioned. In order to adapt a lightweight MobileNet backbone to the finger-vein domain and create a feature extractor that is both compact and discriminative enough for embedded use, this work introduces a layer-wise progressive fine-tuning strategy. We developed a Dense-Head Probabilistic Siamese (DHPS) matcher that generates calibrated match probabilities by incorporating a dense nonlinear head over multiple distance metrics and substituting a binary cross-entropy objective for conventional margin-based contrastive losses. This study aims to answer the following research questions:

Q1: How can a lightweight convolutional backbone be effectively adapted to finger-vein biometrics to achieve a balance between computational efficiency and discriminative power suitable for embedded devices?

Q2: Which similarity measures and loss functions are most effective within a probabilistic Siamese framework for accurate and calibrated finger-vein matching across multiple fingers and subjects?

Q3: To what extent can a multi-finger-agnostic recognition system generalize across heterogeneous datasets with varying image quality and acquisition conditions?

Q4: What trade-offs exist between model complexity, inference latency, and authentication accuracy in resource-constrained finger-vein recognition applications?

Despite substantial progress in finger-vein recognition, several critical challenges remain unresolved. First, many state-of-the-art models rely on heavy convolutional or transformer-based backbones, which achieve high accuracy but are unsuitable for deployment on resource-limited devices such as smart cards, IoT nodes, or wearable authentication systems. Second, most existing approaches still depend on fixed-finger enrollment, forcing users to always authenticate with the same finger and limiting both convenience and system flexibility. Third, widely used margin-based loss functions, such as contrastive and triplet losses, suffer from unstable optimization, high sensitivity to hyperparameters, and difficulties in threshold calibration for real-world deployment. Fourth, robustness across heterogeneous datasets is rarely achieved; performance often drops sharply when models are tested on images with different sensors, resolutions, or noise conditions. This paper directly addresses these gaps by proposing (i) a lightweight MobileNet-based backbone progressively fine-tuned to balance efficiency and discriminative power, (ii) a dense-head probabilistic Siamese matcher that outputs calibrated probabilities rather than margin-dependent scores, and (iii) a flexible multi-finger recognition setting that allows users to authenticate with any finger without retraining or re-enrollment. Together, these contributions provide a practical and scalable path toward robust finger-vein biometrics on embedded and mobile platforms.

There are five main parts to the paper. The first section, the Introduction, talks about why a lightweight and flexible finger-vein recognition system was needed and lists the main research questions. In Sect. “Related work”, we look at different ways that finger-vein recognition has been done in the past. This includes traditional methods, deep learning-based methods, lightweight model deployment, matching architectures like Siamese and Triplet networks, and multi-finger recognition systems. The proposed framework is made up of a layer-wise progressively fine-tuned MobileNet feature extractor and a Dense-Head Probabilistic Siamese (DHPS) matcher. This is explained in Sect. “Methodology”. This part goes into detail about the data preparation, model architecture, fine-tuning strategy, feature extraction, similarity computation, and training setup. Sect. “Results and discussion”, gives a full review of the proposed system on several datasets, focusing on its accuracy, ability to work well in a variety of imaging conditions, and speed of computation. Finally, Sect. “Conclusion”, goes over the main contributions, emphasizes how the framework could be used in the real world, and talks about ways to make it better in the future, like domain adaptation and multi-sensor fusion.

Related work

Traditional methods for finger-vein recognition

In order to balance accuracy and computational cost, traditional finger vein recognition techniques have concentrated on manually created features and simple coding schemes. As presented in8, the authors reduced data redundancy and avoid segmentation by employing centrosymmetric coding to create compact code-words from image blocks, thereby streamlining the recognition process. By employing a simple code generation method based on block-wise averaging and Hamming distance, the authors of9 sought to remove the complexity of segmentation and enable accurate and efficient matching. The Multi-Orientation Weighted Symmetric Local Graph Structure (MOW-SLGS), which integrates both spatial and directional pixel relationships, was introduced by the authors in10 to improve feature extraction when used in conjunction with an Extreme Learning Machine classifier. The authors of11 developed a GLCM-HOG feature fusion technique with PCA for dimensionality reduction and SVM for classification in order to overcome the difficulties of low contrast and noise in finger vein images. This approach produced a reliable and effective recognition system. When taken as a whole, these studies show that conventional methods can effectively extract significant features from finger vein patterns with minimal computational demands.

Deep learning-based approaches

Recent research in finger vein recognition has demonstrated the necessity of enhancing system accuracy, speed, and practicality for real-world applications. The MSFBF-Net architecture, as explained in12, adeptly integrates global and intricate features while employing lightweight layers and attention mechanisms to maintain model efficiency without compromising accuracy. The authors dealt with the problem of working with small datasets, as shown in13, by simplifying a well-known network (VGG-19), adding Gabor filters to enhance the amount of data, and using transfer learning to speed up the process and make it more accurate. The authors of14 came up with methods that operate with different datasets and a new way to judge image quality that helps get rid of bad samples and cut down on false matches. The authors of15 used a more brain-like strategy that made the system accurate but much simpler by turning images into spike signals and using adaptive neuron behavior.

To enhance the balance between speed and accuracy, the authors of16 developed FMFVNet, a model designed for rapid performance while maintaining efficacy on challenging datasets. The authors of17 developed FV-MViT, a tiny transformer-based model that integrates an innovative loss function and sophisticated feature extraction to achieve remarkable accuracy and speed. The authors of18 extend their investigation beyond the conventional emphasis on fingers and palms to examine wrist vein identification. They accomplish this by employing deep learning to develop a contactless system that operates efficiently on a Raspberry Pi.

Lightweight models and mobile deployment

Lightweight models have become essential for deploying finger vein recognition systems on mobile and embedded devices, where computational resources and power consumption are limited. These models aim to maintain high recognition accuracy while significantly reducing parameter size, memory usage, and inference time. Techniques such as depth wise separable convolutions, attention mechanisms, and model pruning are commonly used to optimize performance. Several researchers have been working on building lightweight but powerful models to make finger vein recognition more useful and effective, especially on devices with limited resources. As shown in13, the authors tried to improve performance on small datasets by making the popular VGG-19 model simpler, adding Gabor filters to mimic different imaging conditions, and using attention mechanisms and transfer learning to make it more accurate, faster, and stronger. The authors of19 came up with a small Siamese network that cleverly combines small ResNet structures with Gabor filters to cut down on the number of parameters while still providing top-notch performance, even with little training data. The authors of20 made FV-EffResNet, a model based on a custom Efficient Residual block that uses smart convolution strategies and modern activation functions to speed up processing without lowering recognition quality. This makes it perfect for use in real time on embedded systems. The authors of21 give a wide-ranging overview of finger vein recognition methods, comparing how different methods deal with important steps like taking pictures, extracting features, and matching, and showing how much more accurate the field has become. Finally, the authors of12 came up with a solution to the problem of big models and low accuracy by creating MSFBF-Net, a network that combines fine and broad features using efficient layers and a multi-attention mechanism to get great results with little effort.

Finger-vein matching techniques (Siamese and triplet networks)

Recent improvements in finger vein recognition have used Siamese and Triplet network architectures to make biometric matching more accurate, reliable, and efficient. A lightweight Siamese network with self-attention is presented in22 to deal with low-quality finger vein images by using multi-scale fusion to get a wide range of features. The authors of23 explored how to deal with rotation and a lack of data by using a modified Siamese CNN with contrastive loss and knowledge distillation. This makes a small model that works well on embedded devices. The authors of24 developed a triplet-classifier GAN that makes fake samples to make a CNN classifier better at telling the difference between things. This is to get around the problem of not having enough training data. The authors of25 improved the Siamese Gabor Residual Network (SGRN), a lightweight architecture that combines Gabor filters with small ResNet modules to verify data sets of small size. Finally 26, developed a CL3A-FV, a self-supervised model based on contrastive learning that learns from unlabeled data using adversarial augmentation and a Siamese encoder. It works well even when there aren’t many labeled datasets.

Probabilistic modeling has also been explored for hand and finger analysis in embedded contexts. For example, the authors of27 proposed an adaptive probabilistic framework that combines Bayesian skin-color modeling with particle filtering to track fingertips robustly under changing illumination and backgrounds, explicitly targeting real-time embedded deployment. While this work focuses on dynamic hand motion cues rather than static vascular patterns, it is conceptually aligned with our approach in treating observations probabilistically to improve robustness and deployment readiness. Our DHPS matcher similarly adopts a probabilistic formulation, but at the verification level: instead of modeling fingertip trajectories, we learn calibrated match posteriors over deep vein embedding, providing decision-level probabilities suitable for resource-constrained biometric devices.

Cross-finger and multi-finger matching systems

By analyzing how recognition accuracy varies when using images from various acquisition devices, the authors sought to determine whether cross-sensor finger vein recognition is feasible, as presented in28. They investigated this on four publicly available datasets and discovered that cross-device situations resulted in a significant decline in performance. In addition, the authors of29 presented a specific multi-sensor finger vein dataset to examine the effects of various devices on recognition. Their goal was to recognize and comprehend the main issues that impede cross-device robustness, such as scaling discrepancies and image misalignment. Aiming for real-time applicability with improved universality and hygiene, the authors of30 presented a secure multi-instance finger vein identification system that combines features from several fingers to improve recognition accuracy and decrease template size. In order to increase accuracy without the need for extra sensors, the authors of31 concentrated on merging vein images from the index, middle, and ring fingers using HOG features and a Bayesian-optimized SVM fusion technique. In order to overcome the drawbacks of single-view systems, the authors of32 introduced a full-view, multi-angle finger vein dataset and suggested MFV-FESNet, a Transformer-based network that combines local and global features from various finger views to improve 3D representation and recognition accuracy.

Recent studies in finger vein recognition offer a range of strengths and limitations. Traditional methods are fast and lightweight, making them suitable for devices with limited resources, but they often lack robustness to variations in lighting, image quality, and sensor type. Deep learning approaches have significantly improved recognition accuracy by capturing complex vein patterns using multiscale features, attention mechanisms, or transformer-based models. However, these methods typically require large datasets and are computationally intensive, posing challenges for deployment in embedded or mobile environments. Lightweight deep networks address some of these issues by reducing model size and inference time, yet they may sacrifice generalization or struggle with noisy data. Systems designed for cross-device or multi-finger scenarios improve versatility but often face performance drops due to inconsistent imaging conditions. Methodology

As presented in Fig. 1, the proposed finger-vein recognition framework is structured to be both highly accurate and resource-efficient, making it suitable for real-time applications and embedded devices. The first step in the system is to fine-tune the MobileNet architecture in several stages. MobileNet was first trained on the large ImageNet dataset. Then, through a series of steps, it was adapted to the MMCBNU finger-vein dataset, which improved its ability to find vein-specific features. This leads to a unique MobileNet-FingerVein model that produces 960-dimensional feature maps that are best for capturing the complex vein structures in datasets like FV-USM, UTFVP, and VERA. The Dense-Head Probabilistic Siamese (DHPS) Matcher uses these feature maps as input. This is a new matching module that uses shared-weight Siamese towers to compare pairs of images. Each tower works on either an anchor or a comparison sample (positive or negative), and the results are compared using several similarity metrics, such as Euclidean, Extended Weighted Distance (EWD), and Manhattan. A dense neural layer takes these distance metrics and sends them to a final classification layer, which gives a calibrated probability that tells you whether the two samples come from the same person. This design, which uses multiple metrics and probabilities, not only improves matching accuracy but also makes it easier to understand and more robust in a variety of acquisition scenarios. So, the integrated system provides a workable, scalable way to use finger vein patterns for secure biometric authentication. This design not only focuses on accuracy and efficiency, but it also includes important new features that set it apart from previous work, building on our earlier research in palmprint recognition6,7.Fig. 1Proposed lightweight finger-vein recognition framework.

Data preparation and dataset description

To evaluate the performance and generalization of the proposed finger-vein recognition framework, four distinct datasets were employed as explained in Table 2. We divided the dataset into three parts: 60% for training, 20% for validation, and 20% for testing. We applied the MMCBNU dataset, which has 6000 images of 100 subjects taken in a controlled lab setting with uniform near-infrared lighting, to train the feature extractor because the imaging conditions were so good and consistent. The FV-USM dataset has 5904 images from 123 subjects taken in two different sessions with a little bit of pose variation. This makes it good for both training and testing the matcher in semi-controlled conditions. The UTFVP dataset has 1200 pictures of 120 people taken in indoor settings with soft shadows, which added variability in lighting and helped train and test the matcher even more. Lastly, the VERA dataset has 440 low-resolution images of 110 people taken with a noisy webcam. Fine-tuning MobileNet

The proposed system starts with a layer-wise progressive fine-tuning (Gradual Unfreezing) strategy to make MobileNet, a lightweight and efficient convolutional neural network can work better for recognizing finger veins. At first, we use the default MobileNet architecture that has been trained on ImageNet. This architecture is a general-purpose feature extractor that has been trained on more than a million images from 1000 classes. The next step is to replace the ImageNet classifier head with a 100-class output layer that is specific to the MMCBNU dataset. This lets the model start to adjust to the different visual patterns in finger-vein images. Once the network is set up, it is fine-tuned even more by updating both the classifier layers and the convolutional feature extractor. This makes it better at learning task-specific features. This gradually adjusted MobileNet is then turned into a dedicated feature extractor, keeping only the second-to-last 960-dimensional feature map. This last version, called MobileNet-FingerVein, is designed to give small, unique embedding that are good for biometric matching, especially in environments where computing power is limited. We selected MobileNet as the backbone after screening multiple ImageNet-pretrained CNNs (VGG16/VGG19, ResNet152, DenseNet201, InceptionV3, and MobileNet) on MMCBNU-6000 (100-class identity classification), then optimizing the winning candidate via layer-wise progressive unfreezing. MobileNet-V1 offers a strong Pareto balance between accuracy and deployability on embedded targets for three reasons:

Deployment constraints and footprint. Depthwise separable convolutions yield a compact ~ 13 MB model and cache-friendly compute pattern. On a Raspberry Pi 4B (Cortex-A72, 4 GB RAM, CPU-only), MobileNet-FingerVein-18 indicate per-image inference in the tens of milliseconds, consistent with our target of sub-second end-to-end verification; a full embedded benchmark will be included in future work. Layer-wise Progressive specialization without overfitting. While MobileNet began with the weakest baseline F1, its structure responded best to fine-grain, layer-wise unfreezing, allowing us to lift the MMCBNU classification F1 to 97.4% while keeping the extractor lightweight. This layer-wise progressive scheme retained low-level generic filters and adapted only the necessary higher layers to vein textures, which was critical given the modest dataset sizes.Reproducibility and ecosystem maturity. MobileNet is widely implemented and consistently quantizable across major frameworks and runtimes, easing downstream deployment and replication. Although newer families (EfficientNet-Lite, ShuffleNet, GhostNet) are promising, our screening plus layer-wise progressive fine-tuning produced the best accuracy–latency trade-off for our constraints. Exploring these newer backbones is left as future work.

MobileNet-finger vein feature extraction

After fine-tuning the MobileNet model for finger-vein recognition, it is used as a dedicated feature extractor on several benchmark datasets. At this point, the trained MobileNet-FingerVein model takes in finger-vein images from the FV-USM, UTFVP, and VERA datasets. The model processes each image and gives back a small 960-dimensional feature map that shows the unique vascular patterns on each finger. This consistent feature representation makes sure that the model works well on a wide range of datasets with different conditions for getting the data and image quality. The system keeps its computational efficiency by using the same backbone architecture for all datasets. This allows it to extract high-quality features, which are very important for strong biometric matching.

Multiple established convolutional neural networks pre-trained on ImageNet—including VGG16, VGG19, ResNet152, DenseNet201, InceptionV3, and MobileNet-V1—were evaluated as candidate feature extractors. Despite MobileNet-V1’s notably superior efficiency—boasting the smallest memory footprint (~ 13 MB) and fastest inference time (~ 80 ms per image) as demonstrated in Fig. 2—it initially achieved the lowest classification F1-score. Dense-Head Probabilistic Siamese (DHPS) matcher

The proposed methodology creates a finger-vein recognition pipeline that is both effective and adaptable for use in the real world, especially on devices with limited resources. First, a MobileNet backbone is gradually improved. It starts with a default model that was trained on ImageNet, then it is trained more on the MMCBNU dataset, and finally it is tailored to work with finger-vein data. This creates a small but powerful feature extractor called MobileNet-FingerVein. It can make 960-dimensional feature maps from several public datasets, including FV-USM, UTFVP, and VERA. Then, these extracted features are sent to a new matcher called Dense-Head Probabilistic Siamese (DHPS). The matcher compares an anchor image to either a positive or negative sample using a Siamese network with shared weights. The system uses several similarity measures, such as Euclidean, Extended Weighted Distance (EWD), and Manhattan, to figure out how far apart feature embedding are. A dense head and a final classification layer work together to process these distances and come up with a calibrated probability that tells us if the input pair belongs to the same person. This method is meant to be very accurate, cheap to compute, and able to work well with many different datasets. This makes it perfect for mobile and embedded biometric authentication systems. Stage II applied traditional Siamese networks that use contrastive or triplet loss. It introduces the DHPS, a modified architecture that is based on the characteristics of the pre-trained MobileNet-FingerVein-18 extractor and is inspired by our previous Siamese network design for cross-palmprint recognition. From a probabilistic viewpoint, the DHPS head implements a logistic model over similarity features \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$z$$\end{document} (concatenated distances and element-wise differences), yielding \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$${p}_{\theta }\left(y=1\right| z) = \sigma \left({w}^{T}z+b\right)$$\end{document}. Minimizing binary cross-entropy is therefore equivalent to maximum-likelihood estimation of calibrated posterior match probabilities for genuine (\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$y=1$$\end{document}) and impostor (\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$y=0$$\end{document}) pairs. In contrast, contrastive and triplet losses impose fixed geometric margins in the embedding space; they do not directly optimize posterior probabilities and are highly sensitive to margin choice and hard-negative mining. Our experiments showed that the probabilistic BCE objective leads to more stable convergence and yields scores that transfer more reliably across datasets and operating points, which explains the observed generalization gains.

Loss function and pair sampling

The network outputs calibrated match probabilities because training uses binary cross-entropy loss. This makes it simple to set thresholds when deploying. This method gets rid of contrastive losses that depend on the margin, which are often sensitive to hyperparameters and need careful negative mining. A sampling scheme with anchor-positive–negative triplets makes pairs. It doesn’t matter what finger they use; the anchor and positive images come from the same person. The negative image comes from a different person. This is a big step forward from earlier research that often used fixed fingers to match people. Now the system can recognize people with any finger. The triplets are split into two labeled pairs, real and fake, to fit the binary cross-entropy framework. Training employs Adam optimization with a learning rate of \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\left(1 \times {10}^{-4}\right)$$\end{document}, mini-batches of 300 balanced pairs, and early stopping after 30 epochs without validation improvement.

We implement the matcher in TensorFlow/Keras on Google Colab with an NVIDIA T4 GPU, optimizing ‘binary_crossentropy’ using optimizer = ‘Adam’ (default parameters). Training uses balanced mini-batches of genuine/impostor pairs constructed from anchor–positive–negative triplets (any finger for the same subject), with epochs = 100, early stopping (patience = 30), and batch_size = 32. Results and discussion

This section presents a thorough evaluation of the proposed finger-vein recognition framework across multiple publicly available datasets, emphasizing accuracy, robustness, and computational efficiency. The experiments answer important questions about how well the layer-wise progressive fine-tuning strategy works, how different similarity measures affect the proposed DHPS matcher, and whether the system can be used in a variety of acquisition situations.

Feature extractor fine-tuning effectiveness

Layer-wise Progressive fine-tuning of the MobileNet backbone yielded a substantial boost in classification performance, elevating the F1-score from a weak baseline (≈0.02) to a highly competitive 0.974 on the MMCBNU 6000 dataset as shown previously in Fig. 3. This demonstrates that layer-wise unfreezing enables the model to effectively specialize in vein texture features without incurring overfitting, thus preserving the lightweight nature required for embedded deployment. This incremental training approach mitigates the trade-off commonly observed between model complexity and accuracy in biometric applications, affirming the value of carefully balancing adaptation depth. The resulting MobileNet-FingerVein-18 extractor provides a robust foundation for downstream matching, as evidenced by subsequent experiments.

Computational efficiency and deployment implications

Maintaining a lightweight feature extractor (~ 13 MB) combined with a compact dense head ensures inference latency within 200 ms per image pair on commodity hardware. This level of efficiency aligns with the demands of embedded devices such as smart rings, biometric door locks, or mobile authentication tokens. This efficiency does not come at the expense of accuracy, making the system uniquely suited to resource-constrained deployments—a critical consideration absent in many previous finger-vein recognition studies.

The compact extractor (~ 13 MB) and dense head support ≤ 200 ms per pair on commodity CPUs, aligning with interactive authentication (≤ 500 ms target) in smart locks, kiosks, and mobile apps. On-device execution avoids network dependency; optional edge-server inference can be used where higher throughput or auditing is required.

The system supports single- or multi-finger enrollment per user. Multi-finger profiles increase robustness to temporary occlusions (e.g., bandages) and user convenience. Enrollment quality control (sharpness/contrast checks) and optional periodic refresh (e.g., every 6–12 months) mitigate slow domain drift. Template/storage model. We store embedding (960-D) and metadata (finger label, quality score). Templates can be held locally (on-device secure storage) or centrally (encrypted at rest, access-controlled). Cancellable-biometric transforms and template revocation lists can be added in regulated settings. Liveness and spoofing. Vein biometrics are inherently resistant to surface spoofs; nevertheless, we recommend liveness add-ons for high-assurance deployments such as micro-movement prompts. Practical mitigations include (i) sensor-specific normalization, (ii) lightweight domain adaptation using small target samples, and (iii) optional multi-spectral capture when available.

Embedding should be encrypted at rest and in transit; audit trails should avoid storing raw images unless legally required. Where applicable, deployments should map to local data-protection frameworks and offer transparent user consent, opt-out, and revocation procedures.

In deployments, multi-finger profiles provide resilience to temporary finger conditions (e.g., wounds or bandages), allowing users to switch fingers without re-enrollment while maintaining latency and accuracy targets. Limitations and future directions

While the system exhibits strong performance across datasets, the reduced accuracy on noisier datasets like VERA highlights the continued challenge of robust biometric recognition under unconstrained conditions. Although our focus is on achieving calibrated and accurate verification under embedded constraints, post-hoc interpretability for similarity-based biometric matchers (Siamese/DHPS) remains non-trivial. Techniques such as SHAP/LIME on pixel space can be misleading for pairwise matching; more suitable directions include (i) saliency or Grad-CAM visualization on the extractor to localize vascular regions that most influence embedding, and (ii) SHAP-style analyses on the 960-D embedding and the dense head to quantify feature contributions. We consider explainability a valuable avenue for future work aligned with deployment transparency. The present evaluation is intentionally conducted on standard clean benchmark images without synthetic corruption (e.g., bandage-like occlusions, extreme pose, or sensor noise), as our first goal is to establish a calibrated, multi-finger, lightweight baseline. Accordingly, the reported EER and F1 values should be viewed as performance under controlled, best-case acquisition conditions. In future work, we will incorporate robustness mechanisms that are explicitly constrained to preserve the embedded-friendly profile of our system. Promising directions include: (i) low-cost geometric and photometric augmentations (small rotations, translations, and NIR-consistent contrast/blur) during training, (ii) structured occlusion masks mimicking bandages or partial finger coverage, (iii) test-time strategies and decision-level fusion across multiple enrolled fingers, and (iv) evaluating alternative compact backbones or shallow calibration heads under strict parameter and latency budgets. These extensions are designed to improve tolerance to realistic variations without resorting to heavyweight architectures that would compromise on-device deployment.

Conclusion

This paper describes a new, fast, and adaptable finger-vein recognition system that can be used in places with limited resources. We first created a MobileNet-based feature extractor called MobileNet-FingerVein-18 that gets better and better at its job in two stages. This feature extractor is small and powerful enough to work on embedded devices. Then we added the Dense-Head Probabilistic Siamese (DHPS) matcher. This matcher uses calibrated binary cross-entropy loss and several distance metrics in a dense nonlinear head to make strong, probabilistic matching decisions. Our many tests on three different public finger-vein datasets showed that the proposed system has the best recognition performance, with error rates as low as 0.002 and F1-scores over 99% on the FV-USM dataset. The method stays very accurate even when using the hard UTFVP and VERA datasets, which shows that it can be used in many different situations. Also, the fact that the system can recognize a person using any finger is a big step forward in biometric flexibility compared to older single-finger systems. The proposed framework is a practical solution for new biometric use cases in wearable technology and IoT security because it combines a 13 MB model size with inference latency that is good for real-time embedded applications. To encourage more progress, we promise to make the pre-trained MobileNet-FingerVein-18 feature extractor available to the public through Hugging Face. This will provide a base for future research in finger-vein biometrics.

In the future, we will look into how to make the system more robust in extreme imaging conditions through advanced augmentation and domain adaptation. We will also look into how to make authentication more reliable by combining data from different sources.
