Background

Escherichia coli is a bacterium of major clinical and public health importance, existing as both a commensal and a pathogen responsible for a wide spectrum of intestinal and extraintestinal diseases [1, 2]. Its pathogenic diversity arises from genomic plasticity, which has given rise to distinct pathotypes—including enteropathogenic (EPEC), enterohemorrhagic (EHEC), and extraintestinal pathogenic (ExPEC) variants—each with specialized virulence mechanisms [3, 4]. The global dissemination of successful, often multidrug-resistant clones underscores the critical need for effective genomic surveillance [5].

Whole-genome sequencing (WGS) provides the data necessary for high-resolution characterization [6]. Fully leveraging WGS for E. coli requires the application of multiple complementary genotyping methods: Multi-Locus Sequence Typing (MLST) for strain classification [7], in silico serotyping for O and H antigen determination [8], CH typing (fumC/fimH) for finer discrimination [9], Clermont phylogrouping for evolutionary context [10, 11], and comprehensive screening for antimicrobial resistance (AMR) genes and virulence factors [12].

To perform these analyses, researchers currently rely on a combination of specialized tools and services. For instance, in silico serotyping is commonly performed with tools like ECTyper [13] or web services from the Center for Genomic Epidemiology (CGE) [8, 9], while gene screening is done with tools like ABRicate [14]. Available pipelines for microbial genomics like Bactopia [15] are often designed for broad applicability across taxa, rather than for the specific, integrated combination of genotyping methods needed for dedicated E. coli surveillance. The recently added Escherichia module in Kleborate [16] provides several useful functions, including Clermont phylotyping, pathovar assignment, and Shiga toxin typing. However, it does not include CH typing (fumC/fimH), cross-genome pattern discovery, or an interactive HTML report that consolidates all results across multiple genomes. Consequently, generating a comprehensive genotype still involves using several independent resources and manually integrating their outputs—a process that can delay synthesis and interpretation, particularly in time-sensitive scenarios.

To address this integration challenge, we present EcoliTyper, a computational pipeline for the consolidated genomic analysis of E. coli. EcoliTyper automates a comprehensive set of analyses—including species confirmation and assembly quality control, MLST, in silico serotyping, CH typing, Clermont phylogrouping, pathotype classification, and screening for antimicrobial resistance genes, virulence factors, plasmid replicons, as well as biocide and heavy metal resistance markers (bacmet) —within a single, local workflow. The pipeline synthesizes these discrete results, performing cross-sample analyses such as gene frequency calculation. It further provides epidemiological context through an integrated, curated database that links typing results to high-risk clones and characteristic resistance profiles (see supplementary file 1). Finally, EcoliTyper compiles all results into a unified HTML report (see supplementary file 2), publication-ready visualizations, and structured data files (TSV, JSON), thereby streamlining the transition from raw sequence data to interpreted genomic intelligence.

Method and implementation

Pipeline architecture and distribution

EcoliTyper is implemented as a modular, command-line pipeline in Python (compatible with versions 3.8 to 3.14). Its architecture employs a centralized orchestrator that manages the execution and data flow between nine core analytical modules (Fig. 1). To ensure reproducibility and ease of deployment, the entire pipeline, including all software dependencies and curated databases, is packaged and distributed as a single, platform-agnostic Conda package.

Input requirements, quality control, and species confirmation

EcoliTyper accepts assembled E. coli genomes in FASTA format (e.g., fna, fasta, fn, fa). The pipeline is executed via a single command, which accepts a directory path containing input files or a glob pattern for batch processing. This design choice keeps memory usage low (as the pipeline does not perform assembly) and places the responsibility for assembly quality control on the user. Researchers can therefore choose their preferred assembly strategy (e.g., de novo or reference-based) and evaluate their own QC metrics (contiguity, completeness, contamination) using dedicated tools before running EcoliTyper. By decoupling assembly from genotyping, the pipeline remains lightweight and avoids imposing a single assembly standard, while ensuring that only high-quality inputs are used.

Quality control and species confirmation. Before typing, EcoliTyper performs a mandatory quality assessment of each input FASTA file using Biopython [17]. The pipeline computes fundamental assembly metrics: total length, number of contigs, N50, GC content, and percentage of ambiguous bases. For optimal performance of the downstream typing tools, we recommend that input assemblies exhibit good overall quality, characterised by a high N50, a low number of contigs, and a total genome length consistent with typical E. coli (approximately 4.5–5.7 Mbp). Assemblies that are highly fragmented or contain excessive ambiguous bases may lead to incomplete typing calls.

In parallel, EcoliTyper confirms the species identity of each genome using Average Nucleotide Identity (ANI) with fastANI v1.34 [18]. The query genome is compared against a curated panel of four reference genomes: Escherichia coli K-12 MG1655, Shigella flexneri 2a, Klebsiella pneumoniae, and Salmonella enterica. A sample is considered confirmed as E. coli (including Shigella, which is treated as E. coli for typing purposes) if the best ANI match is ≥ 95% and the species name contains “Escherichia”, “E. coli”, or “Shigella”. If the best match belongs to a different genus (e.g., Klebsiella) with ANI ≥ 95%, the pipeline issues a warning. Additionally, contamination is suspected when the second-best ANI > 90% and the difference between the top two ANI values is < 5%; a corresponding warning is included in the final HTML report. This integrated QC step ensures that only true E. coli genomes proceed to the downstream genotyping modules.

Analytical modules and parameters

EcoliTyper integrates the following analytical modules, each configured with optimized, species-specific parameters and thresholds. All underlying reference databases are bundled with the Conda package, and users can update them with a single command to ensure currency.

To balance reproducibility with ease of maintenance, the Conda environment specifies dependencies using flexible version constraints (e.g., >=1.2.0 rather than hardcoded versions). This design allows users to automatically receive bug fixes and database updates when they update their Conda environment. If a newer version of a dependency introduces an incompatibility, users can manually pin the previous working version in their local environment. This approach avoids the rigidity of hardcoded versions while still providing a stable, tested baseline for routine analyses.

MLST analysis implements the Achtman scheme using the MLST (version ≥ 2.32.2) tool (https://github.com/tseemann/mlst) and the bundled PubMLST database [19]. The module performs BLAST-based allele calling for the seven housekeeping genes (adk, fumC, gyrB, icd, mdh, purA, recA), reporting the sequence type, allelic profile, and alignment coverage and identity metrics.

Serotype determination for O and H antigens is performed using SerotypeFinder (v2.0.1) from the CGE. The module queries contigs against the bundled SerotypeFinder database (https://bitbucket.org/genomicepidemiology/serotypefinder_db/) via BLAST [20] (version ≥ 2.13.0). A positive call requires alignments meeting minimum thresholds of ≥ 90% coverage and ≥ 90% nucleotide identity to reference sequences.

CH Typing for high-resolution strain discrimination analyzes the fumC and fimH loci using a custom BLAST-based module and the curated CGE CH type database (https://bitbucket.org/genomicepidemiology/chtyper_db/). Allele assignment follows thresholds of ≥ 80% coverage and ≥ 80% identity.

Clermont Phylogrouping executes the ezClermont tool (version ≥ 0.7.0) implementation of the 2013 Clermont scheme. This method uses BLAST to detect the presence/absence of marker genes (chuA, yjaA, TspE4.C2, arpA) and assigns genomes to one of the eight main phylogroups (A, B1, B2, C, D, E, F, G).

Comprehensive gene screening is performed by two complementary modules. The ABRicate module (version ≥ 1.2.0) screens against ten curated databases (CARD [21], ResFinder [22], Bacmet [46], NCBI [12], ARG-ANNOT [23], MEGARES [24], VFDB [25], EcoH [26], Ecoli_VF [27], PlasmidFinder [28]) using standard thresholds (≥ 80% coverage, ≥ 80% identity; ≥95% identity for plasmid replicons; PlasmidFinder identifies replicon markers, not complete plasmids). The NCBI-AMRFinderPlus module (≥ v4.2.7) is executed to identify both acquired resistance genes and relevant chromosomal mutations, providing comprehensive resistance profiling.

Pathotype classification Using the virulence gene profiles obtained from the VFDB and Ecoli_VF databases, EcoliTyper automatically assigns diarrheagenic pathotypes according to the guidelines implemented in PathotypeR (https://github.com/kevinsblake/PathotypeR). The pipeline classifies samples as STEC, EPEC, EHEC, EAEC, ETEC, DAEC, or EIEC based on the presence of specific combinations of virulence genes (e.g., stx1/stx2 with/without eae, aggR, lt/sta, ipaH, etc.). Samples may be assigned multiple pathotypes (e.g., EHEC-EAEC) when criteria for more than one pathotype are met.

Parallel execution architecture

The pipeline employs a hybrid parallel architecture to maximize computational efficiency. This strategy incorporates three distinct approaches: Inter-module parallelism, where five analytical modules (MLST, serotyping, CH typing, phylogrouping, ABRicate) execute concurrently across samples using Python’s ThreadPoolExecutor with dynamic load balancing; Intra-module parallelization, where individual modules implement optimized threading—the ABRicate module processes multiple databases and genomes simultaneously, while NCBI-AMRFinderPlus utilizes internal multi-threading; and Strategic sequential execution, where memory-intensive operations, such as lineage database generation and final report consolidation, are sequenced to prevent resource exhaustion.

Data synthesis and intelligent interpretation

A core innovation of EcoliTyper is its automated synthesis and interpretation layer, which consists of two complementary systems.

i.Cross-genome pattern discovery synthesizes results across all input genomes to provide a population-level overview. For every database screened by ABRicate and for NCBI-AMRFinderPlus results, the pipeline performs gene frequency analysis and distribution mapping. It calculates the total number of hits, condenses them into a non-redundant list of unique genes, and automatically calculates the prevalence (frequency) of each gene within the analyzed population. Concurrently, it records the specific genome in which each gene is found, enabling researchers to immediately identify prevalent resistance cassettes, core virulence factors, and successful plasmid replicons across their dataset.ii.Rule-based clinical risk assessment provides a secondary layer of interpretation by scanning results to flag high-consequence determinants. The ABRicate module employs rule-based pattern matching using base gene name extraction (e.g., “blaCTX-M-15” → “blaCTX”) to capture all variant forms of critical genes. It implements a hierarchical risk categorization with priority levels (CARBAPENEMASE > ESBL > COLISTIN-RES > OTHER CRITICAL) and cross-references findings across the ten curated databases while applying consistent quality thresholds (≥ 80% coverage/identity). This system automatically highlights high-priority resistance markers such as carbapenemases (e.g., blaKPC, blaNDM), extended-spectrum β-lactamases (e.g., blaCTX-M), and plasmid-mediated colistin resistance genes (mcr-1 to mcr-10).

Lineage reference database for epidemiological contextualization

A key feature of EcoliTyper is its integrated lineage reference database, a manually curated knowledge base that provides immediate clinical and public health context for genomic findings. This structured repository synthesizes data from published sources to transform typing results into actionable epidemiological intelligence. The database encompasses major high-impact sequence types—categorized by clinical significance into high-risk clones (e.g., ST131, ST1193), resistance-associated lineages (e.g., ST405, ST410), and pathotype-specific variants (e.g., ST11, ST10)—along with their associated metadata. This includes predominant serotypes, phylogroups, pathotype classifications, and characteristic resistance profiles, such as carbapenemase carriage. During analysis, the pipeline automatically queries this database, providing researchers with instant context on whether their isolates represent known pandemic clones, emerging threats, or novel lineages requiring further investigation.

Gene-centric HTML reporting and cross-genome pattern synthesis

To facilitate interpretation across multiple genomes, EcoliTyper generates an interactive HTML report that consolidates all typing, AMR, and virulence results into a single, searchable interface. This reporting module is adapted from our previously described StaphScope pipeline [29]. It presents gene-centric tables, where each antimicrobial resistance or virulence gene is shown only once, accompanied by the list of genomes in which it was detected. This design allows users to immediately identify prevalent genes, rare high-risk determinants, and their distribution across the dataset. The report includes genome-wide search boxes, filter buttons (e.g., by gene class or pathotype), and a cross-genome pattern discovery section that automatically highlights co-occurrence of critical resistance and virulence genes. By transforming fragmented output from multiple tools into a unified, interactive view, this reporting layer enables rapid epidemiological insight without manual data aggregation.

Visualization and reporting

A dedicated Visualization Module generates publication-ready figures from the synthesized data using modern Python libraries (Matplotlib, Seaborn). Outputs include stacked bar charts of gene prevalence, pie charts of phylogroup distribution, and violin plots of quantitative metrics, exported in PDF, SVG, and PNG formats. All results are compiled into an interactive HTML report alongside structured data files (e.g., TSV, JSON) suitable for programmatic access and downstream analysis.

Robust error handling and state management

The pipeline implements comprehensive exception handling with automated cleanup procedures. Signal handlers capture user interrupts (e.g., Ctrl + C) to execute emergency cleanup, preventing orphaned processes and maintaining data integrity. Thread-safe output management prevents log interleaving during parallel execution, while modular isolation ensures that individual component failures do not compromise the entire analysis. The system maintains state through checkpointing, allowing for graceful recovery from interruptions.

Performance optimization and resource management

EcoliTyper employs dynamic resource detection and allocation via Python’s psutil library. The pipeline automatically adjusts its thread usage based on the available CPU cores and RAM at runtime, allowing it to perform efficiently on a range of hardware, from standard laptops to high-performance computing nodes. This design ensures that the pipeline can be used in shared-resource environments without manual configuration, while also maximising throughput when dedicated resources are available. Performance scales with genome characteristics (assembly size and accessory genome complexity) and the number of samples processed in parallel.

Availability

EcoliTyper is open-source under the MIT license and available at https://github.com/bbeckley-hub/EcoliTyper. Detailed installation instructions are provided in the repository’s documentation. Installation can be performed via Conda or Docker/Singularity. The pipeline is designed to run efficiently on standard hardware (minimum 2 CPU cores and 4 GB RAM; 8 GB RAM recommended for optimal performance).

Results and discussion

The analytical fidelity of EcoliTyper was assessed using a benchmark of reference strains with established genotypes. The pipeline achieved 100% concordance with standalone tools and CGE established typing schemes, accurately calling the sequence type, serotype, and phylogroup for E. coli K−12 MG1655, O157:H7, and O18ac: H7 (Table 1). This result validates the precision of EcoliTyper’s integrated MLST, Serotyping, and Phylogrouping algorithms.

Validation with Reference Genomes

Typing of diverse clinical and reference isolates

We next evaluated EcoliTyper’s ability to characterise collection of 60 randomly selected E. coli genomes, simulating a real-world surveillance scenario. The pipeline successfully completed all analyses for every genome, demonstrating its robustness on a moderately sized dataset. Below we present the results for each analytical module. All raw data, including per-genome gene lists, and accessions are provided in Supplementary File 2 the sample overview section.

Quality control and species confirmation

Before typing, EcoliTyper performed quality control and species confirmation step using fastANI. All 60 genomes passed the species check (best match to E. coli or Shigella with ANI ≥ 95%), confirming their identity as members of the E. coli/Shigella species complex. No contamination was flagged (second-best ANI never exceeded 90% with a difference < 5%). Assembly quality metrics (N50, contig count, total length) are summarised in Supplementary Table S1. Most assemblies showed N50 values above 5 Mbp and low contig counts, indicating good assembly quality suitable for downstream typing.

Multi-locus sequence typing

MLST module identified 14 distinct sequence types (STs) among the 60 genomes. ST21 was the most frequent, found in 41 genomes (68.3%). ST29 occurred in three genomes (5.0%), ST95 and ST48 each in two genomes (3.3%), and the remaining STs each in a single genome (1.7%). Two genomes had an unknown ST (designated “ST-”). Acquired antimicrobial resistance genes distribution

EcoliTyper screens for AMR genes using multiple databases (ResFinder, AMRfinder, NCBI, ARG-ANNOT, MEGARES, CARD). Table 4 lists the acquired AMR genes with prevalence ≥ 5% across the 60 genomes. The most frequent acquired resistance gene was aph(6)-Id, detected in 16 genomes (26.7%), followed by tet(A) (12 genomes, 20.0%). β-Lactamase genes blaTEM-1B and blaTEM-1 were found in eight genomes each (13.3%). High-priority resistance determinants were also detected: mcr-1.1 (colistin marker) in three genomes (5.0%), blaCTX-M-1 and blaCTX-M-14 (ESBLs) each in one genome (1.7%). Chromosomal quinolone resistance mutations gyrA_S83L were present in five genomes (8.3%). The full AMR gene list per genome is in Supplementary File 2, amr section.

A notable advantage of screening multiple databases is the increased sensitivity for detecting variant alleles. For example, blaTEM variants were captured by ResFinder (blaTEM-1B, blaTEM-1 A, blaTEM-1 C), AMRfinder (blaTEM-1, blaTEM-176), NCBI (blaTEM-150, blaTEM-235), and ARG-ANNOT (blaTEM-105, blaTEM-150, blaTEM-135, blaTEM-176). Similarly, colistin resistance genes mcr-1.1 and mcr-5.1 were detected by all six databases, albeit with slight differences in naming and count (e.g., MEGARES and CARD captured an additional MCR entry not recorded by ResFinder). This redundancy strengthens the confidence in the presence of these critical resistance determinants.

Virulence genes distribution

EcoliTyper screens for virulence factors using VFDB and Ecoli_VF. Table 5 summarises selected virulence genes with prevalence ≥ 10% (complete list in Supplementary File 2, virulence section). The intimin gene eae was present in 50 genomes (83.3%), and the Shiga toxin gene stx2A in 20 genomes (33.3%). The aerobactin siderophore genes iucA-iucD were detected in 51 genomes (85.0%). The enterobactin biosynthesis genes entA-entF and the outer membrane protein ompA were present in all 60 genomes.

Biocide and heavy metal resistance

EcoliTyper screens for biocide and heavy metal resistance genes using the Bacmet2 database. The arsenic resistance genes arsT, arsC, arsR, arsB, and arsP were present in > 90% of genomes, with arsT and arsC in all 60 genomes (100%). Mercury resistance genes (merR, merT, merP, merC, merA, merD, merE) were found in 8–9 genomes (13.3–15.0%). The oxidative stress regulator soxR and the multidrug efflux regulator baeR were present in all genomes. The high prevalence of arsenic resistance may reflect environmental exposure or co-selection with other resistance determinants. The full list of all detected Bacmet genes is provided in Supplementary File 2, Bacmet section.

Integrated E. coli Ultimate HTML report

All results from the MLST, serotyping, phylogrouping, CH typing, pathotype, AMR, virulence, plasmid, and biocide analyses are automatically compiled into a single interactive HTML report (see Supplementary File 2 for a representative screenshot). The report consolidates the key output tables into a searchable interface, allowing users to filter by gene class, highlight specific genomes, and explore cross-genome patterns (e.g., co-occurrence of mcr-1.1 with particular STs or serotypes). This integrated view removes the need to manually collocate outputs from multiple independent tools. Users can export any table as CSV or download the full JSON data for custom analyses.

Performance on different hardware configurations

To evaluate the computational efficiency of EcoliTyper, we measured its runtime on two hardware setups using a set of 60 E. coli assemblies of varying sizes (representative of routine surveillance). The pipeline was run with its default settings, and the reported times include all modules: species confirmation, MLST, serotyping, CH typing, phylogrouping, pathotype classification, AMR/virulence/plasmid/bacmet screening, and final HTML report generation.

High-performance system (16 CPU cores, 16 GB RAM)

Because EcoliTyper uses the Python psutil library to dynamically detect and allocate available CPU and RAM, its runtime is affected by competing processes. We performed two sets of runs. In the first set, several other applications were left open (simulating a typical shared-use workstation), resulting in a total runtime of 2 h 9 min for 60 genomes. When all non-essential applications were closed, leaving only the terminal open, the same analysis completed in 53 min 1 s. This difference illustrates the pipeline’s ability to adapt to available resources: more background load leads to longer processing times, whereas dedicated resources yield faster completion.

For smaller batches under dedicated conditions, runtimes were: 1 sample – 2 min 58 s (another single sample took 6 min 3 s under shared load), 10 samples – 9 min 48 s, 20 samples – 17 min 58 s.

Low-end system (2 CPU cores, 8 GB RAM)

To assess accessibility for researchers with limited hardware, we ran the pipeline on a machine with 2 cores and 8 GB RAM, with no other applications running. Runtimes were: 1 sample – 9 min 47 s, 10 samples – 1 h 0 min 30 s, 20 samples – 2 h 58 min 35 s.

These data demonstrate that EcoliTyper can be used effectively on both high-performance workstations and more modest hardware, with runtime scaling predictably with the number of genomes and available CPU cores. The results also highlight the importance of minimising background load when maximum speed is desired. Figure 4 summarises the runtimes on both hardware configurations.

EcoliTyper integrates several established E. coli genotyping methods into a single workflow, providing outputs in multiple formats. The pipeline includes a species confirmation step using fastANI, which helps ensure that only genuine E. coli genomes are analysed. The interactive HTML report consolidates typing, AMR, and virulence results, allowing users to explore gene frequencies and cross-genome patterns without manual data wrangling.

The demonstration on 60 public genomes illustrates the tool’s ability to characterise a moderately sized dataset. The observed predominance of ST21, serotype O26:H11, phylogroup B1, and CH type fumC4:fimH440 is consistent with a known EHEC lineage [44, 45]. The detection of acquired AMR genes, including mcr-1.1 and ESBLs, highlights the utility of screening multiple databases to capture variant alleles.

As with any bioinformatics pipeline, the accuracy of EcoliTyper depends on the completeness of the underlying reference databases. Novel alleles or resistance genes not yet represented in these resources will not be detected. The pipeline requires assembled genomes, which limits its use for raw read-only workflows. Periodic updates to the bundled databases are provided via a single command, and users can install the tool via Conda or Docker.

Limitations

EcoliTyper is subject to several constraints inherent to its specialized design and analytical approach. The pipeline is exclusively optimized for E. coli and requires assembled genome sequences as input, limiting its utility for poly-microbial contexts or workflows beginning with raw reads. The accuracy of all typing results is contingent on the completeness of the underlying reference databases; novel alleles, serotypes, or resistance genes not yet included in these curated resources will not be detected. The integrated lineage database is a manually curated resource designed to provide immediate context for a focused set of globally significant clones and is not an exhaustive catalog. The project repository will host periodic updates to core typing databases and this lineage resource. Finally, as with all in silico tools, EcoliTyper’s predictions represent genotypic evidence, and confirmatory phenotypic testing remains necessary for definitive clinical or public health decisions.

Conclusion

EcoliTyper integrates multiple E. coli genotyping methods into a single pipeline. It provides structured, multi-format outputs and automated cross-genome pattern discovery, which may facilitate isolate characterisation for surveillance and epidemiological studies.
