Closed-Loop LLM Discovery of Non-Standard Channel Priors in Vision Models
Tolgay Atinc Uzun, Dmitry Ignatov, and Radu Timofte

Abstract
Channel configuration search—the optimization of layer specifications such as layer widths in deep neural networks—presents a complex combinatorial challenge constrained by tensor shape compatibility and computational budgets. We posit that Large Language Models (LLMs) offer a transformative approach to Neural Architecture Search (NAS), capable of reasoning about architectural code structure in ways that traditional heuristics cannot. In this paper, we investigate the application of an LLM-driven NAS framework to the problem of channel configuration. We formulate the search as a sequence of conditional code generation tasks, where an LLM refines architectural specifications based on performance telemetry. Crucially, we address the data scarcity problem by generating a vast corpus of valid, shape-consistent architectures via Abstract Syntax Tree (AST) mutations. While these mutated networks are not necessarily high-performing, they provide the critical volume of structural data required for the LLM to learn the latent relationship between channel configurations and model performance. This allows the LLM to internalize complex design patterns and apply them to optimize feature extraction strategies. Experimental results on CIFAR-100 validate the efficacy of this approach, demonstrating that the model yields statistically significant improvements in accuracy. Our analysis confirms that the LLM successfully acquires domain-specific architectural priors, distinguishing this method from random search and highlighting the immense potential of language-driven design in deep learning.

A primary challenge in applying LLMs to NAS is the lack of domain-specific training data.
Standard repositories do not contain sufficient variations of executable architectures to train a model on structural design.

Training on the programmatically generated dataset enables the model to learn the syntax required for execution and the relationship between channel dimensions and performance.
The model therefore functions as an optimizer that iteratively refines architectures to improve accuracy.

Related Work

2.1
Neural Architecture Search

Conventional strategies for NAS including reinforcement learning
[
1
]
and differentiable architecture search
[
2
]
have automated the engineering of model structures.
These methods typically require the prior definition of restrictive supernets or search spaces.
Recent research has investigated the use of generative models for architecture definition.
However, these approaches face challenges regarding the discrete and constrained nature of valid neural network code.
Reinforcement learning methods formulate network generation as a sequential decision process operating on a predefined vocabulary of layers and connections.
This formulation restricts the search to a known subspace.
The proposed method treats architecture definition as open-ended code modification at the token level.
This approach enables flexible exploration of the design space and facilitates the discovery of architectural patterns not explicitly encoded in the search space definition.

2.2
Automated Channel Pruning and Model Compression

The specific problem of optimizing channel configurations has a rich history in model compression.
He et al.
[
28
]
propose using a deep deterministic policy gradient reinforcement learning agent to sequentially sample the compression ratio for each layer of a pre-trained network. The agent learns to balance accuracy against hardware constraints (FLOPs, latency) by receiving the fine-tuned accuracy as a reward signal.
While the prior approach treats channel counts as continuous numerical actions within a reinforcement learning environment, our solution treats them as tokens in a code sequence, allowing the LLM to leverage syntactic patterns and programming logic rather than just numerical rewards.
Network slimming
[
29
]
introduces a differentiable approach to pruning by enforcing L1 regularization on the scaling factors of batch normalization layers.
During training, the model automatically identifies insignificant channels, those with near-zero scaling factors, which can then be safely pruned without significant accuracy loss.
Unlike network slimming, which relies on differentiable scaling factors optimized during training, our method optimizes the architecture definition itself before training begins, using the LLM’s code-generation capabilities to propose efficient configurations directly in source code.
MetaPruning
[
30
]
trains a separate hypernetwork to predict the weights for various pruned networks, enabling the evaluation of many different channel configurations without retraining each one from scratch.
While MetaPruning uses a meta-network to predict weights for numerical channel values, our work uses an LLM to predict the code that defines these channels, framing the problem as language modeling rather than weight prediction.

2.3
LLM-Driven Optimization and Discovery

The intersection of LLMs and evolutionary search is a rapidly emerging field.
EvoPrompting
[
15
]
utilizes LLMs as mutation operators within an evolutionary algorithm.
Instead of relying on random bit-flipping or subtree exchange, EvoPrompting prompts the LLM to combine the logic of parent codes or optimize specific functions, effectively treating the LLM as an intelligent genetic operator.
Similarly, FunSearch
[
17
]
demonstrates that LLMs can discover novel mathematical algorithms by iteratively evolving code within a sandbox evaluator.
FunSearch employs evolutionary model where multiple independent populations evolve in parallel, feeding back only the highest-scoring, executable programs into the prompt.
This creates a self-reinforcing loop that has led to discoveries surpassing human baselines in domains like bin packing.
FunBO
[
26
]
extends this concept to Bayesian optimization, using LLMs to discover novel acquisition functions that generalize better across tasks than standard heuristics.

Other approaches like LLM-NAS
[
10
]
and GPT-NAS
[
19
]
explore using LLMs to directly propose layers or connections.
GPT-NAS, for instance, encodes neural architectures into a specialized token sequence and fine-tunes a transformer to predict high-performing strings.
LeMo-NADe
[
27
]
focuses on multi-objective discovery for edge devices, using an expert system to validate constraints like latency and power consumption.
A common limitation in prompt-only approaches is the reliance on the LLM’s pre-trained knowledge to produce valid code.
When applied to complex constraints like channel consistency in residual networks, these methods frequently generate invalid code, wasting evaluation budget.
Our approach differs by explicitly fine-tuning the LLM on a programmatically generated, task guided corpus of valid codes, directing the LLM during generation phase.

The use of synthetic data to train code LLMs is also gaining traction.

This validity-first bootstrapping allows us to leverage the LLM for what it does best—pattern matching and optimization—without burdening it with the task of learning basic syntax from scratch.

3
Methodology

We propose a generative approach to NAS where a LLM acts as an intelligent optimizer.
Rather than relying on heuristic search algorithms or random mutations, we condition the LLM to synthesize neural network architectures that meet specific performance targets.
The pipeline consists of three phases: (1) AST-based bootstrapping to initialize the knowledge base, (2) conditional generative optimization where the LLM captures the implicit patterns and improves architectures based on metric targets, and (3) an iterative fine-tuning loop that continuously refines the LLM’s understanding of high-performing code structures.

3.1
Problem Formulation: Conditional Code Generation

We frame the channel configuration search as a conditional code generation task.
Let
\mathcal{M}
be the space of valid neural network source codes.
Given a baseline model
m_{base}\in\mathcal{M}
with performance
y_{base}
, and a desired target performance
y_{target}>y_{base}
, the LLM must synthesize a new model
m_{new}
:

m_{new}=\text{LLM}(m_{base},y_{base},y_{target}).

(1)

The goal is for the actual performance of
m_{new}
to approximate or exceed
y_{target}
.
This formulation explicitly conditions the generation on the performance metric, requiring the LLM to reason about the relationship between code structure (channel widths) and model capacity. Unlike standard code completion, which optimizes for likelihood
P(code)
, our objective is to optimize for the conditional probability of improvement:
P(m_{new}|m_{base},y_{new}>y_{base})
.

3.2
The LEMUR Database

To support this data-driven process, we utilize the LEMUR dataset of high-capacity and edge-optimized neural networks
[
33
,
34
,
35
]
.
LEMUR serves as the persistent memory for our system, storing every generated model as executable PyTorch code alongside its training metadata (hyperparameters, epoch count) and evaluation metrics (validation accuracy).
This unified storage allows us to query for model pairs and construct training datasets for the LLM dynamically.

While LEMUR serves as a comprehensive repository for networks and their metadata, applying it to the specific problem of channel optimization presents a cold-start challenge. To orient the LLM towards this task, we cannot rely on an empty or generic database; we need a rich set of examples that demonstrate the causal link between channel configuration and model performance. Therefore, we systematically populate the database with generated models to serve as the initial training corpus, ensuring the LLM can discern the nuances of the optimization landscape from the onset of fine-tuning.

3.3
Phase 1: Bootstrapping via AST Mutation

LLM requires domain-specific examples to understand the task of channel configuration.
To solve the cold starting issue, we employ a programmatic mutation engine solely for the initial epoch.
This engine parses the AST of seed models and applies structural changes using a three-stage pipeline. As a seed model, we had chosen AlexNet as it proves to be a simple starting point for channel configuration search
[
7
]
.

1. Source Tracing and Planning

We implement a
ModuleSourceTracer
that patches the
__init__
methods of PyTorch modules (e.g.,
nn.Conv2d
,
nn.Linear
) to capture their exact line numbers and column offsets during instantiation.
A
ModelPlanner
then analyzes the model’s data flow graph (using
torch.fx
with a custom
LeafTracer
) to identify mutation groups, sets of layers that must share dimensions due to downstream dependencies.
This ensures that if a convolutional layer’s output width is modified, the corresponding input width of the next layer (and any parallel branches) is updated synchronously.

2. Constraint-Aware Execution

The
CodeMutator
applies the mutation plan directly to the source code AST.
The AST mutation engine relies on Python’s
ast
module for source edits and
torch.fx
for constraint-aware planning.
While the engine supports various structural modifications including activation swapping, kernel size adjustments, and stride changes, our primary focus in this work is on channel dimension optimization.
Crucially, the system ensures validity by propagating these changes across the entire network, automatically correcting downstream layers to maintain graph consistency.

•

Dimension Mutation:
The
DimensionPlanner
selects a mutation group and assigns a new channel width from a predefined valid range (
[4,1025]
). It enforces architectural constraints, such as ensuring that new channel counts remain divisible by the
groups
parameter in grouped convolutions. If a depthwise convolution’s constraint is violated, the system automatically resets it to a standard convolution.

3. Verification Protocol

Before any mutated model is added to the database, it undergoes a rigorous verification process in the
Orchestrator
:

1.

Shape Consistency:
A forward pass with synthetic data (e.g.,
2\times 3\times H\times W
) confirms that tensor shapes remain valid throughout the network and that the final output matches the dataset’s class count.

2.

Gradient Integrity:
A backward pass ensures the computational graph remains differentiable.

3.

Trainability Check:
A single optimizer step is executed to verify that parameters can be updated.

This phase generates the initial population of valid, trainable models. Once the database is populated, the AST engine is retired, and all subsequent generation is driven by the LLM. Through AST mutations, we generated 1129 variant AlexNet networks.

3.4
Phase 2: Conditional Generative Optimization

We construct training samples by querying LEMUR for pairs of models
(m_{A},m_{B})
trained on the same dataset, where
m_{B}
outperforms
m_{A}
(
y_{B}>y_{A}
).
This pairing logic is handled by the
JoinConf
configuration in our data loader, which explicitly filters for pairs where the addon model has a higher metric than the baseline.
Crucially,
m_{B}
need not be a direct descendant of
m_{A}
; the pairing simply provides a trajectory from a lower-performing architecture to a higher-performing one.

Prompt Engineering

We design a structured prompt that explicitly conditions the LLM on the metrics.
The input prompt contains:

•

Role:
"You are a machine learning model designer."

•

Task:
"Generate a LEMUR dataset neural network model that increases the ’metric’ metric value to at least addon_accuracy…"

•

Context:
The source code of the baseline model
m_{A}
(wrapped in
<nn>
tags), its hyperparameters (
<hp>
), and its achieved accuracy
y_{A}
.

The LLM is tasked with generating the full source code for
m_{B}
(wrapped in
<nn>
tags) and its corresponding hyperparameters.
By training on these pairs, the LLM learns to analyze the baseline architecture and synthesize the necessary structural modifications (e.g., widening specific bottlenecks, balancing layer ratios) to achieve the target metric.

3.5
Phase 3: Iterative Fine-Tuning Loop

The search proceeds in iterative epochs. In each epoch
t
:

1.

Sampling:
We sample baseline models from the current LEMUR database.

2.

Conditional Generation:
We prompt the LLM with these baselines and a
higher
target accuracy (e.g.,
y_{target}=y_{base}+\delta
). The LLM synthesizes
N
new candidate architectures.

3.

Evaluation:
The candidates are trained for a fixed number of epochs (proxy training). Their code and resulting accuracies are stored in LEMUR.

4.

Fine-Tuning:
We identify successful generations (where the new model actually improved over the baseline) and other high-performing pairs from the updated database. The LLM is fine-tuned on this fresh data.

This loop creates a self-reinforcing cycle. As the database accumulates better models, the LLM is exposed to higher-quality code examples and more ambitious improvement trajectories, progressively refining its ability to design optimal architectures.

4.2
Generative Validity Analysis

The search process generated 220 candidate architectures across the initial 22 epochs.
The strict enforcement of trainability and testability resulted in a validity rate of 9.09%.
Specifically, 20 candidates satisfied all structural constraints while 200 candidates failed the verification protocol.
This high rejection rate demonstrates the complexity of the search space where imposing validation structure as well as channel optimization proves to be a fragile constraint satisfaction problem.
Despite the sparsity of valid samples, the successful candidates provided sufficient signal to guide the language model toward improved configurations.

4.4
Statistical Analysis of Improvement

We employed a multi-faceted statistical analysis to evaluate the search trajectory.

Peak Performance Trend (Linear Regression)

We analyzed the progression of the maximum accuracy per epoch to quantify the optimization of the trajectory.
A linear regression analysis on the epoch-wise maximum accuracy reveals a positive slope (
\beta=+0.0019
) with a
p
-value of
0.083
.
While this
p
-value is marginally above the standard
0.05
threshold, it is important to note that linear regression assumes a constant, monotonic improvement.
Optimization algorithms, particularly in high-dimensional discrete spaces like NAS, typically exhibit variable behavior—periods of exploration followed by breakthroughs across epochs.
Linear regression penalizes these necessary exploration phases.
Therefore, while the positive slope indicates an upward trend, we rely on more robust non-parametric tests to confirm the significance of the improvement.

Population Analysis (T-Test)

To assess whether the earlier models displayed improvement over epochs, we compared the model populations from the initial exploration phase, the epochs 0-5, against those from the late optimization phase which is taken as epochs 16-21.
First, we analyzed the entire population of valid models.
The mean accuracy increased from
0.226
in the early phase to
0.273
in the late phase.
A one-tailed t-test confirms this improvement is statistically significant with a
p
-value of
0.0033
.
This statistically significant shift in the population mean indicates that the LLM successfully internalized the latent design patterns governing channel efficiency.
Rather than randomly sampling the search space, the model learned to systematically propose optimized configurations that yield higher predictive performance, effectively pruning the space of low-quality architectures.

Robust Frontier Analysis (Permutation Test)

Given the limited sample size of the late-stage population (
N=4
), we employed a non-parametric permutation test to rigorously verify the improvement in the search frontier.
Unlike the T-test, which assumes normality, the permutation test calculates the exact probability of observing the given difference in means under the null hypothesis of exchangeability.
We compared the early phase population (
N=9
,
\mu=0.226
) against the late phase population (
N=4
,
\mu=0.273
).
By simulating
100,000
random permutations of the group labels, we determined that the probability of observing a performance gap of this magnitude (
\Delta=+0.0474
) by chance is
p=0.0077
.
This result provides a distribution-free confirmation that the search algorithm has systematically shifted the performance distribution upwards, independent of sample size assumptions.

5
Discussion

5.1
Exploration versus Exploitation

The search process demonstrates a shift from exploiting known patterns to exploring new configurations.
Initially, the LLM generates architectures similar to the bootstrap dataset, resulting in consistent but limited performance.
In later epochs, while the rate of valid code generation remains stable, the variance in model accuracy increases.
This indicates that the LLM begins to generate a broader range of channel configurations, deviating from the initial training examples.
This increased diversity is crucial for optimization; while it produces some lower-performing models, it also enables the discovery of high-performing outliers that exceed the initial baseline.
The global maximum accuracy of 0.311 was achieved during this exploratory phase, confirming that moving beyond the initial distribution is necessary for significant performance gains.

5.2
Efficacy of AST-Based Bootstrapping

The programmatic initialization of the search space was a determinant factor in the system’s convergence.
By seeding the repository with 1129 syntactically verified examples, the system decoupled the acquisition of structural constraints from the optimization objective.
This allowed the LLM to leverage the initial corpus as a syntactic prior, focusing its capacity on refining channel configurations for accuracy rather than learning the rules of valid code generation from scratch. Notably, although the seed examples consisted exclusively of AlexNet channel configurations, the LLM successfully extrapolated this structural knowledge to the block-level architecture of AirNet.

5.3
Prompt Importance Ablation

To assess the necessity of our structured prompting strategy, we conducted an ablation study by removing the task definition, metric targets, and dataset context. This unguided generation resulted in severe degradation of both structural validity and task alignment. Across 220 attempts, only 9 candidates proved executable. Crucially, the absence of dataset constraints caused significant domain drift: 5 of the 9 valid models were inadvertently architected for the CelebA Gender task rather than the target CIFAR-100 dataset. The remaining 4 CIFAR-100 candidates displayed negligible capacity, yielding validation accuracies between 0.0202 and 0.108. These results confirm that explicit conditioning is a prerequisite not only for performance optimization but also for constraining the LLM to the correct problem domain.

5.4
Architectural Priors and Late-Stage Expansion

To interpret the design rules acquired by the LLM, we analyzed the correlation between the width of specific layers and the final model accuracy.
The analysis reveals a non-uniform sensitivity to channel capacity, indicating that the LLM learned to reallocate computational resources rather than simply scaling them uniformly.

Resource Reallocation

We observed a strong negative correlation of
\rho=-0.47
between the width of the second layer and model accuracy, contrasted with a strong positive correlation of
\rho=+0.53
for the fourth layer.
This indicates that the LLM discovered a topology characterized by late-stage expansion.
While standard architectures often follow a uniform doubling pattern, the optimal configurations generated by the LLM tend to compress the early feature extraction layers and expand the final representational layer.
The global maximum model exemplifies this with a configuration of
[64,99,256,1536]
.
In this architecture, the second layer is reduced to 99 channels, while the final layer is expanded to 1536 channels.
This suggests the LLM implicitly learned that CIFAR-100 requires a high-dimensional projection space for class separation but can suffice with a compact feature extractor.

Non-Standard Channel Widths

A significant portion, specifically
40.9\%
, of the generated layer widths were not powers of two.
The presence of specific values such as
99
or
308
in high-performing models challenges the standard engineering heuristic of aligning dimensions to hardware registers.
The LLM treated channel count as a continuous hyperparameter.
It found optima that offer better trade-offs between information bottlenecking and parameter count than the discrete power-of-two grid allows.

Parameter Efficiency and Pareto Optimality

Beyond raw accuracy, we analyzed the relationship between model size and performance.
Fig.
5
illustrates the accuracy versus parameter landscape.
We observe a distinct Pareto frontier where the LLM discovers architectures that achieve high accuracy with significantly fewer parameters than the baseline.
The most efficient model achieves comparable performance to the global maximum but with a reduced parameter footprint, suggesting the LLM has learned to optimize for efficiency implicitly.
The architectural flow analysis confirms that these efficient high-performers share a common structural characteristics.
They employ a strategy where early layers are kept narrow to save parameters, while the final layers are expanded to maximize representational capacity.

6
Conclusion

We are introducing a closed-loop neural architecture search framework in which a large language model optimizes channel configurations for vision networks by operating directly on executable source code. By casting channel search as conditional code generation, the approach departs from graph-based or numerical NAS methods and enables optimization under strict structural constraints. A central contribution is a validity-first bootstrapping mechanism based on AST-driven mutations that produces a large corpus of syntactically correct, shape-consistent, and trainable models, resolving the cold-start problem in learning-based NAS and allowing the language model to internalize architectural constraints as an implicit prior. Once this prior is learned, the AST engine is removed and subsequent architectural refinement is performed solely by the language model.

Experiments on CIFAR-100 demonstrate statistically significant accuracy gains, with the best model achieving a 24.1% relative improvement, increasing accuracy from 0.250 to 0.311 over the strongest model in the initial distribution. Population-level and non-parametric analyses confirm that these gains reflect a systematic shift in the performance frontier rather than stochastic exploration. Beyond accuracy, the method uncovers unconventional channel priors, favoring irregular, non–power-of-two widths and late-stage expansion, yielding parameter-efficient models that form a clear Pareto frontier between accuracy and model size despite the absence of an explicit efficiency objective.

Overall, the results show that language models can learn vision-specific architectural principles from structurally valid synthetic data and performance feedback, and leverage this knowledge to optimize channel configurations in a principled manner. The framework is architecture-agnostic and readily extensible to broader vision NAS settings, including topology search and hardware-aware optimization.
