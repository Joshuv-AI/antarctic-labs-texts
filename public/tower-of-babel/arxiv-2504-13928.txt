LLM-Driven NPCs: Cross-Platform Dialogue System for Games and Social Platforms
Li Song

Abstract
NPCs in traditional games are often limited by static dialogue trees and a single platform for interaction. To overcome these constraints, this study presents a prototype system that enables large language model (LLM)-powered NPCs to communicate with players both in the game environment (Unity) and on a social platform (Discord). Dialogue logs are stored in a cloud database (LeanCloud), allowing the system to synchronize memory between platforms and keep conversations coherent. Our initial experiments show that cross-platform interaction is technically feasible and suggest a solid foundation for future developments such as emotional modeling and persistent memory support.

3
Methodology

3.1
Game Design

This study presents a prototype of a virtual companion game, where players can engage in natural language conversations with an in-game NPC. The NPC features a simple favorability system: at the start, it maintains a polite but distant tone. As players interact more frequently, the NPC’s favorability increases, and its responses become warmer and more familiar.

Player Behavior

Players can chat freely with the NPC using natural language inputs inside the game. The NPC’s portrait and visual feedback reflect its emotional state and favorability level. When a player exits the game, they can continue the conversation through Discord. The NPC retains memory of the player and recognizes that they are currently interacting outside the game. If the player expresses a desire to engage more deeply, the NPC will suggest returning to the game.

NPC Behavior

The game features a single NPC, which remains responsive during the entire game session. When the player talks to the NPC “face to face” in-game, the favorability level increases. Outside the game, the NPC shifts to Discord and waits for further messages. However, favorability does not change during Discord-based interactions.

3.2
Implementation

The core of the system is the integration of the NPC with an LLM. Regardless of the platform used, whenever a player sends a message, the system stores the interaction in a cloud database to maintain shared context across platforms.

a) Data flow:

1.

The player sends a message (in-game or via Discord).

2.

The message is saved to the database through an API, including fields such as character,user ID, content, timestamp, favorability, and platform.

3.

The system retrieves the most recent dialogue history (limited to six rounds).

4.

A new prompt is constructed and sent to the LLM.

5.

The LLM’s response is saved to the database and returned to the appropriate platform.

4
Experiments

4.1
Environment

The prototype system was tested locally on a Windows machine. The Discord bot was implemented using Python, while the in-game component was developed with Unity. The LLM used for all dialogue generation was DeepSeek-R1. All dialogue records were stored and synchronized through LeanCloud, a cloud-based database service. Each record includes the following fields:

character (speaker), content (message content), haogandu (favorability), platform (Discord or game), timestamp
, and
user_id

5
Discussion

The current system primarily focuses on building a working data flow for cross-platform communication. As demonstrated in the previous tests, the LLM is capable of maintaining coherent conversations across different platforms. It correctly adapts its responses based on the context and the platform from which the message originates.

That said, the system still presents some clear limitations. One foreseeable issue arises with long-term interactions: the NPC’s memory may become diluted over time. For example, while the NPC may remember a player’s name after a few exchanges, this memory could fade after twenty rounds of dialogue unless the entire conversation history is continually sent to the LLM. However, doing so would increase the input token size significantly as the dialogue grows.

This observation suggests a possible direction for improvement. Introducing a vector database or retrieval-augmented generation (RAG) mechanism could help the system retain essential memories over longer time spans. These technologies would allow the model to reference only the most relevant information during each response, reducing token usage while supporting a more persistent, human-like memory.

6
Conclusion

This study explores the possibility of enabling persistent interactions between LLM-powered NPCs and players across multiple platforms. A prototype system was developed and tested, connecting a game built with Unity and a Discord-based social environment through a shared cloud database. Using the DeepSeek-R1 model, the system allowed a single NPC to maintain conversations with players regardless of the platform, and to react contextually based on the player’s location—whether in-game or on Discord. The results demonstrate the technical feasibility of such a system and its potential to offer continuous companionship through cross-platform dialogue.

Despite these promising results, the system still has several limitations. First, its functionality is primarily restricted to dialogue and memory synchronization; game mechanics and deeper gameplay integration were not part of this implementation. Second, the memory system does not yet support long-term retention. Third, the NPC’s personality is defined solely by a static prompt, lacking dynamic development over time.

Future work may focus on extending the NPC’s functionality outside the game to affect in-game states, as well as expanding the NPC’s behavioral repertoire within the game. Enhancing the memory system with vector search or hybrid memory mechanisms could further support consistent, evolving interactions.

Ultimately, this prototype outlines a direction for NPC design that goes beyond the boundaries of the game itself. With the help of LLMs, NPCs can become not just game elements, but persistent social companions that exist across platforms—an idea that holds great potential for the future of interactive storytelling and digital companionship.
