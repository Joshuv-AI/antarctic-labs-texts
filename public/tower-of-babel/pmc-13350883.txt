Adaptive mobility-aware hierarchical task offloading for delay-sensitive applications in fog computing
Authors: D. Deepa, K. R. Jothi
Published: 2026

ABSTRACT
Delay-sensitive IoT applications require an immediate response, while computing tasks in a fog-enabled network must be executed efficiently. Fog computing nodes are resource-limited and cannot handle more requests within the deadline. The process of task offloading continues to be difficult because of the user’s mobility and the processing capabilities of the fog node. A new multi-level fog layer is proposed in the system architecture of the fog computing. In addition to this, this model utilizes the IoT device as a fog computing node based on certain criteria like computational capacity, mobility, etc. Random mobility prediction model is used to predict the future location of the user and the IoT device. A task offloading scheme that optimize the location aware module before engaging the device for task computation. Comprehensive MobFogSim simulations demonstrate that the proposed model and algorithm converge effectively, reducing latency and improving the user experience of handling sensitive applications by 20% compared to existing methods.

Introduction

With the introduction of 5G services and a rapid increase in smart devices connected to the internet, there is a demand for sensitive applications that require low latency and effective node utilization. These applications include augmented reality, healthcare systems, smart farming, and autonomous driving. Due to the diversity of the applications, the number of tasks produced by smart devices has been increasing rapidly. Because of limited constraints like minimal computational capacity and storage capacity, these devices cannot handle tasks locally and need to transfer them to a cloud server for processing. Due to data transmission and propagation delay, latency is increased while offloading the task from one node to another node. To solve this issue, the fog computing paradigm was introduced, which brings the computational capabilities near the source device where the data is generated. Even though reducing latency is quite complex while allocating the task to the fog computing node for deadline-aware applications1.

In the geographically distributed architecture of fog computing, Internet of Everything (IoE) applications require low latency and necessitate support for real-time data processing. This paradigm offers multiple advantages, including reduced latency, location awareness, mobility support, enhanced security, heterogeneity, cost-effectiveness, interoperability, and federation2. The Internet of Things (IoT) represents a highly promising technology, but its diverse nature has led to an enormous amount of data generated. Because of the limited resource constraints in IoT devices, such as computational power, battery life, and storage capacity, the data generated is forwarded to fog nodes for processing or storage. However, the distribution of tasks among fog nodes is uneven, this leads some nodes to become overloaded while others have underloaded. When tasks are directed to overloaded fog nodes that have critical latency requirements, these nodes often struggle to meet those demands. This inability to perform results in tasks missing their deadlines, which leads to service delays for sensitive applications and a decrease in quality of service3.

In vehicular fog computing, computational capacity of the vehicles are insufficient to offload the task from one device to the another device. In this context, other high-performance computing vehicles or fog nodes can effectively manage the vehicle requests by utilizing their available computational resources. In order to select the fog node and effectively utilize its computing resources, it is essential to offloading techniques that must the transfer of complete tasks or applications for execution on other selected devices. Computation offloading in highly dynamic environments, such as vehicular networks, presents a considerable challenge. This process can be categorized into two distinct types static and dynamic offloading. Static offloading occurs when the system or user predetermines which segments of the application will be downloaded and the specific locations for execution prior to runtime. In contrast, dynamic offloading refers to a scenario in which the system assesses real-time metrics related to current network conditions, available mobile devices, and fog nodes to make informed decisions about which application components to download and where to execute them. This adaptability is critical in optimizing performance and resource utilization in dynamic environments4.

Task offloading involves many critical considerations and challenges. It is crucial to balance both cost and performance, while execution time is a vital performance metric as a deadline, energy consumption also requires significant attention. Additionally, resource utilization should be conducted individually for each user device, as they may have unique requirements and constraints2. The computation offloading could be affected by several factors, such as latency requirement, load balancing, intensive computation, privacy, security, long-term storage, network bandwidth, and energy efficiency5. Despite the advantages of fog computing in supporting latency-sensitive IoT applications, existing task offloading approaches face several challenges. These include inefficient handling of user mobility, imbalance in task distribution among fog nodes with limited resources, high energy consumption of IoT devices, and failure arise due to task deadlines. Moreover, most current solutions do not combinedly consider residual energy, user mobility prediction, and deadline constraints while selecting an optimal fog node for computation. Therefore, there is a need for a deadline- and energy-aware task offloading mechanism that dynamically adapts to user mobility and resource constraints while ensuring quality of service for delay-sensitive IoT applications.

Vehicular fog task—offloading policies

In vehicular fog computing, Fog nodes or Road Side Unit (RSU) or fog nodes on rural highways face energy limitations and need energy-efficient task offloading for fog vehicles. Optimizing energy consumption is complex, as local task processing incurs computation costs, while task assignment to fog vehicles adds communication costs (Table 2). Although offloading tasks to fog vehicles can reduce response time, it increases energy usage at the RSU due to task data transmission1. Predicting the future locations of vehicles can help optimize the distribution of processing tasks. For applications that are sensitive to delays, employing the Kalman filter for forecasting allows for the prediction of a vehicle’s upcoming position. Anticipating locations aids in forecasting the availability of fog resources, influencing the decision-making process related to task offloading6. To improve mobility forecasting, a Vehicle Movement Model is employed to better prediction the dynamics of real-world vehicle movements, it support services within Vehicle-Fog-Computing environments. In this model, vehicle positions and speeds are considered random variables, with vehicles in different lanes moving in various directions. The VMM adapts to the ever-changing conditions of traffic environment7. To enhance mobility prediction, a Vehicle Movement Model is utilized to more accurately predict the dynamics of actual vehicle movements, enhancing services within vehicle fog computing settings. In this model, the positions and speeds of vehicles are treated as random variables, with vehicles in separate lanes traveling in diverse directions. Energy efficient task offloading

Maintaining an energy efficiency is key for successful task offloading. Selecting the right type of fog nodes form homogeneous or heterogeneous is crucial for compatibility with the offloading strategy and defining the level of heterogeneity among them9. Balancing energy consumption among fog nodes (FNs) while minimizing task processing delays at terminal nodes (TNs) is challenging. This framework analyses task offloading, focusing on equitable energy usage among FNs in a fog network with multiple TNs and FNs10. In a distributed environment, fog nodes often rely on battery power, making effective energy management essential for fog node life span. Providing fog computing nodes with solar panels for recharging presents a viable solution. A method to predict energy harvesting helps manage resources by forecasting node energy usage. Additionally, optimizing device roles alternating between resource requesters and providers can further extend the network’s lifespan11. To improve the execution of time-sensitive tasks and reduce the overhead of task offloading, both task offloading and resource allocation are optimized together. The process also considers users’ service quality needs and the battery life of IoT devices12. An effective offloading strategy for selecting the best node to manage tasks from an overloaded node involves two ways as identifying candidate nodes in the fog region and assessing their computational resources and network status to choose the most suitable one13. A federated mobility forecasting model uses historical movement data to predict future cell connections, while a distributed Content Forecasting Model analyses user content demands to anticipate upcoming files for caching. The Join-T Coordination framework combines these models to proactively offload future content at the network edge14.

Computation offloading

Most research on computation offloading addresses a limited set of parameters, such as computation capacity and network bandwidth, while neglecting application characteristics and deadlines. New three-layer IoT systems aim to better understand the impact of computation offloading on application response time by considering factors like application traits, mobility predictions, communication costs, and data flow. Resource allocation is categorized into resource placement, scheduling, and computation offloading, with resource placement focusing on how and where resources are deployed within IoT systems15.

An offloading strategy using a three-layer fog architecture categorizes end-device mobility into three types: devices within range, devices within range assigned to another fog node, and devices out of range. Based on these categories, computational tasks are offloaded to the nearest and most efficient fog node16. Partial offloading optimizes resource allocation and utilization in fog nodes more effectively than binary offloading17. In the osmotic approach, tasks and devices are organized by deadlines and processing capabilities. Tasks are assigned to the most suitable devices based on their current capacity. The Dynamic Estimation of Task Execution Time (DETET) module assesses whether deadlines can be met. Tasks can be shifted to higher-level devices if lower-level ones cannot handle them, ensuring a balanced workload among devices. This method enhances the reliability of meeting deadlines and improves resource utilization at the fog layer18.

Mobility prediction model

MobFogSim simulation parameters

Region in the fog computing is divided into a system of seven fog nodes with the radius of 500 m. The simulation parameters are configured to reflect a realistic IoT–fog–cloud environment for mobility-based task offloading. The communication bandwidth between IoT devices and fog/cloud nodes is set in the range of 100 kbps to 1 Gbps, while fog-to-fog links operate between 1 Mbps and 10 Gbps, and fog-to-cloud links between 10 and 100 Gbps. The fog node processing capability varies from 200 to 2000 MIPS, representing heterogeneous fog resources. Task deadlines are controlled using threshold values T1 = 80 ms and T2 = 100 ms, enabling deadline-aware offloading decisions. Each IoT device generates 2 to 20 tasks, with a margin difference of 2 tasks per experiment to model workload variability. The queue size is limited to 5–10 tasks at IoT devices, 50–100 tasks at fog nodes, and more than 200 tasks at cloud servers to capture congestion effects. For the energy model, IoT devices consume 0.5–1.5 W for processing and 1.0–2.0 W for transmission, fog nodes consume 5–15 W during processing and 2–5 W in idle mode, while cloud servers are assumed to have processing power above 100 W and are not energy-constrained. These parameters collectively enable comprehensive evaluation of the proposed mobility-aware hierarchical fog computing model.

The Linear Mobility Prediction Model is a fundamental approach that predicts a mobile user’s future geographical position, speed, and direction of movement to forecast their potential future locations. This model operates on the assumes that a user will generally continue to move along their same speed and same direction19. The proposed model is evaluated using the Luxembourg SUMO traffic model within the MoboFogSim simulation tool32, which provides realistic vehicular mobility traces and traffic patterns. This setup allows us to capture dynamic vehicle movements and assess the performance of the task offloading algorithm under practical traffic scenarios. Although actual GPS traces could further improve realism, the Luxembourg SUMO dataset is widely recognized for simulating real-world vehicular mobility and is sufficient to validate the effectiveness of the proposed approach.

System model

A mobility-based task offloading method uses threshold values of the applications for a decision-making approach that ensures reliable and efficient task offloading, along with device mobility prediction. The process involves predicting the future location of a device and comparing this prediction with a predefined threshold values, and the required parameters like minimum required connection time, energy level, or computational capacity. If the predicted value exceeds the threshold range, alternative fog node is selected to compute the task. If it does not, the task may be delayed, rejected, or redirected to a more suitable node.

When to offload a task

A task should be offloaded based on user mobility when the predicted location exceeds a predefined threshold. This approach ensures that the task can be completed without interruption. Offloading is most effective when the user is moving slowly, is stationary, or has a predictable mobility pattern, as these conditions reduce the risk of disconnection. Factors such as stable signal strength, acceptable fog node load, and low handoff costs further support the decision to offload tasks. Tasks should also be offloaded when the user is within a good signal range, no immediate handover is expected, and the task is either lightweight or time-sensitive. Additionally, a mobility aware model is calculated from factors like velocity, direction, and signal quality should exceed a certain threshold, indicating that the user’s movement is suitable for reliable task execution at the fog node (Fig. 4).Fig. 4Offloading criteria: (a) User is in the same region, (b) User is in same region task allocated to neighbourhood fog node (c) User navigation to different region.

Finding best neighbour

When a request is sent to the most suitable neighbouring fog node, it experiences about half of the total round-trip delay to reach that node. If the request joins the queue at the neighbour, the time spent waiting is roughly equal to that neighbour’s estimated queue time before the request is processed. If the request does not get queued at the neighbour’s fog node, it will need to be offloaded again, as repeated offloading can occur if neighbouring fog nodes are busy. To make an optimal offloading solution, it’s essential to take into account additional factors such as the propagation and transmission delays between fog nodes and IoT devices.

Checking and updating status queue

When fog nodes receive requests from IoT devices involved in an application that requires timely responses, they must identify the type of application to adjust the queue settings accordingly. Fog nodes must have an estimate of the overall processing delay for the tasks in their queue, which includes the expected waiting time. This information is essential for making decisions about offloading tasks and for communicating their estimated waiting time to neighbouring fog nodes.

When a user mobility is slowly and is expected to stay within the coverage area for a sufficient period, and if a existing fog node can complete the task on time, the task will be delegated to that fog node. Service delay

Service delay refers to the overall time taken for an IoT request to be completed, regardless of whether it process the request locally, at a fog node, or in the cloud. This delay includes all the time delay included as the task progresses from inception to completion, including processing delay, transmission delay, propagation delay, and queuing delay. The delayed service is modelled as a weighted average of these delays based on the probability of the task being executed at each location. If processed locally, the delay includes only the local computation time. If offloaded to a fog node, it provides network delays and processing time. If further cloud server process, additional delays due to distance and cloud queuing are also considered. Offload control mechanism

The offload control mechanism is a distributed, delay-aware strategy that determines whether an IoT task computed in device itself, or in middle layer or top layer. This mechanism employs proper decision-making using a decision tree algorithm. Every IoT node allocates probabilities to various processing choices influenced by factors like the size of the task, its deadline value, and the threshold value. Fog nodes regularly send status updates to all adjacent nodes. This process enables IoT devices to make informed decisions without centralized control, thereby reducing the service delay. This proposed mobility-aware and deadline-aware task offloading model is fundamentally different from recent deep learning–based and federated learning–based offloading approaches in terms of design objectives and operational focus. The proposed model explicitly incorporates user mobility patterns and strict task deadlines into the offloading decision process, ensuring that tasks are completed within their timing constraints even under dynamic network and movement conditions. In contrast, deep learning–based offloading approaches primarily rely on data-driven policy learning to optimize average performance metrics such as latency or energy consumption, and they often do not explicitly guarantee deadline satisfaction or robust adaptability to rapid mobility changes without extensive training. Similarly, federated learning–based approaches emphasize distributed model training and data privacy across devices, but mobility prediction and deadline enforcement are not intrinsic objectives and require additional mechanisms to be effective in real-time, delay-sensitive scenarios.

Conclusion

The proposed multi-level hierarchical fog node deployment model presents a scalable solution to mobility support fog-enabled IoT networks, particularly addressing the dynamic mobility of users and the heterogeneous computational capabilities. By integrating a fog promotion algorithm, the method efficiently identifies suitable IoT devices to compute the task based on capacity, static mobility, network connectivity, and storage capacity. The proposed task offloading scheme optimizes key decision-making components, including task assignment, deadline and the threshold value of the application. It also evaluates balance among the task completion time and communication delay. Through extensive simulations, the approach demonstrates the latency reduced IoT application for mobile users when compared to traditional baseline methods. This confirms the model’s ability to increase user experience (QoE) in real-time, delay-sensitive, and computation-intensive IoT applications. This makes it a highly promising strategy for mobility based fog-IoT environments.
