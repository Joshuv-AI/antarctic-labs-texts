On the multi-objective hyperparameter optimization of the weighted entropic associative memory
Authors: Juan Antonio López Rivera, Carlos Ignacio Hernández Castellanos, Rafael Morales, Luis A. Pineda Cortés
Published: 2025

ABSTRACT
This paper presents an application of automatic algorithm configuration to optimize the performance of the Weighted Entropic Associative Memory (W-EAM). This model holds declarative but distributed representations of remembered objects. We apply two state-of-the-art hyperparameter tuning methods—SMAC and SMS-EMOA—to improve W-EAM’s recognition accuracy across three domains of increasing complexity: digit recognition, character recognition, and phone recognition in Mexican Spanish. Each domain presents unique challenges in memory structure, data representation, and learning dynamics. We evaluate a multi-objective optimization setting, focusing on the trade-off between precision and recall. Our experiments show that optimized configurations consistently outperform the baseline model, with the largest gains observed in the phone domain. Additionally, a cyclical optimization-learning scheme further enhances performance by iteratively improving both model parameters and training data quality. These results highlight the potential of automated configuration methods in advancing adaptive memory systems and providing practitioners with a range of parameters to use on W-EAM.

Introduction

In recent years, automatic algorithm configuration has emerged as a key approach for improving the performance of complex machine learning systems through the optimization of hyperparameters1,2. When multiple conflicting objectives—such as precision and recall—must be considered simultaneously, this task becomes a multi-objective optimization problem3. This paper presents an application of state-of-the-art multi-objective hyperparameter tuning methods to the Weighted Entropic Associative Memory (W-EAM), a model designed for robust and distributed associative memory4.

Although the F1-score is a commonly used aggregate metric in classification tasks, it implicitly assumes equal importance between precision and recall. However, in real-world applications—especially those involving speech and phoneme recognition—this balance is often domain-specific. For this reason, we adopt a multi-objective formulation that treats precision and recall as separate targets, enabling a more flexible and application-aware configuration strategy.

W-EAM extends the original Entropic Associative Memory (EAM)5 framework by introducing weighted memory cells and configurable decision parameters that allow for greater flexibility in learning and recall tasks. However, this increased flexibility results in a higher-dimensional parameter space, making manual tuning infeasible and motivating the use of automated optimization techniques.

We explore the effectiveness of two hyperparameter optimization methods: SMAC (Sequential Model-based Algorithm Configuration)6 and SMS-EMOA (S-Metric Selection Evolutionary Multi-objective Algorithm)7, applying them to three progressively more complex domains—handwritten digit classification (MNIST), character recognition (EMNIST), and phone recognition in Mexican Spanish (DIMEx1008 and CIEMPIESS9). Our goal is to identify parameter configurations that improve W-EAM’s recognition performance while analyzing the trade-offs between competing objectives. This study also evaluates the practicality of incorporating hyperparameter tuning into W-EAM’s training pipeline, including a cyclical learning scheme that iteratively improves model accuracy and training data quality.

Our results offer insights into the benefits and limitations of optimization-based approaches for tuning memory models and provide guidelines for their deployment in future applications.

Entropic associative memory

In this section, we describe the basic aspects of the Entropic Associative Memory. Both the version with and without weights.

Basic system

The EAM/W-EAM system aims to model natural memory. This system is embedded within a cognitive architecture that makes it useful through its interaction with other modules of the cognitive architecture, such as perceptual and motor modules. Therefore, in the EAM architecture, the module that stores associative memory recollections coexists with two other modules for synthesis and analysis, which provide the interface between memory and the external world. The synthesis module extracts object features; that is, -translates a modal representation—such as an image or a sound—into an amodal representation—it is a discrete, finite function whose values are quantized. The analysis module performs the inverse process, converting amodal representations into modality-specific images of the remembered object.

The analysis and synthesis modules are implemented using the deep neural network architecture known as the auto-encoder10, in which the analysis and synthesis modules correspond to the encoder and decoder, respectively. It is worth noting that these two modules do not necessarily have to be implemented as an auto-encoder5; any process that associates concrete representations with a vector in the abstract feature space, and vice versa, would suffice.

The auto-encoder architecture is an unsupervised training technique for neural networks, so called because the training data are not labeled. The goal of the auto-encoder is to synthesize and reconstruct the unlabeled input. According to its original formulation10, an auto-encoder simultaneously trains two neural networks. The first being the encoder, which is responsible for reducing the dimensionality of the input objects. I.e., transforming a given input into a vector of abstract features, which is smaller in size than the original input. The later, the decoder, performs the inverse task. During training, for each example in the dataset, the objective of the decoder is to minimize the difference between its output and the encoder’s input object. Therefore, the decoder computes an approximation of the inverse function of the encoder. Additionally, various techniques are used to encourage the encoder to learn vectors that are most useful to the decoder in reconstructing the input; in other words, the encoder seeks to extract the most relevant features of the input. In addition, the architecture includes a classifier that labels the encoder objects in a supervised manner and helps to train the encoder and the decoder, as illustrated in Fig. 1.Fig. 1Training cycle of the encoder, decoder, and classifier for the MNIST handwritten digits dataset. Associative memory registers

As shown in Fig. 2, the memory module of an EAM system is defined as a set of Associative Memory Registers (AMRs) connected via a data bus. These registers consist of simple numeric tables or matrices. In each implementation of EAM, there are c AMRs, one for each class to be recognized.

In these tables, the n columns are interpreted as the attributes or features of the stored objects, the m rows represent their discretized potential values, and the cells at their intersections specify the attribute values. The number of columns corresponds to the size of the abstract feature vector generated by the synthesis module. Each individual object corresponds to a specific pattern of ‘active’ cells in the table, representing a function that maps attributes to values. Classes are represented as a superposition of the functions corresponding to individuals of the class. Thus, classes are relations from attributes to values.Fig. 3\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\lambda$$\end{document} operation in EAM. Image by Pineda L. (2021).

This auxiliary register is used to store the input cue for the memory register and recognition operations, as well as the objects retrieved from the AMR by the \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\beta$$\end{document} operation.

The \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\lambda$$\end{document} registration operation is defined as the logical inclusive disjunction between each cell’s value in the auxiliary register and the corresponding cell’s value in the AMR. This operation can be diagrammatically interpreted as the overlaying of the auxiliary register’s contents—the cue—onto the AMR—the memory. These representations are distributed because the relationship between cells and represented objects is many-to-many; that is, each ‘active’ cell may contribute to the representation of multiple objects, and each representation may share memory cells with those of other objects11.

The \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\eta$$\end{document} operation is defined as the logical material implication between the corresponding cells of the auxiliary register (antecedent) and the AMR (consequent). This operation is interpreted as checking whether the cue is included in the AMR, and fails if the auxiliary register contains at least one cell on whose corresponding cell in the AMR is off. That is, if the cue is included in memory, the value of \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\eta$$\end{document} is true; otherwise, is false, as shown in Fig. 4a,b, respectively. Finally, the \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\beta$$\end{document} operation retrieves the representation of an object, provided that the \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\eta$$\end{document} operation is successful for the given cue. To achieve this, one value for each attribute is randomly selected from the set of ‘active’ values in the corresponding column, using a triangular probability distribution where the cue value serves as the maximum of the distribution12.

In the most basic case, the retrieved object is exactly the cue, as shown in Fig. 5a. However, the retrieved object may also be a previously stored object that the memory associates with the cue, or a novel object constructed from the cue, as illustrated in Fig. 5b,c, respectively.

The inclusion of probabilistic sampling in this operation allows the AMR to generate genuinely novel objects, as is the case in the final Fig. 5c. Therefore, this operation is constructive, akin to natural memory systems. It is worth noting that this contrasts with the generative process of the auto-encoder, which is ideally reproductive.

Weighted associative entropic memory

Up to this point, we have described the initial version of EAM, in which the elements of memory cells are Boolean values—i.e., their possible states are either one or zero—and, therefore, all stored objects have the same strength or weight. In4, the authors proposed a second architecture named Weighted Associative Entropic Memory (W-EAM), in which the memory cells have integer values.

The inclusion of weights in the AMRs affects the indeterminacy of the memory, as the different values associated with the weighted cells modify the probability of selecting certain cells during the retrieval process. Consequently, the indeterminacy of columns is Shanon’s entropy, and the entire memory is the average entropy of the columns.

In W-EAM, instead of using a logical inclusive disjunction, the \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\lambda$$\end{document}-register operation simply increments by 1 the value of each cell in the AMR that corresponds to the cells of the auxiliary register used by the cue.

Thus, an AMR consists of a parallel array of distributions \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\psi _i$$\end{document}, one for each argument or column i.

In addition to these new parameters, the recognition operation \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\eta$$\end{document} implements two criteria to handle cases in which a cue is accepted by two or more AMRs. Multi-objective hyperparameter optimization

Over the past two decades, the field of optimization has seen the emergence of Automatic Algorithm Configuration, which deals with the optimization of parameterized computational algorithms—that is, algorithms whose performance is affected by the values of intrinsic variables or parameters defined prior to execution. Algorithms used to solve hard computational problems are often highly parameterized.

Methods for automatic algorithm configuration can be classified based on whether they use an explicit model to describe the relationship between algorithm performance and parameter configuration, i.e., a surrogate function. Model-free methods for automatic algorithm configuration date back to the early 1990s6. These methods are relatively simple and can be applied to black-box functions. The most prominent in this category are ParamILS13, an iterated local search algorithm; and F-RACE14, which implements an iterated racing mechanism. This mechanism consists of evaluating a number of solutions simultaneously to discard those with the worst statistical performance, allowing the best solutions to ‘compete’ against each other.

Model-based algorithm configuration methods began gaining popularity in the early 2010s, with the proposal of Sequential Model-Based Optimization (SMBO)6, where each function evaluation alternates between updating the surrogate model and using it to select the next configurations. The early SMBO-based methods had the following limitations: (1) they only worked with numerical parameters, (2) they could only optimize one problem instance at a time, and (3) they lacked a mechanism for identifying poor solutions and aborting their evaluation. In 2011, Hutter et al.6 proposed two methods to overcome the first two limitations: Random Online Aggressive Racing (ROAR) and its extension, Sequential Model-Based Algorithm Configuration (SMAC).

ROAR is an instance of the SMBO framework that selects parameter configurations uniformly at random and iteratively compares them against the best solution found so far (referred to as the incumbent) using a novel intensification mechanism based on weighted Hamming distance, which allows multiple problem instances to be considered simultaneously.

The SMAC method15 extends the ROAR mechanism by selecting configurations based on a surrogate model rather than uniformly at random. Moreover, SMAC generalizes the SMBO model to support both categorical and numerical parameters. To achieve this, SMAC implements a model based on random forests16, or collections of regression trees—similar to decision trees but with numerical values at their leaves. Regression trees allow SMAC to handle categorical data effectively6. SMAC has proven useful across various research areas, including continuous black-box function optimization17,18, machine learning19, configuring CPLEX systems for decentralized energy optimization20, and parameter optimization in Traveling Salesman Problem (TSP) solvers21.

More recently, research has extended algorithm configuration from single-objective to multi-objective settings, where trade-offs between conflicting objectives—such as accuracy vs. training time, or precision vs. recall—must be explored (The interested reader can see specialized surveys on the topic1,2 for a survey on the topic). This area, known as multi-objective hyperparameter optimization (MO-HPO), adapts both model-free and model-based strategies to discover Pareto-efficient configurations. For instance, multi-objective evolutionary algorithms (MOEAs) such as NSGA-II22 and SMS-EMOA7 have been used to directly evolve a set of configurations that approximate the Pareto front. In parallel, Bayesian optimization-based methods like ParEGO23, MO-TPE24, and Expected Hypervolume Improvement-based algorithms25 extend surrogate-assisted search to support multiple objectives through scalarization or hypervolume-based acquisition strategies. These methods provide a principled framework to guide configuration under trade-offs and have seen growing adoption in feature selection26 and neural architecture search27. Our work builds on these advances by applying representative approaches from both evolutionary (SMS-EMOA) and Bayesian (SMAC) approaches to optimize precision-recall trade-offs in the W-EAM model, contributing empirical insights into their effectiveness across domains of increasing complexity.

Data sets

In this work, we aimed to optimize three versions of W-EAM, each with a different level of difficulty. Below is a summary of the characteristics of the data that defined the three versions of the optimization problem. We begin with the recognition task using the MNIST dataset, which has been referred to as “the Hello World of classification problems”29. The second version of W-EAM uses the EMNIST-36 dataset, a subset of EMNIST that shares similarities with MNIST but contains more classes, which are unbalanced and show greater inter-class variability. Finally, the most challenging task is the recognition of Mexican Spanish phones, which was addressed using the DIMEx100 corpus8 together with the CIEMPIESS corpus9.Fig. 6Example instances from the MNIST dataset30.

MNIST

The MNIST dataset (“Modified National Institute of Standards and Technology”) is a database of images of handwritten digits, encoded as 28 \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\times$$\end{document} 28 pixel grayscale images, as shown in Fig. 6. This dataset contains 60,000 images for training and 10,000 for testing.

Since its release in 1998, it has become a standard benchmark for evaluating the performance of classification systems. Today, MNIST classification is considered a problem of low complexity29,31 and relatively straightforward, as most basic machine learning algorithms easily achieve around 97% accuracy, while deep learning models such as convolutional neural networks reach up to 99.7%.

Nevertheless, due to its popularity and simplicity, MNIST continues to be useful as a comparative metric and remains one of the most frequently cited datasets in the machine learning field.Fig. 7Three example instances from each class of the EMNIST Balanced dataset32. EMNIST-36 is a modification of this dataset in which uppercase and lowercase representations of each letter were merged into a single class, resulting in 36 classes.

EMNIST

The MNIST dataset was created from a larger database known as the NIST Special Database 1933, published in 1994, which contains handwritten digits and both uppercase and lowercase letters. In 2017, Cohen et al.34 released the Extended-MNIST or EMNIST dataset, which was extracted from the NIST database using the same procedure used to generate MNIST. The motivation behind EMNIST was to create a dataset that would pose a more difficult recognition task than MNIST while maintaining the same structure and parameters, ensuring direct compatibility with all existing MNIST classifiers.

EMNIST-36 contains the 26 different uppercase and lowercase letters of the English alphabet and the 10 digits (0 through 9), as shown in Fig. 7. For instance, the classes 11 (B) and 47 (b) were collapsed into a single one. This was done to demonstrate EAM’s ability to store overlapping representations of more than one class within the same memory register.

In the present work, the parameters of W-EAM were optimized on the EMNIST-36 dataset in order to compare the new results against the performance reported in the original EAM paper on handwritten symbol memory recognition12.Fig. 8Consonants of the Mexbet-22 phone alphabet for Mexican Spanish.Fig. 9Vowels of the Mexbet-22 phone alphabet for Mexican Spanish.

DIMEx100

The third and final problem addressed using W-EAM is phone memory recognition—that is, the identification of sounds or phone units in spoken language, in this case, Mexican Spanish. This task represents a significant increase in difficulty compared to the previous MNIST and EMNIST, as the data dimensionality increases from 2D to 3D due to the need to recognize sounds instead of images. In the first publication of W-EAM4, the phone domain was tackled using two data sets. The system was initially trained entirely on the DIMEx100 corpus and subsequently extended using the CIEMPIESS corpus, which lacks phone labeling.

The DIMEx100 corpus for Mexican Spanish consists of 6000 spoken sentences by 100 speakers, recorded using a high-quality microphone in a noise-free environment8. The participants were balanced by gender (49% male and 51% female) and selected to limit age (16–36 years), educational background (at least secondary education), and place of origin (residents of Mexico City, where 82% of participants were born). The dialect of Spanish spoken in Mexico City was chosen because it is considered representative of the variety of Spanish spoken by the majority of the population in the country35–37. The sentences to be spoken were selected from the internet, as it provides a large and balanced source in terms of phone variety. Sentences were chosen to contain 5–15 words and to exclude terms in English or other languages.

The spoken sentences were then manually transcribed phonetically by expert using the Mexbet-22 alphabet, shown in Figs. 8 and 9. This process was assisted by an automatic transcription system that provided canonical pronunciations of each word using simple rules to map graphemes to phones, along with default durations for each unit. Based on this transcription, the actual pronunciation of each spoken sentence was identified, and each phone was labeled with its duration at three levels of granularity, named T-22, T-44, and T-54, corresponding to the number of phones in each alphabet.

It has been shown that DIMEx100 is well-balanced8 in terms of phone frequency. A comparison between the phone distributions in DIMEx100 and a representative Latin American Spanish corpus38 found a correlation of 0.98. The corpus also exhibits good diversity in inter-class variability, meaning it contains a wide range of pronunciations. For instance, at the T-22 level of phone granularity, each word has an average of 1.28 distinct pronunciations, which increases to 1.64 at T-44 and 1.97 at T-54.

CIEMPIESS

The “Corpus for Research on Mexican Spanish from the Graduate Program in Electrical Engineering and Social Service” or CIEMPIESS9 was developed by the Language Technologies Laboratory of the School of Engineering at the National Autonomous University of Mexico (UNAM) with the goal of being freely distributed to support the development of automatic speech recognition models. It consists of approximately 18 h of dialogues in Mexican Spanish, sourced from recordings of Radio UNAM broadcasts, along with their textual transcriptions.

In the W-EAM model for phone recognition, CIEMPIESS is used to complement the system’s training, in the following brief procedure. First, the W-EAM system is trained for phone recognition using only the DIMEx100 corpus. Then a learning phase begins, which can be repeated n times: the W-EAM system, in its current trained state, is used to recognize and label phones from the CIEMPIESS corpus. Subsequently, the synthesis and analysis modules—essential components of W-EAM are retrained using new phone units from CIEMPIESS that were correctly recognized by W-EAM. These units also contribute to filling the memory registers, resulting in a new state of the W-EAM system (which can then be reused to identify more phones from CIEMPIESS, retrain, and so on).

Empirical results

This section states all the optimization experiments on W-EAM that were implemented in this work. These experiments are divided into three sections, corresponding to the three test data domains used: MNIST, EMNIST, and the phone domain (using DIMEx100 and CIEMPIESS). An optimization experiment refers to a run of SMAC or SMS-EMOA aimed at optimizing W-EAM in one of these three domains.

In addition to the ‘basic’ experiments, in which SMAC or SMS-EMOA is directly executed to optimize either the F1 score or Precision/Recall, two additional experiments of particular interest are proposed. The first is denoted as ‘W-SMAC’ (for Weighted SMAC) and consists of an SMAC run in which the objective function that maximizes F1 is replaced by a formula that computes a weighted sum of the Precision and Recall values. This is simply another way to summarize Precision and Recall into a single value, much like F1 does through the harmonic mean. However, W-SMAC allows for preferences to be incorporated into the optimization objective: by varying the weights that combine Precision and Recall, one can prioritize one metric over the other to different degrees.

The final experiment proposed here is denoted as ‘cyclical optimization’, and it was implemented only for the phone domain. It consists of executing an optimization method multiple times in sequence, interleaved with a phone learning stage12 after each run. In this stage, the training dataset is expanded by using W-EAM to identify new phones in the CIEMPIESS corpus, followed by retraining the auto-encoder neural networks with this augmented dataset. In this way, the optimization improves W-EAM’s performance not only by refining the \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\eta$$\end{document} operation but also by enhancing the quality of the CIEMPIESS phones selected during each learning phase, resulting in cumulative improvement.

Before presenting the experiments, we emphasize the rationale behind choosing a multi-objective approach that separates precision and recall, rather than optimizing the F1-score alone. Although the F1-score is a widely used metric that summarizes both precision and recall into a single value, it inherently assumes equal importance between these two objectives. In practice, however, this assumption does not always hold: different applications may prioritize one over the other. For example, in phoneme recognition tasks, it is often more critical to maximize recall to ensure that relevant phonemes are not missed, even at the expense of some loss in precision. Conversely, in other classification context,s high precision may be more desirable to avoid false positives. By formulating the problem as a multi-objective optimization task over precision and recall, rather than collapsing them into F1, we allow the search process to uncover the entire Pareto front of trade-offs. This enables practitioners to select the most appropriate configuration according to their domain-specific requirements, rather than being restricted to a single compromise defined by the harmonic mean.

The relatively poor performance of SMS-EMOA is simply due to the fact that the original design of EAM—without additional parameters—is already highly effective. Introducing parameters into the register and recognition operations expands the ways to fine-tune the system, but in practice, many parameter combinations degrade performance compared to the unweighted EAM. This is because parameters \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\iota$$\end{document}, \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\kappa$$\end{document}, and \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\xi$$\end{document} can excessively relax the system’s acceptance criteria, increasing recall at the cost of significantly reducing precision. In fact, the original authors of EAM/W-EAM only tested \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\iota$$\end{document} and \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\kappa$$\end{document} values between 0 and 2, and \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\xi$$\end{document} values of 0 or 1, while these experiments explored a range from 0 to 500. This was done to investigate whether viable configurations existed at higher parameter values; the result was negative, and the search space became both vast and filled with suboptimal solutions. Thus, it’s understandable that SMS-EMOA struggled, as its search process is more random and dispersed than SMAC’s, which leverages Bayesian inference to focus on the most promising regions of the search space.

This can be seen in Table 4, where SMAC’s top 20 configurations have lower standard deviations across all parameters compared to SMS-EMOA’s. It is also illustrated in Fig. 10, which contrasts the original EAM’s performance with the monotonic convergence time series of both optimization methods—each point in the time series indicates a newly found solution better than all previous ones. We see that SMAC located the most promising region of the search space and explored it in detail, while SMS-EMOA sampled a wider and more dispersed range of solutions.

The goal of using per-memory parameters was to provide greater granularity and potentially identify better solutions, but this came at the cost of a significantly larger search space, increasing from 36 to 144 decision variables. Figure 13 presents the monotonic convergence of SMAC in each learning stage. Recall that at the end of each stage, SMAC is run for a fixed amount of time to find the best parameter configuration for the current system state. The best configuration from stage i is then used to perform data augmentation in stage i+1, and the SMAC search in stage i+1 begins from this best prior solution. One might assume that the performance achieved at the end of stage i would be the same at the beginning of stage i+1, as the same configuration is being evaluated. However, note that the first stage is trained on the DIMEx100 corpus, and each subsequent stage addresses a new subset of the CIEMPIESS corpus—meaning each stage faces a different dataset. What we observe is an effect of overfitting—overspecialization to the validation dataset—caused by the fact that, due to time constraints, the objective function only iterates over one of the ten validation folds, thus only approximating true performance. Therefore, although convergence plots allow us to visualize the search behavior, rigorous evaluation of a configuration requires validation over tenfold. Once W-EAM generates a transcription attempt, its performance is evaluated using the Levenshtein distance between the W-EAM output string and the ground-truth transcription. The Levenshtein distance is simply the number of insertions, deletions, and substitutions required to transform one string into another. Thus, the lower the distance between the W-EAM output and the real transcription, the better the system’s performance. In this work, we refer to this metric as phone Distance, denoted ‘DF’. Additionally, we compute the phone distance after removing consecutive repeated characters, denoted ‘DFSR’.

Table 12 shows DF and DFSR values, as well as the corresponding Borda counts. The Borda count40 is a positional voting method used to compare candidates—in this case, W-EAM versions. Each “voter” corresponding to one of the 2000 validation sentences, assigns a ranking to each candidate based on a numerical preference value, where 1 is the worst result and \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$n=6$$\end{document} is the best. This ranking is computed for all 2000 sentences in the validation set. For each sentence, the six versions of W-EAM are compared across all training stages and 10 data folds. This would ideally yield 100,000 distinct Borda rankings; however, due to missing or improperly saved model states, the final total was 85,700 valid rankings. In each comparison, only versions of W-EAM using the same fold and training stage were compared.

The results show that while optimization is computationally intensive, the total time remains within reasonable bounds for offline training settings. Interestingly, SMAC’s cumulative time on MNIST exceeds that of SMS-EMOA despite having a faster first iteration. Conclusions and future work

The main contribution of this work was to identify and study multiple parameter configurations for W-EAM that improve its recognition performance across the three tested data domains.

We applied two state-of-the-art optimization methods, SMAC and SMS-EMOA, to the problem of finding efficient W-EAM parameter configurations in three different data domains. In all cases—except SMS-EMOA on MNIST—the optimization methods successfully found configurations that outperformed the control scenario in their respective domains, validating that the methods were correctly implemented and successfully converged. However, the performance improvement was small across all cases, and in the phone domain—our main target—the improvement was only about 1% in average F1 score.

These results demonstrate the robustness of the original, non-parametric EAM model. In both MNIST and EMNIST, the performance of EAM is very close to that of the best configurations found after hours of optimization, leading us to conclude that the parameter-free EAM model is well suited for handling these and similarly difficult memory recognition tasks.

In the phone domain, we observed the most significant performance gap between EAM and a well-tuned W-EAM—specifically between Scenarios I and V from the original paper. In this domain, parameters are essential to achieving satisfactory performance. However, we faced the issue of overfitting, which limits how long optimization can be applied to the same validation dataset. We believe this overfitting is why single-run optimization methods, such as SMS-EMOA and SMAC Singular, delivered limited results: after a certain point, generalization degrades, making further optimization ineffective. While increasing the size of the validation set would help, this would also increase the computational cost of each objective function evaluation. Using the fold with median performance, rather than a random one, proved to be an effective compromise.

Optimization was most effective in the phone domain when integrated into the staged iterative learning process. In this setup, optimization identified the best parameter configuration for each stage of the evaluation corpus and the current state of W-EAM. This significantly helped W-EAM better recognize and select new phones, which were then used to retrain the neural networks and fill the memory registers. Optimization thus contributed to improving the quality of the training corpus by helping to select better training data.

One of the goals of this research was to propose and implement an optimization methodology applicable to any current or future W-EAM-based system. This goal was fully achieved. However, when weighing the performance gain achievable through optimization against the time required to implement and run the methods, we would only recommend applying optimization in future W-EAM systems if the original non-parametric EAM or a known “good” parameter configuration (e.g., Scenario V) has already been tested and yielded clearly suboptimal results. Several effective configurations for their respective datasets are presented in Tables 3, 4, 6, 7, 9, and 10, which may prove useful for future W-EAM applications.

Through the various efficient configurations found, we were able to study the trade-off between the conflicting objectives of precision and recall. The efficient solutions found in each domain approximate the Pareto front of the multi-objective problem, meaning that all of these solutions are viable depending on which metric is prioritized.

In particular, W-EAM served as a test case for comparing SMS-EMOA and SMAC, revealing that SMAC generally found better solutions and converged more quickly. The results presented here provide further evidence that SMAC is highly effective for optimizing expensive objective functions with many decision variables, as its use of Bayesian optimization directs the search more efficiently toward promising regions of the search space compared to the broader, stochastic exploration typical of evolutionary methods.

Finally, while our current evaluation focused on three representative domains of increasing complexity (MNIST, EMNIST, and Mexican Spanish phone recognition), future work should explore additional benchmarks tailored specifically to highlight precision-recall trade-offs in more diverse or imbalanced classification tasks. This includes datasets where class imbalance or domain-specific costs make the optimization of precision and recall particularly critical, such as medical diagnosis, fraud detection, or information retrieval.
