Gold-standard-guided direct preference optimisation for ICD-10-AM and ACHI code assignment from discharge summaries
Authors: Rajvir Kaur, Jeewani Anupama Ginige, Oliver Obst
Published: 2026

ABSTRACT
Clinical codes assigned from discharge summaries support clinical research, reimbursement, health resource allocation, and service planning. In Australia, ICD-10-AM and ACHI are used to code diagnoses and interventions for admitted episodes of care, but manual coding is time-consuming, labour-intensive, and subject to variability. This study investigates large language models for automated ICD-10-AM and ACHI code assignment from discharge summaries. We first normalised a public ICD-9-CM coded dataset into the Australian coding system using General Equivalence Mappings and semantic similarity over code descriptions, with validation by a domain expert clinical coder. We then fine-tuned Meta-Llama-3-8B and compared full-parameter fine-tuning with a parameter-efficient QLoRA baseline. Finally, we applied Direct Preference Optimisation (DPO) using gold-standard-guided preference pairs, where the gold-standard ICD-10-AM/ACHI code list was treated as the preferred response and the supervised fine-tuned model output as the non-preferred response. Experiments were conducted on a mapped MIMIC-III subset and a de-identified Australian hospital dataset. Among the evaluated model variants, the DPO-aligned full-parameter model achieved the highest score, with micro-F1 scores of 0.7397 on the mapped dataset and 0.7834 on the Australian hospital dataset. These findings suggest that gold-standard-guided DPO can improve agreement with reference code sets compared with supervised fine-tuning alone. However, the results are limited to high-frequency diagnosis and procedure codes, short-document evaluation settings, and DPO preference pairs reviewed by one annotator.Supplementary InformationThe online version contains supplementary material available at https://doi.org/10.1186/s12911-026-03631-w.

Introduction

Accurate clinical coding is foundational to hospital reimbursement and activity-based funding, epidemiological surveillance, quality reporting, and clinical research. In practice, trained clinical coders review free-text clinical documentation - often the discharge summary written at the end of a hospital stay - and assign diagnosis and procedure codes. This process is labour-intensive and time-consuming, and it can be vulnerable to variability and error, which can propagate downstream to funding and reporting outcomes [1].

In Australia, inpatient episodes are coded using the Australian Health Classification System: the International Statistical Classification of Diseases and Related Health Problems, Australian Modification (ICD-10-AM) for diagnoses and health conditions; the Australian Classification of Health Interventions (ACHI) for procedures and interventions; and the Australian Coding Standards (ACS) for national coding rules. Although ICD is an international standard, country specific adaptations differ in code granularity, code availability, and coding rules. These differences can be clinically meaningful and can limit the direct transfer of automated coding models developed for other jurisdictions [2]. For example, in the U.S. classification system, ‘contact with venomous spider’ is coded as X21, whereas in Australia, there is more specificity added in the level of identifying the type of spider including X21.0 (Contact with funnel-web spider), X21.1 (Contact with red back spider), and X21.2 (Contact with white-tailed and other necrotising spider). Automating code assignment from discharge summaries is challenging for several reasons. Discharge summaries are long, heterogeneous, and contain abbreviations, and institution-specific phrasing. The clinical reasoning behind a diagnosis is sometimes implied rather than clearly stated, making it harder for a system to interpret. The target label space is large and highly imbalanced, and each record typically requires multiple diagnosis and procedure codes. Models must also respect hierarchical code structures and adhere to coding standards, while remaining robust to documentation variation across hospitals and time.

Given that manual assignment of ICD code relies on manual inspections and experience-based judgement, studies utilised Artificial Intelligence (AI) techniques to automate the ICD coding process. This includes both conventional machine learning [2–6] and deep learning approaches [7–12]. Most prior work on automated clinical coding has concentrated on United States coding systems(e.g., ICD-9-CM, ICD-10-CM/PCS), largely because large public datasets are available such as MIMIC-III [13]. In contrast, reproducible benchmarks and comparative evidence for Australian ICD-10-AM/ACHI coding remain limited, slowing progress and making it difficult to evaluate newer methods fairly in the Australian context. A second, related barrier is reliability: even when modern neural models achieve strong aggregate metrics, they can under-perform on rare codes and may produce clinically implausible or non-existent codes - behaviour that is especially problematic for billing and reporting workflows.

Large language models (LLMs) offer a promising direction because they can represent long-range context and can be adapted to generate structured outputs directly from free text. However, using these models straight out of the box has its drawbacks. They may not align with local coding expectations and may generate unsupported, invalid, or clinically implausible outputs. One way to address this is to align model outputs more closely with the gold-standard coding references after supervised fine-tuning. Direct Preference Optimisation (DPO) provides a way to optimise a model using preferred and non-preferred responses without training a separate reward model or using an explicit reinforcement-learning loop. In this study, we use DPO as a gold-standard-guided alignment step after supervised fine-tuning.

In this work, we investigate an LLM-based approach for assigning ICD-10-AM and ACHI codes from discharge summaries, focusing on both performance and practical training efficiency. First, to enable controlled experiments using public data, we propose an NLP-assisted mapping pipeline that maps codes from US-coded datasets (via official crosswalks where available) to their closest ICD-10-AM and ACHI counterparts using semantic similarity between code descriptions and expert review. Second, we fine-tune the Llama 3 model for clinical code generation and compare full fine-tuning against parameter-efficient adaptation (LoRA/QLoRA), quantifying the trade-offs between compute requirements and coding accuracy. Third, we apply DPO using gold-standard-guided preference pairs derived from reference code sets and supervised fine-tuned model outputs, aiming to improve agreement with gold-standard ICD-10-AM/ACHI assignments. For tractability and to reflect high-volume coding scenarios, our experiments focus on the top 50 ICD-10-AM diagnosis codes and top 50 ACHI procedure codes (100 codes total). We evaluate on a mapped subset of MIMIC-III discharge summaries and a de-identified Australian hospital dataset, reporting standard multi-label metrics (micro/macro precision, recall, and F1).

Related work

Automated ICD coding has been a prominent area of research in the healthcare domain for the last two decades. Many conventional machine learning [2–6] and deep learning approaches [7–12] have been explored to automate the assignment of ICD codes. Huang et al. [14] compared several methods, including recurrent neural networks (RNNs) and convolutional neural networks (CNNs), and reported that deep learning-based methods achieved higher performance than conventional machine-learning methods for ICD code assignment. Nevertheless, RNNs were found to have several shortcomings when it comes to capture long-range dependencies due to issues like vanishing gradients. CNNs, on the other hand are effective in capturing local features through convolutional filters but lack the ability to model sequential or temporal dependencies effectively. To overcome these limitations, Long Short-Term Memory networks (LSTMs) [14] were introduced, a variant of RNNs designed with gating mechanisms that allow them to retain information over longer sequences. Models like Convolutional Attention for Multi-Label (CAML) [8] utilised label-wise attention mechanisms to better capture the relationships between clinical text and ICD codes. Subsequently, attention-based models such DR-CAML [7] and HyperCore [15] further leveraged label dependencies to enhance coding accuracy. Despite these advancements, challenges persisted, particularly in handling the vast number of ICD codes, the hierarchical structure of ICD codes, unstructured nature of clinical documents, and struggled with rare or ambiguous codes.

The introduction of Transformers including Bidirectional Encoder Representations from Transformers (BERT) [16], and Generative Pretrained Transformer (GPT) [17], have largely replaced LSTMs by leveraging self-attention mechanisms that allow them to model global dependencies and enhance parallelisation. Though, transformers-based models have proven invaluable for many biomedical applications, but these models required significant memory for training, due to which the usage of these models become challenging. Large Language Models(LLMs) posses a great potential to analyse vast amount of unstructured data captured in healthcare, such as patient narratives, electronic health records (EHRs), clinical trial results, and research publications. The extensive datasets used to train these LLMs has enabled them for various transferable language tasks. However, the medical terminologies, domain-specific jargon, and unique reporting practices in healthcare contrast sharply with the general-purpose language used to train these models. To address these issues and improve the usability of pre-trained language models in the biomedical field, researchers have focused on domain-specific adaptations during the pre-training phase and have implemented fine-tuning strategies on the models. During pre-training, efforts are made to use the existing models in the biomedical domain by extending the pre-training process or stating a new with vast amount of raw biomedical data, making these models more adaptable through fine-tuning. Efficient models such as BioBERT [18], ClinicalBERT [19], PubMedBERT [20] have been specifically designed for the biomedical domain and are ideal for downstream task during the fine-tuning stage. ClinicalBERT, pre-trained on clinical notes, and SciBERT [21], pre-trained on scientific texts, are also tailored for medical text summarisation. BioBERT has been reported to improve over the original BERT model on biomedical text-mining tasks such as relation extraction, named entity recognition, and question answering.

Large language models (LLMs) such as GPT-3, GPT-4, and LLaMA have opened up new possibilities for automating ICD coding. These models, with their vast parameter sizes and pretrained on extensive corpora, exhibits remarkable capabilities in understanding and generating human-like text. Nawab et al. [22] fine-tuned GPT-3.5 Turbo on discharge summaries from MIMIC-III, improving top-10 ICD code prediction accuracy by over 30% compared to base models. However, showed reduced performance when tested on external datasets due to differences in documentation styles, coding guidelines and clinical terminology. To address these challenges, there is a need to incorporate human-in-the-loop strategies and reinforcement learning from human feedback (RLHF) to refine model outputs or guide training in real-world preferences.

These prior models provide important context for automated clinical coding; however, they were not re-implemented or evaluated on the same ICD-10-AM/ACHI label space and data splits in this study. Therefore, they are discussed as related work rather than direct experimental baselines.

Methodology

We formulate automated clinical coding as an instruction-following generation task: given a discharge summary, the model generates the corresponding set of ICD-10-AM diagnosis codes and ACHI procedure codes. We use meta-llama/Meta-Llama-3-8B [23] as the base model. Our pipeline proceeds in three stages. First, we perform supervised instruction fine-tuning (SFT) to adapt the base model to the coding task. Second, we benchmark a compute-efficient alternative using parameter-efficient fine-tuning (PEFT) with a 4-bit quantised backbone. Third, we apply gold-standard-guided Direct Preference Optimisation (DPO) to the full-parameter fine-tuned model to improve agreement with reference code sets.

Fine-tune large language model

Fine-tuning is an effective strategy that allows large language models to leverage their pre-trained knowledge and adapt to new tasks, enhancing their performance and generalisation abilities. Through fine-tuning, language models can apply their prior understanding to new domains and tasks, increasing their usefulness and effectiveness. This process involves taking an existing pre-trained model, such as BERT or GPT and training it further on domain-specific knowledge to improve its ability to generate accurate and contextually relevant responses. By leveraging the existing knowledge encoded in pre-trained models, fine-tuning saves considerable time and computational resources compared to training models from scratch.

There are several fine-tuning methods, notably domain adaptation, transfer learning, and task-specific fine-tuning. Domain adaptation involves training models on data what is similar yet distinct, allowing the model to adapt related contexts effectively. Transfer learning leverages a pre-trained model trained on related tasks and further trains it on a new but related task, making it particularly beneficial when training data is limited. On the other hand, task-specific fine-tuning involves training a model extensively from scratch on new data related to a particular task, making it ideal when the new task is very different from the original or requires significant customisation.

When fine-tuning is done properly, it can dramatically improve a model’s performance, making it effective for tasks like translation, summarisation, question-answering, and text generation. However, improper fine-tuning can lead to problems like overfitting, where models perform well on training data but poorly on unseen data; underfitting, which results from insufficient training, reduced generalisation ability, lack of transferability to other tasks, and increased computational complexity. To resolve these challenges, researchers applied techniques like regularisation, early stopping, dropout, cross-validation, and batch normalisation to prevent overfitting or underfitting. Fine-tuning very large models is often extremely computationally demanding and expansive. For example, fine-tuning a large -scale language model such as LLaMA with 65 billion parameters demands more than 780 GB of GPU memory [24].

Task formulation and supervised fine-tuning

We model code assignment as instruction-following generation: the input prompt consists of an instruction and the discharge summary, and the model outputs a structured response listing the predicted codes.

Training instances are represented as JSON records with fields \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\{\texttt{instruction},\texttt{input},\texttt{response}\}$$\end{document}. The instruction specifies the task (e.g., “Assign appropriate ICD-10-AM diagnosis and ACHI procedure codes for the given discharge summary.”), the input contains the discharge summary text, and the response contains the gold-standard code list formatted in a consistent template. Across experiments, we use a fixed output structure that separates diagnosis and procedure codes to support robust downstream parsing and evaluation.

Supervised fine-tuning adapts the base model to the clinical coding task by maximising the conditional likelihood of the reference response y given the prompt x. With an autoregressive policy \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\pi_\theta$$\end{document}, the SFT objective minimises the negative log-likelihood: 1\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$L_{\mathrm{SFT}}(\theta) = -\mathbb{E}_{(x,y)}\left[\sum_t \log \pi_\theta\left(y_t \mid x, y_{ < t}\right)\right].$$\end{document}

At inference time, the model is prompted with the same instruction template and generates a response that is post-processed to extract ICD-10-AM and ACHI codes. Post-processing includes normalising formatting, removing duplicates, and retaining only codes within the evaluation scope. The extracted code sets are then used for evaluation.

Parameter-efficient fine-tuning (LoRa/QLoRA baseline)

Full-parameter fine-tuning of large language models can be computationally expensive. To evaluate a compute-efficient alternative, we compare full fine-tuning against a parameter-efficient baseline based on Low-Rank Adaptation (LoRA) [25]. In LoRA, a frozen weight matrix W is augmented by a low-rank update Δ W = BA, where \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$A \in \mathbb{R}^{r\times k}$$\end{document} and \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$B \in \mathbb{R}^{d\times r}$$\end{document} with rank \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$r \ll \min(d,k)$$\end{document}. Only the adapter parameters are trained, substantially reducing the number of trainable parameters.

We implement a quantised PEFT [26] variant using a bitsandbytes 4-bit quantised backbone (QLoRA-style), in which the base model weights are stored in 4-bit precision for memory efficiency while training LoRA adapters. This model is used as the “quantised” baseline in our full fine-tuning vs. quantised comparison.

Scope of DPO alignment

Although preference alignment can be combined with PEFT/QLoRA in principle, in this work we apply DPO only to the full-parameter, non-quantised fine-tuned model. The QLoRA model is used as a parameter-efficient baseline to compare resource-efficient adaptation with full-parameter fine-tuning. We then evaluate gold-standard-guided DPO as an additional alignment step on the full-parameter model. This design avoids introducing a separate quantised-DPO training condition with different adapter and hyperparameter choices. Therefore, the quantised PEFT baseline is reported as a separate comparison and is not DPO-aligned.

Direct Preference Optimisation (DPO)

Supervised fine-tuning can achieve strong average performance but may still produce extra codes, omit relevant codes, or generate malformed outputs. To better align model behaviour with reference coding, we apply Direct Preference Optimisation (DPO) [27], which learns from pairwise preferences relative to a reference policy \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\pi_{\mathrm{ref}}$$\end{document} (the full-parameter SFT model) without training a separate reward model.

Construction of gold-standard-guided preference pairs

We construct a gold-standard-guided preference dataset for DPO. For each discharge summary x, we form a preference pair \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$(x, y_w, y_l)$$\end{document} where the preferred response \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$y_w$$\end{document} is the gold-standard ICD-10-AM/ACHI code assignment (formatted in the same response template used at inference time) and the non-preferred response \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$y_l$$\end{document} is the model-generated prediction for the same input. This provides a preference signal anchored to reference labels rather than independent human rankings of alternative model outputs.

We implemented a lightweight annotation interface using Streamlit to support review and curation. For each record, the interface displayed the model-generated codes and indicated whether each predicted code was present in the gold-standard set (e.g., “present” vs. “not present” in ground truth). The interface also surfaced missing gold-standard codes to highlight underprediction and enabled the annotator to record correctness judgements and optionally add codes. All annotations and metadata were stored in a SQLite database (record identifier, dataset source, query/prompt, predicted output, gold-standard output, and timestamp) to ensure traceability.

To focus the preference signal on informative failures, we retained records where the model output exhibited (i) extra-code errors, where predicted codes were not present in the gold standard, (ii) completely incorrect predictions (no overlap with the gold standard), or (iii) partially correct predictions (mixed correct and incorrect codes). We excluded instances where the model prediction exactly matched the gold-standard code set because these examples provide no informative preference signal for DPO. Using this procedure, we curated approximately 850 preference pairs from the mapped ICD dataset and 1,150 preference pairs from the hospital dataset (approximately 2,000 pairs total). Although the preference set is modest in size, it is intentionally enriched for difficult cases, including extra-code errors, partially correct predictions, and incorrect predictions, providing high-signal alignment examples. Preference pairs were reviewed and curated by a single annotator, who was also an author. Therefore, the resulting preference dataset should be interpreted as single annotator, gold standard guided curation of gold-versus-prediction pairs, not as expert RLHF or human preference learning based on independent ranking of candidate outputs.

The reward model is trained by minimising the negative log-likelihood loss [29]: 3\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$ \mathcal{L}_R(r_\phi, \mathcal{D}) = -\mathbb{E}_{(x, y_w, y_l) \sim \mathcal{D}} \left[ \log \sigma \left( r_\phi(x, y_w) - r_\phi(x, y_l) \right) \right],$$\end{document}

Experimental setup

The experimental setup involves two distinct datasets to evaluate model performance. Below, we describe the datasets, code mapping methodology, and model training details.MIMIC-III (Mapped to ICD-10-AM and ACHI): The discharge summaries acquired from the MIMIC-III [13], contains deidentified health-related data associated with over 40,000 patients who stayed in the ICU of the Beth Israel Deaconess Medical Center between 2001 and 2012. Normalise clinical datasets pre-coded in different extensions of ICD classification system

Mapping ICD-9-CM diagnosis and procedure codes from MIMIC-III to the Australian Health Classification System (ICD-10-AM for diagnoses and ACHI for procedures) requires a multi-step approach because there is no official one-to-one crosswalk from ICD-9-CM to ICD-10-AM/ACHI. We therefore perform forward mapping via the U.S. ICD-10 extensions and then align to the Australian target vocabularies (Figure 3).Fig. 3Mapping pipeline from ICD-9-CM to ICD-10-AM/ACHI via ICD-10-CM and ICD-10-PCS

Mapping pipeline from ICD-9-CM to ICD-10-AM/ACHI via ICD-10-CM and ICD-10-PCS

In this study, we used the 2018 CMS/CDC General Equivalence Mappings (GEMs) for the ICD-9-CM to ICD-10-CM/PCS mapping step. For the final Australian target vocabulary, we used ICD-10-AM/ACHI/ACS Eleventh Edition code descriptions. Historical IHPA releases from the 1st to 12th editions were checked only to identify code availability, retired codes, and terminology changes; the final mapped target vocabulary was based on the Eleventh Edition.

Step 1: ICD-9-CM → ICD-10-CM/PCS using GEMs

We used the 2018 CMS/CDC General Equivalence Mappings (GEMs) to map ICD-9-CM diagnosis codes to ICD-10-CM and ICD-9-CM procedure codes to ICD-10-PCS. These intermediate codes are accompanied by code titles/descriptions that can be used for subsequent semantic alignment.

Step 2: ICD-10-CM/PCS → ICD-10-AM/ACHI using semantic similarity

Because no direct mapping exists between ICD-10-CM/PCS and ICD-10-AM/ACHI, we select the closest Australian codes using natural language processing (NLP). We embed the textual code descriptions from ICD-10-CM/PCS and ICD-10-AM/ACHI/ACS Eleventh Edition using a sentence-transformer model and compute cosine similarity between embeddings. For each source code, we retrieve the top-k=3 most similar target codes as candidates.

Domain-expert review and validation

The automatically retrieved top-k candidates for each code were reviewed by a domain expert clinical coder (with experience in Australian clinical classification systems). The reviewer selected the most appropriate ICD-10-AM/ACHI code for each source code based on the code definitions and clinical meaning. Ambiguous cases were resolved through discussion with the research team, and the final validated mapping was stored as a structured mapping dictionary used to convert the MIMIC-III labels into the Australian target label space for subsequent experiments.

Diagnosis mapping considerations (ICD-10-CM vs ICD-10-AM)

ICD-10-CM often encodes additional specificity using extra digits (e.g., laterality such as left/right/unspecified), whereas ICD-10-AM may represent the same concept at the stem/parent level within our label scope. Accordingly, when an ICD-10-CM code has no direct one-to-one equivalent at the same level of specificity in ICD-10-AM, we map it to the closest ICD-10-AM stem/parent code that preserves the clinical concept (a controlled many-to-one mapping). For example, sciatica may appear as M54.30 (unspecified side) in ICD-10-CM, whereas it is represented as M54.3 (Sciatica) in ICD-10-AM (Table 6). In contrast, codes that are shared across the modifications (e.g., I12.0, J18.9) map directly without truncation. Procedure mapping considerations (ICD-10-PCS vs ACHI)

Procedure code systems differ more substantially than diagnosis code systems. ICD-10-PCS uses a seven-character alphanumeric structure, while ACHI uses numeric codes organised into blocks. As a result, one-to-one correspondences are less common and mapping collisions can occur more frequently. In the mapped MIMIC-III experiments, the initial top-50 ICD-9-CM procedure source codes produced 45 unique ACHI procedure labels because several ICD-9-CM procedure variants mapped to the same ACHI target label. For example, ICD-9-CM procedure codes 88.56 (coronary arteriography using two catheters) and 88.55 (coronary arteriography using a single catheter) both mapped to ACHI 38,215–00 (Coronary angiography). Similarly, ICD-9-CM procedure codes 36.06 (insertion of non-drug-eluting coronary artery stent) and 36.07 (insertion of drug-eluting coronary artery stent) both mapped to ACHI 38,306–00 (Percutaneous insertion of 1 transluminal stent into single coronary artery). These examples illustrate how procedure-code variants in ICD-9-CM can collapse into a smaller number of ACHI labels in the final mapped vocabulary.

Checking code validity across editions

During mapping, we verified that candidate Australian codes existed in the ICD-10-AM/ACHI/ACS Eleventh Edition target vocabulary used in this study. We also checked historical IHPA releases from the 1st to 12th editions to identify codes that had been introduced, revised, or retired over time. For example, ICD-10-AM code A08.1 underwent revision from the Tenth Edition to the Eleventh Edition. The Tenth Edition listed the condition as “Acute gastroenteropathy due to Norwalk agent”, whereas the Eleventh Edition updated the title to “Acute gastroenteropathy due to Norovirus”, reflecting a change in terminology. Additionally, the associated inclusion terms were also revised in the Eleventh Edition, highlighting updates in clinical language and accuracy.

Multi-label counts

For a code label \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\ell \in L$$\end{document}, we treat prediction as a binary decision (predicted vs not predicted) and compute:\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\begin{aligned} & TP_\ell = \sum_{i=1}^{N}\mathbb{II}[\ell \in Y_i \wedge \ell \in \hat{Y}_i], \quad \cr& FP_\ell = \sum_{i=1}^{N}\mathbb{II}[\ell \notin Y_i \wedge \ell \in \hat{Y}_i], \quad \cr& FN_\ell = \sum_{i=1}^{N}\mathbb{II}[\ell \in Y_i \wedge \ell \notin \hat{Y}_i]\end{aligned}$$\end{document}

We do not emphasise true negatives (TN) because the label space is large and sparse, making TN-dominated measures (e.g., accuracy) less informative for clinical coding.

Micro-averaged precision, recall and F1

Micro-averaging aggregates counts across all labels, weighting each individual label decision equally and reflecting overall system performance on frequent codes: \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\begin{aligned} & P_{\mathrm{micro}}=\frac{\sum_{\ell \in L}TP_\ell}{\sum_{\ell \in L}(TP_\ell+FP_\ell)}, \qquad \cr& R_{\mathrm{micro}}=\frac{\sum_{\ell \in L}TP_\ell}{\sum_{\ell \in L}(TP_\ell+FN_\ell)} \cr& F1_{\mathrm{micro}}=\frac{2P_{\mathrm{micro}}R_{\mathrm{micro}}}{P_{\mathrm{micro}}+R_{\mathrm{micro}}}\end{aligned}$$\end{document}

Macro-averaged precision, recall and F1

Macro-averaging computes metrics per label and then averages them, treating rare and frequent codes equally: \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\begin{aligned} & P_{\mathrm{macro}}=\frac{1}{|L|}\sum_{\ell \in L}\frac{TP_\ell}{TP_\ell+FP_\ell}, \qquad \cr& R_{\mathrm{macro}}=\frac{1}{|L|}\sum_{\ell \in L}\frac{TP_\ell}{TP_\ell+FN_\ell} \cr& F1_{\mathrm{macro}} =\frac{2P_{\mathrm{macro}}R_{\mathrm{macro}}}{P_{\mathrm{macro}} + R_{\mathrm{macro}}}\end{aligned}$$\end{document}

If a denominator is zero for a label (e.g., no predicted positives), we define the corresponding term as zero.

Jaccard similarity

We report global Jaccard similarity using the aggregated true positives, false positives, and false negatives across all labels: \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$JS =\frac{\sum_{\ell \in L} TP_\ell}{\sum_{\ell \in L} TP_\ell + \sum_{\ell \in L} FP_\ell + \sum_{\ell \in L} FN_\ell}.$$\end{document}

Higher JS indicates greater global overlap between predicted and reference code sets.

Confidence intervals

We computed 95% confidence intervals using non-parametric bootstrap resampling over test records. For each dataset and model, we sampled test records with replacement for 1,000 bootstrap iterations and recomputed micro-precision, micro-recall, micro-F1, macro-precision, macro-recall, macro-F1, and Jaccard similarity. We report percentile-based 95% confidence intervals using the 2.5th and 97.5th percentiles.

QLoRA (4-bit) vs full-parameter fine-tuning

QLoRA gave lower scores than full-parameter fine-tuning across both datasets. On the mapped dataset, QLoRA obtained a micro-F1 of 0.5109 (macro F1 0.3687) compared with 0.6569 (macro-F1 0.5985) for full fine-tuning. On the hospital dataset, QLoRA achieved a micro-F1 of 0.4406 (macro-F1 0.4256), whereas full fine-tuning achieved 0.7078 (macro-F1 0.7186). This reflects the expected efficiency–accuracy trade-off when training with a 4-bit quantised backbone and a limited set of adapter parameters.

Effect of DPO alignment

Applying gold-standard-guided DPO to the full-parameter model achieved the highest scores among the evaluated model variants in both datasets. On the mapped dataset, micro-F1 increased from 0.6569 to 0.7397, and Jaccard similarity increased from 0.4891 to 0.5870. On the hospital dataset, micro-F1 increased from 0.7078 to 0.7834, and Jaccard similarity increased from 0.5477 to 0.6439. These results suggest improved agreement with the reference code sets relative to supervised fine-tuning alone.

Error-type analysis

Extra-code errors were defined as predicted codes that were not present in the gold-standard code set, while missed-code errors were defined as gold-standard codes that were not predicted by the model. We also counted exact-match records and records with no overlap between the predicted and gold-standard code sets. This analysis was limited to code-level set errors. Long-document generation failures, such as repeated text, invalid outputs, or failure to produce a usable code list, were considered separately and were not included in the error-type counts.

Mapped vs hospital dataset performance

For the full-parameter and DPO-aligned models, the scores were higher on the hospital dataset than on the mapped dataset. One possible explanation is that the hospital dataset uses native ICD-10-AM/ACHI labels, whereas the mapped dataset may introduce mapping-related uncertainty and label collisions due to cross-system mapping. For example, some ICD-9-CM procedure variants collapse to the same ACHI target label, reducing the final mapped procedure vocabulary from 50 source procedure codes to 45 ACHI labels. The two datasets also differ in source context: MIMIC-III contains United States ICU discharge summaries originally coded with ICD-9-CM, whereas the SWSLHD dataset contains contemporary Australian hospital discharge summaries coded directly using ICD-10-AM/ACHI. Differences in documentation style, clinical terminology, case mix, coding practice, and mapping may therefore all contribute to the observed performance difference. Because we did not perform a controlled matched-subset ablation to isolate the effect of mapping or dataset source, this explanation should be interpreted as a hypothesis rather than a confirmed cause.

Results are reported for discharge summaries up to 1000 words; longer notes led to generation failures (repetition or invalid output) in preliminary testing. Importantly, we did not truncate discharge summaries; longer notes were excluded from the reported evaluation. In future, we aim to explore transformer architectures with extended context windows and structured decoding frameworks to reduce long-document generation failures and improve coding performance on long-form discharge summaries.

Limitations

This study has several limitations. First, the evaluation was restricted to a limited high-frequency code set. The hospital dataset used the top 50 ICD-10-AM diagnosis codes and the top 50 ACHI procedure codes, giving 100 labels in total, while the mapped MIMIC-III dataset contained 95 labels after procedure-code mapping collisions. Codes outside the selected vocabulary were not used as prediction targets or evaluation labels. Therefore, the reported results should be interpreted as performance within a common-code evaluation setting rather than full-vocabulary clinical coding. This restricted label scope may under-represent admissions dominated by rare diagnoses, uncommon procedures, speciality-specific codes, complication codes, or complex multi-morbidity. Records containing both selected and non-selected codes may also be simplified because only selected high-frequency labels are retained for evaluation. Within this restricted label setting, we also treated diagnosis codes as an unordered multi-label set and did not distinguish the principal diagnosis from additional diagnoses or predict condition onset flags. Separating principal and additional diagnoses within this limited label scope may not be reliable because many clinically important diagnosis codes may fall outside the evaluation vocabulary. Future work should evaluate broader code sets and model principal diagnosis, additional diagnoses, and condition onset flags as separate prediction tasks.

Second, the quantitative evaluation was limited to shorter discharge summaries. The reported metrics were calculated only for discharge summaries within the 1,000-word evaluation setting. Longer summaries were excluded rather than truncated because preliminary testing showed repeated text, invalid outputs, or failure to generate a usable code list. This excluded 3,687 of 4,941 mapped MIMIC-III test records and 5,443 of 10,444 SWSLHD test records. Therefore, the reported metrics may describe a shorter-document subset rather than full real-world clinical coding, where longer admissions may contain more diagnoses, procedures, complications, and coding-relevant details. These long-document generation failures have practical implications for clinical coding workflows. If repeated, invalid, missing, or extra code outputs were used without careful human review, they could affect reimbursement, activity-based funding, health-service reporting, and quality indicators. This is particularly relevant for long and complex admissions, where coding decisions may carry greater administrative and clinical importance. Therefore, the current model should be viewed as decision support within the evaluated short-document setting, not as an autonomous coding system for long or complex discharge summaries. Future work should explore long-context models, section-aware chunking, retrieval-augmented generation, and structured decoding to improve performance on longer discharge summaries.

Third, the DPO preference data were gold-standard-guided rather than based on independent human preference rankings. The preferred response was the gold-standard code list, and the non-preferred response was the supervised fine-tuned model output. The preference pairs were reviewed and curated by one annotator, who was also an author, and no second reviewer, inter-annotator agreement analysis, or held-out audit set was available. This limits the reliability assessment of the preference-pair curation process. To reduce subjectivity, the pairs were anchored to gold-standard code sets rather than subjective preferences. In addition, DPO was applied only to the full-parameter fine-tuned model and not to the QLoRA baseline. Therefore, the current results show the effect of gold-standard-guided DPO within the full fine-tuning setting, but do not determine whether similar gains would be achieved when DPO is combined with PEFT/QLoRA. Although we added a code-level error-type analysis, we did not perform a clinician-reviewed qualitative error analysis by ICD chapter, ACHI block, clinical severity, or coding impact. Long-document generation failures were also not included in this code-level error-type analysis. Future work should include multiple independent clinical coding reviewers, formal agreement analysis, evaluation of DPO with parameter-efficient fine-tuning, and clinician-reviewed error analysis by code chapter, error type, and clinical importance.

Fourth, the mapped MIMIC-III dataset depends on indirect cross-system mapping from ICD-9-CM to ICD-10-AM and ACHI. Because no direct one-to-one mapping is available, we used GEMs, semantic similarity over code descriptions, and review by a clinical coding expert. We added a mapping audit summarising which mappings were accepted, retained with coder rationale, or revised after expert review. However, this audit should not be interpreted as an independent mapping accuracy estimate because the review was performed by one clinical coding expert only. No second independent mapping review, inter-coder agreement analysis, or formal mapping error analysis was performed. Differences in code granularity and many-to-one mappings may introduce label noise, especially for procedure codes. In addition, the hospital dataset was drawn from one Australian local health district, so documentation style, coding practice, case mix, and data quality may differ across other hospitals and jurisdictions. Future work should include independent mapping review, formal agreement analysis, and external evaluation across multiple Australian hospitals.

In addition, the reported performance metrics are based on one training run per model. Although we report 95% bootstrap confidence intervals over test records, these intervals quantify test-set sampling uncertainty and do not capture training-run variability due to random seed, optimisation path, or hardware nondeterminism. Because full-parameter fine-tuning and DPO alignment were computationally expensive, the current study was limited to one training run per model condition. Therefore, the observed differences should be interpreted as descriptive comparisons among the evaluated Llama 3 variants rather than statistically confirmed superiority. Future work should include repeated runs with different random seeds and direct comparison with established automated coding baselines under the same ICD-10-AM/ACHI label space and data splits.

Future research directions

In this work, we used LLaMA 3 (8B) and restricted quantitative evaluation to discharge summaries with a maximum length of 1,000 words because generation quality degraded for longer notes (e.g., repetition or failure to output a valid code list). Future work will focus on improving robustness to long clinical documents. Promising directions include long-context models, section-aware chunking and aggregation (e.g., encoding key sections such as diagnoses, procedures, and hospital course), structured decoding with stricter output constraints, and retrieval-augmented generation (RAG) to ground predictions in coding standards and code definitions. Larger-capacity models (e.g., LLaMA 3 70B) may also be explored, although they require substantially greater computational resources and do not by themselves guarantee robustness on long inputs.

We also observed that many high-frequency codes correspond to chronic comorbidities or additional diagnoses rather than the principal diagnosis driving the admission. Future work will explicitly model this distinction by predicting (or ranking) the principal diagnosis separately from additional diagnoses, consistent with Australian coding conventions, and by evaluating principal-diagnosis performance as a dedicated outcome.

Finally, we plan to extend experiments beyond the top-50 diagnosis and top-50 procedure scope by evaluating larger label sets (e.g., top-100 and ultimately broader code coverage), which will require strategies for class imbalance, rare-code learning and hierarchical structure. We also plan to explore additional language models and privacy-preserving approaches (e.g., federated learning), and to investigate retrieval-based methods that incorporate local clinical documentation patterns and coding standards.

Conclusion

Assigning ICD-10-AM diagnosis codes and ACHI procedure codes from discharge summaries is a challenging multi-label task because clinical narratives are heterogeneous and each episode may require multiple diagnosis and procedure codes. In this study, we investigated large language models for automated Australian clinical coding using both a mapped public dataset and a de-identified Australian hospital dataset.

We developed a multi-step normalisation pipeline to map ICD-9-CM labels from MIMIC-III into ICD-10-AM/ACHI using GEMs, semantic similarity over code descriptions, and clinical coding expert review. We then fine-tuned meta-llama/Meta-Llama-3-8B and compared full-parameter fine-tuning with a resource-efficient QLoRA baseline. Full-parameter fine-tuning gave higher scores than QLoRA on both datasets, suggesting a trade-off between computational efficiency and coding accuracy.

We also applied gold-standard-guided Direct Preference Optimisation (DPO) to the full-parameter fine-tuned model. Among the evaluated model variants, the DPO-aligned model achieved the highest score, with micro-F1 scores of 0.7397 on the mapped dataset and 0.7834 on the Australian hospital dataset. These results suggest that gold-standard-guided DPO can improve agreement with reference code sets beyond supervised fine-tuning alone. This should not be interpreted as full human preference learning, because the DPO pairs were based on gold-standard code sets and model outputs rather than independent human rankings of alternative outputs.

Overall, this study demonstrates the feasibility of LLM-assisted ICD-10-AM/ACHI code assignment and provides an initial benchmark for automated Australian clinical coding. Future work should evaluate broader code vocabularies, longer discharge summaries, principal diagnosis and condition-onset information, and multi-annotator preference curation to support stronger evidence for real-world clinical coding workflows.
