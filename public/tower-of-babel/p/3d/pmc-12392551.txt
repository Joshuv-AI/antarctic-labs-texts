Dotplotic: a lightweight visualization tool for BLAST + alignments and genomic annotations
Authors: Hideyuki Miyazawa, Toshiyuki Oda
Published: 2025

ABSTRACT
With the development of sequencing technologies, chromosome-level genome assemblies have become increasingly common across various organisms, including non-model species. BLAST + is one of the most widely used bioinformatics tools for computing sequence alignments, offering numerous optimizations for speed and scalability. Dot plots, which visualize the similarity between two sequences, are widely used in biological research. However, while many dot plot-generating programs exist, most rely on their own alignment algorithms, and it is uncommon to visualize external BLAST results directly. Here, we present Dotplotic, a lightweight Perl program that generates dot plot-like visualizations based on BLAST output in tabular format. Dotplotic visualizes each alignment as a line connecting the start and end points of the query and subject sequences, with a gradient color indicating sequence identity. It allows users to overlay annotation data from external files onto the plot. Although command-line-based, Dotplotic is implemented as a single script using only core Perl modules, making it easy to install and run across platforms. The program supports standard input for both BLAST results and annotation files, enabling flexible visualization under various conditions, such as filtering specific alignments or displaying selected genomic features like genes or repeats. Dotplotic is an efficient, portable, and easy-to-use visualization tool that enhances the exploration of sequence alignments and serves as a valuable resource for both bioinformatics and broader biological research.Supplementary InformationThe online version contains supplementary material available at 10.1186/s12859-025-06255-5.

Background

Whole-genome sequencing has recently been conducted on a wide range of organisms due to advances in high-throughput technologies such as Oxford Nanopore and PacBio HiFi. Chromosome-level assemblies with high accuracy are becoming increasingly common—not only for the small genomes of viruses and prokaryotes but also for the large, repeat-rich genomes of vertebrates. Comparing assembled sequences, including non-coding regions such as introns and repeats, allows researchers to uncover genome diversity and evolution across species. For example, synteny patterns, such as gene order on chromosomes, are becoming increasingly important in phylogenetic studies e.g., [1].

Dot plots are a widely used method for visualizing sequence comparisons and are helpful to researchers across many biological fields. For bioinformaticians, dot plots between assembled and reference sequences help assess the quality of sequencing and assembly. For evolutionary biologists, they reveal genomic rearrangements: large regions of similarity appear as diagonal lines, repeats generate multiple lines, inverted regions appear as lines in the opposite direction, and insertions or deletions appear as gaps.

In a basic dot plot, dots are placed where the two sequences share the same nucleotide or amino acid on a two-dimensional matrix. However, this simple method is unsuitable for large-scale sequence comparisons. Modern approaches instead calculate similarity between sequences and place dots in regions of high similarity. Several programs follow this approach, such as Dotter [2], JDotter [3], tuple_plot [4], Gepard [5], mummerplot [6], FlexiDot [7], and D-Genies [8]. Because calculating sequence similarity is computationally intensive—particularly for searches involving many long sequences—these tools have improved their algorithms to reduce processing time and memory usage. Cabanettes and Klopp [8] classified dot plot-generating tools into two generations based on their user interface: first-generation tools run only on Unix systems and produce static graphics without interactive features, and second-generation tools are platform-independent, user-friendly, and provide interactive interfaces, such as options for changing sequence orientation. The first category includes tuple_plot, mummerplot, and FlexiDot, while Dotter, Gepard, JDotter, D-Genies belong to the second.

Pairwise sequence alignment is a fundamental method for identifying similar regions between two sequences, providing detailed local alignment information. While various tools for sequence similarity searches have been developed, such as minimap2 [9], MMseqs2 [10], and DIAMOND [11], the Basic Local Alignment Search Tool (BLAST) is one of the most commonly used algorithms for sequence similarity searches, despite its long history [12, 13]. BLAST + , a suite of command-line tools developed by the National Center for Biotechnology Information (NCBI), is widely used by both biologists and bioinformaticians [14]. It includes options for parallelization and for reducing database size by masking repetitive regions, making it suitable for large-scale searches on servers. Nearly all DNA sequences generated by researchers are stored in databases maintained by NCBI, and BLAST searches against this vast repository can be run through the NCBI website, contributing greatly to advances in biological and medical research.

Many software tools support BLAST searches and some generate dot plots based on BLAST output, including Unipro UGENE [15], Geneious [16], and NBLAST [17]. However, dot plot visualization tools that directly use external BLAST results remain scarce. Tools like Dotter rely on their own search algorithms and are not optimized to process BLAST output. Graphical user interface (GUI)-based software such as UGENE is user-friendly but not well-suited for large-scale comparisons involving numerous chromosome-level sequences. Dotplotter, a command-line interface (CLI)-based tool that can read external BLAST results [18], offers limited functionality—for instance, it does not display sequence identity in the plots.

Here, we present Dotplotic, a command-line visualization tool that reads external BLAST output and generates dot plots. Dotplotic displays each alignment as a line colored according to sequence identity and allows users to overlay annotation data from external files. Output is generated in Scalable Vector Graphics (SVG) format, which can be edited with software such as Inkscape and exported to Portable Document Format (PDF). We also developed two supplementary programs: EditDotplotic and Minimapsam2blast6. EditDotplotic allows users to modify SVG files generated by Dotplotic, for example, by rotating query sequence labels. Minimapsam2blast converts SAM format files produced by minimap2 into the BLAST tabular-like format files compatible with Dotplotic. Additionally, we provide DotploticGUI.py, a Python-based wrapper that offers a graphical user interface for Dotplotic. This interface enables users to run Dotplotic through an intuitive GUI without needing to type commands. All tools are available on GitHub and are designed to facilitate efficient and user-friendly visualization of large-scale sequence comparisons.

Implementation

Dotplotic, Minimapsam2blast6, and EditDotplotic are implemented in the Perl programming language (version 5.6 or later), and the former two programs require only core modules List::Util, Getopt::Long, and Pod::Text, and the last one require no modules. DotploticGUI.py is implemented in the Python programming language (Python 3.12 or later), requiring the three modules, tkinter, subprocess, and threading.

Although many advanced Perl modules for bioinformatic analyses, such as BioPerl [19], are available, their installation can sometimes be challenging depending on the computing environments. To ensure ease of use, we developed the three Perl programs requiring only core modules, allowing them to use immediately after downloading from the GitHub repository without requiring additional dependencies. DotploticGUI.py is the GUI version of Dotplotic, but it must be launched from the CLI, and the current version can only generate the plot file without displaying it on the window, like other tools. Several Python modules for creating GUIs have been developed, and we used them to develop this tool.

Input data

BLAST + programs (blastn, blastx, blastp, tblastn, and tblastx) support various output formats specified via the ‘outfmt’ option. Dotplotic supports three of these formats: tabular (‘-outfmt 6’), tabular with comment lines (‘-outfmt 7’), and comma-separated values (‘-outfmt 10’). Dotplotic requires that the BLAST search output be formatted appropriately using the ‘outfmt’ option. Users can include various fields in the BLAST output, such as ‘qaccver’ as Query accession version, and ‘bitscore’ as Bit score. The following nine fields are required for Dotplotic processing: ‘qaccver’, ‘saccver’, ‘pident’, ‘bitscore’, ‘length’, ‘qstart’, ‘qend’, ‘sstart’, and ‘send’, and these fields can appear in any order within the input file. Dotplotic also supports overlaying annotation data on the plot, supporting GFF, BED, or OUT from RepeatMasker formats (www.repeatmasker.org) [20].

Drawing process

Using four values—query start (‘qstart’), query end (‘qend’), subject start (‘sstart’), and subject end (‘send’)—the program draws a line connecting the points (‘sstart’, ‘qstart’) and (‘send’, ‘qend’). The percentage of identical matches (‘pident’) is converted into a hexadecimal (hex) color code. Three identity thresholds—maximum (Max), middle, and minimum (Min)—are defined along with their corresponding color codes. By default, these are set to 100% (red, ‘#FF0000’), 80% (orange, ‘#FFFF00’), and 60% (lime, ‘#00FF00’). Identity values between Min and Max are linearly mapped to intermediate colors. Values below Min or above Max are assigned the Min and Max colors, respectively. Rectangles representing annotation features are drawn when annotation data is available.

Output format

Dotplotic produces output in SVG format, which can be opened in web browsers, such as Google Chrome and Mozilla Firefox. If the ‘click’ option is enabled, the SVG file embeds object information that can be viewed by clicking on graphical elements.

Vector graphic software such as Adobe Illustrator and Inkscape can open SVG files and export them to other formats. When converted to PDF, alignment lines and annotation rectangles remain sharp even when zoomed in. Although Dotplotic offers layout flexibility, the display may become cluttered if the BLAST input file includes too many sequences. To address this, the accompanying Perl program EditDotplotic can be used to adjust visual elements such as font size or remove sequence length labels.

Results

Dotplotic represents each alignment in the BLAST tabular format as a single line, each annotation data as a rectangle (Fig. 1). The Dotplotic workflow consists of four steps (Fig. 2): (1) Given a BLAST output file, and optionally an annotation file, Dotplotic reads the input. (2) Dotplotic calculates basic statistics, including the number and total lengths of query and subject sequences. If the sequence order is not specified by the user, Dotplotic automatically arranges the order so that the general direction of the BLAST alignment appears as a diagonal line from top left to bottom right of the plot. To achieve this, best-path searches are performed across all query-subject combinations to determine the query-subject relationships and their relative orientation. Subjects are sorted by name, and queries are ordered according to the order of their associated subjects. For large BLAST files (e.g., genome-to-genome comparisons), best-path computation may consume significant memory and time. In such cases, users can reduce resource usage by manually specifying sequence order or by enabling the ‘light’ mode. When this option is enabled, query and subject sequences are automatically sorted by name, and short BLAST alignments (less than 1kbp) are excluded, thereby reducing both computational load and the size of output SVG file. (3) Based on the statistics of the BLAST alignments, Dotplotic determines the layout of the plot. The reduction scale is set according to the total length of the query or subject sequences, the sequences are arranged in a defined order, and individual plotting regions are allocated for each sequence. (4) If annotation data are provided, they are displayed as rectangles. SAM-format alignment data includes the names of the query and subject sequences, the alignment starting position on the subject, and a CIGAR string. The query start and end positions, query length, and the numbers of mismatches, insertions, and deletions can be calculated from the CIGAR string. The dynamic programming (DP) alignment score that is denoted by the ‘AS:i:’ tag in the SAM file is used as the bit score. Although the resulting output reports all E-values as ‘0.0’ because a single SAM alignment does not provide sufficient information to compute them, Minimapsam2blast6 generates alignment results in a BLAST-like tabular format based on this information.

Sequence identity is then calculated based on the derived alignment statistics. The other accompanying program, EditDotplotic, modifies specific objects in the SVG file generated by Dotplotic. Most of the SVG objects in the output file are represented by individual lines of text, each including an SVG tag and an identifying comment tag. For example, query sequence labels in the plot are written as lines beginning with’ < text’ and containing the tag ‘ < !–query_name– > ’. EditDotplotic uses these comment tags to locate and modify targeted elements within the SVG file. DotploticGUI.py is a supplementary Python program that provide a GUI for executing Dotplotic (Fig. S1). While the GUI is launched from the CLI, it allows users to specify all parameters and paths of input BLAST file and output SVG file without directly editing the command-line options. Although the generated plot is not displayed within the window, the interface facilitates the full configuration and execution of Dotplotic, making it more accessible to users unfamiliar with the CLI.

Discussion

In this study, we present Dotplotic and other accompanying programs. Our aim was to develop a lightweight and easily installable tool for visualizing alignment results with annotation data, without requiring complex dependencies. Minimapsam2blast6 allows to convert minimap2 outputs into a format compatible with Dotplotic. Users can further customize plot features, such as sequence label tilt and alignment line thicknesses, using EditDotplotic. For users unfamiliar with the CLI, the GUI wrapper, DotploticGUI.py, provides an accessible interface. Sequence alignment of long and numerous sequences is often performed on high-performance servers that lack graphical desktop environments, which presents challenges for visualization. Dotplotic, Minimapsam2blast6, and EditDotplotic are compatible with both laptops and headless server environments, providing a practical solution for genome comparison visualization.

Case study in yeast genomes

Here, we demonstrate the visualization of BLAST alignments involving three yeast genomes using Dotplotic. The lager-brewing yeast Saccharomyces pastorianus is an interspecific hybrid of S. cerevisiae and S. eubayanus, and the genome of one of its strains, CBS 1483, has been sequenced at the chromosomal level [21]. We obtained nuclear genome sequence datasets for the three yeast species from GenBank: 31 chromosomes (total length: ca. 23.0 Mbp) for CBS 1483 (S. pastorianus, GenBank assembly accession: GCA_011022315.1), 16 chromosomes (total length: 11.6 Mbp) for S. cerevisiae (GCF_000146045.2), and 16 chromosomes (total length: 12.1 Mbp) for S. eubayanus (GCF_001298625.1). Additionally, we downloaded the genome annotation file of S. cerevisiae (GCF_000146045.2_R64_genomic.gff) from GenBank.

A BLAST search was conducted using CBS 1483 as the query and the other two species as subjects, with output in tabular format including query and subject lengths (using ‘-outfmt "6 std qlen slen"‘). Alignments shorter than 1 kbp were filtered out to reduce the output file size (23 MB to 1 MB). Dotplotic was subsequently executed to visualize the BLAST alignments (Fig. 3). Genomic rearrangements have been reported in several chromosomes [21], and we visualized these events using Dotplotic (Fig. 4). Homologous recombination between chromosome X of S. cerevisiae and S. eubayanus was clearly observed in CBS 1483 (Fig. 4a). In chromosome SeIII-ScIII of CBS 1483, approximately two-thirds of the first half showed high similarity to chromosome III of S. eubayanus, while about one-third of the second half matched chromosome III of S. cerevisiae, suggesting a homologous recombination event between the two species (Fig. 4b). However, the truncated regions, approximately two-thirds of the first half of chromosome III in S. cerevisiae and about one-third of the second half of chromosome III in S. eubayanus, were not present in the CBS 1483 assembly (Fig. 3). While chromosomes ScVII and SeVII-ScVII in CBS 1483 correspond to chromosome VII in S. cerevisiae and S. eubayanus, respectively, approximately 100 kbp from the first half of S. cerevisiae chromosome VII align with that of SeVII-ScVII in CBS 1483, suggesting a translocation from S. cerevisiae to S. eubayanus (Fig. 4c). Although chromosome ScXII in CBS 1483 was generally similar to chromosome XII in S. cerevisiae, several repeated regions were observed (Fig. 5). The repetitive alignments in the central region suggest tandem repeat insertions. Additionally, all interspersed alignments were flanked by long terminal repeats (LTRs) on both the 5′ and 3′ ends, suggesting the proliferation of these regions along with LTR expansion.

Running Dotplotic on large BLAST alignment datasets increases memory usage, processing time, and the size of resulting SVG output file. Although converting SVG files into PDF format using Inkscape remarkably reduced the file size, the resulting PDFs still exceed 1 MB when the alignment count approaches one hundred thousand. Dotplotic’s best path search running for calculation of relative distances between query and subject sequences is skipped when the ‘light’ option is enabled. This substantially reduces both memory usage and processing time. When a BLAST result contains a large number of short, potentially uninformative alignments, filtering them can be an effective approach for generating a more interpretable and concise overview of genome comparisons.

Comparison to other dot plot generating tools

We compared Dotplotic with several recently developed dot plot-generating tools that are available across various platforms, including Gepard [5], Unipro UGENE [15], MUMmer4 [6], and D-GENIES [8] (Table 1). Among these tools, only MUMmer4 is command-line based, while the other three tools, Gepard, Unipro UGENE, and D-GENIES, are primarily GUI-based. These GUI-oriented tools generate dynamic plots that users can interact with, such as by zooming, offering a high level of interactivity, while the command-line based tool generated static plots. Although users can run Dotplotic through the GUI version (DotploticGUI.py) and access object information by enabling the ‘click’ option, the output graphic itself is not interactive, suggesting that Dotplotic belongs to the first-generation category defined by Cabanettes and Klopp [8]. However, Dotplotic does not perform alignment searches itself and dedicated solely to visualization. Comparison of dot plot-generating tools

Despite these limitations, we believe that Dotplotic offers three key advantages. First, it supports output from BLAST + , a widely used command-line alignment tool [14]. According to Google Scholar, BLAST + was cited 2,890 times in 2024 alone, indicating that many bioinformaticians have installed and used the tool. It is likely employed in routine analyses without citation, suggesting that BLAST + is widely and regularly used, even for minor or background tasks. By providing an intuitive visualization option for BLAST + results, Dotplotic can significantly contribute to bioinformatics research. Minimap2 is also widely used alignment tool [9]. The accompanying program, Minimapsam2blast6, convert its SAM-format output into a BLAST-like tabular format, enabling Dotplotic to generate dot plots from the results.

Second, Dotplotic can easily overlay annotation data onto plots. The relationship between LTRs and repetitive regions is visualized in Fig. 5, which was generated with a single command (Table S1), demonstrating its ease of use. By modifying the annotation input, Dotplotic users can investigate the types and locations of genomic rearrangements. It is one of the most beneficial features of Dotplotic is its ability to combine alignment results and annotation data in a single command, without requiring intermediate files or preprocessing by other tools.

Finally, Dotplotic is compatible with a wide range of platforms. Software with advanced features, such as high-throughput computing or multifunctional capabilities, is sometimes sensitive to changes in the development environment and may fail after updates to either the software or the underlying platform. In contrast, Dotplotic is a lightweight Perl program that depends only on core modules, making it likely to remain functional across diverse systems into the future.

Conclusion

BLAST + is a command-line–based alignment search tool and one of the most widely used programs in bioinformatics. However, most existing dot plot visualization tools rely on their own alignment algorithms, and visualizing results directly from BLAST + output remains difficult. To fill this gap, we present Dotplotic, a visualization tool specifically designed for BLAST + output. Dotplotic is implemented as a single Perl script that depends only on core modules, making it lightweight, platform-independent, and easy to use.

Dotplotic can not only generate plots for genome comparisons but also overlay annotation data onto the plots, allowing users to visually compare genomic rearrangements with annotated features. This makes it a valuable tool for many bioinformaticians and biologists.
