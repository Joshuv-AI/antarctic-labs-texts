DNA-DETR: sequence representation matters in object detection for functional genomic elements
Authors: Bing-Shiun Tsai, Jin-Yung Wong, Huai-Kuang Tsai
Published: 2026

ABSTRACT
AbstractObject detection has revolutionized multiple domains by enabling models to jointly classify and localize targets within data. Yet, its potential in genomic sequence analysis remains largely unexplored. Here, we introduce DNA-DETR, an adaptation of the DETR architecture for one-dimensional genomic object detection. Surprisingly, the direct application of object detection to DNA sequences yielded poor performance, even for elements with simple definitions such as Non-B DNA. We found that the widely used one-hot encoding failed to capture key structural features of several Non-B DNA types. To address this limitation, we systematically investigated how different sequence representations, including one-hot encoding, dot matrix, and their combination, affect detection accuracy and model generalization. Our experiments demonstrate that the choice of representation profoundly affects both localization and classification. Notably, the combined representation consistently outperformed single representations, particularly for complex sequence elements. Our findings suggest that there is no universal ‘one-representation-fits-all’ solution in sequence feature learning. Despite the common perception that end-to-end learning diminishes the importance of representation, our results highlight that thoughtful selection of sequence representation remains critical for model design.Keywords: sequence representation, object detection, functional genomic elements, DETR, transformer

Introduction

Data-driven machine learning forms the foundation of artificial intelligence, and with increasing computational power, deep learning has emerged as its dominant paradigm. In bioinformatics, deep learning has been extensively applied to tasks such as gene expression regulation, epigenetics, and drug discovery [1, 2]. Recent studies have also explored its application to genomic sequence analysis [3–5], where DNA sequences are often modeled analogously to images in computer vision or text in natural language processing (NLP). Most of these efforts, however, focus on classification tasks.

In contrast, accurately identifying the location of functional genomic elements remains a major challenge in genomics and computational biology. This problem is conceptually analogous to object detection in computer vision, which requires not only classifying objects but also precisely locating them within an image. Compared to classification, object detection is inherently more complex, as it demands both spatial precision and categorical accuracy. Modern object detection architectures such as YOLO [6], Faster R-CNN [7], and SSD [8], rely heavily on convolutional neural networks (CNNs). Recently, the Detection Transformer (DETR) [9] introduced the first transformer-based architecture for object detection, offering an end-to-end solution that eliminates the need for region proposals and non-maximum suppression. This approach significantly simplifies post-processing and facilitates the handling of densely overlapping features, a common property of genomic data. Despite these advancements, only a few preliminary attempts have been made to apply object detection to DNA sequences [10].

To adapt vision-based object detection models for genomic data, DNA sequences must first be transformed into image-like representations. This can be done with one-hot encoding, which is widely used in genomics and has enabled the adaptation of popular vision models to DNA tasks. In particular, one-hot encoding is the go-to choice for convolution-based classifiers. Yet beyond classification, the combination of one-hot encoding and convolution can be limiting. An alternative is token-based encoding combined with language models, as shown in the adaptation of NLP model for nucleosome positioning [11]. Beyond these two paradigms, other representation strategies remain underexplored, likely because it is expected that end-to-end models can automatically extract all relevant features without explicit representation design [12].

In this study, we developed DNA-DETR, a customized adaptation of the DETR model tailored for DNA sequence analysis. As a proof of concept, we targeted sequences with the potential to form Non-canonical B-form structures (Non-B DNA) as the genomic elements of interest. We chose Non-B DNA potential sequences because their features can be defined by relatively simple rules [13], thus are suitable as baseline training data to test object detection model’s capability in detecting sequence patterns. Unlike canonical B-DNA double helix, Non-B DNA encompasses a variety of atypical DNA conformations, including G-quadruplexes (G4), Z-DNA, R-loop, Slipped DNA, Triplex DNA, and Cruciform DNA. These motifs are present across domains [14], and have been implicated in crucial processes [15–19]. However, training a baseline model with Non-B DNA potential sequences proved more challenging than expected, leading us to explore alternative representation strategies beyond one-hot encoding. Through systematic evaluation, we show that the choice of representation plays a critical role in object detection tasks and our DNA-DETR model is flexible with respect to input representations, providing a framework for DNA element detection.

Results

DNA-DETR enables accurate detection of non-B DNA elements using object detection

We present DNA-DETR, a specialized object detection framework adapted from DETR [9] for the identification and localization of specific DNA elements. As shown in Fig. 1, raw DNA sequences are first transformed into various representations before being processed by DNA-DETR. The model outputs both predicted class labels and bounding boxes, thereby simultaneously classifying and locating detected DNA elements (see Materials and methods for details).

Workflow of DNA-DETR. DNA sequences containing specific DNA elements are transformed into different representations, which are then used as input to the DNA-DETR model for simultaneous classification and localization for sequence elements.

To evaluate DNA-DETR, we focused on six elements of Non-B DNA, including G4, Z, R-loop, Slipped, Triplex, and Cruciform DNA. Representative examples are provided in Table 1. Initially, we used one-hot encoding, a widely-used DNA sequence representation, as input across all six elements. DNA-DETR achieved strong performance in single-class object detection on simulated datasets for G4, Z, and R-loop DNA elements (Fig. 2A), indicating strong detection and classification capabilities for these three elements when using one-hot encoding. In contrast, DNA-DETR with one-hot encoding completely failed to detect DNA elements in the simulated datasets for Slipped, Triplex, and Cruciform (Fig. 2A).

Concept-type DNA is defined by specific patterns or rules that govern how different segments are arranged.

Based on the sequence characteristics and model performance, we categorized Non-B DNA elements into Content and Concept. Content-type DNA, such as G4, Z-DNA, and R-loop, is characterized by simple, repetitive sequence compositions. For example, G4 and R-loop elements are enriched in G clusters, while Z-DNA elements consist of dinucleotide repeats such as CG, TG or CA. These repetitive and straightforward patterns make Content-type DNA well-suited to one-hot encoding. In contrast, Concept-type DNA, such as Slipped, Triplex, and Cruciform DNA, has more complex and diverse repeat elements that vary across instances. For example, Slipped DNA may consist of different repeated units (e.g. ATCG ATCG versus GCAT GCAT), making it difficult for one-hot encoding to generalize and detect these features accurately.

To address the limitations of one-hot encoding for Concept-type DNA, we employed a dot matrix representation, which compares two sequences by plotting one along the x-axis and the other along the y-axis, marking positions of matching nucleotides. Such a matrix is particularly effective in capturing structural symmetries and internal repeats. In addition to using conventional dot matrix representation, we developed novel variations tailored for Non-B DNA detection (see Materials and Methods). Using dot matrix representations, DNA-DETR achieved promising performance in single-class object detection across all six Non-B DNA elements in simulated datasets (Fig. 2A), demonstrating the representation’s versatility in modelling both Concept- and Content-type elements. The necessity of this multi-channel design is demonstrated by a channel-ablation study (Supplementary Table S1), which reveals that no single channel is sufficient for all motifs, and integrating all three specialized channels is required for optimal performance. This design is further supported visually by saliency analysis using Integrated Gradients [20], which shows that the model selectively prioritizes specific dot matrix variants based on the characteristics of each Non-B DNA motif (Supplementary Fig. S1).

Given that canonical B-DNA is the dominant form in the human genome, with only approximately 13% potentially forming Non-B DNA structures [21], we further assessed DNA-DETR’s ability to distinguish between sequences with and without Non-B DNA elements. To this end, we included sequences without Non-B DNA objects as negative samples during training and testing phases. The binary classification results (Fig. 2B) showed that DNA-DETR, using dot matrix representation, achieved F1 scores exceeding 0.9 across various Non-B DNA elements. To provide a comprehensive performance benchmark, we fine-tuned widely-used pretrained model DNABERT-2 [22] for the same task. Notably, while DNABERT-2 and DNA-DETR (with one-hot encoding) failed to learn structurally complex motifs such as Triplex and Cruciform, the dot matrix approach maintained strong performance across all categories. Additional performance metrics were provided in Supplementary Fig. S2A, supporting the model’s robustness in distinguishing true Non-B DNA fromnegatives.

Single-class object detection on genome-derived non-B DNA data and the role of sequence complexity

Following the promising results obtained on simulated data, we applied DNA-DETR to genome-derived sequences. Surprisingly, when using one-hot encoding as input, the model exhibited unexpectedly good performance in detecting Concept-type Non-B DNA elements in genome-derived data (Fig. 3A). Specifically, average precision (AP) scores exceeded 0.5 for Slipped and Cruciform DNA, and reached as high as 0.72 for Triplex DNA, all using one-hot encoding.

Single-class object detection and classification performance on genome-derived non-B DNA data using DNA-DETR with one-hot encoding and dot matrix representations. (A) Bar plots showing that content-type non-B DNA sequences are best detected using one-hot encoding, while concept-type DNA sequences achieve higher detection performance when using dot matrix representation. (B) Binary classification results for identifying sequences containing non-B DNA elements. While DNABERT-2 performs competitively on concept-type non-B DNA, DNA-DETR (with dot matrix representation) consistently outperforms other models in concept-type sequences. (C, D) for sequences with high complexity scores (top 5%) across each non-B DNA element, detection accuracy drops markedly, especially for concept-type sequences, indicating that DNA-DETR with one-hot encoding primarily learned patterns from low-complexity sequences.

To understand this discrepancy from simulated data results, we investigated the detected objects and found that many exhibited relatively simple sequence patterns. For example, sequences such as ‘TATATA TATATA’ conformed to the rules of Slipped DNA, while patterns like ‘TTTTT AAAAA’ matched the criteria for Cruciform DNA. These findings suggest that the genome-derived dataset is enriched for low-complexity instances (see Materials and Methods), in contrast to the more complex and diverse patterns present in the simulated datasets (Supplementary Fig. S3A–F).

We hypothesized that the model primarily learned to recognize low-complexity features, which are more akin to Content-type DNA patterns, rather than truly capturing the structural rules that define Concept-type elements. To test this, we calculated the sequence complexity of all test samples. The results confirmed that sequences with higher complexity (top 5%, Fig. 3C) had substantially lower detection accuracy (Fig. 3D and Supplementary Fig. S3G), indicating that the model failed to generalize to these complex Concept-type sequences. Furthermore, a continuous analysis across all sequence complexity intervals revealed that the performance gap between representations widens as sequence complexity increases (Supplementary Fig. S3H–M). Thus, the model’s performance on genome-derived data was largely driven by overrepresentation of simpler instances rather than true structural learning.

Based on these observations, we conclude that one-hot encoding remains suitable for Content-type DNA detection, while dot matrix representation is essential for robustly modelling Concept-type DNA. This conclusion is further supported by the binary classification results (Fig. 3B and Supplementary Fig. S2B), which show a consistent pattern: one-hot encoding outperforms dot matrix representation for Content-type DNA, whereas the opposite holds true for Concept-type DNA. Notably, while DNABERT-2 performs competitively on certain Non-B DNA elements, DNA-DETR with dot matrix representation consistently outperforms other models on Concept-type sequences. These findings highlight the importance of selecting appropriate input representations based on the inherent sequence characteristics of the DNA element being modeled. Aligning the representation strategy with the structural characteristics of the target elements improves model performance and interpretability.

Multi-class object detection on genome-derived non-B DNA data

Conventional tools for Non-B DNA element detection typically rely on independently designed algorithms, each tailored to a specific element [13]. In this study, we reframed these isolated tasks as a unified object detection problem. By integrating both one-hot encoding and dot matrix representations as model inputs (Fig. 4A; see Materials and methods), we trained DNA-DETR for multi-class object detection across all six Non-B DNA elements. This combined representation enables the model to learn both the compositional features and the structural rules of Content-type and Concept-type Non-B DNA.

(A) Schematic overview of the three input representation strategies used in multi-class model: One-hot encoding, dot matrix, and their combination. (B) Bar plots showing model performance at two input sequence lengths (200 bp and 500 bp) across three independent runs. The combined representation consistently outperforms individual representations, achieving higher mAP with associated error bars. (C) Visualization of detection results illustrating the model’s ability to accurately localize various elements of non-B DNA, with each element represented by a distinct color. (D) Binary classification results indicating whether a sequence contains non-B DNA elements, showing consistent improvements with combined input representations. (E) Model performance on testing sequences with high complexity scores (top 5%) confirms its robustness and capacity to generalize beyond low-complexity patterns.

To improve adaptability across different element lengths, we trained the model using two input sequence lengths: 200 bp and 500 bp. Notably, the 200 bp model excluded R-loop DNA, as the average length of R-loops exceeds 200 bp and differs substantially from the size of other Non-B DNA elements (Supplementary Fig. S4). Such discrepancies in object length can negatively affect model performance, particularly for shorter objects, thus motivating the use of dual-length models to better accommodate sequence diversity.

The results (Fig. 4B), based on three independent runs, demonstrate that models trained with combined representations outperform those using either one-hot or dot matrix alone. Specifically, the model with a 200 bp input length achieved a mean Average Precision (mAP) of 0.908 0.002 at 200 bp and 0.810 0.012 at 500 bp. These findings demonstrate the effectiveness of representation fusion for enhancing multi-class detection performance. Visualization of model predictions (Fig. 4C) further confirms DNA-DETR’s ability to accurately localize divergent Non-B DNA elements in genome-derived sequences. Importantly, the multi-class model with 200 bp input consistently outperformed all single-class models, none of which achieved an AP of 0.9 for any Non-B DNA element. This suggests that the multi-class training enhances the model’s generalization capacity by exposing it to more diverse sequence features. We further hypothesize that multi-class training increases data diversity, thereby enhancing model generalization across structural variation while reducing overfitting. In contrast, single-class models may overfit class-specific features, limiting their adaptability. By learning across multiple elements simultaneously, DNA-DETR achieves a better balance between specificity and generalization, improving its robustness in detecting previously unseen or complex sequence elements.

To further validate model robustness, we evaluated binary classification performance on positive versus negative samples using the three representation strategies (Fig. 4D and Supplementary Fig. S2C). Models trained with combined representations at both 200 bp and 500 bp lengths outperformed those using single representations, demonstrating enhanced ability to distinguish between sequences with and without Non-B DNA elements. Finally, to assess whether the model could detect high-complexity Concept-type sequences, we evaluated its performance on test data composed of the top 5% most complex sequences (Supplementary Fig. S3G). As shown in Fig. 4E, the multi-class model achieved APs exceeding 0.7, with some reaching as high as 0.95, confirming its robustness across varying levels of sequence complexity. Unlike the one-hot single-class model, which failed to detect complex Concept-type elements, the combined representation approach enables the model to generalize beyond simple patterns and recognize structurally diverse features.

Discussion

Deep learning has been widely adopted for DNA sequence prediction, especially for classification tasks. This progress can be partly attributed to the successes of directly applying popular image classification models to DNA, often by transforming DNA sequences into images with simple one-hot encoding. Despite the ‘modality gap’ between image and DNA, end-to-end models can manage to learn meaningful features, and achieve similar performance as in image tasks. However, in contrast to classification, object detection in genomic sequences remains largely underexplored, even though it has been as transformative in computer vision as classification itself. In adapting the image object detection model DETR to DNA, we found that the usual formula of one-hot encoding did not work as well across Non-B DNA patterns. By introducing alternative sequence representations into our detection models, we improved the model’s performance on Non-B elements that were previously difficult to detect, providing a proof-of-concept for object detection on DNA sequences. These results suggest that, while end-to-end learning frameworks can overcome the modality gap in many cases, the choice of representation remains a critical factor when adapting image models to genomics.

Object detection is a more complex problem than classification, slowing its adoption in genomics. In addition to predicting object categories, it must also accurately localize them with nucleotide-level precision. The problem is further complicated by the fact that a given sequence window may contain no object, or multiple (possibly overlapping) objects, both common scenarios in genomic data. Earlier object detection models address the localization and overlapping challenges with hand designed methods such as spatial anchors and non-maximal suppression. In this study, we chose DETR because it removes these components that would otherwise need to be redesigned and optimized when adapting object detection to genomics, reducing ambiguity over whether poor performance reflects failed adaptation or suboptimal tuning. DETR also has known limitations in detecting small objects, which is particularly challenging for genomic elements, as their sizes vary significantly. For example, R-loops are typically much longer than other Non-B DNA elements. Despite these, the fully end-to-end architecture of DETR makes it the ideal choice to test the cross-modality adaptation of object detection on genomics.

When DNA-DETR was trained with one-hot encoding, it failed to converge for ‘Concept-type’ Non-B DNA patterns (Slipped, Triplex, and Cruciform DNA), suggesting that one-hot encoding was unable to capture the structural rules used to simulate these elements. In genome-derived datasets, one-hot encoding-based models were trainable for low complexity sequences but tended to recognize only simpler patterns, such as tandem repeats associated with these Non-B elements, rather than the intended structural features. This overfitting to superficial patterns is a phenomenon known as spurious pattern recognition [23]. Our tests across the full spectrum of sequence complexity showed that one-hot encoded models struggled with a substantial portion of genome-derived Non-B sequence patterns, highlighting that the representation issue for object detection is not limited to idealized settings but may also affect genome-derived data.

Importantly, this limitation is not unique to object detection. Even in the simpler task of classification, one-hot encoding also failed on ‘Concept-type’ Non-B DNA patterns, suggesting that the representation issue occurred at a more fundamental level. In this study, we approached DNA sequence analysis from a computer vision perspective, transforming sequences into image-like representations to facilitate object detection. Alternatively, many researchers model DNA sequences as language [24, 25], and an exciting field is developing to leverage natural language models such as BERT or GPT for genomic data. Pre-trained language models excel at capturing long-range dependencies, which have great potential to solve problems beyond local patterns that are common in genomics [26]. However, the classification model trained with embeddings from the pretrained language model, DNABERT-2 [22], while performing well on Content-type Non-B DNA patterns, also failed to capture the structural patterns of most Concept-type patterns. Our findings suggest that neither end-to-end training nor pretrained language models alone is sufficient to resolve the representation issues that extend beyond object detection into classification problems.

By introducing a novel dot matrix representation tailored to the structural features of Non-B DNA, DNA-DETR models captured the structural patterns of Concept-type elements. The performance gain from integrating dot matrix representation cannot be explained solely by increased input dimensionality, as different dot matrix variants contribute to distinct types of Non-B patterns they are designed for (Supplementary Fig. S1), highlighting the importance of representation design. However, a key limitation of the proposed dot matrix representation is its quadratic computational cost, which restricts its application to relatively short sequences. Unlike images, DNA sequences cannot simply be resized without altering biological signals. To address this, we evaluated downscaling via max-pooling. While training directly on reduced-resolution representations (e.g. R-loop: 250250) resulted in a marginal performance decrease (AP = 0.718 versus 0.774), applying downscaling solely at inference time significantly impaired detection (AP = 0.203). The testing demonstrates that the representation can be adapted to longer sequences with reasonable trade-offs, provided that the models are specifically trained on the downscaled inputs. For longer genomic elements, alternative approaches such as sliding-window schemes, sparse representations, or architectures designed for long-range dependencies (e.g. sparse attention [27] and dilated convolutions [28]) may be more suitable.

Taken together, the present study highlights that the representation issue may have broad implications in genomics and may be present at a more fundamental level than object detection. Our work calls for revisiting the representation issue, as it can happen to end-to-end deep learning as well, not just to classical machine learning methods. To what extent the issue presents in genomics for deep learning models remains to be explored more broadly, as the present study is limited to DNA-DETR and represents a starting point. Future work should also focus on developing predictive criteria for selecting appropriate representations as well as extending these insights to pretrained language models. Addressing the representation issue will be critical not only for advancing object detection in genomics, but also improving the broader application of deep learning models to biological sequence analysis.

Materials and methods

Data preparation

We constructed both simulated and genome-derived datasets. The simulated dataset, containing all six classes of Non-B DNA, was generated based on the sequence composition rules defined for each element (Table 1). Each simulated sequence contained a single Non-B DNA motif embedded within random flanking sequences. Negative samples were generated by randomly sampling genomic fragments that contain no Non-B DNA motifs.

The genome-derived dataset was derived from the human reference genome (hg38, UCSC Genome Browser). Two independent prediction tools were used to identify Non-B DNA loci: QmRLFS-finder [29] for R-loop regions, and the Non-B DNA search tool from Non-B DB V2.0 [13] for G4, Z, Slipped, Triplex and Cruciform DNA sites. Both tools identify potential Non-B structure forming sequences based on simple sequence rules (Fig. 1). We used these rule-defined sequences as training data rather than experimentally validated datasets because they represent clearly defined sequence patterns without ambiguity arising from experimental variability. Therefore, this genome-derived dataset serves as a controlled benchmark for evaluating the pattern detection capability of the model, rather than for detecting biologically validated Non-B DNA structures. Negative samples were randomly extracted from hg38 and confirmed by both tools to ensure the absence of Non-B DNA motifs.

For single-class model training, sequences were 200 bp in length for all Non-B DNA types except R-loop DNA, which required 500 bp windows due to their greater average size. For multi-class model training on genome-derived data, 200 bp sequences were used for five elements of Non-B DNA (excluding R-loop DNA), and 500 bp sequences were used when including all six elements. For each element, including negatives, 10,000 training and 1000 testing sequences were prepared.

Data representation and pre-processing

We implemented three sequence representations, one-hot encoding only, dot matrix only, and a combination of both. For one-hot encoding, each DNA sequence was transformed into a binary matrix (Supplementary Fig. S5A), where each nucleotide (A, C, G, T) was represented by a unique binary vector, resulting in a 4 × N dimensional matrix for a sequence of length N.

For dot matrix representation, three variants were used (Supplementary Fig. S5B). The first was the traditional dot matrix, where a dot was placed at positions where matching nucleotides occurred between a pair of sequences. To reduce noise and highlight longer patterns, we extended this matching to 3-mers. This resulting (N-2) × (N-2) matrix was zero-padded to N × N. The second variant reversed the DNA sequence before creating the dot matrix. Specifically, a dot matrix was generated between the original and reversed sequences, and was then horizontally flipped, producing the reverse-dot matrix.

The third variant used the reversed-complement sequence, generated by complementing and then reversing the original strand. A dot matrix was generated between the original and reversed-complement sequences, and was then horizontally flipped to yield the reversed-complement dot matrix. These three matrices showed different structure patterns across Non-B DNA types (Supplementary Fig. S6), and were stacked to form a three-channel input, analogous to RGB channels in image processing.

For the combined representation, the one-hot encoding representation was considered as a fourth channel. To enhance representational strength, the original 4 × N matrix was vertically expanded to 12 × N by tripling each nucleotide row (Supplementary Fig. S7), followed by zero-padding to form an N × N matrix. Consequently, the combined representation consisted of four channels: one one-hot encoding and three dot matrix layers. This setup allowed the model to leverage both raw sequence information and higher-order pattern recognition.

Model architecture and loss function

We designed DNA-DETR to identify the locations of genomic elements within DNA sequences. The model was adapted from the Detection Transformer (DETR) [9], which employed an end-to-end Transformer-based architecture combined with a convolutional neural network (CNN) backbone with a feedforward network to predict bounding boxes and class labels. We modified the first layer of the CNN backbone (ResNet50) to accommodate variable channel numbers, enabling compatibility with three input modes: (i) one-hot encoding only, (ii) dot matrix only, and (iii) combined representation.

While standard object detection models output two-dimensional bounding boxes (center x, center y, h, w), DNA-DETR predicts one-dimensional bounding boxes (center x, object length). Model training

The hyperparameters of DNA-DETR were configured as follows. The batch size was set to 64 for 200 bp inputs and 128 for 500 bp inputs. The maximum number of predicted objects per sequence was 20 for single-class and 30 for multi-class models. The weights for the classification loss and bounding box loss were assigned to a 1:2 ratio and the no-object class weight was set to 0.05. All other hyperparameters followed the default settings from the original DETR implementation [9]. Training continued until loss convergence, as monitored through training loss curves.

Model performance evaluation

Model performance was evaluated using Average Precision (AP), the standard metric in object detection that captures the trade-off between precision and recall. AP was defined as the area under the precision-recall curve, providing a comprehensive summary of model accuracy. In this study, a prediction was considered correct if the IoU between the predicted and ground truth bounding boxes was ≥0.5, ensuring sufficient overlap between predicted and actual object locations. For multi-class tasks, mAP was computed by averaging the AP scores across all Non-B DNA classes.

To evaluate the model’s ability to distinguish between positive (sequences containing Non-B DNA elements) and negative (sequences without Non-B DNA elements) samples, we computed four standard classification metrics: Accuracy, Precision, Recall, and F1 score, defined as follows: Accuracy = (TP + TN)/(TP + TN + FP + FN); Precision = TP/(TP + FP); Recall = TP/(TP + FN); and F1 score = 2*Precision*Recall/(Precision + Recall), where TP, TN, FP, and FN refer to true positives, true negatives, false positives, and false negatives, respectively.

Sequence complexity

Sequence complexity was quantified as the ratio of observed k-mer vocabulary usage to the maximal possible vocabulary usage, with k ranging from 1 to 7. The observed vocabulary usage referred to the number of distinct k-mers present in a given sequence, while the maximal vocabulary usage corresponds to the theoretical maximum number of unique k-mers possible for a sequence of the same length. A sequence complexity score approaching one suggests a more complex sequence, while a score closer to zero indicates a simpler sequence, such as one consisting of many tandem repeats.

These tools enabled the identification of diverse elements of Non-B DNA across genomic sequences. The full implementation of DNA-DETR, including preprocessing scripts and model training and testing routines, is publicly available at https://github.com/bio-it-station/DNA-DETR.
