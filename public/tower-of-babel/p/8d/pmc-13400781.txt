Letter to the Editor. Re: “Sugarcane leaf dataset: A dataset for disease detection and classification for machine learning applications,” Data in brief 53 (2024) 110268
Authors: M. Sabrigiriraj, K. Manoharan
Published: 2026

Dear Editor,

Overview

We read with interest the article by Thite et al., “Sugarcane leaf dataset: A dataset for disease detection and classification for machine learning applications,” published in Data in Brief 53 (2024) 110268 [1]. The authors presented the Sugarcane Leaf Dataset for disease detection and classification using machine learning. The article reports that the dataset contains 6748 high-resolution sugarcane leaf images. These images are grouped into nine disease categories, one healthy leaves category, and one dried leaves category.

This is an important dataset. Sugarcane is an important crop, and leaf disease detection can help farmers and researchers. Open image datasets are also useful because they support machine learning studies, deep learning experiments, and comparison of disease classification methods.

When we tried to reuse the dataset [2], we performed a dataset audit before model development. The aim was to check whether the image dataset was suitable for fair machine learning evaluation. We checked image readability, class counts, exact duplicate images, identical pHash repeats, deep feature-based near-duplicates, and possible data leakage under random splitting.

Our audit found that all 6748 images were readable, and no corrupted images were detected. The detected class counts matched the dataset description. However, the audit also found many repeated and highly similar images. This is important because duplicate or near-duplicate images can affect machine learning benchmarking if similar images are placed in both training and testing sets.

Details

The original dataset contained 6748 readable images. We first checked exact duplicates using SHA-256 file hashing. We also checked exact pixel duplicates after loading each image as an RGB image. Both checks gave the same result. We found 1051 exact duplicate groups involving 2104 images. After keeping only one image from each exact duplicate group, 1053 repeated images were removed. After this step, 5695 images remained.

We then checked identical perceptual hash repeats using pHash. This was used only as a conservative screening method. It did not remove images directly. This check found 202 identical pHash repeat groups involving 458 images. These images may not always be byte-level duplicates, but they have the same perceptual hash and therefore need attention during dataset reuse.

Next, we checked near-duplicate images using deep visual features. We used an ImageNet-pretrained ResNet18 model to extract visual features from the exact-cleaned images. The feature vectors were normalized, and FAISS cosine-similarity search was used to find highly similar image pairs. We used a cosine similarity threshold of 0.990 for the main near-duplicate audit. This step found 1968 high-similarity image pairs and 582 near-duplicate groups involving 1929 images. We also performed a sensitivity check for the deep feature-based near-duplicate search. At a stricter threshold of 0.995, 341 near-duplicate pairs were detected. At the main threshold of 0.990, 1968 pairs were detected. At a lower threshold of 0.985, 4550 pairs were detected. This shows that the number of detected similar images increases when the threshold is relaxed. For this reason, we used 0.990 as the main threshold because it is strict and conservative.

We also checked whether repeated or highly similar images appeared across different class labels. We found 2 cross-class identical pHash rows and 7 cross-class high-similarity feature pairs at the 0.990 threshold. These cases may need manual inspection. They may be reused images, visually very similar images, or possible label-related issues. We do not claim that all these cases are wrong labels. We only state that such cases should be checked and documented.

This issue matters for machine learning evaluation. If repeated or highly similar images are present in both training and testing sets, the model may partly learn repeated image content. This can make the model performance look better than it really is. In our random split leakage check, 71 identical pHash repeat groups crossed random split boundaries. These groups involved 178 images.

We also compared model results under three evaluation settings. A normal random split gave the highest mean macro F1-score of 0.9774. A duplicate-aware group split gave a lower mean macro F1-score of 0.9645. A random split after near-duplicate removal gave a mean macro F1-score of 0.9690. The difference was not very large, but it was clear. This shows that duplicate and near-duplicate images can increase the reported performance under ordinary random splitting.

These findings do not mean that the Sugarcane Leaf Dataset is not useful. The dataset remains a valuable public resource for agricultural image analysis. The article also clearly describes the dataset as a public image dataset for disease detection and classification, with image collection, preprocessing, and class-wise organization. However, our results show that users should apply duplicate-aware checks before using this dataset for benchmarking.

Suggestions

We respectfully suggest a few improvements for future reuse of the dataset.

First, the dataset record should include a short duplicate-audit note. This note may mention that exact duplicates and near-duplicates can be present and that users should check them before model training.

Second, users should not use only ordinary random train-test splitting without duplicate checking. A duplicate-aware or group-aware split is safer. This can prevent repeated or highly similar images from appearing in both training and testing sets.

Third, near-duplicate detection should be reported in future studies using this dataset. Authors may mention the method used, such as exact hashing, pHash, or deep feature similarity. This will make model evaluation more transparent.

Fourth, cross-class repeated or highly similar images should be manually inspected. If an image or near-identical image appears under different class labels, the dataset documentation should explain whether it is a valid case or a possible label issue.

Finally, future users should report both the original dataset result and the duplicate-aware result, if possible. This will help readers understand how much the reported performance depends on repeated or highly similar image content.

In summary, our audit found that the Sugarcane Leaf Dataset contains readable and well-organized images, but it also contains a considerable number of exact duplicates and near-duplicates. The original dataset has 6748 readable images. After exact duplicate removal, 5695 images remained. After near-duplicate grouping and representative selection, 4348 images remained. Random split evaluation produced a higher macro F1-score than duplicate-aware evaluation. Therefore, we suggest that future studies using this dataset should include duplicate inspection and leakage-aware splitting. This will improve the reliability and reuse value of the dataset.

The corrected analysis notebook used for the audit is provided as supplementary material. The notebook includes the commands needed to generate the detailed file-level CSV outputs and the reproducibility ZIP.

Ethics Statement
