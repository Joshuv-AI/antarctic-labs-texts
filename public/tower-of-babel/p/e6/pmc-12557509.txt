Authors: Juan E Mora-Zarate, Claudia L Garzón-Castro, Jorge A Castellanos-Rivillas
Published: 2025

ABSTRACT
AbstractAccording to the World Health Organization, hearing disabilities are increasing globally, highlighting the need to support the deaf community. In countries such as Colombia, access to sign language education remains limited. Recent advances in Computer Vision have proven effective in promoting sign language learning through real-time interaction. In response to this need, a time-series dataset was developed to represent signs from Colombian Sign Language (CSL), including 11 colors, 33 courtesy phrases, and the numbers 1–10. This dataset served as input for the development of a technological tool aimed at supporting the teaching of CSL vocabulary. It includes both static and dynamic signs, represented as 3D coordinate data of the face, torso and hands. The dataset was built using recordings from 22 participants, each performing sign between three to five times. To increase data diversity and improve model performance, the dataset was augmented by a factor of 45. The data acquisition process involved: A user interface for recording sign language videos; post-processing (extracting coordinates via MediaPipe, and imputing missing hand data), and storing processed data in JSON files.Keywords: Colombian sign language, Pose estimation, Sign language recognition, Deafness, Computer Vision

•In Colombian Sign Language (CSL), few advances have been reported in the development of sign recognition tools [[2], [3], [4], [5]]. Sign languages consist of two main types of signs: static and dynamic. Static signs are those that do not involve movement; in CSL, there are around 30 static signs, which are work in studies like [3]. In contrast, dynamic signs involve movements of the hands, arms, and facial expressions. Various methods have been explored to capture these data, such as data gloves [4] and electromyography (EMG) [2]. However, these approaches require users to make physical contact with a device and are not capable of capturing the complete body posture or facial expressions. Therefore, this dataset, along with those presented in [5,6], provides video recordings for dynamic CSL signs and post-processed data of anatomical landmarks, enabling the extraction of features that describe hand movements, arm motions, and facial expressions.

Background

Hearing disabilities will increase to 10 % of the world’s population by the year 2050, as the World Health Organization reports [7]. In countries like Colombia, access to education for the deaf population is limited; out of a total of 75,000 institutions, only 109 can provide education to deaf individuals [8]. Therefore, developing new tools to support sign language education can help reduce this educational gap. Among the most reported developments in the literature for supporting the deaf community are translation systems [4,9], social robotics [10,11], virtual reality [[12], [13], [14]], and mobile applications [15,16].

Therefore, deep learning models have become increasingly common tools for sign language recognition, and their relevance is greater when dealing with dynamic signs, as time series classification has demonstrated promising results using recurrent neural network architectures [1,17,18]. The dataset presented here is associated with an original research article [1], which proposed using the NAO H25 V6 humanoid robot (SoftBank, Japan) to design an activity for facilitating the learning of the CSL. In that study, the robot’s features —including RGB LED control, tactile sensors, and human-like movements— were leveraged to develop an interaction where the robot does not require sound production for user engagement.

Structure of the JSON file.

As previously mentioned, within the frame number level, the coordinates extracted using the MediaPipe tool are stored. As illustrated in Fig. 2, this level contains four keys corresponding to the right hand, left hand, face, and torso. Each of these keys stores three sub-keys containing lists of coordinate values along the x, y, and z axes, respectively.

Structure for the Frame number level.

Furthermore, as shown in Fig. 2, each frame in the dataset contains three-dimensional coordinates corresponding to the positions of the face (face), torso (pose), right hand (r_hand), and left hand (l_hand). These coordinates are structured as lists of values representing the normalized positions of various anatomical landmarks along the x, y, and z axes. As shown in Fig. 3, the normalized x and y values are relative to the frames width and height, where 0 is the top left corner and 1 is the bottom right corner, on the other hand, the normalized z values will have the same normalization scale of the x values but the o will start at the wrist for the hand and the hip for the torso.

Experimental Design, Materials and Methods

The workflow for the dataset construction, as shown in Fig. 10, begins with the design and development of a Graphical User Interface (GUI). This GUI was then used to record signers performing the signs associated with the topics of cordiality, colors, and numbers. The recorded videos were processed using the MediaPipe Holistic tool to detect hand, pose, and face landmarks. However, hand landmark detections were missing in some frames; therefore, a data imputation process was applied. Subsequently, data augmentation through translation was performed on the imputed data. Finally, all the processed data was stored in a hierarchically organized JSON file.

Workflow for the dataset creation process.

User interface design

To record the videos, a GUI was designed to facilitate video capture, post-processing, labeling and data validation. The GUI was developed in Python 3.12.3 and ran on a laptop equipped with an 8th-generation Intel Core i7 processor and 16 GB of RAM. The frontend was implemented using the customtkinter 5.2.2 library, while the backend incorporated libraries such as OpenCV 4.9.0.80, TensorFlow 2.16.1, and MediaPipe 0.10.21 (see Fig. 11). The interface consists of three main modules: 1) dataset creation through video recording, 2) video post-processing using the MediaPipe tool and 3) validation of the processed data. Link to the GUI repository: https://github.com/juanesmz/SignCapture.git.

Menu window of the GUI, which allows access to the modules 1) DataSet Creation, 2) Data Postprocessing and 3) DataSet Visualization.

The first module of the GUI begins with the experiment setup (see Fig. 12), where the user must select the desired camera for recording, the sign categories to be recorded, the number of repetitions per sign, and the directory where the recordings will be stored (a directory containing only the folders created by the program). Additionally, the top-left section allows the user to choose between Spanish and English as the interface language.

In addition to navigating to the next screen of the application, this button also creates the directory structure for storing the recorded videos. A main folder is created for each participant, identified by ascending numeric labels. DataSet construction

Since the videos had an average frame count of 124 with an inter-frame time of 33 ms, we determined that the sampling interval was shorter than required. Therefore, the video lengths were normalized to a fixed count of 30 frames, corresponding to an average sampling time of 137 ms. This normalization process was performed by uniformly truncating the frames to maintain a consistent inter-frame interval across the 30 selected frames. However, the GUI works with any number of frames in the videos. With the videos normalized, we proceeded to the second module of the GUI (see Fig. 17). In this module, the user must input the path to the video files directory, the data augmentation factor, and the path where the JSON file with the DataSet will be saved.

Postprocessing window.

The postprocessing began with hand assignments to determine whether each detected hand was left or right. This was achieved by calculating the Euclidean distance between a hand's wrist keypoint (from hand detection) and the corresponding left/right wrist keypoints (from torso detection). Each hand was then assigned to the geometrically closer torso wrist.

After assigning the hands correctly, we applied data imputation to fill gaps in hand detections, the technique implied a traditional forward fill [20] and a translation for the wrist shift comprehension due to time. Thereby, we start with missing hands detection (Fig. 18A). Next, the hand position from the preceding frame was imputed onto the current frame (Fig. 18B). Finally, the imputed hand was adjusted to match the current wrist position, compensating for inter-frame movement of the wrist (Fig. 18C).

Data imputation technique for missing hand. A) Missing hand identification. B) Impute the previous hand detection on the current frame. C) Translate the imputed hand to the torso wrist detection.

Finally, to prevent the user’s horizontal position from limiting dataset diversity, we applied a data augmentation process. This involved horizontally translating the data (See Fig. 19) by an augmentation factor of x45. To determine the translation distance, we ensured that the shifted data—both left and right—remained within the frame boundaries.

Translation as data augmentation technique.

Visual data validation

Finally, for dataset validation, we used the third module of the GUI. To utilize this module, the dataset must be saved in the GUI project’s assets folder as datos.json. As shown in Fig. 20, this section allows users to playback any post-processed data from the generated dataset, providing a graphical representation of the results.

Limitations

During video recording, not all users began performing the sign exactly when the GUI's countdown ended. As a result, the temporal alignment of data across users and signs is inconsistent. Additionally, the data augmentation process only incorporated horizontal translations, as vertical translations would risk pushing data points outside the frame boundaries. Furthermore, when MediaPipe fails to detect a hand in both the current and previous frames, no imputation is performed, and the only available hand information comes from the MediaPipe pose detection tool.

Looking ahead, this work aims to increase the number of signers per sign and expand the range of sign categories included in the dataset. Moreover, we are developing new methods for processing landmarks, as certain signs exhibit spatio-temporal similarities that make it challenging for prediction models to achieve accurate classifications.
