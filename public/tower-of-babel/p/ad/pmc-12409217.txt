Software Article: A generalized cascaded linear system model implementation for x‐ray detectors
Authors: Gustavo Pacheco, Juan J Pautasso, Koen Michielsen, Ioannis Sechopoulos
Published: 2025

ABSTRACT
AbstractPurposeCascaded linear models are widely used for the development and optimization of x‐ray imaging systems, yet no publicly available Python implementation currently exists. We introduce CASYMIR, a flexible and open‐source Python package capable of modeling direct and indirect‐conversion x‐ray imaging detectors under various acquisition conditions.MethodsWe employed a modular software design with generalized frequency‐domain expressions for each process in the detection chain, which can be implemented as serial or parallel blocks. The gain factors and other parameters are derived from the detector's characteristics, system geometry, and incident x‐ray spectra, all of which can be specified by the user. The signal reaching the detector is propagated throughout the detection stages by applying these process blocks, enabling the computation of the Modulation Transfer Function (MTF) and Noise Power Spectrum (NPS) at any stage of the model.ValidationOur implementation was experimentally validated using two commercial x‐ray detectors: a flat‐panel a‐Se detector for digital mammography and digital breast tomosynthesis, and a flat‐panel scintillator (CsI) detector for dedicated breast CT. The modeled MTF had root‐mean‐square (RMS) percent errors below 6% for the a‐Se detector, while the normalized RMS error for the NNPS was below 3%. For the CsI detector, the RMS percent error in the MTF was 5.4%, and the normalized RMS error for the NNPS was 5.8%.Usage notesThe CASYMIR Python package can be downloaded from https://github.com/radboud‐axti/casymir_public, and it includes a standalone executable script suitable for modeling common commercial systems, along with an extensive README file and example files.Potential applicationsCASYMIR is available as an open‐source Python package under the MIT license. Given its modular and flexible structure, it can be easily modified and integrated into other simulation/virtual clinical trial pipelines where information about the detector's spatial resolution and noise performance is needed. The standalone version of CASYMIR may be particularly useful for running batch simulations with varying acquisition and system parameters, making it ideal for optimizing system design and acquisition techniques. Furthermore, given the package's modular structure, new processes can be implemented to simulate other detector and system designs.Keywords: flat‐panel detector, image quality, parallel cascaded models, X‐ray detectors

INTRODUCTION

Linear systems theory has proven essential for the development and optimization of x‐ray imaging systems, since it can be used to model different components within the imaging chain, including detectors. 1 By representing the detector as a cascade of linear processes, we can model its signal and noise propagation characteristics using Fourier‐domain metrics such as the Modulation Transfer Function (MTF) and Normalized Noise Power Spectrum (NNPS).

Despite the widespread use of cascaded linear models, few generalized, ready‐to‐use implementations have been published. A generalized MATLAB implementation has been described in the literature, 2 , 3 with the corresponding code available upon request. However, to the best of our knowledge, there is currently no Python‐based tool that provides a modular and flexible framework for modeling different types of detectors and imaging systems. Python is open‐source and freely available, thus making it a more accessible option.

To address this, we developed CASYMIR, an open‐source Python package designed to model direct and indirect‐conversion x‐ray imaging detectors under various acquisition conditions. CASYMIR uses a modular design with generalized frequency‐domain expressions for each process, which can be implemented serially or in parallel. Users can customize the gain factors and other parameters based on the detector's characteristics, system geometry, and incident x‐ray spectra. We validated CASYMIR experimentally using two commercial x‐ray detectors: a flat‐panel amorphous selenium (a‐Se) direct conversion detector for digital mammography (DM) and digital breast tomosynthesis (DBT), and a flat‐panel cesium iodide (CsI) indirect conversion detector for dedicated breast CT (bCT).

This software article introduces CASYMIR, outlining its theoretical framework and structure, and demonstrating its use in modeling a commercial system. The CASYMIR package is available for download at https://github.com/radboud‐axti/casymir_public, and includes a standalone executable script suitable for modeling the spatial resolution and noise characteristics of common commercial systems.

METHODS

In our previous work, 4 we developed and validated a parallel‐cascaded model for a bCT system featuring a CsI scintillator detector. This model was implemented through a series of Python scripts, and it was used to optimize the parameters for contrast‐enhanced bCT acquisitions. CASYMIR builds on this foundation, enhancing flexibility and user‐friendliness by incorporating additional documentation and adopting an object‐oriented approach. Furthermore, we expanded the functionality to handle direct‐conversion detectors and model arbitrary parallel cascades. In Sections 2.1 and 2.2 we explain the theoretical framework used in the model. Details about the implementation and validation are found in Sections 2.3 and 2.4, respectively.

Cascaded system models

Cascaded linear system models represent the stages of image formation as a sequence of elementary processes. 1 , 5 , 6 , 7 , 8 , 9 These models describe the propagation of the following quantities through the image formation chain: the mean number of quanta per unit area, S¯; the Fourier transform of the spatial distribution of quanta, S(f); and the Wiener spectrum, W(f), also referred to as the Noise Power Spectrum (NPS). The physical interpretation of these quantities depends on the stage of the model. In the initial stages, S¯ and S(f) describe distributions of quanta per unit area (mm−2), while W(f) represents noise power per unit area. After integration by the detector elements, S¯ and S(f) become unitless signal magnitudes, and W(f) represents noise power per pixel, with units of mm2.

The validity of this framework is based on several assumptions, formalized in previous works. 1 , 2 , 5 , 6 , 7 For completeness, we summarize the key assumptions here:

Linearity: Both the system and the individual processes are linear.

Independent interactions: Each quantum interacts with the system independently of others.

Wide‐sense stationarity or cyclostationarity: Processes are assumed to be wide‐sense stationary prior to sampling, and wide‐sense cyclostationary after sampling. This assumption ensures that noise statistics can be modeled in the frequency domain via the Wiener spectrum. 10

Parallel cascades

While the elementary processes can effectively model simple systems consisting of single cascades, more complex processes require a different treatment. Parallel cascades were introduced 2 , 6 , 7 to model noise transfer when two or more processes contribute to the image formation, as is the case with characteristic x‐ray emission. These parallel cascades introduce additional statistical dependencies between branching pathways and require the computation of cross‐spectral terms.

The formalism implemented in this work follows from the work of Yao and Cunningham, 7 which established the framework for modeling noise transfer in imaging systems with multiple interacting pathways. In such systems, quanta undergo branching processes, leading to multiple parallel signal pathways that contribute to the final image formation.

Each pathway results in a signal contribution, and the total output signal is obtained by summing the contributions of all paths. Using this theoretical framework, CASYMIR provides a structured, modular implementation for modeling x‐ray detectors. The following sections outline its architecture and components.

The CASYMIR package structure

CASYMIR is a Python package developed to model direct‐ and indirect‐conversion x‐ray imaging detectors using linear systems theory. Its modular architecture allows users to customize the package for modeling current x‐ray imaging systems, while also enabling extensions to accommodate future detectors that may involve additional or differently ordered processes. CASYMIR relies on standard libraries such as NumPy, 18 SciPy, 19 and PyYAML, as well as SpekPy 20 and XrayDB 21 for handling x‐ray spectrum simulations.

CASYMIR was written following an object‐oriented programming approach, using classes and methods as building blocks. The overall structure of the CASYMIR package is illustrated in Figure 1, showing the modules, classes, and data folders. Additionally, the auxiliary files fk_general and tk_general contain functions used for calculating the probability of K‐fluorescence reabsorption and the spread function for remotely absorbed K‐fluorescence photons, respectively. CASYMIR core classes

The ‘casymir’ module defines CASYMIR's five classes: Detector, Tube, Spectrum, Signal, and System.

The Signal class is central to the CASYMIR package, encapsulating the linear systems theory used to model signal propagation through the x‐ray detection process. It contains attributes for storing the frequency vector, average number of quanta S¯, signal magnitude S(f), and Wiener spectrum W(f) at each stage. The elementary gain and blurring processes are implemented as methods of this class (see Tables 1 and 2).

The processes module

CASYMIR includes a collection of predefined process blocks that represent common stages in the x‐ray detection chain. These blocks implement elementary gain and blurring operations and are designed to operate sequentially or in parallel on Signal objects. The modular structure allows users to assemble customized cascaded models representing both direct and indirect‐conversion detectors. Key processes include quantum selection, energy conversion, charge trapping, optical blurring, pixel integration, and noise aliasing. Each process block computes the corresponding gain factors and transfer functions based on user‐defined detector and system parameters. A detailed list of the implemented processes, their equations, and assumptions is available in Appendix A.

The parallel module

This module defines the object classes and functions used to implement the parallel path formalism described in Section 2.2. Parallel cascades are constructed using Path and Node objects: Path objects define a sequence of processes, while Node objects represent branching points connecting multiple Paths and other Nodes. Once the architecture of the branching cascade has been defined, the apply_parallel_process function is used to generate the combined Signal object. This function starts at the summation point and recursively traverses the defined paths, applying their processes and weighting their contributions according to the assigned probabilities. The mean number of quanta, signal magnitude, and Wiener spectrum are calculated using Equations (1), (2), (3). Cross‐spectral terms are computed pairwise for all path combinations according to Equations 5 and 6, based on whether the shared parent node is a Bernoulli split or a quantum fork. This formulation supports an arbitrary number of parallel branches, including nested paths. Further implementation details and examples are available in the CASYMIR documentation on GitHub.

CASYMIR standalone

The CASYMIR package includes a standalone script designed for users who wish to change parameters without modifying the package's structure or implementation of the processes. This script provides pre‐defined blocks to model common commercial system and detector designs, such as the DM/DBT and bCT systems used for validation.

The standalone script can be executed from the command line, using a system YAML file (see Appendix B) and acquisition parameters (tube voltage, time‐current product) as inputs. Detailed information about the required and optional arguments can be found in the package's README file.

When run in standalone mode, CASYMIR generates a CSV file containing the frequency vector (up to the detector's Nyquist frequency), the MTF, and the NNPS. It also provides the option to generate fits to the MTF and NNPS. This script facilitates automated testing of various system and acquisition parameters, allowing users to create batches of system files, run CASYMIR, and obtain the corresponding image quality metrics.

DISCUSSION

While CASYMIR provides a flexible framework for modeling x‐ray detector systems, certain limitations and simplifications in the current implementation are worth noting. These limitations primarily stem from the assumptions made in the underlying theoretical framework and the level of complexity incorporated into the provided process blocks.

The current implementation of CASYMIR incorporates non‐Poisson variance in x‐ray conversion by including a Poisson excess term derived from the energy‐dependent Swank factor 8 , 22 , 23 (see Appendix A). However, other sources of gain variability, such as Fano noise 24 , 25 or photoconductor discharge, 26 are not explicitly modeled. Gain‐related quantities (such as quantum efficiency, conversion gain, and Poisson excess) are computed using spectrum‐weighted averages over the incident spectrum. However, CASYMIR does not propagate signal and noise quantities on a per‐energy‐bin basis. While some of the conversion noise variance is captured through the parallel pathway modeling of K‐fluorescence 27 , 28 and the Poisson excess terms, 6 , 13 , 15 , 27 input‐labeled formulations 2 , 29 are not included.

Additionally, CASYMIR does not account for noise variance due to depth‐dependent effects, such as the Lubberts effect 30 or depth‐dependent variations in optical gain (optical Swank noise 22 , 31 ). The Lubberts effect describes random variations in light transport efficiency depending on the x‐ray interaction depth within a scintillator. Optical Swank noise arises from fluctuations in the number of detected optical photons per absorbed x ray due to depth‐dependent variations in light collection efficiency. While some models neglect these effects, 4 , 15 , 16 , 32 , 33 they may be significant in certain applications.

CASYMIR approximates the detector's absorption coefficient as the total attenuation coefficient minus the coherent scatter contribution. This approach generally performs well for detectors with high quantum efficiency, but it introduces larger discrepancies in systems with lower absorption efficiency, particularly at higher energies. XrayDB was chosen because it is available via the Python Package Index (PyPI), ensuring easy installation and reducing the need for external software or data tables. A sensitivity analysis, provided in the Supplemental Material, compares this approximation to the total energy absorption coefficient. The results show that, while the approximation introduces moderate discrepancies in quantum efficiency, its impact on the NNPS is reduced as it propagates through the model. If more accurate values are needed, users can override the built‐in quantum efficiency calculation by supplying externally computed gain factors and attenuation coefficients.

Beyond these physical considerations, alternative model architectures are not explicitly incorporated. For instance, the detector model proposed by Kim 34 includes an additional pathway that accounts for the conversion of absorbed energy within a photodiode from x rays transmitted through a scintillator. While this specific architecture is not provided in this version of CASYMIR, the framework supports its implementation by allowing users to define custom parallel cascades.

The current implementation does not model temporal effects such as detector lag and ghosting, 35 , 36 which can affect signal accumulation and noise propagation over multiple projections. Additionally, more advanced detector technologies such as photon‐counting detectors, which involve processes like adaptive binning, are not yet included in CASYMIR.

Despite these limitations, most missing effects can be incorporated by modifying existing process blocks or defining new ones. Future versions of CASYMIR may expand its capabilities to include additional effects and processes. In the meantime, users are encouraged to modify and extend the package according to their specific needs.

CONCLUSIONS

We present a generalized cascaded linear system model for x‐ray detectors, capable of modeling both direct and indirect‐conversion detectors under various acquisition conditions. Our implementation, written as a Python package, can be readily used and expanded by others. Because of the modular, generalized approach, other processes relevant for novel detector designs can be implemented. Experimental validation using commercial x‐ray detectors showed close agreement between modeled and measured MTF and NNPS for both a‐Se and CsI flat‐panel detectors.
