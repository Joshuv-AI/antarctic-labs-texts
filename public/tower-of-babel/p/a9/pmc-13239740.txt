OpenPMX Software for Nonlinear Mixed‐Effect Models in Pharmacometrics: Precision Compared With NONMEM First‐Order Conditional Estimation
Authors: Douglas J. Eleveld, Jeroen V. Koomen, Jasper Stevens, Pieter J. Colin, Michel M. R. F. Struys
Published: 2026

ABSTRACT
ABSTRACTMixed effects models are a backbone of pharmacometrics, and NONMEM software, with the first‐order conditional method with interaction having become the de facto industry standard for model estimation. Documentation exists for the general mathematical methodology for estimation, but many technical and implementation details are lacking. OpenPMX aims to enable nonlinear mixed‐effects modeling and estimation in a transparent and efficient manner, with open source licensing allowing for broad application and development. Model parameter estimation bias and root mean squared error (RMSE) obtained using OpenPMX were compared to that using NONMEM for five population models and datasets with varying degrees of complexity. For each model and dataset, repeated simulation and estimation were performed, and the per‐dataset difference in precision for parameter estimates was calculated for OpenPMX versus NONMEM. We found that the bias and RMSE of OpenPMX are comparable to the industry standard NONMEM, and in some cases slightly better. The project has low complexity, few dependencies, and is open source, with all technical details open for inspection, auditing, and scientific collaboration.

Introduction

Mixed‐effects models are a backbone of pharmacometrics in industry and academia. They are essential for estimating predictive pharmacokinetic (PK) and pharmacodynamic (PD) models, guidance in dose finding, hypothesis testing, and gaining insights into drug mechanisms. Development of these models requires the collection of relevant data and the proposal of an a priori model structure, which is then fitted to the data. Different mechanistic theories and their representative model structures can be explored to extend or refine the model to quantify evidence for the theories. Calculating a model fit to data is a critical part of pharmacometrics and requires correct statistical methods and is often computationally intensive. Specialized software has been developed to help researchers perform model estimation and organize the results.

NONMEM software was developed at UCSF in the late 1970s and became the de facto industry standard in pharmacometrics, with the first‐order conditional estimation with interaction (FOCE‐I) method reaching very wide application. The rights to the NONMEM source code were obtained by ICON PLC as of NONMEM VI and were available to read in unencrypted form by licensees. Since NONMEM 7.1, the source code has been encrypted. The investment of ICON PLC has resulted in considerable NONMEM development with many new features and algorithms, with improvements and bug fixes in newer versions.

Despite the FOCE‐I method with NONMEM being a standard in pharmacometrics, few people deeply understand its technical details, even those who work with it regularly. The NONMEM documentation is enlightening from a theoretical standpoint, as is the work of Wang [1]. However, mathematical notation is abstract and difficult to follow for most, and the NONMEM documentation is incomplete for many technical issues. Bae and Yim [2] made the calculation of the FOCE‐I objective function accessible to a wider audience by implementing it in the R language [3]. However, they did not address many practical aspects such as minimization algorithms, parameter limits, and gradient calculations. Other implementations of the FOCE‐I method have appeared; for example, the open‐source nlmixr2 [4], which is extensive and complex with portions written in R and C++. These languages are syntactically complex, making inspection and understanding of the technical details difficult. The numerous R package dependencies create a high knowledge threshold to understand, and obtaining the correct versions may be difficult to resolve.

The purpose of the OpenPMX project is to provide a focused, useful, and educational tool for mixed‐effects modeling and estimation in pharmacometrics. The language chosen was the C language, which is widely available, fast, and energy efficient [5] It is syntactically simpler than R or C++, which may ease examination and contribution by others, as well as integration into other projects. The source code is available under the GNU Public License (GPL‐3.0) and allows all implementation details to be inspected, audited, and improved. Low complexity will be assured by limiting the project scope and dependencies. Currently, the focus is to limit dependencies to gcc [6] (C compiler) and the GNU Scientific Library [7] (GSL).

The FOCE‐I Method

The equations for the FOCE‐I method are well described in Figure 1 of Bae and Yim [2], which are ultimately derived from the NONMEM Guide VII. In OpenPMX, we closely mirror the equations of Bae and Yim. where Y is directly a function of θ and η, but by virtue of the dependence of η on Ω, Y is indirectly a function of Ω. For each individual, we calculate Vk,i as the variance for each prediction and matrix Bk as the individualized precision of ηk. The matrix Bk is calculated from the matrix Jk which contains derivatives of the residuals rk,i summed with Ω−1. This represents the uncertainty of ηk as a symmetric normal distribution with Bk−1 as its variance–covariance. The equations for an individual are: Vk,i=∑j=1Nσ∂Yk,i∂εj2·σj rk,i=Yk,i−DVk,iVk,i Jk=∂rk,1∂η1…∂rk,1∂ηP⋮⋱⋮∂rk,Nobs∂η1…∂rk,Nobs∂ηP Bk=Ω−1+JkTJk Population model estimation involves an outer (stage 2) optimization of θ, σ, and Ω, to find the minimum summed OBJFN. At each OBJFNk evaluation, an inner (conditional, or stage 1) minimization of the first three terms is performed with respect to ηk at the given θ, σ, and Ω, resulting in an individualized (posthoc) ηk. At the individualized value, logBk is calculated via derivatives with respect to ηk. The inner optimizations and subsequent calculation of logBk can be computed in parallel across individuals because they only access individual data and because logΩ is constant for the inner optimization.

Differences With NONMEM

There are technical differences between the FOCE‐I implementation in OpenPMX and NONMEM. The derivatives needed for V and B at the individualized η are calculated numerically whereas NONMEM uses analytic derivatives. Similarly, in the outer (stage 2) optimization, NONMEM uses algorithms that utilize derivatives whereas OpenPMX uses the derivative‐free BOBYQA algorithm [8] for both the inner and outer stages. NONMEM has the option of FOCE without interaction which calculates V at the population typical value (η=0). This is slightly more efficient because it avoids recalculation of V in the inner optimization, but the approach is problematic with the heteroscedastic error models common in pharmacometrics. Also different are the transformations for handling parameter bounds, and the encoding of Ω and σ for optimization.

If Ω has off‐diagonal elements and each element is optimized directly there is a risk that the matrix becomes indefinite during optimization, having negative eigenvalues. These do not make sense in a physical context because they correspond to negative variances. Early versions of NONMEM would terminate if Ω became non‐positive‐definite during minimization, but later versions avoid this by using a Cholesky factor. In OpenPMX, Ω is decomposed into a correlation matrix and a diagonal scaling matrix. The correlation matrix is estimated via a specialized Cholesky factor while the scaling is estimated via a log transformation. This approach ensures that the eigenvalues of Ω are always positive. It may also improve numerical stability because it often reduces the condition number of the matrix being estimated due to the removal of scale effects. Additionally, it allows variances on the diagonal of Ω to be fixed to a specific value even when off‐diagonal values are present. This is not possible with NONMEM; if off‐diagonal values are present then the block must be estimated or fixed.

Both OpenPMX and NONMEM allow parallelization on the level of an individual to speed estimation. OpenPMX can use pthreads or OpenMP, whereas NONMEM can use a file‐passing interface or MPI. This limits OpenPMX to shared‐memory, multi‐core machines, whereas NONMEM can be configured to use heterogeneous computing clusters.

The OpenPMX project source code is written primarily in the C language and using it directly requires considerable boilerplate code. A provided translation program allows a simplified interface, converting a control file containing keywords and snippets of C code into intermediate C source code, which has a similar function to the NMTRAN program in NONMEM. The source code is subsequently compiled and executed to perform the estimation or simulation. The translation program allows users to code their models with 1‐based arrays where the first element of array a is a(1). These are more widely used in pharmacometrics than the 0‐based arrays native to the C language where the first element of array a is a[0]. The intermediate C code is retained in the output which allows users proficient in C to debug their control files.

Methods

Model estimation performance of OpenPMX was compared with NONMEM (version 7.6) by generating simulated datasets from known pharmacokinetic (PK) and pharmacodynamic (PD) population models with inter‐individual (IIV) and residual variance under various experimental conditions, estimating the parameters from the data, and comparing these to the true values. The datasets were generated using NONMEM with the $SIM record. Initial parameter estimates were the same across methods and differed from the true values. For OpenPMX, the default estimation settings were used, and for NONMEM, the estimation settings were SIG = 5 MAX = 5000 METHOD = 1 INTERACT. Estimation was performed on an Intel Xeon W‐2195 CPU at 2.30 GHz with 36 cores running Ubuntu 24.04. Parallelization for NONMEM used 4 cores via a file‐passing interface (FPI) without the additional dependency of the Message‐Passing Interface (MPI) library, and for OpenPMX 4 threads were used. An additional single‐CPU comparison was performed for one analysis, both with and without an option to reduce redundant model initialization, CALLFL = 1 in NONMEM and firstonly = true in OpenPMX. Details for the scenarios can be found in the supplemental content. Full source code and scripts can be found at the OpenPMX GitHub repository [9].

We calculated the bias and relative root mean squared error (RMSE) for each method to estimate (esti) the true population parameters for the simulated dataset i. For each parameter: bias%=100·meanesti−true/true rmse%=100·meanesti−true2/true2 To compare estimation performance between the methods, we calculate the per‐dataset loss of precision when using OpenPMX versus NONMEM as follows: ∆i=esti−true/true lossi%=100·∆OpenPMX,i−∆NONMEM,i A Wilcoxon test was used to determine if loss differed from 0 (two‐sided, p‐value < 0.05). When this was the case, if the median loss was less than 0, then OpenPMX was deemed to outperform (estimate parameters to greater precision) than NONMEM, otherwise NONMEM was deemed to outperform OpenPMX.

SCHNIDER

The first analysis was based on the dataset underlying the schnider propofol PK model [10]. A three‐compartment PK model with allometric scaling was estimated from the data with NONMEM and subsequently used for simulations. Model parameters were the compartmental volumes (V1, V2, V3) and clearances (CL, Q2, and Q3) with IIV on all parameters except V3 and Q3, and proportional residual error. Details can be found in the Supplemental content. This analysis uses rich data with a relatively simple model, so good estimation performance is expected. Simulation and estimation were repeated 100 times. The above analysis was repeated using only a single CPU, with and without options to reduce redundant model initialization.

SPARSE

The second analysis was based on a model for sparsely sampled data investigated for nlmixr [11]. This used a one‐compartment model with population typical values of clearance, volumes and absorption rate of 4 L hour−1, 70 L, and 1 h−1 , respectively, with diagonal Ω with variance 0.09, and proportional residual error variance of 0.04. Single‐dose data were simulated for 120 individuals in equal dose groups of 10, 30, 60, or 120 mg. For each individual, four random time points were uniformly sampled from 0 to 24 h. Details can be found in the Supplemental content. This analysis uses sparse data, and some bias or poor RMSE may be present. Simulation and estimation were repeated 500 times.

FENTANYL

The third analysis was based on the Bae et al. [12] and the underlying data. Simulated datasets were generated using their final model structure estimated from their data. Model parameters were V1, V2, V3, CL, Q2, and Q3 with a full‐block Ω, and proportional residual error. Allometric scaling exponents for volumes and clearance parameters were also estimated. Details can be found in the Supplemental content. This analysis uses a large dataset with a complex model, since minimization of the objective function requires 30 parameters. For off‐diagonal values of Ω, ∆i was evaluated in terms of correlation. This analysis is considered numerically demanding, and the estimation accuracy will depend on the quality of the parameter encoding and optimizers for high‐dimensional problems. Simulation and estimation were repeated 100 times.

WARFARIN

The fourth analysis was derived from warfarin PK–PD data and the model structure from Holford [13]. The model has absorption and central compartments and an indirect‐response model as a third compartment, with model parameters V, CL, KA, E0, C50, and KOUT with IIV and allometric scaling on V, CL, and KA. The PK and PD observations had proportional and additive residual errors, respectively. Doses were simulated as boluses, and the model was estimated to the data with NONMEM. The resulting model was subsequently used for simulations. Details can be found in the Supplemental content. The accuracy of the results will depend on the quality of the differential equation solvers used. For OpenPMX, this was the default Runge–Kutta Prince–Dormand method available in GSL, and for NONMEM it was ADVAN13, both used a tolerance of 1e‐9. Simulation and estimation were repeated 100 times.

DATASIM

The fifth analysis was based on a previously performed blind comparison of model estimation software [14]. In that study, investigators performed 100 population simulations of a one‐compartment model with absorption, with model parameters V, KA and KA–KE, a full‐block Ω, and log‐normal residual error. The simulated datasets were sent to participants with some suggestions about initial model parameters. Participants were blinded to the true model and performed model estimation using different methods and software packages and returned the results to the investigators, who evaluated bias and RMSE and presented the results. For our analysis, blinding was not possible. This analysis is known to be challenging, and considerable bias or poor RMSE is expected for some parameters.

We compare OpenPMX and NONMEM for each dataset in the same dataset‐wise manner as for the other analyses. For comparison with other methods considered in the previously published investigation, a dataset‐wise comparison was not possible because only summary results were available, so we calculated the same measures as in the previous investigation. These were bias and RMSE across fixed effects (θ), random effects (Ω) with off‐diagonals evaluated as correlations, the determinant=ΩestΩtrue−13 (true value = 1), and residual error (σ). Two methods from the previous investigation were removed from the group comparison based on poor results, namely SAS FO, and nmle**.

We summarize the estimation performance of OpenPMX and NONMEM with the measures from the previous investigation by constructing a score for bias and RMSE by evaluating their magnitude between the highest and lowest values across methods. bias score=100·bias−minbias/maxbias−minbias rmse score=100·rmse−minrmse/maxrmse−minrmse

where minbias and maxbias are the minimum and maximum bias magnitude across all methods tested, with corresponding values for RMSE. A score of 0 indicates that the method performs the best of all methods, whereas, a score of 100 indicates the worst. For an overall score, we report the average across the parameters evaluated.

Discussion

OpenPMX is an open‐source tool for mixed‐effects modeling in pharmacometrics, including the FOCE‐I algorithm for model estimation. We evaluated its estimation performance on diverse datasets, and OpenPMX was very similar to NONMEM or slightly better. The similarity is not unexpected, given that both implement the FOCE‐I method. The differences likely result from analytic vs. numeric gradient calculations, different internal transformations for bounded parameters, and different encoding of inter‐ and intra‐individual variability (Ω and σ) for the optimizer.

For the schnider analysis, good predictive performance was expected because of the rich data and comparatively simple model structure, and this was observed, with OpenPMX and NONMEM performing nearly identically. For the sparse analysis, poorer bias and RMSE were expected and observed, and OpenPMX still performed similarly to NONMEM. The Fentanyl analysis represents a challenging optimization of 30 parameters, but OpenPMX still performed very similarly to NONMEM or outperformed it slightly. This suggests that the derivative‐free BOBYQA optimization algorithm performs well for high‐dimensional problems. The warfarin analysis demonstrates similar estimation performance for OpenPMX and NONMEM for models expressed as differential equations, suggesting that the default differential equation solver is of good quality.

The datasim analysis allows comparison of OpenPMX to other software and methods, including “exact methods” and older NONMEM versions, for a collection of datasets that are known to be difficult to estimate. It could be argued that this analysis is not fair because the OpenPMX analysis was not blinded to the true model, as the investigators were for the other methods. At the same time, no specialized estimation settings were used. Given the ranking of OpenPMX among the other methods, the original conclusions of the previous analysis would seem to still hold: that newer “exact methods” generally outperform first‐order conditional methods. Our analysis confirms that NONMEM 7.6 performed similarly to the NM V and NM VI versions previously analyzed. We did not attempt to confirm the performance of any of the “exact methods”, even those available in NONMEM.

Estimation Speed

OpenPMX showed faster estimation times compared to NONMEM under the conditions tested; however, a full comparison of estimation speed is complex and multifactorial. NONMEM can use MPI [15], which increases estimation speed at the cost of introducing a dependency, which is why we did not consider MPI here. Exact computation times will differ depending on other computational loads being performed. For analyses requiring limited computation, such as datasim and sparse, runtimes can be dominated by compilation, making the comparison not very meaningful. The Fentanyl analysis requires greater computation, and the differences were relatively smaller. For the current investigation, we should not make conclusions other than that estimation speed is comparable between OpenPMX and NONMEM.

Software Features

The OpenPMX translation program allows model estimation via control and data files in a manner similar to what NONMEM users are accustomed to. Record names are different, and the equations are C language code as opposed to FORTRAN‐like code, but the structure of the control file will likely be recognizable to NONMEM users. For example, for the datasim analysis, the control file for the first run was:$DATA("sim.1.txt")$ADVAN(pred)$IMODEL(V, KA, KE) V = THETA(1) * exp(ETA(1)); KE = THETA(2) * exp(ETA(2)); KA = KE + THETA(3) * exp(ETA(3));$PREDICT() const double dose = 100.; const double t = TIME; const double CP = (dose*KA)/(V*(KA-KE))*(exp(-KE*t)-exp(-KA*t))*100.; Y = log(CP) + ERR(1);$THETA { 5, 30, 60, ESTIMATE }, { 0.01, 0.3, 2, ESTIMATE }, { 0.01, 0.5, 2, ESTIMATE },$OMEGABLOCK(1, 0.001, 1, 0.001, 0.001, 1)$SIGMA(1)$MAIN estimate();

When the model is defined as differential equations then these are also given in the control file in a manner likely recognizable for NONMEM users. For example the relevant records for the warfarin analysis are:$ADVAN(diffeqn_libgsl) .nstate = 3, .args.diffeqn.abstol = 1e-9, .args.diffeqn.reltol = 1e-9,$DIFFEQN DADT(1) = -A(1)*KA; DADT(2) = A(1)*KA - A(2)*(CL/V); double dcp = A(2)/V; double deff = dcp/(C50+dcp); double pd = 1 - EMAX*deff; DADT(3) = E0*KOUT*pd - KOUT*A(3);

The models tested in this investigation use closed‐form prediction, two‐ and three‐compartment models, and models expressed as differential equations. The OpenPMX project code includes analytic solutions for other one‐, two‐, and three‐compartment models [16] as well. Advanced model structures such as inter‐occasion variability, time‐varying covariates, and complex dosing regimens are supported in manners that are broadly similar to NONMEM. These will be the subject of future documentation and tutorials.

The scope of the OpenPMX project is intentionally focused on estimation and simulation of models in pharmacometrics, applying the well‐known Do one thing and do it well philosophy. Control files, data input and tables are done via text files, allowing for considerable flexibility and ease of integration into other tools. Features such as graphical user interfaces, data management, visualization, and archiving are left for more specialized tools.

Open‐source software is particularly beneficial to users in low‐ and middle‐income countries, who do not have the resources to acquire expensive proprietary software. It also allows all users to benefit from source code inspection and auditing, which is not possible with proprietary software due to commercial interests. Verification of a particular software installation can be challenging when there are complex dependencies because the availability and support for software versions of the dependencies can change over time, causing discrepancies between users and developers. OpenPMX requires few dependencies and also provides scripts that can verify an installation by comparing numerical results from example problems to developer‐computed results.

Development

The OpenPMX project is still in development. The source code is available on the OpenPMX GitHub repository [9] under a GPL 3.0 license. Current development is on Ubuntu Linux, but it compiles and runs on Windows using MSYS2 [17] software and WSL 2 (Windows Subsystem for Linux). Given the limited software dependencies, it is expected to be portable to other platforms. A free‐to‐use installation with a web interface is accessible at OpenPMX online (https://openpmx.com) [18]. This allows OpenPMX to be tested without requiring installation, and users can explore some examples, estimate their own models and data, and download the results. Currently, the computing power at the website is shared across all online users and is quite limited, but this may change in the future.

Features still in development are: (1) improved detection of coding errors in control and data files, (2) additional model diagnostics such as normalized prediction error [19], (3) generation of parameter uncertainty measures such as standard errors and likelihood profiles, (4) handling of quantification limits for observations, and (5) handling of discrete observations.

The OpenPMX project is an open‐source implementation of mixed‐effects models in pharmacometrics, including the FOCE‐I algorithm for model estimation. Precision and accuracy are comparable to the industry standard NONMEM, and are in some cases slightly better. The project has low complexity, few dependencies, and is open source with all technical details open for inspection, auditing, and scientific collaboration.
