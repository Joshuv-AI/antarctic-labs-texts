Symmetric bug prediction in software requirement by machine learning algorithms
Authors: Khalil al-Sulbi, Abdulaziz Attaallah
Published: 2025

ABSTRACT
In the software development, high impact on diverse industries are expanding at a fast pace. Early defect fixation and adjustment according to needs are essential to increase the performance, accuracy, durability and reliability of the software. Machine Learning (ML) approaches have used to analyze the Software Requirement (SR) in software development offer a great way to accelerate symmetric development and defect correction, especially because software failures are unpredictable. This research utilizes classification and regression-based models like Random Forest (RF), Artificial Neural Network (ANN), and Adaptive Moment Estimation (AME) to forecast bug resolving times from applicable asymmetric data attributes. ML models are used to predict defect resolution and feature completion time. The data takes into consideration several stages including issue detection, testing, and validation. The outcome of ML models, K-Nearest Neighbors (KNN) algorithm has an accuracy of 66% but the proposed approach of RF, ANN, and ADE illustrates an astonishing 98% accuracy. The dataset with symmetric attributes has trends and strong correlations. The proposed model result is better than other available software failure time prediction in terms of precision and accuracy, providing a sound to defect solution and prediction in SR.Supplementary InformationThe online version contains supplementary material available at 10.1038/s41598-025-22193-x.

Symmetric bug prediction is a novel approach that extends beyond traditional defect prediction by leveraging ML to forecast both the occurrence of software defects (bugs) and their resolution times, while also incorporating the prediction of new feature integration timelines within SR workflows. The traditional defect prediction, which primarily focuses on identifying defect-prone modules, symmetric bug prediction adopts a broader, balanced perspective. It considers both defect detection and resolution alongside feature completion, using symmetric attributes—features with consistent correlations and predictable patterns, such as Execution Time Hour, State Change, Executor, and Total Op—to model dynamic SR processes.

Principal component analysis (PCA)

PCA is a dimensionality reduction technique that transforms the original features into a smaller set of uncorrelated principal components while preserving most of the data’s variance62. Explaining the dataset distribution and PCA analysis will provide insights into the data’s structure, justify feature selection, and clarify the suitability of the chosen machine learning models (Random Forest, ANN, and KNN). The research analysis uses two datasets: a real-time JIRA dataset from a Saudi-based company and a publicly available NASA dataset. The distribution of these datasets is critical to understanding their patterns, randomness, and suitability for ML. The structured nature of the NASA dataset makes it more suitable for ML, as it exhibits less randomness and stronger feature-target relationships.

PCA can be applied to reduce the dimensionality of the datasets, identify key variance-contributing features, and validate the manual feature selection (Executor, Component, Bug Type, State Change, Execution Time Hour, Defects, Total Op). By transforming the original features into principal components, PCA reveals the data’s underlying structure and helps confirm whether the selected features capture most of the variance.

The features (Execution Time Hour, Total Op) have different scales; standardize the data to zero mean and unit variance to ensure fair contribution to PCA. Compute the covariance matrix to understand feature relationships. Calculate eigenvalues and eigenvectors to identify principal components (directions of maximum variance). Select the top principal components that explain a significant portion of variance (80–90%). Analyze the loadings (weights) of original features in each principal component to identify which features (State Change, Executor) contribute most to variance.

To understand the structure of the JIRA and NASA datasets, Principal Component Analysis (PCA) was applied after standardizing features to zero mean and unit variance. For the JIRA dataset, PCA revealed that variance is distributed across multiple components due to high randomness, with State Change and Execution Time Hour showing high loadings in the top components, confirming their importance. For the NASA dataset, 3–4 components explained ~90% of variance, with Defects, Total Op, and State Change as key contributors, validating the manual selection of seven features. PCA supports the dataset’s suitability for Random Forest and ANN, as selected features capture significant variance, contributing to high accuracy (98–99%).

The Gini Index (Equation 2) and Information Gain (Equation 3) guided tree splits, with a maximum of 7 features considered per node to ensure diversity in bagging (Figure 4).

KNN Hyperparameter: The K-Nearest Neighbors (KNN) model used k=5, selected via 5-fold cross-validation on the JIRA dataset to optimize performance given its high randomness (Figures 7–8). Euclidean distance was applied as the similarity metric, suitable for standardized features post-PCA (Figure 3). This yielded low accuracy (Table 7), reflecting challenges with non-linear patterns.

Feature Selection Validation: Manual selection of seven features (Executor, Component, Bug Type, State Change, Execution Time Hour, Defects, Total Op) is guided by domain expertise and PCA results (Figure 3, Table 8), capturing ~80–90% variance in NASA and ~50–60% in JIRA. A post-hoc Recursive Feature Elimination (RFE) analysis with RF on the NASA dataset confirmed ~85% overlap with manual choices, selecting Execution Time Hour, State Change, Defects, Total Op, and two additional features. Manual selection retained Executor for its SR-specific relevance, despite RFE’s omission due to its categorical nature. Future work will explore hybrid manual-automated approaches to enhance reproducibility.

The JIRA dataset’s 66% accuracy with K-Nearest Neighbors (KNN), compared to 98–99% for Random Forest (RF) and Artificial Neural Network (ANN) on the NASA dataset (Table 7), stems from its high randomness and non-linear patterns (Figures 7, 8). Features like Execution Time Hour and State Change show multimodal distributions due to diverse bug types and executor variability, challenging KNN’s similarity-based approach (Evaluation Criteria section). The NASA dataset’s structured; near-Gaussian patterns (Figure 10, Table 8) enable higher accuracy.

Discussion

Symmetric bug prediction through ML techniques utilizes two distinct datasets: a real-time JIRA dataset collected from a Saudi-based software company and a publicly available NASA dataset, both including time completion attributes. The JIRA dataset exhibits high randomness, as observed in pair plots and correlation graphs (Figures 7, 8). Features like Execution Time Hour and State Change show irregular, non-linear patterns, suggesting a skewed or multimodal distribution due to diverse bug types and executor variability. This randomness results in a maximum precision of 0.44 and an accuracy of 0.66 using the KNN model. Despite this, the dataset enables data analytics and regression tasks, supporting time-to-delivery predictions for startup companies. In contrast, the NASA dataset, processed and analyzed for ML readiness, follows structured patterns with strong correlations (Figure 10), achieving accuracies of up to 0.99 with linear regression and 0.98 with Random Forest (RF), as shown in Figure 9.

The preprocessing of the JIRA dataset addresses its high randomness, enabling the application of KNN to achieve better accuracy than expected given the irregular patterns (Figure 6). The pair plots (Figures 8, 11) reveal interrelationships among features, highlighting trends that inform feature importance. For instance, the execution time versus state change plot indicates that certain state transitions (e.g., from open to resolved) consume significant time, suggesting that companies could optimize development by focusing on these bottlenecks, potentially by hiring specialized developers. Similarly, the execution time versus executor plot shows variability in developer efficiency, indicating a need for targeted resource allocation. The second dataset’s structured nature allows RF, linear regression, and deep learning models (Artificial Neural Network, ANN, with Adaptive Moment Estimation, AME) to perform exceptionally well (Table 7). Loss and accuracy for training and validation are visualized in Figures 6 and 10 for the JIRA and NASA datasets, respectively, with the NASA dataset showing lower mean absolute error (MAE) due to its predictable patterns. The ANN, configured with 512 and 256 neurons in hidden layers (Table 3), handles the NASA dataset’s 21 initial features (reduced to 7) effectively, with 142,848 trainable parameters. The AME optimizer enhances convergence, particularly for the structured NASA dataset. The proposed method’s novelty lies in its ability to handle unpredictable client requirements and user data, which often lead to poor prediction accuracy in traditional software development. By integrating dynamic ML models, the approach adapts to these challenges, enabling task distribution across development stages based on available resources. Continuous model updates during deployment (e.g., via MLOps) ensure improvement with incoming data, enhancing defect detection and resolution time predictions. The suggested symmetric bug prediction method, while effective, faces several challenges that impact its implementation and performance:

The JIRA dataset’s irregular patterns and multimodal distributions (Figures 7, 8) limit model accuracy (66% with KNN). The unpredictability of client-driven requirements and executor variability complicates pattern recognition, requiring robust preprocessing and feature selection to mitigate noise. The NASA dataset exhibits significant class imbalance (91% non-defective, 9% defective modules, Table 8), which can bias models toward majority classes, reducing sensitivity to rare defects. Techniques like oversampling or weighted loss functions are needed but add computational overhead. The manual selection of seven key features (Executor, Component, Bug Type, State Change, Execution Time Hour, Defects, Total Op) relies on domain knowledge rather than automated methods (filter/wrapper approaches). This risks overlooking latent correlations, and the lack of a formal fitness function for feature selection (noted in Conclusions) hinders reproducibility. The ANN and RF models perform exceptionally on the structured NASA dataset (98–99% accuracy) but struggle with the JIRA dataset’s randomness. This sensitivity limits generalizability across diverse SR environments, particularly for startups with less structured data. The ANN’s high parameter count (~142,848) and training requirements (100 epochs, batch size 32) demand significant computational resources, especially for real-time applications. RF, while more efficient, scales poorly with large numbers of trees or features are potentially challenging scalability in larger datasets. The method’s reliance on specific datasets (JIRA for industry, NASA for metrics) may not fully capture the variability in global software development contexts, such as offshore projects or small startups (noted in Related Works). Privacy and data availability constraints further limit applicability. Incorporating the model into real-time SR workflows (JIRA) requires seamless ML Ops integration, which the document does not address. This poses practical challenges for continuous model updates and deployment in dynamic environments.

This study advances software requirement management by predicting defect resolution and feature completion times, integrating symmetric and asymmetric data attributes like Execution Time Hour and State Change to capture dynamic workflows, aiding startups with unpredictable needs. It tackles the JIRA dataset’s high randomness through robust preprocessing and feature selection, yielding 66% KNN accuracy—outperforming prior works on structured data. Seven SR-specific features, validated by PCA (80–90% variance), enhance relevance over generic methods. The approach enables dynamic model adaptation via JIRA integration and MLOps for real-time updates, unlike static models. Comprehensive evaluation of RF, ANN, and KNN across JIRA (66% accuracy) and NASA (98–99%) datasets, using metrics like precision, recall, F1, and MAE, underscores its versatility. The proposed method delivers enhanced accuracy of 98–99% on the NASA dataset using RF and ANN, outperforming prior works through tailored feature selection, PCA, and AME optimization, which accelerates convergence beyond traditional approaches. It exhibits robustness against noisy, real-world data like JIRA’s irregular patterns, attaining 66% accuracy with KNN—exceeding expectations for unstructured scenarios. Time efficiency shines in real-time applications, with RF training under 10 minutes and ANN inference below 1ms for small datasets, outpacing SVM-ANN hybrids. By tackling NASA’s 91% class imbalance via PCA and feature selection, it boosts recall and precision. Finally, seamless JIRA workflow integration supports real-time task distribution and estimation, bridging software requirements management gaps for startups.

Symmetric bug prediction is proposed, advances traditional defect prediction by integrating defect detection with resolution and feature completion time forecasts, tailored to software requirement management. The traditional methods focusing on identifying buggy modules using static code metrics our approach leverages features like Execution Time Hour and State Change to capture dynamic SR workflows, enabling real-time predictions (Figs. 6, 7, 8, 9, 10, 11). It emphasizes symmetric attributes—features with strong, consistent correlations reducing randomness by ensuring equitable focus on bug fixes and feature integrations, unlike traditional reliance on less correlated metrics. The traditional defect prediction targets binary outcomes (defective/non-defective), our method employs classification and regression with ML models (Random Forest, ANN, KNN). This dual modeling enhances predictive scope for both structured and unstructured data, offering a robust solution for dynamic SR contexts, surpassing the limitations of conventional approaches.

Conclusions

Identifying requirements of the software is crucial in creating quality software. The incorporation of requirements makes the reader better understand the system. Faulty specs can have a negative impact on most aspects of software development. This article seeks to discover possible issues developers might encounter in the process of RE and to make these concerns clearer for easier understanding and learning of the noted challenges. The accuracy of using the first dataset to predict bug completion time is 0.66. The accuracy for the second dataset is 0.99. Formulation of strategies to counter the aftermath of evolving needs, as well as the removing the bugs, continues to be a challenge for business. This is possible through effective management of RE and improvement of current methods. The review broad ranges of RE topics are including the inherent challenges involved. The commitment to enhance develops current strategies has been a catalyst for the establishment of the working group. The critical review of the study revealed that the requirements need to be improved in terms of quality and that the existing approaches need to be replaced with an innovative and automated approach to ensure effectiveness. This approach can have certain extent; remove the need for human intervention in the requirement process, making requirement more effective and efficient. The study uses accuracy, precision, recall, F1 score, and MAE as implicit fitness criteria to evaluate model performance, but it does not specify a formal fitness function for feature selection, relying instead on manual analysis of correlations and domain knowledge. This gap could be addressed in future work by incorporating an explicit optimization criterion to justify feature choices more robustly.

The JIRA dataset’s high randomness, characterized by irregular, non-linear patterns in features like Execution Time Hour and State Change, limits model accuracy to 66% with KNN due to challenges in capturing consistent trends. The NASA dataset’s class imbalance (91% non-defective, 9% defective modules) risks model bias toward the majority class, necessitating techniques like SMOTE and weighted loss functions, which increase computational overhead. Manual feature selection, relying on domain knowledge to reduce 21 features to 7, may overlook latent correlations and lacks a formal fitness function, reducing reproducibility. Generalizability is constrained by dataset-specific patterns, particularly for unstructured JIRA data and diverse global software development contexts. For future work, testing on larger, more diverse datasets could enhance robustness, while automated feature selection methods (filter or wrapper approaches) could improve objectivity. Exploring explainable AI techniques, such as SHAP or LIME, could enhance model interpretability, addressing the black-box nature of RF and ANN models and supporting real-world deployment in dynamic software requirement environments.
