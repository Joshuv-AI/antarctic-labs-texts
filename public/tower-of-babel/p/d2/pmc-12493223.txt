Background

K-Nearest Neighbor is a Machine Learning (ML) algorithm used primarily for classification. It is simple, yet an efficient algorithm that finds relevance in various fields, such as medical diagnosis, image classification, fraud detection, text categorization, bioinformatics, sensor networks, business intelligence, scientific simulations, and others [1,2]. Using a labelled training set, the task is to classify unlabeled queries or test data points. The input to the algorithm is also called reference points or a training dataset. Since the input consists of labelled data points, K-Nearest Neighbors (KNN) can be categorized as a supervised ML algorithm. The instances whose class or label needs to be predicted are called query points or test data sets. Class labels can be two or more, depending on the application. KNN is termed as non-parametric and lazy algorithm, non-parametric, as it does not make any assumptions about the underlying data that is being analyzed and lazy, because, unlike other ML algorithms, during the training phase, it does not build a model; rather, it stores or memorizes the input data, and only during the testing phase, it does the computations required for labelling the query points.

Though the two-step process of KNN, i.e. distance calculation and sorting, presents a challenge in terms of performance, GPU intervention can play a significant role in achieving this difficult task. Significant research has been conducted in this area, with various methods implemented to enhance the speed of KNN. However, with an exponential increase in the number of cores of GPUs, there is a need to further improve these algorithms to leverage the HPC architecture. A review of methods used for accelerating KNN algorithm, in an HPC environment, specifically using GPU, can give an insight into how KNN algorithm can be effectively used for classification tasks in various domains.

The existing literature on K-Nearest Neighbors (KNN) and its variants continues to evolve, and a comprehensive and systematic categorization of KNN algorithms has been documented across various studies [1,[3], [4], [5], [6]]. While these systematic reviews provide valuable insights into the techniques, applications, strengths and limitations of the KNN algorithm, they do not delve into acceleration techniques in detail, particularly concerning GPU implementations, nor do they include performance comparisons in terms of speedups. For example, [3] have compared the performance of only sequential versions of KNN variants specifically for disease prediction. Similarly, [4] have reviewed the challenges, impact of distance matrix and KNN variants without particularly focusing on the GPU-based KNN algorithms. Other studies like [5] have reviewed cloud-based KNN query processing, excluding the GPU-based KNN algorithms. Notably, [1,6] have conducted an exhaustive review of the KNN Joins and KNN search techniques, giving methodological overview and analytical insights into a variety of KNN algorithms. However, GPU-accelerated algorithms have been discussed in the context of the parallel and distributed section of the KNN category without devoting an exclusive section for the GPU-accelerated KNN algorithms. This review paper seeks to bridge this gap by focusing exclusively on GPU-based KNN algorithms. It provides a comprehensive analysis of the performance trends of GPU-accelerated KNN algorithms, along with effective methodologies and comparative benchmarks across various hardware configurations and datasets.

Method details

Classical KNN algorithm

The classical KNN algorithm takes as input labelled data points, which are either represented as a vector or a matrix X. Each row in a matrix represents a data point with dimensions d (d1, d2, …, dm), which are essentially the attributes or properties of that data point. Each row also has a class label, li. There could be N such rows. To test the efficacy of the algorithm in an HPC environment, the number of these rows must be large, usually in thousands or in millions. A query point is also a matrix or vector Y, where label computation has to be done for each query point yi in Y. Usually, Y would also be of the same dimension as that of input X. Although there are many variations of the KNN algorithms, the traditional or classical KNN involves the following steps:

1.Choosing the value of k: k is the value that determines the number of closest reference points to consider when labelling the test data point. It has to be chosen carefully, as different values of k can result in different labelling of query points. Choosing a small value of k can make the algorithm excessively flexible and increase the sensitivity to noise within the algorithm. Conversely, large values of k may cause the intensity of the computation to increase and may lead to underfitting [1].

2.Calculation of distance: This is the first step in the KNN algorithm. The distance between the input vector and the unlabeled query vector is calculated. Distance calculation usually involves calculating the difference between the respective dimensions of yi in Y (query vector) and xi in X (input vector). This calculation is done for a particular yi in Y (whose label must be computed), with each of the xi in X. This makes the distance calculation step a computationally intensive task. Algorithms differ on how distance is calculated between xi and yi. Euclidean, Mahalanobis, Kullback-Leibler, and Manhattan are some of the distance calculation methods used for different algorithms.

Usually, one of the sorting algorithms like quick sort, insertion sort, or Bitonic sort, is used to sort the input depending on the distance calculated in step 2. After sorting the input points in ascending order, the top k points are identified as the k nearest neighbors of the unlabeled query point.

KNN, although a simple algorithm, is demanding with respect to computational time. Several researchers have made efforts to overcome this challenge by suggesting variations to the classic KNN algorithm. Some of the popular KNN variants are summarized below:

KNN variants

A.Adaptive KNN: As proposed by [7], the algorithm gives an optimal k for each training instance in a training set. An optimal k is the minimum number of neighbors, which are nearest and a training instance must identify to obtain its accurate class label. Each training example’s ith nearest neighbors are found from the training set. The optimal k for each training set is its nearest neighbor amongst its i nearest neighbors. The rest of the algorithm follows the classical KNN, where the test dataset uses the optimal k of its nearest neighbors to determine its class label.

This approach simplifies the decision-making process but can overlook valuable information from less-represented classes. To overcome this problem [8], proposed an algorithm to utilize the information from other classes that are in the query point’s neighborhood. Using the first two majority classes, discrimination classes at different values of k are selected. The final classification can be determined by the distribution and the number of neighbors across classes for each k-value.

These variants of KNN, as proposed by researchers, strengthen KNN’s classification capabilities by providing variations of algorithm for the distance calculations and the sorting phases of KNN.

One of the factors that can be detrimental to the KNN’s performance is the higher-order dimension or the size of the training data. Computing the distance between each instance of the training set to query points can be a computationally expensive task. Also, sorting such large-dimensional data to determine the k-least distances of the training instance with the testing instance can adversely affect the performance of the algorithm. However, the distance calculation between the query and reference points is an independent operation for every instance in the reference set. This implies that these distance calculation operations can be done in parallel. Moreover, the sorting operation presents an opportunity for parallelization as well. However, using a single-core or multi-core CPU to perform these parallel operations may not significantly boost the performance of KNN algorithms for large data sets. In such a situation, to gain the maximum benefits of parallelization, High-Performance Computing (HPC) using GPUs plays a crucial role in obtaining performance gains.

High performance computing (HPC)

HPC aggregates the computing power of several processors, giving an architectural advantage over a desktop multicore computer. Applications of HPC are found in varied domains, where it is used to solve challenging problems in science, engineering, business, and medicine, thus providing a higher level of service quality in terms of latency, processing time, algorithm integration, remote access, and so on [16]. Additionally, HPC has been pivotal in advancing scientific research and technological innovations across various disciplines, including climate science, astrophysics, genomics and beyond [17]. HPC exhibits unmatched efficiency and speed in conducting large-scale data processing, simulation, and executing complex algorithms. Researchers and scientists have tried to harness this computational power of HPC and combine it with various other fields like Machine Learning (ML). ML algorithms on a single-core CPU may not be efficient for training algorithms for large-scale data. The training time for computationally intensive tasks, such as optical character recognition (OCR) and online handwriting recognition, can extend up to three weeks and may be further influenced by the specific language being processed, as reported in [18]. Multilayer Convolutional Networks, typically used for such operations, can be complex due to the convolution operation, small kernel sizes, and cache-unfriendly memory access. In applications with high computational demands, Graphics Processing Units (GPUs) play a vital role due to their outstanding ability to perform parallel processing on large datasets. The HPC community had already acknowledged the potential and advantages of employing GPUs for accelerating certain problems like the linear algebra computations [19]. This was largely due to GPUs’ proven effectiveness in scenarios where the inherent parallelism of algorithms could be harnessed to improve their efficiency. The properties of the GPU, such as accessing the memory in 2D, multiple ALUs and parallel pipelines, can play a significant role in optimizing such algorithms [20].

Graphics processing unit (GPU)

GPU devices possess a significantly higher number of processing cores than CPUs, and feature device memory that is faster than the CPU's main memory. This results in higher computing power. And therefore, GPU devices are used to process data in high-dimensional spaces. The KNN algorithm has scope for parallelization in both of its stages: distance calculation and sorting, and has thus attracted a lot of attention from researchers to rewrite it to suit the GPU architecture. In this paper, we review the work done by different authors to accelerate KNN on GPU. This review will give an insight into various parallelization techniques used for performance enhancement of KNN and speedups attained by executing them in an HPC environment. In the following section, we discuss some of the significant contributions made by various researchers to accelerate the KNN algorithms by modifying the algorithm for the GPU platform. Several modifications, either in the use of different metric to calculate the distance, variation of sorting algorithms, or use of GPU memory hierarchy, have led to a variety of GPU-accelerated versions of KNN algorithms. Many of these algorithms have been tailored for the GPU architecture, considering the GPU’s thread model and memory hierarchy. Utilizing the strengths of high-performance computing and machine learning techniques is a significant advancement in tackling some of the complex problems.

Overview of GPU-accelerated KNN algorithms

Garcia et al., [23] in their CUDA implementation of the Brute Force KNN, have compared the performance with BF-Matlab (Brute Force implemented in Matlab), BF-C (C implementation of Brute Force) and ANN C++ (Approximated nearest neighbor implemented in C++) [24] algorithms. The authors have used the Brute Force (BF) method of KNN, which is same as the classical KNN, wherein the distance between every reference point and the query point is computed. This is done for every query point, hence the name Brute Force. In their CUDA implementation of the Brute-Force method, the query points are stored in the global memory of the GPU, where coalesced-memory reading is used, whereas reference points are stored in texture memory (read-only), which uses non-coalesced reading. This is because across query points, sorting can be parallelized, but for individual query points, sorting by distance cannot be a parallel operation. Each thread will perform a quicksort for one query point. As the comparing and exchanging operations required for insertion sort are non-coalesced, GPU texture memory is used. Insertion sort is used as it provides smaller computation times than comb sort and quick sort. This algorithm, which is termed as BF-CUDA has a speedup 407x against BF-Matlab, 295x speedup against BF-C, and 148x speedup against ANN C++[24,25], for a number of reference points and query points, varying between 1200 and 38,400 and dimension varying from 8 to 96. Garcia et al. [26] have further improved their earlier algorithm by using the cuBLAS [27] library. cuBLAS is the CUDA implementation of the BLAS library, used for linear algebra operations of matrix/vector. Using the cuBLAS library, the distance calculation equation is reframed to include matrix addition and multiplication operations. In the cuBLAS implementation of KNN, which is an improvement over the earlier KNN algorithm by the author, the Euclidean distance (x, y) is rewritten using the Euclidean Norm. They achieved a speedup of 64x and 189x on synthetic data using the CUDA and cuBLAS implementations, respectively, as compared to the ANN C++ library.

In another CUDA-based KNN algorithm designed by Liang et al. [28], which they have named as CUKNN, the authors have applied optimization strategies to maximize the GPU utilization. The algorithm minimizes global memory access during the distance matrix calculation. The training data is copied between the global memory and shared memory of the Streaming Multiprocessor (SM). Training data is divided into streams to facilitate the parallelization of data loading and distance calculation. Each SM calculates the distance for different parts of the training dataset. Also, the memory coalescing feature of CUDA is utilized to attain optimization, thus leading to efficient use of bandwidth between the shared and the global memory. The algorithm then works on the principle of local and global k-nearest distances. Local ranks are generated by individual threads in blocks simultaneously. Each block will maintain a queue of ascending ranks. Finally, a single thread will find the smallest k (rank) from each block, then the next smallest, and so on, thus getting the global k nearest neighbors. Majority voting will calculate the class of unknown query points. A speedup of 15.2x is achieved against a sequential algorithm using CPU. The algorithm shows optimal performance for a data size of 524 K.

Kuang & Zhao [29] designed an algorithm that utilizes data segmentation and a parallel Radix Sort method. The algorithm used is similar to the classical KNN, the difference being that one query point at a time is selected for calculating the distance between the test and training data points. Secondly, the modification of Euclidean distance is considered, wherein the square root is not computed; only the total of the squared differences between the data points is considered, as the actual distance is not required, but only comparison needs to be done. This omitted step helps to reduce the computational complexity of the algorithm. The parallel nature of the distance computation step is leveraged here. Hence, distance computation and sorting are done on the GPU, as these are computationally demanding jobs, whereas labelling of test data is done on the CPU. In the proposed algorithm, the tiling technique of CUDA is used. The distance matrix is divided into tiles of dimensions T x T. Hence, each block of thread will contain T x T threads, which corresponds to one tile. Thus, each block computes the distance for one tile. Box 1 lists the steps of algorithm as proposed by [29].

The tile size T, was set to 16, making 256 threads per block and thus prompting optimal use of the shared memory. Also, the batch-loading strategy is used to load data from the global memory. For each step of the calculation, one tile from the reference dataset and the corresponding tile from the query dataset are loaded into the shared memory from the global memory. This leads to batch loading d/T times, where d is the data dimension. This segmentation technique makes good use of the shared memory of the GPU. Radix sort, based on CUDA, is used to sort the distance matrix. In the labelling phase, the most frequently occurring label amongst the k-least distances will be the label of the test instance. One of the disadvantages of this algorithm is that the sorting phase acts as a critical performance bottleneck. Also, distance calculation is done for one query point at a time, instead of parallelizing the operations for all the query points. The algorithm showed a speedup of 34.91x in comparison to the CPU version of the algorithm, and a speedup of 15.36x was achieved against the ANN-Brute method [24] on the adult dataset from the UCI repository.

In their paper, Arefin et al. [30] have scaled and parallelized the KNN algorithm (GPU-FS-kNN) using CUDA. They used a chunking strategy in their implementation, where the chunks of the distance matrix are computed in place of the whole distance matrix. Pearson's correlation function was used as a measure to calculate the distance matrix. The chunk size was provided as an external parameter. In this method, all the chunks in the same row belonged to one split. Once the entire set of chunks in a given split is computed, a partial KNN graph is drawn, and upon completion of distances for all the splits, the final KNN graph is drawn. This attains a chunk-level parallelism. The chunk sizes utilized were 4096, 16,384 and 32,768. An increase in the chunk size led to better GPU utilization and yielded better performance. In addition to chunking, the authors have suggested segment-level parallelism, where a segment is a combination of splits, and parallelism can be achieved by distributing the segments over multiple GPUs. They achieved a speedup of 32x with a chunk size of 32,768 as against CPU implementation.

In the accelerated KNN GPU algorithm proposed by Komarov et al. [31], the first phase is implemented as a matrix multiplication problem. The algorithm supports three methods for distance calculation, namely, Euclidean, Cosine, and Pearson, which are needed to find dot products, vector magnitudes, and vector means. In the second phase, a parallel implementation of a two-level quick-select algorithm is proposed. Parallel execution of queries takes place at a coarse level, while at a fine level, parallelism is achieved by executing each query by all the block threads or a warp of threads. Pivot-based partitioning is used to find the k nearest elements. The algorithm for the same is listed in Box 2.

Masek et al. [32] have implemented a parallel version of KNN using OpenCL on multiple GPU platform. The authors used a novel method to optimize the KNN algorithm. Firstly, the OpenCL vector format called float4 is used to store data, which processes four float values in one step, adding considerably to the speed-up. One of the most important modifications made to the algorithm is doing away with the sorting step, which is one of the bottlenecks in the execution of KNN algorithms. In order to do this, while calculating the distance itself, for each label (class), the count of the nearest neighbor is maintained. This is repeated till a total of k neighbors are reached across all the labels. The label with the highest number of neighbors is allotted to the query point. Another major highlight of the algorithm is the multi-GPU support, which was achieved using the Java library to automatically split and transfer data across multiple GPU devices. With this method, a speedup of 750x was attained against a single-threaded CPU model for 4 million elements.

Li & Amenta [33] have proposed a Brute Force algorithm that can handle large dimension data set R as well as large values of k. Authors argue that using a good set of CUDA libraries for Brute Force algorithms operations such as matrix multiplication and sorting can give a significant improvement over the naive implementations. One of the major advantages offered by the algorithm is that it can handle high values of k up to 3000. Additionally, because the brute-force implementation is used, the performance of the program is not influenced by the input data distribution. In their algorithm, as in the traditional KNN, a distance matrix is calculated, which is the squared distance between the reference matrix R and the query matrix Q, which is achieved by modifying the SGEMM Kernel available in the MAGMA library used for matrix multiplication. "Matrix Algebra on GPU and Multi-core Architectures” (MAGMA) is a library for linear algebra operations for computing on heterogeneous platforms [34]. The merge-path function of the Modern GPU library (which merges two sorted sequences in parallel) [35] is used to compute the k smallest distances for an individual query point. Tiling is used to compute the squared-distance matrix of dimension m x n. Here, the query matrix Q is of size d x m, and the reference matrix R is of dimension d x n, d being the dimension of the dataset. Each block processes one tile of the distance matrix using the shared memory and memory coalescing technique of GPU. The use of Fermi architecture allows accessing data from registers rather than shared memory. Thread-level tiling is employed to take advantage of the Fermi architecture. To select the nearest k-neighbors, truncated merge sort is used, which only considers the candidates belonging to the top k. In this type of sort, n points are divided into k chunks of the size of the shared memory, so that sorting of the shared memory elements is done in parallel. The size of the chunks was the same as that of k, but for k < 500, the chunk size was fixed at 500. Then the sorted chunks are merged, while the larger half of each pair is discarded. This process is repeated iteratively till one chunk is left containing k-nearest neighbors. As can be seen, both sorting and merging operations are carried out in parallel for each query point. The authors demonstrated that their algorithm performed best with large values of k and extensive input datasets.

Jiang & Wu [37] proposed a GPU version of the KNN algorithm, focusing on optimizing the distance calculation phase of KNN. Authors represent the training set as T and the test set as P, and calculate the Euclidean distance using matrix operations on these two matrices and obtain the distance matrix L. L is then sorted to find k minimum distances. The algorithm consists of two phases:

1.Parallelization of distance calculation: L is the matrix that contains the distance between the elements of matrices A and B, where Euclidean distance is computed using the row of A and the column of B. This is similar to matrix multiplication and hence can be computed efficiently on a GPU using the parallelization techniques such as Tiling. Using the CUDA framework, the matrices A and B are subdivided into submatrices, and a block computes the operations of these sub-matrices independently of each other.

This algorithm is ideal to run on a GPU as the array can be divided into (N/1024)* 2 (assuming 1024 threads per block). The dimension of the block is set to 32×32, where each dimension matches the warp size. Comparisons and exchanges are done by threads in each block independently for odd and even blocks, thus attaining parallelism.

It was observed that for a data size of 16,000 with dimension 20 as well as 40, a speed up of 150x was observed, whereas for a data size of 16,000 with dimension 60, a speed up of 154x was observed. Velentzas et al. [38] have implemented two in-memory GPU-based KNN algorithms. The first approach is a brute-force algorithm that effectively leverages the Thrust library [39]. Thrust is a C++ template library for CUDA that enables developers to perform GPU-accelerated operations such as sorting, scanning, transforming, and reducing data. However, in this method, sorting distances to find the nearest points can affect the overall performance of large data sets. Hence, a refinement is suggested, called T-DS, wherein the required number of reference points are searched in concentric ranges until k points are found. The speedup gain that was achieved by the algorithm is 529 times the BF-Global [26] algorithm for 750K reference points. Furthermore, the authors have refined their algorithm in [40] by using Symmetric Progression Partitioning (SPP) to avoid calculating the distance of the whole dataset. In the earlier algorithm, all the GPU threads were used to calculate the distance of one query point, whereas the SPP algorithm includes each of the GPU threads handling one query point and calculating the distance with the reference points. The KNN list contains the results for all query points. The reference dataset is sorted for partitioning for the SPP technique. The dataset is divided into partitions of equal data size (equal number of points). Searching for KNN points continues in concentric circles on either side of the query point partition. Partitions are searched till the required number of points is found. Another level of optimization is obtained when populating the distance list buffer. Before a new distance is added to the list, the newly calculated distance and the maximum distance for a query point are compared. If the newly computed distance is less than this maximum distance, the distance in the list is replaced with the new distance. Sorting phase can be eliminated with this implementation. The maximum speedup gain achieved by SPP was 8.88x compared to BF-Global, with 1 million reference points.

Barrientos et al. [41] have developed an algorithm suitable for metric, non-metric spaces as well as high-dimensional databases. They used a GPU-based algorithm for KNN queries involving the following steps:

1.Using a Pivot: Pivot is the point, based on which the elements are selected. All the elements less than the Pivot are selected for each block, and the ones more than the Pivot are discarded. Pivot was selected based on 3 approaches: 1) any random value 2) average of the first, middle and the last element 3) average of all the elements. The approach of selecting the pivot by averaging all the elements performed the best, although it increased the computational cost since it had to access each and every element. Each CUDA block has its first row filled with input data, and the next row is left empty for auxiliary memory. Each thread compares the elements with the pivot and populates the auxiliary space with elements less than the pivot. Once all the elements are compared and relevant elements are stored in auxiliary space, the array with the input becomes auxiliary space, and the process of comparing is repeated. This process continues till elements fewer than k are found.

A variety of techniques have been employed to accelerate and optimize the KNN algorithm. Table 3 summarizes these techniques and the types of applications the algorithm is suitable to apply. Most of these algorithms focus on parallelizing the distance computation loop, as it is a task that requires heavy computational resources. For this purpose, the features of CUDA, such as the global memory, shared memory, and texture memory, are utilized. For example, in the algorithm suggested by Garcia et al. [23], the query points are stored in global memory and reference points in the texture memory, to optimize the GPU version of KNN. Kuang & Zhao [29] and Jiang & Wu [37] have used the tiling technique with the shared memory, whereas Arefin et al. [30] have used the chunking method to optimize the distance calculation phase of KNN. Furthermore, Arefin et al. [30] has attained a dual level of parallelism in their algorithm at the chunk level and the segment level. Most of the algorithms have used the modified version of Euclidean distance; however, to speed up the algorithm, the square root of the difference of dimensions between the reference and query points was not computed, as for comparison, the actual distance is not required, only relative value can be used. In contrast, Gavahi et al. [2] 's KNN algorithm is based on Mahalanobis distance, whereas Komarov et al. [31] have also used Pearson’s and Cosine metric for distance calculation. Although, Barrientos et al. [41] have used pivots and heaps for finding k elements for each block of data, serial quicksort used to find the least k elements is a bottleneck in its performance for large values of k. However, they have enhanced the algorithm to utilize a multi-node and multi-GPU platform. Furthermore, Liang et al. [28] have achieved good scalability for varying dimensions of data using the streaming technique, which parallelizes the operations of data loading and distance calculation. The use of local and global ranks for determining k nearest neighbors is also a unique feature of their algorithm. Wherein, many of the algorithms handle one query point at a time for their KNN calculation, and then loop over the other query points, the algorithm suggested by Komarov et al. [31], can handle multiple queries, as many as 213 at a time. However, for the maximum utilization of the GPU, their algorithm requires that at least 128 queries be running at a time.

Although the majority of the algorithms discussed in the paper have focused on optimizing the distance calculation phase of KNN, Li & Amenta [33] have applied truncated merge sort using shared memory chunking, whereas Masek et al. [32] have suggested a novel way to totally do away with the sorting phase. In their algorithm, the distance computation and searching the k-nearest neighbor for a query point are both done in one phase. Also, it is the only algorithm reviewed in our study, implemented using OpenCL platform. All the other algorithms reviewed are implemented using CUDA, which could be attributed to CUDA’s simpler programming constructs, ease of learning, good API support, and programmers not having to worry about hardware details. However, OpenCL’s, support for multiple vendor devices adds a dimension of portability to the algorithms. Similarly, Velentzas et al. [38] too, have not used a separate sorting phase to find the k nearest elements by maintaining a list buffer and updating it in the distance calculation phase itself.

Considering the speedup attained by different algorithms (Fig. 1), for a multi-GPU platform, Barrientos et al. [41]'s algorithm have reported maximum speed-up of 1840x. The architecture used is a multi-GPU platform with 20 GPUs. Whereas for a dual-GPU platform, Masek et al. [32] have reported a maximum speedup of 750x for a data size of 4 million data points. Also, [28,2,32,33,41] and [40] have tested their algorithms for data sizes varying from thousands to millions, truly utilizing the enormous computing power of GPU's, even though many of the reference and the query points used are synthetically generated. Also, the algorithm proposed by [33] can handle values of k ranging from 500 to 3000.

A notable acceleration in processing speed is observed as the dataset size (N x D) increases (Fig. 1). This observation underscores the superior capability of GPUs in managing high-dimensional data effectively. A few exceptions to these are seen for the speedups 110x [2] and 32x [30]. In [2], the speedup decreases significantly to 110x despite the data size being approximately 10 million and dimensions reaching up to 32. One reason for this decrease could be due to the _syncthread() command, which waits till all the threads return the results. Similarly, in [30], the pre-requisite of the algorithm that the entire data has to be present in the device memory, makes the algorithm infeasible for large datasets, which leads to a speedup of 32x for a dataset size of 1.5 million. As expected, the speedup is also seen to be scaling up with an increasing number of CUDA cores (Fig. 2). Exceptionally, [23] shows a speedup of 407 with only 128 CUDA cores. This could be attributed to the effective use of the coalescing technique for global memory access.

Furthermore, as the volume and dimension of data increase, access to global memory increases. However, larger volumes of data lead to more efficient energy consumption as demonstrated by Gavahi et al. [2] and better scalability of speed-ups. Moreover, using techniques like the use of texture memory for storing reference data can significantly reduce the use of global memory for the distance computation step. Also, it can be deduced that as the number of data points and dimension increase, distance computation time increases and sorting time reduces while not significantly affecting the memory copy time, thus making GPU an ideal device for handling large datasets. The choice of sorting algorithm also affects the speedups achieved, as certain sorting algorithms perform well on specific data sizes. As in Garcia’s [23] algorithm, insertion sort performed faster than comb sort initially but for higher dimensions, comb sort indicated consistent performance. Besides the choice of data structures and algorithms these factors also play an important role in optimizing the KNN algorithm.

The use of Graphics Processing Units (GPUs) has significantly transformed machine learning (ML) by enabling rapid training and large-scale data processing. While GPUs support more complex model architectures, there are still limitations and trade-offs that affect their scalability and real-world applicability. In recent years, memory bandwidth has not scaled proportionally to the GPU performance, especially as the number of cores continues to increase and specialized processing units like Tensor Cores are introduced [43]. The processing of high-dimensional datasets is constrained by the limited on-board GPU memory, and the frequent data transfer between the host and the device diminishes the performance gains due to the resulting latency. Data movement accounts for a significant portion of dynamic energy consumption in GPUs, reaching up to 84 %, with DRAM accesses being the primary contributor [44]. Such latency bottleneck may not make the GPU-enabled applications suitable for real-time applications such as robotics, autonomous vehicles, real-time imaging etc. Utilizing non-volatile memory and implementing techniques like data encoding can help mitigate this overhead [45]. Despite these architectural innovations, GPUs still consume a considerable amount of energy (e.g., the NVIDIA A100 GPU features a 400 W TDP (Thermal Design Power), while the TDP of NVIDIA Blackwell is 1000 W)[44]. Furthermore, scaling ML applications across multi-GPU architectures present challenges such as synchronisation overhead and communication costs. Redesigning the algorithm and exploring data partitioning strategies are potential solutions that could be considered.

Conclusion

Recent advancements in Machine Learning, coupled with the rise of hardware technologies like GPUs, have created an increasing demand to adapt ML algorithms to applications using large volumes of data. This adaptation aims to take full advantage of the parallelism offered by GPU architectures. The KNN implementation of CUDA and OpenCL has resulted in significant performance improvements for large volumes of data. Furthermore, emerging technologies such as NVIDIA’s Tensor Core, hold the potential to further optimize the performance of these algorithms. Tensor Core technology is specifically engineered to enhance matrix multiplication operations. For instance, in the context of KNN, the distance calculation can be restructured into a sequence of matrix manipulation operations, thereby taking advantage of Tensor Core capabilities, particularly for large datasets. The adoption of such advanced technologies is likely to substantially augment algorithmic efficiency while simultaneously improving energy efficiency through superior resource utilization.
