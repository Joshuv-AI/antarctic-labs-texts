Topology-aware adaptive scheduling algorithm for heterogeneous AI-PC collaborative computing environments
Authors: Shijia Shao, Xinyi Ding, Biao Zhao, Peiqing Ye
Published: 2026

ABSTRACT
The proliferation of AI-enabled personal computers with heterogeneous processing units (CPU, GPU, NPU) introduces substantial complexity into resource scheduling due to dynamic neural network topologies that vary across inference phases and model architectures. This paper proposes a topology-aware adaptive scheduling algorithm that integrates real-time computational graph analysis into heterogeneous resource coordination mechanisms. The algorithm comprises three synergistic components: a lightweight runtime topology extraction module that captures evolving neural network structures, a predictive resource modeling system that forecasts device availability patterns, and an adaptive scheduling optimizer that jointly considers topology dependencies, device heterogeneity, and temporal resource fluctuations. Experimental evaluation across six representative neural architectures (ResNet-50, MobileNetV3, YOLOv8, BERT-Base, Vision Transformer, EfficientNet-B4) and three heterogeneous AI-PC platforms demonstrates substantial performance improvements: 13.5% latency reduction, 15.6% throughput increase, 30.1% NPU utilization gain, and 16.1% energy efficiency improvement compared to state-of-the-art baselines. The algorithm exhibits robust performance under dynamic workload conditions and diverse topological structures, maintaining functional operation even under resource failures and measurement uncertainties.

Introduction

The proliferation of artificial intelligence workloads has fundamentally reshaped computational paradigms, particularly in edge computing scenarios where AI-enabled personal computers now serve as critical computational nodes1. Contemporary AI-PC architectures integrate specialized neural processing units alongside traditional CPU and GPU resources, creating heterogeneous computing environments that demand sophisticated resource orchestration mechanisms2. Yet the dynamic nature of neural network topologies—varying across inference phases, model architectures, and deployment contexts—introduces substantial complexity into resource allocation decisions that existing scheduling frameworks inadequately address3.

Recent advances in collaborative computing have demonstrated promising potential for distributing AI workloads across heterogeneous device ecosystems. International efforts have primarily concentrated on static resource partitioning strategies that assume fixed computational graphs, with notable implementations in federated learning platforms and edge-cloud collaboration systems4. These approaches, however, falter when confronted with the inherent variability of modern neural architectures that exhibit topology mutations during execution, particularly in adaptive inference scenarios where network structures respond dynamically to input characteristics5. Domestic research has explored workload migration techniques for heterogeneous platforms, though predominantly within data center contexts where network stability and resource homogeneity differ markedly from distributed AI-PC environments6.

Three critical challenges persist in current resource scheduling methodologies. First, conventional schedulers treat neural networks as monolithic computational blocks, neglecting the fine-grained dependency structures within layer topologies that could inform more intelligent resource mapping decisions7. Second, existing heterogeneous computing frameworks assume relatively static device capabilities, failing to account for the temporal variations in available resources as AI-PCs simultaneously handle diverse user applications and background processes8. Third, the coordination overhead between distributed nodes often negates performance gains from workload distribution, particularly when scheduling decisions lack awareness of inter-layer communication patterns inherent to specific neural topologies9.

Addressing these limitations carries substantial practical significance. The global AI-PC market trajectory suggests exponential growth in distributed AI workload scenarios, where optimized resource utilization directly translates to energy efficiency gains and enhanced user experience responsiveness. Furthermore, enabling topology-aware scheduling unlocks new possibilities for adaptive model deployment strategies that dynamically adjust network architectures based on available computational resources rather than requiring pre-determined model compression or pruning decisions.

This work proposes an adaptive scheduling algorithm that integrates dynamic neural network topology awareness into heterogeneous AI-PC resource coordination mechanisms. Building upon established techniques in graph analysis and scheduling optimization, our primary contributions encompass three dimensions: we develop a real-time topology extraction methodology that captures evolving computational graph structures during neural network execution; we design a resource allocation optimization framework that jointly considers device heterogeneity, topology dependencies, and temporal resource fluctuations; and we implement a coordination protocol that reduces inter-node communication overhead while maintaining scheduling responsiveness10. Rather than introducing entirely new primitives, the algorithm contribution lies in its unified dual-layer adaptation mechanism—adjusting both to neural network topology variations and to dynamic resource availability across heterogeneous computing nodes—thereby achieving measurable performance gains compared to topology-agnostic scheduling approaches across diverse AI workload scenarios.

Related theory and technical foundation

Heterogeneous AI-PC collaborative computing architecture

Contemporary AI-PC platforms represent a departure from traditional computing paradigms through their integration of specialized neural processing units alongside conventional general-purpose processors. The hardware substrate typically comprises three distinct computational domains: multi-core CPUs optimized for sequential logic and control flow operations, massively parallel GPUs designed for uniform data-parallel computations, and dedicated NPUs architected specifically for matrix operations prevalent in neural network inference11. Each processing element exhibits markedly different performance characteristics—CPUs excel at branching-intensive tasks with low latency requirements, GPUs deliver superior throughput for regular arithmetic operations, while NPUs achieve remarkable energy efficiency when executing tensor contractions and convolutions that dominate deep learning workloads12.

Quantifying the computational capabilities of these heterogeneous resources demands careful consideration of workload-specific performance metrics rather than relying solely on theoretical peak performance figures. Our communication cost model assumes that the effective bandwidth between any two devices remains relatively stable over the duration of a single scheduling decision window (typically 100–500 ms). We periodically measure actual bandwidth through lightweight probe transfers executed every 5 s, and the scheduler uses the most recent measurement as the current estimate. In environments where bandwidth fluctuates significantly—for instance, under heavy network contention from concurrent applications—the model may underestimate or overestimate transfer costs. We partially mitigate this by incorporating a safety margin: the scheduler uses 85% of the measured bandwidth as the effective rate, which absorbs moderate fluctuations. Nonetheless, abrupt bandwidth drops exceeding 40% between consecutive measurements can degrade scheduling quality, a limitation we acknowledge and discuss further in Section V.

Collaborative computing across these heterogeneous units hinges on intelligent workload partitioning that balances computational distribution against communication costs. The fundamental challenge emerges from dynamic resource availability—background processes, thermal management policies, and power constraints cause instantaneous computational capacity to fluctuate significantly from nominal specifications. Additionally, neural network layer dependencies impose strict execution ordering constraints that limit parallelization opportunities. The scheduling complexity intensifies when considering that different layers within a single neural network may favor different processing units; convolutional layers naturally map to NPU architectures, whereas attention mechanisms in transformer models sometimes achieve better performance on GPU platforms due to their irregular memory access patterns15. Determining optimal workload distribution thus requires real-time awareness of both hardware states and neural topology structures.

Dynamic neural network topology structure analysis

Neural network topologies no longer conform to static computational graphs predetermined at deployment time. Modern architectures increasingly incorporate conditional execution paths, early-exit mechanisms, and input-dependent layer activations that cause the effective computational graph to vary across inference instances16. Adaptive inference frameworks exemplify this dynamism—networks may bypass intermediate layers when input complexity permits simplified processing, or conversely activate additional refinement modules for challenging samples. Such architectural flexibility fundamentally alters resource scheduling requirements compared to traditional fixed-topology networks.

Capturing inter-layer dependencies necessitates graph-theoretic modeling that explicitly represents both data flow and computational sequencing constraints. The challenge intensifies when multiple networks execute concurrently across shared heterogeneous resources, creating complex interdependencies between topology-driven demand variations and device availability patterns.

Resource scheduling theory and methods

Classical resource scheduling algorithms emerged from distributed computing and cloud infrastructure domains, where list scheduling and bin packing heuristics dominated early implementations. Earliest-deadline-first and shortest-job-first policies provided foundational approaches, yet these methods presumed homogeneous computing resources and failed to capture the complexity inherent in heterogeneous AI workloads21. Min-min and max-min heuristics later extended scheduling capabilities to heterogeneous environments by prioritizing tasks based on estimated completion times across different processing units, though their greedy nature often trapped schedulers in local optima that significantly degraded overall system throughput.

Heuristic strategies have evolved considerably to address heterogeneous computing challenges through more sophisticated decision logic. Genetic algorithms and simulated annealing techniques explore broader solution spaces by iteratively refining task-to-resource mappings, effectively balancing exploration and exploitation tradeoffs22. where S represents a scheduling solution, \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{T}_{makespan}$$\end{document} denotes total execution time, \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{E}_{energy}$$\end{document} captures energy consumption, \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{C}_{comm}$$\end{document} quantifies communication overhead, and weights \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{w}_{i}$$\end{document} encode relative priorities. Reinforcement learning has emerged as a compelling alternative that learns scheduling policies through environmental interaction rather than relying on predetermined heuristics. Deep Q-networks and policy gradient methods enable schedulers to discover complex mapping strategies that respond dynamically to observed system states23. Pareto optimization techniques identify solution sets where improving one objective necessarily degrades another, presenting decision-makers with tradeoff frontiers rather than singular “optimal” solutions25. Despite these advances, most existing approaches largely ignore neural network topology structures—they treat workloads as atomic units rather than exploiting internal computational graph properties that could inform more intelligent scheduling decisions. A notable exception is the device placement literature, where methods such as FlexFlow26 and Placeto27 do consider computational graph structure when mapping DNN operators to devices. FlexFlow explores a comprehensive parallelization search space (Sample, Operator, Attribute, and Parameter dimensions) and employs an execution simulator to predict strategy performance, yet it targets distributed training rather than heterogeneous inference scheduling on resource-constrained AI-PCs. Placeto adopts reinforcement learning with graph embeddings to learn generalizable device placement policies across computation graphs, but its focus remains on training workloads in homogeneous GPU clusters, and it does not address runtime topology changes or dynamic resource fluctuations characteristic of edge environments. Our work differs from these approaches in three respects: we handle dynamic topologies that vary during inference execution, we jointly optimize for heterogeneous device capabilities including CPUs, GPUs, and NPUs, and we incorporate runtime resource prediction to adapt scheduling decisions to fluctuating availability patterns.

Topology-aware adaptive scheduling algorithm design

Algorithm overall framework and design philosophy

Our algorithm pursues three primary objectives: minimizing total execution latency across distributed AI-PC nodes, maintaining load balance among heterogeneous computing units, and reducing inter-device communication overhead. These goals must satisfy strict constraints imposed by neural network dependency structures—layer execution must respect topological ordering encoded in the computational graph—while simultaneously adhering to device capacity limits where instantaneous resource allocation cannot exceed physical boundaries28. Energy efficiency emerges as a secondary objective, particularly relevant for battery-powered AI-PC deployments where prolonged high-intensity computation drains power reserves rapidly.

Figure 1 illustrates the algorithm’s architectural blueprint, which decomposes scheduling logic into three cooperating modules that exchange information through well-defined interfaces. This modular design enables independent refinement of each component without disrupting overall system functionality. The topology awareness module continuously monitors neural network execution state, extracting computational graph structures and identifying active execution paths as they emerge dynamically29. Unlike static profiling approaches that analyze network architecture once during initialization, our module maintains runtime awareness of topology transformations triggered by conditional execution branches or early-exit mechanisms.

Inter-module coordination proceeds through a message-passing protocol where the topology awareness module broadcasts graph updates whenever structural changes occur, triggering the decision module to recompute mappings. The resource predictor operates asynchronously, periodically publishing capacity forecasts that the scheduler incorporates into subsequent decisions32. This decoupled design reduces scheduling latency—the decision module need not block waiting for prediction updates, instead operating on most recent available forecasts. Critical to this architecture is maintaining temporal consistency: the scheduler must reference topology and resource states from aligned time windows, avoiding scenarios where it pairs outdated resource predictions with current topology snapshots. For ease of reading, the topology-aware adaptive scheduling procedure is rendered as a workflow diagram in Fig. 2 rather than a step-by-step listing. The procedure originates from interception of framework execution hooks, which build the initial topology graph G₀ from the model definition. A one-time profiling pass then populates the per-operator affinity table across every available device. Resource prediction (Eq. 9) projects forthcoming device capacities, after which the normalized Laplacian (Eq. 21) is computed and its k smallest eigenvectors feed the k-means routine that yields layer partitions. For each partition, the affinity-weighted compatibility score in Eq. 22 is evaluated against every device, and a greedy assignment subject to memory constraints (Eq. 23) gives an initial mapping. A short burst of local search (Eq. 26) refines this mapping, which is subsequently deployed for inference. A monitoring loop—activated whenever the topology change indicator (Eq. 18) crosses its threshold or resource deviation exceeds tolerance—returns the system to the prediction stage so the cycle can repeat with current information.

Dynamic topology awareness and resource demand prediction

Extracting neural network topology structures during runtime demands lightweight instrumentation that avoids introducing prohibitive overhead into the inference pipeline. We intercept framework-level execution hooks—PyTorch’s autograd engine and TensorFlow’s eager execution mode both expose callback mechanisms—to capture layer activations and data dependencies without modifying model code33. Each time the framework invokes a computational operator, our instrumentation records the operation type, input tensor shapes, and source layers that produced input data, progressively constructing the computational graph \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{G}_{t}$$\end{document} as execution unfolds. This approach naturally handles dynamic topologies since we build graph representations based on actual execution traces rather than static model definitions.

Analyzing dependency relationships within the constructed graph proceeds through topological sorting algorithms that identify permissible execution orderings while respecting data flow constraints. For each layer \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{v}_{k}$$\end{document}, we compute its dependency set:13\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:\mathcal{D}\left({v}_{k}\right)=\{{v}_{j}\in\:V\mid\:\exists\:\mathrm{p}\mathrm{a}\mathrm{t}\mathrm{h}\mathrm{f}\mathrm{r}\mathrm{o}\mathrm{m}{v}_{j}\mathrm{t}\mathrm{o}{v}_{k}\mathrm{i}\mathrm{n}{G}_{t}\}$$\end{document}

To make explicit how the affinity values reported in Table 2 are threaded through the overall scheduling pipeline, we trace the path of a single value from measurement to deployment. Each entry of Table 2 is recorded during a one-time offline profiling sweep that benchmarks every operator type across CPU, GPU, and NPU on the target platform; this sweep corresponds to the affinity table population stage referenced in the procedure of Fig. 2. Once spectral clustering yields the layer partitions {P₁, …, Pₖ} (Sect. 3.3, Eq. 21), the scheduler aggregates the per-operator affinities within each partition, weighting each contribution by the corresponding computational workload. This aggregation is what Eq. 22 computes—a workload-weighted sum that lifts operator-level priors to the partition granularity at which device assignment actually takes place. The resulting compatibility scores then enter the modified Hungarian matcher of Eq. 23, where memory capacity constraints prune infeasible mappings and the matcher commits to a partition-to-device assignment that maximises overall affinity. In short, Table 2 supplies the priors, Eq. 22 lifts them from operator to partition level, and Eq. 23 finalises the choice; the affinity table itself is recomputed only when device characteristics shift (e.g., thermal throttling or hardware reconfiguration), so the runtime cost of consulting it remains negligible.

Resource demand prediction builds upon this operator-level characterization by aggregating requirements across activated layers within the current topology. where \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{V}_{pred}$$\end{document} represents the predicted set of active layers, \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{\theta\:}_{k}$$\end{document} denotes a learned correction factor accounting for runtime variations, and \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{f}_{op}$$\end{document} computes theoretical resource consumption based on operator type and input dimensions36. Historical execution traces inform the prediction—we maintain a sliding window buffer storing past topology snapshots and corresponding resource measurements, training a lightweight regression model that learns correlations between topology features and actual resource consumption:16\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{\theta\:}_{k}={\beta\:}_{0}+\sum\:_{i=1}^{n}{\beta\:}_{i}\cdot{\phi\:}_{i}({G}_{t},{v}_{k})$$\end{document}

where \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{\phi\:}_{i}$$\end{document} extracts topology-aware features such as layer depth, fan-in degree, and path length to output layers.

We train this lightweight linear regression model by minimizing the mean squared error between predicted and observed resource consumption: \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{L}_{pred}=\:\left(\frac{1}{N}\right)\cdot\:\varSigma\:{\left({R}_{predicted}-\:{R}_{observed}\right)}^{2}$$\end{document}, where N denotes the number of collected samples in the sliding window buffer. The buffer retains the most recent 100 topology-resource measurement pairs. Model coefficients are updated every 10 inference iterations through ordinary least-squares fitting, which completes in under 0.5 ms due to the small feature dimensionality (typically 5–8 topology features per layer). During the initial warm-up phase (first 20 iterations), the model operates with default correction factors set to 1.0 until sufficient profiling data accumulates. We validated prediction accuracy across all six benchmark models: under stable load (no background processes), the predictor achieved a mean absolute percentage error (MAPE) of 6.8% for computational load forecasting and 4.2% for memory consumption prediction, with root mean squared error (RMSE) of 3.1 ms for execution time estimation. Under dynamic load with 20–60% background resource contention, MAPE increased to 12.4% for computation and 8.7% for memory, with RMSE rising to 7.8 ms, reflecting the inherent difficulty of forecasting under external interference.

Detecting topology changes necessitates comparing consecutive graph snapshots to identify structural modifications. We compute a graph edit distance metric:17\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:\varDelta\:({G}_{t},{G}_{t-1})=|{V}_{t}\Delta{V}_{t-1}|+|{E}_{t}\Delta{E}_{t-1}|$$\end{document}

where Δ denotes symmetric difference between vertex and edge sets37. When Δ exceeds a predefined threshold \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{\tau\:}_{change}$$\end{document}, the system triggers a rescheduling event since the altered topology invalidates previous resource allocation decisions. This change detection mechanism must balance sensitivity—detecting meaningful structural variations—against stability—avoiding excessive rescheduling overhead from minor fluctuations. We smooth detection by requiring sustained topology changes across multiple consecutive time steps:18\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:\mathrm{T}\mathrm{r}\mathrm{i}\mathrm{g}\mathrm{g}\mathrm{e}\mathrm{r}=\left\{\begin{array}{ccc}\mathrm{T}\mathrm{r}\mathrm{u}\mathrm{e}&\:\mathrm{i}\mathrm{f}\sum\:_{j=0}^{k-1}\mathbb{I}\left[\varDelta\:\right({G}_{t-j},{G}_{t-j-1})>{\tau\:}_{change}]\ge\:{k}_{min}\text{}\mathrm{F}\mathrm{a}\mathrm{l}\mathrm{s}\mathrm{e}&\:\mathrm{o}\mathrm{t}\mathrm{h}\mathrm{e}\mathrm{r}\mathrm{w}\mathrm{i}\mathrm{s}\mathrm{e}\end{array}\right.$$\end{document}

where \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{k}_{min}$$\end{document} specifies the minimum number of consecutive change detections required to initiate rescheduling, effectively filtering transient topology variations that would otherwise cause unnecessary scheduling disruptions.

Heterogeneous resource adaptive scheduling strategy

We cast the scheduling problem as a multi-objective optimization framework that simultaneously addresses makespan minimization, load balancing, and communication overhead reduction. The mathematical formulation expresses these competing objectives through a weighted aggregation:19\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{\mathrm{m}\mathrm{i}\mathrm{n}}_{\phi\:}F\left(\phi\:\right)={w}_{1}\cdot\frac{{T}_{makespan}\left(\phi\:\right)}{{T}_{ref}}+{w}_{2}\cdot\frac{\mathrm{L}\mathrm{I}\left(\phi\:\right)}{{\mathrm{L}\mathrm{I}}_{max}}+{w}_{3}\cdot\frac{{C}_{comm}\left(\phi\:\right)}{{C}_{ref}}$$\end{document}

where normalized terms ensure dimensional consistency, \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{T}_{ref}$$\end{document} and \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{C}_{ref}$$\end{document} denote reference values, and the load imbalance metric quantifies resource utilization variance:20\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:\mathrm{L}\mathrm{I}\left(\phi\:\right)=\sqrt[]{\frac{1}{\left|D\right|}\sum\:_{{d}_{i}\in\:D}^{}{\left({U}_{i}-\stackrel{\mathrm{-}}{U}\right)}^{2}}$$\end{document}

with \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{U}_{i}$$\end{document} representing device \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{d}_{i}$$\end{document}‘s utilization and \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:\stackrel{\mathrm{-}}{U}$$\end{document} the average utilization across all devices38. This formulation differs from conventional approaches by incorporating topology-derived constraints that enforce dependency satisfaction.

Task partitioning exploits graph structure to identify natural segmentation boundaries where inter-partition communication costs remain minimal. We employ a spectral clustering approach that treats the topology graph’s Laplacian matrix eigenstructure to reveal cohesive layer groups39. The normalized Laplacian matrix construction follows:21\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{\mathcal{L}}_{norm}=I-{D}^{-\frac{1}{2}}A{D}^{-\frac{1}{2}}$$\end{document}

where A denotes the adjacency matrix encoding layer dependencies and D represents the degree matrix. Computing the k smallest eigenvalues produces embedding vectors that cluster layers with strong mutual dependencies—these clusters form natural partitions that schedulers can assign to individual devices while minimizing cross-partition data transfers.

To be specific, we adopt the Normalized Cut formulation for spectral clustering. After constructing the normalized Laplacian matrix from Eq. (21), we compute its k smallest non-trivial eigenvalues using the Lanczos iterative method, which avoids the full eigendecomposition and reduces complexity from \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:O\left({\left|V\right|}^{3}\right)$$\end{document} to approximately \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:O\left(\left|V\right|\cdot{k}\cdot{m}\right)$$\end{document}, where m denotes the number of Lanczos iterations (typically \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:m\ll\:\left|V\right|$$\end{document}). The resulting eigenvectors are stacked column-wise into a matrix \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:U\in\:{R}^{\left|V\right|xk}$$\end{document}, and each row is normalized to unit length. We then apply k-means clustering on the rows of U to obtain k partitions that approximate the minimum normalized cut objective. The number of partitions k is set equal to the number of available devices \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:\left|D\right|$$\end{document}, so that each cluster maps naturally to one processing unit. This procedure ensures that layers with dense mutual data dependencies concentrate within the same partition, thereby minimizing the volume of cross-device data transfers.

Heterogeneous resource matching proceeds by computing affinity scores between layer partitions and available devices. For partition \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{P}_{j}$$\end{document} and device \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{d}_{i}$$\end{document}, we define:22\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:S({P}_{j},{d}_{i})=\sum\:_{{v}_{k}\in\:{P}_{j}}^{}\mathrm{A}\mathrm{f}\mathrm{f}\mathrm{i}\mathrm{n}\mathrm{i}\mathrm{t}\mathrm{y}(o{p}_{k},{d}_{i})\cdot\frac{{W}_{k}}{\sum\:_{{v}_{l}\in\:{P}_{j}}^{}{W}_{l}}$$\end{document}

where operator affinities weight according to computational workload contribution, producing a compatibility score that guides the matching process40. We solve the assignment problem through a modified Hungarian algorithm that handles capacity constraints—devices cannot accommodate partitions exceeding their memory limits:23\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:\sum\:_{{P}_{j}:\phi\:\left({P}_{j}\right)={d}_{i}}^{}\mathrm{M}\mathrm{e}\mathrm{m}\left({P}_{j}\right)\le\:{M}_{i}\left(t\right)$$\end{document}

where \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:\mathrm{M}\mathrm{e}\mathrm{m}\left({P}_{j}\right)$$\end{document} aggregates memory requirements across all layers in partition \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:{P}_{j}$$\end{document}.

Dynamic load balancing responds to runtime deviations from predicted resource availability by monitoring actual device utilization and comparing against target thresholds. When imbalance exceeds tolerance levels, the scheduler initiates partition migration:24\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:\mathrm{M}\mathrm{i}\mathrm{g}\mathrm{r}\mathrm{a}\mathrm{t}\mathrm{e}({P}_{j},{d}_{i},{d}_{k})\mathrm{i}\mathrm{f}|{U}_{i}-{U}_{k}|>{\delta\:}_{threshold}\wedge\:{\mathrm{C}\mathrm{o}\mathrm{s}\mathrm{t}}_{migrate}<{\mathrm{B}\mathrm{e}\mathrm{n}\mathrm{e}\mathrm{f}\mathrm{i}\mathrm{t}}_{balance}$$\end{document}

Solving the optimization problem exactly requires enumerating all possible layer-to-device mappings—a combinatorial explosion with complexity \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\:O\left(\right|D{|}^{\left|V\right|})$$\end{document} rendering brute-force approaches intractable for realistic network sizes. where the penalty term discourages overloading already-saturated devices, promoting balanced allocation42. Empirically, this two-phase approach—greedy initialization followed by iterative refinement—produces solutions within 10–15% of optimal assignments computed through exhaustive search for small problem instances, while scaling to production workloads where exact optimization proves computationally prohibitive. making it suitable for online deployment where scheduling decisions must complete within millisecond timescales to avoid becoming execution bottlenecks themselves.

These baselines represent a spectrum of scheduling philosophies from simple heuristics to learning-based methods. To ensure fair comparison, we clarify the information available to each method. Round-Robin receives no topology or profiling information and distributes layers cyclically. Greedy-First accesses real-time device utilization measurements but not the computational graph structure. HEFT receives the complete computational graph with operator-level execution time estimates obtained through pre-execution profiling on each device type, consistent with its standard formulation. The RL-PPO baseline, employing proximal policy optimization45, was trained for 50,000 episodes on historical workload traces collected from the same six models; its state representation encodes current device utilization levels and a fixed summary of pending task properties (operation type, estimated FLOPS, memory footprint), while its reward signal combines negative makespan with a utilization balance bonus. Notably, RL-PPO does not receive the full topology graph at decision time—it observes only local task features. All baselines, including ours, operate under identical hardware conditions and resource monitoring capabilities.

Algorithm adaptability and robustness validation

Evaluating scheduling performance across diverse topological structures reveals how well our algorithm generalizes beyond the specific architectures employed during development. We constructed synthetic neural networks with controlled topological properties—varying graph depth from 10 to 200 layers, branching factors from 1 (purely sequential) to 8 (highly parallel), and dependency density quantified by the ratio of edges to vertices. Networks with linear topologies (ResNet-style sequential blocks) present minimal parallelization opportunities, forcing schedulers to rely primarily on optimal device matching rather than concurrent execution50. Our algorithm maintains 8.3% latency advantage over HEFT even in these constrained scenarios by intelligently assigning sequential segments to their most suitable devices based on operator composition.

Dynamic load scenarios simulate realistic deployment conditions where AI-PC systems simultaneously handle multiple concurrent applications competing for shared computational resources. The predictor continuously monitors actual device utilization, detecting deviations from forecasted availability and triggering adaptive rescheduling when discrepancies exceed tolerance thresholds.

Testing resource configuration sensitivity involved systematically varying heterogeneous device capabilities—reducing GPU memory from 24GB to 8GB, throttling NPU performance by 30% to simulate thermal constraints, and introducing network bandwidth limitations from 10Gbps down to 1Gbps. NPU throttling shifts the optimal device affinity, favoring GPU execution for operations that previously preferred NPU processing. Our algorithm adapts gracefully to these variations—when we reduced GPU memory by 67%, baseline methods experienced catastrophic failures (out-of-memory errors requiring complete redesign), while our dynamic partitioning mechanism automatically adjusted granularity, maintaining functional execution with 31% latency penalty51.

Discussion

The experimental results demonstrate consistent performance improvements across diverse neural network architectures and hardware configurations, supporting our hypothesis that topology awareness yields measurable benefits for heterogeneous resource scheduling. The magnitude of improvements—ranging from 13.5% latency reduction to 30.1% NPU utilization gains, all statistically significant at p < 0.005—suggests that computational graph structure contains information that schedulers can exploit to improve resource allocation in heterogeneous environments. We note that these gains are observed within the scope of the six tested architectures and three hardware platforms; broader generalization to untested model families or hardware configurations warrants further investigation.

Our algorithm’s applicability extends most naturally to scenarios involving complex, branching neural architectures deployed across systems with pronounced device heterogeneity. Vision transformers, multi-branch detection networks, and ensemble models represent ideal candidates where topology awareness delivers maximum value. The scheduler identifies parallelization opportunities within these structures that simpler approaches overlook, simultaneously executing independent attention heads on separate devices or distributing detector branches across heterogeneous units. Conversely, purely sequential networks with minimal branching—simple feedforward classifiers or early convolutional architectures—offer limited topology-derived benefits since few layers can execute concurrently regardless of scheduling sophistication. Yet even in these constrained cases, intelligent device matching based on operator affinity maintains competitive performance.

The mechanism through which topology awareness improves scheduling operates at multiple levels. Most directly, computational graph analysis reveals dependency constraints that define permissible execution orderings, enabling the scheduler to maximize parallelism without violating correctness requirements. Beyond simple parallelization, topology information guides intelligent partitioning—the spectral clustering approach groups layers with strong mutual dependencies, minimizing cross-partition communication when these cohesive clusters map to single devices. Perhaps most importantly, runtime topology monitoring detects structural changes in adaptive networks, triggering rescheduling when execution paths diverge from anticipated patterns. This dynamic responsiveness prevents resource waste from maintaining allocations optimized for inactive network branches.

The algorithm practical advantages include its adaptability across model architectures and its modular design. Unlike learning-based schedulers that require extensive training on representative workload distributions, our approach operates on novel architectures through its topology extraction and analysis methodology, though we acknowledge that the underlying components—spectral clustering, greedy assignment, and linear prediction—are individually well-established in prior literature. Our contribution lies in their integration into a unified online scheduling framework that jointly addresses topology dynamism and resource heterogeneity. The modular design facilitates incremental deployment—organizations can adopt individual components like topology awareness or resource prediction independently before integrating the complete framework. Furthermore, the polynomial computational complexity ensures scheduling decisions complete within acceptable latency bounds even for large networks, as confirmed by the overhead measurements in Table 7.

However, several limitations warrant explicit acknowledgment. First, the current implementation assumes computational graphs remain acyclic—networks with recurrent connections or feedback loops (such as LSTMs and certain graph neural networks with message-passing cycles) require extended handling that our prototype does not yet address; applying the scheduler to such architectures would demand cycle-breaking heuristics or iterative unrolling that could compromise scheduling fidelity. Second, profiling overhead, while generally modest (3.86% of inference time on average, as quantified in Table 7), accumulates for extremely high-frequency inference requests; applications demanding sub-millisecond inference latency may find the 4.55 ms scheduling overhead prohibitive without further optimization. Third, the resource prediction model demonstrates acceptable accuracy for typical workload patterns (MAPE of 6.8–12.4%) but struggles with sudden, unprecedented background load spikes that historical data provides no basis for anticipating—for instance, an antivirus scan consuming 80% of CPU capacity within a single measurement interval can temporarily invalidate predictions. Fourth, our spectral clustering approach relies on the quality of the Laplacian eigenvectors, and for very small graphs (fewer than 10 operators) the clustering may not yield meaningful partitions, effectively reducing the scheduler to a simple affinity-based assignment. Fifth, our method depends on deep learning framework hooks for topology extraction; frameworks that aggressively fuse or rewrite operators during graph compilation (such as TensorRT or XLA) may obscure the logical layer structure, limiting extraction fidelity. Finally, energy measurements on Platform C rely on software-estimated power counters rather than direct hardware instrumentation, introducing measurement uncertainty of approximately 10–15% in the reported energy efficiency figures.

Practical deployment encounters challenges beyond algorithmic considerations. Heterogeneous systems often lack standardized interfaces for querying device capabilities and monitoring resource availability—each vendor provides proprietary APIs requiring platform-specific integration effort. Energy measurement infrastructure varies dramatically across platforms, with mobile devices offering detailed power monitoring while some desktop systems provide only coarse estimates, complicating energy-aware scheduling.

Addressing these challenges demands ongoing refinement. Extending topology analysis to handle cyclic graphs would broaden applicability to recurrent and graph neural networks. Developing adaptive profiling strategies that dynamically adjust instrumentation granularity based on inference frequency could reduce overhead for latency-critical applications. Tighter integration with deep learning compilers might enable co-optimization where the compiler considers scheduling constraints during graph transformation. Despite these remaining challenges, the substantial performance improvements demonstrated across diverse scenarios establish topology-aware scheduling as a promising direction for heterogeneous AI system optimization.

Conclusion

This work addresses the challenge of resource scheduling in heterogeneous AI-PC collaborative computing environments through an approach that integrates dynamic neural network topology awareness into scheduling decision processes. We developed an algorithmic framework comprising three synergistic components: a runtime topology extraction mechanism that captures evolving computational graph structures with modest instrumentation overhead (0.31 ms per operator), a predictive resource modeling system that forecasts device availability patterns with 6.8–12.4% MAPE by analyzing historical utilization traces, and an adaptive scheduling optimizer that jointly considers topology dependencies, device heterogeneity, and temporal resource fluctuations when computing layer-to-device mappings.

The research delivers three principal contributions that extend existing scheduling methodologies. First, we introduced real-time topology monitoring that detects structural changes in adaptive neural networks, enabling schedulers to respond dynamically as execution paths diverge from initial predictions. While runtime graph interception itself builds on established framework hook mechanisms, our contribution is the integration of change detection (Eq. 18) with triggered rescheduling in an online heterogeneous setting. Second, our spectral clustering-based partitioning strategy, formulated via the Normalized Cut criterion with Lanczos-accelerated eigenvector computation, exploits dependency structures within neural topologies to reduce inter-device communication overhead. Third, the dual-layer adaptation mechanism simultaneously adjusts to both neural architecture variations and fluctuating resource availability, as validated by the ablation study (Table 8) showing 17.1% degradation when topology awareness is removed.

Theoretically, this work establishes topology structure as a first-class consideration in heterogeneous scheduling problems, extending classical resource allocation frameworks that traditionally treated workloads as atomic units. The mathematical formulation linking graph-theoretic topology properties to scheduling objectives provides a foundation for future research exploring deeper connections between neural architecture design and computational efficiency. Practically, experimental validation demonstrates substantial performance improvements—13.5% latency reduction, 15.6% throughput increase, and 16.1% energy efficiency gain compared to state-of-the-art baselines—across diverse neural architectures and hardware platforms. These gains translate directly to enhanced user experience responsiveness and extended battery life in mobile AI-PC scenarios.

Several limitations constrain the current work scope, as discussed in detail in Section V. The algorithm presently handles only acyclic computational graphs, excluding recurrent and graph neural network architectures that contain feedback cycles. Profiling overhead, while measured at 3.86% of inference time on average, may prove excessive for ultra-low-latency applications. The resource prediction model occasionally struggles with unprecedented load patterns outside the training distribution. Additionally, our evaluation covers three hardware platforms; results on emerging accelerator architectures (e.g., dedicated transformer engines, neuromorphic chips) remain unverified.

Future research should pursue multiple promising directions. Extending topology analysis to cyclic graph structures would broaden applicability to recurrent architectures. Investigating co-optimization between neural architecture search and scheduling-aware design could yield networks inherently more amenable to efficient heterogeneous execution. Exploring federated scheduling across distributed AI-PC clusters would address emerging scenarios where workloads span multiple physical devices. Finally, developing automated tuning mechanisms that adapt algorithm parameters to specific deployment contexts could reduce the manual configuration burden that currently limits widespread adoption.
