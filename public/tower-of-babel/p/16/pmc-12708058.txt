scHLens: a web server for hierarchically and interactively exploring single cell RNA-seq data
Authors: Jiazhi Xia, Zhiwei Deng, Chen He, Min Li, Ruiqing Zheng
Published: 2025

ABSTRACT
AbstractWith the great advancement of single-cell transcriptome technologies, the identification of cellular heterogeneity from scRNA-seq data has become an important task in biomedical research. There are several challenges associated with the existing analysis methods: (i) The reliance on command-line interfaces creates a substantial technical barrier for researchers lacking computational expertise; (ii) existing methods or platforms usually lack flexibility in workflow customization, forcing users into rigid analytical pipelines; (iii) hierarchical cellular subtypes challenge conventional clustering, as fixed-resolution analyses prevent the detection of biologically subtype cells. Here, we develop a hierarchical and interactive web server named scHLens. scHLens supports a user-defined analysis pipeline and hierarchical exploration mode, providing various visualization views and interaction operations. The three case studies demonstrate scHLens’s ability to identify cellular heterogeneity. The online web server version is freely available at http://schlens.csuligroup.com, while the Docker version is available at https://hub.docker.com/r/zhiweideng975/schlens, and the source code can be obtained at https://github.com/ZhiweiDeng459/scHLens.Keywords: scRNA-seq, cell type identification, custom pipeline, hierarchical exploration, web app

Introduction

Single-cell RNA sequencing (scRNA-seq) provides unprecedented opportunities for studying gene expression at single cell level. In recent years, resolving cellular heterogeneity from scRNA-seq data has become the new paradigm of biomedical research. A well-designed cellular heterogeneity analysis pipeline would enhance the identification of novel cell types, rare cell populations, and transitional states. Many R and Python tools are developed to facilitate the analysis of scRNA-seq, such as CellRanger [1], Seurat [2], and Scanpy [3]. More recently, several deep learning-based methods have been proposed for cell representation learning and subsequent cell clustering, including CAKE [4], scMMN [5], and BNFW [6]. However, most of them are limited to a fixed analysis pipeline and impose considerable programming knowledge, such as programming competence in R and Python, and specialized knowledge for leveraging Graphics Processing Unit (GPU) resources. Therefore, web services would be more efficient and user-friendly for researchers to analyze the scRNA-seq data, especially for wet labs.

Currently, several GUI-based web platforms have been developed to analyze scRNA-seq data. For instance, 10X Genomics developed Loupe Browser to interactively visualize, cluster, and annotate cells. GranatumX [7] offered the user the opportunity to rapidly establish the customized pipeline. CellAnn [8], a reference-based cell annotation web server, is notably fast and user-friendly. ICARUS [9] is mainly based on the Seurat package as the backbone and provides a tutorial-style user interface to guide the biological analysis. Meanwhile, ICARUS-v3 [10] integrated the geometric cell sketching method to deal with large-scale datasets and improve the computational efficiency. Similarly, Yu et al. developed the web tool GRACE [11] to enable the comprehensive online analysis of the massive single-cell transcriptome profile. Although these web tools and platforms offer vivid analysis modules and interactive modes of operation, they often ignore the challenges posed by the inherent hierarchical heterogeneity of cells. As our understanding of cellular heterogeneity deepens, there is an increasing demand for hierarchical analyses targeting specific functional cell subtypes, beyond traditional coarse-grained cell clustering. Simultaneously, the demand for customized analyses is growing, with biologists frequently requiring web servers to provide more interactive features that allow the integration of their biological knowledge and obtain satisfactory outcomes step by step.

In this study, we developed a web server for hierarchically and interactively exploring cellular heterogeneity, called scHLens. scHLens focused on the cell type annotation of scRNA-seq. The main novelty of scHLens includes two aspects. Firstly, for each layer, scHLens provided a customized pipeline for gene selection, cell visualization, clustering, differentially expressed gene analysis, and cell type annotation. Then, scHLens provided a hierarchical analytical mode to explore cellular heterogeneity and proposed a novel hierarchical visualization method to integrate different levels of cell subgroups. This web platform allows users to easily select, export, delete, and reanalyze specific cell groups of interest. We believe that this hierarchical exploration of single-cell RNA-seq data will become a new paradigm for the analysis of cellular heterogeneity.

Materials and methods

Implementation

We implemented scHLens as the framework shown in Fig. 1. The architecture of this implementation is a web-based platform using Flask. The server-side provides popular scRNA-seq analysis modules, enabling users to customize personalized analysis pipelines. Table S1 lists the version information of the methods integrated within these modules. The client-side is implemented in Vue.js and D3.js, offering a diverse range of visualization options and interactive operations, enhancing user engagement and data exploration. Furthermore, scHLens supports four types of formatted scRNA-seq datasets as input, including 10x_mtx, h5ad, csv, and h5df. The figures and the processed data generated by scHLens can be exported as SVG format images and h5ad files, respectively, enabling easy integration with other users’ analysis tools. Besides, we designed the “Job” mechanism to help users manage their analysis work using a personal workspace called “Job,” and this mechanism will be detailed in the tutorials, which have been integrated into this web server. Additionally, we provide three convenient access options for users to use scHLens. The online web version can be found at http://schlens.csuligroup.com. Due to limitations in network transmission speeds and server computing performance, many large scRNA-seq datasets may experience slow processing on our web servers. To mitigate this issue, we offer a deployable Docker version of scHLens (https://hub.docker.com/r/zhiweideng975/schlens), allowing users to effortlessly deploy and run the software on their own high-performance local servers. Additionally, for experienced developers, we also provide the source code of scHLens on GitHub (https://github.com/ZhiweiDeng459/scHLens) to facilitate further development of the platform.

The framework of scHLens. (A) scHLens supports various commonly used formats for scRNA-seq dataset input, including 10x_mtx, h5ad, csv, and h5df. (B) To make the analysis process more flexible, scHLens provides a user-defined pipeline for data input. The pipeline consists of seven customizable modules, each performing a specific task. Users can edit the pipeline as needed. (C) scHLens provides an interactive visualization interface that includes multiple views, such as cell projection view and distribution of gene expression view, along with various interactions like selection and filtering. (D) scHLens proposes a hierarchical exploration mode to support the identification of hierarchical cell type structure. Then, the Global Plot can be merged with the local annotation and good visual separation pattern provided by Local Plot.

The user-defined pipeline with a set of customizable modules

There is no general scRNA-seq analysis pipeline that is suitable for all datasets [12]. Therefore, scHLens introduces a user-defined pipeline for personalized analysis (Fig. 1B). Specifically, the traditional analysis pipeline can be divided into seven modules, each of which performs a specific task, including quality control, normalization, gene selection, visualization, clustering, cell communication, and differentially expressed genes (DEGs) identification. Besides, there are additional Downsampling module and Annotation module, which are respectively used in the process of Data Input (Fig. 1A) and Hierarchical Exploration (Fig. 1D). In scHLens, users can flexibly select and assemble modules according to their specific needs. Likewise, for each module, scHLens also provides a variety of customizable options for selection. scHLens integrates existing popular and advanced methods for each module. We will introduce the details of these modules as follows.

Downsampling module for the large-scale dataset

The downsampling module selects a subset of cells from the large-scale dataset to reduce computational cost and memory usage. This module contains two downsampling methods. The first is Random Sampling, where each cell in the population has an equal chance of being selected. The second is Stratified Sampling, which draws samples from each known cell type or cluster, typically in proportion to the cluster’s size relative to the entire population.

Quality control module

The quality control module filters low-quality cells and genes to ensure downstream analysis quality. This module contains three steps. The first step is to filter cells with gene expression lower than a certain threshold. The second step is to filter genes with cell expression count lower than a certain threshold. The third step is to filter cells that have a high percentage of counts allocated to mitochondrial genes [13].

Normalization module

The normalization module adjusts raw expression counts to a common scale. This module includes five normalization steps or methods: the first is Counts Per Million normalization, which assumes that all cells contain equal total counts (). The logarithmize function is used to transform the expression values with the . The third is scaling, which scales the data to unit variance and zero mean. The fourth step is regressing out. This regressing out method comes from [2], using a simple linear model to remove most of the unwanted sources of variation. Additionally, scHLens incorporates an advanced method known as scTransform [14], which serves as a model-based framework for simultaneous normalization and variance stabilization.

Gene selection module

The gene selection module filters uninformative or noisy genes and only focuses on the biological variable genes. This module offers three feature selection methods: the first method is highly variable genes (HVGs) originally used in Seurat [2]. HVG calculates the normalized variance as the gene variance and then retains the higher-variance ones. The second method, scry [15], selects high-variance genes based on a multinomial null model that assumes each feature has a constant rate. In addition, scTransform [14] (used in the normalization module) can also be used for gene selection.

Visualization module

The visualization module provides the selection of dimension reduction techniques, which embed high-dimensional cell expression data into a 2D space. These visualization techniques allow researchers to directly identify the diversity of cell types and states, and even indicate the presence of numerous rare cell populations. This module supports three different methods. The first dimension reduction algorithm, Principal Components Analysis (PCA) [16], is a linear dimension reduction algorithm that preserves the principal structure of the data. The second is t-SNE [17], which is a nonlinear dimension reduction algorithm that models the similarities between data points in high-dimensional space and preserves neighboring relationships in the lower-dimensional representation. The third dimension reduction algorithm, Uniform Manifold Approximation and Projection (UMAP) [18], is also a nonlinear dimension reduction algorithm and performs better than t-SNE’s performance in preserving global structure and computational speed.

Clustering module

The clustering module is designed to group similar cells based on their biological features. scHLens integrates three popular unsupervised clustering methods. The first method is k-means [19], which is one of the most widely used clustering algorithms due to its simplicity, efficiency, and scalability, particularly for large datasets. The second clustering method, Leiden [20], enhances the Louvain method [21] by employing a multilevel optimization approach to modularity. Additionally, SC3s [22], which is an efficient version of consensus clustering SC3 [23], allows for more accurate and robust characterization of cellular heterogeneity in complex biological backgrounds. Generally, each method performs better based on the principal components generated by PCA. Besides, we also integrated an automatic cluster number recommendation method, MultiK [24], to avoid manual adjustment of clustering parameters.

Differentially expressed gene identification module

After clustering, the DEG identification module identifies specific DEGs for each cell cluster, thereby preparing for cell type annotation. This module integrates two DEG identification methods. The first method is the “rank_gene_groups” function from Scanpy [3]. This function can use different methods for estimating the variance of each group, including t-test, t-test (overestimate variance), Wilcoxon test [25], Wilcoxon test (tie correction,), and logistic regression [26]. The second method is COSine similarity-based marker Gene identification (COSG) [27], which is a cosine similarity-based DEG identification method. Compared to statistical methods, COSG focuses more on differences in expression patterns rather than differences in expression values.

Cell communication module

The cell communication module predicts the specific cell types that act as signal senders and receivers within the dataset, thus identifying potential cell–cell interactions. This module integrates two widely used analytical methods, CellChat [28] and CellPhoneDB [29]. In addition, it incorporates ligand–receptor pair databases from CellChat [28] and NicheNet [30].

Cell type annotation module

The cell type annotation module (abbreviated as Annotation module) can recommend the relevant cell types based on the matching of marker genes (identified in the DEG Identification module) with the gene sets database. This module integrates two widely used methods, EnrichR [31–33] and Gene Set Enrichment Analysis (GSEA) [34], along with 30 marker gene databases from EnrichR, including CellMarker [35] and others. Table S2 provides a detailed summary of these databases.

The diverse and vivid visualization views

An appropriate figure allows users to gain an in-depth understanding of cellular characteristics intuitively. Therefore, scHLens provides various figures in the form of visualization interface, which are called “views” (Fig. 1C), to present the results after analysis. These views include cell projection view, gene projection view, distribution of gene expression view, cell communication view, marker gene view, and hierarchy navigation. The overview of these views is shown in Fig. 2. In this section, we will introduce these visual representations. These views are interactive, and we will introduce some key interactions in Section Hierarchical Exploration with Interactive Steering.

The overview of the visualization interface. Multiple views are organized in the interface of scHLens: (A) cell projection view; (B) gene projection view; (C) distribution of gene expression view; (D) cell communication view; (E) marker gene view; (F) hierarchy navigation.

Cell projection view

The cell projection view (Fig. 2A) represents the distribution of cells in 2D space using a scatter plot, which reflects the distribution of raw gene feature space. Each dot in the plot represents a cell. The position of the dot is derived from the visualization module, and the color indicates its corresponding cluster from the clustering module in the pipeline. Besides, the silhouette score, a computed cluster assessment score, will be displayed in the top-left corner of this view.

Gene projection view

The gene projection view (Fig. 2B) represents the distribution of specific gene(s) expression across all cells on a 2D plot. It consists of two modes: “Scatter” and “Density.” “Scatter” mode (Fig. S1A) uses a color-coded scatter plot to display gene-specific observations across discrete cells, with each point positioned identically to those in the cell projection view. This mode is particularly suitable for small-to-medium-scale datasets. “Density” mode (Fig. S1B) utilizes a 2D-density plot to visualize the mean values obtained by aggregating the scatter plot using a grid-based approach, which is optimized for large-scale datasets.

Distribution of gene expression view

This view (Fig. 2C) generates violin plots for each group to indicate expression of specific gene(s), aiming to compare the distribution of gene expression across different groups. The violin plot uses a kernel density plot to show the distribution of the gene’s expression in its group. Besides, it uses additional visual elements to enhance the violin plot with two modes: “Box” and “Strip.” “Box” mode (Fig. S2A) provides box plots for each group to display statistical values of gene expression. “Strip” mode (Fig. S2B) superimposes individual cell dots within each kernel density plot to depict discrete gene expression values.

Cell communication view

The cell communication view (Fig. 2D) illustrates interactions among different cell groups. It supports the visualization of two types of cell communication data: “Weight” and “Count.” “Weight” represents the communication strength between groups, whereas “Count” denotes the number of ligand–receptor pairs connecting them. Two visualization modes are provided: “Chord” and “Edge.” The “Chord” mode (Fig. S3A) uses a chord diagram, which is well suited for datasets with a small number of groups. In contrast, the “Edge” mode (Fig. S3B) employs a hierarchical edge bundling plot, making it more appropriate for complex datasets involving multiple groups.

Marker gene view

The marker gene view (Fig. 2E) uses a dot plot to indicate the potential marker genes’ expression (from the Differential Expressed Gene Identification module) in each group. In the dot plot, the x-axis represents the marker gene list, and the y-axis represents the group list. Each dot indicates the expression level of a marker gene in the corresponding group. Dot size represents the proportion of expressed cells, and the color gradation of dots represents the mean expression value. By clicking on the gene names within the dotplot, scHLens enables convenient synchronization with the distribution of gene expression view, thereby visualizing the distribution of specific genes across distinct cell clusters.

Hierarchy navigation

The hierarchy navigation (Fig. 2F) visualizes the relationship between the Global Plot and the Local Plots (see Hierarchical Exploration with Interactive Steering for more details) using a tree structure. The root node represents the Global Plot, while the other nodes represent the Local Plots. Child nodes are created based on the “Create Local Plot” operation performed on their parent nodes. The node corresponding to the currently active plot in the system interface is highlighted in the hierarchy navigation, while other inactive nodes are shown in gray.

Hierarchical exploration with interactive steering

The primary advantage of scHLens lies in a hierarchical and interactive exploration manner to analyze the cell heterogeneity. Due to the hierarchical and complex nature of cell types, a comprehensive analysis of scRNA-seq data is challenging to achieve in a single analytical run. Therefore, employing a hierarchical and interactive exploration way is more appropriate. Inspired by previous hierarchical analysis works, such as [36–40], we proposed a new hierarchical and interactive exploration mode that enables users to fully leverage their expertise in the biomedical field—an advantage that is often absent in automated computational analysis methods.

The process of hierarchical exploration is illustrated in Fig. 1D. Following the initial analysis, scHLens generates a visualization plot representing the entire cell population, referred to as the “Global Plot.” In this Global Plot, cell populations are grouped based on the clustering methods utilized in the analysis pipeline. Biologists can then annotate these groups with the help of the Annotation module. However, due to inherent limitations in analytical methods, the Global Plot may not always align with actual biological phenomena. Cells that are apart in the same cluster often indicate potential refined subtypes. To address this issue, users have the option to reanalyze specific local cell clusters of interest. scHLens enables users to select specific cells on the Global Plot to customize and rerun the analysis pipeline, resulting in a local view, termed the “Local Plot.” In the Local Plot, users can obtain new visualization, clustering, and annotation results for this subset of cells. Additionally, scHLens supports the generation of multiple Local Plots by selecting different cell clusters, as well as deeper levels of views.

After finishing the annotation in the Local Plot, it is essential to update the Global Plot based on the results of the Local Plot. We refer to this process as the “merge” operation. The merge process includes two aspects: cellular annotation and visualization result. For cellular annotation, scHLens only needs to replace the corresponding cell annotations in the Global Plot with the local ones. For visualization results, we develop a hierarchical spatial persevering algorithm to ensure that the corresponding relative position of cells in the Local Plot could be preserved in the Global Plot. As shown in Eq. Then, the merged distance matrix will be used in the selected visualization techniques, such as t-SNE or UMAP, to obtain the merged Global Plot. Finally, the merged Global Plot is presented as an updated cell annotation atlas.

Besides, to make hierarchical exploration more convenient, scHLens also provides several interaction designs:

[Select cells] : Selecting cells is a prerequisite for creating Local Plot. Therefore, scHLens provides flexible and powerful selection operations. The first selection form is lasso selection, which allows cells to be selected by moving the mouse. The second form is selecting by cluster because the analysis often needs to focus on one or several groups. The third form is selecting by gene expression requirements. Users can set the range of interested genes to select the cells that meet these expression range requirements. Besides these basic selection forms, scHLens also provides “Selecting All Cells,” “Inverse Selection,” and “Clear Selection.”

[Delete Node] : Delete Node, also called Delete Plot, is used to remove the Local Plot from the hierarchy navigation. It is possible to create some bad Local Plots that you do not want to retain during hierarchical exploration and then you can delete them.

[Discover the correspondence] : Local Plots come from a cell subset of their ancestor plots. When checking the relationship between Local Plots and their ancestor plots, users may want to know the positions of Local Plots’ cells within their ancestors. To satisfy this requirement, scHLens provides a Correspondence Explorer. The Correspondence Explorer can display the corresponding positions of the Local Plot’s cells in the ancestor plot with different colors. It can also display the corresponding positions of the selected cells after selecting in the Local Plot.

Results

Case1: clustering and annotating PBMC-3 K dataset

PBMC-3 K is a widely used scRNA-seq dataset and has credible annotations from the Scanpy tutorial (https://scanpy.readthedocs.io/en/stable/tutorials/basics/clustering-2017.html). The PBMC-3 K dataset, consisting of peripheral blood mononuclear cells (PBMCs) from a healthy donor, represents a diverse set of immune cell types, such as T cells, B cells, Natural Killer (NK) cells, and Monocytes. It includes high-quality gene expression profiles and contains 2700 cells and 32 738 genes. The PBMC-3 K dataset is freely available from 10x Genomics (https://support.10xgenomics.com/single-cell-gene-expression/datasets/1.1.0/pbmc3k). We would evaluate the reliability and accuracy of scHLens based on the comparison with the credible annotation from Scanpy.

For the annotation of PBMC-3 K, a single layer is sufficient without the need for additional multilayer exploration. After the pipeline including HVGs, UMAP, and Leiden algorithms, the cell population was divided into eight clusters and visualized in the Global Plot. In the Annotation module, we selected the EnrichR [31–33] method and the Azimuth 2021 database to recommend cell types for these eight groups. Based on cell types with significantly high confidence in the recommendations, we were able to annotate each group (Fig. 3A). The EnrichR recommendation results are shown in Fig. 3C.

The annotation results for PBMC-3 K dataset in Case 1. We annotated the PBMC-3 K dataset using the EnrichR recommendation results in scHLens, and then compared this annotation with Scanpy’s annotation to validate the effectiveness of scHLens. (A) The cell projection view with annotations from scHLens. (B) The cell projection view with credible original annotations from the Scanpy tutorial. (C) The EnrichR recommendation results. The results for each group are represented by a bar plot, where the x-axis denotes the recommended cell types and the y-axis represents the negative logarithm of the FDR P-values (indicating recommendation confidence).

We compared the final annotation results (Fig. 3A) with the original annotations from the Scanpy tutorial (Fig. 3B) and found that the annotations for most cells matched. Some cell types were annotated as their close subtypes, including FCGR3A+ Monocytes as CD16+ Monocytes and Megakaryocytes as Platelets. The results validate the reliability of scHLens.

Case2: scHLens identifies endocrine subtypes and rare cell types of human pancreatic dataset

This is an early and representative dataset of the human pancreatic cell atlas obtained from an automated platform that utilizes FACS and CEL-Seq2. This dataset can be accessed at https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE85241. After preprocessing, the dataset contains 2122 cells and 19 046 genes, and was originally annotated as nine major cell types, including five kinds of Endocrine cells (Alpha cells, Beta cells, Delta cells, Epsilon cells, and Gamma cells), two kinds of Exocrine cells (Ductal cells and Acinar cells), Mesenchymal cells, and Endothelial cells [41].

The exploration of the Human Pancreatic Dataset was conducted in a hierarchical manner, comprising three levels, as shown in Fig. 4. At level 1, we employed HVGs, PCA for predimensionality reduction, and other techniques alongside the Leiden clustering algorithm. All cells were initially clustered into six categories (c_0–c_5). According to the recommendations from the Annotation module, four major cell types were accurately identified: Acinar cells, Ductal cells, Mesenchymal cells, and Endothelial cells. The clusters c_0 and c_1 exhibit several relatively clear blocks, and therefore, they were selected for more detailed clustering.

Case 2: the overview of the hierarchical exploration process. Upon completion of the initial pipeline, Global Plot ① was generated with six clusters (c_0–c_5). Among these, clusters c_2–c_5 were accurately annotated, while c_0 and c_1 exhibit evident subpopulation patterns that warrant further analysis. First, we selected c_0 to create Local Plot ②. Local Plot ② reveals three clusters and can be identified as Alpha cells, Gamma cells, and Myeloid cells. Then, we selected c_1 to create Local Plot ③, which consists of two clusters, Beta cells and Delta cells. Furthermore, we found that beta cells present a potential separation trend, so we created Local Plot ④ for these beta cells and they were divided into three subtypes.

For cluster c_0, we further employed scry, PCA for predimensionality reduction, and other techniques alongside Leiden clustering. As expected, at level 2, cluster c_0 was further divided into three subclusters, as shown in Fig. S4A. Two subclusters were accurately identified as Endocrine cell types: Alpha cells and Gamma cells, according to EnrichR results (Fig. S4B), consistent with the original annotations. Previous study [42] has indicated that Alpha and Gamma cells in the pancreatic endocrine cell lineage are derived from the same precursor and exhibit a higher degree of similarity, and this similarity is also reflected in our visualization results. We also utilized a 2D-density plot to clearly illustrate the classic marker genes for Alpha and Gamma cells (Fig. S4C). The markers for Alpha cells include GCG, TTR, MAFB, FAP, and GLS, while those for Gamma cells comprise MEIS1, ETV1, PPY, GHSR, and PAX4 [43]. The results revealed that these markers displayed clear high expression levels in their respective clusters. Furthermore, we unexpectedly identified a novel subcluster annotated as immune-related Myeloid cells, which was absent in the original annotations. This subcluster was originally annotated as ductal cells in the published dataset. However, the marker genes of ductal cells (KRT19, SOX9, CFTR, HNF1B, and MUC1) [44] were not highly expressed in this cell population (Fig. S4C). The higher expression of the marker genes CD68, CD14, ITGAM, CTSS, and CD9 also proved that this cluster of cells is Myeloid cells [45] (Fig. S4C). The identification of these Myeloid cells holds significant implications in various biomedical contexts, often indicating the presence of inflammatory responses, tissue damage, or viral infections in the pancreas [46, 47]. Notably, this group of Myeloid cells is quite rare, comprising only 21 cells, which accounts for just 0.9896% of the entire dataset. This highlights the significant potential of scHLens for identifying rare cell types.

For cluster c_1, we also employed scry, PCA for predimensionality reduction, and other techniques with Leiden clustering. At level 2, Beta cells and Delta cells were also identified (Fig. 4 Local Plot ③). Likewise, Beta cells and Delta cells in the pancreatic endocrine cell lineage are also derived from the same precursor. In the original study, Muraro et al. [41] utilized the RaceID algorithm for further analysis of Beta cell clusters, revealing subpopulations of cells characterized by distinct gene expression patterns. Inspired by this, we also performed a comprehensive analysis of subpopulations. Through further analysis of Beta cells, at level 3, we identified three distinct subpopulations (Fig. S5A) and their marker genes (Fig. S5B). Among these subclusters, subcluster c_1 exhibits an upregulation of some of the signature genes for PP cells, such as PPY and SST, suggesting that these Beta cells share similar biological characteristics with canonical PP cells [48]. Besides, subcluster c_2 is characterized by high expression of SRXN1 and ferritin subunits, FTH1, which were also identified by Muraro et al. [41]. Next, we used EnrichR [31–33] to perform gene ontology-biological process term (GO-BP) analysis on the top 50 DEGs in three subclusters of Beta cells (Fig. S5C). Subcluster c_0 displays several immune responses, including amyloid fibril formation and regulation of cell motility. Considering the previous findings related to Myeloid cells, it can be inferred that this donor may be experiencing pancreatic inflammation. Cells in subcluster c_1 are presumed to be PPY-lineage cells, thus enriching biological processes such as the Peptide Biosynthetic Process and Regulation of Peptide Hormone Secretion. Subcluster c_2 is enriched in responses to endoplasmic reticulum (ER) stress, which is also validated by Muraro et al. [41].

By summarizing the hierarchical exploration and merging the visualization plots across different levels, the human pancreatic dataset was ultimately categorized into 9 major classes or 11 subtypes, as shown in Fig. 5.

To further investigate the biological significance, we performed cell–cell communication analysis using the CellChat method. The results, presented in Fig. S6, indicate that myeloid cells exhibit a major signaling interaction with ductal cells mediated by the SPP1 ligand originating from the ductal cells and the cognate receptors CD44 and ITGAV_ITGB1 expressed on the surface of the myeloid cells. The SPP1-CD44 interaction has been previously reported in a study of Pancreatic Ductal Adenocarcinoma (PDAC) [49], where it is associated with ductal carcinoma cell stemness and poor prognosis. This finding suggests that the ductal cells from this pancreatic donor may be undergoing a state of inflammation or injury. In addition, the network also detects that beta cells produce Vascular Endothelial Growth Factor A (VEGFA), which is crucial for islet vascularization, revascularization, and overall function [50].

Case3: scHLens hierarchically identifies vivid cell subtypes from large scale human lung cancer dataset

This dataset, obtained from [51], comes from nine treatment-naïve LUAD patients from Brigham and Women’s Hospital. This dataset can be accessed at https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE253013. This dataset contains 256 379 cells with 32 805 genes. The original annotation of this dataset contains nine types, including Airway Epithelium, B cells, CD45+, Endothelial, Epithelial, Fibroblasts, Granulocytes, Myeloid, and T cells. However, the cell type of some cells is still unknown. To enhance analysis efficiency, we employed stratified sampling to select 10 000 cells. In the original study, Xiang et al. primarily focused on stromal cells, particularly mesenchymal and endothelial cells, while the investigation of immune-related cells and epithelial cells was insufficiently addressed. Therefore, we aim to identify additional subtypes by a reanalysis of the data.

The hierarchical analysis process of the human lung cancer dataset is shown in Fig. 6, and it contains four levels. At Level 1 Global Plot ①, all cells were initially clustered into 10 groups (c_0–c_9). Based on the recommendations from the Annotation module, four cell types were accurately identified: B cells, Mast cells, Plasmacytoid Dendritic cells, and Endothelial cells. In addition, a subset of Epithelial cells was also identified. Clusters c_0, c_1, c_2, and c_3 exhibit distinct subtypes. Therefore, we selected these four clusters along with all epithelial cell types for reanalysis.

For cluster c_0, we employed HVGs and PCA for predimensionality reduction, and other techniques alongside the Leiden clustering algorithm. At level 2, cluster c_0 was divided into three subclusters, as shown in Fig. S7A (Local Plot ②). Two subclusters were identified as T cells and NK cells, according to the EnrichR results shown in Fig. S7B. T cells aligned with the original annotations, while NK cells represented a correction for the originally annotated T cells. As shown in Fig. S7C, we utilized 2D-density plots to exhibit the marker genes for T cells and NK cells [52, 53]. The higher expression of CD3 in T cells and FCGR3A in NK cells, along with the lower expression of CD3 in NK cells, supported these annotations. We then performed a further analysis for subcluster c_2 because we believed it contained multiple subtypes according to its EnrichR result. At level 3, we identified three subclusters, which were annotated as T cells, B cells, and B cells, respectively, as shown in Fig. S8A and B. The expression of markers (CD3 for T cells; CD19, CD79A, and CD79B for B cells) in Fig. S8C validated the reliability of our annotations [54].

For cluster c_1, we employed scry, PCA for predimensionality reduction, and other techniques alongside the Leiden clustering algorithm. At level 2, c_1 was divided into two subclusters (Fig. S9A), and they were identified as Dendritic cells and Monocytes according to EnrichR results (Fig. S9B).

Epithelial cells exhibit a rich diversity of subtypes in lung adenocarcinoma (LUAD), and their heterogeneity and states are closely associated with cancer progression and treatment outcomes. For epithelial cells, at level 1, we employed HVGs, PCA for predimensionality reduction, and other techniques alongside the Leiden clustering algorithm to identify nine subtypes. As shown in Fig. S10 Local Plot ⑤, three subtypes were accurately identified as Airway cells, including Goblet cells and Ciliated cells. The remaining cells exhibited high expression of SFTPB (Fig. S10C), allowing them to be broadly classified as alveolar cells. Therefore, we selected for level 3 analysis shown in Fig. S11A. At level 3 local plot ⑥, cluster c_0 and cluster_5 showed comparably high expression of canonical pulmonary alveolar type II (AT2) cell marker genes, including SFTPC, SFTPB, SFTPA1, and SFTPD (Fig. S11B), indicating conserved transcriptional signatures consistent with the previous study [55]. Likewise, cluster c_3 demonstrated higher expression of genes such as AGER, CAV1, PDPN, and CLIC5 (Fig. S11B), indicating that this cluster is representative of pulmonary alveolar type I cells (AT I cells). These cell clusters were also accurately annotated by scHLens as definitive cell types. Besides, the expression patterns of clusters c_1 and c_6 have not been reported in previous studies. Cluster c_1 exhibited dual positive SMIM22+ and SFTPB+, while cluster c_6 displayed club cell-related genes SCGB3A1- and SCGB3A2+. Therefore, we empirically named these two epithelial cell subtypes based on their marker genes. We further performed Gene Ontology (GO) enrichment analysis on the DEGs of these clusters, as shown in Fig. S11C. Both cluster c_1 and cluster c_6 exhibited biological functions related to immune responses. However, cluster c_1 showed a stronger response to stimuli, with significant enrichment in pathways such as “Peptide Antigen Presentation via MHC Class I via ER Pathway” and “Positive Regulation of NF-κB Pathway.” In contrast, cluster c_6 demonstrated a more pronounced enrichment in the “ATP Biosynthetic Process.” Moreover, the clustering results of cells adjacent to pulmonary alveolar type I cells (i.e. the cells within the red dashed box in Fig. S11A, corresponding to clusters c_2, c_4, c_7, and c_8) were relatively disorganized. Therefore, we conducted further cellular heterogeneity analyses, shown in Fig. S12. At level 4 local plot ⑦ (Fig. S12A), we found a rare number of basal cells (cluster c_5, only 16, accounting for 0.16% of the total cell population, is recommended by EnrichR shown in Fig. S12B) as well as some previously unreported epithelial cell types (HLA-DRB5+ SFTPB+ ECs in cluster c_3 and RACK+ SFTPB- ECs in cluster c_4). More importantly, as shown in Fig. S12A and C, we identified a stem cell population termed bronchioalveolar stem cells (BASCs) that are located at the bronchioalveolar duct junctions and coexpress club-cell and AT2-cell markers (SCGB1A1 and SFTPC as well as SCGB3A1 and SFTPB). Simultaneously, we observed that under conditions of alveolar injuries in LUAD, BASCs follow a differentiation trajectory towards alveolar epithelial AT II cells (Fig. S12A). Through GO enrichment analysis of specifically expressed genes in BASCs (Fig. S12C), we found that these cells exhibit strong capabilities for cell differentiation and proliferation, as well as the establishment of epithelial cell polarity. These findings are closely linked to the stemness and differentiation potential of BASCs. Then, as shown in Fig. S12D, we conducted differential expression and functional enrichment analyses between the differentiated AT II cells and naive AT II cells. Our findings revealed that this cluster of AT II cells exhibits enhanced Integrated Stress Response signaling and Regulation of Blood Vessel Remodeling, which aligns with recent research results. This finding also offers new insights for therapeutic approaches to lung diseases, tissue repair in the lungs, and research in regenerative medicine [56].

Comprehensive benchmarking on scRNA-seq data

For a comprehensive benchmarking, we selected three similar web servers to compare their performance with scHLens, including cellAnn [8], GRACE [11], and ICARUS-v3 [10]. Since cellAnn is solely a cell type annotation platform and requires pre-obtained cell clustering results, we utilized the standard Scanpy clustering labels for cellAnn. To quantify performance, we selected two widely recognized metrics, the Adjusted Rand Index (ARI) and Normalized Mutual Information (NMI) for clustering, as well as accuracy (Acc) for cell type annotation. Notably, when calculating the accuracy of cell type annotation, we also consider the annotation to be correct if a cell cluster is labeled as a cell type that shows biological concordance with the true cell type. To ensure fairness, we provided the actual number of cell types for ICARUS-v3 and adjusted the resolution settings of cellAnn, GRACE, and scHLens to closely match the true number of clusters. We conducted a comparison of these methods using six well-annotated real scRNA-seq datasets, three of which have been previously utilized in case studies. Specifically, we removed those mislabeled cells identified in the case studies. For example, we excluded ductal cells that were incorrectly labeled in the human pancreatic dataset, as well as T cells and unknown cells that were misclassified in the human lung cancer dataset. The additional three scRNA-seq datasets are derived from a published study [57] and originate from the mouse heart, trachea, and spleen. They are referred to as Qs_Heart, Qx_Trachea, and Qx_Spleen, and comprise 4365, 11 269, and 8552 cells, respectively. Moreover, we also recorded the runtime for each platform.

The comprehensive overview of their performance is summarized in Fig. 7. As illustrated in Fig. 7, scHLens achieved the highest NMI and ARI in five out of six datasets, highlighting its advantages in clustering performance. Furthermore, scHLens consistently demonstrated superior cell type annotation accuracy across all datasets. It is worth noting that GRACE failed in the cell annotation task because it exclusively relies on the Human Primary Cell Atlas Data as the reference, which lacks representation of relevant cell types such as pancreatic endocrine cells. In contrast, scHLens benefited from its vivid cell marker sets, enabling it to achieve satisfactory accuracy in cell annotation tasks. Additionally, we were unable to retrieve results for the Qs_Heart, Qx_Trachea, and Qx_Spleen datasets from the GRACE platform due to internal server errors, for which no informative diagnostics were provided. The comparison of runtime is presented in Fig. S14. It is obvious that computational efficiency is not scHLens’s primary advantage. While scHLens exhibits comparable efficiency on smaller scRNA-seq datasets, its computation time increases rapidly when the cell scale surpasses 10 000 cells, resulting in an overall runtime similar to GRACE but slower than both cellAnn and ICARUS-v3. This prolonged runtime is primarily attributed to its interactive front-end design, as the requirement for manual selection and editing on the UMAP plot and hierarchical analysis necessitates the substantial and continuous transfer of back-end computation results as data tables to the front end for rendering, which constitutes the main computational bottleneck.

Performance of scHLens was compared with cellAnn, GRACE, and ICARUS-v3 on six representative single-cell RNA-seq datasets, including three human datasets (PBMC-3 k, Human Pancreas, Human Lung Cancer) and three mouse datasets (Qs_Heart, Qx_Trachea, and Qx_Spleen), with three metrics NMI, ARI, and Acc.

Discussion

Although the high accuracy achieved by scHLens in both cell clustering and annotation tasks, the platform still presents some limitations. The benchmarking results indicate that scHLens requires longer execution times during the computation and visualization processes. Therefore, we conduct a detailed analysis of its scalability. The scalability of scHLens was evaluated using scRNA-seq datasets ranging from 1000 to 50 000 cells. We recorded both the runtime and memory consumption used by the system, with the results shown in Fig. S15. Specifically, the running time increased from 35.97 s for 1000 cells to 728.57 s for 50 000 cells, and memory usage rose from 0.54 GB to 41.91 GB. The results indicate that while the runtime and memory consumption of scHLens increase with the dataset scale, this growth remains within acceptable limits for practical web-based operation. In future work, we intend to address current efficiency limitations by integrating distributed computing frameworks, GPU acceleration, and adaptive data compression techniques. These improvements will substantially enhance computational efficiency, thereby supporting the analysis of scRNA-seq datasets more than million cells. A further consideration relates to the difficulty of selecting parameters in customizable pipelines. Despite providing comprehensive documentation and guidance, determining optimal parameter settings remains nontrivial for users without rich experience with the underlying methodologies. To mitigate this issue, we have integrated MultiK into the clustering module to determine the optimal number of clusters. Experimental results across six scRNA-seq datasets show that MultiK yields satisfactory results in estimating the cluster count, as detailed in Fig. S16. Therefore, the full implementation of automated, intelligent parameter suggestion systems remains a promising improvement for future work.

Conclusion

In conclusion, scHLens, to our knowledge, is the first web and standalone application that integrates multiple popular scRNA-seq analysis modules and hierarchical exploration for cell clustering and annotation. Compared with previous web applications, scHLens boasts the following advantages: (i) scHLens provides a comprehensive suite of seven analytical modules, enabling researchers to construct customized scRNA-seq analysis pipelines for diverse research applications; (ii) scHLens provides a hierarchical analytical mode for exploring cellular heterogeneity and introduces a novel method for integrating multiple levels of cell subgroups; (iii) scHLens offers a rich array of visualization views and interactive operations, enabling users to easily select and analyze the specific cell groups of interest; and (iv) scHLens is accessible in both an online format and as a standalone local application. The online version enables users to efficiently conduct analysis without prior programming skills, while the Docker version can be downloaded for more computationally demanding analyses.
