Learning improved representations in encoder-decoder networks for point cloud registration via point interaction modules
Authors: Ming Wei, Sven Sickert, Tim Büchner, Yaoyuan Zhang, Zhiqiang Xu, Joachim Denzler
Published: 2026

ABSTRACT
Point cloud registration focuses on exploring and exploiting feature similarities to match multiple point clouds of a scene from different viewpoints. However, in many real-world scenarios, points are missing (e.g., multiple LiDAR scans), or there is a substantial variation of points in different viewpoints (e.g., from 3D reconstruction), making registration more difficult. In this paper, we argue that the quality of point clouds should be improved to ease the matching process. Using point cloud completion techniques, we aim to enhance the learned low-dimensional point representations in state-of-the-art encoder-decoder architectures. We propose two modules with easy drop-in integration to support the registration: a point moving and point attention offset module. The point moving module refines the positions of irregular point clouds to strengthen the alignment, whereas the point attention offset module improves the likelihood of point matches. Both modules promote interactions among the implicit point representations to improve matching accuracy. To demonstrate the validity of our idea, we modified those representations in two popular encoder-decoder networks. In our evaluation, we use the datasets 3DMatch, 3DLoMatch, and ModelNet40. When incorporating our proposed modules, we achieve 90.6% RR, 72.4% IR with 5000 samples on 3DMatch and 69.3% RR, 43.5% IR with 5000 samples on 3DLoMatch as a new state-of-the-art. Our findings suggest that improving the point cloud quality via learned point representation benefits point cloud registration.

Introduction

Three-dimensional point cloud processing is widely studied and applied in many fields like autonomous driving1–5, industrial and agricultural production6–9, virtual reality10–12, and medicine13–19. The underlying data is often created via LiDAR scanning (light detection and ranging). However, due to the recording procedure itself, as well as adverse factors of the environment, defects of hardware equipment, or occlusions, a single scan cannot create a complete point cloud of a target scene. Instead, the scene must be scanned multiple times from different angles to obtain accurate three-dimensional information. Point cloud registration is the task of finding spatial transformations that align such point clouds from different views to create the complete scene20–28.

Traditionally, iterative closest point (ICP)29 computes an optimal solution by minimizing point distances. As an iterative approach, it is highly dependent on a robust initialization. Dedicated works provide such an initialization, but need additional computational steps like estimating a triangulation of the point cloud30. Nonetheless, recent advancements demonstrated that deep learning is a well-suited replacement for iterative algorithms31–37. In contrast to traditional methods, they have the advantage of combining feature extraction and contextual semantic understanding, which is highly relevant in complex scenes. There is even the potential to substantially improve registration accuracy without additional computational time38.

A first approach for deep learning uses two unaligned point clouds as input for the network39–42. It predicts the rotation matrix and translation vector that describes the rigid motion transformation between the point clouds. These are the primary components concerning the registration. However, this approach is prone to erroneous data and missing information, which is common in application scenarios. Additional considerations must be taken to guarantee the validity of the predicted rotation matrix. Therefore, we will follow a different approach that overcomes these limitations.

Current state-of-the-art registration architectures employ an encoder-decoder framework43,44. These models predict fully registered point clouds rather than the transformation parameters. An encoder generates a low-dimensional latent point representation that the decoder later utilizes for registration. This architecture approach is more efficient and robust due to implicit regularization. The rotation matrix and translation vector are estimated afterward using traditional RANSAC to validate the matching accuracy45.

In our opinion, the low-dimensional latent point representation has not yet reached its full potential. Modifying the latent point representation is analogous to changing the original point cloud, but with greater efficiency. We aim to update the latent point representation while preserving the existing encoder-decoder architecture. In the optimal case, point pairs can be matched one-to-one, resulting in perfect registration. However, this is not the common case in practical application scenarios. This degradation of point cloud quality poses an additional challenge for registration. Therefore, we propose point interaction (PI) modules and pay more attention to the intrinsic characteristics of point clouds.

We implement these interactions motivated by point cloud completion techniques. These compose changes to the point clouds by increasing point precision and density. However, as we do not intend to change the original point clouds, we apply these changes implicitly to the latent point representations. As a result, we can explore point cloud registration with point cloud completion. Following this approach, our method applies to any encoder-decoder architecture, as seen in the overview of our framework in Fig. 1. Our proposed point interaction (PI) modules can be incorporated into any existing encoder-decoder point cloud registration framework. We adopt two ideas originally proposed for point cloud completion and video processing, respectively. The point moving module is employed to modify the global topology of the point cloud46, and point attention offset is utilized to increase the local matching likelihood of the points using an attention mechanism49.

Inspired by the point path searching approach of the completion network PMP-Net46, we designed the point moving module (PMM) to refine the point cloud shape. Position optimization and shape optimization of the point cloud are performed using the topology information of the points. Points are gradually moved along the optimal path through a path search strategy. The original authors formulate the prediction as a deformation process using recurrent path aggregation of a modified GRU47. We modify this approach to use an adapted process similar to LSTMs48 instead. Additionally, we propose a joint version by weighting the influence of these recurrent structures.

After the point moving module modifies the whole point cloud topology, we allow for additional changes of individual points to achieve better final alignment. The PAO introduces a learnable parameter for each point to find better, closely related matches. We utilize learned parameters of the SwinTransformer’s attention mechanism to compute the offset values49.

Our proposed PI modules combine global topology information about the point clouds and local point information to refine the matching accuracy. We demonstrate how to easily integrate our modules into the two encoder-decoder networks Predator43 and GeoTransformer44 while improving their performance. In our experiments, we use the benchmark datasets 3DMatch31, 3DLoMatch31,43, and ModelNet4050. Our results indicate that enhancing the learned point representation can improve the performance of point cloud registration algorithms with a simple drop-in functionality.

Related works

Point cloud registration

Point cloud registration aims to estimate the rigid transformation regarding rotation and translation between a source and target point cloud. The optimal solution was solved with the ICP algorithm by minimizing distances29. However, the initialization decides whether the solutions can be reached at all30. Recently, learning-based methods have been shown to overcome this issue, requiring no initialization33–35.

The first group of learning-based methods splits the registration process into a multi-stage approach. Instead of relying on the point locations or handcrafted features, regression neural networks learn a descriptor of the 3D local features for later matching. These representations should include global context and semantic knowledge during the matching process. The feature extraction approach of PPF-Net51 uses local patches and computes point pair features (PPF) using Point-Net52. These anti-symmetric 4D descriptors represent the surface of a pair of oriented 3D points and are the input features with the points and point normals. However, the extracted features are sensitive to rotations. A central reference point per patch is used by the PPF-FoldNet approach to achieve a rotation invariant descriptor53. Instead of achieving one-to-one matches for these descriptors, the PR-Net approach leverages soft matching to improve accuracy iteratively54.

The second group of learning-based methods applies end-to-end trained neural networks. Thus, intermediate learned features are represented within these networks themselves55,56. A first approach combines the Point-Net architecture52 with the improved Lucas-Kanade algorithm57 for matching point clouds58. This method’s memory footprint scales with the point cloud size, thus rendering it unsuitable for large-scale scenes. DCP38 utilizes dynamic graph convolutions and attention weighting by interpreting the network as a sequence-to-sequence problem to enable more extensive scan scenes. Similarly, Deep-VCP21 introduces a feature weighting scheme with joint semantics utilizing matching via sparse point selection.

As a one-to-one correspondence between points among point clouds cannot be guaranteed, the PCR-NET33 introduces contrastive learning via a Siamese network architecture to build upon learned similarities. Other approaches change the internal network architecture to achieve similar results. DGR32 computes internal likelihood predictions via convolution, or Deep-GMR59 introduces differentiable latent Gaussian Mixture Models to enhance the registration process further. Predator43 combines self-attention and cross-attention to improve the matching effect of the low overlap state. Newer approaches follow a data-centric approach by incorporating changes to the point clouds to increase the matching accuracy. For example, 3DRegNet60 applies a classification into inlier and outlier to further improve robustness of the matching, and GT44 uses geometric converters to emphasize the learning of geometric features. In our work, we apply implicitly learned modifications to the point cloud by introducing learnable point offset vectors, thus simulating point cloud completion.

Point cloud completion via point interactions

Point interaction methods can also achieve the desired goal of improving point cloud registration by simulating point cloud completion. Such interactions are generally modeled by introducing learnable point offsets to correct positions. The point-to-point displacement network P2P-Net61 enforces a fixed cardinality by interpolating missing points with bearable displacement vectors. Inspired by image completion, missing regions using existing point cloud structures can be estimated62. Alternatively, for Folding-Net63 the missing areas are interpolated by a 2D grid along an estimated plane.

Such traditional approaches can be further combined by computing a set of optional planes based on global context information64. PMP-Net46 follows an earth mover approach, interpreting the completion as a point cloud deformation process. This learnable moving process establishes a point-level correspondence between the source and target point clouds. It captures the topological and structural relationship. The authors aggregated past movement paths and made path predictions with an adapted gated recurrent unit46,47.

In another work a bilateral confidence aggregation unit for path aggregation is introduced to handle coarse point cloud shapes65. Neural-Pull66 estimates the locations based on the network gradients. We use point interaction in the completion process to achieve a higher one-to-one mapping between the target and source point clouds. In this paper, we improve the quality of the point cloud via path moving and attention offset to improve the registration.

Method

We aim to improve the matching accuracy of encoder-decoder point cloud registration networks. Instead of modifying the initial point clouds, we utilize changes in the low-dimensional learned point representation to achieve better alignment. Therefore, we propose two drop-in point interaction (PI) modules between the encoder and decoder without changing the original architectures’ remaining parts. The point moving module (PMM) employs point cloud completion techniques to refine global topology, leveraging path searches with recurrent neural networks. On the other hand, point attention offset (PAO) introduces a learnable offset parameter for each point. It exploits local context via a self-attention mechanism49,67.

Encoder-decoder architectures

Current state-of-the-art registration methods build upon an encoder-decoder architecture39,42,44,68. These models predict fully registered point clouds rather than the transformation parameters. That is, they learn the transformations implicitly. An encoder generates a low-dimensional latent point representation that the decoder later utilizes for registration. Thus, we define the latent point representation as \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$l \in \mathbb {R}^{L \times C}$$\end{document} created by the encoder component. Exact values for L, the number of points, and C, the feature dimension, depend on the underlying architecture. Consequently, to achieve the drop-in capabilities of the point interaction modules, we leave the dimension of the latent representation unchanged.

In our work, we focus on the highly influential architectures Predator43 and GeoTransformer44. Each of them creates a different latent representation. One combines the two input point clouds into one representation, leading to a larger L. The other one generates separate representations for both input point clouds. We apply our PI modules to each representation individually. Thus, our drop-in approach should allow us to amplify the existing ideas of the models by just refining the latent point representation.

Point moving module

As a first step of refining the latent point representations inside the encoder-decoder architecture, we attempt to correct the global point cloud topology. We employ recurrent path aggregation (RPA) for point cloud completion introduced in PMP-Net46 as the core concept of our PMM. The optimal location change for each point should be found iteratively based on its update path and those of neighboring points. A new location is selected from a set of options defined by aggregating other paths. A given radius limits the search area.

In the original work, RPA gradually reduces the search radius along the path46. It adapts the gating mechanism of gated recurrent units (GRU)47 to compute the optimal location at each step. For the remainder, we will refer to such a module as aGRU (adapted GRU). In each step, three independent aGRUs are used in a consecutive manner, modeling an iterative three-level refinement process. According to the authors, this approach enables global deformations of the whole point cloud to be considered in each point location update46. We believe that this technique is also beneficial during point cloud registration. Contrary to the point cloud completion approach, we apply RPA to the low-dimensional latent point representation after the encoder component.

We were inspired by the gating structure within the point-movement layer of PMP-Net46, instead of GRU, we use an adapted process similar to an LSTM module48 (referred to as aLSTM). Recurrent path aggregation

The recurrent path aggregation mechanism46 includes set abstraction (SA), feature propagation (FP), and updated gating units. The first two components were originally introduced with PointNet++69, where SA works as a down-sampling and FP as an up-sampling method, respectively. For SA local vectors are formed by grouping according to the centroid neighborhood. Feature extraction of local vectors reduces losses during maximum pooling operations. FP uses inverse distance weighted average based on K-nearest neighbor to interpolate and propagate features. Aggregation units help the network move points with memory. We refer to the original works for a detailed explanation of RPA.

Updated gating

The updated gating mechanism generates and processes the information on how the point needs to move at each step. PMP-Net46 adapts the GRU structure to fit the point cloud features (aGRU). Instead, we propose an adaptive LSTM unit to update the gating. We rearranged the flow paths of the input and output, and followed PMP-Net46 by replacing tanh with ReLU in the two hidden state parts to treat small and large location updates equally.

Influence control

The two most common gating structures, GRU and LSTM, respectively aGRU and aLSTM, have different advantages and disadvantages67. GRU-based structures offer a simpler architecture, reducing computational complexity and making them well-suited for scenarios with limited data. In contrast, LSTMs possess stronger information filtering abilities to overcome the vanishing gradient problem and are more effective for large datasets. At the same time, they are prone to over-fitting48,70,71. Data availability, quantity, length, and computational requirements influence the choice between GRU and LSTM architectures. Point attention offset

Adding new points can also boost registration accuracy by increasing match opportunities. Note that, as we work with the lower-dimensional point representation l, adding actual points is infeasible in our case. Instead, we add points implicitly. Specifically, we propose to shift existing points to increase the matching likelihood slightly. To do so, we introduce a learnable offset parameter based on location information, utilizing the attention mechanism introduced in the transformer architecture72.

We utilize a relative position bias b, which is sampled from a truncated normal distribution. It is added to the original attention mechanism. Given the additional bias parameter \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$b_n \in \mathbb {R}^{d \times L \times C / d}$$\end{document}, we get the original attention definition72:9\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\begin{aligned} a_n = \text {softmax}\left( \frac{Q_n \cdot K_n^{T}}{\sqrt{d}} + b_n\right) \cdot V_n\,, \end{aligned}$$\end{document}where \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$b_n$$\end{document} is sampled from a truncated normal distribution \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\mathcal {N}(\mu =0.0, \sigma ^2=0.2,a=-2,b=2)$$\end{document}. Please note that the PAO module can be used multiple times, denoted by the index n. In our experiments, we investigate \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$n=\{0,1,2\}$$\end{document}. During training, we use 20% dropout for stabilization.

The final step of the point attention offset module computes the offset from attention results. The refined point representation, denoted as \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$l_o \in \mathbb {R}^{L \times C}$$\end{document}, is computed as10\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\begin{aligned} {l_o} = l_{i} + \sigma _{\text {sig}}(a_n) \cdot l_{i}\,, \end{aligned}$$\end{document}where \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\sigma _{\text {sig}}(\cdot )$$\end{document} again represents the sigmoid function, limiting the range of possible modifications. Each latent point is shifted according to the attention mechanism to improve the likelihood of matches in the decoder component of the architecture.

Optimization

We follow43 and use a combination of circle loss \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\mathcal {L}_{\text {c}}$$\end{document} and overlap loss \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\mathcal {L}_{\text {o}}$$\end{document} to train the encoder-decoder models. Circle loss73 is a variant of the triplet loss that consists of two parts: Given two overlapping point clouds \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\textbf{P}$$\end{document} and \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\textbf{Q}$$\end{document}, \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\mathcal {L}_c^\textbf{P}$$\end{document} is the loss for direction \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\textbf{P}\rightarrow \textbf{Q}$$\end{document} and \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\mathcal {L}_c^\textbf{Q}$$\end{document} is the reverse direction. Both are combined in a weighted sum:11\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\begin{aligned} {\mathcal {L}_{\text {c}}} = {\gamma _c}{\mathcal {L}_c^\textbf{P}} + {(1-\gamma _c)}{\mathcal {L}_c^\textbf{Q}}\,, \end{aligned}$$\end{document}where \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\gamma _c=0.5$$\end{document}. Similarly, the overlap loss \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\mathcal {L}_{\text {overlap}}$$\end{document} introduced in43 has the two parts \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\mathcal {L}_o^P$$\end{document} and \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\mathcal {L}_o^Q$$\end{document}, which are combined as:12\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\begin{aligned} {\mathcal {L}_{\text {o}}} = {\gamma _o}{\mathcal {L}_o^\textbf{P}} + {(1-\gamma _o)}{\mathcal {L}_o^\textbf{Q}}\,. \end{aligned}$$\end{document}This loss is based on the binary classification error between the two overlapping point sets. The weighting parameter \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\gamma _o$$\end{document} is set to 0.5 in all experiments.

Based on these two loss terms, the final loss \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\mathcal {L}$$\end{document} can be represented as13\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\begin{aligned} \mathcal {L} = \gamma \mathcal {L}_{\text {c}} + (1 - \gamma ) \mathcal {L}_{\text {o}}\,, \end{aligned}$$\end{document}where \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\gamma =0.5$$\end{document}. It is worth noting that our point interaction modules do not require any additional loss terms.

Implementation details

Our implementation preserves the original hyper-parameters of both Predator43 and GeoTransformer44, ensuring comparable results to their default configurations. Hence, the latent point representation has a feature dimension of \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$C=256$$\end{document}. In our experiments, for PMM we set the size of the hidden state of aGRU and aLSTM to \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$k_{size}=\left\{ B, 256, P\right\}$$\end{document}. Furthermore, the location refinement for points in PMM is repeated \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$N=3$$\end{document} times. For the PAO, we set the conversion factor to \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$d=8$$\end{document}, following the original SwinTransformer49. Since GeoTransformer generates a unique latent point representation for each input point cloud, we employ dedicated PMM and PAO modules for each representation, individually.

For the fairness of the experiment, we chose the same parameter settings as the authors43,44. They are the optimal settings the authors found for their networks. For our experiments on 3DMatch, each network was trained for 40 epochs with an initial learning rate of 0.005 for Predator, 0.0001 for GeoTransformer, exponentially decaying by 0.05 after each epoch. For ModelNet40, each network was trained for 200 epochs with an initial learning rate of 0.01 for Predator, \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$10^{-5}$$\end{document} for GeoTransformer, exponentially decaying by 0.02 for Predator, 0.05 for GroTransformer after each epoch. We used SGD as optimizer for Predator and Adam74 for GeoTransformer. We utilize PyTorch for model implementation and experiment design75.

Experiments

We conducted experiments on 3DMatch31, with an additional artificial low-overlapping version, and Model40Net50 datasets, and compared the results with related works. To verify the effectiveness of our module, we carried out additional ablation studies. For them, we used a smaller version of 3DMatch to repeat the number of experiments multiple times.

Experimental setup

Datasets

3DMatch is the most widely used point cloud registration dataset for real indoor scenes31. Its point clouds were obtained from the reconstruction of RGB-D images collected from other datasets. In total, more than 200, 000 RGB-D images were processed into point cloud format. The reconstructed datasets were captured in different environments at different scales with different local geometries and created using different reconstruction algorithms. There are 62 scenes in the raw data, 54 for training, and 8 for evaluation. We used the pre-processed pipeline data from Predator43. The overlap of the point cloud pairs was greater than \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$30\%$$\end{document} in 3DMatch and less than \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$30\%$$\end{document} in 3DLoMatch.

ModelNet4050 is a synthetic dataset made of CAD models. It contains 12, 311 shapes with alignment information for 40 categories. Each shape is randomly sampled with 2048 points and normalized to the unit sphere. They are split into 9, 843 samples for training and 2, 468 for testing. However, we followed76 for the evaluation procedure. Training and testing data of the first 20 categories are used for training and validation, respectively. The test data of the remaining 20 categories is used for testing in our experiments. In total, this results in 5, 112 examples for training, 1, 020 examples for validation, and 1, 266 examples for testing.

Metrics

For evaluation, we follow common practices and use the metrics reported with 3DMatch31: Registration Recall (RR), Inlier Ratio (IR), Feature Matching Recall (FMR), Relative Translation Error (RTE) and Relative Rotation Error (RRE). Higher values of RR, IR, and FMR are better, while lower values of RTE and RRE are better. RR is the percentage of correctly registered point cloud pairs. It is based on the root mean square error (RMSE) of individual points i:14\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\begin{aligned} RR = \frac{1}{M}\sum \limits _{i = 1}^M {({RMSE}_i < {\tau _1})}~~, \end{aligned}$$\end{document}where M is the number of points and \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$${\tau _1}$$\end{document} is a threshold, that has to be specified. We follow previous works31,43,77,78 and set it to 0.2. Analogously, IR represents the fraction of inlier matches using mean square error (MSE). The involved threshold is set to 0.131. Then, FMR is the final result of the registration success ratio calculated by IR:15\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\begin{aligned} FMR = \frac{1}{M}\sum \limits _{i = 1}^M {(IR > {\tau _2})} \end{aligned}$$\end{document}where the threshold \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$${\tau _2}$$\end{document} is set to 0.0531,43.

Finally, RRE and RTE are metrics for the quality of the estimated rotation matrix \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\hat{R}$$\end{document} and translation vector \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\hat{t}$$\end{document} in comparison to their respective ground truths R and t. Specifically, RRE computes the geodesic distance between the rotation matrices, and RTE the Euclidean distance between translation vectors:16\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\begin{aligned} RRE&= \arccos (\frac{{\text {trace}({\hat{R}^T R}) - 1}}{2})\,,\end{aligned}$$\end{document}17\documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$\begin{aligned} RTE&= {\left\| {\hat{t} - t} \right\| _2}\,. \end{aligned}$$\end{document}We refer the reader to the literature for a more detailed description of those metrics.

Conclusion

The primary challenge in point cloud registration stems from the inherent noise and variability in point cloud scans. To overcome this issue, we incorporated ideas from another processing task, namely point cloud completion. Specifically, we proposed two drop-in modules for encoder-decoder registration architectures focusing on point interactions. First, our point moving module, inspired by the recurrent path aggregation idea of PMP-Net46, optimizes the global cloud topology. Second, our point attention offset module utilizes a learnable offset parameter based on the local information to increase the likelihood of point-to-point matches. Given this idea, we can improve the low-dimensional point representation in these encoder-decoder frameworks.

In our experiments, we were able to elevate the performance of both the Predator43 and GeoTransformer44 models, requiring no changes to the original parameters or training regimen. While our modules exhibit improved performance on 3DMatch scenarios with high overlap and distinct objects, they do not demonstrate a notable enhancement in cases with low overlap, reflecting the complexity of the underlying problem. Our modular design creates the potential to enhance learned point representations inside any encoder-decoder architecture. Furthermore, it can be applied iteratively. Future work will focus on developing improved completion-based registration techniques, particularly improving low-overlap scenes. Even under uncertain conditions, enhancing point cloud quality in such scenarios will remain an important research objective.
