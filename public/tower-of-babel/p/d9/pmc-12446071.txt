Scvi-hub: an actionable repository for model-driven single-cell analysis
Authors: Can Ergen, Valeh Valiollah Pour Amiri, Martin Kim, Ori Kronfeld, Aaron Streets, Adam Gayoso, Nir Yosef
Published: 2025

ABSTRACT
The growing availability of single-cell omics datasets presents new opportunities for reuse, while challenges in data transfer, normalization and integration remain a barrier. Here we present scvi-hub: a platform for efficiently sharing and accessing single-cell omics datasets using pretrained probabilistic models. It enables immediate execution of fundamental tasks like visualization, imputation, annotation and deconvolution on new query datasets using state-of-the-art methods, with massively reduced storage and compute requirements. We show that pretrained models support efficient analysis of large references, including the CZI CELLxGENE Discover Census. Scvi-hub is built within the scvi-tools open-source environment and integrated into scverse. Scvi-hub offers a scalable and user-friendly framework for accessing and contributing to a growing ecosystem of ready-to-use models and datasets, thus putting the power of atlas-level analysis at the fingertips of a broad community of users.

Main

Machine learning models have been central to efforts to catalog cell states in health and disease with single-cell omics technologies1–3. These models are able to perform a variety of analysis tasks including dimensionality reduction, differential expression comparison, automated cell-type annotation, denoising, deconvolution of spatial data and modality imputation3. With the growth of single-cell data corpora, transfer learning will be an essential technique for accomplishing such tasks by leveraging large-scale datasets as reference atlases in a computationally efficient and performant manner. At present, transfer learning is primarily used for projecting cells onto a common low-dimensional representation that is used for tasks such as annotation or trajectory inference4–6. However, moving forward, additional applications will become more prevalent, such as interpretation of spatial data7 prediction of perturbation outcome8, prediction of multimodal information from single-modality data9, detection of anomalous cellular subsets10 or analysis of differential expression11.

Methods for transfer learning in single-cell omics broadly fall into two categories: non-parametric and parametric. In the non-parametric case, the algorithm uses the reference data directly to remove unwanted sources of variation. For example, Seurat and FastMNN integration utilize mutual nearest neighbors between reference and query data to remove query-specific effects6,12. In the second case, the algorithm uses a parametrized model like a conditional variational autoencoder to reduce the dimension of the reference data as well as remove unwanted variation. This same model can then be leveraged to project new data onto the same low-dimensional space. This approach is used by methods like scVI + scArches4,13,14, and can be efficiently designed, so that at query time only the query dataset is used, and not the original, potentially large, reference dataset. These models can regenerate normalized raw count data with high fidelity from the low-dimensional representation and can be used to analyze the reference data in its original dimension (for example, at the gene level), when only provided with a much smaller (lower dimension) representation of that data.

While parametric approaches have successfully been used in large-scale analyses15,16, there remain challenges with realizing the power of reuse of trained models. First, models can be trained using a variety of machine learning libraries and frameworks or use different versions of the same library, making them difficult to quickly ingest and use. Second, there is no standard for how pretrained models should be deposited, which limits reuse to knowledge of a particular publication or model deposition. Finally, it can be difficult to assess the quality of a pretrained model without standardized summary statistics of key performance metrics.

To address these issues, we introduce scvi-hub, a platform for sharing and reusing single-cell machine learning models that are implemented in the scvi-tools codebase14. Scvi-hub provides access to various popular single-cell model architectures spanning the core data analysis tasks, as well as to any future models that will be implemented using the developer API of scvi-tools (for example, refs. 4,17,18). Scvi-hub facilitates model sharing through the Hugging Face Model Hub, which offers an efficient, version-controlled and feature-rich programmatic and user-facing interface. Scvi-hub also works with models deposited in cloud-based buckets like AWS S3. Scvi-hub provides functionalities that cater to both model consumers and model contributors. To the former community, it offers streamlined access to a variety of downstream analysis tasks using the downloaded models. Many of the downstream tasks are also made available in a form that relies on a low-dimensional (minified) version of the reference data (rather than the complete count matrix). This leads to a substantial decrease in requirements for data storage and download bandwidth, thus increasing accessibility and inclusion within the data analysis community. Scvi-hub also offers a collection of tools to enable comparison and evaluation of models before uploading (by contributors) or before use of models for a specific analysis (by consumers) as well as a streamlined API for model upload and update (for contributors).

We demonstrate the utility of scvi-hub in a range of applications. One set of use cases considers reference-based analysis of query datasets—for annotation, differential analysis and deconvolution. A second set of use cases considers only the reference, demonstrating the merit of tissue atlases as resources for making new discoveries. We have seeded scvi-hub with a collection of more than 90 models pretrained on a variety of tissues and experimental conditions from the Tabula Sapiens consortium16 and other large projects (see https://huggingface.co/scvi-tools/). Scvi-hub also provides fully featured access to the CELLxGENE Census collection—the largest corpora of single-cell omics datasets assembled to date (mouse and human data at s3://cellxgene-contrib-public/models/scvi).

Results

Reusing models pretrained on single-cell datasets

For the community of contributors, scvi-hub provides features that facilitate both evaluation and sharing of models (Fig. 1). Since all core models in scvi-tools are generative (that is, capable of simulating new data), scvi-hub uses posterior predictive checks (PPCs)19 with model-simulated data to evaluate how well it captures the characteristics of the original input data. Here we implemented previously described metrics like the coefficient of variation20,21 and differential expression-based metrics (Methods). To share models, scvi-hub leverages the Hugging Face Model Hub, which is a popular platform for sharing and using machine learning models from diverse domains, including natural languages, images and audio. The Hugging Face Model Hub has features that make it ideal for single-cell genomics. One component of this is model discoverability, enabled via an advanced search interface and a uniform documentation and presentation with Model cards (description files that accompany and provide information on the uploaded model). Additionally, the Hugging Face Model Hub provides features for maintaining consistency and backward compatibility through built-in Git-based version control.

Model contributors have the option to share the data behind their model, enabling downstream analysis (examples in Figs. 2 and 3). The data can be uploaded either in its raw form (count matrix) or in a substantially reduced form, using a new feature we refer to as ‘data minification’. The low-dimensional posterior parameters of the data can be converted into an approximated and normalized form of the original data, using the generative part of the model. This feature provides a compressed representation of a reference dataset, while still enabling much of the same functionality as with the raw data (Fig. 3). As an example, in scVI, which is based on a conditional variational autoencoder, the minified data would be the latent space coordinates (mean and variance) of each cell. Notably, the capability of working directly with minified data is becoming essential, as current atlas-level projects contain information on millions of cells, and analysis of those datasets has, therefore, been inherently tied to high-performance computing resources. Data minification results in significantly less memory requirements and speeds up generation of expression values (Supplementary Fig. 1), thereby enabling investigation of large-scale atlases on conventional hardware.

The second set of users scvi-hub caters to are model consumers, who wish to analyze existing (reference) datasets or leverage reference datasets to analyze their own (query) data. Model consumers begin by searching and downloading their desired reference model and, if needed, its corresponding data in either minified or raw form. These steps can be done either through the Hugging Face website or directly through the scvi-hub Python API (which internally uses the Hugging Face API). Since scvi-hub is part of the scvi-tools package and the scverse ecosystem23, consumers can seamlessly integrate the downloaded models into existing analysis workflows, which provide a slew of functionalities for exploration, visualization and analysis. Extensive tutorials exist to work with scvi-hub in the R ecosystem as well, thus supporting downstream analysis with Seurat24 and other popular environments.

In the following sections, we describe the functionalities for model criticism, which can be used by both contributors (before uploading their models) and consumers (to check existing models before conducting analysis). We then describe the functionalities that are available for consumers through their downloaded models, including both analysis of the reference data (using its minified form) and analysis of user-provided data.

Evaluation to select models and test their suitability

Model evaluation is a key feature of scvi-hub, enabling contributors to assess models before uploading and users to judge their relevance and quality. To support this, we developed scvi.criticism, a module for evaluating models trained with scvi-tools. It implements PPCs, which compare statistics from model-generated data to those from the observed data21,19. Specifically, we compute gene-level and cell-level coefficient of variation and differential expression and assess their similarity. A close match indicates a well-trained model.

To demonstrate this, we computed PPC on the Human Lung Cell Atlas (HLCA) dataset25 using the author-provided scANVI model (Fig. 2a,b). The model captured the distribution of observed gene expression well, recovering similar differential expression patterns and even marker expression for regulatory T (Treg) cells, which were not annotated in the original dataset. This shows how pretrained models can recover fine-grained cell types via generated counts (Fig. 2a–f and Supplementary Fig. 2).

Contributors can use scvi.criticism to compare candidate models (for example, with different hyperparameters) and include these evaluations in the Model card on Hugging Face. This is particularly helpful for models provided with minified data, where raw counts are unavailable and can provide confidence in the reliability of these generated counts. We illustrate this using the Heart Cell Atlas26, comparing a well-trained model, two poorly trained models and one overfit model (Extended Data Fig. 1 and Methods). Cell-wise coefficient of variation correlations with raw data showed the well-trained model outperformed poorly trained models, while the overfit model failed to generalize to validation cells. Differential expression comparisons echoed these results: well-trained and overfit models performed better than poorly trained ones. When cell-type labels were unavailable, we used Leiden clustering for differential expression analysis and find comparable results and conclude that Leiden clusters can be used instead of cell-type labels (Extended Data Fig. 1e,f).

Another key use of scvi.criticism is evaluating how well a reference model fits a new query dataset. We analyzed epithelial cells from Tabula Sapiens using the HLCA scANVI model as a reference (Extended Data Fig. 2). We projected the data using scArches4, and then compared model-generated and real expression values. Reassuringly, we observed good performance on lung epithelial cells and airway epithelial cells. These organs are all included in the HLCA reference dataset. For tissues that are not represented in the HLCA, we found substantially worse correlation, indicating that the model does not capture their underlying distribution of gene expression well. Therefore, criticism allows detecting reference models that are well suited for the query dataset at hand.

Scvi-hub can also be extended to multimodal data. For this purpose, we used the flexible MuData structure, which stores each modality separately21,27. We demonstrate this application using minified models for totalVI that jointly models protein expression and RNA21. To highlight its functionalities, we performed an analysis of a large-scale CITE-seq dataset of peripheral blood mononuclear cells in individuals with coronavirus disease 2019 (COVID-19)28. We found a good preservation of cell types in totalVI’s latent space (Extended Data Fig. 3a) and found for RNA a high Pearson correlation of both models generated; while for protein expression, we found a lower correlation between both metrics (Extended Data Fig. 3b). TotalVI corrects for unspecific background in CITE-seq measured protein expression; therefore, we expect a lower coefficient of variation and recommend using the corrected estimates as highlighted in the totalVI manuscript.

Efficient exploration and reanalysis of reference datasets

The first set of analyses facilitated by scvi-hub is centered on the reference datasets, without inclusion of any additional (query) information. This approach allows for rapid exploration and reanalysis of reference atlases. After searching for a model that fits the user’s specification on Hugging Face (that is, tissue, cell types and a modeling scheme, such as scVI and DestVI), model consumers can pull (download) the model and its corresponding data. Analysis of reference datasets includes operations that concern the low-dimensional (latent) representation of cells, such as visualization, clustering, trajectory inference and differential abundance analysis. Additionally, model consumers can perform analyses at the high-dimensional, omics measurement level by accessing the raw data or by generating count data using the minified format. These high-dimensional representations can then be readily analyzed.

Downloading minified data and the pretrained model therefore allows preservation of information (compared to downloading raw data) but also the reliance on a much smaller dataset. This permits fast interaction with the data using all downstream capabilities offered by Scanpy or Seurat, and also all built-in functions in scvi-tools (for example, for differential expression11). As scvi-hub stores the link to the full data object by invoking a single-line function call, the full data can also be downloaded and findings made on minified data can be validated on the full raw data.

Reference-based analysis of query data by transfer learning

The most fundamental part in analyzing a query dataset given the appropriate reference is to represent the query data using the reference model. In the context of scvi-tools, this is done by calculating the coordinates of each query cell in the latent space of cell states that is encoded by the model and that is initially populated by the reference cells (Fig. 2b). While the encoder networks in scvi-tools can readily provide latent representation for any query cells, these representations might be distorted by batch effects. An efficient way to address this is to perform minimal training only to capture these batch effects while leaving the model otherwise unchanged. This procedure, which is implemented by scArches4, effectively produces a joint embedding of the reference and query dataset. Such joint representations can be leveraged for a variety of downstream tasks that are readily available through scvi-hub. Here, we demonstrate the capabilities of scvi-hub to analyze query data with transfer learning, through four such fundamental tasks: visualization, annotation, comparative analysis and deconvolution.

As a first test case, we used a query dataset of three healthy individuals and three individuals with emphysema29 and designated the HLCA as the reference. The two datasets (query and reference) are well integrated with use of scArches, leading to an informative, reference-informed, visualization of the query data (Fig. 3a,b). To annotate the states of cells in our query, we transferred labels from HLCA using a simple k-nearest-neighbors classifier (using the reference embedding in the joint latent space to identify k-neighborhoods; Fig. 3c and Supplementary Fig. 3). We found that the reference-based annotation is consistent with the labels provided by the original study of the query dataset, yet it adds a great deal of resolution. For instance, cells that were originally labeled as endothelial cells were now divided into venous systemic, venous capillary, arterial and aerocyte capillary (Supplementary Fig. 3a,b).

The probabilistic representation facilitates comparative analysis within the query dataset. We use Milo (which relies on the integrated embedding space) to compare the composition of cell states in the three healthy query samples versus the three emphysema-affected samples. We found a significant (false discovery rate (FDR) < 10%) and reproducible increase in the abundance of certain states of fibroblasts in the emphysema samples (Fig. 3d and Supplementary Fig. 4a,b). To get more insights on the shift in cell states, we next used the differential expression function in scvi-tools to explore disease-associated gene expression changes (Fig. 3e). We found that fibroblasts in individuals with emphysema upregulate pro-inflammatory chemokines that attract neutrophils (CXCL1/CXCL2/CXCL8) and monocytes (CCL2, CSF3).

The original publication highlighted the role of fibroblasts in inducing a niche for resident memory T cells, further corroborated by the fact that depletion of fibroblasts in a mouse model led to a decrease in resident interleukin-17-producing helper T cells. Therefore, our reference-powered analysis highlights additional putative mechanisms associated with neutrophils and monocytes. Indeed, neutrophils release granule proteins like neutrophil elastase and myeloperoxidase and have thus been associated with emphysema30. Similarly, monocyte-derived macrophages produce metalloproteinases leading to tissue remodeling in emphysema31.

When comparing these insights to differentially expressed genes identified with pseudobulk differential expression analysis or training a scANVI model from scratch (Methods), we were not able to identify the same gene signature (Supplementary Figs. 5 and 6). When validating our findings in raw gene expression, we found substantial interindividual variation especially in the control samples (Fig. 3f and Supplementary Fig. 6). Clinical metadata is scarce for healthy controls in the original study and it is not clear whether this deceased donor had any ongoing infection that might explain expression of pro-inflammatory cytokines. Small datasets with few individuals (three donors per group) have limited power to detect disease-specific changes and ideally results should be confirmed using orthogonal assays or a larger cohort.

Another area of single-cell genomics where a form of transfer learning can be used to gain new insight is spatial transcriptomics. Since the resolution of most sequencing-based spatial transcriptomics protocols is at a level coarser than a single cell, deconvolution is needed to estimate the cellular composition of each measurement unit (often referred to as a spot). Algorithms such as DestVI7 and Stereoscope32 were developed to leverage models that are pretrained on non-spatial single-cell RNA-sequencing (scRNA-seq) datasets to perform such deconvolutions. Scvi-hub users can download the scRNA-seq parts of DestVI (CondSCVI) and Stereoscope models and deconvolve their spatial data. We demonstrate this using a spatial dataset of a human prostate, generated with 10x Visium technology33. DestVI using a pretrained model on prostate data from Tabula sapiens distinguishes prostate glands and stromal regions (Extended Data Fig. 3). Beyond deconvolution, the use of DestVI estimates cell-type-specific gene expression inside each relevant spot, thus opening the way for downstream analysis such as comparing how cells of the same type differ between tissue areas7.

Infusing new insights from query-to-reference datasets

The joint embedding of query and reference datasets can also be used for an additional, less prevalent procedure, which we termed label infusion. While reference atlases tend to include large numbers of samples and cells, their levels of annotations can be limited in granularity, at least for some compartments. Conversely, other more narrowly focused datasets may provide higher resolution. By reannotating reference datasets, fine cellular subsets can be identified and their function in disease contexts can be better studied leveraging the power of the reference dataset.

We demonstrate label infusion by refining the cell-type labeling of natural killer (NK) and T cells in the HLCA dataset (Fig. 3g). We used a recent study of immune cells across different organs34, subsetted this study to only NK and T cells across all different organs, and integrated the resulting ‘query’ dataset with the HLCA reference. After integration with scArches, we confirm that the query cells are well integrated with NK cells and T cells of the reference dataset. The joint embedding then helped us infuse labels from the query to the reference (Fig. 3h). This analysis confirmed the presence of Treg cells in the HLCA (Supplementary Fig. 7). We further validated other infused cell-type labels by checking their canonical cell-type marker genes (Fig. 3i). For instance, we confirmed that the cells relabeled as naive T cells indeed express the highest level of CCR7. In addition, we used scTriangulate35 and found that most infused labels are predicted to be an improvement over the original labels (Supplementary Fig. 8).

To demonstrate how infused labels can provide additional insights, we focused on a subset of cells that we reannotated as CD8+ resident memory T cells (labeled as TEM/TEMRA CD8 in Fig. 3h). Because the HLCA includes samples from individuals with COVID-19 in addition to healthy donors, we analyzed effects of infection on this more narrowly defined immune subset. Markers of exhaustion of CD8+ T cells (LAG3, CD38, TIMD4 and HAVCR2) and interferon-regulated genes (GBP2, MX1, MX2, IFI16, XAF1, SAMD9L and IFI44; Fig. 3j) were upregulated, both of which are consistent with recent, more targeted, studies of COVID-19 infection36,37.

Scalable access to CZ CELLxGENE Discover Census

Large single-cell omics collections, like the CELLxGENE Census (CZI, 2023), enable a comprehensive view of cell types and states in various tissue contexts, thus starting to realize the potential of the cell atlases38. The census includes over 30 million human cells across diverse tissues, diseases and conditions. Instead of requiring a specific reference dataset, users can now compare queries against the full census—in a manner reminiscent of searching DNA sequences in a reference genome.

To showcase scvi-hub’s utility with census-scale data, we use an scVI model trained on the entire census, managed by the CELLxGENE Census team and updated regularly. This model is available through scvi-hub, thus providing a way for users to leverage this ever-growing resource that spans diverse populations, tissues, disease contexts and cell subsets (https://chanzuckerberg.github.io/cellxgene-census/). While the full dataset requires 500 GB and hours to download, its minified model form is just 30 GB and downloads in under 30 min, significantly lowering compute and bandwidth barriers for leveraging this potentially transformative resource.

We analyzed a chimeric antigen receptor T (CAR T) cell dataset39, where scRNA-seq was performed on infusion bags from 24 individuals treated with anti-CD19 CAR therapy. These bags contain diverse CAR T cell states, and linking them to treatment response can inform prognosis and guide therapy optimization40.

Using scArches via scvi-hub, we mapped the CAR T dataset onto the census without needing to retrain on the remaining 30 million cells. Model criticism revealed good agreement between predicted and observed coefficient of variation, except for low-quality cells with high mitochondrial/nuclear RNA content (Fig. 4a and Supplementary Fig. 9). The query integrated well into the census immune subsets. For cell-type annotation, we used a high-quality immune cell reference from the census34, and a k-nearest-neighbors classifier on the latent space. We here used a very broad reference dataset spanning the whole CELLxGENE Census as no appropriate reference dataset for CAR T cells existed. We further scrutinize our approach by using a reference model trained only on a cross-organ immune cell atlas34. This approach labeled the same cells as myeloid cells (dendritic cells and macrophages; Supplementary Fig. 10). However, within T cells we found that the model trained on the full CELLxGENE Census better preserved the original distinction between CD4+ and CD8+ T cells that was experimentally verified39. Therefore, we conclude that for studies that are substantially different from a reference dataset, using a census-wide model still allows accurate reference mapping and can be used for cell-type label transfer.

The census-embedded and reannotated representation of the reference data opens a way to further study the association between responses to CAR therapy and the composition of the infusion products. To this end, we applied Milo41 on the embedding coordinates of the query dataset to identify cell subsets that are associated with poorer responses. We found that terminally differentiated CD8+ T cells and Treg cells are associated with reduced response (FDR < 10%; Fig. 4e). The findings on terminally differentiated CD8+ T cells align well with the results in the original study, which reported a subcluster C1 with markers of exhaustion in partial responders. The findings on Treg cells also agree with previous reports about negative association between their concentration in the circulating CAR population after infusion, and the success of CAR therapy42. We additionally used milo to identify cell states that are significantly (FDR < 10%) associated with cytokine-release syndrome (CRS), which is the most common and potentially life-threatening adverse reaction to CAR T therapy. We identified a subset of CD8+ T cells with high proliferation (MKI67 positive) and expression of CCR7 to be negatively associated with CRS (Fig. 4f). In addition, these cells express higher levels of GZMB, GZMA, LAG3 and CCL5 compared to naive CD8+ T cells (Leiden cluster 2; Fig. 4g,h). We have therefore demonstrated that our reference-based analysis can uncover new cell states associated with treatment response and negative side effects, while reducing manual optimization of various hyperparameters.

Surprisingly, our reannotation also identified a population of dendritic cells that are positive for CCR7, CCL17 and CCL22 not identified in the original study (Fig. 4d and Supplementary Fig. 9). Dendritic cells are not meant to be included in the infusion products. However, overexpression of CCR4 on CAR T cells, which interacts with CCL17 and CCL22, has been demonstrated to increase efficiency of T cell treatment43, suggesting a potential beneficial effect in co-stimulation of T cells with activated donor-derived dendritic cells.

Label infusion to the CELLxGENE Census datasets additionally allows the study of specific cell types across diverse conditions and tissues. We performed label infusion to identify Treg cells in the census dataset. We identified 300,000 Treg cells and linked an activated state with cancer across diverse tissues (Supplementary Information and Extended Data Fig. 5). Comparative studies across diseases and tissues will facilitate identifying common disease patterns in the future.

Discussion

With the growing corpus of single-cell omics datasets, including atlas-scale efforts, transfer learning has become pivotal for analyzing new and revisited datasets. Yet, adoption remains limited for two main reasons: first, large reference datasets require significant computing resources and integration expertise; second, there is a lack of a platform to facilitate communication and infrastructure to support quality control, and data access between data providers and users. scvi-hub addresses these challenges by providing a platform for sharing not only single-cell data but also pretrained models. The sharing of models helps lower the need for technical expertise and expensive computing resources (for example, to process atlas-scale references and integrate them with query data) and the respective API was designed to facilitate a wide array of analyses.

The decentralized nature of scvi-hub—leveraging Hugging Face and AWS S3—enables broad community access through user-friendly interfaces. We envision three main user groups: (1) individual researchers sharing data and making analyses reproducible after publication, (2) large-scale atlas efforts using it for advanced analysis and (3) researchers using pretrained models for tasks like cell-type annotation or spatial deconvolution. To demonstrate this, we presented several case studies showing that incorporating external references can improve and enrich the analysis of individual datasets and provide new insights into disease mechanisms and the pertaining effects on cell-type composition and gene expression.

The model-centric approach of scvi-hub enables representation of large reference datasets in a minified format, which enables access with limited memory resources or download bandwidth and thereby accelerates access to those valuable resources. We demonstrate how high-quality gene expression data can be generated from these latent codes. Models within scvi-tools require limited computing resources and inference can be executed on a CPU. This sets these models apart from recent foundational models such as Geneformer or scGPT that require dedicated computing resources and do not generate count data that can be used for downstream analysis44,45. Recently, scPrint was proposed, a model that can generate count data and allow efficient query mapping; however, scvi-tools-based models outperform it in terms of efficiency and integration performance46. We hope scvi-hub broadens access to single-cell analysis, especially for those with limited resources. Validating findings in the original expression space, however, is key and training models using generated data might lead to biased models. Scvi-hub can serve as a central gateway to data repositories, like CELLxGENE Discover47, which allows users to access selected portions of very large datasets (for example, genes or subpopulations highlighted by the model-based analysis) for close inspection. We highlight this capability by reanalyzing an existing CAR T dataset. We highlight label harmonization by identifying a Treg population shared across all types of cancer well represented in the current repository. Challenges remain—for example, metadata often mislabel stimulated cells as healthy or tissues with unrelated diseases. Annotation harmonization, as pursued by projects like HuBMAP48, will be key to enabling more reliable cross-study analysis.

To make scvi-hub a valuable resource for the community and improve model-based analysis of single-cell sequencing studies, we provide tutorials in Google Colab highlighting step-by-step guides of common analysis steps. The aim of scvi-hub is to provide a homogeneous API to the user and facilitate easy access to reference models. To enable this simple API, it is limited to models within the scvi-tools framework and does not extend to other single-cell models like Geneformer or scGPT44,45.

An important part of the interface between data providers and consumers is the ability to criticize and reach informed decisions about the merit of a given reference model. We introduce scvi-criticism, a tool for assessing models before uploading and for determining how well a query dataset fits a reference. The purpose of criticism is merely to compare different models on the same dataset instead of discarding the best model for a specific dataset. However, we aim for a cell-wise coefficient of variation r2 above 0.4 and a marker gene overlap (measured with F1-score) between model-generated and observed expression beyond 80%. If no suitable reference exists, we show that models trained on the CELLxGENE Census generalize well, for example, enabling detection of dendritic cells in CAR T cell data.

Scvi-hub aims to foster a model-driven paradigm in the single-cell data analysis community—one where models are easy to find, access, develop and share, and can be efficiently leveraged to analyze various aspects of new and existing datasets. We expect it to become a growing resource, catering for new types of analyses, use cases and data modalities.

Methods

HubModel

Scvi-hub is implemented as a lightweight submodule within scvi-tools (scvi.hub), which provides an API for uploading and downloading pretrained models to the Hugging Face Model Hub. To do so, scvi-hub uses the huggingface_hub Python API. The main construct within scvi.hub is the scvi.hub.HubModel class, which represents a pretrained scvi-tools model hosted on the Hugging Face Model Hub. An instance of this class has properties that can be used to load the model (HubModel.model) and data (HubModel.adata) into memory on demand (that is, only when/if the property is invoked). To help with new model creation and upload, we also provide a scvi.hub.HubModelCardHelper class, which can be used to auto-generate a template Model card for a new model to be uploaded to the hub, and a scvi.hub.HubMetadata class, which encapsulates metadata required to be uploaded with the model to the hub. Model versioning is built into scvi-hub via usage of Hugging Face as our storage platform, since Hugging Face Hub Models are backed by Git. Hub users can thus request a specific version of the model at download time via the revision argument to the pull_from_huggingface_hub function. We additionally support Hub Models uploaded to an AWS s3 bucket using scvi.hub.HubModel.pull_from_s3. This allows interacting with models that are stored privately inside company buckets or shared with the community without the requirement to register with Hugging Face.

Data minification

We allow storage of the latent posterior parameters (variance and mean in the latent space for each cell). This allows for faster generation of estimated gene expression as the inference function of scvi-tools models aren’t executed and instead the stored latent posteriors are used for the generative parts of the models. In addition, we can reduce the dataset size by removing all count data in the AnnData object. This is performed by setting all expression values to zero and storing count objects as a sparse matrix (therefore, zero entries in the sparse matrix). We additionally allow storing latent posteriors without removing the associated count data. A few functions in scvi-tools rely on computing the reconstruction loss and, therefore, require access to the full count data. These functions are not executable after data minification. All code used throughout the paper is compatible with data minification.

Evaluation using scvi.criticism

Scvi.criticism is a new submodule in scvi-tools that can be used to efficiently compute model evaluation metrics for scvi-tools models. Models must inherit from the scvi’s BaseModelClass class and implement the posterior_predictive_sample method, which samples from the generative distribution used by the scvi-tools model such as a negative binomial distribution. The main entry point for using scvi.criticism is the PPC class, which computes and stores various metrics for the provided collection of models. The PPC class can be initialized with one or a collection of models (for instance, for model comparison), the raw counts and a host of configuration options (such as number of posterior predictive samples to compute). It internally computes and stores a user-provided number of posterior predictive samples for each model (samples from the generative function of the model with user-provided library size).

A crucial aspect of this package is integrated support for three-dimensional sparse arrays. As the posterior predictive samples are n_cells × n_features × n_samples data cubes, their size grows linearly with the size of the dataset and the number of posterior predictive samples. We use the sparse (https://github.com/pydata/sparse/) and xarray (https://github.com/pydata/xarray/) Python packages to store the raw counts and posterior predictive samples in sparse format in memory, and only hydrate the data one batch at a time (this logic is implemented in the scvi-tools package). Supporting sparse arrays in scvi.criticism enables efficient evaluation of models trained on large-scale datasets.

Once initialized, the PPC class can be used to compute various metrics on the per-model posterior predictive samples. The class will store a collection of metrics keyed by metric names where each entry is a Pandas DataFrame holding results for all models that the class was initialized with.

We implemented the coefficient of variation, which is defined as the standard deviation over genes or cells divided by the mean over the same axis. Respectively, the user decides whether the metric is summarized over the different genes or different cells.

To generate Fig. 2d, we instantiated the PPC class with the HLCA raw counts data, the pretrained scANVI model and a value of 2 for the number of posterior predictive samples. The top plot shows the coefficient of variation metric computed across the ‘features’ dimension, using the coefficient_of_variation method of the PPC class. We generated two-dimensional histograms shown along with the best fit and identity lines. The method also prints out correlation measures (such as R2, Pearson and Spearman correlations, and mean absolute error) between raw and approximated results. Results can be stored as an obs column in AnnData. For Fig. 2d, we computed the log ratio of the coefficient of variation between the scANVI model and raw data (without adding any pseudocounts) and displayed the corresponding values overlaid on UMAP.

We implemented the differential expression metric. For each of the posterior predictive samples, differentially expressed genes are computed separately. Samples are first library-size normalized and log1p-transformed. We execute scanpy.tl.rank_genes_groups with a user-provided column for the cell types and the respective method for computation, t-test by default. For each sample, we afterwards compute the F1-score of the top 100 overlapping genes, the mean absolute error, Pearson correlation and Spearman correlation between all estimated log2-fold changes and the area under the receiver operating characteristic curve and the average precision score for all genes with a significant P value computed on the raw expression (P-value threshold of 0.001, by default). Figure 2e shows the differential expression metric computed using the differential_expression method of the PPC class, ‘ann_level_3’ key for cell types and a P-value threshold of 0.2. We used the plot_diff_exp method of the PPCPlot class to generate the box plot shown. To generate the dot plots, we used one sample of the posterior predictive samples

To generate Fig. 3a, we computed Scanpy’s nearest neighbors in the combined latent space using n_neighbors = 30 and UMAP using min_dist = 0.3 in the RAPIDS implementation.

We transferred labels to the query dataset by first learning a nearest-neighbors index on the latent space of the reference atlas, using the NNDescent class of the pynndescent package, and then using the index to compute a nearest-neighbor graph for the query dataset. To this end, we converted nearest-neighbor distances to affinities, and weighted the cell-type labels from adjacent cells using these affinities. For the emphysema dataset, we only use predictions for the confusion matrices with an uncertainty below 0.4 (4.8% of cells filtered out for emphysema dataset). For transferring labels from the query dataset to the reference dataset, the same function was used but the roles of reference and query dataset were replaced.
