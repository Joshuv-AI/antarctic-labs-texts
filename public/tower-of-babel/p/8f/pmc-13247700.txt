Introduction

Data spaces offer a trustworthy, decentralized, and interoperable data sharing platform that enables secure exchange of reliable data between organizations or entities [1]. To this end, initiatives such as IDS and GAIA-X have undertaken the task of providing reference architectures, blueprints, and guidelines for data providers and consumers, which are the primary participating entities in data spaces. In a data space, common vocabularies and semantic models are essential to ensure that shared data by providers is represented in standardized formats and listed in data catalogs that facilitate data discovery for consumers.

Despite the progress made on this front, it is widely recognized that the participation of entities and actual usage of data spaces is far from trivial. Firstly, the whole landscape is still evolving, with new versions of architectures being proposed and reference implementations either minimal or not straightforward to deploy. Secondly, there is a lack of tools that would facilitate the adoption of data spaces. The primary technical component for sharing data is the data connector, i.e., a communication server for sending and receiving data,1 with several reference implementations available. However, data providers need to perform various time-consuming activities before making their data suitable for data sharing, including:•FAIRification of data.•Availability of metadata that assist in data discovery.•and optionally semantic modeling through appropriate ontologies and semantic data transformation and enrichment to extend reusability and interoperability. Consequently, there is still a gap between data spaces and data providers that hinders the wide adoption of data spaces.

Motivated by such limitations, this paper proposes a framework for semantic data modeling and transformation that facilitates the adoption and practical use of data spaces. Our framework targets the side of data providers, offering an easy-to-use solution to uplift raw datasets to semantically-enriched data representations that can be readily shared in data spaces.

In technical terms, the workflow of our approach given a raw dataset, is to apply a change tracking algorithm to identify changes between consecutive versions of the dataset (if any), which are expressed in RDF triples to enable semantic-based queries. Then, it produces a semantic representation of the dataset in RDF given a domain ontology, while extracting metadata that would be interesting for a user, before delving into the actual data, such as:•Spatial and temporal span of the dataset.•Resolution (spatial or temporal).•Frequency or range of values.

Furthermore, our framework employs RDF-Gen [2], [3], which uses a graph template to enable data cleaning, value conversion and transform the data into RDF triples. Therefore, it takes advantage of the benefits of the RDF technology, such as reusability and interlinking between data providers. The current version of the implementation has been dockerized to allow off-the-shelf deployment.2

Related work

In recent years, the concept of data spaces has emerged as a viable solution for managing heterogeneous and distributed data sources without the need for an upfront integration schema. Unlike traditional database systems that enforce rigid schemas, data spaces adopt an incremental integration approach, as described by Franklin et al. [4], enabling flexibility and scalability in data management. This abstraction has positioned data spaces as an essential infrastructure for cross-organizational data sharing and collaboration. One of the primary challenges in data spaces is ensuring compliance with the FAIR principles: Findability, Accessibility, Interoperability, and Reusability. The FAIR guiding principles, first introduced by Wilkinson et al. [5], provide a foundation for systematic and machine-readable data management.

Semantics have been widely recognized as a means to support FAIR compliance in data spaces by enabling the use of standardized vocabularies and ontologies [1], [6]. Multiple initiatives have sought to operationalize the FAIR principles within data spaces. GAIA-X [7], a European effort to create secure and federated data infrastructures, emphasizes self-descriptions, metadata standardization, and authorization mechanisms. GAIA-X incorporates semantic technologies such as RDF-based metadata models and validation using SHACL shapes, facilitating reliable and interoperable data exchange. Similarly, the International Data Spaces (IDS) [8] initiative defines a comprehensive architecture model that leverages RDF/OWL ontologies, DCAT for cataloging, and ODRL for managing usage policies. The IDS Metadata Broker serves as a central registry for semantic descriptions, supporting the discoverability and reusability of resources. Another significant initiative is the European Open Science Cloud (EOSC) [9], which focuses on FAIR research data management. EOSC emphasizes semantic interoperability through the creation of metadata registries, persistent identifiers (PIDs), and crosswalk services for schema alignment. While EOSC primarily targets research domains, it highlights the importance of semantic enrichment and advanced discovery mechanisms for enabling machine-actionable data sharing.

These efforts underscore the role of semantics in addressing the inherent heterogeneity of data spaces. Semantics facilitate standardization through shared vocabularies and ontologies, improving the findability and reusability of data [1]. For instance, the use of DCAT and SHACL has become a de facto standard in ensuring data compliance with FAIR principles [10], [11], [12]. Moreover, enrichment tools, as discussed by Sánchez et al. [13], allow for the annotation and augmentation of raw data, enhancing its utility across various domains.

To enable findability in data spaces, several studies often highlight three main requirements, including unique and persistent identifiers, standardized metadata descriptors and search tools or catalogs to enable discoverability. Digital resources need unique and persistent identifiers (PIDs) such as Uniform Resource Identifiers (URIs) to accurately characterize participants, services, and assets [14], [15], [16]. These PIDs, allow resources to be addressed, updated, and shared independently, even across diverse data spaces. Beyond PIDs, resource self-descriptions and metadata also capture details regarding entities’ attributes and associations, frequently through subject–predicate–object triples in alignment with metadata specifications. As a result, the Resource Description Framework (RDF) data model is widely adopted for these data structures [17], [18]. RDF vocabularies, such as DCAT, enable data space participants to exchange standardized information (e.g., asset labels, types, and lineage) in a manner interpretable by both humans and machines. In addition, catalogs and discovery tools, like the RDF query language SPARQL, grant users the ability to retrieve shared information and navigate resource descriptions, aiding them in finding data relevant to their needs [19], [20], [21], [22].

Current data space initiatives often lack comprehensive automation of data pipelines and integration processes. As noted by Giussani et al. [8], most implementations focus on foundational aspects such as self-description, cataloging, and authorization, leaving advanced functionalities like enrichment and dynamic integration underexplored. Future developments in semantic technologies and graph-based databases hold promise for addressing these gaps and enabling scalable, automated data spaces.

FAIR principles and data spaces

The FAIR principles are a set of guiding recommendations to enhance the utility of digital resources, particularly scientific data, for both machines and people. These principles were introduced in 2016 by a group of experts [5] based on the idea that data should be Findable, Accessible, Interoperable, and Reusable. In turn, this promotes the spreading of knowledge, fosters innovation, and makes digital resources more understandable and shareable across application domains.

Data spaces are by design highly compliant with the FAIR principles, as illustrated also in the respective architectural blueprints. “Findability” is achieved by the use of globally unique and persistent identifiers (e.g., URIs or DOI), while self-describing metadata is also required to accompany any digital resource. This information is assembled and indexed in catalogues or metadata brokers to support findability. “Accessibility” is achieved by means of governance mechanisms and standardized protocols, including authorization mechanisms for controlled access. “Interoperability” highlights that data integration with other datasets should be also enabled through a shared data model and common vocabularies, typically provided by ontologies. For example, the IDS Information Model provides a common structure for different data assets, which facilitates integration and use with different applications and workflows. Also, metadata and data must include qualified references to other related metadata and data, thus enabling data interlinking and the construction of knowledge graphs. Last, but not least, “Reusability” concerns the use of clear usage licenses that specify the terms of reuse, including information about data provenance that enables secondary use of data.

RDF and ontologies

The Resource Description Framework (RDF) is the W3C standard for data interchange.3 The cornerstone of RDF is the triple of resources, namely subject, predicate, and object. A set of such triples forms an RDF Graph, where subjects and objects are represented as nodes, and predicates as edges. The subject of a triple is a resource being described by the triple, the predicate represents an attribute or property of the subject and the object is the value of that attribute or property.

Ontologies provide the conceptualization of the domain, defining the concepts and their relationships. In this way, they define the model of a dataset encoded in RDF (a set of triples). Ontologies can be expressed using plain RDFS to more expressive OWL2 based on Description Logics.4 An ontology is a formal specification of a shared vocabulary that can be used to describe a particular domain or field of interest, thus ensure that the data will be used along with the semantics. This shared understanding enables machines to understand and reason about the data described using RDF, allowing them to perform tasks such as data integration, querying, and inference [28].

While the FAIR principles are technology neutral, RDF is one technology for achieving the Findability principle. This principle requires that data and its metadata can be easily discoverable by search engines, catalogs, or other systems, which can be guaranteed by the fact that RDF uses URIs to identify resources, while it also supports metadata descriptions. Additionally, RDF is closely related to the Interoperability principle of FAIR, which instructs that data should be sharable and integrated across different systems. Ontologies enrich the data with semantics, enabling mutual understanding between systems or applications, integrating and therefore enabling data processing from different sources as a whole.

Provenance and Prov-O

Data provenance refers to the documentation of the origin and lineage of digital assets throughout their lifecycle. This concept is essential in ensuring the authenticity and integrity of data, particularly in domains where accuracy and trustworthiness are paramount, such as scientific research, healthcare, and finance. Provenance information encompasses metadata that describe the creation, modification, and authorship of data. By establishing a chain of versions for datasets, data provenance provides an auditable trail that enables users to verify the reliability and accuracy of information. This is achieved through the use of robust tracking mechanisms and metadata annotations, which facilitate the creation and management of verifiable data provenance records. By incorporating data provenance into data management practices, organizations can enhance transparency, accountability, and reproducibility, contributing to improved decision-making and scientific discourse.

The Prov-O ontology [29] is a formal framework for describing data provenance, designed to capture the complex relationships between entities involved in the generation, processing, and dissemination of digital artifacts. The core concepts and relations in Prov-O, define the classes and properties that establish the fundamental structure of provenance information. The root class, “prov:Activity”, represents an operation or transformation performed on a resource, while “prov:Entity” denotes any entity participating in an activity, including agents, resources, and roles. The ontology also introduces relationships between these entities, such as “prov:wasGeneratedBy”, which indicates the generation of a resource through an activity, and ”prov:used”, which specifies the utilization of a resource in an activity. Furthermore, Prov-O defines subclasses and properties to describe specific aspects of provenance, including responsibility (“prov:wasResponsibleFor”), location (“prov:location”), and temporal information (“prov:startTime” and “prov:endTime”). By providing a standardized vocabulary for describing data provenance, Prov-O facilitates the creation of interoperable and semantically-rich representations of digital artifacts, enabling more effective querying, analysis, and reasoning over complex provenance data.

System architecture

Our proposed framework enables the preparation of raw datasets for sharing via data spaces. Conceptually, the framework consists of software components that take a dataset in its raw format as input and produce a semantically enriched dataset in accordance with the FAIR principles, which can be accessed by a data connector. The components that belong to our framework are: (a) the data enrichment component, which includes two sub-components: the data transformation and link discovery, (b) the findability component, and (c) the data provenance component.

Fig. 2 illustrates the internal architecture of our framework. The first primary component is the data enrichment, responsible for accessing a raw dataset, transforming the records into RDF format, and potentially interlinking the generated RDF triples with other data. The data transformation process is performed by the data transformation sub-component, which employs a template-driven approach, where a graph template is authored to prescribe the syntax of the RDF triples that will be generated. Data interlinking is performed by a Link Discovery sub-component that supports efficient functions for associating entities originating from different datasets. Domain ontologies provide the vocabulary for building the graph template, towards generating RDF triples, that capture the true meaning of the transformed data. The terms of any ontology can be used in the template, enabling our approach to generate RDF triples according to a user-specified conceptual model as well. The generated RDF triples are stored in an RDF store, allowing for easy querying and retrieval via a declarative query language (SPARQL).Fig. 2Architecture of the implemented system.Fig. 2 dummy alt text

Architecture of the implemented system.

In addition, as the input dataset is transformed into RDF triples, the data enrichment component computes and maintains metadata for the dataset at hand, including various properties such as spatial/temporal span, most frequent values, and unique values. These metadata describe the input dataset, using the vocabulary of DCAT5 (Data Catalog Vocabulary) ontology. Upon completion of the data transformation process, the computed metadata is provided to the Findability module, which is responsible for representing the metadata in RDF format and storing them in an RDF store.

After storing data and metadata as Resource Description Framework (RDF) triples, a connectivity API facilitates uniform access through POST requests conforming to the SPARQL protocol. This enables provision of a web-based graphical user interface (GUI) frontend for interactive data exploration and querying. Additionally, the connectivity API can be utilized by a data connector, which now has access to semantically enriched data represented by unique identifiers and adhering to the Findable, Accessible, Interoperable, and Reusable (FAIR) principles. In this manner, the initial raw dataset can be readily shared via a data space following a transformation and semantic modeling process.

Finally, as shown in Fig. 2, our framework can be integrated with the IDS data connector, to become applicable in existing data spaces. In practice, this is achieved by following the typical sequence of steps when sharing data via data spaces, from data discovery to contract negotiation, using the IDS data connector API. The metadata descriptors are made available in the vocabulary used. The main change is in the data exchange phase, where our framework shares the data as a file, which is made available by the IDS data connector to the client, in the exact same way as in the default scenario of sharing CSV data through IDS data connectors. Thus, the integration of our framework with the IDS data connector retains the secure and standardized data exchange offered by the IDS ecosystem.

Data provenance

Provenance metadata are critical for tracking the evolution of datasets. However, manual data entry can hinder flexibility in updating provenance data and may be error-prone in general. To address this issue, we propose an automated approach to extracting provenance metadata from datasets.

This added feature is particularly useful when employed on data servers that support multiple versions of digital objects but lack tracking of actual changes between versions. The automatic extraction of provenance metadata adds a valuable functionality to such data servers, enabling change tracking in a decoupled approach without affecting performance and resource availability. The extracted metadata can be stored in a triplestore, providing a SPARQL query endpoint for provenance data exploration.

More specifically, the provenance metadata extraction process is configured to monitor updates to datasets in predefined repositories. At the initialization phase or upon detection of an update resulting to at least one new version during runtime, the process retrieves the sequence of newly added versions ordered by their annotated upload timestamp. For example, assuming a dataset D with version updates Vt0, Vt1, and Vt2 at timestamps t0, t1, and t2, respectively, the provenance component attempts to identify changes between each consecutive pair of versions (i.e., 〈Vt0,Vt1〉 and 〈Vt1,Vt2〉). Upon detection of a new version (e.g., Vt3), the process evaluates only the pair formed by the last known and newly added versions (i.e., 〈Vt2,Vt3〉).

For each evaluated pair of versions, we apply the Myer’s difference detection algorithm [30]. This algorithm is a divide-and-conquer algorithm that recursively finds the central match of two sequences by minimizing their edit script. Once this central match is identified, it is stored, and the two subsequences preceding and following it are compared recursively until no further comparisons are necessary. To find the central match, the algorithm attempts to match the ends of the sub-sequences as far as possible. If a mismatch occurs, the edit script is augmented by 1, and each position on the diagonal up to that point is examined to determine how far matching can continue. If a match is encountered that aligns with the other end of the sequence, the algorithm has successfully located the central match.

When the difference detection algorithm is completed, the process constructs the RDF triples describing the versions of the dataset and the detected changes, and uploads them to a triplestore for flexible, user-friendly, and uninterruptible data discovery and exploration.

The pair of subsequent versions 〈Vti,Vtj〉 evaluated for changes in our automated metadata extraction process is called a patch Ptitj. The older version (Vti) is referred to as the origin version of the patch, while the newer version (Vtj) is denoted as the update version of the patch. Changes detected for a given patch Ptitj comprise a finite set of any combination of:•Change Delta ΔCij: changes made in the origin version of the patch (e.g., fixing typographical mistakes in the data).•Insert Delta ΔNij: added new data by the update version (e.g., appending new rows in a tabular dataset).•Delete Delta ΔDij: removed data from the origin version of the patch (e.g., removing rows from a tabular dataset).

•Change Delta ΔCij: changes made in the origin version of the patch (e.g., fixing typographical mistakes in the data).

To compute the minimum set of Deltas, the algorithm calculates the differences between two sequences and aims to find the shortest edit steps to transform one sequence into another. The algorithm has a time complexity of O(ND), where N is the sum of the lengths of the two sequences and D is the size of the minimum edit script. Also, the parallelization of this approach is straightforward, as each pair of consecutive versions can be processed independently.

Data enrichment

In real applications, datasets typically come in various (raw) formats, ranging from plain files (text/CSV/JSON/XML) to binary files (NetCDF, GRIB2), different schemas, as well as in archival or streaming mode. To make this data interlinked, reusable, and exchangeable, the data transformation component is responsible for creating a common semantic representation of the dataset from its raw format. To this end, we embrace the Resource Description Framework (RDF), which is the de-facto standard for open linked data in the Semantic Web.

RDF-Gen: Template-based generation of RDF data

Specifically, data transformation relies on RDF-Gen [2], [3], a versatile software component that takes as input a raw dataset and transforms it into RDF triples. RDF-Gen supports various input data formats, both streaming and archival, in an efficient and scalable way. RDF-Gen is designed to consume input data record-by-record, so it is applicable both for archival data as well as for streaming data, e.g., by accessing Kafka topics. Furthermore, RDF-Gen has been shown to outperform competitive approaches for RDF data generation [3].

RDF-Gen consists of two main modules: the data connector6 and the triple generator. The data connector is responsible for establishing a connection to the data source, accessing the input data and producing records for further processing. The triple generator takes as input each record, and transforms it into RDF triples according to a predefined graph template. This abstraction allows to decouple the logic of data access from data processing, achieving a modular design that enables the development of data connectors for new data sources, without affecting the data transformation process. Moreover, it allows the two parts (data access and data processing) to scale independently.

The data connectors available cover a wide range of known data formats, varying from locally stored CSV, JSON, XML files, to a remote or local database, Kafka topics or websockets. For each case, the RDF-Gen configuration includes the necessary information to establish the connection to the data (i.e., path to file or remote address, authentication details, etc.). The data connector iterates over the data of the source in a record by record fashion. The RDF-Gen configuration also includes a list of variables, such that each data value in each record is assigned to a single variable. The variables are used in a graph template, which transforms the data into triples according to the variable assignments made for each retrieved record. The graph template is similar to the SPARQL triple pattern, while it also enables the use of custom functions that can generate resources or triples from the retrieved data. The graph template is always constructed according to a given ontology and the process generates triples that are consistent with the given ontology.

Automatic metadata generation for datasets

In this paper, we have extended RDF-Gen to support automatic extraction of metadata from an input dataset. The metadata extraction is carried out during the data transformation, with minimal overhead to the data transformation process. To achieve this, RDF-Gen maintains the necessary information (the metadata) in memory, and outputs this result at the end of data transformation.

The terms used for the configuration of RDF-Gen are in the http://www.datacron-project.eu/RDFGen_conf# namespace, which uses the prefix “dcf” for convenience. A typical configuration is specified as an RDF file that defines the data source, data connector, template, and output for a data transformation to RDF triples process. This work extends the configuration terms by incorporating metrics to be computed on selected variables of the template. The spatial resolution is defined as the minimum Euclidean distance between any pair of reported positions in the dataset. In this implementation, to compute the spatial resolution, we employ a divide-and-conquer algorithm that recursively partitions the space into sub-regions. This process continues until each sub-region contains exactly one position, at which point it is pruned from further consideration. The algorithm iteratively refines the partitioning by examining the smallest sub-region containing two positions and computing their Euclidean distance. The smallest such distance between any pair of positions in the dataset is taken as the spatial resolution.

Findability

The Findability Component is designed to address the challenges associated with discovery and management of datasets. At its core, it adheres to the FAIR principles (Findability, Accessibility, Interoperability, and Reusability), ensuring that datasets and their associated metadata can be efficiently identified, explored, and reused across diverse systems.

The primary function of the Findability Component is to generate, store, and retrieve metadata that describe the structure, provenance, and attributes of datasets. To achieve this, it employs a semantic meta-model that leverages established W3C standards, including the DCAT (Data Catalog Vocabulary), PROV-O (Provenance Ontology), and QB Vocabulary. These standards ensure that metadata are semantically enriched, machine-readable, and aligned with widely adopted vocabularies, thus promoting interoperability and consistency across datasets.

Our aim is to support the following requirements:1.Ability to categorize datasets by mobility-relevant themes (public transport, air quality, maritime tracking).2.Support for complex spatial descriptors (city polygons, maritime zones, road segments) and a range of temporal resolutions (real-time, daily, seasonal).3.Fine-grained structural metadata to enable queries by dimensions (e.g., time, space) and measures (e.g., speed, passenger count, pollutant concentration, water depth).4.Provenance metadata to clarify how datasets are created (sensor observation, data fusion, forecasting models) and who is responsible (transport operators, sensor manufacturers).5.Indication of how to retrieve data (file downloads, APIs, SPARQL endpoints, database connections) to support automated data discovery integration and access.

Design of the semantic meta-model

The derived requirements led to the selection and adaptation of a semantic meta-model that builds upon W3C standards and domain-independent ontologies. The chosen model integrates DCAT (Data Catalog Vocabulary), which serves as the backbone for representing datasets, their distributions, and associated services. It provides classes and properties for dataset titles, descriptions, publishers, access rights, and thematic areas.

PROV-O (Provenance Ontology) captures information about dataset creation, including activities (e.g., sensor observation, data fusion), agents (e.g., data providers, devices), and entities involved. This enables traceability and trust in the data lifecycle.

QB (RDF Data Cube Vocabulary) defines the structure of datasets with dimensions (e.g., time, location), measures (e.g., speed, battery level, pollutant concentration), and units of measure. QB facilitates fine-grained data exploration and interoperability by aligning dataset schemas with a common conceptual model.

Additional standardized vocabularies and code lists enhance semantic clarity. These include Dublin Core (dct:) for temporal/spatial coverage (dct:temporal, dct:spatial), issuance/modification dates, and SDMX (Statistical Data and Metadata eXchange) for expressing units of measure.

EU Authority Tables, INSPIRE, and other controlled code lists are utilized for licensing terms, geographical identifiers, and thematic codes. These choices ensure alignment with existing standards, facilitating the integration of metadata across platforms.

These domain-independent ontologies are employed in our approach to describe the datasets available in the data space using general terms that are applicable to many domains, while domain-specific ontologies (e.g., like the MobiSpaces ontology) mainly focus on describing the actual data in these datasets.

Evaluation of data provenance

Regarding the extraction of metadata from the data provenance component, we aim to evaluate the performance of Myers’ difference algorithm, which is in the core of this component. This divide-and-conquer algorithm is designed to determine the shortest edit script (SES) between two sequences. As mentioned in Section 5, the time complexity of the algorithm is O(ND), where N represents the sum of the lengths of the two input sequences and D denotes the size of the minimum edit script. Notably, the algorithm exhibits high efficiency when the sequences are similar, as D is small, making it well-suited for typical applications such as version control systems.

We evaluate the performance of the algorithm on a sequence of 30 versions of the AIS dataset [31]. The versions are constructed by introducing random modifications in the data and appending entries in accordance with the following procedures. First, each version vib is generated by randomly modifying 25% of the entries from version vi. Then, each subsequent version v(i+1) is created by adding 3716 new entries to version vi. It should be noted that for each update from a version vib to v(i+1), we do not only append 3716 new entries but also modify 25% of the records in vi, effectively reverting the changes made from vi to vib. We evaluate the sequence of updates between versions in the order: {v1, v1b, v2, v2b,..., v15b} five times and compute the average processing time.

Conclusions

Data spaces platforms provide a revolutionary approach to data sharing, enabling secure and trusted exchange between entities. Despite this, our recent experience in research projects on data spaces indicates that it remains challenging for participating entities to readily adopt the concept of data spaces. Our framework addresses this challenge by simplifying the data interoperability, facilitating template-based data transformation, automatically generating metadata using the W3C Data Catalog Vocabulary, and efficiently extracting metadata while considering the principles of Findable, Accessible, Interoperable, and Reusable (FAIR) data.

By providing a scalable and deployable solution, we meet the mandatory requirements of the Information Discovery System (IDS), with respect to any given semantic model, focusing on data discoverability and sharing.

Future work will focus on deeper integration of our framework with existing implementations of data connectors, aiming to further simplify its use and adoption by data providers. Furthermore, extending our meta-model to support other types of metadata useful for data discovery is an area of interest.
