MontadoDB: A comprehensive dataset of pasture parameters in the Southern Region of Portugal
Authors: Samuel Rodrigues, Guilherme Defalque, João Serrano, Ricardo Santos
Published: 2025

ABSTRACT
This article presents MontadoDB, a dataset comprising samples of pasture quality parameters, weather data, and satellite images from a set of paddocks in the Alentejo region (southern Portugal), the Beira Interior region (Portugal), and Extremadura (Spain). These regions are part of the Montado system, an agro-silvo-pastoral system featuring low-density trees, pastures, and livestock grazing. The pasture parameters were collected along three vegetative cycles from 2018 to 2021 in 8 different paddocks. After the collecting procedure, pasture samples were submitted to laboratory analysis to determine the reference values of pasture moisture content (PMC, in %), crude protein (CP, in g/100 g), and neutral detergent fiber (NDF, in g/100 g), using standard analytical methods. For each pasture sample collected, GPS coordinates were recorded. Using these coordinates, the Google Earth Engine (GEE) platform was utilized to collect satellite multispectral data and weather information. The MontaDB dataset is publicly available, enabling research focused on the analysis and design of machine learning models for predicting pasture parameters. It can also work as a reference dataset for further experiments based on pasture samples, thereby enhancing research on advanced algorithms that rely on large-scale datasets.

•The value of data stands on the significant and consistent data of pasture parameters acquired over a long period across different pasture fields. Obtaining pasture quality data is challenging, as it requires a systematic collection methodology and submission to laboratory analysis. This dataset comprises over 700 samples of natural dryland pastures, along with their corresponding quality parameters.•Each sample is associated with precise GPS coordinates, which were used to extract satellite multispectral and weather data from Google Earth Engine (GEE). These data layers—such as NDVI, EVI, surface temperature, and precipitation—are globally available and standardized, allowing researchers to apply similar methodologies to new locations or compare models across datasets.•The value of data is derived from the correlations among its various components. This dataset can be valuable because it offers many dependent and independent variables for such purposes.•The dataset can support transfer learning approaches, where models trained on MontadoDB can be adapted to other ecosystems with minimal retraining, especially in regions with similar climatic or land cover characteristics.

Background

The livestock sector currently accounts for the majority of the world's agricultural land use, occupying approximately 77 % of the world's available agricultural land. Within this context, pasturelands alone cover nearly two-thirds of the total arable surface dedicated to agricultural production [3]. In Mediterranean regions, livestock production heavily relies on pasture-based systems, with extensive grazing practices forming a central component of management strategies for cattle and sheep. Monitoring pasture availability and quality throughout the growing season is essential to enhance the efficiency and sustainability of these systems. Monitoring is of utmost importance for determining stocking rates, optimizing animal rotation intervals, and accurately estimating pasture needs [4].

Serrano et al., 2024 [4] proposed a rigorous methodology for pasture data collection, ensuring consistency across time and location. Over three years, pasture samples were systematically collected from the same regions and subjected to detailed laboratory analyses. Although the original study focused on predicting the NDVI spectral band, its practical applications are somewhat limited.

The present work aims to expand the original dataset by incorporating multispectral satellite information and weather variables associated with each sample. This improvement is expected to enable the development of machine learning models capable of predicting pasture parameters previously obtained exclusively through laboratory methods.

Data Description

The dataset is organized into two folders: ``dataset'' and ``scripts''. The ``dataset'' folder has seven CSV files and one JSON file. The file Experimental_data.csv provides nutrient information from the pasture samples, while Weather_data.csv consists of the corresponding weather conditions of each collection date. Sentinel_2.csv, Sentinel_3.csv, Landsat_8.csv, and Modis.csv comprise multispectral satellite data. The file Complete_data.csv is the result of merging the experimental data, weather data, and all the spectral bands of each satellite. All the files contain 705 rows, each representing a pasture sampling. The Satellite_info.json file includes metadata information for multispectral band extraction and dataset creation, storing each satellite's Python API code, band names, scale values, and header names of the CSV files.

The ``scripts'' folder contains multispectral_api.py, weather_api.py, and build_dataset.ipynb files. The first script uses the Google Earth Engine [5] to collect Multispectral data from four satellite collections: Landsat-8, Sentinel-2, Sentinel-3, and MODIS. The second script provides methods for collecting weather data from OpenWeather MAP [6] or Open-Meteo [7] APIs. The Python notebook build_dataset.ipynb utilizes both scripts to build the datasets and provides data analysis methods (plot histograms, run descriptive statistics, apply statistical tests, etc.). The python source code files require the following libraries:•Standard libraries: os, csv, json, time, datetime, and logging.•External libraries: ee (Earth Engine API), requests, pandas, and numpy.

Table 2, Table 3, Table 4, Table 5 explain how each satellite's spectral data is organized. The date and geographical coordinates were added first to enable cross-referencing with experimental and weather datasets. The spectral band columns are preceded by a column that indicates the date the image was collected. Every column name highlights the type of satellite, its collection, and tier, e.g., Landsat-8_SR_1, which refers to the Landsat-8 satellite, surface reflectance collection, and tier 1. Landsat-8 and Sentinel-2 offer surface reflectance and top of atmosphere collections, with Landsat-8 adding a Raw images collection and the concept of tiers. The raw image collection consists of the sensor's original data, without calibration. Top of the atmosphere modifies the data to physical units, but still contains cloud and aerosol effects; Surface reflectance removes atmospheric distortions and estimates the sunlight the ground reflects. In the Landsat-8 satellites, the tier represents the quality of the images. Tier 1 comprises high-quality images that meet strict positioning and calibration standards; Tier 2 includes images that do not meet the Tier 1 criteria; RT consists of real-time images that will A - Experimental phase

Serrano et al., 2024 [4] conducted the experimental study over three vegetative cycles (2019, 2020, and 2021) of eight dryland pastures, as shown in Fig. 1– seven located in Portugal (AZI, GRO, MIT, MUR, PAD, TAP, and QF) and one in Spain (CUB). In the 2019 cycle, pasture samples were collected from January to May. In the 2020 cycle, samples were collected from January to June (except for February) and in December. In the 2021 cycle, samples were collected from February to May. For each location, ten to twelve composite samples – comprising five subsamples – were collected using a metal quadrant (0.5 m x 0.5 m) and electric shears from areas with no trees. Pasture samples were submitted to laboratory analysis to determine the reference values of pasture green matter (GM, in kg ha-1), dry matter (DM, in kg ha-1), fresh weight (MV, in kg ha-1), pasture moisture content (PMC, in %), crude protein (CP, in % of DM) and neutral detergent fiber (NDF, in %). The laboratory analysis and procedures were based on the standard analytical methods of the International Association of Official Analytical Collaboration [8].Fig. 1Paddock areas and sample locations.Fig 1

Paddock areas and sample locations.

Once in the laboratory, the pasture sample was weighed to establish total biomass (GM), dried in an oven for 72 h at 65 °C, and weighed again to establish DM and PMC. Then, these samples were ground using a Perten instruments mill equipped with a 1 mm sieve. CP and NDF were analyzed according to the following standard methods: (i) nitrogen content was analyzed with the Kjeldahl method, a colorimetric determination in a Bran + Luebbe autoanalyzer with a factor of conversion to CP of 6.25; (ii) the NDF content was analyzed according to the Goering and Van Soest method in a fibered digester.

B - Multispectral and weather data extraction

Fig. 2 illustrates the workflow for collecting multispectral bands and weather data from each sample. In the spectral bands extraction workflow, data for the API and for building the dataset are read from the Satellites_info.json file, a metadata file. Next, geographical coordinates and dates of the samples (from Experimental_data.csv) are used as input for the build_dataset.ipynb notebook that utilizes the functions in the multispectral_api.py module. The coordinates and dates are also in the current satellite CSV file. The scripts in build_dataset.ipynb work with the Google Earth Engine API to search for image collections of each sample point. It first starts to search for collections with a cloud cover threshold <1 % (only Sentinel-2 and Landsat-8) and a 14-day temporal window. If no image is found, the cloud cover threshold is progressively adjusted, increasing the filter percentage to 1 %, 5 %, 10 %, 20 %, 50 %, and eventually removing the filter. If this search yields no results, the temporal window increases, the cloud cover threshold returns to 1 %, and the process repeats all over again. The valid temporal window values are 14, 30, and 60 days. Once an image is found, the nearest one with valid values is selected. Eventually, band values are calculated as the mean of the adjacent pixel values to the target geographic point and written in the current satellite CSV file.Fig. 2Multispectral and weather data extraction workflow.Fig 2

Multispectral and weather data extraction workflow.

The weather data extraction workflow relies on the build_dataset.ipynb notebook, which utilizes the functions from the weather_api.py module. Weather data can come from two APIs: OpenWeather and Open-Meteo. The scripts in build_dataset.ipynb search for data using the geographical coordinates (latitude and longitude) and the date of each sample. It first looks for data in the OpenWeather API; if no data is found, the process proceeds to the Open-Meteo API. If the weather data is found, the date and geographical coordinates data are additionally written to Weather_data.csv.

Box-Cox transformation is a statistical tool for approximating data to a normal distribution. We have applied data transformation using Box-Cox to evaluate whether the data can be fitted to a normal distribution. The data significantly increased its p-value (p-value>α suggests accepting the null hypothesis that the data follow a normal distribution), as shown in the histograms on the right. Some targets (Crude Protein and Pasture Moisture Content) are far from a normal data distribution (regarding a 1 % significance level). The transformation has impacted the NDF, DM, and FW histograms, shifting them towards a normal distribution.

Either no image for the specified date and location was found, or the nearest available image has a gap of several months, exceeding our temporal tolerance.

Bands Oa01_radiance and Oa10_radiance from Sentinel-3 were removed for convenience due to some pixels containing invalid values.

The weather data scripts are capable of collecting data from OpenWeather and Open-Meteo APIs. However, OpenWeather offers historical weather data, but it is not free. All the weather data in Weather_data.csv was obtained from the Open-Meteo API.

The experimental data had methodological limitations: the sample sizes varied across the eight paddocks, and due to COVID-19, some paddocks had a limited number of samples; furthermore, the samples were not collected on the same day across all paddocks.
