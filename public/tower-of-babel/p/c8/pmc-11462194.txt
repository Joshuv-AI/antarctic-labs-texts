Protocol for analysis of plasma proteomes from patients with hepatocellular carcinoma receiving combination therapy
Authors: Zhi-Feng Pan, Ling Du, Feng Liu
Published: 2024

ABSTRACT
SummaryPlasma shows distinct metabolomic and proteomic signatures in response to combination therapy with lenvatinib and anti-programmed death-1 (PD-1) antibody in treating hepatocellular carcinoma (HCC). Here, we present a protocol for analyzing plasma proteomes from patients with HCC receiving combination therapy. We describe steps for interpreting mass spectrometry data by database searching using MaxQuant and filtering and processing database search outcomes. We then detail procedures for downstream analyses including normalization, differential expression analysis, functional enrichment analysis, correlation analysis, consensus clustering, and survival analysis.For complete details on the use and execution of this protocol, please refer to Li et al.1

Before you begin

Patients with unresectable hepatocellular carcinoma (uHCC), including advanced stages, metastases, or recurrence, usually receive combination therapy. The combination therapy typically includes a tyrosine kinase inhibitor (TKI), such as lenvatinib, along with antibodies targeting the programmed death-1 receptor (PD-1) or the programmed cell death ligand 1 (PD-L1). A significant challenge in this treatment approach is predicting individual patient’s responses to the combination therapy. To address this, we have conducted extensive proteomic and metabolomic analyses of plasma samples from both healthy individuals and HCC patients who were treated with the combination of lenvatinib and anti-PD-11. Additionally, we examined the somatic mutations and proteomes in cancer tissues from these patients. Our study identifies distinct metabolomic and proteomic signatures in plasma that differentiate responders from non-responders. We utilized these findings to create machine learning models that demonstrate strong predictive capabilities in HCC patient cohorts.

This paper outlines a detailed protocol for analyzing plasma proteomic profiles in HCC patients. We provide the protocols to perform protein database search using MaxQuant program. We describe the systematic steps needed to filter and process the initial results obtained from the MaxQuant database search, including the selection of the most effective normalization method from eight potential options. We employ the limma algorithm to identify differential proteins across various comparisons, such as responders versus non-responders, pre-treatment versus post-treatment groups, and cancerous versus healthy samples. Furthermore, this protocol covers comprehensive procedures for conducting functional enrichment, gene set enrichment analysis (GSEA), correlation analysis, consensus clustering, and survival analysis.Note: The protocols are R scripts and each command is started with a '>'. Materials and equipment

We benchmark the protocols on a workstation equipped with dual Xeon X5660 processors and 96 GB of ECC RAM. However, these protocols are adaptable and can be executed on most desktop or laptop computers with internet connections. A minimum requirement for running these protocols effectively is a processor with at least 4 threads and 16 GB of RAM.

Step-by-step method details

MS data interpretation by database search using MaxQuant

Timing: variable

Expected outcomes

The current protocol offers a flexible approach to handling proteomic results obtained from MaxQuant database searches. Initially, it involves filtering and cleaning up the search results from MaxQuant to ensure data quality. The protocol then proceeds to normalize the proteomic quantitative data using a refined normalization method, setting the stage for accurate analysis. Differential proteins are identified leveraging the limma statistical method, which is followed by a comprehensive suite of analyses including hierarchical clustering, functional enrichment, GSEA, principal component analysis (PCA), correlation analysis, and survival plot analysis to deeply understand the biological implications. Additionally, a consensus cluster analysis is conducted on the expression matrix, which may include all samples or be restricted to only cancer samples, to uncover potential subgroups. This thorough approach ensures a robust exploration of the proteomic landscape, facilitating significant insights into the underlying biology.

Quantification and statistical analysis

The differential proteins are identified using empirical Bayes moderation implemented in R package limma. The p values are adjusted for multiple testing using Benjamini-Hochberg method. In survival analysis, the p value is calculated using log rank test.

Limitations

The current protocols begin by processing the results from a MaxQuant database search. If initiating with a different expression matrix table, note that the data format might vary, necessitating modifications to the R script. The protocol focuses on analyzing human proteins, employing UniProtKB as the database for MaxQuant searches. If alternative databases such as NCBI RefSeq be utilized, the approach to processing protein names would need to be adjusted. We do not address or correct for batch effects in our analysis, given that our mass spectrometry data is collected over a span of several days. However, if the MS analysis extends over a longer period, it is crucial to assess and mitigate the variations caused by batch effects. The protocols predominantly rely on R scripts for conducting analyses. Nonetheless, external tools can serve as alternative options for functional or network analysis, such as Metascape,25 g:Profiler,27 String database,28 Cytoscape,29 and standalone GSEA software.

The process of MaxQuant results can also use an online tool LFQ-Analyst to complete the filtering, missing value imputation, and quantification analysis by limma,20 as we have demonstrated in our published paper. DEP is also designed for quantitative analysis of proteomics data.23 Both LFQ-Analyst and DEP are user-friendly Shiny applications, offering features such as filtering, normalization, differential statistical analysis, functional enrichment analysis, network analysis, and PCA analysis. The upgraded version, DEP2, introduces additional functionalities to process data files from RNA sequencing, data-independent acquisition (DIA), and post-translational modifications (PTM). DEP2 is also equipped to perform protein-protein interaction analysis and compare multiple results. However, neither application includes functionality to evaluate multiple normalization methods across different datasets. Additionally, some analyses are unavailable in both applications, requiring users to rely on external tools to perform tasks like consensus clustering and survival analysis. Moreover, the output figures are not configurable in terms of size, color, labels, etc. Perseus represents a standalone and user-friendly software that integrating many functionalities to perform quantitative analysis of proteomic data.30 The database search results file (proteinGroups.txt) can be directly imported into Perseus for further analysis. This includes steps such as filtering, normalization, imputation of missing values, sample grouping, correlation analysis, PCA, and hierarchical clustering. Perseus offers various normalization methods, including Z-score, cluster normalization, and quantile normalization. However, it lacks evaluation tools for these methods, making it challenging to select the most suitable one. The R script we present in our current work streamlines the entire analysis process, from data input and filtering to normalization, differential analysis, functional enrichment, consensus clustering, hierarchical clustering, and PCA analysis, to survival analysis, offering considerable flexibility for beginners or users who are familiar with R language. Furthermore, the pipeline is expandable, allowing for the easy incorporation of additional functions or analyses.

Troubleshooting

Problem 1

The filtering for proteomic results is failed (steps 4–9).

Potential solution

To use this R script, the input should be a proteinGroups.txt resulted from a MaxQuant database search. The database used for MaxQuant search should be UniProtKB (https://www.uniprot.org/). Furthermore, the columns containing quantitation values for the samples should be adjusted accordingly based on whether iBAQ or LFQ is used for quantitation. Moreover, it is important to adjust the processing of the sample names based on the specific requirements of different experiments.

Problem 2

The listed R packages cannot be properly initiated or executed in several steps.

Potential solution

If the packages are not installed or are incomplete, the packages can be installed or reinstalled using BiocManager::install(‘package name’, force = TRUE). During the installation, there may be a prompt to update some current packages that have been installed. In such cases, the ‘all’ option should be chosen to update all necessary packages. After installation, the packages should be initialized using library(‘package name’) before using them. An alternative method for installing the package is to download the package archive file from the link we provided in the ‘key resources table’ and manually install the package.

Problem 3

When attempting to save a figure as a PDF file, a common error is that the resulting PDF may have zero size (such as in step 23).

Potential solution

Please utilize the export function in the RStudio GUI, especially for the GO enrichment results that may contain extremely long function item names.

Problem 4

No significant results in functional enrichment analysis (Steps 24, 25).

Potential solution

When the protein count is low, enrichment processes might not yield statistically significant outcomes. In such circumstances, it’s advisable to lower the stringency of the threshold used for differential protein identification. Alternatively, employing the GSEA method could be a viable solution. Another option is to switch to a different functional enrichment database.

Problem 5

No significant (q value > 0.05) results are obtained in gene set enrichment analysis (Steps 26–28).

Potential solution

Unlike the functional enrichment analysis of the different proteins/genes, the input for GSEA is the entire proteome or transcriptome expression matrix. GSEA discourages any filtering of the raw matrix because it will diminish the statistical performance of its algorithm. If you’re analyzing serum or plasma proteome, only several hundred proteins are typically identified. In such instances, as many proteins as possible should be retained for GSEA.
