Precision meets speed through an FPGA-based natively sparse Ising machine for combinatorial optimization
Authors: Baijian Yao, Daniel Ebler, Xu Shi, Juntao Wang, Fan Zhang, Wei Zhang, Jie Sun
Published: 2026

ABSTRACT
Ising machines constitute a framework to solve combinatorial optimization problems efficiently utilizing dynamical interacting systems. Typical approaches simulate the dynamics on digital hardware, which is strongly dependent on matrix-vector operations, and were shown to experience acceleration of several orders of magnitude by parallel processing on FPGAs. However, optimization on single FPGAs has remained limited to small-scale problems due to memory limitations, and multi-FPGA networks are challenging to operate. In this work, we propose a high-accuracy and FPGA-based Ising machine design that achieves state-of-the-art solution speeds on integrated hardware and is scalable to problems of up to 20,000 variables on a single FPGA unit. Concretely, we introduce a sparse data format, called tiled coordinate list, for more efficient memory use and fast matrix-vector operations. Further, we propose a quantization mechanism to 8-bit integer precision that allows problem sizes to be scaled without reducing the accuracy of the solution. Co-optimization of the data flow and hardware design strongly accelerates the Ising machine while reducing computational costs. This enables 10- to 68-fold speedups on Max-Cut problems from the Gset graph collection compared to previous state-of-the-art FPGA-based Ising machines.

Introduction

For many disciplines, identifying accurate solutions to discrete optimization problems in the shortest possible time is of great importance, including wireless and optical communication networks, synthetic biology, power grids, high-performance computing, machine learning, logistics, and financial markets, among many others1–6. However, given the hardness of the problems, the solution speed and accuracy of the solutions are often limited, especially because the algorithmic design of the solvers is usually decoupled from the supporting hardware architecture.

Recent approaches suggest Ising machines as a class of analog solvers for combinatorial optimization7–14. The optimization problem is encoded into the interaction pattern of coupled dynamical systems, and temporal evolution, combined with external control mechanisms, drives the systems towards stable modes corresponding to candidate solutions. Compared to conventional solvers, state updates in Ising machines are intrinsically parallel. This has led to solution speeds several orders of magnitude faster than conventional solvers, for instance, in physical networks such as coupled photons in fiber cavities, spintronics, and mechanical oscillators9,15,16. However, scaling experiments to practical problem sizes is challenging, and the accuracy of the solution varies strongly.

Simulation of the network dynamics on digital hardware mitigates experimental challenges while preserving the hardware acceleration of the solver10,13,17–19. The dynamics are described by a set of coupled differential equations, which constitute an update rule consisting mainly of matrix-vector operations. This has led to multi-threaded solutions on Field Programmable Gate Arrays (FPGA), which achieve 2-3 orders of magnitude acceleration over conventional solvers20. However, previous proposals were strongly limited in problem scale, mainly for two reasons. Firstly, the optimization problem was stored in dense matrix format20, while many real-world problems are inherently sparse. Sparse FPGA implementations21,22 were proposed to address this issue, but were 2–3 orders of magnitude slower than dense implementations20. Secondly, the matrices and vectors were stored within the FPGA chip memory, which is limited in capacity. To overcome these issues, multi-FPGA networks were proposed to scale problems to 100,000 variables23. This setup, however, requires ultra-large bandwidth and cumbersome multi-chip synchronization, which is hard to control and replicate in practice.

In this work, we present an FPGA-based sparse Ising machine design that achieves state-of-the-art solution speed on digital hardware and consistently high-accuracy solutions. The design is based on several insights. Firstly, we propose a new data format, the tiled coordinate list (TCOO), which allows matrices to be efficiently stored as sparse matrices. Data are stored on off-chip FPGA memory, allowing for simultaneous computation and transmission, yielding on average 30% reduced memory usage compared to COO and 22% reduced memory usage compared to block COO (BCOO)24. The format also enables better workload balancing between multiple processing elements (PEs), achieving on average a utilization rate of PE runtime relative to total system runtime of 95%. Secondly, we introduce a quantization method as part of a computing framework that converts data from single-precision to Int8 format. This reduces the memory usage of the simulation of system dynamics by half and strongly reduces computational complexity. At the same time, the solution accuracy is maintained at 99% compared to single-precision implementations. Lastly, built on these findings, we propose an implementation of quantized simulated bifurcation machines (qSBM) as an Ising machine on an FPGA, which is co-optimized between data flow and hardware. The co-optimization improves both the hardware design of the FPGA and accelerates the sparse matrix-vector (SpMV) operation. We demonstrate 10-fold to 68-fold (average 39-fold) speedups compared to previous state-of-the-art sparse FPGA implementations of Ising machines21. This sparse-to-sparse comparison highlights the architectural advantages of our approach.

Hardware implementations of Ising machines

Implementations of Ising machines have been explored on several hardware platforms. For practical usage, it is important to achieve high performance in terms of accuracy and execution speed, input flexibility, and scalability.

General-purpose CPUs provide maximum flexibility, but are inefficient for fine-grained parallel-spin simulations, see Fig. 1a. Here, the Ising simulation has to be compiled into assembly code and executed by only a few cores (two in the example). GPUs offer substantial parallelism for spin updates by providing thousands of execution threads and have been used to accelerate Ising simulations26, yet their performance remains limited by memory hierarchy constraints, as the data moves between the host device and the GPU very often, see Fig. 1b.Fig. 1FPGA-based Ising machines in comparison with other Ising machine architectures.a CPU-based simulation, where compiled assembly code is stored in memory and executed on two cores. b GPU-based simulation using CUDA code compiled into machine instructions, dispatched by the host CPU, and parallelized across thousands of threads. c DAU, where parallel runs of simulated annealing are performed via a dedicated digital chip, assisted by a server. Dedicated Application-Specific Integrated Circuits (ASICs), such as Fujitsu’s Digital Annealer27 (see Fig. 1c), deliver the highest performance and energy efficiency through custom-designed threading of solver executions. However, the algorithm departs from the fine-grained parallel-spin simulation and implements a replica variant of simulated annealing, which is a discrete optimization algorithm differing strongly in convergence properties and parallelizability. In addition, the Digital Annealing Unit (DAU) can run only small- to medium-scale problems with a few thousand variables.

Emerging paradigms such as quantum annealing28 are implemented in a superconducting hardware architecture, which can reach solutions more efficiently in theory through quantum tunneling (Fig. 1d). However, run-time limitations strongly constrain machine accuracy, and scalability has been considered very challenging29,30. Photonic implementations of coherent Ising machines9 realize a combination of optical cavities and FPGAs (Fig. 1d), where a fiber cable guides the pulses and the FPGA serves as a data channel and matrix-vector multiplier. However, the design struggles with variable inputs and solution accuracy due to noise.

FPGA-based simulators can be configured to implement a custom spatial architecture with parallel matrix multiplication and time evolution (MMTE) engines, see Fig. 1e. This approach offers near-ASIC efficiency while maintaining reconfigurability, making the FPGA a highly flexible platform. Furthermore, the high multithreading capabilities of the FPGA-based architectures enable simultaneous updates of thousands of spins with minimal communication overhead20, avoiding the memory bottlenecks of conventional architectures such as CPU and GPU. The primary constraint is on-chip memory capacity. The number of spins that can be simulated is limited by the available block RAM (BRAM) needed to store interaction coefficients (Jij) and local fields (hi). As problem sizes increase, storing the complete interaction matrix becomes challenging, necessitating efficient external memory access strategies. This work addresses this limitation through a novel architecture that optimizes data flow and memory hierarchy for large-scale sparse Ising problems, pushing the boundaries of reconfigurable computing while maintaining flexibility and precision.

TCOO: high efficiency data storage

The computationally most complex operation in the simulation of the Ising machine dynamics is the matrix-vector multiplication Jx in Eq. (3). In the following, we introduce a new sparse data storage format, called the tiled coordinate list (TCOO), which stores the matrix J more efficiently and allows significant computational speedups. For a more detailed overview of the most common storage formats used in the following, we refer to Supplementary Note 2.

The data format in this work is based on the coordinate list (COO) format, introduced in31. The idea is to compress non-zero (NNZ) matrix elements into an array (col, row, value), denoting the column and row position of the element in the matrix, as well as its value (see Supplementary Fig. 2). We observe that the overhead of addressing the coordinates of an element will increase with the matrix size and eventually form a computational bottleneck. To resolve this issue, we partition J into tiles of size M × M, where M is an adjustable parameter. During matrix-vector multiplication, tiles within the same column are multiplied by the same vector segment. Hence, contiguous tiles in the same column are grouped as a column block of length K. When a processing element (PE) multiplies a tile by the respective vector segment, it loads the segment into its local memory. To avoid repetitive loading of the vector segment, a larger column block length K is favorable, but generally, K is limited by the local result memory size of the PE. Figure 2b shows one example with K = 4.

The column blocks are further arranged in row blocks of length H, see Fig. 2b, where H = 12. There are in total I = 3 row blocks in the example, indicated by different colors. In sparse matrix-vector multiplication (SpMV), parts of the resulting output vector are computed earlier and can be readily used for further processing. For Ising machines, this allows us to simulate parts of the dynamics already, while the other parts of SpMV are being computed. The height of the row block K * M determines the size of the parts.

During SpMV, the PE needs the coordinates of a tile to load it from the off-chip memory and to multiply it with the respective vector segment. The coordinates are also called the header and are received by the PE at the beginning of a calculation. For a tiled matrix with column block length K, row block length H and total number of row blocks I, the header of the tiles is a tuple (k, h, i), with k = 0, 1, ..., K − 1, h = 0, 1, ..., H − 1, and i = 0, 1, ..., I − 1. For example, in Fig. 2b tile d has the coordinates (2, 5, 0).

The compressed data in TCOO then consists of an array with several different elements, see Fig. 2c. Firstly, an 8-bit zero 0 is prepended to the header as an identifier, telling the PE during processing to treat the header as the tile address instead of processing it as a value. We choose an 8-bit zero to ensure that after insertion, the data boundaries will not shift, keeping the data aligned to the data bus width of the hardware, see Supplementary Fig. 7. The identifier and header are followed by the values in the tiles. Each value is an NNZ with a tuple (col, row, value) indicating the position of the value inside the tile. Note that this differs from the COO format in Fig. 2a. If we consider, for illustration purposes, the single value with COO coordinate (1, 5, 3), the TCOO format reads [0, (0, 1, 0), (1, 2, 3)].

We conclude by commenting on implementation efficiency trade-offs depending on the parameters in the TCOO design. Small values of the tile size M increase the number of headers, which leads to higher bandwidth consumption to transmit headers instead of NNZ, lowering the performance. Large values of M, on the other hand, reduce the utilization of the PEs due to decreased parallel processing. Small values of column block height K lead to frequent vector loading, which causes PEs to stall due to memory contention. Large K, on the other hand, reduces the parallelism of the PE processing and increases the consumption of hardware resources. The number of row blocks I and the length H determine the execution performance of SpMV, as short rows increase the loading frequency of the vector in the PE, while long rows decrease the parallelization in processing. To systematically explore these trade-offs, our implementation fully parametrizes both the TCOO format and hardware architecture, see Supplementary Note 3. This enables hardware-software co-optimization through exhaustive design space exploration. The final parameter selections are detailed in the Supplementary Note 6.

We benchmarked TCOO on graphs from the Gset graph collection32 and found that TCOO achieves, on average, a 30.49% higher compression ratio compared to COO, and 22.11% compared to improved bitmap coordinate formats such as BCOO. (See Supplementary Table 3 for detailed data). However, we observe that in specific cases, CSR533 outperforms TCOO. The detailed discussion is given in Supplementary Note 4. This performance difference stems from the inherent structural limitations of simple tiling when applied to matrices with highly irregular, banded sparsity patterns. If the tiles are perfectly aligned with dense bands, TCOO performs well, but for matrices with intersecting band edges that contain few non-zero elements, the storage efficiency is reduced as the fixed header overhead dominates.

Data Flow

The compressed TCOO data array of each tile is stored in off-chip memory (DRAM). To balance the workload of the PEs, a data queue for the tiles is scheduled in DRAM by a bin-packing algorithm that considers the vacancy of the PEs (denoted in a working queue) and the number of non-zeros in the column blocks, as described in the following. The column blocks are sorted by the number of NNZ. Then, the column block with the most NNZs is scheduled to the most vacant PE until all column blocks have been scheduled. The column blocks are written into DRAM in the same order as the scheduling.

A Dispatcher assigns the queued block from the DRAM and the respective vector segments to the PEs. The vector segments are of the same dimension M as the tiles and indexed by the same label h of the header (k, h, i) of the tiles. Then, each PE executes the matrix vector operation, stores the output in local memory, and receives the next unassigned block and vector segment from the dispatcher. The processing on the PEs is done fully in parallel. Once all column blocks in one row block are processed, the PEs add up the local SpMV results and send them to the gather element (GE). The GE uses the results to simulate parts of the Ising dynamics. The Dispatcher loads the tiles from DRAM and puts them with the respective vector segments on the PEs, which perform partial SpMV in parallel. Before moving on to the next row block, all tiles in the current row block are processed such that the PEs are vacant again. This is necessary as each PE stores the outputs of the local multiplications, and because multiple PEs process the same row block, each of the PEs will contain part of the result. This leads to the partial sum issue identified in34, which is overcome by an accumulation element that performs a simple addition of parts once a row block is fully processed. The resulting vector segment is sent to the gather element (GE), which computes the time evolution (TE) of the system corresponding to the segment. The dispatcher then moves on to the next row block. After all row blocks are processed, the combination of all resulting vector segments carries the full result of one TE step of the Ising simulation.

Previous work39 has evaluated the performance of Ising machines under different quantization schemes and found good results with uniform quantization, while other schemes, such as logarithmic quantization, exhibited instabilities (see Fig. 4). We propose a uniform binary quantization that scales the original value range for the system states xi ∈ [−1, 1], i = 1, 2, ..., N, to integers xi ∈ {−2n+1, ..., 2n−1} (see Fig. 4), since integer multiplication is more compatible with the FPGA lookup table (LUT), see Supplementary Note 5.Fig. 4Quantization schemes.a Uniform quantization; b Uniform binary quantization; c Logarithmic quantization.

In Ising machine simulations (see Eq. (3)), the initial state x(t = 0) of the system is picked at random with entries close to zero. In uniform binary quantization, the state is scaled accordingly by choosing the closest discrete values. It was shown that such adjustments to initial state values can improve performance for random graph instances40. In addition, system parameters such as p(t) and coupling ξ are also quantized accordingly. Note that the behavior of the Ising machine usually relies on a specific temporal schedule for p(t). Quantization changes such a schedule, which can disturb the convergence properties. For that reason, we use smaller step sizes Δt based on experimental results.

Quantization reduces the vector BRAM consumption of FPGAs by approximately 50%. In the implementation shown in Supplementary Table 5, this saves 48 BRAM tiles (15% of total FPGA BRAM).

Quantized Ising machines

We benchmark the performance of Ising machines with uniform binary quantization against single-precision implementations. We choose ballistic simulated bifurcation (bSB) as it has been shown to achieve consistently high accuracy on different benchmarks40. The dynamics of bSB execute additional thresholding mechanisms for error mitigation purposes (Supplementary Note 1). The quantized bSB algorithm, which we refer to as qSB in the following, is explained in detail in Supplementary Note 1.

For benchmarking, we choose random instances of the Max-cut problem (see “Methods”) from the Gset graph collection32, which has become a standard testbed for Ising machine performance assessment41. The selected problem sizes range from 800–4000 nodes. For each instance, ten separate runs are conducted, each with 1000 iterative steps. As shown in Fig. 5, in more than half of the instances, qSB has better solution accuracy than single-precision bSB, such as for G19, G21, G47 and G31, and matches it in most others. In the remaining few, the accuracy is within 99% of the single-precision floating point implementations. The Gset benchmark offers a controlled but simplified testbed, with weights { − 1, 0, + 1}. To ensure that our quantization advantages generalize, we provide additional results in Supplementary Figure 12 on graphs with diverse weight distributions, as well as performance benchmarking on more general QUBO problems: balanced minimal cut (bmincut), and QPLIB problems42, which include constrained problems with a wide numerical range of couplings, structural heterogeneity, and mixed sparsity. To understand the impact of quantization and parameter tuning on the performance of qSB, we perform a controlled ablation study in Supplementary Note 5. We find that quantization alone worsens the performance, as reduced precision induces larger local errors per step and coarsens the state-update granularity, which impacts the solver’s ability to navigate the energy landscape. Consequently, applying Int8 quantization without any additional adjustments (Config B) leads to a notable increase in variance in certain instances. However, re-tuning the system parameters—most notably the time step Δt—not only recovers the performance but allows for even surpassing the Float32 baseline, see Config C. Concretely, the quantized system is found to achieve better accuracy, a lower average deviation and significantly lower variance. Importantly, this recovery is not achieved by trading computational efficiency for accuracy, as all experiments were conducted with an identical number of total steps. The inherent nonlinearities introduced by quantization, such as dynamic clipping and variable binarization, naturally align with the intrinsic nonlinear processes of the bSB algorithm. In summary, quantization alone does not offer a drop-in benefit; it must be paired with appropriate parameter re-tuning to realize its full potential. In practice, this re-tuning is a one-time offline step per problem class and does not compromise runtime efficiency, enabling the hardware gains (e.g., reduced memory footprint and integer-arithmetic acceleration) without sacrificing solution quality.

Co-optimized Ising machines on FPGA

Previous implementations of Ising machines in FPGAs suffered from several shortcomings. On dense FPGA architectures20, the size of the optimization problems was limited to small-scale problems of around 4000 variables. In sparse FPGA architectures21, scalability was demonstrated to problems with up to 200,000 variables, but the runtime was 2–3 orders of magnitude slower than in dense architectures. In the following, we propose a sparse hardware-software co-optimized FPGA design that realizes the scalability of previous sparse approaches while at the same time achieving state-of-the-art solution speed.

The design, which we call qSBM, is based on co-optimizing the FPGA architecture with the data format TCOO, the algorithm qSB, which utilizes Int8 precision, and the corresponding data flow. We implement qSBM on Xilinx ZCU106 FPGA using SpinalHDL, a high-level hardware description language. In comparison, the state-of-the-art dense design K200020 is implemented on Intel FPGA Arria 10 GX 1150 using Verilog, and the state-of-the-art sparse design MA21 is implemented on Xilinx FPGAs ZCU106 using Vivado HLS. The complete implementation and hardware design are explained in the Supplementary Note 3, Supplementary Table 2. We focus here mainly on the benchmarking of qSBM against the two designs mentioned above.

The performance benchmark results are summarized in Fig. 6. We compare our qSBM design P4, which has 4 PEs, against the state-of-the-art sparse FPGA simulated bifurcation machine (SBM) MA21. The time to target is defined as the duration required to achieve 99% of the best known solution for an optimization task, which typically involves 1000 steps in bSB. The TCOO parameters M and K were decided prior to implementation and set to M = 64 and K = 8 (Supplementary Note 6). To evaluate the performance on large-scale Ising problems, we generated three sparse graph sets (A1, A2, A3), containing graphs of sizes 10,000, 16,000 and 20,000 nodes. They are constructed to match the number of non-zero elements of the reference test cases21C1, C2, and C3 (containing 524,000, 786,000, and 1,048,000 non-zero elements, respectively) used by MA. All graphs have density <1%. Our simulations demonstrated consistent average speedups of 22.3x, 22.5x, and 18x across the sets compared to the sparse design MA, with net execution times of 112.2 ms, 222.2 ms, and 166.8 ms. In particular, the distribution of graph elements, whether randomly distributed or tile-centered, did not affect the observed speedups, confirming the robustness of our design and the direct architectural improvements over previous approaches.

We also provide a fair comparison of architectural efficiency against the dense design K2000. We focus our analysis on Gset instances where the dense baseline K2000 is not hindered by algorithmic convergence issues (see Supplementary Note 4 for methodological details). Among the 45 such instances, our sparse P4 design achieves a lower time-per-step in 25 cases, with an average speedup of 5.1x. This includes significant speedups on challenging instances (e.g., ~38x on G14, ~71x on G35, ~135x on G37). This comparison underscores the fundamental efficiency of our sparse architecture: its execution time scales with the number of non-zero entries, whereas a dense solver’s time scales with N2.

To understand the sources of the performance advantages, we conducted a systematic ablation study to explore the individual impact of the tiled format, bin-packing-based load balancing, and hardware hazard handling within our TCOO architecture. As detailed in Supplementary Note 6, each component contributes significantly. Concretely, we find that bin-packing-based load balancing alone yields an average speedup of 1.2x. Independently, hardware hazard handling provides a more substantial average speedup of 2.5x by eliminating 59% of the graph preprocessing overheads. Most notably, the full integration of these techniques achieves a combined speedup of approximately 3x over the baseline on the Gset benchmark. This result validates the effectiveness of our integrated architectural approach.

Discussion

We developed an FPGA-based sparse Ising machine design that achieves a state-of-the-art solution speed for sparse binary optimization problems of up to 20,000 variables on a single FPGA unit. The implementation of the Ising machine on-chip is co-optimized between the software layer and the hardware design. Compared to previous implementations, this offers a speedup of one to two orders of magnitude (10-68x) over sparse architectures, and a scaleup over dense architectures of 5x. Note that with further optimization of the size of TCOO headers, the FPGA design proposed in this work is capable of handling larger problem sizes of up to 100,000 variables.

The FPGA design is based on the main conceptual progress from the point of view of data storage format, data flow, and computing framework. Concretely, we introduced the tiled coordinate format as an efficient format for storing sparse matrices in off-chip memory. The format allows for strongly parallel processing and transmission of data, which has been shown to lead, on average, to 30% less memory usage compared to the COO format and 22% less memory usage than BCOO. The format also enables better workload balancing between multiple PEs, achieving 95% efficiency on average. Data were quantized to Int8 on a uniform binary scale, leading to 50% less required storage. Intriguingly, the quantized Ising machine was shown to maintain or even increase accuracy over the corresponding single-precision Float32 variants. In combination, a co-optimized FPGA implementation of bSB, called qSBM, was benchmarked against state-of-the-art sparse FPGA implementations and shown to achieve 18–22x speedup on large-scale problems.

A limitation of the current TCOO approach is its use of uniformly shaped (square) tiles. This leads to suboptimal storage efficiency for matrices with highly irregular, diagonally banded sparsity patterns. The issue is most pronounced at the boundaries of bands, where a uniform tile must encapsulate both dense and sparse regions. Consequently, edge tiles that contain only a few non-zero elements still incur the fixed per-tile metadata overhead. As shown in Supplementary Note 4, this specific edge-tile overhead allows CSR5 (a row-oriented format) to outperform TCOO in a few isolated cases (e.g., graphs G55, G56). For the vast majority of test cases with more uniform or clustered sparsity, TCOO maintains a clear advantage in storage.

From a top-level architecture view, the bandwidth between the off-chip DRAM and the FPGA chip is the bottleneck of the computation. Therefore, in future FPGA designs, an FPGA board with high-bandwidth memory (HBM) could be used, which typically increases the bandwidth by more than a factor of four compared to normal DRAM.

Solving Ising models with dynamical systems

Ising machines consist of a network of dynamical systems, which encode the optimization problem from Eq. (7) into the interactions between the systems. By evolving the systems under external control mechanisms, the systems output a state configuration that solves the optimization49. Many physical networks have been proposed as Ising machines, such as optical networks8,50, coupled oscillator networks49,51, and annealers52.

Embedding Ising dynamics into FPGA

Ising dynamics can be divided into SpMV and TE (see Eq. (10)). Hence, we use a scatter-and-gather paradigm53,54 to embed the dynamics in the FPGA.

In the scatter phase, SpMV J ⋅ x is computed using parallel LUT arrays configured as PEs. Each PE handles a subset of non-zero entries Jij, performing integer arithmetic for energy efficiency: \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$${(J\cdot {{\bf{x}}})}_{i}={\sum}_{j\in N(i)}{J}_{ij}{x}_{j},$$\end{document}(J⋅x)i=∑j∈N(i)Jijxj,where N(i) denotes the nearest neighbors of spin i. Then their multiplication reads \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$$A\cdot B={\sum }_{i=0}^{k-1}(A\cdot {b}_{i}){2}^{i},$$\end{document}A⋅B=∑i=0k−1(A⋅bi)2i,where bi is the i-th bit of B. In the gather phase, TE, encompassing all operations outside of SpMV (typically fixed-point operations), is mapped to digital signal processing (DSP) blocks.

To bridge the two computing modules, one ping-pong Random Access Memory (RAM) stores the SpMV outcomes from PEs for subsequent GE processing, and the other ping-pong vector RAM is deployed to store the spin state used in current steps, xt and yt, and spin state calculated for the next steps, xt+1 and yt+1, enabling simultaneous execution.

SpMV optimization

The execution of SpMV has some intrinsic hazards. Data hazards emerge when multiple threads violate the execution order constraints for shared result vector elements rk. Intra-stage hazards occur when concurrent threads read-modify-write the same rk within a single pipeline stage Sj, leading to unsynchronized updates. For instance, if two threads simultaneously read a vector element rk for accumulation, each thread updates the vector element individually as rk → rk + Δ1 and rk → rk + Δ2, while the correct result requires rk ← rk + Δ1 + Δ2. Inter-stage read-after-write (RAW) hazards arise when a stage Sj+1 prematurely fetches rk before the pending write from stage Sj. Structural hazards arise from hardware resource contention. When N threads attempt to write results via a BRAM with only two ports (N ≫ 2), the system must resolve conflicts through stalling or rescheduling, directly capping throughput at \documentclass[12pt]{minimal} \usepackage{amsmath} \usepackage{wasysym} \usepackage{amsfonts} \usepackage{amssymb} \usepackage{amsbsy} \usepackage{mathrsfs} \usepackage{upgreek} \setlength{\oddsidemargin}{-69pt} \begin{document}$${{{\rm{Throughput}}}}_{\max }=\frac{2\cdot {{\rm{f}}}_{{{\rm{BRAM}}}}}{{{\rm{cycles}}}/{{\rm{write}}}}.$$\end{document}Throughputmax=2⋅fBRAMcycles/write.

To resolve this, the PE employs a hazard detection unit that controls the latter part of the SpMV logic. It decides whether a single multiplied result in row r needs to be merged with other results in the same pipeline stage or forwarded to other pipeline stages, avoiding the wrong SpMV result. In addition, each PE has a local RAM that reads and stores vector segment, avoiding structural hazards.

Scalability

Prior SA-based Ising machines typically support 3-5-bit matrix non-zero weights55, and the dense SBM design K2000 is limited to 2 bits. The current hardware design natively supports 4-bit non-zero weights and activations to maintain algorithmic generality and processing speed, as increasing the bit-width further would lead to diminished processing capability and increase the resource utilization (particularly DSP blocks and LUT). Note that the architecture itself is fundamentally scalable to higher precisions (e.g., 8-bit integer or 16-bit floating-point) without structural modification, as the core dataflow and processing elements are parameterized by bit-width.
