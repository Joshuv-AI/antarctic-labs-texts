A blockchain-enabled scalable and secure architecture for cloud big data storage using sharding and swarming
Authors: R. N. Karthika, C. Valliyammai, V. UmaRani, G. Karthi
Published: 2026

ABSTRACT
Cloud computing enables on-demand access to centralized resources, including applications, networks, and storage, while big data and blockchain technology drive innovation in data management. The rapid growth of data stored in the cloud poses significant challenges, such as ensuring scalability, real-time analytics, and compliance with regulatory frameworks. Big data systems often struggle with elasticity, as many current solutions fail to provide rapid scalability under fluctuating workloads. To address these challenges, blockchain technology integrates big data storage in the cloud, creating a secure and efficient framework. Blockchain offers cryptographically secure, decentralized data management that enhances the reliability and value of big data for analysis. The novel architecture integrates sharding and swarming techniques to overcome the scalability limitations of blockchain-based big data systems and sharding partitions data into smaller fragments stored and accessed using unique partition keys, improving manageability and reducing system load. Swarming complements this approach by enabling parallel data retrieval from the fastest and nearest nodes, minimizing latency and enhancing access speed. An optimized Proof of Work (PoW) mechanism further ensures computational fairness and reduces energy consumption, addressing critical efficiency concerns. This integration of blockchain with cloud-based big data storage provides a transformative solution for secure, scalable, and high-performance data management, advancing decentralized applications and analytics capabilities.

Introduction

In the digital age, the increasing frequency and sophistication of cyberattacks, including large-scale ATM card and net-banking fraud losses reported in 2018–2019, have emphasized the urgent need for stronger security mechanisms in digital transactions1. The growing risks associated with centralized data storage systems have increased research interest in blockchain, a decentralized ledger technology originally introduced for peer-to-peer electronic cash transactions2. Blockchain improves data integrity, confidentiality, traceability, and transaction fairness by reducing dependence on intermediaries and by maintaining tamper-resistant distributed records3. It has also been widely studied from security, analytics, and implementation perspectives because of its ability to support trustworthy data exchange across heterogeneous digital environments4–6.

In addition to improving security, blockchain can enhance operational efficiency by addressing synchronization, accountability, and trust limitations commonly observed in conventional distributed and cloud-based systems7–10. By enabling multi-party access to shared data without compromising integrity, blockchain supports secure data sharing, consensus verification, and decentralized auditability in cloud environments11–13. The use of sharding techniques further improves performance by partitioning data or transactions into smaller fragments that can be processed in parallel, thereby improving load distribution, fault tolerance, throughput, and system scalability14–16. These features make blockchain a suitable candidate for securing and managing sensitive financial, industrial, healthcare, and cloud-based big data applications17–19. Blockchain technology has also shown strong potential in emerging Internet of Things (IoT) environments, where connected devices generate large volumes of sensitive and distributed data20–23. Its decentralized and cryptographic architecture supports lightweight, scalable, and privacy-aware frameworks that help prevent unauthorized access and improve secure data exchange among IoT devices24,25. Recent blockchain-enabled healthcare and pharmaceutical applications further demonstrate the suitability of decentralized frameworks for secure, trusted, and auditable data sharing in sensitive domains24–27. Similarly, blockchain integration with IPFS and decentralized storage models has created new opportunities for improving secure file sharing, access control, storage efficiency, and data availability28–30. The exponential growth of data generation and storage requirements necessitates scalable and secure data management solutions. As traditional big data providers face challenges related to adaptability, scalability, access control, and data integrity, integrating blockchain with cloud-based big data storage provides a promising solution9,10,12,29. This paper proposes a novel architecture for integrating blockchain with cloud-based big data storage by using advanced encryption techniques, an enhanced Proof-of-Work (PoW) algorithm, and cryptographic mechanisms to safeguard data. The proposed system also incorporates sharding and swarming techniques to optimize performance and ensure efficient storage and retrieval of big data. By combining these mechanisms, the proposed framework offers a secure and scalable solution for cloud-based big data management.

Research gap and motivation

Although several research efforts have been done on the integration of blockchain with the cloud computing and big data systems, current solutions still possess a number of limitations. Many blockchain-based cloud storage frameworks have a focus on improving the security and privacy of data but fail to sufficiently resolve the issue of scalability related to big data environments. Traditional blockchain architectures have issues of high computation overhead, latency increase, and low throughput when processing huge data groups.

Sharding-based solutions such as Elastico, OmniLedger, and RapidChain, provide increased transaction throughput through distributed processing of transactions; however, they are primarily interested in transaction validation and not in the efficient big data storage and retrieval. Similarly decentralized storage systems with technologies like IPFS enhance data availability but are often poorly integrated with blockchain consensus mechanisms and cloud infrastructures. Furthermore, most of existing frameworks do not contain a unified approach that simultaneously addresses secure storage, scalable data partitioning, efficient retrieval and computational efficiency.

To overcome the above limitations, this work presents the design of a secure and scalable architecture for big data storage supported by cloud computing, incorporating the approaches of sharding and swarming with optimized proof-of-work mechanism. The proposed system divides large blocks of data into several shards for parallel processing and uses a swarming mechanism based on the aggregation of Merkle trees to reconstruct large blocks of data efficiently. This integrated framework has improved scalability, reduced computational overhead, and big data security management in cloud environments to a great extent.

Proposed blockchain framework architecture for data protection

The proposed architecture for secure cloud storage employs advanced encryption methods, an enhanced Proof of Work (PoW) algorithm, cryptographic layers, and a distributed blockchain framework to ensure comprehensive data protection, efficiency, and scalability. The architecture is divided into several key modules, each contributing to data security, integrity, and performance:

User data input and encryption layer

At the core of the system lies the Data Encryption and Security module, designed to ensure robust data privacy upon input by users. The module initiates a multi-layered encryption process, as follows:SHA-512 Hashing: The data is first hashed using the SHA-512 algorithm, providing a unique fingerprint of the data. This ensures that even if an attacker gains access to the raw data, they cannot alter the information without detection.AES Encryption: After hashing, the data undergoes AES encryption, ensuring that unauthorized parties cannot decrypt the data without the proper decryption keys. This two-tier approach guarantees both data integrity and privacy within a cloud environment, where sensitive data is typically vulnerable to unauthorized access.

Enhanced proof of work (PoW) algorithm

The proposed blockchain framework introduces an optimized Proof of Work (PoW) mechanism designed to improve mining efficiency, reduce energy consumption, and dynamically adapt to network conditions. In conventional blockchain systems such as Bitcoin, miners repeatedly perform hash computations until a valid nonce is discovered that satisfies a predefined difficulty target. This brute-force search leads to high computational overhead and significant energy consumption.

Cryptographic layer and data integrity assurance

Once encrypted data is processed and ready for storage, it enters the Cryptographic Layer and Integrity Assurance module. Here, data is placed into immutable blocks within the Block Creating Layer. The immutability feature guarantees that once the data is committed to the blockchain, it cannot be altered or tampered with, preserving the integrity of the stored information. Transparency within this layer allows authorized parties to verify the data’s authenticity and ensure its correctness, strengthening trust in the system.

Sharding and swarming for efficiency

The swarming mechanism enables efficient reconstruction and retrieval of data blocks that have been partitioned through the sharding process. After a block is divided into multiple shards, these shards are distributed across different nodes in the blockchain network. During the retrieval phase, a swarm group is dynamically formed by selecting a set of nodes that store the required shards. Node selection is performed based on node availability, network latency, and computational capacity to ensure efficient data transfer. Each selected node contributes its corresponding shard to the swarm group, allowing parallel retrieval of shard data. The swarm formation process begins when a requesting node broadcasts a retrieval request for a specific block identifier. Nodes that store the corresponding shards respond to the request and join the swarm group. Once the swarm group is formed, shard data are transmitted simultaneously from participating nodes to the requesting node. This parallel retrieval mechanism significantly reduces latency compared to sequential block retrieval in traditional blockchain storage systems.

To ensure synchronization among swarm nodes, a lightweight coordination protocol is employed. Each shard is associated with a unique hash value generated during the sharding phase. When shards are retrieved from multiple nodes, they are verified using a Merkle tree structure. The Merkle root stored in the blockchain block header is used to validate the integrity of all retrieved shard fragments. If the computed Merkle root matches the original root stored on the blockchain, the reconstructed block is considered valid. The interaction between sharding, swarming, and blockchain consensus ensures both efficiency and security. In order to increase the level of clarity the swarm coordination process, as well as node selection, is formally described as follows. Swarm formation is carried out by selecting nodes characterized with the multi-criteria based decision making model where nodes are ranked in terms of (i) network latency, (ii) available bandwidth, (iii) computational capacity and (iv) shard availability. Each node is assigned a priority score with only those with a specified threshold being used in the swarm group. The swarm coordination has three distinct phases; Discovery Phase: Nodes that advertise relevant shard identifiers will respond to the request to retrieve data; (2) Selection Phase: The node that wants data will select the best nodes based on priority scores; and (3) Aggregation Phase: The best nodes will be selected to simultaneously provide data to the requesting node.

Swarm nodes are synchronized via a lightweight time-based coordination protocol that ensures that shard transmissions are made within a limited time window, otherwise the delivery of stale or non-consistent data is possible. A version identifier and a timestamp is added to every shard to ensure consistency of order in the process of reconstruction. Sharding, swarming and consensus integration is a pipeline. First, the setup of sharding spreads data to nodes to be stored and processed concurrently. Swarming can be used to aggregate shard data simultaneously during retrieval. Lastly, the reconstructed block is validated using the blockchain consensus mechanism (enhanced PoW), so that only verifiably reconstructed and validated blocks can be added to the ledger. This tightly coupled interaction ensures both scalability and consistency in the proposed architecture. Cloud-based blockchain integration

The final stage of the process involves integrating the immutable blocks into a cloud-hosted blockchain. The decentralized nature of the blockchain ensures that data is distributed across multiple nodes, offering redundancy and availability. Cloud-based blockchain integration provides a scalable solution, allowing for seamless expansion as the volume of data grows. The distributed ledger ensures that the data remains secure, transparent, and available for authorized users while retaining the benefits of blockchain’s inherent security properties, such as tamper resistance and decentralized consensus.

Proposed architecture for secured big data storage on cloud

Experimental setup and analysis

Experimental setup and analysis

The proposed blockchain-based secure big data storage framework was implemented and evaluated in the Big Data Analytics Research Laboratory at MIT Campus, Anna University. The experimental environment consisted of a private Ethereum blockchain network deployed on three computing nodes. Each node was configured with an Intel Core i7 processor, 16 GB DDR3 RAM, and 1 TB storage, running the Ubuntu 20.04 operating system. One node was configured as the master peer while the remaining two nodes functioned as client peers participating in the blockchain network. The blockchain platform was implemented using Ethereum with Ganache CLI (v6.x) with a block gas limit of 8,000,000 and an average block time of approximately 15 s for local blockchain simulation, and smart contracts were deployed using the Truffle framework. Each Ganache instance generated ten test accounts with 100 Ether per account to simulate blockchain transactions and smart contract execution. The nodes were interconnected through a peer-to-peer network using Ethereum enode addresses with full peer connectivity over a 1 Gbps local area network. The peer discovery mechanism was configured using static enode URLs to ensure stable connectivity between nodes. Mining operations were executed using both CPU and GPU configurations, where CPU mining utilized multi-threading (up to 8 threads), and GPU acceleration was enabled using CUDA-compatible devices when available. To evaluate the performance of the proposed architecture, datasets with block sizes ranging from 50 to 300 GB were used to simulate large-scale big data storage workloads. The proposed sharding mechanism partitions each block into multiple shards of 4 MB size, enabling efficient parallel processing across distributed mining nodes. The shard distribution across nodes was managed using the enhanced cuckoo hashing algorithm. During swarming-based retrieval, a maximum of 5–10 nodes participated in parallel shard transmission, depending on availability. Network latency between nodes was measured in the range of 2–5 ms within the local network environment. Depending on the total block size, the system generates multiple 4 MB shards which are processed independently using an enhanced cuckoo hashing approach. These shards are subsequently aggregated using a swarming mechanism based on a Merkle tree structure to reconstruct the final block before it is appended to the blockchain stored in the cloud environment. The experimental evaluation focuses on performance metrics such as block generation time, memory utilization, computational cost, and transaction throughput, enabling comparison of system performance before and after implementing the proposed sharding and swarming mechanisms. The experimental configuration, blockchain parameters, and dataset generation process have been documented to facilitate reproducibility of the results by other researchers using a similar private Ethereum environment. Large-scale deployment considerations

While the proposed framework demonstrates strong scalability through analytical modeling and controlled experimental evaluation, its applicability to large-scale real-world deployments is also considered. In practical cloud environments, the architecture can be extended to operate across geographically distributed data centers, where shard distribution is managed dynamically based on workload and node availability. The integration of sharding enables horizontal scaling by increasing the number of participating nodes without significantly impacting system performance. In large-scale deployments, the swarming mechanism can leverage distributed peer-to-peer networks to dynamically form retrieval groups across regions, thereby maintaining low latency even under high data demand.

Furthermore, the adaptive Proof-of-Work mechanism can be tuned based on available computational resources, allowing efficient operation in heterogeneous environments consisting of both high-performance servers and resource-constrained nodes. Although the current implementation is validated on a private Ethereum-based test network, the proposed architecture is compatible with scalable blockchain platforms and cloud-native infrastructures such as containerized environments and distributed storage frameworks. Future work will focus on validating the system over large-scale public or hybrid blockchain networks and integrating with real-time big data pipelines to further demonstrate practical deployment feasibility.

Security threat model and attack resistance analysis

To evaluate the security robustness of the proposed blockchain-based cloud storage framework, a threat model and attack resistance analysis are presented. The system assumes a distributed blockchain network where nodes may behave honestly or maliciously. Attackers may attempt to compromise the system by controlling multiple nodes, manipulating shard data, or attempting to disrupt block validation processes. The proposed architecture incorporates several mechanisms to mitigate these threats.

Shard takeover attack

In a shard takeover attack, a malicious adversary attempts to control the majority of nodes responsible for processing a specific shard in order to manipulate shard data. In the proposed framework, shard fragments are distributed across multiple nodes in the network using a randomized allocation strategy. Since shard fragments are processed independently and later verified using a Merkle tree structure, an attacker must compromise multiple nodes simultaneously to successfully alter the data. Furthermore, the reconstructed block is validated through blockchain consensus before being appended to the ledger, preventing malicious shard modifications from propagating through the system.

Sybil attack

A Sybil attack occurs when an adversary creates multiple fake identities to gain disproportionate influence in the network. The proposed framework mitigates this attack by employing an enhanced Proof-of-Work mechanism that requires computational effort to participate in block mining. Since each node must perform cryptographic puzzle solving to contribute to the blockchain, creating multiple malicious nodes requires significant computational resources, making large-scale Sybil attacks economically infeasible.

Swarm manipulation attack

In the swarming mechanism, shard fragments are retrieved from multiple nodes in parallel. A potential attack scenario involves malicious nodes providing incorrect shard fragments during swarm retrieval. To prevent this, each shard is associated with a cryptographic hash generated during the sharding phase. During reconstruction, shard fragments are verified against the Merkle root stored in the blockchain block header. If any shard fragment fails the integrity check, it is discarded and re-requested from other nodes in the network. This verification process ensures the correctness of reconstructed blocks even if some swarm nodes behave maliciously.

Proof-of-work attacks

Proof-of-Work systems are susceptible to attacks such as double spending or majority (51%) attacks. In the proposed architecture, the enhanced PoW mechanism incorporates adaptive difficulty adjustment and distributed mining across multiple nodes. The dynamic difficulty adjustment mechanism prevents attackers from rapidly generating blocks under fluctuating network conditions. Additionally, because blocks are validated across multiple nodes before acceptance, the probability of a successful majority attack is significantly reduced unless an adversary controls the majority of the network’s computational power.

Security implications

The combination of encryption, sharding, swarming, and blockchain consensus provides multiple layers of protection against common blockchain attacks. Data confidentiality is ensured through AES encryption and SHA-512 hashing, while data integrity is verified through Merkle tree-based validation. The distributed nature of shard storage and swarm-based retrieval further increases resilience against node compromise. As a result, the proposed architecture provides strong security guarantees for cloud-based big data storage while maintaining scalability and performance.

Conclusions and future work

In this paper, blockchain-based big data storage on the cloud is introduced to resolve the security problem in the cloud and scalability issues that arise in blockchain. Sharding and swarming are the techniques introduced to reduce the computational time and increase the performance of the system. The proposed blockchain-based secured big data storage minimizes memory utilization in turn, increases the performance by maximizing the processing transactions per second with the Ethereum framework. It’s impossible to know how many shards are feasible right now, but the throughput requirements of blockchain users are unlikely to outgrow the limitations of sharding in the future. The number of nodes needed to safely run such a prodigious number of shards is orders of magnitude greater than the total number of nodes running all blockchains together. The proposed work can be extended to address the scalability problem of blockchain using different types of sharding such as quadratic sharding, state sharding and polysharding to improve the throughput. Although the current prototype implementation utilizes a three-node blockchain network for experimental validation, the proposed architecture is designed to support larger distributed environments. Future work will focus on evaluating the system using large-scale simulations and multi-node cloud deployments to further validate scalability and performance improvements.
