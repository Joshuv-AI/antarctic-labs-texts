Building morphologies of the USA structures database; a gauntlet feature set
Authors: Taylor Hauser, Clinton Stipek, Nagendra Singh, Jessica Moehl
Published: 2025

ABSTRACT
In recent years there has been a proliferation of methods and data to extract building footprints from satellite imagery. However there has been very little effort to provide additional insight about these buildings beyond their spatial location and shape. Features derived from their geometries can be used to better characterize these buildings which are critical for further research and development. In this work a set of 65 unique features for every building for more than 131 million buildings covering the US has been developed. This rich feature dataset will enable researchers, policymakers and various agencies to derive additional building characteristics like height, occupancy type, and help to gain valuable and new insights of the built environment.

Background & Summary

As cities grow at a global scale, buildings have become a core unit for the expanding built environment. While extracting building outlines from satellite imagery1,2 have become robust over the years, work using features derived from building outlines is limited due to lack of such data. In this work we present a robust workflow to derive 65 unique features from building geometries for every building in the US. The process known as the Geographic Augmentation of Extracted Building Features Tool (Gauntlet) can be used efficiently to generate a building attribute set of 65 distinct features for any given building.

These feature sets have already been successfully used for six different use cases. Two of the use cases simulate attribution of buildings, use type3 and building heights4. The four other use cases are across a broad swath of research domains proving the utility of such datasets. The original use case was for assessing the quality of building feature extraction2. Researchers have used Gauntlet features to investigate class imbalance and various sampling techniques5. In another study, Gauntlet features were found useful in a data driven approach to bin the built environment which outperformed expert domain knowledge6. Lastly, using Gauntlet features, researchers devised a new machine learning model architecture using a hierarchical meta-learning approach7.

Selected Morphology Datasets.

The Global building morphology dataset for urban hydroclimate modelling (GLAMOUR)8 is a raster-based dataset that is derived from Sentinel 1 imagery which produces average height values. Global Building Morphology Indicators (GBMI)9 generates 380 metrics, many of which are building level metrics at various spatial scales derived from Open Street Map (OSM) building polygons. Los Angeles Building Morphology Parameters (LABMP) contain 132 urban metrics at 100 m × 100 m × 5 m cubes that describes building geometries with height10. The last dataset in Table 1 is Gauntlet which is described in detail in the following sections.

As huge volumes of building datasets become publicly available, there is a growing need to enrich these building datasets with more attribution. The Gauntlet feature set, when combined with other built environment features, such as height or use type, will provide robust training data that has become critical for a broad swath of domains such as emergency response, population dynamics, energy consumption, impacts of urbanization on climate, among others.

Methods

The earliest iterations of Gauntlet utilized ancillary data to create additional features. Ancillary data in this sense is any additional datasets other than the building polygon dataset. These ancillary datasets were, for example, the National Land Cover Database (NLCD)11 and a licensed road network dataset. The NLCD value was assigned to the polygon as a categorical attribute according to the polygon centroid. Another early feature was the measure to the nearest road from the polygon’s closest edge. Collectively these features were grouped as ancillary features.

Issues began to arise as the imagery used to extract the building geometries was much more recent than these ancillary datasets or beyond their coverage. Gauntlet needed to be able to generate morphologies on any polygon dataset regardless of location and availability of current supporting datasets. Because of this need for flexibility, these features generated from ancillary datasets were dropped. The ancillary feature category was retired and replaced by the contextual category of features. This change in feature categories represents the Gauntlet feature set version 1.0 from 2020. Since then, there has been a significant increase in features in the contextual category. This paper describes the Gauntlet version 2.0 feature set developed in 2023. The features we selected for inclusion in this dataset are the features we have found to be informative features through published literature2–7. Furthermore, these features function well on a variety of building polygon data sources which span the world without the need for ancillary data and can be computed within reasonable amount of time. Preprocessing

The source building data for this Gauntlet feature set is USA Structures12. USA Structures was chosen because of its rich attribution that could be used for potential training labels. USA Structures is divided by state. Each state is stored within its own file geodatabase (file GDB) as a feature class. We use a spatially enabled Postgres database with the PostGIS extension to store the original geometries and attributes from the source.

As feature classes from each file geodatabase were ingested into the central postgres database two preprocessing steps were conducted. First, the geometries were evaluated for the appropriate Universal Transversal Mercator (UTM) zone projection. Secondly, Square Meters (sqmeters), Square Feet (sqft), Latitude (lat), and Longitude (lon) were calculated based off the identified UTM zone projection and stored in the database with the geometries maintaining their original projections. The building dataset has no projection and the original datum is World Geodetic System (WGS) 84.

Features Categories

The 65 features that Gauntlet generates fall within three categories: Geometric, Engineered, or Contextual. Geometric features are simple measures of geometry that describes a physical characteristic of the geometry. Engineered uses two or more geometric features to describe more complex measures of geometry like compactness or complexity. Lastly, the contextual features describe the geometry and its relationship to neighboring geometries within a set distance. Contextual features attempt to replace the need for calculating features using ancillary datasets. This provides a benefit for scaling workflows without the concern of completeness or coverage of other datasets. Contextual features are calculated on multiple scales as inspired by the work of Milojevic-Dupont’s work using urban form to predict building heights13. Many of contextual features are derived using spatial point pattern analysis14,15 and have been studied in earlier works16. Table 2 provides a brief description of the current Gauntlet features. Geometric Features

Geometric features are the simplest and derived from the direct measurement of a physical property of the geometry. Three of these are features of the geometry’s area in different units: sqft, sqmeters, Shape Area (shape_area). There is one measure of perimeter length: Shape Length (shape_length). Vertex Count (vertex_count) is a count of all the vertices in the geometry. The last feature in the geometric category is Geometry Count (geom_count) which is a count of the number of polygons used to create the shape of the geometry. Most geometries of USA Structures will only have one polygon, occasionally a geometry might have a hole like a courtyard. This hole is represented by a second inner polygon, and the geom_count would be two for this example geometry.

Contextual Features

Contextual features provide information about how a building geometry relates to its neighbors. The neighbors of a building geometry are all the building geometries whose centroids are within a specific distance. This radius will be referred to as a scan window. Once the neighbors are identified a series of measurements are calculated with the scan window centered on the building geometry being evaluated. The process is repeated with larger scan windows to provide various levels of spatial context. The scan window radii are in 50 m, 100 m, 250 m, 500 m, and 1000 m.

Gauntlet generates two sets of contextual features. The first set being point pattern features, which describe the spatial relationships of all building centroids within the scan window. The second are scale related features, which describe the building areas within the scan window. Many of these features, but not all, have been discussed in previous work16,21 and shown to be successful in classification problems3,4,15,22.

Point Pattern Features

There are two foundational measures which we use to compute many contextual features. The first is Neighborhood Count (n_count) which is the count of all the building centroids within the scan window. To quickly identify the neighbors within the specific distance, we use a cKDtree from scipy23 which was originally proposed by Maneewongvatana and Mount24. The KDtree is a performant spatial index for querying point geometries (centroids) within specific radii. Once the total number of centroids are known within the radius we can then compute the second foundational measure: Nearest Neighbor Distance (nnd). nnd is the measured distance from one centroid of a building’s geometry the nearest neighboring building’s centroid. These two features are used to derive more sophisticated contextual features25.

Observed Mean Distance (omd) is the sum of the nearest neighbor distances of all centroids within the scan window divided by the n_count of the same scan window25. Each csv of the morphology dataset contains 69 columns. The schema of each csv consists of three field types. They are either an ID field, training label, or a Gauntlet feature. The uuid field is a universally unique identifier that corresponds to the USA Structures dataset and is the only ID field needed to join to the USA Structures dataset. For example, one may download AL_Structures.gdb from the Figshare source33 and join the Gauntlet alabama.csv dataset to the AL_Structures USA structures dataset using the uuid.

The next category of columns are training label fields. The training label fields come directly from USA Structures data and are occ_cls, prim_occ, and height. occ_cls is the overall occupancy classification of the building. This is a general category of building use. prim_occ is a lower level classification of with more specific labels. These are more specific categories of building use. For example, a building may have ‘Residential’ value for the occ_cls while having a value of ‘Manufactured Home’ in the prim_occ. The last label is height. This value represents the height of the structure in meters and comes directly from the USA Structures dataset.

The final category is the Gauntlet features themselves. There are 65 features per record which describe the morphology of the corresponding building in the USA Structures dataset. Each field has a column header that contains the name of the morphology feature. For example, in the methods section the meaning and formula for omd are given. Technical Validation

The morphology dataset is derived from the USA Structures database. A stratified random sample for each state was taken and found that all Gauntlet features were accurate. This means ten records from each state or territory were sampled. Only half of the sampled records could be residential. The Gauntlet features were calculated using QGIS software. We compared our calculations from QGIS to the python code base we call Gauntlet. We found that Gauntlet was properly handling spatial projections and calculating the described features correctly.

Since morphologies are simply a series of mathematical equations the remaining records are assumed valid. However, error can propagate from the original source data into the Gauntlet morphologies. The overall accuracy of the USA Structures database is discussed in Yang’s work2. For example, in Table 1 of Yang’s work they report that the F1-Score for Texas and Louisiana version 2 was 0.9262. In USA Structures error occurs one of three forms:Omission: A building exists but was not detected. (False Negative)Commission: A detection was included, but no building exists. (False Positive)Inaccurate Detection: A detection that partially represents a building, or overly represents a building by including surrounding area as part of the building detection. Some polygons may encompass more than one building.

If buildings are missed, omission, their absence will affect the contextual features of Gauntlet. Similarly false positives, commission, in the building datasets will impact the contextual features. We designed our methods to use the data as is and acknowledge that error in the source data can propagate into the morphology features.

Furthermore, the accuracy, or quality, of the extraction for a building could also have an impact. A partially extracted building could occur for numerous reasons: A tree overhanging a portion of a building, a cloud in the image, snow, or the image is too far from Nadir. For example, if a tree partially covers a building, the extraction algorithm2 will likely delineate the building outline to exclude the tree. This could produce a geometry that is not representative of the overall shape of the corresponding building within the image. A partial detection would lead to many inaccurate geometric, engineered, and contextual features. Another limitation can often be seen in cities, where one large polygon represents multiple buildings. A large polygon that represents many buildings would generate morphology features that do not describe the underlying buildings. Common examples of this would be row houses, strip malls, and apartment buildings with walkways that connect them. These limitations of the data directly impact and limit our methodology and morphologies produced by Gauntlet.

Usage Notes

We specifically designed this approach to allow the researcher to apply this approach to any footprint dataset, agnostic of source. This offers the user the flexibility to adjust both the spatial scale and source of footprints, such as footprints produced by Microsoft or Google. Therefore, there are various domains which this dataset can be applied to.

For example, Stipek et al.4 leveraged this morphology feature dataset to infer building height at a building-by-building level across the United States and Germany. To do so, they generated the feature dataset described in this article for each building within their area of interest. One of the first steps they did was to remove the square feet feature due to the dataset containing both a square meter and square feet feature. The authors then ran a recursive feature eliminator to streamline the features necessary to efficiently predict their target, building height. The remaining features were then standardized for use in their regression model. Their modeling workflow is publicly available34.

Other potential uses could be in relation to identifying other built environment targets, training data permitting. For example, previous work has leveraged morphology features in relation to inferring building age35 or the use type of a building3. However, researchers must use caution in relation to which features they would like to leverage and best ways to standardize the features. Researchers are welcome to offer suggestions and input in relation to enriching the feature dataset.

A further note for usage by researchers is that the quality of the underlying footprints must be considered. For example, in Africa, Gonzales36 found patterns of irregularity when comparing Google and Microsoft footprints at a building-by-building level. When investigating urban areas, Microsoft tended to generate larger footprints which may encapsulate multiple buildings while Google seemed to have more, smaller buildings. When rural areas were investigated, the building counts were relatively similar, showing little discrepancy. This is important to note as the features generated by this workflow may vary based on the quality of footprints leveraged.
