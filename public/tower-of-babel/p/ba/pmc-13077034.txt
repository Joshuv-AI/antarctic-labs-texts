A data migration and integration approach for big data management using linked data
Authors: Hina Sattar, M. A. Al-Khasawneh, Umar Farooq Shafi, Touseef Hussain, Abdul Khader Jilani Saudagar, Syed Zain Ul Abideen, Mian Muhammad Kamal, Said Baz Jahfar Khan
Published: 2026

ABSTRACT
The growth in volume of heterogeneous data that are being created by web, IoT, and enterprise systems remains a major challenge to Big Data management, specifically, in the integration and migration of structured, semi-structured and unstructured data. Conventional methods tend to take the data of one type and this restricts its application in the real world which is varied, high in volume and velocity. The framework suggested in this paper is an integrated model of Big Data migration and integration based on the Linked Data principles. The methodology presents a new pipeline approach that integrates Semantic Business Vocabulary and Rules with Natural Language Processing in extracting semantic constructs of unstructured and semi-structured data, and model-to-model transformation rules in transforming structured relational data into Resource Description Framework representations. It includes a lightweight DOM parser which is used to discern and maintain structural schemas of semi-structured sources like XML and JSON and maintain relational semantics in the conversion. The structure is carried out in two fundamental modules, analysis and synthesis modules: the analysis module that identifies and classifies types of data and the synthesis module that produces coherent RDF-based Linked Data results. Experimental analysis of the framework based on the precision and recall values proves the efficiency of the framework, with a mean precision of 90–97% and a recall of 82–94% in various datasets. It can be observed that the proposed system is better than the existing ones such as D2RQ and Triplify since it supports all three types of data in a single pipe and offers better structural recovery and query-equivalence accuracy. The work adds a scalable, semantically-aware approach to converting heterogeneous Big Data into interoperable Linked Data to enable the improved integration, migration and semantic web mining of data.

Custom data mining is much simpler than web mining because it works on data that is single and structured, along with aid from pre-loaded algorithms. In comparison, web data mining has a greater degree of difficulty because of the volume and intricacy of the Big Data problem that often comes with unmanaged unstructured and semi-structured data. Web mining aims to derive meaning from complex data sets – the content, structure, and usage of web resources. In its most basic meaning, web mining extracts of information from structured and unstructured web data. But, web mining can exploit its full potential in the processing of unstructured data, which is vital in the evolution of the semantic web2. The semantic web is an extension of the World Wide Web (WWW) by which meaning is added to web resources in a form that is understandable by machines, thereby facilitating more advanced information retrieval(IR). The IR methods that are available fall short of the expectations to fully encode the semantic knowledge contained in documents. Therefore, the results provided by these methods are not satisfactory. In contrast, IR technology has the highest degree of efficiency in the control of annotations in the languages of the semantic web. Linked Data is the basic structure of the semantic web because it connects together sets of data in a way that humans and machines can both understand. One of the most popular ways of doing this is the use of semantic web page and information Uniform Resource Identifier (URI)at the top of the page which describe the resources with properties and values has yet to be defined as a resource. The hieratic semantics of web data depend on the Resource Description Framework (RDF) which captures the semantics within a subject of the web. This captures the principal difficulties in the management of Big Data which in turn are the driving forces behind this investigation. Efficient web mining on a polar set of data (structured, semi-structured, or unstructured) is impossible without adequate data management. We refer to Big Data management as the compilation of policies, practices, and technologies deployed to manage the data in its complete lifecycle from collection to its governance, storage, organization, administration, and finally, delivery. While structured data is less complicated to analyze, the scalability, and schema rigidity, coupled with the relational databases become integration barriers in context of big data3. The complexity of Big Data management does not arise simply from the existence of structured, semi-structured, and unstructured formats. Instead, the challenge lies in their integration and migration into a unified representation, where heterogeneous structures must be transformed consistently into Linked Data for effective processing and analysis. Big data management solutions should consider the problems discussed above and provide services for handling data volume, complexity, integration, and migration5–9. In order to solve major challenges of big data arises due to scale, heterogeneity, and rapid generation of data. As opposed to the earlier research, which centered on the transformation of a single data format like RDB into RDF, this study shows an integrated, end-to-end solution that can be able to handle structured, semi-structured and unstructured data in a single transformation process. The proposed architecture combines Natural Language Processing, semantic analysis based on SBVR and model-to-model mapping, which allows introducing a new semantic integration mechanism that has been rigorously evaluated based on precision and recall measures across heterogeneous datasets. The framework is a systematic way of dealing with three dimensions of data variety. Syntactic diversity, which occurs due to variations in file format and schema as in the case of CSV, XML, and JSON, is handled by modular input adapters and an augmented DOM parser that normalize a wide variety of formats to a common internal format. Multi-level transformation pipelines deal with structural variety, which is due to the different data models, including relational, hierarchical and free-text sources, and transform each source model into a single RDF graph, preserving original relationships and hierarchies. Lastly, semantic variety, that arises out of differences in vocabularies, relationships, and contextual meanings across sources is solved through a combination of entity extraction using NLP and rule mapping using SBVR to find out any semantic relationships.

Literature review

In this section, we discussed about many efficient approaches proposed by different researchers for big data management. An efficient big data storage system was proposed in10, presenting IoT-based big data storage systems in cloud computing and highlighting their perspectives and challenges. Their study of IoT applications concluded that IoT-based applications have become a critical field for engineers and researchers. They proposed a functional framework for the automated identification, acquisition, management, processing, and mining of IoT big data. A comprehensive review of current research on IoT applications revealed the challenges and opportunities associated with IoT big data, providing a critical analysis of the research topic. Additionally, technical modules were proposed to describe the key characteristics and capabilities of IoT-based big data.

In2, the authors presented a Java-based software in Eclipse for triplication, where relational database (RDB) data is converted into resource description framework (RDF) triplets, a process known as RDB2RDF. This conversion involves two main phases: external schema creation, which includes various database views, and data conversion of relational data to RDF instances. The researchers introduced an Eclipse plug-in using the R2RML language, developed by the W3C RDB2RDF working group, to support RDB2RDF conversion based on an architecture tailored to the specifics of the triplication process11. The modular structure of the tool encapsulates change-prone mapping strategies, promoting information hiding and separation of concerns to support system evolution.

In12, the authors studied two W3C recommendations for RDB-to-RDF conversion: Direct Mapping and R2RML. While Direct Mapping uses a static set of transformation rules, R2RML can augment these rules. They proposed MIRROR, a conversion system with two sets of R2RML mappings. The first allows the R2RML engine to generate RDF triples similar to those produced by the Direct Mapping engine, while the second introduces additional knowledge from RDB, such as M-N relationships.

In13, the authors proposed Triplify, a method for RDB-to-RDF conversion. Their methodology maps HTTP-URI requests to RDB queries and converts query results into RDF statements, making them available as linked data on the web. Triplify integrates with web applications like osCommerce, WordPress, Drupal, Gallery, and phpBB, providing a lightweight tool for converting structured data (usually in RDB) into more accessible RDF formats14. D2RQ enables querying and browsing of relational databases and automatic RDF generation15. It includes an interface for database management and a D2RQ engine for the actual conversion. However, D2RQ has limitations, such as a complex vocabulary and official support only for specific database systems (Oracle, MySQL, PostgreSQL, SQL Server, HSQLDB, and Interbase/Firebird2).

The authors in16 proposed ULTRAWRAP that is applied to convert RDB to OWL ontology. The tool has capabilities to generate ontology of the SQL of the relational database in such a way that the user can query the generated OWL ontology with SPARQL. It does triples generation with SQL Views and optimizes queries with SQL optimization. The self-joins were determined to induce certain hiccups and the authors indicated that they would go the extra mile to ensure that SQL Server is optimized and made capable of performing efficiently in the said area.

Quality control of RDB2RDF mappings interested the authors of17,18. They demanded to ensure that RDF data is of high quality by measure of assessment of the mapping process. Their methodology defined 43 quality metrics of RDB2RDF and a prototype software based on the strategy was developed to test the dataset generated by the RDB2RDF strategies.

In19, the authors constructed a framework of analysis of RDB2RDF tool querying the analysis of the materials, interviews, and surveys. The three tools that were reviewed in the framework pointed to the problems concerning the tool stability and maturity within the field20.In21 the authors introduced an Eclipse plug-in to facilitate the production of the Direct Mappings over R2RML standard to produce RDF triples to convert the RDB triples to the RDF triples. In22, the research was conducted with the intention of examining how the Big Data technologies can be applied to study of the IoT data, particularly, the clustering algorithms. It exposed the challenge related to the application of the Big Data clustering algorithms to the IoT and the lack of research in the field. In23, the authors have mentioned certain complexities that arise in the process of transformation of RDB-to-RDF and most significantly on the relationship that will be developed in the transformation. The approach was plotted based on the aid of XML shared peculiarities of the RDB and semantic web schema. The authors found in24 the RDB2OWL which is a high-level database to ontology mapping language. It contains implementation tool, which transforms RDB2OWL mappings into executable D2RQ mappings to create a semantics SPARQL endpoint over RDB data.

The recent works have not limited themselves to the usual RDB-to-RDF conversion and examined more advanced methods of dealing with heterogeneous Big Data. However, in the unstructured data case, natural language processing techniques and ontology systems such as semantic enrichment pipelines and SBVR-based extraction have been in favor to extract entities and relations to create RDF. Scholars in the domain of IoT proposed that Karras et al.25 created TinyML on edge devices to clean, cluster, compress, cache, and hybrid sensor data and showed excellent output in two aspects; the quality of the data and performance. The article by Mansour and Alsaud26 focused on high-quality information acquisition approaches through the use of NLP, semantic search and machine learning with a bid to achieve greater accuracy and scalability of retrieval of large datasets. So, it is in this way that an ontology-based exposome research framework proposed by Diller27 can be viewed as an example of how the complicated biomedical and environmental data can be combined with the help of semantic technologies. Dhummad and Patel28 have their contribution by applying the advanced SQL techniques such as query optimization, schema mapping, and transformation regulations of a smooth data transfer between heterogeneous systems. In29 in the framework of smart cities pointed to the edge computing approaches to optimize latency, energy, and resources distribution in Big Data processing. One of such developments, which we add to it, is one framework in the form of which is the plain text processing inspired by SBVR and the structured and semi-structured articular processing of the data, with the ultimate pipeline of the Big Data transfer and the semantic fusion of data30,31.

Handling structured data in relational database form using proposed approach

Structured data means data in tabular form which is collection of rows and column. Unlike other two types of big data linked representation of structured data is implemented by using model transformation technique. We already know that Generation of RDF from relational data (structured data) is active field of research during last decades. Many tools and methodologies are presented for generation of RDF from RDB i.e. D2RQ server, RDB2Onto, DB2Triples etc. All methodologies and tools dealing with almost similar components of Relational database in different ways for Mapping RDB to RDF.As we know that tabular data have predefine structure (i.e. all tabular data have fixed construct). Despite from data values each database follows default layout. This common framework of structured data give rise to need of common RDF mapping mechanism which should work as generalized mechanism for RDB to RDF conversion. To provide standard conversion method we utilize M2M transformation in our current approach to develop a solution for providing linked representation of RDB. The M2M transformer consists of Reading Phase, Extraction Phase and Generation Phase.

Concept of relational database was based on relational model which was first formally introduced in 1970 by E. F. Codd. In Relational Model single unit of data storage is called relation/table. Complete set of data is organized in one or more than one tables. Table constitute of rows and columns. For each entity type there must be a table in system. Attributes of entity type converted in to column and instance values are stored in rows that is also called tuple or record25. RDF is Semantic web attach semantic details with web contents, make web content enable to process by machines. One way to attach semantic information with web content is attachment of semantic tag in web page. This could have done by extending URL system with URI which describe web resources in term of properties26. It is clear from above discussion that Semantic Web deal with syntax of data. language which supports semantic web is known as RDF.RDF enables semantic processing of information present on web page by using URI for data representation. It is simply graphing data model, which deals information of web page as resources having properties and values i.e. concept of URI. RDF represents web content as single statement having three parts i.e. Subject, Predicate and Object. As each statement contains three parts therefore it’s known as triplets.

RDF Triple is formed by using three basic elements of RDF.

To address the distinction between syntactic and structural variety, a schema inference step has been incorporated into the data preprocessing pipeline. When structured data are re-serialized into formats such as XML or JSON, the proposed system employs a lightweight DOM parser based XMLschema Inference to analyze the tag hierarchy and attribute structure. The parser reconstructs the implicit schema and identifies key–value relationships before semantic mapping. This step guarantees that serialization differences do not alter the structural interpretation of the data and that all relational constraints are preserved during RDF transformation.

Different techniques are used for the implementation of model transformations. Two basic techniques for model transformation are used in our approach. First one is the hard-coding with general purpose programming language and other is the use of dedicated model transformation language (MTL) for programming transformation rules that are executable by model transformation engines. MTL-based applications offer much enhanced proficiencies to review, exchange, update, delete or insert new transformation rules for managing transformation rules within the previously implemented application as compare to hard-coding technique. On the other hand, MTL-based implementations are proved unsuccessful in providing user interaction during execution. A dedicated transformation engine is needed by MTL for the execution of transformation rules and also the application possibly will be constructed before starting the transformation that might provide base in deciding its negative factor in some conditions. According to (Mens and van Gorp, 2006), Transformation development languages could be classified into three categories i.e. declarative, operational (imperative) and hybrid.

Limitations and future work

Although the proposed framework demonstrates significant improvements in integrating structured, semi-structured, and unstructured data into Linked Data, several limitations remain. First, the current focus for unstructured data is restricted to plain text; multimedia formats such as images, audio, and video are not yet processed. Second, while semi-structured data are integrated through text-based conversion, this may result in partial loss of structural hierarchy. Third, the evaluation was conducted on limited datasets and compared conceptually with existing RDB2RDF tools, but full benchmarking across diverse industrial datasets remains to be performed. Future research will address these limitations by:.

Enhancing semi-structured data processing by integrating DOM tree parsing and semantic attribute extraction for richer representation.Conducting large-scale benchmarking experiments against state-of-the-art tools to establish scalability and generalizability.Exploring real-time data migration techniques to better address the Velocity dimension of Big Data.Future work will extend unstructured-data handling beyond text by incorporating image, audio, and video analysis through feature-extraction pipelines and ontological tagging. DOM-based and multimedia-aware parsers will be implemented to preserve rich semantics in semi-structured and unstructured content. Extensive benchmarking using distributed computing frameworks will also be conducted to validate scalability and processing efficiency at Big Data scale.

Conclusion

The Big Data is not only growing exponentially, but it is becoming more complex as it is a complex combination of structured, semi-structured, and unstructured data. Big Data management needs a comprehensive method that has the capacity to deal with these various types of data. This heterogeneity is reflected in the web, which is the major source of Big Data: structured data makes up only 5 to 10% of web content, semi-structured data also occupies another 5 to 10% of the web content, and about 80% of it is unstructured content. This study is hence concerned with the Big Data management related to web data. The methodology that we suggest provides a combined approach of converting heterogeneous sources of data into consistent semantic representations irrespective of the format. The system automatically rebuilds the internal structure of XML andJSON data before semantic mapping by a DOM-based schema inference mechanism as part of the preprocessing and structured data modules. This will guarantee that structural or relational integrity is not jeopardized by syntactical differences. The implementation of the framework as a pipeline of transformation in various modular transformations that include data preprocessing, semantic extraction based on SBVR, and conversion of relational data to RDF data ensure structural and semantic consistency. This paper highlights why it is important to consider all the three V of the Big Data Volume, Variety, and Velocity in order to manage data effectively. Specifically, we broaden the concept of Variety to three different layers which are: Syntactic Variety, covering the borders of file format and schema variation like CSV, XML, or JSON; Structural Variety, covering the borders of other types of data models like relational, hierarchical, and free-text sources; and Semantic Variety, covering the borders of different vocabularies, relationships, and contextual meaning between data sources. These dimensions are addressed in a synergistic manner by the analysis and synthesis modules, such that: SBVR-based extraction leads to semantic relationships being captured, and model to model mapping rules address structural fidelity in the transformation. This is an integrated design that allows the framework to deal with the inherent heterogeneity of Big Data. The schema inference of the DOM showed significant advance on the accuracy of query-equivalence by almost 9% that shows its ability to capture the original relational semantics in the conversion of data. Altogether, the framework offers a unified approach to the integration of heterogeneous data into Linked Data, which makes data migration consistent and provides support of sophisticated semantic web mining.
