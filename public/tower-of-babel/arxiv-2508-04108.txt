XARP Tools: An Extended Reality Platform for Humans and AI Agents
Arthur Caetano, Misha Sra

Abstract
This technical report presents XARP Tools, an extended reality (XR) framework designed for human and AI developers alike. XARP comprises a server-side Python library and platform-specific XR clients. The library offers high-level APIs and communicates with clients via a JSON-based protocol over WebSockets. XR clients encapsulate device and runtime specifics, providing responsive, low-latency user interaction. XARP can be utilized in three ways: (i) as a library that abstracts XR development for humans; (ii) as a set of callable tools that allow AI agents to drive on-the-fly interactions with users; and (iii) as a Model Context Protocol server that plugs XR devices into AI ecosystems. XARP code and working examples are released openly at \url https://github.com/HAL-UCSB/xarp.

\teaser

XARP Tools provides a server-side Python API that allows human developers to control an XR client at a high level (e.g., voice input, access to egocentric camera, display text, or querying head pose). AI agents use the same API as callable tools, enabling dynamic, on-the-fly behaviors. XARP can also expose XR devices as MCP servers for integration with AI ecosystems.

This architecture separates concerns: server-side handles high-level application logic in Python, while the client manages low-latency tasks such as rendering and interaction in the XR runtime. This division isolates engine-specific functionality within the client, allowing the server-side to orchestrate XR building blocks in an application logic sequencing.
\cref
fig:arch shows an overview XARP Tools architecture.

Rapid Prototyping

XARP’s high-level Python API lets developers rapidly recombine XR functionalities without relying on XR engines or specialized editors. By decoupling application logic from engine-specific code, developers can modify behaviors or parameters without rebuilding or redeploying the client, accelerating development and enabling faster iteration. The reuse of a stable client runtime minimizes overhead, letting teams focus on application-level design over low-level engine mechanics. Our web UI also supports rapid prototyping by mocking XR devices (
\cref
fig:web).

Multiplatform

XARP’s architecture inherently supports multiplatform deployment. As long as clients for different XR platforms implement the same set of primitive tools, they can connect to and be controlled by the same server application. This unifies development across devices without requiring separate codebases or logic paths for each target platform.

Adaptable

As part of the XARP protocol, each XR client declares the set of tools and primitive tools it supports. This capability discovery step allows AI agents or applications to tailor behavior dynamically, based on the specific client they are interacting with. As a result, XR experiences can gracefully adapt to heterogeneous device capabilities and interaction affordances.

Figure 1:
XARP Tools Architecture: A server-side Python API offers high-level control to XR functions on the client-side through a JSON-based application protocol over Websockets. Our server reference implementation uses smolagents, fastapi, fastmcp, and LMStudio. A client maps commands received from the server into XR building blocks using a factory pattern. We offer a reference implementation in Unity and Meta Quest that can be adapted for other XR devices.

Tools

Currently, XARP implements a minimal set of tools: read, write, see, and head pose.
\cref
fig:teaser shows the Meta Quest implementation of some of these tools.

1.

Read
: requests a text input from the user. Implemented on the Meta Quest client as a virtual keyboard input with a voice input option.

2.

Write
: displays text to the user. Implemented on the Meta Quest client as a virtual keyboard with a voice input option.

3.

See
: captures an RGB frame from the XR device. The Meta Quest client returns an egocentric image from the left eye.

4.

Head Pose
: provides the position and orientation of the XR device. The Meta Quest client returns a quaternion and position of the HMD.

Figure 2:
XARP Web Client: XARP clients are interchangeable as long as they implement all high-level tools. For example, the see tool captures an RGB frame from the left-eye camera on the Meta Quest, but allows image uploads from the camera when using a web client on a mobile device. This enables rapid testing and supports multiplatform deployment.

2.2
Agent Toolkit Mode

AI code generation has accelerated various software engineering tasks
[
4
]
. In XR development, these benefits may be even more pronounced than in web or mobile contexts, given XR’s dependence on rich assets and its sensitivity to spatial and contextual factors. Beyond current applications of AI in asset generation and adaptive XR content, XARP enables a new class of use cases where AI agents can dynamically control and orchestrate XR environments. XARP can be utilized by AI agents as a high-level toolset that leverages the sensing and interactive capabilities of XR devices, enabling them to execute user-delegated tasks and adapt behaviors to contextual input, all without requiring low-level engine access. The library functions are annotated with doc strings formatted to help agents identify when a particular tool is useful.

3
Limitations & Future Work

XARP currently offers a minimal set of functionalities (
\cref
sec:tools). We are actively expanding the framework to incorporate common functionalities of XR products and research
[
3
]
. Furthermore, we are collaborating with other researchers to develop a series of case studies that will help to shape XARP to their particular needs and developer experience. Two of these case studies are under peer review.

Currently, XARP offers a Meta client app and a web chat interface for local development. We plan to broaden the scope of the framework, including other relevant XR platforms.

Finally, we aim to conduct a series of workshops with researchers and industry practitioners to evaluate current benefits and limitations of XARP Tools and trace new future opportunities to facilitate human-AI collaborative development in XR.
