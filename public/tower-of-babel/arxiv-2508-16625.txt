Data and Context Matter: Towards Generalizing AI-based Software Vulnerability Detection
Rijha Safdar, Danyail Mateen, Syed Taha Ali, Wajahat Hussain, M.Umer Ashfaq

Abstract
The performance of AI-based software vulnerability detection systems is often limited by their poor generalization to unknown codebases. In this research, we explore the impact of data quality and model architecture on the generalizability of vulnerability detection systems. By generalization we mean ability of high vulnerability detection performance across different C/C++ software projects not seen during training. Through a series of experiments, we demonstrate that improvements in dataset diversity and quality substantially enhance detection performance. Additionally, we compare multiple encoder-only and decoder-only models, finding that encoder based models outperform in terms of accuracy and generalization. Our model achieves 6.8% improvement in recall on the benchmark BigVul [ 1 ] dataset, also outperforming on unseen projects, hence showing enhanced generalizability. These results highlight the role of data quality and model selection in the development of robust vulnerability detection systems. Our findings suggest a direction for future systems having high cross-project effectiveness.

1.

II
Background and Related Work

The increasing dependence on open-source and sophisticated software development have increased the demand for automated tools that can detect software vulnerabilities, particularly in C/C++ applications. These powerful languages are prone to memory/low-level flaws that can lead to serious security vulnerabilities.
Coventional vulnerability detection method utilizes static analysis, dynamic analysis, hybrid analysis and symbolic execution techniques. Static analysis tools, such as Fortify
[
19
]
, Clang
[
20
]
, Cppcheck
[
21
]
etc. review source code without running the code to identify vulnerable patterns
[
18
]
. Static analyzers have the ability to identify a wide range of flaws but have limited contextual understanding and often suffer from high false positive rates.

Dynamic analysis, including fuzzing(trigger crashes via random input) and taint analysis(track data flow of untrusted input)
[
24
,
23
]
, involves executing programs to detect runtime vulnerabilities. While this method can be effective at discovering vulnerabilities than static analysis, it is computationally expensive, requires security expert to run applications in a virtual environment and struggle with limitations in code coverage.

Hybrid analysis is a combination of static and dynamic analysis
[
25
]
, it is effective as it does both analysis but requires security expert and computationally expensive.

Another traditional technique is symbolic execution such as KLEE
[
22
]
which attempt to explore program paths systematically, but a major challenge is scalability due to path explosion.

Traditional static and dynamic analysis techniques, though valuable, struggle to scale across wide range of evolving codebases. Consequently, ML and DL approaches have gained attention for their capability to learn vulnerability patterns from data, enabling more accurate, scalable and automated vulnerability detection.
To overcome the limitations of rule-based traditional analysis, researchers have turned toward machine learning (ML) and Deep Learning (DL) based approaches, for detecting vulnerability as a classification task. The models uses features extracted from abstract syntax trees (ASTs), control-flow graphs (CFGs), data-flow graphs (DFGs) or program dependency graphs (PDGs)
[
3
,
4
]
. The details of relevant models are discussed in Section
. Although these approaches are pioneers and improved automation, many models require tools to make graph are language dependent approaches continued to struggle with cross-project generalization, , often overfitting to specific datasets.

With the recent advancements in LLMS, which are based on transformer architecture and massively pretrained on large code and natural language datasets, have significantly improved the ability of models to understand and generate code. However, to use pre-trained model for the task of vulnerability detection, the model is fine-tuned. The details of related LLM models are discussed in Section
. The effectiveness of the fine-tuned models greatly depend on the quality and diversity of training data. The models tend to perform well on the data which they are trained but when evaluated on unseen codebases, they struggle mainly due to label noise and data duplication, biases in training (imbalanced datasets) and short context window. These shortcomings highlight the need for both good quality datasets and architectural improvements in LLMs for reliable, generalizable vulnerability detection, which is previously not achieved in literature.
