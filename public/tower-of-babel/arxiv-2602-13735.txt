Compressed Index with Construction in Compressed Space
Dmitry Kosolobov

Abstract
Suppose that we are given a string s s of length n n over an alphabet { 0 , 1 , … , n O ⁡ ( 1 ) } \{0,1,\ldots,n^{O(1)}\} and δ \delta is a compression measure for s s called string complexity. We describe an index on s s with O ⁡ ( δ ​ log ⁡ n δ ) O(\delta\log\frac{n}{\delta}) space, measured in O ⁡ ( log ⁡ n ) O(\log n) -bit machine words, that can search in s s any string of length m m in O ⁡ ( m + ( occ + 1 ) ​ log ϵ ​ n ) O(m+(\mathrm{occ}+1)\log^{\epsilon}n) time, where occ \mathrm{occ} is the number of found occurrences and ϵ > 0 \epsilon>0 is any fixed constant (the big-O in the space bound hides factor 1 ϵ \frac{1}{\epsilon} ). Crucially, the index can be built within this space in O ⁡ ( n ​ log ⁡ n ) O(n\log n) expected time by one left-to-right pass on the string s s in a streaming fashion. The index does not use the Karp–Rabin fingerprints, and the randomization in the construction time can be eliminated by using deterministic dictionaries instead of hash tables (with a slowdown). The search time matches currently best results and the space is almost optimal (the known optimum is O ⁡ ( δ ​ log ⁡ n δ ​ α ) O(\delta\log\frac{n}{\delta\alpha}) , where α = log σ ⁡ n \alpha=\log_{\sigma}n and σ \sigma is the alphabet size, and it coincides with O ⁡ ( δ ​ log ⁡ n δ ) O(\delta\log\frac{n}{\delta}) when δ = O ⁡ ( n / α 2 ) \delta=O(n/\alpha^{2}) ). This is the first index that can be constructed within such space and with such time guarantees. To avoid uninteresting marginal cases, all above bounds are stated for δ ≥ Ω ⁡ ( log ⁡ log ⁡ n ) \delta\geq\Omega(\log\log n) .

1
Introduction

Given a string
s
of length
n
over the alphabet
\{0,1,\ldots,\sigma-1\}
with
\sigma\leq n^{O(1)}
, a compressed index is a data structure that stores
s
in a compressed form supporting fast substring search. Currently best indexes use
O(\delta\log\frac{n}{\delta\alpha})
space
[
33
,
34
,
31
,
32
]
, measured in
O(\log n)
-bit machine words, where
\alpha=\log_{\sigma}n
and
\delta
is a compression measure called string complexity
[
45
]
, and they can search a substring of length
m
in
O(m+(\mathrm{occ}+1)\log^{\epsilon}n)
time, where
\mathrm{occ}
is the number of found occurrences and
\epsilon>0
is any fixed constant (the big-O in the space bound hides factor
\frac{1}{\epsilon}
). This space
O(\delta\log\frac{n}{\delta\alpha})
is known to be tight for a wide range of parameters
[
31
,
32
]
and it lowerbounds the space of most dictionary-based compressed indexes such as indexes on the Lempel–Ziv parsing
[
15
,
49
]
, run-length grammars
[
16
,
30
]
, Burrows–Wheeler transform
[
23
]
, and string attractors
[
28
]
(see
[
41
]
for an overview).

There are essentially two primary methods to achieve
O(m\log n)
search time within the space
O(\delta\log\frac{n}{\delta})
, which both enhance the basic idea of Claude and Navarro
[
17
]
: (1) a neat scheme
[
23
]
first outlined by Gagie et al.
[
22
]
that combines the Karp–Rabin hashing
[
21
,
26
]
and z-fast tries
[
3
,
4
]
; (2) a variant of the so-called locally consistent parsing
[
16
,
18
,
25
,
38
]
.
Known indexes that achieve
O(m+\log^{\epsilon}n)
search time combine both approaches
[
16
,
32
]
. The method (1) is applicable for many indexes; unfortunately, it has a serious drawback: the Karp–Rabin hashing must be collision-free for all substrings of length
2^{k}
, for
k=1,2,\ldots
, and the only known algorithm that verifies this condition uses
O(n)
space and
O(n\log n)
time
[
9
]
, which is prohibitive in use cases where the uncompressed data barely fits into memory. This issue hinders a wider usage of such indexes and it is the reason for the scarcity of experimental studies that try to translate the theoretical state-of-the-art methods to practice (we note that there are many works on construction of indexes, e.g.,
[
1
,
19
,
27
,
36
,
47
,
48
]
, but they never use the collision-free Karp–Rabin hashing as the best theoretical results do).

We make a step to solve this problem by presenting an index with
O(\delta\log\frac{n}{\delta})
space and
O(m+(\mathrm{occ}+1)\log^{\epsilon}n)
search time that can be built in this space in
O(n\log n)
expected time by one left-to-right pass in a streaming fashion. We do not use the Karp–Rabin hashes and the randomization in the construction can be removed using deterministic dictionaries instead of hash tables (with a slowdown). The result is purely theoretical due to large constants under the big-O but, we believe, its ideas might inspire practical designs. We conjecture that the index can be further improved to
O(\delta\log\frac{n}{\delta\alpha})
space and
O(m/\alpha+(\mathrm{occ}+1)\log^{\epsilon}n)
time in the string packed model (see
[
10
,
39
]
); this direction is left for a future work.

Preliminaries.

Throughout the paper,
s
denotes the input string of length
n
over an integer alphabet
\{0,1,\ldots,n^{O(1)}\}
. Its letters are
s[0],s[1],\ldots,s[n{-}1]
and, for
i,j
, denote by
s[i\,..\,j]
the
substring

s[i]s[i{+}1]\cdots s[j]
(which is empty if
i>j
). The
reversal
of any sequence
t=t_{0},t_{1},\ldots,t_{m-1}
(may be a string) is denoted
\overset{{}_{\leftarrow}}{t}=t_{m-1},\ldots,t_{1},t_{0}
. The notation
s[i\,..\,j)
is used for
s[i\,..\,j{-}1]
. Denote
[i\,..\,j]=\{i,i+1,\ldots,j\}
,
[i\,..\,j)=[i\,..\,j{-}1]
,
(i\,..\,j]=[i{+}1\,..\,j]
.

The string complexity,
\delta
, for
s
is defined as
\delta=\max\{d_{k}(s)/k\colon k\in[1\,..\,n]\}
, where
d_{k}(s)
denotes the number of distinct substrings of
s
with length
k

[
34
,
45
]
.

We heavily use the concept of
blocks
: a block
B
for string
s
is an object attached to a certain substring
s[i\,..\,j]
; denote
\mathop{\mathsf{b}}(B)=i
and
\mathop{\mathsf{e}}(B)=j
. The blocks are not “fragments”: two distinct blocks
B
and
B^{\prime}
can be attached to the same substring
s[i\,..\,j]
. If unambiguous, we treat a block
B
as a string, writing
|B|
,
B=s[i^{\prime}\,..\,j^{\prime}]
, etc. (with not necessarily
i^{\prime}=\mathop{\mathsf{b}}(B)
). Two blocks
B
and
B^{\prime}
are
equal as strings
if
s[\mathop{\mathsf{b}}(B)\,..\,\mathop{\mathsf{e}}(B)]=s[\mathop{\mathsf{b}}(B^{\prime})\,..\,\mathop{\mathsf{e}}(B^{\prime})]
. When defining a new block, we usually use words like “generate”, “create”, “copy” (when the new block is a copy of an old one) and it must be clear to which substring the new block is attached. We sometimes treat the concept of blocks loosely but, hopefully, it will be clear from the context.

2
Hierarchy of Blocks

Main ideas behind our index are outlined in Appendix
A
. At its core is a
hierarchy of blocks
(Fig.
1
): it has
O(\log n)
levels where the topmost level has one block equal to
s
and the bottom level
0
contains
n
one-letter blocks
s[0],\ldots,s[n{-}1]
; the concatenation of all blocks from one level equals
s
; for
\ell>0
, each level-
\ell
block
B
either is a copy of a level-
(\ell{-}1)
block
B^{\prime}
with
\mathop{\mathsf{b}}(B)=\mathop{\mathsf{b}}(B^{\prime})
and
\mathop{\mathsf{e}}(B)=\mathop{\mathsf{e}}(B^{\prime})
or is the concatenation of corresponding consecutive level-
(\ell{-}1)
blocks.
We define the hierarchy of blocks by a bottom-up construction process.

The bottom level-
0
blocks are
n
one-letter blocks
s[0],s[1],\ldots,s[n{-}1]
.
On a generic step with
k\geq 0
, we have a sequence of blocks
B_{1},\ldots,B_{b}
of level
2k
whose concatenation is
s
itself. To produce new blocks of levels
2k+1
and
2k+2
, the construction process will unite some adjacent blocks or will copy some blocks unaffected; in particular, all blocks with length
{>}2^{k}
are copied to levels
2k+1
and
2k+2
unaffected. Every block
B
is assigned an
O(\log n)
-bit integer identifier
\mathsf{id}(B)
; the level-
0
blocks have identifiers equal to the letters they represent (recall that the alphabet is
\{0,1,\ldots,n^{O(1)}\}
). Blocks with equal identifiers are equal as strings but the converse is not necessarily true. For what follows, we choose a method to encode any pair of
O(\log n)
-bit integers
x,y
into one
O(\log n)
-bit integer, denoted
\langle x,y\rangle
. The process maintains a counter to assign new unique identifiers to new blocks.

Level
2k+1
.

In the level-
2k
blocks
B_{1},\ldots,B_{b}
, we identify all maximal “runs” of blocks
B_{i},B_{i+1},\ldots,B_{i+r-1}
with equal identifiers (i.e.,
i=1
or
\mathsf{id}(B_{i-1})\neq\mathsf{id}(B_{i})
, and
i+r-1=b
or
\mathsf{id}(B_{i+r})\neq\mathsf{id}(B_{i+r-1})
), where
|B_{i}|\leq 2^{k}
. Each such run for which
r>1
is substituted by a new block
B=B_{i}B_{i+1}\cdots B_{i+r-1}
whose identifier encodes the pair
\langle\mathsf{id}(B_{i}),r\rangle
. Hence, any two distinct runs of the same length
r>1
with the same identifiers
\mathsf{id}(B_{i})
of the run blocks are substituted by blocks that have the same identifier
\langle\mathsf{id}(B_{i}),r\rangle
. Thus, the blocks for level
2k+1
consist of copies of blocks from level
2k
with length greater than
2^{k}
, copies of blocks that formed runs of length one, and the blocks substituted in place of longer runs.

Level
2k+2
.

For any distinct integers
x,y\geq 0
, denote by
\mathsf{bit}(x,y)
the index of the lowest bit in which the bit representations of
x
and
y
differ; e.g.,
\mathsf{bit}(8,0)=3
. Denote
\mathsf{vbit}(x,y)=2\cdot\mathsf{bit}(x,y)+a
, where
a
is the bit of
x
with index
\mathsf{bit}(x,y)
. Cole and Vishkin based their deterministic coin tossing (DCT) technique on the following observation.

Lemma 1

(see
[
18
,
37
]
)
.

Given a string
a_{0}a_{1}\cdots a_{m}
over an alphabet
[0\,..\,2^{u})
such that
a_{i-1}\neq a_{i}
for any
i\in[1\,..\,m]
, the string
b_{1}b_{2}\cdots b_{m}
such that
b_{i}=\mathsf{vbit}(a_{i-1},a_{i})
, for
i\in[1\,..\,m]
, satisfies
b_{i-1}\neq b_{i}
, for any
i\in[2\,..\,m]
, and
b_{i}\in[0\,..\,2u)
, for any
i\in[1\,..\,m]
.

Let
B_{1},\ldots,B_{b}
be all blocks on level
2k+1
. For each
B_{i}
, we assign two identifiers, denoted
\mathsf{id}^{\prime}(B_{i})
and
\mathsf{id}^{\prime\prime}(B_{i})
. If
|B_{i}|>2^{k}
, define
\mathsf{id}^{\prime}(B_{i})=\infty
. If
|B_{i}|\leq 2^{k}
, then
\mathsf{id}(B_{i-1})\neq\mathsf{id}(B_{i})
since the previous stage united all runs; define
\mathsf{id}^{\prime}(B_{i})=\mathsf{vbit}(\mathsf{id}(B_{i-1}),\mathsf{id}(B_{i}))
if
i>1
and
|B_{i-1}|\leq 2^{k}
, and
\mathsf{id}^{\prime}(B_{i})=\infty
otherwise. Define
\mathsf{id}^{\prime\prime}(B_{i})=\mathsf{vbit}(\mathsf{id}^{\prime}(B_{i-1}),\mathsf{id}^{\prime}(B_{i}))
if
i>1
and
\mathsf{id}^{\prime}(B_{i-1})\neq\infty
and
\mathsf{id}^{\prime}(B_{i})\neq\infty
, and define
\mathsf{id}^{\prime\prime}(B_{i})=\infty
otherwise. This computation of
\mathsf{id}^{\prime\prime}
corresponds to two first steps of the standard DCT, i.e., it is a “cut” variant of DCT.

For any maximal range of blocks
B_{p},\ldots,B_{q}
such that
|B_{h}|\leq 2^{k}
for each
h\in[p\,..\,q]
(i.e.,
p=1
or
|B_{p-1}|>2^{k}
, and
q=b
or
|B_{q+1}|>2^{k}
), we have
\mathsf{id}^{\prime\prime}(B_{p})=\mathsf{id}^{\prime\prime}(B_{p+1})=\infty
(or just
\mathsf{id}^{\prime\prime}(B_{p})=\infty
if
p=q
) and, by Lemma
1
, for each
h\in[p{+}2\,..\,q]
, we have
\mathsf{id}^{\prime\prime}(B_{h-1})\neq\mathsf{id}^{\prime\prime}(B_{h})
and
0\leq\mathsf{id}^{\prime\prime}(B_{h})\leq O(\log\log n)
(here we used the assumption
\mathsf{id}(B_{h})\leq n^{O(1)}
). We will split
B_{p},\ldots,B_{q}
into ranges ending at points corresponding to local minima of
\mathsf{id}^{\prime\prime}
. To this end, we mark each block
B_{i}
, with
i\in[1\,..\,b]
, for which one of the following conditions holds:

(a)

|B_{i}|>2^{k}
or
|B_{i+1}|>2^{k}
or
i=b
(the last block);

(b)

\infty>\mathsf{id}^{\prime\prime}(B_{i-2})>\mathsf{id}^{\prime\prime}(B_{i-1})
and
\mathsf{id}^{\prime\prime}(B_{i-1})<\mathsf{id}^{\prime\prime}(B_{i})<\infty

(i.e.,
\mathsf{id}^{\prime\prime}(B_{i})
is immediately preceded by a local minimum).

The marking splits all blocks
B_{1},\ldots,B_{b}
on level
2k+1
into disjoint ranges as follows: each range
B_{i},\ldots,B_{j}
consists of unmarked blocks
B_{i},\ldots,B_{j-1}
and the marked block
B_{j}
and either
i=1
or
B_{i-1}
is marked.
For each such range
B_{i},\ldots,B_{j}
: if
i=j
, the process copies
B_{i}
to level
2k+2
; if
i<j
, the process creates a new block
B=B_{i}\cdots B_{j}
for level
2k+2
assigning to it a new identifier unless another block
B^{\prime}
produced by the same sequence
\mathsf{id}(B_{i}),\ldots,\mathsf{id}(B_{j})
has already appeared earlier in the process, in which case we assign
\mathsf{id}(B)=\mathsf{id}(B^{\prime})
.
Note that
j-i\leq O(\log\log n)
since
\mathsf{id}^{\prime\prime}\leq O(\log\log n)
and, thus, local minima for
\mathsf{id}^{\prime\prime}
occur often.

H
. Colored rectangles with the same color depict blocks with the same

Properties of blocks.

The main properties of the hierarchy are its “local consistency” and “local sparsity”. The proof of the former is standard
[
34
]
and it was moved to Appendix
B
.

Lemma 2

(local consistency)
.

Fix
\ell=2k
or
\ell=2k+1
. Let
{B}_{1},{B}_{2},\ldots
denote all level-
\ell
blocks. For any
i
,
j
and block
{B}_{h}
, if
s[i{-}2^{k+4}\,..\,j{+}2^{k+4}]=s[\mathop{\mathsf{b}}({B}_{h}){-}2^{k+4}\,..\,\mathop{\mathsf{e}}({B}_{h}){+}2^{k+4}]
, then there exists a level-
\ell
block
{B}_{h^{\prime}}
such that
\mathsf{id}({B}_{h^{\prime}})=\mathsf{id}({B}_{h})
,
\mathop{\mathsf{b}}({B}_{h^{\prime}})=i
, and
\mathop{\mathsf{e}}({B}_{h^{\prime}})=j
.

We call a position
h\in[0\,..\,n)
a
block boundary
for level
\ell
if
h=\mathop{\mathsf{e}}(B)
for some level-
\ell
block
B
.
The “local sparsity” formalizes the intuition that blocks on levels
2k
and
2k+1
have length
{\geq}2^{k}
“on average”. The proof is quite technical and it mostly repeats the arguments from the proof of
[
37
, Lemma 11]
word by word. The proof has been moved to Appendix
B
.

Lemma 3

(local sparsity)
.

For any
i<j
, the number of block boundaries in
[i\,..\,j)
on levels
2k
and
2k+1
is at most
2^{6}\lceil\frac{j-i}{2^{k}}\rceil
. In particular, there are
O(n/2^{k})
blocks on these levels.

Lemma
3
implies that there are
O(\log n)
levels in the hierarchy. We conclude the section with a technical lemma. Its proof is quite straightforward and has been moved to Appendix
B
.

Lemma 4
.

Any blocks
B
and
B^{\prime}
with
\mathsf{id}(B)=\mathsf{id}(B^{\prime})
are equal as strings and both were created on the same level.

3
Jiggly Block Tree

The described hierarchy of blocks for
s
naturally forms a tree
H
with blocks as vertices in which the root is the (only) topmost block and the parent of any level-
\ell
block
B
with
B\neq s
is the block
B^{\prime}
from level
\ell+1
such that
[\mathop{\mathsf{b}}(B^{\prime})\,..\,\mathop{\mathsf{e}}(B^{\prime})]\supseteq[\mathop{\mathsf{b}}(B)\,..\,\mathop{\mathsf{e}}(B)]
(note that
B
and
B^{\prime}
might be equal as strings).
To build an index from
H
, we create a new tree
\hat{H}
that is a copy of
H
with vertices removed according to the following rules 1–4 until it is possible (Fig.
1
):

1.

if a level-
0
block
B
has parent
B^{\prime}
with
\mathsf{id}(B)=\mathsf{id}(B^{\prime})
, merge
B
and
B^{\prime}
by removing
B^{\prime}
and connecting
B
to the parent of
B^{\prime}
;

2.

if, for
\ell>0
, a level-
\ell
block
B
has parent
B^{\prime}
with
\mathsf{id}(B)=\mathsf{id}(B^{\prime})
, merge
B
and
B^{\prime}
by removing
B
and connecting all children of
B
to
B^{\prime}
;

3.

if, for
\ell>0
and
\ell^{\prime}>0
, a level-
\ell
block
B
has a “preceding” level-
\ell^{\prime}
block
B^{\prime}
such that
\mathsf{id}(B)=\mathsf{id}(B^{\prime})
and
\mathop{\mathsf{b}}(B^{\prime})<\mathop{\mathsf{b}}(B)
, remove all descendants of
B
;

4.

if, for
\ell>0
, all children of a level-
\ell
block
B
have equal
\mathsf{id}
, remove them all except for the leftmost child (note that, by removing a child, we remove its descendants).

The idea of such construction is not novel (however, usually the full DCT is used, not the “cut” DCT as we do) and it leads to an index with
\omega(\delta\log\frac{n}{\delta})
space
[
11
,
37
,
38
,
44
,
46
,
47
]
. As it turns out, the obtained tree has
O(\delta\log\frac{n}{\delta})
non-leaf vertices and the main issue with space is due to some vertices having up to
O(\log\log n)
leaves from levels
2k+1
. To reduce the space, our idea is to parse the sequences of leaves by a specialized variant of LZ77
[
49
]
. The construction is quite technical and requires some preparations to define it.

Let
B_{1},\ldots,B_{b}
be all blocks on a level
2k+1
. Recall that the block construction process has marked some of the blocks, thereby splitting them into ranges
B_{i},\ldots,B_{j}
, where
B_{i},\ldots,B_{j-1}
are unmarked and
B_{j}
is marked. Fix such range
B_{i},\ldots,B_{j}
with
i<j
such that
B_{i},\ldots,B_{j}
were not removed from
\hat{H}
after the rules 1–4 above. Let
B
be the parent of
B_{i},\ldots,B_{j}
. We are to parse
B_{i},\ldots,B_{j}
into subranges. To define the parsing, we need some notation.

For any block
B_{m}
and
\ell\geq 0
, choose the largest
h\leq\ell
such that, for all
h^{\prime}\in[m{-}h\,..\,m)
,
B_{h^{\prime}}
is not marked; define
\mathop{\mathsf{left}}(m,\ell)
as the sequence
\beta,\mathsf{id}(B_{m-h}),\mathsf{id}(B_{m-h+1}),\ldots,\mathsf{id}(B_{m{-}1})
, where
\beta
is empty (i.e., it is really not in the sequence) if
h=\ell
, and
\beta
is a special symbol
\$
if
h<\ell
. Choose the largest
h\leq\ell
such that, for all
h^{\prime}\in[m\,..\,m{+}h{-}1)
,
B_{h^{\prime}}
is not marked (but
B_{m+h-1}
may be marked); define
\mathop{\mathsf{right}}(m,\ell)
as the sequence
\mathsf{id}(B_{m}),\mathsf{id}(B_{m+1}),\ldots,\mathsf{id}(B_{m+h-1})
.

We greedily parse
B_{i},\ldots,B_{j}
into subranges from left to right:
suppose that
B_{i},\ldots,B_{m-1}
have already been parsed (initially
m=i
), let
B_{m},\ldots,B_{m+r-1}
be the longest subrange with
m+r-1\leq j
for which there is
m^{\prime}<m
such that
\mathop{\mathsf{left}}(m^{\prime},4r)=\mathop{\mathsf{left}}(m,4r)
and
\mathop{\mathsf{right}}(m^{\prime},5r)=\mathop{\mathsf{right}}(m,5r)
(note that
\mathsf{id}(B_{m}),\ldots,\mathsf{id}(B_{m+r-1})
must be a prefix of
\mathop{\mathsf{right}}(m,5r)
); let
r=1
if there is no such
B_{m},\ldots,B_{m+r-1}
; once
r
is determined, we have obtained a new subrange
B_{m},\ldots,B_{m+r-1}
and we continue the parsing for
B_{m+r},\ldots,B_{j}
, assigning
m:=m+r
.

Define a new tree
J
, called the
jiggly block tree
, that is a copy of
\hat{H}
with the following modifications. For each obtained subrange
B_{m},\ldots,B_{m+r-1}
with
r>1
, we remove from
J
the blocks
B_{m},\ldots,B_{m+r-1}
(which are children of
B
) and insert in their place a new block
B^{\prime}
with the parent
B
and no children;
B^{\prime}
is called
intermediate
. We do not assign
\mathsf{id}
to
B^{\prime}
. The analogous parsing and modifications of the tree
J
are performed on each level
2k+1
for each such range
B_{i},\ldots,B_{j}
whose blocks were not removed from
\hat{H}

To support the basic navigation on the string

Each non-intermediate block

Parsing

For each non-run block

in

into a compacted trie

As is usual for compacted tries, the edge labels in

are sequences of
\mathsf{id}
s and there is a node

denotes the sequence written on the root–

do not store their edge labels, only the lengths of these edge labels. Each internal node of

Our search algorithm constructs a hierarchy of blocks for

Level

\ell

and

. Suppose that

, we identify in

with equal identifiers (i.e.,
\mathsf{id}(B_{i})=\cdots=\mathsf{id}(B_{i+r-1})

or

to level

for level

with identifier

. Thus, all block for level

are constructed. Suppose that

. As in Section

, we assign in

an identifier

that is either

and values of

Lemma 9

We obtain

Appendix A
Idea

What follows is a high level description of main ideas behind our index. Details and precise definitions are provided in Sections
2
–
4
. We start by describing a static index. The algorithm that builds it online is given in Section
5
.

Recent results on block trees
[
33
,
42
]
showed that the space
O(\delta\log\frac{n}{\delta})
for indexes is surprisingly easy to obtain by, roughly, the following scheme (or its variants): one constructs a hierarchy of blocks with
\log n
levels such that the level-
k
blocks are
\lceil n/2^{k}\rceil
substrings
s[i\cdot 2^{k}\,..\,(i+1)2^{k})
of length
2^{k}
(the rightmost block might be shorter) and, for
k>0
, each level-
k
block has two corresponding child blocks from level
k-1
(its prefix/suffix of length
2^{k-1}
); then, each block
B=s[i\cdot 2^{k}\,..\,(i+1)2^{k})
for which the substring
\bar{B}=s[(i-1)2^{k}\,..\,(i+2)2^{k})
has an occurrence at a position smaller than
(i-1)2^{k}
is encoded by a pointer to the leftmost occurrence of
B
in
s
and all descendants of
B
in the hierarchy are removed (for precise and detailed definitions, see
[
6
,
5
,
33
,
40
,
42
]
). The result is a block tree
[
6
,
40
]

After a closer inspection of the proof from
[
34
]
of the bound
O(\delta\log\frac{n}{\delta})
for the size of the block tree, one can notice that the bound still holds if the boundaries of the blocks are slightly “jiggled”. Our idea is to construct a “jiggy block tree”, in which level-
k
blocks are not of exact size
2^{k}
but somewhat close to this “on average”, and each block might have up to
O(\log\log n)
children. The variability of block lengths will be used to form a kind of locally consistent parsing, more specifically, we will use a “cut” version of the so-called deterministic coin tossing (DCT) approach
[
18
]
and the blocks will be built level by level bottom-up using this “cut DCT” (the idea of such level-by-level construction itself is not novel but it is usually used with the full DCT and it leads to a grammar of size
\Omega(\delta\log\frac{n}{\delta}\log^{*}n)
, not to a kind of block tree). Then, the same arguments as in
[
34
]
show that the resulting tree has
O(\delta\log\frac{n}{\delta})
internal nodes. However, some nodes might have up to
O(\log\log n)
leaf children, blowing up the space bound by an
\Omega(\log\log n)
factor, which seems unavoidable when using the DCT
[
11
,
37
,
38
,
44
,
46
,
47
]
.

We eliminate the factor
\Omega(\log\log n)
by introducing a novel intermediate step in the level by level bottom-up construction: given a block
B
with
O(\log\log n)
children
B_{i},\ldots,B_{j}
, we greedily unite the children from left to right into larger “intermediate blocks”
B^{\prime}=B_{m}\cdots B_{m+r-1}
such that the sequence of blocks
B_{m}\cdots B_{m+r-1}
occurs somewhere to the left in the block hierarchy; then, we store in the intermediate block
B^{\prime}
a pointer to this earlier occurrence. Due to the property of “local consistency” of DCT, the pointers will be somewhat “aligned” on the block structure and our jiggly block tree will resemble a grammar with elements of the block tree structure (like a collage system
[
29
]
but more structured). There are many details in this scheme to make it efficient that are explained in the sequel.

For the pattern matching, we follow the standard approach of Claude and Navarro enhanced with the locally consistent parsing and z-fast tries (which is also standard), but we replace the Karp–Rabin fingerprints
[
26
]
used in the tries with new deterministic fingerprints that are derived from our locally consistent block structure.

and
B_{L}
is the leftmost level-
\ell
block from
T_{L}
, then
\mathop{\mathsf{b}}(B_{L})\leq\mathop{\mathsf{b}}(B_{R})
(i.e., the tree
T_{L}
is located to the “left” of
T_{R}
in the hierarchy of blocks
H
, with possible overlaps).

Emulated algorithm.

Now let us transform the simultaneous traversal algorithm for the case when the hierarchy of blocks
H
is not directly accessible but it is emulated through the jiggly block tree
J
using Lemma
6
. The simplest emulation would just descend in the trees
T_{R}
and
T_{L}
computing the children of blocks using Lemma
6
. But it raises the following question: if we first encounter a block
B^{\prime}
during the emulated traversal of the tree
T_{R}
and the level of the parent of
B^{\prime}
in
T_{R}
was known to be
\ell
, then, surely, the level of
B^{\prime}
is
\ell-1
but what is the level in
T_{R}
of the children of
B^{\prime}
in the hierarchy
H
obtained using Lemma
6
from the tree
J
? Recall that
B^{\prime}
stores in
J
the lowest level
\ell^{\prime}
on which a block with identifier
\mathsf{id}(B^{\prime})
appeared in the original hierarchy
H
, denote it
\ell^{\prime}=\ell(B^{\prime})
; then, it follows from Lemma
4
that the obtained children of
B^{\prime}
must have level
\ell^{\prime}-1
in
T_{R}
and, thus,
B^{\prime}
“induces” a chain of
\ell-\ell^{\prime}+1
blocks in
T_{R}
, each of which is a copy of
B^{\prime}
. We can easily navigate to any block in this chain in
O(1)
time.

We slightly speed up the emulation further: when we descend along the rightmost path of
T_{R}
to the rightmost leaf of
T_{R}
(which is the one-letter block
s[q]
) at the beginning of the algorithm, we encounter sequences of descends of the form
B^{\prime}_{1},\cdots,B^{\prime}_{z^{\prime}}
, where all
B^{\prime}_{1},\cdots,B^{\prime}_{z^{\prime}}
are ancestors of
s[q]
and, for each
h\in[1\,..\,z^{\prime})
,
B^{\prime}_{h+1}
is the leftmost child of
B^{\prime}_{h}
; all this chain can be skipped in
O(\log\log n)
time using the weighted ancestor data structure on an auxiliary tree
A_{L}
that was maintained for
J
so that we arrive to the block
B^{\prime}_{z^{\prime}}
in one “hop”. Since, for each
h\in[1\,..\,z^{\prime})
, we have
q<\mathop{\mathsf{e}}(B^{\prime}_{h})
, the algorithm will never need these skipped blocks, so we can ignore them in the algorithm. But we need also the levels
\ell(B^{\prime}_{z^{\prime}})
and
\ell(B^{\prime}_{z^{\prime}-1})
for the correct emulation of skipped levels; we can access
B^{\prime}_{z-1}
with one more weighted ancestor query in a straightforward way. Symmetrically, for the tree
T_{L}
, we skip long sequences of descends into rightmost children along the leftmost path of the tree
T_{L}
. It turns out that this only non-trivial optimization suffices to make the algorithm fast enough. Let us analyse the optimized emulated algorithm.

Analysis.

Denote by
\hat{T}
the tree that is the union of the trees
T_{R}
and
T_{L}
(i.e., the set of blocks in
\hat{T}
is the union of all blocks from
T_{R}
and
T_{L}
). It is convenient to imaging that the emulation traverses the tree
\hat{T}
, not
T_{R}
and
T_{L}
separately.
\hat{T}
has
O(\log m\cdot\log\log n)
leaves and, hence,
O(\log m\cdot\log\log n)
branching nodes. Due to Lemma
6
, given a block
B^{\prime}
from the tree
J
, one can compute all children of
B^{\prime}
from the hierarchy
H
in
O(\log\log n)
time. Hence, the computation on all branching nodes in
\hat{T}
takes
O(\log m\cdot(\log\log n)^{2})
time in total. But the tree
\hat{T}
might also contain long chains of non-branching nodes. In total, we have visited
O(\log m\cdot\log\log n)
blocks of interest in
\hat{T}
during the execution of the algorithm; it remains to estimate how much time was spent on blocks from non-branching chains in
\hat{T}
.

If we encounter a chain that consists of copies of one block, then we reach any block of interest on such chain in
O(1)
time, as described above. Thus, we spend on such chains
O(\log m\cdot\log\log n)
time in total, over all chains (since this is the number of blocks of interest).

Consider a block
B^{\prime}
in
\hat{T}
that has the only child
B^{\prime\prime}
in
\hat{T}
and
\mathsf{id}(B^{\prime})\neq\mathsf{id}(B^{\prime\prime})
. Denote by
\ell
the level of
B^{\prime\prime}
. Suppose that
B^{\prime\prime}
belongs to
T_{R}
; the case when
B^{\prime\prime}
belongs to
T_{L}
is symmetric. Since the tree
T_{R}
has no “gaps” on level
\ell
,
B^{\prime\prime}
must be either the leftmost or rightmost level-
\ell
block in
T_{R}
. Therefore, for
\ell\leq\ell_{\max}
, there are in total at most
2\ell_{\max}=O(\log m)
such blocks
B^{\prime\prime}
in
T_{R}
and we spend
O(\log m)
time on them in total. Let
\ell>\ell_{\max}
.
Since
B
is the lowest block in
H
such that
\mathop{\mathsf{b}}(B)\leq p<q\leq\mathop{\mathsf{e}}(B)
, the block
B^{\prime\prime}
cannot be the only level-
\ell
block in
\hat{T}
. Recall that
B^{\prime\prime}
is the only child of
B^{\prime}
in
\hat{T}
. Therefore, since the tree
T_{L}
has no “gaps” on level
\ell
and the trees
T_{L}
and
T_{R}
“touch” each other (in a precise sense described above) on level
\ell>\ell_{\max}
, then
B^{\prime\prime}
is either the leftmost or rightmost child of
B^{\prime}
. In former (respectively, latter) case,
B^{\prime\prime}
belongs to a part of the rightmost (respectively, leftmost) path along
T_{R}
(respectively,
T_{L}
) that was skipped using the weighted ancestor data structure and
B^{\prime\prime}
was not important for the algorithm.
∎

D.2
Secondary Occurrences

Any non-intermediate leaf block
B
in
J
with
|B|>1
contains a pointer to another block
\hat{B}
in
J
such that
\mathsf{id}(\hat{B})=\mathsf{id}(B)
; any intermediate block
B
in
J
contains two numbers
h=\mathsf{off}(B)\geq 0
and
r=\mathsf{r}(B)>1
and a pointer to a block
\hat{B}
from a level
2k+2
such that
\mathsf{id}(B)
was created from identifiers
\mathsf{id}(B_{i+h}),\ldots,\mathsf{id}(B_{i+h+r-1})
, where
B_{i},\ldots,B_{j}
is the sequence of level-
(2k+1)
blocks from which
\hat{B}
was created and
i+h+r-1\leq j
. The block
\hat{B}
has children in
J
in both cases. Given a leaf
B
, secondary occurrences of
t
corresponding to
B
are exactly all occurrences of
t
from the substring
s[\mathop{\mathsf{b}}(B)\,..\,\mathop{\mathsf{e}}(B)]
. They may exist if the block
\hat{B}
referred by
B
contains occurrences of
t
.

We construct on the tree
J
the marked ancestor data structure
[
2
]
that allows us to mark some nodes and to search the nearest marked ancestor of any node in
O(1)
time. Then, we reverse all pointers: for each block
\hat{B}
, we store in
\hat{B}
a link to each non-intermediate block
B
that has a pointer to
\hat{B}
and we mark
\hat{B}
in this case; further, if
\hat{B}
is from a level
2k+2
and
\hat{B}
was created from level-
(2k+1)
blocks
B_{i},\ldots,B_{j}
, then we store in
\hat{B}
a link to each intermediate block
B
that has a pointer to
\hat{B}
and we store the range
[i+h\,..\,i+h+r)
corresponding to
B
in an augmented binary search tree
R_{\hat{B}}
associated with
\hat{B}
; for any
d\in[i\,..\,j]
, we mark the block
B_{d}
if
B_{d}
is a non-intermediate child of
\hat{B}
in
J
and
d\in[i+h\,..\,i+h+r)
for a range
[i+h\,..\,i+h+r)
from
R_{\hat{B}}
. Note that the tree
R_{\hat{B}}
contains at most
O((\log\log n)^{2})
distinct ranges but one range may correspond to many blocks
B
; thus, range searching operations on
R_{\hat{B}}
can be performed in time
O(\log\log\log n)\leq O(\log^{\epsilon}n)
.

With this machinery, the search for secondary occurrences is just a traversal of the reversed pointers. We maintain a set of occurrences of
t
, which initially contains only primary occurrences, and each occurrence
s[p\,..\,p{+}|t|)
is associated with a lowest block
\hat{B}
in
J
such that
\mathop{\mathsf{b}}(\hat{B})\leq p<p+|t|-1\leq\mathop{\mathsf{e}}(\hat{B})
. Given such an occurrence
s[p\,..\,p{+}|t|)
and the associated block
\hat{B}
, we use the tree
R_{\hat{B}}
to check whether
s[p\,..\,p{+}|t|)
lies inside some blocks
B_{i+h}\cdots B_{i+h+r-1}
where
[i+h\,..\,i+h+r)
is a range stored in
R_{\hat{B}}
and
B_{i},\ldots,B_{j}
are blocks from which
\hat{B}
was created in the hierarchy of blocks
H
for
s
. Each link associated with such range induces a new unique secondary occurrence of
t
that is added to the set of occurrences. We then loop through all links to all non-intermediate blocks
B
that have pointers to
\hat{B}
and each such link analogously induces a new secondary occurrence. Then, we find the nearest marked ancestor
B^{\prime}
of
B
(if any) and continue the same process recursively with
B^{\prime}
in place of
B
, inducing new unique secondary occurrences. Each added secondary occurrence in the set is processed in the same way.

The time for reporting all
\mathrm{occ}
found occurrences is
O(\mathrm{occ}\cdot\log^{\epsilon}n)
.
