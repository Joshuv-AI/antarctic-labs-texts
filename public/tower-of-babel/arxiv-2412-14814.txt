Thinking, Fast and Not So Slowly: Accelerating Neuro-Symbolic AI by Answer Set Networks
Arseny Skryagin, Daniel Ochs, Philipp Deibert, Simon Kohaut, Devendra Singh Dhami, Kristian Kersting

Abstract
Neural-symbolic (NeSy) systems such as Deep Probabilistic Programming Languages (DPPLs) have shown great potential by combining fast deep learning modules with the more deliberate symbolic reasoning, such as Answer Set Programming (ASP). Although reasoning complements deep learning, it specifically suffers from the CPU-bound nature of even the most competitive solvers. On top of this, NeSy inherits the requirement to process large datasets for training. We propose Answer Set Networks (ASN), a GPU-based NeSy solver, to address both issues. Based on Graph Neural Networks (GNN), ASNs offer an accelerated framework for ASP-based DPPLs. Specifically, we show how to translate AS programs into ASNs and how ASNs can efficiently solve the encoded problem by leveraging a GPU’s batching and parallelization capabilities. Our overall contributions are twofold. Namely, we are the first to show the fine-tuning of Large Language Models (LLM) with DPPLs, employing ASNs to guide the training with logic. Furthermore, we scale the “constitutional navigation” of drones, i.e., encoding public aviation laws in an ASN for routing Unmanned Aerial Vehicles in uncertain environments. Our experimental evaluations demonstrate that ASNs outperform state-of-the-art CPU-bound NeSy systems on a selection of vision, language, and navigation tasks.

Introduction

NeSy systems combine high-level (probabilistic) reasoning with low-level perception modules.
Among them, Deep Probabilistic Programming Languages (DDPLs) offer a declarative way, to integrate various kinds of neural networks within logical reasoning.
The first generation of DPPLs includes DeepProbLog

All of these languages share the same bottleneck: they are universally difficult to speed up because their reasoning relies on CPU-based solving.
Even if multithreading is possible, as shown in
(
Skryagin et al., 2022

, the speed-up is constrained due to logical queries being answered separately.
Hence, the anticipation for the second generation of DPPLs is to carry out both parts (reasoning and perception) on many core processors, to be able to unlock the potential of NeSy-AI.

Within the first generation, Scallop

Similarly, SAME

While, both push the boundaries of DPPLs’ scalability, the underlying problem persists, as queries are answered separately from one another.
Furthermore, in many NeSy applications, we make the observation that many samples share the same or similar queries.
Consequentially, the number of unique queries is much smaller than the number of data entries. To the best of our knowledge, none of the existing DPPLs make use of this observation.
Another example in which the NeSy CPU bottlenecks become prevalent is Alpha Geometry
Trinh et al. (2024)

There, 10k CPU cores were used to train a model to reach the silver medal level in geometry at the math Olympiads.
Altogether, this suggests that the second generation should perform logical reasoning on the same hardware where deep model inference takes place; with solving routines designed with parallelization in mind to be easily vectorized to maximize the hardware utilization.

Modeling domain-specific problems in a logical language and then applying a general solving approach is a long-established paradigm.
To this end, Answer set programming (ASP), being a modern, non-monotonic reasoning framework based on stable model semantics, has experienced rising interest in NeSy inference systems.
In this vein, recent NeSy AI pipelines
Skryagin et al. (2023)
;
Skryagin et al. (2022)

Although conflict-driven, state-of-the-art solvers like clingo

Thus, the question of how to integrate these pipelines tightly with modern GPUs is more urgent than ever.
For example, large machine learning models for natural language and vision tasks have dramatically risen in popularity and public awareness.
Widely known, their success is greatly supported by their underlying architectures’ ability to distribute work on many-core systems with ease.
Thus, translating the task of solving ASP-based modeling into a neural framework that leverages modern hardware acceleration to the same level can be seen as a key to applying NeSy systems in real-world applications.

Usually, in state-of-the-art solvers, the search for the solutions, i.e., the stable models, of a program
\Pi
among all interpretations follows a binary tree.
That is, branches of the tree correspond to (partial) assignments of truth values to the program’s atoms (partial interpretations).
Further, alternating between decision and propagation phases generates the searched stable models of the ASP.
However, recent research has proposed alternative approaches based on the propagation of truth values within a graph.
Such graph-based Answer Set Programming solver systems
Li (2021)
are based on
Dependency Graphs
as a basis. The advantage of this explicit representation of atoms and literals as graph nodes is the uniform representation of stable models and preservation of causal relationships, meaning each atom is justified in a particular stable model.
Hence, the usual heuristics inherited from SAT solvers are avoided, i.e., the solving procedure is transparent.

For an atom to be true, at least one rule defining it must be satisfied.
In case there are multiple rules defining the atom, we express their combination through a disjunction.

2.2.2
Literals

Due to the program being already grounded, we know if a built-in literal evaluates to true or false.
For conjunctions, true built-in literals can be ignored safely while making sure that false ones cannot be satisfied.

For disjunctions, we change the course by ignoring false built-in literals and setting any to true if it evaluates to true itself.
Thus, during neural-compilation, built-in literals are handled implicitly.

3.2
Message-Passing

Using message-passing, we want to find the final value at the sink node

3.3
Model Reduction

After message passing, the graphs represent interpretations, as indicated by the truth values of the nodes representing classical atoms.
If
\bot
is true for some graph instance, then the corresponding interpretation is not a model.
However, the interpretation does not equate to a stable model of the original program.
Accurately, ASP’s models are minimal w.r.t. inclusion.
Thus, we filter all the program’s models to obtain the minimal one.
This can be done efficiently in a batch-wise manner using logical bit-wise operators.
Let
I_{1},I_{2}\subseteq A=\{a_{1},\ldots,a_{n}\}\subseteq\mathcal{B}_{\Pi}
be two interpretations over some finite subset of Herbrand base
\mathcal{B}_{\Pi}
.
Further, let
m_{1},m_{2}\in\{0,1\}^{n}
be vectors representing the truth values of the corresponding interpretations with the components
m_{i_{j}}=1
if and only if
a_{j}\in I_{i}
.
We have
m_{1}\otimes m_{2}=

\begin{cases}m_{1}&\text{if }I_{1}\subseteq I_{2},\\
m_{2}&\text{if }I_{1}\supseteq I_{2},\\
m\in\{0,1\}^{n},m_{1}\neq m\neq m_{2}&\text{else}.\end{cases}

(6)

where

For a set of interpretations
\{I_{1},\ldots,I_{k}\}\subseteq A
with corresponding 0-1-vectors

\mathrm{SM}\left(\Pi\right)=

\left\{I_{i}|i\in\{1,\ldots,n\}:m_{i}\otimes m_{j}\neq m_{i},\forall j=i+1,\ldots,n\right\}.

(7)

4.2
Q1 LLM Fine-Tuning with ASN

Berglund et al.
(
Berglund et al., 2024
)
have shown in their work that LLMs suffer from the Reversal Curse.
Meaning, if a model is trained on a sentence of the form “A
\Rightarrow
B”, it will not automatically generalize to the reverse direction “B
\Rightarrow
A”.
To this end, authors tested SOTA LLMs on pairs of questions like “Who is Tom Cruise’s mother?” and “Who is Mary Lee Pfeiffer’s son?”.
Here, we demonstrate how ASN allows for fine-tuning LLMs to alleviate the problem.

To address this issue, we perform
fine-tuning via probabilistic logic
of the LLM using ASN.
Particularly, during training, we predict the relation (mother, father, daughter, and son) between a celebrity and their parent(s) in both directions.
The training dataset consists of queries such as “Q: What is the relation between
<
celebrity_name
>
and
<
celebrity_parent_name
>
? A: …” and the opposite of the prompt by swapping
<
celebrity_name
>
and
<
celebrity_parent_name
>
.
For each celebrity, we only provide one direction during training, i.e., either child-parent or parent-child.
We split the dataset into equal parts for each direction respectively to prevent the fine-tuned model from becoming biased in either direction.
During test time, we evaluate the accuracy of unseen celebrities and their parents in both directions.

We add 12M learnable parameters by LoRA
Hu et al. (2021)
to fine-tune the Llama2-7B
Touvron et al. (2023)
LLM using ASN.
To compare the results of ASN fairly, we fine-tuned the Llama2 in a stand-alone fashion as well.
The difference in the training procedure is founded in ASN’s ability to derive the opposite relation, while baseline handles only one direction for each celebrity.
Using the original dataset from
Berglund et al. (2024)
, we split the 797 celebrities into
70% train, 20% test, and 10% validation.
For in-depth explanations of the experimental setup, we refer our readers to consult the appendix.

The results reveal the following findings.
Firstly, ASN’s runtime equates to the number of passes through the LLM.
Namely, we request both the sex and the relation for two persons for every query.
In particular, the baseline takes 50s and ASN 189s, which corresponds to the four forward passes and one backward pass. Importantly, this means we don’t have any neurosymbolic overhead: The increased run-time is entirely due to the greater number of LLM passes which are connected with ASN.
Secondly, ASN converges one order of magnitude faster (in the number of epochs) than the baseline.
In detail, Fig.
6(a)
(right) paints the picture for ASN taking only 9 epochs (28m:21s) vs. 96 (80m) for the baseline.
On the left, again, there were only 9 (28m:21s) for ASN and 72 (60m) for the baseline.
Lastly, ASN beats the baseline in the more complex direction “B
\Rightarrow
A” (82.2% vs 72.8%) and performs slightly worse in the easier direction of “A
\Rightarrow
B” (90.9% vs 95.1%).
Regarding
Q1
, these findings demonstrate that fine-tuning LLMs within a NeSy framework offers significant advantages while remaining computationally efficient. Moreover, this approach lays a strong foundation for future advances in guiding LLMs with probabilistic logic.

4.3
Q2 Mission Design for Unmanned Aerial Vehicles

Logic is crucial to ensure safety constraints, e.g., in autonomous navigation.
This is evident when considering autonomous agents navigating in human-inhabited spaces.
For example, a complex set of rules must be enforced when considering novel applications of Advanced Aerial Mobility, such as in cutting-edge logistics tasks.
Similarly, metropolitan areas and capital cities pose a particular challenge due to their complex infrastructure and large scale.
Within their borders, they often contain consulates of numerous countries, government buildings, etc.
They can also host major events that attract numerous international guests from all over the world.
All of this makes navigation particularly challenging because such events require additional temporary regulations that must be adhered to.
For example, Paris, France’s capital, was the host city for the 2024 Olympic Games.
Hence, in this experiment, we show how ASN scales NeSy methods for safe navigation to such large-scale scenarios by densely sampling Paris’ area.

In the ProMis framework
Kohaut et al. (2023)
, the requirements of public laws and operator preferences are encoded in a probabilistic logic language.
Essentially, one obtains i.i.d. generative models for each continuous point in the agent’s navigation space.
Although one can compute probabilities independently, splitting up work and parameters in a multithreaded setting, a large number of logic programs need to be solved.
For each
(x_{i},y_{i})\in\mathcal{S}
of points
\mathcal{S}
in a two-dimensional navigation space, we query for a valid
airspace
(x_{i},y_{i})
.
All models entailed via the constraint that encodes the query fulfill one of the rules defining wherever the UAV is allowed to visit the specified point.

ProMis obtains a probability for each coordinate
(x_{i},y_{i})
via Hybrid ProbLog
Gutmann et al. (2010)
.
Using a stochastic error model
Flade et al. (2021)
, it converts crowdsourced geographic features from OpenStreetMap into probabilistic facts.
These probabilistic facts encode probabilities for spatial relations between coordinates and tagged features, e.g., whether a coordinate is likely over a public park or far away from the nearest sports arena.
Note that the probabilities are “hard-coded” as they are obtained from the input map and not forwarded through a neural network, i.e., we use NPPs to encode the probabilities within the ASP program and use SLASH’s inference mechanism without training.
Via SLASH, we can then compute the query probability
p(Q)
from the stable models, which ASN computes for each coordinate.

To cover the area of 169km
2
, we must solve 6500
2
programs corresponding to all coordinate query pairs.
The resulting map can be seen in Fig.
6(b)
.
Despite the problem’s size and complexity, ASN successfully generated the visible map in
56m:32s
.
We took the time to compute a 500
2
grid for ProbLog and SLASH and multiplied it by 169 to obtain the time it would take to compute the whole grid.
For ProbLog, it would take
7d:15h
and
5d:9h
for SLASH.
This makes ASN 194 and 137 times faster on ProMis than ProbLog and SLASH, respectively.
These findings answer
Q2
strongly, and we conclude that ASN’s scalability opens up the opportunity to investigate further related problems. E.g., such as automated route planning
Stenger et al. (2013)
and reactive navigation
Patrinopoulou et al. (2023)
.
For further details on hyperparameter tuning of batch-size and other details, we refer to the appendices.

5
Related Work

5.1
Automated Reasoning

Logic programming traditionally relies on algorithms like Davis-Putnam-Logemann-Loveland (DPLL) for backtracking search
(
Davis et al., 1962
)
, augmented with no-good learning
Dechter and Meiri (1990)
and conflict-driven clause learning (CDCL)
Marques-Silva and Sakallah (1996)
.
One can make the distinction of backward and forward reasoners which start by the query and work backwards to the facts or the other way round. ASP implementations like clingo and DLV exemplify the latter approach, first grounding programs to propositional form then applying CDCL-based solving
Marques-Silva and Sakallah (1996)
. Satisfiability Modulo Theories (SMT) extends these foundations by integrating domain-specific theories (e.g., arithmetic, data structures) with Boolean satisfiability checking
Fazekas et al. (2018)
.

Although the field of SAT and SMT solvers is competitive and consistently improves at solving complex problems
Fazekas et al. (2018)
, single-core execution inherently limits their potential
Heule et al. (2015)
for NeSy applications.
Though some multithreaded extensions exist
Gebser et al. (2012)
, few leverage many-core parallelism effectively. ASN addresses this gap by introducing a parallel-by-design solving mechanism based on GNNs.

5.2
Probabilistic Logic Programming

Probabilistic inference over a model’s potential solutions is necessary to capture ambiguities in the modeled problem.
This is the case in Visual Question Answering problems
Antol et al. (2015)
, with various datasets and benchmarks emerging
Marino et al. (2019)
;
Schwenk et al. (2022)
;
Johnson et al. (2017)
;
Nerdimite (2022)
.
Probabilistic logic languages, like ProbLog
Fierens et al. (2015)
, propose Weighted
Sang et al. (2005)
and Algebraic Model Counting
Kimmig et al. (2017)
over a foundation of SAT-based Prolog.
Many approaches have emerged to accelerate the model counting (inference) step, e.g., through structural adaptations or by porting computations to GPU’s
Maene et al. (2025)
in a similar vein to our approach.
As these systems depend on automated reasoning, as discussed above, the performance gains of ASN directly translate to probabilistic logic languages.

5.3
Neural-Symbolic Systems

The NeSy approach combines neural and symbolic methods to leverage their complementary strengths. Systems like DeepProbLog
Manhaeve et al. (2018)
and Scallop
Huang et al. (2021)
extend the semantics of ProbLog with neural predicates, enabling the integration of neural perception (e.g., image recognition) into probabilistic logic.
Similarly, SLASH
Skryagin et al. (2022)
and NeurASP
Yang et al. (2020)
are DPPLs build on ASP.
However, all of these approaches are often limited by the high computational cost of symbolic reasoning.
Inspired by Scallop, Dolphin
Naik et al. (2025)
and Lobster
Biberstein and others (2025)
adopt a Datalog-based approach and accelerate inference on GPUs using Differentiable Top-k Proofs, Add-Mult Probabilities, and other differentiable provenance semirings.
KLay
Maene et al. (2025)
complements this direction by organizing arithmetic circuits into knowledge layers, optimized for fast parallel execution on GPUs.
Currently, no ASP-based DPPL supports solving on many-core hardware. By integrating ASN into SLASH, we present the first such system and demonstrate its scalability for neurosymbolic tasks.

6
Conclusions and Future Work

We introduced Answer Set Networks, a novel NeSy solver for Answer Set Programs using Reasoning Graphs. ASN integrates seamlessly with ASP-based Deep Probabilistic Programming Languages like SLASH. Our experiments demonstrate its effectiveness across various NeSy tasks. Notably, to the best of our knowledge, we are the first to fine-tune large language models within a DPPL framework.

Through Answer Set Networks, we have taken important steps toward unlocking a wide range of future NeSy AI applications by leveraging the scalability of GPU-based computations.
Hereby, ASNs allow for distributed graph learning, allowing the symbolic component to be scaled alongside the neural component to larger problems and datasets.
We acknowledge that symbolic reasoning is still NP-hard and observe that when the number of NPPs increases we must deal with an exponential number of choice definitizations.
To deal with even more complex problems, the next step is to integrate principles from CDCL into the message passing routine to eliminate unpromising choice definitizations and, hence, reduce the search space for potential solutions.
Additionally, leveraging GNNs as the backbone of RG opens the door to developing differentiable weighted-model semantics for ASN.

Appendix A
Additional Details on Message-Passing

Here, we want to address the message-passing once again, completing the node values update for the aggregate functions of
\min
and
\max
.
These were not discussed in the main paper to keep the formal definitions to the tasks considered in experiments.
With other words, the reader can skip all the descriptions and focus entirely on the Eq. (
11
).

Given a starting configuration of nodes that are considered true, we propagate truth values through the graph with the goal of computing the (stable) models of the program.
Thus, we associate with every node
v\in V
a boolean
node value

h_{v,t}\in\{0,1\}
at a time step
t\in\mathbb{N}
.
Except for
\top
, all nodes are initially set to false (0) at
t
= 0.

Aggregate nodes
v\in\mathcal{V},\tau_{v}\in\mathcal{R}_{\mathrm{aggr}}
additionally have terms
\beta_{v,l},\beta_{v,r}\in\mathbb{N}
and relation operators
\diamond_{v,l},\diamond_{v,r}\in\{=,\neq,<,>,\leq,\geq\}
linked to them, representing the guards of the corresponding aggregate.
Furthermore, each edge
e\in\mathcal{E}
has a
weight

w_{e}\in\begin{cases}\{-1,1\}&\textrm{if }e\in\mathcal{E}_{\mathrm{logical}},\\
\mathbb{Z}&\textrm{if }e\in\mathcal{E}_{\mathrm{aggr}}.\end{cases}

(10)

We can then define the node values for the next time step recursively as
\mathrm{h}_{v,t+1}=

\begin{cases}\mathrlap{\displaystyle\bigwedge_{\begin{subarray}{c}e=(u,v)\in\mathcal{E},\\
w_{e}=1\end{subarray}}h_{u,t}\land\bigwedge_{\begin{subarray}{c}e=(u,v)\in\mathcal{E},\\
w_{e}=-1\end{subarray}}\neg h_{u,t}}&\text{if }\tau_{v}=A_{\land},\\
\mathrlap{\displaystyle\bigvee_{\begin{subarray}{c}e=(u,v)\in\mathcal{E},\\
w_{e}=1\end{subarray}}h_{u,t}\lor\bigvee_{\begin{subarray}{c}e=(u,v)\in\mathcal{E},\\
w_{e}=-1\end{subarray}}\neg h_{u,t}}&\text{if }\tau_{v}=A_{\lor},\\
\beta_{v,l}\diamond_{v,l}|\mathcal{E}^{\mathrm{in},\top}_{t}(v)|\diamond_{v,r}\beta_{v,r}&\text{if }\tau_{v}=A_{\mathrm{count}},\\
\beta_{v,l}\diamond_{v,l}\displaystyle\sum_{e\in\mathcal{E}^{\mathrm{in},\top}_{t}(v)}w(e)\diamond_{v,r}\beta_{v,r}&\text{if }\tau_{v}=A_{\mathrm{sum}},\\
\beta_{v,l}\diamond_{v,l}\min^{\preceq}(\mathcal{W}^{\mathrm{in},\top}_{t}(v)\cup\{\mathrm{\#sup}\})\diamond_{v,r}\beta_{v,r}&\text{if }\tau_{v}=A_{\mathrm{min}},\\
\beta_{v,l}\diamond_{v,l}\max^{\preceq}(\mathcal{W}^{\mathrm{in},\top}_{t}(v)\cup\{\mathrm{\#inf}\})\diamond_{v,r}\beta_{v,r}&\text{if }\tau_{v}=A_{\mathrm{max}}.\end{cases}

(11)

where
\mathcal{E}^{\mathrm{in},\top}_{t}(v):=\{e|e=(u,v)\in\mathcal{E},h_{u,t}=1\}
is the set of incoming edges of
v\in\mathcal{V}
whose source nodes are 1 (true) at time step
t\in\mathbb{N}
and
\mathcal{W}^{\mathrm{in},\top}_{t}(v):=\{w_{e}|e\in\mathcal{E}^{\mathrm{in},\top}_{t}(v)\}
the set of corresponding edge weights.

Updates at the time step
t+1
can be understood in the following way.
Logical nodes
v\in\mathcal{V}_{\mathrm{logical}}
take on the value of the conjunction or disjunction of their incoming neighbors’ values, where the edge weight determines whether the corresponding node value is included positively or negatively.
We therefore call an edge
e\in\mathcal{E}_{\mathrm{logical}}

positive
if
w_{e}=1
and
negative
otherwise.
For aggregate nodes,
v\in\mathcal{V}_{\mathrm{aggr}}
, the edge weights of incoming edges signify the values to be aggregated, but are only included if the source node is considered true.
The node value of an aggregate node is then determined by checking the guards of the aggregated value. For
\mathrm{\#min}
and
\mathrm{\#max}
aggregates, we include the default value for empty sets.
I.e.,
\mathrm{\#sup}
and
\mathrm{\#inf}
for an infinite
T
and swapping both otherwise.

The RGs for the programs here are automatically generated with
