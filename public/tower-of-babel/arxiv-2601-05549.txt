Efficient Temporal-aware Matryoshka Adaptation for Temporal Information Retrieval
Tuan-Luc Huynh Weiqing Wang Trung Le, Thuy-Trang Vu Dragan Gašević Yuan-Fang Li Thanh-Toan Do

Abstract
Retrievers are a key bottleneck in Temporal Retrieval-Augmented Generation (RAG) systems: failing to retrieve temporally relevant context can degrade downstream generation, regardless of LLM reasoning. We propose Temporal-aware Matryoshka Representation Learning (TMRL) , an efficient method that equips retrievers with temporal-aware Matryoshka embeddings. TMRL leverages the nested structure of Matryoshka embeddings to introduce a temporal subspace, enhancing temporal encoding while preserving general semantic representations. Experiments show that TMRL efficiently adapts diverse text embedding models, achieving competitive temporal retrieval and temporal RAG performance compared to prior Matryoshka-based non-temporal methods and prior temporal methods, while enabling flexible accuracy–efficiency trade-offs.



1
Introduction

Retrieval-augmented Generation (RAG)
28
is a paradigm in information retrieval where systems generate answers grounded in external knowledge
29
.
By combining LLM reasoning with retrieved evidence, RAG tackles knowledge-intensive tasks like question answering (QA), mitigating the limitations of static LLM knowledge and reducing hallucinations.
Within QA, Temporal QA (TQA) presents unique challenges that go beyond semantic relevance. Answering time-sensitive queries requires identifying relevant time spans or even reasoning over time-evolving facts
37
.
Driven by the strong reasoning capabilities of LLMs, recent research has proposed a myriad of datasets, analyses, and methods to benchmark TQA
48
;
9
;
46
;
41
; however, they largely focus on LLM reasoning, overlooking the crucial role of retrieval.

Figure 1:

Effectiveness of the proposed augmented data pipeline and Temporal-aware Matryoshka Representation Learning (TMRL) on the Temporal RAG benchmark of Temporal Nobel Prize (TNP).
The results show that poor retrieval limits RAG performance regardless of Qwen3-8B’s reasoning ability.
Adapting Contriever with TMRL enables the RAG system to achieve competitive performance
while reducing storage footprint and inference latency.

We argue that in temporal RAG systems, the main bottleneck lies in the
retriever
, which is usually a text embedding model (TEM).
For example, a query like “What are Australia’s gun laws in 2026?” may fail if the retriever retrieves outdated documents. Following the December 2025 Bondi Beach shooting, legislation is changing rapidly.
With limited temporal encoding capability, a semantic retriever might struggle to distinguish older from current sources, limiting downstream generation regardless of the LLM’s reasoning ability.

Fine-tuning text embedding models (TEMs) for temporal tasks often degrades semantic retrieval performance due to catastrophic forgetting
34
;
45
;
13
. Prior work
49
;
1
mitigates this issue by maintaining separate temporal and semantic retrievers with query routing, which increases both training and inference costs.
At the same time, modern corpora often contain millions of documents and continue to grow, making scalable and efficient retrieval critical. As a result, Matryoshka Representation Learning (MRL)
23
has emerged as a standard approach in modern TEMs
27
;
36
. MRL addresses efficiency constraints by structuring embeddings hierarchically, enabling flexible truncation to trade off performance and computation. Together, these observations motivate a more efficient temporal retriever: a single model that supports temporal retrieval with Matryoshka embeddings.

We propose
Temporal-aware Matryoshka Representation Learning (TMRL)
, an efficient adaptation method that equips TEMs with Matryoshka embeddings to enhance temporal representation while preserving general semantic performance. Our approach is motivated by the hypothesis that, if Matryoshka embeddings hierarchically compress semantic information, part of this nested structure can be explicitly dedicated to encoding temporal signals.
Additionally, TMRL leverages the multi-scale nature of Matryoshka embeddings through self-distillation, where higher-dimensional representations provide supervisory signals to their truncated counterparts, strengthening temporal encoding across embedding scales.
Therefore, TMRL improves temporal retrieval without requiring query routing and incurs no additional inference overhead, since LoRA can be merged into the TEM.

To provide clean temporal supervision for TMRL, we refine the Temporal Nobel Prize (TNP) dataset
49
using a temporal data augmentation pipeline that generates paragraph-level temporal contrastive examples, reducing conflicts caused by multiple temporal expressions.
Building on a strong LoRA-based baseline, we develop TMRL using our augmented TNP dataset and extend evaluation to the TimeQA dataset
6
, demonstrating strong temporal retrieval performance, efficiency, and robustness.
In summary, we make the following contributions:

•

We propose
Temporal-aware Matryoshka Representation Learning (TMRL)
, the first efficient, plug-and-play, temporal-aware Matryoshka adaptation method for text embedding models.

•

We introduce a temporal contrastive learning augmentation pipeline that refines and augments existing temporal datasets with clean training examples for temporal information retrieval.

•

Experiments on the TNP and TimeQA datasets across six TEMs demonstrate TMRL’s effectiveness and efficiency for temporal retrieval and temporal RAG.

2
Related Work

Dense retrieval.

Text embedding models (TEMs) learn an encoder
f_{\theta}(\cdot)
that maps an input sequence of
L
tokens
q=(q_{1},\ldots,q_{L})
into a sequence of contextualized token representations:

f_{\theta}(q)=[h_{1},\ldots,h_{L}]\in\mathbb{R}^{L\times d},\vskip-5.0pt

(1)

where
h_{i}\in\mathbb{R}^{d}
denotes the hidden representation of the
i
-th token produced by the encoder. To obtain a fixed-size embedding from this variable-length sequence, a pooling function is applied:

\mathrm{Pool}(f_{\theta}(q))\in\mathbb{R}^{d}.\vskip-5.0pt

(2)

Depending on the design choice, the pooling operation may correspond to selecting the
[CLS]
token, or end-of-sequence token, or computing the average over all tokens.
Most TEMs are trained with a contrastive learning objective, using the fixed
d
-dimensional InfoNCE loss with in-batch negatives
(
12
;
58
)
.
Given a query
q
, a positive passage
p^{+}
, and a set of negative passages
\mathcal{N}_{q}=\{p^{-}_{1},\ldots,p^{-}_{n}\}
, the loss is:

\begin{gathered}\mathcal{L}_{\mathrm{InfoNCE}}^{(d)}(q,p^{+},\mathcal{N}_{q})=-\log\\
\frac{e^{\,\mathrm{sim}^{(d)}(f_{\theta}(q),f_{\theta}(p^{+}))/\tau}}{e^{\,\mathrm{sim}^{(d)}(f_{\theta}(q),f_{\theta}(p^{+}))/\tau}{+}\sum\limits_{i=1}^{n}e^{\,\mathrm{sim}^{(d)}(f_{\theta}(q),f_{\theta}(p^{-}_{i}))/\tau}},\vskip-5.0pt\end{gathered}

(3)

where
\tau
is a temperature hyperparameter and the similarity function is typically cosine similarity:

\mathrm{sim}^{(m)}(x,y)=\frac{\langle x_{1:m},\,y_{1:m}\rangle}{\lVert x_{1:m}\rVert\,\lVert y_{1:m}\rVert},\vskip-5.0pt

(4)

where
(\cdot)_{1:m}
denotes slicing of the first
m
dimensions.
Both queries and passages are represented as dense vectors.
The corpus is pre-indexed, allowing a TEM to encode a query and perform approximate nearest-neighbor search
20
over the precomputed passage embeddings.

Temporal Information Retrieval (TIR) & Temporal Question Answering (TQA).

TIR aims to retrieve documents that satisfy both semantic relevance and temporal constraints
21
;
37
, while TQA further requires time-aware reasoning beyond relevance matching.
Prior to LLMs, TQA research primarily enhanced pre-trained readers using temporal spans, document timestamps, or temporal attention mechanisms
8
;
40
;
47
;
7
.
Despite recent progress in dense retrieval
57
;
26
and TQA
48
;
9
;
3
,
research in TIR and TQA has been largely overshadowed by LLM-focused studies, leaving the integration of temporal signals into dense retrievers underexplored.

Recent work begins to address this gap: TsContriever
49
introduces supervised temporal contrastive learning, and TempRetriever
1
extends it with semantic–temporal embedding fusion.
However, both require full finetuning and inference-time routing between semantic and temporal retrievers.
TempRetriever additionally depends on external temporal extractors, increasing model complexity and inference latency.
On the other hand, TSM
13
scales training cost by training and merging multiple time-specific retrievers.
Modifying the RAG framework to tailor for reasoning-intensive TQA has also emerged as a growing direction
10
;
38
;
55
.
In contrast, TMRL is a single-model, plug-and-play method that equips TEMs with temporal-aware Matryoshka embeddings, enhancing temporal retrieval while preserving semantic performance for more efficient Temporal RAG.

Matryoshka Representation Learning (MRL).

Modern TEMs
42
;
36
increasingly support Matryoshka embeddings, which incorporate MRL
(
23
)
into the training objective of TEMs to produce nested, truncatable embeddings: a full embedding
f_{\theta}(x)\in\mathbb{R}^{d}
, plus lower-dimensional prefixes corresponding to truncation levels
\mathcal{M}=\{64,128,\ldots,d\}
.
Matryoshka embeddings allow flexible adaptation to varied computational power.
For semantic retrieval, the MRL contrastive learning objective is naturally defined as:

\mathcal{L}_{\mathrm{MRL}}=\sum_{m\in\mathcal{M}}w_{m}\mathcal{L}_{\mathrm{InfoNCE}}^{(m)}(q,p^{+},\mathcal{N}_{q}),\vskip-5.0pt

(5)

where
w_{m}
denotes the scaling factor for each truncated dimension.
Prior work attempts to enable Matryoshka embeddings for LLMs to improve the efficiency of IR.
Matryoshka-Adaptor (M-Adaptor)
53
employs a bottleneck adaptor for this purpose.
Very recently,
54
introduced a sequential MRL training framework to improve performance compared to M-Adaptor.
TMRL shares a similar motivation as M-Adaptor:
both use parameter-efficient fine-tuning to equip TEMs with Matryoshka embeddings.
However, TMRL emphasizes TIR, whereas M-Adaptor preserves general semantic retrieval.

These representations are used in the temporal subspace contrastive loss
\mathcal{L}_{\mathrm{Temp}}

), to endow the Matryoshka embeddings with a dedicated temporal subspace, yielding the final embeddings defined in Eq.
6
and Eq.

.

3
Method

In this section, we first motivate the use of LoRA for efficient temporal adaptation and for enabling the Matryoshka property in text embedding models (TEMs), constituting a strong baseline.
We then introduce
Temporal-aware Matryoshka Representation Learning (TMRL)
, which leverages the Matryoshka structure to introduce an explicit temporal subspace, enhancing temporal representations across embedding dimensions.
The core concepts of TMRL are illustrated in Figure
2
.

3.1
LoRA-based temporal adaptation.

Fine-tuning TEMs on temporal retrieval datasets often incurs a trade-off between semantic and temporal representations
(
13
)
.
Prior approaches
49
;
1
address this via query routers that switch between fine-tuned and original models, but full fine-tuning is costly and routing increases training complexity and inference latency.
LoRA
(
14
)
mitigates this trade-off by freezing the semantic TEM and training a small set of additional parameters for temporal adaptation.
It offers stable training, lower hyperparameter sensitivity, and can be merged into the base model at zero inference overhead (Table
1
).
In Section
5
, we empirically show that LoRA efficiently endows TEMs with the Matryoshka property while preserving semantic retrieval, establishing it as a strong baseline for TMRL.
For simplicity, we continue to denote LoRA-fine-tuned retrievers as
f_{\theta}
in the following sections.

3.2
Temporal-aware Matryoshka Representation Learning

Matryoshka temporal subspace.

Time-sensitive queries contain temporal expressions that specify temporal constraints for retrieval.
Most semantic TEMs encode temporal and non-temporal information jointly, but non-temporal semantics often dominate the representation, overshadowing temporal signals and leading to suboptimal temporal retrieval performance, as observed in zero-shot performance in Table
1
.

We conceptually view a time-sensitive query or passage as containing two components:
a temporal component
q_{\mathrm{T}}
(or
p_{\mathrm{T}}
)
and a non-temporal semantic component
q_{\mathrm{S}}
(or
p_{\mathrm{S}}
),
where the temporal component typically comprises fewer tokens.
Let
m\in\mathcal{M}
and
t
, with
m\geq t
, denote the target Matryoshka embedding dimension and the predefined temporal subspace dimension, respectively.
To preserve temporal cues across all Matryoshka truncation levels, we allocate the first
t
dimensions of the embedding to encode temporal information (Eq.
6
).
As a result, we effectively structure the truncated embedding as the concatenation of a temporal subspace (first
t
dimensions) and a semantic subspace (the remaining
m-t
dimensions) (Eq.
7
), ensuring that all Matryoshka embeddings retain the temporal subspace (Top of Figure
2
).

\displaystyle f_{\theta}(q)_{1:t}\approx q_{\mathrm{T}},

(6)

\displaystyle f_{\theta}(q)_{1:m}\approx f_{\theta}(q)_{1:t}\ \oplus\ f_{\theta}(q)_{(t+1):m}.\vskip-10.00002pt

(7)

Let
\mathcal{T}(q)\subseteq\{\texttt{[CLS]},1,\ldots,L\}
denote the set of temporal token indices in a time-sensitive query representation
f_{\theta}(q)=\{h_{\texttt{[CLS]}},h_{1},\ldots,h_{L}\}
. The temporal token representations are defined as:

f(q)_{\mathrm{T}}=\{\,h_{i}\mid i\in\mathcal{T}(q)\,\}.\vskip-5.0pt

(8)

Regarding CLS-pooling TEMs, we include the
[CLS]
token in
\mathcal{T}(q)
as it aggregates global information and may encode temporal signals.

To compress the temporal information into a
t
-dimensional subspace, we introduce a
temporal projector

\mathcal{P}:\mathbb{R}^{d}{\rightarrow}\mathbb{R}^{t}
,
a two-layer feedforward network that follows the TEM’s activation and layer-normalization configuration.

\mathcal{P}
takes in only temporal tokens
f(q)_{\mathrm{T}}
to learn a compact and compatible
t
-dimensional temporal representation.
The final temporal representation for query
q
is obtained by averaging over the projected temporal tokens:

\bar{q}_{\mathrm{T}}=\frac{1}{|\mathcal{T}(q)|}\sum_{i\in\mathcal{T}(q)}\mathcal{P}(h_{i})\;\in\;\mathbb{R}^{t}.\vskip-5.0pt

(9)

Temporal subspace contrastive learning.

The final step is to incorporate the projected temporal representation
\bar{q}_{\mathrm{T}}
into the contrastive learning framework to obtain the desired embedding in Eq.
7
.
To this end, we introduce a temporal subspace contrastive learning objective that integrates
\bar{q}_{\mathrm{T}}
into the contrastive learning framework (Bottom of Figure
2
).
Since temporal contrastive learning operates on positive and negative
queries
rather than passages
49
, we define the negative set as
\mathcal{N}_{p}=\{q^{-}_{1},\ldots,q^{-}_{n}\}
.
The InfoNCE loss for the
t
-dimensional temporal subspace is:

\begin{gathered}\mathcal{L}^{\mathrm{q}}_{\mathrm{Temp}}(p,q^{+},\mathcal{N}_{p})=-\log\\
\frac{e^{\,\mathrm{sim}^{(t)}({\color[rgb]{0.5,0.5,0.5}\bar{p}_{\mathrm{T}}},\,{\color[rgb]{0.5,1,0}f_{\theta}(q^{+})})/\tau}}{e^{\,\mathrm{sim}^{(t)}({\color[rgb]{0.5,0.5,0.5}\bar{p}_{\mathrm{T}}},\,{\color[rgb]{0.5,1,0}f_{\theta}(q^{+})})/\tau}+\sum_{i=1}^{n}e^{\,\mathrm{sim}^{(t)}({\color[rgb]{0.5,0.5,0.5}\bar{p}_{\mathrm{T}}},\,{\color[rgb]{1,0.47,0.62}f_{\theta}(q^{-}_{i})})/\tau}},\\
\mathcal{L}^{\mathrm{p}}_{\mathrm{Temp}}(p,q^{+},\mathcal{N}_{p})=-\log\\
\frac{e^{\,\mathrm{sim}^{(t)}({\color[rgb]{0.5,0.5,0.5}f_{\theta}(p)},\,{\color[rgb]{0.5,1,0}\bar{q}^{+}_{\mathrm{T}}})/\tau}}{e^{\,\mathrm{sim}^{(t)}({\color[rgb]{0.5,0.5,0.5}f_{\theta}(p)},\,{\color[rgb]{0.5,1,0}\bar{q}^{+}_{\mathrm{T}}}))/\tau}+\sum_{i=1}^{n}e^{\,\mathrm{sim}^{(t)}({\color[rgb]{0.5,0.5,0.5}f_{\theta}(p)},\,{\color[rgb]{1,0.47,0.62}(\bar{q}^{-}_{i})_{\mathrm{T}}})/\tau}},\\
\mathcal{L}_{\mathrm{Temp}}=\mathcal{L}^{\mathrm{q}}_{\mathrm{Temp}}+\mathcal{L}^{\mathrm{p}}_{\mathrm{Temp}},\end{gathered}\vskip-5.0pt

(10)

where
\bar{p}_{\mathrm{T}}
,
\bar{q}^{+}_{\mathrm{T}}
, and
(\bar{q}^{-}_{i})_{\mathrm{T}}
denote the passage, positive, and negative queries counterpart of Eq.
8
.
This loss encourages the first
t
-dimensions to align with the projected
\bar{p}_{\mathrm{T}}
and
\bar{q}^{+}_{\mathrm{T}}
, while pull it apart from
(\bar{q}^{-}_{i})_{\mathrm{T}}
.
This way, we explicitly encode temporal information in the allocated
t
-dimensional temporal subspace (Eq.
6
), resulting in our temporal-aware Matryoshka embeddings (Eq.
7
).

Local and structural self-distillation.

Since lower-dimensional Matryoshka embeddings are trained to mimic higher-dimensional ones, similarities in the full embedding space naturally provide a supervisory signal
53
.
We thus view MRL as a form of self-distillation, where higher-dimensional embeddings act as teachers for their truncated counterparts.
Building on this perspective, we introduce auxiliary objectives to strengthen temporal-aware Matryoshka embeddings.
The first objective preserves
local structure
by aligning nearest-neighbor similarities in the teacher space, encouraging student embeddings to retain fine-grained semantic relationships from the full-dimensional representation.
Given a mini-batch of embeddings
X^{(d)}\in\mathbb{R}^{B\times d}
and their corresponding
m
-dimensional Matryoshka embeddings
X^{(m)}\in\mathbb{R}^{B\times m}
, where
d{>}m
, we employ the top-
k
pairwise similarity loss to preserve local similarity:

\begin{gathered}\mathcal{L}_{\mathrm{Dist}}=\sum\limits_{\mathclap{\begin{subarray}{c}m\in\mathcal{M},\\
m\neq d\end{subarray}}}\sum_{i}\sum_{j\in\mathcal{N}}\left\lVert\mathrm{sim}^{(d)}(x_{i},x_{j})-\mathrm{sim}^{(m)}(x_{i},x_{j})\right\rVert_{1}\\
\vskip-5.0pt\text{where}\quad\mathcal{N}=\operatorname{arg\,top}_{k}\,\mathrm{sim}^{(d)}(x_{i},x_{j}).\end{gathered}\vskip-5.0pt

(11)

Beyond local alignment, preserving the
global structure
of the embedding space is also important. While pairwise similarity loss enforces local consistency, it fails to capture the overall geometry.
Because full-dimensional embeddings encode richer relational structure, we adopt linear Centered Kernel Alignment (CKA)
22
as a structural regularizer, encouraging lower-dimensional embeddings to remain geometrically aligned with the teacher space at the batch level. This complements the local pairwise loss by preserving global semantic geometry.
The linear CKA between two embedding sets can be expressed using covariance
\mathrm{cov(\cdot,\cdot)}
as:

\mathrm{CKA}(X,Y)=\frac{\|\mathrm{cov}(X,Y)\|_{F}^{2}}{\|\mathrm{cov}(X,X)\|_{F}\,\|\mathrm{cov}(Y,Y)\|_{F}}.\vskip-5.0pt

(12)

Let us denote the centered variants of the
d
and
m
-dimensional embeddings as:

\tilde{X}^{(d)}=X^{(d)}-\frac{1}{B}\mathbf{1}\mathbf{1}^{\top}X^{(d)},\;\tilde{X}^{(m)}=X^{(m)}-\frac{1}{B}\mathbf{1}\mathbf{1}^{\top}X^{(m)}.\vskip-5.0pt

(13)

The auxiliary Matryoshka CKA is defined as:

\mathcal{L}_{\mathrm{CKA}}=\sum\limits_{\mathclap{\begin{subarray}{c}m\in\mathcal{M},\\
m\neq d\end{subarray}}}(1-\mathrm{CKA}(\tilde{X}^{(d)},\tilde{X}^{(m)}))\vskip-5.0pt

(14)

Optimization objective.

Combining with the semantic MRL objective in Eq.
5
, the temporal projector
\mathcal{P}
and the LoRAs are jointly optimized with the following TMRL training objective:

\begin{gathered}\mathcal{L}_{\mathrm{TMRL}}=\mathcal{L}_{\mathrm{MRL}}+\alpha\mathcal{L}_{\mathrm{Temp}}+\beta\mathcal{L}_{\mathrm{Dist}}+\gamma\mathcal{L}_{\mathrm{CKA}},\end{gathered}\vskip-5.0pt

(15)

where
\alpha,\beta,\gamma
are hyperparameters (ablation in Section
5.3
).

4
Temporal Contrastive Learning Data Augmentation

The temporal projector
\mathcal{P}
in TMRL requires clean temporal expressions from both queries and passages.
However, upon inspecting the Temporal Nobel Prize (TNP) dataset
49
, we observe that some training samples are ill-suited for temporal contrastive learning (e.g., Figure
3
, left).
In particular, passages may contain multiple temporal expressions (e.g., “In 1972” and “In 1966”), which can induce conflicting temporal gradient signals during contrastive training by forcing a query’s temporal expression to align with unrelated years.
This observation motivates a refinement of the original dataset.
As illustrated in Figure
3
(right), we
(1) split long passages into shorter passages such that each resulting passage contains a single temporal expression; and
(2) systematically generate additional positive and negative queries for each shorter passage based on the original queries, while remaining faithful to the source corpus.

Passage splitting.

We use SUTime
4
to identify temporal expressions at the sentence level.
To preserve semantic context for retrieval, we iteratively merge adjacent sentences until the resulting passage would contain more than one temporal expression, at which point merging stops.
Sentences containing multiple temporal expressions are discarded.
This procedure yields passages with a single temporal expression while retaining as much local context as possible.

Positive/Negative query augmentation.

To systematically guide query augmentation, we characterize the temporal properties of queries along three dimensions.
First, we focus on L2 (time–event) and L3 (event–event) temporal understanding
43
, excluding L1 (time–time relations) as it primarily involves temporal arithmetic, which is uncommon in information retrieval.
Second, we adopt the query taxonomy of
17
, categorizing queries as
explicit
,
implicit
, or
temporal answer
, and exclude
ordinal
queries, which rely on ordinal cues (e.g., “first”, “second”) that could be missing from the corpus.
Finally, we employ Allen’s interval relations
2
as a rubric to control the temporal alignment between each query and its corresponding passage.

We design a structured schema and prompt template (Table
13
and
11
) to instruct Qwen3-4B-Instruct-2507
51
to generate augmented positive and negative queries from the original TNP dataset.
The LLM also extracts temporal spans from queries and passages, refined with preliminary SUTime outputs, without introducing new facts to preserve dataset fidelity.
Examples queries are shown on the right of Figure
3
.
The final dataset statistics are summarized in Appendix
A.3
.

Experimental Setting

Datasets and metrics.

We evaluate our methods on Temporal Nobel Prize
49
and extend to TimeQA
6
.
Following the BEIR benchmark
44
, we report nDCG@10 and Recall@100.
To assess general semantic retrieval performance, we also report nDCG@10 on the Natural Questions (NQ) dataset
24
from BEIR using the original embedding dimension of each TEM.
Please refer to Appendix
A.3
for dataset statistics and further details.

Baselines.

For both datasets, we compare TMRL’s
full-dimensional retrieval performance
against:
BM25
39
,
zero-shot performance of the original TEMs,
Ts-Retriever
49
,
and TempRetriever (element-wise interaction)
1
.
To evaluate the quality of
Matryoshka embeddings
, we include
Matryoshka Adaptor (M-Adaptor)
53

and vanilla LoRA-based MRL as baselines.
Each method is evaluated on six open-source TEMs with fewer than 600 M parameters: contriever
16
,
gte-base (gte)
30
,
nomic-embed-text-v1.5 (nomic)
36
,
gte-base-en-v1.5 (gte1.5)
56
,
bge-base-en-v1.5 (bge)
50
,
and bge-m3 (bgem3)

.

Implementation details.

All experiments are conducted on a single NVIDIA A100 80GB GPU using the AdamW optimizer

.
For Ts-Retriever and TempRetriever, we follow the training settings reported in their respective papers.
For M-Adaptor, LoRA-based MRL, and TMRL, we use a batch size of 256 with 4 hard negatives, a learning rate of
1\times 10^{-4}
, and train for 5 epochs (1 epoch for
nomic
).
We apply LoRA with rank
r{=}4
to all linear layers of the TEM for LoRA-based methods.
TMRL hyperparameters are elaborated in Sections
5.3
.
Additional implementation details are provided in Appendix
A.2
.

6
Conclusion

We propose Temporal-aware Matryoshka Representation Learning (TMRL), an efficient Matryoshka adaptation method that equips TEMs with temporal-aware embeddings, improving temporal retrieval while preserving semantic performance.
We also introduce a temporal contrastive data augmentation pipeline that provides cleaner temporal supervision.
Experiments show that TMRL enhances temporal encoding in retrievers, improves downstream temporal RAG performance, and enables flexible accuracy–efficiency trade-offs under varying computational constraints.

Limitations

Despite evaluating TMRL across six widely used text embedding models, we do not evaluate our method on LLM-based embedding models due to resource constraints. In addition, we adapt only the TimeQA dataset for benchmarking temporal information retrieval and rely on the existing Temporal Nobel Prize dataset for evaluation, which we believe to be of high quality.
There is currently no standardized guideline for converting temporal QA datasets into temporal information retrieval benchmarks. As a result, our preprocessing and dataset adaptation rely on a set of heuristics that may not generalize to all temporal datasets.
Our temporal data augmentation pipeline leverages a non–state-of-the-art LLM to generate contrastive queries.
While we apply extensive quality inspection, LLM-generated data may still introduce noise.
Finally, to ensure clean and unambiguous training signals, our augmented temporal contrastive learning dataset follows a simple principle: splitting long passages into shorter passages and discarding sentences containing multiple temporal expressions.
Extending TMRL to handle passages containing multiple temporal expressions, which is common in real-world documents, remains an open direction for future work, despite the performance gains observed under our evaluation setting.

TimeQA is a popular TQA benchmark constructed from Wikipedia, where high semantic similarity between queries and documents makes evaluating temporal encoding challenging
49
.
To adapt TimeQA into a temporal information retrieval benchmark, we perform careful preprocessing to mitigate the issue of queries and passages being overly semantically aligned
49
.
We use the Wikipedia snapshot
enwiki-20211220-pages-articles
, which is the only publicly accessible snapshot with dates closest to those used in TimeQA.
We use
index_enwiki-20220820
Wikipedia index database.
This snapshot is first processed following FlashRAG

https://github.com/RUC-NLPIR/FlashRAG/blob/main/docs/original_docs/process-wiki.md

and then filtered using SUTime to retain only pages that contain at least one temporal expression and include an answer from the TimeQA train, development, or test sets.

After splitting and generating our augmented dataset, we further filter the original training set to retain only passages whose Wikipedia IDs match those in the augmented dataset, resulting in the “Original (Modified)” column in Table
9
.
We use this training set as the baseline data for our augmentation pipeline.
We do not modify the development set so that model selection is still evaluated under a semantically dominant retrieval setting.

To construct the test corpus, we combine all training, development, and test files from both the easy and hard splits.
We then use the index database to map the corresponding passages’ Wikipedia URLs to Wikipedia IDs.
All pages with non-null Wikipedia IDs from the selected snapshot are accumulated to form the test corpus.
To create the test qrel and corpus files, we retain only queries that are answerable.

Prompt template for temporal annotation

You are a temporal annotation expert for information retrieval. We provide you with a query that may contain one or many temporal expressions and the corresponding SUTIME’s output for your reference. We also provide you with previously annotated examples of positive and negative samples of the query; use them as references if they are semantically relevant to the query. Your job is to generate high-quality positive passages and negative passages for temporal contrastive learning.
Your final output are annotated JSONs (no indentation) that strictly follow the provided JSON schema.

Your temporal annotations must be more precise and reliable than SUTIME or HeidelTime, with top-tier accuracy. You must follow the definitions and instructions below.

* Allen relations and descriptions:
<Allen relations and descriptions>

* Instructions:

1. You must output one or multiple valid JSONs, delimited by a newline, strictly following this pydantic schema:
<Pydantic JSON Schema>

2. "query_id": must be assigned with the provided "query_id".

3. “query":
- A query is a provided sentence that may contain one or many temporal expressions.
- Please note that SUTIME only provides explicit temporal expressions for the query and they are not perfect; therefore, you must double-check them and further detect additional explicit and implicit temporal expressions such as events.
- You must extract all events that are anchored to specific datetime (e.g., “2000 FA Cup Final”, “the 2007 election”, etc.).
- The "temporal" field should be extracted as written from the query’s text and they must be concise, such as: "in April, 1906", "2 July 2010", "2004 general election", etc.

4. "positive_passages":
- Natural, QA-style questions with diverse phrasing that seek information from the query. Each question must contain exactly one extractable temporal expression, logically align with one of the query’s temporal expressions, yet be diverse in Allen relations.
- Based on the query’s temporal expressions, you must generate "positive_passages" that cover all "TemporalQueryType", including ’Explicit’, ’Implicit’, and ’TemporalAnswer’, when possible:
- You MUST prioritise generating questions with explicit temporal constraints, like "in 2010", "from 2010 to 2015", etc. They must logically align with the query’s temporal expression(s), such as being equals, overlapping with, or being contained within the query’s temporal expression(s). If the query has multiple temporal expressions, the generated questions must logically align with at least one of them.
- You should also prioritise generating questions with implicit temporal constraints, such as "after EVENT", "before EVENT". These must logically align with the query’s temporal expression(s).
- For both explicit and implicit "TemporalQueryType" questions, you must not use phrases like what/which date/day/month/year/time or when etc., that inquire about time. You must not confuse this with TemporalAnswer questions.
- You can also generate "TemporalAnswer" (asking for datetime/duration/time-range of an EVENT, e.g., "When did EVENT happen?", "What time did he arrive?"). For this type of question, you must not add any temporal expression and you must set: "TemporalQueryType": "TemporalAnswer", "allen_relation": "Empty", and "temporal": []. Use sparingly (less than 2 per query, only when explicit/implicit cannot be formed).
- "temporal" field: must extract all exact text spans of the temporal expressions that exist in the generated question (not normalized or paraphrased). Regarding explicit and implicit "TemporalQueryType", they must be concise temporal expressions as written, such as "after July 2010", "from 2012 to 2014", that are not just normalized dates. For instance, instead of "In 1906 he moved with his family to a farm", prefer the concise "In 1906" and keep prepositions or context words that anchor the time, e.g., ’from’, ’in’, ’after’, etc. Regarding "TemporalAnswer" passages, the "temporal" field must be an empty list.
- Allen relation: consider Passage = Event A and Query = Event B. Must be correct and align with the provided definition.
- “docid”: must remain the same as provided.
- Quantity: For each split/rewritten query, you must generate a list of 5 high-quality positive passages, prioritizing quality over quantity.

5. "negative_passages": follow the same format as "positive_passages", but represent contexts that are temporally mismatched or semantically irrelevant to the query. Based on the query’s temporal expressions, you must generate "negative_passages" that cover all "TemporalQueryType", including "Explicit", "Implicit", and "TemporalAnswer", when possible. They must be hard, temporally-confused, yet diverse in Allen relations questions that cover all following cases:
- Case 1: Questions with temporal expressions that mismatch with the query’s temporal expression(s):
- If the query specifies a span (e.g., 2005–2007), use an interval that falls completely outside it (e.g., 2008, before 2005, after 2007).
- Adjacent years or ranges are valid negatives (e.g., query = 2010, negative = 2009).
- Use shifted but non-overlapping intervals (e.g., query = 2010, negative = 2012–2014).

Input format

Task

Decide whether the passage is relevant to the query for temporal information retrieval (qrel construction).
A passage is relevant if and only if ALL of the following conditions are satisfied:

1. Temporal correctness (mandatory): The passage must clearly satisfy the temporal constraint(s) explicitly or implicitly expressed in the query (e.g., in, before, after, between, from … to …).
- Explicit dates or time spans in the passage are acceptable.

- Implicit temporal coverage is acceptable only if it unambiguously covers the queried time period (e.g., “served from 1989–1993” satisfies “in 1991”).

- Vague, approximate, or underspecified temporal expressions (e.g., “around that time”, “in the early days”, “in the 1900s”) do not satisfy temporal constraints.

- If the temporal alignment between the query and passage is unclear, the passage must be judged not relevant.

2. Answer-term validity within time: The passage must contain all answer_terms.
- The temporal information must be directly associated with the answer_terms, meaning the answer_terms refer to the same entity, event, or state that is valid within the specified time frame. A passage is relevant if and only if ALL of the following conditions are satisfied:

- Merely mentioning the answer_terms elsewhere in the passage without temporal grounding is insufficient.

3. No external inference: Judge relevance only based on the information explicitly present in the passage.

- Do not rely on external knowledge, common facts, or assumptions.

- Do not infer missing dates or temporal relations.

4. Binary decision rule: If any of the above conditions is not satisfied, the passage is not relevant.

Output format

- Output the integer index only if the passage is relevant.

- Otherwise, output -1.

- Output only the index or -1.

- Do not include explanations, reasoning steps, or additional text.

- Do not guess or assign partial relevance.
