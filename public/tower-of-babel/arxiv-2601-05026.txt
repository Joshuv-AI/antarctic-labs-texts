A data structure for monomial ideals with applications to signature Gröbner bases Conference: International Symposium on Symbolic and Algebraic Computation; July 2026; Oldenburg, Germany Proceedings of the 2026 International Symposium on Symbolic and Algebraic Computation (ISSAC ’26)
Pierre Lairez, Rafael Mohr, Théo Ternier

Abstract
. We introduce monomial divisibility diagrams (MDDs), a data structure for monomial ideals that supports insertion of new generators and fast membership tests. MDDs stem from a canonical tree representation by maximally sharing equal subtrees, yielding a directed acyclic graph. We establish basic complexity bounds for membership and insertion, and study empirically the size of MDDs. As an application, we integrate MDDs into the signature Gröbner basis implementation of the Julia package AlgebraicSolving.jl . Membership tests in monomial ideals are used to detect some reductions to zero, and the use of MDDs leads to substantial speed-ups.



1.
Introduction

A Gröbner basis computation breaks down into two kinds of work:
operations on monomials (multiplications, comparisons, divisibility tests),
and arithmetic operations in the ground field. These arithmetic operations
happen during reductions of new polynomials by previsouly computed relations.
A polynomial which reduces to zero does not contribute to the output of a Gröbner basis computation.
The family of algorithms stemming from the
F
5
algorithm
(
Faugère 2002
;
Eder & Roune 2013
;
Eder & Faugère 2017
;
Gao et al. 2016
;
Lairez 2024
)
relies on the concept of a
signature
, a monomial attached to every polynomial, which enables many reductions to zero, if not all, to be detected before they happen.
This typically decreases the number of arithmetic operations, at the cost of more monomial operations.

As it turns out, one source of reductions to zero in Gröbner basis computations is the trivial commutator relation
fg-gf=0
.
Reductions to zero arising from those can be avoided using signatures by what was initially called the
F
5
criterion, whose verification requires checking whether a given signature lies in a monomial ideal.
Applying this criterion may yield a substantial
number of membership tests in a monomial ideal. For
example, computing a Gröbner basis of the benchmark ideal

eco-14
with the
F
5
implementation provided by

AlgebraicSolving.jl
yields 117 861 802 membership tests. In
this example, membership queries dominate not only the symbolic
workload but also represent a significant part of the whole
computation, as opposed to non-signature Gröbner basis algorithms,
such as
F
4

Faugère 1999
, where the computational workload
typically stems mostly from arithmetic operations. This raises the
question: can we design a data structure for monomial ideals that
supports both efficient insertion of new monomials and fast membership
tests?

Representing a monomial ideal by a list of generators is the most obvious data structure.
An ideal
I\subseteq\mathbb{K}[x_{1},\dots,x_{n}]
is stored as a list
(m_{1},\dots,m_{r})
of generators, and each monomial is represented by its exponent vector in
\mathbb{N}^{n}
.
Inserting a new monomial amounts to appending it to this list, and therefore takes time
O(1)
, ignoring the possible maintenance of minimality.
Answering a membership query for a monomial
m
requires testing whether
m_{i}\mid m
for each generator
m_{i}
.
Assuming that comparing exponents is
O(1)
per variable, each divisibility test costs
O(n)
, so one membership query costs
O(rn)
, where
n
is the number of variables and
r
the number of generators.

With a different space–time tradeoff, we may represent a monomial ideal
I\subseteq\mathbb{K}[x_{1},\dotsc,x_{n}]
generated by monomials with partial degrees bounded by some
D\geq 0

by an
n
-dimensional array
A
of booleans such that
A[i_{1}]\dotsb[i_{n}]
is
true
if and only if
x_{1}^{i_{1}}\dotsb x_{n}^{i_{n}}
is in
I
for all
0\leq i_{k}\leq D
.
This representation uses
(D+1)^{n}
boolean entries and supports membership queries in time
O(n)
: given a monomial
m
with exponent vector
(i_{1},\dotsc,i_{n})
, we compute
j_{k}=\min(i_{k},D)
and read
A[j_{1}]\dotsb[j_{n}]
.
However, inserting a new generator can be costly: to preserve the ideal property one has to set to
true
the array entries corresponding to all multiples of this generator with exponents bounded by
D
, which costs
\Theta(D^{n})
in the worst case.
Moreover, the space consumption makes this naive representation impractical beyond small examples.

Contribution

We propose
monomial divisibility diagrams (MDD)
as a new data structure for representing monomial ideals.
An MDD for an ideal
I
is a compact encoding of the corresponding
n
-dimensional array
A
considered above as a directed acyclic graph.
If the partial degrees of the generators are bounded by
D
, membership in a monomial ideal can be decided in time
O(n\log D)
using an MDD, independently of the number of generators.
MDDs are cousins of
binary decision diagrams (BDD)
, a data structure used to represent boolean functions
\left\{0,1\right\}^{n}\to\left\{0,1\right\}

(
Knuth 2011
)
.
We implemented this data structure in
AlgebraicSolving.jl
and obtained significant speed-ups.

Previous work

Divisibility masks (
divmasks
) are compact bit patterns attached to generators which
allow many potential divisibility tests to be discarded cheaply
(e.g.
Roune & Stillman 2012
)
.
They are used, for example, in
AlgebraicSolving.jl
and
msolve

(
Berthomieu et al. 2021a
)
.
The masks need to be recomputed periodically as the ideal evolves.
Divmasks improve the practical speed of the naive algorithm for ideal membership, but the complexity is still linear in the number of generators.

Several tree data structures for monomial ideals have been proposed in order to speed up membership tests and related operations.

Milowski 2004
introduced
monomial trees
, which are prefix trees built on exponent vectors of generators.
These trees can accelerate membership tests when many monomials share similar exponent patterns, because parts of the tree can be skipped, but they may also degenerate, for example when exponents in the first variable are all distinct.

There have been different definitions of
Janet trees

(
Gerdt et al. 2001
;
Hashemi et al. 2022
)

for representing Janet bases of monomial ideals by prefix trees of exponent vectors, providing an efficient membership test
(
Gerdt et al. 2001
, Theorem 1)
.
The generalization of Janet trees to minimal Janet-like bases
(
Gerdt & Blinkov 2005
;
Hashemi et al. 2023
)
is essentially equivalent to our definition of ideal tree (Section
2.2
).
With respect to this line of work, our contribution is twofold:
first, a theoretical framework independent of the notion of involutive division;
second, a systematic use of maximal sharing, which makes the data structure usable in cases where a Janet basis would not even fit on a hard disk.

Gao & Zhu 2008
also use prefix trees of exponent vectors, with the purpose of computing irreducible decompositions of monomial ideals.
Their
MinMerge step
can be interpreted as an on-the-fly computation of a Janet-like basis.

Support trees, as implemented by
Malkin 2007
in
4ti2
, provide another tree representation.
At each node, the tree branches according to whether a given variable divides the monomial or not, and monomials are stored in the leaves.
This has proved efficient in the context of toric ideals, but the data structure degenerates
when the supports of the exponent vectors are too similar.

Lastly,
Roune & Stillman 2012
;
Roune & Stillman 2012a
propose the use of
kd-trees
for monomial ideals.
Their experiments show clear speed-ups over simple lists of generators and over monomial trees on a range of benchmarks.
However, kd-trees can become unbalanced after many insertions, so they must be rebuilt from time to time, and finding good splitting criteria adapted to a given distribution of monomials is not straightforward.

2.
Monomial ideals as trees

2.1.
Monomial ideals

A monomial ideal in
n
variables
is an ideal
I\subseteq\mathbb{Q}[x_{1},\dotsc,x_{n}]
generated by monomials.
It is well known that a polynomial
f
is in
I
if and only if every monomial in
f

is divided by one of the monomials generating
I

(
Cox et al. 2015
, §2.4)
.
In particular, a monomial ideal is entirely determined by the set of monomials contained in it.
Identifying a monomial
x_{1}^{\alpha_{1}}\dotsm x_{n}^{\alpha_{n}}
with its exponent vector
(\alpha_{n},\dotsc,\alpha_{1})\in\mathbb{N}^{n}
(listed from
x_{n}
down to
x_{1}
for later convenience),
we henceforth view a monomial ideal as a subset
I\subseteq\mathbb{N}^{n}
satisfying

I+\mathbb{N}^{n}=I
.
For
E\subseteq\mathbb{N}^{n}
we write
\langle E\rangle=E+\mathbb{N}^{n}
for the ideal generated by
E
.
By Dickson’s Lemma
(
Cox et al. 2015
, Theorem 2.5)
, every monomial ideal admits a finite generating set.

In
\mathbb{N}^{0}
there are exactly two monomial ideals, namely
\varnothing
and
\mathbb{N}^{0}
.
For
n>0
, we can describe the monomial ideals in
\mathbb{N}^{n}
in terms of monomial ideals in
\mathbb{N}^{n-1}
.
Let
I\subseteq\mathbb{N}^{n}
be a monomial ideal, and let
e\geq 0
.
We define the
e
th quotient ideal of
I
as

I/e=\left\{\alpha\in\mathbb{N}^{n-1}\ \middle|\ e\cdot\alpha\in I\right\},

where
e\cdot\alpha
denotes the concatenation
(e,\alpha_{1},\dotsc,\alpha_{n-1})
.
In terms of ideals in
\mathbb{Q}[x_{1},\dotsc,x_{n}]
,
the definition is equivalent to

I/e=\left(I:x_{n}^{e}\right)\cap\mathbb{Q}[x_{1},\dotsc,x_{n-1}].

We verify that

(1)

I=\bigcup_{e\geq 0}e\cdot(I/e)=\bigcup_{e\geq 0}(e+\mathbb{N})\cdot(I/e).

2.2.
Ideal trees

Given a set
\mathcal{T}
, let
\mathbb{N}\rightharpoonup\mathcal{T}
be the set of partial functions from
\mathbb{N}
to
\mathcal{T}
with finite domain.
The domain of a partial function
t
is denoted
\operatorname{dom}(t)
.

Definition 1.

Let
\bot
be a set that is not a partial function from
\mathbb{N}
to any other set.
The set
\mathcal{T}_{n}
of
n
-trees is defined recursively as

•

\mathcal{T}_{0}=\left\{\bot\right\}
,

•

\mathcal{T}_{n}=\left\{t:\mathbb{N}\rightharpoonup\mathcal{T}_{n-1}\ \middle|\ \operatorname{dom}(t)\neq\varnothing\right\}
, for
n>0
.

In other words, an
n
-tree is a finite tree,
in which all leaves lie at depth exactly
n
.
Moreover, the edges are labeled by natural integers.
There is a one-to-one correspondence between
n
-trees and nonempty finite subsets of
\mathbb{N}^{n}
by defining

\operatorname{set}(\bot)=\mathbb{N}^{0}
and

\operatorname{set}(t)=\bigcup_{e\in\operatorname{dom}(t)}e\cdot\operatorname{set}(t(e)).

Equivalently,
\operatorname{set}(t)
corresponds to the set of paths in
t
, from the root to a leaf.
This is the classical construction of
prefix trees
(for words of fixed length
n
). This yields an interesting data structure to represent finite subsets of
\mathbb{N}^{n}
.
In this section, we develop an analogue construction for monomial ideals.

To this end, we define the
ideal represented by an
n
-tree
t
as
the monomial ideal generated by
\operatorname{set}(t)
, namely

\operatorname{\mathbb{I}}(t)=\langle\operatorname{set}(t)\rangle
.
Equivalently, we have, for
n=0
,
\operatorname{\mathbb{I}}(\bot)=\mathbb{N}^{0}
, and, for
n>0
,

(2)

\operatorname{\mathbb{I}}(t)=\bigcup_{e\in\operatorname{dom}(t)}(e+\mathbb{N})\cdot\operatorname{\mathbb{I}}(t(e)).

Definition 2.

An
n
-tree is
ideal
if either
n=0
, or
n>0
and the following conditions hold:

•

for all
e\in\operatorname{dom}(t)
,
t(e)
is ideal;

•

for all
e,f\in\operatorname{dom}(t)
,

e<f\implies\operatorname{\mathbb{I}}(t(e))\subset\operatorname{\mathbb{I}}(t(f))
,
where
\subset
denotes strict inclusion.

\langle xyz,x^{2},xy^{2}\rangle

, the second to

\langle x^{2},xy^{2}\rangle

An ideal
n
-tree
t
provides an efficient data structure for deciding membership in
\operatorname{\mathbb{I}}(t)
.
Indeed, consider the case
n>0
and write
\alpha=e\cdot\alpha^{\prime}\in\mathbb{N}^{n}
.
By definition,
\alpha\in\operatorname{\mathbb{I}}(t)
if and only if
\alpha^{\prime}\in\operatorname{\mathbb{I}}(t(f))
for some
f\in\operatorname{dom}(t)
with
f\leq e
.
For a general
n
-tree this would require checking all such
f
.
When
t
is ideal, the ideals
\operatorname{\mathbb{I}}(t(f))
form a strictly increasing chain, so it suffices to test

\alpha^{\prime}\in\operatorname{\mathbb{I}}\bigl(t(f)\bigr)
for the largest
f
not exceeding
e
.
This leads to the procedure
contains
(Algorithm
1
).
The following lemma summarises the argument.

Lemma 3.

Let
n>0
and let
t
be an ideal
n
-tree.
For any
e\geq 0
:

(i)

If
e<\min(\operatorname{dom}(t))
, then
\operatorname{\mathbb{I}}(t)/e=\varnothing
.

(ii)

Otherwise,

\operatorname{\mathbb{I}}(t)/e=\operatorname{\mathbb{I}}\bigl(t(f)\bigr)
,
where
f
is the largest element of
\operatorname{dom}(t)
which does not exceed
e
.

Proof.

Equation (
2
) implies

\operatorname{\mathbb{I}}(t)/e=\bigcup_{f\in\operatorname{dom}(t),\ f\leq e}\operatorname{\mathbb{I}}(t(f)).

If
e<\min(\operatorname{dom}(t))
, then the union is empty
and the first point follows.
Otherwise, the defining property of ideal trees shows that
the union is contained in the term
\operatorname{\mathbb{I}}(t(f))
corresponding to the largest such
f
, which yields the second point.
∎

In the same way as there is a unique
n
-tree representing a given nonempty subset of
\mathbb{N}^{n}
,
there is a unique ideal
n
-tree representing a given nonempty ideal of
\mathbb{N}^{n}
.

Theorem 4.

The map
t\in\mathcal{T}_{n}\mapsto\operatorname{\mathbb{I}}(t)\subseteq\mathbb{N}^{n}
induces a bijection between
ideal
n
-trees and nonempty monomial ideals in
\mathbb{N}^{n}
.

Proof.

We argue by induction on
n
. For
n=0
, the claim is immediate because there is exactly one ideal
0
-tree, namely
\bot
, and exactly one nonempty ideal in
\mathbb{N}^{0}
, namely
\mathbb{N}^{0}
.

Assume
n>0
and let
I\subseteq\mathbb{N}^{n}
be a nonempty monomial ideal.
By the ascending chain condition the sequence

I/0\subseteq I/1\subseteq I/2\subseteq\dotsb

eventually stabilises.
Since
I
is nonempty, the stabilised value is nonempty as well.
Choose indices
0\leq f_{1}<\dotsb<f_{r}
(and put
f_{r+1}=\infty
) such that

(i)

I/e=\varnothing
for all
0\leq e<f_{1}
,

(ii)

I/e=I/{f_{i}}
whenever
f_{i}\leq e<f_{i+1}
, and

(iii)

I/{f_{i}}\neq I/{f_{i+1}}
for all
0\leq i<r
.

By the induction hypothesis, each
I/{f_{i}}
is represented by a unique ideal
(n-1)
-tree. Define
t
by
\operatorname{dom}(t)=\{f_{1},\dotsc,f_{r}\}
and
t(f_{i})
is the ideal tree representing
I/f_{i}
.
The strict inclusions among the
I/{f_{i}}
, by
(iii)
, ensure that
t
is an ideal
n
-tree.
Lemma
3
yields
\operatorname{\mathbb{I}}(t)/e=I/e
for every
e\geq 0
, hence
\operatorname{\mathbb{I}}(t)=I
, by (
1
). This proves surjectivity.

For injectivity, let
s
be another ideal
n
-tree with
I=\operatorname{\mathbb{I}}(s)=\operatorname{\mathbb{I}}(t)
. Suppose there exists
e\in\operatorname{dom}(s)\setminus\operatorname{dom}(t)
and choose such an
e
minimal. If
e<f_{1}
, then
\operatorname{\mathbb{I}}(s)/e=\varnothing
, by
(i)
, contradicting
\operatorname{\mathbb{I}}(s(e))\neq\varnothing
. Otherwise
f_{i}<e<f_{i+1}
for a unique

. Minimality of
e
implies
f_{i}\in\operatorname{dom}(s)
.
Lemma
3
and
(ii)
give

\operatorname{\mathbb{I}}(s(e))=I/e=I/f_{i}=\operatorname{\mathbb{I}}(s(f_{i}))
.
This contradicts the strict monotonicity of
s
. Hence
\operatorname{dom}(s)\subseteq\operatorname{dom}(t)
, and the reverse inclusion follows from similar arguments.

Lemma
3
gives
\operatorname{\mathbb{I}}(s(e))=\operatorname{\mathbb{I}}(t(e))
for every
e\in\operatorname{dom}(t)=\operatorname{dom}(s)
. The induction hypothesis then yields
s(e)=t(e)
, so
s=t
.
∎

Direct implementations of ideal trees may face a crushing growth in the number of nodes,
hindering the use of the data structure for practical purposes.
In many cases this growth is only apparent, because the same subtrees occur repeatedly in the ideal tree.
By sharing those common subtrees we obtain a representation of the tree as a directed acyclic graph.
We define a
monomial divisibility diagram (MDD)
as the directed acyclic graph obtained from an ideal tree by maximally sharing its common subtrees. Figure
3
illustrates an ideal tree and Figure
4
displays the corresponding MDD. Figure
6
illustrates another MDD.
Mathematically speaking, ideal trees and MDDs encode the same information, but the compactness of MDDs makes them suitable for practical applications.

3.1.
Formal definition

Let
I\subseteq\mathbb{N}^{n}
be a nonempty monomial ideal
and let
t
be its ideal tree.
Let
S
be the set of subtrees of
t
: it is the smallest subset of
\mathcal{T}_{0}\cup\dotsb\cup\mathcal{T}_{n}

which contains
t
and contains all the children of all its elements.
The
monomial divisibility diagram
of
I
is the directed acyclic graph with vertex set
S
,
with an edge
(t,t(e))
labelled
e
for any
t\in S
and
e\in\operatorname{dom}(t)
.

The algorithms for insertion and membership are the same as for ideal trees (Algorithms
1
and
2
)
but they can be implemented more efficiently using memoization. The critical part is to maintain the maximal sharing property: whenever two subtrees are equal, they must be represented by the same vertex of the MDD.

3.2.
Algorithms and implementation

We now discuss a basic Python implementation,
using actual code rather than pseudo-code on purpose, to be precise and concrete about data representation
and implementation of maximal sharing through hash consing.

To create MDDs efficiently, it is important to decide the structural equality of two nodes in constant time.
A well-known technique is
hash consing

(e.g.
Goto 1974
;
Filliâtre & Conchon 2006
)
: we maintain the invariant that
two nodes are structurally equal if and only if they are physically equal
(maximal sharing).
For this purpose, we maintain a hash table
_universe
that maps tuples of edges to nodes.
When creating a new node from a tuple of edges, we check whether this tuple is already present in
_universe
; if so, we return the existing node instead of allocating a new one.
To ensure that unused nodes are reclaimed by the garbage collector, we store weak references in this dictionary.
We therefore redefine the
__new__

{pythoncode}

Hash consing not only minimizes memory usage; it can also lead to
faster
computation through memoization.
For example, to compute the size of the ideal tree corresponding to an MDD we use the following procedure. Its complexity is linear in the size of the MDD because the table lookup relies on
Node.__eq__

{pythoncode}

memo[t] = size
return size

The same principle applies when implementing the insertion of a monomial in an MDD (Algorithm

3.3.
Complexity

To study the complexity of operations on MDDs, we consider the following size parameters.
Given the MDD of an ideal
I\subseteq\mathbb{N}^{n}
,
its
size
is the number of edges;
its
width
is the maximum number of nodes at a given depth;
and its
branching degree
is the maximum outdegree of a node.
For example, the size of the MDD in Figure
4
is 52, its width is 6, and its branching degree is 6.

Let
I\subseteq\mathbb{N}^{n}
be a nonempty ideal, represented by its MDD of size
N
, width
w
, and branching degree
\delta
.
We easily check that
N\leq n\delta w
,
w\leq\delta^{n-1}
, and
\delta\leq e+1
for any
e
such that
I
is generated by monomials with exponents at most
e
.

Proposition 1.

The cost of testing membership of some
\alpha\in\mathbb{N}^{n}
in
I
is

O(n\log\delta)
.

Proof.

There are at most
n
recursive calls, and each call performs a binary search on an array with at most
\delta
elements.
∎

It is easy to adapt the representation of nodes to obtain an
O(n)
membership test:
instead of storing a sparse array, we may use a dense array. For example, a node
corresponding to an ideal tree
t
with
\operatorname{dom}(t)=\{2,3,6\}
is represented by an array of pairs
such as
\left[(2,t(2)),(3,t(3)),(6,t(6))\right]
,
but we could use instead an array of subtrees, such as

\left[\varnothing,\varnothing,t(2),t(3),t(3),t(3),t(6)\right]
.
However, the memory overhead of the dense representation may be large, so we advocate for the first data structure.

Proposition 2.

The cost of computing
I+\langle\alpha\rangle
, as an MDD,
is
O(N)
.
Moreover,
\operatorname{width}(I+\langle\alpha\rangle)\leq 2\operatorname{width}(I)+1
.

Proof.

The algorithm
insert
(implemented with memoization as in Section
3.2
)
visits every node at most once, and the work at a node is bounded by the number of outgoing edges (including the deduplication in
Node.__new__
).
So the total work is bounded by the total number of edges.

As for the width, we check that every subtree at depth
k
of the ideal tree of
I+\langle\alpha\rangle

is one of the following: a subtree at depth
k
of the ideal tree of
I
;

\textnormal{{insert}}(t,\alpha_{k+1}\dotsb\alpha_{n})
, where
t
is a subtree at depth
k
of
I
;
or
\textnormal{{singleton}}(\alpha_{k+1}\dotsb\alpha_{n})
.
∎

As a direct corollary, we obtain an exponential bound on the width in terms of the number of generators.

Corollary 3.

If
I
is generated by
r
monomials, then
w\leq 2^{r}-1
.

3.4.
Experimental data on the size of MDDs

Figure 5.
Size of the ideal tree and of the MDD across benchmark families.
Each pair of points corresponds to a monomial ideal. The abscissa of a point is the size of the list of generators, in machine words, that is, the number of generators times the number of variables.
The ordinate of the lower point of a pair is the size, in machine words, of the MDD in sequential form, that is, twice the number of edges plus the number of nodes.
The ordinate of the upper point is the size of the ideal tree in the same sequential form.
The shaded area indicates where the ordinate is smaller than the abscissa.

The exponential size bound of Corollary
3

may seem alarming. Fortunately, this bound is pessimistic in many cases, for two reasons.
First, it does not take sharing into account.
It is difficult to quantify
a priori
the benefit of sharing, but in practice the reduction in size is by several orders of magnitude.
Second, the monomial ideals in which we are interested tend to have more structure than random ideals.
As an extreme example, consider the monomial ideal
I_{n,d}\subseteq\mathbb{N}^{n}

generated by all monomials of total degree
d
.
This ideal is minimally generated by
\binom{d+n-1}{n-1}
monomials,
but the width of its MDD is only
d+1
. In this case, the MDD is exponentially more compact than the generator list.

For a practical experiment, we consider five benchmark families of monomial ideals, of which the first four come from the dataset compiled by
Roune 2009
:

random, large degree.:

Monomial ideals in 10 variables generated by 40 to 200 random monomials; exponents are uniformly distributed in
\left\{0,\dotsc,30\,000\right\}
.

random, small degree.:

Monomial ideals in 10 variables generated by 100 to 1 000 random monomials; exponents are uniformly distributed in
\left\{0,\dotsc,10\right\}
.

random, squarefree.:

Monomial ideals in 20 variables generated by 100 to 10 000 random monomials; exponents are uniformly distributed in
\left\{0,1\right\}
.

random, many generators.:

Monomial ideals in 10 variables generated by 1000 to 290 000 random uniformly distributed monomials of total degree exactly 12.

special.:

A collection coming from various problems
(
Roune 2009
, §7.1)
.

GB.:

Ideals generated by leading monomials of grevlex Gröbner bases for the systems Katsura-11, -12, -13, and Eco-14, -15.

Figure
5
plots the size of the MDD of each of the monomial ideals in the dataset as a function of the size of the list of generators.
To appreciate the benefit of maximal sharing, the figure also represents the size of the corresponding ideal tree.
Size is measured in terms of an idealized memory footprint.
Since the actual memory usage of a MDD depends on many implementation-dependent factors,
we associate to each data structure a sequential representation as a flat list of machine words.
For the list of generators, this is the concatenation of all exponent vectors.
For MDDs, we concatenate the representations of the distinct subtrees, where a subtree
t
with domain
\left\{a_{1},\dotsc,a_{r}\right\}
is encoded as the sequence
r,a_{1},p_{1},\dotsc,a_{r},p_{r}
, where
p_{i}
is the index of the node corresponding to
t(a_{i})
in this list.
Thus each node of the MDD contributes one word and each edge two words. The tree size is measured similarly.

We draw several conclusions from this experiment.
First, maximal sharing is what makes the data structure usable: it reduces the tree size by at least an order of magnitude. In some instances, the tree size exceeds a terabyte.

Second, in many cases there is a blowup in the size of the MDD compared to the size of the generator list.
In these cases, the MDD may not be suitable for membership testing, but it may still be useful for other computations in commutative algebra, such as Hilbert series or irreducible components.

Last, there are also many instances of the opposite behaviour, where the MDD is more compact than the generator list.
Most importantly, this is the case for monomial ideals coming from Gröbner bases.
This is related to the weakly-grevlex
(
Moreno-Socías 2003
)
or Borel-fixed structure
(
Green 1998
)
that these monomial ideals often exhibit,
exemplified by the ideal
I_{n,d}
discussed above.
The phenomenon will be investigated in future work from a theoretical point of view.

4.
Application to Signature Gröbner Bases

4.1.
Theory

We now present an application of MDDs to the computation of signature Gröbner
bases (sGB). Signature Gröbner bases have their origin in the
F
5
algorithm
Faugère 2002
and aim to avoid so-called
reductions to zero in Buchberger’s algorithm which do not
contribute to the output but still take time to compute. These reductions
to zero are avoided by introducing additional monomial ideal membership
tests which our data structure is designed to do more optimally.

To illustrate how we apply MDDs in sGB computations we
present here a simplified and specific version of an sGB
algorithm. For the theory of sGB and algorithms to compute them in
full generality we refer to
Eder & Faugère 2017
and

Lairez 2024
. We also do not recall the
basic theory of Gröbner bases, or algorithms to compute them, and
refer the reader to e.g.
Cox et al. 2015
for details.

Let
\mathbb{K}
be a field, let
R:=\mathbb{K}[x_{1},\dots,x_{n}]
be a
polynomial ring over
\mathbb{K}
and let
\prec
be a monomial order on
the set of
n
-variate monomials. For
f\in R
nonzero,
\operatorname{lm}(f)
denote the
largest monomial occurring in the support of
f
with respect to the
monomial order
\prec
, and, for
S\subset R
,

\operatorname{lm}(S)
denotes
\left\{\operatorname{lm}(p)\;\middle|\;p\in S\right\}
.
As in the rest of the paper, we identify the set of monomials in
R
with
\mathbb{N}^{n}
.
Finally, for a set
S\subset R
and a polynomial
p\in R
, write

\operatorname{crit}(S,p):=\left\{\frac{\operatorname{lcm}(\operatorname{lm}(p),\operatorname{lm}(s))}{\operatorname{lm}(p)}\;\middle|\;s\in S\right\}.

The key component of any Gröbner basis computation is the
reduction
process, which works as follows (see

(
Cox et al. 2015
, §2.3)
for further details): Given a
finite set
S\subset R
and a polynomial
p\in R
, let
t
be a term in

p
such that there is
s\in S
and a term
u
with

t=u\cdot\operatorname{lm}(s)
. We replace
p
by
p-us
and repeat this
process, looking for further terms in the result that are divisible by
an element in
\operatorname{lm}(S)
, until no term in the resulting polynomial lies
in the monomial ideal generated by
\operatorname{lm}(S)
. During this reduction
process we can use an MDD representing
\langle\operatorname{lm}(S)\rangle
to check whether
there exists an element
s\in S
whose leading term divides
t
and,
only if the answer is yes, look for the actual element
s
using a
linear search. In practice, this can save many iterations
over
S
.

We now come to applying MDDs specifically to sGB computations:
Suppose that we are given a Gröbner basis

G\subset\mathbb{K}[x_{1},\dots,x_{n}]
with respect to
\prec
as well as a
polynomial
f\in\mathbb{K}[x_{1},\dots,x_{n}]
. In its simplest form, the

F
5
algorithm aims to compute a Gröbner basis for the ideal
generated by
G
and
f
. Note that we can then compute a Gröbner
basis for a polynomial ideal generated by
f_{1},\dots,f_{r}\in R
by an
iterative process, where we start with
G:=\{f_{1}\}
and
f:=f_{2}

to compute a Gröbner basis of
\langle f_{1},f_{2}\rangle
and then enlarge this
Gröbner basis to a Gröbner basis of
\langle f_{1},f_{2},f_{3}\rangle
and so on, until
all elements
f_{1},\dots,f_{r}
have been processed.

We now give a (too optimistic) optimization of Buchberger’s algorithm for computing
a Gröbner basis for
\langle G,f\rangle
:

(1)

Initialize
P:=\{(\mathbf{0},f)\}\subset\mathbb{N}^{n}\times R
and

G_{\text{new}}:=G
. Here
\mathbf{0}\in\mathbb{N}^{n}
is the all zeros
vector, to be understood as the monomial
1\in R
.

(2)

While
P
is not empty:

(a)

Choose some tuple
(u,p)\in P
, remove it from

P
, and reduce
up
by
G_{\text{new}}
to obtain a polynomial
q
.

(b)

If
q\neq 0
, add to
P
the elements
(v,q)
where

v\in\operatorname{crit}(G_{\text{new}},q)
, add
q
to
G_{\text{new}}
, and go
to step
2
.

Step
2b
does not construct the S-pairs explicitly; this is performed implicitly in step
2a
.
However, this is flawed because when we reduce
up
, the polynomial
p
is already in
G_{\text{new}}
, so
up
reduces trivially to 0.
Signatures are introduced into the process to fix the issue.

To obtain an sGB algorithm from the loop above we make the following
three modifications: First, we associate a
signature
to every element of
G_{\text{new}}
.
This is a monomial computed inductively as follows:

•

the polynomial
f
itself gets the signature
\mathbf{0}
;

•

a polynomial
q
obtained in step
2a
by reducing some
up
gets the signature
\mathfrak{s}(q)=u\mathfrak{s}(p)
.

The second modification affects the reduction process in step

2a
: When reducing an element
up
we allow only
monomial multiples of elements in
G
as reducers as well as elements

vq
where
q\in G_{\text{new}}\setminus G
,
v\in\mathbb{N}^{n}
and

v\mathfrak{s}(q)\prec u\mathfrak{s}(p)
. When making these restrictions in step
2a
,
we say that we are
regularly reducing

(u,p)

by
G_{\text{new}}
.

The third and final modification is that in step
2a
we
always choose a tuple
(u,p)\in P
such that
u\mathfrak{s}(p)
is minimal.

The key algorithmic benefit of the introduction of signatures now lies
in the following lemma:

Lemma 1 (Lemmas 4.2 and 6.1 in
Eder & Faugère 2017
).

With the three outlined modifications, any two elements

(u,p),(v,q)\in P
with
u\mathfrak{s}(p)=v\mathfrak{s}(p)
regularly reduce to
the same polynomial by
G_{\text{new}}
. Moreover, an
element
(u,p)\in P
regularly reduces to zero by
G_{\text{new}}
if one
of the following two statements holds:

(1)

An element
(v,q)
that was previously in
P
regularly reduced
to zero by
G_{\text{new}}
and
v\mathfrak{s}(q)
divides
u\mathfrak{s}(p)
.

(2)

We have
u\mathfrak{s}(p)\in\langle\operatorname{lm}(G)\rangle
.

The two criteria in Lemma
1
are called the
syzygy

and
Koszul
criteria in the literature and involve performing a
monomial membership test. Applying them during the run of a
signature-based Gröbner basis algorithm is where MDDs can
be utilized. We refer to Algorithm
3
for a precise
description of an algorithm using these criteria together with MDDs.

An sGB algorithm, such as Algorithm
3
, has two
parts: a purely
symbolic
part (divisibility tests on
signatures, finding reducers, computation of
S
-pairs, etc.) and an

arithmetic
part (the arithmetic operations involved in reducing
polynomials). The use of MDDs affects only the symbolic part.

Table
1
reports on the impact of MDDs on the
total
computation time,
as well as the symbolic part of the computation time.
In most examples, the total computation time is significantly reduced by using MDDs,
with the exception of
noon9
, which operates on monomial ideals with very few generators.
With MDDs, the time spent in membership tests, including the overhead for creating MDDs, is negligible compared to the symbolic part of the computation time. In this sense, MDDs completely solve the problem of fast membership tests in Gröbner basis computations.

Table
1
also highlights the prominence of the symbolic part of the sGB algorithm in
AlgebraicSolving.jl
, with many examples where it dominates the total time, and no example below 50% (without MDDs).
With MDDs, membership testing ceases to be a bottleneck, but it is only a fraction of the symbolic workload.
We expect further gains by designing similar data structures for the remaining
symbolic operations.
