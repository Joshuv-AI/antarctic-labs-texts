EasyARC: Evaluating Vision Language Models on True Visual Reasoning
Mert Unsal, Aylin Akkus

Abstract
Building on recent advances in language-based reasoning models, we explore multimodal reasoning that integrates vision and text. Existing multimodal benchmarks primarily test visual extraction combined with text-based reasoning, lacking true visual reasoning with more complex interactions between vision and language. Inspired by the ARC challenge, we introduce EasyARC, a vision-language benchmark requiring multi-image, multi-step reasoning, and self-correction. EasyARC is procedurally generated, fully verifiable, and scalable, making it ideal for reinforcement learning (RL) pipelines. The generators incorporate progressive difficulty levels, enabling structured evaluation across task types and complexities. We benchmark state-of-the-art vision-language models and analyze their failure modes. We argue that EasyARC sets a new standard for evaluating true reasoning and test-time scaling capabilities in vision-language models. We open-source our benchmark dataset and evaluation code.

A long-standing goal of artificial intelligence research

Previous work has created Visual Question Answering (VQA) benchmarks where the model is asked (open-ended) questions about understanding a real world scene generated synthetically or created from real-world data

2
EasyARC Dataset

2.1
Original ARC Challenge

The ARC challenge introduced by
Chollet 2019
is designed as a benchmark for abstract reasoning robust to memorization. It resembles Raven’s Progressive Matrices where a matrix of figures are provided and the test taker has to fill in the last missing figure. However, in the
ARC setting
we instead have a number of examples consisting of input and output grids which entail a hidden transformation rule between them. In order to demonstrate that the correct transformation rule was found, the test taker then gets one or multiple test input grids and constructs the output grid which is held against a ground truth.

Figure 2
:
Example ARC task from the public evaluation set: Visually, this task is simple as it resembles stacking rectangles in a three-dimensional manner.

ARC originally consists of 400 training and 400 evaluation examples. Common approaches to ARC include (LLM-guided) program synthesis and transductive reasoning with additional test-time-training
Li et al. 2024

Akyürek et al. 2024

Li and Ellis 2024
. In both cases training examples and test input grids are usually provided directly in the form of language.
Li et al. 2024
demonstrate that these two modes of reasoning are complementary for solving the ARC challenge.

Motivated by this, we investigate whether visual reasoning can complement existing approaches to solving ARC problems.
This motivation stems from the observation that humans primarily rely on vision to solve ARC problems. Some patterns become evident in the visual domain but could appear convoluted when described through lengthy natural language representations of the grid.

2.2
EasyARC

We initially evaluated VLMs on ARC, expecting them to generalize. However, even state-of-the-art models — both open and closed-source — scored near 0% when given only images. This failure reveals a fundamental limitation: VLMs struggle with spatial reasoning and grid-based transformations.

In order to facilitate a more meaningful evaluation, we developed EasyARC with tasks that are similar to the original ARC challenge in spirit yet require much simpler spatial/visual understanding. Since ARC challenge has very small training dataset, non-vision approaches to ARC often rely on synthetic data generation
Hodel 2024
;
Li et al. 2024
;
Akyürek et al. 2024
. Specifically,
Li et al. 2024
categorized the 400 original training examples into 160 seed tasks, each annotated with human-written Python code for generating examples, a natural language description, and conceptual tags. Taking inspiration from this approach, we designed generators that create tasks in three difficulty levels: easy, medium, and hard. Higher levels typically require a superset of skills from previous levels. Due to the combinatorial possibilities of grid sizes, color permutations, shape positions, axes, and other factors, each individual task generates a multitude of examples.

For initial evaluation, we selected five problem classes that cover a diverse set of concepts:

•

Cross, Star:
Introduces the model to basic geometric shapes on grids (e.g., rows, columns, diagonals) and their respective anchor points.

•

Counting Cells:
Requires identifying and counting individual cells or contiguous shapes on a uniform background.

•

Double Grid:
Involves copying a pattern while applying a horizontal flip or a color flip.

•

Dominant Side:
Requires understanding sections of the image (e.g., left or upper side). The transformation colors the entire image in the dominant side’s color while filtering out or preserving distracting noise pixels.

•

Drop One Color:
Involves transforming one color into another while preserving a third unaffected color. The goal is to determine which color mappings apply.

We generate 1000 and 100 random samples for train and test splits from each category, respectively. For all tasks, we sample from the easy, medium, and hard categories with probabilities 0.5, 0.35, and 0.15 and sample number of rows and columns uniformly random between 3 and 10 unless there is a specific requirement for a task. This results in a diverse dataset of 5000 train and 500 test examples. We describe detailed task descriptions in the
Appendix
with images included.

2.3
Benchmark for Test-Time Scaling of VLMs

EasyARC serves as an ideal test-bed for test-time scaling in vision models. In particular, EasyARC is:

1.

True Reasoning Benchmark:
EasyARC tasks require multi-step reasoning, including hypothesis formation (e.g., ”Predict minority cell color”), iterative validation (e.g., ”But example 2 has a 1x2 blue grid instead of a single color”), hypothesis refinement, and alternative perspective-taking.

2.

Synthetic and Easily Expandable:
EasyARC allows flexible dataset creation via configurable parameters such as grid sizes and difficulty probabilities. Our dataset includes 5000 training and 500 evaluation tasks, which we will release alongside the generators. Additionally new generators can be seamlessly integrated.

3.

Verifiable:
Since the task requires an exact output grid prediction, evaluation is straightforward. This avoids reliance on proxies such as open-ended VQA, where complex multi-step reasoning tasks often sacrifice verifiability.

4.

Gradual Difficulty Levels:
We can adjust task difficulty progressively to provide a structured learning signal in an RL pipeline, allowing for insights into training dynamics.

5.

Multi-Image Reasoning:
Each example consists of multiple input-output image pairs. The model must correctly associate pairs, attend to their transformations, describe them, and generalize accordingly.

These characteristics make EasyARC particularly well-suited for reinforcement learning (RL) pipelines where the base problem dataset’s difficulty distribution is of utmost importance.

Evaluation of SoTA VLMs

In this section, we present our findings on the performance of SoTA VLMs on our EasyARC benchmark. We evaluate closed-source models such as Claude 3.7 Sonnet and GPT4o-mini as well as small and large open source models such as QVQ-72B-Preview, Qwen2.5-VL-7B-Instruct, and Gemma3-27B-Instruct. We pass a stacked image of input output grids as well as a text prompt describing the task to all models. We use a low temperature of 0.5 and collect 1 sample from each model due to budget constraints.

3.1
Failure Modes

To better understand the challenges faced by VLMs on EasyARC, we manually analyze their outputs.

3.2
What Can Claude See?

Claude 3.7 Sonnet is the only model that demonstrates a degree of true visual reasoning. To analyze its limitations, we break down its success rate by problem category.

Figure 4
:
Claude 3.7 success rate across problem types.

To interpret this plot meaningfully, recall that each category contains problems sampled with probabilities 0.5, 0.35, and 0.15 from the easy, medium, and hard levels, respectively. We observe that the model struggles the most with Counting Cells, which requires precisely counting connected components of a specific color. In contrast, it performs significantly better on Drop One Color, where it simply identifies a missing color, and Dominant Side, where it determines which side of the image dictates the output color.

These results suggest that the model perceives a “blurry” representation of images—capturing high-level features while missing fine-grained details. Notably, most of its successes come from easy tasks; as soon as noise is introduced or the mapping becomes more complex, its performance deteriorates. This highlights a fundamental limitation in its ability to generalize beyond simple pattern recognition.

3.3
Task Analysis: Counting Cells

Below, we include an example of an example input output for the Counting Cells task, where the model needs to simply find the largest connected component for the minority color and count the number of cells in this component. All models, including the most successful Claude 3.7 Sonnet, failed at understanding this transformation.

Figure 5
:
Example Input-Output for Counting Cells Task

The model usually identifies that the output should be of minority color, which allows it to solve the easy version of this task. However, the model is unable to look at the image ”longer” to realize that it should find and count the largest connected component.
This failure suggests that test-time compute on images may be necessary, as models rely solely on the training examples to infer transformation rules rather than processing the image step-by-step.

3.4
Task Analysis: Cross/Star

While many tested models successfully solved the Cross/Star task, we identified two notable failure modes.

The first failure mode is related to the model’s inability to precisely locate objects such as cells, rows, columns, and diagonals. Specifically, the model often fails to recognize that the highlighted cell serves as the anchor point for the transformation. This limitation appears to stem from two potential bottlenecks: On the one hand, the vision component may struggle to establish a direct correspondence between the cell’s position in the input and the placement of the resulting row in the output. On the other hand, if the model was capable of extracting precise positional information per grid in natural language (instead of comparing them directly visually), it could potentially mitigate this issue; however, our findings suggest that it lacks this capability as well.

The second failure mode concerns the generation of diagonal structures. Even when the model correctly identifies the transformation rule and the orientation of the diagonal (e.g., upper-right direction), it frequently fails to fully extend the diagonal. In many cases, the model only completes the upper half of the diagonal after the anchor point while neglecting the preceding portion. Additionally, some models generate the diagonal in an incorrect position, despite correctly articulating that it should be anchored at the given input cell. These findings suggest that the model struggles with effectively integrating information across modalities—specifically, transferring spatial knowledge from the visual input to linguistic reasoning and subsequently applying it correctly in the output grid.

3.5
Analysis of QVQ-72B-Preview Reasoning Model

QVQ-72B-Preview is the only reasoning model that was trained with reinforcement learning to solve problems in our benchmark, in a similar fashion to o-series models by OpenAI. When we look at the outputs of the model, we realize that model has a clear mode of reasoning: even though the model is supposed to do visual reasoning, it follows:

1.

Extract the input output images into text.

2.

Do text based reasoning to solve the problem.

Although correctly extracting the images is necessary to solve the task, we also expect the model to mix the vision and language understanding rather than using the image only for extraction purposes. We speculate that this is an artifact of the model being trained on datasets such as Geometry3k
Lu et al. 2021
where it is sufficient to extract and solve the problem to get the reward. On the contrary, EasyARC presents a benchmark where the VLM has to interact with the image and do some true visual reasoning rather than mere extraction.

4
Conclusion

We introduced EasyARC, the first benchmark designed to evaluate true visual reasoning in vision-language models. Unlike existing benchmarks that focus on visual extraction, EasyARC requires multi-step reasoning, hypothesis formation, and iterative validation. Our results show that state-of-the-art VLMs struggle with even simple EasyARC tasks, highlighting fundamental gaps in visual cognition. With its scalable data generation and structured difficulty levels, EasyARC provides a valuable testbed for studying test-time scaling and reinforcement learning strategies in visual reasoning. We release our dataset and evaluation code to foster further research in this direction.

Appendix A: Details of the tasks

5.1
Cross/Star

The
Cross/Star
task involves generating structured patterns based on highlighted cells. The complexity increases as follows:

•

Easy:
Given a uniform background with a single distinct cell, the model must generate a row, column, or diagonal anchored at that cell.

•

Medium:
The model must create a more complex shape, such as a cross (combining a row and column) or both diagonals intersecting at the given cell.

•

Hard:
Two distinct cells, each in different colors, are provided. The model must replicate the medium-level shapes while following a more intricate coloring scheme.

Key Concepts:
Geometric structures (rows, columns, diagonals), pattern formation, and color-based rules.

5.2
Counting Cells

This task focuses on counting and identifying spatial properties of highlighted regions.

•

Easy:
Given a uniform background and
n
distinct-colored cells, the model must count these cells and output a
1\times n
grid of the same color.

•

Medium:
The grid contains clusters of connected components, and the model must output the number of cells in the largest such cluster.

•

Hard:
The background becomes striped, making it harder to distinguish and count the target clusters.

Key Concepts:
Object counting, recognizing clusters, handling background distractions.

5.3
Double Grid

This task requires duplicating a grid while introducing transformations.

•

Easy:
Given a grid with a background color and a pattern (dot or stripe), the model must duplicate the grid either horizontally or vertically.

•

Medium:
The duplication is accompanied by a transformation, such as a 180-degree rotation or a color flip.

•

Hard:
A randomly generated
3\times 3
grid must be replicated a variable number of times both horizontally and vertically, with transformations such as 90-degree rotations or background color flips.

Key Concepts:
Duplication, transformation, rotation, color manipulation.

5.4
Dominant Side

This task involves detecting and analyzing the dominant portion of a grid.

•

Easy:
A grid is divided into two sides (e.g., left/right, top/bottom). One side (across examples) dictates the output grid’s color.

•

Medium:
A uniform noise is introduced, requiring the model to distinguish the dominant side despite distractions.

•

Hard:
The noise becomes more complex, containing multiple colors, while the model must still correctly identify the dominant region.

Key Concepts:
Spatial division, handling noise.

5.5
Drop One Color

This task focuses on recognizing color transformation rules.

•

Easy:
Three colors are chosen, with one always transforming into another while remaining consistent across examples.

•

Medium:
Two colors are fixed, with one transforming into the other, while a third color varies across examples.

•

Hard:
One color transforms into the background, with the background itself varying but making up at least 70% of the grid.

Key Concepts:
Color mapping, background detection, transformation rules.

6.1
Prompt

We use the following prompt for evaluating VLMs.

Here is an image of multiple input-output grids. The cells of the grids can be of color black, blue, red, green, yellow, grey, pink, orange, teal, maroon. Your goal is to find the common rule that maps the input grid to the output grid. Make sure that you find an unambiguous transformation rule.

Below is a test input grid. After you find the transformation rule, apply it rigorously step by step to the test input grid to find the output grid. Put the final grid in
‘‘‘
in the same format as the input grid, where rows are separated by newline and columns are separated by column.
{test_input}

The image contains a variable number of input-output demonstrations. To ensure a unique solution, some tasks include more examples than others, which can be flexibly adjusted in the generator functions. To guarantee sufficient resolution for recognizing relevant details, the image resolution was set appropriately. The model was also able to read small annotations such as grid shapes and labels like ”Input” and ”Output”, indicating that it had access to a detailed visual representation sufficient for solving the task.
