Redundant Array Computation Elimination
Zixuan Wang, Liang Yuan, Xianmeng Jiang, Kun Li, Junmin Xiao, Yunquan Zhang

Abstract
. Redundancy elimination is a key optimization direction, and loop nests are the main optimization target in modern compilers. Previous work on redundancy elimination of array computations in loop nests lacks universality. These approaches either focus on specific computation patterns or fail to recognize redundancies with complex structures. This paper proposes RACE (Redundant Array Computation Elimination), a more general redundancy elimination technique. RACE utilizes a novel two-level scheme to identify the data reuse between array references and the computation redundancies between expressions. It traverses the expression trees in loop nests to detect redundancies hierarchically in linear time and generates efficient code with optimized auxiliary arrays that store redundant computation results. Furthermore, RACE supports the expression reassociation with various aggressive strategies to improve the redundancy opportunities. Experimental results demonstrate the effectiveness of RACE.



1.
Introduction

Redundancy elimination is one of the key optimizations in modern compilers
(
Aho, Alfred V. et al. 2007
;
Kennedy and Allen 2001
)
. Generally, redundancies fall into two types, unnecessary data movement and redundant computation. The first type includes peephole optimization, copy propagation, and dead-store elimination. The second type contains lazy code motion, dead code elimination, constant folding, common subexpression elimination, value numbering
(
Cocke 1970
;
Knoop et al. 2004
;
Knoop et al. 1994
;
Morel and Renvoise 1979
;
Cocke 1969
;
Su et al. 2019
)
. Most techniques in both types target scalar variables and employ the data-flow analysis.

The loop nest transformation is another critical branch of optimizations. It reschedules the computation in the iteration space of the loop nest, such as loop fusion, loop skewing, loop unrolling, vectorizing, and loop tiling
(
Division et al. 1971
;
Abu-Sufah et al. 1981
;
Wolfe 1978
)
. The primary purpose of these transformations is to improve the data locality and/or expose loop parallelism. In addition, there are several techniques to eliminate redundancies in loop nests. The loop-invariant code motion and induction variable elimination remove redundant computations
(
Aho, Alfred V. et al. 2007
;
Muchnick 1998
)
, but they still focus on scalar variables. The scalar replacement and array contraction target arrays, but they only reduce the array reference overhead.

Computation redundancies widely exist in loop nests of real-world applications. Furthermore, the redundancies are often related to arrays and across loop iterations, which is beyond the scope of the above-mentioned classic compiler optimization techniques. Several techniques are developed to exploit this kind of redundancy. Cooper et al.
(
Cooper et al. 2008
)
propose the first redundancy elimination method for loops. Other methods
(
Basu et al. 2015
;
Luporini et al. 2018
;
Luporini et al. 2020
)
target specific computation patterns only. A detailed analysis is present in Section
3
.

Techniques related to arrays usually rely on data dependence analysis
(
Lamport 1974
;
Maydan et al. 1991
;
Ding and Shen 2017
)
. The data dependence detection is generally undecidable since the addresses can be arbitrary functions. Although most array references are expressed by affine functions of loop index variables, solving the dependence precisely over the integer domain still constitutes an NP-hard problem, Diophantine equations
(
Banerjee 1979
)
.

This paper proposes RACE, a novel redundancy elimination method for array computations across loop iterations.
Unlike previous work, which often utilizes data dependency analysis to explore the redundancy,
RACE distinguishes the principles between the data dependency for loop transformation
and the data reuse for redundancy detection.
Then it utilizes a novel two-level scheme to identify the array references reuse and the expression computation redundancy.
The redundancy can be easily discovered by grouping the
expressions with the same identification value.

RACE traverses the expression trees in loop nests to detect redundancies hierarchically.
Previous work usually requires all pair comparisons between expressions and incurs the
O(n^{2})
complexity for
n
expressions.
However, RACE can complete the
detection on the expression trees in linear time based on the two-level identification scheme.
It generates efficient redundancy-eliminated codes with optimized auxiliary arrays that store
redundant computing results.
The code preserves the original order in the expression evaluation
by only considering redundancies between binary operations, i.e. binary expression trees.
Thus the result consistency is guaranteed.

Furthermore, RACE supports the expression reassociation
with various aggressive strategies
to improve the opportunity for redundancy.
This is equivalent to detecting redundancies on n-ary expression trees,
where the computation order can be reorganized.
This paper makes the following contributions:

•

A novel two-level scheme to identify the array references reuse and the expressions computation redundancy.

•

A linear accuracy-preserved algorithm for detecting hierarchical redundancies on binary operations.

•

An algorithm supporting expression reassociations for discovering more redundancies on n-ary trees.

3.
Related Work

3.1.
Data Dependence

The data dependence test

(
Kennedy and Allen 2001
;
Yu and Li 2012
;
Allen et al. 1983
)
targets two array references and at least one of them is a write. On the contrary, redundant computation means two or more expressions performing the same operation on the same array elements (or the same values). Thus, the redundancy detection focuses on reads. However, this is not an essential difference. The dependence techniques can also be applied to find two array reads to the same memory address.

The essential differences between the data dependence test and the computation redundancy elimination are three-fold.
First, the dependence test seeks to
check whether there is at least one iteration that the two references access the same memory address.
However, the redundancy elimination in loops only targets a large number
of common computations.
Second, the practical general dependence test technique is often conservative in the sense that it may report a false dependence but must report all real data dependence.
However, as an optimization technique, the redundancy elimination should
ensure a potential performance improvement.
Finally, the data dependence test focuses on array references,
while the computation redundancy targets expressions.
Therefore, it needs a new method to determine the redundancy
between two data reuses and between two expressions.

3.2.
Redundancy Elimination

Two classic redundancy elimination techniques for the scalar computation
are the value numbering and common subexpression elimination (CSE)
(
Cocke 1969
;
Cocke 1970
;
Potkonjak et al. 1996
)
.
The key idea underlying both methods is to record the identification of the operands.
The value numbering assigns the same number to the variables that share the same value,
while CSE utilizes the available expression in the data-flow analysis to recognize the operand change.
However, they only target scalar variables.

Cooper et al
(
Cooper et al. 2008
)
propose the enhanced scalar replacement (ESR), the seminal redundancy elimination method for loops. ESR employs two classic optimization techniques, value numbering and classic scalar replacement (CSR)
(
Callahan et al. 1990
)
.
ESR has the following disadvantages.
First, ESR only considers the recomputation across the innermost loop. It fails to discover all redundancies. Second, ESR incorporates the scalar replacement, which relies on advanced data dependence analysis. However, data dependence is not suitable for redundancy detection, which requires a more precise definition and method. Third, ESR is a two-step method that separates the name partition and index alignment. It will compare the unnecessary expressions that are not redundant. Fourth, the affinity graph in ESR fails to discover redundant computations of the arrays within the same name partition. Finally, ESR seeks to find the maximal computation redundancy in a single execution of their algorithm. However, as the example
in Section
2
demonstrates, the computation redundancy may exhibit a hierarchical property.

Deitz et al
(
Deitz et al. 2001
)

proposed array subexpression elimination (ASE)
for sum-of-product array expressions.
Like ESR, it also aims to eliminate the redundancies over the innermost loop dimension.
ASE depends on a specific framework called neighborhood tablet
to search the redundancy.
Basu et al
(
Basu et al. 2015
)
targeted stencil computations
and designed a specific optimization scheme.
It employs extra arrays to
buffer partial sums within the
leading plane of the whole iteration space.
However, it only focuses on simple stencils and
reduces redundant computations effectively for
stencils with symmetric coefficients.
These methods lack generality
and fail to process complex subexpressions, e.g.
a(i)*c(j,k)
.
Chi and Cong
(
Chi and Cong 2020
)
developed
heuristic search–based reuse (HSBR)
for stencil computations. They did observe the conflict between expressions
but did not formalize it as we do.

RCE (redundant computation elimination)
(
Yuan et al. 2016
)

is able to explore redundancies with temporal locality for stencils
but their search algorithm compares all possible expressions
and incurs high overhead.
This scheme is also utilized by the
loop-carried CSE method proposed in
(
Kronawitter et al. 2016
)
.
On the contrary, our method assigns each expression
a hash number and redundancies can be easily
identified by extracting expressions with the same hash number.
Wen et al
(
Wen et al. 2015
)

implemented a profiler to
pinpoint redundant computations by runtime checking. It finds redundancies in
several stencil computations and eliminates them by hand-written optimizations

Redundancy elimination, as well as many other compiler optimizations, such as loop transformation, memory access optimization and vectorization, relies on the results of aliasing analysis
(
Diwan et al. 1998
;
Cooper and Kennedy 1989
)
.
Alias analysis disambiguates memory references, primarily serving for the legality verification or candidate selection.
For example, existing work like ESR
(
Cooper et al. 2008
)
selects the redundancy candidates using the results of data dependence analysis which implicitly incorporates alias analysis.
Thus, alias analysis is orthogonal to these optimizations to some extent.
Furthermore, existing aliasing analysis techniques are powerful but not panaceas.
Other mechanisms such as the
restrict
keyword,
-fno-alias
compiler option, and
#pragma ivdep
directive are provided to enable more aggressive optimizations.
Therefore, in this paper, RACE focuses on the detection technique of redundancies, instead of directly incorporating alias analysis.

4.
Redundancy Identification

This section first limits the scope of this paper.
Then, the following two parts describe the two-level redundancy identification scheme.
The first level focuses on data sharing among array references.
Each array reference is assigned with an identification to determine
its reference pattern.
Array references with the same identification value
may access a sufficiently large set of common array elements.
The second level identifies the redundancies among expressions.
As mentioned before, the proposed method detects redundancies
hierarchically.
Thus, the second identification only focuses on
expressions with two operands, and larger expressions will be processed iteratively.
With this two-level hash mechanism,
RACE achieves linear-time redundancy detection,
while all previous methods require direct pair-wise comparisons between expressions which incurs a quadratic time complexity.
The computation redundancy can be easily discovered by grouping the
expressions with the same identification value
in linear time.

4.1.
Target

This paper describes our work using perfectly nested loops, where
all the statements are inside the innermost loop.
The experiment was also conducted on perfectly nested loops with no branch statement inside the loop.
However, the design is easy to be extended
and our implementation is able to handle imperfectly nested loops.

RACE eliminates redundant computations in unmodified arrays within the loop.
Each candidate expression considered in the algorithm
involves arithmetic operations
on scalar or array variables.
RACE targets array references of the form

A[a_{1}i_{s_{1}}+b_{1}]\dots[a_{n}i_{s_{n}}+b_{n}]
, where
s_{k}
is a loop level number ranking from the outermost loop to the innermost,

1\leqslant s_{k}\leqslant m
,
m
is the nesting depth of the loop structure,
i_{s_{k}}
is a loop index,
a_{k}
and
b_{k}
are constants.
For all the array references in the above POP example in Figure
1
,
we have
s_{1}=2
and

s_{2}=1
, and

i_{s_{1}}=i
and
i_{s_{2}}=j
.
This form covers most loop nests in real-world applications.
For the applications used in the evaluation of this work, over 95% of array accesses in loops conform to this pattern.
Scalars are considered zero-dimensional array references.
Function calls such as
\sin
and
\cos
can be interpreted as binary operators
\copyright
, where the function name is treated as a scalar variable.
For example,
\cos(ulat(1,j-1))
can be viewed as a binary expression
\cos\copyright ulat(1,j-1)
, where
\cos

\mathit{ulat}(1,j-1)

4.2.
Reference Pattern Identification (
\rpi
)

To recognize the redundancy among expressions, the reuse of array references needs to be analyzed. As explained above, the data dependence techniques test whether two array references may access at least the same array element. However, the redundancy elimination of array computations requires the reference of a sufficiently large set of common array elements.

In particular, this paper only considers the redundancy among array references with the same
reference pattern
in the
data space
of an array. The data space of an
n
-dimensional array
A
is
a finite subset of

\mathbb{Z}^{n}
consisting of
all the accessible n-dimensional elements,
but we regard the data space
as the entire infinite space
\mathbb{Z}^{n}

since we consider the pattern rather than a
specific range.
Two array references share the same reference pattern if they access the same infinite sub-lattice in the data space when the range of all loop indices is
\mathbb{Z}
.
For example,
A[i][j]
and
A[i+1][j-1]
have the same reference pattern since they both touch all the lattice points in the data space
of
A
,
\{(i,j)\mid i,j\in\mathbb{Z}\}
, while the reference lattices of
A[2i]
and
A[2i+1]
are disjoint.
A[2i]
and
A[3i]
access partial common lattice points,

\{6i\mid i\in\mathbb{Z}\}
.

Formally,
the infinite sub-lattice of
A[a_{1}i_{s_{1}}+b_{1}]\dots[a_{n}i_{s_{n}}+b_{n}]

is defined by

\mathcal{L}(B,b)=\{\textit{B}x+b\mid x=(i_{1},\dots,i_{m})\in\mathbb{Z}^{m}\}
, where
m
is the nesting depth of the loop structure,

n
is the dimension of the array
A
,

B
is a matrix of size
n\times m
,
B_{k,s_{k}}=a_{k}
and all other elements are 0,
b
is a vector of size
n
and its
k
-th component is
b_{k}
.

We now define the reference pattern identification (
\rpi
) to help recognizing the array references with the same reference pattern. Notice that
i_{k}
determines the dimension axis,
B_{n\times m}
identifies the lattice basis and
b=(b_{1},\dots,b_{n})
is the offset of the origin. It is easy to see that if two references share the same reference pattern, their index list (dimension axis)
\{i_{s_{1}},\dots,i_{s_{n}}\}
must be the same.
It is also straightforward to see that the coefficient list
\{a_{1},\dots,a_{n}\}
must be the same. For example, the point lattices of
A[2i]
and
A[3i]
are different.

The last information in
\rpi
is the offset vector
b
.
According to the above two requirements, two lattices

\mathcal{L}(B,b)
and
\mathcal{L}(B^{\prime},b^{\prime})

can be equal only if

B=B^{\prime}
. Furthermore,

\mathcal{L}(B,b)=\mathcal{L}(B,b^{\prime})
if and only if

b-b^{\prime}\in\mathcal{L}(B,0)
,
i.e.
Bx=b-b^{\prime}
has an integral solution.

Given two potential references
A[a_{1}i_{s_{1}}+b_{1}]\dots[a_{n}i_{s_{n}}+b_{n}]
and
A[a_{1}i_{s_{1}}+b_{1}^{\prime}]\dots[a_{n}i_{s_{n}}+b_{n}^{\prime}]
.
If a loop index
i_{s_{k}}=i
appears only once in the array reference,

a_{k}i=b_{k}-b_{k}^{\prime}
has an integral solution if and only if

b_{k}\bmod a_{k}=b_{k}^{\prime}\bmod a_{k}
.
Thus
\rpi
can incorporate

b_{k}\bmod a_{k}
.
For example,
A[2i]
and
A[2i+2]
have the same
\rpi
.
If there are multiple appearances of
i
, the successive deltas (differences) must also be equal.
Assume
i_{s_{k}}=i_{s_{j}}=i
,
the two equations

a_{k}i=b_{k}-b_{k}^{\prime}
and

a_{j}i=b_{j}-b_{j}^{\prime}

must have the same integral solution.
In addition to
b_{k}\bmod a_{k}=b_{k}^{\prime}\bmod a_{k}
for the first equation,
it is easy to obtain that the necessary and sufficient condition for the second equation is that
b_{k}/a_{k}-b_{j}/a_{j}

and
b_{k}^{\prime}/a_{k}-b_{j}^{\prime}/a_{j}

must be equal.
For example, the two references
A[2i+1][3i+2]
and
A[2i+3][3i+5]
have the same delta value
2/3-1/2=5/3-3/2=1/6
for
i
.
Thus they access the same infinite
sub-lattice.

5.
Redundancy Elimination on Binary Tree

The two-level scheme simplifies the redundancy detection algorithm, especially working with binary expression trees.
Complex expressions can be handled repeatedly and
the redundancies exhibit a
hierarchical structure.
Generating the straightforward code is also simple
but it requires a large extra space for auxiliary arrays.
This section presents a technique to reduce their dimensions.

5.1.
Detection Algorithm

Redundancy elimination stores the intermediate result and reuses it for the same succeeding calculations. Therefore, it can intrinsically guarantee the consistency of the final computing result. Results consistency is usually important for scientific applications that involve floating-point arithmetic operations.
To achieve this, the computing order must be respected.
Thus we first present the detection algorithm working on the high-level intermediate representation (IR), where the computation order is fixed.

The value numbering works on linear IR, such as the three-address code.
It just requires one sequential traversal of the IR code to find all redundancies.
The reason is that each expression
a=b\oplus c
can be assigned a number
used for the following redundancy check,
regardless of whether
b
and
c
are redundancies.
However, in the array redundancy detection of
a=b[\dots]\oplus c[\dots]
,
the
\rpi
is only defined on array references
b[\dots]
and
c[\dots]
,
and the
\eri
can only be computed on
a
.
If there is a following statement

5.3.
Redundancy Analysis

After identifying the expressions with the same
\eri
value, these redundant expressions can be replaced with precomputed auxiliary arrays. The range information for each auxiliary array is computed in the dependency graph. The evaluation of the profit gained from the replacement, i.e., the number of arithmetic operations eliminated, is discussed in this section.

Suppose that the auxiliary arrays
aa_{1},\dots,aa_{m}
appear in the transformed expression trees while the remaining positions are the original tree nodes. Let
cnt(aa_{k})
denote the appearance number of
aa_{k}
in the expression trees. For loop ranges, only the difference between the lower and upper bound is considered, which is denoted by
r(i_{t})
for the original loop range at index
i_{t}
. Let
r(i_{t},aa_{k})
denote the precompute loop range of auxiliary array
aa_{k}
at index
i_{t}
.

The reduction in arithmetic operations is only related to the modified parts of the expression trees. The first step is to calculate the original computational cost of the replaced parts. This can be done by recursively expanding the representative expression of each auxiliary array. Specifically, if the representative expression of
aa_{k}
contains
aa_{p}
, the corresponding part should be replaced by the representative expression of
aa_{p}
, continuing until all operands are no longer auxiliary arrays. Let the number of arithmetic operations in the expanded representative expression of
aa_{k}
be denoted by
ops(aa_{k})
. The original computational cost of the positions replaced by the auxiliary arrays in the expression tree can be computed, and combined with the loop range, the total reduction in computations in the original loop after extraction is given by:

ori=\prod_{t=1}^{n}r(i_{t})\sum_{k=1}^{m}ops(aa_{k})\cdot cnt(aa_{k})

However, generating the auxiliary arrays requires precomputation loops. Therefore, the computational cost associated with this additional precomputation must also be accounted for to determine the benefit. Since our
\eri
method targets binary expressions, each auxiliary array’s precompute expression is a binary expression, thus the precomputation cost of the auxiliary arrays is:

aft=\sum_{k=1}^{m}\prod_{t=1}^{n}r(i_{t},aa_{k})

So the profit gained from the detection algorithm on binary tree is
ori-aft
.

6.1.
Tree Flattening

It may demand the reorganization of expressions to find
redundancies for array computations and even classic scalar calculations
with commutative, associative, and distributive operations.
Consider the two expressions
x+y+z
and
x+z
.
Compilers may specify a pre-defined order for the former one.
The order can be either
((x+y)+z)
with the left-associative rule or
(x+(y+z))

with the right-associative rule, but none of them can
detect the redundancy with
x+z
unless
the expression is allowed to be reordered by commutative, associative, and even distributive reorganizations.
Note that the commutative law here is not the same as the one used
in the
\eri
calculation, where the expressions only have two operands.

However, to produce consistent results, it is generally illegal to perform the operation
reassociation even for the integral computation.
Take the expression
x+y+z
as an example again,
if
x
and
z
are very large positive integers and

y
is a very small negative integer,

((x+y)+z)
and
(x+(y+z))
may produce the correct result
but
((x+z)+y)
may result in an integer overflow.
Nevertheless, compilers usually provide options to control the expression reorganization
for aggressive optimizations
and leave the decision to users.

Therefore, the implementation of RACE provides several options to control the reassociation scheme.
We describe them by three aggressive levels.
First, if a consistent result is required,
the reassociation is prohibited
and the linear redundancy detection algorithm described above is employed.
Second, all the parentheses in the source code are respected,
and the reorganization can be only applied inside each parenthesis
which includes more than two operands.
Third, the parenthesis is removed when the operators are
consistent with the one outside the parenthesis.
Finally, the distributive law is applied to remove more parentheses.
The tree flattening algorithm is trivial according to the aggressive level.
It simply traverses the original binary tree in a post-order manner and merges the children that have the same operator as the current node after visiting them.

The first three levels are simple.
However, the distributive law should be applied cautiously.
It may destroy existing redundancies.
For example, it is obvious that there are two pairs of redundancies in
e=(a[i]+b[i])*(c[i]+d[i])+(a[i+1]+b[i+1])*(c[i+2]+d[i+2])
,
i.e.
\eri(a[i]+b[i])=\eri(a[i+1]+b[i+1])
and
\eri(c[i]+d[i])=\eri(c[i+2]+d[i+2])
.
However, if the distributive law is applied, both of the redundancies disappear
since none of the binary multiplication expressions has the same
\eri
.
Moreover, the distributive law may incur more computations.
For example, there are 2 multiplications and 5 additions in
e
, but 8 multiplications and 7 additions after removing the parentheses.
The detailed discussion is beyond the scope of this paper.

In practice, we only apply distributive law to a constant or loop-invariant scalar variable multiplier.
This may provide more redundancies.
Figure
4

exhibits a loop in the mgrid benchmark of SPEC2000.
It is a 3D stencil computation code.
The middle one of Figure
4

shows the code after the redundancy detection with the
second aggressive level.
Note that the code is optimized with the auxiliary array
optimization described above.

aa\_1\_0
and
aa\_1\_1
are auxiliary arrays
found in the second iteration of the do-while loop in the detection algorithm,
and both of them are built by the combination of two
aa\_0\_*
auxiliary arrays.
There are no more redundancies with this code.
After flattening the expression tree
using the fourth strategy,
more redundancies are discovered as shown in the right figure.
A new auxiliary array
aa\_3\_0
is detected in the fourth iteration of the algorithm.

Another set of options can specify the reassociation
for subtraction and division operations.
For example,
x-y-z
may produce
x-y
,
x-z
and
-y-z
.
Thus, it may require a sign change to identify the redundancy
between
y+z
and
-y-z
.
The rule is simple and just change the first operand to a plus sign
in the
\eri
calculation.
The division operation can be handled similarly.

6.2.
Detection Algorithm

The algorithm on n-ary expression trees
extends the above linear redundancy detection algorithm on binary trees.
Each node in an n-ary tree may have more than two operands, and their
calculation order can be reorganized to eliminate more redundancies.
An expression
e=x\oplus y\oplus\dots
in the n-ary tree is denoted by
\oplus(x,y,\cdots)
.

The extension needs to model the conflict relationship
between expressions.
If both
x\oplus y
and
y\oplus z
in an expression
\oplus(x,y,z)

are redundant,
only one of them can belong to the solution.
We define an undirected conflict graph
G=(V,E)

to formalize the constraint.
Each node in the graph
G
represents a possible binary expression
x\oplus y
.
A node and an expression are equivalent in
G
and used interchangeably.
Since the calculation order can be reorganized, we treat
x\oplus y
and
y\oplus x
as the same node.
Each edge indicates the conflict relation between two nodes, which means
that the two expressions (nodes) share the same array reference and cannot be extracted simultaneously.
Thus, any legal solution is an independent set of
G
.

V=\bigcup\limits_{e=\oplus(\dots)}\bigcup\limits_{x,y\in e}\{x\oplus y\mid x,y\text{ are leaves.},x\neq y\}

E=\{(v,v^{\prime})\mid v,v^{\prime}\in V,v=x\oplus y\neq v^{\prime}=x^{\prime}\oplus y^{\prime},\{x,y\}\cap\{x^{\prime},y^{\prime}\}\neq\emptyset\}

Algorithm
5
presents the extension to
the linear algorithm for n-ary trees.
The algorithm also follows a similar bottom-up scheme.
It initializes an empty graph
G=(V,E)
to maintain the
conflict information and updates the graph in the iteration
of the do-while loop.
It is easy to see that the second step in the do-while loop must
process all possible expressions.
In particular, it generates
C_{n}^{2}

additional binary expressions for each node with
n
children and
calculates their
\eri
values.
The
\eri
values of these newly generated binary expressions are computed as they are generated, and their corresponding edges
are added to
G
.
Then, a non-conflicting subset
S
of expressions
is chosen from
V
as the solution of redundant computations.
The graph
G
is updated again by
removing
S
and the conflicting nodes in
G
.
The last three steps are the same as Algorithm
3
.

set
\rpi
of all leaves to
\infty

initialize an empty graph
G=(V,E)

do

calculate
\rpi
for all leaves with
\rpi==\infty

calculate
\eri
for all possible binary expressions whose child’s
\rpi
is just computed

\eri
is just computed and the corresponding edges to

\{v|\exists v^{\prime}\in S,(v,v^{\prime})\in E\}

It is well-known that MIS is an NP-hard problem.
For a small number of expressions,
the optimal solution can be found
by the exhaustive method that enumerates all the possible MIS solutions
within a reasonable time.
However, for loop nests with numerous expressions and operands,
the exhaustive method becomes computationally infeasible within a reasonable time.
We then introduce a heuristic strategy
to reduce the problem size by considering
expressions with specific conditions.

6.3.
Heuristic Strategy

The array’s memory access patterns in real applications are typically regular and symmetric. As described in Section
5.2
, the auxiliary arrays can be compressed to lower dimensions to save memory and improve the cache performance. Based on the observation, we propose a heuristic algorithm called dimension-first extraction, which aims to find solutions with a higher potential for compression while reducing the problem size. This approach increases the opportunity to leverage cache locality and vectorization. Figure
4
illustrates how the dimension of auxiliary arrays can be further reduced using the dimension-first extraction method.
For instance, if we choose
R(i-1,k,j)+R(i+1,k,j)
as an auxiliary array in the first iteration of our algorithm, it cannot be compressed to a one-dimensional array because its reuses are along the
j
or
k
dimension. Furthermore, other solutions like
R(i-1,k-1,j)+R(i-1,k,j-1)
are irregular and may result in discrete memory access, leading to poor locality. In contrast, if
R(i,k,j-1)+R(i,k,j+1)
is chosen, it can be reused along
i
dimension.

Dimension-first extraction is a greedy algorithm that prioritizes selecting expressions with zero delta in the innermost dimension, i.e.,
e.\mathit{exprDelta}[i_{n}]=0
. A zero delta in the innermost dimension indicates that the reuses are more likely to occur along the innermost
i_{n}
dimension, as demonstrated in the example in Figure
4
.
The algorithm runs in a try-until manner. First, it only generates the nodes with
\mathit{exprDelta}[i_{n}]=0
when constructing Delta Graph. This forms a subgraph of the original Delta Graph, containing significantly fewer nodes. If any solutions are found, the algorithm accepts them and returns the control to the Algorithm
5
to proceed to the next extraction iteration. If no solution is found, the algorithm will generate a new subgraph containing only nodes with
\mathit{exprDelta}[i_{n-1}]=0
and try to find the solution of this graph, repeating this process until it finds a solution at some dimension
i
.

This algorithm improves the performance of finding the solution by significantly reducing the number of nodes and edges in the Delta Graph.
Without this algorithm, the mgrid case will generate more than one hundred nodes in the Delta Graph. In practice, the solution for Figure
4
is found almost immediately with the dimension-first algorithm, whereas the search algorithm may take much longer to find a suboptimal solution.
Additionally, there are multiple solutions satisfying our objective function on the Delta Graph. The dimension-first strategy successfully identifies the innermost loop reuse auxiliary arrays in our experiment, which exhibit better locality and provide opportunities for vectorization.

8.
Conclusion

This paper proposes RACE, which defines a two-level hashing algorithm to detect redundant array computations in nested loops. The first-level hash uses
\rpi
to determine whether two array references share the same memory access pattern.
The second-level hash computes
\eri
for each binary expression as an attribute within the expression, which encodes the expression-level reuse without explicitly comparing two different expressions.
A linear-time detection algorithm for binary expression trees is proposed based on
\eri
. After extraction, code generation and optimization of the auxiliary arrays are discussed.

Furthermore, tree flattening and the Delta Graph are introduced to identify redundancies in n-ary trees. The objective function for optimal single-iteration redundancy elimination is defined using the Delta Graph, which is reduced to a maximum independent set (MIS) problem. To accelerate the solution of this problem, a memory-friendly heuristic algorithm is presented to identify auxiliary arrays with inner-loop reuse.

Experiments show that our algorithm achieves significant speedups on various benchmarks, and the effectiveness of the detection algorithm for n-ary trees and the dimension-first heuristic strategy is demonstrated.
