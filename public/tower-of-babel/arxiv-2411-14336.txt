Finding the root in random nearest neighbor trees
Anna Brandenberger ∘ , Cassandra Marcussen † , Elchanan Mossel ∘ , Madhu Sudan †

Abstract
. We study the inference of network archaeology in growing random geometric graphs. We consider the root finding problem for a random nearest neighbor tree in dimension d ∈ 𝐍 d\in\mathbf{N} , generated by sequentially embedding vertices uniformly at random in the d d -dimensional torus and connecting each new vertex to the nearest existing vertex. More precisely, given an error parameter ε > 0 \varepsilon>0 and the unlabeled tree, we want to efficiently find a small set of candidate vertices, such that the root is included in this set with probability at least 1 − ε 1-\varepsilon . We call such a candidate set a confidence set . We define several variations of the root finding problem in geometric settings – embedded, metric, and graph root finding – which differ based on the nature of the type of metric information provided in addition to the graph structure (torus embedding, edge lengths, or no additional information, respectively). We show that there exist efficient root finding algorithms for embedded and metric root finding. For embedded root finding, we derive upper and lower bounds (uniformly bounded in n n ) on the size of the confidence set: the upper bound is subpolynomial in 1 / ε 1/\varepsilon and stems from an explicit efficient algorithm, and the information-theoretic lower bound is polylogarithmic in 1 / ε 1/\varepsilon . In particular, in d = 1 d=1 , we obtain matching upper and lower bounds for a confidence set of size Θ ⁡ ( log ⁡ ( 1 / ε ) log ⁡ log ⁡ ( 1 / ε ) ) \Theta\left(\frac{\log(1/\varepsilon)}{\log\log(1/\varepsilon)}\right) .



1.
Introduction

Given the structure of a network in which vertices join sequentially over time, one may be interested in how to use the network’s structure to determine properties of the history of the process. For example, is it possible for the network’s structure to reveal which vertex was added first, which vertices were added early, or which vertices were added late? The line of research concerned with the relationship between the network’s structure and reconstructing its history is referred to as
network archaeology

[
NK11
]
. Prior work has focused on network archaeology for combinatorial models of randomly growing graphs such as the uniform and preferential attachment models
[
BDL17
,
CCL+24
]
.

We initiate the study of network archaeology in geometric settings, studying the problem of finding the root of a tree that evolved according to the random nearest neighbor model. First, we formalize several variations of the root finding problem in geometric settings, with the variations differing based on the nature of the information available to the algorithm. We then focus on algorithms that have access to both the graph-theoretic and geometric structure of the network, with the goal of understanding how to best utilize both the combinatorial and geometric properties of the network’s structure to find the root vertex.

The random nearest neighbor model – sometimes referred to as the online nearest neighbor model – is one of the simplest geometric growth models for trees that can be studied. This model, first studied by Steele
[
Ste89
]
, considers a process in which vertices are sequentially placed independently and uniformly in an underlying metric space and connected to the geometrically closest vertex added previously. While the model can be defined on a general metric space, for concreteness we focus on the underlying metric space being the
d
-dimensional torus of unit volume.

Random nearest neighbor model

Fix
d,n\in\mathbf{N}
. The random nearest neighbor process on the
d
-dimensional torus
\mathbf{T}^{d}
of unit volume is defined as follows. For each
i\in[n]
, a vertex is embedded uniformly on
\mathbf{T}^{d}
independently of previous vertices; we refer to vertices by their index. For
i\geq 2
, we connect the new vertex
i
to the closest vertex among
[i-1]
in Euclidean torus distance, breaking ties arbitrarily (no ties occur almost surely). The Euclidean torus distance between
x=(x_{1},x_{2},\dots,x_{d})\in\mathbf{T}^{d}
and
y=(y_{1},y_{2},\dots,y_{d})\in\mathbf{T}^{d}
is defined as

(1)

d(x,y)=\Big(\sum_{i=1}^{d}\left(\min\{|x_{i}-y_{i}|,1-|x_{i}-y_{i}|\}\right)^{2}\Big)^{1/2}.

A tree
T_{n}
with
n
vertices generated according to this process is called a random nearest neighbor tree.
We denote the random nearest neighbor process and tree as
d
-NN process
and
d
-NN tree
respectively.

Network archaeology and root finding

Initiated by the seminal paper
[
BDL17
]
, the root finding question is as follows: given the unlabeled tree at some large time
n
, how can we recover the initial vertex 1? Clearly, since vertices 1 and 2 are exchangeable, this cannot be done with probability greater than
1/2
. Instead, the question is then: how large of a set must be returned to ensure that the root vertex (1) is included in this set with high probability? This question was first studied by
[
BDL17
]
for the uniform and preferential attachment tree models, and has since been the subject of extensive study
[
CX21
,
BCL23
,
CCL+24
,
BB22
,
BH23
,
BDG22
]
.

More precisely, in
non-geometric settings
, a root finding algorithm is given as input a target error parameter
\varepsilon\in(0,1)
and a randomly grown tree of size
n
with its labels removed, and returns a subset of vertices
H(\varepsilon,n)
containing the root with probability
1-\varepsilon
.

There are three natural ways to extend this question to recursive trees generated from a geometric process, which differ based on the amount of geometric information given to the algorithm. We call these
embedded
root finding,
metric
root finding and
graph
root finding.

Definition 1.1
.

A root finding algorithm for a random tree
T_{n}
generated via a geometric process on
\mathbf{T}^{d}
is given inputs
\varepsilon\in(0,1)
,
d\in\mathbf{N}
, and one of the following:

\bullet

(Embedded root finding) the unlabeled tree
T_{n}^{\circ}
embedded in
\mathbf{T}^{d}
;

\bullet

(Metric root finding) the adjacency matrix of the unlabeled tree
T_{n}^{\circ}
, with corresponding edge lengths;

\bullet

(Graph root finding) only the adjacency matrix of
T_{n}^{\circ}
.

It outputs a subset of vertices
H_{\mathbf{T}^{d}}(\varepsilon,T_{n}^{\circ})
of size independent of
n
(only depends on
\varepsilon
), which contains the root with probability
1-\varepsilon
, i.e.,

(2)

\liminf_{n\to\infty}\mathbf{P}_{T_{n}}\left\{1\in H_{\mathbf{T}^{d}}(\varepsilon,T_{n}^{\circ})\right\}\geq 1-\varepsilon.

We refer to
H_{\mathbf{T}^{d}}(\varepsilon,T_{n}^{\circ})
as
H(\varepsilon,n)
throughout the paper when the underlying metric space
\mathbf{T}^{d}
and input unlabeled tree
T_{n}^{\circ}
on
n
vertices are clear from the context.

The first question to ask is then:
does such a root finding algorithm exist
? For some models of random trees, it is impossible to output a confidence set
H(\varepsilon,n)
whose size is independent of
n

[
BDG22
]
. Second, if such a root finding algorithm exists, from an information-theoretic standpoint we also want to ask:
what confidence set size is necessary
? We want to find both upper and lower bounds on the confidence set size
|H(\varepsilon,n)|
returned by the algorithm.

In this paper, we focus on embedded and metric root finding. We show that there
do
exist root finding algorithms whose confidence set size
|H(\varepsilon,n)|
only depends on
\varepsilon
and is uniformly bounded with respect to
n
, whose runtime is polynomial in
n
and
1/\varepsilon
. In particular, a very simple metric root finding algorithm returns a confidence set of size
2^{d}/\varepsilon
; see Section
2
. Focusing on embedded root finding, we derive sharper results: both upper and lower bounds on the confidence set size. Our positive results are given by efficient algorithms, and our lower bounds on the confidence set size are information-theoretic.

For
d=1
, we prove matching upper and lower bounds on the confidence set size and provide an efficient algorithm achieving this bound.

Theorem 1.1
.

There exist
c_{1},c_{2}>0
such that the following holds for the 1-NN model for all
n\in\mathbf{N}
and all sufficiently small
\varepsilon>0
.
There exists a
O(n^{2}+\log^{2}(1/\varepsilon))
-time embedded root finding algorithm that returns
H(\varepsilon,n)
of size satisfying
|H(\varepsilon,n)|\log|H(\varepsilon,n)|\leq c_{1}\log(1/\varepsilon)
. Additionally, it is information-theoretically impossible to provide a confidence set whose size satisfies
|H(\varepsilon,n)|\log|H(\varepsilon,n)|<c_{2}\log(1/\varepsilon)
.

We can equivalently write the confidence set size as
|H(\varepsilon,n)|\asymp\log(1/\varepsilon)/W(\log(1/\varepsilon))
, where
W
is the Lambert
W
function. This is
|H(\varepsilon,n)|\asymp\log(1/\varepsilon)/\log\log(1/\varepsilon)
for sufficiently small
\varepsilon>0
.

The bound on the size of the confidence set here is exponentially smaller than the lower bounds on the size of the confidence set for the well-studied uniform and preferential attachment tree models
[
BDL17
,
BH23
]
(both subpolynomial in
1/\varepsilon
). The fact that the bound here is logarithmic in
1/\varepsilon
indicates that the geometry of the tree retains a lot of information about the history of the process.

Our result for the 1-NN model can be extended to the setting where the underlying space is a thin strip in two dimensions, whose thickness depends on the error parameter
\varepsilon
; see Corollary
4.1
. As we shift to the general setting of the
d
-dimensional unit torus for fixed
d\geq 2
, while we do not retain the bounds from the one-dimensional setting, we prove that it is still possible to return a set whose size is subpolynomial in
1/\varepsilon
, and matches the curent best upper bound for root finding in uniform attachment trees.

Theorem 1.2
.

For the
d
-NN model with
d\in\mathbf{N}
,
d\geq 2
, for all
n\in\mathbf{N}
and all sufficiently small
\varepsilon>0
, there exists a
O(n^{2}+n(1/\varepsilon)^{1/(\log\log(1/\varepsilon))})
-time embedded root finding algorithm that returns a confidence set
H(\varepsilon,n)
of size satisfying
|H(\varepsilon,n)|\leq\exp\left(\frac{\log(1/\varepsilon)}{\log\log(1/\varepsilon)}+d\log\log(1/\varepsilon)\right)
. Additionally, there exists a constant
c>0
such that it is information-theoretically impossible to provide a confidence set whose size satisfies
|H(\varepsilon,n)|\log\left({|H(\varepsilon,n)|}{d^{-1/d}}\right)\leq c\log(1/\varepsilon)/d.

1.1.
Challenges and proof ideas

Root finding algorithms in the geometric setting have access to more information than in the combinatorial settings; namely, metric and embedded root finding algorithms get not only the tree that is formed but also information about edge lengths (metric setting) and geometric embedding (embedded setting). This may seem to suggest that finding the root is inherently easier in geometric settings than in combinatorial settings, where being ‘easier’ corresponds to the required confidence set size being smaller. However, it turns out geometric attachment processes such as the random nearest neighbor process are widely different from combinatorial processes; this leads to new challenges to their analysis.

Previous work on root finding for combinatorial processes
[
BDL17
,
BH23
,
BB22
,
CCL+24
]
has relied on constructing suitable statistics that are useful in uncovering the ages of vertices.
These statistics are typically based on the balance of subtrees rooted at neighbors of a vertex (e.g., for uniform attachment
[
BDL17
]
) or on the degrees of vertices (e.g., for preferential attachment
[
BH23
,
CCL+24
]
), which can be analyzed via martingale methods. In contrast, in the geometric setting, it is difficult to find martingales that indicate the ages of vertices, which also concentrate well. Simple graph parameters or even distances don’t adequately capture the ability of a vertex to acquire new descendants. Let us highlight why existing statistics for combinatorial processes are difficult to analyze for the random nearest neighbor process.
First, analyzing sizes of subtrees is difficult because tracking the precise probabilities of connecting to different vertices becomes intractable due to the dependence of this on the specific geometric positions of vertices. Second, degrees are not well-concentrated enough for our purposes
[
LM24
]
(similarly to in uniform attachment). Due to these challenges, naturally, root finding algorithms for random nearest neighbor trees will rely on different statistics than in combinatorial settings.

For the random nearest neighbor process, using the fact that edges tend to become shorter over time, we focus on long edges, which are expected to have arrived early on in the process. Of course, the first edge may itself not be long, but it is likely to be near a long edge. More specifically, there exist some
\ell<1,k\in\mathbf{N}
depending on
\varepsilon,d
such that, with probability at least
1-\varepsilon
, some edge of length at least
\ell
arrives in the first
k
steps of the process. We can bound the number of long edges using a packing argument, so this motivates our first attempt at an algorithm and analysis: return vertices that are within a graph-theoretic radius of
k
of a long edge. Setting
k=1
, we achieve a confidence size of
O\left(2^{d}/\varepsilon\right)
. To improve over this, we try to search within a radius of
k\geq 2
. However, the degrees scale as
\Theta(\log n)

[
LM24
]
, so searching within
k
-neighborhood could produce confidence sizes that scale with
n
with this approach.

We overcome this challenge with a second key idea: we prune the graph to a bounded-degree induced subgraph which includes the root vertex. In particular, this subgraph excludes so-called “covered” vertices that lie in geometric regions corresponding to edges, which cannot be the root due to a geometric argument. Our final algorithm is as follows: return vertices
in this induced subgraph of bounded degree
that are within a radius of
k
of an edge of length at least
\ell
. This algorithm returns a confidence set whose size is sub-polynomial in
1/\varepsilon
and uniformly bounded in terms of
\varepsilon
and
d
.

We specify the root finding algorithms for
d=1
and
d\geq 2
respectively in Algorithms
2
and
4
, and analyze them respectively in Sections
3
and
5
. In these sections, we also study lower bounds on the confidence size. To do so, we construct a family of trees with the properties that, first, a random nearest neighbor tree is in the family with probability at least
\varepsilon
and, second, for each tree in the family the root has a lower maximum likelihood estimator value than most other vertices in the tree.

We now make some remarks about our results. First, using the approach outlined above, in the one-dimensional setting, we prove that the size of the confidence set needed is exponentially smaller than the known lower bounds on the confidence set size for uniform and preferential attachment trees. This indicates the power of geometric information in finding the root. In the setting of
d\geq 2
, our upper bounds on the confidence set size match those currently given for uniform attachment trees
[
BDL17
]
; however, since the processes evolve rather differently and the algorithms used are also different, this may not point to deeper parallels in the complexity of root finding between the two settings. Second, in the existing literature on random nearest neighbor trees, much more precise statements can often be made in the setting of
d=1
than in the setting of
d\geq 2
(e.g.
[
PW06
]
). The strength of our bounds (for example, as reflected in the comparisons between upper and lower bounds on the confidence set size) parallel this difference between
d=1
and
d\geq 2
.

A note on the underlying geometric space.

We focus on the setting where the underlying geometric space is the unit torus
\mathbf{T}^{d}
in
d
dimensions, in order to avoid issues with boundary conditions.
We believe that the results and proofs extend to other “nice”
d
dimensional sets such as the
d
-dimensional sphere.

1.2.
Related work

The problem of finding the root of a randomly growing graph process is a fundamental question in the realm of
network archaeology
, which is an area of research focused on understanding how well the history of a network can be reconstructed given access to the structure of a network at a later time. Root finding is well-studied for a wide range of combinatorial models of randomly growing graphs, such as uniform attachment trees
[
BDL17
,
CX21
]
and uniform attachment DAGs
[
BCL23
]
, preferential attachment trees
[
BDL17
,
CCL+24
]
, and more general families of graph processes
[
BB22
,
BH23
]
. These algorithms often return sets of vertices whose degrees are large or whose position in the graph (with respect to sizes of subtrees rooted at their neighbors) is “balanced.” Lichev and Mitsche
[
LM24
]
raise the question of if root finding is possible for random nearest neighbor trees. In terms of how root finding can impact network archaeology more broadly, understanding how to find which vertex arrived first in the process can lead to broader insights into how to detect times of arrivals of vertices and understand which vertices arrived early or late in the process. For example, in the setting of uniform attachment processes, an algorithm for finding the root in
[
BDL17
]
was later adapted to the setting of estimating the entire history of the process
[
BGLS24
]
.

Real-world networks are often modeled by processes involving geometric components
[
FFV06
,
JM13
]
. Therefore, it is both interesting and relevant to understand how the geometry of the processes can impact and facilitate the discovery of the root given a snapshot of the network at a later time. The random nearest neighbor model is a useful starting point due its simplicity to state and also because it appears as a limiting case of geometric models of real-world networks (more specifically, of geometric preferential attachment
[
JW15
]
). Network archaeology for geometric network models is, to our knowledge, unstudied and it remains an interesting open direction to understand if or how our approaches extend beyond the random nearest neighbor tree setting.

There is a long line of research on online nearest neighbor graphs over
(0,1)^{d}
; see
[
PW06
,
Wad09
,
Pen05
,
Wad07
,
Tra22
]
. These papers primarily focus on understanding the asymptotic behavior of sums of power-weighted edge lengths (meaning, consider all of the edges in the tree, raise their lengths to some power, and sum this). Additionally, Aldous
[
Ald18
]
studies properties of the Voronoi regions in the two-dimensional case for a related geometric randomly growing graph model. A more recent paper
[
LM24
]
studies combinatorial properties of the random nearest neighbor tree on
\mathbf{T}^{d}
. Many geometric and combinatorial properties of random nearest neighbor trees are still unstudied or unresolved; understanding such properties could lead to improved root finding guarantees.

2.
Warm-up: Metric root finding

We first construct a metric root finding algorithm that simply returns vertices adjacent to a long edge, where the definition of “long” depends on
\varepsilon
. When we move to the setting of
embedded
root finding in sections
3
,
4
and
5
, we still rely on this idea of the root being graph-theoretically “close” to a long edge, while reducing the required confidence set size by using other available geometric properties. Our simple metric root finding algorithm is as follows.

Algorithm 1
.

Return all vertices adjacent to edges of length at least
\ell=\varepsilon^{1/d}\cdot{\Gamma^{1/d}\left(\frac{d}{2}+1\right)}{\pi^{-1/2}}
, where
\Gamma
is Euler’s gamma function.
Note that
\ell
is chosen so that the volume of the
d
-dimensional ball of radius
\ell
is
\varepsilon
.

Additionally, we show that all vertices in the returned confidence set arrived early in the process, where
early
is defined as some function of
d
and
1/\varepsilon
, uniformly bounded with respect to
n
. This is a desirable property out of an algorithm since all of the vertices returned in
H(\varepsilon,n)
are in some sense informative, as opposed to arbitrary.

Remark 1
.

We note that the algorithm presented above is local, in the sense that every vertex can tell if it should be returned by looking within a fixed radius of itself for a long edge (in the case of this algorithm, the radius is one). This locality indicates that it is feasible to run the algorithm efficiently in a distributed setting.

Lemma 2.1
.

This algorithm satisfies the property that, for all
\varepsilon>0
sufficiently small and all
n\in\mathbf{N}
,
\mathbf{P}\{1\in H(\varepsilon,n)\}\geq 1-\varepsilon\text{ and }|H(\varepsilon,n)|\leq{2^{d}}/{\varepsilon}
. The algorithm runs in
O(n)
time. Furthermore, there exists
c>0
such that with probability at least
1-\varepsilon
,
|H(\varepsilon,n)|\subseteq\{1,\dots,\tau\}
for
\tau=\exp(cd)\cdot(1/\varepsilon)\log(1/\varepsilon)
.

Proof.

Correctness.
Let
B_{d}(\ell)
denote the volume of the
d
-dimensional ball of radius
\ell
.
The first edge added to the graph is long with probability
1-B_{d}(\ell)=1-\varepsilon
.
Therefore, for all
n\in\mathbf{N}
, the root is in the returned set with probability at least
1-\varepsilon
.

confidence set size.
We now bound from above the number of vertices adjacent to long edges. When a vertex
t
at position
x
is added to
T_{t-1}
, a long edge is created if and only if there exists an empty open ball of radius
\ell
around
x
.
This implies that, in the subgraph of
T_{n}
consisting of all vertices adjacent to long edges, each vertex occupies a disjoint ball of radius
\ell/2
.
Our confidence set size can therefore be bounded from above by
the number of disjoint balls of radius
{\ell}/{2}
, i.e. of volume
B_{d}\left({\ell}/{2}\right)
, that can be packed into
\mathbf{T}^{d}
, which is

\frac{1}{B_{d}\left({\ell}/{2}\right)}=\frac{2^{d}}{B_{d}(\ell)}=\frac{2^{d}}{\varepsilon}.

Runtime.
The algorithm takes
O(n)
time since per vertex it takes constant time to search for an adjacent edge of length at least
\ell
.

All vertices returned arrived early.
We now prove that all of the vertices in the confidence set returned arrived in the first
\tau
steps of the process.

Let us first consider a space without wrap-around; that is,
[0,1]^{d}
. For a vertex
x\in[0,1]^{d}
, let
\mathcal{C}
be a (minimal size) set
\mathcal{C}(x)=\{C_{i}(x)\}_{i=1}^{\gamma_{d}(x)}
of cones of angle
\pi/4
centered at
x
whose union covers the entire space;
that is,
\gamma_{d}(x)=|\mathcal{C}(x)|
.

We make use of the following two lemmas regarding the size of
\mathcal{C}(x)
for any
x
and the relationship between
\mathcal{C}(x)
and the diameter of cells in a Voronoi diagram.

Lemma 2.2
.

[
DGL13
, Lemma 5.5]

For all
x\in\mathbf{R}^{d}
,
\gamma_{d}(x)\leq 3^{d}
.

Lemma 2.3
.

(Observation from the proof of
[
DGLW17
, Theorem 5.1]
)
Consider any set
\mathcal{S}
of points in
\mathbf{R}^{d}
. For
x\in\mathcal{S}
, let let
D_{i}(x)=\min_{x_{i}\in\mathcal{S}:x_{i}\in C_{i}(x)}\lVert x-x_{i}\rVert
. Consider the Voronoi diagram given by
\mathcal{S}
. Then, for all
x\in\mathcal{S}
, the diameter of the Voronoi cell of

\sqrt{2}\max_{i}D_{i}(x)
.

Given these lemmas, we prove that with high probability all vertices returned arrived in the first
\tau=\exp(cd)\cdot(1/\varepsilon)\log(1/\varepsilon)
steps of the
d
-NN process over
\mathbf{T}^{d}
. Observe that if by time

and are not included in

.
Therefore, if there exists
\tau
such that with probability at least
1-\varepsilon
, the diameter of the Voronoi cell of every vertex
x\in T_{\tau}
is at most
\ell
, then we have that with probability at least

[

DGLW17
]
to bound the diameter of the Voronoi cells.

To complete the proof, we now bound the diameters of the Voronoi cells, using a similar argument as
[
DGLW17
]
. We want to show that for
\tau=\exp(cd)(1/\varepsilon)\log(1/\varepsilon)
,

(3)

\mathbf{P}\left\{\exists x\in[\tau],\ i\in[\gamma_{d}(x)]\text{ such that }D_{i}(x)>\ell/\sqrt{2}\right\}\leq\varepsilon,

which, combined with Lemma
2.3
, yields that with probability

,
D_{i}(x)\leq\ell
for each
x\in T_{\tau}
and each

We now show (

By definition of

implies that there does not exist a

is at least

\mathbf{P}\{D_{i}(x)>\ell/\sqrt{2}\}\leq\left(1-C(d)\left(\frac{\ell}{\sqrt{2}}\right)^{d}\frac{1}{\gamma_{d}(x)}\right)^{(\tau-1)}\leq\exp\left(-(\tau-1)C(d)\left(\frac{\ell}{\sqrt{2}}\right)^{d}\frac{1}{\gamma_{d}(x)}\right).

Then, a union bounding over all

and

3.
Tight bounds for the confidence set size in 1D

We now turn to embedded root finding. In this section, we prove Theorem
1.1
. For our upper bound, we define an algorithm that, as introduced in Section
2
, uses the idea that the root should be close to a long edge. Another useful geometric property is that the root is never in an interval covered by an edge. As the torus
\mathbf{T}^{1}
rapidly becomes covered by edges, this property helps keep the confidence set small.

For lower bounds on the confidence set size, we also use the structure of the subgraph of vertices that are not covered by any edge. The goal is to construct a family of trees that are reasonably likely to occur and for which the root is difficult to identify. We construct this family to be trees that begin with a path of many uncovered vertices.

Before describing our algorithm and proofs, we first introduce some structural results about the one-dimensional nearest neighbor tree.

3.1.
Structural aspects of the 1-NN tree

Each edge
e=(x_{1},x_{2})\in E(T_{n})
edge covers a geometric interval; we denote this interval
I_{e}
. Also, recall that
T_{n}[t]
denotes the induced subtree of vertices
\{1,\dots,t\}
.

Definition 3.1

(Uncovered vertices and edges)
.

A vertex
x\in T_{n}
is covered if there exists an edge
e\in E(T_{n})
such that
x\in I_{e}
. Otherwise,
x
is uncovered.
Similarly, we say that an edge
e=(x_{1},x_{2})
is covered if either of its endpoints
x_{1}
or
x_{2}
is covered. The edge is otherwise uncovered. We denote the induced subgraph of uncovered vertices by
\mathcal{U}_{n}
.

Note that the space covered by edges of
T_{n}
in
d=1
forms a continuous interval, which we
define formally as follows.

Figure 1.
In this example of a 1-NN of size
n=12
, the subtree of uncovered vertices and edges is colored green. The covered vertices and edges are colored red. The remaining uncovered space
\mathcal{L}_{n}
is highlighted in yellow.

Definition 3.2

(Remaining uncovered interval)
.

The remaining uncovered interval
\mathcal{L}_{t}
at time
t
is
\mathbf{T}^{1}\setminus\bigcup_{e\in E(T_{n}[t-1])}I_{e}
, the continuous interval of
\mathbf{T}^{1}
that does not intersect with any existing edge’s covered interval.

We now make a few observations that can be easily derived from the above definitions.
First, note that a vertex
t\in T_{n}
is uncovered if and only if it is in the remaining uncovered space at its time of arrival, i.e.
x_{t}\in\mathcal{L}_{t-1}
.
Indeed, due to the nature of the
1
-NN attachment process, once a vertex is uncovered, it cannot become covered in the future.
Also, if a vertex is uncovered, then all of its ancestors on the path to the root of the tree must also be uncovered.

Our algorithm for root finding in
d=1
relies on geometric and structural properties of the uncovered subgraph
\mathcal{U}_{n}
(see Lemma
3.1
). We also require control of the size of the remaining interval
\mathcal{L}_{t}
(see Lemma
3.2
).

For
i\in\mathbf{N}
, we define the following random variables: let
X_{i}
denote the time at which the
i
th
uncovered vertex is added, and let
L_{i}
denote the length of the remaining uncovered interval after the
i
th
uncovered vertex is added. That is,
X_{1}=1,X_{2}=2,X_{3}\geq 3
, and
L_{1}=1
. Letting
U_{1},U_{2},\dots
be i.i.d. Unif
[1/2,1]
random variables, we have

(4)

X_{i+1}=X_{i}+\mathrm{Geo}(L_{i})\ \text{ and }\ L_{i+1}=U_{i}L_{i},

where
X_{1}=1,L_{1}=1
, and
\mathrm{Geo}(p)
is the number of independent
\mathrm{Ber}(p)
trials until the first success. Note that the number of uncovered vertices is
|\mathcal{U}_{n}|=\max\{i\in\mathbf{N}:X_{i}\leq n\}
.

Lemma 3.1
.

The induced subgraph of uncovered vertices
\mathcal{U}_{n}
in
T_{n}
is a path.
In addition, if
T_{n}
has
K+1
uncovered vertices, it has expected size
X_{K+1}
with
\mathbf{E}X_{K+1}=1+({(\log 4)^{K}-1})/({\log 4-1})
.

Proof.

The first statement follows since each vertex in the induced subgraph can only have one uncovered neighbor on either side.
Next, we can compute that

\mathbf{E}\mathrm{Geo}(U_{1})=\sum_{k=1}^{\infty}k\int_{1/2}^{1}p(1-p)^{k-1}2dp=\int_{1/2}^{1}(2/p)dp=2\log 2

and that similarly,
\mathbf{E}\mathrm{Geo}(U_{j}\cdots U_{1})=(2\log 2)^{j}
for each
j\in\mathbf{N}
. Therefore, from (
4
), the expected size of a 1-NN tree with
K+1
uncovered vertices is

\mathbf{E}X_{K+1}=2+\mathbf{E}\mathrm{Geo}(U_{1})+\mathbf{E}\mathrm{Geo}(U_{1}U_{2})+\dots+\mathbf{E}\mathrm{Geo}(U_{1}\cdots U_{K-1})=1+\sum_{j=0}^{K-1}(2\log 2)^{j},

which yields the second statement.
∎

Lemma 3.2
.

For a
1
-NN tree with
K+1
uncovered vertices, the size of the remaining uncovered interval
L_{K+1}
satisfies

-\log L_{K+1}\overset{d}{=}\sum_{j=1}^{K}E_{j},

where
E_{j}
are i.i.d. truncated exponential
\mathrm{TEXP}(1,\log 2)
random variables, i.e.,
E_{j}=\tilde{E_{j}}\mathbf{1}_{[\tilde{E_{j}}\leq\log 2]}
for i.i.d.
\tilde{E_{j}}\sim\mathrm{Exp}(1)
.

Proof.

Since each new uncovered edge removes a
\mathrm{Unif}(0,1/2)
fraction of the remaining uncovered interval, the interval correspondingly shrinks by a
\mathrm{Unif}[1/2,1]
factor at each step. Therefore,

L_{K+1}\overset{d}{=}\prod_{j=1}^{K}U_{j}
,
where
U_{j}
are i.i.d.
\mathrm{Unif}[1/2,1]
random variables. The statement then follows since
-\log\mathrm{Unif}[1/2,1]\overset{d}{=}\mathrm{TEXP}(1,\log 2)
.
∎

3.2.
Algorithm and upper-bound on the confidence set size

Consider a fixed
\varepsilon>0
and a constant
C>1
depending on
\varepsilon
. Let
k
satisfy
k\log k=C\log(2/\varepsilon)
. Our root finding algorithm in
d=1
is given below.

Algorithm 2
.

Initialize
H(\varepsilon,n)
to be empty. While
|H(\varepsilon,n)|\leq 3k
, add uncovered vertices within graph distance
k
of an uncovered edge of length greater than
\ell=1/(5k)
. More precisely,

Step 1: Find uncovered vertices.
This can be done as follows. For each unidentified vertex
x
, search among neighbors
y
of
x
for an edge
e=(y,z)
such that
x\in I_{e}
(as in Definition
3.1
). If there is no such

,
x
is marked as uncovered. Otherwise, if there exists such an
e
, then
y
is marked as parent of
x
, and the entire subtree of
x
is identified and marked as covered. This marks all vertices; note that a vertex may be updated from uncovered to covered.

Step 2: Building the confidence set.
For each uncovered edge of length greater than
\ell=1/(5k)
, add all uncovered vertices within graph distance
k
while
H(\varepsilon,n)
is of size less than
3k
.

Figure 2.
Our algorithm returns uncovered vertices within a graph distance of

and

We now argue about the correctness, confidence set size, and runtime of the algorithm to complete the proof of the upper bound in Theorem
1.1
.

Lemma 3.3
.

Let
d=1
.
For every sufficiently small
\varepsilon>0
, there exists
C>0
such that for
k
satisfying
k\log k\geq C\log(2/\varepsilon)
, the algorithm above returns a set of size
|H(\varepsilon,n)|\leq 3k
, such that with probability at least
1-\varepsilon
, the root is successfully returned in the set.
Additionally, the runtime of the algorithm is polynomial in
n
and
\log(1/\varepsilon)
.

Proof.

Correctness.

We first argue that with probability at least
1-\varepsilon/2
, the confidence set includes all vertices of distance
\leq k
away from an edge of length
\geq\ell
. To do so, we use Lemma
3.2
. By Lemma
3.2
, the remaining uncovered space
L_{k}
after
k
uncovered vertices are placed satisfies

\displaystyle\mathbf{P}\left\{L_{k}\geq\frac{1}{5k}\right\}

\displaystyle=\mathbf{P}\Big\{\sum_{j=1}^{k-1}E_{j}\leq\log(5k)\Big\}

\displaystyle\leq\binom{k-1}{(k-1)/2}\mathbf{P}\left\{E_{j}\leq\frac{2\log(5k)}{k-1}\right\}^{(k-1)/2}\leq\binom{k-1}{(k-1)/2}\left(\frac{4\log(5k)}{k-1}\right)^{(k-1)/2}

(5)

\displaystyle\leq\exp\left[-\frac{k-1}{2}(\log(k-1)-\log(4\log 5)-\log\log k-\log(2e))\right].

For any sufficiently small
\varepsilon
, there exists
C>0
such that if
k\log k\geq C\log(2/\varepsilon)
, this probability is bounded above by
\varepsilon/2
.
Therefore, with probability at least
1-\varepsilon/2
, all later uncovered edges have length less than
1/(5k)
. In this case, the set of vertices of distance
k
away from any long edge is a subset of the first
k
uncovered vertices, plus
k
uncovered points to either side of this path, for a total of at most
3k
vertices. Therefore, with probability at least
1-\varepsilon/2
, the confidence set includes all vertices of graph distance at most
k
from an edge of length at least
\ell
.

Therefore, to argue that
\mathbf{P}\{1\not\in H(\varepsilon,n)\}\geq 1-\varepsilon
, it only remains to argue that the probability that none of the first
k
uncovered edges has length
\geq\ell
is at most
\varepsilon/2
. The failure probability
\mathbf{P}\{1\not\in H(\varepsilon,n)\}
can be upper bounded by the event
E
that the first
k
uncovered edges are all short, i.e., of length less than
\ell
. Furthermore, note that the length of the
k
th uncovered edge is uniform over
1-\sum_{i=1}^{k-1}L_{i}
where
L_{i}
are the lengths of the previous
k-1
uncovered edges. We have

(6)

\mathbf{P}\{E\}\leq 2\ell\frac{2\ell}{1-\ell}\cdots\frac{2\ell}{1-(k-1)\ell}<\left(\frac{2\ell}{1-k\ell}\right)^{k}=(5\ell/2)^{k}

since
1-k\ell=4/5
for
\varepsilon>0
sufficiently small. For this failure probability to be upped bounded by
\varepsilon/2
, we require

k\log(2k)\geq\log(2/\varepsilon),

which is satisfied by our choice. Therefore, the root is successfully returned in the confidence set with probability at least
1-\varepsilon
.

confidence set size.
The confidence set size of the algorithm is at most
3k
by construction.

Runtime.

In the first step of the algorithm, we mark all vertices as covered or uncovered. This relies on searching within a fixed graph radius and updating labels of descendants, which takes at most
O(n^{2})
time total.
In the second step, for each uncovered edge of length greater than
\ell=1/(5k)
, we look for uncovered vertices within graph distance
k
of the edge. As noted in Lemma
3.1
, the induced subgraph of uncovered vertices is a path. Note also that the number of uncovered edges of length greater than
\ell=1/(5k)
is at most
1/\ell=5k
. Therefore, the runtime of Step 2 is bounded above by
\log^{2}(1/\varepsilon)
.
Therefore, the runtime of the algorithm is
O(n^{2}+\log^{2}(1/\varepsilon))
.
∎

3.3.
Lower bound on the confidence set size

To prove a lower bound on the size of
H(\varepsilon,n)
, we look at the maximum likelihood estimator for the root on a family of trees that occurs with probability at least
\varepsilon
, as in
[
BDL17
]
.

Given a fixed embedded tree
T\in\mathcal{T}
of size
n
with vertices
\{x_{i}\}_{i\in[n]}
, we consider all possible arrival orderings.
Let
\sigma:[n]\to[n]
be a permutation, which we think of as assigning an arrival order to the
n
vertices. Recall that we call
\sigma
“feasible” if
T^{\sigma}
satisfies
(T^{\sigma})^{\circ}=T^{\circ}
.

Given an unlabeled tree
T^{\circ}
of size
n
embedded in
\mathbf{T}^{1}
, the maximum likelihood estimator (MLE) for the root returns the vertex
i\in[n]
maximizing the posterior probability of
i
being the root. For the problem of determining which vertex is the root, this is the Bayes optimal answer given a uniform prior. We denote the probability of
i
being the root as

(7)

\mathrm{MLE}_{T^{\circ}}(i)=\sum_{\begin{subarray}{c}\sigma:[n]\to[n]\\
\sigma(i)=1\end{subarray}}\mathbf{P}\{T_{n}=T^{\sigma}\mid T_{n}^{\circ}=T^{\circ}\}=\sum_{\begin{subarray}{c}\sigma:[n]\to[n]\\
\text{$\sigma$ is feasible and }\sigma(i)=1\end{subarray}}\mathbf{P}\{T_{n}=T^{\sigma}\mid T_{n}^{\circ}=T^{\circ}\}.

On the right hand side,
\mathbf{P}\{T_{n}=T^{\sigma}|T_{n}^{\circ}=T^{\circ}\}
is the probability that a 1-NN tree conditioned its unlabeled tree being
T^{\circ}
has arrival times of vertices corresponding to the permutation
\sigma
. The second equality follows by noting that if
\sigma
is not feasible, then
\{T_{n}=T^{\sigma}\}\cap\{T_{n}^{\circ}=T^{\circ}\}=\varnothing
.
Also, recall that a
d
-NN tree can be generated by first drawing
n
points in
\mathbf{T}^{d}
, then drawing a random permutation
\sigma
for the timestamps, therefore, in fact, for each feasible
\sigma
, the probability
\mathbf{P}\{T_{n}=T^{\sigma}\mid T_{n}^{\circ}=T^{\circ}\}
is equal.

The MLE corresponds to the optimal approach for finding the root; i.e., if one wants a confidence set of size
K(\varepsilon)
, the smallest is the set
H_{\mathrm{MLE}}(\varepsilon,n)
consisting of the
K(\varepsilon)
vertices with largest posterior probability values.
To prove lower-bounds on
|H(\varepsilon,n)|
, we wish to show that, for a family of sufficiently likely tree configurations, the posterior probability of the root is small. As argued in
[
BDL17
]
, it suffices to consider
H_{\mathrm{MLE}}(\varepsilon,K(\varepsilon)+2)
due to the monotonicity of the root finding property.

With this approach, we now prove the lower bound on the confidence set size in the one-dimensional setting from Theorem
1.1
: any root finding algorithm must return a set of size
K(\varepsilon)
satisfying

(8)

(K(\varepsilon)+1)\log(K(\varepsilon)+5)\geq\log(2/\varepsilon).

The tree configurations.

We now prove the lower bound on the confidence set size in

Proof of the lower bound of Theorem
1.1
.

The proof follows from the following three claims:

i)

For all

connects to

).

4.
Embedded root finding in a thin 2D strip

We now consider the setting of random nearest neighbor trees evolving on a thin two-dimensional strip with a height of
h_{\varepsilon}=\text{poly}(\varepsilon)
. This highlights generalizations of the one-dimensional setting as well as potential limitations we encounter in moving to the higher-dimensional setting.
The following result shows that the bounds from the

Corollary 4.1
.

The following holds for
\varepsilon>0

2
-NN model on a thin torus

. If

1-\varepsilon
. Additionally, if
h_{\varepsilon}=O\left({\log^{-1}(1/\varepsilon)}\right)
, it is information-theoretically impossible to provide a confidence set whose size satisfies
|H(\varepsilon,n)|=\Omega\left(\frac{\log(1/\varepsilon)}{\log\log(1/\varepsilon)}\right)
.

4.1.
Upper bound on the confidence set size

5.
Embedded root finding in higher dimensions

We now consider
d\geq 2
, proving the bounds in Theorem
1.2
. First, note that similarly to
d=1
, with high probability there exists a long edge that arrives early on in the process. Therefore, long edges provide useful information for finding the root. Additionally, a notion of
uncovered
vertices can be defined here. Similarly to how in
d=1
an edge blocks off a region of space within which no vertex can be the root, in
d=2
we also have such “covered” regions induced by edges. However, the definition is more involved, since the area can in some sense expand as more vertices connect to it.

Edges that wrap around the torus are dotted. The simulations indicate that the number of uncovered vertices in the tree grows slowly with the number of vertices in the tree.

In this section, we first give a formal definition of uncovered and covered vertices in
d\geq 2
and present a structural lemma about the maximum outdegree in the subtree of uncovered vertices. Then, we present an algorithm (Algorithm
4
) that proves the upper bound in Theorem
1.2
. This algorithm first does a processing pass to identify uncovered vertices, then uses long edges to build the confidence set
H(\varepsilon,n)
. More precisely, the confidence set consists of uncovered vertices within a certain graph distance of a long edge. Finally, we present a lower-bound construction. Similarly to the lower-bound constructions for the one-dimensional torus and the thin two-dimensional strip, the lower-bound construction for
d\geq 2
is a path. We can argue that every permutation of the labels yields a valid nearest neighbor tree. We then argue that the root vertex has a lower posterior probability than all but the last vertex added.

Following, for any
\ell<1/2
, we let
C(d)
be the constant that depends on
d
such that the
d
-dimensional ball of radius
\ell
has volume
C(d)\cdot\ell^{d}
.

5.1.
Structural information

In
d\geq 2
, we can extend the notion of “uncovered” and “covered” vertices and edges.

Definition 5.1

(Uncovered vertex and edge)
.

For each edge
(p_{1},p_{2})
in the graph, if a vertex
x
with parent
p_{1}
lands in the region such that
d(x,p_{1})<d(p_{1},p_{2})\text{ and }d(x,p_{2})<d(p_{1},p_{2})
, a direction can be assigned to the edge
(x,p_{1})
. Particularly, orient the edge from
x
to
p_{1}
to indicate that the arrival time of
p_{1}
must be earlier than that of
x
. We can similarly orient all of the vertices in the subtree of
x
. We consider
x
and its subtree
covered
. Denote by
\mathcal{C}_{n}=[n]\setminus\mathcal{U}_{n}
the set of covered vertices.

A vertex is called
uncovered
if it is not a covered vertex. An edge is called
uncovered
if both of its endpoints are uncovered vertices.

We will consider an algorithm that first does a pass to identify covered vertices and direct their associated edges, then uses long edges to build a confidence set
H(\varepsilon,n)
. This algorithm will rely on several crucial structural components of the random nearest neighbor graph. First, the graph of uncovered vertices has bounded degree. Second, with high probability, one of the first
k\approx\log(1/\varepsilon)
edges added is long. Third, with high probability, the earlier vertex adjacent to this edge is a graph distance at most
7\log(k)
away from the root.

We begin with a structural lemma that bounds the degree of any vertex in the induced subgraph of the uncovered vertices.

Lemma 5.1
.

There exists some
a>0
such that the following holds for all
d\in\mathbf{N}
.
The induced subgraph of the uncovered vertices
\mathcal{U}_{n}\subset[n]
forms a tree of maximum degree
a^{d}
.

Proof.

First, note that the induced subgraph of the uncovered vertices is connected, i.e. it forms a tree. This follows from the definition of covered and uncovered: if a vertex is uncovered, there must exist a path from this vertex to the root along only uncovered edges. This applies to all uncovered vertices, yielding connectivity.

Next, let
\deg_{\mathcal{U}_{n}}(v)
denote the degree of
v\in\mathcal{U}_{n}
in the induced subgraph of uncovered vertices. We seek to upper-bound the number of uncovered vertices adjacent to
v
. Consider any pair of uncovered edges
e=(u,v)
and
e^{\prime}=(u^{\prime},v)
, where the arrival time of
u
is later than that of
u^{\prime}
or
v
. For
u
to connect to
v
rather than
u^{\prime}
, we must have
d(u,v)\leq d(u,u^{\prime})
. For both
u
and
u^{\prime}
to be uncovered,
u
cannot lie in the “forbidden” region of
e^{\prime}
, therefore we must have
d(u^{\prime},v)\leq d(u,u^{\prime})
or
d(u^{\prime},v)\leq d(u,v)
.

Therefore, the three points
v
,
u
, and
u^{\prime}
form a triangle with longest side length
d(u,u^{\prime})
. The angle between
e
and
e^{\prime}
is opposite the longest edge, and thus must be at least
\pi/3
. Therefore, the uncovered degree of any
v\in\mathcal{U}_{n}
is upper bounded by the maximum number of vectors with pairwise angle at least
\pi/3
:

\displaystyle\deg_{\mathcal{U}_{n}}(v)

\displaystyle\leq\max\left\{k:X_{1},\dots,X_{k}\in[-1,1]^{d}:\frac{\langle X_{i},X_{j}\rangle}{\lVert X_{i}\rVert\cdot\lVert X_{j}\rVert}\leq\cos(\pi/3)~~\forall i,j\in[k]\right\}

(12)

\displaystyle=\max\left\{k:Z_{1},\dots,Z_{n}\in S^{d-1}:\langle Z_{i},Z_{j}\rangle\leq\cos(\pi/3)~~\forall i,j\in[k]\right\},

where
S^{d-1}
is the unit ball in dimension
d
. For all
d\geq 1
, the number of unit vectors of maximum inner product
\cos(\pi/3)
is less than
a^{d}
for some constant
a>0
, concluding the proof of the lemma.
∎

Remark 2
.

Note that in
d=1
, we have
\deg_{\mathcal{U}_{n}}(v)\leq 2
: the uncovered tree is in fact a path. In
d=2
,
\deg_{\mathcal{U}_{n}}(v)\leq 5
almost surely (the event of any pairwise angle being exactly
\pi/3
is measure 0).

5.2.
Upper bound on the confidence set size

We are now ready to describe the algorithm for returning a confidence set satisfying property (
2
). The algorithm consists of the following two steps.

Algorithm 4
.

Let
d\geq 2
and
0<\varepsilon<1/2
.

Step 1: Assigning edge directions.
For an edge
e=(p_{1},p_{2})
, denote its
forbidden region
to be
F(e)\coloneqq\{x\in[0,1]^{d}:d(x,p_{1})<d(p_{1},p_{2})\text{ and }d(x,p_{2})<d(p_{1},p_{2})\}\subset\mathbf{T}^{d}
. For

, for each neighbor

of

, if

then
x
is covered: direct the edge
(x,x_{i})
to point towards
x_{i}
, and accordingly direct each other vertex

in the subtree

of
x
(which can be determined since
(x,x_{i})
is directed); assign

for each

. Repeat for each remaining uncovered edge until all edges are processed, and all vertices are labeled either covered (
\in\mathcal{C}_{n}
) or uncovered (
\in\mathcal{U}_{n}
).

Step 2: Building the confidence set.
Consider an edge length cutoff
\ell
and expansion radius
k
. Let
a>0
be the constant from Lemma
5.1
. Let
\gamma=(d\log(a)\cdot\log\log(1/\varepsilon))^{-1}

and set

(13)

k=\gamma\log(1/\varepsilon)\ \text{ and }\ \ell=\left({C(d)\cdot\gamma\cdot e^{1/\gamma}\cdot\log(1/\varepsilon)}\right)^{-1/d},

where
C(d)
is the volume of the unit ball in
\mathbf{T}^{d}
. Return the set of uncovered vertices that are within graph distance
k
of either endpoint of an edge of length greater than
\ell
.

Remark 3
.

Note that if an edge is covered, it is directed, and therefore there is a fixed direction to walk until either an uncovered edge is hit, or
k
steps are taken. On the other hand, if we are at an uncovered edge, each endpoint can be adjacent to at most
a^{d}
uncovered edges, and the exploration therefore grows in at most

We prove that the confidence set size required by Algorithm

satisfies the requirements on the confidence size specified by the upper bound in Theorem

, and additionally that Algorithm

Lemma 5.2
.

First, for any fixed

, there exists an
\varepsilon_{d}>0
such that for all
\varepsilon<\varepsilon_{d}
, the set

returned by Algorithm

|H(\varepsilon,n)|\leq\exp\left(\frac{\log(1/\varepsilon)}{\log\log(1/\varepsilon)}+d\log\log(1/\varepsilon)\right).

Second, Algorithm
4
returns a confidence set containing the root with probability at least
1-\varepsilon

and

.

Proof.

Correctness.
First, observe that if any of the first
k
edges are long (length
\geq\ell
), then the algorithm successfully includes the root vertex in
H(\varepsilon,n)
. The error probability is therefore bounded above by the probability that all first
k
edges are short:

(15)

\mathbf{P}\{1\not\in H(\varepsilon,n)\}\leq\prod_{i=1}^{k}\left(i\cdot C(d)\ell^{d}\right)\leq(kC(d)\ell^{d})^{k}.

With
k
and
\ell
set according to (
13
), we have

\mathbf{P}\{1\not\in H(\varepsilon,n)\}\leq\left(\frac{C(d)\gamma\log(1/\varepsilon)}{C(d)\cdot\gamma\cdot e^{1/\gamma}\cdot\log(1/\varepsilon)}\right)^{\gamma\log(1/\varepsilon)}=e^{-\log(1/\varepsilon)}=\varepsilon.

confidence set size.
Given this setting of
k
and
\ell
, we now analyze the size
|H(\varepsilon,n)|
of the confidence set returned by the algorithm. For each endpoint of a long edge, the algorithm adds up to
a^{dk}
other vertices to the confidence set, because by Lemma
5.1
, the induced subgraph of uncovered vertices has bounded degree. Additionally, as noted in the proof of Lemma
2.1
, the number of long edges is at most
(2/\ell)^{d}
. Therefore, the size of the confidence set returned is at most

(16)

|H(\varepsilon,n)|\leq(a)^{kd}2^{d+1}/\ell^{d}=\left(1/\varepsilon\right)^{\gamma d\log(a)}\cdot 2^{d+1}\cdot C(d)\cdot\gamma\cdot e^{1/\gamma}\cdot\log(1/\varepsilon),

and taking
\gamma=(d\log(a)\cdot\log\log(1/\varepsilon))^{-1}
yields

|H(\varepsilon,n)|\leq\exp\left(\frac{\log(1/\varepsilon)}{\log\log(1/\varepsilon)}+(d\log(a)+1-o(1))\log\log(1/\varepsilon)\right)\frac{2^{d+1}C(d)}{d\log(a)}.

There exists a universal constant

such that for any fixed

. We therefore achieve the expression in (

Runtime.
In the first step of the algorithm, we mark all vertices as covered or uncovered. This relies on searching among neighbors and updating labels of descendants, which uses
O(n^{2})
time.

In the second step of the algorithm, the confidence set is built by having each vertex adjacent to an edge of length greater than
\ell
return uncovered vertices within a radius

, where
\ell
and
k
are defined with respect to
\varepsilon
and

(as in (

\leq k
away from this long edge is at most

which, by the setting of

, is
\left({1}/{\varepsilon}\right)^{\frac{1}{\log\log(1/\varepsilon)}}
. Therefore, Step 2 takes at most

Let

be the family of trees that can be generated by this procedure. We begin with the following claim about
\mathcal{F}
.

Claim 3
.

For all trees in
\mathcal{F}
, for all
t\in\{1,2,\dots,K(\varepsilon)+1\}
,
x_{t+1}
connects to
x_{t}
.

Proof.

By construction, for any
x_{t+1}
for
t\in\{1,2,\dots,K(\varepsilon)+1\}
,
x_{t+1}=x_{t}+w_{t}
, where
w_{t}
is a vector with only positive entries. Specifically, the
i_{t}
-th entry of
w_{t}
satisfies
\frac{1}{4K(\varepsilon)+4}<w_{t}(i_{t})<\frac{1}{2K(\varepsilon)+2}
and the rest of the entries
j
satisfy
0<w_{t}(j)<\frac{1}{4K(\varepsilon)+4}
. Inductively, for
t\geq 3
,
x_{t+1}=x_{t-i}+\sum_{k=t-i}^{t}w_{k}
.

We want to argue that
x_{t+1}
is closer
x_{t}
than any
x_{t-i}
. Observe that:

d(x_{t+1},x_{t})=d(0,w_{t})~~\text{ and }~~d(x_{t+1},x_{t-i})=d\left(0,\sum_{k=t-i}^{t}w_{k}\right).

Since for any
t
, any
i\leq t-1
, and any coordinate
j\in[d]
, we have
\sum_{k=t-i}^{t}w_{k}(j)<\frac{K(\varepsilon)+1}{2K(\varepsilon)+2}=\frac{1}{2}
, we can use the definition of the torus Euclidean distance (
1
) to find that

d(x_{t+1},x_{t})=\lVert w_{t}\rVert_{2}~~\text{ and }d(x_{t+1},x_{t-i})>\lVert w_{t}\rVert_{2},

where
\lVert\cdot\rVert_{2}
denotes the
\ell_{2}
norm of a vector. Therefore, by definition of the random nearest neighbor process,
x_{t+1}
will connect to
x_{t}
.
∎

Claim 4
.

The family
\mathcal{F}
of tree configurations occurs with probability at least
\varepsilon
when

(18)

d^{K(\varepsilon)+1}\cdot\left(4K(\varepsilon)+4\right)^{-d(K(\varepsilon)+1)}\geq\varepsilon.

Proof.

In the family
\mathcal{F}
of tree configurations considered, we impose conditions on the positions of all but the first vertex. After specifying the
string
\left(i_{1},i_{2},\dots,i_{K(\varepsilon)+1}\right)\in[d]^{K(\varepsilon)+1}
that determines the directions we move in at each time step to construct a tree, and once
x_{1}
is placed in the space (it is allowed to fall anywhere), each of the later vertices is required to fall in its own specific cube of side length
r={1}/({4K(\varepsilon)+4})
, which has volume
\left(4K(\varepsilon)+4\right)^{-d}
. Therefore, once the string is chosen, the probability of such a tree configuration is
\left(4K(\varepsilon)+4\right)^{-d(K(\varepsilon)+1)}
.

Note that there are
d^{K(\varepsilon)+1}
different strings that can be chosen. Therefore, when (
18
) holds, the family of tree configurations occurs with probability at least
\varepsilon
.
∎

Claim 5
.

The posterior probability of the root vertex
x_{1}
is lower than that of
x_{t}
for
t\in\{2,3,\dots,K(\varepsilon)+1\}
.

Proof.

This proof follows in the exact same manner as for the lower bounds over the one-dimensional torus and the thin strip. Let a feasible permutation of the arrival times be an assignment of arrival times to vertices in the unlabeled tree that is realizable by the random nearest neighbor process given the geometric positions of vertices and the edges between them.

Note that, given the positions of vertices and the graph structure of a tree from the family considered, the only feasible permutation
\sigma
such that
\sigma(1)=1
is the identity permutation where each
\sigma(i)=i
; else, feasibility is violated. For any other
i
, the feasible permutations such that
\sigma(i)=1
are the permutations satisfying
\sigma(i)<\sigma(i+1)<\sigma(i+2)<\dots<\sigma(K(\varepsilon)+2)
and
\sigma(i)<\sigma(i-1)<\sigma(i-2)<\dots<\sigma(1)
(because, again, otherwise feasibility is violated). All feasible permutations are equally likely given the tree configuration, by the definition of the process. Therefore, for each tree in the family considered, there are at least
K(\varepsilon)
other vertices that have a higher posterior probability than the root.
∎

This last claim implies that when
K(\varepsilon)
satisfies (
18
), the optimal procedure which returns the
K(\varepsilon)
vertices with the highest posterior probabilities fails to return the root.

6.
Conclusion and open questions

In this paper, we studied the problem of finding the root of a tree generated by the random nearest neighbor process over the
d
-dimensional unit torus
\mathbf{T}^{d}
. A root finding algorithm must return a confidence set that includes the root with probability
1-\varepsilon
. In the setting where an algorithm is given access to the unlabeled tree and its embedding (which we call the
embedded root finding
problem), when
d=1
we prove that the size of the confidence set is
\Theta\left(\frac{\log(1/\varepsilon)}{\log\log(1/\varepsilon)}\right)
. For fixed
d\geq 2
, the confidence set size is uniformly bounded in terms of
\varepsilon
and
d
, and our upper bounds are sub-polynomial in
1/\varepsilon
. The difference in the bounds for the setting of
d=1
versus
d\geq 2
leads to the following open question.

Question 1.

For the
d
-NN model with
d\in\mathbf{N}
, does there exist a poly
(n,1/\varepsilon)
-time root finding algorithm that returns a set of size
|H(\varepsilon,n)|\leq\log^{d}(1/\varepsilon)
for all
n\in\mathbf{N}
?

Key to our bounds is the notion of
uncovered vertices
, whose induced subgraph has bounded degree and must contain the root. We believe that a strengthened understanding and analysis of the induced subgraph of uncovered vertices can be useful in obtaining the conjectured set size. We propose the following conjectures regarding uncovered vertices, which may or may not suffice for resolving the conjecture above.

Bounds on uncovered vertices.
Our algorithms in both the one-dimensional and higher-dimensional settings rely on uncovered vertices (see Definitions
3.1
and
5.1
). In the higher-dimensional setting, we use that the outdegree of any uncovered vertex in the uncovered subtree is at most
a^{d}
for some constant
a>0
. However, we believe there are more properties of uncovered vertices that can be explored and utilized. Particularly we pose the following questions.

Question 2.

For a tree
T_{n}
and fixed dimension
d\in\mathbf{N}
, let
\mathcal{U}_{n}
be the set of uncovered vertices (as in Definition
5.1
). Is
\mathbf{E}|\mathcal{U}_{n}|=O(\text{poly}\log n)
? Additionally, for random nearest neighbor trees, is
|\mathcal{U}_{n}|=O(\text{poly}\log n)
with probability at least
1-1/n
?

Question 3.

More strongly, for fixed dimension
d\in\mathbf{N}
, consider any set
S=\{x_{1},x_{2},\dots,x_{n}\}\subset\mathbf{T}^{d}
. Let
\Sigma=\{\sigma\}
be the set of all permutations
\sigma:[n]\to[n]
. For a permutation
\sigma
, let
T_{n}(S,\sigma)
be the nearest neighbor tree corresponding to
\{x_{\sigma(i)}\}_{i\in[n]}
. Let
\mathcal{U}_{n}(T_{n}(S,\sigma))
be the set of uncovered vertices in
T_{n}(S,\sigma)
.
Is it true that, for any set
S
,
\mathbf{E}_{\sigma}|\mathcal{U}_{n}(T_{n}(S,\sigma))|=O(\text{poly}\log n)
?

In the new direction of network archaeology for randomly growing graph processes in geometric settings, there are many interesting open questions to be explored. We highlight several of these below.

Root finding without geometric information.
The algorithms in our paper crucially utilize the geometry of the tree, particularly the lengths of edges and the notion of regions in the space that edges can “cover” (see Definitions
3.1
and
5.1
). It is open to explore the question of root finding without geometric information; that is,
graph root finding
as defined in Definition
1.1
. Algorithms would need to rely on combinatorial properties, e.g. centrality measures as studied in
[
BDL17
]
, or other properties explored in
[
LM24
]
.

Improving the confidence set size when the dimension is large.
The upper-bounds on the confidence set size match those for uniform attachment trees when the dimension
d
is treated as a constant. However, as
d\to\infty
, the random nearest neighbor process behaves as a uniform attachment process because each new vertex is roughly the same distance away from each existing vertex. Removing the dependence on
d
in high dimensions to achieve the uniform attachment bound as
d\to\infty
remains open.

Network archaeology beyond root finding.
One can study other properties of the history of the tree, such as the times of arrival of all vertices. One can also ask to return a confidence set including a vertex added late in the process.
