AraMix: Recycling, Refiltering, and Deduplicating to Deliver the Largest Arabic Pretraining Corpus
Sultan Alrashed, Francesco Orabona

Abstract
We present AraMix 1 1 1 https://huggingface.co/datasets/AdaMLLab/AraMix , a deduplicated Arabic pretraining corpus containing approximately 178 billion tokens across 179 million documents. Rather than scraping the web again, AraMix demonstrates that substantial value lies in systematically reusing and curating existing pretraining datasets: we combine seven publicly available Arabic web datasets, apply quality filtering designed specifically for Arabic text to re-filter some datasets, and perform cross-dataset deduplication, both MinHash and sentence-level. This approach reveals that nearly 60% of tokens across these independently collected corpora are duplicates, redundancy that any new scraping efforts will reproduce. Our work suggests that for lower resource languages, investment in curation pipelines for existing data yields greater returns than additional web crawls, an approach that allowed us to curate the largest heavily filtered publicly available Arabic pretraining corpus.

Introduction

Building pretraining corpora through web scraping requires substantial computational resources, storage infrastructure, and engineering effort. For languages beyond English, multiple research groups have independently undertaken this expensive process, producing overlapping datasets that duplicate both the crawling work and the crawled content itself. This redundancy represents a significant inefficiency: resources spent re-scraping the same web pages could instead be used to improve data quality through better filtering and deduplication.

Related Work

Arabic Pretraining Corpora.

Several large-scale Arabic pretraining corpora have been released in recent years. ArabicWeb24 scraped Arabic web content directly, producing 40 billion tokens after language identification and basic filtering. The 101 Billion Arabic Words dataset aggregated news, Wikipedia, and web sources. CulturaX and HPLT 2.0 extracted Arabic subsets from Common Crawl using multilingual pipelines, while FineWeb-2 extended FineWeb’s
10
filtering approach to non-English languages. These corpora were created independently, each project investing resources in crawling and filtering without knowledge of what others had already collected. Our AraMix dataset takes a different approach: Rather than scraping again, we combine all seven existing corpora and measure their overlap, finding that 60% of tokens are redundant across sources.

Corpus Aggregation and Deduplication.

Prior work has combined and deduplicated existing corpora, though typically within narrower scope. CulturaX merged mC4 and OSCAR with additional cleaning but did not measure cross-source redundancy. SlimPajama
15
applied MinHash deduplication to RedPajama, removing 49% of content, demonstrating substantial within-corpus duplication. The FineWeb effort
10
analyzed overlap between their corpus and RefinedWeb
12
, finding significant shared content from Common Crawl’s upstream data.
16
showed that deduplication combined with diversity-based selection improves training efficiency by 20%. All these efforts focus on English corpora or single-source deduplication. AraMix extends cross-dataset deduplication to seven independently collected Arabic corpora, quantifying pairwise overlaps and identifying content that appears in four or more sources.

Language-Specific Quality Filtering.

Quality filters developed for English corpora perform poorly on morphologically rich or non-Latin-script languages. C4’s pipeline rejects lines not ending in English terminal punctuation, filtering out most Arabic text. The Gopher filters require English stop words, rejecting Arabic documents entirely. CCNet addressed multilingual extraction using perplexity-based filtering against Wikipedia language models, enabling corpus construction for over 100 languages without language-specific rules. FineWeb-2 adapted thresholds for non-English text but retained structurally English-centric heuristics. Work on Arabic-specific NLP tools
2
;
9
has focused on downstream tasks rather than pretraining corpus construction. AraMix introduces filters designed for Arabic text characteristics: accepting documents with zero terminal punctuation (common in Arabic web text), using Arabic punctuation characters for line-level filtering, and tuning repetition thresholds for Arabic’s orthographic patterns.

Standard quality filters designed for English corpora perform poorly on Arabic text. C4’s line-ending filter uses hardcoded English punctuation (

Deduplication

5.1
MinHash Deduplication

We apply MinHash Locality-Sensitive Hashing (LSH) for near-duplicate detection with the following parameters:

•

N-grams
: 5-character shingles

•

Buckets
: 14 bands

•

Hashes per bucket
: 8

The LSH bucketing phase identified 1.52 billion candidate pairs, which were clustered into duplicate groups. This identified 227 million duplicate pairs, marking 152.9 million documents for removal (46.1% of filtered documents). The high deduplication rate reflects substantial overlap between source datasets, as web crawls from different projects often index the same content.

5.3
Sentence-Level Deduplication

After MinHash deduplication, we apply sentence-level deduplication to remove repeated boilerplate passages that appear across documents. While MinHash catches near-duplicate documents, it misses cases where documents share copied paragraphs but differ sufficiently overall to avoid detection.

We hash consecutive 3-sentence spans and count their occurrences across the corpus. Spans appearing 3 or more times are marked as duplicates. For each document, we remove all sentences belonging to duplicate spans, then discard documents left with fewer than 50 words. The algorithm proceeds in two phases:

1.

Signature computation
: For each document, extract sentences using Arabic and Latin punctuation delimiters. Filter to sentences with at least 5 words. Compute MD5 hashes of consecutive 3-sentence spans and store counts in a disk-based SQLite database.

2.

Filtering
: Re-scan documents, removing sentences belonging to spans that appeared 3+ times. Documents reduced below 50 words are discarded entirely.

•

Span size
: 3 consecutive sentences

•

Minimum sentence length
: 5 words

•

Minimum duplicate count
: 3 occurrences

•

Minimum document length after filtering
: 50 words

The 3-sentence span balances precision and recall: Shorter spans would over-match common phrases, while longer spans would miss partial duplicates. The threshold of 3 occurrences avoids removing legitimately repeated content (e.g., standard greetings) while catching true boilerplate.

6
Conclusion

AraMix provides a large-scale, quality-filtered Arabic pretraining corpus. By adapting filtering approaches to Arabic text characteristics and applying deduplication across multiple sources, we produce a corpus suitable for training Arabic language models. We suggest that there is more value to be had in curation pipelines for existing data and data extraction from novel sources instead of scraping Common Crawl, again.
