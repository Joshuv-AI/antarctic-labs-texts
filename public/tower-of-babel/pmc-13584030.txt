Protocol for mapping frequency-specific information transfer between cortical areas using ECoG and Granger causality
Authors: Xiangsheng Zeng, Tao Zhou, Chengpeng Li, Isao Hasegawa, Hisashi Tanigawa
Published: 2026

ABSTRACT
SummaryThis protocol details the application of Granger causality (GC) analysis to primate electrocorticography (ECoG) data to map frequency-specific information transfer. We describe steps for computing pairwise GC and generating spatial GC maps, including differential maps to isolate task-specific activity. We then explain how to perform hierarchical clustering on GC patterns to identify and visualize the spatial distribution of functional electrode clusters, revealing the organization of information flow.For complete details on the use and execution of this protocol, please refer to Zhou et al.1

Before you begin

In modern neuroscience, higher cognitive functions are widely understood to be realized not by the activity of single, isolated brain areas, but by large-scale networks in which multiple, anatomically distant regions cooperate.2,3 A central challenge in this network science paradigm is to elucidate how active brain regions interact and exchange information. Neural oscillations, the rhythmic fluctuations in the activity of neuronal populations, are considered a fundamental mechanism for enabling this inter-areal communication.4,5 Different frequency bands of these oscillations have been linked to distinct cognitive functions. Granger causality (GC) analysis is a powerful statistical method for revealing the directionality of this information transfer via neural oscillations.6 In particular, spectral GC analysis, which evaluates GC in the frequency domain, makes it possible to quantify which brain region influences another, via which frequency band, making it an indispensable tool for deciphering brain communication protocols.7,8

Pioneering studies using spectral GC analysis have revealed general principles of information transfer within the cortical hierarchy. For instance, the “frequency channel hypothesis” proposes that feedforward information is carried by gamma-band oscillations, while feedback information is carried by beta-band oscillations.9 However, many of these foundational studies have treated vast cortical areas, such as the primary visual cortex (V1) or prefrontal cortex (PFC), as single, homogeneous nodes (Regions of Interest; ROIs) in a network. This ROI-based approach has a significant limitation: it overlooks the potential for functional heterogeneity and the spatial organization of information flow within a given cortical area. Recent human ECoG work has profoundly underscored the importance of spatial resolution, demonstrating that spatially distributed category-selective neural responses carry crucial behaviorally relevant information.10 To facilitate investigations at this granular level, the present protocol provides a reproducible and well-documented implementation of electrode-wise spatial GC mapping and clustering, building upon our previous work.1 By leveraging high-density electrocorticography (ECoG) recordings, this workflow maps the intensity distribution of information flow directly onto the cortical surface by calculating GC for all electrode pairs between areas, rather than averaging signals within an ROI.1 This shifts the analytical paradigm from “ROI-to-ROI” to “spatial mapping of information flow on the cortical surface,” opening the door to identifying the functional hubs and clusters involved in information transfer.

This protocol provides a complete analysis pipeline to implement this spatial mapping approach. First, it calculates GC for all electrode pairs from high-density ECoG data for each time point and frequency bin. Next, it uses these results to create a “GC map” that visualizes the average information flow strength at each electrode on the cortical surface in a specific frequency band and generates a task-specific “differential GC map” by subtracting the results from a control task. Finally, as a core component of this approach, it applies “hierarchical clustering” to the resulting differential GC communication patterns. This step objectively identifies groups of electrodes with similar information transfer characteristics, thereby revealing the spatial organization of functional hubs (nodes) within a cortical area. As a concrete example, this manuscript demonstrates the application of this analysis pipeline to the network between the prefrontal cortex (PFC) and inferior temporal cortex (ITC) in macaque monkeys performing an associative memory task that requires memory retrieval and working memory.1

Innovation statement

This protocol presents an integrated, fully reproducible end-to-end workflow for electrode-level spatial Granger causality (GC) mapping and hierarchical clustering analysis based on high-density ECoG recordings. This standardized pipeline is built upon the spectral GC framework established in our previous work,1 with unified, well-documented MATLAB scripts publicly deposited on Zenodo to guarantee full replicability across datasets.

The primary innovation of this protocol is not the introduction of a new causal inference estimator or a novel biological discovery. Rather, our contribution lies in providing a fully integrated, transparent, and reproducible workflow specifically engineered for electrode-level spatial GC mapping and subsequent functional clustering. By standardizing the pipeline—from data pre-processing and spectral factorization to topographical visualization and non-parametric statistical mapping—this protocol bridges the gap between abstract connectivity algorithms and anatomically grounded network analysis, enabling researchers to systematically and reliably map frequency-specific information transfer across the cortical surface.

Data collection

While the analysis methods in this protocol are, in principle, broadly applicable to any multichannel electrophysiological time series data containing neural oscillations, fulfilling the following two requirements is necessary to execute all steps of the spatial mapping and clustering analysis detailed herein. First, because this protocol aims to calculate information flow between two groups of channels (e.g., two brain areas), the signals must be obtained from those two distinct channel groups. Second, to perform the spatial mapping of information flow and the subsequent cluster analysis that are central to this protocol, the electrodes within each channel group must have a known spatial arrangement (e.g., a 2D map like an ECoG grid).

The sample data used in this protocol are local field potentials (LFPs) recorded from ECoG electrodes implanted on the cortical surface of a Japanese macaque monkey (Macaca fuscata; a 7-year-old female weighing 5.6 kg was used for the sample dataset). Specifically, we use data from the prefrontal cortex (PFC) with 64 channels (8 × 8 grid) and the inferior temporal cortex (ITC) with 128 channels (8 × 16 grid), with an electrode spacing of 2.5 mm.

To extract task-specific information flow as a “differential GC map”, this protocol requires datasets from at least two different cognitive states for comparison. The sample data uses recordings from the following two tasks.

Picture-color association task

The memory task. After a picture image is presented as a cue stimulus, following a delay period, the monkey must release a lever when a choice stimulus of a specific color, which it has learned to associate with the cue, is displayed. This task requires information retrieval from long-term memory and its maintenance in working memory.

Picture passive viewing task

The control task. The pictures used as cue stimuli in the PCA task are presented, but after the delay period, the monkey is rewarded simply for releasing the lever when a fixation point dims. This task does not require memory retrieval or maintenance.Note: For the purpose of demonstrating this protocol, we utilize a dataset from a single recording session (one day). After preprocessing, the sample dataset contains 631 trials for the PCA task and 579 trials for the PPV task. These trial counts are highly comparable in magnitude, ensuring well-balanced and unbiased non-parametric statistical comparisons without the need for artificial downsampling. In the sample data, which is already formatted as a FieldTrip-compatible data structure, all of the following preprocessing steps were applied, consistent with our previous research1; however, in actual application of this protocol, users should carefully examine the applicability of each step according to their own objectives. For transparency, the custom FieldTrip-based MATLAB scripts used to pre-process the provided sample dataset are included in the ‘custom/preprocessing’ folder of our repository. Note: In the sample data, a time window from 4.5 s before to 5.0 s after stimulus onset was used. 2.Apply filters.a.Apply a band-pass filter to the segmented data to encompass the frequency range of interest.b.Determine the specific filtering range to encompass signal characteristics and the specific frequency bands under investigation. Note: In the sample data, a band-pass filter of 0.7–250 Hz was applied. 3.Downsample data.a.Resample the data to a lower sampling frequency (e.g., 500 Hz) to reduce computational load while preserving the frequencies of interest (Nyquist theorem). Note: In the sample data, the data was downsampled to 500 Hz after filtering. 4.Reduce noise and artifacts.a.Perform Independent Component Analysis (ICA) on the filtered data to identify non-physiological artifacts.b.Inspect independent components for signatures of noise, such as line noise, eye movements, or localized electrode malfunctions.c.Remove components identified as noise and reconstruct the signals from the remaining components. Note: In the sample data, ICA was performed using the ‘ft_componentanalysis’ function in FieldTrip with the ‘runica’ algorithm (default), decomposing the data into the same number of components as electrodes. We utilized ‘ft_rejectvisual’ to inspect component metrics (e.g., variance) and identify candidates. Selected noise components (typically 3–4 components exhibiting unnatural zero-lag responses or single-electrode localization) were verified by examining their spatial distribution and time-frequency representations, and then removed using ‘ft_rejectcomponent’. For a more detailed description, refer to our previous research.1 5.Re-reference data.a.Calculate the average signal across all valid electrodes within each specific electrode array (e.g., within each 32-channel connector/grid).b.Subtract this common average from each electrode on the corresponding array to eliminate global noise and array-specific fluctuations. Note: In the sample data, this “Segmented Common Average Referencing (CAR)” was applied to minimize global noise and array-specific fluctuations (e.g., impedance differences between connector banks). This step is distinct from the subsequent source derivation and serves as an initial global noise reduction step. 6.Enhance spatial resolution and mitigate volume conduction.a.Apply orthogonal source derivation by subtracting the average potential of spatially adjacent neighbors (up, down, left, right) from each electrode. CRITICAL: This method, also known as the surface Laplacian, acts as a spatial high-pass filter. Accurately define neighbouring electrodes based on the precise physical grid geometry (e.g., a center-to-center distance of 2.5 mm in our sample). Electrodes at the edges of the grid (lacking a full set of neighbours) may require specific handling or exclusion depending on the implementation (e.g., using 3 neighbours or excluding from analysis). Properly executing this procedure is essential to eliminate the effects of broad-scale volume conduction, highlight local neural activity directly beneath each electrode, and improve spatial resolution, thereby enabling high-precision analysis of information flow between cortical areas.12,13 7.Extract induced neural oscillations.a.Calculate the overall event-related potential (ERP) by averaging signals across all successful trials.b.Subtract this overall ERP from the signal of each individual trial. CRITICAL: This procedure removes the “evoked” potential (e.g., phase-locked to the stimulus) to isolate “induced” oscillations (internally generated, non-phase-locked rhythms).14 It is critical to isolate induced activity before performing Granger causality analysis, as it ensures that the measured connectivity reflects intrinsic neural communication dynamics rather than spurious correlations driven by a common external stimulus transient.15

Time-frequency analysis and pairwise Granger causality calculation

Timing: ∼2.5 h per condition (PCA or PPV) for the sample dataset (varies with data size)

Timing: ∼2.5 h per condition (PCA or PPV) for the sample dataset (varies with data size)

This step calculates the spectral Granger causality (GC) between two defined neuronal populations (e.g., ITC and PFC) by transforming the pre-processed time-domain signals into the time-frequency domain with a Continuous Wavelet Transform (CWT) and computing pairwise non-parametric GC between all electrode pairs. The MATLAB script ‘P1_GC_pw_calc.m’ automates this pipeline and generates the ‘gdata’ structure that serves as the input for all subsequent analyses.Note: All timing estimates in this protocol are based on a desktop PC running Windows 10 with an Intel Xeon E5-1620 v4 (4 cores) and 64 GB RAM.

Note: All timing estimates in this protocol are based on a desktop PC running Windows 10 with an Intel Xeon E5-1620 v4 (4 cores) and 64 GB RAM.

The pipeline will automatically perform the following operations based on your configuration:i.Data Loading: Loads the pre-processed ‘trldata’ structure into the workspace.ii.Wavelet Transform (PART A): Applies a Continuous Wavelet Transform (CWT) utilizing the MATLAB built-in ‘cwt’ function to generate spectral data.Note: To optimize memory usage for recordings with a very large number of channels, the script computes and saves spectral data differently for the two groups. For Group A, data is computed and saved channel-by-channel (e.g., cwt_ITC1_red.mat). These filenames are automatically generated based on the defined group name, channel number, and experimental condition (e.g., ‘cwt_[GroupName][ChannelNumber]_[Condition].mat’). For Group B, data is computed and saved as a single block. These intermediate spectral data files are automatically saved in a generated directory structure: fullfile(ecog0path, analyname, ‘GC_Analysis’, ‘cwt_data’, postfix).iii.GC Calculation (PART B): Iterates through all channel pairs between Group A and Group B and calls the FieldTrip toolbox’s connectivity algorithm (‘ft_connectivity_granger’) to compute bidirectional spectral GC.Note: During the GC computation, the script loads Group B data into memory as a single block, while Group A data is loaded sequentially (see troubleshooting 1). This design balances memory optimization with computational speed by minimizing disk I/O operations. The resulting pairwise GC data is saved as individual.mat files. To ensure analytical rigor and reproducibility, the script not only saves the computed GC results but also encapsulates the current step’s parameter configurations and the metadata from previous pre-processing steps (utilizing FieldTrip’s provenance tracking) within the output data structure (gdata.cfg). These filenames are automatically generated based on the source group, source channel, target group, target channel range, and condition (e.g., ‘GC_pw_[GrpAName][ChanA][GrpBName][ChanB_start][ChanB_end]_[Condition].mat’, such as ‘GC_pw_ITC1_PFC129_192_red.mat’). These files are automatically saved in a generated directory structure: fullfile(ecog0path, analyname, ‘GC_Analysis’, ‘pairwise_GC’, postfix).Note: This protocol utilizes non-parametric spectral Granger causality. Unlike parametric methods (e.g., MVAR models) that require model order selection, this approach estimates the transfer function and noise covariance matrix by factorizing the data cross-spectral density matrix using Wilson’s algorithm.17 This method is robust for analyzing complex spectral interactions in the frequency domain (e.g., 1–70 Hz).Pause point: Upon completion of the script, all pairwise GC results are saved as individual .mat files in the specified output directory. The analysis can be paused securely at this stage.3.Reconfigure parameters for the comparative condition.a.Set the ‘analyname’ variable to the folder name of the comparative experimental session (e.g., ‘PPV’) to enable subsequent differential GC analysis.CRITICAL: Ensure that all other analytical parameters (specifically ‘postfix’, ‘grpA_chans’, ‘grpB_chans’, ‘freq_calc_range’, ‘toi_cwt’, and ‘toi_GC’) remain exactly the same as in the first run. Expected outcomes

Successful execution of this protocol provides a comprehensive, multi-layered visualization of frequency-specific information transfer across cortical areas. By integrating high-density ECoG with spectral Granger causality (GC) and hierarchical clustering, we shift the analytical paradigm from treating entire brain regions as single, homogeneous nodes to mapping the precise spatial topology of functional networks on the cortical surface. Researchers can expect to pinpoint task-modulated communication hubs and quantify their spatiotemporal dynamics with high precision, revealing the modular organization of inter-areal information flow.

For illustrative purposes, the multi-panel figures presented in this manuscript display selected representative results (e.g., the theta band during specific task epochs). It is important to note that all figures (Figures 1, 2, 3, and 4) were generated anew from the provided sample dataset using the scripts detailed in this protocol, rather than being reproduced or adapted from our previous work.1 The raw output figures generated by the MATLAB pipeline were subsequently imported into Adobe Illustrator, where they were compiled, aligned, and formatted into cohesive multi-panel layouts for visual clarity and publication quality.

In the initial stage of analysis, the protocol yields the temporal dynamics and global connectivity structure between the ITC and PFC. Specifically, we can observe the bidirectional information flow between representative electrode pairs through time-resolved GC traces (Figure 1A). These plots typically reveal task-event-locked fluctuations, such as prominent GC increases following cue onset or during the working memory delay period. Beyond individual pairs, the protocol generates comprehensive connectivity matrices (Figure 1B), which visualize the baseline-corrected GC strength across all possible electrode combinations in a specific frequency band (e.g., theta). When averaged over a task-relevant window, such as the delay period (0.85–2.2 s), these matrices are expected to reveal a heterogeneous connectivity structure. Notably, the marginal color bars—which display the mean GC for each individual electrode averaged across all electrodes in the opposing cortex—allow us to identify that only specific sub-populations of electrodes are actively involved in inter-areal communication during associative memory retrieval and maintenance.

By aggregating these pairwise connectivity values into topographical heatmaps, we can visualize the average information inflow and outflow at individual electrode locations (Figure 2). For instance, the resulting heatmaps typically reveal specific electrode clusters exhibiting prominent baseline-corrected GC strength, which represent the localized hubs or nodes of information transfer within each cortical area. The ability to map these spatial patterns confirms the successful capture of the frequency-specific neural dynamics inherent in the recorded ECoG signals. To further isolate task-specific communication from background noise, the protocol generates differential GC maps by subtracting control task data (PPV) from the primary task data (PCA) (Figure 3). A successful and robust analysis is marked by the appearance of defined significance contours (black circles), which enclose the “PCA regions” where information flow is significantly modulated by memory retrieval and maintenance. The use of one-sided permutation tests and False Discovery Rate (FDR) correction ensures these identified regions are statistically rigorous.

The final and most advanced stage of the protocol reveals the functional modularity within these task-modulated regions. By performing hierarchical clustering based on the similarity of differential GC patterns, we produce dendrograms and reordered correlation matrices (Figure 4A). The dendrograms should clearly show the hierarchical organization of electrodes, with the dashed line indicating the statistical threshold for forming discrete clusters (GC similarity clusters). Finally, by projecting these cluster identities back onto the cortical surface (Figure 4B), we can visualize the spatial arrangement of functional modules. A successful execution typically reveals that electrodes belonging to the same cluster (marked by identical colors) form spatially contiguous patches within the significant PCA regions. This spatial consistency serves as an internal biological validation, demonstrating that the cortical area is composed of specialized nodes within an oscillatory memory network, as characterized in our previous work.1 Note that the exact boundaries of the black significance contours in Figure 4B may differ slightly from those in Figure 3 if set ‘flg_load_stat’ to 0 in Step 11. This minor variance is a normal consequence of the independent stochastic random-resampling process inherent in the non-parametric permutation tests used for each figure.

Limitations

While this protocol provides a comprehensive and robust pipeline for evaluating time-resolved information flow between cortical regions, several methodological and computational limitations should be considered when applying it to new datasets.

First, the core analytical framework relies on pairwise non-parametric GC. A fundamental mathematical limitation of pairwise connectivity measures is their inability to definitively distinguish between direct causal interactions and indirect influences mediated by a third, unrecorded brain region (e.g., a common driver or an intermediate relay node). Consequently, the resulting GC maps should be interpreted as representations of predictive information flow and functional network hubs, rather than strict anatomical pathways. Extending this pipeline to compute multivariate or conditional GC could theoretically mitigate this issue, but doing so would drastically increase the mathematical complexity and data requirements.

Second, this protocol is highly computationally intensive, which introduces mechanical and environmental limitations. Because the script computes continuous wavelet transforms (CWT) and performs non-parametric spectral factorization (Wilson’s algorithm) for every channel pair at every single time point without time-averaging, it demands substantial computational resources. When dealing with recordings that feature a massive number of channels (e.g., modern high-density arrays with thousands of contacts) or extremely high sampling rates, users may experience out-of-memory errors or impractically long execution times. In such situations, the protocol may be unsuccessful unless the data is heavily downsampled (e.g., using the freq_step parameter introduced in the script) or executed on high-performance computing (HPC) clusters with extensive RAM and multi-core processors.

Third, users must carefully consider the assumption of wide-sense stationarity, which is a fundamental mathematical prerequisite for Granger causality analysis. While the wavelet-based non-parametric spectral factorization utilized in this protocol is generally robust to mild, transient non-stationarities, severe signal drifts or the use of excessively long analysis epochs can violate this core assumption and produce spurious connectivity estimates. We strongly recommend that users proactively assess the stationarity of their pre-processed time series prior to GC calculation. This can be achieved through visual inspection for slow temporal drifts or formal statistical evaluations, such as the Augmented Dickey-Fuller (ADF) test—noting that ADF specifically tests for unit-root non-stationarity; visual inspection remains essential for detecting other common forms in ECoG data, such as slow drifts or abrupt mean shifts. If significant non-stationarity is detected, users should apply appropriate detrending procedures (e.g., polynomial detrending or applying a stricter high-pass filter) during the preprocessing stage to ensure analytical validity. For the sample dataset provided with this protocol, the standard preprocessing pipeline already mitigates slow drifts through band-pass filtering (0.7 Hz high-pass) and trial-averaged ERP subtraction; we confirmed that no further detrending was required.

Finally, it is important to note that the current implementation of this protocol strictly requires the proprietary MATLAB environment and relies heavily on core algorithms from the FieldTrip toolbox. While the mathematical framework of spectral GC is inherently language-agnostic, we currently do not provide or support a validated open-source alternative (e.g., in Python/MNE). Therefore, users must have access to corresponding MATLAB licenses to execute the provided scripts and reproduce the workflow as described.

Problem 2

MATLAB application freezes or becomes completely unresponsive on macOS when executing plotting scripts that generate and save a large batch of figures consecutively (related to Steps 6, 8, 10, and 12).

Potential solution

Set the figure visibility parameter to run purely in the background. To do this, open the plotting script and locate the “User Configuration Parameters” section. Change the value of the ‘flg_plot_visible’ variable from 1 to 0.

Reasoning: When MATLAB is instructed to rapidly generate, display, and export dozens of figures in succession, the macOS WindowServer and MATLAB’s Java-based graphical rendering engine can become easily overwhelmed by the dense queue of GUI update commands, leading to a system-level bottleneck and application freeze. By disabling figure visibility (visible = ‘off’), MATLAB is forced to render and export the plots directly in the background memory. This effectively bypasses the GUI rendering process, completely preventing the freeze while drastically reducing the overall processing time.
