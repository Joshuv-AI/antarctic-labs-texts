A New Torus Generator for AGAMA
James Binney Tom Wright, Eugene Vasiliev

Abstract
Code is presented that computes and exploits orbital tori for any axisymmetric gravitational potential. The code is a development of the agama software package for action-based galaxy modelling and can be downloaded as the agama b code library. Although coded in C++, most of its functions can be accessed from Python. We add to the package functions that facilitate confronting models with data, which involve sky coordinates, lines of sight, distances, extinction, etc. The new torus generator can produce tori for both highly eccentric and nearly circular orbits that lie beyond the range of the earlier torus-mapping code. Tori can be created by interpolation between tori at very low cost. Tori are fundamentally devices for computing ordinary phase-space coordinates from angle-action coordinates, but agama b includes an action finder that returns angle-action coordinates from any given phase-space location. This action finder yields the torus through the given point, so it includes the functionality of an orbit integrator. The action finder is more accurate and reliable but computationally more costly than the widely used Stäckel Fudge. We show how agama b can be used to generate sophisticated but cheap models of tidal streams and use it to analyse data for the GD1 stream. With the most recently published distances to the stream, energy and angular momentum imply that the end that must be leading is trailing, but extremely small changes to the distances rectify the problem.

Introduction

AGAMA (Action-Based Galaxy Modelling Architecture,
Vasiliev 2019
) is a
suite of programs with
which to model galaxies like ours. With
agama
one can quickly recover the
gravitational potential that is self-consistently generated by a specified
density of gas in conjunction with dark matter and several populations of
stars. Stars and dark-matter particles are
specified by distribution functions

that depend on the
action integrals
J_{r}
,
J_{z}
and
J_{\phi}
. The suite can then be used to
examine the model’s dynamics and
simulate observations of the model galaxy, either by an observer internal
to the model, or by an external observer. The suite also includes code for fitting
a mean-field potential

to an N-body model.

Action-based modelling depends on algorithms for shifting between
angle-action coordinates
({\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}},{\bf J})
and conventional phase-space
coordinates
({\bf x},{\bf v})
.
agama
uses the Stäckel Fudge

(
Binney 2012
)
for transformation
({\bf x},{\bf v})\to({\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}},{\bf J})
and
torus mapping
(
McGill & Binney 1990
;
Kaasalainen & Binney 1994
)
for the inverse transformation

({\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}},{\bf J})\to({\bf x},{\bf v})
. The code
Vasiliev 2019
included in
agama
for torus mapping
is a superficial wrapping of the code released by Binney & McMillan (2016;
hereafter
(
9
)
).

The agama code differed from the
BM16 code by using the algorithm for angle finding that is described in

Much of this code dates back to work by W

Orbits are the core concepts of both stellar and planetary dynamics, and they
are central to Schwarzschild modelling, which is used extensively in the
interpretation of observations of external galaxies

;
Cappellari 2016
;

powerful technique.

Significant fractions of dark-matter particles and the stars of our Galaxy’s

Tori make it possible to investigate resonant phenomena via Hamiltonian

(

ability to produce tori by interpolating on a grid of tori. Unfortunately, the Torus Mapper
released by BM16 was implemented in such a way that
in some circumstances interpolation fails.

2
Fundamentals

A torus
T
is an injective map
T({\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}})\to({\bf x},{\bf v})
from
three-dimensional angle space into six-dimensional phase space.
T
is
2\pi

periodic in each component of the three-dimensional vector
`
. Tori
are labelled by their three actions

J_{i}={1\over 2\pi}\int_{0}^{2\pi}{\rm d}\theta_{i}\,{\bf p}\cdot{\partial{\bf x}\over\partial\theta_{i}}

(1)

where
({\bf x},{\bf p})
are the image points associated with
`
. The values of the
integrals depend neither on the values to which we set the angles not
integrated over, nor on which canonical coordinate system we use for

({\bf x},{\bf p})
.

If all image points
({\bf x},{\bf v})
lie on a level surface
H({\bf x},{\bf v})=E
of the
Hamiltonian
H
, the torus is equivalent to an orbit in the sense that given
a vector of angles
{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}_{0}
and a vector of frequencies
\Omega
, the
time series

[{\bf x}(t),{\bf v}(t)]=T({\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}_{0}+\mbox{\boldmath$\Omega$}t),

(2)

with
\Omega_{i}=\partial H/\partial J_{i}
solves Hamilton’s equations of motion for

H
.

We call a torus that lies within a constant-Hamiltonian surface an
orbital torus
. With such a torus we associate values of the vector
\Omega

and the scalar
E
in addition to vector
{\bf J}
.

The classical procedure for obtaining tori is solution of the Hamilton
Jacobi equation

H\Big({\bf x},{\partial S\over\partial{\bf x}}\Big)=E

(3)

for the generating function
S({\bf x},{{\bf J}^{\rm T}})
of the canonical transformation

({\bf x},{\bf p})\leftrightarrow({{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}},{{\bf J}^{\rm T}})
, where the superscripts
T
stand
for ‘toy’ to distinguish this angle-action system from the one,

({\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}},{\bf J})
, required by orbits in the given, real potential.

The Hamilton-Jacobi equation can be solved for very
few Hamiltonians, and we start from one of these Hamiltonians: for orbits that
are not highly eccentric, we use the isochrone potential

(
Hénon 1959
;
Hénon 1960
)

\Phi(r)=-{J_{\rm s}^{2}/b\over{b+\sqrt{b^{2}+r^{2}}}},

(4)

while for highly eccentric orbits (ones with
J_{\phi}/J_{r}
small and

J_{z}/J_{r}\la 1
), we use the
effective potential of a semi-degenerate three-dimensional harmonic
oscillator

\Phi(R,z)={\textstyle{1\over 2}}\big(\omega_{R}^{2}R^{2}+\omega_{z}^{2}z^{2}\big).

(5)

In equation (
4
),
b
is a length scale and
J_{\rm s}=\sqrt{GMb}
is a
scale action, with
M
the mass of the body that generates the potential, and

G
is Newton’s constant. In equation (
5
),
\omega_{R}
and
\omega_{z}

are suitable constants and
R=\sqrt{x^{2}+y^{2}}
is cylindrical radius. For
specified
{{\bf J}^{\rm T}}
and either choice of potential, analytic formula give

({\bf x},{\bf p})
as functions of
{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}
. Other formulae yield
({{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}},{{\bf J}^{\rm T}})

given
({\bf x},{\bf p})

(see
Binney & Tremaine 2008
, §3.5.2)
. We call a map provided by an
isochrone or a harmonic oscillator an ‘HJ map’.

2.1
Point transformations

We combine an HJ map with a point transformation

{\bf x}\leftrightarrow{\bf X}\equiv(R,z,\phi)
. With
P_{i}
the momentum conjugate
to
X_{i}
, the generating function of a point transformation is

{\cal G}({\bf x},{\bf P})=\sum_{i}X_{i}({\bf x})P_{i}.

(6)

The derivatives of
{\cal G}
yield the mapping between the momenta of the two
systems. The choice of point transformation depends on which HJ map has been
chosen and we defer details to Section
7.2
. Here we note that
the map always involves a confocal ellipsoidal coordinate system that is
defined by the
z
coordinates
\pm\Delta
of its foci. Shell orbits
J_{r}=0

can be accurately fitted by ellipses in the meridional plane. Given actions
{\bf J}
, one integrates one
quadrant of the shell orbit
{\bf J}_{\rm sh}=(0,J_{z},J_{\phi})
and chooses

\Delta
such that it is closely fitted by the ellipse

{R^{2}\over R_{\rm sh}^{2}}+{z^{2}\over R_{\rm sh}^{2}+\Delta^{2}}=1,

(7)

where
R_{\rm sh}
is the value of
R
at which the shell orbit crosses
z=0
.

When a potential is initialised, values of
R_{\rm sh}
and
\Delta
are
tabulated as functions of both
(E,\xi)
and
(L,\xi)
, where
L\equiv J_{z}+|J_{\phi}|
and
\xi=|J_{\phi}|/L_{\rm circ}(E)
in the first case and

\xi=|J_{\phi}|/L
in the second case. Initialisation of
agama
’s
Stäckel-Fudge based
actionFinder
involves tabulation of
\Delta(E,\xi)
,
so negligible additional work is required to initialise a
TorusGenerator
.

The mapping

({{\bf J}^{\rm T}},{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}})\quad\smash{\mathop{\longleftrightarrow}\limits^{{\rm HJ\,eqn}}}\quad({\bf x},{\bf p})\quad\smash{\mathop{\longleftrightarrow}\limits^{{\cal G}}}\quad(R,z,\phi,p_{R},p_{z},p_{\phi})

(8)

is canonical because it is a compound of two canonical maps. We call this
compound map the ‘toy map’.

Whereas one parameter,
\Delta
serves to define an ellipsoidal coordinate
system,
agama
b’s point transformations typically have eleven free parameters
because they use Fourier series to relate the vertical coordinate of the HJ
map (either
\vartheta
or
z)
to the ellipsoidal system’s
z
coordinate –
see Section
7
for details. The flexibility
provided by this increased parameter count makes it possible for
agama
b’s
toy maps to fit target orbits remarkably well.

To secure the flexibility to fit our image tori closely to level surfaces of
any galactic Hamiltonian

H={\textstyle{1\over 2}}\Big(p_{R}^{2}+p_{z}^{2}+{p_{\phi}^{2}\over R^{2}}\Big)+\Phi(R,z),

(9)

we precede the toy map with the canonical transformation

({\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}},{\bf J})\quad\smash{\mathop{\longleftrightarrow}\limits^{S}}\quad({{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}},{{\bf J}^{\rm T}})

(10)

that has generating function

S({\bf J},{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}})={\bf J}\cdot{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}+\sum_{\bf k}S_{\bf k}({\bf J})\sin({\bf k}\cdot{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}),

(11)

where
({\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}},{\bf J})
are (approximations to) the angle-action coordinates of
the full galactic Hamiltonian. The subscripts
{\bf k}
in equation (
11
) are
three-dimensional vectors with integer components, but in the axisymmetric
case
S({\bf J})
is non-zero only when
k_{\phi}=0
. Differentiating equation (
11
)
we get

{{\bf J}^{\rm T}}={\bf J}+\sum_{\bf k}{\bf k}S_{\bf k}\cos({\bf k}\cdot{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}),

(12)

so for any chosen
{\bf J}
and coefficients
S_{\bf k}
,
{{\bf J}^{\rm T}}
becomes a function
of
{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}
and then with the toy map

({{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}},{{\bf J}^{\rm T}})\leftrightarrow(R,z,\phi,p_{R},p_{z},p_{\phi})
, the ordinary phase
space coordinates become functions of
\theta^{\rm T}
. The Marquardt-Levenberg
routine
(
Press et al. 1992
, e.g.)
is now used to adjust the
S_{\bf k}
to minimise
the variance in

over a regular grid in

.

McGill & Binney 1990
introduced the use of a generating function (
11
)
and the isochrone HJ map.
Kaasalainen & Binney 1994
showed that a point
transformation was required for orbits with small
J_{r}
, but the
point transformations they used were more complex and less convenient than
those used here. The torus mapper published by
Binney & McMillan 2016
uses a
point transformation only when
J_{r}/J_{z}
is small, and interpolation between
tori with and without point transformations is problematic. This is a
significant weakness because much of the power
of tori for galaxy modelling derives from the ability to
obtain new tori by interpolating between old ones.
Kaasalainen 1995
used
harmonic-oscillator HJ maps but to model resonantly trapped orbits
rather than untrapped but highly eccentric orbits. The reasoning that leads
us to use harmonic-oscillator HJ maps for highly eccentric orbits is given in

Wright & Binney 2025
.

Solving for frequencies and angles

The manner in which we solve for the true angle variables

{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}={{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}+\sum_{\bf k}{\partial S_{\bf k}\over\partial{\bf J}}\sin({\bf k}.\cdot{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}).

(13)

We now derive the algorithm used to find the gradients
\partial S_{\bf k}/\partial J_{i}
in
detail because both the derivation given in
Laakso & Kaasalainen 2013
and the derivation
of the closely related algorithm in
Binney & Kumar 1993
lack clarity about the
nature of partial differentials.

is a function of only three variables, usually taken to be the components

, so we may write

\displaystyle\Omega_{i}

\displaystyle=\sum_{j}\left({\partial H\over\partial J^{\rm T}_{j}}\right)_{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}\left({\partial J^{\rm T}_{j}\over\partial J_{i}}\right)_{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}

\displaystyle=\sum_{j}\left({\partial H\over\partial J^{\rm T}_{j}}\right)_{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}\left(\delta_{ij}+\sum_{\bf k}k_{j}{\partial S_{\bf k}\over\partial J_{i}}\cos({\bf k}\cdot{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}})\right).

(15)

Rearranging we get

\Omega_{i}-\sum_{j}\left({\partial H\over\partial J^{\rm T}_{j}}\right)_{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}\sum_{\bf k}k_{j}{\partial S_{\bf k}\over\partial J_{i}}\cos({\bf k}\cdot{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}})=\left({\partial H\over\partial J^{\rm T}_{i}}\right)_{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}.

(16)

During the minimisation process we have already computed on a grid of points
over the torus the values of

{\partial H\over\partial S_{\bf k}}=\left({\partial H\over\partial{{\bf J}^{\rm T}}}\right)_{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}\!\!\cdot{\partial{{\bf J}^{\rm T}}\over\partial S_{\bf k}}=\sum_{j}\left({\partial H\over\partial J^{\rm T}_{j}}\right)_{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}\!\!\cdot k_{j}\cos({\bf k}\cdot{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}).

(17)

After using this expression to simplify the term in (
16
) with a
cosine, we obtain

\Omega_{i}-\sum_{\bf k}{\partial H\over\partial S_{\bf k}}\cdot{\partial S_{\bf k}\over\partial J_{i}}=\left({\partial H\over\partial J^{\rm T}_{i}}\right)_{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}.

This is a linear equation for the unknowns
\Omega_{i}
and
\partial S_{\bf k}/\partial J_{i}

\partial H/\partial S_{\bf k}
and

that have already been

3.4
An action finder

Fundamentally torus mapping provides the map from angle-action to ordinary

(

)

3.5
The class
eTorus

Real galactic potentials are not integrable: they do not admit a global set
of angle-action coordinates. As discussed in
Binney 2016
, if one
sets a very tight constraint
tol
on the permitted dispersion in
H
,
the tori constructed for adjacent actions may cross.
This unphysical phenomenon arises because the torus mapper is attempting to
generate a global set of angle-action coordinates when no such set is
possible. As Binney explains, in these circumstances one should set an
undemanding upper limit on
\sigma_{H}
such that tori never intersect. Then
the set of tori comprise a global system of angle-action coordinates for a
Hamiltonian
H_{0}({\bf J})
that differs slightly from the real one. The difference between
the real and true Hamiltonians can be quantified by Fourier analysing the
real Hamiltonian over the tori of the constructed Hamiltonian. That is, one
computes the quantities
h_{\bf k}
that are defined by

H({\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}},{\bf J})=H_{0}({\bf J})+\sum_{{\bf k}\neq 0}h_{\bf k}({\bf J})\,\mathrm{e}^{{\rm i}({\bf k}\cdot{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}})}

(23)

Typically
h_{\bf k}
will be much smaller than
H_{0}
and it can be safely
neglected except where
\Omega_{\rm slow}={\bf k}\cdot\mbox{\boldmath$\Omega$}
is small. Where

\Omega_{\rm slow}
is small, resonant trapping may occur. Its effects can
be computed from
h_{\bf k}
with Hamiltonian perturbation theory.

Hamiltonian perturbation theory can also be used to study the dynamics of
potentials for which we cannot (currently) do torus mapping directly. For
example, the dynamics of bars can be studied by treating the non-axisymmetric
part of a bar’s potential as a perturbation on an axisymmetric potential

(
Binney 2018
;
Binney 2020
)
.

An
eTorus
combines a torus of the integrable Hamiltonian
H_{0}
with
the Fourier coefficients
h_{\bf k}
– the latter can be used to create tori of
resonantly trapped orbits by perturbation theory.
To create an
eTorus
we
write

potential::bar_potS bar(0.4, 220./978., 1.7);

eTorus eT(TG.fiteTorus(J,&bar));

Here
bar
is the non-axisymmetric part of a bar’s potential:
in this example it takes the form
\Phi_{2}(R,z)\cos(2\phi)
. The resulting
Fourier coefficient will be dominated by ones generated by the bar. If the

bar
argument of the
eTorus
creator were omitted, the Fourier
coefficient would be smaller and any resonant trapping that they described
would be inherent to the axisymmetric potential.

4
Application to stellar streams

The advent of data from Gaia has led to the detection of stellar streams in
industrial quantities
(
Ibata et al. 2024
, e.g.)
. It has long been recognised
that streams are best quantified by angle-action coordinates

(
Tremaine 1999
;
Helmi & White 1999
)
, and that those seen at high Galactic latitudes are
potentially powerful probes of our Galaxy’s gravitational potential

\Phi({\bf x})
and
hence its dark-matter distribution

(
Ibata et al. 2001
;
Binney 2008
;
Eyre & Binney 2011
;
Sanders 2014
;
Erkal et al. 2019
;
Ibata et al. 2024
, e.g.)
.

Even in the era of Gaia, the phase-space locations of individual stars have
significant uncertainties so we must constrain
\Phi
by computing
the probability distribution for the density of stars in some image of
phase space as functions of parameters describing the stream, and then
marginalise the likelihood of the observed distribution of stars over the
stream parameters
(
Bovy 2014
)
. To implement this agenda we need
an algorithm that rapidly generates model streams given a potential and
stream parameters. We now show how the
TorusGenerator
can be used to
implement a slight modification of the algorithm described by

Bovy 2014
.

The demonstration will serve to illustrate facilities within
agama
b for
connecting astrophysical structures to observational data, which typically
involve sky coordinates, proper motions, magnitudes, etc. Functions for
connecting models to observational data are gathered into
agama
b’s
obs

namespace and listed in Appendix
A
.

4.1
Generating a stream

We start by choosing the actions
JP
of the stream’s progenitor,
computing its torus
TP
and finding the times
tperi
of ten
pericentres

Actions JP(288.5*h, 897.6*h, 3173.7*h);

Torus TP(TG.fitTorus(JP));

double TPr = 2*M_PI/TP.freqs.Omegar;

int Np=10; std::vector<double> tperi(Np);

for(int i=0; i<Np; i++) tperi[i]=i*TPr;

Here
h=intUnits.from_Kpc_kms
is
agama
b’s unit of action and the values of the
progenitor’s actions are those used by
Bovy 2014
to facilitate comparison
with that paper. We do however take
J_{\phi}=+3173h
rather than
-3173h

because
agama
b follows the
astropy
convention in using a right-handed coordinate system such that the Sun’s
value of
J_{\phi}<0
. Bovy used the standard logarithmic potential with
circular speed
V_{c}=220\,\mathrm{km\,s}^{-1}
. This potential cannot be used with
agama
b’s
action finders because they assume that
\Phi({\bf x})\to 0
as
|{\bf x}|\to\infty
.
A potential that is functionally equivalent to the standard one but tends to
zero at infinity is

\Phi({\bf x})=-{\textstyle{1\over 2}}V_{c}^{2}{L_{c}\over 1+L/L_{c}}

(24)

where
L=\ln m^{2}
with
m^{2}=1+(R^{2}+z^{2}/q^{2})/R_{c}^{2}
and
L_{c}
a suitably large constant:
we used 1000 by executing the line

potential::PtrPotential pot(new

potential::Logarithmic(Vc,Rc,1,ZtoX,1000));

with
Rc = 0.1*intUnits.from_Kpc
.

Stars removed from the cluster form two clouds in action space, one below and
one above the progenitor’s value of
J_{\phi}

(
Eyre & Binney 2011
)
. In real space
the lower cloud forms the leading tidal arm while the upper cloud forms the
trailing arm
(
Eyre & Binney 2011
;
Bovy 2014
)
. The clouds are triangular in
shape. We model this shape by distributing
J_{r}
and
J_{z}
normally around
mean values that are slightly offset from the corresponding actions of the
progenitor with dispersions that increase with
|J_{\phi}-JP_{\phi}|
.
J_{\phi}

is also normally distributed and all three dispersions in action are related
to the progenitor’s velocity dispersion by
(cf.
Bovy 2014
, eqs
5–7)

double sigCluster = 0.365*intUnits.from_kms;

double DJr = sigCluster*(RZapo.R-RZperi.R)/M_PI;

double DJz = sigCluster*2*RZzmax.z/M_PI;

double DJphi = sigCluster*RZperi.R;

where
RZperi
and
RZapo
are the locations given by the
torus at angles (0,0,0) and
(\pi,0,0)
, while
RZmax
is the location at
angles
(\pi,\pi/2,0)
. We create grids of tori that cover the volumes occupied by the leading and trailing clouds.
For the leading cloud:

int nx=5, ny=5, nz=5;

std::vector<Torus> Ts(nx*ny*nz);

std::vector<double> xs(nx), ys(ny), zs(nz);

Actions Joff(0.7*DJr, 1.5*DJz, -4*DJphi);

for(int i=0; i<nx; i++){

xs[i]=JP.Jr+Joff.Jr+(i-nx/2)*DJr;

for(int j=0; j<ny; j++){

ys[j]=JP.Jz+Joff.Jz+(j-ny/2)*DJz;

for(int k=0; k<nz; k++){

zs[k]=JP.Jphi+Joff.Jphi+(k-nz/2)*DJphi;

Actions J(xs[i],ys[j],zs[k]);

Ts[(i*nx+j)*ny+k]=TG.fitTorus(J);

}

}

}

TorusGrid3 Tgrd(xs,ys,zs,Ts,TG);

From
Tgrd
we can create the torus with actions
J
by
linear interpolation at negligible
cost by the statement

Torus T(Tgrd.T(J));

In this way we create 1000 tori in each cloud by sampling the
Gaussianly distributed actions. Fig.
8
shows on the left two
projections of the resulting stellar stream in action space, and on the right
the corresponding projections in frequency space. The plot is very similar to
Fig. 2 of
Bovy 2014
, which shows data from a full N-body
simulation. Filling out
Tgrd
took three minutes on a laptop, but then a
stream with 2000 stars can be created in less than
10
milliseconds. Note that Bovy’s figure
relates to a stream with negative
J_{\phi}
while Fig is for a stream with

J_{\phi}>0
so the lower panels need to be reflected in a horizontal plane
before comparison with Bovy’s plot.

The near linearity of the frequency distributions in Fig.
8
is a remarkable
phenomenon given that these are the images of a near-spherical cloud of
objects in action space. As discussed by
Tremaine 1999
and
Eyre & Binney 2011
, it
arises because for typical galactic potentials the symmetric matrix

{\partial\Omega_{i}/\partial J_{j}}
has one eigenvalue that is larger than the others by a
factor
20-30
, so a spherical region is mapped to an ellipsoid that stretches
along the corresponding eigenvector.

PYTHON wrappers

To exploit fully the possibilities offered by
agama
b, one should call its
routines from C++ code as illustrated above. However, we provide Python
wrappers of the underlying C++ code that allow many applications of

agama
b to be completed from within Python. The wrappers take advantage of
the
pybind11
package and differ substantially from those provided by

Vasiliev 2019
. They are designed to facilitate input/output via Python while
leaving the computations and principal data structures in the C++ domain.

Python structures are provided that set up gravitational potentials,
distribution functions (DFs) and galaxy models (i.e., unions of DFs and a
potential). Wrappers are provided for the principal data types (actions,
angles, frequencies, phase-space and sky coordinates). With these tools,
Python can be used to set up a galaxy model or explore orbits in a potential
and then to plot the resulting observables (density, velocity
distributions, etc.) both in six-dimensional phase space and on the sky.

As an example, with
agama
b imported as
AG
and matplotlib imported
as
plt
the following Python code will plot the trajectory across the
sky of an object like the progenitor of the GD1 stream:

IU=AG.galactic_kms

sun=AG.solarShifter(IU)

h=IU.from_Kpc_kms

p=AG.createPotential("type=spheroid, gamma=1, beta=3, alpha=1, scaleradius=18, densityNorm=170, q=0.5")

TG=AG.TorusGenerator(p,1e-4)

J=AG.Actions(50*h,800*h,2800*h)

theta0=AG.Angles(0,0,4)

T=TG.fitTorus(J)

traj=T.orbit(theta0,1*IU.from_Myr,.2*IU.from_Gyr)

s=0

Vlos=0

l=[]

b=[]

for i in range(len(traj)):

astrom=sun.toSky(traj[i][0],s,Vlos)

l.append(astrom.pos.l)

b.append(astrom.pos.b)

plt.xlabel("longitude")

plt.ylabel("b")

plt.plot(l,b)

plt.show()

In this example
IU
is an object that converts between internal and
astrophysical units:
h
is then the unit of action and
p
becomes
an NFW potential with scale radius
18\,\mathrm{kpc}
and a density normalisation that
makes the circular speed at
8\,\mathrm{kpc}

246\,\mathrm{km\,s}^{-1}
. The array
traj
fills up
with
PosVelCyl
in the slots
traj[i][0]
and the corresponding
times in
traj[i][1]
.
sun.toSky
returns the corresponding
astrometry (and also computes distances and line-of-sight velocities, which
we discard).

7
What goes on behind the scenes

This section explains how
agama
b creates tori and uses them in the new
action finder before closing with some plots that are useful in understanding
how well the code is working. Readers who are only interested in
producing and using tori can skip this section.

When an
actionFinder
is initialised in
agama
, shell orbits are
integrated on a grid in energy and
\xi\equiv J_{\phi}/L_{\rm circ}
and values
are stored of each orbit’s intercept
R_{\rm sh}
with the equatorial plane, and
its focal distance
\Delta
. Given that these data are also required by a

TorusGenerator
, in
agama
b they are associated with a potential
rather than an
actionFinder
and they are computed when a ‘composite’
potential is initialised. Such a potential has methods that return
R_{\rm sh}
and

\Delta
as functions of either
(E,\xi)
or
(L,\xi)
: the former dependence
is required by an
actionFinder
while the latter is what’s needed by a

TorusGenerator
.

At each energy
E
,
J_{\phi}
is decreased from its circular value. During
the orbit integration
J_{z}
is determined by integrating the differential
equation
{\rm d}J/{\rm d}t={\bf p}\cdot{\bf v}
in parallel with the equations of motion.
Then to each orbit we can attach the numbers

L\equiv J_{z}+|J_{\phi}|\quad\hbox{and}\quad\xi\equiv{|J_{\phi}|\over L}

(27)

– in the case of a spherical potential,
\xi=\cos i
is a measure of the
orbit’s inclination
i
. Each shell orbit is fitted with an ellipse
with minor semi-axis length
R_{\rm sh}
and focal distance
\Delta
. From
these data interpolators are constructed from which
R_{\rm sh}
and
\Delta

can be predicted at arbitrary
(L,\xi)
. The interpolators’ grid typically
has
\sim 100
points in
L
and 20 in
\xi
.

Once the survey of shell orbits is complete,
agama
b computes box/loop
transition orbits on a grid in energy and stores their values of
J_{z}
as a
function of
J_{\rm fast}\equiv 2J_{r}+J_{z}
, At the same time values of three
quantities,
I_{3\rm crit}
,
\Delta_{\rm crit}
and
u_{\rm min}
, are
stored for these orbits as functions of
E
. These data are used to refine
the Stäckel Fudge as explained in
Wright & Binney 2025
.

When a
TorusGenerator
is initialised, one more table is constructed.
This gives the energy of orbits in the equatorial plane as a function of

J_{r}+|J_{\phi}|
and
|J_{\phi}|/(J_{r}+|J_{\phi}|)
. The table is stored as a quintic
spline
interpJrE
.

7.1
Choosing an HJ map

The first task after a call of
fitTorus
is the choice of an HJ map. It
is undertaken by
TorusGenerator
’s method
chooseTM
. That starts by
using
L
and
\xi
to obtain by
interpolation the radius
R_{\rm sh}
and focal distance
\Delta
of the
underling shell orbit.
R_{\rm sh}
sets the characteristic frequency

\Omega_{\rm scale}
in the convergence criterion (
28
)

\sigma_{H}<{\tt tol}\times\Omega_{\rm scale}J_{\rm scale}.

(28)

Next the table
interpJrE
is used to estimate the
energy from
{\bf J}
. This is used to determine the orbit’s velocity
v_{\rm merid}
in the
meridional plane when the star is at
(R,z)=(\Delta,0)
, and the variable

J_{\rm low}=0.3\Delta v_{\rm merid}
is set. If
J_{\phi}>J_{\rm low}
, an
isochrone HJ map is selected. If
J_{\phi}<J_{\rm low}
,

is
evaluated from the potential’s interpolator and a harmonic-oscillator HJ map
is selected if

and an isochrone otherwise.

7.1.1
Choosing an isochrone

An isochrone is defined by the numbers
J_{\rm s}
and
b
.
The condition for the isochrone’s circular orbit with
L=J_{z}+|J_{\phi}|
to have
radius
R_{\rm sh}
can be written

R_{\rm sh}=bg(J_{\rm s}),

(29)

where

g(J_{\rm s})\equiv\sqrt{{J_{\rm s}^{4}\over(2b^{2}{\cal E}_{c})^{2}}-1}.

(30)

Here
-{\cal E}_{c}
is the energy of the circular orbit, which satisfies

b^{2}{\cal E}_{c}={2J_{\rm s}^{4}\over(L+\sqrt{L^{2}+4J_{\rm s}^{2}})^{2}}.

(31)

Equation (
29
) defines a one-parameter family of possible
isochrones. We choose among this family by requiring that the ratio of the
radial forces at peri- and apo-centre match the corresponding ratio in the
real potential. Specifically, for a trial value
J_{\rm s}
and the corresponding

b=R_{\rm sh}/g(J_{\rm s})
we evaluate

b^{2}{\cal E}\equiv{2J_{\rm s}^{4}\over[2J_{r}+L+\sqrt{L^{2}+4J_{\rm s}^{2}}]^{2}}

(32)

which is
b^{2}
times the absolute value of the energy of the isochrone orbit,
and then the dimensionless parameter

\gamma\equiv{J_{\rm s}^{2}\over 2b^{2}{\cal E}}-1.

(33)

The orbit’s eccentricity is

e(J_{\rm s})=\sqrt{1-{L^{2}\over\gamma J_{\rm s}^{2}}\Big(1+{1\over\gamma}\Big)}

(34)

and from
e
the peri- and apo-radii follow

r_{\pm}(b,J_{\rm s})=\gamma b\sqrt{(1\pm e)(1\pm e+2/\gamma)}.

(35)

The condition on the radial forces can now be written

{(b+a_{-})^{2}a_{-}r_{+}\over(b+a_{+})^{2}a_{+}r_{-}}={(\partial\Phi/\partial R)_{(r_{+},0)}\over(\partial\Phi/\partial R)_{(r_{-},0)}}

(36)

where
a(r)=\sqrt{b^{2}+r^{2}}
and
a_{\pm}\equiv a(r_{\pm})
. An instance of the
class
JsFinder
solves this equation for
J_{\rm s}
with
b
an explicit
function of
J_{\rm s}
through equation (
29
). The isochrone is fully
specified once
J_{\rm s}
and
b
have been chosen.

7.1.2
Choosing a harmonic oscillator

The radius of a degenerate two-dimensional harmonic oscillator of natural
frequency
\omega_{R}
is given by

R^{2}={E\over\omega_{R}^{2}}(1+\beta\cos\theta_{r}),

(37)

where
E=\omega_{R}(2J_{r}+|J_{\phi}|)
and
\beta=\sqrt{1-(\omega_{R}J_{\phi}/E)^{2}}
. So
to set its apo-centric radius to
R_{\rm max}
, we need
frequency

\omega_{R}={1\over R_{\rm max}^{2}}(2J_{r}+|J_{\phi}|)(1+\beta).

(38)

The amplitude
Z
of the vertical oscillator is given by
Z^{2}=2J_{z}/\omega_{z}
.
In the case of a near-shell orbit it’s also related to
R_{\rm sh}
and the
inclination
\sim J_{z}/L
. We adopt

Z={2J_{z}\over\pi L}R_{\rm sh}.

(39)

This yields

\omega_{z}={\pi^{2}\over 2}{L^{2}\over R_{\rm sh}^{2}J_{z}}.

(40)

7.2
Point transformation

The output
(r,\vartheta,p_{r},p_{\vartheta})
or
(R^{\prime},z^{\prime},p_{R}^{\prime},p_{z}^{\prime})
from the chosen
HJ map becomes the input to a point transformation

(r,\vartheta)\leftrightarrow(R,z)
or
(R^{\prime},z^{\prime})\leftrightarrow(R,z)
to
determine the location
(R,z)
at which the real potential will be evaluated.

Given a radial variable such as
x=r
or
x=R^{\prime}
that lies in
(0,\infty)
, we define
a dimensionless variable that is confined to
({\textstyle{1\over 2}},1)
by

s={\textstyle{1\over 2}}\big[1+\tanh(x/x_{0})\big],

(41)

where
x_{0}
is a suitable linear scale. Then we transform
x
to a new
dimensional variable

\widetilde{x}=x+x_{0}\sum_{n=1}^{N_{x}}X^{(x)}_{n}\sin(2n\pi s).

(42)

where the
X^{(x)}_{n}
are dimensionless constants chosen as described below. The derivatives
{\rm d}\widetilde{x}/{\rm d}x
and
{\rm d}^{2}\widetilde{x}/{\rm d}x^{2}
are obtained analytically.

When using an isoschrone as the HJ map, the map

(r,\vartheta)\leftrightarrow(R,z)
is as follows. We write

\displaystyle R=\widetilde{r}\sin v\quad;\quad z=\sqrt{\widetilde{r}^{2}+\Delta^{2}}\cos v,

(43)

where
v(\vartheta)
is defined by the Fourier series

v(\vartheta)=\vartheta+\sum_{n=1}^{N}V^{(\vartheta)}_{n}\sin(2n\vartheta).

(44)

The inverse map is given by

\displaystyle\widetilde{r}^{2}

\displaystyle={\textstyle{1\over 2}}\big(B+\sqrt{B^{2}+4R^{2}\Delta^{2}}\big)

(45)

\displaystyle\cos v

\displaystyle={z\over\sqrt{\widetilde{r}^{2}+\Delta^{2}}},

(46)

where
B=R^{2}+z^{2}-\Delta^{2}
. From
\widetilde{r}
we obtain
r
via equations
(
41
) and (
42
) with
x\to r
.

The point transformation (
43
)
maps circles
\widetilde{r}=\hbox{const}
into ellipses that have foci on the
z
axis at

z=\pm\Delta
. The function
v(\vartheta)
determines how each circle is
mapped to its ellipse. The corresponding inclined
circular orbit of the isochrone maps to the
ellipse defined by equation (
7
) and thus nearly coincides
with the real-space trace of the galaxy’s shell orbit because

\Delta
was determined by fitting an
ellipse to the shell orbit
{\bf J}=(0,J_{z},J_{\phi})
.

When using a harmonic-oscillator HJ map,
R^{\prime}
is mapped to
R
by setting

x=R^{\prime}
and
\widetilde{x}=R
in equations (
41
) and
(
42
). Equation (
41
) is used to map
z^{\prime}
to
s
but
then

rather than to an analogue of

\widetilde{x}
. Specifically we define

v=\pi(1-s)+\sum_{n=1}^{N}V_{n}^{(z)}\sin\big(2n\pi s\big).

(47)

As

increases from zero to large values,

towards zero like the angle

of spherical polar coordinates.
Finally, the second of equations (

In summary, an isochrone map is combined with a point transformation

(r,\vartheta)\leftrightarrow(R,z)
, while a harmonic-oscillator map is
combined with a map

. The role of the Fourier
coefficients in equations (

) and (

) is to
ensure that when one action vanishes and the orbit reduces to a curve in real
space and a loop in position-momentum space, the image of the toy orbit in
position-momentum space fits the trace in this space of the real orbit.
Failure of the point transformation to provide a good fit is likely to cause the
generating function
S({\bf J},{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}})
(eqn.
11
) to yield negative toy
actions, which are meaningless.

7.3
Determining the
S_{\bf k}

Once the toy map has been defined, the code chooses the integer vectors
{\bf k}
that will label non-zero

S_{\bf k}
in the generating function (
11
). If the potential is even
in

, only vectors with even

are required (BM16). Moreover, the symmetry
of the generating function (
13
) is such that if
{\bf k}
is
included,
-{\bf k}
is not required. We implement this condition by selecting
only vectors with

and omitting vectors with
k_{r}=0
and
k_{z}\geq 0
.
Fig.

illustrates this situation. By default terms are included
up to
k_{r}=6
and
|k_{z}|=4
. The Levenberg-Marquardt algorithm now chooses
the

to minimise the variance of
H
.

If the dispersion in
H
does not satisfy the convergence criterion
(
28
), additional terms are added to the generating function.
The boundary of the region of non-zero
S_{\bf k}
is inspected, and new
coefficients are declared wherever a point adjacent to the boundary has a
neighbour whose magnitude exceeds 20 per cent of the magnitude of the largest
point on the current boundary. ‘Neighbour’ is defined to be differences in

k_{r}
no more than three and
k_{z}
no more than two. Once the list of
{\bf k}

vectors
has been expanded, the values of the
S_{\bf k}
are again optimised, starting
from the previous values in the case of coefficients that are not new.
Fig.
15
shows the generating function of the orbit plotted in
Fig.

It’s important to sample tori sufficiently densely in
{{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}}

7.4
Interpolation

The basic building blocks of a torus are a generating function
and a toy map.
Functions such as
interpGenFnc
, and
interpPtrToyMap
are defined that linearly
interpolate between two instances of either of these classes. For example

GenFnc GF2 = interpGenFnc(x, GF0, GF1);

where
0\leq x\leq 1
makes
GF2

x
times
GF0
plus
1-x
times

GF1
.

Some terms
S_{\bf k}
may be in one generating function but not in the other. The
interpolated generating function contains all the terms that appear in either
of the input generating functions, with zero used as the amplitude of a
missing term. Perturbing Hamiltonians are interpolated in the same way.

Interpolation between toy maps is straightforward and can be accomplished by
a function
InterpTorus(x,T0,T1)
so long as the tori use the same HJ
map. If one torus uses an isochrone and the other uses a harmonic oscillator,
interpolation must be achieved by the method
interpTorus
of
TorusGenerator
. This method replaces the torus that uses an isochrone by one
that uses a harmonic oscillator before calling
InterpTorus
.

In Section
4
we used the class
TorusGrid3
that
provides interpolation on three-dimensional grids of tori.
Resonances drive orbits along one-dimensional manifolds in action space that all have
the same energy by virtue of the resonant condition

0={{\bf N}\cdot\mbox{\boldmath$\Omega$}}=N_{r}{\partial H\over\partial J_{r}}+N_{z}{\partial H\over\partial J_{z}}+N_{\phi}{\partial H\over\partial J_{\phi}}.

(48)

so
TorusGenerator
has a method
interpeTorus
that returns
any
eTorus
that lies in this manifold.
Let
eTs
be a
std::vector<eTorus>
that populates the resonant
manifold, and
xs
be a
std::vector<double>
that gives the
corresponding values of some quantity, for example
J_{r}
, that varies along
the manifold. Then any eTorus in the manifold can be constructed by executing
for some value of
x
the line

eTorus eT(TG.interpeTorus(x, xs, eTs));

This version of
interpeTorus
finds
i
such that

xs[i]\leq x\leq xs[i+1]
and then calls
TG.interpeTorus(x,eTs[i],eTs[i+1])
.
The corresponding method
interpTorus(x,xs,Ts)
exists for plain tori.

7.5
The action finder

The action finder’s task is to adjust the
({\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}},{\bf J})
values that are
returned by the Stäckel Fudge for a given phase-space point
{\bf p}
.
The natural algorithm is a Newton-Raphson search of
({\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}},{\bf J})
space. For
such a search one needs to be able to compute
\partial{\bf p}/\partial{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}
and
\partial{\bf p}/\partial{\bf J}
.
Computing derivatives w.r.t.
`
is straightforward but derivatives
w.r.t.
{\bf J}
are problematic unless the toy map is held constant – the
algorithm used to choose the toy map makes it hard to compute the derivatives
of the map’s parameters
\Delta,J_{\rm s},b
, etc. w.r.t.
{\bf J}
. For fixed
toy map we have

{\partial{\bf p}\over\partial{\bf J}}={\partial{\bf p}\over\partial{{\bf J}^{\rm T}}}\cdot{\partial{{\bf J}^{\rm T}}\over\partial{\bf J}}

(49)

with both the matrices on the right available. However, once the toy map has
been fixed, a simpler algorithm becomes available: we can immediately compute
the toy angle-action variables of
{\bf p}
and then adjust
{\bf J}
until the point

{\bf p}^{\prime}({{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}},{\bf J})
pointed to by the torus
{\bf J}
at the toy angles of
{\bf p}

coincides with
{\bf p}
. In practice the code computes the toy actions

{{\bf J}^{\rm T}}^{\prime}({{\mathchoice{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecten\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}{\hbox{{\gkvecseven\char 18\relax}}}}^{\rm T}},{\bf J})
assigned by
{\bf J}
to
{\bf p}^{\prime}
and adjusts

{\bf J}
until
{{\bf J}^{\rm T}}^{\prime}
and
{{\bf J}^{\rm T}}
coincide. In the axisymmetric case, the
Stäckel Fudge returns the correct value of
J_{\phi}
, so the search is
two-dimensional.

The torus returned by
ActionFinderTG
for actions
{\bf J}
may have a
larger dispersion of Hamiltonian values,
\sigma_{H}
, than the torus returned
by
fitTorus
for
{\bf J}
because
ActionFinderTG
doesn’t
optimise the toy map for
{\bf J}
. This shortcoming of the
returned torus does not significantly impact the returned angle-action
coordinates and a precise torus can be obtained by calling
fitTorus
on

{\bf J}
.

8
Conclusions

We have presented a development,
agama
b, of the
agama
software suite
for action-based galaxy modelling. This includes a new torus mapper that uses
the data types and numerical procedures that are native to
agama
, and
handles a wider range of orbital tori with greater economy and precision than
the M16 torus code, wrappers for which were included in the original release
of
agama

(
Vasiliev 2019
)
. Significant upgrades include cleaner, more
effective point transformations and the use of angle-action coordinates from
both harmonic-oscillators and isochrones. The improved toy maps enable the new code to
construct tori that cannot be constructed by the old code. Construction of
tori by interpolation now works faultlessly.

The new code includes an action finder that is more
accurate than the Stäckel Fudge as well as a suite of functions for connecting
models to observational data.

We have shown how orbits can be generated and used as either time series or
density distributions with a handful of statements. We have similarly
illustrated the generation of surfaces of section, both of the familiar

(R,v_{R})
type and ones defined in toy angle-action space which can help
understand the structure of phase space.

As an illustration of the practical use of tori, we showed how tidal streams
can be economically modelled with tori. The plethora of tidal streams that
have recently been catalogued in the Galactic halo
(
Ibata et al. 2024
)
offer a
unique opportunity to constrain the Galaxy’s potential and dark-matter
distribution, but to take advantage of this opportunity we must be able to
model observed streams in trial Galaxy potentials cheaply.
Section
4
showed that tori make it possible to reproduce in a
matter of seconds on a laptop a tidal stream produced by an N-body
integration.

In a second exercise the new action finder was used to compute
actions along the GD1 stream using recently published observational data and
three trial potentials. The recovered actions vary slowly and within narrow
ranges as is to be expected for a stream, but energy and
J_{\phi}
(which is
independent of the potential) appears to increase rather than decrease in the
direction of stellar motion, which is contrary to expectations. However,
negligible adjustments to the published distances suffice to make
J_{\phi}

exactly constant along the stream and
E
nearly constant.

Section
4
on streams illustrated the use of new
agama
b classes that facilitate comparisons between models and observational data.
These classes are more fully explained in Appendix
A
– they
include facilities for switching between heliocentric and galactocentric
coordinates, sampling lines of sight both within our Galaxy and through
external galaxies, even in the presence of dust.

Much of the code can be accessed via Python through wrappers that are
illustrated in Section
5
. Section
7

explained how tori are generated, both by minimising the variance of the
Hamiltonian and by interpolation, and explained the algorithm behind the new
action finder.

Classically, galaxy models have been constructed by two distinct routes: (i)
predicate a DF such as
f(E)
or
f(E,L_{z})
and then find the corresponding
density
\rho({\bf x})
and kinematics by integrating over
{\bf v}

(
King 1966
;
Rowley 1988
, e.g.)
, and (ii) predicate the potential

\Phi({\bf x})
, integrate orbits in it and seek weights for the orbits that are
consistent with
\Phi
and data
(e.g.
Schwarzschild 1979
;
Santucci et al. 2024
, and references
therein)
. The first approach has been extended
to replace
E
by actions
(
Binney 2014
;
Binney & Piffl 2015
;
Binney & Vasiliev 2024
, e.g.)

and the time is ripe to adapt the second approach to replace orbits by tori.
Indeed, the
density
and
containsPoint
methods of the class
Torus
makes Schwarzschild modelling a natural application of tori. It is
easier to sample orbit space systematically by constructing tori at the nodes
of a three-dimensional grid than by integrating orbits from the nodes of a
grid of points in six-dimensional phase space, and tori are much more
economically
stored than the long integrations that are necessary to ensure adequate
coverage of phase space. Moreover, a torus-based model’s resolution can be
enhanced by interpolating between the grid’s tori, and the final model is
easier to interpret if it comprises the weights of tori on a regular grid in
action space than the weights of orbits. Notwithstanding these apparent
advantages, to date all action-based modelling has been based on specified,
analytic DFs rather than on orbit/torus weights. The opportunities and
pitfalls associated with models that are described by a large number of orbit
weights are quite different from those associated with analytic DFs, so
Schwarzschild modelling with tori should be tried.

Torus mapping yields an integrable Hamiltonian that is as close as any to a
given Hamiltonian, and thus provides a unique framework for perturbation
theory
(
Kaasalainen 1994
)
.
Binney 2016
introduced the
rTorus

class to the old torus-mapping code library
(
Binney & McMillan 2016
)
and

Binney 2018
used this
class to study orbit trapping by the Galactic bar. When
agama
b has been
extended to include a class
rTorus
, it promises to be a powerful probe of the
role of resonant trapping in galactic dynamics.

An interface with observational data

Here we explain the contents of

b’s

Models are created in galactocentric coordinates while observational data is

right-ascension and declination
(\alpha,\delta)
or in Galactic longitude
and latitude
(\ell,b)
, are packaged into a struct
PosSky
. This struct
includes a bool

that’s set true if the coordinates are

(\alpha,\delta)
and false otherwise. So we write

PosSky ad(30,40,true);

PosSky lb(30,40);

where the second declaration doesn’t need a third argument because

is false by default. Angles are input and stored in degrees
rather than radians. The members of

are

and

regardless of the value of

, so after the above line

equals

deg.

Proper motions, in
\,\mathrm{mas\,yr}^{-1}
, are stored in a struct
VelSky
that likewise
has a bool

. Proper motion in the
\alpha
direction is
understood to be
\mu_{\alpha}=\dot{\alpha}\cos\delta
and similarly for

\mu_{\ell}
. Positions and proper motions are stored in a struct

, which has two components,

and

. Hence we might

VelSky muad(4.1,0.2,true);

We could have achieved the same result by writing

Transfer between equatorial and Galactic coordinates are done by functions

and

will be the proper motion in

. Attempts to mix positions in equatorial coordinates with proper motions
in Galactic coordinates, or to transfer coordinates into their own system
provoke error messages.

An instance of the class

is used to move between
heliocentric coordinates and phase-space locations. An instance contains
the adopted phase-space location of the Sun.
If we execute

the Sun will be taken to be at

\displaystyle(x,y,z)

\displaystyle=(-8.27,0,0.025)\,\mathrm{kpc}

(51)

\displaystyle(v_{x},v_{y},v_{z})

\displaystyle=(14,251.3,7)\,\mathrm{km\,s}^{-1}

(52)

A different location can be set by instead executing

where

is something like

..,..,12*intUnits.from_kms,..,..);

Given a distance
s
(in kpc) and a line-of-sight velocity

(in

\,\mathrm{km\,s}^{-1}
) we obtain a star’s phase-space location from

Sky positions can be specified in either equatorial or Galactic coordinates
– the calculations are carried out in Galactic coordinates preceded by a
call to

if necessary. Positions in cylindrical coordinates
can be obtained by replacing

with

. These functions will
also process positions alone as in

where

is the distance in kpc.

To obtain sky coordinates from

where

is a phase-space location (in either Cartesian or cylindrical

will be its distance (in kpc). If we just want the

. To obtain complete heliocentric

The component of the Sun’s velocity towards a sky location is obtained by

If we know the star’s distance, we can obtain the proper motion and
line-of-sight velocity that would be
measured if the Sun were stationary in the Galaxy’s rest frame from

A.2
Dust

A minimal dust model can be created by executing
