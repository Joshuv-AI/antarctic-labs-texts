Storm250-L2 : A Storm-Centric 250 m 250\text{\,}\mathrm{m} NEXRAD Level-II Dataset for High-Resolution ML Nowcasting
Andy Shi

Abstract
Machine learning based precipitation nowcasting relies on high-fidelity radar reflectivity sequences to model the short-term evolution of convective storms. However, the development of models capable of predicting extreme weather has been constrained by the coarse resolution ( 1 1\text{\,} – 2 km 2\text{\,}\mathrm{k}\mathrm{m} ) of existing public radar datasets, such as SEVIR, HKO-7, and GridRad-Severe, which smooth the fine-scale structures essential for accurate forecasting. To address this gap, we introduce Storm250-L2 , a storm-centric radar dataset derived from NEXRAD Level-II and GridRad-Severe data. We algorithmically crop a fixed, high-resolution ( 250 m 250\text{\,}\mathrm{m} ) window around GridRad-Severe storm tracks, preserve the native polar geometry, and provide temporally consistent sequences of both per-tilt sweeps and a pseudo-composite reflectivity product. The dataset comprises thousands of storm events across the Continental U.S., packaged in HDF5 tensors, rich context metadata, and reproducible manifests.

radar nowcasting, NEXRAD Level-II, severe weather, machine learning datasets, precipitation

1.4
This Work: The
Storm250-L2
Dataset

We present
Storm250-L2
, a new dataset designed to address the resolution gap in ML-ready radar data. Our approach is centered on three key design principles: storm-centricity, native super-resolution, and ML-ready packaging. Instead of providing continental-scale mosaics, we use GridRad-Severe storm tracks to algorithmically identify and crop individual convective events. Within this focused area, we extract super-resolution (
250\text{\,}\mathrm{m}
) reflectivity data directly from single-site NEXRAD Level-II archives, preserving the native polar geometry of the radar sweeps. This provides a direct, high-fidelity view of storm evolution, free from the smoothing inherent in national composites.

The dataset provides sequences of both native polar sweeps and a derived pseudo-composite reflectivity product, enabling research into both volumetric and 2D nowcasting. Each event is packaged into HDF5 tensors with consistent dimensions (Time, Height, Width, Channels), accompanied by a rich context table and a self-describing JSON schema for ease of use. The pipeline is reproducible and includes integrity manifests and catalogs. We isolate individual convective events at native resolution, enabling models to learn fine-scale reflectivity evolution directly from the source Level-II data.

Contributions.

Our contributions are as follows:

1.

We introduce a storm-centric,

2.

3.

Limitations (alpha release).

We transparently disclose:

2.

No advanced radar quality control (e.g., clutter, attenuation, bright band).

3.

Closing.

Storm250-L2
enables ML researchers to experiment with sub-kilometer radar inputs for nowcasting—a step toward resolving convective dynamics at their native scales. By bridging high-resolution radar physics and data-driven prediction, this dataset aims to improve the fidelity of forecasts for high-impact weather events.

Dataset Description

This section details the composition and construction of the
Storm250-L2
dataset; the dataset is built to provide native
250\text{\,}\mathrm{m}
resolution data, addressing the resolution gap in existing nowcasting benchmarks. The following subsections describe the dataset’s structure, event selection criteria, storm-centric processing methodology, and data representation.

2.1
Dataset Structure

The fundamental unit of
Storm250-L2
is a
storm event
. Each event captures the complete life cycle of a convective storm as a consistent, high-resolution sequence. An event is defined by a storm track from the GridRad-Severe (GR-S) dataset, which provides a spatiotemporal scaffold, and a series of matched NEXRAD Level-II radar volumes.

Each event is packaged into two core components:

Product Tensors:
The primary radar data, stored in HDF5 files as a 4D tensor of shape
(T,H,W,C)
, where
T
is the number of time steps (typically 10–20 volumes),
H
the number of azimuth rays,
W
the number of range gates, and
C
the number of channels (i.e., radar tilts;
C{=}1
for the provided pseudo-composite product). The data preserve the native polar coordinate system of the WSR-88D radar, maintaining the original
250\text{\,}\mathrm{m}
range gate spacing without Cartesian resampling.

Context Metadata:
A companion table, stored in a separate HDF5 file with a JSON schema. This table provides per-timestep contextual information sourced directly from the GR-S dataset, including storm location, motion vectors, echo-top heights, and severe weather labels, using the original GR-S schema for interoperability.

2.2
Event Selection & Composition

Data Sources:
The dataset is built from two primary sources: (1) NEXRAD Level-II data from the AWS Open Data registry, providing the core
250\text{\,}\mathrm{m}
super-resolution reflectivity observations
[
9
]
, and (2) GridRad-Severe (GR-S) storm tracks, which serve to identify and localize convective events
[
6
]
.

Selection Criteria:
A GR-S track becomes an eligible
Storm250-L2
event only if it meets the following criteria:

•

It is consistently observed by a single NEXRAD radar site.

•

All track points are within
250\text{\,}\mathrm{k}\mathrm{m}
of that radar.

•

The track is continuous, with a minimum of
\sim
60 samples (roughly one hour) and no internal gaps exceeding 6 hours.

Temporal Alignment:
For each timestamp in a GR-S track, we find the closest NEXRAD volume within a
\pm
29 s tolerance, preserving the radar’s native 4–6 minute cadence without interpolation. The final number of time steps
T
for an event is the count of successfully matched and processed radar volumes.

2.3
Storm-Centric Processing & Cropping

Instead of providing continental-scale mosaics for storm events,
Storm250-L2
provides a focused, storm-centric view. For each event we algorithmically define a single, stationary geographic window that encompasses the storm for its entire lifecycle.

Reflectivity Composite Creation:
For each matched radar volume, we create a robust 2D view by taking the maximum reflectivity value across all elevation tilts at every range gate.

Storm Identification:
This composite is projected to a
250\text{\,}\mathrm{m}
grid, and the main storm “blob” is identified at each time step using connected-component labeling on values
\geq

20\text{\,}\mathrm{d}\mathrm{B}\mathrm{Z}
.

Figure 2

Example of the storm-centric blob identification applied to a single convective event. The identified storm-centric blob is highlighted by the dashed-red outline.

Optimal Window Fitting:
A single, fixed window for the entire event is calculated by optimizing the coverage of the storm at the beginning and end of its life cycle. This ensures that the entire evolution of the storm remains within the frame.

Figure 3
:
Illustration of the window optimization procedure applied across all time steps of a storm event. Gray boxes represent the per-timestep storm bounds identified in the Storm Identification step. The dashed red rectangle denotes the final optimized window that minimally encloses all identified storm blobs across the storm’s life cycle.

Native-Coordinate Cropping:
All radar data for the event are cropped to this fixed window directly in the native polar coordinate system. The crop focuses the data on the region of interest, reduces file size, and minimizes noise for ML models. Retaining the native polar coordinate system avoids the smoothing artifacts of Cartesian remapping and preserves the full
250\text{\,}\mathrm{m}
radial resolution. A
5\text{\,}\mathrm{k}\mathrm{m}
buffer is added to avoid cutting off storm edges.

2.4
Data Representation & Integrity

File Format:
Data are stored in HDF5 format with GZIP compression. Filenames are descriptive, encoding the radar site, storm ID, dimensions, and time range (e.g.,

KTLX_12345_reflectivity_T12_360x400x1ch_20200504T220000Z_20200504T234500Z.h5
).

Provenance & Reproducibility:
Full traceability is maintained. Each volume in the HDF5 tensor records the exact AWS S3 key of its source NEXRAD file. The processing pipeline generates comprehensive integrity manifests (SHA-256 checksums) and a summary catalog for the entire dataset.

Access:
The dataset will be hosted on Zenodo, packaged by year and radar site, and include software and documentation.

2.5
Known Limitations

This initial release of
Storm250-L2
focuses on providing high-fidelity reflectivity data. Users should be aware of the following limitations, which also represent opportunities for future work:

•

Reflectivity only; dual-polarization variables and radial velocity are not included.

•

No advanced radar quality control (e.g., attenuation, clutter, or the bright band). Users may wish to apply their own QC filters.

•

Event selection is dependent on the coverage and definitions of the GR-S catalog.
