From Language Models over Tokens to Language Models over Characters
Tim Vieira Ben LeBrunMario GiulianelliJuan Luis GastaldiBrian DuSellJohn Terilla, Timothy J. O’DonnellRyan Cotterell ETH ZürichMila -- Quebec Artificial Intelligence InstituteMcGill UniversityCity University of New YorkCanada CIFAR AI Chair, Mila

Abstract
Modern language models are internally—and mathematically—distributions over token strings rather than character strings, posing numerous challenges for programmers building user applications on top of them. For example, if a prompt is specified as a character string, it must be tokenized before passing it to the token-level language model. Thus, the tokenizer and consequent analyses are very sensitive to the specification of the prompt (e.g., if the prompt ends with a space or not). This paper presents algorithms for converting token-level language models to character-level ones. We present both exact and approximate algorithms. In the empirical portion of the paper, we benchmark the practical runtime and approximation quality. We find that—even with a small computation budget—our method is able to accurately approximate the character-level distribution (less than 0.00021 excess bits / character) at reasonably fast speeds (46.3 characters / second) on the Llama 3.1 8B language model. https://github.com/rycolab/token-to-char-lm

The token healing heuristic:

token-healing
present
token healing
as a heuristic that mitigates the prompt boundary problem. Token healing works as follows:
(1) Tokenize (i.e., encode) the prompt.
(2) Backup the tokenized prompt to the penultimate token.
(3) Generate the next token subject to the constraint that it starts with the unmatched substring at the end of the prompt.
(4) Continue generating as usual.

2.3
Tokenization

We now discuss our basic formalization for tokenization.

Definition 1
.

An
(exact) tokenization model
is a tuple
({\color[rgb]{0.3828,0.4492,0.0742}\Sigma},{\color[rgb]{0.5508,0.0391,0.3477}\Delta},{\color[rgb]{0.5508,0.0391,0.3477}\tau},{\color[rgb]{0.3828,0.4492,0.0742}\kappa})
where

•

{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}
is an alphabet of
character
symbols

•

{\color[rgb]{0.5508,0.0391,0.3477}\Delta}
is an alphabet of
token
symbols

•

{\color[rgb]{0.5508,0.0391,0.3477}\tau}
is a (possibly) stochastic
encoder
:
{\color[rgb]{0.5508,0.0391,0.3477}\tau}(\cdot\mid{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}})
is a probability distribution over
{\color[rgb]{0.5508,0.0391,0.3477}{\color[rgb]{0.5508,0.0391,0.3477}\Delta}^{*}}
for each
{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}\in{\color[rgb]{0.3828,0.4492,0.0742}{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}^{*}}

•

{\color[rgb]{0.3828,0.4492,0.0742}\kappa}\colon{\color[rgb]{0.5508,0.0391,0.3477}{\color[rgb]{0.5508,0.0391,0.3477}\Delta}^{*}}\to{\color[rgb]{0.3828,0.4492,0.0742}{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}^{*}}
is a
decoder
function mapping token strings to character strings satisfying

\sum_{{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}\in{\color[rgb]{0.5508,0.0391,0.3477}{\color[rgb]{0.5508,0.0391,0.3477}\Delta}^{*}}}\mathbbm{1}\left\{{\color[rgb]{0.3828,0.4492,0.0742}\kappa}({\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}})={\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}\right\}{\color[rgb]{0.5508,0.0391,0.3477}\tau}({\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}\mid{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}})=1,\quad\text{ for all }{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}\in{\color[rgb]{0.3828,0.4492,0.0742}{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}^{*}}

(6)

The condition between
{\color[rgb]{0.5508,0.0391,0.3477}\tau}
and
{\color[rgb]{0.3828,0.4492,0.0742}\kappa}
expressed in
Equation

6
is called

. One may consider more general tokenization models in which
{\color[rgb]{0.3828,0.4492,0.0742}\kappa}
is possibly stochastic and for which

6
may not hold.
All tokenization models considered in this paper will be exact and will be called simply

rather than

Definition 2
.

A
tokenized language model

p_{{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}}
is a language model over
{\color[rgb]{0.3828,0.4492,0.0742}{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}^{*}}
that is
parameterized
by a language model
p_{{\color[rgb]{0.5508,0.0391,0.3477}\Delta}}
over
{\color[rgb]{0.5508,0.0391,0.3477}{\color[rgb]{0.5508,0.0391,0.3477}\Delta}^{*}}
and a decoding function
{\color[rgb]{0.3828,0.4492,0.0742}\kappa}\colon{\color[rgb]{0.5508,0.0391,0.3477}{\color[rgb]{0.5508,0.0391,0.3477}\Delta}^{*}}\to{\color[rgb]{0.3828,0.4492,0.0742}{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}^{*}}
.
This tokenized language model generates character strings via the following process: (i)
{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}\sim p_{{\color[rgb]{0.5508,0.0391,0.3477}\Delta}}
, (ii)
{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}\leftarrow{\color[rgb]{0.3828,0.4492,0.0742}\kappa}({\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}})
.
Thus, the character strings
{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}
generated have the following distribution:

p_{{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}}({\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}})\mathrel{\overset{\raisebox{-0.75346pt}{{def}}}{=}}\mathop{\mathbb{P}}_{\begin{subarray}{c}{\color[rgb]{0.5508,0.0391,0.3477}Y}\sim p_{{\color[rgb]{0.5508,0.0391,0.3477}\Delta}}\end{subarray}}\left[{\color[rgb]{0.3828,0.4492,0.0742}\kappa}({\color[rgb]{0.5508,0.0391,0.3477}Y})={\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}\right],\qquad\forall{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}\in{\color[rgb]{0.3828,0.4492,0.0742}{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}^{*}}

(7)

Note that
p_{{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}}({\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}})
accounts for the fact that many token strings may be associated with a given character string through
{\color[rgb]{0.3828,0.4492,0.0742}\kappa}

13

13

Many authors
(
cao-rimell-2021-evaluate

chirkova-etal-2023-marginalize
;

have discussed the particular complications introduced by the fact that for a given character string of length

To describe that association, we define

denote the set of
encodings
for any character string
{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}\in{\color[rgb]{0.3828,0.4492,0.0742}{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}^{*}}
.

14

Note that

What about
{\color[rgb]{0.5508,0.0391,0.3477}\tau}
?

The reader may notice that
{\color[rgb]{0.5508,0.0391,0.3477}\tau}
does not appear in

Moreover, attempts to leverage

We note that under exactness (

The mirage of the canonical tokenization.

Consider the case when the encoder
{\color[rgb]{0.5508,0.0391,0.3477}\tau}
is deterministic.
In that case, we write
{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}={\color[rgb]{0.5508,0.0391,0.3477}\tau}({\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}})

{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}
the
canonical
tokenization of
{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}
.
Note that even if
{\color[rgb]{0.5508,0.0391,0.3477}\tau}

{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}^{\prime}\neq{\color[rgb]{0.5508,0.0391,0.3477}\tau}({\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}})

over the encodings
{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}
of a character string
{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}
tends to be highly concentrated around the canonical tokenizations, as illustrated in

2.4
Useful Properties of
{\color[rgb]{0.3828,0.4492,0.0742}\kappa}

This section provides a collection of definitions and basic results that are useful for characterizing tokenizers. We aim to capture only the essential properties of tokenizers, such as BPE, while committing to as few of its nuances as possible, as it will allow us to future-proof our methods.

Definition 3
.

We say that
{\color[rgb]{0.3828,0.4492,0.0742}\kappa}\colon{\color[rgb]{0.5508,0.0391,0.3477}{\color[rgb]{0.5508,0.0391,0.3477}\Delta}^{*}}\to{\color[rgb]{0.3828,0.4492,0.0742}{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}^{*}}
is
prefix monotone
if
{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}\preceq{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}^{\prime}\implies{\color[rgb]{0.3828,0.4492,0.0742}\kappa}({\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}})\preceq{\color[rgb]{0.3828,0.4492,0.0742}\kappa}({\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}^{\prime})
and
strict-prefix monotone
if
{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}\prec{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}^{\prime}\implies{\color[rgb]{0.3828,0.4492,0.0742}\kappa}({\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}})\prec{\color[rgb]{0.3828,0.4492,0.0742}\kappa}({\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}^{\prime})

In simpler terms, strict-prefix monotonicity says that concatenating a token to the encoding necessarily concatenates at least one character to the decoded character string.

This section gives algorithms for

{\overrightarrow{p_{{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}}}}({\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}})
,
{\overrightarrow{p_{{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}}}}({\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}^{\prime}\mid{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}})
,
{\overrightarrow{p_{{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}}}}({\textsc{eos}}\mid{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}})
, and conditional token generation (i.e., our solution to the prompt boundary problem).
Unlike prior papers
(
cao-rimell-2021-evaluate

chirkova-etal-2023-marginalize

3.1
Covering

Our primary tool for the prefix probability
{\overrightarrow{p_{{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}}}}({\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}})
is the covering of
{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}
. It is a subset of tokens associated with the given string
{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}
that is sufficient to evaluate its prefix probability. As we will see experimentally (
), this set’s subset of high-probability token strings is often small enough to enumerate.

Equation

12
shows that we can, in principle, compute the prefix probability
{\overrightarrow{p_{{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}}}}({\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}})
by summing over
prefix-encodings
of
{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}
,
{\color[rgb]{0.5508,0.0391,0.3477}\mathcal{P}}({\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}})\mathrel{\overset{\raisebox{-0.75346pt}{{def}}}{=}}\left\{{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}\in{\color[rgb]{0.5508,0.0391,0.3477}{\color[rgb]{0.5508,0.0391,0.3477}\Delta}^{*}}\colon{\color[rgb]{0.3828,0.4492,0.0742}\kappa}({\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}})\succeq{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}\right\}
. Unfortunately,
{\color[rgb]{0.5508,0.0391,0.3477}\mathcal{P}}({\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}})
is infinitely large. Fortunately, we can exploit the prefix monotone structure of
{\color[rgb]{0.3828,0.4492,0.0742}\kappa}
to find a different way to perform the summation by summing over a
finite
set.

Let
{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}\in{\color[rgb]{0.5508,0.0391,0.3477}{\color[rgb]{0.5508,0.0391,0.3477}\Delta}^{*}}
, and
{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}\in{\color[rgb]{0.3828,0.4492,0.0742}{\color[rgb]{0.3828,0.4492,0.0742}\Sigma}^{*}}
.
We say that
{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}

covers

{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}
if and only if
{\color[rgb]{0.3828,0.4492,0.0742}\kappa}({\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}})\succeq{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}
.
Monotonicity ensures that for all
{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}\in{\color[rgb]{0.5508,0.0391,0.3477}\mathcal{P}}({\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}})
, we have that
\forall{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}^{\prime}\in{\color[rgb]{0.5508,0.0391,0.3477}{\color[rgb]{0.5508,0.0391,0.3477}\Delta}^{*}}\colon{\color[rgb]{0.3828,0.4492,0.0742}\kappa}({\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}{\cdot}{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}^{\prime})\succeq{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}
. In other words, any
{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}
that decodes to an extension of
{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}
(i.e.,
{\color[rgb]{0.3828,0.4492,0.0742}\kappa}({\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}})\succeq{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}
) will continue to do so if we append tokens to it.
Thus, we may additionally qualify the relationship as
{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}

minimally covers

{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}
if and only if
{\color[rgb]{0.3828,0.4492,0.0742}\kappa}({\color[rgb]{0.5508,0.0391,0.3477}\delta}_{1}\cdots{\color[rgb]{0.5508,0.0391,0.3477}\delta}_{M-1})\prec{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}
. With that in mind, we define
{\color[rgb]{0.5508,0.0391,0.3477}\phi}_{{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}}({\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}})
as the
shortest
prefix
{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}^{\prime}\preceq{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}
such that
{\color[rgb]{0.3828,0.4492,0.0742}\kappa}({\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}^{\prime})\succeq{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}
, i.e., it maps any
{\color[rgb]{0.5508,0.0391,0.3477}\boldsymbol{\delta}}
that covers
{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}
to a (possibly equal) token string that minimally covers
{\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}}
. Next, we define the set of
minimal
prefix encodings of
{\color[rgb]{0.5508,0.0391,0.3477}\mathcal{C}}({\color[rgb]{0.3828,0.4492,0.0742}\boldsymbol{\sigma}})
, which we call the
covering
of
