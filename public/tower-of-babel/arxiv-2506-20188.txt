DefElement: an encyclopedia of finite element definitions
Matthew W. Scroggs 0000-0002-4658-2443, Pablo D. Brubeck 0000-0002-3824-0080, Joseph P. Dean 0000-0001-7499-3373, Jørgen S. Dokken 0000-0001-6489-8858, India Marsden 0009-0006-0152-4780

Abstract
DefElement is an online encyclopedia of finite element definitions that was created and is maintained by the authors of this paper. DefElement aims to make information about elements defined in the literature easily available in a standard format. There are a number of open-source finite element libraries available, and it can be difficult to check that an implementation of an element in a library matches the element’s definition in the literature or implementation in another library, especially when many libraries include variants of elements whose basis functions do not match exactly. In this paper, we carefully derive conditions under which elements can be considered equivalent and describe an algorithm that uses these conditions to verify that two implementations of a finite element are indeed variants of the same element. The results of scheduled runs of our implementation of this verification algorithm are included in the information available on DefElement.

The finite element method has its origins in the 1940s, when methods involving the meshing of a domain began to be used by engineers

The most widely used abstract definition of a finite element is the Ciarlet definition
Ciarlet 1978
, which is as follows.

Definition 2

(Ciarlet finite element)
.

A finite element is defined by the triple

(R,\mathcal{V},\mathcal{L})
, where

•

R\subset\mathbb{R}^{d}
is the reference cell, usually an interval, polygon or polyhedron;

•

\mathcal{V}
is a finite dimensional space on
R

of dimension
n
, usually a space of polynomials;

•

\mathcal{L}:=\{l_{0},\dots,l_{n-1}\}
is a basis of the dual space

\mathcal{V}^{*}:=\{f:\mathcal{V}\to\mathbb{R}\,|\,f\text{ is linear}\}
.
Each functional
l_{i}
is associated with a sub-entity of the reference cell
R
. A functional

f\in\mathcal{L}
associated with a sub-entity
E\subseteq R
only depends on a function’s value
restricted to
E
, i.e. if
\left.p\right|_{E}=\left.q\right|_{E}
then
f(p)=f(q)
.

The basis functions
\{\phi_{0},\dots,\phi_{n-1}\}
of the finite element are
defined by

l_{i}(\phi_{j})=\delta_{ij}:=\begin{cases}1&i=j,\\
0&i\not=j.\end{cases}

Sometimes, it is not desirable to define the finite element on a reference cell and map the basis functions to each cell. In
this case, the finite element can be defined directly on the physical cell in the mesh using the following definition.

Definition 3

(Direct finite element)
.

A direct finite element is defined by the triple

(C,\mathcal{V},\mathcal{L})
, where

•

C\subset\mathbb{R}^{d_{g}}
is a
d
-dimensional cell in a mesh;

•

\mathcal{V}
is a finite dimensional space on
C

of dimension
n
, usually a space of polynomials;

•

\mathcal{L}:=\{l_{0},\dots,l_{n-1}\}
is a basis of the dual space

\mathcal{V}^{*}:=\{f:\mathcal{V}\to\mathbb{R}\,|\,f\text{ is linear}\}
.
As in
definition

2
, each functional is associated with a sub-entity of
C
.

The basis functions
\{\phi_{0},\dots,\phi_{n-1}\}
of the direct finite element are
defined by

l_{i}(\phi_{j})=\delta_{ij}.

In both definitions, the value
d
is called the topological dimension. This may differ from the geometric dimension
d_{g}
if, for example,
a mesh of triangular cells is embedded in three-dimensional space. The
value shape
of a finite element is defined
to be the shape of the range space of the polynomials in
\mathcal{V}
. For example,
if
\mathcal{V}
is a set of vector-valued functions in
\{f\,|\,f:R\to\mathbb{R}^{3}\}
then the value shape is
(3)
;
if
\mathcal{V}
is a set of matrix-valued functions in
\{f\,|\,f:R\to\mathbb{R}^{2\times 2}\}
then the value shape is
(2,2)
.
The
value size
of a finite element is defined to be the product of all the entries of the value shape, and equal to 1
if the element is scalar-valued.

For Ciarlet elements, a geometric map
g
is defined that maps points on the reference cell
to points on a physical cell and
a push forward map is defined that maps the basis functions on the
reference cell to functions on a physical cell

Rognes et al. 2009
;
Arnold et al. 2005
;
Kirby 2018
. The push forward map for an element is
chosen so that it preserves specific properties of the element’s basis functions.
The inverse map from a physical cell to the reference cell is called the pull back map.
For some elements (such as serendipity
Arnold and Awanou 2011
), better
convergence is achieved if the geometric map is affine, as defined as follows.

Definition 4

(affine transformation)
.

Let
g:R\to\mathbb{R}^{d_{g}}
be a geometric map.

g
is affine if there exist
a translation
g_{1}:R\to\mathbb{R}^{d}

and a linear transformation
g_{2}:\mathbb{R}^{d}\to\mathbb{R}^{d_{g}}
such that

g=g_{2}\circ g_{1}
.

The functionals
l_{i}\in\mathcal{L}
are the (local) degrees-of-freedom (DOFs) of the finite
element (note that we enumerate functionals and basis functions starting at 0).
When a finite element function space is defined on a mesh, we associate a global DOF number
with each local DOF on each cell. To ensure that the mapped
space has the desired continuity properties, corresponding local DOFs on neighbouring cells
that are associated with a shared sub-entity are assigned the same global DOF.

We note that associating each functional with a sub-entity of the reference cell was not included
in Ciarlet’s original definition of a finite element, but it is now common to include this as
this association is an important part of most finite element implementations, as it allows for
continuity between cells to be naturally implemented.
For continuity to be effectively imposed in this way, it is common to make some additional assumptions about the finite element.
Before stating these assumptions, we first define equivalent sets of functionals.

Definition 5

(equivalent sets of functionals)
.

Let
\mathcal{L}=\{l_{0},\dots,l_{a-1}\}
and
\tilde{\mathcal{L}}=\{\tilde{l}_{0},\dots,\tilde{l}_{b-1}\}
be two sets of functionals associated with entities
E
and
\tilde{E}
.
Let
\{\phi_{0},\dots,\phi_{a-1}\}
and
\{\tilde{\phi}_{0},\dots,\tilde{\phi}_{b-1}\}
be the finite element basis functions corresponding to the functionals in
\mathcal{L}
and
\tilde{\mathcal{L}}
.
The sets of functionals
\mathcal{L}
and
\tilde{\mathcal{L}}
are equivalent if:

•

they have the same size (i.e.
a=b
);

•

there exists a push forward map
\mathcal{F}
such that for all
i=0,\dots,a-1
,

\tilde{l}_{i}(\mathcal{F}\phi_{j})=\delta_{ij}.

For sets of functionals associated with the same sub-entity, the following lemma will be useful.

Lemma 1
.

Let
\mathcal{L}=\{l_{0},\dots,l_{a-1}\}
and
\tilde{\mathcal{L}}=\{\tilde{l}_{0},\dots,\tilde{l}_{a-1}\}
be two sets of functionals associated with entity
E
.
If
\operatorname{span}\mathcal{L}=\operatorname{span}\tilde{\mathcal{L}}
, then
\mathcal{L}
and
\tilde{\mathcal{L}}
are equivalent sets of functionals.

Proof.

As
\operatorname{span}\mathcal{L}=\operatorname{span}\tilde{\mathcal{L}}
, there exists a non-singular matrix
\boldsymbol{\mathrm{A}}\in\mathbb{R}^{a\times a}
such that

\begin{pmatrix}\tilde{l}_{0}\\
\vdots\\
\tilde{l}_{a-1}\end{pmatrix}=\boldsymbol{\mathrm{A}}\begin{pmatrix}l_{0}\\
\vdots\\
l_{a-1}\end{pmatrix}.

(1)

Let
\{\phi_{0},\dots,\phi_{a-1}\}
be the finite element basis functions corresponding to the functionals in
\mathcal{L}
.
The aim is to show that the second bullet point in
definition

5
is true; which holds if we define
\mathcal{F}
as

\begin{pmatrix}\mathcal{F}\phi_{0}\\
\vdots\\
\mathcal{F}\phi_{a-1}\end{pmatrix}=\boldsymbol{\mathrm{A}}^{-\mathsf{T}}\begin{pmatrix}\phi_{0}\\
\vdots\\
\phi_{a-1}\end{pmatrix}.

As the functionals
\tilde{l}_{i}
are linear, we can write

\begin{pmatrix}\tilde{l}_{0}(\mathcal{F}\phi_{0})&\dots&\tilde{l}_{a-1}(\mathcal{F}\phi_{0})\\
\vdots&\ddots&\vdots\\
\tilde{l}_{0}(\mathcal{F}\phi_{a-1})&\dots&\tilde{l}_{a-1}(\mathcal{F}\phi_{a-1})\\
\end{pmatrix}=\boldsymbol{\mathrm{A}}^{-\mathsf{T}}\begin{pmatrix}\tilde{l}_{0}(\phi_{0})&\dots&\tilde{l}_{a-1}(\phi_{0})\\
\vdots&\ddots&\vdots\\
\tilde{l}_{0}(\phi_{a-1})&\dots&\tilde{l}_{a-1}(\phi_{a-1})\\
\end{pmatrix}.

Using
eq.

1

\displaystyle\begin{pmatrix}\tilde{l}_{0}(\mathcal{F}\phi_{0})&\dots&\tilde{l}_{a-1}(\mathcal{F}\phi_{0})\\
\vdots&\ddots&\vdots\\
\tilde{l}_{0}(\mathcal{F}\phi_{a-1})&\dots&\tilde{l}_{a-1}(\mathcal{F}\phi_{a-1})\\
\end{pmatrix}

\displaystyle=\boldsymbol{\mathrm{A}}^{-\mathsf{T}}\begin{pmatrix}l_{0}(\phi_{0})&\dots&l_{a-1}(\phi_{0})\\
\vdots&\ddots&\vdots\\

\displaystyle=\boldsymbol{\mathrm{A}}^{-\mathsf{T}}\boldsymbol{\mathrm{I}}\boldsymbol{\mathrm{A}}^{\mathsf{T}}

\displaystyle=\boldsymbol{\mathrm{A}}^{-\mathsf{T}}\boldsymbol{\mathrm{A}}^{\mathsf{T}}

\displaystyle=\boldsymbol{\mathrm{I}}.

It is common to make a few further assumptions about Ciarlet finite elements to allow the elements
to be mapped from the reference cell to every physical cell in an unstructured mesh.
First, the following assumption is often made:

Assumption 1
.

Each sub-entity of the same type (e.g. each sub-entity that is a triangle) has an equivalent set of functionals associated with it.

This assumption allows neighbouring cells to be attached by any sub-entity of the same type,
as each sub-entity of the given type will have an equivalent set of DOFs.

1
is true of the vast majority of finite elements, but it not true of some such as
transition elements, where different polynomial degrees are used on different sub-entities,
and Fortin–Soulie elements
Fortin and Soulie 1983
, where there are two DOFs associates with two edges
of the reference triangle but only one DOF associated with the third edge.

A second common assumption is as follows:

Assumption 2
.

Let
E
be a sub-entity of
R
, let
g:E\to E
be an affine bijection, and

\mathcal{F}_{g}
be the push forward corresponding to
g
.
If
\phi_{a},\dots,\phi_{b}
are the basis functions associated with the sub-entity
E
, then

\operatorname{span}\left\{\mathcal{F}_{g}(\left.\phi_{a}\right|_{E}),\dots,\mathcal{F}_{g}(\left.\phi_{b}\right|_{E})\right\}=\operatorname{span}\left\{\left.\phi_{a}\right|_{E},\dots,\left.\phi_{b}\right|_{E}\right\},

where
|_{E}
denotes the restriction of a function to the sub-entity
E
.

This assumption allows neighbouring cells to be attached in any orientation, as
any map that corresponds to a rotation or reflection of a sub-entity is affine and a bijection
(
Ern and Guermond 2021
, lemma 20.6, exercise 20.1)
,
and so
2
tells us that the space that needs to be continuous between cells
is not affected by rotating or reflecting a sub-entity. Note, however, that in an implementation
of finite elements some allowances for differences in the orientation of neighbouring cells
need to be made
Scroggs et al. 2022
.

In software implementations, it is common to compute basis functions by first computing the dual matrix

\boldsymbol{\mathrm{D}}=\begin{pmatrix}l_{0}(p_{0})&\dots&l_{n-1}(p_{0})\\
\vdots&\ddots&\vdots\\
l_{0}(p_{n-1})&\dots&l_{n-1}(p_{n-1})\end{pmatrix},

where
\{p_{0},\dots,p_{n-1}\}
is any basis of
\mathcal{V}
(often chosen to be an orthogonal basis).
Multiplying by the vector of basis functions, we see that

\boldsymbol{\mathrm{D}}\begin{pmatrix}\phi_{0}\\
\vdots\\
\phi_{n-1}\end{pmatrix}=\begin{pmatrix}\displaystyle\sum_{i=0}^{n-1}l_{i}(p_{0})\phi_{i}\\
\vdots\\
\displaystyle\sum_{i=0}^{n-1}l_{i}(p_{n-1})\phi_{i}\end{pmatrix}=\begin{pmatrix}p_{0}\\
\vdots\\
p_{n-1}\end{pmatrix},

and so the basis functions can be computed via

\begin{pmatrix}\phi_{0}\\
\vdots\\
\phi_{n-1}\end{pmatrix}=\boldsymbol{\mathrm{D}}^{-1}\begin{pmatrix}p_{0}\\
\vdots\\
p_{n-1}\end{pmatrix}.

(2)

Note that if the functions are not being computed symbolically, the values of
p_{0}(\boldsymbol{x}),\dots,p_{n-1}(\boldsymbol{x})
at
a given point
\boldsymbol{x}\in R
can be used on the right-hand side of
eq.

2
to compute the values of the basis functions at
\boldsymbol{x}
.

Note that if the basis
\{p_{0},\dots,p_{n-1}\}
was chosen to be the set of monomials
and the functionals
l_{0},\dots,l_{n-1}
were all point evaluations, then
\boldsymbol{\mathrm{D}}

would be a Vandermonde matrix with an ill-conditioned inverse
Pan 2016
.
The matrix
\boldsymbol{\mathrm{D}}
for a general finite element is sometimes called the generalised
Vandermonde matrix
(
Ern and Guermond 2021
, chapter 5)
.

2.1
Element types

In this section, we present a brief overview of commonly used types of finite element.

2.1.1
Scalar-valued elements

Scalar-valued elements are most commonly used to discretise the
H^{1}
Sobolev space, defined
for
\Omega\subset\mathbb{R}^{d}
by

H^{1}(\Omega):=\left\{f\in L^{2}(\Omega)\,\middle|\,\frac{\partial f}{\partial x_{0}},\dots,\frac{\partial f}{\partial x_{d-1}}\in L^{2}(\Omega)\right\},

where
x_{0}=x
,
x_{1}=y
,
x_{2}=z
, and

L^{2}(\Omega):=H^{0}(\Omega):=\left\{f:\Omega\to\mathbb{R}\,\middle|\,\int_{\Omega}f^{2}<\infty\right\}.

The scalar-valued Lagrange element is probably the most
widely used element and is the first element introduced in most finite element courses. The polynomial space
\mathcal{V}
of a Lagrange element
on a simplex cell is a complete polynomial space (the polynomial spaces for other cells are later defined in
definition

9
),
and its dual basis
\mathcal{L}
is a set of point evaluations.
On quadrilateral and hexahedral cells, serendipity
Arnold and Awanou 2011
elements are a second widely-used
H^{1}
-conforming finite element: their polynomial spaces

\mathcal{V}
are a smaller set of polynomials than a Lagrange element and their dual bases
\mathcal{L}
contain point evaluations at vertices and integral moments on
other sub-entities. Serendipity elements achieve the same accuracy as Lagrange elements on affine cells, but their accuracy degrades on non-affine cells
Arnold et al. 2002
.

By including derivatives in the definitions of functionals, we can enforce continuity on some derivatives of an element and create elements for
discretising
H^{2}
and higher-order spaces such as the Argyris
Argyris et al. 1968
, Bell
Bell 1969
, Hermite
Ciarlet and Raviart 1972
, Morley
Morley 1968
, Morley–Wang–Xu
Wang and Xu 2013
and Wu–Xu elements
Wu and Xu 2019
.
Note that in some older finite element literature (e.g.
Ciarlet 1978
), Hermite was used as the name for
all
finite elements with at least one derivative
included in their functionals whereas it is now widely used as the name for one specific element.

By associating all the DOFs of an element with the interior of the cell, we can create an element that is discontinuous between cells that can be used to
discretise
L^{2}
.
The discontinuous Galerkin (DG) finite element method
Arnold et al. 2002
;
Reed and Hill 1973
is often based on use of the discontinuous Lagrange element.
A number of elements can also be created that are
H^{1}
-nonconforming—they are neither fully discontinuous nor fully
C^{0}
continuous. The most widely used of these is probably the
Crouzeix–Raviart
Crouzeix and Raviart 1973
element alongside its extensions to higher polynomial degrees and quadrilaterals
Crouzeix and Falk 1989
;
Fortin and Soulie 1983
;
Rannacher and Turek 1992
.

H^{1}
-conforming scalar-valued elements typically use the identity push-forward map, also known as the push-forward by the geometric transformation. This is defined, for a scalar-valued function
\phi
, by

\left(\mathcal{F}^{\text{id}}\phi\right)(\boldsymbol{x}):=\phi(g^{-1}(\boldsymbol{x})),

where
g:R\to\mathbb{R}^{d_{g}}
is the geometric map from the reference cell
R\subset\mathbb{R}^{d}
to a physical cell.
The term
g^{-1}(\boldsymbol{x})
is the point on the reference cell corresponding to the point
\boldsymbol{x}
, so this mapping
maps a value of the function on the reference cell to the same value at the corresponding point.

L^{2}
-conforming elements—such as discontinuous Lagrange elements—use the
L^{2}
Piola push-forward that is defined, for a scalar-valued function
\phi
, by

\left(\mathcal{F}^{\text{L2}}\phi\right)(\boldsymbol{x}):=\frac{1}{\det\boldsymbol{\mathrm{J}}}\phi(g^{-1}(\boldsymbol{x})),

where
\boldsymbol{\mathrm{J}}
is the Jacobian of the transformation
g
.
When
g
is affine,
\det\boldsymbol{\mathrm{J}}
will be constant and the identity push forward
can be used (and is often used) instead of the
L^{2}
Piola push forward.
However, if
g
is not affine, then in some applications it is necessary to use the
L^{2}
Piola map
so that the basis functions maintain properties of the de Rham complex (
section

2.2
).

The mapping of elements involving derivatives in their functionals from the reference cell to a physical cell is a more
involved process
Kirby 2018
, whose detailed discussion is beyond the scope of this paper.

2.1.2
Vector-valued elements

Many problems, including those in electromagnetics
Monk 2003
and fluids
Zienkiewicz et al. 2014

involve vectors. For such problems, vector-valued finite elements can be used. Vector-valued
elements can be created by using a separate scalar-valued element for each component of the vector:
such elements are typically used to represent the geometry of a mesh, with each component of the
position of a cell typically represented by a Lagrange element. Using higher-degree elements in
the representation of geometry allows curved cells to be represented.

Vector-valued elements built from multiple copies of a scalar-valued element copy the continuity
of the scalar element—for most scalar-valued elements, this leads to vector functions whose
components are all continuous across boundaries between cells. In some cases—for example, when
representing geometry—this
C^{0}
continuity is desired, but in other cases, the discontinuity of
some components is more appropriate.

The spaces
H(\operatorname{div})
and
H(\operatorname{curl})

(
Ern and Guermond 2021
, chapter 4)

are defined for
\Omega\subset\mathbb{R}^{d}
by

\displaystyle H(\operatorname{div},\Omega)

\displaystyle:=\left\{\boldsymbol{f}\in\left(L^{2}(\Omega)\right)^{d}\,\middle|\,\operatorname{div}(\boldsymbol{f})\in L^{2}(\Omega)\right\},

\displaystyle H(\operatorname{curl},\Omega)

\displaystyle:=\left\{\boldsymbol{f}\in\left(L^{2}(\Omega)\right)^{d}\,\middle|\,\operatorname{curl}(\boldsymbol{f})\in\tilde{L}\right\},

where

\tilde{L}:=\begin{cases}\left(L^{2}(\Omega)\right)^{3}&\text{if }d=3,\\
L^{2}(\Omega)&\text{if }d=2,\end{cases}

and for
d=2
,
\operatorname{curl}
is defined by

\operatorname{curl}\left(\begin{pmatrix}f_{0}\\
f_{1}\end{pmatrix}\right)=\frac{\partial f_{1}}{\partial x}-\frac{\partial f_{0}}{\partial y}.

When discretising
H(\operatorname{div})
, we only require that components of the vector
normal to each facet are continuous between cells.
Raviart–Thomas
Raviart and Thomas 1977

and Brezzi–Douglas–Marini
Brezzi et al. 1985
elements are the most widely used
H(\operatorname{div})
-conforming elements. To enforce
the appropriate continuity, the DOFs associated with each facet are integral moments against vector functions
normal to the faces.
When discretising

2.1.3
Matrix-valued elements

Some problems involve matrix-valued unknowns, such as the strain and stress in elasticity
Christiansen 2011
.
For such problems, matrix-valued finite elements can be defined.
As in the vector case, these can be created be using a scalar-valued element for each
entry of the matrix. Depending on the application, symmetric or non-symmetric matrices may be
desired for the unknown: both cases can easily be created from scalar-valued element by either
using a seperate element for each entry, or by using fewer elements and setting the appropriate
matrix entries to be equal.

As in the vector-valued case, for many applications we desire elements with weaker continuity than the

C^{0}
continuity usually obtained from the scalar element approach.
For any matrix-valued function

\displaystyle H(\operatorname{curl}\,\operatorname{curl},\Omega)

2.2

When doing finite element computations on meshes that contain a mixture of cell types, it is important to ensure that the elements

Definition 7

1

definition

9
on each sub-cell, with appropriate continuity between sub-cells.

3
Element variants

For many elements, it is possible to define a number of different variants of the element. In many cases,
there is no single variant that is always the best variant, and so implementations may support multiple variants.
For example, for Lagrange elements, it is common to use equally spaced points to define low-degree elements, and
mesh storage formats that use Lagrange elements to represent mesh geometry often assume this equal spacing. However,
if equally spaced points are used for high-degree elements, the basis functions will exhibit Runge’s phenomenon
and become numerically unstable
Runge 1901
, as shown in
fig.

7
. Hence, for higher-degree elements, it is best to use an alternative set of points, such as
Gauss–Lobatto–Legendre (GLL) points or Chebyshev points
(
Trefethen 2019
, chapter 13)
.

Figure 7:
A basis function of a degree 7 Lagrange element on an interval when defined using
equispaced points (left) and GLL points (right). The basis function defined using equispaced
points exhibits Runge’s phenomenon: there are large function values far from the marked point
where the basis function is equal to one. Similar issues can be observed when defining the basis on other cell types.

In general, variants of finite elements are defined as follows.

Definition 15

(Variant of an element)
.

Let
(R,\mathcal{V},\mathcal{L})
and
(\tilde{R},\tilde{\mathcal{V}},\tilde{\mathcal{L}})
be Ciarlet finite elements.

(\tilde{R},\tilde{\mathcal{V}},\tilde{\mathcal{L}})
is a variant of

(R,\mathcal{V},\mathcal{L})
if:

•

\tilde{R}=R
;

•

\tilde{\mathcal{V}}=\mathcal{V}
;

•

For all sub-entities
E\subseteq R
,

\mathcal{L}|_{E}
and
\tilde{\mathcal{L}}|_{E}
are
equivalent sets of functionals,
where
\mathcal{L}|_{E}
and
\tilde{\mathcal{L}}|_{E}
are the sets of functionals in
\mathcal{L}

and
\tilde{\mathcal{L}}
that are associated with
E
.

We will now show that a set of alternative criteria is equivalent to
definition

15
, but we must first define
the controlled and uncontrolled trace of a finite element’s polynomial space on a sub-entity as follows.

Definition 16
.

Let
(R,\mathcal{V},\mathcal{L})
be a Ciarlet finite element. Let
E\subseteq R
be a sub-entity of
R
(i.e. a vertex, edge, or face of
R
, or
R
itself).
Let
\mathcal{L}=\{l_{0},\dots,l_{n-1}\}
and let
\phi_{0},\dots,\phi_{n-1}\in\mathcal{V}
be the basis functions of the finite element.
The uncontrolled trace space
\gamma^{\perp}(\mathcal{V},E,\mathcal{L})
is defined by

\gamma^{\perp}(\mathcal{V},E,\mathcal{L})=\left\{\left.p\right|_{E}\,:\,p\in\mathcal{V}\text{ and }\forall l_{i}\in\mathcal{L}|_{\overline{E}}\text{ }l_{i}(p)=0\right\},

where
\left.\mathcal{L}\right|_{\overline{E}}
is the set of all functionals in
\mathcal{L}
associated
with the closure of
E
.
The controlled trace space
\gamma^{\parallel}(\mathcal{V},E,\mathcal{L})
is defined by

\displaystyle\gamma^{\parallel}(\mathcal{V},E,\mathcal{L})

\displaystyle=\left[\gamma^{\perp}(\mathcal{V},E,\mathcal{L})\right]^{\perp}

\displaystyle=\left\{\left.p\right|_{E}\,:\,p\in\mathcal{V}\text{ and }\forall q\in\gamma^{\perp}(\mathcal{V},E,\mathcal{L})\text{ }\left\langle p,q\right\rangle_{E}=0\right\},

where
\left\langle p,q\right\rangle_{E}:=\int_{E}p\cdot q
.

Note that it is a standard result in functional analysis
(see e.g.
(
Kreyszig 1978
, theorem 3.3-4)
) that if
V
is a function space and

is a subspace of
V
, then

V=W\oplus W^{\perp}
. It follows that

\displaystyle\left.\mathcal{V}\right|_{E}

\displaystyle=\gamma^{\perp}(\mathcal{V},E,\mathcal{L})\oplus\gamma^{\parallel}(\mathcal{V},E,\mathcal{L}).

(5)

As an example, let
(R,\mathcal{V},\mathcal{L})
be a degree
k
Lagrange element.
For any subentity

, the restricted space

\left.\mathcal{V}\right|_{E}
is the Lagrange space
\mathbb{P}_{k}^{E}
.
The uncontrolled trace space
\gamma^{\perp}(\mathcal{V},E,\mathcal{L})

is equal to
\{0\}
, as any non-zero polynomial on

would make at least one functional
associated with
\overline{E}
non-zero.
It follows from

5
that
the controlled trace space
\gamma^{\parallel}(\mathcal{V},E,\mathcal{L})

is
\mathbb{P}_{k}^{E}
.

Lemma 2
.

Let
(R,\mathcal{V},\mathcal{L})
be a Ciarlet finite element.
If
E
is a sub-entity of
R
, then

\gamma^{\perp}(\mathcal{V},E,\mathcal{L})=\operatorname{span}\left\{\left.\phi_{i}\right|_{E}\,:\,l_{i}\not\in\left.\mathcal{L}\right|_{\overline{E}}\right\}.

Proof.

Let
p\in\gamma^{\perp}(\mathcal{V},E,\mathcal{L})
. As
p\in\mathcal{V}
, we can write

p=\sum_{j=0}^{n-1}\alpha_{j}\left.\phi_{j}\right|_{E},

for some
\alpha_{0},\dots,\alpha_{n-1}\in\mathbb{R}
.
If
l_{i}\in\mathcal{L}|_{\overline{E}}
, then

0=l_{i}(p)=\sum_{j=0}^{n-1}\alpha_{j}l_{i}\left(\left.\phi_{j}\right|_{E}\right)=\alpha_{i}.

This means that
p\in\operatorname{span}\left\{\left.\phi_{i}\right|_{E}\,:\,l_{i}\not\in\left.\mathcal{L}\right|_{\overline{E}}\right\}
,
and so

\gamma^{\perp}(\mathcal{V},E,\mathcal{L})\subseteq\operatorname{span}\left\{\left.\phi_{i}\right|_{E}\,:\,l_{i}\not\in\left.\mathcal{L}\right|_{\overline{E}}\right\}.

From the definition of the uncontrolled trace (

16

l_{i}\not\in\left.\mathcal{L}\right|_{\overline{E}}
then
\left.\phi_{i}\right|_{E}\in\gamma^{\perp}(\mathcal{V},E,\mathcal{L})
, and so

\gamma^{\perp}(\mathcal{V},E,\mathcal{L})\supseteq\operatorname{span}\left\{\left.\phi_{i}\right|_{E}\,:\,l_{i}\not\in\left.\mathcal{L}\right|_{\overline{E}}\right\}.

∎

Lemma 3
.

Let
\left.\mathcal{V}\right|_{E}:=\operatorname{span}\left\{\left.\phi_{0}\right|_{E},\dots,\left.\phi_{n-1}\right|_{E}\right\}

For all

Theorem

gives us a way to show that two elements are variants using only their basis functions.
We will use it in the following section as the basis of our algorithm to verify that elements from
different implementations are variants of each other.

4
Element verification

There are a large number of open source libraries available that include implementations of
finite elements. Without a significant amount of work by the user, it is difficult to be
certain that the implementations of the same element in different libraries are indeed
the implementations of the same element, and that the way the element is implemented
agrees with the element’s definition in the literature. For less simple elements in particular,
it is quite possible that a bug in the implementation leads to an element that “looks ok”
but does not solve problems to the accuracy that it should.

In order to confirm that implementations of the same element in different libraries are actually
the same element, DefElement performs verification of finite elements. This verification is
performed every 15 days, with the latest results displayed at
defelement.org/verification/
.
It is currently performed for elements implemented in Basix
Scroggs et al. 2022
, FIAT
Kirby 2004
, and ndelement
Scroggs 2024
, with Symfem
Scroggs 2021
used
as the verification baseline.
DefElement’s element verification has led the authors of this paper to
find and correct a number of bugs in FIAT and Symfem.

When verifying elements, we do not require the basis functions in the two implementations to be
exactly the same, as two libraries may use different variants of the same element, as defined in

5
Contributing to DefElement

Each element on DefElement is defined by a
.def
file which contains information about the element in yaml format.
The full encyclopedia is generated from these files by scripts written in Python. The full code used to generate DefElement is available under an MIT
license in the DefElement GitHub repository
Scroggs
et al. 2020–2025
, with code that is not finite element specific separated into a
separate website-build-tools repository for easier reuse by other projects
Scroggs 2025
.

The adding and updating of information on DefElement is done using a variety of GitHub features.
Changes can be suggested, and errors and bugs can be reported using the issue tracker at
github.com/DefElement/DefElement/issues
.
More detailed discussion about DefElement and its features can be held on the discussions board at
github.com/DefElement/DefElement/discussions
.

More direct proposal of changes to DefElement is encouraged, and can be done by forking the DefElement repository, making the changes, then opening a pull request.
The authors of the paper act as the editors of DefElement and are responsible for checking the correctness of new contributions, both those made by other
editors and people outside the team. This checking is done via the pull request review feature on GitHub, and this allows the editors to comment on specific lines
have changed and suggest direct corrections to lines for more minor issues like typographical errors.

We strongly encourage readers of this paper to contribute to DefElement, by
opening issues for elements that are not yet included in the encyclopedia,
suggesting other changes, or contributing directly via pull requests.

5.1
Adding a finite element library

Readers of this paper who are involved in the development of a finite element library
are encouraged to consider adding their library to the set of libraries that DefElement displays information about.
This can be done by adding a file to the folder
defelement/implementations
,
this file should contain the definition of a subclass of DefElement’s
Implementation
class.
This class includes methods that define how the information for the library will appear on the
element’s page.

The subclass of
Implementation
can optionally include a
verify
function that
takes a DefElement
Element
object, a reference cell and degree, and a set of points as inputs
and returns the evaluation of the basis functions of the element at the given points. If this function
is implemented, then verificiation will be performed for the library.

Full details of how to add a library to DefElement, and make other changes, can be found on the
DefElement contributing page at
defelement.org/contributing.html
.

6
Concluding remarks

As the number of finite elements that exist in the literature continues to grow, we believe
that it is increasingly important that information about elements can be found in a concise
and consistent format.
We hope that you find the information we have made available on DefElement useful, and
that you consider contributing to encyclopedia by editing existing information and adding
more details and elements.
