Space-Efficient Quantum Error Reduction without log Factors
Aleksandrs Belovs, Stacey Jeffery

Abstract
Given an algorithm that outputs the correct answer with bounded error, say 1 / 3 1/3 , it is sometimes desirable to reduce this error to some arbitrarily small ε \varepsilon – for example, if one wants to call the algorithm many times as a subroutine. The usual method, for both quantum and randomized algorithms, is a procedure called majority voting, which incurs a multiplicative overhead of 𝒪 ⁡ ( log ⁡ 1 ε ) \mathcal{O}(\log\frac{1}{\varepsilon}) from calling the algorithm this many times. A recent paper [Quantum 2024] introduced a model of quantum computation called transducers , and showed how to reduce the “error” of a transducer arbitrarily with only constant overhead, using a construction analogous to majority voting called purification . Even error-free transducers map to bounded-error quantum algorithms, so this does not let you reduce algorithmic error for free, but it does allow bounded-error quantum algorithms to be composed without incurring log factors. In this paper, we present a new highly simplified construction of a purifier, that can be understood as a weighted walk on a line similar to a random walk interpretation of majority voting. In addition to providing a new perspective that is easier to contrast with majority voting, our purifier has exponentially better space complexity than the previous one, and quadratically better dependence on the soundness-completeness gap of the algorithm being purified. Our new purifier has nearly optimal query complexity, even down to the constant, which matters when one composes quantum algorithms to super-constant depth. Purifiers can be seen as a way of turning a “Monte Carlo” quantum algorithm into a “Las Vegas” quantum algorithm – a process for which there is no classical analogue – leading to phenomena like the above-mentioned composition of bounded-error quantum algorithms without log factors. Conceptually, our simplified construction sheds light on this strange quantum phenomenon, and, more practically, could have implications for the time and space complexity of composed quantum algorithms.

Can the query complexity be improved?
Often
\delta
is constant, so the query complexity is only logarithmic, and it might not seem important to do better. However, imagine a setting where you want to query a subroutine (perhaps many times) and so you need to reduce its error, at the expense of querying it more often. If this subroutine also queries a subroutine, and so on, to some deep level of recursion, these query complexities multiply together, so that even constant factors may amount to something significant.
The lower bounds mentioned above make query complexity improvements seem impossible.
However, in order to get improvements, we sometimes have to change the setting.
We will show that, in some practical sense, the query complexity of these results
can
be improved.

Consider (classical) Las Vegas algorithms, which have no error, so are exact in some sense, but might run forever. In practice, to get an algorithm with finite running time (a Monte Carlo algorithm), it is necessary to truncate the Las Vegas algorithm after some constant times the expected running time, which introduces some small constant error. However, Las Vegas algorithms, being perfect objects, compose without issue, unlike Monte Carlo algorithms, where in order to successfully compose them, we must first reduce the error, which incurs a
\mathcal{O}(\frac{1}{\delta^{2}}\log\frac{1}{\varepsilon})
factor.
To compose Las Vegas algorithms efficiently, one must first compose them, and then truncate to get a practical (Monte Carlo) algorithm – if one first truncates all algorithms and subroutines, and then composes, one incurs logarithmic factors.

Let
A=A(O)
be a quantum query algorithm with input oracle
O
, to which it can make controlled queries.
The usual definition of its query complexity is the number of queries, or executions of the input oracle.
In
[
7
]
, an alternative definition of
Las Vegas query complexity
was introduced.
Assume
A(O)
is executed on some initial state
\mathopen{}\mathclose{{\left|\xi}}\right>
.
Let
\mathopen{}\mathclose{{\left|\psi_{i}}}\right>
be the state of the algorithm right before the
i

\mathopen{}\mathclose{{\left|\xi}}\right>

\mathopen{}\mathclose{{\left|\psi_{i}^{\bullet}}}\right>
be the projection of

onto the part of the space to which
O
is applied (since
O
is applied with a control, it is potentially only applied to a part of the space).
Then the Las Vegas query complexity of
A(O)
on input

is

That is, it is the sum, over all queries, of the squared norm of the part of the state to which the query is
actually
applied.
For intuition, note that the Las Vegas (i.e. expected) query complexity of a randomized classical algorithm is the sum over all steps where a query might be made, of the probability of making a query at that step. Moreover, this notion of query complexity is meaningful in the sense that we can convert
A
to a (bounded-error) quantum algorithm with query complexity
\mathcal{O}(L)
, where

is the max of
L(A,O,\xi)
over all admissible inputs.

Note that
L(A,O,\xi)
only counts queries to
O
, and not its inverse
O^{*}
. We can easily remedy this by replacing
O
with
O\oplus O^{*}
, which allows us to apply either
O
or
O^{*}
based on the value of some control register.

Transducers

In the standard model of quantum algorithms, a quantum algorithm is a sequence of unitaries, some of which may be black-box calls, the rest of which are “simple” in some desired sense, such as being local, or low depth, or perhaps merely independent of the input. This sequence of unitaries induces some target unitary action, or some unitary action that achieves the target action up to some perturbation. In contrast, transducers are a newer paradigm for quantum algorithms whereby a single unitary – often simple to implement in some desired sense – gives rise to some target unitary action.

Formally, a
transducer
is a unitary
S
acting on a direct sum of vector spaces
{\cal H}\oplus{\cal L}
, called the
public
space and
private
space.
As one can see from the naming, we have a case of encapsulation here: an outside algorithm has only access to the public space
(which we can also call the
boundary
), and can modify the private space
only
by executions of
S
.
The transducer induces a unitary
U
on
{\cal H}
, as follows (proven in
[
5

It is the unitary action

Complexities

A transducer
S
represents an algorithm on the public space
\mathcal{H}

This makes definition of the iteration time,

Note that iteration time is precisely where we marry the model-dependent notion of “time complexity” with the nice clean mathematical model of transducers. The notion of time complexity we use to analyze

might be with respect to a particular gate set; it might include random access gates (or not); it might be the depth. The time complexity of the algorithm we get in

will inherit this model.
Note that neither the iteration time nor the space complexity depend on the initial state, or the input oracle.

Speaking of the input oracle, we define the query complexity

of the transducer

and the initial state

on the initial state

Note that the state

Canonical transducers

It is well known that every quantum query algorithm can be turned into a canonical form: unitaries interspersed with executions of the input oracle.
In case of transducers, the canonical form is extremely simple: it is just one(!) execution of the input oracle on a part of the private space, following by a unitary independent of the input oracle.

As usual, it is much more convenient to design a transducer without assuming the canonical form, but for its implementation, it is extremely helpful.
Luckily, it is easy to transform any transducer into a canonical form with minimal increase in complexity.

For a canonical transducer, we restrict
O
to be applied to the private space
{\cal L}
– this is natural because
O
is somehow “internal” to any algorithm that calls it. As usual, we let

be applied controlled on being in a certain subspace, which we will denote

, where we apply

{\cal L}^{\bullet}

Then we say that

S(O)=S^{\circ}\widetilde{O},

(8)

where
\widetilde{O}
applies

S(O):\xi\oplus v^{\circ}\oplus v^{\bullet}\;\stackrel{{\scriptstyle\widetilde{O}}}{{\longmapsto}}\;\xi\oplus v^{\circ}\oplus Ov^{\bullet}\;\stackrel{{\scriptstyle S^{\circ}}}{{\longmapsto}}\;\tau\oplus v^{\circ}\oplus v^{\bullet},

Thus, for a canonical transducer, the query complexity with respect to an input

Composition of transducers

We can compose transducers similar to how we can compose quantum algorithms, and the complexity of these compositions follows some natural rules. We sketch two examples below that will come up in this paper. For details, refer to Section 9 of
[
5
]
. For all these compositions, it is convenient to assume the transducers are in canonical form.

If
S_{A}
and
S_{B}
are transducers with transduction actions
U_{A}
and
U_{B}
, respectively, on the same public space
\mathcal{H}
, then we can compose them
sequentially
to obtain a transducer
S_{B}*S_{A}
with transduction action
U_{B}U_{A}
on the space
\mathcal{H}
.
The transduction, the query, and the iteration time complexities of
S_{B}*S_{A}
are the sums of the corresponding complexities of
S_{A}
and
S_{B}
.

Next, if
S_{A}(O^{\prime})
is a transducer with an input oracle
O^{\prime}
acting in some space
\mathcal{M}
, and
S_{B}
is a transducer with transduction action
U_{B}
on space
\mathcal{M}
, we can define their

S_{A}\circ S_{B}
, which is a transducer whose transduction action is identical to that of
S_{A}(U_{B})
.

We can also consider functional composition in the case where
S_{A}
and
S_{B}
query some “global” input oracle
O
, distinct from
O^{\prime}
(which
S_{A}
also depends on). Letting a transducer depend on two oracles requires no extension of the model already described. Since an oracle is assumed to be called with some control, we can simply let
S_{A}(O\oplus O^{\prime})
depend on a single oracle
O\oplus O^{\prime}
. Concretely, we can suppose there are orthogonal subspaces
{\cal L}^{(0)}
and
{\cal L}^{(1)}
such that
O
is applied controlled on being in
{\cal L}^{(0)}
and

is applied controlled on being in
{\cal L}^{(1)}
.

To discuss the complexities of functionally composed transducers, we need the concept of a
partial query state
. Consider the algorithm
A_{S}
that implements the unitary
S
.
As usual, we let
\mathopen{}\mathclose{{\left|\psi_{i}}}\right>
denote the state of this algorithm right before the
i
-th query, on oracle
O\oplus O^{\prime}
and input
\xi
. We can decompose it into three orthogonal parts:

\mathopen{}\mathclose{{\left|\psi_{i}}}\right>=\psi_{i}^{\circ}\oplus\psi_{i}^{(0)}\oplus\psi_{i}^{(1)},

where
\psi_{i}^{(0)}
is its projection onto
{\cal L}^{(0)}
, the space to which
O
is applied, and
\psi_{i}^{(1)}
is its projection onto
{\cal L}^{(1)}

is applied. Then the

O

q^{(0)}(S_{A},O\oplus O^{\prime},\xi)=\sum_{i}\mathopen{}\mathclose{{\left|i}}\right>\otimes\psi_{i}^{(0)},

and the partial query state relative to
O^{\prime}
is:

q^{(1)}(S_{A},O\oplus O^{\prime},\xi)=\sum_{i}\mathopen{}\mathclose{{\left|i}}\right>\otimes\psi_{i}^{(1)},

where in both cases,

L^{(0)}(S_{A},O\oplus O^{\prime},\xi)=\bigl\lVert q^{(0)}(S_{A},O\oplus O^{\prime},\xi)\bigr\rVert^{2}.

The query complexity of the composed transducer is then:

L(S_{A}\circ S_{B},O,\xi)=L^{(0)}(S_{A},O\oplus O^{\prime},\xi)+L(S_{B},O,q^{(1)}(S_{A},O\oplus O^{\prime},\xi)).

(13)

To parse (

),
note that the term
L(S_{B},O,q^{(1)}(S_{A},O\oplus O^{\prime},\xi))
can be rewritten:

\bigl\lVert q^{(1)}(S_{A},O\oplus O^{\prime},\xi)\bigr\rVert^{2}L(S_{B},O,\xi^{\prime})=L^{(1)}(S_{A},O\oplus O^{\prime},\xi)L(S_{B},O,\xi^{\prime})

where
\xi^{\prime}
is the normalization of the partial query state
q^{(1)}(S_{A},O\oplus O^{\prime},\xi)
, which is the input to
S_{B}
, and
L^{(1)}(S_{A},O\oplus O^{\prime},\xi)
is the Las Vegas query complexity of

in terms of queries to
O^{\prime}
, on input

. Thus, if
L(S,O)
denotes an upper bound on

over some set of admissable inputs, we have, assuming

is always an admissable input when

L(S_{A}\circ S_{B},O)=L^{(0)}(S_{A},O\oplus O^{\prime})+L^{(1)}(S_{A},O\oplus O^{\prime})L(S_{B},O),

so the query complexity of the composed transducer is the query complexity of

times the query complexity of

relative to

Similarly, the transduction complexity of the composed transducer is

\displaystyle W((S_{A}\circ S_{B})(O),\xi)=W(S_{A}(O\oplus O^{\prime}),\xi)+W(S_{B}(O),q^{(1)}(S_{A},O\oplus O^{\prime},\xi)),

p>\frac{1}{2}
, then
\gamma>1
, and we define
\mathopen{}\mathclose{{\left|v}}\right>=\sum_{j=1}^{\infty}(-\gamma)^{-j}\mathopen{}\mathclose{{\left|j}}\right>
.
The action of the transducer is given by

\displaystyle\mathopen{}\mathclose{{\left|0}}\right>+\mathopen{}\mathclose{{\left|v}}\right>=

\displaystyle\sum_{j=0}^{\infty}(-\gamma)^{-j}\mathopen{}\mathclose{{\left|j}}\right>=\sum_{i=0}^{\infty}\gamma^{-2i}\bigl(\mathopen{}\mathclose{{\left|2i}}\right>-\gamma^{-1}\mathopen{}\mathclose{{\left|2i+1}}\right>\bigr)

(21)

\displaystyle\;\stackrel{{\scriptstyle R_{1}}}{{\longmapsto}}

\displaystyle-\sum_{j=0}^{\infty}(-\gamma)^{-j}\mathopen{}\mathclose{{\left|j}}\right>=-\mathopen{}\mathclose{{\left|0}}\right>+\sum_{i=0}^{\infty}\gamma^{-2i-1}\bigl(\mathopen{}\mathclose{{\left|2i+1}}\right>-\gamma^{-1}\mathopen{}\mathclose{{\left|2i+2}}\right>\bigr)

\displaystyle\;\stackrel{{\scriptstyle R_{2}}}{{\longmapsto}}

\displaystyle-\mathopen{}\mathclose{{\left|0}}\right>-\sum_{i=0}^{\infty}\gamma^{-2i-1}\bigl(\mathopen{}\mathclose{{\left|2i+1}}\right>-\gamma^{-1}\mathopen{}\mathclose{{\left|2i+2}}\right>\bigr)=-\mathopen{}\mathclose{{\left|0}}\right>+\sum_{j=1}^{\infty}(-\gamma)^{-j}\mathopen{}\mathclose{{\left|j}}\right>=-\mathopen{}\mathclose{{\left|0}}\right>+\mathopen{}\mathclose{{\left|v}}\right>.

Therefore,
\mathopen{}\mathclose{{\left|0}}\right>\stackrel{{\scriptstyle S}}{{\rightsquigarrow}}-\mathopen{}\mathclose{{\left|0}}\right>
.
The Las Vegas query complexity is

\sum_{j=0}^{\infty}\gamma^{-2j}+\sum_{j=1}^{\infty}\gamma^{-2j}=\frac{2}{1-\gamma^{-2}}-1=\frac{1}{2\delta}.

By a similar computation, we can show that
\bigl\lVert v\bigr\rVert\leq\frac{1}{2\delta}
in both cases, showing that the transduction complexity is at most
\frac{1}{2\delta}
.

In the first step, we execute

In the second step, we apply an oracle

6
Query-Efficient Implementation

A well-studied and very general type of problem in quantum query complexity is that of state conversion
[
18
,
3
]
.
There it is assumed that a
finite
set
X
and two Hilbert spaces
\mathcal{M}
and
\mathcal{H}
are fixed.
For each
x\in X
, the input oracle
O_{x}\colon\mathcal{M}\to\mathcal{M}
and a pair of states
\xi_{x},\tau_{x}\in\mathcal{H}
are given.
The task is to construct an algorithm

that satisfies
A(O_{x})\xi_{x}=\tau_{x}
for all
x\in X
.

The query complexity of this problem is captured by the corresponding adversary bound.
As shown in
[
7
,
5
]
, the adversary bound is identical to a transducer in canonical form.
Let us briefly repeat the argument here.
Let
\mathcal{L}=\mathcal{L}^{\circ}\oplus\mathcal{L}^{\bullet}
be the decomposition of the private space into the non-query and the query parts, where
\mathcal{L}^{\bullet}=\mathcal{M}\otimes\mathcal{W}
for some space
\mathcal{W}
.
By the definition of canonical form,
v_{x}=v_{x}^{\circ}\oplus v_{x}^{\bullet}
is a valid catalyst for
\xi_{x}
if there exists a unitary
S^{\circ}
such that

S^{\circ}\colon\xi_{x}\oplus v_{x}^{\circ}\oplus(O_{x}\otimes I_{\mathcal{W}})v_{x}^{\bullet}\;\stackrel{{\scriptstyle}}{{\longmapsto}}\;\tau_{x}\oplus v_{x}^{\circ}\oplus v_{x}^{\bullet}

(33)

for all
x\in X
(see (
9
)).
Moreover, the states
v_{x}^{\bullet}
are the corresponding query states, and
\|v_{x}^{\bullet}\|^{2}
are the corresponding query complexities.

It is easy to see that the existence of the unitary
S^{\circ}
is equivalent to the following condition

\mathopen{}\mathclose{{\left\langle\xi_{x},\xi_{y}}}\right\rangle-\mathopen{}\mathclose{{\left\langle\tau_{x},\tau_{y}}}\right\rangle=\mathopen{}\mathclose{{\left\langle v_{x}^{\bullet},v_{y}^{\bullet}}}\right\rangle-\bigl\langle(O_{x}\otimes I_{\mathcal{W}})v_{x}^{\bullet},(O_{y}\otimes I_{\mathcal{W}})v_{y}^{\bullet}\bigr\rangle

(34)

for all
x,y\in X
.
In particular, the non-query parts
v_{x}^{\circ}
of the catalyst are irrelevant and can be removed
if one only cares about query complexity. This means that any non-query parts of the catalyst are purely for keeping the overall time complexity small.

Thus, the transducers from Theorems
11
and
16
and
Corollary
17
give rise to solutions to equation (
34
) for the corresponding state conversion problems.
In all these cases, the space
\mathcal{W}
is infinite by construction.
However,
assuming that
X
is finite
, which is a common assumption in the state conversion problem, we can restrict the space
\mathcal{W}
to have dimension at most
|X|
, which is finite.
This gives the corresponding query-efficient transducer that performs the required transformation exactly and only uses finite space.
It also gives a solution to the corresponding adversary bound.

In
[
3
]
, purifiers were used to show that the adversary bound for bounded-error function evaluation is equal (up to a constant factor) to the adversary bound for exact function evaluation.
This demonstrated that the usual adversary bound for function evaluation (which works assuming bounded error) is a special case of that for the state conversion problem.
The transducers obtained in this section can be used instead of the purifiers of
[
3
]
, and they give a better dependence on
\delta
.

Lower Bound

In this section, we will give an almost tight lower bound on the query complexity of a purifier, showing that
Theorem
20
(the formal version of
Theorem
5
) is nearly optimal.

Consider the following input oracles in
\mathbb{C}
:

O_{x}\colon\mathopen{}\mathclose{{\left|0}}\right>\mapsto(-1)^{x}\mathopen{}\mathclose{{\left|0}}\right>,

where
x\in\{0,1\}
.
The oracle
O_{x}
is inverse to itself, so there is no difference between direct and reverse executions of
O_{x}
in this case.

Trivially, the Las Vegas query complexity of implementing
O_{x}
given the input oracle
O_{x}
is at most 1.
This is also a lower bound.
This can be proven using the adversary lower bound from
[
5
]
.
However, this can also be seen directly using the following simple argument.
If the complexity were
c<1
, we could compose the corresponding procedure with itself
n
times, obtaining implementation of
O_{x}
in query complexity
c^{n}\to 0
as
n\to\infty
, which is absurd.

Consider the following state:

\mathopen{}\mathclose{{\left|\varphi_{x}}}\right>=\sqrt{\frac{1}{2}-\delta}\mathopen{}\mathclose{{\left|00}}\right>+\sqrt{\frac{1}{2}-\delta}\mathopen{}\mathclose{{\left|10}}\right>+\sqrt{2\delta}\mathopen{}\mathclose{{\left|x}}\right>\mathopen{}\mathclose{{\left|1}}\right>,

which has amplitude
\sqrt{1/2+\delta}
on
x
in the first qubit.
It can be generated in Las Vegas query complexity
\delta
as follows. Beginning from the state
\mathopen{}\mathclose{{\left|\psi_{1}}}\right>=\sqrt{1-2\delta}\mathopen{}\mathclose{{\left|0}}\right>\mathopen{}\mathclose{{\left|0}}\right>+\sqrt{2\delta}\mathopen{}\mathclose{{\left|+}}\right>\mathopen{}\mathclose{{\left|1}}\right>
,
perform a query controlled on
\mathopen{}\mathclose{{\left|1}}\right>\mathopen{}\mathclose{{\left|1}}\right>
, on which the state has squared norm
\delta
, to get:

\sqrt{1-2\delta}\mathopen{}\mathclose{{\left|0}}\right>\mathopen{}\mathclose{{\left|0}}\right>+\sqrt{2\delta}\left(\frac{1}{\sqrt{2}}\mathopen{}\mathclose{{\left|0}}\right>+(-1)^{x}\frac{1}{\sqrt{2}}\mathopen{}\mathclose{{\left|1}}\right>\right)\mathopen{}\mathclose{{\left|1}}\right>.

Applying
H
to the first register then gives
\mathopen{}\mathclose{{\left|\varphi_{x}}}\right>
. Since the only query was applied to
\mathopen{}\mathclose{{\left|\psi_{1}}}\right>
, and its projection onto
\mathopen{}\mathclose{{\left|1}}\right>\mathopen{}\mathclose{{\left|1}}\right>
, the query part of the space, has squared norm
\delta
, the total Las Vegas query complexity of this procedure is
\delta
.

Therefore, the oracle
O_{\mathrm{ref}}
reflecting about
\mathopen{}\mathclose{{\left|\varphi_{x}}}\right>
can be implemented in Las Vegas query complexity
2\delta
.
Let
Q_{p}
be the query complexity of the transformation
\mathopen{}\mathclose{{\left|\varphi_{x}}}\right>\mapsto(-1)^{x}\mathopen{}\mathclose{{\left|\varphi_{x}}}\right>
, in terms of queries to
O_{\mathrm{ref}}
, with parameter
\delta
.
We can implement
O_{x}
as follows.
Generate the state
\mathopen{}\mathclose{{\left|\varphi_{x}}}\right>
in query complexity
\delta
.
Map it to
(-1)^{x}\mathopen{}\mathclose{{\left|\varphi_{x}}}\right>
in
Q_{p}
queries to
O_{\mathrm{ref}}
, each costing
2\delta
query complexity.
Map it back to
(-1)^{x}\mathopen{}\mathclose{{\left|0}}\right>
in query complexity
\delta
.
The query complexity of this procedure is

2\delta+Q_{p}2\delta.

It is at least 1 by our above discussion, so we obtain the following result.

Theorem 22
.

The query complexity of any transducer performing the task in
Theorem
20
is at least

\frac{1}{2\delta}-1.

For small
\delta
, this is close to the query complexity
1/(2\delta)
obtained in
Theorem
20
.
