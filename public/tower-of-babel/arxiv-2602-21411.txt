General Convex Agreement with Near-Optimal Communication
Marc Dufay, Diana Ghinea, Anton Paramonov

Abstract
Convex Agreement (CA) strengthens Byzantine Agreement (BA) by requiring the output agreed upon to lie in the convex hull of the honest parties’ inputs. This validity condition is motivated by practical aggregation tasks (e.g., robust learning or sensor fusion) where honest inputs need not coincide but should still constrain the decision. CA inherits BA lower bounds, and optimal synchronous round complexity is easy to obtain (e.g., via Byzantine Broadcast). The main challenge is communication : standard approaches for CA have a communication complexity of Θ ⁡ ( L ⋅ n 2 ) \Theta(L\cdot n^{2}) for large L L -bit inputs, leaving a gap in contrast to BA’s lower bound of Ω ⁡ ( L ⋅ n ) \Omega(L\cdot n) bits. While recent work achieves optimal communication complexity of 𝒪 ⁡ ( L ⋅ n ) \mathcal{O}(L\cdot n) for sufficiently large L L [GLW,PODC’25], translating this result to general convexity spaces remained an open problem. We investigate this gap for abstract convexity spaces, and we present deterministic synchronous CA protocols with near-optimal communication complexity: when L = Ω ⁡ ( n ⋅ κ ) L=\Omega(n\cdot\kappa) , where κ \kappa is a security parameter, we achieve 𝒪 ⁡ ( L ⋅ n ​ log ⁡ n ) \mathcal{O}(L\cdot n\log n) communication for finite convexity spaces and 𝒪 ⁡ ( L ⋅ n 1 + o ⁡ ( 1 ) ) \mathcal{O}(L\cdot n^{1+o(1)}) communication for Euclidean spaces ℝ d \mathbb{R}^{d} . Our protocols have asymptotically optimal round complexity 𝒪 ⁡ ( n ) \mathcal{O}(n) and, when a bound on the inputs’ lengths L L is fixed a priori, we achieve near-optimal resilience t < n / ( ω + ε ) t<n/(\omega+\varepsilon) for any constant ε > 0 \varepsilon>0 , where ω \omega is the Helly number of the convexity space. If L L is unknown, we still achieve resilience t < n / ( ω + ε + 1 ) t<n/(\omega+\varepsilon+1) for any constant ε > 0 \varepsilon>0 . We further note that our protocols can be leveraged to efficiently solve parallel BA. Our main technical contribution is the use of extractor graphs to obtain a deterministic assignment of parties to committees, which is resilient against adaptive adversaries.



1
Introduction

Byzantine Agreement (
BA
)
[
45
]
considers a setting of
n
parties out of which up to
t
may be byzantine (malicious), and is usually phrased as “everyone decides the same thing”, but in many systems the real requirement is “everyone decides something
plausible
”.
In a growing set of applications, however, agreement alone is not the only challenge: the system also needs a decision that is credible relative to the honest data. This occurs whenever inputs are inherently diverse but still “mutually consistent” in a geometric sense. Examples include: blockchain oracle mechanisms that aggregate multiple price reports into a single outcome
[
5
]
, aggregating model updates in distributed or federated learning
[
63
,
27
,
26
,
12
]
, and robust multi-sensor fusion
[
6
]
. In such settings, classical
BA
on its own fails to provide a meaningful output: the output must be an honest input if all honest inputs coincide. Otherwise, the protocol may legitimately output a value that has nothing to do with the honest inputs.

Convex Agreement (
CA
)
[
66
,
57
,
23
]
strengthens the validity condition of
BA
by requiring that the common output lies in the honest inputs’ convex hull (e.g., if the inputs are real values, inside the range spanned by the honest inputs), which captures the principle that the decision should be explainable as a “mixture” of honest views.

CA
immediately inherits the fundamental barriers known for
BA
: round complexity, message complexity, and communication complexity lower bounds carry over by reduction. In particular, matching optimal round complexity for
CA
is not the main difficulty: in synchronous networks, a direct approach via Byzantine Broadcast (
BC
)
[
58
,
25
]
provides the parties with an identical view over the inputs, after which every party can locally compute a valid output using a deterministic “safe-area” rule.
This already achieves optimal resilience and optimal round complexity
[
66
,
57
,
21
]
.

On the other hand, reducing communication becomes challenging: if the inputs can be represented using
L
bits, the
BC
-based approach incurs at least
\mathcal{O}(Ln^{2})
bits of communication. In fact, such approaches require honest parties to relay messages from byzantine parties, leading to an adversarially-chosen communication complexity. This stands in sharp contrast to
BA
, where
extension protocol
techniques enable communication
\mathcal{O}(Ln+\mathsf{poly}(n,\kappa))
even via deterministic protocols, where
\kappa
denotes a security parameter, matching the lower bound of
\Omega(Ln)
bits
[
31
,
48
,
34
,
55
,
9
]
. A natural hope is to port this communication efficiency from
BA
to
CA
. Recent work makes concrete progress in this direction:
[
38
]
proposes a deterministic protocol that, assuming a hash function, achieves
CA
on
\mathbb{Z}
with communication complexity
\mathcal{O}(Ln+\mathsf{poly}(n,\kappa))
, breaking the
\Theta(Ln^{2})
of broadcast-based approaches. As pointed out by
[
38
]
, matching
BA
-style communication in
CA
is intrinsically more delicate: the protocol must preserve enough structure (e.g., relative order in one dimension), while techniques from
BA
extension protocols, which involve compressing values, risk breaking this structure.
In this paper, we investigate this communication gap further.

1.1
Our Contribution

In this paper, we consider the
CA
problem on a convexity space
\mathcal{C}
in the synchronous model and we show that it can be achieved deterministically with near-optimal communication in the long-message regime, asymptotically optimal round complexity, and near-optimal resilience.
Specifically, we give deterministic protocols achieving communication complexity
\mathcal{O}(L\cdot n\log n+n^{2}\kappa\log n)
when, informally, all elements of the convexity space can be represented using
L
bits (e.g., in finite spaces), and
\mathcal{O}(L\cdot n^{1+o(1)}+n^{2}\kappa\log^{1+o(1)}n)
otherwise, where
\kappa
is a security parameter. Our protocols assume a hash function, and we consider both constructions with and without signatures.

At a high level, our approach avoids “compressing” values and instead
compresses the system
:
we use extractor-based deterministic committees to iteratively reduce
n
parties (or supernodes) to a small number of supernodes, each holding a valid value, after which coordinating among only a few candidates suffices to complete
CA
efficiently.
Our extractor-based committee assignment allows us to deterministically assign parties to committees so that an adversary can obtain a majority only in a small fraction of the committees, no matter which parties it corrupts.

We first rely on this technique to aggregate parties into
supernodes
—groups in which parties hold a single value in the convexity space and act as a single entity. Next, using the same extractor-based assignment, we form committees of supernodes. Within each committee, the supernodes deterministically compute a new value – this is identical for all supernodes in the committee, and lies in the convex hull of the values proposed by
good
supernodes. This process reduces
the number of distinct values
in the system and can be iterated until a single value – the final output – is obtained.

Our approach strongly relies on the fact that most of the supernodes are
good
at all times, i.e., indeed act as a single entity and follow the protocol. This is ensured by the extractor: the assignment guarantees that most supernodes have an honest majority. We also rely on most committees being able to correctly determine valid values, which is again guaranteed by the extractor assignment: in most committees, a majority of supernodes are good.

The main communication bottleneck in this approach is supernodes exchanging their
L
-bit values. To make this part efficient, we implement a message-distribution primitive,
super-sending
, inspired by prior extension protocols – this relies on Reed-Solomon codes and Merkle trees.

Overall, our approach yields the following results for
CA
:

Theorem 1
.

Consider a finite convexity space
\mathcal{C}
with constant Helly number
\omega\geq 2
where all elements have
L
-bit encodings. Then, for any constant
\varepsilon>0
, there is a protocol achieving
CA
on
\mathcal{C}
secure against
t<n/(\omega+\varepsilon)
byzantine corruptions, communication complexity
\mathcal{O}(nL\log n+n^{2}\log n\cdot\kappa)
and round complexity
\mathcal{O}(n)
.

Theorem 2
.

For any constants
\varepsilon>0
and
d\geq 2
, there is a protocol achieving
CA
on
\mathbb{R}^{d}
with straight-line convexity assuming that honest parties’ inputs can be encoded using
L
bits, even when up to
t
of the parties involved are byzantine, where
t<n/(d+1+\varepsilon)
if
L
is known a priori, and
t<n/(d+2+\varepsilon)
otherwise. The protocol has communication complexity
\mathcal{O}(n^{1+o(1)}L+n^{2}\log^{1+o(1)}n\cdot\kappa)
and round complexity
\mathcal{O}(n)
.

Theorem 3
.

Consider
q
finite convexity spaces
\mathcal{C}_{1},\mathcal{C}_{2},\ldots,\mathcal{C}_{q}
, each of the elements in
\mathcal{C}_{i}
has an
L_{i}
bit encoding, and let
\omega_{i}\in\mathcal{O}(1)
be the Helly number of
\mathcal{C}_{i}
. Additionally, let
\omega_{\max}=\max\omega_{i}
and
L=\sum L_{i}
.
Then, for any constant
\varepsilon>0
, there is a protocol achieving
CA
simultaneously in all of
\mathcal{C}_{1},\mathcal{C}_{2},\ldots,\mathcal{C}_{q}
even when up to
t<n/(\omega_{\max}+\varepsilon)
of the
n

\mathcal{O}(nL\log n+n^{2}\log n\cdot\kappa)
and round complexity
\mathcal{O}(n)
.

Our approach also leads to results outside
CA
, most notably for parallel instances of
BA
. As
BA
is a particular case of
CA
, we obtain the following results, for instances with various inputs lengths, and for instances with binary inputs:

Corollary 1
.

For any constant
\varepsilon>0
,
it is possible to solve
q
parallel instances of
BA
with inputs of size
L_{1},L_{2},\ldots,L_{q}
with near-optimal resilience
t<n/(2+\varepsilon)
, near-optimal communication complexity
\mathcal{O}(nL\log n)
, and optimal round complexity
\mathcal{O}(n)
, assuming
L=\sum L_{i}=\Omega(n\kappa)
.

Corollary 2
.

For any
\varepsilon>0
, it is possible to solve
n\cdot\kappa
parallel instances of binary

with near-optimal resilience
t<n/(2+\varepsilon)

\mathcal{O}(\kappa\cdot n^{2}\log n)

\mathcal{O}(n)
.

Related work

Convex Agreement.

The strengthened validity condition requiring honest parties’ outputs to lie in the honest inputs’ convex hull was introduced in the context of Approximate Agreement (
AA
) by Dolev et al.
[
23
]
. In
AA
, the classical agreement condition is weakened: parties are allowed to output values that differ by at most a prescribed error
\varepsilon>0
. This relaxation makes deterministic protocols possible even in asynchronous networks, as opposed to deterministic protocols for
BA

[
30
]
.
Approximate agreement has prompted a long line of work studying, among other aspects, optimal convergence rates
[
29
,
28
,
7
]
, improved resilience bounds
[
1
,
36
,
47
]
, reducing message complexity in asynchronous settings
[
53
]
and richer domains beyond real-valued inputs. Examples include inputs from
\mathbb{R}^{d}

[
66
,
51
,
37
]
as well as from discrete spaces such as graphs
[
57
,
4
,
46
,
21
,
3
,
33
]
. For a broader overview on
AA
, see
[
39
]
.
Convex Agreement (
CA
) was first formalized for vectors by Vaidya and Garg
[
66
,
50
]
, and has also been explored for abstract convexity spaces
[
57
,
21
]
. A related direction asks for outputs that satisfy a stronger “centrality” requirement on
\mathbb{R}
, namely being close to the median of the honest inputs
[
62
,
20
]
, or more generally close to the
k
-th smallest honest input
[
49
]
.

Each of these prior protocols involves a step where the parties distribute their (input) values, hence achieving communication complexity of
\Omega(L\cdot n^{2})
bits for
L
-bit inputs. Recently,
[
38
]
has proposed a
CA
protocol for integers (assuming a hash function), tolerating
t<n/3
corruptions, with communication
\mathcal{O}(Ln+\kappa\cdot n^{2}\log^{2}n)
. Their approach deviates from prior works on
CA
and
AA
by relying on a byzantine analogue of the
longest common prefix
problem: viewing inputs as bitstrings, the longest common prefix among honest parties pinpoints a sub-interval of the honest input range, which can then be leveraged to realize
CA
.

Other extension protocols.

Turpin and Coan
[
64
]
have proposed a reduction from long-messages
BA
to short-messages
BA
with a communication cost of
\mathcal{O}(Ln^{2})
bits, given
t<n/3
. In the honest-majority regime, Fitzi and Hirt
[
31
]
achieved
BA
with asymptotically optimal communication
\mathcal{O}(Ln+\mathsf{poly}(n,\kappa))
(given a universal hash function).
Further works have focused on error-free solutions, aiming to reduce the additive
\mathsf{poly}(n,\kappa)
overhead, both for the

setting
[
48
,
34
,
55
]
and for honest-majority thresholds
[

,
55
,
9
]
.
Recently, the work of
[
14

has focused on long-message BA with external validity (i.e., values can be verified via a publicly checkable predicate) whose communication adapts to the actual number of corruptions
f\leq t
, while remaining asymptotically optimal.
Complementarily,
[
15
]
studies multi-shot
BA
and related tasks under classical and external validity, and presents protocols with asymptotically optimal amortized communication for long inputs.
Extension-style approaches have also been studied for closely related primitives, including Byzantine Agreement with
t<n

[
40
,

]
and asynchronous Reliable Broadcast
[
11
,

]
.

Protocols for short messages.

Reducing communication is also an interesting research topic for short inputs (i.e., one bit or a constant number of bits). Dolev and Reischuk
[
24
]
proved that any deterministic

protocol (and therefore any deterministic

protocol) must exchange

Pseudorandomness.

Our approach relies heavily on the use of extractors. Extractors are part of what are called pseudorandom objects
[
65
]
. These objects keep properties about random structures while being fully deterministic. Other common pseudorandom graph structures are, for example, expanders, samplers or condensers. Expanders in particular have been already used multiple times to disseminate information with sparse communication

,
14

19

Parallel instances of
BA
.

As a corollary of our main results, we obtain a near-optimal protocol for parallel
BA
on
\Omega(n)
instances. This has already been studied under the name Multidimensional

[

]

2
Preliminaries

We describe our model, and present a few key concepts and definitions.

Model.

We consider a setting with
n
parties
P_{1},P_{2},\dots,P_{n}
in a fully-connected network where links model authenticated channels.
We assume that the network is synchronous: the parties hold synchronized clocks, all messages get delivered within
\Delta
time, and
\Delta
is publicly known.

Adversary.

We consider a computationally-bounded adaptive adversary that can corrupt up to
t
parties at any point in the protocol’s execution, causing them to become byzantine: corrupted parties may deviate arbitrarily from the protocol.

Cryptographic Assumptions.

We consider a security parameter
\kappa
, a collision-resistant hash function
H_{\kappa}:\{0,1\}^{\star}\rightarrow\{0,1\}^{\kappa}
. Informally,
H_{\kappa}:\{0,1\}^{\star}\rightarrow\{0,1\}^{\kappa}
is collision-resistant if, for any computationally-bounded adversary
\mathcal{A}
, the probability that
\mathcal{A}(1^{\kappa})
outputs two values
x\neq y
such that
H_{\kappa}(x)=H_{\kappa}(y)
is negligible in
\kappa

[
60
]
.

We consider both
unauthenticated
settings and
authenticated
settings. We use the term
unauthenticated
to refer to a setting where the only cryptographic assumption is the hash function. In contrast
authenticated settings
rely on a trusted setup: on top of the hash function, we also assume a public key infrastructure (PKI) and a secure signature scheme, with security parameter
\kappa
as well.

For simplicity of presentation, our proofs assume that the adversary does not find any collisions for
H_{\kappa}
, and that it is unable to forge signatures. When these assumptions are removed, our protocols’ guarantees still hold except with probability negligible in
\kappa
.

Byzantine Agreement.

Our protocols rely on
BA
as a building block, defined below
[
45
]
.
We recall that, in the synchronous model,
BA
can be achieved up to
t<n/3
corruptions in unauthenticated settings, and
t<n/2
corruptions in authenticated settings.

Definition 1

(Byzantine Agreement)
.

Let
\Pi
be an
n
-party protocol where each party holds a value
v_{\textsc{in}}
as input, and parties terminate upon generating an output
v_{\textsc{out}}
.
\Pi
achieves Byzantine Agreement if the following properties hold even when
t
of the
n
parties are corrupted:

(Termination)
All honest parties terminate;

(Validity)
If all honest parties hold the same input value
v
, they output
v_{\textsc{out}}=v
;

(Agreement)
All honest parties output the same value.

Basic convexity notions and
CA
.

Before describing
CA
, we recall a few notions regarding convexity spaces.
Let
\mathcal{C}
be a non-empty set of values.
A
convexity notion
on
\mathcal{C}
is a family
\mathcal{K}\subseteq 2^{\mathcal{C}}

such that
\varnothing,\mathcal{C}\in\mathcal{K}
and
\mathcal{K}
is closed under arbitrary intersections.
Members of
\mathcal{K}
are called
convex sets
.
For simplicity, we will often refer to
\mathcal{C}
itself as a
convexity space
, leaving the underlying family
\mathcal{K}
implicit when it is clear from context.
This framework captures
straight-line convexity
on
\mathcal{C}=\mathbb{R}^{d}
by taking
\mathcal{K}
to be the sets closed under line segments, but it also allows other choices, e.g.,
box convexity
, where
\mathcal{K}
consists of axis-aligned boxes
I_{1}\times\cdots\times I_{D}
with each
I_{i}
a closed interval.
For
S\subseteq\mathcal{C}
, the
convex hull
of
S
, denoted by
\langle{S}\rangle
, is the intersection of all convex sets containing
S
, i.e.

\langle{S}\rangle=\bigcap\{K\in\mathcal{K}:S\subseteq K\}
.
Note that
\langle{S}\rangle
is convex by intersection closure.

We may now state the definition of
CA

[
66
,
57
]
. We mention that, throughout the paper, we will use
valid value
to refer to a value satisfying Convex Validity, as defined below.

Definition 2

(Convex Agreement)
.

Let
\Pi
be an
n
-party protocol where each party holds a value
v_{\textsc{in}}
as input, and parties terminate upon generating an output
v_{\textsc{out}}
.
\Pi
achieves Convex Agreement if the following properties hold even when
t
of the
n
parties are corrupted:

(Termination)
All honest parties terminate;
(Convex Validity)
Honest parties’ outputs lie in the honest inputs’ convex hull;
(Agreement)
All honest parties output the same value.

Optimal resilience thresholds for
CA
on a convexity space depend on a feature of the space called the
Helly number
, denoted by
\omega
. In
\mathbb{R}^{d}
with standard (line-segment) convexity, Helly’s theorem states that if every subcollection of size
D+1
of a finite family of convex sets intersects, then the whole family intersects
[
22
]
.
Motivated by this, the
Helly number

\omega
of a convexity space
\mathcal{C}
is the smallest
h
such that for every finite family
\{C_{i}\}\subseteq\mathcal{K}
, if every
h
of the sets intersect, then
\bigcap_{i}C_{i}\neq\varnothing
. For example,
\omega=D+1
for standard convexity in
\mathbb{R}^{d}
, while
\omega=2
for box convexity.
For
CA
on a convexity space with Helly number
\omega
, the optimal resilience thresholds are
t<n/\max(3,\omega)
in unauthenticated settings, and
n/\omega
in authenticated settings
[
66
,
57
,
21
]
.

Bit representations.

Throughout the paper, values in a convexity space
\mathcal{C}
are manipulated as bitstrings for communication purposes.
We therefore fix a
binary representation scheme
for
\mathcal{C}
, i.e., a surjective function

\textsf{dec}:\{0,1\}^{\star}\mapsto\mathcal{C}
. Note that for any convexity space
\mathcal{C}
, there may be multiple such functions
dec
. Given a decoding function
dec
, we define its encoding
\textsf{enc}:\mathcal{C}\mapsto\{0,1\}^{\star}
such that
\textsf{enc}(v)=\arg\min\{|b|,b\in\{0,1\}^{\star},\textsf{dec}(b)=v\}
. Basically, multiple binary strings can be decoded to the same value and we chose the encoding of a value as the smallest binary string which represents it.

Given an encoding
enc
for a convexity space
\mathcal{C}
, we call another encoding
\textsf{enc}^{\star}
an extension of
enc
if for all
v\in\mathcal{C}
,
|\textsf{enc}^{\ast}(v)|\leq|\textsf{enc}(v)|+1
. The idea of an extension encoding is that in the worst case, only one additional bit is needed to encode a value, but this can allow some values to be encoded in a more compact way.

For a value
v\in\mathcal{C}
, we denote by
|v|_{b}:=|\textsf{enc}(v)|
the bit-length of its encoding.
When we say that values have
L
-bit representations, we mean that
|v|_{b}\leq L
for every value under consideration.

While the optimal resilience thresholds for
CA
guarantee that the honest parties can always identify a valid value
v
, the bit-length of
v
may be higher than the original inputs’ bit-lengths. Our protocols will require the parties to compute intermediate valid values before
CA
is achieved. To control the growth of intermediate values’ bit-lengths, we introduce the notion of
dilation factor

\delta
for a convexity space:

Definition 3

(Dilation factor of a convexity space)
.

Let
\mathcal{C}
be a convexity space with Helly number
\omega
and encoding
enc
. For a given
\delta>0
, we say that
\mathcal{C}
has dilation factor
\delta
if there exists an encoding
\textsf{enc}^{\ast}
which is an extension of
enc
such that for any
L\geq\log(\omega)
and any finite multiset
S\subseteq\mathcal{C}
whose elements can be represented using at most
L
bits, there is an element
v\in\bigcap_{A\subseteq S,|S\setminus A|<|S|/\omega}\langle{A}\rangle
which can be represented using at most
\delta\cdot L
bits.

We say that a convexity space
\mathcal{C}
has finite dilation number if there is a
\delta>0
such that
\mathcal{C}
has dilation factor
\delta
. We analyze the dilation factor for finite convexity spaces (e.g., a finite graph with minimal-path convexity) and for
\mathbb{R}^{d}
with straight-line convexity.

The next theorem is a direct consequence of the definition of the Helly number and can be obtained using
\textsf{enc}^{\ast}=\textsf{enc}
.

Theorem 4
.

Let
\mathcal{C}
be a finite convexity space with Helly number
\omega
, where every element is encoded using
L
bits. Then
\mathcal{C}
has dilation factor
\delta:=1
.

For the theorem below, we defer the proof to
Appendix

A
.

Theorem 5
.

Let
d>0
and
\mathcal{C}
be a convex subset of
\mathbb{R}^{d}
with straight-line convexity. Then,
C
has dilation factor
\delta:=d\cdot(d+1)
.

Communication complexity and round complexity.

We denote the communication complexity for
L
-bit inputs of an
n
-party protocol
\Pi
by
\textsc{bits}_{L,n}(\Pi)
: this is the worst-case total number of bits sent by honest parties if they all hold inputs of at most
L
bits.
In addition,
\textsc{rounds}_{n}(\Pi)
denotes the worst-case round complexity of
\Pi
. We add that for some of our subprotocols we will use different subscripts for the
bits
notation, and the meaning will be clear in context.

3
Protocol for Fixed Inputs’ Bit-Length

The core idea of our approach is to reduce the number of inputs from up to
n
valid inputs to up to a small number
\gamma_{\delta,n}
of valid inputs. To achieve this, we proceed in iterations: the parties are initially arranged into
N:=n

supernodes
such that each (
good
) supernode holds a valid input, and we re-arrange them into
N^{\prime}:=N/\gamma_{\delta,n}
supernodes with valid inputs. We define the factor
\gamma_{\delta,n}
as
\gamma_{\delta,n}:=2
if the input space has dilation factor
\delta=1
, and with
\gamma_{\delta,n}:=\log\log n
otherwise.
This approach leads us to the theorems below, assuming that the honest parties know an upper bound
L
on their inputs’ bit-length a priori. Without this assumption, a byzantine party could follow the protocol correctly with an input of arbitrary bit-length, and force honest parties to relay it. We remove this assumption in
Section

4
, where we describe a mechanism that estimates
L
, enabling us to rely on the protocol described here.

Theorem 6
.

Consider an arbitrary constant
\varepsilon>0
and a convexity space
\mathcal{C}
with constant Helly number
\omega\geq 2
and dilation factor
\delta=1

3.1
Building Block:

within Supernodes

Before describing our subprotocols, we need to highlight a few technical details.

Our protocol assumes a
BA
protocol
\Pi_{\textsc{BA}}
that achieves optimal communication for short messages: this will be run among
supernodes
. As a party may belong to multiple supernodes, the same party may appear in the protocol multiple times, hence simulating multiple
virtual parties
. Our protocols will therefore distinguish between
parties
and
virtual parties
. We say that a virtual party is honest if it is simulated by an honest party, and that a virtual party is byzantine if it is simulated by a byzantine party.
We therefore consider the following property:

(Multi-Participation Safety)
If
\Pi_{\textsc{BA}}
achieves
BA
in an
n
-party setting where up to
t
out of the
n
parties involved are byzantine, then it also achieves
BA
even when it runs in a setting of
n

virtual
parties out of which up to
t
may be simulated by byzantine parties;

In addition, we will be running
\Pi_{\textsc{BA}}
in settings where the number of (virtual) byzantine parties may exceed the number of corruptions that
\Pi_{\textsc{BA}}
can tolerate. We need to ensure that it maintains its communication complexity and round complexity even in such settings.

(Extra-Corruptions Safety)
If
\Pi_{\textsc{BA}}
has round complexity
\textsc{rounds}_{n}(\Pi_{\textsc{BA}})
and the honest parties send
\textsc{bits}_{L,n}(\Pi_{\textsc{BA}})
bits in total by round
\textsc{rounds}_{n}(\Pi_{\textsc{BA}})
in an
n
-party setting where up to
t
out of the
n
parties involved are byzantine, then: in a setting of
n
(virtual) parties where the number of
(virtual)
byzantine parties exceeds
t
, honest parties still complete the execution of
\Pi_{\textsc{BA}}
within
\textsc{rounds}_{n}(\Pi_{\textsc{BA}})
rounds, and still send
\textsc{bits}_{L,n}(\Pi_{\textsc{BA}})
bits in total by round
\textsc{rounds}_{n}(\Pi_{\textsc{BA}})
.

These properties apply naturally to many unauthenticated protocols, and also to authenticated protocols that rely solely on PKI and signatures (notably, without threshold signatures). Concretely, we make use of the unauthenticated protocol of
[
8
]
and of the authenticated protocol of
[
54
]
, described by the theorems below. We discuss the details regarding Multi-Participation Safety and Extra-Corruptions Safety in
Appendix

D
. Moreover, we note that
[
54
]
analyzes the communication complexity of their protocol assuming inputs of length
L=\mathcal{O}(\kappa)
. We extend their analysis to general

in
Appendix

.

On lower resilience thresholds.

We first highlight the reasons behind the reduced resilience threshold: when

To be more specific, the safe area may be reduced to a single point whose length depends on the byzantine inputs length. For example, in

However, this approach would require some kind of public randomness, and our focus is on deterministic algorithms anyway. As such, a randomized approach would not work. However, we discover that assigning parties to committees pseudo-uniformly can be done via an object called

Extractors.

Historically, extractors were used to extract random bits from a ”weak” random source, and their main application was in error-correcting codes
[
61
]
. We give a definition of an extractor in terms of a bipartite graph.

Definition 5
.

A bipartite multi-graph
G=(L\cup R,E)
with
\big\lvert L\big\rvert=n
,
\big\lvert R\big\rvert=m
is left-regular of degree
d
on the left. This graph is a
(k,\varepsilon)
-extractor if, for every subset
S\subseteq L
of size at least
k
and for every subset
T\subseteq R
, it holds that:
\left|\frac{\big\lvert E(S,T)\big\rvert}{d\cdot\big\lvert S\big\rvert}-\frac{\big\lvert T\big\rvert}{\big\lvert R\big\rvert}\right|<\varepsilon
. That is, the probability that an edge leaving
S
goes to
T
is
\varepsilon
-close to the probability that a random vertex on the right is in
T
.

We note that this definition is slightly different compared to the regular one. First, the regular definition uses the concept of min-entropy while for simplicity, we only consider subsets of size at least
k
, which is a weaker notion. Moreover, when building such a graph from an extractor,
n
,
m
and
d
are usually required to be powers of
2
, which is not the case here. Nevertheless, the extractor construction we use works for arbitrary
n
.

Random bipartite graphs are good extractors with high probability. However, generating a random bipartite graph and checking that it is an extractor would take exponential time. Given practical considerations and since we use hashes, which rely on the assumption that the adversary is computationally bounded, we can not allow ourselves this approach to constructing extractors. We thus turn our focus towards
explicit
extractors. A graph is called
explicit
if there exists a deterministic algorithm to build it in time polynomial in its size.

The last point of interest is that the existing literature for extractors mainly focuses on the case where
k<<n
. Meanwhile, for our use case, we want
k\geq t
and thus our interest lies in what are called
high min-entropy
extractors, which have seen much sparser coverage. We give an explicit extractor with near-optimal properties for our use case:

Theorem 21
.

Let
\varepsilon>0,\alpha\in]0,1[
. Then, there is
D(\varepsilon,\alpha)=\mathsf{poly}(1/\varepsilon,1/\alpha)>0
such that, for any
n
and
k\geq\max(\lfloor\alpha\cdot n\rfloor,1)
, there is an explicit
(k,\varepsilon)
-extractor, which has left and right sides of size
n
each and is biregular with degree
D(\varepsilon)
.

Proof.

As we said previously, this kind of extractor with
k=\Omega(n)
is more of a side-interest for the existing literature.
[
65
, Theorem 6.22]
gives a similar result but does not impose
R
to be regular. To make this possible, we start from the first part of the proof from
[
65
, Theorem 6.22]
which shows that if a graph
G=(V,E)
with
|V|=n
has spectral expansion
\lambda
, then the bipartite graph representing its incidence matrix (i.e
L=V\times\{0\}

R=V\times\{1\}
and for every edge

((u,0),(v,1))
and

By using

6
Conclusions

In this paper, we have investigated whether we can achieve
CA
deterministically, with near-optimal communication complexity. For spaces with dilation factor
1
, we achieve communication complexity
\mathcal{O}(L\cdot n\log n+n^{2}\kappa\log n)
, where
\kappa
denotes a security parameter and
L
denotes an upper bound on the honest inputs’ bit-lengths. For spaces with finite dilation factor, we achieve communication complexity
\mathcal{O}(L\cdot n^{1+o(1)}+n^{2}\kappa\log^{1+o(1)}n)
.

As pointed out in
[
38
]
, the standard communication-saving techniques for Byzantine Agreement do not directly extend to
CA
:
they crucially rely on
compressing
parties’ inputs into short encodings that can be efficiently propagated and decoded, whereas in
CA
we must preserve the
geometric/convex structure
of the input space.
Our protocols overcome this obstacle by compressing the
system
rather than the
values
.
Concretely, our main technical contribution is our use of
extractor-based deterministic committees
:
the extractor’s expansion guarantees that, even against an adaptive Byzantine adversary, most committees contain enough honest parties to make progress.
By iterating committee aggregation, we “compress”
n
parties (or supernodes) down to a small set of supernodes, each holding a valid value.
At that point, coordinating among only a few candidate outputs suffices to complete
CA
efficiently.
Overall, this yields deterministic
CA
protocols with near-optimal communication complexity for sufficiently large
L
, asymptotically optimal round complexity, and near-optimal resilience.
Our results have implications beyond
CA
:
in particular, the same extractor-based committee-compression framework provides communication-efficient corollaries for parallel instances of
BA
.

Our work leaves a couple of interesting open problems for further research:

•

Reducing the gap further.
Since
\Omega(Ln)
bits of communication are necessary, can one obtain deterministic
CA
for arbitrary convexity spaces with communication
\mathcal{O}(Ln+\mathsf{poly}(n,\kappa))
, while retaining optimal rounds and near-optimal resilience?

•

Sharper resilience, especially without a priori bounds on
L
.

Is it possible to achieve
CA
on arbitrary convexity spaces with communication complexity
o(Ln^{2})
with near-optimal resilience (with or without
\varepsilon
-slack) when no upper bound on the honest inputs’ bit-length is known in advance?

•

Further reducing communication, in particular for
\delta>1
.

For convexity spaces with finite dilation factor
\delta>1
, our protocols achieve communication complexity
\mathcal{O}(L\cdot n^{1+o(1)}+n^{2}\kappa\log^{1+o(1)}n)
.
Is higher communication inherent for such spaces?

•

Beyond
CA
: general validity in
BA
.

Can our extractor-based committee approach be extended to synchronous
BA
variants with more general validity conditions?

Appendix D
Multi-Participation Safety and Extra-Corruptions Safety

Our protocols assume a
BA
protocol
\Pi_{\textsc{BA}}
and run it in non-standard settings: where the number of byzantine parties may exceed those that
\Pi_{\textsc{BA}}
may tolerate, and where each party may simulate multiple
virtual
parties.

Mapping between parties and simulated parties.

We recall that the set of virtual parties
\mathcal{P}_{V}:=\{P_{1},P_{2},\ldots,P_{m}\}
and the mapping to real parties
M:\mathcal{P}\rightarrow 2^{\mathcal{P}_{V}}
is known to all parties.
As we will be sending party indices over the network, we also define
p(P_{i},M(P))
as the position of
P_{i}
in the list
M(P)
sorted increasingly by the indices
i
. In our protocols, each party simulates a constant number of virtual parties at a time, hence
p(P_{i},M(P))\in\mathcal{O}(1)
for every
P\in\mathcal{P}
and for every
P_{i}\in M(P)
.

Communication over simulated parties.

Whenever virtual party
P_{i}\in M(P)
needs to send a message
\mathtt{msg}
to virtual party
P_{j}
, party
P_{i}
simulates this locally if
P_{j}\in M(P)
, and otherwise sends message
(\mathtt{msg},p(P_{i},M(P)),p(P_{j},M(P^{\prime})))
to
P^{\prime}=M^{-1}(P_{j})
. When party
P^{\prime}=M(P_{j})^{-1}
receives a message
(\mathtt{msg},p(P_{i},M(P)),p(P_{j},M(P^{\prime})))
from
P_{i}
, it forwards the message to the virtual party
P_{j}
that it simulates. Note that this only incurs an overhead of additional
O(1)
bits per message.

Signatures for simulated parties.

For authenticated
BA
we need to note that the PKI is set in place for the real parties, and not for the simulated parties. For the protocol of
[
54
]
, it suffices if we modify the signing function: if virtual party
P_{i}
needs to sign message
\mathtt{msg}
, then
P=M^{-1}(P_{i})
signs
(\mathtt{msg},i)
using its own secret key. When virtual party
P_{j}
needs to verify the signature of simulated
P_{i}
on message
\mathtt{msg}
,
P^{\prime}=M^{-1}(P_{j})
verifies the signature on
(\mathtt{msg},i)
using the public key of
P=M^{-1}(P_{i})
.

Extra-Corruptions Safety: round complexity.

We may assume without loss of generality that any
BA
protocol
\Pi_{\textsc{BA}}
that has an upper bound
R
maintains this property even in a setting with more byzantine parties that
\Pi_{\textsc{BA}}
can tolerate: once
R
rounds have passed, every honest (virtual) party may simply output
\bot
.

Extra-Corruptions Safety: communication complexity

Assuming that a
BA
protocol
\Pi_{\textsc{BA}}
maintains its upper bound on communication complexity even in a setting with more corrupted parties that it can tolerate is not without loss of generality. However, this property is achieved naturally by many protocols where the message scheme is fixed in advance, and an upper bound on the number of bits each party sends in each step can be fixed in advance. This is the case, for instance, in the protocol of
[
8
]
for unauthenticated settings, and in the protocol of
[
54
]
for authenticated settings: in each step, each party sends one value (of bounded size, as we run
BA
on inputs of known length), and up to
\mathcal{O}(n)
signatures of size
\mathcal{O}(\kappa)
each.

Appendix E
Authenticated
BA
: Communication Complexity

The
\Pi_{\textsc{BA}}
protocol of
[
54
]
achieves communication complexity
\textsc{bits}_{L,n}(\Pi_{\textsc{BA}})=\mathcal{O}(\kappa n^{2})
for
L\in\mathcal{O}(\kappa)
. We make
L
explicit in their analysis, and show that
\textsc{bits}_{L,n}(\Pi_{\textsc{BA}})=\mathcal{O}((L+\kappa)\cdot n^{2})
.

\Pi_{\textsc{BA}}
(presented in
[
54
, Figure 1]
) assumes that the input values come from an arbitrary input space
V
. It relies on a weaker variant of
BA
, namely Graded Byzantine Agreement (
gBA
) – parties initially hold inputs from
V
, and, instead of agreeing on a value
v\in V
, each party obtains a value
v\in V
and a grade of confidence
g\in\{0,1\}
. The Validity property for
gBA
requires that, if all honest parties hold input
v
, then every honest party outputs
(v,1)
. Agreement is replaced with Consistency: if an honest party outputs
(v,1)
, then no honest party outputs
(v^{\prime},g^{\prime})
with
v^{\prime}\neq v
.
Assuming a
gBA
protocol
\Pi_{\textsc{gBA}}
,
\Pi_{\textsc{BA}}
becomes a recursive construction:
if the set of parties is small (at most a constant
M
satisfying
2^{r-1}M\leq n\leq 2^{r}
), the parties rely on an inefficient
BA
protocol. Otherwise, the parties first run
\Pi_{\textsc{gBA}}
. This is followed by a
\Pi_{\textsc{BA}}
execution on the first half of the set of parties – they join with the value obtained in
\Pi_{\textsc{gBA}}
, and reports the output obtained to the entire set. Note that
\Pi_{\textsc{BA}}
is only guaranteed to succeed if the first half of the set of parties contains an honest majority. Each party
P
checks if a majority of the values reported are the same – if this is the case, and
P
did not obtain a different value with grade
1
in
\Pi_{\textsc{gBA}}
, it adopts this value. This way, if the first half of the set of parties contains an honest majority,
BA
is already achieved. If this was not the case, then the second half of the set of parties contains an honest majority. The protocol continues with another execution of
\Pi_{\textsc{gBA}}
on the values adopted, a
\Pi_{\textsc{BA}}
execution on the second half of the parties, and another check. If
BA
was already achieved in the first part, it is maintained, otherwise it is now achieved.

The work of
[
54
]
proposes two constructions of
\Pi_{\textsc{gBA}}
. The first construction, described in
[
54
, Section 4.1]
, leads to communication complexity
\mathcal{O}(\kappa n^{2})
in
\Pi_{\textsc{BA}}
for inputs of
\mathcal{O}(\kappa)
bits even up to
t<n/2
corruptions, but relies on threshold signatures. The second construction, described in
[
54
, Section 4.2]
, leads to the same communication complexity for
t<(1/2-\varepsilon)\cdot n
for any predefined constant
\varepsilon>0
, but without threshold signatures.
Recall that we run
\Pi_{\textsc{BA}}
in settings with virtual parties, where multiple virtual parties may be simulated by the same party, hence we cannot rely on threshold signatures, and therefore we rely on the latter
\Pi_{\textsc{gBA}}
construction.

While
[
54
]
states that
\Pi_{\textsc{gBA}}
has communication complexity
\textsc{bits}_{\mathcal{O}(1),s}=\mathcal{O}(\kappa s^{2})
, it is easy to make the inputs’ length
L
explicit in their analysis.
Throughout the execution of
\Pi_{\textsc{gBA}}
in a setting of
s
parties, each party sends
\mathcal{O}(s)
messages, and
\mathcal{O}(d)
certificates, where
d\in\mathcal{O}(1/\varepsilon)=\mathcal{O}(1)
, as
\varepsilon
is a constant. Each message consists of an (input) value and a signature, and each certificate consists of
\mathcal{O}(s)
signed (input) values. As signatures consist of
\mathcal{O}(\kappa)
bits and we run
\Pi_{\textsc{BA}}
, and therefore
\Pi_{\textsc{gBA}}
in settings where an upper bound
L
on the honest inputs’ length is known, each message has length
\mathcal{O}(L+\kappa)
, and each certificate has size
\mathcal{O}(s\cdot(L+\kappa))
. This leads to
\mathcal{O}(s\cdot(L+\kappa))+\mathcal{O}(d\cdot s\cdot(L+\kappa))=\mathcal{O}(s\cdot(L+\kappa))
bits per party. Then, the communication complexity becomes
\textsc{bits}_{L,s}(\Pi_{\textsc{gBA}}):=\mathcal{O}((L+\kappa)\cdot s^{2})
.

We may then make
L
explicit in the analysis of
\Pi_{\textsc{BA}}
as well, by following
[
54
, Lemma 10]
: in an instance over
s\leq M
parties, one can use an inefficient
BA
protocol with communication complexity
\mathcal{O}((L+\kappa)\cdot s^{3})
(as we use this protocol in settings where
L
is known, we may obtain this via
BC

[
25
]
). As
s=\mathcal{O}(1)
in this case, the communication complexity is
C(s)=\mathcal{O}(L+\kappa)
. In an instance over
s>M
parties, the communication complexity is defined recursively:

\displaystyle C(s)

\displaystyle=\textsc{bits}_{L,\lfloor s/2\rfloor}(\Pi_{\textsc{gBA}})+C(\lfloor s/2\rfloor)+\mathcal{O}((L+\kappa)\cdot s^{2})+C(\lceil s/2\rceil)+\textsc{bits}_{L,\lceil s/2\rceil}(\Pi_{\textsc{gBA}})

\displaystyle=\mathcal{O}((L+\kappa)\cdot s^{2})+C(\lfloor s/2\rfloor)+C(\lceil s/2\rceil).

As
2^{r-1}\cdot M\leq n\leq 2^{r}
, it follows that:

\displaystyle C(n)\leq 2^{r}\cdot\mathcal{O}(L+\kappa)+\sum_{i=0}^{r}2^{i}\cdot\mathcal{O}((L+\kappa)\cdot(n/2^{i})^{2})=\mathcal{O}((L+\kappa)\cdot n^{2}),

hence
\textsc{bits}_{L,n}(\Pi_{\textsc{BA}})=C(n)=\mathcal{O}((L+\kappa)\cdot n^{2})
, as claimed.
