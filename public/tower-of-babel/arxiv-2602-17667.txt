When & How to Write for Personalized Demand-aware Query Rewriting in Video Search
Cheng Cheng, Chenxing Wang, Aolin Li, Haijun Wu, Huiyun Hu, Juyuan Wang

Abstract
. In video search systems, user historical behaviors provide rich context for identifying search intent and resolving ambiguity. However, traditional methods utilizing implicit history features often suffer from signal dilution and delayed feedback. To address these challenges, we propose WeWrite , a novel Personalized Demand-aware Query Rewriting framework. Specifically, WeWrite tackles three key challenges: (1) When to Write : An automated posterior-based mining strategy extracts high-quality samples from user logs, identifying scenarios where personalization is strictly necessary; (2) How to Write : A hybrid training paradigm combines Supervised Fine-Tuning (SFT) with Group Relative Policy Optimization (GRPO) to align the LLM’s output style with the retrieval system; (3) Deployment : A parallel "Fake Recall" architecture ensures low latency. Online A/B testing on a large-scale video platform demonstrates that WeWrite improves the Click-Through Video Volume (VV > > 10s) by 1.07% and reduces the Query Reformulation Rate by 2.97%.

2.
Methodology

In this section, we present the proposed
Personalized Demand-aware Query Rewriting
framework.
As illustrated in Figure
3
, the system consists of three main modules:
(1)
Posterior-based Sample Mining
, which constructs high-quality training data from user feedback logs to determine
when
to write;
(2)
Style-aligned LLM Fine-tuning
, which trains the model to learn
how
to write by combining Supervised Fine-Tuning (SFT) and Reinforcement Learning (RL);
(3)
Deployment with Fake Recall
, a parallel execution architecture ensuring low-latency online serving.

2.1.
Problem Formulation

The goal of personalized query rewriting is to generate a reformulated query
Q^{\prime}
based on the user’s original query
Q
and historical context
C_{u}
, such that
Q^{\prime}
retrieves documents maximizing the user’s utility (e.g., valid video consumption).
Formally, we define the user context as a tuple
C_{u}=\{H_{query},H_{video},G\}
, where
H_{query}
and
H_{video}
denote the sequence of historical queries and watched videos, respectively, and
G
represents geolocation features.

We formulate the rewriting task as learning a conditional generation policy
\pi_{\theta}(Q^{\prime}|Q,C_{u})
.
Unlike traditional rewriting that focuses solely on semantic equivalence, our objective is to maximize the expected reward reflecting both
user satisfaction
(Click-Through Rate) and
system retrievability
(Index Hit Rate):

(1)

\theta^{*}=\operatorname*{argmax}_{\theta}\mathbb{E}_{(Q,C_{u})\sim\mathcal{D},Q^{\prime}\sim\pi_{\theta}}[R(Q^{\prime},\mathcal{I}_{sys})]

where
\mathcal{I}_{sys}
represents the online search index and
R(\cdot)
is the reward function defined in Section
2.3
.

2.2.
Posterior-based Sample Mining

A core challenge in personalized rewriting is determining "When to Write".
Indiscriminately rewriting every query introduces noise and increases system load.
To address this, we propose an automated mining strategy that leverages user posterior behaviors (e.g., query reformulations and dwell time) to extract samples where personalization is strictly necessary.
This process generates two types of data:
Rewrite Samples (Positive)
and
Reject Samples (Negative)
.

2.2.1.
Context Definition

We define the user context
C_{u}
as a tuple containing recent interaction history and geolocation:

(2)

C_{u}=\{H_{query},H_{video},G\}

where
H_{query}
is the sequence of recent search queries,
H_{video}
represents the list of recently watched videos (including titles and tags), and
G
denotes the geographical information.

2.2.2.
Positive Sample Mining (Rewrite)

User dissatisfaction is often signaled by immediate query reformulations.
We aim to capture the mapping from an initial failed query
Q_{orig}
to a successful reformulated query
Q_{next}
, conditioned on context
C_{u}
.
A query pair
(Q_{orig},Q_{next})
within a session is selected as a candidate if it satisfies the following temporal constraints:

•

Failure on Origin:
The user had little to no interaction with the results of
Q_{orig}
. Specifically, the maximum video dwell time
T_{orig}<\tau_{short}
(where
\tau_{short}=2.4s
).

•

Success on Next:
The user performed a valid consumption on the results of
Q_{next}
with dwell time
T_{next}>\tau_{valid}
(where
\tau_{valid}=10s
).

However, not all reformulations are driven by personalization (e.g., correcting a typo).
To ensure the rewrite is
demand-aware
, we apply a
two-stage filtering
process:

Step 1: Context Overlap Filter (Coarse-grained):

We calculate the set of new terms introduced in the reformulation:
\Delta T=\text{Terms}(Q_{next})\setminus\text{Terms}(Q_{orig})
.
A sample is retained only if at least one term in
\Delta T
appears in the user’s context history
C_{u}
(e.g., in video titles of
H_{video}
).
This heuristic ensures that the intent shift is grounded in historical behavior.

Step 2: LLM-based Intent Verification (Fine-grained):

To handle subtle semantic dependencies and eliminate false positives, we employ a powerful teacher model (Qwen3-32B) to perform binary classification.
We instruct the LLM to act as an expert data annotator to verify if the query reformulation is explicitly supported by the user’s context.
The specific instruction prompt is designed as follows:

Role:
You are an experienced data annotator specializing in short-form video search analysis.

Task:
Users often reformulate queries when dissatisfied. Given the
Original Query
,
User Context
(Gender, Location, Viewed Videos), and the
Reformulated Query
, determine if the reformulation is derived from the context or is a valid correction.

Constraint:
A valid contextual dependency exists
only if
the new terms (gain words) in the
Reformulated Query
explicitly appear in the
User Context
.

Input:

•

Original Query:
Q_{orig}

•

User Context:
C_{u}

•

Reformulated Query:
Q_{next}

Output:
Answer "Positive" if there is a clear contextual clue; otherwise, answer "Negative".

The model inputs
(C_{u},Q_{orig},Q_{next})
and executes the prompt.
Only samples labeled as "Positive" are deemed strictly demand-aware and added to the final training set
S_{pos}=\{(C_{u},Q_{orig})\to Q_{next}\}
.

2.2.3.
Negative Sample Mining (Reject)

To teach the model
when not to rewrite
, we mine instances where the user’s original query
Q_{orig}
immediately led to satisfaction.
We select samples where no reformulation occurred and the user generated a long consumption (
T_{orig}>\tau_{long}
).
These are labeled as
S_{neg}=\{(C_{u},Q_{orig})\to\texttt{<reject>}\}
, instructing the model to output a special token stopping the rewriting process.

2.3.
Style-aligned LLM Fine-tuning

After determining "when" to rewrite, the next challenge is "how" to generate rewrites that are both semantically accurate and system-friendly.
We employ a two-stage training paradigm: Supervised Fine-Tuning (SFT) for semantic generation and Reinforcement Learning (RL) for style alignment.

2.3.1.
Supervised Fine-Tuning (SFT)

We use the mined dataset
D_{train}=S_{pos}\cup S_{neg}
to fine-tune a base LLM (e.g., Qwen).
To guide the model’s generation, we construct an input sequence
x
that incorporates the user context
C_{u}
and the original query
Q_{orig}
wrapped in a specific system instruction.
The prompt is designed as follows:

Instruction:
Based on user features such as recently watched videos, gender, and historical search queries, determine whether the current query needs to be refined, rewritten, or corrected. If necessary, directly output the rewritten or corrected query; otherwise, output
<reject>
.

Correspondingly, the target sequence
y
is either the reformulated query
Q_{next}
(for positive samples) or the special token
<reject>
(for negative samples).
The SFT objective is to minimize the standard negative log-likelihood:

(3)

\mathcal{L}_{SFT}=-\sum_{t=1}^{|y|}\log P(y_{t}|y_{<t},C_{u},Q_{orig})

2.3.2.
RL for Style Alignment

A common issue with generative rewriting is that the model may produce semantically correct queries that are sufficiently rare or complex that they fail to retrieve valid results in the existing search index (e.g., "zero-recall" problem).
To address this, we introduce a Reinforcement Learning stage to align the generated queries with the online system’s query distribution.

We model the rewriting process as a Markov Decision Process (MDP).
The
Action Space
is the vocabulary of the LLM, and the
State
includes the context and generated tokens so far.
To encourage the model to generate "searchable" queries, we design a
Posterior Reward Function

R(Q_{rew})
based on 180 days of historical search logs:

(4)

R(Q_{rew})=\begin{cases}\begin{aligned} &\lambda_{1}\cdot\log(\text{Freq}(Q_{rew}))\\
&+\lambda_{2}\cdot\text{CTR}(Q_{rew})\end{aligned}&\text{if }Q_{rew}\in\mathcal{V}_{sys}\\
R_{penalty}&\text{otherwise}\end{cases}

where
\mathcal{V}_{sys}
denotes the set of valid queries in the online system,
\text{Freq}(Q_{rew})
is the historical search frequency, encouraging the model to generate popular, well-indexed queries,
\text{CTR}(Q_{rew})
is the historical average Click-Through Rate, biasing the model towards queries with high user satisfaction and
R_{penalty}
is a negative reward to discourage the generation of unknown terms (hallucinations).

Finally, to efficiently optimize the policy without the overhead of a value network, we employ Group Relative Policy Optimization (GRPO).
For each input, we sample a group of
G
rewrites
\{Q^{\prime}_{1},\dots,Q^{\prime}_{G}\}
from the current policy
\pi_{\theta}
.
The advantage
A_{i}
for the
i
-th rewrite is computed by normalizing its reward against the group statistics:

(5)

A_{i}=\frac{R(Q^{\prime}_{i})-\mu(\mathbf{R})}{\sigma(\mathbf{R})+\epsilon}

where
\mu(\mathbf{R})
and
\sigma(\mathbf{R})
are the mean and standard deviation of the group rewards.
The final hybrid loss function maximizes the policy advantage while penalizing deviation from the reference model via KL-divergence (
D_{KL}
):

(6)

\mathcal{L}_{Total}=\mathcal{L}_{SFT}-\beta\cdot\mathbb{E}\left[\frac{1}{G}\sum_{i=1}^{G}\left(\frac{\pi_{\theta}(Q^{\prime}_{i})}{\pi_{old}(Q^{\prime}_{i})}A_{i}-\gamma D_{KL}\right)\right]

where
\beta
controls the contribution of the RL signal.

2.4.
Deployment: Fake Recall & Fusion

Deploying LLMs in a real-time video search system with strict latency constraints is non-trivial.
A serial execution flow would introduce unacceptable delays.
To solve this, we propose a parallel
Fake Recall
architecture.

2.4.1.
Fake Index Construction

We pre-build a key-value index, denoted as
I_{fake}
, mapping valid system queries to their top-performing documents.
To guarantee index coverage and mitigate the sparsity of click signals (especially for long-tail queries), we employ a
hybrid construction strategy
:

•

Interaction-based:
For head queries with rich feedback, we cache the Top-
K
documents based on historical CTR and dwell time.

•

Retrieval-based:
For queries with sparse interaction data, we supplement the index by mining the top-ranked documents from historical search logs.

This pre-built index acts as a massive "result cache" (
K=50
), allowing the system to retrieve candidates for the LLM-generated query
Q_{rew}
in
O(1)
time, bypassing the heavy online retrieval chain.

2.4.2.
Online Parallel Fusion

The online serving flow minimizes latency through parallelism:

(1)

Parallel Execution:
When a user request arrives, the system triggers the
Traditional Search Path
(Text/Vector Recall) and the
Personalized Rewriting Path
simultaneously.

(2)

Asynchronous Inference:
The LLM computes the rewrite
Q_{rew}
asynchronously. If
Q_{rew}
hits the Fake Index
I_{fake}
, we retrieve the candidate document list
Cand_{fake}
.

(3)

Relevance Filtering:
To ensure safety, we apply a lightweight relevance model to filter
Cand_{fake}
, removing documents that are irrelevant to the original intent.

(4)

Fusion:
Finally,
Cand_{fake}
is merged with the main candidate set
Cand_{main}
. Since the LLM inference runs in parallel with the heavy traditional recall phase, the total end-to-end latency remains unchanged, achieving
zero-perceived-latency
personalization.

3.
Experiments

We evaluate the proposed framework through large-scale online A/B testing.

3.1.
Online A/B Testing

We deployed the optimal model (Qwen3-4B + SFT + GRPO) online.
The A/B test results show a
1.07% increase
in
click through video volumn with stay time
>
10s (VV>10s)
and a
2.97% decrease
in Query Reformulation Rate, validating the framework’s effectiveness in a real-world production environment.

4.
Conclusion

In this paper, we presented a novel
Personalized Demand-aware Query Rewriting
framework for video search.
Addressing the limitations of implicit history modeling, we proposed an explicit generative approach that answers two fundamental questions:
When to Write
and
How to Write
.
Through posterior-based sample mining, we ensure that rewriting is triggered only when necessary.
By combining SFT with style-aligned Reinforcement Learning, we guarantee that generated queries are both personalized and retrieval-friendly.
Furthermore, our parallel "Fake Recall" architecture successfully overcomes the latency bottleneck of LLMs.
Online results demonstrate significant gains in user satisfaction, proving the effectiveness of explicit personalization in handling ambiguous user intents.
