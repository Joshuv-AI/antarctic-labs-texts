Protocol for automated analysis of oil red O-stained Caenorhabditis elegans using Redwormpix, a Python-based application
Authors: Thibaud Mabit, Constance Dubois, Audrey Labarre, J Alex Parker
Published: 2026

ABSTRACT
SummaryOil red O (ORO) staining is a widely used histological technique for visualizing neutral lipids in Caenorhabditis elegans. However, quantitative image analysis of ORO-stained worms remains largely manual, time-consuming, and prone to human error. Here, we present a protocol for automating the quantification of ORO staining using Redwormpix, an open-source Python-based application. We describe steps for installing software, transferring images, and running the application. We then detail procedures for manual validation and exporting results.Subject areas: Genetics, High Throughput Screening, Molecular/Chemical Probes

Before you begin

Lipid quantification in C. elegans through Oil Red O (ORO) staining provides valuable insights into metabolic regulation.1 While the method itself is straightforward, extracting consistent and biologically meaningful quantitative information from ORO-stained images remains challenging. Differences in worm size, staining intensity, and background illumination can strongly influence the results, emphasizing the need for standardized, automated analysis tools. In this context, the present study introduces Redwormpix, a computational workflow and web application designed to ensure reproducible and unbiased quantification of ORO staining. The approach relies on color-based intensity measurement of microscopy images, focusing on the red channel where the ORO signal is most pronounced. To quantitatively assess this coloration, two complementary metrics are commonly used: the integrated density, defined as the sum of pixel intensities within the region of interest (ROI), and the mean intensity, which normalizes the signal by the ROI surface area. Because individual worm sizes vary, the mean intensity was chosen as the most robust metric for cross-sample comparison.

Innovation

The extraction of relevant quantitative information from ORO-stained images continues to represent a significant challenge. Manual quantification is not only time consuming but also prone to human error during the segmentation process and data transfer.2 Disparities in the dimensions of worms, the intensity of staining, and the background illumination can exert a substantial influence on the outcomes of analyses. This underscores the necessity for the implementation of standardized, automated analysis tools. To overcome these issues, some automated analysis protocols have been developed.3,4 However, they still present important limitations, such as not accounting for worm size and requiring manual background removal. To address these challenges, we developed Redwormpix, a Python-based web application for automated, standardized lipid quantification. The protocol not only improves precision but also dramatically reduces processing time; for instance, the analysis of 50 images takes less than six minutes.

Redwormpix is built using the Streamlit framework.5 Upon execution, the application automatically launches in a web browser, processes the images, and exports the quantitative results as.xlsx files (Figure 1).

Redwormpix application architecture

Compared with recent approaches described in the literature, Redwormpix offers an efficient and user-friendly solution. It automatically detects and outlines each worm while allowing users to visually inspect and manually validate the segmentation results within the interface. This dual-level process, automated quantification combined with optional manual validation, ensures both efficiency and accuracy in lipid staining analysis. By fully automating the key steps of segmentation, background correction, and color quantification, the software minimizes human-related variability and eliminates common manual errors inherent to traditional ImageJ workflows. Its streamlined web interface and configuration file make it accessible to both expert and non-expert users, while preserving analytical rigor and reproducibility. Even without any coding experience, the installation can be easily achieved by following the instructions provided in the readme file.

Timing: Variable (2–3 s per image)

6.Click “Start” button to launch the operation. The application processes all the images one by one and folder by folder (Figure 3).

Note: The processing can be divided into two main parts: (1) creation of a binary mask (Figures S3 and S4) and (2) processing of the original image (mask application and color quantification, Figure S5). The mask is initially created and further processing is applied to correct it with scikit-image library8 built-in functions. The coloration quantification is subsequently performed on the original image. First, the image is inverted, and the blue channel is extracted. A background subtraction is applied to correct for residual background coloration and illumination variations. Finally, the previously generated mask is applied to isolate the worm and obtain the processed image (Figure S6).

Manual validation

Timing: Variable (<10 s per image)

This section provides a description of the manual validation step for processed images and offers guidance on achieving optimal results.

7.Validate or invalidate the image processing by clicking “accept” or “don’t accept” (Figure 4).

Validate or invalidate the image processing by clicking “accept” or “don’t accept” (Figure 4).

Note: The application presents three visual outputs: the original image, the segmented worm (binary mask), and the fully processed output image. This interface enables users to inspect visually and, if necessary, manually invalidate the segmentation results. Excluded images are saved in the “./redo” folder. Manual processing can be performed using software such as ImageJ, applying the same workflow described in the supplementary data (color inversion, blue channel extraction, background removal, and manual contouring). It is recommended to first apply this procedure to an accepted image to verify consistency of results.

Note: If necessary, a size threshold parameter can be adjusted within the application configuration file to fine-tune the removal of small artifacts or incomplete objects. (Problem 2 & Problem 3) During manual validation, images showing residual artifacts or incorrect segmentation can be excluded from analysis. Selecting the “Don’t accept” option automatically saves the corresponding image in a dedicated “redo” folder. At the end of this process, a.csv file is generated, listing all rejected images by condition. Since these files are stored in a specific directory, users can manually process these images later if they are particularly important for the experiment.

Note: The accept/reject step relies primarily on visual inspection. The worm contour produced by the software should correspond to what would be drawn manually. Whether to accept a particular image remains at the user’s discretion. As a guideline, if the software-generated mask differs by more than ∼10% from the worm size, this exceeds the typical uncertainty expected from manual contouring, and it is preferable to exclude the image and process it manually if its inclusion is critical. The main advantage of the software is to save time and process large numbers of images efficiently. Therefore, the occurrence of excluding individual images (that remains rare) has minimal impact and is acceptable.

Expected outcomes

The results are automatically saved in a dedicated output folder. Two Excel files are generated: (1) all_experiments.xlsx : This file contains a separate sheet for each experimental condition. Each sheet includes the following columns: experiment name, image name, worm area (expressed both in pixels and in square inches), integrated density, and mean intensity. (2) relative_to_control.xlsx: This file summarizes the relative percentage (%) in mean intensity for each condition, compared to the defined control experiment.

Note: Details for metrics calculation are given in the supplementary data Section II.4. Integrated density (int_den) and area in in2 (area_in2) are computed as informative purpose for comparison with ImageJ’s manual processing.

Quantification and statistical analysis

To assess the algorithm’s efficiency and robustness, the pipeline was applied to a set of five experimental conditions, each comprising 10 images. In parallel, the same analysis was performed manually in ImageJ by two users to compare results and simulate a real-world scenario. The outcomes of this comparison are presented in Figure 6.

Experimental relative percentage of difference in mean intensity obtained manually by two different users and with the application

For boxplots, minimum, first quartile, median, third quartile, maximum and outliers are shown.

The results obtained with the application correlate strongly with those of the users, particularly with those of User 1. This observation is especially noteworthy given the relatively small dataset size (n = 10 per condition), which makes the results more sensitive to noise and potential measurement errors. These findings therefore demonstrate the robustness and reliability of the algorithm. For Condition 2, the distribution of values obtained by User 2 appeared broader than those from User 1 or the application. A closer examination revealed that one image had been affected by a manual error, likely due to an incorrect entry or copy–paste mistake, thus explaining the discrepancy. This example further highlights the advantage of automation in minimizing human-related errors and ensuring consistent, reproducible quantification.

Limitations of the study

In its current implementation, the algorithm is optimized for images containing a single worm and for red-channel ORO staining. While this constraint reflects the most common experimental configuration, it currently prevents high-throughput analysis of multi-worm images or alternative staining modalities. However, the underlying codebase is modular and could be extended to accommodate these use cases if needed.

Another limitation concerns data handling: images are processed in real time without database storage, so if an unexpected interruption occurs, the whole pipeline must be rerun from the beginning. Similarly, when multiple analyses are performed sequentially, the control condition must be reprocessed each time to enable final comparative calculations. Finally, our validation was performed on images containing one or two fully visible worms. Since the algorithm relies on mean intensity, the method should, in principle, remain applicable when more worms are present in the field of view. However, images containing more than two worms have not yet been tested. Therefore, if users plan to analyze images containing a higher number of worms, preliminary checks should be performed to confirm proper segmentation and reliable intensity measurements.

Troubleshooting

Problem 1

Because the background is estimated from the upper 50-pixel band of the image, no worm should be present in this region when images are transferred. This helps to avoid inconsistencies across samples within a condition.

Potential solution

A simple solution to this issue is to rotate the image prior to processing (Figure 7).

Rotation for background subtraction

Problem 2

When the worm size is particularly small, the algorithm may occasionally generate an empty mask that can be identified during the manual validation step. This behavior results from the mask curation step, which includes a filtering process designed to remove small artifacts. If the worm’s area is below this threshold, it is mistakenly discarded during this step.

Potential solution

The minimum object size is defined by the area_threshold parameter in the config.ini file, initially set to 0.04. This default value was selected during software development based on the sizes of worms and artifacts in the images (Mendeley Data: http://www.doi.org/10.17632/9scm9y9jn6.1). Users can adjust it if needed. Reducing this value allows the algorithm to retain smaller worms (Figures 8 and 9).

config.ini file

Decreasing area_threshold for worm cut-out

Problem 3

It should be noted that decreasing the area_threshold value may introduce potential issues, particularly when multiple artifacts are present in the image, such as small worm fragments (identified during the manual validation step). In such cases, these elements may be retained as valid objects by the mask and subsequently included in the entire processing workflow, including the quantification step (Figure 10).

Potential solution
