Making the complete OpenAIRE citation graph easily accessible through compact data representation
Joakim Skarding, Pavel Sanda

Abstract
The OpenAIRE graph contains a large citation graph dataset, with over 200 million publications and over 2 billion citations. The current graph is available as a dump with metadata which uncompressed totals ∼ 2.5 \sim 2.5 TB. This makes it hard to process on conventional computers. To make this network more available for the community we provide a processed OpenAIRE graph which is downscaled to 32 GB, while preserving the full graph structure. Apart from this we offer the processed data in very simple format, which allows further straightforward manipulation. We also provide a python pipeline, which can be used to process the next releases of the OpenAIRE graph.

Method

The OpenAIRE graph consist of many entities and many relations. These are stored in many files in the dump, we only need the publication files (nodes) and the relation files (citations/edges) to extract the citation network. The publication files themselves contain a lot of information about publications, only some of which is relevant for most researchers. The relation files include many types of relations, for this dataset we are only interested in citations (the type ”Cites”). The following shows the generic steps we followed to extract the citation network and minimize memory footprint (the full code is available at [Github link]).

Steps

1.

Download the complete OpenAIRE graph dump
(
16
)
, including all publication and relation files.

2.

Extract relevant publication fields and flatten nested JSON structures to obtain a tabular representation.

3.

Generate new more memory efficient(
int32
) nodeIDs, and build a hashtable for translating between OpenAIRE IDs and our nodeIDs.

4.

Process relation files using PySpark
(
24
)
, retaining only relations of type
Cites
by extracting source and target identifiers. Use hashtable to replace OpenAIRE IDs

5.

Update all citation relations to reference the new identifiers.

This achieves a distilled dataset where the relations are efficiently stored using pairs of short integers.

Quality control

A set of validation scripts are run after processing to check for loss of data. The scripts check whether any entries from the original dump was lost and check for completeness of feature columns.

Output

The processing pipeline takes input of OpenAire full dump and transforms it into the files described below.

•

citations.csv
– a simple edge list of the graph (all the citations). Each row has a simple form of two connected nodeIDs of e.g.:

159486578,118392581

•

publications.csv
– all graph nodes (publications), it contains only the nodeID and, when available, the DOI. Each row has a simple form of e.g.:

14209,10.3931/e-rara-45685

•

publications_large.csv
– includes the same number of nodes as
publications.csv
, but includes additional fields, e.g. title, authors, description, etc. For a full overview of fields, see Table
3
.

•

pipeline.zip
– processing pipeline which transform full OpenAIRE dump into the dataset files above. Full details is documented in included
README.md
. The source code is also present online at

https://codeberg.org/Zmeos/OpenAIRE-citation-extraction
.

Example of reduction of a relation (citation/edge)

Our dump has the benefit of only focusing on citations, thus we do not need to indicate the type of citation. We only retain the information of the source ID and target ID. These IDs are also optimized to take up as little space as possible.
The following is an example of how an edge is represented in the OpenAIRE JSON dump:

{
"provenance": {
"provenance": "Inferred by OpenAIRE",
"trust": "0.9"
},
"relType": {
"name": "Cites",
"type": "citation"
},
"source": "doi_________::7e8d84fc096936557defb78d22cca97c",
"sourceType": "product",
"target": "dedup_wf_002::27d83ddfd6e54378d88445aa793d5cb8",
"targetType": "product",
"validated": false
}

An edge in our dump is simply:

159486578,118392581
