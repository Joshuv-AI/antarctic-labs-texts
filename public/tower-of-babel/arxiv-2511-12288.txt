Abstract
. When generating code from natural language prompts, an LLM samples programs from a probability distribution, many of which might be incorrect. Sample consensus techniques — such as majority voting or validation against generated tests or specifications — aim to identify a correct program in the sample or abstain if none is valid. However, existing methods often fail to select a correct solution when its sampling probability is low, or when the problem permits multiple valid but non-equivalent solutions. Additionally, they often fail to abstain when no correct solution is present in the sample. To overcome these limitations, we introduce semantic triangulation, which transforms a programming problem in a way that non-trivially alters its semantics while preserving an exact, verifiable mapping between solutions before and after transformation. We theoretically establish that verifying consistency across such problem transformations increases confidence that generated programs reflect accurate generalization rather than spurious statistical correlations, enabling more reliable sample consensus and abstention. On the LiveCodeBench and CodeElo benchmarks, using GPT-4o and DeepSeek-V3 models, semantic triangulation increases reliability of generated code by 21% compared to the method that selects only high-confidence solutions with the probability threshold 0.5, while being able to pinpoint correct solutions at sampling probabilities as low as 0.14. Apart from that, it is also the only approach to consistently form true consensus on tasks with multiple valid but non - equivalent solutions.

Large language models (LLMs) turn natural language specifications into executable code, but this convenience comes at a cost: the generated programs often contain bugs
(
liu2024exploring
)
or vulnerabilities
(
pearce2025asleep
)
due to LLM hallucinations (also known as confabulations). This is exacerbated by the growing trend of “vibe coding,” where developers engage in continuous prompting without thoroughly reviewing the generated code. Our work aims to enhance correctness of LLM-generated code in a fully automated, black-box setting — without human involvement or internal access to the model.

When solving a programming task, an LLM takes in a prompt with the task description and samples candidate solutions from a probability distribution conditioned on this prompt. In black-box setting, code hallucinations can be mitigated through two orthogonal strategies: (1) improve the input itself — via prompt engineering, such as CoT
(
wei2022chain
)
, or RAG
(
lewis2020retrieval
)
— thereby shifting the distribution toward more reliable solutions, and (2) select high-quality candidates and abstain when none meet the desired criteria
(
feng2024don
)
. Our work focuses on the post-generation selection-and-abstention, which offers the benefit of operating independently of prompt design.

A basic strategy to select programs from the distribution is plurality voting
(
hansen2002neural
)
, which chooses a solution whose semantics appear most frequently in the sample, grouping sampled programs into equivalence classes based on their input-output behavior
(
shi2022natural
)
. This approach suffers from two limitations. First, LLMs often repeatedly make the same mistakes
(
kim2025correlated
)
, which means that when the probability of a correct solution is low, plurality is more likely to amplify frequent errors than identify the truth
(
tumer1996error
)
. Second, programming tasks often permit multiple valid but non-equivalent solutions, which complicates consensus. Alternatives to plurality are software engineering methods such as testing and formal verification. In particular, instead of checking equivalence of samples, the consensus is established by executing sampled programs on a generated test suite
(
huang2023agentcoder
;
taherkhani2024valtest
)
or checking them against autoformalized specifications
(
endres2024can
;
misu2024towards
)
. However, when tests or specifications are produced by an LLM, they may be incorrect or incomplete, resulting in erroneous consensus.

We propose
semantic triangulation
, a novel hallucination detection framework that increases confidence in correctness of LLM-generated code by verifying whether solutions remain consistent under non-semantics-preserving problem transformations. Specifically, the original coding task
d
is transformed into a non-trivially different task
d^{\prime}
that is linked to
d
through a binary relation over solutions (hyperproperty)
\phi
. We then compare solutions to both problems; when a solution to
d^{\prime}
agrees with a solution to
d
as verified via
\phi
, it serves as its
plausibility witness
. Drawing such a plausibility witness from the model’s distribution enhances confidence that the model’s output is grounded in accurate semantic generalization rather than superficial statistical correlations.

Semantic triangulation is theoretically grounded: assuming, in line with empirical evidence
(
shani2025tokens
;
kim2025correlated
)
, that the model behaves as a “stochastic parrot”
(
bender2021dangers
)
— i.e., it lacks deep semantic understanding of the problem — and that its errors are correlated, we prove that a well-designed triangulation outperforms plurality. In our practical realization, we implemented triangulation methods based on partial inversion, answer enumeration and problem decomposition. We first automatically transform a problem by prompting an LLM, and then link the transformed to the original problem via appropriate hyperproperties. These transformed problems typically require different algorithms, thereby reducing the probability that errors in their solutions match under the hyperproperty.

We evaluated our implementation, dubbed
just-tri-it
, on LiveCodeBench
(
jain2024livecodebench
)
and CodeElo
(
quan2025codeelobenchmarkingcompetitionlevelcode
)
’s subset of inexact tasks that admit multiple non-equivalent solutions, using GPT-4o and DeepSeek-V3.
just-tri-it
produced plausibility witnesses that increased the probability of correctness by 25% over baselines, including auto-formalized Hoare-style specifications. It achieved reliable accuracy 21% higher than the high-confidence selector (probability threshold
\geq
0.5), yet correctly selected solutions with sampling probabilities as low as 0.14, enabling reliable solutions to harder tasks and consensus on inexact problems. Finally, we showed that the lack of a bijection between program and specifications classes limits auto-formalization, but is addressed by our method.

In summary, the paper makes the following contributions:

•

Semantic triangulation, a theory-grounded hallucination detection framework that enhances confidence of LLM-generated code by verifying cross-task solution consistency.

•

Practical instances of triangulation, with their design rigorously proven in Lean.

•

Evaluation on LiveCodeBench and CodeElo showing that triangulation outperforms previous consensus methods in correct selection and abstention decisions on instances with low probability of correct solutions, and when the task permits multiple non-equivalent solutions.

All code, data, and mechanized proofs are available at
http://github.com/msv-lab/just-tri-it/
.

2.
Overview

We illustrate semantic triangulation using the ancient Indian parable of the blind men and an elephant (
Figure

1a
). In the parable, multiple observers each perceive only part of the elephant and draw inconsistent conclusions — e.g., two may describe it as a “tree” while one says “elephant,” resulting in the plurality forming a false consensus. Imagine now that the elephant is flipped; two may describe it as a “wall” while one says “upside-down elephant,” again resulting in an erroneous plurality. Crucially, only answers that remain consistent across such transformations can be reliable. Analogously, semantic triangulation (
Figure

1b
) subjects a coding task to controlled transformations and compares solutions of the original and the transformed tasks; responses semantically consistent across transformations are likely grounded in deeper semantic structure, while mismatches reveal hallucinations arising from the LLM’s reliance on surface-level statistical correlations.

2.1.
Forming Sample Consensus via Plausibility Witnesses

Figure 2
.
Probabilities of sampling correct solutions from GPT

Figure

2
illustrates the reliability challenge of LLM-based code generation. It reports probabilities of sampling correct solutions from GPT-4o across tasks in the popular LiveCodeBench benchmark
(
jain2024livecodebench
)
, estimated across 100 trials. The model fails to solve most tasks correctly, and for a large fraction of solvable tasks, the probability of sampling a correct solution is below 0.5. Ideally, there must be a method that abstains on unsolvable tasks, and is able to select low-probability correct solutions on solvable tasks.

Plurality
(
hansen2002neural
)
selects the label occurring most frequently among predictions. In LLM-based code generation, this corresponds to identifying the semantic equivalence class with the highest probability mass under the model’s distribution. A related approach, majority voting
(
hansen2002neural
)
, selects an equivalence class whose probability is at least 0.5. Both are motivated by the sanity assumption that a well-trained model assigns higher probability to correct solutions. Plurality/majority voting becomes ineffective when the probability of sampling a correct solution is low. Additionally, LLMs tend to produce correlated errors — a phenomenon observed not only across samples from the same model but even between different models
(
kim2025correlated
)
. When such correlations are present, plurality consensus can amplify rather than mitigate mistakes, an effect long recognized in ensemble learning literature
(
tumer1996error
)
.

An alternative to plurality is to generate a test suite or autoformalize problem requirements into logical specifications, and then check these against generated programs
(
huang2023agentcoder
;
taherkhani2024valtest
;
endres2024can
;
misu2024towards
)
. Because the model’s output may include mutually conflicting programs, tests, and specifications, it is necessary to detect and exclude outliers using algorithms such as RANSAC
(
fischler1981random
;
chen2022codet
)
. Concretely, for each sampled program
p
, we check its agreement with another sampled artifact
q
— for example, if
p
satisfies the autoformalized specification
q
. Then, RANSAC selects the largest consistent sets of mutually agreeing artifacts. Although generated tests and specifications address limitations of plurality, such an assumption of the problem admitting only a single correct solution, they might themselves be incorrect. First, LLMs can make the same errors in tests and specifications as in the program. Second, LLMs can be less effective in directly predicting expected outputs (for tests) than in generating code
(
gao2023pal
;
bouras2025hoareprompt
)
. Third, specifications are usually written in low-resource languages, which increases hallucinations
(
li2025language
)
. Finally, studies of real-world Eiffel contracts suggest that even humans are as prone to errors in writing specifications as in implementing code
(
ciupa2011number
)
.

We recast prior approaches within a unifying perspective: they sample auxiliary artifacts
q
(such as other programs, tests, specifications, etc.) — which we refer to as the
plausibility witnesses
— and check their agreement with sampled programs
p
. These agreement checks yield matching pairs that are then used to form consensus. This leads to the following fundamental yet overlooked question:

What plausibility witnesses provide higher confidence in program correctness?

More formally, the question asks to identify the type of witnesses that would maximize the probability that the program is correct under an agreement,
\mathds{P}(p\text{ is correct w.r.t. }d\mid\mathrm{agree}(p,q)),
where
d
is a problem description, and “
\mathrm{agree}
” may denote (i) semantic equivalence if
q
is another program, (ii) test execution if
q
is a test suite, or (iii) a verification procedure if
q
is a formal specification.

2.2.
High-Confidence Plausibility Witnesses via Semantic Triangulation

Semantic triangulation is the first approach designed from first principle to answer the above question. Specifically, it applies a non-semantics-preserving transformation to the problem in order to change the surface representation or structure of the task sufficiently to decorrelate model errors, but does so in a way that maintains an exact, verifiable mapping between solutions before and after transformation. This is feasible in the programming domain, where problems have well-defined semantics and program behavior can be reasoned about with precision.

Let
D
be a space of problem descriptions, and
P
be a space of programs. We define:

Definition 2.1 (Semantic Triangulation).

A semantic triangulation
(\tau,\phi)
consists of a problem transformation
\tau:D\to D
and a predicate on pairs of programs
\phi:P\times P\to\{0,1\}
that induces a bijection between semantic equivalence classes of programs such that, for any problem description
d\in D
, it maps correct solutions for
d
to correct solutions for
\tau(d)
.

where by inducing a bijection we mean that there exists a one-to-one correspondence between equivalence classes of programs such that
\phi
holds exactly for those pairs
(p,q)
where the class of
p
is mapped to the class of
q
. Intuitively, this definition can be interpreted as follows:

•

Error decorrelation through bijection
: A bijective mapping between equivalence classes guarantees that distinct errors in solutions to the original problem are mapped to distinct errors in solutions to the transformed problem. Consequently, the probability that two independently generated incorrect programs match exactly under a non-trivial transformation is low.

•

Correctness-coupling
: The requirement that the bijection preserves correctness increases the probability of correctness under agreement via
\phi
since in well-trained models the probabilities of correct solutions are, on average, higher than that of arbitrary bugs.

We theoretically justify this definition using a mathematical model tailored to LLM hallucinations. In particular, to capture LLM’s lack of genuine understanding of the problem’s semantics, which is supported by empirical evidence
(
bender2021dangers
;
shani2025tokens
)
, we posit that for any given problem, there exists a semantically different problem that the model cannot distinguish (Assumption
3
). Furthermore, drawing on empirical findings of widespread error correlation
(
kim2025correlated
)
, we assume that the LLM produces solutions with imbalanced distributions over equivalence classes of errors (Assumption
4
). Under these assumptions, and using the rearrangement inequality
(
hardy1952inequalities
)
, we prove that an appropriately designed triangulation strictly improves upon plurality voting (Proposition
4.2
and Proposition
4.3
):

\mathds{E}_{d\sim\mathrm{Unif}(D)}\bigl[\mathds{P}(p\text{ is correct w.r.t. }d\mid\phi(p,q^{\prime}))-\mathds{P}(p\text{ is correct w.r.t. }d\mid p\equiv q)\bigr]>0,

where
p
and
q
are independently sampled solutions for a uniformly chosen problem,
q^{\prime}
is a sampled solution to the transformed problem, and
\equiv
is semantic program equivalence.

The problem is also inexact: there are multiple valid, non-equivalent solutions. As a result, existing sample consensus methods fail here, e.g., plurality selects the dominant error
p_{1}
with the probability 0.23, which contains an index update bug, instead of, e.g., a correct solution

with the probability 0.07.

Our tool,

, finds such low-probability correct solutions by transforming the problem and verifying cross-task sample consistency. In particular, it transforms

d^{\prec}

that tasks to enumerate all values of the parameter

that would result in a given output. To simplify the inversion problem,
just-tri-it
automatically decomposes it into two subproblems

and
d^{\succ}_{\mathrm{none}}
(top right in

pythonstr and
None} respectively. Moreover, since the LLM identifies that an inverse w.r.t. the parameter $t$ in case of \mintinline
pythonNone requires enumerating an infinite set, it tasks to enumerate a bounded subset of answers and mark it with a dedicated constructor

sec:implementation for details).

Then,
just-tri-it
checks consistency between solutions to these transformed problems. First, it samples programs
\{e_{i}\}
for answer enumerator problem
d^{\prec}
are triangulates them against set-valued inverse samples
\{q_{i}\}
via the hyperproperty ENUM-SINV (
). Notice that while the problems are related, their solutions employ different algorithms. It is non-trivial to make perfectly matching bugs in different algorithms. Thus, while all problems are correctly solved with low probabilities, only correct solutions match under the hyperproperty. This is guaranteed by the design of ENUM-SINV, which ensures a bijective mapping between classes of errors in both solutions. After reliable enumerators are identified, they are used to triangulate solutions
\{p_{i}\}
to the original problem using FWD-ENUM, a property that merely checks that the forward program output is contained in the enumerator output. This process results in the selection of a correct solution

and discards the dominant error

Background, Notation and Basic Assumptions

We use
\mathds{P}(\cdot)
to denote probability and
\mathds{E}[\cdot]
for expectation. Conditional probability

represents the probability of

given that
B
holds. We use

for uniform sampling. Let

be a space of problem descriptions,
P
be a space of programs. Let
m
be a code generation model, and

be a distribution of programs conditioned on the description

. We denote programs independently sampled from this distribution as
p,q,...\sim m(\,\cdot\mid d)
. The support of a distribution is the set of all programs with non-zero probability. Let
\equiv
be the (partial) semantic program equivalence relation
(
ciobacua2016language
)
,
\mathcal{P}/{\equiv}
be the set of all equivalence classes
[p_{1}]_{\equiv},[p_{2}]_{\equiv},...
. Since semantic program equivalence is a classical relation, we omit
\equiv
when denoting equivalence classes w.r.t this relation, e.g.
[p_{1}]
. Given

its representative.

The plurality method selects a representative of the most probable equivalence class. Formally, if we sample
n>2
programs
S\triangleq\{p_{1},p_{2},\dots,p_{n}\}
, that is,
p_{1},p_{2},\dots,p_{n}\sim m(\,\cdot\mid d),
then plurality will select a program
p^{\ast}\triangleq\arg\max_{p_{i}\in S}|[p_{i}]\cap S|
. This method captures the intuition that a well-trained model assigns higher probability to semantically correct solutions. Random sample consensus (RANSAC)
(
fischler1981random
)
is a classical algorithm designed to detect outliers, which was adapted to eliminate hallucinated program-test pairs in CodeT
(
chen2022codet
)
. In this context, this algorithm is applied to sets of programs
\{p_{1},...,p_{n}\}
and witnesses
\{q_{1},...,q_{n}\}
to maximize
|P_{\mathrm{a}}|\cdot|Q_{\mathrm{a}}|
where all program in
P_{\mathrm{a}}
agree with all witnesses in
Q_{\mathrm{a}}
. Importantly, plurality is a special case of RANSAC consensus, where equivalence between two programs directly corresponds to their agreement.

The modulus of an array
x
indexed by
I
is defined as
\|x\|_{\ell^{2}(I)}\triangleq\sqrt{\sum_{i\in I}x_{i}^{2}}.

Since prompts are written in natural language, they are prone to imprecision and ambiguity, often allowing conflicting interpretations
(
jia2025automated
)
. We categorize causes of this uncertainty into two groups. We say that a problem description is
ambiguous
if it admits unintended interpretations. For example, in the task “find three distinct elements of a given list that sum to zero”, the term “distinct” may refer either to distinct indices or to distinct values, and it is likely to be a fault in the description. In contrast, a problem description is
inexact
if it omits unimportant details. For example, the specification “return a positive element of a given list” allows one to choose a positive element arbitrarily, which is likely valid and even desirable. Indeed, Quan et al.
(
quan2025codeelobenchmarkingcompetitionlevelcode
)
found that even in programming contests, where descriptions are more precise than in typical user prompts, “about 30% of problems do not have unique correct outputs.” We rely on the following assumption:

Assumption 1.

All descriptions
D
are unambiguous, but some are inexact.

This relaxes assumptions of previous works. For example, the uncertainty measure by Valentin et al.
(
valentin2025estimating
)
assumes that “if two LLM-generated programs behave differently on the same input, at least one must be incorrect”, thus requiring prompts that are both unambiguous and exact.

This work focuses on generating individual functions, e.g., algorithm implementations or components of larger systems, rather than whole projects interacting with users and environment:

Assumption 2.

Expected solutions to
D
are pure, deterministic functions
p:I\rightarrow O
, where
I
is a space of program inputs, and
O
is a space of program outputs.

Definition 3.1 (Semantic Program Equivalence).

Programs
p
and
q
operating on the same domains are semantically equivalent, which is denoted as
p\equiv q
, iff
\forall i\in I.\ p(i)=q(i).

Given that (partial) program equivalence is undecidable, we estimate it by comparing programs’ outputs on LLM-generated inputs provided that the programs terminate within a timeout.

We rely on the existence (without requiring explicit knowledge) of a semantic function
\llbracket\cdot\rrbracket:\mathrm{NL}\to 2^{I\times O}
that for each problem description returns the required relation between inputs and outputs. For example,
\llbracket``\text{multiply two numbers}"\rrbracket=\{((2,2),4),((2,3),6),\cdots\}.
Inexactness is defined as

Definition 3.2 (Exactness).

A problem description

is

if and only if for any
i\in I
,
o,o^{\prime}\in O
,
(i,o)\in\llbracket d\rrbracket\wedge(i,o^{\prime})\in\llbracket d\rrbracket\Rightarrow o=o^{\prime};
Otherwise, it is
inexact

Example 3.3 (Inexact Problem Description).

\displaystyle\llbracket``\text{return}\text{ a positive element of a given set}"\rrbracket=\ \{\

\displaystyle(\{1,-1,3\},{\color[rgb]{1,0,0}1}),\ (\{1,-1,3\},{\color[rgb]{1,0,0}3}),\cdots\}.

To simplify our definitions, we assume that all inputs are valid and all outputs are reachable:

\forall i\in I\ \exists o\in O.\ (i,o)\in\llbracket d\rrbracket,\quad\forall o\in O\ \exists i\in I.\ (i,o)\in\llbracket d\rrbracket.

In practice, identifying valid inputs is undecidable;
discusses our practical mitigation.

Definition 3.4 (Program Correctness w.r.t. Problem Description).

A program
p\in P
is

w.r.t. a problem description
d\in D
iff
\forall\ i\in I.(i,p(i))\in\llbracket d\rrbracket,
which is denoted as

It is

Hoare logic
(
hoare1969axiomatic
)
is a framework for specifying expected program behavior. Its central construct, the Hoare triple
\{p\}\;c\;\{q\}
, expresses that, if the program
c
starts in a state satisfying the precondition
p
, then — assuming termination — it will end in a state satisfying the postcondition
q
. Pre- and postconditions are predicates over program states — mappings from variables to values — typically expressed in first-order logic
(
filliatre2013why3
)
. Since we assume that programs are pure functions and all inputs are valid, such specifications reduce to
\{\mathrm{True}\}\;o=f(i)\;\{q(i,o)\}
, determined by postconditions
q
.

4.
Theoretical Basis of Triangulation

This section formally justifies the design of semantic triangulation (
Definition

2.1
), along with providing a conceptual account of the underlying improvement. Plurality, test generation, and autoformalization can be unified under the concept of plausibility witnesses. Let
p\sim m(\,\cdot\mid d)
be a program generated for a description
d
. Suppose there exists a procedure for sampling artifacts
q
and a criterion “
\mathrm{agree}
” for assessing their agreement with
p
. We call such
q
plausibility witnesses. Based on agreeing pairs
(p,q)
, algorithms such as RANSAC form consensus over the entire sample, and plurality voting is a special case of this algorithm. Thus, a fundamental question arises:

Definition 4.1 (Confidence-Enhancing Plausibility Witness Problem).

For a sampled program
p
, what type of plausibility witness
q
and the corresponding agreement criterion provide higher
\mathds{P}(p\vdash\llbracket d\rrbracket\mid\mathrm{agree}(p,q)),
the probability that the program is correct under an agreement?

4.1.
Semantic Triangulation Provably Enhances Confidence Under Agreement

We prove that triangulation yields higher-confidence witnesses than plurality in a mathematical model of LLM hallucinations, which rigorously explains the mechanism of mitigating hallucinations, informing our practical implementation. Without loss of generality, we use several simplifications:

•

to avoid modeling linguistic variations, all descriptions in
D
are semantically distinct;

•

to facilitate equivalence checking, all programs
P
operate on exactly the same domains;

•

there is a finite number of equivalence classes
[p_{1}],[p_{2}],\cdots,[p_{n}]
in
P/\equiv
;

•

the existence of
\phi
does not require a closed-form representation.

Plurality voting operates under the assumption that each problem has a single solution. Indeed, if there are multiple correct solutions to a problem, plurality may prefer high-probability errors even if the total probability mass of all correct solutions is higher. Since our theoretical justification involves a comparison with plurality, in this section we assume that each
d
has exactly one solution. In the subsequent section, we show how triangulation alleviates this limitation in practice.

Intuitively, triangulation yields higher-confidence witnesses than plurality by mitigating correlated errors. This arises because LLMs, as “stochastic parrots,” lack precise semantic understanding and therefore fail to preserve errors under non-trivial transformations. To formalize this intuition, inspired by work on spurious correlations
(
ye2024spurious
)
, we assume that LLMs rely on shallow features preventing them from capturing subtle aspects of problem semantics. At the same time, when a model lacks the ability to discriminate between any problem instances, confidence improvement becomes infeasible. The following assumption reflects these intuitions:

Assumption 3 (Stochastic Parrots).

Let
m
be a model that defines a distribution of programs conditioned on problem descriptions
m(p\mid d)

m

d

To formalize the notion of correlated errors, we say that all programs in the same incorrect equivalence class have the same errors, while different classes have different errors. Then, correlated errors across samples for a given problem effectively mean that some equivalence classes are more likely than others. For simplicity, assume that all error classes have different probabilities:

5.
Practical Design of Triangulation

Section

4
presents the theoretical foundations of semantic triangulation, explaining its underlying principles and providing justification for its design. However, the problem transformation method used in the proofs is not directly applicable in practice, as it relies on the exact knowledge of the hallucination patterns of the model in use. Nevertheless, our practical design of transformations is based on the insights of our theoretical analysis (
5
) that require that the transformed problems are not significantly harder to solve, while it is hard to exactly match errors in their implementations. In particular, we transform a problem into one that requires a different algorithm while still being “natural” for an LLM to solve. Our transformations involve algorithm inversion, answer enumeration and problem decomposition. Specifically, we introduce three inversion-based methods consisting of problem transformations and corresponding hyperproperties: FWD-INV, FWD-SINV, and ENUM-SINV, a meta triangulation method STREAM for stateless stream-processing programs, and data-structure decomposition strategies to simplify program inversion. All transformations are performed automatically by prompting an LLM (see, e.g.,
Figure

5
).

To specify the intended effect of transformations, we use an imaginary procedure
\llparenthesis\ \cdot\ \rrparenthesis
that, given a binary relation between inputs and outputs, converts it into natural language text.

Definition 5.1 (Inverse Problem).

Let
d
be a problem such that
\llbracket d\rrbracket\subset I\times O
. The corresponding inverse problem is
d^{-1}\triangleq\llparenthesis\ \{(o,i)\mid(i,o)\in\llbracket d\rrbracket\}\ \rrparenthesis.

Proposition 5.2 (Full FWD-INV).

Let
\tau
transform each problem
d
into
d^{-1}
,
p
is a sample for
d
,
q
is for
d^{-1}
, and
\phi\triangleq q\circ p\equiv\mathrm{id_{I}}\wedge\forall o,o^{\prime}\in O.\ o\neq o^{\prime}\Rightarrow q(o)\neq q(o^{\prime})
. Then,
(\tau,\phi)
is semantic triangulation. We refer to this triangulation method as Full FWD-INV.

Proof.

Intuitively obvious; mechanized in Lean for completeness.
∎

Our hypothesis is that inversion-based transformation exploits dissociative hallucination patterns, because forward and inverse problems often require different algorithms. However, fully inverting an algorithm is often infeasible. Consider, for example, the problem “given a graph and two of its nodes, compute the length of the shortest path between them”. A full inversion would require producing any pair consisting of a graph and two nodes whose shortest-path distance matches a specified value — such outputs would likely fail to align with the behavior of the original forward algorithm, or else require exhaustively enumerating all such pairs, which is infeasible.

To alleviate this problem, we apply a more natural and practical partial inversion, that is inverting an algorithm w.r.t. a single parameter. For instance, “given a graph and a target distance, enumerate all pairs of nodes whose shortest-path length is exactly that distance”. This formulation is easier for an LLM to handle, while still satisfying the properties required for semantic triangulation:

Definition 5.3 (Partial Inverse Problem).

Let
d
be a problem such that
\llbracket d\rrbracket\subset(I_{1}\times I_{2})\times O
. The corresponding partial inverse problem w.r.t. the first argument is

d^{-1}_{1}\triangleq\llparenthesis\ \{((o,i_{2}),i_{1})\mid((i_{1},i_{2}),o)\in\llbracket d\rrbracket\}\ \rrparenthesis.

The inversion with respect to other arguments is defined accordingly. In practice, we prompt an LLM to decide which argument to use for inverting the problem.

Proposition 5.4 (Partial FWD-INV).

Let
\tau
transform each problem
d
into
d^{-1}_{1}
, and

\phi\triangleq\forall(i_{1},i_{2})\in I.\ q(p(i_{1},i_{2}),i_{2})=i_{1}\wedge\ \forall(o,i_{2}),(o^{\prime},\_)\in O^{\prime}.\ o\neq o^{\prime}\Rightarrow q(o,i_{2})\neq q(o^{\prime},i_{2}),

where
p
is a sample for
d
,
q
is for
d^{-1}_{1}
and
O^{\prime}
refers to all inputs to
q
. Then,
(\tau,\phi)
is semantic triangulation. We refer to this triangulation method as Partial FWD-INV.

Proof.

Intuitively obvious; mechanized in Lean for completeness.
∎

Although the problem inversion defined above is likely to change the solution algorithms, while keeping the problem tractable for an LLM, its key limitation is that for the hyperproperty to faithfully hold, i.e., hold on pairs of correct solution-witness pairs, the problem description must permit bijective functions as valid solutions. This, however, often does not hold in practice. For example, for the problem “compute the square of a given number”, a correct solution maps both
-i
and
i
to
i^{2}
, implying that only incorrect forward and inverse implementations will match.

To alleviate this challenge, we employ set-valued inverses that return the exhaustive list of values for a given input argument that would result in a given output:

Definition 5.5 (Set-valued Inverse Problem).

Let
d
be a problem such that
\llbracket d\rrbracket\subset I\times O
. The corresponding set-valued inverse problem is

d^{\succ}\triangleq\llparenthesis\ \bigl\{(o,\{i\mid(i,o)\in\llbracket d\rrbracket\})\mid(\_,o)\in\llbracket d\rrbracket\bigr\}\ \rrparenthesis.

Proposition 5.6 (Full FWD-SINV).

Let
\tau
transform each problem
d
into
d^{\succ}
, and

\phi\triangleq\forall i\in I.\ \underbrace{i\in q(p(i))}_{L_{1}}\wedge\underbrace{\forall i^{\prime}\in q(p(i)).\ p(i^{\prime})=p(i)}_{L_{2}}\wedge\ \underbrace{\forall o,o^{\prime}\in O.\ o\neq o^{\prime}\Rightarrow q(o)\cap q(o^{\prime})=\emptyset}_{L_{3}},

where
p
is a sample for
d
and
q
is for
d^{\succ}
. Then,
(\tau,\phi)
is semantic triangulation. We refer to this triangulation method as Full FWD-SINV.

Proof.

Intuitively, a correctness-coupling bijective mapping via
\phi
is achieved through the interplay of
L_{1}

L_{2}
, and

L_{1}
ensures that if
p

never misses a value in its output on the range of
p
, and if
q
is correct on the range of
p
, then
p
never returns an incorrect value. In turn,

complements
L_{1}
by ensuring that if
p
is correct, then
q
never returns an incorrect value on the range of
p

L_{3}
ensures that
q
matches the behaviour of a single forward function. The proof is mechanized in Lean.
∎
