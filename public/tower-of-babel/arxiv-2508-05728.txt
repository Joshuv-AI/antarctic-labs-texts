CLAPP: The CLASS LLM Agent for Pair Programming
S. Casas, C. Fidler, B. Bolliet, F. Villaescusa-Navarro, J. Lesgourgues

Abstract
We introduce CLAPP ( CLASS LLM Agent for Pair Programming), an interactive AI assistant designed to support researchers working with the Einstein-Boltzmann solver CLASS . CLAPP leverages large language models (LLMs) and domain-specific retrieval to provide conversational coding support for CLASS —answering questions, generating code, debugging errors, and producing plots. Its architecture combines multi-agent LLM orchestration, semantic search across CLASS documentation, and a live Python execution environment. Deployed as a user-friendly web application, CLAPP lowers the entry barrier for scientists unfamiliar with AI tools and enables more productive human-AI collaboration in computational and numerical cosmology. The app is available at https://classclapp.streamlit.app/

CLAPP
9

9

is an AI-based pair-programming assistant tailored specifically for the
CLASS

CLASS
and its Python wrapper
classy

CLAPP

In this article, we present the design and functionality of
CLAPP
, and explain how it integrates emerging AI techniques into the computational workflows common in cosmology. We highlight three key components of its architecture: (1) multi-agent LLM orchestration, (2) retrieval-augmented generation (RAG) over a vectorized
CLASS
knowledge base, and (3) live code execution and plotting through a secure Python environment. Our goal is both pedagogical and practical: to demonstrate how LLM-based systems can be applied to real-world scientific codebases, enabling new modes of human-AI collaboration.

II
CLAPP Architecture and Features

CLAPP
is built as a multi-component system that orchestrates language model agents, a knowledge database, and the
CLASS
code execution environment. At a high level, a user interacts with
CLAPP
through a chat interface, asking questions or requesting assistance with coding tasks related to
CLASS
. Under the hood,
CLAPP
’s architecture (illustrated in Fig. 1) ensures that the AI’s responses are accurate, relevant, and actionable by combining several advanced components. We outline the main features here, corresponding to the three technical pillars of the system.

Figure 1:
Schematic overview of the
CLAPP
system architecture. The user interacts via a chat UI, formulating queries in natural language. The LLM agents (
CLASS
Agent, Review Agent, Formatting Agent) collaborate via a Group Chat to generate and refine answers using retrieved documentation. In Fast Mode the output of the
CLASS
agent is directly handed back to the user, as a live stream. Executable code is optionally passed to a sandbox with an Executor Agent that can call
classy
functions and a Debugger Agent that can autocorrect the code based on the error messages captured by the Executor. Results (including plots) are returned to the user. The user does not see the internal workings of
CLAPP
and only views the main results highlighted here in purple boxes.

II.1
Multi-Agent LLM Orchestration

Rather than relying on a single monolithic AI agent,
CLAPP
employs a team of specialized language models that collaborate to generate high-quality responses. This architecture is built using the
AG2
10
10

10

https://ag2.ai

(
Wu et al. 2023
;
Wang et al. 2024
)
multi-agent framework, which enables coordinated interaction among multiple LLMs within a shared conversational context.

In
Deep Thought Mode
, a specialised
CLASS
agent first drafts a response to the user’s query. A
review agent
then evaluates this draft, scoring it and providing feedback on any logical, stylistic, or technical issues. Subsequently, the response is updated based on the feedback received. This review–improvement loop continues until the response meets a predefined quality threshold or a maximum number of iterations is reached. Then the final, validated response is processed by a formatting agent and returned to the user.

Each agent is powered by either an OpenAI or Gemini model and is guided by a role-specific prompt—for example, the reviewer is instructed to be especially critical and precise. This division of labor effectively simulates an automated peer-review process, allowing
CLAPP
to catch errors and refine explanations before delivering them to the user.

Alternatively, users can opt for
Fast Mode
, which returns the initial draft immediately without any internal review. While this mode may be less accurate, it supports real-time streaming and is well-suited for rapid, iterative workflows.

II.2
Retrieval-Augmented Generation with
CLASS
Knowledge

A key feature of
CLAPP
is its ability to ground responses in the official
CLASS
documentation and codebase of the latest available
CLASS
version. To achieve this,
CLAPP
implements a Retrieval-Augmented Generation (RAG) pipeline that integrates domain-specific knowledge directly into the prompting process.

All relevant materials—including the
CLASS
user manual, parameter descriptions, example scripts, and documentation for the Python wrapper
classy
—are preprocessed and stored in a local vector database. When a user submits a query,
CLAPP
does not rely solely on the LLM’s internal knowledge (which may be incomplete or outdated). Instead, it performs a semantic search over the vectorized
CLASS
documentation to retrieve the most relevant context. This is done by embedding the user’s question into a high-dimensional vector space and matching it against precomputed embeddings of the documentation using a FAISS vector store with HuggingFace embeddings.
In the current version, we employ the embedding model
all-MiniLM-L6-v2
with a chunk size of 1000 and overlapp of 200 tokens.

The four top-matching snippets are then injected into the LLM prompt, allowing
CLAPP
to quote or paraphrase authoritative content directly from the
CLASS
materials. This approach significantly reduces hallucinations and ensures that responses are consistent with the actual behaviour and structure of the
CLASS
codebase.

For example, when asked “What does the parameter
omega_b
do in
CLASS
?”,
CLAPP
retrieves the relevant section from the manual and accurately explains that it represents the physical baryon density—grounding the answer in the original documentation. The same mechanism applies to code generation tasks, where retrieved code snippets guide the LLM in producing correct API calls or configuration options.

The knowledge base is also modular and updateable: new content (e.g., additions to the
class-data/
directory) can be indexed and incorporated without retraining. In this way,
CLAPP
combines the generative capabilities of large language models with the reliability of curated scientific resources, producing answers that are both informative and trustworthy for cosmology researchers.

II.3
Agent–Human Chat

CLAPP
is designed as an interactive chat interface between the user and the
CLAPP
AI. Internally,
CLAPP
employs a team of specialized AI agents; however, this complexity is abstracted away in the user interface, which displays only finalized, formatted responses while omitting the internal agent-to-agent dialogue.

To maintain continuity across interactions, we aggregate the outputs of both the main AI agent and the user into a conversational memory using the
LangChain
framework
11
11

11

https://www.langchain.com

LangChain 2024
. This enables seamless, context-aware dialogue by preserving the history of the exchange.

In
Fast Mode
,
CLAPP
additionally supports real-time message streaming, also powered by
LangChain
, to enhance responsiveness.

This design allows users to engage in an iterative workflow with the AI—akin to pair programming with an expert collaborator who remembers previous steps and adapts accordingly.

II.4
Code Execution and Plotting

What further sets
CLAPP
apart is its integration with an actual runtime environment for
CLASS
.
CLAPP
not only talks about code – it can run code.
Through the use of an
"Install CLASS"
button, the app downloads the full
CLASS
code, compiles it and installs its
Python
wrapper
classy
in the current
Python
environment. The user can check the installation and a plot is produced to verify that the installation was successful (see
appendix

A
for details).
When the app detects that
Python
code was generated, a
"Run Last Code Block"
button will be activated which can be pressed to execute the
classy
code. This behavior can be equally obtained by typying
"execute!"
or
"plot!"
in the agent chat.
If the code produces a plot,
CLAPP
captures the image and displays it in the chat.
If the code contains errors, the error messages are captured and a sequential chat is started where the executor and debugger agent interact with each other up to three times, to correct mistakes or bugs in the code, see lower part of
fig.

1
. The error message is automatically analyzed by a debugging agent, which provides a corrected version of the code – this might involve fixing a typo, adjusting a function call, or reminding the user to install missing dependencies. This error-recovery loop continues until a working solution is found or a clear explanation of the failure is provided.
CLAPP
essentially serves as a virtual “pair programmer,” catching mistakes and providing fixes in real-time.
The ability to generate plots on the fly is particularly useful for scientific exploration: a researcher can ask for “a plot of the linear matter power spectrum for a given set of parameters,” and
CLAPP
will produce the code, execute it, and display the plot – all within the chat window. This tight integration of documentation, code generation, and execution shortens the cycle of experimentation dramatically, letting users focus on understanding results rather than wrestling with software syntax.

Key Concepts

Matter Power Spectrum, P(k):
This is the Fourier transform of the matter two-point correlation function. It quantifies the amount of structure (density fluctuations) at a given comoving scale, represented by the wavenumber k. Large k corresponds to small scales, and small k corresponds to large scales.

Massive Neutrinos (ncdm):
In CLASS, non-cold dark matter (ncdm) components, like massive neutrinos, are treated separately from cold dark matter (cdm). Unlike CDM, massive neutrinos have significant thermal velocities in the early universe.
Neutrino Free-Streaming: Due to their high thermal velocities, massive neutrinos can travel large distances, effectively ”streaming” out of small gravitational potential wells. This erases density perturbations on scales smaller than their free-streaming length, thus slowing down the overall growth of structure.

Cosmological Parameters:
To isolate the effect of neutrino mass, we will compare two models. The baseline model will have only massless neutrinos (N_ncdm=0). The second model will have a massive neutrino component (N_ncdm=1). We will keep the total matter density parameter, Omega_m h2̂, constant between the two models. This is a standard approach that ensures the late-time expansion history is the same, allowing for a direct comparison of structure growth. We achieve this by reducing the cold dark matter density (omega_cdm) to compensate for the mass added by the neutrinos (omega_ncdm).

Define a Massive Neutrino Model:
We will then create a second model with one massive neutrino species with a total mass M_nu = 0.1 eV. To keep the total matter density (omega_m = omega_cdm + omega_b + omega_ncdm) constant, we will calculate the energy density of the massive neutrinos (omega_ncdm) and subtract it from the omega_cdm of the baseline model.

Compute Power Spectra:

Calculate the Suppression Ratio:
We will calculate the ratio of the massive neutrino P(k) to the massless neutrino P(k). This ratio will be close to 1 on large scales (small k) and will drop below 1 on small scales (large k), clearly showing the suppression.
