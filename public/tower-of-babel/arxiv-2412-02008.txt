Stably computable relations and predicates
James Aspnes

Abstract
A population protocol stably computes a relation R ⁡ ( x , y ) R(x,y) if its output always stabilizes and R ⁡ ( x , y ) R(x,y) holds if and only if y y is a possible output for input x x . Alternatively, a population protocol computes a predicate R ⁡ ( ⟨ x , y ⟩ ) R(\left\langle{x,y}\right\rangle) on pairs ⟨ x , y ⟩ \left\langle{x,y}\right\rangle if its output stabilizes on the truth value of the predicate when given ⟨ x , y ⟩ \left\langle{x,y}\right\rangle as input. We consider how stably computing R ⁡ ( x , y ) R(x,y) and R ⁡ ( ⟨ x , y ⟩ ) R(\left\langle{x,y}\right\rangle) relate to each other. We show that for population protocols running on a complete interaction graph with n ​ ≥ ​ 2 n≥2 , if R ⁡ ( ⟨ x , y ⟩ ) R(\left\langle{x,y}\right\rangle) is a stably computable predicate such that R ⁡ ( x , y ) R(x,y) holds for at least one y y for each x x , then R ⁡ ( x , y ) R(x,y) is a stably computable relation. In contrast, the converse is not necessarily true unless R ⁡ ( x , y ) R(x,y) holds for exactly one y y for each x x .

P
be a protocol that stably computes
R(x,y)
. Since
R
is
single-valued, the output of
P
on input
x
always converges to
the same value
y
. To stably compute
R(\left\langle{x,y^{\prime}}\right\rangle)
, construct
a protocol that uses
P
to compute the unique
y
such that

R(x,y)
holds, then make this output the input to a
test for
y=y^{\prime}
using the stabilizing-inputs construction
of
[
AAC+05
]
.
∎

This construction only works for single-valued relations. If some
x

has distinct
y_{1}≠y_{2}
with
R(x,y_{1})
and
R(x,y_{2})
, then if the
embedded computation stably outputs
y_{1}
, the protocol will fail to recognize

R(\left\langle{x,y_{2}}\right\rangle)
. From
Corollary
3.3
we know that
there can be no general method to overcome this problem, although for
specific multiple-valued
R(x,y)
it may be that
R(x,y)
is
stably computed by some specialized protocol.

5
Handling small cases

The assumption that
n
is sufficiently large can be removed subject
to a small technical condition on executions involving only one
agent.
Because this construction may be useful in other
contexts, we state it as a generic lemma:

Lemma 5.1
.

Let
R(x,y)
be a relation that is stably computable for
n≥n_{0}

and single-valued for
n=1
.
Then
R(x,y)
is stably computable for all
n
.

Proof.

Let
P
be a protocol that stable computes
R(x,y)
for
n≥n_{0}
.
We will build a wrapper protocol that stably computes
R(x,y)
for

n<n_{0}
and switches its output to the output of
P
for larger

n
.

The wrapper protocol works by assigning each agent a value

rank
in the range
0
through
n_{0}
, using a variation on the
self-stabilizing leader election protocol of
Cai
et al.

[
CIW12
]
.
2
2

2

The name of the
rank
value
follows the use of this protocol by
Burman
et al.

[
BCC+21
]
in the context of
the more general problem of assigning agents unique ranks.

The
rank
protocol starts all processes with
rank

0
and
consists of a single rule
k,k\textrightarrow k,\min(k+1,n_{0})
.
This eventually assigns each process a stable rank, which will be
a unique value in the range

0\dots n-1
when
n<n_{0}
. When
n≥n_{0}
, at least one process will
be assigned
n_{0}
.

Nondeterminism is provided by an
index
variable stored at the
(eventually unique) agent with
rank
value
0
, which is
eventually locked by setting a
frozen
bit that is initially
0

for all agents. Let
m
be the number of distinct possible outputs

y
for populations of size less than
n_{0}
. Each time an agent
with
\textnormal{{rank}}=0
and
\textnormal{{frozen}}=0
is an initiator, it increments

index
mod
m
. If an agent with
\textnormal{{rank}}=0
is a responder, it
sets
\textnormal{{frozen}}=1
. This ensures that
index
is eventually
stable while still allowing
index
to take on all possible
values in the range
0\dots m-1
provided
n≥2
.

Finally, each agent records in an array location
\textnormal{{data}}[r]
,
initially
⊥
, the
most recent
index
and input it has observed in any agent with

\textnormal{{rank}}=r
. Since inputs are fixed and
rank
and
index

eventually stabilize for all agents, this causes all agents to
eventually obtain identical
data
arrays when
n<n_{0}
. When

n≥n_{0}
,
\textnormal{{data}}[n_{0}]
does not necessarily get the same value at
all agents, but it does eventually get a non-
⊥
value at all
agents.

Each step of the wrapper protocol is carried out in parallel with
a step of protocol
P
. No interaction occurs between these
protocols except in the output function
O
.

The
data
array and the output of
P
are used as arguments to

O
. When
\textnormal{{data}}[n_{0}]=⊥
, each agent can (a) compute
n
based
on the largest non-
⊥
entry in
data
, (b) compute the input
x

to the protocol from the inputs stored in
data
, and (c)
observe the same
\textnormal{{data}}[0].\textnormal{{index}}
value as the other agents.
Let
S=\left\{{y}\;\middle|\;{R(x,y)}\right\}
. The agent with rank
r
selects the
k
-th
element
y
of
S
where
k=\textnormal{{data}}[0].\textnormal{{index}}\bmod\lvert S\rvert
, then outputs
y_{r}
; in this way the agents collectively
output the
k
-th value
y∈S
. When
\textnormal{{data}}[n_{0}]≠⊥
, the agent
outputs whatever its output is in the embedded
P
computation.

We now argue that this combined protocol stably computes
R(x,y)
.
For
n≥n_{0}
, this follows from the fact that the combined protocol
stabilizes on the output of
P
, which stably computes
R(x,y)

for
n≥n_{0}
. For
1<n<n_{0}
, with input
x
, every possible
output
y
satisfies
R(x,y)
, and all such
y
can be obtained by
an appropriate setting of the common value
\textnormal{{data}}[0].\textnormal{{index}}
.
The remaining case
n=1
is covered by the assumption that

R(x,y)
is single-valued when
n=1
; the unique agent never
updates its state and outputs the unique
y
consistent with its
input
x
.
∎

The technical requirement that
R(x,y)
is single-valued when
n=1
is
necessary because a population protocol with only one agent cannot
take any steps, making its output a deterministic function of its input. An
alternative might be to insist that any population protocol have at
least two agents, but regrettably this very natural assumption does
not appear in the original definition of the model by
Angluin
et al.

[
AAD+06
]
.

6
Conclusions

We have considered the connection between relations

R(x,y)
where
x
is an input to a population protocol and
y
a
possible stable output, and their corresponding predicates

R(\left\langle{x,y}\right\rangle)
, where both
x
and
y
are provided as inputs.
We have shown that, for population protocols
running on a complete interaction graph with
n≥2
,
total stably computable predicates always give stably computable
relations, but that the converse is not necessarily true unless
R
is
single-valued.

The proof of some of these results depends on the identity between
stably computable predicates on a complete interaction graph and semilinear
predicates. A natural question is whether these results generalize to
other classes of interaction graphs for which
this property does not hold. Results based on the nondeterministic
freezing technique used in
Theorem
2.5

and
Theorem
3.1

seem like good candidates for generalization, but it is not
immediately obvious how to adapt the current handling of
nondeterminism in these constructions to
more general graphs. We
leave exploration of this question to future work.
