Abstract
. We describe Elevator , a unifying polymorphic foundation for metaprogramming with memory management based on adjoint modalities. In this setting, we distinguish between multiple memory regions using modes where each mode has a specific set of structural properties. This allows us not only to capture linear (i.e. garbage-free) memory regions and (ordinary) intuitionistic (i.e. garbage-collected or persistent) memory regions, but also to capture accessibility between the memory regions using a preorder between modes. This preorder gives us the power to describe monadic and comonadic programming. As a consequence, it extends the existing logical view of metaprogramming in two directions: first, it ensures that code generation can be done efficiently by controlling memory accesses; second, it allows us to provide resource guarantees about the generated code (i.e. code that is for example garbage-free). We present the static and dynamic semantics of Elevator . In particular, we prove the substructurality of variable references and type safety of the language. We also establish mode safety, which guarantees that the evaluation of a term does not access a value in an inaccessible memory.



An Adjoint Analysis of Metaprogramming

1.
Introduction

Metaprogramming is a commonly used technique for generating or
manipulating a program within another program. This allows programmers
to automate error-prone or repetitive tasks and exploit
domain-specific knowledge to optimize the generated code.
Unfortunately, writing safe metaprograms remains very challenging and
is sometimes frustrating as, traditionally, errors in the generated code
are only detected when running it but not at the time when the code is
generated.

The state-of-the-art in most existing languages – from typed
programming languages such as Haskell
[
Sheard:Haskell02
]
to
dependently typed languages such as Coq
[
Anand:ITP18
]
and
Agda
[
vanderWalt:IFL12
]
– is that the generated code is simply
syntax and lacks many guarantees that we would expect: it may contain
dangling free variables and it may be ill-typed. Even in languages
such as MetaML
[
Taha:TCS00
;
Taha:POPL03
]
or more recently
Scala
[
Parreaux:SPLASH17
;
Parreaux:POPL18
]
and
Typed Template Haskell
[
Xie:POPL22
]
, which support the
generation of typed code, we lack guarantees about resource and memory
usage which often prevents compilers from exploiting this information
to generate efficient code. The generation of polymorphic code also
remains challenging despite recent work by
Xie:POPL22
and
Jang:POPL22
.
How can we improve this state-of-the-art and provide a uniform logical
foundation for type-safe, polymorphic, resource-aware metaprogramming?

Recently, the question of how to combine multiple logics with different
structural properties including linear, affine, strict, and
(ordinary) intuitionistic logics has been tackled through graded or
quantitative type systems (see
[
McBride16
;
Atkey:LICS18
;
Moon:ESOP21
;
Choudhury:POPL21
;
Wood22esop
;
Abel:ICFP23
]
). The
essential idea is to track and reason explicitly about the usage of
assumptions through grades. However, they do not support
metaprogramming. In particular, there is no distinction between code
(which simply describes syntax) and programs.

We pursue here an alternative based
on adjoint logic
[
Benton:CSL94
;
Reed09
;
Pruiksma:JLAMP21
;
Pruiksma24phd
;
Jang:FSCD24
]
.
In this adjoint setting, we distinguish between multiple logics using

mode
s where each mode has a specific set of structural
properties. For example, to model linear logic, we force every
resource in a mode to be used exactly once (that is, the mode
admits neither weakening nor contraction), thus ensuring
freedom from garbage. To model strictness, we specify a
mode that does not admit weakening. In addition, we allow a preorder
between modes
m\geq k
that must be compatible with the structural
properties of
m
and
k
, in the sense that
m
should at least allow
the structural rules allowed in
k
. This allows us, among other aspects, to model
intuitionistic S4
[
Pfenning01mscs
]
and lax logic
[
Benton:JFP98
]
,
representing both comonadic and monadic programming.
To model the distinction between code that is being generated and the
program generator, we can use two modes: mode
{\mathchoice{\mathsf{C}}{\mathsf{C}}{\scriptscriptstyle\mathsf{C}}{\scriptscriptstyle\mathsf{C}}}

describes a suspended program that is eventually executable
at mode
{\mathchoice{\mathsf{P}}{\mathsf{P}}{\scriptscriptstyle\mathsf{P}}{\scriptscriptstyle\mathsf{P}}}
for programs where
{\mathchoice{\mathsf{C}}{\mathsf{C}}{\scriptscriptstyle\mathsf{C}}{\scriptscriptstyle\mathsf{C}}}\geq{\mathchoice{\mathsf{P}}{\mathsf{P}}{\scriptscriptstyle\mathsf{P}}{\scriptscriptstyle\mathsf{P}}}
.
The combination of adjoint modalities and a general mode structure
allows us to write linear comonadic programs and hence guarantees that the
generated code is garbage-free.

In this paper, we prsent a new foundation called
Elevator
for polymorphic
metaprogramming with memory management based on adjoint logic. It extends
prior work by
Jang:FSCD24
in the following three directions:

1. Contextualizing Adjoint Logic

In

, modes refer to different regions in memory,
and the accessibility between regions is described using a preorder
of modes. For instance,

As a consequence, the accessibility relation is easily checkable

we move between regions using adjoint modalities

First, we interpret the down-shift modality

in

This fine-grained distinction between the template and the pointer to it

It is this fine-grained distinction that gives

accessed when in memory.
Moreover, as modes also allow us to describe a range of

we can express even stronger guarantees: first, we can
ensure that the suspended program is garbage-free; second, it also
allows us to ensure that the program generation itself is garbage-free.
Hence,

provides a uniform metaprogramming language to
express and statically verify a range of type and memory guarantees.

2. An Operational Semantics for Adjoint Modalities Suitable for Metaprogramming

We define a suitable small-step operational semantics for
Elevator
which is
compatible with metaprogramming. The key idea for this operational semantics is
highlighted in the following principle:

The evaluation of a term should not know anything about
a term in an inaccessible memory other than its syntactic structure.

This gives a different semantics from the one given in
Jang:FSCD24

which treats a template as a black box. Since a template is an
object with a syntactic structure, we can keep the syntactic equality of
templates regardless of the construction order. For instance, whether we splice

In fact, this property is also

[

;

]
.
This is achieved by treating splicing eagerly in our operational
semantics even in inaccessible regions. Hence, our system
conservatively extends prior metaprogramming foundations based on S4 with fine-grained
memory control and access guarantees in contrast to

.

3. Adjoint Modalities and System-F style Polymorphism

To obtain a core language for practical metaprogramming, we add
System-F style polymorphism to
Elevator
. This provides on the one
hand a logical foundation and alternative for combining linearity with
polymorphism as in, for example
Bernardy:POPL18
, but on the
other hand, supports polymorphic code generation as in
Jang:POPL22
.
To include System-F style polymorphism, we introduce the up-shift modality
for kinds and the concept of
type templates
, which describe a
syntactic form of a type that can be used across modes.
This concept of type templates has a significant impact on
how we define the syntax of types and operations such as
substitution. First of all, splicing a type template into another
introduces a type-level redex.
To avoid this kind of type-level computation and keeping syntactic
equalities between identical types, we define the syntax of types only for
normal types and define substitution on types as hereditary
substitution
[
Watkins02tr
;
Nanevski:TOCL08
]
, which reduces all
type-level redices occuring during the substitution. An orthogonal problem
arising due to type variables is how structural rules apply to type
variables. We take a similar approach
to
Atkey:LICS18
for type variables, i.e. they persist regardless
of their modes. This approach is sensible because the type-checking
and type/kind construction are compile-time steps rather than runtime
computation. This approach is also convenient in terms of programming,
as the type of
id

:

(\
alpha

:

Type
)

\rightarrow

\
alpha

\multimap

\
alpha

where the type variable
\alpha

linear mode without any overhead.

On the theoretical side, we prove type safety for

Elevator
. Moreover,
we prove the substructurality of variable references
and prove mode safety, which guarantees that the evaluation of a term
does not access a value in an inaccessible memory.
On the practical side, we discuss
as an example the
In-Place Array Update
. Here we update each
element of an array using a function
f
that transforms an element of
type
\alpha
to an element of type
\beta

utilize our mode structure to update the array in-place and how to
generate polymorphic, garbage-free code that is parametric in

and polymorphic in
\alpha
and
\beta
.
We have also implemented and checked this example with our prototype
environment for
Elevator
.
In conclusion, our work lays the ground for a practical foundation for
metaprogramming with memory regions that extends System F with
adjoint modalities.

3.
Elevator
: Polymorphic Metaprogramming Using Adjoint Modalities

3.1.
Mode Specification

Elevator
is a system parametrized by a mode specification.
A mode specification
\mathcal{M}
is a preordered set of modes with a
signature
operation

\mathcal{S}:\mathcal{M}\to\mathcal{P}(\{\mathtt{C},\mathtt{W}\})
where

\mathcal{P}(S)
means the powerset of
S
. This signature operation tells us what
structural rules (
\mathtt{C}
for contraction and
\mathtt{W}
for weakening) are allowed
in each mode. The signature operation should satisfy the following condition:

m\geq k\text{ then }\mathcal{S}({m})\supseteq\mathcal{S}({k})

This condition protects us from having a wrong mode specification, for example,
where one can use linear memory more than once via unrestricted memory region
accessing it.

For the following sections, we assume that there is a global fixed mode specification.
However, as long as the valid mode specification is provided, the system and its
metaproperties work as is.

3.2.
Syntax

Elevator
extends the polymorphic lambda-calculus with storing and
loading terms into a memory region (written as
{\mathsf{store}}\ (e)
and

{\mathsf{load}}\ (x)=e\ {\mathsf{in}}\ f
) and with suspending terms and resuming their
evaluation. We write
\ulcorner{}\hat{\Psi}\ .\ e\urcorner
for suspending
the term
e
with the free variables in
\hat{\Psi}
. We simply use an

erased context

\hat{\Psi}
, which is a list of variable names,
as we do not need to track type/kind information there.
To resume the evaluation of a suspended term (template) we use

\llcorner{}e\lrcorner@\sigma
. Here the term
e
evaluates to some
template of
e^{\prime}
with free variables in
\hat{\Psi}

(i.e.
\ulcorner{}\hat{\Psi}\ .\ e^{\prime}\urcorner
). The associated substitution
\sigma

provides a map between the variables in
\hat{\Psi}
to the current context
and hence allows us to continue the execution of
e^{\prime}
with the environment
provided by
\sigma
.

\text{Kinds}&K_{k},\mathop{\ldots}&\mathbin{:=}&{\mathtt{Type}}_{k}\mathbin{\ \mid\ }{[\Psi\ \vdash\ K_{l}]{\uparrow}}^{k}_{l}\\[2.5pt]

written as

contextual up-shift, written as

We note that we have a mode associated with every type, in particular,
the base type

As we discussed in the earlier examples, types and in particular type

This avoids any type-level computation due to suspending and splicing
types as in the following example:

3.3.
Context Operations

In preparation for our type system, we define a context split
operation
\Gamma_{1}\bowtie{}\Gamma_{2}
.
This extends the context split operation given in
Jang:FSCD24

to contexts containing type variables as well as term variables.
In particular, we allow duplicating type variables disregarding their modes
as in
Atkey:LICS18
.
As explained in the introduction, this is sensible since the type-checking
and type/kind construction are compile-time steps rather than runtime computation.

\begin{array}[]{l@{~\ctxMerge{}{}~}lcll}(\Gamma_{1}\mathbin{,}\alpha{:}K_{k})\hfil~\bowtie&(\Gamma_{2}\mathbin{,}\alpha{:}K_{k})&=&(\Gamma_{1}\bowtie{}\Gamma_{2})\mathbin{,}\alpha{:}K_{k}\\
(\Gamma_{1}\mathbin{,}\alpha{:}K_{k})\hfil~\bowtie&\Gamma_{2}&=&(\Gamma_{1}\bowtie{}\Gamma_{2})\mathbin{,}\alpha{:}K_{k}\\
\Gamma_{1}\hfil~\bowtie&(\Gamma_{2}\mathbin{,}\alpha{:}K_{k})&=&(\Gamma_{1}\bowtie{}\Gamma_{2})\mathbin{,}\alpha{:}K_{k}\\
(\Gamma_{1}\mathbin{,}x{:}A_{k})\hfil~\bowtie&(\Gamma_{2}\mathbin{,}x{:}A_{k})&=&(\Gamma_{1}\bowtie{}\Gamma_{2})\mathbin{,}x{:}A_{k}&\text{if }\mathtt{C}\in\mathcal{S}({k})\\
(\Gamma_{1}\mathbin{,}x{:}A_{k})\hfil~\bowtie&\Gamma_{2}&=&(\Gamma_{1}\bowtie{}\Gamma_{2})\mathbin{,}x{:}A_{k}\\
\Gamma_{1}\hfil~\bowtie&(\Gamma_{2}\mathbin{,}x{:}A_{k})&=&(\Gamma_{1}\bowtie{}\Gamma_{2})\mathbin{,}x{:}A_{k}\\
{\ \cdot\ }\hfil~\bowtie&{\ \cdot\ }&=&{\ \cdot\ }\\
\end{array}

For a term variable
x{:}A_{k}
where
k
does not allow contraction,
we must make sure that
x
is used only once. However, if a mode allows
contraction, we may want to use it several times. We split a
context into two while respecting this in the definition of the
context split.

We prove that the context split is commutative and associative.

Lemma 3.1 (Properties of Context Split).

•

Commutative :

\Gamma_{1}\bowtie{}\Gamma_{2}=\Gamma
if and only if

\Gamma_{2}\bowtie{}\Gamma_{1}=\Gamma

•

Associative :

(\Gamma_{1}\bowtie{}\Gamma_{2})\bowtie{}\Gamma_{3}=\Gamma
if and only if

\Gamma_{1}\bowtie{}(\Gamma_{2}\bowtie{}\Gamma_{3})=\Gamma

Proof.

By induction on
\Gamma
and case analysis on the definition of
\bowtie{}
.
∎

3.4.
Substitution

As we only use normal types in
Elevator
, we want to define
the (parallel) substitution operation so that it preserves
the normal forms of types.
Thus, we define the hereditary substitution
[

;

]

for types, which reduces type-level redices
(i.e.
\llcorner{}\ulcorner{}\hat{\Psi}\ .\ A_{l}\urcorner\lrcorner@\sigma
form)
occuring during the substitution. However, as this may increase the size of
the type to which we apply a substitution, we cannot use the size as
a termination measure for this operation. To give a termination measure for
this substitution, we use dependency-free context and kind:

\begin{array}[]{llcl}\text{Dependency-Free Kinds}&\kappa_{k},\mathop{\ldots}&\mathbin{:=}&{\mathtt{Type}}_{k}\mathbin{\ \mid\ }{[\psi\ \vdash\ \kappa_{l}]{\uparrow}}^{k}_{l}\\
\text{Dependency-Free Contexts}&\psi,\gamma,\mathop{\ldots}&\mathbin{:=}&{\ \cdot\ }\mathbin{\ \mid\ }\gamma\mathbin{,}\alpha{:}\kappa_{k}\mathbin{\ \mid\ }\gamma\mathbin{,}x\end{array}

These dependency-free contexts/kinds give us the appropriate termination measure, e.g. they
structurally decrease when we define the substitution. We obtain these
dependency-free contexts/kinds from the usual contexts/kinds using a dependency erasure

{(\_)}^{-}
defined below.

\begin{array}[]{lcllcl}\lx@intercol\mbox{Context erasure}:{(\Psi)}^{-}=\psi\hfil\lx@intercol&\lx@intercol\mbox{Kind erasure}:{(K_{l})}^{-}=\kappa_{l}\hfil\lx@intercol\\
{({\ \cdot\ })}^{-}&=&{\ \cdot\ }&{({\mathtt{Type}}_{k})}^{-}&=&{\mathtt{Type}}_{k}\\
{(\Gamma\mathbin{,}\alpha{:}K_{k})}^{-}&=&{(\Gamma)}^{-}\mathbin{,}\alpha{:}{(K_{k})}^{-}&{({[\Psi\ \vdash\ K_{l}]{\uparrow}}^{k}_{l})}^{-}&=&{[{(\Psi)}^{-}\ \vdash\ {(K_{l})}^{-}]{\uparrow}}^{k}_{l}\\
{(\Gamma\mathbin{,}x{:}A_{k})}^{-}&=&{(\Gamma)}^{-}\mathbin{,}x&&&\end{array}

Now, we can define the following substitution for normal and neutral types.

\begin{array}[]{lcll}\lx@intercol\mbox{Substitution for normal types:}{[\sigma]}^{\gamma}A_{k}=B_{k}\hfil\lx@intercol\\[5.0pt]
{[\sigma]}^{\gamma}({[\Psi\ \vdash{}\ A_{l}]{\uparrow}}^{k}_{l})&=&{[\Psi^{\prime}\ \vdash{}\ B_{l}]{\uparrow}}^{k}_{l}&\mbox{where}~{[\sigma]}^{\gamma}\Psi=\Psi^{\prime}~~\mbox{and}~~{[\sigma]}^{\gamma}A_{l}=B_{l}\\[0.0pt]
{[\sigma]}^{\gamma}(A_{m}{\downarrow}^{m}_{k})&=&(B_{m}){\downarrow}^{m}_{k}&\mbox{where}~{[\sigma]}^{\gamma}A_{m}=B_{m}\\[0.0pt]
{[\sigma]}^{\gamma}(\ulcorner{}\hat{\Psi}\ .\ A_{l}\urcorner)&=&\ulcorner{}\hat{\Psi}\ .\ B_{l}\urcorner&\mbox{where}~{[\sigma]}^{\gamma}A_{l}=B_{l}\\[0.0pt]
{[\sigma]}^{\gamma}P_{k}&=&A_{k}&\text{if }{[\sigma]}^{\gamma}_{\mathtt{R}}P_{k}=A_{k}:\kappa_{k}\\[0.0pt]
{[\sigma]}^{\gamma}P_{k}&=&Q_{k}&\text{if }{[\sigma]}^{\gamma}_{\mathtt{R}}P_{k}=Q_{k}\\[10.00002pt]
\lx@intercol\mbox{Substitution for neutral types:}{[\sigma]}^{\gamma}_{\mathtt{R}}P_{k}=Q_{k}\hfil\lx@intercol\\[5.0pt]
{[\sigma]}^{\gamma}_{\mathtt{R}}\alpha&=&A_{k}:\kappa_{k}&\text{if }\alpha{\mapsto}A_{k}\in\sigma\text{ and }\alpha{:}\kappa_{k}\in\gamma\\[2.5pt]
{[\sigma]}^{\gamma}_{\mathtt{R}}\alpha&=&\alpha&\text{otherwise}\\[0.0pt]
{[\sigma]}^{\gamma}_{\mathtt{R}}(\llcorner{}P_{m}\lrcorner@\tau)&=&A^{\prime}_{k}:\kappa_{k}&\text{if }{[\sigma]}^{\gamma}_{\mathtt{R}}P_{m}=\ulcorner{}\hat{\Psi}\ .\ A_{k}\urcorner:{[\psi\ \vdash\ \kappa_{k}]{\uparrow}}^{m}_{l}\\
&&&\text{and}~{[\sigma]}^{\gamma}\tau=\tau^{\prime}~~\text{and}~~{[\tau^{\prime}]}^{\psi}A_{k}=A^{\prime}_{k}\\[2.5pt]
{[\sigma]}^{\gamma}_{\mathtt{R}}(\llcorner{}P_{m}\lrcorner@\tau)&=&\llcorner{}P^{\prime}_{m}\lrcorner@\tau^{\prime}&\text{if }{[\sigma]}^{\gamma}_{\mathtt{R}}P_{m}=P^{\prime}_{m}~~\text{and}~~{[\sigma]}^{\gamma}\tau=\tau^{\prime}\end{array}

In this definition, if
{[\sigma]}^{\gamma}_{\mathtt{R}}P_{k}=A_{k}:\kappa_{k}
, then

\kappa_{k}<\gamma
holds, i.e.
\kappa_{k}
is structurally smaller than
\gamma
. Thus, if
{[\sigma]}^{\gamma}_{\mathtt{R}}P_{m}=\ulcorner{}\hat{\Psi}\ .\ A_{k}\urcorner:{[\psi\ \vdash\ \kappa_{k}]{\uparrow}}^{m}_{l}
,
we get that
{[\psi\ \vdash\ \kappa_{k}]{\uparrow}}^{m}_{l}<\gamma
and hence
\psi<\gamma
.

{[\sigma]}^{\gamma}_{\mathtt{R}}(\llcorner{}P_{m}\lrcorner@\tau)
where we
continue to apply the substitution to the result of
{[\sigma]}^{\psi}_{\mathtt{R}}P_{m}
is fine.

\Psi

\begin{array}[]{lcll}\lx@intercol\mbox{Substitution for terms:}{[\sigma]}^{\gamma}_{\mathtt{R}}e=e^{\prime}\hfil\lx@intercol\\[5.0pt]
{[\sigma]}^{\gamma}x&=&e&\text{if }x{\mapsto_{k}}e\in\sigma\\

Theorem 3.2 (Termination of Substitution).

(1)

{[\sigma]}^{\gamma}A_{k}
terminates, i.e. it either produces a result or fails.

(2)

{[\sigma]}^{\gamma}e
terminates, i.e. it either produces a result or fails.

Proof.

By lexicographical induction on
\gamma
and the target of substitution (
A_{k}
or
e
).
Note that whenever we change
\gamma
to
\psi

\psi

\gamma

\psi<\gamma

∎

\begin{array}[]{l@{~\subMerge{}{}~}lcll}(\sigma_{1}\mathbin{,}\alpha{\mapsto}A_{k})\hfil~\bowtie&(\sigma_{2}\mathbin{,}\alpha{\mapsto}A_{k})&=&(\sigma_{1}\bowtie{}\sigma_{2})\mathbin{,}\alpha{\mapsto}A_{k}\\

{\ \cdot\ }\hfil~\bowtie&{\ \cdot\ }&=&{\ \cdot\ }\\
\end{array}

As in the context split operation, we allow duplication of types disregarding
the mode information and duplication of terms only for modes that allow

We prove that the substitution split is commutative and associative, parallel to

Lemma 3.3 (Properties of Substitution Split).

•

Commutative :

\sigma_{1}\bowtie{}\sigma_{2}=\sigma
if and only if

\sigma_{2}\bowtie{}\sigma_{1}=\sigma

•

Associative :

(\sigma_{1}\bowtie{}\sigma_{2})\bowtie{}\sigma_{3}=\sigma
if and only if

\sigma_{1}\bowtie{}(\sigma_{2}\bowtie{}\sigma_{3})=\sigma

Proof.

By induction on
\sigma
and case analysis on the definition of
\bowtie{}
.
∎
