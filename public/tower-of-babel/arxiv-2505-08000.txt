Limitations to Computing Quadratic Functions on Reed-Solomon Encoded Data
Keller Blackwell, Mary Wootters

Abstract
We study the problem of low-bandwidth non-linear computation on Reed-Solomon encoded data. Given an [ n , k ] [n,k] Reed-Solomon encoding of a message vector f → ∈ 𝔽 q k \vec{f}\in\mathbb{F}_{q}^{k} , and a polynomial g ∈ 𝔽 q ​ [ X 1 , X 2 , … , X k ] g\in\mathbb{F}_{q}[X_{1},X_{2},\ldots,X_{k}] , a user wishing to evaluate g ⁡ ( f → ) g(\vec{f}) is given local query access to each codeword symbol. The query response is allowed to be the output of an arbitrary function evaluated locally on the codeword symbol, and the user’s aim is to minimize the total information downloaded in order to compute g ⁡ ( f → ) g(\vec{f}) . We show that when k = 2 k=2 and q = p e q=p^{e} for odd e e and prime p p satisfying p ≡ 3 mod 4 p\equiv 3\mod 4 , then any scheme that evaluates the quadratic monomial g ⁡ ( X 1 , X 2 ) := X 1 ​ X 2 g(X_{1},X_{2})\vcentcolon=X_{1}X_{2} must download at least 2 ​ ⌈ log 2 ⁡ ( q − 1 ) ⌉ − 3 2\lceil\log_{2}(q-1)\rceil-3 bits of information. Compare this with the straightforward scheme of Reed-Solomon interpolation which recovers f → \vec{f} in its entirety, which downloads 2 ​ ⌈ log 2 ⁡ ( q ) ⌉ 2\lceil\log_{2}(q)\rceil bits. Our result shows that dimension-2 Reed-Solomon codes do not admit any meaningful low-bandwidth scheme for the evaluation of quadratic functions over the encoded data. This contrasts sharply with prior work for low-bandwidth evaluation of linear functions g ⁡ ( f → ) g(\vec{f}) over Reed-Solomon encoded data, for which it is possible to substantially improve the naive bound of k ​ ⌈ log 2 ⁡ ( q ) ⌉ k\lceil\log_{2}(q)\rceil bits [ GW16 , TYB18 , SW21 , KKK+24 , CT22 ] .

Introduction

Suppose that data
\vec{f}\in\mathbb{F}_{q}^{k}

\vec{c}\in\mathbb{F}_{q}^{n}

of the symbol of

for all (or some)
i\in[n]
. The goal is to compute
g(\vec{f})
, while minimizing the number of bits queried (that is, the number of bits in all of the
g_{i}(c_{i})
, taken together).

Variants of this problem arise organically in many domains, including
regenerating codes
in distributed storage (e.g.,
[
DGW+10

DRWS11
]

(e.g,
[

,

,

in distributed computing (e.g.,
[

,
DCG19
,
YLR+19
]
). We will discuss these connections more in Section
1.4
, but first we discuss our particular setting in more detail.

We study the case when the error correcting code is Reed-Solomon (RS). That is, the codeword symbols are indexed by
n
evaluation points
\alpha\in\mathbb{F}_{q}
; the data
\vec{f}\in\mathbb{F}_{q}^{k}
is treated as a polynomial

of degree at most

; and the corresponding encoding

is given by
c_{\alpha}=f(\alpha)
. Reed-Solomon codes are a classical error correcting code, ubiquitous in both theory and practice. Relevant to the domains mentioned above, RS codes are used in distributed storage (e.g.,

When the error correcting code is Reed-Solomon (or any MDS code), the naive approach to compute

is to first recover
\vec{f}
itself, by querying any

symbols of the codeword and doing polynomial interpolation. Then one can compute
g(\vec{f})
for any function

. This approach has bandwidth

bits.

The natural question is whether one can do better. Prior work has shown that the answer is
yes
in the case when

is a linear function. In more detail,
regenerating codes
capture the special case of this problem where

is the function

for some
\alpha\in\mathbb{F}_{q}

[

,

,
TYB18
,

]
) has established that one can compute
g_{\alpha}(\vec{f})
for any

that appears as an evaluation point in the RS code, using substantially fewer than
k\log_{2}(q)
bits in bandwidth. In some parameter regimes
[
TYB18
,
CT22
]
, the bandwidth can even get close to
\log_{2}(q)
bits, the number of bits it takes to write down
g_{\alpha}(\vec{f})
.

For arbitrary linear functions
g:\mathbb{F}_{q}^{k}\to\mathbb{F}_{q}
(not just the evaluation functions
g_{\alpha}
above), it is again possible to use asymptotically less than
k\log_{2}(q)
bits, at least in some parameter regimes
[

,
KKK+24
]
. More precisely,
[

]
showed that for a full-length RS code of dimension

over an extension field, given access to

]
extends the techniques of
[

to consider linear

Given this state of affairs, the natural question is whether these results can extend to non-linear functions. That is, our question is:

Can we compute non-linear functions of Reed-Solomon encoded data, using substantially fewer than

Main Results in a Nutshell.

We give a
negative
answer to the question above. In more detail, we restrict our attention to the simplest instance of this problem: computing quadratic functions
g
on top of dimension

represents the line
f(x)=mx+b

. In this setting, we show that we show that there is no scheme computing
g(\vec{f})
that can download fewer than
2\lceil\log_{2}(q-1)\rceil-3

Our proof requires that

for odd

. However, we conjecture that the result holds over arbitrary fields, and that this restriction is an artifact of our proof.

We also show that any scheme over

requires

(Definition

1.1
Linear Coefficient Product (LCP) Recovery

We now formalize our problem. We limit our attention to the simplest setting for non-linear evaluation, which is over dimension
k=2
Reed-Solomon codes.

Definition 1

(Reed-Solomon (RS) Codes of dimension
k=2

[
RS60
]
)
.

Given some finite field
\mathbb{F}_{q}
of order
q>2
, let
n=q-1
. The corresponding (full length) Reed-Solomon code of dimension
k=2
is the vector space

\mathrm{RS}_{q}[n,2]\vcentcolon=\left\{\langle f(\alpha)\rangle_{\alpha\in\mathbb{F}_{q}^{*}}:f\in\mathbb{F}_{q}[x],\deg(f)<2\right\}.

That is, a dimension
k=2
RS code encodes
\vec{f}=(m,b)
as evaluations of the line
f(x)=mx+b
. We wish to compute the product of
m
and
b
, which we will denote
\prod\vec{f}
.

To formalize the model described informally above, we first define a
leakage function
, which outputs a single bit.

Definition 2

(Leakage Function)
.

For
A\subseteq\mathbb{F}_{q}
, the (bit-valued) leakage function
L=L(A):\mathbb{F}_{q}\to\{0,1\}
is given by

L(x)=\begin{cases}0&x\in A\\
1&\text{else}\end{cases}

Each server may use any number of leakage functions (possibly zero and possibly more than one) as part of a scheme to compute
\prod\vec{f}
. We formalize this as follows.

Definition 3

(Linear coefficient product recovery)
.

Let
t,s\in\mathbb{Z}^{+}
. We say that there exists a
t
-bit,
s
-server
L
inear
C
oefficient
P
roduct recovery scheme (LCP) if for every choice of
S\subseteq\mathbb{F}_{q}^{\ast}
with
|S|=s
, there exists

•

a sequence of
\alpha_{1},\ldots,\alpha_{t}\in S
(possibly with repetition)

•

leakage functions
L_{i}:\mathbb{F}_{q}\to\{0,1\}
,
i\in[t]

•

a reconstructing function
\mathrm{Rec}:\{0,1\}^{t}\to\mathbb{F}_{q}

such that

\mathrm{Rec}\left(L_{i}\left(f(\alpha_{i})\right):i\in[t]\right)=\prod\vec{f}

(1)

for all
f\in\mathbb{F}_{q}[x]
,
\deg(f)\leq 1
. Given a
t
-bit,
s
-server LCP, we call the parameter
t
the download bandwidth of the scheme.

1.2
Our Results

Our primary result is the following.

Theorem 4
.

Fix
\mathbb{F}_{q}=\mathbb{F}_{p^{e}}
for prime
p
and odd extension degree
e
satisfying
p\equiv 3\mod 4
; let
s\geq 3
and suppose there exists a
t
-bit,
s
-server LCP scheme (Definition
3
) for full-length RS codes over
\mathbb{F}_{q}
. Then the download bandwidth satisfies
t\geq 2\lceil\log_{2}(q-1)\rceil-3
.

This result shows that naive Reed-Solomon interpolation is essentially optimal for the problem of coefficient recovery, at least for full-length RS codes of dimension
2
. We find this result surprising: Computing
\prod\vec{f}
intuitively seems “easier” than recovering all of
\vec{f}
; and indeed this intuition is known to be the case for
linear
functions
g
in many parameter regimes.

Additionally, we show that the consideration of completely unstructured bit-valued leakage functions (Definition
2
) is necessary. More precisely, any
t
-bit LCP over
\mathbb{F}_{p^{e}}
that performs any better than the naive download bandwidth of
2\lceil\log_{2}(q)\rceil
requires that the servers evaluate non-linear functions (over the base field
\mathbb{F}_{p}
) on their codeword symbols.

Theorem 5

(Informal; see Theorem
40
)
.

Let
\mathbb{F}_{q}
denote an arbitrary extension field of order
p^{e}
where
e\geq 2
. Suppose each server is restricted to evaluating
\mathbb{F}_{p}
-linear functions
g_{i}:\mathbb{F}_{q}\to\mathbb{F}_{p}
on their codeword symbols. Then there does not exist any
t
-bit LCP with download bandwidth less than
t<2\lceil\log_{2}(q)\rceil
bits.

That is, no scheme with
\mathbb{F}_{p}
-linear leakage functions can perform
even one bit
better than the naive download bandwidth for LCP.
Theorem
5
is notable in contrast to prior work on computing linear functions
g
of
\vec{f}
over extension fields, where the local computation functions
g_{i}
are generally
\mathbb{F}_{p}
-linear
[
GW17
,
TYB18
,
SW21
,
KKK+24
]
. This motivates the use of arbitrary leakage functions (Definition
2
).

1.3
Technical Overview

In this section, we give an overview of the proof Theorem
4
. We begin with a very high-level overview before elaborating on each step.

We first bound the bandwidth of any LCP solution by the round complexity of an iterative algorithm, which partitions all the lines
f(x)=mx+b
into
buckets
determined by their coefficient product
\prod\vec{f}
. That is, we partition the lines into buckets
B_{\gamma}=\{f(x)\in\mathbb{F}_{q}[x]\,:\,\deg(f)\leq 1,\prod\vec{f}=\gamma\}
, for
\gamma\in\mathbb{F}_{q}
.
We then model receiving bits from the leakage functions sequentially, one per round; each round, we “prune” away all of the lines
f(x)
that disagreeing with the leakage bit. The algorithm terminates when there is only one non-empty bucket
B_{\gamma}
remaining, corresponding to the correct coefficient product
\gamma
. If the LCP has bandwidth
t
, then this procedure must halt within
t
steps. Thus, the round complexity of the iterative algorithm yields a lower bound on the bandwidth
t
.

Analyzing how these buckets of lines evolve as we prune them seems challenging. Our second step restricts both the sets of possible servers and of possible coefficient products in order to introduce symmetry aiding our analysis. In more detail, we demand that the coefficient product
\prod\vec{f}
is a
quadratic residue
in the field
\mathbb{F}_{q}
; we similarly restrict queries to servers indexed by quadratic residues. This assumption is without loss of generality: restricting the value of
\prod\vec{f}
makes the LCP problem easier, and thus makes impossibility results stronger; and restricting the set of servers is allowed because in Definition
3
, the client must be able to query
any
set of
s
servers. Since the client must download
at least
one bit per query, any low-bandwidth scheme is only interesting when
s\leq 2\log_{2}(q)
, whereas the order of the quadratic residue subgroup of
\mathbb{F}_{q}
is at least
(q-1)/2
–significantly larger than
2\log_{2}(q)
.

Restricting to this special case introduces useful symmetry in the buckets
B_{\gamma}
described above. In our third step, we use this symmetry to carefully “project” each bucket
B_{\gamma}\subseteq\mathbb{F}_{q}[x]
of lines onto a subset of
\mathbb{F}_{q}
, in a way that the higher dimensional characteristics of lines are sufficiently represented in the lower dimensional projection.
In particular, we show that when one runs an analogous algorithm on the projected buckets (iteratively pruning out
projections
of lines that are inconsistent with the leaked bits), then it is still the case that the round complexity of the projected algorithm is a lower bound on the bandwidth of the original LCP.

The fourth and final step is to bound the round complexity of the projected algorithm. This problem turns out to be more tractable than the original problem about differentiating buckets of lines, and via the logic above, it implies Theorem
4
.

Next, we expand slightly upon each of these steps.

Step 1: Algorithmic View of LCP.

As discussed above, let
B_{\gamma}=\{f(x)\in\mathbb{F}_{q}[x]\,:\,\deg(f)\leq 1,\prod\vec{f}=\gamma\}.
Suppose that we have an
t
-bit,
s
-server LCP scheme as in Definition
3
. For a fixed set
S
of
s
servers, suppose the leakage functions given by the LCP are
\{L_{i}\}
.
We consider the following algorithm for recovering
\prod\vec{f}
given the leaked bits
L_{i}(f(\alpha_{i}))
.

Algorithmic view of the LCP:

1.

Initialize a set
B_{\gamma}^{0}\vcentcolon=B_{\gamma}
for each
\gamma\in\mathbb{F}_{q}
.

2.

For each round
i=1,2,\ldots,t
:

(a)

Learn
L_{i}(f(\alpha_{i}))
by querying the server indexed by
\alpha_{i}
.

(b)

For each
\gamma
, prune
B_{\gamma}^{i-1}
by removing all
\tilde{f}(x)\in B_{\gamma}^{i-1}
such that
L_{i}(\tilde{f}(\alpha_{i}))\neq L_{i}(f(\alpha_{i}))
. Call this pruned set
B_{\gamma}^{i}
.

(c)

If there is only one
\gamma
so that
B_{\gamma}^{i}
that is non-empty, return.

If this algorithm were to go for all
t
rounds, the correctness of the LCP implies that
B_{\gamma}^{t}=\varnothing
for all but one value
\gamma=\prod\vec{f}
. In particular, the bandwidth
t
of the LCP is bounded below by the number of iterations that the algorithm above runs for before returning.

Step 2: Restricting to quadratic residues.

We show that restricting to quadratic residues (for both the coefficient products and the evaluation points) introduces strong symmetries in
B_{\gamma}
that we exploit in our analysis. Observe that

B_{1}=\left\{m^{-1}x+m:m\in\mathbb{F}_{q}^{\ast}\right\}.

Now suppose that for some
\gamma\in\mathbb{F}_{q}^{\ast}
there exists
\sqrt{\gamma}\vcentcolon=\delta\in\mathbb{F}_{q}^{\ast}
such that
\gamma=\delta^{2}
; in other words,
\gamma
is a quadratic residue in
\mathbb{F}_{q}
. One may then rewrite
B_{\gamma}
as

B_{\gamma}=\left\{\sqrt{\gamma}m^{-1}x+\sqrt{\gamma}m:m\in\mathbb{F}_{q}^{\ast}\right\}\subseteq\mathbb{F}_{q}[x]

and observe that in fact
B_{\gamma}=\sqrt{\gamma}\cdot B_{1}
. This correspondence between sets of lines extends to a correspondence between their images under evaluation at a given point
\alpha\in\mathbb{F}_{q}^{\ast}
:

B_{\gamma}(\alpha)\vcentcolon=\left\{\sqrt{\gamma}m^{-1}\alpha+\sqrt{\gamma}m\right\}=\sqrt{\gamma}\cdot B_{1}(\alpha).

When we further restrict
\alpha
to also be a quadratic residue, we show that the following symmetry holds, allowing LCP to be simplified considerably.

Lemma 6

(Informal; see Lemma
16
)
.

Let
\sqrt{\gamma},\sqrt{\alpha}\in\mathbb{F}_{q}^{\ast}
be field elements whose squares are
\gamma,\alpha
, respectively. Then
B_{\gamma}(\alpha)=(\sqrt{\gamma})(\sqrt{\alpha})\cdot B_{1}(1)
.

Given this symmetry, we consider the sub-case of LCP wherein we are guaranteed that
\prod\vec{f}\in\mathbb{F}_{q}^{\ast}
is a quadratic residue, and the user is restricted to querying servers holding
f(\alpha)
where
\alpha\in\mathbb{F}_{q}^{\ast}
is also a quadratic residue. As noted above, this restriction is without loss of generality for the purpose of proving a lower bound on the bandwidth of LCPs.

Step 3: Reduction to distinguishing subsets of
\mathbb{F}_{q}
.

When
\gamma\in\mathbb{F}_{q}^{\ast}
is a quadratic residue, we show that the correspondence in Lemma
6
can be leveraged to “project” each
B_{\gamma}\subseteq\mathbb{F}_{q}[x]
to a set of points
S_{\gamma}\vcentcolon=\lambda_{\gamma}B_{1}(1)\subseteq\mathbb{F}_{q}
, where
\lambda_{\gamma}\in\mathbb{F}_{q}^{\ast}
. This reduces the problem of finding which
B_{\gamma}
contains
f(x)
to that of finding which
S_{\gamma}
contains some distinguished point
\zeta\in\mathbb{F}_{q}
. At a high level, we show that the download bandwidth of LCP is bounded below by the round complexity of the following algorithm:

In Definition
26
and Theorem
27
, we show explicitly how to map a leakage function
L
to a set
V\subseteq\mathbb{F}_{q}
so that if the line
f(X)
has
L(f(\alpha_{i}))=1
, then a distinguished point
\zeta
lies in
V
.
Thus, given our LCP with leakage functions
L_{1},\ldots,L_{t}
, we obtain a list of corresponding sets
V_{1},\ldots,V_{t}
which can be used to iteratively prune the sets
S_{\gamma}
until only one (say,
S_{\delta}
) remains nonempty; the label
\delta
of this final set corresponds to the desired coefficient product
\prod\vec{f}
. Assembling these insights yields the following algorithm, analogous to the one above, except that we now iteratively prune the projected sets
S_{\gamma}\subseteq\mathbb{F}_{q}
.

Algorithmic view of the projected LCP:

1.

Initialize a set
S_{\gamma}^{0}\vcentcolon=S_{\gamma}
for each quadratic residue
\gamma\in\mathbb{F}_{q}
.

2.

For each such round
i=1,2,\ldots,t
:

(a)

Learn whether
S_{\delta}\cap V=\varnothing
.

(b)

For each
\gamma
, prune
S_{\gamma}^{i-1}
by removing all elements inconsistent with the server’s sent bit. That is, if
S_{\delta}\cap V=\varnothing
, then remove everything in
V
; else remove everything in
V
’s complement. Call the pruned set
S_{\gamma}^{i}
.

(c)

If there is at most one
\gamma
so that
S_{\gamma}^{i}
is non-empty, return.

We call this algorithm “projection LCP”, or pLCP for short. We have simplified it a bit for exposition; see Algorithm
2
and Section
4
for a formal description.

We show that, as with our algorithm on buckets of lines, if the projected algorithm is allowed to run for all
t
rounds, then the correctness of the original LCP implies that there will be at most one
\delta
so that
S_{\delta}^{t}
is non-empty, and this
\delta
corresponds to the coefficient product
\prod\vec{f}
we originally wished to compute. This transitively implies that the round complexity of this projected algorithm is again a lower bound on the bandwidth of the original LCP. The round complexity of this projected algorithm is much easier to analyze, leading to our final step.

Step 4: Analyzing the projected algorithm.

The key to our analysis is to show that, when the projected algorithm terminates, most elements of
S_{\delta}
have been removed from consideration.

Theorem 7

(Informal; see Theorem
37
)
.

Suppose that the projected LCP algorithm above terminates after
\ell
rounds. Then
|S^{\ell}_{\delta}|\leq 2
.

The intuition behind this theorem is to observe that each set
S_{\gamma}^{0}
has size
|S_{\gamma}^{0}|\approx q/2
that is half the field, and there are
\approx q/2
quadratic residues
\gamma
. As a result, the sets
S_{\gamma}^{0}
must overlap with each other significantly. Any field element
\alpha\in S_{\gamma}^{0}
is held by many other
S_{\gamma^{\prime}}^{0}
, where
\gamma^{\prime}\neq\gamma
is another quadratic residue. Hence, distinguishing a unique
S_{\delta}
among these will require most elements of the entire field to have been removed from consideration.

With Theorem
7
established, the bound of Theorem
4
follows in Section
4.3.2
by considering “adversarial but honest” servers who always reply to queries with the bit that prunes the fewest elements; that is, at most half of the set. Since the projected algorithm cannot terminate unless there are two or fewer elements remaining among all sets
S_{\gamma}^{i}
, we see that in the worst case, it takes about
\log_{2}(q^{2})
rounds for the algorithm to terminate. The expression seen in Theorem
4
follows from a more precise accounting, but the the basic intuition is the same.

1.4
Related Work

As discussed above, the problem of low-bandwidth computing on top of encoded data arises in many domains. We discuss these areas, and relevant work in them, below.

1.4.1
Computing linear functions: Regenerating codes and beyond

Regenerating Codes.

Existing work has considered our model in the case when
g(\vec{f})
is linear.
Regenerating codes
focus on a particular subset of linear functions.
Regenerating codes (e.g.,
[
DGW+10
,
DRWS11
]
) are error correcting codes equipped with algorithms to efficiently repair a single erased codeword symbol in a distributed storage system. In more detail, some data
\vec{f}
is encoded as a codeword
\vec{c}
, and each symbol
c_{i}
is sent to a different server. If one server
i^{*}
becomes unavailable, the goal is to compute
c_{i^{*}}
using as little information as possible from a subset of
s
surviving nodes. Repair is a special case of our model where the function to compute is
g(\vec{f})=c_{i^{*}}
, whose linearity follows from the linearity of the code. A long line of work has established constructions of optimal regenerating codes in many parameter regimes; most relevant to our work is the study of Reed-Solomon codes as regenerating codes, initiated by
[
SPDC14
]
. By now, it is known that RS codes can be optimal or near-optimal regenerating codes in many parameter regimes. For example,
[
GW17
,
DDK+21
]
show that full-length RS codes (that is, with
q=n
) of rate
1-\varepsilon
can achieve bandwidth bandwidth
(n-1)\log(1/\varepsilon)
, and that this is nearly optimal for linear repair schemes. For constant
\varepsilon
, this is an
\Omega(\log n)
improvement over the naive bound of
k\log q
. When
q
is much larger than
n
, it is possible to do better: Work by
[
TYB18
]
provides repair schemes for RS codes achieving the
cut-set bound

[
DGW+10
]
. In our language, this gives bandwidth
\frac{s\log_{2}q}{s+1-k}
bits, where
s
is the number of surviving servers the scheme contacts. As
s
gets large relative to
k
, this can approach
\log_{2}q
, the number of bits needed to write down
g(\vec{f})
. In particular, this is also significantly less than the naive bound of
k\log_{2}q
.

All the constructions discussed above use linear repair schemes over extension fields
\mathbb{F}_{p^{e}}
, meaning that the local computation functions
g_{i}
, and the function used to aggregate them, are linear over
\mathbb{F}_{p}
. The work
[
CT22
]
studies the problem over prime order fields, where there are no non-trivial subfields and hence no linear repair schemes.
For
k=2
(the same setting we consider),
[
CT22
]
construct non-linear repair schemes which asymptotically converge to the cut-set bound over prime order fields
\mathbb{F}_{p}
as
p\to\infty
.

Computing general linear functions.

The work
[
SW21
]
generalized the regenerating code model to consider the case when
g:\mathbb{F}_{q}^{k}\to\mathbb{F}_{q}
is an
arbitrary
linear function. Given a length
n=q
Reed-Solomon code of dimension
k=(1-\varepsilon)n
over an extension field of constant characteristic,
[
SW21
]
constructs a scheme which recovers
g(\vec{f})
for any linear function given access to any
s=n(1-\gamma)
servers, with download bandwidth
O(n/(\varepsilon-\gamma))
. When
\varepsilon
is constant, this is a factor of
\Omega(\log n)
improvement over the naive bound of
k\log q
bits.

In follow-up work,
[
KKK+24
]
considered reconstructing
\ell
-sparse linear combinations of codeword symbols, for
\ell\leq k
. When
\mathbb{F}_{q}=\mathbb{F}_{p^{e}}
has non-trivial extension degree
e\geq 2
over
\mathbb{F}_{p}
, they give a low-bandwidth scheme for evaluating
g
, which downloads
d\log_{2}(p)
bits, where
d\geq\ell p^{e-1}-\ell+k
. When
p,e
are carefully chosen and
\ell\ll k
, their construction can outperform the naive
ke\log_{2}(p)
download bandwidth.

While they show that the naive bound of
k\log_{2}(q)
can be significantly beaten in some parameter regimes, the results of
[
SW21
,
KKK+24
]
are not meaningful for
k=2
: The focus of
[
SW21
]
is on high-rate codes, while the results of
[
KKK+24
]
require
k
to be large enough that the sparsity
\ell
can be much smaller than
k
. However, we can compare our results to the results of
[
TYB18
]
and
[
CT22
]
. Given a message polynomial
f(x)=mx+b
, these papers together show that it is possible to compute
f(0)=b
with bandwidth approaching
\log_{2}q
as the number of contacted servers
s\to\infty
is sufficiently large and
|\mathbb{F}|\to\infty
, over both prime fields
\mathbb{F}_{p}

[
CT22
]
; and over extension fields
\mathbb{F}_{p^{e}}
for suitably large
e

[
TYB18
]
. Our result works for both prime order fields and extension fields, provided that the characteristic
p\equiv 3\mod 4
and the extension degree
e
is odd. Moreover, our result holds even when
s
is arbitrarily large (noting that without loss of generality we have
s\leq k\log_{2}q
). Thus, in parameter regimes where these results overlap, we see that recovering the linear function
b+\alpha m
, for any evaluation point
\alpha
in the RS code considered by
[
CT22
]
or
[
TYB18
]
(depending on the field), requires substantially less bandwidth than recovering
m\cdot b
.
1
1

1

For
k=2
, it may look like the problem of computing
g(\vec{f})=f(\alpha)
is the same as computing arbitrary linear functions, as all linear functions (up to normalization) of
(b,m)
look like
b+\alpha m
for some
\alpha
. However, these are not the same problem when the set of evaluation points for the RS code is not the entire field. The regenerating code constructions in
[
TYB18
,
CT22
]
have
n\ll q
, so those works do not immediately give a scheme for computing general linear functions, even when
k=2
.

1.4.2
Secret Sharing

In a secret-sharing scheme, a secret
s\in\mathbb{F}_{q}
is shared among
n
parties. One goal is that any
k
of the parties should be able to combine their shares to recover the secret, while any
k-1
parties together learn nothing about the secret. The secret sharing scheme most relevant to our work is
Shamir’s scheme

[
Sha79
]
, the secret
s\in\mathbb{F}_{q}
is shared by sampling
f_{i}\leftarrow\mathbb{F}_{q}
,
i\in\{1,\ldots,k-1\}
, uniformly at random and considering
f(x)=s+\sum_{i=1}^{k-1}f_{i}x^{i}
.
The parties are indexed by elements
\alpha\in\mathbb{F}_{q}^{*}
, and their shares are given by
f(\alpha)
. That is, each party holds a symbol of a RS codeword. It is not hard to see that this scheme has the desired access and security requirements.

There are several questions in secret sharing relevant to our work. We discuss them below.

Low-Bandwidth Secret Sharing.

In
low-bandwidth secret sharing

[
WW08
,
ZCL+12
,
HLKB16
,
HB17
,
RKV18
]
, the goal is for any subset of enough parties to be able to reconstruct the secret in a communication-efficient way. When the secret sharing scheme is Shamir, this is again a special case of our problem, where
g(\vec{f})
is the function
g(\vec{f})=f(0)
. (The difference between this setting and regenerating codes is that we only need to be able recover
f(0)
, rather than
f(\alpha)
for any
\alpha
). In this setting,
[
HLKB16
]
shows that the cut-set bound is still the limit on the bandwidth (for any secret sharing scheme); but it is possible to attain this with a smaller alphabet size than needed for regenerating codes
[
HB17
]
.

Our work on the problem of LCP may be viewed in the context of low-bandwidth secret sharing by considering a “multiplicative” variant of Shamir secret sharing. We specialize to the
k=2
example for simplicity. In standard Shamir sharing with
k=2
, a slope
m
is drawn at random and the shares correspond to the function
f(x)=mx+s
, where
s
is the secret. In the multiplicative variate,
m
and
b
are chosen at random so that the secret is
s=m\cdot b
. This is a special case of LCP, when
\prod\vec{f}
is restricted to be nonzero. In particular, our results imply that there to
not
exist non-trivially low-bandwidth secret sharing schemes for “multiplicative Shamir,” with
k=2
even though there do for standard Shamir.

Leakage-Resilient Secret Sharing.

The work
[
BDIR18
]
considers a threat model in which an adversary has “local leakage access” to more than
k
shares; in this model, an adversary can apply an arbitrary function of bounded output length to each share locally. Concretely, we may think of this model as an adversary extracting a few bits of
local
information from each shareholder. Under this view, for Shamir sharing, the adversary may be considered as a repair scheme wishing to recover the codeword symbol
f(0)
. A code is
local leakage resilient
if the adversary has negligible advantage learning the secret
s
.

For sufficiently large code length
n
and prime field order
p
,
[
BDIR18
]
show that Reed-Solomon codes over
\mathbb{F}_{p}
are local leakage resilient when dimension
k=\alpha n
is a constant fraction of
n
for some constant
\alpha
. As a concrete example, they show that if the adversary is allowed to leak 1 bit from each share, then for
n
sufficiently large, it suffices to take
\alpha\geq 0.92
. Extensive follow-up work (e.g.,
[
MPCSW21
,
MNPCW22
,
KK23
,
Kas25
]
) has progressively lowered the threshold for 1-bit leakage resilience, with
[
Kas25
]
most recently improving the bound to
\alpha\geq 0.668
. In stark contrast,
[
CT22
,
CSTW24
]
show that for low-degree RS codes (with
k\ll n
), non-trivial leakage is possible over prime fields.

Given the discussion above about the “multiplicative” version of Shamir sharing, one may hope that our results imply that multiplicative Shamir sharing is leakage resilient. Unfortunately, this seems not to be the case for dimension
k=2
Reed-Solomon codes.
First, at least over some fields, it’s possible to learn the entire secret from strictly less than
k\lceil\log_{2}(q-1)\rceil
leaked bits, so there is some amount of non-trivial leakage that completely reveals the secret.
2
2

2

In this case, since the secret must be non-zero, the naive bound is
k\lceil\log_{2}(q-1)\rceil
rather than
\lceil k\log_{2}(q)\rceil
.
As an example, we show in Appendix
B
that “multiplicative Shamir” instantiated over
\mathbb{F}_{7}^{\ast}
admits a reconstruction algorithm that downloads only
5
bits, as compared to the
2\lceil\log_{2}(6)\rceil=6
bits one might expect in the naive case. Second, with this scheme,
leaking even one bit
from a server allows an adversary to learn information about the multiplicative Shamir secret; we give an example of this as well in Appendix
B
.

Homomorphic Secret Sharing Schemes.

In (single-client)
homomorphic secret sharing
(HSS)
[
Ben86
,
BGI16
,
BGI+18
]
, a secret
s
is shared as above, and a referee subsequently wishes to compute a function
g(s)
of the secret. Each party is allowed to do some local computation and send a message to the referee. In some applications, it is desirable to reduce the download bandwidth of the scheme. For example, in applications of HSS to Private Information Retrieval (PIR), the download bandwidth corresponds to the download cost of the PIR scheme (see
[
BCG+17
,
FIKW22
]
). Our problem of low-bandwidth function evaluation is related to HSS where we want to minimize the download bandwidth, and where we want
information-theoretic
security.
3
3

3

We note that for some applications of HSS, the reconstruction should be additive; and/or the messages sent by the parties don’t leak any information about the secret beyond
g(s)
. Neither of these are necessarily the case in low-bandwidth function evaluation.

The work
[
FIKW22
]
gives
multi
-client HSS schemes for Shamir sharing, where the referee’s function
g
is a low-degree polynomial. At first glance this seems at odds with our result (which says that computing low-degree polynomials on top of Shamir sharing with non-trivial bandwidth is impossible). However, the model for multi-client HSS is different than the one we consider, as the function
g
is evaluated on multiple secrets, which are independently secret-shared. For example,
[
FIKW22
]
applies to a setting where a user wishing to compute the monomial
g(x,y)=xy
on inputs
x=s_{1}
and
y=s_{2}
assumes that
s_{1},s_{2}
are shared separately with lines
f_{1}(x)=s_{1}+m_{1}x
and
f_{2}(x)=s_{2}+m_{2}x
; this task is distinct from computing
s_{i}\cdot m_{i}
.

Our result does not immediately imply any impossibility results for HSS, because it has to do with a function of both of
(m,b)
, rather than just of the secret, which in this case is
b
. However, we note that an extension of our result to
k>2
would apply to single-client HSS with the multi-secret extension of Shamir’s scheme
[
FY92
]
. That is, consider a message polynomial
f(x)=a+bx+cx^{2}
, where the secret is
(a,b)
and
c
is chosen randomly. An extension of our work to show a lower bound on the bandwidth of computing
a\cdot b
in this setting would prove impossibility results for computing low-degree polynomials for single-client HSS.

1.4.3
Coded Computation

In
coded computation
(e.g.,
[
LLP+17
,
DCG19
,
YLR+19
]
or see
[
LA20
]
for a survey), the goal is to compute a function
g
of some data
\vec{f}
, distributed among
n
worker nodes. The concern is that some worker nodes may unpredictable be
stragglers
(slow or non-responsive), and we would like to carry on the computation without them. The
idea is to encode
\vec{f}
as a codeword
\vec{c}
, so that
g(\vec{f})
can be computed even if a the computation on a few symbols of
\vec{c}
are unavailable.

This is similar in spirit to our model, but there are a few differences. First, coded computation is often studied over
\mathbb{R}
, rather than finite fields—it is an interesting question whether a version of our result holds over
\mathbb{R}
. Second, in our model the leakage functions are allowed to depend on the set
S
of queried servers, which is not generally the case in coded computation. However, we note that our lower bound would apply to coded computation leakage function model as well, as the problem of LCP is harder if the leakage functions cannot depend on
S
.
4
4

4

A third difference is that, to the best of our knowledge, coded computation schemes that are not repetition-based do not attempt to minimize the download bandwidth, but rather the number of workers that need to finish before the function
g(\vec{f})
can be computed, and/or an analysis of how much this speeds up the computation in the presence of stragglers. However, minimizing bandwidth—or proving that it cannot be done—seems well-motivated.
Thus, while coded computation is similar in spirit to our model, extensions to our work (to the reals and to computations larger than the product of two field elements) would be needed to give meaningful bounds in this setting.

1.5
Open Questions

We mention a few open questions raised by our results.

•

Our results leave open the possibility of low-bandwidth quadratic computation on top of RS codes that are not full-length: we rely on the fact that we may assume that (enough of) the evaluation points are quadratic residues. Do similar results hold for RS codes with arbitrary evaluation points?

•

Our results only over fields of order
p^{e}
, where
e
is odd and
p\equiv 3\mod 4
. We conjecture that this restriction is an artifact of our proof. Do our results hold over arbitrary fields?

•

It would be interesting to extend our results to larger
k
. Note that an RS code of dimension
k>2
includes linear polynomials, and thus our work implies that
2\log_{2}(q)-3
bits are necessary for computing quadratic functions
g(\vec{f})
, even for larger
k
. However, when
k>2
, the goal would be to show that one needs about
k\log_{2}(q)
bits, not
2\log_{2}(q)
bits. Do our results extend to other parameter regimes? In particular, do they extend to the high-rate parameter regime covered by
[
SW21
]
?

Preliminaries

In this section, we set notation and establish an algorithmic view of LCP. We denote by
\mathbb{F}_{q}
the finite field of
q=p^{e}

As a shorthand for the product of coefficients, we use the following notation: for any

\prod\vec{f}\vcentcolon=\prod_{i=0}^{k-1}f_{i}.

In this work, we’re interested in finding the products of coefficients of linear polynomials: for any

\vec{f}=(b,m)\in\mathbb{F}_{q}^{2}
and
\prod\vec{f}=mb\in\mathbb{F}_{q}

(Definition

3
Restricted Parameter Regime for LCP

In Section
2.1
, we established that determining the optimal download bandwidth incurred by an instance of LCP is equivalent to bounding the round complexity of the corresponding instantiation of Algorithm
1
. Rather than directly analyzing Algorithm
1
, we pursue an alternate strategy: within the scope of all parameter regimes for which LCP must succeed, we find a subset whose corresponding algorithmic view can be greatly simplified.

3.1
An Evaluation Map View of LCP

Algorithm
1
determines the coefficient product by
elimination
; given each leakage bit
b
, it removes from consideration any line inconsistent with
b
. The algorithm terminates when only one
\mathbf{B}(\gamma)\subseteq B_{\gamma}
is non-empty; it succeeds because, assuming a valid LCP, all lines consistent with a given leakage transcript have the same coefficient product.

Instead of tracking the number of lines in each set
\mathbf{B}(\gamma)
, consider an alternate implementation of Algorithm
1
that tracks the size of
\mathrm{ev}_{\alpha}(\mathbf{B}(\gamma))=\{f(\alpha)\,:\,f\in\mathbf{B}(\gamma)\}\subseteq\mathbb{F}_{q}
for any
\alpha\in\mathbb{F}_{q}^{\ast}
. This view is equivalent, since for any such
\alpha
,

\mathrm{ev}_{\alpha}(\mathbf{B}(\gamma))=\emptyset\ \iff\mathbf{B}(\gamma)=\emptyset.

It turns out that we can precisely construct such a correspondence between linear functions and their evaluations which, within a restricted parameter regime, gives a far simpler but equivalent algorithm. To state the restricted parameter regime we will consider, we first give the following definition.

Definition 11

(Quadratic Residues)
.

Given a field
\mathbb{F}_{q}
, let

\mathrm{QR}_{q}\vcentcolon=\left\{\alpha^{2}:\alpha\in\mathbb{F}_{q}^{\ast}\right\}

(6)

denote the quadratic residue subgroup of
\mathbb{F}_{q}^{\ast}
.

Definition 12

(Restricted Parameter Regime)
.

Let LCP be as in Definition
3
. We consider the following restricted parameter regime for LCP. Fix prime
p>2
satisfying
p-3\mod 4=0
and odd extension degree
e
specifying
q=p^{e}
.

1.

We will only consider lines
f\in\mathbb{F}_{q}[x]
such that
\prod\vec{f}\in\mathrm{QR}_{q}
, and

2.

during any round
i\in[t]
, we can only contact servers indexed by some
\alpha_{i}\in\mathrm{QR}_{q}
.

We discuss the restrictions placed by Definition
12
.

•

p\neq 2
makes the restrictions substantial; everything is a quadratic residue when
p=2
, and the subsequent restrictions would not simplify LCP.
p-3\mod 4=0
and
e
odd ensure
-1\not\in\mathrm{QR}_{q}
, which simplifies later counting arguments.

•

The first restriction makes LCP strictly easier - we need only consider half as many possibilities for the value of
\prod\vec{f}\in\mathbb{F}_{q}
.

•

The second restriction appears to make LCP harder; however, Definition
3
requires that an
s
-server LCP allow us to query
any
set of
s
servers. We may view our restriction to
\mathrm{QR}_{q}
-indexed servers as a
sub-case
of Definition
3
, arguing that any lower bound for a sub-case must apply to the general case.

In particular, note that any impossibility result for the restricted parameter regime in Definition
12
will imply an impossibility result for LCPs in general.

3.2
Application of Parameter Restrictions

We now apply the restricted parameter regime (Definition
12
) towards constructing a simplified version of Algorithm
1
whose round complexity will under-bound that of the general case. The construction of this simplified version, along with its analysis, is given in Section
4
. Our goal in this subsection is to demonstrate the simplifications afforded by the restricted parameters and to develop the techniques to re-cast LCP into this simplified framework.

3.2.1
Evaluation Map Images

We now describe the algebraic structure of
B_{\gamma}(\alpha)
when both
\gamma
(the coefficient product; see Definition
8
) and
\alpha
(the evaluation parameter; see Definition
9
) are restricted to
\alpha,\gamma\in\mathrm{QR}_{q}
. Consider the case where
\gamma=1
, so that

B_{1}=\left\{\frac{1}{m}x+m:m\in\mathbb{F}_{q}^{\ast}\right\}\subseteq\mathbb{F}_{q}[x].

(7)

Appendix B
5-bit reconstruction for “multiplicative” Shamir secret sharing over GF(7)

Recall that Shamir secret sharing shards a secret
s\in\mathbb{F}_{q}
by choosing
c_{1},\ldots,c_{k-1}\in\mathbb{F}_{q}
uniformly at random to construct the polynomial
h(x)\vcentcolon=s+\sum_{i=1}^{k-1}c_{i}x^{i}
. To each shareholder indexed by
\alpha\in\mathbb{F}_{q}
is dealt a secret share
h(\alpha)\in\mathbb{F}_{q}
. Any
k
shareholders can pool their shares and interpolate
h(x)
, recovering
s
in the process.

We informally recall the notion of “multiplicative” Shamir secret sharing first mentioned in Section
1.4
. The dealer wishes to shard a secret
s\in\mathbb{F}_{q}^{\ast}
, and chooses
c_{0},c_{1},\ldots,c_{k-1}\in\mathbb{F}_{q}^{\ast}
uniformly at random subject to the constraint that their product is the secret - namely,

\prod_{i=0}^{k-1}c_{i}=s.

(69)

The dealer constructs the polynomial
h(x)\vcentcolon=\sum_{i=0}^{k-1}c_{i}x^{i}
, then distributes to each shareholder indexed by
\alpha\in\mathbb{F}_{q}^{\ast}
a secret share
h(\alpha)
.

Note that in both cases, the shareholders’ shares are polynomial evaluations, but only in the former can the secret shares be viewed as a linear function of the secret; in the latter, the secret shares are non-linear in the secret.

We now consider a example of such a “multiplicative” secret sharing scheme over
\mathbb{F}_{7}^{\ast}
, where
k=2
. As the shares are now non-linear in the secret, we may wonder whether this implies one can do no better than what we might expect as the bandwidth incurred by naive interpolation,
2\lceil\log_{2}(|\mathbb{F}_{7}^{\ast}|)\rceil=6
bits. We briefly show that this is not the case, and in fact we can deterministically recover the secret in 5 bits.

Explicitly, we fix the following leakage functions. Set

T_{0}=\{0,\pm 2\},\quad T_{1}=\{0,\pm 1\},\quad T_{2}=\{0,\pm 3\},\quad T_{3}=\{0,\pm 2\},\quad T_{4}=\{0,\pm 1\}

(70)

and associate to each shareholder indexed by
i=0,1,2,3,4
the leakage function

L_{i}:\mathbb{F}_{7}\to\mathbb{F}_{2},\;x\mapsto\begin{cases}0&x\in T_{i}\\
1&\text{else}.\end{cases}

(71)

To each line
f(x)\in\mathbb{F}_{7}^{\ast}[x]
with non-zero coefficients, we may then associate the leakage transcript

\mathbf{t}_{f}\vcentcolon=\left(L_{0}(f(0)),L_{1}(f(1)),\ldots,L_{4}(f(4))\right)\in\mathbb{F}_{2}^{5}.

(72)

It is easily verified (with a computer!) that given lines
f(x),g(x)\in\mathbb{F}_{7}^{\ast}[x]
,
\mathbf{t}_{f}=\mathbf{t}_{g}
implies
\prod\vec{f}=\prod\vec{g}
, which implies that this collection of leakage functions yields a 5-bit secret reconstruction scheme for a
k=2
instance of multiplicative Shamir over
\mathbb{F}_{7}^{\ast}
.
