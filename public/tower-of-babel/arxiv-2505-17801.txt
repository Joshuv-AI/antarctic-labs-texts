Integrating Counterfactual Simulations with Language Models for Explaining Multi-Agent Behaviour
Bálint Gyevnár, Christopher G. Lucas, Stefano V. Albrecht, Shay B. Cohen

Abstract
Autonomous multi-agent systems (MAS) are useful for automating complex tasks but raise trust concerns due to risks like miscoordination and goal misalignment. Explainability is vital for trust calibration, but explainable reinforcement learning for MAS faces challenges in state/action space complexity, stakeholder needs, and evaluation. Using the counterfactual theory of causation and LLMs’ summarisation capabilities, we propose A gentic e X planations via I nterrogative S imulation (AXIS) . AXIS generates intelligible causal explanations for pre-trained multi-agent policies by having an LLM interrogate an environment simulator using queries like whatif and remove to observe and synthesise counterfactual information over multiple rounds. We evaluate AXIS on autonomous driving across 10 scenarios for 5 LLMs with a novel evaluation methodology combining subjective preference, correctness, and goal/action prediction metrics, and an external LLM as evaluator. Compared to baselines, AXIS improves perceived explanation correctness by at least 7.7% across all models and goal prediction accuracy by 23% for 4 models, with improved or comparable action prediction accuracy, achieving the highest scores overall.

Problem Definition

We focus on multi-agent goal-based sequential decision-making systems with possible partial observability, following the definitions of
Albrecht et al. 2021
with examples from the AD domain.
We write
s_{a:b}
for the ordered subsequence
(s_{a},s_{a+1},\dots,s_{b})
with positive integers
a<b
.

Let
\mathcal{I}
be the set of indexed agents in the system, e.g. vehicles on road section for AD.
At timestep
t\in\mathbb{N}^{+}
, each agent
i\in\mathcal{I}
is in local state
s^{i}_{t}\in\mathcal{S}^{i}
, e.g. the vehicle’s position coordinates and velocity, and receives a local observation
o^{i}_{t}\in\mathcal{O}^{i}
, e.g. position, velocity, and action of other vehicles. The action probabilistically depends on
s^{i}_{t}
through
p(o^{i}_{t}\mid s^{i}_{t})
.
Agent
i
selects an action
a^{i}_{t}\in\mathcal{A}^{i}
, e.g. acceleration and steering, in reaction to observations through
p(a^{i}_{t}|o^{i}_{1:t})
.
The joint state of all agents is denoted
s_{t}\in\mathcal{S}
where
\mathcal{S}=\times_{i}\mathcal{S}^{i}
and similarly for observations
o_{t}\in\mathcal{O}
and actions
a_{t}\in\mathcal{A}
.
We assume that the local observations and actions of agents are mutually independent, that is,
p(o_{t}|s_{t})=\prod_{i}p(o^{i}_{t}|s_{t})
and
p(a_{t}|o_{1:t})=\prod_{i}p(a^{i}_{t}|o^{i}_{1:t})
.
If the system dynamics are given by
p(s_{t+1}|s_{t},a_{t})
, the probability of any joint state sequence
p(s_{1:n})=\prod^{n-1}_{t=1}\int_{\mathcal{O}}\int_{\mathcal{A}}p(s_{t+1}|s_{t},a_{t})p(a_{t}|o_{1:t})p(o_{t}|s_{t})\text{d}o_{t}\text{d}a_{t}.

We assume that agent
i
is aiming to reach a goal state from
G^{i}\subset\mathcal{S}^{i}
, defined as any partial local state description, e.g. destination coordinates.
We say that the state sequence
s_{1:t}
reaches
G^{i}
and write
\textsc{{Reach}}(s_{1:t},G^{i})
if
s^{i}_{t}\in G^{i}
and
\forall n<t:s^{i}_{n}\notin G^{i}
, i.e. the goal is never achieved sooner than
t
.
The goal
G^{i}
is generally assumed to be unobservable to other agents.
If, over a state sequence
s_{1:t}
, agent
i
reaches
G^{i}
, the agent receives a reward given by
R^{i}(s_{1:t})
which we take to be a weighted sum of reward components, e.g. the time required to reach the goal and cumulative lateral acceleration.

Our problem is to find an optimal explanation function
\hat{h}\,\colon\mathcal{S}^{*}\mapsto\mathcal{H}
that maps a joint state sequence to an explanation from the set of possible explanations
\mathcal{H}
, such that for a given external reward model
R_{h}\,\colon\mathcal{S}^{*}\mapsto\mathbb{R}
parametrised by explanation function
h
and taking a joint state sequence, the function
\hat{h}
is maximised in expectation over joint state sequences:

\hat{h}\in\argmax_{h}\sum^{\infty}_{n=1}\int_{\Omega^{\varepsilon}_{n}}p(s_{1:n})R_{h}(s_{1:n})\text{d}s_{1:n},

(1)

where we assume that we explain from the perspective of a pre-selected
ego
agent
\varepsilon
and the integral is over
\Omega^{\varepsilon}_{n}=\{s_{1:n}\mid\textsc{{Reach}}(s^{\varepsilon}_{1:n},G^{\varepsilon})\}
.
1
1

1

The sum converges, because for a large enough
t
and for all
n\geq t
, the set
\Omega^{\varepsilon}_{n}=\varnothing
because the goal will have been reached by a shorter trajectory, i.e.
\exists k<t:s^{\varepsilon}_{k}\in G^{\varepsilon}
which contradicts the condition of
Reach
.

For AXIS, we take
\mathcal{H}
to be the set of all English sentences.
For the external reward model
R_{h}
, we use an LLM, describing our approach in detail in
Section

4
.

3
AXIS: Agentic Explanations via Interrogative Simulation

The exact or analytical maximisation of
Equation

1
may be, in general, intractable and requires design choices, e.g. the selection of
\mathcal{H}
and
R_{h}
.
We approximate
\hat{h}
with the AXIS framework, giving an overview in
Figure

1
and a full algorithm in
Algorithm

1
.
Below, we describe the architectural components and the decision-making algorithm of AXIS.

Memory

AXIS maintains an observations and an episodic memory.
The observation memory stores the current observation sequence
o^{\varepsilon}_{1:t}
and is updated on every step of the environment with the new observation
o^{\varepsilon}_{t+1}
.
The episodic memory stores the messages passed to the LLM, the interrogation results with the simulator, and the synthesised intermediate explanations.
In our experiments with autonomous driving (AD), an observation
o^{\varepsilon}_{t}
contains the position, velocity, and bearing as a tuple in
\mathbb{R}^{4}
, and acceleration and steering of visible vehicles as vectors in
\mathbb{R}^{2}
per vehicle.

Macro Actions

Actions in the environment may not be immediately understandable to the LLM, and vice versa; instructions that the LLM can parse may not mean anything to the simulator directly, e.g. in AD, actions are sequences of real-valued vectors which are not easily parsed by an LLM for longer sequences
[
42
]
.
In addition, LLM reasoning over low-level actions may not be effective for long-horizon explanations
[
42
]
, unless
|\mathcal{A}|
is finite and small, but this is not generally the case.

Therefore, we define a set of higher-level
macro actions

\mathcal{M}
based on the action space
\mathcal{A}
, e.g.
slow-down
and
change-lane
for AD
[
41
]
.
A macro action is a named program with an applicability condition, e.g.
‘no vehicles in the neighbouring lane’
, tested against a given context observation
o^{i}_{t}
.
If applicable, the macro action specifies a sequence of actions
a^{i}_{t:n}
, e.g. steering and acceleration sequence for lane changing, to execute from the context state until a termination condition is met, e.g.
‘ego vehicle in neighbouring lane’
.
The set of macro actions
\mathcal{M}
may be hand-engineered or learned from data via, for example, program induction
[
43
]
, neural program synthesis
[
44
]
, or time series classification
[
45
]
.
To wrap an observed action sequence into macro actions, written as
\textsc{{Wrap}}(a_{1:t})
, one can check the applicability and termination conditions of all macro actions against the sequence until a match is found.
In our experiments, we test two versions of macro actions:
(1) low-level (
L-Macro
)
: acceleration and steering compared to zero to determine consecutive sequences of acceleration/deceleration and turning left/right, and
(2) high-level (
H-Macro
)
: hand-engineered macro actions, e.g. exit right and change lanes, from
Albrecht et al. 2021
.

The simulator provides counterfactual domain information to the LLM by rolling out various changes to the actions of the agents.
The choice of simulator depends on the domain, but otherwise, we take a broad definition of what can be used.
We only require that we may override agent policies to force certain actions and then roll out states of the environment starting from a joint state
s_{t}
.
This means that most current multi-agent RL training environments with some trained policy are applicable
[
46
]
.
In AXIS, the simulator takes as input the current sequence of ego observations
o^{\varepsilon}_{1:t}
and a query
q
.
In case
q.\texttt{time}\neq t
, we either roll back time by truncating
s_{1:t}
or simulate forward the environment until the starting simulator-time,
\tau
, matches
q.\texttt{time}
.
From
s_{1:\tau}
, the environment is rolled out, overriding the joint agent policy with the queried changes as applicable, until the simulation terminates.
At that point, we return the new ego observations
o^{\varepsilon}_{\tau:n}
and joint action sequence
a_{\tau:n}
, as well as the ego agent rewards
R^{\varepsilon}(s_{\tau:n})
.
In our experiments, we use a 2D driving simulator with a static road layout, a 20 Hz execution speed, and vehicles following either A* search or Monte Carlo Tree Search planning algorithms
[
41
]
.

We facilitate communication between the LLM and the simulator through a set of
queries
, shown in
Table

1

These queries allow the LLM to propose changes to agents’ behaviour and the simulator to interpret those proposals.
A query
q
, e.g.
‘What if the ego vehicle had changed lanes at time 40?’
, consists of a keyword followed by a number of arguments in parentheses, e.g.
whatif
(
\varepsilon,[\texttt{change-lane}],40
).
Arguments are referred to with the notation
q.a
, where
a
stands for the name of the argument.

Verbalisation

We call
verbalisation
, and write
Verbalise
(
\cdot
), the process of converting into text the representations of the environment.
For AXIS, we may verbalise static environment elements (
V_{env}
), e.g. the road layout, the observation sequences (
V_{o}
), the macro actions (
V_{m}
), and the reward signal (
V_{r}
).
An example for each verbalisation element is given in Appendix B.
To verbalise macro actions, their associated names and start and end times are used.
For reward signals, we print the reward components’ names and associated values into text.
In contrast, the observation space
\mathcal{O}
is usually more complex and not, in general, understandable to the LLM directly.
For complex state spaces or long sequences, state filtering
[
47
]
, state abstraction
[
48
]
, or hand-engineering
[
35
]
may be necessary to produce useful verbalisations.
In our experiments, the observation space is sufficiently small, i.e. sequences of tuples in
\mathbb{R}^{4}
, such that we can use string printting methods.

Prompt Templates

We define five prompt templates,

,
context
,

,

, and

prompts, to dynamically create LLM prompts.
Each template contains a number of placeholders, e.g. for the simulation results or the user prompt, which are replaced with the appropriate strings during runtime.
The complete text of templates is given in Appendix C.

4
Evaluation

We test AXIS on the task of motion planning for autonomous driving
[
40
]
, a safety-critical decision-making problem, where explanations may be particularly useful for safety analysis and calibrating trust
[
49
]
.
Unfortunately, the evaluation of explanations is notoriously difficult
[
23
,
21
,
50
,
51
]
.
The perceived utility of an explanation depends not only on its causal content but also on the context and background of people interpreting the explanation
[
24
,
25
,
22
]
.
To mitigate these issues, we use scenario-based evaluation with a novel combination of subjective metrics of user preference and objective metrics of actionability for goal and next action prediction.

Scenarios & User Prompts

We use 10 scenarios with up to 5 vehicles based on previous work
[
41
,
52
,
22
]
in which explanations were to shown to be useful for users.
Scenarios capture tactical driving situations, e.g. lane changing, unprotected turn, lane merging, and roundabout entry, and involve either safety or efficiency-related reactions from an ego vehicle.
Scenarios have three categories: five have normal, rational driving behaviour (rational scenarios #1-5), two contain irrational behaviour from a non-ego vehicle (irrational scenarios #6-7), and three contain occluded vehicles (occlusion scenarios #8-10).
For each scenario, we define up to three user prompts
p_{u}
, e.g.
‘Why did vehicle 0 change lanes left?’
and
‘What would have happened if Vehicle 1 went straight?’
, and generate explanations for each separately.
Full scenario and prompt descriptions are in Appendix A.

Metrics

Unlike previous work in XRL which usually centres on subjective preference and, infrequently, on downstream performance
[
23
]
, we use a novel combination of three metrics which allows the measurement of subjective preferences, perceived correctness, and the objective actionability for improving downstream user performance.
(1) Subjective preference
along four axes following
Hoffman et al. 2023
: perceived completeness, satisfaction, trustworthiness, and sufficient detail of the explanation.
We calculate the geometric mean of the four numbers and report a single score between 1 and 5.

(2) Perceived correctness
, calculated by comparing our expert causal explanation of the scenario, described in Appendix D, to a generated explanation, reported on a scale between 1, completely incorrect, to 5, completely correct.

(3) Goal and next action prediction
, for whether the explanation helps the evaluator perform better on the downstream tasks of overall goal prediction and immediate next action prediction
[
26
]
, reported as accuracies in
[0,1]
.
When presenting aggregate results, we select best-round explanations which have the highest geometric mean of preference and correctness scores across interrogation-synthesis rounds.
We do not use prediction scores for selection because, for individual rounds, the prediction scores are binary 0 or 1.
When reporting aggregate results, we give error bars using standard error of mean.

We design prompt templates for each metric and use Anthropic Claude 3.5
[
54
]
, an LLM not used for explanation generation, as evaluator, i.e. the external reward model
R_{h}
in
Section

2
.
Preference and correctness are measured using 5-point Likert scales.
For goal/action prediction, four pre-selected options are given in random order and we calculate the accuracy of the LLM in selecting the correct goal and action.
Full prompts given to the LLM during evaluation are in Appendix D.

Baselines & Models

We compare against two baselines.

(1) Model only (
ModelOnly
)
, where we give the full initial context to the LLM and ask it to explain the scenario.

(2) No explanation (
NoExp
)
, only applicable for actionability metrics, where we do not provide any explanation to the evaluator, to establish a baseline capacity to predict the agent goal and next action.
We are not aware of relevant previous research that is directly comparable to AXIS as a baseline.
Five LLMs are used to generate explanations and test the robustness of AXIS to the type and size of LLMs: OpenAI GPT-4.1-2025-04-14
[
55
]
, o1-2024-12-17
[
56
]
, DeepSeek-V3-0324
[
57
]
, DeepSeek-R1
[
58
]
, and Meta Llama 3.3-70B-Instruct
[
59
]
.
We tried LLMs up to 7B parameters but results were incorrect, with models only copying text from context for interrogation queries.
For sampling, we use default hyperparameters across all models and set a maximum output token limit of 512 for instruct and 16,384 for reasoning models.
We use
N_{max}=10
maximum rounds in AXIS.

We test elements of the verbalised context, i.e. the road layout, observations, low- and high-level macro actions (4 features), as well as a feature controlling linguistic complexity of the LLM’s output explanation which may be complex or concise (1 feature).

We compare Shapley values for two models: the larger GPT-4.1 and the smaller Llama 3.3-70B, showing our aggregate results and model comparisons in
Figure

2
and per-scenario results in Appendix E.
Based on these, we select the high-level macro actions, complex linguistic content, and observation for larger models, and low and high-level macro actions, and concise linguistic complexity for the smaller model.

.
An example of this is the drop at

5
Related Work & Conclusion

Related Work

In taxonomies of explainable AI
[
63
]
, AXIS is a counterfactual, post-hoc, local explanation algorithm.
Similar work in XRL, especially counterfactual explanation generation, has received significant attention but almost exclusively in the single-agent setting (for a survey, see
[
32
]
).
In the multi-agent setting,
Boggess et al. 2022
introduced policy summarisation and query-based language explanations for multi-agent RL (MARL), extending this work to tackle temporal user queries
[
65
]
. In a different approach,
Heuillet et al. 2022
explored the application of Shapley values
[
60
]
to cooperative MARL, although limited to explaining individual actions.

Three works are most relevant to AXIS.

Admoni et al. 2025
introduce SysLLM, which synthesises global textual summaries of single-agent policies by prompting LLMs to describe behavioural patterns based on a dataset of observed trajectories, showing alignment with expert insights, but their work is limited to simple GridWorld environments.
CEMA by
Gyevnar et al. 2024
explains agent decisions in multi-agent systems using a probabilistic forward model to identify salient causes, performing well in AD evaluations but the requirement of a probabilistic model is not always easy to satisfy.
Finally,
Yang et al. 2025
propose a model-agnostic approach which trains LLMs to explain agent decisions using generative flow matching for per-sentence rewards, producing effective explanations that may improve decision accuracy, but their work also uses a single-agent setting.

Limitations & Future Work

Certain limitations must be considered when interpreting our results.
(1) LLM as external reward model
: While previous work has shown that LLM-based substitutes of crowdsourced human data for explanation evaluation are feasible
[
68
]
, results are preliminary, and the assessment of LLMs, especially on subjective preference, is biased, as our results and previous work have shown
[
62
,
69
]
.
Future work will focus on running a human subjects evaluation for comparison against LLM-based scores.

(2) LLM brittleness in multi-turn conversation
:
AXIS can be thought of as a multi-turn conversation between the LLM and the simulator.
As a result, AXIS is subject to limitations of the underlying LLM, e.g. verbosity, premature ending of conversation, incorrect assumptions, and recency bias
[
61
]
.
We also did not tailor individual prompts for specific LLMs besides our Shapley analysis, and we may see higher scores with better-tuned prompts.

(3) Baseline availability and experimental setup
:
As with almost all work in XRL, our results are limited by a lack of comparable baselines from the literature, which we tried to solve by comparing against LLM-only baselines.
In addition, relevant explanations are domain-dependent, and thus, so are experiments that test them.
In our case, this meant focusing on autonomous driving in experiments, and future work should test generalisation to other domains.

(4) Scaling with number of agents
:
We tested AXIS with up to five agents in highly coupled scenarios with complex continuous action spaces.
However, it is unclear how the method would scale to discrete domains with simpler action spaces where many more agents may be present, e.g. level-based foraging
[
70
]
or warehouse routing
[
71
]
.

Conclusion

This paper presented Agentic eXplanations via Interrogative Simulation (AXIS) which uses LLMs to targetedly explore counterfactual worlds of an observed multi-agent system to generate causal explanations of agent behaviour.
Experiments with 10 autonomous driving scenarios for 5 LLMs showed improved perceived correctness and higher or comparable goal/action prediction accuracy for most models, with AXIS achieving the highest scores for all metrics.
Qualitatively, AXIS captures the causality behind agents’ decisions and provides contrastive explanations that are better aligned with human expectations.
AXIS is a general algorithm for explaining any pre-trained multi-agent policy which has a simulator available, contributing to an increasingly important literature that can help mitigate risks from emergent risks of multi-agent systems.

Appendix E
Shapley Value Analysis

This section describes the methodology and results of the Shapley value analysis presented in the main paper.
As desribed in the main paper in Section 4., we use 5 features for which we calculate their Shapley value contributions to the final correctness score of the explanation.
The features are verbalised aspects of the environment context, and they are:

•

Road Layout
: The static road layout
V_{env}
.

•

Observation
: The observations
V_{o}
.

•

Low-Level Macro Action
: The low-level macro actions, e.g. accelerate, steer left,
V_{a}
.

•

High-Level Macro Action
: The high-level macro actions, e.g. turn right, give way,
V_{ma}
.

•

Linguistic Copmlexity
: The linguistic complexity of the explanation, i.e. concise or complex,
V_{c}
.

Let us denote the set of features as
V=\{V_{1},V_{2},V_{3},V_{4},V_{5}\}
, corresponding to the features above in the same order.
The Shapley value
\phi_{i}
of a feature
V_{i}
is defined as:

\phi_{i}=\sum_{S\subseteq V\setminus\{V_{i}\}}\frac{|S|!(|V|-|S|-1)!}{|V|!}\left(v(S\cup\{V_{i}\})-v(S)\right)

(2)

where
v(S)
is the value, i.e. perceived correctness, of the subset of features
S
and
|S|
is the number of features in the subset.
The Shapley value is a measure of the contribution of each feature to the overall correctness of the explanation.
We calculate
\phi_{i}
for each feature
V_{i}
by evaluating the correctness of explanations generated with all possible subsets of features, then using
Equation

2
to calculate the Shapley value for each feature.
We calculate Shapley values for scenarios #2, #6, and #7, and for the models GPT-4.1 and Llama 3.3-70B.
