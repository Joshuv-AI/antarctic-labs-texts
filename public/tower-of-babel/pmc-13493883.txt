RefactoCNN-system: an optimized deep learning framework for predicting software refactoring opportunities using CNN-based code analysis
Authors: E Lakshmi Prasanna, K Srinivas
Published: 2026

ABSTRACT
AbstractRefactoring is crucial for ensuring the long-term quality, readability, and maintainability of software code in evolving systems. The conventional methods for identifying refactoring are almost rule-based or heuristic-driven and have limitations due to the usage of handcrafted features and shallow structural inspection. Such methods generalise poorly across different codebases and often fail to capture the more abstract semantic similarity of source code. Deep learning has recently become significantly more powerful, enabling it to automate these tasks. However, available models are rarely optimised and do not integrate well with real-world development pipelines. To overcome this limitation, we present RefactoCNN-System, an efficient deep learning-based framework that predicts opportunities for macroscopic refactoring from raw Java source code. Syntax Trees (ASTs) and token sequences are thus used as structured representations of code. System maps them to embedding vectors, which are subsequently fed to a custom-made CNN model. The integration of Bayesian hyperparameter tuning and learning rate scheduling improves the model’s predictive performance. The refactoring suggestions are generated by the mapping engine using heuristics that transform classification outputs into recommendations that are easy for developers to read. RefactoCNN extends a shallow feature-based classifier and handles common architecture adaptation problems such as heterogeneous datasets and automated feature discovery automatically using full deep learning capabilities, as experimental results show that RefactoCNN outperforms traditional machine learning classifiers and existing deep learning baselines when achieving 94.6% classification accuracy, 93.1% precision, 92.3% recall, and 92.7% F1-score on benchmark datasets. Qualitative analysis and examples from practice provide additional support for the system’s practical usability. With a modular, extensible architecture, RefactoCNN serves as a significant resource for automated software maintenance, helping developers proactively manage and improve code quality. Our proposed framework represents a promising direction for improving automated, data-driven refactoring support. Introduction

As software systems become more complex and evolve, maintaining clean, readable, and maintainable code is increasingly required. Refactoring refers to a class of maintenance activities that reorganise existing code without changing its functionality. Traditionally, developers have used either manual inspection or heuristic tools to find promising refactoring opportunities. However, they are usually narrow in focus, subject to human infirmity, and not scalable across large, changing codebases. This has led to increased demand for machine learning and deep learning models to automate refactoring prediction tasks1,2.

There have been some recent studies on using static code metrics, source code smell detection, and lightweight classifiers to predict refactoring1,2. Despite significant advances, most state-of-the-art approaches remain limited in two main respects: they do not generalise well across different programming contexts and rely on hand-crafted features that fail to exploit the rich semantics of source code structure3,4. While syntax-based learning pipelines have proven sufficient with traditional machine learning approaches, we argue that they do not generalise to the multi-target task of code generation, which is both structured and challenging. Also, the feature inputs they are given are often binary, sparse (e.g., one-hot representations), or vector representations (e.g., word2vec and fasttext)4. Deep learning methods, particularly convolutional neural networks (CNNs), have demonstrated significant effectiveness on structured representations of code (e.g., Abstract Syntax Trees (ASTs) and token sequences5 due to their improved abstraction and learning capabilities6.

However, other previously proposed automated methods for recommending refactoring changes have many practical issues that remain unresolved. With these objectives in mind, in this work, the authors propose a complete deep-learning-based methodology referred to as ‘RefactoCNN-System‘(again using original Java code) for the prediction of external acceptable phase potentials. It integrates AST and token-based word embeddings and comes with a simplified model architecture that balances efficiency and versatility: a CNN equipped with a Bayesian hyperparameter optimiser and a mapping engine that is ready to operate in real-world contexts. In addition to improving forecasting ability, this delivery system also supports large encoder outputs that are generalisable across many operational domains.

The main contributions of this research are: (1) a wholly automated end-to-end pipeline from raw Java code to specific refactoring proposals; (2) This involves an automated end-to-end system from original Java code through to specific refactoring suggestions based on AST to CNN. A deep CNN model specially laid out and tuned via sophisticated manipulation strategy; (3) We deliver model verification tests on real-world codebases involving both quantitative evaluation and qualitative case studies; (4) We offer a modularised solution that can be easily plugged into existing development environments or CI/CD pipelines. These features make this research applicable not only to the old-fashioned rule-based approaches to refactoring support but also to data-driven refactoring assistance tools.

Compared to previous code-analysis CNNs that would take only one representation, RefactoCNN performs deployment-oriented dual fusion by late-fusion gating AST-node embeddings with byte-pair token embeddings, then applying temperature scaling to improve actionability through calibrated confidence. It uses a lightweight depthwise-separable CNN backbone with channel squeeze/expand, optimised with Bayesian hyperparameter tuning (kernel widths, strides, dropout) to meet CI latency constraints and achieve sub-40 ms/method CPU inference. We contribute an interpretable rule-mapping engine that maps feature activations to specific refactoring intents (e.g., Extract Method, Rename Variable), and we use ablations (complete vs. no-rules vs. rules-only) to quantify its contribution. In addition to accuracy, we assess cross-project generalisation using LOPO splits and parser robustness on incomplete code settings not often reported in prior CNN-based work to provide a more complete view of reliability and deployability.

While previous studies have investigated CNNs and transformer encoders for understanding source-code, this work introduces a unique formulation optimized for deployment: (i) a dual-stream representation where gated cross-attention over sequence of code tokens and AST paths is applied before convolution, which preserves long-range structure while maintaining locality; (ii) a stride-aware dilated CNN head optimized to the token/statement granularity of the code, delivering transformer-level F1/MCC at a significantly lower latency/VRAM; (iii) a calibrated logit→refactoring mapping that combines temperature scaling and a rule-precedence engine to produce actionable refactorings; and (iv) an integrated explainability+faithfulness suite (SHAP/LIME with deletion/insertion curves) that directly relates developer-meaningful cues to predictions. We demonstrate in Sect. 4.5 that each component contributes significantly to accuracy, robustness, and CI/CD suitability, compared to merely concatenating AST and tokens or running a vanilla CNN on tokens.

The current deep learning methods are either single-code corpus-based, each single-code representation computationally intensive, and with limited generalisation abilities, or large and complex transformer-based models, each requiring a single-code representation. The RefactoCNN-System is a deployment-oriented, lightweight system composed of two code representations, token sequences and in-the-box Abstract Syntax Trees (ASTs) that are seamlessly combined to form a new system. It employs a compact convolutional architecture, optimised via Bayesian hyperparameter adjustment to enhance prediction quality, with low computational demands suitable for CI environments. Also, a rule-based mapping engine converts predictions into human-readable refactoring suggestions that are useful in real-world software maintenance contexts.

Proposed system

To address the limitations identified in prior work, we propose RefactoCNN-System, an end-to-end deep learning framework for predicting software refactoring opportunities from raw Java source code. The system integrates structured code preprocessing, embedding generation, CNN-based classification, and a rule-based recommendation engine to produce actionable refactoring suggestions. In this study, we describe the RefactoCNN system, which aims to predict idea-specific software refactoring automatically. It covers the high-level system architecture, the implemented code-preprocessing pipeline, both embedding and feature-extraction methods, and the CNN-based classification model. It is effective and scalable, as it is custom-designed to learn semantic code patterns and improve prediction performance, and is suitable for refactoring recommendations across broad software projects.

Overview of the RefactoCNN-system architecture

The RefactoCNN-System is a pipeline that directly maps predictions of software refactoring opportunities to raw Java source code. As illustrated in Fig. 1, the system consists of six main modules executed sequentially: code input retrieval, preprocessing, embedding extraction, CNN-based classification, suggested mapping, and output to the user. First, the system accepts Java projects or files in two forms and parses them into abstract syntax trees and token sequences, respectively, with the tools javalang or JavaParser. The input to the RefactoCNN model is embedding vectors with a fixed maximum number of normalised tokens, so only the structured representations need to be converted to fixed-length vectors. Before classifying code text as refactoring or not, a CNN uses this pretrained embedding. The predictions are then translated into actual refactoring suggestions using a heuristic rule engine. Lastly, the output (file name, method context, and suggestion details) is displayed in the CLI (and can also be accompanied by a simple Flask-based web UI). In this sense, the layered structure creates an extensible, readable, and viable solution that can be incorporated into actual software maintenance procedures.

The general layout of the RefactoCNN system is presented in Fig. 1, which shows the data flow and interactions among the system elements for predicting refactoring opportunities. The pipeline begins with the Java Code Input module, to which raw data is provided. It can take input in the form of Java files or a project directory. After that, the Code Preprocessing Module receives these files, and the source code is analysed syntactically by an Abstract Syntax Tree (AST) parser and lexically tokenised by a tokeniser. This yields us an AST and a token stream used to parse into a type-structured entity.

The output from the parsed data is then passed to the Feature Embedding module, where features of discrete tokens and syntactic units are transformed into vector representations in a real-valued space. There are two main components in this module: a submodule for the Token Vectorizer, which maps each token to a high-dimensional embedding, and an Embedding Averager, which averages the token embeddings to produce a fixed-length feature vector. It is easier to pass the input to the CNN model in the same vectorisation format, regardless of the original code’s size or complexity.

The RefactoCNN module is the core of the system: a convolutional neural network that retrieves the necessary variables for classifying embedded vectors and transforms these into a prediction label indicating whether refactoring is needed or not. The CNN module interacts closely with the Training Engine, which manages the model’s training lifecycle, including validation and testing. After doing that, it saves the model weights to the Trained Model File (a .pt or .pt file). In this case, you can save the model in h5 format so that it can be load during the inference time.

Each module interacts sequentially, ensuring a smooth transformation from raw code input to structured embeddings and final classification output.

The Refactoring Suggestion Engine takes as input prediction labels from the CNN. Lastly, the stable-labels are mapped to binary predictions by the engine utilizing a heuristics function and modelled into refactoring suggestions that can be interpreted. These recommendations are then forwarded to the Output Interface, which may either be a command-line viewer or web-based Flask viewer) and constructs into a recommendation to the developer in terms of file name, method identifier and the text to be included in the recommendation. It is also this instillation of architectural granularity that solidifies this dataflow (all these design patterns go through the pipeline) and gives a modular separation of concerns so that specific components e.g. various embedding methods, or proposal heuristics can be precisely replaced with their newer incarnations whilst still having a monolithic pipeline to deploy. Key innovations of the RefactoCNN-system

The state-of-the-art in automated software refactoring prediction also includes some methodological improvements from RefactoCNN-System, to the best of our knowledge. Unlike conventional rule-based or metric-driven systems, which rely on manually engineered features, the proposed framework is data-oriented and applies deep learning to directly acquire semantic information from representations of the source code. This method blends structural and lexical data in the textual form of a Java program representation, providing greater resilience when applying a refactoring opportunity to heterogeneous codebases.

A very significant aspect of the created framework is the compatibility of two code representations: token sequences and Abstract Syntax Trees (ASTs). Token embeddings are also helpful for capturing the semantics of lexical and contextual information in the source code, and the AST of the program can encode the syntactic dependencies among program elements. The system improves the accuracy of refactoring prediction by combining two complementary representations: one that reflects the structural properties and the other the semantic properties of the software code.

The other distinctive aspects of the framework include the development of a lightweight CNN architecture for analysing software code. Transformer-based models are favoured for their performance in source code understanding tasks, although they typically consume significant resources and incur high inference latency. Conversely, unlike the RefactoCNN architecture, which involves convolutional layers, the approach can learn local code patterns at a lower level of complexity and inference time, which is preferable in actual applications when deployed to large-scale software repositories and continuous integration infrastructure.

Some element of Bayesian hyperparameter optimisation is also incorporated into the framework, in which optimal values for particular model parameters, such as learning rate, dropout rate, and convolutional filters, can be automatically found. This optimisation method enables the model to converge fairly and achieve greater generalisation without manual tuning. Finally, in addition to the deep-learning model, the RefactoCNN-System also provides a mapping engine that transforms predictions from machine-learning models into interpretable, useful refactoring suggestions, e.g., Extract Method, Rename Variable, etc. This component bridges the gap between machine learning model predictions and developer support, thereby enhancing the practicality of the automated software maintenance system presented.

To achieve compatibility with convolutional neural networks, we pre-order-traverse the abstract syntax tree to linearize it. In spite of the fact that this transforming process does not retain the complete two-dimensional branching structure of the original tree, it still contains desirable local structural configurations such as parent-child ordering, subtree organisation, and sequences of syntactic roles. This design decision purposely sacrifices complete structural fidelity for the sake of computational efficiency and stable fixed length representations necessary for CNNs to process the data. Since flattening AST sacrifices some hierarchical information, we jointly fuse the simplified AST representation with token-level embeddings, such that the model would gain complementary lexical and syntactic cues during training.

Even though AST flattening facilitates the fixed-length sequential representation needed to efficiently enable the application of CNNs, it also flattens the original tree structure into a linear sequence. This may lead to the loss of some hierarchical parent–child relationships and long-range structural dependencies. It is a trade-off between structure completeness and computational efficiency. In RefactoCNN, this shortcoming is alleviated by using flattened AST features in conjunction with token-level features that enables the model to learn both syntactic patterns and lexical context at low inference latency.

During AST extraction on real-world repositories, we may encounter ill-formed or incomplete code (e.g., unclosed blocks or merge conflicts). RefactoCNN employs (i) tolerant parsing with best-effort recovery; (ii) an error-aware mask to label uncertain nodes/edges so that they are not selected in high-weight paths; (iii) subtree imputation to fill small gaps and a fall back to token-only when unusable trees are produced; (iv) subtree dropout to make embeddings sensitive to missing structure at training-time. Additionally, we further pretrain on syntactically corrupted snippets (deleted braces, truncated methods) and report robustness during results section: F1/MCC degrade ≤ 2–4% for 5–15% corruptions, indicating graceful performance under realistic parsing noise.

Performance metrics

To assess the classification performance of the proposed RefactoCNN model, a range of metrics that capture multiple dimensions of performance were used, largely because the software refactoring datasets are challenging due to class imbalance.

Correctness is the accuracy, defined as the ratio of correct instances to the sum of predicted instances and correct instances. However, it should be taken with a pinch of salt, given that we may be dealing with an imbalanced dataset, in which case the classes have different sizes. The metric precision measures the ratio of correctly identified positives to all predicted positives; it indicates how many false positives the model avoids. In contrast, recall (or sensitivity) is the proportion of true positives that the model retrieves, representing its ability to identify all refactorings. F1-score, which is also just known as f1, is the harmonic mean of precision and recall, so we have a tradeoff between the two: precision and recall. This is also useful when class distributions are imbalanced, as it weighs false positives and false negatives equally.

An additional calculation of the Matthews correlation coefficient (MCC) was performed to assess classification quality. MCC is a splendid measure to work with because it characterizes each of the four groups (TP, FP, TN, FN) and yet provide a measure of the related value between − 1, => +1[+ 1 is perfect, 0 random and − 1 full opposite] This measure applies to imbalanced problems of binomial classification since it works with all the classes of the confusion matrix without giving one of the classes preference over Further on, to gain a closer perspective of finding misclassifications and improve the model based on that, confusion matrices were additionally directed towards the aspect of viewing how the predictions were allocated across the other classes as well. Hence, these metrics are included in the evaluation framework to ensure that the performance of the RefactoCNN software refactoring prediction model is assessed properly and fairly.

The choice of these metrics is because refactoring prediction may be characterised by class imbalance and dissimilar costs of false positives and false negatives. Precision is a measure of the occurrence of the proposed refactorings, recall is a measure of what is referred to as the capacity to accept reality of refactoring opportunities, and F1-score is a reconciliation of the two factors. MCC also offers a balanced assessment that includes all the aspects of the confusion matrix.

Ablation studies

We conduct ablation studies to systematically analyse the contribution of each core component of the RefactoCNN framework. We considered three key factors: (i) types of input embedding layer, (ii) the number of convolution layers, and (iii) hyperparameter tuning strategies.

For embedding evaluation between AST nodes, token-level embeddings were used, and AST-based node embeddings were used to train the models. Findings showed an approximate 4.3% increase in F1-score with AST-based embeddings compared to token-only embeddings, indicating that structural syntax may provide richer context for refactoring decisions.

We see from the ablation results that all architectural components lead to the final model performance. AST-based embeddings supply a richer structural context than token-only embeddings, while the three-layer CNN architecture strikes a sweet spot between working memory and overfitting. In addition, convergence stability and predictive performance are consistently improved by Bayesian hyperparameter tuning compared with manual or grid-based tuning strategies.

Cross-language generalisation (protocol, findings, and implications)

Even though we primarily target Java in our experiments, many refactoring cues, such as naming regularity, long methods, duplicated blocks, and deeply nested conditionals, are language-independent. For multi-language comparability, we compare RefactoCNN on extra languages via a plug-in parsing interface that separates language-specific front ends from the model. The token stream uses subword BPE to avoid vocabulary drift between languages, and the structural stream takes parser-agnostic ASTs, normalising them to a UAST-style schema via node remapping, depth caps, statement-path sampling, and light canonicalisation. RefactoCNN can be extended to other languages, such as Python and C++, without changing its architecture, thanks to out-of-the-box Tree-Sitter grammar adapters.

The evaluation consists of three scenarios that reflect plausible paths of adoption. Zero-Shot Model Transfer: The test for inherent transfer is done directly on the target language; the model was trained on Java, so it is in a zero-shot regime. In the Few-Shot regime, only a small subset of target-language data (1%− 10%) is used for model adaptation. Whole-fine-tuning regime: training is performed entirely in the target language. The only splits are at the project level to avoid cross-file leakage. Metrics were performed the same way as in Sect. 4.4, including Accuracy, Precision, Recall, F1, MCC, and Expected Calibration Error while keeping preprocessing techniques, batch sizes, and hardware identical. Discussion

As I explained in my previous post, predicting refactoring opportunities is one of the most serious and important problems we face in modern software maintenance. However, the task remains largely unsolved due to the scarcity of reliable, broadly generalizable models capable of interpreting source code semantics. Heuristic tools, rule-based engines, etc. However, they are not scalable for detecting instances, because they do not capture all structural details in complex, arbitrarily large codebases. Furthermore, previous machine learning approaches are limited by their feature representations: they rely on simplistic manual metrics or shallow learning methods, which become increasingly challenging to scale as the project grows.

This could be addressed by using deep learning, especially convolutional neural networks, which have outperformed traditional methods on most pattern recognition tasks. Nevertheless, it relies more on preprocessing and encoding schemes that allow these to be translated into source code. To alleviate this discrepancy, we introduce the RefactoCNN-System. The entire Deep Learning system at this company converts meaningful abstract representations of Java programs directly from their source code. It also determines the pattern in discrimination required to predict code refactoring.

We employ AST and token-based embeddings, a feed-forward CNN Architecture with optimised hyperparameter tuning via Bayesian optimisation, and a mapping engine that translates classification outputs into actionable recommendations for developers. Based on several quantitative and qualitative evaluations we conducted, the model appears promising in terms of classification performance, generalizability to other projects, and real-world relevance, as it recognises numerous refactoring patterns (e.g., Extract Method, Rename Variable).

Unlike existing deep learning methods for code analysis, our approach focuses on practical applicability and the interpretability of results. Although transformer-based models, like CodeBERT and GraphCodeBERT, perform better, they also demand a much bigger scale of computation. On the contrary, the new architecture maintains equivalent predictive performance and requires an order-of-magnitude fewer parameters and inference time. Moreover, by incorporating a rule-based mapping engine, our solution can convert model outputs into actionable refactoring recommendations, which have largely been neglected in previous deep learning-based refactoring prediction systems.

We alleviate some of the limitations of previous work (e.g., overfitting to project-specific patterns, low generalizability) by relying on a data-driven, generalizable architecture rather than a rule-dependent system. Our implementation is also scalable and provides a stable runtime performance, enabling practical adoption in the software development pipelines.

Compared to transformer-based approaches, the proposed framework provides a better trade-off between accuracy and deployment efficiency.

Our findings can guide software quality assurance, automated maintenance and tool-assisted programming education. The modular design of RefactoCNN also encourages future work regarding hybrid or explainable AI extensions. Limitations of the current study are outlined in Sect. 5.1.

Limitations of the study

The advantages of the RefactoCNN-System are also present; however, not everything is perfect. Although we have trained the model on only a small subset of refactoring patterns (e.g., Extract Method, Rename Variable), it may not include more advanced refactorings that involve significant structural transformations. Second, it is biased because it relies on already labelled datasets that are not representative of the entire spectrum of terror in the real-world codebase. Third, it provides low explainability of the offer, which makes it difficult for the developer who desires to extract the foundation of some proposition, as amenable to more refactoring types, semi-supervised learning, generalisation, and to expand explainable AI further to supply the transparency of prognostication.

The use of a linearised AST representation is a significant drawback of the proposed method, as it fails to capture complete long-range or hierarchical dependencies in tree-based source code. The structures of graph-based neural networks or Transformer-like models could prove more efficient at preserving relationships among overall codes due to their design. However, their computational and memory costs are also much higher. The RefactoCNN framework is a low-overhead model designed for deployment and therefore focuses on inference speed, scalability, and CI/CD compatibility, with minimal overhead. Experimentally demonstrated as a trade-off, the approach offers physical predictive power at the cost of latency and resource consumption, and thus can be applied to large-scale software maintenance pipelines.

There are obvious weaknesses in the capacity of our proposed structure, and, in any case, it is limited to explicitly representing long-term semantic links between distant parts of code; these are better represented by Transformer-based models (e.g., CodeBERT). Self-attention mechanisms are very useful for relating relatively distant code aspects, but they are extremely computationally costly and memory-intensive. Instead, RefactoCNN is more about deployment efficiency and scalability, providing a viable trade-off between the benefits of representation and applicability (in real-time) to CI/CD and large-repository settings.

Trade-offs between lightweight CNN architecture and structure-aware models

RefactoCNN-System employs a low-complexity CNN-based architecture that effectively balances predictive performance and the efficiency needed for deployment. Convolutional models are powerful at discovering local syntactic and semantic patterns. However, they generally do not explicitly retain full hierarchical code structures or long-range dependencies as graph neural networks or Transformer-based architectures do. While structure-aware models like GNNs and CodeBERT require considerably more computational effort, storage, and inference time, they can represent much more global context and sophisticated relations between code.

The outlined framework purposely emphasises scalability, inference time, and CI/CD compatibility to serve as a mechanism for integrating into large, continuous software maintenance workflows. We experimentally validate that RefactoCNN maintains state-of-the-art performance compared to structure-aware baselines while incurring a significantly lower global computational budget. Such a trade-off is a practical design decision that prioritises the prototype’s real-world deployability over total structural fidelity.

Conclusion and future work

We propose RefactoCNN-System, a learning-based framework that predicts the best possible software refactoring opportunity using text data, such as raw Java code. The system directly detects code fragments needing refactoring and suggests them to the developer using ASTs, token embeddings, and a tailored CNN architecture. This approach is particularly resilient to the core deficiencies of feature engineering, generalisation, and adaptability seen in previous heuristics and shallow learning techniques, enabling it to be effective across a wide variety of codebases. It uses Bayesian hyperparameter tuning to optimise reachable modular components of the system for predictive performance and computational efficiency. The model performs better than the baselines we find useful in our experiments. It was shown to be practically useful through four case studies, which contributed to actionable recommendations for refactoring. Notably, it can even be scaled to larger projects with a small runtime footprint, which is why it is a low entry point to deployments in state-of-the-art development environments. Nevertheless, limited coverage of patterns and incomparable predictions remain an unresolved issue (Sect. 5.1). All this is good material for use in other work. This framework can be expanded to study additional types of refactoring, such as architectural and behavioural refactorings. By employing explainable AI modules, they may also enhance developer trust and provide better decision assistance. Such advances could range from merging classical and quantum models to cross-language refactoring support to semi-supervised learning methods that minimise the need for labelled datasets. Finally, we present RefactoCNN-System, a proof-of-concept system that takes first steps towards intelligent automated refactoring and provides a solid Baseline for future research leveraging deep learning in software maintenance and code quality improvement applications. Future work may investigate tree-aware CNNs, graph neural networks, or transformer-based structural encoders to preserve richer AST hierarchy while retaining deployment efficiency.
