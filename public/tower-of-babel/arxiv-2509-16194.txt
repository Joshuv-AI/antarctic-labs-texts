Abstract

Instead of removing individual data points, our model allows discarding up to z z subsets from a given family of candidate outlier sets ℋ \mathcal{H} . 1.
Introduction

Clustering is a fundamental technique in computer science, widely applied in domains such as social network analysis, search result grouping, medical imaging, and image segmentation. By partitioning data into coherent groups, clustering helps uncover hidden structures and relationships that inform downstream tasks like classification, anomaly detection, and recommendation.

However, real-world data is often noisy due to human error or data integration issues, and many classical clustering objectives are not robust to such noise. For instance, in
k
-center clustering, where the goal is to minimize the maximum distance of any point to its closest center, a few outlier points can drastically alter the resulting clusters, potentially leading to misleading interpretations.
To address this, prior work has studied robust versions of clustering, notably
k
-center clustering with
z
outliers. Given a metric space
(P,\mathsf{dist})
, where
P
is a set of elements and
\mathsf{dist}
a distance metric, the objective is to select
k
centers and remove
z
outliers so as to minimize the maximum distance from any remaining point to its closest center. This problem is known to be
\mathsf{NP}
-complete, but efficient constant-factor approximation algorithms exist
(
charikar1999constant
;
charikar2003better
)
.

In this work, we introduce a novel and natural generalization of this problem:
k
-center clustering with
z
set outliers
. Instead of removing individual outlier points, the goal is to remove
z
subsets from a given family
\mathcal{H}\subseteq 2^{P}
of candidate outlier sets. This formulation captures practical scenarios in data cleaning, fault-tolerant systems, and federated data analysis. For example, each subset might represent data from a single source in a data integration task, or a group of measurements from a single sensor in a sensor network. The goal is to discard entire sources that may be faulty or unreliable, rather than identifying individual points.

Consider the following example showing an instance of our problem in the geometric case where sets are represented as hyper-rectangles.
Transactions or user activities are embedded as points with features like (price, quantity, time, store location).
Hyper-rectangles naturally model ranges of values, e.g., Price range:
[10,20]
, Time window:
[1\textsf{pm},3\textsf{pm}]
. So a rectangle corresponds to all transactions in a spatio-temporal range. Using an ML classifier a data analyst can identify a set of potential fraudulent patterns or promotion windows represented as hyper-rectangles. For example, all transactions with price
[0,1]
that took place between
[1\textsf{am}-2\textsf{am}]
are likely spam or test transactions.
The goal is to exclude up to
z
suspicious rectangles to reveal meaningful transaction patterns/clusters.

We present the first approximation algorithms for this problem, which we formalize under multiple settings: general metric spaces with arbitrary subsets, and geometric settings where points lie in
\mathbb{R}^{d}
and outlier sets correspond to axis-aligned hyper-rectangles. Our algorithms offer tri-criteria approximations: we return at most
2k
centers and up to
2fz
outlier sets from
\mathcal{H}
, while achieving a constant-factor approximation in clustering cost, where
f
is the maximum number of sets an element belongs to. While
f
can be large in theory, it is often small in practical settings.
We also show that if the unique game conjecture is true, there is no hope to design a polynomial time algorithm that returns
k
centers,
(f-\zeta)z
outlier sets, having any sublinear approximation on the clustering cost, where
\zeta>0
is any positive number.
Our algorithms run in near-quadratic time for general metrics and near-linear time in the geometric setting. These results offer robust and scalable methods for clustering with structured noise.

Finally, we show how this model can capture relational clustering problems. In relational databases, data is stored across multiple tables, and complete information is only revealed through joins.
This is the standard formulation in real database systems
(
link1
;
link:relational
)
.
We define two versions of relational
k
-center clustering with outliers: one where outliers are tuples in the join result, and another where outliers are input tuples whose removal affects the join. The former reduces to the relatively well-studied problem of
k
-center clustering with outliers
whereas the latter reduces to geometric
k
-center clustering with set outliers problem introduced in this paper.
We provide new approximation algorithms for both these variations, thus establishing a bridge between robust clustering and relational data management.

To further motivate relational clustering with outliers, consider a crowdsourcing scenario where data is aggregated from multiple online sources and stored in a relational database.
A data analyst may want to cluster the results of a join query to construct a classifier (unsupervised learning). However, even a handful of erroneous tuples (outliers) in one table can lead to arbitrarily large errors in k-center clustering on the join result. This problem is particularly relevant in crowdsourcing, where identifying and mitigating erroneous data via cleaning techniques is a central challenge
(
chu2015katara
)
. Efficient algorithms for k-center clustering with outliers in the relational setting are therefore essential.

Notation and Problem Definition

Let
(P,\mathsf{dist})
be a metric space where
P
is a set of elements,
\mathsf{dist}
is a metric function and
\mathsf{dist}(p,q)
denotes the distance between elements
p,q\in P
.
For a set of elements
P
and a subset of centers
C\subseteq P
, let
\rho(C,P)=\max_{p\in P}\min_{c\in C}\mathsf{dist}(p,c)
be the
clustering cost
defined as maximum distance of an element in
P
from its closest center in
C
. The
k
-center clustering
problem is a well-studied problem where given
(P
,
\mathsf{dist})
, and a parameter
k
the goal is to compute a set
C\subseteq P
with
|C|\leq k
such that the cost
\rho(C,P)
is minimized.
Prior work has also studied the
k
-center clustering with outliers
problem where given
P
,
\mathsf{dist}
, and two parameters
k,z
the goal is to compute a set of centers
C\subseteq P
with
|C|\leq k
and a set of outliers
H\subseteq P
with
|H|\leq z
, such that
\rho(C,P\setminus H)
is minimized.
Let
\rho^{*}_{k,z}(P)
be the cost of an optimal
k
-center clustering of
P
with
z
outliers.

In the paper, we introduce some natural extensions of

k
-center clustering with outliers problem. We first define the
k
-center Clustering problem with Set Outliers
, or
\mathsf{CSO}
in short, assuming that
\mathsf{dist}
is any general metric function.

Definition 1.1 (
\mathsf{CSO}(P,\mathcal{H},k,z)
).

Given a set
P
of
n
elements, a family
\mathcal{H}
of
m
subsets of
P
, where
every element in
P
belongs to at least one set in
\mathcal{H}
, and two integer positive parameters
k,z
, the goal is to compute a set of centers
C\subseteq P
with
|C|\leq k
and a family
H\subseteq\mathcal{H}
of outlier sets with
|H|\leq z
and
C\cap(\bigcup_{h\in H}h)=\emptyset
such that the cost excluding the points covered by outliers
\rho(C,P\setminus(\bigcup_{h\in H}h))
is minimized.

Let
\rho^{*}_{k,z}(P,\mathcal{H})
be the cost of an optimal solution of
\mathsf{CSO}(P,\mathcal{H},k,z)
.
Throughout the paper we use the notation
f
to denote the maximum number of sets that a point belongs to, i.e.,
f=\max_{p\in P}|\{h\in\mathcal{H}\mid p\in H\}|
.
When we say that a valid solution
C,H
is computed for
\mathsf{CSO}(P,\mathcal{H},k,z)
we mean that
C\subseteq P
,
H\subseteq\mathcal{H}
and,
C\cap(\bigcup_{h\in H}h)=\emptyset
.
An algorithm returns a
(\mu_{1},\mu_{2},\mu_{3})
-approximation for the
\mathsf{CSO}(P,\mathcal{H},k,z)
problem if it returns a valid solution
C,H
with
|C|\leq\mu_{1}\cdot k
,
|H|\leq\mu_{2}\cdot z
, and
\rho(C,P\setminus(\bigcup_{h\in H}h))\leq\mu_{3}\cdot\rho^{*}_{k,z}(P,\mathcal{H})
.

We consider different versions of the
\mathsf{CSO}
problem. Recall that in the most general one,
P
is a set of elements in a general metric space and every set in
\mathcal{H}
is an arbitrary subset of
P
. We distinguish into cases where every element in
P
lies in one or multiple sets in
\mathcal{H}
, i.e.
f=1
or
f>1
. Furthermore, we consider the geometric case where
P
is a set of points in
\mathbb{R}^{d}
,
\mathsf{dist}
is the Euclidean distance, and
\mathcal{H}
is a set of hyper-rectangles in
\mathbb{R}^{d}
. In this case every rectangle

defines a subset

. More formally, we define the
Geometric
k
-center Clustering with rectangular Outliers
, or
\mathsf{GCSO}
in short.

Definition 1.2 (
\mathsf{GCSO}(P,\mathcal{R},k,z)
).

Given a set
P
of
n
points in
\mathbb{R}^{d}
, a set
\mathcal{R}
of
m
hyper-rectangles in
\mathbb{R}^{d}
, where
d
is a constant and every point in
P
lies in at least one hyper-rectangle in
\mathcal{R}
, and two integer positive parameters
k,z
, the goal is to compute a set of centers
C\subseteq P
with
|C|\leq k
and a set
R\subseteq\mathcal{R}
of hyper-rectangles as outliers with
|R|\leq z
and
C\cap(\bigcup_{\square\in R}\square\cap P)=\emptyset
, such that the cost excluding points covered by outliers

Let
\rho^{*}_{k,z}(P,\mathcal{R})
be the cost of an optimum solution of
\mathsf{GCSO}(P,\mathcal{H},k,z)
.
When we say that a valid solution
C,R
is computed for
\mathsf{GCSO}(P,\mathcal{R},k,z)
we mean that
C\subseteq P
,
R\subseteq\mathcal{R}
and,
C\cap(\bigcup_{\square\in R}\square\cap P)=\emptyset
.
An algorithm returns a
(\mu_{1},\mu_{2},\mu_{3})
-approximation for the
\mathsf{GCSO}(P,\mathcal{R},k,z)
problem if it returns a valid solution
C,R
with
|C|\leq\mu_{1}\cdot k
,
|R|\leq\mu_{2}\cdot z
, and
\rho(C,P\setminus(\bigcup_{\square\in R}\square\cap P))\leq\mu_{3}\cdot\rho^{*}_{k,z}(P,\mathcal{R})
.

If
k,z
are clear from the context, we write
\mathsf{CSO}(P,\mathcal{H})
,
\mathsf{GCSO}(P,\mathcal{R})
.
Interestingly, as we will see later the

-center problem with outliers.

Join Queries.

Let
{\mathbf{R}}
denote a database schema with
g
relations
R_{1},\ldots,R_{g}
and let
{\mathbf{A}}
denote the set of
d
attributes. Each relation
R_{i}
has a subset of attributes
{\mathbf{A}}_{i}\subseteq{\mathbf{A}}
.
Let
{\texttt{dom}}(A)
denote the domain of attribute
A\in{\mathbf{R}}
.
We assume that all attributes have the domain
\mathbb{R}
of reals.
A database instance
\mathbf{I}
consists of the set
\{R_{i}^{\mathbf{I}}\}
of relational instances, where each
R_{i}^{\mathbf{I}}
is a set of tuples over the domain
\mathbb{R}^{|{\mathbf{A}}_{i}|}
.
When the context is clear, we will drop the superscript
\mathbf{I}
, and simply refer to relation instance
R_{i}^{\mathbf{I}}
as relation
R_{i}
. Let
|\mathbf{I}|=N
. We study all our problems in the data complexity, i.e.,
g,d=O(1)
, while
N
is large.
For a set of tuples
X
over a subset of attributes
A_{X}\subseteq{\mathbf{A}}
and a set of attributes
Y\subseteq{\mathbf{A}}
, the operator
\pi_{Y}(X)
returns the projection of every tuple
t\in X
on the attributes
Y\cap A_{X}
. Notice that the projection is defined as a set so
\pi_{Y}(X)
does not contain duplicates.
We consider
join queries
:

\mathcal{Q}:=R_{1}\Join R_{2}\Join\cdots\Join R_{g}
.
The result of
\mathcal{Q}
over database instance
\mathbf{I}
is defined as

\mathcal{Q}(\mathbf{I})=\bigl\{t\in\mathbb{R}^{d}\bigm|\forall R_{i}\in{\mathbf{R}},\pi_{{\mathbf{A}}_{i}}(t)\in R_{i}\bigr\}
.
Note that each tuple in
\mathcal{Q}(\mathbf{I})
is essentially a point in
\mathbb{R}^{d}
and it might be the case that
|\mathcal{Q}(\mathbf{I})|=O(N^{\mathbbm{p}(\mathcal{Q})})\gg N
, where
\mathbbm{p}(\mathcal{Q})
is the fractional edge cover of
\mathcal{Q}

(
atserias2013size
)
.
A join query is acyclic
(
beeri1983desirability
;
fagin1983degrees
)
if there exists a tree
\mathcal{T}
, called a
join tree
of
\mathcal{Q}
, where
the nodes of
\mathcal{T}
are
R_{1},\ldots,R_{g}
, and for each attribute
A\in\cup_{i\in[m]}{\mathbf{A}}_{i}
, the set of nodes whose attributes contain
A
form an edge-connected subtree of
\mathcal{T}
.

Relational
k
-center clustering with outliers

The standard relational
k
-center clustering (without outliers) has been defined in
(
agarwal2024computing
;
chen2022coresets
)
.
Given a database instance
\mathbf{I}
, a join query
\mathcal{Q}
, and a parameter
k
the goal is to compute a set
C\subseteq\mathcal{Q}(\mathbf{I})
with
|C|\leq k
such that
\rho(C,\mathcal{Q}(\mathbf{I}))
is minimized.
In this paper, we define the problem of relational
k
-center clustering with outliers. There are two meaningful and practical definitions of this problem. In the first one outliers are tuples in the join results, while in the second one outliers are tuples from the input database instance.
For every problem in the relational setting we assume that
\mathsf{dist}
is the Euclidean distance.

We define the
k
-Center Clustering with Tuple-Outliers
problem, or
\mathsf{RCTO}
in short. In this case, outliers are tuples from the input database
\mathbf{I}
.

Definition 1.3 (
\mathsf{RCTO}(\mathcal{Q},\mathbf{I},k,z)
).

Given a database schema
{\mathbf{R}}
, a database instance
\mathbf{I}
of size
O(N)
, a join query
\mathcal{Q}
, and two integer positive parameters
k,z
, the goal is to compute a set
S\subseteq\mathcal{Q}(\mathbf{I})
with
|S|\leq k
and a set
T\subseteq\mathbf{I}
with
|T|\leq z
and
S\subseteq\mathcal{Q}(\mathbf{I}\setminus T)
, such that
\rho(S,\mathcal{Q}(\mathbf{I}\setminus T))
is minimized.

Let
\hat{\rho}^{*}_{k,z}(\mathcal{Q}(\mathbf{I}))
denote the cost of the optimum solution for the
\mathsf{RCTO}
problem.
When we say that a valid solution
S,T
is computed for
\mathsf{RCTO}(\mathcal{Q},\mathbf{I},k,z)
we mean that
S\subseteq\mathcal{Q}(\mathbf{I})
,
T\subseteq\mathbf{I}
and
S\subseteq\mathcal{Q}(\mathbf{I}\setminus T)
.
An algorithm returns a
(\mu_{1},\mu_{2},\mu_{3})
-approximation for the
\mathsf{RCTO}(\mathcal{Q},\mathbf{I},k,z)
problem if it returns a valid solution
S,T
with
|S|\leq\mu_{1}\cdot k
,
|T|\leq\mu_{2}\cdot z
, and
\rho(S,\mathcal{Q}(\mathbf{I}\setminus T))\leq\mu_{3}\cdot\hat{\rho}^{*}_{k,z}(\mathcal{Q}(\mathbf{I}))
.

We also study a variation of
\mathsf{RCTO}(\mathcal{Q},\mathbf{I},k,z)
where we only allow outliers from the tuples of one specific relation. Without loss of generality, assume that
T\subseteq R_{1}
.
This is common in practice, as we might have collected data in
R_{1}
from an untrustworthy source, while the remaining tables in
{\mathbf{R}}
come from trustworthy sources.
Let
\mathsf{RCTO1}(\mathcal{Q},\mathbf{I},k,z)
be the
\mathsf{RCTO}(\mathcal{Q},\mathbf{I},k,z)
problem where
T
should be a subset of
R_{1}
.
Let

\hat{\rho}^{*}_{k,z,1}(\mathcal{Q}(\mathbf{I}))
denote the cost of the optimum solution for the
\mathsf{RCTO1}
problem.
When we say that a valid solution
S,T
is computed for
\mathsf{RCTO1}(\mathcal{Q},\mathbf{I},k,z)
we mean that
S\subseteq\mathcal{Q}(\mathbf{I})
,
T\subseteq R_{1}
and
S\subseteq\mathcal{Q}(\mathbf{I}\setminus T)
.
An algorithm returns a
(\mu_{1},\mu_{2},\mu_{3})
-approximation for the
\mathsf{RCTO1}(\mathcal{Q},\mathbf{I},k,z)
problem if it returns a valid solution
S,T
with
|S|\leq\mu_{1}\cdot k
,
|T|\leq\mu_{2}\cdot z
, and
\rho(S,\mathcal{Q}(\mathbf{I}\setminus T))\leq\mu_{3}\cdot\hat{\rho}^{*}_{k,z,1}(\mathcal{Q}(\mathbf{I}))

As we show later, an instance of the

This connection is conceptually interesting: a problem defined as clustering with tuple outliers in the relational setting can be naturally reformulated as a clustering problem with set outliers in the standard computational setting.

Related work

Clustering is a fundamental problem in computer science with applications in various domains such as community detection, recommendation systems, and dimensionality reduction
(
rokach2005clustering
)
.
There are multiple clustering objective functions such as
k
-center (minimize the maximum distance from a center)
k
-median (minimize the sum of distances from every point to its closest center), and
k
-means (minimize the sum of square distances from every point to its closest center). While the problems are
\mathsf{NP}
-hard even in the geometric setting (in
2
-dimensions) there are efficient constant approximation factors that run in polynomial time
(
har2003coresets
;
charikar1999constant
;
krishnaswamy2018constant
)
.

Clustering with outliers is a well studied problem
(
chen2008constant
;
agrawal2023clustering
)
. For
k
-center clustering with outliers Charikar et al.
(
charikar2001algorithms
)
described a
3
-approximation algorithm that runs in polynomial time. Later, Charikar et al.
(
charikar2003better
)
showed a sampling-based method for the
k
-center clustering with outliers that runs in the streaming setting. Interestingly, they also show that running the more expensive algorithm from
(
charikar2001algorithms
)
on a sufficiently large number of samples from the input set, returns a constant approximation to the
k
-center clustering with outliers.
The problem of

-center clustering with outliers has been studied under various settings and models, such as MPC, streaming, distributed, dynamic, sliding window, and fairness models
(
de2023k

malkomes2015fast
;
ceccarello2019solving
;
chan2022fully

;
amagata2024fair
)
.
While clustering with outliers is well-studied, it is unclear how to extend these algorithms to

-center clustering with set outliers.

Faster Algorithms for Practical Use Cases.
Motivated by practical applications in data cleaning and relational clustering, we study several specializations of

) and the geometric version

2.
Clustering with set outliers

We begin our discussion by noticing an interesting connection between the
\mathsf{CSO}
and the classic
set cover
problem. Let
D
be the sorted list of all pairwise distances between elements in
P
. Observe that the optimal clustering cost
\rho_{k,z}^{*}(P,\mathcal{H})
is one of the values in
D
, so we can ‘guess’ this
optimal value by binary searching over all
r\in D
. For a given
r\in D
, suppose we construct a collection
\mathcal{C}
of
n
sets, one for each
p_{i}\in P
as center and consisting of all
p_{j}
such that
\mathsf{dist}(p_{i},p_{j})\leq r
. Therefore, we now have two collections of sets:
\mathcal{C}
and
\mathcal{H}
and the
\mathsf{CSO}
problem is essentially the same as selecting at most
k
sets from
\mathcal{C}
and at most
z
sets from
\mathcal{H}
that cover all elements in
P
.
One approach to solve
\mathsf{CSO}
is by extending traditional approximation algorithms for set cover in this setting but that will likely result in a
\log n
approximation on both number of centers and outliers
(
dehghankar2024fair
)
.
Interestingly, as shown next, the set-cover problem can also be reduced to
\mathsf{CSO}
demonstrating that the difficulty of
\mathsf{CSO}
comes from the structure of outlier sets and there is no hope for efficient approximation algorithms in the general case.
We describe our hardness construction below and design efficient (and in some cases near-optimal) approximation algorithms in subsequent sections.

2.1.
Hardness

We show an inapproximability result for the
\mathsf{CSO}(P,\mathcal{H},k,z)
problem: There is no polynomial time algorithm that returns a valid solution
C,H
with a sublinear approximation on the cost of the objective function, where
|H|\leq(f-\zeta)z
, for any
\zeta>0
, if the unique games conjecture is true.

Let
\mathsf{SC}(X,\mathcal{Y})
be an instance of the set-cover problem where
X
is a set of
n^{\prime}
elements and
\mathcal{Y}
is a family of
m^{\prime}
subsets of
X
. Every element in
X
belongs to at least one set in
\mathcal{Y}
. In low-frequency systems, we assume that every element in
X
belongs to at most
f=o(\log(n^{\prime}))
sets in
\mathcal{Y}
.
A family of sets
Y^{\prime}\subseteq\mathcal{Y}
is called a cover if for every
x\in X
,
x\in\bigcup_{y\in Y^{\prime}}y
.
An algorithm is a
\lambda
-approximation for the
\mathsf{SC}(X,\mathcal{Y})
problem if it returns a cover
Y\subseteq\mathcal{Y}
with
|Y|\leq\lambda\cdot\mathsf{opt}
, where
\mathsf{opt}
is the cardinality of the minimum cover.
If the unique games conjecture is true there is no
(f-\zeta)
-approximation for the
\mathsf{SC}(X,\mathcal{Y})
problem, for any
\zeta>0

(
khot2008vertex
;
dinur2003new
)
.
In Appendix
A
we show a polynomial time reduction from the
\mathsf{SC}
problem to
\mathsf{CSO}
that leads to the proof of the next lemma.

Lemma 2.1.

If
\mathsf{Alg}
is a polynomial time
(1,f-\zeta,\gamma)
-approximation algorithm for the
\mathsf{CSO}
problem, where
\gamma=o(|\mathcal{H}|)

-approximation algorithm for the
\mathsf{SC}
problem.

Sketch of the proof.

The full proof is shown in Appendix
A
.
Given

\mathsf{CSO}

For each

Let

We show that if

Since

Lemma 2.3.

It holds that: i) If
r\geq\rho^{*}_{k,z}(P,\mathcal{H})
then (
\mathsf{LP}
Clustering with Set Outliers and Applications in Relational Clustering
) is feasible. ii)
|H|\leq 2fz
. iii) If (
\mathsf{LP}
Clustering with Set Outliers and Applications in Relational Clustering
) is feasible for a distance

, then
\rho(C,P\setminus(\bigcup_{h_{j}\in H}h_{j}))\leq 2r
. iv)

.

Proof.

We first show i).
Equivalently, we prove that if
r\geq\rho^{*}_{k,z}(P,\mathcal{H})
then the corresponding IP is feasible. Since
r\geq\rho^{*}_{k,z}(P,\mathcal{H})
, there exists the optimum set of
k

C^{*}\subset P
and a family of
z
sets
H^{*}\subseteq\mathcal{H}
such that
\rho(C^{*},P\setminus\bigcup_{h\in H^{*}}h)=\rho^{*}_{k,z}(P,\mathcal{H})
.
Based on this optimum solution, we construct a solution to the IP as follows. If
p_{i}\in C^{*}
then we set
\bar{x}_{i}=1
, otherwise we set
\bar{x}_{i}=0
. If
h_{j}\in H^{*}
we set
\bar{y}_{j}=1
, otherwise
\bar{y}_{j}=0
. Since
|C^{*}|=k
and
|H^{*}|=z
, the first two constraints are satisfied in the IP. Next, we focus on the third family of constraints in the IP. If
p_{i}\in\bigcup_{h_{j}\in H^{*}}h_{j}
then there exists a set
h_{j_{i}}\in L_{i}
such that
h_{j_{i}}\in H^{*}
and
\bar{y}_{j_{i}}=1
. Hence
\sum_{h_{j}\in L_{i}}\bar{y_{j}}\geq 1
and the inequality is satisfied. If
p_{i}\notin\bigcup_{h_{j}\in H^{*}}h_{j}
, then
p_{i}
must be covered within distance
r
from a center in
C^{*}
. Hence there exists an element
p_{i^{*}}\in C^{*}
such that
\mathsf{dist}(p_{i},p_{i^{*}})\leq r
where
\bar{x}_{i^{*}}=1
, so the inequality is satisfied.

Then, we show ii).
Assume that
|H|>2fz
. Then there would be more than
2fz

y_{j}
with value
y_{j}^{*}\geq\frac{1}{2f}
, so
\sum_{j\in[m]}y_{j}^{*}>z
, which is a contradiction.

Next, we prove iii).
By definition, the algorithm only finishes when no elements in
\mathsf{Act}
remain. Every time we add an element
p_{i}
in
C
we remove all points in (current)
\mathsf{Act}
within distance
2r
from
p_{i}
. So all elements in
P\setminus(\bigcup_{h_{j}\in H}h_{j})
are within distance
2r
from
C
.

Finally, we prove iv).
Let
p_{i}
be an element that does not belong in any outlier set in
H

\sum_{h_{j}\in L_{i}}y_{j}^{*}\leq f\frac{1}{2f}=\frac{1}{2}
so from the third family of inequalities in the LP, we have
\sum_{p_{\ell}\in B(p_{i},r)}x_{\ell}^{*}\geq\frac{1}{2}
.
We use an assignment argument. Every time we add a point
p

C

to
p

Assume that an element
p_{i}
is added in
C

The weight

\sum_{i\in[n]}x_{i}^{*}\leq k
.
Furthermore, for two different elements

C
.
Hence, each time that we add a new element

in
C
a weight
w_{p_{i}}\geq 1/2
is assigned to
p_{i}
. The total amount of weight among all elements is at most

C
.
Hence
\sum_{p\in C}w_{p}\leq k
and
\sum_{p\in C}w_{p}\geq|C|\cdot\frac{1}{2}

|C|\frac{1}{2}\leq k\Leftrightarrow|C|\leq 2k

Approximation Algorithm for Disjoint

Next, we assume that all pairwise sets in

For every distance

\mathsf{CSO}

At a high level, we compute a small set

Coreset construction

The construction of our coreset works in two phases. In the first phase we compute a set

and a family of sets

by running a

and keeping only centers that can cover all points in the set within distance

In the second phase we continue by removing additional elements where a sufficiently large ball around them intersects elements from sufficiently many different sets. If a set becomes empty in the process is removed from
\mathcal{H}
. In the end of the second phase we get a set
P^{\prime}\subseteq\bar{P}
and a family of set
\mathcal{H}^{\prime}\subseteq\bar{\mathcal{H}}
, which is given as input to the algorithm from Section

.

For every set

, we run the Gonzalez algorithm
(

)
for

-center clustering (without outliers) on the elements in

. Let

be the set of
k

Multiplicative Weight Update (MWU) method

The MWU method
(
arora2012multiplicative
)
is used to solve the following linear feasibility problem.

(5)

\exists\psi\in\mathcal{P}:A\psi\geq b,

where
A\in\mathbb{R}^{m^{\prime}\times n^{\prime}}
,
\psi\in\mathbb{R}^{n^{\prime}}
,
b\in\mathbb{R}^{m^{\prime}}
,
Ax\geq 0
,
b\geq 0
, and
\mathcal{P}
is a convex set in
\mathbb{R}^{n^{\prime}}
.
Arora et al.
(
arora2012multiplicative
)
describe an iterative algorithm using a simple
ORACLE
.
Let
ORACLE
be a black-box procedure that solves the following single linear constraint for a probability vector
\sigma\in\mathbb{R}^{m^{\prime}}
.

(6)

\exists\psi\in\mathcal{P}:\sigma^{\top}A\psi\geq\sigma^{\top}b.

The
ORACLE
decides if there exists an
\psi
that satisfies the single linear constraint. Otherwise, it returns that there is no feasible solution.
A
\xi
-
ORACLE
is an
ORACLE
such that whenever
ORACLE
manages to find a feasible solution
\hat{\psi}
to problem (
6
), then
A_{i}\hat{\psi}-b_{i}\in[-1,\xi]
for each constraint
i\in[m^{\prime}]
, where
A_{i}
is the
i
-th row of
A
, and
b_{i}
is the
i
-th element of vector
b
.

The algorithm starts by initializing
\sigma
to a uniform probability vector with value
1/m^{\prime}
. In each iteration the algorithm solves Equation (
6
). If (
6
) is infeasible, we return that the original feasibility problem in Equation (
5
) is infeasible. Let
\psi^{(t)}
be the solution of the problem in Equation (
6
) in the
t
-th iteration of the algorithm.
Let
\delta_{i}=\frac{1}{\xi}(A_{i}\psi^{(t)}-b_{i})
. We update
\sigma[i]=(1-\delta_{i}\cdot\varepsilon/4)\sigma[i]
, where
\sigma[i]
is the
i
-th element of vector
\sigma
. We continue to the next iteration solving (
6
) respect to the new probability vector
\sigma
. After
T=O(\xi\log(m^{\prime})/\varepsilon^{2})
iterations, if every oracle was feasible, they return
\psi^{*}=\frac{1}{T}\sum_{t=1}^{T}\psi^{(t)}
.
Otherwise, if an oracle was infeasible, they argue that the initial problem is infeasible.
Overall, every algorithm using the MWU method to solve a problem in the form of Equation (
5
) should implement two procedures:
\mathsf{Oracle}(\cdot)
that implements a
\xi
-
ORACLE
and
\mathsf{Update}(\cdot)
that updates the probability vector
\sigma
.
In
(
arora2012multiplicative
)
they prove the following theorem.

Theorem 3.1 (
(
arora2012multiplicative
)
).

Given a feasibility problem as defined above, a parameter
\varepsilon
, a
\xi
-

implemented in procedure

, and an update procedure

WSPD

Using a quadtree
(
finkel1974quad
)
, one can compute a

(WSPD)
(
callahan1995decomposition
;

)
for a set

BBD tree

BBD tree
(
arya1998optimal
;
arya2000approximate
)
is tree-based data structure that is used for counting, reporting and other aggregation queries over balls and other convex query regions. Given a set
P
of
n
points in
\mathbb{R}^{d}
the BBD tree
\mathcal{T}
over
P
is constructed in
O(n\log n)
time and has space
O(n)
. The height of the tree is
O(\log n)
. Every node
u
of
\mathcal{T}
is associated with a region
\square_{u}
, which is either a hyper-rectangle or a hyper-rectangle with a hole. A hole is defined by another hyper-rectangle. Given a query ball
B(x,r)
over a point
x\in\mathbb{R}^{d}
and a distance
r
, and a parameter
\varepsilon\in(0,1)
, a query on
\mathcal{T}
returns a set of canonical nodes
\mathcal{C}(B(x,r))
such that
B(x,r)\cap P\subseteq\bigcup_{u\in\mathcal{C}(B(x,r))}\square_{u}\cap P\subseteq B(x,(1+\varepsilon)r)\cap P
. Furthermore, for any pair of nodes
u,v\in\mathcal{C}(B(x,r))
, we have that
\square_{u}\cap\square_{v}=\emptyset
.
The query procedure runs in
O(\varepsilon^{-d+1}+\log n)
time and
|\mathcal{C}(B(x,r))|=O(\varepsilon^{-d+1}+\log n)
.
If for each node
u
we store
u.c=|P\cap\square_{u}|
or
u.P=P\cap\square_{u}
, notice that the BBD tree can be used to count or report the points in a ball
B(x,r)
. According to its definition we report (or count) all points in
B(x,r)\cap P
, but we might also report (or count) points of
P
slightly outside the ball

.

While BBD tree is used for approximate query processing over a ball, a range tree

;

The
\mathsf{Oracle}(\cdot)
procedure

We design a
(k+z)
-
ORACLE
procedure as defined in Section
3.1
. The goal is to decide whether there exists
\psi
such that
\sigma^{\top}A\psi\leq 1
and
\psi\in\mathcal{P}
. We note that
\mathsf{Oracle}(\cdot)
does not compute the matrix
A
explicitly.
In fact,
\sigma^{\top}A\psi
can be written as
\sum_{p_{\ell}\in P}\lambda_{\ell}\psi_{\ell}+\sum_{\square_{j}\in\mathcal{R}}\mu_{j}\psi_{n+j}
, for some real coefficients
\lambda_{\ell},\mu_{j}
.
Intuitively, our goal is to find
k
points from
P
and
z
hyper-rectangles from
\mathcal{R}
having the largest coefficients
\lambda_{\ell},\mu_{j}
. Our algorithm first finds all coefficients
\lambda_{\ell},\mu_{j}
and then it chooses the
k
largest
\lambda_{\ell}
coefficients from
P
and the
z
largest
\mu_{j}
coefficients from
\mathcal{R}
. In that way, we find the solution
\bar{\psi}
that maximizes
\sigma^{\top}A\bar{\psi}
for
\bar{\psi}\in\mathcal{P}
. Finally, we check whether
\sigma^{\top}A\bar{\psi}\geq 1
.

We are given a probability vector
\sigma\in\mathbb{R}^{n}
. Each value
\sigma[i]\in\sigma
corresponds to the
weight
of the
i
-th row of matrix
A
. In other words each point
p_{i}\in P
is associated with a weight
\sigma[i]
.
Let
\mathcal{T}
be the BBD tree constructed as described in Section
3.1
over the set of points
P
.
For every node
u
of
\mathcal{T}
, we initialize a weight
u_{s}=0
.
Let
\mathcal{G}
be the tree constructed as described in Section
3.1
over the set of weighted points
P
.
By construction, every node
v

of
\mathcal{G}
, initializes a weight
v_{s}
which is equal to the sum of weights of points that lie in leaf nodes of the subtree rooted at
v
.
The data structure
\mathcal{T}
has
O(n)
space and can be constructed in
O(n\log n)
time. The data structure
\mathcal{G}
has
O(n\log^{d-1}n)
space and can be constructed in
O(n\log^{d-1}n)
time.

Using
\mathcal{T}
and
\mathcal{G}
, we show how to check whether there exists
\bar{\psi}
such that
\sigma^{\top}A\bar{\psi}\geq 1
and
\bar{\psi}\in\mathcal{P}
.
For each
p_{\ell}\in P
we run the query
\mathcal{T}(p_{\ell},r)
and we get the set of canonical nodes
\mathcal{C}(B(p_{\ell},r))
. For each node
u\in\mathcal{C}(B(p_{\ell},r))
, we update
u_{s}\leftarrow u_{s}+\sigma[\ell]
.
After we traverse all points in
P
,
we revisit each point
p_{\ell}\in P
and continue as follows: We initialize a weight
w_{\ell}=0
. We start from the leaf node of
\mathcal{T}
that contains
p_{\ell}
and we traverse
\mathcal{T}
bottom up until we reach the root of the BBD tree. Let
v
be a node we traverse; we update
w_{\ell}=w_{\ell}+v_{s}
.
Intuitively in this process we get the sum of weight of all points
p_{i}
such that
p_{\ell}\in S_{p_{i}}^{\varepsilon}
.
After computing all values
w_{\ell}
for
\ell\in[n]
,
we find the
k
points from
P
with the largest weights
w_{\ell}
. Let
P_{L}
be these points. For each
p_{\ell}\in P_{L}
we set
\bar{\psi}_{\ell}=1
. Otherwise, if
p_{\ell}\notin P_{L}
we set
\bar{\psi}_{\ell}=0
.
Next, we process the hyper-rectangles.
For each
\square_{j}\in\mathcal{R}
, we run a query on
\mathcal{G}
and we get the set of canonical nodes
\mathcal{U}(\square_{j})
.
We set
\tau_{j}=\sum_{u\in\mathcal{U}(\square_{j})}u.s
.
Let
\mathcal{R}_{L}\subseteq\mathcal{R}
be the
z
hyper-rectangles with the largest weights
\tau_{j}
.
For each
\square_{j}\in\mathcal{R}_{L}
we set
\bar{\psi}_{n+j}=1
. Otherwise, if
\square_{j}\notin\mathcal{R}_{L}
we set
\bar{\psi}_{n+j}=0
.
If
\sum_{p_{\ell}\in P}w_{\ell}\bar{\psi}_{\ell}+\sum_{\square_{j}\in\mathcal{R}}\tau_{j}\bar{\psi}_{n+j}\geq 1
the oracle returns
\bar{\psi}
as a feasible solution. Otherwise, it returns that there is no feasible solution.

Correctness

We show that the
ORACLE
we design is correct.
We first show that
\lambda_{\ell}=w_{\ell}
for
\ell\in[n]
and
\mu_{j}=\tau_{j}
for
j\in[n]
,
so
\sigma^{\top}A\psi=\sum_{p_{\ell}\in P}w_{\ell}\psi_{\ell}+\sum_{\square_{j}\in\mathcal{R}}\tau_{j}\psi_{n+j}
.
Recall that
\sigma^{\top}A\psi=\sum_{p_{\ell}\in P}\lambda_{\ell}\psi_{\ell}+\sum_{\square_{j}\in\mathcal{R}}\mu_{j}\psi_{n+j}
, for the real coefficients
\lambda_{\ell}
and
\tau_{j}
.

By definition, each
\lambda_{\ell}
is defined as
\lambda_{\ell}=\sum_{p_{i}\in P}\sigma[i]\cdot\mathcal{I}(p_{\ell}\in S_{p_{i}}^{\varepsilon})
, where
\mathcal{I}(p_{\ell}\in S_{p_{i}}^{\varepsilon})=1
if
p_{\ell}\in S_{p_{i}}^{\varepsilon}
and
0
otherwise.
If
p_{\ell}\in S_{p_{i}}^{\varepsilon}
then by definition
\lambda_{\ell}
contains a term
\sigma[i]
in the sum.
There exists also a node
u\in\mathcal{C}(B(p_{i},r))

such that
p_{\ell}\in\square_{u}\cap P
, i.e.,
p_{\ell}
lies in a leaf node of the subtree rooted at
u
.
Starting from the leaf containing
p_{\ell}
, our algorithm will always visit the node
u
, and since
u\in\mathcal{C}(B(p_{i},r))
we have that
\sigma[i]
is a term in the sum
u_{s}
so by updating
w_{\ell}=w_{\ell}+u_{s}
we include the term
\sigma[\ell]
in the weight
w_{\ell}
.
Overall, we have that
w_{\ell}=\lambda_{\ell}
for
\ell\in[n]
.
Similarly, each
\mu_{j}
is defined as
\mu_{j}=\sum_{p_{i}\in P\cap\square_{j}}\sigma[i]
. By definition

\bigcup_{v\in\mathcal{U}(\square_{j})}(\square_{v}\cap P)=\square_{j}\cap P
and

\sum_{v\in\mathcal{U}(\square_{j})}v.s=\sum_{p_{i}\in P\cap\square_{j}}\sigma[i]
so
\tau_{j}=\mu_{j}
for
j\in[n]
.
We conclude that our algorithm finds all the correct coefficients in the linear function
\sigma^{\top}Ax
.

Then we focus on maximizing the sum
\sum_{p_{\ell}\in P}w_{\ell}\psi_{\ell}+\sum_{\square_{j}\in\mathcal{R}}\tau_{j}\psi_{n+j}
satisfying
\psi\in\mathcal{P}
. The constraints in
\mathcal{P}
suggests that
\sum_{\ell\in[n]}\psi_{\ell}=k
and
\sum_{j\in[m]}\psi_{n+j}=z
. Our algorithm sets the variables
\psi_{\ell}
that are multiplied by the largest
k
coefficients to
1
and sets the variables
\psi_{n+j}
that are multiplied by the largest
z
coefficients to
1
. Hence, by definition

\sum_{p_{\ell}\in P}w_{\ell}\bar{\psi}_{\ell}+\sum_{\square_{j}\in\mathcal{R}}\tau_{j}\bar{\psi}_{n+j}
maximizes the sum
\sum_{p_{\ell}\in P}w_{\ell}\psi_{\ell}+\sum_{\square_{j}\in\mathcal{R}}\tau_{j}\psi_{n+j}
for
x\in\mathcal{P}
.

Let
\bar{\psi}
be the feasible solution returned by
\mathsf{Oracle}(\cdot)
.
Notice that by definition,
\bar{\psi}
sets
k+z
variables to
1
. Hence, for each Constraint (
9
), it holds that
A_{i}\bar{\psi}-b_{i}\leq k-1
and
A_{i}\bar{\psi}-b_{i}\geq-1
, where
A_{i}
is the
i
-th row of
A
. We conclude that our
\mathsf{Oracle}
procedure computes a
(k+z)
-
ORACLE
as defined in
(
arora2012multiplicative
)
, so
\xi=k+z
.

4.1.
Relational

-center clustering with tuple-outliers – Acyclic queries

We first show an interesting connection of the
\mathsf{RCTO}
problem with the
\mathsf{GCSO}
problem.
The set of points we should cover is
\mathcal{Q}(\mathbf{I})
.
Let
t\in R_{j}
be a tuple in relation
R_{j}\in{\mathbf{R}}
. Let
\mathcal{Q}_{t}(\mathbf{I})=\pi_{{\mathbf{A}}_{j}=t}(\mathcal{Q}(\mathbf{I}))
, be the set of join results that are generated using the tuple
t
. Every time that
t
is selected as a tuple outlier, then all points from
\mathcal{Q}_{t}(\mathbf{I})
should be removed from
\mathcal{Q}(\mathbf{I})
.
The main observation is that for every
t\in\mathbf{I}
there exists a (degenerate) hyper-rectangle
\square_{t}
in
\mathbb{R}^{d}
such that
\mathcal{Q}_{t}(\mathbf{I})=\square_{t}\cap\mathcal{Q}(\mathbf{I})
.
For every
A_{i}\in{\mathbf{A}}
, if
A_{i}\notin{\mathbf{A}}_{j}
then we define the (open) interval
I_{i}=(-\infty,\infty)
, while if
A_{i}\in{\mathbf{A}}_{j}
then we define the (point) interval
I_{i}=[\pi_{A_{i}}(t),\pi_{A_{i}}(t)]
. We define the degenerate hyper-rectangle
\square_{t}=I_{1}\times I_{2}\times\ldots\times I_{d}
. It is easy to observe that
\mathcal{Q}_{t}(\mathbf{I})=\square_{t}\cap\mathcal{Q}(\mathbf{I})
.
Thus, the
\mathsf{RCTO}
problem can be mapped to the
\mathsf{GCSO}
problem, where
P=\mathcal{Q}(\mathbf{I})
and
\mathcal{R}=\bigcup_{t\in\mathbf{I}}\square_{t}
. Every time that a hyper-rectangle
\square_{t}
is selected as an outlier in
\mathsf{GCSO}
, then tuple
t
is set to be an outlier in the
\mathsf{RCTO}
problem.

It might be the case that for two tuples
t_{1}\in R_{i_{1}}
and
t_{2}\in R_{i_{2}}
,
\square_{t_{1}}\cap\square_{t_{2}}\cap\mathcal{Q}(\mathbf{I})\neq\emptyset
, i.e., the sets defined by the hyper-rectangles in
\mathcal{R}
intersect.
Hence, someone might try to use our algorithm from Theorem
3.2
to solve
\mathsf{RCTO}
.
Unfortunately, in addition to the challenges implementing the algorithm from Theorem
3.2
in the relational setting, notice that
f
might be
O(N)
leading to a bad approximation factor on the number of outliers.

4.1.1.
Tuple outliers from one relation

We assume that only tuples from relation
R_{1}\in{\mathbf{R}}
can be marked as outliers. We map
\mathsf{RCTO1}
to
\mathsf{GCSO}
where hyper-rectangles in
\mathcal{R}
do not intersect. Indeed consider two different tuples
t,t^{\prime}\in R_{1}
. By definition,
\square_{t}=\bigtimes_{A_{i}\notin{\mathbf{A}}_{1}}(-\infty,\infty)\bigtimes_{A_{i}\in{\mathbf{A}}_{1}}[\pi_{A_{i}}(t),\pi_{A_{i}}(t)]
and
\square_{t^{\prime}}=\bigtimes_{A_{i}\notin{\mathbf{A}}_{1}}(-\infty,\infty)\bigtimes_{A_{i}\in{\mathbf{A}}_{1}}[\pi_{A_{i}}(t^{\prime}),\pi_{A_{i}}(t^{\prime})]
. Since
t\neq t^{\prime}
, there exists at least one attribute
A_{\ell}\in{\mathbf{A}}_{1}
such that
\pi_{A_{\ell}}(t)\neq\pi_{A_{\ell}}(t^{\prime})
, so
\square_{t}\cap\square_{t^{\prime}}=\emptyset
.
Fortunately, our algorithm for the
\mathsf{GCSO}
runs on a small coreset, when hyper-rectangles in
\mathcal{R}
do not intersect. We construct the coreset efficiently in the relational setting and then we follow the algorithm from Section
3.3
.

Algorithm

Recall that the algorithm from Section
3.3
runs a binary search over an approximate set of all pairwise distances (WSPD). Unfortunately, we are not aware of how to construct a WSPD in the relational setting. Instead, we use the trick from
(
agarwal2024computing
)
to run a binary search on the
L_{\infty}
pairwise distances of the points in
\mathcal{Q}(\mathbf{I})
. In fact Agarwal et al.
(
agarwal2024computing
)
showed that the
\ell
-th smallest
L_{\infty}
pairwise distance among all points in
\mathcal{Q}(\mathbf{I})
can be computed in
O(N\log N)
time.

Let
r
be a guess of the cost of
\mathsf{GCSO}(\mathcal{Q}(\mathbf{I}),\mathcal{R})
from the binary search. Recall that the algorithm in Section
3.3
runs the standard
k
-center algorithm on the elements of every input set. In the relational setting, for every
t\in R_{1}
, we should run the
k
-center clustering on
\square_{t}\cap\mathcal{Q}(\mathbf{I})
. We define
R_{1}^{\prime}=\{t\}
and the query
\mathcal{Q}^{\prime}_{t}=R_{1}^{\prime}\Join R_{2}\Join\ldots R_{g}
. Then notice that
\mathcal{Q}^{\prime}_{t}(\mathbf{I})=\square_{t}\cap\mathcal{Q}(\mathbf{I})
. Hence, we run the oracle for the relational
k
-center clustering from Lemma
4.2
on
\mathcal{Q}^{\prime}_{t}(\mathbf{I})
.
Let
C_{t}
be the set of
k
centers and
r_{C_{t}}
be the value returned by the oracle in Lemma
4.2
. If
r_{C_{t}}>(2+\varepsilon)r
then we set

and we mark

as a tuple-outlier,

. We also remove
\square_{t}
from
\mathcal{R}
.
If
r_{C_{t}}\leq(2+\varepsilon)r
then we continue with the same procedure for the next tuple
t

4.1.2.
Tuple outliers from multiple relations

Lastly, we focus on the more involved case assuming that outliers can be selected from multiple (possibly all) relations.
We develop a new approach which is efficient when both
k
and
z
are relatively small.
The high level idea is the following.
Let

be the optimum set of
k
centers, and let
T^{*}\subseteq\mathbf{I}
be the optimum set of tuple outliers in
\mathsf{RCTO}(\mathcal{Q},\mathbf{I},k,z)
.
Using sampling, we partition
\mathbf{I}
into two subsets
\mathbf{I}_{1},\mathbf{I}_{2}
such that i)
\mathbf{I}_{1}\cap\mathbf{I}_{2}=\emptyset
, ii)
\mathbf{I}_{1}\cup\mathbf{I}_{2}=\mathbf{I}

and

.
Then the relational
k

. We get a set of
k

\mathbf{I}_{2}
that are joined to create join results far from

.

Algorithm

We give a high level description of our algorithm. All the details can be found in Appendix
F
.
We repeat the following procedure for
\tau=\Theta(2^{g\cdot k+z}\log N)
iterations. For each iteration,
initially
\mathbf{I}_{1}=\mathbf{I}_{2}=\emptyset
.
Each tuple

is placed in
\mathbf{I}_{1}
with probability
\frac{1}{2}
and in
\mathbf{I}_{2}
in
\frac{1}{2}
.
Notice that within
\tau
iterations, we will find a partition such that

and
T^{*}\subseteq\mathbf{I}_{2}

We execute the oracle

and we get a set of
k
-centers

and a value

such that
\rho(S_{1},\mathcal{Q}(\mathbf{I}_{1}))\leq r_{S_{1}}\leq(2+\varepsilon)\rho^{*}_{k}(\mathcal{Q}(\mathbf{I}_{1}))
.
Notice that
\rho^{*}_{k}(\mathcal{Q}(\mathbf{I}_{1}))\leq 2\rho^{*}_{k}(\mathcal{Q}(\mathbf{I}))
because
\mathcal{Q}(\mathbf{I}_{1})\leq\mathcal{Q}(\mathbf{I}))
. Then, assume that we know the optimum
r=\hat{\rho}_{k,z}^{*}(\mathcal{Q}(\mathbf{I}))
. Around each point
p\in S_{1}
, we construct a hyper-cube

with center
p
and side-length

. Let

be the set of all constructed hyper-cubes.
We note that all points in

are within distance

from a center in
S_{1}
.
On the other hand, if a point

does not belong in a hyper-cube in

must be an outlier, i.e., at least one of

must be an outlier.
We identify tuples in
\mathcal{Q}(\mathbf{I})
that lie outside the union of

by constructing

(this is also equivalent to the decomposition of the complement of the arrangement of

4.2.
Extension to Cyclic Queries

Similarly to
(
agarwal2024computing
;
esmailpour2024improved
)
, all our results for relational
k
-center clustering with outliers can be extended to cyclic join queries using the notion of
fractional hypergraph width

(
gottlob2014treewidth
)
. For a join query
\mathcal{Q}
, we use
\mathsf{fhw}(\mathcal{Q})
to denote the fractional hypergraph width of
\mathcal{Q}
. Intuitively
\mathsf{fhw}(\mathcal{Q})
shows how far
\mathcal{Q}
is from being acyclic. If
\mathcal{Q}
is an acyclic join query then
\mathsf{fhw}(Q)=1
. Using well-known and standard methodology
an algorithm for the
\mathsf{RCRO}
or
\mathsf{RCTO}
problem over an acyclic query
\mathcal{Q}
with running time
O(\eta(k,z)\cdot N\cdot\mathsf{polylog}(N))
, where
\eta(k,z)
is any real positive function over
k,z
, can be converted to an algorithm for any cyclic query with running time
O(\eta(k,z)\cdot N^{\mathsf{fhw}(\mathcal{Q})}\cdot\mathsf{polylog}N)
.

5.
Conclusion

In this work we defined the
k
-center clustering problem with set outliers. The problem has various applications in data cleaning, privacy, sensor networks etc. We gave efficient approximation algorithms in general metric spaces with arbitrary sets and in Euclidean space where sets are hyper-rectangles. Then we proposed efficient algorithms for the relational clustering problem with outliers. There are multiple open problems arising from this line of work.
An interesting direction is to study other clustering objectives such as
k
-median and
k
-means clustering in presence of set outliers. Finally, we aim to study more efficient algorithms for the relational
k
-center clustering with tuple-outliers in cases where outliers might exist in multiple tables.

is the root of
\mathcal{T}
. If yes, then we continue the binary search with larger values of

. If no, then we add in

In the end we return the last stored

.

Proof of correctness and runtime

Lemma E.1.

\rho(S,\mathcal{Q}(\mathbf{I})\setminus T)\leq 3(1+\varepsilon)^{2}\rho^{*}_{k,z}(\mathcal{Q}(\mathbf{I}))
and
|T|\leq(1+\varepsilon)^{2}\delta|\mathcal{Q}(\mathbf{I})|
with probability at least
1-\frac{1}{N}

Proof.

The correctness proof of our algorithm follows from the properties of the BBD tree. Every time that a node
u
becomes inactive the points in
\square_{u}
do not contribute in the counts of the active nodes, i.e., the update operation of the counts is correct. In each iteration, it finds a point
p_{i^{*}}
with the maximum number of points in a region that contains
B(p_{i^{*}},r)
and might contain some parts of
B(p_{i^{*}},(1+\varepsilon)r)\setminus B(p_{i^{*}},r)
. Furthermore, every time that
p_{i^{*}}
is added in
S
all points in
Q
within distance
3r
and some within distance
3(1+\varepsilon)r
are explicitly removed from
Q
, i.e., the canonical nodes that contain these points become inactive. The analysis is the same as in
[
21
]
(
3
-approximation), however we have a multiplicative
(1+\varepsilon)
error due to the BBD tree approximation. Furthermore, because of the WSPD we might not get
r=\textsf{opt}
. Instead, we guarantee that we will find at least a distance at most
(1+\varepsilon)\textsf{opt}
. Hence the overall approximation is
3(1+\varepsilon)^{2}
with probability at least
1-\frac{1}{N^{2}}
.

The second part of the lemma
|T|\leq(1+\varepsilon)^{2}\delta|\mathcal{Q}(\mathbf{I})|
follows directly from
[
22
]
.
∎

Notice that
3(1+\varepsilon/6)^{2}\leq 3+\varepsilon
and
(1+\varepsilon/6)^{2}\leq(1+\varepsilon)
.

Lemma E.2.

The running time of the algorithm is
O(N\log N+\varepsilon^{-d}\tau\log\tau+k(\tau\log\tau+\tau\varepsilon^{-d+1})\log\tau)
.

Proof.

Using Lemma
4.1
we can sample
\tau
points from
\mathcal{Q}(\mathbf{I})
in
O(N\log N+\tau\log N)

\mathcal{T}
is constructed in

in
O(\varepsilon^{-d}\tau\log\tau)

O(\log(\varepsilon^{-d}\tau))=O(\log\tau)

k
times. We find all points that are not contained in any inactive node in
O(\tau\log\tau)
time. For each such point
p_{i}
we compute

in
O(\log\tau+\varepsilon^{-d+1})

\mathcal{C}(B(p_{i^{*}},3r))
and the update procedure is executed in
O(\log\tau+\varepsilon^{-d+1})

We conclude with the next theorem.

Theorem E.3.

For an acyclic join query
\mathcal{Q}
of

attributes, a database
\mathbf{I}
of input size

Lemma F.1.

It holds that

,
|T|\leq g\cdot z

\rho(S,\mathcal{Q}(\mathbf{I}\setminus T))\leq O(1)\cdot\hat{\rho}^{*}_{k,z}(\mathcal{Q}(\mathbf{I}))

By definition for every center in

we add a point in

. Recall that

is the set of
k

k
-center clustering algorithm from Lemma

Next, we note that in every iteration of the algorithm we visit at most
z

g

\mathbf{I}
in

\ell\in[\tau]

Next, we show the approximation guarantee that holds with high probability. The probability that all tuples from

and all tuples in
T^{*}
are included in

and there are

and all tuples in

are included in

is bounded by

and
T^{*}\subseteq\mathbf{I}_{2}
with probability at least

. Without loss of generality, assume that this is the
\ell
-th iteration.

Let
r^{*}=\rho^{*}(S^{*},\mathcal{Q}(\mathbf{I}\setminus T^{*}))

By the definition of the binary search on

distances, it will guess a value

We have

z
