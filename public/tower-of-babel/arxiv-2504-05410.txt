Fast Controlled Generation from Language Models with Adaptive Weighted Rejection Sampling
Benjamin Lipkin * Benjamin LeBrun * Jacob Hoover Vigly João Loula David R. MacIver Li Du Jason Eisner Ryan Cotterell Vikash Mansinghka, Timothy J. O’DonnellAlexander K. Lew Tim Vieira MIT ETH Zürich McGill Canada CIFAR AI Chair Mila Johns Hopkins Yale CHI FRO

Abstract
The dominant approach to generating from language models subject to some constraint is locally constrained decoding (LCD), incrementally sampling tokens at each time step such that the constraint is never violated. Typically, this is achieved through token masking : looping over the vocabulary and excluding non-conforming tokens. There are two important problems with this approach. (i) Evaluating the constraint on every token can be prohibitively expensive—LM vocabularies often exceed 100,000 100,000 tokens. (ii) LCD can distort the global distribution over strings, sampling tokens based only on local information, even if they lead down dead-end paths. This work introduces a new algorithm that addresses both these problems. First, to avoid evaluating a constraint on the full vocabulary at each step of generation, we propose an adaptive rejection sampling algorithm that typically requires orders of magnitude fewer constraint evaluations. Second, we show how this algorithm can be extended to produce low-variance, unbiased estimates of importance weights at a very small additional cost—estimates that can be soundly used within previously proposed sequential Monte Carlo algorithms to correct for the myopic behavior of local constraint enforcement. Through extensive empirical evaluation in text-to-SQL, molecular synthesis, goal inference, pattern matching, and JSON domains, we show that our approach is superior to state-of-the-art baselines, supporting a broader class of constraints and improving both runtime and performance. Additional theoretical and empirical analyses show that our method’s runtime efficiency is driven by its dynamic use of computation, scaling with the divergence between the unconstrained and constrained LM, and as a consequence, runtime improvements are greater for better models. https://github.com/genlm/genlm-control

A key diagnostic quantity for assessing the quality of a generated sequence is the marginal probability of the constraint under the LM’s local next-token distribution at each timestep,

{\color[rgb]{0,0,0}Z}\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}\sum_{{\color[rgb]{0,0,0}x}\in{\color[rgb]{0,0,0}\mathcal{X}}}{\color[rgb]{0,0,0}p_{0}}({\color[rgb]{0,0,0}x}){\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}({\color[rgb]{0,0,0}x})

{\color[rgb]{0,0,0}p_{0}}

{\color[rgb]{0,0,0}\mathcal{X}}

{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}
checks whether a given token conforms to the constraint at the current time step.
Within sequential IS or SMC,
{\color[rgb]{0,0,0}Z}
arises as an incremental importance weight update.
When this quantity is low, we have reached a point in generation where it is difficult to sample any continuation of the sequence that satisfies the constraint.
For SMC specifically, this can be used as a signal for reallocating computation to more promising sequences during subsequent resampling.
Using token masking, it is clear how to compute
{\color[rgb]{0,0,0}Z}

{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}

this quantity may not be directly available, and we must seek to estimate it.

In this paper, we introduce an exact sampler for constrained token distributions whose runtime is faster than token masking, often by orders of magnitude.
Our algorithm is based on
rejection sampling
and, thus, is a
Las Vegas algorithm
, i.e., an exact algorithm with a stochastic runtime. Rather than using fixed compute for each step, compute scales dynamically based on need.
Furthermore, we derive unbiased estimators of
{\color[rgb]{0,0,0}Z}
for this algorithm that can be used to correct samples globally within an SMC framework.

Our core contributions are as follows:

•

A fast Las Vegas sampling algorithm compatible with any constraint.

We develop
adaptive weighted rejection sampling
(AWRS), a sampling algorithm for constrained generation.
Like other rejection sampling algorithms, the cost of our approach scales with the difficulty of the constraint.
However, our adaptive algorithm outperforms standard rejection sampling by capitalizing on the statistical structure of the next token distribution.
Due to the speed of this algorithm, we can comfortably evaluate arbitrary black-box constraints.

•

Stochastic estimates of
{\color[rgb]{0,0,0}Z}
to correct for greediness.

We develop an approach to calculate low-variance, unbiased estimates of
{\color[rgb]{0,0,0}Z}

•

Runtime analysis.

We theoretically and empirically characterize the work done by constrained decoding in terms of the probabilistic update between the LM’s unconditional next token distribution and the conditioned target distribution.
Critically, AWRS runs faster when the base model is better able to capture the constraint—meaning that our approach is more efficient for more accurate LMs—aligning with scaling trends.

•

Empirical evaluations.
We evaluate AWRS alongside several state-of-the-art baselines on five challenging controlled generation benchmarks. AWRS yields improvements to expressiveness, runtime, and accuracy across relevant comparisons.

Background

Locally Constrained Decoding (LCD).

A
language model

{\color[rgb]{0,0,0}P_{0}}
over an
alphabet

{\color[rgb]{0,0,0}\mathcal{X}}
is a probability distribution over the set of
strings

{\color[rgb]{0,0,0}{\color[rgb]{0,0,0}\mathcal{X}}^{*}}
.
We write
{\color[rgb]{0,0,0}x}
for individual tokens and
{\color[rgb]{0,0,0}\boldsymbol{x}}
for complete strings.
A
global constraint function

{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{L}}}}\colon{\color[rgb]{0,0,0}{\color[rgb]{0,0,0}\mathcal{X}}^{*}}\to\{0,1\}
encodes the
set of valid strings

{\color[rgb]{0,0,0}\mathcal{L}}\subseteq{\color[rgb]{0,0,0}{\color[rgb]{0,0,0}\mathcal{X}}^{*}}
.
The problem of controlled generation can be expressed as sampling
{\color[rgb]{0,0,0}\boldsymbol{x}}\sim{\color[rgb]{0,0,0}P}\xspace
, where
{\color[rgb]{0,0,0}P}\xspace\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}{\color[rgb]{0,0,0}P_{0}}(\cdot\mid{\color[rgb]{0,0,0}\boldsymbol{x}}\in{\color[rgb]{0,0,0}\mathcal{L}})
, i.e., sampling a complete string from the LM that satisfies the constraint while preserving the relative probabilities of possible strings.
This latter property is what distinguishes proper global conditioning from arbitrary constrained sampling.

During the autoregressive generation of a string, it is sometimes possible to evaluate whether sampling any given token would cause an immediate violation of the constraint.
For example, if a constraint requires writing a sentence where no word exceeds
5
characters, the only possible continuations to “north” should induce word boundaries, rather than continuing with “ern” or “east”.
At each step of generation, based on a current string prefix
{\color[rgb]{0,0,0}\boldsymbol{x}}_{p}
, we assume access to a
local constraint function

{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}\colon{\color[rgb]{0,0,0}\mathcal{X}}\to\{0,1\}
, encoding a
set of valid next tokens

{\color[rgb]{0,0,0}\mathcal{C}}\subseteq{\color[rgb]{0,0,0}\mathcal{X}}
, such that
{\color[rgb]{0,0,0}x}\not\in{\color[rgb]{0,0,0}\mathcal{C}}\implies\forall{\color[rgb]{0,0,0}\boldsymbol{x}}_{s}\colon{\color[rgb]{0,0,0}\boldsymbol{x}}_{p}\,{\color[rgb]{0,0,0}x}\,{\color[rgb]{0,0,0}\boldsymbol{x}}_{s}\not\in{\color[rgb]{0,0,0}\mathcal{L}}
. That is, if the local constraint function rejects a token
{\color[rgb]{0,0,0}x}
, there is no valid continuation of
{\color[rgb]{0,0,0}\boldsymbol{x}}_{p}
that begins with
{\color[rgb]{0,0,0}x}
.

Fixing a prefix

At each step, LCD samples a next token from the

\displaystyle{\color[rgb]{0,0,0}p}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}\frac{1}{{\color[rgb]{0,0,0}Z}}{\color[rgb]{0,0,0}\widetilde{p}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}\qquad{\color[rgb]{0,0,0}\widetilde{p}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}{\color[rgb]{0,0,0}p_{0}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}\,{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}\qquad{\color[rgb]{0,0,0}Z}\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}\sum_{{\color[rgb]{0,0,0}x}\in{\color[rgb]{0,0,0}\mathcal{X}}}{\color[rgb]{0,0,0}\widetilde{p}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}

(1)

where
{\color[rgb]{0,0,0}\widetilde{p}}
is its unnormalized density and
{\color[rgb]{0,0,0}Z}
is its normalizing constant.
(Note
0<{\color[rgb]{0,0,0}Z}\leq 1
.)
Intuitively,
{\color[rgb]{0,0,0}Z}
is the total probability of satisfying the local constraint under
{\color[rgb]{0,0,0}p_{0}}
.
The most common approach to implementing LCD is token masking: computing
{\color[rgb]{0,0,0}p}
exactly during generation, by evaluating
{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}
on every item in the vocabulary, zeroing impossible tokens, summing
{\color[rgb]{0,0,0}p_{0}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}
over the remainder to compute
{\color[rgb]{0,0,0}Z}
, and renormalizing to obtain
{\color[rgb]{0,0,0}p}
(
Fig.

1

By applying constraints locally at every token, LCD can greedily sample its way into low-probability sequences that are difficult or impossible to recover from.
For example, continuing with the constraint of generating a sentence where no word may exceed
5
characters, an LM will struggle to complete the prefix “The Fed says the cost of a 30-yr fixed mortg”, despite there having been no issues up until that point
(
Lew et al., 2023
, see)
.

Interestingly, such dead-ends can be readily detected using precisely the quantity
{\color[rgb]{0,0,0}Z}
computed as a byproduct of LCD.
When
{\color[rgb]{0,0,0}Z}
is very low, we have reached a point in string generation where only very few, improbable tokens can continue the string.

Why
{\color[rgb]{0,0,0}Z}
and not sequence probability? While methods optimizing sequence probability, like beam search, partially address the sample quality desiderata, there are caveats. If there are many valid tokens, whose sum is large, but each individual token has low probability, sequence probability will unfairly penalize any token
(
Koehn & Knowles, 2017
;
Murray & Chiang, 2018
;
Cohen & Beck, 2019
;
Stahlberg & Byrne, 2019
)
. Methods that account for
{\color[rgb]{0,0,0}Z}
do not suffer this drawback.

This local
{\color[rgb]{0,0,0}Z}
can be used in
sequential Monte Carlo (SMC)
to reweight partial generations (particles) for subsequent re-sampling steps, which tend to eliminate unpromising string prefixes and duplicate more promising ones (
Apps.

A
and
1
).
In this setting—where
LCD is used as a
proposal distribution
within SMC—
{\color[rgb]{0,0,0}Z}
is precisely the incremental correction factor that can be derived by simplifying the importance weights
(
Naesseth et al., 2019
)
.

Since
{\color[rgb]{0,0,0}Z}
is computed as a byproduct of token masking, this algorithm provides its own correction factors when used as a part of a proposal distribution in SMC.
Unfortunately, however, modern LMs often have vocabularies exceeding
100,000
tokens; evaluating
{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}
on every token in this set—and, thus, exactly computing
{\color[rgb]{0,0,0}Z}
—is often prohibitively slow.
It would initially appear that exact sampling from the local posterior
{\color[rgb]{0,0,0}p}
and exact weight correction with
{\color[rgb]{0,0,0}Z}
are impractical in these cases.

In the next sections, we develop an approach to sampling from the local posterior
{\color[rgb]{0,0,0}p}
that is exact, tractable for large vocabularies, typically fast in terms of average time, and provides correction factors to correct the greediness of LCD.

Simple rejection sampling.

Simple rejection sampling is an algorithm that can provide exact samples from
{\color[rgb]{0,0,0}p}
without looping through the entire token vocabulary.
It works by drawing a token
{\color[rgb]{0,0,0}x}\sim{\color[rgb]{0,0,0}p_{0}}
, then checking whether the token satisfies
{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}
.
If it does, the token is returned; otherwise, this process is repeated.
The returned token is an exact sample from
{\color[rgb]{0,0,0}p}
.

Compared to the constant cost of token masking, this algorithm is a
Las Vegas algorithm
, i.e., an exact algorithm with a stochastic runtime.
It is easy to show that the expected number of samples drawn by the algorithm before meeting the constraint is
\frac{1}{{\color[rgb]{0,0,0}Z}}
; it can furthermore be shown that
D_{KL}\left({\color[rgb]{0,0,0}p}\parallel{\color[rgb]{0,0,0}p_{0}}\right)=-\log{\color[rgb]{0,0,0}Z}

(
Levy, 2008
;
Freer et al., 2010
)
, and thus that the expected runtime is exponential in
D_{KL}\left({\color[rgb]{0,0,0}p}\parallel{\color[rgb]{0,0,0}p_{0}}\right)
.
When the constraint is relatively easy to satisfy (i.e., when
{\color[rgb]{0,0,0}Z}\approx 1
so
D_{KL}\left({\color[rgb]{0,0,0}p}\parallel{\color[rgb]{0,0,0}p_{0}}\right)
is low), this can lead to runtimes that are much faster than those required by full-vocabulary token masking. However, when
Z
is very small (
{\color[rgb]{0,0,0}Z}<|{\color[rgb]{0,0,0}\mathcal{X}}|^{-1}
), rejection sampling’s runtime can be even worse than that of token masking.

Adaptive rejection sampling (ARS).

Adaptive rejection sampling
(
Gilks & Wild, 1992
;
Mansinghka et al., 2009
)
is a version of rejection sampling that is never slower than token masking and often significantly faster. In ARS, we adaptively
remove
each invalid token encountered while rejection sampling, so that we never sample the same rejected token twice. This simple modification can dramatically improve the runtime of the algorithm (
Fig.

F.2
).

Both rejection sampling approaches evaluate
{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}
only on the samples they draw and, thus, can be more efficient than token masking. However, neither provides a direct way to exactly compute
{\color[rgb]{0,0,0}Z}
. A solution to this problem arises from the observation that for SMC, it suffices to use independent unbiased estimates of each local
{\color[rgb]{0,0,0}Z}
, rather than the exact quantities, as correction factors
(
Naesseth et al., 2015
,
Apps.

A
and
2
; )
.

3
Our Algorithms

In lieu of the exact but expensive correction factors obtained as a byproduct of token masking, we wish to find cheap, unbiased estimates of
{\color[rgb]{0,0,0}Z}
that we can compute as a byproduct of simple or adaptive rejection sampling.

Our first observation toward this goal is that the
number of rejected tokens
sampled before generating a valid next token
{\color[rgb]{0,0,0}x}
contains signal about the magnitude of
{\color[rgb]{0,0,0}Z}
: when many rejected tokens are generated, this suggests
{\color[rgb]{0,0,0}Z}
is small, and can serve as a sign that the current prefix
{\color[rgb]{0,0,0}\boldsymbol{x}}_{p}
has landed us in a low-probability region of the global posterior
{\color[rgb]{0,0,0}P}\xspace
.

Indeed, in simple rejection sampling, the number of trials
{\color[rgb]{0,0,0}n}_{0}+1
(that is,
{\color[rgb]{0,0,0}n}_{0}
rejections plus the final success) is an unbiased estimate of
1/{{\color[rgb]{0,0,0}Z}}
.
Unfortunately,
1/({\color[rgb]{0,0,0}n}_{0}+1)
is
not
an unbiased estimate of
{\color[rgb]{0,0,0}Z}
, and we require unbiased estimates of
{\color[rgb]{0,0,0}Z}
for sound use within SMC.

Warm-up: Weighted Rejection Sampling (WRS)

Adaptive Weighted Rejection Sampling (AWRS)

Definition 2

Methods.

We first compare the following
uncorrected

•

Base language model (

\xspace

•

Locally constrained decoding with token masking (
TM-LCD
\xspace

The standard approach to constrained decoding. We mask the entire token vocabulary, re-normalize, and sample.
6
6

6

Due to the high cost of full token masking, we only include this baseline for one benchmark, from which we illustrate our orders-of-magnitude speed-up.

•

Locally constrained decoding with adaptive rejection sampling (
ARS-LCD
\xspace
).
A faster implementation of LCD: rather than masking the entire vocabulary, we draw a sample from the same LCD distribution using ARS. (We do not yet use an importance-weight correction, so we run only the first rejection loop.)

The baselines above allow us to gauge the degree to which adaptive rejection sampling improves runtime.
Our next set of methods go beyond LCD, returning a weighted ensemble of
{\color[rgb]{0,0,0}M}

{\color[rgb]{0,0,0}P_{0}}({\color[rgb]{0,0,0}\boldsymbol{x}})\cdot{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{L}}}}({\color[rgb]{0,0,0}\boldsymbol{x}})\,\propto\,{\color[rgb]{0,0,0}P}\xspace({\color[rgb]{0,0,0}\boldsymbol{x}})

\xspace

Sample
{\color[rgb]{0,0,0}M}

Metrics.

•

Accuracy.
The accuracy of a returned string is defined by the benchmark.
For methods that construct a weighted ensemble, we report the expected accuracy of a random string returned from this ensemble (with probability proportional to its weight).
8
8

8

The rationale is that the probability of returning
{\color[rgb]{0,0,0}\boldsymbol{x}}
then approaches
{\color[rgb]{0,0,0}P}\xspace({\color[rgb]{0,0,0}\boldsymbol{x}})

minimum Bayes risk

{\color[rgb]{0,0,0}M}

We analyzed the

\xspace

D_{KL}\left({\color[rgb]{0,0,0}p}\parallel{\color[rgb]{0,0,0}p_{0}}\right)

We then ran AWRS for each of these steps, illustrating a few key results (

1.

2.

As
D_{KL}\left({\color[rgb]{0,0,0}p}\parallel{\color[rgb]{0,0,0}p_{0}}\right)

An interesting consequence is that
AWRS samples faster for more accurate base models

3.

As

AWRS is roughly bounded by the number of non-conforming tokens whose individual probabilities are close to or exceed

This set is typically small, and it turns out empirically that more accurate models seem to reduce the size of this set.
Even when a model’s top choice is wrong, it often still prefers constraint-conforming tokens to arbitrary non-conforming tokens.

Related Work

One approach to accelerating constrained decoding has been to pre-compile restricted constraint classes to reduce runtime overhead.
Engineering advances have enabled at least partial compilation of constraints expressible as membership in regular
(
Deutsch et al., 2019
;
Willard & Louf, 2023
;
Kuchnik et al., 2023
)
or context-free
(
Koo et al., 2024
;
Ugare et al., 2024
;
Dong et al., 2024
)
languages as well as restricted classes of Boolean circuits
(
Ahmed et al., 2025
)
.
In comparison, our approach supports arbitrary programmable constraints.

Another approach has explored limiting the number of constraint evaluations.

Poesia et al. (2022)
and
Ugare et al. (2025)
allow the LM to proceed unrestrictedly and then backtrack on errors.

Scholak et al. (2021)
and
Shin & Van Durme (2022)
use top-
k
truncation within beam search.

Loula et al. (2025)
, in a similar spirit to
Morin & Bengio (2005)
, hierarchically stratify the vocabulary and incrementalize the constraint checker to byte sequences.
A subset of the Outlines library
(
Willard & Louf, 2023
,
v.0.2.2
;)
uses a variant of deterministic probability-ordered search, first sorting tokens by their logits and then yielding the first conforming token.

Botta et al. (2025)
and
Mündler et al. (2025)
propose related variants of simple unweighted token-level rejection sampling.
Our work builds on these approaches within a probabilistic framework, deriving an exact sampler equivalent to token masking (
ARS-LCD
\xspace
) alongside importance weights supporting the sound use of such samples in SMC (
AWRS-SMC
\xspace
).

Several recent papers have used SMC to correct the greediness of LCD
(
Lew et al., 2023
;
Zhao et al., 2024
;
Loula et al., 2025
)
.
These approaches come with significant limitations:
Zhao et al. (2024)
require an expensive fine-tuning procedure for learning twists, whereas
Loula et al. (2025)
require constraints to be decomposable into slow and fast components, the latter of which must still be evaluated over large sets of tokens. In contrast, our approach works with any constraint out of the box and evaluates it frugally, being typically more accurate than twisted SMC for any fixed runtime.

7
Conclusion

Locally constrained decoding is both slow and greedy. In this paper, we address these weaknesses respectively by introducing (i) an adaptive rejection sampler requiring orders of magnitude fewer constraint evaluations, and (ii) an algorithm computing weights for transforming this local sampler into a global one. Across many challenging controlled generation domains, we find that our method is faster and more accurate than existing methods, even when using fewer particles and smaller LMs.
Finally, we use theoretical and empirical analyses to show that the number of constraint evaluations our method makes scales with the KL divergence between the unconstrained and constrained LM distributions—as a consequence, our method is faster for more powerful LMs.

Strings.

{\color[rgb]{0,0,0}\boldsymbol{x}}\in{\color[rgb]{0,0,0}{\color[rgb]{0,0,0}\mathcal{X}}^{*}}
. We also define
{\color[rgb]{0,0,0}{\Box}}\xspace\notin{\color[rgb]{0,0,0}\mathcal{X}}

Constraints.

Let
{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{L}}}}\colon{\color[rgb]{0,0,0}{\color[rgb]{0,0,0}\mathcal{X}}^{*}}\to\{0,1\}

. Let
{\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}\mathcal{L}}}}\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}\left\{{\color[rgb]{0,0,0}\boldsymbol{x}}\mid{\color[rgb]{0,0,0}\boldsymbol{x}}\,{\color[rgb]{0,0,0}\boldsymbol{x}}^{\prime}\in{\color[rgb]{0,0,0}\mathcal{L}}\right\}
, i.e., the set of all valid prefixes of strings in
{\color[rgb]{0,0,0}\mathcal{L}}
. We define the

:

\displaystyle{\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{L}}}}}}({\color[rgb]{0,0,0}x}^{\prime}\mid{\color[rgb]{0,0,0}\boldsymbol{x}})\begin{cases}\mathbbm{1}_{{\color[rgb]{0,0,0}\boldsymbol{x}}\in{\color[rgb]{0,0,0}\mathcal{L}}}&\textbf{if }{\color[rgb]{0,0,0}x}^{\prime}={\color[rgb]{0,0,0}{\Box}}\xspace\\
\mathbbm{1}_{{\color[rgb]{0,0,0}\boldsymbol{x}}\,{\color[rgb]{0,0,0}x}^{\prime}\in{\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}\mathcal{L}}}}}&\textbf{otherwise}\end{cases}

Language models.

A
language model

{\color[rgb]{0,0,0}P_{0}}
is a probability distribution over
{\color[rgb]{0,0,0}{\color[rgb]{0,0,0}\mathcal{X}}^{*}}
.
The
prefix probability

{\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}P_{0}}}}({\color[rgb]{0,0,0}\boldsymbol{x}})
is the probability that a string drawn from
{\color[rgb]{0,0,0}P_{0}}
has
{\color[rgb]{0,0,0}\boldsymbol{x}}
as a prefix:

{\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}P_{0}}}}({\color[rgb]{0,0,0}\boldsymbol{x}})\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}\sum_{{\color[rgb]{0,0,0}\boldsymbol{x}}^{\prime}\in{\color[rgb]{0,0,0}{\color[rgb]{0,0,0}\mathcal{X}}^{*}}}{\color[rgb]{0,0,0}P_{0}}({\color[rgb]{0,0,0}\boldsymbol{x}}\,{\color[rgb]{0,0,0}\boldsymbol{x}}^{\prime})

(4)

The
conditional prefix probability
is the probability that a string drawn from
{\color[rgb]{0,0,0}P_{0}}
has the prefix
{\color[rgb]{0,0,0}\boldsymbol{x}}\,{\color[rgb]{0,0,0}\boldsymbol{x}}^{\prime}
given that it already has the prefix
{\color[rgb]{0,0,0}\boldsymbol{x}}
for any strings
{\color[rgb]{0,0,0}\boldsymbol{x}},{\color[rgb]{0,0,0}\boldsymbol{x}}^{\prime}\in{\color[rgb]{0,0,0}{\color[rgb]{0,0,0}\mathcal{X}}^{*}}
:

{\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}P_{0}}}}({\color[rgb]{0,0,0}\boldsymbol{x}}^{\prime}\mid{\color[rgb]{0,0,0}\boldsymbol{x}})\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}\frac{{\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}P_{0}}}}({\color[rgb]{0,0,0}\boldsymbol{x}}\,{\color[rgb]{0,0,0}\boldsymbol{x}}^{\prime})}{{\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}P_{0}}}}({\color[rgb]{0,0,0}\boldsymbol{x}})}\quad\text{and}\quad{\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}P_{0}}}}({\color[rgb]{0,0,0}{\Box}}\xspace\mid{\color[rgb]{0,0,0}\boldsymbol{x}})\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}{{\color[rgb]{0,0,0}P_{0}}({\color[rgb]{0,0,0}\boldsymbol{x}})}/{{\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}P_{0}}}}({\color[rgb]{0,0,0}\boldsymbol{x}})}

(5)

Then, the probability of
{\color[rgb]{0,0,0}\boldsymbol{x}}
may be factorized as

\displaystyle{\color[rgb]{0,0,0}P_{0}}({\color[rgb]{0,0,0}\boldsymbol{x}})={\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}P_{0}}}}({\color[rgb]{0,0,0}{\Box}}\xspace\mid{\color[rgb]{0,0,0}\boldsymbol{x}})\prod_{t=1}^{|{\color[rgb]{0,0,0}\boldsymbol{x}}|}{\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}P_{0}}}}({\color[rgb]{0,0,0}x}_{t}\mid{\color[rgb]{0,0,0}\boldsymbol{x}}_{<t})

(6)

In particular, we define the
posterior distribution

{\color[rgb]{0,0,0}P}\xspace({\color[rgb]{0,0,0}\boldsymbol{x}})
of a language model

{\color[rgb]{0,0,0}\boldsymbol{x}}\sim{\color[rgb]{0,0,0}P_{0}}

\displaystyle{\color[rgb]{0,0,0}P}\xspace({\color[rgb]{0,0,0}\boldsymbol{x}})\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}\frac{1}{G}{\color[rgb]{0,0,0}\widetilde{{\color[rgb]{0,0,0}P}\xspace}}\xspace({\color[rgb]{0,0,0}\boldsymbol{x}})\qquad{\color[rgb]{0,0,0}\widetilde{{\color[rgb]{0,0,0}P}\xspace}}\xspace({\color[rgb]{0,0,0}\boldsymbol{x}})\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}{\color[rgb]{0,0,0}P_{0}}({\color[rgb]{0,0,0}\boldsymbol{x}}){\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{L}}}}({\color[rgb]{0,0,0}\boldsymbol{x}})\qquad G\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}\sum_{{\color[rgb]{0,0,0}\boldsymbol{x}}\in{\color[rgb]{0,0,0}{\color[rgb]{0,0,0}\mathcal{X}}^{*}}}{\color[rgb]{0,0,0}\widetilde{{\color[rgb]{0,0,0}P}\xspace}}\xspace({\color[rgb]{0,0,0}\boldsymbol{x}})

(7)

For
{\color[rgb]{0,0,0}P}
\xspace
to be a well-defined probability distribution, we require
G=\Pr_{{\color[rgb]{0,0,0}\boldsymbol{x}}\sim{\color[rgb]{0,0,0}P_{0}}}[{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{L}}}}({\color[rgb]{0,0,0}\boldsymbol{x}})]>0
.
In other words, there must be a way to generate a constraint-conforming string from
{\color[rgb]{0,0,0}P_{0}}
, and
G
tells us the probability of this event.
Note that

\displaystyle{\color[rgb]{0,0,0}P}\xspace({\color[rgb]{0,0,0}\boldsymbol{x}})=\Pr_{X\sim{\color[rgb]{0,0,0}P_{0}}}\left[X={\color[rgb]{0,0,0}\boldsymbol{x}}\,\middle|\,X\in{\color[rgb]{0,0,0}\mathcal{L}}\right]

(8)

Probabilistic conditioning is an enticing method for conditional generation as it is the only method that preserves the relative probabilities of all events that satisfy the condition.

Note that
{\color[rgb]{0,0,0}P}
\xspace
is a language model, so it has conditional prefix probabilities
{\color[rgb]{0,0,0}\vec{P}}\xspace
. Unfortunately, however,
G
and the conditional prefix probabilities are generally intractable to compute exactly as they involve intractable sums over all
{\color[rgb]{0,0,0}\boldsymbol{x}}\in{\color[rgb]{0,0,0}{\color[rgb]{0,0,0}\mathcal{X}}^{*}}

(
Rosenfeld et al., 2001
)
. This makes ancestral sampling, i.e., left-to-right sampling from the conditional prefix probability distribution, infeasible. In what follows, we will develop methods for (approximate) sampling from
{\color[rgb]{0,0,0}P}
\xspace
.

Locally constrained decoding.

Locally constrained decoding (typically performed through token masking) defines a language model
{\color[rgb]{0,0,0}\ell}
that attempts to approximate
{\color[rgb]{0,0,0}P}
\xspace
by approximating
{\color[rgb]{0,0,0}\vec{P}}
\xspace
with
{\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}\ell}}}({\color[rgb]{0,0,0}x}^{\prime}\mid{\color[rgb]{0,0,0}\boldsymbol{x}})\approx{\color[rgb]{0,0,0}\vec{P}}\xspace({\color[rgb]{0,0,0}x}^{\prime}\mid{\color[rgb]{0,0,0}\boldsymbol{x}})
where

\displaystyle{\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}\ell}}}({\color[rgb]{0,0,0}x}^{\prime}\mid{\color[rgb]{0,0,0}\boldsymbol{x}})\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}\frac{{\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}P_{0}}}}({\color[rgb]{0,0,0}x}^{\prime}\mid{\color[rgb]{0,0,0}\boldsymbol{x}}){\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{L}}}}}}({\color[rgb]{0,0,0}x}^{\prime}\mid{\color[rgb]{0,0,0}\boldsymbol{x}})}{L({\color[rgb]{0,0,0}\boldsymbol{x}})}\quad\text{and}\quad L({\color[rgb]{0,0,0}\boldsymbol{x}})\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}\sum_{{\color[rgb]{0,0,0}\boldsymbol{x}}^{\prime}\in{\color[rgb]{0,0,0}\mathcal{X}}\cup\left\{{\color[rgb]{0,0,0}{\Box}}\xspace\right\}}{\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}P_{0}}}}({\color[rgb]{0,0,0}x}^{\prime}\mid{\color[rgb]{0,0,0}\boldsymbol{x}}){\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{L}}}}}}({\color[rgb]{0,0,0}x}^{\prime}\mid{\color[rgb]{0,0,0}\boldsymbol{x}})

(9)

Prior work
(
Lew et al., 2023
;
Park et al., 2024
;
Ahmed et al., 2025
, e.g.,)
has shown
that this local approximation can be very different (i.e., biased) from
{\color[rgb]{0,0,0}P}\xspace
in both theory and practice. Fortunately, it is possible to improve this approximation (i.e., overcome this bias) with additional computation using the techniques that we describe next.

Explanation for why locally constrained decoding is biased.

Although
{\color[rgb]{0,0,0}\ell}
is an effective method for generating strings
{\color[rgb]{0,0,0}\boldsymbol{x}}\sim{\color[rgb]{0,0,0}\ell}
that satisfy
{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{L}}}}({\color[rgb]{0,0,0}\boldsymbol{x}})
, it has a tendency to over-represent certain strings. We can quantify this through the string’s relative probability

\displaystyle\rho({\color[rgb]{0,0,0}\boldsymbol{x}})\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}\frac{{\color[rgb]{0,0,0}P}\xspace({\color[rgb]{0,0,0}\boldsymbol{x}})}{{\color[rgb]{0,0,0}\ell}({\color[rgb]{0,0,0}\boldsymbol{x}})}=\frac{1}{G}\frac{{\color[rgb]{0,0,0}P_{0}}({\color[rgb]{0,0,0}\boldsymbol{x}}){\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{L}}}}({\color[rgb]{0,0,0}\boldsymbol{x}})}{{\color[rgb]{0,0,0}\ell}({\color[rgb]{0,0,0}\boldsymbol{x}})}=\frac{1}{G}\prod_{t=1}^{|{\color[rgb]{0,0,0}\boldsymbol{x}}|+1}L({\color[rgb]{0,0,0}\boldsymbol{x}}_{<t})

(10)

because

\displaystyle{\color[rgb]{0,0,0}P}\xspace({\color[rgb]{0,0,0}\boldsymbol{x}})=\frac{{\color[rgb]{0,0,0}P_{0}}({\color[rgb]{0,0,0}\boldsymbol{x}}){\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{L}}}}({\color[rgb]{0,0,0}\boldsymbol{x}})}{G}\quad\text{and}\quad{\color[rgb]{0,0,0}\ell}({\color[rgb]{0,0,0}\boldsymbol{x}})=\frac{{\color[rgb]{0,0,0}P_{0}}({\color[rgb]{0,0,0}\boldsymbol{x}}){\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{L}}}}({\color[rgb]{0,0,0}\boldsymbol{x}})}{\prod_{t=1}^{|{\color[rgb]{0,0,0}\boldsymbol{x}}|+1}L({\color[rgb]{0,0,0}\boldsymbol{x}}_{<t})}

(11)

In other words, if we compare samples from the local distribution
{\color[rgb]{0,0,0}\ell}
to their relative probability in the global distribution
{\color[rgb]{0,0,0}P}\xspace
, the string
{\color[rgb]{0,0,0}\boldsymbol{x}}
will appear at a rate of
\rho({\color[rgb]{0,0,0}\boldsymbol{x}})
more if
\rho({\color[rgb]{0,0,0}\boldsymbol{x}})<1
or less if
\rho({\color[rgb]{0,0,0}\boldsymbol{x}})>1
than it should.

In this work,
L({\color[rgb]{0,0,0}\boldsymbol{x}})\leq 1
for all
{\color[rgb]{0,0,0}\boldsymbol{x}}
.

In the expression for
\rho({\color[rgb]{0,0,0}\boldsymbol{x}})
, we see the factor that actually depends on the string
{\color[rgb]{0,0,0}\boldsymbol{x}}
independent of
G
, which is fortunate for us as we cannot efficiently compute
G
. Let
w({\color[rgb]{0,0,0}\boldsymbol{x}})=G\rho({\color[rgb]{0,0,0}\boldsymbol{x}})=\prod_{t=1}^{|{\color[rgb]{0,0,0}\boldsymbol{x}}|+1}L({\color[rgb]{0,0,0}\boldsymbol{x}}_{<t})
.

Clearly,
\prod_{t=1}^{|{\color[rgb]{0,0,0}\boldsymbol{x}}|+1}L({\color[rgb]{0,0,0}\boldsymbol{x}}_{<t})
is an important diagnostic for sample quality.

Operationally, when sampling from
{\color[rgb]{0,0,0}\ell}
, the cumulative product of local
L
’s is a useful signal for detecting low-quality samples.

Interestingly, the average weight is equal to
G
, i.e.,
\mathop{\mathbb{E}}_{{\color[rgb]{0,0,0}\boldsymbol{x}}\sim{\color[rgb]{0,0,0}\ell}}\left[\prod_{t=1}^{|{\color[rgb]{0,0,0}\boldsymbol{x}}|+1}L({\color[rgb]{0,0,0}\boldsymbol{x}}_{<t})\right]=G
.

Although the expression for the bias does not care about the ordering, it’s hard not to think about the operational view of ancestral sampling from
{\color[rgb]{0,0,0}\ell}
; in this view, the sample is created from left to right by sampling from the conditional token distributions. We say that our specific sample is distorted by the product of its local normalization constants. This quantity measures how much the constraints affected the sample. If the constraints only rule out very low (or even zero) probability tokens, then the distortion will be small as
L
will be
\approx 1
.

This operational view motivates the use of sequential Monte Carlo (SMC). In the case of SMC, we compare samples of complete and incomplete strings of length
\leq t
, and resample those that appear to be on track, i.e., favoring those that have higher intermediate weight values. Thus, if a particle was favored initially by the proposal distribution, it may be evicted later in favor of a replica of a higher-weight particle.

Importance sampling.

In our setting, importance sampling is a simple sampling-based approximate inference technique that can be used to extend locally constrained data with a weight correction. The weight correction allows us to overcome the bias in
{\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}\ell}}}\approx{\color[rgb]{0,0,0}\vec{P}}\xspace
with additional computation, i.e., taking more samples. Given a computational budget of
{\color[rgb]{0,0,0}M}>0
samples, the
importance sampling
procedure works as follows:

1.

Sample from the locally constrained distribution:
{\color[rgb]{0,0,0}\boldsymbol{x}}^{(1)},\ldots,{\color[rgb]{0,0,0}\boldsymbol{x}}^{({\color[rgb]{0,0,0}M})}\mathrel{\overset{\text{{{\scriptsize i.i.d.}}}}{\sim}}{\color[rgb]{0,0,0}q}
where
{\color[rgb]{0,0,0}q}
is a
proposal distribution
such as
{\color[rgb]{0,0,0}q}={\color[rgb]{0,0,0}\ell}
.

2.

Compute weights for each
{\color[rgb]{0,0,0}m}
:
{\color[rgb]{0,0,0}w}^{({\color[rgb]{0,0,0}m})}=\frac{{\color[rgb]{0,0,0}P_{0}}({\color[rgb]{0,0,0}\boldsymbol{x}}^{({\color[rgb]{0,0,0}m})})}{{\color[rgb]{0,0,0}q}({\color[rgb]{0,0,0}\boldsymbol{x}}^{({\color[rgb]{0,0,0}m})})}
. For the special case of
{\color[rgb]{0,0,0}q}={\color[rgb]{0,0,0}\ell}
, the weight simplifies to
{\color[rgb]{0,0,0}w}^{({\color[rgb]{0,0,0}m})}=\prod_{t=1}^{|{\color[rgb]{0,0,0}\boldsymbol{x}}^{({\color[rgb]{0,0,0}m})}|+1}L({\color[rgb]{0,0,0}\boldsymbol{x}}_{<t})
.

3.

Define estimates :

\displaystyle\widehat{G}\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}\frac{1}{{\color[rgb]{0,0,0}M}}\sum_{{\color[rgb]{0,0,0}m}=1}^{\color[rgb]{0,0,0}M}{\color[rgb]{0,0,0}w}^{({\color[rgb]{0,0,0}m})}\qquad\widehat{{\color[rgb]{0,0,0}\widetilde{{\color[rgb]{0,0,0}P}\xspace}}\xspace}({\color[rgb]{0,0,0}\boldsymbol{x}})\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}\frac{1}{{\color[rgb]{0,0,0}M}}\sum_{{\color[rgb]{0,0,0}m}=1}^{\color[rgb]{0,0,0}M}{\color[rgb]{0,0,0}w}^{({\color[rgb]{0,0,0}m})}\mathbbm{1}_{{\color[rgb]{0,0,0}\boldsymbol{x}}={\color[rgb]{0,0,0}\boldsymbol{x}}^{({\color[rgb]{0,0,0}m})}}\qquad\widehat{{\color[rgb]{0,0,0}P}\xspace}({\color[rgb]{0,0,0}\boldsymbol{x}})\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}\frac{\widehat{{\color[rgb]{0,0,0}\widetilde{{\color[rgb]{0,0,0}P}\xspace}}\xspace}({\color[rgb]{0,0,0}\boldsymbol{x}})}{\widehat{G}}

4.

Return a sample from the posterior estimate
\widehat{{\color[rgb]{0,0,0}P}\xspace}
.

Sequential Monte Carlo.

SMC is an extension of importance sampling, which effectively applies importance sampling to a sequence of intermediate target distributions chosen to keep partial generations on track rather than once for the entire sequence.

We define an intermediate
twist function
(also referred to as a
shaping function
)
{\color[rgb]{0,0,0}\vec{\psi}}\colon{\color[rgb]{0,0,0}{\color[rgb]{0,0,0}\mathcal{X}}^{*}}\to\mathbb{R}_{\geq 0}
, which is the key to providing partially generated strings intermediate feedback. Complete strings, on the other hand, will be judged by
{\color[rgb]{0,0,0}\widetilde{{\color[rgb]{0,0,0}P}\xspace}}
\xspace
. In this work, we use
{\color[rgb]{0,0,0}\vec{\psi}}({\color[rgb]{0,0,0}\boldsymbol{x}})={\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}P_{0}}}}({\color[rgb]{0,0,0}\boldsymbol{x}}){\color[rgb]{0,0,0}\vec{{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{L}}}}}}({\color[rgb]{0,0,0}\boldsymbol{x}})
, but we will discuss alternatives shortly. In our incarnation of the SMC algorithm, both complete and incomplete strings will evolve through a time-indexed state space where, at time
t
, the state contains two variables: a string of length
\leq t
, a Boolean indicating if the string is active (incomplete). When the string is active, its length is restricted to equal
t
. Once the string has been completed, it is never changed, i.e., no symbols can be appended to it.

We define the
initial target
as

\displaystyle\pi_{0}({\color[rgb]{0,0,0}\alpha},{\color[rgb]{0,0,0}\boldsymbol{x}})

Appendix B
Recursive Auxiliary-Variable Inference (RAVI)

Importance sampling
is an approach to approximate sampling from an unnormalized target distribution
{\color[rgb]{0,0,0}\widetilde{p}}
, with normalizing constant
{\color[rgb]{0,0,0}Z}
, through a proposal distribution
{\color[rgb]{0,0,0}q}
whose support is at least that of
{\color[rgb]{0,0,0}\widetilde{p}}
.
We would like to design
{\color[rgb]{0,0,0}q}
with favorable properties towards our downstream goal, e.g., efficient runtime.
Crucially, this design of a strong proposal distribution
{\color[rgb]{0,0,0}q}
is often mediated by auxiliary random choices
{\color[rgb]{0,0,0}r}
such that we sample
\langle{\color[rgb]{0,0,0}x},{\color[rgb]{0,0,0}r}\rangle\sim{\color[rgb]{0,0,0}q}
.
When this is the case, it is necessary to calculate a weight
{\color[rgb]{0,0,0}w}({\color[rgb]{0,0,0}x},{\color[rgb]{0,0,0}r})
to correct for
{\color[rgb]{0,0,0}r}
.

RAVI
(
Lew et al., 2022
)
gives us a generalized, flexible recipe for deriving the weights of relatively arbitrary choices of
{\color[rgb]{0,0,0}q}
.
Within RAVI, we may work with any unnormalized target distribution
{\color[rgb]{0,0,0}\widetilde{p}}
over any space
{\color[rgb]{0,0,0}\mathcal{X}}
.
Let
\langle{\color[rgb]{0,0,0}x},{\color[rgb]{0,0,0}w}\rangle\sim{\color[rgb]{0,0,0}Q}
denote the process of sampling from a proposal
{\color[rgb]{0,0,0}q}
and calculating its weight
{\color[rgb]{0,0,0}w}
.
We are interested in developing
{\color[rgb]{0,0,0}Q}
with the following property:

Definition 3
.

The proposal distribution
{\color[rgb]{0,0,0}Q}
is
properly weighted
if:

\mathop{\mathbb{E}}_{{\color[rgb]{0,0,0}\langle{\color[rgb]{0,0,0}x},{\color[rgb]{0,0,0}w}\rangle}\sim{\color[rgb]{0,0,0}Q}}[{\color[rgb]{0,0,0}w}\,{\color[rgb]{0,0,0}f}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}]={\color[rgb]{0,0,0}Z}\,\mathop{\mathbb{E}}_{{\color[rgb]{0,0,0}x}\sim{\color[rgb]{0,0,0}p}}[{\color[rgb]{0,0,0}f}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}]

(16)

Note that by taking trivial
{\color[rgb]{0,0,0}f}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}=1
, this property implies
\mathop{\mathbb{E}}_{{\color[rgb]{0,0,0}\langle{\color[rgb]{0,0,0}x},{\color[rgb]{0,0,0}w}\rangle}\sim{\color[rgb]{0,0,0}Q}}[{\color[rgb]{0,0,0}w}]={\color[rgb]{0,0,0}Z}
.
Leveraging this identity, each estimator
{\color[rgb]{0,0,0}\widehat{Z}}
in the main text is approximated via the weight
{\color[rgb]{0,0,0}w}
of a properly weighted proposal distribution.
For notational consistency with the literature on proper weighting,
{\color[rgb]{0,0,0}w}
will be used as opposed to
{\color[rgb]{0,0,0}\widehat{Z}}
throughout the appendix.

B.1
The Proposal

A RAVI proposal is a joint distribution
{\color[rgb]{0,0,0}q}({\color[rgb]{0,0,0}r},{\color[rgb]{0,0,0}x})
over a product space
{\color[rgb]{0,0,0}\mathcal{R}}\times{\color[rgb]{0,0,0}\mathcal{X}}
, where
{\color[rgb]{0,0,0}\mathcal{R}}
holds auxiliary random choices made by the proposal. Typically, proposals will be designed to make the marginal
{\color[rgb]{0,0,0}q}({\color[rgb]{0,0,0}x})
a good approximation to the target
{\color[rgb]{0,0,0}p}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}
.

In this work, we consider exclusively exact proposals, where
{\color[rgb]{0,0,0}q}({\color[rgb]{0,0,0}x})={\color[rgb]{0,0,0}p}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}
. This is achieved via various formulations of rejection sampling, where
{\color[rgb]{0,0,0}r}
represents the auxiliary randomness generated by the rejection sampler. Because

{\color[rgb]{0,0,0}q}({\color[rgb]{0,0,0}x})=\sum_{{\color[rgb]{0,0,0}r}\in{\color[rgb]{0,0,0}\mathcal{R}}}{\color[rgb]{0,0,0}q}({\color[rgb]{0,0,0}r},{\color[rgb]{0,0,0}x})
is typically intractable to evaluate exactly, the usual importance weight
{\color[rgb]{0,0,0}w}=\frac{{\color[rgb]{0,0,0}\widetilde{p}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}}{{\color[rgb]{0,0,0}q}({\color[rgb]{0,0,0}x})}
cannot be computed directly. RAVI provides a way to tractably compute a (noisy) importance weight that still satisfies proper weighting.

B.2
The Meta-Proposal

A RAVI meta-proposal
{\color[rgb]{0,0,0}h}({\color[rgb]{0,0,0}r};{\color[rgb]{0,0,0}x})
is designed to infer
{\color[rgb]{0,0,0}r}
given
{\color[rgb]{0,0,0}x}
. The optimal meta-proposal would be
{\color[rgb]{0,0,0}q}({\color[rgb]{0,0,0}r}|{\color[rgb]{0,0,0}x})\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}{\color[rgb]{0,0,0}q}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}r},{\color[rgb]{0,0,0}x}}\right)}/{\color[rgb]{0,0,0}q}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}
, but this optimal choice is often not tractable. In practice, we select a family of probability distributions
{\color[rgb]{0,0,0}h}({\color[rgb]{0,0,0}r};{\color[rgb]{0,0,0}x})
over
{\color[rgb]{0,0,0}\mathcal{R}}
, indexed by
{\color[rgb]{0,0,0}x}\in{\color[rgb]{0,0,0}\mathcal{X}}
, with the appropriate support, in order to define an ‘extended’ target

B.5
RAVI Intuitions for
Def.

1
(WRS)

In the context of the RAVI framework, WRS can be understood as representing the rejected samples as auxiliary variables generated during the sampling process. The auxiliary space
{\color[rgb]{0,0,0}\mathcal{R}}=\cup_{i\in\mathbb{N}}{\color[rgb]{0,0,0}\mathcal{X}}^{i}
consists of finite lists of rejected samples. The proposal
{\color[rgb]{0,0,0}q}
generates a trace of rejection sampling, while the meta-proposal
{\color[rgb]{0,0,0}h}
generates
{\color[rgb]{0,0,0}L}
additional rejection loops to improve our inference of the auxiliary variables. Finally, a meta-meta-proposal
{\color[rgb]{0,0,0}j}
accounts for the additional auxiliary variables introduced by
{\color[rgb]{0,0,0}h}
.

Intuitively, as
{\color[rgb]{0,0,0}L}
increases, we obtain a better estimate of the acceptance probability
{\color[rgb]{0,0,0}Z}
, leading to lower variance in our importance weights. In the limit as
{\color[rgb]{0,0,0}L}\to\infty
, meta-proposal
{\color[rgb]{0,0,0}h}({\color[rgb]{0,0,0}r};{\color[rgb]{0,0,0}x})
converges to its optimal distribution
{\color[rgb]{0,0,0}q}({\color[rgb]{0,0,0}r}\mid{\color[rgb]{0,0,0}x})
and the meta-meta-proposal
{\color[rgb]{0,0,0}j}({\color[rgb]{0,0,0}s};{\color[rgb]{0,0,0}r},{\color[rgb]{0,0,0}x})
converges to its optimal distribution
{\color[rgb]{0,0,0}h}({\color[rgb]{0,0,0}s}\mid{\color[rgb]{0,0,0}r};{\color[rgb]{0,0,0}x})
.

B.6
RAVI Intuitions for
Def.

2
(AWRS)

In the context of the RAVI framework, AWRS represents a modification where the sampling procedures in the proposal, meta-proposal, and meta-meta-proposal all maintain memory of previously rejected samples. The sampling distributions are continually renormalized after each rejection to account for the removed probability mass. This adaptation requires a different weight calculation that accounts for the changing probability distributions throughout the sampling process.

G.1
Runtime Analysis of
Def.

1
(WRS)

See
2

Proof.

Def.

1
performs
{\color[rgb]{0,0,0}L}+1
independent rejection sampling loops. In each loop, we sample
{\color[rgb]{0,0,0}x}_{j}\sim{\color[rgb]{0,0,0}p_{0}}
repeatedly, until obtaining a sample such that
{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}({\color[rgb]{0,0,0}x}_{j})=1
.

Define total runtime as
{\color[rgb]{0,0,0}T}\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}\sum_{i=0}^{{\color[rgb]{0,0,0}L}}{\color[rgb]{0,0,0}T}_{i}
, where random variable
{\color[rgb]{0,0,0}T}_{i}
denotes the number of samples in the
i
th loop (some number
{\color[rgb]{0,0,0}n}_{i}\geq 0
of rejected samples, and one final successful sample).

Since we sample independently with replacement, each
{\color[rgb]{0,0,0}T}_{i}
is identically distributed as a geometric distribution supported on
\mathbb{N}_{\geq 1}
with parameter
{\color[rgb]{0,0,0}Z}=\Pr_{{\color[rgb]{0,0,0}x}\sim{\color[rgb]{0,0,0}p_{0}}}[{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}({\color[rgb]{0,0,0}x})]\in(0,1]
. Thus total runtime is as follows.

\displaystyle\mathop{\mathbb{E}}[{\color[rgb]{0,0,0}T}]

\displaystyle=\sum_{i=0}^{{\color[rgb]{0,0,0}L}}\mathop{\mathbb{E}}[{\color[rgb]{0,0,0}T}_{i}]

[
Def.

1
; Linearity of expectation]

(32a)

\displaystyle=\sum_{i=0}^{{\color[rgb]{0,0,0}L}}\sum_{k=1}^{\infty}k\,\Pr[{\color[rgb]{0,0,0}T}_{i}=k]

[Def. of expectation]

(32b)

\displaystyle=({\color[rgb]{0,0,0}L}+1)\sum_{k=1}^{\infty}k\,(1-{\color[rgb]{0,0,0}Z})^{k-1}{\color[rgb]{0,0,0}Z}

[PMF of geom. dist.; Independence]

(32c)

\displaystyle=({\color[rgb]{0,0,0}L}+1)\sum_{k=1}^{\infty}kr^{k-1}(1-r)

[Let
r=1-{\color[rgb]{0,0,0}Z}
]

(32d)

\displaystyle=({\color[rgb]{0,0,0}L}+1)\sum_{k=1}^{\infty}r^{k-1}

[Simplify by subtracting like terms]

(32e)

\displaystyle=({\color[rgb]{0,0,0}L}+1)\frac{1}{1-(1-{\color[rgb]{0,0,0}Z})}

[Sum geom. series;
r=1-{\color[rgb]{0,0,0}Z}<1
]

(32f)

\displaystyle=\frac{{\color[rgb]{0,0,0}L}+1}{{\color[rgb]{0,0,0}Z}}

(32g)

Thus, the computational complexity is
{{\color[rgb]{0,0,0}{{\color[rgb]{0,0,0}\mathcal{O}}}\left(\frac{{\color[rgb]{0,0,0}L}}{{\color[rgb]{0,0,0}Z}}\right)}}
.
∎

G.2
Runtime Analysis of

(AWRS)

Proof.

In AWRS, we sample
without replacement
from initial distribution
{\color[rgb]{0,0,0}p_{0}}
, until we reach a sample which satisfies the constraint, which is sampled
with replacement
. This is repeated for a total of
1+{\color[rgb]{0,0,0}L}
successive loops.

To derive a simple expression for the expected total number of samples,
Eq.

42
, the following general property will be useful.

Lemma 1
.

Let
{\color[rgb]{0,0,0}\widetilde{P}}
be any (potentially unnormalized) probability distribution over the discrete set
{\color[rgb]{0,0,0}\mathcal{X}}
.
Suppose we begin sequentially sampling (with or without replacement) according to
{\color[rgb]{0,0,0}\widetilde{P}}
. For any two disjoint sets
{\color[rgb]{0,0,0}\mathcal{A}}_{1},{\color[rgb]{0,0,0}\mathcal{A}}_{2}\subseteq{\color[rgb]{0,0,0}\mathcal{X}}
, let
{\color[rgb]{0,0,0}x}_{\color[rgb]{0,0,0}\mathcal{A}}
be the first sampled element that happens to be in
{\color[rgb]{0,0,0}\mathcal{A}}\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}{\color[rgb]{0,0,0}\mathcal{A}}_{1}\sqcup{\color[rgb]{0,0,0}\mathcal{A}}_{2}
.
The probability that
{\color[rgb]{0,0,0}x}
is in
{\color[rgb]{0,0,0}\mathcal{A}}_{1}
(write
{\color[rgb]{0,0,0}\mathcal{A}}_{1}\prec{\color[rgb]{0,0,0}\mathcal{A}}_{2}
) is
\Pr[{\color[rgb]{0,0,0}\mathcal{A}}_{1}\prec{\color[rgb]{0,0,0}\mathcal{A}}_{2}]=\frac{{\color[rgb]{0,0,0}\widetilde{P}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}\mathcal{A}}_{1}}\right)}}{{\color[rgb]{0,0,0}\widetilde{P}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}\mathcal{A}}}\right)}}
.

Proof.

The crucial insight is that for a sequence drawn with or without replacement, the event
{\color[rgb]{0,0,0}\mathcal{A}}_{1}\prec{\color[rgb]{0,0,0}\mathcal{A}}_{2}
is determined by the first occurrence of an element in
{\color[rgb]{0,0,0}\mathcal{A}}
(denote this element
{\color[rgb]{0,0,0}x}_{\color[rgb]{0,0,0}\mathcal{A}}
), which is independent of the order or weight of elements outside of
{\color[rgb]{0,0,0}\mathcal{A}}
. That is,

\Pr[{\color[rgb]{0,0,0}\mathcal{A}}_{1}\prec{\color[rgb]{0,0,0}\mathcal{A}}_{2}]=\Pr[{\color[rgb]{0,0,0}x}_{\color[rgb]{0,0,0}\mathcal{A}}\in{\color[rgb]{0,0,0}\mathcal{A}}_{1}]=\frac{{\color[rgb]{0,0,0}P}^{\prime}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}\mathcal{A}}_{1}}\right)}}{{\color[rgb]{0,0,0}P}^{\prime}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}\mathcal{A}}}\right)}}
, where
{\color[rgb]{0,0,0}P}^{\prime}
is the probability distribution from which
{\color[rgb]{0,0,0}x}_{\color[rgb]{0,0,0}\mathcal{A}}
is sampled.

In sampling with replacement the distribution
{\color[rgb]{0,0,0}P}^{\prime}={\color[rgb]{0,0,0}P}\propto{\color[rgb]{0,0,0}\widetilde{P}}
trivially, and we have our result. In sampling without replacement, let
{\color[rgb]{0,0,0}R}\subset{\color[rgb]{0,0,0}\mathcal{X}}
be the set of already-rejected elements at the point when
{\color[rgb]{0,0,0}x}_{\color[rgb]{0,0,0}\mathcal{A}}
is drawn. Then the sampling distribution is
{\color[rgb]{0,0,0}P}^{\prime}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}\propto\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{X}}\setminus{\color[rgb]{0,0,0}R}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}{\color[rgb]{0,0,0}P}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}
. Since the elements in
{\color[rgb]{0,0,0}\mathcal{A}}
are not yet rejected by definition, simply
\frac{{\color[rgb]{0,0,0}P}^{\prime}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}\mathcal{A}}_{1}}\right)}}{{\color[rgb]{0,0,0}P}^{\prime}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}\mathcal{A}}}\right)}}=\frac{{\color[rgb]{0,0,0}P}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}\mathcal{A}}_{1}}\right)}}{{\color[rgb]{0,0,0}P}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}\mathcal{A}}}\right)}}=\frac{{\color[rgb]{0,0,0}\widetilde{P}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}\mathcal{A}}_{1}}\right)}}{{\color[rgb]{0,0,0}\widetilde{P}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}\mathcal{A}}}\right)}}
.
∎

Define total runtime as the total number of samples (both rejected and accepted) in the algorithm:

{\color[rgb]{0,0,0}T}\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}{\color[rgb]{0,0,0}T}_{0}+{\color[rgb]{0,0,0}T}_{1}+\mdots@+{\color[rgb]{0,0,0}T}_{\color[rgb]{0,0,0}L}

(33)

where
{\color[rgb]{0,0,0}T}_{0}

{\color[rgb]{0,0,0}T}_{\color[rgb]{0,0,0}i}
is the runtime of the
{\color[rgb]{0,0,0}i}

additional loop, for
{\color[rgb]{0,0,0}i}\in\{1,\mdots@,{\color[rgb]{0,0,0}L}\}
.

{\color[rgb]{0,0,0}T}

{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}

{\color[rgb]{0,0,0}\mathcal{C}}

{\color[rgb]{0,0,0}\pi_{{\color[rgb]{0,0,0}x}}}\mathrel{\overset{\raisebox{-0.75346pt}{{\tiny def}}}{=}}\Pr[{\color[rgb]{0,0,0}x}\prec{\color[rgb]{0,0,0}\mathcal{C}}]=\frac{{\color[rgb]{0,0,0}p_{0}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}}{{\color[rgb]{0,0,0}p_{0}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}+\sum_{{\color[rgb]{0,0,0}x}^{\prime}\in{\color[rgb]{0,0,0}\mathcal{C}}}{\color[rgb]{0,0,0}p_{0}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}^{\prime}}\right)}}=\frac{{\color[rgb]{0,0,0}p_{0}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}}{{\color[rgb]{0,0,0}p_{0}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}+{\color[rgb]{0,0,0}Z}}

We may think of clipped AWRS as the following extension of AWRS (

Proposal.

We again define over the space

or

Meta-proposal.

Given
{\color[rgb]{0,0,0}x}

{\color[rgb]{0,0,0}x}

{\color[rgb]{0,0,0}\widehat{Z}}=0

{\color[rgb]{0,0,0}x}

{\color[rgb]{0,0,0}n}_{0}

We continue generating a second loop with threshold

H.2.2
Practical considerations

Stochastic runtimes (particularly if the runtime distribution has long tails) can lead to issues in production systems.
Here, we have presented a modified version of AWRS that incorporates a user-specified upper bound on the mass sampled to generate a satisfying next token.
Using this variant, if a single particle within SMC has found itself in a poor position, it will stop early with a weight of
0
, allowing resampling to cull the particle (and clone a more promising particle) without slowing down the rest of the algorithm.
If a constraint is so difficult that the upper bound is hit frequently (across all particles in an SMC algorithm), the user may opt to increase their upper bound, dispatch to a larger model more capable of satisfying the constraint, or increase the number of particles in SMC to mitigate the issue.
We recommend testing how the inclusion of early stopping at various levels of strictness affect accuracy/runtime tradeoffs in your exact setting.

H.3

1

Def.

2

{\color[rgb]{0,0,0}R}

H.3.2
Geometric Adaptive Weighted Rejection Sampling

We can now reduce the sampling without replacement version to the above, through the following observation: Any run of sampling without replacement can be thought of as sampling with replacement, where any samples that have already been seen during the run are discarded (not recorded). Thus you can construct a run of sampling with replacement from a run of sampling without replacement by inserting a number of “phantom” samples that the without replacement algorithm removed. Because the estimator only depends on the
number
of tokens, we do not need to actually generate these phantom tokens, only to count them, so instead of actually sampling individual phantom tokens (which is slow), you can sample from a geometric distribution representing the number of phantoms to insert before getting a given novel token.

H.3.3
Recursive Adaptive Weighted Rejection Sampling

Another method operates from the trivial observation that

{\color[rgb]{0,0,0}Z}=\mathop{\mathbb{E}}[{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}{\color[rgb]{0,0,0}\left({X}\right)}]={\color[rgb]{0,0,0}p_{0}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)}+(1-{\color[rgb]{0,0,0}p_{0}}{\color[rgb]{0,0,0}\left({{\color[rgb]{0,0,0}x}}\right)})\mathop{\mathbb{E}}[{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}{\color[rgb]{0,0,0}\left({X}\right)}|X\neq{\color[rgb]{0,0,0}x}]
, for

and arbitrary
{\color[rgb]{0,0,0}x}\in{\color[rgb]{0,0,0}\mathcal{X}}
.
This allows us to recursively construct an estimator for
{\color[rgb]{0,0,0}Z}
by picking some
{\color[rgb]{0,0,0}x}

H.3.4
Trade-offs and Performance Considerations

Which of these two algorithms performs better depends on the shape of the distribution. In terms of absolute number of calls, RAWRS always makes the same or strictly fewer calls than GAWRS, but this ignores the fact that some of the calls in the latter may be repeated and not need recalculating (if the same accepted token is sampled multiple times). In particular, in the case where the distribution has a single element
x
with
{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}{\color[rgb]{0,0,0}\left({x}\right)}=1
and
{\color[rgb]{0,0,0}p_{0}}{\color[rgb]{0,0,0}\left({x}\right)}>\frac{2}{3}
, the expected number of calls made by GAWRS is under
2
, while the minimum number of calls made by RAWRS is always at least
2
.

This
\frac{2}{3}
threshold follows from the fact that the number of calls to the constraint function is bounded above by one plus the number of tokens other than
x
seen before
x
is drawn twice (one call for evaluating
{\color[rgb]{0,0,0}\mathbbm{1}_{{\color[rgb]{0,0,0}\mathcal{C}}}}{\color[rgb]{0,0,0}\left({x}\right)}
and at most one call per other token seen), which is bounded above by a negative binomial distribution with parameters
(2,{\color[rgb]{0,0,0}p_{0}}{\color[rgb]{0,0,0}\left({x}\right)})
(because that’s how many you’d see in the with-replacement model). So the expected number of calls is at most
1+\frac{2(1-{\color[rgb]{0,0,0}p_{0}}{\color[rgb]{0,0,0}\left({x}\right)})}{{\color[rgb]{0,0,0}p_{0}}{\color[rgb]{0,0,0}\left({x}\right)}}
, which some simple algebra shows is strictly less than two when
{\color[rgb]{0,0,0}p_{0}}{\color[rgb]{0,0,0}\left({x}\right)}>\frac{2}{3}
.

In contrast, in less peaked distributions
{\color[rgb]{0,0,0}p_{0}}
, GAWRS may often need to sample more than
1
token in its second loop, and thus RAWRS will strictly dominate in those cases.

These two methods can also be hybridized: At any point in RAWRS one can switch to GAWRS in the recursion. This likely yields the best of both worlds, but considerable further investigation is needed to empirically explore this design space, which we leave for future work.

H.4
Combination with truncation sampling

There are a few ways one might combine AWRS with truncation-based modifications to an LM’s sampling procedure.

The most straightforward way is to think of truncation-based sampling as modifying the base LM distribution, on top of which AWRS can then be applied.
For example, in top-p sampling with
p=0.9
, we zero out the bottom
10\%
of token probabilities and renormalize to obtain a modified next-token probability distribution.
We can then apply AWRS as though the base LM had generated this truncated next-token probability distribution: we adaptively rejection-sample from the truncated distribution, rather than from the full next-token distribution.
One caveat is that the user must ensure that truncation does not remove all valid next tokens (according to the constraint) from the support.

Another way to combine AWRS with truncation-based sampling is to consider the truncation as part of the constraint: we write a new constraint function that accepts a token only if it passes the original constraint and is in the top
10\%
of logits from the base model.
If AWRS-SMC were applied with this constraint, the weights would correct not only for myopia from locally constrained decoding, but also for myopia from top-p decoding.
As the number of particles grows, the algorithm’s output distribution would converge to the global posterior distribution that arises when the base LM is conditioned on the event that (1) the string satisfies the original constraint, and (2) each token is in the top
10\%
of the LM’s predictions given the previous tokens.
Note that, as above, the user must be careful to avoid the situation where there are no strings that satisfy this more stringent constraint.

I.2
From Global Constraints to Local Constraints

The goal of controlled generation is to satisfy some sequence-level constraint.
However, to enforce this constraint incrementally during generation, we need to formulate some local version of the constraint to check at each step.
An important design question is how to implement this local constraint.

The optimal Boolean local constraint checks for membership in the prefix language of the sequence-level constraint, i.e., it checks that there exists at least one suffix that, when concatenated to the current prefix, satisfies the sequence-level constraint.
In some cases, this prefix language can be evaluated quickly and precisely, e.g. in our pattern matching task, where we see performance near
100\%
.

But in many other cases, the exact calculation of this prefix language is intractable.
Still, it is often relatively simple to implement fast local checks of validity, i.e., upper bounds on the optimal local constraint.
For example, assume our goal is to generate Python code that passes a series of tests.
While it is not feasible to ask in the middle of the program whether it will eventually pass these tests, it is still simple to rule out many generations: the Python code should be syntactically valid, not reference undefined variables, use types correctly, and more generally execute without exception through the most recent complete statement, regardless of what it outputs.

When we talk about black-box constraint integration, this means that local constraint checkers may be arbitrary programs that map prefixes to Booleans.
They need not adhere to some special restricted class of functions like regular grammars.
This enables us to practically implement constraints like the one above, by writing a short program that actually calls the Python interpreter on generated code and checks if exceptions are raised.
Existing frameworks for locally constrained decoding typically do not support this degree of freedom, instead requiring the local constraints to be expressed in restricted formal languages.

In general, it is up to the user to strike their own tradeoff between the local constraint’s speed and precision.
In general, more precise constraints will make
AWRS-SMC
\xspace
more sample-efficient (better performance with fewer particles), whereas less precise constraints may mean that
AWRS-SMC
\xspace
requires more particles to produce great posterior samples.
But for all valid local versions of a constraint (i.e., all checkers that do not incorrectly rule out prefixes that could be completed to valid strings), the algorithm does correctly target the sequence-level conditional distribution, generating exact samples as the number of particles grows.
