EyeMulator : Improving Code Language Models by Mimicking Human Visual Attention
Yifan Zhang, Chen Huang, Yueke Zhang, Jiahao Zhang, Toby Jia-Jun Li, Collin McMillan, Kevin Leach, Yu Huang

Abstract
. Code language models (so-called CodeLLMs) are now commonplace in software development. As a general rule, CodeLLMs are trained by dividing training examples into input tokens and then learn importance of those tokens in a process called machine attention. Machine attention is based solely on input token salience to output token examples during training. Human software developers are different — humans intuitively know that some tokens are more salient than others. While intuition itself is ineffable and a subject of philosophy, clues about salience are present in human visual attention — people tend to look at more salient words more often. In this paper, we present EyeMulator , a technique for training CodeLLMs to mimic human visual attention while training for various software development tasks. We add special weights for each token in each input example to the loss function used during LLM finetuning. We draw these weights from observations of human visual attention derived from a previously-collected publicly-available dataset of eye-tracking experiments in software engineering tasks. These new weights ultimately induce changes in the attention of the subject LLM during training, resulting in a model that does not need eye-tracking data during inference. Our evaluation shows that EyeMulator outperforms strong LLM baselines on several tasks such as code translation, completion and summarization. We further show an ablation study that demonstrates the improvement is due to subject models learning to mimic human attention.



1.
Introduction

Large language models (LLMs) are becoming so popular that they are becoming a cultural cliché.
LLMs used for software development (CodeLLMs) now perform many tasks recently considered as only the domain of human experts: code generation, test generation, bug localization, automatic documentation generation, and many others.
And while “vibe coding” and other AI-based programming concepts proliferate, educational, commercial, and government institutions are grappling with the potential consequences of LLM use in software engineering.

Yet, behind this hype sits a surprisingly small set of technologies: the Transformer neural network architecture, internet-scale code and text datasets for training, a handful of preprocessing and tokenization techniques, and loss functions used during training.
Many CodeLLMs are now available and their success has vindicated the strategy of training via big data input followed by human feedback: first, CodeLLMs are trained to produce desired outputs from examples drawn from large code repositories, and later, they are finetuned with exemplars curated or edited by people.

Informally, when training LLMs, (1)
training examples are split into sequences of tokens, and
(2) the LLM’s neural architecture learns that certain tokens in input examples are salient to tokens in output examples.
Given an arbitrary input sample after training, the model generates output tokens one at a time that it learned are salient to tokens in the input.
This process is often called “machine attention” and is a metaphor for human attention.
Models learn which input tokens are salient regulated by a loss function during training that computes a similarity score between the model’s generated tokens and the example output tokens.
This similarity is used to update model weights, in turn leading the LLM to learn salience with respect to input and output example tokens.

But human developers are different.
Human attention is based on intuition learned from life experience. The process that people follow to read and understand code is called “program comprehension”
(
O’Brien 2003
;
Harth and Dugerdil 2017
;
Schulte et al. 2010a
;
Tempero and Tu 2024
)
and has been studied for decades.
Surveys by O’Brien
(
O’Brien 2003
)
, Harth and Dugerdil
(
Harth and Dugerdil 2017
)
, and others
(
Schulte et al. 2010b
;
Tempero and Tu 2024
)
characterize program comprehension as reading source code and related documents, forming a mental model of program behavior, and then comparing actual program behavior against the expectations in their mental model.
Errors in the mental model require investigation by further reading of software artifacts.
Over time, people develop an intuitive sense about what is salient in code samples they read.
The effect of this intuition is measurable with eye-tracking technology and has been the basis for studies of human visual attention for many years — people tend to read more salient tokens more often and for more time
(
Huang et al. 2020
;
Sharafi et al. 2021
;
Bertram et al. 2020
;
Rodeghero et al. 2014
;
Sharafi et al. 2020a
;
Sharif et al. 2012
;
Sharif and Kagdi 2011
;
Sharif et al. 2017
)
.

In this paper, we present
EyeMulator
, an approach to improve CodeLLMs by causing them to mimic human attention during training.

EyeMulator
leverages a previously-released dataset of eye-tracking measurements in which people read code to solve programming problems
(
Zhang et al. 2024
)
.
We extract
scan paths
from this eye-tracking data, which reflects the order in which tokens are read by humans
(
Bansal et al. 2023b
)
.
We use these scan paths to assign attention weights to each token in the input samples used to train an LLM.
Then, we finetune an LLM with a custom loss function based on categorical cross entropy (CCE) that rewards the model when it emphasizes the same tokens as a person would in a given input.
A key advantage of
EyeMulator
is that it requires no architectural changes to the LLM and is used only during finetuning — it is applicable to most LLMs, does not rely on any specific model or product, and does not require retraining LLMs from scratch.

We evaluate
EyeMulator
using three representative software engineering tasks:
code translation,
summarization, and
completion.
Our results demonstrate that the injection of human attention patterns substantially
boosts model performance, surpassing strong baseline LLMs.
Different human attention patterns have distinct, significant impacts on model attention, improving its focus on relevant code structures. Furthermore, ablation studies verify that all three components (semantic salience priors, gaze-transition tables, and token-level preference optimization) contribute meaningfully to these gains.

We claim the following contributions:

•

EyeMulator
, a lightweight, model-agnostic approach that leverages eye-tracking data to induce human attention into LLM attention during finetuning without requiring neural architectural changes or retraining.

•

A comprehensive evaluation of the performance of LLMs with
EyeMulator
applied, showing marked improvement over state-of-the-art baselines consisting of code translation, completion, and summarization.

•

An analysis of how model attention affects focus on tokens when
EyeMulator
is applied.

•

An open-source release of our software artifacts and datasets (
currently available to reviewers in the submission)
.

2.
Preliminaries

In this section, we establish notation and review foundational techniques: formalizing eye
-
tracking data as fixations, saccades, and scan paths; modeling token
-
level salience via Bayesian Beta inference; and integrating gaze
-
derived priors into LLM training through supervised fine
-
tuning (SFT) and a token
-
level variant of Direct Preference Optimization (DPO) that directly embeds human attention patterns.

2.1.
Eye
-
tracking in Software Engineering

Eye
-
tracking offers direct insight into developers’ cognitive processes by recording where and for how long they look at code
(
Grabinger et al. 2024
;
Sharafi et al. 2020b
)
. We use three core concepts:

•

Fixations
(
\mathcal{F}
): brief pauses (100–300 ms) during which visual information is processed. Each fixation
f_{i}
is characterized by its start time
t_{i}
and duration
d_{i}

(
Just and Carpenter 1980
)
.

•

Saccades
(
\mathcal{S}
): rapid eye movements (40–50 ms) between fixations that reposition the gaze without significant processing
(
Sharafi et al. 2015b
)
.

•

Scan path
(
\mathcal{P}
): the ordered sequence of fixations, capturing the flow of attention through the code
(
Karas et al. 2024
;
Sharafi et al. 2020b
)
.

According to the immediacy assumption, most cognitive processing occurs during fixations, while saccades simply move the gaze to the next point of interest
(
Just and Carpenter 1980
)
. Representing eye movements as
\mathcal{F}
,
\mathcal{S}
, and
\mathcal{P}
provides a human
-
centered foundation for our artifact extraction and modeling in Section
3
.

2.2.
Bayesian Salience Modeling

Bayesian inference provides a principled way to model token
-
level attention salience with uncertainty. A Beta distribution
\mathrm{Beta}(\alpha,\beta)
serves as the conjugate prior for Bernoulli processes, with density

\mathrm{Beta}(\theta;\alpha,\beta)=\frac{\theta^{\alpha-1}(1-\theta)^{\beta-1}}{B(\alpha,\beta)},\quad\theta\in[0,1],

where
B(\alpha,\beta)
is the Beta function. Given
k
salient fixations out of
n
observations and a prior
\mathrm{Beta}(\alpha,\beta)
, the posterior is
\mathrm{Beta}(\alpha+k,\beta+n-k)
. Its mean
(\alpha+k)/(\alpha+\beta+n)
quantifies the expected salience. We leverage this framework to derive the semantic salience priors used for token
-
level attention weighting in our subsequent training stages in Section
3
.

2.3.
Model Adaptation Techniques

SFT and reinforcement learning from human feedback (RLHF) are standard approaches for adapting pretrained LLMs to code tasks. In SFT, a model
P_{\phi}
is trained on a dataset
D=\{(x^{(i)},y^{(i)})\}
by minimizing the cross
-
entropy loss

\mathcal{L}_{\mathrm{SFT}}(\phi)=-\sum_{i=1}^{N}\sum_{t=1}^{|y^{(i)}|}\log P_{\phi}\bigl(y^{(i)}_{t}\mid y^{(i)}_{<t},x^{(i)}\bigr),

where
x
and
y
denote input–output pairs for completion, translation, or summarization
(
Jiang et al. 2024b
)
. Parameter
-
efficient methods such as adapter layers and low
-
rank adaptation (LoRA) help limit compute and preserve general capabilities
(
Hu et al. 2021
;
Hou et al. 2024
)
.

RLHF refines model behavior by learning a reward model from human preference pairs and optimizing via PPO
(
Christiano et al. 2023
;
Ouyang et al. 2022
;
Schulman et al. 2017
)
, but this pipeline is complex and sensitive to reward quality
(
Bai et al. 2022
)
. DPO streamlines RLHF by directly optimizing pairwise preferences without an explicit reward model:

L_{\mathrm{DPO}}=-\mathbb{E}_{(x,y_{w},y_{l})}\bigl[\log\sigma\bigl(\beta\bigl[\log\tfrac{\pi_{\phi}(y_{w}|x)}{\pi_{\mathrm{ref}}(y_{w}|x)}-\log\tfrac{\pi_{\phi}(y_{l}|x)}{\pi_{\mathrm{ref}}(y_{l}|x)}\bigr]\bigr)\bigr],

where
\pi_{\mathrm{ref}}
is a fixed reference policy,
\sigma
the sigmoid, and
\beta
the KL
-
penalty weight
(
Rafailov et al. 2024
)
. DPO offers stable alignment with fewer hyperparameters. We adopt DPO in our methodology to integrate pseudo
-
preferences derived from human
-
attention signals in Section
3
.

3.
Approach

As illustrated in Figure 1, our pipeline comprises three components: ① an eye
-
tracking stage that captures fixations and saccades while programmers read and write code; ② an artifact
-
extraction stage that parses source into an AST, aligns each gaze fixation to leaf tokens, and distills semantic salience priors (Beta distributions) and n
-
gram gaze
-
transition tables; and ③ a contextual
-
augmentation and fine
-
tuning stage that generates pseudo monograms, bigrams, and trigrams for code augmentation and performs attention
-
aware supervised fine
-
tuning of LLMs with under 1 MB of overhead.

3.1.
Developer Gaze Data Transformation

To ground our approach in authentic developer behavior, we first transform raw gaze recordings into clean, token-aligned attention data. This preprocessing step segments continuous eye-tracking streams into standardized fixations, saccades, and scan paths, and aligns them to AST leaf tokens, ensuring reliable inputs for downstream artifact extraction.

We leverage the open
-
source EyeTrans corpus
(
Zhang et al. 2024
)
, which provides raw eye
-
tracking recordings from 27 intermediate
-
to
-
advanced programmers (mean 20
\pm
2 CS semesters) performing distinct
reading
and
writing
tasks on single
-
function Java snippets (Figure
2
). Data were captured at 120 Hz with a mean angular error below 0.4°.

Raw gaze samples were segmented into fixations and saccades using a dispersion
-
threshold (I
-
DT) algorithm:

•

Fixations
(
\mathcal{F}
) are intervals of stable gaze within a 1° dispersion window lasting at least 100 ms.

•

Saccades
(
\mathcal{S}
) are rapid eye movements (40–50 ms) between fixations.

•

Blinks and noise outliers were removed prior to analysis.

Each Java snippet was parsed into an AST and instrumented in an IDE to record screen
-
space bounding boxes for every leaf token. A fixation
f_{i}
is aligned to token
t_{j}
if its
(x,y)
coordinates fall inside
t_{j}
’s box; unmapped fixations (approximately 3%) were discarded. From these mappings, we extracted a total of 1,565 scan paths (
\mathcal{P}
), with 914 from reading sessions and 651 from writing sessions, each representing a time
-
ordered sequence of fixations on AST leaf tokens.

3.2.
Attention Pattern Extraction

We convert token-aligned fixations into two types of statistical artifacts, semantic salience priors and sequential gaze-transition distributions, through three stages: distribution construction, pseudo-attention mask sampling, and pseudo scan path generation.

Distribution Construction.

We first derive monogram counts
c_{1}(s)
by counting fixations on tokens of each semantic class
s
. Let
n_{s}^{\mathrm{tok}}
be the total number of tokens in class
s
. We fit a Beta distribution with parameters

\alpha_{s}=c_{1}(s)+1,\quad\beta_{s}=n_{s}^{\mathrm{tok}}-c_{1}(s)+1,

so that the posterior mean

\mathbb{E}[\theta_{s}]=\frac{\alpha_{s}}{\alpha_{s}+\beta_{s}}

provides a smoothed estimate of the probability that a token of class
s
attracts attention.

To capture transition dynamics, we parse each scan path—a time-ordered sequence of fixations on tokens—and count bigrams
c_{2}(s_{a},s_{b})
and trigrams
c_{3}(s_{a},s_{b},s_{c})
. We convert these to conditional probabilities

P(s_{b}\mid s_{a})=\frac{c_{2}(s_{a},s_{b})}{\sum_{s^{\prime}}c_{2}(s_{a},s^{\prime})},\quad P(s_{c}\mid s_{a},s_{b})=\frac{c_{3}(s_{a},s_{b},s_{c})}{\sum_{s^{\prime}}c_{3}(s_{a},s_{b},s^{\prime})},

and prune any n-gram whose count is fewer than five to reduce noise.

Sampling Pseudo-Attention Masks.

For an example with
n
tokens, we sample a saliency ratio
\rho
from the combined Beta distribution over classes. We compute the total number of attended tokens as
m=\lfloor\rho\,n\rfloor
and allocate per-class quotas
m_{s}=\max\bigl(1,\lfloor p_{s}\,m\rfloor\bigr)
, where
p_{s}=c_{1}(s)/\sum_{s^{\prime}}c_{1}(s^{\prime})
. Token positions are shuffled and selected to satisfy these quotas, yielding a binary mask of length
n
.

Pseudo
-
Attention Path Generation.

Starting from the sorted list of masked token indices, we build a sequence of
n
-
grams to approximate the developer’s gaze path:

(1)

Trigram matching: consider three consecutive masked positions
t_{i},t_{i+1},t_{i+2}
. Accept this as a trigram if their line
-
number span
\ell_{t_{i+2}}-\ell_{t_{i}}\leq L
(e.g. 3 for reading, 5 for writing, 4 for combined) and the class tuple
(s_{t_{i}},s_{t_{i+1}},s_{t_{i+2}})
exists in the trigram table. If matched, emit the trigram and advance by 3.

(2)

Bigram matching: otherwise, consider the pair
(t_{i},t_{i+1})
. If
\ell_{t_{i+1}}-\ell_{t_{i}}\leq L
and the class pair appears in the bigram table, emit the bigram and advance by 2.

(3)

Monogram fallback: if neither larger
n
-
gram matches or at the list end, emit the single token class and advance by 1.

Each emitted
n
-
gram, whether a monogram, bigram, or trigram, is recorded in a global index dictionary seeded with all semantic classes and extended with every observed bigram and trigram. As we greedily match tokens, we assemble a pseudo scan path

\tilde{\mathcal{P}}=\langle g_{1},g_{2},\dots,g_{K}\rangle,

where each
g_{k}
is the
k
th emitted
n
-
gram. We also capture its index
\mathrm{idx}(g_{k})
, enabling the model to distinguish higher
-
order patterns from simple monograms when computing rarity bonuses and encoding input. This line
-
aware procedure produces
\tilde{\mathcal{P}}
, a pseudo
-
attention path that reflects both semantic transitions and code locality. Figure
3
shows a simplified monogram example; in practice, higher
-
order
n
-
grams are emitted whenever available. These paths, together with the semantic
-
salience priors, feed into the weight projection and fine
-
tuning stages.

3.3.
Subword Weight Projection

Having distilled developer attention into AST
-
level salience weights in the previous section, we next need to align those weights with the token units the LLM actually processes. Tokenizers break each source token (and its corresponding AST node) into several subword shards, so a direct one
-
to
-
one transfer is not possible. To preserve the full effect of each AST weight, we assign every shard the same score as its parent.

Formally, let

\texttt{Shards}(T_{i})=[s_{i,1},\dots,s_{i,k_{i}}]

be the
k_{i}
subword tokens generated for AST token
T_{i}
. We propagate the AST token’s salience weight
w_{i}^{\mathrm{AST}}
uniformly:

w_{i,j}^{\mathrm{shard}}=w_{i}^{\mathrm{AST}}\quad\text{for }j=1,\dots,k_{i}.

Concatenating these shard weights in the order of the tokenized input produces

\mathbf{w}=[\,w_{1,1}^{\mathrm{shard}},\dots,w_{1,k_{1}}^{\mathrm{shard}},\dots,w_{M,1}^{\mathrm{shard}},\dots,w_{M,k_{M}}^{\mathrm{shard}}\,].

By construction, the length of
\mathbf{w}
matches the LLM’s input sequence exactly. During fine
-
tuning, each weight
w_{\ell}
multiplies the corresponding cross
-
entropy term, ensuring that shards derived from high
-
salience AST tokens have proportionally greater influence on the model’s parameter updates.

3.4.
Gaze
-
Informed Fine
-
Tuning

Before fine
-
tuning, we compute per
-
token weights
w_{j}
by combining three components:

w_{j}=w_{\text{base}}+\frac{1}{\log(\text{freq}(g_{j})+2)}+\mathbb{E}[\theta_{s_{j}}],

where

•

w_{\text{base}}
is a constant base weight (e.g. 3) applied to every target token,

•

\text{freq}(g_{j})
is the count of the
n
-gram
g_{j}
(monogram, bigram or trigram) from the pseudo scan path
\tilde{\mathcal{P}}
, and

•

\mathbb{E}[\theta_{s_{j}}]
is the semantic
-
salience prior for the token’s class
s_{j}
.

These weights reflect human attention frequency, n
-
gram rarity, and a uniform baseline.

Each training example thus comprises an input prompt
x
, a target sequence
y
, and a weight vector
\mathbf{w}=[w_{1},\dots,w_{L}]
. We first fine
-
tune under a reweighted cross
-
entropy loss:

L_{\mathrm{SFT}}(\phi)=-\sum_{j=1}^{L}w_{j}\,\mathbb{1}[j\in\text{target}]\,\log P_{\phi}(y_{j}\mid y_{<j},x).

Here
\mathbb{1}[j\in\text{target}]
masks out prompt tokens, and higher
w_{j}
amplify the learning signal for tokens that developers attended to more.

To further align model preferences with gaze
-
derived importance, we apply Direct Preference Optimization at the token level. We sample two candidate outputs
(y_{w},y_{l})
in proportion to the sum of their shard weights over
\mathbf{w}
, and minimize

L_{\mathrm{DPO}}(\phi)=-\mathbb{E}_{(x,y_{w},y_{l})}\log\sigma\Bigl(\beta\bigl[\log\tfrac{\pi_{\phi}(y_{w}\mid x)}{\pi_{\mathrm{ref}}(y_{w}\mid x)}-\log\tfrac{\pi_{\phi}(y_{l}\mid x)}{\pi_{\mathrm{ref}}(y_{l}\mid x)}\bigr]\Bigr),

where
\pi_{\mathrm{ref}}
is a fixed reference policy and
\beta
controls the KL penalty strength. This step encourages the model to prefer outputs that emphasize high
-
salience and rare
n
-grams.

The final training objective is a weighted combination:

L(\phi)=L_{\mathrm{SFT}}(\phi)+\gamma\,L_{\mathrm{DPO}}(\phi),

with
\gamma
balancing supervised and preference signals. Empirically, this gaze
-
informed fine
-
tuning yields substantial gains on code translation, completion, and summarization, producing outputs that more closely mirror real developer attention.

4.
Experimental Setup

To evaluate EyeMulator’s effectiveness, we conduct experiments on three core code-intelligence tasks: translation, completion, and summarization. We compare our attention-augmented models against state-of-the-art baselines using a diverse set of automated and behavioral metrics. Below, we detail the datasets, our training setup, and evaluation criteria.

4.1.
Research Questions

Our goal is to determine whether
EyeMulator
’s incorporation of human visual
-
attention signals can meaningfully improve LLM performance on core code
-
intelligence tasks. To evaluate this, we investigate five research questions:

•

RQ1 (Artifact Distillation)
: How effectively do our distilled semantic salience priors and n
-

-

•

RQ2 (Cross
-

: To what extent do these artifacts boost performance on summarization (aligned with the original eye
-

•

RQ3 (Session
-

: How do reading
-

-

•

RQ4 (Component Ablation)
: What is the individual contribution of each

•

RQ5 (Attention Distribution)

4.2.
Datasets and Preprocessing

We combine developer gaze data from the open
-
source EyeTrans corpus
(
Zhang et al. 2024
)
(27 expert Java developers, yielding 914 reading and 651 writing sessions) with code benchmarks drawn from CodeXGlue
(
Lu et al. 2021
)
. For the Java→C# translation task we use the full CodeXGlue split, which comprises 8 701 training, 431 validation, and 836 test examples. For Java code completion we randomly sample 20% of the CodeXGlue Java completion dataset (1 633 train / 1 005 valid / 1 318 test), and for Java → NL summarization we sample 10% of the CodeXGlue Java summarization dataset (16 490 train / 518 valid / 1 095 test).

4.3.
Evaluation Metrics

We assess our models along two dimensions: task performance (translation, completion, summarization) and attention alignment (see Section
5.5
).

Translation and completion metrics.
For both Java→C# translation and Java code completion, we report:

•

Hybrid Exact Match (H
-
Exact)

\mathrm{H\text{-}Exact}=0.5\,\mathrm{ExactMatch}+0.5\,\mathrm{SubstringMatch}
,
where
\mathrm{ExactMatch}
is the strict token match rate and
\mathrm{SubstringMatch}
allows partial overlaps.

•

CodeBLEU

(
Ren et al. 2020
)
, the mean of four sub-scores: n
-
gram match, weighted n
-
gram match, AST similarity and flow similarity.

•

CrystalBLEU

(
Eghbali and Pradel 2022
)
, a BLEU
-
based metric that ignores trivially shared n
-
grams to improve semantic distinguishability while preserving language
-
agnostic efficiency.

Summarization metrics.
For code summarization, we use:

•

ROUGE
-
L
, the F1 score over the longest common subsequence between system and reference.

•

METEOR
, the harmonic mean of precision and recall over exact, stem and synonym matches, with a fragmentation penalty.

•

BERTScore
, which computes F1 by averaging cosine similarities of contextual token embeddings from a pretrained BERT encoder.

Attention alignment metrics

Let
\mathbf{a}=(a_{1},\dots,a_{n})
be the normalized final-layer attention over the
n
input tokens,
C
the set of semantically critical token indices, and
k=20
. We measure:

•

Generation Confidence Score (GCS)
:

\displaystyle\frac{1}{T}\sum_{t=1}^{T}\log P(y_{t}\mid y_{<t},x)
, where
y
are the
T
generated tokens.

•

Recency Focus Score (RFS)
:

\displaystyle\frac{\sum_{i=n-k+1}^{n}a_{i}}{\sum_{i=1}^{n}a_{i}}
, the fraction of attention on the last
k
tokens.

•

Average Focus Score (AFS)
:

\displaystyle\frac{1}{|C|}\sum_{i\in C}a_{i}
, the mean attention weight on critical tokens.

•

Attention Entropy
:

\displaystyle-\sum_{i=1}^{n}a_{i}\log a_{i}
, capturing the dispersion of the attention distribution.

6.
Threats to Validity

While we have adopted rigorous methods to ensure reliable results, several factors could still influence the robustness and applicability of
EyeMulator
. In particular, the precision of our eye-tracking setup, the representativeness of our developer sample and the assumptions underlying our attention artifacts each introduce potential biases. By outlining these threats we aim to contextualize our findings and identify priorities for future validation and refinement.

Internal validity
The eye-tracking data may suffer from calibration inaccuracies, unmapped fixations and constrained viewing conditions in the laboratory. To mitigate these we discard outliers (approximately 3% of fixations), use a high precision tracker with mean error below
0.4^{\circ}
and apply Bayesian smoothing to our semantic salience estimates. Even so, our pseudo attention masks and n gram transition tables remain algorithmic approximations that may not capture all nuances of natural gaze behaviour.

External validity
This study relies on a single open source Java corpus and recordings from twenty seven student programmers, which may not reflect professional workflows, diverse code bases or other programming languages. To address this limitation we plan to evaluate
EyeMulator
on industry data sets, additional languages such as Python and C# and in situ IDE sessions with professional developers.

Construct validity
Our attention artifacts encode where developers look but do not reveal why those code elements attract focus or how deeply they are processed. We use Direct Preference Optimization as a proxy for developer priorities under the assumption that higher salience scores correspond to greater importance. However this simplification may overlook subtle cognitive reasoning steps, suggesting the need for future qualitative studies and multimodal analysis.

7.
Discussion and Future Work

Building on our results with one billion parameter models,
EyeMulator
opens several avenues for enhancement and real
-
world deployment, including scaling to larger backbones, broadening task and language support, and integrating human attention priors into diverse training paradigms and development tools.

Model scalability
Our method is architecture agnostic and can be applied to larger pre trained code models (for example seven or thirteen billion parameters) without changing the network backbone, since attention priors are injected as additional inputs or prompt augmentations. We expect similar or greater performance gains, but have not yet conducted these experiments due to limited compute resources. Future work will secure cloud GPU clusters and employ parameter efficient fine tuning techniques to evaluate
EyeMulator
at scale.

Framework expansion
We will adapt
EyeMulator
to additional languages such as Python and C# and to new code intelligence tasks such as bug localization, test generation and code review. We will investigate gaze aware pre training objectives that integrate token salience into masked token and fill in the middle learning. We will prototype real time IDE integration using low cost camera based gaze estimation to tailor code completions and documentation suggestions during editing.

Evaluation and scaling
To assess practical utility, we will conduct field studies with professional developers measuring productivity, code quality and user satisfaction. We aim to enrich our behavioral signals by combining gaze data with keystroke dynamics and think aloud protocols. To scale beyond laboratory settings we will develop semisupervised automated gaze collection pipelines that preserve privacy and enable large scale corpus creation for future human aware code models.

Recent studies have incorporated eye-tracking data to guide model focus—most notably EyeTrans—but have not distilled gaze patterns into reusable priors across tasks. Retrieval-augmented methods (e.g., RAG) and neural completion techniques leverage external examples or learned patterns, yet omit human cognitive cues. EyeMulator unifies these directions by integrating distilled attention priors, n

-

Dou et al. 2024

EyeMulator

Collectively, these methods are vital for tuning models to nuanced developer judgments that encompass code clarity, efficiency, and maintainability
(
Wang et al. 2023
;
Kirk et al. 2023
;
Wang et al. 2024a
)
