Semantics of Sets of Programs
Jinwoo Kim, Shaan Nagy, Thomas Reps, Loris D’Antoni

Abstract
. Applications like program synthesis sometimes require proving that a property holds for all of the infinitely many programs described by a grammar—i.e., an inductively defined set of programs. Current verification frameworks overapproximate programs’ behavior when sets of programs contain loops, including two Hoare-style logics that fail to be relatively complete when loops are allowed. In this work, we prove that compositionally verifying simple properties for infinite sets of programs requires tracking distinct program behaviors over unboundedly many executions. Tracking this information is both necessary and sufficient for verification. We prove this fact in a general, reusable theory of denotational semantics that can model the expressivity and compositionality of verification techniques over infinite sets of programs. We construct the minimal compositional semantics that captures simple properties of sets of programs and use it to derive the first sound and relatively complete Hoare-style logic for infinite sets of programs. Thus, our methods can be used to design minimally complex, compositional verification techniques for sets of programs.

1.
Introduction

The central problem of this work is to understand what formal semantics are needed when verifying infinite sets of imperative programs.

Example 1 (Verifying a Set of Imperative Programs).

Consider the following grammar, which defines a set
L(W)
of loops:

\displaystyle W

\displaystyle::=\mathsf{while}\;{x<E}\;\mathsf{do}\;{x:=x+1}

\displaystyle E

\displaystyle::=0~|~E+2

Can we prove that, for every loop
w\in L(W)
, running
w
on the initial value
x=0
results in a final state in which
x
is even?

The need to verify
a property of an infinite set of programs
appears in several domains.
For example, in language-wide verification, one may wish to prove that every program in a given domain-specific language
terminates or satisfies some safety property.
Another example is verifying programs that contain constructs like
eval
,
which load code as a string/tree at run time and dynamically execute it.
In this setting, one may need to reason about
infinitely many possible strings/trees that represent programs and are passed to
eval

(
Malmkjær, 1993
)
.
A third example, and the main motivation behind our work, is proving unrealizability of program-synthesis problems
(
Kim et al., 2023
)
,
where the goal is to determine whether all programs in a search space satisfy the negation of a given specification—i.e., no program in the search space matches the desired specification.
Unrealizability of program-synthesis problems can be used to speed up program synthesis and also to prove optimality of a program
c
with respect to a given metric
(
Hu and D’Antoni, 2018
)
—i.e., by
showing that the problem of synthesizing a program that is better than
c
is unrealizable.

While there are many techniques to prove that a
particular
loop
w\in L(W)
satisfies the specification given in Example
1
, no verification technique that we are aware of can prove that the specification holds for

all

w\in L(W)
.

Our two main goals in this paper are: (
i
) to present a fundamental theoretical
obstacle that
makes it hard to design effective frameworks for reasoning about extensional properties (i.e., input-output properties) of sets of deterministic imperative programs with loops (e.g.
Example

1
), and (
ii
) in light of this obstruction, to present a provably simplest semantic basis for designing verification techniques. To ground our study, we first consider reasoning about
individual imperative programs.

Denotational Semantics for Single Imperative Programs

Formal verification can always be defined with respect to a denotational semantics—i.e.,
a map that assigns a mathematical object, called a denotation, to each program.
These denotations
capture the program information one is interested in studying.
A familiar example of
a denotation is a

state transformer
—i.e., a function (or relation) that captures how a program maps input states to output states.

In this paper, we are interested in understanding how powerful denotations must be
to capture extensional properties for sets of programs.
For a
single program

c
, an

extensional property

is a property of the relation between inputs and outputs captured by the state transformer of
c
.
1
1

1

In this paper, we use
c
to refer to arbitrary single programs (i.e., program statements or expressions). We use
s
to refer specifically to program statements (derivable from
\mathit{Stmt}
in the grammar given in
Figure

3
). Similarly, we use
C
to refer to sets of programs, and we use
S
to refer to sets of program statements.

For example, monotonicity and commutativity are extensional properties—they are
direct properties of the mathematical relation that the state transformer assigned to
c
induces.
On the other hand, program text size or running time of the program are
not
extensional properties—they are unrelated to the input-output relation described by
c
.

To reason about extensional properties
of individual deterministic imperative programs, one often uses a semantics that maps every syntactic program to a partial function mapping input program states
\sigma
to output program states
(
Stoy, 1977
;
Schmidt, 1986
)
, illustrated in the following example:

(1)

\llbracket{{{x}\ \mathsf{:=}\ {10}}}\rrbracket=\lambda\sigma.\sigma[{x}\mapsto{10}]

This semantics is the simplest one that expresses single-input extensional properties (i.e., the output
state of the program on a given single input state
\sigma
). Despite its simplicity, this denotational semantics boasts two key properties that enable effective verification techniques to be built on top of it, the second of which enables the first:

Compositionality.:

The denotational semantics of a complex program can be expressed precisely in terms of the semantics of its subprograms, as shown by the following example:

\llbracket{{{{x}\ \mathsf{:=}\ {10}}}{\mathsf{;}}\ {{{y}\ \mathsf{:=}\ {12}}}}\rrbracket=\llbracket{{{y}\ \mathsf{:=}\ {12}}}\rrbracket\circ\llbracket{{{x}\ \mathsf{:=}\ {10}}}\rrbracket

Expression of Multiple Executions.:

The semantics of a program is capable of describing how the program acts on multiple different input states. For example, to understand how
c
acts on two states rather than just one, one need not define a new semantics. Instead,
one can apply
\llbracket{c}\rrbracket
to each state:

(2)

(\sigma_{1},\sigma_{2})\mapsto(\llbracket{c}\rrbracket(\sigma_{1}),\llbracket{c}\rrbracket(\sigma_{2}))

Both traits
are desirable for program analysis and verification.
Compositionality enables scalable program analysis:
a program can be analyzed by decomposing the original analysis into simpler ones over
smaller subprograms.
Expression of multiple executions enables compositionality over constructs that repeatedly execute code (e.g., while loops):
to determine the behavior of a while loop “
\mathsf{while}\;{b}\;\mathsf{do}\;{s}
” on an input state
\sigma
compositionally,
one must understand how
b
and
s
behave on every state that appears in a loop iteration.
For example, to see that

\llbracket{\mathsf{while}\;{x<2}\;\mathsf{do}\;{x:=x+1}}\rrbracket({x\mapsto 0})

=({x\mapsto 2})
,
one must observe multiple executions of the guard and body:

\llbracket{x{<2}}\rrbracket({x\mapsto 0})~=~t

\longrightarrow

\llbracket{x:=x{+}1}\rrbracket({x\mapsto 0})~=~({x\mapsto 1})

\swarrow

\llbracket{x{<2}}\rrbracket({x\mapsto 1})~=~t

\longrightarrow

\llbracket{x:=x{+}1}\rrbracket({x\mapsto 1})~=~({x\mapsto 2})

\swarrow

\llbracket{x{<2}}\rrbracket({x\mapsto 2})~=~f

Although one might take the power to express
multiple executions for granted in this single-program semantics,
it turns out to be surprisingly hard to design a semantics of
sets
of programs that can express multiple executions for multiple programs
at once
.
The reason is that
“natural” extensions lifting single-program semantics to
semantics for sets of programs tend to mix the outputs of
different programs together, making it hard to tell
when two possible outputs on two different inputs can be produced by the same program.
As a result, it is hard to design a compositional semantics for a set of programs when the programs can contain loops.

Challenges in Designing a Denotational Semantics for Sets of Imperative Programs

Taking inspiration from the properties of denotational semantics of individual programs, this paper addresses the following objective:

Design a
compositional
semantics for
sets of programs
that can express
extensional properties
.

The simplest extensional properties are

single-input extensional properties
,
which for a single program
c
,
are the facts
that can be
deduced
by computing
\llbracket{c}\rrbracket(\sigma)
on some
state
\sigma
.
To generalize single-input extensional properties to a set of programs
C
, our first attempt is a straightforward lifting of the single-program semantics in
Equation

1
—which we call
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
, the “program-agnostic” semantics for sets of programs.
Whereas
\llbracket{c}\rrbracket
has the signature
\mathsf{State}\rightarrow\mathsf{State}
,
the signature of

\langle\!\langle{C}\rangle\!\rangle^{\mathbf{a}}
must be

2^{\mathsf{State}}\rightarrow 2^{\mathsf{State}}

because
C
may generate multiple outputs for a single input
(i.e., one for each
c\in C
).
To maintain compositionality on, e.g., sequential composition (
{S_{1}}{\mathsf{;}}\ {S_{2}}
),

\langle\!\langle{C}\rangle\!\rangle^{\mathbf{a}}
must have signature

2^{\mathsf{State}}\rightarrow 2^{\mathsf{State}}
—that is,

single-input
extensional properties require reasoning about

sets
of inputs in the case of sets of programs.
Then on a given set of input states
P
,
\langle\!\langle{C}\rangle\!\rangle^{\mathbf{a}}

returns the set of all output states that programs in
C
can generate:

(3)

\langle\!\langle{C}\rangle\!\rangle^{\mathbf{a}}=\lambda P.\{\llbracket{c}\rrbracket(p)\mid c\in C,p\in P\}

(In this paper, we will use
\langle\!\langle{\cdot}\rangle\!\rangle
—typically with a distinguishing superscript, such as

\langle\!\langle{C}\rangle\!\rangle^{\mathbf{a}}
—to denote a
semantics that operates over a set of programs.)

\langle\!\langle{C}\rangle\!\rangle^{\mathbf{a}}
, as defined in
Equation

3
,
has been used implicitly in prior work as the basis of relatively incomplete
Hoare-style logics for sets of programs without loops
(
Kim et al., 2023
;
Nagy et al., 2024
)
.
Crucially,
Equation

3
is the
least-expressive
semantics
(formally, the
coarsest-grained
semantics [see
Definition

10
])
that captures single-input extensional properties of sets of programs.
In other words,
Equation

3
is the least-expressive semantics
that can specify the set of all possible output states
that can be produced by running some program in
C
on a single given input state
\sigma
.
Thus, it is reasonable to say that a useful verification technique
for sets of programs should capture
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
at a minimum.

As with
\llbracket{\cdot}\rrbracket
, the semantics for sets

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
must also be capable of
expressing multiple executions to achieve compositionality for loops.
However, for sets of programs,
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
is surprisingly
too weak
to be
compositional for loops: it cannot capture the semantics of multiple executions with sufficient precision.
The first contribution of this paper is a
formal
proof that although the semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}

is compositional for sets of loop-free programs (
Theorem

3
),

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
is not compositional for sets of programs that are allowed to contain loops (
Theorem

4
).
The non-compositionality of
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
is due to the fact that,
for a set of loops
\mathsf{while}\;{B}\;\mathsf{do}\;{S}
,
it is not always possible
to derive
\langle\!\langle{\mathsf{while}\;{B}\;\mathsf{do}\;{S}}\rangle\!\rangle^{\mathbf{a}}
from only
\langle\!\langle{B}\rangle\!\rangle^{\mathbf{a}}
and
\langle\!\langle{S}\rangle\!\rangle^{\mathbf{a}}
,
because
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
cannot
precisely express multiple executions

of individual programs in
B
or
S
.

To see why
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
cannot precisely express multiple executions, suppose that the set
S=\{{\color[rgb]{1,0.5,0}s_{1}},{\color[rgb]{0,1,1}s_{2}}\}
contains two statements,
and we are given two input states
\sigma_{i}
and
\sigma_{j}
.
We want to combine
\langle\!\langle{S}\rangle\!\rangle^{\mathbf{a}}(\sigma_{i})
and
\langle\!\langle{S}\rangle\!\rangle^{\mathbf{a}}(\sigma_{j})
to produce the set
\{(\llbracket{{\color[rgb]{1,0.5,0}s_{1}}}\rrbracket(\sigma_{i}),\llbracket{{\color[rgb]{1,0.5,0}s_{1}}}\rrbracket(\sigma_{j})),(\llbracket{{\color[rgb]{0,1,1}s_{2}}}\rrbracket(\sigma_{i}),\llbracket{{\color[rgb]{0,1,1}s_{2}}}\rrbracket(\sigma_{j}))\}
, which tells us what can happen if we run each program in
S
on both
\sigma_{i}
and
\sigma_{j}
.
In
Equation

2
, our semantics produced a single output state, so we directly combined the results into a tuple of states. Because
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
returns a
set
of output states, we must take the Cartesian product of
\langle\!\langle{S}\rangle\!\rangle^{\mathbf{a}}(\{\sigma_{i}\})
and
\langle\!\langle{S}\rangle\!\rangle^{\mathbf{a}}(\{\sigma_{j}\})
to get a set of tuples of states:

\displaystyle(\sigma_{i},\sigma_{j})\mapsto

\displaystyle\langle\!\langle{S}\rangle\!\rangle^{\mathbf{a}}(\{\sigma_{i}\})\times\langle\!\langle{S}\rangle\!\rangle^{\mathbf{a}}(\{\sigma_{j}\})

\displaystyle=\{\llbracket{{\color[rgb]{1,0.5,0}s_{1}}}\rrbracket(\sigma_{i}),\llbracket{{\color[rgb]{0,1,1}s_{2}}}\rrbracket(\sigma_{i})\}\times\{\llbracket{{\color[rgb]{1,0.5,0}s_{1}}}\rrbracket(\sigma_{j}),\llbracket{{\color[rgb]{0,1,1}s_{2}}}\rrbracket(\sigma_{j})\}

\displaystyle=\{(\llbracket{{\color[rgb]{1,0.5,0}s_{1}}}\rrbracket(\sigma_{i}),\llbracket{{\color[rgb]{1,0.5,0}s_{1}}}\rrbracket(\sigma_{j})),(\llbracket{{\color[rgb]{1,0.5,0}s_{1}}}\rrbracket(\sigma_{i}),\llbracket{{\color[rgb]{0,1,1}s_{2}}}\rrbracket(\sigma_{j})),(\llbracket{{\color[rgb]{0,1,1}s_{2}}}\rrbracket(\sigma_{i}),\llbracket{{\color[rgb]{1,0.5,0}s_{1}}}\rrbracket(\sigma_{j})),(\llbracket{{\color[rgb]{0,1,1}s_{2}}}\rrbracket(\sigma_{i}),\llbracket{{\color[rgb]{0,1,1}s_{2}}}\rrbracket(\sigma_{j}))\}

The
orange
-only
(\llbracket{{\color[rgb]{1,0.5,0}s_{1}}}\rrbracket(\sigma_{i}),\llbracket{{\color[rgb]{1,0.5,0}s_{1}}}\rrbracket(\sigma_{j}))
and
cyan
-only
(\llbracket{{\color[rgb]{0,1,1}s_{2}}}\rrbracket(\sigma_{i}),\llbracket{{\color[rgb]{0,1,1}s_{2}}}\rrbracket(\sigma_{j}))
outcomes reflect the programs
s_{1}
and
s_{2}
, but the outcomes with two colors—i.e.,
(\llbracket{{\color[rgb]{1,0.5,0}s_{1}}}\rrbracket(\sigma_{i}),\llbracket{{\color[rgb]{0,1,1}s_{2}}}\rrbracket(\sigma_{j}))
and
(\llbracket{{\color[rgb]{0,1,1}s_{2}}}\rrbracket(\sigma_{i}),\llbracket{{\color[rgb]{1,0.5,0}s_{1}}}\rrbracket(\sigma_{j}))
—do not correspond to any single program in
S
.
The semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
does not track which programs produce which output states (i.e., it is program-agnostic), so it cannot tell whether or not a given pair of output states
(\sigma^{\prime}_{i},\sigma^{\prime}_{j})\in\langle\!\langle{S}\rangle\!\rangle^{\mathbf{a}}(\{\sigma_{i}\})\times\langle\!\langle{S}\rangle\!\rangle^{\mathbf{a}}(\{\sigma_{j}\})
is produced by the same program
s\in S
.

As a result,
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
is not compositional over sets of programs containing loops.
In practice, this
property
means that, given
\langle\!\langle{B}\rangle\!\rangle^{\mathbf{a}}
and
\langle\!\langle{S}\rangle\!\rangle^{\mathbf{a}}
,
one cannot distinguish the set of loops
\mathsf{while}\;{B}\;\mathsf{do}\;{S}

from the singleton set containing the nondeterministic program
\mathsf{while}\;{choose(B)}\;\mathsf{do}\;{choose(S)}
,
which nondeterministically chooses an expression from
B

and program statement from
S
on every loop iteration.
Note that, in the absence of loops, sets of programs can usually be modeled as a single
nondeterministic program
(
Hu et al., 2019
)
.

Compositional Denotational Semantics for Sets of Imperative Programs

To resolve the noncompositionality of
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
, we must design a more expressive semantics that explicitly tracks
the effects of programs on multiple inputs.
Our next contribution is a “vector-state semantics,”
denoted by
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
,
which meets the above goal by mapping sets of input vectors of states
P
to sets of output
vectors that programs in
C
can produce when applied to each entry of an input vector:

\langle\!\langle{C}\rangle\!\rangle^{\mathbf{v}}=\lambda P.\{[\llbracket{c}\rrbracket(\sigma_{1}),\cdots,\llbracket{c}\rrbracket(\sigma_{n})]\mid c\in C,[\sigma_{1},\cdots,\sigma_{n}]\in P\}

Unlike the program-agnostic semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
, the vector-state semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
is capable of precisely expressing multiple executions.
The key difference is that the vectorized input-states group inputs together, preventing the loss of precision that occurred by taking Cartesian products when we attempted to
express multiple executions using
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
.
As an illustration,
taking the set of statements
S=\{{\color[rgb]{1,0.5,0}s_{1}},{\color[rgb]{0,1,1}s_{2}}\}
as before, the vectorized semantics yields the following behavior:

\displaystyle(\sigma_{1},\sigma_{2})\mapsto

\displaystyle\langle\!\langle{S}\rangle\!\rangle^{\mathbf{v}}(\{[\sigma_{1},\sigma_{2}]\})

\displaystyle=\{[\llbracket{s}\rrbracket(\sigma_{1}),\llbracket{s}\rrbracket(\sigma_{2})]\mid s\in S\}

\displaystyle=\{[\llbracket{{\color[rgb]{1,0.5,0}s_{1}}}\rrbracket(\sigma_{1}),\llbracket{{\color[rgb]{1,0.5,0}s_{1}}}\rrbracket(\sigma_{2})],[\llbracket{{\color[rgb]{0,1,1}s_{2}}}\rrbracket(\sigma_{1}),\llbracket{{\color[rgb]{0,1,1}s_{2}}}\rrbracket(\sigma_{2})]\}

The main contribution of this paper is to show that
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
is compositional, even over sets of loops (
§

5.2.2
) and is the coarsest-grained (i.e., least expressive)
compositional semantics that is stronger than
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
(
§

5.2.2
). Thus, the vector-state semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
is the simplest semantics that can serve as the foundation of a compositional verification framework for sets of programs.

Taken together, our results show that a complete, compositional verification framework for sets of programs that can capture single-input extensional properties must capture at least
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
. This result sets a lower bound on the expressivity of complete, compositional verification frameworks for sets of programs.
Whether a framework abandons completeness, abandons compositionality, removes loops from the language under consideration, or adopts the complexity of the vector-state semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
is a design choice to be made on a case-by-case basis.

Relationship to Program Synthesis

Readers familiar with program synthesis may wonder how single-input extensional properties
tie in with program-synthesis problems, where specifications are often written over
multiple examples, as in programming-by-example (PBE)
(
Solar-Lezama, 2013
;
Gulwani, 2011
)
.
Single-input extensional properties correspond to single-example synthesis problems.
Later, in
§

5.2
, we discuss how
the vector-state semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}

can be viewed as an extension of
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
that supports reasoning about finitely many inputs simultaneously,
allowing the vector-state semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
to model multiple-input PBE problems as well.

In this section, we demonstrate the utility of our theory by deriving semantics

(

2.1.
A Program Logic for Sets of Programs

A program logic (e.g., Hoare Logic
(
Hoare, 1969
)
) is a proof system for reasoning about program properties.
In this case study, the goal is to design a program logic
L
for reasoning about
single-input extensional properties of sets of programs.
Previous attempts at designing such a logic
(
Kim et al., 2023
;
Nagy et al., 2024
)
have resulted in incomplete logics,
due to implicitly basing the logics on
\langle\!\langle{C}\rangle\!\rangle^{\mathbf{a}}
from
§

1
; we illustrate
why exactly this is the case, providing an outline here and more formal details in
§

6
.

To design such a logic, one needs to define
(
i
) some kind of meaningful judgments (
J(C)
) about sets of programs
C
, and
(
ii
) inference rules that allow the logic to prove new judgments
from known judgments or axioms, for example,

(4)

\vdash J_{3}(\mathsf{while}\;{B}\;\mathsf{do}\;{S})\vdash J_{1}(B)\quad\vdash J_{2}(S)

where
B
is a set of Boolean expressions,
S
is a set of statements.
Critically, the inference rules should be compositional:
for example,
any valid judgment about the set
\mathsf{while}\;{B}\;\mathsf{do}\;{S}

should be derivable from valid judgments about
B
and
S
, as in
Equation

4
.

Existing Logics’ Judgments are Noncompositional

In the logic proposed by Nagy et al.
(
Nagy et al., 2024
)
, judgments are triples,
denoted by
\{\kern-2.15277pt|{P}|\kern-2.15277pt\}\>C\>\{\kern-2.15277pt|Q|\kern-2.15277pt\}
, where
C
is a set of programs, and
P
and
Q
are sets of states.
In terms of semantics,
the meaning of
this kind of triple can be written as follows:

(5)

\{\kern-2.15277pt|{P}|\kern-2.15277pt\}^{\mathbf{a}}\>C\>\{\kern-2.15277pt|Q|\kern-2.15277pt\}^{\mathbf{a}}\triangleq\langle\!\langle{C}\rangle\!\rangle^{\mathbf{a}}(P)\subseteq Q

Other prior work interprets triples slightly differently but relies on the same intuition
(
Kim et al., 2023
)
.

Observe that a denotational semantics over a set of programs is just a map that assigns to each
set of programs
C
a mathematical object
associated with
C

(i.e., its denotation).
Thus, one can also define a
“logic-based”
semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{La}
that associates with
C

the set of valid judgments about
C
:

(6)

\langle\!\langle{C}\rangle\!\rangle^{La}\triangleq\{{(P,Q)\mid~\{\kern-2.15277pt|{P}|\kern-2.15277pt\}^{\mathbf{a}}\>C\>\{\kern-2.15277pt|Q|\kern-2.15277pt\}^{\mathbf{a}}\text{ holds}}\}

Under this definition,
the logic-based semantics

\langle\!\langle{\cdot}\rangle\!\rangle^{La}
and
the program-agnostic semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
carry the same information:

\langle\!\langle{C}\rangle\!\rangle^{La}
can be derived from
\langle\!\langle{C}\rangle\!\rangle^{\mathbf{a}}
and vice versa.

Previous work has failed to find relatively complete, compositional inference rules for a logic over such triples. Our theory proves that such rules do not exist: because both the program-agnostic semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
and the logic-based semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{La}
carry the same information, noncompositionality of the program-agnostic semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}

(see
Theorem

4
) implies noncompositionality of
the logic-based semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{La}
.
The non-compositionality of
\langle\!\langle{\cdot}\rangle\!\rangle^{La}
implies that there is
no complete system of compositional inference rules for such triples (see
§

6
)!

More concretely, there are sets of Boolean guards
B
and loop bodies
S
for which there exist true triples
\{\kern-2.15277pt|{P}|\kern-2.15277pt\}^{\mathbf{a}}\>\mathsf{while}\;{B}\;\mathsf{do}\;{S}\>\{\kern-2.15277pt|Q|\kern-2.15277pt\}^{\mathbf{a}}
that cannot be proven from any true triples about
B
and
S
.
For example, if
B=\{x==1,\neg(x==1)\}
then we cannot compositionally prove the triple

(7)

\{\kern-2.15277pt|{x=0}|\kern-2.15277pt\}^{\mathbf{a}}\>(\mathsf{while}\;{\{x==1,\neg(x==1)\}}\;\mathsf{do}\;{{{x}\ \mathsf{:=}\ {x+1}}})\>\{\kern-2.15277pt|x=0\lor x=1|\kern-2.15277pt\}^{\mathbf{a}}

Without the ability to track the effects of programs on multiple inputs, the set of guards
B
is indistinguishable from the set of guards
B^{\prime}=\{x==2,\neg(x==2)\}
,
because both sets can produce
{{\mathsf{true}}}
and
{{\mathsf{false}}}
on any input state (i.e.,
\langle\!\langle{B}\rangle\!\rangle^{\mathbf{a}}=\langle\!\langle{B^{\prime}}\rangle\!\rangle^{\mathbf{a}}
so
\langle\!\langle{B}\rangle\!\rangle^{La}=\langle\!\langle{B^{\prime}}\rangle\!\rangle^{La}
).
In other words, every triple that is true of
B
is true of
B^{\prime}
.
However, changing the set of guards from
B
to
B^{\prime}
invalidates the triple in
Equation

7
(i.e.,
\{\kern-2.15277pt|{x=0}|\kern-2.15277pt\}^{\mathbf{a}}\>(\mathsf{while}\;{B^{\prime}}\;\mathsf{do}\;{{{x}\ \mathsf{:=}\ {x+1}}})\>\{\kern-2.15277pt|x=0\lor x=1|\kern-2.15277pt\}^{\mathbf{a}}
is false because
x=2
is a possible outcome). A compositional logic that cannot distinguish
between

B
and
B^{\prime}
also cannot distinguish
between

\mathsf{while}\;{B}\;\mathsf{do}\;{{{x}\ \mathsf{:=}\ {x+1}}}
and
\mathsf{while}\;{B^{\prime}}\;\mathsf{do}\;{{{x}\ \mathsf{:=}\ {x+1}}}
, so no compositional logic can prove the
triple given in
Equation

.

Compositional Triples via Vector-State Semantics

To design a compositional logic, we need to strengthen our triples. Our new triples must yield a semantics that is at least as expressive as the vector-state semantics

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}

Following

Noncompositionality of a Simple Interpreter

To analyze the extensional properties of a syntactically defined set of programs
C
,
one can compute
\llbracket{\mathtt{interpret}}\rrbracket(C\times P)

given an arbitrary set of inputs
P
.
This approach is equivalent to deriving a Hoare triple of the form:

\{{t\in C\land x\in P}\}\>y=\mathtt{interpret}(t,x)\>\{y\in Q\}.

For example, to understand the possible outputs of the set of loops
W
from
Example

1
on the input
({x\mapsto 0})
, one can
prove

\{{t\in W\land x=0}\}\>y=\mathtt{interpret}(t,x)\>\{y=0\pmod{2}\}.

However, reasoning about such triples can be complicated.
Cartesian preconditions of the form
t\in C\land x\in P

can check membership of an input
(t,x)
in the precondition by checking

t\in C
and
x\in P

independently
.
Critically, because
C
is defined syntactically and

P
cannot reference
t
, one cannot relate the syntax of
t
to its semantics
\llbracket{t}\rrbracket
inside the precondition.
Observe that Cartesian preconditions have a direct correspondence with the program-agnostic semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
:
a triple

\{{t\in C\land x\in P}\}\>\mathtt{interpret}(t,x)\>\{Q\}
holds iff
\langle\!\langle{C}\rangle\!\rangle^{\mathbf{a}}(P)\subseteq Q
.
Unfortunately, when
\mathtt{t}
contains a loop, such Cartesian preconditions often cannot be proven without using substantially more complicated
“non-Cartesian” preconditions that relate
\mathtt{t}
and
\mathtt{x}
.
In this situation, we no longer have a direct correspondence between Hoare triples and
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
, which corresponds to reasoning about complex properties outside the program-agnostic semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
.

For example, consider proving the triple
\{{t\in\mathsf{while}\;{B}\;\mathsf{do}\;{S}\land x\in P}\}\>y=\mathtt{interpret}(t,x)\>\{y\in Q\}
.
Analysis is straightforward until
Line

9
of
Figure

2
, emphasized in
red
, where the semantics of a loop
requires that the same
\mathtt{b}\in B
and
\mathtt{s}\in S
be

repeated
for each iteration of a loop.
Upon reaching
Line

9
, there is a relation formed with the input state and the program:

\mathtt{x}_{1}

is created using a specific combination of
\mathtt{b}\in B
and
\mathtt{s}\in S
, such that

\llbracket{\mathtt{b}}\rrbracket(\mathtt{x}_{0})={{\mathsf{true}}}

and

\llbracket{\mathtt{s}}\rrbracket(\mathtt{x}_{0})=\mathtt{x}_{1}
,
for some input state
\mathtt{x}_{0}
.
Thus, the precondition over which the recursive call to
\mathtt{interpret}
must operate becomes:

(10)

(\mathtt{t},\mathtt{x})\in\{{(\mathtt{while\ b\ do\ s},\texttt{x}_{1})\mid\mathtt{b}\in B\wedge\mathtt{s}\in S\wedge(\exists\mathtt{x}_{0}\in P.\llbracket{\mathtt{b}}\rrbracket(\mathtt{x}_{0})={{\mathsf{true}}}\wedge\llbracket{\mathtt{s}}\rrbracket(\mathtt{x}_{0})=\mathtt{x}_{1})}\}

Although
t\in\mathsf{while}\;{B}\;\mathsf{do}\;{S}\land x\in P
was initially a Cartesian precondition,

Equation

10
is not—the additional condition

\exists\mathtt{x}_{0}\in P.\llbracket{\mathtt{b}}\rrbracket(\mathtt{x}_{0})={{\mathsf{true}}}\wedge\llbracket{\mathtt{s}}\rrbracket(\mathtt{x}_{0})=\mathtt{x}_{1}

forces our precondition to reason about both the syntax of our programs (e.g.,
s\in S
) as well as their semantic effects (i.e.,
\llbracket{\mathtt{s}}\rrbracket(\mathtt{x}_{0})=\mathtt{x}_{1}
).
This entanglement requires a complex notion of ‘interpretation’
\llbracket{\cdot}\rrbracket
in our precondition that one would expect analysis of an interpreter to avoid.

Reasoning about non-Cartesian preconditions
is actually an unavoidable feature of every
correct recursive implementation of
\mathtt{interpret}:\mathsf{Prog}\times\mathsf{State}\rightarrow\mathsf{State}

(
Theorem

6
).
To understand why this observation holds,
consider an interpreter-based semantics

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathtt{interpret}_{a}}
akin to
\langle\!\langle{\cdot}\rangle\!\rangle^{La}
in
§

2.1
:

(11)

\langle\!\langle{C}\rangle\!\rangle^{\mathtt{interpret}_{a}}=\{{(P,Q)\mid\{{\mathtt{t}\in\ C\wedge\mathtt{x}\in P}\}\>y=\mathtt{interpret}(t,x)\>\{Q\}\text{ is true}}\}

If one could prove every Cartesian triple with a Hoare-logic proof using only Cartesian triples,
one would be able to derive a compositional characterization of
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathtt{interpret}_{a}}
.
However,
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathtt{interpret}_{a}}
is noncompositional
because it is equivalent to the noncompositional program-agnostic semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
,
just like the logic-based semantics

\langle\!\langle{\cdot}\rangle\!\rangle^{La}
.
Consequently, reasoning about non-Cartesian preconditions like
Equation

10

is unavoidable for
any
recursive implementation of
\mathtt{interpret}:\mathsf{Prog}\times\mathsf{State}\rightarrow\mathsf{State}

(see
Theorem

6
for a proof).

Complete Interpreter Analysis

To precisely reason about all facts of the form
\llbracket{\mathtt{interpret}}\rrbracket(C\times P)
with Hoare logic, one can either
(
i
) accept the complexity of non-Cartesian preconditions or
(
ii
) extend the signature of
\mathtt{interpret}
so that
\mathtt{x}
is a vector-state rather than a single input
(i.e.,
\mathtt{interpret}_{v}:\mathsf{Prog}\times\mathsf{State}^{*}\rightarrow\mathsf{State}^{*}
).
In the second case, this new interpreter induces a semantics:

(12)

\langle\!\langle{C}\rangle\!\rangle^{\mathtt{interpret}_{v}}=\{{(P,Q)\mid\{{\mathtt{t}\in\ C\wedge\mathtt{x}\in P}\}\>\mathtt{interpret}_{v}(t,x)\>\{Q\}\text{ is true}}\},

which is equivalent to the vector-state semantics

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
.
Because

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
is compositional (
§

5.2.2
),
there will also exist a Hoare-style analysis of
\mathtt{interpret}_{v}

that stays within the realm of Cartesian preconditions—at the cost of introducing vector-states.
Alternatively, one could forego completeness in exchange for
a simple and compositional analysis.
For example, in
Equation

10
, one could disallow
conditions such as

\exists\mathtt{x}_{0}\in P.\llbracket{\mathtt{b}}\rrbracket(\mathtt{x}_{0})={{\mathsf{true}}}\wedge\llbracket{\mathtt{s}}\rrbracket(\mathtt{x}_{0})=\mathtt{x}_{1}

and only consider preconditions that are Cartesian.
This approach would enlarge the possible input states to subsequent calls of
\mathtt{interpret}
, resulting in an imprecise, but still sound, analysis.

Definition 1 (Regular Tree Grammar).

A

G=(\mathcal{N},\mathcal{A},\mathit{Start},a,\delta)

\mathcal{N}
is a finite set of nonterminals;

\mathcal{A}

\mathit{Start}\in\mathcal{N}

\mathcal{A}\cup\mathcal{N}

and
\delta

where for

is a nonterminal
such that if
a_{\alpha^{(i)}}=(\tau_{0},\tau_{1},...,\tau_{i})
then
a_{N_{j}}=\tau_{j}
.

Definition 2 (Inductively Defined Set of Programs).

Given a set of programs
C
and an RTG
G
with start nonterminal
N
, we say that
C
is
inductively defined by

G

if
C=L(N)
.

For this paper, the alphabet of an RTG consists of constructors for each of the constructs of
\mathit{G_{imp}}
.
For simplicity of presentation,
we elide the arity of constructors and use infix notation (e.g.,
{{x}\ \mathsf{:=}\ {0}}
, rather than
:=^{(2)}(x^{(0)},0^{(0)})
)) and
also allow inlining of nonterminals
(e.g.,
S^{\prime}::={{x_{1}}\ \mathsf{:=}\ {x_{1}}}

S^{\prime}::={{V_{x}}\ \mathsf{:=}\ {E_{x}}}

E_{x}::=V_{x}

V_{x}::=x_{1}
).
We assume grammars use productions that differ from the ones in
\mathit{G_{imp}}
only due to the nonterminal name
(i.e., the constructor
\alpha^{(n)}
of a production must be from
\mathit{G_{imp}}
and have the same arity).
We call a production
N_{0}::=\alpha^{(i)}(N_{1},\cdots,N_{i})

valid with respect to
\mathit{G_{imp}}
if replacing each nonterminal
N_{j}
with the nonterminal of the same type in the set
\{\mathit{Stmt},\mathit{Exp},\mathit{BExp}\}

\mathit{G_{imp}}
(e.g., production

\mathit{G_{imp}}

\mathit{Stmt}::=\mathit{Stmt};\mathit{Stmt}

\mathit{G_{imp}}

Given a nonterminal

3.2.
Semantics of Programs

We now formalize the definition of a
semantics
of a
single
program.

Definition 3 (Semantics of a Program).

Let
A(\tau_{\mathit{Stmt}},\tau_{\mathit{Exp}},\tau_{\mathit{BExp}})
be a 3-tuple with an associated name
\mathit{A}
where
\tau_{\mathit{Stmt}}
,
\tau_{\mathit{Exp}}
, and
\tau_{\mathit{BExp}}
are the types of the denotations that the semantics assigns to programs of type
\mathit{Stmt}
,
\mathit{Exp}
, and
\mathit{BExp}
, respectively.
Then a
semantics over programs

\llbracket{\cdot}\rrbracket^{A}
is
a 3-tuple
\llbracket{\cdot}\rrbracket^{A}=(\llbracket{\cdot}\rrbracket^{A}_{\mathit{Stmt}},\llbracket{\cdot}\rrbracket^{A}_{\mathit{Exp}},\llbracket{\cdot}\rrbracket^{A}_{\mathit{BExp}})
, where:

\llbracket{\cdot}\rrbracket^{A}_{\mathit{Stmt}}:\mathit{Stmt}\rightarrow\tau_{\mathit{Stmt}}
,
\llbracket{\cdot}\rrbracket^{A}_{\mathit{Exp}}:\mathit{Exp}\rightarrow\tau_{\mathit{Exp}}
, and
\llbracket{\cdot}\rrbracket^{A}_{\mathit{BExp}}:\mathit{BExp}\rightarrow\tau_{\mathit{BExp}}
.
We call
A(\tau_{\mathit{Stmt}},\tau_{\mathit{Exp}},\tau_{\mathit{BExp}})
the
signature
of
\llbracket{\cdot}\rrbracket^{A}
.

In this paper, we will only be defining semantics where

\tau_{\mathit{Stmt}}=\tau_{\mathit{Exp}}=\tau_{\mathit{BExp}}
, by
interpreting integer and Boolean expressions as state transformers as well.
Specifically, an expression
e\in\mathit{Exp}
is considered to update a reserved variable
e_{t}

instead of returning an integer value;
Boolean expressions update a separate reserved variable
b_{t}
in a similar manner.
This formalism makes it easier to relate the result of an expression with its input state,
which will become convenient later when constructing compositional characterizations for sets of programs,
as in
Figure

5

When
\tau_{\mathit{Stmt}}=\tau_{\mathit{Exp}}=\tau_{\mathit{BExp}}=\tau
, we abbreviate the signature
A(\tau_{\mathit{Stmt}},\tau_{\mathit{Exp}},\tau_{\mathit{BExp}})
as
A(\tau)
,
and we often omit subscripts for
\mathit{Stmt}
,
\mathit{Exp}
, and
\mathit{BExp}
when they are clear from context.

Definition

3

by changing the signature

and the definition of
\llbracket{\cdot}\rrbracket^{A}
.
We will first define a collecting big-step semantics for programs in
\mathit{G_{imp}}

Having established a formal notion of semantics in
§

3.2

turn to the issue of

.
As argued in §
1
, the compositionality of a semantics is crucial
for
supporting practical reasoning methods.
In this section, we formally define what it means for a semantics to be
compositional, and then prove that
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{aw}}

is
compositional,
whereas
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
and
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{at}}

are not
compositional.
6
6

6

In
§

3
, none of
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
,
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{at}}
, and
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{aw}}
are stated in a compositional manner.

Theorem

2
shows that
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{aw}}
can be characterized compositionally.

The compositionality of a semantics is
inspired by

grammar-flow analysis
(GFA)
(
Möncke and Wilhelm, 1991
)
.
GFA is a formalism for recursively
specifying, and computing, aggregate properties of the nonterminals
in a given regular tree grammar.
A compositional semantics for sets of programs does something very similar:
it computes properties
over a given inductive set of programs
(which is, in this paper, defined by a regular tree grammar).
Thus, the
notion that “a semantics for a set of programs
\langle\!\langle{\cdot}\rangle\!\rangle^{A}
is compositional”
can be taken to mean that
\langle\!\langle{\cdot}\rangle\!\rangle^{A}
should be computable in a fashion similar to grammar-flow analysis
(i.e., the semantics of a nonterminal should be computed from the semantics of its productions,
and the semantics of each production is computed from the semantics of its terms),
an analogy that may be drawn for many other analyses over sets of
programs as well (as illustrated in
§

2
).
We capture this notion of compositionality by requiring that the semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{A}
satisfy the
following intuitive properties for any input set of programs
C
, defined by a regular tree
grammar
G_{C}
:

•

For each nonterminal
N\in G_{C}
, defined by the production right-hand sides

5.
Vector-State Semantics

Having proved that

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
and
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{at}}

do not admit compositional characterizations,
the natural question to ask is:
What is the coarsest
compositional
semantics that is at least as fine as
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}

(or
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{at}}
)?
In this section, we answer this question by proposing the

vector-state semantics

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}

(and
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
), the coarsest compositional semantics
that is at least as fine-grained as
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}

(or as
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{at}}
).

5.1.
Intuition for Vector-States

The fundamental challenge of describing the behavior of sets of programs is “synchronizing” programs with inputs
to express multiple executions, as described in
§

1
.
To enable this synchronization, we lift our semantics from sets of individual input states to sets of sequences of input states.
This approach allows us to apply the same program to each state in an input sequence,
so that the corresponding output sequence is the result of executing a single program
c\in C
.

The noncompositionality of the program-agnostic semantics

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
and
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{at}}
can be attributed to their inability to express multiple executions.
In particular, for a set of guards
B
and set of statements
S
, each loop

(\mathsf{while}\;{b}\;\mathsf{do}\;{s})\in(\mathsf{while}\;{B}\;\mathsf{do}\;{S})
may execute
b
and
s
arbitrarily many times.
Consequently, to answer questions about the program-agnostic semantics of
\mathsf{while}\;{B}\;\mathsf{do}\;{S}
, we need to be able to answer questions about multiple executions
of specific pairs
(b,s)\in B\times S
.
For example, to know that

p_{n}=~({x\mapsto 10})
is a possible final state of

\langle\!\langle{\mathsf{while}\;{B}\;\mathsf{do}\;{S}}\rangle\!\rangle^{\mathbf{a}}(\{({x\mapsto 0})\})
,
we would need to know that there is a guard
b\in B
, a loop body
s\in S
, and a sequence of states
[p_{1},\cdots,p_{n}]

for which

b
is true on all
p_{j}
except
p_{n}
, and
s
maps each
p_{j}
to
p_{j+1}
.

More generally, given a set of programs
C
and sequences
[p_{1},\cdots,p_{n}]
and
[q_{1},\cdots,q_{n}]
of inputs and outputs,
one must be able to ask whether there
exists a
single
program
c\in C
such that
\llbracket{c}\rrbracket^{\mathit{a}}(p_{j})=q_{j}
for all
j
.
Questions of this sort cannot be answered from
\langle\!\langle{C}\rangle\!\rangle^{\mathbf{a}}
,
yet they are necessary to understand the program-agnostic behavior of sets of loops defined in terms of
C
.

The goal of this section is to introduce
two new,
vector-state semantics
, denoted by
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
and
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
, which
capture exactly this kind of information about
C

(with and without the ability to capture nontermination, respectively).
These vector-state semantics admit compositional characterizations over

while
, and they are at least as fine as
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
and
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{at}}
, respectively.
In addition, the vector-state semantics are the
coarsest
such semantics,
and thus they represent the minimum amount of information about sets of programs one must track to enable compositional reasoning.

5.2.
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
: Divergence
-
Agnostic Vector-State Semantics

We begin by developing

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
—a divergence
-
agnostic vector-state semantics.
We first provide
some intuition about how
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
should operate on
input vector-states, and formalize the definition of
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
.
Then, we prove that
(
i
)
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
has a compositional characterization, and
(
ii
)
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
is
the coarsest-grained compositional semantics that is
finer than
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
.
As discussed,
we will use
vector-states to capture the behavior of a set of programs
(e.g., a set of loop bodies) under multiple executions.

Following this intuition,
\langle\!\langle{C}\rangle\!\rangle^{\mathbf{v}}

should let each
c\in C
operate over
each entry in the vector
to generate an output vector-state.
For example, given the set

S=\{{{{x}\ \mathsf{:=}\ {x+2}},{{x}\ \mathsf{:=}\ {x+10}}}\}
,
the vector-state semantics

\langle\!\langle{S}\rangle\!\rangle^{\mathbf{v}}([({x\mapsto 2}),({x\mapsto 4})])
yields

\{[({x\mapsto 4}),({x\mapsto 6})],[({x\mapsto 12}),({x\mapsto 14})]\}
.

We define
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
so that, when a program diverges on

any
state in a vector-state,
the
entire
output vector is discarded. This is
similar to how Hoare logic returns
{{\mathsf{false}}}

as the postcondition of a diverging loop. For example, for the singleton set

S=\{{\mathsf{while}\;{x<2}\;\mathsf{do}\;{{{x}\ \mathsf{:=}\ {x-1}}}}\}
, the vector-state semantics

\langle\!\langle{S}\rangle\!\rangle^{\mathbf{v}}([({x\mapsto 2}),({x\mapsto 4})])
yields
\{[({x\mapsto 2}),({x\mapsto 4})]\}

because the loop does not diverge on any input in the vector,
but
\langle\!\langle{S}\rangle\!\rangle^{\mathbf{v}}([({x\mapsto 2}),({x\mapsto 4}),({x\mapsto 1})])

yields
\emptyset
:
the
entire output vector-state
is eliminated, due to the existence of a diverging
element in the input vector-state.

5.2.1.
Formalization of
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}

In the following,
\mathsf{State}^{*}

\mathsf{State}

Definition 1 (Divergence

The

We first define the semantics for singleton vector states.
For a program

(1)

If for every

\llbracket{c}\rrbracket^{\mathit{a}}(v_{i})\neq\emptyset

\llbracket{c}\rrbracket^{\mathit{v}}(\{[v_{1},\ldots,v_{n}]\})=\{[\llbracket{c}\rrbracket^{\mathit{a}}(v_{1}),\cdots,\llbracket{c}\rrbracket^{\mathit{a}}(v_{n})]\}.

If for some

\llbracket{c}\rrbracket^{\mathit{a}}(v_{i})=\emptyset

\llbracket{c}\rrbracket^{\mathit{v}}(\{v\})=\emptyset.

Note that entries of the output vectors are technically singleton sets; we unpack them as states.

Then for a set of vector states

\llbracket{c}\rrbracket^{\mathit{v}}(V)=\bigcup\limits_{u\in V}\llbracket{c}\rrbracket^{\mathit{v}}(\{u\})

Intuitively,
\llbracket{c}\rrbracket^{\mathit{v}}(\{v\})

\llbracket{c}\rrbracket^{\mathit{v}}(v)

gives the output of

v

c

If

Thus,
\llbracket{c}\rrbracket^{\mathit{v}}(V)

\llbracket{c}\rrbracket^{\mathit{v}}(v)=\emptyset
.
Generalizing

Definition 2 (Divergence

\langle\!\langle{C}\rangle\!\rangle^{\mathbf{v}}(V)=\bigcup\limits_{c\in C}\llbracket{c}\rrbracket^{\mathit{v}}(V).

5.3.
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}

We now introduce

divergence
-

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{at}}

Whereas
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
(

naïvely extending
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{at}}

In this section, we provide

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}

§

D.1

5.3.1.
The Naïve Approach:
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}_{\mathbf{fine}}}

The natural approach to handle nontermination is to extend
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
to operate over infinite vectors and record divergence on each state in a vector as follows:

Example 4 (
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}_{\mathbf{fine}}}
Semantics: Too Fine).

Consider a semantics for single programs
\llbracket{\cdot}\rrbracket^{\mathbf{vt}_{\mathbf{fine}}}

\displaystyle=\{[\llbracket{w_{1}}\rrbracket({x\mapsto 1}),\llbracket{w_{1}}\rrbracket({x\mapsto 2})],[\llbracket{w_{2}}\rrbracket({x\mapsto 1}),\llbracket{w_{2}}\rrbracket({x\mapsto 2})]\}

5.3.2.
The Right Approach:
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}

To define a semantics with the appropriate granularity,

(1)

6.
Compositional Hoare-style Rules

We have argued that when a semantics is compositional,
it is easier to design formal systems for reasoning about sets of programs.
To validate this claim, we return to the idea of designing a Hoare-style proof system for inductively defined sets of programs.
First, we show that in the same way there does not exist
a compositional characterization for program-agnostic semantics of sets of programs,
there is no sound and relatively complete compositional Hoare-style While-rule for
automatically proving properties of sets of programs with program-agnostic triples (
§

6
).
Next, we show that for the two vector-state semantics

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
and
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
,
which both admit compositional characterizations,
there
do
exist sound and relatively complete compositional Hoare-style While-rules (
§

6.1
).
Combined with previous work on Unrealizability Logic
(
Kim et al., 2023
;
Nagy et al., 2024
)
—a
relatively complete, compositional Hoare-style proof system for sets of loop-free programs—these
rules provide the first
sound, relatively complete, compositional Hoare-style logics for reasoning about sets of programs.

We start by defining what it means for a while-loop rule to be compositional
for a Hoare-style proof system for sets of programs under a specific semantics.
Given a semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{A}
where the signature

A(\tau)
has type
\tau=X\rightarrow X
for some
X
,
an
unrealizability triple

\{\kern-2.15277pt|{P}|\kern-2.15277pt\}^{A}\>S\>\{\kern-2.15277pt|Q|\kern-2.15277pt\}^{A}
denotes that
\langle\!\langle{S}\rangle\!\rangle^{A}(P)\subseteq Q
holds.
When writing proofs by induction (i.e., for inductively defined sets of programs),
one uses a set
\Gamma
to hold their inductive hypotheses.
When
\Gamma
is a set of such triples, we
use
\Gamma\vdash\{\kern-2.15277pt|{P}|\kern-2.15277pt\}^{A}\>S\>\{\kern-2.15277pt|Q|\kern-2.15277pt\}^{A}

to mean that
\{\kern-2.15277pt|{P}|\kern-2.15277pt\}^{A}\>S\>\{\kern-2.15277pt|Q|\kern-2.15277pt\}^{A}
holds, assuming that
all triples in
\Gamma
hold.

Definition 1 (Compositional While-Rule).

Given a semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{A}
, a While-rule is compositional if it has the following form, where

\varphi(v_{1},\cdots,v_{n})
is
a formula over
v_{1},\cdots,v_{n}
:

\Gamma\vdash\{\kern-2.15277pt|{P_{B}}|\kern-2.15277pt\}^{A}\>B\>\{\kern-2.15277pt|Q_{B}|\kern-2.15277pt\}^{A}

\Gamma\vdash\{\kern-2.15277pt|{P_{S}}|\kern-2.15277pt\}^{A}\>S\>\{\kern-2.15277pt|Q_{S}|\kern-2.15277pt\}^{A}

\Gamma\vdash\{\kern-2.15277pt|{P}|\kern-2.15277pt\}^{A}\>(\mathsf{while}\;{B}\;\mathsf{do}\;{S})\>\{\kern-2.15277pt|\varphi(\mathit{vars}(B),\mathit{vars}(S),P,P_{B},P_{S},Q_{B},Q_{S})|\kern-2.15277pt\}^{A}

Definition

1
disallows one from referring directly to
B
and
S

in the postcondition; only information that can be captured by a compositional semantics (e.g.,
the input and output sets
P_{B}
and
Q_{B}
for
B
) can be referenced.
This restriction captures compositionality for inference rules.

Hoare-style logics often also contain “structural” rules that do not correspond to a single constructor (e.g., the weakening rule in standard Hoare logic
(
Hoare, 1969
)
).
An important structural rule
we will consider in this paper is the
\mathsf{GrmDisj}
rule
from Unrealizability Logic
(
Kim et al., 2023
;
Nagy et al., 2024
)
,
which allows one to partition a set of programs into a finite number of subsets.

Definition 2 (The Grammar-Disjunction Rule
(
Kim et al., 2023
)
).

Given a semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{A}
, the grammar-disjunction rule
\mathsf{GrmDisj}
is defined as follows:

\Gamma\vdash\{\kern-2.15277pt|{P}|\kern-2.15277pt\}^{\mathbf{a}}\>(C_{1}\cup C_{2})\>\{\kern-2.15277pt|Q|\kern-2.15277pt\}^{\mathbf{a}}\Gamma\vdash\{\kern-2.15277pt|{P}|\kern-2.15277pt\}^{\mathbf{a}}\>C_{1}\>\{\kern-2.15277pt|Q|\kern-2.15277pt\}^{\mathbf{a}}\quad\Gamma\vdash\{\kern-2.15277pt|{P}|\kern-2.15277pt\}^{\mathbf{a}}\>C_{2}\>\{\kern-2.15277pt|Q|\kern-2.15277pt\}^{\mathbf{a}}

\mathsf{GrmDisj}
allows a proof system more power than a strictly compositional
characterization would: a proof system with
\mathsf{GrmDisj}
allows
one to partition sets of loops into smaller sets, while a proof system without

\mathsf{GrmDisj}
is denied this ability.
When proving or disproving the existence of a compositional While-rule, we wish to
account for this additional power.
Thus, we show that
there exists no While-rule even if
\mathsf{GrmDisj}

(and the standard weakening rule)
are
allowed—which in turn shows that
Unrealizability Logic over a program-agnostic semantics is fundamentally incomplete.

{thm}

[No Program-Agnostic While-Rule]

There is no sound and relatively complete compositional While-rule
over triples
\{\kern-2.15277pt|{P}|\kern-2.15277pt\}^{\mathbf{a}}\>C\>\{\kern-2.15277pt|Q|\kern-2.15277pt\}^{\mathbf{a}}
, even when finitely many applications of
\mathsf{GrmDisj}
(and the standard weakening rule) are allowed.

The proof,
given in
§

A.3
,
is similar to the proof of
Theorem

Related Work

Program Synthesis and Unrealizability

The inputs to the semantics discussed in this paper align
well with
program-synthesis problems, which often
assume a syntactic search space constrained by
a regular tree grammar
or some other recursively defined language
(
(
Alur et al., 2013
;
Kim et al., 2021
;
Torlak and Bodík, 2014
;
Feng et al., 2018
)
,
to single out just a few).
As discussed in
§

5.2
,
the results on single-input
properties discussed
in this paper generalize almost immediately to
multiple-input properties, which in turn capture
PBE specifications used in many
synthesizers
(
Solar-Lezama, 2013
;
Kim et al., 2021
;
Gulwani, 2011
;
Polozov and Gulwani, 2015
)
.

In particular, our work provides a formal result
about
the difficulty of proving

unrealizability

of synthesis problems (i.e., the non-existence of a solution).
Two recent publications
(
Kim et al., 2023
;
Nagy et al., 2024
)
introduced

Unrealizability Logics
,
Hoare-style logics for reasoning about inductively defined sets of programs.
Both logics are sound, but not relatively complete when loops are allowed (see
Footnote

2
).
The main semantics for sets of programs used in
Nagy et al. (2024)
is coarser than

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
;

§

5.2.2
proves that a compositional rule for while loops
under such semantics does not exist.
In
Kim et al. (2023)
(and in the appendices of
Nagy et al. (2024)
),
a vector-state semantics finer than
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
is used.
That semantics is
compositional,
but the inference rules are written with the assumption that a program-agnostic
rule like the one disallowed by
§

6
exists.
Vector-states are only added to
discuss
k
-input extensional properties;
their role in enabling compositionality is not
exploited.

Nagy et al. (2024)
designed a proof synthesizer for an incomplete Unrealizability Logic for infinite vector-states.
Their implementation suggests that reasoning over infinite
vector-states is tractable, at least in simple cases,
giving hope
for tractable verification techniques to be derived from
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
.

Outcome Logic and Hyper Hoare Logic

An Outcome Logic is a program logic for uninterpreted nondeterministic programs expressed in a Kleene algebra. In an Outcome Logic, program semantics are monadic, and the monad is equipped with the operations of a partial commutative monoid to split monadic objects.

Zilberstein et al. (2023)
give an instantiation of Outcome Logic for the set monad equipped with a set-union monoid operation.
Hyper Hoare Logic is a program logic for imperative nondeterministic programs in which pre- and postconditions are second-order predicates over sets of states, rather than first-order predicates over states
(
Dardinier and Müller, 2023
)
.

The logic from
§

6
is not subsumed by existing logics, although Outcome
Logic
and Hyper Hoare Logic share some similarities.
Because both logics reason about sets of states explicitly, and a vector-state is simply an indexed set of states, triples about a single program that are expressible in our divergence
-
agnostic vector-state logic are expressible in both Outcome and Hyper Hoare Logic. Triples about a single program in divergence
-
aware logic cannot be expressed in Hyper Hoare Logic because there is no treatment of divergence there; they may be expressible in an Outcome Logic if one can define an
\mathit{EVS}
monad, where
\mathit{EVS}
is the set of vector-states over which

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
operates.
Note that neither logic expresses properties of sets of programs.

Because Outcome Logic is expressed over an uninterpreted Kleene algebra,
one might wonder whether we can simply interpret elements of the Kleene algebra
as sets of programs to obtain a complete Outcome Logic for sets of programs revision (i.e., can we represent a set of programs as a single nondeterministic program
and use an Outcome Logic to reason about its behavior on vector-states?).
Unfortunately, this reduction is not possible in general:
the traces of infinite sets of while loops, such as the one in our proof of

§

6
, do not always form regular languages and thus are not expressible by
Kleene algebras
(e.g., by the Myhill-Nerode Theorem
(
Nerode, 1958
)
).

Incompleteness of Hoare-Style logics.

Clarke
(
Clarke Jr, 1979
)
studies programming languages for which one cannot obtain
a relatively complete “Hoare-style logic”,
which Clarke
(and
others, most notably
Lipton (1977)
)
interprets
as a
syntax-directed proof system
involving axiomatic rules that
capture the semantics of a program
(
Clarke, 1984
;
Apt and Olderog, 2019
)
.
Clarke proves that such logics cannot exist for certain
combinations of language features
(e.g., coroutines with parameterless recursive procedures).

Such “Hoare-style logics”
are not necessarily compositional as defined in this paper.
In particular, such “Hoare-style logics” may contain as
part of their proof system a separate procedure that reduces deriving a triple
into some other kind of decidable problem (e.g., enumeration in the case of finite interpretations),
instead of constructing a proof tree.
Clarke observes that these “Hoare-style logics”
do not necessarily lead to
practical proof systems
(
Clarke, 1984
, p11)
.

Our work defines compositionality as an additional desideratum to support
practical reasoning;
one might view compositionality
as a formal criterion of
“natural Hoare-style logics”
mentioned by Clarke
(
Clarke, 1984
)
.
We are unaware of any non-compositional logics that see major use.

Variational Analysis.

Variational analysis (VA) encompasses a broad set of techniques
for tracking the behavior of finite sets of programs,
where each program is the result of some combination of ‘tags.’
A combination of tags encodes
the usage of different features, permissions, etc.
For example, in a set of differently configured email clients,
the tags
(\mathtt{encryption}=\mathtt{RSA},\mathtt{spam}={{\mathsf{t}}})
would denote
the unique configuration that uses RSA encryption and a spam filter.
The main aim of VAs
is to construct a map from tag combinations (i.e., specific programs)
to program properties or behaviors.

For example, the semantics of the choice calculus,
used in the analysis of variable software,
builds a map from
(
i
) combinations of finitely many tags describing choices about program syntax
to
(
ii
) program behavior
(
Erwig and Walkingshaw, 2011
)
.
Model checking-based VA approaches, useful in product-line analysis,
build more compact maps from
(
i
) propositional formulas
that represent
finite sets of configurations to
(
ii
) program behaviors
(
Gruler et al., 2008
)
.
Faceted execution, used in dynamic enforcement of privacy policies,
builds maps from
(
i
) users to
(
ii
) program states
to
model
different users executing the same code
(
Austin and Flanagan, 2012
)
.

We emphasize that VA is a family of specific
techniques including the above, and does not provide a framework for semantic analysis or derivation of our key results
(e.g.,
§

5.2.2
).
One might wonder
whether a VA technique (extended to operate over infinite sets) could,
at least in theory,
efficiently verify extensional properties for sets of programs.
Our theory suggests that the answer is no, for two reasons.
First,
a complete, compositional VA technique capable of
verifying extensional properties will induce a semantics strictly
finer than
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
due to the need to track
tag combinations, which correspond to
syntactic information.
7
7

7

To be precise, to construct
a semantics for VA techniques, one must extend
\mathit{G_{imp}}
to include tags.
This extension is necessary because VA techniques construct
different maps for differently tagged sets of programs.

Second,
expressing maps from tag combinations to semantic behaviors
requires non-Cartesian predicates that explicitly relate program syntax and semantics; these predicates are complex and best avoided for infinite sets of programs
(see
§

2.2
).

Finally, we remark that
Bittner et al. (2024)
define
a notion of
denotational semantics for variability languages
to compare
the expressive power of different VA formalisms. Both our work and theirs use denotational semantics to describe the expressivity of verification objectives, albeit for very different purposes. We believe that this strategy
has potential to advance the analysis and design of verification techniques, as both works evidence.

Compilers and Self-Modifying Code.

A compiler is
the canonical example of a tool that creates a set of programs.
Generally, “compiler correctness’
is concerned with whether each (single) source program is
translated correctly to an appropriate target program.
The scheme for establishing
compiler correctness
is due to Burstall

(
Burstall, 1969
)

and followed in most of the 14 passes in
the CompCert compiler,
which translated CLight to PowerPC assembly language

(
Leroy, 2009
)
.

A compiler-correctness problem closer to the questions addressed
in this paper would be, e.g.,
to prove that a compiler can only emit target programs
that satisfy a memory-safety property
(i.e., the
set
of programs emittable
by the compiler’s translation function are memory-safe).
Myreen
(
Myreen, 2010
)
addressed a version of this problem:
he developed a machine-code Hoare logic to support
reasoning about self-modifying x86 machine code,
which was applied to the verification of JIT compilers.

Other work on self-modifying code includes Gerth
(
Gerth, 1991
)
and Cai et al.
(
Cai et al., 2007
)
.
The latter is based on an extension of Hoare logic, but to support self-modification, it treats program instructions as any other mutable data structure—an issue that we do not face in our work.
Gerth’s earlier work also adopts a data-centric view of the world: there is no code, only data.
Gerth’s proof system was based on Manna and Pnueli
(
Manna and Pnueli, 1983
)

and proves properties expressed in linear temporal logic.

While these problems are beyond the scope and capabilities of our work, the semantics and Hoare-style rules studied in our paper provide a new way of reasoning about sets of programs, including languages (domain-specific or produced by compilers) and self-modifying code.

8.
Conclusion

This paper set out to understand why existing compositional program logics for sets of programs
(
Kim et al., 2023
;
Nagy et al., 2024
)

fail to be relatively complete, and whether such logics can be modified to achieve completeness.
By formalizing verification relative to a denotational semantics for sets of programs, we were able to prove that no complete compositional proof system exists for the kind of logical triples proposed in prior work.
In light of this result,
we define a more expressive kind of triple
and give
the first (two) sound and relatively complete Hoare-style logics
for inductively defined sets of programs (even for programs that contain loops), solving an open problem in the literature
(
Kim et al., 2023
;
Nagy et al., 2024
)
.

Appendix B
Granularity Induces a Lattice

In this appendix, we prove that the granularity preorder induces a lattice. Most results are obvious if one imagines granularity as a measure of the fineness of the partition
(\langle\!\langle{\cdot}\rangle\!\rangle^{A})^{-1}
.

Definition 1 (Granularity).

Let a semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{A}
be given. The granularity of
\langle\!\langle{\cdot}\rangle\!\rangle^{A}
is defined as
[\langle\!\langle{\cdot}\rangle\!\rangle^{A}]=\{\langle\!\langle{\cdot}\rangle\!\rangle^{B}\mid\langle\!\langle{\cdot}\rangle\!\rangle^{A}\preceq\langle\!\langle{\cdot}\rangle\!\rangle^{B}\preceq\langle\!\langle{\cdot}\rangle\!\rangle^{A}\}
, the set of semantics with the same granularity as
\langle\!\langle{\cdot}\rangle\!\rangle^{A}
.

Note that the granularity preorder induces a partial order (
\preceq
) over the set of granularities.

Theorem 2 (Granularity Partial Order is a Complete Lattice).

The set of granularities equipped with the partial order

Incompleteness of Cartesian Triples

As stated in
§

\mathtt{interpret}:\mathsf{Prog}\times\mathsf{State}\rightarrow\mathsf{State}

\mathtt{interpret}
using only Cartesian triples.

To prove this fact, we first define a semantics induced by the true Cartesian triples of
\mathtt{interpret}
. Understanding this semantics will be key to proving the necessity of non-Cartesian triples.

Definition 4 (Interpreter Semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathtt{interpret}_{a}}

Recall from

\langle\!\langle{C}\rangle\!\rangle^{\mathtt{interpret}_{a}}=\{{\{{\mathtt{t}\in\ ?\wedge P(\mathtt{x})}\}\>y=\mathtt{interpret}(t,x)\>\{Q\}\mid\text{the triple is true when $C$ is substituted for $?$}}\}

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathtt{interpret}_{a}}\equiv\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}

The semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathtt{interpret}_{a}}

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
are equivalently granular. Moreover, both semantics are noncompositional over while and compositional over all other constructors.

Because a triple
\{{\mathtt{t}\in C\wedge\mathtt{x}\in P}\}\>y=\mathtt{interpret}(t,x)\>\{Q\}

\langle\!\langle{C}\rangle\!\rangle^{\mathbf{a}}(P)\subseteq Q

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathtt{interpret}_{a}}
and
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
are equivalently granular. Since compositionality over each constructor is preserved between equivalently granular semantics, the noncompositionality over while of
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
implies the noncompositionality over while of
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathtt{interpret}_{a}}

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
over all other constructors implies the compositionality of
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathtt{interpret}_{a}}
over all non-while constructors.

We are now ready to state and prove the necessity of non-Cartesian triples:

Theorem 6 (Cartesian Reasoning is Incomplete).

Let
\mathtt{interpret}:\mathsf{Prog}\times\mathsf{State}\rightarrow\mathsf{State}

\{{t\in C\land x\in P}\}\>y=\mathtt{interpret}(t,x)\>\{y\in Q\}

Suppose we have a correct recursive interpreter
\mathtt{interpret}:\mathsf{Prog}\times\mathsf{State}\rightarrow\mathsf{State}
for which every Cartesian triple can be proven using only Cartesian triples. We will show that this implies compositionality of
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathtt{interpret}}
over while, a contradiction of

5
.

Let

\langle\!\langle{W}\rangle\!\rangle^{\mathtt{interpret}_{a}}
from
\langle\!\langle{B}\rangle\!\rangle^{\mathtt{interpret}_{a}}
and
\langle\!\langle{S}\rangle\!\rangle^{\mathtt{interpret}_{a}}

If the triple is true, then by hypothesis there is a Hoare-style analysis of

Completing
\mathtt{interpret}
for Cartesian Triples

We have seen that Hoare-style analyses of
\mathtt{interpret}:\mathsf{Prog}\times\mathsf{State}\rightarrow\mathsf{State}
that use only Cartesian triples cannot prove all Cartesian triples. This insufficiency holds because the signature of
\mathtt{interpret}
induces a noncompositional semantics. A natural question is whether we can extend the signature of
\mathtt{interpret}
to induce a compositional semantics, and whether Cartesian reasoning over such an extended interpreter might be complete. As it turns out, we can.

Recall that the divergence

agnostic vector-state semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
is a compositional semantics finer than the divergence

agnostic program-agnostic semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}

agnostic program-agnostic semantics corresponds to the signature
\mathtt{interpret}:\mathsf{Prog}\times\mathsf{State}\rightarrow\mathsf{State}

\mathtt{interpret}_{v}:\mathsf{Prog}\times\mathsf{State}^{*}\rightarrow\mathsf{State}^{*}
will induce a semantics equivalent to
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}

Appendix D
Divergence

Aware Vector-State Semantics

Next, we describe a divergence
-
aware vector-state semantics
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
, the minimal compositional semantics that is at least as fine as
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{at}}
. While similar to
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
,
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
must be able to reason about nontermination. This means that it must be able to explicitly represent divergence, and it must also be able to reason about infinitely many executions of loop bodies. Unlike
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
, the vector states
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
operates over may be infinite (but still computable) or contain an occurrence of
\uparrow
(i.e.,
[({x_{1}\mapsto 1}),({x_{1}\mapsto 2}),({x_{1}\mapsto 3}),\cdots]
and
[({x_{1}\mapsto 1}),({x_{1}\mapsto 2}),\uparrow]
are vector-states we may wish to consider).

D.1.
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
: Divergence-Aware Vector-State Semantics

The tricky part the construction of
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
is handling divergence—i.e., nontermination.
Observing divergence of carefully crafted loops (
\uparrow\in\langle\!\langle{\mathsf{while}\;{b}\;\mathsf{do}\;{\cdots C\cdots}}\rangle\!\rangle^{\mathbf{at}}
) will never give enough information to determine whether any
c\in C
diverges
on two distinct inputs.
Similarly, inspecting the content of
\langle\!\langle{C}\rangle\!\rangle^{\mathbf{vt}}
cannot help us conclude whether a single program diverged on two inputs—i.e., we cannot take a program
c
which diverges on
({x_{1}\mapsto 1})
and
({x_{1}\mapsto 2})
and determine that
\langle\!\langle{\{c\}}\rangle\!\rangle^{\mathbf{vt}}([({x_{1}\mapsto 1}),({x_{1}\mapsto 2})])=[\uparrow,\uparrow]
by querying the program-agnostic semantics of sets of loops containing
c
. This issue inspires the first restriction on our vector-state semantics—outputs are truncated after the first occurrence of
\uparrow
.

Furthermore, consider a program
s_{1}
that diverges only when
x_{1}=1
,
a program
s_{2}
diverges only when
x_{1}=2
,
and a program
s_{3}
that never diverges; otherwise all three behave as
identity. Then the program-agnostic semantics of the three sets of loops

W_{j}
(
j=0,1,2
) that each run the set of bodies

S=\{s_{1},s_{2},s_{3}\}
on the sequence

[({x_{1}\mapsto 0}),\cdots,({x_{1}\mapsto j})]
give us enough information to identify that there is a program in
S
with the behavior
[({x_{1}\mapsto 0}),\uparrow]
(i.e., because
\langle\!\langle{W_{0}}\rangle\!\rangle^{\mathbf{at}}
always converges
({x_{1}\mapsto 0})
on the first input state but
\langle\!\langle{W_{j}}\rangle\!\rangle^{\mathbf{at}}
may diverge).
However, these
\langle\!\langle{W_{j}}\rangle\!\rangle^{\mathbf{at}}
(
j=0,1,2
) will never give us enough information to see that

[({x_{1}\mapsto 0}),({x_{1}\mapsto 1}),\uparrow]
is a possible outcome
because although
\langle\!\langle{W_{1}}\rangle\!\rangle^{\mathbf{at}}
and
\langle\!\langle{W_{2}}\rangle\!\rangle^{\mathbf{at}}
may both diverge, we cannot determine whether there is divergence in
\langle\!\langle{W_{2}}\rangle\!\rangle^{\mathbf{at}}
from loop bodies which do not cause divergence in
\langle\!\langle{W_{1}}\rangle\!\rangle^{\mathbf{at}}
. We say that the divergence of
s_{1}

occludes
the later divergence of
s_{2}
.
One can see this by observing that the three
\langle\!\langle{W_{j}}\rangle\!\rangle^{\mathbf{a}}

are unchanged if we remove
s_{2}
.
This occlusion constitutes half of our second restriction—captured
formally in
Definition

2
.

A similar phenomenon of occlusion happens when we want to test the behavior of
C

on an infinite sequence of states.
In this case, checking the program-agnostic semantics of various sets of loops
does not allow us to distinguish divergence due to divergence in the body from
divergence due to the body being run infinitely many times.
Thus, if a loop
(\mathsf{while}\;{{{\mathsf{t}}}}\;\mathsf{do}\;{s;x_{1}:=x_{1}+1})
diverges on a given input,
we cannot distinguish divergence of
s
from convergence of
s
on infinitely many states
because the loop diverges in both cases.
This second type of occlusion is the other half of our second restriction, captured formally
in
Definition

2
.

Because we are searching for the coarsest semantics satisfying our criteria, the restrictions imposed on
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
naturally limit its expressivity. The cost of the truncation we describe is that we cannot identify when there is a single program in a set that diverges on two or more particular inputs. The cost of our occlusion is that, although we can tell when a set of loops may diverge, we can see only the most immediate cause of divergence.
It turns out that the ability to see the most immediate cause of divergence is a minimal requirement to compute the semantics of a set of loops in a compositional fashion.
Also, the lost behaviors are not required for a compositional semantics finer than
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{at}}
.
Those interested in such behaviors should refer to the program-aware semantics for sets of programs defined in
Definition

8
.

We call an infinite sequence of states

Definition 1 (

As in

From this interpretation, it follows that

[({x_{1}\mapsto 1}),({x_{1}\mapsto 2}),\uparrow]

2

For the purposes of our definition,

Given a set of extended vector states

Intuitively, every vector-state in

D.2.
The Granularity of
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
and
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}

Clearly
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}\not\preceq\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{at}}
following the proof of Theorem
4
. Of course,
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{at}}\not\preceq\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
because
\langle\!\langle{\emptyset}\rangle\!\rangle^{\mathbf{v}}=\langle\!\langle{\{\mathsf{while}\;{{{\mathsf{t}}}}\;\mathsf{do}\;{{{x}\ \mathsf{:=}\ {x}}}\}}\rangle\!\rangle^{\mathbf{v}}
but
\langle\!\langle{\emptyset}\rangle\!\rangle^{\mathbf{vt}}\neq\langle\!\langle{\{\mathsf{while}\;{{{\mathsf{t}}}}\;\mathsf{do}\;{{{x}\ \mathsf{:=}\ {x}}}\}}\rangle\!\rangle^{\mathbf{vt}}
.

Now, comparing
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
and
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
, since
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
is a compositional semantics finer than
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{a}}
,
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}\preceq\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
. Moreover, since
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
is incomparable with
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{at}}
,
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
and
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
do not have equivalent granularity. Thus
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}\prec\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
.

Interestingly, the strict
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}\prec\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
holds even over sets of nondiverging programs.

{thm}

[
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}\prec\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
]

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}\prec\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
over sets of nondiverging programs.

Proof.

As above,
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}\preceq\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
in general, so
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}\preceq\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
on sets of nondiverging programs. It remains to show
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}\not\preceq\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{v}}
on sets of nondiverging programs. We do so by borrowing the sets of programs introduced by
Kim et al. (2023)
in their Example 5.1.

Consider the set
S_{1}=L(S)
defined by the grammar with nonterminals
S::={\mathsf{if}}\ {x_{2}==N}\ {\mathsf{then}}\ {{{x_{1}}\ \mathsf{:=}\ {N}}}\ {\mathsf{else}}\ {S}\mid{{x_{1}}\ \mathsf{:=}\ {N}}
and
N::=0\mid 1+N
. Consider also
S_{2}=S_{1}\cup\{{{x_{1}}\ \mathsf{:=}\ {x_{2}}}\}
. One may observe that the behavior of
{{x_{1}}\ \mathsf{:=}\ {x_{2}}}
on finitely many input states may be captured by some

by hardcoding the states. However, no program in
S_{1}
has the semantics of
{{x_{1}}\ \mathsf{:=}\ {x_{2}}}
because all programs in
S_{1}
have finite range. Said another way, the function computed by
{{x_{1}}\ \mathsf{:=}\ {x_{2}}}
is a limit point in the Baire topology of the set of functions computed by the programs in
S_{1}
.

Observe that
\langle\!\langle{S_{1}}\rangle\!\rangle^{\mathbf{v}}=\langle\!\langle{S_{2}}\rangle\!\rangle^{\mathbf{v}}
because, for any finite vector-state, there is a program

that matches the behavior of
{{x_{1}}\ \mathsf{:=}\ {x_{2}}}
on it. However,
\langle\!\langle{S_{1}}\rangle\!\rangle^{\mathbf{vt}}\neq\langle\!\langle{S_{2}}\rangle\!\rangle^{\mathbf{vt}}
. To see this, one may consider an infinite vector-state

. All output vector-states in

will have an upper bound on the value of

, but

has no bound on

.
∎

Of course, both vector-state semantics are strictly coarser than the program-aware semantics. In the case of the divergence
-
aware vector-state semantics, this is a consequence of blocking our ability to observe multiple instances of divergence.

{thm}

[
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
Strictly Coarser than
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{aw}}
]

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}\prec\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{aw}}

Proof.

First, observe that program-aware semantics is at least as fine as vector-state semantics. We can determine
\langle\!\langle{C}\rangle\!\rangle^{\mathbf{vt}}
on singleton sets from

by, on an input

and applying
\mathit{reduce}
. Of course,
\langle\!\langle{C}\rangle\!\rangle^{\mathbf{vt}}
is determined by its value on singleton sets.

Second, we show vector-state semantics is strictly coarser than program-aware semantics. Consider the following four partial computable functions, where
\uparrow

\mathsf{while}\;{{{\mathsf{t}}}}\;\mathsf{do}\;{x_{1}:=x_{1}}

•

•

•

Let

and

. Evidently
\langle\!\langle{S_{1}}\rangle\!\rangle^{\mathbf{aw}}=\{\llbracket{f}\rrbracket^{\mathit{at}},\llbracket{f_{1,2}}\rrbracket^{\mathit{at}}\}
and
\langle\!\langle{S_{2}}\rangle\!\rangle^{\mathbf{aw}}=\{\llbracket{f}\rrbracket^{\mathit{at}},\llbracket{f_{1}}\rrbracket^{\mathit{at}},\llbracket{f_{2}}\rrbracket^{\mathit{at}}\}
. Since
\llbracket{f_{1}}\rrbracket^{\mathit{at}}\neq\llbracket{f}\rrbracket^{\mathit{at}},\llbracket{f_{1,2}}\rrbracket^{\mathit{at}}
, we see that
\llbracket{f_{1}}\rrbracket^{\mathit{at}}\in\langle\!\langle{S_{1}}\rangle\!\rangle^{\mathbf{aw}}\setminus\langle\!\langle{S_{2}}\rangle\!\rangle^{\mathbf{aw}}
and thus
\langle\!\langle{S_{1}}\rangle\!\rangle^{\mathbf{aw}}\neq\langle\!\langle{S_{2}}\rangle\!\rangle^{\mathbf{aw}}
.

However,
\langle\!\langle{S_{1}}\rangle\!\rangle^{\mathbf{vt}}=\langle\!\langle{S_{2}}\rangle\!\rangle^{\mathbf{vt}}
. For any input vector
v
not containing a state setting
x_{1}
to
1
or
2
, all functions behave identically, and the outputs of the semantics are equal. When
x_{1}\mapsto 1
and
x_{1}\mapsto 2
appear in
v
, if
x_{1}\mapsto 1
appears first, then
\llbracket{f_{1}}\rrbracket^{\mathit{vt}}(v)=\llbracket{f_{1,2}}\rrbracket^{\mathit{vt}}(v)
, and moreover
\llbracket{f_{1}}\rrbracket^{\mathit{vt}}(v)
is a prefix of
\llbracket{f_{2}}\rrbracket^{\mathit{vt}}(v)
. So

\displaystyle\langle\!\langle{S_{1}}\rangle\!\rangle^{\mathbf{vt}}(v)

\displaystyle=\mathit{reduce}(\{\llbracket{f_{1}}\rrbracket^{\mathit{vt}}(v),\llbracket{f_{2}}\rrbracket^{\mathit{vt}}(v),\llbracket{f}\rrbracket^{\mathit{vt}}(v)\})

\displaystyle=\{\llbracket{f_{1}}\rrbracket^{\mathit{vt}}(v),\llbracket{f}\rrbracket^{\mathit{vt}}(v)\}

\displaystyle=\{\llbracket{f_{1,2}}\rrbracket^{\mathit{vt}}(v),\llbracket{f}\rrbracket^{\mathit{vt}}(v)\}

\displaystyle=\langle\!\langle{S_{2}}\rangle\!\rangle^{\mathbf{vt}}(v).

If
x_{1}\mapsto 2
appears first, the argument is analogous. When
v
is infinite, the sets are still equal, but
\llbracket{f}\rrbracket^{\mathit{vt}}(v)
does not appear in them.

Thus,
\langle\!\langle{S}\rangle\!\rangle^{\mathbf{vt}}
does not determine
\langle\!\langle{S}\rangle\!\rangle^{\mathbf{aw}}
for every
S\in\mathbf{Stmt}
.
So
\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}\prec\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{aw}}
.
∎

While program-aware semantics is strictly finer than divergence
-
aware vector-state semantics for sets of
diverging
programs, the two semantics are equivalent for sets of
nondiverging
programs in which only finitely many program variables appear. This distinction suggests that even divergence
-
aware vector-state semantics is a rather expressive semantics. When
\mathbf{T}
is a collection of sets of programs, call
ND(\mathbf{T})
, the collection of sets
C\in\mathbf{T}
such that
C
contains only nondiverging programs and
\lvert{\mathit{vars}(C)}\rvert<\infty
.

{thm}

The three compositional semantics

\langle\!\langle{\cdot}\rangle\!\rangle^{\mathbf{vt}}
