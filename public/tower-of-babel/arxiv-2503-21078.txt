Sub-ODEs Simplify Taylor Series Algorithms for Ordinary Differential Equations Thanks: Submitted to the editors December 8, 2024.
Nedialko S. Nedialkov, John D. Pryce

Abstract
A Taylor method for solving an ordinary differential equation initial-value problem x . = f ⁡ ( t , x ) \accentset{\mbox{\large.}}{x}=f(t,x) , x ⁡ ( t 0 ) = x 0 x(t_{0})=x_{0} , computes the Taylor series (TS) of the solution at the current point, truncatedto some order, and then advances to the next point by summing the TS with a suitable step size. A standard ODE method (e.g. Runge–Kutta) treats function f f as a black box, but a Taylor solver requires f f to be preprocessed into a code-list of elementary operations that it interprets as operations on (truncated) TS. The trade-off for this extra work includes arbitrary order, typically enabling much larger step sizes. For a standard function, such as exp \exp , this means evaluating v ⁡ ( t ) = exp ⁡ ( u ⁡ ( t ) ) v(t)=\exp(u(t)) , where u ⁡ ( t ) , v ⁡ ( t ) u(t),v(t) are TS. The sub-ODE method applies the ODE d ​ v / d ​ u = v \textrm{d}v/\textrm{d}u=v , obeyed by v = exp ⁡ ( u ) v=\exp(u) , to in-line this operation as v . = v ​ u . \accentset{\mbox{\large.}}{v}=v\accentset{\mbox{\large.}}{u} . This gives economy of implementation: each function that satisfies a simple ODE goes into the “Taylor library” with a few lines of code—not needing a separate recurrence relation, which is the typical approach. Mathematically, however, the use of sub-ODEs generally transforms the original ODE into a differential-algebraic system, making it nontrivial to ensure a sound system of recurrences for Taylor coefficients. We prove that, regardless of how many sub-ODEs are incorporated into f f , this approach guarantees a sound system. We introduce our sub-ODE-based Matlab ODE solver and show that its performance compares favorably with solvers from the Matlab ODE suite.

Introduction

We are concerned with computer solution of an initial-value problem (IVP) for an ordinary differential equation (ODE) system:

\displaystyle\accentset{\mbox{\large.}}{x}=f(t,x),\quad x(t_{0})=x_{0},

(1)

We exclude here non-differentiable functions like absolute value,
\min

A Taylor method for (
1

These methods go back centuries. However multistep and Runge–Kutta methods, since their invention in the 1800s, have been generally more popular for numerical work, because they treat the function
f
as simply a black box that converts numeric input to numeric output.
A Taylor method cannot do this—it must know how

as an expression or as code.

Conceptually the Taylor process seems straightforward: change
f

However, by the nature of an ODE, one must build up one Taylor order

0

Hence the solution process involves first encoding

into a

There is an outer loop to step the solution from

to some

, and an inner loop for
k{=}0\!:\!p
.

Despite this overhead, Taylor methods have various advantages:

\bullet

They allow any Taylor order
p
.
At small
p
, step size is too small; at large
p
, work is too much.
In double precision, typically
15\leq p\leq 20

\bullet

They are especially good, using arbitrary-precision arithmetic, for hyper-accurate work such as long-time modelling of solar system motion.
In
[
Barrio05b
]

Complexity is polynomial in the digits of precision obtained
[

]

\bullet

For validated solution by interval arithmetic, they have been popular because truncation error can easily be enclosed by interval evaluation of Taylor coefficients

Established systems that compute Taylor coefficients include

1.1.1
Sub-ODEs

These are a way to handle standard functions, that applies to any function that itself obeys a simple ODE.
Most functions met in practice are in this class, e.g.
\exp,\log,\text{sqrt}
.
The Gamma function, for example, is not in this class.

Take

When used in a Taylor solver, its meaning is to compute

\displaystyle v(t)=\exp(u(t))

(2)

where

is a Taylor series (both input and output truncated to order

Most Taylor implementations write an individual recurrence for this, maybe as a separate function.
Instead, we use the fact that

by the chain rule.
This is inserted as

Does this save (or cost) work at run time?
No—the cost of (
2

If separate recurrence, and insertion of
\accentset{\mbox{\large.}}{v}=v\accentset{\mbox{\large.}}{u}
, are both well written, they might give identical floating point operation counts.
But a sub-ODE is far simpler to implement.
For
\exp
in our solver it just consists of writing this one-line definition in class

(Code-List item) that generates the code-list:

⬇

=

(
u
)

("

This causes insertion of one code-list line at each occurrence of

in

.
The sub-ODE versions of the 40-odd other standard functions one would wish to include are not much more complicated, e.g.

\textrm{d}v/\textrm{d}u=\frac{1}{2}v/u
, has such a one-line
CLitem
definition, which inserts three code-list lines at each occurrence.

By contrast with writing 40-odd separate recurrences, the sub-ODE approach makes it simpler to write, maintain and extend a Taylor standard function library.

Executing the code-list requires the implementation of the following:

•

Addition, subtraction, multiplication, and division of Taylor polynomials.

•

The operator (derived later) to handle a sub-ODE, which we denote
1

1

These five building blocks form a

The code-list of

is

The

of any standard function—the computer library’s numeric version—is used by the

All other operations at

This economy of implementation has other advantages.
Code performance optimisation can focus on the kernel.
And, to find sensitivities with respect to an initial condition or parameter, the chain rule of AD only needs applying to the kernel.

1.1.2
Do sub-ODEs work?​​

No matter how many standard function calls are replaced by sub-ODEs in the code-list, are the resulting recurrences
sound
at run time, in the sense that no value is ever asked for before it is computed?
One might be dubious of, say,
\log(\cos(u))
, where the output of one sub-ODE is input to another.

As Example
2
shows, inserting a sub-ODE almost always turns an ODE into a
differential-algebraic equation
(DAE) system.
We answer our question above in terms of
structurally amenable
(S-amenable) DAEs, whose theory is summarised in Appendix
.

Specifically, we consider a DAE in dependent variables
x_{j}=x_{j}(t)
,
j{=}1\!:\!n

\displaystyle F_{i}(t,\mbox{the $x_{j}$ and derivatives of them})=0,\quad i{=}1\!:\!n.

(3)

We refer to it as the DAE
F=0
, of size
n
where
F=(F_{1},\ldots,F_{n})
.

Section
3
proves three key results, which Section
applies to the basic fact that an ODE
\accentset{\mbox{\large.}}{x}=f(t,x)
, converted to a DAE in the obvious way,

F:=\accentset{\mbox{\large.}}{x}-f(t,x)=0
,
is S-amenable.
The key results are that these operations on
F
preserve S-amenability:

(a)

Replace an expression
\psi
by a new variable
u
, and add a new equation
0=u-\psi
.

(b)

Differentiate one of
F
’s equations.

(c)

Replace equation
0{=}\accentset{\mbox{\large.}}{v}-g^{\prime}(u)\accentset{\mbox{\large.}}{u}
, where
g
obeys
g^{\prime}(u){=}h(u,g(u))
, by
0{=}\accentset{\mbox{\large.}}{v}-h(u,v)\accentset{\mbox{\large.}}{u}
.

Inserting one sub-ODE can be broken into at most two uses of (
a

b
) and one of (
c

So starting with the ODE and inserting any number of sub-ODEs, we end with an S-amenable DAE (Theorem
).
Every S-amenable DAE has a
standard solution scheme
—an always sound recurrence for expanding a solution in TS.
This turns out identical with what the code-list does, proving sub-ODEs work.

1.2
Back story

Automatic solution of IVPs for ODEs by TS expansion goes back (at least) to Moore (1966)
[
moore
]
.
So does the idea of converting an ODE to an equivalent rational ODE—in
[
moore
, §11.2]
is an example where
\cos
,
\exp
, and
\log
occur, and are eliminated.
In the DAE context, Corless and Ilie (2008)
[
corless2008polynomial
]
note explicitly that one can convert a DAE to an equivalent one using only BAOs.
But to our knowledge, Neidinger (2013)
[
Neidinger2013
]
is the first person to give an embedding
method
that can in principle be automated—an operator he calls
ddot
, nearly equivalent to our
\mathop{\odot}
.

Both Moore and Neidinger only consider recurrence relations (RRs) for calculating
Taylor coefficients (TCs), and not a differential system that these might represent; while Corless–Ilie treat the differential system, but not (at that point of their exposition) the resulting RRs, nor with an automated way to do the conversion.
None notes that barring special cases, the result of thus converting an ODE is always a DAE.
To recast it as an ODE, one must differentiate one or more equations, and algebraically manipulate the result—Moore does this in his example without noting it is unavoidable.

Nor do they note this adds extra degrees of freedom (DOF) that need initial values.
In an IVP code’s stepping process, these must be found and applied at each step.
By contrast it is inherent in the
\mathop{\odot}
operator that what DOF it adds by differentiation, it removes by its built-in IVs, leaving their number unchanged.

2.1
Taylor series solution

For an ODE
\accentset{\mbox{\large.}}{x}=f(t,x)

Given an initial value

For

\accentset{\scalebox{.8}{\mbox{\large..}}}{x}(t_{0})=\partial f/\partial t(t_{0},x_{0})+\partial f/\partial x(t_{0},x_{0})\accentset{\mbox{\large.}}{x}(t_{0}).

This gives the first three TS terms,
x(t_{0}+s)=x(t_{0})+\accentset{\mbox{\large.}}{x}(t_{0})s/1!+\accentset{\scalebox{.8}{\mbox{\large..}}}{x}(t_{0})s^{2}/2!+\cdots

This proves TS solution is possible but does not give a practical scheme.
For that, use

(or algorithmic)

is built of elementary operations.
E.g., to solve

\displaystyle x^{2}

\displaystyle=x_{0}^{2}+(2x_{0}x_{1})s+(2x_{0}x_{2}+x_{1}^{2})s^{2}+\cdots,

\displaystyle\accentset{\mbox{\large.}}{x}

\displaystyle=x_{1}+2x_{2}s+3x_{3}s^{2}+\cdots.

Starting with a known

In general, denote the

\displaystyle u_{k}={u}^{\!(k)}(t_{0})/k!\,.

(4)

(u/v)_{k}&=\frac{1}{v_{0}}\bigl(u_{k}-\sum_{r=0}^{p-1}v_{k-r}(u/v)_{r}\bigr),\quad(v_{0}\neq 0).\end{split}

3
Sub-ODEs from a DAE viewpoint

3.1
Discussion

Using a sub-ODE means replacing some standard function, occurring in the definition of an ODE or DAE, by an ODE that it satisfies.
Subsection
2.3
showed that this converts an ODE to a DAE.
Why does this not cause problems for the Taylor coefficient recurrences?
The theory of
standard solution scheme
of a
structurally amenable
(S-amenable) DAE answers this question.
It is summarised in Appendix
; a term defined there is shown
slanted
on first appearance.

Consider a DAE in
n

x_{j}=x_{j}(t)
, of the form

\displaystyle F_{i}(t,\mbox{the $x_{j}$ and derivatives of them})=0,\quad i=1\!:\!n.

(15)

We assume functions are suitably smooth, so needed derivatives always exist.

As informal notation, denote by
\underline{x}
the vector of
t
, and all derivatives
{x_{j}}^{\!(k)}
,
k{\geq}0
,
j{=}1\!:\!n
that occur in the
F_{i}
, in some standard order.
Then (
15
) can be written

\displaystyle F(\underline{x})=0.

(16)

As we do it, using a sub-ODE involves three stages.

(1)

Extract each relevant occurrence of function
g
to an explicit assignment
v=g(u)
, making
u(t),v(t)
state-variables (
u
scalar,
v
possibly vector) if they aren’t already.

(2)

Differentiate
v=g(u)
to become
\accentset{\mbox{\large.}}{v}=g^{\prime}(u)\accentset{\mbox{\large.}}{u}
.

(3)

Replace
\accentset{\mbox{\large.}}{v}=g^{\prime}(u)\accentset{\mbox{\large.}}{u}
by
\accentset{\mbox{\large.}}{v}=h(u,v)\accentset{\mbox{\large.}}{u}
for a suitable

.

In case we started with an ODE, an initial stage (0) recasts it as a DAE, which is easily shown to be always S-amenable.
Then Subsections
3.2
,
3.3
,
3.4
show each of stages (1)–(3) preserves S-amenability.

3.2

The first result is purely algebraic and deceptively simple: if a DAE (

) is S-amenable, it remains so when we extract a scalar expression

present in one or more components

and replace it by a new variable

Replacing is optional: if there are several occurrences of the expression, one can replace all, some or none.
For example with

\displaystyle 0
