Open-Vocabulary Part-Based Grasping
Tjeard van Oort, Dimity Miller, Will N. Browne, Nicolás Marticorena, Jesse Haviland, Niko Suenderhauf

Abstract
Many robotic applications require to grasp objects not arbitrarily but at a very specific object part . This is especially important for manipulation tasks beyond simple pick-and-place scenarios or in robot-human interactions, such as object hand-overs. We propose AnyPart, a practical system that combines open-vocabulary object detection, open-vocabulary part segmentation and 6DOF grasp pose prediction to infer a grasp pose on a specific part of an object in 800 milliseconds. We contribute two new datasets for the task of open-vocabulary part-based grasping, a hand-segmented dataset containing 1014 object-part segmentations, and a dataset of real-world scenarios gathered during our robot trials for individual objects and table-clearing tasks. We evaluate AnyPart on a mobile manipulator robot using a set of 28 common household objects over 360 grasping trials. AnyPart is capable of producing successful grasps 69.52 %, when ignoring robot-based grasp failures, AnyPart predicts a grasp location on the correct part 88.57 % of the time.



I
Introduction

For intelligent robots to safely interact in robot-human environments, objects need to be grasped appropriately. Many common household items have designated parts that need to be grasped based on the circumstances. For example, if a robot were pick up a mug of hot coffee with the intention of handing it to a person, the robot should grasp the body of the mug with the handle facing outwards, allowing the person to grab the handle. In a different scenario, for example, grabbing this same mug out of a cluttered dishwasher, a different grasp position would need to be selected. Ideally, we want the mobile manipulator to be able to flexibly grasp any object by any part in a widescale open-vocabulary manner.

Recent work

While they achieve state-of-the-art grasping performance for open-vocabulary part-based grasping, a key limitation is the time it takes to produce a single grasp prediction. To compute a grasp, the system requires capturing multiple photos and train a Lerf for the given scene, which can take upwards of 118 seconds to complete. We aim to address this gap in research for computationally efficient open-vocabulary part-based grasp prediction models.

AnyPart decomposes part-based grasping into three stages: object isolation, part detection and grasp prediction. We propose AnyPart, a modular framework that, given a user prompt, can predict part-specific grasp proposals for open-ended objects within 800 milliseconds. The framework incorporates three modules that blend recent advances in foundation models with state-of-the-art task-specific models: a vision-language model object detector, a vision-language part segmentation model, and a grasp prediction model. AnyPart’s design allows models to run from a shared GPU within their own separate programming environments preventing any dependency issues that can occur. The modularised design further allows users to easily determine which models are responsible for grasp failures as each model only works towards a specific sub-task. We demonstrate AnyPart using two separate experiments, a digital dataset of hand-labelled images of objects and their relevant part segmentations, and a set of physical grasping experiments with a mobile manipulation platform on a range of common household objects.

While bounding box based detection can perform well there is a notable drawback with utilizing them. With bounding boxes, there is an inherent lack of separation of elements within the box itself. III
Problems and Assumptions

The objective of the mobile manipulator is to grasp and successfully lift a target object by the specified part. The object and part are identified through a natural language query (e.g. “mug, handle”). This query provides both the object of interest “mug” along with the part of interest that should be grasped “handle”. We assume access to a robotic arm with a wrist-mounted RGB-D camera and parallel grippers for grasping. It is further assumed that the object and part are both visible and reachable by the mobile manipulator. Lastly, in scenes where multiple of the same type of object are present, we assume that there is a discernible difference that can be added to the object prompt (e.g., “red mug” or “wooden spoon”).

IV
Method

Provided a given scene with an object of interest, AnyPart is provided an RGB and depth image along with an object, Part pair text prompt and outputs a 6 DOF grasp pose for the robot to action. AnyPart is capable of this by composing the problem as a multi-stage pipeline. The desired object is isolated from the field of view using an object detector and the object component of the text prompt to produce a cropped image. A part-based segmentation model segments the desired part of interest using the part component of the text prompt. This segmentation, as well as the depth image is provided to the grasp prediction model to generate the target poses specific to the part of interest. A breakdown of this is shown in Figure
2
which showcases grasp predictions for a mug handle.

A binary segmentation mask is produced and resized to match the original image, this is provided to Contact-GraspNet along with the depth map to produce the final grasp pose prediction

IV-A

Object and Part Isolation

A part prompt e.g. “handle” can match multiple objects. AnyPart is required to perform object isolation before part segmentation to prevent the wrong object from being grasped. This is currently achieved using the open-vocab object detector Grounding-DINO
[
14
]
. The object detector is fed an RGB image from the wrist-mounted camera and a user-provided object text prompt and produces a bounding box for the desired object. This bounding box is used to crop the image to isolate the target object before providing it to the part-segmentation model. An example of this can be seen in Figure
2
where the glue bottle is cropped in on before being provided to the part-segmentation model

Once the image is cropped in on the target object, we use VLPart
[
22
]
, an open-vocab part-based segmentation model to further isolate the desired part. We utilise a segmentation model for this instead of an object detector as the segmentation mask allows for foreground and background elements in the image to be filtered out with only the desired part isolated. To do this, VLPart is provided the cropped RGB image and the part text prompt and produces a binary segmentation mask. This segmentation is performed by limiting VLPart’s vocabulary to only the desired part and collecting the top-ranked segmentation produced from the model. This can be seen in Figure
2
where the segmentation produced by VLPart is overlayed onto the original cropped image in blue. This image is then resized to be the same as the original RGB image before being provided to the grasp generation model to ensure that the segmentation is aligned correctly to the depth image.

IV-B

Grasp Generation

The final stage of the framework involves the use of a grasp proposal model. The model used for our testing was Contact-Graspnet
[
3
]
however any generalistic grasp generation model could be used in place as long as grasps are filtered to the binary segmentation mask produced by the part segmentation module. In AnyPart the grasp generation module is provided with an aligned depth image as well as the segmentation mask produced earlier, this module then predicts a list of grasp proposals that are ranked by the model’s confidence for a successful grasp. We filter these grasp proposals to use the highest-scoring prediction. Contact-Graspnet was chosen over other grasp proposal models as it allowed grasp predictions to be generated from any camera angle rather than limiting the mobile manipulator to only a top-down perspective, furthermore, it allows for grasps to be filtered through a segmentation mask using built-in functionality.

IV-C

Integration with the Mobile Manipulator

Once all the modules are linked the framework can produce 6 DOF grasp poses from the provided RBG-D image and a target text prompt. For our experiments, no additional filtering was performed for situations where objects are occluded or not visible by the robot when the RGB-D image is captured. These aspects can be focused on in future research.

To utilize AnyPart with our mobile manipulator we collect an RGB-D image from the wrist-mounted camera as well as an object-part text prompt from the user. This information is fed into AnyPart to generate the 6 DOF grasp pose prediction. Actioning the grasp itself is set up with three stages, a pre-grasp, grasp and post grasp position. The pre-grasp position is generated 10cm away from the target grasp pose in the z direction. As an example, if the robot determines to grasp an object from the side the pre-grasp pose will be facing towards the object but be placed 10cm away in the direction it will travel to reach the target grasp pose. The target grasp pose is unaltered from the grasp prediction. The post-grasp pose is positioned 10cm in the vertical direction with respect to the world frame, this results in the object being lifted off of the table.

For table clearing tasks two additional steps are added. As we are placing the objects on a cart to the side of the robot we have a home position, wrist at a rough 45-degree angle positioned higher up over the base of the arm to prevent collisions. The placing position is directly over the cart with the wrist facing downwards to gently drop the object.

V
Digital Experiments

To evaluate the effectiveness of this framework we used two sets of experiments. The first experiment is conducted using a digital dataset of RGB images taken with an intel realsense D435 camera of a variety of common household objects, in total there are 42 unique objects photographed and 90 hand-labelled parts segmented. Photos were taken with objects individually and in groups on a textured background from a top-down perspective. Each image and part segmentation were further augmented by flipping horizontally and rotating images by 10 degrees in either direction providing a total of 1014 segmented image and text prompt pairs. Text prompts for each image are the object name and the desired part. This dataset is used to evaluate the object detector and part segmenter combination of the framework using the mIoU score. The dataset further contains images of door/drawer handles as well as buttons to help evaluate if this is a potential application for future works dealing with manipulation of objects.

VII
Limitations

There are a few key limitations to AnyPart. Firstly as the framework is built using a combination of foundation models this can require access to more video memory than a more conventional model design. In our testing we utilized up to 22 GB of video memory with all models running at the same time. This can be reduced depending on the model usage but could also increase if larger and more reliable models are utilized. Secondly, as there is a reliance on running the models one after the other if one model were to cause a failure it prevents the rest of the framework from producing a correct grasp prediction, this results in errors of each of the models compounding. Lastly as the framework in its current design requires 3 models to be run back to back the overall time to produce a grasp prediction is heavily dependent on the speed of these models, in our testing it takes between 6-9 seconds per grasp prediction depending on the size of the object in the camera field of view. This slower time was largely caused by VLPart being initialized for new part prompts, which would take 5-8 seconds to process. This time can be reduced by using smaller and faster models at the cost of performance as these could result in higher error rates.

In future works, we aim to utilize AnyPart for tasks like open vocabulary object manipulation. Once the robot has grasped the part of interest knowing what to do next can be beneficial as many objects need to be grasped in specific ways but also handled in specific orientations.

VIII
Conclusion

This paper presents AnyPart, a framework for combining foundation models to perform open-vocabulary part-based grasping of objects. Utilizing the discussed combination of models AnyPart was able to successfully grasp and lift 69.52% and 54.67% of the time for individual objects and objects in more cluttered table-clearing scenarios. The framework was capable of producing grasp pose suggestions on the correct part 88.57% and 82% of the time for individual and groups of objects. AnyPart can achieve this performance while maintaining a significantly lower inference time compared to existing state-of-the-art systems like Lerf-TOGO. Further work will be conducted to showcase the modularity of the framework and compare a variety of model combinations and their performances. All code, results and datasets collected throughout this work will be available online.
