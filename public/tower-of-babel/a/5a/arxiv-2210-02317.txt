A Real-Time Learning System for Vision-Based Deep Reinforcement Learning on Resource-Limited Computers
Yan Wang, Gautham Vasan, A. Rupam Mahmood

Abstract
Deep reinforcement learning (RL) methods can be prohibitively expensive in terms of computational resource requirements, especially on complex visuomotor control tasks. Running state-of-the-art deep RL algorithms is far beyond the capability of current embedded computers. As onboard computing is a scarce resource in mobile robots, policies and learning systems must be designed such that the computational platform can meet the real-time requirements. In this work, we explore how to use resource-demanding RL algorithms on resource-limited computers for robotic control tasks while satisfying real-time learning constraints. To shed some light on this issue, we propose a system which we call remote-onboard that distributes agent-environment interaction and learning of control policies between a remote and an onboard computer. The onboard computer only performs simple tasks requiring minimal resources essential for agent-environment interaction. The training process and resource-demanding components run on a powerful remote workstation. Our system supports two different policy gradient methods of different computational requirements and three different remote-onboard configurations. We evaluate them on two vision-based control tasks using the UR5 industrial robot arm and iRobot Create2—a mobile robot. Our study shows that the remote-onboard system enables resource-limited computers to leverage resource-demanding RL algorithms for efficiently solving vision-based control tasks in real-time. However, when all computations happen on a single tethered computer, the performance of our system is on par with off-the-shelf implementations. In addition, our results indicate that decoupling agent-environment interaction from policy learning can be beneficial if not vital for good learning performance. Our code will be publicly available at https://github.com/rlai-lab/remote-onboard-agent



I
INTRODUCTION

Building robots capable of adapting to their environments solely using environmental interactions is one of the long-standing goals of embodied artificial intelligence.
Such a capability entails learning on the fly as the agent interacts with the physical world, also known as
real-time learning
. The reinforcement learning (RL) framework is well-suited to formulate real-time learning tasks since an RL agent can discover optimal behaviour through trial-and-error interactions with its environment
(
sutton2018reinforcement
)
.

While researchers have developed impressive deep RL methods to solve complex motor control problems
(
haarnoja2018sac_apps
;
schulman2017proximal
;
abdolmaleki2018maximum
)
, these techniques do not easily extend to real-time learning systems that operate under time and resource constraints (e.g., quadrotors and mobile robot bases). While approaches including learning from demonstrations
(
gupta2016learning
;
vasan2017learning
)
, sim-to-real
(
peng2018sim
;
bousmalis2018using
)
, and offline RL
(
levine2020offline
)
have been used to develop pre-trained agents, there has been relatively little interest in studying real-time learning agents in the physical world.

The primary challenge of real-time learning is that the real world does not pause while the agent computes actions or makes learning updates. In the real-time learning setting, an agent obtains sensorimotor information from various devices and executes action commands at specific frequencies. Given these constraints, an RL agent must compute an action within a chosen action cycle time and perform learning updates without disrupting the periodic execution of actions.

Fig. 1
:
Remote-Onboard system: An overview of the agent-environment interaction in this system.

The problems inherent to real-time learning systems are particularly exacerbated when only resource-limited computers are available to a robot.
Most onboard embedded computers (e.g., Jetson Nano and Raspberry Pi) cannot run a computationally intensive algorithm such as Soft Actor-Critic.
The primary goal of our work is to develop a system that leverages state-of-the-art deep RL methods to support real-time learning on resource-limited computers. On the other hand, the system should introduce minimum overhead to RL algorithms so that it is also suitable for conventional RL research and powerful workstations.
We propose a way to decouple the agent-environment interaction loop from policy learning to make computationally intensive learning methods feasible for real-time learning. We exploit multi-threading and multiprocessing capabilities to handle the intensive computations of state-of-the-art RL algorithms effectively.

The primary contribution of our paper is a task-agnostic
remote-onboard
system that can support various model-free deep RL algorithms.
We decouple agent-environment interaction and policy learning into two distinct elements, namely the
performer
and
learner
as shown in Figure
1
.
In the proposed system, all computationally intensive operations such as gradient updates and sampling from replay buffer are occur within the learner and run on a powerful remote workstation. In contrast, all elements essential for the agent to interact with the real world are a part of the performer and run on a resource-limited onboard computer.

We hypothesize that such a decentralized system enables resource-limited systems to take advantage of resource-demanding deep RL algorithms in real-time learning setting. To fully utilize the computational resources available to a learning agent, our system supports three modes: 1) remote-only, 2) remote-onboard, and 3) onboard-only (see section
VI
for details). We evaluate the performance of the three modes on two visuomotor policy learning tasks using the UR5 industrial robot arm and iRobot Create2, a mobile robot. We use two different learning algorithms, Soft Actor-Critic (SAC) and Proximal Policy Optimization (PPO), to assess the effectiveness of our system.

Our second hypothesis considers the setting where all computations happen on a single computer. In this scenario, we presume that the performance of our system will be on par with off-the-shelf implementations that require lots of computational resource requirements to learn real-time tasks. To assert this, we compare the performance of our system with
yuan2021asynchronous
’s implementation on the UR5-VisualReacher task on a single workstation, although the latter overall learns slightly faster.

II
RELATED WORK

SenseAct is a computational framework for physical robots that allows learning experiments to be reproducible in different locations and under diverse conditions
(
mahmood2018setting
)
. Although SenseAct supports the systematic design of robotic tasks for RL, it does not address how to design real-time learning agents. It is unclear how best to order and distribute computations relevant to learning. We use the guiding principles of SenseAct to design the tasks employed in this paper to showcase the effectiveness of our approach.

krishnan2019air
introduced an open-source simulator and a gym environment for quadrotors. Given that these aerial robots need to accomplish their tasks with limited onboard energy, it is impossible to run computationally intensive RL methods on the onboard hardware. Since onboard computing is a scarce resource and updating RL policies is computationally intensive, they carefully designed policies considering the power and computational resources available onboard. They focused on sim-to-real techniques for learning instead of using experience generated in the real world, thus making their method unsuited to real-time learning.

nair2015massively
proposed a distributed learning architecture called GORILA framework that mainly focused on using multiple actors and learners to collect data in parallel and accelerate training in simulation using clusters of CPUs and GPUs. On the other hand, our work focuses primarily on how best to distribute performer and learner between resource-limited onboard computers and powerful remote workstations to enable real-time learning. In other words, GORILA framework is conceptually akin to the DistBelief
(
distbelief
)
architecture and our system is designed to allow resource limited computers to take advantage of resource demanding RL algorithms in real-time learning tasks. In addition, the GORILA framework is customized to Deep Q-Networks (DQN) while our system can support multiple RL algorithms.

A recent paper by
bloesch2021towards
used a distributed version of Maximum aposteriori Policy Optimization (MPO)
abdolmaleki2018maximum
to learn how to walk with Robotis
OP3 bipedal robots
. The robots’ onboard computer samples actions and periodically synchronizes the policy’s neural network weights with a remote learner process at the start of each episode. They roll out one episode using the current policy, after which the onboard computer sends all data from that episode to a remote replay buffer implemented using the Reverb library
(
cassirer2021reverb
)
.
haarnoja2018learning
also proposed a similar asynchronous learning system tailored to learn a stable gait using SAC and the minitaur robot
kenneally2016design
. However, this approach does not solve any image-based control task. Unlike these two methods, our system is task-agnostic and compatible with multiple algorithms. In addition, our code is publicly available to make it easier for the research community to incorporate the system in their work.

III
Background

Reinforcement learning is a setting where a learning agent can discover the optimal behaviors through trial-and-error interactions with its environment. The agent-environment interaction is modeled using a Markov Decision Process (MDP), where an agent interacts with its environment
at discrete time steps. At each step t, the agent obtains its state information
S_{t}\in\mathcal{S}
and a scalar reward signal
R_{t}\in\mathcal{R}
from the environment. The agent uses a stochastic policy
\pi
with a probability distribution
\pi(a|s)\doteq\mathbb{P}(A_{t}=a|S_{t}=s)
to sample an action
A_{t}\in\mathcal{A}
. After executing the action, the agent transitions to the next state
S_{t+1}
and obtains a reward
R_{t+1}
at the subsequent timestep
{t+1}
according to a transition probability distribution
p(s^{\prime},r|s,a)=\mathbb{P}(S_{t+1}=s,R_{t+1}=r|S_{t}=s,A_{t}=a)
. The state space
\mathcal{S}
and the action space
\mathcal{A}
are assumed to be continuous or discrete. The standard RL objective maximizes the expected sum of rewards
\mathbb{E}_{A_{t}\sim\pi}[\sum_{t}R_{t+1}]
.

III-A

Soft Actor-Critic

Soft Actor-Critic (SAC) is an off-policy RL algorithm where the policy is trained to maximize a trade-off between the expected return and the policy’s entropy
(
haarnoja2018soft
)
. Instead of the standard RL objective,
it uses the maximum entropy objective proposed by
(
ziebart2010modeling
)
:

\displaystyle\pi^{*}=\argmax_{\pi}\mathbb{E}_{A_{t}\sim\pi}\left[\sum_{t=0}^{T}R_{t+1}+\alpha\mathcal{H}\pi(\cdot|S_{t})\right],

where
\alpha
is the temperature parameter determining the relative importance of entropy compared to reward.

SAC concurrently learns a policy
\pi_{\phi}(A_{t}|S_{t})
, where
\phi
denotes the policy parameters and a soft-Q function
Q_{\theta}(S_{t},A_{t})
, where
\theta
denotes the Q-network parameters. The policy is learned by maximizing the following objective:

\displaystyle J_{\pi}(\phi)

\displaystyle=\mathbb{E}_{S_{t}\sim\mathcal{D}}\left[\mathbb{E}_{A_{t}\sim\pi_{\phi}}[\alpha\log{\pi_{\phi}(A_{t}|S_{t})}-Q_{\theta}(S_{t},A_{t})]\right].

The soft-Q function incorporates an entropy bonus to the action-value estimate unlike a regular Q-function. The parameters of the soft Q-function are trained to minimize the soft Bellman residual:

\displaystyle J_{Q}(\theta)

\displaystyle=\mathbb{E}_{D}\left[\frac{1}{2}\left(R_{t+1}+\gamma V_{\tilde{\theta}}(S_{t+1})-Q_{\theta}(S_{t},A_{t})\right)^{2}\right],

where the soft value function
V_{\tilde{\theta}}
is defined as:

\displaystyle V_{\tilde{\theta}}(S_{t})

\displaystyle=\mathbb{E}_{\pi}\left[Q_{\theta}(S_{t},A_{t})-\alpha\log{\pi_{\phi}(A_{t}|S_{t})}\right].

The temperature parameter
\alpha
can be learned by approximating dual gradient descent
(
haarnoja2018sac_apps
)
:

\displaystyle J(\alpha)

\displaystyle=\mathbb{E}_{S_{t}\sim\mathcal{D}}\left[\mathbb{E}_{A_{t}\sim\pi_{t}}[-\alpha\log{\pi_{\phi}(A_{t}|S_{t})}-\alpha\tilde{\mathcal{H}}]\right],

where
\tilde{\mathcal{H}}
is a desired minimum expected entropy.

III-B

Proximal Policy Optimization (PPO)

PPO
(
schulman2017proximal
)
is an on-policy policy gradient algorithm that alternates between collecting data via interactions with the environment and optimizing a clipped surrogate loss function. It limits the magnitude of the policy gradient step to prevent overly large updates that can prove detrimental to learning. The following objective function is used to train the policy:

\displaystyle L_{\theta}^{\text{CLIP}}=

\displaystyle\mathbb{E}_{S_{t},A_{t}\sim\pi_{\theta_{old}}}[\min(\rho_{\theta}(A_{t}|S_{t}){H}_{\theta_{\text{old}}}(S_{t},A_{t}),

\displaystyle\quad\text{clip}(\rho_{\theta}(A_{t}|S_{t}),1-\epsilon,1+\epsilon){H}_{\theta_{\text{old}}}(S_{t},A_{t}))],

where
\rho_{\theta}(A_{t}|S_{t})=\frac{\pi_{\theta}(A_{t}|S_{t})}{\pi_{\theta_{\text{old}}}(A_{t}|S_{t})}
and
H_{\theta_{\text{old}}}(S_{t},A_{t})
is an estimate of the advantage function. The function
\text{clip}(\rho_{\theta}(A_{t}|S_{t}),1-\epsilon,1+\epsilon)
clips the ratio to be no more than
1+\epsilon
and no less than
1-\epsilon
. The policy is optimized by running several iterations of stochastic gradient ascent at each update. We use an adaptation of the PPO-Clip implementation from
SpinningUp2018
for our experiments.

III-C

Random Augmented Data

laskin2020reinforcement
showed the effectiveness of adding random augmentations to image input, such as random cropping, in improving sample efficiency of state-of-the-art learning algorithms in pixel-based control tasks during training. Their proposed approach RAD regularizes representations by learning an augmentation-invariant critic. We also used RAD concurrently with both SAC and PPO to achieve higher data efficiency and overall performance. We apply random cropping during the training phase only. The original image is used during action computation.

V
TASKS

To demonstrate the benefits of our system, we develop two visuomotor tasks that are not easy to solve using simple RL approaches since they require tens of thousands of images to learn good representations and control policies. All environments were designed using the guidelines proposed by SenseAct to reduce computational overhead and take advantage of its asynchronous architecture for handling different transmission rates.

V-A

UR5-VisualReacher

This environment is a modification of the environment proposed by
yuan2021asynchronous
. It is an image-based task whose objective is to move UR5’s fingertip to a random target designated by a red circle displayed on a monitor (Fig.
2
). The movement of UR5 is restricted within a bounding box to prevent collisions and accidental damage. The action space is the desired angular velocities for the five joints between
[-0.7,0.7]
rad/s. The observation vector includes the latest joint angles, the latest joint angular velocities, three consecutive images of dimension
160\!\times\!90\!\times\!3
taken by the camera, and the previous action. Every 40 ms, the Senseact environment process actuates the five joints of UR5 by sending low-level control commands to them and receiving the next observation. The Senseact communicator process transmits the joint data every 8 ms and the image data every
33.\bar{3}
ms. Since this environment is inherently non-Markovian, we stack three images to provide the RL agent temporal history. Each episode lasts 4 seconds (i.e., 100 timesteps). The reward function is designed to encourage the following two behaviors: 1) moving the fingertip closer to the target while keeping the target centralized, and 2) avoiding abrupt twisting of the joints. Specifically, the reward function is as follows
(
yuan2021asynchronous
)
:

r_{t}=\alpha\frac{1}{hw}M\circ W-\beta\left(\bigg|\pi-\sum_{n=1}^{3}\omega_{n}\bigg|+\bigg|\sum_{n=4}^{5}\omega_{n}\bigg|\right),

where
h
is the height and
w
is the width of the image,
M
is a mask matrix whose element
M_{i,j}
is 1 if the target color is detected at location
(i,j)
and 0 otherwise,
W
is a constant weight matrix whose elements range from 0 to 1 to encourage centralization of the target, and
\omega
is the vector of the five joint angles. The coefficient
\alpha
and
\beta
weigh the importance of the two behaviors. In this paper, we set
\alpha=800
and
\beta=1
. During a reset, a new random target is generated and displayed on the monitor for the next episode, and UR5 is set to a predefined posture. The environment runs on a Lenovo Ideapad Y700 Laptop.

V-B

Create-Reacher

In this image-based task, the objective is to move Create2 to a target designated by a green square on a wall as soon as possible. We assume Create2 reached the target if the target square occupies more than 12% pixels of the current image. The size of the image is
160\!\times\!120\!\times\!3
. The area of Create2’s movement is limited by an arena of size
110\text{cm}\times 70\text{cm}
built by wood and cardboard (Fig.
3
). The action is the desired speeds of the two wheels, limited to
[-150,150]
mm/s to prevent damage to it. The observation includes the latest values of the six wall sensors, three consecutive images taken by the camera, and the previous action. The wall sensors are normalized to convert raw values into approximate distances to walls.
Every 45ms, the Senseact environment process actuates the two wheels of Create2 by sending low-level control commands to them and receiving the next observation. The Senseact communicator process transmits the sensory data every 15 ms and the image data every
33.\bar{3}
ms.
Similar to UR5-VisualReacher, we stack three images to give the learning agent temporal history. Each episode has a maximum length of 666 timesteps. The episode terminates earlier if the Create2 reaches the target. The reward is
-1
per step to encourage the agent to reach the target as fast as possible.
The reset routine brings Create2 to a random location in the arena. During a reset, Create2 first moves backward and reorients itself in a random direction. Our reset routine also handles recharging when the battery life falls below a specified threshold. All environment interface processes run on a Jetson Nano 4GB.

VI
The Remote-Onboard System

(a)

Onboard Agent

(b)

Remote Agent

Fig. 4
:
Remote-Onboard System

In our proposed system, the
agent
consists of two distinct computational units:

•

Performer.
This contains computational items responsible for mapping observations to actions sent to the environment. It consists of all essential components for a system to perform in the real world, such as, the actor network and its inference.

•

Learner.
This contains all computationally intensive items involved in learning such as replay buffer, random sampling from it, mini-batch gradient updates, and data augmentation. This process periodically synchronizes with the performer by sharing new policy parameters.

The system supports three modes to handle different computational configurations:

1.

remote-only:
Both performer and learner run on the remote workstation. The onboard computer only needs to relay actions to robots. This mode requires the minimal onboard resources, suitable for small onboard computers such as Arduino Uno.

2.

remote-onboard:
The performer runs on the onboard computer to sample actions, and the learner runs on the remote workstation to update policies. Policies are synchronized between the onboard computer and the remote workstation periodically. This mode has potential advantages over remote-only when using powerful onboard computers such as Jetson-Nano that can perform policy inference.

3.

onboard-only:
Both performer and learner run on the onboard computer. This mode assumes the availability of considerable computational resources onboard. This mode is impractical for RL algorithms that require large replay buffers and intensive computations. However, powerful onboard computers may support this mode for relatively simpler algorithms such as PPO.

The system is designed to work with various RL algorithms. Users can easily add more RL algorithms to the system by implementing the agent interfaces defined by the system. In this paper, we implement two state-of-the-art RL algorithms: PPO and SAC. The resulting systems are called PPO-agent and SAC-agent, respectively. The structure of the SAC-agent configured to the remote-onboard mode is demonstrated in Fig.
4
. In this example, the performer runs on a resource-limited onboard computer, while the learner runs asynchronously on a powerful remote workstation.

When SAC-agent runs in the remote-onboard mode, the performer forks three processes that run in parallel on the onboard computer to mitigate the negative effects of network latency.
The agent-environment interaction process
is responsible for sending actuation commands, receiving observations, and collecting state transition samples.
The send process
sends the collected state transition samples to the replay buffer process in the remote workstation.
The receive process
receives new policy weights from the remote workstation and updates the local policy parameters used to compute actions (Fig.
4(a)
). In the onboard-only and the remote-only mode, the send process and the receive process are not required. The agent-environment interaction process will also send transition samples and receive/update policies.

In the remote workstation, the learner forks three concurrent processes.
The main process
receives samples and sends updated polices.
The replay buffer process
stores state transition samples, samples mini-batches, converts mini-batches to CUDA tensors, and applies random augmentation to images.
The update process
performs gradient updates and shares new policy parameters with the onboard computer (Fig.
4(b)
). The PPO-agent does not have separate replay buffer and update processes. The policy updates are performed in the main process.

The remote agent and the remote workstation are not needed in the onboard-only mode. All learning and performing operations will run on the onboard computer.

VII
EXPERIMENTS

In this paper, we aim to demonstrate the advantages of our remote-onboard system on resource-limited computers. We run experiments using PPO and SAC. While SAC is computationally intensive, PPO has relatively low computational requirements. We used an adaptation of the asynchronous SAC system proposed by
yuan2021asynchronous
to reduce the overhead of policy updates. The PPO-agent was adapted from
SpinningUp2018
, and we extended it to support learning with images.

The default hyper-parameter configuration provided by
yuan2021asynchronous
and
SpinningUp2018
is used for SAC and PPO, respectively. We used a Jetson Nano 4GB as the onboard computer for Create-Reacher. However, the Jetson Nano’s CPU is not fast enough to run UR5-VisualReacher. We observed that the Jetson Nano was only able to support an average action cycle time of
100\text{ms}
for UR5-VisualReacher. Thus, we used a Lenovo Ideapad Y700 as the onboard computer for UR5-VisualReacher instead. The remote workstation
franka
for Create-Reacher has an AMD Ryzen Threadripper
3970\times 32
core processor and an NVidia 3090 GPU. The remote workstation
helper
for UR5-VisualReacher has an AMD Ryzen Threadripper
2950\times 16
core processor and an NVidia 2080Ti GPU.

We compared the performance of SAC and PPO in the three modes of our system. The Jetson Nano and the laptop cannot fit the default buffer size of SAC. We used a binary search strategy to determine the maximum size for the onboard replay buffer. We performed five independent runs with different seeds for each task and mode.

We also run the proposed system on the workstation helper in the onboard-only mode to compare its performance to the system proposed by
yuan2021asynchronous
. This is to verify if the performance of our implementation is comparable to the off-the-shelf implementation in this setting. The environment is UR5-VisualReacher, and five independent runs were performed for each system.

One complete run of Create-Reacher that lasts
150K
timesteps requires roughly 5h of robot operation. This includes the real experience time, the time needed to recharge the batteries, and the reset time of the environment. Similarly, a complete run of UR5-VisualReacher that lasts
100K
timesteps requires roughly 2.5h of robot operation.

IX
DISCUSSION & CONCLUSIONS

In this paper, we proposed a remote-onboard system to allow resource-limited computers to take advantage of resource-demanding RL algorithms to solve robotic control problems. In total, we conducted 45 independent runs in our experiments, which took nearly 160 hours of usage on robots. We achieved effective learning without tuning the hyper-parameters, using only default hyper-parameters proposed by the original authors of PPO and SAC, which indicates the reliability of the algorithms, our learning system, and our task setup. The subtleties and interesting properties of real-time learning revealed by our experiments are summarized in this section.

Effects of latency in communicating actions and observation.
We believe that the relatively poor performance of remote-only mode in all tasks is primarily due to the variable latency in communicating actions and receiving observations over WiFi.
mahmood2018setting
showed that system delays occurring in different computational stages could be detrimental to learning. The variable latency of WiFi in our remote-only setup negatively impacted our learning system.

Comparison of SAC and PPO in this setting.
While we could not run SAC on resource-limited onboard computers in the onboard-only mode, it was relatively straightforward to use PPO in this setting. However, PPO takes much longer than SAC to learn a good policy. SAC achieves twice the return attained by PPO in a shorter time frame (see Fig.
5(b)
and Fig.
6
). While SAC is more sample efficient since it can effectively leverage frequent off-policy gradient updates, it requires considerably more computational resources than PPO. Our results indicate that there exists a trade-off between the availability of computational resources and overall learning performance.

Failure of SAC in onboard-only mode
. Through binary search, we found that the buffer size can be set to 25000 on the Jetson Nano and 40000 on the laptop for the SAC-agent. But unfortunately, we were unable to learn a good policy within a reasonable time frame. The main problem is that each SAC update takes enormous time on both platforms (e.g.,
\sim 87s
on the Jetson Nano). Given a fixed learning period, the total number of learning updates performed by an agent is inversely correlated with the time required to make one SAC update. Considering that both tasks require tens of thousands of updates to achieve good performance, we determined it is impossible to finish the training within a reasonable time frame. Thus, we decided that the Jetson Nano and the laptop does not have enough resources to take advantage of SAC. While SAC is more sample efficient than PPO, its computational requirements prohibit us from successfully deploying it to resource-limited onboard computers in this mode. However, as mentioned earlier, we could still deploy PPO and potentially achieve good learning performance, albeit at a much slower rate.

Our results show that the proposed
remote-onboard
system successfully supported SAC and PPO on resource-limited computers such as Jetson Nano and Lenovo Ideapad Y700 Laptop in solving two real-time tasks, Create-Reacher and UR5-VisualReacher. Our results indicate that the remote-only mode performs worse than the remote-onboard and onboard-only modes due to network latency issues, causing variable delays in collecting observations and sending actions. On the other hand, the remote-onboard mode seems to sidestep the latency issues, thus avoiding the pitfalls of remote-only learning. In addition, our results also show that when our system is configured to the onboard-only mode and deployed to a powerful workstation, its performance is on par with off-the-shelf systems that require lots of resources to enable real-time learning. Thus, our experiments support the claim that the remote-onboard system can help resource-limited computers leverage resource-demanding deep RL algorithms in an effective manner.
