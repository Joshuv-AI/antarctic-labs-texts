Some Fibonacci-Related Sequences
Benoit Cloitre, Jeffrey Shallit

Abstract
We discuss an interesting sequence defined recursively; namely, sequence A105774 from the On-Line Encyclopedia of Integer Sequences , and study some of its properties. Our main tools are Fibonacci representation, finite automata, and the Walnut theorem-prover. We also prove two new results about synchronized sequences.

Fibonacci representations

In this paper we represent the natural
numbers
{\mathbb{N}}=\{0,1,2,\ldots\}
in the Fibonacci (aka Zeckendorf)
numeration system
[
7
,
12
]
.
In this system we write
n
as the sum of
distinct Fibonacci numbers
F_{i}
for
i\geq 2
, subject to the
condition that no two consecutive Fibonacci numbers appear in the sum.
For example,
43=F_{9}+F_{6}+F_{2}=34+8+1
. Usually we write
this representation as a bit string
(n)_{F}=e_{1}e_{2}\cdots e_{t}
,
with
e_{i}\in\{0,1\}
,
e_{1}\not=0
, and

e_{i}e_{i+1}\not=1
, such that
n=\sum_{1\leq i\leq t}e_{i}F_{t-i+2}
.
For example,
(43)_{F}=10010001
. The inverse function, mapping
an arbitrary bit string (with no conditions)
x=e_{1}e_{2}\cdots e_{t}

to the number it represents is defined
to be
[x]_{F}=\sum_{1\leq i\leq t}e_{i}F_{t-i+2}
.

3
Finite automata and regular expressions

A finite automaton is a simple model of a computer. In its simplest
incarnation, a
deterministic finite automaton
(DFA),
the automaton can be
in any one of a finite number of different states. It takes
as input a finite string over a finite alphabet, and processes its
input symbol-by-symbol, choosing the next state through a lookup
table (the
transition function
)
based only on the current state and the next input symbol.
Some of the states are designated as
accepting states
; an
input string is accepted if the automaton is in an accepting state after all
its symbols are processed. In this paper we represent integers in
Fibonacci representation, so we can think of the DFA as processing integers
instead of strings. Thus, a DFA is a good model to represent a
set

of natural numbers; namely, the set of all integers whose representations
are accepted. In this sense, a DFA decides
membership
for
a set (or sequence). DFA’s are typically drawn as
transition diagrams
,
where the arrows represent transitions between states, double circles
denote accepting states, and single circles denote nonaccepting states.

As an example, consider the automaton in Figure
2
. It takes
the Fibonacci representation of a natural number
n
as input, and accepts
if and only if
n
is even.

Figure 2:
Fibonacci automaton for the set of even numbers.

A slightly more complicated model is the
deterministic finite automaton
with output
(DFAO). In this model, an output is associated with every
state, and the output on an input string
x
is the output associated with
the last state reached after processing
x
. This model is adequate for
representing sequences over a finite alphabet; since there are only finitely
many states, only finitely many different outputs are possible.
If a sequence
(a(n))
is computed by a DFAO in the following way—the input
is the representation of
n
and the output is
a(n)
—then we say

(a(n))
is
automatic
. Again, a DFAO is often displayed as a transition
diagram, with the notation
q/i
in a state meaning that the state is
numbered
q
and has output
i
.

For example, the transition diagram in Figure
3
illustrates
a DFAO computing the sequence
(n\bmod 3)_{n\geq 0}
, where the input
is in Fibonacci representation.

Figure 3:
Fibonacci DFAO computing
n\bmod 3
.

We note in passing that, due to a nice result of
Charlier et al.
[
4
]
,
the minimal DFAO computing

(n\bmod k)_{n\geq 0}
for
n
in Fibonacci representation is
known to have
2k^{2}
states.

Finally, there is the notion of
synchronized automaton
that computes
a function
f:{\mathbb{N}}\rightarrow{\mathbb{N}}
. In this case, we use a DFA, but
with
two
integer inputs
n
and
x
read in parallel,
where the shorter input is padded with leading zeros, if necessary,
and the DFA accepts if and only if
x=f(n)
. This model is suited
to representing sequences of natural numbers. It has the important advantage
that if a sequence is represented in this way, then there is a decision
procedure to answer first-order queries about the values of the sequence,
in the logical structure
\langle{\mathbb{N}},+,n\rightarrow f(n)\rangle
.
See
[
9
]
for more details.

As an example, the synchronized automaton in Figure
4
computes
the function
n\rightarrow\lfloor n/2\rfloor
in Fibonacci representation.

Figure 4:
Synchronized Fibonacci automaton computing
\lfloor n/2\rfloor
.

It is quite useful to adopt the convention that in all three models, the result
is not sensitive to the presence or absence of leading zeros in the
representation of numbers.

The most powerful of all three representations for a sequence is the synchronized automaton, since one can obtain the other two from it easily. The downside
is that it is quite possible that there exists a DFA to decide membership
in a sequence
\bf s
,
but there is no corresponding synchronized
automaton computing the
n
’th term of
\bf s
.

In this paper, we sometimes use the notation called a
regular expression
.
For our purposes, the main thing to know
is that
x^{*}
, where
x
is a single string or set of strings,
denotes the set of all strings consisting of zero or more
concatenations of elements chosen from the set
x
specifies.
For more about automata and regular expressions,
see
[
6
]
.

4
Walnut

Walnut
is a theorem-prover for automatic sequences. It can answer
first-order queries about automatic and synchronized sequences defined
over the natural numbers
{\mathbb{N}}
.
The syntax is basically first-order logic, with the following
meanings of symbols:

•

&
is logical AND,
|
is logical OR,

~
is logical NOT,
=>
is implication, and

<=>
means IFF.

•

!=
means
\neq
and
x/y
denotes integer division, that
is,
\lfloor x/y\rfloor
.

•

A
is
Walnut
’s representation for the universal quantifier

\forall
and
E
is the representation for
\exists
.

•

reg
defines a regular expression.

•

def
defines an automaton for later use.

•

eval
evaluates a first-order logic expression with no free
variables, and returns either
TRUE
or
FALSE
.

•

?msd_fib
is a bit of jargon telling
Walnut
to represent
all numbers in the Fibonacci numeration system.

When
Walnut
returns
TRUE
(resp.,
FALSE
) to an
eval

query, the result is a
rigorous proof

that the particular logical statement holds (resp., does not hold).

As examples, here is the
Walnut
code for generating the automata
in Figures
2
and
4
:

def even "?msd_fib Ek n=2*k":
def nover2 "?msd_fib z=n/2":

We will need some
Walnut
code for
the functions
n\rightarrow\lfloor\varphi n\rfloor
and

n\rightarrow\lfloor\varphi^{2}n\rfloor
, where

\varphi=(1+\sqrt{5})/2
, the golden ratio.
The synchronized automata for these can be found in
[
10
]
, under
the names
phin
and
phi2n
, respectively.

Guessing and checking

One of the principal tools we use is the “guess-and-check” method. Here we

guess

and then use

that the defining equation holds. The guessing procedure is
described in
[
10

We can carry out this guessing procedure
for the sequence
A105774

(a(n))

computes the sequence in the following sense: the input is a pair

(n,x)
in Fibonacci representation, and the automaton
accepts if and only if

Theorem 10
.

Suppose
(a(n))_{n\geq 0}
and
(b(n))_{n\geq 0}

are synchronized sequences. Then the following property is
decidable:
(a(n))_{n\geq 0}
is a permutation of
(b(n))_{n\geq 0}
.

Proof.

We just sketch the proof, which depends on linear representations.
For more about these, see
[
10
, Chap. 9]
and

[
2
]
.
Given automata for
(a(n))_{n\geq 0}
and
(b(n))_{n\geq 0}
,
we can find linear representations counting the number of occurrences
of each natural number
n
in each sequence. Then we can form the
linear representation for the difference of these two. Then we
use the fact that whether a linear representation is identically
0

is decidable.
∎

When we perform this calculation
for the sequences
A105774
and
A368200
,
we find that the linear representation for the difference is indeed
zero. It now simply remains to check
that the numbers computed by the automaton are in ascending order:

eval ascending "?msd_fib An,x,y ($a368200(n,x) & $a368200(n+1,y)) => y >= x":

.

Letting

b(n+1)-b(n)\in\{0,1,2\}

Proof.

We use the following

def diff "?msd_fib Ex,y $a368200(n,x) & $a368200(n+1,y) & y=x+z":

It now follows that the first difference sequence
