Analysis of Concurrent Lock-Free Hash Tries with Constant-Time Operations
Aleksandar Prokopec

Abstract
. Ctrie is a scalable concurrent non-blocking dictionary data structure, with good cache locality, and non-blocking linearizable iterators ( Prokopec et al. 2012 ) . However, operations on most existing concurrent hash tries run in O ⁡ ( log ⁡ n ) O(\log n) time. In this technical report, we extend the standard concurrent hash-tries ( Prokopec et al. 2011 ) with an auxiliary data structure called a cache 1 1 1 A complete description of the new data structure is given in the corresponding PPoPP 2018 paper ( Prokopec 2018 ) . . The cache is essentially an array that stores pointers to a specific level of the hash trie. We analyze the performance implications of adding a cache, and prove that the running time of the basic operations becomes O ⁡ ( 1 ) O(1) .

Appendix A
Complexity Analysis

In this section,
we show that the expected execution time
of the cache-trie operations is
O(1)
.
The proof consists of establishing the key depth distribution,
and bounding the expected key and cache depths.
From these bounds, we then conclude that the expected distance
from the cache to the key is constant.

Definition A.1.

Depth
d
of a key is the number of pointer indirections
required to reach an S-node by following pointers in the A-nodes minus
1
,
starting from the root.
Level
\ell
in a 16-way cache-trie
is the number of hash code bits used to find the corresponding S-node,
and is defined as
\ell=d\cdot 4
.

Definition A.2.

We say that a key with a specific hash code
h

occupies
level
\ell
or a depth
d=\ell/4
in a cache-trie
if it has a unique hash code
\ell
-prefix in the cache-trie,
but it does not have a unique
(\ell-4)
-prefix.

Theorem A.3.

Given a universal hash function,
and a cache-trie that contains
n+1
keys,
the probability that an arbitrary key occupies
a position at depth
d
is:

(1)

p(d,n)=(1-16^{-d-1})^{n}-(1-16^{-d})^{n}

Proof.

Consider an arbitrary key
x
in the cache-trie.
There are
n
other keys in the cache-trie,
so the key
x
will occupy the level
\ell

if some non-empty subset of
k
other keys
has the same
\ell
-prefix of the hash code,
but not the same
(\ell+4)
-prefix,

and
the other
n-k
keys have a different
\ell
-prefix.

Next, note that, for any given set of keys
S
,
the cache-trie has the same structure regardless of the order of insertion.
Thus, we can behave as if the key
x
was the first key inserted into the cache-trie.
The rest of the
n
keys are then inserted as
n
independent trials –
each trial is an independent choice of a hash code,
and can either cause a collision
(have the same
\ell
-prefix and a different
(\ell+4)
-prefix compared to
x
),
or not cause a collision (have a different
\ell
-prefix compared to
x
).
Two keys colliding at level
\ell
have

\ell/4
identical consecutive hash code substrings of length
4
,
followed by a different substring of length
4
,
so the corresponding probability is
16^{-\ell/4}\cdot 15/16
.
The probability of a non-collision is
1-16^{-\ell/4}
.
We are interested in those events in which there was at least one collision,
so we count all combinations of
k
colliding keys, where
k\geq 1
.

(2)

p(\ell,n)=\sum_{k=1}^{n}\binom{n}{k}\Big(\frac{1}{16^{\ell/4}}\cdot\frac{15}{16}\Big)^{k}\Big(1-\frac{1}{16^{\ell/4}}\Big)^{n-k}

From the identity:

(3)

\sum_{k=1}^{n}\binom{n}{k}P^{k}(1-P)^{n-k}Q^{k}=(1-P+PQ)^{n}-(1-P)^{n}

we get:

(4)

p(\ell,n)=(1-16^{-\ell/4-1})^{n}-(1-16^{-\ell/4})^{n}

By Definition
A.1
,
d=\ell/4
, and the claim follows.
∎

The probability function
p(d,n)
is a probability distribution over the depth
d
,
as shown by the following corollary.

Corollary A.4.

Let a cache-trie contain a fixed number of keys
n
.
Then
p(d,n)
is a discrete probability distribution over the depths
d
.

Proof.

From the definition of a discrete probability distribution –
the sum of probabilities across all depths is
1
:

\displaystyle\sum_{d=0}^{\infty}p(d,n)=

\displaystyle(1-\frac{1}{16})^{n}-0+(1-\frac{1}{16^{2}})^{n}-(1-\frac{1}{16})^{n}+\ldots

\displaystyle=

\displaystyle\lim_{d\to\infty}\Big[(1-\frac{1}{16})^{n}+(1-\frac{1}{16^{2}})^{n}-(1-\frac{1}{16})^{n}+

\displaystyle+\ldots+(1-\frac{1}{16^{d+1}})^{n}\Big]=\lim_{d\to\infty}(1-16^{-d-1})^{n}=1

Furthermore,
p(d,n)
is positive
for a non-negative
d
.
∎

Theorem

Lemma A.7.

The following sum:

Appendix B

We start by defining some preliminary notions,

While proving safety, we develop sufficient foundation
to easily show linearizability as well.
After that, we show lock-freedom.
The proofs assume the absence of the cache extension.
We then prove that, by extending the cache-trie with the cache data structure,
none of the previously proven properties change.

We start with some basic definitions.

Corollary B.27.

between any two state changes.

A change in the cache-trie state does not imply a consistency change.

we will show that, eventually, a state change must also change
the abstract set that the cache-trie is consistent with.
