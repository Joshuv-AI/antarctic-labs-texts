Faster Cycle Detection in the Congested Clique
Keren Censor-Hillel, Tomer Even, Virginia Vassilevska Williams

Abstract
We provide a fast distributed algorithm for detecting h h -cycles in the Congested Clique model, whose running time decreases as the number of h h -cycles in the graph increases. In undirected graphs, constant-round algorithms are known for cycles of even length. Our algorithm greatly improves upon the state of the art for odd values of h h . Moreover, our running time applies also to directed graphs, in which case the improvement is for all values of h h . Further, our techniques allow us to obtain a triangle detection algorithm in the quantum variant of this model, which is faster than prior work. A key technical contribution we develop to obtain our fast cycle detection algorithm is a new algorithm for computing the product of many pairs of small matrices in parallel, which may be of independent interest.

Introduction

Finding small subgraph patterns is a fundamental computational task, with a multitude of applications for uncovering connections between elements in a data set. Research has been thriving, addressing the complexity of different variants of subgraph isomorphism for fixed size subgraph patterns
H
in a larger host graph
G
: detecting whether a copy of
H
exists, listing all of its copies, counting the number of occurrences, and more.

In this paper, we provide a fast distributed algorithm for detecting
h
-cycles
in the
Congested Clique
model
[
LPSPP06
]
, in which

n

\mathcal{O}(\log{n})
-bit messages to each other, in synchronous rounds.

The pioneering work of
[
DLP12
]
showed that all copies of any
fixed
h
-vertex graph
H
in an
n
node graph can be listed in this model within
\mathcal{O}(n^{1-2/h})
rounds. This result of course applies also to the detection variant. For the case when
H
is a cycle,
[
CKK+19
]
provided an
h
-cycle detection algorithm running in
2^{\mathcal{O}(h)}n^{\rho}
rounds, for both undirected and directed graphs (henceforth digraphs). Here,
\rho
is the exponent of distributed fast matrix multiplication (FMM) in the
Congested Clique
model, i.e., the value such that
\mathcal{O}(n^{\rho})
rounds are sufficient for multiplying two
n\times n
matrices. The value of
\rho
is currently known to be at most
1-2/\omega
where
\omega
is the centralized fast matrix multiplication exponent, and since
\omega\leq 2.371552

[
ADV+24
]
, we get a bound for
\rho
of
0.15667

In the case of 4-cycles in undirected graphs,
[
CKK+19
]
obtained a constant-round detection algorithm, and this result was later generalized
by
[
CFG+20
]

This leaves the complexity of odd-cycle detection as an open question, as well as the detection of cycles of any length in digraphs. For triangles,

]

\tilde{\mathcal{O}}(n^{1/3}/(t^{2/3}+1))

To frame our technical contributions, we first briefly overview the two previous approaches for the case of
triangles
. In
[
DLP12
]
, an
\tilde{\mathcal{O}}\left(n^{1/3}/(t^{2/3}+1)\right)
-round algorithm is presented, where
t
is the number of triangles. The algorithm samples
n
induced subgraphs, and for each sample it checks for a triangle by letting a dedicated vertex collect the edges of the sample.
In
[
CKK+19
]
, a
2^{\mathcal{O}\left(h\right)}n^{\rho}
-round algorithm is presented which employs fast matrix multiplication over the entire graph.

Warm-up.
As a warm-up, consider the following combination of these approaches to get the best of both worlds, leading to an algorithm that completes in
\tilde{\mathcal{O}}\left(n^{\rho}/(t^{2\rho}+1)\right)
rounds, which is already an improvement over the prior state of the art (recall that
\rho<1/3
).
To obtain this, we sample only
t^{2}
induced subgraphs to which each vertex is added with probability
1/t
.
Using the second moment method, we can show that at least one sampled subgraph contains a triangle with probability
\Omega\left(1\right)
.
To check if each subgraph contains a triangle we use matrix multiplication, and so no vertex has to collect the edges of an entire sample.
To compute the product of
t^{2}
square matrices of size
n/t
, we develop a new algorithm, which computes the product of
s
pairs of square matrices of size
k
in

\mathcal{O}\left(n^{\rho-2}\cdot k^{2}\cdot s^{1-\rho}\right)
rounds. This algorithm may be of independent interest.

Another natural approach to consider is one that samples a subset of vertices and checks whether any of these vertices participates in a triangle, rather than attempting to sample a complete triangle.
Here, we can sample each vertex with probability
1/t^{1/3}
and check whether it is in a triangle by invoking rectangular matrix multiplication.
While this too improves upon the state of the art for some graphs, it is always slower than our first approach.
Note that trying to reduce the running time by sampling with a probability that is smaller than
1/t^{1/3}
would reach a dead-end since it is not likely to hit any vertex in a triangle in case all
t
triangles are induced by a clique of
t^{1/3}
vertices. See
for a comparison of the two approaches, as well as the previous algorithms, and our new algorithm.

A caveat is that the first approach does not extend for
h
-cycles, as the number of samples it needs to perform increases with
h
. For example, for
C_{4}
detection, if we sample uniformly random induced subgraph with
n/t
vertices, it contains a copy of
C_{4}
with probability at least roughly
1/t^{3}
which means we have to sample at least
t^{3}
subgraphs to ensure that we find a copy of
C_{4}
with a constant probability. This is slower than the previous best known algorithm of
[
CKK+19
]
which takes
2^{\mathcal{O}\left(h\right)}n^{\rho}
rounds. In other words, the first approach is slower as
h
is larger.

Our contribution.
Our key insight is that we can further boost these two approaches such that they complement each other, in the following sense. For a fixed value of
t
, the first approach is better when the number of vertices that participate in a triangle, which we denote by
x
, is small, while the second approach is better when
x
is large.
This refinement of considering the parameter
x
along with
t
allows us to bring these two approaches a big leap forward by obtaining a faster algorithm for triangle detection, as well as an algorithm for
h
-cycle detection for longer cycles, in both graphs and digraphs.

Our first algorithm, which we refer to as
Find-Cycle
, follows the first approach.
It samples
s=x^{3}/t
subsets of vertices
(U_{1},\ldots,U_{s})
, by adding each vertex to
U_{i}
independently with probability
1/x
.
The algorithm then checks for every
i\in[s]
if
G[U_{i}]
contains a triangle.
This involves computing the product of
s
pairs of square matrices of size
n/x
each, which we do in

\tilde{\mathcal{O}}(n^{\rho-2}\cdot(n/x)^{2}\cdot s^{1-\rho})=\tilde{\mathcal{O}}(n^{\rho}\cdot(1/x)^{2}\cdot(x^{3}/t)^{1-\rho})

rounds.
Using the second moment method (which is very similar to Chebyshev’s inequality) we show that at least one of the
s
induced subgraphs contains a triangle with a constant probability.

Our second algorithm, which we refer to as
Find-Vertex-In-Cycle
, follows the second approach. It samples a subset of vertices
S
, by adding each vertex to
S
independently with probability
1/x
. The algorithm then checks if one of the vertices from
S
participates in a triangle by computing the product of a rectangular matrix of size
n/x\times n
and a square matrix of size
n
. Interestingly, the algorithm
Find-Vertex-In-Cycle
also achieves the same round complexity, as a function of
x
, for
h
-cycle detection, for
h=\mathcal{O}\left(1\right)
.

Our final algorithm alternates between the two algorithms until one of them terminates.
Among all
n
vertices with
t
triangles, the final algorithm is the slowest when the two algorithms have the same round complexity, which happens when
x^{3-1.82408}=\Theta(t)
.

The following states the running time of our fast
h
-cycle detection algorithm, and is proven in
Section

4
.

Theorem 1.1

(
h
-Cycle Detection)
.

Let
G
be a (directed) graph with
t
copies of
h
-cycles.
There is a randomized
Congested Clique
algorithm for
h
-cycle detection, which takes

\tilde{\mathcal{O}}\left(h^{\mathcal{O}\left(h\right)}\cdot n^{0.1567}/(t^{\frac{0.4617}{h-1.82408}}+1)\right)

rounds w.h.p.

Here, the constants
0.1567,0.4617
arise from the complexity of rectangular multiplication.
We are able to show that the product of a rectangular matrix of size
k\times n
and a square matrix can be computed in
O(n^{0.1567}/k^{0.4617})
rounds, using the formula of
[
Gal16
]
and an adaptation of the code of
[
Bra
]
. To get a flavor of the above complexity, note that a crucial implication of
Theorem

1.1
is that we detect a triangle in
\tilde{\mathcal{O}}\left(1\right)
rounds for graphs with at least
t=\Omega(n^{0.3992})
triangles,
improving upon the previously known threshold of
t=\Omega(n^{1/2})
from
[
DLP12
]
.

Many Matrix Multiplications in Parallel.

To implement our
Find-Cycle
algorithm, we need to compute the product of many small random square matrices, which are submatrices of the adjacency matrix of the input graph. We state this informally in the following theorem.

Theorem 1.2

(Informal)
.

Let
k,s
be two integers such that
k\in[\sqrt{n},n]
, and
s\leq(n/k)^{2}
.
Then, in the
Congested Clique
model, the
n
vertices can compute the product of
s
pairs of square matrices of size
k
in
\mathcal{O}\left(n^{\rho-2}\cdot k^{2}\cdot s^{1-\rho}\right)
rounds, given that the input is distributed among the vertices in a “balanced” manner.

The formal definitions and the proof of
Theorem

1.2
appear in
Section

3
, as well as the definitions and claims we need for the proof of
Theorem

1.1
.

The conceptual contribution of
Theorem

1.2
is as follows.
On one hand, it is known that
n
vertices can compute the product of
n
pairs of matrices of size
\sqrt{n}
in a constant number of rounds, given that the input is balanced, by letting the
i
-th vertex collect all the entries of the
i
-th pair of matrices and computing their product.
On the other hand,
n
vertices can also compute the product of one square matrix of size
n
in
\mathcal{O}\left(n^{\rho}\right)
rounds, as shown in
[
CKK+19
]
.

Theorem

1.2
gives a smooth trade-off between these two extremes.

Note that
[
Gal16
]
provides an algorithm for computing the product of
s
pairs of square matrices of size
n
in
\mathcal{O}\left(n^{\rho}\cdot s^{1-\rho}\right)
rounds for
s\leq n
. The paper also provides an algorithm for computing the product of
s
pairs of
rectangular
matrices of sizes
n\times m
and
m\times n
, where the bound on the round complexity is more involved and is not given by an analytic expression, see
Section

3.3
for a discussion.
Moreover, we need to compute the product of square matrices of size smaller than
n
, which is not covered by the above algorithm.

Before providing intuition about our proof of
Theorem

1.2
, we explain what we mean by a balanced input and how the output should be distributed. Given a set of
s
pairs of square matrices
\mathcal{Q}=\left\{(S_{i},T_{i})\right\}_{i\in[s]}
of size
k
each, where
sk^{2}\leq n^{2}
, we think of the input as a “flat” array of
sk^{2}
entries. The input is distributed as follows. The input given to the first vertex is the first
n
entries in this array. The second vertex gets the next
n
entries and so on.
For the output
\left\{(P_{i})\right\}_{i\in[s]}
, where
P_{i}=S_{i}\cdot T_{i}
for
i\in[s]
, we again transform the set of output matrices into a flat array and let each vertex learn distinct consecutive
n
entries from it.
Note that as long as each vertex holds unique
n
entries from the input, and every vertex knows which entries from the input every other vertex holds, then the input can be redistributed in
\mathcal{O}\left(1\right)
rounds, using
Lemma

2.1
.
We therefore define a balanced input as such.

Definition 1

(Balanced Input)
.

An input for
n
vertices is
balanced
if it is partitioned between the vertices such that each vertex holds at most
n
(unique) entries from the input, and every vertex knows which entries from the input are held by every other vertex.

Now we can give the intuition behind the proof of
Theorem

1.2
. We partition the
n
vertices into
s
sets of size
n/s
each. For every
i\in[s]
we call the
i
-th set in the partition the
i
-th
team
. The
i
-th team is responsible for computing the product
(S_{i},T_{i})
(this partitioning method is similar to that of
[
Gal16
]
).
After partitioning, the problem boils down to computing one product of square matrices of size
k
using
n/s
vertices with bandwidth of size
s\log n
, which we solve by extending the work of
[
CKK+19
]
, which considers only the product of square matrices of size equal to the number of vertices.

Recall that our main motivation for this tool of
Theorem

1.2
is to implement the algorithm
Find-Cycle
.
That is, given a graph
G
with
n
vertices, we sample
s
subsets of vertices
(U_{1},\ldots,U_{s})
, where each vertex joins each set independently with probability
p
. Each set
U_{i}
defines an induced subgraph
G[U_{i}]
with an adjacency matrix
A_{i}
.
We need to compute
(A_{i})^{h}
for every
i\in[s]
, and we denote the set
\mathcal{Q}=\left\{(A_{i},A_{i})\right\}_{i\in[s]}
as the input, where we assume
s\leq 1/p^{2}
.
In order to implement the algorithm
Find-Cycle
using
Theorem

1.2
, we need to show that
\mathcal{Q}
is a balanced input. However, this does not precisely hold, but we can show a sufficient guarantee of
\mathcal{Q}
being “almost” balanced w.h.p., in which the requirements in
Definition

1
are weakened. These weaker conditions still allow us to quickly redistributed the elements into a balanced input in
\mathcal{O}\left(\log n\right)
rounds w.h.p.

To conclude, we obtain a fast algorithm for
h
-cycle detection, which beats the previous state-of-the art for odd-length cycles, as well as directed cycles. The algorithm is faster as the number of copies of
h
-cycles increases, where the key parameter for the algorithm and the analysis is the number of vertices in the graph that participate in an
h
-cycle.

Triangle Detection in the
Quantum Congested Clique
Model.

Our new matrix multiplication tool turns out to be helpful for additional tasks. In the quantum setting, we obtain the following in the
Quantum Congested Clique
model, which is similar to the
Congested Clique
model, but the vertices exchange messages of
\mathcal{O}\left(\log n\right)
qubits in each round instead of standard bits.

Theorem 1.3
.

There exists a
Quantum Congested Clique

\tilde{\mathcal{O}}\left((n/(t^{2}+1))^{3\rho/4}\right)
-round algorithm for triangle detection, with a success probability of at least
1/2
.

We prove this theorem in
Section

5
.

Theorem

1.3
obtains an
\tilde{\mathcal{O}}(n^{3\rho/4})
-round algorithm that remains effective even when
t=0
. This is faster than the previous state-of-the-art algorithm from
[
CKK+19
]
, which takes
\mathcal{O}\left(n^{\rho}\right)
rounds and does not leverage the additional capabilities that the
Quantum Congested Clique
model offers.
For subgraphs other than triangles, there are detection algorithms in the
Quantum Congested Clique
which use the extra power of the model. For example,
[
CFG+22
]
provides an algorithm for larger clique detection.
Moreover, in the quantum
Congest
model, there are algorithms for clique and cycle detection
[
ILG17
,
FLMT24
]
, which are faster than their
Congest
counterparts.

Our algorithm uses a Grover search
[
Gro96
]
, which is a quantum algorithm to find an element in an unsorted list of size
L
, while accessing only
\sqrt{\left\lvert L\right\rvert}
entries from the list.
Generally, given a function
f:X\to\left\{0,1\right\}
and a universe
X
, Grover search is a quantum algorithm which finds an
x\in X
such that
f(x)=1
(assuming such
x
exists), by querying
f
at most
\sqrt{\left\lvert X\right\rvert}
times w.h.p.
In
[
LGM18
]
a distributed implementation of Grover search was provided, for the quantum
Congest
model, which was later extended to the
Quantum Congested Clique
model in
[
IG19
,
CFG+22
]
.

We provide an overview of our algorithm, which has two steps. In the first step, we sample
s=1/t^{2}
random induced subgraphs
(U_{1},\ldots,U_{s})
, where each vertex joins every set independently with probability
1/t
.
We partition the vertices into
s
sets, each of
n/s
vertices, which we call teams.
For
i\in[s]
, the
i
-th team uses Grover search to detect a triangle in the subgraph
G[U_{i}]
, as follows. It samples
\ell=8\log n/q^{3}
subsets of vertices
(W_{1},\ldots,W_{\ell})
, where each vertex from
U_{i}
joins each set independently with probability
1/q
. The universe for the search is the set
X\triangleq\left\{G[W_{i}]\right\}_{i\in[\ell]}
, and the boolean function
g
is defined as
g(G[W_{i}])=1
if
G[W_{i}]
contains a triangle, and
0
otherwise.

The correctness of the algorithm follows because if the graph
G
has
t
triangles, then there exists an index
i\in[s]
such that
G[U_{i}]
contains a triangle with probability at least
1/10
. The
i
-th team finds this triangle using
\sqrt{1/q^{3}}
evaluations of
g
w.h.p.
The final detail of the algorithm is to set
q
such that each evaluation of
g
takes
\mathcal{O}\left(1\right)
rounds, which optimizes the round complexity of this approach.

Our above fast triangle detection algorithm for the
Quantum Congested Clique
model is given in
Section

5
. Extending our approach to
h
-cycle detection is not straightforward; we elaborate on the challenges in
Section

5.2
.

Additional Related Work.

In this
Congested Clique
model, matrix multiplication was first studied by
[
DKO14a
]
. After the aforementioned works of
[
CKK+19
,
Gal16
]
, the work of
[
CHLT20
]
showed an algorithm whose running time improves with the sparsity of the input matrices, and
[
CDKL21
]
showed algorithms for sparse matrix multiplication which also enjoy the sparsity of the output or when only a sparse piece of the output is needed.

The task of listing subgraphs has also received great attention in the
Congested Clique
model. Here, each vertex needs to output a list of copies of the subgraph
H
, such that the union of the lists is exactly the set of all copies of
H
in the graph. As mentioned,
[
DLP12
]
give an algorithm for listing all
h
-vertex graphs within
O(n^{1-2/h})
rounds. For triangles, this is known to be tight by
[
ILG17
,
PRS21
]
.
This optimality extends to larger cliques due to
[
FGKO18
]
.
Listing triangles in sparse graphs can be done faster, as first shown by
[
PRS21
]
with a randomized algorithm, and then followed up by
[
CHLT20
]
with a deterministic algorithm. Afterward,
[
CHGL20
]
showed faster sparse listing for larger cliques, which also has a deterministic algorithm due to
[
CFG+20
]
.

We mention that in the closely-related
Congest
model, in which the communication graph is the input graph itself, rather than being a complete network, the state of affairs is in stark contrast to the
Congested Clique
model. For listing cliques, optimal algorithms are known due to
[
CPSZ21
,
CHCGL21
]
, with deterministic solutions in
[
CS20
,
CHLV22
,
CHS24
]
. The underlying approach, initiated by
[
CPSZ21
]
, is to construct an expander decomposition, which partitions the vertices into components with good expansion (low mixing time). At a very high level, the vertices of each component list cliques for which some edges are inside the component, and then recurse over the remaining edges.
However, for an algorithmic approach of the
Congested Clique
model to have a fast implementation in the
Congest
model, also when using the known routing procedures
[
GKS17
,
GL18
]
, the algorithm has to adhere to certain conditions. In other words, it is not the case that any algorithm in the
Congested Clique
model can be executed efficiently by the components of the expander decomposition in the
Congest
model.

Specifically, we stress that for the detection variant in
Congest
, the state of the art even just for triangles is the same as for listing. That is, even the
O(n^{\rho})
algorithm of
[
CKK+19
]
does not have an implementation in the
Congest
model, and it is unknown how to detect triangles in less than the time it takes for listing them (interestingly, the only lower bounds that are known are that a single round does not suffice
[
ACKL20
,
FGKO18
]
). For larger
h
-cycles, detection for odd values of
h
is known to have a complexity of
\tilde{\Theta}(n)

[
DKO14b
]
. Much work is invest in studying the complexity of detecting even cycles

[
DKO14b
,
KR17
,
CFG+20
,
EFF+22
,
CFG+22
,
vAdV22
,
FLMT24
]
, with the state of the art being a recent result showing that
h
-cycles can be detected in
\tilde{O}(n^{1-2/h})
rounds for even values of
h

[
FLMT24
]
.

Investigations into the subgraph detection problem have also been conducted in additional models such as the quantum
Congest
and
Quantum Congested Clique
models, where vertices exchange qubits instead of standard bits. In
[
ILGM20
]
, a quantum

\tilde{\mathcal{O}}\left(n^{1/4}\right)
-round algorithm for triangle detection was presented, which outperforms the

-round

]

Additional upper and lower bounds for cycle detection in the quantum

[

,

]
.
In
[

]
, an

, was presented, which achieves an
\tilde{\mathcal{O}}\left(n^{1-2/(p-1)}\right)
-round complexity, which is faster than the classical

Further research in the quantum distributed models includes both upper and lower bounds for various problems
[
EKNP14
,

,
vAdV22
]
.

There is extensive research about subgraph finding in additional models of distributed computing. All of these important works are a bit more far from our work here, and hence we refer the reader to the survey of

as such that

.
If

as such that

We present two claims on

, and that the term

is equal to is the probability for
h

to form an
h
-cycle in

.

Claim 1
.

Let
G
be a graph with
t
copies of an
h
-cycle and
x
vertices that participate in at least one
h
-cycle.
Sample
h
vertices
(v_{1},\ldots,v_{h})
from
V_{\mathcal{C}_{h}}(G)
uniformly at random with replacement from
V_{\mathcal{C}_{h}}(G)
. Then the probability that they form an
h
-cycle is exactly

.

Proof.
We first emphasize that we consider
(v_{1},\ldots,v_{h},v_{1})
to be an
h
-cycle only if all the vertices are distinct other than the first and the last which are the same vertex, and that for
i\in[h]
we have that
(v_{i},v_{i+1\mod h})
is an edge in
G
.

To prove the claim, we count the number of
h
-tuples of vertices that form an
h
-cycle in
G
, and the number of
h
-tuples of vertices from
V_{\mathcal{C}_{h}}(G)
. The probability that the sampled vertices form an

-cycle is equal to the ratio of the former to the latter.

The latter is equal to
x^{h}
. The former is equal to
2ht
for undirected graphs, as each
h
-cycle is associated with exactly
2h
tuples of vertices.
For directed graphs, the former is equal to
ht
, as each
h
-cycle is associated with exactly
h
tuples of vertices.

For undirected graphs, this implies that the sampled vertices form an

-cycle is equal to

, where we used the fact that
2ht=x^{h-\delta}
.
For directed graphs, this implies that the sampled vertices form an
h
-cycle is equal to
\frac{ht}{x^{h}}=\frac{x^{h-\delta}}{x^{h}}=x^{-\delta}
, where we used the fact that
ht=x^{h-\delta}
.
This completes the proof.
∎

Claim 2
.

It holds that
\delta\in[0,h-1]
.

Proof.
It is clear that
\delta\geq 0
, as

is equal to the probability of some event and therefore cannot be strictly bigger than

We prove that
\delta\leq h-1

Sample
h

with replacement and let

h
-cycle, there is an ordered tuple of

such that

forms an

for every

is exactly

. This lower bounds the probability of sampling an
h
-cycle. Therefore,
x^{-\delta}\geq 1/x^{h-1}
, implying
\delta\leq h-1
.
∎

3.1
Preliminaries and Balanced Products.

In this section, we define the problem of computing
s

k
each, as well as defining what is a balance input.
We assume throughout the paper that the matrices are over a field
\mathbb{F}
, where each element can be represented using
\mathcal{O}\left(\log n\right)
bits.

We introduce the following definitions to specify the required input.

Definition 3

(The notations

and

)
.

Let

be some matrix. We denote the

-th row of

by

.
For a matrix

and two indices

for

to denote a matrix of dimension

. For every index

, we split it into three indices

v_{1},v_{3}\in[n^{1/2}\cdot k^{-1/4}],\;v_{2}\in[\sqrt{k}]

The expression

The following definition formally defines the problem of multiple matrix multiplications.

Definition 4

(
\mathsf{Product}\left(\mathcal{Q}\right)
)
.

Given set of
s

\mathcal{Q}=\left\{(S_{i},T_{i})\right\}_{i\in[s]}
of size

.
In the
\mathsf{Product}\left(\mathcal{Q}\right)
problem,
n
nodes need to compute the products of those pairs of matrices. The input is distributed as follows.
Each vertex
v\in V
is assigned a label
\ell(v)=(i,x,y)
, where
i\in[s]
, and
x,y\in[\sqrt{n/s}]
.
The vertex

gets as input the submatrix

, and has to learn the entries of the submatrix
P_{i}[*x*,*y*]
, where
P_{i}=S_{i}\cdot T_{i}
for
i\in[s]
.
We denote the round complexity of this problem by
\mathsf{MM}\left(k,k,k;s\right)
.

Note that every vertex can learn the label of each other vertex in
\mathcal{O}\left(1\right)
rounds.
The following theorem is the main theorem for this section, in which we provide an upper bound for the round complexity of the
\mathsf{Product}\left(\mathcal{Q}\right)
problem.

Theorem 3.1
.

For any two integers

where

and
s\leq(n/k)^{2}
, we have that

\mathsf{MM}\left(k,k,k;s\right)=\mathcal{O}(n^{\rho-2}\cdot k^{2}\cdot s^{1-\rho})
.

To prove the theorem, we first partition the
n
nodes into
s
sets of size
n/s
each. For every
i\in[s]
we call the
i
-th set in the partition the
i
-th
team
. The
i
-th team is responsible for computing the
i
-th product in
\mathcal{Q}
, i.e., the product
(S_{i},T_{i})
.
After partitioning into teams, the problem boils down to computing one product of square matrices of size
k
using
n/s
node with bandwidth of size
s\log n
.
This extends
[
CKK+19
]
, in which only the product of square matrices of size equal to the number of vertices is considered, and uses
[
Gal16
]
, in which multiple products are divided into teams.
A crucial step in the algorithm for

3.1
is to compute the product of a single matrix of size

using
n^{\prime}
nodes, which we define next.

Definition 5

(
\mathsf{Single\mhyphen Product}\left(n^{\prime},R\right)
)
.

Let

be a team with
n^{\prime}
vertices.
Let

be two square matrices of dimension

Each vertex

The input of each vertex

and

.

Proposition 1
.

The
\mathsf{Single\mhyphen Product}\left(n^{\prime},R\right)

model with

vertices in the base graph and bandwidth

\mathcal{O}\left((n^{\prime})^{\rho}\cdot(R/n^{\prime})^{2}\cdot\frac{F}{B}\right)

Using bandwidth

The proof for

1
(

) is derived by minor modifications to the proof of
[

, Theorem 1]
of multiplying

We are now ready to prove

.

Proof of
Theorem

3.1
.
We use

1
by setting

to be the size of each team, i.e.,

. We set

to

. Since the base matrix is a boolean matrix, we can set

.
We get that after step one, each team can compute the square of the matrix it is responsible for in

We next explain how to further improve the running time of the second step.
In the algorithm presented in

Consequently, each vertex transmits only

messages per round of size

However, by utilizing the bandwidth between the teams, each vertex can send more messages or equivalently send larger messages.

\mathcal{O}\left(n^{\prime}\right)

\mathcal{O}\left((n/n^{\prime})\log n\right)

From

Specifically, each team completes its computation in

∎

Before presenting the algorithms, we overview the color-coding technique
[

]

To detect an
h

colorful

h

h

This provides additional structure, which a detection algorithm can benefit from.
However, not every coloring induces a colorful
h
-cycle, which means that to detect an
h
-cycle, we might have to repeat this experiment multiple times, until we sample a coloring that induces a colorful
h
-cycle.

In more detail, given a graph
G
with
n

\varphi:V\to[h]
, which means that
\varphi
colors each vertex uniformly independently at random. We then build the auxiliary graph
G_{\varphi}
which is a directed graph, as follows.

Definition 11

(
G_{\varphi}
)
.

Given a graph
G
, and a coloring
\varphi:V\to[h]
, we define a new directed graph
G_{\varphi}
on the same vertex set, with a set of directed edges
E(G_{\varphi})\triangleq\left\{(u,v)\in E(G)\mid\varphi(v)=(\varphi(u)+1)\mod h\right\}
. That is, only a subset of the edges is kept, and it consists of the edges from the vertices of color
i
to the vertices of color
(i+1)\mod h
, for
i\in[h]
.

The graph

has the property that every walk of length smaller than
h
is a simple path, and every closed walk of length
h
is a cycle. Here, a
walk
of length
h
on a (directed) graph is a sequence of vertices
(v_{1},v_{2},\ldots,v_{h+1})
not necessarily distinct, such that for
i\in[h]
we have that
(v_{i},v_{i+1})
is an edge in
G
.
We say that a walk is a simple path if all the vertices in the walk are distinct. A walk
(v_{1},v_{2},\ldots,v_{h},v_{h+1})
is
closed
if
v_{1}=v_{h+1}
.

We explain how we benefit from the property that every closed walk of length
h
in
G_{\varphi}
is a cycle.
Let
A_{\varphi}
denote the adjacency matrix of
G_{\varphi}
.
We can compute the
h
-th power of the matrix
A_{\varphi}
, and look at the diagonal of the obtained matrix. Then,
G_{\varphi}
is
h
-cycle free if and only if all the entries on the diagonal are equal to
0
.
Clearly, if
G
does not contain an
h
-cycle, then for any coloring
\varphi
, we have that
G_{\varphi}
does not contain an
h
-cycle.
The more interesting property of this random coloring is that if
G
contains an
h
-cycle, then the probability that
G_{\varphi}
contains one is at least

, as we prove next.

Claim 7
.

Let

be a graph with at least one

-cycle.
Let
\varphi:V\to[h]
be some uniformly random coloring.
Then

contains an
h
-cycle with probability at least
\frac{1}{h^{h}}
.

Proof.
Let
C=(v_{1},\ldots,v_{h},v_{1})
be some
h
-cycle in
G
.
We prove that
C
is also an
h
-cycle in
G_{\varphi}
with probability at least
\frac{1}{h^{h}}
.
For
C
to be an
h
-cycle in
G_{\varphi}
, the vertex
v_{i}
must be colored by the color

, for

. As each vertex is colored with a uniformly random color, this event occurs with probability

, which proves the claim.

4.1

We explain how to detect an

-cycle in time

w.h.p., with a one-sided error, as stated in the next theorem.

Theorem 4.1
.

There exists a randomized
Congested Clique
algorithm to detect an
h
-cycle in time
\tilde{\mathcal{O}}\left(\mathsf{MM}\left(n,n,\frac{n}{x}\right)\right)
w.h.p., with a one-sided error.

Let
G
be a graph with
n
vertices and
t
copies of an
h
-cycle, for a fixed constant
h
.
For a graph
H
, we denote by
V_{\mathcal{C}_{h}}(H)
the set of vertices that participate in an
h
-cycle in
H
. Let
x=\left\lvert V_{\mathcal{C}_{h}}(G)\right\rvert
.
We prove
Theorem

4.1
by
analyzing the following random process. We implement it in the
Congested Clique
model in
Section

4.2
.

Find-Vertex-In-Cycle
.

The input of the algorithm is a graph
G
and some value
p\in[0,1]
. The output is “
True
” if at least one
h
-cycle is detected, and “
False
” otherwise.
The algorithm works as follows.
The algorithm samples a coloring
\varphi:V(G)\to[h]
, uniformly at random, and uses it to define a new auxiliary graph
G_{\varphi}
, as explained in
Definition

11
.
Let
V_{i}
denote the set of vertices in
G_{\varphi}
that are assigned the color
i
, for
i\in[h]
.
The algorithm then samples a subset of vertices from
V_{1}
, by sampling each vertex independently with probability
p
. Let
U_{1}
denote the set obtained.
Define
F_{\varphi}
as the induced subgraph of
G_{\varphi}
with the vertex set
U_{1}\cup\bigcup_{i=2}^{h}V_{i}
.
Let
A_{F_{\varphi}}
denote the adjacency matrix of the graph
F_{\varphi}
.
Next, the algorithm exactly counts the number of
h
-cycles in
F_{\varphi}
using rectangular matrix multiplication.
That is, it computes the trace of the
h
-th power of
A_{F_{\varphi}}
, and outputs “
True
” if it is not zero, and “
False
” otherwise.
Clearly, this can be computed by first computing the
h
-th power of
A_{F_{\varphi}}
, and then computing its trace, which takes
\mathcal{O}\left(\mathsf{MM}\left(n,n,n\right)\right)
rounds.
However, a faster well-known way to compute this trace, without computing the
h
-th power of
A_{F_{\varphi}}
, is as follows.
Compute the following product:

\displaystyle A_{F_{\varphi}}[U_{1},V_{2}]\cdot A_{F_{\varphi}}[V_{2},V_{3}]\cdots A_{F_{\varphi}}[V_{h-1},V_{h}]\cdot A_{F_{\varphi}}[V_{h},U_{1}]\;,

where for
S,T\subseteq V
the matrix
A_{F_{\varphi}}[S,T]
denotes the rectangular matrix with
\left\lvert S\right\rvert
rows and
\left\lvert T\right\rvert
columns, every for every
s\in S
and
T\in t
we have that
(A_{F_{\varphi}}[S,T])_{s,t}=1
if
(s,t)\in E(F_{\varphi})
and
0
otherwise. This matrix is also called the biadjacency matrix.
The order in which the multiplications are computed affects the round complexity.
The algorithm computes this product by sequentially multiplying a rectangular matrix of size at most
4np\times n
and a matrix of size at most
n\times n
, to get a new matrix of size
4np\times n
. In other words, the algorithm first computes the product
A_{F_{\varphi}}[U_{1},V_{2}]\cdot A_{F_{\varphi}}[V_{2},V_{3}]
, to obtain some matrix
B_{2}
, and then computes the product
B_{2}\cdot A_{F_{\varphi}}[V_{3},V_{4}]
.
In this way, the algorithm does not multiply two square matrices of size
n
, and can benefit from the fact that it only computes the product of one smaller rectangular matrix with a square one.
This completes the description of the algorithm.

Clearly, the algorithm never outputs “
True
” if the graph
G
is
h
-cycle free. In what follows, we give a lower bound on the probability that it outputs “
True
” when the graph has
h
-cycles.

Claim 8
.

If the sampling probability of vertices from

into

satisfies

”
with probability at least
\frac{1}{4h^{h}}
.

Proof of
Claim

8
.
Let
q\triangleq\frac{1}{h^{h}}
.
Let

, which is the set of vertices that participate in an
h
-cycle in

, and also belong to the first color class.
Let

, which is the subset of vertices from

, which are also sampled into

.
We show that

1.

\left\lvert S\right\rvert\geq x\cdot q/2
with probability at least

, and

2.

\left\lvert S^{\prime}\right\rvert
has the distribution of a binomial random variable with
\left\lvert S\right\rvert
trials (note that the number of trials is also a random variable), and success probability
p
.

Using conditional probability and the fact

, we get that with probability at least
q/2
, the set
S^{\prime}
is not empty, which means that the subgraph
F_{\varphi}
contains an
h
-cycle, and therefore the algorithm outputs “
True
”.
We first prove the first item, where the randomness is over the choice of the coloring
\varphi
.
For
v\in V
, let
X_{v}
denote the indicator random variable for the event that
v\in S
. Note that
\left\lvert S\right\rvert=\sum_{v\in V}X_{v}=\sum_{v\in V_{\mathcal{C}_{h}}(G)}X_{v}
, and therefore, by the linearity of expectation, it suffices to show that for every
v\in V_{\mathcal{C}_{h}}(G)
, we have
\mathbb{E}\left[X_{v}\right]\geq q
.
To see this, fix some vertex
v\in V_{\mathcal{C}_{h}}(G)
and an
h
-cycle

that contains

. By

7
, we know that
C
is also an
h
-cycle in

with probability

, and therefore,
v\in V_{\mathcal{C}_{h}}(G_{\varphi})
with probability at least
q
, as
v
could belong to more than one
h
-cycle in
G
.
We get that
\mathbb{E}\left[\left\lvert S\right\rvert\right]\geq x\cdot q
.

We can now use a reverse Markov’s inequality (
Theorem

2.3
), to get that with probability at least
q/2
, we have that
\left\lvert S\right\rvert\geq\mathbb{E}\left[\left\lvert S\right\rvert\right]/2

\displaystyle{\mathrm{Pr}}\left[\left\lvert S\right\rvert\geq\mathbb{E}\left[\left\lvert S\right\rvert\right]/2\right]\geq\frac{\mathbb{E}\left[\left\lvert S\right\rvert\right]-\mathbb{E}\left[\left\lvert S\right\rvert\right]/2}{x-\mathbb{E}\left[\left\lvert S\right\rvert\right]/2}\geq\frac{\mathbb{E}\left[\left\lvert S\right\rvert\right]-\mathbb{E}\left[\left\lvert S\right\rvert\right]/2}{\mathbb{E}\left[\left\lvert S\right\rvert\right]/q-\mathbb{E}\left[\left\lvert S\right\rvert\right]/2}\geq q/2\;.

To conclude, we showed that if
p\geq\frac{4h^{h}}{x}=\frac{4}{q\cdot x}

{\mathrm{Pr}}\left[\left\lvert S\right\rvert\geq\mathbb{E}\left[\left\lvert S\right\rvert\right]/2\right]\geq q/2
, and since
\mathbb{E}\left[\left\lvert S\right\rvert\right]\geq xq
, we get that
\begin{aligned} {\mathrm{Pr}}\left[\left\lvert S\right\rvert\geq xq/2\right]\geq q/2\end{aligned}
,
which proves the first item.

We now move to the second part of the proof, which establishes a lower bound on
\left\lvert S^{\prime}\right\rvert
.
Let
Y
denote the random variable equal to
\left\lvert S^{\prime}\right\rvert
, which is the number of vertices in
U_{1}
which participate in
F_{\varphi}
.
For
v\in V_{1}
let

denote the indicator random variable for the event that

is in the set

.
The key point here is that the set

is an independent set over

, and therefore the random variables

are pairwise independent.
This means that for every
v\in S
, the event
\left\{Y_{v}=1\right\}
is equivalent to the event
\left\{v\in U_{1}\right\}
, which occurs with probability
p
.
Note that for

, we have that

is always
0
.
We get that

trials and success probability

\displaystyle{\mathrm{Pr}}\left[Y\neq 0\right]\geq{\mathrm{Pr}}\left[Y\neq 0\mid\left\lvert S\right\rvert\geq 1/p\right]\cdot{\mathrm{Pr}}\left[\left\lvert S\right\rvert\geq 1/p\right]\geq\left(1-(1-p)^{1/p}\right)\cdot\frac{q}{2}\geq\frac{q}{4}\;.

This means that the probability that

contains an

which completes the proof.

This whole part can be implemented in

\mathcal{O}\left(1\right)

This completes the implementation of the first part of the algorithm.

In what follows, we implement the second part of the algorithm.
Let

.
To implement the second part, the algorithm computes the product

\prod_{i=1}^{h}A_{i}
, where the matrices

are defined as follows:

\displaystyle\forall i\in[h],\quad A_{i}\triangleq\begin{cases}A_{F_{\varphi}}[U_{1},V_{2}],&\text{if }i=1\\
A_{F_{\varphi}}[V_{h},U_{1}],&\text{if }i=h\\
A_{F_{\varphi}}[V_{i},V_{i+1}],&\text{otherwise. }\end{cases}

The product
\prod_{i=1}^{h}A_{i}
is computed recursively.
We compute

.
After computing

outputs “

” if the entry

is positive and outputs “
False
” otherwise. Any vertex not in

outputs “
False
”.
This completes the implementation of the second part, and therefore, the entire description of the implementation of the algorithm.

The following claim bounds the running time of the algorithm

Claim 9

The round complexity of the algorithm
Find-Vertex-In-Cycle

(G,p)

\mathcal{O}\left(\mathsf{RM}\left(4np\right)\right)

Proof.
We claim that computing

We want to reduce the problem of computing the product of the matrices

to the problem

∎

”.

We prove that for

If

To prove the above, we use the second moment method
[

, Theorem 4.3.1]
.
Let

We need to give an upper bound on

Definition 12
.

For
\ell\in[h+1,2h]

denote the number of pairs of copies of an

Let

Note that

The following claim will help us obtain an upper bound on

Claim 10
.

For every

\mathcal{D}^{i}\leq(2h)^{h}\cdot t\cdot x^{i-h}\;.

Proof of
Claim

10
.
For
i\in[h+1,2h-1]
, every pair of

-cycles

that share

First, we specify the index of
C^{\prime}
among the
t
options.
Then, we specify the vertices in
V(C^{\prime\prime})\setminus V(C^{\prime})
, which have at most
x^{i-h}
possible options.
Then, we specify the edges of
C^{\prime\prime}
between the already specified vertices, which have at most
(2h)^{h}
options.
∎We can now apply the second moment method:

\displaystyle{\mathrm{Pr}}\left[t_{F}>0\right]\geq\frac{\mathbb{E}\left[t_{F}\right]^{2}}{\mathbb{E}\left[t_{F}^{2}\right]}\;,

where
\mathbb{E}\left[t_{F}\right]=t\cdot p^{h}
, to prove
Proposition

3
.

Proof of
Proposition

3
.
We first use
Claim

10
to bound
\mathbb{E}\left[t_{F}^{2}\right]
. We have

\displaystyle\mathbb{E}\left[t_{F}^{2}\right]

\displaystyle=\sum_{i,j\in[t]}\mathbb{E}\left[X_{i}\cdot X_{j}\right]

\displaystyle=t\cdot p^{h}+\sum_{i=h+1}^{2h-1}\mathcal{D}^{i}\cdot p^{i}+(t\cdot p^{h})^{2}

\displaystyle\leq t\cdot p^{h}+((2h)^{h}\cdot t)\sum_{i=1}^{h-1}x^{h-i}p^{2h-i}+(t\cdot p^{h})^{2}

\displaystyle=t\cdot p^{h}+p^{h}\cdot((2h)^{h}\cdot t)\sum_{i=1}^{h-1}(xp)^{i}+(t\cdot p^{h})^{2}

\displaystyle\leq tp^{h}\cdot\left(1+(2h)^{h}\cdot h(1+(xp)^{h-1})+tp^{h}\right)

\displaystyle=tp^{h}\cdot\left(1+(2h)^{h}\cdot h(1+(xp)^{h-1})+(xp)^{h}\cdot x^{-\delta}/2h\right)\;,

where the penultimate inequality follows as
\sum_{i=1}^{h-1}(xp)^{i}\leq h(1+(xp)^{h-1})
, and the last equality uses
x^{h-\delta}=2h\cdot t
, which follows from the definition of
\delta
.
We can further upper bound this expression by

\displaystyle(2h)^{h+1}\cdot tp^{h}\cdot\left((xp)^{h-1}+(xp)^{h}\cdot x^{-\delta}\right)\;.

From
Claim

10
and the second moment method, we have

\displaystyle{\mathrm{Pr}}\left[t_{F}>0\right]\geq\frac{\mathbb{E}\left[t_{F}\right]^{2}}{\mathbb{E}\left[t_{F}^{2}\right]}

\displaystyle\geq\frac{(tp^{h})^{2}}{(2h)^{h+1}\cdot tp^{h}\cdot\left((xp)^{h-1}+(xp)^{h}\cdot x^{-\delta}\right)}

\displaystyle=\frac{1}{(2h)^{h+2}}\cdot\frac{x^{h-\delta}\cdot p^{h}}{(xp)^{h-1}+(xp)^{h}\cdot x^{-\delta}}

\displaystyle=\frac{1}{(2h)^{h+2}}\cdot\frac{x^{-\delta}}{(xp)^{-1}+x^{-\delta}}\;.

The inequalities hold due to the following reasons.
The first inequality follows from the second moment method.
The second inequality follows by plugging in the previously computed values for
\mathbb{E}\left[t_{F}\right]^{2}
and
\mathbb{E}\left[t_{F}^{2}\right]
.
The penultimate equality follows by canceling terms and plugging in
x^{h-\delta}=2ht
.
The last equality is obtained by simply canceling terms.

For
p\geq 1/x
, we get that
(xp)^{-1}\leq 1
, and therefore
(xp)^{-1}+x^{-\delta}\leq 2
, which proves that

\frac{x^{-\delta}}{(xp)^{-1}+x^{-\delta}}\geq\frac{1}{2x^{-\delta}}
.
Therefore,
{\mathrm{Pr}}\left[t_{F}>0\right]\geq\frac{1}{(2h)^{h+2}}\cdot\frac{1}{2x^{\delta}}
, which completes the proof of
Proposition

3
.
∎The following lemma shows that the described experiment outputs “

A simple upper bound of

Another obstacle is a one that lies in extending our quantum algorithms for longer cycles.

d=O\left(n^{\prime 1/\sigma}\right)
.

Proof of
Proposition

1
.

We assume each element in the matrices can be represented using
\mathcal{O}\left(F\right)
bits.

The algorithm computes the matrix product
P=ST
as follows.

Step 1: Linear combination of entries.

Each node
v
with label
\ell^{\prime}(v)=xy
computes for
w\in V
the linear combinations

\displaystyle\hat{S}^{(w)}[{x}\mathord{\ast},{y}\mathord{\ast}]=

\displaystyle\sum_{(i,j)\in[d]^{2}}\alpha_{ijw}S[{i}{x}\mathord{\ast},{j}{y}\mathord{\ast}]\,,\hskip 28.45274pt\text{and}

\displaystyle\hat{T}^{(w)}[{x}\mathord{\ast},{y}\mathord{\ast}]=

\displaystyle\sum_{(i,j)\in[d]^{2}}\beta_{ijw}T[{i}{x}\mathord{\ast},{j}{y}\mathord{\ast}]\,.

The computation is performed entirely locally.

Step 2: Distributing the linear combinations.

Each node
v
with label
\ell^{\prime}(v)=xy
sends, for
w\in V
, the submatrices
\hat{S}^{(w)}[{x}\mathord{\ast},{y}\mathord{\ast}]
and
\hat{T}^{(w)}[{x}\mathord{\ast},{y}\mathord{\ast}]
to node
w
.
Each submatrix has

({\color[rgb]{1,0,0}{\frac{R}{d}\cdot\frac{1}{\sqrt{n^{\prime}}}}})^{2}={\color[rgb]{1,0,0}{\frac{R^{2}}{d^{2}\cdot n^{\prime}}}}

entries and there are
{\color[rgb]{1,0,0}{n^{\prime}}}
recipients each receiving two submatrices, for a total of
O(({\color[rgb]{1,0,0}{R/d}})^{2})
messages per node.

Dually, each node
w\in V
receives the submatrices
\hat{S}^{(w)}[{x}\mathord{\ast},{y}\mathord{\ast}]
and
\hat{T}^{(w)}[{x}\mathord{\ast},{y}\mathord{\ast}]
from node
v\in V
with label
\ell^{\prime}(v)=xy
. Node
u
now has the matrices
\hat{S}^{(w)}
and
\hat{T}^{(w)}
. The total number of received messages is
O(({\color[rgb]{1,0,0}{R/d}})^{2})
per node.

Step 3: Multiplication.

Node
w\in V
computes the product
\hat{P}^{(w)}=\hat{S}^{(w)}\hat{T}^{(w)}
. The computation is performed entirely locally.

Step 4: Distributing the products.

Each node
w
sends, for
x,y\in[({\color[rgb]{1,0,0}{n^{\prime}}})^{1/2}]
, the submatrix
\hat{P}^{(w)}[{x}\mathord{\ast},{y}\mathord{\ast}]
to node
v\in V
with label
xy
.
Each submatrix has
(({\color[rgb]{1,0,0}{R/d}})^{2}\cdot 1/{\color[rgb]{1,0,0}{n^{\prime}}})
entries and there are
{\color[rgb]{1,0,0}{n^{\prime}}}
recipients, for a total of
O(({\color[rgb]{1,0,0}{R/d}})^{2})
messages sent by each node.

Dually, each node
v\in V
with label
\ell^{\prime}(v)=xy
receives the submatrix
\hat{P}^{(w)}[{x}\mathord{\ast},{y}\mathord{\ast}]
from each node
w\in V
.
The total number of received messages is
O(({\color[rgb]{1,0,0}{R/d}})^{2})
per node.

Step 5: Linear combination of products.

Each node
v\in V
with label
\ell^{\prime}(v)=xy
computes for
i,j\in[d]
the linear combination

P[{i}{x}\mathord{\ast},{j}{y}\mathord{\ast}]=\sum_{w\in V}\lambda_{ijw}\hat{P}^{(w)}[{x}\mathord{\ast},{y}\mathord{\ast}]\,.

Node
v\in V
now has the submatrix
P[{\mathord{\ast}}{x}\mathord{\ast},{\mathord{\ast}}{y}\mathord{\ast}]
. The computation is performed entirely locally.

Analysis.

The maximal number of entries sent or received by a node in the above steps is
O(({\color[rgb]{1,0,0}{R/d}})^{2})
, where each entry can be represented using
\mathcal{O}\left(F\right)
bits. First, let’s assume each vertex can send in each round, one message of
B
bits to every other vertex in
V
.
We get that sending
O(({\color[rgb]{1,0,0}{R/d}})^{2})
messages takes

\displaystyle(R/d)^{2}/n^{\prime}\cdot\frac{F}{B}=R^{2}/(n^{\prime})^{1+2/\sigma}\cdot\frac{F}{B}=(R/n^{\prime})^{2}\cdot(n^{\prime})^{1-2/\sigma}\cdot\frac{F}{B}=\mathcal{O}\left((n^{\prime})^{\rho}\cdot(R/n^{\prime})^{2}\cdot\frac{F}{B}\right)

rounds.
We can further see, that the communication pattern is fixed. In other words, the content of the messages does not effect the communication pattern. Therefore, increasing the bandwidth by a factor of
C
will decrease the number of rounds the algorithm takes by a factor of
C
.
We therefore get the desired running time. This completes the proof of
Proposition

1
.
