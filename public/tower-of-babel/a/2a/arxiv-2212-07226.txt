An Efficient Incremental Simple Temporal Network Data Structure for Temporal Planning
Andrea Micheli

Abstract
One popular technique to solve temporal planning problems consists in decoupling the causal decisions, demanding them to heuristic search, from temporal decisions, demanding them to a simple temporal network (STN) solver. In this architecture, one needs to check the consistency of a series of STNs that are related one another, therefore having methods to incrementally re-use previous computations and that avoid expensive memory duplication is of paramount importance. In this paper, we describe in detail how STNs are used in temporal planning, we identify a clear interface to support this use-case and we present an efficient data-structure implementing this interface that is both time- and memory-efficient. We show that our data structure, called δ − STN \operatorname{\delta-STN} , is superior to other state-of-the-art approaches on temporal planning sequences of problems.



1
Introduction

Automated temporal planning concerns the synthesis of strategies to
reach a desired goal in a system subject to temporal constraints that
is specified by providing an initial condition together with
the possible actions that can drive it.

Over the years, several techniques to solve the temporal planning
problem have been presented; e.g. encoding into Satisfiability Modulo
Theory (SMT)
(
Shin and Davis 2005
)
, plan-space planning
(
Frank and Jónsson 2003
)
and
decision-epoch planning
(
Do and Kambhampati 2003
)
. One technique in particular
emerged to deal with temporally-expressive

(
Cushing et al. 2007
)
, action-based temporal planning:
Forward-Chaining Temporal Planning (
\operatorname{FCTP}
)
(
Coles et al. 2009a
)
, embodied
in planners such as CRIKEY
(
Coles et al. 2008
;
Coles et al. 2009b
)
, POPF

(
Coles et al. 2010
)
, OPTIC
(
Benton, Coles, and Coles 2012
)
, VHPOP
(
Younes and Simmons 2003
)
and TAMER

(
Valentini, Micheli, and Cimatti 2020
)
. The basic idea behind
\operatorname{FCTP}
is to use forward heuristic
search to incrementally construct a causally-sound interleaving of
events and to check the temporal feasibility of any plan prefix using
scheduling techniques, where the timing of each event is encoded as a
symbolic variable.

When the planning problem at hand does not contain numeric variables
or continuous change (i.e. we are dealing with pure temporal
planning), the most efficient way to implement an
\operatorname{FCTP}
schema is to
use Simple Temporal Networks (STNs)
(
Dechter, Meiri, and Pearl 1991
)
to represent and check
the consistency of the symbolic scheduling problems. STNs have been
widely studied and several algorithms to incrementally add and remove
constraints have been presented

(
Cesta and Oddi 1996
;
Ramalingam and Reps 1996
;
Gerevini, Perini, and Ricci 1996
;
Coles et al. 2009a
)
; moreover, STNs can be
easily encoded in Linear Programming (LP) or in SMT. However, all
these algorithms focus on how to efficiently solve, propagate and
maintain
a single
STN; instead, in an
\operatorname{FCTP}
schema, we have one
STN associated to each search state, with minimal differences between
the STN of a state and the one of its predecessor in the search
(usually, each search step either introduces a new time-point in the
STN or adds precedence constraints).

In this paper, we present a novel data structure to efficiently
represent, maintain and solve STNs in an
\operatorname{FCTP}
schema. Our data
structure, called
\operatorname{\delta-STN}
, is persistent
(
Okasaki 1999
)
and explicitly avoids the support for
retracting constraints (as this is never used in the
\operatorname{FCTP}
schema) and
efficiently saves memory, by maintaining references to STNs of
parent nodes in the search tree. Effectively, we identify the set of
operations needed for an STN to be employed in an
\operatorname{FCTP}
schema, we
show how to implement these in
\operatorname{\delta-STN}
and we show that
\operatorname{\delta-STN}
is
consistently superior in terms of both solving time and memory usage
to the other approaches and algorithms in the literature.

2
STNs and their use in FCTP

A Simple Temporal Network (STN)
(
Dechter, Meiri, and Pearl 1991
)
is a data structure that
maintains constraints over a set of temporal variables called
time-points.

Definition 2.1
.

An STN is a pair
\langle T,C\rangle
where
T
is a set of time points
and
C
is a set of constraints of the form
x-y\leq k
with
x,y\in T
and
k\in\mathbb{Q}
.

An STN
\langle T,C\rangle
is said to be consistent if there exists an
assignment, called a consistent model,
\mu:T\rightarrow\mathbb{Q}
such that for each constraint
(x-y\leq k)\in C
, the
inequality
\mu(x)-\mu(y)\leq k
is satisfied. Without loss of
generality, we assume that each
STN
contains a reference zero time
point
z
and a constraint
z-x\leq 0
for each time point
x
.

STNs are used in different areas of Artificial Intelligence to
maintain temporal knowledge and to efficiently check temporal
feasibility. In fact, STN consistency can be checked in polynomial
time by using a shortest path algorithm able to detect negative
cycles, such as the Bellman-Ford algorithm
(
Cormen et al. 2001
)
, over the
“Distance Graph” (DG). The DG of a given STN is the graph having one
node for each time point, and an edge
\langle x,y\rangle
with weight
k

for each constraint
y-x\leq k
in the STN. If the DG contains a
negative cycle, then the network is inconsistent; otherwise, for each
node
x
we can set
\mu(x)
to the distance from
x
to
z
to obtain
the earliest possible execution time for each time point (the
minimal-makespan consistent model)
(
Dechter, Meiri, and Pearl 1991
)
.

We call “Inverted Distance Graph” (IDG) the graph where each edge

\langle x,y\rangle
with weight
k
of the DG is transformed into an edge

\langle y,x\rangle
with weight
k
. It is easy to see that the IDG has a
negative cycle if and only if the DG has one (the weights do not
change and we can simply walk a negative cycle in the DG in reversed
order and vice-versa). Moreover, the shortest path distance from any
node
x
to any node
y
in the DG corresponds to the minimum distance
from node
y
to node
x
in the IDG. For convenience, in
\operatorname{\delta-STN}
algorithms we will use the IDG and we will maintain and update the
distances from
z
to each time point.

2

constraints for the new state. Different algorithms add different

(

prefix, while
Tamer

(
Valentini, Micheli, and Cimatti 2020
)
constructs a total
ordering. Finally, we check the resulting STN for consistency and we
only enqueue the children whose STN is consistent
(
12

\operatorname{\delta-STN}
Algorithms

We now describe our
\operatorname{\delta-STN}
data structure, implementing the defined
interface.
In the following, we indicate with
\mathbb{T}
the set of all possible
time points. There are four key ideas that are at the base of the time
and memory efficiency of
\operatorname{\delta-STN}
. First, we leverage the intended use of the data structure in the
\operatorname{FCTP}
search schema by avoiding the duplicated representation of the constraints between a search node and its ancestors. In fact, we represent the set of temporal constraints in a
\operatorname{\delta-STN}
as an associative container (implemented with a sorted vector to save space and retain logarithmic access time), which maps a time point to a persistent list of pairs of a time point and a bound.
The second key idea stems from the observation that for the
incremental Bellman-Ford checking algorithm to work
(
Wang et al. 2005
)
, we
only need to retrieve the constraints that are of the form
x-y\leq k
given a specific time point
x
. We call such constraints
“neighbors” of
x
. Our representation makes it easy to iterate through all the neighbors of
x
as we can simply access the associative container in position
x
.
Third, we do not explicitly represent the reference time point

z
: we implicitly impose the constraint
z-x\leq 0
for each time
point upon addition, setting the initial distance to
0
. Finally, we
copy the distances map in the
CopyTN
method, so that the
computation done in the parent STNs can be re-used in the children and
only additional constraints need to be incrementally propagated.

The implementation of the interface defined in the previous section is
reported in
Algorithm

3
. The
MakeSTN
method, simply
constructs an empty
\operatorname{\delta-STN}
with no ancestor (is_sat is set to true
because the STN is vacuously consistent). The
CopySTN

method, also creates a new
\operatorname{\delta-STN}
, but this time the constraints of the parent
\operatorname{\delta-STN}
are inherited by shallow copying the
p.constraints
map (meaning that the map is copied, but the pointers to the
\operatorname{\delta-Neighbors}
structures in the values are not duplicated in memory). The distances and is_sat values are simply copied from the parent. In this way, subsequent calls updating the consistency or the distances
will not affect the parent, because the
\operatorname{\delta-Neighbors}
structures are persistent, but parent constraints are still reachable and new constraints can be added on top of the parent constraints. The core of the algorithm is
encapsulated in the
STNAdd
method. We first extend the
distances and constraints maps, if needed, by setting the new time points to distance 0
(because an unconstrained time-point can always be set to 0 in a
consistent model) and the constraints to empty lists if not already present. At this point, we check (
11
) if
the constraint
x-y\leq b
is already subsumed by other constraints
in this network. This check is performed by the
IsSubsumed

method that checks if this
\operatorname{\delta-STN}
already has a
constraint
x-y\leq b^{\prime}
with
b^{\prime}\leq b
.
One drawback of a list representation instead of an associative container is that in order to recognize subsumption we require an iteration through the list that is in general
O(E)
where
E
is the number of constraints in the
\operatorname{\delta-STN}
. However, we limit this problem by maintaining a partial ordering property on the list of neighbors of each time point
x

\langle y,k\rangle
and
\langle y,k^{\prime}\rangle
in
stn.constraints[x]
with
k^{\prime}<k
, then
\langle y,k^{\prime}\rangle
appears before
\langle y,k\rangle
in the list. This property is maintained by the fact that we never add subsumed constraints (
11
) and is exploited by the
IsSubsumed
function to early terminate as soon as the target time point
y
is encountered in the list (
23

If the constraint being added is found to be subsumed, then it means that it is
weaker than an already present constraint and can be
discarded. Instead, if the new constraint is not subsumed, we add it
to the set of constraints of this
\operatorname{\delta-STN}
(
12
) and
we launch an incremental Bellman-Ford check from this constraint by
calling the
IncCheck
function (
14

IncCheck

Bellman-Ford algorithm from
(
Wang et al. 2005

implementation exploits the previously computed distances and
guarantees to store the minimal valid consistent model in the
distances assignment. The retrieval of the neighbors of a
time point
x
(
) is implemented by simply iterating over the elements of
self.constraints[x]

\operatorname{\delta-STN}

Experimental Evaluation

In this section, we experimentally compare the merits of
\operatorname{\delta-STN}
against several alternative techniques: linear programming using the
CLP
(
johnjforrest et al. 2019
)
library used by
Optic
(indicated as
\operatorname{LP}
), an
implementation of the standard Bellman-Ford algorithm with an optimized constraint representation using a Red-Black tree (indicated as
\operatorname{STN}
), and three
implementations of the interface using Satisfiability Modulo Theory:
using no incrementality and re-constructing the problem each time
(
\operatorname{SMT}
); cloning the problem (
\operatorname{SMT-Incremental}
) and using the “solving under
assumptions” interface (
\operatorname{SMT-SUA}
).

We built 638 benchmark instances by instrumenting the
Optic
and
Tamer
planners to output their STN/LP operations in textual
format. Each instance is a sequence of operations of the identified
interface extracted from a planning run. We let both the planners run
for 600 seconds on temporal domains from the IPC (
Optic
) and from the
domains used in
(
Valentini, Micheli, and Cimatti 2020
)
(
Tamer
).

All the experiments have been conducted on a Xeon E5-2670 2.30GHz
machine with a runtime limit of 600 seconds and a memory limit of
10GB.
The source code implementation of
\operatorname{\delta-STN}
and of all the other
approaches is available for inspection in the additional material with
some example benchmarks and a Linux-64 binary to replicate the
results. The full set of benchmarks is available online
at
https://es-static.fbk.eu/people/amicheli/resources/deltastn
.

The results of the experimentation is reported in

Figure

1
. The cactus plots in the top part of the figure
show the time and memory performance of the approaches in terms of the
number of solved instances. It is evident that
\operatorname{\delta-STN}
dominates
both the plots and it is the only implementation that is able to solve
all the 638 instances. The
\operatorname{LP}
implementation is competitive but
falls quite far beyond
\operatorname{\delta-STN}
, solving 595 instances in total. The

\operatorname{SMT}

problems. This is also highlighted from the cactus plots in the bottom

against
\operatorname{\delta-STN}
. An interesting observation comes from the
comparison with
\operatorname{STN}
: some instances are solved essentially in the same amount of time by duplicating the constraints in
each search state. This is
due to the fact that
Optic
does not internally use incrementality in
the way it interacts with CLP, hence some of the advantages of
\operatorname{\delta-STN}
are not fully exploited.

5
Conclusions

We presented an optimized data structure to
solve Simple Temporal Networks in the
\operatorname{FCTP}
use-case.
\operatorname{\delta-STN}
exploits the
\operatorname{FCTP}
characteristics to be more time- and
memory-efficient than other implementations.
In the future, we plan to study the use of
\operatorname{\delta-STN}
in other contexts
such as Partial Order Causal Planning
(
Ghallab, Nau, and Traverso 2004
)
.
