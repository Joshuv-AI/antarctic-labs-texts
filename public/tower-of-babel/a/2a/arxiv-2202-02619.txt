A bird’s eye view on Multi-Objective Optimization techniques in Relational Databases
Giuseppe Tortorelli

Abstract
Multi-objective optimization is the problem of optimizing simultaneously multiple objective functions and several techniques exist to deal with this problem. This paper aims to present the main methods that can be used to solve this issue in the context of relational databases. In particular, this work examines Top-k query to get the k best result from a dataset and Skyline query that provides a more general overview of the best results. We also discuss Flexible-skyline , a new method designed to improve upon the previous techniques, mitigating their shortcomings. For each method, we describe the main characteristics and present an overview of the algorithms implementing such thecniques, while comparing advantages and disadvantages.

In this way, we can select the

2.1
Algorithms

To talk about
Top-k
algorithms for aggregations, we need to make
a distinction between how data are accessed.
We talk about
sorted access
when we access objects sequentially in a list that has been previously ordered according to one or more attributes,
random access
if objects are accessed directly in one step. All of the following algorithms work for
monotone
scoring functions.
This is a reasonable property for a scoring function since
if the partial score
\sigma[a^{t}_{i}]
of each attribute
a
of a tuple
t
is greater or equal to that of the attribute of a tuple
s

\sigma[a^{s}_{i}]
, one would expect the overall score of
t

\sigma[t]

to be greater or equal to the overall score of s
\sigma[s]
.

\sigma[a^{t}_{i}]\geq\sigma[a^{s}_{i}]\ \forall i\in I\Rightarrow\sigma[t]\geq\sigma[s]

where
I
is the set of attributes of the tuples.

Fagin’s algorithm
(
FA
)
[
6
]
: For each list of tuples make one sorted access at a time until
k
objects in common are found.
For each selected object, using random access, apply the scoring function to compute its overall score, then select the best
k
objects. The complexity of the algorithm is
O(N^{\frac{(m-1)}{m}}k^{\frac{1}{m}})
, where
N
is the number of the tuples,
m

is the number of the considered attributes and
k
is the number of the best objects that we want to select. An aspect that has to be kept into consideration, is that the access pattern of
FA
is independent of the specified scoring function. Hence, the efficiency of the algorithm remains the same for all the possible scoring functions.
Furthermore, since
FA
must keep every object of each sorted list in memory, its buffer is proportional to the size of the database.
Threshold algorithm
(
TA
)
[
7
]
: The
TA
algorithm incrementally computes a threshold under which an object is excluded by the result set.
Unlike
FA
, it performs parallel sorted access for each list, and for each extracted tuple, it computes its overall score through random access.
The threshold is updated at each iteration by applying the scoring function to the last objects seen in sorted access.

TA
terminates when the score of the
k
-th object is above the threshold. The number of sorted access performed by
Threshold algorithm
is at most equal to that of
FA
, but since it is instance optimal and thanks to the fact that it is strongly dependent on the shape of the scoring function, its performances are on average better than
FA
.
In fact,
TA
stops as soon as it has found the
k
-best results. Another advantage is that the algorithm uses a bounded buffer of size
k
, which is independent of the size of the database.
Therefore, the amount of memory used by
TA
is also optimal.

No Random Access algorithm
(
NRA
)
[
7
]
: For each list of objects, makes one sorted access at a time and for each extracted tuple, keeps a sorted list with a threshold, a lower and an upper bound of the score.
The algorithm stops when the
k
-th object has a lower bound greater than the higher upper bound over all records. Among all algorithms that don’t perform random access,
NRA
is instance optimal.
Nonetheless, it needs an unlimited buffer to record the extracted objects with associated values.
Another important aspect of the algorithm is that, for performance reasons, it provides only the
k
best objects but unsorted, as information about the overall score is not presented to the user.
Because random access is not available, looking for the exact order would require running the algorithm
k
times.
Assume that we want to find the best 3 objects, to do that we will execute
NRA
3 times, starting from
k=1
and increasing every time the value of
k
by 1.
By doing this, we can keep a buffer of size
k
where at each iteration we enqueue the object of the result set not yet present in the buffer.

Skyline

Skyline
offers a different approach to extract results from a dataset.
Unlike
Top-k
, this method provides to the user an overview of all optimal objects without specifying a scoring function.
This framework is an extension of the
maximum vector problem

[
11
,
9
]
to the relational model, obtained by substituting vectors and points with a set of tuples. The key concept behind
Skyline
is the notion of
dominance
:
Definition
Given two tuples
t
and
s
and a set of attributes
A_{i}
common to
s
and
t
, of cardinality
m
,

t

dominates

s
and indicate
t\prec s
if:

s[A_{i}]\leq t[A_{i}]\quad\forall i\in\{1,..,m\}

\exists\ j\ |\ s[A_{j}]<t[A_{j}]\quad j\in\{1,..,m\}

To explain it in another way, a tuple
t

dominates
a tuple
s
if all attributes of
t
are at least equal to that of
s
and if there exists at least one attribute
t

that is better than
s
.
Skyline
is defined as the set of tuples of a relation not dominated by any other tuples
[
1
]
. As we said before, to obtain the
Skyline
, we did not have to select any metric, because the result comes as a property of the dataset and for this reason, it presents to the users a broad view of the best objects. On the other hand, the absence of a tool that expresses which attribute should be more important, it’s usually not the desired behavior, mainly with a large and fuzzy dataset.
The size of the
skyline
could be much bigger than the size of the result set obtained with a reasonable value of
k
using the
Top-k
method.

Each object in the

is not dominated by any other point; for example, JS dominates FS since both

are greater than FS’s ones (3 vs 2 and 9.8 vs 7.8).
Furthermore, JS is not dominated by PT, nor is PT dominated by JS since from the
experience
point of view, PT wins on JS but JS has a higher score with respect to PT. Thanks to the fact
that PT is not dominated by any other tuple, also PT is in the
skyline
.

3.1
Algorithms

Block Nested Loop
(
BNL
)
[
1
]
: the algorithm keeps track of all non-dominated points by inserting them in a buffer.
It scans all the dataset and compares each point
p
with all points in the buffer: if
p
is not dominated by any point, all points dominated by
p
are removed from the buffer, and
p
is added.
BNL
is as simple as inefficient since its effectiveness depends on the size of the buffer.
Considering the case, in which its size is equal to the size of the dataset
n
, the complexity of the algorithm is
O(n^{2})
.
Soft Filter Skyline
(
SFS
)
[
2
]
: this algorithm is similar to the previous one, but
SFS
starts by sorting the
dataset using a fixed monotone function (usually an entropy function). Due to the monotonicity of the sorting function, we know that given two sorted tuples
t
and
s
, if
t
comes before

s
,
t
is not
dominated
by
s
. As a consequence, if a tuple is in the buffer, it is a part of the skyline and it can be output without waiting for the end of the algorithm. Furthermore, the number of iterations is optimal and the complexity is
o(ln+n\log{n})
where
l
is the size of the skyline and

n
is the size of the dataset (
O(n\log{n})
needed for sorting). In the worst case, the size of the
Skyline
equals the size of the dataset (
l=n
); the complexity of the
SFS
turns back to
O(n^{2})
.

4
Flexible-Skyline

As already described in the upper sections, the two traditional approaches have different pros and cons. Therefore, there is the need for a new method that can combine the best from
Skyline
and
Top-k
and resolve the issues of both.
Flexible-skyline
(
F-skyline
) inherits from
Top-k
the use of a scoring function but with an important difference: preferences are expressed in terms of constraints on the weights instead of letting the user guess the appropriate values. This solves one of the main weaknesses of
Top-k
. The major idea behind
F-skyline
, is that this framework outputs a subset of the
skyline
of the dataset since it selects only the optimal objects that fulfill the constraints imposed by the scoring function. This is done using the concept of
\mathcal{F}
-dominance
, which applies the
dominance
to the
scoring function
.
[
4
,
3
]

Definition
Given two distinct tuples
t
and
s
, and a family of monotone functions
\mathcal{F}
, we said that

t

\mathcal{F}
-dominates

s
, and indicate
t\prec_{\mathcal{F}}s
, if

f(s)\leq f(t)\quad\forall f\in\mathcal{F}

In other words,
t

\mathcal{F}
-dominates

s
if there does not exist any scoring function in
\mathcal{F}
for which the value of
s
is better than the value of
t
. In particular,
Flexible-skyline
offers two operators; given a set of tuples
r
,
\textsc{nd}(r;\mathcal{F})
is the subset of
r
of tuples that are
non
-
\mathcal{F}
-
dominated
by any other tuples in
r
, and
\textsc{po}(r;\mathcal{F})
is the subset of
r
of tuples that are potentially optimal according to a specific scoring function
f\in\mathcal{F}
.
Considering that
nd
and
po
are both monotone operators with respect to the set of scoring functions, an important property is
[
4
,
3
]
:

\textsc{po}(r,\mathcal{F})\subseteq\textsc{nd}(r;\mathcal{F})\subseteq\textsc{sky}(r)

where
sky
is the
skyline
of the dataset. This property highlights that
po
can be obtained starting from
nd
by looking for tuples that are not
\mathcal{F}
-dominated
by any convex combination of the tuples in
nd
.
Therefore,
po
outputs more accurate results than
nd
and indicates that stricter constraints mean a smaller result set.
This is a significant result since it allows users to set the right levels of constraints according to their needs. Another relevant concept is the notion of
\mathcal{F}
-dominance

region
, which is useful for computing both
po
and
nd
:
Definition
The
\mathcal{F}
-dominance

region
of a tuple
t
is the set of points that are
\mathcal{F}
-dominated
by
t

4.1
Algorithms

For the implementation of
F-skyline
, several algorithms can be used to compute
po
and
nd

[
4
]
, here we report the main characteristics and the most promising ones. Concerning
nd
, the classes of the algorithm are divided by:

•

Number of Phases
:
nd
can be retrieved by computing
Skyline
(2 phases) or directly from the starting dataset (1 phase).

•

Sorting
: the dataset can be sorted in advance according to a specific function (S) or not (U). Due to monotony, the advantage of sorting the dataset is that an upper tuple is never dominated by a lower one.

•

\mathcal{F}
-dominance
:
\mathcal{F}
-dominance
can be tested either by solving an associated
LP problem
(LP) or by checking if the tuple is in
\mathcal{F}
-dominance

region

[
4
]
using vertex enumeration (VE) of the polytope containing this region.

Concerning
po
, the classes of the algorithm are divided by:

•

Phases
:
po
can be retrieved by computing first
nd
(2 phases) or directly from the dataset by excluding non-
po
tuples (1 phase).

•

po
test
: using primal
po
test
(P) or the dual
po

test
(D). The main difference is that the primal test exploits the dependence of
po
to
nd
, while the dual test uses the convex combination of a set of tuples. (See
[
4
]
for formal definitions)

•

Incrementality
: each tuple can be tested with the set of all other tuples (U) or
LP problem
of increasing sizes can be solved to test the tuple with a subset of the others (I). Using this last approach we can discard a tuple as soon as it is not optimal for a subset, due to the monotony of the functions
f\in\mathcal{F}
.

Several experimental analyses
[
4
]
have verified that the best algorithm between the combination of the previous classes, is
SVE1F

for computing
nd
and
PODI2
for computing
po
.
SVE1F
is a 1-phase algorithm that sorts the dataset before exploiting the vertex enumeration of the polytope representing the
\mathcal{F}
-dominance

region
.
Its complexity is
O(ve(c)+N\textperiodcentered(\log{N}+|\textsc{nd}|\textperiodcentered q))
where
O(ve(c))
is the cost for enumerating vertex (
c
is the number of constraints),
|\textsc{nd}|
is the size of the set of the non-dominated tuples,
q
is the number of vertices of the polytope and
N
is the number of tuples in the dataset.
PODI2
is a 2-phase algorithm that computes the
po
set using the dual
po
incrementally solving
LP problems
.
Its complexity is
C_{\textsc{nd}}+O(|\textsc{nd}|\textperiodcentered\log{|\textsc{nd}|}\ \textperiodcentered lp(q,|\textsc{nd}|))
.
C_{\textsc{nd}}
is the complexity of the algorithm used for computing
nd
set, that is, the starting point of the algorithm.

O(lp(q,|\textsc{nd}|))
is the complexity of computing the
LP problem
with
q
inequalities and
|{\textsc{nd}}|
variables.

4.2
Related work

Flexible-skyline
was described for the first time under the name of
Restricted-skyline
(
R-skyline
)
[
3
]
, where only scoring functions in the form of
L_{p}
norms were considered.
F-skyline
instead, extends the previous work letting the scoring function be subject to an arbitrary monotone transformation, the so called
monotonically transformed, linear-in-the-weight
(MLW) functions.
Uncertain top-k query
(
UTK
)
[
14
]
is a method that offers a solution to the problem of weight selection in
Top-k
.
It aims is to report all possible
Top-k
results to offer to the user similar options, starting from initial uncertain selected preferences.
To do that,
UTK
as
F-skyline
represents the user preferences in a convex polytope instead of a vector and inherits from
Flexible-skyline
the concept of
\mathcal{F}
-dominance
.
Furthermore, it extends
nd
and
po
operators applying them to
k-skyband

[
15
]
(generalization of the
Skyline
for
k\geq 1
).
ORD
and
ORU
operators
[
13
]
have the same goals as the previous ones but in addition, they can control the output size. This method starts from the preferences input vector of
Top-k
, and expands it equally in all directions of the preferences domain.
As a consequence, additional records, that satisfy preferences similar to selected ones, are included in the result set. The
OSS
(
output-size specified
) property is accomplished by a stopping radius directly correlated to the desired output size.

5
Conclusion

Top-k
is a very efficient way to extract data of interest from a dataset.
Unfortunately, the strength of this method is also its weakness; in fact, choosing the right weight values is a hard task,
that can lead to rerunning the queries several times by changing them.
Furthermore, this method may not select some results near to the optimal ones that may be of interest to the user
[
14
]
. On the other hand, using
Skyline
the user may have a general overview of the best results in the dataset, without selecting preferences on attributes.
This is paid in terms of the size of the result set: especially for a large anti-correlated dataset, the size of the
skyline
can be too large that this method is unusable. Furthermore, the simplicity of the algorithms for computing
Skyline
has the cost of a higher complexity:
O(n^{2})
in the worst case.
Flexible-skyline
is a new approach for solving
multi-objective
optimization problems that combine the properties of the previous methods.
It solves the problem of
Top-k
by reducing user efforts in choosing the appropriate scoring function, meanwhile, it outputs a result set which size is a trade-off between the two previous approaches.
Moreover, it also offers two levels of accuracy thanks to
nd
and
po
operators.
Despite such advantages, also
F-skyline
presents negative aspects. In particular, with this method, the user does not have control over the size of the output that could be larger or smaller than the user might expect
[
13
]
.
Another limit of this operator is that the higher is the number of constraints, the more unstable is the
LP solver
. In fact, for a large number of constraints, the result could be unreliable
[
4
]
. Concerning complexity,
Top-k
provides the most efficient algorithms among the others, even if
F-skyline
is comparable with
Skyline
.
Experimental results
[
4
]
show that
Flexible-skyline
is more effective than
Skyline
, and for these reasons, it is a convenient alternative to those applications that require the characteristics of this approach.
