Using Color Refinement to Boost Enumeration and Counting for Acyclic CQs of Binary Schemas
Cristian Riveros, Benjamin Scheidt, Nicole Schweikardt

Abstract
We present an index structure, called the color-index, to boost the evaluation of acyclic conjunctive queries (ACQs) over binary schemas. The color-index is based on the color refinement algorithm, a widely used subroutine for graph isomorphism testing algorithms. Given a database D D , we use a suitable version of the color refinement algorithm to produce a stable coloring of D D , an assignment from the active domain of D D to a set of colors C D C_{D} . The main ingredient of the color-index is a particular database D col {D_{\operatorname{col}}} whose active domain is C D C_{D} and whose size is at most | D | |D| . Using the color-index, we can evaluate any free-connex ACQ Q Q over D D with preprocessing time O ⁡ ( | Q | ⋅ | D col | ) O(|Q|\cdot|{D_{\operatorname{col}}}|) and constant delay enumeration. Furthermore, we can also count the number of results of Q Q over D D in time O ⁡ ( | Q | ⋅ | D col | ) O(|Q|\cdot|{D_{\operatorname{col}}}|) . Given that | D col | |{D_{\operatorname{col}}}| could be much smaller than | D | |D| (even constant-size for some families of databases), the color-index is the first index structure for evaluating free-connex ACQs that allows efficient enumeration and counting with performance that may be strictly smaller than the database size.

1
Introduction

An important part of database systems are
index structures
that provide
efficient access to the stored data and help to accelerate query evaluation.
Such index structures typically rely on hash tables or balanced trees such as B-trees or B
+
-trees,
which boost the performance of value queries
[
31
]
.
Another recent example is indices for worst-case optimal join algorithms
[
27
]
.
For example,
Leapfrog Triejoin

[
34
]
,
a simple worst-case optimal algorithm for evaluating multiway-joins on relational databases,
is based on so-called trie iterators for boosting the access under different join orders.
These trie indices have recently improved in the use of time and space
[
3
]
.
Typically, index structures are not constructed for supporting the evaluation of a single query,
but for supporting the evaluation of an entire class of queries.
This paper presents a novel kind of index structure called the
color-index

to boost the evaluation of free-connex acyclic conjunctive queries (fc-ACQs).

Acyclic conjunctive queries (ACQs) were introduced
in
[
7
,
10
]

and have since then received a lot of attention.
From Yannakakis’ seminal paper
[
35
]
it is known that
the result of every fixed ACQ
Q
over a database
D
can be computed in time
linear in the product of the database size
|D|
and the output size
|{\left\llbracket Q\right\rrbracket}(D)|
.
For the particular subclass fc-ACQ of
free-connex
ACQs,
it is even known to be linear in the sum
|D|+|{\left\llbracket Q\right\rrbracket}(D)|
:
the notion of
free-connex
ACQs was introduced in the seminal paper by
Bagan, Durand, and Grandjean
[
6
]
, who improved Yannakakis’ result as follows.
For any database
D
, during a preprocessing phase that takes time linear in
|D|
,
a data structure can be computed that allows to enumerate, without repetition,
all the tuples of the query result
{\left\llbracket Q\right\rrbracket}(D)
,
with only a
constant
delay between outputting any two tuples.
Note that the data structure computed in the preprocessing phase is designed for the particular
query
Q
, and the above running time statement suppresses factors that depend on
Q
.
For evaluating a new query
Q^{\prime}
, one has to start an entirely new preprocessing phase that,
again, takes time linear in
|D|
.

The main contribution of this paper is a novel index structure called the
color-index
.
Upon input of a database
D
of a binary schema
(i.e., the schema consists of relation symbols of arity at most 2),
the color-index can be built in time
O(|D|{\cdot}\log|D|)
in the worst-case,
and for many
D
the time is only
O(|D|)
.
The main ingredient of the color-index is the
color database

{D_{\operatorname{col}}}
.
By using the color-index, upon input of an arbitrary fc-ACQ
Q
we can enumerate
the tuples of the query result
{\left\llbracket Q\right\rrbracket}(D)
with constant delay after a preprocessing phase
that takes time linear in
|{D_{\operatorname{col}}}|
.
Compared to the above-mentioned result by Bagan, Durand, and Grandjean
[
6
]
,
this accelerates the preprocessing time from
O(|D|)
to
O(|{D_{\operatorname{col}}}|)
.
The size of
{D_{\operatorname{col}}}
is
O(|D|)
in the worst-case, but depending on the particular structure of
D
,
the database
{D_{\operatorname{col}}}
may be substantially smaller than
D
; we show that even
O(1)
is possible.
Apart from enumerating the query result with constant delay, the color-index
can also be used to count the number of tuples in the query result
{\left\llbracket Q\right\rrbracket}(D)
;
this takes time
O(|{D_{\operatorname{col}}}|)
(in data complexity).
To the best of our knowledge, the color-index is the first index structure for fc-ACQs
that allows efficient enumeration and counting with performance guarantees
that may be sublinear in the database size.

The starting point for constructing the color-index is to represent
D
by
a suitable vertex-labeled and edge-labeled directed graph,
to which we then apply a variant of the well-known
color refinement
algorithm.
Color refinement is a simple and widely used subroutine for graph isomorphism testing algorithms;
see e.g.
[
8
,
19
]
for an overview
and
[
15
,
4
,
25
,
26
]
for details on its expressibility.
Its result is a particular coloring of the elements in the active domain of
D
.
The construction of the color-index and, in particular,
the color database
{D_{\operatorname{col}}}
is based on this coloring.
Our result relies on a close connection between the colors computed by the
color refinement algorithm and the homomorphisms from acyclic conjunctive queries to the database.
This connection between colors and homomorphisms from tree-like structures has been used before
in different contexts
[
16
,
20
,
18
,
11
,
24
]
.
Notions of index structures that are based on concepts of bisimulations
(which produce results similar to color refinement)
and geared towards conjunctive query evaluation have been proposed and empirically evaluated,
e.g., in
[
29
,
30
,
33
]
.
But to the best of our knowledge, the present paper is the first to use color refinement
to produce an index structure that guarantees efficient constant-delay enumeration and counting.

The remainder of the paper is organized as follows.
Section
2
fixes the basic notation concerning databases and queries.
Section
3
formalizes the general setting of
indexing for query evaluation
.
Section
4
provides the background on fc-ACQs that is necessary
for achieving our main result.
Section
5
gives a detailed description of the color-index,
while Section
6
shows how it can be utilized for
enumerating and counting the results of fc-ACQs.
Section
7
provides a precise statement of our main result.
We conclude in Section
8
with a summary and an outlook on future work.
Further details are provided an appendix.

2
Preliminaries

We write
\mathbb{N}
for the set of non-negative integers, and we let

\mathbb{N}_{\scriptscriptstyle\geqslant 1}:=\mathbb{N}\setminus\{0\}
and
[n]:=\{1,\ldots,n\}
for all
n\in\mathbb{N}_{\scriptscriptstyle\geqslant 1}
.
Whenever
G
denotes a graph (directed or undirected),
we write
V(G)
and
E(G)
for the set of nodes and the set of edges of
G
.
Given a set
U\subseteq V(G)
, the subgraph of
G

induced
by
U

(for short:
G[U]
) is the graph
G^{\prime}
such that
V(G^{\prime})=U
and
E(G^{\prime})
is
the set of all
e\in E(G)
such that both endpoints of
e
belong to
U
.
A
connected component
of an undirected graph is a maximal connected subgraph of
G
.
A
forest
is an undirected acyclic graph; and a
tree
is a connected forest.

We usually write
\bar{a}=(a_{1},\ldots,a_{k})
to denote a
k
-tuple
(for some arity
k\in\mathbb{N}
) and write
a_{i}
to denote its
i
-th component.
Note that there is only one tuple of arity 0, namely,
the
empty tuple
denoted as
()
.
For a
k
-tuple
\bar{a}
and an
\ell
-tuple
\bar{c}
,
we write
\bar{a}{\cdot}\bar{c}
or
\bar{a}\bar{c}
for
the
(k{+}\ell)
-tuple
({a}_{1},\ldots,{a}_{k},{c}_{1},\ldots,{c}_{\ell})
.
Given a function
f\colon X\to Y
and a
k
-tuple
\bar{x}
of elements in
X
,
we write
f(\bar{x})
for the
k
-tuple
(f({x}_{1}),\ldots,f({x}_{k}))
.
For
S\subseteq X^{k}
we let
f(S)=\{f(\bar{x})\,:\,\bar{x}\in S\}
.

We fix a countably infinite set
dom
for the
domain
of potential database entries,
which we also call
constants
.
A
schema

\sigma
is a finite, non-empty set of relation symbols,
where each
R\in\sigma
is equipped with a fixed arity
\operatorname{ar}(R)\in\mathbb{N}_{\scriptscriptstyle\geqslant 1}
.
A schema
\sigma
is called
binary
if every
R\in\sigma
has arity
\operatorname{ar}(R)\leqslant 2
.

A
database

D
of schema
\sigma
(
\sigma
-db, for short)
is a tuple of the form
D=(R^{D})_{R\in\sigma}
, where
R^{D}
is a finite subset of
\textbf{dom}^{\operatorname{ar}(R)}
. The
active domain

\textrm{adom}(D)
of
D
is the smallest subset
S
of
dom

such that
R^{D}\subseteq S^{\operatorname{ar}(R)}
for all
R\in\sigma
.
The
size

|D|
of
D
is defined as the total number of tuples in
D
, namely,

|D|=\sum_{R\in\sigma}|R^{D}|
.

A
k
-ary
query
(for
k\in\mathbb{N}
) of schema
\sigma
(
\sigma
-query, for short) is a
syntactic object
Q
which is associated with a function
{\left\llbracket Q\right\rrbracket}
that maps every
\sigma
-db
D

to a finite subset of
\textbf{dom}^{k}
, and which is
generic
in the following sense.
For every permutation
\pi
of
dom
and every
\sigma
-db
D
we have

\pi({\left\llbracket Q\right\rrbracket}(D))={\left\llbracket Q\right\rrbracket}(\pi(D))
, where
\pi(D)
is the
\sigma
-db
D^{\prime}

with
R^{D^{\prime}}:=\pi(R^{D})
for all
R\in\sigma
.

Boolean
queries are
k
-ary queries for
k=0
and

non-Boolean
queries are
k
-ary queries with
k\geqslant 1
.
Note that there are only two relations of arity 0, namely,
\emptyset
and
\{()\}
.
For a Boolean query
Q
we write
{\left\llbracket Q\right\rrbracket}(D)=\texttt{true}
to indicate that
()\in{\left\llbracket Q\right\rrbracket}(D)
,
and we write
{\left\llbracket Q\right\rrbracket}(D)=\texttt{false}
to indicate that
{\left\llbracket Q\right\rrbracket}(D)=\emptyset
.
In this paper we will focus on the following evaluation tasks for a given
\sigma
-db
D
:

•

Boolean query evaluation:
On input of a Boolean
\sigma
-query
Q
,
decide if
{\left\llbracket Q\right\rrbracket}(D)=\texttt{true}
.

•

Non-Boolean query evaluation:
Upon input of a non-Boolean
\sigma
-query
Q
,
compute the relation
{\left\llbracket Q\right\rrbracket}(D)
.

•

Counting query evaluation:
Upon input of a
\sigma
-query
Q
,
compute the number
|{\left\llbracket Q\right\rrbracket}(D)|
of tuples in the result of
Q
on
D
.

Concerning the second task, we are mainly interested in finding an
enumeration algorithm

for computing the tuples in
{\left\llbracket Q\right\rrbracket}(D)
.
Such an algorithm consists of two phases:
the
preprocessing phase
and the
enumeration phase
.
In the preprocessing phase, the algorithm is allowed to do arbitrary preprocessing to build
a suitable data structure
\textsf{{DS}}_{D,Q}
.
In the enumeration phase, the algorithm can use
\textsf{{DS}}_{D,Q}
to enumerate all tuples
in
{\left\llbracket Q\right\rrbracket}(D)
followed by an End-Of-Enumeration message
EOE
.
We require here that each tuple is enumerated exactly once (i.e., without repetitions).
The
delay
is the maximum time that passes between the start of the enumeration phase and
the first output, between the output of two consecutive tuples, and between the last tuple and
EOE
.

For our algorithms, we will assume the RAM-model with a uniform cost measure.
In particular, storing and accessing elements of
dom
requires
O(1)
space and time.
This assumption implies that, for any
r
-ary relation
R^{D}
, we can construct
in time
O(r\cdot|R^{D}|)
an index that allows to enumerate
R^{D}
with
O(1)
delay
and to test for a given
r
-tuple
\bar{c}
whether
\bar{c}\in R^{D}
in time
O(r)
.
Furthermore, this implies that given any finite partial function
f\colon A\to B
,
we can build a
lookup table
in time
O(|\textrm{dom}(f)|)
, where

\textrm{dom}(f):=\{x\in A\,:\,f(x)\text{ is defined}\}
,
and have access to
f(a)
in constant time.

3
Indexing for Query Evaluation

In this section, we formalize the setting for
indexing for query evaluation
for the tasks
of Boolean (
bool
), non-Boolean (
enum
), and counting (
count
) query evaluation
for a given class
\mathcal{Q}
of queries over a fixed schema
\sigma
.
We present here the general setting.
Later, we will instantiate it for a specific class of queries.
The scenario is:

(1)

As input we receive a
\sigma
-db
D
.
We perform an
indexing phase
in order to build a suitable data structure
\textsf{{DS}}_{D}
.
This data structure shall be helpful later on to efficiently evaluate

any
query
Q\in\mathcal{Q}
.

(2)

In the
evaluation phase
we have access to
\textsf{{DS}}_{D}
.
As input, we receive arbitrary queries
Q\in\mathcal{Q}
and
one of the three task descriptions
bool
,
count
, or
enum
,
where
bool
is only allowed in case that
Q
is a Boolean query.
The goal is to solve this query evaluation task for
Q
on
D
.

This scenario resembles what happens in real-world database systems,
where indexes are built to ensure efficient access to the information stored in the database,
and subsequently these indexes are used for evaluating various input queries.
We formalize the problem as:

Problem:

\textup{{IndexingEval}}(\sigma,\mathcal{Q})

Indexing:

\left\{\text{
\begin{tabular}[]{rl}{input:}&\!\!\!
a $\sigma$-db $D$\\
{result:}&\!\!\!
a data structure $\textsf{{DS}}_{D}$\end{tabular}
}\right.

​​

Evaluation:

\left\{\!\!\!\text{
\begin{tabular}[]{rl}{input:}&\!\!\!
\parbox[t]{212.1769pt}{a $\sigma$-query $Q\in\mathcal{Q}$, and a task
description in $\{\textsl{{bool}},\textsl{{enum}},\textsl{{count}}\}$
}\\
{output:}&\!\!\!
\parbox[t]{212.1769pt}{the correct answer solving the given task for ${\left\llbracket Q\right\rrbracket}(D)$
}\end{tabular}
}\right.

The
indexing time
is the time used for building the data structure
\textsf{{DS}}_{D}
.
It only depends on the input database
D
, and we usually measure it by a function

f_{\operatorname{index}}(D)
that provides an upper bound on the time it takes
to perform the indexing phase for
D
.

The time it takes to answer a Boolean query
Q
on
D
or for counting the number of result tuples
of a query
Q
on
D
depends on
Q
and the particular properties of the data structure
\textsf{{DS}}_{D}
.
We usually measure these times by functions
f_{\textsl{{bool}}}(Q,D)
and

f_{\textsl{{count}}}(Q,D)
that provide an upper bound on the time it takes
to perform the task by utilizing the data structure
\textsf{{DS}}_{D}
.
Concerning the task
enum
, we measure the preprocessing time and the delay by functions

f_{\operatorname{prep}}(Q,D)
and
f_{\operatorname{delay}}(Q,D)
that provide upper bounds on the time taken
for preprocessing and the delay, respectively,
when using the data structure
\textsf{{DS}}_{D}
to enumerate
{\left\llbracket Q\right\rrbracket}(D)
.

Note that for measuring running times we use
D
and not
|D|
(e.g.,
f_{\textsl{{bool}}}(Q,D)
),
because we want to allow the running time analysis to be more fine-grained
than just depending on the number of tuples of
D
.
The main result of this paper is a solution for
\textup{{IndexingEval}}(\sigma,\mathcal{Q})
where
\mathcal{Q}
is
the class
\textsf{{fc-ACQ}}[\sigma]
of all
free-connex acyclic conjunctive queries
of a

binary
schema
\sigma
(i.e., all
R\in\sigma
have arity
\operatorname{ar}(R)\leqslant 2
).

4
Free-Connex Acyclic CQs

This section provides the necessary definitions and known results concerning
\textsf{{fc-ACQ}}[\sigma]
.
We fix a countably infinite set
var
of
variables
such that
\textbf{var}\cap\textbf{dom}=\emptyset
.
An
atom

a
of schema
\sigma
is of the form
R(x_{1},\ldots,x_{r})
where
R\in\sigma
,

r=\operatorname{ar}(R)
, and
x_{1},\ldots,x_{r}\in\textbf{var}
.
We write
\textrm{vars}(a)
for the set of variables occurring in
a
.
Let
k\in\mathbb{N}
.
A
k
-ary
conjunctive query
(CQ) of schema
\sigma
is of the form

\textit{Ans}(z_{1},\ldots,z_{k})\leftarrow a_{1},\ldots,a_{d}

(1)

where
d\in\mathbb{N}_{\scriptscriptstyle\geqslant 1}
,
a_{j}
is an atom of schema
\sigma
for every
j\in[d]
,
and
z_{1},\ldots,z_{k}
are
k
pairwise distinct variables in
\bigcup_{j\in[d]}\textrm{vars}(a_{j})
.
The expression to the left (right) of
\leftarrow
is called
the
head
(
body
) of the query.
For a CQ
Q
of the form (
1
) we let

\textrm{atoms}(Q)=\{a_{1},\ldots,a_{d}\}
,
\textrm{vars}(Q)=\bigcup_{j\in[d]}\textrm{vars}(a_{j})
,
and
\textrm{free}(Q)=\{z_{1},\ldots,z_{k}\}
.
The
(existentially) quantified
variables are the elements in

\textrm{quant}(Q):=\textrm{vars}(Q)\setminus\textrm{free}(Q)
.
A CQ
Q
is called
Boolean
if
\textrm{free}(Q)=\emptyset
, and it is called
full

(or,
quantifier-free
) if
\textrm{quant}(Q)=\emptyset
.
The
size

|Q|
of the query is defined as
|\textrm{atoms}(Q)|
.

The semantics are defined as usual.
A
valuation

\nu
for
Q
is a mapping
\nu\colon\textrm{vars}(Q)\to\textbf{dom}
.
A valuation
\nu
is a
homomorphism
from
Q
to a
\sigma
-db
D
if for every atom

R(x_{1},\ldots,x_{r})\in\textrm{atoms}(Q)
we have
(\nu(x_{1}),\ldots,\nu(x_{r}))\in R^{D}
.
The
query result
of a CQ
Q
of the form (
1
) on
the
\sigma
-DB
D
is defined as the set of tuples

{\left\llbracket Q\right\rrbracket}(D)\;:=\;\{\,(\nu(z_{1}),\ldots,\nu(z_{k}))\,:\,\nu\text{ is a homomorphism from $Q$ to $D$}\,\}.

(2)

The
hypergraph

H(Q)
of a CQ
Q
is defined as follows.
Its vertex set is
\textrm{vars}(Q)
, and it contains a hyperedge
\textrm{vars}(a)

for every
a\in\textrm{atoms}(Q)
.
The
Gaifman graph

G(Q)
of
Q
is the undirected simple graph with vertex set
\textrm{vars}(Q)
,
and it contains the edge
\{x,y\}
whenever
x,y
are distinct variables such that

x,y\in\textrm{vars}(a)
for some
a\in\textrm{atoms}(Q)
.

Acyclic
CQs and
free-connex acyclic
CQs are standard notions studied in
the database theory literature
(cf.
[
7
,
10
,
17
,
6
,
1
]
;
see
[
9
]
for an overview).
A CQ
Q
is called
acyclic
if its hypergraph
H(Q)
is
\alpha
-acyclic
, i.e.,
there exists an undirected tree
T=(V(T),E(T))
(called a
join-tree
of
H(Q)
and of
Q
)
whose set of nodes
V(T)
is precisely the set of hyperedges of
H(Q)
, and where for each variable

x\in\textrm{vars}(Q)
the set
\{t\in V(T)\,:\,x\in t\}
induces a connected subtree of
T
.
A CQ
Q
is
free-connex acyclic
if it is acyclic
and
the hypergraph obtained
from
H(Q)
by adding the hyperedge
\textrm{free}(Q)
is
\alpha
-acyclic.

Note that any CQ
Q
that is either Boolean or full is free-connex acyclic iff it is acyclic.
However,
\textit{Ans}(x,z)\leftarrow R(x,y),R(y,z)
is an example of a query that is acyclic,
but not free-connex acyclic.

For the special case of a
binary
schema, there is a particularly simple characterization of
(free-connex) acyclic CQs that will be useful for our purpose
(see Appendix
A
for a proof).

Proposition 4.1

(Folklore)
.

A CQ
Q
of a
binary
schema
\sigma
is
acyclic

iff its Gaifman graph
G(Q)
is acyclic.
The CQ
Q
is
free-connex acyclic
iff
G(Q)
is acyclic
and the following statement is true: For every connected component
C
of
G(Q)
,
the subgraph of
C
induced by the set
\textrm{free}(Q)\cap V(C)
is connected or empty.

We write
\textsf{{fc-ACQ}}[\sigma]
to denote the set of all free-connex acyclic CQs of schema
\sigma
.
In the following, we state two seminal results by Yannakakis
[
35
]
and Bagan,
Durand, and Grandjean
[
6
]
that will be crucial for the main result of this paper.

Theorem 4.2

(Yannakakis
[
35
]
)
.

For every schema
\sigma
there is an algorithm that receives as input a
\sigma
-db
D
and
a Boolean acyclic CQ
Q
of schema
\sigma
and takes time

O(|Q|{\cdot}|D|)
to decide if
{\left\llbracket Q\right\rrbracket}(D)=\texttt{true}
.

In the literature, Yannakakis’ result is often described in terms of
data complexity
, i.e.,
running time components that depend on the query are hidden in the O-notation.
Adopting this view, Yannakakis’ result states that Boolean acyclic CQs can be evaluated with
linear-time data complexity.
Bagan, Durand, and Grandjean
[
6
]
achieved an influential result for the task of
enumerating the set
{\left\llbracket Q\right\rrbracket}(D)
for (non-Boolean)
free-connex acyclic
CQs
Q
:
They found an enumeration algorithm with
O(|D|)
preprocessing time and constant delay.
This statement refers to data complexity, i.e.,
running time components that depend on the query are hidden in the O-notation.
Several proofs of (and different algorithms for) Bagan, Durand and Grandjean’s theorem
are available in the literature
[
6
,
5
,
12
,
28
,
21
,
22
,
23
]
;
all of them focus on data complexity.
For this paper we need a more refined statement that takes into account the combined complexity of
the problem, and that is implicit in
[
9
]
(see Appendix
A
).

Theorem 4.3
.

For every schema
\sigma
there is an enumeration algorithm that receives as input
a
\sigma
-db
D
and a query
Q\in\textsf{{fc-ACQ}}[\sigma]
and that computes within preprocessing time

O(|Q|{\cdot}|D|)
a data structure for enumerating
{\left\llbracket Q\right\rrbracket}(D)
with delay
O(|\textrm{free}(Q)|)
.

Our main result provides a solution for the problem
\textup{{IndexingEval}}(\sigma,\textsf{{fc-ACQ}}[\sigma])

for
binary
schemas
\sigma
.
The data structure
\textsf{{DS}}_{D}
that we build for a given database
D
during the indexing phase will
provide a new database
{D_{\operatorname{col}}}
.
This database
{D_{\operatorname{col}}}
is potentially much smaller than
D
, and it will allow us to improve
the preprocessing time provided by Theorem
4.3
to
O(|Q|{\cdot}|{D_{\operatorname{col}}}|)
.
At a first glance one may be tempted to believe that it should be straightforward to generalize our
result from binary to arbitrary schemas by representing databases of a non-binary schema
\sigma

as databases of a suitably chosen binary schema
\sigma^{\prime}
.
However, the notion of fc-ACQs is quite subtle, and an fc-ACQ of schema
\sigma
might translate
into a CQ of schema
\sigma^{\prime}
that is not an fc-ACQ
(see Appendix
A.3
for an example), hence prohibiting to
straightforwardly reduce the case of general schemas to our results for fc-ACQs over binary schemas.

5
Construction of the color-index

For the remainder of this paper let us fix an arbitrary
binary
schema
\sigma
,
i.e., every
R\in\sigma
has arity
\operatorname{ar}(R)\leqslant 2
.
Our main result is a solution for
\textup{{IndexingEval}}(\sigma,\textsf{{fc-ACQ}}[\sigma])
.
In this section, we describe the indexing phase of our solution.
Upon input of a
\sigma
-db
D
, we will build a data structure
\textsf{{DS}}_{D}

that we call the
color-index
for
\textsf{{fc-ACQ}}[\sigma]
.
To describe this data structure, we need the following notions.

Graph representation

Let
D
be a
\sigma
-db that we receive as input.
We start by encoding self-loops in
D
into unary predicates.
Let
\bar{\sigma}
be the schema obtained by inserting into
\sigma
a new unary relation symbol

S_{R}
for every
R\in\sigma
with
\operatorname{ar}(R)=2
.
We turn
D
into a
\bar{\sigma}
-db
\bar{D}
by letting
R^{\bar{D}}=R^{D}
for every
R\in\sigma
,
and
S_{R}^{\bar{D}}:=\{(v)\,:\,(v,v)\in R^{D}\}
for every
R\in\sigma
with
\operatorname{ar}(R)=2
.
Thus, relation
S_{R}
of
\bar{D}
consists of all elements
v
such that
(v,v)\in R^{D}

(i.e.,
(v,v)
is a
self-loop
w.r.t.
R
in
D
).
Note that self-loops are still present in each binary relation
R
,
and
S_{R}
is a redundant representation of these self-loops.
Clearly, the size of
\bar{D}
is linear in the size of
D
.

We represent
\bar{D}
as a vertex-labeled and edge-labeled directed graph

\bar{G}=(\bar{V},\bar{E},\textnormal{{vl}},\textnormal{{el}})
as follows:

\bar{V}=\textrm{adom}(D)
and
\bar{E}
consists of all directed edges
(v,w)
such that
v\neq w
and

(v,w)\in R^{\bar{D}}
or
(w,v)\in R^{\bar{D}}
for some
R\in\bar{\sigma}
with
\operatorname{ar}(R)=2
.
Further, we define the vertex- and edge-labeling functions
vl
and
el
:

\displaystyle\textnormal{{vl}}(v)\;\;

\displaystyle:=\;\;\;

\displaystyle\{\,U\in\bar{\sigma}\,:\,\operatorname{ar}(U)=1,\ (v)\in U^{\bar{D}}\,\}\vskip 3.0pt plus 1.0pt minus 1.0pt

\displaystyle\textnormal{{el}}(v,w)\;\;

\displaystyle:=

\displaystyle\{\,(R,\rightarrow)\,:\,R\in\bar{\sigma},\ \operatorname{ar}(R)=2,\ (v,w)\in R^{\bar{D}}\,\}\ \,\cup

\displaystyle\{\,(R,\leftarrow)\,:\,R\in\bar{\sigma},\ \operatorname{ar}(R)=2,\ (w,v)\in R^{\bar{D}}\,\}

for every vertex
v\in\bar{V}
and every edge
(v,w)\in\bar{E}
.

Note that
(\bar{V},\bar{E})
is a self-loop-free simple and symmetric directed graph.
Self-loops present in
D
are not represented by (labeled) edges but by vertex-labels in
\bar{G}

(to enable this, we moved over from
D
to
\bar{D}
).
For every edge
(v,w)\in\bar{E}
, the label
\textnormal{{el}}(v,w)
determines the label
\textnormal{{el}}(w,v)
of
the corresponding “backwards edge” as follows.
If
\textnormal{{el}}(v,w)=\lambda
, then
\textnormal{{el}}(w,v)=\widetilde{\lambda}
for the
dual
label

\widetilde{\lambda}:=\{(R,\rightarrow)\,:\,(R,\leftarrow)\in\lambda\}\cup\{(R,\leftarrow)\,:\,(R,\rightarrow)\in\lambda\}
.

Let
L_{\bar{V}}:=\textrm{img}(\textnormal{{vl}})
and
L_{\bar{E}}:=\textrm{img}(\textnormal{{el}})
be the sets of labels that are
actually used as vertex labels and edge labels, respectively, of
\bar{G}
.
One can easily check that
\bar{G}
can be generated in time
O(|\bar{D}|)
, and
|\bar{E}|=O(|\bar{D}|)
.
Furthermore, although the number of potential labels of
vl
and
el

could be exponential in
|\bar{\sigma}|
, it holds that the number of actual labels

|L_{\bar{V}}|
and
|L_{\bar{E}}|
is at most linear in
|\bar{D}|
.

Color refinement

Once having produced
\bar{G}
, we apply to it a suitable variant of the well-known

color refinement
algorithm.
A high-level description of this algorithm, basically taken from
[
8
]
,
is as follows.
The algorithm classifies the vertices of
\bar{G}
by iteratively refining a coloring of the vertices.
Initially, each vertex
v
has color
\textnormal{{vl}}(v)
.
Then, in each step of the iteration, two vertices
v,w
that currently have the same color get
different refined colors if for some color
c
of the currently used vertex-colors and
for some edge-label
\lambda\in L_{\bar{E}}
,
we have
{\#}_{\rightarrow}^{\lambda}({v},{c})\neq{\#}_{\rightarrow}^{\lambda}({w},{c})
.
Here, for any vertex
u
of
\bar{G}
, we let
{\#}_{\rightarrow}^{\lambda}({u},{c}):=|{N}_{\rightarrow}^{\lambda}({u},{c})|

where
{N}_{\rightarrow}^{\lambda}({u},{c})
denotes the set of all outgoing
\bar{E}
-neighbors
u^{\prime}
of
u

(i.e.,
(u,u^{\prime})\in\bar{E}
) such that
\textnormal{{el}}(u,u^{\prime})=\lambda
and
u^{\prime}
has color
c
.
The process stops if no further refinement is achieved,
resulting in a
stable coloring
of the vertices.

In
[
8
]
, Berkholz, Bonsma, and Grohe showed that this can be implemented
in such a way that it runs in time
O((|\bar{V}|+|\bar{E}|)\log|\bar{V}|)
.
To formally state their result, we need the following notation.
Let
f\colon\bar{V}\to S
be a function, where
S
is any set.
We say that a function
\textnormal{{col}}\colon\bar{V}\to C

refines

f
iff for all

v,w\in\bar{V}
with
\textnormal{{col}}(v)=\textnormal{{col}}(w)
we have
f(v)=f(w)
.
Further, we say that
col

is stable
iff for all
v,w\in\bar{V}
with
\textnormal{{col}}(v)=\textnormal{{col}}(w)
,
and for every edge-label
\lambda\in L_{\bar{E}}
and for every color
c\in C
we have:

{\#}_{\rightarrow}^{\lambda}({v},{c})={\#}_{\rightarrow}^{\lambda}({w},{c})
.
Finally,
col
is a
coarsest stable coloring that refines
vl
iff
col
is stable,

col
refines
vl
, and for every coloring
\textnormal{{col}}^{\prime}\colon\bar{V}\to C^{\prime}
(for some set
C^{\prime}
)
that is stable and that refines
vl
we have:
\textnormal{{col}}^{\prime}
refines
col
.
The main result of
[
8
]
implies the following theorem
(see Appendix
B
for details).

Theorem 5.2

(
[
8
]
)
.

For any vertex-labeled and edge-labeled directed simple graph
\bar{G}=(\bar{V},\bar{E},\textnormal{{vl}},\textnormal{{el}})
, within time
O((|\bar{V}|+|\bar{E}|)\log|\bar{V}|)
one can compute a coloring
\textnormal{{col}}\colon\bar{V}\to C
(for a suitably chosen set
C
), such that
col
is a coarsest stable coloring that refines
vl
.

In the indexing phase, we apply the algorithm provided
by Theorem
5.2
to
\bar{G}
.
Let
f_{\operatorname{col}}(\bar{D})
denote the time taken for this, and note that

f_{\operatorname{col}}(\bar{D})\in O(|\bar{D}|\cdot\log|\textrm{adom}(\bar{D})|)
.
Note that this is the
worst-case
complexity; in case that
\bar{D}
has a particularly simple
structure, the algorithm may terminate already in time
O(|\bar{D}|)
.

As a result we obtain a
coarsest stable coloring
\textnormal{{col}}\colon\textrm{adom}(\bar{D})\to C

that refines
vl
, for a suitable set
C
.
Note that the number
|\textrm{img}(\textnormal{{col}})|
of colors used by
col
is the smallest number possible
in order to obtain a stable coloring that refines
vl
, and, moreover,
the coarsest stable coloring that refines
vl
is
unique
up to a renaming of colors.

The color-index

To describe the color-index structure
\textsf{{DS}}_{D}
, we use the following notation.
For all
c,c^{\prime}\in C
and every edge-label
\lambda
we let

{\#}_{\rightarrow}^{\lambda}({c},{c^{\prime}}):={\#}_{\rightarrow}^{\lambda}({v},{c^{\prime}})

for some (and hence, for every, by Fact
5.4
)
v\in\bar{V}
with
\textnormal{{col}}(v)=c
.
For every potential edge-label
\lambda

(i.e.,
\lambda\subseteq\{(R,\rightarrow),\,(R,\leftarrow)\,:\,R\in\bar{\sigma},\,\operatorname{ar}(R)=2\}
with

\lambda\neq\emptyset
) we let

\displaystyle{\widehat{\#}}_{\rightarrow}^{\lambda}({c},{c^{\prime}})

\displaystyle\ :=\ \sum_{\lambda^{\prime}\supseteq\lambda}{\#}_{\rightarrow}^{\lambda^{\prime}}({c},{c^{\prime}})

and

\displaystyle{\widehat{N}}_{\rightarrow}^{\lambda}({v},{c})

\displaystyle\ :=\ \bigcup_{\lambda^{\prime}\supseteq\lambda}{N}_{\rightarrow}^{\lambda^{\prime}}({v},{c})\;,

where the considered
\lambda^{\prime}
are actual edge-labels in
L_{\bar{E}}
.
The reason why we exclude
\lambda=\emptyset
is that we do not need it.
Including it would only unnecessarily blow up the number of tuples present in
{D_{\operatorname{col}}}
.
The data structure
\textsf{{DS}}_{D}
that we build during the indexing phase consists of
the following five components:

(1)

the schema
\bar{\sigma}
and the
\bar{\sigma}
-db
\bar{D}
;

(2)

a lookup table to access the color
\textnormal{{col}}(v)
given a vertex
v\in\bar{V}
, and
an (inverse) lookup table to access the set
\{v\in\bar{V}\,:\,\textnormal{{col}}(v)=c\}
given a
c\in C
,
plus the number
n_{c}
of elements in this set;

(3)

lookup tables to access the set
{\widehat{N}}_{\rightarrow}^{\lambda}({v},{c})
,
given a potential edge-label
\lambda
, a vertex
v\in\bar{V}
, and a color
c\in C
;

(4)

lookup tables to access the number
{\widehat{\#}}_{\rightarrow}^{\lambda}({c},{c^{\prime}})
,
given a potential edge-label
\lambda
and colors
c,c^{\prime}\in C
;

(5)

the
color database

{D_{\operatorname{col}}}
of the
color schema

\sigma_{\operatorname{col}}
defined as follows:

•

The schema
\sigma_{\operatorname{col}}
consists of all the
unary
relation symbols of
\bar{\sigma}

and a binary relation symbol
E_{\lambda}
for every potential edge-label
\lambda

(i.e.,
\lambda\subseteq\{(R,\rightarrow),\,(R,\leftarrow)\,:\,R\in\bar{\sigma},\,\operatorname{ar}(R)=2\}

with
\lambda\neq\emptyset
).

•

The
\sigma_{\operatorname{col}}
-db
{D_{\operatorname{col}}}
is defined as follows.
For each unary relation symbol
U\in\bar{\sigma}
we let
U^{{D_{\operatorname{col}}}}
be the set of unary
tuples
(c)
for all
c\in C
such that there is a
(v)\in U^{\bar{D}}
with
\textnormal{{col}}(v)=c
.
For every potential edge-label
\lambda
we let
E_{\lambda}^{{D_{\operatorname{col}}}}
be the set of
all tuples
(c,c^{\prime})\in C\times C
such that
{\widehat{\#}}_{\rightarrow}^{\lambda}({c},{c^{\prime}})>0
.
Note that
\textrm{adom}({D_{\operatorname{col}}})=C
.

6
Evaluation using the color-index

This section shows how to use the color-index
\textsf{{DS}}_{D}
to evaluate
any free-connex acyclic CQ
Q
over
D
.
I.e., we describe the
evaluation phase
of our solution for
\textup{{IndexingEval}}(\sigma,\textsf{{fc-ACQ}}[\sigma])
.
We assume that the color-index
\textsf{{DS}}_{D}
(including the color database
{D_{\operatorname{col}}}
)
of the given database
D
has already been built during the indexing phase.
Let
Q\in\textsf{{fc-ACQ}}[\sigma]
be an arbitrary query that we may receive as an input during the evaluation phase.
We first explain how the evaluation tasks can be simplified by focusing on
connected
queries.

Connected queries

We say that a CQ
Q
is
connected
iff its Gaifman graph
G(Q)
is connected.
Intuitively, if a CQ
Q
is not connected, then we can write
Q
as

\textit{Ans}(\bar{z}_{1},\ldots,\bar{z}_{\ell})\ \leftarrow\ \bar{\alpha}_{1}(\bar{z}_{1},\bar{y}_{1}),\ldots,\bar{\alpha}_{\ell}(\bar{z}_{\ell},\bar{y}_{\ell})

such that each
\bar{\alpha}_{i}(\bar{z}_{i},\bar{y}_{i})
is a sequence of atoms,

\textrm{vars}(\bar{\alpha}_{i}(\bar{z}_{i},\bar{y}_{i}))

g^{\prime}(c,y)\ :=\ \ \sum_{c^{\prime}\in C}\ f^{\prime}_{\downarrow}(c^{\prime},y)\cdot\ {\widehat{\#}}_{\rightarrow}^{\lambda_{e}}({c},{c^{\prime}}).

For every

By induction (bottom-up along

Thus,

7
Statement of our main result

From Sections

and

where
{D_{\operatorname{col}}}

Theorem 7.1
.

For every binary schema

, the problem

8
Final Remarks

Our main result provides a solution for the problem
\textup{{IndexingEval}}(\sigma,\textsf{{fc-ACQ}}[\sigma])
for any

binary
schema
\sigma
.
Our approach can be summarized as follows.
Upon input of a database
D
of schema
\sigma
, during the indexing phase we construct a
vertex-labeled and edge-labeled directed graph
\bar{G}
that represents
D
.
We then use a suitable version of the well-known color refinement algorithm to construct a
coarsest stable coloring
\textnormal{{col}}\colon\textrm{adom}(D)\to C
(for a suitable set
C
of colors)
that refines the vertex-labels of
\bar{G}
.
Based on this, we construct the data structure
\textsf{{DS}}_{D}
that we call
color-index
and
that we view as the result of the indexing phase.
The main ingredient of
\textsf{{DS}}_{D}
is the
color database

{D_{\operatorname{col}}}
.
This is a database of a newly constructed schema
\sigma_{\operatorname{col}}
; its active domain is the set
C
.

During the evaluation phase, we can access the color-index
\textsf{{DS}}_{D}
.
When receiving an arbitrary
k
-ary input query
Q\in\textsf{{fc-ACQ}}[\sigma]
, we use
\textsf{{DS}}_{D}

(and, in particular,
{D_{\operatorname{col}}}
) to

•

answer
Q
, in case that
k=0
, in time
O(|Q|{\cdot}|{D_{\operatorname{col}}}|)
,

•

compute
|{\left\llbracket Q\right\rrbracket}(D)|
in time
O(|Q|{\cdot}|{D_{\operatorname{col}}}|)
, and

•

enumerate
{\left\llbracket Q\right\rrbracket}(D)
with delay
O(k)
after
O(|Q|{\cdot}|{D_{\operatorname{col}}}|)
preprocessing.

It was known previously that each of these query evaluation tasks can be solved
(without access to our color-index
\textsf{{DS}}_{D}
) in time
O(|Q|{\cdot}|D|)
.
Our result provides an improvement from
|D|
to
|{D_{\operatorname{col}}}|
.
In the worst-case,
|{D_{\operatorname{col}}}|=O(|D|)
; but depending on the particular structure of
D
,
the color database
{D_{\operatorname{col}}}
may be much smaller than
D
(see Proposition
5.6
).

Future work

Obvious questions (we currently work on) are:

Can our approach be generalized from fc-ACQs to queries of free-connex tree-width
\leqslant k
,
for any fixed
k\geqslant 1
?

When sticking with binary schemas, we believe that this can be achieved by using a variant of
the
k
-dimensional Weisfeiler-Leman algorithm (cf.
[
15
,
19
]
).

Can our approach be generalized from binary schemas to arbitrary schemas?

Due to subtleties concerning the notion of fc-ACQs, a straightforward representation of databases
over an arbitrary schema
\sigma
by databases of a suitably chosen binary schema
\sigma^{\prime}

apparently does not help to easily lift our results from binary to arbitrary schemas
(see Appendix
A.3
).
To solve the case for arbitrary schemas, a generalization of the color refinement algorithm from
graphs to hypergraphs would be desirable.
Böker
[
14
]
provided a color refinement algorithm that seems promising for handling
queries
Q
that are free-connex
Berge-acyclic
.
But a new color refinement algorithm needs to be developed to handle also
free-connex acyclic queries that are not free-connex Berge-acyclic.

Can our approach be lifted to a dynamic scenario?

The
dynamic Yannakakis
approach of Idris, Ugarte, and Vansummeren
[
21
]
lifts Theorem
4.3
to a dynamic scenario,
where a fixed query
Q
shall be evaluated against a database
D
that is frequently updated.
Note that our color-index
\textsf{{DS}}_{D}
is not built for a fixed query,
but for supporting
all
queries.
When receiving an update for the database
D
,
we would have to modify the color-index
\textsf{{DS}}_{D}
accordingly.
Already a small change of the color of a single vertex or its local neighborhood in
\bar{G}
might
impose drastic changes in the result of the color refinement algorithm and might change
the size of
{D_{\operatorname{col}}}
from
O(1)
to
\Theta(|D|)
, or vice versa.
(For example, consider the database
D^{n}
from the proof of Proposition
5.6
.
Inserting the tuple
(1,1)
into the
R
-relation leads to
a coarsest stable coloring with approximately
n/2
colors;
and subsequently deleting
(1,1)
from the
R
-relation again reduces the number of colors to 1.)
Nevertheless, it is an interesting question if
\textsf{{DS}}_{D}
can be updated in time proportional to
the actual difference between the two versions of
\textsf{{DS}}_{D}
before and after the update.

What is the potential practical impact of our approach?

To further reduce the size of
{D_{\operatorname{col}}}
,
one may decide to let the color refinement procedure only run for a fixed number
r
of rounds.
The resulting coarser variant of our color-index can still be used
for evaluating fc-ACQs of radius up to
r
.
We believe that this variant of the color-index deserves a detailed experimental evaluation.

A.3
An example concerning a non-binary schema

At a first glance one may be tempted to believe that it should be straightforward to generalize
our main result from binary to arbitrary schemas by representing databases of
a non-binary schema
\sigma
as databases of a suitably chosen binary schema
\sigma^{\prime}
.
However, the notion of fc-ACQs is quite subtle, and an fc-ACQ of schema
\sigma
might translate
into a CQ of schema
\sigma^{\prime}
that is not an fc-ACQ, hence prohibiting to straightforwardly
reduce the case of general schemas to our results for fc-ACQs over binary schemas.
Here is a concrete example.

Let us consider a schema consisting of a single, ternary relation symbol
R
.
A straightforward way to represent a database
D
of this schema by
an edge-labeled bipartite digraph
D^{\prime}
is as follows.

D^{\prime}
has 3 edge-relations called
E_{1},E_{2},E_{3}
.
Every element in the active domain of
D
is a node of
D^{\prime}
.
Furthermore, every tuple
t=(a_{1},a_{2},a_{3})
in the
R
-relation of
D
serves as a node of
D^{\prime}
,
and we insert into
D^{\prime}
an
E_{1}
-edge
(t,a_{1})
, an
E_{2}
-edge
(t,a_{2})
,
and an
E_{3}
-edge
(t,a_{3})
.
Now, a CQ
Q
posed against
D
translates into a CQ
Q^{\prime}
posed against
D^{\prime}
as follows:

Q^{\prime}
has the same head as
Q
.
For each atom
R(x,y,z)
in the body of
Q
we introduce a new variable
u
and insert
into the body of
Q^{\prime}
the atoms
E_{1}(u,x),E_{2}(u,y),E_{3}(u,z)
.

We want to build an index structure on
D
that supports constant-delay enumeration and counting
for all fc-ACQs
Q
posed against
D
.
The problem is that an fc-ACQ
Q
against
D
does
not
necessarily translate
into an
fc-ACQ

Q^{\prime}
against
D^{\prime}
— and therefore,
lifting our approach from binary to arbitrary schemas is not so easy.
Here is a specific example of such a query
Q
:

\textit{Ans}(x,y,z)\ \leftarrow\ R(x,y,z),\ R(x,x,y),\ R(y,y,z),\ R(z,z,x).

This query is an fc-ACQ (as a witness, take the join-tree whose root is labeled with
R(x,y,z)

and has 3 children labeled with the remaining atoms in the body of the query).
But the associated query
Q^{\prime}
is

\textit{Ans}(x,y,z)\ \leftarrow\begin{array}[t]{l}E_{1}(u_{1},x),E_{2}(u_{1},y),E_{3}(u_{1},z),\\
E_{1}(u_{2},x),E_{2}(u_{2},x),E_{3}(u_{2},y),\\
E_{1}(u_{3},y),E_{2}(u_{3},y),E_{3}(u_{3},z),\\
E_{1}(u_{4},z),E_{2}(u_{4},z),E_{3}(u_{4},x).\end{array}

Note that the Gaifman-graph of
Q^{\prime}
is not acyclic (it contains the cycle
x-u_{2}-y-u_{3}-z-u_{4}-x
).
Therefore, by Proposition
4.1
,
Q^{\prime}
is not an fc-ACQ.
This simple example illustrates that the straightforward encoding of the database
D

as a database over a binary schema won’t help to easily lift the main result of
this paper from binary to arbitrary schemas.

(
\Rightarrow

.

Appendix D
A modified approach that avoids the exponential dependency on
\sigma

Before finalizing this paper, we had two versions of our construction.
Version 1 is clean, easy to understand, and easily proved to be correct —
but has an exponential dependency on the schema.
Version 2 is more complicated, more difficult to be proved to be correct —
but avoids the exponential dependency on the schema.
Once having understood the construction of Version 1,
we believe that the overall idea of Version 2 can be explained with only moderate additional effort.
But presenting only Version 2 without prior explanation of Version 1, we believe,
the main idea of our index structure (and its correctness) would have been much harder to grasp.
