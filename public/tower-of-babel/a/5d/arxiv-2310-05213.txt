A Quantum Approach for Reducing Communications in Classical Cryptographic Primitives
Jiayu Zhang

Abstract
How could quantum cryptography help us achieve what are not achievable in classical cryptography? In this work we consider the following problem, which we call succinct RSPV for classical functions (SRC). Suppose f f is a function described by a polynomial time classical Turing machine, which is public; the client would like to sample a random x x as the function input and use a protocol to send f ⁡ ( x ) f(x) to the server. What’s more, (1) when the server is malicious, what it knows in the passing space should be no more than f ⁡ ( x ) f(x) ; (2) the communication should be succinct (that is, independent to the running time of evaluating f f ). Solving this problem in classical cryptography seems to require strong cryptographic assumptions. We show that, perhaps surprisingly, it’s possible to solve this problem with quantum techniques under much weaker assumptions. By allowing for quantum communication and computations, we give a protocol for this problem assuming only collapsing hash functions [ 26 ] . Our work conveys an interesting message that quantum cryptography could outperform classical cryptography in a new type of problems, that is, to reduce communications in meaningful primitives without using heavy classical cryptographic assumptions.

1.1
Our Works, Part I: the Problem and the Basic Construction

In this work we formalize a classical cryptographic problem called

1.1.1
Succinct RSPV for classical functions (SRC)

The problem that we consider is as follows. Consider a client and a server, and a function
f
described by a polynomial time classical Turing machine, and an input length
n

x\leftarrow_{r}\{0,1\}^{n}

to the server. We would like to design a protocol for this problem with roughly the following correctness, security and efficiency requirement:

•

(Correctness) When both parties follow the protocol, the protocol passes successfully and the client gets a random

and the server gets the corresponding

•

(Security) For any polynomial time malicious server, there is a server-side simulator taking

f(x)

•

(Efficiency) The honest behaviors of both parties run in polynomial time; what’s more, the total size of the communication is independent to the running time of evaluating
f

An overview of the full proof

What we already have is, by the knowledge extraction property of the SAoK protocol, the server holds
d^{(out)}
that satisfies the conditions by the end of step 3.d of the test roundtype. What we want to argue is, before the beginning of step 3.d, the server already knows such a

1.

Prove the server knows (more formally, there exists an efficient extractor that could extract)

if only one of

(say,

2.

Prove the server already knows

before the client sends

Once we complete the argument above, the problem is roughly reduced to the simplified setting described in Section

Furthermore, the difficulties in two steps above are actually the same. Thus we could zoom in to the first step: how to remove the reliance on
x_{1}
on the server-side extraction of

Note that in each step of the protocol, the state appearing in the protocol could be written as the sum of two states: one state is the output state when the state prepared in step 1 of Protocol

\frac{1}{\sqrt{2}}\ket{x_{1}}\ket{x_{1}^{(inppad)}}\ket{x_{1}^{(outpad)}}

-branch and the
x_{1}
-branch. Then the construction of the extraction of

is further divided into two steps.

1.

Show that there exists a server-side extraction algorithm with access to

that extracts

2.

Show that the extraction operation above also works in the
x_{1}
-branch; what’s more, the output of the extraction algorithm on these two branches are coherent in the right way.

The first step is roughly what we have done in the Section
1.2.2

is sent out, the server-side of the

The nontrivial part is how to move from one branch to the other branch. Here we make use of the collapsing property of hash functions together with the Hadamard test conditions to achieve this leap.

1.

To move from one branch to the other, a key step here is to return to consider the behavior of the protocol in the normal execution, that is, the input state is the sum of the two branches. The passing condition says, the server’s probability of holding a

but the hash checking (

Here we need to be careful that the server’s operation here is different from the “extraction of

Related Works

Studies of succinctness in quantum cryptography

There has been several works that study succinctness in quantum cryptography, like
[

,
4
]
.
[
29
]
studies succinctness of quantum communication in blind quantum computation problem;

Classical primitives that share similarities to our problem

There are a series of classical primitives that share some similarity to our notion including garbling
[
27
]
, succinct randomized encoding
[
7
]
, laconic function evaluation
[
21
]
, etc. As far as we know, our notion is different from these existing notions: we allow interactions so our notion is different from garbling and succinct randomized encoding; the communication size in our problem should be independent to the output size of
f
so it’s different from laconic function evaluation. Despite this, considering the extensive development of classical cryptography, it’s not a surprise that our notion has already been considered in existing works of classical cryptography.

Quantum works that share technical similarities to our construction

Our construction contains a sense of revocation or deletion, which is a quantum phenomenon. A series of existing works also make use of this phenomenon to achieve nontrivial cryptographic tasks, for example,
[
24
,
9
,
5
,
28
]
. However, our usage of this quantum phenomenon is different from these existing techniques so we consider our technique to be in the same class as but parallel to these existing works.

1.4
Summary and Discussion

The big message of this work is that we study and discover a new type of quantum advantage in cryptography.

Our result also leads to several open questions. For example:

•

There is an undesirable exponential blowup related to the approximation error (see Section
1.1.3
,
1.2.2
).

•

Our construction is not necessarily optimal in terms of number of rounds, assumptions, or the type of functions that it could support.

•

Another question that seems open is to give formal evidences that the problem that we consider is hard to construct in the classical world.

We also hope our construction could be useful in other problems, or could inspire the discovery of more quantum advantage in other problems.

3
Succinct RSPV for Classical Functions

In this section we formalize the notion of succinct RSPV for classical functions (SRC), and give the protocol and the theorems.

3.1
Definitions

As the preparation of definition we first discuss the modeling of protocols. A usual modeling is as follows.

Definition 3.1
.

A protocol is described by a sequence of executions of algorithms on two parties, a client and a server. The operations (that is, executions of algorithm) in a protocol could be in the following types:

•

The client does its local computations.

•

The client sends messages or states to the server.

•

The server does its local computations.

•

The server sends back messages to the client.

Finally the client decides whether to accept to reject.

In Section
3.1.1
we further discuss variants of protocol modeling, including the introduction of transcript registers.

Below we formalize the notion of SRC.

Definition 3.2

(Setting of SRC)
.

An SRC protocol is defined for a function family
f=(f_{n})_{n\in\bN}
,
f_{n}:\{0,1\}^{n}\rightarrow\{0,1\}^{m}
where
m=m(n)
is the output length. In the protocol there is a client and a server, and the protocol takes an input size
n
as its input; initially the description of a polynomial time classical Turing machine
T
that computes
f
is publicly available to both parties.

Definition 3.3

(Completeness of SRC)
.

An SRC protocol for
f
is complete with completeness error
c
if in the honest setting in the end of the protocol the joint state of the client and the server is
c
-close to the following: for input length
n
, the client gets
x\leftarrow_{r}\{0,1\}^{n}
, and the server gets the corresponding
f(x)
.

Definition 3.4

(Efficiency of SRC)
.

In an SRC protocol the honest behavior of both the client and the server should be in polynomial time and the communication should be in
{\mathsf{poly}}(n)
, independent to the running time of evaluating
f
.

As a preparation of SRC soundness definition, we introduce the following notation from
[
28
]
.

Notation 3.1
.

For a function
f
and input length
n
as defined in Definition
3.2
, using density operators, the target joint state between the client and the server is defined as

\sum_{x\in\{0,1\}^{n}}\frac{1}{{2^{n}}}\underbrace{\ket{x}\bra{x}}_{\text{client}}\otimes\underbrace{\ket{f(x)}\bra{f(x)}}_{\text{server}}

(13)

Note that in our problem the target state is a joint distribution that could be described classically on two parties.

Below we make the input size
n
implicit.

Below we give two slightly different definitions for the soundness of SRC. The first definition contains a soundness parameter
s
and an approximation error
\epsilon
. The second definition only has a parameter
\epsilon
. We will use the first definition as an intermediate definition in the construction later and consider the second definition as the final target.

Definition 3.5

(Soundness of SRC)
.

An SRC protocol for
f
has soundness

and approximation error
\epsilon
if for any polynomial time adversary
{\mathsf{Adv}}
there exists an efficiently computable server-side simulator
{\mathsf{Sim}}^{{\mathsf{Adv}}}
such that one of the following two is true:

•

(Small passing probability)

\tr(\Pi_{{\mathsf{pass}}}(\pi^{{\mathsf{Adv}}}(1^{n})))<s

•

(Simulation-based security)

\Pi_{{\mathsf{pass}}}(\pi^{{\mathsf{Adv}}}(1^{n}))\approx_{\epsilon}^{ind}\Pi_{{\mathsf{pass}}}({\mathsf{Sim}}^{{\mathsf{Adv}}}(\eqref{eq:tar11}))

Definition 3.6

(Soundness of SRC)
.

An SRC protocol for
f
is sound with approximation error
\epsilon
if for any polynomial time adversary
{\mathsf{Adv}}
there exists an efficiently computable server-side simulator
{\mathsf{Sim}}^{{\mathsf{Adv}}}
such that

\Pi_{{\mathsf{pass}}}(\pi^{{\mathsf{Adv}}}(1^{n}))\approx_{\epsilon}^{ind}\Pi_{{\mathsf{pass}}}({\mathsf{Sim}}^{{\mathsf{Adv}}}(\eqref{eq:tar11}))

We further clarify that the simulator is server-side while the distinguisher has access to both parties.

The time complexity and communication complexity are formalized as the usual definitions.

3.1.1
Different modelings of protocol and security

For simplicity of security analysis we consider the following variant of protocol modeling. We will introduce transcript registers to hold the classical transcripts generated by the protocol execution. Furthermore we purify the states appeared during the protocol so that we could work on Dirac symbols.

Definition 3.7
.

In our work, the protocol works between a client and a server. Furthermore, there are a series of message registers that stores classical messages between them (quantum states are transmitted directly). These message registers are read-only once a message is stored in them.

The operations in a protocol could be in the following types:

•

The client does its local computations.

•

The client sends messages or quantum states to the server. Messages are stored in the message register while quantum states are sent to an empty server-side register directly.

•

The server does its local computations; note that the server only has read-only access to the message registers.

•

The server sends back messages to the client (note that we only consider classical messages for this type. That is, in this type of operations, the server writes its computation result to an empty message register).

Finally the client decides whether to accept to reject. (That is, the client writes the flag of decision in a specific transcript register.)

This variant of modeling is equivalent to the modeling in Definition
3.1
. The classical client could always stores a copy of classical transcript during the protocol so any adversary in modeling
3.1
is no more powerful than the adversary in modeling
3.7
; the other direction also holds since the server could also keep a copy of classical transcripts.

We further purify the states appeared during the protocol and security analysis so that the symbols are easier to work on. Note that the cq-states (
13
) look the same as the state

\sum_{x\in\{0,1\}^{n}}\frac{1}{\sqrt{2^{n}}}\underbrace{\ket{x}}_{\text{client}}\otimes\underbrace{\ket{f(x)}}_{\text{server}}

(14)

in the view of distinguishers that only have classical access to the client-side register. Thus Definition
3.5
is equivalent to:

Definition 3.8

(Soundness of SRC)
.

An SRC protocol for
f
has soundness
s
and approximation error
\epsilon
if for any polynomial time adversary
{\mathsf{Adv}}
there exists an efficiently computable server-side simulator
{\mathsf{Sim}}^{{\mathsf{Adv}}}
such that one of the following two is true:

•

(Small passing probability)

\tr(\Pi_{{\mathsf{pass}}}(\pi^{{\mathsf{Adv}}}(1^{n})))<s

•

(Simulation-based security)

\Pi_{{\mathsf{pass}}}(\pi^{{\mathsf{Adv}}}(1^{n}))\approx_{\epsilon}^{ind}\Pi_{{\mathsf{pass}}}({\mathsf{Sim}}^{{\mathsf{Adv}}}(\eqref{eq:newtarre}))

where the distinguisher has classical access to the client and transcript and full access to the server.

Note the server-side simulator could also simulate the transcripts while the distinguisher only has classical access to the transcript registers.

Definition 3.9

(Setting and efficiency of SAoK)

A succinct argument of knowledge (SAoK) protocol takes a security parameter

(Post-quantum AoK knowledge extractability)

By Kilian’s protocol

.
