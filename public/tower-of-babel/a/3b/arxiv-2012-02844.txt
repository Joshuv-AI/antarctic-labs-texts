Polynomial-time trace reconstruction in the low deletion rate regime
Xi Chen, Anindya De, Chin Ho Lee, Rocco A. Servedio, Sandip Sinha

Abstract
In the trace reconstruction problem , an unknown source string x ∈ { 0 , 1 } n x\in\{0,1\}^{n} is transmitted through a probabilistic deletion channel which independently deletes each bit with some fixed probability δ \delta and concatenates the surviving bits, resulting in a trace of x x . The problem is to reconstruct x x given access to independent traces. Trace reconstruction of arbitrary (worst-case) strings is a challenging problem, with the current state of the art for poly ⁡ ( n ) \mathrm{poly}(n) -time algorithms being the 2004 algorithm of Batu et al. [ BKKM04 ] . This algorithm can reconstruct an arbitrary source string x ∈ { 0 , 1 } n x\in\{0,1\}^{n} in poly ⁡ ( n ) \mathrm{poly}(n) time provided that the deletion rate δ \delta satisfies δ ≤ n − ( 1 / 2 + ε ) \delta\leq n^{-(1/2+\varepsilon)} for some ε > 0 \varepsilon>0 . In this work we improve on the result of [ BKKM04 ] by giving a poly ⁡ ( n ) \mathrm{poly}(n) -time algorithm for trace reconstruction for any deletion rate δ ≤ n − ( 1 / 3 + ε ) \delta\leq n^{-(1/3+\varepsilon)} . Our algorithm works by alternating an alignment-based procedure, which we show effectively reconstructs portions of the source string that are not “highly repetitive”, with a novel procedure that efficiently determines the length of highly repetitive subwords of the source string.



1
Introduction

The
trace reconstruction
problem was proposed almost twenty years ago in works of
[
Lev01a
,
Lev01b
,
BKKM04
]
, though some earlier variants of the problem were already considered in the 1970s
[
Kal73
]
.
This problem deals with the
deletion channel
, which works as follows: when an
n
-bit string (the source string) is passed through a deletion channel of rate
\delta
, each coordinate is independently deleted with probability
\delta
.
The surviving
n^{\prime}\leq n
coordinates are concatenated to form the output of the channel, which is referred to as a
trace
of the original source string; we write “
\boldsymbol{z}\sim\mathrm{Del}_{\delta}(x)
” to indicate that
\boldsymbol{z}
is a trace generated from source string
x
according to this probabilistic process.
As discussed in
[
Mit09
]
, this channel provides an elegant formalization for the theoretical study of problems involving synchronization errors.

In the
trace reconstruction problem
, independent traces are generated from an unknown and arbitrary source string
x\in\{0,1\}^{n}
, and the task of the algorithm is to reconstruct (with high probability)
x
from its traces.
The trace reconstruction problem is motivated by applications in several domains, including sensor networks and biology
[
Mit09
,
ADHR12
,
YGM17
,
OAC+18
]
.
It is also attractive because it is a clean and natural “first problem” which already seems to capture much of the difficulty of dealing with the deletion channel.

The problem of trace reconstruction for an arbitrary (worst-case) source string
x
has proved to be quite challenging.
1
1

1

We note that the average-case problem, in which the reconstruction algorithm is only required to succeed for a
1-o(1)
fraction of all possible source strings in
\{0,1\}^{n}
, is much more tractable, with the current state of the art
[
HPP18
,
HPPZ20
]
being an algorithm that uses
\exp(O(\log^{1/3}n))
traces and runs in
\mathrm{poly}(n)
time for any deletion rate
\delta
that is bounded away from 1.

[
BKKM04
]
gave an algorithm that runs in
\mathrm{poly}(n)
time, uses
\mathrm{poly}(n)
traces, and with high probability reconstructs an arbitrary source string
x\in\{0,1\}^{n}
provided that the deletion rate
\delta
is at most
n^{-(1/2+\varepsilon)}
for some constant
\varepsilon>0
.
Unfortunately, the trace reconstruction problem seems to quickly become intractable at higher deletion rates. Holenstein et al.
[
HMPW08
]
gave an algorithm that runs in time
\exp(O(n^{1/2}))
and uses
\exp(O(n^{1/2}))
traces for any deletion rate
\delta
that is bounded away from 1 by a constant, and this result was subsequently improved in simultaneous and independent works by
[
DOS17
,
NP17
]
, both of which gave algorithms with time and sample complexity
\exp(O(n^{1/3})).
On the lower bounds side, for
\delta=\Theta(1)
successively stronger lower bounds on the required sample complexity were given by
[
MPV14
]
and
[
HL18
]
, with the current state of the art being a
\smash{\tilde{\Omega}(n^{3/2})}
lower bound due to Chase
[
Cha19
]
.

The low deletion rate regime.
The positive result of
[
DOS17
]
actually gives an algorithm that is faster than
\exp(O(n^{1/3}))
if the deletion rate is sufficiently low:
[
DOS17
]
shows that for
O(\log^{3}n)/n\leq\delta\leq 1/2
, their algorithm runs in time
\exp(O(\delta n)^{1/3})
. Consequently, for the specific deletion rate
\delta=n^{-(1/2+\varepsilon)}
, the
[
DOS17
]
algorithm runs in time essentially
\exp(O(n^{1/6}))
, and
[
DOS17
]
shows that no faster running time or better sample complexity is possible for any “mean-based” algorithm, a class of algorithms which includes those of
[
DOS17
,
NP17
,
HMPW08
]
.

Algorithmic approaches other than mean-based algorithms can provably do better at low deletion rates.
This is witnessed by the algorithm of Batu et al.
[
BKKM04
]
which, as described earlier, runs in
\mathrm{poly}(n)
time and uses
\mathrm{poly}(n)
samples at deletion rate
\delta=n^{-(1/2+\varepsilon)}
.
The main algorithmic component of
[
BKKM04
]
is a “
Bitwise Majority Alignment
” (
BMA
for short) procedure, which is further augmented with a simple procedure to determine the length of long “runs” (subwords of
x
of the form
0^{\ell}
or
1^{\ell}
with
\ell\geq\sqrt{n}
).
Roughly speaking, the
BMA
algorithm maintains a pointer in each trace and increments those pointers in successive time steps, attempting to always keep almost all of the pointers correctly aligned together.
The analysis of
[
BKKM04
]
shows that the
BMA
algorithm succeeds if the source string
x
does not contain any long runs, but a challenge for the
BMA
algorithm is that the pointers in different traces will inevitably become misaligned if
x
does contain a long run
0^{\ell}
or
1^{\ell}
; this is why the
[
BKKM04
]
algorithm must interleave
BMA
with a procedure to handle long runs separately.
Intuitively, deletion rate
\delta=n^{-1/2}
is a barrier for the
[
BKKM04
]
analysis because if
\delta=\omega(n^{-1/2})
, then each trace is likely to have multiple locations where more than one consecutive bit of
x
is “dropped,” which is problematic for the analysis of
BMA
given in
[
BKKM04
]
.

To summarize: given this state of the art from prior work, it is clear that alignment-based approaches can outperform mean-based algorithms at low deletion rates, but it is not clear whether, or how far, alignment-based approaches can be extended beyond the
[
BKKM04
]
results. Further incentive for studying the low deletion rate regime comes from potential applications in areas such as computer networks, where it may be natural to model deletions as occurring at relatively low rates. These considerations motivate the results of the present paper, which we now describe.

1.1
This work: An improved algorithm for the low deletion rate regime

The main result of this paper is an efficient algorithm that can handle significantly higher deletion rates than the
[
BKKM04
]
algorithm.
We prove the following:

Theorem 1

(Efficient trace reconstruction at deletion rate
\delta\geq n^{-(1/3+\varepsilon)}
)
.

Fix any constant
\varepsilon>0
and let
\delta=n^{-(1/3+\varepsilon)}.
There is an algorithm
Reconstruct
that uses
O(n^{4/3})

independent traces drawn from
\mathrm{Del}_{\delta}(x)

(
where
x\in\{0,1\}^{n}
is arbitrary and unknown to
Reconstruct
)
, runs in
O(n^{7/3})

time, and outputs the unknown source string
x
with probability at least
9/10
.

Note that any deletion rate
\delta<n^{-(1/3+\varepsilon)}
can of course be handled, given
Theorem

1
, by simply deleting additional bits to reduce to the
\delta=n^{-(1/3+\varepsilon)}
case.
Note further that any desired success probability
1-\kappa
can easily be achieved from
Theorem

1
by running
Reconstruct

O(\log(1/\kappa))
times and then taking a majority vote.

At a high level, the
Reconstruct
algorithm works by interleaving two different subroutines.

•

The first subroutine is (essentially) the
BMA
algorithm, for which we provide an improved analysis, showing that
BMA
successfully reconstructs any string that does not contain a long subword
(of length at least
M=2m+1
with
m=n^{1/3}
)
that is a prefix of
s^{\infty}
for some short (constant-length) bitstring
s
.
We refer to long and “highly-repetitive” subwords of
x
of this form
as “
s
-deserts
” of
x
; see
Definition

2
for a detailed definition.

•

The second subroutine is a new algorithm which we show efficiently
determines the length of an
s
-desert in the source string
x
.

Thus, two novel aspects of this work that go beyond
[
BKKM04
]
are (i) our improved analysis of
BMA
, and (ii) our new procedure for efficiently measuring deserts (the analogous component of the
[
BKKM04
]
algorithm could only measure runs, which correspond to
s
-deserts with
|s|=1
).

We believe that it may be possible to further extend the kind of “hybrid” approach that we employ in this paper to obtain efficient trace reconstruction algorithms that can handle even larger deletion rates
\delta
. However, there are some significant technical challenges that would need to be overcome in order to do so. We describe some of these challenges at the end of the next section, which gives a more detailed overview of our approach.

2
Overview of our approach

As alluded to in the introduction, at a high level our algorithm carries out a careful interleaving of two procedures, which we call
BMA
and
FindEnd
. In this section we first give a high-level overview of the procedure
BMA
as well as our improved analysis. Then we give a high-level overview of
FindEnd
, and finally we explain how these two procedures are interleaved. We close with a brief discussion of possibilities and barriers to further progress.

2.1
Overview of
BMA

The procedure
BMA
is exactly the same as the bitwise majority alignment algorithm of
[
BKKM04
]
; our new contribution regarding
BMA
is in giving a more general analysis. To explain the high level idea, let us fix the deletion rate
\delta=n^{-(1/3+\varepsilon)}
and a constant
C=

\lceil 100/\varepsilon\rceil
.
Let

m=n^{1/3}\quad\text{and}\quad M=2m+1.

The
BMA
procedure operates on a sample of some
N=O(\log n)
traces

\boldsymbol{y}^{1},\ldots,\boldsymbol{y}^{N}
drawn independently from
\mathrm{Del}_{\delta}(x)
before the procedure begins its execution. Note that for any
i\in[N]
and
any position
\ell
in the trace
\boldsymbol{y}^{i}
, there is a position
f_{i}(\ell)
satisfying
\ell\leq f_{i}(\ell)\leq n-1

in the target string
x=(x_{0},\dots,x_{n-1})
that maps to
\ell
under the deletion process.
2
2

2

It will be convenient for us to index a binary string
x\in\{0,1\}^{\ell}

using
[0:\ell-1]
as
x=(x_{0},\dots,x_{\ell-1})
.
The high level idea of
BMA
is to maintain pointers
\textnormal{current}_{1},\ldots,\textnormal{current}_{N}
,
with
\textnormal{current}_{i}
pointing to a position in
\boldsymbol{y}^{i}
,
such that
most of them are correctly aligned
— i.e., at the beginning of each time step
t
,

t=0,1,\ldots
, as we try to determine
x_{t}
,
we have
f_{i}(\textnormal{current}_{i})=t
for most
i\in[N]
. Note that if this alignment guarantee were to hold for more than half of the traces for all
t=0,1,\ldots,n-1
, then we could reconstruct the unknown string
x
by taking a majority vote of
\boldsymbol{y}^{i}_{\textnormal{current}_{i}}
in each time step.
Indeed we show that this happens with high probability over
the randomness of
\boldsymbol{y}^{1},\ldots,\boldsymbol{y}^{N}
when
x
does not contain an
s
-desert
for any string
s\in\{0,1\}^{\leq C}
(i.e. a subword of length at least
M=2m+1

that is a prefix of
s^{\infty}
).
In contrast, the analysis of
[
BKKM04
]
requires the deletion rate to be

n^{-(1/2+\varepsilon)}
but works as long as
x
does not contain a run of
0
’s or
1
’s
(or
s
-deserts with
|s|=1
in our notation)
of length at least
\sqrt{n}
.

To explain
BMA
in more detail, let us initialize
t=0
and pointers

\textnormal{current}_{1}(0),\ldots,\textnormal{current}_{N}(0)
to position
0
.
(Note that most pointers are correctly aligned as desired
given that
\delta=n^{-(1/3+\varepsilon)}
and thus,
x_{0}
is not deleted in most traces and
f_{i}(\textnormal{current}_{i}(0))=f_{i}(0)=0
for most

i
.)
The way the pointers are updated is as follows: At each time step
t
, we let
w_{t}
be the majority element of the
N
-element multiset
\smash{\{\boldsymbol{y}^{i}_{\textnormal{current}_{i}(t)}\}_{i\in[N]}}
.
For those traces
\boldsymbol{y}^{i}
with
\smash{\boldsymbol{y}^{i}_{\textnormal{current}_{i}(t)}=w_{t}}
(i.e., the bit of
\boldsymbol{y}^{i}
at the current pointer is the majority bit), we move the pointer to the right by
1
, i.e. we set
\textnormal{current}_{i}(t+1)\leftarrow\textnormal{current}_{i}(t)+1
; otherwise the
pointer stays the same, i.e., we set
\textnormal{current}_{i}(t+1)\leftarrow\textnormal{current}_{i}(t)
.
Next we increment
t
and start the next round, repeating until
t=n
when

BMA
outputs the string
(w_{0},\ldots,w_{n-1})
.

For intuition we observe that if most of the pointers were aligned at the beginning of time step
t
(i.e.,

f_{i}(\textnormal{current}_{i}(t))=t
for most
i\in[N]
), then
w_{t}=x_{t}
is indeed the next bit in
x
.
Moreover, if
\textnormal{current}_{i}(t)
is aligned and
w_{t}=x_{t}
, then
moving
\textnormal{current}_{i}
to the right by
1
is justified by noting that
most likely
x_{t+1}
is not deleted in
\boldsymbol{y}^{i}
(with probability
1-\delta
),
and when this happens

f_{i}(\textnormal{current}_{i}(t+1))=t+1

\textnormal{current}_{i}
remains aligned at the beginning of the next time step.

In more detail, our analysis shows that when
x
does not contain
an
s

s\in\{0,1\}^{\leq C}

maintains the following invariants at the beginning of time step

:

1.

At time
t
,
BMA
has reconstructed
x_{0},\ldots,x_{t-1}

correctly as
w_{0},\ldots,w_{t-1}
.

2.

For every trace
\boldsymbol{y}^{i}
,
i\in[N]
, it holds that
f_{i}(\textnormal{current}_{i}(t))\geq t
.

3.

Finally,
\sum_{i\in[N]}\big(f_{i}(\textnormal{current}_{i}(t))-t\big)\leq 2N/C
.

The intuitive meaning behind conditions (2) and (3) is as follows: while (2) says that the “original position” of
\textnormal{current}_{i}(t)
never falls behind
t

t
by too much. In fact, since
C
is a large constant, most of the pointers are perfectly aligned, i.e., they satisfy
f_{i}(\textnormal{current}_{i}(t))=t.

We now discuss how the invariants (1), (2) and (3) are maintained. First, we observe that invariant (1)
for time step
t+1
, i.e.,
w_{t}=x_{t}
, follows immediately from (3) at time step
t
.
Invariant (2) for time step
t+1
follows almost immediately from (2) at
t
and
w_{t}=x_{t}
.
(If
f_{i}(\textnormal{current}_{i}(t))>t
, then
f_{i}(\textnormal{current}_{i}(t+1))\geq f_{i}(\textnormal{current}_{i}(t))\geq t+1
given that both

f_{i}
and
\textnormal{current}_{i}
are nondecreasing; if
f_{i}(\textnormal{current}_{i}(t))=t
is aligned at time step
t
, then

w_{t}=x_{t}
implies
\textnormal{current}_{i}(t+1)=\textnormal{current}_{i}(t)+1
and thus,
f_{i}(\textnormal{current}_{i}(t+1))\geq t+1
.)
The main challenge is to show that invariant (3) is maintained.
While this is not true for a general string
x
, we show that this holds with high probability (over
\boldsymbol{y}^{1},\ldots,\boldsymbol{y}^{N}\sim\mathrm{Del}_{\delta}(x)
) for any string
x
which does not have an
s

s\in\{0,1\}^{\leq C}
.
(We note here that the value of
m
is selected so as to satisfy
m\delta\ll 1
; on the other hand, when we discuss the

m\gg\sqrt{\delta n}

In a nutshell, the main proof idea for (3) is to exploit the fact that when we draw

\boldsymbol{y}^{1},\ldots,\boldsymbol{y}^{N}\sim\mathrm{Del}_{\delta}(x)
, with high probability they satisfy two properties:
(i) for every
\boldsymbol{y}^{i}
and
every subword of roughly
C^{2}m
consecutive positions in the original string
x
, no more than
C
positions
within the subword are deleted in the generation of
\boldsymbol{y}^{i}
;
(ii) for every subword of roughly
m
consecutive positions in
x
,
the number of
\boldsymbol{y}^{i}
that have at least one deletion in the subword is no more than
N/C^{3}
.
These two properties can be shown using straightforward probabilistic arguments by taking advantage of the aforementioned

m\delta\ll 1
.
Using these two properties, a detailed (non-probabilistic) argument shows that
BMA
can reconstruct the string
x
with high probability if
x
contains no
s
-desert.

The above discussion sketches our argument
that if the target string
x
does not have an
s
-desert, then
BMA
correctly reconstructs
x
. More generally, our arguments show that if
x
does have an
s
-desert, then
BMA
correctly
reconstructs the prefix of
x
up to the position when an
s
-desert shows up:
Let
r
be
the first position in
x
that is
“
deep in an
s
-desert
”; this is the first position in
x
such that

x_{[r-m:r+m]}
3
3

3

For a string
x\in[0:n-1]
integers
0\leq a<b\leq n-1
, we write
x_{[a:b]}
to denote the
subword

(x_{a},x_{a+1},\dots,x_{b})
.
,
the length-

subword of
x

centered at
r
, is an
s
-desert. Then

BMA
correctly reconstructs the prefix of
x
up to position
r+m
.
Having reached such a position, it is natural to now ask — “how do we determine the
end
of this desert?”. This naturally leads us to the next procedure
FindEnd
.

2.2
Overview of
FindEnd

Suppose that
x
has an
s
-desert with
|s|=k\leq C
, so
BMA
reconstructs the length-
(r+m+1)
prefix of
x
,
where
r
is the first position that is “deep in the
s
-desert” (note that it is easy to determine the position
r
from the output of
BMA
). The algorithm
FindEnd
takes as input the prefix
x_{[0:r+m]}
of
x
and the location
r
,
and its task is to compute the end of the
s
-desert:
the first position
\textup{{end}}\geq r+m
such that

x_{\textup{{end}}+1}\neq x_{\textup{{end}}-k+1}
.
The
FindEnd
algorithm is rather involved but at a high level it consists of two
stages: an initial
coarse estimation

of the end of the desert followed by

alignments
of traces from
\mathrm{Del}_{\delta}(x)

with the end of the desert
(using the coarse estimate).

Coarse estimation:
The goal of the coarse estimation stage is to
identify an integer
\widehat{\beta}
that is close to
(1-\delta)\textup{{end}}
:

|\widehat{\beta}-(1-\delta)\textup{{end}}|\leq 2\sigma
, where
\sigma:=\tilde{O}(\sqrt{\delta n})\ll m

is basically how far an entry
x_{i}
of
x
can deviate from its expected location
(1-\delta)i
in a typical trace

\boldsymbol{y}\sim\mathrm{Del}_{\delta}(x)
.
Intuitively,
\widehat{\beta}
is an estimation of the location of
x_{\textup{{end}}}

in a trace
\boldsymbol{y}\sim\mathrm{Del}_{\delta}(x)
that contains it, i.e., when
x_{\textup{{end}}}
is not deleted in
\boldsymbol{y}
.
To do this, we draw
\alpha=O(1/\varepsilon)
many traces
\boldsymbol{y}^{1},\dots,\boldsymbol{y}^{\alpha}\sim\mathrm{Del}_{\delta}(x)
.
Roughly speaking, we split each trace
\boldsymbol{y}^{i}
into overlapping intervals of length
4\sigma
.
The first interval starts at
(1-\delta)r
and each successive interval shifts to the right by
\sigma
(so it
overlaps with the previous interval by
3\sigma
).
Since
m\gg\sigma=\tilde{O}(\sqrt{\delta n})
(which is
one of the bottlenecks that requires
\delta\ll n^{-1/3}
),
the
s
-desert is unlikely to end before
(1-\delta)r
in a trace
\boldsymbol{y}\sim\mathrm{Del}_{\delta}(x)

and must end in one of constantly many
intervals with high probability, by the choice of
\sigma
.
To identify one such interval, we make the following observation.
Let
\textup{{Cyc}}_{s}
be the set of all
k
-bit strings that can be obtained as cyclic shifts of
s
.
Given
end
as the end of the
s
-desert that starts
at
x_{r-m}
, every
k
-bit subword of
x_{[r-m:\textup{{end}}]}
is in
\textup{{Cyc}}_{s}

but
(x_{\textup{{end}}-k+2},\ldots,x_{\textup{{end}}+1})\notin\textup{{Cyc}}_{s}
, and these
k\leq C
bits
will most likely remain in a trace given the low deletion rate.
This motivates us to look for the leftmost interval
I^{*}
such that in at least half of
\boldsymbol{y}^{1},\dots,\boldsymbol{y}^{\alpha}
, it holds that
\boldsymbol{y}^{i}_{I^{*}}
contains a
k
-bit subword not in
\textup{{Cyc}}_{s}
.
We show that with high probability, setting
\smash{\widehat{\beta}}
to be
the right endpoint of
I^{*}
gives us
a coarse estimate of
(1-\delta)\textup{{end}}
up to an accuracy of
\pm 2\sigma
.

In addition to obtaining
\widehat{\beta}
,
the coarse estimation stage recovers the following
8\sigma
-bit subword of
x
:

(x_{\textup{{end}}-k+2},\ldots,x_{\textup{{end}}-k+8\sigma+1})
, which we will refer to as the

of the
s
-desert and denote by
\textup{{tail}}\in\{0,1\}^{8\sigma}
.
To this end, we draw another
\alpha=O(1/\varepsilon)
fresh traces
\boldsymbol{y}^{1},\ldots,\boldsymbol{y}^{\alpha}
and examine
the subword of each
\boldsymbol{y}^{i}
of length
6\sigma
centered at location
\widehat{\beta}
.
Each
\boldsymbol{y}^{i}
looks for the first
k
-bit subword in this interval that is not in
\textup{{Cyc}}_{s}

and votes for its
8\sigma
-bit subword that starts at this non-cyclic shift as its candidate for
tail
.
We show that with high probability, the string with the highest votes is exactly
tail
.
(We note that both parts of this coarse estimation procedure require that with high probability, any fixed interval of length
O(\sigma)
in
x
does not get any deletions in a random trace, i.e.,
\sigma\delta\ll 1
. This follows from the two
constraints
m\delta\ll 1
and
m\gg\sigma
.)

Alignments:

Suppose the first stage succeeds in computing
\widehat{\beta}
and
\textup{{tail}}\in\{0,1\}^{8\sigma}
.
The second stage is based on a procedure called
Align

which satisfies two crucial criteria. These criteria are as follows: if
Align
is given an input trace
\boldsymbol{y}\sim\mathrm{Del}_{\delta}(x)
, then (a) with
fairly high
probability (by which we mean

for the rest of the overview) it returns a location
\ell
in
\boldsymbol{y}
such that

\boldsymbol{y}_{\ell}
corresponds to

x_{\textup{{end}}}
in
x
, and moreover (b) the expectation of
\ell
(over the randomness of
\boldsymbol{y}
) is a “sharp estimate” of
(1-\delta)\textup{{end}}

that is accurate up to an additive
\pm 0.1
error.
4
4

4

1/n^{\Theta(\varepsilon)}
, but if when

2.3
The overall algorithm

The overall algorithm works by alternately running

and

and returns

Then the algorithm runs

Note that the execution of

will misalign some small fraction of the traces it uses, but these errors do not affect

as

With

Next the algorithm runs

N

of

Let

2.4
Discussion

We believe that it may be possible to improve on our algorithmic results (specifically, to handle larger
1/\mathrm{poly}(n)
deletion rates) by refining our basic approach of alternating between successively (i) exactly inferring non-desert subwords of the string (as currently done by
BMA
), and (ii) exactly computing the length of the intervening deserts
(as currently done by
FindEnd
).
However, some nontrivial obstacles are encountered in attempting to go beyond
\delta=n^{-1/3}
to improve the current result, which we now briefly discuss.

Roughly speaking, our algorithm takes advantage of the fact that with
\delta=n^{-(1/3+\varepsilon)}
, we have
\sqrt{\delta n}\ll 1/\delta
and as a result it is easy to come up with the initial “coarse estimate” of the right end of a particular desert given fresh traces as the input to
FindEnd
. If
\delta=n^{-(1/3-\varepsilon)}
then we have
\sqrt{\delta n}\gg 1/\delta
and it is not clear how a procedure like
FindEnd
can reliably find any location within a particular desert of interest given fresh traces (which seems to be a prerequisite to performing “coarse estimation”).
One possible way around this is to not draw fresh traces at the start of each execution of
FindEnd
, but if the same traces are used for repeated runs of both
BMA
and

FindEnd
then it is not clear how to prevent alignment errors from accumulating, and such accumulated errors seem problematic for running
FindEnd
successfully. A natural approach to pursue along these lines is to develop an improved version of
FindEnd
which can handle some substantial number of “misaligned” or “adversarial” input traces; this is an interesting direction for future work.

then we have

Proof.

Let

\textnormal{current}_{i}(t-M)

Since the pointer into the

\textnormal{current}_{i}(t)\leq\textnormal{current}_{i}(t-M)+M

Having

\textup{{position}}_{i}(t)<\textup{{position}}_{i}(t-M)+M

, which violates

\textnormal{current}_{i}(t)=\textnormal{current}_{i}(t-M)+M

In order to have

,
we must have

\textnormal{current}_{i}(t-M+\ell)=\textnormal{current}_{i}(t-M)+\ell

for every

(again because the

By the second part of
8
and the assumption that
w_{[0:t-1]}=x^{\prime}_{[0:t-1]}
, this implies that

x^{\prime}_{t-M+\ell-1}=x^{\prime}_{\textup{{position}}_{i}(t-M+\ell-1)}=x^{\prime}_{t-M+\ell-1+k}

for all
\ell\in[M]
.
Thus, the substring of

starting at

and ending
at

is a desert of length

with a pattern of length

. However, this contradicts with the choice of

and the fact that

; this contradiction concludes the proof.
∎

Finally we use the two previous lemmas to show that if

must lie between

and

Intuitively, this says that prior to a desert, the alignment of a trace will be at worst modestly ahead of where it should be.

Lemma 12
.

Let
t\leq r^{\prime}+m+1
and suppose that
w_{[0:t-1]}=x^{\prime}_{[0:t-1]}
.
Then
\textup{{distance}}_{i}(t)\leq C
for all

.

Proof.

Assuming for a contradiction that
\textup{{distance}}_{i}(t)>C
, we write

to denote the smallest

\textup{{distance}}_{i}(t^{*})>C
(so
\textup{{distance}}_{i}(t^{\prime})\leq C

First we claim that we must have
\textup{{position}}_{i}(t^{*})>L_{1}
(recall that

).
By part (i) of
Definition

6
, there are no more than
C
deletions in

within the interval of

\textup{{distance}}_{i}(t^{\prime})\leq C
for

So we assume below that
\textup{{position}}_{i}(t^{*})>L_{1}

To derive a contradiction,

.
By the first condition in

.
So it follows from the pigeonhole principle and the choice of

that there must be a interval

of length

(so
\textup{{right}}=\textup{{left}}+CM-1
)
inside

.
Let

be the integer such that
\textup{{position}}_{i}(t^{\prime})=\textup{{left}}
.
Since
\textup{{position}}_{i}(t^{\prime})<\textup{{position}}_{i}(t^{*})
, we have

, and hence
\textup{{distance}}_{i}(t^{\prime})\leq C
by the choice of

.
We also have

[\textup{{position}}_{i}(t^{\prime}+\ell M):\textup{{position}}_{i}(t^{\prime}+\ell M)+M-1]\cap D_{i}=\emptyset
for each

As a result, for each

\textup{{distance}}_{i}(t^{\prime}+\ell M)=0

\textup{{distance}}_{i}(t^{\prime}+\ell M)>0
and
\textup{{distance}}_{i}(t^{\prime}+(\ell+1)M)

This implies
\textup{{distance}}_{i}(t^{\prime}+CM)=0

Note that
\textup{{position}}_{i}(t^{\prime}+CM)\leq\textup{{position}}_{i}(t^{\prime})+CM\leq\textup{{position}}_{i}(t^{*})

It follows that

.

We prove by induction that for every positive integer

:

w_{[0:t-1]}=x^{\prime}_{[0:t-1]}\quad\text{and}\quad\sum_{i\in[R]}\textup{{distance}}_{i}(t)\leq\frac{2R}{C}.

(1)

It follows that every

For the inductive step we consider

such that

Given

To conclude the proof it remains to bound

with

for each

.
Note that by

Recall that by item (ii) of

of the

To conclude the proof of

Appendix A
Preprocessing the string

In this section, we prove the following simple lemma (recall

) which shows that given traces from

Proof.

The algorithm chooses the string
v
to be a random string of length
n/2
. Items 1 and 2 easily follow from the fact that a sample from
\mathrm{Del}_{\delta}(z)
can be generated by sampling
\boldsymbol{y}\sim\mathrm{Del}_{\delta}(x)

\boldsymbol{y}^{\prime}\sim\mathrm{Del}_{\delta}(v)

s
