Near-Optimal Deterministic Vertex-Failure Connectivity Oracles
Yaowei Long, Thatchaphol Saranurak

Abstract
We revisit the vertex-failure connectivity oracle problem [ DP10 , BPWN12 , DP20 ] . This is one of the most basic graph data structure problems under vertex updates , yet its complexity is still not well-understood. We essentially settle the complexity of this problem by showing a new data structure whose space, preprocessing time, update time, and query time are simultaneously optimal up to sub-polynomial factors assuming popular conjectures. Moreover, the data structure is deterministic. More precisely, for any integer d ⋆ d_{\star} , the data structure preprocesses a graph G G with n n vertices and m m edges in O ^ ​ ( m ​ d ⋆ ) \hat{O}(md_{\star}) time and uses O ~ ​ ( min ⁡ { m , n ​ d ⋆ } ) \tilde{O}(\min\{m,nd_{\star}\}) space. Then, given the vertex set D D to be deleted where | D | = d ≤ d ⋆ |D|=d\leq d_{\star} , it takes O ^ ​ ( d 2 ) \hat{O}(d^{2}) updates time. Finally, given any vertex pair ( u , v ) (u,v) , it checks if u u and v v are connected in G ∖ D G\setminus D in O ⁡ ( d ) O(d) time. This improves the previously best deterministic algorithm by Duan and Pettie [ DP20 ] in both space and update time by a factor of d d . It also significantly speeds up the Ω ⁡ ( min ⁡ { m ​ n , n ω } ) \Omega(\min\{mn,n^{\omega}\}) preprocessing time of all known (even randomized) algorithms with update time at most O ~ ​ ( d 5 ) \tilde{O}(d^{5}) .

Technical Highlights.

The technical novelty of this paper lies in the new oracle from
Theorem

1.1

with two parts to be highlighted.

First, we give a
\hat{O}(m)
-time algorithm for computing the
low-degree
hierarchy
of
[
DP20
]
. This step previously requires

O(mn\log n)
time in the preprocessing algorithm by Duan and Pettie

[
DP20
]
and it was their bottleneck. This new
algorithm then leads to faster preprocessing time. Actually, similar hierarchies are the key structures behind most vertex-failure
oracles (for the connectivity problem
[
DP10
]

and for the shortest path problem
[
DGR21
]
) Our
construction is based on expander decomposition, which is very versatile,
and so we expect that the approach can be adapted to solves more problems
under vertex failures.

Towards our construction, we give the first almost-linear-time algorithm for computing
vertex-expander decomposition
.
Given that in the last decade numerous fast graph algorithms are based on edge-expander decomposition (see e.g.
[
ST04
,
KLOS14
,
RST14
,
NSWN17
,
CDK+21
]
), our fast vertex-expander decomposition will likely very useful.
To facilitate future applications, we show a general decomposition that works even for general vertex weights and demands. We even generalize the technique to obtain hypergraph-expander decomposition. See
2.3
for the basic version,
Theorem

4.3
for the weighted version and
Theorem

C.3
for the hypergraph version.

Second, given a near-optimal low degree hierarchy, the main challenge
is designing an oracle with small space and update time based on it.
There were two previous solutions by Duan and Pettie
[
DP20
]
:
(1) a randomized Monte-Carlo near-optimal algorithm with
\tilde{O}(m)

space and
\tilde{O}(d^{2})
update time, and (2) a deterministic algorithm
with
\tilde{O}(md_{\star})
space and
\tilde{O}(d^{3})
update time. We
show how to achieve the best of both, near-optimal and deterministic. The techniques we developed can be interpreted as a deterministic
repairable hypergraph-to-graph connectivity-sparsifer
which transforms a hypergraph to a graph with the same vertex set and almost preserves pairwise connectivity in the vertex-failure setting. Actually, the sparsifer is somewhat stronger because it preserves the connectivity of each hyperedge individually. Thus we expect that this tool can have applications on other vertex-failures problem. See the discussion at the very end of
Section

2.2
for details.

[
BPWN12
]
.

Optimal Deterministic Oracles

Next, we give an overview how to obtain a vertex-failure oracle with
near-optimal space and update time. (Achieving near optimal preprocessing
and query time is relatively simpler.) This part is discussed in
Section

6
and
Section

7
in details. We will start by describing
the previous deterministic construction with
\tilde{O}(md)
space and

\tilde{O}(d^{3})
update time of
[
DP20
]
. Then,
we show how to improve either space or update time individually. Obtaining
both improvement simultaneously turn out to be challenging. This is
the most technically involved step of this part and we will sketch
the idea at the end of the overview.

Throughout this overview, we will assume that the input graph
G=(L,R,E)

is a semi-bipartite graph (i.e. there is no edge between
R
). Moreover,

L
is spanned by a path
\tau
and
\tau
is given to us. This
restricted structure of
G
will allows us to explain the key ideas
more clearly. Actually, as mentioned in
Section

2.1
,
the low-degree hierarchy “almost” allows us to reduce the problem
to this case. So this assumption is almost without lost of generality.

To simplify notations, assume further that
|L|=|R|=n
and the vertex
set
D
to be deleted always contains
d
vertices from
L
, denoted
by
D_{L}
, and
d
vertices from
R
, denoted by
D_{R}
.
In the updated graph
G\setminus D
, the path
\tau
will be split
into
d+1
connected intervals, denoted by
\mathcal{I}=I_{1},\dots,I_{d+1}
.
We call each interval
I\in\mathcal{I}
a
left interval
(or simply an
interval
) and each vertex

v\in R
a
right vertex
. Sometimes, we use
\gamma
to denote
a right vertex, to make it consistent with the main body of the paper.
Let
A_{\gamma}\subseteq L
denote the ordered set of vertices adjacent to
\gamma
with order consistent with the path
\tau
.

To support connectivity queries in
O(d)
time, given the set
D
,
it suffices (as shown in
[
DP10
,
DP20
]
)
to compute connectivity between the left intervals
\mathcal{I}
in
G\setminus D
,
i.e., whether
I
and
I^{\prime}
are in the same connected components
of
G\setminus D
for every
I,I^{\prime}\in\mathcal{I}
. Suppose the query is
(u,v)
.
In the easy case when both
u,v\in L
, we just identify the intervals

I
containing
u
and
I^{\prime}
containing
v
in
O(1)
time and
answer if
I
and
I^{\prime}
are connected in
G\setminus D
in
O(1)
.
Now, even if
u\in R
, we can identity a non-deleted neighbor
u^{\prime}

of
u
in
O(d)
time as there are only
O(d)
deleted vertices.
Note that
u^{\prime}\in L
and, say,
u^{\prime}\in I
. If
v\in R
, then we similarly
find a neighbor
v^{\prime}\in L
of
v
in
O(d)
time, and say
v^{\prime}\in I^{\prime}
.
Finally, we answer if
I
and
I^{\prime}
are connected in
G\setminus D
.
The total query time is
O(d)
time.

From now, we discuss how to preprocess
G
using small space so that,
given
D
, we can compute the connectivity between the left intervals

\mathcal{I}
in
G\setminus D
fast. Below, for any set
L^{\prime},L^{\prime\prime}\subset L

on the left, we say that
L^{\prime}
and
L^{\prime\prime}
are
adjacent
in
G

if there exists an edge
(u,v)\in L\times L^{\prime\prime}
or there exists a
right vertex
\gamma
adjacent to both vertices in
L^{\prime}
and
L^{\prime\prime}
.
We say that
L^{\prime}
and
L^{\prime\prime}
are
adjacent via
(u,v)
in the
former case and
adjacent via
\gamma

in the latter case.

The bounds discussed below will be slightly better than our final
bounds for general graphs. More precisely, we will pay an additional

n^{o(1)}
factor in update time and
\omega(1)
-factor in space
when apply the ideas together with the low-degree hierarchy.

2.2.1
Warming-up: No right vertices.

To motivate the idea, consider the extremely simple case when
R=\emptyset
.
We will show a data structure with
O(m)
space and
\tilde{O}(d^{2})

update time. In this case, the whole edge set
E(G)
can be represented
in a 2-dimentional table
\mathsf{Table}=[L]\times[L]
where the entry
(u,v)

is the number of (multi-)edges between
u
and
v
. Hence, during
preprocessing we can build a range counting data structure on this
table, which takes
O(|E(G)|)=O(m)
space. Given the deletion set

D
and so the left intervals
\mathcal{I}
are defined, we can check if

I
and
I^{\prime}
are adjacent in
G\setminus D
by querying the range
counting data structure in
\tilde{O}(1)
time if

|E(G)\cap(I\times I^{\prime})|>0.

By querying between all pairs
I,I^{\prime}\in\mathcal{I}
, we deduce the connected
components of
\mathcal{I}
in
\tilde{O}(d^{2})
time.

2.2.2
Deterministic Construction of
[
DP20
]
:
\tilde{O}(md)

space and
\tilde{O}(d^{3})
update time.

We first describe the deterministic construction of
[
DP20
]
that uses
\tilde{O}(md)
space and
\tilde{O}(d^{3})
update time. We view the high-level idea of
[
DP20
]
for handling
right vertices as follows: Construct a
restricted
(multi-)graph

\hat{G}
whose vertex set only contains
V(\hat{G})=L
, but
\hat{G}

should captures connectivity between left vertices of
G

even
after vertex deletions
. Since
\hat{G}
contains only left vertices,
we can use the range counting idea on
\hat{G}
.

Here is a natural way to construct
\hat{G}
. Starting with
\hat{G}=G[L]
, for each right vertex
\gamma\in R
, add a
(d+1)
-vertex connected graph on its neighbors
A_{\gamma}\subseteq L
(or a clique if
|A_{\gamma}|\leq d
), in which the edges are called the
artificial edges
of
\gamma
, denoted by
\hat{E}_{\gamma}
. Specially, we define
\hat{E}_{\gamma}=A_{\gamma}\times B_{\gamma}
, where
B_{\gamma}\subseteq A_{\gamma}
is an arbitrary subset of size
\min\{|A_{\gamma}|,d+1\}
.
8
8

8

We note that the deterministic construction in
[
DP20
]
did not define
\hat{E}_{\gamma}
as a product set
A_{\gamma}\times B_{\gamma}
, but their
\hat{E}_{\gamma}
still forms a
\min\{|A_{\gamma},d+1|\}
-connected graph on
A_{\gamma}
. Our product-set construction will be crucial for faster update time as will be explained in
Section

2.2.3
.
Observe that
\hat{E}_{\gamma}
spans
A_{\gamma}
with the following

fault-tolerant
property: for any
D_{L}\subseteq L
,
A_{\gamma}\setminus D_{L}

(which are obliviously connected in
G\setminus D_{L}
via
\gamma
)
are still connected in
\hat{G}\setminus D_{L}
. It follows that, for
any deleted set
D=D_{L}\cup D_{R}
, the graph
\hat{G}_{D}:=\hat{G}\setminus(D_{L}\cup\bigcup_{\gamma\in D_{R}}\hat{E}_{\gamma})

preserves connectivity between all left vertices of
G\setminus D

and, in particular, between all left intervals
\mathcal{I}
. So it suffices
to computed components of
\mathcal{I}
in
\hat{G}_{D}
. We can query if
I
and
I^{\prime}
are adjacent in
\hat{G}_{D}
by checking
if

|E(\hat{G})\cap(I\times I^{\prime})|-\sum_{\gamma\in D_{R}}|\hat{E}_{\gamma}\cap(I\times I^{\prime})|>0,

which can be computed using
1+|D_{R}|=O(d)
range queries. By querying
all pairs, the connected components of
\mathcal{I}
in
\hat{G}_{D}
can be
deduced in
\tilde{O}(d^{3})
time as desired. The total space for range counting structures on
E(\hat{G})
and all
\hat{E}_{\gamma}
is
\tilde{O}(|E(\hat{G})|+\sum_{\gamma}|\hat{E}_{\gamma}|)=\tilde{O}(|E(G)|+\sum_{\gamma}|A_{\gamma}|d)=\tilde{O}(md)
.

2.2.3
Update-Time Improvement:
\tilde{O}(md)
space and
\tilde{O}(d^{2})

update time.

Then we will show how to deterministically improve the update time to
\tilde{O}(d^{2})
. To improve the update time to
\tilde{O}(d^{2})
, the high-level idea is that we want to avoid querying for all
O(d^{2})

pairs of left intervals
I,I^{\prime}\in\mathcal{I}
.
We will use a Bor
\mathring{\text{u}}
vka’s based algorithm instead, which can reduce the number
of queries to
\tilde{O}(d)
. However, the queries become more complicated.

Recall that Bor
\mathring{\text{u}}
vka’s algorithm uses the “hook and merge” approach. There are
O(\log|{\cal I}|)
phases. In each phase there has already been a partition of intervals
{\cal I}
into groups
Z_{1},...,Z_{z}
such that intervals in a same group are in a same connected component. In this phase, these groups will be further merged by looking for an adjacent group for each
Z_{k}
9
9

9

Namely, find another group
Z_{k^{\prime}}
such that some
I^{\prime}\in Z_{k^{\prime}}
and some
I\in Z_{k}
are adjacent.
, which can be reduced to some
batched-adjacency queries
: given
Z_{k}
and a batch of groups
Z_{l},Z_{l+1},...,Z_{r}
, is there any group in this batch adjacent to
Z_{k}
? This query can be answered by checking if

\sum_{I\in Z_{k}}\sum_{I^{\prime}\in Z_{l,r}}|E(\hat{G})\cap(I\times I^{\prime})|-\sum_{\gamma\in D_{R}}\sum_{I\in Z_{k}}\sum_{I^{\prime}\in Z_{l,r}}|\hat{E}_{\gamma}\cap(I\times I^{\prime})|>0,

(1)

where
Z_{l,r}=\bigcup_{l\leq k^{\prime}\leq r}Z_{k^{\prime}}
. By further exploiting the fact that each
\hat{E}_{\gamma}
is a product set
A_{\gamma}\times B_{\gamma}
, Inequality (
1
) is equivalent to

\sum_{I\in Z_{k}}\sum_{I^{\prime}\in Z_{l,r}}|E(\hat{G})\cap(I\times I^{\prime})|-\sum_{\gamma\in D_{R}}\left(\sum_{I\in Z_{k}}|A_{\gamma}\cap I|\cdot\sum_{I^{\prime}\in Z_{l,r}}|B_{\gamma}\cap I^{\prime}|\right)>0.

The key to fast update time is the following. We arrange intervals in an ordered list
{\cal I}_{t}
(
t
denotes the phase number) such that
{\cal I}_{t}
is the concatenation of
Z_{1},...,Z_{z}
.
Now, by preprocessing a 2D-counting table
\mathsf{Table}_{t}=\{|E(\hat{G})\cap(I\times I^{\prime})|\}_{I\times I^{\prime}\in{\cal I}_{t}\times{\cal I}_{t}}
with size
|{\cal I}|^{2}
, the first term can be answered by a single 2D-range counting query on
\mathsf{Table}_{t}
.
Next, by preprocessing, for each
\gamma\in D_{R}
, a 1D counting array
\textsf{A-Array}_{\gamma,t}=\{|A_{\gamma}\cap I|\}_{I\in{\cal I}_{t}}
and another 1D array
\textsf{B-Array}_{\gamma,t}=\{|B_{\gamma}\cap I|\}_{I\in{\cal I}_{t}}
, the second term can be answered using
2|D_{R}|
queries to these arrays
\textsf{A-Array}_{\gamma,t}
and
\textsf{B-Array}_{\gamma,t}
.
Therefore, the query time for each batched-adjacency query is
\tilde{O}(d)
.
For each phase, we make
\tilde{O}(d)
such queries which take
\tilde{O}(d^{2})
total query time.
Notice that since the ordered list
{\cal I}_{t}
will be shuffled between phases,

\mathsf{Table}_{t},\textsf{A-Array}_{\gamma,t}
and
\textsf{B-Array}_{\gamma,t}
must be rebuilt at the beginning of each phase. But this takes
\tilde{O}(d^{2})
total time. Over all
O(\log|\cal{I}|)
phases, the total update time is
\tilde{O}(d^{2})
.

We emphasize that this approach highly relies on that each
\hat{E}_{\gamma}
is a product set
A_{\gamma}\times B_{\gamma}
, which enables us to consider two dimensions separately. If
\hat{E}_{\gamma}
is less structured, a 2D counting table is required for each
\gamma\in D_{R}
in this approach, and we cannot afford to construct them in
\tilde{O}(d^{2})
update time. The space is still
O(md)
as shown above. Note that this is an inherent limitation of this approach. As long as
\hat{E}_{\gamma}

forms
\min\{|A_{\gamma}|,d+1\}
-connected graph on
A_{\gamma}
, we will have space
\Omega(md)
in the worst case.

2.2.4
Space Improvement:
O(m)
space and
\tilde{O}(d^{3})
update
time.

Now, we will improve the space to
O(m)
, but it will bring the update time back to
\tilde{O}(d^{3})
. This step already gives the first deterministic oracle with
near-linear space. The high-level idea is to relax the fault-tolerant property in order to get sparser artificial edges. Concretely, it is acceptable that, for some right vertices
\gamma
, its artificial edges
\hat{E}_{\gamma}
do not satisfy the fault-tolerant property, but we want the number of such vertices to be small so we can afford to “repair” their
\hat{E}_{\gamma}
in an additional
repairing phase
of the update algorithm. We note that the Monte Carlo construction in
[
DP20
]
also takes advantage of a similar relaxation.

Towards this goal, let
\hat{E}=\bigcup_{\gamma\in R}\hat{E}_{\gamma}
contains all artificial edges.
We will redefine the artificial edges
\hat{E}_{\gamma}

of
\gamma
so that the total number of artificial edges
not counting multiplicity
, denoted by
\|\hat{E}\|_{0}
, is linear to
\sum_{\gamma\in R}|A_{\gamma}|=O(m)
. The construction
works by scanning through right vertices
\gamma\in R
one by one.
Initialize
\hat{E}=\emptyset
. Then, for each
\gamma
, if
(u,v)\in\hat{E}

for all
(u,v)\in A_{\gamma}\times B_{\gamma}
(as before
B_{\gamma}\subseteq A_{\gamma}
is an arbitrary subset with size
\min\{|A_{\gamma}|,d+1\}
), then define
\hat{E}_{\gamma}=A_{\gamma}\times B_{\gamma}
. Otherwise,
if there exists
(u_{\gamma},v_{\gamma})\notin\hat{E}
where
u_{\gamma},v_{\gamma}\in A_{\gamma}
,
then set
\hat{E}_{\gamma}=A_{\gamma}\times\{u_{\gamma},v_{\gamma}\}
. Lastly, we insert
\hat{E}_{\gamma}
into
\hat{E}
and proceed to the next right vertex.
Note that although
\sum_{\gamma\in R}|\hat{E}_{\gamma}|
can be large,
\|\hat{E}\|_{0}
is bounded by the number of new artificial edges added in each round. Since there is no new edge in the former case, it follows that
\|\hat{E}\|_{0}=\sum_{\gamma\in R}|A_{\gamma}|=O(m)
.

We then show there are only a few
\hat{E}_{\gamma}
without the fault-tolerant property. Let
R_{\mathrm{fault}}
contain all
\gamma
where
D_{L}
contains both
u_{\gamma}
and
v_{\gamma}
. Observe that
A_{\gamma}\setminus D_{L}

is not connected by
\hat{E}_{\gamma}\setminus D_{L}

only if
\gamma\in R_{\mathrm{fault}}
. As

D_{L}
contains at most
|D_{L}|^{2}
different pairs of vertices,
so
|R_{\mathrm{fault}}|\leq|D_{L}|^{2}=O(d^{2})
. Therefore, we have that
the graph
\hat{G}_{D}:=\hat{G}\setminus(D_{L}\cup\bigcup_{\gamma\in D_{R}}\hat{E}_{\gamma})

still preserves preserves connectivity between all left intervals
of
G\setminus D
, except that it might miss the connectivity information
from each
\gamma\in R_{\mathrm{fault}}
.

To compute the connected components of
\mathcal{I}
in
G\setminus D
, we
fist compute connected components of
\mathcal{I}
in
\hat{G}_{D}
. This can
be done in
\tilde{O}(d^{2})
time as in
Section

2.2.3
. But then some connected components
\mathcal{I}

in
\hat{G}_{D}
may be further connected via
\gamma\in R_{\mathrm{fault}}
.
Therefore, we add a
reparing phase
in the update algorithm. For every
I\in\mathcal{I}

and
\gamma\in R_{\mathrm{fault}}
, we simply check
I\cap A_{\gamma}\neq\emptyset
. If there is some
I,I^{\prime}\in{\cal I}
and
\gamma\in R_{\mathrm{fault}}
such that
I\cap A_{\gamma}\neq\emptyset

and
I^{\prime}\cap A_{\gamma}\neq\emptyset
, then the connected components of

I
and
I^{\prime}
can be merged as
I
and
I^{\prime}
are adjacent via
\gamma
. After these queries, we can finally deduce
connected components of
\mathcal{I}
in
G\setminus D
. We can check
if
I\cap A_{\gamma}\neq\emptyset
in
\tilde{O}(1)
time.
However, there are
O(d^{3})
pairs of
I,I^{\prime}\in\mathcal{I}
and
\gamma\in R_{\mathrm{fault}}
, the repairing phase needs
\tilde{O}(d^{3})
time.

Therefore, we obtain an oracle with
O(m)
space and
\tilde{O}(d^{3})
update time.

2.2.5
Repairing-Time Improvement:
\tilde{O}(d^{3})
update time with
\tilde{O}(d^{2})
repairing time

As a prerequisite to our final construction in
Section

2.2.6
, here we will improve the running time of the repairing phase from
\tilde{O}(d^{3})
to
\tilde{O}(d^{2})
. However, the total update time would still be
\tilde{O}(d^{3})
.
because our artificial edges
\hat{E}_{\gamma}
in this step will not be well-structured and so we cannot apply the Bor
\mathring{\text{u}}
vka’s based algorithm for interval connectivity as we did in
Section

2.2.3
. We will sketch how to handle this issue in
Section

2.2.6
.

The high-level idea is to redesign the artificial edges
\hat{E}_{\gamma}
for each
\gamma\in R
, such that for any failure set
D
, vertices in
A_{\gamma}\setminus D_{L}
may not be connected by
\hat{E}_{\gamma}\setminus D_{L}
itself, but they will be connected by
(\hat{E}_{\gamma}\cup\hat{F}_{\gamma})\setminus D_{L}
, where
\hat{F}_{\gamma}
is a small set of
D
-repairing edges
generated after
D
is deleted. In fact, in our following construction, the total number of
D
-repairing edges for all
\gamma
is bounded by
O(d^{2})
. Therefore, the repairing phase only needs to add the connectivity provided by these repairing edges and it takes
\tilde{O}(d^{2})
time.

We introduce a new structure called the
segmentation hierarchy
. For each
\gamma\in R
, the segmentation hierarchy
{\cal S}_{\gamma}
is simply a recursive division of
A_{\gamma}
like a segment tree. The elements of
{\cal S}_{\gamma}
are
segments
, which are consecutive sublists of
A_{\gamma}
.
{\cal S}_{\gamma}
is partitioned into
r=O(\log|A_{\gamma}|)
levels
{\cal S}_{\gamma,1},...,{\cal S}_{\gamma,r}
such that for each level
j
, segments in
{\cal S}_{\gamma,j}
partition the list
A_{\gamma}
. In particular, the top level has the unique segment
A_{\gamma}
and each segment at the bottom level is a singleton list of each vertex in
A_{\gamma}
. Furthermore, for each level
j\geq 2
, each segment
S\in{\cal S}_{\gamma,j}
is the union of two
child-segments

S_{1},S_{2}\in{\cal S}_{\gamma,j-1}
. See
Definition

6.9
for the complete definition.

The construction of
\hat{E}_{\gamma}
is similar to the previous step. We process
\gamma\in R
one by one and initialize
\hat{E}=\emptyset
.
Let
B_{\gamma}
be an arbitrary subset of
A_{\gamma}
of size
\min\{d+1,|A_{\gamma}|\}
.
For each
\gamma\in R
if there are less than
|{\cal S}_{\gamma}|
pairs in
(A_{\gamma}\times B_{\gamma})\setminus\hat{E}
, we set
\hat{E}_{\gamma}=A_{\gamma}\times B_{\gamma}
as usual. Otherwise we assign a distinct pair
(u_{S},v_{S})\in(A_{\gamma}\times B_{\gamma})\setminus\hat{E}
to each segment
S\in{\cal S}_{\gamma}
and let
\hat{E}_{\gamma}=\sum_{S\in{\cal S}_{\gamma}}S\times\{u_{S},v_{S}\}
. Lastly, insert
\hat{E}_{\gamma}
to
\hat{E}
and proceed to the next
\gamma
. Now, we claim that the total number of artificial edges (without multiplicity) is
\|\hat{E}\|_{0}=\tilde{O}(m)
since the former case will bring at most
|{\cal S}_{\gamma}|
new edges and in the latter case the number of new edges is at most
|\hat{E}_{\gamma}|=O(\sum_{S\in{\cal S}_{\gamma}}|S|)=\tilde{O}(|A_{\gamma}|)
. So
\|\hat{E}\|_{0}=\sum_{\gamma\in R}\tilde{O}(|A_{\gamma}|)=\tilde{O}(m)
and so the total space is
O(\|\hat{E}\|_{0})=\tilde{O}(m)
.

The repairing algorithm is based on the segmentation hierarchy.
Let
{\cal S}_{\mathrm{fault}}
contain all segments
S
(in
{\cal S}_{\gamma}
for
all

\gamma\in R
) such that
u_{S},v_{S}\in D_{L}
.
By the same argument,
S\setminus D_{L}
is not connected by
\hat{E}_{\gamma}\setminus D_{L}
only if
S\in{\cal S}_{\mathrm{fault}}
, and we have
|{\cal S}_{\mathrm{fault}}|=O(d^{2})
. For each
\gamma\in R
with nonempty
{\cal S}_{\mathrm{fault}}\cap{\cal S}_{\gamma}
, suppose that we are given a non-deleted vertex
v_{\gamma}\in A_{\gamma}\setminus D_{L}
.
10
10

10

In the complete algorithm, the
v_{\gamma}
for each
\gamma\in R
with
{\cal S}_{\mathrm{fault}}\cap{\cal S}_{\gamma}\neq\emptyset
can be computed in totally
\tilde{O}(d^{2})
time.
Then we construct
D
-repairing edges
\hat{F}_{\gamma}
by, for each
S\in{\cal S}_{\mathrm{fault}}\cap{\cal S}_{\gamma}
, connecting its two child-segments
S_{1},S_{2}
to
v_{\gamma}
. Concretely, we add to
\hat{F}_{\gamma}
four
D
-repairing edges connecting
v_{\gamma}
to each of
u_{S_{1}},v_{S_{1}},u_{S_{2}},v_{S_{2}}
for each
S\in{\cal S}_{\mathrm{fault}}\cap{\cal S}_{\gamma}
. Thus there are totally
O(|{\cal S}_{\mathrm{fault}}|)=O(d^{2})

D
-repairing edges and the repairing time is
\tilde{O}(d^{2})
.

To see the correctness, we say that a segment
S
is
maximal
if
S\in\mathcal{S}_{\gamma}\setminus\mathcal{S}_{\mathrm{fault}}
but its parent-segment is in
\mathcal{S}_{\gamma}\cap\mathcal{S}_{\mathrm{fault}}
. Observe that maximal segments cover
A_{\gamma}\setminus D
, the whole non-deleted part of
A_{\gamma}
. Now, for each maximal segment
S
, we have that either
u_{S}\notin D
or
v_{S}\notin D
. Say
u_{S}\notin D
, so
u_{S}
is connected to
v_{\gamma}
via
\hat{F}_{\gamma}
and the whole
S
is connected to
u_{S}
via
\hat{E}_{\gamma}
. Therefore, indeed we have that vertices in
A_{\gamma}\setminus D
will be connected via
(\hat{E}_{\gamma}\cap\hat{F}_{\gamma})\setminus D
as promised.

2.2.6
Final Algorithm:
\tilde{O}(m)
space and
\tilde{O}(d^{2})
update
time.

The last step to our final algorithm is to make
\hat{E}_{\gamma}
in
Section

2.2.5
well-structured. We cannot hope each
\hat{E}_{\gamma}
forms a perfect product set because of the segmentation hierarchy. Yet, we can still design it to have some good structural property so that it is compatible with the Bor
\mathring{\text{u}}
vka’s based algorithm in
Section

2.2.3
, which finally leads us to
\tilde{O}(d^{2})
update time and
\tilde{O}(m)
space simultaneously.

The construction algorithm of artificial edges is relatively simple. We only summarize the outputs here and see
Section

6.4
for details. For each right vertex
\gamma\in R
, we still assign a pair
(u_{S},v_{S})\in A_{\gamma}\times A_{\gamma}
to each segment
S\in{\cal S}_{\gamma}
, and the actual
\hat{E}_{\gamma}
will be

\hat{E}_{\gamma}=A_{\gamma}\times B_{\gamma}+\sum_{S\in{\cal S}_{\gamma}}S\times\{u_{S}\},

where

Perspective: Repairable Hypergraph-to-Graph Connectivity-Sparsifiers.

Lastly we discuss our techniques in

in a different perspective. If we corresponds left vertices and right vertices in the semi-bipartite graph to vertices and hyperedges in a hypergraph respectively, the techniques on constructing artificial edges and

-repairing edges can be viewed as some kind of sparsifier which transform a hypergraph

to a graph

Concretely, the transformation will keep the vertex set unchanged, and for each hyperedge

, add an edge set

to

. Namely we will have

and

. Moreover, the sparsifier has the following properties.

•

(Vertex Restricted) The vertex set is unchanged.

•

(Sparse) The number of edges in

is nearly linear to the total size of edges in
H
. Namely
|E(G)|=\tilde{O}(\sum_{e\in E(H)}|e|)
, where we use the same notation

to denote the set of
e
’s endpoints.

•

(Fault-Tolerant/Repairable) Given any failure set

with
|D|=d
, by augmenting each
\hat{E}(e)
with a set
\hat{F}(e)
of repairing edges, it will be guaranteed that for each hyperedge

, vertices in

are still connected by
\hat{E}(e)\cup\hat{F}(e)
. Moreover, the total size of
\hat{F}(e)
summing over all
e\in E(H)
is
\tilde{O}(d^{2})
, and all nonempty
\hat{F}(e)
can be computed in totally
\tilde{O}(d^{2})
time.

We apply this tool to obtain an nearly optimal vertex-failure connectivity oracle. Furthermore, we note that this sparsifier is somewhat stronger than maintaining just pairwise connectivity because the connectivity of each hyperedge

is perserved by

individually. Thus we expect that this tool or its variant can have applications on other vertex-failure problems.

The cut-matching game is an interactive process between a

and a

to construct an expander. The goal of the cut player is to ensure the game will terminate with an expander in a small number of rounds, while the matching player can act arbitrarily or even adversarially to slow down this process. The game was first introduced by Khandekar, Rao and Variranzi
[

]
to design fast algorithm to compute sparse cuts and balanced cuts.

Before we describe the cut-matching game, we emphasize that the game is designed under the edge cut setting, where whether an edge cut is sparse or not is measured by its

5
The Low Degree Hierarchy

The
low degree hierarchy
, which was first introduced in
[
DP20
]
, is an important ingredient of our oracle. In this section, we will show an alternative construction algorithm of the low degree hierarchy, which exploits vertex expander decomposition. Compared to the construction in
[
DP20
]
, our algorithm is more time-efficient, at a cost of giving a slightly low-quality hierarchy.

In short, the low degree hierarchy includes a laminar set
{\cal C}
of components and a set
{\cal T}
of low-degree Steiner trees. Every component
\gamma\in{\cal C}
is corresponding to a tree
\tau\in{\cal T}
which will span all (but may not only)
terminals
of
\gamma
, where terminals of
\gamma
are vertices in
V(\gamma)
that are not in any of the child components. The main result of this section is an almost-linear time construction algorithm for the low degree hierarchy as shown in
Theorem

5.3
. In
Section

5.1
, we will show how to use vertex expander decomposition repeatedly to construct a prototype of the low degree hierarchy. In
Section

5.2
, we will refine the prototype to formally construct the hierarchy and complete the proof of
Theorem

5.3
.

5.1
Low Degree Hierarchy.

Let
G
be a connected undirected graph. A
(p,\Delta)
-low degree hierarchy with height
p
and degree parameter
\Delta
on
G
is a pair
({\cal C},{\cal T})
of sets, where
{\cal C}
is a set of vertex-induced connected subgraphs called
components
, and
{\cal T}
is a set of Steiner trees with maximum vertex degree at most
\Delta
.

The set
{\cal C}
of components is a laminar set. Specifically,
{\cal C}
has the following properties.

(1)

Components in
{\cal C}
belong to
p

{\cal C}_{i}
the set of components at level
i
. In particular, at the top level
p
,
{\cal C}_{p}=\{G\}
is a singleton set with the whole
G
as the unique component. Furthermore, for each level
i\in[1,p]
, components in
{\cal C}_{i}
are vertex-disjoint and there is no edge in
E(G)
connecting two components in
{\cal C}_{i}
.

(2)

For each level
i\in[1,p-1]
and each component
\gamma\in{\cal C}_{i}
, there is a unique component
\gamma^{\prime}\in{\cal C}_{i+1}
such that
V(\gamma)\subseteq V(\gamma^{\prime})
, where we say that
\gamma^{\prime}
is the
parent-component
of
\gamma
and that
\gamma
is a
child-component
of
\gamma^{\prime}
.

(3)

For each component
\gamma\in{\cal C}
, the
terminals of
\gamma
, denoted by
U(\gamma)
, are vertices in
\gamma
but not in any of
\gamma
’s child-components. Note that
U(\gamma)
can be empty. In particular, for each
\gamma\in{\cal C}_{1}
,
U(\gamma)=V(\gamma)
.

Generally, for each level
i\in[1,p]
, we define the
terminals at level
i
be terminals in all components in
{\cal C}_{i}
, denoted by
U_{i}=\bigcup_{\gamma\in{\cal C}_{i}}U(\gamma)
.

The set
{\cal T}
of low-degree Steiner trees has the following properties

(4)

{\cal T}
can also be partitioned into subsets
{\cal T}_{1},...,{\cal T}_{p}
, where
{\cal T}_{i}
denote trees at level
i
and trees in
{\cal T}_{i}
are vertex-disjoint.

(5)

For each level
i\in[1,p]
and tree
\tau\in{\cal T}_{i}
, the
terminals of
\tau
is defined by
U(\tau)=U_{i}\cap V(\tau)
.

(6)

For each level
i\in[1,p]
and each component
\gamma\in{\cal C}_{i}
with

, there is a tree
\tau\in{\cal T}_{i}
such that
U(\gamma)\subseteq U(\tau)
, denoted by
\tau(\gamma)
. We emphasize that two different components
\gamma
and
\gamma^{\prime}\in{\cal C}_{i}
may correspond to the same tree
\tau\in{\cal T}_{i}
.

5.2
.

In
Definition

5.1
, terminal sets of components
\{U(\gamma)\mid\gamma\in{\cal C}\}
forms a partition of

. Similarly, regarding terminal sets of Steiner trees and levels,

and

.

The main result of this section is
Theorem

5.5

Let

6.1
.

We define the

•

Let

.

Given a failure set

(1)

The number of second-type objects is

.

(2)

There is no edge connecting two first-type objects.

(3)

For any two second-type objects

\hat{\tau}_{1}
and

, and any

and

Proof.

Because components in the same level are disjoint by (1) in

O(pd)
failed vertices on affected trees summing over

Let

be two distinct first-type objects and assume

Note that each second-type object

∎

The task of our update algorithm is to compute the connectivity of the abstract graph
H
. Precisely, since the number of first-type objects may be large but the number of second-type objects is quite small by
(1)
, we will see that, our update algorithm only reestablish connectivity among second-type objects in

.
The data structures constructed in this section aim for supporting fast update algorithm.

6.2
Overview

There are two parts of the affiliated structures. The first part is basically a 2D range counting structure in
Section

6.3
. The intuition behind is that we can view affected subtrees, i.e. the second-type objects, as intervals on some Euler tour order by
Lemma

6.3
, so querying whether two affected subtrees are connected directly by some edges is equivalent to some 2D range counting queries.

An issue is that two second-type objects in
H
can be connected by, instead of an edge, a path through a first type object, but such paths are not captured by a 2D range counting structure only storing original edges. Following an idea from
[
DP20
]
, we will add
artificial edges
into the counting structure to capture the connectivity provided by them. Our construction of artificial edges in
Section

6.4
is deterministic and compact, which leads to faster deterministic update algorithm and lower space requirement.

Since the objects of
H
are “dynamic” (depending on
D
), we should be able to efficiently “subtract” from the 2D range counting structure artificial edges whose underlying paths go through affected components, because these edges are not guaranteed to provide valid connectivity. Therefore, we also construct some navigation structures around artificial edges in
Section

6.4
. When some components becomes affected, these structures can support efficient “subtraction” of invalid artifical edges.

6.3
The Euler Tour Order and the 2D Range Counting Structure

Our goal of this subsection is to construct a 2D range counting structure (see
Lemma

6.5
) to support connectivity queries of affected subtrees under a multiset of edges
E=E(G)+\hat{E}
, where
\hat{E}
is the multiset of artificial edges which will be constructed in
Section

6.4
. We emphasize that although we conceptually define
E
and
\hat{E}
be multisets of undirected edges, actually our algorithm will construct and view them as multisets of ordered pairs, where each pair relates to an undirected edge. The original edge set
E(G)
can also be viewed as a set of ordered pair by giving an arbitrary direction to each undirected edge.

We will exploit the Euler tour order as in
[
DP20
]
to reduce queries on connectivity of affected subtrees to 2D range counting queries. Our algorithm will process each
\tau\in{\cal T}
individually. For an unrooted tree
\tau
, by picking a root arbitrarily, we define the Euler tour order
\mathrm{ET}(\tau)
as an ordered list of the vertices ordered by the time each vertex first appears during an Euler tour of
\tau
(treating each undirected edge as two directed edges). The Euler tour order can be interpreted as a linearization of the tree in the sense that after deleting some vertices on
\tau
, the remaining subtrees are corresponding to intervals in
\mathrm{ET}(\tau)
as shown in
Lemma

6.3
. Proving
Lemma

6.3
is an easy exercise and we leave the complete proof in
Section

A.5
.

6.3
.

Let
\tau

As mentioned in

, each affected subtree

For each level

6.5
2D Range Counting Structure.

Let
E
be a multiset of ordered pairs in

. There is a data structure which given any disjoint intervals

on

with first entries in

and second entries in

. The data structure takes space is

and the construction time is

, where

Proof.

We can generate from

with

by putting for each

in

[
Ben80
]
or the persistent segment tree
[
DSST89
,
BW80
]
. The space is

and the query time is
O(\log n)
.
∎

6.4
Artificial Edges

In this subsection, we will construct the set
\hat{E}
of artificial edges. Actually, our algorithm will construct a set
\hat{E}_{\gamma}
of artificial edges for each
\gamma\in{\cal C}
, in which each artificial edge will connect two vertices adjacent to
\gamma
, i.e. the set
\hat{E}_{\gamma}
of ordered pairs is a subset of
A_{\gamma}\times A_{\gamma}
, where
A_{\gamma}
is
\gamma
’s adjacency list (see
Definition

6.7
). The whole set
\hat{E}
is a multiset such that
\hat{E}=\sum_{\gamma\in{\cal C}}\hat{E}_{\gamma}
.

6.7
Adjacency List.

For each
\gamma\in{\cal C}
, the
adjacency list
of
\gamma
is an ordered list

A_{\gamma}=\{v\mid v\notin V(\gamma)\text{ s.t. }\exists u\in V(\gamma),(u,v)\in E(G)\},

whose order is consistent with
\mathrm{ET}_{\mathrm{glo}}
.

6.8
.

The total size of adjacency lists of all components is
\sum_{\gamma\in{\cal C}}|A_{\gamma}|=O(pm)
.

Proof.

Consider a level
i
in the low degree hierarchy. For each
\gamma\in{\cal C}_{i}
and
v\in A_{\gamma}
, there is an edge connecting
\gamma
and
v
. Also, each edge will correspond to at most one such pair of
\gamma
and
v
since property (1) in
Definition

5.1
. Thus
\sum_{\gamma\in{\cal C}_{i}}|A_{\gamma}|\leq m
and
\sum_{\gamma\in{\cal C}}|A_{\gamma}|=O(pm)
.
∎

Our update algorithm will only solve the connectivity of second-type objects in
H
for efficiency. Recall that there is no edge in
H
connecting two different first-type objects (see
(2)
).
Therefore, from the perspective of second-type objects, each first-type object
\gamma
with its adjacent edges can be viewed as a hyperedge, which will also contribute to the connectivity of second-type objects in addition to original edges. The artificial edges
\hat{E}_{\gamma}
of
\gamma
are served as a simulation of this hyperedge. Therefore, we hope each
\hat{E}_{\gamma}
has the following
fault-tolerant
property: for any failure set
D
with
|D|\leq d_{\star}
, there will be either
A_{\gamma}\subseteq D
or vertices in
A_{\gamma}\setminus D
are connected by
\hat{E}_{\gamma}
.
On the other hand, we hope the size of
\hat{E}_{\gamma}
is small to save the space taken by the 2D range counting structure. A natural idea is to take an arbitrary subset
B_{\gamma}\subseteq A_{\gamma}
with size
|B_{\gamma}|=d_{\star}+1
(
B_{\gamma}=A_{\gamma}
if
|A_{\gamma}|\leq d_{\star}
), and let
\hat{E}_{\gamma}=A_{\gamma}\times B_{\gamma}
with
|\hat{E}_{\gamma}|=O(d_{\star}|A_{\gamma}|)
. This simple construction can indeed lead to an oracle that takes space
\tilde{O}(d_{\star}m)
. Actually, this is the optimal construction of
\hat{E}_{\gamma}
under this setting by the fact that any
d_{\star}
-vertex-connected graph on
A_{\gamma}
has at least
\Omega(d_{\star}|A_{\gamma}|)
edges.

In our construction, we get around this barrier by slightly relax the requirement on the fault-tolerant property, inspired by the Monte Carlo construction algorithm in
[
DP20
]
. For each
\gamma\in{\cal C}
, instead of ensuring the fault-tolerant property on all
\hat{E}_{\gamma}
in the preprocessing phase, we are allowed to add some
D
-repairing edges

\hat{F}_{\gamma}
temporarily in the update phase, such that
\hat{E}_{\gamma}\cup\hat{F}_{\gamma}
is fault-tolerant. Under this setting, we are able to deterministically construct artificial edges
\hat{E}_{\gamma}
for each
\gamma\in{\cal C}
such that the total number of distinct artificial edges is bounded by
\tilde{O}(m)
, which is exactly nearly linear to the space of the 2D range counting structure. Moreover, we will show that the construction of
D
-repairing edges only takes
\tilde{O}(d^{2})
time and the total number of
D
-repairing edges is bounded by
\tilde{O}(d^{2})
, which can be afforded by the update algorithm. Lastly, our construction of
\hat{E}_{\gamma}
is based on a simple recursive division on the list
A_{\gamma}
called
segmentation hierarchy
, so the artificial edges are well-structured and can be efficiently manipulated by the update algorithm.

6.9
Segmentation Hierarchy.

For each component
\gamma\in{\cal C}
, we define a
segmentation hierarchy

{\cal S}_{\gamma}
on its adjacency list
A_{\gamma}
.
{\cal S}_{\gamma}
is an ordered list of
segments
on
A_{\gamma}
, where a segment on
A_{\gamma}
is a consecutive sublist of
A_{\gamma}
.

There are
r=\lceil\log|A_{\gamma}|\rceil+1
levels in the hierarchy and we denote by
{\cal S}_{\gamma,j}
the ordered list of segments at level
j
for each
1\leq j\leq r
. The whole list
{\cal S}_{\gamma}
is the concatenation of
{\cal S}_{\gamma,1},...,{\cal S}_{\gamma,r}
. The list
{\cal S}_{\gamma,j}
is obtained by partitioning
A_{\gamma}
into segments using step length
2^{j-1}
. Concretely, Let
A_{\gamma}[k_{1},k_{2}]
denote the sublist of
A_{\gamma}
from rank
k_{1}
to
k_{2}
.

•

For
1\leq i\leq\lfloor|A_{\gamma}|/2^{j-1}\rfloor
, the
i
-th segment
S_{j,i}
of
{\cal S}_{\gamma,j}
is
A_{\gamma}[2^{j-1}(i-1)+1,2^{j-1}i]
.

•

If
|A_{\gamma}|
is not divisible by
2^{j-1}
, we let the tail
A_{\gamma}[2^{j-1}(i-1)+1,|A_{\gamma}|]
be the last segment
S_{j,i}
where
i=\lfloor|A_{\gamma}|/2^{j-1}\rfloor+1
.

Observe that the total number of segments is
|{\cal S}_{\gamma}|=O(|A_{\gamma}|)
, and the total length of segments is
O(|A_{\gamma}|\log|A_{\gamma}|)
.

For each segment
S_{j,i}

(j\geq 2)
in the hierarchy, we let
S_{j-1,2i-1}
and
S_{j-1,2i}
be its
child-segments
(the latter may not exist), and we say
S_{j,i}
is the
parent-segment
of
S_{j-1,2i-1}
and
S_{j-1,2i}
. Observe that
S_{j,i}
is exactly the union of its child-segments. In particular, the topmost level
S_{\gamma,r}
only contains
A_{\gamma}
as its unique segment, called the
root segment
of this hierarchy.

6.10
.

For simplicity, the segmentation hierarchy defined in
Definition

6.9
is a
two-branched
recursive division with
O(\log n)
levels. It is natural to define
multiple-branched
segmentation hierarchy to obtain a tradeoff between the number of levels and the number of branches. The number of levels will affect the space of the oracle, while the number of branches will affect the number of
D
-repairing edges and the update time. Therefore, when we allow a update time of
d^{2}n^{o(1)}
, we can use a

-branched segmentation hierarchy with

\beta(n)
is any slowly growing function e.g.
\beta(n)=\log^{*}n

factor in the space complexity by

.

(2)

We define

6.11
.

For each
\gamma

|\mathrm{Tag}_{\gamma}|=\Theta(|A_{\gamma}|)

First, by the choice of

(3)

The “find-neighbor” operations are delegated to the function
\textsc{FindNeighbor}(t,Z_{t,k})
. The inputs are the phase number
t
and some
Z_{t,k}\in{\cal Z}_{t}
, and the required output is another
Z_{t,k^{\prime}}\in{\cal Z}_{t}
adjacent to
Z_{t,k}
(or claiming such
Z_{t,k^{\prime}}
does not exist), where we say
Z_{t,k}
and
Z_{t,k^{\prime}}
are
adjacent
if there exists two adjacent intervals
I\in Z_{t,k}
and
I^{\prime}\in Z_{t,k^{\prime}}
.

First, we let
{\cal I}_{t}
be an ordered list of intervals in
{\cal Z}_{k}
by viewing each
Z_{t,k}
a list of intervals with an arbitrary order and taking the concatenation from
Z_{t,1}
to
Z_{t,|{\cal Z}_{k}|}
. By the definition, each
Z_{t,k}
is a set of intervals locating consecutively in the list
{\cal I}_{t}
. Let
\textsc{BatchConnCheck}(t,k,l,r)
be a function which returns a boolean indicating the existence of
Z_{t,k^{\prime}}
such that
l\leq k^{\prime}\leq r
and
Z_{t,k^{\prime}}
is adjacent to
Z_{t,k}
. With access to the function
\textsc{BatchConnCheck}(t,k,l,r)
, the function
\textsc{FindNeighbor}(t,Z_{t,k})
can use a binary search scheme to find the minimum
k_{r}
such that
k_{r}>k
and
Z_{t,k}
and
Z_{t,k_{r}}
are adjacent. If there is no such
k_{r}
exists, it will perform a symmetric binary search on the other side.

Implementing the indicator
\textsc{BatchConnCheck}(t,k,l,r)
is equivalent to solving a counting problem. By the definition of
{\cal I}_{t}
, intervals in
\bigcup_{k^{\prime}=l}^{r}Z_{t,k^{\prime}}
are located consecutively on
{\cal I}_{t}
and we let them be
{\cal I}_{t}(x,y)
. The indicator responds affirmatively if and only if the following value
\delta(t,k,x,y)
is greater than zero.

\delta(t,k,x,y)=\sum_{I\in Z_{t,k}}\sum_{I^{\prime}\in{\cal I}_{t}(x,y)}|E_{D}\cap(I\times I^{\prime})|+|E_{D}\cap(I^{\prime}\times I)|.

By the fact that
E_{D}=E-\sum_{\gamma\in{\cal C}_{D}}(A_{\gamma}\times B_{\gamma}+\sum_{S\in{\cal S}_{\gamma}}S\times f(S))
, we can divide the whole counting problem into several subproblems.

\delta(t,k,x,y)=\delta_{1}(t,k,l,r)-\delta_{2}(t,k,l,r)-\delta_{3}(t,k,l,r),

where

\displaystyle\delta_{1}(t,k,x,y)

\displaystyle=\sum_{I\in Z_{t,k}}\sum_{I^{\prime}\in{\cal I}_{t}(x,y)}|E\cap(I\times I^{\prime})|+|E\cap(I^{\prime}\times I)|,

\displaystyle\delta_{2}(t,k,x,y)

\displaystyle=\sum_{\gamma\in{\cal C}_{D}}\sum_{I\in Z_{t,k}}\sum_{I^{\prime}\in{\cal I}_{t}(x,y)}|(A_{\gamma}\times B_{\gamma})\cap(I\times I^{\prime})|+|(A_{\gamma}\times B_{\gamma})\cap(I^{\prime}\times I)|,

\displaystyle\delta_{3}(t,k,x,y)

\displaystyle=\sum_{\gamma\in{\cal C}_{D}}\sum_{S\in{\cal S}_{\gamma}}\sum_{I\in Z_{t,k}}\sum_{I^{\prime}\in{\cal I}_{t}(x,y)}|(S\times f(S))\cap(I\times I^{\prime})|+|(S\times f(S))\cap(I^{\prime}\times I)|.

In what follows, we will construct some additional structures and use them to compute
\delta_{1}(t,k,x,y)
and
\delta_{2}(t,k,x,y)
in
Section

7.2.2
. In section
Section

7.2.3
, we will show the algorithm for computing
\delta_{3}(t,k,x,y)
.

7.2.3
Computing
\delta_{3}(t,k,x,y)

We first rearrange the expression of
\delta_{3}(t,k,l,r)
as follows.

\delta_{3}(t,k,l,r)=\sum_{\gamma\in{\cal C}_{D}}\sum_{j=1}^{\lceil\log|A_{\gamma}|\rceil+1}\sum_{I\in Z_{t,k}}Q_{1}(t,\gamma,j,I,x,y)+Q_{2}(t,\gamma,j,I,x,y),

where

\displaystyle Q_{1}(t,\gamma,j,I,x,y)

\displaystyle=\left|\left(\sum_{S\in{\cal S}_{\gamma,j}}S\times f(S)\right)\cap\left(I\times\bigcup_{I^{\prime}\in{\cal I}_{t}(x,y)}I^{\prime}\right)\right|,

\displaystyle Q_{2}(t,\gamma,j,I,x,y)

\displaystyle=\left|\left(\sum_{S\in{\cal S}_{\gamma,j}}S\times f(S)\right)\cap\left(\bigcup_{I^{\prime}\in{\cal I}_{t}(x,y)}I^{\prime}\times I\right)\right|.

The algorithm we show below can compute
Q_{1}(t,\gamma,j,I,x,y)
and
Q_{2}(t,\gamma,j,I,x,y)
in nearly constant time. The key property for the efficient computation is the monotonically increasing property of the witness function
f
over
{\cal S}_{\gamma,j}
(
Proposition

6.12
). Take the function
Q_{1}
as an example. Roughly speaking, segments in
{\cal S}_{\gamma,j}
that intersects
I
have their witnesses locating in a consecutive range on
C_{\gamma,j}
by
Proposition

6.12
. In the other direction, ignoring the boundary case, segments with witnesses in this range will totally included by
I
. Therefore, if we view
I\times\bigcup_{I^{\prime}\in{\cal I}_{t}(x,y)}I^{\prime}
as “conditions” of the counting problem
Q_{1}
, we can reduce the condition
I
on the first dimension into a new condition on the second dimension, i.e. the range on
C_{\gamma,j}
. The task basically becomes a counting problem on the intersection of the range on
{\cal C}_{\gamma,j}
and intervals in
{\cal I}_{t}(x,y)
, which can be answered by part (D) of the additional data structures.

An illustration for computing
Q_{1}(t,\gamma,j,I,x,y)

(vertices below) are partitioned by segments in

. The witness list

(black vertices above) is a sublist of

. The intervals in this figure have been restricted on

.

We now formally describe the algorithm for computing

. See

for an illustration.

•

First, we take the restriction of
I
on
A_{\gamma}
, and let

and

denote the leftmost vertex and the rightmost vertex in
I\cap A_{\gamma}
. If

is empty, the algorithm terminates with zero as the output. Let
S_{L}
(resp.
S_{R}
) be the unique segment in
{\cal S}_{\gamma,j}
containing

(resp.
v_{R}
). We further denote their witnesses

and

by

and

•

In this step we will count the part contributed by the witnesses
w_{L}
and
w_{R}
. Precisely, the part

contributes to the answer is

\mathrm{Ans}(w_{L})=\left|\left(f^{-1}(w_{L},{\cal S}_{\gamma,j})\times w_{L}\right)\cap\left(I\times\bigcup_{I^{\prime}\in{\cal I}_{t}(x,y)}I^{\prime}\right)\right|,

where

denotes the union of segments in
{\cal S}_{\gamma,j}
with
w_{L}
as their witness. We first check if

belongs to an interval in
{\cal I}_{t}(x,y)
. If so,
\mathrm{Ans}(w_{L})=|f^{-1}(w_{L},{\cal S}_{\gamma,j})\cap I|
, otherwise
\mathrm{Ans}(w_{L})=0
. In the former case, we first take the restriction

and then let
\mathrm{Ans}(w_{L})
be the size of intersection of

and

(note that vertices in

). If

and

\mathrm{Ans}(w_{R})=\left|\left(f^{-1}(w_{R},{\cal S}_{\gamma,j})\times w_{R}\right)\cap\left(I\times\bigcup_{I^{\prime}\in{\cal I}_{t}(x,y)}I^{\prime}\right)\right|
similarly, otherwise the algorithm terminates with the answer

.

•

In the following steps we will compute the part contributed by witnesses between
w_{L}
and
w_{R}
on
C_{\gamma,j}
(not including

). Note that witnesses located before
w_{L}

. We let

be the successor of
w_{L}
and let

be the predecessor of
w_{R}
on

. We denote witnesses from

to
w_{R}^{-}
on

by a sublist

. If the list
C_{\gamma,j}(w_{L}^{+},w_{R}^{-})
is empty, i.e.

is before
w_{L}^{+}
on
C_{\gamma,j}
, the algorithm terminates with the current answer
\mathrm{Ans}(w_{L})+\mathrm{Ans}(w_{R})
. Otherwise, we compute

\mathrm{Ans}(w_{L}^{+},w_{R}^{-})=\left|\sum_{w\in C_{\gamma,j}(w_{L}^{+},w_{R}^{-})}\left(f^{-1}(w,{\cal S}_{\gamma,j})\times w\right)\cap\left(I\times\bigcup_{I^{\prime}\in{\cal I}_{t}(x,y)}I^{\prime}\right)\right|.

By

6.12
, for each
w\in C_{\gamma,j}(w_{L}^{+},w_{R}^{-})
, we have

. Therefore, we can rewrite

\mathrm{Ans}(w_{L}^{+},w_{R}^{-})=\sum_{w\in W}|f^{-1}(w,{\cal S}_{\gamma,j})|,\text{ where }W=C_{\gamma,j}(w_{L}^{+},w_{R}^{-})\cap\bigcup_{I^{\prime}\in{\cal I}_{t}(x,y)}I^{\prime}.

-weight of

The remaining part of

\displaystyle Q_{1}(t,\gamma,j,I,x,y)

\displaystyle=\mathrm{Ans}(w_{L})+\mathrm{Ans}(w_{R})+\mathrm{Ans}(w_{L}^{+},w_{R}^{-})

Proof of
Lemma

.

The correctness of the algorithm directly follows the description. We will focus on analysing the running time.

As mentioned, the Bor
\mathring{\text{u}}
vka’s algorithm has
\log|{\cal I}|

\textsc{FindNeighbor}(t,Z_{t,k})

with fix parameters

at most

\textsc{BatchConnCheck}(t,k,l,r)

O(|{\cal C}_{D}|\cdot|Z_{t,k}|\log^{2}|{\cal I}|\log n)
time. Therefore, the total running time is

O(|{\cal I}|^{2}\log n+|{\cal I}|\cdot|{\cal C}_{D}|\log^{3}|{\cal I}|\log n)+\sum_{t\leq\log|{\cal I}|}\sum_{Z_{t,k}\in{\cal Z}_{t}}O(\log|{\cal Z}_{k}|)\cdot O(|{\cal C}_{D}|\cdot|Z_{t,k}|\log^{2}|{\cal I}|\log n),

where the first term is the construction time of the additional structures from
Lemma

7.6
.
It is exactly
O(|{\cal I}|^{2}\log n+|{\cal I}|\cdot|{\cal C}_{D}|\log^{4}|{\cal I}|\log n)

because
\sum_{Z_{t,k}\in{\cal Z}_{t}}|Z_{t,k}|\leq|{\cal I}_{t}|\leq|{\cal I}|
for any
t
.

It remains to show that computing
\textsc{BatchConnCheck}(t,k,l,r)
takes
O(|{\cal C}_{D}|\cdot|Z_{t,k}|\log^{2}|{\cal I}|\log n)
time. We analyse the three subproblems one by one. Computing
\delta_{1}(t,k,x,y)
requires only two 2D-range sum query on part (A), which takes
O(1)
time. Computing
\delta_{2}(t,k,x,y)
needs
O(|{\cal C}_{D}|)
queries on part (B) each of which takes constant time, so the total time is
O(|{\cal C}_{D}|)
. Computing
\delta_{3}(t,k,x,y)
takes
O(|{\cal C}_{D}|\cdot|Z_{t,k}|\log^{2}|{\cal I}|\log n)
because it can be decomposed into
O(|{\cal C}_{D}|\cdot|Z_{t,k}|\log n)
computations of
Q_{1}(t,\gamma,j,I,x,y)
and
Q_{2}(t,\gamma,j,I,x,y)
. Each computation of
Q_{1}
or
Q_{2}
takes
O(\log^{2}|{\cal I}|)
time because the bottleneck is querying part (C).

∎

7.3
The Query Algorithm

The query algorithm is identical to that in Section 5.2 of
[
DP20
]
, since we have implemented the required interfaces. We describe the algorithm as follows for completeness. Let
u,v\notin D
be the given vertices. The goal of the query algorithm is to find two affected subtrees connected to
u
and
v
in
G\setminus D
, so the connectivity of
u
and
v
is equivalent to the connectivity of these two subtrees, which can be answered by checking if they belong to the same group of
\hat{\cal R}
.

First we find the component
\gamma(u)
with
u
in its terminal set
U(\gamma(u))
. If
\gamma(u)
is an unaffected component, let
\hat{\gamma}(u)
be the most ancestral unaffected component of
\gamma(u)
, which can be identified in
O(\log d)
time as follows. Fix some preorder of components in
{\cal C}
(recall that they form a tree structure). Let
\gamma_{-}(u)
be the predecessor of
\gamma(u)
among components
\gamma
with
U(\gamma)\cap D\neq\emptyset

(note that it is not the same with the definition of affected components). Then
\hat{\gamma}(u)
is exactly the
{\rm LCA}(\gamma(u),\gamma_{-}(u))
’s child such that it is an ancestor of
\gamma(u)
. Specially, if
\gamma_{-}(u)
does not exist, then
\hat{\gamma}(u)
is the root. Analogously, we find
\gamma(v)
and
\hat{\gamma}(v)
. If
\hat{\gamma}(u)=\hat{\gamma}(v)
, we claim
u
and
v
are connected. The bottleneck is the predecessor search for
\gamma_{-}(u)
, which takes
O(\log d)
time.

If
\gamma(u)
itself is affected, the affected tree
\tau(\gamma(u))
has an affected subtree
\hat{\tau}
with
u
as a terminal, which can be found in
O(\log d)
time by
Lemma

6.3
. Otherwise, we scan the list
A_{\hat{\gamma}(u)}
until we find a vertex
u^{\prime}\notin D
, which takes
O(d)
time. If there is no such
u^{\prime}
, we claim that
u
and
v
is not connected since
u\in V(\hat{\gamma}(u))
,
v\notin V(\hat{\gamma}(u))
and
\hat{\gamma}(u)
has no edge connecting outside after failures. If we find such
u^{\prime}
, then
u
and
u^{\prime}
are connected in
G\setminus D
and
u^{\prime}
is a terminal of some affected component, which implies we can find an affected subtree containing it in
O(\log d)
time by
Lemma

6.3
. We do the same thing for
v
.

Obviously, the query time is
O(d)
and the correctness follows
Theorem

7.2
and
(3)
.

Conditional Lower Bounds

In this section, we will show conditional lower bounds on major complexity measures of the connectivity oracle with batched vertex failures, including update time and construction time. The lower bounds on query time and space have been shown in
[
HKNS15
,
DP20
]
. Combining all the lower bounds, our oracle with construction time
O(m)+\tilde{O}(\bar{m}d_{\star})+\bar{m}^{1+o(1)}
, space
\tilde{O}(\bar{m})
, update time
d^{2}n^{o(1)}
and query time
O(d)
, where
\bar{m}=\min\{m,nd_{\star}\}
, is nearly optimal up to
n^{o(1)}
factors. Namely, improvement on any measure without extra costs on other measures needs significant breakthrough.

In this section, we use the same notation as in
[
HKNS15
]
.

Notation.

For any parameters

such that

. We use the analogous definition for functions with one or two parameters.

Lower Bound for Construction Time.

We will show a lower bound on construction time conditioning on
8.2

-vertex-failure connectivity problems.

No truly subcubic combinatorial BMM,

In the Word RAM model with words of

The lower bound of the update time is shown by exploiting the relationship between online Boolean vector-matrix-vector
multiplication (
{\sf OuMv}

-vertex-failure connectivity problems. Formally speaking, in a

{\sf OMv}
Conjecture,
[

]

For any constant
\epsilon>0

{\sf OuMv}

-Vertex-Failure Global Connectivity Problem.

We also study a related problem of

and

, and the required answer is to decide whether there exists vectors

Strong Exponential Time Hypothesis (SETH),
[
AW14
]
.

For every
\epsilon>0
, there exists a
k
such that SAT on
k
-CNF formulas on

variables cannot be solved in
\tilde{O}(2^{(1-\epsilon)n})

8.8

[

]

For any constant

, unless

fails, there is no an algorithm for OV, restricted to

and

, that runs in time
\tilde{\tilde{o}}(nm)

8.9

For any constant
t>0
, unless
8.7
fails, there is no algorithm for
d
-vertex-failure global connectivity on

-edge graphs even with

Open Problems

While
Theorems

1.1
and
1.2
together have settled
the complexity of the connectivity oracles with vertex failures up to sub-polynomial factors, they still leave interesting
and questions for this problem.

1.

If the update and query time can depend only on
d_{\star}
, what
is the best bound we we can hope for? van den Brand and Saranurak

[
vdBS19
]
showed a randomized Monte-Carlo oracle with

O(n^{2})
space,
O(n^{\omega})
preprocessing,
O(d^{\omega})

update, and
O(d^{2})
query time. Note that both update and query
time are both constant for all
d=O(1)
. Very recently, Pilipczhuk
et al.
[
PSS+21
]
gave the first deterministic
solution for this setting though the bounds seem far from being optimal.

2.

Our
\hat{O}(md_{\star})
preprocessing time is tight only under the

combinatorial
BMM conjecture. Can we improve the bound using
fast matrix multiplication?

The following questions about generalization of this problem seem
challenging:

1.

Suppose the vertices to be deleted are given one by one and queries
are given between each deletion, can we still handle all
d
deletions
in total
\hat{O}(d^{2})
update time?

2.

Is there a vertex-failure
c
-(edge/vertex)-connectivity oracle for

c>1
? The dynamic
c
-edge connectivity algorithm by Jin and Sun

[
JS22
]
implies a near-optimal
edge
-failure
c
-edge
connectivity oracle for
c=\log^{o(1)}n
, but all other variants
of this problems remain open.

. Given parameters
0<\epsilon\leq 1
, there is an algorithm that computes an
(\epsilon,\phi)
-expander decomposition of
H
, where
\phi=\epsilon/m^{o(1)}
. The algorithm can be deterministic with running time
O(p^{1+o(1)}/\phi)
, or randomized with running time
O(p^{1+o(1)})
and high correct probability.

Theorem

C.3
is the main result on expander decomposition on hypergraphs defined in
Definition

C.2
. As we will show below, the expander decomposition problem on a hypergraph can be reduced to computing a
neighbor-included vertex expander decomposition
on some weighted bipartite graph. We define this variant in
Definition

C.4
and obtain a fast algorithm in
Theorem

C.5
. We first describe the algorithm in
Theorem

C.5
, and then complete the proof of
Theorem

C.3
using it.

C.4
.

Let
G=(V(G),E(G),w,\boldsymbol{\mathrm{d}})
be a graph with weight
w(v)\geq 0
and demand
\boldsymbol{\mathrm{d}}(v)\geq 0
for each vertex
v\in V(G)
. For parameters
\epsilon>\phi>0
, an
(\epsilon,\phi)
-neighbor-included vertex expander decomposition
of
G
is a collections of pairs of subgraphs
{\cal G}=\{(V_{1},W_{1}),...,(V_{k},W_{k})\}
such that
V_{1},...,V_{k}
are disjoint (some
V_{i}
can possibly be empty). Let
X=V(G)\setminus(\bigcup_{i}V_{i}
) denote the
separator
. Then
{\cal G}
further satisfies the following.

(1)

For all
(V_{i},W_{i})\in{\cal G}
,
V_{i}\cup N_{G}(V_{i})\subseteq W_{i}
.

(2)

X=\bigcup_{i}W_{i}\setminus V_{i}
.

(3)

For all
(V_{i},W_{i})\in{\cal G}
,
h(G[W_{i}])\geq\phi
.

(4)

\sum_{i}w(W_{i}\setminus V_{i})\leq\epsilon\cdot\boldsymbol{\mathrm{d}}(V(G))
.

We emphasize that
Definition

C.4
is slightly different from
Definition

4.2
. First, the decomposition will guarantee that, for each
V_{i}\in{\cal G}
, the neighbor-included subgraph
G[W_{i}]
(i.e.
V_{i}\cup N_{G}(V_{i})\subseteq W_{i}\subseteq V_{i}\cup X
) is an vertex expander, rather than
G[V_{i}]
itself. Furthermore, it requires a stronger bound on the weight of the separator
X
. Concretely, instead of bounding
w(X)
, we can even bound the total weight (counting multiplicity) of vertices in the multiset
\sum_{i}W_{i}\setminus V_{i}
, where
\bigcup_{i}W_{i}\setminus V_{i}=X
.

C.5
.

Let
G=(V(G),E(G),w,\boldsymbol{\mathrm{d}})
be an
n
-vertex
m
-edge graph with for each
v\in V(G)
, integral weight
1\leq w(v)\leq U
and integral demand
0\leq d(v)\leq w(v)
. Given parameters
0<\epsilon\leq 1
, there is a algorithm that computes an
(\epsilon,\phi)
-neighbor-included vertex expander decomposition of
G
, where
\phi=\epsilon/(m^{o(1)}U^{o(1)})
. The algorithm can be deterministic with running time is
O(m^{1+o(1)}U^{1+o(1)}/\phi)
, or randomized with running time
O(m^{1+o(1)}U^{o(1)})
and high correct probability.

C.6
.

Let
G=(V(G),E(G),w,\boldsymbol{\mathrm{d}})
be an
n
-vertex
m
-edge graph with, for each
v\in V(G)
, integral weight
1\leq w(v)\leq U
and integral demand
0\leq\boldsymbol{\mathrm{d}}(v)\leq w(v)
. Given parameters
0<\epsilon\leq 1/2
and
1\leq r\leq\lfloor\log_{20}\boldsymbol{\mathrm{d}}(V(G))\rfloor
, there is a deterministic algorithm that computes a vertex cut
(L,S,R)
(possibly
L=S=\emptyset
) of
G
with
w(S)\leq\epsilon\cdot\boldsymbol{\mathrm{d}}(L\cup S)
, which further satisfies

•

either
\boldsymbol{\mathrm{d}}(L\cup S),\boldsymbol{\mathrm{d}}(R\cup S)\geq\boldsymbol{\mathrm{d}}(V(G))/3
; or

•

\boldsymbol{\mathrm{d}}(R\cup S)\geq\boldsymbol{\mathrm{d}}(V(G))/2
and
h(G[R\cup S])\geq\phi
for some
\phi=\epsilon/\log^{O(r)}U\log^{O(r^{5})}(m\log U)
.

The running time of this algorithm is
O(m^{1+o(1)+O(1/r)}\cdot U^{1+O(1/r)}\cdot\log^{O(r^{4})}(mU)/\phi)
.

The proof of
Theorem

C.5
relies on
Lemma

C.6
which is a variant of
Lemma

4.6
. The difference is that, in the case of returning an unbalanced sparse vertex cut
(L,S,R)
,
Lemma

C.6
will certify that
G[R\cup S]
is a vertex expander rather than
G[R]
. The algorithm of
Lemma

C.6
is the same with that of
Lemma

4.6
, except that each time when using the cut
(L,S,R)
from
Lemma

4.14
to prune the graph, the pruned part is
L
rather than
L\cup S
. The correctness and running time basically follows the same proof in
Section

A.4
and we omit it here.

Proof of
Theorem

C.5
.

Let
\epsilon^{\prime}=\epsilon/(10\log(nU))
and
\phi=\epsilon^{\prime}/(\log^{2}U\log^{O(r^{5})}(m\log U))
. We design a procedure
\textsc{Decomp}(G)
, which takes a graph
G
as input and returns a collection of subgraphs. By directly applying
Lemma

C.6
on
G
with parameters
\epsilon^{\prime},r
, we get a cut
(L,S,R)
with
w(S)\leq\epsilon^{\prime}\cdot\boldsymbol{\mathrm{d}}(L\cup S)
. There are two cases.

Case 1.
If
\boldsymbol{\mathrm{d}}(L\cup S),\boldsymbol{\mathrm{d}}(R\cup S)\geq\boldsymbol{\mathrm{d}}(V(G))/3
, the algorithm will recurse on both side. Let
G_{L}=G[L\cup S]\setminus E(G[S])
be the graph from
G[L\cup S]
after deleting edges inside
S
, and obtain
G_{R}=G[R\cup S]\setminus E(G[S])
similarly. Let
{\cal G}_{L}=\textsc{Decomp}(G_{L})
and
{\cal G}_{R}=\textsc{Decomp}(G_{R})
. The output
{\cal G}=\{(V_{i}\setminus S,W_{i})\mid(V_{i},W_{i})\in{\cal G}_{L}\cup{\cal G}_{R}\}
.

Case 2.
In the other case, we have
\boldsymbol{\mathrm{d}}(R\cup S)\geq\boldsymbol{\mathrm{d}}(V(G))/2
and
h(G[R\cup S])\geq\phi
for some
\phi=\epsilon^{\prime}/(\log^{O(r)}U\log^{O(r^{5})}(m\log U))
. We only recurse on the left side and obtain
{\cal G}_{L}=\textsc{Decomp}(G_{L})
, where
G_{L}
is defined as above. The output is
{\cal G}=\{(V_{i}\setminus S,W_{i})\mid(V_{i},W_{i})\in{\cal G}_{L}\}\cup\{(R,R\cup S)\}
. In particular, if
L
and
S
are empty, we return
{\cal G}=\{(R,R)\}
without any further recursion.

We claim that the maximum recursion depth
j^{*}
is at most
10\log(nU)
. At each recursive step, we have
\boldsymbol{\mathrm{d}}(S)\leq w(S)\leq\epsilon^{\prime}\boldsymbol{\mathrm{d}}(L\cup S)\leq\boldsymbol{\mathrm{d}}(V(G))/10
, so we have
\boldsymbol{\mathrm{d}}(L\cup S),\boldsymbol{\mathrm{d}}(R\cup S)\leq(2/3+1/10)\boldsymbol{\mathrm{d}}(V(G))
in both cases, which implies
j^{*}\leq\log\boldsymbol{\mathrm{d}}(V(G))/(-\log(2/3+1/10))\leq 10\log(nU)
.

We now show the correctness of the algorithm by induction. Let the induction hypothesis be that, for all
1\leq j\leq j^{*}
, each recursive step
\textsc{Decomp}(G_{j})
at depth
j
will return an
(\epsilon_{j},\phi)
-neighbor-included vertex expander decomposition of
G_{j}
, where
\epsilon_{j}=2(j^{*}-j+1)\epsilon^{\prime}(1+\epsilon^{\prime})^{j^{*}-j}
. Observe that the hypothesis holds for every leaf-step
\textsc{Decomp}(G_{j})=\{(G_{j},G_{j})\}
. Consider a recursive step
\textsc{Decomp}(G)
with output
{\cal G}
at depth
j
and assume w.l.o.g. it invokes two recursive steps
\textsc{Decomp}(G_{L})
and
\textsc{Decomp}(G_{R})
with outputs
{\cal G}_{L}
and
{\cal G}_{R}
at depth
j+1
, where
G_{L}
and
G_{R}
are defined as above. The case with only one recursive branch is analogous. First of all, all
V_{i}
in
{\cal G}
are obviously disjoint because
(L,S,R)
is a vertex cut and the induction hypothesis on
{\cal G}_{L}
and
{\cal G}_{R}
. We then verify the properties as follows.

Property (1).
We consider any
(V_{i},W_{i})\in{\cal G}
. We have
V_{i}=V^{\prime}_{i}\setminus S
and
W_{i}=W^{\prime}_{i}
for some
(V^{\prime}_{i},W^{\prime}_{i})\in{\cal G}_{L}\cup{\cal G}_{R}
. Assume w.l.o.g.
(V^{\prime}_{i},W^{\prime}_{i})\in{\cal G}_{L}
. From the induction hypothesis,
V^{\prime}_{i}\cup N_{G_{L}}(V^{\prime}_{i})\subseteq W^{\prime}_{i}
. Because
V_{i}=V_{i}^{\prime}\setminus S
and
V_{i}\subseteq L
is not adjacent to
R
, we have
N_{G}(V_{i})\subseteq L\cup S
and
N_{G}(V_{i})\subseteq N_{G_{L}}(V^{\prime}_{i})\cup(V^{\prime}_{i}\setminus V_{i})=N_{G_{L}}(V^{\prime}_{i})\cup(V^{\prime}_{i}\cap S)
, which implies
V_{i}\cup N_{G}(V_{i})\subseteq V^{\prime}_{i}\cup N_{G_{L}}(V^{\prime}_{i})\subseteq W^{\prime}_{i}=W_{i}
.

Property (2).
From the induction hypothesis, we know
(L\cup S)\setminus\bigcup_{(V_{i},W_{i})\in{\cal G}_{L}}V_{i}=\bigcup_{(V_{i},W_{i})\in{\cal G}_{L}}W_{i}\setminus V_{i}
. Combining
V_{i}\subseteq W_{i}
for each
(V_{i},W_{i})\in{\cal G}_{L}
, we have
L\cup S=\bigcup_{(V_{i},W_{i})\in{\cal G}_{L}}W_{i}
. Analogously
R\cup S=\bigcup_{(V_{i},W_{i})\in{\cal G}_{R}}W_{i}
. Therefore,
V(G)=\bigcup_{(V_{i},W_{i})\in{\cal G}}W_{i}
, which implies property (2).

Property (3).
It is simply from the induction hypothesis and the facts that
G_{L}
and
G_{R}
are subgraphs of
G
and that
{\cal G}
collects all
W_{i}
in
{\cal G}_{L}
and
{\cal G}_{R}
.

Property (4).
For each
(V_{i},W_{i})
, it corresponds to some
(V^{\prime}_{i},W^{\prime}_{i})\in{\cal G}_{L}\cup{\cal G}_{R}
such that
V_{i}=V^{\prime}_{i}\setminus S
and
W_{i}=W^{\prime}_{i}
, so
w(W_{i}\setminus V_{i})=w(V_{i}^{\prime}\cap S)+w(W^{\prime}_{i}\setminus V^{\prime}_{i})
. First, we have
\sum_{i}w(V^{\prime}_{i}\cap S)\leq 2w(S)\leq 2\epsilon^{\prime}\boldsymbol{\mathrm{d}}(V(G_{j}))
because
V^{\prime}_{i}
from the same side are disjoint and
w(S)\leq\epsilon^{\prime}\boldsymbol{\mathrm{d}}(L\cup S)\leq\epsilon^{\prime}\boldsymbol{\mathrm{d}}(V(G_{j}))
. Then by the induction hypothesis,
\sum_{i}w(W^{\prime}_{i}\setminus V^{\prime}_{i})\leq\epsilon_{j+1}\cdot(\boldsymbol{\mathrm{d}}(L\cup S)+\boldsymbol{\mathrm{d}}(R\cup S))=\epsilon_{j+1}\cdot(\boldsymbol{\mathrm{d}}(V(G_{j}))+\boldsymbol{\mathrm{d}}(S))\leq\epsilon_{j+1}(1+\epsilon^{\prime})\boldsymbol{\mathrm{d}}(V(G_{j}))
, where the last inequality is because
\boldsymbol{\mathrm{d}}(S)\leq w(S)\leq\epsilon^{\prime}\boldsymbol{\mathrm{d}}(V(G_{j}))
. Therefore, we have
\sum_{i}w(W_{i}\setminus V_{i})\leq(2\epsilon^{\prime}+\epsilon_{j+1}(1+\epsilon^{\prime}))\boldsymbol{\mathrm{d}}(V(G_{j}))\leq\epsilon_{j}\boldsymbol{\mathrm{d}}(V(G_{j}))
.

We finally claim that
{\cal G}
is an
(\epsilon,\phi)
-neighbor-included vertex expander decomposition of
G
because
\epsilon_{1}\leq\epsilon
. Regarding the running time, observe that for a recursive step which cuts a graph
G
by
(L,S,R)
, its two branches on
G_{L}
and
G_{R}
satisfy
|E(G_{L})|+|E(G_{R})|\leq|E(G)|
because we remove all edges inside
S
. Thus the total number of edges in all recursive steps at each depth is still
O(m)
and all recursive step at one depth takes
O(m^{1+o(1)+O(1/r)}\cdot U^{1+O(1/r)}\cdot\log^{O(r^{4})}(mU)/\phi)
. Summing over
O(\log(nU))
levels and set
r=\log\log\log(mU)
, the overall running time is
O(m^{1+o(1)}U^{1+o(1)}/\phi)
and the conductance
\phi
is at least
\epsilon/(m^{o(1)}U^{o(1)})
. Like
Remark

4.5
, we can substitute the subroutine in
Lemma

B.2
with that in
Lemma

B.1
to obtain a faster randomized algorithm with running time improved by an
O(U/\phi)
factor.
∎

Proof of
Theorem

C.3
.

We construct a bipartite graph
G
with
V(G)=V(H)\cup V_{E}
where
V_{E}=\{x_{e}\mid e\in E(H)\}
and
E(G)=\bigcup_{e\in E(H)}\{(x_{e},v)\mid v\in e\}
. Namely, we convert
H
into a graph
G
by substituting each
e\in E(H)
with a vertex
x_{e}
and edges connecting
x_{e}
and
e
’s endpoints. We set the vertex weight and demand functions on
V(G)
as follows. For each
x_{e}\in\{x_{e}\mid e\in E(H)\}\subseteq V(G)
, it has weight
w(x_{e})=1
and demand
\boldsymbol{\mathrm{d}}(x_{e})=1
, while for each
v\in V(H)\subseteq V(G)
, it has weight
w(v)=m
and demand
\boldsymbol{\mathrm{d}}(v)=0
. The weights and demands are bounded by
U=m
. Let
{\cal G}
be an
(\epsilon,\phi)
-neighbor-included vertex expander decomposition of
G
obtained by applying
Theorem

C.5
with parameter
\epsilon
, where
\phi=\epsilon/(|V(G)|^{o(1)}U^{o(1)})=\epsilon/m^{o(1)}
. We construct
{\cal H}
by letting
{\cal H}=\{V^{\prime}_{i}\cap V(H)\mid(V^{\prime}_{i},W^{\prime}_{i})\in{\cal G},V^{\prime}_{i}\cap V(H)\neq\emptyset\}
. We claim that
{\cal H}
is an
(\epsilon,\phi)
-expander decomposition of
H
.

To show
{\cal H}
is a collection of disjoint subsets of
V(H)
. First all
V_{i}
in
{\cal H}
are disjoint because all
V^{\prime}_{i}
in
{\cal G}
are disjoint. To see
\bigcup_{i}V_{i}=V(H)
, we will show
\bigcup_{i}W^{\prime}_{i}=V(G)
and
V_{i}=W^{\prime}_{i}\cap V(H)
. The former is directly from properties (1) and (2) in
Definition

C.4
. The latter is from the following reasons. On one direction, we have
V_{i}=V^{\prime}_{i}\cap V(H)\subseteq W^{\prime}_{i}\cap V(H)
. On the other direction, assume there is some
v\in W^{\prime}_{i}\cap V(H)
not in
V_{i}
. It implies
v\in W^{\prime}_{i}\setminus V^{\prime}_{i}
and
\sum_{i}w(W^{\prime}_{i}\setminus V^{\prime}_{i})\geq w(v^{\prime})=m>\epsilon\cdot\boldsymbol{\mathrm{d}}(V(G))
, a contradiction.

For each
V_{i}\in{\cal H}
corresponding to
(V^{\prime}_{i},W^{\prime}_{i})\in{\cal G}
, we claim that
\Phi(H[V_{i}])\geq h(G[W^{\prime}_{i}])\geq\phi
. To see this, we first claim
V_{i}=W^{\prime}_{i}\cap V(H)
implies
V_{i}\cup N_{G}(V_{i})=W^{\prime}_{i}
. Observe that
V_{i}\cup N_{G}(V_{i})\subseteq V^{\prime}_{i}\cup N_{G}(V^{\prime}_{i})\subseteq W^{\prime}_{i}
. For any
x_{e}\in W^{\prime}_{i}\setminus V(H)
, it must be connected to some
v\in W^{\prime}_{i}\cap V(H)
from the definition of
E(G)
and the fact that
G[W_{i}]
is an expander. Thus
W^{\prime}_{i}\setminus V(H)\subseteq N_{G}(V_{i})
and
W^{\prime}_{i}\subseteq N_{G}(V_{i})\cup V_{i}
. To prove
\Phi(H[V_{i}])\geq h(G[W^{\prime}_{i}])
, consider any cut
(A,B)
of
H[V_{i}]
where
B=V_{i}\setminus A
. it corresponds to a vertex cut
(L,S,R)
in
G[W^{\prime}_{i}]
where
S=\{x_{e}\mid e\in E_{H[V_{i}]}(A,B)\}
,
L=A\cup N_{G[W^{\prime}_{i}]}(A)\setminus S
and
R=B\cup N_{G[W^{\prime}_{i}]}(B)\setminus S
. Observe that
E(H[A])
corresponds to vertex set
N_{G}(A)
, which is the same as
N_{G[W^{\prime}_{i}]}(A)
because
W^{\prime}_{i}=V_{i}\cup N_{G}(V_{i})
. Thus
N_{G}(A)\subseteq L\cup S
and
\boldsymbol{\mathrm{d}}(L\cup S)\geq|N_{G}(A)|=|E(H[A])|
. Similarly, we have
\boldsymbol{\mathrm{d}}(R\cup S)\geq|E(H[B])|
. Therefore,

\Phi_{H[V_{i}]}(A,B)=\frac{|E_{H[V_{i}]}(A,B)|}{\min\{|E(H[A])|,|E(H[B])|\}}\geq\frac{w(S)}{\min\{\boldsymbol{\mathrm{d}}(L\cup S),\boldsymbol{\mathrm{d}}(R\cup S)\}}=h_{G[W^{\prime}_{i}]}(L,S,R),

and
\Phi(H[V_{i}])\geq h(G[W^{\prime}_{i}])
.

To bound the number of crossing hyperedges, we claim that each
x_{e}\in V^{\prime}_{i}\cap V_{E}
for any
V^{\prime}_{i}
in
{\cal G}
corresponds to a non-crossing hyperedge
e
only connecting vertices in
V_{i}
. Otherwise let
v
in another
V_{i^{\prime}}
be an endpoint of
e
. By the definition of
E(G)
, there is an edge
(x_{e},v)\in E(G)
, but
v\notin W^{\prime}_{i}
because
v\notin V_{i}
and
V_{i}=W^{\prime}_{i}\cap V(H)
, which contradicts the fact that
W^{\prime}_{i}=V_{i}\cup N_{G}(V_{i})
. Therefore, all crossing hyperedges correspond to some
x_{e}\in(V(G)\setminus\bigcup_{i}V^{\prime}_{i})\cap V_{E}
, and we can conclude that the number of crossing hyperedges is at most
w(V(G)\setminus\bigcup_{i}V^{\prime}_{i})\leq w(\sum_{i}W^{\prime}_{i}\setminus V^{\prime}_{i})\leq\epsilon\cdot\boldsymbol{\mathrm{d}}(V(G))=\epsilon m
.

Regarding the running time, if we allow randomization, the algorithm can run in
O(|E(G^{\prime})|^{1+o(1)}\cdot U^{o(1)})=O(p^{1+o(1)})
time by
Theorem

C.5
. For the deterministic algorithm, we can only obtain an
O((pm)^{1+o(1)}/\phi)
bound directly from
Theorem

C.5
. However, a tighter bound
O(p^{1+o(1)}/\phi)
can be obtained by a more careful analysis. The bottleneck of the decomposition algorithm is the subroutine in
Lemma

B.2
and the bottleneck of the algorithm in
Lemma

B.2
is the flow decomposition barrier. However, we will run the algorithm on
G^{\prime}
slightly modified from
G
(see
Section

A.2
). Because
G
is a bipartite graph with one side on which every vertex has unit weight, such vertices have capacity
O(1/\phi)
and the length of flow paths in
G^{\prime}
is at most linear to the total capacity of these vertices, i.e.
O(n/\phi)
. Therefore, the running time of the deterministic algorithm only increases by an
O(1/\phi)
factor.
∎
