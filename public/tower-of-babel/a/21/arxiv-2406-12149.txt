Tight Streaming Lower Bounds for Deterministic Approximate Counting
Yichuan Wang

Abstract
We study the streaming complexity of k k -counter approximate counting . In the k k -counter approximate counting problem, we are given an input string in [ k ] n [k]^{n} , and we are required to approximate the number of each j j ’s ( j ∈ [ k ] j\in[k] ) in the string. Typically we require an additive error ≤ n 3 ​ ( k − 1 ) \leq\frac{n}{3(k-1)} for each j ∈ [ k ] j\in[k] respectively, and we are mostly interested in the regime n ≫ k n\gg k . We prove a lower bound result that the deterministic and worst-case k k -counter approximate counting problem requires Ω ⁡ ( k ​ log ⁡ ( n / k ) ) \Omega(k\log(n/k)) bits of space in the streaming model, while no non-trivial lower bounds were known before. In contrast, trivially counting the number of each j ∈ [ k ] j\in[k] uses O ⁡ ( k ​ log ⁡ n ) O(k\log n) bits of space. Our main proof technique is analyzing a novel potential function. Our lower bound for k k -counter approximate counting also implies the optimality of some other streaming algorithms. For example, we show that the celebrated Misra-Gries algorithm for heavy hitters [ MG82 ] has achieved optimal space usage.

1.2
Model: Read-once Branching Programs (ROBP)

We use the read-once branching program (ROBP) model, which is the standard model to study streaming lower bounds. We give an intuitive description of ROBP here. (See
Definition

3.1
for a formal definition.) An ROBP is a layered multigraph. The vertices in each layer characterize all possible memory states of a streaming program. Each vertex (except those in the last layer) has outgoing edges labeled with possible input words, which indicates the next state after reading an input word.

ROBP lower bounds imply streaming lower bounds. Define the width of an ROBP as the maximal number of vertices in any layer. It is easy to observe that if a problem requires width
\geq w
in ROBP, then it requires
\Omega(\log w)
bits of space in the streaming model. We need to mention that by ROBP we do not care about the computational resources needed to compute the next state from the previous state and the input word. However, the ROBP model is still sufficient for us to establish the lower bound results.

1.4
More on the Complexity of Approximate Counting

It was already known that approximate counting is easy in some other computation models, which are slightly stronger than deterministic ROBP but still very weak. Therefore our lower bounds shed light on what is the exact weakest model to compute approximate counting.

If we relax
deterministic
streaming to
randomized
streaming, then approximate counting becomes very easy. Since we can only sample a few words of the input and count the fraction of each word in the sampled part. By concentration inequalities (e.g., the Chernoff Bound), we can show that this randomized algorithm achieves a small error with high probability.

If we consider approximate counting with a small multiplicative error (instead of additive error in our work),
[
Mor78
]
presented a super efficient randomized algorithm, which was called
Morris’ Counter
.
[
NY22
]
improved that algorithm and also gave a matching lower bound. Their optimal algorithm uses
O(\min\{\log n,\log\log n+\log(1/\varepsilon)+\log\log(1/\delta)\})
bits of space to estimate the number of
1
’s in an
n
-bit
0,1
-string up to a multiplicative error of
\varepsilon
, with success probability
1-\delta
. Their lower bound was also generalized to the
k
-counter setting in
[
AHNY22
]
.

Another surprising algorithm for approximate counting is that (deterministic and worst-case)
\mathsf{ApproxCount}[n,n/3]
can be computed in uniform
\mathsf{AC}^{0}

[
Ajt90
]
, which is a very weak complexity class.

The

, and we are given
n
i.i.d. random bits, each of which has probability

to be
1

2.1
Known Techniques do not Work

Before presenting the overview of our proof, we first need to illustrate why proving our lower bound results is difficult.

A popular approach for streaming lower bounds is the

If we can prove a communication lower bound on the length of Alice’s message, then it immediately gives a streaming lower bound. We refer to
[
Rou16
]

However, note that in order for Alice and Bob to compute, say,

1

\leq n/20

\mathsf{ApproxCount}[n,n/10]

3.1
Computation Model: Read-once Branching Programs

We use the following formal definition of the read-once branching program (ROBP) model.

Definition 3.1
.

(Read-once Branching Program)

Let
\Sigma
be a finite alphabet. A length-
n
read-once branching program (ROBP)
P
consists of a directed layered multigraph with
n+1
layers
V_{0},V_{1},\cdots,V_{n}
. For every
0\leq i\leq n-1
, each vertex
v\in V_{i}
has
|\Sigma|
outgoing edges leading to
V_{i+1}
, each labeled a distinct element in
\Sigma
. Vertices in
V_{n}
have zero outgoing edges.
V_{0}
consists of a single “start vertex”:
V_{0}=\{v_{\mathrm{start}}\}
.

An input
x\in\Sigma^{n}
selects a path
(v_{0},v_{1},\cdots,v_{n})
through the graph: the path starts at
v_{0}=v_{\mathrm{start}}
, and upon reaching a vertex
v_{i}\in V_{i}
, the term
x_{i+1}
specifies which outgoing edge to use. Each vertex
v
in
V_{n}
is labeled an output string
\mathrm{output}(v)
, and the output of
P
on input
x
is
P(x)=\mathrm{output}(v_{n})
.

We further require that each vertex can be reached on some input. i.e., there are no useless vertices.

The width of the program is the maximum number of vertices in a single layer.

3.2
Problem: Approximate Counting

We formally define the problem of approximate counting and its variants.

Definition 3.2
.

(
\{0,1\}
-approximate Counting)

For any integer
n\geq 1
and real number
\Delta\geq 0
, define the problem
\mathsf{ApproxCount}[n,\Delta]
as follows: on any input
x\in\{0,1\}^{n}
(
\{0,1\}
is the alphabet and
n
is the input length), a valid output of
x
is a real number
\hat{S}
such that

\left|\hat{S}-\sum_{i=1}^{n}x_{i}\right|\leq\Delta.

We say a program
P
computes
\mathsf{ApproxCount}[n,\Delta]
if on any input
x\in\{0,1\}^{n}
,
P(x)
outputs a valid output of
x
.

Definition 3.3
.

(
k
-counter Approximate Counting)

For any integers
k\geq 2
,
n\geq 1
, and real number
\Delta\geq 0
, define the problem
\mathsf{ApproxCount}_{k\text{\rm\sf-counter}}[n,\Delta]
as follows: on any input
x\in[k]^{n}
(
[k]
is the alphabet and
n
is the input length), a valid output of
x
is a
k
-tuple of real numbers
\left(\hat{S}_{1},\cdots,\hat{S}_{k}\right)
such that

\left|\hat{S_{j}}-\#\{i\in[n]\colon x_{i}=j\}\right|\leq\Delta

for all
j\in[k]
.

We say a program
P
computes
\mathsf{ApproxCount}_{k\text{\rm\sf-counter}}[n,\Delta]
if on any input
x\in[k]^{n}
,
P(x)
outputs a valid output of
x
.

Definition 3.4
.

(
k
-parallel Approximate Counting)

For any integers
k\geq 1
,
n\geq 1
, and real number
\Delta\geq 0
, define the problem
\mathsf{ApproxCount}_{k\text{\rm\sf-parallel}}[n,\Delta]
as follows: on any input
x\in\left(\{0,1\}^{k}\right)^{n}
(
\{0,1\}^{k}
is the alphabet and
n
is the input length), a valid output of
x
is a
k
-tuple of real numbers
\left(\hat{S}_{1},\cdots,\hat{S}_{k}\right)
such that

\left|\hat{S_{j}}-\#\{i\in[n]\colon(x_{i})_{j}=1\}\right|\leq\Delta

for all
j\in[k]
.

We say a program
P
computes
\mathsf{ApproxCount}_{k\text{\rm\sf-parallel}}[n,\Delta]
if on any input
x\in\left(\{0,1\}^{k}\right)^{n}
,
P(x)
outputs a valid output of
x
.

We remind that
\mathsf{ApproxCount}_{2\text{\rm\sf-counter}}
and
\mathsf{ApproxCount}_{1\text{\rm\sf-parallel}}
are equivalent to
\mathsf{ApproxCount}
.

4
Lower Bound for
k
-counter Approximate Counting

The main purpose of this section is to prove
Theorem

4.1
, which is a very general statement of the lower bound for
k
-counter approximate counting. In
Section

4.4
we present the corollaries in various regimes of the parameters, whose statements are more intuitive.

Theorem 4.1
.

(
k
-counter Lower bound)

For any integers
k\geq 2
,
n\geq 1
,
w\geq 1
, and real number
0\leq\Delta\leq\frac{n}{2(k-1)}
, if there exists a length-
n
width-
w
ROBP
P
over alphabet
[k]
such that
P
computes
\mathsf{ApproxCount}_{k\text{\rm\sf-counter}}[n,\Delta]
, then the following holds: let
m
be the largest integer such that
m\leq n-1
and
\binom{m+k-1}{k-1}\leq w
, then

\binom{m+k}{k}+(n-m-1)w\geq\binom{n-2(k-1)\Delta+k-1}{k}.

We remark that one can easily verify that the left-hand side,
\binom{m+k}{k}+(n-m-1)w
, is non-decreasing in
w
.

4.1
Rectangle Labeling

We present a formal definition and some basic properties of the rectangle labeling on the vertices, which is the first step of our proof of the lower bounds.

Let’s define some basic notions. For a set
S\subseteq\mathbb{R}^{k}
and a vector
\mathbf{v}\in\mathbb{R}^{k}
, define
S+\mathbf{v}:=\left\{\mathbf{s}+\mathbf{v}\colon\mathbf{s}\in S\right\}
. We use
\{\mathbf{e}_{1},\cdots,\mathbf{e}_{k}\}
to denote the standard basis of
\mathbb{R}^{k}
. i.e.,
\mathbf{e}_{i}
is the vector with
1
in the
i
th coordinate and
0
’s in all other coordinates.

Definition 4.2
.

(Rectangle Labeling of the
k
-counter Case)

For a length-
n
ROBP
P
over alphabet
[k]
that attempts to compute
\mathsf{ApproxCount}_{k\text{\rm\sf-counter}}[n,\Delta]
, label each vertex
v\in V_{t}

(0\leq t\leq n)
with a
(k-1)
-dimensional rectangle
R(v)
.
R(v)
is defined as
[a_{1},b_{1}]\times\cdots\times[a_{k-1},b_{k-1}]
, here for each
j\in[k-1]
,
a_{j},b_{j}
are the minimal and maximal elements in

\left\{c\in\mathbb{N}\colon\text{$\exists(x_{1},\cdots,x_{t})\in[k]^{t}$ such that $(x_{1},\cdots,x_{t})$ reaches $v$ in $P$ and $\#\{i\in[t]\colon x_{i}=j\}=c$}\right\}.

i.e.,
a_{j},b_{j}
are the minimal/maximal possible number of
j
’s in the first
t
input words to reach
v
in layer
V_{t}
.

For each
0\leq t\leq n
, let
\mathcal{R}_{t}:=\{R(v)\colon v\in V_{t}\}
be the collection of all rectangle labels in layer
V_{t}
.

Rigorously speaking, we should use
R^{(P)}(v)
and
\mathcal{R}_{t}^{(P)}
to show that these rectangles are corresponding to ROBP
P
. Nevertheless, we omit the superscript “
(P)
” when
P
is clear from the context.

We also give some immediate observations on the properties of rectangle labeling.

Proposition 4.3
.

(Properties of Rectangle Labeling of the
k
-counter Case)

For a length-

ROBP

over alphabet
[k]
that attempts to compute

(1)

\mathcal{R}_{0}=\{[0,0]^{k-1}\}
. For each

.

(2)

Suppose

(3)

Suppose

Proof.

(1):

For any

’s respectively. So

. Also note that for each

(3): For any

By using the rectangle labeling, we convert the question of establishing lower bounds for approximate counting into analyzing the rectangle labelings.

Lemma 4.5
.

(Growth of the Potential)

Consider a length-
n
ROBP
P
over alphabet
[k]
that attempts to compute
\mathsf{ApproxCount}_{k\text{\rm\sf-counter}}[n,\Delta]
. Let
w
be the width of
P
, then
\Phi_{0}=0
, and for any
0\leq t\leq n-1
we have

\Phi_{t+1}-\Phi_{t}\geq\max\left\{0,\binom{t+k-1}{k-1}-w\right\}.

Proof.

\Phi_{0}=0
is because by
Proposition

4.3
we have
\mathcal{R}_{0}=\{[0,0]^{k-1}\}
. Thus
\Phi_{0}=0
.

Note that
\phi_{t+1}(x_{1},\cdots,x_{k-1})=0
if
x_{1}+\cdots+x_{k-1}=t+1
. Thus

\Phi_{t+1}-\Phi_{t}=\sum_{(x_{1},\cdots,x_{k-1})\in T_{t,k}}\left(\phi_{t+1}(x_{1},\cdots,x_{k-1})-\phi_{t}(x_{1},\cdots,x_{k-1})\right).

Consider any
(x_{1},\cdots,x_{k-1})\in T_{t,k}
. Suppose when computing
\phi_{t}(x_{1},\cdots,x_{k-1})
, the maximum of
\left(\min\{b_{1}+\cdots+b_{k-1},t\}-x_{1}-\cdots-x_{k-1}\right)
is achieved when
R=R_{0}=[a_{1},b_{1}]\times\cdots\times[a_{k-1},b_{k-1}]
, then by
Proposition

4.3
there exists
R_{1}\in\mathcal{R}_{t+1}
such that
R_{0}\subseteq R_{1}
. Thus when computing
\phi_{t+1}(x_{1},\cdots,x_{k-1})
, by taking
R=R_{1}
we can achieve a larger (or equal) value of
\left(\min\{b_{1}+\cdots+b_{k-1},t\}-x_{1}-\cdots-x_{k-1}\right)
. So
\phi_{t+1}(x_{1},\cdots,x_{k-1})\geq\phi_{t}(x_{1},\cdots,x_{k-1})
.

Furthermore, if
(x_{1},\cdots,x_{k-1})\neq(a_{1},\cdots,a_{k-1})
, pick
j\in[k-1]
such that
x_{j}\geq a_{j}+1
, then
(x_{1},\cdots,x_{k-1})\in R_{0}+\mathbf{e}_{j}
. By
Proposition

4.3
there exists
R_{2}=[a_{1}^{\prime},b_{1}^{\prime}]\times\cdots\times[a_{k-1}^{\prime},b_{k-1}^{\prime}]\in\mathcal{R}_{t+1}
such that
(x_{1},\cdots,x_{k-1})\in R_{0}+\mathbf{e}_{j}\subseteq R_{2}
. Therefore
b_{1}^{\prime}\geq b_{1},\cdots,b_{k-1}^{\prime}\geq b_{k-1}
and
b_{j}^{\prime}\geq b_{j}+1
and

\min\{b_{1}^{\prime}+\cdots+b_{k-1}^{\prime},t+1\}-x_{1}-\cdots-x_{k-1}\geq(\min\{b_{1}+\cdots+b_{k-1},t\}-x_{1}-\cdots-x_{k-1})+1.

So for any
(x_{1},\cdots,x_{k-1})
, if there does not exist
[a_{1},b_{1}]\times\cdots\times[a_{k-1},b_{k-1}]\in\mathcal{R}_{t}
such that

, then
\phi_{t+1}(x_{1},\cdots,x_{k-1})\geq\phi_{t}(x_{1},\cdots,x_{k-1})+1
.

To summarize, over all tuples
(x_{1},\cdots,x_{k-1})\in T_{t,k}
,
\phi_{t+1}(x_{1},\cdots,x_{k-1})-\phi_{t}(x_{1},\cdots,x_{k-1})

, and is

\Phi_{t+1}-\Phi_{t}\geq\max\left\{0,\binom{t+k-1}{k-1}-|\mathcal{R}_{t}|\right\}\geq\max\left\{0,\binom{t+k-1}{k-1}-w\right\}.

∎

Lemma 4.6
.

(Implication of Large
\Phi_{n}

Let

be a length-

\displaystyle\leq\sum_{\begin{subarray}{c}(x_{1},\cdots,x_{k-1})\in\mathbb{N}^{k-1}\\

\displaystyle=\binom{n+k-1}{k}-\binom{n-(k-1)\left\lfloor 2\Delta\right\rfloor+k-1}{k}

∎

Proof of

. ∎

Proof of
Corollary

.

Let

be as stated in
Theorem

. Since

, we only need to prove that

, or equivalently,
n-m-2(k-1)\Delta\leq O\left(\sqrt{n\Delta}\right)

Since
\binom{m+k-1}{k-1}\leq w<\binom{m+k}{k-1}
,

implies

\binom{m+k}{k}+(n-m-1)\binom{m+k}{k-1}\geq\binom{n-2(k-1)\Delta+k-1}{k},

divide both sides by

, we get

\displaystyle 1+\frac{k(n-m-1)}{m+1}

\displaystyle\geq\frac{\binom{n-2(k-1)\Delta+k-1}{k}}{\binom{m+k}{k}}\geq\left(\frac{n-2(k-1)\Delta+k-1}{m+k}\right)^{k}

\displaystyle\geq 1+k\cdot\frac{n-m-2(k-1)\Delta-1}{m+k}+\frac{k(k-1)}{2}\cdot\left(\frac{n-m-2(k-1)\Delta-1}{m+k}\right)^{2}.

\displaystyle\left(n-m-2(k-1)\Delta-1\right)^{2}

\displaystyle\leq(m+k)^{2}\cdot\frac{2}{k-1}\cdot\left(\frac{n-m-1}{m+1}-\frac{n-m-2(k-1)\Delta-1}{m+k}\right)

\displaystyle=\frac{2}{k-1}\cdot\left(\frac{(k-1)(n-m+1)(m+k)}{m+1}+2(m+k)(k-1)\Delta\right)

\displaystyle\leq\frac{4(n+1)(m+k)}{m+1}+4n\Delta.

If

So finally we only need to prove that

0
or
1
, respectively.
∎

We remark that in the case
w=3
, the
f
we compute is just the
\mathsf{Tribe}
function.

Combine with
Corollary

4.8
we get:

Corollary 6.2
.

For any integers
n\geq 1
and
3\leq w\leq n/10
, let
\Delta(n,w)
be the minimal value of
\Delta
such that there exists a length-
n
width-
w
ROBP
P
such that
P
computes
\mathsf{ApproxCount}[n,\Delta]
. Then
\Delta(n,w)\in n/2-\Theta(\sqrt{nw})
.

6.2
Small Error Regime of
k
-counter Approximate Counting

Theorem 6.3
.

For any integers
k\geq 2
,
n\geq 10k
and real number
10\leq\Delta\leq n/10
, there exists a length-
n
width-
w
ROBP
P
over alphabet
[k]
such that
P
computes
\mathsf{ApproxCount}\left[n,\Delta\right]
for some
w\leq\binom{n+k-1-\Omega(\sqrt{n\Delta})}{k-1}
.

Proof.

Let
l:=\left\lceil\sqrt{\frac{n}{\Delta-1}}\right\rceil+1
and
m:=\left\lfloor\sqrt{n(\Delta-1)}\right\rfloor-1
.

Suppose the input is
(x_{1},\cdots,x_{n})
. Let
P
works as follows: in the first to the
\left(n-m\right)
-th layer we count the exact number of
1,2,\cdots,k
’s in
x_{1},\cdots,x_{n-m}
via a simple dynamic programming. Suppose
x_{1},\cdots,x_{n-m}
contains
a_{1},\cdots,a_{k}
many
1,\cdots,k
’s respectively. Now we round
(a_{1},\cdots,a_{k})
to a new tuple
(b_{1},\cdots,b_{k})
(which only depends on
a_{1},\cdots,a_{k}
) such that
b_{j}\in\left\{\left\lfloor\frac{l-1}{l}\cdot a_{j}\right\rfloor,\left\lceil\frac{l-1}{l}\cdot a_{j}\right\rceil\right\}
and
b_{1}+\cdots+b_{k}=\left\lfloor\frac{l-1}{l}\cdot\left(a_{1}+\cdots+a_{k}\right)\right\rfloor=\left\lfloor\frac{l-1}{l}\cdot(n-m)\right\rfloor
. Such
b_{1},\cdots,b_{k}
always exists since
\sum_{j=1}^{k}\left\lfloor\frac{l-1}{l}\cdot a_{j}\right\rfloor\leq\left\lfloor\frac{l-1}{l}\cdot\left(a_{1}+\cdots+a_{k}\right)\right\rfloor\leq\sum_{j=1}^{k}\left\lceil\frac{l-1}{l}\cdot a_{j}\right\rceil
. In the
\left(n-m+1\right)
-th layer to the last layer we exactly count the value of
b_{j}
plus the number of
j
’s in
x_{n-m+1},x_{n-m+2},\cdots
for each
j\in[k]
via a simple dynamic programming.

Suppose
x_{n-m+1},\cdots,x_{n}
contains
c_{1},\cdots,c_{k}
many
1,\cdots,k
’s respectively. Then at the last layer we know the value of
(b_{j}+c_{j})
for each
j\in[k]
. We output
\frac{l}{l-1}\left(b_{j}+c_{j}\right)
as an estimate of the number of
j
’s in
x_{1},\cdots,x_{n}
. Note that the exact number of
j
’s in
x_{1},\cdots,x_{n}
is
(a_{j}+c_{j})
and we have

\displaystyle\left|\frac{l}{l-1}\left(b_{j}+c_{j}\right)-(a_{j}+c_{j})\right|

\displaystyle\leq\left|\frac{l}{l-1}\cdot b_{j}-a_{j}\right|+\frac{c_{j}}{l-1}\leq\frac{l}{l-1}+\frac{m}{l-1}\leq\Delta.

So
P
correctly computes
\mathsf{ApproxCount}\left[n,\Delta\right]
.

Finally we count how much width
P
needs. In the
t
-th layer (
t\in[n-m]
),
|V_{t}|
is the number of tuples
(a_{1},\cdots,a_{k})\in\mathbb{N}^{k}
such that
a_{1}+\cdots+a_{k}=t
. In the
(n-m+t)
-th layer (
t\in[m]
),
|V_{t}|
is the number of tuples
(a_{1},\cdots,a_{k})\in\mathbb{N}^{k}
such that
a_{1}+\cdots+a_{k}=\left\lfloor\frac{l-1}{l}\cdot(n-m)\right\rfloor+t
. Therefore the width
w
of
P
satisfies

\displaystyle w

\displaystyle\leq\max\left\{\binom{n-m+k-1}{k-1},\binom{\left\lfloor\frac{l-1}{l}\cdot(n-m)\right\rfloor+m+k-1}{k-1}\right\}

\displaystyle\leq\max\left\{\binom{n-m+k-1}{k-1},\binom{n-\left\lceil\frac{n-m}{l}\right\rceil+k-1}{k-1}\right\}

\displaystyle\leq\binom{n+k-1-\Omega(\sqrt{n\Delta})}{k-1}.

∎

Combine with
Corollary

4.9
we get:

Corollary 6.4
.

For any integers
k\geq 2
,
n\geq 10k
and real number
10\leq\Delta\leq n/(10k^{2})
, let
w(k,n,\Delta)
be the minimal value of
w
such that there exists a length-
n
width-
w
ROBP
P
such that
P
computes
\mathsf{ApproxCount}_{k\text{\rm\sf-counter}}[n,\Delta]
. Then
w(k,n,\Delta)\in\binom{n+k-1-\Theta(\sqrt{n\Delta})}{k-1}
.

7
Implications in other Streaming Lower Bounds

In this section, we prove streaming lower bounds for other problems. The proofs are based on our lower bound for approximate counting.

7.1
Lower Bound for Heavy Hitters

For simplicity of the notions, we define the
frequency
of an element
u
in a list
L
as the number of
u
’s in
L
.

Definition 7.1
.

For any integers
n,U,k
such that
\min\{n,U\}\gg k\geq 2
,
\mathsf{HeavyHitters}[n,U,k]
is the following problem: given an input string
\mathbf{x}\in[U]^{n}
, we are required to output a list of
k
elements
u_{1},\cdots,u_{k}\in[U]
such that: each element in
[U]
that appears
\geq n/k
times in
\mathbf{x}
is contained in
\{u_{1},\cdots,u_{k}\}
. Moreover, let
f_{i}
be the frequency of
u_{i}
in
\mathbf{x}
, we are also required to output estimates
\widetilde{f_{1}},\cdots,\widetilde{f_{k}}
of
f_{1},\cdots,f_{k}
such that
f_{i}-n/k\leq\widetilde{f_{i}}\leq f_{i}
.

WerecallthattheMisra-Griesalgorithm
[
MG82
]
for
\mathsf{HeavyHitters}[n,U,k]
uses

O\left(k(\log(n/k)+\log(U/k))\right)
bits of space in the streaming model.

Theorem 7.2
.

Foranyintegers
n,U,k
suchthat
\min\{n,U\}\gg k\geq 2
,computing

\mathsf{HeavyHitters}[n,U,k]
requires
\Omega\left(k(\log(n/k)+\log(U/k))\right)
bits of space in the streaming model.

Proof.

First we prove that
\mathsf{HeavyHitters}[n,U,k]
requires
\Omega\left(k\log(U/k)\right)
bits of space.

Consider the following type of inputs: for any subset
I\subseteq[U]
such that
|I|=\left\lfloor n/\left\lceil n/k\right\rceil\right\rfloor
, let
\mathbf{y}(I)
be an input string in
[U]^{n}
such that each
u\in I
appears
\geq\left\lceil n/k\right\rceil
times. Note that when we read
\mathbf{y}(I)
, the list
\{u_{1},\cdots,u_{k}\}
in our output should contain
I
. Also note that since there are
\binom{U}{\left\lfloor n/\left\lceil n/k\right\rceil\right\rfloor}
many subset
I
’s, and each list
\{u_{1},\cdots,u_{k}\}
can only be a valid output for at most
\binom{k}{\left\lfloor n/\left\lceil n/k\right\rceil\right\rfloor}
many
\mathbf{y}(I)
’s. So any algorithm that computes
\mathsf{HeavyHitters}[n,U,k]
need to have
\geq\binom{U}{\left\lfloor n/\left\lceil n/k\right\rceil\right\rfloor}/\binom{k}{\left\lfloor n/\left\lceil n/k\right\rceil\right\rfloor}\geq(U/k)^{\Omega(k)}
many possible outputs, and therefore requires
\geq\log\left((U/k)^{\Omega(k)}\right)\geq\Omega(k\log(U/k))
bits of space.

Then we prove that
\mathsf{HeavyHitters}[n,U,k]
requires
\Omega\left(k\log(n/k)\right)
bits of space.

Note that any algorithm for
\mathsf{HeavyHitters}[n,U,k]
also computes
\mathsf{ApproxCount}_{U\text{\rm\sf-counter}}[n,n/(2k)]
on the same input, and the output of
\mathsf{ApproxCount}
only depends on the output of
\mathsf{HeavyHitters}
: for each
u\in[U]
, if
u
is some
u_{i}
in the output list, then
\widetilde{f_{i}}+n/(2k)
is an estimate for the frequency of
u
with an additive error
\leq n/(2k)
; if
u
is not in the output list, then the frequency of
u
is
\leq n/k
, and thus
n/(2k)
is an estimate for the frequency of
u
with an additive error
\leq n/(2k)
.

Also note that since
U\gg k
, by computing
\mathsf{ApproxCount}_{U\text{\rm\sf-counter}}[n,n/(2k)]
,wecanalsocompute
\mathsf{ApproxCount}_{\left\lceil 2k/3\right\rceil\text{\rm\sf-counter}}[n,n/(2k)]
,andby
Corollary

4.7
,computing

\mathsf{ApproxCount}_{\left\lceil 2k/3\right\rceil\text{\rm\sf-counter}}[n,n/(2k)]
requires
\Omega(k\log(n/k))
bits of space in the streaming model. Therefore we conclude that computing
\mathsf{HeavyHitters}[n,U,k]
requires
\Omega\left(k\log(n/k)\right)
bits of space.

To summarize, computing
\mathsf{HeavyHitters}[n,U,k]
requires

\Omega\left(\max\{k\log(n/k),k\log(U/k)\}\right)\geq\Omega\left(k(\log(n/k)+\log(U/k))\right)

bits of space in the streaming model.
∎

We remark that the proof above depends on the estimates
\widetilde{f_{1}},\cdots,\widetilde{f_{k}}
in the output. If we are only required to output a list
\{u_{1},\cdots,u_{k}\}
, we do not know whether we can prove the streaming lower bound. We leave this as an open problem.

Open Problem 7.3
.

Prove or disprove: for any integers
n,U,k
such that
\min\{n,U\}\gg k\geq 2
, computing
\mathsf{HeavyHitters}[n,U,k]
(without outputting
\widetilde{f_{1}},\cdots,\widetilde{f_{k}}
) requires
\Omega\left(k\log(n/k)\right)
bits of space in the streaming model.

7.2
Lower Bound for Quantile Sketch

We first define the
rank
of an element
u
in a list
L
as the number of elements in
L
that are at most
u
.

Definition 7.4
.

For any integers
n,U
and real number
\varepsilon
such that
\min\{n,U\}\gg 1/\varepsilon\gg 1
, let
\text{\sf{Quantile}}[n,U,\varepsilon]
be the following problem: given a stream of inputs
(x_{1},\cdots,x_{n})\in[U]^{n}
. For each
1\leq t\leq n
, when a query
x\in[U]
arrives after we read
x_{1},\cdots,x_{t}
, we are required to output an estimate of the rank of
x
in
x_{1},\cdots,x_{t}
, with an additive error
\leq\varepsilon t
.

We recall that
[
GSW24
]
’s algorithm for
\text{\sf{Quantile}}[n,U,\varepsilon]
uses
O\left(\varepsilon^{-1}(\log(\varepsilon U)+\log(\varepsilon n))\right)
bits of space in the streaming model.

[
GSW24
]
presented the following conditional streaming lower bound for quantile sketch.

Theorem 7.5
.

(
[
GSW24
]
)

Assumeforanyintegers
n,k
suchthat
n\gg k\gg 1
,computing

\mathsf{ApproxCount}_{k\text{\rm\sf-counter}}[n,n/k]
requires
\Omega(k\log(n/k))
bits of space in the streaming model. Then for any integers
n,U
and real number
\varepsilon
such that
\min\{n,U\}\gg 1/\varepsilon\gg 1
, computing
\text{\sf{Quantile}}[n,U,\varepsilon]
requires
\Omega\left(\varepsilon^{-1}(\log(\varepsilon U)+\log(\varepsilon n))\right)
bits of space in the streaming model.

We remark that
[
GSW24
]
stated the assumption in
Theorem

7.5
as a conjecture. By resolving their conjecture via our lower bounds for approximate counting, we give an unconditional streaming lower bound for quantile sketch.

Theorem 7.6
.

For any integers
n,U
and real number
\varepsilon
such that
\min\{n,U\}\gg 1/\varepsilon\gg 1
, computing
\text{\sf{Quantile}}[n,U,\varepsilon]
requires
\Omega\left(\varepsilon^{-1}(\log(\varepsilon U)+\log(\varepsilon n))\right)
bits of space in the streaming model.

Proof.

By
Theorem

7.5
, we only need to prove that: for any integers
n,k
such that
n\gg k\gg 1
, computing
\mathsf{ApproxCount}_{k\text{\rm\sf-counter}}[n,n/k]
requires
\Omega(k\log(n/k))
bits of space in the streaming model.

Notethatbycomputing
\mathsf{ApproxCount}_{k\text{\rm\sf-counter}}[n,n/k]
,wecanalsocompute

\mathsf{ApproxCount}_{\left\lceil k/3\right\rceil\text{\rm\sf-counter}}[n,n/k]
, and by
Corollary

4.7
, computing
\mathsf{ApproxCount}_{\left\lceil k/3\right\rceil\text{\rm\sf-counter}}[n,n/k]
requires
\Omega(k\log(n/k))
bits of space. Therefore computing
\mathsf{ApproxCount}_{k\text{\rm\sf-counter}}[n,n/k]
requires
\Omega(k\log(n/k))
bits of space in the streaming model.
∎
