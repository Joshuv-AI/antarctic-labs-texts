Abstract

This document presents implementations of fundamental
convolutional neural network (CNN)
layers on the Manticore cluster-based many-core architecture and discusses their characteristics and trade-offs.

Introduction

The
Manticore
architecture
[
1
]
is a many-core processor designed for high-performance, high-efficiency data-parallel floating-point computing.
The implementation proposed in
[
1
]
consists of four chiplets on an interposer, see
Fig.

1
.
Each chiplet contains 1024 cores grouped into 128 clusters, one
8\text{\,}\mathrm{GiB}
HBM2E controller and PHY, as well as L2 memory and I/Os to connect to the other chiplets.

Figure 2:
Simplified block diagram of a Manticore cluster
[
1
]
.

Each cluster, shown in
Fig.

2
, contains eight small 32-bit integer RISC-V cores
[
2
]
, each paired with a large double-precision
floating-point unit (FPU)

[
3
]
, and
128\text{\,}\mathrm{KiB}
of tightly-coupled L1
scratchpad memory (SPM)
organized in 32 banks of
64\text{\,}\mathrm{bit}
width each.
The
FPU
is capable of computing one double-precision floating-point
multiply-and-accumulate (MAC)
operation or two single-precision
MAC
operations in each clock cycle.
As primary means for moving data into and out of L1, each cluster contains two 512-bit-wide
direct memory access (DMA)
engines
[
4
, Section 2.5]
– one for reads and one for writes – which are attached to the L1 memory and share one master port into the on-chip network.

DMA
engines in other clusters can access the L1 memory through an additional 512-bit-wide slave port.
Each cluster has a 64-bit master port to let its cores access external memory and a 64-bit slave port to let cores in other clusters access its L1 memory.
Four clusters form an L1 quadrant, four L1 quadrants form an L2 quadrant, four L2 quadrants form an L3 quadrant, and two L3 quadrants form a chiplet.

Figure 3:
On-chip network of one Manticore chiplet, adapted from
[
4
, Section 4]
.

Manticore’s on-chip network
[
4
, Section 4]
, shown in
Fig.

3
, features:

1.

physically separate networks for traffic by
DMA
engines and cores to minimize the interference between the wide bursts of
DMA
engines and the word-wise accesses of the cores;

2.

a tree topology to combine a high bandwidth between off-chip main memory and any cluster for effective data transfers and low latency between any two cores for efficient concurrency;

3.

fully-connected crossbars within each quadrant to provide units within the same quadrant with a high bandwidth for effective local data sharing; and

4.

the same data width and frequency throughout the
DMA
network to provide a high bandwidth between off-chip main memory and any clusters.

This document describes the implementation of convolutional and fully-connected layers, which together account for
95\text{\,}\mathrm{\%}99\text{\,}\mathrm{\%}
of the floating-point operations in
convolutional neural networks (CNNs)
, on a Manticore chiplet.

1.1
Convolutional Neural Networks (CNNs)

We follow the notation used in Stanford University’s “CS231n Convolutional Neural Networks for Visual Recognition”
[
5
, Module 2: CNNs]
.
There is no single established convention on describing neural networks, but adapting the notation of a course rather than that of a specific paper in the field hopefully makes this document understandable for a wide range of readers.

Figure 4:
A
convolutional neural network (CNN)
with its input layer in red on the left, two hidden layers in blue in the middle, and its output layer in green on the right
[
5
]
.
Every layer of a
CNN
transforms a 3D input volume of neuron activations to a 3D output volume of neuron activations.
The neurons of each layer are arranged in three dimensions: width, height, and depth.

A
CNN
is generally a sequence of layers, and each
layer
transforms one three-dimensional
volume
of activations to another three-dimensional volume of activations.
The layers of a
CNN
, shown in
Fig.

4
, have neurons arranged in three dimensions: width, height, and depth.

Width
and
height
are the
spatial dimensions
, and
depth
is the third dimension of a layer (and not the number of layers in a network).

The neurons in convolutional and fully-connected layers are also called
filter parameters
, because they are the parameters of mathematical filters that are applied to transform an input volume to an output volume.

The
hyperparameters
of a layer, listed in
Table

1
, describe the shape of its input and output volumes and how its filter is applied.

W_{I}

width and height of input volume

D_{I}

depth of input volume

W_{O}

width and height of output volume

D_{O}

depth of output volume

F

receptive field (i.e., width and height) of the filter

P

zero padding elements in the spatial dimensions

S

stride of the filter

B

batch size

Table 1:
Hyperparameters of
CNN
layers.

A convolutional layer transforms an input volume
\mathbf{I}[W_{I}\times W_{I}\times D_{I}]
(i.e., of width and height
W_{I}
and depth
D_{I}
) to an output volume
\mathbf{O}[W_{O}\times W_{O}\times D_{O}]
.
It does this transformation by convolving every two-dimensional
depth slice
(i.e., a matrix with
W_{I}
rows and columns) of the input volume with a two dimensional filter kernel (i.e., a matrix with
F
rows and columns) to produce one two-dimensional depth slice (i.e., a matrix with
W_{O}
rows and columns) of the output volume.
Each pair of input and output depth slice has its own filter kernel.
The overall filter parameters of one layer (also known as the neurons of the convolutional layer) are thus
\mathbf{F}[F\times F\times D_{I}\times D_{O}]
.
Before the convolution with the filter kernel, each input depth slice is
padded
with
P
zeros at the beginning and end of each row and column.
The convolutional filter is then applied with a
stride

S
, i.e., to every
S
-th row and column.
The width and height of the output volume are thus given by
W_{O}=(W_{I}+2P-F)/S+1
.

A fully-connected layer transforms an input volume
\mathbf{I}[W_{I}\times W_{I}\times D_{I}]
to an output volume
\mathbf{O}[1\times 1\times D_{O}]
.
Any fully-connected layer can be represented as convolutional layer by setting
F=W_{I}
(and
S=1
,
P=0
), so the filter parameters of a convolutional layer are
\mathbf{F}[W_{I}\times W_{I}\times D_{I}\times D_{O}]
.

1.2
Notation

1.2.1
Algorithms

For
loops are written as “
for

\mathit{var}\leftarrow\mathit{lb}

to

\mathit{ub}

do

\mathit{body}

end
”, where the loop variable
\mathit{var}
is initialized to
\mathit{lb}
and is incremented in each iteration by one.
The loop
\mathit{body}
is executed as long as
\mathit{var}<\mathit{ub}
.

For
loops executed in parallel by all clusters start with “
parallelize for
” and their loop header ends with “
over clusters do
”.
The schedule of the parallelization is not restricted and may be optimized by the compiler, the
runtime environment (RTE)
, or both.
In this document, we do not detail parallel execution
within
clusters.

Indices into multi-dimensional volumes are written in square brackets with dimensions separated by commas (e.g.,
[a,b,c]
), where the innermost dimension is on the left and the outermost dimension is on the right.
Indexing starts at zero.
A range of indexes is written with a colon, e.g.,
[d:e]
is a one-dimensional range including all elements starting at
d
and ending before
e
, i.e.,
\{n\in\mathbb{N}\mid d\leq n<e\}
.
A range without start and end, such as
[:]
, includes all elements in a dimension.

Data is loaded from main memory into cluster local memory and stored back primarily through
DMA
engine transfers.
Such loads and stores are denoted with
DmaLoad(
)
and
DmaStore(
)
, respectively.

DMA
engine transfers run asynchronous to computation.
That is, the cores of the cluster can continue to compute while the
DMA
engine transfers data.
Of course, the cores can only compute on data in local memory that has already been transferred.
To ensure synchronization between cores and
DMA
engine where necessary, the
DmaWait(
)
function blocks until the data given in the argument is completely transferred.

Each cluster has a constant, unique numerical ID.
Numbering starts at
0
for the first cluster in the first L1 quadrant of the first L2 quadrant of the first L3 quadrant.
The next cluster cluster in that same L1 quadrant has ID
1
, the first cluster in the next L1 quadrant of the same L2 quadrant has ID
4
, and so on.
The cluster ID is denoted as
\mathit{CID}
.

1.2.2
Units

Single- and double-precision floating-point numbers and operations according to IEEE 754 are both supported by Manticore.
In this document, we assume that all numbers in a layer have either single- or double-precision.
This allows for a generic discussion where each number is a
word
.
A single-precision word is
4\text{\,}\mathrm{B}
(four byte) in size, and a double-precision word is
8\text{\,}\mathrm{B}
(eight byte) in size.

The main compute operation in
CNN
layers are
multiply-and-accumulates (MACs)

.
We count one
MAC
as two floating-point operations (since it consists of one multiplication and one addition).
An operation on single-precision numbers is called
single-precision floating-point operation (
\mathrm{spflop}
)
, and an operation on double-precision numbers is called
double-precision floating-point operation (
\mathrm{dpflop}
)
.

Algorithm 1

Implementation of a convolutional layer where the depth slices of the output volumes are parallelized over the clusters.

The implementation of a convolutional layer shown in
Algorithm

1
parallelizes the output depth slices over the clusters.
In the parallel section, the cluster first initializes the output depth slice in its local memory to zero and then loops over the input depth slices.
Within that loop, the cluster loads the input depth slice and the filter parameters for the current pair of input and output depth slices from main memory.
1
1

1

The loading of input data is split into two parts:
Before the loop over the input depth slices, the data for the first iteration of the loop is loaded.
Within the loop, the data for the subsequent iteration of the loop is loaded (except for the last iteration).
The calls to
DmaWait(
)
make sure that the data for the current iteration is present in local memory before the computation.

Then the cluster convolves the input depth slice with the filter parameters and accumulates the result to the output depth slice in local memory.
After it has looped over all input depth slices, the cluster stores the output depth slice to main memory.

This implementation exploits the independence of the output depth slices, necessitating no communication between the clusters.

The main drawback of this implementation is that each cluster loads all input depth slices for each output depth slice it processes, because it cannot store the entire input volume in local memory.
This leads to a lot of data loaded over and over again, which significantly reduces the
compute-to-communication ratio (CCR)
and causes the implementation to become memory-bound.
The implementation in
Section

2.2
will resolve this limitation by processing output depth slices in stacks.

2.1.1
Compute Complexity

The convolution (
Conv(
)
) does
W_{I}\cdot W_{I}\cdot F^{2}

MACs
, and it is placed inside a loop with
D_{I}
iterations.
In total, each cluster task does
W_{I}^{2}\cdot F^{2}\cdot D_{I}

MACs
.
Together, the clusters do
W_{I}^{2}\cdot F^{2}\cdot D_{I}\cdot D_{O}

MACs
.

2.1.2
Space Complexity

Each cluster must store:

1.

its output depth slice, which are
W_{O}^{2}
words;

2.

one input depth slice, which are
W_{I}^{2}
words;

3.

the filter parameters for one input-output depth slice pair, which are
F^{2}
words.

Thus, the minimum local memory required per cluster is
W_{O}^{2}+W_{I}^{2}+F^{2}
words.
For a typical layer with
W_{I}=32
,
F=3
, and
W_{O}=32
(due to
S=1
and
P=1
), this corresponds to
2057
words, or less than
8.1\text{\,}\mathrm{KiB}
for single-precision and
16.1\text{\,}\mathrm{KiB}
for double-precision data.
Both easily fit into the
128\text{\,}\mathrm{KiB}
of local memory of each cluster.

Beyond the minimum local memory requirements, additional storage can be required to hide the latency of loads from off-chip main memory.
Especially the input depth slice (2) and the filter parameters (3), which are loaded once per inner loop iteration, can benefit from a buffer.
The size of that buffer depends on the latency to the main memory.
Assuming a round-trip latency of 256 clock cycles and a data bus width of
$512\text{\,}\mathrm{bit}$=$64\text{\,}\mathrm{B}$
, up to
16\text{\,}\mathrm{KiB}
can be in transfer in the on-chip network.
A buffer of the same size can be added for output depth slice (1), so that data transfers by the
DMA
engine run fully in background.
2
2

2

The
DMA
transfer buffer could be shared by the input depth slices and the filter parameters, since the total amount of data in transfer in the on-chip network does not depend on the type of data being transferred.
This would save local memory in the cluster, but it requires the
RTE
to dynamically partition the
DMA
transfer buffer between different data types and variables, which is not trivial.
We therefore do not assume this
RTE
capability.

In total, roughly
48\text{\,}\mathrm{KiB}
are required as buffers.

2.1.3
Communication Complexity

Inter-Cluster Communication

No communication between the clusters is required.
The clusters exclusively access data that is not shared among the clusters in main memory.

Main Memory Accesses

Inside the parallel section, each cluster executes a loop of
D_{I}
iterations.
Inside that loop, each cluster loads one input depth slice, which are
W_{I}^{2}
words, and the filter parameters for one input-output depth slice pair, which are
F^{2}
words, from main memory.
Over all loop iterations, each cluster thus loads
D_{I}\cdot(W_{I}^{2}+F^{2})
words from main memory.
After the loop, each cluster stores one output depth slice, which are
W_{O}^{2}
words, to main memory.
Together, the clusters in all iterations load
D_{O}\cdot D_{I}\cdot(W_{I}^{2}+F^{2})
words from and store
D_{O}\cdot W_{O}^{2}
words to main memory.

Compute-to-Communication Ratio

Dividing the number of
MACs
by the number of words accessed in main memory gives the
CCR
:

CCR

\displaystyle=

\displaystyle\frac{W_{I}^{2}\cdot F^{2}\cdot D_{I}\cdot D_{O}}{D_{O}\cdot D_{I}\cdot(W_{I}^{2}+F^{2})+D_{O}\cdot W_{O}^{2}}\frac{$\mathrm{MAC}$}{$\mathrm{word}$}

(1)

\displaystyle=

\displaystyle\frac{D_{I}\cdot W_{I}^{2}\cdot F^{2}}{D_{I}\cdot(W_{I}^{2}+F^{2})+W_{O}^{2}}\frac{$\mathrm{MAC}$}{$\mathrm{word}$}.

(2)

To give some numerical intuition:
For typical values
W_{I}=W_{O}=32
,
D_{I}=D_{O}=128
, and
F=3
, the

is ca.
8.9\text{\,}\mathrm{MAC}\text{/}\mathrm{word}
.
That is, the
CCR
for single-precision data is
4.4\text{\,}\mathrm{spflop}\text{/}\mathrm{B}
and for double-precision data
2.2\text{\,}\mathrm{dpflop}\text{/}\mathrm{B}
.
These are very low values, which cause

1

The reason is that the algorithm reloads each input depth slice once per output depth slice.
Thus, the

is mainly determined by the receptive field of the filter,
F

This can also be seen analytically as follows:
Make the reasonable assumption that

(i.e., stride

Then the

CCR

\displaystyle\stackrel{{\scriptstyle W_{O}=W_{I}}}{{=}}

\displaystyle\frac{D_{I}\cdot W_{I}^{2}\cdot F^{2}}{D_{I}\cdot(W_{I}^{2}+F^{2})+W_{I}^{2}}\frac{$\mathrm{MAC}$}{$\mathrm{word}$}

(3)

\displaystyle=

\displaystyle\frac{W_{I}^{2}\cdot D_{I}\cdot F^{2}}{W_{I}^{2}\cdot(D_{I}+1)+F^{2}\cdot D_{I}}\frac{$\mathrm{MAC}$}{$\mathrm{word}$}.

(4)

Typically,

\text{\lx@glossaries@gls@link{acronym}{ccr}{{{}}CCR} }\stackrel{{\scriptstyle D_{I}\gg 1}}{{\approx}}\frac{D_{I}\cdot W_{I}^{2}\cdot F^{2}}{D_{I}\cdot(W_{I}^{2}+F^{2})}\frac{$\mathrm{MAC}$}{$\mathrm{word}$}=\frac{W_{I}^{2}\cdot F^{2}}{W_{I}^{2}+F^{2}}\frac{$\mathrm{MAC}$}{$\mathrm{word}$}.

(5)

Finally, typically
W_{I}^{2}\gg F^{2}

\text{\lx@glossaries@gls@link{acronym}{ccr}{{{}}CCR} }\stackrel{{\scriptstyle W_{I}^{2}\gg F^{2}}}{{\approx}}F^{2}\frac{$\mathrm{MAC}$}{$\mathrm{word}$}.

(6)

Summary

The main drawback of this implementation is that each cluster loads the entire input volume once for each output depth slice it processes.

Algorithm 2

Implementation of a convolutional layer where stacks of depth slices of the output volumes are parallelized over the clusters.

The implementation of a convolutional layer shown in
Algorithm

2
extends
Algorithm

1
by processing output depth slices in stacks: each cluster computes
\Delta_{O}
output depth slices in each parallel task.
Within the parallel task, the stack of output depth slices is initialized in the beginning and stored to main memory at the end as a whole.
Between that, output depth slices are calculated as in
Algorithm

1
.
This stacking of output depth slices increases the reuse factor of each input depth slice and therefore reduces the
CCR
compared to
Algorithm

1
.

Compute Complexity

The convolution (
Conv(
)
) does
W_{I}^{2}\cdot F^{2}

MACs
, and it is placed inside an inner loop with
\Delta_{O}
iterations.
(If
\Delta_{O}

The inner loop is placed inside an outer loop with

Thus, in comparison to

With

Algorithm 4

Implementation of a fully-connected layer where the depth slices of the input volumes are parallelized over the clusters.

The implementation of a fully-connected layer shown in
Algorithm

4
parallelizes the input depth slices over the clusters.
Before the parallel section, each cluster allocates a private output volume
\mathbf{O}^{\prime}
and initializes it to zero.
In the parallel section, the cluster first loads the entire batch of one depth slice of the input volume and then loops over the output depth slices.
Within that loop, the cluster loads the filter parameters for the current pair of input and output depth slices and then enters an inner loop over the batch.
Within the inner loop, the cluster in the
ElemMac(
)
operation multiplies the input depth slice of a batch element with the loaded filter parameters element-wise and then accumulates all products to a single value, which it adds to the output element for the current output depth slice and batch element.
After the parallel section, the private output volumes of all clusters are reduced by summation to a single output volume, which contains the contributions of all input depth slices.

This implementation exploits batching of input and output data, so the filter parameters for each pair of input and output depth slices can be used
B
times.
This is crucial for increasing the operational intensity to a range where the implementation is not memory-bound.

The main problem of this implementation, however, is that each cluster must store a private copy of the entire output volume, which are
D_{O}\cdot B
words.
This limits the maximum output depth (which restricts the generality of the implementation) or the batch size (which limits the operational intensity).
The implementation in
Section

3.2
will resolve this limitation by processing output depth slices in stacks.

3.1.1
Compute Complexity

The element-wise
MAC
operation (
ElemMac(
)
) does
W_{I}\cdot W_{I}

MACs
, and it is placed inside two loops, so it is executed
D_{O}\cdot B
times per cluster task.
In total, each cluster task does
W_{I}^{2}\cdot B\cdot D_{O}

MACs
.
Together, the clusters do
W_{I}^{2}\cdot B\cdot D_{O}\cdot D_{I}

MACs
.

3.1.2
Space Complexity

Each cluster must store:

1.

its private output volume, which are
D_{O}\cdot B
words;

2.

the entire batch of one input depth slice, which are
W_{I}^{2}\cdot B
words;

3.

the filter parameters for one input-output depth slice pair, which are
W_{I}^{2}
words.

Thus, the minimum local memory required per cluster is
D_{O}\cdot B+W_{I}^{2}\cdot(B+1)
words.
For a typical layer with
W_{I}=7
and
D_{O}=4096
and a reasonable batch size of
B=32
, this corresponds to
132\,689
words, or ca.
519\text{\,}\mathrm{KiB}
for single-precision and ca.
1037\text{\,}\mathrm{KiB}
for double-precision data.
This is too much for a cluster with
128\text{\,}\mathrm{KiB}
of local memory.
Decreasing the batch size below 32 usually leads into a memory-bound regime and is therefore not an option.
However, this algorithm can be viable up for
D_{O}
on the order of 512 for single-precision data and
D_{O}
on the order of 256 for double-precision data; more on that below.

Beyond the minimum local memory requirements, additional storage can be required to hide the latency of loads from off-chip main memory.
Especially the filter parameters (3), which are loaded once per very short inner loop iteration, can benefit from a buffer.
The size of that buffer depends on the latency to the main memory.
Assuming a round-trip latency of 256 clock cycles and a data bus width of
$512\text{\,}\mathrm{bit}$=$64\text{\,}\mathrm{B}$
, up to
16\text{\,}\mathrm{KiB}
can be in transfer in the on-chip network.
A buffer of the same size can be added for input depth slices (2), so that data transfers by the
DMA
engine run fully in background.
3
3

3

The
DMA
transfer buffer could be shared by the input depth slices and the filter parameters, since the total amount of data in transfer in the on-chip network does not depend on the type of data being transferred.
This would save local memory in the cluster, but it requires the
RTE
to dynamically partition the
DMA
transfer buffer between different data types and variables, which is not trivial.
We therefore do not assume this
RTE
capability.

In total, roughly
32\text{\,}\mathrm{KiB}
are required as buffers for input depth slices and filter parameters, which leaves
96\text{\,}\mathrm{KiB}
for the cluster-private output volume.
For
W_{I}=7
and
B=32
, this allows
D_{O}\leq 768
for single-precision and
D_{O}\leq 384
for double-precision data.

3.1.3
Communication Complexity

Inter-Cluster Communication

Before and inside the parallel section, the clusters do not communicate between them.
After the parallel section, the private output volumes
\mathbf{O}^{\prime}
of all clusters must to be accumulated to one output volume
\mathbf{O}
.
The optimal way in terms of latency to do this is by tree reduction:
In the first step, for every two clusters in an L1 quadrant, one reads
\mathbf{O}^{\prime}
of the other cluster and adds it to its own.
In the second step, one of the two clusters in an L1 quadrant that read
\mathbf{O}^{\prime}
in step 1 reads it from the other cluster and adds it to its own.
This then goes on until one cluster in one L3 quadrant reads the accumulated
\mathbf{O}^{\prime}
of the other L3 and adds it to its own.
In the first two steps,
\mathbf{O}^{\prime}
is read three times over each L1 network.
In steps three and four,
\mathbf{O}^{\prime}
is read three times over each L2 network.
In steps five and six,
\mathbf{O}^{\prime}
is read three times over each L3 network.
And in the last step,
\mathbf{O}^{\prime}
is read once between L3 networks.
In total,
127\cdot D_{O}\cdot B
words are communicated between clusters to reduce all
\mathbf{O}^{\prime}
s into
\mathbf{O}
.

Main Memory Accesses

Inside the parallel section, each cluster loads the entire batch of one input depth slice, which are
W_{I}^{2}\cdot B
words, from main memory.
Then, in a loop of
D_{O}
iterations, each cluster loads the filter parameters for the current pair of input and output depth slices, which are
W_{I}^{2}
words, from main memory.
Thus, within every cluster task, each cluster loads
W_{I}^{2}\cdot(B+D_{O})
words from main memory.
Together, the clusters in all iterations load
D_{I}\cdot W_{I}^{2}\cdot(B+D_{O})
words from main memory.
After the parallel section, one cluster stores the accumulated output volume,
\mathbf{O}
, which are
D_{O}\cdot B
words, to main memory.

3.1.4

The bulk of accesses to main memory are the loads by each cluster within the parallel region.
Dividing the compute complexity by that memory access complexity gives the

\text{\lx@glossaries@gls@link{acronym}{ccr}{{{}}CCR} }=\frac{W_{I}^{2}\cdot B\cdot D_{O}}{W_{I}^{2}\cdot(B+D_{O})}\frac{\text{MAC}}{\text{word}}=\frac{B\cdot D_{O}}{B+D_{O}}\frac{\text{MAC}}{\text{word}}.

(11)

As typically

Equation

11

Clearly, the

B

D_{O}

To give some numerical intuition for

:
with single-precision data,
D_{O}
may be at most 768 and the
CCR
would then be
30.7\text{\,}\mathrm{MAC}\text{/}\mathrm{word}
or
15.4\text{\,}\mathrm{spflop}\text{/}\mathrm{B}
;
and with double-precision data,
D_{O}
may be at most 384 and the

would then be
29.5\text{\,}\mathrm{MAC}\text{/}\mathrm{word}
or
7.4\text{\,}\mathrm{dpflop}\text{/}\mathrm{B}
.

Summary

This document has presented three implementations of convolutional layers and two implementations of fully-connected layers on the Manticore cluster-based many-core architecture.
By cleverly using the local memory of each cluster and the high-performance on-chip network, two convolutional layer implementations and one fully-connected layer implementation attain a high
CCR
, which allow them to exploit the full computational potential of Manticore.
