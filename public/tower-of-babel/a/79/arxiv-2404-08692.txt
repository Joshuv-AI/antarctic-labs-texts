Abstract

The emergence of Large Language Models (LLMs) has innovated the development of dialog agents. Specially, a well-trained LLM, as a central process unit, is capable of providing fluent and reasonable response for user’s request.
Besides, auxiliary tools such as external knowledge retrieval, personalized character for vivid response, short/long-term memory for ultra long context management are developed, completing the usage experience for LLM-based dialog agents.
However, the above-mentioned techniques does not solve the issue of
personalization from user perspective
: agents response in a same fashion to different users, without consideration of their features, such as habits, interests and past experience. In another words, current implementation of dialog agents fail in “knowing the user”. The capacity of well-description and representation of user is under development.
In this work, we proposed a framework for dialog agent to incorporate user profiling (initialization, update): user’s query and response is analyzed and organized into a structural user profile, which is latter served to provide personal and more precise response.
Besides, we proposed a series of evaluation protocols for personalization: to what extend the response is personal to the different users.

The framework is named as
Apollonion
, inspired by inscription of “Know Yourself” in the temple of Apollo (also known as
Apollonion
) in Ancient Greek.
Few works have been conducted on incorporating personalization into LLM,
Apollonion
is a pioneer work on guiding LLM’s response to meet individuation via the application of dialog agents, with a set of evaluation methods for measurement in personalization.

However, these implementation of dialog agents seldom take user’s features into consideration. User information is solely represented in their queries, which are processed as a common component for prompt construction in response generation. Shot / long-term memory can be somehow considered as user’s historical information, however, its usage aims at retrieving relevant memory for precision.
In summary, user understanding and corresponding profile, advantage of the information is less studied in previous works, leading to a situation that dialog agents know little about the user it is responding and assisting.
Though lacking of user feature does not affect reasonable response, it hinders to provide personalized and more precise answers to users.
For example, on the awareness of user’s diet preference to be non-spicy, food recommendation is more precise and user-friendly. With the information that user has kept hiking for the past several weekends, dialog agents should infer and generate the user profile that his or her interests includes outdoor activities, leading to items recommendation with similar topic such as camping and bicycling facilities.

Based on the observation, we proposed a framework for dialog agents that incorporate user profiling to provide response with individuation:
A structural data is set as user profile, representing and storing the characters (including basic information, deduced interests and etc) of user.
User profile is updated dynamically: an introduced LLM module is utilized to analyze and understand user’s query, leading to reflections for the user. The LLM infers user’ characters based on each of his or her query.
For example, user’s query for a specific topic (“Recommend a salad for lunch”) is regarded as a preference or interests (“This user prefers light food”). Moreover, the latter query may add more information (“What is good for sore throat” presents the reason of searching light food is user’s having sickness, with sore throat as symptom) and change the previous speculation (“I am on a diet, recommend some light but delicious food, like barbecue with less oil” represents that though user is searching light food, his/her true interest is heavy meals.)
The procedure is called “reflection”: an introduced LLM is responsible for deducing underlying information on user’s query, reflecting user’s characters, current situation, leading to a dynamic and informative user profile for latter usage.
The user profile, together with historical conversations are retrieved by LLM based and embedding based method using query, leading to selected profile and conversation to reduce inference time and generate precise response.
Besides, as previous works are lacking in evaluation for personalization. We proposed a series of evaluation of user profiling, reflection, retrieval and response for measuring their effects to personalization.

The framework aims at knowing the user to provide personalized service (from user perspective). Based on its motivation, it is named as
Apollonion
, which is an Ancient Greek temple of Apollon and well-known for its inscription: “Know yourself”. The great philosopher, Socrates cited it as his lifelong goal for he thinks knowing oneself is most fundamental and difficult.
We believe that understanding users serves as a very important step in LLM’s applications.

4.1.1
Meituan User Information Collection

Composing services ranging from food delivery to movie performances, Meituan’s ecosystem enables us to gain a comprehensive understanding of users’ diverse preferences in their daily lives. We primarily consider two kinds of information existed in Meituan’s transaction system: 1) purchase behavior for its fidelity to the user’s genuine intention and 2) item comments, which could help to reveal the user’s personality traits and provide a more fine-grained preference signal.
Additionally, item-level supplementary information such as food categories, movie plots, and medication indications, is introduced to facilitate the induction of user interest or living status.

4.1.2
Behavior Sequence Integration

Despite its thoroughness, the user information is presented in a disorganized manner, which we found to jeopardize the effectiveness of the following preference summarization and personality reasoning methods. Consequently, we integrate the user behaviors and comments into
8
distinct behavior sequences in time order, according to their source categories and theirs semantic similarities to the behavior categories.

4.1.3
User Profile Generation

Based on extracted behavior sequences, we adopt multiple methods to (1) Compress the textual information to ease downstream token limitation; (2) Summarize and reason the user’s preference and personality traits, finally leading to user profile.

Apollonion

Retrieve

Apollonion
sets up
3

(1) Initial Profile: user description based on interaction history in Meituan. (Sec.
4.1

(2) Reflection: user description summarized during conversation (Sec.
4.3

(3) Historical Conversation.
For each component,
Retrieve
implements 3 types of retrieval methods.

Full Content
: Practically, a well-trained foundation model is able to retrieve relevant information according to query to generate proper response.
Retrieve
uses full content as a baseline.

Embedding based Retrieval
: Retrieved components are constituted by a list of elements.
Specially, in Initial Profile,
6
elements are derived to represent user’s corresponding respects.
Reflection progressively collect user profile during conversation. Each query generates a reflection, which is denoted as an elements.
Each conversation (including query and response) is regarded as en elements.

Each elements are embedded by Text2Vec
[
36
]

For example, retrieved profile
\tilde{\mathbf{P}}
is formulated as:

\displaystyle\tilde{\mathbf{P}}=\text{TopK}(\text{emb}(\mathbf{P}),\text{emb}(\mathbf{Q}),k)

(1)

Correspondingly, historical conversation is retrieved:

\displaystyle\tilde{\mathbf{H}}=\text{TopK}(\text{emb}(\mathbf{H}),\text{emb}(\mathbf{Q}),k)

(2)

Normally, we set
k=1

LLM based Retrieval

\displaystyle\tilde{\mathbf{P}}=\text{LLM}(\mathbf{P},\text{Prompt})

(3)

5
Experiments

Evaluation of dialog agents has always been a challenge.
Tradition topics in machine learning such as Computer Vision (CV), Natural Language Processing (NLP) conduct evaluation on well-define setting, where labels are given without ambiguity, such as image classification, objection detection and named entity recognition.
Performance of the proposed method can be directly measured with input features (images, sentences and etc.) for prediction and labels for error computation.
However, dialog agents aim at “How intelligent / humanoid / satisfying it is”. Given a user query, there are abundant of responses that can be regarded as satisfactory. Though human intervention is able to discriminate the difference and score the response, it is still difficult and consuming for scalable and quantification evaluation.
Basically, it measures to what extend the dialog agent performs, instead of a specific output (such as logits for deep learning models) for loss calculation.

Based on that, commercial dialog agents use online performance such as dialog duration, number of conversations for evaluation and etc (Fig.
4
(a)). A higher value represents users are tending to converse and ask assistance from the agents, which indirectly reflects a good performance of the dialog agent.
However, the online statistic are collected in official deployment, which is a very last step in development. Besides, it is difficult to apply online data directly in algorithm design, intermediate offline indicators are necessary.

Traditionally, manual / GPT-based evaluation is widely used in offline response evaluation. The setting employs human or human-like GPT models to examine responses and provide scores according to different standards, such as “fidelty” (how the response resembles human’s wordings), “truthful” (whether the response is faking information) and etc. Though it is straightforward and directly corresponding to final online performance, it is time/cost-consuming and it relies on subjective judgement who may also have bias.
On the contrary, automatic evaluation is commonly used in specific machine learning problems such as image classification, it is rare that dialog agents perform measurable and specific tasks.

In this work, we proposed a series of evaluation protocols for dialog agents, especially on their ability to provide personalization service.
Traditionally, evaluation of LLM based dialog agents heavily reply on a third-party judge LLM, normally more powerful but more expensive.
Besides, it is very difficult to perform scalable evaluation due to the limited input length for the judge LLM.
In stead, the evaluations proposed by
Apollonion
reply on automatic evaluation for quick and cheap evaluation.
As shown in Fig.

These offline indicators are quantifiable and scalable, whose central measurement replies on personalization measurement in Fig.
4

Apollonion

5.2
Evaluation of
Profile Initialization

In this section, we first introduce the principles that a user profile with good quality should adhere to. Then the proposed automatic evaluation metrics for direct user profile quality evaluation are illustrated, followed by the detailed experiment setting and corresponding experimental results.

5.2.1
Quality Principles

Specifically, a user profile with good quality should follow:
(1)
Distinctiveness
: user profile should compose individual traits and preferences that set users different, rather than standardized phrases. It is supposed to be distinctive enough to enable personalized response generation of dialog agent;
(2)
Truthfulness
: The user profile should be faithful to origin user behaviors and comments content without severe hallucination. It should be able to reflect users’ genuine interests or point and thus be beneficial to the honesty of dialog agent;
(3)
Inductiveness
: Instead of enumerating raw data, the user profile should summarize and reason user’s preferences and characteristics. Besides of decreasing the number of token used in downstream tasks, an inductive profile can generalize to future behavior and thus be beneficial to the long-term helpfulness of the dialog agent.

5.2.2
Evaluation Metrics

Following the profile principles, we propose two tasks for comprehensive user profile evaluation: user prediction task and recommendation task, which are illustrated in Figure

(generated by training set), given a group of candidate users composing ground truth user
U_{g}
and
k
negative users
<U_{g},U_{1},...,U_{k}>
.
The users are represented by their behavior sequences
<\tilde{B}_{g},\tilde{B}_{1},...,\tilde{B}_{k}>
in test set, the task aims at discriminate
U_{g}
from the candidates based on the given profile. Mathematically, the task can be formulated as:

\displaystyle\text{Prob}(U_{g}|\mathbf{P}_{g},<\tilde{B}_{g},\tilde{B}_{1},...,\tilde{B}_{k}>)

(7)

In Eq.
7
, we measure the probability of finding the ground truth user
U_{g}
from
<U_{g},U_{1},...,U_{k}>
(represented by
<\tilde{B}_{g},\tilde{B}_{1},...,\tilde{B}_{k}>
) given
\mathbf{P}_{g}
.
By the definition, the user profile should adhere to the three principles, especially distinctiveness, to achieve success on this task.
Specifically the user profile should be distinct and faithful enough to differentiate from negative samples, and be inductive to align with forthcoming behavior sequence
\tilde{B}_{g}
.
Eq.
7
generates the probability for all candidate users,
Acc@1
is denoted as the ground truth user with highest probability.

•

Recommendation Task
: Given
\mathbf{P}_{g}
and a candidate item set that includes n positive items
<I_{\text{pos}_{i}},...,I_{\text{pos}_{n}}>
sampled from
\tilde{B_{g}}
and k negative items
<I_{\text{neg}_{1}},...,I_{\text{neg}_{k}}>
sampled from item pool, the recommendation task aims at prioritizing positive samples over negative ones, by leveraging user profile. Mathematically, the task can be formulated as:

\displaystyle\text{Prob}(<I_{\text{pos}_{1}},...,I_{\text{pos}_{n}}>\xrightarrow{}<I_{\text{neg}_{1}},...,I_{\text{neg}_{k}}>|\mathbf{P}_{g},<I_{\text{pos}_{1}},I_{\text{neg}_{1}},...,I_{\text{pos}_{n}},I_{\text{neg}_{n}}>)

(8)

Given a profile
\mathbf{P}_{g}
, Eq.
8
measures the probability of ranking the positive items (belongs to
U_{g}
) above the negative items.
\alpha\xrightarrow{}\beta
stands for
\alpha
prioritizes
\beta
in an ordered set.
Referring to the task specification, a faithful and inductive profile is necessary for predicting forthcoming interacted items and achieving success on the task. Besides, intuitively better performance on the task is beneficial to the personalization of downstream dialog agent, especially in recommendation related topics.
We report
NDCG@5
and
Recall@5
that positive items are ranked within the top 5.

to
4

7

(9)

5.3
Evaluation of
Response

Apollonion
aims at providing personalized response: users with different profile are expected to be served with diverse under a same query.
For example, a user with interest in outdoor activities should be recommend with high-protein food (instead of light food, such as salad) under the query “Help me with a menu for this lunch”.

However, it is difficult to determine whether a response is personalized:
1) There is no prior works on personalization measurement.
2) Labeling personalization by human effort is consuming and biased.
3) Given a query and profile, personalization measurement of corresponding response by LLM can be regarded as ability of instruction following. The difference between ability for personalization and instruction following should be studied.

Based on the above-mentioned concerns, we proposed a metric for response personalization given query and profile. Formally, for a dialog system
\mathbf{M}_{\theta}
parameterized by
\theta
, where
\theta
includes LLM’s parameters, prompts and hyperparameters.
\mathbf{M}_{\theta}
receives query
\mathbf{Q}
and profile
\mathbf{P}
as input and generate response
\mathbf{R}=\mathbf{M}_{\theta}(\mathbf{Q},\mathbf{P})
as output. A metric for personalization
\text{Pers}(\mathbf{P},\mathbf{R})
is defined with the following properties:

Definition 5.1
(Properties of Personalization)

Given different profile
\mathbf{P}_{i},\mathbf{P}_{j}
and corresponding
\mathbf{R}_{i}
,
\mathbf{R}_{j}
, personalization between a pair of profile and corresponding response should be larger than that of the profile and other response:

\displaystyle\text{Pers}(\mathbf{P}_{i},\mathbf{R}_{i})\quad\text{or}\quad\text{Pers}(\mathbf{P}_{j},\mathbf{R}_{j})>\text{Pers}(\mathbf{P}_{j},\mathbf{R}_{i})\quad\text{or}\quad\text{Pers}(\mathbf{P}_{i},\mathbf{R}_{j})

(10)

We further formulate
Pers
as:

\displaystyle\text{Pers}(\mathbf{R},\mathbf{P})=\text{embedding}(\mathbf{R})^{\top}\text{embedding}(\mathbf{P})

(11)

Basically, Eq.
11
simply embeds
\mathbf{R}
and
\mathbf{P}
to a same space and calculate their similarity using inner production. In practice, we use Text2Vec
[
36
]
for embedding.

Though simple and straight forward, Eq.
11
is proven to be a practical tool for measuring the instruction following ability of
\mathbf{M}_{\theta}
.
Though repeat of profile as response is able to achieve highest personalization score, LLM’s completion ability ensures the response to be reasonable and normal.

Besides, personalization of
\mathbf{R}
is highly related to query: dialog system is expected to provide personalized response for subjective query, such as activity arrangement, food recommendation. But objective query for common knowledge assistance requires response without injection of profile.

Therefore, to evaluate the usage of Eq.
11
and examine whether it can be used in personalization measure, we prepare a series of subjective queries and user profiles. We use a simple
\mathbf{M}_{\theta}
(simply feeding profile and query to LLM) to generate response and calculate the
Pers
. Full prompt incorporating profile and query and subjective queries are listed in App.
7.2.1
.

Specially, we select 11 users and generate 5 personal questions. GPT-4, GPT-3.5, Baichuan-2 are used as foundation model to generate response.
For each query, we use all profiles provided in Sec.
5.2
to generate corresponding responses and calculate
Pers
.
We further compute
Pers
across user and response, leading to a 2-dimension heat map where elements with index
(i,j)
representing

\text{Pers}(\mathbf{P}_{i},\mathbf{R}_{j})
.
By retrieving the top k
Pers
in
l
-th row and determining whether
l
-th response lies in the retrieval set, we further derive a metric for personalization matching accuracy among the profile set.
The accuracy represents the similarity between the generated response and corresponding initial profile, among all user candidates.

6
Conclusion

In this paper, we proposed a framework to deal with the challenge of user information incorporation for dialog agents to provide personal response.
Specially, for each user, we construct an initial user profile (Sec.
4.1
) by collection of user interaction in Meituan and inferred by LLM.
The the user profile and historical conversation are retrieved (Sec.
1
) according to user query, followed by a response module (Sec.
4.4
) to provide personal responses.
Finally, a reflection module (Sec.
4.3
) is set up to infer user’s preference, recent activities according to the query, forming a detailed profile for latter response.

Besides, we proposed a series of evaluation protocols to quantify “Personalization” (Sec.
5.3
) and measure the performance of modules.
The protocols are cheap and scalable, instead of relying third-party LLM for evaluation.

Personal Queries Set

\{\text{num}\}
