Alexandre Vigny

Abstract
. We consider the evaluation of first-order queries over classes of databases that have bounded degree and low degree . More precisely, given a query and a database, we want to efficiently test whether there is a solution, count how many solutions there are, or be able to enumerate the set of all solutions. Bounded and low degree are rather natural notions and both yield efficient algorithms. For example, Berkholz, Keppeler, and Schweikardt showed in 2017 that over databases of bounded degree, not only any first order query can efficiently be tested, counted and enumerated, but the data structure used can be updated when the database itself is updated. This paper extends existing results in two directions. First, we show that over classes of databases with low degree, there is a data structure that enables us to test, count and enumerate the solutions of first order queries. This data structure can also be efficiently recomputed when the database is updated. Secondly, for classes of databases with bounded degree we show that, without increasing the preprocessing time, we can compute a data structure that does not depend on the query but only on its quantifier rank. We can therefore perform a single preprocessing that can later be used for many queries.



1.
Introduction

Query evaluation is one of the most central tasks of a database system and a vast amount of literature is devoted to the complexity of this problem. Given a database
\mathcal{D}
and a query
\varphi
, the goal is to compute the set
\varphi(\mathcal{D})
of all solutions for
\varphi
over
\mathcal{D}
. Unfortunately, the set
\varphi(\mathcal{D})
might be much bigger than the database itself, as the number of solutions may be exponential in the arity of the query. It can therefore be insufficient to measure the complexity of answering
\varphi
on
\mathcal{D}
only in terms of the total time needed to compute the complete result set
\varphi(\mathcal{D})
. Many other algorithmic tasks have been studied to overcome this situation. We can for instance only compute the number of solutions or simply test whether there exists a solution.

In addition, we consider evaluation of queries in a “dynamic setting”, where the databases may be updated by inserting or deleting tuples. In this setting, given a database
\mathcal{D}
and a query
\varphi
, the goal is to compute a
data structure
that represents the result of evaluating
\varphi
on
\mathcal{D}
. After every database update, the data structure must be adapted so that it represents the result of evaluating
\varphi
on
\mathcal{D}^{\prime}
, the new database.

Since we do not wish to compute the entire set of solutions, we want the data structure to enable us to efficiently perform the following tasks:

•

Model check:
Decide whether
\varphi(\mathcal{D})=\emptyset
.

•

Enumerate:
Enumerate the set
\varphi(\mathcal{D})
i.e. to output one by one all elements of
\varphi(\mathcal{D})
.

•

Test:
Given a tuple
\overline{a}
, decide whether it is in
\varphi(\mathcal{D})
.

•

Count:
Compute the number
\#\varphi(\mathcal{D})
of solutions.

The time needed to solve these problems is split between three sub-processes.
The first one is the
preprocessing
, i.e. the process that computes the data structure. The second one is the
update
, i.e. the process that adapts the data structure when the database is updated. The third and final process is the
answering
, or
enumeration
. For the enumeration problem, the
delay
is the maximum time between the outputs of any two consecutive solutions.

We want to perform these processes as efficiently as possible.
For the answering or enumeration process, the best we can hope for is to perform it in constant time (or with constant delay): depending only on the query and independent from the size of the database. For the preprocessing, an ideal time would be linear time: linear in the size of the database with a constant factor depending on the query. The ideal update time depends on what kind of updates are allowed. If we only allow
local updates
that only affect a fixed number of tuples, one can hope for update procedures working in constant or almost constant time.

1.1.
The need of restrictions

Efficient algorithmic procedures for these problems cannot be achieved for all queries over all databases. Even without updates the model checking of first-order (
FO

AW[

If we allow updates, the problem is at least as hard.
This more restricted line of research is quite recent but already some dynamic procedures have been provided: for conjunctive queries over arbitrary relational structures

, for MSO queries over words, trees, and graphs with bounded tree-with

1.2.
Main results

Our first result concerns classes of databases with low degree. We show that for such classes, and for any first order query, there is a data structure that can be computed in time
O(n^{1+\epsilon})
(where
n
is the size of the database) and recomputed in time
O(n^{\epsilon})
when the database is updated.
Using the data structure, the answering processes for the model-checking, testing and counting problems can be performed in constant time. Additionally, the set of solutions can be enumerated with constant delay, without further preprocessing.
See Theorems
7
and
8
for formal statements of that result.

The second result concerns classes of graphs with bounded degree. We expand on existing results and show that a single linear time preprocessing can be used to model-check, test, and count in constant time, and also to enumerate with constant delay the solutions of a whole family of queries. We are also able to update the results in constant time when the database is updated.
We already knew that it was possible when only one query is given as input
[
6
]
.
Additionally, one can note that if a finite family of queries is given as input, it is easy to perform one preprocessing for each query. The parameter would simply be the sum of the sizes of the queries.
However, in our contribution,
the preprocessing time is smaller than the time it would take to perform one preprocessing for each individual query of the inputed family. Even better, our running time matches those of the algorithms that take as input only one query: triply exponential in the quantifier rank of the query, or in our case in the maximal quantifier rank amongst the possible queries.
See Theorems
14
and
15
for formal statements of that result.

1.3.
Related techniques

While the results are new, the techniques used to obtain them are not. We are using Gaifman local form of first order formulas, which is already at the core of the existing results for structures with bounded and low degree
[
6
,
11
,
17
]
.

Enumeration algorithms with constant delay often need a mechanism used to skip irrelevant parts of the input.
An adequate technique (with small variations) has been used several times in previously published results. The firsts appearances where in
[
11
, Section 3.5]

and
[
18
, Section 4]
. Some variations have been used again in
[
6
, Lemma 10.1]
and
[
24
, Lemma 3.10]
. We use a similar structure described in Lemma
12
.
Concerning the counting part of our results, we use a classic inclusion-exclusion argument. This argument is materialized in Lemma
13
, which is analogous to what can be found in
[
25
, Section 7]
.

The proofs of our main results follow the same path. In both cases we focus first on centered queries (Definition
5
). These queries only talk about the neighborhood of one node. When the degree of the database is small, that neighborhood is also small. It is therefore possible to entirely compute all solutions of a given centered query in (pseudo) linear time. The main results are then proved using the fact that all first order queries are combinaisons of centered ones together with adequate tools like Lemmas
12
and
13
.

2.1.
Colored graphs and first-order queries

We define
undirected colored graphs
(or simply graphs) as sets of vertices equipped with a symmetric binary relation (edges) and some unary predicates (colors).

As mentioned in the introduction, our algorithms work for classes of databases. However we will only prove results for classes of graphs. Our algorithms can be adapted to the general case of databases (viewed as relational structure) via standards techniques. Namely, one can take any relational structure and compute a colored version of its adjacency graph.
Interested readers can look at
[
24
]

(Section 2, From databases to colored graphs)
to see the details of this transformation.

We denote by
|G|
the size
|V|
of its vertex set, and
\|G\|
the size of (an encoding of)
G
. Without loss of generality we assume that the set
V
comes with a linear order. If not we arbitrarily choose one. This order induces a lexicographical order among the tuples of vertices.

In this paper, queries are first-order formulas. We assume familiarity with first-order logic (
FO
), over relational structures (see
[
1
,
20
]
for more information). We use standard syntax and semantics for
FO
. In particular we write
\varphi(\overline{x})
to denote the fact that the free variables of the query
\varphi
are exactly the variables in
\overline{x}
. The length of
\overline{x}
is called the
arity
of the query. The
size
of a query
\varphi
is the number of symbols needed to write down the formula and is denoted by
|\varphi|
, and the
quantifier rank
of a query
\varphi
is the depth of nesting of its quantifiers.

A
sentence
(or boolean query) is a formula with no free variable, i.e. of arity 0.

We write
G\models\varphi(\overline{a})
to indicate that
\overline{a}
is a solution for
\varphi
over
G
and note
\varphi(G)
the set of tuples
\overline{a}
such that
G\models\varphi(\overline{a})
.

2.2.
Model of computation

As customary when dealing with linear time, we use Random Access Machines (RAM) with uniform cost measure as a model of computation. More precisely, we need our computational model to perform two tasks.
The first one is to store (ordered) lists with the ability of testing whether an element is in the list in constant time. The ordered version would require logarithmic time to insert (resp. remove) an element to (resp. from) the list.
The second one is to store the values of a given function, and later retrieve the image of a given input in constant time. These requirements are standards, see e.g.
[
5
]

(Section 2, Dynamic Algorithms for Query Evaluation)
.

Both come for free in the RAM model. For any fix integer
k
, it is possible to associate any
k
-tuple of integers to a specific cell of the memory and, given that tuple, to access this cell in constant time. This together with the fact that we can assume that the memory is initially empty (which require a technique called the lazy array initialisation
[
22
]
) enable us to perform these two tasks.

While this works on the RAM model, it shows that we are getting away from real-life computers.

2.3.
Parametrized complexity

All problems encountered in this paper have two inputs: a graph
G
and a query
\varphi(\overline{x})
. However, they play different roles as
|\!|G|\!|
is often very large while
|\varphi|
is generally small. We therefore adopt the parameterized complexity point of view. When we say
linear time
we mean in time
O(|\!|G|\!|)
, the constants hidden behind the “big
O
” depending on
\varphi
, on the class
\mathcal{C}
of graphs under investigation, and possibly on further parameters that will be clear from the context.

We say that a problem is solvable in
pseudo-linear time
if, for all
\epsilon
, it can be solved in time
O(|\!|G|\!|^{1+\epsilon})
. In this case, the constant factor also depends on
\epsilon
. If a subroutine of a procedure depending on
\epsilon
produces an output of size
O(|\!|G|\!|^{\epsilon})
we will say that the output is
pseudo-constant
.

2.4.
Distance and neighborhoods

Given a graph
G=(V,E)
and two elements
a
and
b
of
V
, the
distance
between
a
and
b
noted
\mathrm{dist}(a,b)
is the length of the shortest path between
a
and
b
(the number of edges). If there is no such path,
\mathrm{dist}(a,b):=\infty
. The notion of distance extends to tuples in the usual way, i.e., the distance between two tuples
\overline{a}
and
\overline{b}
is the minimum of the distances between
a_{i}
and
b_{j}
over all
i,j
.

For a positive integer
r
, we write
N_{r}^{G}(a)
for the set of all elements of
V
at distance at most
r
from
a
. The
r
-neighborhood of
a
in
G
, denoted
\mathcal{N}^{G}_{r}(a)
, is the substructure of
G
induced by
N_{r}^{G}(a)
. Similarly, for a tuple
\overline{a}
of arity
k
we let
N_{r}^{G}(\overline{a}):=\bigcup_{i\leq k}N_{r}^{G}(a_{i})
, and we define
\mathcal{N}_{r}^{G}(\overline{a})
as the substructure of
G
induced by
N_{r}^{G}(\overline{a})
.

2.5.
Graphs with bounded and low degree

The
degree
of an undirected graph
G=(V,E)
is the maximal number, over all elements
a
of
V
, of elements
b
in
V
such that
(a,b)\in E
. We note
d(G)
the degree of
G
.

A class
\mathcal{C}
of graphs has
bounded degree
if there is an integer
d
such that every graph of
\mathcal{C}
has degree at most
d
.

A class
\mathcal{C}
of graphs has
low degree
if there is a function
f(\cdot)
such that for any
\epsilon>0
, and for any graph
G
of
\mathcal{C}
, we have
d(G)\leq f(\epsilon)\cdot|G|^{\epsilon}
. Examples of classes of graphs with low degree are classes of graphs with bounded degree and classes of graphs
G
with
d(G)\leq\log(|G|)
.

2.6.
Updates

We allow graphs to be updated. A
local update
of a graph
G
is a graph
G^{\prime}
obtained from
G
by inserting or deleting a node, an edge, or by modifying the membership of a given node to a unary predicate (relabeling). In this paper, we restrict our attention to classes of graphs with bounded or low degree. Therefore when updating a graph, the update is allowed only if the bounds on the degree are maintained in the new graph.

For classes of graphs with bounded degree, given a number
d
it is easy to check in time
O(d)
whether when adding a given edge to a graph of degree at most
d
, we make the new graph to have a degree exceeding
d
or not.

For classes of graphs with low degree, the problem is a little bit trickier. A class of graph
\mathcal{C}
has
effectively low degree
if there is a
computable
function
f(\cdot)
such that for every
\epsilon>0
, and for all graph
G
in
\mathcal{C}
, we have
d(G)\leq f(\epsilon)\cdot|G|^{\epsilon}
.

If
\mathcal{C}
has effectively low degree, then it is possible (for example) to maintain the ordered list of every vertex’s degree in time
\log(|G|)
. Then for any
\epsilon>0
, it is possible to check in time
\log(|G|)=O(f(\epsilon)\cdot|G|^{\epsilon})
whether the degree of
G
still remains below that bound. In this paper, we only talk about classes of graphs with effectively low degree and therefore often omit the “effectively” for better readability.
When dealing with update, the following definition and lemma (although quite elementary) simplify every proof.

Definition
\thethm
.

Let
G
be a graph and
G^{\prime}
a local update of
G
. For an integer
r
in
\mathbb{N}
, a node

is
r
-impacted
if it is: (i) only in
G
, or (ii) only in
G^{\prime}
, or (iii) in both but
\mathcal{N}^{G}_{r}(a)\neq\mathcal{N}^{G^{\prime}}_{r}(a)
.

Lemma 1
.

Let
G
be a graph and
G^{\prime}
a local update of
G
. For any integer
r
in
\mathbb{N}
, the list
L_{u}
of all
r
-impacted nodes has size
O(d^{r})
and can be computed in time

, where

is the degree of

.

3.
Technical definitions

In this section we explain and define some tools that are used throughout the rest of the paper.
We first define the notions of distance queries, distance types, and later explain how they are used to express
FO
queries in a local and succinct way.

3.1.
Distance and types

A distance query is a binary query that only talks about the distance of two nodes in a graph. For all
r\in\mathbb{N}
, the query
\mathrm{dist}_{\leq r}(a,b)
states that there is a path of length at most
r
between
a
and
b
. It can formally be defined as follows:

\mathrm{dist}_{\leq 0}(x,y):=(x=y)\quad\quad\mathrm{dist}_{\leq r+1}(x,y):=\mathrm{dist}_{\leq r}(x,y)~\vee~\exists z~\big(E(x,z)\wedge\mathrm{dist}_{\leq r}(z,y)\big).

Once this is defined, one can also make use of those variations:
\mathrm{dist}_{>r}(x,y):=\neg\mathrm{dist}_{\leq r}(x,y)
and

\mathrm{dist}_{=r}(x,y):=\mathrm{dist}_{\leq r}(x,y)\wedge\mathrm{dist}_{>r-1}(x,y)
.

Definition 2

(Distance type)
.

For a graph
G=(V,E)
and an integer
r
in
\mathbb{N}
, the
r
-distance type
of a tuple
\overline{a}=(a_{1},\ldots,a_{k})
is the undirected graph
\tau_{r}^{G}(\overline{a})
whose nodes are
[1,k]
and edges are exactly the pairs
(i,j)
such that
G\models\mathrm{dist}_{\leq r}(a_{i},a_{j})
. We denote by
{\cal T}_{k}
the set of all possible distance types with
k
elements.

For every integers
r
,
k
and distance type
\tau\in{\cal T}_{k}
, there is a query
\Delta_{r,\tau}(\overline{x})
such that for every graph
G
and tuple
\overline{a}
, we have that
G\models\Delta_{r,\tau}(\overline{a})
if and only if
\tau_{r}^{G}(\overline{a})=\tau
. Furthermore
\Delta_{r,\tau}(\overline{x})
is a boolean combination of distance queries.

For example, if
k=3
and
\tau
only contains the edge
(1,2)
, then
\Delta_{r,\tau}(x,y,z):=\mathrm{dist}_{\leq r}(x,y)\wedge\mathrm{dist}_{>r}(x,z)\wedge\mathrm{dist}_{>r}(y,z)
.

3.2.
Normal form for
FO
queries

The classes of graphs we consider have
small neighborhoods. It is therefore interesting to use the locality of first order logic.

Definition 3

(Local queries)
.

A query
\varphi(\bar{x})
is said to be
r
-local if all its quantifications are relative to elements at distance at most
r
from one of its free variables
\bar{x}
,
i.e. if it uses quantifications of the form
\exists y~\mathrm{dist}_{\leq r}(y,\bar{x})\land\cdots
and
\forall y~\mathrm{dist}_{\leq r}(y,\bar{x})\Rightarrow\cdots
.

Theorem 4

(Gaifman’s theorem. Originally
[
13
]
, see
[
20
, Theorem 4.22]
)
.

For every
FO
formula
\phi(\overline{x})
, there are
r,s\in\mathbb{N}
such that
\phi
is equivalent to a boolean combination of
r
-local queries and sentences of the form:

\exists x_{1}\ldots x_{s}~\Big(\underset{1\leq i\leq j\leq s}{\bigwedge}~\mathrm{dist}_{>2r}(x_{i},x_{j})\wedge\underset{1\leq i\leq s}{\bigwedge}\alpha(x_{i})\Big)

(1)

Here
\alpha(x)
is an
r
-local query. Moreover, this combination is computable from
\phi
,
r=2^{O(q)}
, and
s\leq q
where
q
is the quantifier rank of
\varphi
.

When working with non boolean queries, locality is not enough. We also want to know how the free variables are scattered across the graph.

Definition 5

(Local centered queries)
.

An
r
-local query
\alpha(\overline{x})
is said to be
r
-local centered
if for every graph
G
and tuple
\overline{a}
, if
G\models\alpha(\overline{a})
then the
2r
-distance type of
\overline{a}
has only one connected component.

Note that an
r
-local centered query of arity
k
is also
2kr
-local around any of its free variables.
It is also worth mentioning that an
r
-local query that is unary is necessarily centered. Similarly, the query
\mathrm{dist}_{\leq 2r}(x,y)
is
r
-local centered, and
\Delta_{2r,\tau}(\overline{x})
is
r
-local centered if and only if
\tau
has exactly one connected component.

Corollary 6

(Of Theorem
4
)
.

For every integers
k
and
q
, there is an integer
r
such that every query
\varphi(\overline{x})
of arity
k
and quantifier rank
q
is equivalent to a boolean combination of sentences of the form of Equation
1
and
r
-local queries. Furthermore, once all sentences have been replaced by their truth value, we are left with a strict disjunction of queries of the form:

\alpha_{1}(\overline{x}_{1})\wedge\ldots\wedge\alpha_{p}(\overline{x}_{p})\wedge\Delta_{2r,\tau}(\overline{x}),

(2)

where
r=2^{O(q)}
,
\alpha_{i}(\overline{x}_{i})
are
r
-local centered queries,
(I_{1},\ldots,I_{p})
is a partition of
[k]
and
\tau
is a graph whose connected components are exactly
(I_{1},\ldots,I_{p})
, with
I_{i}:=\{j\leq k~:~x_{j}\in\overline{x}_{i}\}
.

To obtain this corollary from Theorem
4
, we need (among other things) to take a disjunction over all possible
\tau
in
{\cal T}_{k}
. For each
\tau
, the remaining local query can be simplified as all atoms of the form

can be set to false, as soon as

and

are not in the same connected component of
\tau
.

Centered queries

We restrict our attention to

-local centered queries. For these queries, and thanks to the degree bound,
it is actually possible to compute the entire result and to recompute it when the graph is updated.

Lemma 9

Let
\mathcal{C}
be a class of graphs with effectively low degree. For every graph

in

with

, every

•

and

in time

, and

and

in time

Here,

Proof 4.1

(Proof of Lemma
9
)
.

The challenging part of the proof of Lemma
9
is the update part. The preprocessing one can be performed using the update procedure as follows:

•

Start with
G:=\emptyset
. We have
\#\alpha
equals
0
and
L_{\alpha}
is empty.

•

Add all vertices one by one and for each perform the update procedure.

•

Add all edges one by one and for each perform the update procedure.

This gives a preprocessing procedure with the desired complexity. We now turn to the update procedure.

Let
\mathcal{C}
be a class of graph with low degree. Let
G=(V,E)
be a graph in
\mathcal{C}
. Let
\epsilon>0
,
r\in\mathbb{N}
and
\alpha(\overline{x})
be an
r
-local centered query and
k
its arity. Let
\delta>0
small enough that:
\epsilon\geq 6\delta k^{2}r\cdot|\alpha|
and
\log(n)\leq f(\delta)\cdot n^{\delta}
. (Recall
f(\delta)
from the definition of classes of graphs with effectively low degree.)

Let
G^{\prime}=(V^{\prime},E^{\prime})
the graph obtained from
G
after the update.
Let
n=|V^{\prime}|
.
We know that
d(G^{\prime})\leq f(\delta)\cdot n^{\delta}
. Let
L_{u}
be the list of nodes
2kr
-impacted by the local update. By Lemma
1
, we have that
|L_{u}|
has size at most
O(d(G)^{2kr})=O(n^{\delta\cdot 2kr})
and can be computed in similar time. We then apply the following algorithm:

For every
r
-impacted node
a_{1}\in L_{u}
, we study every possible tuple
\overline{a}=(a_{1},\ldots,a_{k})\subseteq N_{2kr}^{G^{\prime}}(a_{1})
.
Then for every such tuple, we test by brut fore whether
\mathcal{N}_{2kr}^{G^{\prime}}(a_{1})\models\alpha(\overline{a})
. As
\alpha
is
r
-local centered, this is true if and only if
G\models\alpha(\overline{a})
. We also test whether
\overline{a}
was already in
L_{\alpha}
. We finally update
L_{\alpha}
and
\#\alpha
accordingly.

For the complexity analysis, the size of
\mathcal{N}_{2kr}^{G^{\prime}}(a_{1})
is bounded by
d(G)^{2kr}
, i.e. bounded by
n^{2\delta kr}
. Therefore the number of considered tuples is bounded by
(\mathcal{N}_{2kr}^{G^{\prime}}(a_{1}))^{k}=n^{2\delta k^{2}r}
.
Then we need time
O(|\mathcal{N}_{2kr}^{G^{\prime}}(a_{1})|^{|\alpha|})
to check with brute force whether
\mathcal{N}_{2kr}^{G^{\prime}}(a_{1})\models\alpha(\overline{a})
, i.e.
O(n^{2\delta kr\cdot|\alpha|})
.
The procedures
add
and
remove
require time
O(\log(n))
to keep

ordered, and thus
O(f(\delta)\cdot n^{\delta})
. Therefore the time spend for every considered

is
O(n^{2\delta kr\cdot|\alpha|})
.
Hence we spend time
O(n^{4\delta k^{2}r\cdot|\alpha|})
for every element

. At the end, the overall complexity is:

O(|L_{u}|\cdot n^{4\delta k^{2}r\cdot|\alpha|})=O(n^{6\delta k^{2}r\cdot|\alpha|})=O(n^{\epsilon})
.

This ends the proof of Lemma

We now have at our disposal a data structure that efficiently evaluates centered queries. In the upcoming sections we generalize it to deal with full
FO
.

4.3.
The enumeration problem

The goal of this section is to prove the enumeration part of Theorem
8
.
Thank to Corollary
6
, every
FO
query is a boolean combination of sentences and
FO
queries of the form:

\alpha_{1}(\overline{x}_{1})\wedge\ldots\wedge\alpha_{p}(\overline{x}_{p})\wedge\Delta_{2r,\tau}(\overline{x}).

Furthermore, once the sentences have been replaced by their truth value, we are left with a strict disjunction of queries of the form above.

We can compute the data structure of Lemma
10
for each sentence of the decomposition. Unfortunately, the value of those sentences over the graph can be impacted by the update. Fortunately, there is only a constant number of possible valuations for the sentences.

Every possible evaluation of the sentences gives us a strict disjunction of queries of the form above. For each, we compute a data structure (described below) allowing us to enumerate their solutions with constant delay.
For the enumeration phase, we first test which sentences are true. This gives us which strict disjunction of queries of the form above needs to be enumerated. We then simultaneously enumerate all of their solutions in lexicographical order and with constant delay.

We therefore only prove the following lemma.

Lemma 11
.

Let
\varphi(\overline{x})
be an
FO
query of the form
\varphi(\overline{x})=\alpha_{1}(\overline{x}_{1})\wedge\ldots\wedge\alpha_{p}(\overline{x}_{p})\wedge\Delta_{2r,\tau}(\overline{x})
,
where
\alpha_{i}
are
r
-local centered queries. Let
G

•

The proof goes by induction on

Proof 4.3

(Proof of Lemma

)
.

Similarly to the proof of Lemma
9
, we only provide the update procedure as the preprocessing can be viewed as performing updates from the empty graph to the desired one.

\bullet
If

. Then

and this case has already been proved by Lemma

. Once

has been stored on a RAM, we can simply run through it.

\bullet
If

. Let
\overline{z}=(\overline{x}_{1},\ldots,\overline{x}_{p-1})
. Consider the following
two queries:

\varphi_{1}(\overline{z}):=\exists\overline{y}_{p}~\varphi(\overline{z},\overline{y}_{p})\quad\text{and}\quad\varphi_{2}(\overline{x}_{p}):=\alpha_{p}(\overline{x}_{p}).

It is easy to see that both

and
\varphi_{2}
have strictly less than
k

variables. Therefore, the induction hypothesis holds for
\varphi_{1}
and
\varphi_{2}
.
A simple (and wrong) idea would be to enumerate all solutions
\overline{c}
in
\varphi_{1}(G)
and for each of them enumerate all solutions
\overline{a}_{p}
in
\varphi_{2}(G)
and output

if and only if

We need, for any tuple

and any tuple

in

and that satisfies the condition:

An adequate technique to solve this issue has been used several times in previously published results. The firsts appearances where in
[
11
, Section 3.5]

and
[
18
, Section 4]
. Some variations have been used again in
[
6
, Lemma 10.1]
and
[

. We now state our version, that is particularly suited to deal with tuples of elements.

Lemma 12
.

Let
\mathcal{C}
be a class of graphs with low degree. Let

be a graph in

,

,

and

be a list of

The idea is to compute a function

4.5.

Here we prove the counting part of Theorem

Proof 4.5

(Proof of Lemma
13
)
.

Let
\varphi(\overline{x})
be an
r
-local query of the form
\alpha_{1}(\overline{x}_{1})\wedge\ldots\wedge\alpha_{p}(\overline{x}_{p})\wedge\Delta_{2r,\tau}(\overline{x})
.
If

. Let
\overline{w}=(\overline{x}_{2},\ldots,\overline{x}_{p})
. Consider the following three queries:

\begin{array}[]{r l}\varphi_{1}(\overline{x}_{1})&:=\alpha_{1}(\overline{x}_{1}),\\
\varphi_{2}(\overline{w})&:=\alpha_{2}(\overline{x}_{2})\land\ldots\land\alpha_{p}(\overline{x}_{p})\land\Delta_{2r,\tau^{\prime}}(\overline{w}),\text{where }\tau^{\prime}\text{ is the restriction of }\tau\text{ to }\overline{w}\\
\varphi_{3}(\overline{x}_{1},\overline{w})&:=\varphi_{1}(\overline{x}_{1})\wedge\varphi_{2}(\overline{w})\wedge\mathrm{dist}_{\leq 2r}(\overline{x}_{1};\overline{w}).\end{array}

For all
(\overline{a},\overline{b})\in G^{k}
, we have that:
G\models\varphi(\overline{a}\overline{b})
if and only if

hence
\varphi(G)=\varphi_{1}(G)\bowtie\varphi_{2}(G)\setminus\{\overline{a},\overline{b}\in G~|~\varphi_{1}(\overline{a})\wedge\varphi_{2}(\overline{b})\wedge\mathrm{dist}_{\leq 2r}(\overline{a},\overline{b})\}
,

which gives
\varphi(G)=\varphi_{1}(G)\bowtie\varphi_{2}(G)\setminus\varphi_{3}(G)
.

And since
\varphi_{3}(G)\subseteq\varphi_{1}(G)\bowtie\varphi_{2}(G)

\#\varphi(G)=\#\varphi_{1}(G)\cdot\#\varphi_{2}(G)-\#\varphi_{3}(G)
.

It is easy to see that both

and

have strictly less than

r
-locals. Therefore, the induction hypothesis holds for

and
\varphi_{2}

and

are arithmetic combinations of number of solutions for

-local centered queries.

We now turn our attention to

. We say that
(\overline{x}^{\prime}_{1};\ldots;\overline{x}^{\prime}_{p^{\prime}})\ll(\overline{x}_{1};\ldots;\overline{x}_{p})
if and only if:

•

(\overline{x}^{\prime}_{1};\ldots;\overline{x}^{\prime}_{p^{\prime}})
is a partition of
\overline{x}
with
p^{\prime}<p
,

•

\overline{x}_{1}\subsetneq\overline{x}^{\prime}_{1}
,

•

\forall 1<j\leq p^{\prime},
there is a

such that
\overline{x}^{\prime}_{j}=\overline{x}_{i}
.

Basically,
\overline{x}^{\prime}_{1}
is the collapse of
\overline{x}_{1}
and at least one of the

. The other

remain unaltered. Given

It follows from those definitions that:

\varphi_{3}(\overline{x})=\bigvee\limits_{(\overline{x}^{\prime}_{1};\ldots;\overline{x}^{\prime}_{p^{\prime}})\ll(\overline{x}_{1};\ldots;\overline{x}_{p})}\alpha^{\prime}_{1}(\overline{x}_{1})\wedge\ldots\wedge\alpha^{\prime}_{p^{\prime}}(\overline{x}^{\prime}_{p^{\prime}})\wedge\Delta_{2r,\tau^{\prime}}(\overline{x}).

in
L_{u}
, step (1), (2), (5) and (7) can be performed in time
O(1)
with our computational model. Step (3) can be performed in time
O(d^{r\ell})
. Step (6) can be performed in time
O(2^{d^{r\ell}})=2^{d^{2^{O(\ell)}}}
. For step (4), the number of elements in
\mathcal{H}
is bounded by
O(2^{(d^{r\ell})^{2}})
. For each we perform a test similar to the one in Step (6), leading again to a total complexity of

.

We now turn to the application of the Basic Data structure.

5.2.
The model checking problem

In this section we prove Theorem
14
. The data structure is almost the one defined in Section
5.1
.

Let
d,\ell
be two integers, and
G
a graph of degree
d
. Assume that
BDS(G,d,\ell)
has been computed. We are now given an
FO
sentence
\phi
of quantifier rank at most
\ell
. By Theorem
4
,
\phi
is equivalent to a boolean combination of sentences of the form:

\exists x_{1}\ldots x_{s}~\Big(\underset{1\leq i\leq j\leq s}{\bigwedge}~\mathrm{dist}_{>2r}(x_{i},x_{j})\wedge\underset{1\leq i\leq s}{\bigwedge}\alpha(x_{i})\Big)

where
\alpha
is an
r
local query and
r=2^{O(\ell)}
. We show how to test whether
G\models\varphi
for sentences of the form above.

•

The first thing we do is to compute
\#\alpha(G)
that is the number of elements of
G
satisfying
\alpha
. Note that
G\models\alpha(a)
if and only if
\mathcal{N}_{r\ell}^{G}(a)\models\alpha(a)
and therefore if and only if
H\models\alpha(c^{H})
, where
H=\mathcal{X}(a)
i.e. the graph isomorphic to
\mathcal{N}_{r\ell}^{G}(a)
.

Hence we have that
\#\alpha(G)=\sum\limits_{\{H\in\mathcal{H}\ |\ H\models\alpha(c^{H})\}}\#L_{H}
. Thus we test for every
H
in
\mathcal{H}
whether
H\models\alpha(c^{H})
, and if so, we add
\#L_{H}
to the total.

•

Once
\#\alpha(G)
has been computed we consider two cases:

–

If
\#\alpha(G)>k\cdot d^{2r}
, there must be
k
elements satisfying
\alpha(x)
at distance greater than
2r
from each other. We can therefore assert that
G\models\varphi
.

–

If
\#\alpha(G)\leq k\cdot d^{2r}
, we compute the list
\alpha(G)
of all elements satisfying
\alpha(x)
. Similarly to the first phase, we have that
\alpha(G)=\bigcup\limits_{\{H\in\mathcal{H}\ |\ H\models\alpha(c^{H})\}}L_{H}
.

We then define
\bm{\tilde{}}{G}:=\bigcup\limits_{a\in\alpha(G)}N_{r}^{G}(a)
. We have that
G\models\varphi
if and only if
\bm{\tilde{}}{G}\models\varphi
. We then use any naive algorithm to test whether
\bm{\tilde{}}{G}\models\varphi
.

This completes the answering phase. Let us now look at the complexity of this procedure. The number of graphs in
\mathcal{H}
and their sizes is a function of
d
and
\ell
and is independent of
|G|
. Therefore computing
\#\alpha(G)
only took time
O(1)
.

More precisely, there are
O\left(2^{(d^{r\ell})^{2}}\right)
elements in
\mathcal{H}
each of size
O(d^{r\ell})
.
Testing whether a given
H
models
\alpha(c^{H})
can therefore be performed in time
O\left(2^{d^{r\ell}}\right)
. The overall complexity of the first phase is therefore
2^{d^{2^{O(\ell)}}}
.

During the second phase, the first case is just a test that can be performed in time
O(1)
. In the second case, we have that
|\bm{\tilde{}}{G}|\leq\#\alpha(G)\cdot d^{r}
. Since
\#\alpha(G)\leq k\cdot d^{2r}
, we have that
|\bm{\tilde{}}{G}|\leq k\cdot d^{3r}
. We then check whether
\bm{\tilde{}}{G}\models\varphi
in time
O\big(|\bm{\tilde{}}{G}|^{|\varphi|}\big)
.

Hence the total time of the second phase
O\big((k\cdot d^{3r})^{|\phi|}\big)=2^{d^{2^{O(|\phi|+\ell)}}}

The enumeration problem

This section is devoted to the enumerating part of Theorem

and the radius

The first algorithm only uses the Basic Data Structure and works by induction on the number

of free variables in

Lemma 17
.

For every fixed

is computed, then for any unary

of quantifier rank

Lemma 18
.

For every fixed

, once

and quantifier rank

and

The following induction on

explains why these two lemmas are enough. Fix

Proof sketch of Lemma

Once

5.4.
The testing problem

In this section we prove the testing part of Theorem

Naive algorithm

Let

5.5.
The counting problem

Here we prove the counting part of Theorem
15

Let
(G,d,\ell)

6.
Conclusion

We proved that over structures with bounded or low degree and for every first-order query, we can efficiently compute and recompute a data structure allowing to answer in constant time (or with constant delay) the model-checking, testing, counting and enumeration problems. It was already known for classes of graphs with bounded degree
[
6
]
but not for classes of graph with low degree.

In the case of structure with bounded degree we showed that, without increasing the preprocessing time, we can compute a data structure that does not depend on the query but only on its quantifier rank. We can therefore compute a single preprocessing that can later be used for a variety of queries.

-local queries. We are then given a tuple
\overline{a}=(a_{1},\ldots,a_{k-1})
and we want to enumerate all
b
such that
(\overline{a},b)\in\varphi(G)
.

•

First, for every sentence of the decomposition, test their truth value on
G
.

•

We are left with a strict disjunction of queries of the form

\alpha_{1}(\overline{x}_{1})\wedge\ldots\wedge\alpha_{p}(\overline{x}_{p},y)\wedge\tau_{2r_{q}}(\overline{x}_{1};\ldots;\overline{x}_{p})
where all
\alpha_{i}(\overline{x}_{i})
are
r_{q}
-locals (we can assume without loss of generality that
y
appears on
\alpha_{p}
). We enumerate the appropriate
b
for each query from the disjunction one by one.

•

We now have a tuple
\overline{a}=\overline{a}_{1},\ldots,\overline{a}_{p}
and a query
\alpha_{1}(\overline{x}_{1})\wedge\ldots\wedge\alpha_{p}(\overline{x}_{p},y)\wedge\tau_{2r_{q}}(\overline{x}_{1};\ldots;(\overline{x}_{p},y))
. We check whether
G\models\tau_{2r_{q}}(\overline{x}_{1};\ldots;\overline{x}_{p-1})
and
G\models\alpha_{i}(\overline{a}_{i})
for all
i<p
. If this is not the case, we can safely enumerate the empty set.

•

It remains to enumerate all
b
such that
G\models\alpha_{p}(\overline{a}_{p},b)
and
\mathrm{dist}(a_{i},b)>2r_{q}
for all
a_{i}\not\in\overline{a}_{p}
. We distinguish two cases whether
\overline{a}_{p}=\emptyset
.

–

Case
1
,
\overline{a}_{p}\neq\emptyset
. Let
a_{j}
be an element of
\overline{a}_{p}
. All matching
b
must be in
\mathcal{N}^{G}_{kr_{q}}(a_{j})
and therefore
G\models(\alpha_{p}(\overline{a}_{p},b))
if and only if
\mathcal{N}^{G}_{r_{\ell}}(a_{j})\models(\alpha_{p}(\overline{a}_{p},b))
.
We can therefore look at all the elements of
N^{G}_{2kr_{q}}(a_{j})
(there are only
d^{2kr_{q}}
), and for each test whether
G\models\alpha_{p}(\overline{a}_{p},b)
and
\mathrm{dist}(a_{i},b)>2r_{q}
for all
a_{i}\not\in\overline{a}_{p}
.

We can produce the list of these elements in time
O(2^{d^{r_{\ell}}})
and then enumerate the list.

–

Case
2
,
\overline{a}_{p}=\emptyset
. In this case, we run through the list of all
b
such that
G\models\alpha_{p}(b)
. For each such
b
, we test in constant time whether it is at distance greater than
2r_{q}
to
\overline{a}
. If so we output it, otherwise we go to the next element of the list. We now explain how to run through all
b
such that
G\models\alpha_{p}(b)
and why this procedure as constant delay.

To compute the list of all
b
such that
G\models\alpha_{p}(b)
, it is enough to see that
G\models\alpha_{p}(b)
if and only if
H\models\alpha_{p}(c^{H})
where
H=\mathcal{X}(a)
. Therefore we have that:

\{b\in G\ |\ G\models\alpha_{p}(b)\}~=~\bigcup\limits_{\{H\in\mathcal{H}\ |\ H\models\alpha_{p}(c^{H})\}}L_{H}

We can test in time in constant time whether a graph
H
satisfies the condition and there is only a constant number of them. Hence in constant time (triply exponential in
\ell
), we can run through all
b
such that
G\models\alpha_{p}(b)
.

For the constant delay, it is enough to see that testing whether
b
is at distance greater than
2r_{q}
from
\overline{a}
can be performed in constant time, more precisely
O(kd^{2r_{q}})
. Furthermore at most
k\cdot d^{2r_{q}}
element are at distance less than
2r_{q}
to
\overline{a}
and will not be enumerated. This makes the delay constant, i.e. only triply exponential in
\ell
.

This ends the proof of Lemma
18
.

B.2.
Fast enumeration algorithm

In this section we explain how to improve the data structure for the enumeration part of Theorem
15
. Ideally, we would like the delay to be independent from the degree of the graph.

Theorem 25
.

Let
d,\ell
in
\mathbb{N}_{\scriptstyle\geq 1}
and a graph
G
of degree bounded by
d
. There is a data structure that:

•

can be computed in time
O(|G|)
,

•

can be recomputed in constant time (triply exponential in
\ell
) when
G
is subject to a local update, and

•

upon a query
\varphi(\overline{x})
of arity
k
and quantifier rank
q
with
k+q\leq\ell
perform a final task in constant time (triply exponential in
|\phi|+\ell
) such that afterward, the solution for
\varphi(\overline{x})
over
G
can be enumerated with delay
O(k^{3})
.

The data structure for Theorem
25
combine ideas from different parts of previous algorithms.
We first use the efficient testing procedure i.e. Lemma
19
, precisely the fact that there is a data structure allowing to test the distance up to some threshold in time
O(k^{2})
.
We also use the Lemma
12
that allows to skip some part of a list.
This enable us to improve the two lemmas (Lemmas
17
and
18
) that are at the core of the proof of the enumerating part of Theorem
15
.

The proof of Lemma
17
already matches our new standards, i.e. the list of solution for a unary query can be enumerated with delay truly
O(1)
, after an additional preprocessing depending on the degree of the graphs (triply exponential in the size of the query).

Concerning the improvement of Lemma
18
, we need to improve the structure using Lemma
12
and Lemma
19
. For each list
L_{H}
of the Basic Data Structure, we compute the skip pointers
{\textup{SKIP}}(b,I)
(as in Lemma
12
). Additionally, for every distance query
\mathrm{dist}_{\leq r}(x,y)
with
r\leq 2^{\ell}
, we maintain the data structure allowing to test the solutions in time
O(1)
.

During the enumeration phase, instead or running a BFS algorithm, we can test all the distances in time
O(k^{2})
. We can therefore test whether we are looking at a solution in time
O(k^{2})
. If not we can use a skip pointer that directly gives us the next solution.

The procedure in the proof of Lemma
18
work in time
O(k^{2})
after the additional preprocessing (triply exponential in the size of the query).

The overall delay becomes
O(k^{3})
because of the
k
recursive calls produced by the global procedure.

B.3.
Fast algorithm for the testing problem

Proof B.3

(Proof of Lemma
19
)
.

The only thing that we add (before knowing the query) is a structure that contains the value of the function
\delta_{r}(x,y)
that test the distance up to threshold
r
. I.e.
\delta_{r}(a,b)=r^{\prime}
with
r^{\prime}\leq r
if
G\models\mathrm{dist}_{=r^{\prime}}(a,b)
and
\delta_{r}(a,b)
is undefined otherwise. Here,
r
is obtain from
\ell
with Corollary
6
, and
r=2^{O(\ell)}

The size of the domain of
\delta_{r}
is
O(|G|\cdot d^{r})
and a simple BFS algorithm up to distance
r
for all node of the graphs is enough to compute
\delta_{r}
. When an update occurs, we have to perform the BFS for all
r
-impacted nodes, which can be done in constant time (triply exponential in
\ell
).

Let
(G,d,\ell)
fixed. Let
r=2^{O(\ell)}
, we assume that
BDS(G,d,\ell)
and the function
\delta_{r}(\cdot,\cdot)
has been computed.

We are now given an
FO
query
\varphi(\overline{x})
with quantifier rank
q
and arity
k
such that
q+k\leq\ell
. Similarly to the Naive algorithm, we can assume without loss of generality that
\varphi(\overline{x})=\alpha_{1}(\overline{x}_{1})\wedge\ldots\wedge\alpha_{p}(\overline{x}_{p})\wedge\Delta_{2r,\tau}(\overline{x})
where
(\overline{x}_{1},\ldots,\overline{x}_{p})
is a partition of
\overline{x}
, and all
\alpha_{i}(\overline{x}_{i})
are
r
-locals centered.

We then compute a final structure in constant time (triply exponential in
|\varphi|
) before any tuple is given. The structure is composed of function
SOL_{i,H}(\cdot)
for all
i\leq p
and
H
in
\mathcal{H}
. We define and compute these function as follows:

For all
i\leq p
, for all
H
in
\mathcal{H}
and for all tuple
\overline{a}_{i}
(with
|\overline{a}_{i}|=|\overline{x}_{i}|
), we test whether
H\models\alpha_{i}(\overline{a}_{i})
. If so, we set
SOL_{i,H}(\overline{a}_{i}):=1
. Those functions are stored and ready to be accessed in constant time.

The complexity of this final phase is triply exponential in

graphs in

. For a fixed
H

.

We are now given a tuple
\overline{a}
in

.

•

For all
(a_{j},a_{j^{\prime}})
in

\delta_{2r}(a_{j},a_{j^{\prime}})
. Therefore in time

holds in

•

For all
\overline{a}_{i}
in
\overline{a}

•

Let
H_{i}=\mathcal{X}(a_{i}^{1})

Since

Hence

Therefore

This ends the testing algorithm. The structure can be updated in time triply exponential in
