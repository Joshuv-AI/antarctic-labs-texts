Introduction

String processing is an important field of research in theoretical computer science.
There are lots of results for various classic string processing problems such as string matching
[
KMP77
,
BM77
,
KR87
]
, longest common substring, edit distance.
The development of string processing algorithms has led to the discovery of many impactful computer science concepts and useful tools, including dynamic programming, suffix tree
[
Wei73
,
Far97
]
and trie
[
Fre60
]

String processing also has applications in various fields such as bioinformatics
[

[

[

A natural extension of string processing is to do it between
compressed strings
. Ideally, the time cost of the string processing between compressed strings would be independent of the decoded lengths of the strings. Since the compressed string can be much shorter than the original string, this would significantly save computation time. Of course, whether such fast string processing is possible depends on what kind of compression scheme we are using.

Run-Length Encoding (RLE) is a simple way to compress strings. In RLE, the consecutive repetition of a character (run) is replaced by a character-length pair – the character itself and the length of run.
For example, the RLE of the string
aaabcccdd
is
\texttt{a}^{3}\texttt{b}^{1}\texttt{c}^{3}\texttt{d}^{2}
.
RLE is a common method to compress fax data
[
ITU04
]
, and is a part of the JPEG and TIFF image standard
[
ISO94
,
ISO98
]
as well.
String processing on RLE strings has been studied a lot. Apostolico, Landau, and Skiena gave an
\mathcal{O}(n^{2}\log n)
-time algorithm on finding Longest Common Subsequence between two RLE compressed strings
[
ALS99
]
, where
n
is the length of the compressed strings.
Hooshmand, Tavakoli, Abedin, and Thankachan obtained an
\mathcal{O}(n\log n)
-time algorithm on computing the Average Common Substring with RLE inputs
[
Hoo+18
]

Chen and Chao proposed an algorithm to compute the edit distance between two RLE strings
[
CC13
]
, and the result was further improved to near-optimal by Clifford, Gawrychowski, Kociumaka, Martin and Uznanski in
[
Cli+19
]
, which runs in
\mathcal{O}(n^{2}\log n)
time.

Alternatively, another way to speedup string processing is to use
quantum algorithms
. If we use quantum algorithms for string processing, it is possible to get time cost
sublinear
in the input length because the quantum computer can read the strings in superposition. One of the earliest such results was by Hariharan and Vinay
[
HV03
]
, who constructed an
\tilde{\mathcal{O}{}}(\sqrt{n})
-time string matching quantum algorithm, in which Grover’s search
[
Gro96
]
and Vishkin’s deterministic sampling technique
[
Vis90
]
were used to reach this near-optimal time complexity.
Recently, Le Gall and Seddighin
[
LS22
]
obtained several sublinear-time quantum algorithms for various string problems, including an
\tilde{\mathcal{O}{}}(n^{5/6})
-time algorithm for longest common substring (LCS), an
\tilde{\mathcal{O}{}}(\sqrt{n})
-time algorithm for longest palindrome substring (LPS), and an
\tilde{\mathcal{O}{}}(\sqrt{n})
-time algorithm for approximating ulam distance.
Another recent work is done by Akmal and Jin
[

]
, using synchronizing sets
[
KK19

with quantum walk

In this work, we combine the two above ideas and investigate the possibility of using

Is it possible to have a quantum string processing algorithm whose time cost is sublinear in the encoded lengths of the strings and independent of the decoded lengths?

1.2
Overview of the algorithm

The LCS algorithm in
[
LS22
]
starts with a binary search on the solution size
d
, in which, different algorithms are used to find an LCS of length at least
d
for different sizes. For
d\leq n^{1/3}
, an element distinctness algorithm is used; for
d\geq n^{1/3}
, an amplitude-amplified sampling algorithm is used.

Here, to find the longest common substring from two RLE strings
A
and
B
of decoded length
\tilde{n}
, we do a binary search on the decoded length of the answer
\tilde{d}\in[\tilde{n}]
. In each iteration of the binary search, we check whether a common substring
s
of decode length
|\tilde{s}|=\tilde{d}
exists.
The checking algorithm consists of two sub-algorithms, one finds the “short” answers, and the other finds the “long” ones. We say a common substring
s
is “short” if its
encoded length
is not greater than
n^{1/3}
, otherwise we say it is “long”. Different from
[
LS22
]
, in our work, both sub-algorithms are executed in every iteration of the binary search.

finding short answers

We use Ambainis’ element distinctness between two sets of size
n
to find an LCS from two RLE strings, in which we consider
i\in[n]
and
j\in[n]
being “equal” if they correspond to the first run of a common substring
s
in
A
and
B
, respectively
4
4

4

This is possible because Ambainis’ algorithm can solve problems more general than element distinctness. See e.g.
[
CE05
]
. More precisely,
i\in[n]
and
j\in[n]
are “equal” if and only if
f(i,A,j,B)\vee f(j,B,i,A)=1
, where
f(i,A,j,B)
is a predicate that is
1
iff a common substring of decoded length
\tilde{d}
and encoded length at most
n^{1/3}
starting from the beginning of
A[i]
and within
B[j]
exists.
Here we utilize the observation that, for the RLE of an LCS
s
, the first character of
s
must correspond to either the beginning of a run in
A
, the beginning of a run in
B
, or both of them.
f(i,A,j,B)
can be seen as finding a substring with the assumption that it starts from the beginning of
A[i]
. The separation of
f(i,A,j,B)
and

enables us to use skip list and range minimum query to construct a data structure on
B
that, for any given

Element distinctness costs
\tilde{\mathcal{O}{}}(n^{2/3}\cdot T)
time where

is the time to compare two elements.
Here two elements are compared by using Grover’s search to find a mismatched run, with some extra
\tilde{\mathcal{O}{}}(1)
-time checks. Hence the time complexity is
\tilde{\mathcal{O}{}}(n^{2/3}\cdot\sqrt{n^{1/3}})=\tilde{\mathcal{O}{}}(n^{5/6})
.

finding long answers

Consider the following procedure: choose an integer
n^{1/3}<\ell\leq n
. Sample two RLE strings
P=A[i:i+2\lfloor\ell/3\rfloor-1]
and
S=B[j:j+\ell-1]
with uniformly random

.
Suppose a common substring
s
with encoded length

exists, then the probability that
P
being a substring of
s
and
S
covers the corresponding
P
in
B
at the same time, is
\Omega(\ell^{2}/n^{2})
.
By first finding the corresponding
P
in
S
with pattern matching with time cost
\tilde{\mathcal{O}{}}(\sqrt{\ell})

2\ell

\tilde{\mathcal{O}{}}(\sqrt{\ell})

This procedure succeeds with probability
\Omega(\ell^{2}/n^{2})
.
With amplitude amplification, we can boost the success probability of the whole above procedure to

\ell

\tilde{\mathcal{O}{}}(\sqrt{n^{2}/\ell^{2}}\cdot\sqrt{\ell})=\tilde{\mathcal{O}{}}(n/\sqrt{\ell})

We run the amplified procedure repeatedly with

\mathcal{O}(\log n)

\mathcal{O}(\log n)
queries to the prefix-sum oracle.
Then we move on to show the internals of the main algorithm.

Overview of the algorithm

To find a longest common substring from two RLE strings
A
and
B
, we do a binary search on the decoded length of the answer
\tilde{d}\in[\tilde{n}]
. In each iteration of the binary search, we check whether a common substring
s
such that its decode length
|\tilde{s}|=\tilde{d}
exists.
The checking algorithm consists of two sub-algorithms, one finds the short answers, and the other one finds the long ones. Both of them are executed in every iteration of the binary search. Here, we say a common substring
s
is “short” if its
encoded length
is not greater than
n^{1/3}
, otherwise we say it is “long”. The algorithm for short answers is discussed in
subsection 3.2
, and the one for long answers is discussed in
subsection 3.3
.

3.1
Inverse Prefix-Sum

In
subsection 2.4
, we introduced the notion of prefix-sum,
which can be seen as a translation of indices
i
of an RLE string to the corresponding indices
\tilde{i}
in the decoded string. Here we show how to do an inverse-ish translation, that sends
\tilde{i}
to
i
.
This translation is utilized heavily in our algorithm.

Lemma 11

(Inverse Prefix-sum,
P^{\text{ -1}}_{S}
)
.

Given a prefix-sum oracle of an RLE string
S
of encoded length
\mathcal{O}(n)
, one can calculate the function
P^{\text{ -1}}_{S}:[\tilde{n}]\rightarrow[n]
that maps indices of
\tilde{S}
, the decoded string, to the corresponding ones of
S
in
\mathcal{O}(\log n)
time.

Proof.

Let
\tilde{i}\in[\tilde{n}]
be a decoded index. To find the corresponding index
i\in[n]
, we do a binary search over
[n]
to find the
i\in[n]
such that
P_{S}[i-1]<\tilde{i}\leq P_{S}[i]
. The process is correct since the prefix-sum is strictly-increasing.
∎

A naïve approach

The prefix-sum oracle,
P^{\text{ -1}}_{S}
, together with the oracle to the RLE string,
S
, are sufficient to build the oracle for the corresponding decoded string, since a query to
\tilde{S}[\tilde{i}]
can be answered with
C(S[P^{-1}_{S}(\tilde{i})])
.
As a consequence,
\mathsf{LCS\text{-}RLE}^{\mathsf{p}}
can be solved using algorithms for LCS problem on decoded strings, such as
[
LS22
]
,
[
AJ22
]
, and
[
GT23
]
, with an extra logarithmic factor of the encoded length to the time complexity.
For example, applying this approach on
[
LS22
]
gives a
\tilde{\mathcal{O}{}}(\tilde{n}^{5/6})
-time algorithm.
Note that this method does not utilize the fact that RLE strings could be much shorter than the decoded ones.
And that is what we take advantage of in our algorithm, whose time cost is
\tilde{\mathcal{O}{}}(n^{5/6})
.

•

(\Leftarrow)

•

∎

3.2.1
Quantum walk search

To find a
\tilde{d}
-witness pair in

[

]
in the formulation of
[
LS22
]
, in which we walk on a direct product of two Johnson graphs.

A Johnson graph, denoted as
J(n,r)
, consists of
\binom{n}{r}
vertices, each being an
r

R
of a list
S
of size
n
.
In
J(n,r)
, two vertices
R_{1}
and
R_{2}
are connected iff
|R_{1}\cap R_{2}|=r-1
.

In the direct product of two Johnson graphs
J_{A}(n,r)
and
J_{B}(n,r)
, each vertex is a pair of subsets
(R_{A},R_{B})
, in which
R_{A}
comes from
J_{A}
and
R_{B}
comes from
J_{B}
, and the vertex is connected to another one
(R^{\prime}_{A},R^{\prime}_{B})
if and only if
|R_{A}\cap R^{\prime}_{A}|=r-1
and
|R_{B}\cap R^{\prime}_{B}|=r-1
.
In a search problem, vertices that one wants to find are called
marked
vertices.

Associated with each vertex
(R_{A},R_{B})
, is a data structure
D(R_{A},R_{B})
that supports three operations: setup, update, and checking; whose costs are denoted by
s(r)
,
u(r)
, and
c(r)
, respectively.
The setup operation initializes the
D(R_{A},R_{B})
for any vertex
(R_{A},R_{B})
;
the update operation transforms
D(R_{A},R_{B})
into
D(R^{\prime}_{A},R^{\prime}_{B})
which is associated with a neighbouring vertex
(R^{\prime}_{A},R^{\prime}_{B})
of
(R_{A},R_{B})
in the graph;
and the checking operation checks whether the vertex
(R_{A},R_{B})
is marked.
The MNRS quantum walk search algorithm can be summarized as:

Theorem 15

(MNRS Quantum Walk search
[
Mag+11
]
, in the formulation of
[
LS22
]
)
.

Assume the fraction of the marked vertices is zero or at least
\delta
.
Then there is a quantum algorithm that always rejects when no marked vertex exists; otherwise, with high probability, it finds a marked vertex
(R_{A},R_{B})
.
The algorithm has complexity

\tilde{\mathcal{O}{}}\left(s(r)+\frac{1}{\sqrt{\delta}}\left(\sqrt{r}\cdot u(r)+c(r)\right)\right).

(3.1)

In our setting, the list
S
is
[n]
, and the Johnson graphs
J_{A}(n,r)
and
J_{B}(n,r)
are associated with the input RLE strings
A
and
B
, respectively.
A vertex
(R_{A},R_{B})
is marked if and only if a
\tilde{d}
-witness pair
(i_{A},i_{B})\in R_{A}\times R_{B}
exists.
The fraction of marked vertices
\delta
is lower-bounded by
\Omega(r^{2}/n^{2})
since in the worst case there is only one
\tilde{d}
-witness pair exists, and thus
\binom{n-1}{r-1}^{2}
out of
\binom{n}{r}^{2}
pairs of subsets are marked.
The data structure

consists of two instances of another data structure
D_{A}
and

, one for each subset. So

can be viewed as the pair

with some extra operations on top of it.

.

Associated with an RLE string

of length

and an

of

that supports the following operations:

(1)

of

(2)

where

(3)

: given an index

associated with another RLE string

and a positive number
\tilde{d}\leq\tilde{n}
, in
\tilde{\mathcal{O}{}}(T(n))

and

Let’s see how to build

,
in which
R(S_{B}[i])=2+B_{i}
.
Then, using
\mathcal{A}
, we find the length of LCS of
S_{B}
with itself.
Here, what
\mathcal{A}
outputs is basically the decode length of
S_{B}
, i.e.
|\widetilde{S_{B}}|
.
From that, we can calculate the parity of
B
easily,
and thus
25
is proven.

Proof.

Given an
n
-bit binary string
B
, we can construct an RLE string
S_{B}
as:

S_{B}=\texttt{a}^{B_{1}+2}\texttt{b}^{B_{2}+2}\texttt{a}^{B_{3}+2}\texttt{b}^{B_{4}+2}\cdots\gamma^{B_{n}+2},

(4.1)

where
\gamma
is
a
if
n
is odd, otherwise it is
b
.

Then we assume the algorithm
\mathcal{A}
exists.
With
S_{B}
as the inputs, the output of
\mathcal{A}
, the decoded length of LCS between
S_{B}
and itself, is

\mathcal{A}(S_{B},S_{B})=|\tilde{S}_{B}|=\sum_{i=1}^{n}(B_{i}+2)=2n+\sum_{i=1}^{n}Bi,

(4.2)

which has the same parity as
\bigoplus_{i\in[n]}B_{i}
, i.e. the parity of
B
.
Therefore, by checking the lowest bit of
\mathcal{A}(S_{B},S_{B})
, we can solve
\mathsf{PARITY}
with no extra query.
Since solving
\mathsf{PARITY}
requires
\Omega(n)
queries, solving
\mathsf{DL\text{-}LCS\text{-}RLE}
needs at least the same number of queries.
∎

4.2
Lower Bounds on
\mathsf{EL\text{-}LCS\text{-}RLE}
and
\mathsf{LCS\text{-}RLE}

In this section, we show an
\tilde{\Omega{}}(n)
lower bound on both
\mathsf{EL\text{-}LCS\text{-}RLE}
(
26
) and
\mathsf{LCS\text{-}RLE}
(
27
).
More precisely, we reduce
\mathsf{PARITY}
to
\mathsf{EL\text{-}LCS\text{-}RLE}
, which is then reduced to
\mathsf{LCS\text{-}RLE}
.

Here is a high-level overview of the first reduction (from
\mathsf{PARITY}
to
\mathsf{EL\text{-}LCS\text{-}RLE}
).
We encode an
n
-bit binary string
B=B_{1}B_{2}\cdots B_{n}
into an RLE string
S_{B}
,
in a way similar to
Equation 4.1
in the proof of
25
.
We then assume an algorithm
\mathcal{A}
of query complexity
Q(\mathcal{A})
for
\mathsf{EL\text{-}LCS\text{-}RLE}
exists.
Using
\mathcal{A}
, we construct an algorithm to compare the decoded length of
S_{B}
, i.e.
|\tilde{S}_{B}|
, with any
k>0
.
We then use binary search on
k
to find
|\tilde{S}_{B}|
, invoking
\mathcal{A}
for
\mathcal{O}(\log n)
times.
From
|\tilde{S}_{B}|
, we calculate the parity of
B
without extra query.
Finally, since
\mathsf{PARITY}
has query lower bound
\Omega(n)
,
Q(\mathcal{A})
is at least
\tilde{\Omega{}}(n)
, getting
26
below.

Lemma 26

(Lower Bound of
\mathsf{EL\text{-}LCS\text{-}RLE}
)
.

Any quantum oracle algorithm
\mathcal{A}
requires at least
\tilde{\Omega{}}(n)
queries to solve
\mathsf{EL\text{-}LCS\text{-}RLE}
, with probability at least
2/3
.

Proof.

Given an
n
-bit binary string
B=B_{1}B_{2}B_{3}\ldots B_{n}\in\{0,1\}^{n}
,
we can construct an RLE string

S_{B}=\texttt{a}^{2B_{1}+2}\texttt{b}^{2B_{2}+2}\texttt{a}^{2B_{3}+2}\texttt{b}^{2B_{4}+2}\ldots\gamma^{2B_{n}+2},

(4.3)

where
\gamma
is
a
if
n
is odd, otherwise it is
b
.

For every positive natural number
k
, we can also construct an RLE string, simply by repeating another character:

S_{k}=\texttt{c}^{k}.

(4.4)

We then concatenate
S_{B}
and
S_{k}
together with different characters in the middle, getting

S_{B,\texttt{@},{k}}:=S_{B}\texttt{@}^{1}S_{k}\quad\text{and}\quad S_{B,\texttt{\#},{k}}:=S_{B}\texttt{\#}^{1}S_{k}.

(4.5)

Let us check what we know about the LCS
\tilde{s}
between
\widetilde{S}_{B,\texttt{@},{k}}
and
\widetilde{S}_{B,\texttt{\#},{k}}
.
Firstly,
@
and
#
are not in
\tilde{s}
since none of them appears in
\widetilde{S}_{B,\texttt{@},{k}}
and
\widetilde{S}_{B,\texttt{\#},{k}}
at the same time.
Secondly,
\tilde{s}
is a substring of
\tilde{S}_{B}
or
\tilde{S}_{k}
, but not both,
because the character set of
\tilde{S}_{B}
,
\{\texttt{a},\texttt{b}\}
, and the one of
\tilde{S}_{k}
,
\{\texttt{c}\}
, do not intersect.
Finally,
\tilde{s}
is the “longest” common substring, so it is the longest one among
\tilde{S}_{B}
and
\tilde{S}_{k}
.

Now we assume the algorithm
\mathcal{A}
in
26
exists,
and it has query complexity
Q(\mathcal{A})
.

Additionally, the success probability of
\mathcal{A}
can be boosted from constant to high probability with an extra logarithmic factor on its query complexity (
2
).

With
S_{B,\texttt{@},{k}}
and
S_{B,\texttt{\#},{k}}
as inputs,
\mathcal{A}
outputs

\displaystyle\mathcal{A}(S_{B,\texttt{@},{k}},S_{B,\texttt{\#},{k}})

\displaystyle=\begin{cases}|S_{k}|,&|\tilde{S}_{k}|>|\tilde{S}_{B}|\\
|S_{B}|\text{ or }|S_{k}|,&|\tilde{S}_{k}|=|\tilde{S}_{B}|\\
|S_{B}|,&|\tilde{S}_{k}|<|\tilde{S}_{B}|\end{cases}

(4.6)

\displaystyle=\begin{cases}1,&k>|\tilde{S}_{B}|\\
n\text{ or }1,&k=|\tilde{S}_{B}|\\
n,&k<|\tilde{S}_{B}|\end{cases}.

(4.7)

For a given
B
, we use
\mathcal{A}_{B}({}\cdot{})
as a shorthand for
\mathcal{A}(S_{B,\texttt{@},{\,\cdot\ }},S_{B,\texttt{\#},{\,\cdot\ }})
in the following text.
Note that when
k=|\tilde{S}_{B}|
, two answers (
n
and
1
) are possible,
and we only assume
\mathcal{A}
outputs one of them.
Thus,
\mathcal{A}_{B}(k)
is non-deterministic when
k=|\tilde{S}_{B}|
.
We will resolve this issue with a property of binary search later.

To find
|\tilde{S}_{B}|
, we do a binary search on
k
to find a
k^{\prime}\in[2n,4n]
, such that
\mathcal{A}_{B}(k^{\prime}-1)=n
and
\mathcal{A}_{B}(k^{\prime})=1
.
11
11

11

The search range
[2n,4n]
comes from
2n\leq|\tilde{S}_{B}|=\sum_{i}(2B_{i}+2)\leq 4n
.

In the binary search,
\mathcal{A}_{B}
will not be called with the same
k
twice so it does not matter whether
\mathcal{A}_{B}
and the underlying
\mathcal{A}
are deterministic or not.
So from now on, we treat
\mathcal{A}_{B}
as if it were deterministic.

Since there are two possible outputs for
\mathcal{A}_{B}(k)
when
k=|\tilde{S}_{B}|

(the middle case in
Equation 4.7
),
each corresponds to a different result
k^{\prime}
for the binary search.
If
\mathcal{A}_{B}(|\tilde{S}_{B}|)
outputs
1
, we will get
k^{\prime}=|\tilde{S}_{B}|
, the desired result.
But if
\mathcal{A}_{B}(|\tilde{S}_{B}|)
outputs
n
, we will get
k^{\prime}=|\tilde{S}_{B}|+1
instead.
We can detect if the latter one is the case from the parity of
k^{\prime}
because
|\tilde{S}_{B}|=2\sum_{i=1}^{n}(B_{i}+1)
is always even, and thus we can correct the result accordingly.

With
|\tilde{S}_{B}|
in hand, we then check if

\sum_{i=1}^{n}B_{i}=\frac{1}{2}\sum_{i=1}^{n}\left(2B_{i}+2\right)-n=\frac{1}{2}|\tilde{S}_{B}|-n

(4.8)

is odd or even to determine the parity of
B
.

Alternatively, we can XOR the lowest bit of
n
with the second-lowest bit of
k^{\prime}
, which is the same as the one of
|\tilde{S}_{B}|
, directly.
Then the result is the parity of
B
.
This allows us to avoid correcting
k^{\prime}
explicitly.

In total, we use
Q(\mathcal{A})\log^{2}n
queries to solve
\mathsf{PARITY}
.
The logarithmic factors come from boosting
\mathcal{A}
to high probability and the binary search.
Finally, solving
\mathsf{PARITY}
requires
\Omega(n)
queries so we have

Q(\mathcal{A})\log^{2}n\in\Omega(n)\implies Q(\mathcal{A})\in\Omega(n/\log^{2}n)\in\tilde{\Omega{}}(n),

(4.9)

and
26
follows.
∎

Furthermore, an algorithm solving
\mathsf{LCS\text{-}RLE}
outputs a triplet
(i_{A},i_{B},\ell)
, where
\ell
is the encoded length of LCS between the inputs, which is also the answer to
\mathsf{EL\text{-}LCS\text{-}RLE}
.
I.e.
\mathsf{EL\text{-}LCS\text{-}RLE}
can be reduced to
\mathsf{LCS\text{-}RLE}
with no extra query to the input strings.
As a result,
\mathsf{LCS\text{-}RLE}
shares the same query lower bound with
\mathsf{EL\text{-}LCS\text{-}RLE}
.
This gives the corollary below.

Corollary 27

(Lower Bound of
\mathsf{LCS\text{-}RLE}
)
.

Any quantum oracle algorithm
\mathcal{A}
requires at least
\tilde{\Omega{}}(n)
queries to solve
\mathsf{LCS\text{-}RLE}
, with probability at least
2/3
.

is our motivation and justification to introduce the prefix-sum oracles.
