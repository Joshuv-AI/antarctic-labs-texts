Sean Kauffman, Kim G. Larsen, Martin Zimmermann

Abstract
Nfer is a Runtime Verification language for the analysis of event traces that applies rules to create hierarchies of time intervals. This work examines the complexity of the evaluation and satisfiability problems for the data-free fragment of nfer. The evaluation problem asks whether a given interval is generated by applying rules to a known input, while the satisfiability problem asks if an input exists that will generate a given interval. By excluding data from the language, we obtain polynomial-time algorithms for the evaluation problem and for satisfiability when only considering inclusive rules. Furthermore, we show decidability for the satisfiability problem for cycle-free specifications with a NExpTime lower bound and undecidability for satisfiability of full data-free nfer.

1
Introduction

Nfer
is an interval logic for analyzing and comprehending event traces that has been used in a wide range of applications, from anomaly detection in autonomous vehicles
Kauffman et al. (2021)
to spacecraft telemetry analysis
Kauffman et al. (2018)
.
However, its high complexity demands that users restrict the features they incorporate into their applications to ensure tractability.
Despite this, no work exists that examines the runtime complexity of
nfer
without data; an obvious restraint on the power of the language that more closely resembles propositional interval logics like Halpern and Shoham’s logic of intervals
Halpern and Shoham (1991)
and Duration Calculus
Goranko et al. (2004)
.
These languages still tend to be undecidable in the general case, however, so it is unclear if this restriction on
nfer
helps with tractability.
In this article, we show that evaluation of the data-free variant of
nfer
is tractable and, futhermore, satisfiability for this variant is tractable with additional restrictions.

Nfer
was developed by scientists from NASA’s Jet Propulsion Laboratory in collaboration with other researchers to analyze event traces from remote systems like spacecraft
Kauffman et al. (2016b)
;
Kauffman et al. (2016a)
;
Kauffman et al. (2018)
.
In
nfer
, specifications consist of rules that describe and label relationships between time periods called intervals.
Applying
nfer
rules to an event trace yields a hierarchy of these intervals that is easier for humans and machines to comprehend than the raw events.

Nfer
originated from prior work at Jet Propulsion Laboratory on trace analysis using rule-based programming systems
Havelund and Joshi (2014)
.
Existing systems such as the Scala DSL, Logfire
Havelund (2015)
had been used at NASA for some time and other, more similar, systems like PyContract
Dams et al. (2022)
are still in use.
However, these are more general tools for data analysis with tight integrations with general-purpose programming languages, and users have sometimes found them too verbose for many tasks
Havelund and Joshi (2015)
.

Nfer
is also a rule-based formalism like these tools, but is far more specialized for representing traces as hierarchies of intervals, leading to a more concise syntax for that task.

The conciseness of
nfer
can be seen in the motivating example of “warning analysis” for the Curiosity rover (Mars Science Laboratory)
Kauffman et al. (2018)
.
On the rover, events can be mis-labeled as
warning
s when a thread servicing the radio is starved by higher priority threads.
Previously, an ad-hoc Python script had been used to filter these anomalous
warning
s, but this proved to be error prone, slow, and hard to maintain.

Nfer
required only five rules to search for conditions where the benign
warning
s were known to occur and mark them as
ok
.

Nfer
resembles data-flow languages such as those found in Complex Event Processing and Stream Runtime Verification systems, which compute information about streaming data using predefined rules.
Like
nfer
, Complex Event Processings process low-level event data into high-level abstractions
Cugola and Margara (2012)
, but these tend to be more general-purpose, with more verbose rules and slower performance.
For example, Siddhi
Suhothayan et al. (2011)
is an open-source Complex Event Processing used by Uber, eBay, and PayPal for use cases like fraud analysis and policy enforcement.
Complex Event Processings typically employ a SQL-like rule syntax applied to event streams to query arbitrary abstractions, which makes them powerful but generic tools, prone to verbose rules and slower response times.
In one experiment, the Python embedding of
nfer
was found to be more than 30 times faster than Siddhi
Kauffman et al. (2021)
.

Stream Runtime Verification systems support computing arbitrary streams of outputs from streams of input data and include examples such as TeSSLa
Convent et al. (2018)
, Lola
D’Angelo et al. (2005)
, and Striver
Gorostiaga and Sánchez (2018)
.
Stream Runtime Verification languages tend to be good at computing streams of values, but are not as well suited to creating abstractions of events.
One study found it took 34 lines of TeSSLa to compute the result of four lines of
nfer

Kauffman (2021)
.
The data-flow language Quantified Regular Expressions
Alur et al. (2016)
is simpler and achieves linear-time evaluation complexity, but only supports the computation of a single quantitative result from a stream of events, making it much less expressive and unable to handle a use case such as the warning analysis described above.

The need for both expressiveness and performant execution makes the complexity problem for
nfer
evaluation interesting.
Recent work analyzing the problem has shown that it is undecidable for the full language, but with various decidable fragments
Kauffman and Zimmermann (2022)
;
Kauffman and Zimmermann (2024)
.
Introducing less expressive language fragments for tractability purposes is a common technique for data-flow languages
Leucker et al. (2018)
;
Baumeister et al. (2026)
.
These
nfer
-language fragments mostly remain intractable, however, with
PTime
complexity only possible by employing a meta-constraint on the size of the results that may not be practical in many cases.
One obvious restriction omitted by those works, however, was data-free
nfer
, which has some precedent in the literature.

Like data-flow languages,
nfer
typically operates on intervals with data, but here we define a data-free fragment of the language.
Data-free
nfer
is expressive enough for many use cases, having been used, for example, to analyze the Sequential Sense-Process-Send (SSPS) dataset
Kauffman et al. (2018)
.
Data-free
nfer
is also the target for an algorithm to mine rules from real-time embedded systems
Kauffman and Fischmeister (2017)
.
What has not been known until now is how much of the expressive power of
nfer
stems from its ability to analyze data and how much is inherent in its temporal interval reasoning capabilities.

Other works have examined the evaluation complexity of interval-based logics without data.
Halpern et al.introduced an interval temporal logic and explored its decidability in
Halpern et al. (1983)
.
Chaochen et al.found decidable and undecidable fragments of an extension of that work, Duration Calculus
Chaochen et al. (1991)
, over both discrete and dense time
Chaochen et al. (1993)
.
Bolander et al.later introduced Hybrid Duration Calculus that added the ability to name an interval and refer to it in a formula
Bolander et al. (2007)
.
They showed that Hybrid Duration Calculus can express Allen’s relations and is decidable over discrete and dense time domains with non-elementary complexity.
Montanari et al.examined the satisfiability problem for the subset of Halpern and Shoham’s logic of intervals over the natural numbers with only
begins/begun by
and
meets
operators and proved it to be
ExpSpace
-complete
Montanari et al. (2010a)
.
The same authors later proved that adding the
met by
operator increases the complexity of the language to be decidable only over finite total orders
Montanari et al. (2010b)
.
Aceto et al.later examined the expressive power of all fragments of Halpern and Shoham’s logic of intervals over total orders
Aceto et al. (2016)
.

A major advantage of restricting
nfer
to the data-free fragment is that the satisfiability problem also becomes interesting.
Here, the satisfiability problem asks if a set of
nfer
rules can produce an interval with a particular identifier, restricting the inputs to events with a set of possible identifiers.
With data, it is trivial to show that satisfiability for
nfer
is undecidable.
This follows from the results in
Kauffman and Zimmermann (2024)
where
nfer
is shown to have undecidable evaluation.
One can encode a Turing machine using
nfer
rules and satisfiability asks if there is an initial tape such that the machine terminates.

Asking if an
nfer
specification is satisfiable is useful in practice as it allows for a sanity-check on the validity of the rules.
If a user defines a set of rules that is meant to produce a certain interval if an unlikely problem occurs, it is helpful to know that the rules can, in fact, produce that interval.
If the rules are unsatisfiable, the user is likely to spend a long time debugging why the interval is not produced or, even worse, not notice the problem and deploy faulty rules to production.

Without data, it is much less obvious if
nfer
satisfiability is undecidable.
In fact, we show that satisfiability for the full data-free
nfer
language is still undecidable, but we achieve decidability by restricting to a cycle-free or inclusive-only fragment, the latter of which we demonstrate is decidable in
PTime
.
That the satisfiability of inclusive, data-free
nfer
is decidable in
PTime
has exciting implications for practitioners, since these checks can be implemented in event-trace analysis tools
Kauffman (2023)
;
Sadman et al. (2025)
.
We also show that the evaluation problem for data-free
nfer
is in
PTime
without any artificial restrictions on the size of the result from meta-constraints.

This article is a revised and extended version of a paper published at RV 2024
Kauffman et al. (2024)
, which contains all proofs omitted in the conference version and improved results on cycle-free data-free
nfer
satisfiability.

2.1
Syntax

The data-free
nfer
syntax consists of
rules
.
There are two forms of rules: inclusive and exclusive.
Inclusive rules test for the existence of two intervals matching a temporal constraint.
Exclusive rules test for the existence of one interval and the absence of another interval matching a temporal constraint.
When such a pair is found, a new interval is produced with an identifier specified by the rule and timestamps taken from the matched intervals.
We define the syntax of these rules as follows:

•

Inclusive rules have the form
\eta\leftarrow\eta_{1}\>\oplus\ \eta_{2}
and

•

exclusive rules have the form
\eta\leftarrow\eta_{1}\>{\bf unless}\ominus\ \eta_{2}

where
\eta,\eta_{1},\eta_{2}\in\mathcal{I}
are identifiers,

\oplus\in\{{\bf before}{},{\bf meet}{},{\bf during}{},{\bf coincide}{},{\bf start}{},{\bf finish}{},\\
{\bf overlap}{},{\bf slice}{}\}

on three intervals (one for each of
\eta,\eta_{1},\text{ and }\eta_{2}

\eta_{2}

For a rule
\eta\leftarrow\eta_{1}\>\oplus\ \eta_{2}

\eta\leftarrow\eta_{1}\>{\bf unless}\ominus\ \eta_{2}

appear on the right-hand side.

A specification is a finite list of rules.

3
Satisfiability of Data-Free
nfer

We are interested in the existential
nfer
satisfiability problem: Given a specification
D
, a set of identifiers
\Sigma
, and a target identifier
\eta_{T}
, is there an input trace of events
\tau\in\mathbb{E}^{+}
with identifiers in
\Sigma

such that an
\eta_{T}
-labeled interval is in
T[\![D]\!]\>\tau
?
The
nfer
satisfiability problem is interesting in part because of the restriction of input identifiers to
\Sigma\subseteq\mathcal{I}
.
If
\eta_{T}\in\Sigma
, then any specification is trivially satisfiable.
When
\eta_{T}\not\in\Sigma
, however, then an
\eta_{T}
-labeled interval must be derived.
This problem is non-trivial and, as we shall see, undecidable in general.

In this section, we show the undecidability of the data-free

The undecidability result relies on the recursive nature of

Theorem 3.1

We now show how to simulate a Context-Free Grammar

Formally, a Context-Free Grammar is a four-tuple

Given a grammar

We present six types of data-free

The six types of rules are:

1.

Rules to label non-unique timestamps in an event trace so that they can be filtered out.
We do so, because event traces in

So, to simplify our translation between event traces and words, we just filter out events with non-unique timestamps.

2.

Rules that then perform the actual event filtering to only include events with unique timestamps.

3.

Rules that label every interval in a trace by its starting event, i.e. where some event occurs at the start and some other event occurs at the end, we label the interval by the starting event.

4.

Rules that select the minimal starting-event-labeled intervals, i.e. the intervals where no other interval is subsumed by that interval. The result of this step is a set of contiguous intervals labeled by their starting event. These minimal intervals are totally ordered and in one-to-one correspondence with the original events with unique timestamps. Thus, we have transformed the event trace into an

5.

Rules that simulate the productions of the Context-Free Grammars on the pool of minimal starting-event-labeled intervals. The generated intervals encode a derivation tree. The word corresponding to the event trace is accepted by a Context-Free Grammar if an interval is generated that is labeled by that grammar’s initial non-terminal.

6.

A rule that labels an interval by a given target label if the simulation of the two Context-Free Grammars labeled the same interval by their initial non-terminals. The interval is generated if the word corresponding to the same event trace is accepted by both Context-Free Grammars.

, where specifications can be evaluated without a fixed-point computation.

3.2
Inclusive Data-Free
nfer
Satisfiability is in
PTime

We begin our study with the case where an
nfer
specification may contain cycles but only contains inclusive rules.

Theorem 3.2

The data-free, inclusive
nfer
satisfiability problem is in
PTime
.

We show that there is a polynomial-time algorithm that determines if an input trace
\tau
exists such that an
\eta_{T}
-labeled interval is in
T[\![D]\!]\>\tau
for a given specification
D
.
To do this, we show how the satisfiability of a data-free Inclusive-
nfer
specification can be proven through an analysis of the rules without guessing a witnessing trace.
This is due to the monotone nature of inclusive
nfer
rules: new events added to an input trace only add intervals and cannot invalidate existing ones.
We leverage this fact to show how only two factors influence the satisfiability of cycle-free, inclusive
nfer
specifications: producibility from events in
\Sigma
and the requirement of positive duration for some intervals.

To begin, observe that inclusive
nfer
rules are monotone in nature. The interpretation functions
R
,
S
, and
T
only add intervals; they never remove them.
Furthermore, if the rule is inclusive,
R
only tests for the existence of intervals; it only tests for non-existence in the case of exclusive rules.
This means that we may always introduce new events into an input trace without needing to keep track of prior results.
The consequence is that ensuring that an
\eta_{T}
-labeled interval appears in a fixed-point of
T[\![D]\!]\>\tau
only requires showing that a rule
\delta_{T}
exists in
D
with
\eta_{T}
on its left-hand side and that
\delta_{T}
may be matched by intervals resulting from
\Sigma

This concept is very similar to graph reachability and we define it here inductively.

Definition 1

Let
\Sigma

3.3
Cycle-Free Data-Free
nfer
Satisfiability is Decidable

Next, we consider data-free
nfer
with inclusive and exclusive rules, but without cycles.
We conjecture that data-free cycle-free
nfer
satisfiability is
NExpTime
-complete but only prove that it is
NExpTime
-hard and decidable.
Here, we begin with proving decidability obtained by a transformation to
monadic first order logic
(MFO) over strings over the alphabet of identifiers.
MFO allows the quantification of positions in a string and uses the predicates “
<
” (the order between positions of the string) and a unary predicate
\eta(\cdot)
that holds at each position labeled by
\eta
. We refer to, e.g.,
Grädel et al. (2002)
for a full definition.

Theorem 3.3

The cycle-free data-free
nfer
satisfiability problem is decidable.

Proof

Given a cycle-free specification
D
, we will, for each identifier
\eta
, construct an MFO formula
{\varphi}_{D,{\eta}}(t_{0},t_{1})
with free variables
t_{0},t_{1}
, such that
\eta
is satisfiable with respect to
D
iff
{\varphi}_{D,{\eta}}(t_{0},t_{1})
is satisfiable, i.e. there exists a string (word)
w
over
2^{\Sigma}
and an assignment
v:\{t_{0},t_{1}\}\rightarrow\{0,\ldots,|w|-1\}
such that
w,v\models{\varphi}_{D,{\eta}}(t_{0},t_{1})
.
Note, that for an event identifier
\eta\in\Sigma
,
\eta(\cdot)
is a monadic predicate, where
\eta(t)
evaluates to true in a string
w
over
2^{\Sigma}
at position
t
if and only if the set of
w
at position
t
contains
\eta
. That is
w,v\models\eta(t)
if and only if
\eta\in w_{v(t)}
.

Now from

, where
w,v\models{\varphi}_{D,{\eta}}(t_{0},t_{1})
, a satisfying input trace for
\eta
may be obtained as the concatenation
\tau_{w,v}=(w_{t_{0}},t_{0})(w_{t_{0}+1},t_{0}+1)\cdots(w_{t_{1}},t_{1})
, where for a set

w=\{\eta_{1},\ldots,\eta_{k}\}\subseteq\Sigma
and

, we denote by
(w,t)
the (any) string
(\eta_{1},t)(\eta_{2},t)\cdots(\eta_{k},t)
.

Since
D
is cycle-free, we may order the identifiers by a topological sort of the directed graph formed by the rules. The construction of
{\varphi}_{D,{\eta}}(t_{0},t_{1})
now proceeds by induction on this order. In the base case,
\eta
is an event identifier. Here
{\varphi}_{D,{\eta}}(t_{0},t_{1})=(t_{0}=t_{1}\wedge\eta(t_{0}))
.
For the inductive case,
{\varphi}_{D,{\eta}}(t_{0},t_{1})
is obtained by a disjunction of all the rules for
\eta
in
D
, i.e.:

{\varphi}_{D,{\eta}}(t_{0},t_{1})=\bigvee\nolimits_{\eta\leftarrow\eta_{1}\>\textbf{op}\ \eta_{2}\in D}\psi_{D,\eta_{1}\,\textbf{op}\,\,\eta_{2}}(t_{0},t_{1})

where
\textbf{op}\in\{\oplus,{\bf unless}{}\ \ominus\}
. Here the definition
\psi_{D,\eta_{1}\,\textbf{op}\,\,\eta_{2}}(t_{0},t_{1})
is obtained using the MFO formulas for
\eta_{1}
and
\eta_{2}
from the induction hypothesis.
Here we just give the definition for two rules, one inclusive
and one exclusive rule, leaving the remaining rules for the reader to provide.

\psi_{D,\eta_{1}\ {\bf before}\ \eta_{2}}(t_{0},t_{1})=\\
\exists t^{\prime}_{0},t^{\prime}_{1}\raisebox{-1.07639pt}{\scalebox{1.6}{.}}{\ }t_{0}\leq t^{\prime}_{1}<t^{\prime}_{0}\leq t_{1}\wedge{\varphi}_{D,{\eta_{1}}}(t_{0},t^{\prime}_{1})\wedge{\varphi}_{D,{\eta_{2}}}(t^{\prime}_{0},t_{1})\\

Büchi (1960)

Though the reduction to MFO in Theorem

yields the desired decidability result, it comes with a non-elementary complexity
Stockmeyer (1974)

In the remainder of this section, we present a

Note that the problem with establishing a tight upper bound comes from the arbitrary nesting of exclusive rules, such that one rule may need to match so as to not produce an interval that blocks another rule.
This possibility blocks constructions that rely on simple induction over the rules and introduces barriers to, for example, game-based solutions.

Theorem 3.4

The cycle-free data-free
nfer
satisfiability problem is
NExpTime
-hard.

To prove the lower bound, we want to express the existence of an accepting run of a nondeterministic Turing machine with exponential running time as an
nfer
satisfiability problem using only cycle-free rules.
Assume the running time on an input
x
is bounded by
2^{p(|x|)}
for some polynomial
p
, which implies that the length of each configuration is also bounded by
2^{p(|x|)}
.
Thus, by repeatedly halving a configuration, we obtain a tree structure of height
p(|x|)
. Hence, we can use
O(p(|x|))
cycle-free rules to check whether a sequence of
2^{p(|x|)}
events encodes a valid configuration, aggregating every infix of length
2^{k}
, for
k\in\{0,1,\ldots,p(|x|)\}
.

Further, when writing two configurations one after the other, the distance between the encoding of the same cell is at a distance of
2^{p(|x|)}
.
Hence, we can again use another
O(p(|x|))
many cycle-free rules to check whether the second configuration is a successor of the first one.
Finally, as there are only
O(p(|x|))
many configurations, we can use final
O(p(|x|))
many cycle-free rules to check whether the first configuration is the initial one on
x
, whether for any two successive configurations the second one is a successor of the first one, and whether there is an accepting configuration.
Thus, checking satisfiability of the
nfer
specification is equivalent to checking whether the Turing machine has an accepting run on
x
.

To formalize this, let us fix a nondeterministic Turing machine
\mathcal{M}=(Q,\Sigma_{\mathcal{M}},\Gamma,q_{I},q_{A},q_{R},\Delta)

As the running time of
\mathcal{M}
is exponentially bounded, there is a polynomial

such that
\mathcal{M}
halts after at most

.
Thus, a configuration of
\mathcal{M}
on an input

can be seen as a word over the alphabet

of length

with exactly one letter from
\Gamma\times Q
, whose position encodes the position of the head.

For technical convenience, we assume

for all inputs

, which implies that each configuration has at least length

.

.
Hence, we assume that for every tape alphabet symbol

We reduce deciding the existence of an accepting run of

\mathcal{M}
is a nondeterministic Turing machine with exponential running time, and
D_{\mathcal{M},x}
is acyclic, we obtain that satisfiability for cycle-free data-free
nfer
is
NExpTime
-hard.
∎

4
Evaluation of Data-Free
nfer

The evaluation problem for
nfer
asks, given a specification
D
, a trace
\tau
of events, and a target identifier
\eta_{T}
, is there an
\eta_{T}
-labeled interval in
T[\![D]\!]\>\tau
?
The problem has been extensively studied in the presence of data, with complexities ranging from undecidable (for arbitrary data and cycles in the rules) to
PTime
(for finite data under the minimality constraint). We refer to
Kauffman and Zimmermann (2024)
for an overview of the results.
One case that has not been considered thus far is the complexity of the evaluation problem for data-free
nfer
.

Obviously, the result from
Kauffman and Zimmermann (2024)
for finite-data covers the case of data-free specifications,
but without the “minimality” meta-constraint that artificially limits the size of the result, evaluation with only inclusive rules
is
PSpace
-complete (without cycles) and respectively
ExpTime
-complete (with cycles).
Here, we show that these results depend on the availability of (finite) data: data-free
nfer
can be evaluated in polynomial time (even without minimality).

Theorem 4.1

The evaluation problem for data-free
nfer
is in
PTime
.

Proof

Consider an input consisting of a specification
D
, a trace
\tau
of events, and a target identifier
\eta_{T}
, and let
k
be the number of unique timestamps in
\tau
.

Recall that an interval is completely specified by its identifier in
\mathcal{I}
and its starting and ending timestamp.
Hence, as the application of rules does not create new timestamps (cf. Table
1
and Table
2
), the number of intervals in
T[\![D]\!]\>\tau
is bounded by
k^{2}|\mathcal{I}|
.

Checking if an interval is generated by a specification can also be done in polynomial time.
Whether a single inclusive rule is applicable to two intervals can be checked in constant time.
For exclusive rules, checking if an interval should be generated requires testing at most every interval, the number of which is polynomial in the size of the input.
Thus, one can compute
T[\![D]\!]\>\tau
in polynomial time and then check whether it contains an
\eta_{T}
-labeled interval.
∎

5
Conclusion and Future Work

We have studied the complexity of the satisfiability and evaluation problems for Data-free
nfer
.
We proved that the evaluation problem is in
PTime
and the satisfiability problem is undecidable in the general case, but decidable for cycle-free specifications and in
PTime
for specifications with only inclusive rules.

It is interesting that, although much of the complexity of
nfer
evaluation comes from data, the satisfiability problem is still hard without it.
As we have seen from prior works
Kauffman and Zimmermann (2022)
;
Kauffman and Zimmermann (2024)
, complexity can often be mitigated by restricting the language to meaningful fragments.
In the case of data-free
nfer
, removing exclusive rules is sufficient to obtain
PTime
complexity.

There are still open questions around the complexity of
nfer
that may be interesting.
We showed that satisfiability for data-free
nfer
is decidable and
NExpTime
-hard for cycle-free specifications, but we do not prove a tight bound and we conjecture it to be
NExpTime
-complete.

Another open question is if satisfiability is decidable for restricted cases of
nfer

with data
, for example if specifications are cycle-free and data is finite.
It is also interesting to consider if there are restrictions to data that have not yet been considered that might lead to better complexity, for example restricting to a single datum per interval and only equality tests.

We are also interested in the complexity of
monitoring

nfer
.
Here and in other works,
nfer
is presented with an offline semantics. A naïve monitoring algorithm might simply recompute produced intervals each time a new event arrives, but we suspect that better monitoring complexity can be achieved without requiring assumptions beyond temporal ordering.
We hope that this work inspires others to examine the complexity of other modern Runtime Verification languages.

Finally, another interesting direction for future work is to consider the universality problem, i.e., the question of whether every specification allows to derive an interval with a given identifier.
For practitioners deploying
nfer
in a realistic scenario, universality is likely to indicate a mistake in their specification since an identifier that is produced by every input is not likely to assist in trace comprehension.
As such, the universality problem has application as a way to catch bugs before deployment.
