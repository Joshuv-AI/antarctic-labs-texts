1.1.1
Background and Prior Work

Transshipment Boosting,
\ell_{1}
-Oblivious Routing, and Transshipment Flow Rounding

All modern SSSP-algorithms, including ours, compute shortest paths via the transshipment problem (see text before
Theorem

1.1
for a definition). The key idea in this approach of Sherman
[
94
,
96
]
is that even a rather bad
\alpha
-approximation algorithm for (dual) transshipment can be
boosted
to a
(1+\varepsilon)
-approximation. This is achieved via the multiplicative weights method (or equivalently: gradient descent) and requires only
\mathrm{poly}(\alpha,\varepsilon^{-1},\log n)
invocations of the
\alpha
-approximation algorithm
[
96
,
17
,
105
]
. A particularly convenient way of obtaining such a boostable
\alpha
-approximation is to design a linear matrix
R
which maps any node-demand
b
to an
\alpha
-approximate transshipment flow for
b
. Such a matrix is called an
\ell_{1}
-oblivious routing because linearity forces each node to route its demand obliviously, i.e., without knowledge of the demand on other nodes. As mentioned before, in order to obtain an actual
(1+\varepsilon)
-SSSP tree from a transshipment flow most algorithms
[
80
]
are using an approach of
[
15
]
which produces a
(1+\varepsilon)
-SSSP tree after
O(\log n)
adaptive applications of some rounding algorithm. All parts of this reduction except for the rounding algorithm are deterministic.

Putting all these pieces together proves that all one needs to obtain an efficient (deterministic) algorithm for both the
(1+\varepsilon)
-transshipment and the
(1+\varepsilon)
-SSSP problem is a
\widetilde{O}(1)
-competitive
\ell_{1}
-oblivious routing that can be evaluated efficiently and a (deterministic) rounding algorithm. Our algorithm uses these steps in a black-box fashion except that we need to replace the randomized rounding algorithm by a new deterministic transshipment flow rounding procedure.

Vertex Reduction Framework

Unfortunately, it is clear that
\ell_{1}
-oblivious routing cannot be done without having some approximate shortest path information. This chicken and egg problem is resolved via a clever vertex-reduction framework of Li
[
80
]
. The vertex-reduction framework relies on a cyclic sequence of efficient problem reductions. For transshipment
[
80
]
, these problems are SSSP, transshipment,
\ell_{1}
-oblivious routing, and
\ell_{1}
-embedding. Specifically:

•

To solve
(1+\varepsilon)
-SSSP on
G
, it is sufficient to solve
(1+\varepsilon)
-transshipment on
G
,

•

for which it is sufficient to construct
\widetilde{O}(1)
-competitive
\ell_{1}
-oblivious routing on
G
(via boosting),

•

for which it is sufficient to construct an
\widetilde{O}(1)
-distortion
\ell_{1}
-embedding on
G
,

•

for which it is sufficient to solve
O(\log^{2}n)
instances of
\widetilde{O}(1)
-SSSP on a sequence of graphs
G^{\prime}_{1},G^{\prime}_{2},\ldots,G^{\prime}_{O(\log^{2}n)}
, which are resolved recursively.

As stated, this simply reduced
(1+\varepsilon)
-SSSP on
G
to multiple
\widetilde{O}(1)
-SSSP on graphs that are slightly larger than
G
, which isn’t particularly helpful on its own. The key idea to transform this “branching cycle” into a branching spiral that terminates (fast) is to add a step into the cycle which applies ultrasparsification on
G^{\prime}_{i}
, which is an operation that transforms a graph with
n
nodes to a smaller graph with
\frac{n}{\gamma}
nodes such that distances in the smaller graph
\widetilde{O}(\gamma)
-approximate distances in the larger graph. Applying this step, we can reduce
(1+\varepsilon)
-SSSP on a graph with
n
nodes to
O(\log^{2}n)
instances of
\widetilde{O}(1)
-SSSPs on smaller graphs with
O\left(\frac{n}{\log^{100}n}\right)
nodes. It is easy to see that the total size of all recursive calls falls exponentially on each subsequent level, hence the total parallel runtime is
\widetilde{O}(1)
and the total work
\widetilde{O}(m)
(since a single sequence of reductions requires
\widetilde{O}(m)
work).

Minor Aggregates and the Low-Congestion Shortcuts Framework

The low-congestion shortcuts framework was originally intended for designing simple and efficient
distributed

[

59
,
60
,
58

75

53

Indeed, we present our parallel SSSP algorithm using the framework and our hope is that this choice simplifies the exposition, even before considering the benefits of immediately obtaining distributed results.

We describe our algorithms in the recently introduced
\mathsf{Minor}
-
\mathsf{Aggregation}

[

,
57

\mathsf{Minor}
-
\mathsf{Aggregation}
model, one can (1) contract edges, thereby operating a minor, (2) each (super)node in the contracted graph can compute an aggregate (e.g., min, max, sum) of surrounding neighbors, and (3) add
\widetilde{O}(1)

\widetilde{O}(1)
-round algorithms in this model. Such a
\mathsf{Minor}
-
\mathsf{Aggregation}
algorithm can be compiled to a near-optimal algorithm in both the parallel and distributed settings.

1.1.2
Our New Tools

Near-Optimal Graph-Based
\ell_{1}
-oblivious routing

The first key contribution of this paper is a new construction of graph-based
\ell_{1}
-oblivious routing with drastically improved guarantees from the so-called sparse neighborhood covers. A sparse neighborhood cover of distance scale
D
is a collection of
O(\log n)
clusterings (partitioning of the node set into disjoint
clusters
) such that (1) each cluster has diameter at most
D
, and (2) each ball in
G
of radius
D/(\log^{C}n)
is fully contained in at least one cluster (for some fixed constant
C>0
). Specifically, given sparse neighborhood covers for all
O(\log n)
exponentially-increasing distance scales
\beta,\beta^{2},\beta^{3},\dots,\mathrm{poly}(n)
for some
\beta=\widetilde{O}(1)
along with some extra distance information, we construct an
\widetilde{O}(1)
-competitive
\ell_{1}
-oblivious routing.
The algorithm greatly differs from all prior approaches, as all of them had inherent barriers preventing them from achieving deterministic near-optimality, which we describe below.

Derandomization issues:
Efficient constructions of an
\ell_{1}
-oblivious routing either use an
\ell_{1}
-embedding or so-called low-diameter decompositions; this is a clustering problem whose deterministic version is also known as a sparse neighborhood cover.
Sparse neighborhood covers were introduced in the seminal work of
[
7
]
and applied with great success for many problems, including approximate shortest paths and other distance based problems
[
31
,
14
]
.

Since an efficient deterministic
\ell_{1}
-embedding is not known, we need a deterministic construction of sparse neighborhood covers.
Luckily, many of the ideas required to derandomize the computation of sparse neighborhood covers were developed very recently by a sequence of papers that derandomized the closely related network decomposition problem which is, essentially, an unweighted version of the sparse cover problem
[
92
,
49
,
20
]
.
In
[
35
]
, these unweighted results were extended to an algorithm constructing sparse neighborhood cover for weighted graphs and this is the result that we use to solve the shortest path problem here.

Distance-reduction framework: Iterative and Locality-Friendly

As we explained earlier, our new
\ell_{1}
-oblivious routing construction reduces the SSSP problem in
G
to computing sparse neighborhood covers along with some extra distance information.
Clearly, this requires our SSSP computation to compute some distance information, leading again to a chicken and egg problem. Unfortunately, directly applying the vertex-reduction framework is not compatible with our desire to obtain fast minor-aggregation (or distributed) algorithms. In particular, at the lowest level of the recursion, the vertex-reduction framework generates a polynomial number of constant-size SSSP problems, each of which essentially corresponds to a minor of
G
. While these problems can each be solved in constant time in the parallel setting, the fact that these minors can be arbitrarily overlapping and each correspond to large diameter subsets in
G
means that polynomially many instead of the desired polylogarithmic number of minor aggregations are necessary.

This paper therefore designs a novel, completely different, and more locality-friendly complexity-reduction framework:
distance reduction
. On a high-level, we show that obtaining “sparse neighborhood covers up to distance scale
D
” can be reduced to several “shortest path computations up to distance
D
” which are computable from “sparse neighborhood covers up to distance
D/\mathrm{poly}\log n
” (see
Figure

1
).
This iterative and local nature of our distance-reduction framework directly translates into a small overall number of minor aggregations; this is in stark contrast to the inherently recursive vertex-reduction framework (which recurses on different graphs, requiring a recursive approach).
As a nice little extra, combining our distance-reduction framework with the new
\ell_{1}
-embedding makes for an algorithm that is (in our not exactly unbiased opinion) a good bit simpler than the previous algorithms of
[
80
,
11
]
.
We note that this framework is more reminiscent of older approaches to hopset constructions
[
28
,
40
]
. In these approaches, hopsets over longer paths which use at most
\ell/2
edges are used to bootstrap the construction of hopsets over paths using at most
\ell
edges.

A key definition to formalize what exactly the “up to distance
D
” in our distance-reduction framework means is the following. We attach a virtual, so-called,
cheating node
and connect it to all other nodes with an edge of length
D
. This new graph naturally preserves distance information “up to distance
D
” and the complexity of computing distances increases as
D
increases.

Derandomization: Deterministic Transshipment Flow Rounding via Eulerian Tours

All previous transshipment approaches crucially use randomization. The most significant challenge we had to overcome in making our results deterministic stem from the following issue: The only problem that remains to be derandomized in this paper is
rounding
a (fractional) transshipment solution to (a flow supported on) a tree, a crucial step in the distance-reduction framework. We prove the following theorem (only the parallel version is stated for simplicity).

Theorem 1.3
.

There is a deterministic parallel algorithm which takes as an input any fractional transshipment flow

b

G

While such a flow rounding seems an unlikely bottleneck for a deterministic SSSP algorithm, we remark that even for randomized algorithms a lot of complexity has come from this rounding step in the algorithms of

Note that if the fractional flow

through which flow is routed, choosing the probability of each edge proportional to the outflow in
f
. It is easy to see that retaining the edges that are in the connected component of the source truthfully samples a tree-supported flow from
f
. The complexity comes in once
f
is not acyclic as the sampled edges can now create many connected components. This requires finding the cycles in these components, contracting the edges and again running a randomized out-edge sampling on the remaining graph.

Deterministically none of the above works. Indeed, we are not aware of any simple(r) way of deterministically obtaining a tree-supported flow even if
f
is acyclic. Our rounding procedure can be seen as a generalization of an algorithm of Cohen’s rounding
[
29
]
, which can be used to round any fractional transshipment flow to an integral flow by scaling flow values to only leave integral and half-integral flow values and then finding an Eulerian tour covering all half-integral edges. Pushing one half-unit of flow in the cheaper direction of this Eulerian tour makes all flow values fully integral and allows the scaling to be reduced. At the end of this procedure, all flow values are integral but this does not guarantee that the flow is supported on a tree. To eliminate any non-tree like parts of the flow we show how to keep the algorithm running and find further Eulerian tours until the flow becomes tree-supported.

A Distributed Eulerian Tour Algorithm

The problem of computing Eulerian Tours can be stated as follows. Given an undirected graph with all degrees even, direct the edges in such a way that the out-degree of every node equals the in-degree. Note that we do not require connectedness. While computing Eulerian tours is a well-known parallel primitive which can be efficiently computed in near-linear work and polylogarithmic time
[
12
]
, there are, to our knowledge, no distributed algorithms known for this problem.

Therefore, to also give
distributed
SSSP algorithms in this paper we need to design efficient distributed Eulerian-tour algorithms that can then be used in the Eulerian-tour-based rounding procedure of
Theorem

1.3
. We build the first algorithm computing such an Eulerian tour orientation by using algorithms from
[
90
,
91
]
for low-congestion cycle covers. Interestingly, these low-congestion cycle covers were only developed for the completely unrelated purpose of making distributed computation resilient to Byzantine faults introduced by an adversary in a recent line of work
[
90
,
91
,
71
,
70
]
.

Theorem 1.4

(Informal)
.

There is a deterministic
\mathsf{CONGEST}
algorithm which, given any Eulerian subgraph
H
of the network
G
as an input, computes an Eulerian tour orientation in
\widetilde{O}(\sqrt{n}+\mathrm{Hop}\-\mathrm{Diam}(G))
rounds or
\widetilde{O}(\mathrm{Hop}\-\mathrm{Diam}(G))
rounds if
G
is an excluded-minor graph.

The most general and fully formal statements of all results proven in this paper are given in

Preliminaries and Terminology

In this section, we first review some basic terminology related to graphs, clusterings, shortest paths and (transhipment) flows. Afterwards, we describe the computational models we use in this paper.

Graphs.

For a graph
G
we use
V(G),E(G)
to denote its node set and edge set, respectively. The set of neighbors of a node
v
is denoted with
\Gamma_{G}(v)\subseteq V
.
An eulerian graph is a graph with
|\Gamma_{G}(v)|
being even for every
v\in V(G)
.
It is often convenient to direct
E
consistently. For simplicity and without loss of generality, we assume that
V=\{v_{1},v_{2},\ldots,v_{n}\}
and define
\vec{E}=\{(v_{i},v_{j})\mid(v_{i},v_{j})\in E,i<j\}
. We identify
E
and
\vec{E}
by the obvious bijection. We chose this orientation for simplicity and concreteness: arbitrarily changing the orientations does not influence the results (if done consistently). We also introduce the notation
\overleftrightarrow{E}
which includes each edge of
\{u,v\}\in E
in both directions:
(u,v)\in\overleftrightarrow{E}
and
(v,u)\in\overleftrightarrow{E}
.

A weighted graph
G
is an undirected graph, together with a function
\ell_{G}:E\rightarrow\{1,\ldots,n^{O(1)}\}
that assigns a polynomially-bounded non-negative weight to each edge in
E
. We sometimes use just
\ell
if
G
is clear from context. This weight function induces a distance function
\operatorname{dist}_{G}(u,v)
on
G
. For two sets of nodes
A,B\subseteq V(G)
we define
\operatorname{dist}_{G}(U,W)=\min_{u\in U,w\in W}\operatorname{dist}_{G}(u,w)
and sometimes write
\operatorname{dist}_{G}(U,w)
for
\operatorname{dist}_{G}(U,\{w\})
.
A ball
B_{G}(u,r)
of radius
r
around a node
u
is a set of nodes
v
such that
\operatorname{dist}_{G}(u,v)\leq r
. The diameter of a weighted graph
G
is defineed as
\textrm{diam}(G)=\max_{u,v}\operatorname{dist}_{G}(u,v)
and its hop diameter
\mathrm{Hop}\-\mathrm{Diam}(G)
is the longest unweighted shortest path (i.e., in terms of hops and not weight).

Clusters and Clusterings.

A
cluster

C
is a set of nodes
C\subseteq V(G)
.
A
clustering

\mathcal{C}
is a collection of disjoint clusters.
Finally, a
sparse neighborhood cover
of a graph
G
with
covering radius

R
is a collection of
\gamma:=O(\log n)

3
3

3

Sometimes we use
\log(\cdot)
outside the
O
-notation, in which case it stands for
\log_{2}(\cdot)
.
clusterings
\mathcal{C}_{1},\dots,\mathcal{C}_{\gamma}
such that for each node
v\in V(G)
there exists some
i\in\{1,\ldots,\gamma\}
and some
C\in\mathcal{C}_{i}
with

.

Flows, Transshipment, and SSSP.

Given a graph
G=(V,E)
, a flow is either a function
f:\overleftrightarrow{E}\to\mathbb{R}_{\geq 0}
(that is identified with a vector
\mathbb{R}_{\geq 0}^{\overleftrightarrow{R}}
by the obvious identification), or a function
f:\vec{E}\to\mathbb{R}
(identified with
\mathbb{R}^{\vec{E}}
). We often use one or the other flow notation for convenience. Given
f\in\overleftrightarrow{E}
, we can covert it to
f^{\prime}\in\vec{E}
by letting
(f^{\prime})_{(u,v)}:=f(u,v)-f(v,u)
and, similarly, in the other direction
f_{(u,v)}:=\mathbb{1}[(u,v)\in\vec{E}]f^{\prime}_{(u,v)}-\mathbb{1}[(v,u)\in\vec{E}]f^{\prime}_{(v,u)}
. A
demand

is simply a function
b:V\to\mathbb{R}
(or equivalently
\mathbb{R}^{V}
) satisfying
\sum_{v\in V}b_{v}=0
. We say a flow
f\in\mathbb{R}^{\overleftrightarrow{E}}

a demand

v\in V
, we have
\sum_{u:(u,v)\in\overleftrightarrow{E}}(f(u,v)-f(v,u))=b(v)
. Given edge weights
\ell\in\mathbb{R}^{E}
, the
transshipment cost
of the flow is
\ell(f):=\sum_{(u,v)\in\overleftrightarrow{E}}\ell(\{u,v\})f(u,v)
.

Furthermore, we say that a function
\phi:V(G)\rightarrow\mathbb{R}
(a vector in
\mathbb{R}^{V(G)}
) is a

if
|\phi(u)-\phi(v)|\leq\operatorname{dist}_{G}(u,v)
for all
u,v\in V
. Equivalently, we can require that for every edge
\{u,v\}
we have
|\phi(u)-\phi(v)|\leq\ell(\{u,v\})
. We note the following useful fact about potentials.

Fact 2.1
.

If
\phi_{1},\phi_{2},\ldots,\phi_{k}
are potentials, then
\phi_{min}
and
\phi_{max}
are also potentials. Here,
\phi_{min}(v)=\min_{i\in[k]}\phi_{i}(v)
and

\phi_{max}(v)=\max_{i\in[k]}\phi_{i}(v)
for all
v\in V
.

This now allows us to formally define (approximate) transshipment and SSSP.

Definition 2.2

(Transshipment)
.

Given a (connected) graph
G=(V,E)
with lengths
\ell\in\mathbb{R}^{E}
and a demand
b\in\mathbb{R}^{V}
, the transshipment problem asks us to find (1) a flow
f\in\mathbb{R}^{\vec{E}}
, and (2) a potential
\phi\in\mathbb{R}^{V}
that minimize/maximize their respective program in the following primal-dual formulation:

\displaystyle\min~\ell(f):\text{$f$ is a flow satisfying $b$},

\displaystyle\max~b^{\top}\phi:\text{$\phi$ is a potential}.

For
\alpha\geq 1
, a solution
(f,\phi)
is
\alpha
-approximate if both
f
and
\phi
are feasible (
f
satisfies
b
,
\phi
is a potential), and
\ell(f)\leq\alpha\cdot b^{\top}\phi
. Note that a
1
-approximate solution is optimal.

Definition 2.3

(SSSP and set-source shortest path)
.

Suppose we are given a (connected) graph
G=(V,E)
with lengths
\ell\in\mathbb{R}^{E}
. Given a

, the
\alpha
-approximate set-source shortest path problem asks us to compute a forest

such that
\operatorname{dist}_{F}(S,u)\leq\alpha\cdot\operatorname{dist}_{G}(S,u)
for each node

. The problem is called

-approximate SSSP when

. The singleton node

is called the
source
.

\ell_{1}
-Oblivious Routing.

Let

be a fixed graph with weights
\ell\in\mathbb{R}_{\geq 0}^{E}
. For a demand

with
\sum_{v\in V}b_{v}=0
we define
\left\lVert b\right\rVert_{\mathrm{OPT}}:=\ell(f_{b}^{*})
to be the cost of the minimum-cost flow that satisfies the demand

. Then, the
\ell_{1}
-oblivious routing is defined as follows.

Definition 2.4

(
\ell_{1}
-oblivious routing)
.

For a graph
G=(V,E)
, a matrix

is called a (linear)
\ell_{1}
-oblivious routing if for any demand

\sum_{v\in V}b_{v}=0
the flow

\ell_{1}
-oblivious routing

2.1
Model: Minor-Aggregation for
\mathsf{PRAM}

In this section we give a minimal-but-complete description of the
\mathsf{Minor}
-
\mathsf{Aggregation}
interface, which exposes to the user the following operations on a graph: (1) contract edges, thereby operating a minor, (2) each (super)node in the contracted graph can compute an aggregate (e.g., min, max, sum) of surrounding neighbors, and (3) add
\widetilde{O}(1)
arbitrarily-connected virtual nodes over the course of the algorithm. The goal is to design
\widetilde{O}(1)
-round algorithms in this model. Such a
\mathsf{Minor}
-
\mathsf{Aggregation}
algorithm can be compiled to a near-optimal algorithm in both the parallel and distributed settings.

The full model, as defined in
[
103
,
57
]
, is used in the distributed setting which requires specifying some low-level details we can leave out here. For a more in-depth discussion of
\mathsf{Minor}
-
\mathsf{Aggregation}
and its extensions to distributed models see
Appendix

B
.

Aggregations.
An
aggregation operation

\bigoplus
is any associative function that combines two
\widetilde{O}(1)
-bit inputs into one of equal size (e.g., sum or max). For multiple inputs
x_{1},x_{2},\ldots,x_{k}
, their
aggregate

\bigoplus_{i=1}^{k}x_{i}
is defined by arbitrarily aggregating messages until one remains.

Definition 2.5

(Minor-Aggregation model in
\mathsf{PRAM}
)
.

We are given an undirected graph
G=(V,E)
. There is a single
\mathsf{PRAM}
processor and private memory associated with each node and each edge. Between-processor communication happens during synchronous rounds, and processors perform
\widetilde{O}(1)
-work local computation between rounds. Each round consists of the following three steps (in that order).

•

Contraction step.
Each edge (associated processor)
e
chooses a value
c_{e}=\{\bot,\top\}
. This defines a new
minor network

G^{\prime}=(V^{\prime},E^{\prime})
constructed as
G^{\prime}=G/\{e:c_{e}=\top\}
, i.e., by contracting all edges with
c_{e}=\top
and self-loops removed. Vertices
V^{\prime}
of
G^{\prime}
are called supernodes, and we identify supernodes with the subset of nodes
V
it consists of, i.e., if
s\in V^{\prime}
then
s\subseteq V
.

•

Consensus step.
Each individual node
v\in V
chooses a
\widetilde{O}(1)
-bit value
x_{v}
. For each supernode
s\in V^{\prime}
we define
y_{s}:=\bigoplus_{v\in s}x_{v}
, where
\bigoplus
is some aggregation operator. All nodes
v\in s
learn
y_{s}
.

•

Aggregation step.
Each edge
e\in E^{\prime}
connecting supernodes
a\in V^{\prime}
and
b\in V^{\prime}
learns
y_{a}
and
y_{b}
, and chooses two
\widetilde{O}(1)
-bit values
z_{e,a},z_{e,b}
(i.e., one value for each endpoint). Finally, (every node of) each super
s\in V^{\prime}
learns the aggregate of its incident edges in
E^{\prime}
, i.e.,
\bigotimes_{e\in\text{incidentEdges(s)}}z_{e,s}
where
\bigotimes
is some aggregation operator.

PRAM simulation.
Simulating contractions and aggregations is a well-known and simple primitive in
\mathsf{PRAM}
that can be performed in
\widetilde{O}(1)
time and
\widetilde{O}(m)
work (see e.g.
B.12
).

We note that the following operations can be efficiently simulated.

•

Minors.
It is immediate from the model that any
\mathsf{Minor}
-
\mathsf{Aggregation}
algorithm can be run on a minor in a black-box manner.

•

Node-disjoint scheduling.
Similarly, it is immediate that we can simultaneously run separate algorithms on node-disjoint and connected subgraphs of
G
.

•

Virtual nodes.
Given a graph
G
, we can construct a
virtual graph
by starting with a connected graph and repeatedly adding a
virtual node
that is connected to an arbitrary set of neighbors. Due to the constraints in the distributed setting, we constrain the number of virtual nodes to
\widetilde{O}(1)
. A
\mathsf{Minor}
-
\mathsf{Aggregation}
round on such graphs can be simulated in
\mathsf{PRAM}
with
\widetilde{O}(m)
work and
\widetilde{O}(1)
depth. For example, we frequently use this operation to connect a “supersource” node, enabling us to use our standard SSSP algorithm to implement a set-source-
S
shortest path.

Distributed storage and input.
Our
\mathsf{Minor}
-
\mathsf{Aggregation}
algorithms operate on objects that are
“distributedly” stored
, meaning that each processor has its own part of the object in private memory. Specifically, we store a
node vector

x\in\mathbb{R}^{V}
by storing
x_{v}
in node
v
. Similarly, edge vectors

are distributed over edges. Subgraphs

are specified by distributedly storing the characteristic vectors
\mathbb{1}_{V(H)}\in\mathbb{R}^{E(G)}
and
\mathbb{1}_{E(H)}\in\mathbb{R}^{E(G)}
. Initially, the problem-specific input is assumed to be distributedly stored. For transshipment and SSSP, we assume the lengths (edge vector) and demands (node vector) are stored. At termination, the output is required to be stored.

Oracles.
An oracle is a black-box function that takes a certain input (on the original graph) and produces a specified output. An algorithm with access to an oracle can, in each round, choose to perform a regular
\mathsf{Minor}
-
\mathsf{Aggregation}
round, or to call a single oracle (i.e., multiple oracle calls per round are forbidden). Some oracles we use only have an efficient
\mathsf{PRAM}
implementation, but no efficient
\mathsf{Minor}
-
\mathsf{Aggregation}
implementation.

Ancestor and subtree sums.
The following operation is often useful. Given a (distributedly stored) tree
T
and a root
r\in V(T)
, there is a deterministic
\widetilde{O}(1)
-round
\mathsf{Minor}
-
\mathsf{Aggregation}
algorithm that computes for each node the ancestor and descendent sum (or a general aggregate) with respect to
T
rooted at
v
(see
Lemma

B.8
for a fully formal version).

4
\ell_{1}
-Oblivious Routing with
\widetilde{O}(1)
Competitiveness and Evaluation Time via Sparse Neighborhood Covers

In this section, we prove our main result, an efficient
\ell_{1}
-oblivious routing in the distributed setting. We first give an overview of the new ideas required to overcome the barriers present in all previously known approaches, and then present a formal construction and proofs in
Section

4.2
.

4.1
An Overview of New Ideas

The first key contribution of this paper is a new graph-based
\ell_{1}
-oblivious routing with drastically improved guarantees. In order to simplify the discussion, in this overview we will explain the ideas from a randomized (low-diameter decomposition) perspective, rather than a deterministic (sparse neighborhood covers) one.

We develop this polylog-competitive
\ell_{1}
-oblivious routing by using (near-optimal) polylog-quality low-diameter decompositions (LDDs). A
\widetilde{O}(1)
-quality low-diameter decomposition is a randomized partitioning of the nodes of
V
into so-called
clusters
of a specified radius
r
such that two nodes
u,v
are in different clusters with probability at most
\widetilde{O}(1)\frac{\operatorname{dist}(u,v)}{r}
. Notably, we use a “deterministic version” of LDDs, namely sparse neighborhood covers; we mostly consider randomized approaches in this introductory discussion due to its relative simplicity. A randomized version of an LDD-based approach was considered in
[
103
]
, but achieved only a
n^{o(1)}
-competitive routing. Moreover, many inherent barriers prevent an LDD-based approach from achieving polylog-competitiveness and we develop several new ideas described below to overcome them.

For the purposes of this section, we pretend we have access to an oracle constructing polylog-quality LDDs (or sparse neighborhood covers). Note that this is also an important open problem which we solve concurrently using our locality-friendly reduction framework from
Section

3
.

Idea 1: Remembering where the flows came from.

Oblivious routings generally work by taking a demand
b:V(G)\to R
and judiciously intermixing it until, eventually, all demand is routed to some single node. This is a valid solution to the transshipment problem, albeit its competitiveness depends on the intermixing strategy. Note that sending a negative demand along a directed edge corresponds to sending a positive demand over the reversed edge.

All current approaches to oblivious routing had the property that once two demand (i.e., flows) were merged in a single node during the intermixing, from this point on they were always routed together. Such strategies make the routing and the analysis simple: each intermixing step only depends on the demand vector given to it at the start, hence can be analyzed independently of other steps. For example,
[
80
]
does a
\ell_{1}
-embedding based approach using
O(\log n)
steps of intermixing, each blowing up the optimum by a multiplicative
(1+1/\log n)
, yielding a polylog-competitive routing (in each step the current optimum is added to the solution). Similarly,
[
103
]
does a LDD-based approach with
(\log n)^{1/4}
steps of intermixing, each losing a
2^{\sqrt{\log n}}
factor, hence yielding a
2^{(\log n)^{3/4}}=n^{o(1)}
-competitive routing. Unfortunately, all approaches that use LDDs and lose a polylog factor in each step (this is optimal) require at least
O(\frac{\log n}{\log\log n})
steps, yielding only an (unusable) polynomially-competitive routing. This is a inherent barrier preventing LDDs-based approaches from being polylog-competitive.

We overcome this barrier by remembering the origin of each flow. In other words, instead of simply remembering that, after an intermixing step, there is
b^{\prime}_{u}
flow at a node
u
, we remember that there is
b^{\prime}_{u}(v)
flow at
u
that originated at node
v
. Therefore, each flow is treated differently based on its origin, making the flows splittable even after being aggregated at the same node. This idea, along with the next one, allows us to convert the multiplicative polylog-losses to additive ones, hence achieve a polylog-competitive routing.

Idea 2: Reduce the outflow of nodes close to the boundary.

Consider the following natural intermixing step. Sample an LDD of (large) radius
r
, and send the entire demand of each node
v
to the center of its cluster in the LDD. Let us examine how the demand
b:=\mathbb{1}_{u}-\mathbb{1}_{v}
supported on two nodes
u
and
v
at distance
\operatorname{dist}_{G}(u,v)=1
gets intermixed. If
u,v
are in the same cluster, their demand gets merged and the new transshipment cost is
0
. On the other hand, if they end up in different clusters, the new transshipment cost grows by at most
+2r
, but this happens (by LDD properties) only with probability
\widetilde{O}(1)\cdot\frac{1}{r}
. Therefore, in expectation the new transshipment cost grows by an (acceptable) polylog factor. However, in worst-case the cost grows by an (unacceptable) multiplicative
O(r)
, requiring the algorithm to average over
\widetilde{O}(r)
different LDDs until the blowup becomes acceptable. The key idea in the approach of
[
103
]
is to gradually increase the radius by an
n^{o(1)}
factor until a single cluster consumes the entire graph and the demand is consolidated in a single node. This gradual increase enables one to average only over
n^{o(1)}
different LDD samples and achieve a worst-case guarantee, even when the radius is
\Omega(n)
.

We, on the other hand, choose an approach that does not include a large number of repetitions to achieve worst-case guarantees. First, we note that if two very-close nodes
u
and
v
are not in the same cluster, then they are extremely close to the boundaries of their respective clusters. Our key idea is that nodes that are close to the boundary only send a small portion of their flow to the center of the LDD cluster. This allows us to repeat the LDD sampling until every node is far-away from the boundary in at least one sample, hence we repeat the sampling only
O(\log n)
times.

We now consider the intermixing strategy associated with a single LDD sample of radius
r
. Formally, let
d(u)
the distance of
u
to the boundary of
u
’s LDD cluster. The node
u
will only send approximately
d(u)/r
amount of flow to the center of the cluster (up to a polylog constant of proportionality which we ignore here). Therefore, since
\operatorname{dist}_{G}(u,v)=1
, we know the difference in the flows sent by
u
and
v
to the some
r
-distant cluster center is at most
|d(u)-d(v)|/r\leq 1/r
(this is the amount we have to pay for), yielding a cost of at most
\widetilde{O}(1)
per LDD sample independent of the LDD radius. Of course, this only describes the routing in the first step. Later, as the radius of the LDD clusters increase, the flow that originated at
u
(called
u
-associated flow) is already intermixed in various nodes, we generalize the strategy in the following way. Each node
w
sends approximately
d(u)/r
-fraction of its incoming
u
-associated flow (from
w
) to the center of the LDD cluster
containing the origin
u
(note:
w
is not considered here). Note that this idea crucially requires us to remember where the flow comes from. Again, it is easy to show that the cost per LDD is
\widetilde{O}(1)
. After the LDD radius is exponentially increased for a logarithmic number of steps, the LDDs start consuming the entire graph and the entire demand is consolidated at a polylogarithmic cost, achieving a polylog-competitive routing (at least for
u,v
at distance
1
, but also generally).

Algorithmic remark.

In addition to being extremely simple this new
\ell_{1}
-oblivious routing is also routing directly on the graph G and thus provides a linear
n\times m
map
R
which directly maps any node-demand to a
\widetilde{O}(1)
-approximate transshipment flow in
G
. Moreover, the evaluations of this routing map
R
can trivially be evaluated in near-linear time because it can be written as a product
R=A\times B
of two sparse matrices
A
and
B
. Here,
A
maps each node to
\widetilde{O}(1)
paths and
B
map each path to its edges, where each edge is used by at most
\widetilde{O}(1)
paths. These two sparse mappings can furthermore be directly read off in near-linear time if the
O(\log^{2}n)
LDDs and (approximate) distances of nodes to the LDD boundary are given.

f_{C,C^{\prime}}(v):=(p_{C}(v)/w_{j}(v))\cdot(p_{C^{\prime}}(v)/w_{j+1}(v))
. (We do not yet specify the path from
r_{C}
to
r_{C^{\prime}}
along which the flow is sent.) Over a single level
j
, the flow can be viewed as a “product flow” among all clusters
C
in
\mathcal{S}_{j}
and
C^{\prime}
in
\mathcal{S}_{j+1}
containing
v
, weighted proportionally to
p_{C}(v)
and
p_{C^{\prime}}(v)
, respectively.

v
is deep enough in two clusters
C_{1},C_{2}
in the sparse neighborhood cover
\mathcal{S}_{1}
to send flow to their centers
r_{C_{1}},r_{C_{2}}
.
There are two clusters
C^{\prime}_{1},C^{\prime}_{2}
in the cover
\mathcal{S}_{2}
where

and

f_{C,C^{\prime}}(v)\propto p_{C}(v)p_{C^{\prime}}(v)
. Note that by
4.4
we have
C_{1}\cup C_{2}\subseteq C^{\prime}_{1}\cap C^{\prime}_{2}
.

Claim 4.3
.

For each
v\in V^{\prime}\setminus\{v_{D_{i}}\}
, the
v
-associated flow sends
1
unit of net flow out of
v
,
1
unit of net flow into the virtual node
v_{D_{i}}
, and zero net flow into/out of any other node. The
v_{D_{i}}
-associated flow has zero net flow into/out of every node.

Proof.

Fix any node
v\in V^{\prime}
. Since
\sum_{C\in\mathcal{C}\in\mathcal{S}_{j}}p_{C}(v)/w_{j}(v)=1
for all
j
, it is easy to see that each node
v
receives exactly
p_{C}(v)/w_{j}(v)
total flow from level
j-1
and sends exactly
p_{C}(v)/w_{j}(v)
total flow to level
j+1
, which is a net flow of zero. This also means that for
j=1
, the node
v
sends
1
unit of flow out. Finally, since
\mathcal{S}_{i}
has a single cluster with center
v_{D_{i}}
, all flow eventually coalesces at node
v_{D_{i}}
. This means that if
v\neq v_{D_{i}}
, then the flow sends
1
unit out of
v
and
1
unit into
v_{D_{i}}
, and if
v=v_{D_{i}}
, then the two units of flow cancel, and the net flow is zero on every node.
∎

Claim 4.4
.

We have
f_{C,C^{\prime}}(v)\neq 0
only if
C\subseteq C^{\prime}
.

Proof.

The claim is vacuous for
j=i-1
since
\mathcal{S}_{i}
has a single cluster of all the nodes, so assume that
j<i-1
. If
f_{C,C^{\prime}}(v)\neq 0
then in particular,
p_{C^{\prime}}(v)=\max\{0,\widetilde{d}_{C^{\prime}}(v)/D_{j+1}-0.25/\tau\}>0
, which implies that
\widetilde{d}_{C^{\prime}}(v)\geq 0.25D_{j+1}/\tau
. Since
\widetilde{d}_{C^{\prime}}
is a potential with respect to
V^{\prime}\setminus C^{\prime}
, by properties (1) and (2) of Definition
3.5
, we have
\operatorname{dist}_{G}(v,V^{\prime}\setminus C^{\prime})\geq\widetilde{d}_{C^{\prime}}(v)\geq 0.25D_{j+1}/\tau
. In other words,
v
has distance at least
0.25D_{j+1}/\tau
to the outside of cluster
C^{\prime}
. Since
\tau\leq\beta/8
by construction, this distance is at least
2D_{j+1}/\beta=2D_{j}
. Since
C
is a cluster of radius at most
D_{j}
, node
v
has distance at most
2D_{j}
to all of
C
, and it follows that
C\subseteq C^{\prime}
.
∎

The following lemma is key to bounding the competitive ratio of the oblivious routing algorithm.

Lemma 4.5
.

Fix two nodes
u,v\in V^{\prime}
. For every
j<i
and two clusters
C\in\mathcal{C}\in\mathcal{S}_{j}
and
C^{\prime}\in\mathcal{C}^{\prime}\in\mathcal{S}_{j+1}
, we have
|f_{C,C^{\prime}}(u)-f_{C,C^{\prime}}(v)|\leq O(\gamma\tau d_{G}(u,v)/D_{j})
.

Proof.

Consider some
j<i
and clusters
C\in\mathcal{C}\in\mathcal{S}_{j}
and
C^{\prime}\in\mathcal{C}^{\prime}\in\mathcal{S}_{j+1}
.
To avoid clutter, let
d:=\operatorname{dist}_{G}(u,v)
and
\delta:=\operatorname{dist}_{G}(u,v)/D_{j}
.
The claim is trivial if
\delta\geq 1/(\gamma\tau)
since
f_{C,C^{\prime}}(u),f_{C,C^{\prime}}(v)\in[0,1]
by construction. For the rest of the proof, assume that
\delta\leq 1/(\gamma\tau)
. It suffices to prove
f_{C,C^{\prime}}(u)-f_{C,C^{\prime}}(v)\leq O(\gamma\tau d_{G}(u,v)/D_{j})
without the absolute value, since we can swap
u
and
v
to obtain the other direction.

By property 2(ii) of Definition
3.6
, both
|\widetilde{d}_{C}(u)-\widetilde{d}_{C}(v)|
and
|\widetilde{d}_{C^{\prime}}(u)-\widetilde{d}_{C^{\prime}}(v)|
are at most
d
, so both
|p_{C}(u)-p_{C}(v)|
and
|p_{C^{\prime}}(u)-p_{C^{\prime}}(v)|
are at most
d/D_{j}=\delta
. Since
w_{j}(v)=\sum_{C^{\prime\prime}\in\mathcal{C}^{\prime\prime}\in\mathcal{S}_{j}}p_{C^{\prime\prime}}(v)
is the sum of at most
\gamma
many terms, we have
|w_{j}(u)-w_{j}(v)|\leq\gamma\delta
. Similarly,
|w_{j+1}(u)-w_{j+1}(v)|\leq\gamma d/D_{j+1}\leq\gamma d/D_{j}=\gamma\delta
. Therefore,

\displaystyle f_{C,C^{\prime}}(u)-f_{C,C^{\prime}}(v)

\displaystyle=\frac{p_{C}(v)}{w_{j}(v)}\cdot\frac{p_{C^{\prime}}(v)}{w_{j+1}(v)}-\frac{p_{C}(u)}{w_{j}(u)}\cdot\frac{p_{C^{\prime}}(u)}{w_{j+1}(u)}

\displaystyle=\frac{p_{C}(v)p_{C^{\prime}}(v)w_{j}(u)w_{j+1}(u)-p_{C}(u)p_{C^{\prime}}(u)w_{j}(v)w_{j+1}(v)}{w_{j}(v)w_{j+1}(v)w_{j}(u)w_{j+1}(u)}

\displaystyle\leq\frac{p_{C}(v)p_{C^{\prime}}(v)(w_{j}(v)+\gamma\delta)(w_{j+1}(v)+\gamma\delta)-(p_{C}(v)-\delta)(p_{C^{\prime}}(v)-\delta)w_{j}(v)w_{j+1}(v)}{w_{j}(v)w_{j+1}(v)w_{j}(u)w_{j+1}(u)}.

Expanding out the numerator and canceling out the
p_{C}(v)p_{C^{\prime}}(v)w_{j}(v)w_{j+1}(v)
terms, we obtain

\displaystyle p_{C}(v)p_{C^{\prime}}(v)(w_{j}(v)w_{j+1}(v)+\gamma\delta w_{j}(v)+\gamma\delta w_{j+1}(v)+(\gamma\delta)^{2})

\displaystyle\quad-(p_{C}(v)p_{C^{\prime}}(v)-\delta p_{C}(v)-\delta p_{C^{\prime}}(v)+\delta^{2})w_{j}(v)w_{j+1}(v)

\displaystyle={}

\displaystyle p_{C}(v)p_{C^{\prime}}(v)(\gamma\delta w_{j}(v)+\gamma\delta w_{j+1}(v)+(\gamma\delta)^{2})+(\delta p_{C}(v)+\delta p_{C^{\prime}}(v)-\delta^{2})w_{j}(v)w_{j+1}(v).

Using that
p_{C}(v)\leq w_{j}(v)
and
p_{C^{\prime}}(v)\leq w_{j+1}(v)
, and ignoring the last
-\delta^{2}
term, this is at most

\displaystyle w_{j}(v)w_{j+1}(v)(\gamma\delta w_{j}(v)+\gamma\delta w_{j+1}(v)+(\gamma\delta)^{2})+(\delta w_{j}(v)+\delta w_{j+1}(v))w_{j}(v)w_{j+1}(v)

\displaystyle={}

\displaystyle w_{j}(v)w_{j+1}(v)((\gamma+1)\delta w_{j}(v)+(\gamma+1)\delta w_{j+1}(v)+(\gamma\delta)^{2})

Dividing by the denominator
w_{j}(v)w_{j+1}(v)w_{j}(u)w_{j+1}(u)
and then using
|w_{j}(u)-w_{j}(v)|\leq\gamma\delta
and
|w_{j+1}(u)-w_{j+1}(v)|\leq\gamma\delta
, we upper bound
f_{C,C^{\prime}}(u)-f_{C,C^{\prime}}(v)
by

\displaystyle\frac{(\gamma+1)\delta w_{j}(v)+(\gamma+1)\delta w_{j+1}(v)+(\gamma\delta)^{2}}{w_{j}(u)w_{j+1}(u)}

\displaystyle\leq{}

\displaystyle\frac{(\gamma+1)\delta(w_{j}(u)+\gamma\delta)+(\gamma+1)\delta(w_{j+1}(u)+\gamma\delta)+(\gamma\delta)^{2}}{w_{j}(u)w_{j+1}(u)}

\displaystyle\leq{}

\displaystyle\frac{(\gamma+1)\delta w_{j}(u)+(\gamma+1)\delta w_{j+1}(u)+O(\gamma\delta)^{2}}{w_{j}(u)w_{j+1}(u)}

\displaystyle={}

\displaystyle\frac{(\gamma+1)\delta}{w_{j+1}(u)}+\frac{(\gamma+1)\delta}{w_{j}(u)}+\frac{O(\gamma\delta)^{2}}{w_{j}(u)w_{j+1}(u)}.

Finally, using that
w_{j}(u),w_{j}(v)\geq 0.25/\tau
from
Lemma

4.2
, this is at most
O(\gamma\tau\delta+(\gamma\tau\delta)^{2})
. Since
\delta\leq 1/(\gamma\tau)
, the linear term dominates, and we obtain the desired
f_{C,C^{\prime}}(u)-f_{C,C^{\prime}}(v)\leq O(\gamma\tau\delta)
.
∎

Lemma 4.6
.

Assume that
\tau\leq\beta/8
.
For any demand vector
b:\mathbb{R}^{V^{\prime}}
for the graph
G_{S,D_{i}}
, the summation

\displaystyle\sum_{j<i}\sum_{\begin{subarray}{c}C\in\mathcal{C}\in\mathcal{S}_{j},\\
C^{\prime}\in\mathcal{C}^{\prime}\in\mathcal{S}_{j+1}\end{subarray}}\bigg|\sum_{v\in V^{\prime}}b(v)f_{C,C^{\prime}}(v)\bigg|\cdot D_{j}

is at most
i\gamma^{3}\tau
times the optimal cost of a transshipment flow on
G_{S,D_{i}}
satisfying demand
b
.

Proof.

Decompose the optimal transshipment flow into a collection
\mathcal{P}
of paths. Fix a path with endpoints
u,v
of flow value
F
, which contributes cost
F\cdot d_{G}(u,v)
to the transshipment solution. For any
j<i
, there are at most
\gamma^{2}
pairs
(\mathcal{C},\mathcal{C}^{\prime})
with
\mathcal{C}\in\mathcal{S}_{j}
and
\mathcal{C}^{\prime}\in\mathcal{S}_{j+1}
, and for each
(\mathcal{C},\mathcal{C}^{\prime})
, there are at most two pairs
(C,C^{\prime})
with
C\in\mathcal{C}
and
C^{\prime}\in\mathcal{C}^{\prime}
for which either
f_{C,C^{\prime}}(u)
or
f_{C,C^{\prime}}(v)
is nonzero: these are the pairs
C,C^{\prime}
that either both contain
u
or both contain
v
. So the total summation of
F\cdot|f_{C,C^{\prime}}(u)-f_{C,C^{\prime}}(v)|\cdot D_{j}
from level
j
is
O(\gamma^{3}\tau d_{G}(u,v))\cdot F
by
Lemma

4.5
. There are
i-1
levels for a total of
O(i\gamma^{3}\tau d_{G}(u,v))\cdot F
, which we charge to the cost
F\cdot d_{G}(u,v)
in the transshipment solution. It follows that
\sum_{u,v,F}\sum_{C,C^{\prime}}F\cdot|f_{C,C^{\prime}}(u)-f_{C,C^{\prime}}(v)|\cdot D_{j}
is at most
O(i\gamma^{3}\tau d_{G}(u,v))
times the transshipment cost, so it remains to relate this summation to the desired
\sum_{C,C^{\prime}}|\sum_{v\in V}b(v)f_{C,C^{\prime}}(v)|\cdot D_{j}
.

Summing over all paths in
\mathcal{P}
, we obtain

\displaystyle\sum_{u,v,F}\sum_{C,C^{\prime}}F\cdot|f_{C,C^{\prime}}(u)-f_{C,C^{\prime}}(v)|\cdot D_{j}

\displaystyle\geq\sum_{C,C^{\prime}}\left|\sum_{u,v,F}F\cdot(f_{C,C^{\prime}}(u)-f_{C,C^{\prime}}(v))\right|\cdot D_{j}.

(4.1)

Since the paths in
\mathcal{P}
together form a transshipment solution that satisfies demand
b
, the sum of
F\cdot(\mathbbm{1}_{u}-\mathbbm{1}_{v})
over all paths in
\mathcal{P}
(with endpoints
u,v
and flow
F
) is exactly the demand vector
b
. That is,
\sum_{u,v,F}F\cdot(\mathbbm{1}_{u}-\mathbbm{1}_{v})=b
as vectors. Multiplying each vector coordinate
v
by
f_{C,C^{\prime}}(v)
for any
C,C^{\prime}
and then summing over all coordinates, we obtain
\sum_{u,v,F}F\cdot(f_{C,C^{\prime}}(u)-f_{C,C^{\prime}}(v))=\sum_{v\in V^{\prime}}b(v)f_{C,C^{\prime}}(v)
. It follows that the right-hand side of (
4.1
) is exactly our desired expression
\sum_{C,C^{\prime}}\left|\sum_{v\in V}b(v)f_{C,C^{\prime}}(v)\right|\cdot D_{j}
, and we are done.
∎

In the next corollary, we replace
D_{j}
in the summation with
D_{j+1}
, which is needed for our final analysis, and we also add an additional restriction
C\subseteq C^{\prime}
.

Corollary 4.7
.

Assume that
\tau\leq\beta/8
.
For any demand vector
b:V^{\prime}\to\mathbb{R}
for the graph
G_{S,D_{i}}
, the summation

\displaystyle\sum_{j<i}\sum_{\begin{subarray}{c}C\in\mathcal{C}\in\mathcal{S}_{j},\\
C^{\prime}\in\mathcal{C}^{\prime}\in\mathcal{S}_{j+1}\\
{C\subseteq C^{\prime}}\end{subarray}}\bigg|\sum_{v\in V^{\prime}}b(v)f_{C,C^{\prime}}(v)\bigg|\cdot D_{{j+1}}

at most
O(i\gamma^{3}\tau\beta)
times the optimal cost of a transshipment flow on
G_{S,D_{i}}
satisfying demand
b
.

Proof.

We invoke
4.4
, which allows us to eliminate the restriction
C\subseteq C^{\prime}
, since all other pairs
(C,C^{\prime})
satisfy
f_{(C,C^{\prime})}(v)=0
for all
v
.
The statement follows from
Lemma

4.8
and the fact that
D_{j+1}=D_{j}\cdot\beta
.
∎

We now define our oblivious routing matrix
R
. It is the product of two matrices
A\times B
, where
A\in\mathbb{R}^{\vec{E}\times P}
and
B\in\mathbb{R}^{P\times(V^{\prime})}
where
P
is the set of all pairs of clusters
C,C^{\prime}\subseteq V^{\prime}
such that (1)
C\subseteq C^{\prime}
, and (2) there exists
j<i
such that
C
is a cluster in some clustering
\mathcal{C}\in\mathcal{S}_{j}
and
C^{\prime}
is a cluster in some clustering
\mathcal{C}^{\prime}\in\mathcal{S}_{j+1}
.

We construct
B\in\mathbb{R}^{P\times V^{\prime}}
as
B_{(C,C^{\prime}),v}=f_{(C,C^{\prime})}(v)
if clusters
C,C^{\prime}
both contain
v
, and
0
otherwise. For
A\in\mathbb{R}^{\vec{E}\times P}
, consider two clusters
C,C^{\prime}
. Since
C\subseteq C^{\prime}
, we have in particular the center
r_{C}
is in
C^{\prime}
. Take the path from
r_{C}
to
r_{C^{\prime}}
in the spanning tree
T_{C^{\prime}}
of
C^{\prime}
. For each edge
(u,v)
on the path, assign entry
A_{(u,v),(C,C^{\prime})}=1
if the path travels in the direction
u
to
v
, and
-1
otherwise. All other entries on column
(C,C^{\prime})
get assigned
0
.

Lemma 4.8
.

Assume that
\tau\leq\beta/8
.
For any demand vector
b:\mathbb{R}^{V^{\prime}}
for the graph
G_{S,D_{i}}
, let
\textsf{{opt}}(b)
be the optimal cost of a transshipment flow on
G_{S,D_{i}}
satisfying demand
b
. Then,
\textsf{{opt}}(b)\leq\left\lVert ABb\right\rVert_{1}\leq i\gamma^{3}\tau\beta\textsf{{opt}}(b)
.

Proof.

We begin with the first inequality. Observe that by construction, for each
v\in V
and
\mathbbm{1}_{v}
as the indicator vector of
v
, the vector
AB\mathbbm{1}_{v}
is the final flow distribution on nodes
V^{\prime}
of the
v
-associated flow. By
4.3
, this flow distribution is
\mathbbm{1}_{v_{D_{i}}}
, i.e., all flow eventually ends up at
v_{D_{i}}
. Since
\sum_{v\in V^{\prime}}b(v)=0
, the sum of the flows
AB\mathbbm{1}_{v}
over all
v\in V^{\prime}
routes all demands successfully. In other words,
AB\mathbbm{1}_{v}
is a valid transshipment flow on
G_{S,D_{i}}
satisfying demand
b
, so its cost
\left\lVert ABb\right\rVert_{1}
is at least
\textsf{opt}(b)
.

We now prove the second inequality. By construction of
B
, entry
(C,C^{\prime})
of
Bb
is exactly
\sum_{v}b(v)f_{(C,C^{\prime})}(v)
. Next, for the indicator vector
\mathbbm{1}_{(C,C^{\prime})}
, by construction of
A
, we have
\left\lVert A\mathbbm{1}_{(C,C^{\prime})}\right\rVert_{1}
is exactly the length of the path from
r_{C}
to
r_{C^{\prime}}
in the spanning tree
T_{C^{\prime}}
of
C^{\prime}
, which is at most
\alpha D_{j}
for the level
j
whose
\mathcal{S}_{j}
contains cluster
C^{\prime}
. It follows that

\displaystyle\left\lVert ABb\right\rVert_{1}

\displaystyle=\left\lVert A\times\sum_{(C,C^{\prime})}\left(\sum_{v\in V}b(v)f_{C,C^{\prime}}(v)\right)\mathbbm{1}_{(C,C^{\prime})}\right\rVert_{1}

\displaystyle\leq\sum_{(C,C^{\prime})}\left|\sum_{v\in V}b(v)f_{C,C^{\prime}}(v)\right|\left\lVert A\mathbbm{1}_{(C,C^{\prime})}\right\rVert_{1}

\displaystyle\leq\sum_{\begin{subarray}{c}(C,C^{\prime})\\
C^{\prime}\in\mathcal{C}^{\prime}\in\mathcal{S}_{j}\end{subarray}}\left|\sum_{v\in V}b(v)f_{C,C^{\prime}}(v)\right|\alpha D_{j}.

By
Corollary

4.7
, this is at most
\alpha\cdot O(i\gamma^{3}\tau\beta)\cdot\textsf{opt}(b)
.
∎

Finally, we discuss distributed implementations of multiplying by

and

for

.

Theorem 5.1

(Rounding)

The rest of the section is dedicated to the proof. Our algorithm is inspired by Cohen’s rounding algorithm for integral flow

in which one is given a fractional flow that satisfies integral demand constraints, and the algorithm constructs an integral flow of non-increased cost that satisfies the same demand. The algorithm uses bit-scaling, meaning that for

is named the new node

. The algorithm stops when there is a single node
s
. To construct the arborescence, the algorithm reverses the contractions in reverse chronological order, maintaining an arborescence of the current graph at each step. On each step, all contracted components are un-contracted. Edges in the arborescence of the contracted graph remain as edges in the arborescence of the un-contracted graph. This concludes the description of the algorithm, which clearly runs in
O(\log n)

\mathsf{Minor}
-
\mathsf{Aggregation}
rounds.

We will show that
(*)
each contracted component that contains
s
is always an arborescence, while each contracted component not containing
s
is always a directed cycle. For the contracted component containing
s
, we add the edges of its arborescence to the new arborescence. For each contracted component that is a directed cycle, we add all but one edge into the new arborescence. Aside from the proof of
(*)
, we can apply the standard analysis of Edmonds’ algorithm to show that the algorithm constructs an arborescence rooted at
s
. We also need to show that all nodes
v\in V
with
b(v)>0
are spanned by the arborescence, which we show after
(*)
.

We now prove the statement
(*)
. The proof that the contracted component containing
s
is an arborescence is also standard, and relies on the fact that we do not select an incoming neighbor into
s
. On the other hand, the proof that every other contracted component is a directed cycle is non-standard and relies on the specific construction of the graph
H
. Suppose for contradiction that such a component
C
is not a directed cycle; then, there must be node
u
in
C
with no incoming neighbor but at least one outgoing neighbor. Let
S\subseteq V
be the set of original vertices that eventually get contracted to
u
. Then,
S
has no incoming neighbor in
H
and at least one outgoing neighbor. By construction of
H
, this means that the flow
f
flows out of
S
on at least one arc, but never into
S
, so the net flow out of
S
is positive. Since the flow satisfies demands
b
, it follows that
\sum_{v\in S}b(v)<0
. This contradicts the fact that
b(v)\geq 0
for all
v\in S
, since
S
does not contain
s
.

Finally, we show that each node
v\in V
with
b(v)>0
is spanned by the arborescence. Suppose not; then, in some contracted graph, the node that
v
got contracted to must have no incoming neighbors (after which that node is deleted). For this to happen, the set
S\subseteq V
of original vertices that got contracted to that node must satisfy
\sum_{v\in S}b(v)\leq 0
. On the other hand,
b(v)>0
and
b(u)\geq 0
for all
u\in S
since
s\notin S
, a contradiction.
∎

6
Distributed Algorithms for the Eulerian-Orientation Problem

In this section, we show how to construct the
Eulerian-
Orientation
oracle
\mathcal{O}^{Euler}
.
Instead of talking about oracles, we talk about solving the
Eulerian-
Orientation
problem, in which we are asked to orient each edge such that each node has the same indegree and outdegree.
The main result of the section is the following theorem.

Theorem 6.1
.

There are deterministic algorithms for the
Eulerian-
Orientation
problem (that is, implementing the oracle
\mathcal{O}^{Euler}
) with the following round complexities.

1.

\widetilde{O}(\mathrm{Hop}\-\mathrm{Diam}(G))

\mathsf{CONGEST}
rounds if
G
comes from a fixed minor-free family.

2.

n^{o(1)}

\mathsf{CONGEST}^{PA}
rounds.

3.

\widetilde{O}(\sqrt{n}+\mathrm{Hop}\-\mathrm{Diam}(G))

\mathsf{CONGEST}
rounds.

There is a simple deterministic parallel algorithm for the
Eulerian-
Orientation
problem with near-linear work and polylogarithmic depth
[
12
]
.
The algorithm starts by pairing up all edges at every node of
H
. This splits
E(H)
into a set of closed walks. In the following
O(\log|E(H)|)
rounds, edges of the same closed walk are collected and the whole walk is consistently oriented.
This ensures the equal indegree and outdegree at each node of
H
.

Theorem 6.2

(
[
12
]
)
.

There is a deterministic
O(\log n)
depth and
O(m\log n)
work algorithm for the
Eulerian-
Orientation
problem on CRCW
\mathsf{PRAM}
.

However, to the best of our knowledge there are no non-trivial distributed algorithms known for the Eulerian-Orientation problem.
Here we provide a fast distributed algorithms using the Low Congestion Cycle Covers of
[
90
,
91
,
71
]
.
First, we prove several preparatory lemmas in
Section

6.1
and postpone the proof of
Theorem

6.1
in
Section

6.2
.

6.1
Technical Preparations

First, we prepare several necessary tools. We start by proving that if we contract degree two nodes in a graph, in the contracted graph we can simulate
\mathsf{CONGEST}^{PA}
rounds.

Lemma 6.3
.

Let
G
be a graph and
G^{\prime}
be a graph we get by contracting every node of degree
2
in
G
.
Then we can simulate one
\mathsf{CONGEST}^{PA}
round in
G^{\prime}
in
O(1)

\mathsf{CONGEST}^{PA}
rounds in
G
.

Moreover, if each edge
e\in E(G^{\prime})
is arbitrarily oriented, we can consistently orient the whole path in
G
contracting to
e
in that direction in
O(\log n)

\mathsf{CONGEST}^{PA}
rounds.

Proof.

To simulate one
\mathsf{CONGEST}
round in
G^{\prime}
, we first use one
\mathsf{CONGEST}
round in
G
to send the message along edges that remain the same in
G
and
G^{\prime}
.
Moreover, for each path
u_{1},u_{2},\dots,u_{k}
in
G
that contracts to an edge
e
in
G^{\prime}
, we let
u_{1}
send the message meant to
u_{k}
to its neighbor
u_{2}
.
The path
u_{2},u_{3},\dots,u_{k-1}
is node-disjoint from all other contracted paths, hence the message to

can be sent to
u_{k-1}
with one call to the partwise aggregation oracle. In one final

round the message is delivered to

.

The simulation of the partwise aggregation oracle in

is implemented analogously: each edge in

connecting two nodes of the same part is expanded to a full path. The new set of parts of

is still node-disjoint. We then use the partwise aggregation oracle of
G

The final claim is proven by building a tree of constant degree and radius
O(\log n)
on top of each path, in
O(\log n)

\mathsf{CONGEST}^{PA}
rounds.
The tree is then used to propagate an information about the orientation of the path to all nodes, in
O(\log n)

\mathsf{CONGEST}^{PA}
rounds. We omit details as they are standard and essentially the same as in the proof of
Lemma

6.6
.
∎

Dealing with virtual nodes

Next, we discuss how to handle virtual nodes. See
Section

B.3
for the definitions related to virtual nodes. In what follows, we assume that the input graph
G
may contain
\widetilde{O}(1)
virtual nodes and show how one can reduce this case to the case without any virtual nodes.

Lemma 6.4

(Variant of Lemma 4.3.2 in
[
87
]
)
.

Let
T\subseteq G
be a rooted tree of
G
and
S
a set of
marked
nodes.
Then, in
\widetilde{O}(1)

\mathsf{CONGEST}^{PA}
rounds, we can output a set of paths
P=\{p_{1},p_{2},\dots,p_{\lfloor S/2\rfloor}\}
such that

1.

Each path
p\in P
satisfies
p\subseteq T
.

2.

All nodes of
S
, except of possibly one, are endpoints of exactly one
p\in P
.

3.

Any two
p_{1},p_{2}\in P
are edge-disjoint.

4.

We can implement partwise aggregation on
P
in
O(1)

\mathsf{CONGEST}^{PA}
rounds of
G
.

Proof.

We first describe how we build the set
P
of paths.
For each
u\in V(T)
, let
x_{u}=1
if
u\in S
and
x_{u}=0
otherwise. We use
Lemma

B.8
to compute
s_{u}=\sum_{v\in T_{u}}x_{v}
for every
u
, where
T_{u}
is the subtree of
u
in
T
.
If
s_{u}
is odd,
u
will be connected in a path with its parent
\textrm{par}(u)
(unless
u
is the root) and sends this information to
\textrm{par}(u)
. Next, each node
u
collects messages from all its children nodes to know which of them will be in the same path as
u
. The node
u
arbitrarily pairs up these proposals into paths (for each such created path,
u
is the node in it closest to the root).
By construction, there is a leftover, unpaired, proposal if and only if
u
itself proposed and
u\not\in S
(unless
u
is a root).
In this case, the leftover unpaired child of
u
is combined with
u
in the same path.
Otherwise, if
u\in S
and children of
u
are paired up,
u
is the endpoint of a new path that continues to
\textrm{par}(u)
.
This local algorithm defines the set of paths
P
.
The only reason why
P
not necessarily satisfies properties 1,2,3 from the lemma statement is that if
|S|
is odd,
P
contains an additional path from a vertex in
S
to the root of
T
. Next, we describe how to implement any partwise aggregation on

and this allows us to remove this additional path from

so that it satisfies all three desired properties.

To prove property 4, let
p_{i}\in P
be any path and let us write
p_{i}=r_{i},\dots,s_{i}^{-},s_{i},s_{i}^{+},\dots,t_{i}
, where
s_{i}
is the node on
p_{i}
closest to the root of
T
.
Consider any two paths
P_{i},P_{j}
and let

. We know that the edge from
v
to its parent can be present in at most one of the paths
P_{i},P_{j}
as they are edge-disjoint, hence
v\in\{s_{i},s_{j}\}
. That is, if two paths
P_{i},P_{j}
intersect in a node, the node is the “top” node of one of them.
Hence, to implement a partwise aggregation on
P
, we compute the operation on the parts
\{\{r_{i},\dots,s_{i}^{-}\},\{s_{i}^{+},\dots,t_{i}\}\}_{1\leq i\leq{\lfloor S/2\rfloor}}
that are node-disjoint and use additional
O(1)

\mathsf{CONGEST}
rounds to extend the operation to the set of full paths.
∎

Proposition 6.5
.

Given an input
H
to the
Eulerian-
Orientation
problem with
k=\widetilde{O}(1)
virtual nodes, there is a deterministic distributed algorithm that orients some subgraph
I\subseteq H
such that

1.

All edges incident to virtual nodes are in
I
.

2.

Each node has the same indegree and outdegree in
I
. In particular, the residual graph
H\setminus I
is still Eulerian.

The algorithm needs
\widetilde{O}(1)

\mathsf{CONGEST}^{PA}
rounds.

First, we sketch how to prove the above proposition if there is just one virtual node.
We then proceed with the more difficult (but still routine) proof for multiple virtual nodes.

To prove
Proposition

6.5
with
k=1
, we start by finding any spanning forest
F
of
H
in
\widetilde{O}(1)

\mathsf{CONGEST}^{PA}
rounds using the distributed MST algorithm
[
74
]
.
Next, we use
Lemma

6.4
with
S
being the neighborhood of the virtual node
u

in any component of

is even, we pair all of its nodes.
Note that each constructed path closes a cycle together with the two appropriate virtual edges to

. We can use the fact that we can aggregate information on these paths (property 4 in

6.4
) to consistently orient the graph

formed by these cycles, which proves the proposition in case

.
We now continue with the proof for
k=\widetilde{O}(1)
.

Proof.

The first part of the algorithm consists of
k

During the
i
-th step we orient some of the virtual edges incident to
u_{i}
as well as some non-virtual edges. We maintain a residual graph
H_{i}
of not yet oriented edges at the beginning of the
i
-th phase.

More precisely, at the beginning of the
i
-th phase we compute a spanning forest of
H_{i}[V(G)]
(that is, we consider only the graph of non-virtual nodes and edges of
H_{i}
) by an MST algorithm. Next, in each connected component of

we use, in parallel,
Lemma

6.4
to match nodes neighboring with

. At most one node is unmatched in each connected component of

.
Each path
p
in the set of matching paths closes a cycle together with the two virtual edges connecting the endpoints of
p
with
u_{i}
. We can orient this cycle consistently in
\widetilde{O}(1)

\mathsf{CONGEST}^{PA}
rounds using property (4) in
Lemma

6.4
. This leaves us with a new residual graph
H_{i+1}
such that
H_{i+1}[V(G)]
has possibly more connected components but it still retains the property that each connected component of
H_{i+1}[V(G)]
is incident to at most one edge from
u_{i}
.
Hence, after
k

H^{\prime}=H_{k+1}
such that each connected component of
H^{\prime}[V(G)]
contains at most
k
edges to virtual nodes. Moreover, the number of these incident virtual edges is even.

In the second part of the algorithm, we use
Lemma

6.4
on the spanning forest of
H^{\prime}[V(G)]
again, but this time every node incident to
\{u_{1},\dots,u_{k}\}
is in the set
S
. The lemma yields a set of edge-disjoint paths such that each path
p
between two nodes

and
t
, incident to
u_{i}
and
u_{j}
, respectively, connects
u_{i}
with
u_{j}
).
For each such path, we replace the two virtual edges
\{u_{i},s\},\{u_{j},t\}
with a new virtual edge
\{u_{i},u_{j}\}
, to create a new graph
H^{\prime\prime}
. After the replacement, there are no connections between the virtual and nonvirtual nodes, hence
H^{\prime\prime}
satisfies that
H^{\prime\prime}[\{u_{1},\dots,u_{k}\}]
is an Eulerian graph.
All nodes of
G
now learn the graph
H^{\prime\prime}[\{u_{1},\dots,u_{k}\}]
in
O(k^{2})=\widetilde{O}(1)

\mathsf{CONGEST}^{PA}
rounds and all nodes of

compute internally the same Eulerian orientation of it.
Finally, we will uncontract each contracted edge
(u_{i},u_{j})
of

into the original path and orient the respective path

More concretely, for every multi-edge

\mathsf{CONGEST}^{PA}

Hence, in
\widetilde{O}(1)

\mathsf{CONGEST}^{PA}

Weaker Result

We now give an algorithm for the
Eulerian-
Orientation
problem with weaker than desired propeties. It will be used in the proof of
Theorem

6.1
.

Lemma 6.6
.

There is a distributed algorithm that solves the
Eulerian-
Orientation
problem in
\widetilde{O}(\sqrt{|E(G)|}+\mathrm{Hop}\-\mathrm{Diam}(G))
rounds.

Proof.

We assume the input Eulerian graph
H
does not contain any virtual nodes, as we can deal with them using
Proposition

6.5
and
Theorem

B.9
in
\widetilde{O}(\sqrt{n}+\mathrm{Hop}\-\mathrm{Diam}(G))

\mathsf{CONGEST}
rounds.

Each node
u
arbitrarily pairs up the edges of
H
incident to it – note that their number is even.
Starting in any edge, the pairing defines a closed walk containing the edge. We will next orient each such walk consistently, which solves the
Eulerian-
Orientation
problem.

To orient the walks, each one first elects a leader in
O(\log n)
steps as follows. At first, we interpret each edge as a path of length
1
.
Next, we concatenate these paths using our pairing into progressively longer paths, until all paths of the walk are glued together.
In particular, consider the incidence graph of our paths, induced by our edge pairing, which is always a set of disjoint cycles.
In each step we use Linial’s deterministic algorithm to compute a
(3,4)
-ruling set
[
81
]
.
That means we mark some of the paths such that the marked paths are of distance at least
3
in the incidence graph, while every path is of distance at most
4
to a marked path. Next, each unmarked path is joined with the closest marked path, to form a longer path.
There are always at least
3
and at most
5
paths forming a longer path, unless the whole walk is connected in this step.
Hence, in
O(\log n)
steps, all paths are connected. Each step needs
O(\log^{*}n)

\mathsf{CONGEST}
rounds of communication in the incidence graph. To simulate one round in the incidence graph, we need to implement sending messages in parallel from one endpoint of a path to the other endpoint. To do that, each path remembers its length. If it is at most
\sqrt{|E(H)|}
, then it sends the message from its endpoint to the other one along its edges. If it is more than
\sqrt{|E(H)|}
, it broadcasts the message to the whole graph using the edges of
G
.
As there are at most
\sqrt{|E(H)|}
such paths, it is a standard fact that, with correct implementation, in
O(\mathrm{Hop}\-\mathrm{Diam}(H)+\sqrt{|E(H)|})
rounds all broadcasts finish.
Hence, in
\widetilde{O}(\mathrm{Hop}\-\mathrm{Diam}(H)+\sqrt{|E(H)|})=\widetilde{O}(\mathrm{Hop}\-\mathrm{Diam}(G)+\sqrt{|E(G)|})
rounds each walk can elect a leader. The leader chooses an arbitrary orientation and, similarly to the election, this orientation is messaged to smaller and smaller paths, until after additional
O(\log n)
steps, each implemented in
\widetilde{O}(\mathrm{Hop}\-\mathrm{Diam}(G)+\sqrt{|E(G)|})
rounds, each edge knows it.

∎

Remark
.

The above result seems to imply that the
Eulerian-
Orientation
problem can be solved in
\widetilde{O}(1)
part-wise aggregations.
However, in each step, the parts where aggregation happens are only edge-disjoint and not node-disjoint.

A

The Eulerian Orientation Algorithm

Finally, we are ready to prove

.

Proof.

We start with item (1), the proofs of other items will be similar.

We will work in a graph

When we work later with

.
Note that every node in

Hence, we have

\displaystyle|E(H^{\prime}_{i})|\geq 4|V(H^{\prime}_{i})|/2=2|V(H^{\prime}_{i})|.

(6.1)

Next, we describe the algorithm.

1.

Let
\overline{H}_{i}
be the graph that we get from

by subdividing each edge

.
We run the clustering algorithm for separated strong-diameter network decomposition from

.

.
The algorithm needs
\widetilde{O}(1)

\mathsf{CONGEST}
rounds of
\overline{H}_{i}
, hence can be implemented in
\widetilde{O}(1)

\mathsf{CONGEST}
rounds of
H^{\prime}_{i}
.
After building the clustering in
\overline{H}_{i}
, for each

.
This new clustering of nodes in

still consists of disjoint clusters due to the property

Appendix B
Computational Models: Minor-Aggregation,
\mathsf{CONGEST}
,

In this section we give a description of various models we use throughout this paper.

B.1
\mathsf{CONGEST}
model

First, we define the standard distributed model of computation called
\mathsf{CONGEST}
. Any algorithm defined in the
\mathsf{Minor}
-
\mathsf{Aggregation}
model efficiently compiles down to
\mathsf{CONGEST}
.

Definition B.1

(
\mathsf{CONGEST}
)
.

We are given an undirected graph
G=(V,E)
called the “communication network”. The vertices of
G
are called nodes and they are independent computational units (i.e., have their own processor and private memory). Communication between nodes occurs in synchronous rounds. In each round, each pair of nodes adjacent in
G
exchange
O(\log n)
bits. Nodes perform arbitrary local computation between rounds. Initially, nodes wake up at the same time and only know their unique
O(\log n)
-bit ID.

B.2
Partwise Aggregation, Low-Congestion Shortcut Framework, and the
\mathsf{CONGEST}^{PA}
model

We start by giving some background on partwise aggregation (PA) and the low-congestion shortcut framework before defining the
\mathsf{CONGEST}^{PA}
model.

Partwise aggregation (PA)
is a high-level primitive that frequently arises while designing distributed (and parallel) algorithms. A partwise aggregation task is specified by giving each node a
private value
, choosing a simple aggregation function such as min, max, or sum, and specifying a collection of connected and node-disjoint subsets
P_{1},P_{2},\ldots\subseteq V
. To solve partwise aggregation, all nodes
v
are required to output the aggregate of all private values of the nodes in
v
’s part. Note that PA is immediately solvable in parallel using near-linear work and polylogarithmic depth.

While extremely simple, the utility of PA stems from the fact that many important graph problems (e.g., MST, SSSP, min-cut, etc.) can be reduced to a small (polylogarithmic or
n^{o(1)}
) number of partwise aggregation instances. Therefore, any reduction to
\mathrm{poly}\log n
many PA instances directly gives near-optimal parallel algorithms.

The low-congestion shortcuts framework
was first introduced in
[
50
]
and developed over a long sequence of works
[
50
,
59
,
60
,
58
,
66
,
51
,
73
,
75
,
53
,
52
]
. The framework defines a natural graph parameter called
\mathrm{Shortcut}\-\mathrm{Quality}(G)
which assigns a number to each undirected and unweighted graph
G
. The framework then shows that shortcut quality is
THE
parameter that characterizes the distributed complexity for a large class of seemingly unrelated graph problems. In particular: any distributed
\mathsf{CONGEST}
algorithm for MST, (approximate) min-cuts, connectivity, max-flow, partwise aggregation
[
73
]
, and SDD or Laplacian system solving
[
45
,
3
]
requires
at least

\mathrm{Shortcut}\-\mathrm{Quality}(G)
rounds on a network
G
(up to polylogarithmic factors), even if only a non-trivial approximation is required and randomization is allowed. In more details, on a fixed graph
G
the adversary can always force any correct algorithm to require
\widetilde{\Omega}(\mathrm{Shortcut}\-\mathrm{Quality}(G))
rounds if the adversary is allowed to choose the input (e.g., edge weights).

On the other hand, the framework complements the above lower bound with an efficient distributed implementation of partwise aggregation. The ultimate goal would be to show that PA can be solved in (deterministic)
\widetilde{O}(\mathrm{Shortcut}\-\mathrm{Quality}(G))

\mathsf{CONGEST}
rounds, which would be near-optimal and would yield unconditional universally near-optimal algorithms for all of the above problems. However, we currently only achieve such a result under some conditions about the graph topology
G
. For example, such a result can be achieved in excluded-minor graphs where
[
59
]
and
[
66
]
show that PA can be solved in
\widetilde{O}(\mathrm{Shortcut}\-\mathrm{Quality}(G))=\widetilde{O}(\mathrm{Hop}\-\mathrm{Diam}(G))
rounds. Moreover, very recent work on hop-bounded oblivious routings and hop-bounded expander decomposition
[
53
,
52
]
shows that PA can be solved in randomized
n^{o(1)}

\mathsf{CONGEST}
rounds whenever
\mathrm{Shortcut}\-\mathrm{Quality}(G)\leq n^{o(1)}
.

With the knowledge that PA can be efficiently implemented, we define the
\mathsf{CONGEST}^{PA}
model which is simply
\mathsf{CONGEST}
with access to a PA oracle.

Definition B.2

(
\mathsf{CONGEST}^{PA}
model)
.

The
\mathsf{CONGEST}^{PA}
model naturally extends the
\mathsf{CONGEST}
model. However, in each round we can choose to either perform a standard
\mathsf{CONGEST}
round, or we can call the PA oracle. For the latter, each node chooses a private input at the start and learns the partwise aggregate at the end of the round.

Per the above discussion, we can implement the PA oracle with the following constraints.

Theorem B.3
.

A
\tau
-round
\mathsf{CONGEST}^{PA}
algorithm can be simulated in
\widetilde{O}(\tau\cdot\tau_{PA})
rounds of
\mathsf{CONGEST}
, where
\tau_{PA}
is the number of rounds in which one can solve any partwise aggregation instance on
G
. The following bounds have been proven for
\tau_{PA}
:

•

For all graphs
G
, there is a deterministic algorithm with
\tau_{PA}\leq\widetilde{O}(\mathrm{Hop}\-\mathrm{Diam}(G)+\sqrt{n})
.
[
50
]

•

If
G
is minor-free, there is a deterministic algorithm with
\tau_{PA}\leq\widetilde{O}(\mathrm{Hop}\-\mathrm{Diam}(G))
(the hidden constants depend on the family).
[
51
]

•

If the nodes of
G
know the topology in advance, there is a randomized algorithm with
\tau_{PA}\leq\widetilde{O}(\mathrm{Shortcut}\-\mathrm{Quality}(G))
.
[
73
]

•

If
\mathrm{Shortcut}\-\mathrm{Quality}(G)\leq n^{o(1)}
, there is a randomized algorithm with
\tau_{PA}\leq n^{o(1)}
.
[
52
]

B.3
Minor-Aggregation Model

In this section we define the
\mathsf{Minor}
-
\mathsf{Aggregation}
model, defined in
[
103
]
and
[
57
]
, an expressive model which provides an easy-to-use interface to the most recent advancements in the low-congestion framework. Specifically, the
\mathsf{Minor}
-
\mathsf{Aggregation}
model leverages partwise aggregation to implement fast aggregation operations on minors of the communication network
G
. The connection between minor aggregations and partwise aggregations is straightforward: computing a partwise aggregate is basically the same as computing a node-wise aggregate in the minor in which each part is contracted.

We first define a notion of aggregations and then formally specify the Distributed
\mathsf{Minor}
-
\mathsf{Aggregation}
model.

Definition B.4

(Aggregation operator)
.

An aggregation operator
\bigoplus
takes two
B
-bit inputs
m_{1},m_{2}
for some
B=\widetilde{O}(1)
, and combines them into a new
B
-bit output
m_{1}\bigoplus m_{2}
. Furthermore, given
k
inputs
m_{1},\ldots,m_{k}
, their
\bigoplus
-aggregate
\bigoplus_{i=1}^{k}m_{i}
is the result from arbitrarily aggregating some two inputs until a single one remains.

Note that for a commutative and associative operator (e.g., sum or max), the value
\bigoplus_{i=1}^{n}m_{i}
is unique.
However, we gain flexibility by allowing for arbitrary operators where the output might depend on the execution sequence.

Definition B.5

(Distributed Minor-Aggregation model)
.

We are given an undirected graph
G=(V,E)
. Both nodes and edges are separate computational units (i.e., have their own processor and private memory). Communication occurs in synchronous rounds and nodes/edges perform
\widetilde{O}(1)
-work local computation between rounds. Initially, nodes wake up at the same time and only know their unique
\widetilde{O}(1)
-bit ID, while edges know the IDs of their endpoints. Each round consists of the following three steps (in that order).

•

Contraction step.
Each edge
e
chooses a value
c_{e}=\{\bot,\top\}
. This defines a new
minor network

G^{\prime}=(V^{\prime},E^{\prime})
constructed as
G^{\prime}=G/\{e:c_{e}=\top\}
, i.e., by contracting all edges with
c_{e}=\top
and self-loops removed. Vertices
V^{\prime}
of
G^{\prime}
are called supernodes, and we identify supernodes with the subset of nodes
V
it consists of, i.e., if
s\in V^{\prime}
then
s\subseteq V
.

•

Consensus step.
Each individual node
v\in V
chooses a
\widetilde{O}(1)
-bit value
x_{v}
. For each supernode
s\in V^{\prime}
we define
y_{s}:=\bigoplus_{v\in s}x_{v}
, where
\bigoplus
is some predefined aggregation operator. All nodes
v\in s
learn
y_{s}
.

•

Aggregation step.
Each edge
e\in E^{\prime}
connecting supernodes
a\in V^{\prime}
and
b\in V^{\prime}
learns
y_{a}
and
y_{b}
, and chooses two
\widetilde{O}(1)
-bit values
z_{e,a},z_{e,b}
(i.e., one value for each endpoint). Finally, (every node of) each super
s\in V^{\prime}
learns the aggregate of its incident edges in
E^{\prime}
, i.e.,
\bigotimes_{e\in\text{incidentEdges(s)}}z_{e,s}
where
\bigotimes
is some predefined aggregation operator.

Distributed storage and inputs.
Our
\mathsf{Minor}
-
\mathsf{Aggregation}
algorithm operates on objects that are
“distributedly” stored
, meaning that each processor has its own part of the object in private memory. Specifically, we store a
node vector

x\in\mathbb{R}^{V}
by storing
x_{v}
in node
v
. Similarly, edge vectors
x\in\mathbb{R}^{E},x\in\mathbb{R}^{\vec{E}},x\in\mathbb{R}^{\overleftrightarrow{E}}
are distributed over edges. Subgraphs
H\subseteq G
are specified by distributedly storing the characteristic vectors
\mathbb{1}_{V(H)}\in\mathbb{R}^{E(G)}
and
\mathbb{1}_{E(H)}\in\mathbb{R}^{E(G)}
. Initially, the problem-specific input is assumed to be distributedly stored. For transshipment and SSSP, we assume the lengths (edge vector) and demands (node vector) are stored. At termination, the output is required to be distributedly stored.

Minors.
Algorithms designed in this model can take advantage of several high-level primitives typically unavailable in other distributed models (due to the power of being able to solve PA). Notably, any algorithm can be run on any minor in a black-box manner. For example, this allows extremely simple descriptions of contraction-based algorithms such as Boruvka’s MST algorithm.

Corollary B.6
.

Any
\tau
-round
\mathsf{Minor}
-
\mathsf{Aggregation}

\tau
-round
\mathsf{Minor}

\mathsf{Aggregation}
algorithm on

e\in E
needs to know whether

G

B.4
Virtual Nodes in the
\mathsf{Minor}
-
\mathsf{Aggregation}
Model

Another useful high-level primitive is adding
\widetilde{O}(1)
arbitrarily-connected virtual nodes to the communication network
G
and running an arbitrary
\mathsf{Minor}
-
\mathsf{Aggregation}
algorithm in a black-box manner on the new graph while only incurring a
\widetilde{O}(1)
slowdown. Note that such an operation is completely inadmissible in other models of distributed computing like
\mathsf{CONGEST}

[
87
]
where nodes are allowed to send/receive arbitrary (i.e., non-aggregate) information to/from each one of their neighbors separately, as this would allow efficiently communicating the entire network topology to a single node and solving the problem locally. On the other hand, virtual-node addition can be efficiently simulated in the
\mathsf{Minor}
-
\mathsf{Aggregation}
model due to the “aggregate”-nature of communication. For example, we use this operation to connect a “supersource” node, enabling us to use our standard SSSP algorithm to implement a set-source-
S
shortest path.

Given a graph
G
, we can construct a
virtual graph
by repeatedly adding a
virtual node
and connecting it to an arbitrary set of neighbors. This is formalized in the following definition.

Definition B.10
.

A virtual graph
G_{\mathrm{virt}}
extending a connected graph
G=(V,E)
, is a graph whose node set can be partitioned into
V
and a set of so-called
virtual nodes

V_{\mathrm{virt}}
, i.e.,
V(G_{\mathrm{virt}})=V\sqcup V_{\mathrm{virt}}
. Furthermore, the edge set
E(G_{\mathrm{virt}})
can be partitioned into
E
and a set of so-called
virtual edges

E_{\mathrm{virt}}
with the property that every virtual edge is adjacent to at least one virtual node. We say
G_{\mathrm{virt}}
has at most
\beta
virtual nodes if
|V_{\mathrm{virt}}|\leq\beta
.

Distributed storage of virtual graphs.
In order to “construct” a virtual graph, one needs to be able to distributedly store it; unfortunately, this requires specifying some low-level storage details. A virtual graph
G_{\mathrm{virt}}
is distributedly stored in
G
in the following way. A virtual edge connecting a non-virtual
u
and a virtual
v
is only stored in
u
(other nodes do not need to know about its existence). A virtual edge between two virtual nodes is required to be known by all nodes. All nodes know about all virtual nodes.

Simulations on virtual graphs.
We can add
\beta
many virtual (arbitrarily interconnected) nodes to any graph
G
and still simulate any Minor-Aggregation algorithm on the virtual graph with a
O(\beta+1)
blowup in the number of rounds. We say a node/edge
a
simulates a virtual node/edge
v
if
a
’s private memory contains all data of
v
’s private memory in the virtual graph (i.e.,
a
knows what
v
is outputting in each round, and learns everything
v
receives). The following simulation result formalizes this (proven in
[
57
]
).

Theorem B.11
.

Suppose
A_{\mathrm{virt}}
is a
\tau
-round Minor-Aggregation algorithm on a virtual graph
G_{\mathrm{virt}}(\beta)
that extends
G
and has at most
\beta
virtual nodes. Any such
A_{\mathrm{virt}}
can be simulated in
G
with a
\tau\cdot O(\beta+1)
-round Minor-Aggregation algorithm.
Upon termination, each non-virtual node
v\in V(G)
learns all information learned by
v
and all virtual nodes in
