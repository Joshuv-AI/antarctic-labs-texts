GPT-4 as an interface between researchers and computational software: improving usability and reproducibility
Juan C. Verduzco, Ethan W. Holbrook, Alejandro Strachan

Abstract
Large language models (LLMs) are playing an increasingly important role in science and engineering. For example, their ability to parse and understand human and computer languages makes them powerful interpreters and their use in applications like code generation are well-documented. We explore the ability of the GPT-4 LLM to ameliorate two major challenges in computational materials science: i) the high barriers for adoption of scientific software associated with the use of custom input languages, and ii) the poor reproducibility of published results due to insufficient details in the description of simulation methods. We focus on a widely used software for molecular dynamics simulations, the Large-scale Atomic/Molecular Massively Parallel Simulator (LAMMPS), and quantify the usefulness of input files generated by GPT-4 from task descriptions in English and its ability to generate detailed descriptions of computational tasks from input files. We find that GPT-4 can generate correct and ready-to-use input files for relatively simple tasks and useful starting points for more complex, multi-step simulations. In addition, GPT-4’s description of computational tasks from input files can be tuned from a detailed set of step-by-step instructions to a summary description appropriate for publications. Our results show that GPT-4 can reduce the number of routine tasks performed by researchers, accelerate the training of new users, and enhance reproducibility.

- large language models; artificial intelligence; computational simulations; molecular dynamics

We evaluate input files generated by GPT-4 from three task descriptions created by the authors and two obtained from the literature and its ability to generate human readable descriptions of a computational task from a LAMMPS input file. We find that GPT-4 creates working and accurate input files for relatively simple and well described tasks. This achievement by itself is quite remarkable; GPT-4 selects the correct crystal structure for the material of interest and the correct thermostat to create the desired thermodynamic ensemble, among other simulation details. For complex tasks like simulating spall failure following a high-velocity impact simulation, GPT-4 creates input files that, while requiring modification, provide an excellent starting point and significantly reduce the time required to create a working input file. Finally, given a LAMMPS input file, GPT-4 is capable of generating a detailed description of the simulation performed and, if prompted, can provide a summary statement that is appropriate to be included in the methods section of a publication.

Methods

We investigate GPT-4’s ability to generate LAMMPS input files from the description of MD tasks in English, as well as the inverse problem of explaining what a LAMMPS input file does. Our goals are to reduce the number of routine tasks performed by researchers, accelerate the training of new users, and enhance reproducibility. To address the first challenge, we designed two tasks. Task 1 assesses GPT-4 generated LAMMPS input files from three task descriptions of increasing complexity created by the authors. Task 2 tests the creation of LAMMPS input files based on the methods section of two publications. To address the second challenge, Task 3 prompts GPT-4 to generate comprehensive and summary human-readable descriptions of computational tasks provided with a LAMMPS input file obtained from literature. These tasks evaluate GPT-4’s understanding of the LAMMPS input language but also its ability to generalize, which enables it to perform tasks combining information about various topics, to understand complex procedures, and their translation into instructions
[
14
]
.

For each prompt, we asked GPT-4 to generate ten LAMMPS input files and we executed them using LAMMPS version 29 Oct 2020 for Task 1 and Task 2.2 and version 15 Sep 2022 for Task 2.1 which required a separate set of packages. The generated input files are evaluated according to the metrics outlined in Table
1
. We define “script validity” as the fraction of input files that execute in their entirety without any modification and “script accuracy” refers to the subset of those files that successfully performed the task requested. “Consistency” measures the average pairwise similarity between the files generated and “usefulness” denotes the average similarity between the GPT-4 generated files and a
gold standard
input file created by the authors. We measure similarity between input files using the cosine similarity criteria. To account for the non-numerical and non-key-pair values, each file is transformed into term-frequency vectors
[
19
]
. Thus, the cosine similarity metric identifies common keywords. We note that quantifying the similarity between LAMMPS input files is challenging due to the custom nature of the LAMMPS input language. For example the order of commands may or may not affect the simulation. In addition, similar key-value pairs can result in drastically different physics simulations (i.e.
fix 1 all npt/sphere temp 300.0 300.0 100.0
vs
fix 1 all nvt temp 300.0 300.0 100.0
).

Results

Task 1: LAMMPS input file generation from authors’ descriptions

GPT-4 (version March 23, 2023) was tasked with the creation of LAMMPS input files from an English description of the desired simulation. We created three descriptions of MD tasks of increasing complexity, see box below, and used them as input to GPT-4 through ChatGPT with this prompt: Make a LAMMPS script based off this method description: “
Prompt
”. Prompt engineering on distinct ways to request the creation of the file is out of the scope of this work. Ten input files generated were generated for each prompt and analyzed as discussed above after discarding the many useful comments added by GPT-4 to explain the workings of the LAMMPS commands.

Prompt:Task 1

We used molecular dynamics with LAMMPS to equilibrate an Al sample under isobaric, isothermal conditions (NPT ensemble) at 300 K and 1 atm for 500 ps. The initial conditions were obtained by replicating the fcc unit cell 5 times in each direction. We used Nose-Hoover thermostat and barostat with relaxation timescales of 0.1 and 1 ps, respectively. All MD simulations were performed using LAMMPS. Atomic interactions were obtained using an embedded atom model developed by Ercolessi and Adams [1] obtained from OpenKIM.org. [1] EAM potential (cubic natural spline tabulation) for Al developed by Ercolessi and Adams (1994) v002. OpenKIM. 2018. doi:10.25950/376e3e7e.

Prompt:Task 2

We characterized the melting of a bulk Ni sample using molecular dynamics with LAMMPS. The initial condition was obtained by replicating the Ni unit cell 10 times in each direction. Initial velocities were drawn from the Maxwell-Boltzmann distribution at 600 K. The system was heated from 300 K to 2500 K continuously, at a rate of 10 K per ps under isothermal and isobaric conditions at 1 atm. Interactions were described using an embedded atom model developed by Mishin et al. in 1999 [1] obtained from OpenKIM.org. [1] EAM potential (LAMMPS cubic hermite tabulation) for Ni developed by Mishin et al. (1999) v005. OpenKIM; 2018. doi:10.25950/a88dfc37.

Prompt:Task 3

We simulate spall failure on Nb single crystals using high-velocity impact simulations using molecular dynamics (MD) with the LAMMPS code. We simulate the impact of a projectile on a target with a relative velocity of 2 km/s. The projectile is obtained by replicating the Nb BCC unit cell 20 times along the [100], [010], and [001]; the target is longer along the shock direction and is obtained by replicating the BCC unit cell 20 times along [100] and [010] and 40 times along [001]. We apply periodic boundary conditions along the directions normal to the impact direction, [001], and free boundaries along [001]. A gap of 1.5 nm initially separates the target and projectile. The system is equilibrated at 300 K for 100 ps using isothermal, isochoric MD. An impact velocity of 2 km/s is added to the thermal velocities to all the atoms in the projectile along [001] in the direction of the target. Adiabatic MD is used to simulate the impact and subsequent expansion. All atomic interactions are described using an EAM potential developed by Fellinger et al. [1] and downloaded from openKIM [2]. [1] Fellinger MR, Park H, Wilkins JW. Force-matched embedded-atom method potential for niobium. Physical Review B. 2010Apr;81(14):144119. doi:10.1103/PhysRevB.81.144119
[2] https://doi.org/10.25950/befb2eea.

Model Selection.
All the files generated select the correct crystal structure (FCC for Al and Ni and BCC for Nb) and lattice parameters even when these values are not explicitly included in the prompt (except for Nb being BCC). It is unclear whether the model infers this information or it is selected from similar input files seen during training. The input files correctly set the boundary conditions as periodic for Prompts 1 and 2 and, remarkably, 9/10 input files for Prompt 3 correctly set up a free boundary along the Z-direction.

Interatomic potentials.
LAMMPS input files always refer to separate files for the interatomic potential required for the simulation and the file names vary between different files obtained from the same prompt. These names are placeholders, as GPT-4 consistently included warnings about the need to add the correct potential file with the correct name. For instance, in Prompt 1, the file name for the potential varied between different files, with names such as ”Al99.eam.alloy”, ”Al.eam.alloy”, and ”Al_Ercolessi_Adams.eam.alloy”. The ”Al99.eam.alloy” filename coincides with the Al potential by Mishin and Farkas
[
22
]
available on OpenKim
[
23
]
. However, none of the files matched the correct filename for the potential ”Al_EA.eam.alloy” for the Ercolessi and Adams
[
24
]
EAM potential. Interestingly, GPT-4 reference Finnis-Sinclair form of the Embedded Atom Model (EAM) is some cases and the standard EAM form in others; regardless of the form, the simulations are identical.

Ensemble and simulation time.
GPT-4 correctly interprets the prompts regarding the desired thermodynamic ensemble requested and uses the LAMMPS
fix
command to setup the correct simulation in the majority of the cases. In all cases for Prompts 1 and 2, GPT-4 selects the correct ensemble and Nosé-Hoover thermostats and barostats. Prompt 3 requests a thermalization using isothermal-isochoric MD (NVT ensemble) followed by an NVE simulation of the process of impact. 8/10 of the input files use appropriate thermostats for the initial simulation (interestingly various approaches are used to accomplish this: Berendsen, Nosé-Hoover, and Langevin thermostats). The impact simulations call for an NVE simulation and GPT sets this up correctly in 9/10 cases. We note that setting up thermostats or barostats requires the non-trivial step of selecting damping parameters (relaxation times); values close to 0.1 ps are considered ideal for thermostatting under most conditions and a value around 1 ps is appropriate for barostats. GPT-4 uses appropriate relaxation times 23 out of the 27 times a Nosé-Hoover thermostat is used and 19/20 in the case of barostats. The length of the simulation, the product between time step and number of MD steps, is always accurate for Prompt 1 where it is explicitly declared, and is inaccurate in 3/10 files generated for Prompt 2 where it has to be inferred from the heating rate. For Prompt 3, a spall simulation, the description did not specify a total simulation time. This is common practice, and it is assumed that the simulation time would be long enough for spall failure to fully develop in the case of strong enough shocks. This time can be estimated from the speed of sound of the material, or more accurately, from knowledge of the shock speed as a function of particle velocity. GPT-4 appears to select a standard simulation time.

Consistency and accuracy.
We now turn our attention to the consistency and accuracy metrics, see Table
1
. The cosine similarity metric indicates that the input files for each prompt are closely related to each other, with similarity scores between 0.81 and 0.87. To establish a baseline, we computed the cosine similarity across prompts and obtained that the average similarity score hovers around 0.55 - 0.7, see Table
3
. This is again clearly a result of the custom nature of the LAMMPS input language, which is not fully captured by the cosine similarity metric. It is interesting to note that we find increasing variability in the scripts generated with increasing complexity of the task. This reflect the fact that more ways exist to set up a correct simulation but also that GPT-4 is less certain about the answer. This result suggests that the consistency score could be used by researchers as a surrogate for the accuracy of the script generated. We include pair-wise similarity comparisons as Figure S
5
, and an average excluding self-similarity is added in Table

. Regarding their usefulness, it is clear that only a minor number of adjustments are needed to make these systems run.

Common problems.
Inaccuracies in the input files for Prompts 1 and 2 are primarily due to a redundant
replicate
command, which results in system sizes significantly larger than requested, see Figure
1
. As observed in Figure
1
, superfluous keywords were also often included in the command to initialize velocities,
velocity create
. The
mom/rot
keywords are used to zero out the linear and angular momentum of the newly created velocities. A uniform distribution was chosen to generate atomistic velocities in one of the files. While this would have a negligible effect on the results, a Maxwell-Boltzmann distribution is preferred.
Prompt 3 introduces significant complexity. Although no input file generated by GPT-4 could be executed fully without adjustments, an input file matching the prompt can be obtained with minor modifications, merging the best parts of several files. This task requires creating a complex system including a target and a projectile and performing two distinct processes, a thermalization step followed by an impact simulation. GPT-4 consistently switches from an isothermal simulation (NVT ensemble) for equilibration to an adiabatic one (NVE) for the spall portion. 9 out the 10 input files generated by GPT-4 create separate projectile and target systems but none of the them are separated by the requested 1.5 nm. Setting the dimensions of the simulation box and boundary conditions requires an understanding of the impact simulations. Following the initial compression, the system expands. For impact velocities above a threshold value spall failure occurs in tension. Thus, the system size along the impact direction should enable this process or a spacial-purpose, adjustable, boundary condition should be selected. This is not accomplished in any of the input files but is easily fixed.
An important step in the simulation workflow is the addition of a relative impact velocity of 2 km/s z-axis on top of thermal velocities of atoms in the projectile portion of the system. This requires thermalization of the system, which is generally achieved by these files (in 8 out of 10 cases), but only 2 out of the remaining 8 input files correctly add the desired impact velocity on top of the thermal ones (this requires the addition of
sum yes
in the
velocity
command). The remaining 8 input files replace the thermal velocities with the collective velocity.

In-line comments
. In addition to the generation of correct or nearly correct files, useful warnings, and in-line comments coupled with the model’s ability to follow up on additional questions to clarify or expand upon the generated code represent a powerful tool that can speed up the on-boarding of new users and accelerate the work of experts. Moreover, such explanations of the code’s logic can aid in enhancing the user’s comprehension of the LAMMPS input file and its implementation.

Task 2: Reproducibility of published results

Task 1 demonstrated the GPT-4 model’s ability to generate useful LAMMPS input files. In Task 2, we examine its potential to enhance the reproducibility of published computational studies. To this end we used GPT-4 to generate input files based on the simulation details provided in the Methods section, or similar, of publications and compare the GPT-4 files with those either originally shared with the publication (in the first example) or one created for this publication (second example).

Montes de Oca Zapiain et al (2022). npj Computational Materials, 8(1), 189.
[
20
]

In their study, Montes de Oca Zapiain and collaborators explored various methods for generating diverse training sets to improve the transferability of machine learning interatomic potentials. A key part of their analysis involves executing a LAMMPS simulation to assess energy conservation of an MD run. We took some of the details from this publication’s methods to evaluate the GPT-4’s (Version March 23, 2023) capabilities to reconstruct the simulation. We extracted the following excerpt from the Methods section of their publication, which outlines the parameters for the MD simulations:

Task 3: Human description for publications from LAMMPS input files

Tasks 1 and 2 focused on GPT-4’s ability to generate useful LAMMPS input files. Now, we aim to assess its ability generate a human-interpretable description of an MD simulation from a LAMMPS input file. The goal is to evaluate its potential to improve the quality and accuracy of research reports and publications via complete and accurate descriptions. The prompt used in our first attempt, see Figure
3

[
20

and used in Task 2. As shown in Figure

, GPT-4 provides a detailed description of the task including implementation details such as variable names. The description goes significantly deeper that the comments in the file and indicates that GPT-4 understands the sequence of steps used in setting up an MD simulations. Note that it even described the calculation of the deviation of total energy. We believe that such a complete and detailed explanation would benefit a researcher unfamiliar with LAMMPS in understanding the simulation. Such a description is overly detailed to be included in the methods section of an academic publication.

In a second test, we adjusted the query statement to include: 1) a target text length; 2) context pertaining to the expectations of such descriptors in academic journals; and 3) a directive to refrain from referencing LAMMPS commands directly. We used GPT-4 version May 3, 2023 for the detailed reconstruction, and version May 12, 2023 for the short reconstruction. As shown in Figure
4

The main shortcoming is the mislabeling of the potential used for the MD simulation. MLIAP is described as “smooth atomic neighbor environment representation” instead of the correct spectral neighbor analysis potential (SNAP). In regards to conventions and clarity, the description lacks a simulation time, it instead lists the timestep and number of steps. Additionally, it is vague in phrases such as “[properties]… were computed and recorded at regular intervals” and “results averaged over specificed time invervals”. Overall in this attempt, GPT-4 is unable to fully filter out redundant information (i.e. explanations of the ensemble), it brings us much closer to a fully automated description with only the LAMMPS input file as an input. Providing the model with the entire manuscript might potentially result in a richer description. It’s important to note that GPT-4 still lacks a full understanding of machine-learned potentials and descriptors, as it mistakenly classified them as Smooth Overlap of Atomic Positions (SOAP) descriptors rather than the correct spectral neighbor analysis potential (SNAP) descriptors. This inaccuracy is present in both descriptors and is consistent with the mistakes seen on Task 2.

1) Write a detailed methods section for an academic publication in computational materials science based on the following LAMMPS script: Script

GPT-4

In this study, a molecular dynamics simulation was performed using the Large-scale Atomic/Molecular Massively Parallel Simulator (LAMMPS) to investigate the mechanical properties of a computational material. The following methodology was applied:

1. Simulation parameters: The timestep (variable dt) was set to 0.5e-3/1 (1 being the dtfac index), and the total number of timesteps (variable nsteps) was set to 15,000. The temperature (variable t) was maintained at 300 K throughout the simulation. The thermodynamic data was output every 15,000 timesteps (variable nthermo). The simulation box was subjected to periodic boundary conditions in all three dimensions (x, y, and z).

2. Sampling parameters: The simulation was repeated 250 times (variable nrepeat), with the average thermodynamic properties calculated every 60 timesteps (variable nfreq, derived from nthermo/nrepeat). The system size was set by replicating the unit cell twice in each dimension (variable nrep), creating a total of eight unit cells.

3. Lattice structure and box creation: A body-centered cubic (bcc) lattice with a lattice constant of 3.16 Å (variable a) was used. The simulation box (region box) was created based on the dimensions of the replicated unit cells (nx, ny, and nz), which were derived from the nrep variable. A single atom type was assigned to the simulation box with a mass of 183.84 atomic mass units.

4. Atom velocities: The initial velocities of all atoms were generated using a Gaussian distribution corresponding to the specified temperature (300 K) and a random seed number (4928459).

5. Interatomic potential: The Machine Learning-Interatomic Potential (MLIAP) was employed in the study using a model (model name) and a descriptor based on the Smooth Overlap of Atomic Positions (SOAP) representation. The pair_style and pair_coeff commands were used to define the interatomic potential and coefficients, respectively.

6. Energy deviation calculation: Before running the simulation, the initial total energy of the system (etot0) was calculated. During the simulation, the mean energy deviation (etotdelta) was computed by taking the absolute difference between the current total energy and the initial total energy, and dividing it by the number of atoms.

7. Thermodynamic output: The simulation output included the step number, temperature, potential energy (epair), kinetic energy (ke), total energy (etotal), pressure, mean energy deviation (etotdelta), and average energy deviation (f_avede) over the specified nfreq.

8. Integration: The simulation was integrated using the NVE (microcanonical) ensemble, in which the number of particles (N), volume (V), and total energy (E) are conserved. The simulation was run for the specified number of timesteps (nsteps) after setting up all the parameters.

In this computational materials science study, molecular dynamics simulations were performed to investigate the properties of a tungsten system. Conclusions

This paper studied GPT-4’s ability to create LAMMPS input files from technical descriptions of computational tasks and the inverse problem of explaining, in technical English, computational tasks from LAMMPS input files. While human intervention is required except for the simplest tasks, we find GPT-4 to be a powerful tool to train beginners in MD simulations with LAMMPS, accelerating the development of LAMMPS input files. GPT-4’s ability to act as interpreter between technical writing and code or files can accelerate progress in computational materials science and reduce the time required to reproduce results or create new tasks. We believe the our results indicate the need to reconsider education and training of researchers increasing the focus on the why and what of computational tasks and reducing the focus on how. While our results focused on MD simulations and LAMMPS, we believe our results can be extrapolated to other fields and codes with communities that actively share scripts and files online.
