PRewrite: Prompt Rewriting with Reinforcement Learning
Weize Kong Spurthi Amba Hombaiah Mingyang Zhang, Qiaozhu Mei Michael Bendersky

Abstract
Prompt engineering is critical for the development of LLM-based applications. However, it is usually done manually in a “trial and error” fashion. This manual procedure can be time consuming, ineffective, and the generated prompts are, in a lot of cases, sub-optimal. Even for the prompts which seemingly work well, there is always a lingering question: can the prompts be made better with further modifications? To address these questions, in this paper, we investigate prompt engineering automation. We consider a specific use case scenario in which developers/users have drafted initial prompts, but lack the time/expertise to optimize them. We propose PRewrite , an automated tool to rewrite these drafts and to generate highly effective new prompts. PRewrite is based on the Reinforcement Learning (RL) framework which allows for end-to-end optimization and our design allows the RL search to happen in a large action space. The automated tool leverages manually crafted prompts as starting points which makes the rewriting procedure more guided and efficient. The generated prompts are human readable, and self-explanatory, unlike some of those in previous works. We conducted extensive experiments on diverse datasets and found that the prompts generated with this new method not only outperform professionally crafted prompts, but also prompts generated with other previously proposed methods.

Introduction

With the wide-scale proliferation of LLMs, prompting LLMs has become critical to achieving desired results on various downstream tasks. With the right prompts, LLMs can show impressive performance on various downstream tasks in zero-shot or few-shot settings.

Currently, most prompt engineering is done on an ad-hoc basis and there are no clear universal guidelines on writing good prompts for various downstream tasks. This approach is prone to various problems. Writing good prompts is
time-consuming
and requires some amount of prior experience of working with LLMs to understand their performance and reasoning capabilities. It can also be
ineffective
as end-users who call the LLMs through APIs and even engineers might face difficulties in getting the LLMs to behave as intended through their hand-crafted prompts. Moreover, they might be
sub-optimal
as the manual prompts might not be optimized for the task at hand.

To address the limitations above, we propose to automate the process of prompt engineering. This can be helpful for both end-users as well as engineers who work with LLMs to build applications. The prompt rewriting/reformulation can be implicit or explicit as prompt suggestions to the user.

Automated prompt engineering is important due to various reasons (a) the wide and fast adoption of LLM applications, and (b) LLMs themselves are evolving, and as a result, we’ll need effective methods to update prompts to adapt to new models. Instruction tuned models are better at understanding prompts and the prompts do not require a lot of tweaking to get the desired behavior from the models. However, non-instruction tuned models are not always good at following instructions and their corresponding prompts need to be formulated with greater care.

Related Work

A number of methods have been proposed to automate prompt engineering. They can be further categorized into discrete prompts, where the prompt is an actual piece of text, and continuous prompts (or soft prompts), where embeddings are directly used as prompts.

Continuous prompts
(
Lester et al. 2021
;
Li and Liang 2021
)
are more straightforward to optimize using gradient-based methods. However, computing gradients requires access to the task LLM’s internal parameters, which is not feasible for blackbox LLMs (i.e., access to the LLMs via their APIs). Continuous prompts are also harder to interpret and usually incompatible with LLMs that they haven’t been trained for. Continuous prompts are not the focus of this work.

Discrete prompts do not suffer from these issues. However, their discrete nature renders prompt optimization very difficult, which is the major challenge for automated discrete prompt engineering. We describe some existing works on discrete prompts below.

Jiang et al. 2020
propose
Prompt Mining
to automatically find prompt templates using the middle words or dependency paths between the inputs and outputs, given some training data. In
Prompt Paraphrasing
, a hand-crafted/mined seed prompt is paraphrased to a set of other candidate prompts, and then selecting the one with the best performance on the target task.
Jiang et al. 2020
propose round-trip translation from source to target language and then back whereas
Yuan et al. 2021
propose replacement of phrases from a thesaurus for prompt paraphrasing.
Haviv et al. 2021
uses a neural prompt rewriter to improve the accuracy of models using the paraphrased prompt.

Wallace et al. 2021
used a
Gradient-Based Search
approach over prompt tokens to find short sequences to generate the desired target prediction using the underlying LLM. Built on the method of searching over prompt tokens,
Shin et al. 2020
proposed AutoPrompt which automatically searches for template tokens using the task training examples.

There are some works which use generation models for the
Prompt Generation
task.
Gao et al. 2021
used the seq2seq pre-trained LM T5 for template search and generated template tokens by specifying the insert position and providing training samples to decode the tokens. In another line of work,
Guo et al. 2022
used reinforcement learning to generate prompts to control the text generation process whereas
Ben-David et al. 2022
proposed to train T5 to generate unique domain relevant features for each input which can be concatenated with the input to form a prompt template.

Most of the prior work essentially uses search algorithms to find the optimal discrete prompt from the proposed candidates. Differently, RLPrompt
Deng et al. 2022
directly optimized discrete prompts using reinforcement learning and showed promising results for both classification tasks as well as a text generation task (style transfer).
Zhang et al. 2022
have proposed TEMPERA to perform prompt editing at test-time using reinforcement learning, considering the initial prompt, query and a pool of examples. We identify a few limitations of RLPrompt and TEMPERA and try to address them in this work, specifically these works were developed using relatively small LLMs (e.g., RoBERTa-large) whereas we use larger and more powerful models from the PaLM 2 family. Moreover, RLPrompt is likely to produce ungrammatical gibberish text unlike our proposed model.

More recently,
Zhou et al. 2023
propose an
Automatic Prompt Engineer
framework to improve the initial instruction candidates generated via output demonstrations, and using Monte Carlo search to improve them further.
Fernando et al. 2023
propose
Promptbreeder
, a self-improvement and self-referential framework based on evolutionary algorithms to evolve best prompts for a given task. In
Optimization by PROmpting (OPRO)
,
Yang et al. 2023
propose using LLMs as optimizers with a meta-prompt consisting of previous solution-score pairs and a task description for generating solutions at the current step and thereby, improve the performance of the generated prompts through iterative optimization until convergence. These works are mostly based on search actions and use a frozen LLM-based prompt rewriter. However, in PRewrite, we fine-tune our prompt rewriter LLM using reinforcement learning.

3.1
Problem Formulation

We formulate our prompt rewriting problem more formally in this section.
In our work, a task can be any text generation problem, e.g., question answering. We denote the task input and output by
x
and
y
respectively. To solve the generation problem, one can use a LLM for prediction,
y = LLM(p)
, where p is the text input to the LLM, aka prompt.

Prompts can often be constructed using a prompt template,
p = construct(t, x)
, where
t
denotes the template. While a prompt is constructed by filling in
x
into the prompt template
t
, the prompt template itself is agnostic to the input (i.e., the template does not change for different values of
x
). A prompt template usually consists of an instruction, and sometimes in-context examples. The task input
x
can be “expanded” with supplementary input,
\delta
(x)
. For example, for the question answering task, one can retrieve some related passages as supplementary input,
\delta
(x)
.

Prompt rewriting aims to rewrite an initial prompt to another prompt,
p
†
= rewrite(p)
in order to optimize the task output. The rewriting process can be input-dependent or independent.

We focus on input-independent prompt rewriting. We specifically rewrite only the initial prompt template and construct a new prompt based on the rewritten template
p
†
= construct(rewrite(t), x)
. In this case, “rewrite” operation can be performed offline and “construct” operation can be cheaply executed online. We do not use input expansion (i.e., supplementary input),
\delta
(x)
for any of the tasks in this work.
p
†
is used to generate the output,
y
.

Since our focus is on input-independent rewriting, i.e., prompts do not have input,
x
augmented to them, we will refer to the initial prompt template and rewritten prompt template as the initial prompt and rewritten prompt respectively, going forward, for ease of understanding.

3.2
Method Overview

3.2.1
Prompts

Below, we describe the different prompts used in our rewriting framework.

Meta Prompt / Rewriting Instruction.

A meta prompt is a rewriting instruction used to instruct the LLM to rewrite the initial prompt. The meta-prompt does not change during training. However, we experimented with different meta-prompts when training PRewrite.

Initial Prompt.

This is the original hand-crafted prompt which is rewritten using the rewriter model. The initial prompt that is chosen changes with the task under consideration.

Rewritten Prompt.

This is the final rewritten prompt generated from the initial prompt by our rewriter model.

3.2.2
Reinforcement Learning

We formulate our task as a RL problem and describe some important components of the RL setup.

Policy Function.

A policy function is a probability distribution over the actions, given the states. Here, the action space can be considered as the set of all tokens in the prompt rewriter model’s vocabulary which can be used to edit/rewrite the prompts via additions/deletions/modifications.

Rewards.

Rewards are used to inform about the effectiveness of the rewritten prompt on the task at hand where we compare the generated output against the ground-truth output. We explore several reward functions for different tasks including

•

EM

•

F1: Token F1 score between the actual and predicted outputs

•

Perplexity

•

Perplexity + F1: A linear combination of perplexity and F1 score

•

Length difference: Difference in the lengths of ground-truth and generated outputs after tokenizing

3.3
Architecture

We start with an initial prompt,
p_{0}
. A meta-prompt is used to prompt the “Prompt Rewriter Model” to rewrite
p_{0}
to get a set of prompt variants {
p^{v}_{i}
}. Each input,
x
is plugged into
p^{v}_{i}
to get an input-augmented prompt,
p^{v}_{{i},x}
which is fed to a frozen task LLM to generate a task output. We continue training the prompt rewriter model using reinforcement learning using a reward like “EM” computed by comparing the generated output against the ground-truth output. The rewriter model is updated to maximize the reward.

4.2
Experimental Setup

We use a PaLM 2-S as our prompt rewriter model as well as the task LLM. However, only the prompt rewriter model is trained and the parameters of the task LLM are frozen. The prompt rewriter model is trained until its performance converges on the dev set.

We use the Proximal Policy Optimization (PPO)
Schulman et al. 2017
as the RL algorithm. To prevent the rewriter model from outputting gibberish, we add the KL divergence between the policy model and the initial state of the LLM as a regularization parameter while training.

Conclusion & Future Work

In this paper, we presented our preliminary work on PRewrite, an automated prompt rewriter to improve the initial hand-crafted prompts using reinforcement learning. Our proposed method addresses the drawbacks of previous methods including using larger and more powerful models for the rewriting task, training the prompt rewriter end-to-end and producing human-readable prompts showing impressive performance over some of the previous SoTA models.

As future work, we aim to test our approach on more diverse datasets and with larger models than the PaLM 2-S. We would also like to study the effectiveness of different meta-prompts and initial prompts on the task performance.
