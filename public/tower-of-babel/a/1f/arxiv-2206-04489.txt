Holistic Verification of Blockchain Consensus Conference: ; ;
Nathalie Bertrand, Vincent Gramoli, Igor Konnov, Marijana Lazić, Pierre Tholoniat, Josef Widder

Abstract
. Blockchain has recently attracted the attention of the industry due, in part, to its ability to automate asset transfers. It requires distributed participants to reach a consensus on a block despite the presence of malicious (a.k.a. Byzantine) participants. Malicious participants exploit regularly weaknesses of these blockchain consensus algorithms, with sometimes devastating consequences. In fact, these weaknesses are quite common and are well illustrated by the flaws in the hand-written proofs of existing blockchain consensus protocols ( Tholoniat and Gramoli 2022 ) . Paradoxically, until now, no blockchain consensus has been holistically verified using model checking. In this paper, we remedy this paradox by model checking for the first time a blockchain consensus used in industry. We propose a holistic approach to verify the consensus algorithm of the Red Belly Blockchain ( Crain et al. 2021 ) , for any number n n of processes and any number f < n / 3 f<n/3 of Byzantine processes. We decompose directly the algorithm pseudocode in two parts—an inner broadcast algorithm and an outer decision algorithm—each modelled as a threshold automaton ( Konnov et al. 2017b ) , and we formalize their expected properties in linear-time temporal logic. We then automatically check the inner broadcasting algorithm, under a carefully identified fairness assumption. For the verification of the outer algorithm, we simplify the model of the inner algorithm by relying on its checked properties. Doing so, we formally verify not only the safety properties of the Red Belly Blockchain consensus but also its liveness in about 70 seconds.

Without a holistic approach, the verification of the components of a protocol does not

Contributions

In this paper, we verify holistically the safety and liveness properties
of a Byzantine consensus used in the Red Belly Blockchain system
(

et al. 2021

, a scalable blockchain used in production.
Our approach is holistic because it starts from the pseudocode of the distributed algorithm as typically

The advantage is that the formally verified algorithm matches the pseudocode and no user-defined invariants or proofs need to be checked, which drastically reduces the risks of human errors.

(1)

We formally verify a Byzantine consensus

(

et al. 2018

Preliminaries

The consensus algorithm runs over
n
asynchronous sequential
processes from the set
\Pi=\{p_{1},\ldots,p_{n}\}
.
The processes communicate by exchanging messages through

Failure model.

Up to

Algorithm semantics.
The asynchronous semantics of a

receives a message by
executing the primitive “
\mathord{\sf receive}()
”. The shorthand

\mathord{\sf broadcast}
(

And the right arrow in

The verification method considered in this paper exploits

The consensus problem.
Assuming that each correct process
proposes a binary value, the binary Byzantine consensus problem is for
each of them to decide on a binary value in such a way that the
following properties are satisfied:

(1)

Termination. Every correct process eventually decides on a value.

(2)

Agreement. No two correct processes decide on different values.

(3)

Validity. If all correct processes propose the same value, no
other value can be decided.

3.2.
Properties of the binary value broadcast

As was previously proved by hand
(
Mostéfaoui
et al. 2014
;
Mostéfaoui et al. 2015
)
, the
\scriptsize\mathord{\sf bv-broadcast}
primitive satisfies four properties: BV-Justification, BV-Obligation,
BV-Uniformity and BV-Termination. Here, we formalize these properties
in linear temporal logic (
LTL
) to formally and automatically prove
they hold. As we will discuss in Section
6
, we verify them
for any parameters
n
and
t<n/3
in less then 10
seconds.

The BV-Justification property states:
“If
p_{i}
is correct and
v\in\mathord{\it contestants}_{i}
, then
v
has been
bv-broadcast by some correct process” where
v\in\{0,1\}
. Alternatively, “if
v
is not
bv-broadcast by some correct process and
p_{i}
is correct, then

v\notin\mathord{\it contestants}_{i}
”. In the TA from
Fig.
2
,
v\in\mathord{\it contestants}_{i}
corresponds to
process
i
being in one of the locations
C_{v}
,
CB_{v}
or
C_{01}
.
Thus, justification can be expressed in
LTL
as the conjunction

\mathord{\it BV-Just_{0}}\land\mathord{\it BV-Just_{1}}
where,

\mathord{\it BV-Just_{v}}
is the following formula:

(
\mathord{\it BV-Just_{v}}
)

\kappa[V_{v}]=0\;\Rightarrow\;\square\,\bigl(\kappa[C_{v}]=0\wedge\kappa[CB_{v}]=0\wedge\kappa[C_{01}]=0\bigr)\kern 5.0pt.

BV-Obligation requires that if at least
(t{+}1)
correct processes bv-broadcast the same value
v
,
then
v
is eventually added to the set
\mathord{\it contestants}_{i}
of each correct process
p_{i}
.
This can again be formalized as
\mathord{\it BV-Obl_{0}}\land\mathord{\it BV-Obl_{1}}

where
\mathord{\it BV-Obl_{v}}
is the following formula:

(
\mathord{\it BV-Obl_{v}}
)

\square\,\Bigl(b_{v}\geq t{+}1\;\Rightarrow\;\lozenge\,\bigl(\bigwedge_{L\in\text{Locs}_{v}}\kappa[L]=0\bigr)\Bigr)\kern 5.0pt,

where
\text{Locs}_{v}=\{V_{0},V_{1},B_{0},B_{1},B_{01},C_{1-v},CB_{1-v}\}
are all the possible locations of
a process
i
if
v\not\in\mathord{\it contestants}_{i}
.

BV-Uniformity requires that if a value
v
is added to the set
\mathord{\it contestants}_{i}
of a correct process
p_{i}
,
then eventually
v\in\mathord{\it contestants}_{j}
at every correct process
p_{j}
.
We formalize this as
\mathord{\it BV-Unif_{0}}\land\mathord{\it BV-Unif_{1}}

where
\mathord{\it BV-Unif_{v}}
is the following:

(
\mathord{\it BV-Unif_{v}}
)

\lozenge\,(\kappa[C_{v}]{\neq}0~\vee~\kappa[CB_{v}]{\neq}0~\vee~\kappa[C_{01}]{\neq}0)\;\Rightarrow\;\lozenge\,\bigwedge_{L\in\text{Locs}_{v}}\kappa[L]{=}0\kern 5.0pt,

where
\text{Locs}_{v}
is defined as in
\mathord{\it\eqref{eq:bvobl}}
.

Finally, the BV-Termination property claims that eventually the set
\mathord{\it contestants}_{i}
of
each correct process
p_{i}
is non empty. This can be phrased as the following
LTL
formula
\mathord{\it BV-Term}
:

(
\mathord{\it BV-Term}
)

\lozenge\,\bigl(\kappa[V_{0}]{=}0~\wedge~\kappa[V_{1}]{=}0~\wedge~\kappa[B_{0}]{=}0~\wedge~\kappa[B_{1}]{=}0~\wedge~\kappa[B_{01}]{=}0\bigr)\kern 5.0pt,

forcing each correct process to be in one of the “final” locations
C_{0},C_{1},C_{01},CB_{0},CB_{1}
.

3.3.
A fairness assumption to solve consensus

The traditional approach to establishing guarantee properties in verification
is to require that all fair computations, instead of all computations, satisfy the property
(
Alur and
Henzinger 1994
)
.
We thus introduce the fairness assumption
that will be crucial in the rest of this paper.
In order to define it, we first define a
good execution
of the

\scriptsize\mathord{\sf bv-broadcast}
with respect to binary value
v
as an execution:

Definition 3.1 (
v
-good
\scriptsize\mathord{\sf bv-broadcast}
).

A
\scriptsize\mathord{\sf bv-broadcast}
execution is
v
-
good
if all its correct processes bv-deliver
v
first.

We express this property in
LTL
.
A
\scriptsize\mathord{\sf bv-broadcast}
execution is
v
-
good
if no process ever visits locations
C_{1-v}
and
CB_{1-v}
:

\square\,\;\Big(\kappa[C_{1-v}]=0~\land~\kappa[CB_{1-v}]=0\Big)\kern 5.0pt.

Second, we consider an infinite sequence of
\scriptsize\mathord{\sf bv-broadcast}
executions,
tagged with
r\in\mathbb{N}
.
It is important to stress that the setting is asynchronous, that is,
processes invoke
\scriptsize\mathord{\sf bv-broadcast}
infinitely many times, but at their own relative speed.
Thus, they do not all invoke the
\scriptsize\mathord{\sf bv-broadcast}
tagged with the same number
r
at the same time.
Nonetheless, every process invokes
\scriptsize\mathord{\sf bv-broadcast}
infinitely many times and
in the
r^{\mathord{\it th}}
invocation its behavior depends
on the messages sent in the
r^{\mathord{\it th}}
invocation of other processes.
Therefore, we refer to the
r^{\mathord{\it th}}
execution of
\scriptsize\mathord{\sf bv-broadcast}
even though the
processes invoke it at different times.

Definition 3.2 (fairness).

An infinite sequence of
\scriptsize\mathord{\sf bv-broadcast}
executions is
fair
if
there exists an
r
such that the
r^{\mathord{\it th}}
execution is

(r{\sf~mod~}2)
-good.

For simplicity, we use the terminology
fair
\scriptsize\mathord{\sf bv-broadcast}
when the
infinite sequence of
\scriptsize\mathord{\sf bv-broadcast}
executions is fair.
We illustrate in Appendix
B
a possible
execution of
\scriptsize\mathord{\sf bv-broadcast}
whose existence implies fairness.

developed for crash fault tolerant randomized

5.1.
Safety

Under no fairness assumption, one can prove the safety properties—agreement and validity—of the Byzantine consensus based
on
\scriptsize\mathord{\sf bv-broadcast}
.
Precisely, we formulate these properties in
LTL
and want to establish that they hold
on the threshold automaton of Fig.
4
.

Agreement requires that no two correct processes disagree, that is, if one process decides
v
then no process should decide
1{-}v
for all binary values
v\in\{0,1\}
.
Thus, we want to prove that the following formula holds for both values of
v
:

(
\mathord{\it Agree}_{v}
)

\forall R\in\mathbb{N},\forall R^{\prime}\in\mathbb{N}\;\Bigl(\lozenge\,\kappa[D_{v},R]\neq 0\;\Rightarrow\;\square\,\kappa[D_{1-v},R^{\prime}]=0\Bigr)\kern 5.0pt,

stating that for any two superrounds
R
and
R^{\prime}
, if eventually a process decides
v
, then globally (in any superround) no process will decide
1-v
. In terms of the TA from Fig.
4
, if a process enters location
D_{v}
no process should enter location
D_{1-v}
(not only in that superround, but in any other).

Validity requires that if no process proposes a value
v\in\{0,1\}
, no process should ever decide that value.
Hence, we want to prove the following formula for both values of
v
:

(
\mathord{\it Valid}_{v}
)

\forall R\in\mathbb{N}\;\Bigl(\kappa[V_{v},1]=0\;\Rightarrow\;\square\,\kappa[D_{v},R]=0\Bigr)\kern 5.0pt,

stating that if initially no process has value
v
, then globally (in any superround) no process decides
v
.
In terms of the TA, if location
V_{v}
is initially empty (in superround 1), then no process should enter location
D_{v}
in any superround.

ByMC can only check formulas of the form

\forall R\in\mathbb{N}\;\varphi[R]
(see
Appendix
A
). Thus, automatically checking
(

Agree
v

) and (

Valid
v

) is non-trivial, as
they both involve two superround numbers:
R
and
R^{\prime}
in
(

Agree
v

), and 1 and
R
in
(

Valid
v

).
We instead check
well-chosen one-superround
invariants (

Inv1
v

) and (

Inv2
v

):

(
\mathord{\it Inv1}_{v}
)

\forall R\in\mathbb{N}\;\Bigl(\lozenge\,\kappa[D_{v},R]\neq 0\;\Rightarrow\;\square\,\bigl(\kappa[D_{1-v},R]=0\wedge\kappa[E^{\prime}_{1-v},R]=0\bigr)\Bigr)\kern 5.0pt,

(
\mathord{\it Inv2}_{v}
)

\forall R\in\mathbb{N}\;\Bigl(\square\,\kappa[V_{v},R]=0\;\Rightarrow\;\square\,\bigl(\kappa[D_{v},R]=0\wedge\kappa[E^{\prime}_{v},R]=0\bigr)\Bigr)\kern 5.0pt.

The choice of these invariants follows a previous approach used for
the crash fault tolerant
consensus where it is shown
that these invariants imply (

Agree
v

) and
(

Valid
v

)
(
Bertrand
et al. 2019
, Proposition 2)
. Intuitively,
this follows from the fact that (i) emptiness of
D_{0}
and
E_{0}^{\prime}
in
one superround leads to the emptiness of
V_{0}
in the next superround,
and (ii) emptiness of
E_{1}^{\prime}
(and
D_{1}
) in one superround leads to
the emptiness of
V_{1}
in the next superround. Therefore, in order to
prove agreement and validity, we only need to prove (

Inv1
v

)
and (

Inv2
v

) for both values
v\in\{0,1\}
. We successfully
do this automatically with ByMC (see Section
6
).

5.2.
Liveness

We now aim at proving termination of Algorithm
1
.
First, we need to prove that every superround eventually terminates,
in the sense that for every round eventually there are no processes in
any location of that round to the exception of the final ones (
D_{0}
,

E_{0}^{\prime}
and
E_{1}^{\prime}
). Formally, using ByMC we prove the following:

(
\mathord{\it SRoundTerm}
)

\forall R\in\mathbb{N}\;\lozenge\,\Bigl(\bigwedge_{L\in\mathcal{L}\setminus\{D_{0},E_{0}^{\prime},E_{1}^{\prime}\}}\kappa[L,R]=0\Bigr)\kern 5.0pt.

From this property and the shape of the TA from Fig.
4
,
it easily follows that if no process ever enters
E_{0}^{\prime}
and
E_{1}^{\prime}
of some superround, then
all processes visit
D_{0}
in that superround.
Similarly, if no process ever enters
E_{0}
and
E_{1}
of some superround, then
all processes visit
D_{1}
in that superround.
This allows us to express termination as the following
LTL
property on the threshold
automaton of Fig.
4
:

(
\mathord{\it Term}
)

\exists R\in\mathbb{N}\;\Bigl(\square\,\bigl(\kappa[E_{0},R]=0\wedge\kappa[E_{1},R]=0\bigr)\;\vee\;\square\,\bigl(\kappa[E^{\prime}_{0},R]=0\wedge\kappa[E^{\prime}_{1},R]=0\bigr)\Bigr)\kern 5.0pt.

In words, there is a superround
R
in which either (i) all processes visit
D_{1}
,
or (ii) all processes visit
D_{0}
.
Here again formula (

Term

) is non-trivial to check since it
contains an existential quantifier over superrounds, that cannot be
handled by the model checker ByMC. Adapting the technique
from
(
Bertrand
et al. 2019
, Section 7)
to a non-randomized context, it
is sufficient to prove a couple of properties on the threshold
automaton of Fig.
4
, that we detail below. The
first property expresses that if no process starts a superround
R

with value
v
, then all processes decide
1{-}v
in superround
R
:

(
\mathord{\it Dec}
)

\begin{split}\forall R\in\mathbb{N}\;&\Bigl(\square\,\bigl(\kappa[V_{0},R]=0\bigr)\Rightarrow\square\,\bigl(\kappa[E_{0},R]=0\wedge\kappa[E_{1},R]=0\bigr)\Bigr)\\
\wedge\;\;&\Bigl(\square\,\bigl(\kappa[V_{1},R]=0\bigr)\Rightarrow\square\,\bigl(\kappa[E_{0}^{\prime},R]=0\wedge\kappa[E_{1}^{\prime},R]=0\bigr)\Bigr)\kern 5.0pt.\end{split}

The second property claims that (i) emptiness of
M_{0}
in superround
R
implies
(emptiness of
E_{0}
and therefore also) emptiness of
D_{0}
and
E_{0}^{\prime}
in

and
(ii) emptiness of
M_{1}^{\prime}
in superround

implies emptiness of
E_{1}^{\prime}
in
R
:

(1)

\forall R\in\mathbb{N}\;\Bigl(\bigl(\square\,\kappa[M_{0},R]=0)\;\Rightarrow\;\square\,(\kappa[D_{0},R]\wedge\kappa[E_{0}^{\prime},R]=0)\bigr)\\
\;\wedge\;\bigl(\square\,\kappa[M_{1}^{\prime},R]=0)\;\Rightarrow\;\square\,\kappa[E^{\prime}_{1},R]=0\bigr)\Bigr)\kern 5.0pt.

The main idea is to exploit the fairness of
\scriptsize\mathord{\sf bv-broadcast}
,
which ensures the existence of a round

which is
(r{\sf~mod~}2)
-good.
Intuitively, the next superround
R=\lceil r/2\rceil
is the desired witness
for (

Term

), namely the one in which all processes decide (not necessarily for the first time).
We formalize this in our main result:

Theorem 5.1.

Assuming fairness of the
\scriptsize\mathord{\sf bv-broadcast}

Proof.

First we prove formulas (

(

Formula (

(

Indeed, since we assume fairness of the

4.2

•

\square\,\kappa[M_{1}^{\prime},R]=0

Note that the form of the (dotted) round-switch rules yield

Related Work

Interactive theorem provers
(
Sergey
et al. 2018
;
Rahli et al. 2015
;
von Gleissenthall et al. 2019
)
already checked proofs of consensus algorithms used in the blockchain industry.
In particular, Coq helped prove the Raft consensus algorithm
(
Wilcox et al. 2015
)
, which is not Byzantine fault tolerant but part of crash fault tolerant distributed ledgers
(
Brown
et al. 2016
;
Androulaki et al. 2018
)
, and the Byzantine consensus algorithm of the Algorand blockchain
(
Alturki et al. 2019
)
.
In addition, Dafny
(
Hawblitzel et al. 2015
)
proved MultiPaxos, a consensus algorithm that tolerates crash failures.
Isabelle/HOL
(
Nipkow
et al. 2002
)
was used to prove Byzantine fault tolerant algorithms
(
Charron-Bost et al. 2011
)
and was combined with Ivy to try to prove the Byzantine consensus protocol of the Stellar blockchain
(
Losa and Dodds 2020
)
as discussed in the introduction.
Theorem provers check proofs, not the algorithms.
Hence, one has to invest efforts into writing detailed mechanical proofs.

Specialized decision procedures are a way of proving consensus algorithms.
They were used to prove Paxos
(
Kragl et al. 2020
)
, which could itself be used in the aforementioned crash fault tolerant distributed ledgers.
Crash fault tolerant consensus algorithms were manually encoded with their invariants and properties
to prove formulae using the Z3 SMT solver
(
Dragoi et al. 2014
)
.
Decision procedures also proved the safety of Byzantine fault tolerant consensus algorithms when
f=t

(
Berkovits et al. 2019
)

but not their termination.
Similarly, a proof by refinement of the safety of a Byzantine variant of Paxos was proposed
(
Lamport 2011
)
but its liveness is not proven.
These decision procedures require the
user to fit the specification into a suitable logical fragment.

Explicit-state model checking fully automates verification of distributed algorithms
(
Holzmann 2003
;
Yu
et al. 1999
)
.
It allows to check the reliable broadcast algorithm
(
John
et al. 2013
)
, a common component of various blockchain consensus algorithms
(
Miller
et al. 2016
;
Crain
et al. 2018
;
Civit
et al. 2021
)
.
TLC
(
Yu
et al. 1999
)
checked a reduction of fault tolerant distributed algorithms in the Heard-Of model
that exploits their communication-closed property
(
Chaouch-Saad et al. 2009
)
.
And the agreement of consensus algorithms was proved in the asynchronous setting
(
Noguchi
et al. 2012
)
.
These explicit-state tools enumerate all reachable states and thus suffer from state explosion.

Symbolic model checkers
(
Burch et al. 1990
)
cope with this explosion by
representing state transitions efficiently.
NuSMV and SAT helped check consensus algorithms for up
to 10 processes
(
Tsuchiya and
Schiper 2008
;
Tsuchiya and
Schiper 2011
)
.
Apalache
(
Konnov
et al. 2019
)
uses satisfiability modulo theories (SMT) to check inductive
invariants and verify symbolic executions of
TLA
+

specifications of the reliable broadcast and crash fault tolerant consensus algorithms but requires
parameters to be fixed.
These tools cannot be used to prove (or disprove) correctness for an arbitrary number of
processes.

Parameterized model checking
(
Downey and
Fellows 1999
)
works for an
arbitrary number
n
of processes
(
Bloem et al. 2015
)
.
Although the problem is undecidable
(
Apt and Kozen 1986
)
in general, one
can verify specific classes of algorithms
(
Emerson and
Kahlon 2000
)
.
Indeed, distributed algorithms with a ring-based topology were checked with automata-theoretic method
(
Aiswarya
et al. 2018
)
and with Presburger arithmetics formulae verified by an SMT solver
(
Sangnier et al. 2020
)
.
Bosco
(
Song and van
Renesse 2008
)
has been the focus of various parameterized verification techniques
(
Lazic
et al. 2017
;
Balasubramanian et al. 2020
)
, however,
it acts as a fast path wrapper around
a separate correct consensus algorithm that remains itself to be proven.
The condition-based consensus algorithm
(
Mostéfaoui
et al. 2003
;
Mostéfaoui et al. 2003
)
was verified
(
Balasubramanian et al. 2020
)
with the Byzantine model checker ByMC
(
Konnov
et al. 2017b
;
Konnov and Widder 2018
;
Konnov
et al. 2020
)
, only under the condition that the difference between the numbers of processes initialized with 0 and 1 differ by at least
t
.
Recently, the crash fault tolerant Ben-Or consensus algorithm was proved correct with a probabilistic reasoning extension of ByMC
(
Bertrand
et al. 2019
)
.
In this paper, we also exploit ByMC but prove the Byzantine consensus algorithm
(
Crain
et al. 2018
)
of an existing blockchain
(
Crain
et al. 2021
)
.

8.
Conclusion

We presented the first formal verification of a blockchain consensus
algorithm thanks to a new holistic approach.
Previous attempts to formally verify the liveness of blockchain consensus consisted of
verifying different parts of the consensus algorithm without verifying the sum of the parts.
By modeling directly the pseudocode into a disambiguated threshold automaton
we guarantee that the “actual” algorithm is verified.
By model checking the threshold automaton without the need for user-defined invariants
and proofs, we drastically reduce the risks of human errors.
We believe that this holistic verification technique will help verify or identify bugs
in other distributed algorithms based on various broadcast primitives.

Appendix A
Reducing multi-round
TA
to one-round
TA

Let us first formally define a (finite or infinite)
run
in a (one-round or multi-round) counter system
\mathord{\it Sys}(
TA
)
. It is an alternating sequence of configurations and transitions
\sigma_{0},t_{1},\sigma_{1},t_{2},\ldots
such that
\sigma_{0}\in I
is an initial configuration and for every
i\geq 1
we have that
t_{i}
is unlocked in
\sigma_{i-1}
, and executing it leads to
\sigma_{i}
, denoted
t_{i}(\sigma_{i-1})=\sigma_{i}
.

Here we briefly describe the reasoning behind the reduction of multi-round
TA
s to one-round TAs
(
Bertrand
et al. 2019
, Theorem 6)
.
Note that the behavior of a process in one round only depends on the variables (the number of messages) of that round.
Namely, we check if a transition is unlocked in a round by evaluating a guard and a location counter in that round.
This allows us to modify a run by swapping two transitions from different rounds, as they do not affect each other, and preserve
\mbox{{LTL}}_{\textsf{{-X}}}
properties, which are properties expressed in
LTL
without the next operator
X
.
The type of swapping we are interested in is the one where a transition of round
R
is followed by a transition of round
R^{\prime}<R
.
Starting from any (fully asynchronous) run, if we keep swapping all such pairs of transitions, we will obtain a run in which processes synchronize at the end of each round and which has the same
\mbox{{LTL}}_{\textsf{{-X}}}
properties as the initial one.
This, so-called
round-rigid
structure, allows us to isolate a single round and analyze it.
Still, different rounds might behave differently as they have different initial configurations.
If we have a formula
\forall R\in\mathbb{N}.\;\varphi[R]
, where
\varphi[R]
is in the above mentioned fragment of (multi-round)
LTL
, then Theorem 6 of
(
Bertrand
et al. 2019
)
shows exactly that it is equivalent to check that (i) this formula holds (or
\varphi[R]
holds on all rounds
R
) on a multi-round
TA
, and (ii) formula
\varphi[1]
(or just
\varphi
) holds on the one-round
TA
′
(naturally obtained from the
TA
by removing dotted round-switch rules) with respect to all possible initial configurations of all rounds.
Thus, we can verify properties of the form
\forall R\in\mathbb{N}.\;\varphi[R]
on multi-round threshold automata, by using ByMC to check
\varphi
on a one-round threshold automaton with an enlarged set of initial configurations.

Examples of fairness and of non-termination without fairness

First, we explain that the fairness is satisfied as soon as one execution of

Then, we explain that the Byzantine consensus algorithm cannot terminate without an additional assumption, like fairness.

Relevance of the fairness assumption

Appendix F
Specification of the termination property in the simplified
threshold automaton for consensus algorithm

The reliable communication assumption and the properties
guaranteed by the
\scriptsize\mathord{\sf bv-broadcast}
are expressed as preconditions for
\mathord{\it s\_round\_termination}
. The
progress conditions work exactly the same as in

(
Bertrand
et al. 2019
)
. However, since the shared counters representing the

\scriptsize\mathord{\sf bv-broadcast}
execution do not represent regular messages, we cannot
directly use the reliable communication assumption. Instead, we use the properties of the

\scriptsize\mathord{\sf bv-broadcast}
that we proved in a separate automaton.

In practice, instead of using progress preconditions on the
\scriptsize\mathord{\sf bv-broadcast}
counters in

\mathord{\it s\_round\_termination}
, such as:

(locM == 0 || bvb1 < 1) && (locM == 0 || bvb0 < 1) &&
(locM1 == 0 || bvb0 < 1) && (locM0 == 0 || bvb1 < 1)

/* BV-Termination */
(locM == 0) &&
/* BV-Obligation */
(locM1 == 0 || bvb0 < T + 1) && (locM0 == 0 || bvb1 < T + 1) &&
/* BV-Uniformity */
(locM1 == 0 || aux0 == 0) && (locM0 == 0 || aux1 == 0) &&

One can note that we do not use BV-Justification as a precondition in
this specification. Instead, the BV-Justification property is baked in
the structure of the simplified threshold automaton (in the guard of
the transition
M\rightarrow M0,M1
