Modifications to a classic BFGS library for use with SIMD-equipped hardware and an AAD library
Evgeny Goncharov, Alexandre Rodrigues

Abstract
We introduce certain modifications of the BFGS method for functions that are not parallelizable by nature (having consecutive operations only) taking advantage of SIMD. We also provide a modified LBFGS ++ library that takes advantage of these modifications, and the use of AAD, and give an interface for AAD users that takes advantage of the modified library automatically. We give two examples to illustrate the performance. The modified library is up to 3.8 times faster for European Swaption curve calibration in ORE [ 16 ] (not parallelizable) and 1.4 times faster for calibrating the LMM model by a set of European options.



1
Introduction

The classical Newton’s method
[
2
]
uses the Hessian matrix
H
(the matrix of second derivatives) to find an extremum of a function
f:\mathbb{R}^{n}\to\mathbb{R}
by an iterative algorithm starting at some initial point
x_{0}
. However, computing the Hessian can be too expensive, which gave rise to the development of the less costly
quasi-Newton
methods. The first one was proposed by William C. Davidon in
[
20
]
but it is rarely used now as more efficient methods have been developed. Popular methods today include the symmetric rank-one formula
[
7
]
and the BHHH method
[
9
]
. The BFGS method
[
18
,
14
,
1
,
6
]
and its low-memory extension LBFGS
[
13
]
are currently the most used. We give an overview of the algorithms in Section
2
. These methods require little memory, have low computational complexity since no matrix inversions are required, and can find the solution even when the initial point
x_{0}
is quite far from the extremum.

Parallelization is an important tool to improve computing efficiency. The two main approaches to parallelization are
multi-threading
and
Single Instruction Multiple Data (SIMD)
.
Multi-threading separates the calculation into parallel independent computations (threads) whereas SIMD allows taking multiple data points as input and processing them at the same time. It is straightforward to implement multi-threading into the BFGS method for a parallelizable function
f
. However, if
f
is not parallelizable (e.g. it is a sequence of consecutive operations), it is less clear how to use parallelization to enhance performance. We review the BFGS method and introduce our parallelization modifications utilizing SIMD in Section
3
. We use Advanced Vector Extensions (AVX)
[
4
]
in the process.

We implemented the modifications into the LBFGS
++
library, the modified library is available at
[
5
]
. The interface of the classical library assumes a functor (an AAD library) that calculates both the value (forward mode) and the gradient (reverse mode) of the target function
f
. However, straightforward use of an AAD library may lead to unnecessary computations. We modify the functions in the library to avoid them, see Section
3.3
.

The AAD library that we use is Matlogica’s AADC
[
11
]
. It is compatible with AVX and SIMD which makes it ideal for the project. We developed a C
++
class that allows AADC users to utilize the (modified version of) LBFGS
++
library automatically.

We discuss implementation in Section
4
and give two examples to illustrate performance. In the first example, we take the Open Source Risk Project (ORE)
[
16
]
code for the European Swaption curve calibration and pass it through the AADC library to get optimized and vectorized binary kernels for the forward (computing the function) and the reverse (computing the gradient) passes of
f
. We achieve an up to 3.8 times acceleration for the optimized code with the modified library. In the second example, we calibrate the Libor Market Model (LMM)
[
19
]
using the recipe of
[
17
]
and achieve a 1.4 times acceleration with the modified library. We note that in this case all the acceleration is achieved just by avoiding the unnecessary gradient computations mentioned above. Note also that the recent
[
3
]
gives alternative recipes for performing AAD in this setup. All the code is available at
[
5
]
.

Finally, we discuss other possible approaches to improving the performance of the LBFGS
++
library in Section
5
.

2
The BFGS method

The BFGS method
[
18
,
14
,
1
,
6
]
for computing a minimum of a function
f:\mathbb{R}^{n}\to\mathbb{R}
runs as follows.

Algorithm 1

(BFGS)
.

Start with an initial guess
x_{0}
and a Hessian matrix estimation
B_{0}
. Repeat the following steps for
k\geq 0
.

1.

Obtain the search direction:
p_{k}:=-B_{k}^{-1}\nabla f(x_{k})
.

2.

Perform a line search (one-dimensional optimization, see
[
12
]
for details) to find the acceptable step
\alpha_{k}
in the direction
p_{k}
. Line search is terminated when a chosen termination condition (Armijo, Wolfe, or Strong Wolfe) is reached.

Line search produces a sequence of steps
\alpha_{k}^{i}
for
i\geq 0
and
x_{k}^{i}:=x_{k}^{i-1}+\alpha_{k}^{i}p_{k}
for
k\geq 1
(here
x_{k}^{0}:=x_{k}
) until an acceptable step
\alpha_{k}
is found (the termination condition is reached).

3.

Use the displacement
s_{k}:=\alpha_{k}p_{k}
to update the variable
x_{k+1}:=x_{k}+s_{k}
.

4.

Set the change of gradient
y_{k}:=\nabla f(x_{k+1})-\nabla f(x_{k})
.

5.

Update the Hessian matrix estimation

B_{k+1}:=B_{k}+{\frac{{y}_{k}{y}_{k}^{\mathrm{T}}}{{y}_{k}^{\mathrm{T}}{s}_{k}}}-{\frac{B_{k}{s}_{k}{s}_{k}^{\mathrm{T}}B_{k}^{\mathrm{T}}}{{s}_{k}^{{T}}B_{k}{s}_{k}}}.

As
k\to\infty
, the
x_{k}
converge to a minimum of
f
.

The LBFGS algorithm is an enhancement of Algorithm
1
that has similar steps with certain modifications that allow to store less data in the memory (see
[
13
]
for details). LBFGS
++
is a classical library implementing the BFGS and LBFGS methods.
We make use of certain LBFGS
++
parameters given to the solver in one
LBFGSParam
object:

•

\varepsilon_{\rel}
: we change it to guarantee convergence in some applications;

•

max_iterations
: limited to 100 to reduce computational time in LMM (Section
4.3
);

•

linesearch
: we tested for various line search termination conditions.

3
Modifications to the BFGS method and the LBFGS
++
library

We shall now explain our modifications to the BFGS algorithm, and the LBFGS
++
library. All our modifications only concern line search, that is Step 2 of Algorithm
1
.

3.1
Parallelizing line search (LS)

Suppose that we are at the line search step of Algorithm
1
and we are about to compute
f(x_{k}^{i})=f(x_{k}^{i-1}+\alpha_{k}^{i}p_{k})
. A simple way to improve performance is to instead calculate the function value at several points at each call of the functor and choose the point with the smallest value of the function.

We use AVX as it allows us to use
4
points (AVX-2) or
8
points (AVX-512) and is well-integrated into AADC. For AVX-2 we use the
4
points:

x_{k}^{i-1}+\frac{1}{2}\alpha_{k}^{i}p_{k},\ x_{k}^{i-1}+\alpha_{k}^{i}p_{k},\ x_{k}^{i-1}+\frac{3}{2}\alpha_{k}^{i}p_{k},\ x_{k}^{i-1}+2\alpha_{k}^{i}p_{k}.

For AVX-512 we use the 8 points:

\begin{split}&x_{k}^{i-1}+\frac{1}{4}\alpha_{k}^{i}p_{k},\ x_{k}^{i-1}+\frac{1}{2}\alpha_{k}^{i}p_{k},\ x_{k}^{i-1}+\frac{3}{4}\alpha_{k}^{i}p_{k},\ x_{k}^{i-1}+\alpha_{k}^{i}p_{k},\\
&x_{k}^{i-1}+\frac{5}{4}\alpha_{k}^{i}p_{k},\ x_{k}+\frac{3}{2}\alpha_{k}^{i}p_{k},\ x_{k}^{i-1}+\frac{7}{4}\alpha_{k}^{i}p_{k},\ x_{k}^{i-1}+2\alpha_{k}^{i}p_{k}.\end{split}

We let
x_{k}^{i}
be the point for which the value of
f
is the smallest among the
4
or
8
points respectively, and proceed with line search (or do a Hessian update and proceed with the algorithm if the termination condition has been reached).
This modification alone results in acceleration of the European Swapton curve calibration by a factor of
2
as we see in Section
4.2
.

3.2
Polynomial regression (Polyfit)

We proceed with the same setup as above. However, instead of letting
x_{k}^{i}
be the point where
f
is the smallest, we use polynomial fitting as follows. We fit the function values at the
4
or
8
points using a polynomial of degree
3
or
7
respectively as a least-square polynomial fitting using the QR factorization from the Eigen library
[
8
]
. This gives a polynomial:

\displaystyle f(\alpha)

\displaystyle=p_{0}+p_{1}\alpha+p_{2}\alpha^{2}+p_{3}\alpha^{3}\text{ (if using AVX-2)}

\displaystyle f(\alpha)

\displaystyle=p_{0}+p_{1}\alpha+p_{2}\alpha^{2}+p_{3}\alpha^{3}+p_{4}\alpha^{4}+p_{5}\alpha^{5}+p_{6}\alpha^{6}+p_{7}\alpha^{7}\text{ (if using AVX-512)}

and we can find its roots.
Let the smallest root be
\alpha_{k}^{\min}
and set
x_{k}^{\min}:=x_{k}^{i-1}+\alpha_{\min}p_{k}
.

We found the best acceptable step interval to be
\alpha_{k}^{\min}\in[\frac{1}{4}\alpha_{k},4\alpha_{k}]
.
If
\alpha_{\min}\in[\frac{1}{4}\alpha_{k},4\alpha_{k}]
and
f(x_{k}^{\min})<f(x_{k}^{i-1})
we let
x_{k}^{i}:=x_{k}^{\min}
. Otherwise, we use the
x_{k}^{i}
of Section
3.1
.
This turns out to be a more powerful modification than the one of Section
3.1
and offers an acceleration of the European Swapton curve calibration by a factor of
3.8
(again, see Section
4.2
).

3.3
Computing derivatives

By studying the line search implementation of the LBFGS
++
library we realized that we can improve performance by separating the interface of the
operator()
function into 3 different functions. The
operator()
function of LBFGS
++
calculates both the target function value and the gradient. However, none of the termination conditions use the gradient which is only required by Step 4 of the LBFGS version of Algorithm
1
. The termination conditions only require directional derivatives at Step 2 of the LBFGS version of Algorithm
1
.

Using
operator()
, the directional derivative is computed via the dot product

\frac{\partial f}{\partial\alpha_{k}^{i}}=\nabla f(x_{k}^{i})\cdot p_{k}.

We instead use the finite difference method implemented in a new function
getDg()
. This change allows us to move the gradient computation from
operator()
to a new function
getGrad()
, which is only called after line search.

We now explain how
getDg()
works. Suppose that we are at some stage
x_{k}^{i}
of line search. To calculate the directional derivative of
f
at
x:=x_{k}^{i}
we can use

f^{\prime}(x)\approx\frac{f(x+hp_{k})-f(x)}{h},

where
h>0
is a parameter that one can set using an interface parameter
delta
. This approach is simple but can cause a significant error for some target functions
f
and parameters
h
.

A better approach is to use AVX as before and define 4 or 8 points as follows:

x_{-2}=x-2hp_{k},\ x_{-1}=x-hp_{k},\ x_{1}=x+hp_{k},\ x_{2}=x+2hp_{k}\text{ (if using AVX-2)}

\ \ \ \ \ \ \ \ \ x_{-4}=x-4hp_{k},\ x_{-3}=x-3hp_{k},\ x_{-2}=x-2hp_{k},\ x_{-1}=x-hp_{k},\ x_{1}=x+hp_{k},\\
x_{2}=x+2hp_{k},\ x_{3}=x+3hp_{k},\ x_{4}=x+4hp_{k}\text{ (if using AVX-512)}

Then one can approximate the derivative using:

f^{\prime}(x)\approx\frac{\sum_{i}f(x_{i})c_{i}}{h}

(1)

where
c_{i}
are the central finite difference coefficients, see
[
10
]
.

In the cases of
4
and
8
points we get:

f^{\prime}(x)\approx\frac{1}{h}\left[\frac{1}{12}f(x-2hp_{k})-\frac{2}{3}f(x-hp_{k})+\frac{2}{3}f(x+hp_{k})-\frac{1}{12}f(x+2hp_{k})\right]

\ \ \ \ \ \ \ \ \ \ \ \ f^{\prime}(x)\approx\frac{1}{h}\left[\frac{1}{280}f(x-4hp_{k})-\frac{4}{105}f(x-3hp_{k})+\frac{1}{5}f(x-2hp_{k})-\frac{4}{5}f(x-hp_{k})\right.\\
\left.+\frac{4}{5}f(x+hp_{k})-\frac{1}{5}f(x+2hp_{k})+\frac{4}{105}f(x+3hp_{k})-\frac{1}{280}f(x+4hp_{k})\right]

This broader averaging usually gives better results.

4
Implementation and testing

We shall explain the changes that we made to the LBFGS
++
library, introduce an interface for AADC that takes advantage of the modified library automatically and give two examples illustrating the efficiency of our modifications. All the code is available at
[
5
]
.

4.1
Implementation

We created a C
++
class
[
5
]
that facilitates the use of the LBFGS
++
library by AADC users.
The interface includes all the functions required by our implementation.
For most implementations we only need to pass the following AADC data to the basic class: recorded function, workspace, input and output variables.

One can set the value of
h
in the computation of the directional derivative.
The implementations that need extra data or an iterative method to calculate the gradient or function value require straightforward changes to the interface.
By default we calculate the function value as the sum of all the outputs since most target functions are of the form
f:\mathbb{R}^{n}\rightarrow\mathbb{R}
.

As our implementation is based on AVX we cannot disable the line search parallelization but one can set the number of computation points with the
typedef
template, i.e. initializing the interface object as
BFGSHelper<mmType>
.

Polynomial regression is achieved with a polynomial of order
3
(for AVX-2) or
7
(for AVX-512) by default as it uses
avx_count
points to compute it. The order can be set and verified by the functions
setPolyFitOrder(int ord)
and
int getPolyFitOrder()
. It can also be fully disabled by setting the order to 0.

The computation of the directional derivative uses all the available
avx_count
points. The options are using
2,\ 4,\ 6
or 8 points (note that for AVX2 the maximum is
4
). The user can use the functions
setDgOrder(int ord)
and
int getDgOrder()
to set and verify the number of points used. If an invalid number is set, the procedure is disabled by substituting it with the original implementation where the directional derivative is computed as the dot product of the gradient and the direction.

The user can also set the finite differences coefficients
c_{i}
using the functions

setDgCoeffs(std::vector<double> cs)
and
std::vector<double> setDgCoeffs()
(although the interface already has the default central finite difference coefficients for any valid number of points).

4.2
Curve calibration in ORE

We used the third example in the Open Source Risk Project (ORE) user guide
[
16
]
that shows the exposure evolution of European Swaptions with cash and physical delivery. This example already had AADC integrated into the underlying quantitative finance library QuantLib
[
15
]
.

We made some minor changes to
reportwriter.cpp
and used as input the curve
“xois 0 EUR”
. This curve has 14 outputs and 33 curve parameters so the curve function is
g:\mathbb{R}^{33}\rightarrow\mathbb{R}^{14}
. Our target function
f:\mathbb{R}^{33}\to\mathbb{R}
for ORE is the quadratic loss function relative to the desired outputs:

f(x):=\sum_{i=1}^{14}\left(g(x)_{i}-g(x_{\min})_{i}\right)^{2}

(2)

where
g(x)_{i}
is the
i
-th output of the curve function at the point
x
and
x_{\min}
represents the vector of the target parameters.

We set
\varepsilon_{\rel}:=3\cdot 10^{-4}
and
h:=10^{-14}
. These parameters required modifications in certain specific cases.
We take the initial vector
x_{0}
to be a vector of random numbers limited to the intervals
[0.9c_{i},1.1c_{i}]
where the
c_{i}
-s are the respective curve parameters.

4.3
Calibrating the LMM model

We analyzed the simple example of calibrating the LMM model by a set of European options. In this particular case, the loss function can be expressed in the form

G=\frac{1}{2}\sum_{i=1}^{m}(Ey_{i}-C_{i})^{2}.

(3)

Applying AAD to a function of this form is not straightforward and was done in
[
17
]
.

We employed a calibration tool provided by Matlogica (available at
[
5
]
) with the algorithm of
[
17
]
implemented that used Monte Carlo simulations, multithreading, LBFGS
++
, AVX, and AADC.
This tool has two major functions:
simulate1()
and
simulate2()
.

Simulate1()
updates the values needed to calculate the function value at the chosen point.

Simulate2()
calls
simulate1()
to update the values and then computes the gradient at that point.
Therefore, we can use
simulate1()
when we only want the function value (forward mode) and
simulate2()
to get the gradient (reverse mode).

It was not possible to implement our SIMD modifications of Sections
3.1
and
3.2
due to the calibration tool already using AVX and multithreading. Implementing the changes would require a full refactoring of the tool. However, we split the interface into
3
functions as explained in Section
3.3
. We also saved the reverse calls by deactivating the call of
simulate1()
when we called
simulate2()
in
getGrad()
. This could be done since the required outputs to compute the gradient were already calculated in
operator()
.

We set
\varepsilon_{\rel}:=10^{-6}
,
h:=10^{-5}
and take the initial vector
x_{0}
to be
90\%
of the target parameters
x_{0}:=0.9x_{\min}
.

We tested for unlimited LBFGS iterations and for LBFGS limited to 100 iterations (to reduce computational time).
We have also experimented with many termination conditions and line search algorithms. Table

5
Further improving the efficiency of LBFGS
++

It would be interesting to try to improve the method of approximating the Hessian matrix in the case of the LBFGS version of Algorithm
1
. The LBFGS
++
implementation consists of a loop and it should be possible to improve efficiency by using SIMD to calculate portions of the loop in parallel.

We have considered the Nocedal-Wright line search algorithm
[
12
]
but have not been able to notably improve efficiency. Although we have implemented our modifications to this method it would be interesting to try to improve efficiency with specific changes to the interface.

LBFGS-B is an extension of LBFGS to simple box constraints
[
12
]
. It would be interesting to see if our modifications are effective in this case. Extra verification may be needed to guarantee that we do not exit the box constraints.

This research was undertaken before more effective methods for computing gradients of functions of the form (
3
) were found in
[
3
]
(expanding on the work of
[
17
]
). It would be interesting to implement the modifications of Section
3.3
for calibrating with these improved algorithms.
