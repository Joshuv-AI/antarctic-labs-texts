A tutorial on implementing De Morgan cubical type theory
Tesla Zhang

Abstract
. This tutorial explains (one way) how to implement De Morgan cubical type theory to people who know how to implement a dependent type theory. It contains an introduction to basic concepts of cubes, type checking algorithms under a cofibration, the idea of ‘‘transportation rules’’ and cubical operations. This tutorial is a by-product of an experimental implementation 1 1 footnotemark: 1 of cubical type theory, called Guest0x0 .

1.1.
Target Audience

This tutorial assumes familiarity with the following:

•

Dependent type theory concepts, such as formation rules,
introduction rules, eliminators, etc., and functional programming.

•

Programming and theorem proving in a proof assistant based on dependent type theories.

•

The ability to translate (simple) typing rules into a type-checking procedures
and combine them into an algorithm.

•

Basic understanding of De Morgan cubical type theory
[
CCHM
,
CHM
]

(hereafter as øTT), including the interval type
\mathbb{I}
, the path type,
the idea of representing
n
-dimensional cubes using terms with interval variables in it,
and the De Morgan operators on
\mathbb{I}
.

This tutorial will not treat substitution formally –
variable names are assumed to respect capture-avoiding substitution.
In the implementations, any binding representation that works for untyped

\lambda
-calculus should work for the type theory introduced in this tutorial.

.

1.2.
Motivation

This tutorial is intended to help readers to get more familiar with how
øTT works under the hood, what difficulties it is having in implementations,
what it can already do, and what it cannot do yet.

øTT is a type theory evolved from a model using Kan cubical sets
[
CubicalSets
]
,
which uses sophisticated homotopy theory. Computer scientists, on the other hand,
usually do not have relevant courses taught in their undergraduate program.
However, it is also the computer scientists who are supposed to implement øTT as
programming languages. This tutorial tries to help those who did not study homotopy
theory, but have learned about the informal concepts of øTT
(like what is written in
[
NCTT
]
) and wish to learn the implementation details of øTT.

øTT extends Martin-Löf type theory with a huge amount of new constructions,
especially the typing rules are written in a very compact way (like in
[
HCompPDF
]
).
This tutorial aims to discuss them from an algorithmic perspective,
and hopefully to inspire more people to implement cubical type theory,
to fuse these ideas into other work, or just to worship these brilliant ideas.

This tutorial is a by-product of an experiment in implementing øTT, called
Guest0x0
,
a project created to encourage a particular person to learn øTT.
The story ends up in the worst way: the person did not learn øTT, and instead created
a new project to encourage the author of
Guest0x0
to learn extensional type theory.

2.1.
The interval
\mathbb{I}
and contexts

øTT has the interval type:

\vdash\mathbb{I}~\text{type}\quad\vdash\textsf{0}:\mathbb{I}\quad\vdash\textsf{1}:\mathbb{I}

The interval type and its products are used to represent dimensions
(ignoring the De Morgan structures for now).

Demonstration 2.1
.

Suppose
x:\mathbb{I}\vdash A~\text{type}
and
x:\mathbb{I}\vdash u:A
.
From a semantical or a topological perspective, one can say:

•

A
is a (type) line between
A[\textsf{0}/x]
and
A[\textsf{1}/x]
.

•

u
is a (term) line between
u[\textsf{0}/x]
and
u[\textsf{1}/x]
.

•

The type of a line is a line, so the type of
u
is
A
.

Then, because
typing relations are preserved by substitution
,
the following typing relations hold:

\frac{}{u[\textsf{1}/x]:A[\textsf{1}/x]}\frac{}{u[\textsf{0}/x]:A[\textsf{0}/x]}

We may visualize the fact as:

{\lx@inpgf@ignorespaces{u[\textsf{0}/x]}}
{\lx@inpgf@ignorespaces{A[\textsf{0}/x]}}
{\lx@inpgf@ignorespaces{u[\textsf{1}/x]}}
{\lx@inpgf@ignorespaces{A[\textsf{1}/x]}}
\scriptstyle{\lx@inpgf@ignorespaces u}
\scriptstyle{\lx@inpgf@ignorespaces A}
\scriptstyle{\lx@inpgf@ignorespaces:}

∎

Notation 2.2
.

Typing judgments are written as
\Psi;\Gamma\vdash A~\text{type}
and
\Psi;\Gamma\vdash u:A
,
where
\Psi;\Gamma
is the usual
context
in type theories,
with variables classified into two groups: if a variable has type
\mathbb{I}
,
it goes to
\Psi
, otherwise it goes to
\Gamma
.
This convention is borrowed from
[
ABCFHL
]
.
∎

Note that
2.2
does not imply that contexts has to be classified
in the implementations. The
Guest0x0
type checker mix intervals
and other bindings in a unified context, just like usual dependent type checkers.

Remark 2.3
.

Consider

and
\vdash v:\mathbb{I}\to A

Usually both are referred to as a

Suppose the context is weakened with

2

in which

x
y
u

Note that the orientation of

However, for

x
y
v~x
v~y

So, interval application may also be thought of as

placing an
n
