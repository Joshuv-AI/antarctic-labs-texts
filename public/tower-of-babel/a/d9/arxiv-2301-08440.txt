Hypercore Decomposition for Non-Fragile Hyperedges: Concepts, Algorithms, Observations, and Applications
Fanchen Bu, Geon Lee, and Kijung Shin

Abstract
Hypergraphs are a powerful abstraction for modeling high-order relations, which are ubiquitous in many fields. A hypergraph consists of nodes and hyperedges (i.e., subsets of nodes); and there have been a number of attempts to extend the notion of k \mathchar 29035 -cores, which proved useful with numerous applications for pairwise graphs, to hypergraphs. However, the previous extensions are based on an unrealistic assumption that hyperedges are fragile , i.e., a high-order relation becomes obsolete as soon as a single member leaves it. In this work, we propose a new substructure model, called ( k , t ) \delimiter 67273472\mathchar 29035\mathchar 24891\mathchar 29044\delimiter 84054785 -hypercore, based on the assumption that high-order relations remain as long as at least t \mathchar 29044 fraction of the members remains. Specifically, it is defined as the maximal subhypergraph where (1) every node is contained in at least k \mathchar 29035 hyperedges in it and (2) at least t \mathchar 29044 fraction of the nodes remain in every hyperedge. We first prove that, given t \mathchar 29044 (or k \mathchar 29035 ), finding the ( k , t ) \delimiter 67273472\mathchar 29035\mathchar 24891\mathchar 29044\delimiter 84054785 -hypercore for every possible k \mathchar 29035 (or t \mathchar 29044 ) can be computed in time linear w.r.t the sum of the sizes of hyperedges. Then, we demonstrate that real-world hypergraphs from the same domain share similar ( k , t ) \delimiter 67273472\mathchar 29035\mathchar 24891\mathchar 29044\delimiter 84054785 -hypercore structures, which capture different perspectives depending on t \mathchar 29044 . Lastly, we show the successful applications of our model in identifying influential nodes, dense substructures, and vulnerability in hypergraphs.

3.1
Proposed concepts

In pairwise graphs, each edge represents a connection between two nodes, and thus the removal of either node naturally results in the complete nullification of the edge.
In contrast, a hyperedge with three or more nodes still represents the interactions among the remaining nodes even when some constituent nodes are removed.
As we have discussed and shown in Fig.

groundlessly assumes fragile hyperedges and suffers from information loss.

6.1
Influential-node identification

It is well-known that in pairwise graphs, coreness is a good indicator of influential nodes
(
Kitsak et al. 2010
)
.
However, influential-node identification in hypergraphs is still underexplored, while some trials have been done
(
Zhu et al. 2018a
;
Antelmi et al. 2021
)
.
We use the SIR model, a widely-used epidemic model.
The model is straightforwardly generalized so that it can be used on hypergraphs, where the probability of a susceptible node being infected by the infected nodes in a hyperedge is proportional to the proportion of infected nodes in the hyperedge.
At each time step, each infected node recovers with a given probability (
\mathchar 28941
) independently.
We simulate the
hyperSIR
(see Alg.
4

\mathchar 28721\mathchar 28720\%
of the nodes, and perform the simulation
\mathchar 28721\mathchar 28720\mathchar 28720
times for each seed node.

\mathchar 28721\mathchar 28720\mathchar 24891\mathchar 28720\mathchar 28720\mathchar 28720
times for each node as the seed.

Alg.
5
(with
\mathchar 29038_{\mathchar 29027}\mathchar 12349\mathchar 8704\mathchar 28721
) shows the generalization of CKC
(
Zhang et al. 2017b
)
, which was originally designed for the collapsed
\mathchar 29035
-core problem, to the collapsed
\delimiter 67273472\mathchar 29035\mathchar 24891\mathchar 29044\delimiter 84054785
-hypercore problem.
Following CKC, in each round, we find a best collapser (i.e., a node that reduces the size of
\delimiter 67273472\mathchar 29035\mathchar 24891\mathchar 29044\delimiter 84054785
-hypercore most) in the candidate set
\mathchar 29012
, and update the
\delimiter 67273472\mathchar 29035\mathchar 24891\mathchar 29044\delimiter 84054785
-hypercore after removing the chosen collapser, until all
\mathchar 29026
collpasers are chosen.
However, the naive generalization encounters the following problems:

•

CKC only considers simple pairwise graphs. In simple pairwise graphs, where at most one edge exists between each node pair, the candidate set
\mathchar 29012
, i.e., the set of nodes whose deletion will result in the removal of some other node, simply consists of the neighbors of the nodes with degree
\mathchar 29035
.
In hypergraphs, two nodes may co-exist in
multiple
hyperedges. Therefore, we need to additionally check the number of
endangered hyperedges
in the set
\tilde{\mathchar 28997}
, where endangered hyperedges are the ones with exactly the minimum size satisfying the threshold determined by
\mathchar 29044
.
Furthermore, we need to count each node pair in each endangered hyperedge, which is time-consuming with time complexity
\mathchar 29007\delimiter 67273472\mathchar 4944\displaylimits_{\mathchar 29029\mathchar 12850\mathchar 28997^{\mathchar 560}}\delimiter 69640972\mathchar 29029\delimiter 86418188^{\mathchar 28722}\delimiter 84054785
(Line
15
).
To make the situation worse, this process is repeated in each round (
\mathchar 29026
times in total).

•

CKC computes the
\mathchar 29035
-core after removing each candidate to evaluate the candidates.
Similarly,
\delimiter 67273472\mathchar 29035\mathchar 24891\mathchar 29044\delimiter 84054785
-hypercore computation is required for
each
candidate (Line
22
), where the number of all candidates can be large.
Compared to core computation with time complexity linear in the number of edges
(
Batagelj and Zaversnik 2003
)
, as shown in Thm.
1
,
\delimiter 67273472\mathchar 29035\mathchar 24891\mathchar 29044\delimiter 84054785
-hypercore computation has considerably higher time complexity.

We propose
HyCoM
(
Hy
per-
Co
re
M
inimization) and the further-optimized
HyCoM+
, which are described in Alg.
5
, to address the above problems with the following improvements:

•

Only checking the most promising candidates.

Although we may have a large number of candidates, not every candidate is likely to be the best collapser.
Intuitively, we may set a maximum number of candidates to check in each round (
\mathchar 29038_{\mathchar 29027}\mathchar 12828\mathchar 29012
) and only check the most promising ones.
The technique reduces the time of hypercore decompositions in each round from
\mathchar 29007\delimiter 67273472\mathchar 29012\delimiter 84054785
to
\mathchar 29007\delimiter 67273472\mathchar 29038_{\mathchar 29027}\delimiter 84054785
, which gives
HyCoM
.
We further improve the algorithm by the following two techniques and have
HyCoM+
.

•

Sorting candidates by the number of direct followers.

In
HyCoM
, the degrees are used to sort the candidates and to find the promising ones.
However, the degree does not always imply a node’s ability in (hyper)core minimization.
The
direct followers
(
\mathcal{\mathchar 28998}\delimiter 67273472\mathchar 8705\delimiter 84054785
in Line
17
, i.e., the nodes that will leave the hypercore immediately due to the deletion) of each candidate are accessible without additional cost during the process of finding candidates,
and the number of direct followers provides a lower bound for the total number of followers.
Thus, we use the number of direct followers to find the most promising candidates (Line
18
).

•

Incremental update of the endangered hyperedges.

It is necessary to find the endangered hyperedges, and we incrementally update the set whenever the hypercore is updated (Line
27
) instead of computing it from scratch in each round.
By doing so, during the whole process,
\tilde{\mathchar 28997}
is constructed from scratch only once.
The number of hyperedges needed to be checked in each round is the size of the
symmetric difference
between the current set of endangered hyperedges and that in the previous round, which is empirically much less than the total number of hyperedges in the hypercore.
