Path and Ancestor Queries over Trees with Multidimensional Weight Vectors
Meng He, Serikzhan Kazi

Abstract
We consider an ordinal tree T T on n n nodes, with each node assigned a d d -dimensional weight vector 𝐰 ∈ { 1 , 2 , … , n } d , \mathbf{w}\in\{1,2,\ldots,n\}^{d}, where d ∈ ℕ d\in\mathbb{N} is a constant. We study path queries as generalizations of well-known orthogonal range queries , with one of the dimensions being tree topology rather than a linear order. Since in our definitions d d only represents the number of dimensions of the weight vector without taking the tree topology into account, a path query in a tree with d d -dimensional weight vectors generalize the corresponding ( d + 1 ) (d+1) -dimensional orthogonal range query. We solve ancestor dominance reporting problem as a direct generalization of dominance reporting problem, in time 𝒪 ⁡ ( lg d − 1 ⁡ n + k ) \mathcal{O}(\lg^{d-1}{n}+k) and space of 𝒪 ⁡ ( n ​ lg d − 2 ​ n ) \mathcal{O}(n\lg^{d-2}n) words, where k k is the size of the output, for d ≥ 2 . d\geq 2. We also achieve a tradeoff of 𝒪 ⁡ ( n ​ lg d − 2 + ϵ ​ n ) \mathcal{O}(n\lg^{d-2+\epsilon}{n}) words of space, with query time of 𝒪 ⁡ ( ( lg d − 1 ⁡ n ) / ( lg ⁡ lg ⁡ n ) d − 2 + k ) , \mathcal{O}((\lg^{d-1}n)/(\lg\lg n)^{d-2}+k), for the same problem, when d ≥ 3 . d\geq 3. We solve path successor problem in 𝒪 ⁡ ( n ​ lg d − 1 ​ n ) \mathcal{O}(n\lg^{d-1}{n}) words of space and time 𝒪 ⁡ ( lg d − 1 + ϵ ⁡ n ) \mathcal{O}(\lg^{d-1+\epsilon}{n}) for d ≥ 1 d\geq 1 and an arbitrary constant ϵ > 0 . \epsilon>0. We propose a solution to path counting problem , with 𝒪 ⁡ ( n ​ ( lg ⁡ n / lg ⁡ lg ⁡ n ) d − 1 ) \mathcal{O}(n(\lg{n}/\lg\lg{n})^{d-1}) words of space and 𝒪 ⁡ ( ( lg ⁡ n / lg ⁡ lg ⁡ n ) d ) \mathcal{O}((\lg{n}/\lg\lg{n})^{d}) query time, for d ≥ 1 . d\geq 1. Finally, we solve path reporting problem in 𝒪 ⁡ ( n ​ lg d − 1 + ϵ ​ n ) \mathcal{O}(n\lg^{d-1+\epsilon}{n}) words of space and 𝒪 ⁡ ( ( lg d − 1 ⁡ n ) / ( lg ⁡ lg ⁡ n ) d − 2 + k ) \mathcal{O}((\lg^{d-1}{n})/(\lg\lg{n})^{d-2}+k) query time, for d ≥ 2 . d\geq 2. These results match or nearly match the best tradeoffs of the respective range queries. We are also the first to solve path successor even for d = 1 d=1 .

Introduction

The problem of preprocessing a weighted
tree, i.e., a tree in which each node is associated with a weight value, to support various queries
evaluating a certain function on the node weights
of a given path, has been extensively studied

[
2
,
6
,
14
,
19
,
8
,
17
,
4
]
.
For example, in
path counting
(resp.
path reporting
),
the nodes of the given path with weights lying in the given query interval are counted (resp. reported).
These queries address the needs of fast information retrieval from tree-structured data such as XML and tree network topology.

For many applications, meanwhile, a node in a tree is associated with not just a single weight, but rather with a vector of weights.
Consider a simple scenario of an online forum thread,
where users can rate responses and respond to posts.
Induced is
a tree-shaped structure with posts representing nodes,
and replies to a post being its children.
One can imagine enumerating all the ancestor posts
of a given post that are not too short and
have sufficiently high average ratings. Ancestor dominance query,
which is among the problems we consider, provides an appropriate
model in this case.

We define a
d
-
dimensional weight vector

\mathbf{w}=(w_{1},w_{2},\ldots,w_{d})

to be a vector with
d
components, each in rank space
[n],

1
1

1

Throughout this paper,
[n]
stands
for
\{1,2,\ldots,n\}
for any positive integer
n

i.e.
\mathbf{w}\in[n]^{d},

with
w_{i}
being referred to as the
i
th weight of
\mathbf{w}.

We then consider an ordinal tree
T
on
n
nodes,
each node
x
of which is assigned a
d
-dimensional weight vector
\mathbf{w}(x).

The queries we will define all give a
d
-dimensional orthogonal range

Q=\prod_{i=1}^{d}[q_{i},q^{\prime}_{i}],

and a weight vector
\mathbf{w}
is in
Q

iff
for any
i\in[1,d],\,q_{i}\leq w_{i}\leq q^{\prime}_{i}
holds.
In our queries, then,
we are given a pair of vertices
x,y\in T,
and an arbitrary orthogonal range

With
P_{x,y}
being the path from
x
to
y

T,

the goal is to preprocess the tree
T
for the following
types of queries:

•

Path Counting
: return
|\{z\in P_{x,y}\,|\,\mathbf{w}(z)\in{Q}\}|
.

•

Path Reporting
: enumerate
\{z\in P_{x,y}\,|\,\mathbf{w}(z)\in{Q}\}
.

•

Path Successor
: return
\mathtt{argmin}\{w_{1}(z)\,|\,z\in P_{x,y}\,\text{and}\,\mathbf{w}(z)\in Q\}
.
2
2

2

For path successor,
we assume that
q^{\prime}_{1}=\infty
;
if not, we need only check whether the
1
st weight of the returned node is at most
q^{\prime}_{1}
.

•

Ancestor Dominance Reporting
: a special case of path reporting, in which
y
is the root of the tree and
q_{i}^{\prime}=+\infty
for all
i\in[d].

That is, the query reports the ancestors of
x
whose weight vectors dominate the vector
\mathbf{q}=(q_{1},q_{2},\ldots,q_{d})
.

This indeed is a natural generalization of the traditional
weighted tree, which we refer to as “scalarly-weighted”,
to the case when the weights
are multidimensional vectors. At the same time,
when the tree degenerates into a single path,
these queries become respectively
(d+1)
-dimensional orthogonal range counting, reporting, successor,
as well as
(d+1)
-dimensional dominance reporting queries.
Thus, the queries we study are generalizations of these fundamental geometric queries in high dimensions.
We also go along with the state-or-art in orthogonal range search by considering weights in rank space,
since the case in which weights are from a larger universe can be reduced to it
[
11
]
.

To achieve our results,

We now describe the algorithm for answering queries, and analyze its running time
and space cost:

Lemma 9
.

A tree
T
on
n
nodes, in which each node is assigned a
2
-dimensional weight vector,

\mathcal{O}(n)
words, so that an ancestor dominance
reporting query can be answered in

is the number of the nodes reported.

Proof.

Let

be the node and weight vector given as query parameters, respectively.
We define

Let

denote the node at level

for some

or (ii)

contains at least one node whose corresponding node in

Let

-view of

There are two cases depending on whether

, of

in

correspond to all the ancestors of

in
T
that have corresponding nodes in

.
We then perform a weighted ancestor query using

to locate the highest ancestor,

whose

Since the

Hence, by performing a

.
Then, for each of these nodes, we retrieve from

IF

Therefore, by performing a

whose corresponding nodes in

We then perform a

as the query path and

.

The space occupied by the annotation array

Namely,

, which stores,

whose weights are in the range represented by

Rather than maintaining

,
for predecessor/successor search

]
in

Assuming the availability of a
\mathchoice{{\scriptstyle\mathcal{O}}}{{\scriptstyle\mathcal{O}}}{{\scriptscriptstyle\mathcal{O}}}{\scalebox{.7}{$\scriptscriptstyle\mathcal{O}$}}(n^{\delta})

\mathcal{O}(\lg\lg{n})

\mathcal{O}(\lg{n}/\lg\lg{n})

We now turn to answering the query using the data structures built.
Resolving the query falls into two distinct cases, depending
on whether the level

, at which the query node

resides, is marked or not.

When the level

is marked, we use the structures
S_{u}
stored therein, directly.
We adopt the strategy in
[
16
]
to find

First, for an arbitrary index
i
to
A_{u},
we observe that node
A_{u}[i]\in T
corresponds to node
(s_{u}+i-1)
in
T_{l}.

We thus fetch
\langle{}a_{u},b_{u},s_{u},t_{u}\rangle{}
from

Then the predecessor
p\in A_{u}
of

is obtained through
S_{u}
via an
\mathcal{O}(\lg\lg{n})

\mathcal{O}(1)

\mathcal{B}
-structure,
which totals
\mathcal{O}(\lg^{\epsilon^{\prime}}{n})
time. We then determine the lowest common ancestor
\chi\in T

of

and

in
\mathcal{O}(1)
time. If the weight of
\chi
is in
[a_{u},b_{u}],

by the

By another predecessor query, therefore, we can find the position,

,
of

in

, and
(s_{u}+j-1)
is the sought

Otherwise, a final query to

in

of

Let

in

.
Then the parent of the node

in

is

We perform a constant number of predecessor/successor queries, and correspondingly
a constant number of calls to the ball-inheritance problem. The time complexity
is thus
\mathcal{O}(\lg^{\epsilon^{\prime}}{n}).

When the level

is not marked, we ascend to the lowest ancestor
u^{\prime}
of

residing on a marked level

and reduce the problem to the previous case.
More precisely, via the navigation operations (

to move to a parent, and

Let

.
We find the answer to the original query, as if the query

in

-view
of the original query node

in

Let us initialize a variable

We descend down to the original level

back to the original

adjusting the node

to the proof of
\Cref

As we arrive, in time

the variable

In both cases, the term
\mathcal{O}(\lg^{\epsilon^{\prime}}{n})
dominates the time complexity,

Therefore, a query is answered in

∎

Finally, each

We now describe the algorithm for answering queries
and analyze its running time, as well as give the space cost of the built data structures:

Lemma 14
.

A scalarly-weighted tree

on

\mathcal{O}(n)
words,
so that a path successor query
is answered in
\mathcal{O}(\lg^{\epsilon}{n})

Proof.

Let

and

be respectively the nodes and the orthogonal range given as query’s parameters.
Appealing to the proof of
\Cref

the path

where

\mathtt{LCA}(T,x,y).

We locate in
\mathcal{O}(1)

of

Let

in

let

We binary search in

is the root of

as the height of

is the leaf

]

7
Path Counting

Note that we can not directly apply previous approaches,
such as e.g.
[
17
]
as a base data structure
for the
1D
case. Those being not
(1,d,\epsilon)
-dimensional data structures,
naïve way of accommodating the last
(d-1)
weights
would inevitably incur an extra
\lg^{2(d-1)\epsilon}{n}
-factor
in space. To do better than that, we need a few more techniques,
notably,
tree covering.

Tree covering first appeared in
[
12
,
15
,
10
]

as a method of succinct representation of ordinal trees.
The original tree is split into
mini
-trees, given a certain parameter
L
:

Lemma 16

(
[
10
]
)
.

A tree with
n
nodes can be decomposed into
\Theta(n/L)
subtrees
of size at most
2L.
These are pairwise disjoint aside from the subtree roots.
Furthermore, aside from the edges stemming from the subtree roots,
there is at most one edge per subtree leaving a node of a subtree
to its child in another subtree.

Each of the mini-trees
in turn can be recursively decomposed into
micro
-trees, with another parameter
L^{\prime}.

The idea is to choose the parameter
L^{\prime}
such that
intra
-micro-tree queries
are executed in constant-time by virtue of a precomputed table
\mathcal{T}
of
size
\mathchoice{{\scriptstyle\mathcal{O}}}{{\scriptstyle\mathcal{O}}}{{\scriptscriptstyle\mathcal{O}}}{\scalebox{.7}{$\scriptscriptstyle\mathcal{O}$}}(n),

indexed by micro-trees. Consequently, for any given node
x\in T,

the solutions of
[
12
,
15
,
10
]

provide a constant-time access to the mini-tree
\tau
and micro-tree
\tau^{\prime}

containing the node
x,
as well as the address of the micro-tree
\tau^{\prime}
in the table
\mathcal{T},

using
\mathcal{O}(n)
bits of space,
for suitably chosen parameters
L
and
L^{\prime}.

The goal of this section is to design a data structure to solve the
path counting problem
when the nodes are assigned
(0,d,\epsilon)
-dimensional weight vectors.
It turns out that when the weight vector of a node can be packed into
\mathchoice{{\scriptstyle\mathcal{O}}}{{\scriptstyle\mathcal{O}}}{{\scriptscriptstyle\mathcal{O}}}{\scalebox{.7}{$\scriptscriptstyle\mathcal{O}$}}(\lg{n})
bits,
counting queries can be executed in constant time. The key machinery used is tree covering.

Let
T
be a given ordinal tree on
n
nodes, each node of which is assigned
a
(0,d,\epsilon)
-dimensional weight vector. Let
\rho
be the root of
T.

In our solution to the
(0,d,\epsilon)
-dimensional path counting problem for
T,

we set
c=\lceil\lg^{\epsilon}n\rceil,
and using
\Cref
lemma:lemmaOnTreeCover01
perform the decomposition of
T
into mini-trees with parameter

L=c^{2d}\lg{n}.
Each of the mini-trees is further subject to decomposition
into micro-trees with parameter
L^{\prime}=c^{2d}.

Each mini- or micro-tree
b
stores
an array
b.cnt,
indexed by a tuple from
([c]\times{}[c])^{d},

with the following contents
(henceforth let
r_{b}
be the root of the mini- or micro-tree
b
):

•

for a mini-tree
b,
an
\mathcal{O}(\lg{n})
-bit number
b.cnt[Q]

stores the answer to the path counting query with parameters
r_{b},\rho,Q;

i.e.,
b.cnt[Q]
is the number
of the nodes with weight vectors falling within the range
Q

on the path
A_{r_{b},\rho}
in
T,
where
\rho
is the root of
T;

•

for a micro-tree
b^{\prime}
inside a mini-tree
b,

an
\mathcal{O}(\lg\lg{n})
-bit number
b^{\prime}.cnt[Q]
stores the answer
to the path counting query with parameters
r_{b^{\prime}},r_{b},Q;

i.e.,
b^{\prime}.cnt[Q]
is the number
of the nodes with weight vectors falling within the range
Q

on the path
A_{r_{b^{\prime}},r_{b}}.

We also precompute a look-up table
D
that is indexed by a quadruple
from the following Cartesian product:

•

all the possible micro-tree topologies
\tau,

times

•

all possible assignments
\lambda
of weight vectors to the nodes of
\tau,

times

•

all nodes in
\tau
,
times

•

all possible query orthogonal ranges
Q.

The entry
D[\tau,\lambda,x,Q]
stores the answer
to the path counting query with parameters
x,r_{\tau},Q
over a micro-tree
with topology
\tau,
nodes of which are assigned weight vectors
from configuration
\lambda.
More precisely,
\lambda
is
a labeling of the micro-tree
\tau
with
(0,d,\epsilon)
-dimensional
weight vectors, and
D[\tau,\lambda,x,Q]
stores the number
of nodes on the path
A_{x,r_{\tau}}
in
\tau,
such
that their weight vectors belong to the range
Q.

We now show how to use these data structure to answer queries.

Lemma 17
.

The data structures in this section can answer a
(0,d,\epsilon)
-dimensional
path counting query in
\mathcal{O}(1)
time, for any constant integer
d\geq 1.

Proof.

Let
P_{x,y}
and
Q
be, respectively, the path and the orthogonal range given as the parameters to the query.
Using the notation from the proof of
\Cref
lem:reductionBinaryCase, and for the reasons given therein,
we describe only how to answer the query over
A_{x,z},
where
z=\mathtt{LCA}(T,x,y).

We assume the encoding of
T
as in
\Cref
lemma:smallAlphabetTrees, so the
\mathtt{LCA}

operator is available; the space overhead is only
\mathcal{O}(n)
bits,
i.e. negligible with respect to the space bound we are ultimately aiming at.

We further notice that answering path counting query over
A_{x,z}

is equivalent to answering two path counting queries, one over
A_{x,\rho}

and another over
A_{z,\rho}
, and taking their arithmetic difference.
It is thus sufficient to describe the procedure of
answering the query over
A_{x,\rho},
and analyze its running time,
as the query over
A_{z,\rho}
can be handled similarly.

The key observation is that overall we perform a constant number of constant-time operations.
Indeed, using data structures of
[
10
]
,
we first identify, in
\mathcal{O}(1)
time, the mini-tree
b
and micro-tree
b^{\prime}
containing
the node
x,
as well as the encoding of
b^{\prime}.

From the (disjoint) decomposition of the path

A_{x,\rho}=A_{x,r_{b^{\prime}}}\cup A_{r_{b^{\prime}},r_{b}}\cup A_{r_{b},\rho},

it is now immediate that the answer to the query over
A_{x,\rho}
is

D[b^{\prime},\mathtt{lab}(b^{\prime}),x,Q]+b.cnt[Q]+b^{\prime}.cnt[Q],

where
\mathtt{lab}(b^{\prime})
is the labeling of the micro-tree
b^{\prime}.

Therefore, our algorithm runs in
\mathcal{O}(1)
time.
∎

We now analyze the space cost of our data structures.

Lemma 18
.

The data structures in this section occupy
\mathcal{O}(n\lg\lg{n})
bits when
\epsilon\in(0,\frac{1}{4d}).

Proof.

To analyze the space cost, we tally up the costs of the main constituents
of our data structure: the
cnt
-arrays
stored at the roots of each
mini- and micro-tree, and the
D
-table.

There being
\Theta(n/(c^{2d}\lg{n}))
mini-trees,
each of which contains an array of
c^{2d}
elements,
\mathcal{O}(\lg{n})
bits each,
the associated
cnt
-arrays contribute
\mathcal{O}(n/(c^{2d}\lg{n})\times{}c^{2d}\times{}\lg{n})=\mathcal{O}(n)
bits.

Analogously, for the
\Theta(n/c^{2d})
micro-trees,
the net contribution of the associated
cnt
-arrays is

\mathcal{O}(n/c^{2d}\times{}c^{2d}\times{}\lg{(c^{2d}\lg{n})})=\mathcal{O}(n\lg\lg{n})
bits,
which is the space claimed in the statement.

It suffices to show, therefore, that the space occupied by the
D
-structure
can not exceed
\mathcal{O}(n\lg\lg{n})
bits; as demonstrated below, it is much less.
Indeed, as mentioned in
\Cref
lemma:lemmaOnTreeCover01,
each micro-tree can have up to
2c^{2d}
nodes, which gives us at most

2^{2\cdot{}2c^{2d}}
possible topologies
\tau.

In turn, each of the
2c^{2d}
nodes can independently be assigned
c^{d}
possible weight vectors;
hence the number of possible configurations
\lambda
is at most
(c^{d})^{2c^{2d}}

(the number of strings of length
2c^{2d}
over alphabet
[c^{d}]
).
Furthermore, the
c^{2d}
query orthogonal ranges
Q

make for

2c^{2d}\times{}c^{2d}=2c^{4d}
distinct queries,
i.e. the number of nodes times the number of ranges.
The number of entries in the table
D
is thus
at most
\mathcal{O}(2^{4c^{2d}}\cdot{}(c^{d})^{2c^{2d}}\cdot{}2c^{4d})=\mathcal{O}((4c^{d})^{2c^{2d}}c^{4d}).

The term
c^{4d}
is
\mathchoice{{\scriptstyle\mathcal{O}}}{{\scriptstyle\mathcal{O}}}{{\scriptscriptstyle\mathcal{O}}}{\scalebox{.7}{$\scriptscriptstyle\mathcal{O}$}}(\lg{n}).

To upper-bound the term
(4c^{d})^{2c^{2d}},
we notice
that
c^{d}=\lceil\lg^{\epsilon}{n}\rceil^{d}<\sqrt[4]{\lg{n}}/4
for sufficiently large
n
.
Therefore, we have the following chain of inequalities for sufficiently large
n
:

\begin{array}[]{lllllll}(4c^{d})^{2c^{2d}}&<&\Bigl(\sqrt[4]{\lg n}\Bigr)^{2c^{2d}}&<&\Bigl(\sqrt[4]{\lg n}\Bigr)^{2\sqrt{\lg n}}&=&{\Bigl(\sqrt{\lg{n}}\Bigr)^{\sqrt{\lg{n}}}}\\
&=&{\Bigl({2^{\lg\sqrt{\lg{n}}}}\Bigr)^{\sqrt{\lg{n}}}}&=&{2^{{\sqrt{\lg{n}}}\cdot\lg\sqrt{\lg{n}}}}&<&{2^{\sqrt{\lg{n}}\cdot\frac{\sqrt{\lg n}}{2}}=\sqrt{n}}\end{array}

Thus, the number of entries in
D
is at most
\mathcal{O}(\sqrt{n}\lg^{4d\epsilon}{n}).

Each entry holding a value of
\mathcal{O}(\lg{c^{2d}})=\mathcal{O}(\lg\lg{n})
bits,
the table
D
occupies
\mathcal{O}(\sqrt{n}\lg\lg{n}\lg^{4d\epsilon}{n})=\mathchoice{{\scriptstyle\mathcal{O}}}{{\scriptstyle\mathcal{O}}}{{\scriptscriptstyle\mathcal{O}}}{\scalebox{.7}{$\scriptscriptstyle\mathcal{O}$}}(n)
bits,
in total.

Finally, as shown above, the number of ways to assign
weight vectors to nodes of a micro tree is a

\mathcal{O}(L^{\prime}\lg\lg{n})
-bit number.
Thus, the storage space for the labelings of each of the
\Theta(n/L^{\prime})
micro-trees
amounts to
\mathcal{O}(n\lg\lg{n})
bits.
∎

\Cref
lemma:pathCountingQueryBaseCase0Time,lemma:pathCountingQueryBaseCase0Space, we have the following

Finally, instantiating

Lemma 22
.

Let
d\geq 1
and
0<\epsilon<\frac{1}{2(d-1)}
be constants,
and let
T
be an ordinal tree on
n
nodes,
in which each node is assigned a
(1,d,\epsilon)
-dimensional
weight vector. Then,
T
can be represented in

\mathcal{O}(n\lg^{\epsilon^{\prime}}{n})
words of space,
for any
\epsilon^{\prime}\in(2(d-1)\epsilon,1),

a path reporting query can be answered in
\mathcal{O}(\lg\lg{n}+k)

where
k
is the number of reported nodes.

Proof.

In brief, we build a path reporting data structure from
\Cref
lemma:pathReportingBaseCase
for each possible orthogonal range over the last
(d-1)
dimensions.
When presented with a query, we directly proceed to the appropriately-tagged (by the last

(d-1)
weights) reporting structure, and launch the query therein.
A detailed exposition follows.

We assume the encoding of
T
as in
\Cref
lemma:smallAlphabetTrees; the space
incurred is only
\mathcal{O}(n)
bits, i.e. negligible with respect
to the terms derived below.

For any
(0,d-1,\epsilon)
-dimensional orthogonal range
G

we build an explicit scalarly-weighted tree
E_{G}
as the
extraction of the node set
\{v\,|\,v\in T\text{ and }\mathbf{w}_{2,d}(v)\in G\}
from
T
.
The weight of a node in
E_{G}
is the
1
st weight of its
T
-source.
If
E_{G}
has a dummy root, then its weight is
-\infty.

E_{G}
is represented using
\Cref
lemma:pathReportingBaseCase,
in space that is at most
\mathcal{O}(n\lg^{\delta}{n})
words, for arbitrarily small positive
\delta.

In order to adjust the nodes between
T
and
E_{G},
a
0/1
-labeled
tree
T_{G}
is maintained. It has the same structure as
T,

and a node in it has label
1

iff
it has been extracted into
E_{G};

its label is
0,
otherwise.
The tree
T_{G}
is represented using
\Cref
lemma:smallAlphabetTrees,
in
3n+\mathchoice{{\scriptstyle\mathcal{O}}}{{\scriptstyle\mathcal{O}}}{{\scriptscriptstyle\mathcal{O}}}{\scalebox{.7}{$\scriptscriptstyle\mathcal{O}$}}(n)
bits.

Accounting for all possible ranges
G,
we therefore have
\mathcal{O}(n\lg^{\delta+2(d-1)\epsilon}{n})
words of space, in total.
Setting
\delta
to be sufficiently small and assigning
(\delta+2(d-1)\epsilon)
to
\epsilon^{\prime}

justifies the space claimed. All the
T_{G}
-structures collectively
occupy
\mathcal{O}(n\lg^{2(d-1)\epsilon}{n})
bits of space, which is
\mathchoice{{\scriptstyle\mathcal{O}}}{{\scriptstyle\mathcal{O}}}{{\scriptscriptstyle\mathcal{O}}}{\scalebox{.7}{$\scriptscriptstyle\mathcal{O}$}}(n)
words.

Let
P_{x,y}
and

Using the notation of the
\Cref

as given therein, we concern ourselves only with answering the query over the path

To answer the query, we first locate the relevant tree
E_{Q^{\prime}},
where
Q^{\prime}=Q_{2,d},

and launch path reporting query in
E_{Q^{\prime}}
, having adjusted the nodes
x
and
z

accordingly to their
T_{Q^{\prime}}
-views
as
x=\mathtt{pre\_rank}_{1}(T_{Q^{\prime}},\mathtt{level\_anc}_{1}(T_{Q^{\prime}},x,1))
,
and analogously for

Finally, the one-dimensional query in

executes in
\mathcal{O}(\lg\lg{n}+k)
time,
by
\Cref
lemma:pathReportingBaseCase, thereby establishing the claimed time bound.
For each returned node

with
\mathtt{pre\_select}_{1}(T_{Q^{\prime}},x)
