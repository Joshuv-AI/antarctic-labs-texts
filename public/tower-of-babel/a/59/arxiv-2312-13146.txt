FLASH-TB: Integrating Arc-Flags and Trip-Based Public Transit Routing
Ernestine Großmann, Jonas Sauer, Christian Schulz, Patrick Steil, Sascha Witt

Abstract
We present FLASH-TB, a journey planning algorithm for public transit networks that combines Trip-Based Public Transit Routing (TB) with the Arc-Flags speedup technique. The basic idea is simple: The network is partitioned into a configurable number of cells. For each cell and each possible transfer between two vehicles, the algorithm precomputes a flag that indicates whether the transfer is required to reach the cell. During a query, only flagged transfers are explored. Our algorithm improves upon previous attempts to apply Arc-Flags to public transit networks, which saw limited success due to conflicting rules for pruning the search space. We show that these rules can be reconciled while still producing correct results. Because the number of cells is configurable, FLASH-TB offers a tradeoff between query time and memory consumption. It is significantly more space-efficient than existing techniques with a comparable preprocessing time, which store generalized shortest-path trees: to match their query performance, it requires up to two orders of magnitude less memory. The fastest configuration of FLASH-TB achieves a speedup of more than two orders of magnitude over TB, offering sub-millisecond query times even on large countrywide networks.

Introduction

Journey-planning applications that provide real-time routing information have become a part of our daily lives.
To allow for interactive use, the employed routing algorithms must be very fast.
Although Dijkstra’s algorithm
[
14
]
finds shortest paths in quasi-linear time, it still takes several seconds on continental-sized networks.
Practical applications therefore rely on
speedup techniques
, which compute auxiliary data in a preprocessing phase to accelerate the query phase.
For road networks, many speedup techniques have been developed in recent decades
[
3
]
.
These achieve sub-millisecond query times with only moderate preprocessing time and space consumption.
For public transit networks, the situation is less satisfactory.
Although some techniques offer sub-millisecond query times on networks representing large countries, these require auxiliary data in the tens to hundreds of gigabytes.
This discrepancy has been explained by the fact that road networks exhibit beneficial structural properties that are less pronounced in public transit networks
[
1
]
.
Another challenge is that passengers typically consider multiple criteria when choosing between journeys.
Therefore, most algorithms Pareto-optimize at least two criteria: the arrival time and the number of used trips.
This increases the solution size and thereby slows down the algorithms even further.
For these reasons, a speedup technique that achieves very low query times with a moderate amount of precomputed data has remained elusive.

1.1
Related Work

For this work, we consider public transit journey planning algorithms that Pareto-optimize arrival time and number of trips.
For a more general overview, we refer to a survey by
[
3
]
.
Classical approaches model the public transit timetable as a graph and apply a multicriteria variant of Dijkstra’s algorithm
[
20
,
15
]
.
In the
time-dependent
graph model
[
9
,
21
]
, nodes represent stops in the network and edges are weighted with functions that map departure time to arrival time.
This yields a compact graph but requires a time-dependent version of Dijkstra’s algorithm.
By contrast, the
time-expanded
model
[
20
,
21
]
introduces nodes for each event in the timetable (e.g., a vehicle arriving at or departing from a stop).
Edges connect consecutive events of the same trip and events between which a transfer is possible.
This results in a larger graph, but Dijkstra’s algorithm can be applied directly.

Graph-based models can be combined with speedup techniques for Dijkstra’s algorithm.
A notable example is Arc-Flags
[
17
,
18
,
19
]
, which partitions the graph into cells and computes a boolean
flag
for each combination of edge and cell.
The flag indicates whether the edge is required to reach the cell.
Arc-Flags has been applied to both time-dependent
[
8
]
and time-expanded
[
12
]
graphs, although only the arrival time was optimized in the latter case.
However, this has only produced speedups of 3–4, compared to over 5 000
[
3
]
for road networks.

More recent algorithms do not model the timetable as a graph.
Instead, they use tailor-made data structures that allow for cache-efficient queries.
Notable examples are RAPTOR
[
13
]
and Trip-Based Routing (TB)
[
24
]
.
The latter employs a lightweight preprocessing phase that computes relevant transfers between pairs of trips.
This yields query times below 100 ms, even on large networks, significantly improving upon graph-based techniques.

Algorithms that offer query times in the sub-millisecond range do so by precomputing auxiliary data whose size is quadratic in the size of the network.
Public Transit Labeling (PTL)
[
11
]
adapts the ideas of Hub Labeling
[
10
]
to time-expanded graphs.
On metropolitan networks, PTL achieves query times of a few microseconds but requires tens of gigabytes of space.
Additional space in the hundreds of gigabytes would be required to support
journey unpacking
, i.e., retrieving full descriptions of the optimal journeys.
Transfer Patterns (TP)
[
2
]
is a technique that, in its most basic form, answers all possible queries during the preprocessing phase.
The journey descriptions are then condensed into
transfer patterns
, i.e., sequences of stops at which transfers between vehicles occur.
This yields a search graph for each possible source stop, which is explored during the query phase.
On the network of Germany, TP answers queries in less than 1 ms but requires hundreds of hours of preprocessing time and over 100 GB of space
[
4
]
.

To make the preprocessing phase more practical,
[
2
]
split the transfer patterns into global components between a small set of important
hub stations
and local components that lead to and from the hub stations.
This significantly reduces the memory consumption, but the preprocessing time is improved only when applying a heuristic that causes a small percentage of queries to be answered incorrectly.
A similar approach that answers all queries correctly is Scalable Transfer Patterns
[
4
]
, which employs graph clustering to split the patterns into local and global components.
However, when these are recombined during a query, the search space increases drastically.
Thus, the resulting query times are only barely competitive with TB.
Trip-Based Routing Using Condensed Search Trees (TB-CST)
[
25
]
re-engineers the ideas of TP with a faster, TB-based preprocessing algorithm.
To save space, shared suffixes are extracted from the search graphs and re-attached by the query algorithm.
TB-CST offers faster query times than TP on country-scale networks, although it is less successful on metropolitan areas.

1.2
Contribution

We present FLASH-TB (TB with FLAgged SHortcuts), a speedup technique for TB that exceeds the query performance of TP and TB-CST with a much smaller memory footprint.
Like those techniques, FLASH-TB answers all possible queries in advance, but it condenses the journey descriptions in a different manner.
Instead of computing transfer patterns, FLASH-TB stores and annotates the individual transfers.
The simplest variant stores a flag for every combination of transfer and target stop
p_{t}
that indicates whether the transfer is needed to reach
p_{t}
.
Because transfers connect events rather than stops, this approach retains fine-grained information that is lost in the transfer patterns.
The memory consumption can be reduced by leveraging Arc-Flags: the stops are partitioned into
k
cells and a combined flag is stored for each pair of transfer and target cell.
Thus, FLASH-TB is conceptually simpler than previous space-saving techniques for TP.
Furthermore, because
k
is configurable, it offers a tradeoff between query performance and space consumption.

Our approach is similar to applying Arc-Flags to the time-expanded graph, but there are crucial differences that allow it to overcome the issues observed by
[
12
]
.
In particular, we observe that the low speedups that were previously reported are caused by a conflict between different pruning rules in the preprocessing and query phases.
We resolve this conflict with a redesigned preprocessing step and show that this vastly reduces the search space.
We perform an experimental evaluation on four real-world datasets representing metropolitan and country-scale public transit networks.
With less than 1 GB of precomputed data, FLASH-TB achieves query times of 500
\mu s
on the network of Germany and well below 100
\mu s
on smaller country-scale networks.
This corresponds to a speedup of two orders of magnitude over TB.
The metropolitan network of Paris requires 8 GB to achieve a similar speedup.
When allowed to use as much space as TB-CST, FLASH-TB is faster by a factor of two to nine.

2.1
Public Transit Network

A
public transit network
is a 5-tuple
(\mathcal{S},\mathcal{E},\mathcal{T},\mathcal{L},\mathcal{F})
consisting of a set of stops
\mathcal{S}
, a set of stop events
\mathcal{E}
, a set of trips
\mathcal{T}
, a set of lines
\mathcal{L}
, and a set of footpaths
\mathcal{F}\subseteq\mathcal{S}\times\mathcal{S}
.
A
stop

p\in\mathcal{S}
is a location visited by a vehicle at which passengers can embark or disembark.
A
stop event

\varepsilon\in\mathcal{E}
represents a visit of a vehicle at the stop
p(\varepsilon)\in\mathcal{S}
with the arrival time
\uptau_{\mathrm{arr}}(\varepsilon)
and the departure time
\uptau_{\mathrm{dep}}(\varepsilon)\geq\uptau_{\mathrm{arr}}(\varepsilon)
.
A
trip
is a sequence
T=\left<\varepsilon_{0},\varepsilon_{1},\dots\right>
of stop events performed by the same vehicle.
We denote the
i
-th stop event of
T
as
T[i]
and the number of stop events in
T
as
\left|T\right|
.
The
stop sequence
of
T
is given by
\left<p(\varepsilon_{0}),p(\varepsilon_{1}),\dots\right>
.
We say that a trip
T_{a}

overtakes
another trip
T_{b}
with the same stop sequence if
\uptau_{\mathrm{arr}}(T_{a}[0])\geq\uptau_{\mathrm{arr}}(T_{b}[0])
and if there is an index
i
such that
\uptau_{\mathrm{arr}}(T_{a}[i])\leq\uptau_{\mathrm{arr}}(T_{b}[i])
or
\uptau_{\mathrm{dep}}(T_{a}[i])\leq\uptau_{\mathrm{dep}}(T_{b}[i])
.
A line
L\in\mathcal{L}
is a set of trips with the same stop sequence such that no trip overtakes another.
Every trip
T
is included in exactly one line, which is denoted by
L(T)
.
We define a total order on trips
T_{a},T_{b}
of the same line
L(T_{a})=L(T_{b})
:

\displaystyle T_{a}\prec T_{b}

\displaystyle\iff\uptau_{\mathrm{arr}}(T_{a}[0])<\uptau_{\mathrm{arr}}(T_{b}[0]),

\displaystyle T_{a}\preceq T_{b}

\displaystyle\iff T_{a}=T_{b}\lor T_{a}\prec T_{b}.

If
T_{a}\prec T_{b}
, it follows from the non-overtaking property that
\uptau_{\mathrm{arr}}(T_{a}[i])<\uptau_{\mathrm{arr}}(T_{b}[i])
and
\uptau_{\mathrm{dep}}(T_{a}[i])<\uptau_{\mathrm{dep}}(T_{b}[i])
for
0\leq i<\left|T\right|
.
Furthermore, if two trips with the same stop sequence have the same arrival or departure time at any point along the sequence, our definition of overtaking forces them to be in different lines.
For a trip
T
, its predecessor according to
\prec
is denoted by
\mathrm{pred}\left(T\right)
.
If
T
is the first trip of its line, we write
\mathrm{pred}\left(T\right)=\bot
.
A partial order of stop events
T_{a}[i],T_{b}[j]
is given by

\displaystyle T_{a}[i]\preceq T_{b}[j]

\displaystyle\iff L(T_{a})=L(T_{b})\land T_{a}\preceq T_{b}\land i\leq j,

\displaystyle T_{a}[i]\prec T_{b}[j]

\displaystyle\iff T_{a}[i]\preceq T_{b}[j]\land(T_{a}\prec T_{b}\lor i<j).

A
footpath

(p,q)\in\mathcal{F}
allows passengers to transfer between stops
p
and
q
, which requires the time
\Delta\uptau_{\mathrm{fp}}(p,q)
.
If no footpath between
p
and
q
exists, we define
\Delta\uptau_{\mathrm{fp}}(p,q)=\infty
.
For each stop
p\in\mathcal{S}
, we require that a footpath
(p,p)\in\mathcal{F}
exists with
\Delta\uptau_{\mathrm{fp}}(p,p)=0
; we call this an
empty
footpath.
We require that the set of footpaths is transitively closed and fulfills the triangle inequality, i.e., if there are stops
p,q,r\in\mathcal{S}
with
(p,q)\in\mathcal{F}
and
(q,r)\in\mathcal{F}
, then there must be a footpath
(p,r)\in\mathcal{F}
with
\Delta\uptau_{\mathrm{fp}}(p,r)\leq\Delta\uptau_{\mathrm{fp}}(p,q)+\Delta\uptau_{\mathrm{fp}}(q,r)
.

2.2
Journeys

A
trip segment

T[i,j]
is the subsequence of the trip
T
between the two stop events
T[i]
and
T[j]
.
A
transfer
is a tuple
(T_{a}[i],T_{b}[j])\in\mathcal{E}\times\mathcal{E}
with
\uptau_{\mathrm{arr}}(T_{a}[i])+\Delta\uptau_{\mathrm{fp}}(p(T_{a}[i]),p(T_{b}[j]))\leq\uptau_{\mathrm{dep}}(T_{b}[j])
.
It represents a passenger changing from trip
T_{a}
to
T_{b}
at the respective stop events.
For a source stop
p_{s}
and target stop
p_{t}
, a
p_{s}
-
p_{t}
-
journey

J=\left<f_{0},T_{1}[i_{1},j_{1}],\dots,T_{k}[i_{k},j_{k}],f_{k+1}\right>
is a sequence of trip segments such that a transfer connects every pair of consecutive trip segments.
In addition, the journey contains the
initial footpath

f_{0}=(p_{s},p(T_{1}[i_{1}]))\in\mathcal{F}
, which connects
p_{s}
to the first trip, and the
final footpath

f_{k+1}=(p(T_{k}[j_{k}]),p_{t})\in\mathcal{F}
connecting the last trip to
p_{t}
.
For the sake of brevity, we omit empty footpaths from the notation.
We denote the source stop of
J
by
p_{s}(J)
and the target stop by
p_{t}(J)
.
The number of trips used by
J
is denoted as
\left|J\right|=k
.
The arrival time of
J
at
p_{t}
is given by
\uptau_{\mathrm{arr}}(J)=\uptau_{\mathrm{arr}}(T_{k}[j_{k}])+\Delta\uptau_{\mathrm{fp}}(p(T_{k}[j_{k}]),p_{t})
.
The
departure time
of
J
is the latest possible departure time at
p_{s}
such that
T_{1}
can still be entered, i.e.,
\uptau_{\mathrm{dep}}(J)=\uptau_{\mathrm{dep}}(T_{1}[i_{1}])-\Delta\uptau_{\mathrm{fp}}(p_{s},p(T_{1}[i_{1}]))
.

The
stop sequence

\mathcal{S}(J)
of
J
is obtained by removing every stop from the sequence
\widetilde{\mathcal{S}}(J)=\left<p_{s},p(T_{1}[i_{1}]),p(T_{1}[j_{1}]),\dots,p(T_{k}[i_{k}]),p(T_{k}[j_{k}]),p_{t}\right>
that is identical to its predecessor.
For two stops
p,q\in\mathcal{S}(J)
, the
subjourney

J[p,q]
is the
p
-
q
-journey whose trip segments form a subsequence of
J
.
A
partial journey

J_{p}=\left<f_{0},T_{1}[i_{1},j_{1}],\dots,T_{k}[i_{k},j_{k}],T_{k+1}[i_{k+1}]\right>
differs from a journey in that the final footpath is replaced by a transfer to the
target event

\varepsilon_{t}(J_{p})=T_{k+1}[i_{k+1}]
.
The trip
T_{k+1}
, which is entered but not exited, is still counted as a used trip, i.e.,
\left|J_{p}\right|=k+1
.

We define three types of
prefixes
of a journey
J=\left<f_{0},T_{1}[i_{1},j_{1}],\dots,T_{k}[i_{k},j_{k}],f_{k+1}\right>
:

•

For
0<\ell\leq k
, the
p_{s}
-
p(T_{\ell}[j_{\ell}])
-journey
\left<f_{0},T_{1}[i_{1},j_{1}],\dots,T_{\ell}[i_{\ell},j_{\ell}]\right>
is an
exit prefix
.

•

For
0\leq\ell<k
, the
p_{s}
-
p(T_{\ell+1}[i_{\ell+1}])
-journey
\left<f_{0},T_{1}[i_{1},j_{1}],\dots,T_{\ell}[i_{\ell},j_{\ell}],f_{\ell+1}\right>
with final footpath
f_{\ell+1}=(p(T_{\ell}[j_{\ell}]),p(T_{\ell+1}[i_{\ell+1}]))\in\mathcal{F}
is a
footpath prefix
.

•

For
0\leq\ell<k
, the partial journey
\left<f_{0},T_{1}[i_{1},j_{1}],\dots,T_{\ell}[i_{\ell},j_{\ell}],T_{\ell+1}[i_{\ell+1}]\right>
is called a
partial prefix
.

Exit and footpath prefixes are called
proper
prefixes to distinguish them from the partial prefix.

2.3
Journey Planning Problem

A
query

Q=(p_{s},p_{t},\uptau_{\mathrm{dep}})
consists of source and target stops
p_{s},p_{t}\in\mathcal{S}
and a departure time
\uptau_{\mathrm{dep}}
.
The set
\mathcal{J}(Q)
of
feasible journeys
for
Q
consists of all
p_{s}
-
p_{t}
-journeys
J
with
\uptau_{\mathrm{dep}}(J)\geq\uptau_{\mathrm{dep}}
.
A
partial query

Q_{p}=(p_{s},\varepsilon_{t},\uptau_{\mathrm{dep}})
has a target event
\varepsilon_{t}\in\mathcal{E}
instead of a target stop.
The set
\mathcal{J}_{p}(Q_{p})
of
feasible partial journeys
consists of all partial
p_{s}
-
\varepsilon_{t}^{\prime}
-journeys
J_{p}
with
\uptau_{\mathrm{dep}}(J_{p})\geq\uptau_{\mathrm{dep}}
and
\varepsilon_{t}^{\prime}\preceq\varepsilon_{t}
.

Let
\mathcal{J}
denote a set of feasible (partial) journeys.
A
cost function

c\colon\mathcal{J}\to\mathcal{C}
maps (partial) journeys to a
cost space

\mathcal{C}
.
A
(2D) cost system

C=((c_{1},\preceq_{1}),(c_{2},\preceq_{2}))
is formed by cost functions
c_{1}\colon\mathcal{J}\to\mathcal{C}_{1}
and
c_{2}\colon\mathcal{J}\to\mathcal{C}_{2}
with partial orders
\preceq_{1},\preceq_{2}
on
\mathcal{C}_{1}
and
\mathcal{C}_{2}
, respectively.
The
cost vector
of a (partial) journey
J
is the tuple
c(J)=(c_{1}(J),c_{2}(J))
in the 2D cost space
\mathcal{C}_{1}\times\mathcal{C}_{2}
.
We call
J
a
representative
of
c(J)
.
Two (partial) journeys
J,J^{\prime}
are
equivalent
if
c(J)=c(J^{\prime})
.
The
dominance relation
of
C
is a partial order on
\mathcal{C}_{1}\times\mathcal{C}_{2}
that is defined as follows for cost vectors
c=(c_{1},c_{2})
and
c^{\prime}=(c_{1}^{\prime},c_{2}^{\prime})
:

\displaystyle c\preceq c^{\prime}

\displaystyle\iff c_{1}\preceq_{1}c_{1}^{\prime}\land c_{2}\preceq_{2}c_{2}^{\prime},

\displaystyle c\prec c^{\prime}

\displaystyle\iff c\preceq c^{\prime}\land c\neq c^{\prime}.

We say that
c

weakly dominates

c^{\prime}
if
c\preceq c^{\prime}
and
c

strictly dominates

c^{\prime}
if
c\prec c^{\prime}
.
The dominance relation carries over to (partial) journeys: we say
J
weakly dominates
J^{\prime}
(
J\preceq J^{\prime}
) if
c(J)\preceq c(J^{\prime})
and
J
strictly dominates
J^{\prime}
(
J\prec J^{\prime}
) if
c(J)\prec c(J^{\prime})
.
A (partial) journey
J\in\mathcal{J}
and its cost vector
c(J)
are called
Pareto-optimal
if there is no (partial) journey
J^{\prime}\in\mathcal{J}
with
c(J^{\prime})\prec c(J)
.
The
Pareto set
(in the cost space) is the set of all cost vectors
c(J)
for
J\in\mathcal{J}
such that
c(J)
is Pareto-optimal.
A
representative set
is a subset of
\mathcal{J}
that consists of exactly one representative for every Pareto-optimal cost vector.
This set is not necessarily unique because there may be multiple representatives for the same cost vector.
Note that journeys with a non-empty final footpath may dominate journeys with an empty final footpath; this requires that the footpath set is transitively closed.

Unless otherwise noted, we use the cost system
C=((\uptau_{\mathrm{arr}},\leq),(\left|\cdot\right|,\leq))
to evaluate journeys and
C_{p}=((\varepsilon_{t},\preceq),(\left|\cdot\right|,\leq))
to evaluate partial journeys.
A journey is Pareto-optimal for a query
Q=(p_{s},p_{t},\uptau_{\mathrm{dep}})
if it is Pareto-optimal among the feasible journeys
\mathcal{J}(Q)
.
Likewise, a partial journey is Pareto-optimal for a partial query
Q_{p}=(p_{s},\varepsilon_{t},\uptau_{\mathrm{dep}})
if it is Pareto-optimal among the feasible partial journeys
\mathcal{J}_{p}(Q_{p})
.
We call
J

exit-optimal
for
Q
if every exit prefix
J^{\prime}
of
J
is Pareto-optimal for the query
(p_{s},p_{t}(J^{\prime}),\uptau_{\mathrm{dep}})
.
We call
J

prefix-optimal
if every proper prefix
J^{\prime}
is Pareto-optimal for
(p_{s},p_{t}(J^{\prime}),\uptau_{\mathrm{dep}})
and every partial prefix
J_{p}
for
(p_{s},\varepsilon_{t}(J_{p}),\uptau_{\mathrm{dep}})
.

We consider several variants of the
journey planning problem
in a public transit network
(\mathcal{S},\mathcal{E},\mathcal{T},\mathcal{L},\mathcal{F})
.
Given a query
Q=(p_{s},p_{t},\uptau_{\mathrm{dep}})
, the (one-to-one)
fixed departure time problem
asks for a Pareto set (according to
C
) and a representative set.
For the
profile problem
, we are given an interval
\left[\uptau_{1},\uptau_{2}\right],\,\uptau_{1}\leq\uptau_{2}
of possible departure times in addition to
p_{s}
and
p_{t}
.
Here, the objective is to find the union of the Pareto sets for each query
(p_{s},p_{t},\uptau)
with
\uptau\in\left[\uptau_{1},\uptau_{2}\right]
, as well as a representative for each Pareto-optimal cost vector.
In the
full-range profile problem
, the departure time interval spans the entire service duration of the network.
In an
one-to-all query
, no target stop is given.
Instead, the objective is to solve the fixed departure time or profile problem for every possible target stop
p_{t}\in\mathcal{S}
.
Finally, an
all-to-all query
asks for a solution to the journey planning problem for each possible pair of source and target stops.

2.4
Graph

A directed, weighted graph
G=(V,E,c)
consists of a set of nodes
V
, a set of edges
E\subseteq V\times V
, and an edge weight function
c:E\to\mathbb{R}
.
A
path

P=\left<v_{1},v_{2},\dots,v_{k}\right>
is a sequence of nodes between
v_{1}
and
v_{k}
such that an edge connects each pair of consecutive nodes.
The weight of a path is the sum of the weights of all edges in the path.
A path
P=\left<v_{s},\dots,v_{t}\right>
between a source node
v_{s}
and a target node
v_{t}
is called a
shortest path
if there is no path between
v_{s}
and
v_{t}
with a smaller weight.

Given a value
k\in\mathbb{N}
and a graph
G=\left(V,E,c\right)
, a (
k
-way
)
partition
of
G
is a function
r:V\to\left\{1,\dots,k\right\}
that partitions the node set
V
into
k

cells
.
The set of nodes in cell
i
is denoted as
V_{i}\coloneqq r^{-1}(i)
.
An edge
(u,v)\in E
is called a
cut edge
if
u
and
v
belong to different cells.
A node is called a
boundary node
if it is incident to a cut edge.
The partition is called
balanced
for an imbalance parameter
\varepsilon>0
if the size of each cell
V_{i}
is bounded by
\left|V_{i}\right|\leq\left(1+\varepsilon\right)\left\lceil\left|V\right|/k\right\rceil
.
The
graph partitioning problem
asks for a balanced partition that minimizes the weighted sum of all cut edges.

3
Basic Algorithms

In this section, we discuss the algorithms upon which our work is based.
We outline the basic TB algorithm in Section
3.1
, extensions for profile and one-to-all search in Section
3.2
, the TB-CST speedup technique in Section
3.3
, and Arc-Flags in Section
3.4
.

3.1
Trip-Based Routing

The TB
[
24
]
algorithm is split into two phases: a precomputation step generates a set
\mathfrak{T}\subseteq\mathcal{E}\times\mathcal{E}
of transfers between stop events, which is used in the query phase.

Transfer Precomputation.

The preprocessing step begins by generating possible transfers between pairs of stop events.
Then, pruning rules are applied to discard some transfers that are not required to answer queries.
These pruning rules are not exhaustive, so
\mathfrak{T}
may still contain transfers that do not occur in any Pareto-optimal journey.
The generation step creates all transfers
\mathfrak{t}=(T_{a}[i],T_{b}[j])
with
i>0
,
j<\left|T_{b}\right|-1
and
T_{a}[i]\not\preceq T_{b}[j]
such that
T_{b}
is the earliest trip of its line that can be entered at
p(T_{b}[j])
when arriving at
\uptau_{\mathrm{arr}}(T_{a}[i])+\Delta\uptau_{\mathrm{fp}}(p(T_{a}[i]),p(T_{b}[j]))
.
The
U-turn
reduction rule removes a transfer
\mathfrak{t}=(T_{a}[i],T_{b}[j])
if
p(T_{a}[i-1])=p(T_{b}[j+1])
and
\uptau_{\mathrm{arr}}(T_{a}[i-1])\leq\uptau_{\mathrm{arr}}(T_{b}[j+1])
.
A second reduction rule, which we call the
latest-exit
rule, removes transfers that can be replaced with another transfer from the same trip.
For every journey of the form
J=\left<T_{a}[k,i],T_{b}[j,\ell]\right>
that uses the transfer
\mathfrak{t}
, the algorithm checks whether there is a journey of the form
J^{\prime}=\left<T_{a}[k,i^{\prime}],T_{c}[j^{\prime},\ell^{\prime}],f\right>
with
i<i^{\prime}
,
f=(p(T_{c}[\ell^{\prime}]),p(T_{b}[\ell]))
and
J^{\prime}\preceq J
.
Note that
J^{\prime}
is required to start with the same trip as
J
and must exit it at a later stop event.
This means that many possible journeys that might dominate
J
are not considered.

3.2
TB Extensions

Profile Search.

Profile-TB extends TB to solve the profile problem.
It collects all possible departure times at
p_{s}
within the departure time interval
[\uptau_{1},\uptau_{2}]
and processes them in descending order.
A departure time
\uptau_{\mathrm{dep}}
is possible if there is a stop event
T[i]
such that
\uptau_{\mathrm{dep}}+\Delta\uptau_{\mathrm{fp}}(p_{s},p(T[i]))=\uptau_{\mathrm{dep}}(p[i])
.
For each departure time, a run of the TB query algorithm is performed.
All data structures, including reached indices, are not reset between runs.
This exploits the fact that journeys found in a run with departure time
\uptau_{\mathrm{dep}}
are still feasible for all departure times before
\uptau_{\mathrm{dep}}
, so they can be used to prune suboptimal results in subsequent runs.
This principle is called
self-pruning
.
To obtain correct results, the definition of reached indices must be modified slightly.
For each trip
T
and each number of trips
n
, the algorithm now maintains a reached index
R_{n}(T)
, which is the index of the first stop event in
T
that was reached with
n
or fewer trips.
Whenever
R_{n}(T)
is updated to
\min(R_{n}(T),k)
for some value
k
, the same is done for the reached indices
R_{m}(T)
with
m\geq n
.

One-to-All Search.

A one-to-all extension of Profile-TB was briefly outlined by
[
25
]
.
The same extension can also be applied to the original TB algorithm for fixed departure time queries.
We give a more detailed description.
The earliest arrival time
\uptau_{\textsf{min}}
and the Pareto set
\mathcal{P}
are replaced with an earliest arrival time
\uptau_{\mathrm{arr}}(p,n)
for each stop
p
and number of trips
n
.
The Pareto set of journeys with target stop
p
is represented implicitly: the cost vector
(\uptau_{\mathrm{arr}}(p,n),n)
is Pareto-optimal if
\uptau_{\mathrm{arr}}(p,n)<\uptau_{\mathrm{arr}}(p,n-1)
, where we define
\uptau_{\mathrm{arr}}(p,-1)=\infty
for the sake of simplicity.
To unpack the journeys, the algorithm stores a trip segment pointer and exit index along with each earliest arrival time
\uptau_{\mathrm{arr}}(p,n)
, in the same manner as the one-to-one algorithm.
As with the reached indices, the profile query does not reset the earliest arrival times between runs.

The trip scanning operation for a round
n
(cf. Algorithm
1
) is modified as follows:
When a stop event
T[k]
is scanned during the first loop, the algorithm iterates over all stops
p
with
\Delta\uptau_{\mathrm{fp}}(p(T[k]),p)<\infty
and computes the arrival time
\overline{\uptau_{\mathrm{arr}}}=\uptau_{\mathrm{arr}}(T[k])+\Delta\uptau_{\mathrm{fp}}(p(T[k]),p)
at
p
.
If
\overline{\uptau_{\mathrm{arr}}}<\uptau_{\mathrm{arr}}(p,n)
, then
\uptau_{\mathrm{arr}}(p,m)
is set to
\min(\overline{\uptau_{\mathrm{arr}}},\uptau_{\mathrm{arr}}(p,m))
for all
m\geq{}n
.
The target pruning rule, which is no longer applicable, is replaced with a
local pruning
rule:
When a stop event
T[k]
is scanned during the second loop, the algorithm checks whether
\uptau_{\mathrm{arr}}(T[k])>\uptau_{\mathrm{arr}}(p(T[k]),n)
.
If so, the outgoing transfers of
T[k]
are not scanned.
Similar rules are also employed in other algorithms, such as RAPTOR
[
13
]
.

3.3
Condensed Search Trees

Trip-Based Routing Using Condensed Search Trees (TB-CST)
[
25
]
uses TB to precompute search graphs in a similar manner to TP.
The preprocessing phase solves the all-to-all full-range profile problem by running one-to-all Profile-TB from every stop.
Consider the Profile-TB search for a source stop
p_{s}
.
After each TB run, all newly found representative journeys are unpacked.
This yields a breadth-first search tree with
p_{s}
as the root, trip segments as inner nodes, the reached target stops as leaves, and footpaths and transfers as edges.
The search trees of all runs are combined into the
prefix tree
of
p_{s}
.
Here, each trip segment
T[i,j]
is replaced with a tuple
(L(T),i)
consisting of the corresponding line
L(T)
and the stop index
i
where the line is entered.

To answer a query
(p_{s},p_{t},\uptau_{\mathrm{dep}})
, TB-CST builds a
query graph
from the prefix tree of
p_{s}
by extracting all paths that lead to a leaf representing
p_{t}
.
Then a variant of Dijkstra’s algorithm is run on the query graph.
Because the prefix tree only provides information about lines, the used trips are reconstructed during the query.
When exploring an edge from
p_{s}
to a tuple
(L,i)
, the algorithm computes the earliest trip of
L
that can be entered at the
i
-th stop.
When exploring an edge between tuples
(L,i)
and
(L^{\prime},j)
, the used trip
T
of
L
is already known, so the algorithm scans the outgoing transfers of
T[i]
in
\mathfrak{T}
to find the earliest reachable trip
T^{\prime}
of
L^{\prime}
.

The space required to store all prefix trees can be reduced by extracting
postfix trees
.
Consider the prefix tree for a source stop
p_{s}
.
For each path from the root to a leaf representing a target stop
p_{t}
, a
cut node
is chosen.
The subpath from the cut node to the leaf is then removed from the prefix tree of
p_{s}
and added to the postfix tree of
p_{t}
.
Because many of these extracted subpaths occur in multiple prefix trees, moving them into a shared postfix tree considerably reduces memory consumption.
To construct the query graph for a source stop
p_{s}
and target stop
p_{t}
, the prefix tree
p_{s}
and the postfix tree of
p_{t}
are spliced back together at the cut nodes.

3.4
Arc-Flags

Arc-Flags
[
17
,
18
,
19
]
is a speedup technique for Dijkstra’s algorithm in road networks.
Given a weighted graph
G=\left(V,E,c\right)
, the preprocessing phase of Arc-Flags performs two steps:
First, it computes a partition
r:V\to\{1,\dots,k\}
of the node set into
k
cells, where
k
is a freely chosen parameter.
Then, a
flags function

b:E\times\left\{1,\dots,k\right\}\to\left\{0,1\right\}
is computed.
For an edge
e
and a cell
i
, the value
b(e,i)
is called a
flag
, and we say that
e
is
flagged
for cell
i
if
b(e,i)=1
.
The flags function must have the following property: for each pair of source node
v_{s}
and target node
v_{t}
, there is at least one shortest path
P
from
v_{s}
to
v_{t}
such that every edge
e
along
P
is flagged for the cell
r(v_{t})
containing the target node.
With this precomputed information, a shortest path query between
v_{s}
and
v_{t}
can be answered by running Dijkstra’s algorithm but only scanning edges that are flagged for
r(v_{t})
.
The parameter
k
imposes a tradeoff between query speed and memory consumption.
The space required to store the flags is in
\Theta\left(k\left|E\right|\right)
, which is manageable for
k\ll\left|V\right|
.
On the other hand, the search space of the query decreases for larger values of
k
because fewer edges will be flagged if the target cell is smaller.

Flags can be computed naively by computing a shortest-path tree from every node.
This can be improved by exploiting the observation that every shortest path that leads into a cell
i
must pass through a boundary node of
i
.
Thus, it is sufficient to compute backward shortest-path trees from all boundary nodes.
For more details, we refer to
[
17
]
.

4
Precomputing Auxiliary Data with TB

TB-CST precomputes its auxiliary data by solving the all-to-all full-range profile problem with Profile-TB.
Our own approach, which we present in Section
5
, uses the same precomputation scheme but extracts a different set of data from the computed journeys.
In this section, we discuss challenges that arise when using Profile-TB for this computation and how they can be overcome.

4.1
Issues

If one-to-all TB with local pruning (see Section
3.2
) is combined with the original TB transfer precomputation, it may answer some queries incorrectly.
This is because local pruning is incompatible with the latest-exit reduction rule employed by the preprocessing.
Local pruning ensures that the journeys found by one-to-all TB are exit-optimal, i.e., a trip is only exited if the resulting arrival time at the stop is optimal.
By contrast, the latest-exit rule prefers journeys that exit a trip at the latest possible stop.
As shown in Figure
1
, these two choices can conflict.
In this example, exiting the trip
T_{a}
at
T_{a}[1]
and walking to
p(T_{a}[2])
is faster than exiting at
T_{a}[2]
.
Therefore, local pruning prevents the transfer
(T_{a}[2],T_{b}[0])
from being scanned.
However, the latest-exit rule discards the transfer
(T_{a}[1],T_{b}[0])
in favor of
(T_{a}[2],T_{b}[0])
.
As a result, one-to-all TB will not find any journeys from
p(T_{a}[0])
to
p(T_{b}[1])
.
A similar issue can also occur in circle lines that visit the same stop twice.
Due to local pruning, transfers will only be scanned for the first visit.
However, the latest-exit rule will only keep the outgoing transfers for the second visit.
Note that this issue does not occur in one-to-one variants of TB, which do not use local pruning.
The TB-CST preprocessing as originally implemented by
[
24
]
also avoids this issue because it does not apply local pruning.

4.2
Property-Preserving Transfer Sets

Both issues are caused by the fact that the different phases of the algorithm make inconsistent choices between representatives of the same cost vector.
Although this can be avoided by disabling certain pruning rules, doing so increases the query search space.
Instead, we modify the transfer generation and profile search phases to make them compatible with each other and the query phase.

To formalize the notion of compatibility, we study whether a transfer set preserves certain journey properties.
For a transfer set
\mathfrak{T}\subseteq\mathcal{E}\times\mathcal{E}
and a query
Q
, let
\mathcal{J}(Q,\mathfrak{T})\subseteq\mathcal{J}(Q)
denote the set of feasible journeys whose transfers are all included in
\mathfrak{T}
.
Let
X
denote a property of journeys, such as exit optimality.
The transfer set
\mathfrak{T}
is called
X
-preserving
for
Q
if there exists a representative set
\mathcal{J}_{R}
for
Q
such that every journey
J\in\mathcal{J}_{R}
has the property
X
and is contained in
\mathcal{J}(Q,\mathfrak{T})
.
If
\mathfrak{T}
is
X
-preserving for all possible queries, we simply call it
X
-preserving overall.

We show that one-to-all TB with local pruning is correct when using an exit-optimality-preserving (EOP) transfer set.
Note that while the set of all possible transfers is EOP, it is extremely large and will lead to slow queries.
In Section
4.3
, we present an algorithm that computes a sufficiently small EOP transfer set.
First, we show that for each Pareto-optimal cost vector, there is an exit-optimal representative whose stop events are all scanned by the search.
Note that this is not necessarily the journey returned by the algorithm.

Lemma 1
.

Let
\mathfrak{T}
be a transfer set and
J=\left<f_{0},T_{1}[i_{1},j_{1}],\dots,T_{k}[i_{k},j_{k}],f_{k+1}\right>\in\mathcal{J}(Q,\mathfrak{T})
an exit-optimal journey for a query
Q=(p_{s},p_{t},\uptau_{\mathrm{dep}})

4.3
Transitive ULTRA

An alternative transfer generation algorithm for TB was previously presented in the context of multimodal journey planning.
Here, the transitively closed set of footpaths is replaced with an unrestricted
transfer graph
that may represent one or several road-based transportation modes.
ULTRA (UnLimited TRAnsfers)
[
7
]
is a technique that enables TB to handle multimodal networks by condensing the transfer graph into a set of edges between pairs of stop events, i.e., a transfer set.
The method for generating this transfer set is substantially different from the TB transfer precomputation and does not employ the latest-exit rule.
We propose Trans-ULTRA, a variant of ULTRA for transitively closed footpaths.
We show that the computed transfer set preserves a journey property called canonicity, which is stronger than exit optimality.
Because Trans-ULTRA is identical to ULTRA expect for minor differences in the exploration of footpaths, we only give details that are necessary to prove the canonicity-preserving property.
For a full overview of ULTRA, including algorithmic details and the original proofs, we refer to
[
7
]
.

Canonical Journeys.

We call a journey with exactly two trips and empty initial and final footpaths a
candidate
.
For example, the candidates contained in the journey
J=\left<f_{0},T_{1}[i_{1},j_{1}],\dots,T_{k}[i_{k},j_{k}],f_{k+1}\right>
are
\left<T_{\ell}[i_{\ell},j_{\ell}],T_{\ell+1}[i_{\ell+1},j_{\ell+1}]\right>
for
1\leq\ell<k
.
ULTRA exploits the observation that a set of transfers that is sufficient for answering all queries can be found by only inspecting candidates.
Formally, the set of transfers that occur in at least one Pareto-optimal candidate is Pareto-optimality-preserving.
However, this set is unnecessarily large: it covers all Pareto-optimal journeys, but one representative for every Pareto-optimal cost vector is sufficient.

To choose the representative, ULTRA defines a unique
tiebreaking sequence
for each journey.
For Trans-ULTRA, we modify this sequence slightly to account for the fact that footpaths consist of single edges.
Let
\text{id}_{\mathcal{L}}:\mathcal{L}\to\mathbb{N}
and
\text{id}_{\mathcal{S}}:\mathcal{S}\to\mathbb{N}
be total orderings on the sets of lines and stops.
Let
\text{id}_{\mathcal{E}}\colon\mathcal{E}\to\mathbb{N}
be a total ordering of the stop events such that
\text{id}_{\mathcal{E}}(T[i])<\text{id}_{\mathcal{E}}(T^{\prime}[j])
if and only if
\langle\text{id}_{\mathcal{L}}(L(T)),\uptau_{\mathrm{arr}}(T[0]),i\rangle<\langle\text{id}_{\mathcal{L}}(L(T^{\prime})),\uptau_{\mathrm{arr}}(T^{\prime}[0]),j\rangle
.
Note that this ordering is consistent with the partial order
\prec
on stop events, i.e.,
L(T)=L(T^{\prime})
and
T[i]\prec T^{\prime}[j]
implies
\text{id}_{\mathcal{E}}(T[i])<\text{id}_{\mathcal{E}}(T^{\prime}[j])
.

For a journey
J=\langle f_{0},\dots,T[i,j],(p,q)\rangle
, the
tiebreakers
are given by

X_{b}(J):=\begin{cases}\langle\text{id}_{\mathcal{E}}(T[i]),\mathmakebox[0pt][l]{\infty}\hphantom{\text{id}_{\mathcal{E}}(T[j])}\rangle&\text{if }p=q,\\
\langle\mathmakebox[0pt][l]{\infty}\hphantom{\text{id}_{\mathcal{E}}(T[i])},\text{id}_{\mathcal{E}}(T[j])\rangle&\text{otherwise.}\\
\end{cases}

The
local tiebreaking sequence

X_{\ell}(J):=\langle\uptau_{\mathrm{arr}}(J)\rangle\circ X_{b}(J)
consists of the arrival time followed by the tiebreakers.
The global tiebreaking sequence of a journey
J
with stop sequence
\mathcal{S}(J)=\langle p_{1},\dots,p_{k}\rangle
concatenates the local tiebreaking sequences in reverse order:

X(J):=X_{\ell}(J[p_{1},p_{k}])\circ\dots\circ X_{\ell}(J[p_{1},p_{2}]).

Sequences are compared via the lexicographical order
\leq_{\text{lex}}
.
If one sequence is shorter than the other, it is padded by adding entries with value
-\infty
at the end.
A journey
J
is called
canonical
for a query
Q
if it is Pareto-optimal under the cost system
C_{X}=((X,\leq_{\text{lex}}),(\left|\cdot\right|,\leq))
.
Because the tiebreaking sequences of all feasible journeys for
Q
are unique and totally ordered, no two journeys are equivalent under
C_{X}
.
Accordingly, the only representative set for the query is the
canonical representative set
, which consists solely of canonical journeys.
Because adding a common prefix or suffix to two journeys does not change the relative order of their tiebreaking sequences, the set of canonical journeys is closed under subjourney decomposition: if a journey
J
is canonical for some query
Q
, then every subjourney
J[p,q]
of
J
is canonical for the query
Q^{\prime}=(p,q,\uptau_{\mathrm{dep}}(J[p,q]))
.
Hence, the set of transfers that occur in at least one canonical candidate is canonicity-preserving (CP).
Furthermore, Lemma
4
shows that canonical journeys are prefix-optimal and therefore also exit-optimal.
Hence, the set is EOP and can be used for one-to-all-TB by Theorem
2
.

Lemma 4
.

Every canonical journey
J
for a query
Q
is prefix-optimal for
Q
.

Proof.

Let
\mathcal{S}(J)=\langle p_{1},\dots,p_{k}\rangle
be the stop sequence of
J
.
For each proper prefix
J[p_{1},p_{n}]
, the local tiebreaking sequence
X_{\ell}(J[p_{1},p_{n}])
begins with
\uptau_{\mathrm{arr}}(J[p_{1},p_{n}])
, so
J[p_{1},p_{n}]
is Pareto-optimal under
C
.
Let
T[i,j]
denote the last trip segment of
J[p_{1},p_{n}]
.
Assume that the partial prefix of
J
that ends with
T[i]
is not Pareto-optimal under
C_{p}
.
Because
J[p_{1},p_{n}]
is Pareto-optimal, there must be a journey
J^{\prime}[p_{1},p_{n}]
with
c(J^{\prime}[p_{1},p_{n}])=c(J[p_{1},p_{n}])
that ends with a trip segment
T^{\prime}[i^{\prime},j]
such that
T^{\prime}[i^{\prime}]\prec T[i]
.
Because trips of the same line do not overtake each other, this requires that
T^{\prime}=T
and
i^{\prime}<i
and therefore
\text{id}_{\mathcal{E}}(T^{\prime}[i^{\prime}])<\text{id}_{\mathcal{E}}(T[i])
.
However, then it follows that
X_{b}(J^{\prime}[p_{1},p_{n}])<X_{b}(J[p_{1},p_{n}])
, which contradicts the fact that
J
is canonical.
∎

Canonical representative sets can be computed with a slight modification of RAPTOR
[
13
]
called
canonical RAPTOR
.
Like TB, RAPTOR operates in rounds.
Each round first explores the outgoing lines and then the outgoing footpaths of previously reached stops.
To ensure that canonical journeys are found, canonical RAPTOR makes two modifications:
The collected lines are sorted according to
\text{id}_{\mathcal{L}}
before they are explored.
For each stop
p
reached directly via a trip, the algorithm maintains the stop event
\varepsilon(p)
at which the trip was exited.
The collected stops are then sorted according to
\text{id}_{\mathcal{E}}(\varepsilon(p))
before their outgoing footpaths are explored.

Departure-Canonical Journeys.

Enumerating all canonical candidates requires solving the all-to-all full-range profile problem, restricted to journeys with at most two trips.
Trans-ULTRA does this with rRAPTOR, an extension of RAPTOR for profile queries.
In the same manner as Profile-TB, rRAPTOR performs a canonical RAPTOR run for each possible departure time in decreasing order.
Because candidates have two trips, each run can be stopped after two rounds.
As we saw in Section
4.1
, the self-pruning rule cannot be applied directly because it conflicts with exit optimality.

This issue can be solved by relaxing the notions of both canonicity and self-pruning.
The local tiebreaking sequence of a journey
J
is replaced with the
local departure tiebreaking sequence

X_{\ell}^{\mathrm{dep}}(J):=\langle\uptau_{\mathrm{arr}}(J),\uptau_{\mathrm{dep}}(J)\rangle\circ X_{b}(J)
.
For two journeys
J_{1}
and
J_{2}
, we denote by
J_{1}\cap_{s}J_{2}
the longest proper suffix of
J_{1}
that is also a proper suffix of
J_{2}
.
The longest proper prefix of
J_{1}
that excludes
J_{1}\cap_{s}J_{2}
is denoted by
J_{1}\setminus_{s}J_{2}
.
We define the
departure-canonical total order

\prec_{\text{dep}}
on journeys as follows:

J_{1}\prec_{\text{dep}}J_{2}
if and only if
X_{\ell}^{\mathrm{dep}}(J_{1}\setminus_{s}J_{2})<X_{\ell}^{\mathrm{dep}}(J_{2}\setminus_{s}J_{1})
.
A proof that
\prec_{\text{dep}}
is a strict total order is given in Appendix
A
.
The strictness follows from the fact that the only shared suffix of
J_{1}\setminus_{s}J_{2}
and
J_{2}\setminus_{s}J_{1}
is the empty journey.

We call
J

departure-canonical
for a query
Q
if it is Pareto-optimal under the cost system
C^{\prime}_{X}=((\text{id},\prec_{\text{dep}}),(\left|\cdot\right|,\leq))
, where
id
is the identity function.
Because
\prec_{\text{dep}}
is strict, the only representative set consists entirely of departure-canonical journeys; we call it the
departure-canonical representative set
.
Note that canonicity can be defined in an analogous way via a canonical total order
\prec_{\text{can}}
, where
J_{1}\prec_{\text{can}}J_{2}
if and only if
X_{\ell}(J_{1}\setminus_{s}J_{2})<X_{\ell}(J_{2}\setminus_{s}J_{1})
.
Then the cost system
(\text{id},\prec_{\text{can}})
is equivalent to
(X,\leq_{\text{lex}})
.
With this, it is easy to see that if
J
is canonical for
Q=(p_{s}(J),p_{t}(J),\uptau_{\mathrm{dep}}(J))
, it is also departure-canonical for
Q
because no journey in
\mathcal{J}(Q)
departs earlier than
J
.
The converse is not necessarily true.
Furthermore, we can show that the set containing all departure-canonical journeys for all possible queries is closed under subjourney decomposition:

Lemma 5
.

Let
J
be a departure-canonical journey for a query
Q=(p_{s},p_{t},\uptau_{\mathrm{dep}})
with stop sequence
\langle p_{s}=p_{1},p_{2},\dots,p_{k}=p_{t}\rangle
.
For every
1\leq i<j\leq k
, the subjourney
J_{ij}:=J[p_{i},p_{j}]
is departure-canonical for
Q_{ij}:=(p_{i},p_{j},\uptau_{\mathrm{dep}}(J[p_{i},p_{j}]))
.

Proof.

Assume that
J_{ij}
is not departure-canonical for
Q_{ij}
.
Then there is a journey
J^{\prime}_{ij}\in\mathcal{J}(Q_{ij})
with
J^{\prime}_{ij}\prec_{\text{dep}}J_{ij}
and
|J^{\prime}_{ij}|\leq|J_{ij}|
.
Let
i\leq x\leq j
be the index for which
J_{ij}\cap_{s}J^{\prime}_{ij}=J_{xj}
.
Then it follows that
J_{ij}\setminus_{s}J^{\prime}_{ij}=J_{ix}
.
We also denote
J^{\prime}_{ix}:=J^{\prime}_{ij}\setminus_{s}J_{ij}
.
For
1\leq n\leq i\leq x\leq m\leq k
, let
J^{\prime}_{nm}
denote the journey that is obtained by prepending
J_{ni}
to
J^{\prime}_{ix}
and appending
J_{xm}
.
By the definition of the departure-canonical total order,
J^{\prime}_{nm}\prec_{\text{dep}}J_{nm}
is equivalent to
X_{\ell}^{\mathrm{dep}}(J^{\prime}_{nx})<X_{\ell}^{\mathrm{dep}}(J_{nx})
.

We show that
J^{\prime}_{1k}\prec_{\text{dep}}J_{1k}=J
, which contradicts the departure canonicity of
J
.
To this end, we show that
X_{\ell}^{\mathrm{dep}}(J^{\prime}_{ix})<X_{\ell}^{\mathrm{dep}}(J_{ix})
implies
X_{\ell}^{\mathrm{dep}}(J^{\prime}_{1x})<X_{\ell}^{\mathrm{dep}}(J_{1x})
.
The local departure tiebreaking sequence consists of the arrival time, the departure time and the tiebreakers.
The arrival time and the tiebreakers depend only on the last trip segment, so it follows that

\displaystyle X_{\ell}^{\mathrm{dep}}(J^{\prime}_{1x})

\displaystyle=\langle(\uptau_{\mathrm{arr}}(J^{\prime}_{ix}),\uptau_{\mathrm{dep}}(J^{\prime}_{1x})\rangle\circ X_{b}(J^{\prime}_{ix})

\displaystyle X_{\ell}^{\mathrm{dep}}(J_{1x})

\displaystyle=\langle(\uptau_{\mathrm{arr}}(J_{ix}),\uptau_{\mathrm{dep}}(J_{1x})\rangle\circ X_{b}(J_{ix}).

We know that
X_{\ell}^{\mathrm{dep}}(J^{\prime}_{ix})<X_{\ell}^{\mathrm{dep}}(J_{ix})
holds.
If
\uptau_{\mathrm{arr}}(J^{\prime}_{ix})<\uptau_{\mathrm{arr}}(J_{ix})
holds, then
X_{\ell}^{\mathrm{dep}}(J^{\prime}_{1x})<X_{\ell}^{\mathrm{dep}}(J_{1x})
follows immediately.
Assume therefore that
\uptau_{\mathrm{arr}}(J^{\prime}_{ix})=\uptau_{\mathrm{arr}}(J_{ix})
.
It follows from
J^{\prime}_{ij}\in\mathcal{J}(Q_{ij})
that
\uptau_{\mathrm{dep}}(J^{\prime}_{ix})=\uptau_{\mathrm{dep}}(J^{\prime}_{ij})\geq\uptau_{\mathrm{dep}}(J_{ij})=\uptau_{\mathrm{dep}}(J_{ix})
.
Hence, the departure times must be equal and
X_{b}(J^{\prime}_{ix})<X_{b}(J_{ix})
must hold.
It remains to be shown that
\uptau_{\mathrm{dep}}(J_{1x})=\uptau_{\mathrm{dep}}(J^{\prime}_{1x})
.
If
i>1
, this is the case because both values are equal to
\uptau_{\mathrm{dep}}(J)
.
If
i=1
, then this is equivalent to
\uptau_{\mathrm{dep}}(J_{ix})=\uptau_{\mathrm{dep}}(J^{\prime}_{ix})
, which we have already shown.
∎

Departure-canonical rRAPTOR
is a modification of rRAPTOR that returns departure-canonical representatives.
Each RAPTOR run is done with canonical RAPTOR.
Additionally, the self-pruning rule is relaxed to ensure that it does not discard journeys that are dominated by equivalent journeys (under
C
) with a later departure time.
The run in which a journey
J
is found is the one for
\uptau_{\mathrm{dep}}(J)
.
Let
J^{\prime}
the journey with the earliest arrival time among those with at most
\left|J\right|
trips that were previously found at
p_{t}(J)
.
Usually, RAPTOR discards
J
if
J^{\prime}\preceq J
holds under
C
.
Otherwise,
J
replaces
J^{\prime}
.
Departure-canonical rRAPTOR instead discards
J
if
J^{\prime}\preceq J
holds under
C^{\prime}_{X}
.
This is the case if one of the two
ULTRA conditions
holds under
C
:

(U1)

J^{\prime}\preceq J
and
\uptau_{\mathrm{dep}}\left(J^{\prime}\right)=\uptau_{\mathrm{dep}}\left(J\right)
.

(U2)

J^{\prime}\prec J
.

With these conditions, we can show that each run of departure-canonical rRAPTOR returns the departure-canonical representative set:

Lemma 6
.

Let
J
be a departure-canonical journey for a query
Q=(p_{s},p_{t},\uptau_{\mathrm{dep}})
.
After the run for
\uptau_{\mathrm{dep}}
in the departure-canonical rRAPTOR search from
p_{s}
, the representative for
c(J)
at
p_{t}
is
J
.

Proof.

Note that the ULTRA conditions do not affect the computed cost vectors, only the parent pointers (and thereby the representative).
Hence, it follows from the correctness of canonical RAPTOR and rRAPTOR that departure-canonical rRAPTOR returns the Pareto set, which includes
c(J)
.
Let
J^{\prime}
be the corresponding representative found by departure-canonical rRAPTOR.
We show that
J^{\prime}=J
.
If
\uptau_{\mathrm{dep}}(J^{\prime})=\uptau_{\mathrm{dep}}(J)
, then it follows from the correctness of canonical RAPTOR that
J^{\prime}
is the journey with the smallest tiebreaking sequence among those in
\mathcal{J}(Q)
with cost vector
c(J)
and departure time
\uptau_{\mathrm{dep}}(J)
, which is
J
.
Assume therefore that
\uptau_{\mathrm{dep}}(J^{\prime})>\uptau_{\mathrm{dep}}(J)
.
We prove the claim by induction over the proper prefixes of
J
.
Because every proper prefix of
J
is departure-canonical by Lemma
5
, the algorithm returns it as a representative by the induction hypothesis.
We therefore know that the run for
\uptau_{\mathrm{dep}}(J)
finds
J
and compares it to
J^{\prime}
.
Condition (U1) is not fulfilled by our assumption that
\uptau_{\mathrm{dep}}(J^{\prime})>\uptau_{\mathrm{dep}}(J)
, whereas condition (U2) is not fulfilled because
J
is Pareto-optimal.
Hence,
J
is not discarded and replaces
J^{\prime}
, a contradiction.
∎

Trans-ULTRA.

Trans-ULTRA performs a departure-canonical rRAPTOR search from each possible source stop, restricted to the first two rounds.
For each candidate in this set, its transfer is added to the transfer set
\mathfrak{T}
.
We show that
\mathfrak{T}
is departure-canonicity-preserving (DCP).

Theorem 7
.

The transfer set
\mathfrak{T}
generated by Trans-ULTRA is DCP.

Proof.

Consider a departure-canonical representative
J=\left<T_{1}[i_{1},j_{1}],\dots,T_{k}[i_{k},j_{k}]\right>
for some query
Q
and, for each
1\leq n<k
, the candidate subjourney
J_{n}=\left<T_{n}[i_{n},j_{n}],T_{n+1}[i_{n+1},j_{n+1}]\right>
.
By Lemma
5
,
J_{n}
is departure-canonical for the query
(p_{s}(J_{n}),p_{t}(J_{n}),\uptau_{\mathrm{dep}}(J_{n}))
.
Hence, the transfer
(T_{n}[j_{n}],T_{n+1}[i_{n+1}])
is included in
\mathfrak{T}
by Lemma
6
.
∎

Because all canonical journeys are also departure-canonical, the transfer set is also CP.
Note that the proof of Theorem
7
only requires a weaker version of Lemma
6
: it is sufficient to find and unpack the departure-canonical representatives that are candidates.
ULTRA exploits this with several performance optimizations that prevent irrelevant non-candidate journeys from being explored
[
7
]
.
These optimizations carry over to Trans-ULTRA; see Appendix
B
.

4.4
Departure-Canonical Profile-TB

We now return to the task of precomputing auxiliary data to speed up TB.
The precomputation scheme is as follows:
Using the Trans-ULTRA transfer set, the all-to-all full-range profile problem is solved by running one-to-all Profile-TB from every source stop.
For every run and every target stop, the representative journeys are unpacked and the auxiliary data is computed from them.
It follows from Theorems
2
and
7
that this search produces correct Pareto sets in the cost space, but as outlined in Section
4.1
, the representatives are not necessarily compatible with the pruning rules of the query algorithm.
Therefore, we perform the profile searches with
DC-Profile-TB
, a variant of one-to-all Profile-TB that computes all departure-canonical representatives when it is used with a DCP transfer set (such as the one computed by Trans-ULTRA).

Whereas RAPTOR always finds prefix-optimal representatives, TB in its original form only guarantees exit optimality via the local pruning rule.
We add a new pruning rule to ensure that optimal footpath prefixes are selected.
Furthermore, although the reached index data structure ensures that the algorithm finds optimal partial prefixes, they are not necessarily selected during journey unpacking.
To change this, we redesign the parent pointers used for journey unpacking.
We also adjust the order in which trip segments, footpaths and transfers are scanned within each round to match the order given by the tiebreakers.
This ensures that each run finds the departure-canonical representative first and therefore discards all others.
Finally, we relax self-pruning by incorporating the ULTRA conditions.
Pseudocode for the modified parts is given in Algorithm
3
.

Relaxing-Self Pruning.

Like RAPTOR, one-to-all TB represents found journeys implicitly via the earliest arrival time
\uptau_{\mathrm{arr}}(p,n)
for each stop
p
and round
n
.
We incorporate the ULTRA conditions in the procedure
AddArrival
, which updates this value.
Unlike RAPTOR, TB also represents partial journeys implicitly via the reached index
R_{n}(T)
for each trip
T
and round
n
.
When this is updated in
Enqueue
, a version of the ULTRA conditions also needs to be incorporated.

We represent the run of a partial journey implicitly by maintaining a secondary reached index
R_{\mathrm{r}}(\cdot)
, which is reset after every run.
Consider a call to
Enqueue
for a stop event
T[j]
in round
n
.
Let
J
denote the corresponding partial journey up to
T[j]
.
Condition (U1) becomes condition (E1), which is evaluated in line
3
: if
R_{\mathrm{r}}\left(T\right)\leq j
, then the algorithm has already found a partial journey
J^{\prime}
with
J^{\prime}\preceq J
and
\uptau_{\mathrm{dep}}(J^{\prime})=\uptau_{\mathrm{dep}}(J)
.
Condition (U2) can be tested by evaluating the reached index
R_{n}\left(T\right)

Reordering the Trip Scanning Phase.

At the start of the trip scanning phase of round

Flag Representation.

For an edge
e

\langle b(e,1),\dots,b(e,k)\rangle
its

.

[
6
]

They exploit this with the following compression technique:
All flag patterns that occur in the graph are stored in a global array
A

For each edge
e

e
directly, but rather the index
i
for which

This saves space at the cost of additional pointer accesses whenever an edge is explored.
We apply this compression technique in FLASH-TB and sort the flag pattern array in decreasing order of occurrence.
This ensures that the most commonly accessed flag patterns are stored close together in memory, which increases the likelihood of cache hits.
If flag compression is not used, the flags are stored in an array
A
of size
k\left|\mathfrak{T}\right|
.
To improve cache efficiency, we store the flags for each cell consecutively.
Thus, the flag
b(\mathfrak{t},i)
for a transfer
\mathfrak{t}
and cell
i
is stored at position
A[i\left|\mathfrak{T}\right|+\mathfrak{t}]
.
This ensures that flags for irrelevant target cells do not occupy space in the cache.

Reached Index Timestamping.

Usually, TB resets the reached index of every trip
T
to
\left|T\right|
after each query.
However, the search space of FLASH-TB is so small that the vast majority of reached indices are not modified during a typical query.
To prevent unnecessary overhead, we store a 16-bit
timestamp

\eta(T)
for each trip
T
, which indicates last query in which
R(T)
was modified.
When
R(T)
is accessed during the
i
-th query and
\eta\left(T\right)\neq i
,
R(T)
is reset to
\left|T\right|
and
\eta(T)
is set to
i
.
Every
2^{16}
queries, the timestamp overflows, so all reached indices are reset.

6
Comparison with Other Algorithms

In this section, we outline the similarities and differences of FLASH-TB to other algorithms.
In particular, we explain why FLASH-TB reduces the search space compared to TP, TB-CST, and previous applications of Arc-Flags in public transit networks.

6.1
Transfer Patterns and TB-CST

Both TP and TB-CST (without split trees) store a generalized shortest-path tree for every possible source stop.
This offers a near-perfect reduction in the query search space but at the expense of a memory consumption of
\Omega(\left|\mathcal{S}\right|^{2})
.
By contrast, the memory consumption of FLASH-TB is in
\Theta\left(k\left|\mathfrak{T}\right|\right)
, where
k
is the number of cells.
Although
\left|\mathfrak{T}\right|
is theoretically in
\Omega(\left|\mathcal{E}\right|\left|\mathcal{T}\right|)
, it is comparable to
\left|\mathcal{E}\right|
in practice.
Thus, FLASH-TB can be seen as a way to interpolate between TB and TP regarding query search space and memory consumption.
For
k=1
, every non-superfluous transfer is flagged, so the search space is identical to that of TB with a filtered set of transfers.
For
k=\left|\mathcal{S}\right|
, only transfers that are part of a departure-canonical journey to the target stop are flagged.
An advantage of our approach is that the transfer flags provide information about which specific trips should be entered.
By contrast, the search graphs of TB-CST and TP only provide information about lines and stop sequences, respectively.
This means that FLASH-TB does not have to invest additional effort during the query phase to find the earliest reachable trip of each line.

6.2
Arc-Flags on Public Transit Networks

Conceptually, FLASH-TB is similar to Arc-Flags on a time-expanded graph, albeit with TB as a query algorithm instead of Dijkstra’s algorithm.

[
8
]
and
[
12
]
observe low speedups when applying Arc-Flags to public transit networks.
We analyze the issues causing this and how FLASH-TB overcomes them.

Issues with Existing Approaches.

[
8
]
apply Arc-Flags to a time-dependent graph model in a problem setting that asks for
all
Pareto-optimal paths, i.e., all representatives for every Pareto-optimal cost vector.
They observe that for nearly every combination of edge
e
and cell
i
, there is at least one point in time for which
e
occurs on a Pareto-optimal path to a node in cell
i
.
To solve this problem, the authors divide the service period of the network into two-hour intervals and compute a flag for each combination of edge, cell and time interval.
However, this merely yields a speedup of three over Dijkstra’s algorithm.

Time resolution is not an issue in the time-expanded graph, where each node is associated with a specific point in time.
Each stop event is modeled with three nodes: an
arrival node
, a
transfer node
and a
departure node
.
The edges in the graph can be divided into
trip edges
, which connect the arrival and departure nodes of the same trip, and
transfer edges
, which are incident to transfer nodes.
The transfer nodes of each stop are connected by a “chain” of transfer edges leading from earlier to later nodes.
An example is shown in Figure
4
.
A trip segment corresponds to a path between a departure node and an arrival node consisting only of trip edges.
By contrast, a transfer corresponds to a path of transfer edges between an arrival node and a departure node.

In principle, applying Arc-Flags to the time-expanded graph should yield much more fine-grained information than in the time-dependent model.
However,
[
12
]
still only report a speedup of four over Dijkstra’s algorithm, even when optimizing only the arrival time.
One reason for this is noted by the authors: in a time-expanded graph, every path is optimal because its arrival time depends only on the time of the target event.
To solve this problem, the authors employ strategies for breaking ties between paths.
Moreover, they propose a pruning technique called
node-blocking
, which applies the principle of line pruning to Dijkstra’s algorithm in time-expanded graphs.
They observe that node-blocking conflicts with their tiebreaking choices for Arc-Flags, leading to incorrectly answered queries.
Hence, they disable node-blocking when evaluating Arc-Flags, which increases the search space.

A second reason is that their approach computes flags that are sufficient to find a shortest path between any pair of nodes.
However, the public transit journey planning problem has two crucial differences to the shortest path problem in the time-expanded graph:
Firstly, the source node may only be a transfer node.
Secondly, no target node is supplied, only a target stop.
The actual target node is the earliest reachable transfer node of the target stop, which only becomes known during the search.
For these reasons, not every pair of source and target node occurs in an optimal journey.
Thus, the approach by Delling, Pajor, and Wagner flags more edges than necessary.

Improvements in FLASH-TB.

Arc-Flags on the time-expanded graph flags both trip and transfer edges, whereas FLASH-TB flags only transfers.
Flagging an entire TB transfer provides more information than flagging all the transfer edges it consists of.
Consider an example with four stop events
T_{1}[i_{1}],T_{2}[i_{2}],T_{3}[i_{3}],T_{4}[i_{4}]
at the same stop
p
such that their arrival and departure times are increasing in this order.
Let
v_{1},v_{2},v_{3},v_{4}
be the corresponding transfer nodes.
Then the “transfer chain” of
p
includes the path
P=\left<v_{1},v_{2},v_{3},v_{4}\right>
.
Assume that FLASH-TB flags the transfers
(T_{1}[i_{1}],T_{3}[i_{3}])
and
(T_{2}[i_{2}],T_{4}[i_{4}])
.
In Arc-Flags, this corresponds to flagging the entire path
P
.
However, this creates flagged paths from
T[i_{1}]
to
T_{4}[i_{4}]
and from
T_{2}[i_{2}]
and
T_{3}[i_{3}]
, which are akin to also flagging the transfers
(T_{1}[i_{1}],T_{4}[i_{4}])
and
(T_{2}[i_{2}],T_{3}[i_{3}])
.
Thus, Arc-Flags on the time-expanded graph always explores these transfers, whereas FLASH-TB only does so if they are flagged.

We refrain from flagging trip segments in FLASH-TB because it would not provide any benefit beyond the first round of a FLASH-TB query:
If a trip segment is not flagged for the target cell, then neither are its incoming or outgoing transfers.
Thus, an unflagged trip segment can only be entered during the first round, and no further trip segments are reachable from there.
It would be possible to compute a flag for each trip
T
and cell
i
that indicates whether
T
is used for the first trip segment of a required journey to cell
i
.
However, preliminary experiments have shown that this barely improves query times at the cost of additional memory consumption.

The other crucial difference between FLASH-TB and Arc-Flags on time-expanded graphs is how the flags are computed.
Arc-Flags is typically employed for solving the shortest path problem on a graph, where any node can occur as the source or target node of a query.
In this scenario, it is sufficient to compute a backward shortest-path tree from each boundary node.
Because every edge in the tree is required to answer at least one query, it is not wasteful to flag all of them.
However, as explained above, not all optimal paths between all pairs of nodes in the time-expanded graph occur in an optimal journey.
Computing and flagging a backward shortest-path tree from every boundary node
v_{t}
is wasteful for two reasons:
If
v_{t}
is a departure or arrival node, optimal paths to
v_{t}
correspond to partial journeys, which may not occur in any optimal journey.
If
v_{t}
is a transfer node, it is not necessarily the earliest reachable node of its stop for every leaf in the tree.
FLASH-TB solves both issues by computing the flags with forward Profile-TB searches from every stop in the network.
Because this approach is independent of the network partition, it does not need to run searches from boundary nodes that are departure or arrival nodes.
Secondly, because it uses forward searches, it can easily discard journeys with a suboptimal arrival time at the target stop.
The downside of this approach is that the preprocessing effort becomes quadratic in the number of stops and no longer scales with the partition size.

Finding a suitable preprocessing algorithm based on backward searches from the boundary nodes remains an open problem.
Such an algorithm would need to discard enough irrelevant paths to keep the search space small while being compatible with the pruning rules of the query algorithm.
As observed by
[
12
]
, achieving compatibility with line pruning (or their implementation of it, node-blocking) is particularly challenging.
Line pruning prefers journeys that use the earliest trip of each line that is still reachable from the source node.
However, this trip is difficult to determine during a backward search from the target node.
Delling, Pajor, and Wagner were only able to avoid this issue by disabling node-blocking altogether.
As seen in Section
4.1
, a naive implementation of FLASH-TB would run into a similar issue due to the conflict between self-pruning and line pruning.
However, we resolved this by adjusting the preprocessing algorithm, allowing FLASH-TB to benefit from both pruning rules simultaneously.

As expected, the preprocessing time of FLASH-TB is independent of

With the time for partitioning the network and the Trans-ULTRA transfer precomputation included, the preprocessing takes less than 30 minutes for the three smaller networks.
The much higher times for Germany indicate that the precomputation effort is quadratic in the network size.

Flagging the transfers is extremely effective at pruning the search space:
With the highest number of cells, FLASH-TB reduces the number of scanned trips by a factor of 367 on the Paris network, 782 on Switzerland and over 1 000 on the other two networks.
Without flag compression, this yields speedups of 501 on Germany, 112 on Paris, 448 on Sweden and 334 on Switzerland.
Because the memory consumption scales linearly with the number of cells, it quickly becomes very high, whereas the speedup eventually begins to stall.
However, excellent query times can be achieved with a reasonable amount of data:
For a speedup of 100 over TB, FLASH-TB without memory compression requires a few gigabytes on Germany and Paris, and a few hundred megabytes on Sweden and Switzerland.
For profile queries, the speedups are slightly lower at 457 for Germany, 48 for Paris, 235 for Sweden, and 164 for Switzerland.
This is because self-pruning already thins out the search space of each individual run, which means that there is less potential for additional pruning.

Flag compression reduces the memory consumption by a factor of two to five on Paris and four to seven on the other networks.
The resulting loss in query speed ranges from almost nothing to a factor of four; it is generally greater for higher values of
k
.
This is because the performance overhead caused by the additional memory accesses amortizes if cached flag patterns are accessed frequently.
Once the search space is reduced to a few dozen trips per query, this is no longer the case.
With flag compression, the highest achieved speedups are 198 on Germany, 25 on Paris, 123 on Sweden, and 156 on Switzerland.
The space required for a speedup of 100 over TB is reduced to around 500 MB for Germany and around or less than 100 MB for Sweden and Switzerland.

We observe that Paris, a dense metropolitan network, behaves differently from the other networks, which represent entire countries.
The overall speedup of FLASH-TB is lower, and in relation to the size of the network, the memory consumption is much higher.
Whereas a speedup of 100 can be achieved with around 10 bytes per transfer on the other networks, it requires 500 for Paris.
This is both because more cells are required and because flag compression is less effective.
Similar discrepancies in the performance between metropolitan and country networks were observed for Transfer Patterns
[
2
]
and TB-CST
[

]

7.4
Comparison to TB-CST

We compare FLASH-TB to TB-CST, which is the state of the art among speedup techniques with a high preprocessing effort.
A direct comparison with TP is difficult because we do not have access to its original implementation.
However, preliminary experiments with our own implementation of TP confirmed the findings of
[
25
]
that TB-CST without split trees has a very similar memory consumption and query performance while the preprocessing time is significantly lower.
We also do not compare our algorithm to Scalable Transfer Patterns, whose query times are barely competitive with TB, or to PTL, which does not support journey unpacking.

The results of our evaluation are shown in Table
3
.
The precomputation of TB-CST is four to ten times faster than that of FLASH-TB, even though both algorithms solve the all-to-all problem.
This is because our algorithm cannot fully benefit from self-pruning due to the ULTRA conditions.
However, the additional preprocessing effort pays off in the query phase.
Whereas TB-CST must reconstruct the earliest reachable trip of each line during the query, FLASH-TB can access it directly.
Furthermore, TB-CST has an additional time overhead for constructing the query graph.
Consequently, it is significantly outperformed for fixed departure time queries:
When comparing TB-CST with split trees to a configuration of FLASH-TB that requires approximately the same amount of space, FLASH-TB is two to nine times faster.
The speedup is especially high for Germany and Paris.
On the other hand, to achieve the same query speed, FLASH-TB requires between one and two orders of magnitude less space.
Additionally, the fastest configuration of FLASH-TB outperforms TB-CST without split trees while still requiring much less space.

For profile queries, TB-CST loses much of its disadvantage.
Firstly, the construction of the query graph takes up a smaller portion of the overall running time.
Secondly, instead of performing a run for each possible departure time, TB-CST constructs the entire profile during a single search within the query graph.
Thus, the step of finding the earliest reachable trip of a line is performed for all profile entries simultaneously, making it more efficient.
Consequently, TB-CST answers profile queries slightly faster than FLASH-TB.
However, we note that our implementation of FLASH-TB is not specifically optimized for profile queries and its performance can likely be improved.

Conclusion

We presented FLASH-TB, a speedup technique for public transit journey planning that applies the concept of Arc-Flags to the precomputed transfers used by TB.
We overcame previous obstacles in applying Arc-Flags to public transit networks by reconciling the pruning rules used in different phases of the algorithm.
As a result, FLASH-TB is the first technique that offers extremely fast query times without requiring impractical amounts of space.
However, because the preprocessing time is still quadratic, the scalability for very large networks remains limited.
Existing algorithms that reduce the preprocessing time, including Scalable Transfer Patterns and Arc-Flags on time-expanded graphs, pay for this with a significant increase in the search space.
Thus, the most important open question is whether a small query search space can be achieved with subquadratic preprocessing effort.
Another important issue in practice is handling delays.
The search graphs computed by TP are known to be very robust in this regard
[
5
]
.
By comparison, FLASH-TB is likely to be more sensitive to delays because its pruning information is highly time-dependent.
It remains to be shown whether a delay-resistant variant of FLASH-TB can be designed that still retains most of its speedup over TB.
Finally, real-world timetables cover more than two days, e.g., an entire year.
Currently, the preprocessing effort of FLASH-TB is proportional to the number of days.
However,
[
26
]
presents a TB variant that handles longer timetables efficiently.
Incorporating similar ideas into the FLASH-TB preprocessing step may improve its scalability for longer timetables.

Appendix A
Departure-Canonical Total Order

In Section
4.3
, we introduced the local departure tiebreaking sequence
X_{\ell}^{\mathrm{dep}}(J)
of a journey
J
.
Based on this, we define the departure-canonical total order
\prec_{\text{dep}}
on journeys:
J_{1}\prec_{\text{dep}}J_{2}
if and only if
X_{\ell}^{\mathrm{dep}}(J_{1}\setminus_{s}J_{2})<X_{\ell}^{\mathrm{dep}}(J_{2}\setminus_{s}J_{1})
, where
J_{1}\cap_{s}J_{2}
is the longest proper suffix of
J_{1}
that is also a proper suffix of
J_{2}
and
J_{1}\setminus_{s}J_{2}
is the longest proper prefix of
J_{1}
that excludes
J_{1}\cap_{s}J_{2}
.

Lemma 10
.

The relation
\prec_{\text{dep}}
is a strict total order.

Proof.

It is clear that
\prec_{\text{dep}}
is irreflexive and total.
To show that it is transitive, consider three journeys
J_{1},J_{2},J_{3}
with
J_{1}\prec_{\text{dep}}J_{2}
and
J_{2}\prec_{\text{dep}}J_{3}
.
Of the three suffixes
J_{1}\cap_{s}J_{2}
,
J_{1}\cap_{s}J_{3}
and
J_{2}\cap_{s}J_{3}
, at least two are equal and proper suffixes of the third one.

If all three are equal, this implies
J_{1}\setminus_{s}J_{2}=J_{1}\setminus_{s}J_{3}
,
J_{2}\setminus_{s}J_{1}=J_{2}\setminus_{s}J_{3}
and
J_{3}\setminus_{s}J_{2}=J_{3}\setminus_{s}J_{1}
.
Then it follows that

\displaystyle X_{\ell}^{\mathrm{dep}}(J_{1}\setminus_{s}J_{3})=X_{\ell}^{\mathrm{dep}}(J_{1}\setminus_{s}J_{2})

\displaystyle<

\displaystyle X_{\ell}^{\mathrm{dep}}(J_{2}\setminus_{s}J_{1})=X_{\ell}^{\mathrm{dep}}(J_{2}\setminus_{s}J_{3})

\displaystyle<

\displaystyle X_{\ell}^{\mathrm{dep}}(J_{3}\setminus_{s}J_{2})=X_{\ell}^{\mathrm{dep}}(J_{3}\setminus_{s}J_{1}).

Otherwise, one suffix is strictly longer than the other two, which are equal.
If the longest suffix is
J_{1}\cap_{s}J_{2}
, then
J_{3}\setminus_{s}J_{1}=J_{3}\setminus_{s}J_{2}
.
Furthermore,
J_{1}\setminus_{s}J_{3}
and
J_{2}\setminus_{s}J_{3}
share a non-empty proper suffix, which means that their local departure tiebreaking sequences are equal.
Then it follows that

X_{\ell}^{\mathrm{dep}}(J_{1}\setminus_{s}J_{3})=X_{\ell}^{\mathrm{dep}}(J_{2}\setminus_{s}J_{3})<X_{\ell}^{\mathrm{dep}}(J_{3}\setminus_{s}J_{2})=X_{\ell}^{\mathrm{dep}}(J_{3}\setminus_{s}J_{1}).

If the longest suffix is
J_{2}\cap_{s}J_{3}
, then
J_{1}\setminus_{s}J_{2}=J_{1}\setminus_{s}J_{3}
and
X_{\ell}^{\mathrm{dep}}(J_{2}\setminus_{s}J_{1})=X_{\ell}^{\mathrm{dep}}(J_{3}\setminus_{s}J_{1})
.
Then it follows that

X_{\ell}^{\mathrm{dep}}(J_{1}\setminus_{s}J_{3})=X_{\ell}^{\mathrm{dep}}(J_{1}\setminus_{s}J_{2})<X_{\ell}^{\mathrm{dep}}(J_{2}\setminus_{s}J_{1})=X_{\ell}^{\mathrm{dep}}(J_{3}\setminus_{s}J_{1}).

Finally, if the longest suffix is
J_{1}\cap_{s}J_{3}
, then
J_{2}\setminus_{s}J_{1}=J_{2}\setminus_{s}J_{3}
and
X_{\ell}^{\mathrm{dep}}(J_{1}\setminus_{s}J_{2})=X_{\ell}^{\mathrm{dep}}(J_{3}\setminus_{s}J_{2})
.
Then it follows that

X_{\ell}^{\mathrm{dep}}(J_{1}\setminus_{s}J_{2})=X_{\ell}^{\mathrm{dep}}(J_{3}\setminus_{s}J_{2})>X_{\ell}^{\mathrm{dep}}(J_{2}\setminus_{s}J_{3})=X_{\ell}^{\mathrm{dep}}(J_{2}\setminus_{s}J_{1}),

which contradicts
J_{1}\prec_{\text{dep}}J_{2}
.
∎

Appendix B
Trans-ULTRA Optimizations

A simplified version of Trans-ULTRA was presented in Section
4.3
.
In this section, we present additional performance optimizations that are carried over from ULTRA.
These are based on the observation that in order to generate a DCP transfer set, it is not necessary to find and unpack all departure-canonical journeys, merely those that are candidates.

In the profile search performed from each source stop
p_{s}
, this is exploited by skipping all runs that cannot produce any candidates.
The set of initial stop events that can occur in a journey with departure time
\uptau_{\mathrm{dep}}
is given by

\mathcal{E}(p_{s},\uptau_{\mathrm{dep}}):=\{T[i]\mid\uptau_{\mathrm{dep}}+\Delta\uptau_{\mathrm{fp}}(p_{s},p(T[i]))=\uptau_{\mathrm{dep}}(T[i])\}.

Normally, the profile search performs a run for every departure time
\uptau_{\mathrm{dep}}
such that
\mathcal{E}(p_{s},\uptau_{\mathrm{dep}})
is not empty.
We call
\uptau_{\mathrm{dep}}
a
candidate departure time
if there is a stop event
T[i]\in\mathcal{E}(p_{s},\uptau_{\mathrm{dep}})
with
p(T[i])=p_{s}
.
Let
\uptau_{\mathrm{dep}}^{1},\dots,\uptau_{\mathrm{dep}}^{k}
be the sequence of candidate departure times, sorted in ascending order.
To simplify the notation, let
\uptau_{\mathrm{dep}}^{k+1}:=\infty
.
Trans-ULTRA performs a run for each candidate departure time
\uptau_{\mathrm{dep}}^{i}
in descending order; the non-candidate departure times are skipped.
As a consequence, the run for
\uptau_{\mathrm{dep}}^{i}
may find new journeys whose departure time is not exactly
\uptau_{\mathrm{dep}}^{i}
but lies in the interval
[\uptau_{\mathrm{dep}}^{i},\uptau_{\mathrm{dep}}^{i+1})
.
The proof of Lemma
6
still carries over to a weaker claim, which is sufficient to prove Theorem
7
:

Lemma 11
.

Let
J
be a candidate that is departure-canonical for the query
Q=(p_{s}(J),p_{t}(J),\uptau_{\mathrm{dep}}(J))
.
After the run for
\uptau_{\mathrm{dep}}(J)
in the departure-canonical rRAPTOR search from
p_{s}(J)
, the representative for
c(J)
at
p_{t}(J)
is
J
.

Another optimization is that the algorithm only maintains parent pointers for representatives whose initial transfer is empty; all other pointer are set to a dummy value.
This allows the algorithm to efficiently identify whether a found journey is a candidate and needs to be unpacked.
It can also be leveraged by adding an extra ULTRA condition (U3):
Let
J
be the newly found journey and let
J^{\prime}
be the previous representative.
Then
J
is discarded if
J^{\prime}\preceq J
and
J
has a non-empty initial transfer.
This does not affect the correctness of Lemma
11
because (U3) is not fulfilled for any prefix of a departure-canonical candidate.
