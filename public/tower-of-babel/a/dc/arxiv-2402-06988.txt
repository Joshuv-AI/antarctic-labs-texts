Three Subtyping Algorithms for Binary Session Types and their Complexity Analyses
Thien Udomsrirungruang, Nobuko Yoshida

Abstract
Session types are a type discipline for describing and specifying communication behaviours of concurrent processes. Session subtyping , firstly introduced by Gay and Hole [ 4 ] , is widely used for enlarging typability of session programs. This paper gives the complexity analysis of three algorithms for subtyping of synchronous binary session types. First, we analyse the complexity of the algorithm from the original paper, which is based on an inductive tree search. We then introduce its optimised version, which improves the complexity, but is still exponential against the size of the two types. Finally, we propose a new quadratic algorithm based on a graph search using the concept of 𝒳 ​ 𝒴 ​ 𝒵 ​ 𝒲 \mathcal{XYZW} -simulation, recently introduced by Silva et al. [ 13 ] .



1
Introduction

Session types
[
6
,
14
]
are a type discipline for describing and specifying communication behaviours of concurrent processes. They stem from the observation that many real-world processes communicate in a highly-structured manner; these communications may include sending and receiving messages, selection and branching from a set of labels, and recursion. These session types allow programs to be validated for type safety using typechecking algorithms.

With regards to the synchronous session type system, Gay and Hole
[
4
]
proposed a subtyping scheme, and proved the soundness of the type system; Chen
et al.

[
3
]
later proved that the type system was complete (i.e. there is no larger subtyping relation between session types that is sound). Thus this notion of subtyping is of interest as it is most general. Our presentation of session types will use this system, as described in Gay and Hole’s paper
[
4
]
. For simplicity, we omit the
channel type

\hskip 3.00003pt\widehat{}\left[S\right]
: they can be adopted into the algorithms with little issue.

As an example, consider the following type, which represents an interface to a server which is able to respond to pings, as well as terminate itself:

\displaystyle T^{\mathsf{interface}}_{1}

\displaystyle=\mu X.\oplus\negmedspace\langle\mathsf{respond}\!:\>?[\mathsf{end}];X,\mathsf{exit}\!:\mathsf{end}\rangle\negmedspace

(1)

Here, the channel offers two choices of label to the process using it: (1) choosing
\mathsf{respond}
then receiving a message of unit type
\mathsf{end}
, or (2) choosing
\mathsf{exit}
and terminating the channel. After performing (1), the
\mu
-recursion means that the channel reverts to its original state.

Next, consider the scenario where we upgrade the interface to the server such that it can be replicated.

\displaystyle T^{\mathsf{interface}}_{2}

\displaystyle=\mu X.\oplus\negmedspace\langle\mathsf{respond}\!:\>?[\mathsf{end}];X,\mathsf{exit}\!:\mathsf{end},\mathsf{replicate}\!:\>?[X];X\rangle\negmedspace

(2)

The interface offers another choice: (3) choosing
\mathsf{replicate}
and receiving a new channel with the same type
T^{\mathsf{interface}}_{2}
. We can immediately see that any program that expects a channel of type
T^{\mathsf{interface}}_{1}
will also work on a channel of type
T^{\mathsf{interface}}_{2}
. This is because the functionality of the new channel type is identical to the old type, as long as the
\mathsf{replicate}
label is never chosen. Thus, it would make sense to accept
T^{\mathsf{interface}}_{2}
in type checking. It turns out that
T^{\mathsf{interface}}_{2}
is a subtype of
T^{\mathsf{interface}}_{1}
(denoted
T^{\mathsf{interface}}_{2}\leq_{c}T^{\mathsf{interface}}_{1}
), which characterises this property.

This subtyping relation is easy to see with a
syntactic
approach: the shapes of the types are almost identical, except for one additional branch in
T^{\mathsf{interface}}_{2}
; we could then argue inductively that the subtyping relation holds. However, for some types, this is not possible:

\displaystyle T^{\mathsf{interface}}_{3}

\displaystyle=\mu Y.\oplus\negmedspace\langle\mathsf{respond}\!:\>?[\mathsf{end}];Y,\mathsf{exit}\!:\mathsf{end},\mathsf{replicate}\!:\>?[T^{\mathsf{interface}}_{1}];Y\rangle\negmedspace

(3)

In essence,
T^{\mathsf{interface}}_{3}
is an interface that can be replicated to get copies, but those copies cannot themselves be replicated. We have that
T^{\mathsf{interface}}_{2}\leq_{c}T^{\mathsf{interface}}_{3}
. Syntactic subtyping does not work because the types do not have the same shapes (namely, the messages sent in the
\mathsf{replicate}
branch are
X
and
T^{\mathsf{interface}}_{1}
respectively). The difficulty of checking subtyping comes from the ability to "branch off" into multiple subterms: in the above example, checking the subterm
\>?[T^{\mathsf{interface}}_{1}];Y
would require us to check both
T^{\mathsf{interface}}_{1}
and
Y
. In certain cases this can lead to exponential complexity in the standard inductive algorithm given in
[
4
]
(see Example
).

Contributions.
We first analyse the algorithm given in Gay and Hole’s original paper on session type subtyping
[
4
, §5.1]
, improving the bound given in
[
9
, §5.1]
. Second, we propose its optimised version, in the style of
[
12
, Fig. 21-4]
. Both of these algorithms have worst-case exponential complexity, with the second algorithm having better complexity than the first. Third, we represent types as labeled transition systems, and formulate the subtyping problem as checking an
\mathcal{XYZW}
-simulation, similarly to
[
13
]
; we then give a quadratic algorithm for subtyping by checking the validity of the simulation.

3
Related work

The first algorithm for subtyping of
recursive function types dates back to Amadio and Cardelli
[
2
]
, where they give an exponential algorithm for recursive function type subtyping. Their algorithm inductively checks for
\alpha\rightarrow\beta\leq\gamma\rightarrow\delta
by recursively checking that
\alpha\leq\gamma
and
\beta\leq\delta
, unwrapping
\mu
-recursions, and keeping track of which pairs have been checked before.

Pierce
[
12
, Chapter 21.12]
surveys the development of quadratic subtyping algorithms for these types. Notably, Kozen
et al.

[
8
]
represent types as automata, then does a linear-time check on the product automaton of two types to check for subtyping, a method similar to our third algorithm (§
).

The subtyping relation for synchronous session types was introduced by Gay and Hole
[
4
]
, in which they showed that subtyping is sound and decidable. Their algorithm for subtyping (as presented here in §
), is similar to Amadio and Cardelli’s, adapted for session types. Later, Chen
et al.
[
3
]
proved that this relation is
precise
: no strictly larger relation respects type safety.

Lange and Yoshida
[
9
]
investigate subtyping for session
types by converting terms to a modal
\mu
-calculus formula which
represents its subtypes, then using a model checker to check for
subtyping. A short analysis of two other subtyping algorithms is also
provided, along with an empirical evaluation. The first is Gay and
Hole’s algorithm
[
4
]
, in which a doubly-exponential upper
bound is given, which we improve to a singly-exponential bound. The
second is an adaptation of Kozen’s algorithm
[
8
]
, which
is similar to our LTS-based construction (§
) in
that it builds a product automaton and checks for reachability. A
quadratic algorithm is given; however, the type system provided in

[
9
]
does not allow sending sessions as messages; instead,
sorts are used as payloads. Our algorithm is adapted to remove this
restriction. A comparison of complexity bounds in
[
9
]
and
this paper is in Table
1
.

Subtyping for non-regular session types, in which there are infinitely many subterms, are explored by Silva
et al.

[
13
]
, in which the concept of
\mathcal{XYZW}
-simulation for session type subtyping is introduced; it is also used in this paper. A sound algorithm is introduced to semi-decide the subtyping problem for context-free session types, which is accompanied by an empirical evaluation. In general, subtyping for context-free session types is undecidable, as shown by Padovani
[
10
]
.

We believe that the results from this paper could be applied to other session typing schemes with little difficulty: for example, the subtyping relation for local synchronous multiparty session types
[

, which is also sound and complete

.
