Towards Algebraic Subtyping for Extensible Records
Rodrigo Marques, Mário Florido, Pedro Vasconcelos

Abstract
. MLsub is a minimal language with a type system combining subtyping and parametric polymorphism and a type inference algorithm which infers compact principal types. Simple-sub is an alternative inference algorithm which can be implemented efficiently and is easier to understand. MLsub supports explicitly typed records which are not extensible. Here we extend Simple-sub with extensible records, meaning that we can add new fields to a previously defined record. For this we add row variables to our type language and extend the type constraint solving method of our type inference algorithm accordingly, keeping the decidability of type inference.

1.
Introduction

MLsub
(
Dolan and Mycroft 2017
)
is a minimal ML-like functional language with records that successfully combines algebraic subtyping and parametric polymorphism
(
Damas and Milner 1982
)
. It has decidable type inference and the type inference algorithm is sound and complete, in the sense that it returns principal types. Simple-sub
(
Parreaux 2020
)
is a subsequent formulation of a type inference algorithm which has the same features but is easier to understand because it does not require any concepts from abstract algebra.

Inspired by previous work on extensible records by Rémy and Pottier
(
Rémy 1993
;
Pottier 1998
)
, we extend Simple-sub with record extension, adding row variables to record types. We present a new definition of subtyping, a new type system and a new type inference algorithm to deal with these additions.

A prototype implementation and code of our type inference algorithm can be found in the Github repository:

https://github.com/RodrigoMarques16/simple-sub-records
.

This is ongoing work. We wish to apply our inference algorithm to more elaborate examples and pursue formal proofs of soundness and completeness that we believe will hold, but do not have yet done. However, we believe that our extension, particularly the new notion of subtyping is an important step towards the integration of row variables in a new type system with extensible records and algebraic subtyping, keeping all the known advantages of Simple-sub.

2.
Terms and Types

We now briefly review the term and type languages used by Simple-sub
(
Parreaux 2020
)
. We will only present the syntax, type rules and subtyping cases which are going to be used in our extension for extensible records.
Terms include integers, variables, lambda abstraction, application, records and let expressions. The type language consists of base types, type variables, functional types, records, top
\top
(the type all values), bottom
\bot
(the type of no values), union and intersection types, and recursive types.

3.
Extensible Records

Wand
(
Wand 1987
)
introduced row polymorphism to handle inference in a system with record extension. Rémy iterates on this in
(
Rémy 1993
)
. Rémy and Pottier study subtyping and row polymorphism in
(
Rémy 1995
;
Pottier 1998
)
.
Here we present an extension to Simple-sub, combining row variables with subtyping.
First we extend the term language with an action to extend records and add rows and field types to the type language.

\displaystyle t\

\displaystyle::=\cdots\ |\ t\text{ with }\{l=t\}

terms

\displaystyle\tau\

\displaystyle::=\cdots\ |\ \{\rho\}

types

\displaystyle\rho\

\displaystyle::=\ l:\theta,\ \rho\ |\ \char 12\relax\ |\ \alpha

rows

\displaystyle\theta\

\displaystyle::=\ \alpha\ |\ \char 12\relax\ |\ \ \text{Pre}~\tau

fields

Records are built incrementally with rows, starting from the empty row
Abs
. We still interpret records as a sequence of fields, but one that can now be open, ending in a row variable (a placeholder for fields that are not explicitly named but could be present), or closed and ending in
Abs
(all implicit fields are absent).
A field type is
Pre
\tau
if it is explicitly present.
Abs
(absent) means that a field is not present in the record. A type variable stands for either option.
We now extend the type system in
(
Parreaux 2020
)
to support these new constructs.

\displaystyle\frac{\Gamma\vdash t_{1}:\{l:\alpha;\ \rho\}\quad\Gamma\vdash t_{2}:\tau}{\Gamma\vdash t_{1}\text{ with }\{l=t_{2}\}:\{l:Pre\ \tau;\rho\}}\quad\textsc{T-Ext}\qquad\frac{\Gamma\vdash t:\{l:Pre\ \tau;\rho\}}{\Gamma\vdash t.l:\tau}\quad\textsc{T-Proj}

Type equivalence is defined modulo commutativity of fields and
Abs
unfolding. Thus
we add the following axioms to the subtyping relation:

\{...;Abs\}\equiv\{...,l:Abs;Abs\}\qquad\{l_{1}:\tau_{1},l_{2}:\tau_{2};\rho\}\equiv\{l_{2}:\tau_{2},l_{1}:\tau_{1};\rho\}

Finally we update the definition of subtyping, changing only the S-Rcd and S-Depth rules to account for row variables and introducing two new rules to handle field types.

\displaystyle\frac{}{Pre\ \tau\leq Abs}\quad\textsc{S-Ignore}\qquad\frac{\Sigma{}\vdash\tau_{1}\leq\tau_{2}}{\Sigma{}\vdash Pre\ \tau_{1}\leq Pre\ \tau_{2}}\quad\textsc{S-Pre}

\displaystyle\frac{}{\{\overline{l_{i}:\tau_{i}}^{i},Abs\}\equiv\sqcap_{i}\{l_{i}:\tau_{i},Abs\}}\quad\textsc{S-Rcd}\qquad\frac{\Sigma{}\vdash\tau_{1}\leq\tau_{2}}{\Sigma{}\vdash\{l:\tau_{1},Abs\}\leq\{l:\tau_{2},Abs\}}\quad\textsc{S-Depth}

The last concept we need for type inference is row
expansion

(
Pottier 1998
)
. Consider the following constraint:

\displaystyle\{x:\tau,\rho\}\leq\{\rho^{\prime}\}

Constraint solving creates an expansion
\rho^{\prime}\longrightarrow x:\alpha,\rho^{\prime\prime}
and constraints
\tau\leq\alpha
and
\rho\leq\rho^{\prime\prime}
, thus, later occurrences of
\rho^{\prime}
are now related to label
x
and type
\tau
as a lower bound of its possible field types.

4.
Examples

Consider the extension function f
=\lambda r.\ r\text{ with }\{y=1\}
.
Using subtyping alone function
f
admits a type
\{\}\rightarrow\{y:\text{int}\}

which loses all information about any existing fields of
r
.
If we then tried to infer a type for f
\ (\{x=1\}).x
we would fail since the information about the presence of
x
was lost.
With row variables we infer
\{y:\beta,\rho\}\rightarrow\{y:\text{int},\rho\}
.
The presence of the field
x
is recorded in the row variable
\rho
during inference so we can type this application.
We now present a type derivation tree and show how our type inference algorithm works for this example.
Due to space limitations, we will omit
Pre
from fields and
Abs
from rows. The type derivation tree is:
