Robustness of Locally Differentially Private Graph Analysis Against Poisoning
Jacob ImolaUC San Diego, Amrita Roy ChowdhuryUC San DiegoKamalika ChaudhuriUC San Diego

Abstract
Locally differentially private ( LDP ) graph analysis allows private analysis on a graph that is distributed accross multiple users. However, such computations are vulnerable to data poisoning attacks where an adversary can skew the results by submitting malformed data. In this paper, we formally study the impact of poisoning attacks for graph degree estimation protocols under LDP . We make two key technical contributions. First, we observe LDP makes a protocol more vulnerable to poisoning – the impact of poisoning is worse when the adversary can directly poison their (noisy) responses, rather than their input data. Second, we observe that graph data is naturally redundant – every edge is shared between two users. Leveraging this data redundancy, we design robust degree estimation protocols under LDP that can significantly reduce the impact of data poisoning and compute degree estimates with high accuracy. We evaluate our proposed robust degree estimation protocols under poisoning attacks on real-world datasets to demonstrate their efficacy in practice.

2.1
Local Differential Privacy for Graphs

Differential privacy (
DP
) is a quantifiable measure of the stability of the output of a randomized mechanism to changes to its input. One of the most popular models of
DP
is known as
local
model the which is the focus of our paper. The local model consists of a set of individual users (
U

DP
algorithm and sends it to the aggregator which uses these noisy data to estimate certain statistics of the entire dataset. Thus, the
LDP
model allows gleaning of useful information from the dataset without requiring the data owners to trust any third-party entity.

Framework for Robust Degree Estimation

In this section, we present our formal framework for analyzing the robustness of a protocol for degree estimation. First, we describe the protocol setup we consider in the paper. Next, we discuss how to formally quantify the robustness of a protocol.

3.1
Protocol Setup

Problem Statement.

We consider single round, non-interactive protocols in which users evaluate
pre-specified randomizers on their adjacency lists
l_{i}
, and send the responses
to a data aggregator
who computes the final degree estimates. To this end, a protocol
\mathcal{P}
consists of
the tuple

\mathcal{P}=(D,\{R_{1},\ldots,R_{n}\}).

Each user
\textsf{U}_{i},i\in[n]
runs the local randomizer

R_{i}:\{0,1\}^{n}\rightarrow\mathcal{X}
for some output space
\mathcal{X}
.
Finally, the data aggregator applies a function

D:\mathcal{X}^{n}\rightarrow(\mathbb{N}\cup\{\perp\})^{d}
to produce final degree
estimates. Note that the aggregator is allowed to output a special symbol
\perp
for a user
\textsf{U}_{i}
if they believe the estimate
\hat{d}_{i}
to be invalid (i.e.,
\textsf{U}_{i}
is malicious). We elaborate on this in the following section.
The protocol
\mathcal{P}
is executed by the users and the analyst to produce degree
estimates, given by

\hat{\textbf{d}}=\langle\hat{d}_{1},\ldots,\hat{d}_{n}\rangle)=D(R_{1}(l_{1}),\ldots R_{n}(l_{n})).

Here,
\hat{d}_{i}
is the aggregator’s estimate for
d_{i}
for user
\textsf{U}_{i}

Threat Model.

In the execution of a protocol
\mathcal{P}
, a subset of users

may be malicious and carry out a poisoning attack on

\mathcal{A}=\big(\mathcal{M},\{A_{i}(\cdot):i\in\mathcal{M}\}\big).

The functions

functions instead of the randomizers specified by

executes the same way, except that a malicious user
\textsf{U}_{i},i\in\mathcal{M}
responds with

instead of the true randomized response

outputs a manipulated degree estimate given by

m=|\mathcal{M}|

3.2
Quantifying Robustness

The robustness of a protocol can be measured along two dimensions,
correctness
(for honest users) and
soundness
(for malicious users) as now described.

Correctness (For Honest Users).
Malicious users can adversely affect an honest user
\textsf{U}_{i},i\in\mathcal{H}
by

\bullet

tampering with the value of
\textsf{U}_{i}
’s degree estimate
\hat{d}_{i}
(by introducing additional error), or

\bullet

attempting to mislabel
\textsf{U}_{i}
as malicious (by influencing the aggregator to report
\hat{d}_{i}=\bot
)

Note that a malicious user
\textsf{U}_{j}
can tamper with
\hat{d}_{i}
since it can manipulate the shared edge
e_{ij}
. The

of a protocol assesses its resilience to manipulation of an honest user’s estimator and is formally defined as:

Definition 3

(

\mathcal{A}
be an attack on
\mathcal{P}

\mathcal{H}

\displaystyle\forall\textsf{U}_{i}\in\mathcal{H},\mathrm{Pr}_{\mathcal{A}}\left[\hat{d}_{i}=\perp\vee|\hat{d}_{i}-d_{i}|\geq\alpha_{1}\right]\leq\delta_{1}.

Poisoning Attacks on Graphs

In this section, we introduce the two types of poisoning attacks to

4.1
Types of Poisoning Attacks

Note that for

\bullet

Input Poisoning.
In this case, the malicious users falsify their underlying input data, i.e., for a malicous user
\textsf{U}_{i},i\in\mathcal{M}
, their original data is changed from
l_{i}
to
l^{\prime}_{i}
and then,
\textsf{U}_{i}
carries out the protocol honestly on

instead (Fig.

\textsf{U}_{i}
reponds with

instead of
R(l_{i})
. This attack applies to
any
protocol, private or not. Algorithm
6
formalizes the attack.

\bullet

Response Poisoning.
This is a more powerful form of attack where the user can completely bypass the randomizer and submit an arbitrary response
q_{i}
(Fig.
3
) to the aggregator. The example attacks discussed in Section
3.1
are response manipulation attacks.

Although response poisoning attacks, by definition, subsumes all input poisoning attacks, it is important to distinguish between them for the following two reasons. First, the distinction between an user’s input and their response is a characteristic of

to ensure that all the steps of the privacy protocol (such as noise generation) is followed correctly.

In this section, we present our proposed protocol for robust degree estimation.
As discussed in the previous section, the naive

\textsf{DegRRNaive}(\cdot)

\textsf{DegRRNaive}(\cdot)

7
Improving Correctness with Hybrid Protocols

Note that the robustness guarantees for the

(\cdot)

O(\frac{\sqrt{n}}{\epsilon})

any
randomized response based mechanism
[
7

14

22
]
since each of the
n
bits of the adjacency list need to be independently randomized. Unfortunately, this dependence on
n
has an adverse effect on the utility of the degree estimates. Typically, real-world graphs are sparse in nature with maximum degree
d_{max}\ll n
. Hence, the
O(\frac{\sqrt{n}}{\epsilon})
noise term completely dominates the degree estimates resulting in very poor utility for the honest users
4
4

4

The “utility” of the malicious users is inconsequential – our goal is to minimize the impact of poisoning from the worst-case factor of
n-1
.
(correctness). In what follows, we present a mitigation strategy that uses a hybrid protocol for degree estimation based on two mechanisms – Laplace (
\textsf{R}_{Lap}(\cdot)
) and randomized response (
DegRRCheck
(\cdot)
).

7.1

We start by analyzing an alternative approach for private degree estimation – the Laplace mechanism,
\textsf{R}_{Lap}(\cdot)
(Algorithm
2
). The impact of poisoning attacks on
\textsf{R}_{Lap}(\cdot)
is formalized as follows.

For input poisoning attacks, we have:

Theorem 7
.

The
\textsf{R}_{Lap}(\cdot)
protocol is
(O(\frac{\log\frac{1}{\delta}}{\epsilon}),\delta)
correct and
(n-1,\frac{1}{2})
-sound with any input poisoning attack for
\forall m\in[n]
.

For response poisoning attacks, we have:

Theorem 8
.

The
\textsf{R}_{Lap}(\cdot)
protocol is
(O(\frac{\log\frac{1}{\delta}}{\epsilon}),\delta)
-correct and
n-1
-tight sound with respect to any response poisoning attack for
\forall m\in[n]
.

From the above theorems, we observe that
\textsf{R}_{Lap}(\cdot)
continues to have poor soundness – worst-case
n-1
. However, the correctness guarantee is improved to
O(\frac{1}{\epsilon})
for both input and response poisoning. The reason is as follows. In the
\textsf{R}_{Lap}(\cdot)
protocol, each user directly reports their noisy estimates. Consequently, the degree estimate of an honest user
cannot
be tampered with at all – the
O(\frac{1}{\epsilon})
term is due to the error of the added Laplace noise. This error is in fact optimal (matches that of central
DP
) for degree estimation. On the flip side, a malicious user can flagrantly lie about their estimate without detection resulting in poor soundness. Recall that the
DegRRCheck
(\cdot)
protocol prevents this behavior with the help of a consistency check.

Hence, the key idea is to combine the two approaches and use a hybrid protocol,
DegHybrid
(\cdot)

\bullet

correctness guarantee of
\textsf{R}_{Lap}(\cdot)
, and

\bullet

soundness guarantee of
DegRRCheck
()
.

Here, we discuss our empirical results in the context of our three evaluation questions. First, we observe that the baseline protocol

(\cdot)

(\cdot)

Related Work

In this section, we discuss the relevant prior work.

Data Poisoning for LDP.
A recent line of work
[
17
,
13
,
49
,
37
]
has explored the impact of data poisoning attacks in the LDP setting. However, these works focused either on tabular data or key-value data. Specifically, Cao et al.
[
13
]
proposed attacks where an adversary could increase the estimated frequencies for adversary-chosen target items or promote them to be identified as heavy hitters. Wu et al.
[
49
]
extended the attacks for key-value data where an adversary
aims to simultaneously promote the estimated frequencies and mean values for some adversary-chosen target keys. Both the works also presented some ad-hoc defenses against the proposed poisoning attacks. However, their efficacy is heavily dependent on instantiation specific factors such as the data distribution or the percentage of fake users. Cheu et al.
[
17
]
formally analyzed the poisoning attacks on categorical data and showed that local algorithms are highly vulnerable to adversarial manipulation – when the privacy level is high or the input domain is large, an adversary who controls a small fraction of the users in the protocol can completely obscure the distribution of the users’ inputs. This is essentially an impossibility result for robust estimation of categorical data via non-interactive LDP protocols. Additionally, they showed that poisoning the noisy messages can be far more damaging than poisoning the data itself. A recent work
[
37
]
studies the impact of data poisoning for mean and variance estimation for tabular data. In the shuffle
DP
model, Cheu et al.
[
18
]
have studied the impact of data poisoning for histogram estimation. In terms of general purpose defenses, prior work has explored strategies strategy based on cryptographically verifying implementations of
LDP
randomizers
[
36
,
5
,
40
]
– this would restrict the class of data poisoning attacks to input poisoning only.

A slew of poisoning attacks on machine learning models have been proposed in the federated learning setting
[
32
]
. The attacks could be either untargeted where the attack goal is to reduce the overall model accuracy
[
10
,
39
,
25
,
9
]
, or targeted where backdoors are injected for certain target classes
[
16
,
6
,
51
]
. A recent line of work
[
44
,
12
]
explores defense strategies based on zero-knowledge proofs that aim to detect the poisoned inputs.

LDP on Graphs.
DP on graphs has been widely studied, with most prior work being in the centralized model
[
11
,
15
,
29
,
20
,
33
,
35
,
41
,
34
,
45
,
47
]
.
In the local model, there exists work exploring the release of data about graphs in various settings
[
46
,
42
,
19
,
52
,
50
,
53
]
. Recent work exploring private subgraph counting
[
30
,
31
]
is the most relevant to our setting, as the degree information is the count of an edge, the simplest subgraph. However, no previous work explores data poisoning LDP protocols in the graph setting.

Conclusion

In this paper, we have investigated the impact of data poisoning attacks on private degree estimation for graphs. We have presented a formal framework for analyzing the robustness of a protocol against poisoning. Our framework can quantify the impact of a poisoning attack on both honest and malicious users.
Additionally, we have proposed novel robust degree estimation protocols under
LDP
by leveraging the natural data redundancy in graphs, that can significantly reduce the impact of data poisoning.

with probability at least
\frac{\delta}{4}
. The interval can be rewritten as
\rho^{2}m+[-\sqrt{m\ln\frac{4}{\delta}},(1-2\rho)m+\sqrt{m\ln\frac{4}{\delta}}]
. Thus,

\geq\sqrt{m\ln\tfrac{4}{\delta}}+(1-2\rho)m+\sqrt{6\rho n\ln\tfrac{4}{\delta}}]\leq\tfrac{\delta}{2}.

.

Claim 2
.

When player

is honest, we have that

∎

The

-correctness follows from the union bound over the two claims.

A.4
Proof of Theorem
5

Our results are aided by the Bernstein’s inequality:

Lemma 1
.

Let
X_{1},\ldots,X_{n}
denote independent
0
/
1
-valued random variables. Let
X=X_{1}+\cdots+X_{n}
, and let
v=\sum_{i=1}^{n}\mathbb{V}[X_{i}]

We have that, for all

,

\Pr[|X-\mathbb{E}[X]|\geq t\sqrt{v}]\leq\exp\left(-\frac{t^{2}}{2(1+t/(3\sqrt{v}))}\right)

As an immediate corollary, we obtain the following result:

Corollary 1
.

Let
X_{1},\ldots,X_{n}
denote independent random variables such that
X_{i}\sim\textnormal{Bernoulli}(p_{i})
. If we know that
p_{i}\in[0,\kappa]\cup[1-\kappa,1]
for some constant
\kappa<\frac{1}{2}
, and further that
\frac{4}{3}\ln\frac{1}{\delta}\leq n\kappa
, then

\displaystyle\Pr[|X-\mathbb{E}[X]|\geq\sqrt{3n\kappa\ln\frac{1}{\delta}}]

\displaystyle\leq\delta.

Proof.

Apply the previous result, substituting
\frac{n\kappa}{2}\leq v\leq n\kappa
where necessary.
∎

Correctness.

The proof of this lemma follows from the following claims. In the following, it will be helpful to split
r_{i}^{11}=hon_{i}^{11}+mal_{i}^{11}

and

.

is honest, we have that

B.3.1
Degree Inflation Attacks

Let
\textsf{U}_{t},t\in\mathcal{M}
be the target malicious user.

Input Poisoning.
The attack is formally given by:

\displaystyle\mathcal{A}_{4}=(\mathcal{M},A_{t}(\cdot):=\bar{A}_{input}(\cdot);A_{i}(\cdot):=\hat{A}_{input}(\cdot),i\in\mathcal{M}\setminus t)

All the malicious users report the adjacency list based on the strategy used for
DegRRCheck
(\cdot)
. For reporting the degree, the target malicious user plays the following strategy. First, it computes the (debiased) expected value of following
\textsf{RR}_{\rho}(\cdot)
on the adjacency list computed for
DegRRCheck
(\cdot)
. Next, they inflate this count by
b\tau_{input}
and add appropriate Laplace noise to it. Thus,
\textsf{U}_{t}
here scales the estimate by a factor
b
of the threshold for the consistency check. Clearly, the scaling factor
b
determines a trade-off between the skew and the probability of getting caught. All the non-target malicious users follow the Laplace mechanism truthfully to report their degrees as these values are immaterial for estimating
\textsf{U}_{t}
’s degree.

Response Poisoning.

The attack is formally given by:

\displaystyle\mathcal{A}_{5}=(\mathcal{M},A_{t}(\cdot):=\bar{A}_{response}(\cdot);A_{i}(\cdot):=\hat{A}_{response}(\cdot),i\in\mathcal{M}\setminus t)

All the malicious users report the adjacency list based on the strategy used for
DegRRCheck
(\cdot)
. For reporting the degree, the target malicious follows the similar strategy as that for the input response with the following changes.
\textsf{U}_{t}
now scales by
\tau_{response}
, the threshold for response poisoning. Additionally,
\textsf{U}_{t}
does not add any Laplace noise. All the non-target malicious users follow the Laplace mechanism truthfully to report their degrees as these values are immaterial for estimating
\textsf{U}_{t}
’s degree.
