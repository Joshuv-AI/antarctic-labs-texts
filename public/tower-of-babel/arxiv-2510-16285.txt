A Note on Algorithms for Computing p n p_{n}
Ansh Aggarwal

Abstract
We analyze algorithms for computing the n n th prime p n p_{n} and establish asymptotic bounds for several approaches. Using existing results on the complexity of evaluating the prime-counting function π ⁡ ( x ) \pi(x) , we show that the binary search approach computes p n p_{n} in O ⁡ ( n ​ ( log ⁡ n ) 4 ) O(\sqrt{n}\,(\log n)^{4}) time. Assuming the Riemann Hypothesis and Cramér’s conjecture, we construct a tighter interval around li − 1 ​ ( n ) \text{li}^{-1}(n) , leading to an improved sieve-based algorithm running in O ⁡ ( n ​ ( log 7 / 2 ⁡ n ) ​ log ⁡ log ⁡ n ) O(\sqrt{n}\,(\log^{7/2}n)\,\log\log n) time. This improvement, though conditional, suggests that further refinements to prime gap estimates may yield provably faster methods for computing primes.



1
Introduction

Finding the
n
th prime, denoted
p_{n}
, given
n
is an important problem
[
2
]
. It is known that an oracle for
\pi(x)
, the prime counting function, allows one to simply run binary search to compute
p_{n}
with at most
\log_{2}n
calls to
\pi(x)

[
2
]
.

First, given recent developments, we present a simple analysis for the explicit run time for this binary search approach. Notably, we look at Pierre Dusart’s bounds for
p_{n}

[
4
]
and look at the fastest known method of computing
\pi(x)

[
7
]
. Here, we conclude that
p_{n}
can be found, given
n
, in
O(\sqrt{n}\cdot\log^{4}n)
time.

Next, we consider sieving to find
p_{n}
. We show that the fastest sieve, which is a sublinear sieve
[
13
]
, cannot beat the binary search algorithm asymptotically. Instead, we consider a sieve that finds primes over an interval
[R,L]
using a segmented sieve. Ultimately, we show that for such a sieve to beat binary search, it must have an interval tighter than some
B
. A look at the literature tells us that an easy bound for
p_{n}
that is sufficiently tight does not exist.

Finally, we assume the Riemann hypothesis and Cramér’s conjecture on prime gaps to show a way to construct an interval tight enough that an interval sieve would asymptotically beat binary search. Thus based on this result, we construct a new algorithm that beats binary search to find
p_{n}
given
n
. This algorithm runs in
O(\sqrt{n}\cdot(\log^{7/2}n)\cdot\log\log n)
time.

In this document,
\log
refers taking logarithm with base
e
. We generally denote logarithms in big-
O
notation with
\log
.

2
Bounds for
p_{n}

In
[
4
]
, Pierre Dusart provides bounds for
p_{n}
, namely, for
n\geq 6
:

\displaystyle L=n(\log n+\log(\log n)-1)<p_{n}<n(\log n+\log(\log n))=R

(1)

This has the immediate consequence that
p_{n}
is always contained in interval of size
n
.

Corollary 2.1
.

R-L=n(\log n+\log(\log n))-n(\log n+\log(\log n)-1)=n

For
n\geq 688383
, Dusart gives a more refined interval of size
\frac{n}{10\cdot\log n}
. However, since we hope to use this interval with binary search, we show that this improvement does not yield an asymptotic improvement for computing
p_{n}
.

Lemma 2.2
.

Improving the search interval for binary search by a
\log
factor does not improve the asymptotic run time.

Proof.

We want to show
O(\log n)=O(\log(n/\log n))
. Consider the following limit:

\displaystyle\lim_{n\to\infty}\frac{\log(n/\log n)}{\log n}=\lim_{n\to\infty}\frac{\log n}{\log n}-\lim_{n\to\infty}\frac{\log\log n}{\log n}=1-0=1

(2)

Thus, under binary search, the bounds for
p_{n}
give the same asymptotic result.
∎

3
Using
\pi(x)
to Compute
p_{n}

The prime counting function,
\pi(x)
, returns the number of prime numbers smaller than or equal to
x
. Formally, this may be written
[
2
]
as:

\displaystyle\pi(x)=\sum_{p\leq x}1

(3)

This, however, is not an efficient method to compute
\pi(x)
. Instead, there are two major efficient approaches to computing
\pi(x)
, both of which, in their best forms, run in
\tilde{O}(\sqrt{x})
time. In
[
9
]
, Lagarias and Odlyzko present an analytic method to compute
\pi(x)
, assuming the Riemann hypothesis holds true however, the authors note that despite its asymptotic result, it might be impractical to use due to the implied constants, leaving the combinatorial approach as the only real option.

In
[
7
]
, Hirsch, Kessler, and Mendlovic improve to
\tilde{O}(\sqrt{x})
, explicitly
O(\sqrt{x}\cdot(\log x)^{5/2})
due to proposition 16 in their paper, with previous notable results attributed Lagarias, Miller, and Oldyzko
[
8
]
and Rivat and Deléglise
[
3
]
.

In
[
2
]
, the authors prove that
p_{n}
can be computed quickly given an oracle for
\pi(x)
using binary search. This is done by finding the smallest
x
such that
\pi(x)=n
because all
x^{\prime}>x
such that
\pi(x^{\prime})=n
are necessarily composite. Let
T_{\pi}
denote the time complexity of evaluating
\pi(x)
.

Theorem 3.1
.

Using an oracle for
\pi(x)
, the
n
th prime is computed in
O(T_{\pi}\log n)
time.

Proof.

From
Section 2
,
[L,R]
defines an interval that contains
p_{n}
and it suffices to run binary search over it. The length of the interval is
n\implies
up to
\log_{2}n
evaluations of
\pi(x)
are required, thus we have
O(T_{\pi}\log n)
time. Remark: The change of base from
\log_{2}
to
\log
is allowed as it does not affect the asymptotic result but allows for cleaner simplifications in the proofs that follow
∎

Thus, using the algorithm from
[
7
]
, we obtain a more refined result.

Lemma 3.2
.

We can compute
p_{n}
in
O(\sqrt{n}\cdot(\log n)^{4})
time.

Proof.

Using the Prime Number Theorem, it is trivial to note that
O(\sqrt{x}\cdot(\log x)^{5/2})\sim O(\sqrt{n\log n}\cdot(\log(n\log n))^{5/2})=T_{\pi}
thus we have:

\displaystyle O(\sqrt{n\log n}\cdot(\log(n\log n))^{5/2})

(4)

\displaystyle\implies T_{\pi}=O(\sqrt{n}\cdot(\log n)^{3})

(5)

Following
Theorem 3.1
, we conclude that
p_{n}
is computed in
O(\sqrt{n}\cdot(\log n)^{3}\cdot\log n)\implies O(\sqrt{n}\cdot(\log n)^{4})
.
∎

4
Sublinear Sieves

In
[
13
]
, Sorenson presented a sublinear sieve that built on Pritchard’s work in
[
10
,
11
]
. A sieve produces all primes up to some bound
M
; thus, to compute
p_{n}
, it suffices to sieve up to an upper bound, like
R
from
Section 2.1
and counting to
n
th number in the list. With
R
as the upper bound, the sublinear sieve runs in
O(R/\log\log R)
time.

Lemma 4.1
.

A sublinear sieve takes
O((n\log n)/\log\log n)
time to compute
p_{n}
.

Proof.

From
Section 2
,
R=n(\log n+\log(\log n))
gives:

\displaystyle O\left(\frac{n(\log n+\log(\log n))}{\log(\log n(\log n+\log(\log n)))}\right)\implies O\left(\frac{n\log n}{\log(\log n(\log n+\log(\log n)))}\right)

(6)

Let
T
denote the expression on the right. Note that:

\displaystyle T\subseteq O\left(\frac{n\log n}{\log\log n}\right)

(7)

Counting once sieving is completed takes
O(n)
time thus, we have
O((n\log n)/\log\log n)
.
∎

Theorem 4.2
.

A sublinear sieve is asymptotically worse than the binary search algorithm to compute
p_{n}
.

Proof.

The theorem is true if the following limit converges to
0
:

\displaystyle\lim_{n\to\infty}\sqrt{n}\cdot(\log n)^{4}\cdot\frac{\log\log n}{n\log n}=\lim_{n\to\infty}\frac{(\log n)^{3}(\log\log n)}{\sqrt{n}}

(8)

Note that

\displaystyle\frac{(\log n)^{3}(\log\log n)}{\sqrt{n}}\leq\frac{(\log n)^{3}}{\sqrt{n}}

(9)

Thus, if the latter expression converges, so does the original limit,

\displaystyle\lim_{n\to\infty}\frac{(\log n)^{3}}{n^{1/2}}=0

(10)

We conclude that this converges to
0
by a few applications of L’Hopital’s rule.
∎

5
Further Sieving Troubles

Another way to find
p_{n}
is to sieve over a sufficiently small range
[i,j]
with a counter that is initialized at
\pi(i)
and incremented for every prime in
[i,j]
. To sieve over such an interval, the best known method involves using segmented sieves that finds all primes up to
\sqrt{j}
and uses them to mark primes in
[i,j]

[
5
]
. Note that such an algorithm runs in
O((j-i+1)\log\log j+\sqrt{j}\log\log\sqrt{j})
time where
O(\sqrt{j}\log\log\sqrt{j})
comes from needing to find all primes up to
\sqrt{j}
. We assume a stronger variant where the list of primes up to
\sqrt{j}
is precomputed thus giving
O((j-i+1)\log\log j)
as the time complexity.

Theorem 5.1
.

The size of
[i,j]
must be less than
\sqrt{n}\cdot\frac{(\log n)^{4}}{\log\log n}
(up to some constant) in order to beat the binary search algorithm asymptotically when attempting to find
p_{n}
.

Proof.

First, we let
s=(j-i+1)
and in order to isolate the dependence on
s
instead of the upper bound
j
alone, we let
j\sim n\log n
giving the time complexity of the interval sieve as:

\displaystyle O(s\log\log(n\log n))=O(s\log\log n)

(11)

From the previous sections, we note that the best binary search algorithm runs in
O(\sqrt{n}\cdot(\log n)^{4})
thus, for the sieve to beat the algorithm, the following inequality must hold for some
s
and some constant
c
:

\displaystyle c\cdot\frac{s\log\log n}{\sqrt{n}\cdot(\log n)^{4}}<1\implies s<\frac{1}{c}\cdot\frac{\sqrt{n}\cdot(\log n)^{4}}{\log\log n}=B

(12)

If
|[i,j]|=s<B
, then a sieve over
[i,j]
would be asymptotically faster than the binary search algorithm.
∎

Dusart’s bounds show that
p_{n}
is found in an interval of size
O(n/\log n)
as noted in
Section 2

[
4
]
and while, further work, notably by Christian Axler
[
1
]
, does improve bounds for
p_{n}
, asymptotically, they yield
O(n)
. As such, with current state of bounds for
p_{n}
a segmented sieve over an interval cannot beat the binary search algorithm without further work.

6
Using Schoenfeld’s Bound

A consequence of the Riemann hypothesis, as given by Lowell Schoenfeld
[
12
]
, is the following bound:

\displaystyle|\pi(x)-\text{li}(x)|\leq\frac{1}{8\pi}\cdot\sqrt{x}\cdot\log x

(13)

Where
\text{li}(x)
is the logarithmic integral function. A consequence of this result given in the following corollary:

Corollary 6.1
.

For
k=\frac{1}{8\pi}
,

\displaystyle\pi(x)\in I=[\text{li}(x)-k\sqrt{x}\log x,\text{li}(x)+k\sqrt{x}\log x]

(14)

For an
\alpha
such that
\text{li}(\alpha)=n
, we have that
\pi(\alpha)=n^{\prime}\in I
. Consider the two possibilities, if
n^{\prime}>n
, then
p_{n}<\alpha
and if
n^{\prime}<n
, then
p_{n}>\alpha
.

Unlike
\pi(x)
,
\text{li}(x)
is easy to approximately compute using the following expansion:

\displaystyle\text{li}(x)\sim\frac{x}{\log x}\sum_{k=0}^{\infty}\frac{k!}{(\log x)^{k}}

(15)

This means for any evaluation of
\text{li}(x)
with precision
\varepsilon
, the time complexity is
O(\log(1/\varepsilon))\implies O(1)
, constant time. As such, using
\text{li}(x)
almost as a ‘proxy’ for
\pi(x)
by evaluating
\text{li}(x)

\log_{2}n
times to get
\alpha
such that
\text{li}(\alpha)=n
, done entirely in
O(\log_{2}n)\implies O(\log n)
time. The obstacle that remains is going from
\alpha
to
p_{n}
however, here we may consider Cramér’s conjecture
[
6
]
:

\displaystyle p_{n+1}-p_{n}\in O((\log p_{n})^{2})

(16)

A natural extension of this conjecture is given for larger gaps,

\displaystyle p_{n+\Delta}-p_{n}\in O(\Delta(\log p_{n+\Delta})^{2})

(17)

Note that while
\alpha
is not guaranteed to be a prime, we may still use it as though it were a prime and
p_{n}
together to bound
|p_{n}-\alpha|
asymptotically.

Theorem 6.2
.

The gap
|p_{n}-\alpha|
is
O(\sqrt{n}\cdot(\log^{7/2}n))
where
\pi(p_{n})=n
and
\text{li}(\alpha)=n
.

Proof.

From Schoenfeld’s bound,

\displaystyle|\pi(\alpha)-\text{li}(\alpha)|\leq\frac{1}{8\pi}\cdot\sqrt{\alpha}\cdot\log\alpha

(18)

Additionally, for some
\Delta
using Cramér’s conjecture, we have,

\displaystyle|\alpha-p_{n}|\in O(\Delta((\log\max(\alpha,p_{n}))^{2})

(19)

Note that the bound gives a precise value for
\Delta
, explicitly
\Delta=\frac{1}{8\pi}\cdot\sqrt{\alpha}\cdot\log\alpha
and, without loss of generality, let
\max(\alpha,p_{n})=\alpha
, then we have:

\displaystyle|\alpha-p_{n}|\in O(\sqrt{\alpha}\cdot\log^{3}\alpha)

(20)

Now, we use the Prime Number Theorem
\alpha\sim p_{n}\sim n\log n
, giving:

\displaystyle|\alpha-p_{n}|\in O(\sqrt{n\log n}\cdot\log^{3}(n\log n))\implies O(\sqrt{n}\cdot(\log^{7/2}n))

(21)

We have our result,
O(\sqrt{n}\cdot(\log^{7/2}n))
.
∎

The immediate consequence of this theorem is that attempting to sieve over the interval around
\alpha
that contains
p_{n}
necessarily beats the binary search algorithm, as given by the theorem in
Section 5
.

7
An Improved Algorithm

Following the discussion in the previous section, a consolidated algorithm to find
p_{n}
is as follows:

1.

Evaluate
\text{li}(x)

\log_{2}n
many times over the interval given by Dusart’s bounds to find
\alpha
such that
\text{li}(\alpha)=n
. This is done in
O(\log n)
time.

2.

Define an interval
[L,R]=[\alpha-O(\sqrt{n}\cdot(\log^{7/2}n)),\alpha+O(\sqrt{n}\cdot(\log^{7/2}n))]
. Sieving over this interval takes
O(\sqrt{n}\cdot(\log^{7/2}n))\cdot\log\log n)
time.

3.

With the list of primes in the interval, evaluate
\pi(p^{\prime})
once for any
p^{\prime}
in the list and simply count up / down to the
n
th prime. This is done in
{O}(\sqrt{p^{\prime}}\cdot(\log p^{\prime})^{5/2})\implies{O}(\sqrt{n\log n}\cdot(\log(n\log n))^{5/2})\implies O(\sqrt{n}\cdot\log^{3}n)
time.

Overall, this algorithm runs in:

\displaystyle O(\log n+\sqrt{n}\cdot(\log^{7/2}n))\cdot\log\log n+\sqrt{n}\cdot\log^{3}n)\implies O(\sqrt{n}\cdot(\log^{7/2}n)\cdot\log\log n)

(22)

This is faster than binary search with multiple
\pi(x)
evaluations, which runs in
O(\sqrt{n}\cdot\log^{4}n)
time.

8
Conclusion

In this note, we analyzed multiple algorithms for computing the
n
th prime
p_{n}
and established concrete asymptotic bounds for their performance. Using existing results on the complexity of evaluating the prime-counting function
\pi(x)
, we showed that the binary search approach computes
p_{n}
in
O(\sqrt{n}\cdot(\log n)^{4})
time. We further demonstrated that even the fastest known sublinear or segmented sieves cannot asymptotically outperform this method with current bounds for
p_{n}
.

Assuming the Riemann Hypothesis and Cramér’s conjecture, we constructed a tighter interval around the approximation
\alpha
satisfying
\text{li}(\alpha)=n
. This led to an improved sieve-based algorithm running in
O(\sqrt{n}\cdot(\log^{7/2}n)\cdot\log\log n)
time, which asymptotically beats the binary search approach.

While the improvement is conditional and primarily theoretical, it suggests that future refinements in prime gap estimates or unconditional bounds on
p_{n}
could lead to provably faster methods for computing primes.
