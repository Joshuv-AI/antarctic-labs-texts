Advanced security in fog environments using encryption and adaptive user activity tracking
Authors: Hari Mohan Rai, Abdul Razaque, Neha Agarwal, Saurabh Agarwal, Hanaa A. Abdallah, Shashi Kant
Published: 2026

ABSTRACT
The use of fog computing is on the rise, adding new dimensions to security and, more specifically, to data protection in fog cloud environments. Storing fog-computing data increases the likelihood of data exploitation when it is uploaded to fog-computing storage. In this paper, Adaptable User Activity Tracking (ASUT) is introduced, integrating AES-256, SHA-512, and user activity tracking (UAT). The need to integrate activity monitoring into the ASUT to collect statistical information on user actions has been stated. The file uploaded to the fog computing storage is encrypted using a 256-bit AES key. Then, this key is hashed with SHA-512 and stored in the fog cloud. The AES expansion is used to decrypt the data, while the SHA-512 hash of the AES key is used to verify that the user-provided key matches the original before decryption proceeds—the hash is irreversible, and the original key is never stored in plaintext. The user must know the initial key to access the file further. When the client re-enters the fog, the algorithm compares the hashes of the two: the initial and the second entry keys. In parallel, the fog cloud broadcasts the user’s actions to track any abnormal activity on the account. This mechanism helps mitigate risks of unauthorized data access and suggests ways to improve user protection. The proposed ASUT is designed using Python and PHP. Experimental results show that ASUT achieves 43.39% faster encryption, 66% faster decryption, and 19.86% higher throughput compared to the best-performing competing method, indicating improved computational efficiency and practical feasibility under the evaluated conditions.

Introduction

The rise of the Internet of Things (IoT) devices has generated a wealth of data that can be leveraged to enhance various aspects of daily life. Data integrity is compromised because offenders change or delete backups1. The main components of fog security are data security, availability, compliance, and access management. Among these, threats targeting data confidentiality and availability are widely recognized as major challenges in cloud and fog computing environments, irrespective of other security aspects2. Real-time data analysis and decision-making have been enabled by fog computing, but it also introduces new security challenges that must be addressed. Studies rely on encrypted keys to authenticate users, which simplifies key management but reduces data privacy3. The distributed structure of the fog computing environment and the mobility of IoT devices contribute to a fragile security situation, making it just as prone to attacks such as DDoS4. There are several primary causes of data breaches, including intrusions by thieves and hackers seeking unauthorized access to user information. Examples include cyber-attacks, phishing, malware, and others5. Fog nodes are deployed in uncontrolled settings, implying that IoT devices lack intrinsic protection mechanisms, leaving them vulnerable to threats that compromise data privacy and security. Furthermore, fog nodes may also be susceptible to physical attacks, resulting in a high chance of data breaches6. A storage breach is considered physical when an intruder takes the physical disk containing sensitive information, or when an employee moves corporate information to the cloud. The last is unauthorized login in a cloud, which is designed inappropriately7. The dynamic nature of fog computing environments also creates a need for security control, as security regulations must be updated regularly to account for changes in the network topology and the addition or removal of devices8. Violations of data confidentiality in fog cloud environments have significant consequences. This means that if someone infiltrates an organization or company, for example, they will cause considerable harm by embezzling money, damaging the reputation, and potentially facing legal trouble. Additionally, proprietary information in the compromised data may be exploited for fraud, identity theft, and espionage9. These effects increase the need to appropriately protect fog nodes that are vulnerable to such attacks and also ensure the privacy of data stored in them.

The first exceptional solution that maintains data privacy is the new PURA-SCIS protocol, designed to detect and analyze cybercrime. It requires a system that links devices together and provides a tenancy for an interconnecting system. Its primary purpose is to mitigate and monitor occurrences for the user10. Another measure is data encryption using the AES-256 and SHA-512 algorithms to ensure the security of information stored on fog nodes11. The second approach may involve using activity logs to track user activity within the fog computing environment, helping identify unusual activities that could lead to unauthorized access to fog nodes. Additionally, implementing firewalls and intrusion detection systems can serve as effective preventive measures to detect attacks on fog nodes. Other solutions include implementing access controls, upgrading security software, and using a virtual private network (VPN) to secure data transfer between fog nodes12. Thus, this paper introduces a new method for enhancing fog–cloud security that incorporates AES-256 and SHA-512 encryption technologies along with a user activity monitoring approach.

Based on the goals mentioned earlier, the primary aim of this work is to propose a hybrid symmetric–hashing scheme that enhances data privacy in fog cloud environments, particularly in healthcare IoT and automation systems. Specifically, the approach integrates AES-256 and SHA-512 encryption with user activity tracking to enhance the security of fog nodes. Furthermore, the proposed algorithm is evaluated against relevant methods in terms of time and memory consumption, as well as the adopted data transmission mechanism. Finally, its performance is compared with existing encryption methods in fog computing environments. However, user activity tracking is also used in real time. This is an added advantage because the system notifies the user when a file is deleted or changed. Integrating AES-256 and SHA-512 encryption with user activity tracking in the ASUT algorithm can enhance the security of the fog computing environment. Thus, based on user activity tracking, the algorithm can provide a second layer of security to prevent unauthorized access to fog nodes.

Novelty and contributions of ASUT

The proposed ASUT framework does not introduce a new cryptographic primitive; instead, its novelty lies in the architecture-level integration of security mechanisms within the fog computing pipeline. Specifically, ASUT unifies symmetric encryption, hash-based key verification, and behavioral monitoring into a single, tightly coupled access-control workflow. First, unlike conventional designs where encryption and logging operate as independent modules, ASUT embeds user activity tracking (UAT) directly into the authorization path. Access to encrypted data is not determined solely by key verification but is subject to conditional governance by real-time behavioral evaluation. This establishes a pre-decryption enforcement model, in which anomalous sessions can be blocked before data exposure occurs. Second, the framework introduces a coupled verification mechanism in which cryptographic validation (AES-256 + SHA-512) and behavioral assessment (UAT scoring) are executed jointly at the fog layer. This contrasts with traditional “encrypt-then-log” approaches, where activity monitoring is performed post hoc and cannot influence immediate access decisions. Third, ASUT is architected specifically for resource-constrained fog environments, ensuring that all security operations—encryption, hashing, and monitoring—are co-located and lightweight. This avoids reliance on computationally expensive asymmetric cryptography while maintaining enforceable security controls at the edge. Finally, the contribution lies in demonstrating that security in fog computing can be strengthened through coordinated control-flow integration, rather than by introducing additional cryptographic complexity. The proposed design shifts the focus from isolated security components to real-time, policy-driven orchestration of encryption and behavioral monitoring within the fog access pipeline.

Cryptographic concepts for fog computing

To make the proposed method more accessible, the core cryptographic concepts used in ASUT are briefly summarized. AES-256 is a symmetric block cipher that encrypts data using a 256-bit secret key; it can be viewed as a lock-and-key mechanism, where the same key is required to both lock (encrypt) and unlock (decrypt) the data. SHA-512 is a member of the SHA-2 hash family that computes a 512-bit digest from an input; it behaves like a digital fingerprint, allowing integrity checks without revealing the original data or key. In ASUT, the private encryption key is first passed through SHA-512, and only the resulting hash is stored or attached to encrypted content, so that the original key never appears in clear form in fog storage. The proposed scheme combines symmetric encryption with hash-based key verification: files are encrypted with AES-256, keys are protected with SHA-512, and access is continuously supervised using UAT scores derived from user behavior in the fog environment.

Related work

This section discusses the various approaches proposed earlier, with a focus on the confidentiality of cloud data storage. Several works employ multiple levels of an access control mechanism or symmetric key algorithms to enhance the protection of data stored in the cloud. Unfortunately, this is not an effective solution from a cybersecurity perspective. The research by volunteers, as presented in a paper by Kayes et al21., focused on RBAC for cloud storage security and access. It has been designed to enhance information protection and isolate data stored in the cloud. Guan et al22. proposed a security scheme for big data storage in Hadoop. The scheme employs an enhanced version of the ECC encryption technique and a two-channel distributed storage system. Consequently, a solution is proposed to improve secure and efficient encrypted data storage. Premkumar and Sathya23introduced a protocol called Service Constraint NCBQ (Network Condition and Behavior Quality) Trust-oriented Secure Transmission Protocol (SCNCQB-TSTP). The method finds different routes to a service point and extracts information about the message channel in the vicinity. According to the information obtained on the various methods, the method evaluates the reliability of each channel across three stages: network support evaluation, behavioral support evaluation, and quality of service (QoS) support evaluation. Wang et al24. have developed a secure method for data collection. The system utilizes a novel proxy re-encryption mechanism to safeguard data in the cloud. As a result, they can use their technology to combat many attacks on sensitive data. Ren et al25. introduce a model based on an SVM encryption service, which provides a key to facilitate data encryption in cloud computing. Ghafoorian et al26. proposed a new straightforward model for computer reliability. Role-based access is designed to ensure data storage in secure cloud environments is based on reputation and trust. Comparing the absolute errors, reliability, and time consumption with those of existing models, the results indicate that if the proposed model is given high priority, it will be used in real cloud systems. Khalid et al27. outline a cloud-based security algorithm that utilizes centroids to enhance secure file transfers. It supports network maneuvering and efficiency. This scheme stops malicious transfer points from working for new data. Security between the server and the system itself is maintained using an asymmetric encryption algorithm. One disadvantage is that it cannot be integrated with traditional sensor network solutions. It is not resistant to attacks that do not allow for network failure and replay. Ricardo et al28. proposed cloud-to-cloud encryption to secure data against unauthorized access by providers outside the cloud. It is also available to store data in different clouds under one name for quick retrieval. The two main advantages are economic: virtual machines are significantly less expensive than cloud-to-cloud storage and require less administrative interference. This system is not designed to store large amounts of data and manage data partitioning. It also does not offer a solution to file security. People who have access to cloud files can manipulate them in any way, including deleting, modifying, or duplicating them. Table 1 summarizes representative approaches for securing data in fog and cloud computing environments and highlights their key limitations. Building on this analysis, the proposed ASUT framework is designed to explicitly address these shortcomings through a unified, fog-oriented security architecture that integrates efficient cryptography with behavioral monitoring.

Many existing approaches rely on homogeneous encryption mechanisms or external policy enforcement to protect data confidentiality. In contrast, ASUT adopts a combined symmetric encryption and hash-based key protection design, combining AES-256 for efficient data encryption with SHA-512 for secure key hashing. The evaluated implementation does not store plaintext keys directly. As a result, ASUT enhances confidentiality and key management in distributed, partially trusted fog environments.

Another common limitation of existing solutions is their dependence on static, authentication-only access control, which assumes that user behavior remains trustworthy after login. ASUT partially addresses this limitation by integrating user activity tracking (UAT) as an intrinsic component of the security workflow. UAT continuously monitors access patterns and file operations, supporting the detection of abnormal behavior, such as repeated access attempts, unauthorized modifications, or suspicious deletions. This capability enables ASUT to mitigate insider threats and misuse that cannot be addressed solely through encryption and authentication.

Several prior approaches also exhibit limited scalability or compatibility with dynamic fog and IoT environments, particularly when handling heterogeneous devices or large volumes of data. ASUT addresses this issue by relying on lightweight symmetric cryptography and hash-based key protection, which impose low computational and memory overhead. This makes the framework suitable for resource-constrained fog nodes while maintaining scalability for large-scale data storage and processing.

Threat model for fog-based confidential data storage

The threat model considered in this work reflects realistic risks in fog environments where sensitive data are stored and processed close to the edge. An adversary may be an external attacker intercepting traffic between IoT devices, fog nodes, and cloud storage; a malicious insider with legitimate credentials but dishonest intent; or an attacker who temporarily compromises a fog node or database. Potential attacks include password guessing and credential stuffing, man-in-the-middle interception of files in transit, unauthorized read or modification of stored files, replay of outdated credentials or tokens, and deletion or tampering with activity logs. In addition, resource-constrained fog devices are vulnerable to denial-of-service conditions when security mechanisms are overly complex. ASUT addresses these threats by encrypting all sensitive content with AES-256, hashing keys with SHA-512 before storage, enforcing registration and logging processes that bind credentials to encrypted client secrets, and continuously monitoring user actions via UAT. Certain deviations from normal behavior, such as repeated failed logins or unusual file-download patterns, may be detected and used to trigger additional checks or block access at the fog layer.

To illustrate the threat model concretely, consider a fog-based healthcare IoT deployment in which patient records are uploaded from bedside sensors to fog nodes before being relayed to central cloud storage. In this scenario, an insider nurse with valid credentials begins downloading unusually large numbers of patient records outside of normal working hours. Under existing schemes with static authentication, this anomaly goes undetected. Under ASUT, the UAT score for this user rises sharply as the weighted activity level (Eq. 1) exceeds the rolling-average baseline by more than two standard deviations, triggering an automatic alert and suspending further file access until re-authentication. To better understand how these threats materialize in practice, Fig. 1 illustrates the end-to-end architecture of the ASUT framework across three layers: the IoT device layer, the fog computing layer, and the cloud storage layer. As shown in Fig. 1, data originating from IoT sensors first passes through the fog layer, where AES-256 encryption and SHA-512 key hashing are applied before any file reaches cloud storage. Simultaneously, the UAT monitor embedded within the fog layer continuously scores user activity against a rolling behavioral baseline. When the activity score exceeds the anomaly threshold, access is suspended at the fog layer before the request reaches the cloud, meaning the threat may be contained early in the processing pipeline, rather than being detected after the fact.

It also makes clear why integrating UAT with the cryptographic layer is architecturally significant. In schemes where activity logging is a separate, loosely coupled component, an anomalous session can still complete a file download or deletion before the log is reviewed. In ASUT, the UAT decision sits in the same pipeline as the key verification step, so a session flagged as anomalous may be denied decryption authorization in real time. This design distinction is what separates ASUT from a standard encrypt-then-log approach.

How ASUT overcomes shortcomings of existing approaches

Table 1 highlights several limitations of existing fog-security solutions, such as reliance on external policy engines, homogeneous encryption schemes that concentrate risk in a single primitive, limited support for large-scale data storage, and insufficient protection against insider misuse. The proposed ASUT framework explicitly addresses these issues through its multi-layered design. Symmetric AES-256 encryption provides efficient, high-strength confidentiality for bulk data. SHA-512-based key hashing and key expansion improve the robustness of key management compared with schemes that store keys or hashes with lower entropy. The integration of UAT directly into the cryptographic workflow introduces behavioral monitoring, reducing dependence on separate access-control policies. Furthermore, ASUT is designed to operate with low memory overhead and high throughput, making it suitable for distributed fog deployments in which many edge devices generate and upload encrypted files.

Proposed method of securing confidential data in fog cloud computing

The proposed ASUT method employs a hybrid symmetric–hashing scheme that combines symmetric encryption with hash-based key protection to strengthen the security of sensitive data stored in fog computing environments. The proposed ASUT consists of multiple features, i.e., Cloud monitoring, Cloud hashing, and SED with a hashed key (Storing encrypted data with a hashed key). These features are important components of the proposed security design of sensitive data stored in the cloud. Cloud monitoring analyzes user activity in the cloud using the Drive Activity Report. Security assumptions and design rationale

The security of the proposed ASUT framework relies on standard cryptographic assumptions. AES-256 is assumed to behave as a secure pseudo-random permutation, and SHA-512 is assumed to provide strong preimage and second-preimage resistance. Under these assumptions, an adversary with access to ciphertext and stored hash values cannot feasibly recover the original plaintext or encryption key. The framework enforces confidentiality through AES-256 encryption, while mitigating key exposure by storing only the hash value H(K). Since SHA-512 is a one-way function, the original key cannot be reconstructed from stored data. Access is granted only when a user-provided key satisfies H(K′) = H(K), ensuring secure key verification without revealing the key itself. In addition, user activity tracking introduces a behavioral control layer that can restrict anomalous sessions before decryption.

Integrity verification before local storage

To prevent malicious file injection, ASUT performs an integrity verification step before any file is saved locally or committed to fog storage. Specifically, after the file is encrypted with AES-256, the system computes a SHA-512 hash of the original plaintext and stores this hash separately from the encrypted file. Upon retrieval and decryption, the plaintext is re-hashed and compared against the stored hash; any mismatch indicates file tampering or corruption, and access is denied. This mechanism ensures that even if an attacker gains write access to fog storage, an injected or modified file cannot pass integrity verification without knowledge of the original plaintext hash.

Key generation processes for hashing and encryption

The creation of a key requires a security check to ensure its further use in encryption. After passing the weakness check, the key is hashed to ensure its security. The proposed design improves resistance to password-guessing and key-recovery attacks by avoiding the storage of plaintext keys. Since only the SHA-512 hash of the key is stored, an attacker must perform a brute-force search over the key space and verify each guess through hash comparison. Given the size of the AES-256 key space and the properties of SHA-512, such attacks are computationally infeasible under standard assumptions.

The SHA-512 hash of the AES key is stored alongside the ciphertext and is used solely for key verification. However, since SHA-512 is a one-way function, possession of the stored hash H(K) does not enable recovery of the original key K. The attacker cannot reverse the hash to obtain K, and therefore cannot decrypt the ciphertext. The hash is used exclusively to verify that a user-supplied key K’ matches the original by checking whether H(K’) = H(K); it provides no pathway to key recovery.

The use of symmetric encryption (AES-256) and hash functions (SHA-512) enables efficient execution in resource-constrained fog environments. Unlike asymmetric cryptographic operations such as RSA or ECC, which involve computationally expensive modular arithmetic, the proposed approach relies on fixed-round operations with lower computational overhead. This design reduces encryption and decryption time, as supported by the experimental results.

In the ASUT framework, all cryptographic operations consist of AES-256 block cipher rounds and SHA-512 compression steps. AES-256 processes data in fixed 128-bit blocks using iterative substitution and permutation, while SHA-512 applies bitwise operations over 1024-bit message blocks. Neither operation requires the large-integer modular exponentiation or elliptic-curve point multiplication that underpin RSA and ECC, respectively. Since RSA-2048 exponentiation is an O(n³) operation relative to key length, while AES-256 completes in a fixed number of rounds, the symmetric-only design of ASUT is inherently more efficient in constrained fog environments. This is confirmed by the experimental results in Sect. 5, where ASUT achieves 43.39% faster encryption and 66% faster decryption than the best-performing competing scheme incorporating asymmetric components.

AES-256 was chosen as the core encryption algorithm in ASUT because it provides a strong balance between security and efficiency for resource-constrained fog nodes. With a 256-bit key, AES offers a large key space (2²⁵⁶ possibilities), making exhaustive key-search attacks infeasible with current and foreseeable computing capabilities. It is a NIST-standardized cipher widely deployed in security-critical domains, and optimized implementations are available for most commodity processors. Using AES rather than asymmetric encryption for bulk data allows the proposed framework to maintain low latency and modest energy consumption on fog devices.

SHA-512 was selected as the hashing primitive for key protection and integrity checking. Compared to shorter hash functions such as SHA-256, its 512-bit output length significantly increases resistance to collision and preimage attacks, which is desirable when hashing long-lived encryption keys. In ASUT, the private AES key is never stored directly; instead, its SHA-512 hash serves as a hardened representation for verification and the construction of additional subkeys. This design limits the damage even if a database or fog node is compromised, since an attacker would have to invert the hash function to recover the original encryption key. Together, AES-256 and SHA-512 therefore provide a robust cryptographic foundation tailored to the performance and security requirements of fog computing.

To place ASUT in context, its security properties are qualitatively compared with those of other hybrid approaches, including ARS, A3S, RAS, R23DS, and ECC-based ERS. All of these methods provide strong cryptographic protection for data in transit and at rest. Still, they either lack integrated behavioral monitoring, rely heavily on asymmetric primitives that incur higher computational costs, or use legacy ciphers with known weaknesses. ASUT combines high-strength AES-256 encryption and SHA-512 hashing with built-in user activity tracking, thereby reducing the attack surface against insider misuse and credential compromise. Furthermore, by minimizing dependence on asymmetric cryptography in the data path, ASUT offers better scalability and responsiveness for fog-based applications that must process large volumes of encrypted data in real time.

While encryption and decryption time are important performance indicators, a security-oriented framework must also be evaluated based on its ability to mitigate diverse threats in fog computing environments. This subsection provides a qualitative security comparison between the proposed ASUT framework and representative hybrid symmetric–hashing schemes discussed in the literature.

Most existing hybrid methods primarily focus on cryptographic strength to protect data confidentiality during storage and transmission. These approaches generally assume that once users are authenticated, their subsequent behavior is trustworthy. However, fog computing environments are characterized by distributed nodes, partial trust, and increased exposure to insider misuse and compromised devices. Under such conditions, encryption alone is insufficient for end-to-end security.

ASUT addresses these limitations through a multi-layer security design. First, AES-256 is used to ensure strong data confidentiality with low computational overhead, making it suitable for resource-constrained fog nodes. Second, encryption keys are protected using SHA-512 hashing, ensuring they are never stored or transmitted in plain form and reducing the risk of exposure even if fog storage is compromised. Third, ASUT integrates user activity tracking to continuously monitor access behavior and file operations. This behavioral layer enables detection of abnormal or malicious actions, such as unauthorized access attempts or suspicious modification patterns, which cannot be prevented by cryptographic mechanisms alone.

Conclusion

The use of a hybrid symmetric–hashing scheme for data security in fog computing is a significant topic in cloud security, and this article contributes to advancing the field. In recent years, fog computing has seen a rise in the use of edge computing and storage, but this comes with significant risks to data protection. This research finding revealed that the encryption and decryption execution times of the suggested work, ASUT, consume less time than those of other models, and achieves 43.39% faster encryption and 66% faster decryption compared to the baseline method. As for encryption throughput, our proposed work achieves the highest rate of 19.86%. This approach combines symmetric encryption with hash-based key protection, making the overall security framework both effective and computationally efficient. The AES-256 and SHA-512 algorithms were chosen to encrypt the data and support a higher level of security under the evaluated conditions.

Limitations and system complexity

The proposed ASUT framework has several limitations that must be acknowledged. First, the current implementation is designed exclusively for fog-cloud environments and cannot be deployed directly in traditional cloud-only or on-premises storage architectures. Second, the framework supports a limited set of cryptographic algorithms (AES-256 and SHA-512); extending it to include asymmetric primitives such as RSA or ECC would increase computational latency and memory overhead, particularly on resource-constrained fog nodes. Third, the UAT mechanism relies on a simplified weighted-sum model (Eq. 1) that uses a rolling baseline and a fixed deviation threshold. While effective for detecting obvious anomalies, this model may generate false positives under benign traffic spikes or miss sophisticated low-and-slow insider attacks. Fourth, integrating additional security layers increases system complexity and may introduce measurable latency overhead in high-frequency IoT deployments that require sub-millisecond response times. These limitations should be considered when deploying ASUT in production environments.

Future work

Future research could examine the following directions: (1) developing a formal security proof for ASUT using game-based cryptographic definitions to rigorously bound the system’s security under standard computational assumptions; (2) integrating ASUT with a zero-trust fog architecture for continuous re-authentication and fine-grained authorization at each access event; (3) replacing the weighted-sum UAT model with a machine-learning-based anomaly detection engine trained on behavioral baselines, which could improve detection accuracy and reduce false-positive rates; (4) evaluating ASUT on heterogeneous IoT hardware platforms (e.g., Raspberry Pi, ARM-based fog nodes) to measure real-world latency and throughput under resource-constrained conditions; and (5) investigating post-quantum secure key-establishment and signature mechanisms, while reassessing the role of AES and SHA-512 under quantum attack models.
