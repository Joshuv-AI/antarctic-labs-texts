4
Creating a new model

FeynMaster
is a model dependent program: it cannot run without the specification of a model.
As already mentioned, one of the major simplifications of
FeynMaster
2 lies in model building: while in the previous version the specification of each model required two files, in
FeynMaster
2 only one file is required to fully define a model.
This one file — which we now identify as
the

FeynMaster
model file — is essentially a regular model file for
FeynRules
;
as such, it has the termination
.fr
.
5
5

5

It is assumed here that the user is familiar with
FeynRules
and knows how to create a
FeynRules
model. If this is not the case, we refer to the
FeynRules
website
https://feynrules.irmp.ucl.ac.be/
. Finally, it should be clear that the
FeynMaster
model file can always be used as a
FeynRules
model file.

Its name is identified in the following as the
internal name
of the model. This model file must be inside a folder with the same name — that is, with the internal name of the model —, which in turn must be inside the folder with the models for
FeynMaster
.

FeynMaster
already comes with three models : QED, Scalar QED (SQED) and the Standard Model (SM).
6
6

6

The SM model file is written in an arbitrary
R_{\xi}
gauge and with the
\eta
parameters of ref.
[
33
]
, and it closely follows ref.
[
34
]
for renormalization.

These serve as prototypes, and we highly recommend them as guiding tools in the creation of a new model.
Since there are already models available, this section can be skipped in a first utilization of
FeynMaster
.

FeynMaster

Parameters

Parameters are defined via the usual
FeynRules

Different attributes can be associated to a certain parameter; their order is irrelevant.
As in
FeynRules

The

The backslash should always be doubled in

Parameters can have indices, which are defined as in
FeynRules
(ex:

).
10
10

10

In this example, the range of

= Range[3]

A numerical value can be given to a parameter through the attribute

11

The attribution of numerical values is useful only in case the user wants to exploit the numerical interface of

The renormalization rule for a parameter can be defined through the attribute

Renormalization -> {mf -> mf + dmf}

12

12

It should be clear that it is not mandatory to define renormalization rules. That is,
FeynMaster

Finally, note that, if a parameter is complex, the renormalization of its complex conjugate is automatically considered.

Finally, parameters corresponding to counterterms should be flagged by setting the attribute

13

13

There can be counterterms for both parameters and fields; since counterterms themselves are parameters, they are defined in the parameters sections

Particle classes

Particles are defined via the usual
FeynRules

M$ClassesDescription
;
again, the order of attributes associated to a certain parameter is irrelevant.
The

The attribute

Unphysical particles (except Weyl fermions) should be flagged with the attribute

Every propagating particle must have a mass assignment, either to a variable or to 0 (ex:

Propagating particles should also have a

The decay width can be defined through

14
14

14

The decay width thus defined will show up in the denominator of the propagator of the particle at stake whenever such propagator mediates the

Weyl components must be specified for Dirac fermions whenever the latter are composed of Weyl particles defined in the model (ex:

Neutrinos should be flagged with the attribute

15

15

This is relevant only for the definition of number of polarizations in decay or scattering processes. In particular, the functions

Finally, renormalization is defined in a way similar to that of the parameters (ex:

In the case of gauge bosons, generic Lorentz indices should be included; ex:

Concerning the

At this point, we should clarify the difference between UV divergences and infrared (IR) divergences. It is well known that, while the former are in general present in loop integrals, the latter can only show up when there is a massless particle running inside the loop (in which case the IR divergence comes from the integration region near

Indeed, we assume that the IR divergences can be regulated by giving the massless particle a fake mass — which one shall eventually be able to set to zero in physical processes, after considering real emission graphs. With that assumption, IR divergences will never show up explicitly (only implicitly through the fake mass). In the following, unless in potentially dubious statements, we will stop writing UV explicitly: it is assumed that, whenever we mention divergences, we shall be referring to UV divergences.

M=\epsilon_{1}^{\nu}\epsilon_{2}^{\sigma}\,M_{\nu\sigma},

and

For a quick first usage of
FeynMaster
, the user should follow this sequence of steps:

1) Make sure you have installed
Python
,
Mathematica
and
L
a
T
e
X
, on the one hand, and
FeynRules
,
QGRAF
and

, on the other;

2) Download
FeynMaster
in
https://porthos.tecnico.ulisboa.pt/FeynMaster/
;

3) Extract the downloaded file and place the resulting folder in a directory at will;

4) Edit the file
RUN-FeynMaster

2
;

5) Run
RUN-FeynMaster

This should generate and open 4 PDF files relative to QED: the Feynman rules for the tree-level interactions, the Feynman rules for the counterterms

\overline{\text{MS}}
