J. Cheukam Ngouonou 1,2,4, R. Gindullin 1,2, C.-G. Quimper 4, N. Beldiceanu 1,2 and R. Douence 1,2,3

Abstract
We present an improved incremental selection algorithm of the selection algorithm presented in [ 1 ] and prove all the selected conjectures.

An Incremental Selection Algorithm

We present an incremental version of the selection algorithm described in
[
1
]
.
Unlike our original algorithms, we do not post the candidate bound constraints from scratch during each step of the dichotomic search;
nor do we scan the set of solutions from scratch when looking for the next candidate bound constraint to select.

In the following, we assume that if a constraint fails while being posted, it will be removed by the solver.
Given the set of constraints already posted
\mathcal{C}
, the function
\mbox{Labeling}(\mathit{Feat\!Vars},\mathcal{X})
returns a triplet
(\mathit{NBack},\mathit{Finished},\mathit{Sol})

\mathit{Sol}
is the first solution found that satisfies all the constraints of
\mathcal{C}
by assigning the variables of
\mathit{Feat\!Vars}
and
\mathcal{X}
from left to right, assuming that the variables are fixed by scanning their domains by increasing values:

–

\mathit{NBack}
is the number of backtracks to find a solution or prove that there is no solution,

–

\mathit{Finished}
is set to
true
if no solution could be found, and to
false
otherwise,

–

\mathit{Sol}
is meaningless if no solution was found.

Lines 1–5 split the list of candidate bound constraints

The current way to split

We prefer to incrementally add a limited number of bound constraints so that we end up in a situation where we do not have enough constraints and this increases the number of backtracks needed to find a solution.
Otherwise, adding too many bound constraints would result in not increasing the number of backtracks, which would have the effect of scanning all remaining solutions in
\mathit{Sols}

As a result, the same solution from

\displaystyle(\underline{M}+r_{2})^{2}+2(r_{2}-r_{1})+2
