Multi-Document Grounded Multi-Turn Synthetic Dialog Generation
Young-Suk Lee *, Chulaka Gunasekara, Danish Contractor

Abstract
We introduce a technique for multi-document-grounded multi-turn synthetic dialog generation that incorporates three main ideas. First, we control the overall dialog flow using taxonomy-driven user queries that are generated with Chain-of-Thought (CoT) prompting. Second, we support the generation of multi-document-grounded dialogs by mimicking real-world use of retrievers to update the grounding documents after every user-turn in the dialog. Third, we apply LLM-as-a-Judge to filter out queries with incorrect answers. Human evaluation of the synthetic dialog data suggests that the data is diverse, coherent, and includes mostly correct answers. Both human and automatic evaluations of answerable queries indicate that models fine-tuned on synthetic dialogs consistently out-perform those fine-tuned on existing human generated training data across four publicly available multi-turn document grounded benchmark test sets.

Subsequent user queries and all agent answers are grounded on the retrieved passages and dialog history. We use a series of carefully designed prompts to ensure generated agent answers continue to remain meaningful in the presence of retrieved passages, often noisier than human generated documents. 2
Multi-turn Dialog Generation

Our multi-turn dialog generation consists of four components: (1) Two question taxonomies - one designed for the first turn of the dialog (ST-QT) and the other for subsequent turns (MT-QT). (2) Chain-of-Thought (CoT) prompting to generate desired query types according to question taxonomy, (3) Two separate synthetic data generation pipelines for single-document and multi-document grounded dialogs. (4) LLM-as-a-Judge to filter out dialogs containing incorrect answers for any given queries.

2.1
Question Taxonomy

To ensure that generated dialogs are diverse we devise a question type taxonomy. This taxonomy is a subset of contemporaneous ideas presented in
Yang et al. (2024)
and covers the most critical query types found in RAG datasets. We adopt the following question taxonomy for all initial user queries:

Direct
: Free form questions whose answer can be directly extracted from the grounding document

Comparative
: Questions that request comparisons between different entities and/or concepts

Aggregate
: Questions that require synthesis of information from multiple documents or paragraphs

Unanswerable
: Questions that request information unavailable in the given documents

For subsequent user turns, we use the following:

Follow-up
: Questions that build on previous responses, typically with elliptical phrases such as
what about, how about, etc.

Clarification
: Questions that seek to resolve ambiguities, as in
you mean, does that mean

Correction
: Questions that aim to rectify errors or misunderstandings from earlier conversations, as in
no, that’s not what I meant

2.2
Query generation with CoT Prompting

To ensure that the generated queries
conform the pre-specified question taxonomy, we incorporate question-type specific CoT prompts that instruct an LLM to reason through the grounding document.

While most previous work adopts CoT prompts for accurate answer generation in reasoning tasks
Wei et al. (2022)
;
Kojiman et al. (2022)
;
Yao et al. (2023)
, we found it effective for steering an LM to generate queries of desired properties. We use a CoT prompt in zero-shot setting for initial turns and few-shot setting for subsequent turns. In our experiments, we found that using
3
in-context learning (ICL) examples of a question type (ex: comparative questions) without CoT prompt resulted in only 5% of the intended query type,
whereas CoT prompt for a specific query type without any ICL examples resulted in more than 90% of the generated queries adhering to the intended query type.

Our data generation framework is flexible enough to incorporate any changes to the taxonomy, as a user could create new prompts for additional question types, and run the rest of the data generation pipeline.

2.3
Response generation with CoT Prompting

For generating the agent answers, we utilize another CoT prompt. This CoT prompt includes a reasoning step to explain how the model looks for the answer in the available documents, and then generates the answer grounded on the documents and generated reasoning. To ensure that the model generates consistent (w.r.t. the generated reasoning) and faithful (w.r.t. the documents), the CoT prompt instructs the LLM to perform a consistency check (inspired by
Wang et al. (2022a)
), and extract evidences from the documents.
This dual use of CoT for both query and answer generation
ensures that the interactions are both rich and logically consistent. We use greedy decoding for each user and agent turn generation and top-k sampling (k=50)
Fan et al. (2018)
for all other steps. All of the CoT prompt templates used in this study are available in Figures

-

(Appendix).

2.5
LLM-as-a-Judge for Correctness

We incorporate an LLM-as-a-Judge module to filter out queries with incorrect answers. For each generated dialog, we first extract all context-response pairs, consisting of dialog history plus the current query and its answer, as shown in Figure

(1) What is the difference in performance when using generated synthetic data in place of human-generated data for training content-grounded conversational models? (2) Is multi-document grounded data generation useful for tasks evaluated in multi-document settings, e.g. RAG?

Related Work

Baize
Xu et al. (2023)
propose a seed-driven self-chat technique for generating open-domain multi-turn user-agent conversations by enabling ChatGPT to engage in a conversation with itself, using Quora and Stack Overflow as seeds.
UltraChat
Ding et al. (2023)
demonstrated the efficiency of scaling up LLM-based conversation generation. Unlike our work, it focuses on covering a wide range of topics, rather than multi-turn conversations.

Recent work has also explored different forms of grounding when generating conversations – grounding on personas
Jang et al. (2022)
;
Bao et al. (2023)
, topics
Abbasiantaeb et al. (2024)
, conversation summaries
Gunasekara et al. (2021)
, conversation instructions
Mohapatra et al. (2021)
and single-document
Sultan et al. (2024)
;
Abbasiantaeb et al. (2024)
.
Chen et al. (2023)
generate conversations by grounding on retrieved knowledge graphs. In contrast we focus our work on multi-document grounded dialogs.

QuAC
Choi et al. (2018)

is a human generated multi-turn conversational benchmark. The data collection process resembles RAG setup with non-RAG characteristics for many initial queries. OR-QuAC
Qu et al. (2020)
tackles this problem by replacing initial questions in QuAC with their context-independent rewrites provided in CANARD dataset
Elgohary et al. (2019)
.
Our RAG-style multi-turn dialog generation closely resembles OR-QuAC.
Nonetheless, OR-QuAC relies on the human generated dialogs from QuAC and some of the rewrites from CANARD. Furthermore, their grounding passages are based on human generated queries and answers.
Multidoc2Dial
Feng et al. (2021)
is designed for information-seeking dialogs grounded on multiple documents. Aside from the fact that grounding documents is human generated in MultiDoc2Dial and automatically generated by retrievers in our work, we automatically generate both the agent answers and user queries whose style and content are guided by query taxonomy and CoT-prompting.

5
Conclusion

We presented a multi-turn synthetic dialog generation technique that incorporates a novel idea of taxonomy driven user query generation with CoT prompting, dialog generation from multi-documents updated by a retriever and an LLM-as-a-Judge module to select dialogs with correct answers.
Human evaluations suggest that the synthetic data is diverse, coherent, and includes mostly correct answers. Human and automatic evaluations indicate models fine-tuned on our synthetic dialogs out-perform those fine-tuned on human generated benchmark data for answerable queries. Performance comparisons of OR-QuAC testset on models fine-tuned on single- versus multi-document grounded data suggest that multi-document grounded data generation is more effective for multi-document grounded tasks.

6
Limitations

The method employs
mixtral-8x7b-instruct-v0.1
in the public domain. Therefore, the generated synthetic data can be susceptible to the limitations of the language model, particularly the biases inherent in the training data which may be harmful leading to synthetic data with hate, abuse and social stereotypes.

For multi-document grounded generation, there is no straightforward way of applying unanswerable query taxonomy to document retrieval, which always tries to retrieve relevant documents to a given user query. The query answerability may be determined only after examining whether or not the retrieved passages contain the correct answer to the query. This is unlike the single-document grounded data generation pipeline for which the grounding document is provided before query generation and therefore, one can steer an LM to generate a query whose answer cannot be found in the provided document.
In addition, the benchmark test sets used in the evaluations have dataset specific categorical answers for unanswerable queries whereas the synthetically generated dialogs have often correct natural, contextual responses with no lexical overlap with the categorical reference answers. This may under-report any benefit from the use of our synthetic data for evaluation of unanswerable queries.
We leave evaluation and generation of unanswerable queries in a multi-document grounded dialog generation setup to future work.
