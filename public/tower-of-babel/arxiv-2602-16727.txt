Abstract
. Large-scale human mobility simulation is critical for applications such as urban planning, epidemiology, and transportation analysis. Recent works treat large language models (LLMs) as human agents to simulate realistic mobility behaviors using structured reasoning, but their high computational cost limits scalability. To address this, we design a mobility-aware cache framework named MobCache that leverages reconstructible caches to enable efficient large-scale human mobility simulations. It consists of: (1) a reasoning component that encodes each reasoning step as a latent-space embedding and uses a latent-space evaluator to enable the reuse and recombination of reasoning steps; and (2) a decoding component that employs a lightweight decoder trained with mobility law-constrained distillation to translate latent-space reasoning chains into natural language, thereby improving simulation efficiency while maintaining fidelity. Experiments show that MobCache significantly improves efficiency across multiple dimensions while maintaining performance comparable to state-of-the-art LLM-based methods.



1.
Introduction

Understanding human mobility is essential for many science domains such as urban science
(
38
;
39
)
, epidemiology
(
10
;
9
)
, and transportation analysis
(
34
;
25
)
.
Effective human mobility analysis typically relies on large-scale, fine-grained mobility data that capture population-level movement patterns over space and time. In practice, such data are mainly obtained through two channels. Travel surveys record individual trips but suffer from recall bias, sparse temporal sampling, and high collection costs
(
36
;
26
)
. Sensor-based tracking, such as mobile-phone traces or Bluetooth beacons, provides denser temporal coverage but depends on device penetration and raises significant privacy concerns
(
5
;
18
)
. As a result, both channels face challenges in scaling to millions of agents while preserving privacy, motivating the need for privacy-preserving alternatives such as mobility simulation.

A growing body of recent work leverages large language models (LLMs) to simulate human mobility trajectories without relying on real mobility traces
(
14
;
8
;
28
;
22
;
16
;
32
;
1
;
20
)
.
These methods typically model an LLM as a virtual human agent and prompt it to perform step-by-step reasoning over mobility intentions and activities. While such methods can produce realistic mobility behaviors, they often incur substantial computational costs. For instance, simulating one million agents for a single day can exceed $1,000 in API fees under current token pricing schemes
(
31
;
4
)
.
There are two main methods to reduce cost.
First, a group-based methods divides agents into coarse profile groups (e.g., by job and income) and calls the LLM once per group to generate trajectories
(
6
)
. However, the method forces every agent in the same group to share identical behavior, which reduces individual diversity.
Second, by processing multiple I/O operations simultaneously and reusing TCP connections, the system can handle many requests at the same time
(
40
;
28
)
. But each agent still needs one LLM call for every trajectory, so the total monetary cost of these methods remains high.

A natural way to reduce repeated LLM calls is
response caching
, where input–output query pairs are stored locally and reused whenever a similar query arises.
This caching paradigm has proven effective in many domains such as e-commence
(
43
)
, intelligent QA systems
(
7
)
and Machine Translation
(
11
)
.
Note that this paradigm is orthogonal to other caching mechanisms such as KV caching
(
15
;
44
)
, and we provide a comparison in the related work section.
However, response caching suppresses diversity. Common queries—such as
“What is the next activity for a software engineer who has just finished work?”
—often hit the same cached answer, for example a nine
-
to
-
five schedule, even though real workers also take night shifts, overtime, or flexible hours. The resulting lack of behavioral variation lowers simulation fidelity (see Section
2.1
and Section
4.7
).

To overcome this limitation, we design a new caching paradigm in which we cache the reasoning steps produced by LLMs when generating mobility data, rather than directly caching the final responses.
This paradigm is motivated by prior work
(
32
;
14
)
, which indicates that mobility behaviors are typically generated via multi-step reasoning processes.
By representing reasoning steps as nodes in a tree, we can flexibly recombine existing cached reasoning steps to obtain new responses, which enhances reusability and diversity (as shown in Figure
1
).
We name it
reconstructible caches
.
A straightforward implementation would represent reasoning steps in natural language and reconstruct reasoning chains by concatenating steps from multiple cached chains. However, although this method increases response diversity, it does not guarantee mobility awareness (e.g., inherent spatial or temporal constraints in mobility patterns
(
42
;
37
)
), thus limiting fidelity.

To this end, we design a mobility-aware cache framework that builds reconstructible caches to enable efficient large-scale human mobility simulations.
This framework enables the reuse and recombination of mobility-aware reasoning chains by addressing challenges from both the reasoning and decoding perspectives:

Reasoning perspective
:
A major obstacle to generating mobility-aware reasoning chains is the direct use of explicit language tokens, which are not flexible enough to incorporate mobility-specific constraints.
To address it, we shift the reasoning process into latent space
(
13
;
35
)
, representing each reasoning step as a latent-space embedding rather than language tokens.
This shift provides two advantages.
First, mobility constraints can be directly embedded into latent-space embeddings during learning.
Second, these embeddings implicitly encode diverse reasoning patterns and decision paths
(
13
;
30
)
, which enables efficient exploration of logically consistent reasoning chains through mobility-aware decoding (explained in the decoding perspective).
Additionally, we design a latent-space evaluator guided by a fine-tuned LLM to identify valid reasoning paths within the latent space.

Decoding perspective
:
After obtaining the reconstructed reasoning chains in the latent space, we design a lightweight decoder trained through mobility law-constrained distillation.
This decoder efficiently translates latent reasoning chains into natural language.
This strategy avoids repeated calls to the original LLMs for decoding while achieving comparable performance, thereby ensuring efficiency and fidelity in large-scale simulations.

In particular, our main contributions are as follows.

•

We explore the idea of building reconstructible caches in latent space to accelerate large-scale LLM-based mobility simulation. We aim to improve not only simulation efficiency but also mobility data diversity.

•

We present MobCache, a mobility
-
aware cache framework with two key components:
(1) a reconstructible cache that stores latent-space reasoning embeddings produced by a fine-tuned LLM and supports tree-structured search for flexible recombination;
and (2) a lightweight decoder trained via mobility law-constrained distillation that converts latent-space reasoning chains into natural language while maintaining spatial and temporal consistency.

•

We conduct extensive experiments, and the results show that our method outperforms all baselines across multiple efficiency metrics while maintaining comparable performance in quality metrics, achieving at least a 42.20% reduction in inference time, an 79.71% increase in tokens per second, a 28.56% improvement in throughput, and a 42.46% reduction in cost.
In a case study, we apply MobCache to enhance the simulation efficiency of Urban-Mobility-LLM, showing a 66.93% reduction in inference speed and a 93.18% reduction in cost without sacrificing quality.

2.2.
Logic inconsistency of reasoning chain reconstruction in language space

A common idea for reusing existing reasoning chains is to recombine reasoning steps directly in natural language space. Suppose we have many textual reasoning chains in a cache. When going through a textual reasoning chain, we may want to branch at some point to extend it with a new plausible continuation. A straightforward approach is to compute the similarity between the current textual reasoning step and candidate textual reasoning steps using a language model (e.g., sentence-transformers/all-MiniLM-L6-v2). If the similarity between two textual reasoning steps exceeds a threshold, we link them to form a new reasoning chain.

However, this language-based way of recombining reasoning steps has an important limitation: even if the text is fluent, the underlying logic may be incorrect. As shown in the example in Box, the third step contains a holiday-related shopping trip on November 2nd, even though there are no upcoming holidays. The distance is calculated from the workplace. However, the person was previously at home, and it is a weekend, so they should not be at work. This indicates that the reasoning steps are logically inconsistent.

3.
Design

3.1.
Problem formulation

Given profiles of individuals such as age, income, occupation, and home locations and the city’s points of interest (POIs), our goal is to design an efficient human mobility simulator. This simulator should not only generate realistic daily human mobility trajectories but also be capable of efficiently simulating tens or hundreds of thousands of individuals.

3.2.
Overview

We design MobCache, a mobility-aware caching framework that builds reconstructible caches to enable efficient and large-scale human mobility simulation.
The workflow of MobCache is shown in Figure
4
, which consists of two stages: a training phase that builds reconstructible caches from LLM-generated mobility trajectories, and an inference phase that generates new mobility trajectories by reusing the caches.

Training phase:

For reconstructible cache construction, we first utilize existing LLMs (e.g., GPT) to generate small-scale mobility data in the form of
textual paired reasoning chains and mobility activities
, where the reasoning chains capture the intention behind each activity. Such data can also be obtained from existing mobility simulation works
(
32
)
.
To enable structured reasoning in the latent space, we then fine-tune the LLM using these mobility data (i.e., textual paired reasoning chains and mobility activities) with a latent-space reasoning training strategy
(
13
)
, thereby producing
paired latent-space reasoning chains and textual mobility activities
.
These latent-space reasoning chains are then used to build a reconstructible cache.
The cache construction consists of three components:
(1) Storage of latent-space reasoning chains, which enables tree-structured search for flexible reasoning reconstruction.
(2) A latent-space evaluator, which assesses the plausibility of branching new latent-space reasoning chains within the cache.
(3) A lightweight decoder, which decodes latent-space reasoning chains into textual mobility activities.

Inference phase:

For a new user, we first identify cached users whose context information (e.g., profile and date) is most similar to that of the new user.
We then obtain latent-space reasoning chains for this new user from the cache, starting from the matched cached user, using different strategies: either by following existing chains or by exploring the cache to generate new ones.
Finally, we decode the new user’s latent-space reasoning chains into textual mobility activities using the lightweight decoder, and then map them to real geographic locations with a mapping model.

3.3.
LLMs fine-tuning for latent-space reasoning

3.3.1.
Data initialization

We first leverage general LLM-based human mobility simulation methods to generate a small-scale mobility dataset for cache construction.
In our work, we use GPT as the generator with task-specific prompts, but this step can be replaced by other LLM-API-based human mobility simulation method
(
32
;
1
)
.
Following existing works, the generated data are in the form of textual paired reasoning chains and mobility activities, where the reasoning chains capture the intention behind each activity.
To ensure the required data format, we construct prompts that include the person’s demographic profile (e.g., income and occupation), the date, nearby POIs around their home and workplace, and other task-specific requirements.
An example is provided in the appendix.

3.3.2.
Latent-space reasoning

To facilitate reuse of reasoning chains, we shift the reasoning process into the latent space
(
13
;
35
)
, where each reasoning step is represented as a latent-space embedding instead of a language token.
Under standard chain-of-thought (CoT) reasoning training, the LLM is supervised to generate both intermediate reasoning steps and the final answer as text tokens.
In our latent-space reasoning training, we replaces the explicit reasoning step outputs with latent-space reasoning embeddings.
Specifically, given an input prompt, the LLM is trained to produce latent-space reasoning embeddings
r_{t}
at each reasoning step, which replace token-level outputs and are recursively fed back into the LLM as inputs for subsequent reasoning, while the final answer (i.e., final mobility activities) is still generated in language.
The process is formulated by

r_{t}=f_{\theta}(q,R_{1:t-1}),

where
q
is the input prompt and
R_{1:t-1}=[r_{1},r_{2},\ldots,r_{t-1}]
are previous latent-space reasoning embeddings. The latent-space reasoning embedding
r_{t}
is used as input for generating the next latent-space reasoning embedding.

Multi-stage training process:

We achieve the transition from CoT reasoning to latent-space reasoning through multi-stage training.
The LLM is first fine-tuned using the standard CoT training.
To achieve latent-space reasoning, we then progressively replace textual reasoning steps with latent-space reasoning embeddings from earlier to later steps.
Specifically, at each stage
t
, the first
t
reasoning steps are replaced by latent embeddings
R_{1:t}
, while the remaining reasoning steps and the final answer are still supervised in text.
This continues until all reasoning is performed in the latent space, while the final answer
y
(i.e., mobility activities) remains under language-level supervision:

\max_{\theta}\ \log p_{\theta}(y\mid q,R_{1:t}).

3.4.
Reconstructible cache building

3.4.1.
Store latent-space reasoning chains

The latent-space reasoning chains are then used to build a reconstructible cache.
Specifically, each entry in the cache corresponds to a chain, which consists of: (1)
prompt:
the initial task input, denoted as
q
.
(2)
latent-space reasoning embeddings:
intermediate reasoning steps in latent space, denoted as:
R_{1:t}=[r_{1},r_{2},\ldots,r_{t}],
where each
r_{t}
is the latent-space reasoning embedding at reasoning step
t
.
Each chain can be viewed as a tree where latent-space reasoning embeddings serve as nodes, and branches can be extended from any intermediate nodes to connect with other chains, which enables flexible tree-structured search and reasoning recombination.

3.4.2.
Construct new reasoning chains

After storing the latent-space reasoning chains in the cache, we can further utilize these cached reasoning chains to generate new reasoning chains by branching from existing chains.
However, latent-space reasoning embeddings are not interpretable by humans, making it hard to determine which branches are logically valid and consistent with human reasoning.

To assess whether each branch is valid, we design a latent-space evaluator that outputs a score indicating how promising a given branch is.
Formally, the latent-space evaluator model
g_{\xi}
is trained to predict a score:
\sigma_{t}=g_{\xi}(q,R_{1:t-1},r_{t}),

where q is the prompt and
R_{1:t-1}=[r_{1},r_{2},\ldots,r_{t-1}]
is the sequence of previous reasoning steps.
\sigma_{t}
indicates the estimated quality of including
r_{t}
as the next reasoning step.
In our work, the latent-space evaluator is implemented using a Transformer-based architecture, which allows it to effectively capture the contextual dependencies within reasoning chains when assessing their validity and coherence.

Label construction:

To construct labels for latent-space evaluator training, we adopt a similarity-based method:

(1) Generate next latent-space reasoning step.
For each training example
(q,R_{1:t-1})
, we use the fine-tuned LLM (details in Section.
3.3
) to generate the next latent-space reasoning steps:
\hat{r}_{t}
.

(2) Compute similarity-based labels.
Given a candidate reasoning
r_{t}
, its supervision label
b_{t}
is computed as:
b_{t}=\text{sim}(r_{t},\hat{r}_{t}),

where
\text{sim}(\cdot,\cdot)
is a similarity function (e.g., embedding cosine similarity or model-based scoring). Intuitively,
b_{t}
is high if
r_{t}
is similar to next latent-space reasoning steps:
\hat{r}_{t}
, and low otherwise.
The evaluator is trained to minimize the squared error between the predicted scores and supervision labels
\mathcal{L}=\sum_{t}(\sigma_{t}-b_{t})^{2}
.

3.4.3.
Lightweight decoder

After that, we use a decoder to convert all latent-space reasoning chains from the cache into textual activities.
This process was originally handled by the LLM described in Section
3.3
. However, to reduce dependence on large models and enable efficient decoding, we instead train a lightweight decoder.

Distillation:

Our goal is to decode each latent-space reasoning chain into its final answer, i.e., the textual mobility activities.
Formally, given a reasoning embedding chain
R=(r_{1},\dots,r_{T})
, the decoder generates an activity sequence
Y=(y_{1},\dots,y_{L})
in an autoregressive manner. Here,
r_{t}
denotes the latent-space embedding of the
t
-th reasoning step, and
y_{l}
denotes the
l
-th output token.
In the original pipeline, the decoding process is performed by the LLM (described in Section
3.3
), which serves as the teacher decoder.
To reduce dependence on large models and enable efficient decoding, we instead train a lightweight decoder as the student decoder to learn the same mapping from
R
to
Y
.
The lightweight decoder is trained using standard cross-entropy loss:

\mathcal{L}_{\text{distill}}=-\sum_{l=1}^{L}\log P_{\rho}\!\left(y_{l}\mid y_{<l},\hat{R}\right),

where
\rho
denotes the parameters of lightweight decoder,
\hat{R}
is the lightweight-side input representation of the cached reasoning chain, and
y_{l}
denotes the
l
-th token generated by the teacher decoder.
Since the dimensionality of the reasoning embeddings
R
from the teacher decoder differs from that of the lightweight decoder, we introduce an MLP projector
e_{\mu}
to project each latent embeeding from the teacher decoder into the lightweight decoder space and forming
\hat{R}=e_{\mu}(R)
as the decoder input.

Mobility law constraint:

To improve the quality of distillation, we introduce explicit mobility law constraints to the training process.
Specifically, we penalize the distributional discrepancy between the mobility law statistics produced by the lightweight decoder and those produced by the teacher decoder.
Given the activity sequences
Y_{\text{teacher}}
generated by the teacher decoder, we apply a statistics function
d(\cdot)
to extract
mobility law features (e.g., jump distances) and obtain the corresponding distribution
p_{\text{teacher}}(d(Y))
.
For the lightweight decoder, to make the entire process differentiable, we further learn a function
z_{\tau}
(e.g., an MLP) that predicts mobility law distributions from the lightweight decoder’s hidden states
h_{\text{light}}
.
The predicted distribution
z_{\tau}(h_{\text{light}})
is encouraged to match the teacher distribution
p_{\text{teacher}}(d(Y))
, by minimizing the Kullback–Leibler (KL) divergence:

\mathcal{L}_{\text{law}}=\mathrm{KL}\!\left(z_{\tau}(h_{\text{light}})\ \|\ p_{\text{teacher}}(d(Y))\right).

Training objective:

The training objective combines the distillation loss
L_{\text{distill}}
with the mobility law constraint loss
L_{\text{total}}=L_{\text{distill}}+\lambda L_{\text{law}},

where
\lambda
is a trade-off parameter.

3.5.
Inference

For a new user’s mobility trajectory generation, we first identify cached users whose context information (e.g., profile and date) is most similar to that of the new user.
If no cached user exceeds the predefined similarity threshold, we directly invoke the fine-tuned LLM to generate a new reasoning chain and mobility activities, which are then stored in the cache for future reuse.
Otherwise, if a similar cached user is found, we have strategies for searching reasoning chains in the cache:

•

Follow existing chains.

We directly use the reasoning chain of the most similar cached user for the new user.

•

Explore alternative chains.

Starting from the reasoning chain of the retrieved similar user, we go through the chain and randomly select a node as a branching point. From this point, we search the cache for several candidate latent-space embedding nodes from other reasoning chains based on embedding similarity.
A latent-space evaluator then scores these candidates and selects the most plausible one.
The selected node is appended to the current chain, after which we repeat the above procedure by selecting a new branching point and extending the chain again.
This process is repeated for a fixed number of iterations.

•

Generate new chains.

If the latent-space evaluator assigns low scores to all available branching nodes, we invoke the LLM to generate a new reasoning chain, which is then stored in the cache for future reuse.

We use an exploration rate to control the probability that the model follows an existing chain or explores a new branch.
After obtaining a valid reasoning chain using these strategies, we input it into the lightweight decoder to decode the corresponding textual mobility activities. Finally, these textual activities are mapped to real geographic locations to form trajectories using the gravity model.

4.1.
Dataset description

We use two public mobility datasets.
One dataset is collected in Beijing, China, covering the period from October 1, 2019 to December 31, 2019
(
32
)
.
The dataset contains mobility trajectories and user profile information (e.g., age, gender, and occupation), collected via a social networking platform.
Another dataset is the NYC POI check-in dataset. For this dataset, we simulate users’ profiles based on U.S. Census demographics
(

4.2.
Evaluation setup

4.2.1.
Evaluation configuration

We first select 4,000 people from the real-world dataset and use an LLM to generate 13,000 synthetic human mobility trajectories based on their profiles. These generated synthetic mobility trajectories are then used to fine-tune an LLM (details in Section
3.3
) to produce latent-space reasoning chains. These latent-space reasoning chains are stored to construct our mobility cache. For evaluation, we further sample 10,000 real trajectories as the test set, ensuring no user overlap with the cache. Generated trajectories are evaluated against the test set.

4.2.2.
Implementation

We implement our method using Python 3.10 and PyTorch 2.1.0. The LLM we use is LLaMA 3.2-3B, and the lightweight decoder we use is the LLaMA 3.2-1B. Model training is conducted on both NVIDIA A100 and NVIDIA A6000 GPUs using the Adam optimizer with a learning rate of 5e-5.
To determine profile similarity during cache retrieval, we employ the pre-trained language model
(
29
)
.
We test the exploration rate in [0.3, 0.5, 0.7] and select 0.5 based on the efficiency and quality trade-off.
We test
\lambda
in [0.01, 0.03, 0.05, 0.07] and select 0.05 based on the best performance.
The number of search rounds is randomly sampled between 1 and 3.

Baselines

We compare our method with two categories of LLM-based human mobility simulation baselines: methods not requiring real-world data for training and methods requiring real-world data for training. Our method belongs to the former category.

(i) Methods not requiring real-world data for training
:
CoPB
(
32
)
is a mobility simulation framework guides LLMs through structured reasoning stages to generate realistic mobility intentions.

Urban-Mobility-LLM

(
1
)
is a method that synthesizes travel survey data by prompting LLMs to generate individual mobility patterns.

LLMob
(
14
)
is an LLM-based agent framework for personal mobility generation, combining self-consistency and retrieval strategies.

(ii) Methods requiring real-world data for training
:
Geo-LLaMA

(
20
)
is a fine-tuning framework that enables LLMs to generate realistic human trajectories under multiple spatiotemporal visit constraints.
We train Geo-LLaMA on 10,000 real-world trajectories from the Beijing dataset and one-week trajectories from the NYC check-in dataset.

We also conduct comparisons with several variants of the model: (1)
MobCache without latent-space evaluator (w/o LE)

MobCache without mobility law distillation (w/o MD)

. In this setting, we remove the lightweight decoder and use the original LLM for latent embedding decoding.

4.2.4.
Metric

We evaluate our model from two perspectives: efficiency and generation quality.

Efficiency evaluation:
. To assess simulation efficiency, we evaluate it from four perspectives.
(1) Inference time (s/trajectory): the average inference time required to generate a single simulated trajectory.
To conduct a fair comparison, all methods perform inference sequentially, without parallel or batched execution.
(2) Tokens (tokens/s): the number of tokens processed per second during inference.
(3) Throughput (trajectories/s): the number of complete trajectories generated per second when processing requests in batches (batch size = 8).
(4) Monetary cost ($/trajectory): we estimate the average expense per trajectory under the setting of generating 100K trajectories. For local LLMs (Geo-LLaMA), we compute average inference time per-trajectory and multiply it by a realistic GPU rate ($0.5/hour on an A6000) to obtain the total cost. For API-based LLMs (Urban-Mobility-LLM and CoPB), we approximate the average number of output tokens per trajectory and apply GPT-4o’s official rate of $10 per 1M output tokens (input tokens are ignored), so the API figures represent strict lower bounds.

Quality evaluation:
. To evaluate the similarity between generated and real-world mobility data, we compute the Jensen–Shannon divergence (JSD) between their distributions on five key metrics following existing work
(
32
;
12
;
33
)
: (1) Radius of gyration: measures the spatial dispersion of individual mobility. We compute the radius of gyration for each individual as the root mean square distance from all visited points to the individual’s trajectory centroid.
(2) Stay duration: measures how long individuals remain at each visited location. We compute the duration distribution from the time intervals between consecutive movements.
(3) Jump length: measures the distance between consecutive visited locations. We calculate it as the geographical distance between two consecutive locations in a trajectory.
(4) Location frequency (LocFreq): measures how well the generated trajectories replicate the spatial distribution of visits. We compute location frequency as the JSD between the spatial visit frequency distributions of the generated and real trajectories.
(5) Origin-destination similarity (OdSim): measures the similarity between generated and real trajectories in terms of OD travel patterns. It is computed by comparing the normalized frequency distributions of OD pairs using JSD.

4.6.
Evaluation of decoding results via LLMs

In addition to evaluating overall performance, we also ensure that the mobility activities decoded from the cache are behaviorally reasonable.
To this end, we use an LLM (i.e., GPT-4o) as an evaluator to assess the quality of decoded results produced by our method and by MobCache w/o LE.
Specifically, we first input the user’s profile and its decoded mobility activity sequence into the LLM. We then prompt the LLM to determine whether the mobility activity sequence is plausible for that individual (i.e., a binary yes/no judgment). We finally compute the percentage of "yes."
Experiments show that 91% of decoded sequences generated by our method are considered appropriate by the LLM, compared to only 82% for MobCache w/o LE.
This result shows that the latent-space evaluator can guide cache path selection and confirms that our decoder produces reasonable mobility activity sequences.

4.9.
Parameter experiment

An important parameter in our method is the exploration rate used when searching for new mobility chains in the cache.
Figure
10
shows the inference speed under different exploration rates on Beijing dataset. As the figure indicates, lower exploration rates result in faster inference since the system performs fewer cache searches for new chains. However, this speed gain comes at the cost of output diversity and behavioral quality.
Specifically, the average simulation quality at an exploration rate of 0.5 is 11.10% higher than at 0.3, while increasing the rate further to 0.7 only improves quality by an additional 2.83%. Considering this trade-off, we set the exploration rate to 0.5 as the default in all our experiments.

5.
Limitations and ethical considerations

Lessons learned:

Based on the results from our paper, we summarize the following lessons learned:

•

Our reconstructible latent-space cache can augment LLM calls by querying cached results, thereby accelerating large-scale mobility simulation. As shown in Table
1
, MobCache achieves comparable performance to state-of-the-art LLM-based methods while significantly reducing inference time and resource consumption.

•

Our framework can be generalized to other LLM-based mobility simulation methods. As demonstrated in Figure
6
and Figure
6
, MobCache significantly enhances the simulation efficiency of Urban-Mobility-LLM while maintaining comparable simulation quality.

Limitation:
While our framework effectively accelerates other mobility simulation models, it only applies to models that expose interpretable reasoning steps. In particular, the simulation model must provide accessible step-by-step reasoning, either as text or structured latent representations.

Ethics and privacy:

This work focuses on accelerating large-scale mobility simulation rather than individual tracking or prediction. Our approach does not require real trajectory data for supervised model training; instead, real-world data is used only for evaluation. Moreover, all trajectory data used for evaluation is fully anonymized and does not contain identifiable user information.
Our framework relies on user profiles from census statistics or publicly available data sources. All information is highly anonymized and represented at a coarse-grained level, preventing the identification of specific individuals and preserving user privacy.

LLM-based human mobility simulation. Existing works explored using LLMs for human mobility simulation by leveraging their knowledge and human-like reasoning capabilities. The advantage of these approaches is that they do not require large-scale real-world mobility data for training.
These works

guide LLMs to simulate human-like mobility intention reasoning step by step and then produce realistic mobility activity sequences.
For example, CoPB
(

is an intention and planing based framework that enables LLMs to generate human mobility trajectories through step-by-step reasoning.
Although these works produce realistic outputs, the reliance on LLMs makes the simulation expensive.
This work
(
14

design a LLM-based agent framework for personal mobility generation, combining self-consistency and retrieval strategies to align language models with real-world human activity for accurate and interpretable urban mobility simulation.

To reduce the cost of LLM-based simulation, some works
(
6
)
design a group-based approach, where people are clustered into coarse-grained groups based on profiles and the LLM is invoked once per group to generate shared mobility activities. However, this approach limits diversity, since people in the same group share identical behaviors.
Other works focus on optimizing the efficiency of API interactions
(
40
;
28

. For example, OpenCity
(

accelerates LLM-based simulation by combining I/O multiplexing and TCP connection pooling to parallelize LLM requests.
AgentSociety
(
28
)
accelerates GPT API calls by using Agent Grouping, Ray with asyncio for asynchronous distributed execution, MQTT-based message reuse, and a unified interface for local and remote models, enabling large-scale agent simulations on commodity hardware.
However, the requirement of querying the LLM API for each agent at every simulation step remains, resulting in high cumulative cost.

6.2.
Caches for LLMs.

When referring to “cache” in the context of LLMs, the most common form is key-value (KV) caching.
KV cache stores the intermediate attention states of previously processed tokens, allowing faster autoregressive decoding without re-computing hidden states.
Techniques such as prefix caching
(
17
;
21
;
23
)
reuse KV pairs for initial prompt tokens, while full KV
(
11
)
reuse extends this idea to non-prefix positions via positional embedding shifts.
Our method is orthogonal to traditional KV caching. While KV cache accelerates decoding at the token level within a fixed prompt, our latent cache operates at a higher level by storing latent reasoning steps. This enables flexible reuse across different simulation queries. Importantly, the two approaches are complementary. Our method can potentially benefit further by incorporating KV cache for additional decoding speedup.
In addition, several existing methods leverage query similarity to cache or retrieve useful information, thereby improving efficiency or generation quality in LLMs
(
27
;
2
;
19
)
.
For example, MemGPT
(
27
)
introduces a memory system that simulates long-term memory, retrieving context dynamically during extended interactions.
Unlike retrieval methods based on text similarity, our method enables latent-space reasoning reuse, supporting efficient and compositional simulation.

7.
Conclusion

In this work, we design MobCache for large-scale mobility simulation. It consists of two key components: (1) a reconstructible cache that stores latent-space reasoning embeddings and supports tree-structured search for flexible reuse; and (2) a lightweight decoder that decodes latent-space reasoning chains into natural language while maintaining spatial-temporal consistency. Experiments show that our method significantly reduces simulation cost while maintaining comparable performance to other LLM-based methods.
