Abstract
. Traditional approaches to network management have been accessible only to a handful of highly-trained network operators with significant expert knowledge. This creates barriers for lay users to easily manage their networks without resorting to experts. With recent development of powerful large language models (LLMs) for language comprehension, we design a system to make network management accessible to a broader audience of non-experts by allowing users to converse with networks in natural language. To effectively leverage advancements in LLMs, we propose an agentic framework that uses an intermediate representation to streamline configuration across diverse vendor equipment, retrieves the network state from memory in real-time, and provides an interface for external feedback. We also conduct pilot studies to collect real user data of natural language utterances for network control, and present a visualization interface to facilitate dialogue-driven user interaction and enable large-scale data collection for future development. Preliminary experiments validate the effectiveness of our proposed system components with LLM integration on both synthetic and real user utterances. Through our data collection and visualization efforts, we pave the way for more effective use of LLMs and democratize network control for everyday users. 1 1 1 Data and code available at https://github.com/jzhou316/LLM-networking-control .



1.
Introduction

Network management is a challenging task. As networks grow in size and complexity, managing them becomes labor-intensive and error-prone even for experienced network operators
(
Benson et al. 2009
;
Sung et al. 2016
)
. Moreover, because modern networks rely on equipment from multiple vendors, network management remains accessible only to a limited number of experts who are familiar with the specific tools, documentation, and configuration protocols unique to each vendor. This creates a steep learning curve for non-experts, which can stifle innovation and limit the democratization of network technologies.

We envision a future where network control is more accessible to non-experts across a wide range of network applications, as depicted by Figure
1
. For example, entry-level developers and end-users may lack the specialized knowledge necessary to configure complex home or business networks.
A natural solution is to enable users to interact with networks through natural language. Natural language (NL), which is universally understood, does not demand any domain-specific expertise from the user. Although a handful of previous works have explored the use of NL for network management
(
Jacobs et al. 2021
;
Birkner et al. 2018
)
, recent progress in Large Language Models (LLMs)
(
Brown et al. 2020
;
Bommasani et al. 2021
;
Wei et al. 2022
;
Chowdhery et al. 2023
;
Li et al. 2025a
)
opens up greater possibilities to realize this vision. LLMs are already widely used to simplify other complex tasks, such as ChatGPT
(
OpenAI 2023
)
for drafting emails and GitHub Copilot
(
GitHub 2023
)
for coding, and the idea of general pretraining behind LLMs has also been applied to building foundation models for network dynamics
(
Dietmüller et al. 2022
;
Zhou et al. 2024
)
.

In particular, LLMs have given rise to “LLM agents,” advanced AI systems that exhibit behaviors such as planning ahead, retaining context from prior interactions, utilizing tools, and adapting their behavior based on feedback
(
Guide 2024
;
Tian et al. 2025
)
. By leveraging the reasoning capabilities of LLMs, agents have been used for a variety of complex tasks, including software development
(
Yang et al. 2024
)
, web browsing
(
Zhou et al. 2023
)
, data science analytics
(
Luo et al. 2025
)
, and interfacing with operating systems
(
Wu et al. 2024
)
. These advancements motivate the use of LLM agents for network control via NL
(
Wang et al. 2025
)
.

A few recent works have attempted to apply LLMs for network configuration
(
Mondal et al. 2023
;
Mani et al. 2023
;
Wang et al. 2024
)
. However, they largely focus on isolated tasks based on detailed inputs provided by expert network operators, which may not reflect real-world network scenarios. For example, NetConfEval
(
Wang et al. 2024
)
proposes an LLM prototype that automatically retrieves relevant documentation for the specific networking use case, but the user is nevertheless expected to provide detailed instructions in the initial prompt, including a description of the topology and existing configurations on the network devices. We propose an agentic framework to reduce the expertise required from the user by augmenting an LLM agent with the domain-specific knowledge base and tools.

With NL as the user-network interface,
we identify several important qualities of an accessible network management system: (1)
The system should streamline configuration across different vendor languages.
Many networks are heterogeneous, consisting of devices from various vendors, each using its own configuration language. In general, pretrained LLMs are not trained on this domain-specific knowledge. (2)
The system should be aware of real-time network conditions.
Networks are highly dynamic; devices join and leave, traffic patterns shift, and policies are frequently updated. While the knowledge base of an LLM is generally frozen after pretraining or fine-tuning, our system must continuously learn and track changes to the networking devices in real time. (3)
The system should be able to incorporate external feedback.
For example, it is well-known that LLMs are prone to “hallucination,”
(
Xu et al. 2024
)
a phenomenon in which the LLM generates plausible but factually inaccurate information. This poses a significant challenge when applying LLMs to network configuration, which often has strict accuracy and reliability guarantees. To minimize disruptions from misconfigurations, the system might rely on feedback from users or external verifiers. (4)
The system should facilitate user-friendly and efficient human-AI interaction.
It should be easy for users to verify configurations, further clarify their intentions, and interact with the AI system in an intuitive manner. This would enhance the overall user experience and make network management more accessible to a wider audience.

This paper proposes a comprehensive agentic framework that addresses these challenges by (1) leveraging a vendor-agnostic intermediate representation (IR) such as YANG
(
Björklund 2016
)
to streamline configuration generation, (2) retrieving from a dynamic memory store, and (3) providing a unified interface for external feedback. We also (4) collect data from real users and develop a visualization tool to facilitate large-scale data collection. We conduct preliminary experiments that evaluate the ability of our system to accurately retrieve relevant details from the network state and to produce configurations that adhere to the IR specifications. Our experiments reveal that configurations are highly dependent on the accuracy of the retrieval results, verification is crucial to mitigate errors, and leveraging an agentic design improves the system performance. Based on these preliminary results, we call upon the research community to investigate retrieval techniques tailored to networking data, build robust verifiers for LLM integration, and standardize efforts to benchmark NL data in this domain under a shared IR.

2.
Motivation and Challenges

We motivate our agentic design by highlighting several challenges of applying LLMs to network management.

Handling Multiple Configuration Languages.

Large networks typically include equipment from various vendors. Managing these networks is complicated because different vendor languages implement configurations with vastly different structures, even for ostensibly similar functionalities
(
Tang et al. 2021
)
. To demonstrate, consider configuring MPLS administrative groups to include certain links (red) while excluding others (blue) in Juniper Junos and Cisco IOS. In Juniper, administrative groups are given explicit names (colors)
(
Juniper Networks 2024
)
:

mpls {
admin-groups {
red 15;
blue 8;
}
}
label-switched-path red-notblue {
to 10.0.1.1;
admin-group {
include red;
exclude blue;
}
}

In Cisco IOS, the same goal is achieved through a combination of affinity bits and masks
(
Cisco Systems, Inc. 2020
)
:

interface Tunnel0
description red-notblue
ip unnumbered Loopback 1
tunnel destination 10.0.1.1
tunnel mode mpls traffic-eng
tunnel mpls traffic-eng affinity 0x08 mask 0x0A
tunnel mpls traffic-eng path-option 1 dynamic

In addition to vastly different syntax, vendor-specific differences can lead to semantic drift in heterogeneous networks. In Juniper, LSP constraints use intuitive directives like
include
and
exclude
, allowing a logical OR operation for included colors. Cisco IOS, however, uses affinity bits and masks, which implements a stricter logical AND operation. The default behavior is also different between the two vendors. LLMs are generally not trained on these inconsistencies, and it is labor-intensive to fine-tune an LLM on all the nuanced differences among a large number of vendor languages.

Managing Network State.

The intention of a user query often depends on the real-time network state. For example, the LLM might need to know the current topology, the names of interfaces on each device, the IP addressing scheme, the VLAN assignments, the routing protocols in use, and any specific policies or constraints (e.g., access control lists, bandwidth limits, or high availability requirements). This requires a large amount of effort and technical expertise from the user, who must collect all the necessary contextual details to craft a comprehensive prompt.

This challenge is further complicated by the fact that topologies
(
Zhou et al. 2020
)
and network policies often change between queries, meaning that even minor updates to the network state could render previous prompts outdated. Moreover, this approach does not scale well. For example, we can estimate the complexity of configuring a SONiC switch
(
Foundation 2023
)
by counting the number of leaf nodes in their YANG network models, where each leaf node corresponds to a configurable state variable in the switch. Then a simple switch that supports only interface configuration, ACLs, port channels, VXLAN, static routing, and route maps would have over 150 configurable parameters, and a modest network with 8 switches would already have over 1000 parameters to track
(
Cisco 2020
)
. In a data center setting, state management may involve tens of thousands of network devices with many more state variables
(
Sung et al. 2016
;
Sun et al. 2014
)
.

In practice, prompt engineering can be challenging, and the accuracy of LLM outputs is highly dependent on the quality of the prompts provided. Instead, we seek a scalable approach to state management that can adapt to changing network conditions and also reduce user effort.

Ensuring Configuration Accuracy.

Given that many networks require high accuracy guarantees, a robust network management system must mitigate LLM hallucination by implementing strong mechanisms for error detection and correction before deploying configurations. Network operators currently leverage a wide variety of specialized tools to reduce errors. These range from control plane analysis tools
(
Fogel et al. 2015
)
and semantic verifiers
(
Tang et al. 2021
)
to simulation tests. Our goal is to improve LLM reasoning on complex tasks
(
Feng et al. 2025
)
by enabling the LLM to act autonomously based on external feedback. To reduce the manual effort of integrating a large number of tools, we envision an LLM agent that dynamically invokes the appropriate feedback tool based on the present task.

Collecting Natural Language Data for Networks.

The lack of real-world data for benchmarking and evaluation significantly hinders the development of NL-based network configuration systems. Previous efforts to compile such a dataset have been insufficient. NetConfEval
(
Wang et al. 2024
)
compiled a synthetic dataset based on template-based approaches, while other works have focused on task-specific scenarios
(
Mani et al. 2023
)
or domain-specific contexts
(
Jacobs et al. 2021
)
. These datasets all fall short of capturing the variability and complexity of real-world network configuration request. In order to develop and evaluate a system that enables accessible network control for non-experts in the wild, we need to establish benchmarks with NL utterances that reflect how users would actually express them in real-world scenarios.

Collecting such data is challenging because NL is not traditionally used for network management. Without existing systems to facilitate these interactions, it is difficult to predict how users would naturally express network configuration requests. Therefore, an initial system must be developed to observe and gather these interactions. In the following sections, we will discuss our methods for creating effective simulation and utilizing visualization tools to support large-scale data collection and system development.

3.
Proposed System Components

To tackle the challenges discussed in §
2
, we propose the design of a systematic, agentic framework. The framework consists of a core decision-making LLM, which we refer to as the
LLM agent
. This agent is augmented by a configuration generator (§
3.1
), a memory base (§
3.2
), and an interface for external feedback (§
3.3
). Figure
3
provides an overview of the system components, as well as how human users interact with them. An example end-to-end workflow from our agentic system is provided in Appendix
A
.

3.1.
IR for Configuration Generation

The first component of our system is a
configuration generator
that translates an NL request into configuration code using a separate LLM. As discussed in §
2
, it is challenging to build an intelligent LLM system that can operate reliably with multiple vendor languages. Each new vendor language would require developing a unique parser to ensure interoperability with other system components, as well as fine-tuning a separate vendor-specific LLM model.

We introduce the use of an
intermediate representation
(IR) to generate configurations. The IR is a vendor-agnostic abstraction that distills the complexities of NL requests into a structured format that can then be deterministically compiled into low-level network configuration code. Figure
2
illustrates our vision of a single IR through an example configuration. In this pipeline, we first map user requests from NL to the IR. NL expressions are highly variable, and a single configuration objective can be expressed in any number of ways. Although precise interpretation using rule-based methods is difficult, LLMs are capable of handling NL variations. Next, we map the configuration from the IR to various vendor-specific languages. Existing synthesizers already achieve this via explicit one-to-one mappings between elements in the IR and their counterparts in the target language.

Rather than build multiple LLM agents that are individually tailored to specific vendor languages, our approach develops a single intelligent LLM for configuration generation that is fluent in the IR and augments it with compilers to convert between the IR and the target language. Since only one LLM is used, it is easier to improve the configuration generation by experimenting with different prompts or by fine-tuning a single LLM, as done in
(
Wang et al. 2024
)
. In designing the IR, we seek a
vendor-agnostic
,
structured
, and
expressive
abstraction. A structured representation, as opposed to a CLI-based language, facilitates schema validation, which can identify missing fields, incorrect data types, or out-of-range values in the LLM output. Moreover, an expressive IR helps to support a wide range of network configurations, including those that are proprietary to specific vendors.

We use YANG
(
Björklund 2016
)
as our IR in this work. Figure
7
shows the prompts that we used for configuration generation in YANG. YANG follows a structured hierarchical schema that can be extended to a wide range of network tasks, and a growing number of vendors have added YANG support on their devices.

3.2.
Memory Base

We augment the LLM components with a
memory base
, implemented as two separate data stores: one for the network state and another for the IR documentation. The
network state
is dynamically refreshed at query time to provide an up-to-date understanding of the network. The
IR documentation
provides the configuration generator with the IR schema.

In a memoryless approach, the user writes all the necessary context directly in the prompt via a template. It is left to the user’s judgment to determine the relevant context for their specific use case. This alternative works well for one-off queries where the required knowledge can fit within the prompt’s token limit, and iterative interactions are limited. However, for network management, an agentic design with a decoupled memory component is preferable due to its greater dynamism and scalability
(
Li et al. 2025b
)
. The memory component can also be flexibly expanded to include additional resources. For example, future work could include a repository of previous interactions between the user and the LLM agent, which would improve its performance in iterative workflows.

The agent leverages dense retrieval on a vector database
(
Karpukhin et al. 2020
)
to fetch the most relevant information from the memory base. The configuration and topology files, as well as the IR documentation, are first encoded into vector representations via a pretrained embedding model to capture the semantic information of the data. Similarly, user queries in NL are also embedded into vectors, and retrieval is done by finding the closest matching vectors in the database. Vector databases scale well and enable fast querying, making them suitable for low-latency, large-scale network environments. Future work could improve the retrieval mechanism based on the hierarchical nature of networking data.

3.3.
Feedback Integration

We design an interface to integrate
external feedback
into our system. Our design is similar to
(
Yao et al. 2022
)
, in which the LLM agent interleaves reasoning action generation. An agentic feedback loop is more flexible than a predefined feedback workflow because it allows the LLM agent to react autonomously to feedback. For example, Figure
8
shows the prompt for an agent with access to a verifier. Based on the verifier’s feedback, the agent may leverage other tools or retrieve more details from memory before regenerating the configuration.

The user is another valuable source of external feedback. We explicitly incorporate entry points for human feedback at critical steps in the workflow. During the initial retrieval of the network state, the agent iteratively clarifies with the user that their intent is clearly understood and aligns with the retrieved information from the network state. Before invoking the configuration generator, the agent may ask the user for missing details. Finally, after automatic verification, the agent presents the configuration to the user for review. This effectively results in a continuous user-agent dialogue, which improves the overall accuracy of the system and eliminates the need for an exhaustive prompt from the outset.

4.
Data and User Interface

Data Collection.
Real-world data is critical to the development and evaluation of NL-based network control systems. We are the first to collect NL utterances that captures the distribution of configuration intents as they occur in real-world scenarios. We collected a small dataset by distributing a survey to network operators from a large networking solution provider. Our survey presented a 3-stage Clos network scenario
(
Parise et al. [n. d.]
)
and solicited network configurations in NL for several common management tasks. For each task, we asked the respondent to describe a network-wide policy in NL and provide per-device configuration requests in NL. The per-device configuration requests are used as the inputs for our LLM, while the network-wide policy descriptions are used to evaluate the LLM’s outputs against the user’s intentions.

Visualization Interface.
To facilitate data collection and system evaluation, we design a conversational interface with which non-experts can view responses from the agent and give further instructions. Our aspiration is akin to that of ChatGPT’s success story, in which the system is continuously deployed to a wide audience and refined based on user interactions. In the same spirit, our visualization tool features an intuitive interface to facilitate user-agent dialogue.

An example interaction is shown in Figure
4
, where the user wants to set up an overlay network to extend VLANs and enable intra- and inter-VLAN traffic. All intermediary responses from the LLM agent are displayed in NL. This allows the user to monitor the agent’s reasoning and engage with it in continous dialogue. Future work can improve the interface by providing additional network details, such as a visualization of the network topology. With this visualization tool, we hope to make the network management system accessible to a large audience, and in doing so, enable large-scale data collection for future development.

5.
Experiments and Results

In this section, we present the results of our experiments. We test our LLM agent on two datasets: a pre-existing dataset, and the real-world network scenario dataset, as described in §
4
. For the first dataset, we compare our agent with a baseline system to underscore the advantages of configuration generation via LLMs. Then we run our LLM agent on our own dataset to demonstrate the effectiveness of its components in real-world network configuration scenarios.

5.1.
Comparative Analysis with Lumi

We compare our LLM agent with Lumi
(
Jacobs et al. 2021
)
as the baseline. Lumi is an intent-based network management system that translates NL intents into low-level configuration commands. It trains an LSTM to perform Named Entity Recognition (NER) on operator utterances. Using a system of templates and predefined rules, the extracted entities are then structured into configuration statements expressed in their Network Intent Language (Nile).
We test on the
alpha
and
campi
datasets provided with Lumi.
alpha
consists of 150 synthetically-generated intents, while
campi
consists of 50 real-world intents obtained by crawling university websites. All intents involve network tasks common to campus networks, and each is manually annotated with ground-truth entities and Nile intent.

For evaluation, we adopt Lumi’s metric on entity tagging with Precision, Recall, and F1-score measures.
Moreover, we would like to evaluate the accuracy of the generated Nile configurations. We propose the metrics “exact match” and “fuzzy match,” where the latter is more lenient, accounting for slight variations of text strings such as capitalization and synonyms of a consistent term.
This offers a more fine-grained evaluation of the generated Nile configurations.

We instruct GPT-4o to convert the NL utterances into Nile intents based on Nile’s BNF grammar. Since Lumi’s LSTM system does not consider the network state, we make a fair comparison by only including the following components of system: configuration generator with one-shot prompting, and schema verifier with a BNF grammar verifier for Nile.

The results of our evaluation are given in Table
1
. They demonstrate that our general-purpose LLM agent performs comparably to an LSTM that was specifically trained on these datasets. We believe that incorporating more sophisticated prompting techniques, such as multi-shot prompting, would further enhance the accuracy of our system. Finally, Figure
5
reports the amount of time taken by our LLM system with respect to the number of verification iterations. As shown in the figure, the BNF verifier is able to correct all syntax errors within 8 iterations for 195 out of 200 total intents.

5.2.
Evaluation on 3-Stage Clos Network

Next, we assess the agent’s ability to generate complete and correct configurations for the 3-stage Clos network dataset. In our experiments, we use YANG as the IR and the Python library pyang as an automatic syntax verifier. We use
(
Cisco 2020
)
to compile the YANG generations into SONiC. We populate the memory base with topology information and per-device configuration files. The backbone is deployed with GPT-4o, while we leverage OpenAI’s text-embedding-ada-002
(
OpenAI 2022
)
model for the retrieval component. We limit the scope of our evaluation to all components that do not require human-in-the-loop and evaluate the correctness of the final configurations based on whether they are syntactically well-formed and accurately reflect user intent. Each generation is evaluated as either correct or incorrect based on human expertise.

We run each of 13 NL requests through 3 trials, resulting in 39 total generations. Table
2
presents our evaluation results. Without verification, only 33.33% of the outputs are generated with proper YANG syntax, but our verifier corrects 87.5% of these errors within 5 iterations. Among the verified outputs, 76.92% can be deployed without errors. The remaining errors generally involve inconsistent IP and AS assignments, missing configurations for specific devices, or missing deny rules in ACL generations. These errors may be further reduced by incorporating feedback sources for verification. We also conduct an ablation study to demonstrate the effectiveness of state retrieval. Without the retrieval mechanism, the LLM exhibits significant hallucinations on every input. Including a retrieval mechanism that returns the relevant state components in the raw configuration file format results in only 46.15% accuracy. However, instructing the LLM agent to describe the retrieved parts in NL rather than in the original configuration file format drastically improves accuracy to 76.92%. Finally, Figure
6
presents a detailed latency breakdown of the various components in the LLM system across all generations. We observe that on average, each query requires 86.43 seconds to complete. Moreover, more than 61% of the trials require at least one round of correction and re-verification, underscoring the significance of feedback integration in our agentic system.

6.
Conclusion

We present a vision to make network management widely accessible by enabling non-experts to interact with network systems through natural language. To realize this vision, we designed an agentic framework to facilitate state-aware, vendor-agnostic, interactive, and user-friendly network control. We also address the challenge of using LLMs to perform configurations in multiple target languages by introducing an intermediate representation. We hope that future work will focus on enhancing these core components of LLM-based network control systems, particularly by building verifiers for additional network invariants and developing more user-friendly interfaces to scale out data collection and realiable benchmarking.
