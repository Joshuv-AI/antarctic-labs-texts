Leveraging Content Words for OOD Generalization in Dense Retrieval
Xincan Feng, Noriki Nishida, Yusuke Sakai, Yuji Matsumoto, [0.5em] Nara Institute of Science, Technology

Abstract
Prior synthetic query generation for dense retrieval produces one query per document, focusing on quality. We systematically study multi-query synthesis, discovering a quality-diversity trade-off : quality benefits in-domain, diversity benefits out-of-domain (OOD). Experiments on 31 datasets show diversity especially benefits multi-hop retrieval. Analysis reveals diversity benefit correlates with query complexity ( r r ≥ \geq 0.95), measured by content words (CW). We formalize this as the Complexity-Diversity Principle (CDP) : query complexity determines optimal diversity . CDP provides thresholds (CW > > 10: use diversity; CW < < 7: avoid it) and enables CW-weighted training that improves OOD even with single-query data.

Introduction

Task: Synthetic Query Generation for Dense Retrieval.

Dense retrieval models encode queries and documents into a shared embedding space for efficient similarity search
(
7
;
18
)
. Training these models requires large-scale query-document pairs, which are expensive to annotate manually.
Synthetic query generation
addresses this by using LLMs to generate training queries from documents
(
1
;
3
)
. Given a document corpus
\mathcal{D}
, the goal is to generate queries
\{q_{i}\}
such that training on
(q_{i},d_{i})
pairs yields a retriever that generalizes well to unseen evaluation tasks.

Prior Work and Gap.

Existing methods generate
one query per document
, focusing on query quality. InPars
(
1
)
, Promptagator
(
3
)
, and SAP
(
13
)
use few-shot prompting to produce high-quality queries resembling human-written ones. DRAGON
(
8
)
combines multiple data sources but still produces one query per document—its “diversity” refers to data source variety, not per-document query diversity.
No prior work studies generating multiple queries for the same document.
This leaves a fundamental question unexplored:
does multi-query diversity help retrieval, and if so, when?

Our Hypothesis.

We hypothesize that
query complexity
determines when diversity helps. We measure complexity via
content words (CW)
—the count of unique non-stopwords in a query. CW is simple to compute yet captures information density: complex queries contain multiple content words that jointly define the information need (Figure
1
). Simple queries have few content words where diversity provides limited benefit. If true, diversity benefit should correlate with CW.

Contributions.

•

Complexity-Diversity Principle
: We shift the focus from quality to diversity in query synthesis. Using proposed Q-D metrics to quantify quality and diversity, we discover through experiments on 4 benchmark types with Contriever, RetroMAE, and Qwen3-Embedding that query complexity determines optimal diversity (
r
\geq
0.95,
p
<
0.05 in 12/14 conditions).

•

Multi-query synthesis
: We systematically study multi-query synthesis, discovering the
quality-diversity trade-off
: quality benefits in-domain, diversity benefits OOD. We derive CW thresholds (CW
>
10: use diversity; CW
<
7: avoid it).

•

CW-weighted training
: We propose CW-weighting that can be applied to both single-query and multi-query data for compounded OOD gains.

Related Work

Query Synthesis for Dense Retrieval

Query synthesis has followed the
1 query : 1 document
paradigm. InPars
(
1
)
introduced LLM-based few-shot prompting. Promptagator
(
3
)
improved quality via consistency filtering. SAP
(
13
)
designed summarize-then-ask prompts for multilingual retrieval. DRAGON
(
8
)
reduced costs by mixing sentence cropping with docT5query. DRAMA
(
9
)
improved few-shot example selection. ReasonEmbed
(
21
)
augmented queries with reasoning chains for reasoning-intensive tasks. Despite these advances,
all prior work maintains the 1:1 paradigm
. We are the first to study
N queries : 1 document
and discover the
quality-diversity trade-off
.

Data Augmentation and OOD Generalization

Contriever
(
6
)
and RetroMAE
(
17
)
use unsupervised pretraining. DPR
(
7
)
and ANCE
(
18
)
improve hard negative sampling. BEIR
(
14
)
benchmarks OOD generalization. While prior work explores pretraining and data scaling, the role of
query diversity
remains unstudied. Our work fills this gap.

3
Methodology

To test our hypothesis, we adopt
zero-shot multi-query synthesis
that controls quality and diversity via prompts, generating
M
queries per document in one LLM call (Figure
2
).

3.1
Step 1: Zero-shot Multi-Query Synthesis

Unlike few-shot methods that produce homogeneous queries due to pattern copying (CE
>
0.5, Table
1
), we use zero-shot prompting to generate
M
semantically diverse queries per document in a single LLM call with temperature=0. The prompt specifies multiple formats (Figure
3
): factual, procedural, causal, conditional, keyword, and comparison queries. This achieves true semantic diversity, reproducibility, and cost efficiency.

Diverse Prompt

Your task is to generate {M} independent queries based on the document(s).

You MUST generate queries in these specific formats:

–
What
… questions (factual)

–
How
… questions (procedural)

–
Why
… questions (causal)

–
When/If
… questions (conditional)

–
Keyword
queries (2-5 words, no question mark)

–
Statement/claim
format (e.g., “X is used for Y”)

–
Comparison
questions

Each query must target
different information
from the document.

Figure 3:
Diverse prompt. The prompt enforces varied query formats (factual, procedural, causal, conditional, keyword, statement, comparison) targeting different information from the document. M denotes Q/Doc.

3.2
Step 2: Q-D Metrics Measurement

We propose Quality-Diversity (Q-D) metrics. For
quality
(higher = better):
Dist-Sim
(embedding similarity to human queries) and
Len-Sim
(length similarity). For
diversity
(lower = more diverse):
CE
(cross-encoder paraphrase ratio) and
Self-BLEU
(lexical overlap among queries). Formal definitions in Appendix
D
.

3.3
Step 3: Diversity Tuning

To isolate the effect of diversity, we design two prompt variants with the same query quantity
M
: (1)
Diverse mode
generates semantically distinct queries (different formats; CE
\approx
0.04); (2)
Paraphrase mode
generates semantically equivalent queries (same question, different wording; CE
\approx
0.50), serving as a low-diversity control. Full templates in Appendix
O
.

3.4
Step 4: CW-Weighted Training

We propose
CW-weighted training
as a complementary method to multi-query synthesis. We measure query complexity via content words (CW), defined as unique non-stopwords:

\text{CW}(q)=|\{w\in\text{tok}(q):w\notin\mathcal{S}\land|w|>1\}|

(1)

Unlike reasoning-based metrics that require model inference, CW can be computed from queries alone via simple word counting. During training, we apply truncation and batch normalization:

w(q)=\frac{\min(\text{CW}(q),\kappa)}{\sum_{q_{i}\in B}\min(\text{CW}(q_{i}),\kappa)}\cdot|B|,

(2)

where
\kappa
=100 truncates extreme values and
|B|
is batch size. CW-weighting can be applied to both single-query and multi-query data for compounded OOD gains.

Our method excels on reasoning tasks.

Query quantity

Formalization.

We formalize our findings as
CDP
:
query complexity determines whether diversity helps or hurts
. Complex queries contain multiple content words that jointly define the information need—no single word (e.g., a person name or common term) can capture it alone. Training on diverse formulations helps models learn to match based on the full semantic content rather than superficial word overlap. For simple queries dominated by few distinctive terms, diversity provides limited benefit: 2WikiMultihopQA (CW=6.34) shows negative
\Delta
NDCG@10 in 93% of conditions.

Diversity as Regularization.

Theoretically, multi-query training acts as
implicit regularization
: each query variant provides a different “view” of the document, similar to multi-view learning
(
19
)
. Error analysis (Appendix
F
) confirms this: M=3 corrects M=1’s overfitting to superficial features. Figure
6
shows 68% of datasets benefit from Q/Doc
>
1.

6.7
Validation on External Pipeline

ReasonEmbed
(
21
)
is a state-of-the-art reasoning-intensive retrieval pipeline. It synthesizes 82K training samples from BRIGHT via ReMixer and applies RI-weighted training via Redapter. The Reasoning Index (RI) measures reasoning intensity using the original query
q
, reasoning-augmented query
q^{\prime}
, and document
D
:

\text{RI}_{\theta}(s)=\min\left(\frac{\mathcal{L}_{q,D}}{\mathcal{L}_{q^{\prime},D}},\kappa\right),

(3)

where
\mathcal{L}
is InfoNCE loss,
q
is the original query,
q^{\prime}
is the reasoning-augmented query, and
\kappa
=5.0. Higher RI indicates stronger reasoning requirements. RI weights samples during training via batch normalization.

Experimental Setup.

We sample 8K documents from public ReasonEmbed data (derived from BRIGHT) and train Qwen3-Embedding-0.6B, using original queries combined with ReMixer-generated reasoning queries as multi-query data; BRIGHT serves as in-domain and Multi-hop as OOD.

7
Conclusion

We shift the focus from quality to diversity in query synthesis and retriever training, discovering the
Complexity-Diversity Principle (CDP)
: query complexity determines optimal diversity (
r
\geq
0.95). We propose multi-query synthesis and CW-weighted training, both improving OOD generalization with compounded gains when combined.

Limitations

We validate CDP on three dense retriever architectures; extending to sparse retrievers and late-interaction models would strengthen generalizability. CW trades sophistication for simplicity: it ignores individual word difficulty, syntactic structure, and attention weights. More nuanced measures may offer additional benefits. We focus on English; CDP may vary across languages.

Ethics Statement

We use publicly available datasets and commercial LLM APIs. No personal data is collected. Synthetic queries may contain LLM biases.

Appendix C
Implementation Details

Training Configuration

We train all retriever models using the sentence-transformers library. We use AdamW optimizer with
\beta_{1}=0.9
,
\beta_{2}=0.98
,
\epsilon=10^{-8}
, and weight decay of 0.01. The learning rate is set to
2\times 10^{-6}
for Contriever and
5\times 10^{-6}
for RetroMAE, selected via grid search using supervised human-annotated data on the MS MARCO development set, then applied uniformly to all methods. We use cosine learning rate decay without warmup. The batch size is 128, and models are trained for up to 100 epochs with gradient clipping (max norm 1.0). We use InfoNCE loss
(
16
)
with scale factor 20.0 as the loss function, and cosine similarity for scoring. Training employs FP16 mixed precision with gradient checkpointing enabled. Checkpoints are saved and evaluated every 500 steps, with model selection based on NDCG@10 on the MS MARCO development set. We use the official Contriever (
facebook/contriever
) and RetroMAE (
Shitao/RetroMAE
) checkpoints as initialization.

Temperature Setting for LLM-based Query Generation

For our zero-shot method, we use temperature=0 to ensure reproducibility, as our prompt explicitly instructs the LLM to generate multiple diverse queries in a single API call. For few-shot baselines (InPars-GBQ, SAP, DRAMA), we use temperature=0.7 when generating multiple queries per document, since few-shot prompts typically produce a single query per call and require multiple sampling to obtain M queries.

Learning Rate Selection

We conduct a learning rate sweep using supervised human-annotated MS MARCO data, selecting from
\{2\times 10^{-7},5\times 10^{-7},1\times 10^{-6},2\times 10^{-6},5\times 10^{-6},1\times 10^{-5}\}
. Table

Appendix L
Cross-Condition Consistency for Threshold Estimation

Our CW threshold recommendations (Table
9
) are derived from only 4 multi-hop datasets. Here we explain why the consistency across 14 experimental conditions provides reliability for these estimates.

The Challenge of Small Sample Size.

With only 4 datasets, a single correlation coefficient could be spurious. A significant result in one experimental condition might be due to chance or specific methodological choices.

Cross-Condition Consistency as Replication.

Instead of relying on a single experiment, we compute the same analysis across 14 different experimental conditions:

•

3 Diverse vs. Paraphrase comparisons (Q/Doc
\in
{5, 10, 20})

•

Each condition represents a different operationalization of “high diversity vs. low diversity.” If the CW-diversity relationship holds across all these variations, it is unlikely to be an artifact of any specific experimental choice.

Positive Rate as a Robust Metric.

For each dataset, we compute the
positive rate
, defined as the proportion of conditions where diversity improves performance (
\Delta
NDCG@10
>
0). This metric is robust because:

•

It aggregates evidence across multiple conditions

•

It is based on the sign of the effect (positive/negative), not magnitude

•

It provides a probabilistic interpretation: “In X% of experimental setups, diversity helps”

Results.

The positive rates show a clear monotonic relationship with CW: NovelHopQA (CW=11.64) benefits in 100% of conditions, HotpotQA (CW=8.60) in 86%, MuSiQue (CW=8.64) in 43%, and 2WikiMultihopQA (CW=6.34) in only 7%. Linear regression across all 56 data points (4 datasets
\times
14 conditions) yields
r
=0.89 (
p
<
0.0001), confirming the strong relationship.

Limitations.

This approach increases
internal validity
(confidence that the relationship is real) but does not address
external validity
(generalization to other datasets). The thresholds are validated only for reasoning-intensive multi-hop QA tasks where CW-diversity correlation holds. For other task types (e.g., BEIR, BRIGHT), the relationship may not apply.

Appendix M
CW at Training vs. Inference

We analyze whether CW can predict reasoning query benefit at inference time. On 81k queries across 12 BRIGHT domains, reasoning queries improve NDCG@10 by +0.0275 on average. However, CW shows near-zero correlation with this improvement (

0.019,

Appendix N
Limitations of Few-shot Methods

Existing methods like InPars
(
1
)
and SAP
(
13
)
employ few-shot prompting with carefully selected examples. While few-shot prompting can ensure high-quality queries that closely match target distributions, it has two critical limitations:

High Cost.

Few-shot methods require
M
separate LLM calls to generate
M
queries per document, and depend on powerful LLMs to follow complex few-shot patterns.

Limited Diversity.

LLMs tend to mimic the patterns of few-shot examples (syntax, length, question type), causing the output distribution to be anchored around these examples. Even with high temperature sampling (
>
0.7), the generated queries remain clustered around the exemplar patterns, producing only surface-level lexical variations rather than true semantic diversity. This results in high paraphrase ratios (CE
>
0.5), as shown in Table
1
: few-shot queries for the same document are largely paraphrases of a single underlying pattern.
